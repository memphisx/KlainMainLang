# ADR-00931: Invalid-IR conformance sweep — coercion, return-type & ABI fixes

- **Date**: 2026-09-13

## Context

Continuation of the Test262 invalid-IR (CLANG_ERROR) reduction across both
compat lanes. After the symbol-key work ([ADR-00930](ADR-00930.md)) a cluster of
smaller, distinct codegen defects remained, each emitting invalid IR on a real
in-scope path. Found by bucketing the full-corpus faillist of both lanes by the
offending IR instruction.

## Investigation

Each cluster was reproduced to its offending IR line:

- **Bitwise/shift on a non-numeric or empty operand** (12 files): `{} & fn`
  reached `trunc i64 <ptr>`; `(function(){throw})() & x` reached
  `trunc i64  <empty>` (a void operand + a block already terminated by the
  callee's throw).
- **String-method args** (~13): `s.replace(obj,obj2)` / `s.lastIndexOf(anyVal)`
  / `s.split(0)` passed a non-string (dynamic/number/object) word to a
  `ptr`-typed `__kml_str_*` helper; `[].join(coercibleObj)` did the same for the
  separator; `String("b" * null)` emitted `mul ptr, null`.
- **Promise executor callback ABI** (3): a boxed `reject` closure whose reason
  parameter is `TypeCaught` got the bare i64 payload where a `{ i8, i64 }` was
  expected.
- **eval return-type** (7): `() => eval("/re/")` — the enclosing closure's
  inferred return type (default i64) disagreed with the ptr/object/regexp the
  static-eval body actually returned.
- **ArrayBuffer/SharedArrayBuffer ToIndex** (2): `new ArrayBuffer("")` passed a
  string `ptr` to calloc.
- **`obj += ''`** (1): a string operand with a non-string (object) compound-
  assignment target fell through to numeric `add ptr`.

## Decision

Faithful coercion at each site (compat=js applies JS coercion; strict keeps its
clean rejection where it already had one):

- `bitwiseNonNumericToZero` maps undefined/null/void/object/function operands to
  literal 0 (ToInt32 of each is 0); a `blockDone` guard in `emitBinaryExpr`
  short-circuits an unreachable binary expression. **Symbol is excluded** —
  ToNumber(symbol) is a TypeError, never 0.
- `coerceStringArg` ToStrings any non-string, non-nullish arg (was objects only).
- `emitArrayJoin` ToStrings a non-string separator (`undefined` → default ",").
- `emitArith` routes `+` to string concat whenever an *operand* is a string,
  regardless of the target slot type.
- `emitUnboxBoxToType` reconstructs a `{ i8, i64 }` `TypeCaught` aggregate from
  the NaN-box (tag, payload) instead of returning the raw payload.
- `inferExprType` mirrors `emitStaticEval` for a static `eval("<expr>")` call so
  the closure return type matches the emitted body.
- `coerceByteLengthArg` (ArrayBuffer): numeric passes through; an object runs
  ToPrimitive; a bare string runs ToNumber (NaN → ToIndex 0); a dynamic value
  keeps the runtime tag-checked `coerce` (which still throws on a Symbol).

## Implementation notes

Touched emit_exprs_operators.go, emit_toprimitive.go, emit_arrays_sort.go,
emit_narrowing.go, emit_eval.go, emit_exprs_types.go, emit_arraybuffer.go. The
`bitwiseNonNumericToZero` Symbol exclusion and `coerceByteLengthArg`'s
dynamic→`coerce` path both exist specifically to preserve the
Symbol-to-number TypeError (regression caught by `TestE2ESymbolToNumberThrows`
on the first test-par run).

## Side effects discovered

Several of these files now *run* but fail an assertion for unrelated
runtime-semantics reasons (e.g. object `valueOf`/`toString` not invoked by the
runtime ToNumber, `assert.throws` matching) — no longer a codegen bug, tracked
as ordinary coverage. Remaining invalid-IR files not addressed here are the
any-keyed `Map` feature, heterogeneous tuple/element boxing (TDD-00205 Stage 2:
`Object.fromEntries` pairs, `Array.prototype.flat` of object elements), and a
handful of per-case inference bugs (do-while var typing, `Iterator.reduce`
accumulator type, RegExp `lastIndex` ToInteger, Set-of-bigint, DataView
`setBigInt64` void-return-to-var).

## Verification

`make test-par` green, `make examples` 302/302, `go vet` clean. Each cluster's
target files reproduced to 0 clang errors before/after. Test262 both lanes
re-run to refresh the canonical per-lane reports.
