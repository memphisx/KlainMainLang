# ADR-02056: A literal method's implicit `this` is context-sensitive

- **Date**: 2026-11-22

## Context

- A literal method nested under a generic call's `ThisType<D & M>`
  (`make({ data: { n: 2 }, methods: { inner: { twice() { return this.n } } } })`)
  failed in codegen ("no type for function body"), with or without
  overloads: the checker typed the method's `this` as unanswered.
- Two gaps: a parameterless method was not context-sensitive, so it was
  typed with the arguments that infer M rather than after them (tsc's
  `hasContextSensitiveParameters` counts a function expression's implicit
  `this`); and the contextual `this`, `{ n: number } & M` with M still
  open, was dropped whole as generic.

## Decision

- `contextSensitive` (now a checker method, to read `Program.ThisParams`)
  treats a function expression with no type parameters and no `this: T`
  parameter as context-sensitive; an object literal's accessors are not
  members it looks through, as tsc's `isContextSensitive`.
- `settledThis` reads a `ThisType` whose type parameters are still open
  with them as `{}`, what tsc's non-fixing inference mapper leaves an
  uninferred one: `{ n: number } & M` types `this.n`.

## Consequences

- `TestE2EThisTypeNestedGenericMethod` (overloaded and plain, nested and
  flat) matches Node; tsc accepts the program.
- Verified on Node304 (Linux x86-64).
