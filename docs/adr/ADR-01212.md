# ADR-01212: A property added to a static object through `any` is its own

- **Relations**: `Implements TDD-00230`, `Extends ADR-01210`
- **Date**: 2026-09-28

## Context

JavaScript adds a property to any extensible object: `anyObj.extra = 1`.
For a statically laid-out object (a class instance, an object literal
built at its type) this threw "Cannot add property extra, object is not
extensible" (BACKLOG 73). A class instance with no methods avoided the
throw by being copied into a dynamic bag when it was stored in `any`
("allocation-site widening"). The copy lost its identity (`q === q2`
held only by accident of the binding), its class name in console.log
(BACKLOG 68) and its layout.

## Investigation

- `emitDynAnyMemberSetNamed` sends a static object to its layout row's
  setter (`__kml_shape_set`), which answers 0 for a key that is not a
  field; the caller threw.
- `dynWidenable` accepted method-less classes. The widened bag carried the
  class tag for `instanceof` but not the name, and was a different object.
- Integrity levels of static objects (`Object.freeze`/`seal`/
  `preventExtensions`) already live in `__kml_frozen_set`.

## Decision

- **Added properties live beside the layout.** shape.c keeps a table from
  object address to its added properties, in insertion order
  (`__kml_shape_expando_set`/`count`/`delete`). `__kml_shape_get` falls
  back to it after the layout's fields (an added property shadows a class
  member of the same name). `__kml_shape_set` overwrites an added property,
  and `__kml_shape_nkeys`/`key` enumerate the fields and then the added
  keys, so `Object.keys`, `for…in`, console.log and `JSON.stringify` of the
  object in `any` include them.
- A dynamic set of a key that is neither a field nor an added property
  adds it when `@__kml_obj_extensible(obj)` holds (defined at finalize: the
  frozen set's level is 0, or true when the program never freezes). A
  frozen, sealed or non-extensible object still throws Node's message.
- `in` and `Object.hasOwn` on a static object in `any` answer from its row
  (an own field or added property; a class member for `in`). `delete`
  removes an added property.
- A class instance is never widened into a bag: stored in `any` it stays
  itself.
- `console.log`, `JSON.stringify` and `Object.keys` of the statically typed
  binding check `@__kml_obj_has_extra` (`emitExtraSplit`, and the
  structural split) and take the layout-row path when the object has added
  properties. The hooks are defined at finalize (`emitObjExtraFinalize`):
  constant "none" unless the program has a dynamic set that can add a
  property, so other programs link nothing new.

## Implementation notes

`codegen/llvm/shapesrc/shape.c`, `emit_shape.go`, `emit_dynobj.go`,
`emit_record_view.go`, `emit_inspect.go`, `emit_call_json.go`,
`emit_objects.go`, `emit_classes.go`, `emitter.go`.

## Side effects discovered

- `for…in` over the statically typed binding lists the layout's keys only,
  and a method called on it dispatches to the class method even when an own
  property of that name was added through `any` (BACKLOG).
- `delete` of a declared field of a static object leaves it in place.

## Verification

Mac (Apple Silicon), against Node v24.19: `TestE2EAddedPropertyOnStaticObject`,
`TestE2EAddedPropertySeenFromStaticBinding`;
`TestE2EAddedPropertyRefusedWhenFrozen` (strict-mode messages).
