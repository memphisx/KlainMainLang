# ADR-01782: Array destructuring steps an iterator only as far as the pattern reads

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- Array destructuring of a value that is not an array collected every value the iterator yields (`__kml_any_iter_collect`). This affected `var [a] = it`, `[a] = it` and nested `[[a]] = [it]`. An endless iterator hung, and the iterator was never closed. In the spec, a pattern takes one step per position, and IteratorClose calls `return()` when it leaves the iterator unfinished.
- A destructured parameter over an `any` read `v[0]`, `v[1]` by index rather than iterating. It rejected rest elements ("array rest … over a dynamic value is not yet supported").
- The parser gave `[]` a nil pattern, so an empty array pattern parameter was not destructured at all.

## Decision

- `__kml_any_iter_take(v, n)` is compiled once from a `for…of` over `any`. It collects at most n values; the loop's `break` closes the iterator. With n = 0 it only gets the iterator and calls its `return`.
- `emitAnyArrayElemsTake` bounds the next protocol collection. `patternTake` and `assignPatternTake` give a pattern's count (every value when it has a rest). The count is set by the declaration, assignment and nested sites, and carried through `resolveArrayHOF` (read and cleared on entry, before anything nested runs).
- `unpackDynArrayPatternInto` takes its values the same way, then binds each position, past-the-end positions as undefined. A rest element binds a new array of the remaining values.
- `parseArrayPatternElems` returns a non-nil empty slice for `[]`.

## Consequences

- Element defaults are evaluated after the pattern's steps rather than between them. Only an iterator whose `next` observes a default's side effects can tell.
- `TestE2EJSFileIteratorDestructuring` checks the exact `next`/`return` sequence against Node for parameters, declarations, assignments, rest, holes, empty and nested patterns.
