# ADR-02082: PCRE2 references are ordinary; a Windows task's stack is its fiber's

- **Relations**: Extends ADR-02069, ADR-02077; Implements TDD-00230
- **Date**: 2026-11-25

## Context

With the link fixed (ADR-02081), three Windows E2E tests still failed:
`TestE2EAsyncOmittedArgumentJS` and `TestE2EArrayAbsenceFromProducers`
crashed (`0xc0000005`), and `TestE2EAsyncRecursionStackOverflow` printed
nothing and exited 0.

## Investigation

- Every regular-expression operation crashed on its own:
  `/x/.exec("abc")`, `/^1/.test("1")`, `"abc".match(/x/)` and a global
  `exec` loop. Every match goes through `__kml_regex_mctx`, which calls
  `pcre2_match_context_create_8`; `regexp.c` declared it, and six other
  PCRE2 functions, `__attribute__((weak))`. `regexp.c` is now a library
  unit that links with `pcre2-8` (ADR-02073), and a weak reference pulls no
  member from a static archive and, to a DLL import, can resolve to null:
  the first call jumped to address 0.
- On Windows `makecontext` runs a task on a fiber whose stack
  `CreateFiberEx` allocates (`win32io.c`); the `ss_sp` block the task
  records is not that stack. `task_stack_used` measured the frame against
  that block, found it outside, and returned 0, so the chain of synchronous
  task starts never grew and unbounded async recursion was never stopped.
  The same recursion without the overflow (`ok(500)`) ran correctly.

## Decision

- The seven PCRE2 declarations in `regexp.c` are ordinary references. The
  unit cannot link without PCRE2, so the reason for weak ("a program may
  link this file without matching anything") is gone. A PCRE2 built
  without JIT still exports the JIT functions: `pcre2_jit_compile_8`
  returns an error and `pcre2_jit_stack_create_8` returns NULL, which the
  callers already handle, so their null checks are dropped.
- On Windows a task's used stack is measured from the running stack's base
  (the TEB's `StackBase`, exported by `win32io.c` as
  `__kml_fiber_stack_base`); elsewhere it stays the recorded block's top.

## Implementation notes

- `codegen/llvm/stringsrc/regexp.c`: the declarations, `__kml_regex_mctx`,
  `__kml_regex_jit`.
- `codegen/llvm/win32src/win32io.c`: `__kml_fiber_stack_base`.
- `codegen/llvm/tasksrc/task.c`: `task_stack_used`.

## Verification

- macOS arm64: `go test ./codegen/llvm`; the RegExp, StringMatch,
  StringReplace, dynamic-import, ArrayAbsenceFromProducers,
  AsyncOmittedArgumentJS and AsyncRecursionStackOverflow E2E tests pass.
- Linux x86-64: `go test ./codegen/llvm`; the same E2E tests and
  ProcessResourceUsage pass.
- Windows x64 (MSYS2 UCRT64, clang 22): the four regex programs that
  crashed print Node's output; the overflow program prints
  `true Maximum call stack size exceeded true`, `500`, `done`; the
  AsyncRecursionStackOverflow, AsyncOmittedArgumentJS,
  ArrayAbsenceFromProducers, RegExp, StringMatch and StringReplace E2E
  tests pass (81, none failing).
