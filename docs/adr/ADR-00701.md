# ADR-00701: FinalizationRegistry — mode-dependent finalization + leak diagnostics

- **Relations**: Implements TDD-00163 (Stages 1–4); Extends ADR-00349 (weak-collection gc plumbing), ADR-00661 (dynamic-object referent unbox)
- **Date**: 2026-09-04

## Context

`FinalizationRegistry` was the missing half of the GC-observing pair
(`WeakRef` shipped with TDD-00112). TDD-00163 scoped it as a mode-dependent
feature rather than a rote port: the spec's best-effort clause makes *every*
firing policy conformant, and this compiler's memory modes each have a more
useful death signal than "whenever the collector gets around to it" —
`Memory.free` is a deterministic death point under `-mm=manual`, and a
registration still live at exit under the leak-by-default model is a
*labeled leak*.

## Investigation

- The WeakRef plumbing (`emit_weak.go` / `runtime_weak.go`) supplied the
  object-referent check (incl. the `-compat=js` dynamic unbox, ADR-00661)
  and the Boehm declaration pattern; the AsyncLocalStorage handle
  (TDD-00168) supplied the lighter `ast.NewExpression`/`ClassName` plumbing
  recipe (no dedicated AST node), which this follows.
- The microtask FIFO (`runtime_microtask.go`) already drains at exactly the
  spec-reachable points a finalizer queue needs (end of top-level script,
  each scheduler step, each fired timer), so the pending-finalizer queue
  rides it behind a generic thunk instead of adding a parallel FIFO.
- Two Boehm findings on Mac (arm64):
  1. Boehm only *queues* finalizers at collection and runs them lazily from
     later allocation points — nothing observable fired until `gc()` and
     the exit flush called `GC_invoke_finalizers()` explicitly.
  2. Boehm does not scan TLS blocks as static roots on macOS (they are
     dyld-allocated), so a registration cell reachable only through a
     `thread_local` list head was collected out from under its own pending
     finalizer — a verified jump-to-garbage crash. The list head is a plain
     global under gc, and the queued env/header are
     `GC_malloc_uncollectable`'d (they are reachable only through the
     microtask FIFO's own thread_local buffer).

## Decision

One API (`new FinalizationRegistry<T>(cb)`, `.register(target, held,
token?)`, `.unregister(token)`), one execution path (enqueue → microtask
drain / atexit flush → `cb(held)`), several death signals:

- **`-mm=manual`**: the `freeResolvedPointer` chokepoint calls
  `__kml_finreg_onfree(ptr)` before freeing (gated on a whole-program
  pre-scan, `programConstructsClass`, since a free can be emitted before the
  construction); every live registration targeting that pointer is
  enqueued. An `atexit` hook enqueues all survivors and drains — nothing
  registered ever silently misses its cleanup.
- **`-mm=auto`**: compiler-inserted frees route through the same chokepoint,
  so they are the same death signal; in practice a registered target
  currently counts as escaping (it is passed to `register`), so callbacks
  fire at the exit flush.
- **`-mm=gc`**: `register()` also calls `GC_register_finalizer` with the
  cell as client data; the collector-invoked callback only enqueues.
  Multiple registrations on one target chain through the cell's `gcNext`
  (Boehm hands back the previous finalizer's client data). `gc()` calls
  `GC_invoke_finalizers()` after `GC_gcollect()` so firing is observable.
- **`-finalizers=report`** (new flag, off by default): under manual mode
  the atexit hook first prints `[finalizers] leak: N registration(s) never
  freed` plus one `held=…  registered at line:col` line per survivor —
  the held value stringified by a per-construction-site printer that knows
  its static type, the call site captured as two constants at `register()`.
- **Held values** ride the WeakMap-value i64 box; a per-site trampoline
  (`__kml_finreg_tramp_N`) unboxes back to the callback's real parameter
  type (floats are widened to double bits), so the runtime queue stays
  generic while the callback keeps its typed ABI. Aggregate held types
  (arrays, nullable scalars) are cleanly rejected.
- Compile-time rejections: non-object target/token; `held === target` when
  both are the same identifier (it would pin the target under gc);
  `cleanupSome` (non-standard) is rejected with a pointer to the drain
  points.

## Implementation notes

- New: `codegen/llvm/emit_finalization.go` (construction, per-site
  trampoline + report printer, method dispatch),
  `codegen/llvm/runtime_finalization.go` (registry/cell runtime, death
  signals, atexit flush), `tests/finalization_test.go`,
  `examples/finalization/finalization_registry.ts`.
- Touched: the ALS pre-scan walker generalized to
  `programConstructsClass(prog, cls)` (`emit_asynchooks.go`); dispatch in
  `emit_classes.go`/`emit_call.go`/`emit_exprs_types.go`/
  `emit_exprs_vardecl.go` (handle promotion included); the
  `freeResolvedPointer` hook (`emit_memory.go`); `gc()`
  (`emit_weak.go`); `-finalizers` flag (`main.go`); `declare i32
  @atexit(ptr)` factored into a shared `ensureAtexitDecl` (was inline in
  the h2 client blob, `http2.go`).
- Registration cells are never unlinked (dead flag instead), matching the
  timer queue's never-compact posture; `unregister` and the free hook are
  linear scans of one global list.

## Side effects discovered

- Whether a gc-mode registration fires depends on conservative-scanning
  reachability, exactly like the existing WeakRef tests (the E2E test uses
  the same escape-the-frame shape).
- `Memory.free` of a dynamic (`any`) object is unsupported (pre-existing),
  so under `-compat=js` a dynamic target's callback fires at the exit
  flush, not at a free.
- V1 is same-thread: the registration list is `thread_local` under manual
  mode and the atexit flush drains the main thread only; a worker's
  registrations flush only if its own thread drains them.

## Verification

Mac (Apple Silicon): 9 E2E tests in `tests/finalization_test.go` (manual
free firing + survivor flush, unregister/token, number held, register
inside a function, `-compat=js` dynamic target, held===target and
primitive-target rejections, `-finalizers=report` output, gc-mode
collection-triggered firing alongside a WeakRef proof); example compiles
and runs; `Weak|Memory|Microtask|Timer|GCMode` suites pass; `go vet`
clean; Node oracle (`make conformance-node`) flat.
