# TDD-00119: Union response bodies for `http.listen` handlers

- **Status**: Implemented

## Context

An `http.listen` handler's response `body` field has a single static type per
program, derived by first-return-wins inference over the handler's return type
(`emit_http.go`: `streamingBody := bodyTy.IsReadableStream`). A handler that
returns `{ body: "..." }` on one branch and `{ body: req.stream() }` (or any
`ReadableStream`) on another cannot be expressed — the second shape is forced to
the first's type. This is the last caveat on the `req.stream()` HTTP-Server row
after ADR-00361 (hidden internal fields) and ADR-00362 (disturbed-body throw).

Scoped as a *deferred* design item (like the binary-safe-strings work,
[TDD-00120](TDD-00120.md)) rather than built inline during the HTTP-Server
caveat-cleanup pass: it needs a real response-body union representation and a
runtime branch in the response writer, not a local fix.

## Design

**Chosen: extend the general union subsystem** (over an HTTP-local bespoke
representation) so a handler can declare `body: string | ReadableStream<...>` as
an ordinary union and the response writer branches on its runtime tag. This
touches a common JS-language path (unions), so a Test262 run gates delivery.

### Root problem

`emitBoxValue` (`emit_dynamic.go`) tags any `IR=="ptr"` non-object value as
`kmlTagString` (2) — so a `ReadableStream` (`{IR:"ptr", IsReadableStream:true}`,
not `IsObject`) boxes *identically to a string*. And `validateUnionMembers`
rejects a `ReadableStream` union member outright (`isUnionObjectMember` requires
a plain object). So `string | ReadableStream` neither validates nor round-trips.

### Stages

1. **Distinct boxing** — add `kmlTagStream` and box a `ReadableStream` value to
   it (ptrtoint payload), ahead of the string fallthrough. `typeof` → "object",
   `===` → reference equality on the pointer (same as arrays).
2. **Union membership** — `validateUnionMembers` accepts a `ReadableStream`
   member; it is tag-distinguishable, so it does *not* count toward the
   "2+ object members need a discriminant" rule.
3. **Assignment** — `unionAllowsAssignmentFrom` accepts a `ReadableStream` value
   into a union declaring a `ReadableStream` member; object-literal field
   construction boxes a `string`/`ReadableStream` body into the union field.
4. **Response writer** — in `buildHTTPDispatcher`, when the `body` field type is
   a union, load the `{i8,i64}` box, switch on the tag: `kmlTagStream` → the
   existing chunked-transfer tail (unbox to the stream ptr); otherwise → the
   buffered `__kml_http_send_response` tail (unbox to the string ptr).
   `ArrayBuffer` as a third member is a possible follow-up; V1 targets
   `string | ReadableStream`.

### As-built notes

- Implementing the response-body union required completing the deferred general
  case: a **constrained union as an object field** now works end-to-end
  (construction boxes + checks each member via `unionAllowsAssignmentFrom`, reads
  unbox, `typeof` narrowing selects the member). `containsDynamicElement` allows
  a constrained union as an object field but still rejects it as an **array
  element** (element-level checking/boxing remains unwired — a deliberate cut
  kept from TDD-00043).
- Surfaced and fixed a latent struct-layout bug: `StructFieldSize` under-counted
  a dynamic/union field as 8 bytes (`ty.Align()`) instead of the 16-byte
  `{ i8, i64 }` box, so any struct with a union field `calloc`'d too small and
  the box store overflowed. First real struct-with-a-union-field made it
  observable (a corrupted `status` field in the response object).

### Non-goals (V1)

- Narrowing a `ReadableStream` union member in user code (`instanceof
  ReadableStream`) — the response writer branches internally; user-side
  narrowing of a stream member can stay a documented gap if not needed.
- Inferring the union return type when branches disagree — the handler declares
  the union body field explicitly (an `interface Res { body: string |
  ReadableStream<Uint8Array> }`), matching how typed handlers already work.
