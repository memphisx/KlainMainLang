# ADR-00290: TS `namespace` declarations with function merging

- **Relations**: Implements [TDD-00095](../tdd/TDD-00095.md); unblocks the Test262 harness shim's bare-`assert` form (631 files gated per the [ADR-00288](ADR-00288.md) histogram)
- **Date**: 2026-08-22

## Context / Decision

Per TDD-00095: `namespace X { export function f() {...} export const c = ... }`
at top level, merging with a same-name top-level `function X(...)` — TS's own
idiom for JS's callable-object duality.

- **Parser**: members desugar to flat top-level declarations named
  `ast.NamespaceMangle(X, member)` (`X__kmlns_member`); the member set is
  recorded on `ast.Program.Namespaces`. `parseStatement`'s single-return
  shape is bridged by a `pendingTopLevel` queue drained in `ParseProgram`.
- **Resolver**: namespace tables merge across files; `__kmlns_` declarations
  are *exempt* from the per-file `__kml_modN` rename (codegen reconstructs
  the flat name from the source-level namespace + member) — tradeoff: two
  files declaring the same namespace member collide at link time with a
  clear duplicate-symbol error instead of being file-private.
- **Codegen**: `X.member(args)` calls and `X.member` value reads resolve
  through the table (`namespaceMembers`, which also strips a `__kml_modN`
  suffix the resolver put on a *merged function's* rewritten references)
  before every other member dispatch; a local binding shadowing the name
  wins. Inference mirrors both paths.

## Harness shim modernization (same change)

`assert` becomes the real upstream shape: bare `function assert(...)` merged
with `namespace assert { ok, sameValue, notSameValue, throws, compareArray }`
— the bare-call form (631 blocked files) now compiles, and `compareArray`
(generic, element-wise `===`) exists for the first time. `Test262Error`'s
constructor message argument gained a default (`new Test262Error()` — 252
files). `assert.throws` still only checks that *something* was thrown.

## Side effect fixed in passing

The `const n = parseInt/Number(...)` declaration path truncated NaN to 0:
`emitVarDecl`'s pre-inference switch had no case for these callees, so the
slot stayed its blind i64 default. Now inferred properly (`String`/`Number`/
`Boolean`/`parseInt`/`parseFloat` cases).
