# ADR-01553: Strict code's early errors in the strict lane and in strict regions

- **Relations**: Extends ADR-00197, TDD-00230
- **Date**: 2026-10-10

## Context

- TypeScript's `strict` (the default since TypeScript 6) implies
  `alwaysStrict`: every file is strict code, so `eval` or `arguments` as a
  binding name, a parameter or an assignment target is TS1100, and
  `delete` of a plain name is TS1102. The parser raises JavaScript's
  strict-mode early errors only for a program that is strict itself (a
  "use strict" directive, a module), so the strict lane compiled
  `(arguments) => arguments` and `delete q`, which tsc rejects.
- In a sloppy program, a function opening with "use strict" was checked
  for its parameters and bindings only: `delete` of a name, `eval =` /
  `arguments++`, and bindings inside an accessor body went through; a
  class body (always strict) was checked the same narrow way.
- In sloppy code `delete name` failed to compile; JavaScript returns
  false for a declared binding (not configurable) and true for a name
  that resolves to none.

## Decision

- The checker reports the strict-code early errors (TS1100, TS1102) for a
  binding that is not sloppy: every program of the strict lane, and a
  TypeScript test case under alwaysStrict. `binder.Binding.Sloppy` (from
  `Options.AnnexB`) exempts -compat=js, whose JavaScript keeps sloppy
  semantics unless it is strict itself.
- The parser applies its whole strict-code walk to every strict region of
  a sloppy program: a function whose body opens with "use strict" and a
  class body. That walk also rejects `eval`/`arguments` as an assignment
  or update target, and checks the bindings of every function body it
  reaches.
- `delete name` in sloppy code is false for a declared binding and true
  otherwise, deleting nothing.
