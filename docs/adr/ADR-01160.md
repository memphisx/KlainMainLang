# ADR-01160: Index signatures in the checker; codegen's own strictness gates deleted

- **Relations**: `Implements TDD-00230` (P2.5, P2.7: codegen's user-facing errors move to the checker); `Implements TDD-00231` (stage 1); `Extends ADR-01159`
- **Date**: 2026-09-25

## Context

The stream module written in TypeScript (TDD-00231) failed to compile at
`if (cb) callback = cb;`, with "type 'object | undefined' is not assignable
to type 'object'". Codegen ran its own strict-null gates, which do not see
the checker's narrowing:

- `checkStrictUndefinedAssign`, at five boundaries (initializer,
  assignment, return, argument, field);
- an operator gate ("is possibly undefined in operator").

The checker already reports tsc's codes for these (TS2322, TS18048) before
codegen runs. Deleting the gates showed what they had covered that the
checker did not, and what they rejected that tsc accepts:

- `const p: string = process.env.PATH` (tsc's TS2322) was rejected only by
  codegen. The checker typed `process.env` as unanswered, because it did
  not model index signatures at all: any interface declaring one was
  unanswered.
- `const c: number = process.stdout.columns`, `process.stdout.rows * 2` and
  `const a: string = process.argv[2]` were rejected, but tsc accepts all
  three: `@types/node` types `columns` and `rows` as `number`, and
  `noUncheckedIndexedAccess` is off.
- Two tests ran JavaScript programs (a number stored into `process.env`, a
  relational comparison with `undefined`) in the strict lane, which tsc
  rejects.

The same probe hit four more gaps:

- `BufferEncoding` annotations lowered as numbers: codegen did not see
  library type aliases.
- An `any` passed to a `Buffer` parameter was "'chunk' is not an array".
- `options?.objectMode ?? false`, where `objectMode?: boolean`, emitted
  invalid IR: the optional chain wrapped the field's `{ i1, i1 }` again.
- A closure in a class method capturing a local in one branch emitted
  invalid IR ("Instruction does not dominate all uses"). Methods never ran
  the eager capture pre-scan that functions run (ADR-00619), so the local
  was boxed at its first capture, inside that branch.

## Decision

- **Checker: index signatures.**
  - Type literals and interfaces carry `StringIndex`/`NumberIndex`, from
    their own signatures or their bases'. An object type with them interns
    apart (`in.indexed`).
  - A property read falls back to the string index, and so does an element
    read by a string key. A number key reads the number index, else the
    string index. TS2339 is not reported on a type with a string index.
  - Relations follow tsc's `indexSignaturesRelatedTo`:
    - a source's own index relates to the target's;
    - only an object literal or type literal has an implicit one, through
      every property;
    - an interface or class instance without one does not fit (TS2322);
    - a target `[k: string]: any` takes any object.
  - A literal is elaborated against the index for keys the target lacks,
    and excess properties are not checked against an indexed target.
  - An intersection with an indexed member stays unanswered.
  - `for (const k in x)` acts as a non-null assertion on x in the flow, as
    tsc's `getTypeAtFlowAssignment` does. The binder records the loop as
    the store's node.
  - A generic function argument (`map(xs, first)`) leaves the type
    parameters it could infer unanswered, since instantiating it in context
    is not modelled.
- **Codegen: the gates are deleted.** The checker owns strict nulls. An
  absent `T | undefined` operand of arithmetic is `NaN` in the strict lane
  too (it was `-compat=js` only), as JavaScript's `ToNumber(undefined)`.
- **Tests follow tsc.**
  - The `columns`/`rows` test is now `TestE2EStdoutRowsArithmeticWhenNotTTY`
    (compiles; `NaN`).
  - The `argv[2]` case compiles.
  - `TestE2EProcessEnvValuesAreStrings` and `TestE2EProcessEnvMissingCompare`
    run in the `-compat=js` lane.
- **Codegen, smaller:**
  - The library's string-literal-union aliases (`BufferEncoding`) register
    as strings unless the program declares the name.
  - An `any` argument to an array or Buffer parameter unboxes to it.
  - An optional chain keeps an optional field's aggregate as is.
  - Class methods run the eager capture pre-scan.

## Side effects discovered

- BACKLOG 31 (`Object.fromEntries(e).a + 1` rejected) is fixed by the
  gate's removal: it prints `2` and `NaN` for a missing key, as Node does.
- An absent value stored into a declared `number` slot reads 0, where Node
  keeps `undefined` (BACKLOG, P3.3).
- A missing key of an interface-typed dictionary reads its zero (BACKLOG).

## Verification

  positives. Before: 3,113. No match lost. Over `examples` and `apps`: 0
  diagnostics.
- **Tests:**
  - `TestE2EIndexSignatureDictionary`, `TestE2EOptionalChainOptionalScalarField`,
    `TestE2EMethodClosureCapturedInOneBranch`,
    `TestE2EAnyIntoBufferParameter` and `TestE2EStdoutRowsArithmeticWhenNotTTY`;
  - `TestE2EStrictRejectsEnvIntoBareString` now asserts tsc's split
    (`process.env.PATH` rejected, `process.argv[2]` accepted).
- **Node:** the new tests' programs print exactly what Node v24 prints, and
  are clean under `tsc --strict`.
