# ADR-01288: `assert` as Node's lib/assert.js in TypeScript

- **Relations**: `Implements part of TDD-00230` (P3.1), `Supersedes ADR-00140`, `Extends ADR-01287`
- **Date**: 2026-09-30

## Context

`assert` was compiled directly (emit_assert.go). Its failure messages were
its own ("values are not equal"). `equal` and `strictEqual` were the same
check. `throws` ignored its matcher, and `deepStrictEqual` rejected Maps,
Sets and class instances at compile time. `rejects`, `AssertionError`,
`partialDeepStrictEqual`, `Assert` and `assert/strict` were missing.

Porting Node's own sources needed several things this compiler could not
yet do:

- **Runtime inspect options.** The messages use
  `inspect(v, { compact: false, sorted: true, depth: 1000 })`, but the
  inspector's layout and depth were fixed at compact 3 and depth 2.
- **Prototype identity.** Deep equality compares prototypes, and
  `Object.getPrototypeOf` answered null for every static object.
- **Classes and constructors as values:**
  - `assert.throws(fn, MyError)` passes a class as a value;
  - `actual instanceof expected` tests against one held in `any`;
  - `Object.prototype.hasOwnProperty.call(o, k)` was undefined.
- **Error fields.** Reading an Error subclass's own fields through `any`
  gave `undefined`, as did `err[k]` and `k in err`.
- **`assert.ok`'s source text.** Its message quotes the failing call's
  source, which Node reads off the stack.

The port also hit further bugs:

- **Error messages:**
  - `new TypeError().message` was `"TypeError"`;
  - `super(undefined)` set `"undefined"`;
  - `class E extends Error { code = 'C' }` did not compile.
- **Tuples:** pushing a literal into a `[number, string][]` crashed.
- **Ternaries:** a ternary mixing a typed-array element with a number read
  garbage.
- **Async functions:** called through a value, they received garbage
  parameters.
- **Boxing and inferred types:**
  - a missed `RegExp.exec` boxed as `[]`;
  - `const r = f(x)`, with `f: any`, typed `r` as a number;
  - `[e.message, e.flag]`, with `e: any`, was a string array.
- **Checker:** a call that no overload's arity fits passed unreported.

## Decision

**The modules.**
- `lib/node/assert.ts` ports assert.js and internal/assert/utils.js. The
  default export is `ok`, carrying every assertion as a property, and there
  is an `Assert` class. `assert_strict.ts` is `assert/strict`.
- `internal_assert_assertion_error.ts`, `internal_assert_myers_diff.ts`,
  `internal_util_comparisons.ts` and `internal_util_colors.ts` port their
  Node namesakes.
- `internal_tty.ts` takes `getColorDepth` out of `tty.ts`, so checking
  colours does not pull in `tty`'s streams.
- emit_assert.go is deleted.

**Natives** (lib/native.d.ts):
- **`inspectWith(value, depth, compact, sorted)`** sets the C inspector's
  layout options for one rendering (`__kml_inspect_opt_*`). Compact 0 is
  `false`: one entry per line. Sorted orders object, Map and Set entries.
  `-0` shows its sign.
- **`protoKey(value)`** names a value's prototype: `Object`, `Array`, a
  class (`C:Point`), a host class, a typed array kind, an error's kind or
  Error subclass (`Error:<id>`), or a dynamic object's own prototype. Two
  objects have one prototype exactly when their keys are equal. Symbol-keyed
  properties are not compared.
- **`ctorKind(value)`** reports whether a value is a constructor reference,
  and whether an Error one. **`errorConstructorName(value)`** gives the
  subclass name in `[MyErr [Error]: a]`.

**Call source.**
- The parser records each call's source (`CallExpression.Source`), with
  type syntax blanked as Node's type stripping leaves it. That covers
  annotations, `as T`, `!` and type arguments.
- The resolver marks calls of `assert`'s `ok` and `strict` bindings.
  `/** @callsite */` on a function or method, such as `Assert#ok`, marks
  calls resolved to it.
- A marked call passes its source as a hidden last argument, which the lib
  removes.

**Class values** (emit_classref.go):
- A class in value position boxes as a constructor reference, as the Error
  kinds already did. Its payload is a string constant of its own that holds
  the class's name.
- `x instanceof C`, with `C` a value, calls `__kml_dyn_instanceof`. That
  function dispatches on the reference to the static test of the class it
  names.

**`Object.prototype`'s methods.**
- `Object.prototype.hasOwnProperty.call(o, k)` is `Object.hasOwn`, and
  `propertyIsEnumerable` is membership in `Object.keys`.
- `toString` gives `[object Tag]`: host boxes by their class
  (`__kml_host_class_tag`), not their own `toString`.

**Errors.**
- A boxed error's property by run-time key goes through
  `__kml_error_get_key`, the named reads.
- `in` knows an Error's `message`, `stack`, `name`, `toString` and
  `constructor`.
- An Error subclass has a layout row of its own fields only, so its fields
  read through `any` and `Object.keys` lists only them.
- An undefined message sets none (`''`).
- A constructor-less subclass takes `(message?)`. Field initializers alone
  synthesize a constructor, and an initializer may redeclare an inherited
  field of the same type.

**Other codegen.**
- A function's expando property call dispatches before the methods named
  by string (`assert.match`).
- An async function's value spawns its task.
- A tuple element pushed or unshifted is built as the tuple.
- Two numbers of different representations meet as a number in a ternary.
- An absent nullable array boxes as null.
- A literal tsc types `any[]` is `any[]`, and a call of an `any` binding is
  `any`.
- The obj-extra hooks are defined again after the finalize-time routines,
  which can need them.

**Checker.**
- A call no overload's arity fits is TS2554, with the overloads' range.
- A class method's property records its declaration.
- `ExpandoMember` tells an expando from a namespace member.

**Compile time.** A program importing `assert` produced 600k IR lines and
took about 10 s to compile. It now produces about 120k lines and takes
about 2.3 s:
- `any` property reads and writes call one routine per property name
  instead of repeating the dispatch inline.
- The embedded C sources compile once per content, flags and clang version
  into objects under the user cache directory, then link from there. Set
  `KLAIN_NO_SIDECAR_CACHE` to disable the cache.

## Verification

On the Mac (Apple Silicon), outputs match Node v24.19.0:
`tests/assert_port_test.go`, the updated `tests/node_core_modules_test.go`
and `tests/module_decls_test.go`.
