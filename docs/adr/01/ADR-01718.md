# ADR-01718: Web streams through any, console.log and released handles

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-18

## Context

The WHATWG streams diverged from Node in several ways:

- A ReadableStream boxed into `any` used a tag of its own (9), with no layout row. Its members (`getReader`, `locked`, `cancel`, …) threw "dynamic property access … not supported". console.log printed `[object Object]` (BACKLOG #72).
- console.log of a stream printed an empty line (ReadableStream) or crashed (WritableStream, readers, writers).
- `releaseLock()` only cleared the lock bit. The released reader kept reading, its `closed` stayed shared with the next reader, and a released writer kept writing.

Probing these surfaced four more defects:

- `if (handle)` on a host handle took the string truthiness path. It read the first byte, so a writable-stream controller (state 0) was falsy.
- A bare `WritableStreamDefaultController` annotation (it takes no type argument) lowered to the structural interface. Bare reader, writer and controller annotations did the same.
- `let x!: T` was a parse error.
- `Object.assign` and `Object.defineProperties` through the dynamic path dropped symbol-keyed properties.

Separately, an Error with own properties past the depth limit printed in full with `{ ... }`, where Node prints `[TypeError]`. And a class extending Error could not declare a field named `extra`, which the Error layout used for its property bag.

## Decision

- ReadableStream is a headered host like WritableStream: `__kml_rs_alloc` writes `KML_RS_HDR` before the struct. A box is the object itself, under the object tag, so the layout table, `instanceof`, rendering and identity work as for the other host classes. Tag 9 is no longer produced.
- `emitInspectStream` renders ReadableStream, WritableStream, TransformStream, readers, writers and both controllers in Node's custom-inspect form:
  - a fresh layout of the `{ … }` data object, with the class name before it and re-indented by its level;
  - limit `depth - 1` inside, `undefined` past the limit;
  - a released writer's `desiredSize` throwing, as Node's does.
- A reader or writer handle is `{ stream, closed, ready }`. `releaseLock()` calls `__kml_rs_release` / `__kml_ws_release`:
  - the handle's closed (and ready) reject with Node's `ERR_INVALID_STATE` errors;
  - pending reads reject;
  - the stream takes fresh promises for its next reader or writer;
  - the stream slot is nulled.
- Operations on a released handle reject (`read`, `cancel`, `write`, `close`, `abort`), `releaseLock` is a no-op, and `closed`/`ready` read the handle's own promises.
- `isPlainStringTy` excludes host handles.
- `anyElemLayout` defaults a bare reader, writer or controller annotation's chunk to `any`.
- `let x!: T` sets `VarDeclaration.Definite`, which exempts the binding from the use-before-assignment check. An initializer is TS1263 and a missing annotation TS1264.
- The dynamic `Object.assign` copies own enumerable symbol keys after the string keys. `Object.defineProperties` reads the descriptor map's own enumerable symbol keys the same way (BACKLOG #112).
- The error render collapses an error with own properties, a cause or aggregated errors to `[Name]` past the depth limit.
- The Error layout's property bag is `__kml_extra`.

## Verification

macOS (Apple Silicon): `TestE2EStreamInspect`, `TestE2EReadableStreamThroughAny`, `TestE2EStreamReleasedHandles`, `TestE2EErrorWithPropsPastDepth` and `TestE2EDefiniteAssignmentAssertion` match Node. `TestE2ESymbolReflection` and `TestFallOffClosureAgainstDeclaredTypeRejected` (the flatMap case moved to the accepted list, as tsc accepts it) pass, as does `TestE2ESymbolKeysAssignDefineProperties`. So do the stream, inspect, error, Response and fetch E2E tests.
