# ADR-01140: Early errors moved from code generation to the parser

- **Relations**: `Implements TDD-00230` (P1, P2.7); `Extends ADR-01135`, `ADR-01139`
- **Date**: 2026-09-25

## Context

TS2304 ([ADR-01139](ADR-01139.md)) dropped strict-lane Test262 from 7,005
to 6,882. Diffing the pass lists against the session-start build showed
that most of the loss was parse-negative tests. Codegen had been rejecting
them, and a codegen error counts as the expected SyntaxError. Now the
checker's TS2304 fired first, and the runner rightly does not count a type
error as a syntax error.

Each of these files opens with `$DONOTEVALUATE()` and names something
undeclared. Their real early errors had never been detected by the parser:

- `yield` outside a generator;
- an undeclared private name, or `delete` of one;
- `[...x, y] = []`;
- `f() += 1`, `f() &&= 1`;
- `delete x` in strict code;
- `continue nonexist`;
- `in = 1`, `(debugger)`;
- `for (a in arr; ;)`;
- `({ a = 1 })`;
- `export` inside a `for` body.

## Investigation

- **The runner ignored `onlyStrict`.** Test262's INTERPRETING rules run
  such a file with a `"use strict"` directive prepended. The runner did not
  prepend it, so no strict-only early error could ever be seen.
- **Strictness.** The parser tracked strictness per function only, for
  bodies that start with `"use strict"`. Module code is strict throughout,
  as is a program whose directive prologue says so.
- **`in` in a `for` initializer.** The grammar forbids `in` there (`[~In]`),
  including inside an arrow's concise body, until a bracket opens. Node
  agrees: `for (let i = 0, f = () => "a" in {}; ;)` is a SyntaxError. The
  parser backtracks by resetting its token position, so a nesting counter
  kept in `advance` would drift. The depth is computed from the
  initializer's tokens instead.
- **Two tsdiag cases showed rules that must not over-reach:**
  - a method decorator runs in the context enclosing the class
    (`@(yield "")` inside a generator is valid);
  - a direct `eval` sees the enclosing class's private names.
- **Node-core suite.** The Node-core runner dropped `require('url')` and
  `require('events')`, as if their members were only globals. The resolver
  imports from those modules now (TDD-00165), and tsc rejects the bare
  `url.format` the dropped require left behind.

## Decision

- **Parser: post-parse passes** in `ParseProgram` (each a
  `ast.ForEachChild` walk). The messages are tsc's codes where tsc has one.
  - `yieldOutsideGenerator` (TS1163): context is set by each function
    declaration or expression's `IsGenerator`; an arrow is never a
    generator; a method's decorators are checked in the outer context.
  - `privateNameErrors`: a `#name` access must be declared by an enclosing
    class (18016), and `delete` of one is rejected (18011). Skipped for
    direct eval code (`parser.ParseEval`, used by codegen's static eval).
  - `labelErrors` (1116): a `break`/`continue` label must be an enclosing
    one within the same function.
  - `coverInitErrors` (1312): a shorthand property with a default is valid
    only in an assignment pattern. `ast.ObjectProperty.CoverInit` marks it.
  - `nestedModuleDecl` (1233): import and export declarations are top-level
    only.
  - For a strict program (`programIsStrict`: a leading `"use strict"`, or
    an import or export):
    - the existing `eval`/`arguments` binding rule over the top level;
    - `strictErrors`: `delete` of a name (1102), and a call as an
      assignment or update target.
- **Parser: while parsing.**
  - A reserved word the scanner leaves an identifier (`in`, `with`,
    `debugger`, `delete`, `enum`) cannot be an identifier reference (1359).
  - A logical assignment's target is never a call.
  - An array pattern needs its rest element last, without a default or a
    trailing comma (`ast.ArrayLiteral.RestTrailingComma`).
  - An object pattern's rest property is last and plain.
  - `inExcluded` stops a relational `in` inside a `for` initializer at the
    initializer's own depth.
- **Test262 runner.** It prepends `"use strict";` to an `onlyStrict` file.
- **Node-core runner.**
  - `const url = require('url')` becomes a namespace import, and
    `const EventEmitter = require('events')` a default import.
  - A destructuring require of `url`, `events`, `buffer` or `timers` becomes
    a named import.
  - The other ambient modules are still dropped.

## Side effects discovered

- **A `with` statement** (a TypeScript case with `@ts-ignore`) is now a
  parse error on `with`. The compiler has no `with` statement, and tsc
  reports it in strict code.
- **Stale tests.** Tests that expected codegen's own messages for these
  errors (the labelled-jump tests, the private-name tests, and
  `yield` outside a generator) now expect the parser's.

## Verification

- **Test262:** strict 7,019, js 7,769. At the session start they were
  6,992 and 7,721; before this change and after TS2304 they were 6,882 and
  7,738. Against the session start, the strict pass list gains 45 files and
  loses 17:
  - 15 are TS2304 on names tsc cannot resolve either (`typeof` of an
    undeclared name, …);
  - 2 are the checker's TS2367.

  Every parse-negative file the old build passed passes again.
- **Node-core:** strict 61, js 63, unchanged from the session start.
- **`tools/tsdiag`:** 1,584 of 1,586 reports match. The parse-failure count
  rose by 68 cases, and each new one has a tsc error baseline except the
  `with` case above.
- **`make examples`:** 358/358. **`make test-par`:** only the known macOS
  `-mm=gc` segfaults fail.
