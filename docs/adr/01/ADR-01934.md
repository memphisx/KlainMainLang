# ADR-01934: The last IR `define` text leaves Go; a `function` owns its `prototype`

- **Relations**: Implements TDD-00240, Implements TDD-00230, Extends ADR-01933
- **Date**: 2026-10-28

## Context

TDD-00240's ratchet (`TestIRTextOnlyShrinks`) still allowed IR `define` text in 30 files. This batch removes all of it. The only text left frames a builder's function (`funcDef`/`funcHead`), plus the IR reader in `ir_sites.go`. Every function those files defined was checked against Node after its port. Those checks turned up four bugs, fixed here.

## Investigation

- **A `function` had no `prototype` once it was a value.** `(F as any).prototype` and `const a = F; a.prototype` were `undefined`. `new` of a function held in `any` threw "is not a constructor", and so did `new` of a function expression. `instanceof` against one was always false. Only the direct `F.prototype` form worked: it went through `emit_protoclass.go`'s per-name global, which nothing else could reach.
- **A named async function passed to an array method** (`[1, 2].map(w)`) was called directly, not spawned as a task. Its first `await` suspended the caller's task, so the mapped promises read as garbage (`NaN`, `[Object]`), and `for (const p of ps) await p` segfaulted.
- **A function literal emitted straight into a dynamic slot** (an `any[]` element, an `any` object's method) printed `function () { [native code] }` from `String(f)`: `emitDynCallable` never recorded its source text.
- **Under `-compat=js`,** a declared function's `name` read as its mangled name (`P__kml_mod0`).

## Decision

- **Moved to C:**
  - `__kml_hypot` → `fdlibm.c`.
  - `__kml_arr_lit_rows` → `holes.c`.
  - `__kml_dyn_bound` → `dynobj.c`.
  - `__kml_reject_node_interp_flags` → `hooks.c`.
  - `memmem` for Windows → `strheader.c`.
  - The bigint-cell hooks' no-bigint defaults: weak definitions in `hooks.c`.
- **Built by builder functions:**
  - The NaN-box primitives (`__kml_nb_pack`/`_tag`/`_pay`) and the string-header leaves (`__kml_str_alloc`/`_len`/`_free`). They stay `weak_odr` in each unit, so every call site still inlines them.
  - `__kml_resp_collect_done`, `__kml_classref_keys` and `__kml_elem_kind_width`.
  - `__kml_native_process_version` and the prototype-bag getters.
- **Framed by `funcDef`/`funcHead`/`writeFunc`/`defineContentNamed`:** the rest. These are the per-program stubs, the `.then` runner, the coroutine trampolines, the worker entry and run loop, the island glue, `main`, the hooks constructor and the unit-registry initializers.
- **A `function` owns its `prototype`:**
  - A `function` is a declaration or expression that is not an arrow, a method, async or a generator. Its metadata row carries `FN_CTOR`.
  - `fnmeta.c` seeds the function's property bag with `prototype`, an object inheriting `Object.prototype` whose non-enumerable `constructor` is the function's own record (a record is its own identity for `===`).
  - The static `F.prototype` getter now takes that same object, through `__kml_fn_ctor_proto`.
  - `__kml_dyn_construct` falls back to `__kml_dyn_construct_fn` for such a function. It builds an object inheriting `c.prototype`, calls `c` with it as `this`, and keeps an object result.
  - `__kml_gen_has_instance` answers `instanceof` for constructor functions as well as generator functions.
- A named callback whose signature may suspend goes through `emitSpawnCall`, as a direct call does.
- `emitDynCallable` records the literal's source text and unmangles the display name.

## Implementation notes

- **Two mistakes during the port, both caught by Node comparisons:**
  - `__kml_dyn_bound` in C first passed the call's `this` instead of the bound one (`env[1]`).
  - The first `constructor` value was a heap copy of the record. A copy is a different identity, so `o.constructor === F` was false.
- **The prototype-bag getter** builds the function's value with `emitExpr(Identifier)`, not `emitNamedFuncValue`. Under `-compat=js` a declaration's value is its dynamic callable, and the first metadata registration of a symbol wins.
- **`instanceof` against `any`** now always links the generator-prototype runtime, since any right operand may be a function.

## Side effects discovered

- BACKLOG `-compat=js` #137 (function-expression constructors) is fixed by this change and removed from the BACKLOG.

## Verification

- `TestIRTextOnlyShrinks`: the allowance map now holds only `funcstate.go` and `ir_sites.go`.
- Probes against Node v24 match. They cover:
  - `Math.hypot` edge cases.
  - Nested array literals.
  - Response stream collection.
  - `.then`/`.catch`/`.finally` chains.
  - `process.version`, and the `-p` guard (exit 9).
  - Bound functions.
  - Class references through `any`.
  - Record views, and the NaN-box and string primitives.
  - `prototype`, `new` and `instanceof` through `any`, in the strict lane and under `-compat=js`.
- New E2E tests:
  - `TestE2EAsyncNamedFunctionAsCallback`
  - `TestE2EDynamicFunctionLiteralSourceText`
  - `TestE2EFunctionPrototypeObject`
- The Worker suite and targeted E2E suites were run on the Mac (Apple Silicon).
