# ADR-00437: klain:webview Stage 1 — the Webview handle and window methods

- **Relations**: Implements [TDD-00142](../tdd/TDD-00142.md); Extends [ADR-00436](ADR-00436.md), [ADR-00432](ADR-00432.md)
- **Date**: 2026-08-28

## Context

Stage 1 is the window itself: `new Webview(opts)` and the synchronous method
surface (`navigate`/`html`/`setTitle`/`setSize`/`init`/`eval`/`run`/
`terminate`/`destroy`). One window per process in V1.

## Investigation

`new http.Agent(...)` (ADR-00432) is the closest posture: a parse-time
constructor returning a ptr-slot handle, flag-tagged (`IsHTTPAgent`), dispatched
in `emit_call.go`. The `IsHTTPServer`/`IsChildProcess` handles show the same
five touch points: parser case, type flag, emit dispatch, inference
(`emit_exprs_types.go`), var-decl handle case (`emit_exprs_vardecl.go`).
`klain:http`'s marker in `resolver/virtual_modules.go` and the stream-class
identity binding in `resolver/rename.go:527` are the module-plumbing precedents.

## Decision

- Handle: a calloc'd `{ ptr webview_t, ptr boundListHead }` (`WebviewType`,
  `IsWebview`). Field 0 is the opaque `webview_t`; field 1 heads the bound-list
  (Stage 2). Constructor validates `{title,width,height,debug}`, calls
  `webview_create(debug, null)`, and applies title/size.
- Methods load `webview_t` from field 0 and call the extern C API. `eval` is
  routed through `webview_dispatch` (a fixed `@__kml_wv_eval_tramp`) so it is
  thread-safe from any thread — the one uniform path, safe on the GUI thread too.
- `klain:webview` is a virtual module; `Webview` binds as identity (a parse-time
  constructor), like stream's class names.
- A second `new Webview` is a clean compile-time rejection
  (`webviewConstructed` guard).

## Implementation notes

- Extern declarations live in `runtime_webview.go` (`ensureWebviewRuntime`),
  declared once; `emit_webview.go` holds the constructor + dispatch.
- `run()` blocks (it owns the GUI main loop); statements after it are the
  shutdown path — the honest contract, no faked continuation.

## Side effects discovered

None beyond the event-loop coexistence already scoped by the TDD (servers/timers
belong in a Worker; the GUI loop owns the main thread).

## Verification

- macOS: an inline-HTML window opens and renders; `setTitle`/`setSize`/`eval`/
  `init`/`terminate` all take effect (manual run) and `run()` returns on
  terminate.
- Compile-tier E2E (`TestE2EWebviewCompiles`) builds a full method-surface
  program; `TestE2EWebviewSecondWindowRejected` asserts the one-window guard.
- Linux: compile-tier only, not yet run (no display / pending the Ubuntu box).
