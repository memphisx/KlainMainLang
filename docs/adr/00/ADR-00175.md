# ADR-00175: Conformance harness — kill the whole process group and bound the pipe wait

- **Date**: 2026-08-12

## Context

While regenerating `CONFORMANCE-RESULTS.md` to measure [ADR-00174](ADR-00174.md), the full-corpus run hung: it reached `53000/53578 done` and then stalled for 10+ minutes without writing the report. A handful of Test262 files generate tens of MB of LLVM IR (39 MB observed for `.conformance-out/w9.ll`), on which `clang -O2` runs for many minutes — far past the 5s per-file timeout that was supposed to bound it.

## Investigation

`runOne` compiled each file with `exec.CommandContext(cctx, "clang", ...).CombinedOutput()` (`main.go:286`), with `cctx` a 5s-timeout context. Observed with `ps` during the hang: the `clang` *driver* had been killed by the context, but its forked `clang -cc1` grandchild (pid confirmed running standalone) was still consuming 100% CPU after 6+ minutes.

Two compounding Go `os/exec` behaviors:
1. `CommandContext` kills only the direct child (the driver), not the `-cc1` grandchild it forked — the grandchild is orphaned and keeps running.
2. `CombinedOutput()` (and `Wait` generally) blocks until the output pipe's write end is closed. The orphaned grandchild inherited that pipe, so `Wait` blocked indefinitely even though the driver was already dead.

The committed report had been generated successfully before, so this is intermittent (depends on whether the orphaned grandchild is reaped promptly) — but a single bad file being able to stall the entire run past its timeout is a real robustness bug.

## Decision

Route both the `clang` compile and the compiled-binary run through a `killableCommand` helper that:
- sets `SysProcAttr{Setpgid: true}` so the child starts its own process group, and
- sets `Cmd.Cancel` to `syscall.Kill(-pid, SIGKILL)` — a negative pid signals the whole group, reaping the `-cc1` grandchild too — and
- sets `Cmd.WaitDelay = 2s` (Go 1.20+) to bound any residual `Wait` blocked on a pipe an escaped descriptor still holds.

## Implementation notes

- `tools/conformance/main.go` — new `killableCommand`; both invocation sites switched from `CommandContext`/`CombinedOutput` to it. The clang site now captures combined output into a single buffer explicitly (it no longer uses `CombinedOutput`).
- Unix-only `SysProcAttr` fields; fine on this project's Linux + macOS targets.
- Each pathological file now costs ~its 5s timeout per worker (a clean `CLANG_TIMEOUT`) instead of stalling the run.

## Side effects discovered

None beyond the ADR-00174 work that surfaced this.

## Verification

- `go vet ./tools/conformance/` clean; builds.
- Full `make conformance` (Linux) now **completes** (~report written), where it previously hung — the run producing the ADR-00174 numbers (4998 passing). Verified on Linux; not re-run on macOS (same unix process-group semantics apply).
