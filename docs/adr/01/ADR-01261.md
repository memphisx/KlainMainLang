# ADR-01261: `Map | undefined` and generic `T | undefined` keep their absence

- **Date**: 2026-09-29

## Context

Two ways the `| undefined` of a type was lost:
- A `Map<K, V> | undefined` (or `Set<T> | null`) parameter compared with
  `undefined` folded to a constant: the Map/Set arms of the annotation
  resolver dropped the absence. `p !== undefined` was always true, and
  calling methods on the absent map crashed.
- In a generic class, `get(): T | undefined` with an object `T` returned a
  garbage pointer for `undefined`. The generic signature's substitution
  replaced `T` with the argument and dropped the reference's own absence.

## Decision

- An absent-able Map/Set, object or class annotation keeps `Nullable`
  after resolution.
- A substituted type parameter keeps the reference's `| undefined` /
  `| null`, as the type-parameter scope already did.

## Verification

Mac (Apple Silicon): `TestE2ECollectionOrUndefinedAndBranchCapture` and
`TestE2EGenericOptionalObjectReturn` match Node.
