# ADR-01418: fetch fails with Node's `TypeError: fetch failed` and its cause

- **Date**: 2026-10-05

## Context

A failed `fetch` rejected with a `TypeError` whose message was libcurl's
(`Couldn't connect to server`), a recorded caveat. Node's (undici's) is
`fetch failed`, with the reason as its `cause`.

## Investigation

Node 24 on the Mac:

- refused: cause `Error: connect ECONNREFUSED 127.0.0.1:39999` with
  `errno` (-61), `code`, `syscall: 'connect'`, `address`, `port`;
- unknown host: cause `getaddrinfo ENOTFOUND host` with `errno` -3008,
  `code`, `syscall`, `hostname`;
- a port on the fetch standard's bad-port list (1, 22, 6000, …): cause
  `Error: bad port`, without a connection attempt;
- `localhost` refusing on both addresses: an `AggregateError` cause.

libcurl gives the OS errno (`CURLINFO_OS_ERRNO`) after a failed connect, but
on macOS no `CURLINFO_PRIMARY_IP`. `fetch.c` allocated its errors at 24
bytes (`kerr`) and its AggregateError at 112, under the Error layout's 120,
so a read of `.cause` or any later Error field went past the allocation.

An AggregateError kept its errors array and length in the Error layout's
`code` and `errcode` fields, so `Object.keys`, `JSON.stringify` and
`console.log` showed a `code` (the array pointer read as a string) and an
`errcode`, and `(e as any).code` read garbage.

## Decision

- A finished transfer that failed records its cause on the pending fetch
  (a new last field) before the easy handle is freed: a connect failure
  becomes the system error (address and port from libcurl, or else from the
  URL, a name as its first address), a lookup failure the `getaddrinfo`
  error, anything else an `Error` with libcurl's message.
- The rejection is `TypeError('fetch failed')` with that cause; a request
  error (a GET/HEAD body) keeps its own message.
- A URL on a bad port fails before a transfer starts (code -3).
- Errors built in `fetch.c` are allocated at the full Error layout.
- An AggregateError is the Error layout with `{ errors, length }` after it
  (`aggregateErrorStructIR()`, sized from `errorObjType` so they cannot
  drift; `KML_AGG_ERRORS`/`KML_AGG_SIZE`/`KML_ERRKIND_AGG` in the layout
  header for C). Its Error fields stay absent.
- `util.inspect` (dynjson.c) shows an Error's options cause after its own
  properties as `[cause]: …`, nested errors indented, as Node does; an
  assigned `cause` stays an ordinary `cause:` property. An AggregateError's
  errors show as `[errors]: [ … ]`.

## Side effects discovered

A name whose every address refuses (`localhost`) is Node's `AggregateError`
cause (code, one connect error per address in `getaddrinfo` order), and
`.errors` of an AggregateError held in `any` now reads its array (it read
`undefined`). Recorded as caveats: other transport failures' causes carry
libcurl's message, not undici's error codes; an explicit
`{ cause: undefined }` is not shown as `[cause]: undefined`.

## Verification

Mac (M4): the refused (IPv4, IPv6), unknown-host and bad-port cases print
what Node prints, `JSON.stringify(e.cause)` included;
`TestE2EFetchFailedCause`; `TestE2EErrorInspectCause`. `Promise.any` of
rejected promises and of failed fetches, `new AggregateError` and its
`structuredClone` print what Node prints.
