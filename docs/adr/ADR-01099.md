# ADR-01099: Invalid IR names the codegen site that emitted it (`KML_IR_SITES`)

- **Relations**: `Implements TDD-00230` (Phase 0, P0.1)
- **Date**: 2026-09-23

## Context

When clang rejects a generated module, its error points at a line of a
generated `.ll` file. Working back from that line to the Go code that wrote it
took a separate hunt for every invalid-IR fix, about 90 of them across the ADR
history. [TDD-00230](../tdd/TDD-00230.md) makes invalid IR report its origin
directly: that is the first safety net for the restructure. It also lets the
conformance histogram rank emitters rather than clang messages.

## Investigation

- **Where text enters the module.** Every line goes through four writers in
  `codegen/llvm/emitter.go`: `emitInstr`, `emitTerminator`, `emitAlloca` and
  `emitGlobal`. `emitGlobal` also takes whole multi-line runtime chunks.
  Function bodies are assembled by concatenating those builders.
- **Does anything read the text back?** No code parses the emitted text after
  the fact. The one test that inspects it (`emit_store_guard_test.go`) checks a
  substring, so a trailing comment leaves it unaffected.
- **Where clang errors surface.**
  - The driver goes through `RunClangLink` (`hostclang.go`), which streams
    clang's stderr straight through.
  - The test harness reports them at 22 identical
    `t.Fatalf("clang: %v\n%s", err, out)` sites.
  - The conformance runner builds a `CLANG_ERROR` reason from the first line and
    keeps each failing module under `clang-fail/`.
- **Rejected alternative: a typed IR builder** that checks operand types as each
  instruction is emitted. It would mean rewriting about 8,300 `emitInstr` calls.
  The disagreements it would catch come from types and representations being
  decided in several places, which TDD-00230's phases 2 and 3 remove at their
  source.

## Decision

- **Tagging emitted lines.** With the environment variable `KML_IR_SITES` set,
  each writer passes its text through `withSite`:
  - A single line gets a trailing `  ; @site file.go:N < file.go:M` comment:
    the first two stack frames outside the writers themselves.
  - A multi-line chunk gets that comment as a line of its own above the chunk.
- **Reading a site back.** `AnnotateClangOutput(out)` finds every
  `x.ll:N:C: error:` line in clang's output, reads line N of that file, and
  inserts `  emitted by <site>` beneath the error. The site is taken from line N
  itself, or from the nearest `; @site` comment above it within the same
  function, including the one directly above a chunk's `define`.
- **Where it's applied.**
  - `RunClangLink` captures and annotates stderr when sites are on.
  - The test harness's 22 clang failure sites print the annotated output.
  - The conformance runner appends ` @ <site>` to the `CLANG_ERROR` reason, and
    writes the annotated output to `clang-fail/<test>.clang.txt`.
- **With the variable unset,** `withSite` returns its input unchanged and the
  output is byte-identical.

## Implementation notes

- **New:** `codegen/llvm/ir_sites.go` and `codegen/llvm/ir_sites_test.go`.
- **Changed:**
  - `codegen/llvm/emitter.go`: the four writers.
  - `codegen/llvm/hostclang.go`: `RunClangLink`.
  - `tools/conformance/main.go`: the `CLANG_ERROR` path.
  - `tests/*.go`: the 22 failure sites. The two Windows-only files among them
    gained the `llvm` import.
  - `README.md`: a "Tracing invalid IR to the emitter" section.
- **Formatting:** `gofmt` was also applied to `codegen/llvm/dynjson_c.go` and
  `tests/bigint_any_test.go`, which were unformatted from earlier work.
- **Design choices:**
  - Two frames are recorded, not one, because the direct caller is often a thin
    helper and the frame above it names the construct.
  - `irSites` is read once at package initialisation.

## Side effects discovered

- **The first annotated failure names its origin.** Test262's
  `language/statements/switch/scope-lex-close-dflt.js` in the js lane fails
  with:

  ```
  CLANG_ERROR: error: floating point constant invalid for type @ emit_stmts.go:1427 < emit_stmts.go:181
  ```

  A `switch` on a string discriminant compares each `case` through
  `__kml_str_cmp`, even when the case label is a number. That is a
  representation mismatch, left to TDD-00230 phase 2, where the checker types
  each case label.
- **The test harness assembles the clang link line by hand,** one
  `append…Backend` call per C sidecar in `tests/compiler_test.go`, apart from
  `main.go` and the conformance runner's generic `EmbeddedCSources` loop. This
  was already BACKLOG §0 item 23.
- **About 40 emitters close a function by concatenating `allocas` and `body`
  themselves,** with no shared finish helper. That is left to TDD-00230 P3.5,
  which splits the Emitter by lifetime.

## Verification

All on macOS arm64 (M4):

- `go test ./codegen/llvm/ -run 'AnnotateClang|WithSite'` passes. It covers a
  single-line site, a chunk site above a `define`, output with no IR errors
  left unchanged, and frame skipping.
- `KML_IR_SITES=1 make examples` gives 357 passed, 0 failed: the comments never
  break the IR.
- `KML_IR_SITES=1 go run ./tools/conformance -category=language/statements/switch -compat=js`
  reports the site-attributed `CLANG_ERROR` above, and the kept `.clang.txt`
  carries the `emitted by` line.
- `go vet ./...` passes, and so does `GOOS=windows go vet ./tests/`.
