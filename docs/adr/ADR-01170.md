# ADR-01170: `net`, `tls`, `http` and `https` in TypeScript on Node's layering

- **Relations**: `Implements [TDD-00231](../tdd/TDD-00231.md)` (stage 4); `Extends [ADR-01166](ADR-01166.md)`, [ADR-01167](ADR-01167.md)
- **Date**: 2026-09-26

## Context

TDD-00231 stage 4 moves HTTP's request and response onto the `stream`
module written in TypeScript. Node builds them in layers: `net` (a Socket is
a Duplex over a TCP handle), `tls` (a TLSSocket is a Socket whose handle
carries a TLS session), and `http`/`https` (`_http_common`,
`_http_incoming`, `_http_outgoing`, `_http_server`, `_http_agent`,
`_http_client`) over a native HTTP/1 parser (llhttp). The code-generated
`net`, `tls` and `http` server/client had their own behaviour at every seam:
a blocking TLS handshake, an IPv4-only bind, `listen()` errors thrown
synchronously, handler fibers, a libcurl client whose `IncomingMessage` was
not a Readable, request fields Node does not have (`req.path`).

## Investigation

- Node's sources (v24) were ported module by module; each behaviour probe
  ran against Node v24.19 (parse errors and their `bytesParsed`,
  `requireHostHeader`'s 400, `listen` errors on the next tick, keep-alive
  timeouts of `keepAliveTimeout + keepAliveTimeoutBuffer`, the
  `connectionsCheckingInterval` sweep, verify errors' messages).
- The existing `klainpool.c` thread pool already had the loop hooks a TCP
  handle table needs (fd sets, dispatch after `select`), and the reactor
  already drains microtasks after each dispatch.

## Decision

- **Native primitives** (`lib/native.d.ts`, `klainpool.c`): TCP handles as
  ids — listen (dual-stack `::`), connect (non-blocking; failure reported on
  the next dispatch), read start/stop with the bytes taken into a Buffer,
  write (synchronous when it can, else queued), shutdown, close, no-delay,
  keep-alive, ref/unref, address; Unix-domain pipes; `dns.lookup` on the
  pool. A handle can carry a TLS session (`tlsStart`): the pool drives its
  handshake and I/O through operations `tlssrc/tlshandle.c` installs
  (OpenSSL; a separate unit linked with `-lssl` only when used), reporting
  `onSecure` and the verify result. An HTTP/1 parser
  (`threadpoolsrc/klainhttp.c`) with llhttp's strict rules and error codes:
  `execute` runs to the next event (headers, body chunk, message complete,
  upgrade, error) and the getters read the message.
- **`lib/node/net.ts`**: Node's `lib/net.js` — Socket (a Duplex), Server,
  `connect`/`createConnection`/`createServer`, `isIP*`, errors as Node
  builds them (`ErrnoException`, `ExceptionWithHostPort`,
  `UVExceptionWithHostPort`, `getaddrinfo ENOTFOUND`).
- **`lib/node/tls.ts`**: TLSSocket over a released net handle, `tls.Server`
  wrapping each connection (`secureConnection`, `tlsClientError`),
  `tls.connect`, `createSecureContext`.
- **`lib/node/internal_http.ts`** (the `http` module's part in TypeScript):
  the parser wrapper, IncomingMessage (a Readable), OutgoingMessage,
  ServerResponse, the server's connection handling (`_kmlHttpServerCore`,
  shared with https), Server, Agent (keep-alive pooling, unref'd free
  sockets), ClientRequest, `request`/`get`. `lib/node/internal_https.ts`:
  `https.Server` (a `tls.Server` running the same core), `https.Agent` over
  `tls.connect`, `request`/`get`. `lib/node/klain_ws.ts`: `klain:ws`'s
  WebSocketServer over the server's `'upgrade'` event.
- Builtin modules import each other by relative path; a `_kml`-prefixed
  export is shared among them, not a member of the module.
- A bare `IncomingMessage`/`ServerResponse` (no import) is tsc's TS2304: a
  name a module written in TypeScript exports is bound by its import.
- Windows keeps the code-generated `net` (its handles are POSIX sockets).
- A cluster worker's listen sets `SO_REUSEPORT` and announces its port and
  host to the primary: `cluster`'s `'listening'` address is Node's (`null`
  for a server on every address, else the host).

## Side effects discovered

- `http.request(new URL(…))` is not accepted: a `string | URL | options`
  parameter needs a union of two object types code generation cannot tell
  apart at run time (BACKLOG).
- `setHeaders` takes a `Map` only (the same limit, with `Headers`).

## Verification

Mac (Apple Silicon): probes of each layer against Node v24.19 —
net echo/connect errors/Unix sockets, TLS client/server with verify
failures, https server and client, HTTP keep-alive and idle exit, parse
errors, upgrade, `klain:ws` against Node's WebSocket client. The net,
http, websocket, tls tests (updated to Node's behaviour where they asserted
the code-generated one) and examples.
