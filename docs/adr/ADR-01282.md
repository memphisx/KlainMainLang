# ADR-01282: `node:test` and Node's test-suite helpers in TypeScript

- **Relations**: `Implements part of TDD-00230` (P3.1), `Supersedes part of TDD-00140`, `Supersedes part of TDD-00122`
- **Date**: 2026-09-29

## Context

Code generation emitted `test` itself:

- The runner ran each test at registration. Top-level code after a
  `test()` ran after it, where in Node it runs first.
- It printed `ok - name` lines and a one-line summary, not Node's spec
  reporter.
- `beforeEach` and `afterEach` were single slots.
- `mustCall` wrapped only fixed signatures.
- `mustSucceed` counted calls without checking the error.

The bare `test` specifier mixed the runner with Node's test-suite helpers
(Node's `test/common`, which this compiler's copies of Node's tests
import). Those helpers include a `skip` that exits the process, unlike
node:test's `test.skip`.

## Decision

### `node:test` (`lib/node/test.ts`)

- Tests register while the module runs and run afterwards, one at a time,
  in registration order. A suite's function runs when the suite is
  registered.
- Hooks:
  - `before` and `after` run once around their scope;
  - `beforeEach` and `afterEach` run around every test inside their
    scope, outermost first, not around suites;
  - skipped tests run no hooks.
- The TestContext has `test`, `skip`, `todo`, `diagnostic`, `plan`,
  `name`, `fullName` and its own hooks. `test.skip`, `test.todo`,
  `test.only` and the default export's properties exist too.
- Output follows the spec reporter:
  - lines `✔`, `✖` and `﹣` with `# SKIP`, `# TODO` or a message;
  - `▶` headers for tests and suites with children, indented;
  - `ℹ` diagnostics;
  - the `ℹ tests … duration_ms` summary;
  - the `✖ failing tests:` section.
- Output ordering:
  - lines are held until the event loop turns, or the run ends, as
    Node's reporter stream delivers them;
  - a test that waited on the loop reports before the next starts.
- Durations are hrtime nanoseconds / 1e6, as the runner measures them.
- A failure sets `process.exitCode = 1`.

### Node's test-suite helpers (`lib/node/test_common.ts`)

- The bare `test` specifier maps to this file (`lib.ModulePath`).
- It holds `mustCall` and `mustCallAtLeast`, with overloads giving the
  callback's type:
  - the counts are checked on `'exit'`;
  - a mismatch prints Node's `Mismatched <name> function calls. Expected
    exactly N, actual M.` and exits 1.
- It holds `mustSucceed`, which asserts no error, then calls with the rest
  of the arguments.
- `mustNotCall`, `expectsError`, `expectWarning` (checked as warnings
  arrive), `skip` (`1..0 # Skipped: …`, exit 0) and the platform probes
  are there too.
- The runner's functions are re-exported.
- The codegen runner and helpers are deleted (`emit_nodetest.go`,
  `emit_testmod.go` and their runtimes).

### Fixes needed along the way

- **Calling a function's own function-valued property.** `f.p(…)` on a
  TypeScript expando was "no method". It now calls through the boxed
  function's property bag (`funcOwnPropCall`).
- **A call typed `any` in codegen but a function by the checker.** An
  overload that returns its argument's type (`mustCall(fn)`) now converts
  its result to that function type, when the parameters are numbers,
  strings, booleans or `any` (`checkerRefinedCallType`).
- **The `Function` type.** It is a dynamic value. Before, it was an
  object: `typeof` said `'object'`, and `.name` read `null`.
- **`crypto.generateKeyPair`'s callback** may be a function value. It is
  called with `(null, publicKey, privateKey)`, as in Node. The special
  two-parameter shape for the old `mustSucceed` is gone.
- **A top-level `bigint` binding** is a module global: functions can read
  it. Before, it was "undefined variable".

## Verification

Mac (Apple Silicon):

- Every `node:test` test compares the whole report with Node v24.19.0's,
  durations normalised.
- The failure case matches up to the error text, which omits the location
  line and the stack.
- The `test` module and `crypto` suites pass.
