# ADR-00176: Bare `any`/`unknown` as a function/method parameter and return type (TDD-00062 Staged V2)

- **Relations**: `Implements TDD-00062`. `Extends ADR-00008` (the original `any`/`unknown` staging), `Extends ADR-00174` (call-site dynamic-argument boxing).
- **Date**: 2026-08-12

## Context

ADR-00008 shipped `any`/`unknown` as a runtime-tagged `{ i8, i64 }` box but deliberately *guarded out* their use as a function parameter or return type (an active rejection, so the box couldn't silently produce broken IR). [TDD-00062](../tdd/TDD-00062.md) scoped lifting that guard: it is core type-system completion and the enabling machinery already existed (boxing/unboxing/`===`/`typeof` from ADR-00008; the dynamic-param *binding* path already used by `@erased` generics and constrained-union params; call-site argument boxing from ADR-00174).

## Investigation

- The rejection lived at four+ guard sites, all gated on `isUnconstrainedDynamic(ty) || containsDynamicElement(ty)`: function-declaration params/return (`emit_func.go`), class/static-method params (`emit_classes.go`), and the arrow/function-expression equivalents.
- `containsDynamicElement` (`emit_dynamic.go:58`) deliberately does *not* inspect the top level, so **dropping `isUnconstrainedDynamic` from a guard while keeping `containsDynamicElement` allows bare `any`/`unknown` at the top level while still rejecting `any[]`/`{x:any}`** — and it subsumes the old `@erased`-only carve-out (an erased `T[]` is `IsArray`, not top-level `IsDynamic`, so it still fails).
- The dynamic-param binding path (`emit_func.go:196`) already allocas+stores a `{ i8, i64 }` param; a constrained union (also `IsDynamic`) and an `@erased` bare-`T` param already prove it round-trips.
- `emitBoxValue` already boxes every scalar shape *and objects* (`ptrtoint`, tag=object); `===` on two boxed objects compares payloads = pointer identity = correct JS reference equality. So object arguments work once the guard is lifted.
- **Gap found (pre-existing, ADR-00008 invariant violation):** boxing an *array* value produces broken IR — an array is a `{ ptr, i64 }` aggregate, and `emitBoxValue` fell through to the `IR=="ptr"` branch and `ptrtoint`'d the whole aggregate (`'{ ptr, i64 }' ... expected 'ptr'`). Reproduced independently of the param work via `let x: any = [1,2,3]`, confirming it lives at the shared `emitBoxValue` chokepoint, not the param path.
- **Gap found:** `emitClassCall` (instance-method dispatch) used a bare `coerce` for arguments, same shape the static path had before ADR-00174 — it "worked" only via ADR-00174's coerce backstop, which skips constrained-union member validation.

## Decision

1. Lift the guard for the top-level bare `any`/`unknown` parameter and return position across **every function shape** — function declarations, class/static methods, arrow functions, and function expressions — dropping `isUnconstrainedDynamic` and keeping `containsDynamicElement` (now the sole rejection, with a message naming the nested array/object case). The closure-call path (`emitClosureCallByPtr`) already boxes a dynamic-typed argument, so arrow/function-expression params needed only the guard relaxation.
2. Reject boxing an array centrally in `emitBoxValue` with a clean error, restoring ADR-00008's "clean error, never broken IR" invariant for every box site (var decl, return, assignment, and — new — an argument to an `any` parameter).
3. Make `emitClassCall` box dynamic arguments explicitly (mirroring the free-function and static-method paths), so instance-method `any`/union params validate and box the same way everywhere.
4. Update the Test262 harness shim's `assert.sameValue`/`notSameValue`/`throws` to take bare `any` — a strict superset of the previous scalar union (now covers object arguments by reference identity).

**Deferred** (still rejected, tracked in TDD-00062): boxing an array value (so passing an array into an `any` slot is a clean error — lifted immediately after in [ADR-00177](ADR-00177.md), which boxes arrays by reference); a bare-`any` array-element/object-field (`any[]`, `{ x: any }`), including the `any[]` a HOF like `.map(x => …: any)` would construct.

## Implementation notes

- `codegen/llvm/emit_func.go` — guard relaxations for function-declaration, arrow-function, and function-expression param+return; `codegen/llvm/emit_classes.go` — method param guard relaxation + explicit dynamic-arg boxing in `emitClassCall`.
- `codegen/llvm/emit_dynamic.go` — array-boxing guard in `emitBoxValue`.
- `tools/conformance/harness-shim/assert.js` — `any` parameters.
- No aggregate coverage-% change: the `any`/`unknown` rows were already ✅ (Staged); this widens their capability and shrinks their caveat, and they remain excluded from Strict Coverage (arithmetic/nested/array-boxing caveats remain).

## Side effects discovered

The array-boxing broken-IR gap (item 2) was pre-existing and independent of this feature — `let x: any = [1,2,3]` reproduced it. Fixed here as part of upholding the invariant.
