# ADR-00833: `undefined !== null` for absent scalars, and `Map.get()` misses are `undefined`

- **Relations**: Extends [TDD-00064](../tdd/TDD-00064.md) (the `{ i1, T }` nullable scalar) and [TDD-00187](../tdd/TDD-00187.md) (the `T | undefined` sentinel)
- **Date**: 2026-09-10

## Context

Hunting remaining `T | undefined` adopters surfaced two linked correctness bugs:

1. For **any** absent `T | undefined` scalar (e.g. `[1,2,3].find(x => x > 9)`),
   `x === null` returned `true`. In JS `undefined === null` is **false** — the
   compiler was treating strict `=== null` and `=== undefined` identically,
   keyed only on the presence bit, ignoring the null-vs-undefined distinction.
2. `Map<K, scalar>.get(missingKey)` was typed `V | null` and rendered/compared as
   `null`; Node's `Map.get` miss is `undefined` (`m.get(k) === undefined` true,
   `=== null` false).

## Investigation

`emitNullableScalarNullCompare` (`emit_nullable_scalar.go`) reduced `x == null` /
`=== null` / `== undefined` / `=== undefined` all to `presenceToNullCompare`,
which only tests the presence bit — so every nullish comparison against an absent
value returned the same answer regardless of (a) strict vs loose and (b) whether
the literal was `null` or `undefined`. The AST already distinguishes them:
`ast.NullLiteral.IsUndefined`, and the value's `Type.IsUndefined`. For Map.get,
`emitMapGetNullable` set `Nullable` but not `IsUndefined`, and the matching
`inferExprType` case did the same.

JS semantics: strict `===`/`!==` require the nullish *kind* to match (an absent
`undefined` strict-equals only `undefined`, an absent `null` only `null`); loose
`==`/`!=` treat `null` and `undefined` as interchangeable.

## Decision

- `emitNullableScalarNullCompare`: capture the literal's `IsUndefined` and the
  value's `IsUndefined`. For strict `===`/`!==` where the kinds differ, the
  result is a compile-time constant (`===` → `false`, `!==` → `true`) — never
  equal, independent of the presence bit. Otherwise (loose, or strict with
  matching kinds) it stays presence-based as before. Loose `== null` /
  `== undefined` therefore still both match an absent value.
- `Map.get()`/`WeakMap.get()` are now `V | undefined` for **both** value
  shapes: a scalar value sets `IsUndefined` on the `{ i1, T }` aggregate
  (`emitMapGetNullable`), and a pointer value (string/object/class) reads its
  null-pointer miss as `V | undefined` via `mapGetUndefinedablePtr`
  (arrays/dynamic/already-nullable excluded). `inferExprType`'s map `get` case
  mirrors both. **`URLSearchParams.get` is excluded** (receiver
  `IsURLSearchParams`) — it is spec'd `string | null` and keeps `null`. A
  `URLPattern.exec()` result is a plain Map (not a flagged receiver), so a
  missing group now reads `undefined` — which is faithful (an unmatched optional
  group is `undefined` in real URLPattern); the guard also names `IsURLPattern`
  defensively for any direct URLPattern-as-map use.

## Implementation notes

`emit_nullable_scalar.go` (`emitNullableScalarNullCompare`); `emit_collections.go`
(`emitMapGetNullable`); `emit_exprs_types.go` (map `get` inference). The kind
mismatch is resolved at compile time (both `IsUndefined` flags are static), so no
extra runtime work on the hot path.

## Side effects discovered

Several tests asserted the pre-fix (non-faithful) behavior and were corrected to
Node's truth: `TestE2EMapGetScalarMissingVsZero` (`m.get('missing')` prints
`undefined`, `=== null` false), `TestE2EMapGetMissingKeyPrintsNull` → renamed
`…PrintsUndefined`, `TestE2ENullEquality` (`null === undefined` is false), and
`TestE2EURLPatternMultiComponentAndOptionalGroup` (an unmatched optional group is
`undefined`, not `null`). `URLSearchParams.get` was verified to still return
`null` (spec) — the reason the pointer-value flip is gated on the receiver type.

## Verification

macOS (Apple Silicon M4): `[1,2,3].find(x=>x>9)` → `undefined`, `=== undefined`
true, `=== null` false, `== null` true — all matching Node; `Map<string,number>`
get miss → `undefined`, `=== undefined` true, `=== null` false, `?? 99` → 99.
Updated `TestE2EMapGetScalarMissingVsZero` + Map/collections/URLPattern/nullable/
undefined and the array/expr/process/object/string suites green.
