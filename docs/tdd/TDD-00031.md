# TDD-00031: Terminal UI primitives (raw mode, tty size, key reads)

- **Status**: Not Started
- **Date**: 2026-08-06

## Context

Raised while researching what it would take to build interactive terminal UIs (progress bars, prompts, key-driven navigation) on top of this compiler — a natural extension of the project's existing CLI-tooling priority (see `CLAUDE.md`'s Project direction), not a new one.

Direct research into how established Node TUI/CLI libraries (oclif, `inquirer`, `blessed`, `chalk`/`ansi-escapes`) are actually built ruled out the tempting shortcut of trying to compile one of them directly: their value is almost entirely a design/API layer, not exotic native code — `process.stdin.setRawMode()`, `process.stdout.columns`/`rows`, and plain ANSI escape strings are all that most of them sit on, and those three primitives are already built into Node's own C++ core rather than being userland packages. Compiling oclif itself specifically is a dead end for an unrelated, more fundamental reason: its core feature is a runtime plugin/command-discovery system that `require()`s command modules from paths and installed packages decided at runtime — a direct conflict with this compiler's whole-program, no-dynamic-import compilation model (`resolver/resolver.go`, [ADR-00022](../adr/ADR-00022.md)), independent of any missing primitive. The right move here is the same one this project already takes everywhere else: reimplement the underlying *primitives* natively, then optionally hand-write a small idiomatic helper module in KlainMainLang itself borrowing the API shapes these libraries settled on — not port their source.

This also cleanly separates from the other two UI directions considered in the same discussion (GUI via native bindings, direct hardware/framebuffer access — see [TDD-00032](TDD-00032.md)/[TDD-00033](TDD-00033.md)): TUI needs no general FFI and no callback-to-C trampolines, just a handful of specific libc calls in the exact same shape `os`/`fs`/POSIX-signal support already use. That's why this is the one of the three ready for a real design pass now.

## Design

### Scope: four primitives, no new architecture

Everything here follows the project's established `ensure*()`/`emit_process.go`-style pattern (declare a specific C function once via `e.emitGlobal`, wrap it in a builtin). No FFI, no user-facing `extern`, no callback trampolines — every function below is a fixed, compiler-known primitive, the same shape `process.env`/`os.cpus()`/`process.on('SIGINT', ...)` already are.

1. **`process.stdin.isTTY: boolean` / `process.stdout.isTTY: boolean`** — wraps `isatty(fd)`. Lets a program detect whether it's running interactively (a real terminal) vs. piped/redirected, the standard guard every TUI library checks before touching raw mode at all.

2. **`process.stdin.setRawMode(enabled: boolean): void`** — wraps `tcgetattr`/`tcsetattr` on fd 0. Matches real Node's semantics deliberately, not a looser interpretation: Node's raw mode (`libuv`'s `UV_TTY_MODE_RAW`) disables canonical mode, echo, *and* signal generation (`ISIG`) — meaning Ctrl-C no longer delivers `SIGINT` while raw mode is active, and a raw-mode program is expected to watch for the raw `0x03` byte itself and decide what to do. Matching this exactly (rather than inventing a "half-raw" mode that keeps `ISIG` on) means example code and any future ported API shapes behave the way developers coming from Node already expect.

3. **`process.stdout.columns: number` / `process.stdout.rows: number`** — wraps `ioctl(STDOUT_FILENO, TIOCGWINSZ, &winsize)`. Read on demand (a plain getter-style read, not cached), matching real Node.

4. **`process.stdin.readByteRaw(): number`** (name to be finalized at implementation time) — a new single-byte blocking read off fd 0, returning `-1` at EOF. Needed because the *existing* stdin primitive (`process.readLineSync()`, `PROCESS-CLI.md`, [ADR-00024](../adr/ADR-00024.md)) is a line-buffered `getline()` wrapper — it loops internally until it sees `\n`, which never arrives in raw single-keystroke input (arrow keys, individual characters without Enter). A raw byte read is a materially different primitive, not a variant of the existing one.

### Terminal resize: extend the existing signal allowlist, don't invent a new mechanism

`process.on('SIGINT'/'SIGTERM', handler)` already exists ([TDD-00019](TDD-00019.md)/[ADR-00079](../adr/ADR-00079.md)) with a compile-time-literal-only event-name check. `'SIGWINCH'` (terminal resize) is a third literal to add to that same allowlist — no new dispatch mechanism, just widening a `switch`/string-compare that's currently hardcoded to two values. Reuses the exact same "fires from ordinary control flow at the top of the event loop's own iteration, never real signal context" design [ADR-00079](../adr/ADR-00079.md) already established.

### Explicitly out of scope for this TDD

- **A TUI widget/layout library** (boxes, flexbox-style layout à la `ink`'s Yoga dependency, scrollable lists). That's a KlainMainLang-authored helper module built *on top of* these primitives, not compiler work — and not needed to make the primitives themselves useful (raw ANSI + a spinner/prompt is already a real, useful CLI upgrade on its own).
- **Interactive `readline` (prompt-driven, history, `'line'` events)** — already separately tracked as an untracked gap in `PROCESS-CLI.md`, depends on `EventEmitter` (built, [TDD-00023](TDD-00023.md)) but is its own scoping exercise, not a prerequisite for raw terminal control.
- **Raw, no-trailing-newline stdout writes** (`process.stdout.write(s)`) — `PROCESS-CLI.md` already documents this as a known gap independent of TUI work (console.log's auto-appended `\n` breaks `\r`-based in-place progress updates and other partial-line ANSI sequences). Listed under Prerequisites below since a real TUI can't ship without it, but it's a pre-existing, separately-scoped gap, not new design work this TDD needs to do.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| ANSI escape sequences (colors, cursor movement, clear-line) | ✅ usable today | Plain strings — no syscall involved, works via existing `console.log`/string concatenation right now. |
| POSIX signal handling infrastructure (`process.on`) | ✅ built | [TDD-00019](TDD-00019.md)/[ADR-00079](../adr/ADR-00079.md) — needs its event-name allowlist widened by one literal (`'SIGWINCH'`), not new machinery. |
| `EventEmitter<T>` | ✅ built | [TDD-00023](TDD-00023.md) — not a direct dependency of this TDD's four primitives, but a prerequisite for any later interactive-`readline` follow-on. |
| Raw, no-newline `process.stdout.write(s)` | ❌ missing, pre-existing gap | Documented in `PROCESS-CLI.md` independent of this TDD. A real TUI needs this for in-place progress/spinner updates (`\r` without a trailing `\n`); should likely land alongside this work even though it's not new *design*. |
| Raw single-byte stdin read | ❌ missing | New primitive (#4 above) — `process.readLineSync()`'s `getline()` wrapper doesn't cover this case, it's not extendable to it. |
| `tcgetattr`/`tcsetattr` (termios) binding | ❌ missing | New Go-side C declarations, `emit_process.go`/`runtime_process.go`-shaped. |
| `ioctl(TIOCGWINSZ)` binding | ❌ missing | Same shape as the termios binding above. |
| `isatty()` binding | ❌ missing | Trivial, single libc call. |

## Open questions

- **Exact naming/shape** of the new `process.stdin`/`process.stdout` sub-object fields — this compiler doesn't currently model `process.stdin`/`process.stdout` as real nested objects with their own fields at all (`process.env`, `process.argv` are the closest existing precedent, both flatter). Whether these four primitives hang off synthetic nested objects (matching real Node's shape, `process.stdin.isTTY`) or flatten to top-level `process.*` functions (`process.stdinIsTTY()`) is an implementation-time call, not a design fork worth blocking on here.
- **Terminal-state restoration on exit.** Real-world TUI libraries are notorious for leaving a terminal stuck in raw mode after a crash or an unhandled exception, forcing the user to blind-type `reset`. Node itself doesn't auto-restore either — it's application responsibility. Worth deciding at implementation time whether this compiler should do better (e.g. auto-restore on `process.exit()`/an uncaught exception reaching the top) or just document the same footgun real Node has. Not blocking the primitives themselves either way.
- **`termios` struct layout across the two dev machines.** Both Linux (glibc) and macOS/Darwin implement POSIX termios, but this project has hit exactly this class of bug before — a struct assumed identical across platforms turning out not to be (`ucontext_t`, [ADR-00051](../adr/ADR-00051.md); `GC_stackbottom`/`pthread_getattr_np`, [ADR-00080](../adr/ADR-00080.md)). Per `CLAUDE.md`'s platform-parity standing rule, the `tcgetattr`/`tcsetattr`/`ioctl` struct shapes must be verified directly on both machines during implementation, not assumed from having "the same field names" — flag which machine any raw-mode claim was actually tested on.
