# ADR-01131: The compile target joins the options struct; the resolver and checker take the options

- **Relations**: `Implements TDD-00230` (Phase 2, P2.6); `Extends ADR-01119`
- **Date**: 2026-09-25

## Context

P2.6 names one options struct that carries every mode (`-compat`,
`--no-any`, the decorator dialect, the memory mode, the target) to the
checker, `reprOf` and `@lower` alike. [ADR-01119](ADR-01119.md) built the
struct, but two gaps remained:

- **The target** (`--target`/`--sysroot`, TDD-00146) was a package-level
  variable in `codegen/llvm`, set once by `main.go` (`SetCrossTarget`). It
  was read through `targetGOOS()`/`targetGOARCH()` at 155 sites, about 50 of
  them in free helper functions that build C source.
- **The strict lane's type check did not see the options.** The resolver
  took two booleans instead (`allowGlobalShadowing`, `lazyDynamicImport`),
  and `TypeCheck` built its checker with none. So `--no-any` never reached
  the resolver's checker, and neither would P3.1's platform-conditional
  declarations.

## Investigation

- **Only `main.go` set the target.** The E2E harness, the conformance runner
  and the tests always built for the host. The global was a structural
  problem, not a live race.
- **The target reads split into two groups.** An AST walk found 68 in
  `*Emitter` methods and 52 free functions that reach one, directly or
  through each other. None of those functions has a caller without an
  emitter in scope.
- **The clang driver** (`HostClangArgs`, `ClangCommand`, `RunClangLink`) is
  toolchain code shared by the CLI, the test harness and the conformance
  runner, which build for the host.
- **The Yoga object cache** (`klain:tui`) was keyed by compiler only. A
  cross-architecture build on the same OS could link host-architecture
  objects cached by an earlier host build. This is a latent pre-existing
  bug.

## Decision

- **`options.Target{Triple, Sysroot, GOOS, GOARCH}`** is a field of
  `options.Options`, with `OS()`/`Arch()` falling back to the host.
  - `llvm.ParseTarget` builds it from a triple and sysroot.
  - `main.go` builds the options before resolving, and every program and
    island is resolved, checked and emitted with them.
- **The 52 free functions become `*Emitter` methods**, and every target read
  is `e.opts.Target`. The package variable, `SetCrossTarget` and the
  `CrossTarget*` accessors are deleted.
- **`llvm.Toolchain{Target}`** is the clang invocation for one target, with
  `Args`, `Argv`, `Command` and `RunLink`.
  - `HostClangArgs`, `ClangCommand` and `RunClangLink` are the host
    toolchain's.
  - `Emitter.Toolchain()` is the program's toolchain; the CLI links through
    it, and Yoga compiles through it.
  - The Yoga object cache is keyed by the target triple too.
- **`resolver.ResolveProgramWithOptions(path, options.Options)`** replaces
  the two booleans.
  - `TypeCheck(prog, fileOf, opts, script)` builds its checker with the
    options.
  - A single file with no imports or exports binds as a script
    (`resolver.IsModule`), whose top-level `let` a closure never sees
    narrowed ([ADR-01126](ADR-01126.md)).

## Implementation notes

- **The mechanical conversion** was done by an AST rewriter that finds every
  free function reaching a target read, makes it a method, qualifies its
  calls, and refuses to rewrite any call without an emitter in scope. There
  were none.
- **Test helpers** read `em.Options().Target.Sysroot`,
  `em.LocateWebview`, `em.FFIRegistrySources` and `em.OSInfoLibs`.

## Side effects discovered

- The Yoga cache key fix above.

## Verification

- `go vet ./...` is clean.
- `TestCrossTarget*` pass, including the IR-level macOS-to-Linux codegen
  check.
- **`tools/tsdiag`** is unchanged: 1,341 of 1,343 matching, and 0 reports on
  the project's own programs, which now bind single-file scripts as scripts.
- **`make test-par`** passes apart from the four macOS `-mm=gc` segfaults
  (BACKLOG: `-mm=gc` thread-local roots on macOS), identical at HEAD.
  - One shard timed out on `TestE2EHTTPClientMethodAndHeaders`, the known
    intermittent HTTP hang (BACKLOG: HTTP examples hang on the M4). It
    then passed 5 of 5 reruns, and the rest of its shard, rerun, passed.
