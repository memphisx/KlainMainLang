# ADR-01310: Date operands convert as JavaScript does

- **Relations**: `Supersedes ADR-00018`
- **Date**: 2026-09-30

## Context

`date + 1` and `date - 1` yielded a new Date, ADR-00018's "duration
arithmetic". `1 - date` and `date + date` were compile errors, and `d < 0.5`
truncated 0.5 to an integer. JavaScript converts a Date operand with
ToPrimitive instead:

- `+` uses the default hint, the date string, and concatenates.
- `-`, `*`, `/`, `%`, `**` and the relational operators use the number hint,
  the time value.

The strict lane rejects arithmetic on a Date, as TypeScript does (TS2362,
TS2363, TS2365), so this is observable under `-compat=js` (BACKLOG 58). The
duration arithmetic was a divergence no native-compilation constraint forced.

## Investigation

`emitBinary` (emit_exprs_operators.go) captured the Date flags, then special
cased `+` and `-` to add or subtract in the i64 millisecond domain and stamp
the result a Date. `inferExprType` mirrored that. `emitConcatOperandString`
already renders a Date as its date string (the `"x" + date` path).

## Decision

A Date operand is converted where the flags are captured:

- `+`: both operands through `emitConcatOperandString`, then string
  concatenation.
- `-`, `*`, `/`, `%`, `**`, `<`, `>`, `<=`, `>=`: the Date side as its time
  value, a double, then the ordinary numeric path.

The inference answers a string for `+` and a number for the others. The
rejections of `date + date` and `number - date` are gone. Equality keeps
comparing time values, which is separate from JavaScript's object identity.

## Implementation notes

The `+` and `-` cases lost their Date branches. The remaining i64 coercion of
a Date operand serves equality only.

## Side effects discovered

- A compound `date += n` keeps a Date-typed variable a Date, where
  JavaScript makes it a string. The variable would have to widen (BACKLOG 58,
  narrowed).
- `d1 === d2` compares time values; JavaScript compares identity.

## Verification

`TestE2EDateOperandsConvertAsJS` (tests/js_undefined_arith_test.go) matches
Node under `-compat=js` on macOS arm64.
