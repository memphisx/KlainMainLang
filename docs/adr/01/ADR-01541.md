# ADR-01541: A function expression's parameters take their context

- **Relations**: Extends ADR-01528, TDD-00230
- **Date**: 2026-10-10

## Context

An unannotated arrow parameter takes the checker's contextual type in
the strict lane; a function expression's was `any` (an IIFE's
`(function (t) { … })(2 + 3)`, where tsc types `t` as `number`). In the
js lane, a function's parameters take its call sites' types, but an IIFE
had no call site the checker knew of.

## Decision

- A function expression's unannotated parameter takes its contextual
  type, as an arrow's does (strict lane).
- An IIFE's call is its call site (js lane).

- Under -compat=js, a function literal its enclosing function returns
  (`return (a) => a`, `() => (a) => a`) has its callers out of sight:
  its unannotated parameters are `any`, as checkJs types them.
