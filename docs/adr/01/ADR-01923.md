# ADR-01923: checker — type arguments in scope, members on demand, apparent pattern members, own-key order

- **Relations**: `Implements TDD-00230` (checker coverage)
- **Date**: 2026-10-21

## Context

Four gaps in the checker, each found through an unanswered or mismatched shadow row:

- An explicit type argument (`new Map<string, T>()` inside `function f<T>`) was resolved at module scope, so the enclosing function's `T` was not found and the call was typed `Map<string, any>`.
- Reading a binding initialized from `this.next()`, in a class whose `*[Symbol.iterator]()` yields that binding, built the class's whole instance type. That inferred the generator's yields, which read the binding still being resolved: a cycle, cached as unanswered. tsc resolves the one member on demand.
- An object pattern over an array or a primitive (`const { length } = xs`, `(...{ length }: string[]) => length`) was unanswered: pattern properties were read only off object types.
- An object literal property naming an earlier one (`{ ...w1, name: "x" }`, `{ a: 1, a: 2 }`) was removed and appended, so the type's order differed from the object's own-key order, the order the layout follows.

## Decision

- The binder records the scope each explicit type argument is written in, and the checker resolves it there.
- `this.m` naming an annotated, non-overloaded method of the enclosing non-generic class, read before that class's instance type exists, is that method's type, resolved alone.
- An object pattern's property is read off the source's apparent type (`Array<T>`, `String`, …), except for a tuple, whose `length` is its own size.
- A property naming an earlier one, from a spread or written out, replaces it in place, matching ES own-property order (Node prints `{ ...w1, name }` as `{ name, inner }`).

## Consequences

- The generic Promise and Map, class-iterator, rest-pattern and object-spread compiles agree with codegen.
- tsc prints a spread's properties in a different order (`getSpreadType` puts the right side first). That is display only, and diagnostics keep their codes and positions.
