# ADR-00471: ambient value declarations become real bindings

- **Relations**: Extends the ambient-erasure ADR behind `parseAmbientDeclaration`
- **Date**: 2026-08-29

## Context

The TS oracle's two largest remaining buckets — `undefined variable` (231)
and `undefined function or closure` (154) — were dominated by ambient
value declarations (`declare var a: boolean; declare function before():
void;`) that the blanket token-skipper erased entirely, leaving every use
site undefined. Erasure was originally chosen because an AOT compiler has
no runtime lookup to satisfy an ambient symbol; blanket acceptance was
earlier declined as producing unlinkable binaries.

## Decision

The principled middle path — ambient values become *real bindings with
defined fallback behavior*, so nothing is unlinkable and nothing is
silent:

- `declare function f(sig);` parses via the existing bodiless
  `parseFunctionRest` path and gets a **synthesized throwing body**
  (`throw new Error("ambient function 'f' has no implementation")`).
  The program compiles and links; the error is clear, catchable, and
  fires only if the ambient is actually called. Zero codegen changes —
  the stub is ordinary AST.
- `declare var/let/const x: T;` is an ordinary uninitialized `var`
  (zero/`undefined` default — the ADR-00454 semantics).
- Consecutive redeclared ambient signatures collapse through the existing
  var/function-redeclaration rule; **top-level function emission is now
  last-wins per name** (matching JS re-declaration hoisting) — previously
  a redeclared function pair emitted twice and died as an LLVM
  redefinition.
- `declare class/namespace/module/global` keep the balanced-token erasure.

## Verification

Mac. `tests/type_features_test.go` E2E (zero-read var, throwing stub,
collapsed redeclarations) and the `examples/types/ambient-declare.ts`
extension pass; parser + ambient/function/overload/namespace batches
green. TS oracle: **56.0% → 56.5%** (agreement 5184 → 5226, match-accept
1540 → 1691 — the largest single-feature move since namespaces V2). Node
oracle unchanged (40).
