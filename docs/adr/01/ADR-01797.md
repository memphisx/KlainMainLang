# ADR-01797: Generator functions read their receiver; sloppy `this` is always the global object

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- A generator function declaration or expression that read its own `this` failed to compile in the js lane ("'this' is only valid inside a method or constructor body"). Only class and object-literal generator methods bound a receiver.
- A sloppy-mode function's absent receiver is the global object. The substitution (`emitSloppyThis`) applies only when `globalThis` is linked, and it was linked only when the source names `globalThis`. Otherwise `const t = this` held undefined.

## Decision

- `jsThisGeneratorsAsFunctions` runs before `jsThisFunctionsAsBindings`. It lowers such a generator into a plain function that binds `__kml_gthis = this` and, when the body uses it, `__kml_gargs = arguments`, then returns an inner generator over the body with those names replaced. The outer function is then compiled like any other function that reads its own receiver.
- A generator's parameters are bound at the call (before the first `next`), so they stay on the outer function with unchanged timing.
- A function that reads both its own `this` and `arguments` stays a dynamic value. Its inferred type mirrors that, so every call passes the exact argument count. Previously a typed call passed each fixed parameter, an omitted one as undefined, which counted as supplied. The extra arguments also came through as one array, because the hinted closure type dropped the implicit rest; that crashed with "the value is not an array". Other hinted this-taking functions keep `FuncHasRest`/`FuncThis`, and the dynamic-to-typed thunk spreads a rest after a `this` parameter.
- The resolver links the global-object module for a sloppy script that mentions `this` (`sloppyThisUse`).

## Consequences

- `TestE2EJSFileGeneratorThis` compares method-assigned, called and plain-called generators (receiver, `arguments`, defaults) and sloppy `this` held in bindings against Node.
- The outer function is constructible, while a generator function is not: `new g()` on such a generator does not throw.
