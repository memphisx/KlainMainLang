# ADR-00391: Node's `http.createServer` / `(req, res)` (TDD-00131 Stage 1)

- **Relations**: Implements TDD-00131
- **Date**: 2026-08-27

## Context

The compiler's HTTP server was a bespoke shape — `http.listen(port, (req) =>
({ status, body }))`, the handler *returns* a response — with no
`http.createServer` at all. Node code (`http.createServer((req, res) => {
res.writeHead(200); res.end(body) }).listen(port)`) neither compiled here nor was
KlainMainLang HTTP code portable to Node. TDD-00131 chose to expose the **real
Node API** under the `http` name and move the bespoke model to `klain:http`.

## Decision

Implement Node's `http.createServer(listener).listen(port[, cb])` under the
`http` specifier, reusing the entire existing HTTP runtime (fiber-per-connection
accept loop, request parser, buffered/chunked response writer) — only the
handler-call shape changes.

Key insight: the existing dispatcher reads `{status, body, headers}` off the
handler's returned object. If `res` is an object with **those same fields** that
the handler *mutates*, the whole response-writing tail is reused unchanged. So
`res` is a `ServerResponseType` (`{status, body, headers}` + an
`IsServerResponse` marker); a `httpResMode` flag switches `emitHTTPCallHandler`
to: create `res`, call `handler(req, res)` (void), and hand `res` back as the
response object.

## Implementation notes

- **`res` object** (`ServerResponseType`, `IsServerResponse`): `res.writeHead(
  status[, headersObject])`, `res.setHeader(k, v)`, `res.write(chunk)`,
  `res.end([chunk])` are intercepted in `emitCall` when the receiver
  `IsServerResponse` and translated to field mutations — status stored, headers
  set into the map, body accumulated via string-concat. `write`/`end` append.
- **`http.createServer(listener).listen(port[, cb])`**: the chained call is
  recognized in `emitCall` (callee `<createServer call>.listen`) and routed to
  `emitHTTPCreateServerListen`, which runs the same bind/dispatch/loop core with
  `httpResMode`. The optional `listening` callback fires after bind. Reuses the
  single-`@__kml_listen_handler` global, so it shares the one-server-per-program
  V1 limit with `http.listen`.
- **`IncomingMessage`/`ServerResponse`** type names resolve to `RequestType`/
  `ServerResponseType`; `req.url` is aliased onto the existing `path` field for
  Node-property fidelity (`req.method`/`req.headers` already matched).
- The `klain:http` specifier (this ADR's sibling in the `virtualBuiltinMarkers`
  table) keeps the bespoke `http.listen` model.

## Side effects discovered

- The HTTP status **reason phrase** is hardcoded `OK` (the response writer never
  varied it), so `writeHead(201)` yields `201 OK`, not `201 Created` — a
  pre-existing cosmetic gap, unchanged here, noted for a follow-on.
- V1 scope: one server per program; `res` is a pragmatic Writable subset
  (`writeHead`/`setHeader`/`write`/`end`) — no `statusCode=` property setter,
  streaming backpressure, or the non-chained `const s = createServer(...);
  s.listen(...)` form yet.

## Verification

- E2E test `TestE2EHTTPCreateServerNodeShape` (server + real HTTP GET): asserts
  status 201, the `Content-Type` header from `writeHead`, the `X-Method` header
  from `setHeader(_, req.method)`, and the `write`+`end` appended body. Passes.
- Example `examples/http/node_createserver.ts` (routes on `req.url`), runs and
  self-exits.
- Full `go test ./tests/` + `make examples` green; `make conformance` at the end
  of the batch.
