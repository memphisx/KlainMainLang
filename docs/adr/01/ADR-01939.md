# ADR-01939: One string allocator, allocator-reported array capacity, an identity-hash seam, and Proxy over any object

- **Relations**: Implements TDD-00230
- **Date**: 2026-10-28

## Context

TDD-00230 Phase 5 asks for three more things:

- every string producer goes through one allocator;
- an array header carries a capacity word;
- no table derives an object's hash from its address.

While I was probing the string paths, `new Proxy([7, 8], {})` threw "Proxy target called on non-object". Node accepts any object as a target.

## Investigation

- **String allocation:**
  - Outside `__kml_str_alloc` itself, four sites still allocated headered strings: `emitStringScratchReg` and three `%lld` index-key buffers (in `emit_iter_collect.go`, `emit_shape.go` and `emit_stmts_forof_any.go`).
  - The three key buffers also never wrote their length word.
- **Array capacity:** `emitArrayReserve` already grows arrays geometrically. It reads the room from the allocator (`__kml_heap_usable`), so the capacity a header word would hold already exists, kept where it cannot drift from the real allocation.
- **Identity hashing:**
  - Reference keys of every static `Map`/`Set` ride the `any`-keyed runtime, so `any_hash` (`collections_any.c`) is the only table that hashes object addresses.
  - `weak.c` compares disappearing links, which a moving collector updates, and hashes nothing.
  - The gcshim's foreign-block set tracks memory the collector does not manage.
- **Proxy:**
  - `emitNewProxy` required a dynamic-object bag for the target.
  - The C trap paths stored the target in the bag's proto slot and passed `target | 5` to every trap.

## Decision

- **One allocator:**
  - `emitStringScratchReg` calls `__kml_str_alloc`.
  - The three key buffers use `emitStringScratch` and `emitStringFinalizeLen`, which also gives them a correct length word.
  - Only `buildStrLeaves` names `allocString` now.
- **Capacity:** no capacity word. The allocator-reported capacity meets the requirement, and the comment in `emit_arrays_core.go` says so.
- **Identity hash:**
  - `kml_id_hash(p)` in `kml_heap.h` is the one function a table may derive an object's hash from.
  - Every collector linked today is non-moving, so it returns the address. A moving collector changes only this function, to a stored hash in a header field or in a side table it updates.
  - `any_hash` routes array, function, host and object boxes through it.
- **Proxy:**
  - Any object is a target; a primitive is Node's TypeError ("Cannot create proxy with a non-object as target or handler").
  - The header keeps the target's bag in the proto slot, or NULL when the target is not a dynamic object, and keeps the boxed target in the `cap` word.
  - Traps receive the boxed target.
  - Without a trap, a non-bag target is read and written through two program hooks, `__kml_proxy_tget` and `__kml_proxy_tset` (the program's own `any` get and set; weak defaults in `hooks.c`).
  - `shape.c`'s ownKeys, descriptor and define paths treat a non-bag target as having no own bag keys.

## Implementation notes

- **Strings:** `emit_strings.go`, `emit_iter_collect.go`, `emit_shape.go`, `emit_stmts_forof_any.go`.
- **Identity hash:** `kmlheapsrc/kml_heap.h`, `collectionssrc/collections_any.c`.
- **Proxy:** `emit_reflect.go` (`emitNewProxy`, `ensureProxyTargetHooks`), `dynobjsrc/dynobj.c` (`PX_TBOX`, `__kml_dynobj_proxy_tbox`), `shapesrc/shape.c`, `hookssrc/hooks.c`, `runtime_hooks.go`.

## Side effects discovered

- The Proxy target bug above.
- The missing length word on the index-key buffers.

## Verification

- `tests/dynstage67_test.go` `TestE2EProxyArrayTarget`: reads, iteration, a write, `in` and a get trap on an array target, plus the primitive-target TypeError. It matches Node.
- The `Proxy|Reflect`, `Map|Set|Weak` and runtime-symbol E2E suites pass, as do the `codegen/llvm` unit tests.
- A probe of `Array.from` on an array-like, `for…of` over `any`, an array iterator through `any`, and object, function and array keys in a Map and a Set matches Node. Verified on the Mac.
