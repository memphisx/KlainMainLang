# TDD-00241: `undefined` in a `number` slot

- **Status**: Partially Implemented
- **Date**: 2026-10-02

## Context

A `number` is a bare `double`, which has no `undefined`. A required
`number` slot can still receive one in a well-typed program:

- a dynamic call that passes fewer arguments than the callee declares
  (`setTimeout((a: number, c: number) => …, 0, ...[1])`, a function held in
  `any`);
- an unboxing from `any` (`const n: number = o.missing`);
- an assertion over an absent value (`x!`, `x as number` on a
  `number | undefined` that is absent).

Node keeps `undefined` there: `typeof c` is `"undefined"`,
`console.log(c)` prints `undefined`, `c === undefined` is true, and
`c + 1` is `NaN`. This compiler reads `NaN` (from ToNumber at the unboxing)
or `0` (from the payload of an absent `{i1, T}`). The `{i1, T}`
representation of [TDD-00187](TDD-00187.md) covers the slots whose declared
type admits `undefined`; these slots' declared type does not, so widening
them would change every `number` parameter's ABI to carry a value that
well-typed code never passes.

## Design

**A signaling-NaN sentinel.** `undefined` in a `double` slot is the bit
pattern `0xFFF4000000000001`: a NaN with the quiet bit clear and the sign
bit set.

Measured with `clang -O2` on Apple Silicon (clang 21) and on x86-64
(Ubuntu clang 18):

- A copy, a call argument, a return value, a `select` and a store/load
  keep the pattern on both.
- `x + 1` quiets it, giving a NaN with other bits, on both, so arithmetic
  on `undefined` reads `NaN`, as in JS.
- `-x` and `Math.abs(x)` change the sign bit, so they read `NaN` too. That
  is why the sentinel's sign bit is set: with it clear, `fabs` would
  return the sentinel unchanged.
- `x * 1` is folded to `x` by LLVM even for a signaling NaN, so the
  sentinel survives an identity operation. Every identity the emitter
  itself produces (unary `+`, `Number(x)` on a number, `x * 1`, `x / 1`,
  `x - 0`) must therefore quiet explicitly.
- `llvm.canonicalize` does not lower on x86-64 with clang 18 ("Cannot
  select: fcanonicalize").
- `fadd x, +0.0` quiets but turns `-0` into `+0`, and `fadd x, -0.0` is
  folded away.
- The quieting is therefore `select(bits(x) == SENTINEL, NaN, x)`.

**Producers** store the sentinel:

- unboxing `undefined` (`nbUndefined`) to a `double`, where ToNumber gives
  `NaN` today;
- an omitted argument for a required `number` parameter, in the typed
  trampolines and the dynamic-record adapters;
- `x!` and `x as number` over an absent `{i1, double}`.

**Consumers** test for it:

- boxing a `double` to `any` gives `nbUndefined`;
- number-to-string (template literals, `String()`, concatenation,
  console, inspect) prints `undefined`;
- `typeof` on a `number`-typed expression becomes a run-time check;
- `=== undefined`, `== null`, and `===` between two numbers (two sentinels
  are equal; `fcmp oeq` alone says false);
- JSON omits a `number` field holding it, and gives `null` for an array
  element holding it;
- truthiness already holds: a NaN is falsy.

An integer slot (`i64`, the unannotated-number default) has no spare
pattern. A producer targeting one stores `0` as today, and the divergence
stays documented for the integer lane only.

**Cost.** Only the consumers above gain a compare, and arithmetic is
unchanged. The emitter's own identity operations gain a compare and a
select.

**Alternative considered: widening each `number` parameter to
`{i1, double}`.** It doubles the slot, changes every call ABI, and still
leaves locals, fields and returns uncovered. Rejected.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| NaN-boxed `any` ([TDD-00155](TDD-00155.md)) | Implemented | `nbUndefined` is the boxed side of the boundary |
| `{i1, T}` nullable scalars ([TDD-00187](TDD-00187.md)) | Implemented | `x!` over an absent value is the third producer |
| Number-to-string routines (`coresrc`) | Implemented | one bit test at entry |

## Open questions

- `Math.max`/`Math.min` lower through `llvm.maxnum`/`llvm.minnum`, whose
  signaling-NaN semantics differ by target. JS wants `NaN` for any
  undefined operand, so these may need the explicit quieting first.
- A `float32` slot (`/** @type {float32} */`) needs its own sentinel,
  `0xFFA00001`, and the same consumer set.
