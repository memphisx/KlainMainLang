# ADR-01319: Error subclasses render, enumerate and nest as Node's

- **Relations**: Extends ADR-00630, ADR-01181, ADR-01318
- **Date**: 2026-10-01

## Context

These came up while doing ADR-01318: BACKLOG 69 and 110, and a cluster
around them.

- `console.log` of an Error subclass's instance printed a plain object that
  listed every internal error slot (`code: undefined, errcode: 0, …`), where
  Node prints `X [Error]: msg` and the instance's own properties. A builtin
  Error nested in an array or object printed `[Object]`.
- `Object.keys` of a statically typed subclass instance listed the internal
  slots; an assigned `this.name` was not an own key, and JSON lacked it.
- `class E extends Error { code = 5 }` was rejected: `code`, `errno`,
  `syscall`, … are this compiler's slots for system errors, which TypeScript's
  `Error` does not have.
- Extending an Error subclass was rejected.
- `(err as any).x = v` on a builtin error was a compile error (`no field`).
- `JSON.stringify` of an Error-subclass promise or abort reason was `{}`.

## Investigation

- A boxed error already had a full own-key walk (`__kml_obj_nkeys/key/get`
  in `emit_record_view.go`): the layout row's keys for a subclass,
  then the system fields that are set and the `extra` bag
  (`emitErrorOwnKeysHooks`). Only inspect, the static
  `console.log`/`Object.keys` paths and the error header bypassed it.
- Node's `util.inspect` (lib/internal/util/inspect.js `improveStack`) writes
  `Ctor [name]` when the name ends in `Error` and is not the constructor's.
  An error's own keys follow the stack, and `name`/`message` are not listed
  again.
- A class's fields are defined when its constructor's `super()` returns, so
  a `name` first assigned in class K's constructor sits after the fields of
  K and its bases. A later assignment keeps the property where it is.
- A header bit for "name is own" was rejected: the error header is compared
  for exact equality at many `instanceof` sites. A trailing errorObjType
  slot changes no existing offset, and every error allocation is zeroed.

## Decision

1. **Rendering.** A boxed error renders through `inspect_error`
   (dynjson.c): the header `Name: message`, with Node's `Ctor [Name]` when
   the class is not what the name says, then its own enumerable properties
   one per line, as Node prints them after the stack. The stack's frames
   are not printed: this compiler has none. The inspect path of an `any`,
   the static `console.log` of a subclass instance and of a caught value,
   and a builtin Error nested in an array or object all reach it.
2. **Own keys.** A static `Object.keys` of an Error enumerates through the
   boxed walk. errorObjType gains `__kml_name_own`: zero, or one plus the
   index among the layout's keys at which the first assignment of `name` on
   the error placed it (the count of own layout keys of the class whose
   constructor assigned it, else after them all). `__kml_obj_key` lists
   `name` there; inspect leaves `name` and `message` to the header.
3. **System-named fields.** A subclass field named like one of the
   system-error slots is the subclass's own field, in its declaration order.
   The system slot is renamed internally in that class's layout. The layout
   row treats the error prefix by position, so such a field is listed, read
   and written as the subclass's own. Through `any`, a subclass's own field
   is read and written by the layout before the error's fixed slots.
4. **Subclass of a subclass.** A class extending an Error subclass is one:
   it takes the error flag, an error-range TagID and its base's builtin
   kind. Its `super(…)` calls the base's constructor (only a direct
   subclass of the Error root writes the message itself). `instanceof` on a
   caught value matches the class's descendants as well.
5. **`(x as any).p = v`** writes through a boxed `x`: a property x lacks is
   added at run time.

## Implementation notes

- `codegen/llvm/dynjsonsrc/dynjson.c`: `inspect_error`, `error_header_key`.
- `codegen/llvm/emit_dynamic.go`: the boxed error's inspect calls
  `__kml_obj_inspect_at`; `emit_call_console.go`: a caught value prints
  as its boxed form; `emit_inspect.go`: the subclass and nested-error paths,
  `isErrorValue`, `markErrorNameOwn`.
- `codegen/llvm/emit_exceptions.go`: `errorNameOwnField` in errorObjType.
- `codegen/llvm/emit_record_view.go`: `__kml_error_name_pos`, and `name`
  interleaved in `__kml_obj_nkeys`/`__kml_obj_key`.
- `codegen/llvm/emit_iter_collect.go`: the extras walk reads an own `name`.
- `codegen/llvm/emit_shape.go`: `errorOwnLayoutKeys`.
- `codegen/llvm/emit_classes.go`: `isErrorSub`, `errorSystemSlot`,
  `redeclaresSameStorage`, and `super` only writes the message for a direct
  subclass.
- `codegen/llvm/emit_dynobj.go`: the layout's getter and setter first for an
  error, and `name` written through `any` marks it own.
- `codegen/llvm/emit_exprs_assign.go`: `castToAny`.

## Side effects discovered

- The `Promise.allSettled` and `AbortSignal` caveats ("JSON of an
  error-subclass reason is `{}`") were already stale before this change and
  are removed.

## Verification

- New E2E tests: `TestE2EErrorSubclassInspect` (pinned output: Node prints
  stack frames this compiler has no equivalent of),
  `TestE2EErrorSubclassOwnProps` and `TestE2EErrorSubclassOfSubclass`
  (against Node). The existing Error, `allSettled`, `AbortSignal` and reason
  tests pass.
- Verified on macOS (Apple Silicon).
