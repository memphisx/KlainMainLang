# TDD-00214: res Writable — observable backpressure (`false` + `'drain'`)

- **Status**: Implemented
- **Date**: 2026-09-15

## Context

[TDD-00195](TDD-00195.md) Stage 2 made a server `res` an incremental Writable:
`res.write` frames chunks to the socket mid-handler (ADR-00959), binary chunks
go as raw bytes (ADR-00960), and a slow consumer parks its own connection fiber
instead of blocking the reactor — **Layer A**, socket-level backpressure
(ADR-00961). Layer A fixed the real harm (one slow client no longer stalls the
whole server), but it does not expose Node's *observable* backpressure contract:

1. `res.write()` **always returns `true`** today (the `__kml_ws_desired>0`
   fast-path in `emit_http.go`). Node returns `false` once the buffered, unsent
   size crosses `highWaterMark`.
2. `res.on('drain', cb)` is **not supported at all** — `res.on` falls through to
   the "not yet supported" error. Node fires `'drain'` asynchronously once the
   buffer empties, while the handler proceeds.

A well-behaved Node producer *stops* on `false` and waits for `'drain'` before
writing more (the canonical `write→false→once('drain')→resume` loop). Layer A
cannot serve that producer: with inline park there is no queue to drain and
nothing to trigger `'drain'`, so a producer that respects the contract would
stall. Faithfulness-first (this project's own practice) therefore requires a real per-response
output queue — this stage.

## Design

### The queue model

`res.write(chunk)` stops parking inline. Instead:

1. Frame the chunk (`<hexlen>\r\n<data>\r\n`, or raw bytes for a binary chunk)
   and **try a non-blocking write** of as much as the socket accepts.
2. Whatever the socket does not accept is **copied into a per-response output
   queue** (the handler's chunk buffer may be freed/reused after `write`
   returns, so the tail is copied, not referenced).
3. Return `queuedBytes <= highWaterMark`. Crossing above HWM sets a
   `needDrain` flag on the response.

Most writes fully flush and the queue stays empty → return `true`. When the
socket backs up the queue grows → return `false`.

### Draining on the connection fiber (fiber-resume dispatch)

The connection fiber already parks in the dispatcher tail (`emitParkUntilResEnded`)
until `res` is `ended`. That park loop is extended to also own draining:

- On **every resume** (the reactor already resumes a write-parked fd when it
  comes back writable — Layer A's `%wfdset` path in `rcheckready`), the fiber
  calls `__kml_res_drain(res)`: write as much of the queue as the socket
  accepts (non-blocking); on `EAGAIN` re-mark the fd in `@__kml_conn_writepark`
  and swapcontext back (exactly Layer A's park).
- When the queue **empties** and `needDrain` was set, the fiber fires the
  registered `'drain'` listener **on itself** (a plain `emitCBCall`), clears
  `needDrain`. Because this runs on the fiber, the listener may `res.write`
  again (re-queue, re-park) or `res.end` naturally — the canonical producer
  loop works.
- The loop exits when `ended` **and** the queue is empty.

Consequence: **no new "resume reason" enum on the fiber**. The reactor keeps
resuming write-parked fds on writable and poked fibers as before; the fiber
re-derives its own state (queue non-empty? crossed to empty? ended?) on each
resume, mirroring how `rcheckready`'s other parkers re-check their own
condition. This is the minimal reactor change — none — and reuses Layer A's
`@__kml_conn_writepark`/`%wfdset` infrastructure wholesale.

### `res.end` with a non-empty queue

`res.end` must **flush the queue fully before the terminal chunk**: if the queue
is non-empty it drives the same drain-and-park loop until empty, then writes
`0\r\n\r\n`, sets `ended`, restores `O_NONBLOCK` for keep-alive re-arm. Keep-alive
re-arm ordering is already gated on `ended`; the flush-before-terminal keeps the
byte stream well-formed.

### `'drain'` semantics (faithful)

Node fires `'drain'` when the buffered length returns to **0** after a `write`
returned `false` — not merely on crossing below HWM. So: fire only when the
queue reaches empty *and* `needDrain` is set, then clear `needDrain`. A
`res.once('drain')` unregisters after firing (single-shot); `res.on('drain')`
re-arms for the next `false→empty` cycle.

### Response-object fields

`ServerResponseType` gains (appended after `__kml_reqheaders`, so existing
indices are unchanged):

- `__kml_outq` (`ptr`) — the output queue (null until the first partial write);
  a small heap struct `{ptr buf, i64 len, i64 cap, i64 needDrain }` (a single
  growable byte buffer — the unsent tail is contiguous, so one `realloc`-grown
  buffer with a drained-prefix offset is simpler than a chunk list and matches
  how the bytes leave the socket).
- `__kml_drain_cb` (`ptr`) — the registered `'drain'` listener `{fp,env}` closure
  (null until `res.on('drain')`); plus a one-bit "once" marker folded into the
  low bit or a sibling field.

Malloc/free managed (consistent with the rest of the http runtime); the queue is
freed when it empties at `res.end`.

### `res.on('drain')` (and siblings)

`emitServerResponseMethod` gains an `on`/`once` case: `'drain'` stores the
callback + once-flag into `res`. `'finish'`/`'close'` can be accepted as
deferred no-ops or wired later; only `'drain'` is in scope here.

### SIGPIPE (folded in — chosen scope)

A client disconnecting mid-write raises `SIGPIPE`, which is not ignored
process-wide today → the server dies (exit 141) on any write path. This is
squarely the slow-client/backpressure scenario. Fix: `signal(SIGPIPE, SIG_IGN)`
once at reactor/listen start. `__kml_res_write_all` (and the new drain writer)
already treat a non-`EAGAIN` `n<=0` as "give up", so `EPIPE` then unwinds the
connection gracefully instead of killing the process. Global signal disposition
is handled cautiously per the ADR-00710 SIGINT saga — set once, isolated,
regression-tested that SIGINT/existing signal handling is unaffected.

## Open questions

1. **HWM value.** The WHATWG sink was allocated with a 64 KiB desired size;
   Node's socket default `highWaterMark` is 16 KiB. Match Node (16 KiB) for the
   `false` threshold, independent of the sink's WHATWG desiredSize. Settle at
   implementation; document if it diverges.
2. **HTTPS/1.1.** Layer A left TLS chunk writes blocking (streamed TLS
   backpressure unvalidated), so the queue/`false`/`'drain'` path is plain-HTTP
   first; over HTTPS `res.write` may keep returning `true` (blocking drain) until
   TLS backpressure is validated. Disclose as a caveat rather than diverge
   silently.
