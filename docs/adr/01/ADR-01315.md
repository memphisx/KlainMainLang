# ADR-01315: Local-time Date, Date.parse, Invalid Date, and Map/Set/Date through their declarations

- **Relations**: `Implements TDD-00230` (P3.2); `Extends ADR-01307`; `Supersedes` the UTC-only rule of the Date ADRs (ADR-00015, ADR-00016, ADR-00844)
- **Date**: 2026-09-30

## Context

- Date was UTC-only by an early deliberate choice (deterministic output
  across machines). Every local getter, the component constructor, the
  local setters, `toString` and `toDateString` worked in UTC. On a machine
  in Europe/Athens, `new Date(2024, 6, 15, 10, 30).toISOString()` gave
  `10:30Z` where Node gives `07:30Z`.
- `Date.UTC` and `getTimezoneOffset` did not compile.
- `Date.parse` read a date-time without an offset as UTC (the spec reads it
  as local time), dropped the time of `"2024-07-15T10:30"`, knew no legacy
  format, and returned `-1` for unparseable input where Node returns `NaN`.
- Map, Set, WeakMap, WeakSet and Date methods were still dispatched by name
  in `emitCall` (TDD-00230 P3.2).

## Investigation

- Local time is available on every target through the C library:
  `localtime_r` on POSIX, `localtime_s` on Windows. The offset at an instant
  is the difference between the local fields composed as UTC and the
  instant. The inverse (local wall-clock to UTC) takes two fixed-point
  steps from the offset at the naive reading, as engines compute
  LocalTime→UTC. This gives Node's answers across DST changes.
- Node's zone names in `toString` come from ICU, keyed by zone. The C
  library gives only the abbreviation (`EEST`), and some zones only a
  number (`-03`).
- A Date is an `i64`, so it cannot hold NaN. `INT64_MIN` lies outside the
  time value range (±8.64e15 ms), which makes it free for Invalid Date.

## Decision

- **Local time.** `stringsrc/string.c` gains:
  - `__kml_tz_offset_ms(t)` and `__kml_local_to_utc_ms(local)`;
  - `__kml_tz_suffix(t)`, the `" GMT+0300 (Eastern European Summer Time)"`
    suffix, with a long-name table keyed by abbreviation and offset (`IST`
    at +5:30 is India, at +1 Irish, at +2 Israel).

  Codegen (`emitDateLocal`, `emitLocalToUTC`) routes these through it:
  - the local getters;
  - the local setters (decompose local, compose, convert back);
  - the component constructor;
  - `toString`, `toDateString` and `toLocaleDateString`;
  - `getTimezoneOffset`.

  `Date.UTC` and the `getUTC*`/`setUTC*` accessors compose and decompose
  UTC (`emitDateFields`).
- **`Date.parse`** is a C parser (`__kml_date_parse_str`) returning a
  double:
  - the ECMAScript format: `±YYYYYY` or `YYYY`, `-MM`, `-DD`, `THH:mm`,
    `:ss`, `.sss`, `Z` or `±HH:mm`, with field ranges checked; a date-only
    form is UTC, a date-time without an offset is local time;
  - failing that, the legacy forms V8 accepts: words (months, weekdays,
    `GMT`/`UTC`/`Z`, `am`/`pm`), a time, an offset, and a
    day/month/year order by magnitude;
  - `NaN` for anything else, or past the time value range.
- **Invalid Date** is the stored time value `INT64_MIN`
  (`emitTimeValueToDate`: a NaN or out-of-range double becomes it).
  - `getTime()` and `valueOf()` are doubles, NaN for it.
  - `toString`, `String(d)`, template literals and `console.log` give
    `Invalid Date`, and JSON gives `null`.
  - `toISOString` throws `RangeError: Invalid time value`.
  - `new Date(number)` with a double argument goes through the same
    conversion.
- **Declarations.** `@intrinsic Map.prototype.*`, `Set.prototype.*`,
  `WeakMap.prototype.*`, `WeakSet.prototype.*` and `Date.prototype.*` route
  these calls through `emitCollectionIntrinsic` and `emitDateIntrinsic`
  when codegen holds the receiver as that kind (`intrinsicApplies`). A
  dictionary, `Headers` or `URLSearchParams` keeps its own path.
  `inferCollectionCallType` was extracted from `inferExprType` so the
  intrinsics share it. `lib/es.d.ts` gains the `setUTC*` setters.
- **The name dispatch becomes a fallback.** `emitCall`'s by-name branches
  for Map, Set, WeakMap, WeakSet and RegExp `exec`/`test` now run only for a
  receiver the checker gives no declaration: a private `#field` read off
  another instance (`target.#listeners.get(k)`) under `-compat=js`, the
  case found. The Date branch is deleted. The checker now types the
  parser's own nodes for `new Date`, `new Map`, `new Set`, `new WeakMap`
  and `new WeakSet` (`newBuiltinType`) through the global's construct
  signatures, as it types a `NewExpression`. Before, it left them
  unanswered, so no method call on the result had a declaration.
  `Map.get` on an array-valued Map is typed `T[] | undefined`.
- **Tests** run with `TZ=UTC` unless they set a zone (`tests/main_test.go`),
  so an expectation of local fields holds on any machine.

## Implementation notes

- `toString` renders the suffix into an 80-byte stack buffer and formats
  the rest around it.
- `getTime`'s type is `number` (a double), because of NaN. Arithmetic and
  comparisons that read it take the double.

## Side effects discovered

- A zone outside the name table prints its abbreviation (`(-03)` where
  Node says `(Brasilia Standard Time)`). Node's full names are ICU data.
- Setters still need a named-variable receiver: a Date is a value, not a
  heap object. That is P3.3 representation work.
- `Date.UTC` with invalid fields is not NaN.

## Verification

On macOS arm64:
- `tests/date_local_time_test.go` compares with Node under `TZ=UTC`,
  Europe/Athens, America/New_York, Asia/Tokyo, Europe/London and
  Asia/Kolkata. It covers getters, the constructor, setters across a DST
  change, `toString`, `getTimezoneOffset`, `Date.UTC`, `Date.parse`'s forms
  and Invalid Date.
- Seven more zones' `toString` names were compared by hand.
- The two tests that pinned the `-1` sentinel now expect `NaN`.
