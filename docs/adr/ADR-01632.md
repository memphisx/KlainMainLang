# ADR-01632: In untyped JS, `process.getuid()` on Windows is Node's runtime TypeError

- **Relations**: Extends TDD-00177
- **Date**: 2026-10-14

## Context

Three Node-core files (`test-cluster-bind-privileged-port`,
`test-cluster-shared-handle-bind-privileged-port`,
`test-fs-mkdir-recursive-eaccess`) failed to compile on Windows: "process.getuid
is not available on Windows". Each skips itself on Windows before the call.

## Investigation

`process.getuid`/`geteuid`/`getgid`/`getegid` are undefined on Windows in
Node. Calling one is a TypeError when, and only when, the call runs. The
compiler rejects the bare call when targeting Windows (`emit_call.go`, per
TDD-00177). For typed code that matches tsc: `@types/node` declares the
members optional, so a bare call is already an error under strict null
checks. Untyped JavaScript has no such check, and a program that tests the
platform first is correct JavaScript on Windows.

## Decision

Under `-compat=js` the bare call on Windows evaluates its arguments, as JS
does before the call, then throws `TypeError: process.<name> is not a
function`. The code after it is dead; the expression's value is its type's
zero. The strict lane keeps the compile-time error.

## Implementation notes

`codegen/llvm/emit_call.go` (the `getuid` family case).

## Verification

Windows 11: a platform-guarded call runs and a reached one throws, matching
Node 24.19's output. `TestE2EProcessGetUIDWindowsCompatJSTypeError`. The three
Node files pass.
