# ADR-00696: util.format `%d` (no float truncation) and `%c` (consume-and-drop)

- **Date**: 2026-09-04

## Context

Two Node-fidelity gaps in `util.format`, found comparing output against
Node.js v26:

1. `util.format('%d', 3.7)` produced `3` — a truncated integer. Node does
   **not** truncate a float for `%d`; it formats the number as-is (`3.7`).
   Only `%i` truncates to an integer.
2. `util.format('%c', 'red')` produced `%c red` — the specifier was left
   literal and its argument was appended as an excess arg. Node treats `%c`
   as a CSS-styling directive: it **consumes** its argument and emits
   nothing.

## Investigation

`util.format`'s specifier loop (`codegen/llvm/emit_util.go`) mapped both
`%d` and `%i` through `coerce(v, TypeI64)`, and never listed `%c` among the
recognized verbs, so it fell to the "unrecognized specifier left literal"
branch and the arg spilled into the excess-arg tail.

## Decision

- **`%d`**: format through `coerce(v, TypeF64)` + `emitValueToString` (JS
  number formatting — `3` stays `3`, `3.7` stays `3.7`). **`%i`** keeps the
  `TypeI64` truncation (matching Node, where only `%i` floors).
- **`%c`**: recognized as a verb that evaluates its argument for side
  effects, then discards it and emits nothing.

## Implementation notes

- File: `codegen/llvm/emit_util.go` (specifier handling only).

## Verification

- `go build -o klainmain .` clean.
- Repros match Node: `format('%d',3.7)` → `3.7`, `format('%i',3.7)` → `3`,
  `format('%c','red')+'|'` → `|`.
- E2E `tests/util_querystring_fidelity_test.go` (the two `%d`/`%c` cases) and
  the existing `util` suites pass; `examples/util/format_inspect.ts` runs
  with the expected output. Verified on macOS (Apple Silicon).

## Deferred

`querystring.parse` accumulating a repeated key into an array (Node
`parse('a=1&a=3')` → `{ a: ['1','3'] }`) was explored alongside this fix but
is **not shipped**: it needs `querystring.parse` to return `Map<string,any>`
and `JSON.stringify` to serialize a runtime-dynamic array held in an `any`
map value, which entangles with the JSON-serializer value path. Repeated
keys still collapse to the last value (documented as a caveat on the
`querystring` row) — a self-contained follow-up.
