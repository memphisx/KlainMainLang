# ADR-01283: generic references instantiate; `new Promise`'s value type

- **Relations**: `Extends ADR-01132`, `Supersedes part of TDD-00087`
- **Date**: 2026-09-29

## Context

`const v = await new Promise<number>((r) => r(1)); v + 1` was a type
error ("operator '+' cannot be applied to types 'T' and 'number'").
`new Promise<number>(…)` typed as `Promise<T>`.

The checker's `instantiate` substituted type parameters in arrays,
tuples, functions and object literals. It returned a generic class or
interface reference (`Promise<T>`, `Box<T>`) unchanged. So a generic
construct signature's result (`new <T>(…): Promise<T>`) kept its `T`, and
so did any other signature returning a reference.

Code generation typed an untyped `new Promise(…)` as a promise of a
64-bit integer, from before `number` was a double. So
`const q: Promise<number> = new Promise((r) => r(3))` awaited to 0: the
integer 3, read as a double.

## Decision

- `instantiate` substitutes a class or interface reference's type
  arguments, then instantiates the declaration again (`instanceOf`,
  `interfaceOf`).
- `new Promise(executor)`'s value type comes from the first of these that
  applies:
  1. the type argument;
  2. the checker's `Promise<X>`, when `X` is a number, string, boolean or
     `any`;
  3. `any`, the value an untyped promise resolves with.

  The emitter, its type inference and the module-global pre-pass share
  one helper (`newPromiseValueType`).

## Verification

Mac (Apple Silicon):

- `checker/check_test.go` covers a generic construct signature with an
  explicit type argument and with an inferred one.
- The probes print Node's results: `await new Promise<number>`, a
  contextually typed `new Promise` and an untyped one.
