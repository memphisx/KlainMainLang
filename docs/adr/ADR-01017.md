# ADR-01017: Boxed error-subclass recovery at render/member sites

- **Relations**: Closes the subclass residue of TDD-00222 (boxed-object
  type-id); Extends ADR-01003 (rejection-reason fidelity), ADR-00630
  (`extends Error`); Relates to TDD-00169, TDD-00155 Stage 6
- **Date**: 2026-09-18

## Context

The boxed-error probe (`emitBoxedBuiltinErrorProbe`) accepted only built-in
kinds — field-0 flag set AND low bits below `errorSubclassTagBase` — so an
error-**subclass** instance boxed into `any` (a `Promise.allSettled` reject
reason, a custom `AbortSignal` `abort(reason)`) fell through to the plain
-object arm: it rendered `[object Object]` and a `.message`/`.name` read
threw the no-dynamic-shape TypeError. The restriction assumed a subclass
layout "doesn't line up" with `errorObjType` — but it does, by construction:
`registerClasses` seeds an `extends Error` class's flat fields from
`errorObjType.Fields[1:]` with the class tag occupying the kind slot, and an
error subclass can never carry the index-1 vtable pointer that would shift
those offsets (a vtable requires virtual slots, which require subclassing,
and extending an Error subclass is rejected). message/name sit at
errorObjType offsets 1/2 for every error-shaped object — the same
prefix-compatibility throw/catch already relies on.

## Decision

The probe becomes `emitBoxedErrorProbe`: flag-set alone qualifies. Both
consumers — the boxed render arm (`emit_dynamic.go`) and the boxed
member-get arm (`emit_dynobj.go`) — now recover subclass instances exactly
like built-ins: `String(reason)`/`console.log` give `Name: message`
(`emitErrorToString`), `.message`/`.name`/`.stack` read the real fields.
`instanceof` was already precise and is unchanged; the low-bits builtin/
subclass split remains where behaviour genuinely differs (catch arms,
`instanceof` hierarchy, the rethrow tagging in `runtime_exceptions.go`).

**Recorded residue** (status caveat, not fixed here): `JSON.stringify` of an
error-subclass instance yields `{}` where Node serializes the instance's own
*enumerable* fields (an assigned `this.name`, extra declared fields) —
faithful behaviour needs per-field enumerability tracking on class
instances.

## Consequences

- Verified against the node oracle (macOS arm64): subclass reasons through
  `allSettled` and `AbortSignal.reason` match for `.message`, `.name`,
  `String()`, template interpolation, `.stack` presence, and `instanceof`.
- Tests: `TestE2EAllSettledErrorSubclassReason`,
  `TestE2EAbortReasonErrorSubclass`.
- The events-cancellation and allSettled caveats shrink to the JSON
  enumerability residue.
