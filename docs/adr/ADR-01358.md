# ADR-01358: Class values relate through their construct signatures

- **Relations**: Extends ADR-01355
- **Date**: 2026-10-03

## Context

`let K: typeof Shape = Square`, where Square's constructor takes a `number`
and Shape's an optional `string`, is TS2322 in tsc. So is assigning Square
to a constructor type `new (n?: string) => Shape`. The checker accepted both.
`examples/classes/class_values.ts` relied on it (ADR-01355).

## Investigation

- A class value's type is its statics plus one construct signature.
  `relate` compared only the properties. Since every class has a
  `prototype`, `typeof Square` fit `typeof Shape` whenever Square's
  instances fit Shape's.
- The checker built no type for a constructor type annotation (`new (…) =>
  R`), so nothing was checked against it.
- tsc names a class value `typeof C` and a constructor type `new (n?:
  string | undefined) => A`, with the declared parameter names. The checker
  printed the statics as an object literal and named every parameter `p0`,
  `p1`, ….
- tsc reports an initializer that does not fit at the declared name, not at
  `let`.

## Decision

- **Relation.** When both sides carry a construct signature, the source's
  must fit the target's. A class value against a function type is related
  through its construct signature. That turns what was a `maybe` into a
  `no` only where tsc also rejects.
- **Constructor types.** `new (…) => R` is an object type whose one member
  is that construct signature, as tsc models it.
- **Printing.**
  - `classValue` interns a class value with its class (`ClassOf`), and
    prints it as `typeof C`.
  - A constructor type prints as `new (…) => R`.
  - Function types carry their declared parameter names for display
    (`withParamNames`, which relations ignore). They print with `?` and
    `...` as tsc does.
- **Inference.** A constructor type infers from the source's construct
  signature (`make<T>(ctor: new () => T)` over a class or `Map`).
  `hasTypeParam`, `occurs` and `instantiate` see an object type's signatures.
  `instantiate` keeps parameter names.
- **Position.** `VarDeclaration.NamePos` records the name. TS2322 for an
  initializer is reported there.

## Implementation notes

- **Checker:** `checker/relate.go`, `checker/types.go`, `checker/symbols.go`,
  `checker/generics.go` and `checker/check.go`.
- **Front end:** `ast/nodes.go` (walker regenerated) and
  `parser/parser_stmts.go`.
- **Tests:** the checker tests now expect tsc's parameter names where they
  expected `p0`.

## Verification

Mac (Apple Silicon), against tsc 5.9:
- both rejected assignments with tsc's text and column;
- a compatible subclass accepted, both as `typeof A` and as a constructor
  type;
- `make(Shape).name` and `make(Map).size` through `new () => T` match Node;
- new `TestConstructSignatureAssignability`;
- the checker binary under the memory guard.
