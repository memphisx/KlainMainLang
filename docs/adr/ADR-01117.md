# ADR-01117: The `missing` type, storage types, and the discriminant rule

- **Relations**: `Implements TDD-00230` (Phase 2, P2.5); `Extends ADR-01112`
- **Date**: 2026-09-24

## Context

[TDD-00230](../tdd/TDD-00230.md) P2.5 left two checker pieces open after
[ADR-01112](ADR-01112.md):

- A distinct `missing` singleton for an omitted optional property. An
  explicit `null`, an explicit `undefined` and an omitted field are three
  different facts (superseding [TDD-00227](../tdd/TDD-00227.md); BACKLOG §0
  items 5 and 18), and a destructuring default applies for `undefined` and
  `missing`, never for `null`.
- A reference's storage type, separate from each read's narrowed type, so
  that `reprOf(storage)` picks the representation. ADR-01112's shadow
  report listed four disagreements where the checker answered a narrowed
  read (`x` after `x = 42`, `absent` after `= null`) and codegen answered
  the variable's representation.

## Investigation

- **typescript-go** keeps `missingType` apart from `undefinedType` only
  under `exactOptionalPropertyTypes`. Without it they are one type, and an
  optional property reads as `T | undefined`. Optional parameters get
  `undefinedType`, not `missingType`.
- **tsc 5.6.3 `--strict`**:
  - `interface P { s?: string | null }`: `p.s` is `string | null | undefined`.
  - `const { s = 1 } = p` is `string | 1 | null`: the default replaces the
    absent case and keeps `null`.
  - `if (p.s === undefined) { } else { p.s }` is `string | null`.
- **The checker's discriminant rule** narrowed a union by any property. tsc
  narrows only by a discriminant property (`isDiscriminantProperty`): the
  property's type differs between the members that declare it, and at
  least one member gives it a literal type (a unit type, a union of units,
  or `boolean`). Given `type A = { k: 'a', x?: number }` and
  `type B = { k: 'b', x: string }`, tsc leaves `v.x === undefined` at
  `A | B`. The checker narrowed it to `A`. With `x?: 'p'` against `x: 'q'`,
  or `t: boolean | undefined` against `t: string`, tsc does narrow.
- **codegen's `inferExprType`** on an identifier answers the variable's
  representation, not a narrowed type. So the shadow oracle was comparing
  two different questions.

## Decision

- **`missing`** is an interned type with the `Undefined` flag and its own
  identity (`Type.IsMissing`). Every rule that tests `Undefined` treats it as
  undefined: narrowing, `??`, `!`, `typeof`, destructuring defaults. It
  prints as `undefined`, and a union holding both prints `undefined` once.
- **An optional property's type** is `T | missing`, for class fields,
  interface fields and type-literal members. Optional and defaulted
  parameters keep `T | undefined`, as in typescript-go.
- `undefined` and `missing` are **mutually assignable**, so assignment
  reduction keeps the declared type's own member either way:
  `let v: number | undefined = p.u` stays `number | undefined`.
- **A discriminant** follows tsc's `isDiscriminantProperty`, and treats
  `undefined` and `missing` as the same unit when matching.
- **`Checker.StorageTypeOf(e)`**: for a variable or a property path, the
  declared type before the read narrows it (an evolving `let`'s storage
  type); otherwise `TypeOf(e)`. The shadow oracle's `ExprType` answers with
  it, since it is the question `inferExprType` asks.
- **Not in this step:** deleting codegen's per-site absence handling. Most
  of the remaining absence rows are codegen's `UncheckedIndex`: `a[5]` is
  `string` to TypeScript, but `undefined` at run time. The fix is a
  representation fact (a string slot that can hold `undefined`, BACKLOG §0
  item 18), so it belongs to P3.3's closed set, not to the checker.

## Implementation notes

- `checker/checker.go`:
  - the `missingT` singleton;
  - the `storage` side table and `StorageTypeOf`.
- `checker/types.go`: `IsMissing`, and union printing.
- `checker/symbols.go`: optional properties take `missing`.
- `checker/narrow.go`:
  - `narrowedType` and `narrowedMember` record the storage type;
  - `isDiscriminant` and `isLiteralType`;
  - `assignableMember` relates `undefined` and `missing`.
- `codegen/llvm/shadow_binder.go`: `ExprType` reads `StorageTypeOf`.

## Side effects discovered

- The discriminant rule above was wrong before this step, as the
  Investigation shows. It is fixed here.

## Verification

All on macOS arm64 (M4):

- `go test ./checker`, with each expectation checked against tsc 5.6.3
  `--strict`:
  - `TestMissing`:
    - class, interface and type-literal optional properties hold
      `missing`;
    - an explicit `undefined` is kept apart from it;
    - destructuring defaults and `??` remove it and keep `null`;
    - an optional parameter holds `undefined`, not `missing`.
  - `TestNarrowing`: the discriminant cases, and narrowing an optional
    property by `=== undefined`.
- Shadow report over the examples and apps: 472 disagreements, down from
  476. The four that went are exactly ADR-01112's narrowed reads
  (`examples/types/unions.ts:13,16`,
  `examples/nullable_scalars/nullable_scalars.ts:13,14`). No new bucket.
