# ADR-02050: A Request's ReadableStream body stays a stream

- **Date**: 2026-11-22

## Context

- `new Request(url, { body: stream, duplex: "half" })` stringified the
  stream (`[object ReadableStream]`): a Request only ever held bytes, so a
  stream body's Body methods read the wrong text, and `fetch` uploaded
  either that text or nothing. undici keeps the stream, checks `duplex`,
  and sends the stream's bytes.

## Decision

- A Request keeps a stream body the way a constructed Response does: the
  stream in `__kml_stream`, the stream flags in `__kml_bodyflags`. Its Body
  methods read it to its end first (`@__kml_req_collect`, the Response
  collector made per type). A stream held in an `any` init is recognized at
  run time, its chunk type checked as it is read.
- undici's TypeErrors: a stream body without `duplex`, and a GET/HEAD
  request with one. `new Request(req)` moves the stream, marking the input
  used.
- `fetch(request)` reads a stream body before sending it with the
  request's method, headers and signal. `fetch(url, init)` with a stream
  body goes through `new Request(url, init)`. Both forms of `fetch(request)`
  settle a task promise: the stream form is an async read.

## Consequences

- A stream upload is read whole and then sent with a Content-Length, where
  undici sends it chunked as it is read. The server gets the same bytes. A
  stream that never ends never sends, where undici would have sent its
  first chunks already.
