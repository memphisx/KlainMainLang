# ADR-00665: Completeness indexes for TypeScript features and JavaScript built-ins

- **Relations**: Extends [ADR-00664](ADR-00664.md)
- **Date**: 2026-09-03

## Context

ADR-00664 added a completeness index for Node built-in modules, so a reader can
see at a glance which are supported, partial, not-started, or out of scope. The
same ambiguity existed for the two other surfaces this compiler targets: a reader
of the status pages could not tell, for a given **TypeScript language feature**
(JSX, `satisfies`, conditional types, decorators) or **JavaScript built-in**
(`Intl`, `FinalizationRegistry`, `Proxy`, `Iterator` helpers), whether it was
supported, limited, unbuilt, or deliberately out of scope. The detailed pages
enumerate what *is* implemented well but are not a canonical checklist against
the full TS/JS surface, so the out-of-scope and not-yet-tracked items were simply
absent.

## Investigation

Two structured audits cross-referenced the canonical surfaces (the TS handbook
feature set; MDN's "standard built-in objects" + the ubiquitous Web globals)
against the status data (`type-system`, `language-constructs`, `jsdoc`,
`modules`; `string-methods`, `array-methods`, `object-collections`,
`number-math`, `json`, `regexp`, `binary-data-typed-arrays`, `encoding-text`,
`url`, `web-crypto`, `events-cancellation`, `timers`, `performance-timing`,
`global-functions`) and, where the pages were silent, the codegen source.

Findings that were previously untracked anywhere:

- **TypeScript**: type-level assertions and utility modifiers are *erased, not
  enforcing* (`as`/`satisfies`/`readonly`/`Partial`/template-literal types widen
  or erase); unions/tuples/intersections carry real fixed-shape restrictions;
  JSX has no parsing at all; `.d.ts` emission, dynamic `import(expr)`, and
  `eval` are out of scope by the AOT/no-runtime model.
- **JavaScript**: `Intl.*` and `Temporal` are entirely absent (the root cause of
  the `localeCompare`/`toLocaleString`/`Date.toLocale*` gaps); `FinalizationRegistry`
  and general `Iterator`/`AsyncIterator` helpers have no status row at all;
  `Proxy`/`Reflect` are dynamic-target-only subsets; several ✅ built-ins carry
  real residual caveats (byte-sequence strings, no `.buffer` back-ref, single
  URLSearchParams value per key, UTC-only `Date`).

## Decision

Add two dedicated, informational status pages mirroring the Node one:

- `docs/status/TYPESCRIPT-FEATURES.md` (source `typescript-features.json`) —
  every canonical TS feature grouped Implemented / Partial / Not started / Out of
  scope, each implemented/partial row pointing to its detailed counted page.
- `docs/status/JAVASCRIPT-BUILTINS.md` (source `javascript-builtins.json`) — the
  same four groups over the MDN standard-built-ins + Web-globals surface.

Both set `countsTowardParity: false` on every table (the same rationale as
ADR-00664: an out-of-scope built-in isn't a missing feature, and these indexes
must not double-count the detailed pages or drag the honest percentages down).
Each is registered in the README index as a `pageText`+`coverageOverride`
("— index") row — TypeScript under the TypeScript Core Language section, the JS
built-ins under Web Platform APIs — so the section totals are unaffected
(verified: 350/356 and 118/120 unchanged).

## Implementation notes

Same index-registration mechanics as ADR-00664 (a `pageFile` row would fail
`resolveCategoryTableRef`, which only resolves pages with a parity table; these
have none). The four-way nuance (implemented / partial / not-started /
out-of-scope) is carried by the table groupings, since the row schema has only
`implemented`/`missing`. Generation is idempotent — verified by regenerating
twice with an empty resulting diff.

## Side effects discovered

Named several canonical built-ins with **zero prior status tracking**:
`FinalizationRegistry` (its `WeakRef` sibling ships; designed in TDD-00163),
`Intl.*`, `Temporal`, and the ES2024/2025 `Iterator`/`AsyncIterator` helpers.
These are now listed (not-started or out-of-scope) rather than silently missing.

## Verification

`make status` regenerates both pages + README; `make status-check` (40 pages) and
`make reference-check` green; regeneration idempotent. Feature classifications
come from two audits against the status data and codegen greps; the compile-level
gaps that were directly checked (JSX absence, module-specifier importability) were
run on Mac.
