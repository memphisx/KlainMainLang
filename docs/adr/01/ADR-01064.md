# ADR-01064: A literal-only array literal is built from a static image

- **Relations**: Extends ADR-01061 (the conformance non-termination sweep — this is its one remaining `CLANG_TIMEOUT`), TDD-00029 (boxed nested-array elements), TDD-00127 (object-reference arrays)
- **Date**: 2026-09-22

## Context

BACKLOG §0 item 2. test262's `staging/sm/String/string-upper-lower-mapping.js` is a 65,536-row
`[string, string]` table (3.3 MB of source). It emitted 49 MB of IR and clang never finished; a 20 K-row
table took clang 21 s. Any generated lookup table — Unicode data, a country list, an opcode table — hits the
same wall, and the conformance runner reported it as `CLANG_TIMEOUT`.

## Investigation

- `emitArrayLiteralData` (`emit_arrays_core.go`) emits a GEP + `store` per element; for an array-typed element
  `storeArrayElem` → `boxArrayValue` adds a 16-byte `malloc` and a `{ptr,i64}` store, and the inner literal is
  itself a `malloc` + per-element stores. A `[string, string]` row is therefore two mallocs, two GEPs and four
  stores, plus the outer slot's GEP + store — ~10 instructions per row, times 65 K, plus 131 K interned string
  globals. Clang's cost on one enormous `main` basic block is superlinear.
- The array is mutable: `push`/`splice`/`unshift` (`emit_arrays_mutate.go`) `realloc` the data pointer, so the
  buffer can never *be* the constant. What can be static is the buffer's *image*: a string element is already a
  constant (`internString` returns a `getelementptr inbounds (...)` constant expression, valid in an
  initializer), a number literal is a bit pattern, a boolean is `0`/`1`.
- A number literal reaching an integer element slot goes through `coerce`'s float→int path (saturating
  `fptosi`, then a modular `trunc` for narrow targets, ADR-01061). Folding that at compile time is only safe for
  a value that is an exact integer in range — for anything else (`2.5`, `300` into `uint8`, `NaN`) the literal
  keeps the runtime coercion, so those semantics stay in exactly one place.
- Considered, rejected: a capacity/`cap` field so the buffer could alias the constant until first write
  (copy-on-write) — that is the deferred amortized-growth work of TDD-00127 and a much larger change for a
  one-time `memcpy` of a table the program was going to allocate anyway.

## Decision

`tryEmitStaticArrayLiteral` (`emit_arrays_literal_static.go`), called first from `emitArrayLiteralData`:

1. **Flat literal** of ≥ 16 elements (`staticArrayLiteralMinLen`), every element a foldable literal for the
   element type: one `private unnamed_addr constant [N x T]` global (`@.arrlit<n>`), then `malloc(N·size)` +
   `memcpy` from the global. Foldable: a string literal into a string slot; a boolean into `i1`; a number
   literal (optionally `-`-prefixed; decimal, hex, binary, octal, exponent) into `double`/`float` as its bit
   pattern (`llvmDoubleLit`, float32 via the rounded value), or into an integer slot when it is an exact
   integer within the slot's signed/unsigned range. Below 16 elements the per-element path stays (a handful of
   stores is no larger than the constant, and the small literals every test uses keep exercising it).
2. **Table of literal rows** (`T[][]`, any length, rows of any length including empty): one flat
   `[total x T]` image of every row's elements back to back, one `[N x i64]` row-length table, and a runtime
   loop `__kml_arr_lit_rows(outer, flat, lens, n, elemSize)` that mallocs each row's buffer, `memcpy`s its
   slice of the flat image, mints the row's `{data, len}` box and stores it into the outer slot — the same
   objects `boxArrayValue` + `emitArrayLiteralData` build per row, in O(1) IR.
3. **Not folded** (general path, unchanged): a spread or hole, an identifier/call/any non-literal element,
   `any[]`, nullable/union/flat-`@value` elements, object/tuple/function-typed slots, three-level nesting, a
   nested row whose own elements are not all foldable.

The produced array is indistinguishable from the per-element one: an ordinary malloc'd buffer with the same
header, box and element storage, so every mutator, alias and read path is untouched.

## Implementation notes

- `codegen/llvm/emit_arrays_literal_static.go` (new): `constArrayElemOperand`/`constNumberOperand` (pure,
  emitter-free foldability + operand), `constArrayImage`, `newConstGlobal`, `tryEmitStaticArrayLiteral`,
  `ensureArrLitRows`. `emitter.go`: `arrLitIdx`, `usedArrLitRows`. `emit_arrays_core.go`: the one call.
- The foldability check runs before any emission, so a non-foldable literal leaves no dead instructions or
  unused globals behind (`TestStaticArrayLiteralIRShape` asserts no `@.arrlit` for a literal with an
  identifier element).
- Integer range: signed `[-2^(bits-1), 2^(bits-1)-1]`, unsigned `[0, 2^bits-1]`; `-0` into an integer slot
  folds to `0` (JS ToInt32(-0) is 0); into a double slot it keeps its sign bit.
- The threshold is only for flat literals; a row table has no threshold because its per-row cost (two mallocs)
  is what made the repro pathological.

## Side effects discovered

- The repro test file still fails after this change, for two unrelated reasons now in BACKLOG §0:
  `toUpperCase`/`toLowerCase` are ASCII-only and `strlen`-bounded (a string containing `\u0000` is cut at the
  NUL; `"\u0000".toUpperCase()` is `""`), and the table is full-Unicode case mapping. `__kml_tolower` also has
  internal callers on header-less raw buffers (HTTP header names, URL hosts), so the length fix is not a plain
  `strlen` → `__kml_str_len` swap.
- `util.inspect` prints `-0` as `0` (Node: `-0`) and truncates a string at an embedded NUL; pre-existing,
  logged in BACKLOG §0.
