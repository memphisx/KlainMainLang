# ADR-00262: `Promise.resolve` / `Promise.reject`, and awaiting a `.then`/`.catch` chain

- **Relations**: builds on [ADR-00248](ADR-00248.md) (task-promise `.then` chaining), [ADR-00249](ADR-00249.md) (task-promise struct); fixes a use-after-free in the lightweight await path
- **Date**: 2026-08-20

## Context

Two gaps in the Promise surface, neither disclosed in the status rows:

- **`Promise.resolve(v)` / `Promise.reject(e)`** were unsupported — the standard
  factories for a settled promise. `Promise.resolve` hit "only simple function
  calls are supported".
- **`await` on a `.then`/`.catch`/`.finally` chain result crashed.** In the
  lightweight (no-fiber, `!hasMaySuspend`) await path, a task promise was assumed
  already settled — true for a non-suspending async fn's result, but a chain
  returns a genuinely *pending* promise its reaction settles via a queued
  microtask. The await read the pending promise (garbage value), freed its slot,
  and the end-of-script microtask drain then ran the reaction against that freed
  slot — a use-after-free (an intermittent segfault; observably, the chain
  callback ran *after* the value was already read).

## Decision

### `Promise.resolve` / `Promise.reject`

Both build a settled **task-shaped** promise (`__kml_task_alloc_promise`, state
field set directly), so `.then`/`.catch`/`.finally`/`await` all work:

- `Promise.resolve(v)` — a fulfilled promise carrying `v` (via `storePromiseValue`).
  An already-promise argument passes through (JS flattens a thenable); no argument
  is a fulfilled `Promise<void>`. Typed `Promise<typeof v>`.
- `Promise.reject(e)` — a rejected promise carrying the error
  (`errorPtrFromValue`, so a bare primitive is wrapped like a thrown value). Typed
  `Promise<number>` by default — a rejected promise never yields a value (await
  re-throws before the type is observed).

Only the promise + microtask runtime is pulled in (no fiber/libcurl), matching
the rest of the non-suspending async surface.

### Awaiting a pending chain promise

In the lightweight await path, if the task promise is still pending
(`state == 0`), drain the microtask FIFO once before reading it. One
`__kml_drain_microtasks()` runs the chain's reaction and every reaction it
enqueues (the FIFO drains to empty), settling the whole chain — so the await then
reads a settled promise instead of freeing a live one. A settled async-fn result
is never pending here, so the drain only fires for a real chain await. The
may-suspend path (`__kml_task_await_ready` + the scheduler) already drained
microtasks correctly and is unchanged.

## Consequences

- `Promise.resolve(v)` / `Promise.reject(e)` work with `await`, `.then`, `.catch`,
  and inside `Promise.all`/`.any`/`.race` arrays.
- `await p.then(f)`, `await p.then(f).then(g)`, and `await p.catch(f)` read the
  chained value correctly (callbacks run before the await returns) with no crash.
- `Promise.reject`'s default `Promise<number>` typing means a rejected promise
  awaited into a differently-typed binding may need a type annotation — harmless,
  since the value is never produced.
- `new Promise((resolve, reject) => …)` (the executor constructor) is still
  unsupported — tracked separately as the next Promise-surface item.
