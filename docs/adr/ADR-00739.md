# ADR-00739: Windows fidelity batch — os.tmpdir algorithm, CSPRNG mkdtemp, unlink attribute restore, GetLastError-after-free, isWindows probe

- **Relations**: Implements five §4/§6 rows of [TDD-00180](../tdd/TDD-00180.md); extends [ADR-00719](ADR-00719.md) (the Win32 platform layer), [ADR-00737](ADR-00737.md) (the same session's process/socket hardening)
- **Date**: 2026-09-07

## Context

The small, independently verifiable rows from the Windows faithfulness audit, batched: each is a localized change with an observable behaviour Node documents.

## Decision

- **`os.tmpdir()`** on Windows now implements Node's exact algorithm (`lib/os.js`) in a shim helper `__kml_os_tmpdir`: `TEMP`, then `TMP`, then `<SystemRoot|windir>\temp` (previously a literal `C:\Windows\temp`), with one trailing backslash stripped unless it names a drive root (`C:\` stays). The emitter wraps the raw C string into a length-prefixed header string, as every runtime-returned string must be — the first cut skipped the wrap and crashed on concat, which is worth recording: **a raw `char*` from a runtime helper is not a language string**.
- **`mkdtemp` names** come from the OS CSPRNG (the shim's `getrandom` → `BCryptGenRandom`, as Node's `uv__random` does) instead of a predictable `GetTickCount64 × pid` mix; the old mix remains only as a fallback if the CSPRNG fails.
- **A failed unlink of a read-only file restores the read-only attribute** it had cleared first, as libuv does — the file is left exactly as it was.
- **`GetLastError()` clobbered by `free()`**: a dozen error paths freed the wide-path buffer between the failing Win32 call and the `fail()` that read `GetLastError()` (free can reach `HeapFree`, which may overwrite it). Every `free` in `win32fs.c` now goes through `free_keep_err` (saves and restores the last error); mechanically applied file-wide so no future error path can regress.
- **`__kml_builtin.isWindows`** (the conformance-runner environment probe) is host-computed like `isLinux`/`isMacOS` instead of hardcoded `0`.

## Consequences

- `tests/os_tmpdir_windows_test.go` runs the compiled program under controlled `TEMP` values: trailing backslash stripped, drive root kept, plain path unchanged.
- mkdtemp randomness is visible in every `mkdtempSync` test (names no longer correlate with time); no dedicated statistical test — the change is a one-line source swap to an already-tested primitive.
- Verified on Windows 11 x86-64: the new tmpdir test plus the fs/child_process/cluster/worker/URLPattern/RegExp/Fetch batch, and the full suite on Linux x86-64 (Docker).
- Still open from the same audit table (deliberately not in this batch): `FILE_SHARE_DELETE` + `\\?\` long paths, `fs.watch`/`utimes`/`link`/`fsync`/`ftruncate`/`copyFile`/`statfs`, the console/encoding column, the WSA errno table, and the CRT fd table itself ([TDD-00180](../tdd/TDD-00180.md) Option A).
