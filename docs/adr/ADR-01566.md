# ADR-01566: `typeof x.p` reads an object's own property

- **Date**: 2026-10-10

## Context

`let x: typeof o.a = 2`, with `o` an object, crashed the compiler with a
nil dereference in the checker. tsdiag hit the same crash on four cases of
the TypeScript corpus (`cloduleGenericOnSelfMember.ts`,
`controlFlowForIndexSignatures.ts`, `enumAssignmentCompat2.ts` and one
other), after ADR-01562 made the checker answer more of them.

## Investigation

`typeQueryType` (`checker/symbols.go`) walks the path's properties on
`apparentType(t)`. `apparentType` is a primitive's wrapper interface
(`String`, `Number`, …) or an array's `Array<T>`, and nil for every other
type, so an object's property path dereferenced nil. The previous build
crashed on the same two-line program.

## Decision

The path reads properties on `apparentType(t)` when there is one, and on
`t` itself otherwise.

## Implementation notes

`checker/symbols.go` (`typeQueryType`).

## Side effects discovered

None.

## Verification

`TestTypeOf` case; the four tsdiag cases check without a panic (Mac).
