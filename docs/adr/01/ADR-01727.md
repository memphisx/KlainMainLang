# ADR-01727: EventEmitter's typed event map in the checker

- **Relations**: `Implements TDD-00230`, Extends [ADR-00392](../00/ADR-00392.md)
- **Date**: 2026-10-18

## Context

`lib/node/events.ts` declared every `EventEmitter` method with `eventName: string | symbol` and `...args: any[]`. The checker therefore accepted every call on a typed emitter (`EventEmitter<{ data: [number, string] }>`):

- `emit("undeclared")`;
- `emit("data", "bad", 1)`;
- a listener taking more parameters than its event passes.

tsc, with @types/node, rejects all three.

Declaring @types/node's types exposed several checker bugs:

- **Unresolved defaults:** a type-parameter default naming a declared type (`class C<T = S>`, `function f<T = S>`, `type A<T = S>`) resolved to nothing. The resolver renames top-level declarations per module (`S` → `S__kml_mod0`) but did not rewrite type-parameter defaults, or a type alias's constraints and defaults. `new C()` was `C<unknown>`.
- **Object vs array:** an object literal type was "maybe" assignable to an array or tuple, so `{ a: [] } extends [never] ? 1 : 2` stayed undecided. A member typed with it was unanswered, and an alias of it accepted either branch.
- **Single overload:** a call to a method with one overload signature went through overload resolution, which skips the checks of a plain call (tuple and `never` rest parameters, the inferred instantiation).
- **Deferred conditional target:** inference did not look into a conditional type that was not yet decided (`Key<K, T>` while `T` is still being inferred), so `K` stayed uninferred.
- **Literal widening:** inference widened `"a"` inferred through `K | "z"`. tsc keeps it there; it widens through `K`, `K | undefined`, `K[]` and `{ v: K }`.
- **Tuple rest arity:** `(...args: []) => void` accepted a function requiring a parameter.

## Decision

### Declarations

- `lib/node/events.ts` declares @types/node's `EventMap`, `DefaultEventMap`, `AnyRest`, `Args`, `Key`, `Key2`, `Listener`, `Listener1` and `Listener2`.
- `EventEmitter` becomes `EventEmitter<T extends EventMap<T> = DefaultEventMap>`.
- Each public method gets @types/node's signature as an overload ahead of its implementation:
  - `addListener`, `on`, `once`, `prependListener`, `prependOnceListener`, `removeListener` and `off` take `(eventName: Key<K, T>, listener: Listener1<K, T>)`;
  - `emit` takes `(eventName: Key<K, T>, ...args: Args<K, T>)`;
  - `listeners`, `rawListeners`, `listenerCount` and `removeAllListeners` follow the same pattern.
- The implementations are unchanged.
- Codegen ignores overload signatures when deciding whether a class's type parameters are type-only (`eraseTypeOnlyGenerics`). `EventEmitter` still compiles as an ordinary class, extendable with type arguments.

### Checker

- **Defaults:** the resolver rewrites type-parameter defaults of functions and classes, and an alias's constraints and defaults. An alias's type parameters stay bound while its body is rewritten.
- **Relation:** an anonymous object type without a `length` property is not an array or a tuple.
- **One overload:** a call to a single overload signature is checked as a plain call. Its messages are an ordinary call's, as tsc reports them.
- **Inference into conditionals:** a deferred conditional parameter type infers from both of its branches (tsc's `inferToConditionalType`). A branch binding `infer` names is skipped.
- **Literal widening:** a literal inferred through a union parameter that has a literal member of the same primitive kind is kept (`literalKept`, which replaces this session's `lowPriority` map).
- **Rest arity:** a rest parameter of a fixed tuple type relates as that many parameters.
- **Generic rest:** the check reports a call's first mismatching argument only, as tsc does.

## Verification

macOS (Apple Silicon), against tsc 5.9 with @types/node 24 and Node:

- The probe file's four expected errors match tsc's, at the same positions and with the same types:
  - `emit("undeclared")`;
  - a wrong argument type;
  - a listener with too many parameters;
  - an undeclared event on a subclass.
- Its valid lines match Node's output.
- `tests/eventemitter_test.go` TestE2EEventEmitterTypedMapChecked covers the valid program and the three rejections.
- `tests/tuple_rest_test.go` TestE2ETypeParamDefaultsAndLiteralInference covers:
  - defaults naming a declared type;
  - the literal-widening cases;
  - the decided object-vs-tuple conditional.
- The checker, parser, codegen, resolver, binder and declaration-conformance unit tests pass.
