# ADR-02065: XMLHttpRequest.statusText

- **Date**: 2026-11-22

## Context

- TypeScript's lib declares `XMLHttpRequest.statusText`, so a program
  reading it type-checks. The compiler's XMLHttpRequest had no such slot,
  and the read failed in codegen with an internal error.
- Two of this project's apps read `process.argv` from index 1, as if
  `argv[0]` were the program: `klainload` took the program's own path as
  its target URL (every request failed at once) and `klainconf` ignored its
  directory argument. Node's `argv[1]` is the script.

## Decision

- The XMLHttpRequest struct gets a `statusText` slot. It is `""` when
  constructed and after a network failure. A completed `send()` stores the
  status line's reason phrase, from the same `__kml_fetch_status_text`
  that `Response.statusText` reads.
- The case-mapping sidecar (casemap.c, now also `normalize`'s tables) is
  compiled with the dead-strip flags the other large sidecars use. A
  program that never normalizes drops ~99 KB of tables at link.
- The apps read their arguments from `process.argv[2]`. `klainconf`'s
  snapshot mode (stdin not a terminal) draws on the normal screen, so the
  snapshot stays visible after it exits.

## Consequences

- `TestE2EXHRStatusText` covers the initial, success and failure values.
- `klainload` against a local server: 85,077 requests, all 2xx.
- Verified on Node304 (Linux x86-64).
