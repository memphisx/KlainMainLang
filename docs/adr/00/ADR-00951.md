# ADR-00951: Clean rejection of a mixed object / nested-array literal (`[obj, [x]]`)

- **Relations**: `Extends TDD-00205` (Stage 2 heterogeneous-array boundary)
- **Date**: 2026-09-15

## Context

An array literal mixing an object element with a nested-array element emitted
invalid IR instead of a clean compile error (or a boxed `any[]` under
`-compat=js`):

```ts
const a = {}, b = {};
const r = [a, [b]].flat();   // clang: store {ptr,i64} into a ptr slot
```

Found in the Test262 invalid-IR (Bucket B) sweep — the sole remaining
`built-ins/Array` CLANG_ERROR file,
`Array/prototype/flat/empty-object-elements.js`.

## Investigation

`inferArrayType` (emit_exprs_types.go:296) picks the element type from the first
element under the strict lane, so `[a, [b]]` infers `ArrayOf(objectType)`.
`emitArrayLiteralData` (emit_arrays_core.go:668) then coerces each element to
that type and has a heterogeneous-reject guard, but the guard compares
`val.Ty.IR != elemTy.IR`. Every array-shaped value reports `Ty.IR == "ptr"`
(the header model's shared "ptr" trap), identical to an object/string slot — so
a nested-array element (whose real storage is a `{ptr,i64}` aggregate) sailed
past the IR-equality check and `storeArrayElem` emitted `store ptr <{ptr,i64}>`
into a bare ptr slot: invalid IR.

The reverse (`[[1],2]`, elemTy `number[][]`, element `2` a number) has the same
blind spot.

## Decision

Add a second element guard right after the IR-equality one that compares
array-ness directly rather than through `.IR`: reject when
`val.Ty.IsArray != elemTy.IsArray` and `elemTy` is not dynamic. A dynamic/any
`elemTy` is exempt because `storeArrayElem` boxes arrays into `any[]` slots —
so `-compat=js`, where `inferArrayType` already lowers a heterogeneous literal
to `ArrayOf(TypeAny)`, keeps boxing and running; the strict lane gets a clean
`COMPILE_ERROR` naming the heterogeneous-array limitation. An array-of-arrays
`elemTy` (both sides `IsArray`) still matches and compiles unchanged.

## Implementation notes

One guard added in `emitArrayLiteralData` (emit_arrays_core.go). No change to
inference or to the boxed-element path.

## Side effects discovered

`flat()` over a `-compat=js` boxed `any[]` whose element is itself a boxed
array does not recurse into that element (`[a,[b]]` flattens to
`[{…},[{…}]]`) — a separate boxed-array-flat gap, left as-is and out of scope
for this reject fix.
