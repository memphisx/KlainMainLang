# ADR-00236: AbortController / AbortSignal (Events & Cancellation, stage 3a)

- **Relations**: `Implements TDD-00081` (Stage 3); `Extends ADR-00235`
- **Date**: 2026-08-19

## Context

Final row of the Events & Cancellation area: the WHATWG cancellation token that
the `EventTarget` work was building toward. This ships the objects and the abort
event (the token pattern, useful standalone); wiring `signal` into `fetch`/timers
to actually cancel in-flight work is a follow-on (Stage 3b).

## Decision

- **`AbortSignal`** is an object with `aborted` (bool), `reason` (ptr), and a
  hidden `listeners` map, tagged `IsAbortSignal`. It behaves as an EventTarget:
  `resolveEventTargetMap` returns the `listeners` field for an `IsAbortSignal`
  object (and the object itself for a plain EventTarget), so the Stage-2
  `addEventListener`/`removeEventListener`/`dispatchEvent` implementations work on
  a signal unchanged — the `emit_call.go` guard just gained `IsAbortSignal`
  alongside `IsEventTarget`.
- **`AbortController`** (`new AbortController()`) wraps a fresh signal in its
  `signal` field. `controller.abort(reason?)` sets `signal.aborted = true`,
  records `reason`, and dispatches a plain `Event("abort")` to the signal's
  listeners (reusing the extracted `emitDispatchToMap`).
- `AbortController`/`AbortSignal` resolve as type names; `signal.aborted`/
  `signal.reason` and `controller.signal` are ordinary object-field reads.

## Implementation notes

The Stage-2 dispatch loop was factored into `emitDispatchToMap(mapPtr, event)` so
both `EventTarget.dispatchEvent` and `AbortController.abort` share it, and
add/remove/dispatch route their target through `resolveEventTargetMap` rather than
assuming the object *is* the map. `inferExprType` gained `abort()`→void (so
`() => ctrl.abort()` infers a void return, not the malformed i64 default).

## Side effects discovered

- **Not yet wired into `fetch`/timers** — the signal is a working token
  (check `aborted`, listen for `"abort"`), but passing it to `fetch(url,
  { signal })` does not yet cancel the in-flight transfer, and there is no
  `setTimeout(..., { signal })` cancellation. That runtime integration
  (`curl_multi_remove_handle` on the tracked transfer, per the status note; the
  timer path) is the remaining follow-on.
- `reason` is a pointer (string/object); a defaulted `AbortError` DOMException
  when no reason is given is not synthesized (reason stays null).

## Verification

- `tests/abort_test.go`: signal aborted-flag + "abort" listener firing on
  `abort()`, `abort(reason)` recording the reason, and an `AbortSignal` passed to
  a function that registers a listener. All pass.
- `examples/events/abort-controller.ts` (the token pattern end to end) runs
  correctly; IR verified with `clang`.
- `go build`, `go vet ./...`, and the abort/event/eventtarget subset are green on
  Apple Silicon (macOS).
