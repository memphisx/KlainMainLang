# ADR-00858: Leading-/trailing-dot float literals emit exact bit pattern, not verbatim

- **Date**: 2026-09-10

## Context

A decimal fraction written without a leading integer digit — `.9`, `-.9` — is
valid JavaScript (and idiomatic: `.5`, `.25`). This compiler emitted such a
literal's source spelling *verbatim* into the IR, producing `store double .9,
ptr …`. LLVM's double token requires a digit on both sides of the point, so it
rejects `.9` with "expected value token" — invalid IR that reached clang.

Found while grinding the invalid-IR backlog: the "expected value token"
CLANG_ERROR bucket includes `Math/trunc/Math.trunc_NegDecimal.js`
(`Math.trunc(-.9)`) and BigInt range tests whose source uses leading-dot floats.

## Investigation

`emitNumberLit` (`emit_exprs.go:257`) handled a plain fraction (no exponent) by
returning `Value{Ref: v}` — the raw source string — on the stated assumption
that "LLVM parses `1.5` fine." True for `1.5`, false for `.9`/`-.9`. Every other
numeric path in the same function already normalizes through
`llvmDoubleLit(f) = "0x%016X"` (`emit_exprs.go:305`), the exact IEEE-754 hex
bit-pattern. Both Go's `strconv.ParseFloat` and LLVM's parser are
correctly-rounded, so routing the fraction through `ParseFloat → llvmDoubleLit`
yields the identical double while always producing a valid token.

## Decision

Replace the verbatim fraction path with `ParseFloat → llvmDoubleLit` (with the
existing invalid-literal error as the fallback). This normalizes `.9`, `-.9`, and
any other spelling uniformly and bit-exactly.

## Implementation notes

- `codegen/llvm/emit_exprs.go`, `emitNumberLit`.
- Bit-exact by construction — no value changes for any previously-valid literal
  (`1.5` now emits its hex form, same double).

## Side effects discovered

A *trailing*-dot literal (`9.`) fails earlier, at the parser (`expected IDENT,
got )`) — the lexer reads `9.` as `9` followed by a member-access dot. That is a
separate, rarer front-end issue and is left untouched here; this ADR fixes the
codegen emission of the (already-parsed) leading-dot form.

## Verification

- E2E `TestE2ELeadingDotFloatLiteral`: `.9` → `0.9`, `Math.trunc(-.9)` → `-0`,
  `.5 + .25` → `0.75`, matching `node -e` exactly.
- `go build`, `go vet` clean. Platform: Apple-Silicon Mac.
