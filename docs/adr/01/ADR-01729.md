# ADR-01729: Symbol-keyed members, discriminated unions and builtin types in the relation

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-18

## Context

The checker accepted any value as the fetch API's `BodyInit` and `HeadersInit`, where tsc reports TS2769, TS2345 and TS2322. For example, `fetch(u, { body: 5 })`, `{ body: true }`, `headers: new Map<string, number>()` and `new Response(5)` all compiled. The causes:

- **Empty interfaces:** `Iterable<T>` and `FormData` were declared empty, so any non-nullish value fit them.
- **Symbol-keyed members:** a member named by a symbol (`[Symbol.iterator]`) in an interface or type literal was dropped, and the type was marked partial. Every relation against it answered "maybe".
- **Discriminated unions:** an object sharing a discriminant property with a union of objects was always "maybe". `{ done?: false; value: [string, number] }` fit `IteratorResult<number>`.
- **Depth limit:** the relation stopped at depth 8. A function result `MapIterator<[K, V]>` against `Iterator<number>` sits deeper than that.
- **Builtin types:** a builtin declaration is partial, since it lists only what this compiler implements. So a `Map` was "maybe" an array, a `Record<string, string>` or a `Headers`, although TypeScript's `Map` has neither `length`, nor an index signature, nor `append`.

## Decision

- **Declarations:**
  - `Iterable<T, TReturn, TNext>` declares `[Symbol.iterator](): Iterator<T, TReturn, TNext>`.
  - `String` declares `[Symbol.iterator](): StringIterator<string>`, with `StringIterator` as in TypeScript's library.
  - `FormData` declares TypeScript's methods. It still has no constructor.
- **Symbol keys:** a `[Symbol.<name>]` member of an interface or type literal is recorded under the `@@<name>` key, the key the parser gives a class's or object literal's member of that symbol. Messages and printed types show it as `[Symbol.<name>]`.
- **Discriminated unions:** the relation still answers "maybe" for a source sharing a discriminant, unless every object member is ruled out. A member is ruled out when either:
  - none of the source's discriminant values fits the member's discriminant, with `boolean` split into `true` and `false` as tsc does; or
  - a property that is no discriminant is missing or does not relate. No split of the source can change such a property.
- **Union members:** these are related with a missing required property as "no", as tsc relates each member.
- **Memo and depth:** relations between object types are memoized by (source, target, relation), as tsc's relation cache is.
  - A pair still being related answers "maybe".
  - A result that leaned on that assumption is not remembered.
  - With the memo, the depth limit rises to 20.
- **Builtin types against TypeScript's lists:** `lib/tsmembers.txt` is TypeScript's full member list for each builtin interface. It settles what a partial builtin source lacks:
  - a member both lists lack is missing;
  - a known builtin interface has no implicit index signature;
  - a builtin class or interface without `length` is no array.
  - A missing-member check on a builtin target reports the members its declaration lists.
- **Index signatures:** a type literal's index signatures are printed (`{ [x: string]: string; }`).

## Verification

macOS (Apple Silicon), against tsc 5.9:

- **The BACKLOG probe:** its six errors match tsc's lines.
- **`tests/class_foreign_field_test.go` TestE2EBodyInitHeadersInitChecked:**
  - rejects `body: 5`, `body: true`, a `Map` as headers, `new Response(5)`, a `Map<string, number>` as `Iterable<number>`, a number as `Iterable`, a class without `[Symbol.iterator]` (TS2741's message), the discriminated `IteratorResult` case, and a `Set` as an array;
  - runs the valid iterable and `BodyInit`/`HeadersInit` values against Node.
- **Unit tests:** checker and declaration-conformance pass; `lib/tsmembers.txt` was regenerated.
