# ADR-00872: Eager-box captured object/class-instance locals (try/catch dominance)

- **Relations**: `Extends ADR-00619`
- **Date**: 2026-09-11

## Context

Building the WPT conformance track (ADR-00871), the `testharness.js` shim's
`promise_test` — a `const t = new __WptT(name)` captured by two `.then` closures
inside a `try`, with `t` also read in the `catch` — failed to compile with
`invalid LLVM IR input: Instruction does not dominate all uses` on a
`malloc`/`load` pair. Minimal repro:

```ts
class T { name: string; constructor(n: string){ this.name=n; } finish(): void {} }
let counter: number = 0;
function pt(fn: (t: T) => any, name: string = ""): void {
  const t: T = new T(name);
  try {
    Promise.resolve(fn(t)).then((): void => { t.finish(); }, (e: any): void => { counter = counter + 1; t.finish(); });
  } catch (e) { counter = counter + 1; t.finish(); }
}
pt((): any => Promise.resolve(1), "p");
```

## Investigation

ADR-00619 fixed exactly this failure class for scalars: a local captured by a
closure is heap-boxed so closure and scope share one mutable cell; boxing it
*lazily* at the closure-construction site lands the `malloc` in whatever block
that site sits in (a conditional / `try` body), which doesn't dominate a later
read of the box. The fix was to box **eagerly at the declaration point**, which
dominates the whole scope, via `hoistedCaptures` + `boxHoistedCapture` in
`emit_exprs_vardecl.go`.

Reading the emitted IR for the repro (`-emit-llvm`), the catch block loaded `t`
from the capture box `%t22 = call malloc(8)` allocated inside `try.body.0` — the
lazy site — while the eager box was never created. The cause: `emitVarDecl`'s
eager-box branch (`else if e.hoistedCaptures[v.Name]`) sits *after* the
`ty.IsObject` early return that dispatches to `emitObjectVarDecl`. `ClassType`
always sets `IsObject` (`types.go`), so a captured class-instance / object `const`
returns through `emitObjectVarDecl` and never reaches the eager-box path — it fell
back to the lazy `promoteCaptureToCell` inside the try. ADR-00619 covered only the
scalar/ptr path; object and class-instance bindings were the residual.

`capturedLocalNames`/`capScanStmts` *do* recurse into try/catch bodies, so `t` was
correctly in `hoistedCaptures` — the scan wasn't the gap; only the object
declaration path ignored the set.

## Decision

Give `emitObjectVarDecl` the same eager-box branch the scalar path has. When the
binding name is in `e.hoistedCaptures`, allocate its heap cell at the declaration
point instead of letting the closure box it lazily: object bindings are a uniform
`ptr` slot, so the cell holds one pointer seeded `null`, registered as a `Boxed`
symbol. The existing `storeObj` helper already re-resolves the variable's current
storage via `lookup` before storing the initializer, so it writes the real object
pointer into the box with no further change; and because the symbol is `Boxed`,
the lazy `promoteCaptureToCell` path (`if !cap.Sym.Boxed`) is skipped and reuses
this cell. Reads in the closures and the catch both resolve through the `Boxed`
symbol to the eagerly-allocated cell, which now dominates.

Placement mirrors ADR-00619's `var` vs `let`/`const` rule: a function-scoped `var`
boxes in the entry block (dominates unconditionally); a `let`/`const` boxes at its
body declaration point (dominates its block scope and re-`malloc`s per loop
iteration for fresh per-iteration `let` cells).

## Implementation notes

`codegen/llvm/emit_objects.go`, `emitObjectVarDecl`: one `else if
e.hoistedCaptures[v.Name]` branch between the module-global promotion and the
default alloca, boxing as `ptr` (not `ty.IR`, which for a class is the struct) so
the cell matches the object storage model. Boxes exactly the set the lazy path
would have (the captured ones), only earlier — non-captured object locals are
untouched (no over-boxing).

## Side effects discovered

None. This removed the last workaround in the WPT shim (`promise_test` had guarded
only the synchronous `fn(t)` to keep the `.then` closures out of the try — see
ADR-00871 Side effects); the shim is now the straightforward form.

## Verification

macOS (Apple Silicon). The minimal repro and both `promise_test` forms compile
clean and exit 0; the emitted IR shows the box `malloc` now preceding `setjmp`, so
it dominates both `try.body` and `try.catch`. Regression test
`TestE2ECapturedObjectInTryUsedInCatch` (`tests/exceptions_test.go`) added and
passing. The WPT shim's synthetic selfcheck (sync `test` + `promise_test`) reports
PASS with the reverted straightforward `promise_test`. Targeted
exception/closure/capture/object/async suites pass; `go build`/`go vet` clean.
