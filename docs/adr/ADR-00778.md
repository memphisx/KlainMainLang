# ADR-00778: `T | undefined` element-absence results — `.pop()`/`.shift()`/`.find()`/`.findLast()`/`.at()` (TDD-00187 Stage 1)

- **Relations**: Implements [TDD-00187](../tdd/TDD-00187.md) Stage 1; reuses [TDD-00064](../tdd/TDD-00064.md)'s `{ i1, T }` optional and [ADR-00628](ADR-00628.md)'s NaN-boxed `undefined`; scoped-around limit from [ADR-00246](ADR-00246.md)
- **Date**: 2026-09-08

## Context

Array element-absence operations — `.pop()`/`.shift()` on an empty array,
`.find()`/`.findLast()` on a predicate miss, `.at()` out of range — were
modelled as returning a bare, zero-filled `T`, though TypeScript types all of
them `T | undefined`. Each carried a documented zero-fill caveat, the family
TDD-00187 exists to retire. The representation already existed (TDD-00064's
presence-flagged `{ i1, T }` optional for scalars; the null pointer for pointer
types; the NaN box's `undefined` immediate for `any`) — only the inferred
return types and the miss branches said otherwise.

## Decision

**Types.** `inferExprType` (and `emitVarDecl`'s mirroring pre-inference) now
reports `T | undefined` (`Nullable|IsUndefined`) for the five operations, via
`undefinedableElem` (`emit_undefined.go`). A nested-array element and a
by-value tuple element stay bare (their aggregates have no absent state —
ADR-00246's nesting limit, scoped around, not fixed); a dynamic element stays
`any` (its box carries `undefined` natively).

**Values.** Each emit site produces the matching representation
(`wrapUndefinedable`):

- scalar element: `{ i1 present, T value }` — `.pop()`/`.shift()` derive the
  presence bit from the emptiness test, `.find()`/`.findLast()` from a new
  found-flag slot, `.at()` from the bounds check;
- pointer element (string/object/bigint handle): the miss stays the null
  pointer; only the static type gains the flags. A bigint-TypedArray `.at()`
  miss now selects a null handle instead of fabricating `0n`;
- dynamic element: the miss branch stores the `undefined` NaN-box immediate
  (`missRef`) where it stored a raw 0 (which decoded as `+0.0`).

**Consumer policy (the mode axis, confirmed in TDD-00187).** Strict (default)
is faithful strictNullChecks: `checkStrictUndefinedAssign` rejects a
`T | undefined` absence result flowing into a bare-`T` boundary — typed var
declaration, assignment, return, call argument, field store — and `emitBinary`
rejects arithmetic/relational use, each with a fix-it message (narrow /
`??` / `!`). A flow-narrowed local (`NarrowedNonNull`) passes. `-compat=js`
gates nothing: `coerce`'s existing payload demotion is exactly
`strictNullChecks: false` auto-widening. The gate keys on `IsUndefined`, so
TDD-00064's documented lenient `T | null` behaviour is untouched.

**Postfix `!` (non-null assertion).** Added as the strict-mode escape hatch:
`ast.NonNullExpression`, parsed in the member/call chain (unambiguous — `!=`/
`!==` lex as their own tokens), emitted as a compile-time unwrap with no
runtime check, exactly as TS. Every generic AST walker (resolver rename/TDZ/
definite-assignment, free-variable and capture scans, escape analysis, the
upgrade/new scanners) learned the node — the resolver's rename walker was the
one that actually broke without it (the inner identifier kept its unmangled
name at module scope).

**Observables fixed alongside:**

- `console.log`, `String()`/template interpolation, and the ptr print guard
  render an absent `T | undefined` as `undefined` (`absentLiteral`), keeping
  `T | null`'s `null`.
- Equality became presence-aware (`emitNullableScalarValueEq`): an absent
  result never compares equal to the payload zero (`[].pop() === 0` is now
  `false`; also fixes the pre-existing `T | null` payload-zero collision, e.g.
  a `Map.get()` miss comparing `=== 0` as true).
- `??`'s inferred type unwraps a nullable-scalar left operand, and
  `withoutNullable` now clears `IsUndefined` too (a leaked flag made `??`
  treat a bare payload as statically nullish).

## Corpus migration (measured)

The strict flip broke exactly 2 of 277 examples and 5 E2E tests. The examples
took a one-token `!` each; four tests asserted the old zero-fill divergence and
now assert `undefined` (the fifth was `findLast`'s miss). No test relied on the
absence result in arithmetic beyond those.

## Consequences

- The four status-page zero-fill caveats for these operations are retired;
  the rows' remaining caveat is the nested-array-element scope-out.
- `typeof arr.pop()` still reports the static kind (`"number"`), not
  `"undefined"`, when absent — recorded as a caveat; `JSON.stringify` of an
  absent scalar likewise renders the payload.
- An un-narrowed `T | undefined` *local* still collapses leniently in
  arithmetic (`emitIdent` unwraps locals before `emitBinary` sees them); only
  direct results gate. Recorded as a caveat on the strict gate.
- Stage 2–4 of TDD-00187 (optional fields/destructuring, env/argv, TTY) build
  on the same helpers.

Verified on macOS/Apple Silicon (full `make test-par`, `make examples`, Node
oracle).
