# ADR-02007: A bigint held in any written by Buffer; a bigint[] into a TypedArray

- **Date**: 2026-11-21

## Context

- `buf.writeBigInt64LE(v)` (and the other 64-bit writes) with `v` held in
  `any` threw "Cannot mix BigInt and other types" whatever `v` held. A
  program that reads `Array.prototype.values` as a value iterates its arrays
  through the protocol, so `for (const v of [5n]) buf.writeBigInt64LE(v)`
  hit it.
- `new Float64Array([1n])` failed to compile ("no conversion from bigint to
  number") when the source array's static element type was bigint. Only a
  TypedArray source was treated as mixing.

## Decision

- A boxed argument to a 64-bit Buffer write is unboxed when its box holds a
  bigint, and throws Node's TypeError otherwise.
- A TypedArray built from an array-like whose elements are bigint while its
  own are numbers (or the reverse) converts each element through
  `toTypedArrayElem`, which throws V8's TypeError.

## Implementation notes

- codegen/llvm/emit_buffer.go: `emitAnyBigIntOrMixError`.
- codegen/llvm/emit_arraybuffer.go: `emitTypedArrayFromArrayLike`.

## Verification

- `TestE2EBufferBigInt64WriteRange` (with a boxed 7n, 5, "5" and null) and
  `TestE2EWeakFinalizationTypedArrayArgumentsJS` match Node on Linux x86
  (Node304).
