# TDD-00073: Runtime debug symbols (DWARF via LLVM debug metadata)

- **Status**: Not Started
- **Date**: 2026-08-18
- **Notes**: Emit LLVM debug metadata (`DICompileUnit`/`DISubprogram`/`!dbg`) and build with `clang -g` at `-O0`/`-Og`, behind a `--debug` flag. Positions already exist on every AST node, so it's "attach what we track", the cost being hand-numbered metadata nodes in the text IR. **MVP:** line-level `!dbg` + per-function `DISubprogram` → stack traces/line numbers/breakpoints. **Full:** `DILocalVariable` + DWARF type descriptors → variable inspection. Synergy: the ASan/UBSan builds already pass `-g`, so sanitizer reports gain `.ts` source lines for free

## Context

A compiled binary carries no source-level debug information. `main.go` invokes `clang` with a hardcoded `-O2` and no `-g`, and the emitter produces zero LLVM debug metadata (no `DICompileUnit`/`DISubprogram`/`!dbg` anywhere in `codegen/llvm/`). Consequences at runtime: a hard crash (a trap, an out-of-bounds in an unchecked path) segfaults with no indication of *where* in the `.ts` source it happened, and an uncaught `throw` prints its message but no stack or line. There is no way to set a breakpoint on a source line or inspect a variable in a debugger.

The goal: source-level debugging — stack traces with `.ts` file/line, crash locations, breakpoints, and ideally local-variable inspection — behind a `--debug`/`-g` flag, off by default. Distinct from [TDD-00072](TDD-00072.md) (compile-time error text): that's the front-end's messages; this is the back-end's runtime symbols. They share exactly one ingredient — the source position — and nothing else.

## Design

Emit **LLVM debug metadata** into the generated IR and compile a debug build with `clang -g` at a debug-friendly optimization level. Then `lldb`/`gdb` resolve native frames back to `.ts` source.

The enabling fact: the source position already exists everywhere. Every AST node carries `Pos{Line,Col}`, and the emitter already threads it (it's what every compile error uses). So this is not "start tracking positions" — it is "attach the positions already in hand as `!dbg` metadata." The mechanical cost is that the emitter writes IR as *text* (not via the LLVM C API), so the metadata nodes — `DICompileUnit`, `DIFile`, `DISubprogram`, `DILocation`, and for the full tier `DILocalVariable`/`DIBasicType`/`DICompositeType` — are hand-generated and hand-numbered. Verbose bookkeeping, not conceptual difficulty.

### Two tiers

- **MVP (moderate) — line-level traces.** Module-level `DICompileUnit` + `DIFile` + the `!llvm.dbg.cu`/`!llvm.module.flags` preamble; one `DISubprogram` per emitted function; and a `DILocation` `!dbg` attachment on each instruction carrying its statement's line/col. This alone yields source-level **stack traces, line numbers, crash locations, and breakpoints** — the 80% win.
- **Full (substantial) — variable inspection.** `DILocalVariable` + `llvm.dbg.declare`/`llvm.dbg.value` tying each local's alloca to its name and source, plus DWARF **type descriptors** for the type system (`DIBasicType` for scalars; `DICompositeType` for arrays, objects, classes, tuples). This is a lot more surface — every `Type` needs a debug-info projection — and is the second, later cut.

### Mechanics

- **Carrying the current location into `emitInstr`.** `!dbg` attaches per instruction (`... , !dbg !N`). The cleanest approach is emitter state — a "current debug location" set when a statement/expression begins emitting, appended by `emitInstr`/`emitAlloca` when debug mode is on — rather than threading a position parameter through every emit call. This is the main emitter-side change; it must respect the two-builder model (`e.allocas`/`e.body`) and SSA conventions unchanged.
- **`clang` flags.** The `--debug` build swaps the hardcoded `-O2` (`main.go:86`) for `-O0` or `-Og` (since `-O2` inlines and reorders past what line tables can faithfully represent) and adds `-g`. Everything else in the invocation is unchanged.
- **Flag shape.** `--debug`/`-g`, off by default — matching the existing mode-flag style (`-globals`, `-mm`, the `-regex` dialects). Debug metadata is purely additive to the IR and ignored by a non-`-g` clang line, so a non-debug build is byte-for-byte unaffected.

### Synergy and platform

- The ASan/UBSan build helpers already pass `-g` (`tests/compiler_test.go`'s `buildBinaryASan`). Once the IR carries `!dbg` metadata, those sanitizer reports gain `.ts` source lines essentially for free — a real multiplier on the existing sanitizer investigation workflow ([ADR-00100](../adr/ADR-00100.md) and the memory-corruption work).
- The metadata is target-neutral (clang lowers it for the host), but the *experience* is per-platform: `lldb` on Mac, `gdb`/valgrind on Linux (per the project's machine notes). Traces should be validated on both, and the debug-info quality (especially the full tier's type descriptors) confirmed rather than assumed on each.

### Rejected

A non-DWARF shortcut — a `SIGSEGV`/`SIGABRT` handler printing libc `backtrace()` — is not worth it as the primary mechanism: without DWARF those frames are raw addresses and mangled C-runtime names, useless for `.ts` source. It's only worth adding *alongside* DWARF, as a nicer default crash message that doesn't require attaching a debugger.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| `Pos{Line,Col}` on every AST node | ✅ already exists | The line/col the metadata needs — the whole reason this is "attach", not "track" |
| Position threaded to the emitter | ⚠️ partial | Errors use it; *instructions* don't yet carry it — needs a current-debug-location mechanism in `emitInstr`/`emitAlloca` |
| Text IR emission (`emitInstr`/`emitAlloca`) | ✅ already exists | Needs a `, !dbg !N` attachment path and a metadata-node emitter/counter |
| `clang` invocation | ✅ already exists | Needs `-g` and an `-O2`→`-O0`/`-Og` switch under `--debug` |
| DWARF type descriptors for the `Type` system | ❌ not started | Full tier only — a `DIBasicType`/`DICompositeType` projection per `Type` |
| `--debug`/`-g` flag | ❌ not started | Off by default; also flips the optimization level |

## Open questions

- MVP (line-level traces) vs. full (variable inspection) as the first cut — lean MVP; it's the disproportionate share of the value and avoids the type-descriptor surface.
- Current-location as emitter state vs. a per-`emitInstr` parameter — leaning emitter state to avoid touching every emit call site.
- `-O0` vs. `-Og` for the debug build — debuggability vs. staying closer to release codegen behavior.
- Whether to also ship the companion crash-time `backtrace()` handler for nicer default crash output without a debugger.
- Which machine validates the traces (`lldb` Mac / `gdb`+valgrind Linux) — a platform-touching claim that must be stated per the project's own rule, not inferred.
