# ADR-01205: A fetch with a signal resolves at its headers

- **Relations**: `Extends ADR-01203`
- **Date**: 2026-09-28

## Context

EventSource in TypeScript (TDD-00232 Stage 2) is a `fetch` with an
`AbortController` signal that reads the body stream until `close()`
aborts it. It never opened: a signal-carrying fetch resolved only when the
whole body had arrived, and a server-sent-events stream never ends. The
same holds for any program that fetches a long stream with a signal.

## Investigation

- `__kml_await_fetch_headers` (`runtime_fetch.go`) sent a signal-carrying
  fetch to the full `__kml_await_fetch`, because the abort check and
  teardown lived only there.
- After the headers resolve, nothing watched the signal: the body stream
  (`runtime_fetch_stream.go`) is fed by libcurl's write callback, so an
  abort with a quiet connection would never be noticed. The event loop
  asks `__kml_curl_inflight` every turn before `select()`, and an abort
  always comes from JavaScript run between turns.

## Decision

- `@__kml_fetch_abort_now(pending)` tears a transfer down once: it removes
  and cleans up the easy handle, marks the pending fetch done with result
  -1, and errors an active body stream with the signal's reason (an Error
  reason itself, else the AbortError or TimeoutError DOMException,
  `@__kml_fetch_abort_error`). `@__kml_fetch_throw_abort(sig)` throws the
  reason from an await, as before.
- Every fetch with a signal is registered (`@__kml_sigfetch_add`);
  `@__kml_sigfetch_scan` drops finished ones and aborts those whose signal
  fired. `__kml_curl_inflight` and `__kml_fetch_pump` run the scan first,
  so an aborted transfer no longer counts as in flight.
- Both awaits check the signal while waiting and reject a transfer marked
  aborted; the headers await no longer falls back to the full await.

## Implementation notes

`codegen/llvm/runtime_fetch.go` (`emitFetchAbortRuntime`; the full await's
teardown moved into it), `runtime_fetch_stream.go`
(`__kml_fetch_body_abort`), `emitter.go` (its stub without a body stream).

## Side effects discovered

None.

## Verification

Mac (Apple Silicon): `TestE2EFetchAbortMidStream` — a streamed response
resolves, an abort mid-body rejects the pending read with
`AbortError: This operation was aborted`, `AbortSignal.timeout` rejects a
fetch whose headers never come with a TimeoutError, and a pre-aborted
signal rejects at once — the output Node v24.19 prints for the same
program. The EventSource tests close held-open connections through it.
