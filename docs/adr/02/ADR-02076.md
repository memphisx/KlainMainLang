# ADR-02076: A typed array built from an untyped typed array of its own kind copies its storage

- **Relations**: Implements TDD-00230
- **Date**: 2026-11-24

## Context

The Node js lane on macOS was killed by the 3 GB guard. A sampler of
the test programs' RSS caught `test-stream-readable-to-web` at 686 MB
five seconds in. The test streams 64 KB `Buffer` chunks through a web
`ReadableStream` whose source wraps each chunk with
`new Uint8Array(chunk)`, where `chunk` is `any`.

## Investigation

- `emitTypedArrayFromDynamic` handled an untyped source as a generic
  array-like: it read every element as an f64 through the dynamic path
  and stored it converted. A 64 KB chunk cost about 640 KB of
  allocation, ten times the payload, and the loop ran per byte.
- Under the default `-mm=manual` nothing is freed, so the test's
  allocation rate is its growth rate: about 1 GB a second before the
  fix.
- The runner's reaper (`tools/conformance/reaper.go`) sweeps `ps`
  every 3 s and enforces `-mem-cap-mb` on the sum. On Linux each test
  also runs under RLIMIT_DATA; macOS has none, so a test growing at
  1 GB a second can pass the cap by up to 3 GB between two sweeps,
  and past the guard's 3 GB total with it.

## Decision

- `__kml_any_typed_same(word, kind, esize, &len)` (dynjson.c): when
  the untyped value is a typed array (not `arguments`) of the target's
  element kind, return a fresh copy of its storage and its length; else
  null. `emitTypedArrayFromDynamic` tries it first and falls back to the
  element walk on null. A `Buffer` source into `Uint8Array` takes the
  copy; the result is a plain `Uint8Array`, as in Node.
- The reaper sweeps every 250 ms on macOS, where it is the only bound
  on a test's growth. Linux keeps 3 s.

## Implementation notes

- `codegen/llvm/dynjsonsrc/dynjson.c`: `__kml_any_typed_same`, copying
  through `kml_copy` (kml_heap.h).
- `codegen/llvm/emit_arraybuffer.go`: the `tadyn.same` / `tadyn.walk`
  branch.
- `tools/conformance/reaper.go`: the darwin interval.

## Verification

- `TestE2ETypedArrayFromUntypedTypedArray`: same element kind, a
  `Buffer`, conversions between kinds, BigInt64 to BigUint64, an empty
  source and a `subarray` view, each matching Node, with the copy
  independent of its source. Passes on Linux x86-64 and macOS arm64.
- `test-stream-readable-to-web` on Linux x86-64: 131 KB of allocation
  per chunk against 640 KB, 8.5 times the throughput.
