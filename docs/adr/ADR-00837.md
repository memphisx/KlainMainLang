# ADR-00837: `JSON.stringify` drops an omitted optional field's key

- **Relations**: Extends [TDD-00187](../tdd/TDD-00187.md) / [ADR-00779](ADR-00779.md) (optional fields as `T | undefined`); follow-on to [ADR-00836](ADR-00836.md)
- **Date**: 2026-09-10

## Context

`JSON.stringify` of an object with an **omitted optional field** (`b?: number`
absent) serialized the key as `"b":null`, where real JS **drops the key
entirely** — only a genuinely `null`-valued property serializes as `null`. So
`JSON.stringify({ a: 1 } as { a: number; b?: number })` gave `{"a":1,"b":null}`
instead of Node's `{"a":1}`.

## Investigation

The object serializer (`emitJSONStringifyObject`, `emit_call_json.go`) placed
commas with a **static** `ind.itemPrefix(i)` keyed on the field index, and
`emitJSONStringifyValue` rendered an absent nullable scalar as `"null"`. Dropping
a key is a *runtime* decision (whether the field is `undefined`), which in turn
makes comma/newline placement runtime-dependent — the static-index prefix can't
express it.

## Decision

- New `jsonFieldSkippable(ty)` = `ty.Nullable && ty.IsUndefined` — a field whose
  value can be `undefined` at runtime (an optional `x?: T`), distinct from a
  `T | null` field (which still serializes `null`).
- `emitJSONStringifyObject` **gates** on it: an object with no skippable field
  keeps the byte-identical static-comma path (zero risk); an object with ≥1
  skippable field routes to a new `emitJSONStringifyObjectOptional`.
- The runtime path tracks a "have we emitted a field yet" flag (`emittedA`) and a
  running accumulator in allocas. Each field's prefix (comma/newline) is a
  runtime `select` on that flag; a skippable field is wrapped in a
  `present ? emit : skip` branch (present = the nullable-scalar aggregate's bit,
  or a non-null pointer). The close bracket is compact `}`, or — pretty — a
  runtime `select` between `\n<pad>}` (something emitted) and `}` (all absent →
  `{}`).

## Implementation notes

`emit_call_json.go`: `jsonFieldSkippable`, `emitJSONStringifyObjectOptional`, and
the gate in `emitJSONStringifyObject`. The fast path is untouched, so every
object without an optional field serializes exactly as before.

## Verification

macOS (Apple Silicon M4): matches Node across an omitted field
(`{"a":1}`), a present optional (`{"a":1,"b":2}`), a dropped *middle* field with
correct commas, a first-field-absent object, an all-absent object (`{}`), and
pretty-print (`null, 2`) for each. New
`TestE2EJSONStringifyDropsUndefinedOptionalFields` + the full JSON suite and the
object/http/fetch/inspect suites green.
