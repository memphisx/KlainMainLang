# ADR-01895: `new` of a target without a construct signature

- **Relations**: `Implements TDD-00230` (P3.3 shadow buckets; the strict lane rejects what tsc rejects)
- **Date**: 2026-10-21

## Context

- tsc types `new f()` whose target has call signatures but no construct signature as any and, under noImplicitAny, reports TS7009. The checker left it unanswered and the strict lane compiled it. As JavaScript, a generator, async function or arrow throws a TypeError on `new`; a plain function is a constructor function.

## Decision

- The checker types such a `new` any, and the strict lane reports TS7009 at it. In the js lane only a target that never constructs (generator, async function, arrow) is typed any; a plain function keeps codegen's constructor-function typing.

## Consequences

- Diagnostics and positions match tsc 5.6.3; the js lane's runtime is unchanged (Node-equal on Apple Silicon).
