# ADR-01230: Closures, optional functions and `any` results take their real types in codegen

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-09-29

## Context

Running Node's `child_process` logic as TypeScript exposed codegen typing
gaps that silently produced wrong values:

- An unannotated closure parameter with no hint was a number. A callback
  through `any` or `mustCall`, a `(msg) => …` fork listener, printed
  `2.48e-312`.
- `const out = k()`, with `k` a local closure returning `any`, was a
  number (0).
- A function type in a union with `undefined` (`cb?: (e) => void`) lost
  its `| undefined`. `cb !== undefined` folded to `true` and a missing
  callback was called (a null closure).
- A listener typed `(code: number | null)` registered through a dynamic
  `EventEmitter` received `0` for `null`: the `any` hint stripped the
  parameter's nullability.
- An untyped `[]` (a dynamic array) unboxed into `string[]` read as a
  static array: a crash.
- A call whose implementation signature returns `any` (behind overloads)
  stayed `any` when its overload returns a string, number or boolean.
  `execSync(…, { encoding }).trim()` then dispatched through `any`, where
  String methods were missing (`trim is not a function`).

## Decision

- An unannotated, unhinted closure parameter takes the checker's
  contextual type when it is a primitive or `any`, and is otherwise
  TypeScript's implicit `any` (the numeric default stays for
  `-compat=js` and when no checker runs).
- A call through a local closure keeps its `any` result.
- `(…) => T | undefined` is a nullable function (a null closure pointer);
  the strict `=== undefined` fold applies to nullable scalars only.
- An `any` hint no longer decides a parameter's optionality.
- Unboxing into a static array converts a dynamic array element by element
  (for elements stored as one value), with its own header.
- A call answered `any` whose overload the checker resolves to a number or
  a boolean is that primitive. A string stays `any`: through `any` it may
  be `null` or `undefined`, which a string cannot tell apart.
- A String method called on an `any` dispatches on the tag. A string runs
  the string's own method (its result boxed). Anything else takes the
  dynamic path, whose TypeError names `null` or `undefined` as Node's does.
