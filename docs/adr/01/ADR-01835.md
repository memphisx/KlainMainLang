# ADR-01835: ConditionalExpression takes its type from the checker

- **Relations**: `Implements TDD-00230` (P3.3: inferExprType's kinds switch to the checker one at a time)
- **Date**: 2026-10-20

## Context

- A kind switches when the old inference agrees with the checker's side over the whole corpus. In the full shadow report (47,923 compile runs), ConditionalExpression disagreed in two places only:
  - the JSON serializer's array conditional, fixed by ADR-01833;
  - `encoding === undefined ? 'utf8' : encoding` in `node:ffi`. The oracle's undefined-slot rule held the result as an undefined-capable string, though the checker proves it never is one. Emission builds a plain string.

## Decision

- The undefined-slot rule keeps a string's undefined only where the checker types the conditional as possibly undefined (`mayBeUndefined`). A string is its pointer either way, so only the type's claim changes. A scalar's slot is unchanged: its undefined is a sentinel in the slot itself.
- ConditionalExpression joins `switchedExprKind`. Where the checker has no answer, the old inference remains the fallback until the kind settles.

## Consequences

- Beyond literals and constructors, the checker now types `this`, Identifier, MemberExpression, CallExpression, and ConditionalExpression. Identifier, MemberExpression and CallExpression are settled.
- Verified on Apple Silicon (120 ternary, conditional, narrowing, nullish and optional-chain E2E tests), and with the gate on Linux x86-64 (DeskMini). The next full shadow run (Node304) checks the corpus.
