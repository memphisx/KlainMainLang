# ADR-00533: `Number.prototype.toFixed` digits argument is optional

- **Relations**: (none)
- **Date**: 2026-08-31

## Context

`(3.14159).toFixed()` — `toFixed` with no argument — was a compile error
("toFixed takes exactly 1 argument"). Real JS makes the `digits` argument
optional, defaulting to `0`, so `(3.7).toFixed()` is `"4"`. Documented as a
caveat on the `Number.prototype.toFixed(n)` row.

## Investigation

`emitNumberToFixed` (`emit_strings.go`) required exactly one argument and always
evaluated `args[0]` as the digit count fed to `sprintf("%.*f", digits, x)`.
Defaulting is a matter of using `0` for the `%.*f` precision when no argument is
present — `sprintf` already rounds correctly.

## Decision

Accept 0 or 1 arguments; when the argument is omitted, use a constant `i32 0`
for the precision. Otherwise the existing evaluate-coerce-truncate path is
unchanged.

## Implementation notes

`emit_strings.go` only. No inference change was needed — `toFixed` already
returns `string`.

## Side effects discovered

None.

## Verification

`TestE2ENumberToFixedDefaultDigits` (new): `(3.14159).toFixed()` → `"3"`,
`(3.7).toFixed()` → `"4"` (rounds), `(2).toFixed()` → `"2"`, cross-checked
against real Node. The existing `TestE2ENumberToFixed` (explicit digits) passes.
Verified on Mac (Apple Silicon).
