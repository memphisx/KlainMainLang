# ADR-01459: BigInt(x) at run time; `super.#x` is an early error

- **Relations**: none
- **Date**: 2026-10-07

## Context

Test262's strict lane lost three files and one more failed at run time
after this batch:

- `super-private-access-invalid.js` and `grammar-private-field-super-access.js`
  (class expression and statement) passed only by accident: codegen
  rejected their undefined base class. The checker now reports that first,
  as tsc does, so the real early error (`super.#x`) was missing.
- `DataView/prototype/setBigInt64/set-values-return-undefined.js` failed
  once a `[…, undefined, …]` literal kept its `undefined` (ADR-01453):
  `BigInt(undefined)` returned `0n` instead of throwing.

## Investigation

- Nothing rejected `super.#x`; tsc reports it as TS2339, and JavaScript
  engines as an early SyntaxError.
- `emitBigIntConstructor` converted an `any` argument's box bits as a
  machine integer, a statically undefined value as a null string (a
  crash), and threw a plain `Error` for a non-integral number. Node throws
  `TypeError: Cannot convert undefined to a BigInt` and `RangeError: The
  number 1.5 cannot be converted to a BigInt because it is not an integer`.

## Decision

- The parser rejects `super.#x` (code 2339, as tsc) in both lanes.
- `bigintFromValue` dispatches a box, a possibly-absent scalar and a
  possibly-nullish pointer at run time: a number, string, boolean or boxed
  bigint converts as its static type does; any other object converts its
  ToPrimitive (number hint) result (`valueOf`, `[Symbol.toPrimitive]`);
  null and undefined throw the TypeError. A non-integral number throws the
  RangeError naming it.

## Verification

- `TestE2ESuperPrivateNameIsEarlyError`, `TestE2EBigIntRuntimeConversion`
  (against Node).
