# ADR-01143: Number's formatting methods by the spec's algorithms, in C

- **Relations**: `Implements TDD-00230` (Phase 3, P3.2); `Extends ADR-01141`, `ADR-01142`
- **Date**: 2026-09-25

## Context

`toFixed`, `toExponential`, `toPrecision` and `toString(radix)` were
hand-written IR over `sprintf`. Their status rows disclosed three
divergences from Node:

- half-to-even ties in `toFixed`;
- `%g`'s fixed/exponential threshold in `toPrecision`;
- trailing-digit drift in a non-power-of-two `toString` radix.

A sweep of 18 values (ties, `-0`, `1e21`, `1e-7`, NaN, ±Infinity, the
extremes) through all four, against Node, found more:

- `NaN.toFixed()` printed `nan`, and `Infinity` printed `inf`;
- `(-0).toFixed()` printed `-0`;
- `(1e21).toFixed(2)` expanded all 22 digits; the spec gives `String(x)`;
- `toPrecision(1)` printed `1.e+2`;
- `toString(radix)` of a value past 2^63 saturated;
- the RangeErrors were missing.

## Investigation

- **The spec's three algorithms** pick "the integer n … as close to zero as
  possible; if there are two such n, pick the larger n". That is
  correct rounding of the exact value, with a tie going to the larger
  magnitude, since the sign is taken off first. `printf` rounds correctly
  too, but breaks a tie to even.
- **Exact digits.** Every double has a finite decimal expansion (at most
  767 significant digits), which `printf("%.780e")` writes in full. From
  those digits both the rounding and the tie are exact.
- **`toString(radix)`.** V8 converts with `DoubleToRadixCString`, a short
  algorithm:
  - it writes the fraction only while it is above half the gap to the next
    double, with round-to-even and a carry into the integer part;
  - it fills integer digits past 2^53 with zeros.

  Ported as it is, it matches Node digit for digit.
- **A number receiver.** `NaN` is a builtin global, like `Math`, so a call
  on it first took the static-method path and read its argument as the
  receiver. The global path now requires a global of object type.

## Decision

- **`codegen/llvm/numbersrc/number.c`** holds these entry points:
  - `__kml_Number_toFixed`, `__kml_Number_toExponential` and
    `__kml_Number_toPrecision`: the spec's steps, including their order.
    `toFixed` validates its digits before looking at the value;
    `toExponential` returns `String(x)` for a non-finite value before
    validating.
  - Rounding runs over `exact_decimal`/`round_to`, with a tie going to the
    larger value.
  - `__kml_Number_toString`: `String(x)` for radix 10, otherwise V8's
    algorithm.
  - Node's RangeError messages, raised through `@__kml_throw_range_error`
    ([ADR-01141](ADR-01141.md)).
- **Lowering.** `lib/es.d.ts` lowers the four methods (`@link number`).
  `loweredReceiver` takes a number receiver as a double.
  `Checker.PrimitiveMember` gives a string's or a number's member where
  the checker cannot type the receiver.
- **Deleted:** the hand-written `toFixed`, `toExponential`, `toPrecision`
  and radix emitters, and their dispatch. A boolean's `toString()` (the
  one other numeric-typed receiver) becomes `String(x)`.
- **Docs.**
  - The three disclosed caveats are removed from `NUMBER-MATH.md`'s rows.
  - The website reference's `toFixed` entry claimed `exact` while its
    status row carried a caveat. All four entries are now `exact`, and the
    strict-coverage badge was re-derived.

## Verification

- **The sweep:** all 18 values through all four methods match Node, as
  do the RangeErrors (`TestE2ENumberFormattingLowered`, with Node's
  output).
- **`make examples`:** 358/358.
- **Test262 (both lanes, together with ADR-01142–01144):** strict 7,031
  (+7), js 7,793 (+9).
- **`make test-par`:** only the four known `-mm=gc` failures and the
  load-dependent HTTP hang (`TestE2EHTTPChainedListenBinding`).
