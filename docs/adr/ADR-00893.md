# ADR-00893: Caught-value truthiness and Error-subclass field narrowing (TDD-00202 regressions)

- **Relations**: `Extends ADR-00870`
- **Date**: 2026-09-12

## Context

The committed catch-value record (TDD-00202/ADR-00870, "faithful thrown
values") regressed two shipped examples, failing the Release CI on **every**
platform:

- `examples/basics/namespaces.ts` — `Boolean(e)` / `if (e)` in a `catch` block
  emitted `icmp ne { i8, i64 } %e, 0` (comparing the catch-record aggregate to a
  scalar): `error: integer constant must have integer type`.
- `examples/classes/error_subclass.ts` — after `if (e instanceof HttpError)`,
  reading `e.status` (a subclass-declared field) threw at runtime: "dynamic
  property access on a statically-typed value is not supported".

Both worked before the catch value became the `{ i8, i64 }` record (previously
the catch binding was typed `errorObjType`). The `make examples` lane is
separate from `make test-par`, so the session's per-delivery `test-par` runs did
not catch it — a process gap noted below.

## Investigation

- **Truthiness.** `toBool` (`emit_exprs_types.go`) had no `IsCaught` branch, so a
  caught value fell through to the generic `icmp ne <IR>, 0`, and the record's IR
  is the aggregate `{ i8, i64 }`. `Boolean()` routes through `toBool`, so both
  `Boolean(e)` and `if (e)` were affected.
- **Subclass field.** `applyUnionBranchNarrowing` (`emit_narrowing.go`) narrowed
  `e instanceof HttpError` only when `sym.Ty.IsError` — the *legacy*
  errorObjType-typed catch binding. The catch variable is now `TypeCaught`
  (`IsCaught`), so the narrowing was skipped, `e` stayed a caught record, and
  `e.status` (not a base Error field) fell to `emitCaughtMemberGet`'s dynamic
  fallback, which throws for a statically-typed object payload. The record's
  built-in Error fields (`name`/`message`) still read, masking the gap.

## Decision

- **`toBool` gains an `IsCaught` branch** that widens the record to a NaN-boxed
  `any` (`emitCaughtToAny`) and reuses the dynamic ToBoolean — one correct
  answer in both `-compat` lanes.
- **`applyUnionBranchNarrowing` handles a caught binding.** For `e instanceof
  <ErrorSubclass>` in the true branch, it unpacks the caught record's payload
  (the thrown instance pointer) via `caughtParts`, stores it in a fresh slot,
  and re-binds `e` in the branch scope as that subclass type. Member access then
  takes the static class-field path (`e.status` reads its real field), and the
  binding is discarded on branch exit like every other narrowing. The legacy
  `IsError` path is preserved (a pure retype, since it already holds the object
  pointer).

## Implementation notes

- A class binding's `Symbol.Ptr` is a slot holding the object pointer (like any
  object local), so the re-bind allocates `alloca ptr` and stores the unpacked
  payload — not a bare SSA value (`Symbol` has no value field).
- Error-subclass instances are prefix-compatible with `errorObjType`, so the
  payload pointer is a valid subclass object with its own fields laid out after
  the base — no relayout needed.

## Side effects discovered

- **Process gap:** `make examples` must run before committing a codegen change,
  not only `make test-par`. The two examples exercised catch-value paths no unit
  test covered. Regression tests added here; running `make examples` per
  codegen-affecting delivery going forward.

## Verification

- Both examples pass (exit 0) with correct output: `error_subclass` →
  "HttpError 404: …" / instanceof results / the `TimeoutError` toString;
  `namespaces` → all five lines. `make examples`: 296/296.
- New `TestE2ECaughtValueTruthiness`, `TestE2ECaughtErrorSubclassFieldAfterNarrowing`;
  exception/class/narrowing suites green; `go build`, `go vet ./...`, gofmt
  clean; full `make test-par` gate run.
