# ADR-01069: `JSON.stringify` — a null string is `null`, and every control character is escaped

- **Relations**: Supersedes the `""` placeholder of ADR-00683; Extends ADR-00685 (non-finite numbers), TDD-00120 (length-headed strings)
- **Date**: 2026-09-22

## Context

BACKLOG §0 item 2b: `JSON.stringify({ s: null })` for `interface P { s: string | null }` printed `{"s":""}`;
Node prints `{"s":null}`. A `number | null` field was already right. Found alongside it (the same runtime
function): control characters other than `\n`/`\r`/`\t` were written raw instead of as `\u00XX`.

## Investigation

`@__kml_json_str_str` (`runtime_json.go`) is the one string quoter. ADR-00683 stopped a `strlen(NULL)` fault
there by returning `""` for a null pointer — a crash fix, not Node's output: a null string pointer *is* the value
`null` (that is how every `string | null` is stored). Its escape set was the five characters `" \ \n \r \t`.
`dynjson.c`'s `sb_json_string` (the `any` walker) had the complete set already.

A length-headed quoter (reading the TDD-00120 header instead of `strlen`, so an embedded NUL would be escaped
as `\u0000`) was implemented and reverted in the same session: not every runtime string carries the header —
the URL and crypto sidecars, EventSource and `Blob.text()` hand back bare C strings — and reading `ptr-8` on
those printed heap garbage in 14 tests on Windows and Linux alike. The same finding reverted a length-driven
`console.log` string write (ADR-01075).

## Decision

- A null string pointer serialises as the literal `null`.
- The quoter escapes per `QuoteJSONString`: `\" \\ \b \f \n \r \t`, any other code unit below 0x20 as
  `\u00XX`. The output buffer is sized for the 6× worst case and its header length is stored directly.
- Both quoters stay `strlen`-bounded, so an embedded NUL still ends a string in JSON output — recorded in
  BACKLOG §0 with the list of header-less producers, which is the real fix.
- `dynjson.c`: `sb_json_bytes(s, n)` takes an explicit length; `sb_json_string` passes `strlen`.

## Implementation notes

`codegen/llvm/runtime_json.go`, `codegen/llvm/dynjsonsrc/dynjson.c`.

## Side effects discovered

- `JSON.stringify(new Error("boom"))` prints every internal field (`{"message":…,"name":…,"code":null,…}`);
  Node prints `{}` for a plain Error (its own properties are non-enumerable) and only the enumerable
  `errno`/`code`/`syscall`/`path` for a system error. BACKLOG §0.
- Header-less strings from sidecars (above). BACKLOG §0.

## Verification

Windows: `{ s: null, n: null }` → `{"s":null,"n":null}`, an array of such objects, `"a\u0001b\u001f\b\f"`
escaped as Node does, all equal to Node 24's output. E2E: `TestE2EJSONStringifyNullStringField`,
`TestE2EJSONStringifyControlCharEscapes` (`tests/json_null_nul_test.go`). Full suites: Windows + Linux (Docker).
