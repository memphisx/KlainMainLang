# ADR-00632: Contextual typing of arrow arguments to callback parameters (call/store sites)

- **Relations**: `Extends ADR-00042`
- **Date**: 2026-09-02

## Context

Passing an untyped arrow (or function-expression) argument to a **class
method** whose parameter is a function type — e.g. `r.go((name, value) =>
...)` against `go(cb: (name: string, value: number) => void)` — silently
produced wrong results: the callback's parameters decoded to garbage. Found
while implementing EventEmitter method overrides (ADR-00631), where an
overridden `on(event, listener)` receiving an untyped-param listener
mis-decoded the emitted arguments; confirmed independently against a plain
class with no EventEmitter involvement.

## Investigation

`emitArrowFunctionWithHints` (emit_func.go:2074) already types an untyped
arrow's params from provided hints, and `emitExprWithObjectHint`
(emit_objects.go:110–133) already routes a function-typed hint into it. The
free-function/closure call paths use these; a direct repro (`function go(cb:
(name, value) => void)`) typed correctly. The class-method argument loop in
`emitClassCall` (emit_classes.go) instead emitted a plain scalar argument
via bare `e.emitExpr(a)`, giving a function-typed parameter no hint — so the
arrow's untyped params fell to the ADR-00042 numeric default and the closure
adapter read the wrong bytes.

## Decision

Wherever a value is emitted against a *known function-typed target* and could
be an untyped arrow/function-expression, emit it via
`emitExprWithObjectHint(a, ty)` (which already routes `ty.IsFunc` into
`emitArrowFunctionWithHints`) instead of bare `emitExpr(a)`. Kept narrow to
`IsFunc` so the surrounding dynamic/union/object/nullable handling is
untouched. The gap was a cluster of call/store sites that each hand-rolled
argument emission and never threaded the func hint, while the free-function
path, declaration initializers, plain assignment, object/array literals,
object-field assignment, and return position already did.

Sites fixed:
- `emitClassCall` — class instance-method arguments (the site that surfaced
  it via EventEmitter overrides, ADR-00631).
- `emitStaticMethodCall` — static-method arguments.
- Array `.push` / `.unshift` — a function-typed element.
- `Map.set` — a function-typed value.

## Implementation notes

- emit_classes.go (`emitClassCall`, `emitStaticMethodCall`): scalar arg loop
  branches on `paramTy.IsFunc` → `emitExprWithObjectHint`, preserving the
  existing `scratch.enter/leave` bookkeeping.
- emit_arrays_mutate.go (push/unshift item loop) and emit_collections.go
  (`Map.set` value): branch on the element/value type's `IsFunc`.

## Side effects discovered

None. Array-typed and nullable-scalar parameters are handled by earlier
branches in the same loops and were already correct; only the scalar/func
branch lacked the hint. `Set.add` of a function value and `new Map([...])`
entry seeding with function values are the remaining untested corners
(function-typed collection *elements* seeded via a literal are unusual) —
noted, not swept.

## Verification

- Mac (Apple Silicon): `go build`, `go vet` clean; new regressions
  `TestE2EClassMethodCallbackParamContextualTyping` (class method) and
  `TestE2ECallbackParamContextualTypingSweep` (static method + array push +
  Map.set) green; collection/array/class/EventEmitter suites green; the
  EventEmitter override tests (ADR-00631) that surfaced it green.
