# ADR-01759: An array method's thisArg, and a module var read by a rewritten function

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- `arr.forEach(cb, thisArg)`, and the same call on `map`, `filter`, `find`, `findIndex`, `findLast`, `findLastIndex`, `some`, `every` and `flatMap`, failed to compile ("forEach takes exactly 1 argument"). The second argument is the callback's `this`.
- `var result; function cb() { result = this.res; }` failed with "undefined variable 'result'". A function declaration that reads `this` is rewritten to `var cb = function …` before module globals are decided. `namesReadInFunctions` looked only at top-level function and class declarations, so `result` did not count as read by a function and stayed a local of `main()`.

Test262's Array method tests use both shapes.

## Decision

- `arr.m(cb, thisArg)` is rewritten as `arr.m(cb.bind(thisArg))` (`hofWithThisArg`), with the receiver evaluated first into a temporary. The receiver, the callback and `thisArg` are evaluated once each, in order. An `undefined` thisArg is dropped. A wrapping arrow (`(v, i, a) => cb.call(thisArg, v, i, a)`, as `Array.from` builds) was tried first: it captures synthetic temporaries, which produced invalid IR inside a builtin prototype method's shared body.
- `namesReadInFunctions` also counts the identifiers inside a function expression or arrow in a top-level initializer.

## Consequences

- `TestE2EArrayHOFThisArg` and `TestE2ECompatJSArrayHOFThisArg` cover both lanes.
