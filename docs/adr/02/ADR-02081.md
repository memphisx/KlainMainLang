# ADR-02081: A COMDAT definition in a COFF object is weak

- **Relations**: Extends ADR-02073; Implements TDD-00230
- **Date**: 2026-11-25

## Context

On Windows every test in a CI shard failed at link: `ld.lld` reported the
stack guard's, the host hooks', the string map's and the loop's symbols
undefined (`__kml_stack_guard_init`, `__kml_host_tojson`,
`__kml_map_str_get`, `__kml_loop_uv`, ...). It reproduced on a Windows
machine on a single test (`TestE2EArrayEntries`), with a fresh object cache
and a fresh symbol-table directory alike.

## Investigation

- The symbol tables were right: `stackguard`'s listed
  `s __kml_stack_guard_init`, `hostbox`'s `s __kml_host_tojson`, and the
  objects held the functions (`llvm-nm`: `T`).
- The same table's first line was `s .refptr.__kml_range_error_hook`. A
  MinGW object gives each extern variable it reads a `.refptr.<name>` stub
  in a COMDAT section; every object reading that variable carries one.
- `readObjSyms` read every defined external COFF symbol as strong, and
  `resolveRuntime`'s `clashes` leaves out a pool file that strongly defines
  a name the link already defines. Once one runtime file holding a stub was
  linked, every other file holding the same stub clashed with it and was
  left out, with the functions it defines.

## Decision

- A COFF definition in a section marked `IMAGE_SCN_LNK_COMDAT` is read as a
  weak definition: the linker keeps one copy of it, as of an ELF weak or a
  Mach-O weak-def symbol.
- A symbol table's key includes a format version (`symTableVersion`), so a
  change in how an object's symbols are read replaces the tables already on
  disk; the tables written before this change hold the stubs as strong.

## Implementation notes

- `codegen/llvm/runtime_resolve.go`: the COFF branch of `readObjSyms`;
  `symTableVersion` in `scanSymsWith`'s key.
- `codegen/llvm/runtime_resolve_coff_test.go`: compiles a file for
  `x86_64-w64-windows-gnu` and checks its `.refptr` stub reads weak; skipped
  where clang cannot target it.

## Verification

- macOS arm64: `TestCOFFComdatDefinitionIsWeak` passes (clang cross-compiles
  the COFF object); `go test ./codegen/llvm` passes.
- Windows x64 (MSYS2 UCRT64, clang 22): `TestE2EArrayEntries`, which
  failed at link before, passes; every unit package passes
  (`go test -p 1` over every package but `tests/`).
