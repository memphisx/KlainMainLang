# ADR-02033: A mixin's returned class over a value base (js)

- **Date**: 2026-11-22

## Context

- `function mix(K) { return class extends K {} }` worked when every
  argument was a program class, which specialization covers. Called with a
  builtin (`mix(Map)`), it failed to compile: specialization declines a
  builtin candidate. The run-time heritage path (`valueBases`, ADR-style
  ClassDefinitionEvaluation) only saw class declarations, and the binder
  scope lookup `localBaseClassBinding` uses finds nothing in a function's
  body block.

## Decision

- In the js lane, `returnLocalBaseClasses` rewrites `return class extends
  K {}`, with K a parameter or local binding of the function, into the
  class's declaration under a name of its own plus a return of it. It walks
  the AST for the function's locals, not the binder. A named class
  expression's own name is renamed inside its body. The name `.name` shows
  is recorded, and block hoisting keeps a name an earlier rewrite recorded.
- `fnBases` reads class expressions as well as declarations
  (`classDeclOf`).

## Consequences

- The class's heritage evaluates where it stands, so a builtin base's
  instance takes the class's prototype, as for a declared class.
- An Error object given a prototype (`extends globalThis.Error` through a
  value) still keeps `Error.prototype`. That is a BACKLOG item.
- Tests: `TestE2EMixinReturnValueBaseJS`.
