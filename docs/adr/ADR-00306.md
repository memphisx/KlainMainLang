# ADR-00306: Worker threads — `-mm=gc` support, error/termination semantics, browser surface

- **Relations**: Implements [TDD-00098](../tdd/TDD-00098.md) (stages 4–6); Extends [ADR-00305](ADR-00305.md)
- **Date**: 2026-08-23

## Context

[ADR-00305](ADR-00305.md) shipped the Worker core (spawn/join, typed copy-only `postMessage`, per-thread event loops) with `-mm=gc` rejected, no `'error'`/termination semantics, and only the Node `worker_threads` surface. This closes the remaining three stages of [TDD-00098](../tdd/TDD-00098.md).

## Investigation

- **`GC_set_stackbottom` availability and semantics** confirmed against Homebrew bdw-gc (symbol present; NULL handle = current thread; the header requires the GC alloc lock, honored via `GC_call_with_alloc_lock`). A dedicated `.ll` prototype — two registered pthreads, each repeatedly repointing its own stack bottom around ucontext fiber swaps while both allocate through `GC_malloc` — passed 5/5 runs before any compiler change.
- **A latent gc-soundness hole found by reasoning through the channel design**: while a message envelope is in flight, its only reference lives inside the kernel's pipe buffer — invisible to Boehm's scan — so envelopes and (transitively) payload clones were collectable mid-flight. Same exposure for control blocks referenced only from thread-local globals (TLS scanning is not a guarantee to lean on). Not observed as a crash (windows are short), fixed on principle.

## Decision

- **Stage 4 (`-mm=gc`)**: the worker trampoline does `GC_get_stack_base` + `GC_register_my_thread` before anything else and `GC_unregister_my_thread` on the way out; each thread records its own stack bottom in the (now `thread_local`) `@__kml_gc_orig_stackbottom`. Every fiber-swap stackbottom repoint across the runtime (HTTP conn fibers, task scheduler, generators) goes through one helper, `gcSBStore`: the historical direct `@GC_stackbottom` store when the program has no workers (bit-for-bit unchanged single-threaded behavior), or a lock-guarded `GC_set_stackbottom(NULL, sb)` call under workers. `GC_allow_register_threads()` runs at main start. Gc-soundness: control blocks, the per-thread worker registry array, and envelopes allocate via `GC_malloc_uncollectable` — never collected but *scanned*, so payload clones stay conservatively reachable through the envelope's encoded words; the receiver's `free` is already shimmed to `GC_free`.
- **Stage 5 (error/termination)**: `terminate()` now reports exit code 1 (Node's own behavior). An uncaught exception on a worker thread routes through a new `@__kml_worker_uncaught` hook in `@__kml_throw`'s uncaught path (no-op stub without workers): on a worker thread it sends an error envelope (kind 3, the message string) plus an exit(1) envelope and ends only that thread via `pthread_exit`; the parent fires `'error'` then `'exit'`. With no `'error'` listener the parent prints `Uncaught (in worker): <msg>` and exits 1 — Node's default.
- **Stage 6 (browser surface)**: `new Worker(path)` needs no import (the constructor was always parse-time recognized — the documented import-gating exception). Parent: `w.onmessage = (e) => … e.data …` and `w.onerror = (e) => … e.message …` property assignments (arrow literals), delivering one-field event objects built by a wrapping adapter variant. Worker side: bare `onmessage = (e: { data: T }) => …` (the annotation declares the inbound type, mirroring `parentPort.on`'s rule), bare `postMessage(x)`, and the `self.` spellings — all gated behind user-binding shadow checks so local declarations win. Both surfaces share one mechanism and can mix. `self.onerror` inside a worker is a clean rejection (worker errors report to the parent). Array payloads via `onmessage` are rejected toward `.on('message', …)` (the event struct holds one word).

## Implementation notes

`runtime_worker.go` (trampoline gc block, kind-3 envelopes, `__kml_worker_uncaught`, uncollectable allocs, terminate exit code), `runtime_exceptions.go` (uncaught hook call), `emitter.go` (gc helper emission, `GC_allow_register_threads`, uncaught stub, `hasWorkers` set from `Program.WorkerModules` before any emission so `gcSBStore` picks the mechanism deterministically), `runtime_http.go`/`runtime_task.go`/`emit_generators.go` (stackbottom sites through `gcSBStore`), `emit_worker.go` (wrapped adapters, handler-property assignment, worker-side browser surface), `emit_exprs_assign.go`/`emit_call.go` (dispatch hooks).

## Side effects discovered

- The stage-3 echo/timer tests' expected `'exit'` codes moved from 0 to 1 — `terminate()` reporting 1 is the correct Node behavior, and the old 0 was the stage-3 placeholder.
- `onmessage`-style handlers receive a freshly-allocated one-field event object per message (manual-mode leak per message, on top of the clone itself — same standing manual-mode posture).

## Verification

darwin/arm64, `clang -O2`: 15 E2E tests in `tests/worker_test.go` all pass — the 12 from [ADR-00305](ADR-00305.md) (gc-rejection replaced by a gc round-trip that forces collections in the worker while messaging, on both sides of `terminate()`), plus uncaught-exception → `'error'`+`'exit'(1)` with the parent surviving, uncaught-without-listener → process exit 1 with the message, and three browser-surface tests (onmessage/e.data round-trip, onerror, `self.` spellings). Full `go test ./...` and `make examples` pass; `make conformance` run at delivery end.
