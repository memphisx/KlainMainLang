# ADR-00428: assert.match/doesNotMatch, process.getuid family, honest marker diagnostics

- **Relations**: Extends [ADR-00195](ADR-00195.md) (assert module), [ADR-00026](ADR-00026.md) (process POSIX reads)
- **Date**: 2026-08-28

## Context

Three small first-blockers from the Node-oracle histogram:
`assert.match` (13 files), `process.getuid`/`geteuid`/… (a handful, and
cheap), and 14 files reporting the internal
"undefined variable 'cluster__kml_builtin'" whenever an unhandled member
of a builtin module (e.g. `cluster.settings`) leaked past its dispatch —
an unreadable message that also polluted the failure histogram.

## Decision

- `assert.match(str, re[, msg])` / `assert.doesNotMatch`: a synthesized
  `re.test(str)` member call feeding the standard assert-check tail
  (custom message honored, AssertionError on failure with Node's own
  default messages). The second argument must be statically a RegExp.
- `process.getuid()`/`geteuid()`/`getgid()`/`getegid()`: direct POSIX
  reads returning `number` (this compiler is POSIX-only, so they exist
  unconditionally, matching Node-on-POSIX).
- A `*__kml_builtin` marker reaching the generic identifier fallback now
  reports "this usage of the built-in '<mod>' module is not supported"
  instead of leaking the internal marker name.

## Implementation notes

`emit_assert.go` (match cases), `emit_call.go`/`emit_process.go`
(`emitProcessGetID`), `emit_exprs.go` (marker diagnostic).

## Side effects discovered

None.

## Verification

`TestE2EAssertMatch` (match, doesNotMatch, catchable mismatch message),
`TestE2EProcessGetUIDFamily` (non-negative, effective==real);
`TestE2EAssert*`/`TestE2EProcess*` suites green (Mac).
