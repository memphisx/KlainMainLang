# ADR-01090: net.Socket buffers writes issued before the connect completes

- **Relations**: `Extends ADR-01021` (the asynchronous net.connect state machine)
- **Date**: 2026-09-23

## Context

`net.connect(port)` followed by a synchronous `socket.write(...)` — the shape
`TestE2ENetConnectPortOnly` exercises and idiomatic Node — hung the program: the
server accepted the connection but never saw the bytes, so the echo round trip
never completed and neither peer closed. Under `go test ./...` this parked a
child process forever, and the whole `tests` package hit its 50-minute timeout
(the macOS Release lane's headline failure: a panic after 3000s with a
goroutine stuck 43 minutes in `net_test.go` waiting on the child).

The passing sibling `TestE2ENetConnectOptionsObject` differs only in *when* it
writes — inside the connect callback — which masked the bug.

## Investigation

`net.connect` is fully asynchronous (ADR-01021): the fd is created non-blocking,
`connect()` is issued, and the socket is returned immediately while the connect
is still in flight. `__kml_net_sock_write` (`codegen/llvm/runtime_net.go`) wrote
straight to the fd with `write(fd, data, n)`. On a socket whose non-blocking
connect has not yet completed that `write()` fails with `ENOTCONN`/`EAGAIN`, and
the bytes were silently dropped. Node instead buffers any write issued before
the `'connect'` event and flushes it once the socket is writable.

Reduced repro (`socket.write` in the `listen` callback, before `'connect'`):
connects, server fires `'connection'`, but the `'data'` handler never runs.
Moving the write into the connect callback works — confirming the drop is
exactly the pre-connect window.

## Decision

Buffer pre-connect writes on the socket's connect-state blob (field 9,
`netConnStateIR`, which exists only while the connect is outstanding) and flush
them when the connect completes.

- Extend `netConnStateIR` with two trailing fields: `5 ptr pbuf`, `6 i64 plen`
  (size 144 → 160). Trailing, so existing field indices are undisturbed.
- `__kml_net_sock_write`: if the socket carries a connect-state blob whose status
  is *connecting* (1), `realloc`-append the bytes to `pbuf`/`plen` and return
  instead of writing. A socket with no blob (server-accepted, tls.connect) or a
  resolved connect (blob freed, field 9 null) writes directly as before.
- Dispatch `conndone`: once the fd is confirmed connected, `write()` the buffered
  bytes (in order, before the `'connect'` listener fires) and free `pbuf`, then
  free the blob as before.
- Dispatch `connfail`: free `pbuf` too, so a failed connect leaks nothing
  (`free(null)` is a no-op, so the free is unconditional).

## Implementation notes

- `ensureNetSockIO` now pulls `ensureRealloc`/`ensureMemcpy` — the minimal
  net.Socket path (HTTP `clientError`/`connection` sockets) shares this helper,
  and those sockets always have a null field 9, so they still write directly.
- The sock_write/sock_close emit block was converted to indexed `%[n]s` verbs
  (sock struct, connect-state struct) so the two struct types can both be
  referenced without miscounting positional args.
- TLS client sockets do not use the connect-state blob (ADR-01021), so the
  pending buffer never applies to them; their writes go through
  `__kml_tls_write` unchanged.

## Side effects discovered

The 50-minute suite hang was one of several unrelated Release-lane failures
accumulated over the preceding week; those (Node-oracle drift, a wrong test
assertion, a too-tight timing threshold, a Windows path-canonicalization
expectation, and the deferred Linux `-mm=gc` collector crash) are tracked in
the CI-green sweep ADR and `docs/BACKLOG.md` §0 item 20.

## Verification

- `TestE2ENetConnectPortOnly` now passes (previously hung to timeout); the whole
  `TestE2ENet*` group is green on macOS arm64.
- Manual repro binary exits cleanly printing `got e:hi`.
- Broader `TestE2ENet|TestE2ETLS|TestE2EWebSocket|TestE2EHTTP` group re-run on
  macOS arm64 as a regression check on the shared socket-write path.
- Verified on: macOS (Apple Silicon M4).
