# ADR-00147: klmpm Stage 2 — `klain.json`/`klain.lock` manifest parsing

- **Relations**: Implements [TDD-00054](../tdd/TDD-00054.md) (Stage 2 only). Extends [ADR-00146](ADR-00146.md)
- **Date**: 2026-08-10

## Context

[ADR-00146](ADR-00146.md) (klmpm Stage 1) gave the compiler enough to resolve a bare import specifier against a hand-constructed `klain_modules/<name>/klain.json`'s `"main"` field — but that resolution deliberately used its own minimal, compiler-only struct (`Main string`, nothing else), since the compiler has no use for a package's `"dependencies"`. [TDD-00054](../tdd/TDD-00054.md)'s own Stage 2 is formalizing the *full* schema (name/version/main/dependencies for a manifest; the resolved-package records for a lockfile) as real, validated, tested code — groundwork Stage 3's Minimal Version Selection algorithm will need real structured data to operate on, not something this ADR does itself.

Before starting, one real fork was worth deciding explicitly rather than assuming: should this parser live in Go (fast to build now, but potentially superseded if klmpm ends up self-hosted in klainmain TypeScript per the TDD's own stated direction for Stage 4) or as klainmain-compilable TypeScript (direct groundwork for that self-hosted tool, slower to iterate). Decided: Go, for now — see Decision.

## Decision

**New standalone package, `klmpm/`** (`klmpm/manifest.go`, `klmpm/lockfile.go`) — deliberately *not* imported by `resolver/`, `main.go`, or anywhere else in the compiler. This is the one architectural point worth being explicit about: `resolver.go`'s Stage 1 resolution keeps its own separate, minimal manifest struct rather than being changed to import this package's fuller `Manifest` type, so the compiler's actual module-resolution hot path never carries package-manager-tooling code as a dependency. The two structs happen to overlap on one field (`Main`) but are intentionally not unified.

`Manifest` (`klain.json`): `Name`, `Version`, `Main` (optional — only matters once a package is actually used as a dependency, which Stage 1 already enforces independently), `Dependencies map[string]Dependency` (`Source`, `Version` — a single "at least this version" floor, never a range operator, matching the TDD's Minimal-Version-Selection design). `ParseManifest(path)` does structural validation only: required fields present and non-empty (`name`, `version`, every dependency's `source`/`version`). No semver format validation, no check that a `source` is actually fetchable — deliberately deferred to Stage 3, which is the first stage that actually needs to compare or fetch anything.

`Lockfile` (`klain.lock`): `Packages map[string]LockedPackage` (`Source`, `Version`, `Commit`, `Integrity` — optional, per the TDD's own still-open question on whether a content hash beyond git's commit SHA is worth adding; reserved in the schema regardless since it costs nothing to have the field available). `ParseLockfile(path)` validates the same way — `source`/`version`/`commit` required, `integrity` optional.

Both parsers return a plain Go `error` (not a custom error type) with a message naming the file and the specific missing/invalid field — matching this codebase's existing error-reporting style throughout `resolver/`.

## Implementation notes

- `klmpm/manifest.go` (new): `Dependency`, `Manifest`, `ParseManifest`.
- `klmpm/lockfile.go` (new): `LockedPackage`, `Lockfile`, `ParseLockfile`.
- `klmpm/manifest_test.go`, `klmpm/lockfile_test.go` (new): table of individual test functions (matching this repo's existing preference for named tests over table-driven ones in `resolver`/`tests`), each writing a temp file via `t.TempDir()` — same pattern `tests/compiler_test.go`'s `writeMultiFile` already uses, reimplemented locally here since `klmpm` has no reason to depend on the `tests` package (nor vice versa).
- No changes anywhere in `resolver/`, `main.go`, or any existing package — purely additive, zero risk to anything already shipped.

## Side effects discovered

None.

## Verification

- `go build ./...`, `go vet ./...`, `go test ./...` all clean.
- 16 new tests in `klmpm/manifest_test.go`/`klmpm/lockfile_test.go`: valid manifest with/without dependencies, `"main"` correctly optional, each required field's absence rejected individually (`name`, `version`, a dependency's `source`/`version`, a locked package's `source`/`version`/`commit`), `"integrity"` correctly optional, invalid JSON, and file-not-found — for both the manifest and lockfile parsers.
