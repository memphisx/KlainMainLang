# ADR-01617: A non-null assertion counts as initialized; timers and fetch link the loop

- **Relations**: Extends ADR-00475
- **Date**: 2026-10-13

## Context

The full Windows suite after TDD-00252 Stage 4 failed three tests outside
the platform work:

- `TestUninitializedTypedLocalIsUndefined` and
  `TestE2EUnionWithoutInitializerReadsUndefined` were refused with
  "variable is used before being assigned" (TS2454) by the binder's
  definite-assignment check.
- `TestE2EHeadersErrors` (a program using `Headers`/`Response` and nothing
  of the event loop) failed to link: `timers.c` and `fetch.c` call into
  `loop.c` and libuv, which only an event-loop program linked.

## Investigation

- TypeScript's checker takes a reference under a non-null assertion
  (`last!.length`) as initialized: `assumeInitialized` includes a parent
  that is a `NonNullExpression`. The binder checked every read.
- `let x: string | number; console.log(x)` is an error in TypeScript too:
  the test asserted behaviour TypeScript refuses. With `| undefined` in the
  type, TypeScript accepts the read, and the program prints `undefined`.
- `timers.c` holds its timers as `uv_timer_t` handles on the thread's loop
  and `fetch.c` watches libcurl's sockets on it (TDD-00244, TDD-00252); the
  dependency was declared nowhere.

## Decision

- The binder records identifiers that are the operand of a non-null
  assertion (`asserted`) and skips the definite-assignment diagnostic for
  them.
- The test takes the form TypeScript accepts (`string | number | undefined`).
- A program that uses timers or fetch links the event loop
  (`emitLoopTaskStubs` ensures it before emitting the loop's stubs).
- The Windows-only webview page-tick stubs there, dead since ADR-01614, go.

## Implementation notes

`binder/binder.go`, `binder/flow.go`, `codegen/llvm/runtime_task.go`,
`tests/dynamic_test.go`.

## Side effects discovered

None.

## Verification
