# ADR-00763: `spawn(cmd, args, { windowsHide })`

- **Relations**: Extends [ADR-00433](ADR-00433.md) (spawn's options) and [ADR-00762](ADR-00762.md) (the spawn-options struct); addresses [TDD-00180](../tdd/TDD-00180.md) §3
- **Date**: 2026-09-07

## Context

`spawn`'s options gained `env` ([ADR-00762](ADR-00762.md)); the next of
[TDD-00180](../tdd/TDD-00180.md) §3's spawn-option rows is `windowsHide` —
Node's flag to suppress the console window a spawned child would otherwise pop up
on Windows. On POSIX it is a no-op that Node still accepts. Small and
self-contained.

## Investigation

The Windows spawn path is `__kml_win_spawn` → `CreateProcessW` (win32proc.c),
whose `dwCreationFlags` already carries `CREATE_UNICODE_ENVIRONMENT` and,
conditionally, `EXTENDED_STARTUPINFO_PRESENT`. `CREATE_NO_WINDOW` is the flag
libuv sets for `UV_PROCESS_WINDOWS_HIDE`. The option's effect (window visibility)
is not observable in captured stdout, so it is not directly assertable — the
testable contract is "accepted on both platforms, stdio unaffected."

`__kml_win_spawn` already receives a `flags` int (bit 0 = Node's
`windowsVerbatimArguments`), derived in `cpSpawnForkIR` as `mode >> 1`. So a new
`mode` bit rides to `flags` for free through that shift.

## Decision

- `cpSpawnOptions` (emit_childprocess.go) now returns a `cpSpawnOpts` **struct**
  (replacing the growing 4-value tuple), with a `windowsHide bool` set from a
  literal boolean `windowsHide` option (a non-literal is a clean rejection). A
  dynamic (non-literal) options object does not read it — documented.
- `emitCPSpawn` folds `windowsHide` into the `mode` bitmask as **bit 2** (`| 4`).
  `cpSpawnForkIR`'s existing `%kmlverb = mode >> 1` carries mode bit 2 to
  `__kml_win_spawn`'s `flags` **bit 1**; the buffered check (`mode & 1`) and the
  verbatim bit are unaffected.
- `__kml_win_spawn` (win32proc.c): `flags & 2` adds `CREATE_NO_WINDOW` to
  `CreateProcessW`'s `dwCreationFlags`. POSIX ignores the bit entirely — the
  no-op Node also gives.

## Implementation notes

- Bit layout recap: `mode` bit 0 = buffered, bit 1 = shell/verbatim, bit 2 =
  windowsHide; `__kml_win_spawn` `flags` = `mode >> 1`, so flags bit 0 = verbatim,
  bit 1 = windowsHide. Streaming spawn passes `mode` `0|4` or, with `shell`,
  `2|4`.
- The `cpSpawnOpts` struct refactor is the reason the diff also touches the `env`
  return path — same call, one struct instead of four returns.

## Side effects discovered

None. `detached` / `timeout` / `stdio` arrays remain clean rejections — the
remaining TDD-00180 §3 spawn-option rows.

## Verification

- New E2E test `TestE2EChildProcessSpawnWindowsHide` (`windowsHide: true`, output
  still captured). Full `TestE2EChildProcess*` green on Windows 11 and Docker
  Linux.
- Manual repros: **Windows 11 native** — `windowsHide: true` alone and combined
  with `shell: true` + `env`, stdio intact. **Docker Linux `klain-ci:latest`** —
  accepted as a no-op, output unaffected.
- `examples/child_process/child_process.ts` extended; compiles and runs.
  `go build`, `go vet ./codegen/...` clean. `make status`/`reference-check`/
  `conformance` at delivery.
