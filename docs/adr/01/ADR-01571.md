# ADR-01571: Compile-time fixes for large and deeply nested programs

- **Relations**: Extends ADR-01562, Implements TDD-00230
- **Date**: 2026-10-11

## Context

After ADR-01562, Test262 recorded seven CODEGEN_TIMEOUTs (the 30-second
in-process deadline). Small files that had compiled in under a second took
about 19 seconds, and a 3 MB table file (`string-upper-lower-mapping.js`)
took 22 seconds instead of 9.

## Investigation

Goroutine dumps and CPU and allocation profiles found three causes:

- The fallbacks for nodes the checker never saw re-infer their parts. A
  name's binding re-infers its initializer, and a member read or call
  re-infers its receiver. Only the inner `inferExprTypeMemo` was memoised,
  so nesting compounded.
- The resolver's identifier scan (`codeIdents`) copied the rest of the
  source for each block comment it skipped
  (`strings.Index(string(src[i+2:]), …)`). That is quadratic, and it
  allocated 94 GB for a file with a comment on every line.
- Each pre-pass over a large array literal (global typing, cross-type
  widening, the empty-array usage pass) re-typed every element through
  the checker.

## Decision

- `inferExprType` memoises names, member reads and calls in the
  inference's scope-keyed layers, in a map of its own (`full`) beside the
  inner memo's. Both maps are made on first store.
- `codeIdents` searches the byte slice (`bytes.Index`).
- `inferArrayType` caches the type of an array literal of 64 or more
  constant elements (`constLiteralTree`) for the whole emission. Such a
  literal has the same type under any scope.

## Verification

The two small timing files compile in 1 second, as before. The table file
compiles in 9 seconds (`-compat=js`), the same as before ADR-01562. Mac:
the resolver and codegen unit packages and targeted E2E. Linux full gates.
