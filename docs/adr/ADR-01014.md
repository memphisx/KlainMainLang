# ADR-01014: Nested-function letrec hoisting, per-iteration loop capture, first-class generators (TDD-00129 complete)

- **Relations**: Completes TDD-00129 (Stages 2 + 3); Extends ADR-01013 (escape inference), ADR-00386 (Stage 1 capture); Relates to TDD-00057, TDD-00094
- **Date**: 2026-09-18

## Context

Three residuals after ADR-01013: a capturing nested function called before
its declaration statement was a clean error (JS hoists function declarations
with their bodies); an escaping capturing generator (`return g`) rejected; a
capturing declaration one block deeper produced invalid IR. Probing the loop
edge also surfaced a pre-existing arrow divergence: closures over a C-style
`let` loop variable shared ONE counter cell (klain printed 90 where Node
prints 30) — the very corruption the nested-decl for-loop-var rejection
existed to prevent.

## Decision

- **Letrec hoisting on demand.** A reference (call or value position) to a
  not-yet-emitted capturing nested declaration of the current body emits the
  closure at the reference point (`letrecEmitCapturingNested`, hooked into
  the call/identifier resolution fallbacks; `inferExprType` and the var-decl
  initializer inference mirror the closure type). This is semantically exact
  for every legal JS program: a legal call-before-declaration only touches
  captured variables already initialized above the call; one that would TDZ-
  crash in Node stays a clean compile error (the TDD-00070/00071 posture).
  Captures are shared heap cells, so the declaration statement's re-emission
  binds the same cells — behavior is identical whichever construction a
  caller holds. Only the innermost body's own declarations hoist this way
  (emitting an outer sibling mid-inner-body could capture shadowed symbols).
- **Per-iteration `let` loop binding.** `emitFor` detects loop variables some
  closure in the body captures (a capScan with the loop vars pre-bound, so
  only closure-crossing references collect) and gives each iteration a fresh
  heap cell: seeded from the working slot at the body's top, shadow-bound
  Boxed (closures capture the cell), written back at the increment block's
  top (so `continue` carries mutations; the update expression and next
  condition read the written-back value — JS's copy-in/copy-out). `var`
  keeps the single shared binding, like JS. The loop variables also join
  `enclosingCapturables`, so nested declarations classify as capturing; the
  for-loop-var rejection (and its `activeForLoopVars` machinery) is deleted.
  Closure-mutates-loop-var, `continue`, and body-mutation-advances-loop all
  match Node byte-for-byte.
- **First-class generator values.** A generator name in value position
  (`return g`, `const G = g`, an object-literal field) becomes a constructor
  closure (`emitGeneratorCtorClosure`): the captured env is packed at the
  ESCAPE point (cells still resolvable, shared by reference), the thunk
  constructs a fresh instance per call (construction refactored into
  `emitGeneratorConstructValues` over pre-evaluated params + a pre-built
  env). Registration-time element inference now binds the enclosing body's
  params/locals (shared `defineForInference`) so the two GenTy computations
  agree — the mismatch read a yielded f64 as garbage bits.
- **Iterator for-of loop variables.** `emitForOf` pushes its loop variable(s)
  (bare name or destructuring-pattern leaves) as an `enclosingCapturables`
  frame, so a nested declaration in a generator/stream/`Symbol.iterator`
  for-of body classifies as capturing (each iteration re-binds the variable,
  so the closure naturally captures that iteration's cell). Fixing this
  exposed a PRE-EXISTING closure bug: an enclosing loop's pending
  iterator-close finallys (the sync-generator `.return()` synthesis,
  ADR-00613) ran inside a closure body's own `return`, referencing the
  enclosing frame's synthetic generator binding ("a number has no method
  'return'" — reproducible with a plain block-bodied arrow before this
  change). Closure emission now saves and clears
  `pendingFinallys`/`breakFinallyDepth`/`continueFinallyDepth` alongside the
  break/continue/label stacks it already reset.
- **Block-deeper capture fix.** `capScanStmts` gained the missing
  `*ast.FunctionDeclaration` closure boundary, so a captured local is eagerly
  boxed at its declaration (dominating cell) instead of lazily in a
  non-dominating conditional block (invalid IR).
