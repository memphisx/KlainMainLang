# ADR-01146: Type-only imports and exports

- **Relations**: `Extends ADR-00134`, `ADR-00135`, `ADR-01145`
- **Date**: 2026-09-25

## Context

`import type { P } from "./m"`, `import { type P }` and `export type { P }`
did not parse. They are common TypeScript forms, and the usual way to name
a Node type such as `IncomingMessage` without importing a value. Nothing
tracked the gap. It was found while ADR-01145 declared `process`.

## Investigation

- **A plain `import { P }` of an interface already works.** The resolver
  binds an imported type by its name, so a user module needs no new
  resolution, only the parse.
- **A builtin module's value-export table does not list its types.**
  `import { type ParsedPath } from 'path'` failed with "has no exported
  member". Its types come from the library, and codegen already offers
  Node's classes (`IncomingMessage`) as global types.
- **`type` is contextual.** `import type from './x'` is a default import
  named `type`, and `{ type as B }` imports a name `type`.

## Decision

- **Parser.**
  - `import type` before `{`, `*` or a default name marks every binding
    type-only (`ImportDeclaration.TypeOnly`, `ImportSpecifier.TypeOnly`).
  - A `type` before a specifier's name marks that one (`isTypeModifier`),
    in import and export lists.
  - `export type { … }`, with or without `from`, marks the list.
- **Resolver.**
  - A builtin module's type-only bindings are erased right after parsing
    (`eraseBuiltinTypeImports`). An import left binding nothing is dropped.
  - A user module's type-only bindings resolve as before, and are recorded
    per file (`typeOnlyLocals`). A value use of one is TS1361, reported at
    the identifier.

## Verification

- **`TestE2ETypeOnlyImportsAndExports`:** every form, a type-only
  re-export, `IncomingMessage` from `http`, a `type` specifier beside a
  value from `path`, and `import type from` as a default import. A called
  type-only import is TS1361.
- **`examples/imports/type_only.ts`:** Node's output.
- **Gates (with ADR-01145–01147):** Test262 strict 7,034 (+3 over
  ADR-01144), js 7,825 (+32), no clang failures in either lane; the Node
  suite is unchanged (strict 61, js 63). `make examples` 360/360 apart
  from `chained_listen`'s intermittent hang (1 in 3 alone; HEAD hangs at
  the same rate). `make test-par`: only the four macOS `-mm=gc` failures.
