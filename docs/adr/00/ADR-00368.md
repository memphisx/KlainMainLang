# ADR-00368: path.basename suffix strip is binary-safe (length header, not NUL)

- **Relations**: `Extends ADR-00364`, `Implements TDD-00120`
- **Date**: 2026-08-25

## Context

Running Node's own `test-path-basename.js` through the Node conformance track
(TDD-00121 Track B) surfaced a wrong result: `path.basename('aaa/bbb', 'bb')`
returned a value that compared unequal to `'b'`, and `console.log` of it printed
truncated (the tail after the first byte vanished).

## Investigation

`__kml_path_basename` (`runtime_path.go`) strips a matching suffix in its
`truncate` block by writing a single NUL over the suffix start
(`store i8 0, ptr %sufp`). That was correct before length-carrying strings, but
TDD-00120 (ADR-00364) made every string carry an `[i64 len]` header, and
`.length`/`===`/search now read that header rather than stopping at a NUL. The
base buffer was allocated with `__kml_str_alloc(baselen)` — header = `baselen` —
so after the NUL store the header still claimed the full pre-strip length:
`.length` returned `baselen`, and `__kml_str_cmp` compared `baselen` bytes
(matching-suffix bytes now zeroed) against the expected string, so equality
failed. `console.log`'s `%s` path (the one deferred TDD-00120 consumer) stopped
at the NUL, hence the truncated print. This is the same missed-consumer class
ADR-00364 fixed for the string builtins, here in a hand-written runtime helper.

## Decision

In the `truncate` block, return a correctly-headered buffer of the post-strip
length instead of NUL-terminating in place: `__kml_str_alloc(%sufoffset)`,
`memcpy` `%sufoffset` bytes from the base, NUL-terminate for C-string interop, and
return it. The untruncated `done` path is unchanged.

## Implementation notes

One block in `ensurePathBasename` (`runtime_path.go`); `memcpy`/`__kml_str_alloc`
are already ensured by the function. No emitter or API change.

## Side effects discovered

Other `path` helpers were spot-audited: `dirname`/`extname` already build their
result via `__kml_str_alloc` + `memcpy` at the correct length (no in-place NUL
truncation), so they were not affected. Other Node `path` files still fail for
unrelated reasons (unsupported `assert.match`, `instanceof` against a builtin,
`Object.entries` into a template literal) tracked in the Track B report, not here.

## Verification

`go build` + the `tests` E2E suite green (no regression). A direct repro over the
`basename(input, suffix)` edge cases from `test-path-basename.js`
(`'aaa/bbb','bb'`→`'b'`, `'aaa/bbb','b'`→`'bb'`, trailing-slash and no-match cases)
all pass after the fix; `test-path-basename.js` flips from fail to pass in the Node
track (`-suite=node`). Verified on macOS (arm64).
