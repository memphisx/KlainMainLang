# ADR-02080: The conformance runner sets its memory budget on macOS too

- **Relations**: Extends ADR-02075; Implements TDD-00230
- **Date**: 2026-11-25

## Context

The macOS Node lane (`-workers 2`, `GOMEMLIMIT=1600MiB`) was killed by
the 3 GB guard with the runner itself at 2.7 GB. Through the Test262 js
lane the runner held 483 MB to 2272 MB.

## Investigation

- A heap profile every two minutes (a temporary hook, not kept): the live
  heap was 100-400 MB throughout, on macOS as on Linux x86-64. On Linux
  the runner's RSS stayed at 1627 MB (HEAD 1696 MB) over the same lane.
- `footprint`: 2827 MB of the runner's 2832 MB was untagged dirty memory,
  the Go heap; at a sample with 92 MB in use, RSS was 1755 MB. The
  memory was collected garbage the collector had not reached.
- `setBudget` (budget.go) sets the compiles' budget, the heap's limit
  and the headroom for the front-end slots, but `main` called it only
  when `availableCommitBytes()` was positive, and on macOS it returns 0.
  So the macOS runner had no budget and kept GOGC=400 under the
  GOMEMLIMIT: the heap goal at five times the live heap sat past the
  limit, every cycle was the limit's, and once those cycles wanted more
  than the collector's CPU cap the runtime let the heap pass the limit.

## Decision

- With no figure from the OS, `main` calls `setBudget(0)`: a GOMEMLIMIT
  becomes the compiles' budget, and the heap's limit follows the slots.
- When the memory limit is below the slots' headroom (1.5 GB plus 384 MB
  per slot) and GOGC is not set, `setBudget` sets GOGC back to 100, so
  the collector works at twice the live heap instead of against the
  limit. A run whose limit has the headroom keeps GOGC=400.

## Implementation notes

- `tools/conformance/main.go`: the `setBudget(0)` branch.
- `tools/conformance/budget.go`: the GOGC rule.

## Verification

- macOS arm64 Node suite, both lanes, `-workers 2`,
  `GOMEMLIMIT=1600MiB`: completed under the 3 GB guard with no test
  killed, the runner between 377 MB and 1511 MB (sampled every ten
  minutes); before, the guard killed it at 2.7 GB. Strict 388, js 1141.
- Linux x86-64 takes the `availableCommitBytes` branch with a limit
  above the headroom, so its GOGC and limit are unchanged; the same-file
  benchmark (ADR-02075's sample) is unaffected.
