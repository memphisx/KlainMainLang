# ADR-00540: `node:sqlite` V1 — synchronous DatabaseSync/StatementSync over libsqlite3

- **Relations**: Implements TDD-00151 (V1 — Layers 1–3, row-shape Option A)
- **Date**: 2026-08-31

## Context

[TDD-00151](../tdd/TDD-00151.md) scoped faithful support for Node's built-in
`node:sqlite` module. This ADR commits the V1 slice and its concrete
implementation shape so the work can proceed directly from it: `import
{ DatabaseSync } from 'node:sqlite'`, `new DatabaseSync(path)`,
`db.exec`/`db.prepare`/`db.close`/`db.isOpen`, and on the returned
`StatementSync` the `get`/`all`/`run` reads plus `sourceSQL`/`expandedSQL`,
backed by the system `libsqlite3`.

V1 deliberately excludes the Layer 4 surface (`iterate`, `columns`,
`setReadBigInts`, user-defined `function`/`aggregate`, sessions/changesets,
extension loading, async `backup`) and the Layer 3 Option B dynamic-row record —
each is an independent follow-on ADR. The scope here is the smallest useful,
fully-faithful core: open a database, run statements, read typed rows.

## Investigation

The recon that fed TDD-00151 confirmed every mechanism V1 needs already has a
working precedent in the tree; this ADR records the exact call sites so the diff
is re-derivable.

- **Module registration** — `resolver/virtual_modules.go`:
  `virtualBuiltinMarkers` (the `import`→marker rewrite, TDD-00049) and
  `virtualModuleMembers` (named-import allowlist). `node:sqlite` has no bare
  Node counterpart, so — like the `klain:` entries — it is registered
  explicitly and skipped by the `init()` auto-`node:`-prefixer at line 243.
- **Builtin constructor at parse time** — `parser/parser_literals.go` already
  switches on the constructor identifier (`URL`/`Headers`/`Request`/`Worker`/…)
  to produce a dedicated AST node; codegen routes those in `emit_exprs.go`'s
  `case *ast.NewXxxExpression`. The general `emitNewExpression`
  (`emit_classes.go`) is user-classes-only and builtins never reach it. `new
  URL()` is the end-to-end template: `parseNewURLBody` (parser_literals.go) →
  `emitNewURLExpression` (`emit_url.go`) → a `CURLU*` handle in a heap struct
  flagged `IsURL`.
- **Handle-bearing object + method dispatch** — `codegen/llvm/types.go` carries
  boolean discriminants on `Type` (`IsURL`, `IsResponse`, `IsServerResponse`,
  `IsIncomingMessage`) with constructor helpers, and `emit_call.go`'s `emitCall`
  dispatches methods on those flags (the `IsServerResponse` / `IsIncomingMessage`
  checks at lines ~64–76). This is exactly the `db.<m>()` / `stmt.<m>()` shape.
- **C-lib linking** — `emitter.go` `requireLink(lib)` (~line 942) feeds
  `LinkLibs()` (~line 951), consumed by `main.go` (~lines 181–183) to append
  `-l<lib>` to the clang line. `runtime_fetch.go:25` (`requireLink("curl")`) and
  `runtime_url.go`'s `ensureCurlURL()` are the direct precedent for a
  third-party C library's externs-plus-conditional-link. `LocateCrypto`
  (`crypto.go`) is the pattern for a pkg-config→`brew --prefix`→bare-`-l` probe
  (needed for macOS's keg-only Homebrew `sqlite`).

**Row shape** was the one open design point; TDD-00151 settled it for V1 as
Option A (statically-typed rows), rejecting positional-array rows as an
unfaithful divergence and deferring the dynamic-record variant (Option B) to the
subsystem that also gates nested `JSON.parse`. This ADR implements Option A.

## Decision

**1. Register the module.** Add `"node:sqlite": "sqlite__kml_builtin"` to
`virtualBuiltinMarkers` and a `virtualModuleMembers["node:sqlite"]` allowlist
(`DatabaseSync`, `StatementSync`) — no bare `"sqlite"` alias (faithful: there is
no bare Node `sqlite`).

**2. `new DatabaseSync(path, opts?)`.** A `parser/parser_literals.go`
`case "DatabaseSync"` builds a new `ast.NewDatabaseSyncExpression` (path
expression + optional options-object literal); `emit_exprs.go` routes it to
`emitNewDatabaseSync`. Codegen opens via `sqlite3_open_v2` into a heap struct
typed `SQLiteDatabaseType()`/`IsSQLiteDatabase` holding the `sqlite3*` and an
open-flag. V1 options honoured: `readOnly` (→ `SQLITE_OPEN_READONLY` vs
`READWRITE|CREATE`), `open: false` (construct without opening; a later
`db.open()` follow-on), `enableForeignKeyConstraints` (default true → `PRAGMA
foreign_keys=ON`), `timeout` (→ `sqlite3_busy_timeout`). A non-OK open throws
(see 6).

**3. `DatabaseSync` methods** (`emitSQLiteDatabaseMethod`, dispatched on
`IsSQLiteDatabase` in `emitCall`):
- `exec(sql)` → `sqlite3_exec`, returns `undefined`.
- `prepare(sql)` → `sqlite3_prepare_v2` into a heap struct typed
  `SQLiteStatementType()`/`IsSQLiteStatement` (holds the `sqlite3_stmt*`, a
  back-pointer to the db for error reporting, and the cached column count).
- `close()` → `sqlite3_close_v2`, clears the open-flag.
- `isOpen` (property) → the open-flag as a boolean.

**4. `StatementSync` methods** (`emitSQLiteStatementMethod`, dispatched on
`IsSQLiteStatement`). Each read binds parameters, then:
- `get(...p)` → one `sqlite3_step`; a row object or `undefined` on `SQLITE_DONE`.
- `all(...p)` → step-to-`SQLITE_DONE`, an array of row objects.
- `run(...p)` → step once, `{ changes, lastInsertRowid }` from
  `sqlite3_changes64` / `sqlite3_last_insert_rowid`.
- `sourceSQL` / `expandedSQL` (properties) → `sqlite3_sql` /
  `sqlite3_expanded_sql`.
Statements are `sqlite3_reset` before each re-execution.

**5. Parameter binding + value mapping.** Positional trailing args bind by index;
a single trailing object literal binds named params (`:name`/`@name`/`$name`).
Value → SQLite: integral `number` → `bind_int64`, non-integral → `bind_double`,
`string` → `bind_text`, `null`/absent → `bind_null`, `Uint8Array` →
`bind_blob`, `bigint` → `bind_int64` (range-checked). Column read →
JS per the spec's storage-class map: `INTEGER`/`REAL` → `number`, `TEXT` →
`string`, `BLOB` → `Uint8Array`, `NULL` → `null`. INTEGER defaults to `number`
(matching Node; `setReadBigInts` is Layer 4), with the >2^53 precision caveat
documented.

**6. Row shape — Option A (typed rows).** The row object's shape is taken from
the call site's static type: the generic type argument on `.get<T>()`/`.all<T>()`
(how the Node `.d.ts` types are written) or, at an un-generic call site, a
`/** @type {{ … }} */` override. Given the shape, codegen emits a concrete
object struct and fills fields by **name** via `sqlite3_column_name`
(name-matched to the declared fields, not positional), applying the type map in
5. When neither a generic arg nor a `@type` is present, V1 raises a clear
compile-time error pointing at the annotation requirement rather than guessing a
shape — `SELECT *` against an unknown schema awaits Option B. If generic
type-args on builtin methods are not yet threaded through `inferExprType`, the
`@type` path stands alone and the generic form is a fast-follow.

**7. Linking.** A new `codegen/llvm/runtime_sqlite.go` holds `ensureSQLite3()`
(idempotent `declare`s for `sqlite3_open_v2`, `sqlite3_close_v2`,
`sqlite3_prepare_v2`, `sqlite3_step`, `sqlite3_reset`, `sqlite3_finalize`, the
`sqlite3_bind_*` / `sqlite3_column_*` families, `sqlite3_column_count`,
`sqlite3_column_name`, `sqlite3_column_type`, `sqlite3_changes64`,
`sqlite3_last_insert_rowid`, `sqlite3_sql`, `sqlite3_expanded_sql`,
`sqlite3_errmsg`, `sqlite3_extended_errcode`, `sqlite3_busy_timeout`, `sqlite3_exec`),
`requireLink("sqlite3")` gated on use, and a `LocateSQLite` probe copied from
`LocateCrypto`. Default is link-the-system-lib (libsqlite3 ships on macOS and
nearly all Linux, the libcurl posture); the bundled-amalgamation `CSource`
fallback for `--static` is out of V1 scope.

**8. Errors.** A non-OK `sqlite3` return constructs an `Error` carrying `code`
(`'ERR_SQLITE_ERROR'`), `errcode`, and `errstr` (from `sqlite3_errmsg` /
`sqlite3_extended_errcode`) and throws it through the existing
`setjmp`/`longjmp` exception path (TDD-00006), so `try/catch` around a bad query
behaves faithfully.

## Implementation notes

Files expected to change: `resolver/virtual_modules.go` (registration),
`parser/parser_literals.go` + the `ast` node (constructor), `codegen/llvm/emit_exprs.go`
(new-expression routing), `codegen/llvm/types.go` (two `Type` flags + constructors),
`codegen/llvm/emit_call.go` (two dispatch branches), a new
`codegen/llvm/emit_sqlite.go` (the database/statement method emitters + row
struct construction) and `codegen/llvm/runtime_sqlite.go` (externs + link +
locate). Per TDD-00151, the `new URL()` path is the closest end-to-end model to
follow for the handle-object shape.

Ordering constraint worth flagging for the implementer: the row-struct
construction in `all()`/`get()` depends on the Option A type being resolvable
from `inferExprType(callExpr)` — wire the generic-arg / `@type` resolution first
and assert a clear error on its absence, so the rest of the read path always has
a known field list to emit against.

## Side effects discovered

- **Resolver bug fixed in passing:** the rename pass rewrote a `CallExpression`'s
  callee and arguments but **not** its call-site type arguments, so *any*
  generic call carrying a user-defined type — `foo<Row>()`, and here
  `stmt.all<Row>()` — kept the un-mangled type name and failed to resolve at
  codegen (an interface used as a plain annotation worked, only the call
  type-arg position was missed). `NewExpression` already rewrote its `TypeArgs`;
  the `CallExpression` case now does too (`resolver/rename.go`). Not sqlite-
  specific — it was masking the named-type row form for every generic call.
- **No `LocateSQLite` probe needed.** Unlike keg-only Homebrew OpenSSL, the
  system `libsqlite3` is on clang's default search path on macOS and resolves
  via the distro `-dev` package on Linux, so a bare `requireLink("sqlite3")`
  suffices on both dev machines — the probe the recon anticipated was dropped.
- **Named parameters landed alongside V1:** a single object argument binds
  `:name`/`@name`/`$name` (or the bare key, resolved via
  `sqlite3_bind_parameter_index` over the four spellings), throwing on an
  unknown name — so both `stmt.run('Alice')` and `stmt.run({ name: 'Alice' })`
  work. The `setAllowBareNamedParameters` toggle stays unexposed (bare keys
  always accepted).
- **Staged out (fast-follows, not dropped):** `BLOB`→`Uint8Array` (needs
  aggregate-typed row struct fields — real layout work), `setReadBigInts`/bigint
  integers, `expandedSQL` (only `sourceSQL` ships), and the
  `.code`/`.errcode`/`.errstr` properties on thrown errors (the sqlite message
  text ships). All recorded in the status caveats.
- **Linux verified** (arm64, Docker `golang:latest` + `libsqlite3-dev`): the
  full sqlite E2E suite passes with the same bare `-lsqlite3`, closing the
  platform gap the recon flagged.

## Namespace completion (follow-on stages)

The initial slice above was extended to cover essentially the whole practical
`node:sqlite` surface, in verified stages:

- **Column types:** `BLOB`→`Uint8Array` (read via a copied heap buffer, bound
  via `sqlite3_bind_blob`) and INTEGER→`bigint` for a `bigint`-typed row field.
  Integral `number` params now bind as INTEGER, fractional as REAL (matching
  Node), decided by a runtime `fptosi`/`sitofp` round-trip.
- **DatabaseSync:** `open()` (reopens an `open:false`/closed handle — the path
  and flags are stored on the object), `isTransaction` (via
  `sqlite3_get_autocommit`), `location()` (via `sqlite3_db_filename`, `""`→null),
  and scalar **`function()`** — a per-registration C-callable trampoline
  (`void(sqlite3_context*, int, sqlite3_value**)`, generated through
  `beginThunkEmit`) retrieves the compiled closure from `sqlite3_user_data`,
  converts each `sqlite3_value` to the closure's declared parameter type, calls
  it, and forwards the result. Number/integer/bigint/string params and returns.
- **StatementSync:** `iterate<T>()` (eager materialisation so `for…of` works;
  lazy `.next()` deferred), `columns()` (name + declared type; origin fields
  null without `SQLITE_ENABLE_COLUMN_METADATA`), `expandedSQL`, and
  `setReadBigInts`/`setAllowBareNamedParameters` (accepted; the typed row field
  governs representation, so effectively no-ops).
- **Deliberately rejected with a self-documenting compile-time message** (the
  system `libsqlite3` doesn't provide them, or they are out of scope):
  `aggregate()` (a later stage), `createSession`/`applyChangeset` (no session
  extension), `loadExtension`/`enableLoadExtension` (extension loading
  disabled + a native-plugin security surface), and async `backup()`.
- Still deferred as documented caveats: the dynamic-row (untyped `SELECT *`)
  mode, a lazy iterator, and `aggregate()`.

## Fidelity pass (differential against a real Node binary)

Running the same programs through this compiler and a real `node` (v26) as an
oracle surfaced real divergences, since fixed:

- **`NULL` → `null` for nullable columns.** A `T | null`-typed row field now
  reads a SQL `NULL` as `null` (guarding on `sqlite3_column_type == SQLITE_NULL`)
  instead of the column type's zero — nullable-scalar (`number|null` via the
  `{i1,T}` slot), `bigint|null`/`string|null` (null pointer), and
  `Uint8Array|null` (`{null,0}`). A non-nullable field still reads `NULL` as its
  zero (the type system has no null there).
- **`err.code`/`errcode`/`errstr`.** SQLite failures now throw an Error carrying
  `code = 'ERR_SQLITE_ERROR'`, the numeric `errcode`, and `errstr` — byte-identical
  to Node. This extended the shared `errorObjType` with three trailing fields
  (offsets 0–2 unchanged, so the AggregateError prefix and every `.message`/
  `.name` read stay valid); `buildErrorObj` defaults them.
- **Two compiler bugs fixed in passing** (both pre-existing, not sqlite-specific):
  `bigint | null === null` was constant-folded to `false` (so a null bigint
  never compared equal, and calling a method on it segfaulted) — now a
  null-pointer check; and a mixed-type ternary (`cond ? aString : aNumber`)
  silently emitted invalid IR — now a clean compile-time rejection (a
  union-typed ternary stays unsupported in this typed subset).
- **Standing differential oracle** (`tests/sqlite_oracle_test.go`): runs paired
  programs through this compiler and a real `node`, requiring identical stdout;
  skips cleanly when `node`/`node:sqlite` is absent. Makes "identical to Node"
  machine-checked rather than asserted from memory.

## Verification

- `tests/sqlite_test.go` (15 tests, all cross-checked against real Node's
  `node:sqlite`): typed `.all<Row>()`/`.get<T>()` with named-interface and
  inline row types; positional and named parameters (and the unknown-name
  throw); `.run()`; INTEGER/REAL/TEXT/NULL plus `BLOB`→`Uint8Array` and
  `bigint`; `isOpen`/`readOnly`; `expandedSQL`/`isTransaction`; `open:false`
  then `open()`; `columns()` and `iterate()`; a scalar `db.function()` invoked
  per-row; the untyped-row compile rejection; and the reasoned rejections for
  `createSession`/`loadExtension`/`aggregate`.
- `examples/sqlite/sqlite.ts` (new): a typed-row task-list CRUD flow.
- `go vet` clean; the generics/namespaces/type E2E suites pass (guarding the
  resolver rename change); `make conformance-node` flat at 43 (expected — the
  module isn't in the compilable parallel corpus).
- Platform: verified on macOS (Apple Silicon M4) with the system `libsqlite3`
  and on Linux (arm64, Docker `golang:latest` + `libsqlite3-dev`) — the sqlite
  E2E suite passes on both via a bare `-lsqlite3`.
