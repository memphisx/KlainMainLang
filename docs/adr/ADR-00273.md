# ADR-00273: Module-level variables — a named `function` can read a top-level `const`/`let`

- **Relations**: Implements [TDD-00093](../tdd/TDD-00093.md); relates to [ADR-00001](ADR-00001.md) (closure capture/boxing)
- **Date**: 2026-08-20

## Context

A named `function` declaration could not read a top-level `const`/`let`/`var` — `const BASE = 100;
function add(n) { return BASE + n }` failed with `undefined variable 'BASE__kml_mod0'`. Top-level
statements are emitted into the synthetic `main()`, so a top-level binding is a `main()` local; a
named function is a separate top-level LLVM function with a fresh scope and can't see `main()`'s
locals. An arrow/closure worked (it captures free variables), which masked the gap. A previously
undocumented, everyday limitation surfaced while testing `for await` over a typed array.

## Investigation

`lookup` (`emitter.go`) walks `e.scopes` innermost→outermost; a function body resets `e.scopes` to a
single fresh frame (`emit_func.go`), so the top-level binding — living in `main()`'s scope — is
invisible. Functions are emitted in Pass 2, *before* Pass 3 emits `main()`'s top-level statements, so
any fix must register the binding before function bodies are emitted. `gatherCaptures`
(`emit_func.go`) collects a closure's free variables via `lookup`, so once `lookup` can resolve a
top-level binding, a closure would try to *capture* it — which (for a mutable `let`) would box a
second copy that diverges from a named function's view.

## Decision

Promote a top-level `const`/`let`/`var` of a **reliably-typed scalar/string/object/`Map`/`Set`** (one
global — a ptr for the pointer types) or **array** (two globals — data ptr + length) to an LLVM
module global; leave everything else a `main()` local (unchanged).

- New `e.moduleGlobals` (name→`Symbol{Ptr:@global}`) and `e.promotedGlobalDecls` (the exact promoted
  decl nodes, by pointer).
- `registerModuleGlobals` (new Pass 1.7, before function emission): for each direct top-level decl
  with an unambiguous simple type, emit `@__kml_global_<name> = internal global <ty> <zero>` and
  register it.
- `lookup` falls back to `e.moduleGlobals` after the function scopes (a same-named local shadows it).
- `emitVarDecl` stores the initializer into the global for a promoted decl — keyed by node pointer,
  since a function body also runs at scope depth 1 (depth alone would misclassify a function-local
  `const` of the same name and clobber the global).
- `gatherCaptures` skips a module global: a closure references it directly, no boxed second copy.

**The invariant:** the global's declared IR type must equal the store `emitVarDecl` later emits,
which holds iff the type is computable in the pre-pass exactly as `emitVarDecl` computes it in
`main()` — i.e. it depends only on annotations, literals, earlier module globals (registered in
source order, so `lookup` finds them), and named non-generic non-async functions (`resolveFuncRef`).
`promotableInitInPrePass` states that rule directly, and `reliableGlobalType` computes the type with
the *same* `lookup`/`resolveFuncRef`/`inferArrayType`/`inferObjectType`/`resolveType` helpers
`emitVarDecl` uses — so no shadow inference can drift. This covers scalars/strings/arrays/objects/
`Map`/`Set` **plus** an un-annotated call to a named function (`const cfg = loadConfig()`) and an
initializer referencing an earlier global (`const b = a`). A scope-dependent init (a spread
`{ …rest }`, `[localVar]`, a computed key), a generic/async/scalar-returning call, or a `bigint`
stays a `main()` local, never miscompiled. `emitArrayVarDecl` (two globals), `emitObjectVarDecl`,
and `emitMapVarDecl`/`emitSetVarDecl` (one ptr global, via `moduleGlobalPtrOrLocal`) gained the same
promoted-decl redirect; `reliableGlobalType` computes `Map`/`Set` from the initializer to match
those emitters.

## Implementation notes

- `emitter.go`: the two maps + inits; the `lookup` fallback; the Pass 1.7 call.
- `emit_exprs_vardecl.go`: `registerModuleGlobals`, `reliableSimpleGlobalType`, `isSimpleGlobalType`;
  the plain-scalar path stores into the global for a promoted decl (no alloca, no local `define` —
  it's already in `e.moduleGlobals`, and the global's own initializer is the zero default).
- `emit_func.go`: `gatherCaptures` skips `e.moduleGlobals` names.

## Side effects discovered

- **Pre-pass type inference must be scope-independent.** Promoting an un-annotated object/array
  literal via `inferObjectType`/`inferArrayType` in Pass 1.7 (before `main()`'s body) infers a type
  that diverges from `emitVarDecl`'s when the literal references another top-level binding (a spread
  `{ …rest }`, an element `[x]`, a computed key) — a malformed global. Caught as two suite
  regressions (`Object.keys requires known fields`, `no field 'c'`); fixed by gating un-annotated
  composite-literal promotion on `literalTypeIsScopeIndependent` (pure literals only). An annotated
  type (`resolveType`) or a scalar/string literal is scope-independent and unaffected.
- The complementary gap — a `bigint`/un-annotated-call/initializer-typed-`Set` top-level const still
  unreadable from a named function — is the documented follow-on in TDD-00093, not a regression.
