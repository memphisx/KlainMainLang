# ADR-01787: Parameter defaults capture the enclosing variables they read

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- Several free-variable scans read only a function's body: the dynamic callable, a generator, a function nested in an expression, and the `arguments` checks. A parameter default that read an enclosing local (`f = function (a = iter) {}` with `iter` held by `main`) failed to compile with "undefined variable". So did a default inside a destructured parameter (`[x = local]`, `{ z = local }`) and a generator's desugared pattern parameters.
- Where the captures were scanned, the closure bound them after its parameters, and destructured parameters unpack (running their defaults) in the parameter loop.
- A destructured parameter whose default read a captured variable was rejected outright ("only supported for a scalar, string, object, or array parameter").
- A typed function expression built `arguments` after its defaults ran, so `function (a = arguments.length)` could not compile.

## Decision

- `scanParamDefaultsFV` adds the free names of every parameter default and every default inside a destructuring pattern. All capture scans call it. The generator scan also reads `genPatternInits`.
- The dynamic callable, `emitClosureFunc` and `emitFunctionExpression` bind captures (and `arguments`) before the parameters. A parameter of the same name still shadows a capture.
- `emitPatternParamBodyDefault` fills a destructured parameter's slot (boxed, or one object pointer) from its default before unpacking it. It runs when the argument was left out (presence-mask bit clear) or, for a boxed slot, is undefined.

## Consequences

- A destructured parameter held in the two-word array ABI, or a nullable scalar, still rejects a default that reads a captured variable.
- `TestE2EJSFileParamDefaultCaptures` compares assigned functions and generators, nested pattern defaults, arrows and `arguments` against Node.
