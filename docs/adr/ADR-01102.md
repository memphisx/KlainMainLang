# ADR-01102: A generated AST traversal, and the search walkers moved onto it

- **Relations**: `Implements TDD-00230` (Phase 1, P1.4)
- **Date**: 2026-09-23

## Context

Every pass that walked the AST carried its own type switch over node kinds: 49
recursive walkers across codegen, the resolver and the parser. Each had to list
the kinds it descends into. A kind it forgot silently skipped a subtree, which is
the "new AST node needs every walker" failure recorded in several ADRs. Six more
walkers descended by reflection instead, which avoids missing kinds but also
enters type annotations and aliased fields. [TDD-00230](../tdd/TDD-00230.md) P1.4
replaces both with one traversal that can't fall out of step with the node set.

## Investigation

- **The AST.** `ast/nodes.go` defines 99 node structs and 16 helper structs that
  carry nodes (`Param`, `SwitchCase`, `CatchClause`, `ObjectProperty`,
  `AnnotField`, the destructuring patterns, …).
- **`TypeAnnotation` holds no expressions.** `typeof` operands are stored as
  strings. `Program.DynamicImportNodes` aliases nodes already in the body, and
  `Program.WorkerModules` holds separate module bodies.
- **The search walkers had real gaps:**
  - `programContainsCall`, the HTTP-upgrade and HTTPS pre-scan, never entered
    class bodies. A comment admitted a "safety net for the theoretical case this
    walk misses a container type".
  - The return-statement scans (`stmtHasReturn`, `returnExprsInStmt`,
    `firstReturnExprInStmt`) skipped labeled statements.
  - `collectYieldExpr` entered only calls, binary and conditional expressions,
    assignments and `await`.
  - `exprSuspend` did not enter `new` expressions, template literals, or array
    and object literals.
  - The `@pure` checker's `checkStmt` treated any statement kind it did not name
    as pure: `try`/`catch`, `do…while`, labeled statements, `throw` and
    destructuring.
- **typescript-go** generates its `ForEachChild` from a schema
  (`_scripts/ast.json` → `ast_generated.go`).

## Decision

- **`ast/gen` generates the traversal.** A `go generate` tool reads the Go
  definitions in `ast/nodes.go`, so the schema is the AST itself, and writes
  `ast/walk_generated.go`: `ForEachChild(n, visit)` for every node kind, visiting
  children in field order.
  - A child is a field typed `Expression`, `Statement` or `Node`; a pointer to a
    node struct; a helper struct, by value or pointer, that transitively contains
    children; or a slice of any of those.
  - Excluded: `TypeAnnotation` and `Pos`, `Program.DynamicImportNodes` (aliases)
    and `Program.WorkerModules` (separate bodies, walked explicitly where needed).
  - An embedded field is a generator error.
- **`ast/walk.go`** adds `Inspect(n, fn)`, a pre-order walk that descends only
  when `fn` returns true. A typed nil pointer held in an interface counts as
  absent.
- **Walkers moved onto the traversal.** Each keeps its semantics, and gains the
  node kinds it missed:
  - `programContainsCall` and `programConstructsClass`.
  - The three return scans (and their block variants) become one
    `forEachReturn`, with `hasReturn`/`firstReturnExpr`/`returnExprs` on top. It
    never enters expressions or nested function or class declarations, and
    `firstReturnExpr` still skips a bare `return;`.
  - `collectYields` replaces three yield functions and stops at nested functions
    and classes.
  - `awaitsDirectly` replaces the suspension classifier (`stmtSuspend`,
    `exprSuspend` and the dead `isSuspendingAwaitArg`) and the reflective
    top-level-await walk.
  - Reflective walkers moved: `programMayWait` (which still includes worker
    module bodies), `lexicalThisIn` (which now also stops at classes),
    `scanConstRegex` with `collectReassignedIdents`, and `collectFnValueRefs`
    (worker modules included).
  - The `@pure` checker keeps its scoped handling of the kinds it names. Every
    other statement is checked through `ForEachChild`, and locals are collected
    through the traversal, including catch parameters and destructured names.
- **Left for phase 2 on purpose:**
  - The walkers the binder and flow graph replace outright: free-variable and
    capture scans, readability and definite assignment, renaming, escape
    analysis.
  - The reflective scans that depend on *field names* rather than node kinds
    (`thisEscapesFn`, `collectFinRegNames`). They need binding information, not a
    better traversal.

## Implementation notes

- **New:** `ast/gen/main.go`, `ast/walk.go`, `ast/walk_generated.go` (682 lines),
  `ast/walk_test.go`, `tests/ast_walk_test.go`.
- **Changed:** `emit_http_upgrade.go`, `emit_asynchooks.go`, `emit_http.go` (a
  comment), `emit_func.go`, `emit_generators.go`, `emit_task_classify.go`,
  `emit_module_task.go`, `emit_async_coroutine.go`, `emit_regexp_replace.go`,
  `emit_tuple_byval.go`, `pure_check.go`.
- **Net effect:** about 700 lines of hand-written walking removed.

## Side effects discovered

- **An `'upgrade'` handler registered in a class method** failed with an
  internal "not detected by the upgrade pre-scan" error. Now fixed
  (`TestE2EHTTPUpgradeRegisteredInClassMethod`).
- **A function whose only valued returns sit under a label** emitted invalid IR
  (`ret ptr` in an `i64` function). Now fixed
  (`TestE2EReturnInsideLabeledLoopSetsReturnType`).
- **A generator with `yield`s inside an array literal** was rejected with a type
  mismatch. Now fixed (`TestE2EGeneratorYieldsInsideArrayLiteral`).
- **`@pure` accepted I/O** inside `try`/`catch`, `do…while` and labeled loops.
  Now rejected (`TestPureRejectsEffectsUnderAnyStatement`).
- **An async function that awaits inside `new Uint8Array(await …)`** was
  classified as non-suspending (`examples/crypto/crypto.ts` `digests`). It is now
  a coroutine. The output is unchanged on this program.
- **Found, not fixed here:**
  - Return-type inference doesn't bind a `for…of` variable, and emits invalid
    IR (BACKLOG §0 item 28, for TDD-00230 phase 2).
  - `crypto.getRandomValues(number[])` is accepted where Node throws, and
    `examples/crypto/crypto.ts` relies on it (item 29, for phase 3).
  - `examples/http/async_handler_inproc_client` and `req_readable` hang about
    one run in 10–20 on every build tried, including the session's starting
    binary (item 1, for phase 4).

## Verification

All on macOS arm64 (M4):

- **`TestInspectMatchesReflectionOracle`.** An independent reflection walker,
  with the same exclusions, visits exactly the node sequence `Inspect` visits
  across 4,829 parsed sources: all examples, the `tests` sources, and every
  backquoted program in the Go tests.
- **`TestWalkGenerated`** fails when `walk_generated.go` is stale.
- **Equivalence corpus** (24,125 files, compared with the preceding build):
  - No file changed between compiling and failing, in either direction. 94
    failing files changed their error message.
  - The one IR change among compiling files is `crypto.ts`'s `digests` becoming
    a coroutine (above), with identical output.
- **Targeted suites** (generators, async, top-level await, tuples, regex
  replace, upgrade, finalization, `@pure`, ASI) pass, apart from the known macOS
  `-mm=gc` TLS failure. `make examples` passes, apart from the pre-existing
  flaky hang above.
