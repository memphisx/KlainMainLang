# ADR-01658: Builtin constructors as values from the checker side, typeof from declarations, Object()

- **Relations**: Implements [TDD-00230](../../tdd/TDD-00230.md) (P3.3, `reprOf` totality; P0.2 shadow rows)
- **Date**: 2026-10-16

## Context

A refreshed `make shadow-report` (47,909 compile runs) listed 21,258 rows;
18,295 were `switchFallback` rows for identifiers, where the checker side
had no answer and inference fell back to the old decider. About 4,000 of
those in program code were builtin constructors read as values: `Number`
(as the receiver of `Number.MAX_VALUE` and in `const N = Number`), `Object`,
`Date`, `Symbol`, `String`, `Array`, `Promise`, `Function`. The rows did not
record the fallback's answer, so they could not show which representation
the checker side had to give.

While probing them: `typeof Function`, `typeof Proxy`, `typeof WeakMap` and
`typeof globalThis` were `"undefined"` (Node: `"function"`, `"object"`), and
`new Object()` and `Object(x)` failed with "unknown class 'Object'" even in
the strict lane, which accepted them although the library's
`ObjectConstructor` declared no call or construct signature.

## Investigation

- The fallback for a builtin constructor is `identStorageType`
  (`emit_exprs_types.go`): `inferBuiltPreamble`'s `builtinRef` gives `Number`
  and `Symbol` the intrinsic's function value; `Object`, `Function`,
  `Promise` and the builtin constructors are boxed (`TypeAny`).
- `typeofStaticAnswer` (`emit_exprs_operators.go`) answered builtin names
  from two hand-kept tables, which had drifted from the implemented runtime.
- TypeScript's `lib.es5.d.ts` declares `new (value?: any): Object; (): any;
  (value: any): any;` on `ObjectConstructor`.

## Decision

- `shadowSwitchFallback` records the fallback type, so a row names the
  representation the checker side must give.
- `builtinGlobalValueType` holds the value rules for a name with no program
  binding (a builtin function value, a namespace object, a boxed
  constructor, a builtin module's `__kml_native` namespace). `identStorageType`
  uses it, and the oracle reaches it through `reprCtx.builtinValue` for an
  identifier the binder resolves to a library global whose type is an object
  other than a plain function type, unless codegen binds the name (a library
  module's export reads as its storage). A declared function keeps its
  function type's representation.
- A member read on a library global is never a dynamic read in the oracle,
  however the global itself is held: `Math.sqrt` stays the intrinsic's
  function type with `Math` boxed.
- `typeof` of a library global comes from its declaration: callable or
  constructible is `"function"`, any other object type `"object"`, a
  primitive infers. The two tables are deleted. `globalThis` is `"object"`.
- `ObjectConstructor` declares TypeScript's signatures. `new Object()` and
  `Object()` with no argument, `null` or `undefined` make an empty dynamic
  object; with an object argument they return it. A primitive argument, or
  one that may be primitive, is a clean rejection: primitive wrapper objects
  do not exist yet (BACKLOG).

## Implementation notes

`shadow.go`, `infer_memo.go`, `emit_exprs_types.go`
(`unboundBuiltinValueType`), `shadow_binder.go` (`isLibObjectValue`,
`libGlobalRef`), `emit_exprs_operators.go`, `emit_classes.go`
(`isGlobalObjectCtor`, `emitObjectCtor`), `emit_call.go`, `lib/es.d.ts`.

## Side effects discovered

None.

## Verification

`TestE2ETypeofBuiltinGlobalsAndObjectCtor` compares the `typeof` of 18
builtin globals and the `Object()` forms with Node; the existing builtin
function value, constructor call and `typeof` suites pass. A shadow run of
the probe records no fallback (Mac). A shadow report run before the
library-global rule went from 21,258 to 9,778 disagreements; switchFallback
identifier rows went from 18,295 to 6,808 (Node304).
