# ADR-01443: Implicit-any arithmetic and method parameters under -compat=js

- **Relations**: Implements TDD-00230 (P2.2)
- **Date**: 2026-10-07

## Context

The `inferUnannotatedReturnType` unanswered bucket (968 rows) was almost
all js-lane Test262 classes: a method whose return the checker could not
type. The top causes were:

- `x + 1` with `x` an implicit `any`.
- A call to a method with an unannotated parameter (`this.n(2)`,
  `this.#m(x)`).

## Investigation

- `checkBinary` left `+` unanswered when an operand is `any`. TypeScript
  types it `string` when either side is string-like, else `any`.
- Under `-compat=js` an unannotated parameter is typed from its call
  sites. A method's sites are "out of sight" because its receiver decides
  the call, so the whole signature was unanswered. checkJs types such a
  parameter `any`, and codegen already treats it as dynamic.

## Decision

- `+` with an `any` operand and no string-like side is `any`.
- An unannotated parameter of a class method (not the constructor) whose
  call sites are unknown is `any` under `-compat=js`.

## Side effects discovered

- Reading an instance method as a value (`return this.#gen`, `const f =
  k.greet`) still fails with "no field". It is the open BACKLOG item for
  method values, after Phase 5's method table.

## Verification

- New `TestCompatJS` cases; the checker package passes on the Mac.
