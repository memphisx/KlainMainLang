# ADR-01964: A contextual tuple return is the arrow's result

- **Relations**: Implements TDD-00230 (P3.3)
- **Date**: 2026-10-29

## Context

An arrow or function expression with no return annotation, typed by a signature returning a tuple, compiled its array literal as an array. The call site read the result as the signature's tuple, a positional struct:

- `const pair: (a: number, b: string) => [number, string] = (a, b) => [a, b]` crashed on `pair(1, "x")`;
- with `any` elements, the call returned `[ '', null ]`.

TypeScript types such a literal as the tuple, as it would under a return annotation. A generic signature's tuple (`<A, B>(a: A, b: B) => [A, B]`) is held with boxed elements. A binding declared as the instantiation's tuple (`const p: [number, string] = gen(1, "x")`) stored that boxed tuple unconverted and read `1.125`, the box's bits as a double.

## Decision

- When every value the body returns is an array literal without spreads and the contextual signature's result is a tuple, that tuple is the function's result (`contextualTupleReturn`). A generic signature's own type parameter is `any` there, as codegen compiles the signature.
- A tuple of one element layout converted to another is copied element by element, each converted (`relayoutTuple`), in `convert` and in an object-kind declaration's initializer.

## Consequences

- The cases above print what Node prints (`TestE2ETupleContextualReturn`).
