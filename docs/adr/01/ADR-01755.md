# ADR-01755: A class expression's body reads the file's names

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

`const C = class { m() { return foo(1); } }` failed with "cannot find name 'foo'" under the strict lane, and with "undefined function or closure 'foo'" under `-compat=js`. Any binding of the file was affected: a function, a `const`, a function declared after the class. The resolver mangles a file's top-level names (`foo` to `foo__kml_mod0`). Its expression walk had no case for a class expression, so references inside one kept the bare name, which no declaration has. A namespace member read (`assert.sameValue`) keeps its name, which is why the Test262 class-expression tests that only read the harness's `assert` compiled.

## Decision

The resolver walks a class expression's declaration as it walks a class declaration in the enclosing scope (`rewriteClassDeclIn`). A frame binding the class's own name surrounds it, so a named class expression's self-references (`Named.k`) stay its own.

## Consequences

- `TestE2EClassExpressionReadsModuleNames` covers a module-level class expression, one returned from a function, and a named one reading its own static.
