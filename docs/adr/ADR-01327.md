# ADR-01327: The microtask, rejection and try-frame runtimes in C

- **Relations**: Implements TDD-00240 (first ports), Extends ADR-01326
- **Date**: 2026-10-01

## Context

[TDD-00240](../tdd/TDD-00240.md) moves the runtime out of IR text into C.
The first candidates are the routines every program with a promise or a
`try` reaches, and that changed per program: the microtask and
`process.nextTick` queues were a real runtime in one program and empty
stubs in another, so their symbols could not be shared by separately
compiled units ([TDD-00238](../tdd/TDD-00238.md) Stage 4).

Separately, `TestE2EAsyncLocalStorageDeepStack` aborted on Linux with
glibc's "stack smashing detected" (BACKLOG 133). The stack of setjmp
buffers `try` frames unwind through was a fixed thread-local array of 64
slots, and a coroutine task's or a generator's a fixed 16; `push` had no
bound, so the 65th nested `try` wrote past the array. On glibc the main
thread's static TLS sits beside the thread control block, which holds the
stack-protector canary; macOS's layout hid the overwrite.

## Investigation

- `tools/libdrift -runtime` (ADR-01326) lists the runtime routines that
  differ between programs; `__kml_drain_microtasks` and the unhandled
  rejection hooks were among them, each as a real body or a stub.
- A setjmp buffer holds the frame's registers, not its own address, and
  nothing reads a buffer's address after `setjmp` returns: only `push`
  (for the `setjmp`) and the throw path (for the `longjmp`) compute slot
  addresses. A buffer therefore only has to stay put while its frame is
  live, which a chunked stack gives without a bound.

## Decision

1. **`kml_layout.h`** is generated from the emitter's struct strings
   (`layout_header.go`: the promise, the closure header, the reaction list
   node, the promise flag bits) and prepended to each runtime C source, so
   a layout change reaches C and changes the object cache key.
2. **`microtasksrc/microtask.c`**: the microtask and nextTick queues, their
   drains, `queueMicrotask`'s enqueue, the top-level-await tick, a
   promise's reaction drain, and the unhandled-rejection tracking (mark
   handled, note rejected, the checkpoint check). The report of one
   unhandled rejection stays generated (it boxes the promise for the
   listeners); a program that tracks none defines it as a no-op, so C needs
   no weak symbol (unreliable on COFF). Every stub of these symbols is
   gone: where one was emitted, the C file is linked.
3. **`jmpstacksrc/jmpstack.c`**: the try-frame buffer stack. A stack is a
   descriptor of 256 chunk pointers, each chunk of 64 slots allocated when
   first reached; the thread's own stack is a thread-local descriptor, and
   each task and generator allocates one (`__kml_jmp_stack_new`) instead of
   a fixed 8 KiB block. `__kml_cur_jmp_stk` and `__kml_jmp_top` move to C
   (IR declares them `external thread_local`), so the dozen sites that swap
   a task's stack in and out are unchanged. Past 16,384 nested frames the
   program reports `RangeError: Maximum call stack size exceeded` and exits
   instead of writing past the stack.
4. **A ratchet** (`TestIRTextOnlyShrinks`) counts the IR definitions each
   file writes as text; a file may only lose them.

## Implementation notes

- A `.then` reaction, a timer and a task all reach the C queues through the
  same symbols as before; only their definitions moved.
- Fixed in passing: the class snapshot problem behind ADR-01326's signal
  bug was general. A class type held in a signature, a field or a closure
  type before the class's layout was final (its vtable field decided) read
  fields at the wrong index once library classes always carried a vtable
  (`performance.measure(...).duration` read `startTime`). The emitter now
  rewrites every registered signature, field, interface and module global
  with the final class types before any body is emitted
  (`refreshClassTypes`), and a member read canonicalizes a class type.

## Side effects discovered

- Recorded for TDD-00240: a C routine calling back into generated code
  should take a registered function pointer rather than a weak symbol.
- The stack limit is a process exit, not a catchable `RangeError`; Node's
  limit is the native stack's, and its error is catchable.

## Verification

- macOS (Apple Silicon): targeted tests for promises, microtasks, ticks,
  async functions, generators, `try`/`finally`, uncaught and unhandled
  rejections, `AsyncLocalStorage`, XHR; probes diffed against Node,
  including a 2,000-deep nested `try` and a `try` across generator and
  async suspension; `TestLayoutHeaderMatchesEmitter`.
- Linux x86-64 (test boxes): `TestE2EAsyncLocalStorageDeepStack`; the full
  gates.
