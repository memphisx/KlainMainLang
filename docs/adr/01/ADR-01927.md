# ADR-01927: namespace objects and live bindings

- **Relations**: `Implements TDD-00230` (faithful namespace and module semantics found while closing oracle rows)
- **Date**: 2026-10-21

## Context

- The parser desugars a namespace's members into top-level declarations, so a namespace has no value of its own. `console.log(App)`, `Object.keys(App)` and `const c = App.Config` were compile errors. Node prints the object TypeScript's emit builds.
- A namespace's own top-level statements were emitted outside its context. `export const t = s * 3` could not read the sibling `s`, and a member function could not read `t` because the global pre-pass never promoted it. `count++` and `count = 0` on a bare sibling inside a member function failed, although reads worked.
- A namespace function value printed its mangled name (`[Function: App__kmlns_f]`).
- A module namespace object (`import * as M`) copied each export once at the top of the module. A `let` export read through a saved reference (`const o: any = M; M.inc(); o.n`) kept its first value. Node reads the live binding.

## Decision

- The parser records, per namespace and in declaration order, the members its object holds: exported values, classes, non-const enums, and instantiated nested namespaces, including the outer name of a dotted `namespace A.B`.
- Before binding, `ast.AddNamespaceObjects` adds a hidden `any` constant for each namespace the program reads whole, and for the nested namespaces those objects hold. It is placed after the last statement of the namespace or of any namespace inside it. Each property is the `N.member` read, so the checker types it and codegen emits it through the existing paths. A namespace merged with a function, class or enum is that value and gets none.
- An exported `let`/`var` becomes a getter/setter pair over its binding. The `LiveBindings` intrinsic builds the literal as a runtime bag and marks those accessors live. Module namespace objects use the same mechanism for their `let`/`var` exports.
- The runtime's live attribute presents such an accessor as the data property it stands for: inspect shows the value, the descriptor is `{ value, writable }`, and a write without a setter is a read-only write.
- Top-level statements of a namespace, and the global-type pre-pass on its declarations, run with the namespace as context. The promotion gate and the read-in-functions scan know about siblings. Stores to a bare sibling go to the mangled binding. A namespace function's display name drops the namespace prefix.

## Consequences

- Namespace values, `import X = N.Sub` aliases, and live `let` exports on namespace and module namespace objects match Node, verified on the Mac against `node --experimental-transform-types`.
- Only namespaces read whole get an object, so programs that only use `N.member` are unchanged.
- A namespace read before its last statement runs sees the hidden constant's undefined. In TypeScript's emit, the partly built object is visible.
