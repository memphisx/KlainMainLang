# ADR-00561: Template literal types parse and resolve to string

- **Relations**: Extends TDD-00079
- **Date**: 2026-09-01

## Context

A template literal type in a type position (`type Id = ` + "`user-${number}`" +
`) was a hard parse error: "expected type name, got TEMPLATE_HEAD". This was
the last parse-level ❌ in the type-system category (distinct from template
literal *values*, which already work). The type system does not narrow or
enforce string-literal types — they resolve to `string` (TDD-00079) — so a
template literal type has the same faithful outcome: `string`.

## Investigation

The type-atom parser (parser_types.go) rejected any token that wasn't a type
name/keyword. The lexer already emits the correct
`TEMPLATE_HEAD`/`TEMPLATE_MIDDLE`/`TEMPLATE_TAIL`/`TEMPLATE_NO_SUB` token
sequence for a backtick in any context, so the parser only needed to consume
that structure in a type position.

## Decision

In the type-atom parser, before the type-name check:

- `TEMPLATE_NO_SUB` (`` `plain` ``) → consume it, return a `string` type.
- `TEMPLATE_HEAD` → consume it, then loop: parse the `${...}` interpolated type
  (recursively `parseTypeAnnotation`), then consume a `TEMPLATE_MIDDLE`
  (another interpolation follows) or `TEMPLATE_TAIL` (end). Return a `string`
  type.

Both go through `parseTrailingArrayBrackets`, so `` `a-${string}`[] `` is a
`string[]`. Matching the existing string-literal-type narrowing, the pattern
itself is erased — the type is `string`, not a checked literal shape.

## Implementation notes

- Type-position only (parser_types.go); template literal *value* expressions
  are a separate path (parser_literals.go) and are unchanged.
- The recursive `parseTypeAnnotation` for the `${...}` content naturally stops
  before the `TEMPLATE_MIDDLE`/`TEMPLATE_TAIL` the lexer emits (the closing `}`
  is folded into that token).

## Side effects discovered

None.

## Verification

`TestE2ETemplateLiteralType` exercises no-substitution, single- and
multi-substitution, and `[]`-suffixed forms (all usable as `string`); the
parser suite and existing template/type tests still pass. Built and verified on
Mac (Apple Silicon).
