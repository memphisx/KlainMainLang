# ADR-00904: Generator runtime global declared on the body path

- **Date**: 2026-09-12

## Context

Invalid-IR sweep. A generator declared but never constructed referenced an
undefined global:

```
%t0 = load ptr, ptr @__kml_gen_pending_obj   ; clang: use of undefined value
```

From `language/statements/generators/prototype-typeof.js`,
`for-await-of/let-identifier-with-newline.js`, and
`class/syntax/class-declaration-computed-method-generator-definition.js`.

## Investigation

`ensureGeneratorRuntime` (`emit_generators.go`) declares
`@__kml_gen_pending_obj` and is called on the *construction* path
(`emitGeneratorConstruction`). But a generator function body is emitted whether
or not it is ever constructed, and the body's prologue *loads* that global. A
generator declared but never called (`function* g(){}; typeof g.prototype`) thus
emitted a load of a never-defined global.

## Decision

Call `e.ensureGeneratorRuntime()` (idempotent) at the top of the generator body
emission, right before the load — so the global is declared wherever it is
referenced, not only on the construction path.

## Implementation notes

`usedGeneratorRuntime` already guards the declaration against duplication.

## Side effects discovered

None.

## Verification

- `TestE2EGeneratorDeclaredNotConstructed` (new).
- All 3 files compile clean.
- `make examples` 296/296.
