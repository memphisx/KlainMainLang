# ADR-01013: Returned-by-name nested functions infer a closure type

- **Relations**: Part of TDD-00129 (closes the escape-inference residual; Stage 2 hoisting of capturing declarations and escaping capturing generators stay open); Extends ADR-00386 (Stage 1 capture)
- **Date**: 2026-09-18

## Context

Auditing TDD-00129's open stages: in-scope capturing generators and array
captures already work (landed with later closure work, ADR-00941 — the status
prose was stale), while Stage 2 proper (a *capturing* nested fn called before
its declaration statement) and an *escaping* capturing generator remain clean
rejections. One residual was cheap and real: returning a capturing nested
function **by name** from a function with **no return-type annotation** —

```ts
function makeCounter() {
  let n = 0;
  function bump() { n++; return n; }
  return bump;   // caller's binding mistyped → "undefined function or closure"
}
```

`inferBlockReturnExpr` (the unannotated-return-type inference) bound the
block's `let`/`const` locals but not its nested function declarations, so
`return bump` fell to the bare-scalar default and the caller's `const c =
makeCounter()` was not a callable. An explicit `(): () => number` annotation
already worked — inference was the only gap.

## Decision

`inferBlockReturnExpr` also binds each top-level nested
`*ast.FunctionDeclaration` of the block as a `FuncType(params, ret)` symbol
(signature via the authoritative `buildFunctionSig`), so a returned nested
function infers the same closure type an arrow would.
