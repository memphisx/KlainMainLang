# ADR-01589: An `any` converts into tuples and arrays of arrays

- **Date**: 2026-10-11

## Context

`const t: [number, string] = a` with `a: any` holding `[1, "x"]` crashed
(SIGSEGV). Reading `z["a"]` from a `{ [k: string]: number[][] }` built by
an object literal threw "the value is not an array". Found writing the DNS
test server ([ADR-01587](ADR-01587.md)).

## Investigation

- **Tuples**: `coerce` from a dynamic value had no tuple arm, so a tuple
  target fell to the plain `ptr` arm. That arm reinterpreted the array
  box's payload as the tuple's headerless struct. `emitUnboxBoxToType`
  already had `emitUnboxTuple`; `coerce` never reached it.
- **Arrays**: the dynamic-array branch of the array unbox
  (`emit_narrowing.go`) excluded element types that are arrays (other than
  Buffer), objects and tuples. An object literal builds its nested arrays
  as dynamic arrays, so `number[][]` and `[number, string][]` targets fell
  through to the static-only path and threw.

## Decision

- `coerce` from `any` into a tuple goes through `emitUnboxBoxToType`.
- The dynamic-array unbox accepts array and tuple element types. Each
  element is unboxed through `storeArrayElem` (array elements) or
  `coerce` (tuples), recursively.

## Verification

`TestE2EAnyIntoTuplesAndNestedArrays` matches Node. It covers static and
dynamic boxes, `JSON.parse` output, and `Record` reads at module and
function scope.
