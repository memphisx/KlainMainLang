# ADR-00761: ChildProcess `'exit'`/`'close'` fire as `(code, signal)`; `child.kill` takes a signal name

- **Relations**: Implements [TDD-00184](../tdd/TDD-00184.md); extends [ADR-00759](ADR-00759.md) (the Windows wide exit code in the finalize path) and [ADR-00754](ADR-00754.md) (the spawn-`'error'` finalize branch); addresses [TDD-00180](../tdd/TDD-00180.md) §3
- **Date**: 2026-09-07

## Context

Node fires a streaming child's `'exit'`/`'close'` events with two arguments,
`(code, signal)`: a normal termination gives the integer code and `signal = null`;
a signal-terminated child gives `code = null` and the signal **name** (`'SIGTERM'`,
`'SIGKILL'`, …). The port supported only a single non-nullable numeric argument
and folded a signalled death into it as POSIX's `128 + signum`, so
`child.on('exit', (code, signal) => …)` — the canonical Node spelling — could not
be written, and a killed child reported `143` where Node reports `(null,
'SIGTERM')`. `child.kill('SIGTERM')` (a string signal name, Node's idiomatic
call) also failed: `kill` coerced its argument straight to `i64`, so a string
produced a `getelementptr`-as-`i64` constant and a clang type error. The highest-
value remaining `child_process` faithfulness gap ([TDD-00180](../tdd/TDD-00180.md)
§3), scoped and designed in [TDD-00184](../tdd/TDD-00184.md).

## Investigation

`__kml_cp_finalize` (`runtime_childprocess.go`) is emitted once and calls the
stored `'exit'`/`'close'` closure through a hand-written fixed function-pointer
signature `void(ptr env, double code)`. Widening the event is therefore a
**listener ABI change**, not a local edit — the reactor cannot know a given
listener's arity. `emitCBCall` reconciles arity but passes a nullable-scalar
param as its bare `ty.IR` (`double`), while a closure callee expects
`storageIR` (`{ i1, double }`) — so routing the nullable `code` through it would
mismatch. The adapter-closure mechanism already used for the chunk/dgram ABIs
(`buildBuiltinClosure`/`beginThunkEmit`, `emit_net.go`) is the right tool: a
per-call-site adapter that presents the reactor a fixed signature and forwards to
the user closure with its own arity. Windows has no `WIFSIGNALED` — `TerminateProcess`
just sets an exit code — so a killed child there needs the signal the `.kill()`
recorded, which nothing stored.

## Decision

- **Event ABI.** `'exit'`/`'close'` listeners receive `(code, signal)`,
  `code: number | null`, `signal: string | null`; 0, 1, or 2 params allowed. The
  reactor always calls a fixed adapter signature `void(ptr env, i1 present,
  double code, ptr signal)`; the per-call-site adapter (`cpExitCloseAdapter`)
  forwards to the user closure with its declared arity/types. An untyped first
  param defaults to a plain `number` (0 on a signalled death); typing it
  `number | null` opts into the faithful `null`. The `signal` name is always
  delivered when a second param is declared. `contextTypeArrowParams(arg,
  "number", "string")` sets the defaults without overriding an explicit
  annotation.
- **Signal source, per platform.** A GOOS-parameterized helper
  `__kml_cp_event_flags(i32 status, i64 killsig) -> { i1 present, i32 signum }`
  decides the shape: POSIX from the wait status (`WIFSIGNALED` = low 7 bits set,
  `WTERMSIG` = those bits); Windows from the recorded `.kill()` signal (a new
  cp-struct field 21), since there is no signalled bit. The reactor keeps the
  old folded `128 + sig` value only for the buffered exec path / field-5
  `exitCode`; the streaming event uses a separate `plaincode` (0 on signal) and
  the flags helper, so no `strings.Replace` is needed.
- **Signal names.** `__kml_cp_signal_name(i64) -> ptr` switches the signal number
  to an interned Node name string (null for an unmapped number), using the host
  platform's numbering (native compile) — 1–6, 8, 9, 11, 13–15 shared, and
  `SIGBUS`/`SIGUSR1`/`SIGUSR2` resolved per GOOS. Shared table `cpSignalTable()`.
- **`child.kill(signal)`.** A string **literal** signal name resolves to the
  host's number at compile time via `cpSignalNumber`; a numeric argument passes
  through; the default is `SIGTERM` (15). The number is recorded into field 21
  (for the Windows event shape) before the `kill(2)` call. A dynamic (non-literal)
  signal-name string is rejected with a clear error — a documented caveat.

## Implementation notes

- The cp struct grows to 22 fields / 176 bytes (field 21 = recorded kill signal);
  both `calloc` sites (`runtime_childprocess.go`, `runtime_ipc.go`) and
  `cpStructBytes` moved in lockstep. `calloc`-zeroed, so "not killed" reads 0.
- The finalize format string gained one `%s` (the field-21 GEP) — the args list
  grew by one `cp`; `go vet ./codegen/...` confirmed the count.
- **Gotcha:** an IR comment inside the finalize raw-string literal originally
  contained a back-quoted `` `number|null` `` — back-quotes terminate a Go raw
  string; the comment was reworded. (The same class of trap as the `fmt.Sprintf`
  arg-count one.)
- The adapter forwards through `coerce`, which demotes the boxed `number | null`
  to a plain `double` for a legacy param and keeps the `{ i1, double }` box for a
  `number | null` one — the single point that reconciles the two typings.

## Side effects discovered

- The existing `examples/child_process` "wide exit status" line prints 44 (not
  300) on Windows because it runs through **mingw `sh`**, which truncates to 8
  bits POSIX-style; ADR-00759's wide code applies to Windows-native children. Not
  changed here — pre-existing, and orthogonal to this ADR.
- Exposing `.exitCode`/`.signalCode` **properties** on the handle (distinct from
  the event arguments) remains a future row (TDD-00184 leaves it out of scope).
