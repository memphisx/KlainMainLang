# ADR-01822: Private-name brands: `#x in o`, foreign receivers

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- `#x in o` (ES2022's ergonomic brand check) did not parse.
- A method called on another receiver (`C.prototype.m.call(o)`) ran on it if its prototype chain held `C.prototype`, as `Object.create(C.prototype)`'s does. The method then read that object as a `C` instance: memory it does not own.
- A method reading `this.#x` called on a foreign receiver threw `Method C.prototype.m called on incompatible receiver` on entry. V8 runs the body and throws at the private access.

## Decision

- The parser reads a private name followed by `in` as the left operand of `in`. The checker leaves the name to the class, and codegen resolves it to the innermost enclosing class declaring it.
- A right operand that is not an object throws V8's TypeError (`Cannot use 'in' operator to search for '#x' in 1`).
- A brand is the class tag the constructor gives an instance (a subclass's included), never the prototype chain. `#x in o` tests it for an instance private field or method, and a static private is present only on the class itself. A method's receiver check tests the same brand.
- A body run on a foreign receiver throws at `this.#x` with V8's messages, after whatever the body did first: `Cannot read private member #x from an object whose class did not declare it`, `Cannot write private member …` (after evaluating the right side), `Receiver must be an instance of class C` for a private method or accessor.

## Consequences

- `TestE2EPrivateNameIn` and `TestE2EJSFilePrivateForeignReceiver` cover these.
- A body reaching another object's private member (`other.#x`) or `super` still refuses a foreign receiver with the entry TypeError.
