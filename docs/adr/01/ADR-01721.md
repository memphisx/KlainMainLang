# ADR-01721: A find callback past a shrunk length sees `undefined`

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-18

## Context

`find`, `findIndex`, `findLast` and `findLastIndex` visit every index up to the length the array had when the call started (spec `Get`, not `HasProperty`).

If the callback shrinks the array, a later index reads `undefined`. For a scalar element type (`number[]`, `boolean[]`, `bigint[]`), the compiler passed the type's zero instead (`0`, `false`), because a plain `number` slot cannot hold `undefined`.

## Decision

When the walk reads through the array's live header, the callback's element parameter takes the scalar's `T | undefined` form. That form is the presence-flagged `{ i1, T }` value that `find`'s own result already uses. Each step passes the element as present when the index is below the current length, and as absent otherwise.

A walk without a live header keeps the plain element: it reads data loaded before the walk, so the array cannot shrink under it.

## Verification

macOS (Apple Silicon):

- `TestE2EFindPastShrunkLength` matches Node for all four methods, including ordinary callbacks that do arithmetic on the element, annotate it, or pass a named function.
- The Find, HOF, Callback and Undefined suites pass.
