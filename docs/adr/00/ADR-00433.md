# ADR-00433: spawn options — cwd wired through, shell/stdio:'pipe' tolerated

- **Relations**: Extends [ADR-00322](ADR-00322.md) (async child_process), [ADR-00411](ADR-00411.md) (the *Sync options)
- **Date**: 2026-08-28

## Context

28 oracle files fail on spawn's third options argument — mostly
`spawn(process.execPath, args, opts)` and `spawn(cmd, [], { shell:
common.isWindows })` (a variable-bound object).

## Decision

`spawn(command, args?, options?)` accepts an options argument, literal
or variable-bound typed object (the ADR-00429 treatment):

- `cwd` is real: `__kml_cp_spawn` grew a cwd parameter — the child
  `chdir`s before exec (exec/execFile pass null; the *Sync forms already
  had this via their own C core).
- `shell` is accepted and ignored — its corpus value is
  `common.isWindows` (false here), and commands always exec directly,
  never through a shell. A literal `shell: true` is therefore *not*
  honored (disclosed caveat).
- `stdio` accepts the literal `'pipe'` only (this runtime's one wiring);
  `env`/`detached`/stdio arrays are clean rejections.
- The 2-arg `spawn(cmd, options)` form (options in the args slot) also
  resolves.

The `chdir` declaration moved to a shared `ensureChdirDecl`
(process.chdir previously declared it privately — a duplicate-declare
hazard once both features co-occur).

## Implementation notes

`emit_childprocess.go` (`cpSpawnOptions`, arg re-slotting,
`cpSpawnCall` cwd param), `runtime_childprocess.go` (spawn signature +
child chdir block), `runtime_core.go`/`runtime_process.go`/`emitter.go`
(shared decl).

## Side effects discovered

None.
