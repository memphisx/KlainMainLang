# ADR-01021: Asynchronous `net.connect` (non-blocking connect + async `'error'`)

- **Relations**: `Extends ADR-00324` (net server event loop), `ADR-00501` ('close' ordering); relates to `TDD-00183` (Windows IOCP — this unblocks its ConnectEx path), `ADR-00754` (spawn 'error' event), `ADR-01000` (fs error shape)
- **Date**: 2026-09-20

## Context

`net.connect`/`net.createConnection` was implemented, but the underlying
`connect()` syscall was issued **blocking** (`runtime_net.go`
`__kml_net_connect`, "the same V1 simplification the WebSocket client uses — no
non-blocking-connect/write-set machinery in the loop"). Two faithfulness gaps
followed:

1. The connect handshake blocked the event loop until it completed.
2. A failed connection **threw a synchronous, catchable Error**
   (`emit_net.go` `finishNetConnect`, "V1: no async 'error' event"). Node never
   throws here — `net.connect` returns a socket immediately and reports failure
   asynchronously through the socket's `'error'` event.

This surfaced while scoping the Windows IOCP reactor Stage 2 (TDD-00183): the
completion model's `ConnectEx` primitive exists to service the `EINPROGRESS`
path, but the IR never produced one because it connected blocking. Rather than
build `ConnectEx` as dead code, the blocker — async `net.connect` — is built
first, faithfully, on all platforms.

## Investigation

- `runtime_net.go`: `__kml_net_connect`/`__kml_net_connect_unix` did a blocking
  `connect()` then registered the socket; `__kml_net_fdset_add` force-zeroed the
  select timeout whenever a socket had a pending field-4 'connect' listener (the
  blocking-era "fire it on the next pass" hack).
- `runtime_http.go`: the event loop already builds and passes a **write set**
  (`%wfdset`) and **except set** (`%efdset`) to `select()`, but only
  `curl_multi_fdset` ever populated them; the per-subsystem `fdset_add` hooks
  receive the read set alone.
- `emit_exceptions.go`: `errorObjType` carries `code`/`errno`/`syscall`/`path`
  but **not** `address`/`port`, which Node's connect error exposes.
- The Windows shim (`win32io.c`) uses the **Linux errno namespace** for its
  `L_E*` values, maps `WSAEWOULDBLOCK→L_EINPROGRESS` on the connect path
  (line 785), and its `getsockopt(SO_ERROR)` translates `L_SO_ERROR`(4)→
  `WS_SO_ERROR` and maps the result back into that same namespace (line 844+).
- The portable `connect()`-retry idiom (retry connect: `EISCONN`=done,
  `EALREADY`/`EINPROGRESS`=pending, else=the error) **does not report a connect
  failure on Windows** — a second `connect()` there does not surface
  `ECONNREFUSED`. `getsockopt(SO_ERROR)` does, on every platform.

## Decision

Make `net.connect` fully asynchronous, faithful to Node, on all platforms.

- **Non-blocking connect.** `__kml_net_connect`/`_unix` create the socket
  non-blocking, issue `connect()` without blocking, and record a **connect-state
  blob** (new `netSocketIR` field 9, `netConnStateIR
  {status, addrlen, err, pad, addr[128]}`): status 1 = connecting
  (`connect()` returned 0 or `EINPROGRESS`/`EWOULDBLOCK`/`EALREADY`/`EINTR`),
  2 = immediate connect error (errno captured), 3 = DNS failure (the host string
  is stashed in the addr blob for the error message). The call **always returns a
  socket and never throws**.
- **Write/except readiness.** New `__kml_net_conn_wset_add(wfdset, efdset,
  maxfd)`, called from the event loop, adds every still-connecting client fd to
  the write and except sets, and forces a zero-timeout pass when a socket already
  carries a resolved error (so a DNS failure, whose fd is -1, is still delivered
  promptly). `__kml_net_fdset_add` no longer force-zeroes on a pending 'connect'
  listener (completion is now writability-driven).
- **Completion in dispatch.** `__kml_net_dispatch` completes a connecting socket
  portably: `getsockopt(SO_ERROR)` first (reports failure on every platform —
  the retry idiom's Windows blind spot), then a `connect()` retry to distinguish
  connected (`rc==0`/`EISCONN`) from still-in-progress. On success it fires the
  field-4 `'connect'`/`'ready'` listener; on failure it builds a coded Error and
  fires the field-8 `'error'` listener (or throws it uncaught, as Node does for
  an unhandled `'error'`), then closes and fires `'close'`.
- **Coded errors.** New `__kml_net_conn_errobj` builds Node's exact shapes:
  `connect <CODE> <ip>:<port>` (code via `__kml_errno_code`, `errno` the negative
  platform value, `syscall` "connect", plus `err.address`/`err.port`), and
  `getaddrinfo ENOTFOUND <host>` (code ENOTFOUND, errno -3008, syscall
  getaddrinfo). `errorObjType` gains `address`/`port` fields (12/13); all three
  errorObjType builders switch `malloc`→`calloc` so the new (and the pre-existing
  `cause`) trailing fields default cleanly on errors that do not set them.
- **`socket.on('error')`** is now accepted (field 8), typed with the
  `errorObjType` hint so `err.code`/`.address`/… resolve to real fields.
- `net.connect({ path })` (AF_UNIX) uses the identical async machinery.

The `select()`-contract choice, and why the write set is projected rather than
the reactor API redesigned, follow TDD-00183's projection decision.

## Implementation notes

- `netSocketIR` widened 8→10 fields (80 bytes); all seven socket allocation
  sites (`runtime_net.go` ×3, `runtime_tls.go`, `emit_http.go`,
  `emit_http_upgrade.go` ×2) bumped 64→80 so a `socket.on('error')` field-8 store
  is never out of bounds on any net.Socket.
- The connect-completion logic is spliced into `__kml_net_dispatch`'s drain loop
  as a self-contained `connBlock` (its own indexed-arg `fmt.Sprintf`, one `%s`
  in the outer function) so the large outer positional-arg format string is
  undisturbed; it branches into the outer `%rloop`/`%cnext` labels.
- A socket with no connect-state (field 9 null) — server-accepted or
  `tls.connect` — keeps the legacy field-4 fire-once behavior.
- Errno classification uses per-platform constants (`netConnectErrnos`,
  `netSOError`); Windows shares the Linux column via the shim.

## Side effects discovered

- `aggregateErrorStructSize` was stale (80) versus the 11-field `errorObjType`
  (88) after `cause` was added; bumped to 104 alongside the new fields, which
  also removes that latent under-size.
- Common connect errnos (`ETIMEDOUT`/`EHOSTUNREACH`/`ENETUNREACH`/
  `ECONNABORTED`) were missing from the Linux/macOS `errno→code` table (Windows
  already had them); added so `err.code` is never null.
- On Windows the async connect runs today over the **existing Stage-1
  Winsock-`select` bridge** (`win32io.c`), which already projects a socket's
  write/except readiness into the reactor's result bitmaps — so the behavior is
  delivered on all three platforms now. TDD-00183 Stage 2 will replace that
  bridge with `ConnectEx` on an IOCP; this async path is the caller that finally
  gives `ConnectEx` a reason to exist, but Stage 2 is separate follow-on work.

## Verification

- **Windows** (native, MSYS2 UCRT64, clang 22): direct example runs — success
  round-trip (`'connect'` fires, PING/PONG), `ECONNREFUSED`
  (`connect ECONNREFUSED 127.0.0.1:1`, code/errno -111/syscall/address/port,
  `'close'` after `'error'`), and DNS failure
  (`getaddrinfo ENOTFOUND …`, errno -3008). `TestE2ENet*`, `TestE2EError*`,
  `TestE2EException*`, `TestE2ETls*`, `TestE2EChildProcess*` green.
- **Linux** (WSL2 Ubuntu, native `select`/real `EINPROGRESS`): `TestE2ENet*`,
  `TestE2EError*`, `TestE2EException*`, `TestE2ETls*`, and the `TestE2EHTTP*`
  suite (socket-struct widening) green; full `./tests` run green.
- E2E: `TestE2ENetConnectFailureEmitsError` and
  `TestE2ENetConnectDNSFailureEmitsError` added; the old
  `TestE2ENetConnectFailureThrows` (which asserted the unfaithful synchronous
  throw) rewritten to assert the async `'error'` event.
- `make conformance` (Test262) run at delivery.
