# ADR-00871: Web Platform Tests conformance track (TDD-00082 Track 2)

- **Relations**: `Implements TDD-00082`
- **Date**: 2026-09-11

## Context

TDD-00082 designed four external-conformance tracks. Three were live — Test262
(TDD-00008), Node-core and the TypeScript accept/reject oracle (both TDD-00121) —
but the Web-Platform track (WPT) was the one remaining *unbuilt* piece: there was
no `-suite wpt`, no WPT fetch, no checkout, so the Web-Platform API surface
(`URL`/`URLSearchParams`, `AbortSignal`/`AbortController`, `EventTarget`) had no
external oracle at all. Its async prerequisite (`promise_test`/`async_test` and
the `dom/abort` timer tests) had since shipped, so the track was actionable.

## Investigation

Sparse-cloned the headless-testable, in-scope-relevant slice of
`web-platform-tests/wpt` — URL, DOM, fetch, streams, encoding, URLPattern,
console, hr-time (timers), FileAPI, WebCryptoAPI, and the HTML web-app APIs —
and measured it directly, then probed the compiler for the primitives a
`testharness.js` shim needs, to design the shim against reality rather than guess:

- **Runnable subset**: **~1,340** `.any.js`/`.window.js`/`.worker.js` files across
  21 areas (IndexedDB 213, websockets 89, xhr 87, wasm/jsapi 80, streams 79, fetch
  247, WebCryptoAPI 129, dom 67, …). An initial 3-dir slice caught only 47 — the
  applicable surface is far larger; the `.html` files (2,217) build a real document
  tree and are out of scope by construction. Assertion vocabulary is ~30 functions
  (`assert_equals`/`_true`/`_false`/`_array_equals`/`_throws_js`/`_throws_dom`/
  `_class_string`/`_inherits`/…) plus `test`/`promise_test`/`async_test`/`step_wait`
  and a `// META:` frontmatter line — the same extract-frontmatter + prepend-harness
  shape the Test262/Node runners use.
- **wpt-runner parity**: a `// META: script=` helper include (`/common/utils.js`,
  `../util/helpers.js`) is **resolved and inlined** from the checkout the way
  wpt-runner/Node/Bun load them, not pre-skipped — the largest unblock. Results are
  counted at the **subtest** level (each `test`/`promise_test`/`async_test` is one
  subtest, WPT's own metric), not just file-level pass/fail. The genuine limit vs a
  JS-engine runner: no DOM and no dynamic global object, so a real DOM-tree file is
  reported out of scope (a scope choice), where jsdom-backed runners mock a full DOM.
- **Fixtures**: the URL corpus loads `resources/*.json` via
  `fetch("resources/x.json").then(r => r.json())`.
- **Runtime primitives** (all confirmed working): a `setTimeout`-based
  event-loop drain then `process.exit`; a file-backed `fetch` shadowing the
  builtin (`const`/`function fetch` both shadow); `try/catch` throw-detection;
  contextual typing of an untyped callback param to a class type (so `t.step_func`
  resolves against a real `__WptT` class).
- **Compiler limits that shaped the shim** (each found by compiling the shim
  against the real corpus): a top-level `const` arrow is **not** callable as a
  callee from a nested closure or class method here — only a hoisted `function`
  declaration is; an `any[]` parameter type is rejected (nested-any); `JSON.stringify`
  of a statically-typed value passed as `any` throws at runtime; a bare-`any`
  value can't infer a generic type argument.

## Decision

A `-suite wpt` track parallel to the existing three, restricted to the headless
`.any.js`/`.window.js` files, behind a **fully typed** `testharness.js`-shaped
shim (`wpt_harness.go`) prepended to each file. Typed so it compiles clean under
*both* compat lanes — a strict-lane failure is then the test body, never the
harness. Every shim callable is a `function` declaration (callable from the
nested callbacks the corpus wraps assertions in). The test context `t` is a class
(`__WptT`) so an untyped `t => {…}` callback is contextually typed to it.

Reporting is by **exit code**: each assertion throws on failure, the
`test`/`promise_test`/`async_test` wrappers catch it and bump a module-level
counter, and a self-rescheduling `setTimeout` drain waits for every async test to
settle before exiting nonzero if anything failed — the seam the runner reads. The
compiled binary runs with its cwd set to the test file's directory so the
file-backed `fetch` shim resolves `resources/*.json` fixtures. The `.html`
majority and any DOM-touching `.any.js` file are reported as an explicit
out-of-scope bucket, never silently dropped. The report reuses the Test262/Node
shape (per-area table, failure/skip histograms, passing-file list) and merges into
`docs/testing/conformance-summary.json`.

Deliberate, documented shim loosenesses so the numbers read honestly:
`assert_throws_js/_dom/_exactly` verify only that *something* threw (a passed-in
`any` ctor can't be matched against the thrown value's constructor here);
`assert_array_equals` is generic over the element type (a bare-`any` argument
can't infer it and fails to compile — rare in this slice);
`assert_own_property`/`assert_implements_optional`/`assert_props`/
`assert_reports_exception` are best-effort/no-ops.

## Implementation notes

- `fetch.sh` gains a pinned (SHA `85235b8e`, WPT ships no release tags),
  sparse, blobless checkout into gitignored `.wpt-tests/`; `wptRoots` in `wpt.go`
  names the same slice dirs so a new area is a paired edit.
- `wpt.go`: walk + `transformWPTSource` (strip `// META:`, inline local
  `script=./resources/*.js` helpers, classify DOM/`idlharness` files out of scope)
  + report; `wpt_harness.go`: the shim strings. `compileAndRun` was factored into
  `compileAndRunInDir` (a run-cwd param) so the WPT run resolves fixtures; the run
  binary path is made absolute when the cwd is redirected.
- `-suite wpt` dispatch in `main.go`, `wptSummaryLane` in `summary.go`,
  `make conformance-wpt` target, `docs/testing/README.md` track column.

## Side effects discovered

The shim's original `promise_test` wrapped the `Promise.resolve(fn(t)).then(…)`
chain in a `try/catch`, which emitted **invalid IR** (`Instruction does not
dominate all uses`) — a live codegen bug: a `const` local captured by a closure
defined *inside* a `try` block and also read in the `catch` block is boxed in a
block that doesn't dominate the catch use (residual of the ADR-00619
captured-local-box class). Minimal repro:

```ts
class T { name: string; constructor(n: string){ this.name=n; } finish(): void {} }
let counter: number = 0;
function pt(fn: (t: T) => any, name: string = ""): void {
  const t: T = new T(name);
  try {
    Promise.resolve(fn(t)).then((): void => { t.finish(); }, (e: any): void => { counter = counter + 1; t.finish(); });
  } catch (e) { counter = counter + 1; t.finish(); }
}
pt((): any => Promise.resolve(1), "p");
```

**Fixed in [ADR-00872](ADR-00872.md)** (eager-box captured object/class-instance
locals — ADR-00619's residual object path); the shim workaround was reverted to
the straightforward `promise_test` form once the codegen fix landed.

The track's first run surfaced a ranked worklist of genuine fidelity gaps (all
recorded in BACKLOG §3): `URLSearchParams` is modeled as a bare `Map` with no
`append`/`get`/`getAll`/`has`/`sort`/`size`; `URL.parse`/`URL.canParse` statics
missing; `instanceof` against the ambient `AbortSignal` class unsupported; an
event listener must be exactly a 1-arg function (blocks the `.onabort`-property /
`unreached_func` abort tests); `for…of` over a JSON-parsed `any` isn't iterable;
`JSON.stringify` of a `URL` doesn't call `toJSON`.

## Verification

macOS (Apple Silicon). `go build ./...`, `go vet ./...` clean. A synthetic
correct test (sync `test` + `promise_test`, `assert_equals`/`assert_array_equals`)
compiles, runs, and is reported **PASS** — proving the harness validates correct
behavior, so the corpus's low pass count (7/255 in-scope at first run, before the
URL work of ADR-00873/00874) is real gaps, not a broken harness. Both lanes run
via `make conformance-wpt`; reports written to
`docs/testing/{strict,js}/CONFORMANCE-RESULTS-WPT.md`. A `transformWPTSource` unit
test was added to `tools/conformance`. Test262 numbers are unaffected (this touches
only the conformance tool + shim, no compiler code path).
