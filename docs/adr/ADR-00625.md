# ADR-00625: `-compat=js` call-site inference for plain function parameters

- **Relations**: `Implements TDD-00022 (sub-problem 1, plain-function slice)`, `Extends ADR-00624`, `Implements TDD-00005 (option 2, top-level functions)`
- **Date**: 2026-09-02

## Context

[ADR-00624](ADR-00624.md) shipped call-site inference for constructor
parameters. The last purely-static TDD-00022 break shape was the plain
function: `function greet(name) { return "hello " + name }` still failed on
the ADR-00042 number default. This ADR extends the same mechanism to
top-level function declarations — TDD-00005's "option 2", exactly as
TDD-00022 adopted it.

## Decision

Two collection passes now share one whole-program AST walker
(`jsWalkProgram`, callbacks per `new` and per identifier-callee call):

- **`new` args** collect before `registerClasses` (unchanged, ADR-00624).
- **Function-call args** collect *after* `registerClasses` and before
  `registerFunctions` (`jsCollectFuncParamTypes`) — the ordering that lets a
  class-instance argument infer to its real class type. Identifier
  arguments, invisible to bare `inferExprType` pre-scope, resolve through a
  map of top-level binding initializer types (annotated bindings use the
  annotation), which covers the idiomatic
  `const home = new City(...); describe(home, 2)` shape. A spread argument
  ends collection for that call (positions shift); an uninferrable argument
  contributes nothing.
- **Application** happens inside `buildFunctionSig` — an unannotated,
  non-rest parameter takes the collected type — so the ADR-00041 fixed-point
  return-type re-inference sweep rebuilds with the inferred types too.
- **Conflicts are deferred, not errored, at collection**: the callee
  namespace includes builtins (`console.log(1)` vs `console.log("s")` must
  never trip it). `registerFunctions` validates only user functions with an
  unannotated parameter at the conflicting index — there it is a hard error
  asking for an annotation, first-inferrable-site-wins otherwise. Class-typed
  slots compare by class name, not just pointer-shaped IR.

Strict mode is untouched: collection never runs, `e.jsFuncParamTy` stays
nil, and the ADR-00042 default + non-numeric guard behave exactly as before.

## Consequences

- All of TDD-00022's break shapes 1 and 2 now compile under `-compat=js`
  with concrete native types — classes and functions, verified
  byte-identical to Node. What remains of the TDD: prototype-based pre-ES6
  "classes" (D1 Stage 4) and the separately-scoped implicit-`any` operator
  work ([TDD-00076](../tdd/TDD-00076.md)).
- Disclosed limits: top-level function declarations only (a nested/local
  function keeps the default + guard); identifier arguments resolve through
  top-level bindings only (a local-variable argument contributes nothing);
  `super(...)`/`.call`-style dispatch sites aren't collection sites.
- Verified on the Mac (arm64): 5 new E2E tests (13 in
  `tests/jsmode_test.go`), the wider class/function/generics regression
  suite green.
