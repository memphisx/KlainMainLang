# ADR-01015: Cluster fidelity closeout — live workers, json messages, listener lists, setupPrimary

- **Relations**: Extends ADR-01012 (module-level surface), ADR-00427 (worker IPC), TDD-00105, TDD-00141
- **Date**: 2026-09-18

## Context

ADR-01012 left fidelity caveats: exited workers stayed in `cluster.workers`
(Node deletes before emitting `'exit'`); no id-keyed lookup; `disconnect()`
dropped in-flight messages and took no callback; no `'listening'`/
`'disconnect'` cluster events; `setupPrimary`/`settings` absent; messages
were strings only; one listener per event (a cluster relay and a
`worker.on(...)` overwrote each other).

## Decision

- **Cross-runtime hooks**, armed by the cluster startup seed in every process
  (null and inert otherwise): `@__kml_cp_reaped_hook` fires from
  `__kml_cp_finalize` right after state 2 is set — BEFORE the exit/close
  listeners, so the registry drop is visible inside `'exit'` (verified
  against Node: `left: 1, 0`); `@__kml_cp_disc_hook` fires once per channel
  open→closed transition (drain EOF or explicit disconnect);
  `@__kml_cp_ctrl_hook` intercepts `"__kml:"`-prefixed control lines; and
  `@__kml_http_listening_announce` (its own shared ensure — either runtime
  can be emitted without the other) lets a worker's successful
  `bind_and_listen` announce `__kml:listening:<port>` over its channel.
- **Live registry.** The reap hook compact-shifts the parallel pid/Worker
  tables; `cluster.workers` is a snapshot copy of the live list (a worker
  exit mid-iteration would otherwise shift under the reader);
  `cluster.workers[id]` is Node's ID-keyed lookup (registry scan by `.id`,
  null when gone).
- **`cluster.disconnect([cb])`** drains each channel before closing (a
  kernel-buffered in-flight message is delivered, Node's flush; the drain's
  own EOF path is not double-fired) and runs the optional callback on the
  next microtask checkpoint.
- **`'disconnect'` and `'listening'` events** via the hooks; `'listening'`
  passes Node's `{ address, port, addressType }` object (a `ClusterAddress`
  annotation name context-types the listener).
- **`setupPrimary` (`setupMaster`)**: `args` replaces the workers' argv tail
  ([argv0, ...args], Node's `settings.args`); `silent: true` pipes worker
  stdio to `worker.process.stdout/stderr` (pipes made before the fork, read
  ends handed to the cp handle, write ends dup2'd in the child); the values
  read back as `cluster.settings`. `exec`/`execArgv` are a compile-time
  rejection — under the re-exec-self model there is no separate script file
  for a worker to run: a genuine impossibility of native compilation, per
  this project's faithfulness rule, not a deferral.
- **Object messages (Node's `json` serialization mode), both directions and
  both channel ends** (cluster AND `child_process.fork`): `send(x)` of a
  non-string JSON.stringifies and frames the value verbatim
  (`__kml_ipc_send_raw`); the wire distinguishes a quoted string line from a
  raw JSON value (`__kml_ipc_take2`'s isstr flag) so a user string that
  looks like JSON is never mis-parsed. The delivery ABI is
  `void(env, msg, i1 isstr)`; every `'message'` listener registers through a
  wire adapter (`cpMessageAdapter`) — an `any`-typed (now the untyped
  default: JS-faithful) parameter receives the sent value itself (boxed
  string, or the JSON parsed to a dynamic tree), `msg: string` keeps the
  plain-text fast path.
- **Listener lists.** The `'close'`/`'exit'`/`'error'`/`'message'` slots (cp
  fields 10/11/12/18) and the child-side `process.on('message')` global hold
  `{hdr, next}` lists appended in registration order (Node fires in order);
  finalize/drain iterate. Several `worker.on(...)` registrations and a
  cluster-level relay now coexist. Stream `'data'`/`'end'` slots and the
  other single-listener surfaces elsewhere are unchanged.

## Verification

- New `TestE2EClusterFidelitySurface` (delete-before-exit with live
  `workers.length` inside the listener, by-id hits and misses, object +
  string messages both directions with a typed reply, two worker-level exit
  listeners + the cluster relay in registration order) and
  `TestE2EClusterListeningAndSetupPrimary` (listening event with the address
  object over a real worker `http.createServer`, args in worker argv, silent
  captured via `worker.process.stdout`, `cluster.settings` readback).
- Cluster/ChildProcess/IPC/Fork/Spawn/Exec/Worker/Process/HTTP suites green.
  macOS arm64.
