# ADR-01956: Runtime Event matches the DOM Event, and dynamic `new` counts its arguments

- **Relations**: Implements TDD-00230 (P2.3)
- **Date**: 2026-10-29

## Context

The shadow report left `spawn('sleep', ['10'], { signal: ac.signal })` unanswered by the front end's checker: the runtime `AbortSignal` class (`lib/node/kml_event_target.ts`) did not relate to the global `AbortSignal` interface the spawn options declare. Its `Event` failed the DOM `Event` interface for two reasons:

- The checker widened a readonly field's literal initializer (`readonly NONE = 0` typed `number`), where tsc keeps the literal type, as it does for a const.
- The runtime `Event` had no `initEvent`, which Node's has.

Checking the new `initEvent` against Node exposed two more divergences:

- A missing `type` threw a plain `TypeError` without Node's `ERR_MISSING_ARGS` code.
- `new` through `any` reported `arguments.length` as the constructor's declared parameter count, not the count passed. It also dropped the overflow into a rest parameter.
- A derived class's implicit constructor passed its base the declared count rather than its own caller's count.

## Decision

- A readonly field, instance or static, keeps its initializer's literal type. A non-readonly field still widens.
- `Event.initEvent(type, bubbles?, cancelable?)` follows Node: it is a no-op during dispatch, and `type` is required. Both it and the constructor throw `ERR_MISSING_ARGS`.
- The dynamic construct arm caps `argc` at the regular parameters and stores it as the callee's count. Arguments past the regular parameters fill the rest parameter, built from `argv` the way the method shape adapter builds one.
- The synthesized pass-through constructor forwards the count its caller stored to `super(...)`.

## Builtin data-shape generics

The same report left calls returning `IteratorResult<T, R>` unanswered when they initialized a binding. The front end's representation step mapped a program's instantiated generic interface to its members, but excluded every builtin one. Codegen instantiates a builtin generic interface that is only a data shape (fields, no methods, index, call signatures or heritage: `IteratorYieldResult<T>`) as it does a program's own (`registerAmbientGeneric`). The representation step now applies the same test, through one shared predicate (`ambientDataShape`).

## TextEncoder's result

`crypto.subtle.importKey("raw", new TextEncoder().encode(…), …)` was unanswered too. The runtime `TextEncoder.encode` declared `Uint8Array` (that is, `Uint8Array<ArrayBufferLike>`), which does not fit the `BufferSource` overload's `ArrayBufferView<ArrayBuffer>`. Node's declaration, and this project's own `node.d.ts`, return `Uint8Array<ArrayBuffer>`; the runtime class now declares the same.

## Consequences

- `examples/crypto/crypto.ts` reports no disagreement, and its output still matches Node.
- Probes over `IteratorResult` bindings and `then` callbacks report no disagreement.
- The runtime `AbortSignal` relates to the global interface, and the spawn call is answered.
- `TestE2EEventInitEvent` and `TestE2EDynamicConstructArgumentCount` match Node (Mac).
