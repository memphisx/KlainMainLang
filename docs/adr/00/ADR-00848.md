# ADR-00848: `indexOf(x, fromIndex)` — the optional start-offset argument

- **Relations**: Extends `indexOf` ([ADR-00843](ADR-00843.md) `lastIndexOf`, [ADR-00558](ADR-00558.md) buffer path)
- **Date**: 2026-09-10

## Context

`String.prototype.indexOf` and `Array.prototype.indexOf` rejected the standard
second argument, `fromIndex` ("indexOf takes exactly 1 argument"). `"…".indexOf(
"o", 5)` and `arr.indexOf(x, 2)` are common.

## Decision

- **String**: a new runtime `__kml_str_indexof_from(hay, needle, from)` clamps
  `from` to `[0, len]`, runs `memmem` over the suffix, and returns the absolute
  byte offset or -1. `emitStringIndexOf` accepts 1 or 2 args.
- **Array**: `emitArrayIndexOf` starts its scan at the (clamped) `fromIndex` — a
  negative index counts from the end (`from + len`, clamped to 0), matching JS.
- **`String.includes(x, position)`** reuses `__kml_str_indexof_from` (the search
  starts at `position`, then `>= 0`).
- **`String.startsWith(x, position)`** / **`String.endsWith(x, endPosition)`** —
  new `__kml_str_startswith_at` / `__kml_str_endswith_at` (bounds-checked memcmp
  at the offset / ending at endPosition; out-of-range → false).

## Implementation notes

`runtime_strheader.go` (`__kml_str_indexof_from`); `emit_strings.go`
(`emitStringIndexOf`); `emit_arrays_search.go` (`emitArrayIndexOf` start-offset).

## Side effects discovered

All the sibling position arguments are closed here: `includes(x, position)`,
`startsWith(x, position)`, `endsWith(x, endPosition)`, and
`lastIndexOf(x, fromIndex)` — the last a backward scan from
`min(fromIndex, len-needleLen)` via `__kml_str_lastindexof_from`.

## Verification

macOS (Apple Silicon M4): matches Node — `"Hello, World".indexOf("o", 5)` → 8,
`"aaa".indexOf("a", 1)` → 1, out-of-range `from` → -1; `[1,2,3,2].indexOf(2, 2)`
→ 3, a negative `from` (`[1,2,3,2,1].indexOf(1, -2)`) → 4. New
`TestE2EStringIndexOfFromIndex`/`TestE2EArrayIndexOfFromIndex` + the string/array/
buffer suites green.
