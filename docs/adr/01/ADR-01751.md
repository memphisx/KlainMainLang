# ADR-01751: A static method's `this` reads the class's statics

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-19

## Context

`class T { static v = 5; static next() { return ++this.v; } }` failed with invalid IR: "'%t5' defined with type 'double' but expected 'i64'". Codegen rewrites a static member's `this` to the class's name (`staticThisToClass`). The front end could not resolve that synthesized identifier, so it missed the rule that reads a class value's statics as declared, and answered `this.v` as a box. The update stepped a box while the read produced the static field's double.

The same shadow-report pass turned up further disagreements:
- the rows of a nested js array literal kept only the null absence;
- an unannotated binding of such a row read held the checker's plain array;
- `NodeJS.*` types took a program interface's layout, with its presence word;
- an immediately invoked generator had no answer;
- a function value's property other than its own (`f.toString`) took the checker's method type, though codegen reads it off the boxed function;
- a body whose type the checker gives but `reprOf` cannot name had no answer either.

## Decision

- The front end counts a static member's rewritten `this` as the class itself (`localClassValue`), so its statics read as declared.
- A row of a nested js literal sets its absence nullable first, then undefined. Setting undefined on a non-nullable type is a no-op, so the old order lost it.
- An unannotated js binding of such a row read, including a `var` declared again (its first declaration's global), holds the read.
- `NodeJS.*` annotations and interfaces take `nodeJSNamespaceType`'s builtin layout.
- An immediately invoked generator function expression is a box, and so is a function value's property other than its own (`funcValueProp`).
- A return type `reprOf` cannot name falls back to what the returns read as.

## Consequences

- `++this.v` and `this.v--` in a static method work, called directly and through a boxed class value.
