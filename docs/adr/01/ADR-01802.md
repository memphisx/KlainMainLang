# ADR-01802: Array override results are not species instances; builtins skip override dispatch

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- Two bugs in programs with a class that extends Array and overrides one of its methods:
- A call through a value typed as a plain array (`const a: string[] = r; a.map(f)`) runs the override (`emitArrayOverrideDispatch`). The species rule around it (`arrayBodySpeciesRule`) then rebuilt the override's own result as an instance of the receiver's class: `R(1) [ 'over' ]` where Node prints `[ 'over' ]`.
- `Array.from` used as a value is emitted from its intrinsic, and that intrinsic's internal `map` went through the override dispatch. The callback's capture cells were emitted in one arm and reused in the other, so clang rejected the IR ("Instruction does not dominate all uses"). This showed up in any such program that inspects a value, because inspect pulls in `Array.from`.

## Decision

- The species rule's class branch excludes instances of classes that override the method. Those instances return what their override returns.
- A builtin function's body is emitted with the override dispatch off. Node's builtins use Array's own methods, never a subclass's.

## Consequences

- `TestArraySubclassOverrideResultNotSpecies` and `TestArraySubclassOverrideArrayResultDynamic` cover both.
