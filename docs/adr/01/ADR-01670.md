# ADR-01670: The loop computes no deadline of its own

- **Relations**: Implements TDD-00244
- **Date**: 2026-10-17

## Context

`pass_wait` (loop.c) bounded each pass's wait itself. It scanned the connection table for fibers parked on a fetch whose AbortSignal had an `AbortSignal.timeout` deadline. It also capped the wait at 200 ms in a cluster worker, so the worker would poll the primary's shared close flags. Both are deadlines the loop worked out by predicate instead of holding as libuv handles.

## Decision

- **Fetch deadlines.** The scan is deleted. `AbortSignal.timeout` already arms a libuv timer, unreferenced, that aborts the signal. `uv_run`'s wait is bounded by every timer in the heap, referenced or not, so that timer wakes the loop. Its callback sets `#aborted` before the pass resumes the parked fibers.
- **Cluster flags.** A cluster worker gets an unreferenced 200 ms repeating `uv_timer_t` that only wakes the loop. The pass still runs `cluster_poll`, as before, so the listener closes outside libuv's callbacks.
- **The wait.** A pass now waits 0 when work is runnable, else until an event. `__kml_loop_next_ms` (the webview embedding) is `uv_backend_timeout`.

## Side effects discovered

A probe of a handler's fetch timing out found a pre-existing bug. The error escaped the handler: ADR-01671.

## Verification

- AbortSignal, fetch-abort, fetch-timeout and cluster tests pass on Mac.
- New test `TestE2EFetchTimeoutSignalInHandler` passes on Mac.
