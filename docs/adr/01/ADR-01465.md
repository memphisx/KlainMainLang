# ADR-01465: Thenables adopted through their `then`

- **Relations**: Extends ADR-00271
- **Date**: 2026-10-07

## Context

A value with a callable `then` is a thenable: the spec's promise resolution
(`await x`, `Promise.resolve(x)`, a combinator's member, a reaction's
result, an `async` function's `return x`, `resolve(x)`) calls
`x.then(resolve, reject)` from a job (NewPromiseResolveThenableJob) and
settles the promise with what it passes. Here only a typed `Promise` was
adopted: `await new T(21)` for a class `T` with a `then` method gave the
instance itself, and `then` was never called. Found while working out how
`await` must treat an instance of a class extending Promise (TDD-00247
stage 3), whose constructor is not `%Promise%`, so Node adopts it the same
way.

## Investigation

- `emitAwait`, `emitPromiseResolve`, the combinators' member wrapping
  (`wrapValueMembers`), `emitPromiseThen` and the async `return` path each
  treated a non-promise as a fulfilled value; `resolve(x)` adopted only a
  `Promise`-typed argument (emit_func.go).
- A value held in `any` resolves through `__kml_promise_resolve_any`
  (anyprom.c), which recognized only a boxed promise wrapper.
- tsc types `await x` as the parameter type of `then`'s first callback
  (Awaited); codegen's inference gave the class type, so a binding of the
  result was sized for a pointer.

## Decision

- A thenable is a class instance whose class declares or inherits `then`,
  or an object value whose `then` member is a function (`thenableClass`);
  its fulfillment type is its first callback's first parameter.
- `emitThenableToPromise` makes a pending promise and queues a job, `()
  => { try { x.then(res, rej) } catch (e) { rej(e) } }`, with `res`/`rej`
  the promise's resolving closures; a `then` declaring fewer parameters is
  passed fewer arguments, as JavaScript ignores the rest.
- Each resolution site converts a thenable through it: `await`,
  `Promise.resolve`, the combinators' members, `resolve(x)` (then adopted
  as a promise is), an `async` return (awaited, as a returned promise is),
  and a `.then`/`.catch` callback whose result is a thenable (wrapped to
  return the adopting promise, `__kml_thenable_resolve`); the type side
  (`inferExprType`, `promiseStaticType`, an async function's inferred
  return) takes the fulfillment type.
- `__kml_promise_resolve_any` reads the `then` of a boxed static object or
  dynamic bag and, when it is a function, queues a job calling it with
  resolving functions whose first call wins; a throw before either is
  called rejects.

## Implementation notes

`codegen/llvm/emit_thenable.go` (new), `emit_async.go`, `emit_promise.go`,
`emit_promise_then.go`, `emit_func.go`, `emit_stmts.go`, `emitter.go`,
`emit_exprs_types.go`, `emit_call.go`, `emit_anyprom.go` (the promise
runtime now links the object hooks it reads `then` through),
`promisesrc/anyprom.c`.

## Side effects discovered

None open.
