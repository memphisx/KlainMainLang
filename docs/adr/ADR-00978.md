# ADR-00978: `AbortSignal.onabort` event-handler property

- **Relations**: Extends ADR-00236; Implements TDD-00081
- **Date**: 2026-09-16

## Context

`AbortSignal` already behaved as an EventTarget that fires `"abort"` —
`signal.addEventListener('abort', cb)` worked (ADR-00236) — but the WHATWG
`onabort` event-handler property (`signal.onabort = cb`) was unsupported
(docs/BACKLOG.md §3, surfaced by the WPT track ADR-00871). Assigning it was a
plain member store into a non-existent field, so the handler never fired. In the
DOM `onabort` is simply another listener slot invoked alongside the
`addEventListener` listeners when the signal aborts.

## Investigation

- `codegen/llvm/emit_abort.go` — the whole AbortController/AbortSignal emit
  surface; `emitAbortControllerAbort` (line 42) marks the signal aborted, records
  the reason, and dispatches an `"abort"` event to the signal's listener map via
  `emitDispatchToMap`.
- `codegen/llvm/emit_eventtarget.go:241` — a listener is invoked as
  `Callback{kind: cbClosure, hdrPtr: listenerPtr, ty: FuncType([Event], void)}`
  through `emitCBCall`. `resolveEventTargetListenerArg` (line 19) compiles the
  listener with an Event-typed param hint and an arity check (0 or 1 param).
- `codegen/llvm/types.go:1546` `AbortSignalType()` — a heap `ObjectType`
  `{aborted, reason, listeners, deadlineNs}`. `ensureSignalAborted`
  (`emit_abort.go`) hardcodes field 0 (`aborted`) and field 3 (`deadlineNs`).
- Existing `on<event>` precedent: EventSource keeps `onmessage`/`onopen`/`onerror`
  as nullable `ptr` field slots (`emit_eventsource.go:50`); Worker/BroadcastChannel
  intercept the assignment in `emit_exprs_assign.go`.

`AbortSignal.timeout(ms)` aborts lazily (`__kml_signal_aborted` latches the flag
when awaited) with no listener dispatch, and static `AbortSignal.abort()` returns
an already-aborted signal that never dispatches — so, exactly as for
`addEventListener('abort')` listeners, `onabort` fires only on a live
`controller.abort()`. This is not a new limitation introduced here.

## Decision

Model `onabort` as a field slot (EventSource pattern) fired inline in the abort
dispatch (AbortSignal's dispatch is compile-time-emitted, not a runtime function):

1. Append `onabort` (a nullable `ptr`) as the **last** field of `AbortSignalType()`
   — after `deadlineNs` — so the field-0/field-3 indices `ensureSignalAborted`
   relies on stay valid.
2. Initialize it to `null` in all four construction sites (`new AbortController`,
   `AbortSignal.timeout`, static `AbortSignal.abort`, `AbortSignal.any`) — an
   uninitialized slot would fire a garbage pointer.
3. Intercept `signal.onabort = cb` in `emit_exprs_assign.go`
   (`emitAbortSignalOnabortAssign`): resolve the listener through
   `resolveEventTargetListenerArg` (same Event hint + arity check as
   addEventListener) and store its closure header into the field; `= null` clears
   it, and a re-assignment replaces it (field-store semantics match the IDL
   "replace" rule for free).
4. In `emitAbortControllerAbort`, fire `onabort` (`emitFireOnabort`: load, null-
   check, `emitCBCall`) **before** the addEventListener listeners, sharing the one
   `abort` event object — so a `stopImmediatePropagation()` in `onabort` suppresses
   the rest (`emitDispatchToMap` re-reads the stop flag each iteration).

Interception is used rather than the generic member store because the generic
path would not apply the Event-typed param hint an arrow/function listener needs.

## Implementation notes

- Files: `codegen/llvm/types.go`, `codegen/llvm/emit_abort.go`,
  `codegen/llvm/emit_exprs_assign.go`.
- Ordering constraint: `onabort` must be the last field (indices 0 and 3 are
  hardcoded in the `__kml_signal_aborted` runtime template).

## Side effects discovered

None. Remaining AbortSignal gaps are unchanged: `instanceof` against the ambient
`AbortSignal` class (BACKLOG §3), `AbortSignal.any` live propagation, and a
custom `controller.abort(reason)` value not surfacing through an awaited fetch.
