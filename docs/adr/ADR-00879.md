# ADR-00879: TS oracle — multi-file cases materialized, not skipped

- **Relations**: `Implements TDD-00204`, `Extends ADR-00459`
- **Date**: 2026-09-11

## Context

The TypeScript acceptance oracle skipped every case containing
`// @filename:` directives as "out of scope for the single-entry V1" — a
large bucket, despite the compiler resolving multi-file imports natively
(the resolver merges an entry's import graph into one program).

## Decision

`runOneTS` materializes a multi-file case: each virtual file is written under
a per-case scratch dir (wiped per case; the TS lane is single-threaded), and
the **last implementation file** (`.ts`/`.tsx`, not `.d.ts`) compiles as the
entry — TypeScript's own convention that later files consume earlier ones.
The case is then classified exactly like a single-file one against its
`.errors.txt` baseline. Declaration-only multi-file cases remain a named
skip. Cases whose files interact only via script-mode global merging (no
imports between them) reject and are counted — an honest disagreement with
TypeScript's whole-program compilation model, visible in the false-reject
histogram, not hidden in a skip bucket.

## Consequences

Thousands of formerly skipped cases enter the classified denominator; the
agreement percentage moves accordingly and the false-reject reasons now
include the multi-file shapes worth implementing (script-global merging is
expected to dominate initially). Regenerate with `make conformance-ts`.
