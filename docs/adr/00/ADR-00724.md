# ADR-00724: String comparison against a missing value (`process.env.X === "a"`) segfaulted

- **Relations**: Extends [ADR-00722](ADR-00722.md) (found while running the Windows suite for it); relates to [ADR-00487](ADR-00487.md) (`process.env` semantics)
- **Date**: 2026-09-06

## Context

`TestE2EOSHomedirMatchesEnvHOME` failed with `0xC0000005` on Windows only
when `go test` was launched from PowerShell, and passed from Git Bash. The
test compares `os.homedir()` (which reads `USERPROFILE` on Windows) with
`process.env.HOME`; PowerShell does not set `HOME`, so the right-hand side
was a missing variable. A two-line repro segfaulted on Linux as well:

```ts
console.log("a" === process.env.KML_DEFINITELY_UNSET_VAR)
```

## Investigation

A missing `process.env` entry is the null pointer that this compiler uses
as its `undefined` stand-in for string-typed values (documented in the
`process.env` status row). `emitStringBinary` in `emit_strings.go` emits
`__kml_str_cmp(lhs, rhs)` for every comparison operator on two `ptr`
operands; `__kml_str_cmp` reads the TDD-00120 length header at `ptr - 8`,
so a null operand is a read at address `-8`. Nothing upstream guarded it:
the env read returns `ptr` typed as a string, and the comparison never
checked for null. Any nullable string reaching `==`/`===`/`<`… had the same
exposure (`.find()`'s possibly-null convention, for example).

JS semantics to match: `undefined === undefined` is `true`; `undefined`
compared with any string is `false` for `==`/`===` and `true` for
`!=`/`!==`; every ordering comparison involving `undefined` is `false`
(the operand becomes NaN).

## Decision

`emitStringBinary` is null-aware for the comparison operators: it tests
both operands for null, substitutes `""` for a null before calling
`__kml_str_cmp` (so the compare never dereferences one), and then selects
the result: both null → equal; exactly one null → not equal and every
ordering false; neither → the compare's result. No branches, three
`select`s. `__kml_str_cmp` itself is unchanged.

`TestE2EOSHomedirMatchesEnvHOME` now compares against `USERPROFILE` on
Windows, which is what `os.homedir()` reads there.

## Implementation notes

- `codegen/llvm/emit_strings.go`: the null handling in `emitStringBinary`.
- `tests/process_test.go`: `TestE2EProcessEnvMissingCompare` covers
  equality, inequality, both-missing, `=== undefined`, ordering, and a
  bound variable.
- `docs/status/data/process-cli.json`: the `process.env` caveat now states
  the comparison semantics; the `null`-not-`undefined` representation and
  the `typeof` divergence remain caveats.

## Side effects discovered

- `console.log(process.env.MISSING)` prints `null` where Node prints
  `undefined`; already a documented caveat of the representation, not
  changed here.

## Verification

- Repro above (five comparisons incl. `=== undefined` and a bound variable): identical output to Node v24 on Windows 11 and Linux (WSL2) after the fix; segfault before, on both.
- `go test -run 'TestE2EOSHomedir|TestE2EProcessEnv' ./tests` passes on Windows and Linux.
