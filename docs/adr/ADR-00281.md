# ADR-00281: Async ordering fixes from a conformance/node-diff sweep — non-promise `await` ticks, absent `.then` callbacks, `for await` suspension classification

- **Relations**: Extends [ADR-00268](ADR-00268.md) (await-tick model / TDD-00088), [ADR-00248](ADR-00248.md) (`.then` reactions); corrects a premise recorded in [ADR-00275](ADR-00275.md) (see Side effects); extended by [ADR-00283](ADR-00283.md), which closes the disclosed async-generator divergence
- **Date**: 2026-08-21

## Context

A targeted sweep for further async/Promise gaps: the Test262 conformance runner
re-run per async category (`-category built-ins/Promise`, `language/expressions/await`,
`language/statements/for-await-of`, the async-function/generator categories) with
`-faillist`, hunting `RUNTIME_NONZERO_EXIT` entries (tests that compiled but gave
a *wrong answer*, the dangerous class) — plus an ordering battery of small
programs diff'd against node v26.3.0 (the same source run through both).

## Investigation

Three genuine ordering/semantics bugs surfaced:

1. **`await <non-promise>` ran fully synchronously.** `emitAwait`'s identity
   guard returned the value with no tick, so `f(); log("c")` where `f` awaits a
   plain value printed `a b c` — JS prints `a c b` (every await defers its
   continuation). The status row's "every await yields a microtask tick" claim
   was true only for promise operands.
2. **`.then()` with no argument, or an `undefined`/`null` callback slot, was a
   compile error** ("then expects at least 1 argument") — JS treats an absent
   onFulfilled as a pass-through (`p.then().then(g)`, and `.then(undefined, onR)`
   is the `.catch` shape). The runner already had the pass-through block; only
   the emitter's arity handling rejected it.
3. **A `for await...of` loop did not classify its enclosing async fn as
   may-suspend** (`stmtSuspend`'s `ForOfStatement` case never looked at
   `st.Await`), so an async fn whose only awaits were the loop's implicit ones
   ran the *whole loop synchronously* before the top-level script continued —
   node suspends at the first element (node-diff case c7).

## Decision

1. In `emitAwait`'s non-promise branch, when inside an async fn compiled
   alongside tasks (`e.isAsync`, not a generator body, `hasMaySuspend`): wrap
   the value in a freshly-allocated *settled* task promise (raw fulfilled store
   — no reactions can exist yet) and go through `emitAwaitTaskPromise`, whose
   `__kml_task_await_ready` park-and-resume-as-microtask is exactly the tick
   ([TDD-00088](../tdd/TDD-00088.md)). Value semantics unchanged (identity);
   only the continuation is deferred, as in JS. Outside a task context (an
   async generator's fiber has no current task) the identity return stands.
2. `emitPromiseThen`: the arity error is gone; a missing/`undefined`/`null`
   `then` callback leaves `onF` null (runner pass-through) with the returned
   promise typed to the source's value type; an absent second slot leaves `onR`
   null (propagation).
3. `stmtSuspend`: `case *ast.ForOfStatement` now returns true for `st.Await`.

## Implementation notes

- `codegen/llvm/emit_async.go` (identity branch), `emit_promise_then.go`
  (`isAbsentCallback` — a `NullLiteral` covers both `undefined` and `null`),
  `emit_task_classify.go`.
- Fix 1's wrapper allocates one 40-byte promise per non-promise await — the
  ambient leak profile every promise already has (collected under `-mm=gc`).

## Side effects discovered

The node diff also exposed **async-generator step-timing divergences** — found,
verified against node, and *disclosed* (not fixed here; the fix is a redesign of
the generator-fiber/await fusion, the subsystem with the ADR-00274/275 deadlock
history, and a half-measure would only trade divergences):

- **[ADR-00275](ADR-00275.md)'s premise is contradicted by V8/node**: node runs
  an async generator's body **synchronously at `.next()` up to the first
  `await`/`yield`** (`console.log("before"); g().next(); console.log("after")`
  with a logging body prints `before body after` on node v26.3.0); this
  compiler defers the whole body start to a microtask (printing
  `before after body`, which that ADR recorded as the JS ordering).
- An `await` **inside** an async generator body drives inline within the fiber
  (the [ADR-00253](ADR-00253.md) fusion) rather than suspending the step back
  to the consumer, so body-side effects around an await do not interleave with
  consumer-side microtasks the way node's do; relatedly, `await <plain value>`
  inside a body yields no tick (fix 1 deliberately excludes generator bodies).

Both are now caveats on the async-generators status row (Async/Promise Strict
9/9 → 8/9). Matching node exactly needs: synchronous body start *plus*
park-at-await (swap the fiber back to the consumer with the step promise left
pending, resume via a reaction) *plus* request-queueing for `.next()` during a
parked step — one coherent redesign, not three patches.

## Verification

- Node-diff battery (8 programs: microtask-vs-timer order, then-chain/await
  interleave, executor timing, catch/finally, `Promise.all`, double
  non-promise await, for-await over promises, timer-deferred executor):
  all `SAME` vs node v26.3.0 after the fixes (macOS, Apple Silicon).
- New E2E: `TestE2EAwaitNonPromiseYieldsTick` (`a c b`),
  `TestE2EThenAbsentCallbacksPassThrough` (`.then()`, `.then(undefined, onR)`,
  `.then(null)` chaining); node-diff case c7 covered by the classifier fix.
- `go build`, `go vet ./...`, full `go test ./...` green; `make examples` and
  the async conformance categories re-run at delivery (see [ADR-00282](ADR-00282.md)
  for the category deltas).
