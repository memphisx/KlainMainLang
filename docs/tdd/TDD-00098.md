# TDD-00098: `Worker` (background-thread concurrency) — revised design

- **Status**: Implemented
- **Date**: 2026-08-22
- **Relations**: Supersedes [TDD-00047](TDD-00047.md)

## Context

Supersedes [TDD-00047](TDD-00047.md), which scoped `Worker` correctly but predates a large stretch of shipped work and left the hardest design pieces as open questions. What still stands from it is carried forward here unchanged: message-passing-only V1 scope (`SharedArrayBuffer`/`Atomics` deferred, still not designed), Node `worker_threads` shape first with the browser ambient `Worker` global as a later stage, `pthread_create`/`pthread_join` as the mechanism with one event-loop instance per thread, and the four confirmed blockers (process-global exception state, Boehm stack-bottom tracking, first-ever `-pthread` link, unverified libcurl handle lifecycle across threads).

What made a superseding document necessary rather than a status bump:

- Its prerequisite table lists structured-clone deep-copy codegen as "Not built." It has since shipped ([ADR-00113](../adr/ADR-00113.md), `codegen/llvm/emit_structured_clone.go`) — a static-type-driven, compile-time-unrolled deep copy with compile-time rejection of non-cloneables. That is exactly the `postMessage` copy machinery, so the boundary-copy design collapses to reuse.
- It designs `worker.on(...)` around `EventEmitter`'s then-limitation of one payload type per instance. Per-event payload typing has since shipped ([ADR-00303](../adr/ADR-00303.md)), so `'message'`/`'error'`/`'exit'` can each carry their own payload type with no workaround.
- The event loop it plans to instantiate per thread has since been unified and substantially extended (unified loop [ADR-00250](../adr/ADR-00250.md), microtask FIFO, promise-reaction draining, stream/request-body pumps, curl multi integration). The per-thread state audit below re-inventories the singletons against the current runtime, and the list is much longer than the three items TDD-00047 found.
- Four load-bearing designs were left open there and are settled here: worker-entry compilation, the per-thread-state strategy, message-channel mechanics, and channel typing.

Tracked in [docs/status/CONCURRENCY-WORKERS.md](../status/CONCURRENCY-WORKERS.md) (0/3 today).

## Design

### Carried forward (settled in [TDD-00047](TDD-00047.md), unchanged)

- **Scope**: message-passing only; every sent value is deep-copied at the boundary, nothing is shared. `SharedArrayBuffer`/`Atomics` deferred, not designed.
- **API**: `import { Worker } from 'worker_threads'; new Worker(path, { workerData })`, `Worker` composing on the `EventEmitter` machinery for `.on('message'|'error'|'exit')`; the worker side imports `parentPort`/`workerData` from the same module. Browser ambient `Worker` global (a documented exception to [TDD-00049](TDD-00049.md)'s import gating) as the final stage.
- **Mechanism**: `pthread_create` per worker, declared via the usual `ensure*()` pattern; each thread runs its own instance of the fiber-based event loop; `-pthread` added to the clang invocation.

### Worker-entry compilation: an extra entry in the same binary

`new Worker(path)` requires `path` to be a **compile-time string literal**, resolved relative to the importing file. A non-literal path is a compile error (there is no interpreter to load code at runtime — same posture as the `eval` rejection), as is a worker spawning nested workers in V1.

The resolver resolves the worker file (plus its imports) as an additional entry, kept as a separate statement list on the program (`Program.WorkerModules`, keyed by file index) rather than merged into the main statement stream. The existing per-file name mangling already guarantees cross-file-unique symbols, so no new renaming is needed. `EmitProgram` emits each worker module's top-level statements into `define void @__kml_worker_entry_<fileIdx>(ptr %ctrl)` using the same alloca/body builder-swap seam every emitted function already uses (`emit_func.go`). One binary, no `fork`/`exec`, statically typed end to end.

### Per-thread runtime state: `thread_local global`

Every per-loop runtime singleton becomes an LLVM `thread_local global`. TLS keeps the same `@name`, so the change is declaration-site-only — call sites are untouched — versus a loop-context struct that would touch hundreds of sites. clang lowers `thread_local` on both ELF and Mach-O targets.

Full inventory (re-audited against the current runtime):

Intentionally **shared**: module globals `@__kml_global_*` and `@__argv_*`. Workers may read them; mutation is unsynchronized and documented as such.

### Message channel: mutex-guarded linked FIFO per direction + self-pipe wakeup

Each `new Worker(...)` allocates a control block:

```
%kml.worker = { pthread_t tid,
                in-queue  {head, tail, mutex},   ; parent → worker
                out-queue {head, tail, mutex},   ; worker → parent
                pipe parent→worker (2 fds), pipe worker→parent (2 fds),
                terminate flag, exited flag, exit code,
                workerData clone ptr, parent-side EventEmitter listeners ptr }
```

`postMessage` (either direction): deep-clone the payload via the existing `emitDeepClone` into fresh malloc'd memory, append a node `{ptr next, <payload>}` under the queue mutex, write one byte to the peer's pipe. Both sides run the same `select()`-based event loop, so the pipe read-fd folds into the fdset exactly like the curl fds already do; on readable, drain the queue and dispatch each message through the existing EventEmitter listener machinery. No condition variables needed — the pipe is both the wakeup and the loop-integration point.

Exit protocol: the worker's top level returns and its loop drains → set exited flag + exit code, write a final wake byte → the parent emits `'exit'` and `pthread_join`s. `worker.terminate()` sets the terminate flag + writes a wake byte; the worker's loop checks the flag at the top of each iteration (and at fiber-yield points) and unwinds cooperatively — never `pthread_cancel`.

### Channel typing: the worker file declares, the parent is checked

No generics, no runtime type tags (values have none). Single message type per direction, per worker file:

- Inbound (parent → worker): the annotated handler `parentPort.on('message', (msg: In) => ...)`.
- Outbound (worker → parent): inferred from the worker's first `parentPort.postMessage(...)`.
- `workerData`: an annotation in the worker, e.g. `const cfg: Cfg = workerData`.

Worker modules are type-registered before `main` is emitted, so the emitter records `{inTy, outTy, dataTy}` per worker path and checks every parent-side `worker.postMessage(...)`, `.on('message', ...)`, and `workerData` argument against it. Cloneability restrictions are exactly `structuredCloneUnsupportedKind`'s existing compile-time rejections (functions/closures, class instances, `Map`/`Set`, `Promise`, ...).

### Error and mode semantics

- Uncaught exception on a worker thread terminates that worker only and emits `'error'` on the parent `Worker` object (depends on the `thread_local` exception fix).
- `-mm=manual` + `Worker` is allowed; the compounding leak risk of long-running workers is documented, not restricted. `-mm=gc` + `Worker` is a clean compile error until the GC stage lands (`GC_register_my_thread`/`GC_unregister_my_thread` with a per-thread `GC_stack_base`, reconciled with the fiber stack-bottom-repointing trick per thread).
- Fork-clustering (`http.listen({workers: N})`) combined with `Worker` threads is a compile-time rejection for V1 (fork + threads is a known-hazardous mix).

### Staging

1. **TDD reconciliation** — this document; [TDD-00047](TDD-00047.md) marked Superseded.
2. **Throwaway prototypes** (committed nowhere): hand-written `.ll` files compiled with the exact clang invocation — `thread_local` from two pthreads (Mach-O TLS), TLS setjmp-stack with concurrent try/throw/catch, ucontext fibers created and swapped on a non-main pthread, and `GC_register_my_thread` + `GC_malloc` on a spawned thread. Abort/redesign points live here.
3. **Spawn/join + copy-only `postMessage`**, `-mm=manual` only: resolver + parser + `emit_worker.go` + `runtime_worker.go` + the TLS conversion + loop integration + `-pthread`.
4. **`-mm=gc` support**: per-thread GC registration; lift the stage-3 restriction.
5. **Error/termination semantics**: cooperative `terminate()`, worker `'error'`/exit codes.
6. **Browser ambient `Worker` global**: `postMessage`/`onmessage`/`onerror` property convention over the same mechanism.

## Open questions

- Whether a `MessageChannel`/`MessagePort` pair (the third row of the status page) falls out of the same control-block design or needs its own — deferred until the `Worker` stages are done.
- `BroadcastChannel` semantics across N workers (fan-out copy per subscriber) — deferred likewise.
- `SharedArrayBuffer`/`Atomics` — still deferred, still not designed.
