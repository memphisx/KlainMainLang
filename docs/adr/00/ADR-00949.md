# ADR-00949: Self-referential interfaces and object-shape type aliases

- **Relations**: `Extends ADR-00946` (the class-side self-ref fix, TDD-00213 bundle)
- **Date**: 2026-09-15

## Context

A self- or mutually-referential **interface** (and object-shape `type` alias)
failed at compile time, while the equivalent `class` shape worked (ADR-00946):

```ts
interface N { children: N[]; val: number }
const r: N = { children: [c], val: 1 }   // "element 0 does not match the array's element type"

interface M { next: M | null; val: number }
const a: M = { next: b, val: 1 }
a.next!.val                              // "field access on non-object (no field 'val')"
```

Both trace to one root: `registerInterfaces` resolves each interface's field
types eagerly, in declaration order, *before* the interface's own name is
registered. A self-reference (`N` inside `N`'s fields) therefore resolves to
nothing — defaulting to the numeric `i64` element (so `N[]`'s element IR is
`i64`, not `ptr`, and the array-literal homogeneity check rejects a real `N`
element) or to an empty field list (so a second drill `a.next.val` finds no
field).

The class case solves this with two ingredients (ADR-00946 + TDD-00009): a
Pass 0 that seeds a **named placeholder** before any field is resolved, and
`canonicalizeClassTy`, which re-resolves a class-typed field's stale by-value
snapshot through the live `e.classes` registry **on demand** at each drilling
access — keyed by the nominal `ClassName`. Interfaces are structural
`ObjectType`s with no nominal name, so neither ingredient applied.

## Decision

Give named structural types the same two ingredients, without borrowing the
class machinery:

- **`Type.RefName`** (new): a nominal re-resolution handle set on the
  `ObjectType` registered in `e.interfaces` for a plain interface or an
  object-shape `type` alias. It never implies `IsClass` and drives no method
  dispatch / `instanceof` / decorator-metadata / monomorphization — those all
  gate on `IsClass` or read `ClassName`, which `RefName` never sets.
- **`registerInterfaces` Pass 0**: seed every plain interface and object-shape
  alias name with an empty `ObjectType` placeholder carrying `RefName`, before
  any field is resolved. A self/forward reference now resolves to a real
  ptr-shaped named type instead of the numeric default, fixing the array-literal
  homogeneity rejection. The final full type keeps `RefName` set (at the main
  store, the `extends`-merge store, and the alias store).
- **`canonicalizeClassTy`**: a new branch re-resolves a `RefName`-tagged object
  type whose snapshot has empty `Fields` through the live `e.interfaces` entry
  (preserving the caller's `Nullable`/`IsUndefined`/`IsNull`), and its array
  branch recurses into a `RefName` element type as well as an `IsClass` one.
  Every drilling site already routes field-read types through
  `canonicalizeClassTy` (emitMember / emitOptionalMember / inferExprType), so no
  new call sites are needed.

Index-signature and call-signature interfaces are non-structural and excluded;
generic interfaces/aliases stay on the on-demand-instantiation path unchanged.
