# ADR-01003: faithful `Promise.allSettled` reason via a boxed-object Error type-id

- **Relations**: Implements TDD-00169 (the faithful arbitrary-value reason) and TDD-00222 (the boxed-object type-id it builds on), Supersedes ADR-01002's real-errorObjType reason slot
- **Date**: 2026-09-18

## Context

ADR-01002 removed the `.reason.message`-on-an-Error segfault by keeping
`SettlementType.reason` typed `errorObjType` and always storing a real Error
there. That fixed the crash but left the value infidelity TDD-00169 is about: a
non-Error reject value was still coerced — `Promise.reject(42)` gave
`typeof reason === "object"` and `JSON.stringify` rendered `"42"` (Node: the
number `42`), and an Error reason's JSON was its message string, not Node's
`{}`. The faithful move (`reason: any`, carrying the original value) was blocked
because a caught Error boxed into `any` becomes a bare `kmlTagObject` whose Error
shape can't be recovered at a general render/JSON/member site — the box tag
space is full and an `errorObjType`'s field-0 `kind` collides with a class
instance's field-0 `__kml_tag`.

## Investigation

- The missing primitive was a **boxed-object type-id**: one runtime
  discriminator, at the only offset in-bounds on any boxed object (field 0),
  that recognises an Error. Designed in TDD-00222.
- `errorObjType`'s `kind` and a class's `__kml_tag` are the only field-0 values;
  both are read *only* by equality compares (no runtime path indexes
  `errorKinds[kind]` — `emitErrorToString` reads the stored `name` string), so
  a marker bit in field 0 needs no masking on the read side, only a flagged
  constant on each compare.
- Field 0 of an arbitrary boxed object can be a **pointer** (a boxed allSettled
  settlement's field 0 is its `status` string pointer), so the marker bit must
  sit where a valid user-space heap pointer never has one. Both targets keep
  user pointers < 2^47, so **bit 48** is always clear for a pointer or a small
  class tag — only a real Error sets it.

## Decision

**Type-id (TDD-00222).** Field 0 of every Error-shaped object carries
`errorTypeIDFlag = 1<<48` OR'd onto its kind/TagID:

- Written by `buildErrorObj`/`buildErrorObjWithCode`/the AggregateError builders,
  by class construction and value-object literals **for error-subclasses only**,
  and by every hand-written runtime error builder (`runtime_fetch`/`fs`/`http`/
  `process`/`encoding`/`crypto_subtle`/`streams_zlib`/`threadpool`/…).
- Compared against `errorTypeIDStored(id)` everywhere an Error's field 0 is
  tested — `instanceof` (built-in kind, error-subclass hierarchy, caught and
  dynamic arms), the AggregateError `.errors` guard. The dynamic
  `instanceof Error` base arm stops punting to `tag == kmlTagObject` and tests
  the flag, so a boxed plain object is no longer `instanceof Error`.
- Recovered by three consumers via `emitBoxedBuiltinErrorProbe` (flag set **and**
  low bits < `errorSubclassTagBase`, so a subclass instance — a different struct
  layout — is not misread): `emitDynamicToString`'s object arm renders an Error
  as `name: message`; `emitDynAnyMemberGetNamed` reads `.message`/`.name`/`.stack`
  from the real fields; and the dynamic JSON walker (`dynjson.c`) emits `{}` for
  a boxed Error.

**Faithful reason (TDD-00169).** `SettlementType.reason` becomes `any` (same i64
width as the former pointer — no layout change). The allSettled task path boxes
the caught reason with `emitCaughtToAny` (an Error → `kmlTagObject` carrying the
flagged errorObjType; a non-Error → its own primitive box); the Response path
boxes its wrapped transport Error the same way; a fulfilled entry's absent
reason is boxed `undefined` (so JSON omits it). The settlement JSON serialises
`reason` through the dynamic value path instead of reading a message field.

## Consequences

- `Promise.reject(42)` → `typeof reason === "number"`, JSON `42`;
  `reject("e")` → `"e"`; a rejected Error → `reason.message`/`.name`/
  `String(reason)` byte-exact, JSON `{}`, `reason instanceof Error` true — all
  matching Node.
- `x instanceof Error`/`instanceof TypeError` on a boxed value is now precise
  (a boxed plain object is no longer an Error).
- `String`/`console.log`/`.message`/JSON of a boxed Error at any `any` site now
  recover the Error rather than printing `[object Object]`/empty or throwing.
- ADR-01002's `emitCaughtToErrorObj` is removed (its single caller now boxes to
  `any`).

## Not covered (tracked)

- `AbortSignal.reason` is still typed `errorObjType` and stores a raw string for
  a non-Error `abort(reason)`; flipping it to `any` is a separate change on
  TDD-00081's surface (noted in TDD-00222/TDD-00169) that this type-id now
  unblocks.
- A boxed **error-subclass** instance renders as `[object Object]` and its
  members are not recovered (its layout is not `errorObjType`); `instanceof`
  is precise for it. Needs the class's own field metadata (D1 Stage 6 bridge).
- No stack traces are retained, so `err.stack` is approximated by the
  `name: message` toString form.

## Verification

macOS arm64 (M4), byte-exact vs `node`: allSettled with number/string/Error/
TypeError reasons (typeof, value, JSON, member, String, instanceof); a boxed
`any[]` of Errors (String/member/JSON `{}`); `instanceof` precision. New tests
in `tests/allsettled_reason_error_test.go`; `examples/async/promise_combinator_shape.ts`
extended. `make examples`, `make status-check`, `make reference-check` green;
Test262 run at delivery.
