# ADR-00745: Windows — UTF-8 `process.argv` from GetCommandLineW

- **Relations**: Implements a [TDD-00180](../tdd/TDD-00180.md) §2 row; extends [ADR-00719](ADR-00719.md) (the Win32 platform layer), [ADR-00740](ADR-00740.md) (spawn already sends args as UTF-16, so this is the receiving half)
- **Date**: 2026-09-07

## Context

`process.argv` was built from the `argv` the CRT hands `main` — decoded in the process ANSI code page. A non-ASCII argument (`café`, Greek, CJK, an emoji) therefore arrived as `?`. The spawn side already passes arguments to `CreateProcessW` as UTF-16 (ADR-00740), so a child launched by a compiled program received the correct bytes on the command line and then corrupted them on the way in. Node reads `GetCommandLineW` and exposes UTF-8.

## Decision

A shim function `__kml_win_argv(int *out_argc)` reads `GetCommandLineW()`, splits it with `CommandLineToArgvW`, converts each argument to UTF-8, and returns a malloc'd NULL-terminated `char**` (with the count). On Windows the emitter's `main` prologue calls it and uses its result in place of the CRT `argv`/`argc` for the `process.argv` headerize step, falling back to the CRT values if the shim returns null. POSIX is unchanged (argv bytes already pass through untouched). Links `-lshell32` for `CommandLineToArgvW` (a system DLL, no runtime install).

## Consequences

- `tests/argv_utf8_windows_test.go`: a compiled binary run with `café-Ω-日本語` and `naïve🚀` as arguments reads them back from `process.argv` byte-for-byte (verified on Windows 11). The test runs on every host — POSIX passes the same bytes through, so the assertion holds there too.
- Every Windows program now links `shell32`; the argv reconstruction runs once in `main` before any user code.
- The `argv[0]` a program sees on Windows is now the command-line form from `CommandLineToArgvW` (what Node exposes) rather than the CRT's; `process.execPath` continues to come from `GetModuleFileNameW` (unchanged).
- Still open in §2: `WriteConsoleW` for non-ASCII console *output* (still `_write`, so mojibake off code page 65001), `ReadConsoleW` for non-ASCII console input, and a console-resize (`'resize'`) event.
