# TDD-00212: A boxed array carries its element type so `any` renders its contents

- **Status**: Implemented
- **Date**: 2026-09-14

## Context

An array boxed into `any` renders as the placeholder `[object Array]` instead of
its contents, in both string contexts and `console.log`:

```ts
let a: any = [1, 2, 3];
console.log(a);        // prints "[object Array]"   — Node: [ 1, 2, 3 ]
console.log("" + a);   // prints "[object Array]"   — Node: "1,2,3"
let c = [1, 2, 3];
console.log(c);        // prints "[ 1, 2, 3 ]"      — correct (statically typed)
```

A statically-typed array renders correctly because the emit site knows its
element type (`emitInspectArray`, `emit_inspect.go`). The `any`-boxed case does
not: the box (ADR-00478) is a bare 16-byte `{ ptr data, i64 len }` header with
**no element type**, so at the render site — which sees only the runtime NaN-box
tag `kmlTagArray` — the element kind is unrecoverable and the code stores the
honest stand-in `"[object Array]"` (`emit_dynamic.go:585`, the deviation
documented in TDD-00062).

This is the "boxed-element boundary": every path that widens a typed array to
`any` (a `: any` binding, a null-evolving `let x = null; x = [1,2,3]`, an `any`
parameter/return, an array value put into a `Map<any,V>`) loses the ability to
show or `String()` its own contents. It is now the visible residue after the
cross-type-store fixes (ADR-00933/00934) closed the invalid-IR half of this area.

## Design

The crucial asymmetry: **at box time the static element type IS known**
(`emitBoxValue` receives `v.Ty.ElemType`, `emit_dynamic.go:409`); it is simply
discarded. The fix records enough of it in the box for the render site to recover.

### Option A — convert to a boxed-element structure at box time (rejected)

When boxing `T[]` into `any`, walk it into a self-describing structure whose
elements are individually NaN-boxed (a `kmlTagDynArray` / `any[]`), then reuse
`__kml_dynarr_join` for `String()` and the dynamic inspector for `console.log`.

Rejected: it is an O(n) **copy** at every box, and it breaks two invariants the
current box holds. (1) Identity — `__kml_any_eq`'s array arm compares the data
pointer inside the header as the array's stable identity (ADR-00478); a copied
dynarr has a different pointer, so `a === boxedA` would go false. (2) Live
mutation — a later `a.push(x)` must be visible through the box (reference
semantics); a snapshot copy freezes the contents at box time.

### Option B — element descriptor in the any-array box (recommended)

Give the `any`-array box its own header, distinct from the 16-byte nested-array
element box (`boxArrayValue`, TDD-00029, which must stay 16 bytes — it is a hot
per-element slot shape and unrelated to the `any` boundary):

```
{ ptr data, i64 len, i8 elemKind }   // 24 bytes, the any-array box payload
```

`data`/`len` stay the *same pointers* the array already uses — O(1) box, identity
preserved, later mutation visible (the header points at the live data buffer, and
`len` is re-read at render time... see Open questions on growth). `elemKind` is a
compact descriptor derived from `v.Ty.ElemType` at box time.

`elemKind` enumerates the flat element storages the backing buffer can hold:
`i64`/`f64`/`bool`/`string`/`boxed-any`/`array`/`object` (extended per JSDoc
integer widths as needed). Render sites switch on it:

- **`String()` / interpolation** (`emit_dynamic.go` array arm) → a runtime
  `__kml_array_join(ptr hdr)` that strides the buffer by the element width for
  `elemKind`, formats each element as JS does, and joins with `,` — giving
  `String([1,2,3]) === "1,2,3"`, `String(["x","y"]) === "x,y"`.
- **`console.log`** → the Node inspector form `[ 1, 2, 3 ]` / `[ 'x', 'y' ]`
  (quoted strings, `util.inspect` spacing), sharing the stride/format logic with
  join but with inspect punctuation.
- Nested (`array` elemKind, `T[][]`) and `object` elemKind recurse to
  `[Array]`/`[object Object]` at depth, matching `util.inspect`'s depth cap
  (`emit_inspect.go`) and `Array.prototype.toString`.

Only the handful of any-boundary sites change (box producer `emit_dynamic.go:410`,
the `dynstr.array` arm `:585`, `Array.isArray` `:864` which is layout-agnostic,
`__kml_any_eq`'s array arm, and any `any`→typed-array unbox). The nested-element
box and every statically-typed array path are untouched.

## Open questions

- **Growth after boxing.** A named array's `push` swaps the header's data pointer
  through the object-reference model (TDD-00127); the box holds a copy of the
  `{data,len}` at box time, so a post-box `push` would not be seen. Does the
  any-array box need to hold the *header pointer* (one more indirection, full
  live-mutation fidelity) rather than a `{data,len}` snapshot? Leaning yes —
  reference semantics is the faithfulness bar — but it interacts with how the box
  payload is a single tagged pointer.
- **Integer element widths.** `number[]` is `f64` (TDD-00123), but JSDoc
  `int32[]`/`uint8[]` etc. have narrower storage. `elemKind` must encode width +
  signedness, or reuse the existing element-kind enum the typed-array path uses.
- **`console.log` currently routes a boxed value through ToString, not inspect.**
  Fixing the inspect form (`[ 1, 2, 3 ]`) may require the boxed-array console.log
  path to branch into an inspector rather than `emitDynamicToString`; scope that
  in Stage 2 vs. deferring the bracket form and shipping the `String()` join
  first.
