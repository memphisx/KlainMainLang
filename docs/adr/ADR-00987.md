# ADR-00987: fs.constants O_* open flags

- **Relations**: `Extends ADR-00795`
- **Date**: 2026-09-17

## Context

`fs.constants` exposed the POSIX access modes (`F_OK`/`R_OK`/`W_OK`/`X_OK`) and
libuv's copyFile flags but not the `O_*` open flags. `openSync(path, flags)`
already accepts a raw numeric flag mask (passed straight to the host `open(2)`),
so the natural Node idiom

```ts
const fd = fs.openSync(p, fs.constants.O_WRONLY | fs.constants.O_CREAT | fs.constants.O_TRUNC, 0o644)
```

failed to compile — `fs.constants.O_WRONLY` was rejected as an unknown member.
The `O_*` flags were deliberately omitted originally because their numeric
values are host-specific (Darwin and glibc disagree on everything past
`O_RDONLY`/`O_WRONLY`/`O_RDWR`), and a compile-time literal can't honour that.

## Investigation

`openFlagBits` (codegen/llvm/runtime_fs.go:1660) — the string-flag path
(`'w'`/`'a'`/…) — already resolves the per-OS bits against `targetGOOS()`
(ADR-00813 threads target OS through codegen), so the host-specific objection no
longer holds: the same target-aware table gives faithful values, and a
cross-compiled binary carries its *target's* values, which is what the `open(2)`
it runs against expects. `emitFsOpenSync` (emit_fs.go:665) passes a numeric
`flags` argument through to `@__kml_fs_open` unchanged, so `O_*` constants OR'd
together are already consumed correctly; only the constant *names* were missing.

## Decision

Add the `O_*` set to `fs.constants`, resolved against `targetGOOS()` in a new
`fsOpenConstant(name)` (emit_fs_constants.go): Darwin, Windows (MSVC `_O_*`,
Node's Windows subset), and a default asm-generic Linux/Android table (identical
on x86-64 and arm64). Each platform lists exactly the flags Node exposes there —
`O_DIRECT`/`O_NOATIME` Linux-only, `O_SYMLINK` Darwin-only, etc. `emitFsConstant`
consults the invariant map first, then `fsOpenConstant`. Values match each
platform's `<fcntl.h>` and Node's own `fs.constants` (verified against
`node -e` on macOS: `O_CREAT` 512, `O_TRUNC` 1024, `O_APPEND` 8, `O_EXCL` 2048).

## Implementation notes

The string-flag masks in `openFlagBits` and the new `O_*` constants are the same
bits, so `openSync(p, 'w')` and `openSync(p, O_WRONLY|O_CREAT|O_TRUNC)` produce
identical masks — kept consistent by hand (both derive from the same per-OS
`<fcntl.h>` values). The access-mode low bits (`O_RDONLY` 0 / `O_WRONLY` 1 /
`O_RDWR` 2) are universal.

## Side effects discovered

`TestE2EFsConstantsUnknownMemberRejected` used `O_RDWR` as its "unknown member"
probe — now a valid member, so it was repointed at `O_BOGUS`.

## Verification

macOS arm64 (M4). New E2E tests (tests/fs_test.go): `TestE2EFsConstantsOpenFlags`
(round-trips `openSync(O_WRONLY|O_CREAT|O_TRUNC)` → write → read back) and
`TestE2EFsConstantsOpenFlagValues` (representative bits match `runtime.GOOS`'s
`<fcntl.h>`); the existing constants tests still pass. Example: the fd-I/O
section of examples/fs/fs.ts opens a file via the `O_*` mask. `go build`/`vet`
clean; targeted `TestE2EFsConstants*` green; `make examples`; `make status` +
`make reference-check`. Values cross-checked against `node -e` on macOS.
