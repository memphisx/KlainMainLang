# ADR-02075: The front end reads a library module once per path check, and no compile forces a collection

- **Relations**: Extends ADR-02072; Implements TDD-00230
- **Date**: 2026-11-24

## Context

The Test262 js lane on Linux x86-64 took 3804 s on 2026-11-17 and
5006-5217 s on every run since. Compared old against new on one fixed
sample (`built-ins/Array`, `-compat=js`, 14 workers, Node304): HEAD
195 s, the working tree 222-227 s. On the 2357 files HEAD passes, run
by both through `-only`: HEAD 147 s, the working tree 156 s.

## Investigation

CPU profiles of both runs (`-cpuprofile`), compared function by
function:

- `regexp.(*machine).match` took 247 s of the working tree's samples and
  none of HEAD's. 242 s of it came from one call in
  `resolver.ResolveProgramWithOptions`: `dottedPathRE(uses).Match(src)`,
  run for every library module against every lowered function whose
  uses form a dotted path. The pattern starts with `(^|[^\w$.])`, so
  the regexp engine finds no literal prefix to skip to and steps
  through the whole module once per path.
- With that fixed, the remaining difference was the collector:
  `runtime.gcBgMarkWorker` 68 s at HEAD against 208 s, and
  `runtime.GC` 30 s against none. `EmitProgram` called `runtime.GC()`
  before its final IR passes, to free the emission's garbage before the
  passes copied the module. The conformance runner compiles 14
  programs in one process, so each compile's collection was a
  collection for all 14.
- The runner's own peak RSS over the WPT js lane, sampled every second
  from `/proc/<pid>/status`: 6927 MB with the forced collection, 6932
  MB without. The heap's soft limit (`setBudget`: 1.5 GB plus 384 MB
  per front-end slot, 6.9 GB for 14 slots) already holds it there, and
  ADR-02072 removed the module copies the collection was meant to
  free.

## Decision

- `hasDottedPath(src, parts)` replaces the per-path regexp. It finds
  each occurrence of the first name with `bytes.Index`, rejects one
  preceded by a word character, `$` or `.`, then reads each further
  name after regexp `\s*`, an optional `?` and a `.`, then `\s*`, and
  accepts when the path is not followed by a word character or `$`.
  This is the language the regexp matched, byte for byte (a non-ASCII
  rune's bytes are all outside `[\w$.]`, as the rune is).
- `EmitProgram` no longer calls `runtime.GC()`.

## Implementation notes

- `resolver/resolver.go`: `hasDottedPath`, `isWordByte`,
  `skipRegexpSpace`; the `dottedPathREs` cache is gone.
- `codegen/llvm/emitter.go`: the collection and its comment.

## Side effects discovered

- The macOS lanes run with `-workers 2` to stay under the 3 GB guard, a
  quarter of the default; that, not the compiler, is most of their
  wall time.

## Verification

- `TestHasDottedPathMatchesRegexp`: 800,000 generated inputs over four
  paths, the scan's answer equals the regexp's on each.
- Same-file benchmark (the 2357 files HEAD passes, `built-ins/Array`,
  js, 14 workers, Node304): HEAD 147 s, before 156 s, after 134 s.
  Pass counts identical (2356 / 2357 each).
- WPT js lane, Linux x86-64: 201 passed both ways; runner peak RSS
  6927 MB before, 6932 MB after; wall 865 s before, 808 s after.
- `go test ./resolver/... ./codegen/llvm/... ./tools/...`, then
  `make test-par`, `make examples`, `make drift` on Linux x86-64.
