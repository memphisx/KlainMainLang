# TDD-00103: Node `Buffer`

- **Status**: Implemented
- **Date**: 2026-08-23

## Context

ADR-00094 settled fetch/fs binary returns on WHATWG types (`ArrayBuffer`/`Uint8Array`) and deliberately built no `Buffer` class. That surface stands unchanged — but a large share of real Node CLI/microservice code (and conformance corpus files) constructs Buffers directly, above all for string↔bytes codecs (hex/base64) that nothing else in the runtime provides. This TDD adds the Buffer class itself; **the ADR delivered with it supersedes ADR-00094's "no Buffer class" half** while keeping its "WHATWG returns from fetch/fs" half.

## Design

**Representation.** A Buffer IS a `Uint8Array` — `TypedArrayType("uint8")` with a new `IsBuffer` flag, the exact `IsURLSearchParams`-rides-on-`IsMap` pattern. Indexing, `.length`, `.slice`/`.subarray`, numeric `.fill`/`.indexOf`/`.includes`, HOFs, for-of, `.set`, `.byteLength`, and `fs` writes all come free from the TypedArray machinery. The flag only adds `Buffer.*` static dispatch and instance-method dispatch (`.toString` etc.).

**General expression.** `Buffer.from(...)`/`Buffer.alloc(...)` are *call* syntax, dispatched as a namespace (the `Atomics` pattern in emitCall) — not `new`, so the TypedArray vardecl-only restriction never applies. Statics return the `{ptr,i64}` aggregate (the value shape `.subarray` already returns), usable in any expression position.

**Codecs.** A self-contained libc-only C runtime (`buffersrc/buffer_codecs.c`, embedded and compiled alongside the program exactly like the JSON parse-tree runtime): hex encode/decode, base64/base64url encode/decode (decode is lenient like Node's — skips non-alphabet bytes), latin1 bytes↔UTF-8 string. utf8 needs no codec (strings are already UTF-8 bytes — strlen/memcpy). Encoding arguments must be compile-time string literals (the codec choice is a compile-time dispatch); supported names: `utf8`/`utf-8`, `hex`, `base64`, `base64url`, `latin1`/`binary`, `ascii` (treated as latin1).

**Surface (in).** Statics: `from(stringLiteral-encoded string)`, `from(array literal | number[] | TypedArray | ArrayBuffer | Buffer)` (ArrayBuffer arg **copies** — Node views it; disclosed caveat, avoids the out-of-scope `.buffer` aliasing machinery), `alloc(n, byteFill?)`, `allocUnsafe(n)`, `concat(inline array literal of Buffers/TypedArrays, totalLength?)`, `compare(a, b)`, `isBuffer(x)` (a compile-time constant from the inferred type), `byteLength(string, enc?)`. Instance: `.toString(enc?, start?, end?)`, `.write(string, offset?, enc?)`, `.copy(target, targetStart?, sourceStart?, sourceEnd?)`, `.equals`, `.compare`, and the full fixed-width accessor set `read/write{U}Int{8,16,32}{LE,BE}`, `readFloatLE/BE`, `readDoubleLE/BE`, `read/write BigInt64/BigUInt64 LE/BE` — implemented over the same bswap/bitcast core DataView uses, with RangeError bounds checks.

**Cut (disclosed caveats).** `utf16le`/`ucs2` (the compiler is UTF-8-native; no two-byte string representation exists), string-valued `.fill`/`.indexOf`/`.includes`/`.lastIndexOf`, `.write`'s 4-arg `(string, offset, length, encoding)` form, `.swap16/32/64`, `.toJSON`, `Buffer.of`, arbitrary-width `readIntLE(offset, byteLength)`, `poolSize`/`allocUnsafeSlow` (no pool concept), runtime-computed encoding names.
