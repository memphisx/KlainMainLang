# ADR-01179: A primitive is not a library object; a literal elaborates past a union's primitives

- **Relations**: `Extends [ADR-01174](ADR-01174.md)`; `Implements [TDD-00230](../tdd/TDD-00230.md)` (P2.7)
- **Date**: 2026-09-26

## Context

`const u: URL = 42`, `const b: Buffer = 42` and `fs.unlinkSync(42)` passed
the checker, which only reports a definite no. A primitive against an
object type was always "maybe": its apparent type (`Number`, `String`, …)
might have the members the target requires. The strict lane then left the
program to code generation, which rejected it with its own messages.

## Investigation

- The library's declarations (`lib/*.d.ts`) are partial: they list what
  this compiler implements, so the library's `Number` lacks members
  TypeScript's has. A rule reading them rejected `number` against a user's
  `NotNumber` that mirrors `Number` exactly (tsdiag: 35 new spurious
  errors). A rule on a program's own types also met inference the checker
  does not finish (a `coAndContra<T>` call).
- TypeScript's apparent types' member lists (lib.es5 through esnext) are
  small and fixed; every apparent type inherits `Object`'s members.
- tsc elaborates an object literal returned as `Stuff | string` into its
  properties: a literal is never the union's primitive members.

## Decision

- A primitive is not assignable to a library object type (Buffer, URL,
  Promise, …) that requires a member its apparent type does not have in
  TypeScript (the fixed member lists, `Object`'s included); the apparent
  interface itself (`number` to `Number`, augmented or not) is exempt.
- An object or array literal's elaboration against a union skips the
  union's primitive members as it skips null and undefined.

## Implementation notes

`checker/relate.go` (`primitiveLacksLibraryMember`, `apparentMembers`),
`checker/check.go` (`elaborate`).

## Side effects discovered

None.

## Verification
