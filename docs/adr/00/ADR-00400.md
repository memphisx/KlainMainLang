# ADR-00400: Accept any function-typed expression as a callback

- **Relations**: Implements TDD-00131 (per-module Node API fidelity — front-end enabler); Extends [ADR-00398](ADR-00398.md)
- **Date**: 2026-08-27

## Context

`callback must be an arrow function or function identifier` was the front-end
fallback in `resolveCallback` (the shared callback resolver used by timers,
`dgram`, `net`, `String.replace`, and array HOFs). It accepted only three arg
shapes — an arrow function, a function expression, and an identifier (a named
function or a function-typed variable) — and rejected every other expression,
even when its static type is a function. It ranked among the largest Node-oracle
blockers (58 files on this exact message), and the dominant real pattern behind
it is `common.mustCall(fn)` used directly as a callback (245 corpus occurrences):
the runner rewrites it to the native `mustCall(fn)` (TDD-00122), a
**call-expression that returns a function**, which the resolver then refused.

## Decision

`resolveCallback` gains a final generalization: after the specific
arrow/expression/identifier cases, **any expression whose static type is a
function value** is evaluated once to its closure header and dispatched as a
closure. This covers:

- a wrapper-returning call — `mustCall(fn)`, `fn.bind(null, x)` (ADR-00398);
- a function-typed object field or array element — `obj.handler`, `handlers[i]`;
- a ternary — `cond ? f : g`.

A method *reference* (`obj.method` where `method` is a class method, not a
field) is still rejected — class methods are not first-class values here, so
`inferExprType` does not report them as functions, and the resolver's error
stands. This keeps the change to genuinely-function-typed expressions with no
risk of miscompiling a non-callable.

## Consequences

Bound functions, wrapper calls (`mustCall`), field/element references, and
ternaries now work anywhere a callback is accepted, verified byte-identical to
Node for the standard-JS forms (bind/field/ternary). The stricter arrow-only
resolvers that store a raw closure header in a runtime struct (`net`'s
`netArrowClosure`, `child_process`, ReadableStream source callbacks) keep their
own narrower requirement — relaxing those to accept a *named* function needs a
header-wrapping step, a separate change. Broad regression run (timers, dgram,
net, regexp, arrays, EventEmitter) is clean.
