# TDD-00171: Geolocation API — native reinterpretation, IP-geo first

- **Status**: Not Started
- **Date**: 2026-09-03

## Context

The [W3C Geolocation API](https://www.w3.org/TR/geolocation/)
(`navigator.geolocation.getCurrentPosition` / `watchPosition`) is listed
out-of-scope as "browser-only". But a headless server/CLI *does* have a
meaningful location, and the standard's shape maps onto native sources cleanly —
the trick is to **hook location services that already exist** (never build GPS or
a WiFi-triangulation database) and let the standard's own `enableHighAccuracy`
option pick the source. It reuses infrastructure already built (`fetch`/libcurl,
`JSON.parse`, the async task/event loop, and the `navigator` global introduced by
[TDD-00170](TDD-00170.md)). Genuinely useful for the target: geo-routing,
GDPR/data-residency decisions, region-defaulting timezone/locale, geo-tagged
logs, and — at the high-accuracy tier — robotics/IoT control CLIs (pairing with
the Gamepad reinterpretation).

## Design

### Surface — the faithful W3C shape

- `navigator.geolocation.getCurrentPosition(success, error?, options?)`
- `navigator.geolocation.watchPosition(success, error?, options?): number` /
  `clearWatch(id)`
- `PositionOptions` `{ enableHighAccuracy?, timeout?, maximumAge? }`
- `GeolocationPosition` `{ coords: GeolocationCoordinates, timestamp }`
- `GeolocationCoordinates` `{ latitude, longitude, accuracy, altitude|null,
  altitudeAccuracy|null, heading|null, speed|null }`
- `GeolocationPositionError` `{ code, message }` with `PERMISSION_DENIED=1`,
  `POSITION_UNAVAILABLE=2`, `TIMEOUT=3`.

Callback-based and asynchronous: `getCurrentPosition` kicks off the chosen source
(a `fetch` for IP-geo) and fires `success`/`error` on the event-loop tick when it
resolves — riding the existing async task machinery. `watchPosition` is a poll
(`setInterval`-style) over the source through the event loop.

### Tiered source selection (the whole point — hook, don't build)

`enableHighAccuracy` and availability pick the tier; `coords.accuracy` is
reported **honestly** per source (km for IP, meters for GPS):

- **Tier 0 — IP geolocation over `fetch` (V1, default, zero new dependency).**
  `enableHighAccuracy: false` → one HTTPS call to an IP-geo service
  (ip-api.com / ipinfo.io / ipapi.co), `JSON.parse` the `{lat, lon}`, fill the
  W3C objects with a coarse `accuracy` (tens of km) and null altitude/heading/
  speed. This is what a headless server actually is: no GPS, one public IP.
  Offline → `error(POSITION_UNAVAILABLE)`. **This is the entire V1** — small,
  reuses `fetch` + JSON + the `navigator` host, no hardware/DB/link-dep.
- **Tier 1 — OS location service (follow-on, `enableHighAccuracy: true`).** The
  WiFi/GPS aggregation database already exists as a system service — hook it, as
  SDL is hooked for gamepad: **Linux GeoClue** (D-Bus; *is* the WiFi/MLS/GPS
  aggregator) and **macOS CoreLocation** (`CLLocationManager`, real WiFi+GPS
  fix). Falls back to Tier 0 when unavailable/denied.
- **Tier 2 — NMEA-over-serial GPS (follow-on).** A USB GPS dongle emits line-based
  NMEA text (`$GPGGA,…`) on `/dev/ttyUSB*` / `/dev/tty.usb*`; parsing is trivial
  (no driver). The robotics/IoT/control-CLI angle, reinforcing the Gamepad story.
- **Tier −1 — env/config override (`KML_GEOLOCATION=lat,lon`).** Trivial;
  pins a server's declared location and makes CI/tests deterministic (no network,
  no hardware). Checked before any tier so it always wins when set — the mockable
  path for the E2E test.

### Faithful option mapping

- `enableHighAccuracy` → Tier 1 (OS service) when true, Tier 0 (IP) when false.
- `timeout` → the source attempt is abandoned with `error(TIMEOUT)` past it.
- `maximumAge` → a cached last position within the window is returned without a
  fresh lookup (a small per-process cache).
- `PositionError` codes: `PERMISSION_DENIED` (an OS service refused),
  `POSITION_UNAVAILABLE` (offline / no fix), `TIMEOUT`.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| `fetch` / libcurl | Built | Tier 0's IP-geo lookup |
| `JSON.parse` into a typed shape | Built | parse the service's `{lat, lon}` |
| async task + event loop | Built | callbacks fire on the tick; `watchPosition` polls |
| `navigator` global | To build (shared) | introduced by [TDD-00170](TDD-00170.md); `geolocation` hangs off it |
| `performance.now()` / epoch | Built | `GeolocationPosition.timestamp` |
| GeoClue (D-Bus) / CoreLocation | Not needed for V1 | Tier 1 only, opt-in |

## Staging (ordering, not dropping)

1. **Tier 0 IP-geo V1**: `navigator.geolocation.getCurrentPosition` + the
   `GeolocationPosition`/`Coordinates`/`PositionError` objects, over `fetch`;
   plus the `KML_GEOLOCATION` override (Tier −1) as the always-first, testable
   path. `watchPosition`/`clearWatch` over a poll.
2. **`enableHighAccuracy` → Tier 1 OS services** (GeoClue on Linux, CoreLocation
   on macOS), with Tier 0 fallback.
3. **Tier 2 NMEA-over-serial GPS** for a directly-attached receiver.

## Open questions

- **Consent model.** The browser API gates on a permission *prompt*; a headless
  native runtime has no prompt. V1 is allow-by-default (a server opting into the
  call is the consent), with `PERMISSION_DENIED` reserved for an OS service that
  itself refuses. Confirm no prompt is expected.
- **IP-geo provider + config.** A default endpoint (ip-api.com is keyless) plus a
  `KML_GEOLOCATION_ENDPOINT` override; note rate limits and that the returned
  accuracy/fields vary by provider. Whether to ship a fallback provider list.
- **Privacy/egress.** Tier 0 sends the machine's IP to a third-party service —
  document it clearly; the `KML_GEOLOCATION` override and Tier 1/2 are the
  no-egress alternatives.
- **`watchPosition` cadence** and whether IP-geo (which barely changes) should
  poll at all vs emit once then idle.
