# ADR-01637: ToPrimitive on a typed object goes past a method that gives an object

- **Relations**: Extends ADR-00859
- **Date**: 2026-10-15

## Context

Comparing the Test262 failure lists of Windows and Linux AMD64 turned up
`built-ins/String/S9.1_A1_T2.js`, failing on Windows only. Reduced, the
strict lane printed `[object Object]` on both platforms for

```ts
const a = { valueOf: function() { return 5 }, toString: function() { return {} } }
String(a)   // Node: "5"
```

## Investigation

- `emitObjectToPrimitive` (`codegen/llvm/emit_toprimitive.go`) left
  `valueOf` out of the string hint's order, reasoning that the inherited
  `Object.prototype.toString` always answers first. That holds only when the
  object has no `toString` of its own. OrdinaryToPrimitive tries `toString`
  and then `valueOf` for the string hint.
- A candidate whose declared result is an object was skipped without being
  called. The spec calls it and goes on, so its side effects are lost, and
  the call order differs from Node's.
- When no method gives a primitive, Node throws `TypeError: Cannot convert
  object to primitive value`. The typed path fell back to the caller's
  `[object Object]`. The dynamic path (`boxsrc/toprim.c`) already threw.
- The Windows-only failure of the Test262 file has a different cause: the
  file redeclares `var object` with a second object type. That is
  ADR-01638.

## Decision

- The string hint's order is `@@toPrimitive`, `toString`, `valueOf`. A
  missing `toString` is `Object.prototype.toString`, which ends the ladder
  with the caller's default, so `valueOf` is reached only past an own
  `toString`. The number and default hints keep `@@toPrimitive`, `valueOf`,
  `toString`.
- A ladder method whose declared result is an object, on a typed object or a
  class instance, is called for its effects, and the ladder goes on.
- If an own `toString` gave an object and `valueOf` is missing (the inherited
  one returns the object) or gave an object too, the conversion throws
  `TypeError: Cannot convert object to primitive value`.

## Implementation notes

`codegen/llvm/emit_toprimitive.go`. The throw ends the block, so the
function opens a fresh dead label and returns "not converted", and the
caller's default code lands in a block nothing reaches.

## Verification

Windows 11: `TestE2EToPrimitiveObjectResultFallsThrough` compares seven
cases with Node in both lanes: typed objects and class instances; `String`,
template literals and `+`; the TypeError; and the order in which the methods
were called. Every test in the 19 test files that exercise
`valueOf`/`toString`/ToPrimitive passes.
