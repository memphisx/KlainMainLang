# ADR-01873: `ThisType<T>` and a literal method's missing `this` member

- **Relations**: `Implements TDD-00230` (P3.3), follows ADR-01869
- **Date**: 2026-10-21

## Context

- ADR-01869 typed an object-literal method's `this` by the literal's contextual type. `Object.defineProperty`'s descriptor is typed `PropertyDescriptor & ThisType<any>` in tsc's library; ours dropped the marker, so `{ get() { return this.a } }` reported `a` missing on PropertyDescriptor in the strict lane, where tsc accepts it.
- `{ a: 1, m() { return this.b } }`: the read of a property the literal does not name left `m`'s result, and with it the literal, unanswered. tsc types the read as its error type (any) and reports TS2339 against the finished literal type.

## Decision

- The library declares `ThisType<T>`. `Object.defineProperty`, `Object.defineProperties` and `Reflect.defineProperty` take tsc's `& ThisType<any>`. An intersection holding the marker carries its T, and an object literal it contextually types takes that T as its methods' `this`.
- A member read on a literal's `this` snapshot naming no property of the literal is any.

## Consequences

- `TestThisTypeMarker` and `TestObjectLiteralMethodThisMissing` hold tsc 5.6's codes. tsc's TS7023 beside the TS2339 (`m` implicitly returns any) is not reported; the strict lane rejects the program either way.
- Verified on Apple Silicon.
