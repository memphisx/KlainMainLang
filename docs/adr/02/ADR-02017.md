# ADR-02017: A primitive or null `F.prototype`

- **Date**: 2026-11-21

## Context

A constructor function's `prototype` was held only as an object bag.
Assigning it a primitive (`F.prototype = 1`, `F.prototype += 1`) threw
"Object prototype may only be an Object or null". Assigning null left the
slot empty, so the lazy getter built a fresh bag on the next read, and
`new F` made a null-prototype object.

## Decision

- Each constructor function also has a value slot,
  `@__kml_protoval_<F>`. It holds what was assigned when that is a
  primitive or null (0 means the property is the bag), and `F.prototype`
  reads it back.
- A primitive or null leaves the bag slot empty. The getter builds a bag
  only when nothing was assigned.
- `new F` sets the new object's prototype only when there is a bag.
  Otherwise the object keeps Object.prototype
  (OrdinaryCreateFromConstructor's fallback).

## Implementation notes

- codegen/llvm/emit_protoclass.go: `ensureProtoBag`, `emitProtoBagRead`,
  `emitProtoBagWrite`, and the `new F` path.

## Verification

- `TestE2EPrimitiveFunctionPrototypeJS` matches Node on Linux x86
  (Node304).
