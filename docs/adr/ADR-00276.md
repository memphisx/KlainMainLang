# ADR-00276: `yield*` delegates `.throw`/`.return` into a user async-iterable's optional methods — plus reserved words as class member names

- **Relations**: Closes the last caveat of [TDD-00094](../tdd/TDD-00094.md) (async-generators row → strict); completes the `yield*`-async-iterable path of [ADR-00274](ADR-00274.md)/[ADR-00275](ADR-00275.md)
- **Date**: 2026-08-21

## Context

The async-generators row was ✅ but one narrow caveat kept it out of strict: a `yield*` over a user
`Symbol.asyncIterator` async-iterable (as opposed to another async *generator*, which already
forwards) re-yielded values but did **not delegate** a `.throw(e)`/`.return(v)` on the outer into
the inner iterator's own optional methods — it ran the outer's own propagate/complete path instead.
JS delegates: `it.throw`/`it.return` on a generator suspended at `yield* inner` calls
`inner.throw`/`inner.return` when they exist.

Closing it surfaced a **parser** gap first: a class could not even declare methods **named**
`throw` or `return` — the class-body parser accepted only `IDENT` as a member name, so a reserved
word (`throw`, `return`, `catch`, …) as a method name was a parse error. In JS a class member name
is an `IdentifierName`, which includes every reserved word (the same reason `promise.catch` already
lexes fine after `.`). Without this, a conformant user async iterator literally cannot spell its
protocol methods.

## Decision

1. **Parser: reserved words are valid class member names.** `isClassMemberNameStart` now returns
   true for any keyword token (so `async throw() {}` reads as an async method, not a field named
   `async`), and the member-name parse accepts a keyword token as the name (re-tagged as an `IDENT`
   with the keyword's literal). General — not special-cased to `throw`/`return`.
2. **Codegen: `emitYieldStarAsyncIterable` delegates.** The delegation loop is restructured around a
   `proc` label that both `it.next()` and a forwarded step re-enter. On resume the outer dispatches
   on `__resumeMode`:
   - **mode 1 (`.throw`)** — if the inner class has a delegatable `throw` (present, returns
     `Promise<{value,done}>`), forward into `inner.throw(e)`, await it, and feed the result back
     through `proc` (so the inner may catch and keep yielding); otherwise re-throw at the suspension
     point (the outer body's `try`/catch-all handles it) — the prior own-path.
   - **mode 2 (`.return`)** — if the inner has a delegatable `return`, forward into `inner.return(v)`,
     await it, and if the inner honors it (`done`) complete the outer with the inner's value, else
     re-yield and continue; otherwise run the outer's finallys and complete with the sent value.
   - **mode 0 (`.next`)** — loop for the next element.

   The inner method takes an *expression* argument but the forwarded value is a runtime register, so
   `forwardCall` binds the value to a fresh synthetic local and hands `emitClassCall` an identifier
   for it — reusing all of the method-dispatch/coercion path rather than open-coding a second one.

## Verification

Mac (Apple Silicon M4). `go build`, `go vet ./...`, `go test ./parser` and `go test ./tests` clean.
New tests: a parser test that a class may declare `throw`/`return`/`async catch` members, and an
E2E where an outer async generator `yield*`s a user async-iterable with `throw`/`return` methods —
`it.throw(e)` forwards into `inner.throw` (recovers, keeps yielding), `it.return(v)` forwards into
`inner.return` (completes). The own-path fallback (an inner *without* those methods, ADR-00275) is
still covered and green. With this, the async-generators row is **strict**.
