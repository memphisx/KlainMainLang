# ADR-01309: spawnSync's stdin output slot, and stale BACKLOG items

- **Relations**: `Extends ADR-01228`
- **Date**: 2026-09-30

## Context

A sweep of the BACKLOG's open items re-ran each one's repro against Node
(macOS arm64). Several had been fixed by the builtin-module ports without
their lines being deleted. One (BACKLOG 55, `spawnSync`'s output) was fixed
except for one slot.

## Investigation

- 55: `spawnSync` returns Buffers without an encoding and strings with one,
  as Node does. But `output[0]` was an empty Buffer (or `''`), where Node has
  `null`. Node's `getValidStdio` marks stdin's pipe readable only (the child
  reads it), and `spawn_sync.cc` returns output only for the pipes the child
  writes.
- 30 (`[["a", 1]] as [string, number][]`), 36 (`process` as a
  `NodeJS.Process` parameter) and 38 (`typeof` a builtin module function) all
  match Node now.
- 39 (Math functions as values) is fixed by ADR-01307.

## Decision

`spawnSyncNormalized` (lib/node/child_process.ts) pushes `null` for stdio
slot 0 as well as for a non-pipe slot. BACKLOG 30, 36, 38, 39 and 55 are
deleted.

## Implementation notes

The fix is TypeScript only; the native spawn is unchanged.

## Side effects discovered

A `const { x = 1 } = …` probe in the same sweep led to ADR-01307's
destructuring changes.

## Verification

`TestE2ESpawnSyncOutputShape` (tests/childprocess_sync_options_test.go)
matches Node on macOS arm64. The deleted items' repros were run and compared
with Node on the same machine.
