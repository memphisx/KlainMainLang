# ADR-01166: Native primitives for builtin modules written in TypeScript, and companion modules

- **Relations**: `Implements [TDD-00231](../tdd/TDD-00231.md)` (stage 4); `Implements [TDD-00230](../tdd/TDD-00230.md)` (P3.2); `Extends [ADR-01161](ADR-01161.md)`, [ADR-01137](ADR-01137.md)
- **Date**: 2026-09-26

## Context

TDD-00231 stage 4 moves the fs streams and HTTP's request and response onto
the `stream` module written in TypeScript. Node's own fs streams
(`lib/internal/fs/streams.js`) are JavaScript over the callback
operations `fs.open`/`read`/`write`/`close`/`fsync`, which this compiler
did not have; a builtin module needed a way to call native, asynchronous
operations, and `fs` — a module code generation implements — needed a part
written in TypeScript beside it.

The `@lower` path (ADR-01137) lowered methods of builtin global objects
with number, boolean, string and `string[]` parameters only: no callback,
no byte buffer, no `Error` result, and no way for a builtin module to reach
a primitive a program cannot.

## Investigation

- A pool completion settles a Promise, whose reactions run as promise
  jobs. Node calls an fs callback from the poll phase through MakeCallback,
  which drains the tick queue and then the promise jobs on its way out: a
  `process.nextTick` queued by the callback runs before a promise job it
  queues. A `.then` over a pooled Promise inverts that order, so a native
  callback must be a completion of its own. Draining inside the pool
  dispatch itself resumed an HTTP handler's fiber outside the reactor's
  connection scan, which then never sent its response; the reactor's drain
  after the dispatch keeps Node's order for a lone completion (completions
  landing in one batch drain together).
- The collector scans globals, not the loop thread's thread-local
  completion port (Boehm does not scan macOS TLS as roots); a callback's
  closure, and the buffer it keeps, must stay reachable while a worker runs
  its syscall.
- `fs.createReadStream` resolved to a codegen member of the `fs` marker; a
  program's `fs.X` needs to reach an export of a TypeScript module instead
  for the members that module defines, and the codegen members for the rest.

## Decision

- **`lib/native.d.ts`** declares `interface KmlNative` and `declare var
  __kml_native: KmlNative`: the primitives the builtin modules call, each
  method with its `@lower` entry point. A program naming `__kml_native`
  gets TS2304 from the resolver's rename pass; only a file under
  `lib.ModuleRoot` may.
- **Lowering** (`emit_lowered.go`) now passes, by the declared parameter
  type: a `Uint8Array`/`Buffer` as its data pointer and byte length; a
  callback `(…scalars) => void` as an invoker and the closure, the invoker
  a per-site thunk (`__kml_lower_inv_N`) converting the runtime's values
  to the closure's own parameter representations through `emitCBCall`; an
  `Error` result as the error object.
- **Native operations** (`klainpool.c`): `KML_OP_NATIVE` work items carry
  their own work function; the completion `KML_CMP_CALL` calls
  `invoker(closure, errno, result)` on the loop thread, whose own drain then
  runs the tick queue and the promise jobs. A pending item is linked into a
  process-wide `native_live` list, a collector root.
- `__kml_pool_dispatch` reports whether a completion ran, and the reactor
  then pokes its parked connection fibers, as a fired timer does: a
  completion's callback may settle what an HTTP handler awaits. Without the
  poke a handler awaiting a Promise settled by a pooled operation (`await new
  Promise(r => fs.readFile(p, r))`) never answered — pre-existing, on both
  `http.createServer` and `klain:http`.
- The fs primitives are open, close,
  fsync, read and write (`pread`/`pwrite` for a position), `fsFlags` (Node's
  `stringToFlags`) and `fsError` (`__kml_native_fs_error`, the IR runtime's
  fs error object, factored out of `__kml_fs_throw2` as
  `__kml_fs_error_new`).
- **Companion modules**: `lib.CompanionPath(spec)` names
  `node/internal_<module>.ts` for a builtin module implemented in code
  generation. Importing the module visits its companion; the companion's
  exports resolve for a named import (`import { createReadStream } from
  'fs'`), a namespace member (`fs.createReadStream`, `new fs.ReadStream`,
  `fs.ReadStream` as a type) and a type-only import. Every other member
  stays the codegen one. `ModulePath` refuses `internal*` specifiers, as
  Node refuses `internal/…`.
- The dead `stream` special cases in the resolver (the class names bound as
  identity) and the pool's read-stream job (`KML_OP_READSTREAM`, the
  `STREAM_*` completions, the stream control block) are deleted; the pool's
  op ids after `READDIR` shift down by one in lockstep with
  `emit_fs_async.go`.

## Implementation notes

`lib/native.d.ts`, `lib/lib.go` (`CompanionPath`, the `internal` guard),
`resolver/resolver.go`, `resolver/virtual_modules.go` (`companionExports`,
type imports kept), `resolver/rename.go` (`nativeGlobal`),
`codegen/llvm/emit_lowered.go`, `codegen/llvm/runtime_native.go`,
`codegen/llvm/threadpool.go`, `codegen/llvm/threadpoolsrc/klainpool.c`,
`codegen/llvm/runtime_fs.go`.

The invoker is emitted through `beginThunkEmit`, so a callback's closure
is called with the same arity reconciliation and coercions as any
higher-order callback.

## Side effects discovered

The Windows side of the pool's positioned read and write (`_lseeki64` then
`_read`/`_write`) is unverified: this was built and run on the Mac only.

## Verification

Mac (Apple Silicon): a probe calling each primitive from a builtin module
matched Node's output, including the ENOENT error's message, code, errno,
syscall and path, and a tick queued in a native callback running before a
promise job. `tests/fs_stream_test.go` (15 programs, expected output from
Node v24) passes.
