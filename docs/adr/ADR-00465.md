# ADR-00465: URL component assignment is a clean rejection

- **Date**: 2026-08-29

## Context

Probing the Node oracle's `test-whatwg-url-custom-href-side-effect.js`
found `url.href = ''` compiling as a bare field store: real URL setters
re-parse and update every component (or throw TypeError on invalid
input), while here the write silently desynced the other derived fields —
the URL printed an empty href with stale components. Silent wrongness.

## Decision

Assignment to any component of a `URL` object is a compile-time rejection
naming the limitation ("construct a new URL instead"). URL parsing
happens inline at the `new URL(...)` site via curl_url; a real setter
would need that parse refactored into a runtime-callable path plus a
TypeError-on-invalid contract — deferred until something needs it beyond
this one corpus file. Rejection over silent desync per this project's own
practice.

## Verification

Mac. `tests/url_test.go` rejection test; URL E2E batch green. Neither
oracle number moves (the corpus file now fails at compile instead of
producing a wrong runtime result — honest either way).
