# ADR-00149: Nested function declarations (V1: hoisted, own scope, no capture)

- **Relations**: Implements [TDD-00057](../tdd/TDD-00057.md)
- **Date**: 2026-08-10

## Context

`docs/status/LANGUAGE-CONSTRUCTS.md`/`docs/status/README.md` tracked a `function` declaration written inside another function's body as a confirmed gap. [TDD-00057](../tdd/TDD-00057.md) scoped it directly against the source first: the parser and AST already handle it for free (a `function` keyword inside a block already parses into a normal `*ast.FunctionDeclaration`, already a valid `ast.Statement`); the only actual blocker was one explicit codegen rejection (`emit_stmts.go`'s `*ast.FunctionDeclaration` case). This ADR implements the TDD's design.

## Decision

Implemented exactly as scoped in TDD-00057: a nested function declaration written directly in an enclosing function/arrow-block body's own immediate statement list is hoisted (forward-referenceable, self-recursive, visible to its own further-nested descendants), does not capture the enclosing body's locals, and is rejected cleanly one block deeper (inside a further `if`/`for`/`while`/`switch`) or when generic or duplicate-named. See the TDD's Design section for the full reasoning, including why this reuses the two-pass top-level registration model rather than desugaring to an arrow-function-shaped closure.

## Implementation notes

- **`codegen/llvm/emitter.go`**: factored the per-declaration signature-building block out of `registerFunctions` into `buildFunctionSig(fd *ast.FunctionDeclaration) FuncSig` — one authoritative computation reused by both the existing top-level pass and the new nested pass.
- **`codegen/llvm/emit_func.go`**: new `nestedFuncEntry`/`nestedFuncScope` types, `Emitter.nestedFuncScopes`/`nestedFuncCtr` fields, and three new methods:
  - `pushNestedFuncScope(body []ast.Statement) error` — pre-scans `body`'s direct statements, assigns each nested `*ast.FunctionDeclaration` a unique mangled name (`fmt.Sprintf("%s__nested%d", fd.Name, e.nestedFuncCtr)`), builds its `FuncSig` via `buildFunctionSig`, and records it under both its source name (`byName`, for `resolveFuncRef`) and its own AST pointer (`byDecl`, so `emitStmt` can tell a pre-scanned declaration apart from a deeper, unsupported one). Rejects a generic declaration or a same-scope duplicate name.
  - `popNestedFuncScope()`.
  - `resolveFuncRef(name string) (string, FuncSig, bool)` — searches `e.nestedFuncScopes` innermost-first, falling back to the flat top-level `e.funcs` map.
  - `emitFunctionDeclAs` and `emitClosureFunc` (the arrow-function block-body path) each call `pushNestedFuncScope`/`defer popNestedFuncScope()` right after their own `e.pushScope()`, guarded on `decl.Body != nil`/`af.Block != nil` respectively. `emitFunctionDeclAs` is already fully reentrant (save/reset/restore of every per-function emitter field, already exercised recursively by TDD-00010 V1's on-demand generic instantiation), so a nested function's body is emitted by simply calling it recursively — no new emission path needed.
- **`codegen/llvm/emit_stmts.go`**: `emitStmt`'s `*ast.FunctionDeclaration` case now looks the statement up by AST-pointer identity in the current top `nestedFuncScopes` frame; a hit dispatches to `emitFunctionDeclAs` with the pre-registered mangled name/signature, a miss produces a clean "only supported directly in an enclosing function's own body" error.
- **Five call sites switched from a direct `e.funcs[<identifier>]` index to `resolveFuncRef`**, so a nested function's mangled name is used everywhere a bare identifier callee/callback is resolved: `emit_call.go` (direct call dispatch), `emit_exprs_types.go` (×2 — `inferExprType`'s bare-identifier-as-`IsFunc`-value case and its `CallExpression` return-type case), `emit_exprs_vardecl.go` (`emitVarDecl`'s own pre-inference switch), and `emit_func.go`'s `resolveCallback` (the single chokepoint `resolveCallbackWithHints`, every array HOF method, `setTimeout`/`setInterval`, `EventEmitter`, and `.replace()`/`.replaceAll()` callback resolution all funnel through). Confirmed via `grep -n "e\.funcs\["` that every remaining direct-index site is either the flat top-level registration writes themselves or an already-mangled generic-instantiation lookup (`emit_generics.go`), neither of which needed to change.
- **Ordering**: `resolveFuncRef` is checked before the existing `e.genericFuncs` lookup at each of the above call sites (its own internal search already ends with the top-level `e.funcs` fallback), so a nested function correctly shadows an unrelated top-level function or generic function of the same name — real JS/TS lexical-scoping shadowing, not a new special case.

## Side effects discovered

None — the change is additive (a previously-rejected construct now compiles under a narrower set of rules than real JS/TS allows) and touches no existing call path for a program that doesn't use the feature (`resolveFuncRef` falls straight through to the pre-existing `e.funcs[name]` lookup when `e.nestedFuncScopes` is empty, which it is outside any function/closure body).
