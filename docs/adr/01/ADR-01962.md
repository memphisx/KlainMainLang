# ADR-01962: The checker types nested generic functions before codegen erases them

- **Relations**: Implements TDD-00230 (P2.3)
- **Date**: 2026-10-29

## Context

Codegen compiles a generic function declared inside a block once, with its type parameters erased to `any` in its annotations (`lowerNestedGenericFuncs`). The erasure rewrites the declaration in place, before emission, and assumed the checker had typed every call site already. The checker types lazily, though: a symbol first asked about after the erasure read the erased declaration, so `last<T>(xs: T[]): T | undefined` became `(xs: any[]) => any` and calls of it were unanswered. Which reading a call got depended on the order of the asks. The erased body's own `T[]` had no representation either, because no instantiation binds `T` there.

## Decision

The checker types the whole program before the erasure (`warmFront`), as it already did before the local-class passes, whenever the program has a nested generic function. The erasure records the declarations it rewrites. Within those declarations, the front end represents a type parameter as `any`, as codegen compiles it.

## Consequences

- `examples/generics/nested_generic_functions.ts` reports no disagreement (nine rows before).
- Programs with a nested generic function pay for one eager checker pass.
