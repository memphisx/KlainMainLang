# ADR-01477: Invalid IR the Node suite's clang timeouts hid

- **Relations**: Extends ADR-01476
- **Date**: 2026-10-09

## Context

With the runtime objects and library modules compiled once per run
(ADR-01476), Node-suite files that used to hit the 30 s clang limit got
compiled, and some of them produced invalid IR: 6 files in the strict lane,
11 in the js lane. Each one was a compiler bug, not a test-harness problem.

## Investigation

Each file was compiled through the runner on the Linux box, with the IR kept
and fed to clang (`value doesn't match function result type 'i32'`,
`'%t' defined with type '{ ptr, i64 }' but expected 'ptr'`, `floating point
constant invalid for type`, `constant expression type mismatch`), then cut
down to a small program:

- A CommonJS top-level `return tls.createServer({})` was emitted as
  `ret ptr` inside `main`. Node ends the module's evaluation there and
  discards the value; the event loop carries on. TypeScript rejects a
  module-level return (TS1108); the checker did not.
- `http.get({ headers: ['k', 'v', ...] })`: Node's `RequestOptions.headers`
  is `OutgoingHttpHeaders | readonly string[]`, and `_http_client.js` sends
  an array's raw pairs as given, with no Host or Authorization of its own.
  The library declared only `OutgoingHttpHeaders`, and the checker let an
  array into that index-signature interface (TypeScript: TS2322, "Index
  signature for type 'string' is missing in type 'string[]'").
- `new Uint8Array([seq])` with `seq: number[]`: TypeScript reports TS2769.
  Three checker gaps let it through: an array against `Iterable<T>` or
  `ArrayLike<T>` only had its member names checked, not its elements; an
  array against a union of object types fell into the discriminated-union
  leniency (`maybe`); and an overload candidate whose inferred type argument
  breaks its constraint (`TArrayBuffer extends ArrayBufferLike`) counted as
  matching. In the js lane, the element (an array) was stored into the typed
  array without ToNumber.
- `console.count(1)`: the label was passed to the counter map as is; Node
  converts it with `` `${label}` ``.
- `.reduce((es, e) => es.concat(e), [])`: the accumulator slot was declared
  with the array type's `ptr` IR while an array value is its `{ptr, i64}`
  aggregate (strict lane too, with `[] as string[]`). In the js lane, the
  empty seed was typed `number[]`, so strings became NaN. A seedless reduce
  over arrays of arrays failed to compile ("initializer's type is
  incompatible"): the static type of its result was not the element type.
- `new Worker(__filename, { argv: 'foo' })` (js lane): a string stored into
  an `any[]` field; `coerciblePure` refused an array into a string slot but
  not a string into an array slot.

## Decision

- The resolver records each module-level `return` against its module's last
  statement (`ast.Program.TopLevelReturns`, resolver/resolver.go
  `appendModule`); code generation evaluates the value, discards it and
  branches past that statement. The checker reports TS1108 outside
  -compat=js.
- `RequestOptions.headers` is `OutgoingHttpHeaders | readonly string[]`;
  `ClientRequest` stores an array's pairs as the header block directly.
- Checker (checker/relate.go): an array, tuple or function never fits a
  non-`any` string index signature; an array or tuple against a number
  index, `Iterable<T>`, `IterableIterator<T>` or `ArrayLike<T>` relates its
  elements; arrays and tuples are excluded from the union leniency.
  checker/overloads.go: a candidate whose argument alone answers a
  constrained type parameter must meet the constraint.
- A typed array's non-numeric element is stored as its ToNumber after
  ToPrimitive (`coerceTypedArrayStore`).
- Console labels go through ToString (`consoleLabelArg`); an `undefined`
  label is the default `'default'`.
- reduce: the accumulator slot is the value's register shape
  (`accSlotIR`); the js lane's empty `[]` seed is `any[]` in both the
  emitter and the static type (`reduceSeedType`); a seedless reduce's
  result is the element type.
- `coerciblePure` refuses a string, number or boolean into an array slot, so
  the js-lane case is a clean compile error.

## Side effects discovered

- BACKLOG 157: -compat=js with an annotation or field type its value
  contradicts keeps the declared representation; JavaScript semantics make
  the binding hold the value (`new Worker(f, { argv: 'foo' })` should reach
  the library's ERR_INVALID_ARG_TYPE check).
- BACKLOG 158: `console.countReset` never emits Node's "Count for '<label>'
  does not exist" warning.

## Verification

- tests/toplevel_return_test.go, array_relations_test.go,
  reduce_seed_test.go, js_conversions_test.go, http_raw_headers_test.go
  (Node as the oracle where the program runs); examples/jsmode/
  top_level_return.js. Each Node-suite file above compiles to valid IR on the
  Linux box.
- Two false rejections the first version of the checker rules made were
  caught by the examples and test-par: `new Headers([['a', 'b']])` (a union
  with an array member keeps the array literal's contextual element types)
  and `entryTypes: ['mark']` (a widened string element against a literal
  union).
- Gates: as ADR-01476.
