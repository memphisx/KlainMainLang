# ADR-01307: `@intrinsic` globals and builtin functions as values

- **Relations**: `Implements part of TDD-00230` (P3.2), `Extends ADR-00573`
- **Date**: 2026-09-30

## Context

P3.2 of TDD-00230 moves builtins off name-dispatch in `emit_call.go` and
onto their declarations. `Math` already used `/** @intrinsic Math.x */`. The
`Number`/`String` statics and the global functions (`parseInt`,
`parseFloat`, `isNaN`, `isFinite`, the URI functions, `btoa`/`atob`) were
still matched by name at the call site and again in `inferExprType`.

Moving them surfaced a larger gap. A builtin used as a value did not compile:
`['1', '2'].map(parseFloat)`, `const f = Math.floor`, `[4, 9].map(Math.sqrt)`,
`String.fromCharCode` passed to a method. The errors were "'parseFloat' is not
a callable" and "callback must be an arrow function or function identifier".
Probing those paths against Node showed that the array methods did not pass
callbacks their extra arguments. `reduce` gave no index, and `some`/`every`/
`find`/`findIndex` gave neither the index nor the array. `map` and `filter`
gave no array. So `[5, 6].reduce((a, x, i) => a + i, 0)` was 0, not 1.

## Investigation

- A `declare function` dropped its JSDoc: `parseAmbientDeclaration` never
  took the pending doc comment, so `@intrinsic` on `parseInt` was invisible.
- `loweredCall` only resolved member callees (`Math.sin`). A global function
  is an identifier bound in the binder's global scope, and its declaration is
  a `FunctionDeclaration`.
- Named functions already become values through a static `{trampoline,
  null}` closure header (`emitNamedFuncValue`). The header gives each function
  one identity, so a builtin needs a real LLVM function to point that header at.
- The rest intrinsics (`Math.max/min/hypot`, `String.fromCharCode/
  fromCodePoint`) have to take a spread for the value function to forward its
  rest array. `min`/`max` already folded spreads. `hypot` was a fixed two-operand
  libm call, and `fromCharCode` rejected spreads and any non-number argument
  (a divergence recorded in ADR-00195).
- `Math.*` did not ToNumber an `any` operand; it coerced the box's bits.
  `__kml_toprimitive` passed arrays through unchanged, so `+[-2]`,
  `isNaN([1])` and `[-2] == '-2'` all diverged.

## Decision

- `/** @intrinsic name */` is read on an ambient `declare function`
  (`FunctionDeclaration.Intrinsic`). `loweredCall` resolves an identifier
  callee bound in the global scope to its intrinsic.
- The following are now intrinsics, and their name-dispatch and inference
  cases are deleted:
  - `parseInt`, `parseFloat`, `isNaN`, `isFinite`
  - `encodeURI`, `decodeURI`, `encodeURIComponent`, `decodeURIComponent`
  - `btoa`, `atob` (now declared in `lib/node.d.ts`, as Node's globals)
  - `Number.isInteger/isFinite/isNaN/isSafeInteger`
  - `String.fromCharCode/fromCodePoint`

  `Number.parseInt`/`parseFloat` are tagged with the global's key, because the
  spec makes them the same function objects.
- A builtin referenced by value (`builtinRef`) is either an intrinsic or a
  global object's non-overloaded `@lower` method. It is materialized once as
  `@__kml_builtin_fn_<key>`:
  - An intrinsic takes `any` parameters (a rest one `any[]`) and its body is
    the intrinsic call.
  - A lowered method takes its declared representations and its body is the
    lowered call.

  `emitNamedFuncValue` gives it its static header, so every reference is the
  same value. The name is the builtin's own. The length is the declaration's,
  or the spec's where the two differ (`Math.max` is 2).
- The value is emitted in three places: `emitExpr` (identifier and member),
  `resolveCallback`, and `inferExprType`, which answers the function's type.
- `hofCBArgs` builds every array method's callback arguments: the leading
  ones, then the index and the array when the callback takes them. It is used by
  map, forEach, filter, reduce/reduceRight, find, findIndex, findLast,
  findLastIndex, some and every. Their type hints include the array.
- `Math.hypot` is variadic and computes as V8 does (`@__kml_hypot`): scaled by
  the largest magnitude, with a compensated sum. `emitNumberArgsBuffer`
  ToNumbers a variadic builtin's arguments into doubles, filling a heap buffer
  at run time when there is a spread. `fromCharCode`/`fromCodePoint` use it,
  which removes ADR-00195's rejection of non-number arguments.
- A `Math` operand that is not a static number is ToNumber'd
  (`emitUnaryPlus`), and so is a non-number element in a `min`/`max` spread.
  Global `isNaN`/`isFinite` ToNumber through `emitUnaryPlus` as well.
- `__kml_toprimitive` turns an array (tag 7, or 11 for a dynamic array) into
  its join, which is Array.prototype.toString.
- Array methods are intrinsics too. The following are tagged
  `@intrinsic Array.prototype.x` on `Array`, `ReadonlyArray` and every typed array's
  declaration:
  - `map`, `filter`, `reduce`, `reduceRight`, `find`, `findIndex`,
    `findLast`, `findLastIndex`, `some`, `every`, `forEach`, `flatMap`
  - `join`, `sort`, `flat`, `reverse`, `toReversed`, `toSorted`,
    `toSpliced`, `with`, `copyWithin`, `fill`, `slice`
  - `indexOf`, `lastIndexOf`, `includes`, `at`, `concat`, `keys`, `values`,
    `entries`
  - `push`, `pop`, `shift`, `unshift`, `splice`

  The String methods that take a RegExp or a replacer callback are
  `@intrinsic String.prototype.x`: `search`, `localeCompare`, `replace`,
  `replaceAll`, and `split`'s RegExp overloads (its string overload keeps its
  `@lower`). `match`/`matchAll` stay name-dispatched, since the builtin
  declarations do not declare them yet.

  Their name-dispatch in `emitCall` is deleted.
  `methodIntrinsic` resolves a method call's intrinsic from the checker's
  member declaration, whatever declares it. An Array intrinsic applies only to
  a regular array codegen holds statically, so a `@value` array, a bigint typed
  array's rejected method, or a dynamic receiver still reaches its guard. Their
  types come from `inferMethodNameType`, the method-name inference extracted
  into a function. The name-dispatch stays as the fallback, as the TDD's
  migration rule has it, for receivers no declaration reaches:
  - a Buffer's own `slice`/`fill`/`indexOf`
  - a receiver the checker cannot type
  - `flat`, which the declarations lack

  Using `Array`'s member for an untyped receiver was tried and dropped. At
  that point codegen's inference of an `any`-declared local is not reliable
  (a string held in `any` read as a Buffer).
- An instance intrinsic's key has the spec's `Owner.prototype.name` form.
  It is never materialized as a function value, because it needs its receiver.
- `.bind` accepts `any` parameters. Each one is a NaN-boxed word in one
  8-byte env slot, so `parseInt.bind(null)` and binding a function over `any`
  work.
- A typed array's `map` and `filter` return the receiver's own kind, as
  %TypedArray%'s species does. A Buffer maps to a Buffer, and a Uint8Array
  filters to a Uint8Array, not a plain array.
- The checker types `globalThis.X` as the global `X` (`namespaceMember`),
  keeping its declaration. So `globalThis.Math.max(…)` and `[1].map(
  globalThis.parseFloat)` reach the declaration. Before, the checker left
  `globalThis` untyped, and codegen rewrote the callee into a synthetic `Math.max`
  that no declaration resolved. `isBuiltinGlobalObject` accepts `Math`,
  `globalThis` and `globalThis.Math`.

- `str.split(regexp)` splices the separator's capture groups in after each
  piece, as `@@split` does. The scan keeps each match's PCRE2 match data for
  its callback, and the count pass adds the pattern's capture count per split
  point.
- An unmatched capture group is `undefined` (a null element) in `exec`,
  `match` and `matchAll` results, in split results, and in a replacer
  callback's arguments (typed `string | undefined`). A `$n` template splices it
  as `""`, and `join` renders any null or undefined element as `""`.

- A destructuring default replaces `undefined` only (in the declaration and
  assignment forms). A field that never holds `undefined` (`T | null`, or a
  non-nullable one) keeps its value, and its default is neither evaluated nor
  rejected (tsc accepts `const { x = 1 } = { x: 5 }`). A destructured array
  field binds the field's own array (one header), or null.
- A `null`/`undefined` literal asserted to a type that holds it
  (`undefined as number | undefined`), or a value asserted to its own type
  widened with null or undefined (`[1] as number[] | undefined`), takes the
  asserted type (`nullAssertedType`), so an object literal's field keeps
  the declared optionality.
- BACKLOG 17, 18 and 23 are fixed: the default on null, the invalid IR of a
  nullable-scalar element default, and a `string | RegExp` separator (split
  now dispatches on what the box holds).

## Implementation notes

- `ensureBuiltinFunc` emits its body in a detached function. The parameters
  are bound as `__kml_ia<i>` codegen locals and passed to the builtin's emitter
  as synthetic identifiers. A rest parameter arrives as its array header and
  length (the rest ABI), and the header is stored as-is.
- `builtinRef` filters by syntax before asking the checker, because
  `inferExprType` reaches it for every identifier and member.
- `ensureAnyToPrimitive` now links the dynjson C unit for the joins.

## Side effects discovered

- BACKLOG 119 is narrowed to `exec`/`match` results lacking `index`/`input`/
  `groups`, which needs an array carrying named properties (P3.3).

- `JSON.stringify` of a string with an embedded NUL still truncates at the NUL.
  This is the null-byte-string item in BACKLOG §0.
- A non-BMP string's `length` counts UTF-8 bytes (`String.fromCodePoint(
  0x1F600).length` is 4). This is unchanged.

## Verification

- `tests/builtin_function_values_test.go` (`TestE2EBuiltinFunctionValues`,
  `TestE2EArrayCallbackIndexAndArray`, `TestE2EMathVariadicToNumber`) matches
  Node.
- `TestE2EGlobalThisMath` (which regressed when `Math` left name-dispatch)
  passes again.
- The probes behind this record, including a `-compat=js` probe of untyped
  array receivers, typed arrays and Buffer, were compared with Node output on
  macOS arm64.
