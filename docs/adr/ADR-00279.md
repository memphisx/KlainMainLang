# ADR-00279: Object-literal `[Symbol.asyncIterator]` as a `for await` iterable

- **Relations**: Extends [ADR-00269](ADR-00269.md) ([Symbol.asyncIterator] classes), [ADR-00277](ADR-00277.md) (for-await iterable coverage)
- **Date**: 2026-08-21

## Context

The `[Symbol.asyncIterator]` protocol required both the iterable and its
iterator to be class instances; an object literal carrying the method —
`{ [Symbol.asyncIterator]: () => gen() }`, the common ad-hoc adapter shape —
was unsupported, because a computed property key collapses the whole literal to
a dynamic `Map<string,V>` and object-literal properties are plain values, not
`this`-bound methods.

## Investigation

- `parser/parser_literals.go`'s computed-key branch (`[expr]: value`) always
  produced a `KeyExpr` property, which `inferObjectType` routes to the dynamic
  Map representation — unusable for protocol dispatch.
- The class grammar already solved the same problem by desugaring the
  well-known symbol to a reserved *static* name (`@@asyncIterator`), keeping
  everything else structural.
- Object-literal method shorthand already desugars to a `FunctionExpression`
  value and closure fields are callable, so a closure-typed `@@asyncIterator`
  field needs no new calling machinery (`emitClosureCallByPtr`).

## Decision

- The parser recognizes a well-known-symbol computed key in an object literal
  (`wellKnownSymbolMemberName`, shared with the class grammar) and stores it as
  a *static* `@@asyncIterator`/`@@iterator` key, so the literal stays a static
  struct. Both `[Symbol.asyncIterator]: fn` and the method-shorthand
  `[Symbol.asyncIterator]() {...}` forms parse.
- `for await` dispatch: a static object type with an `@@asyncIterator`
  function-typed field loads the closure from the field and calls it, then
  iterates the result by its type — an async generator
  (`emitForAwaitOfGenerator`), a sync generator
  (`emitForAwaitOfSyncGenerator`), a class with its own `[Symbol.asyncIterator]`
  (`emitForAwaitOfAsyncIterable`), or directly an iterator class instance.
- **`emitForAwaitOfAsyncIteratorInstance`** — the loop half of
  `emitForAwaitOfAsyncIterable` split out, so a directly-returned iterator
  instance (no `[Symbol.asyncIterator]` of its own) enters at the `next()`
  validation.
- The sync twin comes for free: an object literal with a `[Symbol.iterator]`
  member is consumable by sync `for...of` (returning a sync generator or a
  `[Symbol.iterator]` class instance) and by `for await` (values awaited),
  through the same shared dispatcher (**`emitForOfObjectSymbolIterable`**) —
  the parser desugar accepting both symbols would otherwise have produced a
  field no loop consumed.

## Implementation notes

- `parser/parser_literals.go`: well-known-symbol branch inside the computed-key
  case of `parseObjectLiteral`.
- `codegen/llvm/emit_stmts.go`: the `s.Await` object branch (GEP + load the
  closure header, `emitClosureCallByPtr`, dispatch on the returned type).
- `codegen/llvm/emit_generators.go`: `emitForAwaitOfAsyncIterable` split.
- `this` inside the literal's method body stays the pre-existing clean
  rejection object literals have always had — the adapter shape captures via
  the closure environment instead.

## Side effects discovered

- A top-level `const` object holding a closure-typed field is not promoted to a
  module global (the [TDD-00093](../tdd/TDD-00093.md) promotable-shape rule),
  so such an iterable must be declared in function scope (or used at top
  level) to be seen inside an async fn — the same pre-existing promotion limit
  every closure-field object has (`o.f()` on a top-level `o` inside a function
  is "only simple function calls are supported" today, independent of this
  work).

## Verification

- New E2E `TestE2EForAwaitObjectLiteralAsyncIterator`: arrow-valued member
  returning an async generator, method shorthand returning a sync generator,
  and an arrow returning a class-instance iterator; and
  `TestE2EForOfObjectLiteralSymbolIterator` for the `[Symbol.iterator]` twin in
  both loops.
- `examples/async/for_await_iterables.ts` covers the arrow form.
- `go build`, `go vet ./...`, full `go test ./...` green; `make examples` and
  `make conformance` run at delivery. Apple Silicon (macOS).
