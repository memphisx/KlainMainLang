# ADR-02006: An arguments object's callee and own Symbol.iterator

- **Date**: 2026-11-21

## Context

`arguments.callee` read undefined, and strict code's did not throw.
Reflection on an arguments object (`Object.getOwnPropertyNames`,
`getOwnPropertySymbols`, `Reflect.ownKeys`, `getOwnPropertyDescriptor`,
`hasOwnProperty`, `Object.hasOwn`) left out its own `callee` and
`Symbol.iterator` properties (ECMA-262 §10.4.4.6–7).

## Decision

- When the program reads `callee` (as a member or a string key) or reflects
  on `arguments` itself, a function that builds an arguments object records
  its callee beside it, in a hidden binding:
  - for a declaration, its own value;
  - for a function expression, the closure itself, captured the way a named
    expression's own name is.
  Strict code records only that it is strict.
- `arguments.callee` reads the binding. In strict code it throws the
  restricted-property TypeError.
- Reflection calls whose argument is the function's own arguments object
  lower to library forms that add `callee` and `Symbol.iterator`:
  - `callee` is writable and configurable with the function as its value,
    or in strict code an accessor whose get and set throw;
  - `Symbol.iterator` is `Array.prototype.values`;
  - both are non-enumerable.
- A function that rebinds `arguments` records no callee.

## Implementation notes

- codegen/llvm/emit_func.go: `argumentsReflected`, `defineArgumentsCallee`,
  `ownArguments`, `argumentsReflectCall`, the self capture in
  `emitFunctionExpression`; codegen/llvm/emit_dynfunc.go: the same for a
  dynamic callable; codegen/llvm/emit_exprs_member.go: the `callee` read;
  codegen/llvm/emit_call.go: the reflection route.
- lib/node/kml_array.ts: `__kml_args_*`.
- An arrow reading its enclosing function's `arguments.callee` still reads
  undefined (the hidden binding is not captured).
