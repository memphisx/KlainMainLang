# ADR-01763: `instanceof Object`, `Function` and `Symbol` on any value, and builtin constructors held in a variable

- **Relations**: `Implements TDD-00230`, `Extends ADR-00605`
- **Date**: 2026-10-20

## Context

- `x instanceof Object` on a value held in `any`, a union or a nullable was a compile error (ADR-00605 kept it as a "clean rejection").
- `x instanceof Function` and `x instanceof Symbol` were compile errors ("'Function' is not a registered class").
- `x instanceof F` with `F` holding a builtin constructor (`chk(Map)`, `chk(Object)`) answered `false` for every value. The run-time dispatcher (`__kml_dyn_instanceof`) had rows only for the Error kinds and user classes.

Test262 uses all three forms throughout the `Object` built-in tests.

## Decision

- `instanceof Object` on a box calls `__kml_instanceof_object` (dynobj.c). A dynamic object is one when its prototype chain reaches `Object.prototype`, so a null-prototype object and `Object.prototype` itself are not. Every other object or function box is one, and a primitive is not.
- `instanceof Function` is true for a function or class: by static type, or for a box by its function tags. `instanceof Symbol` is false: it holds only for a Symbol wrapper object, and there are none yet.
- `ctorRefTargets` also lists the builtin constructors `instanceof` decides (`Object`, `Function`, `Symbol`, and `builtinInstanceofTypes`: `Array`, `Map`, `Set`, `Date`, `RegExp`, `Promise`, `Buffer`, the streams and typed arrays). A constructor reference to one of them boxes as its interned name, as an Error kind's does, so the dispatcher answers it through the same `emitInstanceOf` the static form uses.

## Consequences

- `TestE2ECompatJSInstanceofBuiltinCtors` covers the static and held-in-a-variable forms. The status row has no caveats left.
