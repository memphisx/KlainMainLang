# TDD-00137: `Function.prototype.call` / `.apply` / `.bind`

- **Status**: Implemented (Stages A–C) — `.call`, `.apply` (literal + runtime-array-into-rest), `.bind` (partial application). See [ADR-00398](../adr/ADR-00398.md).
- **Date**: 2026-08-27

## Context

`only simple function calls are supported` (emit_call.go's final fallback) is the
**single largest** blocker in the Node `test/parallel` oracle (282 files). A
confirmed, common instance is dynamic invocation via `Function.prototype`'s
`call`/`apply`/`bind` — e.g. `fn.apply(net, args)`, `cb.call(this, x)`,
`handler.bind(null, id)`. These are core JS reflection, used pervasively in real
code (not just tests), so closing them is a genuine front-end lever, not a
per-module API.

## The hard part: `this`

`call`/`apply`/`bind`'s defining purpose in JS is **rebinding `this`**. This
compiler's functions have no rebindable `this`:

- Free functions and arrow/closure values take no `this` parameter.
- Class methods take `this` as a fixed first parameter, dispatched structurally —
  there is no mechanism to invoke a method value against an *arbitrary* receiver.

So a faithful "borrow method `m` and run it with `this = other`" is **out of
scope** — this compiler has no first-class method values to borrow, and no
`this`-slot on closures to overwrite. What *is* tractable, and covers the
dominant real use, is the **argument-plumbing** use of call/apply on a
function-typed *value* (a closure, a function parameter, a function expression),
where `thisArg` is `null`/`undefined`/an ignored namespace object. That is what
`fn.apply(net, args)` and `cb.call(null, x)` actually do: spread arguments into a
free function.

## Decision (V1 = Stage A)

For a receiver whose static type `IsFunc` (a first-class function value):

- **`fn.call(thisArg, a, b, …)`** lowers to a direct closure call `fn(a, b, …)`
  — `thisArg` is **evaluated then discarded** (preserving any side effect) since
  the callee has no rebindable `this`. The trailing arguments are type-checked
  against `fn`'s parameter types exactly as a normal call (reusing
  `emitClosureCallByPtr`).
- **`fn.apply(thisArg, [a, b, …])`** with a **literal array** second argument
  lowers identically to `fn(a, b, …)`.

Everything else is a clean compile error for now (not silent misbehavior):

- **`fn.apply(thisArg, runtimeArray)`** (Stage B) — a runtime args array is
  variadic spread; tractable only when `fn` has a single rest parameter matching
  the array's element type (`fn(...arr)`). Deferred.
- **`fn.bind(thisArg, …bound)`** (Stage C) — must synthesize a *new* closure that
  captures the bound leading arguments (partial application) and forwards the
  rest. A real new-closure-construction stage. Deferred.
- **call/apply/bind on a non-first-class callee** (a builtin like
  `net.connect.apply(net, …)`) — builtins aren't function values here, so there
  is nothing to invoke indirectly. Out of scope until/unless builtins become
  first-classable.
- **A non-ignored `thisArg`** intending method-borrow — unsupported by
  construction (documented), since there is no `this` to rebind.

## Staging

- **Stage A** — `.call` + literal-array `.apply` on a function value → direct
  call, `thisArg` discarded. (This document's implemented scope.)
- **Stage B** — `.apply(thisArg, runtimeArray)` into a rest-parameter function.
- **Stage C** — `.bind` as partial-application closure synthesis.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| First-class function/closure values (`IsFunc`, header `{fn,env}`) | Built | `emitClosureCallByPtr` — the lowering target |
| Call-site argument type-checking + coercion against `FuncParams` | Built | Reused unchanged, so args are validated as a normal call |
| Rest-parameter closures (`FuncHasRest`) | Built | The Stage B hook (variadic apply) |
| New-closure synthesis with captured env | Built (arrow/function-expr path) | The Stage C hook (bind) |

## Open questions

- Stage C `bind`: reuse the arrow-closure env-struct builder to pack the bound
  args, or a dedicated partial-application trampoline? The bound function's arity
  is `fn`'s arity minus the bound count — expressible as a new `IsFunc` type.
- Whether to accept a non-null `thisArg` silently (ignore) or reject it. V1
  ignores it (matching the arg-plumbing intent); a stricter mode could warn.
