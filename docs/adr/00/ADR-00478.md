# ADR-00478: adapter aggregate coverage; any-boxed arrays keep their length

- **Relations**: Completes [ADR-00477](ADR-00477.md); Extends [ADR-00375](ADR-00375.md)-era boxing (TDD-00062) and TDD-00064's nullable scalars
- **Date**: 2026-08-29

## Context

ADR-00477's closure adapters excluded aggregate positions (arrays' split
`(ptr, len)` ABI, nullable scalars' `{ i1, T }`) and rest slots — those
kept the unadapted passthrough. Rare, but a passthrough at a
dynamism-mismatched aggregate position is the same silent
reinterpretation the ADR exists to kill. Doing it properly required a
representation fix first: the dynamic box stored only an array's *data
pointer* ("length documented-lost"), so any→array was inexpressible.

## Decision

**Representation**: `emitBoxValue`'s array case now boxes a heap
`{ ptr, i64 }` *header* holding the full aggregate — the exact 16-byte
shape the nested-array element box (`boxArrayValue`) already uses — so
the length survives the round trip. `__kml_any_eq`'s array case compares
the *data pointers inside* the headers (two boxings of one array malloc
two headers; the data pointer stays the per-array identity, so
`x1 === x2` for one array is still true and distinct arrays still
compare false). `typeof` and the `[object Array]` toString are
tag-only and unchanged; the element type is still not carried.

**Unboxing**: `emitUnboxBoxToType` gains two cases — `target.IsArray`
(header → loaded aggregate, with a null-payload guard yielding the
`{null, 0}` empty sentinel) and nullable scalars (a null/undefined tag →
the absent aggregate; anything else unboxes the payload and wraps it
present).

**Adapter**: `funcAdapterPlan`/`emitClosureAdapter` now cover arrays
(forwarded through the split ABI; boxed/unboxed via the header at
dynamism boundaries — including array *returns*), nullable scalars
(both directions, params and returns), and rest slots (forwarded when
both sides carry a same-element rest tail; a source-only rest receives
the empty `(null, 0)` tail; a target-only tail is dropped). The
remaining unsupported set is only genuine type errors
(concrete-vs-concrete shape mismatches) and void→concrete returns.

## Bugs found in passing (both pre-existing, both fixed)

1. An expression-bodied arrow with a nullable-scalar return type emitted
   the bare payload where the `{ i1, T }` aggregate was expected — a hard
   clang error (`(x: number | null): number | null => x` didn't compile
   at all). The arrow shortcut now mirrors `emitReturn`'s presence-aware
   `emitNullableScalarBoxedValue` branch, so `id(null)` returns absent.
2. `coerce` treated a bare scalar and its nullable aggregate as identical
   (`Type.IR` is the bare T for both) and passed the payload through
   unwrapped; it now wraps a bare scalar present into a nullable target.

Disclosed edge: an *absent* nullable boxed into `any` reads as
`undefined` (the established absent-value convention), so
`console.log(g(null))` on an any-returning adapter prints `undefined`
where JS prints `null`.

Also fixed mid-review: the plan's void→any return case was ordered after
the generic dynamism check and got misclassified as unsupported —
caught by this ADR's own matrix test in the full run.

## Verification

Mac. `tests/dynamic_test.go`: `TestE2EClosureAdapterAggregates` (arrays
both directions incl. an array *return* unboxed back to a real
`.length`-bearing array, nullable both directions, boxed-array identity
positive and negative) and `TestE2ENullableScalarExpressionArrowReturn`
(the pre-existing clang error, now `7`/`null`). **Full `make test-par`
green** (the representation change touches `===`/`typeof`/boxing
everywhere; only the two standing embed-fixture cwd artifacts remain).
Both oracles unchanged (TS 56.8%, Node 40) — this is a correctness
change below the accept/reject surface.
