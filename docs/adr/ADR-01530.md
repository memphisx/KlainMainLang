# ADR-01530: An evolving binding starts its container undefined

- **Relations**: Extends TDD-00162, TDD-00230
- **Date**: 2026-10-10

## Context

An unannotated binding declared without a value evolves: each read is
the flow type of the stores reaching it. A `let`'s declaration is itself
a flow assignment of `undefined`, but a hoisted `var` has none, so a
read whose flow reaches the container's start fell back to the storage
type, the union of every store, unreachable ones included:
`var b; do { break; b = "w" } while (c)` read `b` as
`string | undefined` where tsc says `undefined`.

The JavaScript call-site parameter collectors also ran before the
globals were registered, so such a binding passed as an argument was
typed by its flow there while emission reads its `any` storage.

## Decision

- `initialType` of an evolving binding is `undefined` (tsc's initial
  type for an auto-typed declaration).
- The constructor-argument collector binds an untyped, uninitialized
  top-level binding as `any`, as the function-argument collector does,
  and both collectors are analysis passes (their reads are not
  compared with the checker's).
