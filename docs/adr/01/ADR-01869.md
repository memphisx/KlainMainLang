# ADR-01869: `this` in an object literal's method, and its receiver through optional calls

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's ObjectLiteral bucket)
- **Date**: 2026-10-21

## Context

- tsc gives `this` in an object literal's method the literal's contextual type, else the literal's own type (getThisTypeOfObjectLiteral), so `const a = { b() { return this._b; }, _b: { c: 42 } }` has `b(): { c: number }`. The checker left that `this` unanswered, and with it every method result reading it.
- Codegen calls such a method with its object as a leading `this` argument. `a.b?.()`, `(a.b)?.()` and `(a?.b)?.()` called the field's value through a temporary instead and passed `undefined` (Node prints 42; the program threw a TypeError), an existing bug.

## Decision

- While an object literal with methods is typed, `this` in its methods is a partial snapshot of its other properties. A `this` that read the snapshot is asked again afterwards and gets the finished type.
- The oracle answers `this` in a method shorthand that reads it as the method's own boxed `this` parameter, which is how codegen holds it. A `const` binding of such a literal answers as its declaration does, and a read of a method field taking its `this` answers as the field holds it.
- An optional call of a method field taking its `this` binds the receiver once and calls through a member read on it. This covers the plain path, the chain path and `emitFuncFieldCallReceiving`.

## Consequences

- `TestObjectLiteralMethodThis` holds tsc 5.6's declaration types; `TestE2EObjectLiteralMethodThisOptionalCalls` matches Node; Test262's `optional-call-preserves-this.js` passes in both lanes.
- Verified on Apple Silicon.
