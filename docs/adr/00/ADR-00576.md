# ADR-00576: Buffer.alloc accepts a string fill

- **Relations**: Extends ADR-00559

- **Date**: 2026-09-01

## Context

`Buffer.alloc(size, fill)` accepted only a numeric byte fill (a `memset`); a
string fill (`Buffer.alloc(5, "ab")` → `ababa`) was a clean rejection. Real Node
repeats the fill string's bytes across the buffer, and 13 files in the Node
conformance suite tripped on the rejection (the top compile-error bucket after
this batch).

## Decision

`buf.fill(string)` already repeated a needle's UTF-8 bytes across a range
(ADR-00559). Factor that loop into `emitBufferRepeatFill(bufPtr, needle,
needleLen, start, end)` and call it from `Buffer.alloc` when the fill argument is
a string (`start = 0`, `end = size`) — after the `calloc`, so a zero-length fill
string leaves the buffer zero-filled. A numeric fill still `memset`s; any other
fill type is a clean rejection.

## Side effects discovered

None. `buf.fill(string)` is unchanged (it now calls the shared helper), and the
numeric-fill and no-fill paths are untouched.

## Verification

New `TestE2EBufferAllocStringFill` (`"ab"`→`ababa`, `"x"`→`xxxx`, `"abc"`→
`abcabc`, and a numeric fill still `AAA`), plus the existing Buffer suite; output
compared against real Node. Built and verified on Mac (Apple Silicon).
