# ADR-01963: The front end answers synthesized declarations, generic function types and constrained callbacks

- **Relations**: Implements TDD-00230 (P2.3, P3.3); follows [ADR-01961](ADR-01961.md)
- **Date**: 2026-10-29

## Context

The shadow report reached zero disagreements over its corpus: 480 compiles of the examples, tools and apps, with 35,548 top-level bindings compared between codegen's `decideGlobalType` and the front end. A scan of that corpus for the bindings the front end could not answer listed:

- the declarations codegen synthesizes for an enum's object, a namespace's object and an enum's computed member, whose `any` and `number` annotations carried no type node the checker could read;
- `var idf: <T>(x: T) => T`, a generic function type, which the checker left unanswered.

Switching `reliableGlobalType` to the front end then failed the E2E suite, whose programs are outside the shadow corpus:

- bindings the front end left unanswered (`const o = { n: function () { return o.m(); } }`) or answered differently (the result of `await import(…)`, an asserted tuple array, `Date["UTC"]` under `-compat=js`);
- `http.createServer(mustCall((req, res) => …))`, whose type depended on the order of the checker's queries.

## Decision

- `decideGlobalType` stays the decider. It switches when the shadow corpus includes the E2E programs and agrees there too.
- `ast.AnyAnnotation` and the enum computed-member annotation carry their type nodes. The front end answers a synthesized declaration, which the binder never bound, from its annotation. The bare `[]`, `new Map()` and `new Set()` that the front end typed by asking `decideGlobalType` read codegen's pre-pass directly.
- The checker types a generic function type through its own type parameters, as a signature member's are typed (`signatureOfNodes`). The front end represents such a signature, which is not a declaration's, with those type parameters erased to `any`, as codegen compiles a value of it.
- A function argument whose contextual type is an uninferred type parameter is typed by the parameter's constraint (`(...args: any[]) => any`). A generic overload candidate gives a context-sensitive argument its context, through the call's own context when its result is that type parameter (tsc's return-type inference).
- A query that met another still being computed (a symbol resolving, an overload pick in progress) and ended unanswered is not cached, as an expression or as a symbol type. Asked again after the cycle closes, it may be answered.

## Consequences

- `const g = mustCall((a, b) => …)` is `(a: any, b: any) => void`, and `const idf: <T>(x: T) => T` has its signature, as tsc reports.
- `TestE2EProcessEnvEnumeration` read `copy.KML_ENUM_A` from `{ ...process.env, KML_ENUM_C: "3" }`, which tsc rejects (TS2551). It now annotates the copy as `NodeJS.ProcessEnv`, as `examples/os/os_info.ts` does.
- The shadow report's next corpus adds the E2E programs.
