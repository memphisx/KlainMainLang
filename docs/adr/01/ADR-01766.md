# ADR-01766: Array patterns over Sets, Maps, tuple elements and iterable loop elements

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

Destructuring an iterable that is not an array failed in several places. Test262's for-of and for-await destructuring tests hit them by the hundred:

- `const [a] = new Set([7])` and `const [[k, v]] = map` were compile errors ("array destructuring needs an array, a string or an iterable").
- A nested pattern over a tuple element (`const [[k, v]] = pairs` with `pairs: [string, number][]`) was "cannot array-destructure a non-array element".
- A for-of or for-await head pattern over an element that is not an array or a tuple (a Set, a value held in `any`, an object with `[Symbol.iterator]`) was a compile error at eight sites, in plain functions and in generator and async frames.
- `[new Set(…), new Map(…)]` was typed as an array of the first element's type, so the Map element iterated as a Set (`[...e]` gave its keys). `elemKindKeyBroad` put every host type in one "other" kind.
- A generator's yield type was inferred before its for-of pattern names were bound, so `for await (const [x] of sets) yield x` with string elements failed ("no conversion from string to number").

## Decision

- A Map or Set source destructures its iteration (`[...s]`; entries for a Map).
- A nested array pattern over a tuple element unpacks the tuple's fields. Past the source's end the element is `undefined`, and Node's TypeError is thrown.
- A for-of head over any other element with a value is destructured as `let [pat] = elem`. In a generator or async frame, whose locals are frame slots, the element is first collected as an array (`genUnpackIterableElem`), as the plain declaration does.
- `elemKindKeyBroad` keys a host handle by its representation (`reprKey`), so different host kinds hold boxes and identical ones still share a type.
- The yield-type pre-pass binds a for-of array pattern's names (`patternElemType`).

## Consequences

- `TestE2EArrayPatternOverIterables` covers each case.
- Destructuring an iterable collects all of its elements before binding, as the plain declaration path already did. A pattern that needs fewer elements does not stop the iterator early, so its `return()` is not called.
