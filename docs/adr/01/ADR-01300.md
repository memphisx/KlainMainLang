# ADR-01300: `crypto` as Node's lib/crypto.js over the backend's natives

- **Relations**: `Implements part of TDD-00230` (P3.1), `Supersedes ADR-00434`, `Supersedes ADR-00590`, `Supersedes ADR-00636`, `Supersedes ADR-00637`
- **Date**: 2026-09-30

## Context

The Node `crypto` module was compiled directly:
- emit_nodecrypto.go: `generateKeyPair`(`Sync`) and `randomBytes`, with
  PEM assembled in IR;
- emit_crypto_hash.go: `createHash`/`createHmac` as codegen types over the
  backend's digest contexts.

That covered five functions. It had no ciphers, KDFs, signatures,
`randomInt` or `timingSafeEqual`. Its callbacks fired inline rather than
after the pool had done the work. Algorithm names had to be string
literals.

## Investigation

Node's lib/crypto.js re-exports lib/internal/crypto/*. Each class there
(`Hash`, `Hmac`, `Cipheriv`, `Sign`, …) is JavaScript around one native
handle: create it from a name, feed it bytes, take the result. Each
one-shot operation (pbkdf2, scrypt, hkdf, keygen, randomFill) is one native
job, run synchronously or as a thread pool job with a callback. Validation,
option defaults, encodings and error construction are JavaScript.

## Decision

**Natives** (`__kml_native_crypto_*`, in the crypto backend's C file,
linked through the `crypto` unit):
- a handle table for digest, HMAC and cipher contexts (`hash_new`,
  `hmac_new`, `cipher_new`, `update`/`digest`/`final`, `copy`, `free`);
- one-shot `kdf` (pbkdf2/scrypt/hkdf), `random_fill`, `keygen` (PEM out),
  `sign`/`verify` (PEM keys);
- `_async` forms of `kdf`, `random_fill` and `keygen` run on the pool
  through a new generic entry, `__kml_pool_job(work, job, inv, clo)`. It
  calls back `(err, result)` on the loop thread.
- `names(which)`: the backend's digest or cipher list, or, for
  `constants.OPENSSL_VERSION_NUMBER`, the linked libcrypto's version.
- `last_error`: the backend's error text, for Node's `opensslError`
  shape (`ERR_OSSL_*` codes, `error:…` messages).

`typedBytesBack` (dynjson.c) copies a native's output back into a
non-`Uint8Array` view.

**TypeScript** (`lib/node/crypto.ts`): `Hash`/`Hmac`/`hash`/`getHashes`,
`Cipheriv`/`Decipheriv`/`getCiphers`, `pbkdf2`/`scrypt`/`hkdf` (+ `Sync`),
`randomBytes`/`randomFill`(`Sync`)/`randomInt`/`randomUUID`/
`getRandomValues`, `timingSafeEqual`, `generateKeyPair`(`Sync`) for rsa,
ec, ed25519 and x25519, `Sign`/`Verify`/`sign`/`verify`, and Node's
`constants` table.

**Deleted**: emit_nodecrypto.go, emit_crypto_hash.go, the Hash/Hmac codegen
types, the `crypto` virtual module marker, and `declare module "crypto"`.

## Implementation notes

- Keys are PEM strings only. `generateKeyPair` needs `spki`/`pkcs8` PEM
  encodings. `KeyObject` and `createPrivateKey`/`createPublicKey`/
  `createSecretKey` are not ported, nor are Diffie-Hellman/ECDH,
  `publicEncrypt`/`privateDecrypt`, `X509Certificate`, `generatePrime`/
  `checkPrime` and `argon2`.
- `webcrypto`/`subtle` are not exported from the module. The global
  `crypto` is a codegen surface, not a value a module can re-export. The
  global `crypto.subtle` still works.
- A program that links the crypto backend for `crypto.subtle` alone, with
  no thread pool, gets a no-op `__kml_pool_job`. Nothing there calls it.

## Side effects discovered

- A `Buffer` or array parameter passed `undefined` received an empty
  array (packArrayArg), so `console.log(d)` printed `<Buffer >`. A null
  header now crosses the call. Reads go through the null-safe header.
  Mutations and index reads throw Node's TypeError (`Cannot read properties
  of undefined (reading 'push')`, `Cannot set properties of undefined
  (setting '0')`).
- `randomInt`'s callback receives `undefined` as its error, as Node's does.
- `x instanceof Buffer` was a compile error. It is now `IsBuffer`
  statically, and a boxed value's typed tag (3, a Buffer) dynamically. A
  boxed Buffer is also `instanceof Uint8Array`.
- An array literal mixing a string with two object shapes
  (`[key, { key }, { key, passphrase }]`) read every element as the first
  element's type. Other mixed kinds hold boxed elements now (`any[]`), as
  `-compat=js` already did.
  `flat()` over such boxed elements splices the ones that are Arrays at run
  time (`__kml_anyarr_flat`); it used to copy them unflattened, and
  `[a, [b]].flat()` was a compile error.
- A top-level `const` holding a call's `any` result (`fs.readFileSync(p,
  'utf8')`) read in a function was an undefined variable: it is a module
  global holding the box now.
- The dynamic Buffer-method branch (ADR-01299) is skipped for a call passing
  a function (`stream.write(text, cb)` on an `any`): no Buffer method takes
  one, and the static attempt emitted invalid IR.
- `{ key, passphrase }` decrypts an encrypted PEM key (a passphrase callback,
  never a terminal prompt). OpenSSL errors report the queue's earliest error
  and Node's library-prefixed code (`ERR_OSSL_CRYPTO_INTERRUPTED_OR_CANCELLED`).
- AEAD-only methods (`setAAD`, `setAuthTag`, `getAuthTag`) throw
  `ERR_CRYPTO_INVALID_STATE` on other modes; `hkdf` checks the length
  against 255 digest blocks (`ERR_CRYPTO_INVALID_KEYLEN`); an unknown EC
  curve is `ERR_CRYPTO_INVALID_CURVE`; a keygen failure is a plain `Error`
  with OpenSSL's text; a short GCM tag without `authTagLength` emits
  DEP0182 once.
- Emitter fields left unused by this and earlier ports were deleted.

## Verification

- `tests/crypto_port_test.go`: the sync surface and each callback form,
  one request at a time. Every program also runs under Node and must print
  the same.
- The existing Web Crypto and Node crypto suites pass. Two of them assumed
  callbacks fire inline and now expect Node's order.
- **Mac (Apple Silicon):** Node v24.19.0, OpenSSL 3.6.4.
