# ADR-01672: libcurl holds the loop by a handle

- **Relations**: Implements TDD-00244
- **Date**: 2026-10-17

## Context

Two keep-alive predicates in `__kml_event_loop_run` held the loop for fetch:

- `__kml_curl_inflight() > 0` asked libcurl, on every pass, how many transfers were running.
- `__kml_task_holds_loop()` (task.c) held it for a task that was runnable, or parked on a fetch or a fetch group, "in case its transfer had not reached libcurl yet".

TDD-00244 Stage 5 replaces liveness predicates with handle references.

## Decision

- **Hold handle.** fetch.c owns `curl_hold`, a `uv_async_t` that never fires. It is referenced while libcurl reports transfers running, and unreferenced otherwise. `hold_sync` updates it after every `curl_multi_socket_action` and `curl_multi_socket_all`. A transfer just added is driven at once (`__kml_curl_kick` right after `curl_multi_add_handle`), so it holds the loop from the moment it starts, awaited or not.
- **Libcurl step.** The pass still calls `__kml_curl_inflight`, for its work only: it aborts transfers whose signal fired and drains finished ones. Its return value no longer decides liveness.
- **Task hold removed.** `__kml_task_holds_loop` is deleted:
  - a task parked on a fetch is held by that transfer's handle;
  - a task parked on a fetch group is held by its members' transfers;
  - a runnable task is runnable work (`__kml_task_resumable`), like a queued microtask.

The keep-alive predicates left belong to `klain:http`'s server: the primary listener, the connection table and the extra listeners. They go with that server's port to a TypeScript module, which comes last in TDD-00230.

## Side effects discovered

None.

## Verification

- Fetch, XMLHttpRequest, abort, task, async, await and promise tests pass on Mac.
- An unawaited `fetch(...).then(...)` still keeps the program alive until it settles.
- The IR-text allowance for `runtime_task.go` drops from 6 to 5.
