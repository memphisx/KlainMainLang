# ADR-01987: Boxed receivers, empty-array properties and Buffer keys

- **Relations**: Implements TDD-00230; follows [ADR-01986](ADR-01986.md)
- **Date**: 2026-11-07

## Context

Several programs from the corpus that Node runs and the checker accepts
were rejected by codegen. Some were the checker typing a program
differently from tsc:

- `.then` on an immediately called async function expression: its closure
  type was not a task promise.
- `buf[`readBigInt64${e}`](0)`: no rule called a Buffer method named by a
  run-time key.
- `{ a: [] }` with no context: the checker left the literal untyped, so
  the whole object read as `any`.
- `for (const [a, e] of xs)` over elements of several shapes: the element
  held boxed was not destructured.
- An object literal with a key the parameter's type does not declare (a
  JavaScript caller's extra option): rejected.
- A JavaScript parameter laid out as an array, assigned null: rejected.
- `/** @return {Promise} */`: a generic named bare was left untyped.
- `t.match(re)`, `t.matchAll(re)` on a value held boxed: rejected, or not
  found at run time.
- `res.write(chunk, cb)` on an `any` holding a stream: taken as a Buffer's
  `write(string, offset)`, which cannot take the callback.
- `assert.match(v, re)` on a boxed module object: taken as a string's
  `match`.
- `new F()` of a constructor function declared in a block inside an
  arrow: untyped.
- `new Uint8Array()`, `new ArrayBuffer()`: rejected for a missing length.
- An async JavaScript function called without a parameter: rejected.
- `new Date(...xs)`, and `super(...args)` in a class extending Date or
  RegExp: rejected. A RegExp's flags held boxed undefined became the
  string "undefined".
- `this[0] = v` in a class extending a builtin, `const { a } = f` of a
  function declaration's value (the assert module), `err[sym] = v`, and
  `Symbol.toStringTag` and the other well-known symbols: rejected.
- A JavaScript function declared in a function body reading its own
  `this` (`function nb() { this.x = 1 }`, then `new nb()`): rejected.
- A property added in JavaScript to an object of a fixed layout, a
  library callback's options bag (`options.readableHighWaterMark = n`).
- `new Request(request, init)`; `net.isIP(123)`;
  `AbortSignal.any()`; `process.getActiveResourcesInfo()`.
- `F.prototype = Date.prototype; new F() instanceof Date` was false.
- `Object.setPrototypeOf` of a typed array, and of a function to a
  builtin's constructor (`Object.setPrototypeOf(T, Buffer)`): rejected,
  or a TypeError; `Buffer.prototype` read undefined.
- Found by the full test run, all regressions of this round of work:
  - `extends M.C1` of a namespace's class: rejected, since the class
    now carries its file's suffix and the qualified base did not.
  - `const c = { ...r }` with `r` held boxed: invalid IR (the binding
    took the checker's struct type, the literal the boxed object).
  - `const r1 = r[1]` from `Promise.allSettled`, then `r1.status`: a
    TypeError (the checker's union view of a settlement found no layout
    row for the settlement).
  - A write to a read-only property added by `Object.defineProperty`
    on an object of fixed layout was dropped silently in strict code.
  - The word `this` in a comment of a sloppy script made it read the
    global object, compiling in every global's module, the WebAssembly
    engine among them.
  - Two example files were not tracked (the `.js` modules of
    `examples/jsmode/commonjs.js`), and their directory shared the
    example's binary's name; `examples/types/symbol.ts` converted a
    symbol in a template literal, a TypeError in Node and TS2731 for
    tsc.
  - A class reference's own-key test listed its static methods in map
    order, so the same program compiled to different IR.
  - A binding the compiler synthesized (named after a register number,
    which restarts per function) took a display name another function
    had given that name, so a library function's "is not iterable"
    message named a variable of the program.
  - A closure a library function creates took a per-program function id
    in its header word; it now has the stable id a library function has.
  - A receiver temporary was numbered by a counter that ran across the
    whole program; it is now named per function.
  - The drift check took a library class's renamed private name
    (numbered within its own module, the same in every program) for a
    program-numbered symbol; it now tells the two apart.
  - Every class method call asked whether a generator method was
    overridden by walking the whole program and every class; the class
    map and the answers are now computed once.
  - A function's `this` (the global object when a call supplies none)
    compiled in every global module even when it was only read or
    written by name (`this.x = 1`): seven times the code of the same
    program before, which ran the conformance runner out of memory on
    Test262. A `this` used only by names now brings in the globals
    those names are; one used any other way (passed, indexed by a
    computed key, an Object.prototype member) still brings in every
    one, as it can observe them. A type cast around the global object
    (`(globalThis as any).x = 1`, in every async Test262 file's harness)
    counted as such a use; casts are now looked through.
  - `navigator.platform` on Linux named the kernel's machine (`Linux
    aarch64`) where Node names `process.arch` (`Linux arm64`; x64 and
    ia32 as `x86_64` and `i686`).

## Decision

- An async function expression's closure returns its task promise, as an
  async arrow's does.
- A string key known at run time on a Buffer, or on a value that may hold
  one, compares against the Buffer methods the key can name. A template
  key's fixed text narrows the list. A matching key calls that method, and
  any other key reads the property and calls it. The strict lane reports
  tsc's TS7053 for a string key on a builtin with a number index only.
- `writeBigInt64*` and `writeBigUInt64*` throw Node's `ERR_OUT_OF_RANGE`
  for a value outside the 64-bit range, under both BigInt backends.
- An empty array property with no context is `never[]`, as tsc types it
  under strictNullChecks. JavaScript files keep the untyped form.
- An array pattern over a value held boxed takes its elements by the
  iteration protocol.
- A key a literal's layout lacks is the object's own extra property, for
  plain layouts as for class ones.
- A JavaScript binding laid out as an array takes null (kept apart from
  undefined) and undefined.
- In a JavaScript file, or under a JSDoc tag, a generic named without type
  arguments gets `any` for each, unless a parameter has a default. Library
  code keeps its defaults (`Uint8Array`'s buffer type).
- `match`, `matchAll` and `search` on a boxed value are the string's when
  it holds a string. Otherwise they are the value's own, which is also
  what happens when the string method cannot take the arguments. A
  `matchAll` iterator held boxed is walked by the iteration protocol.
- A dynamic dispatch's static branch fails, and the dynamic call runs,
  when an argument cannot convert to the method's parameter.
- `new F()` of a constructor function local to a block or function is a
  dynamic object, as a top-level one is. This includes Annex B's var that
  the block's function assigns.
- `new Uint8Array()` and `new ArrayBuffer()` are empty.
- `crypto.randomUUID(options)` validates its options as Node does.
- A JavaScript async function's omitted parameter is undefined, as a
  plain function's is.
- A `new` with a spread argument is the dynamic construction. A Date or
  RegExp subclass's `super(...args)` makes its value from the spread.
  Flags held boxed are none when undefined, else their ToString.
- An index key on a builtin subclass's instance, and any key not a
  constant name on an Error, is the instance's own property, which
  `Object.prototype.toString` reads for the tag. The well-known symbols are
  declared.
- Destructuring a function declaration's value reads its boxed function
  object.
- Such a nested function is a function value, which binds the receiver.
- In JavaScript, a property a fixed layout lacks is the object's own extra
  property. `net.connect` hands its buffering options to the Socket, as
  Node's does.
- `new Request(request, init)` takes the input's url, method, a copy of
  its headers, its body and its other members; the init overrides them, a
  member an `any` init lacks included. A body moved from the input marks
  it used, and an input already used throws Node's TypeError.
- `net.isIP`, `isIPv4` and `isIPv6` test `${input}` of any value.
- `AbortSignal.any` takes WebIDL's `sequence<AbortSignal>`: an iterable of
  signals, anything else Node's ERR_INVALID_ARG_TYPE.
- `instanceof` a builtin (Date, Map, an Error kind, …) also walks a plain
  object's prototype chain for the builtin's prototype
  (`F.prototype = Date.prototype; new F() instanceof Date`).
- An array, typed array or Buffer given a prototype by
  `Object.setPrototypeOf` keeps it beside its header, in the table that
  holds its own added properties. A property it lacks is read on that
  chain, with the array as the receiver; `Object.getPrototypeOf` and
  `instanceof` follow it.
- A constructor reference (a builtin's, a class's) given as a function's
  prototype (`Object.setPrototypeOf(T, Buffer)`) stands in the chain as
  its extra-property bag, which reads on in the constructor's statics;
  `Object.getPrototypeOf(T)` is the constructor.
- `Buffer.prototype` is a prototype object whose `constructor` is Buffer,
  inheriting `Uint8Array.prototype`, and a Buffer's prototype.
- `process.getActiveResourcesInfo()` lists the loop's referenced open
  handles by Node's wrap names, then the referenced timers and
  immediates.
- A class extending a namespace's class (`extends M.C1`) takes the
  class's own top-level name, as `new M.C1()` does.
- An unannotated declaration whose object literal spreads a value held
  boxed is held boxed, as the literal is built.
- A settlement object has a layout row, so a view of it reads its
  fields.
- A sloppy script reads the global object as `this` only from a `this`
  in a function that is sloppy code, found in its syntax tree.
- A write to a read-only added property of an object of fixed layout
  throws in strict code ("Cannot assign to read only property"). A
  `.ts` file is strict code, as tsc emits it.

## Consequences

- `process.getActiveResourcesInfo()` lists no pending requests, and the
  stdio wraps only once `process.stdout` or `process.stderr` is read.
- Covered by `TestE2EAsyncFunctionExpressionIIFEThen`,
  `TestE2EBufferComputedMethodCall`, `TestE2EBufferBigInt64WriteRange`,
  `TestE2EEmptyArrayPropertyAndUnionDestructuring`,
  `TestE2ELiteralUndeclaredOptionKey`, `TestE2EArrayParamAssignedNull`,
  `TestE2EJSDocBareGeneric`, `TestE2EBoxedStringMatch`,
  `TestE2EBoxedNonStringMatch`, `TestE2EHTTPAnyResponseWriteCallback`,
  `TestE2EBlockConstructorFunctionInArrow`, `TestE2EAsyncOmittedArgumentJS`,
  `TestE2EAbortSignalAnyValidation`, `TestE2EDateSpreadConstruct`,
  `TestE2ERegExpSpreadSuperAndBoxedUndefinedFlags`,
  `TestE2EHostSubclassIndexProperty`, `TestE2EDestructureFunctionValue`,
  `TestE2ENestedConstructorFunctionDecl`,
  `TestE2EErrorSymbolKeyAndWellKnownSymbols`,
  `TestE2EHTTPCreateConnectionHighWaterMark`, `TestE2ERequestFromRequest`,
  `TestE2ENetIsIPAnyValue`, `TestE2EProcessGetActiveResourcesInfo`,
  `TestE2EInstanceofBuiltinProtoChain` and `TestE2EArraySetPrototypeOf`,
  which match Node; the rest by `TestE2ERecursiveCallablesAndQualifiedBases`,
  `TestE2EThreeStateOptionalRecordFields`,
  `TestE2EPromiseAllSettledPropertyAccessStillWorks` and
  `TestE2EDefinePropertyBesideLayout` (now strict code).
- The prototype an array is given stays in that table as long as the
  program runs, as the array's other added properties do.
- A function whose `this` is used other than by name (`Object.keys(this)`,
  `this[k]`) still compiles in every global's module, the WebAssembly
  engine among them, whether or not the function is ever called without
  a receiver.

- **Compile cost of the managed-space rewrite and the global object.** `toManagedSpace` runs on every unit of every program, so its regexes became linear scanners, with the regex form kept in the test as their specification. The global object carries every builtin only when a program can see a property it does not name (the object itself escaping, `eval`, a `Function(...)` call); otherwise it links just the names read off an object, which keeps each constructor's surface out of programs that cannot observe it. Own-key checks with a literal key (`hasOwnProperty.call(globalThis, "k")`, `Object.hasOwn`) count as one named read. `structuredClone` and the full fill are separate modules for the same reason. An iterator's getter now lists a helper method only when the program can reach it: named, under reflection, read off an untyped value by library code, or part of the iteration protocol. `instanceof` over a builtin's prototype chain reads the prototype's slot without building it (`__kml_proto_peek_*`), since an unbuilt prototype is on no chain.

- **Promise combinators over an untyped iterable** read, resolve and subscribe one item at a time in `lib/node/internal_promise_combine.ts`, closing the iterator when a member's `then` throws, rather than draining the iterable first, which never ended on an endless iterator. Left: `PromiseResolve` treats a subclass instance as itself, because a promise's `.constructor` reads `Object`; `p.then()` called directly ignores an own `then`.

## Closure-converted classes and the conformance runner's memory

Two process-wide memo maps keyed by program and binding kept every compile alive for a whole conformance run, which starved the collector and got runs killed; the memos now live on the binding. A timed-out front end cannot be stopped, so it keeps its worker's slot until it ends, and live front ends never exceed the worker count.

Every class that captures locals now has an evaluation record, since any instance reaches its class through `constructor`: `obj.constructor` answers the record, and a `new` through it gets that evaluation's bindings. Before this, such a class never named as a value produced a truncated constructor thunk, invalid IR that failed 2,793 Test262 files. A thunk that cannot be generated is now a compile error. Reads of a captured local before `super()` no longer take the `this` check, because `new` stores the hidden fields before the constructor runs.

Locals with non-ASCII names are encoded to ASCII before the managed-space pass
reads the IR. A value the emitter knows only as `any` is converted where a
static instance type is used: the species `new` of a class whose constructor
may return another object, a builtin constructor called without `new`, and a
function expression called at once that reads its own `this`. A constructor's
rebound `this` slot belongs to the function that made it, so a `super()` inside
an arrow no longer leaves the enclosing constructor naming a register of the
arrow. `super()` inside an arrow still does not bind the constructor's `this`.

`os.availableParallelism()` and `navigator.hardwareConcurrency` cap the affinity count by the cgroup CPU quota, the tightest on the way up from the process's own cgroup (cgroup v1 and v2), as libuv does; a limited container reported its whole host before. libuv's scaling by `cpu.weight` is not applied.

A type parameter's per-instantiation copy (`boundCopy`) whose new bound is itself a copy of that parameter is that copy: `then<TResult1 = T>` typed for `PromiseLike<TResult1>` copied once per level, members being typed eagerly, and one file reading the global object instantiated `PromiseLike` 67,522 times, stopped only by the instantiation bound. The conformance runner keeps a lower `GOMEMLIMIT` than its compile budget would set. It does not hand freed heap back to the OS: macOS keeps memory Go releases in the process's footprint anyway, and taking it back cost a sixth of a heavy run's CPU. A program whose global object escapes still emits every global's code (about 105 MB of IR for `globalThis.valueOf()`); the library units it splits into are compiled once (a lookup keyed by the unit's text as split, the cached objects a process has seen remembered, and one compile of a missing object at a time, so a cold cache no longer has every worker compile the same units and run out the codegen timeout), but their text is produced per program.


`Promise.all`/`allSettled`/`any`/`race` called with a receiver other than Promise itself (`Promise.all.call(C, iterable)`) now follow NewPromiseCapability(C): the result is C's promise, `C.resolve` is read once and called with C for each member, a throw from it rejects through C's reject function and closes the iterator, and a receiver that is not an object, not a constructor, or whose executor misbehaves throws the TypeError Node throws. Before this, the receiver was dropped: the combinator built a plain Promise and drained the iterator, so an endless iterator ran until memory ran out. Test262 `built-ins/Promise`: js 357 → 427, strict 80 → 95 (Mac).

A conformance runner now starts a front end only while its live heap is under three fifths of the run's memory limit, unless no other front end is running. A program whose global object escapes emits every global's code and peaks near 1.3 GB, with typed-array tests not far behind, but such a program is known only once it runs, and the memory budget counts a compile at its default share until its IR exists. A few of them in flight together pushed the Mac runner past 2.4 GB while its live heap stayed under 200 MB. So a program whose global object escapes, known once it is resolved, also waits before codegen for one of as many slots as the run's memory limit fits at 1.4 GB each (one on the Mac, many on the boxes). A stretch of Test262, the Temporal tests among them, is hundreds of such programs in a row, and on the Mac that stretch runs at about 2 files a second. The fill's cost itself is the open part: every such program emits about 100 MB of IR for 2,531 Node library units whose compiled objects are already cached, and only codegen reusing those units across programs removes it. A machine with a large limit never waits. A `SIGUSR1` to a runner writes a heap profile and its memory stats, so a long run's growth can be told apart as live data or memory held between compiles.

An accessor-bearing object literal built as a dynamic object (an `any[]` element) still registered its synthetic class, and the class-reference rows and the `Object.getPrototypeOf` dispatch then built that class's prototype. Its builder reached the getter's body through the shape record and emitted it outside the literal's scope: inside the builder's own function (invalid IR, a register defined twice), and once that was detached, as an undefined symbol, since the body reads the enclosing function's locals. A synthetic literal class no instance was made of now has no rows, accessor bodies are emitted in a function of their own and marked emitted only once they emit, and the WPT `serialization-via-notifications-api` files compile (they still fail: the Notifications API does not clone its `data` member).

`Array.from(src, mapFn, thisArg)` with a mapFn that may be undefined is lowered to a branch between the unmapped and the mapped call. The mapping closure was made inside the mapped arm, and making it boxes the locals it captures (`thisArg`, `mapFn`), so code after the branch read them through a box that the unmapped arm never made: invalid IR ("Instruction does not dominate all uses", Test262 `built-ins/Array/from/calling-from-valid-2.js`, js lane, seen on macOS arm64). The closure is now made once, before the branch.
