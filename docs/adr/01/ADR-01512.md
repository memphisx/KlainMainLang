# ADR-01512: `f.call` / `f.apply` return f's result

- **Relations**: Extends TDD-00230
- **Date**: 2026-10-09

## Context

The checker typed `f.call(…)` and `f.apply(…)` through the lib's
`Function` interface, which returns `any`. tsc's `strict` includes
`strictBindCallApply`, under which `CallableFunction` gives f's own
result. So `const r: string = add.call(null, 1, 2)` passed the strict
lane where tsc reports TS2322, and the oracle typed the call `any` where
codegen used f's result (shadow bucket 7, 144 rows).

## Decision

- The checker types `f.call(…)` / `f.apply(…)` as f's result when f is a
  function of one non-generic signature, in the strict lane. The js lane
  keeps `any`, as tsc does for a JavaScript file.
- The arguments are not checked against f's parameters yet; tsc does.
- The oracle types the call as the receiver function's result in both
  lanes, as codegen does.

## Divergences

The strict lane reports TS2322 where tsc does. Argument checking
(TS2345 on `f.call`) is still missing.
