# ADR-00195: Conformance report — category descriptions, pipeline-phase breakdown, per-reason examples

- **Relations**: Extends [ADR-00153](ADR-00153.md) (the conformance runner); follows [ADR-00194](ADR-00194.md) (which added `-faillist`)
- **Date**: 2026-08-13

## Context

`docs/testing/CONFORMANCE-RESULTS.md` reported the overall pass rate, a
per-top-level-category table (bare counts), and the 50 most common normalized
failure reasons (bare count + message). Two things it didn't answer, both of
which came up repeatedly while deciding what to work on:

- **What is each category, and is it in scope?** `built-ins` at 1.7% looks
  alarming next to `language` at 19.9% until you know most built-ins tests
  probe the dynamic object model this compiler can't represent.
- **Where in the pipeline did each failure die?** A raw first-error count
  (the trap [ADR-00169](ADR-00169.md) documented) can't distinguish a file
  that never parsed from one that compiled, ran, and produced a wrong result —
  yet those are completely different amounts of work to fix. The
  compile-and-ran-wrong files are the real near-misses; invalid-IR (clang)
  failures are our own codegen bugs; wrongly-accepted files are negative tests
  we should reject.

## Decision

Enrich `writeReport` (`tools/conformance/main.go`):

1. **Category descriptions** — a hardcoded `categoryDesc` map adds a "What it
   covers" column to the per-category table, stating scope inline.
2. **Failures by pipeline phase** — a new summary table groups every failing
   file by the phase it died in (`phaseOf` classifies the normalized reason):
   runtime near-miss (ran, wrong result), clang (invalid IR — codegen bug),
   wrongly-accepted (negative test compiled/ran), compile (front-end),
   run-timeout, skipped (unsupported harness include), infra. Ordered
   most-actionable-first.
3. **Per-reason phase + example** — the most-common-reasons table gains a
   compact `Phase` column and an `Example` column naming one representative
   file (the lexicographically first hitting that reason), so a reason can be
   reproduced by handing that file straight to the compiler.

## Implementation notes

- Files touched: `tools/conformance/main.go`.
- `phaseOf` keys off the normalized reason's `KIND:` prefix
  (`RUNTIME_NONZERO_EXIT`, `CLANG_ERROR`, `COMPILE_ERROR`, …) plus the two
  bare negative-test strings; `phaseShort` is the table-cell-width variant.
- The failure-reason sort is now `(count desc, reason asc)` so ties are stable
  across runs (the example file was already deterministic via the min-path
  rule) — no more churn in the generated file from map iteration order.

## Side effects discovered

The pipeline-phase table immediately surfaced **354 files failing at the clang
phase** — invalid IR this compiler emitted — as a distinct, actionable bucket
(previously scattered, unlabelled, across the reason list). The first one
investigated, `String.fromCharCode("0")` emitting `trunc i64 <ptr> to i8`, is
fixed in [ADR-00196](ADR-00196.md).

## Verification

- Linux (x86-64). `go build`/`go vet ./...` clean; `make conformance`
  regenerates the report in the new format (overall unchanged at 5169/53578).
- Report reviewed: category descriptions render, the phase table sums to the
  failing-file total, and each reason row carries a real, reproducible example
  path.
