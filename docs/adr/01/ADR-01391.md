# ADR-01391: Child processes spawn through uv_spawn

- **Relations**: Implements TDD-00244; Extends ADR-01389
- **Date**: 2026-10-04

## Context

[TDD-00244](../../tdd/TDD-00244.md) Stage 4 moves child processes onto
`uv_process_t`, the handle Node's `process_wrap` uses. The POSIX spawn in
`klainpool.c` forked by hand and reaped through a SIGCHLD pipe. The older C
child-process runtime (`childproc.c`, `cpipc.c` and their emitter files)
was no longer enabled by any program.

## Decision

- **POSIX spawn is `uv_spawn`** on the thread's loop (`proc_spawn_on`).
  Pipes are `UV_INHERIT_FD` of the runtime's own pipe ends, unused stdio is
  `UV_IGNORE`. The exit callback records the exit code and signal, then
  closes the handle.
- **The self-spawn marker stays.** `KML_KLAIN_REEXEC=1` is added to the
  environment passed to `uv_spawn`, so the interpreter-flag guard
  ([ADR-00972](../00/ADR-00972.md)) still stops a self-spawn loop.
- **`spawnSync` runs on a private `uv_loop_t`**, as Node's does, so a
  synchronous spawn never runs the program's other handles.
- `klainpool.c` compiles with the libuv flags.
- **The unused C child-process runtime is deleted**: `childproc.c`,
  `cpipc.c`, `runtime_childprocess.go`, `runtime_childprocess_exit.go`
  and their layout header entries.
- Windows keeps its own spawn path until Stage 6.

## Verification

- Linux x86-64 (Ubuntu 24.04 container): test-par 3922 tests pass,
  including the child_process, spawnSync and cluster suites; examples
  393/393; Test262 strict 8498 and js 10506 (unchanged), no invalid IR.
- Mac: not run.
