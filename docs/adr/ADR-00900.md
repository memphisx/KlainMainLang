# ADR-00900: Void value in a value position boxes to undefined

- **Date**: 2026-09-12

## Context

Invalid-IR sweep. A spec-undefined-returning method (`set.clear()`,
`arr.forEach()`, an empty-body arrow) whose result is consumed as a value —
boxed for `assert.sameValue(s.clear(), undefined)` or passed as an `any`
argument — emitted invalid IR:

```
%t5 = sitofp i64  to double     ; no operand: the void call produced no register
```

From `built-ins/Set/prototype/clear/returns-undefined.js` and the whole
"expected value token" cluster (8 files: Set/forEach returns-undefined, arrow
empty-body, return/throw/try statement-value cases).

## Investigation

These builtins return `Value{Ty: TypeVoid}` (`IR: "void"`). `emitBoxValue`
(`emit_dynamic.go`) had no void case: it fell through to the numeric default,
which coerced the (nonexistent) void result to a double — `sitofp i64 <empty>`.
In JS a void-returning call used as a value *is* `undefined`.

## Decision

Add a guard at the top of `emitBoxValue`: a `void`-IR operand boxes to the
undefined NaN-box (`nbUndefined`), exactly as a real `undefined` literal does.

## Implementation notes

One branch, placed right after the `IsDynamic` pass-through so it runs before any
nullable/array/scalar handling.

## Side effects discovered

`inferExprType` does not report `void` for these builtin calls, so a *direct*
`s.clear() === undefined` compile-time fold still takes a non-void path — a
latent inference gap (not invalid IR). The boxing path (arguments, `sameValue`)
is what the corpus exercises and is fixed here.

## Verification

- `TestE2EVoidMethodResultAsValue` (new).
- All 8 "expected value token" files compile clean; the Set/clear conformance
  file runs to exit 0.
- `make examples` 296/296.
