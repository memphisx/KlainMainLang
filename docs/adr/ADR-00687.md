# ADR-00687: a void-returning predicate emitted invalid IR (`icmp` on `void`)

- **Date**: 2026-09-03

## Context

The invalid-IR backlog's `void type only allowed for function results` cluster.
Repro: `[1,2,3].filter(pred)` where `function pred(x) {}` has no `return` — the
callback's return type is `void`, and `filter`/`some`/`every`/`find` test that
result for truthiness, emitting `icmp ne void, 0` / `br i1 void` — invalid IR.

## Investigation

The HOF truthiness path routes the callback result through `emitToBool` →
`toBool`. `toBool` handled `i1`/dynamic/bigint/pointer/scalar values but not a
`void` one, so it fell through and built a comparison against the `void` call
result. In JS a predicate returning `undefined` is falsy
(`ToBoolean(undefined) === false`), so the element is simply excluded / the
predicate fails.

## Decision

`toBool` now returns `false` for a `void`/`undefined`/`null` value (JS
`ToBoolean`), so a no-`return` predicate is falsy instead of producing an `icmp`
against a `void` operand. General across every truthiness site (`if`, `&&`/`||`,
`filter`/`some`/`every`/`find`, the ternary), not just array HOFs.

## Verification

Mac. `[1,2,3].filter(pred)` → `0` (all excluded); `[1,2].every(function(x){})` →
`false` — both match Node. In `built-ins/Array` this cleared every remaining
`void`-type invalid-IR file (CLANG_ERROR 44→33, passes 149→160); combined with
ADR-00686 the category went 52→33 invalid-IR / +18 passes. Truthiness regression
green.
