# ADR-02004: Host method tables link only reached methods

- **Date**: 2026-11-21

## Context

Every String method's host wrapper was emitted in any program with the
string method table, so `normalize`'s Unicode tables (about 100 KB) were in
all of them. `examples/arrays/array_bounds.ts` was 1,184,128 bytes on Linux
x86 and calls none of those methods.

## Investigation

- `emitHostShapeGetter` already skipped unreached methods, but only for the
  iterator interfaces. Every other class emitted every method.
- The reachability check (`hostMethodReachable`, proto_reach.go) counts a
  method a source name, a reflection call or a computed key can reach.
  Library code was counted only when the receiver was typed dynamic, but
  library code also reads host members through loosely typed values
  (`res.body!.getReader()`).
- Symbol-keyed methods (`@@asyncIterator`) are found by the runtime's
  protocol walks (`for await`, spread), never by a source name.

## Decision

- The method filter applies to every host class.
- Every member name library code reads counts as reached.
- Every well-known-symbol method counts as reached.

## Implementation notes

- codegen/llvm/emit_host_shape.go: `emitHostShapeGetter`.
- codegen/llvm/proto_reach.go: `hostMethodReachable`, `buildProtoReach`.

## Verification

- Linux x86 (Node304): `array_bounds.ts` is 701,200 bytes, with the same
  output. The String, any, dynamic, prototype, reflection, inspect, host,
  fetch, stream and event test groups pass, including
  `TestE2EReadableStreamAsyncIterator` and
  `TestE2EReadableStreamFromAsyncGenerator`.
