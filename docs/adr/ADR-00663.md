# ADR-00663: Object-pattern destructuring over a D1 dynamic source (`-compat=js`)

- **Relations**: Implements TDD-00155 (D1 dynamic object model)
- **Date**: 2026-09-03

## Context

Under `-compat=js`, destructuring an object pattern against a value with no fixed
static struct shape — a bare `any` or D1 dynamic object — failed at codegen with
`object has no field 'x'`. The canonical case is a `for…of` over an array of
dynamic-object elements:

```js
for (const { x, } of [{ x: 23 }]) { … }   // element is a D1 dynamic object
```

Surfaced running the `-compat=js` Test262 for-of destructuring bucket
(`language/statements/for-of/dstr/*-obj-ptrn-*-trailing-comma.js`). Strict mode
passes these (the element is a fixed struct); `-compat=js` regressed because the
element is dynamic and the binder GEP'd a struct field that doesn't exist.

## Investigation

- `unpackObjectPatternInto` (`codegen/llvm/emit_objects.go`) is the shared
  destructuring core (for-of elements, vardecl, destructured params). It calls
  `objTy.FieldIndex(prop.Key)` and rejects a miss with `object has no field`.
- Debug printing confirmed the for-of element type is `TypeAny`
  (`isUnconstrainedDynamic`), IR `i64`, and `objPtr` is the boxed any value
  register — not a struct pointer.
- The runtime dynamic-get already exists: `emitDynAnyMemberGet` /
  `emitDynAnyMemberGetNamed` (`codegen/llvm/emit_dynobj.go`) read a property
  from a boxed any, returning `undefined` for a missing key. This is exactly
  what `x.prop` on a dynamic base already compiles to.

## Decision

At the top of `unpackObjectPatternInto`, when the source type is
`isUnconstrainedDynamic`, delegate to a new dynamic path
(`codegen/llvm/emit_dynobj_destr.go`) that reads each property through
`emitDynAnyMemberGet` instead of a struct GEP:

- **Leaf / renamed** (`{ x }`, `{ x: y }`): bind `prop.Local` as an `any` local
  (alloca `i64`, store the box).
- **Default** (`{ x = d }`): fires on the JS rule — the got value is
  `undefined` (missing key) — via a real branch so the default expression is
  only evaluated when absent.
- **Nested** (`{ x: [a] }`, `{ x: { a } }`): recurse through the dynamic path;
  the array sub-pattern reads elements by numeric-string key ("0", "1", …).

A `{ ...rest }` element (residual keys of a runtime bag into a fresh dynamic
object) is not yet supported on this path and is rejected with a clear message —
tracked as a follow-up; none of the in-scope conformance files need it.

## Implementation notes

New file `emit_dynobj_destr.go` holds `unpackDynObjectPatternInto`,
`unpackDynArrayPatternInto`, `bindDynPatternValue`, and `applyDynDefault`. The
array-pattern dynamic path reuses the same numeric-string-keyed `dynarr` get the
D1 model already exposes, so `{ x: [a] }` over a dynamic array Just Works. The
static path is completely unchanged; the dynamic branch is entered only for an
unconstrained-dynamic source, so strict mode and statically-typed `-compat=js`
objects keep their native-struct destructuring.

## Side effects discovered

- Object/array **rest** in a dynamic destructuring pattern is deferred (clean
  rejection). Recorded as a limitation on the D1 status page.
- The `*-obj-ptrn-prop-id-*` conformance variants stay failing in *both* modes —
  they assert a runtime `ReferenceError` for an unbound name via
  `assert.throws(ReferenceError, () => { x })`, which this compiler models as a
  compile-time error, not a runtime throw. Not a regression (strict fails them
  too); out of scope.
