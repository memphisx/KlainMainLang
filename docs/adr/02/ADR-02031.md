# ADR-02031: A binding Object.assign retypes is held dynamically

- **Date**: 2026-11-22

## Context

- In the strict lane, `Object.assign(t, { a: "x" })` on `t: { a: number }`
  (valid TypeScript) was rejected: the field's typed slot cannot hold a
  string, and the checker refused the call (AssignRetypesField).

## Decision

- The checker refuses only when the target is not a variable's own binding
  (a parameter, a property). `AssignRetypes` exposes the same test to code
  generation.
- Code generation holds such a binding boxed (`assignRetypedDecls`, an
  `anyHeldDecl` case): its object is a dynamic one, which takes a value of
  any type in any field.
- `checkerPrimitive` leaves a read rooted at a box-held binding to the box,
  so `typeof t.a` and `t.a` give what the field holds.

## Consequences

- A parameter's or property's object stays refused. Its layout belongs to
  the values the callers pass, and the Object.assign status row discloses
  that.
- Tests: `TestE2EObjectAssignIncompatibleFieldTypeRejected`.
