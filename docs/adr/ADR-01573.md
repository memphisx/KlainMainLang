# ADR-01573: Bounded resolution of recursive conditional types

- **Relations**: Extends ADR-01571, Implements TDD-00230
- **Date**: 2026-10-11

## Context

The TypeScript acceptance suite's process was killed twice after using 47
GB. A verbose run with a resident-memory watchdog stopped on
`conditionalTypeDoesntSpinForever.ts`. Its builder types
(`BuildPubSubRecordType<SO_FAR>`) are conditional types whose branches each
instantiate the builder again with a larger `SO_FAR`. tsc bounds these with
instantiation-depth and instantiation-count limits. Codegen's own
annotation resolution (`resolveConditionalType`, used for representation)
had no bound. The expansion grows exponentially rather than deeply, and
each `as BuildPubSubRecordType<…>` cast repeated it.

## Decision

`resolveConditionalType` resolves a conditional type as `any` once any of
three limits is reached:

- 16 nested conditional types;
- 1,000 resolved under the outermost one;
- 50,000 in the whole program.

`any` is a representation choice only. The value is held boxed, and
operations on it take the dynamic path. All three limits are far above
what ordinary utility types (`DeepPartial`, `ReturnType`, `Awaited`)
reach.

## Verification

The suite file now finishes in about 1 second, with an ordinary codegen
error rather than unbounded memory. Mac: the conditional, utility, mapped
and inference E2E suites. Linux (DeskMini kmlbox): the TypeScript
acceptance suite in both lanes.
