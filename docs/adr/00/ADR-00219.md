# ADR-00219: Fix a class-typed interface/type-alias field resolving to `i64` (placeholder-registration ordering)

- **Date**: 2026-08-18
- **Relations**: Extends [ADR-00218](ADR-00218.md) (surfaced while testing object inspection)

## Context

An interface (or type alias) field typed as a user class — `interface W { p: Point }` — was silently mis-compiled: the field resolved to `i64` instead of the class's pointer type. So `const w: W = { p: new Point() }` emitted `store i64 <ptr>` (a pointer stored into an `i64` slot), and any access through it (`w.p.x`) failed with "field access on non-object (no field 'x')". Found while adding the object inspector ([ADR-00218](ADR-00218.md)) — a nested class-typed field in a test.

## Investigation

- `resolveType` (`emitter.go`) *does* resolve a named type against `e.interfaces` (the "interface, type-alias, and class" registry) before falling back to `ResolveTypeName`, which returns `i64` for an unknown name.
- Classes get a name-only placeholder — `e.interfaces[name] = ClassType(name, nil, nil, false, false)` — in `registerClasses`' Pass 0 (`emit_classes.go:567`), whose comment states it "must exist before any field/param/return type is resolved."
- But **`registerInterfaces` (EmitProgram Pass 0) runs before `registerClasses` (Pass 0.5)**. So when an interface's fields are resolved, no class placeholder exists yet, and `resolveType(Point)` fell through to `i64`. The comment's invariant held for *class* fields (resolved during `registerClasses`, placeholder present) but not for *interface* fields.
- Member access already canonicalizes a class-typed field's type on use (`canonicalizeClassTy` swaps the name-only placeholder for the live field-bearing type from `e.classes`), so a placeholder is sufficient — the field just needed to resolve to one instead of `i64`.

## Decision

Register the class name-only placeholders one pass **earlier** — a new `registerClassNamePlaceholders` (EmitProgram Pass -0.5) that runs before `registerInterfaces`, recording `ClassType(name)` for every non-generic top-level class. Interface/type-alias fields then resolve a class name to its `ptr` type; the full field-bearing type is still filled in by `registerClasses`, and access canonicalizes to it. Generic classes are skipped (they live in `e.genericClasses`, instantiated on demand). `registerClasses`' own Pass-0 placeholder write is now a harmless idempotent re-registration.

The inspector ([ADR-00218](ADR-00218.md)) additionally canonicalizes `val.Ty` at the top of `emitInspectObject`, so a nested class-typed field renders its real fields (`Point { x: 3, y: 4 }`) rather than the placeholder's empty `Point {}`.

## Implementation notes

- `emitter.go`: new Pass -0.5 call between `registerEnums` and `registerInterfaces`.
- `emit_classes.go`: `registerClassNamePlaceholders(prog)` — mirrors Pass 0's placeholder write, non-generic classes only. Class expressions are already rewritten to declarations in Pass -2, so they're covered.
- `emit_inspect.go`: `emitInspectObject` canonicalizes its value's type first.

## Side effects discovered

- A **separate, still-open** pre-existing bug: a *class* field typed as another class with a **direct `new` initializer** — `class Box { p: Point = new Point() }` — fails with "unknown class 'Point'" (the same field via a function call, `p: Point = makePoint()`, works). This is independent of this fix (it reproduces with no interfaces involved, and this change is a no-op for an interface-free program) and untouched here — recorded for a future fix.

## Verification

- `tests/nominal_fields_test.go` — the interface-field repro (`s.origin.x`/`.y`/`.label`) and its inspection (`{ origin: Point { x: 3, y: 4 }, label: 'box' }`).
- `go vet ./...` clean; `Class|Object|Inspect|Interface` suites green (no regression from the earlier-placeholder registration); full `go test ./...` at the delivery's end.
- Platform-independent (registration-order change, no native code).
