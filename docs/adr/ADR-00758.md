# ADR-00758: `fs.watch` macOS backend — kqueue/EVFILT_VNODE (TDD-00181 Stage 3)

- **Relations**: Implements [TDD-00181](../tdd/TDD-00181.md) Stage 3; extends [ADR-00756](ADR-00756.md) (the FSWatcher subsystem + Linux backend), [ADR-00757](ADR-00757.md) (the Windows backend)
- **Date**: 2026-09-07

## Context

[ADR-00756](ADR-00756.md)/[ADR-00757](ADR-00757.md) shipped `fs.watch` on Linux (inotify) and Windows (ReadDirectoryChangesW + a wakeup socket). This ADR is the macOS backend, `kqueue` with `EVFILT_VNODE`. Like inotify — and unlike Windows — the kqueue is a **readable fd**, so it drops into the loop's `select()` `fd_set` with no thread.

## Decision

An IR backend (`emitFsWatchDarwin` in `runtime_fswatch.go`), sharing the `FSWatcher` struct and JS surface with the other two.

- One process-wide `kqueue()` (lazily created). Each `fs.watch` `open`s the target with `O_EVTONLY` (event-monitoring, does not block unlink) and registers a `struct kevent` — `EVFILT_VNODE`, `EV_ADD|EV_CLEAR`, `fflags = NOTE_DELETE|WRITE|EXTEND|ATTRIB|LINK|RENAME|REVOKE (0x7F)` — with **the `FSWatcher` pointer stored in `udata`**. So `dispatch` reads `udata` straight back and needs no registry scan (the elegant half of kqueue).
- `fdset_add` adds the kqueue fd while any watcher is open; `dispatch` calls `kevent` with a zero timeout to pull the ready events, maps each `fflags` (`NOTE_DELETE|RENAME|REVOKE` → `'rename'`, `NOTE_WRITE|EXTEND|ATTRIB|LINK` → `'change'`), and fires the `udata` watcher's listener. `close` closes the `O_EVTONLY` fd, which auto-removes its kevent.

kqueue watches an fd, not a directory's entries, so it **cannot name a changed directory entry** — `filename` is the watched path (Node uses FSEvents on macOS for named/recursive directory events). Recorded as a documented divergence; the file-watch case (the common one) is faithful.

## Implementation notes

- The `struct kevent` 64-bit layout is built by byte offset on a `[4 x i64]` stack slot: `ident@0`, `filter@8` (`EVFILT_VNODE = -4`), `flags@10` (`0x21`), `fflags@12` (`0x7F`), `data@16`, `udata@24`; `struct timespec {0,0}` is a `[2 x i64]`.
- `open` is now declared via a shared `ensureOpenDecl` (the fd ops and this backend both need it and would otherwise redefine `@open` — the same class of collision the `@read` dedup fixed in [ADR-00756](ADR-00756.md)).
- `kqueue`/`kevent` link to macOS's `_kqueue`/`_kevent`; no `$INODE64`-style variant applies to `kevent`.

## Side effects discovered

None on the built platforms — the backend is GOOS-gated, so Windows/Linux are unaffected (verified: Windows fs.watch native and Linux fs.watch + fd-ops via Docker still pass, confirming the `ensureOpenDecl` refactor).
