# ADR-01244: `string_decoder` is a TypeScript module

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-09-29

## Context

`string_decoder` did not exist. Node's readline decodes its input through
it (ADR-01243), and streaming byte→text code imports it directly.

## Decision

`lib/node/string_decoder.ts` is Node's StringDecoder: the JavaScript
implementation Node shipped before moving it to C++. The observable
behaviour is the same:

- `write` holds back a character split across Buffers (UTF-8, UTF-16LE,
  base64/base64url) and passes a string through;
- `end` flushes what is held: a partial UTF-8 character as U+FFFD, UTF-16
  code units, or the base64 of the remaining bytes;
- `hex`, `latin1` and `ascii` decode each Buffer whole;
- an unknown encoding is `ERR_UNKNOWN_ENCODING`.

## Verification

Mac (Apple Silicon), against Node v24.19: `TestE2EStringDecoder` (split
UTF-8/UTF-16/base64, `end`, unknown encoding), identical output.
