# ADR-01425: The shadow report measures every decider

- **Relations**: Implements TDD-00230 (P0.2, P2.3, P3.3)
- **Date**: 2026-10-06

## Context

TDD-00230 switches a codegen decider over to the checker when the shadow
report shows no disagreement for it, and then deletes it. `make
shadow-report` reported "0 disagreements over 47899 compile runs", which
reads as every decider being ready to delete. A single compile with
`KML_SHADOW` set by hand recorded ten disagreements in a six-line file.

## Investigation

- `tools/shadow/main.go` passed each compile a record path under
  `.shadow-out/runs`, relative to the repository, and ran the compile with
  its working directory set to the source file's directory. Every record
  went to a path that did not exist, and the open failed silently.
- The oracle (`codegen/llvm/shadow_binder.go`) answered `GlobalType` and
  `ReturnType` with "no answer", so `reliableGlobalType` and
  `inferUnannotatedReturnType` were never compared.
- `reprOf` had no representation for a function type and none for a
  generic builtin with a `@lowerType` (`Map<string, number[]>`): the
  layouts of those (`genericLayouts`) were built from an
  `ast.TypeAnnotation`, which the checker's types do not have.
- `reprKey` printed an empty slice and a nil one differently
  (`FuncParams=[]`), and keyed the call-site metadata codegen keeps on a
  function type (`FuncParamNames`, `FuncParamOptional`, `Inferred`) as if
  it were representation.

## Decision

- The shadow tool makes the run directory absolute.
- `GlobalType` answers with `reprOf` of the module variable's declared type
  (`Checker.ModuleVarType`, the declaration's symbol type: an evolving
  `let`'s storage type); the variable is promotable when that type has a
  representation. `ReturnType` answers with `reprOf` of
  `Checker.BodyReturnType`, with no value for `void`.
- `reprOf` gives a non-generic, non-overloaded function type a closure
  representation: its parameters' and result's representations, a `this`
  parameter first, rest and optional parameters marked.
- `genericLayouts` take their type arguments already in codegen's
  representation (`[]*Type`, nil for one not given), with each layout's
  parameter count. An annotation resolves its arguments first
  (`genericLayout`); a checker type's `TypeArgs` go through `reprOf`
  (`genericLowerTypeRepr`, which `lowerTypeRepr` falls back to).
- `reprKey` skips empty slices and the call-site metadata fields.

## Implementation notes

- `tools/shadow/main.go`, `codegen/llvm/shadow.go`,
  `codegen/llvm/shadow_binder.go`, `codegen/llvm/lower_type.go`,
  `checker/symbols.go`.
- The layout table no longer needs its `init` function: no builder calls
  `resolveType`, so the table has no initialization cycle.

## Side effects discovered

- The first complete report: 270,226 disagreements in 392 buckets over
  47,899 compile runs (`inferExprType` 156,736, `reliableGlobalType`
  88,348, `resolveType` 17,167, `emitIdent` 7,815,
  `inferUnannotatedReturnType` 160). The large causes: codegen keeps an
  untyped `number` binding as `i64` where the checker's representation is
  `double`; in `-compat=js` an unannotated parameter no call site types
  takes codegen's number default where the checker says `any`; and
  `reliableGlobalType` declines to promote most declarations the checker
  types.
- A user class's `prototype` is not a value in the strict lane
  (`C.prototype.method` is "no static field 'prototype'"), already noted in
  the BACKLOG's readline entry.

## Verification

- A hand-run compile of a probe file records the same rows the tool now
  collects; `make shadow-report` on the corpus records them.
- `Map<string, number[]>` as a module global agrees between the two.
- `go test ./checker ./binder ./codegen/...`.
