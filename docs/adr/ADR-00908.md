# ADR-00908: Array.includes with a cross-type search value

- **Date**: 2026-09-12

## Context

Invalid-IR sweep. `includes` with a search value of a type disjoint from the
element type emitted invalid IR:

```ts
[42, 0, 1].includes("42")   // clang: fcmp oeq double %elem, <string ptr>
```

From `built-ins/Array/prototype/includes/samevaluezero.js`.

## Investigation

`emitArrayIncludes` (`emit_arrays_search.go`) coerced the needle to the element
type and compared with `fcmp`. SameValueZero never coerces across types, so a
string needle on a number array can never match — but `coerce(string → double)`
left the string pointer, producing `fcmp double, <ptr>`.

## Decision

Before coercing, if the element and needle have two concrete but differing scalar
kinds (`scalarTypeKind`), the match is impossible: `-compat=js` folds to a
constant `false`; `-compat=strict` rejects (TypeScript reports the argument-type
error). The guard only fires when the element kind is a concrete scalar
(number/string/boolean), so object/array/dynamic element arrays keep the existing
boxed comparison.

## Implementation notes

`scalarTypeKind` returns "" for dynamic/object/array/null/undefined, so the guard
is naturally inert for those element types.

## Side effects discovered

`includes(NaN)` SameValueZero (NaN matches NaN) is a separate runtime-correctness
concern (`fcmp oeq` says NaN≠NaN), not invalid IR — not addressed here.
