# ADR-01362: Blob is a TypeScript class

- **Relations**: Implements part of TDD-00230 P3.4; supersedes the representation of TDD-00102
- **Date**: 2026-10-03

## Context

Blob was a host type: the `NewBlobExpression` node, the `IsBlob` flag and a
`{size, data, type}` heap struct, with codegen for its constructor,
properties, five methods and inspect. That code carried four caveats:
- `stream()` gave one chunk;
- parts had to be an inline literal or a `string[]`;
- there was no `endings` option, and the type was not lowercased;
- `text()` stopped at a NUL, and a multi-part Blob settled its readers as a
  one-part Blob does.

## Investigation

Node's `lib/internal/blob.js` and a probe of Node 24 give the behaviour to
match:
- A Blob keeps its parts, and a Blob part contributes its own parts.
- `stream()` yields one chunk per part.
- `arrayBuffer()` settles after two microtasks per part (immediately for a
  Blob of no parts); `text()` and `bytes()` take one more. Measured over
  0–3 parts, nested Blobs and empty strings.
- The type is lowercased, or empty when a character is outside
  U+0020–U+007E.
- `endings: 'native'` replaces `/\n|\r\n/g` with the platform's EOL in
  string parts, keeping a lone `\r`. Any other value is
  `ERR_INVALID_ARG_VALUE`, and a non-iterable parts argument is
  `ERR_INVALID_ARG_TYPE`.
- It inspects as `Blob { size, type }`.

Native code reads Blobs in three places: `new Response(body)`, a `fetch`
body, and the synthesized stream-body collector.

## Decision

1. **`lib/node/kml_blob.ts`** is a global module exporting `class Blob` with
   all of the above. `kmlBytes()` and `kmlParts()` are the native readers'
   access.
2. **Deleted:**
   - `NewBlobExpression` and its sema, checker, walker and codegen
     entries;
   - the `IsBlob` flag, `BlobType`, the Blob struct and its emitters;
   - the five `@intrinsic Blob.prototype.*` annotations and the parser-time
     reexport of `Blob` from `buffer`.
   The `{len, data}` helpers ArrayBuffer and Buffer share move to
   `emit_arraybuffer.go` (`emitBufSizeData`, `emitCopyBytes`).
3. **Native readers:**
   - `new Response(body)` wraps a non-Blob body in `new Blob([body])`, then
     reads `kmlBytes()` and `type` (`emit_blob.go`).
   - A fetch body tests for the class through `any`.
   - The stream collector returns the `Uint8Array`, not a Blob.
   - `lib.NativeGlobalUses` links Blob into programs that name `Response`
     or `fetch`.

## Implementation notes

- **Library:** `lib/node/kml_blob.ts`, `lib/node.d.ts` and `lib/lib.go`.
- **Front end:** `ast/nodes.go` (walker regenerated), `sema/builtin_new.go`,
  `checker/checker.go` and `resolver/virtual_modules.go`.
- **Codegen:** `emit_blob.go` (rewritten), `emit_arraybuffer.go`,
  `emit_buffer.go`, `emit_fetch_body.go`, `emit_response_new.go`,
  `emit_exprs*.go`, `emit_func.go`, `emit_inspect_host.go`,
  `emit_intrinsics.go`, `emit_lowered.go`, `emit_memory.go`,
  `emit_strings.go`, `emit_classref.go` and `types.go`.

## Side effects discovered

Each of these was fixed in its own ADR:
- a typed array's `constructor` did not compile (ADR-01360);
- `ArrayBufferView` resolved to `number` in codegen (ADR-01359);
- a non-array `any` in an array slot crashed (ADR-01361);
- a promise's typed view settled one microtask late (ADR-01363);
- `JSON.stringify` stopped at a NUL (ADR-01364).

`TestE2EBlobStreamForAwait` expected one chunk; it now compares with Node.
The `-mm=auto` Blob test builds through the CLI, since the class is linked
by the resolver.

## Verification

Mac (Apple Silicon), against Node 24, matching:
- `examples/blob/blob.ts`;
- the new `TestE2EBlobGlobalClassParity` (errors, type normalization,
  endings, nested parts, inspect, reader timing, embedded NUL);
- the existing Blob, Response, fetch-body, WebSocket and memory groups.
