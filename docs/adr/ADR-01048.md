# ADR-01048: A finished coroutine gives its stack back

- **Relations**: `Extends ADR-00985`; `Implements TDD-00083, TDD-00223` (§2: every async callable that awaits is a coroutine)
- **Date**: 2026-09-21

## Context

Found while reading the task runtime for [TDD-00224](../tdd/TDD-00224.md): nothing in `runtime_task.go` ever frees a
task's fiber stack, context or jmpbuf stack, and nothing removes a finished task from `@__kml_task_data`.

```ts
async function tick(i: number): Promise<number> {
  await new Promise<void>((r) => setTimeout(r, 0));
  return i;
}
async function run(): Promise<void> {
  let s = 0;
  for (let i = 0; i < 20000; i++) s += await tick(i);
  console.log(s, Math.round(process.memoryUsage().rss / 1048576));
}
run();
```

Windows 11 x64, manual memory mode: RSS 9 MB at the start, **363 MB** at the end (≈18 KB resident per call, plus
256 KiB of commit each — 5 GB of commit charge for this loop). Node 24: flat. Since TDD-00223 §2 made every async
callable that awaits a coroutine, this is every `await`-ing call in a long-running server. The scheduler's scan
(`@__kml_task_sched_step`, `@__kml_task_resumable`) was also linear in every task the process had ever run.

On Windows there was a second holder: a context is a Win32 fiber (`CreateFiberEx`), and a task never returns
through the fiber trampoline — it leaves through `@__kml_task_finish` / `@__kml_task_reject` with a `swapcontext` —
so the shim's "reap the fiber that just returned" path never saw it and the fiber (its OS stack included) was never
deleted.

## Decision

- `@__kml_task_reclaim(ptr %t)`: if the task is done (state 2) and still owns a stack, release the platform context
  (`@__kml_ctx_release`), free the stack block, the context and the jmpbuf stack, and null the three fields. It is
  called by **whoever swapped into the task**, right after that `swapcontext` returns and the swapper's own jmpbuf
  stack / GC stack bottom are restored — the three swap-in sites: `@__kml_spawn_task`, `@__kml_task_sched_step`'s
  resume, `@__kml_task_resume`. A finished task has left its stack for good by then, so the free cannot pull a
  stack out from under running code.
- `@__kml_ctx_release(ptr %ctx)`: an internal no-op on POSIX (ucontext owns nothing beyond the IR's blocks); on
  Windows a shim function that drops the parked-stack GC root the task's last switch registered (the range now
  lives in the context — `park_lo`/`park_hi`, offsets 48/56 of the 64 bytes the IR already allocates — because the
  frame that used to hold it is on the stack being deleted) and calls `DeleteFiber`.
- `@__kml_task_compact()`: the outermost `@__kml_task_sched_step` (a thread-local depth counter tells it apart
  from a step driven re-entrantly by a resumed task or a connection fiber) drops finished tasks from the task array,
  in order, before scanning.
- The 104-byte task struct is **not** freed. A promise's `waiter` field can still name a task that has since
  finished (the loser of a `Promise.race` settling late), and `@__kml_task_finish` writes through it. Collected under
  `-mm=gc`; in manual mode it is the same order of per-call residue as the promise struct itself.

## Implementation notes

`codegen/llvm/runtime_task.go`, `codegen/llvm/win32src/win32io.c` (`__kml_ctx_release`, `park_lo`/`park_hi`),
`codegen/llvm/win32src/kml_posix_compat.h` (the C-visible `ucontext_t` grows to the full 64 bytes — `swapcontext`
now writes the last two fields for every caller, the goroutine scheduler's contexts included).
Tests: `tests/task_reclaim_gc_tls_test.go` (`TestE2ETaskStackReclaimed`, `…GC`).

## Side effects discovered

Running the probe under `-mm=gc` segfaulted — before this change as well as after. That turned out to be three
separate holes in what the collector scans, on Windows and Linux: [ADR-01049](ADR-01049.md).

`setTimeout(f, 0)` fires without Node's 1 ms clamp (20,000 sequential zero-delay timers take 0.3 s here, ≥ 20 s in
Node). Observable only through timing; recorded in the backlog.

## Verification

Windows 11 x64: the probe ends at 17 MB (manual) / 15 MB (`-mm=gc`); Node 24 ends at 54 MB. Linux x86-64 (Docker):
17 MB manual. macOS not run.
