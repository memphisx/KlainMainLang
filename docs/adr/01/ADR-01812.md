# ADR-01812: strict code rejects `yield` names, not `yield` property names

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- ADR-01799 rejected a `yield` read as an identifier in strict code by recording every `yield` token the parser peeked outside a generator. Property names go through the same peek: a `yield()` method, a `{ yield: 1 }` key, `o.yield`. Strict code with one then failed to parse, including the builtin `timers/promises` module, whose `Scheduler` has a `yield()` method. Its examples and the builtin-declarations test failed.

## Decision

- The check walks the parsed program instead of the tokens. A `yield` identifier reference is an error, and so is a binding named `yield`: a variable, a parameter, a function or class name, or a catch parameter. A class's methods and constructor are named by property keys and are skipped.
- The token record (`yieldIdents`) is deleted.

## Consequences

- `TestStrictYieldNames` covers the rejected names and the accepted property names, in a module and a `"use strict"` script.
- `examples/timers/module.ts`, `examples/timers/promises.ts` and `TestImplementedBuiltinsHaveDeclarations` pass again.
