# ADR-00407: Node oracle — reclassify shimmable harness helpers as in scope

- **Relations**: Extends ADR-00402, [TDD-00121](../tdd/TDD-00121.md) Track B
- **Date**: 2026-08-27

## Context

An audit of the Node oracle's skip buckets found ~450 files labeled out of
scope ("requires Node common harness" / "unsupported module") whose actual
blocker was a constant or a one-line function: `common.platformTimeout(ms)`
(returns its argument), `common.localhostIPv4` (`'127.0.0.1'`),
`common.PIPE` (a unix-socket path), `common.hasOpenSSL3` (a boolean probe),
`common.skipIfWorker`/`skipIfDumbTerminal` (no-ops here), and the whole
`require('../common/tmpdir')` module (~212 files — a temp-dir path plus
`refresh()`/`resolve()`). Labeling those out of scope silently inflated the
pass rate's denominator honesty: the rate was computed only over files the
runner deigned to attempt.

## Investigation

The skip-reason histogram in the generated report, cross-checked against
`.node-tests/test/common/index.js` for what each helper actually does, and
against `docs/status/` for which modules the compiler really implements.
Genuinely-out-of-scope buckets (dynamic `require`, `vm`, `node:test`,
inspector-gated files, `.call`/`.apply`) were left untouched; the borderline
`invalidArgTypeHelper` bucket (files asserting Node's exact dynamic-misuse
error strings, which a typed compiler rejects at compile time) stays skipped
with its verdict recorded in the gap analysis.

## Decision

- Extend `commonShimmable` with the pure-value/no-op helpers; the injected
  `common` shim literal is now built per file (`commonShimFor`) so `PIPE` is
  unique per test and parallel workers don't collide on one socket path.
- Generate a typed `../common/tmpdir` shim (`writeTmpdirShim`) alongside the
  existing fixtures shim: `path` is `/tmp/kml-tmpdir-<pid>`, `refresh()`
  ensures it exists (no recursive wipe — `fs.rmSync` is unimplemented, which
  is enough for the corpus's create-and-write usage), `resolve(...)` joins.
- Add `NODE_RAW_REASONS=1` alongside `NODE_FAILLIST`: the fail list then keeps
  each failure's concrete identifier/position detail instead of the
  `%s`-normalized histogram buckets — without this, triaging "which method is
  actually missing" required re-running files by hand.
- Record the interpretation contract in `docs/testing/NODE-GAP-ANALYSIS.md`
  (hand-written companion the generated report now links): a module `docs/
  status/` marks ✅ may never be skipped as "unsupported module", and a skip
  reason naming a one-line helper is a shim waiting to be written.

## Implementation notes

`tools/conformance/node.go` only. The reclassification moved 259 files from
SKIP to attempted: 3478 total went from 26 passed / 1318 failed / 2134
skipped to 27 / 1576 / 1875 — the pass rate over attempted files *dropped*
1.9% → 1.7%, which is the honest direction.

## Side effects discovered

- The `http2` (~224 files) and `https` (~54) skip buckets are correctly
  labeled "unsupported module" but are in-scope-not-delivered features, not
  harness noise — flagged in the gap analysis.
- `fs.rmSync` and `fs.mkdirSync`'s options argument are unimplemented
  (surfaced writing the tmpdir shim).

## Verification

`go test ./tools/conformance` passes; full `-suite=node` run regenerated
`CONFORMANCE-RESULTS-NODE.md` with the new totals (Mac).
