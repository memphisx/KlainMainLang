# ADR-00359: Cross-worker `http.close()` via a shared mmap flag

- **Relations**: Implements [TDD-00117](../tdd/TDD-00117.md). Extends [ADR-00097](ADR-00097.md) (clustering fork), [ADR-00102](ADR-00102.md) (`http.close()`).
- **Date**: 2026-08-25

## Context

`http.close()` in a `{ workers: N }` cluster stopped only the calling worker's
listener; the other `N-1` forked processes kept accepting on the shared socket,
so a full-cluster shutdown needed an external signal to the process group. This
was the caveat dropping the `http.close()` row out of HTTP Server Strict
Coverage. First item of the HTTP-Server caveat-cleanup pass (the null-byte
string caveat is deferred to its own effort).

## Investigation

Cluster workers are real `fork()`ed processes (`runtime_http.go`'s
`__kml_http_cluster_fork`), unlike `new Worker(...)` which is a pthread sharing
the address space (`runtime_worker.go:165`) — so signalling a sibling needs a
genuine cross-process channel. Options weighed in [TDD-00117](../tdd/TDD-00117.md):
a shared anonymous `mmap` flag (chosen), tracked child PIDs + `kill` (only works
from the primary; needs signal handlers), and `kill(0, SIGTERM)` to the group
(collides with the user's own `SIGTERM` graceful-shutdown handler, and SIGTERM's
default disposition kills rather than drains).

## Decision

A single `MAP_SHARED|MAP_ANONYMOUS` word, `mmap`'d before the fork so every
worker inherits the same physical page:

- **`__kml_http_cluster_fork`**: when it actually forks (`numWorkers > 1`),
  `mmap` 8 bytes and store the pointer in a new global
  `@__kml_cluster_close_flag` (init 0). `MAP_FAILED` leaves the flag null —
  cross-worker close degrades to the caller's own listener, no boot failure.
- **`__kml_http_close`**: if the flag pointer is non-null, `store atomic i64 1`
  into it (`seq_cst`) before the existing local teardown.
- **Event loop (`afteresreconnect`)**: each iteration, if the flag is non-null,
  atomically load it; if set and this worker still holds a listener, run the
  same local teardown (`close(listenfd)`, `@__kml_listen_fd = -1`). The existing
  drain logic then lets each worker finish in-flight connections and exit.
- **Loop timeout**: in cluster mode (flag non-null) force the bounded
  `timeoutpath` and cap the `select()` wait at 200ms, so an *idle* sibling —
  otherwise blocked in `select()` with an infinite timeout — wakes to poll the
  flag promptly. Without this an idle worker would only notice the flag when a
  connection happened to wake it.

Single-process programs (`workers ≤ 1`) never mmap the flag, so every access is
a guarded no-op and behavior is byte-identical to before.

## Implementation notes

- New `ensureMmapDecl` (`runtime_core.go`) + `usedMmapDecl` flag, following the
  declared-exactly-once pattern (mmap is otherwise unused).
- `mmapSharedAnonFlags()` (`runtime_http.go`): `MAP_SHARED|MAP_ANONYMOUS` is
  `0x1001` on Darwin, `0x21` on Linux (MAP_ANONYMOUS is `0x1000` vs `0x20`).
- The flag global is declared in `ensureHTTPClusterFork`, which `ensureHTTPRuntime`
  always calls, so both `__kml_http_close` and the event loop can reference it
  whether or not the program uses clustering.
- The shared word is monotonic 0→1, so the atomics are a plain `seq_cst`
  store/load — no CAS, no ABA.

## Side effects discovered

The idle-cluster-worker `select()` wakeup cadence (200ms) is a poll, not an
event. A self-pipe/eventfd added to the fdset would let a sibling's `.close()`
wake the others immediately with no periodic wakeup; noted as a possible future
optimization, not needed for correctness (shutdown latency is ≤200ms + drain).

## Verification

- `TestE2EHTTPListenClusterCloseReachesAllWorkers` (new): a single `/shutdown`
  making one worker call `http.close()` must make the shared inherited socket
  refuse connections (proving all 3 workers closed). Passes in ~0.8s **with**
  the fix; **negative control** (implementation reverted) fails — the port stays
  accepting for the full 5s deadline.
- `HTTPListen|Cluster|Close|Timer|EventSource|WebSocket` suites pass (the loop
  timeout change is exercised by every server/timer test).
- `go build`/`go vet` clean.
