# ADR-01564: `for await` over a Map iterates its entries

- **Date**: 2026-10-10

## Context

`for await (const v of m)` over a `Map` bound each value (`5`, `7`). Node
binds each `[key, value]` entry (`[ 'a', 5 ]`), exactly as a sync
`for...of` over the Map does. `for await` over a sync iterable is the
same iteration with each value awaited (CreateAsyncFromSyncIterator), and
an entry is not a thenable. `for await (const [k, v] of m)` was rejected
as a non-tuple element. Found while checking `examples/async/for_await_iterables.ts`
against Node; the example's comment and `TestE2EForAwaitOverSyncMapAndSet`
both encoded the divergent output.

## Investigation

The `for await` arm for a Map or Set (`emit_stmts.go`) materialized
`mapOrSetValuesArray`, which is a Set's elements but a Map's values.

## Decision

A Map materializes its entries (`emitMapEntries`, the `[K, V]` tuple
array `m.entries()` builds); a Set keeps its elements. Each is iterated by
the array loop's per-element await.

## Implementation notes

`codegen/llvm/emit_stmts.go`. The test now expects Node's output and adds
a destructuring loop; the example's comment is corrected.

## Side effects discovered

None.

## Verification

`TestE2EForAwaitOverSyncMapAndSet`; `examples/async/for_await_iterables.ts`
matches Node (Mac).
