# ADR-00847: `Number.prototype.toLocaleString()` — the no-argument en-US default

- **Relations**: Reuses the embedded `dtoa.c` (as [ADR-00832](ADR-00832.md) did)
- **Date**: 2026-09-10

## Context

`(1000000).toLocaleString()` was "a number has no method 'toLocaleString'". The
full method is an Intl feature (locale/options arguments), which this compiler
deliberately does not carry — but the **no-argument** form has a fixed,
well-defined default (en-US: group the integer part with commas, keep at most 3
fraction digits, rounded) and is very common for display. Leaving it a compile
error is a real gap distinct from the Intl-out-of-scope decision.

## Decision

- New runtime `__kml_num_tolocalestring(char *buf, double v)` in `dtoa.c`:
  formats `%.3f` (rounds to ≤3 fraction digits), strips trailing fraction zeros
  (and the point when the fraction is empty), then groups the integer part with
  commas every three digits. `NaN` → `"NaN"`, `±Infinity` → `"∞"`/`"-∞"`, `-0` →
  `"0"`.
- `emitNumberToLocaleString` calls it (via `ensureDtoa`, which forces `dtoa.c`
  in). A locale/options **argument** is a clean rejection naming Intl as the
  reason. `inferExprType` types it `string`.

## Implementation notes

`dtoasrc/dtoa.c` (`__kml_num_tolocalestring`); `float_fmt.go` (declaration);
`emit_strings.go` (`emitNumberToLocaleString`); `emit_call.go` (dispatch, guarded
on a numeric receiver); `emit_exprs_types.go` (inference). Buffer sized 512 for
the widest double's grouped integer part.

## Verification

macOS (Apple Silicon M4): matches Node — `(1000000)` → `1,000,000`, `(1234.5)` →
`1,234.5`, `(1234.5678)` → `1,234.568` (rounded), `(-9876543.21)` →
`-9,876,543.21`, `(999)` → `999`, `(0)` → `0`; an integer-typed receiver
(`n.toLocaleString()`) too. New `TestE2ENumberToLocaleString` + the number/
conversion suites green.
