# ADR-00980: `fs.readdirSync` supports `{ recursive: true, withFileTypes: true }`

- **Relations**: Extends ADR-00752, ADR-00786, ADR-00787
- **Date**: 2026-09-16

## Context

`fs.readdirSync` already implemented each of its two option flags independently:
`{ withFileTypes: true }` returns a `Dirent[]` (name + `parentPath` + kind
predicates, ADR-00752/ADR-00787) and `{ recursive: true }` walks the whole
subtree returning a `'/'`-joined `string[]` (ADR-00786). Passing *both* together
was a clean compile-time rejection. Node returns, for that combination, a
`Dirent[]` covering every entry in the tree, where each `Dirent.parentPath` is
the full path of the directory the entry was read from and `.name` is its
basename.

The rejection's stated reason — "recursive Dirents need `parentPath`, which this
compiler's Dirent has no field for" — was stale: `DirentType` has carried a
`parentPath` field since ADR-00787, and the non-recursive `withFileTypes` path
already populates it. The only thing missing was a recursive descent that builds
Dirents instead of joined relative-path strings.

## Decision

Accept `{ recursive: true, withFileTypes: true }` and return a faithful
`Dirent[]`: one Dirent per entry in the whole subtree, `.name` = basename,
`.parentPath` = the full path of the containing directory, `.mode` = the hidden
`S_IFMT` word derived from `d_type` (backing the kind predicates), matching the
non-recursive `withFileTypes` shape.

## Implementation notes

- `codegen/llvm/emit_fs.go`: the recursive+withTypes combination no longer
  rejects; it calls the new `@__kml_fs_readdir_recursive_types` and returns
  `ArrayOf(DirentType())`.
- `codegen/llvm/emit_exprs_types.go`: `inferExprType` now returns
  `Dirent[]` for `withFileTypes` regardless of `recursive` (was: only when
  `recursive` was absent), keeping the type in lockstep with the emitter.
- `codegen/llvm/runtime_fs.go`: `ensureFsReaddirRecursiveTypes` — a structural
  merge of `__kml_fs_readdir_rec` (the recursive descent, ADR-00786) and the
  `mkdirent` block of `__kml_fs_readdir` (the Dirent builder, ADR-00752). Each
  entry becomes a `{ptr name, ptr parentPath, i64 mode}` heap struct;
  a subdirectory (`d_type == DT_DIR`) is descended with its full path.
  `parentPath` is a header-copied string of the descent path `%full` (its own
  copy, since the caller frees the malloc'd descent path after the recursive
  call returns). No per-file `stat`; a `DT_UNKNOWN` filesystem is still not
  descended, as with the string-form recursive walk.

## Side effects discovered

None. The stale "no `parentPath`" reason in the rejection was corrected in the
status caveats (`docs/status/data/file-system.json`); the `.path` alias for
`.parentPath` and `encoding: 'buffer'` remain genuine open edges.

## Verification

- `go build` + `go vet ./codegen/...` clean.
- Output byte-identical to Node's `fs.readdirSync(dir, { recursive: true,
  withFileTypes: true })` on a three-level fixture tree (name/parentPath/kind of
  every entry), verified on macOS arm64 (M4).
- New E2E test `TestE2EFsReaddirSyncRecursiveWithFileTypes` (replaces the former
  `...Rejected` test); `examples/fs/fs.ts` extended and runs.
