# ADR-00423: chained `createServer().listen()` binding + function-less `mustCall()`

- **Relations**: Extends [ADR-00406](ADR-00406.md) (server handle), [ADR-00370](ADR-00370.md) (`mustCall`); Implements part of [TDD-00131](../tdd/TDD-00131.md)
- **Date**: 2026-08-28

## Context

The fresh Node-oracle failure histogram put two idioms near the top:

- ~140 files failing "a number has no method 'address'/'close'/'on'/…" —
  all the chained-binding idiom `const server =
  http.createServer(cb).listen(0, readyCb)` with `server.address().port`
  read inside the ready callback (Node's `listen()` returns the server).
- 12+ files failing "test.mustCall takes 1-2 arguments" — Node's
  function-less forms `common.mustCall()` / `mustCall(n)`, which count a
  noop; plus 7 more failing "undefined function or closure 'callback'"
  from binding that wrapper to a variable.

## Investigation

- The chained form had its own emitter returning `void` (so the binding
  inferred `number`, producing the method errors), while the
  variable-bound handle (ADR-00406) already had everything needed:
  `.listen(port?, cb?)`, `.address()`, `.close()`. The one real obstacle:
  in `const server = …listen(0, cb)`, the ready callback and the event
  loop run *inside* the initializer, before the normal var-decl store —
  `server` would be read uninitialized inside the callback.
- Zero-arg `mustCall()` failed twice over: the arity gate, and call-type
  inference returning the *first argument's* type (absent → `i64`, so a
  bound wrapper wasn't callable).

## Decision

- Route the chained form through the bound-handle machinery and delete
  the bespoke chained emitter: a shared `chainedCreateServerListen`
  AST matcher feeds `emitHTTPCreateServer` + `emitHTTPServerListen`,
  and `listen()` now returns the handle (Node's contract). A var-decl
  whose initializer matches the chain is split: build the handle, store
  it into the binding, *then* emit listen — so the ready callback sees a
  live `server`. Call-type inference returns `HTTPServerType()` for the
  chain.
- `mustCall()` / `mustCall(n)` (and `mustSucceed()` / `mustCallAtLeast(n)`)
  synthesize an empty zero-param arrow and reuse the counting wrapper
  unchanged; inference returns `() => void` when no function argument is
  present.

## Implementation notes

- `codegen/llvm/emit_http.go`: `chainedCreateServerListen` matcher +
  `emitChainedCreateServerListen` (optional pre-store hook);
  `emitHTTPServerListen` returns the handle; old
  `emitHTTPCreateServerListen` removed.
- `codegen/llvm/emit_call.go`: chained branch now three lines.
- `codegen/llvm/emit_exprs_vardecl.go`: the chain split (store before
  listen).
- `codegen/llvm/emit_exprs_types.go`: chain → `HTTPServerType()`;
  function-less `mustCall` family → `FuncType(nil, void)`.
- `codegen/llvm/emit_testmod.go`: noop synthesis; arity message updated.

## Side effects discovered

- The HTTP-SERVER.md caveat "a handler wrapped in `mustCall(fn)` isn't
  contextually typed" had already been false since ADR-00412 — removed
  while updating the row.

## Verification

- New E2E: `TestE2EHTTPChainedListenBinding` (full corpus shape: chained
  binding, `address().port` in the ready callback, in-process client,
  close), `TestE2ETestMustCallZeroArg` (+ unmet-expectation exit-1
  twin). New example `examples/http/chained_listen.ts` (self-contained
  request-and-close), verified by run.
- Relevant suites re-run green: `TestE2EHTTP*`, `TestE2ENodeStream*`,
  `TestE2ETest*` (Mac). Node oracle rerun accompanies this change.
