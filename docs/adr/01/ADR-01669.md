# ADR-01669: An isolated island's loop is a watched handle on the importer's

- **Relations**: Implements TDD-00244, Extends ADR-01056
- **Date**: 2026-10-17

## Context

An isolated dynamic-import island with a top-level await runs its own copy of the runtime, so it has its own libuv loop. The importer drove it through three hooks in its event loop: a dispatch that polled every pending island on each pass, a keep-alive that held the loop while an island was not idle, and a deadline folded into the wait. The island's sockets were invisible to the importer's wait, so a pending island with no timer capped that wait at 10 ms: the importer polled. TDD-00244 Stage 5 says islands become tasks on the importer's loop and the hooks go.

## Decision

An island keeps its own loop: it is a separate program by design (`-dynamic-import=isolated`), with its own instance of every module, its loop state included. The importer watches that loop as handles on its own:

- **Backend watcher.** A read watcher on the island loop's backend descriptor (epoll/kqueue). It fires when anything in the island is ready: a socket, a thread-pool completion, a signal. On Windows the backend is a completion port, which has no descriptor. A thread waits on the port, puts back what it took, and wakes the importer with a `uv_async_t`, as the webview embedding does (`loop_embed.cc`).
- **Deadline timer.** A timer at the island's earliest timer deadline. The first pass is a zero-delay start of the same timer.
- Either one runs one non-blocking pass of the island and re-arms both. The watcher is referenced while the island is pending and not idle, so it alone holds the importer's loop. When the island's module promise settles, both handles close and the import() promise settles.
- **Exports.** The poll and the backend are fixed-name exports in a small C unit linked into islands with a top-level await (`islandsrc/island.c`). The importer looks them up on the island's handle. An island without a top-level await has neither and is never polled.
- **Removed.** The three dynimport hooks (`hooks.c`), their uses in `__kml_event_loop_run`, and the 10 ms cap.

## Divergence from TDD-00244

The TDD has islands become tasks on the importer's loop. That would merge the island's loop state into the importer's, which is what `isolated` exists to prevent. Watching the island's loop as a handle meets the stage's goal: the loop holds by handle reference, and no keep-alive predicate or poll remains.

## Implementation notes

- `__kml_loop_pass` (loop.c) runs one non-blocking pass and returns whether it found the loop idle. `__kml_loop_run_once` (the webview embedding) calls it.
- New loop entry points:
  - `__kml_loop_backend_handle`;
  - `__kml_loop_async_new`/`_send`, a referenced cross-thread wake-up;
  - `__kml_loop_timer_free`.
- The island's IR glue loses its `_poll` definitions, so the IR-text allowance for `emit_dynimport.go` drops from 9 to 7.

## Side effects discovered

- **Deferred watcher registration.** libuv hands a new watcher to the kernel only at the start of its next poll. An island pass that started I/O, such as a socket's connect, left that descriptor outside the island's epoll set. The backend descriptor then never became readable, and the import hung on Linux. On the Mac the test passed by timing. `__kml_loop_pass` now repeats, at most 64 times, while libuv holds unregistered watchers (`loop.watcher_queue` non-empty) or work is runnable. After that, whatever remains can wake the island only through its backend descriptor or a timer. The webview embedding's `__kml_loop_run_once` goes through the same pass, and its host loop watches the same descriptor, so it gets the fix too.

## Verification

- New test `TestE2EDynamicImportIsolatedIslandAwaitsSocket`: an island awaits a TCP round trip on its own loop, with no timer pending.
- The dynamic-import and top-level-await tests pass on Mac. The dynamic-import tests pass on Linux (DeskMini). The first test-par run on Node304 hung in the new test before the deferred-registration fix.
- Emitted IR is byte-identical over the 68-file IR list (none uses `isolated`).
- The Windows thread path has not been built yet; CI is its first build.
