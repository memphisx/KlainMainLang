# ADR-01852: Function and object literals take the checker's type; `{ __proto__ }` is an own property

- **Relations**: `Implements TDD-00230` (P3.3: the checker answers what inferExprType did)
- **Date**: 2026-10-21

## Context

- Arrow functions and function expressions were still typed by inferExprType. The shadow harness showed only a few disagreements left for them, all on find-kin callbacks, which the oracle already patches the way findElemHint does.
- Object literals in the js lane, and literals using the `__proto__: value` form, are built as dynamic objects by emission, but the oracle answered them with a fixed layout or the synthetic accessor class.
- `hasProtoKey` and the dynamic-object literal path also treated the shorthand `{ __proto__ }` as the prototype-setting form. In JavaScript only `__proto__: value` sets the prototype; the shorthand defines an ordinary own property named `__proto__`. `Object.keys({ __proto__ })` printed nothing and the prototype was replaced.

## Decision

- `ArrowFunction`, `FunctionExpression` and `ObjectLiteral` join the node kinds whose type comes from the checker oracle (`reprOracle`), falling back to inferExprType only when the oracle has no answer.
- The oracle gives a box to an object literal using the `__proto__:` form, and to every bare object literal under `-compat=js`, accessor-bearing ones included.
- An annotated return on a function literal is the annotation as emission resolves it (`resolveType`). A declared tuple (`(a, b): Pair => [a, b]` with `type Pair = [number, number]`) is a positional struct, while the checker's tuple maps to an array; reading the struct as an array crashed the program.
- A function expression reading `arguments` carries the synthetic rest parameter emission appends (`maybeAddArgumentsRestParams`), which the checker's signature leaves out, so a call through it still stores its argument count.
- A sloppy js-lane function expression that reads its own `this` and `arguments` without taking `this` (a lowered `this`-reading declaration) stays dynamic, as emission builds it. The FunctionDeclaration `arguments` rule allows for a prepended `this` parameter.
- The checker types a js-lane destructured rest parameter (`...[a, , b]`) as `any[]`, the array it collects, not `any`.
- In a union, a `Promise<never>` (a `Promise.reject`) beside another promise adds nothing: `[Promise.reject(e), Promise.resolve(2)]` holds promises of number, so `Promise.any` over it decodes the number winner.
- The js-lane rule runs before the checker lookup, and the GlobalType accessor-class rule is strict-lane only, so no synthetic accessor class is registered for a js-lane literal that emission builds dynamically.
- The shorthand `{ __proto__ }` is excluded from both `hasProtoKey` and the literal path's prototype handling, so it defines an own property as in Node.

## Consequences

- `TestShadowRecordsDisagreementsWithoutChangingIR` now checks an Identifier row, as arrow functions no longer go through inferExprType.
- `TestE2EProtoShorthandIsOwnProperty` compares the shorthand, the `__proto__:` form and `__proto__: null` against Node.
- Verified on Apple Silicon (targeted arrow, closure, callback, array-method, dynamic-object E2E tests).
