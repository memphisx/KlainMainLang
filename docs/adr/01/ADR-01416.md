# ADR-01416: The Sailfish sysroot carries libuv and the runtime's C libraries

- **Relations**: Extends ADR-00817, ADR-01404
- **Date**: 2026-10-05

## Context

TDD-00244 put every program's event loop on libuv, and the Sailfish webview
shim (Stage 7) on Qt's notifier and timer over it. A cross build against the
sysroot `docker/Dockerfile.sfos-sysroot` produces failed for every program,
with or without a webview: `uv.h` not found. Past it, `tommath.h` and
`nghttp2/nghttp2.h` were missing and `-lcurl`/`-lpcre2-8` found no `.so`.

The cross build also showed each runtime C source's `-D` flags reaching every
other source (`KML_NB_UNDEFINED` redefined in `fserror.c`).

## Investigation

- Jolla's repos package `libcurl-devel`, `pcre2-devel`, `libnghttp2-devel`,
  `openssl-devel` and `sqlite-devel`; they carry neither libuv nor
  libtommath, and the device ships neither.
- Without the object cache (a cross target, `-no-cache`) `main.go` compiles
  all runtime sources in one clang command, where a `-D` is global; the
  cached path compiles each source with its own flags.

## Decision

- The sysroot image installs those `-devel` packages and builds libuv
  (1.51.0) and libtommath (1.3.0) from pinned releases as static archives
  only, so `-luv`/`-ltommath` resolve to them and the program carries both,
  needing nothing extra on the phone.
- Where sources share one clang command (`main.go` without the cache, and
  the conformance runner's Test262 and Node-core drivers), a source's `-D`
  flags become `#define` lines at the top of its own text
  (`CSource.Standalone`).
- `fetch.c` and `asynchooks.c` stop passing the defines the layout header
  they include already gives (`KML_NB_UNDEFINED`, `KML_TAG_OBJECT`).

## Verification

Mac (M4), Docker arm64: the image builds; from an arm64 Debian container with
clang 19, `--target sfos-aarch64 --sysroot` cross-builds a timer program, an
AsyncLocalStorage + fetch program and `examples/webview/{bindings,inline,
spa_server}.ts` (`-webview=sailfish`) to aarch64 PIE executables, with no
compiler warnings. `bindings` links Qt5/xul/sailfishwebengine and defines
`__kml_loop_backend_fd`/`__kml_loop_next_ms`, which its `QSocketNotifier`
and `QTimer` drive; libuv's `uv_run` is linked in statically. Not run on the
device (no phone here). `-no-cache` and cached builds of the same programs
behave the same on the Mac.
