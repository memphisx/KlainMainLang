# ADR-00804: Multi-server relisten + WebSocket/upgrade on the primary — TDD-00191 Stages 2–3 (in part)

- **Relations**: `Implements TDD-00191`, `Extends ADR-00803`
- **Date**: 2026-09-09

## Context

ADR-00803 shipped TDD-00191 Stage 1: multiple concurrent plain Node HTTP servers
in one program via an extra-listener table plus per-server suffixed dispatchers.
It left two Stage-1 boundaries as clean rejections and two later stages open:

- Stage 2's `listen()`-after-`close()` (relisten) on an additional server was
  unverified — `close()` cleared the table entry (fd = -1), but a later
  `listen()` was never exercised end to end.
- Stage 3 rejected *any* additional server whenever the program used
  WebSocket/`upgrade` handling anywhere, even when that handling belonged to the
  primary server — the common shape of "an app that speaks WebSockets on its main
  port and exposes a plain health/metrics port on another."

This ADR closes Stage 2 and the tractable half of Stage 3.

## Investigation

- `emit_http.go` server `listen`/`close` branch on the handle's primary flag
  (slot 3): the primary hits the `@__kml_listen_*` scalars, an additional server
  the extra-listener table (`__kml_http_register_extra_listener` /
  `__kml_http_close_extra_listener`). A relisten therefore just re-appends a
  table entry — it worked untested, but `register_extra_listener` always
  *appended*, so a `close()`/`listen()` cycle leaked a dead (-1) entry per
  relisten (`runtime_http.go:1040`).
- The ws/upgrade diverts in `buildHTTPDispatcher` (`emit_http.go` ~1870/1892)
  were gated only on the whole-program `usedKlainWS`/`usedHTTPUpgrade` flags, so
  every server's dispatcher — primary and additional — emitted them, all reading
  the primary's fixed handler globals (`@__kml_listen_ws_handler` /
  `_upgrade_handler`). The broad createServer rejection was what kept that
  latent mis-wiring unreachable.
- The handler registration sites (`server.on('upgrade', …)` in `emit_http.go`;
  `new WebSocketServer({ server })` in `emit_ws_server.go`) store into / attach
  to those fixed globals with no record of *which* server handle they name — the
  `.on` machinery still assumes one server (`httpServerHandlerPending` is a
  single bool). Associating a non-primary handle with its own suffixed globals is
  the remaining Stage-3 slice and needs handle→suffix tracking, so it is left
  out here.

## Decision

**Stage 2 — relisten.** Keep the primary-flag routing; make
`__kml_http_register_extra_listener` reuse the first freed (fd < 0) table slot
before appending, so a `close()`/`listen()` cycle stays bounded rather than
leaking a dead entry per relisten. Primary relisten already worked (close sets
`@__kml_listen_fd = -1`; listen rebinds and stores the new fd).

**Stage 3 (in part) — ws/upgrade on the primary + plain additional servers.**

- Gate the dispatcher's WebSocket and `'upgrade'` diverts to the *primary*
  dispatcher only (`usedKlainWS && isPrimary`, `usedHTTPUpgrade && isPrimary`):
  they read the primary's fixed globals, so an additional server's dispatcher
  must not emit them. An additional server stays plain HTTP/1.1.
- Drop the createServer rejection that forbade *any* additional server when
  ws/upgrade was used. It is now allowed, because the handlers can only attach to
  the primary.
- Because the registration sites still target the primary's globals, guard them:
  `emitHTTPRequirePrimaryHandle(handleRef)` emits a runtime check on the handle's
  primary flag (slot 3) at `server.on('upgrade', …)` and at
  `new WebSocketServer({ server })`; a non-primary handle prints a clear message
  and `exit(1)`. This converts what would otherwise be a silent mis-attach to the
  primary into a clean runtime rejection. The check runs once, at registration,
  not per request.

Making a *non-primary* server the ws/upgrade server, HTTPS multi-instance, and
HTTP/2 per-listener + cluster coexistence remain (TDD-00191 Stage 3 remainder +
Stage 4).

## Implementation notes

- `runtime_http.go` `__kml_http_register_extra_listener`: a scan-for-free-slot
  loop ahead of the grow/append path; the grow check now loads `%cap` in its own
  block since the reuse loop precedes it.
- `emit_http.go`: `buildHTTPDispatcher` ws/upgrade blocks gated on `isPrimary`
  (already a parameter); the createServer ws/upgrade rejection removed; new
  `emitHTTPRequirePrimaryHandle` helper + `httpPrimaryGuardMsgEmitted` dedup flag
  (`emitter.go`); guard call added at the `'upgrade'` `.on` site.
- `emit_ws_server.go`: `new WebSocketServer({ server })` now captures the server
  handle Value and guards it when it is an `http`/`https` server handle.

## Side effects discovered

None beyond the register-slot leak fixed here. The primary path is byte-unchanged
for single-server programs (all WebSocket/upgrade/HTTP/2/cluster suites pass).

## Verification

Mac (Apple Silicon). `tests/http_test.go`: `TestE2EHTTPMultipleServersRelisten`
(additional server closes and relistens on a fresh port, then serves there),
`TestE2EHTTPMultipleServersUpgradeOnPrimary` (upgrade echo on the primary + a
plain additional server, both exercised), `TestE2EHTTPMultipleServersUpgradeOnExtraRejected`
(upgrade on a non-primary handle aborts at runtime with a clear message; the old
compile-time-rejection test it replaces no longer applies). Full `TestE2EHTTP*`,
HTTPS, upgrade, and WebSocket suites green; `go vet` clean;
`examples/http/multi_server_upgrade.ts` compiles, runs, and exits cleanly.
