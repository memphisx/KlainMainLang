# ADR-01785: Pattern defaults and hoisted class expressions take their inferred names

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- NamedEvaluation (`inferFunctionNames`) named an anonymous function that initialized a variable, parameter, property, assignment or class field. A default inside a destructuring pattern (`[arrow = () => {}]`, `{ fn = function () {} }`) got no name.
- Anonymous class expressions got no inferred name anywhere except `const K = class {}`. Class expressions are hoisted before names are inferred, and the parser gives an anonymous class a `$` placeholder name, which the name pass did not count as anonymous.

## Decision

- The name pass also visits `ArrayPatternElem` and `DestructProp` leaves with a default.
- It treats a placeholder-named class as anonymous (`anonymousClass`). It runs once before class expressions are hoisted, and the hoist records each inferred name as the class's shown name (`classShownNames`), which `classDisplayName` reads.

## Consequences

- `TestE2EJSFilePatternDefaultNames` compares `.name` against Node for array and object pattern defaults, parameter defaults, properties and assignments.
