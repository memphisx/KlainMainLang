# ADR-01565: Only a generator function is held boxed in an object literal

- **Relations**: Extends ADR-01562
- **Date**: 2026-10-10

## Context

`examples/async/for_await_iterables.ts` crashed (SIGSEGV) at
`const obj = { [Symbol.asyncIterator]: () => agen() }; for await (const x of obj)`
once calls took their type from the checker.

## Investigation

`inferObjectType` held a property boxed when its value's type was a
function returning a generator. That rule is meant for generator methods
(`{ *gen() {} }`), which are emitted as boxed functions. Before ADR-01562,
the arrow `() => agen()` happened to be typed with a non-generator result,
so its field stayed a typed closure. Typed correctly, its result is the
generator `agen()` constructs, the rule boxed the field, and the `for
await` over an object with a boxed `[Symbol.asyncIterator]` crashed.

The two cases have the same checker type, so the rule cannot rely on the
type. It has to look at the value.

## Decision

A property is held boxed when its value is a generator function
expression (`IsGenerator`), not when its value is a function that returns
a generator.

## Implementation notes

`codegen/llvm/emit_exprs_types.go` (`inferObjectType`).

## Side effects discovered

The minimized repro's `async function work(n): Promise<number>` with an
empty body printed `0` where Node prints `undefined`. tsc rejects that body
(TS2355) and this project's checker does not report it yet; likewise a
generator annotated with its element type (`function* f(): number`, TS2322),
which `examples/` and `tests/` use widely.

## Verification

`examples/async/for_await_iterables.ts` matches Node (Mac); the minimized
repro and an `async *[Symbol.asyncIterator]()` method literal both run.
