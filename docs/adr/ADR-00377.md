# ADR-00377: `number` defaults to IEEE-754 double (TDD-00123 Stage 1)

- **Relations**: Implements [TDD-00123](../tdd/TDD-00123.md)
- **Date**: 2026-08-26

## Context

TypeScript/JavaScript's `number` is a 64-bit IEEE-754 double; this compiler
modelled a bare `: number` (and every numeric literal) as `i64`, the single
largest fidelity gap in the project (`0.1 + 0.2 === 0`, `10 / 3 === 3`, `2 **
-1 === 0`). TDD-00123 Stage 1 flips the default to `float64`, keeping the
explicit integer types (`int8..int64`, `uint8..uint64`) as the opt-in escape
hatch for real integers.

## Decision

Flip the default at the three seams that decide a numeric type, then coerce at
every boundary where an i64-represented value meets a now-float `number`.

**The three seams** (must agree — the primary desync risk):
- `ResolveTypeName("number")` → `TypeF64` (`types.go`).
- `emitNumberLit` — every non-bigint literal (integer, hex, bin, oct, oversize)
  is a `float64`, emitted as an LLVM hex-float constant via `llvmDoubleLit`
  (`0x%016X` of the value's bits — exact, and avoids the `7e+00`
  integer-constant-in-a-double-slot error a decimal/exponent formatter causes).
- `inferExprType(*ast.NumberLiteral)` → `TypeF64`.

Plus the unannotated numeric defaults (`emit_func.go` inferred params/returns/
rest-elements) and the `emitVarDecl` / `reliableGlobalType` numeric-literal var
typing (both had their own i64 literal deciders).

**What rides existing machinery for free:** arithmetic (`fadd`/`fdiv`…),
comparison (`fcmp`), unary/`++`, coercion, and dtoa printing all already branch
on `Type.Float` (the `float64` support), and mixed int/float promotion already
covers `arr.length / 2` etc. — so those needed no change.

**Boundary coercions added** (i64-slot ↔ `number`):
- **Callback-param ABI** — a runtime that invokes a user callback with a
  `number` param (process/worker/child-process `exit`/`close` code) now
  `sitofp`s the i64 to a double at the call site.
- **Map/Set number keys** — `valueToMapKey` bitcasts a `double` key to i64
  (full bit pattern, so `1.5 ≠ 1` — also fixes a pre-existing fractional-key
  collision); reads load as `keyTy.IR` (double) directly.
- **Map value type from annotation** — a bare `new Map()` under an annotated
  `Map<K,V>`/`Record<string,V>` takes K/V from the annotation
  (`emitMapVarDecl`/`reliableGlobalType`) — latent before, since the i64 default
  equalled `number`.
- **float→narrow-int coercion** — via a signed i64 intermediate then `trunc`,
  giving JS `ToUint8`/`ToInt32` modular wraparound (`300 → 44`, `-1 → 255`) and
  avoiding the out-of-range `fptosi`-to-i8 UB that produced `0`.
- **Sort comparator** — the custom-comparator trampolines call the closure with
  a `double` return and reduce it to qsort's `-1/0/1` sign (an fptosi would
  collapse a fractional difference).
- **HOF callback return-type inference** (`callbackReturnType`) now binds the
  callback params to the receiver's element type so `map`/`flatMap`/`filter`
  infer the same element type the emission produces (was defaulting the param to
  a scalar, mistyping the result array).
- **BigInt** — `BigInt(x: number)` converts an integer-valued finite double
  (runtime `RangeError` for a fractional/NaN/Infinity/out-of-range value,
  matching JS); bigint↔number comparison is now the exact comparison in both
  `-compat` modes (blanket-rejecting a float operand is hostile now that every
  number is a float).
- **Zero values** — `.at()`/`.find*` result-slot inits and the bare-`return`
  default use `zeroRef` (`0.0` for a float), not a hard-coded `0`.
- **Date** duration arithmetic coerces both operands to i64 regardless of order
  (`500 + d1`).
- **Response.status** (fetch) is a `number` field: both Response builders
  `sitofp` the i64 curl status into it; the http-handler `{status:number}`
  return coerces back to i64 on the wire.
- **`crypto.getRandomValues`** fills a `number[]` (float64) array with doubles;
  the `http.listen { workers: N }` count coerces the `number` field to i64.

**Integer division / overflow traps** stay on the explicit integer types only —
`number / 0` is now `Infinity`/`NaN` (JS-correct, no throw).

## Side effects / caveats discovered

- **Large integer literals lose precision** — an `int64` literal past 2^53
  routes through `float64` and rounds (`-9223372036854775807` → i64 MIN).
  Inherent to literals being doubles; exact large integers need a different
  literal path (a Stage-N / open-question item).
- **`int32 / literal`** promotes to float (the literal is a `number`); integer
  division needs both operands integer-typed.

## Verification

- `make test-par` (full E2E, 20m): all pass except the pre-existing
  `TestE2ESignalBothRegisteredIndependently` flake, which fails identically on
  the clean pre-change tree (the server + SIGTERM handler work standalone) — not
  a number-model regression.
- New E2E: `TestE2ENumberIsDouble`, `…IntegerEscapeHatch`, `…LiteralForms`;
  ~11 existing tests updated for the now-correct semantics (integer division,
  `**` negative exponent, `number`-field coercion, bigint-number comparison,
  division-by-zero → Infinity, the generic-specialization mangling).
