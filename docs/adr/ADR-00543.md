# ADR-00543: `klain:sync` Stages 3–5 — select, channel range, P-handoff, complete preemption, tunable stacks

- **Relations**: `Implements TDD-00143`, `Extends ADR-00542`
- **Date**: 2026-09-01

## Context

With the scheduler, channels, and cooperative preemption in place
([ADR-00541](ADR-00541.md), [ADR-00542](ADR-00542.md)), the remaining
TDD-00143 stages are `select` + channel range + blocking-syscall P-handoff
(Stage 3), signal-based async preemption (Stage 4), and growable stacks
(Stage 5). This ADR delivers Stage 3 in full, and reaches a reasoned,
evidence-backed conclusion on Stages 4 and 5 — both of which the TDD itself
frames as gated or possibly-unnecessary.

## Investigation

- **select** needs Go's algorithm: poll all cases (random-fair), else park the
  *goroutine* on every case at once and let the first channel to fire claim it.
  Parking on multiple channels means holding several channel locks across the
  park and releasing them only after the switch-out (the same deferred-unlock
  invariant a single channel op already uses, generalised to a list).
- **async preemption** (Stage 4): Go needs it because Go historically
  instrumented only *function entry*, leaving a call-free loop uninstrumented.
  This compiler already instruments *loop back-edges* (ADR-00542) — so the gap
  is narrower here. The question was whether any preemptible region remains
  uninstrumented.
- **growable stacks** (Stage 5): copying a stack to grow it requires relocating
  every pointer into it — precise stack maps (`llvm.experimental.gc.statepoint`),
  the exact infrastructure TDD-00135's moving collector needs and does not have.

## Decision

**Stage 3 — select, range, P-handoff (all implemented):**

- **select** (`klainsync_select`): distinct channel locks taken in address
  order; a random-rotation poll runs the first ready case; with a `default`
  it never blocks; otherwise one `sudog` per case is enqueued behind a shared
  `ks_selgroup` whose `won` is claimed by CAS — the first channel to make its
  case ready wins, every other case's sudog goes stale and is discarded when a
  waker pops it (`ks_wq_pop_acquire`). The parked selector releases all channel
  locks via a multi-lock deferred park, and on wake pulls its remaining sudogs
  out of the other channels. Surface: `select(ch.recvCase(v => …),
  ch.sendCase(x, () => …), defaultCase(() => …))`; codegen builds the case
  array, calls the runtime, and dispatches to the chosen case's handler.
- **channel range**: `for (const v of ch) { … }` receives until the channel is
  closed and drained (`emitForOfChannel`).
- **P-handoff**: work-stealing already lets an idle M drain a blocked M's
  stranded goroutines; the unhandled case is *all* Ms blocked in syscalls at
  once. A bounded, sysmon-driven **rescue M** (P-less; drains the global queue
  and steals from the stuck Ps) is spawned when every P's M is stuck past a
  20 ms threshold with runnable work waiting and no idle M — the V1
  approximation of Go's `entersyscall`/`exitsyscall`, capped so it cannot run
  away.

**Stage 4 — reasoned ceiling (gap closed, not deferred):** the safepoint pass
is extended to **every** standard loop back-edge (`for`/`while`/`do-while`,
`for-of` over arrays and channels, `for-in`) in addition to function entry. So
tier-1 cooperative preemption now covers every preemptible region in compiled
TS. The only safepoint-free long-running case is a blocking C builtin — which a
signal cannot safely interrupt (it holds runtime locks/`malloc` state) and which
Stage 3's P-handoff already covers. Signal-based async preemption is therefore
unnecessary here; tier-1 is the complete, safe ceiling — exactly the outcome the
TDD's open question anticipated.

**Stage 5 — tunable stacks + documented gate:** goroutine stack size is
configurable via `KLAINSYNC_STACK_KB` (default 256 KiB, floor 8 KiB), so a
program with many shallow goroutines can pack far more of them. True
growable/moving stacks (an 8 KiB start that copies-and-grows) are gated on
precise stack maps — the same infrastructure TDD-00135 needs — and are not
implemented; this is an architectural dependency on a separate subsystem, not a
deferral of the goroutine feature itself (whose scheduler/channels/select/
preemption/P-handoff are all complete).

## Implementation notes

- `ks_sudog` gained a `group`/`caseidx`/`select_ok` triple; the plain
  send/receive paths must null-initialise them (an early bug left `select_ok`
  uninitialised, so a normal delivery wrote through a garbage pointer — a
  reminder that every sudog field a shared path reads must be set on both
  creation sites).
- The scheduler is now safe for a P-less M: `ks_ready`, `ks_p_steal`, and
  `ks_findrunnable` all handle `m->p == NULL` (readying and stealing route
  through the global queue).
- select's `ks_selgroup` carries its own mutex/cond for a main-thread select
  (the non-goroutine caller waits on the group, not a per-sudog cond).

## Side effects discovered

- The `gosched`-to-global-queue fix from ADR-00542 was load-bearing for the
  rescue path too: readied Gs from a P-less M go global, so any M can pick them.

## Verification

- Standalone C: select (default / ready-recv / blocked-wake / closed-recv),
  a `GOMAXPROCS=1` preemption spinner, and a `GOMAXPROCS=2` all-Ms-blocked
  rescue scenario all pass; the runtime stays clean under ThreadSanitizer with
  select + sysmon + rescue exercised; the base suite passes with
  `KLAINSYNC_STACK_KB=16`.
- E2E: `TestE2ESelectRecv/Default/Send/FanIn`, `TestE2EChannelRange`, and a
  `for-of`-array `TestE2EGoroutinePreemption`-style check pass; a non-`klain`
  program's IR still contains zero safepoint/runtime references.
- TDD-00143 is now fully implemented except the moving-stack optimisation, which
  is gated on TDD-00135's precise-stack-map work.
