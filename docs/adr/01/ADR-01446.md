# ADR-01446: Untyped streams hold any; builtin constructors type their callbacks

- **Relations**: Implements TDD-00230 (P2.2)
- **Date**: 2026-10-07

## Context

A shadow bucket (670 rows; `kml_blob.ts`, `stream.ts`) was the `controller`
of `new ReadableStream<T>({ pull(controller) { … } })`: codegen typed it
`ReadableStreamDefaultController<T>`, the oracle `any`.

Probing it found a miscompile: a stream without a type argument
(`new ReadableStream({ start(c) { c.enqueue("a") } })`) held `i64` chunks,
so a string chunk read back as its pointer's number. Node gives `"a"`.

## Investigation

- The parser gives `new ReadableStream`, `new Map` and similar builtins
  their own nodes. The checker types these nodes through the global's
  construct signatures (`newBuiltinType`). `contextualType`, however, knew
  only a `NewExpression`'s arguments, so a callback in one of these nodes
  had no contextual type.
- The declarations default every stream's chunk to `any`
  (`ReadableStream<R = any>`, `WritableStream<W = any>`,
  `TransformStream<I = any, O = any>`). Codegen defaulted all of them to
  `i64` in emission, inference and the `@lowerType` layouts.

## Decision

- `contextualType` types an argument of a builtin `new` node by the
  global's construct signature (`constructsParamContext`, shared with the
  `NewExpression` path). With explicit type arguments the signature is
  instantiated by them. With none, it is instantiated by its type
  parameters' defaults when every one has a default: nothing else infers
  them for a callback argument.
- An untyped stream's chunk, and an untyped transform's input and output,
  are `any` everywhere codegen picks a default.

## Verification

- `TestBuiltinNewContext` (expectations from tsc --strict) and
  `TestE2EStreamsUntypedChunksAreAny` (against Node).
- The probe's shadow rows are gone.
