# ADR-00571: JSON.parse projects into a declared-variable reassignment

- **Relations**: Extends ADR-00224
- **Date**: 2026-09-01

## Context

`JSON.parse(s)` (and `await res.json()`) need a target type to project the
parsed tree into typed native storage. That target was resolved only in a typed
var-declaration or an object-field initializer (`emitDeclJSONProjection`, called
from the var-decl and object-literal emitters). A bare reassignment
`xs = JSON.parse(s)` fell through to the generic assignment path with no
projection and was unsupported — even though the assignment target's type is
known from the binding's own declaration.

## Decision

Call `emitDeclJSONProjection` in the identifier-assignment paths of `emitAssign`,
using the bound symbol's declared type as the target:

- **Array-typed binding** (`let xs: T[] = …; xs = JSON.parse(s)`): project
  against `sym.Ty`, box the result into a fresh array header, and rebind the
  slot (the same object-reference rebind a normal array reassignment does).
- **Object-typed binding** (`let p: Pt = …; p = JSON.parse(s)`): project against
  `sym.Ty` and store the projected pointer.

Both reuse the exact projection the typed var-decl already runs, so the
deserialization semantics are identical; only the entry point is new.

A member or element target (`obj.items = JSON.parse(s)`, `grid[i] = …`) is still
not projected — those LHS forms don't carry a bound symbol to read the declared
type from — and remains the row's residual caveat (assign into a variable
first).

## Side effects discovered

None. The projection is attempted only for a `JSON.parse`/`Response.json` RHS
(`emitDeclJSONProjection` returns `ok=false` otherwise), so every other
assignment is unchanged.

## Verification

New `TestE2EJSONParseBareReassignment` (array and object bindings reassigned
from `JSON.parse`) plus the existing JSON parse/projection suite pass. Built and
verified on Mac (Apple Silicon).
