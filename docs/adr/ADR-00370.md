# ADR-00370: Native `test` builtin — `mustCall` family via a counting-closure trampoline

- **Relations**: `Implements TDD-00122`
- **Date**: 2026-08-25

## Context

Examples and E2E tests assert via `console.log` + expected output, which cannot verify that an
*asynchronous* callback actually fired. A handler that is silently never invoked passes today. TDD-00122
specifies a first-class `test` builtin — `import { mustCall } from 'test'` — whose `mustCall` wraps a
callback, counts invocations, and verifies the count at process exit, giving real async assertions (and, as a
side benefit, making the large class of external Node tests that depend on this helper runnable).

## Decision

A Go-codegen builtin module `test`, wired like `assert`:
- **Resolver** (`resolver/virtual_modules.go`): `"test" → "test__kml_builtin"` + a member allow-list.
  Named imports are rewritten to `test__kml_builtin.<member>` member-calls by the existing rename pass, so
  one dispatch site serves both import forms.
- **Call dispatch** (`emit_call.go`): `id.Name == "test__kml_builtin"` → `emitTestModuleCall`
  (`emit_testmod.go`).
- **Value probes** (`emit_exprs_member.go`): `isWindows`/`isLinux`/`isMacOS`/`hasCrypto`/`hasIntl`/
  `isMainThread` as constant `i1`s (host OS resolved at compile time via `runtime.GOOS`).
- **Type inference** (`emit_exprs_types.go`): `mustCall`/`mustCallAtLeast`/`mustSucceed` return the *same*
  function type as their callback argument (so `const cb = mustCall(fn)` is callable exactly like `fn`);
  `mustNotCall` returns `() => void`.

**The counting wrapper.** `mustCall(fn, exact?)` allocates an `i64` counter, builds an env `{origClosure,
counterPtr}`, and constructs a wrapper closure header `{trampoline, env}` (header construction cloned from
`emitNamedFuncValue`). The trampoline (`ensureMustCallTrampoline`, memoized per callback signature) is a
receive-all/forward-all forwarder like `ensureFuncValueTrampoline`, but it first loads the counter from its
env and increments it, then invokes the *original* closure via the standard slot-0/slot-1 indirect-call
sequence, returning its result. The expectation is registered with `@__kml_test_register(counterPtr, min,
max, msg)`.

**Exit-time verification** (`runtime_testmod.go`, `ensureTestRuntime`): a fixed-capacity registry of
`{counterPtr, min, max, msgPtr}` plus `@__kml_test_verify`, which walks the registry and, on the first
unmet/exceeded count, prints a diagnostic and `exit(1)`. `@__kml_test_verify` is invoked from the **existing**
program-exit sink (`__kml_run_exit_handlers`, `runtime_process.go`), after any user `process.on('exit')`
handler — so verification needs no user call and a failure forces a non-zero exit. `ensureTestRuntime` sets
`usedProcessLifecycle` so that sink is emitted.

`mustNotCall()` returns a `() => void` whose trampoline prints and `exit(1)`s the moment it is invoked (fail
fast). `skip(msg)` prints and `exit(0)`s (skipped ≠ failed). `expectsError(fn)` reuses `emitAssertThrows`.

## Implementation notes

- **V1 ABI bound:** the counting trampoline supports callbacks of 0–2 scalar/pointer parameters. A rest
  parameter, >2 parameters, or an array/nullable-scalar parameter is a clean compile error — never a silent
  miscompile — matching the trampoline's signature-parametric memoization key. This covers the overwhelming
  majority of real callbacks (`()`, `(err)`, `(err, result)`, `(value)`).
- **File naming gotcha:** the two new codegen files were first named `emit_test.go` / `runtime_test.go`; Go
  treats a `_test.go` suffix as a test file and excludes it from normal builds, so they are named
  `emit_testmod.go` / `runtime_testmod.go`.
- **Format-string constants** are emitted via `llvmCStrConst`, which computes the `[N x i8]` length and
  escaping from the actual bytes rather than hand-counting.
- `mustSucceed`'s "err is falsy" assertion and `expectWarning`'s warning capture are V1 simplifications
  (`mustSucceed` = `mustCall` count-only; `expectWarning` runs the thunk), staged in TDD-00122's open
  questions.

## Side effects discovered

`__kml_run_exit_handlers` was restructured to route both the has-handler and no-handler branches through a
`%post` block (under the existing single-run guard) so the verifier runs exactly once. Verified that a plain
`process.on('exit')` program (no `test` usage, empty `%post`) is unaffected.

## Verification

`go build ./...` + `go vet ./...` clean. New `tests/testmodule_test.go` (10 cases): satisfied `mustCall` →
exit 0; never-called / over-called → exit 1; explicit count; `mustCallAtLeast`; `mustNotCall`
invoked/not-invoked; `skip`; probes output; and `mustCall` driving a real `setTimeout` callback → exit 0.
`examples/testing/testing.ts` compiles and runs (exit 0). Process/exit/signal E2E suite green (the shared
exit-sink change is safe). Verified on macOS (arm64).
