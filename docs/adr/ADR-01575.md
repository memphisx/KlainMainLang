# ADR-01575: Return checks after the body; exhausted flow queries stay unanswered

- **Relations**: Extends ADR-01568, ADR-01574, Implements TDD-00230
- **Date**: 2026-10-11

## Context

Two checker defects surfaced in the final gates.

1. `TestE2EThenAbsentCallbacksPassThrough` failed with "type 'void' is not
   assignable to type 'number'". In an `async function m(): Promise<void>`,
   `await f().then()` was typed `void`. ADR-01574 had moved
   `checkReturnPaths`' reachability test (`endReachable`) ahead of resolving
   the annotation. `checkReturnPaths` itself ran before the body was checked.
   Reachability types the body's calls, to find calls that never return, so
   `f().then()` was typed outside its own context. The cache then kept that
   answer.
2. `controlFlowSelfReferentialLoop.ts` (an md5 loop of untyped bindings,
   each assigned from all the others) took more than 60 seconds in the js
   lane. The flow budget restarts for each top-level query. An exhausted
   query cached nothing, so every later query on the same node spent the
   whole budget again.

## Decision

- The function declaration, function expression and arrow function arms of
  `checkNode` run `checkReturnPaths`, and the getter check, after the body.
- A top-level `TypeOf` query that exhausts the flow budget records its node
  as unanswered.

## Verification

- `await f().then()` is `number` again.
- The suite case compiles in 5 seconds.
- `TestE2EExpandingInterfaceAndSelfReferentialLoopCompileJS` is a scaled-down
  version of the loop.
- Mac: checker and binder unit tests.
- Linux (Node304 and DeskMini kmlbox): full gates.
