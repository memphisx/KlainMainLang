# ADR-01265: `perf_hooks` and `performance` are a TypeScript module

- **Relations**: `Implements TDD-00230`, `Supersedes ADR-00673`
- **Date**: 2026-09-29

## Context

`performance.now/mark/measure` and `PerformanceObserver` were generated
by codegen: `measure()` returned a number, a mark name kept one
timestamp, observers ran synchronously inside `mark()`, and the rest of
`perf_hooks` (entries, histograms, `monitorEventLoopDelay`, `timerify`)
did not exist.

## Decision

`lib/node/perf_hooks.ts` ports Node v24's `lib/internal/perf/*`:
- user-timing entries (`PerformanceMark`, `PerformanceMeasure`) and the
  timeline getters;
- observers delivered on a later turn of the loop, entries sorted by
  start time;
- `createHistogram`, `monitorEventLoopDelay`, `timerify`.

The module is a global module whose `export const performance … //
kml:global` line makes `performance` a global too: `lib.GlobalModuleNames`
now also reads marked constants, and a global module named for a Node
module stays importable. `lib/node.d.ts` declares the globals.
`perfNow`/`perfTimeOrigin` (lib/native.d.ts) read the runtime clock.

A histogram keeps its samples exactly rather than in an HDR histogram, so
a percentile of large values can differ in its last digits.
`eventLoopUtilization` and `nodeTiming` are not ported.

## Verification

Mac (Apple Silicon): marks, measures, missing-mark `DOMException`,
observer delivery and order, histograms and the loop-delay monitor match
Node v24 on the probes and the rewritten perf tests.
