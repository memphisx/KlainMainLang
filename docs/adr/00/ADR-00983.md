# ADR-00983: configurable `highWaterMark` on `http.createServer`

- **Relations**: Extends ADR-00962, ADR-00977
- **Date**: 2026-09-16

## Context

`http.createServer`'s response backpressure threshold — the number of unsent,
queued bytes past which `res.write()` returns `false` and a later empty queue
fires `'drain'` (ADR-00962/TDD-00214) — was a fixed compile-time constant of
16384, baked into the shared `__kml_res_qwrite` runtime function as the literal
`HWM`. Node exposes it as the `createServer({ highWaterMark })` option; passing
it was a clean compile-time rejection (ADR-00977 explicitly left it as a genuine
behavior-changing option, not a no-op). This closes that gap — the first of the
remaining `createServer` "edges" in the backlog.

## Investigation

- The `16384` was one token substituted into the IR template via
  `strings.NewReplacer("HWM", "16384", …)` in `runtime_http_reswrite.go`; both
  read sites (`%over = icmp sgt … HWM`, `%ok = icmp sle … HWM`) live in
  `__kml_res_qwrite`, which is emitted **once** and shared by every response of
  every server.
- Because the function is shared, a per-server value cannot be a compile-time
  constant in it — it must be read from the response at runtime.
- `res` is a fixed native struct (`ServerResponseType`, `types.go`); adding a
  field is layout-safe (fields are addressed by name via `FieldIndex`, size is
  computed).

## Decision

Carry the threshold as a per-response field. `createServer({ highWaterMark: N })`
accepts any non-negative compile-time integer; the value threads into every
response the server mints, and the shared `__kml_res_qwrite` compares the queued
size against the loaded field instead of a baked constant. An omitted option (or
`0`) reads as Node's 16384 default.

`highWaterMark` is handled *before* the no-op-option allowlist
(`checkCreateServerNoopOption`), because — unlike `noDelay`/`requestTimeout`/etc.
— it genuinely changes behavior and so is not a "states the fixed behavior"
no-op.

## Implementation notes

- `types.go`: new `__kml_hwm` (i64) field on `ServerResponseType`.
- `emitter.go`: `curServerHWM int64` carries the current server's configured
  value (0 ⇒ default) from option parsing to the res-mint.
- `emit_http.go`: `emitHTTPCreateServer` resets `curServerHWM` per server and
  captures `{ highWaterMark }` via the new `createServerHighWaterMark` helper
  (positive-integer validation); `emitNewServerResponse` stores it (defaulting to
  16384). The rejection message now lists `highWaterMark:N` as accepted.
- `runtime_http_reswrite.go`: `__kml_res_qwrite` loads `res.__kml_hwm` once and
  compares against it; the `HWM` replacer token is gone, replaced by `HWMIDX`
  (the field index).

## Side effects discovered

None. The default path is byte-identical (the field is minted at 16384 when the
option is absent). The value is honored on both the plain-HTTP and HTTPS/1.1
`res.write` paths, since both route through the same `__kml_res_qwrite`.

## Verification

- `go build` + `go vet ./codegen/llvm/` clean.
- `tests/http_test.go`: `TestE2EHTTPCreateServerHighWaterMark` (a tiny non-default
  threshold of 256 still delivers the full 8 MiB body through the drain-gated
  producer — proving the value threads through without breaking the drain loop);
  `TestE2EHTTPCreateServerOptionRejections` updated (a non-integer
  `highWaterMark` is a clean rejection; the option is no longer in the
  unsupported set). Existing `TestE2EHTTPCreateServerResWriteDrain` (default
  threshold) still passes. macOS arm64 (M4).
- `examples/http/create_server_options.ts` updated with `highWaterMark: 8192`;
  compiles and runs.

## Still open (separate `createServer` edges, not this ADR)

Real non-zero `requestTimeout`/`headersTimeout`/`keepAliveTimeout` (reactor-level
per-connection deadlines, TDD-00217), custom `IncomingMessage`/`ServerResponse`
classes (needs the D1 dynamic object model), h2 async handlers, and
multi-server+cluster.
