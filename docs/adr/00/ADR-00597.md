# ADR-00597: Parser support for object shorthand-default in destructuring

- **Relations**: Completes [ADR-00595](ADR-00595.md)
- **Date**: 2026-09-01

## Context

ADR-00595 brought nested patterns and defaults to destructuring *assignment*, but
noted one remaining sub-item: the object-property `{ x = default }` shorthand
default. The codegen already handled it (`unwrapDestructDefault` on the
property's `Value`), but the object-literal parser rejected `{ x = default }`
with "expected }, got =" — the shorthand branch had no `=` case. (The keyed form
`{ k: x = default }` already parsed, since the colon branch runs `parseAssignment`
which produces the `x = default` `AssignmentExpression` directly.)

## Decision

In the object-literal parser's shorthand branch, accept a following `=` and parse
a default, representing `{ x = default }` as a property whose `Value` is
`x = default` (an `AssignmentExpression` — the exact shape the keyed form and the
declaration-form pattern already produce, and which the destructuring codegen
unwraps). This is a cover-grammar production: `{ x = 1 }` is only valid as a
destructuring target, so as an object *value* it degrades to the same semantics
as `{ x: x = 1 }` (accepting-more, never miscompiling a valid program — real JS
makes it a SyntaxError, which no real code relies on).

An object-property default fires when the field is `null` (the compiler's only
"absent" reference signal), so it requires a nullable-reference field — matching
the declaration form.

## Verification

`TestE2EObjectDestructuringAssignmentDefault` (shorthand `{ name = "fallback" }`
on a null field → default, on a real value → the value; keyed
`{ field: v = "keyed" }`). The declaration form, existing object-literal, and
destructuring suites all still pass. Built and verified on Mac (Apple Silicon).
