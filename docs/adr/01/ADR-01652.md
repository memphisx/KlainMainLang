# ADR-01652: An uninitialized static field is undefined

- **Relations**: Implements [TDD-00230](../../tdd/TDD-00230.md) (P3.3, values and representation); builds on [TDD-00187](../../tdd/TDD-00187.md)
- **Date**: 2026-10-16

## Context

`static n: number;` with no initializer read `0` (a string one `null`), and
`static #next: number` incremented from `0`; Node reads `undefined`, and
`undefined + 1` is `NaN`. tsc applies no initialization check to static
fields, so the strict lane accepts the program.

## Decision

An annotated static field with no initializer is stored as its type
widened with `undefined` (`undefinedableElem`), as an optional field is: a
zeroed slot is absent. Every static field access uses the storage type
(`storageIR`): the global, its record slot, reads, assignments, captured
initial values and logical assignment, whose `??=` now tests a nullable
scalar's presence bit.

An absent `number | undefined` converted to a `double` (`coerce`) is
`NaN`, ToNumber(undefined), instead of the payload's zero.

## Consequences

- `TestE2EClassStaticFieldUninitialized` matches Node for reads,
  arithmetic and `||=`/`??=`/`&&=`.
- A `number` holding `undefined` still loses it across a typed boundary (a
  `(): number` method returning the field prints `NaN`), a representation
  limit tracked in the backlog.
