# TDD-00225: An `import()` island with a top-level `await` — driving a second runtime from the importer's loop

- **Status**: Implemented
- **Notes**: Shipped as [ADR-01056](../adr/ADR-01056.md) (option 3). Open questions 1–3 stand.
- **Date**: 2026-09-22

## Context

TDD-00224 made a module with a top-level `await` a coroutine: the entry program in Stage 1 (ADR-01050), Worker
modules in Stage 2 (ADR-01055). Its §5 planned the same for a lazy dynamic-import island — "`init` spawns the module
task and returns its promise; the importer's `import()` promise adopts it" — on the assumption that the island runs
inside the importer's runtime. It does not. Under `-dynamic-import=lazy` (TDD-00056) each island is an independent
whole-program compile linked as a shared library: it has its own `main()`, event loop, microtask queue, task
scheduler and thread-local state, all `internal`. `import()` in the importer calls the C shim's
`__kml_dynimport_load`, which `dlopen`s the island and calls `__kml_dynmod_<hash>_init()` → the island's `main()`,
synchronously, and then reads the exports through `dlsym`ed accessors and wraps them in an already-resolved promise.

An island with a top-level `await` therefore waits on the *island's* main stack (`@__kml_top_await`), which turns
the island's own loop — nested inside the importer's synchronous `import()` call. Probe (Windows, 2026-09-22):

```
main: start            main: start
island: start          main: microtask
island: after await 42 island: start
main: got 42 done      main: timer 10
main: microtask        island: after await 42
main: timer 10         main: got 42 done
main: timer after      main: timer after
(this compiler)        (Node 24)
```

The importer's microtask and its 10 ms timer wait behind the island's 30 ms await. Node evaluates the island up to
its first await and returns to the importer's loop; both modules' timers interleave; `import()` resolves when the
island's evaluation promise does. The same import from inside a task or a loop callback is worse: the island's loop
then runs on a coroutine or connection-fiber stack.

This is the last place `emitAwait`'s main-stack tick branch and `@__kml_top_await` are reached from module code
(TDD-00224 §3).

## Design

### Options

1. **Share one runtime.** Link the island against the executable's runtime symbols instead of carrying its own copy
   (ELF: export them with `-rdynamic` and let the island's undefined references bind at `dlopen`; Mach-O: `-undefined
   dynamic_lookup`; Windows: an import library generated from the executable). Every runtime `define` in the island
   would have to become a `declare`, thread-locals included; the island and the importer would then share one loop,
   one scheduler, one microtask queue, and §5 of TDD-00224 applies verbatim. **Rejected for now:** a re-architecture
   of how islands are built, per-platform linking rules, and an ABI freeze between the executable and every island
   it may load (an island compiled by a later compiler version could no longer be loaded by an older executable, or
   the reverse). The perf and simplicity gain is real; it is recorded under Open questions as the long-term shape.
2. **Run the island's top level on its own thread**, like a Worker, and settle the `import()` promise across threads.
   **Rejected:** JavaScript module evaluation is single-threaded; an island's timers and callbacks would run
   concurrently with the importer's, and its exports are read across threads. Observable divergence.
3. **Drive the island's runtime from the importer's loop** — the island stays a separate runtime copy, evaluates its
   top level as a module task (TDD-00224's shape, no loop of its own), and exposes three small entry points the
   importer's loop calls each turn. **Chosen.** Faithful ordering at module granularity on one thread, no change to
   how islands are built or loaded.

### The island side

An island (`e.islandHash != ""`) with a top-level await:

- `main()` = prologue + spawn the module task + return. No loop, no unsettled check, no exit. The module trampoline
  is the ordinary `@__kml_task_trampoline` (with its catch-all): a top-level throw rejects the module promise, which
  rejects the importer's `import()` — Node's behaviour for a throwing imported module. (The entry program's
  trampoline has no catch-all because there a top-level throw is an uncaught exception.)
- The module promise is kept in the island's `@__kml_module_promise`.
- Exports, alongside `__kml_dynmod_<h>_init` and the accessors:
  - `__kml_dynmod_<h>_state() → i64`: 0 pending, 1 fulfilled, 2 rejected (the promise's state word). An island
    without a top-level await returns 1.
  - `__kml_dynmod_<h>_poll() → i64`: one **non-blocking** turn of the island's loop (`@__kml_loop_oneshot` +
    a new thread-local `@__kml_loop_nowait` that folds into the loop's `needimmediate`, so `select()` gets a zero
    timeout), then the state. Returns the loop's idle verdict in bit 8 (`0x100`): nothing in the island can wake it
    any more.
  - `__kml_dynmod_<h>_next_deadline_ns() → i64`: the island's earliest pending timer deadline on the shared
    monotonic clock, 0 for none — the same contract as `@__kml_cp_next_timeout_ns`.
  - `__kml_dynmod_<h>_error() → ptr`: the rejection value (an `errorObjType` pointer; both compiles share the
    layout, so `e.message`/`instanceof` work in the importer).
- An island whose top level has no await is unchanged: `init` runs it to completion synchronously.

### The importer side

`emitImportCall` (lazy mode) becomes: load + init (unchanged, `dlopen` is idempotent); `state()`; if settled, build
the result object from the accessors and settle a fresh **task promise** (`@__kml_task_alloc_promise`, so `await`
parks on it as on any promise) — fulfilled with the object, or rejected with `error()`; if pending, register a
watcher `{handle, promise, settleFn}` with the new `@__kml_dynimport_watch` and return the pending promise.
`settleFn` is a per-site function (the field list is static per call site) that reads the accessors into the
typed object and fulfils the promise; rejection is generic.

Three loop hooks, the `child_process` pattern (`runtime_http.go`'s keep-alive fold, dispatch pass and deadline
fold; no-op stubs when the program has no `import()`):

- `@__kml_dynimport_dispatch()`: for each pending watcher, `poll()`; fulfilled → `settleFn`; rejected → store the
  error, `@__kml_promise_settle(p, 2)`; either way drop the watcher.
- `@__kml_dynimport_keepalive() → i1`: any pending watcher whose last poll did not report idle. (An island that is
  idle with its promise pending can never settle; the importer's `await import()` then ends as an unsettled
  top-level await — exit 13 — exactly as Node.)
- `@__kml_dynimport_next_deadline_ns() → i64`: the minimum of the pending islands' `next_deadline_ns()`.

**What the importer's `select()` cannot see:** an island's sockets, pipes, child processes and worker pipes live in
the island's own fd sets. V1 folds only timers exactly; when a pending island reports "not idle" and no deadline,
the importer caps its wait at 10 ms (`@__kml_dynimport_next_deadline_ns` returns now + 10 ms) so a socket
completion inside the island is noticed within that. Correct, not free: a documented perf gap, with the fix being
option 1 or an fd-set export from the island.

### What is deleted

With islands and workers both coroutines, nothing in module code reaches `emitAwait`'s "not a task → microtask
tick" branch (`emit_async.go`) or the settled/turn paths of `@__kml_top_await` from a module body. TDD-00224 §3:
delete the branch; `@__kml_top_await` stays only if a non-module caller remains (the synchronous body accessors,
the combinator waits), decided at implementation.

## Open questions

1. Option 1 (one shared runtime) as the eventual shape — it removes the poll bridge, the fd blind spot and the
   duplicate runtime per island. Needs its own TDD when islands matter more than they do today.
2. A synchronous throw during an island's `init` (no await): today an uncaught exception in the island's `main()`
   exits the process; Node rejects the `import()` promise. Same fix shape (the island's `main()` under a catch that
   records the error and `state()` reports 2), not done here.
3. Node evaluates a dynamically imported module's *synchronous* part in a later microtask, not inside the `import()`
   call (its `import: start` lands after the importer's already-queued microtask). This design runs the island's
   synchronous prefix inside `import()`. A one-job deferral of `init` would close that gap; measure first whether
   anything observable beyond log order depends on it.
