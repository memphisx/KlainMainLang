# ADR-01953: The checker's answers and the program's analysis facts leave the Emitter

- **Relations**: Implements TDD-00230 (P3.5)
- **Date**: 2026-10-28

## Context

[ADR-01930](ADR-01930.md) moved the function builder, the function context, inference's memo, the program's declarations, its module units and the module output into their own objects. About 250 fields still sat on the Emitter itself, mixing four lifetimes: the checker over the program and what codegen kept from it, what the analysis pre-passes found in the program, what the module output already contained, and the modes of the emission in progress.

## Decision

- **`frontState`** (funcstate.go) holds the checker over the program, its binding, the answers kept from it (warmed types, synthesized and lowered nodes, the representation oracle) and the shadow comparison's recorder and memo.
- **`programFacts`** holds what the pre-passes record for the whole program: per-node marks and plans (sloppy and strict functions, void sites, constant regex literals, template sites, `-mm=auto`'s free and stack-allocation plans, class captures, the scans for property attributes, wrappers, holes and bigint operators, the evolving-container candidates, forced global types, module globals).
- **`moduleOut`** takes the counters behind generated names, the layout table, the function metadata and words, the constructor and hook lists, the C sources and link libraries, and the other tables describing what the output holds.
- **The emission modes move into `funcContext`.** The flags a caller sets around one nested emit (a species call on an array body, an Array override's default branch, a private-brand `instanceof`, a dynamic read or write helper's inline body, a dynamic constructor arm, a `for…in` key walk, a heap primitive and their kin) now live in the function's context. A function body started meanwhile, declared or detached, begins with none of them set, where before it inherited whatever its caller had set.
- The Emitter embeds each by pointer, so every read stays `e.field`. It keeps about 80 fields, mostly type-resolution state and the module-wide modes set once from the options.

## Consequences

- Behaviour is unchanged: every read still names the same storage through the embedded pointers. The E2E suite passes on Linux (x86-64).
- A field's struct now says how long it lives.
