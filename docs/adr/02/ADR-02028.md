# ADR-02028: A primitive intersected with an object type is held boxed

- **Date**: 2026-11-22

## Context

- `Object.assign(5, { k: 1 })` is typed `number & { k: number }`, a
  branded primitive in the checker. Codegen held it as the bare number, so
  the wrapper object Object.assign returns (`[Number: 5] { k: 1 }`) lost its
  properties.
- Problems found next to it:
  - The checker reported `k` missing on `number & { k: number }`. Its
    primitive-member check did not consult the brand's object members.
  - A wrapper made only by Object.assign printed without its own
    properties: the wrapper scan looked only for `Object(x)` and
    `new Number/String/Boolean`.

## Decision

- A branded type lowers to `any` (reprCtx), and the checker-primitive and
  checker-narrowing shortcuts leave a brand boxed. At run time the value is
  either the primitive itself (a cast brands it) or its wrapper object
  (Object.assign made it), and only a box holds both.
- An `Object.assign` call onto a primitive yields `any` at every site that
  types a call's result (`dynamicResultCall`, alongside a decorated
  method's).
- The checker finds a member through the brand's object type.
- The wrapper scan counts `Object.assign` onto a target that may be a
  primitive: by its checker type, or (JavaScript) anything but a literal
  object, array, function or `new`.

## Consequences

- A branded primitive costs a box. The opt-in to hold it bare when no
  wrapper reaches it is recorded as perf work.
- Tests: `TestE2EObjectAssignPrimitiveTargetTS`.
