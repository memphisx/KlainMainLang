# ADR-01697: TS2339 on Node's global interfaces and builtin statics

- **Relations**: `Implements TDD-00230`; `Extends ADR-01342`
- **Date**: 2026-10-18

## Context

ADR-01342 reports TS2339 for a member missing from a builtin interface, using TypeScript's library member list (`lib/tsmembers.txt`). Two gaps remained, and all of these compiled in the strict lane:

- `b.nope` on a `Buffer` and `process.nope`: `Buffer`, `NodeJS.Process` and the timer types are declared only by `@types/node`. Its files do not parse whole, so they were not in the list.
- `Map.nope`, `Promise.nope`, `Buffer.nope`: no builtin constructor's statics were checked at all.

tsc reports each one as TS2339.

## Investigation

- **The number index skip was too wide.** `Buffer` extends `Uint8Array`, so it has a number index signature. `libLacks` returned early for any type with a number index. In tsc a number index covers only numeric names.
- **The merged-declaration skip was too wide.** A builtin constructor's symbol has two declarations: `interface MapConstructor` (through `declare var Map`) and `interface Map`. `checkProperty` skipped every symbol with more than one declaration. That rule was there for an enum merged with a namespace, but it caught every builtin value.
- **Some of Node's declarations only re-wrap TypeScript's own.** For a global the library already declares, such as `Blob` or `AbortController`, Node's declaration extends a conditional alias (`interface Blob extends _Blob {}`). If those bases were taken, those names could no longer be checked.
- **Some of Node's declarations have index signatures.** `JsonWebKey` and `NodeJS.Dict` accept any name, so tsc reports nothing on them.

## Decision

1. `tools/libconform -members` also reads `@types/node` (`lib/conform/nodemembers.go`). It finds every interface and class declaration in the text:
   - members are its body's top-level member names, without statics;
   - bases are its `extends`/`implements` names, a qualified name by its last part;
   - every declaration of a name is merged, whatever module or namespace holds it, so a member any of them has counts.
2. A name TypeScript's library declares takes Node's members but not its bases.
3. A name is left out of the list when its members are not all known:
   - a declaration of it has an index signature;
   - or one of its bases is declared by neither library (an alias or an intersection), or is itself left out.
4. A namespace interface the builtin declarations declare (`NodeJS.Process`) gets a line under its dotted name. It carries the members and bases of `@types/node`'s declarations of its last name. That is the name the checker looks up.
5. `libLacks` skips a type with a number index only for a numeric member name.
6. `checkProperty` skips a merged declaration only when it merges an enum or has a namespace.

Found along the way: `Buffer.poolSize` read as `undefined`. It is now a writable `export let poolSize = 65536` in `lib/node/internal_buffer.ts`, Node's current default. The resolver pulls that file in when a program mentions `Buffer.poolSize`. Reads and assignments, compound ones included, are rewritten to the variable.

## Consequences

- A member missing from `Buffer`, `BufferConstructor`, `NodeJS.Process` and the timer types (`Timeout`, `Immediate`) is TS2339. So is a missing static on any builtin constructor.
- `NodeJS.ProcessEnv` is still not checked: it extends `Dict`, which has an index signature, so any name is valid there, as in tsc.

## Verification

macOS (Apple Silicon):
- Probes: `b.nope`, `Buffer.nope`, `process.nope`, `Map.nope`, `Promise.nope` and `t.nope` on a `Timeout` each report TS2339. A program using the `Buffer`, `process` and timer members Node declares compiles and runs.
- `Buffer.poolSize` read, assignment and compound assignment match Node.
- `go test ./checker ./lib/... ./binder` passes, as do the targeted E2E tests `TestUnknownBuiltinMemberIsTS2339` and `TestE2ENodeGlobalMembersCompile`.

Linux (DeskMini box): every example compiles through the checker with `-emit-llvm`, with no type error.
