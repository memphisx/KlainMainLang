# ADR-01346: ECDH, `diffieHellman` and the RSA cipher functions; overloads called with `any`

- **Relations**: Implements TDD-00230 (P3.2), Extends ADR-01345
- **Date**: 2026-10-03

## Context

Backlog 152, continued from ADR-01345. Web Crypto's ECDH and X25519
derivation, and its RSA-OAEP, are written in Node over `crypto`'s `ECDH`,
`diffieHellman` and `publicEncrypt`/`privateDecrypt`, none of which
existed here. `getCurves` was missing too.

## Investigation

- Node's `lib/internal/crypto/diffiehellman.js` keeps the ECDH key in a
  native handle. `generateKeys`, `computeSecret`, `getPublicKey(enc,
  format)`, `setPrivateKey` and `ECDH.convertKey` run over it.
  `diffieHellman()` derives with `EVP_PKEY_derive` over two KeyObjects.
  `cipher.js`'s `rsaFunctionFor` makes the four RSA functions from one
  binding, with OAEP as the default padding for the public-encrypt and
  private-decrypt pair and PKCS#1 for the other.
- Node was the oracle for each output length, error and code: the
  `ERR_CRYPTO_ECDH_*` errors, `ERR_CRYPTO_INVALID_KEYTYPE` as a RangeError,
  OpenSSL's `ERR_OSSL_RSA_*`, and Node's own "Invalid digest used".
- Writing ECDH found a codegen bug. Codegen erases overload signatures, so
  a call yields the implementation's value (ADR-00446). When the
  implementation returns `any`, `checkerPrimitive` converted that value to
  the overload's number, boolean or Buffer. With an `any` argument tsc
  picks the first overload that fits any value, so
  `this.getPublicKey(encoding, format)` inside `generateKeys` was taken for
  the `Buffer` overload while it held a string. The string was unboxed as
  a Buffer header, and the program crashed.

## Decision

1. **ECDH** (`ECDH`, `createECDH`, `ECDH.convertKey`) in
   `lib/node/crypto.ts`.
   - The private key and public point are `#private` fields.
   - One stateless native, `__kml_native_crypto_ecdh`, over `EC_GROUP`/
     `EC_POINT`, does each step: a private key in [1, order), its public
     point in any of the three formats, the shared secret (the x
     coordinate, field-size bytes), a point's re-encoding, and a private
     key's check.
   - An off-curve point, an out-of-range key and an unknown curve each map
     to Node's error.
2. **`diffieHellman({ privateKey, publicKey })`**: types that differ are
   `ERR_CRYPTO_INCOMPATIBLE_KEY`. The secret comes from
   `__kml_native_crypto_derive_secret` (`EVP_PKEY_derive`), and a string
   key is parsed as Node parses it.
3. **`publicEncrypt`, `privateDecrypt`, `privateEncrypt` and
   `publicDecrypt`** use one native, `__kml_native_crypto_pkey_crypt`:
   `EVP_PKEY_encrypt`/`decrypt`/`sign`/`verify_recover` with the padding,
   OAEP digest and label (a copy OpenSSL owns). The implementation takes
   `any` behind each declared signature, since codegen has no
   representation for `ArrayBufferView | string`.
4. **`getCurves`**: the built-in curves' short names (names native, kind
   3), sorted and deduplicated.
5. **AES key wrap** already ran through `createCipheriv('id-aes256-wrap')`.
   A failed `update`, an unwrap that does not verify, now throws Node's
   message: Node's `CipherBase::Update` pops the error queue before it
   throws, so the failure is always "Trying to add data in unsupported
   state".
6. **The overload fix:** `Checker.AnyArgOverloadCall` reports a call of an
   overloaded function with an `any` or `unknown` argument whose fitting
   overloads disagree on the result. `checkerPrimitive` leaves such a call
   `any`. An overload set that agrees on one result still converts.
7. **In passing:** the asynchooks and process C units passed
   `-DKML_NB_UNDEFINED=10` and `KML_NB_DOUBLE_OFFSET` without the `LL` the
   fetch and fnmeta units use. In one clang invocation that was a "macro
   redefined" warning on every program linking more than one of them. All
   spell them alike now.

The commoncrypto backend gets failing stubs, as in ADR-01345.

## Implementation notes

- **Library:** `lib/node/crypto.ts`, `lib/native.d.ts`, and
  `tools/libconform/allow.txt` (the new `KmlNative` members).
- **Natives:** `codegen/llvm/cryptosrc/crypto_openssl.c` and
  `crypto_commoncrypto.c`.
- **Overload fix:** `checker/checker.go` (`AnyArgOverloadCall`) and
  `codegen/llvm/emit_exprs_member.go` (`checkerPrimitive`).
- **Macro spellings:** `codegen/llvm/runtime_asynchooks.go` and
  `runtime_process.go`.

## Side effects discovered

Web Crypto port. Also
open: finite-field `createDiffieHellman`/`getDiffieHellman`, and `dh` key
pairs.
