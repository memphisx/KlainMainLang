# ADR-01228: child_process is Node's lib/child_process.js in TypeScript

- **Relations**: `Implements TDD-00234`, `Implements TDD-00230`
- **Date**: 2026-09-29

## Context

TDD-00234: the code-generated `child_process` had one literal listener per
event, non-stream stdio, compile-time options and bespoke errors.

## Decision

- `lib/node/child_process.ts` ports Node v24's `lib/child_process.js` and
  the parts of `lib/internal/child_process.js` the native surface serves:
  `normalizeSpawnArguments`, `ChildProcess extends EventEmitter`, `spawn`,
  `exec`, `execFile`, `spawnSync`, `execSync`, `execFileSync`, `fork`. Its
  exports carry @types/node's overloads (a `spawn` without `stdio` returns
  `ChildProcessWithoutNullStreams`).
- Native process handles (`klainpool.c`, `lib/native.d.ts`):
  `processSpawn` (fork/execvp with libuv's status pipe, socketpair stdio,
  `setsid`, `uid`/`gid`, `cwd`; `__kml_win_spawn` on Windows),
  `processStdio`, `processPid`, `processKill`, `processRef`,
  `processClose`, a blocking `spawnSync`, and the signal tables. The
  SIGCHLD self-pipe and the reaping ride the stream handles' reactor hooks.
- A spawn of this program's own binary marks the child
  (`KML_KLAIN_REEXEC`), whose startup guard exits 9 (ADR-00972). `fork`, a
  deliberate self-run, is not marked.
- `fork` re-executes this program with the json IPC channel on a
  socketpair (`NODE_CHANNEL_FD`), TDD-00141's wire. Forking another
  module throws `ERR_CHILD_PROCESS_FORK_MODULE`.
- `NodeJS.Signals` is declared (`lib/node.d.ts`).

## Implementation notes

`lib/node/child_process.ts` (new), `lib/native.d.ts`, `lib/node.d.ts`,
`codegen/llvm/threadpoolsrc/klainpool.c`.

## Side effects discovered

- The Buffer gaps in ADR-01227.
- The codegen gaps in BACKLOG 105–109. The module avoids them, and user
  code hitting them gets a clean compile error.
- The checker and codegen fixes in ADR-01229/ADR-01230, and the runtime
  ones in ADR-01231 (`process.cwd()` and the loop's active handles).
- Tests that relied on the old codegen caveats (`spawnSync` output as a
  string without an `encoding`) are made valid Node programs.
- The code-generated module is deleted: its dispatch and the
  spawn/exec/fork/spawnSync emitters (`emit_childprocess_sync.go`
  entirely). `emit_childprocess.go` keeps the process handle cluster's
  workers use and the IPC wire helpers of the child's side.
- The first test run became an exponential fork bomb: the self-spawn
  marker lived in the deleted spawn path. It is now part of the native
  spawn.

## Verification

Mac (Apple Silicon), against Node v24.19: the `tests/childprocess*_test.go`
suites (every one passes), `TestE2EChildProcessStreamsAndSignal`, the full
test suite (only the 4 known `-mm=gc` failures), and the example
`examples/child_process/streams.ts`.
