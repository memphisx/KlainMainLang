# ADR-00300: Chunked HTTP responses from a ReadableStream body

- **Relations**: Implements [TDD-00097](../tdd/TDD-00097.md) Stage 5 (response side); extends [ADR-00296](ADR-00296.md)–[ADR-00299](ADR-00299.md)
- **Date**: 2026-08-22

## Context

TDD-00097 Stage 5: an `http.listen` handler whose returned object's `body`
field is statically a `ReadableStream<string | Uint8Array>` now produces a
`Transfer-Encoding: chunked` response streamed chunk-at-a-time, instead of
the single fully-materialized write every response used before. The handler
returns immediately; a slow producer holds only its own connection open.

## Investigation

The path selection is entirely compile-time (the `body` field's static type),
so the dispatcher emits either the buffered tail (byte-for-byte unchanged) or
the streaming tail — no runtime branch, no change to any existing handler.

Three real bugs surfaced while wiring the reaction-driven writer into the
event loop, each fixed at its root:

1. **`select()` blocked over queued microtasks.** A connection fiber that
   starts a stream chain enqueues reactions *mid-iteration*; the loop then
   computed its select() timeout with no knowledge of them and blocked
   indefinitely. Fixed with `__kml_microtasks_pending()` folded into the
   timeout decision immediately before select() (checking at the top of the
   iteration was provably too early).
2. **Nested async closures inherited the handler's bare-slot model.** The
   `emittingHTTPHandler` flag (TDD-00084 Part A's legacy inline-slot async)
   applied to *every* closure emitted inside the handler expression — an
   async `pull` callback returned an 8-byte never-settled slot, silently
   dropping every reaction attached to it (traced with temporary runtime
   markers to a lost `pull_settled` wakeup). The flag is now pinned to the
   handler node itself (`httpHandlerNode`); nested async closures get real
   settled promises.
3. **Task-parked fetches never woke at headers.** The coroutine scheduler
   resumed a fetch-parked task on `done` only, and
   `__kml_await_fetch_headers` busy-spun in task context — a self-fetch
   (in-process client task consuming the process's own streaming endpoint)
   deadlocked, since the busy-spin starves the accept loop. The headers
   await now parks a task exactly like the full await, and both the
   scheduler's and the event loop's resume scans (ADR-00299 added the
   latter) wake on `headersDone`.

## Decision

- New `runtime_http_stream.go`: `__kml_http_send_stream_head` (status line +
  `Transfer-Encoding: chunked` + optional serialized headers) and the 40-byte
  `%kml.hws` writer context — read → on settle write `<hex>\r\n<data>\r\n`
  (length via the `{ptr,len}` word for byte chunks, strlen for strings;
  zero-length chunks are skipped, they'd terminate the encoding) → repeat;
  `done` writes the `0\r\n\r\n` terminator; a stream error closes the
  connection without one (nothing else is signallable mid-chunked). The
  writer owns the fd: it closes it and decrements the active-connection
  count (so `http.close()` still waits for in-flight streams), while the
  connection slot itself is freed immediately.
- `emit_http.go`'s dispatcher: on a stream-typed `body`, emit the streaming
  tail — send head, emit the per-site decode thunk (ADR-00298's), start the
  writer, return. Chunk types other than `Uint8Array`/`string` are a compile
  error.
- Fixed in passing: `inferUnannotatedReturnType` now sees the block's own
  top-level locals (a `return { body: localStream }` used to infer the
  bare-scalar default for the local); `__kml_fetch_pump` moved into
  `ensureFetchAsync` (the task runtime pulls fetch in without the
  headers-await, leaving the pump undefined).

## Side effects discovered

- Request-side streaming (`req.body` as a stream, lifting the 10 MiB buffer)
  remains TDD-00097 Stage 5b — not started.
- A streaming response ignores a `bodyBytes` field if both are present at
  the type level (the stream wins by construction).

## Verification

- `tests/streams_test.go` Stage 5 block: a Go `http.Get` against a compiled
  server asserts `Transfer-Encoding: chunked` and the reassembled body from
  an async timer-paced pull source; a `Uint8Array`-chunk body arrives
  byte-exact.
- `examples/streams/http_chunked.ts`: one binary streams its own chunked
  endpoint *and* consumes it in-process — a timer-scheduled async task whose
  `fetch` parks at headers, then reads the body incrementally through
  Stage 4's streaming `Response.body`.
- Full `go test ./...` green, all 153 examples pass, `go vet` clean (Mac).
