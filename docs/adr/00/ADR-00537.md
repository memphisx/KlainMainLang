# ADR-00537: string concat renders a `number | null` operand's null as "null"

- **Relations**: Extends ADR-00165
- **Date**: 2026-08-31

## Context

`"x" + n`, where `n` is `number | null` and null, printed `"x0"` instead of
real JS's `"xnull"`. A null *string* operand already stringified as `"null"`
(ADR-00165); only the nullable *scalar* case collapsed to its payload zero.
Documented as a caveat on the `+` (concatenation) row.

## Investigation

`emitBinary` (`emit_exprs_operators.go`) collapses a nullable-scalar aggregate
operand to its bare payload up front (a null reads as its zero — the correct
lenient behavior for arithmetic). By the time the string-concat branch calls
`emitValueToString`, the presence bit is gone. A nullable-scalar *local* is worse
still: `emitIdent` auto-unwraps it to the bare payload before `emitBinary` even
sees it.

Two operand shapes matter:
- A field/return value reaches `emitBinary` as the full `{ i1, T }` aggregate.
- A local identifier reaches it already unwrapped, but it is an lvalue whose
  aggregate can be reloaded from storage with no side effect.

## Decision

1. Skip the up-front payload collapse when the operator is `+` and one operand
   is a string (string concatenation), so a field/return aggregate survives to
   the concat branch and `emitValueToString`'s existing nullable-scalar case
   renders "null".
2. Add `emitConcatOperandString(origExpr, cur)`: for a nullable-scalar *local*
   identifier operand, reload the `{ i1, T }` aggregate from storage (via
   `emitNullableScalarBoxedValue`, side-effect-free for an lvalue) and stringify
   that; otherwise stringify the already-evaluated value. Route both concat
   operands through it.

Parameters, locals (from a literal or a parameter), and object fields now all
render "null".

## Implementation notes

`emit_exprs_operators.go` (the `strConcatToStr` collapse guard + routing both
operands through the helper) and `emit_nullable_scalar.go` (the helper). The
guard is scoped to `+`-with-a-string so arithmetic (`(n ?? 0) + 1`) still
collapses the payload as before.

## Side effects discovered

A `number | null` value returned *inline from a function call* (`"x" + get()`)
initially still printed its payload zero — the call return did not carry its
presence bit into downstream operations (`?? ` too). That root cause was traced
to the ternary `return b ? 3 : null` and fixed in the immediately-following
ADR-00538, so the concat row is now fully correct (no remaining `number | null`
caveat) once both land together.

## Verification

`TestE2EStringConcatNullableScalar` (new): parameter, local (null and value),
and field operands render "null"/the value, cross-checked against real Node.
Arithmetic on a nullable-scalar operand still collapses to its zero. The full
operators/strings/nullable suites pass. Verified on Mac (Apple Silicon).
