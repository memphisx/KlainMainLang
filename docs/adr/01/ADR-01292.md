# ADR-01292: Conversion and iteration of objects, functions and `any` iterables

- **Relations**: `Extends ADR-01232`, `Extends ADR-00279`, `Implements part of TDD-00230`
- **Date**: 2026-09-30

## Context

The os port (ADR-01291) sets a `Symbol.toPrimitive` on functions, and
probing that showed a cluster of gaps around ToPrimitive and the iteration
protocol:

- **Functions.** A function ignored its own `Symbol.toPrimitive`,
  `valueOf` and `toString`. A typed function in a template literal
  (`${f}`) did not compile, and `+f` was NaN.
- **Well-known symbol keys.** `o[Symbol.toPrimitive] = …` stored the key
  under a pointer name the ToPrimitive ladder never looked up.
- **Object literals.** A literal's `[Symbol.toPrimitive]()` keyed
  `@@toPrimitive` as a plain string, so it showed in `Object.keys`,
  `for…in` and inspect. `*[Symbol.iterator]()`, `async [k]()` and
  `[k]() {}` did not parse.
- **Classes.** The static ladder read object-literal fields only, so a
  class's `[Symbol.toPrimitive]()` and `valueOf()` were never called: `+q`
  was NaN and `q + ""` used `toString`.
- **`+` with a string.** `any`, object and function operands were
  converted with the string hint where JS uses the default hint.
- **Strict-lane string conversion.** An object without its own `toString`
  printed an inspect dump; JS gives `[object Object]`.
- **Iteration of non-arrays.** Spread, array destructuring and
  `Array.from` of a value held in `any` that is not an array (a generator,
  an object with `[Symbol.iterator]()`) threw "is not iterable". A static
  iterable did not compile.
- **Smaller gaps.** A nested array pattern over `any` elements was
  rejected. `Array.from` returned `[]` for a generator, filled an indexed
  array-like with `undefined`, and rejected an object with no `length`
  (JS gives `[]`). An anonymous generator expression was named
  `__kml_genexpr_N`.

## Decision

- **Runtime ToPrimitive** (`__kml_toprimitive`) runs its ladder over a
  function's own-property bag as it does over a dynamic object's. With no
  applicable method, the function passes through and converts as a
  function.
- **Typed functions box.** A function operand of string conversion, `+`
  and unary `+` is boxed and takes the dynamic path.
- **Well-known member keys.** The well-known symbols the parser names
  `@@x` (`iterator`, `asyncIterator`, `toPrimitive`, `dispose`,
  `asyncDispose`) are keyed `@@x` at run time too, so a set and a literal
  agree. `__kml_key_is_symbol` treats those keys as symbol keys:
  - hidden from `Object.keys`, `getOwnPropertyNames`, `for…in` and JSON;
  - shown as `Symbol(Symbol.x)` by inspect.

  A `[Symbol.x]` member's function name is `[Symbol.x]`.
- **Parser.** An object literal's `async` and `*` modifiers are read before
  a computed key, and a computed key takes the method forms. A literal
  whose iterator member is typed `any` (a generator method) iterates
  through the `any` lowering.
- **Class ladder.** `emitObjectToPrimitive` calls a class's
  `[Symbol.toPrimitive](hint)`, `valueOf` and `toString` in the hint's
  order. `+` with a string converts an object operand with the default
  hint first.
- **Strict lane.** String conversion of an object without its own
  `toString` is `[object Object]` in both lanes. The strict lane differs
  from JS in type checking only.
- **Iteration protocol for collections.** `__kml_any_iter_collect(v)` is
  `for (const x of v) r.push(x)`, compiled once through the `for…of`-over-
  `any` lowering. `emitAnyArrayElems`, the choke point of spread and
  destructuring over `any`, calls it for a non-array value with an
  `@@iterator` function. Otherwise it throws Node's `"<name> is not
  iterable"`.
  - A static object or class instance with a `[Symbol.iterator]` member
    is boxed and takes the same path.
  - Box elements spread into a concrete array are unboxed element by
    element.
- **Array.from** over `any`, a static iterable or a generator: an array's
  elements, else the protocol's values, else the array-like reading
  (`__kml_any_arraylike_collect`: `length`, then `v[0]`, `v[1]`, …).
  - A generator's result has its element type. Its values previously fell
    to the string branch and came back empty.
  - A static array-like with indexed properties is read the same way. A
    bare `{ length }` still fills with `undefined`.
  - A static object with no `length` gives `[]`.
- **Also fixed:**
  - A nested array pattern over an `any` element destructures what the
    element iterates to.
  - An anonymous generator expression takes its binding's name, else
    `(anonymous)`.

## Verification

On the Mac (Apple Silicon), outputs match Node v24.19.0:
- `tests/function_toprimitive_test.go`: functions, well-known symbol keys,
  computed methods, and the class ladder;
- `tests/iterable_spread_test.go`: spread, destructuring, `Array.from`,
  nested patterns, and the not-iterable messages;
- the updated `TestE2EInspectStringCoercionStrict`.

The same probes match Node 26.10 on Linux (Docker, glibc/arm64).
