# ADR-01298: `fs` as Node's lib/fs.js over one native request per operation

- **Relations**: `Implements part of TDD-00230` (P3.1), `Supersedes ADR-00495`, `Supersedes ADR-00795`
- **Date**: 2026-09-30

## Context

`fs` was the largest module TDD-00230 P3.1 still compiled directly:
- emit_fs.go: every `*Sync` function as its own IR lowering;
- emit_fs_async.go: the callback and promise forms, as the sync lowering
  run on a pool worker behind a setjmp thunk;
- emit_fs_constants.go: `fs.constants` as compile-time literals;
- runtime_fs.go: about 2,300 lines of hand-written IR, one helper per
  operation;
- runtime_fswatch.go's `FSWatcher` methods.

Only the streams, `open`/`read`/`write`/`close` and `FileHandle` were
already TypeScript (internal_fs.ts, a companion of the compiled module).

The compiled module carried caveats that came from its shape rather than
from the platform:
- Stats had no Date accessors;
- `mkdirSync` took only a literal `{ recursive: true }`;
- a utf8 read stopped at an embedded null byte;
- half the async operations ran on the loop thread;
- options had to be literals;
- `FSWatcher` took one arrow-literal listener per event name.

## Investigation

Node's lib/fs.js calls one `binding.*` function per operation. Each is a
single libuv `uv_fs_*` request: synchronous when there is no callback, on
the thread pool when there is. Everything else is JavaScript:
- argument validation;
- `getOptions`;
- `readFileSync`'s fstat-then-read loop and `writeFileSync`'s write loop;
- the recursive readdir queue;
- `realpathSync`'s lstat walk;
- rimraf.

A result is a number, a string, or values written into a typed array
(`statValues`).

## Decision

**Natives** (`threadpoolsrc/klainfs.c`, in the pool's translation unit,
compiled in only under `-DKLAINPOOL_FS`) are one work function over every
libuv request Node's fs uses. Two entry points share it:
- `fsCall(op, path, dest, a, b, c, d, bytes)` runs it on the calling
  thread and returns the result or the negated errno.
- `fsCallAsync(…, callback)` runs it on a pool worker and calls back
  `(errno, result)` on the loop thread.

A string result (readlink, realpath, mkdtemp, a recursive mkdir's first
directory, a directory listing) is `lastString()`. A listing is its
entries as `<type digit><name>`, joined by `/` (no name contains one),
sorted by strcmp as libuv's scandir sorts them. A stat fills 18 doubles
in Node's order (dev … blocks, then sec/nsec of each time). On Linux it
comes from `statx`, for the birth time, as libuv does. Windows runs the
same C against win32fs.c's POSIX surface. `fsError` gained `dest` for
two-path messages (`rename 'a' -> 'b'`).

**TypeScript**:
- `internal_fs_utils.ts` (lib/internal/fs/utils.js): validators,
  `getOptions`, `Stats` (Node's fields, prototype Date getters and kind
  predicates), `StatFs`, `Dirent`, `constants` (Node's per-platform table
  through the `process.platform` fold), and the binding wrappers.
- `internal_fs.ts` (lib/fs.js): every sync and callback function Node
  has, except `cp`, `opendir`/`Dir`, `openAsBlob`, `glob`,
  `watchFile`/`unwatchFile` and `lchmod`. It also holds `FSWatcher`/
  `watch` (lib/internal/fs/watchers.js, an EventEmitter over
  `fsWatch`/`fsWatchClose`, a shim over runtime_fswatch.go's
  inotify/kqueue/ReadDirectoryChangesW backends), the streams and
  `FileHandle`.
- `internal_fs_promises.ts`: fs/promises, each function its callback
  form's request settling a promise.
- `fs.ts` and `fs_promises.ts`: the modules, with `fs.promises` an object
  of fs/promises' functions, as dns.promises is.

**Deleted**:
- emit_fs.go, emit_fs_async.go and emit_fs_constants.go;
- all of runtime_fs.go except the errno tables and `__kml_fs_error_new`;
- the pool's one-shot promise ops (`__kml_pool_submit*`, the IR thunks,
  `KML_OP_*`, `__kml_pool_settle`);
- the Stats/Dirent/FSWatcher codegen types and their flags;
- the `fs`/`fs/promises` virtual markers and member lists, and
  `declare module "fs"`/`"fs/promises"`.

## Implementation notes

- A non-`Uint8Array` view is copied out through `typedBytes`, as zlib's
  are.
- `realpathSync` is Node's lstat walk: an error names the component, with
  syscall `lstat`. `realpathSync.native`/`realpath.native` are
  `realpath(3)`.
- `rmSync` removes a tree as std::filesystem::remove_all does: contents,
  then the directory, errors with syscall `rm`. `rm` is rimraf's callback
  form.
- A watched file's own event reports its base name (libuv's).
- `persistent: false`, `recursive` on `watch`, and `bigint` stats are not
  implemented: the options are validated and ignored.

## Side effects discovered

Fixed in ADR-01299:
- `type = x` / `interface = x` parsed as declarations;
- an array literal holding an `any` element and another kind;
- an Error held in `any` rejected through a promise;
- a primitive assignable to an anonymous object type;
- `s.toString()` on a narrowed string inferred as a number.

## Verification

- `tests/fs_port_test.go`: sync errors, the sync surface, callbacks and
  promises, and `watch`. Every program also runs under Node and must print
  the same.
- The existing fs, fs-async, FileHandle, stream and errno-fidelity suites
  pass.
- **Mac (Apple Silicon):** Node v24.19.0.
- **Linux (Docker, glibc/arm64):** the pool unit compiles with
  `-DKLAINPOOL_FS` (clang `-fsyntax-only -Wall`), `statx` included.
- **Windows:** the pool unit with `-DKLAINPOOL_FS` passes
  x86_64-w64-mingw32-gcc `-fsyntax-only`; not run.
