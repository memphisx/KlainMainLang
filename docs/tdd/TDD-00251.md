# TDD-00251: The runtime resolves on its own: dependencies and registered hooks

- **Status**: Implemented
- **Date**: 2026-10-12

## Context

[ADR-01476](../adr/01/ADR-01476.md) compiles each runtime C file once into a
cached object and links the same object into every program, relying on
section garbage collection to drop what a program does not reach,
together with that code's references. That holds for ELF and Mach-O
linkers, which never resolve a symbol referenced only from a discarded
section. It does not hold for COFF: GNU ld and lld both resolve every
symbol of every loaded object before collecting sections, and mingw's
default script keeps every `.pdata`/`.xdata` section, so no function with
unwind data is dropped anyway. A runtime object that names something the
program does not define fails the link on Windows.

A full Windows run of the E2E suite on 2026-10-12 failed most tests this
way. The first half of the suite (1,490 failures) reported these
undefined symbols, by referencing object and function:

| Symbol | Defined in | Referenced from |
|---|---|---|
| `__kml_heap_total_bytes`, `__kml_heap_used_bytes` | per-program C, memory-mode specific (`emit_process.go`) | `process.c` `__kml_native_process_memory` (1,226 links) |
| `__kml_dynarr_len`, `__kml_dynarr_at` | `dynarr.c` | `shape.c` `__kml_own_symbols_checked` (325) |
| `__kml_fs_statfs` | `osinfo.c` | `threadpool.c` `work_fs` (240) |
| `__kml_curl_multi` | IR thread-local (`runtime_fetch.go`) | `fetch.c` (16) |
| `__kml_main_ctx`, `__kml_conn_data`, `__kml_current_conn_idx` | IR thread-locals (`runtime_http.go`) | `fetch.c` await paths |
| `__kml_signal_reason`, `_aborted`, `_timeout` | IR functions (`emit_signal.go`) | `fetch.c` |
| `__kml_wait_outside_coroutine` | `loop.c` | `fetch.c` |
| `__kml_monotonic_ns` | `timers.c` | `fetch.c` |
| `__kml_typed_int_view` | `dynjson.c` | `cryptorand.c` |
| `__argv_ptr`, `__process_argv_ptr`/`_len`, `__kml_ctorname.*`, `.s.*` literals | IR globals | one link each |

They are of two kinds:

- **A. Runtime to runtime.** One runtime file calls another that this
  program did not link.
- **B. Runtime to program.** A runtime file names something the compiler
  generates per program, only when the program needs it: thread-local
  globals, IR functions, memory-mode-specific C, argv globals.

[ADR-01327](../adr/01/ADR-01327.md) already found weak symbols unreliable on
COFF and recorded for [TDD-00240](TDD-00240.md) that a C routine calling
back into generated code should take a registered function pointer. The C
weak stubs added since (`fetch.c` `__kml_current_task`,
`__kml_task_gc_restore`, `__kml_fetch_bodyprom_on_done`; `fetch_stream.c`
`__kml_rs_*`; `process.c` `__kml_thread_exit`; `fnmeta.c`
`__kml_dynobj_inspect_at`; `klainpool.c`
`__kml_cluster_announce_listening_at`) are COFF weak externals too.
[TDD-00230](TDD-00230.md) has the runtime compiled once into static
libraries; a static library is only sound if its objects resolve without
naming the program.

## Design

**Invariant.** Every symbol a runtime object leaves undefined is defined
by a runtime object it depends on, by a system library it links, or by the
small fixed set of symbols every program emits (its `main`, the registered
hook table below). Nothing in a runtime object names a symbol that only
some programs generate.

### A. Runtime dependencies are declared

`CSource` gains `Deps []string`: the runtime files this one calls.
`EmbeddedCSources` closes the selected set over `Deps`, so linking
`shape` links `dynarr`, the pool links `osinfo`, `fetch` links `loop` and
`timers`, `cryptorand` links `dynjson`. A dependency costs its object in
the link; on ELF and Mach-O the unreached part is still collected.

Option rejected: an archive of every runtime object, letting the linker
pull members on demand. It compiles the whole runtime for every flag set,
and a member pulled for a dead reference still brings its own category B
references. It is TDD-00230's end state and needs this invariant first.

### B. The program registers what it provides

1. **Data the runtime reads is the runtime's.** A thread-local or global
   that C reads is defined in the C file that owns it, and the IR declares
   it `external`: `__kml_curl_multi` in `fetch.c`; `__kml_main_ctx`,
   `__kml_conn_data`, `__kml_current_conn_idx` in `loop.c` (the context
   size comes from `kml_layout.h`); the argv globals in `process.c`.
2. **Generated code the runtime calls is a hook.** A core runtime file
   (`unitreg.c`, always linked, [ADR-01325](../adr/01/ADR-01325.md)) defines
   `struct kml_hooks __kml_hooks`, one function pointer per callback, each
   initialised to a C default that does what the program without that
   feature would observe (no signal is aborted, heap counters read 0
   before registration, `__kml_thread_exit` is `exit`). A program that
   emits the callback stores its address in the table from its
   `@llvm.global_ctors` constructor, as units already register their rows.
   C calls `__kml_hooks.signal_reason(sig)`.
3. **The C weak stubs become hooks** in the same table, with their stub
   bodies as the defaults.
4. **Memory-mode C** (`__kml_heap_*`) registers its two functions as
   hooks from its own constructor.

### Guard

A codegen test compiles every embedded runtime file with the host clang,
lists each object's undefined symbols (`llvm-nm -u`), and fails when one
is not defined by the file's `Deps` closure, by the core set, or by an
allow-list of system symbols. It runs on every platform, so a reference a
change adds on macOS or Linux fails there, not first on Windows.

### Alternatives considered

- **Keep weak symbols, add COFF workarounds** (`-Wl,--allow-multiple-definition`,
  linker scripts dropping `.pdata` keeps, `-force:unresolved`). Each masks
  the dependency instead of removing it, and unresolved references would
  crash at run time instead of failing the link.
- **Compile the runtime with the program again on Windows.** Undoes
  ADR-01476 and its build-time savings on the slowest host.

## Stages

1. Guard test, with the current violations as a shrinking allow-list.
2. Category A: `Deps`.
3. Category B data ownership.
4. Hook table; IR callbacks, memory-mode C and the C weak stubs move to it.
5. Allow-list empty; Windows E2E suite links.
