# ADR-00806: HTTPS/1.1 multi-instance — TDD-00191 Stage 3

- **Relations**: `Implements TDD-00191`, `Extends ADR-00803`, `Extends ADR-00805`, `Extends ADR-00802`

- **Date**: 2026-09-09

## Context

The last open piece of TDD-00191 Stage 3: an *additional* server could only be
plain HTTP/1.1. Combining an additional server with HTTPS was a clean rejection,
because the reactor's TLS accept branch (`h2tlsBranch`, `runtime_http.go`) was
primary-only — it read the single `@__kml_http_tls_ctx` global and wrapped the
primary listener's accepts. The extra-listener accept path
(`__kml_http_xl_accept`) did a plain `accept()` + `append_conn` with no TLS. This
ADR lets any server be an HTTPS/1.1 server: a plain app port plus an HTTPS admin
port, an HTTPS public server plus a plain internal one, or two HTTPS servers.

## Investigation

The connection I/O shims already self-dispatch per fd: `__kml_http_conn_recv` /
`_send` / `_close` look the fd up in the fd→SSL table (`__kml_http_conn_ssl_get`)
and use TLS when present, raw otherwise. So mixing plain and TLS connections on
one event loop already works at the I/O layer — the dispatcher is TLS-aware
whenever `usedHTTPS1Server` is set. The only gap was the *accept* side: an extra
listener never performed the `SSL_accept` handshake nor registered its fd→SSL
entry.

Two ordering hazards surfaced:

1. `xl_accept` is emitted by `ensureHTTPRuntime`, which runs on the *first*
   server. If a plain primary triggers it before an additional
   `https.createServer` sets `usedHTTPS1Server`, the accept path would be emitted
   without its TLS branch — and referencing `__kml_tls_server_accept` /
   `__kml_http_conn_ssl_set` when no HTTPS server exists would drag libssl into
   every plain HTTP program. Fixed with a whole-program pre-scan
   (`programUsesHTTPS1Server`) that sets `usedHTTPS1Server` before Pass 2, so the
   flag is correct regardless of createServer order.
2. `@__kml_http_tls_ctx` is a single global. If every HTTPS server stored into
   it, a plain primary next to an HTTPS additional would wrongly TLS-wrap the
   primary's connections (its accept branch guards on the global being non-null).
   So the global must hold the *primary's* ctx only.

## Decision

- **Pre-scan.** `programUsesHTTPS1Server(prog)` (a `programContainsCall` over a
  refactored predicate-parameterized walker shared with the upgrade pre-scan);
  `EmitProgram` calls `ensureHTTPS1Server()` early when it hits. `ensureHTTPS1Server`
  now dedups on a separate `httpS1Wired` flag so setting `usedHTTPS1Server` early
  doesn't skip its one-time wiring.
- **Per-listener TLS ctx.** The extra-listener table entry grows to
  `{ i64 fd, ptr dispatch, ptr tlsctx }` (24 B). The `Server` handle grows to
  40 B: slot 4 = its SSL_CTX* (null for plain). `https.createServer` hands its
  ctx to the handle builder (`pendingServerTLSCtx`), which stores it in slot 4
  and — for the primary only — into `@__kml_http_tls_ctx`. `server.listen` reads
  slot 4 and passes it to `register_extra_listener`.
- **TLS accept in `xl_accept`.** When `usedHTTPS1Server`, a ready listener with a
  non-null ctx does `__kml_tls_server_accept` on the still-blocking fd,
  registers the SSL via `__kml_http_conn_ssl_set`, then sets the fd non-blocking
  and `append_conn`s it — mirroring the primary HTTPS branch. A null ctx (plain
  listener) skips straight to the non-blocking + append path. The TLS blocks are
  emitted only under `usedHTTPS1Server`, so a plain-only program links no libssl.
- **Boundary.** The broad "additional server + HTTPS" rejection is removed. An
  additional `http2.createSecureServer` (HTTP/2 over TLS) stays rejected at its
  own emit site (`httpServerCount > 0`) — per-listener h2 is Stage 4.

## Implementation notes

- `emit_http_upgrade.go`: the upgrade walker is now `programContainsCall` +
  `walk*ForCall(pred, …)`; `programUsesHTTPUpgrade`/`programUsesHTTPS1Server` are
  thin predicate wrappers.
- `runtime_http.go`: the whole extra-listener table section uses the 3-field
  entry; `xl_accept`'s TLS branch is a Go-conditional string.
- The additional HTTPS server is HTTP/1.1 (h1-only ALPN ctx, as
  `https.createServer` already builds); no h2c/h2 on an extra listener.

## Side effects discovered

The `Server` handle grew 32→40 B and the extra-listener entry 16→24 B; the
`calloc`/`realloc` sizes were bumped in lockstep (a missed bump would corrupt the
handle/table — the same class of bug ADR-00803 hit with the `%kml.hws` context).
