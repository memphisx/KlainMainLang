## Context

An index signature — `interface Dict { [key: string]: number }`, `type M = {
[k: string]: T }` — is a parse error today (`expected IDENT, got [`). It's the
idiomatic shape for dictionaries/records and blocks a large class of interfaces;
`Record<string, V>` is the current partial stand-in.

The apparent blocker is that objects are fixed-shape structs (no arbitrary
runtime keys). But the runtime this feature needs **already exists**: TDD-00012's
computed-key object literals introduced `IsDynamicObject` — a `Map<string,V>`-
backed object with `d[key]` read/write sugar (`emitDynamicObjectGet`/`…Assign`,
`emit_objects.go`) and literal construction (`emitDynamicObjectLiteral`). Index
signatures are essentially the **type-annotation grammar** for that existing
representation. This is not TDD-00068's dynamic/prototype object model.

## Design

### Representation (the decision this TDD records)

An index-signature type resolves to the existing `Type{IsMap:true,
IsDynamicObject:true, MapKey:&TypePtr, MapVal:V}`. Consequences, all reusing
shipped machinery unchanged:

- `d[key]` read → `emitDynamicObjectGet` (map get); `d[key] = v` →
  `emitDynamicObjectAssign` (map set); an object literal `{a:1,b:2}` assigned to
  an index-signature target → `emitDynamicObjectLiteral` (build a map from
  entries). `Object.keys/values/entries` and `for…of` already handle `IsMap`.

### V1 scope cuts

- **String index only** (`[k: string]: T`). A number index (`[i: number]: T`) is
  a clean rejection for V1 (numeric-keyed maps aren't the dynamic-object shape).
- **No mixed named + index** (`{ id: number; [k: string]: string }`): the
  fixed-struct and map representations are disjoint (TDD-00012 rejected hybrids).
  A clean rejection in V1.
- Value type `V` is the single index-signature value type; a homogeneous map,
  matching `IsDynamicObject`'s single `MapVal`.

### Change set (bounded, all in the files the feasibility scan named)

1. **Parser** (`parser/parser_types.go`): in the interface field loop
   (`parseInterfaceDecl`, ~:512) and the inline object-type loop (~:323), add an
   `LBRACKET` branch for `[ IDENT : type ] : type`. Disambiguate from the mapped
   type `[K in …]` (already detected at ~:281) by the token after the key
   identifier: `:` = index signature, `in` = mapped. Reject a number key and a
   mixed named+index shape cleanly.
2. **AST**: an `IndexSig *TypeAnnotation` (the value type `V`) on `TypeAnnotation`
   / the object-type carrier.
3. **resolveType** (`emitter.go`, the inline-`Fields` path ~:1066 and the
   interface path): when the annotation carries an index signature and no named
   fields, return the `IsDynamicObject` map type.
4. **Record parity** (`emit_utility_types.go`, ~:98): flag the
   `Record<string,V>` result `IsDynamicObject` so it gains the same bracket
   sugar — closes the JSDoc `Object.<K,V>` ❌ as a near-free win.
5. **JSON.stringify** (`emit_call_json.go`): add an `IsMap`/`IsDynamicObject`
   branch (iterate keys/values via the map runtime) so an index-signature dict
   serializes — the one genuinely new piece of codegen, and the main thing that
   makes the feature *useful*.
6. E2E test + example; status/JSDOC/README doc updates; ADR.

## Open questions

- Number index signatures (`[i: number]: T`) and mixed named+index — deferred to
  a later stage; V1 rejects both cleanly.
- Whether a later stage unifies mixed named+index by interning named fields as
  map keys (needs a heterogeneous value model) or a two-part representation.
