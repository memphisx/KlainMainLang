# ADR-01606: fork() passes execArgv; the child_process residue checked

- **Relations**: Extends ADR-01080
- **Date**: 2026-10-13

## Context

BACKLOG §2 listed `fork()` options (`cwd`, `env`, `silent`, `stdio`,
`timeout`, `execArgv`), numeric-descriptor `stdio` entries and the exec
callback error's `code`/`cmd` as unfinished.

## Investigation

Each compared with Node 24 on Windows, same program:

- `exec('cmd /c exit 3')`, `execFile`, a missing command: `code`, `cmd`,
  `killed`, `signal` identical.
- `fork` with `cwd`, `env`, `silent` and a `stdio` array with `'ipc'`: the
  child's cwd, environment, piped stdout and messages identical.
- `spawn` with `stdio: ['ignore', fd, 'inherit']`: identical.
- `fork({ execArgv })`: Node's child sees them as `process.execArgv`; here
  it saw `[]`. `fork`'s normalized spawn dropped the option and
  `process.execArgv` was always `[]`.

(A run under MSYS's `timeout` showed a child with seven environment
variables: that wrapper starts the program with a reduced environment; not
the runtime.)

## Decision

`fork` takes `options.execArgv`, else the parent's `process.execArgv`, as
Node does, and passes it in `KML_EXEC_ARGV` next to `NODE_CHANNEL_FD`. The
child's `process.execArgv` reads it on first use and removes it from the
environment. A compiled program has no Node options to apply, so the flags
change nothing else.

## Verification

Windows 11: `TestE2EChildProcessForkExecArgv`, the fork and cluster tests.
Linux: owed (shared `child_process.ts`).
