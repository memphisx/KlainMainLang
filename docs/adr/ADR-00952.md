# ADR-00952: A void-returning method bound to an untyped variable is `undefined`

- **Relations**: `Extends ADR-00882` (DataView A1 sweep; its noted remaining case)
- **Date**: 2026-09-15

## Context

Binding the result of a void-returning method call to an untyped variable
emitted invalid IR:

```ts
const dv = new DataView(new ArrayBuffer(8));
const r = dv.setInt8(0, 5);   // clang: alloca void / store void 0
```

In JS a `DataView` setter returns `undefined`, so `r` should be `undefined`.
This was the whole Test262 `built-ins/DataView/prototype/set*/
set-values-return-undefined.js` family (8 files) — flagged as the last DataView
CLANG_ERROR in ADR-00882.

## Investigation

`emitVarDeclBody` already has a void-initializer handler
(emit_exprs_vardecl.go:1244): if the emitted initializer's `Ty.IR == "void"`
and the binding is untyped, it discards the pre-inference slot and rebinds the
variable as `undefined`. But it never fired here, because the pre-inference type
switch runs first: the member-call `default` case (emit_exprs_vardecl.go:1019)
adopts `inferExprType(init)` whenever it differs from the i64 default — and for
a void method that inferred type is `TypeVoid`. `emitVarSlotDefault` then emitted
`%t = alloca void` + `store void 0` for the slot (invalid IR on its own, even
though the void handler later leaves it dead).

## Decision

Exclude `void` when the member-call `default` case adopts the inferred type
(`inferred.IR != "void" && (…)`). `ty` stays at its harmless i64 default, the
pre-inference slot is a dead `store i64 0`, the initializer emits its `void`
Value, and the existing void-initializer handler fires — rebinding the variable
as `undefined`. This is the faithful JS semantics (the call runs for its side
effect, the binding is `undefined`); an *annotated* binding still gets the clean
"cannot assign the result of a void expression" rejection the handler already
enforces.

The fix is general — any void-returning method bound to an untyped `var`/`const`
benefits — not DataView-specific.

## Implementation notes

One condition tightened in `emitVarDeclBody`'s member-call inference
(emit_exprs_vardecl.go). No new AST nodes or type machinery.

## Side effects discovered

None. The `built-ins/DataView` Test262 category drops to 0 CLANG_ERROR.
