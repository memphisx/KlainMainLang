# ADR-01809: rest parameters can be destructuring patterns

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- `function f(...[a, b]) {}` and `(...{ length }) => length` are valid JavaScript and TypeScript. The parser rejected both with an own "unsupported" diagnostic (90001).

## Decision

- Both parameter-list parsers accept a pattern after `...`. The parameter is a hidden name with `Rest` set and the pattern attached. As for a plain rest, no initializer is taken and the parameter ends the list.
- An array rest pattern unpacks from the collected array through the existing array-pattern path.
- An object rest pattern needs a step of its own. `bindArrayParamPattern` binds the collected array, then destructures the pattern from it. Top-level functions, closures, function expressions and class methods call it.
- Generators desugar a rest pattern like any other parameter pattern. The hidden rest parameter is typed `any[]`, and the pattern runs at the call.
- The 90001 diagnostic is deleted.

## Consequences

- `TestE2EJSFileRestParameterPattern` covers, in the js lane: function expressions with holes, arrows with an object pattern, methods and statics, async functions, nested patterns, defaults with an inner rest, and generators. It also covers a typed strict-lane function and arrow.
- `examples/basics/destructuring.ts` shows both forms.
