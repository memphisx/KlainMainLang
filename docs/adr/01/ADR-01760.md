# ADR-01760: A sloppy function's primitive `this` is its wrapper object

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- In sloppy code, a function called with a primitive receiver (`f.call(5)`, `[1].map(fn, 7)`) sees `this` as the wrapper object: `typeof this` is `"object"`. `emitSloppyThis` replaced only an undefined or null receiver (with globalThis), so `typeof this` printed `"number"`. It also returned without doing anything when globalThis was not linked into the program.
- A wrapper held in `any` (`Object(5)`, `[Object("xyz")][0]`) read its members through its host layout's adapters, which typed the receiver as the wrapper handle. So `this.toFixed(1)` threw "the method 'toFixed' can't be called through a dynamic value", and `.length` read a pointer as a number.

## Decision

- `emitSloppyThis` stores `Object(this)` for any receiver that is not undefined or null. `Object` is the identity on an object, so an object receiver is unchanged. The globalThis arm runs only when globalThis is linked; the wrapping runs either way.
- A wrapper layout's getter and method adapters read and call members on the primitive it holds (`hostReadSelf`), as the wrapper's prototype methods do.

## Consequences

- `TestE2EJSFileSloppyThisWrapsPrimitive` covers both.
- Every sloppy function that reads `this` makes one `Object` call on entry.
