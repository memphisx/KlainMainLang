# ADR-01326: The builtin library compiles to the same code in every program

- **Relations**: Implements TDD-00238 (Stage 4, first part), Extends ADR-01325
- **Date**: 2026-10-01

## Context

[TDD-00238](../tdd/TDD-00238.md) Stage 4 compiles each builtin module once
and links it. That is only possible if a library function's code does not
depend on the program it is compiled into. After Stage 3
([ADR-01325](ADR-01325.md)) it still did: across eight example programs,
299 of 2,457 library functions differed. A module's top-level statements
also ran inline in `@main`, so there was nothing a separately compiled
module could export as its initialization.

## Investigation

`tools/libdrift` emits the IR of a list of programs and reports each
library function (a `__kml_modL` name, a literal named after a library
position, a module init) whose body differs between them, with a
histogram of the symbols on the differing lines. It also lists the
counter-numbered symbols library code names, which may agree in a sample
and still differ elsewhere. The causes, largest first:

- Helpers named by a per-program counter: dynamic get/set routines,
  closure and function adapters, the dynamic-to-static thunks, promise
  settle and `.then` runners, stream wrappers, bind trampolines, array
  element boxers, the lowered-API invokers, array literal images.
- String constants numbered in emission order (`@.s12`).
- Closures and dynamic functions numbered by a counter, also inside
  generic instantiations and a generic class's statics.
- Devirtualization: a call was direct unless something in the program
  overrode the method, and a class had a vtable field only if something in
  its tree was overridden. A library class's layout depended on the user's
  subclasses.
- Vtable slots numbered across the whole tree: the set of library modules a
  program imports moved a class's slots.
- Choices made from what the program had emitted so far: `String(any)`
  probed for host boxes only after one was made; reading an error's own
  field checked error-subclass layouts only if the program declared one.
- Temporaries named by a counter (`__kml_dynarr_5`) that reached a message.
- Map iteration order: a closure's forward-declared captures were boxed in
  Go map order, so even one program could compile two ways.

## Decision

1. **Module init functions.** The resolver records each library
   statement's module key (`LibStatements` maps statement to key). Each
   module's top-level statements become `__kml_lib_<key>_init`, which runs
   them once per isolate (a thread-local flag under workers). `@main` calls
   it where the statements stood; a worker calls the same inits on its own
   thread. Every library binding is a module global, so an init keeps no
   state of its own.
2. **Content names.** A generated helper is named by a hash of its
   signature and body and defined `linkonce_odr hidden`
   (`defineContentNamed`), so two units that generate the same helper link
   to one copy. A helper whose body names itself is named by its memo key
   (the async-generator step). Strings and array literal images are named
   by their content. Error-kind and builtin-constructor names are
   `linkonce_odr` symbols, so their address (which identity tests compare)
   is the same in every unit.
3. **Position names.** A literal in library code is named
   `<prefix>.<module>.<line>_<col>` (`literalSymbol`), with the
   instantiation's type arguments inside a generic one. Generic
   instantiations and a generic class's statics take their declaration's
   module, not the caller's.
4. **Library methods are always virtual**, and a tree rooted in a library
   class always has a vtable: a subclass the library never sees may
   override any method. A class numbers its new slots after its base's
   (single inheritance), so its slots depend only on its ancestors. A vtable
   slot is addressed as `getelementptr ptr, %vt, i32 <slot>`, independent of
   the table's size. A value can carry a class type it is not an instance
   of (Node's types make a Duplex a `Writable`; a cast from `any`), so a
   virtual call first checks the receiver's class: the same class or a
   subclass (`__kml_class_is`) goes through the vtable, anything else calls
   the typed class's implementation directly, as every call did before
   (`emitVirtualTarget`).
5. **No choices from the program.** The host-box probe and the
   error-subclass field read are always emitted.
6. **Determinism.** Captured names are walked in sorted order.

After these, `libdrift` over all 368 examples reports 0 of 8,739 library
functions differing and no counter-named symbol in library code.

## Implementation notes

- `codegen/llvm/contentsym.go`: `contentSymbol`, `defineContentNamed`,
  `contentNamedHelper` (memoized, with a pending check for recursion),
  `closureSymbol`, `literalSymbol`.
- `codegen/llvm/emit_libinit.go`: `libModuleInit`, `emitLibInitCalls`,
  `groupLibStatements`.
- `inLib` is the module key ("" outside the library), not a bool.
- Error subclasses keep the error object's fields in place: the vtable
  field follows them (`errorFieldsPrefix`; a displaced system slot renamed
  `__kml_err_<name>` still counts). `Type.VTableIndex` replaces the
  hard-coded field 1.
- `tests/compiler_test.go` links the runtime through `appendRuntime`,
  which reads `EmbeddedCSources`, the list the CLI links, instead of 25
  hand-kept `append*` helpers that had drifted (one omitted the registry
  runtime).

## Side effects discovered

Fixed (each repro checked against Node):

- An `Error` subclass with an overridden method segfaulted on a generic
  error path (`throw`, `String(e)`): its vtable pointer sat on the error's
  `message` field.
- A virtual call with an optional number parameter passed `{ i1, double }`
  where the call type said `double` (invalid IR).
- `pipeTo` with an abort signal read the signal's `#reason` through a
  class type snapshot taken before its layout was final (without the
  vtable field), and the stream runtime rejected promises with the payload
  only, leaving the reason's tag unset: the result depended on stray
  memory (a hang at some path lengths, a crash without a `try`). Private
  fields are now reached through `classField`, and every rejection goes
  through `__kml_promise_reject_with` (with `_err`, `_from` and `_box`
  forms); `TestPrivateFieldsGoThroughClassField` and
  `TestRejectionsGoThroughOneWriter` hold both rules. A dynamic import's
  failure had the same unset tag.
