# TDD-00155: The native dynamic object model (D1) — per-instance property bag, prototype chain, descriptors

- **Status**: Implemented

- **Date**: 2026-09-01

## Context

[TDD-00068](TDD-00068.md) settled the *direction* of the object model once: the
endpoint is a **native dynamic/prototype object model** ("D1" — per-instance
mutable property set + prototype pointer + property descriptors), later
optimized by hidden classes ("D2"), with the per-type shape descriptor rejected
outright as throwaway work. That document deliberately stopped at direction.
This one is the design: the concrete representation, the runtime surface, the
static↔dynamic boundary rules, and the staging, in enough detail that
implementation can start.

Why now: a root-cause clustering of every caveat in `docs/status/data/*.json`
shows the static object model is the single largest blocker in the project —
roughly **144 of 488 caveats (~30%), across 15+ areas**, all reduce to "no
runtime dynamic value / no prototype model". The recurring symptom shapes:

- **Literal-only arguments** (~26 caveats alone): any API that walks a value at
  compile time (`hasOwnProperty` keys, format strings, computed member names)
  rejects a runtime-computed argument.
- **`any` carries no shape**: the `{i8,i64}` box's object tag (6) is a bare
  pointer — field access, indexing, calling, `Object.keys`, and object rest on
  an `any`/union value are all clean rejections. `JSON.parse → any` is
  unsupported for the same reason ([TDD-00077](TDD-00077.md)).
- **No prototype machinery at all**: no `.prototype`, `Object.create`,
  `getPrototypeOf`/`setPrototypeOf`, `__proto__`, no `class X extends Error`
  (built-in bases aren't extendable), no pre-ES6 prototype "classes" — the core
  payload of vanilla-JS compat ([TDD-00022](TDD-00022.md)).
- **No descriptors**: `defineProperty`, enumerable/writable/configurable,
  accessors-as-data, `getOwnPropertyDescriptor`; `freeze`/`seal` are faked with
  a runtime frozen-pointer set rather than attributes.
- **No `Proxy`/`Reflect`/well-known symbols** — the object-model conformance
  ceiling [TDD-00061](TDD-00061.md)/[TDD-00063](TDD-00063.md) documented
  (generators shipped and flipped zero corpus files because every test probes
  `.prototype`).

Axis 1 of TDD-00068 (object type arguments in generics) shipped as
[ADR-00352](../adr/ADR-00352.md), so the static track is done; everything left
on the list above is Axis 2, i.e. this document.

## Design

### The one governing decision: a two-tier object model

TDD-00068 left "does everything become dynamic?" open. Decided here: **no —
two tiers, permanently.**

- **Tier S (static)**: objects whose shape the front end fully knows stay
  exactly what they are today — fixed-shape nominal structs, `FieldIndex` →
  GEP, direct/vtable method dispatch, zero headers added. This preserves the
  native-performance identity for the typed core and means D1 adds **zero cost
  to existing compiled code**.
- **Tier D (dynamic)**: a heap object with a per-instance property table, a
  prototype pointer, and per-property descriptors. This is where `any` member
  access, `JSON.parse → any`, runtime-keyed access, prototype semantics,
  descriptors, `Proxy`, and vanilla-JS compat live.

The dividing line is drawn **at compile time, per allocation site** (see
"boundary rules" below) — there is no runtime migration of a live struct into a
bag, which is exactly the per-type-descriptor trap TDD-00068 rejected.

This matches the project's options-as-differentiator stance: the typed core
keeps Go-class performance by default; dynamism is paid for only where the
source actually demands it.

### Runtime representation

One new heap layout, allocated with plain `calloc` (so `-mm=gc` inherits it
through the existing allocator shim, no mode-specific code):

```
DynObj header (32 bytes):
  offset 0:  i64  magic/flags     — low 32 bits: magic KMLDYNOBJ_MAGIC
                                    high bits: EXTENSIBLE | SEALED | FROZEN | IS_PROXY
  offset 8:  ptr  proto           — prototype (DynObj* or null)
  offset 16: ptr  props           — property entry array (grown by realloc, doubling)
  offset 24: i64  count|cap       — i32 count, i32 cap packed

Property entry (32 bytes each):
  offset 0:  ptr      key         — interned NUL-terminated UTF-8 string
  offset 8:  {i8,i64} value       — the existing any box, verbatim
                                    (accessor property: payload = ptr to {getter, setter} closure pair)
  offset 24: i64      attrs       — WRITABLE | ENUMERABLE | CONFIGURABLE | ACCESSOR
```

Decisions folded into that layout:

- **The value cell is the existing `{i8,i64}` any box** (tags 0–9,
  `emit_dynamic.go`), not the map runtime's untagged raw-`i64` slot. The box
  already self-describes every runtime value the compiler has (int, float,
  string, bool, null, undefined, object, array-with-malloc'd-header, funcRef);
  a dynamic property *must* be self-describing because no static type exists at
  the read site. The `__kml_map_str_*` store ([TDD-00012](TDD-00012.md)) is
  per-site-typed and stays what it is — the typed `Map`/index-signature
  backend. D1 does not replace it and does not build on it; they share nothing
  but the linear-scan idea.
- **One new box tag, 10 = DynObj.** Tag 6 (static object/class pointer) keeps
  its meaning; the two must be distinguishable at runtime because member access
  compiles completely differently. `typeof`, `__kml_any_eq`, and
  `emitDynamicToString` gain a tag-10 arm.
- **Insertion-ordered linear array, not a hash table.** Correctness-first per
  TDD-00068: insertion order *is* JS property order for string keys created
  this way, `for...in`/`Object.keys` fall out by walking the array, and delete
  is `memmove`. O(n) lookup is the honest V1; the perf ladder is (a) an
  optional key-hash word per entry later, (b) D2 hidden classes — both
  invisible to callers of the runtime API. Faithfulness first; the perf gap is
  recorded, not designed around.
- **Key interning**: keys are compared by `strcmp` in V1. String-literal keys
  reuse the module-level interned globals; runtime keys are copied on first
  insert (the entry owns its key). Integer-index key canonicalization
  (`obj[1]` ≡ `obj["1"]`, array-index ordering before string keys) is deferred
  to the stage that needs it (Stage 5 exotic behavior) and disclosed until then.
- **Accessors**: an `ACCESSOR` entry's payload points at a two-slot
  `{getter, setter}` pair of closure pointers (the object-literal
  getter/setter machinery from [TDD-00153](TDD-00153.md)/[ADR-00603](../adr/ADR-00603.md)
  provides the closure shape). Data↔accessor conversion via `defineProperty`
  is just rewriting the entry in place.

### Runtime surface

Emitted once via the mandatory `ensureXxx()` pattern, `@__kml_dynobj_*`:

```
@__kml_dynobj_new(ptr proto)                      -> ptr
@__kml_dynobj_get(ptr, ptr key)                   -> {i8,i64}   // full proto-chain walk, accessor call, miss = undefined (tag 5)
@__kml_dynobj_set(ptr, ptr key, {i8,i64} v)       -> i1         // walks chain for setters/writability, else own define; false = rejected (frozen/readonly)
@__kml_dynobj_has(ptr, ptr key)                   -> i1         // `in`: chain walk
@__kml_dynobj_has_own(ptr, ptr key)               -> i1
@__kml_dynobj_delete(ptr, ptr key)                -> i1
@__kml_dynobj_define(ptr, ptr key, {i8,i64} v, i64 attrs) -> i1 // defineProperty core, no chain walk
@__kml_dynobj_get_desc(ptr, ptr key, ptr out)     -> i1         // getOwnPropertyDescriptor
@__kml_dynobj_keys_enum(ptr)                      -> {ptr,i64}  // own enumerable string keys, insertion order
@__kml_dynobj_keys_all(ptr)                       -> {ptr,i64}  // getOwnPropertyNames
@__kml_dynobj_get_proto(ptr) / _set_proto(ptr,ptr) -> ptr / i1  // set_proto: cycle check, false on cycle/non-extensible
@__kml_dynobj_prevent(ptr, i64 mode)                            // preventExtensions / seal / freeze (attrs sweep)
```

Accessor invocation inside `_get`/`_set` calls through the closure pair with
the receiver boxed as tag 10 — which is what finally gives dynamic-object
methods a real, rebindable `this` (the receiver is just an argument).

### Compile-time boundary rules (where Tier D is chosen)

An expression compiles to Tier D when any of these hold; otherwise nothing
changes:

1. **Member access / index / call on an `any`-typed value.** Tag-checked at
   runtime: tag 10 → `__kml_dynobj_get`; tag 6 → still a clean *runtime* error
   in V1 ("static object in dynamic position", see rule 4); other tags → the
   JS primitive behavior (string length etc.) or TypeError, staged.
2. **`JSON.parse` with no type assertion** returns tag-10 objects / tag-7
   arrays all the way down ([TDD-00077](TDD-00077.md) closes here — this is
   D1's first end-to-end consumer and its acceptance test).
3. **Explicit dynamic constructors**: `Object.create(proto)`, a literal whose
   contextual type is `any`, and (Stage 4) the vanilla-JS opt-in's
   function-constructor instances.
4. **A Tier-S value reaching a dynamic position** (assigned into `any`,
   boxed): V1 keeps today's behavior — the box is tag 6, and *member access
   through it stays rejected* (now at runtime rather than compile time only
   where a compile-time rejection is impossible). The bridge that lifts a
   static struct into a first-class dynamic view is **Stage 6**, and the
   options are constrained by TDD-00068's rejection of per-type descriptors:
   the chosen route is **allocation-site widening** — when the front end can
   see that a struct literal/`new` flows into a dynamic position, it allocates
   it as Tier D from the start (shape known at the site, so the bag is filled
   field-by-field at construction; reference semantics preserved because there
   is only ever one representation per instance). Escapes the analysis can't
   see stay clean rejections. No runtime migration, ever.

Class instances stay Tier S unconditionally in this document's scope; making
`class` interoperate with `.prototype` reads is D2-adjacent and explicitly out
of scope (the existing vtable model is not disturbed).

### What each existing subsystem does with tag 10

- `Object.keys/values/entries`, `for...in`, spread, rest: on a static shape,
  unchanged (compile-time `VisibleFields`); on tag 10, the runtime enumeration
  helpers. Object rest over `any`/union — TDD-00068's original trigger —
  becomes `keys_enum` minus the named set, at runtime.
- `JSON.stringify`: tag-10 arm walks `keys_enum` + `_get` recursively (the
  map-backed arm from [ADR-00482](../adr/ADR-00482.md) is the template).
- `freeze`/`seal`/`isFrozen`: tag 10 uses header flags + attrs sweep
  (real descriptors); Tier S keeps the frozen-pointer set. The caveat "freeze
  is a pointer set, not descriptors" stays disclosed for Tier S only.
- `structuredClone`, `__kml_any_eq`, `emitDynamicToString`, `typeof`: one new
  tag arm each ("object" for typeof).

### Staging

| Stage | Content | Clears |
|---|---|---|
| **1 — core bag** | Layout + `__kml_dynobj_*` (data properties, no proto walk yet: proto=null), tag 10, `any` member get/set/delete/`in`/index via runtime key, `Object.keys`/`for...in`/spread/rest on tag 10, JSON.stringify arm | the `any`-has-no-shape caveat family; runtime-keyed access |
| **2 — `JSON.parse → any`** | Untyped parse builds tag-10/tag-7 trees; the existing typed `JSON.parse<T>` path untouched | TDD-00077; the single most-cited dynamic-data caveat |
| **3 — prototype chain** | proto pointer live in get/set/has, `Object.create/getPrototypeOf/setPrototypeOf`, `__proto__` on tag 10, cycle check | prototype-semantics caveats; unblocks 4 |
| **4 — vanilla-JS prototype "classes"** | function-constructor `new F()` (tag-10 instance, proto = `F.prototype` bag), `F.prototype.m = function...`, method calls with real `this` (receiver argument) — gated behind the vanilla-JS opt-in flag of [TDD-00022](TDD-00022.md) | TDD-00022's break shapes #3/#4 |
| **5 — descriptors** | `defineProperty`/`getOwnPropertyDescriptor(s)`/`getOwnPropertyNames`, accessor entries, attrs enforced in set/delete/enumerate, `preventExtensions`/seal/freeze via flags | descriptor caveats; the corpus's object-model probes |
| **6 — the static bridge** | allocation-site widening (rule 4), `class X extends Error` (Error becomes a Tier-D-compatible base under the opt-in), union-of-objects member access | boundary caveats; TDD-00043/TDD-00062 leftovers |
| **7 — `Proxy`/`Reflect`** | `IS_PROXY` flag + handler table consulted in the runtime entry points; `Reflect.*` maps 1:1 onto `__kml_dynobj_*` | the last conformance-ceiling tier |

Each stage is independently shippable, lands with E2E tests + examples, and
updates the status JSON same-commit. D2 (hidden classes / inline caches) is a
separate future TDD by design — nothing in this layout blocks it (the header
word has room for a shape pointer), and nothing here is discarded by it except
the linear scan's interior.

### Rejected within this design

- **Building D1 on `__kml_map_str_*`**: its untagged `i64` values can't
  self-describe, its header has no proto/flags, and generalizing it would tax
  the typed `Map` path. Shared-nothing is cleaner; the map runtime stays the
  typed backend.
- **All-dynamic (every object a bag)**: simpler mental model, but taxes every
  typed allocation and field access, contradicts the native-performance
  identity, and buys nothing Tier S code asked for.
- **Runtime migration of a live struct to a bag**: needs a per-type descriptor
  to know the fields at runtime — the exact rejected mechanism. Allocation-site
  widening keeps shape knowledge at compile time where it already lives.
- **Hash-backed bag from day one**: insertion order must be maintained anyway
  (JS enumeration order), so the hash is an add-on index, not a replacement —
  i.e. deferrable by construction. Correctness-first V1 stays the plain array.

## Open questions

- **Primitive members through `any` (Stage 1 edge)**: tag-2 string / tag-7
  array member access through the dynamic path (`x.length`, `x.push`) — full
  primitive-method dispatch at runtime is a large surface. Likely staged as a
  small allowlist (length, common methods) with clean runtime TypeErrors
  elsewhere; exact cut line to be settled by the Node-oracle histogram.
- **Integer-index canonicalization and key ordering** (`obj[1]` vs `obj["1"]`,
  array-index-first enumeration order): which stage absorbs it, and whether the
  entry array splits index/string regions or sorts lazily at enumeration.
- **Symbols as keys**: well-known symbols (Stage 7 needs `Symbol.iterator` at
  least) — a second key kind in the entry (tagged key pointer) or a parallel
  symbol table.
- **`null`-prototype vs default-prototype objects**: whether tag-10 literals
  get a shared `Object.prototype` bag (needed the moment `hasOwnProperty` is
  called *on* a dynamic object) and where that singleton lives per binary.
- **Allocation-site widening precision** (Stage 6): flow analysis depth —
  local-only (assignment/argument into a declared-`any` slot) vs
  interprocedural. Local-only is the likely V1; the miss cases stay clean
  rejections either way, so precision only moves the caveat line.
- **Manual-mode lifetime**: `-mm=manual` has no free-points for bags that
  escape through `any`; presumably the same "leaks are the manual-mode
  contract" stance as closures/boxes today — confirm and disclose.
