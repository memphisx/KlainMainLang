# ADR-01701: arguments is an Arguments object

- **Relations**: `Implements TDD-00230`; `Extends ADR-00387`
- **Date**: 2026-10-18

## Context

A function's `arguments` was an Array, so it differed from Node's Arguments object in six ways:

| | Node | Before |
|---|---|---|
| `Array.isArray(arguments)` | `false` | `true` |
| `arguments.constructor` | `Object` | `Array` |
| `Object.prototype.toString.call(arguments)` | `[object Arguments]` | `[object Array]` |
| inspect | `[Arguments] { '0': 1 }` | `[ 1 ]` |
| `JSON.stringify(arguments)` | `{"0":1}` | `[1]` |
| `String(arguments)` | `[object Arguments]` | `1` |

## Decision

The object stays an `any[]` array header, so its elements, `length`, iteration, spread, `Array.from` and `Array.prototype` methods still work. Only its header word changes, to `HArguments` (`argumentsHeaderWord`).

- **Typed reads.** Every place that renders or classifies an `any[]` checks that word at run time, through `emitArgumentsBranch`, `emitArrayIsArguments` and `mayBeArguments`. These are `Array.isArray`, inspect, `JSON.stringify` and string conversion. An Arguments object takes its boxed path.
- **The C runtime.** `kj_is_args` (`dynjson.c`) recognizes the word in the boxed paths:
  - inspect (`[Arguments] { … }`, or `[Arguments] {}` when empty);
  - JSON (an object of its index keys, with undefined values left out);
  - join (`[object Arguments]`);
  - the toString tag;
  - the prototype key (Object);
  - `constructor` (Object).
- **Array subclasses.** Their body checks (`emitArrayWordIsClass`) treat the word as no class's.

## Verification

macOS (Apple Silicon): the probes match Node's output. They cover typed and boxed reads, an `any[]` parameter given `arguments`, and the `-compat=js` lane. `TestE2EArgumentsObject` passes.
