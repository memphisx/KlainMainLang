# ADR-01227: Buffer.from is binary-safe; isEncoding and the ranged ArrayBuffer form

- **Relations**: `Implements TDD-00234`
- **Date**: 2026-09-29

## Context

Porting `child_process` to TypeScript (TDD-00234) exercised `Buffer` the
way Node's own code does, and five gaps showed:

- `Buffer.from("a\u0000b")` was 1 byte: the UTF-8 path measured the
  string with `strlen`. The spawn's NUL-separated argv block was cut at
  its first NUL, so `sh -c '…'` started an interactive shell on its stdin.
- `Buffer.isEncoding` was a codegen error.
- `Buffer.from(arrayBuffer, byteOffset, length)` was a codegen error.
- `Buffer.byteLength(x)` with `x: any` passed the box where a string
  pointer belongs (invalid IR).
- `new Uint8Array(buffer, byteOffset, length)` rejected an `any`
  buffer.

## Decision

- The UTF-8 decode (the static path and `__kml_buf_decode_enc`) takes the
  string's header length. Strings are length-prefixed, so a NUL is a byte
  like any other.
- `Buffer.isEncoding(x)`: true for a non-empty string that Node's
  `normalizeEncoding` knows (case-insensitive), false for anything else,
  `any` included.
- `Buffer.from(arrayBuffer, byteOffset, length?)` copies that range, as
  the one-argument form copies the whole. An offset or length past the
  end is Node's `RangeError` `ERR_BUFFER_OUT_OF_BOUNDS` (`"offset" is
  outside of buffer bounds` / `"length" …`).
- `Buffer.byteLength` of an `any` reads its string.
- The typed-array view constructor unboxes an `any` buffer (the host
  cell's ArrayBuffer).

## Implementation notes

`codegen/llvm/emit_buffer.go`, `buffersrc/buffer_codecs.c`,
`runtime_buffer.go`, `emit_arraybuffer.go`.

## Verification

Mac (Apple Silicon), against Node v24.19: `Buffer.from("a\u0000b")` is
`<Buffer 61 00 62>`; `TestE2EBufferBinarySafeAndRanges`.
