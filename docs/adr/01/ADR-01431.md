# ADR-01431: The checker types a name read before its declaration

- **Relations**: Implements TDD-00230 (P2.2), Extends ADR-01430
- **Date**: 2026-10-06

## Context

After ADR-01430 the shadow report's largest bucket (12202 rows) was an
identifier codegen answered `i64` where the checker answered `number`: a
`var` declared in a `for` header (`for (var i = 1; …)`), read in the js lane.

## Investigation

- A stack at the disagreeing query: `jsCollectCtorParamTypes`, a js-lane
  pass over the whole program that types untyped constructor parameters
  from the arguments of each `new`. It runs before any declaration is
  emitted, and a `for`-header `var` is not among the top-level names that
  inference types from their own declaration (ADR-01060), so the name fell
  to the number default, `i64`.
- Probes passing such a variable to a constructor printed what Node prints:
  a later pass overrides the guess, so no output differed.

## Decision

An identifier inference cannot resolve, after the cases it already handles,
takes the checker's storage type for it when that type has a
representation, instead of the number default.
