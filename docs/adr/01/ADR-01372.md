# ADR-01372: A class method's number parameter takes ToNumber under -compat=js

- **Relations**: Extends TDD-00022's `-compat=js` lane; Superseded by ADR-01377 (the conversion moved into `coerce`)
- **Date**: 2026-10-03

## Context

Conformance of the staged tree (strict 8,308, js 10,023) showed 28 more
files of invalid IR than before. About twenty were DataView files:
`sample.getBigInt64("1")`, `getBigInt64([0])`, `getBigInt64(["1"])`.
Strict rejects these (TS2345), and the conformance tool classifies the
rejection by compiling the file under `-compat=js`. DataView became a
TypeScript class in ADR-01352.

## Investigation

- A class method call converted each argument with `coerce`, which turns
  neither a string nor an array or object into a number. The pointer was
  passed where a `double` was declared. A free function's call already
  applied ToNumber.
- ToNumber of an object or array goes through ToPrimitive first. `["1"]` is
  `"1"`, so 1; `__kml_any_tonum` alone gives NaN for an object.

## Decision

Under `-compat=js`, a string, array or object argument for a number
parameter of a class method is boxed. An array or object goes through
`__kml_toprimitive` (number hint), and the result through `__kml_any_tonum`,
before the usual conversion to the parameter's width.

## Implementation notes

`codegen/llvm/emit_classes.go` (`emitClassCall`).

## Verification

Mac (Apple Silicon): the DataView `toindex-byteoffset` Test262 file passes
under `-compat=js`, and the DataView category has no invalid IR;
`TestE2ECompatJSClassCallToNumber` matches Node's values.
