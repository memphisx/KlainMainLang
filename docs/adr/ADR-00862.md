# ADR-00862: Runtime ToPrimitive over NaN-boxed objects — compat=js (TDD-00201 Stage 4)

- **Relations**: `Extends ADR-00859, ADR-00860, ADR-00861`, `Implements TDD-00201`
- **Date**: 2026-09-10

## Context

Stages 1–3 made object ToPrimitive faithful in the **strict** lane via a static
ladder (`emitObjectToPrimitive`, gated on `!IsDynamic`). But under `-compat=js` a
plain object literal is a **D1 dynamic bag** (NaN-box tag 10), so the static
ladder never fires and the value hit the dynamic path's "heap ref → NaN" arm:
`{valueOf(){return 5}} * 2` was `NaN`, `String({toString(){return "hi"}})` was
`"[object Object]"`. This inverted the usual axis — the *faithful* lane was the
*less* faithful one. Stage 4 restores it with a runtime ToPrimitive.

## Investigation

The pieces already exist: `__kml_nb_tag` (logical tag: 10 = dynamic object, 12 =
dynamic function), `__kml_nb_pay` (the bag pointer), `__kml_dynobj_get(bag, key)`
→ boxed value, and the tag-12 dynamic-function ABI
`call i64 %fp(ptr %env, i64 %recvBox, i64 %n, ptr %argv)` (from
`emitDynFnBoxCall`). A primitive box is `nb_tag < 6`. So a runtime ladder can look
up `valueOf`/`toString`/`@@toPrimitive` on the bag, invoke the callable with the
object as receiver, and check the result — no new object model needed.

The integration points are `emitAnyBinary` (all `-compat=js` arithmetic/`+`) and
`emitDynamicToString` (`String()`/template/concat of a dynamic value).

## Decision

New runtime functions (`emit_toprimitive_dyn.go`, emitted once):

- `@__kml_tp_invoke0(fnbox, recv)` / `@__kml_tp_invoke1(fnbox, recv, arg)` —
  invoke a tag-12 boxed function with the object as receiver (0 args for
  valueOf/toString; 1 arg — the hint string — for `@@toPrimitive`).
- `@__kml_toprimitive(box, i1 strHint)` — the ladder: `@@toPrimitive` first, then
  valueOf→toString (number/default hint) or toString→valueOf (string hint); the
  first callable whose result is a primitive (`nb_tag < 6`) wins, else the literal
  `"[object Object]"`. A non-object box passes through unchanged, so it is safe to
  apply to every dynamic operand.

Wired in: `emitAnyBinary` runs `@__kml_toprimitive(_, 0)` on both boxed operands
before the concat/ToNumber logic (a string result concatenates, a number adds);
`emitDynamicToString` runs `@__kml_toprimitive(_, 1)` before formatting.

**Loose equality** (`==`/`!=`) is JS's Abstract Equality Comparison, which
coerces — distinct from strict `===` (`__kml_any_eq`). New
`@__kml_any_loose_eq(a, b)`: both heap objects → reference compare (`{}=={}` is
`false`); exactly one object → ToPrimitive it; null/undefined loosely equal only
each other; same primitive type → strict compare; mixed primitives → ToNumber
both and compare (`fcmp oeq`, so a NaN makes it `false`). Routed in three places:
the dynamic-operand `==`/`!=` branch, and — for static mismatched-kind pairs
(`5 == "5"`, `"" == 0`, `null == 0`) under `-compat=js` — an early divert (after
numeric promotion, so int/float pairs are untouched) plus the incompatible-types
escape. `===`/`!==` stay uncoerced.

## Implementation notes

- `emit_toprimitive_dyn.go` (`ensureAnyToPrimitive`, `emitAnyToPrimitive`);
  `usedAnyToPrimitive` guard field; hooks in `emit_anyops.go` and
  `emit_dynamic.go`.
- The receiver passed to valueOf/toString is the object box itself, so `this`
  works inside the method.
- Idempotent: applying it in `emitAnyBinary` and then again inside the concat
  branch's `emitDynamicToString` is a no-op the second time (the operand is
  already a primitive).

## Side effects discovered

- **Runtime ToPrimitive invokes Proxy `[[Get]]` traps (faithful), which unmasked
  a pre-existing promises gap.** `String(proxy)` / coercing a Proxy now performs
  the `[[Get]]` of `toString`/`valueOf`/`@@toPrimitive` — matching Node exactly
  (a Proxy whose `get` trap throws makes `String(proxy)` throw in both). Before
  Stage 4 the dynamic-to-string path returned `"[object Object]"` without a
  `[[Get]]`, so it silently diverged. The Node-oracle test
  `test-promises-unhandled-proxy-rejections.js` (an all-traps-throw Proxy passed
  to `Promise.reject` under `--unhandled-rejections=none`) went strict 49→48
  purely from this: the compiler stringifies the rejection value even though
  `--unhandled-rejections=none` says never to touch it, so the now-faithful
  trap-throw surfaces where the old `[object Object]` masked it. The root cause is
  the unhandled-rejection / `--unhandled-rejections` gap (a promises/process
  feature, not ToPrimitive) — recorded in BACKLOG. `make test-par` is unaffected.
- A method-less object in an operator: **compat=js** is faithful — `{a:1} + 5` →
  `"[object Object]5"`, `{a:1} * 2` → `NaN` (the ladder returns `"[object Object]"`
  for a method-less object). **strict** previously emitted invalid IR for
  `{a:1} + 5` / `* 2` / `< 5`; since TypeScript itself errors on object arithmetic,
  this now rejects cleanly (message names the `-compat=js` hatch), generalizing the
  object-vs-scalar equality rejection to the arithmetic/relational operators.
  `"s" + {a:1}` still compiles (TS allows string+object; it stringifies — the
  pre-existing strict inspect-view vs compat `"[object Object]"` divergence).

## Verification

- E2E `TestE2EToPrimitiveCompatJSRuntime` (`*`, `+`, concat, `String()`,
  template, `@@toPrimitive`) and `TestE2EToPrimitiveCompatJSLooseEquality`
  (object ToPrimitive `n == 5`, both-objects `{}=={}` → false, nullish, mixed
  static scalars `5 == "5"`/`"" == 0`) under `-compat=js`, all matched to `node`.
  Strict-lane ToPrimitive tests unchanged.
- `go build`, `go vet ./...` clean; full `make test-par` — no regression.
