# ADR-00646: Factory decorators — calling a callee that is itself an expression

- **Relations**: `Implements TDD-00161`, `Extends ADR-00645`
- **Date**: 2026-09-02

## Context

Factory (parameterized) decorators — `@dec(...)` — are the shape almost every
real framework uses (`@Controller('/api')`, `@Get('/users')`, `@Injectable()`,
`@Column({…})`). They lower (TDD-00161) to `(dec(...))(target, key[, …])`: the
factory call runs, and its **returned value** is invoked as the decorator. This
was the next decorator gap and the last identified TypeScript-oracle lever.

## Investigation

- The decorator-application code already synthesizes an `ast.CallExpression`
  whose callee is the decorator expression. For `@tag("meta")` that callee is
  itself a `CallExpression`, so the synthesized outer call is
  `(tag("meta"))(args)`.
- `emitCall` (`emit_call.go`) dispatched on specific callee shapes — a named
  function, a method, a closure *variable*, an arrow/function-expression IIFE,
  and `mem`/index callees whose inferred type `IsFunc` — but had **no** case for
  a callee that is an *arbitrary expression* producing a function value. Such a
  callee fell through to `"only simple function calls are supported"`. This is
  the general "bare-function-as-value / returned-value-call ABI gap" the earlier
  decorator stages disclosed.
- The tag-12 dynamic-function ABI (`emit_dynfunc.go`) already exists for calling
  a boxed function value; `emitClosureCallByPtr` already exists for a typed
  closure value. Only the routing from `emitCall` was missing.

## Decision

Add a final fallback to `emitCall`, after every specific callee form (and after
member callees, which return their own "has no method" diagnostic): if the
callee expression's inferred type is `IsFunc` or `IsDynamic`, evaluate it and
call through the value —

- `IsFunc` → `emitClosureCallByPtr` (a typed closure/function value; captures
  and the closure ABI handled).
- `IsDynamic` → `emitDynCallValue`, a new helper that boxes the arguments and
  dispatches through the tag-12 ABI with an `undefined` receiver.

`emitDynCallValue` and the existing dynamic *method* call now share
`emitDynFnBoxCall` (the tag-12 unbox → call → throw-on-non-function core),
factored out rather than duplicated.

This is a **general** fix, not decorator-specific: `getHandler()(x)`, a function
read out of an `any` value, and any other "call the result of an expression"
site now work too.

## Side effects discovered

- Factory decorators work across all placements (property/method/class/parameter)
  when the returned decorator is a named function or a **typed** closure
  (verified incl. one capturing its factory argument through the closure ABI).
- A returned **`any`-typed** closure that *captures* the factory's arguments
  still hits the separate dynamic-prototype-method capture limitation (a boxed
  dynamic function can't yet carry captures) — annotate the factory's return
  type to route it through the typed-closure path. Disclosed as a caveat and in
  the example.
- Oracle: the `only simple function calls` false-reject bucket dropped 19→17 and
  TS agreement ticked 5365→5367; small, because the remaining decorated corpus
  files carry independent blockers (as the earlier stages found).

## Verification

- `tests/decorators_test.go`: factory decorators on a property, on a method +
  class (the `@Controller`/`@Get` pattern), and a typed factory capturing its
  argument. The old `TestE2EDecoratorFactoryRejectedCleanly` (Stage-1 rejection)
  is replaced.
- `examples/decorators/factory_decorators.ts` runs the NestJS-shaped pattern.
- `go vet`, full `make test-par`, the call/closure/HOF/decorator/generic suites,
  node oracle, `status-check`/`reference-check` pass. Mac (Apple Silicon).
