# ADR-00556: decodeURI/decodeURIComponent throw URIError on malformed input

- **Relations**: Extends ADR-00024
- **Date**: 2026-09-01

## Context

The global `decodeURI(s)`/`decodeURIComponent(s)` were permissive on malformed
input: a `%` not followed by two hex digits (including a truncated one at the
string end) was passed through as literal text. Real JS throws a `URIError`.
This was a disclosed caveat on the `decodeURI` status row.

## Investigation

Both functions share `ensurePercentDecode` (runtime_encoding.go), whose
`__kml_decode_uri_component` output is *also* consumed internally by HTTP
query-string / URLSearchParams parsing (runtime_http.go), where lenient
handling is desirable (a bad query param should not abort request parsing —
matching URLSearchParams's own forgiving percent-decode). So the throw must be
scoped to the global functions only, not the shared decoder.

## Decision

Generalize `ensurePercentDecode` into `ensurePercentDecodeVariant(...,
strict bool)`. When `strict`, the malformed-escape branch targets a new
`pcterr` block that throws a `URIError` (kind id 5, message "URI malformed")
via the same inline error-object construction `atob`'s DOMException path uses.
Add `__kml_decode_uri_strict` / `__kml_decode_uri_component_strict` (strict) and
point the global `decodeURI`/`decodeURIComponent` dispatch at them. The lenient
`__kml_decode_uri_component` stays in place for HTTP/query-string decoding.

## Implementation notes

- The strict variant is byte-identical to the lenient one except the
  bothok-false branch target (`plain` → `pcterr`) and the appended throwing
  block; both are threaded through the shared IR template.
- Per-function error-message/name globals are named by `fnName` to avoid a
  duplicate-global collision between the two strict functions.

## Side effects discovered

None. HTTP query decoding and URLSearchParams keep the lenient decoder, so a
malformed query param is still tolerated rather than aborting request parsing.

## Verification

`TestE2EDecodeURIMalformedThrows` (`"%"`, `"%ZZ"`, `"abc%2"`, `decodeURI("%G1")`
all throw `URIError`; a valid `"ok%20here"` decodes) plus the existing
encode/decode and URLSearchParams/query tests pass. Built and verified on Mac
(Apple Silicon).
