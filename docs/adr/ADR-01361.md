# ADR-01361: A non-array in `any` throws where an array is declared

- **Relations**: Refines TDD-00212's any-array unboxing
- **Date**: 2026-10-03

## Context

`f(x)` with `x: any = "abc"` and `function f(p: any[])` crashed with a
segmentation fault. Found while porting Blob to TypeScript.

## Investigation

- Unboxing `any` into an array slot read the payload as an any-array box
  without checking the tag. A string's payload is its character pointer, so
  the "header" read was garbage. A number's payload is not a pointer at all.
- Node passes the string, and `p.length` is 3. A static array slot holds an
  array's `{data, len}` and cannot hold a string. Matching Node would take
  every array parameter becoming dynamic.

## Decision

The unbox checks the tag:
- an array, or a dynamic array (the existing converting path), is read;
- null and undefined stay the empty-array sentinel;
- anything else throws a `TypeError` ("the value is not an array").

The divergence is a caveat on the `any` row.

## Implementation notes

`codegen/llvm/emit_narrowing.go` (`emitUnboxBoxToType`).

## Verification

Mac (Apple Silicon): a string and a number throw a TypeError that `catch`
narrows; an array and a defaulted null pass through
(`TestE2EAnyNonArrayIntoArraySlotThrows`).
