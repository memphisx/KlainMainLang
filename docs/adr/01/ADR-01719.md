# ADR-01719: Mode-lane fixes: class-captured cells, goroutine stacks under gc

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-18

## Context

The mode-lanes gate builds every example in the default memory mode and under `-mm=auto`, `-mm=auto -optimize-memory` and `-mm=gc`. It reported three differences:

- **`examples/classes/class_factory.ts` under `-mm=auto`:** the counter its factory's class closes over was shared between factory calls.
  - A local that a nested class's methods write lives in a cell, `name__kml_cell: { v: T }`, which the class record keeps.
  - The escape checker models capture by nested functions and arrows, but not by a class body. It found the cell local to its block, so auto-free released it when the factory returned.
  - The next call's cell reused the block.
- **`examples/goroutines/parallel_primes.ts` under `-mm=gc`:** the program crashed in the collector's marker thread.
  - An M thread registers its own stack with the collector, which scans a thread from its stack pointer to the registered bottom.
  - While the thread runs a goroutine, its stack pointer is inside the goroutine's mmap'd stack, so the scanned range spans unmapped memory.
  - The crash needs a collection while a goroutine runs. Here the main thread's `select` allocates its cases and handlers.
- **`examples/readline/lines.ts`:** with no argument it counts its own binary, which differs per mode. That is not a defect, but it hides real ones.

## Decision

- The escape checker treats a nested class (declaration or expression) whose constructor, methods, field initializers or static blocks name the binding as a capture, like a nested function.
- klain:sync moves the collector's stack bottom with every switch, using Boehm's `GC_set_stackbottom`:
  - to the goroutine's stack top when the scheduler resumes a goroutine;
  - back to the thread's own base when a goroutine parks, yields or ends.
- Each switch runs with the collector's lock held. The lock is taken just before `swapcontext` and released on the other side, which is the same thread. So no collection can see the stack pointer on one stack and the bottom on another.
- Every goroutine stack stays a root region, so a parked goroutine's stack is still scanned.
- The mode-lanes runner takes per-example arguments. `lines.ts` counts its own source.

## Verification

macOS (Apple Silicon):

- `TestE2EMemoryAutoClassCaptureCell` passes.
- `TestE2EGCModeGoroutinesSelectChurn` passes. It segfaults with the previous runtime.
- `go run ./tools/modelanes -only 'readline/lines|class_factory|parallel_primes'` reports no mismatches.
- The auto, gc and goroutine suites pass.

Linux x86-64 (DeskMini, Ubuntu 24.04 container):

- Every TLS example under `-mm=gc` runs clean five times in a row. These are the crypto, HTTPS client, multi-server HTTPS, TLS client, websocket server and fetch examples, which segfaulted before this change. Three examples exit 1 in both modes because they need the httpbin fixture or certificates: `async/promise_all`, `fetch/fetch` and `tls/tls_server`.
- Host-name lookups under allocation churn run clean in 15 runs of 50 rounds. `TestE2EGCModeFetchFromResolverThread` now runs 25 rounds, the size that crashed before.
