# ADR-01764: Undeclared names under `-compat=js`

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

Under `-compat=js`, a name no scope declares failed to compile: "undefined variable 'nope'" for a read, "undefined function or closure" for a call. In Node a read of such a name looks it up on the global object and throws `ReferenceError: nope is not defined` if it is not there. A sloppy-mode assignment `y = 2` creates the global object's property `y`; in strict code it throws the same ReferenceError. Test262 checks the ReferenceError in hundreds of tests (every destructuring test that asserts a skipped binding stays undeclared, for one), and older tests create globals by assignment.

## Decision

- A reference the binder looked up and found no declaration for (`unresolvedReference`: no symbol, and a lookup scope recorded) reads as `"name" in globalThis ? globalThis.name : throw ReferenceError(...)` (`emitGlobalPropertyRead`). When the global object is not linked into the program nothing can have given it a property, and the read just throws. A call of such a name does the same.
- An assignment to one in a sloppy file (`sloppyAt`, from `sloppyFiles`) assigns `globalThis.name`. A compound assignment reads it first, so a missing name throws. In strict code the right-hand side is evaluated, then the ReferenceError is thrown.
- The resolver links the global object for a `.js`/`.cjs` file that may assign a name it never declares (`undeclaredAssign`, a text match). An over-match only links the global object.
- The strict lane keeps rejecting such names, as tsc does.

## Consequences

- `TestE2EJSFileUndeclaredNames` covers reads, calls, a property `globalThis` was given, and both kinds of assignment.
