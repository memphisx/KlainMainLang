# TDD-00222: unified boxed-object type-id (recognise an Error at a general boxed site)

- **Status**: Implemented
- **Date**: 2026-09-18

## Context

A caught or rejected Error boxed into `any` becomes `kmlTagObject` with the
`errorObjType` pointer as payload — indistinguishable at a general
render/JSON/member site from a boxed plain class instance or a D1 dynobj bag.
The NaN-box pointer-kind space is full (`kmlTagError = 13` has no packed
encoding), so the discriminator cannot live in the box tag; it has to live in
the pointed-at object. The only offset guaranteed in-bounds on an arbitrary
boxed object is field 0 (every boxed object — errorObjType, class instance,
dynobj bag — begins with an 8-byte i64), and today field 0 collides:

- an `errorObjType` stores its error **kind** (0–8, index into `errorKinds`);
- a class instance stores its **`__kml_tag`** (`TagID`: plain classes 0…N,
  error-subclasses `1000 + n`).

So a boxed plain object with `__kml_tag == 1` reads back as `TypeError` (kind 1),
and `boxedAnything instanceof Error` is unconditionally true
(`emitErrorInstanceOf`'s dynamic arm punts to `tag == kmlTagObject`). This gap
blocks faithful rejection values (TDD-00169), an Error's JSON, safe
`console.log(err)` on a boxed Error, and `AbortSignal.reason` — all need to
recover an Error's shape at a site that only has a boxed pointer.

## Design

**A single marker bit in field 0.** Field 0 of every Error-shaped object (a
built-in `errorObjType` *and* an error-subclass class instance) carries a high
flag bit far above any class `TagID`:

```
errorTypeIDFlag = 1 << 40          // class TagIDs are < 1<<40 by construction
stored(id)      = errorTypeIDFlag | id
```

The low bits still hold the original kind/`TagID` unchanged, so nothing that
consumes the low value needs to mask — and it turns out **nothing reads the low
value except equality compares**: `emitErrorToString` reads the stored `name`
string, not `errorKinds[kind]`, and no runtime path indexes by kind. So the
whole read side is "compare field 0 to a constant"; the change is to flag the
*constant* (`stored(kindID)`), never the loaded register. "Is this an Error"
at a general boxed site is one `and`+`icmp ne 0` against `errorTypeIDFlag`.

Why a bit and not a magic-in-the-value or a wrapper object:

- A **wrapper** (`{ marker-ptr, errObj }` boxed instead of the bare Error)
  would break `===` identity (two boxes of one Error would differ) and adds an
  allocation per box. Rejected.
- **Magic-in-the-whole-value** (re-encode kind as a large base+id) forces every
  compare to change too, same as the bit, but is harder to read in the
  hand-written runtime IR. The bit keeps the low value legible.

**Site inventory** (field 0 is written / compared here; all move to the flagged
value in lockstep):

*Writes (add the flag):*
- `buildErrorObj`, `buildErrorObjWithCode` (via it), AggregateError store
  (`emit_exceptions.go`).
- class instance construction `emit_classes.go` and value-object literal
  `emit_objects_accessors.go` — flagged **only** when `info.IsErrorSubclass`.
- hand-written runtime error builders that stamp field 0 directly:
  `runtime_crypto_subtle`, `runtime_encoding` (×2), `runtime_fetch` (×2, one a
  formatted kind), `runtime_fetch_stream`, `runtime_http`, `runtime_http_reqbody`
  (×2), `runtime_fs`, `runtime_process` (×3), `runtime_streams_zlib`.
  (`runtime_chan`/`runtime_worker` field-0 stores are envelope kinds, **not**
  errors — untouched.)

*Compares (flag the constant):*
- built-in kind compares — `emit_caught.go` (kind arm), `emit_classes.go`
  dynamic-boxed and static `IsError` `instanceof <BuiltinKind>`,
  `emitErrorErrorsAccess` AggregateError guard: `stored(kindID)`.
- error-subclass `TagID` compares — `emit_caught.go` (class-tag arm),
  `emit_classes.go` caught-vs-subclass and the class-`instanceof` hierarchy
  (`tagIDs`): flagged iff the class is an error-subclass. A hierarchy rooted at
  `Error` is uniformly error-subclass, so the whole `tagIDs` list flags or not
  together; the widened-bag `__kml_dynobj_classtag` copies field 0 verbatim, so
  it stays consistent with the flagged store.
- `emitErrorInstanceOf` dynamic `Error`-base arm stops punting to
  `tag == kmlTagObject` and tests the flag instead → boxed plain objects are no
  longer `instanceof Error`.

*Consumers (new, recover the Error):* `emitBoxedValueToString`'s object arm,
`JSON.stringify`'s boxed-object arm, and `emitDynAnyMemberGet` branch on the
flag: an Error renders via `emitErrorToString` / serialises per JS
(`Error → {}` for own enumerable props) / reads `.message`/`.name` from the
real fields; a non-Error keeps the existing object behaviour.
