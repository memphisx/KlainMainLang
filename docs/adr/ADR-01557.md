# ADR-01557: Overloaded and callable sources in assignability; `Iterable` needs iteration; `__promisify__` typing

- **Relations**: Extends ADR-01554, TDD-00230
- **Date**: 2026-10-10

## Context

Tightening which weak overload fits (ADR-01554) exposed relations the
checker answered "maybe" where TypeScript answers yes or no:

- An overloaded function as the source of a function type (`promisify(exec)`)
  related as "maybe" whatever its signatures, so the first overload of
  `promisify` fitted `exec` though `exec` needs more parameters than it
  supplies.
- `Iterable<T>` has no modelled members (its `[Symbol.iterator]`), so every
  object fitted it: `Array.from(new Counter())` resolved to the iterable
  overload for a class that does not iterate.
- A function merged with a namespace (`function execFile` + `namespace
  execFile`) is, in TypeScript, one value with both the call signatures and
  the namespace's members; overload inference saw only the function.
- A callable object type lacked the members every function has through
  `Function.prototype`, so it fitted no interface extending `Function`.
- A subclass of `Array<T>` did not iterate as `T` (the base chain was not
  followed), and `Array<T>`/`ReadonlyArray<T>` met as interfaces were not
  iterated at all.
- @types/node types `util.promisify(exec)` and `util.promisify(execFile)`
  through the functions' `__promisify__` members and the
  `CustomPromisifyLegacy` overload of `promisify`; this project's library
  had neither, so those calls only type-checked through a loose fit.
- `new K()` through a class value looked the class up by the checker's
  symbol name, which a local class (renamed to stay unique) does not have,
  so the instance was built boxed.

## Decision

- An overloaded source relates to a plain function type when one of its
  signatures does, and fails when none does.
- An object of a program class or literal type fits `Iterable<T>` /
  `IterableIterator<T>` only when it iterates.
- Overload resolution types an identifier argument naming a function with
  a merged namespace as that merged value.
- A callable object type has `Function`'s members.
- An instance iterates as its base class does; `Array<T>` and
  `ReadonlyArray<T>` iterate as `T`.
- A weak overload fit whose argument is not whole (ADR-01554) is taken
  when no other overload fits, instead of none.
- The library declares `exec.__promisify__` and `execFile.__promisify__`
  type-only (`declare namespace`), with @types/node's overloads, and
  `promisify`'s `CustomPromisifyLegacy<TCustom>` overload.
- `new K()` through a class value finds the class through its declaration
  first.

## Divergences

- @types/node's `CustomPromisifySymbol` (a `[util.promisify.custom]`
  member) is not declared: symbol-keyed members are not modelled; the
  `__promisify__` form covers the library's own functions.
- The promisified forms resolve `Promise<{ stdout; stderr }>`, not
  @types/node's `PromiseWithChild<…>` (the `child` property is present at
  run time, untyped).
