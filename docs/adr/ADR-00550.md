# ADR-00550: atob() implements WHATWG forgiving-base64

- **Relations**: Extends ADR-00458
- **Date**: 2026-09-01

## Context

`atob(s)` (`__kml_atob`) had two V1 simplifications versus WHATWG
forgiving-base64: ASCII whitespace in the input was *rejected* (it isn't in the
base64 alphabet) instead of stripped, and an input length that wasn't a
multiple of 4 silently dropped the trailing 2- or 3-character group because the
decode loop only processed complete 4-char groups. Both were disclosed caveats
on the global-functions status page.

## Investigation

The decode loop keyed off `%str`/`%len` with a `i4 <= len` group guard and
already handled `=` padding via the `ch2eq`/`ch3eq` selects. The faithful fix
is a normalization prefix that produces a whitespace-free, correctly-padded
buffer, after which the existing validate+decode logic runs unchanged.

## Decision

Prepend a normalization stage to `__kml_atob`:

1. Copy every non-whitespace byte (tab/LF/FF/CR/space = 9/10/12/13/32) of the
   input into a fresh `%norm` buffer (`rawlen + 5` capacity for padding + NUL).
2. Strip up to two trailing `=`.
3. If the remaining length ≡ 1 (mod 4), throw `InvalidCharacterError`
   (matches WHATWG — that residue is undecodable).
4. Re-pad with `=` to the next multiple of 4 and NUL-terminate.

The validate and decode loops then run over `%norm`/`%len` exactly as before.
An empty input yields `""`.

## Implementation notes

- Only `__kml_atob` changed; `__kml_btoa`/`__kml_base64_encode_bytes` are
  untouched.
- The character-validity loop still treats `=` as valid anywhere, so an
  interior/excess `=` is tolerated (decoded as alphabet index 0) rather than
  rejected. This is a pre-existing leniency, unrelated to the whitespace/
  padding fix, and is disclosed as the row's remaining caveat.

## Side effects discovered

None. `atob("we go!")` still throws (whitespace stripped → `wego!`, the `!` is
invalid), so the existing invalid-character test is unaffected.

## Verification

`TestE2EAtobForgivingBase64` (internal whitespace, unpadded 7-/3-char inputs,
empty input, and the `"a"` length-1 throw) plus the existing btoa/atob and
invalid-character tests pass. Built and verified on Mac (Apple Silicon).
