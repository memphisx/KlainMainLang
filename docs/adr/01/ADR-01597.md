# ADR-01597: Windows links: runtime dependencies, comdats and lld

- **Relations**: Implements TDD-00251 (Stages 2–3, partly 4), Extends ADR-01476, ADR-01327
- **Date**: 2026-10-13

## Context

The Windows CI job failed at `go vet` (`syscall.SIGUSR2` in a test shared
with POSIX), and behind it the whole suite: after the compiler restructure a
Windows program barely linked. A full run of the E2E suite reported 2,543
failing tests out of 4,146, almost all at the link.

## Investigation

- **Weak and linkonce definitions.** mingw lowers a `weak`/`linkonce`
  definition without a comdat to a COFF weak external. GNU ld does not
  resolve another object's reference to it, and libsplit's copies in each
  unit collide as `.weak.*` multiple definitions.
- **Dead references.** ADR-01476 links one cached object per runtime file
  and relies on section garbage collection to drop what a program does not
  reach. COFF linkers (GNU ld and lld) resolve every symbol of every loaded
  object first, and mingw's script keeps every `.pdata`/`.xdata`, so an
  unreached call into a runtime file the program did not link fails. The
  per-symbol inventory (`tools/testsel/undefrefs.py` over the run's log) is in
  TDD-00251: `process.c`→heap shim (1,226 links), `shape.c`→`dynarr.c`,
  the pool→`osinfo.c`, `fetch.c`→its async runtime, `native.c`→the fs-error
  runtime, `exceptions.c`→the Worker hook.
- **The shim's own libc names.** `win32fs.c` defines `strerror` and
  `win32io.c` the Winsock calls (`getaddrinfo`, `inet_ntop`, …). A runtime
  file compiled against the system headers calls those through their import
  slot (`__imp_strerror`), which pulls the CRT or ws2_32 import member and
  its own definition: a duplicate symbol under lld, a missing `-lws2_32`
  under GNU ld.
- **Section numbers.** A program with a 20,000-row literal table emits about
  40,000 sections (each string literal is `linkonce_odr`, so a comdat). GNU
  ld's COFF reader takes a section number as a signed 16-bit value and loses
  every symbol in a section past 32,767 (`nm` shows them undefined; the same
  object links with lld). LLVM switches to big-object COFF only past 65,279.
- **Command length.** A link with every runtime object passes Windows' 32 K
  command-line limit.

## Decision

- `coffWeakComdats` (`coff_comdat.go`) gives every weak or linkonce
  definition in a Windows module its own comdat (`$name = comdat any`), run
  on the program module and on each libsplit unit. It is idempotent and adds
  a declaration a copied definition lacks.
- `ensureRuntimeDeps` (`runtime_deps.go`) links the runtime files a linked
  runtime file calls, to a fixed point, before the finalize steps and again
  after them (a finalize step can link a runtime file first). The process
  lifecycle runtime re-checks the same way (`emitProcessLifecycleRuntime` is
  idempotent). `__kml_wait_outside_coroutine` becomes a static copy in each
  file that waits (`fetch.c`, `task.c`) instead of a `loop.c` export.
  `exceptions.c` names `__kml_worker_uncaught` only when built for Workers.
- The shim defines the import slots for the names it owns
  (`__imp_strerror`, `__imp_getaddrinfo`, `__imp_freeaddrinfo`,
  `__imp_inet_ntop`, `__imp_inet_pton`, `__imp_gethostname`,
  `__imp_getnameinfo`), so a dllimport call resolves to the shim and the
  import member is never pulled. `kml_posix_compat.h` declares the address
  converters when only `winsock2.h` came in.
- Windows links with lld when it is installed (`-fuse-ld=lld`), GNU ld
  otherwise. `UnreachableRefFlags` passes nothing there: lld has no
  `--unresolved-symbols`, and the runtime no longer leaves an unreachable
  reference. `DeadStripFlags` uses `--gc-sections` (the MSVC `/OPT:REF` it
  passed was never a GNU ld or lld MinGW flag).
- `Toolchain.Command` writes an argv past 32,000 characters to a response
  file (`%TEMP%\klainmain-rsp\<sha256>.rsp`, `--rsp-quoting=windows`).
- Layout constants in `kml_layout.h` are `#ifndef`-guarded; a few C
  prototypes take `__SIZE_TYPE__` (`unsigned long` is 32-bit on Windows).

## Implementation notes

`coffWeakComdats` matches a string constant's trailing `, align N` only, so
a literal holding that text is untouched. The second `ensureRuntimeDeps`
pass runs after `emitBoxedBigIntHooksFinalize`; every dependency it can add
only declares functions or links a C file, so no row registration is missed.
The response file's name is its content hash, so parallel links share it.

## Side effects discovered

- The new libuv runtime's Windows paths had compile errors that the link
  failures hid: `http2.c` redeclared `swapcontext`, `klainzlib.c`'s
  `zlib.h` pulled `unistd.h`/`io.h` declarations clashing with the shim's,
  and `tlshandle.c` lacked `inet_ntop`. Fixed here.
- A program-level function named like a libc symbol (`function read()`)
  collides with the shim in the test harness's resolver-less build path
  (`buildBinary`), which leaves top-level names unmangled; the CLI mangles
  them. `buildBinary` now resolves the program as the CLI does (it keeps
  the test-mode environment the mode lanes set).

## Verification

Windows 11 (MSYS2 UCRT64 clang): the full E2E suite through
`tools/testshard` went from 2,543 failures to 28, then to the residue
listed in ADR-01599. `go test ./codegen/...` passes. The 20,000-row table
test links and runs with lld. Linux and macOS are not yet verified for the
shared changes (Docker run owed).
