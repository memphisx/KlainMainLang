# ADR-00633: Node-faithful HTTP `'upgrade'` event and `wss://` server

- **Relations**: `Implements TDD-00158` (Stage 1), `Extends ADR-00111` (HTTPS/1.1 server), `Extends ADR-00126` (WS server handshake)
- **Date**: 2026-09-02

## Context

The last open gap in the WebSocket row was the **server side of `wss://`**:
the client spoke `wss://` (TDD-00039 Stage 4), but the server was `ws://`
only. TDD-00039 had deferred a server TLS story ("same as `https://` doesn't
exist for `http.listen`"), a premise since invalidated by `https.createServer`
(TDD-00111), which brought a full server-side TLS accept path, an fd→`SSL*`
table, and TLS-aware connection I/O shims. Under the project's
faithful-under-Node-namespaces rule, the fix is not a bespoke `wss` entry
point but Node core's real mechanism: the HTTP server's `'upgrade'` event
(`server.on('upgrade', (req, socket, head) => …)`), over which the `ws`
package builds its server in Node.

## Investigation

The connection dispatcher (`buildHTTPDispatcher`, emit_http.go) is a
per-connection fiber. At its header-parse seam it holds the parsed headers,
the fd (32/64-bit), the request line, the leftover read buffer (the `head`
bytes), and the compile-time `usedHTTPS1Server` TLS flag. A `net.Socket`
object type already existed (`NetSocketType`/`netSocketIR`) with
`.write`/`.end`/`.destroy`/`.on('data'|'end'|'close')` wired and an `SSL*`
slot (field 5); `__kml_net_sock_write` already routes through `__kml_tls_write`
when that slot is set. The only missing glue: constructing a `net.Socket`
from an accepted HTTP-fiber fd and driving its `'data'` events from that
fiber (the `net` module's own select loop doesn't own this fd).

## Decision

Add `'upgrade'` to the server `.on` event set (emit_http.go), storing the
handler in `@__kml_listen_upgrade_handler`. A whole-program pre-scan
(`programUsesHTTPUpgrade`, a recursive walk — `.on('upgrade')` can nest
anywhere and a miss would silently drop the handler) sets `e.usedHTTPUpgrade`,
gating the dispatcher's upgrade block; the registration site carries a
compile-error safety net if the pre-scan ever misses it.

At the seam, when a handler is registered and the request is an upgrade (a
protocol-agnostic `Upgrade:` + `Connection: upgrade` check — Node fires
`'upgrade'` for any upgrade, not just websocket), build:
- **`req`** — an `HttpRequest`/`IncomingMessage` from the parsed headers +
  method + path;
- **`socket`** — a `net.Socket` over the fd, with field-5 `SSL*` set to
  `__kml_http_conn_ssl_get(fd)` when `usedHTTPS1Server` (so `.write` routes
  through SSL automatically — this is the whole of `wss://`);
- **`head`** — a `Buffer` of the bytes already read past the header
  terminator.

Invoke the handler, then run a generic raw read loop on the fiber (the exact
`swapcontext`-yield-on-EAGAIN structure the WS loop uses, minus frame
decoding): read via `__kml_http_conn_recv` (TLS-aware) when `usedHTTPS1Server`
else raw `read`, fire the socket's `'data'` listener with each chunk as a
`Buffer`, and on EOF/error fire `'end'` then `'close'` before teardown.

## Implementation notes

- New file emit_http_upgrade.go: the pre-scan walker, `emitUpgradeReqDetect`,
  `emitHTTPUpgradeBlock`, `emitHTTPRawSocketLoop`, `emitFireSocketVoidListener`.
- `ensureNetRuntime()` is called from the upgrade block: the socket's
  `.write`/`.end`/`.on` runtime helpers are normally pulled in by a `net.*`
  call, which an upgrade socket never makes.
- The `(req, socket, head)` params are contextually typed via
  `resolveCallbackWithHints` (ADR-00632).

## Side effects discovered

`'echo:' + buffer` renders a `Buffer` as comma-separated byte values rather
than Node's utf8 decode — a pre-existing Buffer-string-concat fidelity gap,
independent of this work; `.toString()` is the idiom used in the examples.
Not fixed here.

## Verification

- Mac (Apple Silicon): `go build`, `go vet` clean. New E2E tests
  `TestE2EHTTPUpgradeEventEcho`, `TestE2EHTTPUpgradeCoexistsWithNormalHTTP`,
  and `TestE2EHTTPSUpgradeEventEchoTLS` (a raw upgrade echo over TLS, driven
  by a Go `tls.Dial` client) all green; broad HTTP/net/TLS/WS suites green.
- **Linux verified** (Debian/glibc/arm64, Docker `golang:latest` + clang 19 +
  `libssl-dev`/`libcurl4-openssl-dev`/`libnghttp2-dev`): the raw-upgrade
  echo over TLS (`TestE2EHTTPSUpgradeEventEchoTLS`) and the plain-upgrade
  tests pass — the server-accepted `SSL*` reuse through `net.Socket.write`
  works on OpenSSL/Linux, not just macOS.
