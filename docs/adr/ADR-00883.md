# ADR-00883: String/Number methods reject a non-numeric index/count argument cleanly

- **Relations**: `Extends ADR-00882`
- **Date**: 2026-09-11

## Context

Continuation of the A1 invalid-IR sweep (BACKLOG §4, memory "Invalid-IR backlog
histogram"). After DataView (ADR-00882), the String sub-family was the next A1
cluster: a non-numeric argument to a string/number method that expects a numeric
index/count/position reached arithmetic uncoerced and emitted invalid IR.

Repro (macOS arm64):

```ts
"hello".charAt(Symbol("x"));
// before: clang error — '%t3' defined with type 'ptr' but expected 'i64'
//         at `icmp sge i64 %t3, 0`
```

The Test262 files are the `charAt`/`charCodeAt`/`repeat`/… `*-symbol` and
`return-abrupt-from-tonumber-*` families: they pass a `Symbol` where a numeric
argument is expected and assert the runtime `TypeError` from `ToNumber(symbol)`.

## Investigation

~20 string/number method emitters in `emit_strings.go` coerced their numeric
argument with bare `e.coerce(v, TypeI64/F64)`. As diagnosed in ADR-00882, for a
non-numeric `ptr` value (a `Symbol`) `coerce` hits its "return unchanged"
fallthrough and yields a value *typed* i64 whose register is still the `ptr` —
which then flows into `add`/`icmp`/`trunc`/`mul` as invalid IR.

`coerceChecked`/`coerciblePure` (`emit_exprs_coerce.go`) is the right tool: it
returns a clean, context-named compile error when the coercion isn't sound. The
rejection is the faithful behavior for a typed subset — `tsc` itself rejects
`"x".charAt(sym)` ("Argument of type 'symbol' is not assignable to parameter of
type 'number'").

Two sites were already correct and left unchanged: `String.fromCharCode`
(already guards with `isNumberTy`, ADR-00195) and the *receiver* coercions in
`toString(radix)`/`toFixed` (the number itself, gated by numeric dispatch).

## Decision

Added a thin helper `coerceNumArgRef(v, target, pos, what)` (coerceChecked +
`.Ref`) and converted every numeric-*argument* site to it (or to `coerceChecked`
where a `Value` is needed): slice/substring/substr indices, indexOf/lastIndexOf/
includes/startsWith/endsWith positions, charAt/charCodeAt/codePointAt/at indices,
bracket-index `s[i]`, split limit, repeat count, pad target length, and the
Number formatters toFixed/toExponential/toPrecision digits and toString radix.
Each names its context in the error (e.g. "charAt index", "repeat count").

## Implementation notes

- `codegen/llvm/emit_strings.go` only; helper added near the top.
- Receiver coercions and the already-`isNumberTy`-guarded fromCharCode path are
  intentionally untouched.

## Side effects discovered

`built-ins/String/prototype/{padStart,indexOf}` each retain one CLANG_ERROR from
a *different* root cause — `integer constant must have integer type`, a
non-string fill/search argument (object→ToPrimitive constant), not the numeric
coercion pattern. Tracked as separate A-cluster work.

## Verification

- Per-method repros now reject cleanly (charAt/charCodeAt/codePointAt/slice/
  substring/substr/indexOf/includes/startsWith/repeat/at/padStart/toFixed/
  toExponential/toPrecision/toString all verified).
- Focused conformance sample (macOS arm64, lane=strict, isolated `-workdir`,
  reduced workers to avoid contending with an in-progress full run):
  `built-ins/String/prototype/{charCodeAt,charAt,repeat,at,includes,slice,
  substring}` → **0 CLANG_ERROR**; padStart/indexOf → 1 each (the unrelated
  ToPrimitive-constant bug above).
- New E2E `TestE2EStringNonNumericArgRejected`; a broad positive
  string/number-method program and `TestE2E(String|Number)` suite stay green.
- `go build`, `go vet ./...` — clean. Full Test262 not re-run here (a
  conformance run was in progress; isolated-only rule).
