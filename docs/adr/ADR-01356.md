# ADR-01356: A statement after a terminator opens an unreachable block

- **Relations**: Refines the dead-code drop (`emitTerminator`/`emitLabel`)
- **Date**: 2026-10-03

## Context

Under `-compat=js`, this program made clang reject the IR with "use of
undefined value":

```ts
const dv = new DataView(new ArrayBuffer(8), Symbol("x"));
console.log(dv);
```

Node throws `TypeError: Cannot convert a Symbol value to a number`.

## Investigation

- Converting the Symbol to a number is a compile-time-known throw, so the
  first statement ends in `unreachable`.
- The emitter drops instructions after a terminator until the next label.
  That is how code after `return`/`break` disappears.
- `console.log(dv)` loaded `dv` (dropped), then opened labels of its own,
  `extra.dyn`/`extra.static`. Their instructions survived and used the
  dropped load.
- Any statement that computes a value before opening a block can hit this
  after an unconditional throw.

## Decision

`emitStmt` opens a fresh label when it starts after a terminator. The
statement is emitted whole into a block with no predecessor. That is valid
IR, and clang deletes it. The drop still covers expressions within a
statement.

`codegen/llvm/emit_stmts.go`.

## Verification

Mac (Apple Silicon): the program compiles under `-compat=js` and throws
Node's TypeError. Full gates: test-par on Node304 and examples on DeskMini.
