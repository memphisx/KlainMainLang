# ADR-00895: Nullable-scalar truthiness in a boolean context

- **Date**: 2026-09-12

## Context

Part of the ongoing invalid-IR (Test262 `CLANG_ERROR`) sweep. An optional chain
whose result is a scalar `T | undefined` — the `{ i1 present, T }` nullable-
scalar aggregate — used directly as a boolean condition emitted invalid LLVM IR:

```ts
const obj: { a: boolean } | null = { a: true };
while (obj?.a) { /* … */ }        // clang: '%t13' defined with type '{ i1, i1 }' but expected 'i1'
```

The two Test262 files `language/expressions/optional-chaining/iteration-statement-{while,do}.js`
died this way, with a `br i1 %agg` branching on the raw `{ i1, i1 }` aggregate.

## Investigation

The `while`/`do`/`if` condition paths already route the test value through
`toBool` (`emit_stmts.go:462`). `toBool` (`emit_exprs_types.go`) opens with a
fast path `if v.Ty.IR == "i1" { return v }`. A nullable **bool** reports payload
IR `"i1"` (`undefinedableElem` sets `Nullable`/`IsUndefined` but leaves
`IR == "i1"`), so this fast path fired and returned the whole `{ i1, i1 }`
aggregate register unchanged — where an `i1` was required. The value's static
type *is* a nullable scalar (`isNullableScalar` true), but the check that would
have handled it sat *after* the `i1` fast path.

## Decision

Add a nullable-scalar branch to `toBool` **before** the `IR == "i1"` fast path.
A nullable scalar's truthiness is the JS `ToBoolean` of a `T | undefined`:
`present && ToBoolean(payload)` — an absent value is `undefined`, hence falsy.
The branch extracts the presence bit and payload via `nullableScalarAggParts`,
recurses `toBool` on the bare payload, and `and`s the two i1s.

## Implementation notes

- Ordering is the whole fix: the new branch must precede `if v.Ty.IR == "i1"`,
  since a nullable bool's payload IR collides with the fast path.
- Reuses `nullableScalarAggParts` (presence + bare payload) and recurses so the
  payload's own truthiness rule (string/float/int/etc.) still applies.

## Side effects discovered

None. The change is confined to `toBool`; every non-nullable value still takes
its existing branch.

## Verification

- `TestE2EOptionalChainTruthyInLoopCondition` (new): `while (obj?.a)` counts once
  and a null `maybe?.flag` is falsy.
- Both Test262 files now emit valid IR; the `while` case runs to exit 0.
- `make examples` 296/296; nullable-scalar / optional-chaining E2E suites green.
