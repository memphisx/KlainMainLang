# ADR-01932: Equality, the key lists, Object.entries, the sort comparators and the Symbol registry leave IR text

- **Relations**: Implements TDD-00240, Implements TDD-00230
- **Date**: 2026-10-28

## Context

TDD-00230 Phase 4 moves the runtime written as LLVM IR in Go string literals into C (TDD-00240). `TestIRTextOnlyShrinks` counted 137 such definitions across 54 files. This batch takes the ones whose port needs no new runtime structure.

## Investigation

The definitions fall into three groups:

- **Routines with a body**: `__kml_any_eq` (`===` on boxes), `__kml_Object_is`, `__kml_closure_free`, `__kml_dynobj_entries` (`Object.values`/`entries` of a dynamic object), the float sort comparator, and `Symbol.for`/`Symbol.keyFor` over their registry.
- **ABI wrappers**: a C routine fills an out-parameter because a large aggregate return differs between the C and IR ABIs (Windows above all), and an IR function rebuilds the aggregate. These are `__kml_date_decompose`, `__kml_dynobj_keys`/`keys_enum`, `__kml_await_fetch` and `__kml_await_fetch_settled`, plus the two `pending_finish` wrappers that nothing calls. The Map and Set `keys`/`vals` copies were the same shape.
- **A copy of an existing builder function**: `__kml_any_to_cstr` rendered a box as `String(x)` does, a second copy of the shared `__kml_dynrender_s`.

## Decision

- **Routines move to C**, each into the unit whose data it uses:
  - `__kml_any_eq` and `__kml_Object_is` go to `boxsrc/strict_eq.c`, linked when the program uses strict equality on boxes. `hooks.c` no longer trampolines `any_eq`: the C callers (`loose_eq.c`, `collections_any.c`) already pull in the strict-equality unit.
  - `__kml_closure_free` goes to `coresrc/core.c` and frees through `kml_heap.h`.
  - `__kml_dynobj_entries` goes to a unit of its own (`dynobjsrc/dynentries.c`), since it needs both the dynamic object and the dynamic array, and neither of those implies the other.
  - The float comparator goes to `dtoasrc/dtoa.c`, beside the formatter it calls.
  - The Symbol registry goes to `collectionssrc/collections.c`, beside the string map it is, and is thread-local, since each Worker is its own realm.
- **The wrappers become call-site code.** `emitOutAggCall` allocates the out-parameter in the entry block, calls the C routine and loads the aggregate. `emitKeyListCall` builds the `{ptr, i64}` from a `char **f(void *, i64 *n)` key list, for the dynamic object's own, enumerable and `for...in` keys. `emitMapCopy` builds a Map's or Set's keys or values from its size word and `__kml_map_copy_*`.
- **The `any[]` default sort comparator is a builder function** calling the shared `String()` render, and `__kml_any_to_cstr` is deleted.

## Implementation notes

- The C side reads a Symbol as `{ type-id word, description }`. `ensureSymbolRegistry` panics if `SymbolType` stops being 16 bytes.
- `KML_SYMBOL_TYPEID` and the host-box flags reach the C as defines generated from the Go constants.

## Verification

- Probes against Node (strict equality and SameValue over numbers, strings, arrays, functions, bigints and collections; key lists and entries; default sorts; the Symbol registry) all match.
- `codegen/llvm` units, and the equality, dynamic-object, collection, Symbol, sort, Date and memory E2E suites, pass on the Mac (Apple Silicon).
