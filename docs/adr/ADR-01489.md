# ADR-01489: `arguments` counts the arguments a call passed

- **Relations**: Extends ADR-00387, TDD-00210
- **Date**: 2026-10-09

## Context

`arguments` held every declared parameter plus the overflow, so
`f(1, 2)` of `function f(a, b?, c?)` read `arguments.length` as 3. A
call fills an omitted optional parameter with its zero or undefined, so
the callee could not tell an omitted parameter from a passed one.

## Investigation

- Module code is strict, and strict code's `arguments` is unmapped: a
  snapshot of the values passed. Only the count was missing.
- Packing every argument into the hidden rest at the call would evaluate
  the regular arguments twice.
- Class methods and constructors never had the hidden rest. Adding one
  would change an override's ABI, and an override is called through its
  base's signature.
- A named function used as a value is called through a forwarding
  trampoline, whose type did not say the function reads `arguments`.

## Decision

- A thread-local count, `@__kml_argc`, says how many declared parameters
  a call passes. The caller stores it just before the call. The callee
  reads it at entry and resets it to -1, which means "unknown, count
  every declared parameter". `arguments.length` is that count plus the
  overflow.
- Calls to a function that reads `arguments` store it. These are named
  calls, closure calls (`FuncCountsArgs` on a named function's value
  type), and, when any class member reads `arguments`, every method,
  constructor and `super(...)` call. Programs that never read
  `arguments` store nothing.
- A spread among the regular arguments stores nothing (tsc rejects one,
  TS2556).
