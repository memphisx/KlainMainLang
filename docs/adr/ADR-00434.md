# ADR-00434: the Node crypto module — generateKeyPair(Sync), randomBytes

- **Relations**: Extends [TDD-00104](../tdd/TDD-00104.md)'s keygen ABI ([ADR-00317](ADR-00317.md) line), [ADR-00370](ADR-00370.md) (mustCall ABI)
- **Date**: 2026-08-28

## Context

`crypto.generateKeyPair` was a 13-file member gap. The corpus imports it
from the Node `crypto` *module* (`const { generateKeyPair } =
require('crypto')`), which didn't exist as an importable module at all —
only the ambient WebCrypto global (`crypto.subtle`, `getRandomValues`,
`randomUUID`). Both keygen backends (OpenSSL `EVP_PKEY_Q_keygen`,
CommonCrypto `SecKey`) already produce PKCS#8/SPKI DER for
`crypto.subtle.generateKey`.

## Decision

- `crypto` becomes a virtual module (`nodecrypto__kml_builtin`)
  exporting `generateKeyPair`/`generateKeyPairSync`/`randomBytes` plus
  re-exports of `randomUUID`/`getRandomValues` (same emitters as the
  global).
- `generateKeyPair('rsa'|'ec', options, cb)` / `…Sync`: V1 requires both
  `publicKeyEncoding: { type: 'spki', format: 'pem' }` and
  `privateKeyEncoding: { type: 'pkcs8', format: 'pem' }` — KeyObject
  results, `pkcs1`/`sec1`/`der`, and `cipher`/`passphrase` are clean
  rejections. `rsa` takes `modulusLength` (+ the 65537-only
  `publicExponent`); `ec` takes `namedCurve` P-256/384/521. Generation
  is synchronous; the async form fires its callback inline (fs's
  async-shaped posture). The callback may be `(err, publicKey,
  privateKey)` or the 2-param `mustSucceed((publicKey, privateKey))`
  shape — arity-dispatched, with matching contextual typing.
- PEM assembly is a new bufcodecs helper `__kml_pem_from_der` (base64 in
  64-char lines between BEGIN/END markers — Node's own shape), so both
  crypto backends share it.
- `crypto.randomBytes(size)` returns a CSPRNG-filled Buffer (the
  callback form is a clean rejection).
- The `mustCall` counting-trampoline arity cap rose 2→3 (the trampoline
  was already signature-parametric) — Node's `(err, a, b)` callbacks fit.

## Implementation notes

`emit_nodecrypto.go` (new), `buffersrc/buffer_codecs.c` (PEM),
`resolver/virtual_modules.go` (module + members), `emit_call.go`
dispatch, `emit_exprs_types.go` inference, `emit_testmod.go` (arity 3).

## Side effects discovered

- A file that namespace-imports crypto and then uses `crypto.subtle`
  would hit the marker, which only covers the five members — WebCrypto
  via the *module* binding stays unsupported (the ambient global is the
  route); surfaced as a clean rejection.

## Verification

`TestE2ENodeCryptoGenerateKeyPair` (sync EC pair, async RSA-2048 with
(err, pub, priv), mustSucceed EC P-384, randomBytes length — PEM
markers asserted); webcrypto/subtle/buffer-codec/mustCall suites green
(Mac).
