# ADR-01857: A nested class reads its outer class's private field; a block class's class-valued field

- **Relations**: `Implements TDD-00230` (P3.3: found while answering the shadow report's NewExpression bucket)
- **Date**: 2026-10-21

## Context

- A private name resolves lexically: in `class C { #outer; B = class { method(o) { return o.#outer; } } }` the `#outer` inside B is C's, and `o` must carry C's brand.
- Codegen resolved the read against the innermost class only. Under `-compat=js`, where `o` is untyped, the read became a dynamic property get of the name `#outer`, which no object's dynamic shape holds: `b.method(c)` printed `undefined` where Node prints `test262`, and an object without the brand read `undefined` where Node throws "Cannot read private member #outer from an object whose class did not declare it". Test262's `private-field-on-nested-class.js` exercises it.

- A class declared in a block or function whose field holds a class expression (`function f() { class C { B = class {} } }`) laid the field out as a number: the block class is hoisted before the class expression in its own body, so when C registered, its field's initializer named a class not registered yet and fell to the default. `new c.B()` threw "c.B is not a constructor" in both lanes.

- The checker typed `new c.B()` as `any`. The parser keeps `new o.C()` as a qualified name; the binder resolved the bare `C` (a same-named declaration elsewhere would have been taken instead), the resolver renamed the qualifier but not its path, and a class-valued field's type was computed lazily, after hoisting had replaced its class expression with a reference the binder never saw.

## Decision

- `outerPrivateReads`, before class expressions are hoisted (while a nested class still sits in its outer one), rewrites a read `o.#p` in a class that does not declare `#p`, where an enclosing named class D declares it as an instance field, to the `kml.privateGet(o, D, "#p")` intrinsic: a brand check (`instanceof` under `brandOnly`, as `kml.privateIn` checks) with V8's TypeError, then the field read through D's layout. Writes, updates and private method calls keep their members.
- The checker is bound before the rewrite and keeps its answer for each read; the call is linked to the read it stands for (ADR-01856's `warmFront`/`originate`).

- Hoisting renames D's references with the rest of D's body, so an outer class that is itself hoisted is reached under its new name.
- `fieldDepsFirst` orders the hoisted classes so that each comes after every hoisted class its field initializers or `extends` name, keeping the source order otherwise.
- The binder binds a `new o.p.C()` whose root `o` is a variable as the member expression `o.p.C` (`QualifiedCallee`), which the checker constructs through; the resolver renames a one-segment qualifier path with its qualifier. Hoisting registers each class expression's reference with the checker (`StandsFor`), which types the reference as the expression it replaced, so a type computed after hoisting (a class-valued field, a parameter whose default is a class, Test262's `ary-ptrn-elem-id-init-fn-name-class` family) still reads the class.

## Consequences

- `TestE2ENestedClassReadsOuterPrivate` matches Node in both lanes, the brand failures, a function-local outer class and a block class's class-valued field included. An anonymous outer class (`return class { #p; … }`) has no name to brand against yet and keeps the old dynamic read.
- `TestQualifiedNewThroughVariable` covers the checker; the shadow report's NewExpression bucket (176 rows) is answered.
- Verified on Apple Silicon.
