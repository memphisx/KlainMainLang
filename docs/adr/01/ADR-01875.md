# ADR-01875: Optional tuple elements and a generator's pattern parameters

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's CallExpression bucket)
- **Date**: 2026-10-21

## Context

- tsc types an unannotated pattern parameter by its implied type: an element with a default may be undefined, and the trailing ones are optional (`[[x, y, z] = [4, 5, 6]]` is `[([number, number, number] | undefined)?]`); a pattern typing an empty `[]` default makes every element optional. The checker had no optional tuple elements, so the parameter was `[[number, number, number]]`, which `method([])` does not satisfy. A pattern parameter with no default, contextual type or annotation typed each leaf any instead of from its own default.
- Codegen rewrites a generator's destructured parameters in place (desugarGeneratorPatternParams) before the lazy checker had typed the generator, so a later read of the method (`this.#method` in Test262's `async-private-gen-meth` family, about 380 shadow rows) saw a parameter with no type and was unanswered.

## Decision

- A tuple type carries its count of trailing optional elements, each holding undefined. It prints as tsc does (`[(T | undefined)?]`, with its labels when written with them), relates by length range, and has a union of literals as `length`. Instantiation, mapped types, rest slices and contextual typing keep the count. The implied pattern type uses it, and a leaf of an undefaulted, unannotated pattern parameter is its implied type's (any when that says nothing, a computed key's or a rest's).
- A nested pattern's default drops undefined from what it destructures.
- Before the rewrite, codegen has the checker type the generator's declaration, its parameter leaves and its class (WarmDecl).
- An annotated optional element (`[T?]`, `[a?: T]`) is read the same way; a rest parameter of such a tuple takes optional parameters. `[]` against a tuple that requires an element is TS2322.
- The shadow mapper holds a tuple with an optional element as an array of boxes, as codegen converts the annotation (variableTupleElement).

## Consequences

- `TestPatternParameterFromDefault` and `TestOptionalTupleAnnotation` hold tsc 5.6's output. A labelled tuple keeps its labels, printed as tsc prints them (`[x: number, y?: string | undefined]`).
- Verified on Apple Silicon.
