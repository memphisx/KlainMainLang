# ADR-00389: `typeof` type queries

- **Date**: 2026-08-27

## Context

A `typeof value` type query (`type Config = typeof config`, `let x: typeof base`,
`function f(s: typeof settings)`) was a parse error (`expected type name, got
typeof`). It is a common way to derive a type from an existing value without
restating its shape.

## Decision

Parse `typeof <ident>(.<ident>)*` in type position into a `TypeAnnotation` marked
`IsTypeof` (with `TypeofName` and a `TypeofPath` for member segments), and
resolve it in `resolveType` to the referenced value's type, walking any member
path.

`resolveValueType(name)` finds the value's type in a pass-stable way:

1. **The value's top-level declaration in the program AST first** — its
   annotation, else its inferred initializer type (a `const`/`let`/`var`, or a
   `function` declaration's function type). This is checked before value scope so
   the query resolves identically whether it runs at eager type-alias
   registration (before scope exists) or at emit time; a promoted global's stored
   handle type can differ from its structural shape, which would otherwise desync
   the two passes.
2. Otherwise an in-scope local/parameter, then a module global, then a top-level
   function.

The AST is retained on the emitter (`e.prog`, set at `EmitProgram` start) for
step 1.

## Implementation notes

- Top-level names carry the resolver's per-file `__kml_mod<N>` mangling suffix
  while a `typeof` query keeps the source name — the prog-scan compares against
  the unmangled declaration name (the same `strings.LastIndex(name, "__kml_mod")`
  idiom used elsewhere).
- `resolveType` has no error channel, so an unresolvable query falls back to the
  number default rather than failing.
- The rare case of a function-local shadowing a top-level binding of the same
  name is not distinguished (the top-level wins); `typeof` of a shadowed name is
  uncommon.

## Side effects discovered

None — `IsTypeof` is handled at the top of `resolveType`, ahead of every other
annotation shape, so no existing path changes.
