# ADR-01164: Typed arrays, `ArrayBuffer`, `DataView` and `Buffer` declared; an interface's own member overrides its base's

- **Relations**: `Implements TDD-00230` (P3.1); `Extends ADR-01163`, `ADR-01132`
- **Date**: 2026-09-25

## Context

`Buffer` was declared as a type with two members and no constructor, and
the typed arrays and `ArrayBuffer` not at all, so the checker left every
`Buffer.from(…)`, `new Uint8Array(…)` and their methods unanswered. They are
the data types of the stream, fs and HTTP surfaces now being declared.

## Decision

- **`lib/es.d.ts`** gains, copied from TypeScript's own library:
  `ArrayLike`, `ArrayBuffer` and its constructor (with the es2017 and
  es2024 constructor merges), `ArrayBufferView`, `SharedArrayBuffer` (a
  type), and the eleven typed arrays with their constructors, from
  `lib.es5.d.ts` and `lib.es2020.bigint.d.ts` and their later members
  (es2015 core, iterable and well-known symbols, es2016 `includes`,
  es2017's no-argument constructor, es2022 `at`, es2023's copying
  methods), and `DataView` (es5, with es2020's bigint accessors).
  `ArrayBufferLike` is written as the union
  `ArrayBufferTypes[keyof ArrayBufferTypes]` evaluates to.
- **`lib/node.d.ts`** declares `Buffer<TArrayBuffer>` as `@types/node` does
  (extending `Uint8Array<TArrayBuffer>`, every member), `BufferConstructor`
  and `declare var Buffer`, `NonSharedBuffer`/`AllowSharedBuffer`, and
  `NodeJS.TypedArray`/`NodeJS.ArrayBufferView` (a typed array or a
  `DataView`). `Buffer.from`'s overloads
  take plain `ArrayLike<number>`, `ArrayBufferLike` and `string`
  arguments: `@types/node` wraps them in `WithImplicitCoercion` and
  `ImplicitArrayBuffer`, conditional types the checker does not model, and
  one unanswered overload leaves a whole set unanswered (ADR-01148).
- **Checker: an interface's own member overrides its base's.** Building an
  interface copied the base's members first, and an own method signature of
  the same name was then merged with the base's as one overload set:
  `Buffer.slice` became `Uint8Array.slice`'s overloads plus Buffer's, and
  `buf.slice(0, 2).toString("hex")` was typed through `Uint8Array.toString()`
  (TS2554). Only an interface's own declarations of a name merge now; an
  own member replaces an inherited one, as in tsc.
- **Codegen: an encoding through `as`.** A Buffer encoding may be written
  `'UCS-2' as BufferEncoding` (tsc rejects the bare `'UCS-2'`): the codec
  is read through the type assertion (`stringLiteralThrough`).

## Side effects discovered

- Three E2E programs were JavaScript tsc rejects: `Buffer.from(s,
  'UCS-2')`, and `ta.set(null)` / `ta.set("12x")` / an array-like of mixed
  element types into a typed array's `set`. Each now states its `any` or
  `BufferEncoding` with `as`, which is what the tests are about; so does
  `examples/dynamic/any_arrays_symbols.ts`. `apps/files` returned a
  Buffer's slice as a `string` preview: it reads the file as utf8.
- `TestE2EDataViewNonNumericRejected` now sees the checker's TS2345 for a
  `DataView` method; the constructor's generic buffer constraint (an
  intersection) leaves its call to code generation's rejection.

## Verification

- **tools/libconform:** 0 divergences not allowlisted.
- **tsdiag, TS 7.0.2 corpus:** 3,157 diagnostics, 0 false positives; the
  first draft's 36 (the later `toLocaleString(locales, options)` and
  no-argument constructor forms) are the merges above.
- **Checker:** `const b: number = Buffer.from('x')` is tsc's "type
  'Buffer<ArrayBuffer>' is not assignable to type 'number'".
- **Tests:** the Buffer, typed-array, ArrayBuffer and Atomics groups pass;
  the stream programs (ADR-01161) still match Node.
