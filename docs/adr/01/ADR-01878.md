# ADR-01878: A guarded string local reads present after an index store

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's Identifier Absent bucket)
- **Date**: 2026-10-21

## Context

- Codegen reads a `string | undefined` local as the bare string only when every path stores a value that is never absent. A local whose last store is an index read that may miss (`binding = resolveMap[rrtype]`) stayed absent-flavoured even inside `if (binding !== undefined)`, where the checker, as tsc, narrows it to `string`. The shadow oracle answered `string`.

## Decision

- The binder answers `GuardedSinceStore`: every path back from a read meets a condition excluding undefined on the local (`x`, `x !== undefined`, `x != null`, a typeof test other than `"undefined"`; `!x`, `x === undefined`, `x == null` on the false branch) before any store to it. Inner block entries are walked through; the local's own scope entry ends a path unguarded.
- `assignedString` accepts such a read, for codegen's inference and emission alike; the shadow oracle mirrors it.
- The oracle's present-store rule also requires every store to be held present (reprStoresPresent): `const e = d.publicExponent as bigint` is erased and stays absent-flavoured, so `e.toString()` throws TypeError on a miss as in Node. A store reading the binding itself (`n = n + 1`) answers not present on that path, as the emitter's busy set does, rather than asking again.

## Consequences

- `TestE2EGuardedStringSinceStore` (the guard over an index store, typeof, and an unguarded miss staying undefined) matches Node. The dns resolver's `resolve` leaves the shadow report.
- Verified on Apple Silicon.
