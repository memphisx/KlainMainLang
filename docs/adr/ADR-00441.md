# ADR-00441: klain:webview Stage 5 — typed bind + the `bindings` object

- **Relations**: Implements [TDD-00142](../tdd/TDD-00142.md); Extends [ADR-00438](ADR-00438.md), [ADR-00439](ADR-00439.md), [ADR-00224](ADR-00224.md)
- **Date**: 2026-08-28

## Context

`bind` (Stage 2) is a raw string-JSON-in / string-JSON-out contract: the callback
gets the page's whole argument list as one JSON string and returns a JSON string.
Stage 5 adds **typed bind** — auto-decode the page's arguments into the callback's
declared parameter types and JSON-encode the return — and a declarative
**`bindings` object** on the constructor whose keys become the `window.*` names
(the explicit-allowlist surface, the answer to the security question). `w.bind`
stays the raw escape hatch.

## Investigation

Every bound signature is statically known, so the decode target is a tuple of
the parameter types and the encode is `JSON.stringify` of the return — both reuse
the existing JSON machinery:
- `emitJSONParseValue(strVal, targetTy, pos)` (emit_call_json.go) parses a string
  Value and projects it to a Type via the single `emitJSONProject` walk
  (emit_json_project.go:19).
- `emitJSONStringifyValue(val, jsonIndent{})` (emit_call_json.go:344) encodes a
  typed Value to a compact JSON string; tuples already serialize as arrays.

The one gap: `emitJSONProject` **rejected** tuple targets (emit_json_project.go:25).
A tuple is structurally an object struct (`TupleType`, types.go:586) with synthetic
field names "0","1",…, but JSON delivers arguments as a JSON *array*, so projection
must be *positional* (`__kml_json_item(node, i)`), not keyed.

## Decision

- **`emitJSONProjectTuple`** (new) replaces the rejection: mirrors
  `emitJSONProjectObject` (malloc struct, per-field found/missing/merge branch,
  `emitJSONFieldFound` + `jsonDefaultRef`) but fetches each element via
  `__kml_json_item(node, i)`. A missing element (page passed fewer args) takes the
  default branch. **Free side benefit**: `JSON.parse<[T,U]>(s)` now works generally.
- **Typed thunk**: `emitWebviewBindThunk(cbTy, typed, pos)` gains a `typed` branch —
  decode `%rstr` into `TupleType(cbTy.FuncParams)`, GEP+load each field into the
  `emitCBCall` arg list, then `emitJSONStringifyValue` the return (void → `"null"`).
  Malformed JSON aborts inside the setjmp guard → rejects the page promise.
- **Surfaces**: a shared `bindOne(w, handle, nameRef, closureHdr, cbTy, typed, pos)`
  factors the node-alloc + retention + `webview_bind` tail. `w.bind` calls it with
  `typed=false` (unchanged raw contract); `w.bindTyped(name, fn)` and the `bindings`
  object call it with `typed=true`. `bindings` accepts an object literal or a
  variable of functions (the shape travels with the type — each function field is a
  stored `{fp,env}` closure ptr, loaded and bound under the field name).
- **Async typed bind** (`Promise<T>`) is a clean compile-time rejection in `bindOne`
  — the typed encode can't run at callback time for a value that settles later;
  raw `w.bind` `Promise<string>` remains the async path.

## Implementation notes

- The resolver's rename pass didn't recurse into `NewWebviewExpression.Options`, so
  a variable referenced in `bindings: api` stayed unrenamed and failed lookup
  (inferred as the numeric default). Added the `NewWebviewExpression` case to
  `resolver/rename.go` — a real bug the `bindings` variable form surfaced.
- `emitCBCall` already coerces args and splits array `{ptr,i64}` params, so the
  tuple-field loads feed scalars/strings/objects/arrays through unchanged.

## Side effects discovered

Deferred to a new **Stage 6** (not dropped): the `--emit-window-dts` / `global.d.ts`
generation (was written into the TDD's Stage 5 row — moved out as orthogonal
tooling), async typed bind, and advertising nested-tuple params (the projection
already supports them recursively).

## Verification

- macOS (Apple Silicon M4), windowed (gated `KML_WEBVIEW_SMOKE`): a page calls
  `window.add(2,3)`→5, `window.greet('klain')`→"hi klain", `window.mkPoint(4,5)`→
  `{x:4,y:5}` — scalar, string, and object all decode args and encode returns
  correctly (`TestE2EWebviewTypedBindSmoke`).
- Compile-tier: `bindings` literal + variable forms + `bindTyped` compile
  (`TestE2EWebviewTypedBindingsCompiles`); `JSON.parse<[number,string]>` runs and
  prints `42 hello` (`TestE2ETupleJSONParse`); non-function bindings field and
  async typed binding are clean rejections. JSON/object regression suites green.
- The tuple-projection change is additive (tuple targets were previously a hard
  error) and untyped Test262 programs never produce a tuple target, so
  conformance is unaffected by construction.
- Linux: compile-tier only, not yet run.
