# ADR-01487: Parameter-default edges, `{}`, a method's `this` type, TS2454 on `var`

- **Relations**: Extends ADR-01480
- **Date**: 2026-10-09

## Context

A per-case diff of the TypeScript suite (strict lane) against the staged
compiler showed four cases tsc accepts that ADR-01480's default-parameter
prologue now rejected. Two cases tsc rejects were now accepted. ADR-01480
made the mixed ternary and `??` work, and those two files had only been
rejected by accident through those constructs.

## Investigation

- `function foo(a = bar())` with `bar(): void`: the prologue stored the
  default's value, and a void call has none ("an expression produced no
  value"). Before ADR-01480 the default was only built at call sites, and
  this file has none.
- `function strange(x = a, y = b) { var b = "" }`: `b` is declared only
  in the body, which the parameters' scope does not see. The prologue
  compiled the read and failed with "undefined variable 'b'". Node throws
  `ReferenceError: b is not defined` when the default runs.
  - Our binder already keeps body names out of a default's scope (tsc's
    ES2015+ rule), so the checker reports TS2304, as tsc does.
  - The checker only checked an annotated default (its assignability). An
    unannotated one was checked only when a call needed its type, so
    `function f(y = nowhere) {}` with no call reached codegen.
- `class Weird { m(this: Example) { return this.getNumber() } }`: `this`
  inside the method was always the enclosing class, whatever the declared
  `this` type, and the default reading it now runs in the body.
- `(options: { headers?: {} })` given `{ headers: { foo: 1 } }`: `{}`
  (any value but null and undefined) resolved to a number slot. A check
  added by ADR-01480 rejected the argument and hid the invalid IR behind
  it. That check is meant for a primitive of another kind (a string where
  a number default is).
- bestCommonTypeOfConditionalExpressions expects TS2454 on a `var` read
  before assignment. The binder's assignment tracking skipped every
  `var`, and its unit test asserted that skip. tsc checks a `var` like a
  `let`.
- The TS-suite runner looks up a case's errors baseline by the plain case
  name. A case with only per-option baselines
  (`name(target=es2015).errors.txt`) counts as accepted, though tsc
  rejects it. optionalParamReferencingOtherParams2 is one: tsc reports
  TS2304 for both targets. The runner's scoring is left as it is
  (BACKLOG 162).

## Decision

- A void default runs for its effects when the argument is undefined, and
  the parameter is then undefined.
- A name a default reads that only the function body declares, with
  nothing of that name outside, is a `NotDefined` symbol while the default
  runs. Reading it throws `ReferenceError: <name> is not defined`
  (`bodyDeclaredNames`, `bodyOnlyRefs`).
- The checker checks every unannotated parameter default as written.
- A method whose explicit `this: C` names another class reads `this` as
  C (`declaredMethodThis`).
- `{}` (a type literal with no members) is held as `any` in codegen.
- The strict check on a defaulted slot's argument applies only when both
  the argument and the slot are primitive (`isPrimitiveRepr`).
- The binder tracks `var` bindings for TS2454, as tsc does, except an
  ambient `declare var` (examples/types/ambient-declare.ts caught it).

## Side effects discovered

- BACKLOG 162: the TS-suite oracle ignores per-option baselines.
