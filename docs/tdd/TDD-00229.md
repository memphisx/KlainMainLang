# TDD-00229: Function objects, null-prototype objects, and a runtime node:ffi library registry

- **Status**: In Progress
- **Date**: 2026-09-23

## Context

A differential pass of `node:ffi` against a real `--experimental-ffi` Node
(26.10.0) found that the module's remaining divergences are not local to FFI.
They sit on three missing foundations:

1. **Function values have no object side.** A closure is a `{fnptr, env}`
   header and nothing else: no runtime `name`, no `length`, no own
   properties. `console.log(f)` of a plain function falls through to the
   `%s` printf of the header pointer (prints raw bytes), a function inside an
   object/array renders `[Function]` without its name, and `String(f)` does
   not compile. Boxing the same closure into `any` twice allocates two
   adapter records, so the two boxes are not `===`. Unboxing a tag-12
   (dynamic-ABI) record back into a typed function type reinterprets the
   record as a closure header — there is no reverse adapter.
2. **No null-prototype objects.** Every dynamic object bag already has
   `proto == NULL` unless one is set, so `Object.create(null)` and `{}` are
   indistinguishable; nothing renders `[Object: null prototype]`; on the
   static-struct path `{ __proto__: null, a: 1 }` becomes a field literally
   named `__proto__`; `Object.isFrozen` has no static-object arm.
3. **node:ffi's library state is compile-time only.** A bound function is the
   raw C symbol pointer typed `ptr`, so `typeof` says `"string"`, printing
   treats it as a C string, and `lib.functions.abs === lib.functions.abs`
   compares strings over code memory (SIGBUS). `lib.symbols` /
   `lib.functions` are static structs rebuilt from a compile-time
   accumulator: a runtime-string name is never recorded, conditional
   registration is invisible, an unregistered library cannot be enumerated
   (`Object.keys` compile error), a re-resolution with a different signature
   is not diagnosed, and nothing is checked after `close()`. The key order
   was modeled as "reverse registration order", which only coincides with
   Node's for small inputs: Node stores both tables in a
   `std::unordered_map<std::string, …>`, and its enumeration order is that
   container's iteration order.

Node's reference behaviour (26.10.0, macOS arm64, re-derived by probe):

- A bound function is a real function: `typeof` `'function'`, `name` = the
  symbol, `length` = parameter count, one own enumerable property
  `pointer: <bigint>`, renders `[Function: abs] { pointer: 6851891788n }`.
  Callables are cached per library + name, so every `getFunction` /
  `getFunctions` / `lib.functions` read of one symbol is `===`.
- Argument validation throws `TypeError` `ERR_INVALID_ARG_VALUE`:
  `Invalid argument count: expected 1, got 0`, `Argument 0 must be an int32`
  (non-integer, out of range, bigint, string, NaN, undefined all reject),
  `… must be an int64` for a `number` passed to `int64` (bigint only, range
  checked), `… must be a uint8`, `… must be a double` (bigint/string reject),
  `… must be a buffer, an ArrayBuffer, a string, or a bigint` for a pointer
  or string slot.
- Re-requesting a symbol with a different signature (aliases count as
  different when the canonical form differs) throws `TypeError`
  `ERR_INVALID_ARG_VALUE` `Function abs was already requested with a
  different signature`.
- A missing symbol throws `Error` `ERR_FFI_CALL_FAILED`
  `dlsym failed: <dlerror text>`.
- After `close()`: calls, `getSymbol`, `getFunction`, `symbols`,
  `functions`, `getSymbols()` all throw `Error` `ERR_FFI_LIBRARY_CLOSED`
  `Library is closed`; `path` still reads; a second `close()` is a no-op.
- `lib.symbols` / `lib.functions` / `getSymbols()` / no-arg `getFunctions()`
  are fresh null-prototype objects enumerated in `unordered_map` order.
  `getFunctions(defs)` enumerates in the definitions' own property order.
  `ffi.dlopen(path)` without definitions returns a frozen empty
  null-prototype `functions`; with definitions it is not frozen.
- `new DynamicLibrary(null).path` is `''`; the library renders as
  `DynamicLibrary { path: [Getter], symbols: [Getter] }`.
- `exportString(str, ptr, len, encoding = 'utf8')` honours Buffer encodings
  (`utf16le`/`ucs2` get a 2-byte terminator) and throws `ERR_OUT_OF_RANGE`
  when `len` is too small.

## Design

Three stages, implemented serially (A and B are core and land first; C
consumes them).

### Stage A — function objects

**Header.** A closure header grows from `{fnptr, env}` to

    { ptr fnptr, ptr env, ptr meta, ptr props, ptr dynrec }   ; 40 bytes

- `meta` → `{ ptr name, i64 length, i32 kind }`. `name` is a KML string,
  `kind` distinguishes plain / async / generator / async-generator / class /
  bound. For every function literal the descriptor is a private constant
  emitted once; runtime-named functions (FFI, `bind`'s `bound x`) allocate
  one. A null `meta` renders as anonymous, so a creator that forgets it
  degrades to `[Function (anonymous)]`, never to a crash.
- `props` → a lazily-created dynamic-object bag (tag 10) holding own
  properties; null means none.
- `dynrec` caches the tag-12 adapter record the first time this header is
  boxed, so boxing the same function twice yields the same record and
  `===` holds through `any`.

The fnptr/env offsets are unchanged, so every existing indirect call site
keeps working; only header *creators* change (arrow, function expression,
named-function constant header — now a writable `private global`, since
`props`/`dynrec` are mutated — bind, the static adapters, generator
constructors, and the stack-planned `alloca` under `-optimize-memory`, which
must zero the new words).

**Name inference** follows ECMAScript NamedEvaluation: declaration name;
`const x = () => …` / `function` expression bound to `x` → `x`; object
literal property → the key; class method → method name; `bind` →
`bound <name>`; otherwise `''`. `length` = count of parameters before the
first optional/default/rest one.

**Dynamic record.** The tag-12 record grows from `{fnptr, env, arity}` to
`{fnptr, env, arity, meta, props, owner}`. A record adapted from a static
header sets `owner` to that header and reads/writes `meta`/`props` through
it (one function object, two ABIs); a natively dynamic callable (compiled
straight to the dyn ABI) owns its own.

**Rendering** (static inspect, dynamic inspect, nested, arrays):
`[Function: name]`, `[Function (anonymous)]`, `[AsyncFunction: name]`,
`[GeneratorFunction: name]`, `[AsyncGeneratorFunction: name]`,
`[class X]`, followed by ` { … }` when the props bag has enumerable keys.
`console.log` of a top-level static function gets an explicit arm instead of
the `%s` fall-through.

**Members.** `f.name` / `f.length` read `meta`. `f.x` / `f.x = v` on a
function value go through the props bag (typed `any` on read).

**Reverse adapter.** Unboxing a tag-12 value into a typed function type
wraps it in a generated closure-ABI trampoline (box the typed args, call the
dyn ABI, unbox the result) — the mirror of `emitDynClosureAdapter` — instead
of reinterpreting the record.

`String(f)` / `f.toString()` return the function's source text (Node's
type-stripped text: annotations blanked to spaces), carried in `meta` from
the lexer's source spans. If exact type-stripping spans turn out not to be
recoverable from the AST, this sub-item is split out rather than
approximated.

### Stage B — null-prototype objects

- A dynamic-object flag bit (`1<<34`, next to the existing
  non-extensible/Proxy bits) marks "prototype is null" as distinct from "no
  prototype chain modeled" (an ordinary `{}`). Set by `Object.create(null)`,
  `{ __proto__: null }`, `Object.setPrototypeOf(o, null)`; cleared when a
  prototype is set.
- The dynamic inspector prefixes `[Object: null prototype] `.
- An object literal with a non-computed `__proto__` key is routed to the
  dynamic-object literal path (which already implements the `__proto__`
  setter semantics) instead of the static struct path.
- A static object type gains a compile-time `NullProto` render flag, for
  runtime-built objects whose shape is still static (FFI `getFunctions(defs)`
  and `dlopen`'s `functions`).
- `Object.isFrozen` / `isSealed` / `isExtensible` get their static-object
  arms (lookup in the existing frozen set).

### Stage C — node:ffi on the foundations

**Order container.** Node's enumeration order is reproduced by using the
same container family Node is built with:

- POSIX: a C++ member (`ffisrc/ffi_umap_stl.cc`) wrapping a real
  `std::unordered_map<std::string, void*>` behind a small C API. Node's
  macOS build uses libc++ and its Linux build libstdc++ — the same STL clang
  links on each host — so the order holds by construction. Verified with a
  400-trial randomized differential (1–500 keys, duplicates) against real
  Node 26.10.0: identical on macOS/arm64 (libc++) and on Linux/arm64 in the
  `node:26.10.0` Docker image (g++ 14 libstdc++).
- Windows: Node is built against the MSVC STL while this toolchain is mingw
  (libstdc++), so `ffisrc/ffi_umap_msvc.c` ports `<xhash>`'s order-relevant
  logic (FNV-1a 64, `hash & mask`, 8 initial buckets, ×8 growth below 512,
  front-of-bucket insertion, list-order rehash splicing) behind the same C
  API. Verified by the FFI oracle on the Windows CI lane.

**Registry.** `__kml_ffi_lib` (C runtime) replaces the plain library struct:
`{ handle, path, closed, symbols umap, functions umap }`, with a function
entry `{ canonical signature string, C pointer, cached function object }`.
Entry points mirror Node's `ResolveSymbol` / `PrepareFunction` /
`GetSymbol` / `GetSymbols` / `GetFunctions` / `Close` exactly, including
which tables each operation inserts into and the error codes/messages.

**Bound functions.** A bound native function is a function object (Stage A)
whose dyn-ABI fnptr is a per-signature thunk
`@__kml_ffi_dyn_<sigkey>(env, this, argc, argv)`: argument-count check,
Node's per-type validation, marshalling, closed-library check, the C call,
return boxing. Its `meta` carries the symbol name and parameter count, its
props bag the `pointer` bigint. The registry caches it, giving Node's
identity. Statically, `getFunction`/`dlopen` results keep the
`IsFFIFunction` + compile-time signature typing, so a direct call still
lowers to an inline validated C-ABI call (no boxing); only the runtime value
changes from the raw symbol to the record.

**Accumulators.** `lib.symbols` / `lib.functions` / `getSymbols()` /
no-arg `getFunctions()` are runtime-built null-prototype dynamic objects
(`any`), filled by walking the registry's umap. `getFunctions(defs)` and
`dlopen`'s `functions` stay static structs (definition order = literal
order) with the `NullProto` render flag; no-definitions `dlopen` registers
its empty object as frozen.

**Remaining conformance items folded in:** `int64`/`uint64` reject a
`number` (runtime `TypeError`, as Node); `exportString` encodings and the
`ERR_OUT_OF_RANGE` message; `lib.path` of a `null` open is `''`; library
rendering.
