# ADR-00338: Spread into the variadic builtins `console.*` and `Math.min`/`Math.max`

- **Relations**: Implements TDD-00106 (V2 cont.); follows ADR-00335, ADR-00337
- **Date**: 2026-08-24

## Context

ADR-00335 (V1) and ADR-00337 (V2) covered spread into a callee's rest parameter
for user functions, closures, and class methods. The one remaining spread form
from the "remaining forms" gap was **variadic builtins** — `console.log(...arr)`,
`Math.max(...arr)`, `Math.min(...arr)` — which each fold a *static*,
compile-time-known argument list one expression at a time and so couldn't take a
runtime-length array. TDD-00106 flagged these as needing bespoke per-builtin
work, since they don't route through the generic rest-parameter ABI.

## Decision

Support a spread argument (in any position, any count, mixed with positional
args) into the two variadic builtins that matter for this project's use cases:

- **`Math.max` / `Math.min`** — fold the array at runtime. An accumulator is
  seeded with the reduction identity (`-Infinity`/`+Infinity` for a float result,
  `INT64_MIN`/`INT64_MAX` for an integer one), each static arg is folded in, and
  each spread array is looped over element by element. Any argument count is now
  valid (the old "expects at least 2 arguments" check is bypassed when a spread
  is present), so a lone `Math.max(...arr)` works. An empty fold yields the seed:
  `±Infinity` for a float result exactly matches JS; an `i64` result has no
  Infinity, so it yields the extreme `i64` — the same concrete-type stand-in
  ADR-00157 uses for values JS would call `undefined`/`Infinity`.
- **`console.log` / `.info` / `.debug` / `.error` / `.warn` / `.trace`** —
  expand a spread to space-separated tokens. Because the token count is a runtime
  quantity, the static last-token detection (index vs length, which picks `" "`
  vs `"\n"`) doesn't apply; a dedicated path prints each token with no
  terminator, emits one separator space *before* every token except the first
  (tracked by a runtime flag, so an empty spread contributes nothing), and closes
  the line with a single newline — yielding exactly `a b c\n` for any
  positional/spread mix, matching Node.

Other variadic builtins (`Math.hypot`, `String.fromCharCode`, …) still reject a
spread — none is on the priority path; they can reuse the same runtime-fold shape
if they ever surface.

## Implementation notes

- `emit_call_math.go`: `emitMathMinMax` delegates to a new `emitMathMinMaxSpread`
  when `anySpread(args)`; the reducer seeds an alloca accumulator and folds
  static args plus a per-spread element loop.
- `emit_exprs_types.go`: the compile-time `Math.min`/`max` result-type inference
  now reads a spread argument's array element type (a `float64[]` spread promotes
  the fold to `double`), keeping inference in step with codegen.
- `emit_call_console.go`: the per-argument type dispatch was factored out of
  `emitConsolePrint`'s loop into `emitConsolePrintArgToken` (argument) and
  `emitConsolePrintValueToken` (already-evaluated value); the new
  `emitConsolePrintSpread` reuses the value half for each spread element. The
  static, spread-free path is byte-for-byte unchanged (same output).

## Verification

- `tests/spread_test.go`: `TestE2ESpreadMathMinMax` (int/float, lone spread,
  mixed with positional) and `TestE2ESpreadConsoleLog` (lone spread, mixed,
  string array, empty spread). The former variadic-builtin *rejection* test is
  replaced by these.
- Manual: `console.error(...)` to stderr, boolean/float array elements.
- Machine: verified on Mac (arm64); the change is platform-independent.
