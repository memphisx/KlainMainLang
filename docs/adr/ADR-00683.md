# ADR-00683: `JSON.stringify` segfaulted on null object/string fields

- **Date**: 2026-09-03

## Context

`JSON.stringify` over an array of `Promise.allSettled` results segfaulted (exit
139). Found in the audit.

## Investigation

A settlement object `{status, value, reason}` always carries both `value` and
`reason` (this compiler has no optional fields), so a fulfilled element has
`reason = null` (an object-typed null ptr) and a rejected element's wrapped
Error carries null `code`/`errstr` string fields. Two unguarded derefs:
`emitJSONStringifyValue`'s `IsObject` branch recursed into a **null** object
pointer (GEP/load from ~0), and `__kml_json_str_str` called `strlen` on a
**null** string pointer — either faults.

## Decision

Null-guard both: `emitJSONStringifyValue` emits JSON `null` for a null
object-typed value instead of recursing; `__kml_json_str_str` returns an empty
JSON string `""` for a null input instead of `strlen(NULL)`. This stops the
crash for any object with a null object/string field, not just settlements.

## Side effects discovered

This fixes the **crash**, not the full `allSettled` output fidelity: `reason`
still serializes as a wrapped `Error` (not the original rejected value) and the
always-present `value`/`reason` fields aren't omitted, so the output still
diverges from Node's `[{"status":"fulfilled","value":1},{"status":"rejected","reason":42}]`.
That is a deeper async reject-value-representation change (the reject slot
Error-wraps the original value across both `reject` and `throw`) — scoped in
[TDD-00169](../tdd/TDD-00169.md), and disclosed as a caveat on the allSettled row.

## Verification

Mac. `JSON.stringify(allSettledResult)` returns instead of segfaulting. E2E
test `TestE2EJSONStringifyAllSettledNoCrash`; full JSON/promise/async
regression green.
