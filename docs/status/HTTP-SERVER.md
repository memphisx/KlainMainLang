# HTTP Server

> Part of the [Implementation Status](README.md) index. The piece that unlocks this project's microservice direction. Full design: [TDD-00004](../tdd/TDD-00004.md).

**Coverage**: 100% (9/9).

**Caveats**: `http.close()` ([TDD-00027](../tdd/TDD-00027.md)) stops accepting new connections immediately and lets already-open ones finish naturally before the event loop actually returns control to the rest of the program. In a `{ workers: N }` cluster, `.close()` only affects the calling process's own copy of the listener — a full-cluster shutdown still requires an external signal to the whole process group (as the test harness's `startHTTPClusterServer` cleanup already does).

| API | Status | Notes |
|---|---|---|
| `http.listen(port, handler)` — bind, accept, dispatch | ✅ | Concurrent connection handling: each accepted connection runs on its own fiber (`ucontext.h`-based, no custom assembly — see [TDD-00006](../tdd/TDD-00006.md)'s Part 2 prototype), so a connection that hasn't sent its request yet no longer blocks any other connection from being accepted and answered. Built on the generalized `select()`-based event loop ([TDD-00006](../tdd/TDD-00006.md) Part 1), so the listening socket, every open connection, and any pending `setTimeout`/`setInterval` timers all share one wait. See [ADR-00048](../adr/ADR-00048.md) (V1), [ADR-00049](../adr/ADR-00049.md) (concurrent connections), and [ADR-00052](../adr/ADR-00052.md) (fixed a stack leak in the main dispatch loop that crashed a running server after ~20,000 requests). |
| `http.listen(port, handler, { workers: N })` — multi-process clustering | ✅ | `fork()`s `N-1` additional worker processes sharing the one listening socket right after bind+listen succeeds, so a single `http.listen()` service can use every core on the machine instead of just one — the cooperative fiber scheduler above still gives *concurrency* within each process; this is what adds real *parallelism* across processes. `cluster.isPrimary`/`cluster.workerId` (0 = original process, 1..N-1 per fork) let a program branch on which process it's running as. Both memory-management modes are production-quality: `manual` ([TDD-00025](../tdd/TDD-00025.md)/[ADR-00097](../adr/ADR-00097.md)/[ADR-00098](../adr/ADR-00098.md)) and `-mm=gc` ([ADR-00099](../adr/ADR-00099.md) fixed a 100%-reproducible crash; [ADR-00101](../adr/ADR-00101.md) then root-caused and fixed a residual low-frequency hang — a missing `GC_stackbottom` restore when a fiber runs to completion without yielding again). |
| Request-line parsing (`req.method`, `req.path`) | ✅ | The request line's method token and path token are parsed generically (`sscanf("%15s %2047s", ...)`) — this is **not** GET-only: verified directly by curling `POST`/`PUT`/`DELETE` requests at a running server and confirming `req.method` reports each one correctly. `req.path` no longer includes a trailing `?...` query string (see below) — [ADR-00072](../adr/ADR-00072.md) fixed that. |
| Request headers (`req.headers: Map<string, string>`) | ✅ | Lowercased keys (case-insensitive lookup, matching real HTTP semantics) — [ADR-00072](../adr/ADR-00072.md) |
| Query string (`req.query: Map<string, string>`) | ✅ | Split from `req.path` and parsed (`a=b&c=d`), both keys and values percent-decoded via the same `decodeURIComponent` primitive this compiler already had — [ADR-00072](../adr/ADR-00072.md) |
| Request body (`req.body: string`) | ✅ | `Content-Length`-aware — the read buffer now accumulates across as many `read()` calls as it takes (growing via `realloc`, capped at 10MiB against a hostile/malformed `Content-Length`) rather than assuming one `read()` call returns an entire request — [ADR-00072](../adr/ADR-00072.md) |
| Response headers (optional `headers: Map<string, string>` field) | ✅ | Fully user-controlled, including `Content-Type` if set — omitting the field behaves byte-identically to before this existed — [ADR-00072](../adr/ADR-00072.md) |
| Graceful shutdown via `process.on('SIGINT'/'SIGTERM', handler)` | ✅ | A registered handler runs from ordinary control flow at the top of the event loop's own iteration (never from real signal context), can do cleanup, and call `process.exit()` — see [TDD-00019](../tdd/TDD-00019.md)/[ADR-00079](../adr/ADR-00079.md), [PROCESS-CLI.md](PROCESS-CLI.md). Fixed a real, related bug along the way: `select()`'s return value wasn't checked, so an `EINTR` from any signal could leave a spuriously-"ready" stale `fd_set` in place and risk hanging the loop instead of reacting to the signal. |
| `http.close()` (formal listener teardown, distinct from the graceful-shutdown row above) | ✅ | A bare global function (like `http.listen` itself), reachable only from inside a running request handler, `setTimeout`/`setInterval` callback, or `process.on(...)` handler — the only places code ever runs "alongside" the event loop. Stops accepting new connections immediately; already-open connections finish naturally before `http.listen()`'s own call actually returns control to the rest of the program. See [TDD-00027](../tdd/TDD-00027.md)/[ADR-00102](../adr/ADR-00102.md). |

## Known Limitations

| Limitation | Notes |
|---|---|
| Request/response bodies truncate at an embedded null byte | Same root cause as `fetch`'s equivalent limitation (see [NETWORKING.md](NETWORKING.md)'s Known Limitations): every string in this compiler is a plain null-terminated C string. On the response side, confirmed directly at `codegen/llvm/runtime_http.go:664` — the handler's `body: string` field is written to the socket via a `strlen`-computed length, not a carried byte count, so a null byte truncates the response before any bytes past it go out. `req.body: string` (request side) is symmetric: the read loop itself is `Content-Length`-aware and accumulates the exact byte count ([ADR-00072](../adr/ADR-00072.md)), but once exposed to TS code as a plain string, ordinary string operations on it (`.length` included) revert to `strlen` semantics. Unlike `fetch`/`fs`, which gained a binary-safe escape hatch (`.arrayBuffer()`, [ADR-00094](../adr/ADR-00094.md)) once `ArrayBuffer`/TypedArrays existed, `http.listen` was never revisited for the same fix — scoped in [TDD-00026](../tdd/TDD-00026.md), not yet implemented. |
| `http.close()` in a `{ workers: N }` cluster only stops the calling process | Each worker is a separate `fork()`ed process with its own independent copy of every listener/connection global — no IPC exists between them. A full-cluster shutdown still needs an external signal to the whole process group. See [TDD-00027](../tdd/TDD-00027.md). |
