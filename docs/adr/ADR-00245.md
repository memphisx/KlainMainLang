# ADR-00245: Microtasks — queueMicrotask + Promise.prototype.then/.catch/.finally

- **Relations**: `Implements TDD-00083` (Stage 3); builds on [ADR-00244](ADR-00244.md) (coroutine tasks + rejection)
- **Date**: 2026-08-19

## Context

With true async suspension and rejection in place ([ADR-00244](ADR-00244.md)),
the remaining ergonomic gap was the microtask surface: `queueMicrotask` and
`Promise.prototype.then`/`.catch`/`.finally`, absent because the synchronous
async model had no deferred-callback concept.

## Decision

**Microtask FIFO** (`runtime_microtask.go`): a growable queue of callback closure
headers (`__kml_microtask_enqueue` / `__kml_drain_microtasks`), drained at the
reachable checkpoints — the end of the top-level script (before timers/tasks) and
each `__kml_task_run_all` scheduler iteration. A drained callback may enqueue
more, run in the same pass. `queueMicrotask(cb)` enqueues a 0-arg closure.

**Reactions**: the task promise struct gains a `reactions` field — a `{ closure,
next }` list. `.then`/`.catch`/`.finally` on a task promise attach a reaction; a
task, when it settles (`__kml_task_finish`/`__kml_task_reject`), drains its
reactions onto the microtask FIFO; an already-settled promise enqueues
immediately. Each reaction is a **per-call-site, type-specialized runner**
closure (`emit_promise_then.go`) capturing `{promise, onFulfilled, onRejected,
onFinally}` — the runner knows the promise's value type, so it reads the settled
value/reason and invokes the right callback with the right argument type, while
the FIFO stays generic (0-arg closures).

**Parser**: reserved words are now accepted as property names after `.`
(`promise.catch`, `promise.finally`), matching JS — a keyword token carries the
word as its `Literal` (`lexer.IsKeyword`).

## Consequences

- `queueMicrotask` and `.then`/`.catch`/`.finally` work with correct ordering
  (sync run, then microtasks, then timers).
- Scoped for V1 (documented caveats): `.then`/`.catch`/`.finally` return a
  resolved `Promise<void>` — the callback's own result does not chain into it; a
  `.catch` callback's error parameter is untyped (annotate to access `.message`);
  reaction order across *independent* promises is scheduler-timing-dependent.

## Verification

`queueMicrotask` ordering (sync-first, FIFO, nested-in-same-batch) and
`.then`/`.catch`/`.finally` firing after the synchronous script all produce the
expected output. New E2E tests (`TestE2EQueueMicrotask`,
`TestE2EPromiseThenCatchFinally`); the parser + lexer + exception + async/promise
suites stay green; `go vet` clean. Apple Silicon (macOS).
