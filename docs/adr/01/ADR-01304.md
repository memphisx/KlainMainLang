# ADR-01304: `node:sqlite` as Node's src/node_sqlite.cc, in TypeScript

- **Relations**: `Implements part of TDD-00230` (P3.1), `Supersedes ADR-00540`
- **Date**: 2026-09-30

## Context

`node:sqlite` was compiled directly (`emit_sqlite.go`, `runtime_sqlite.go`).
Rows needed a call-site type argument (`stmt.all<Row>()`), which neither
Node nor @types/node has (tsc rejects it); `get()` returned `null` where Node
returns `undefined`; `iterate()` was materialised eagerly; options were read
only from an object literal; `aggregate()`, the authorizer, sessions,
serialization, tag stores and `backup()` were rejected or missing;
`setReadBigInts` did nothing and an INTEGER past 2^53 lost precision where
Node throws.

## Investigation

Node v24's lib/sqlite.js is a thin export of src/node_sqlite.cc. Its
behaviour, checked against Node 24.19: rows are null-prototype objects (or
arrays with `returnArrays`); a JS number binds as REAL, a bigint as INTEGER;
a leading plain object binds named parameters, bare keys matching `:x`,
`@x`, `$x`; an unknown name is `ERR_INVALID_STATE`; an INTEGER column past
2^53 is `ERR_OUT_OF_RANGE` without `readBigInts`; errors are
`ERR_SQLITE_ERROR` with `errcode`/`errstr`; closing finalizes statements;
`prepare('')` yields a finalized statement; a user function's exception is
rethrown from the statement; `iterate()` results are null-prototype
`{ done, value }`. macOS's system libsqlite3 has column metadata, sessions,
window functions and serialization, but omits extension loading.

## Decision

- **Natives** (`klainsqlite.c`, compiled into the pool's unit with
  `-DKLAINPOOL_SQLITE`, linking libsqlite3; `@link sqlite`): databases,
  statements, sessions and backups as per-thread handle ids; open, exec,
  prepare, step, reset (clearing bindings only when binding anew), bind and
  column accessors (integers as decimal strings), column metadata, user
  functions and aggregates (one callback kind per call, a per-group key from
  `sqlite3_aggregate_context`, arguments and results read and set through
  thread-local call state), the authorizer and changeset callbacks (answering
  through `sqliteCallbackReturn`, since native callbacks return nothing),
  serialize/deserialize, backup steps. Sessions, extension loading and
  serialization are looked up with `dlsym`, so a library without them still
  links.
- **Module** (`lib/node/sqlite.ts`): `DatabaseSync`, `StatementSync` (with a
  lazy iterator), `Session`, `SQLTagStore`, `constants`, `backup()` — Node's
  argument validation, error codes and messages. `node:sqlite` only: a module
  marked `kml:scheme-only` has no bare specifier (`lib.ModulePath`).
- **Deleted**: `emit_sqlite.go`, `runtime_sqlite.go`,
  `NewDatabaseSyncExpression`, its sema builder, the `SQLite*` codegen types
  and the `node:sqlite` virtual module.

## Implementation notes

- Compiler fixes found on the way: a top-level `const X = BigInt(…)` is a
  module global (readable from named functions); `for…of` over a class
  iterator whose `next()` returns `any` iterates by the dynamic protocol; a
  generic interface used with fewer type arguments than parameters takes the
  parameters' defaults (it resolved `T` as a number before).
- A view's bytes are bound through `typedBytes`: typed arrays have no
  `.buffer`/`.byteOffset` here.

## Side effects discovered

- Typed arrays lack `.buffer`/`.byteOffset` (statically and through `any`).
- `Map.prototype.keys()` returns an array, not an iterator.

## Verification

- `tests/sqlite_test.go` and `tests/sqlite_oracle_test.go` pass, updated to
  Node's API (no row type arguments, `undefined` for no row, numbers binding
  as REAL, `setReadBigInts` for integers past 2^53).
- A program covering run/get/all/iterate/columns/functions/aggregates/
  returnArrays/bigints/errors/finalization prints exactly what Node 24.19
  prints; so does `examples/sqlite/sqlite.ts`. macOS (arm64).
