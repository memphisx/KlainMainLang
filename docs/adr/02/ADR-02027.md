# ADR-02027: Members overriding an inherited member of another kind

- **Date**: 2026-11-22

## Context

- A subclass accessor over a base method, a field over a base accessor and
  an accessor over a base field were compile errors (an internal one in the
  strict lane, where tsc reports TS2423/TS2610/TS2611).
- Problems found next to it:
  - A field over a base method (`x = () => 2` over `x() {}`, legal
    TypeScript) still called the method, in both lanes.
  - A field over a base getter called the base's setter at construction
    ("Cannot set property … which has only a getter").
  - `typeof obj.m` was folded to "function" whenever the class had a
    method `m`, even when an accessor or field overrides it.
  - `Object.getOwnPropertyNames(C.prototype)` listed overrides in their
    base's slot order instead of the class's declaration order.

## Decision

- The checker reports tsc's kind checks (checkKindsOfPropertyMemberOverrides):
  TS2423 (accessor over method), TS2425 (method over property), TS2426
  (method over accessor), TS2610 (property over accessor) and TS2611
  (accessor over property). A property over a method is allowed.
- `accessorOverMethods` (both lanes, before static `this` is rewritten):
  - The overriding class gets a method of the inherited signature, result
    `any`, calling what its own property gives (`this.m.call(this, …)`), so
    a call through the base's type reaches the override. This covers an
    accessor (instance or static) or a field over a method.
  - For an accessor, the base class gets the method-as-value getter that
    `shadowInheritedGetters` makes, which the accessor overrides. A setter
    alone gets a getter giving undefined.
- `fieldOverAccessors` (JavaScript): a field over an inherited accessor gets
  an accessor pair over its own slot, and the base pair takes and gives
  `any`.
- `classAccessorSigs` treats an instance field as shadowing any accessor of
  the same name, so reads and writes inside that pair (and on the
  instance) reach the field. An accessor the instance's own field shadows
  stays registered, for its prototype property.
- The synthesized members are not prototype properties. A class's own
  prototype keys are listed in declaration order.

## Consequences

- Tests: `TestMemberKindOverrideDiagnostics`, `TestE2EFieldOverMethodTS`,
  `TestE2EMemberKindOverridesJS`.
