# ADR-01883: a Map of tuples; an initialized reference read present

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's Identifier bucket)
- **Date**: 2026-10-21

## Context

- `new Map<number, [string, string]>()` holds its values as the headerless tuple struct its type argument names. `m.set(k, [a, b])` through the map-view dispatch built the literal as an array, and the representation oracle answered `m.get(k)` and `m.get(k)!` from the checker's tuple, an array: reads printed ` null undefined`, `const w = m.get(k)` failed to compile, and destructuring `m.get(k)!` crashed (util's getSystemErrorMap is one).
- The oracle answered a binding's storage slot without the present-reference narrowing codegen applies (checkerPresentRef) when its initializer may be absent (`const own = find(); if (own !== undefined) return own[1]`).

## Decision

- A Map value argument is built against the map's value type on the map-view path as on the direct one (mapValHinted).
- The oracle answers `m.get(k)` off a Map holding tuples as that tuple, undefined on a miss, and `x!` over a tuple-held operand as that tuple; a collection's tuple type arguments, written or declared, map to the tuple layout.
- The oracle's slot rule applies the present-reference narrowing whatever initialized the binding.

## Consequences

- Map-of-tuple programs match Node; util's rows leave the shadow report.
- Verified on Apple Silicon.
