# ADR-00096: Replace httpbin.org with a local httpbin-lite fixture in `make examples`

- **Relations**: Extends [ADR-00021](ADR-00021.md) (`fetch.ts`), [ADR-00073](ADR-00073.md) (`promise_all.ts`), [ADR-00074](ADR-00074.md) (`fetch_init.ts`), each of which originally pointed its example at `httpbin.org`
- **Date**: 2026-08-04

## Context

The GitHub Actions "test" job (`.github/workflows/release.yml`) failed a `make examples` run with `examples/async/promise_all.ts` reported as `FAIL`, all 70 other examples passing. Told directly that a flaky example/test is unacceptable and asked to find an alternative that gives consistent results, rather than accept "httpbin.org was probably having a bad moment" as a satisfactory answer.

`promise_all.ts`'s own header comment already flagged its real-fetch section as needing real network access and being "expected to FAIL under `make examples` without it" — but that framing assumes the only failure mode is "no network at all." In practice, `make examples` runs on a GitHub Actions runner, which *does* have network access, so the actual failure mode in CI is httpbin.org itself being briefly down, rate-limiting the six-plus requests this one file alone makes per run, or just being slow enough to trip curl's default timeouts — none of which this compiler has any control over, and none of which indicate an actual bug. The same dependency exists in `examples/fetch/fetch.ts` and `examples/fetch/fetch_init.ts`.

## Investigation

- `grep -rln httpbin` across `examples/`, `docker/`, `tests/` turned up four files: `examples/fetch/fetch.ts`, `examples/fetch/fetch_init.ts`, `examples/async/promise_all.ts` (all three gated by `make examples`, and therefore CI), and `docker/fetch-demo.ts` (not run by `make examples` or CI — only built manually via `docker build`, and specifically exists to prove real DNS/TLS/libcurl-static-linking works end to end, so hitting a real external host there is the actual point, not a liability — left unchanged).
- `tests/fetch_test.go` already established the right precedent for the Go test suite: its own header comment says plainly "these spin up a local `httptest.Server` rather than hitting a real external URL, so the suite stays deterministic and offline-capable." `httptest.Server` only works inside a Go test binary, though — `make examples` invokes `klainmain`-compiled *native binaries* as separate OS processes, so the same fix needed a standalone process, not a Go-test-scoped server.
- `examples/fetch/wttr_weather.ts` also hits a real third-party host (`wttr.in`) but was left alone: it's wrapped in `try/catch` specifically so a transient failure prints a message instead of failing the file, and its whole point (per its own header) is demonstrating that resilience pattern against a real, non-test-dedicated API — it doesn't gate CI the way an unhandled `FAIL` does.

## Decision

Added `tools/httpbin-lite/main.go`, a small dependency-free Go `net/http` server implementing only the specific endpoints the three CI-gated examples exercise (`GET /get`, `GET /ip`, `GET /status/{code}`, `GET /redirect-to?url=`, `GET /bytes/{n}`, `POST /post`, `DELETE /delete`, `GET /headers`, `GET /delay/{n}`) using Go 1.22+'s method-and-wildcard `ServeMux` patterns. `make examples` now builds it to `.httpbin-lite` and starts it in the background before the example loop, polling `GET /get` until it responds (up to 5s) before running anything, and kills it via a `trap ... EXIT INT TERM` when the target finishes (success or failure). The three examples were repointed from `https://httpbin.org/...` to `http://127.0.0.1:8765/...`.

Rejected alternatives:
- **A different public httpbin-compatible host** (e.g. httpbingo.org) — still an external dependency with its own uptime/rate-limit risk; doesn't actually solve the problem, just moves it.
- **Excluding these examples from `make examples`'s pass/fail gate** — was considered, but the ask was specifically for *consistent results*, not fewer things checked; a local fixture achieves that without reducing coverage.
- **Writing the fixture server in KlainMainLang itself** (dogfooding `http.listen`) — rejected because it can't express everything needed (redirects, arbitrary status codes, `DELETE`) without stretching `http.listen`'s current scope solely to serve a test fixture, and it would make the fixture depend on the exact feature (`fetch`/HTTP) it exists to test in isolation.

## Implementation notes

- Files touched: `tools/httpbin-lite/main.go` (new), `Makefile` (`examples` target builds/starts/stops the fixture, plus `HTTPBIN_LITE`/`HTTPBIN_LITE_PORT` vars and a `clean` update), `.gitignore` (`/.httpbin-lite`), `examples/fetch/fetch.ts`, `examples/fetch/fetch_init.ts`, `examples/async/promise_all.ts`.
- `GET /bytes/{n}` deliberately writes a fixed byte pattern with a hardcoded null byte at index 5, rather than random bytes like the real httpbin — the point of that example (ADR-00094) is proving `.arrayBuffer()` survives an embedded null byte, which random bytes only exercised probabilistically (~1/256 chance per byte of *not* including one at all). Now it's exercised on every single run.
- `POST /post` echoes the raw request body back verbatim instead of httpbin's JSON-reformatting behavior — since both the fixture and the example are ours to define, `fetch_init.ts`'s assertion changed from `indexOf('"hello": "world"')` (httpbin's pretty-printed spacing) to `indexOf('"hello":"world"')`, matching this compiler's own compact `JSON.stringify` output (`examples/json/json_obj.ts`) exactly instead of a third party's formatting choice.
- `GET /delay/{n}` is called with `1` (not httpbin's `3`) in `promise_all.ts`'s `Promise.race` section — a 1-second gap is already far larger than the near-instant local `/get` it's racing against, and keeps `make examples`' runtime down.
- The readiness poll in the Makefile (`curl` against `/get` in a `for`-loop with `sleep 0.1`, up to 50 iterations) exists because the fixture binary needs a moment to bind its listening socket after being `&`-backgrounded; without it the first example's `fetch` calls could race the server's own startup.

## Side effects discovered

None new.

## Verification

- `go build -o tools/httpbin-lite ./tools/httpbin-lite` (via the Makefile's new step) and `curl` against every endpoint directly — `/get`, `/status/404`, `/redirect-to?url=/get` (redirect followed, final 200), `/ip`, `/bytes/16` (confirmed the embedded null byte with `xxd`), `/post` (echoes body verbatim), `/headers` (echoes a custom header back), `/delete`, `/delay/1` (confirmed ~1s wall-clock via `time`).
- Compiled and ran `examples/fetch/fetch.ts`, `examples/fetch/fetch_init.ts`, and `examples/async/promise_all.ts` individually against the running fixture — all three produce exactly the output their own inline comments document, with no network access beyond `127.0.0.1`.
- Ran the full example suite (the same loop `make examples`'s recipe runs) end to end against the fixture: **71 passed, 0 failed** — the same 71 files as before this change, including the three examples that previously depended on httpbin.org's uptime.
