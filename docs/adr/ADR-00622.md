# ADR-00622: D1 Stage 2 — untyped JSON.parse to dynamic trees, dynamic arrays, dynamic stringify

- **Relations**: `Implements TDD-00155 (Stage 2)`, `Extends ADR-00621, ADR-00223, ADR-00224`, `Advances TDD-00077 (Track P P4)`
- **Date**: 2026-09-01

## Context

Stage 1 ([ADR-00621](ADR-00621.md)) shipped the dynamic object bag behind
`any`. Stage 2 is its first end-to-end consumer: untyped `JSON.parse` keeping
the whole tree dynamic — the single most-cited dynamic-data caveat
([TDD-00077](../tdd/TDD-00077.md) P4) — which forces the remaining piece of
the dynamic value universe: arrays whose elements are boxes.

## Decision

**Dynamic array, box tag 11** (`runtime_dynarr.go`): a 24-byte header
`{len, cap, data}` over 16-byte `{i64 tag, i64 payload}` elements —
deliberately distinct from tag 7, which boxes a *statically typed* array
whose element type lives at the call sites. IR helpers: `new`, `push`,
`at` (out-of-bounds → undefined), `put` (JS extension semantics: past-the-end
writes grow and hole-fill with undefined), `get_by_key`/`set_by_key`
(canonical numeric-string index via `strtoll`; `length` reads the count; a
non-index write is a clean TypeError), `keys` (index strings), `grow`.

**Tree conversion in IR, not C**: `__kml_dynjson_from_node` is a recursive
IR-defined function walking the existing `KmlJsonNode` tree (json_parse.c)
through its scalar accessors — so the `{i8,i64}` box never crosses the C ABI
and the bag-set logic stays single-sourced. Two new C accessors
(`__kml_json_key`/`__kml_json_val`) expose object pairs. Numbers become int
boxes unless the lexeme carries `./e/E` or exceeds 18 digits (then float via
`strtod`); strings/keys are copied out so `__kml_json_free` stays correct.

**Wiring**: `emitJSONProject`'s `IsDynamic` case calls the converter (typed
targets untouched); context-free `JSON.parse` now defaults to the dynamic
parse instead of the old string-target quirk — JS-faithful, and
`const data = JSON.parse(s)` with no annotation just works. A dynamic
argument to `JSON.parse` goes through ToString first (JS coercion). Member/
bracket/`.length` reads, index writes, `Object.keys`, and `for...in` on
tag 11 ride the Stage-1 tag dispatch with new arms; `inferExprType` types
member/bracket reads off a dynamic base as `any`, which is what lets
`data.server.ports[0]` chain. An array literal in an `any` context builds a
dynamic array (heterogeneous elements included); object literals kept their
Stage-1 bag path.

**Stringify in embedded C** (`dynjsonsrc/dynjson.c`, read-only walker over
the documented bag/array layouts): `__kml_dynjson_stringify` renders JSON —
undefined/function values skipped in objects and `null` in arrays,
NaN/Infinity → `null`, floats via `__kml_dtoa`, `\uXXXX` control escaping,
ancestor-stack cycle detection throwing `Converting circular structure to
JSON`, and a TypeError for statically-typed (tag 6/7) values in the tree. Its
result is `any` (string box, or undefined for a top-level undefined/function
— matching JS). `__kml_dynarr_join` backs `String(arr)`/template rendering
with the JS Array join. New `CSource{"dynjson"}` gated on `UsesDynJSON()`,
mirrored in the test harness (`appendDynJSON`).

## Consequences

- `JSON.parse → any` closes on the status pages ([JSON.md](../status/JSON.md)
  row flips ✅); the round-trip `JSON.parse(JSON.stringify(x))` is clean and
  the Stage-2 smoke program's output is byte-identical to Node's.
- Remaining, disclosed: a `space` argument on dynamic stringify; spread in a
  dynamic array literal; dynamic-array expando/`length` writes; `console.log`
  of a dynamic array shows the join, not util.inspect's `[ 1, 'two' ]`.
- Verified on the Mac (arm64); 7 new E2E tests (16 total in
  `tests/dynobj_test.go`), example extended, object/any/JSON regression suite
  green.
