# ADR-01161: Node's `stream` module in TypeScript; the codegen stream classes deleted

- **Relations**: `Implements TDD-00231` (stages 1–3); `Implements TDD-00230` (P3.1, P3.2); `Supersedes ADR-00304`, `ADR-00393`, `ADR-00422`, `ADR-00449`, `ADR-00483`, `ADR-00484`, `ADR-00493`, `ADR-00982`
- **Date**: 2026-09-25

## Context

TDD-00231 moves Node's `stream` module out of codegen into a TypeScript
module compiled with the program. Stage 1 (the loader and the compiler
gaps it needed first, ADR-01158–01160) left a first draft of
`lib/node/stream.ts` that compiled and passed the strict checker. The
draft's event timing differed from Node in places ("finished" printed
before "end", a pipeline callback ran a tick early), because it had been
written from the documentation rather than from Node's code.

## Investigation

- Node v24's stream sources were read from the running binary
  (`process.binding('natives')`): `readable.js`, `writable.js`,
  `duplex.js`, `transform.js`, `destroy.js`, `end-of-stream.js`,
  `pipeline.js`, `from.js`, `utils.js`.
- The ordering differences traced to three places:
  - `onwrite` completes a synchronous write without a tick only when the
    callback is the no-op one, and `afterWrite` ends in
    `finishMaybe(stream, state, true)`, which defers `finish` to a tick;
  - `endReadable` defers `'end'` to `endReadableNT`, and
    `end-of-stream` waits for `'close'` when the stream will emit one;
  - `from()` pushes a sync iterable's values synchronously
    (`nextSyncWithSyncValues`), with `highWaterMark: 1`.
- Two of Node's behaviours are not in its documentation:
  - `onwrite` computes `needTick` with
    `(state[kState] & kDestroyed !== 0)`. By precedence that is
    `state[kState] & true`, which reads bit 0: `kObjectMode`
    (`utils.js`). An object-mode write therefore always completes on a
    tick. That is why, with a flowing Readable and an object-mode Writable
    ended in the same tick, Node emits `'end'` before `'finish'`.
  - `Writable.prototype._final` does not exist. `prefinish` calls
    `_final` only when `typeof stream._final === 'function'`: an options
    `final`, a subclass method, or Transform's own.

## Decision

- **The loader.** `lib/node/*.ts` is embedded (`lib.ModuleRoot`,
  `lib.ModulePath`, `lib.ModuleSource`). The resolver checks it before
  the file system, so `stream`, `node:stream` and `stream/promises`
  resolve to an embedded file, which is parsed, bound, checked and
  merged like a user module, and only when imported. Those specifiers
  are removed from the virtual builtin tables. A module whose source
  carries the `kml:default-namespace` marker has its default import read
  as the namespace (`import stream from 'stream'`, then
  `stream.Readable`), as Node's default export is the module object.
- **Node's event loop order for the port.** `process.nextTick` callbacks
  have their own queue, drained before the promise jobs at each
  checkpoint (`processTicksAndRejections`). An ES-module entry drains
  its promise jobs first, as Node's module evaluation does.
- **`lib/node/stream.ts` is a port of those sources**, function by
  function, with Node's names:
  - Readable: `readableAddChunkPush*`/`Unshift*`, `addChunk`, `read`,
    `howMuchToRead`, `fromList`, `emitReadable`/`emitReadableNT`,
    `maybeReadMore`, `updateReadableListening`, `resume`/`pause`/`flow`,
    `pipe` (its listener web held by a `Pipe` object, so the listeners can
    be removed), `endReadable`/`endReadableNT` and the async iterator;
  - Writable: `writeOrBuffer`, `onwrite` with the `afterWriteTick`
    batching, `afterWrite`, `clearBuffer`, `end`, `needFinish`,
    `prefinish`, `finishMaybe`, `finish`;
  - `destroy`, `errorOrDestroy`, `emitCloseNT`, `emitErrorNT`;
  - `finished` (end-of-stream) with `willEmitClose`, and `pipeline` as
    `pipelineImpl`, `destroyer` and `pipe`;
  - `Readable.from` as `from.js` (an array, string or Buffer; a value
    that is a promise is awaited);
  - `duplexPair` as Node's `DuplexSide`: a write completes when the peer
    reads it, and `end()` finishes once the peer has ended.
- **Node's state bits are named fields.** `needTick` reads `objectMode`
  where Node reads bit 0, with a comment saying why.
- **`_final`.** The base class's `_final` marks itself absent
  (`_kmlNoFinal`) instead of calling back; `prefinish` then prefinishes
  synchronously, as Node does when there is no `_final`.
- **The decoder** for `setEncoding` keeps a UTF-8 character, a UTF-16
  code unit or surrogate pair, or a base64 group that is split across
  chunks for the next chunk, as `string_decoder` does.
- **Defaults** are Node v24's: `highWaterMark` 64 KiB (16 KiB on
  Windows), 16 in object mode. TDD-00231 said 16 KiB; Node raised it in
  v22.
- **Codegen is deleted:**
  - `emit_node_stream_class.go` (the synthetic-root class model);
  - `NewNodeStreamExpression` and sema's `Readable`/`Writable`/
    `Transform`/`PassThrough`/`Duplex` builders;
  - the `stream`/`stream/promises` module calls, `Readable.from`/
    `fromWeb`, `duplexPair`;
  - `ClassInfo`'s stream flags and the classes' hidden stream-handle
    field (`ClassNodeStreamField`, `HasNodeStream`).
- **What stays in codegen.** `emit_node_stream.go` and
  `runtime_node_stream.go` remain the handles behind
  `fs.createReadStream`/`createWriteStream` and the HTTP server's `req`
  and `res`. They move onto the TypeScript classes with `fs` and `http`
  (TDD-00231 stage 4).
- **Tests and examples are Node's forms.** Every Node-stream E2E test and
  example is rewritten the way Node code writes it: options with `this`,
  `write(chunk, encoding, callback)`, class overrides with Node's
  parameter types, and `import type` for type-only names. Each expected
  output is Node v24's. Two tests asserting rejections that Node does not
  make are deleted: a two-parameter `write` sink, and the `latin1`
  encoding. `TestE2ENodeStreamWriteEncodings` replaces them.

## Implementation notes

- The module uses no construct the compiler does not support for user
  code. Where the port hit a gap, the gap is fixed in the compiler
  (ADR-01162), not worked around in the module. The one exception is
  `fromList`, which reads buffered chunks through typed locals: a method
  call on a primitive held in `any` is BACKLOG's primitive-member
  dispatch item.
- `Pipe` exists because a capturing arrow could not call one declared
  after it. That is fixed now (ADR-01162); `Pipe` stays, being as clear.

## Side effects discovered

- An omitted error argument arrives as `null` in a callback declared
  `(err?: Error | null)`; Node passes `undefined` (`finished`,
  `pipeline`, the `write`/`end` callbacks). This is the reference
  three-state representation of TDD-00230 P3.3 (BACKLOG).
- fs streams and the HTTP `req`/`res` are not instances of these classes
  (the status page's Node-stream row).

## Verification

- **Node:** the 31 Node-stream tests' programs and the five rewritten
  examples print exactly what Node v24 prints. A comparison program
  covering options and class forms, `setEncoding`, `pipeline`, `finished`
  and `for await` matches except for the `null`/`undefined` above.
- **Tests:** `tests/node_stream_test.go` (31 tests). The stream,
  pipe, EventEmitter, override and fs-stream test groups pass, and so do
  `TestE2EStreamFinishedFollowsEnd` and the `sema`, `parser`, `resolver`,
  `checker`, `codegen` and `lib` packages.
- **tsdiag, TS 7.0.2 corpus:** 3,157 diagnostics, all matching, 0 false
  positives (3,145 before).
- **Conformance (Mac):** Node's test suite, strict lane 64 → 87 passing
  files (`stream` 0 → 17, `buffer` 2 → 4, `fs` 4 → 5), js lane 65 → 92;
  no directory lost a pass. Test262 strict 7,035 → 7,126, js 7,834 →
  7,838 (with ADR-01162–01165).
- **Gates:** `make examples` 358/360 on the pre-fix snapshot (the two
  failures are fixed or flaky); `make test-par`: only the four known
  `-mm=gc` failures (BACKLOG 11). Verified on the Mac.
