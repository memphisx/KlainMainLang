# ADR-01867: `fs.promises` through the oracle: overloaded function values and mixed unions

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's ObjectLiteral bucket, reached by every program importing `fs`)
- **Date**: 2026-10-21

## Context

`node:fs`'s `promises` object literal was unanswered by the oracle, for three reasons:

- An overloaded function's value is held by its implementation signature (`appendFile(path: any, data: any, options?: any)`), which the checker's overload-set type does not carry.
- A union with a Buffer or typed array beside strings and a class (`string | Buffer | URL`, `PathLike`) was rejected: any array member stopped the mapping, though resolveType boxes one host array with the rest.
- Strings beside one plain object (`BufferEncoding | ObjectEncodingOptions`) were rejected, though resolveType boxes them as a string and an object member.

## Decision

- The checker exposes `ImplementationSignature(fd)`. An object literal (or a `const` binding of one) whose type does not map is its properties' answers in order; a property whose type does not map takes its value's answer, or, for an overloaded function's name, its implementation signature.
- A union box may hold one Buffer or typed array; two arrays still have no box.
- Strings beside one plain object map to the box of a string and that object.

## Consequences

- `import { promises } from "fs"` leaves the shadow report; `TestE2EHTTPUnion*` (two array members) still compile through codegen's own answer.
- Verified on Apple Silicon.
