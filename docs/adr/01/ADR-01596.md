# ADR-01596: A library call prefers the instance's own method

- **Date**: 2026-10-12

## Context

Node's stream tests set a hook on an instance (`r._read = fn`,
`w._write = fn`) and expect the library to call it. Ours threw
"The _read() method is not implemented". Five node-suite files that the
staged reports counted as passing failed, among them
test-stream2-read-sync-stack and test-stream-big-push.

## Investigation

A class method call checks for an own property of the method's name only
when the program assigns that name (`jsMemberWritten`).

Library code compiles to units shared by every program (ADR-01326), so
its calls skipped the check: they always took the class's method.

## Decision

- **Library call sites** read a per-name i8 global, `__kml_mw.<name>`, and
  look up the own property only when it is set. The program's unit
  defines it (1 when the program assigns the name), so the library units
  stay identical across programs.
- **The own arm** calls the property as a plain function value
  (`emitDynAnyMethodCallPlain`), not through a builtin method of the same
  name (`some`).
- **A call with a function-literal argument** keeps the class call: both
  arms would emit the literal's closure. So the stream library passes its
  hook callbacks (`_write`, `_final`, `_flush`, `_transform`) as consts, as
  Node's own code passes `state.onwrite`.

## Verification

- TestE2ELibraryInstanceOwnMethod passes, along with the stream, pipe,
  transform and instance-override E2E tests on the Mac.
- The node-suite stream files pass again.
