# TDD-00190: `klain:ffi` — FFI capabilities beyond `node:ffi`'s surface

- **Status**: Not Started
- **Date**: 2026-09-09

## Context

`node:ffi` ([TDD-00164](TDD-00164.md), Stage A shipped in
[ADR-00797](../adr/ADR-00797.md)) is kept strictly Node-conformant: a program
using Node's FFI compiles here unchanged, and nothing non-Node is added to
that module's surface (the namespace rule, [TDD-00131](TDD-00131.md)). But
Node's surface is primitives-only, and a survey against the field (koffi,
node-ffi-napi, Deno FFI, Bun FFI) shows real-world C interop needs more. This
TDD scopes those extensions under `klain:ffi` — a superset module that
re-exports `node:ffi` and adds the missing capabilities, so a program opts
into non-portable surface by its import specifier, exactly the `klain:http`
posture.

The gap matrix (what `node:ffi` lacks; ✓ = who has it):

| Capability | koffi | ffi-napi | Deno | Bun | Notes |
|---|---|---|---|---|---|
| Struct **by value** (args + returns) + `sizeof`/`alignof`/`offsetof` | ✓ | ✓ | ✓ | — | the biggest hole; without it `struct timespec`/`stat`/sockaddr/small-struct-return ABIs need hand-written C shims |
| Packing control / unions / fixed arrays | ✓ | ✓ | part | — | `#pragma pack` Win32 structs, wire formats |
| `errno` / `GetLastError` captured **atomically** with the call | ✓ | ✓ | — | — | essentially every POSIX call reports through errno; runtime code may clobber it between call and read |
| Thread-safe callbacks | part | ✓ | ✓ | ✓ | audio/GPU/device libs fire callbacks off-thread; `node:ffi` callbacks are same-thread-only by rule |
| Non-blocking (pooled) calls | ✓ | ✓ | ✓ | — | a long native call stalls the reactor; the TDD-00185 thread pool is a natural reuse |
| Variadic calls (`printf`, `open(path, flags, mode)`, `fcntl`) | ✓ | ✓ | — | — | explicitly unsupported in `node:ffi` |
| Typed non-function symbol data | ✓ | ✓ | ✓ | part | Deno's `{ type: 'i32' }` static-symbol defs are the ergonomic model; raw peek/poke over `getSymbol` works today but is untyped |
| Wide strings (UTF-16 / Win32 `*W` APIs) | ✓ | ✓ | — | — | relevant to the Windows-fidelity track |
| Output-param sugar (`_Out_` decode-after-call) | ✓ | — | — | — | ergonomics over raw pointers; tail |
| Auto-free ownership hints for returned buffers | ✓ | — | — | — | tail |

The structural advantage worth stating up front: every V8-hosted FFI does
these through libffi trampolines and runtime marshalling. Here a signature is
a compile-time constant lowered to direct LLVM — struct-by-value is *just the
aggregate C ABI the backend already speaks* for its own runtime calls, and
adding a struct type to a signature is codegen, not a runtime library. Several
"hard" rows above are cheaper in this compiler than anywhere in the Node
ecosystem, which is exactly the kind of options-as-differentiator surface
worth owning ([TDD-00133](TDD-00133.md)'s identity argument).

## Design

`import ffi from 'klain:ffi'` re-exports all of `node:ffi` (same emitters,
same marker machinery) plus, in priority order:

1. **Structs**: `ffi.struct(name, { field: type, ... })` returning a type
   usable in signatures by value or as `pointer`; `ffi.sizeof/alignof/offsetof`
   as compile-time constants; JS object ↔ C struct marshalling derived from
   the field list at compile time (the same static-object-literal discipline
   signatures already have). Packed variant via an options bag. Unions and
   fixed-size array fields ride the same declaration form, later stage.
2. **`ffi.errno()` + per-call capture**: an opt-in signature flag
   (`{ ..., errno: true }`) that saves `errno` into the returned wrapper
   immediately after the call instruction, before any runtime code can run —
   only reliable when emitted inline, which this backend can do and a JS
   runtime cannot.
3. **Non-blocking calls**: `ffi.async(fn)` (or a `nonblocking` signature flag,
   Deno-style — pick one) returning `Promise<T>`, dispatched on the TDD-00185
   pool.
4. **Variadic calls**: per-call-site promoted types, koffi-style
   (`fn(fixed..., ...pairs)` or a `variadic: true` signature + explicit
   per-call arg typing) — AOT needs each call site's full type list, which is
   statically visible anyway.
5. **Typed data symbols**: `getData(name, type)` / Deno-style typed entries in
   the `dlopen` definitions map.
6. **Thread-safe callbacks**: extends TDD-00164 Stage C's trampoline with a
   marshal-to-reactor option; designed *with* Stage C, shipped after it.
7. **Wide strings** (`str16`), output-param sugar, disposables: tail, pulled
   forward only when a concrete consumer (Win32 track, a real library
   binding) demands them.

Hard dependency discipline: nothing here starts before `node:ffi` Stages B–C
close ([TDD-00164](TDD-00164.md) is not done until `registerCallback` ships,
and this module must never become the excuse to leave the Node-faithful
module's hard part unfinished).

| Dependency | Status | Notes |

## Open questions

- **Struct ABI coverage**: small-struct-in-register rules differ per arch
  (SysV vs AAPCS64); clang handles them when given the LLVM aggregate type —
  confirm the text-IR path produces the classified ABI (byval/sret attributes)
  or whether signatures must emit those attributes explicitly.
- **`errno` flag vs ambient `ffi.errno()`**: the flag is the only truly atomic
  form; is the ambient getter worth having at all if it can lie?
- **Variadic surface**: signature-declared (`variadic: true` + per-call types)
  vs koffi's inline pairs — pick the one that stays statically checkable.
- **How much lands back in `node:ffi` later**: if Node's experimental module
  grows structs or async natively, the `klain:ffi` form should be deprecated
  in favour of the faithful one — design the declaration syntax to shadow
  Node's plausible direction (Deno-style `{ struct: [...] }`) to keep that
  migration cheap.
