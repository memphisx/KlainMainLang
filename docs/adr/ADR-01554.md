# ADR-01554: Uninferred type parameters, overload type parameters, empty array elements

- **Relations**: Extends ADR-01552, TDD-00230
- **Date**: 2026-10-10

## Context

- A type parameter that no argument gave a candidate stayed open while a
  context-sensitive argument was typed: `Array.from({ length: n }, (_, i)
  => i * i)` typed its callback `any` and the call `any[]`, where
  TypeScript fixes `T` (unknown) first and gets `number[]`. With no
  context-sensitive argument at all, the first inference pass already
  sees every argument, yet left such a parameter open, and the overload
  result refused an `unknown` inference outright: `Array.from({ length: 2
  })` was unanswered, TypeScript's `unknown[]`.
- An overload set of repeated `declare function f<T>(…)` signatures took
  fresh type parameters for each signature while its parameters and
  result kept the binder's: nothing inferred reached the result (`T[]`
  left uninstantiated).
- An empty array element (`[[], [1]]`) left the literal unanswered; in
  TypeScript it is `never[]`, which subtype reduction drops beside another
  array (`number[][]`). Codegen read the empty element as `number[]`, so
  `[[], ["x"]]` became `any[]` instead of `string[][]`.
- The checker-side mapping had no tuple representation.

## Decision

- A type parameter with no candidate is fixed (its default, else unknown,
  else its constraint when unknown does not satisfy it, as tsc's
  getInferredType) before a context-sensitive argument whose contextual
  signature takes it as a parameter is typed, for a generic and an
  overloaded callee alike; one that occurs only in the callback's result
  is left to be inferred from it. Inference is complete in one pass when
  no argument is context-sensitive, and an overload's result instantiates
  an `unknown` inference.
- A type parameter is fixed, and an overload taken on an `unknown`
  inference, only when each non-callback argument that could have
  inferred it has a whole type (an object literal's): a library type
  lists part of its members, so its fitting `ArrayLike<unknown>` is not
  proof. An overload that left such a parameter without a candidate is a
  weak fit, taken only when no overload fits better.
- `Iterable<T>` (and `IterableIterator`, `IteratorObject`) infers `T` from
  what iterating the argument yields, and the iterated type covers a Map
  (`[K, V]`), a Set, a typed array, a tuple and an object with its own
  `[Symbol.iterator]`: `Array.from(map.values())` is `string[]`, not the
  first overload's `unknown[]`.
- A signature the binder saw keeps its own type parameters in its
  overload set.
- An empty element with no contextual type is `never[]`, dropped from the
  element type when another array or tuple element is present; codegen
  infers such a literal from its other elements.
- The checker-side mapping answers a tuple where codegen stores one: a
  type an annotation declares (a binding's, a global's, a function's
  declared return through a call), an unannotated binding as its
  initializer is held, and an array literal of such tuples.
