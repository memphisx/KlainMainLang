# ADR-01016: Recursion guard + rest-flag fidelity in nested-function signature inference

- **Relations**: Fixes a crash in ADR-01014 (letrec hoisting); Relates to TDD-00129, ADR-00041 (unannotated return inference)
- **Date**: 2026-09-18

## Context

ADR-01014's letrec identifier lookup calls `buildFunctionSig` for a capturing
nested declaration referenced before it is bound. For a **self-recursive
unannotated** nested function (`function f(n) { if (n > 0) return f(n - 1);
return x; }`), that lookup re-enters `buildFunctionSig` for the same
declaration from inside its own return-type inference
(`inferUnannotatedReturnType → inferBlockReturnExpr → inferExprType →
buildFunctionSig …`) without bound — a compiler stack overflow. The full
Test262 run crashed the conformance runner on the first such corpus file
(~40k/53k in). A second gap compounded it: the call-expression inference never
consulted the letrec capturing set at all, so `f(n - 1)` in value position
fell through to the scalar i64 default — a string-returning recursive nested
function emitted `ret ptr` in an `i64` function (invalid IR).

## Decision

- **Guard**: `e.sigInferInProgress` marks each declaration while
  `buildFunctionSig` infers its unannotated return type. Re-entry for the
  same declaration keeps the void default and sets `e.sigInferCycleHit`.
- **Candidate fallback**: `inferCandidateReturnExpr` (now used by both
  `inferUnannotatedReturnType` and its pattern-aware sibling) detects the
  cycle flag and retries with each later return expression
  (`returnExprsInBlock`, a source-order collector mirroring
  `firstReturnExprInStmt`'s shapes) until one infers cleanly — so a function
  whose FIRST reachable return is the recursive call infers from its base
  case. All candidates poisoned (purely self-recursive) ⇒ void default.
- **Call-site letrec inference**: the identifier-callee branch of the
  call-expression inference now checks the innermost capturing set (after
  `resolveFuncRef`/generic/closure lookups, before the scalar fallback) and
  returns `buildFunctionSig(fd).RetType`, mirroring the identifier case.
- **Rest flag survives type inference.** The full-run sweep surfaced a second
  invalid-IR bug in the same area: every site building a closure Type from a
  `FuncSig` via `FuncType(sig.ParamTypes, sig.RetType)` dropped `HasRest`
  (the letrec identifier case, `inferBlockReturnExpr`'s escaped-by-name
  binding, and the two `typeof`-resolution sites), so a nested function that
  reads `arguments` (implicit `any[]` rest, TDD-00210) and escapes by name
  was called through a fixed-arity type — the caller coerced the first
  argument as if it were already an array header (Test262
  `language/statements/function/S13.2_A2_T1.js`, `extractvalue` on a plain
  string pointer). All four sites now mirror `emitNamedFunctionValue` and
  copy `sig.HasRest` onto the type.
- **Mutual recursion stays a clean error.** Two mutually-recursive capturing
  siblings would need a shared self-capture cell to emit (on-demand emission
  recurses f→g→f). `letrecEmitCapturingNested` deliberately scans only the
  innermost scope's capturing set; the cross-sibling case is a clean
  "undefined function or closure" compile error, recorded as the open
  letrec residue.

## Consequences

- Self-recursive unannotated capturing nested functions compile and match
  Node byte-exactly (scalar and string base cases verified against the node
  oracle on macOS arm64).
- Tests: `TestE2ENestedFunctionCaptureSelfRecursive`,
  `TestE2ENestedFunctionMutualRecursionRejected` (tests/func_test.go).
- The nested-function status row gains the mutual-recursion caveat alongside
  the TDZ posture.
