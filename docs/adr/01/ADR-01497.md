# ADR-01497: `x.constructor` of a builtin-made value

- **Relations**: Extends ADR-01204
- **Date**: 2026-10-09

## Context

`o.constructor` of an object literal, `arr.constructor`,
`m.constructor` of a Map and `"s".constructor` failed to compile ("no
field 'constructor'"). Through `any`, a string's, number's or boolean's
`constructor` was undefined, so `.name` threw.

## Investigation

- A class instance already answered through its type id
  (`__kml_constructor_of`), and an `any` holding a host object (a Map, a
  Date) through its host class name.
- A static object no class made has no type-id row, so its `constructor`
  through `any` was undefined; Node answers `Object`.
- A primitive box had no answer at all.
- `String`, `Number` and `Boolean` as values are their conversion
  functions, function objects. A primitive's `constructor` here is the
  builtin's name reference (what `Map` and `Object` are), so identity
  with the conversion function does not hold (BACKLOG 126).

## Decision

- `x.constructor` of a value no class of the program made (an object
  literal, an array, a Map or Set or other host object, a string, number
  or boolean) is read off its box (`builtinCtorRead`).
- Through `any`: a primitive answers `String`, `Number` or `Boolean`; a
  static object no class made answers `Object`.

## Side effects discovered

None.

## Divergences

- BACKLOG 126: a primitive's `constructor` is not identical to its
  conversion function.

## Implementation notes

codegen/llvm/emit_exprs_member.go (`builtinCtorRead`), emit_exprs_types.go,
emit_dynobj.go (`emitDynAnyMemberGetInline`); BACKLOG 126 narrowed.
