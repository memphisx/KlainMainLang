# ADR-00361: Hide HttpRequest's internal fields from Object.keys/JSON

- **Date**: 2026-08-25

## Context

`Object.keys(req)` / `JSON.stringify(req)` / `{...req}` on an `http.listen`
handler's `HttpRequest` exposed two implementation-only fields —
`bodyLength` and `__kml_bodyctx` — alongside the real surface
(`method`/`path`/`query`/`headers`/`body`). One of the caveats on the
`req.stream()` HTTP-Server row (the status text named only `__kml_bodyctx`; a
direct check showed `bodyLength` leaked too).

## Investigation

`Type.VisibleFields()` (`types.go`) already filters implementation fields for
class/error/regexp/EventSource/WSConnection/WebSocketClient/XHR types (and
`#`-private fields), and every enumeration path — `Object.keys`
(`emit_objects.go`), `JSON.stringify` (`emit_call_json.go`), spread
(`emit_objects.go`) — goes through it. `RequestType` (`IsRequest`) simply had no
case, so all seven fields were visible. Confirmed with a live server:
`Object.keys(req)` returned `method,path,query,headers,body,bodyLength,__kml_bodyctx`.

`.bodyBytes()`/`.stream()` read `bodyLength`/`__kml_bodyctx` via
`FieldIndex` directly, not `VisibleFields`, so hiding them from enumeration
doesn't affect those accessors.

## Decision

Add an `IsRequest` case to `VisibleFields()` that keeps the first five fields
(`method`/`path`/`query`/`headers`/`body`) and drops the trailing two
implementation fields. After it, `Object.keys(req)` returns exactly
`method,path,query,headers,body`.

## Implementation notes

- One case in `types.go`'s `VisibleFields()`, guarded `len(fields) > 5`.
- A suffix trim rather than the other cases' prefix trim (Request's internal
  fields are last, not first) — the surrounding `#`-private filter still runs.

## Verification

- `TestE2EHTTPRequestObjectKeysHidesInternals` (new): `Object.keys(req)` equals
  `method,path,query,headers,body` and contains neither internal field.
- `HTTP|Object|JSON|Spread|Stream|Request` suites pass.
- `go build`/`go vet` clean.
