# ADR-00768: fs errors carry `err.syscall` and `err.path`

- **Relations**: extends [ADR-00684](ADR-00684.md) (the Node error-code trio `code`/`errno`/`errstr` on fs errors) and [ADR-00021](ADR-00021.md) (surfacing an OS failure as a catchable Error); addresses [TDD-00180](../tdd/TDD-00180.md) §4
- **Date**: 2026-09-07

## Context

Node's fs errors expose more than `err.code`/`err.errno`: every failure from a
path- or fd-based `fs.*` call also carries `err.syscall` — the **bare syscall
name** that failed (`'open'`, `'stat'`, `'scandir'`, `'unlink'`, `'mkdir'`, …) —
and `err.path`, the offending path. Both are load-bearing in real code:
`if (e.code === 'ENOENT' && e.syscall === 'open')` distinguishes a missing file
from a missing directory in a readdir, and tooling logs `e.path` to say *which*
file was missing. The port set `code`/`errno`/`errstr` ([ADR-00684](ADR-00684.md))
but left `err.syscall` and `err.path` unset (read back as `null`), the last of the
`fs`-error-shape gaps in [TDD-00180](../tdd/TDD-00180.md) §4.

## Investigation

Every `fs.*` (and `os` proc-file read, and `process.chdir`) failure funnels
through one emitted helper, `__kml_fs_throw(opdesc, path)` (`runtime_fs.go`),
which builds the Node-shaped message and the `errorObjType` instance. The path
was **already** passed to it at all ~35 call sites (it goes into the message) but
was thrown away after formatting; the syscall name was nowhere — each call site
interns a *human* description (`"cannot stat path"`), not the bare syscall Node
reports. `errorObjType` (`emit_exceptions.go`) is the single shared Error struct;
its fields 3–5 (`code`/`errcode`/`errstr`) are precedent for carrying fs-specific
slots on the shared type, resolved by name through `Type.FieldIndex` so
`err.syscall`/`err.path` member reads need no special-casing once the fields
exist.

## Decision

- **Two new `errorObjType` fields.** `syscall` (idx 6) and `path` (idx 7), both
  `ptr`, appended after the error-code trio. `buildErrorObj` default-inits both to
  `null`, so an ordinary `new Error()` reads `err.syscall === null`,
  `err.path === null` (Node reports `undefined`; the port's null is the same
  falsy observable it already uses for an unset error slot). Member access
  resolves via `FieldIndex` — no new interception.
- **`__kml_fs_throw` gains a `syscall` param** → `(opdesc, syscall, path)`,
  storing `syscall` into field 6 and the already-passed `path` into field 7. All
  ~35 call sites (in `runtime_fs.go`, `runtime_fs_stream.go`,
  `runtime_fswatch.go`, `runtime_os.go`, `runtime_process.go`) pass the bare Node
  syscall name for that operation: `open`/`read` (readFile, EISDIR-guard),
  `open` (write/append/streams), `stat`/`lstat`/`fstat`, `scandir` (readdir),
  `unlink`/`rmdir`/`mkdir`/`rename`, `mkdtemp`/`symlink`/`link`/`readlink`/
  `chmod`/`access`, `utime` (utimes), `fsync`/`ftruncate`, `watch` (fs.watch),
  `chdir` (process.chdir).
- **AggregateError allocation bumped 40 → 64 bytes.** The AggregateError struct
  is a separate 5-field allocation typed `errorObjType` at read time; sizing it
  to the full `errorObjType` keeps a (non-meaningful but bounds-safe) read of any
  trailing field — now including `syscall`/`path` — inside the buffer, the same
  guarantee the pre-existing `code`/`errcode`/`errstr` reads relied on.

## Faithfulness notes

- The syscall names match Node for the common, testable operations exactly
  (Node's `readdir` reports `scandir`, not `readdir`; `realpath` reports `lstat`).
  A few rare paths use the direct syscall we invoke where nobody exercises the
  quirk: `fs.truncateSync` reports `open` (matching Node, which opens then
  `ftruncate`s), while `fs.rmSync`'s single failure label reports `unlink` even
  when the failing step was the trailing `rmdir` of an emptied directory — a
  documented simplification, not a divergence in the tested surface.
- fd-based ops (`read`/`write`/`fstat`/`fsync`/`ftruncate`) carry the syscall
  name but a null/empty `path` — Node's fd errors have no `path` either.

## Verification

- New E2E test `TestE2EFsErrorSyscallAndPath` (`tests/fs_test.go`): `read`→
  `open`, `stat`→`stat`, `unlink`→`unlink`, `mkdir`→`mkdir`, `readdir`→`scandir`,
  each with the offending path; a plain `throw new Error()` reads `null`/`null`.
- `examples/fs/fs.ts` extended to print `e.code`/`e.syscall`/`e.path` on a failed
  read; compiles and runs.
- Manual repros on **Windows 11 native** (the shim sets Linux errno + echoes the
  path verbatim, so the shape is identical to POSIX). Full `Fs`/`Error`/
  `Exception`/`Aggregate`/`Sqlite` and `Os`/`Process`/`StructuredClone`/`Watch`/
  `Stream` suites green on Windows 11 (the shared-`errorObjType` change is broad).
  `go build`, `go vet ./codegen/...` clean.
- `make status`/`status-check`, `make reference-check`, `make conformance` run at
  delivery.
