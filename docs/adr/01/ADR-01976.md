# ADR-01976: Inference widens only fresh literals

- **Relations**: Implements TDD-00230; follows [ADR-01975](ADR-01975.md)
- **Date**: 2026-11-07

## Context

An inferred type argument widened every literal candidate. tsc widens only
fresh ones, the types of literal expressions (getWidenedLiteralType): for
`f<U>(a: (e: 0 | 1) => U): Box<U>`, `f((q: 0 | 1) => q)` is `Box<0 | 1>`,
and here it was `Box<number>`. A literal from a declared type was lost the
same way through a plain argument (`g(k)` with `k: 'x' | 'y'`).

## Decision

- Inference records, for each argument, which of its literal types are
  fresh and which regular. It reuses the syntactic freshness that
  `widenFrom` already applies to mutable bindings (`freshLiterals`).
  - A function argument's literals are those of the values it returns.
  - With a return annotation, they are the annotation's, and so regular.
- When a type parameter's candidates widen, a literal that only a regular
  source gave stays.
- Async and generator function arguments keep the old widening.

## Consequences

- Covered by two cases in the checker's `TestCheck`, each checked against
  tsc.
- Freshness stays syntactic, not a property of the type: a literal that is
  both fresh and regular across arguments widens.
