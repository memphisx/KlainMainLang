# ADR-00336: Deduplicate the getaddrinfo/freeaddrinfo externs

- **Date**: 2026-08-24

## Context

The Release CI (Linux) build failed on the "Process/CLI completion + spread
into rest parameters" commit. `go test ./...` reported clang errors of the form
`invalid redefinition of function 'getaddrinfo'` for the net, dns, and dgram
E2E suites. The build passed on the Mac dev machine, so the failure was
Linux-only and only surfaced in CI.

## Investigation

Two runtimes emit the extern declaration for `getaddrinfo`/`freeaddrinfo`:

- `runtime_dns.go:40` — unconditionally, inside `ensureDNSRuntime`.
- `runtime_websocket_client.go:107` — but only when `runtime.GOOS != "darwin"`.

The websocket-client runtime's `!= "darwin"` guard is why the clash never
reproduced on the Mac: there, only the DNS runtime emitted the declares. On
Linux, a program pulling in both runtimes emitted the declaration twice, and
clang rejects the redefinition. `emitGlobal` (`emitter.go:688`) just appends,
so it offers no dedup of its own — the `ensure*()` convention is how the
codebase declares a C extern exactly once.

## Decision

Add a shared, idempotent `ensureGetaddrinfo()` helper guarded by a new
`getaddrinfoDeclared` emitter flag, and route both call sites through it. Same
pattern as every other `ensure*()` extern declarer.

## Implementation notes

- `emitter.go`: new `getaddrinfoDeclared bool` field.
- `runtime_dns.go`: new `ensureGetaddrinfo()`; `ensureDNSRuntime` calls it.
- `runtime_websocket_client.go`: `!= "darwin"` branch now calls the helper.

The Darwin-only guard in the websocket client is preserved as-is — on Mac the
declaration is still emitted only via the DNS path.

## Verification

`go build`, `go vet ./codegen/...`, and the previously-failing net/dns/dgram
E2E tests pass on the Mac. The Linux path could not be exercised locally
(Docker daemon not running this session); the fix is platform-independent —
a single idempotent guard — and the Linux failure was strictly a
double-emission, now impossible.
