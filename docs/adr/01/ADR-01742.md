# ADR-01742: Static reads see a field's shadow; `++` on an `any` member is numeric

- **Relations**: `Implements TDD-00230`, Extends [ADR-01215](ADR-01215.md), Extends [ADR-01741](ADR-01741.md)
- **Date**: 2026-10-19

## Context

A value of another kind written into an object's field through `any` (`a.x = "s"` for a `number` field) is kept beside the layout as a shadow (ADR-01215). Dynamic reads saw it, and so did `typeof o.x`, but the object's own statically typed reads did not: `o.x` still read the old value, and `o.x + 1` was `2` where Node gives `"s1"`.

While checking compound updates, `a.n++` on an `any` member holding `"5"` turned out to concatenate (`"51"`) instead of applying ToNumber (`6`). `++` on an `any` identifier was already right.

## Decision

- **Which keys.** A pre-pass collects the keys of writes that can store a value of another kind:
  - writes through `any`: `a.x = v`, `a["x"] = v`, `a.x op= v`, `a.x++`;
  - writes through a structural type whose member is a union or `any`: `v.x = "s"` with `v: { x: number | string }`.
  - Private names (`#x`) never count, since they have no dynamic access. The structural rule applies only to an interface or type-literal view, never to a class's own field: that field's layout already holds the union or `any` it declares.
- **Shadow-aware reads.** A static read of a primitive-kind field under one of those keys reads the field, boxes it, and takes the object's shadow instead when it has one. The read is a box: it is typed `any` in inference and in the type oracle, and the checker's primitive is not re-imposed on it. A receiver with effects is evaluated once.
- **The read hook.** `__kml_shadow_get_hook` is a weak pointer, set together with the unshadow hook when the first shadow of a field is made. A program that never shadows a field pays one load per such read.
- **Compound writes and updates** to such a field go through the object as `any`: `(o as any).x op= v`, `(o as any).x++`. The read sees the shadow, and the write stores the field, or the shadow, as the result's kind decides.
- **`++`/`--` on an `any` member** step by ToNumeric, the path an `any` that may hold a BigInt already took. The BigInt branch is emitted only when the program can hold a BigInt, so a program without one does not link the BigInt runtime.

A write under a key computed at run time (`a[k] = v`), and a shadow of a field holding an object or a function, are still not seen by static reads. They stay a caveat on the class row. A box placed in a typed container literal (`[o.x]`) is converted to the container's element type; that is a BACKLOG item for P3.3's container representation.
