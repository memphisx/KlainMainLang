# ADR-00708: TDD-00174 Stage A — dev-default differential mode knobs (+ `??`/`||`/`&&` autofree fix)

- **Relations**: Implements TDD-00174 (Stage A); Extends ADR-00702, ADR-00704, ADR-00705
- **Date**: 2026-09-04

## Context

TDD-00174 gates flipping the shipped default to `-mm=auto -optimize-memory`
on manufactured maturity evidence, and its Stage A is a no-gate move that
makes `auto` the default *inside this repository* so every feature and fix is
exercised against it as a side effect of normal development. The claim that
`auto` (and `-optimize-memory`) change only the allocation/free profile, never
observable behavior, is itself a free test oracle: any program whose output
differs between modes has found a bug. Stage A needs the plumbing to actually
run each corpus this project owns in a second mode.

## Investigation

Two switch points had to grow a mode knob without disturbing the mode-pinned
paths:

- The examples runner (`Makefile`) compiled every program in default mode
  only. It needed a per-run mode selector, and two programs
  (`examples/memory/memory_free.ts`, `examples/finalization/finalization_registry.ts`)
  call `Memory.free` by design, which is a compile error under `-mm=auto`
  (TDD-00173 exclusivity) — they must stay pinned to manual.
- `buildBinary` in `tests/compiler_test.go` is the generic E2E emitter; the
  mode-specific helpers (`buildBinaryGC`, `buildBinaryOptimizeMemory`, …) each
  construct their own `Emitter` and set their own mode. An env knob had to
  reach only `buildBinary`, never the pinned helpers.

The first auto-mode differential run over the examples corpus immediately
earned its keep: `examples/nullish` (`greet(x) ?? 'default'`) aborted at
block exit. Root cause in `autoFreeOwningInit` (`emit_autofree.go`): the
`*ast.BinaryExpression` arm returned `true` unconditionally, classifying every
binary initializer of a freeable type as owning fresh heap. That holds for `+`
(concatenation allocates), but `??`/`||`/`&&` yield one of their *operands* —
an alias of another binding or an interned literal — so the inserted
block-exit free double-freed or freed non-heap memory. This is exactly the
use-after-free class TDD-00174 warns is auto's asymmetric downside, and the
differential lane surfaced it on its first pass — the mechanism working as
designed.

## Decision

- **Examples lane** (`make examples MM=auto OPTMEM=1`): `MM` (manual/auto) and
  `OPTMEM` compose into `MODEFLAGS`, prepended to every compile. `gc` stays
  out (needs per-machine libgc + its own suite). The two `Memory.free`
  programs use `MODEFLAGS_NOMM` (keeps `-optimize-memory` if set, drops the
  `-mm`) so they compile manual regardless of `MM`.
- **E2E lane**: `applyTestModeEnv` reads `KLAIN_TEST_MM=manual|auto` and
  `KLAIN_TEST_OPTMEM=1` and applies them to `buildBinary`'s emitter only.
  `KLAIN_TEST_MM=auto KLAIN_TEST_OPTMEM=1 make test-par` runs the full suite
  as a mode-differential lane; assertions are unchanged, so a mode-sensitive
  failure is the finding. `gc` is deliberately not env-selectable (extra link
  flags, per-machine libgc, own suite).
- **Autofree fix**: `autoFreeOwningInit`'s binary arm returns `x.Op == "+"`.
  Comparisons and arithmetic never pass the freeable-type gate, so `+` is the
  only owning binary initializer; the value-selecting operators are treated as
  non-owning (their result may alias or intern, so it is not auto-freed).

## Implementation notes

- `Makefile`: `MM`/`OPTMEM` vars, `MODEFLAGS`/`MODEFLAGS_NOMM`, threaded into
  the base, `-compat=js`, and `-decorators=standard` example passes.
- `tests/compiler_test.go`: `applyTestModeEnv`, called from `buildBinary`.
  The mode-pinned helpers are untouched.
- `codegen/llvm/emit_autofree.go`: the binary-arm narrowing to `+`, and an
  earlier guard skipping registration when the initializer was stack-planned
  (`e.stackAllocatedLits[v.Init]`) — freeing an alloca would corrupt the heap.

## Side effects discovered

- The `??`/`||`/`&&` autofree bug (fixed here) was a real use-after-free
  reachable only in auto mode; found and fixed on the first differential run.
- Stage A verification only; the shipped default (Stage B) remains gated on
  TDD-00174's exit criteria (N=3 releases of green differential/ASan/fuzz/soak
  lanes on both machines). The remaining lanes (conformance flip-diff, fuzz
  Lane C, `-debug-frees` census, klainload soak) are not yet built.
