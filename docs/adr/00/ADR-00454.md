# ADR-00454: `var` exempted from definite-assignment (no TDZ)

- **Relations**: Extends [ADR-00215](ADR-00215.md) (TDD-00071); Extends [ADR-00452](ADR-00452.md) (the generic depth cap it retunes)
- **Date**: 2026-08-29

## Context

`variable '%s' is used before being assigned` was the largest remaining
TS-oracle false-reject bucket (250). The cases are old-corpus `var`
patterns (`var union: string | string[]; for (const v of union)`) — legal
JS, accepted by TS.

## Decision

JS gives `var` no temporal dead zone: it is hoisted and
undefined-initialized, so a read before assignment is *legal* and this
compiler already gives it a deterministic zero/undefined default
(ADR-00215). The definite-assignment analysis (TDD-00071) had lumped `var`
in with `let`; it now never tracks `var` bindings — `let`/`const` (real
TDZ) keep full enforcement. This is a deliberate policy revision toward
JS fidelity: TDD-00071's flagship conditional-`var` rejection test becomes
a positive test asserting the zero-default read (`0` then `42`).

## Side effects discovered

Un-gating unassigned `var`s of recursive generic types exposed the
ADR-00452 depth cap as exponentially wrong: `interface List<T> { next:
List<T>; owner: List<List<T>> }` (the corpus's `infinitelyExpandingTypes1`)
has *two* recursive fields, so eager expansion costs O(2^depth) type nodes
— at cap 32 the oracle run was OOM-killed (`signal: killed`). The cap is
now 8 (256 nodes worst-case), which compiles the case in milliseconds.

## Trade-off, disclosed

TS oracle agreement moved only +1 net (match-accept 1383 → 1444, but ~60
formerly-matching rejections of strict-mode cases now compile clean and
count as false-accepts). The change is kept for semantic fidelity — the
new acceptances are legal JS/non-strict TS — and because the remaining
var-blocked cases now surface their next blockers instead of dying here.

## Verification

Mac. Updated `tests/func_test.go` flagship test
(`TestE2EDefiniteAssignConditionalVarAllowed`); `let` rejection tests
unchanged and green; var/let/const/for/switch E2E batch green. TS oracle
55.2% (composition shift as above); Node oracle unchanged (37).
