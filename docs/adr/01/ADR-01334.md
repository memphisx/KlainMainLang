# ADR-01334: Closure-converted local classes, `.bind` over any parameter list, and `void`

- **Relations**: Extends ADR-01333, TDD-00137
- **Date**: 2026-10-02

## Context

[ADR-01333](ADR-01333.md) hoisted a class declared in a function body when
it names none of the function's locals, and left one that does as
"unknown class". `.bind` rejected a function with a rest, array or
nullable-scalar parameter (`Math.max.bind(null, 0)`). The final gate of
ADR-01333 also showed that the reserved-global and getRandomValues tests
still asserted the deleted behavior. Working through those turned up the
gaps below. Each repro was run against Node v24.19, and tsc where a lane
question arose.

## Investigation

- The unary `void` operator was a parse error ("unexpected token void in
  expression"): it was lexed but never parsed.
- `undefined` is not a reserved word. Plain JS accepts
  `function f(undefined) {}` and `var undefined = 5` in a function, and so
  does tsc, which reports TS2397 only for a script's global declaration.
  The parser rejected the name because the scanner gives it its own token.
- `tests/compiler_test.go`'s `buildBinaryMultiFilePermissive` resolved in
  the js lane but built the emitter without options, so every "permissive"
  E2E test compiled its code in the strict lane.
- Under `-compat=js`, `function f(a) { return a }; f(7); f()` failed with
  "missing argument 1": call-site inference typed `a` as a number from
  `f(7)` and ignored the call that leaves it out.
- `.bind`'s trampoline holds each bound argument in one 8-byte slot, so it
  cannot express an array (two words), a `{i1, T}` nullable scalar, or
  bound arguments that join a rest parameter.

## Decision

1. **Local classes are closure-converted** (`codegen/llvm/emit_classclosure.go`).
   A block class that names locals of its function is hoisted like any
   other block class. Each local it names becomes a hidden private instance
   field, `#__kml_cap_<name>`, which inspect, JSON and `Object.keys` never
   show, as with any private field. References in the class body read
   `this.#__kml_cap_<name>`.

   Every `new` of the class, or of a block class extending it, stores the
   locals into the instance after allocation and before the constructor
   runs, so field initializers and the constructor already see them. A
   `new` inside the class's own body copies them from `this`. Each
   evaluation of the function therefore gives instances their own
   bindings.

   A local written after its declaration moves into a cell,
   `const <name>__kml_cell: { v: T } = { v: init }`, which the function and
   every instance share. A parameter's cell opens the function body. The
   field's type is the local's own annotation, else the checker's
   primitive type, else `any`.

   The conversion does not apply to a class that reads a local from a
   static member, a static block or a nested `function`, a class used as a
   value, a generic class, or a written loop, catch or destructured
   binding. Those report "class 'D' names 'b', a local of its function,
   and …; not supported yet". They need a class object carrying its
   evaluation's environment.
2. **`.bind` over any parameter list.** A function with a rest, array or
   nullable-scalar parameter binds through its dynamic function record
   (`emitDynBind`, the `-compat=js` path), whose call ABI forwards any
   argument shape. The bound value is an `any` function; calls through it
   use the dynamic call ABI. `bindsDynamically` decides for the emitter and
   for `inferExprType` alike. A `this: T` function keeps the typed
   trampoline.
3. **`void e`** parses to `e, undefined` (the bare `undefined` for a
   literal operand). Its `undefined` is marked `Void`, so it is never
   redirected to a binding.
4. **Bindings named `undefined`.** The parser accepts the name for a
   variable or parameter (`expectBindingName`). The binder records an
   `undefined` literal in that binding's scope (`UndefinedRef`), the
   checker types it from the binding, and sema rewrites it to an
   identifier before codegen.
5. **Omitted arguments in the js lane.** A call that passes fewer
   arguments than an unannotated parameter list (no spread) marks each
   omitted non-rest, non-default parameter polymorphic, so it takes the
   implicit `any` and reads a real `undefined`. A required `any` parameter
   left out passes the boxed `undefined`.
6. The permissive test helper passes its options to the emitter. The
   reserved-global tests become `tests/shadowed_globals_test.go`, asserting
   Node's output in both lanes. The getRandomValues tests assert
   TypeMismatchError (code 17) for a float view and a bare ArrayBuffer, as
   Node throws. The `NaN`/`Infinity` shadowing caveats, stale since
   ADR-01333, are removed.

## Side effects discovered

- A required `number` parameter passed `undefined` (a short call through a
  dynamic value, `x!` on an absent value) still reads `NaN` or `0`. A
  `double` slot has no `undefined`; the representation is a design of its
  own.
- The bound value of a rest-, array- or optional-parameter function is
  typed `any` in codegen, so its calls dispatch at run time (a performance
  gap, not a behavioral one).

## Verification

Node's output is the expectation in `tests/local_class_closure_test.go`,
`tests/bind_wide_test.go`, `tests/void_operator_test.go` and
`tests/shadowed_globals_test.go`, each run in both lanes. tsc accepts
`examples/basics/void_operator.ts`. Examples
`examples/classes/local_class_closure.ts`,
`examples/function_expressions/bind_rest.ts` and
`examples/basics/void_operator.ts` match Node. Mac (Apple Silicon):
targeted suites. Linux x86-64 gates: see the session's gate record.
