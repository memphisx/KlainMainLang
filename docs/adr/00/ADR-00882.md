# ADR-00882: DataView accessors reject a non-numeric byteOffset/value cleanly

- **Date**: 2026-09-11

## Context

Invalid-IR backlog (BACKLOG §4, memory "Invalid-IR backlog histogram"): the
DataView sub-family was the largest single A1 cluster (uncoerced `ptr` operand
reaching a numeric op). A sampled category run (`go run ./tools/conformance
-category=built-ins/DataView`, macOS arm64, lane=strict) showed **37 of 561
DataView files as CLANG_ERROR** — invalid IR *we emitted*, the worst failure
class (a broken binary, not an honest rejection).

Minimal repro:

```ts
const dv = new DataView(new ArrayBuffer(8));
dv.getInt16(Symbol("x"));
// before: clang error — '%tN' defined with type 'ptr' but expected 'i64'
//         at `add i64 %tN, 2`
```

The Test262 files are the `return-abrupt-from-tonumber-*-symbol` /
`return-abrupt-tonumber-byteoffset|bytelength-symbol` families: they pass a
`Symbol` where a numeric byteOffset/value is expected and assert a runtime
`TypeError` from `ToNumber(symbol)`.

## Investigation

Every DataView accessor funnels its byteOffset through
`emitDataViewBoundsCheckedPtr` (`emit_dataview.go`), which did
`off := e.coerce(offVal, TypeI64).Ref`. For a `Symbol` (a `ptr`-shaped value),
`coerce` has no numeric conversion and hits its documented "return unchanged"
fallthrough (`emit_exprs_coerce.go:213`) — yielding a value *typed* `i64` but
whose register is still the `ptr`. That register then flows into `add i64 …`,
`icmp slt i64 …`, the store — invalid IR.

The codebase already has the right tool: `coerceChecked`
(`emit_exprs_coerce.go:284`) runs `coerce` and, via `coercionIsSound`, returns a
clean compile error when the conversion didn't actually produce the target
storage type. The DataView sites simply used bare `coerce`. The same
fallthrough affected three more sites: the `setX` **value** argument (both the
float and integer paths) and the constructor's **byteOffset**/**byteLength**.

This rejection is the faithful behavior for a typed subset: `tsc` itself rejects
`dv.getInt16(sym)` ("Argument of type 'symbol' is not assignable to parameter of
type 'number'"). A compile error matches TypeScript and is strictly better than
emitting a broken binary.

## Decision

Replace bare `coerce` with `coerceChecked` at the four DataView numeric-argument
sites, so a non-coercible (e.g. `Symbol`) byteOffset/value/byteLength is a clean
compile error naming the context ("DataView byteOffset" / "DataView value" /
"DataView byteLength") instead of invalid IR:

- `emitDataViewBoundsCheckedPtr` — the shared accessor byteOffset (covers every
  get/set).
- `emitNewDataViewExpression` — constructor byteOffset and byteLength.
- `emitDataViewSet` — the value argument, both the `spec.float` and integer
  branches.

The existing float-offset ToIndex path (RangeError for NaN/Inf/negative/>2^53)
and all numeric/BigInt handling are unchanged.

## Implementation notes

- `codegen/llvm/emit_dataview.go` only. Each site already returned an `error`;
  the `coerceChecked` error threads straight out.
- The integer/float `setX` edits shadow-declare with `:=` reusing the in-scope
  `err` (one new var `i`/`f`), which Go permits.

## Side effects discovered

One DataView file remains CLANG_ERROR — `setBigInt64/set-values-return-undefined.js`
— but from a *different* root cause: `var result = dv.setBigInt64(...)` assigns
the `void` return of a setter to a variable (`void type only allowed for
function results`). That is the void-result-as-value pattern, not argument
coercion; left for separate work.

## Verification

- Sampled DataView category run: **37 → 1 CLANG_ERROR** (36 files reclassified
  from invalid-IR to clean COMPILE_ERROR rejections). Measured on macOS arm64,
  lane=strict, isolated `-workdir`.
- New E2E `TestE2EDataViewNonNumericRejected` (Symbol byteOffset / value /
  constructor offset) and the existing `TestE2EDataView*` round-trip tests pass.
- `go test ./tests/ -run 'TestE2E(ArrayBuffer|BigInt|TypedArray|DataView)'`,
  `go build`, `go vet ./...` — clean.
- Full Test262 not re-run here (another conformance run was in progress; the
  isolated-only rule). The category sample is the measurement.
