# ADR-00766: `spawn(cmd, args, { stdio })` — per-fd `pipe`/`inherit`/`ignore`

- **Relations**: Extends [ADR-00433](ADR-00433.md) (spawn options) and [ADR-00322](ADR-00322.md) (the three-pipe fork/exec spawn machinery); addresses [TDD-00180](../tdd/TDD-00180.md) §3
- **Date**: 2026-09-07

## Context

`spawn`'s `stdio` option accepted only the literal `'pipe'`. Node lets each of the
child's three standard fds be `'pipe'` (a stream on the ChildProcess), `'inherit'`
(share the parent's fd), or `'ignore'` (`/dev/null`), given either as a string
(applied to all three) or a 3-element array `[stdin, stdout, stderr]`. This is the
last of [TDD-00180](../tdd/TDD-00180.md) §3's spawn-option rows and the largest —
it reworks the core per-fd pipe setup every child_process feature sits on.

## Investigation

`__kml_cp_spawn` always creates three pipes and the forked child `dup2`s the pipe
ends onto 0/1/2; the parent keeps the read/write ends, folds them into `select()`,
and finalize reaps once both read ends hit EOF. For `inherit`, the child must
simply *not* `dup2` (fd stays the inherited parent fd); for `ignore`, `dup2`
`/dev/null`. The parent must then close the now-unused pipe ends and store `-1`
for that fd so the drain/write path skips it — on Windows especially, where the
child is spawned via `__kml_win_spawn` (no fork) and a parent-held write end would
otherwise keep the read end from ever reaching EOF (a hang). The modes are known
at compile time from the literal, but `__kml_cp_spawn` is one shared runtime
function, so they are threaded as runtime bits and branched on.

## Decision

- **Encoding**: per-fd 2-bit modes (0 `pipe`, 1 `inherit`, 2 `ignore`) parsed by
  `cpParseStdio` from a string ('pipe'/'inherit'/'ignore', applied to all three)
  or a 3-element array of those strings. fd numbers, `'ipc'`, streams, and
  non-3-length arrays are clean rejections. The 6 bits ride in `mode` bits **4-9**
  (`optBits |= stdioModes << 4`) — no `__kml_cp_spawn` signature change; they land
  in `__kml_win_spawn`'s `flags` (`mode >> 1`) at bits 3-8, which the shim ignores.
- **Child (POSIX, `cpSpawnForkIR`)**: per fd, `dup2` the pipe end (pipe), leave
  the inherited fd (inherit), or `dup2` `/dev/null` (ignore). `/dev/null` (RDWR)
  is opened once — only when some fd is `ignore` — and closed before exec; a
  private `@.kml_cp_devnull` constant feeds `open`.
- **Child (Windows, `__kml_win_spawn`)**: the per-fd argument is the pipe end
  (pipe), `-1` (inherit — the shim uses our std handle), or `-2` (ignore — a new
  `inheritable_std` sentinel that always opens `NUL`).
- **Parent (shared)**: for a non-`pipe` fd, close both pipe ends and store `-1` in
  the handle's fd field, so the drain, `child.stdin.write`, and finalize's
  both-EOF check all skip it. A `pipe` fd is unchanged (the read ends are still
  made non-blocking).

## Implementation notes

- Mode-bit map is now: 0 buffered, 1 shell/verbatim, 2 windowsHide, 3 detached,
  4-5 stdin stdio, 6-7 stdout, 8-9 stderr. exec/execFile stay all-`pipe`
  (stdioModes 0) since they buffer output.
- The parent per-fd rewrite keeps the two non-blocking `fcntl`s (now inside the
  `pipe` branches) and the four cp-field GEPs, so the `fmt.Sprintf` verb count is
  unchanged (`go vet` confirmed).
- Not implemented (clean rejections / caveats): a raw fd number, `'ipc'` (that is
  `fork`'s channel, TDD-00141), a Stream, `'overlapped'`, and arrays longer than
  3. `child.stdout`/`stderr` remain accessor objects even for a non-`pipe` fd
  (Node returns `null`); they simply never emit `'data'`.

## Side effects discovered

None new. A non-`pipe` stdin still exposes a `child.stdin` whose `.write` goes
nowhere (the fd is `-1`); documented.

## Verification

- New E2E tests: `…SpawnStdioInherit` (child output appears directly),
  `…SpawnStdioIgnore` (discarded), `…SpawnStdioArray` (`[pipe, inherit, ignore]`
  — stdout appears, stderr gone). Full `TestE2EChildProcess*` green on Windows 11
  and Docker Linux.
- Manual repros: **Windows 11 native** and **Docker Linux `klain-ci:latest`** —
  `inherit` prints straight to our stdout, `ignore` discards, `pipe` still
  captured via `child.stdout`, and the array form mixes all three per fd.
- `examples/child_process` extended; compiles and runs. `go build`, `go vet
  ./codegen/...` clean. `make status`/`reference-check`/`conformance` at delivery.
