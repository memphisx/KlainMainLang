# ADR-01112: Flow narrowing in the checker, and the storage type of an evolving `let`

- **Relations**: `Implements TDD-00230` (Phase 2, P2.5, first increment); `Extends ADR-01110`, `ADR-01111`
- **Date**: 2026-09-24

## Context

[TDD-00230](../tdd/TDD-00230.md) P2.5 has the checker narrow each reference
by walking the binder's flow graph backwards from it, and gives an
unannotated `let x;` a storage type (the union of everything assigned to it)
separate from each read's narrowed type
([TDD-00162](../tdd/TDD-00162.md)). The flow graph of
[ADR-01110](ADR-01110.md) records assignments but not conditions, and the
checker of [ADR-01111](ADR-01111.md) answers every reference with its
declared type, and leaves `let x;` unanswered.

## Investigation

- **typescript-go** (`internal/checker/flow.go`): `getFlowTypeOfReference`
  walks back from a reference's flow node. An assignment gives
  `getAssignmentReducedType(declared, assigned)` (the declared type's members
  the assigned type can be). A condition node applies
  `narrowTypeByTruthiness`, `narrowTypeByEquality`, `narrowTypeByTypeof`,
  `narrowTypeByInstanceof`, `narrowTypeByInKeyword`,
  `narrowTypeByDiscriminant` and `narrowTypeByTypePredicate`. A branch label
  unions its antecedents. A loop label is solved by iteration, with the
  partial answers of an open loop kept out of the caches. An auto-typed
  `let x;` starts as `undefined`, and each assignment gives its widened
  literal type.
- **tsc 5.6.3 `--strict`**: each expectation in the new tests is confirmed
  against it, with a `const n: never = x` probe whose error prints `x`'s
  type. Some of the results were not the obvious ones:
  - `let x: T;` reads as `T`, not `undefined`: only definite assignment
    sees the missing value.
  - `x === 1` leaves a `number` member `number`: it doesn't narrow it to
    the literal `1`.
  - `number | 0` is `number`: a union drops a literal whose primitive it
    contains.
  - The falsy branch of `if (!x)` keeps `string` and `number` whole: only
    members that are never falsy are removed.
  - A closure reads its enclosing variable's declared type, unnarrowed.

## Decision

- **The flow graph gains five node kinds** (`binder/flow.go`):
  - `FlowTrueCondition` and `FlowFalseCondition` carry a condition. They
    follow an `if`'s test into its branches, a `?:` test into its arms,
    a `while` or `for` test into the body and the exit, and a `do…while`
    test into the back edge and the exit.
    They also follow the left operand of `&&` and `||` into the right
    operand and into the short-circuit path (`??` is not a truthiness
    test).
  - `FlowSwitchClause` enters a `switch` case from the flow before the
    `switch`: case *i*'s test matched, or, for `default` and the exit of a
    switch without one, no test matched.
  - `FlowCall` follows a call statement, where an `asserts` function's
    predicate takes hold.
  - `FlowPropertyAssignment` follows a store to a property or element path
    rooted at a name (`x.a.b = v`, `x[0] = v`).
- **The binding exposes more of the graph.**
  - An assignment node now also carries what stores the value: the
    declaration or the assignment expression.
  - `StoresTo` lists every node that stores to a symbol, in any function,
    reachable or not.
  - `EndReachable` says whether a function body's end is reachable, which
    return-type inference uses (ADR-01111).
  - `FlowAt` gives a reference's flow node, and whether the reference is in
    the function or module that declares the symbol.
  - Definite assignment and the dead zone walk through the new nodes
    unchanged.
- **The checker narrows references** (`checker/narrow.go`). A reference to a
  symbol whose declared type is a union, `unknown`, a class instance or an
  evolving `let` is narrowed along the flow paths that reach it, when it
  occurs in the container that declares the symbol. Elsewhere, in a
  closure, it keeps its declared type.
  - An assignment gives the declared type's members that the assigned type
    can be. The declared type is used for a compound assignment, an update,
    a destructuring or a loop variable.
  - A condition applies:
    - truthiness, where the true branch drops nullish, `false`, `""` and
      `0` and the false branch drops the never-falsy members;
    - `!`, `&&` and `||`, composed;
    - `===`, `!==`, `==` and `!=` against `null`, `undefined` or a literal;
    - `typeof x === "…"`, which also narrows `unknown`;
    - `instanceof` a class: a subclass instance stays, a base class's
      instance becomes the class's (so a declared class type narrows too);
    - `"p" in x`;
    - a discriminant `x.p === lit`, with `x?.p === lit` also proving `x`
      non-nullish;
    - a call to a `(v): v is T` predicate, and after a call statement, an
      `asserts v is T` or `asserts v` one;
    - a `switch` on `x`, `typeof x` or `x.p`: a case narrows as `===` its
      test, and `default` as `!==` every test.
  - **A property path narrows like a variable** (`x.a`, `x.a.b`, and an
    element access with a literal key, `x["a"]` being `x.a`): the same
    conditions apply to it, a store to the same path gives the stored
    type, and a store to its root or a shorter prefix resets it to the
    declared type. A reference is a symbol plus a property path; every
    narrowing form matches the whole reference.
  - A branch label unions its antecedents. A loop label contributes nothing
    through a path back into the walk in progress: the least fixed point, so
    a loop adds only what it assigns.
  - An assignment whose value reads the symbol being narrowed (`x = x + 1`
    in a loop) contributes `never` to a recursive query. Every answer that
    depended on such a cut, while its computation is still open, is kept
    out of the `TypeOf` cache.
- **The evolving `let x;`**: an unannotated binding declared without a value
  has a storage type: `undefined` joined with the widened type of every
  `=` value stored to it anywhere. A compound or destructuring store leaves
  it unanswered, for now. Each read narrows from it, starting at `undefined`
  and taking each assignment's widened type.
- **Property access on a union of objects** that all declare the property
  gives the union of its types (a discriminated union's tag). An element
  access with a literal key reads a tuple element or an object property.
- **Function types carry a `p is T`, `asserts p is T` or `asserts p`
  predicate**; `this is T` stays unanswered.
- **Not in this increment:** the `missing` singleton for absent optional
  properties (and a destructuring default applying to it), and deleting
  codegen's per-site absence handling. That deletion waits for the shadow
  report to reach zero for it.

## Implementation notes

- **New:**
  - `checker/narrow.go`: the flow walk, the narrowing forms, references
    and `storageType`;
  - `checker/narrow_test.go`.
- **Changed:**
  - `binder/flow.go`: the five node kinds, `FlowAt`, `StoresTo` and
    `EndReachable` (`FlowFlags` widened to 16 bits);
  - `binder/binder.go`: the condition nodes wired into `if`, `?:`, the
    loops, `&&`, `||` and `switch`; a call node after each call
    statement; a property-assignment node after each store to a path; the
    `storing` field, which records each assignment node's value;
  - `checker/checker.go`: narrowed identifier, member and element reads,
    the provisional-answer log, member access on unions;
  - `checker/symbols.go`: predicates;
  - `checker/types.go`: `Predicate` and literal reduction.
- A recursive query caches only answers whose cuts have all closed. The
  cut log is a slice that `TypeOf` marks before it computes and scans
  afterwards; it is emptied when no assignment value is being computed.

## Verification

All on macOS arm64 (M4):

- `go test ./checker ./binder`. The narrowing tests cover:
  - `typeof`, equality, truthiness and the composed forms;
  - assignments, branches and loops (including `x = x + 1`);
  - closures;
  - discriminated unions, `in`, `instanceof` (subclasses included) and
    predicates, `asserts` predicates;
  - property paths and literal element accesses: conditions, stores to the
    path, stores to a prefix;
  - `switch` on a tag, on `typeof`, and on the value;
  - the evolving `let`.

  Each expectation was checked against tsc 5.6.3 `--strict`.
- Resolver output over the 107,567-run corpus dump is identical to
  ADR-01110's: the new nodes change no dead-zone or definite-assignment
  verdict.
- Shadow report over the examples and apps with narrowing in place: the
  breakdown is in ADR-01111. Four disagreements are narrowed reads the
  checker types narrowed (`x` after `x = 42`, `absent` after `= null`)
  where codegen keeps the declared representation, and 88 are places
  codegen adds `undefined` that TypeScript does not. Both are this step's
  remaining work: the storage type against the read type, and absence.
- `make examples`: 358/358. `make test-par`: pass apart from the four
  `-mm=gc` macOS segfaults (`task_reclaim_gc_tls_test.go`), which fail
  identically at HEAD (BACKLOG §0 item 1d). The checker runs only under
  the shadow harness, so compiled output does not depend on it.
