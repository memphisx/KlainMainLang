# ADR-00811: `fs.readFileSync` reads zero-stat-size `/proc` and `/sys` files

- **Date**: 2026-09-09

## Context

Building a portable `top` (klaintop) on Sailfish OS surfaced this: on Linux the
process table is read from `/proc`, but `fs.readFileSync("/proc/<pid>/stat")`
returned an empty string, so the process list was empty (and downstream parsing
of the empty result crashed on the device). The same code shelling out to `ps`
had already failed on Sailfish's BusyBox, so `/proc` is the portable route — and
it was broken.

## Investigation

`__kml_fs_read_file_raw` (`runtime_fs.go`) sizes the file with
`fseek(SEEK_END)` + `ftell`, `malloc`s that many bytes, and `fread`s exactly
that count. `/proc` and `/sys` are pseudo-filesystems: their files report
`st_size` 0 (and are not seekable for a size), so `ftell` returns 0, `fread`
reads 0 bytes, and the result is `""` — even though a normal read returns real
content. Confirmed with a probe in an aarch64 Linux container: `readFileSync
("/proc/1/stat")` gave `""`, while the file plainly contains
`1 (bash) S 0 1 …`. Node reads these files correctly because it does not trust
`st_size`; it reads in a loop until EOF.

## Decision

Keep the fast size-known path for regular files, and add a grow-until-EOF
fallback when `ftell` reports size `<= 0` (0 for pseudo-files; negative if the
seek/tell failed). The fallback `malloc`s a starting buffer and `fread`s 4 KiB
chunks, `realloc`-doubling when it would run tight, until a short read signals
EOF, then null-terminates at the true byte count. This also correctly handles a
genuinely empty regular file (first `fread` returns 0 → length 0 → `""`), so no
regular-file behaviour changes.

## Implementation notes

- `codegen/llvm/runtime_fs.go`: the `ok:` block of `__kml_fs_read_file_raw`
  splits into `sized:` (unchanged fast path) and a `grow:`/`growloop:`/
  `growbuf:`/`doread:`/`growdone:` loop; added `e.ensureRealloc()`. The loop
  uses three entry-block-free allocas (cap/buf/total) driven by load/store,
  which clang -O2 promotes — simpler to emit correctly by hand than a phi web.
- Bytes-mode reads (`readFileSyncBytes`) share the same raw routine, so they
  gain procfs support too.

## Side effects discovered

This was itself the fix for a bug found while writing the klaintop portability
example (its Linux `/proc` data source). No further issues; the app now reads a
live process table on Sailfish.

## Verification

- `tests/procfs_read_test.go` (Linux-only, skips elsewhere): `readFileSync
  ("/proc/self/stat")` returns non-empty content containing the `(comm)` field.
  Green in the aarch64 Linux Docker lane.
- End-to-end: klaintop cross-built for Sailfish now shows a live, sorted process
  table on a real Xperia 10 II (reading `sailfish-qml`, `lipstick`, kworkers,
  etc. from `/proc`), where it previously crashed. (Mac + arm64 Docker + device.)
- Regular-file reads unaffected: the full `fs`/read-file E2E suite passes on
  macOS.
