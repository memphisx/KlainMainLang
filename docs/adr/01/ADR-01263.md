# ADR-01263: `dgram` in TypeScript

- **Relations**: `Implements TDD-00230`, `Supersedes ADR-00327, ADR-00581`
- **Date**: 2026-09-29

## Context

`dgram` was code-generated (ADR-00327):
- `udp4` only;
- no `'listening'`/`'error'` events, options object, multicast, TTL,
  offset/length send or connect;
- listeners had to be literals;
- its sockets ran in their own loop hooks.

TDD-00230 P3.1 moves the Node surface to TypeScript modules.

## Decision

`lib/node/dgram.ts` ports Node v24's lib/dgram.js:
- `Socket` is an `EventEmitter` with Node's bind/connect state machines,
  address lookup, send queue (a send before the bind completes waits for
  `'listening'`), argument forms and error codes;
- `createSocket` takes a type or an options object (`reuseAddr`,
  `ipv6Only`, buffer sizes, `signal`).

The socket is made at bind, as libuv makes it, so an option or `address()`
before the bind is `EBADF`, as in Node.

Datagram sockets are handles in the pool reactor's TCP table (a `udp`
flag). Each read there is one `recvfrom`, whose sender `udpSender` reports,
and a zero-length datagram is a message, not an end of stream. New natives
in lib/native.d.ts:
- `udpSocket`, `udpBind`, `udpConnect`, `udpSend`, `udpSender`;
- `udpOption` (broadcast, TTL, multicast TTL and loopback, buffer sizes),
  `udpMembership`, `udpMulticastInterface`.

A send is a synchronous `sendto`, and a full send buffer is waited out.
On Windows the option numbers the Windows layer passes through are
Winsock's.

The codegen module and its event-loop hooks are deleted (emit_dgram.go,
runtime_dgram.go, the Dgram socket type, the resolver's virtual module).

## Side effects discovered

- Boxing a `Buffer[]` into `any` and reading it back as `any[]` lost its
  elements (ADR-01264). This is how a queued send's list crossed the queue.
- The existing tests and the example read `address()` and set options
  before the bind completed, which throws in Node. They now do so in the
  bind callback.
- Status caveats remain:
  - the send queue is always empty (sends are synchronous);
  - the `lookup`/block-list options, `bind({ fd })` and cluster-shared
    sockets are not ported;
  - Windows options apply to `udp4` sockets only.

## Verification

Mac (Apple Silicon), against Node v24.19:
- `TestE2EDgramSendFormsAndConnect`, `TestE2EDgramUdp6AndOptions`,
  `TestE2EDgramSetBroadcast`, the echo and address tests, and
  `examples/dgram/echo.ts` match Node's output.
- Windows is compile-checked (`GOOS=windows go vet`); the Windows reactor
  tests are the first run there.
