# ADR-01222: The definite-assignment walk visits each flow node once

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-09-29

## Context

Compiling `lib/node/internal_url.ts` (ADR-01221) never finished: the
compiler spun at full CPU with flat memory.

## Investigation

- A stack dump showed `binder.walkBack` recursing through loop labels.
- `walkBack` answers two questions for a use: does some path back from it
  meet an assignment (found), and does some path reach the binding's
  scope start without one (missed). It memoized an answer at a label only
  when no loop cut it short. Inside nested loops almost every answer is
  cut, so each label was re-walked once per path: exponential in the
  number of branches in a loop body. `Url.prototype.parse` has a long
  loop with a dozen-branch `if` chain.
- Both answers are reachability over the predecessor graph with the
  assignment and the scope start as path ends. A cycle adds no new path
  end.

## Decision

`walkBack` is one traversal with a visited set: an assignment that
establishes the fact sets found, a scope start or the binding's own
function start sets missed, a label pushes its predecessors. It stops
early once both are set.

`binder/flow.go`.
