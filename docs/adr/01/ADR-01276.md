# ADR-01276: Weak-type check (TS2559) for assignments and calls

- **Relations**: `Extends ADR-01132`
- **Date**: 2026-09-29

## Context

A weak type is one whose properties are all optional. It accepts no
primitive or array that shares none of its properties. The checker applied
this only when choosing among overloads. Otherwise the relation answers
"maybe", so the following all compiled in the strict lane, where tsc
rejects them:

- `f(5)` for `f(o?: Opts)`;
- `const o: Opts = 'x'`;
- a single-overload call such as `setTimeout(1, 'x', 5)` from
  `timers/promises`.

## Decision

- An assignment or argument the relation leaves undecided is reported as
  TS2559 when the weak-type check fails. The message names the target
  without its `| undefined`, as tsc does.
- An overload's argument check treats a weak mismatch as a misfit. With a
  single candidate, that argument is reported as TS2559.
- Constructor arguments are still not checked (BACKLOG).

## Verification

Mac (Apple Silicon): checker unit cases for a plain call, a declaration and
an overloaded call, compared against `tsc --strict`;
`TestE2ETimersPromisesWeakOptionsTypeError`.
