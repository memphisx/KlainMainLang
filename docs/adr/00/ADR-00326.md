# ADR-00326: Node `dns` — `dns.lookup`

- **Date**: 2026-08-23

## Context

`dns` was one of the self-contained unstarted modules on NODE-CORE-MODULES.md.
`fetch`/libcurl already resolve hostnames internally, but no resolver was
exposed to user code. `dns.lookup(hostname, cb)` is the common surface — turn a
hostname into an IP — and needs only a single `getaddrinfo(3)` call, no event
loop.

## Investigation

The WebSocket client (runtime_websocket_client.go) already resolves hostnames
via `getaddrinfo` on Linux, but **deliberately skips it on Darwin**
(runtime_websocket_client.go:133) because `struct addrinfo`'s field layout is
not a standardized byte layout and had not been verified on Darwin — the
project's standing rule is to confirm such an offset on the machine rather than
trust it. That gate is exactly what would block `dns.lookup` on this (Mac) dev
machine.

Resolved it directly with a compiled `offsetof` probe on arm64 Darwin:
`sizeof(struct addrinfo) == 48`, and `ai_addr` is at offset **32** — Darwin
swaps `ai_canonname` (24) and `ai_addr` relative to glibc, where `ai_addr` is at
24. `sockaddr_in.sin_addr` is at offset 4 on both. `getaddrinfo`/`freeaddrinfo`
themselves are in libSystem on Darwin, so they are callable on both platforms
once the offset is pinned per-OS.

## Decision

`runtime_dns.go` emits `@__kml_dns_lookup(host) -> ptr`: `getaddrinfo(host,
NULL, {AF_INET, SOCK_STREAM}, &res)`, read the first result's `sin_addr` four
bytes at `ai_addr + 4` (with `ai_addr`'s offset chosen by `dnsAiAddrOffset()` —
32 on Darwin, 24 elsewhere), `sprintf` a dotted quad into a malloc'd buffer,
`freeaddrinfo`, return it (or null on failure).

`emit_dns.go` implements `dns.lookup(hostname, (err, address, family) => …)`:
call the helper, branch on null, and fire the callback synchronously (the zlib
callback posture) with `(null, address, 4)` on success or
`(Error "getaddrinfo ENOTFOUND", null, 0)` on failure. The error object is built
via the shared `buildErrorObj`.

`dns.promises` and `dns.resolve*` are not implemented in V1.

## Implementation notes

- New `runtime_dns.go` (guarded by `e.dnsDeclared`) and `emit_dns.go`.
- Registration/dispatch: `dns` → `dns__kml_builtin` in
  resolver/virtual_modules.go, dispatch in emit_call.go, `TypeVoid` return in
  emit_exprs_types.go.
- The callback-firing branch uses `freshLabel`/`emitTerminator`/`emitLabel`;
  `br` targets need a `%` prefix that `emitLabel`'s block header does not — a
  small IR-syntax gotcha caught on first compile.

## Side effects discovered

The Darwin `getaddrinfo` gap that keeps the WebSocket client's own resolver
Linux-only is now unblocked in principle (the offset is known and verified);
teaching the WS client to use it on Darwin is a possible follow-up, tracked on
NETWORKING.md rather than done here.

## Verification

- `tests/dns_test.go`: `localhost` → `127.0.0.1` family 4, a numeric IP
  passthrough, and a bogus hostname's error path.
- `examples/dns/lookup.ts` run on macOS (arm64).
- Machine: verified on Mac (Apple Silicon), including the probed `ai_addr`
  offset. Linux uses offset 24 (glibc) — not separately re-run this session.
