# ADR-01613: Windows children through uv_spawn; pipes and consoles as libuv streams

- **Relations**: Implements TDD-00252 (Stage 3), Extends ADR-01602
- **Date**: 2026-10-13

## Context

After Stages 1–2 of TDD-00252 (ADR-01602) Windows ran the POSIX loop on
libuv, but a child process still went through `win32proc.c`'s own
`CreateProcessW` path: its exit reached the loop as a registered wait that
posted to the shim's port, the dispatch reaped it with an emulated
`waitpid`, its stdio pipes were shim descriptors served by overlapped
zero-byte reads and reader threads, and the loop learned of their data
through the shim's `select()` run from the check callback. The IPC
channel's far end reached the child as a raw handle value in an environment
variable (`KML_WIN_INHERIT_FD`). `spawnSync` ran the async spawn on the
thread's own loop and polled the shim's descriptors.

## Investigation

- `klainpool.c` `proc_spawn_on` already had the POSIX `uv_spawn` branch
  (TDD-00244 Stage 4); the Windows branch differed only in how the child
  started, how its stdio was made, and how its exit was seen.
- Node's Windows child stdio is libuv's `UV_CREATE_PIPE` (a duplex named
  pipe) and its parent end a `uv_pipe_t`; a console is a `uv_tty_t`. libuv
  polls only sockets on Windows (`uv_poll_init_socket`), so a pipe or a
  console in the stream table needs a stream handle of its own, not a
  readiness watcher.
- libuv hands descriptors beyond 0–2 to the child through the CRT's
  descriptor table (`lpReserved2`), which the child's CRT rebuilds before
  `main`; `UV_INHERIT_FD` takes a CRT descriptor.
- `childprocsrc/spawnsync.c` and the re-exec helper in
  `runtime_reexec_guard.go` were linked only when `usedSpawnSync` /
  `usedReexecGuard` were set, and nothing set them: dead since `spawnSync`
  moved to `__kml_native_spawn_sync`.

## Decision

- **Spawn.** `proc_spawn_on` is the `uv_spawn` path on both hosts. On
  Windows a `'p'` descriptor is `UV_CREATE_PIPE | UV_READABLE_PIPE |
  UV_WRITABLE_PIPE`; the IPC channel stays a socket pair (its end polled by
  libuv, KMLH framing for handles unchanged) whose far end the child
  inherits with `UV_INHERIT_FD` at its slot; an inherited descriptor is a
  CRT descriptor too (`__kml_win_fd_crt`, a duplicate of the shim
  descriptor's handle). `windowsVerbatimArguments` and `detached` are libuv's
  flags, and libuv's own `PATH`/`PATHEXT` search and environment block
  (required variables added to a custom one) replace `win32proc.c`'s.
  Node's refusal of a batch file without a shell (`EINVAL`) and the
  self-spawn marker (ADR-00972) are checked before `uv_spawn`; the marker
  joins a UTF-8 copy of the environment (`uv_os_environ`).
- **Exit and kill.** The exit is `uv_process_t`'s callback, with the full
  32-bit exit code; `kill` is `uv_process_kill`.
- **Streams.** A Windows pipe or console in the stream table is a
  `kml_ustream`: a `uv_pipe_t`/`uv_tty_t` read into a buffer the table's
  reads take from, written one `uv_write` request at a time, shut down with
  `uv_shutdown`, closed with `uv_close`. Its arrivals and finished writes
  set the handle's readiness for the dispatch, so the table's read, write,
  shutdown and close paths are unchanged above `raw_recv`/`raw_send`.
  `__kml_native_stream_open` makes one for a pipe or console descriptor
  (process.stdin, `tty.ReadStream`), and raw mode is `uv_tty_set_mode`.
- **spawnSync** runs on its own loop on both hosts, as Node's does; on
  Windows the pipes are read to their end there, with the timeout a
  `uv_timer_t` and the input one `uv_write`.
- **The child's channel.** A constructor in `win32proc.c` adopts the socket
  behind the CRT descriptor `NODE_CHANNEL_FD` names and points the variable
  at its shim descriptor; the `KML_WIN_INHERIT_FD` variable is gone.
- **What `win32proc.c` keeps.** The cluster re-spawn
  (`__kml_win_spawn_worker`, the IR's one fork site), the batch-file and
  self-spawn tests, `__kml_win_fd_crt`, `kill()` for `process.kill(pid)`,
  and signals. The pid table, the exit watch, `waitpid`, the pseudo-pids
  for a failed spawn, and the program search go.
- The dead `spawnsync.c` and re-exec helper are deleted.

## Implementation notes

- `codegen/llvm/threadpoolsrc/klainpool.c`: `kml_ustream` (`us_*`),
  `proc_spawn_on`, `proc_env_marked`, `spawn_sync_win`, `proc_on_exit`
  (32-bit code), process kill/ref/close, stream open, raw mode.
- `codegen/llvm/win32src/win32proc.c`: `__kml_win_is_batch_file`,
  `__kml_win_spawn_is_self`, `__kml_win_fd_crt`, `__kml_win_spawn_worker`,
  `kml_win_adopt_channel`.
- `codegen/llvm/runtime_spawn_win.go`: the cluster fork calls
  `__kml_win_spawn_worker`.
- A stream handle has no shim descriptor: its `fd` is `US_FD`, a number
  every shim call refuses with `EBADF`.
- A `uv_write` that finishes reports the bytes on the next send of the
  same buffer (the queue's head): the table's write queue and its
  callbacks are unchanged.

## Side effects discovered

- `detached` was not passed to the Windows spawn at all (the flag was
  dropped before `__kml_win_spawn`); it is now `UV_PROCESS_DETACHED`.

## Verification

Windows 11 (this machine): the child-process, IPC, cluster, stdio and tty
tests.
