# ADR-00938: A boxed array shares the live array header, so post-box mutation is visible (TDD-00212 Stage 3)

- **Relations**: Implements TDD-00212 (final stage); Relates to ADR-00936, ADR-00937, ADR-00478, TDD-00127
- **Date**: 2026-09-14

## Context

Stages 1 (ADR-00936) and 2 (ADR-00937) taught an `any`-boxed array to render its
contents in `String()`/interpolation and `console.log`. But both boxed a
`{data,len}` **snapshot**: `emitBoxValue` receives an already-loaded aggregate, so
a mutation of the original array after boxing was invisible through the box:

```ts
let a = [1, 2, 3];
let b: any = a;
a.push(4);
console.log(b);   // [ 1, 2, 3 ]   — Node: [ 1, 2, 3, 4 ]
```

Under the object-reference array model (TDD-00127) a named array's storage is a
stable slot holding a pointer to a shared heap `{data,len}` header; `push`/splice
write a new data pointer/length *through* that header, so every alias sees the
change. The snapshot broke that reference semantics at the `any` boundary. This
was not a regression (before Stage 1 it printed `[object Array]`), so it was
genuinely a later stage — but it is the faithfulness bar for reference types.

## Decision

Store the **live array header pointer** in the box instead of a snapshot.

- **Box layout.** `anyArrayBoxTy` becomes `{ ptr, i8 }`: field 0 is the live
  `arrayHeaderTy` pointer (the shared `{data,len}` cell the source array mutates
  through), field 1 the element-kind byte. Render/unbox sites deref field 0 to
  reach the current data/len (one extra load), so they observe post-box `push`.
- **Plumbing the live header.** `Value` gains an optional `ArrayHeader` field — the
  live header pointer, set only where it is in hand: the array-identifier eval
  (`emit_exprs.go`, where `arrayDataLenSlots` already yields the header) and the
  dynamic-param adapter (`emit_func_adapt.go`, where the incoming array arg *is* a
  header pointer). `boxAnyArray` stores `ArrayHeader` when present; a transient
  array expression (literal/slice/HOF result — no caller-visible identity) mints a
  fresh header from its `{data,len}` aggregate. The field is purely additive:
  every other consumer reads only `Ref`/`Ty`.
- **Identity, for free.** `__kml_any_eq`'s array arm already compares field 0 of
  the box. Now that field 0 is the shared header pointer, two aliases of one array
  compare equal *and stay equal across a reallocating push* (the old data-pointer
  identity could change when `push` realloc'd) — strictly more correct, no code
  change to the runtime.

## Implementation notes

Files: `codegen/llvm/emitter.go` (`Value.ArrayHeader`), `emit_exprs.go` (set the
hint at array-identifier eval), `emit_func_adapt.go` (set it across the adapter),
`emit_dynamic.go` (`anyArrayBoxTy`, `boxAnyArray`, the render arm deref),
`emit_narrowing.go` (`any`→array unbox derefs the header), `runtime_dynamic.go`
(comment only — the field-0 compare is unchanged).

Unboxing `any`→a value-typed array still materializes a `{data,len}` snapshot (a
later mutation of *that* value does not write back through the box) — matching how
every `any`→array read produces a plain array Value; the live path is the box
itself and any typed alias of the original array.

Coverage note: the hint is set at the canonical array-value producers (named
identifier, adapter). An array sourced from an object/class field boxed into `any`
mints a fresh header (snapshot) until that producer also carries the hint — not
exercised by the Stage 3 cases and left as a follow-on if it surfaces.

## Verification

- Live push through the box in both render modes (`console.log(b)` and `"" + b`),
  string-element arrays, a second push, mutation-through-a-typed-param propagating
  to the aliased `any`, and identity (`a === b`) stable across pushes — all match
  Node. A reassignment of the original binding correctly leaves the aliased array
  untouched.
- Transient boxed arrays (`let b: any = [1,2,3]`) unchanged.
- Targeted dynamic/array/collections/JSON/coerce/any/class suites + `make examples`.
  macOS arm64.
