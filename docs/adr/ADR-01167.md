# ADR-01167: fs's callback operations and file streams in TypeScript

- **Relations**: `Implements [TDD-00231](../tdd/TDD-00231.md)` (stage 4, fs); `Extends [ADR-01166](ADR-01166.md)`; `Supersedes` the codegen file streams of [TDD-00108](../tdd/TDD-00108.md) and [TDD-00186](../tdd/TDD-00186.md)'s read-stream job
- **Date**: 2026-09-26

## Context

`fs.createReadStream` and `fs.createWriteStream` were codegen handles over
the WHATWG stream structs: string chunks (a "text-first" fs), a missing
file thrown synchronously, `{ highWaterMark }` and `{ flags }` the only
options, as compile-time literals. `fs.open`, `fs.read`, `fs.write`,
`fs.writev`, `fs.close` and `fs.fsync` did not exist in callback form.

## Investigation

Node v24's `lib/internal/fs/streams.js` (read with
`process.binding('natives')`) builds `ReadStream` and `WriteStream` on
`Readable` and `Writable`: `_construct` opens the file (`'open'`, then
`'ready'`), `_read` reads `min(end - pos + 1, n)` bytes into a fresh
buffer and pushes a copy trimmed to the bytes read, `_write` writes all of
a chunk with up to five zero-byte retries, and `_destroy` waits for an
operation in flight before closing the descriptor. `lib/fs.js` gives the
callback operations' argument forms and validation (`getValidatedFd` is
`validateInt32(fd, 'fd', 0)`; `validateOffsetLengthRead` and
`validateOffsetLengthWrite` order their checks).

## Decision

- **`lib/node/internal_fs.ts`**, `fs`'s companion (ADR-01166), exports
  `open`, `close`, `fsync`, `read`, `write`, `writev`, `ReadStream`,
  `WriteStream`, `createReadStream` and `createWriteStream`, ported from
  those two files:
  - each operation's overloads as `@types/node` declares them, the
    implementation taking the rest of its arguments as Node does
    (`arguments.length` is the rest array's length);
  - Node's validators and error texts (`ERR_INVALID_ARG_TYPE`,
    `ERR_INVALID_ARG_VALUE`, `ERR_OUT_OF_RANGE`), and Node's `isURL` for a
    `file:` URL path;
  - errors from the native operation as Node's `uvException` (`ENOENT:
    no such file or directory, open '…'`, with code, errno, syscall and
    path);
  - `ReadStream` options `flags`, `encoding`, `fd`, `mode`, `autoClose`,
    `emitClose`, `start`, `end`, `highWaterMark` (64 KiB default) and
    `WriteStream` options `flags`, `encoding`, `fd`, `mode`, `autoClose`,
    `emitClose`, `start`, `flush`, `highWaterMark`; `bytesRead`,
    `bytesWritten`, `path`, `pending`, `autoClose`, `close(cb)`,
    `destroySoon()`.
- `writev` gathers its buffers into one positioned write (writev(2)'s
  result).
- **`stream.ts`** gains Node's `_construct` (destroy.js's `construct` and
  `constructNT`, the options form, and `destroy()` waiting for
  construction with the two errors aggregated) and the try/catch around
  `_destroy`.
- `emit_fs_stream.go` and `runtime_fs_stream.go` are deleted, with their
  call and type-inference cases.

## Implementation notes

The helpers Node writes over `stream` (the streams' `close`/`_close`) are
per-class methods here: a `ReadStream | WriteStream` union has no single
representation in code generation yet (BACKLOG, class and interface
layouts). An implementation signature takes `path: any` where the overloads
say `PathLike`, as the union `string | Buffer | URL` has none either.

## Side effects discovered

The port surfaced the compiler fixes of [ADR-01168](ADR-01168.md) and
[ADR-01169](ADR-01169.md).

## Verification

Mac (Apple Silicon): `tests/fs_stream_test.go` — pooled ordered reads while
a timer fires; a WriteStream's `'open'`/`'ready'`/`'finish'`/`'close'`
order and `bytesWritten`; `for await` with Buffer, string and hex chunks;
`start`/`end` ranges and the `start > end` error; `pipe`; append; a missing
file and a directory as `'error'` events; an early `break` closing the
stream; the callback operations with their errors (a second `close` is
`EBADF`); `fs.read`'s option forms; positioned and encoded writes and
`writev`; validation errors; `options.fd` with `autoClose: false`;
`close(cb)`. Every expected output is Node v24's. `examples/fs_streams` and
`examples/fs/read_stream_backpressure` match Node.
