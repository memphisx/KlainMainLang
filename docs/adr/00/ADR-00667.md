# ADR-00667: Aliased imports of the codegen-recognized Web-global reexports (TDD-00165 Stage 2)

- **Relations**: Implements TDD-00165 (Stage 2); Extends [ADR-00666](ADR-00666.md)
- **Date**: 2026-09-03

## Context

ADR-00666 (Stage 1) made a **same-name** import of the Web-global-backed modules
(`url`/`timers`/`perf_hooks`/`buffer`/`events`) work by validating and erasing to
the ambient global. An **aliased** import (`import { setTimeout as later } from
'timers'`) was deferred with a clear message. Stage 2 closes the aliased form for
the exports that can support it.

## Investigation

The reexport members split into two recognition kinds:

- **Codegen-recognized by bare name** — `setTimeout`/`setInterval`/`setImmediate`/
  `clearTimeout`/`clearInterval`/`clearImmediate` (`emit_call.go` call sites),
  `performance` (member access), `atob`/`btoa` (`emit_call.go`). These are read in
  codegen, *after* the resolver's scope-aware rename pass runs.
- **Parser-recognized as `new <Name>(...)`** — `URL`/`URLSearchParams`/`Buffer`/
  `Blob`/`EventEmitter` (`parser/parser_literals.go`). The parser keys on the
  literal identifier, before imports are resolved.

The rename pass (`resolver/rename.go`) already rewrites any unshadowed
top-level-scope identifier `X` to `lu.names[X]` — the exact mechanism a named
module-member import uses. So for a codegen-recognized reexport, aliasing is just
`lookup[alias] = canonicalName`: the rename rewrites `later(...)` to
`setTimeout(...)`, which reaches codegen as the ordinary global. A
parser-recognized constructor cannot be aliased this way — `new U()` was already
parsed as a generic class instantiation, not the built-in construct, so a
post-parse rename can't recover it.

## Decision

Add a `parseTimeReexports` set (`URL`/`URLSearchParams`/`Buffer`/`Blob`/
`EventEmitter`) in `resolver/virtual_modules.go`. In the resolver's reexport
branch, for an aliased specifier (local name ≠ export name):

- If the export is in `parseTimeReexports` → the existing clean Stage 3
  rejection (message refined to say "recognized at parse time").
- Otherwise → bind `lookup[spec.Local] = <canonicalName>`, so the scope-aware
  rename rewrites the alias to the global. The bound value is a real global name,
  not a marker, so it reaches codegen as the bare global.

Collision checks (against `lookup`/`builtinMembers`/`ns`) are hoisted to run for
both the same-name and aliased forms.

## Implementation notes

- The alias binding rides the same `lu.names` table and `!sc.bound` guard as every
  other rename, so a local variable of the alias name still shadows the import
  (covered by a test).
- Capability parity with the global: an aliased `setTimeout` is exactly the
  global `setTimeout`, so it inherits the same limitations (e.g. not usable as a
  first-class value) — aliasing adds nothing the global lacks.

## Verification

E2E tests in `tests/node_core_modules_test.go`: aliased `setTimeout`, aliased
`performance` (via `node:perf_hooks`), aliased `atob`/`btoa`, the parse-time
constructor rejection (`URL`/`Buffer`), and a local-shadow-wins case. `go test`
over the import/module/rename/shadow suites green (Mac); `go vet ./resolver`
clean.
