# ADR-01239: process.stdin, stdout and stderr are Node's streams; `tty`

- **Relations**: `Implements TDD-00235`
- **Date**: 2026-09-29

## Context

TDD-00235 stage 1: `process.stdin`/`stdout`/`stderr` and the `tty` module.

## Decision

- **Natives** (`klainpool.c`, `win32io.c` on Windows):
  - `guessHandleType(fd)`;
  - `streamOpen(fd, readable)`: a descriptor as a stream handle; a
    readable terminal is reopened by its path, and a pipe or socket is made
    non-blocking;
  - `writeSync(fd, bytes, off, len)`;
  - `ttySetRawMode(handle, raw)`, with the original mode restored at exit;
  - `ttyWindowSize(fd)`.
- **`lib/node/tty.ts`**:
  - `isatty`;
  - `ReadStream` (`setRawMode`, `isRaw`, `isTTY`);
  - `WriteStream` (`columns`/`rows`, `'resize'` on SIGWINCH,
    `getWindowSize`, `getColorDepth`/`hasColors` with Node's env rules,
    `cursorTo`/`moveCursor`/`clearLine`/`clearScreenDown`).
- **`lib/node/internal_process_stdio.ts`**: Node's `getStdin` and
  `createWritableStdioStream`. By descriptor kind:
  - a terminal gets a tty stream;
  - a pipe or socket gets a `net.Socket` (stdout/stderr written
    synchronously, as on Linux);
  - a file gets `SyncWriteStream` for output and a Socket over the
    descriptor for input.
  
  stdin starts paused, delivers Buffers, and stops reading when paused.
- **`net.Socket`** takes `manualStart` and `readable`/`writable`.
- **Binding.** Code generation binds `process.stdin` & co. to these
  getters. The resolver includes the module when a file names `process`
  and a stdio stream.
- **Deleted:** the code-generated stdin stream, `process.stdout.write`,
  `.isTTY`, `.columns`/`.rows` and `setRawMode`.

## Side effects discovered

- A program using `process.stdout` compiles in ~5 s (BACKLOG 113).
- `process.stdin`/`stdout`/`stderr` are typed `any` to the checker until
  `process` is typed from its module (TDD-00230 P3.2), so
  `process.stdout.write()` with no argument is no longer a compile error.
- Tests that asserted the old stream's limits were Node-incorrect and are
  changed or removed:
  - `isTTY` on a pipe is `undefined`, not `false`;
  - `'data'` chunks are Buffers, so tests typing them `string` now call
    `setEncoding('utf8')`, as Node needs;
  - a non-utf8 `setEncoding`, a `'close'` listener, and `setRawMode` on a
    piped stdin (a TypeError in Node: a Socket has no `setRawMode`) are no
    longer rejections.
- The test harness resolves (rather than only parses) a program naming
  `process` with `stdin`/`stdout`/`stderr`, as the CLI does, so the stdio
  module joins it.

## Verification

Mac (Apple Silicon), against Node v24.19: piped and file stdin (`'data'`,
`setEncoding`, `for await`, `pipe`, `once` + `pause` exiting), stdout/stderr
writes on a pipe; the full test suite. On a pseudo-terminal (`script`):
`isTTY`, `setRawMode`/`isRaw` and `hasColors` match Node; `'resize'` has not
been run.
