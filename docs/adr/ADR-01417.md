# ADR-01417: A then/catch whose two paths settle to different types

- **Date**: 2026-10-05

## Context

`p.catch(e => e.name)` printed a pointer as a number, `p.then(x => x, e =>
e.name)` printed 0, and `Promise.resolve(5).catch(e => e.name)` crashed.

## Investigation

- `callbackReturnType` typed the rejection callback's unannotated parameter
  as a number (its default), so `e.name` inferred as a number, while the
  emitted callback takes the caught reason (`TypeCaught`).
- The promise `then`/`catch` returns settled to one path's type: `then` used
  the fulfilment callback's, `catch` the rejection callback's, and the
  runner stored the other path's value into the same slots. TypeScript types
  the result as the union of both paths (the source value's type for a
  pass-through fulfilled path).

## Decision

- The rejection callback's return type is inferred with the caught-reason
  hint, in `promiseThenType` and in `emitPromiseThen`.
- When the two paths' types differ (`thenPathsDiffer`: not the same type, not
  both `any`, neither a promise, which adoption handles), the result is
  `any`: each handler is adapted to return its value boxed, and a
  pass-through fulfilled path becomes an identity callback (`v => v`) adapted
  the same way. Equal types keep their unboxed representation.

## Verification

Mac (M4): the six then/catch shapes (fulfilled and rejected source; `then(f,
r)`, `then(undefined, r)`, `catch(r)`; a void-returning handler; awaited
results used as numbers and strings) print what Node prints;
`go test ./tests/ -run 'Promise|Then|Catch|Finally'` passes;
`TestE2EPromiseThenCatchUnion`.
