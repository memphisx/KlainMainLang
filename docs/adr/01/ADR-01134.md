# ADR-01134: The builtin library as declaration files (P3.1, first stage)

- **Relations**: `Implements TDD-00230` (Phase 3, P3.1); `Extends ADR-01132`, `ADR-01133`
- **Date**: 2026-09-25

## Context

P3.1 moves the builtin surface into `.d.ts` files that are parsed and bound
like user code, so the checker knows `Map`, `Math` or `"x".padStart` without
name checks. Until now every builtin name was unresolved in the checker,
and every expression reaching one was unanswered. That hid most programs'
types from the checker, and the codegen deciders it is meant to replace
kept deciding alone.

[ADR-01132](ADR-01132.md) made TypeScript's own library parse, which gives
two things: declarations can be written in full TypeScript syntax, and the
real library can be read to check them.

## Investigation

- **The TDD calls for authored declarations.** Declarations are written for
  this compiler rather than ingested, because the real library relies on
  conditional and mapped types a monomorphic target does not reproduce.
  Authored declarations can be wrong in the other direction: narrower than
  TypeScript's, and so reject valid programs. The first measurement showed
  that. Declaring `forEach(callbackfn)` without its `thisArg` turned
  `arr.forEach(f, this)` into a false TS2554.
- **A declaration can mismatch TypeScript's in four ways:** existence,
  arity, `readonly`-ness, and argument types. The first three can be
  compared mechanically against the real library. Argument types need
  review. A method with fewer signatures than TypeScript's
  (`replace(search, replacer)`) is the case to review.
- **The checker's apparent types.** tsc reads a primitive's members through
  its apparent type (`String` for `string`), and an array's through
  `Array<T>`.
- **Contextual inference.** With the library declared, `arr.map(x => ({
  … }))` in a typed context is typed. tsc infers such a call's type
  arguments from the context too, which keeps literal result types; the
  checker does not model that. Asking for the context type recursed
  through an enclosing generic call's own inference.

## Decision

- **`lib/`** is a package that embeds `*.d.ts` and parses them once per
  process with `parser.ParseDeclarations`.
  - `lib/es.d.ts` declares the ECMAScript surface this compiler implements:
    `Object`, `Function`, `String`, `Number`, `Boolean`, `Math`, `JSON`,
    `Array`/`ReadonlyArray`, the `Error` family and `AggregateError`, `Date`,
    `RegExp`, `Promise`, `Map`, `Set`, `WeakMap`, `WeakSet`, and the global
    functions.
- **`binder.Options.Lib`** binds the declaration programs first, into
  `Binding.Globals`, the parent of the program's module scope. Their own
  references are dropped from the program's flow checks.
- **The checker:**
  - a builtin interface is `partial`: it lists what this compiler
    implements, not the whole library type, so TS2339 and the
    missing-property codes are not reported against it;
  - `apparentType` gives `string`/`number`/`boolean` and arrays or tuples
    their `String`/`Number`/`Boolean`/`Array<T>` members, with the receiver
    as `this`;
  - a generic call whose argument is a literal, an object or array literal,
    or a callback is unanswered where it may have a contextual type
    (`mayHaveContext`, a syntactic test);
  - an interface's call and construct signatures are modelled
    (`Type.Calls`, `Type.Constructs`). A callee is called through them
    (`signaturesOf`), `new X(…)` through a value whose type has construct
    signatures (`declare var Map: MapConstructor`), and a derived
    interface's signatures come before its bases'. Such a type also has
    Function's members, so it is not property-checked as whole;
  - a value is typed from its value declaration (tsc's
    `valueDeclaration`), not a merged interface's;
  - a switch without a default whose cases cover its discriminant's type
    drops its bypass path (`exhaustiveSwitch`). A function's end is
    reachable by the checker's reading of the graph, which honours that and
    never-returning calls (`endReachable`);
  - no excess-property check is made against `{}` (`Object.keys({ a: 1 })`).
- **The strict lane** (`resolver.TypeCheck`), the shadow oracle and
  `tools/tsdiag` bind with the declarations.
- **`tools/libconform`** checks every declaration against TypeScript's own
  library, which `tools/conformance/fetch.sh` now fetches (`src/lib` at the
  pinned v5.6.3):
  - it fails on a name or member TypeScript lacks, an arity difference, or
    a `readonly` difference not listed in `tools/libconform/allow.txt`;
  - it lists members with fewer signatures than TypeScript's, for review.
  The declarations are brought to TypeScript's arity (`thisArg`, `locales`,
  the `reduce` overloads, `new Array(...items)`) and given the reviewed
  overloads (`replace`/`replaceAll` with a replacer, `Object.keys({})`, the
  collections' iterable constructors).

## Implementation notes

- **The declarations take no part in code generation.** A declaration
  without `@lower` (P3.2) changes nothing in codegen: it only answers the
  checker.
- **Division of labour between the checks.** `tools/libconform` compares
  arity and membership, not parameter types. A narrower parameter type is
  caught by the review list and by `tools/tsdiag`, where it shows as a
  false TS2345.

## Side effects discovered

- **Examples that tsc rejects.** Three examples held tsc errors the checker
  now sees:
  - `pts.pop()` stored as a non-optional object;
  - `matrix.at(0)[0]` and `matrix.pop()[0]` on a possibly-undefined
    element;
  - `date.ts`'s `Date ± number` arithmetic.
  Each was confirmed with tsc 5.6.3. The first two now use `!`, and
  `date.ts` uses `getTime()`/`setTime()`.
- **`-compat=js` Date arithmetic.** `Date ± number` giving a Date
  (ADR-00018) is now reachable only under `-compat=js`, where JavaScript
  gives a string for `+` and a number for `-` (BACKLOG: `-compat=js`
  date arithmetic).

## Verification

- **`tools/libconform`:** 63 globals and 50 interfaces, 0 divergences.
- **`tools/tsdiag`:** 1,602 reports over 6,576 cases, of which 1,600 match
  tsc's baselines (1,358 of 1,360 without declarations); the two misses are
  the known Annex B cases. The project's own programs report 0.
- **`lib` tests:** `TestDeclarationsType` types builtin members through the
  declarations. `lib/conform`'s `TestDeclarationsConformToTypeScript`
  passes, and skips when the corpus is not fetched.
- **The edited examples** print what Node prints, apart from two
  divergences the example itself discloses: `getHours()` is UTC here, and
  an unparseable `Date.parse` is `-1` here where Node gives `NaN`.
