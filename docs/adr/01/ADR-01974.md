# ADR-01974: The WebAssembly JS API on wasmtime

- **Relations**: Implements TDD-00230; follows [ADR-01973](ADR-01973.md)
- **Date**: 2026-11-06

## Context

Node exposes `WebAssembly` as a global: compile a module's bytes, link it
against JS imports, call its exports, share its memory. A program that
used it failed to compile (`undefined variable 'WebAssembly'`), and with
it every Node test that touches it, such as the worker test that posts a
`WebAssembly.Module` across threads. A compiled program has no V8, so it
needs an engine of its own. A WebAssembly *target* for the compiler is a
separate direction and is not part of this.

## Decision

- Modules compile and run on **wasmtime**, through its C API. The engine
  sits behind a small backend interface (`kml_wasm_*` in
  `threadpoolsrc/klainwasm_wasmtime.c`): compile, validate, the import and
  export descriptors as type strings, instantiate, call, and the memory,
  table and global operations. Another engine can take its place without
  changing the library. `threadpoolsrc/klainwasm.c` puts the
  `__kml_native_wasm_*` natives over it:
  - a module table that every thread shares;
  - extern and instance tables per thread, since wasmtime stores are
    per thread.
- The JS surface is TypeScript (`lib/node/kml_wasm.ts`): `Module`,
  `Instance`, `Memory`, `Table`, `Global`, the three error classes,
  `compile`/`instantiate`/`validate`, and
  `compileStreaming`/`instantiateStreaming`. It is declared from
  TypeScript's own `lib.dom` `WebAssembly` namespace.
- V8's observable behavior is matched:
  - **Values**: `i64` values cross as `BigInt`.
  - **Exported functions**: same identity, `name` and `length`.
  - **Host functions**: they can call back into the module, and a JS
    exception thrown inside one propagates through the module unchanged.
  - **Traps**: V8's `RuntimeError` messages; a stack overflow is a
    `RangeError: Maximum call stack size exceeded`.
  - **Timing**:
    - An async compile settles as V8's `AsyncCompileJob` does: decoding
      in one task, finishing in the next.
    - Instantiating bytes takes a task after that.
    - Instantiating an already compiled `Module` settles at once.
  - **Streaming**: `compileStreaming`/`instantiateStreaming` check the
    `Response` as Node's `wasm_web_api` does, with the same error codes
    and messages.
- Threads (shared memory and atomics) are enabled, as in V8:
  - A shared `Memory`'s `buffer` is a `SharedArrayBuffer`, viewed in place
    (`ffiView` kind 2).
  - Posting a `Module` or a shared `Memory` to a worker sends a handle
    through the clone hooks (`internal_clone_hooks.ts`). The worker gets
    the same compiled module, or the same memory's bytes.
  - An unshared `Memory` throws `DataCloneError`, as in V8.
- `new Worker(code, { eval: true })` now runs when `code` is a constant
  string (a literal or a `+` of literals). The resolver compiles it in as
  a virtual module, keyed by its code. Computed code still fails at
  `new Worker`.
- The wasm unit is linked only when the program uses `WebAssembly`.
  `LocateWasm` finds the C API through pkg-config, `WASMTIME_DIR`,
  Homebrew, `/usr/local` or `/usr`. CI installs a pinned wasmtime release
  (Homebrew's on macOS).
- Two compiler bugs that blocked the library are fixed:
  - `this.length` in a class with a `length` getter now reads the getter.
  - A `Map<number, any>` miss now reads as `undefined`.
- `String(x)`, where `x` is `any` holding a class instance that has a
  `valueOf` but no `toString`, now gives `[object Tag]` as in Node, not
  the `valueOf` result.

## Consequences

- `WebAssembly` programs compile and match Node on Linux and macOS. The
  covering tests are `tests/wasm_test.go` and `examples/wasm/wasm.ts`.
- Left as caveats on the status row:
  - Compile and link error text is wasmtime's.
  - The old `memory.buffer` is not detached after `grow()`.
  - An integer remainder by zero traps as `divide by zero`.
- An `eval: true` worker resolves its `require`s against the file's
  directory, not the working directory.
- `node:wasi` is still not ported.
