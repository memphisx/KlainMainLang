# ADR-01233: Array, string and number methods, `hasOwnProperty` and `in` through `any`; arrays of objects in `any`

- **Relations**: `Extends ADR-01059`
- **Date**: 2026-09-29

## Context

On an `any` holding an array:

- `a.slice(1)` and `a.indexOf(x)` threw "slice is not a function";
- `a.join("-")` and `a.map(f)` were compile errors ("value is not an
  array").

This held for a boxed static array and a `JSON.parse` array alike. Both
failures are at HEAD. The TypeScript `child_process` module's `execFile`
hit it: `args.slice()` on its `any` argument.

Also broken:

- an `any` holding an array of objects (or class instances, Maps,
  `T | null` numbers) could not be read at all: `ap[0]`, `for…of` and
  methods threw "element access through `any` on an array whose element
  type is not representable";
- `n.toFixed(2)` on an `any` threw "toFixed is not a function";
- `x.hasOwnProperty(k)` on any `any` threw "hasOwnProperty is not a
  function";
- `k in a` for an array threw "Cannot use 'in' operator on a non-object
  value".

## Investigation

- Name-based array dispatch in `emitCall` ran before the `any` receiver
  check, and required a static array.
- The dynamic method path read the method as a property, and an array box
  has no such property.
- A boxed static array (tag 7) holds its live header plus an element-kind
  byte (`KjBox`). A dynamic array (tag 11) holds `{tag, payload}` pairs.
  Neither is an `any[]`, except a boxed `any[]`, whose header is one.

## Decision

- **Array methods.** An Array method name on an `any` receiver checks at
  run time for an array:
  - `__kml_anyarr_view` gives an `any[]` header: the array's own live
    header for a boxed `any[]`, otherwise a fresh one holding the elements
    boxed;
  - the ordinary `any[]` method runs on a temporary binding of it;
  - after a mutator (`push`, `pop`, `shift`, `unshift`, `splice`, `sort`,
    `reverse`, `fill`, `copyWithin`), `__kml_anyarr_sync` writes the
    elements back in the array's own representation;
  - the result is boxed.
  
  A non-array receiver takes the String method path (for a shared name) or
  its own property.
- **Arrays of any element type.** An element kind the kind byte can't
  describe is `KJ_BOXED` (14). For each such element type, codegen
  generates two routines, stored in the box together with the element's
  size: one boxes element i, one stores a box into element i.
  - The box grows to 32 bytes: `{ ptr, i8×4, i32 esize, ptr boxer,
    ptr unboxer }`.
  - Element reads, `for…of`, inspect, join, `JSON.stringify`, the method
    view and the write-back all go through the two routines.
- **Number methods.** `toFixed`, `toPrecision` and `toExponential` on an
  `any` holding a number run the number's own method, as String methods
  do (ADR-01230).
- **Inference.** `inferExprType` types such a call as `any`, as the emit
  side does, so a chained call (`a.map(f).join(",")`) dispatches
  dynamically too.
- **`hasOwnProperty`.** `x.hasOwnProperty(k)` on an `any` calls the
  receiver's own `hasOwnProperty` when it has one. Otherwise it is
  own-property membership: a string's indices and `length`, false for a
  number or boolean, and a TypeError for null or undefined.
- **`in` on arrays.** `in` and `hasOwn` on an array answer its indices
  below the length and `length`. `in` also answers Array.prototype's
  members.

## Implementation notes

- `emit_dynfunc.go` (`dynArrayMethods`, `emitDynArrayMethodCall`,
  `dynNumberMethods`, `emitDynHasOwnPropertyCall`), `emit_call.go`,
  `emit_dynobj.go`, `emit_dynamic.go` (`anyArrayBoxTy`,
  `anyArrayElemRoutines`), `emit_exprs_types.go`,
  `sidecar_layout_test.go`.
- `dynjsonsrc/dynjson.c` (view and sync); `fnmetasrc/fnmeta.c`
  (`__kml_array_has_key`).
- A string element written back into a `string[]` that is not a string
  becomes its ToString. Such a value is only reachable through `any`.
