# ADR-01380: Dynamic functions: captured parameters, nested pushes, generator expressions called at once

- **Relations**: Extends ADR-00619, TDD-00205
- **Date**: 2026-10-03

## Context

- `DataView/prototype/setBigInt64/set-values-return-undefined.js`: "Instruction
  does not dominate all uses" in a `forEach(function (value) { … })`
  callback whose `if` and `else if` branches each create an arrow capturing
  `value`.
- The Iterator-helper Test262 files built their iterator as
  `(function* () { yield 1; })()`: invalid IR with the helpers, "a string
  has no method 'next'" at HEAD.
- An empty array filled only inside a callback or an accessor
  (`[1].forEach(v => out.push(() => v))`, `set foo(b) { log.push("v" + b) }`)
  kept the `number[]` default.

## Investigation

- A function compiled as a dynamic function (`emitDynCallable`) never
  computed its captured-locals pre-scan (ADR-00619), and `beginDetachedFunc`
  does not save `hoistedCaptures`, so the body ran with the enclosing
  function's set. A captured parameter was promoted to a heap cell at its
  first capture, inside the first branch, and the symbol rewritten in
  place: the second branch used a register its block is not dominated by.
- The immediately-invoked-function path compiled a generator expression as
  a plain closure, and inference fell to the default type.
- `inferEmptyArrayElemTypes` did not descend into nested function bodies.
- A top-level destructuring declaration (`var { array, log } = f()`)
  captured by a method inside a branch was promoted lazily too: its
  bindings never consulted the pre-scan.
- `var [x, y = 4] = [1]; var g = function () { return x + y; }` printed
  11's bit pattern (the staged tree had this, HEAD did not):
  `collectTopLevelNames` missed a pattern's names, so the pre-pass
  promoting a function-valued global took `x` and `y` for builtins and
  typed `g`'s result before they were known.

## Decision

- `emitDynCallable` computes `capturedLocalNames` for its body (saving
  and restoring the enclosing set), and a captured parameter is boxed where
  it is bound, in the preamble that dominates the body.
- A generator expression called at once takes the dynamic call of its
  boxed constructor, as `const g = function* () {}; g()` does; its result
  is `any`.
- The empty-array pre-pass walks arrow functions, function expressions
  and object-literal methods and accessors. Their parameters are `any`
  there; a name they bind shadows the outer candidate; their own empty
  arrays are inferred when they are compiled.
- A pattern's local that a closure captures is moved into its heap cell
  where the pattern binds it (`definePatternLocal`), for object and array
  patterns, static and dynamic. Array-header and nullable-aggregate
  bindings keep their existing handling.
- `collectTopLevelNames` includes every name a top-level pattern binds
  (`ast.ArrayPatternNames`, `ast.ObjectPatternNames`), so a function-valued
  global reading one is not promoted before it is typed.

## Side effects discovered

- An unannotated arrow parameter with no hint is a `number` under
  `-compat=js` (ADR-00042), so `(f) => f()` and
  `for (const f of out) f()` over closures pushed into an empty array are
  compile errors; under strict it is TypeScript's implicit `any`.
- `BigInt(undefined)` does not throw, and `BigInt(1.5)` throws `Error`
  rather than `RangeError`; through `any` they give `0n` and `1n`.

## Verification

Mac (Apple Silicon): the branch-capture program, the generator IIFE with
`next`, `every`, a non-callable predicate and `take(-1)`, and the setter
pushing a string all match Node; the Test262 files compile to valid IR.
