# ADR-01611: -dynamic-import=lazy works on Windows

- **Relations**: Implements TDD-00254, Extends ADR-01330
- **Date**: 2026-10-13

## Context

`-dynamic-import=lazy` refused Windows (ADR-01330), and its five E2E
subtests were the last failures in the Windows suite apart from the RAM
drive's realpath.

## Investigation

See TDD-00254: a DLL binds to an import library at link time and cannot
import a thread-local. A prototype with `-femulated-tls`,
`--export-all-symbols` and `--out-implib` read the executable's
thread-local per thread from a DLL.

## Decision

- `llvm.SetEmulatedTLS` adds `-femulated-tls` to every compile's host
  arguments (and so to the object cache's keys) for a Windows program built
  with `-dynamic-import=lazy`.
- The executable exports every symbol and writes `<binary>.d/program.lib`
  (`ExportDynamicFlags`); each island DLL links against it
  (`IslandLinkFlags`). The Windows refusal in `main.go` goes.

## Verification

Windows 11: every `DynamicImport` E2E test, the five `…/lazy` subtests
included (shared modules, evaluation order, microtask order, top-level
await interleaving, an unsettled target exiting 13).
