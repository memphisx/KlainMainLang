# ADR-00798: node:ffi Stage B — raw memory helpers (peek/poke, to/export buffers, getRawPointer)

- **Relations**: Extends ADR-00797; Implements TDD-00164 (Stage B)
- **Date**: 2026-09-09

## Context

ADR-00797 shipped node:ffi Stage A (loading + typed calls). Any real
pointer-out C API also needs the module's raw-memory helper set — reading a
`char*` a call returned, filling a caller-allocated struct, handing C a
buffer's address. This ADR ships that set (TDD-00164 Stage B), verified
against the Node docs' exact signatures: getter offsets optional, setter
offsets required, `export*` returning `undefined`, `toString` taking no
length parameter.

## Decision

All helpers are `ffi.*` module functions on the existing marker dispatch
(`emit_ffi.go`), with two shared lowerings:

- **Pointer+offset**: a `bigint` address (the pointer-family argument
  lowering from Stage A, so `null`/buffers also work) plus an optional i64
  byte offset via `getelementptr i8`. Length/offset arguments accept both
  `number` and `bigint` (lengths are frequently written `64n`).
- **Byte source**: Buffer/TypedArray (data ptr + element count × element
  size), DataView (data ptr + byteLength from its hidden header), and
  ArrayBuffer (its `{i64, ptr}` header) all normalize to (ptr, byteLength).

Shipped surface:

- `getInt8`…`getFloat64(ptr[, offset])` and `setInt8`…`setFloat64(ptr,
  offset, value)` — a name-suffix table maps each accessor to its canonical
  FFI type, then reuses Stage A's argument/return marshalling (sext/zext
  widening, 64-bit ↔ `bigint`, float32 through double). Loads/stores use
  `align 1`: C-side memory has no alignment guarantee at an arbitrary offset.
- `toString(ptr)` → string, `null` for `0n` (Stage A's `string`-return
  marshal reused verbatim).
- `toBuffer`/`toArrayBuffer(ptr, length[, copy])` — `copy` defaults to true
  (fresh `malloc`+`memcpy`); `copy: false` wraps the native memory zero-copy
  with the caller responsible for its validity, Node's documented contract.
  The flag may be a runtime value (a real branch, not a literal-only gate).
- `exportString(str, ptr, length[, encoding])` — copies the UTF-8 bytes
  NUL-terminated, truncating to the capacity (`min(strlen, length-1)`,
  zero-capacity writes nothing). Only `'utf8'`/`'utf-8'` encodings are
  accepted (UTF-8-native strings); others reject at compile time. Whether
  Node truncates or throws on overflow is unverified against a real
  `--experimental-ffi` build — documented as a caveat.
- `exportBuffer`/`exportArrayBuffer`/`exportArrayBufferView(src, ptr,
  length)` — `memcpy` of the source's bytes; `length` smaller than the
  source's byteLength throws a `RangeError`, as in Node.
- `getRawPointer(src)` → the backing data pointer as `bigint`.

**Dispatch-order fix ridden in on**: the `ffi.*` marker dispatch moved ahead
of every property-name-keyed handler in `emitCall` — `ffi.toString(ptr)` was
being captured by the generic number-`.toString` path, because a module
marker identifier has no real value type and infers as the number default.
The FFI checks (library methods + module functions) now sit with the other
type-flag dispatches at the top of the chain.

## Consequences

- Pointer-out APIs are fully usable: allocate with a dlopen'd `malloc`, pass
  the address, decode results with the getters/`toString`/`toBuffer`.
- Zero-copy views carry Node's own lifetime hazard (freed native memory
  behind a live Buffer) — matching the module's explicitly unsafe posture.
- Remaining for TDD-00164: Stage C `registerCallback` (the trampoline),
  `using` disposal, Windows.

## Verification

- `tests/ffi_test.go` additions (macOS M4): every accessor width round-trips
  (including `int64` above 2^53 and `uint64` max exactly), optional getter
  offset, `exportString` + truncation, `toString(0n) → null`, copy-vs-view
  `toBuffer` semantics (a write through the pointer is visible in the view,
  not the copy), `toArrayBuffer().byteLength`, `getRawPointer`,
  `exportArrayBufferView` + its too-small-capacity throw.
- `examples/ffi/ffi.ts` extended with a peek/poke + `exportString`/
  `toString`/`toBuffer` block. Buffer/`toString`/sqlite regression slice and
  the Node oracle re-run are flat.
