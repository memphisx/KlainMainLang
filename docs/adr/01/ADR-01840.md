# ADR-01840: BinaryExpression switched to the checker

- **Relations**: `Implements TDD-00230` (P3.3: the checker answers what inferExprType did)
- **Date**: 2026-10-20

## Context

The previous full shadow run left 29 BinaryExpression disagreements. Once the earlier fixes were rechecked, these causes remained:

- A bound name is read from its storage (`identStorageType`, which runs before the checker is asked). Where that storage is a box, or a scalar slot that holds undefined (a callback's parameter over boxed elements, a `reduce` accumulator a callback may leave undefined), the oracle still answered with the checker's `number`. Every operator over such a name inherited the wrong answer.
- `a && b` and `a || b` are value-preserving in both lanes. Their slot comes from the operands' representations (`andAbsentScalar`, then `shortCircuitValueType`, else bool). The oracle used the checker's narrowed type, which is `undefined` for `undefined && true`.
- Under `-compat=js`, an arithmetic operand held null or undefined goes through the runtime dispatch and yields a box (ADR-00901). The oracle said `number`.

## Decision

- An identifier whose binding is held as a box or as an undefined-holding scalar answers with that storage. `heldIdent` now returns `identStorageType`, flow refinement included, instead of the raw binding type.
- The oracle computes `&&`/`||` the way emission does, from its own operand answers.
- Under `-compat=js`, an arithmetic operator with a null- or undefined-held operand is a box, unless a real string side concatenates.
- `a ?? b` is computed the same way. The old inference's case moved into `nullCoalesceType(lt, rt)`, which both sides now call. Without it, `x ?? null` on a `number | undefined` became a double and failed to convert to a string.
- `await p` of an operand held as a promise is that promise's payload as held, as `emitAwait` produces it. An index read off an array held with boxed elements reads the box. `Promise.all([new T(2), Promise.resolve(7)])` over a thenable class fulfills with boxes, which had been read as doubles (`[ 4.5, 7.5 ]`, and `typeof all[0]` gave `undefined`).
- An interface over a native layout (`interface Coded extends RangeError`, `interface Stamp extends Date`) is found by `interfaceRepr`, which had accepted only object layouts with fields. An object assertion keeps that interface's name when the layouts match. The name is what `nativeIfaceMember` reads the interface's own members through, and the shadow compare treats it as metadata, so the missing name never showed up as a row.
- BinaryExpression joins the switched kinds. A node the checker has no answer for falls back to the old inference and is logged as `switchFallback`, as for the other non-settled kinds.

## Consequences

- No disagreements remain in the files behind the 29 rows (union values, JS-lane undefined arithmetic, named array properties, the Test262 logical, coalesce, modulus and generator files).
- `TestE2EPromiseAllThenableElementRead` added.
- Verified on Apple Silicon (targeted logical/nullish/arithmetic/binary/union/callback/JS-file/async/interface tests). The gate runs on Linux x86-64 (DeskMini).
