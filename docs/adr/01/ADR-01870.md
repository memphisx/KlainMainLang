# ADR-01870: A type parameter maps to the instantiation being emitted

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's NonNullExpression, ArrayLiteral and IndexExpression rows inside generic bodies)
- **Date**: 2026-10-21

## Context

- Codegen emits a generic function's body once per instantiation, with `typeParamScope` naming each type parameter's concrete type. The checker types the body once, with its type parameters. The oracle mapped no type parameter, so every expression typed by one (`[a]`, `xs[0]!` with `a: T`, `xs: T[]`) was unanswered and left to codegen's own inference.

## Decision

- The representation mapping takes a type parameter, named by its declaration's symbol or its own name, to the concrete type `typeParamScope` gives it while an instantiation is emitted. Outside an instantiation it stays unanswered, as before.

## Consequences

- `examples/generics/generic_promise.ts` leaves the switch-fallback rows; the generics E2E suite is unchanged.
- Verified on Apple Silicon.
