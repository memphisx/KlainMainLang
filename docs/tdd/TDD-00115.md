# TDD-00115: Object members in union types (usable via narrowing)

- **Status**: Implemented
- **Date**: 2026-08-25
- **Notes**: Allow one object/interface/class member in a union (boxed as tag 6, reference-equality + `[object Object]` stand-in un-narrowed); `typeof x === "object"`/truthiness narrows to it and unboxes to the typed pointer so fields/destructuring/rest work. Structural assignment check; two object members (discriminated unions) and array members deferred. Closes TDD-00065 Stage 3c's object-union case

## Context

Union types ([TDD-00043](TDD-00043.md)) are scalar-members-only — an object,
interface, or class member is a clean rejection (`union member types are
currently limited to number, string, and boolean`). That blocks the realistic
`body: string | ArrayBuffer` / `value: string | Point` API shapes TDD-00043's own
Context flagged, and it is the last still-deferred sub-case of
[TDD-00065](TDD-00065.md) Stage 3c (object rest over an object-union source) and
of the object-model work in [TDD-00068](TDD-00068.md).

Two things that were missing when TDD-00043 shipped now exist and make this
tractable:

- **Object boxing already works** — `emitBoxValue` boxes an object pointer as tag
  6 (`kmlTagObject`), and `emitDynamicToString`/`__kml_any_eq` already give a
  boxed object a `"[object Object]"` stand-in and reference equality. So the
  *un-narrowed* boxed object is already safe (no crash), exactly like a boxed
  array.
- **Flow narrowing exists** ([TDD-00114](TDD-00114.md)) — the box can't carry an
  object's field shape at runtime, but narrowing recovers the **static** member
  type in a branch, and `emitUnboxBoxToType` already unboxes a box to a concrete
  pointer type. So `if (typeof x === "object") { x.field }` recovers the object
  type and rides the existing object field-access machinery.

## Design

### Representation — unchanged

An object union member reuses the exact `{ i8, i64 }` box: tag 6, payload =
`ptrtoint` of the object's heap pointer (already emitted). No new runtime shape;
the static member type supplies the fields when narrowed.

### Validation and assignment

- `validateUnionMembers`: accept an object/interface/class member (`IsObject` /
  `IsClass`), not just scalars. **V1 restriction: at most one object member per
  union** — with two object members (`A | B`), `typeof x === "object"` can't pick
  one (that needs discriminated-union narrowing, deferred), so a second object
  member is a clean rejection.
- `unionAllowsAssignmentFrom`: an object value is assignable to the union when it
  structurally matches the (single) object member — reuse `matchExtends`
  (structural width subtyping), the same test generic constraints use. A scalar
  value still matches a scalar member as today.

### Narrowing to the object member

- `unionMemberTag` returns `"object"` for an object member (the `typeof` a boxed
  object reports). `typeof x === "object"` narrows to the object member;
  `emitUnboxBoxToType` unboxes tag-6 payload → `inttoptr` → the member's object
  `Type`, so field access / destructuring / object rest (closing TDD-00065 Stage
  3c's object-union case) all work via existing machinery.
- Truthiness `if (x)` on `Point | null` narrows out null → the object member
  (single remaining) → concrete, same as the scalar path.

### Un-narrowed behavior — unchanged stand-ins

An un-narrowed object-union value keeps the boxed-object stand-ins already
present: `String(x)`/`console.log` → `"[object Object]"`, `===` → reference
equality. Field access on an *un-narrowed* object union is a clean rejection
(the shape isn't known without narrowing) — the same posture bare `any` takes.

### Relationship to boxed-`any` object shape

Full field access on a bare `any` holding an object stays deferred
([TDD-00062](TDD-00062.md)) — `any` carries no static shape to recover, unlike a
union member. This TDD unlocks the *union* case (which does carry member shapes),
not general `any`-object introspection.

## Scope (V1)

- **In:** a union with scalar members plus **at most one** object/interface/class
  member; assignment checked structurally; narrowing via `typeof === "object"` /
  truthiness to recover the object type and use it (fields, destructuring, object
  rest); un-narrowed stand-in toString/equality.
- **Out (deferred):** two+ object members (discriminated unions); array/
  `ArrayBuffer` union members (2-slot aggregate doesn't fit the box's single
  payload — a separate representation question); field access on an un-narrowed
  object union or bare `any`; `switch`/`in`-based discriminant narrowing.

## Open questions

- **Structural vs nominal member match at assignment.** `matchExtends` is
  structural width subtyping; confirm a class-instance value assigns to an
  interface-typed object member (it should) and that two same-named-but-different
  shapes don't false-match (they won't — structural compares fields).
