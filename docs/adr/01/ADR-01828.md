# ADR-01828: One GC interface; codegen and the runtime never name the collector

- **Relations**: `Implements TDD-00230` (phase 4: one GC interface in the runtime)
- **Date**: 2026-10-20

## Context

- Codegen called Boehm directly in 23 places:
  - `GC_malloc_uncollectable` for shared buffers;
  - `GC_gcollect` and `GC_invoke_finalizers`;
  - the fiber stack bottom through `@GC_stackbottom`, `GC_set_stackbottom` and `GC_get_my_stackbottom`.
- Three of those were runtime functions written as IR text in Go (`__kml_gc_set_sb_locked`, `__kml_gc_set_sb`, `__kml_gc_get_sb`).
- Ten C runtime files declared and called `GC_*` themselves. Each learned of `-mm=gc` under its own macro: `KML_GC`, `KML_GC_MODE`, `KLAIN_GC`, `KLAINSYNC_GC`, `KLAINPOOL_GC`, `KML_GC_SB`.
- Another collector would have meant editing all of them.

## Decision

- **The interface.** `kml_heap.h`, which precedes every runtime file, declares `kml_gc_*`:
  - allocation: plain, pinned, atomic, atomic-pinned; free; the base of a managed block;
  - weak links, finalizers (returning the previous one's data), running queued finalizers, collect;
  - root ranges, heap statistics;
  - thread permission, registration and unregistration; the allocation lock; the suspend and restart signals;
  - the fiber stack bottom: set, set with the lock held, read, and this thread's own base.
- **`gcshim.c` implements it on Boehm.** It is the only file that includes `gc.h` or names a `GC_*` function. Only gc-mode code calls the interface.
- **Codegen calls `kml_gc_*` only.**
  - `main()` starts with `kml_gc_main_started(threads)`. That records the main thread's stack base, and says whether Worker threads will run.
  - A fiber switch calls `kml_gc_set_stack_bottom`. That writes the process-wide bottom while single-threaded, and this thread's own record under the lock once threads run. On Windows it reads the running stack from the TEB instead.
  - The three IR-text functions are deleted.
- **A thread's own stack base lives in gcshim.c.** It replaces the `__kml_gc_orig_stackbottom` thread-local that IR, `task.c` and `worker.c` shared. It is written only after the thread registers: on macOS a thread's first thread-local access allocates through `malloc`, which is the collector's here.
- **`gc.h` makes `GC_alloc_lock`/`GC_alloc_unlock` no-op macros without `GC_THREADS`.** gcshim.c declares the threaded library's real functions instead. klain:sync holds that lock across a goroutine switch, and the first version of the wrapper, through the macros, crashed `TestE2EGCModeGoroutinesSelectChurn` on Apple Silicon.
- **One mode macro.** Under `-mm=gc` every runtime file is compiled with `KML_GC` defined ahead of the shared prelude. The per-file defines and cflags are deleted. `KLAINPOOL_GC_ENABLE`, the thread pool's ownership of thread permission, stays.

## Consequences

- The Boehm-specific code is one file, so another collector is another implementation of the `kml_gc_*` list.
- The IR-text allowance falls by three (`emitter.go` 11→9, `runtime_worker.go` 2→1).
- Verified: the gc, weak, finalization, Worker, generator and async E2E tests on Linux x86-64 (DeskMini), and a gc-mode selection on Apple Silicon (Worker round trip, coroutine chains, generators from the module task, goroutine select churn, FinalizationRegistry, WeakRef, task stack reclamation, thread-local roots, class records).
- Still open in phase 4's GC interface:
  - pin/unpin and handle tables for native code holding managed pointers;
  - safepoint and write-barrier hooks;
  - `kml_gc_alloc(typeid, size)`, which waits on phase 5's type ids.
