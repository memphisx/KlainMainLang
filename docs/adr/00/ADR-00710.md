# ADR-00710: Catch SIGINT in the E2E test binary — sh-`&` shards spawned servers with SIGINT ignored

- **Date**: 2026-09-04

## Context

`TestE2ESignalNoHandlerDefaultDisposition` (a no-handler `http.listen`
program must die from SIGINT via the OS default disposition) failed under
4-shard `make test-par` but passed on the serial retry, so the suite
reported PASS overall. It looked like a rare concurrency race: during a
failing run, re-sending SIGINT for 20 seconds never killed the server,
while SIGTERM always worked, and the failure never reproduced under pure
CPU load or compile churn.

## Investigation

The signal *mask* audit came up clean: the only `pthread_sigmask` in the
emitted runtime is the Worker trampoline (blocks all signals on worker
threads, by design; the failing program spawns no workers), fiber
contexts are all `getcontext`-initialized before `makecontext`, and
Darwin `setjmp`/`swapcontext` save/restore the mask symmetrically.

The actual cause is signal *disposition* inheritance, and it is
deterministic, not a race:

1. `test-par` launches each shard as `( ... ) &` from make's
   non-interactive shell. POSIX requires async commands in a shell
   without job control to start with SIGINT and SIGQUIT set to SIG_IGN.
   Verified with a sigaction-probe binary: foreground → SIG_DFL,
   sh-backgrounded → SIG_IGN.
2. The Go runtime honors a SIG_IGN disposition present at process
   startup — it does not install its own SIGINT handler over it.
3. Ignored dispositions survive `exec`, so every compiled server the
   shard's test binary spawned inherited SIGINT=SIG_IGN. The server
   "ignored" SIGINT because the shell told it to; the emitted runtime
   was never involved. SIGTERM was unaffected (the shell only touches
   INT/QUIT), matching the observed asymmetry exactly.

Why it never reproduced in isolation: a foreground `go test -run ...`
interposes the go tool, whose own `signal.Notify` makes SIGINT *caught*
in the tool — and caught signals reset to SIG_DFL across exec, so the
test binary (and its servers) started clean. `test-par` runs the
precompiled test binary directly, skipping that accidental laundering.
Running the precompiled binary under `sh -c '( ... ) & wait'` reproduced
the failure deterministically in 15s, single test, idle machine.

An earlier diagnosis note warned that bash-`&` repros are invalid
because the shell sets SIG_IGN — that mechanism was the bug itself, one
layer up: the *shard*, not the repro, was the background job.

## Decision

Add `tests/main_test.go` with a `TestMain` that `signal.Notify`s SIGINT
into a goroutine that exits with code 130. This flips SIGINT to caught
in the test process no matter how it was launched, so every exec'd child
starts with SIGINT=SIG_DFL — the same state a foreground run always had.
It also makes Ctrl-C actually terminate a backgrounded shard, which
SIG_IGN previously blocked (shards survived an interrupted `make
test-par`).

Fixing the Makefile instead (resetting the disposition inside the shard
subshell) is not portable: POSIX forbids a script from `trap`-resetting
a signal that was ignored on entry, so it would need an external helper
binary. The Go-side fix is self-contained and hardens the suite against
any future launcher.

## Consequences

- `TestE2ESignalNoHandlerDefaultDisposition` passes under the exact
  test-par spawn conditions (verified: precompiled binary, sh-`&`), and
  the full signals suite passes the same way.
- Default-disposition assertions in tests are now environment-independent.
- The serial-retry escape hatch no longer masks this class of failure.
