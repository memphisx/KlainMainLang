# ADR-01490: An instance's own properties and methods

- **Relations**: Extends ADR-00887, TDD-00230
- **Date**: 2026-10-09

## Context

In `-compat=js`, a class instance took no property its class did not
declare. `this._read = fn` in a constructor, `q.go = fn` on an instance
whose class has `go()`, and `q.extra = 5` failed to compile ("no field").
JavaScript gives the instance an own property, and a call of that name
then runs the instance's function, not the class's.

## Investigation

- A store through `any` onto a static object already adds an own
  property beside the layout (`__kml_shape_expando_set`), and a dynamic
  read or call through `any` finds it first.
- The js-lane constructor inference made `this._read = fn` a field named
  like the method. A call of `_read` then went to the class's method, and
  the field was never read.
- A call of a name the class does not have stopped at the generic
  missing-method diagnostic (emit_call.go), before reaching the class
  call path.

## Decision

- A read, write or call of a name a class instance does
  not declare goes through the instance boxed as `any`. The property
  lives beside the layout, as on any static object.
- A constructor assignment to a name the class declares as a method is
  an own property, not an inferred field.
- When the program assigns a property of a method's name anywhere, a
  call of that method checks the instance's own properties first
  (`__kml_shape_expando_has`) and calls the own function when there is
  one. Other method calls are unchanged.
- Both lanes: whatever reaches codegen passed the checker, and the strict
  lane's valid forms (`q.m = fn` for a declared method, `(p as any).m =
  fn` then `p.m()`) need the same paths (BACKLOG 91). An undeclared name
  in the strict lane is the checker's TS2339 before codegen.
- The own-or-class call's result slot has the value's register form (an
  array's `{ptr, i64}`; the httpbin fixture caught a method returning an
  array stored as a pointer), and a private name (`#m`) never takes the
  check.
- `for…in` over a class instance lists its own keys, the added ones
  included (its methods are not enumerable), as `Object.keys` does.
- A method adding a property (`grow() { this.b = 2 }`) was a deliberate
  js-lane rejection, asserted by a test. It is now an own property, as in
  Node, and the test compares against Node
  (`TestJSModeMethodIntroducedProperty`).
