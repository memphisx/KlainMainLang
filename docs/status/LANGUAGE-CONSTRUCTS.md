| Array destructuring `const [a, b] = arr` | ✅ | • *Assignment* to already-declared targets (`[a, b] = expr`, not a fresh declaration) is narrower than a declaration: every target must be a plain variable — no nested patterns, no default, no compound operator ([ADR-00160](../adr/ADR-00160.md))<br>• Nested patterns work in a declaration, for-of loop variable, and destructured parameter, but not yet in the *assignment* form; a `= default` on a nested position is a clean rejection ([ADR-00193](../adr/ADR-00193.md)/[TDD-00065](../tdd/TDD-00065.md) Stage 2) | • Holes are supported (`const [, b] = arr` skips index 0)<br>• Default values (`[a = 1]`) fire exactly when that position is past the source array's actual length — see [ADR-00157](../adr/ADR-00157.md)/[ADR-00158](../adr/ADR-00158.md)<br>• A rest element (`[a, ...rest]`) works in the declaration form, a destructured parameter, and the assignment form alike — a real, independent copy of every remaining position, empty (not an error) when the source is shorter than the pattern — see [ADR-00161](../adr/ADR-00161.md)<br>• Usable as a for-of loop variable (`for (const [a, b] of pairs)`, over an array-of-arrays), reusing the same unpack core — see [ADR-00192](../adr/ADR-00192.md)/[TDD-00065](../tdd/TDD-00065.md) Stage 1<br>• Nested patterns (`[[a, b], c]`, `[{ x }, { y }]`) work in a declaration, for-of loop variable, and destructured parameter — see [ADR-00193](../adr/ADR-00193.md)/[TDD-00065](../tdd/TDD-00065.md) Stage 2 |
| Object destructuring `const { x, y } = obj` | ✅ | • Default values (`{ x = 1 }`) are supported only for a field typed as a nullable *reference* (`T \| null` where T is string/array/object/class) — the only field shape with a real "not provided" signal; nested patterns don't work in the assignment form and there's no `= default` on a nested position<br>• `{ ...rest }` over an `any`/union/generic source (Stage 3c) and in the *assignment* form (`({ a, ...rest } = e)`) stay clean rejections<br>• No computed key (`{ [key]: val }`)<br>• The object-*type* annotation grammar still rejects a string-literal-named field, so a genuinely non-identifier field name (`"first-name"`) is reachable only via object-literal type inference | • Renaming is supported (`{ x: y }`)<br>• *Assignment* to already-declared targets (`({ x, y } = expr)`, parens required at statement level, matching real JS) — see [ADR-00160](../adr/ADR-00160.md)<br>• Nested patterns (`{ inner: { v }, tag }`, `{ coords: [x, y] }`) work in a declaration, for-of loop variable, and destructured parameter — see [ADR-00193](../adr/ADR-00193.md)/[TDD-00065](../tdd/TDD-00065.md) Stage 2<br>• String- or numeric-literal keys (`{ "k": v }`, `{ 0: v }`) reuse the object-literal key grammar — a non-identifier key has no shorthand, so it must bind through an explicit `: name` ([ADR-00203](../adr/ADR-00203.md)/[TDD-00065](../tdd/TDD-00065.md) Stage 3a)<br>• A rest element (`{ a, ...rest }`) works in the declaration, for-of, and destructured-parameter forms ([ADR-00204](../adr/ADR-00204.md)/[TDD-00065](../tdd/TDD-00065.md) Stage 3b): `rest` binds a fresh residual object of every visible source field not named earlier — a plain object (a class instance's rest strips hidden metadata, matching JS's own-enumerable copy), shallow-copied (a pointer-valued field is shared), usable like any object; requires a statically-known source shape<br>• Usable as a for-of loop variable (`for (const { x, y } of points)`) — see [ADR-00192](../adr/ADR-00192.md)/[TDD-00065](../tdd/TDD-00065.md) Stage 1 |

## Known limitations

- **Strict-mode early errors**: there's no general strict-mode parser context, so several Test262 early-error cases around a literal `"use strict"` directive stay unrejected — notably `eval`/`arguments` as an *assignment* target in strict code, and bindings inside a getter/setter accessor body. A narrower safe subset is caught: duplicate parameter names, a non-simple parameter list, and `eval`/`arguments` as a parameter or `let`/`const`/`var` (or for-of/for-in loop-variable) binding name under `"use strict"` (or an always-strict class method). Block-scope `let`/`const`-vs-`var` redeclaration *is* now tracked — a strict-independent early error, including the cross-nested-block `let x; { var x }` intersection (see [TDD-00070](../tdd/TDD-00070.md)/[ADR-00210](../adr/ADR-00210.md)/[ADR-00211](../adr/ADR-00211.md)).
