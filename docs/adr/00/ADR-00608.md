# ADR-00608: Constant-key bracket access on a fixed-shape object

- **Relations**: Complements the tuple constant-index path (TDD-00066) and dynamic-object `obj[key]` (TDD-00012)
- **Date**: 2026-09-01

## Context

Bracket access with a compile-time-constant key on a fixed-shape object —
`o["a"]`, `o[0]` (a numeric-literal key) — was a clean error (`'o' is not an
array`): only `o.a` dot access reached the field. A dynamic (map-backed) object
already supported `d[key]`; a tuple already supported `t[0]`; but a plain static
object did not, and `o["a"]` is common real-world code.

## Decision

For a fixed-shape object (an object literal's static struct, or a class
instance) with a **compile-time-constant** string or integer key, resolve the
bracket access to the matching field — the same field `o.a` would reach.

- **Read** (`emitIndex`): after the dynamic-object and tuple branches, a value
  whose type is `IsObject && !IsArray` with a `constObjectKey` index does a
  `FieldIndex` GEP + load (a class getter is dispatched first, mirroring the dot
  read path; visibility is checked for a class field). A missing field is a clean
  "object has no field" error.
- **Write** (`emitAssign`): `o["a"] = v` / `o[0] += v` is rewritten to the
  equivalent member-target assignment (`o.a = v`) and re-emitted, so it reuses the
  accessor / `readonly` / nullable / frozen machinery unchanged.

`constObjectKey` accepts a string literal (its value) or an **integer** numeric
literal (its digit text, matching the field name an object literal stores for a
numeric key); a bigint or non-integer literal is not a valid key. A non-constant
key on a fixed object stays a clean rejection (the struct has no runtime key
lookup — that is what a dynamic `{ [k: string]: T }` object is for).

The object-type-annotation grammar (both `interface` bodies and inline
`{ ... }` type literals) also accepts a string-literal or numeric field name
(`interface P { "first-name": string }`, `type T = { 0: string }`), mirroring the
object-literal key grammar — so such a field is declarable in a type, not only in
an object literal, and is then reachable via the constant-key access above.

## Verification

Read (`o["a"]`, `o["b"]`, `n[0]`, `n[1]`, `new C()["field"]`), write (`o["a"] =
v`), and compound (`o["count"] += 3`) all match Node v26; a dynamic
index-signature object's `d[key]` is unaffected. Object / array / index / tuple /
enum / class / string suites still pass. Built and verified on Mac (Apple Silicon).
