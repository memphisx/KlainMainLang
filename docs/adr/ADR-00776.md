# ADR-00776: `Array.prototype.reduceRight()`

- **Relations**: Extends [ADR-00163](ADR-00163.md) (`.reduce()` optional initial value)
- **Date**: 2026-09-08

## Context

`.reduceRight()` was the one array method with no implementation at all — it
appeared in the HOF method-name allowlists (`emit_exprs_operators.go`,
`emit_arraybuffer.go`) but had no dispatch, so a call fell through to the
generic "unknown method" path. The array-methods status page and the website
reference both called it out as the sole not-implemented array method
(BACKLOG §4). A small, self-contained fidelity gap.

## Investigation

`.reduceRight()` differs from `.reduce()` (`emitArrayReduce`,
`emit_arrays_hof.go:277`) only in traversal order — it seeds from the last
element (or the initial value) and walks the index down to 0, with the callback
argument order (`accumulator`, `element`, …) unchanged. The accumulator
storage, callback invocation, result coercion, and the empty-array-with-no-init
throw (`"Reduce of empty array with no initial value"`, the same message Node
uses for both) are all identical.

Two shapes were possible: a separate `emitArrayReduceRight` duplicating the
~100-line body, or parameterizing `emitArrayReduce` with a direction flag. The
loop differs in only three spots — the start-index setup, the loop-termination
test, and the step — so a `fromRight bool` parameter keeps the shared machinery
in one place and makes the direction the single axis of difference, which is
what the code actually is. Duplication was rejected as needless divergence risk.

## Decision

`emitArrayReduce(mem, args, pos, fromRight bool)`. When `fromRight`:

- **Start index**: `len-1` with an initial value; with no initial value the
  seed is `arr[len-1]` and the loop starts at `len-2`. (Ascending: `0` and `1`.)
- **Termination**: `icmp slt i64 idx, 0` — the descending index finishes once
  it passes 0 and goes negative. (Ascending: `idx == len`.) An empty array with
  an initial value starts at `len-1 == -1`, so the loop body never runs and the
  initial value is returned, matching real JS.
- **Step**: `sub i64 idx, 1`. (Ascending: `add i64 idx, 1`.)

`reduce`/`reduceRight` dispatch in `emit_call.go` pass `false`/`true`; the
type-inference case in `emit_exprs_types.go` covers both (the accumulator type
is the initial value's type when given).

## Verification

- `go build`, `go vet ./codegen/...` — clean.
- 5 new E2E tests (`tests/arrays_test.go`): right-to-left order (`"dcba"`),
  no-initial seed + direction (`-5`), single-element no-init (`42`),
  empty + initial (`42`), empty + no-init throws. All pass.
- `examples/arrays/higher_order.ts` gained a `reduceRight` section (compiles and
  runs; `dcba`, `-5`).
- Verified on macOS (Apple Silicon).
