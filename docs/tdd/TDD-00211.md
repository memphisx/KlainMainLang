# TDD-00211: Any-keyed `Map<any, any>` — heterogeneous keys, SameValueZero

- **Status**: Implemented — [ADR-00932](../adr/ADR-00932.md)

## Context

`Map` today has exactly two backing runtimes, chosen at compile time from the
key type (`emitMapOrSetCreate`): `__kml_map_str_*` (string keys, hashed by
content) and `__kml_map_num_*` (numeric keys, hashed by raw i64 bits, compared
with `icmp eq`). A bare `new Map()` with no type arguments, no annotation, and
no seed entries defaults to **string keys, number values** (`mapKVTypes`).

That default miscompiles the idiomatic untyped map. `new Map(); map.set(1, 42)`
inttoptr's the numeric key through the string path; `map.set('a', 'x')` stores a
string pointer into an i64-typed value slot and reads it back typed as a number.
The three Test262 CLANG_ERROR files that exercise this all use the same shape —
`var map = new Map()` followed by heterogeneous `.set(k, v)` over string,
number, `NaN`, boolean, object, array, symbol, `null`, `undefined` keys
(`built-ins/Map/prototype/{get/returns-value-different-key-types,
has/return-{true,false}-different-key-types}`).

Two things are missing: (1) a runtime that can hold **heterogeneous** keys with
JS `Map` key semantics, and (2) type inference that widens a bare `new Map()` to
that runtime when its uses demand it.

## Design

### Runtime: `__kml_map_any_*`

A third monomorphic map runtime, structurally identical to `__kml_map_num_*`
(same 56-byte open-addressing header: `{size, cap, keys, vals, idx, icap,
used}`, same dense keys/vals arrays, same probe/rehash/tombstone machinery).
Keys **and** values are stored as NaN-boxed `i64` words. It differs from the
numeric map in exactly two places:

- **Hash** (`__kml_map_any_hash`): must agree with equality. String-kind boxes
  hash by **content** (reuse `__kml_map_str_hash` on the underlying char\*), so
  two distinct string pointers with equal content collide into the same slot;
  the numeric-zero box is **normalized** (`-0` → `+0` bits) before hashing so
  `map.set(-0, …)` and `map.get(0)` land together; every other box hashes by its
  raw i64 bits through the existing multiply-shift.
- **Equality** (`__kml_map_svz`): JS **SameValueZero**, not `===`. It is exactly
  `__kml_any_eq` (strict equality over boxes: numbers by `fcmp oeq` so `-0`/`+0`
  equal, strings by `strcmp`, objects/arrays by identity) **plus** the one case
  where SameValueZero and strict equality diverge — `NaN` is SameValueZero-equal
  to `NaN`. So `svz(a,b) = any_eq(a,b) || (isNaN(a) && isNaN(b))`. The numeric
  map's raw `icmp eq` is wrong here (string content, and `NaN`); there is no
  shortcut.

`get` returns the boxed value or the `undefined` box on miss (the numeric map
returns `0` on miss — wrong for `any`). `keys`/`vals` return `{ptr, i64}` arrays
of boxes, i.e. `any[]`, which is already the representation `Array.from(map.keys())`
and `for…of` expect.

### Compile-time: bare-`new Map()` K/V widening

Mirror `inferEmptyArrayElemTypes` (TDD-00205 Stage 1): a pre-pass
(`inferEmptyMapKVTypes`) scans each scope for bindings initialized to a bare
`new Map()` (no type args, no annotation, no seed) and unifies the key and value
types across every `map.set(k, v)` contribution in that scope:

- **keys** — all string ⇒ string map; all one numeric type ⇒ numeric map;
  anything else (heterogeneous, or a boolean/object/symbol/`null`/`undefined`
  key, or mixed) ⇒ **any** map. Zero contributors keeps today's default (the key
  type is unobservable).
- **values** — unify likewise; heterogeneous ⇒ `any` (boxed).

The result is stashed in `e.emptyMapKV[name]` and consulted by `emitMapVarDecl`.
This also fixes, in passing, a bare `new Map()` used purely with numeric or
string-valued keys that today silently rides the wrong default.

### Dispatch wiring

`emitMapOrSetCreate`, `emitMapCall` (set/get/has/delete/keys/values/entries/
forEach/clear), `emitMapSeedFromEntries`, and the keys/vals/entries/forEach
array producers gain a third `anyKey` branch alongside the existing str/num
split. Keys reaching an any-map are boxed via `emitBoxValue` (not `coerce` — an
already-evaluated `NaN` is an i64 box that `coerce`'s IR shortcut would leave
unboxed, the variadic-arguments gotcha); values likewise. `get` yields
`TypeAny`.

### Scope

Stage 1 (this TDD): `Map<any,any>` — the runtime, the widening pre-pass, and
full method dispatch. `WeakMap`, and `Set<any>` heterogeneous sets, are **not**
in scope (Set keeps its str/num split; a separate follow-up if a test needs it).

## Open questions

- Content-hash collisions: string keys share the str-map hash; fine. Object keys
  hash by identity pointer — correct (Map keys objects by reference).
- `-0` normalization lives only in the hash; equality already unifies `-0`/`+0`
  via `fcmp oeq`, so stored keys keep their original box (observable via
  `keys()` — Map preserves the first-inserted key, and `-0` is normalized to
  `+0` on the way in per spec, so normalizing the stored key too is acceptable
  and matches the "normalized zero key" tests).
- Sets with heterogeneous elements: deferred; no failing file needs it yet.
