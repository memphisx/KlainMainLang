# ADR-02052: bind reads its target's `length` and `name`; concat honors isConcatSpreadable on `any`

- **Date**: 2026-11-22

## Context

- A bound function's `name` and `length` were computed from the target's
  compiled metadata when read: a redefined `name` or `length` on the
  target was ignored (`bound fn`, not `bound renamed`), a non-string
  `name` showed the compiled one, and an accessor ran on every read of the
  bound function's `name` rather than once, when `bind` ran — so its throw
  never reached `bind`.
- A function's own non-string `name` (`defineProperty(h, "name",
  { value: 42 })`) read through `any` as the compiled name.
- `[0].concat(a)` with `a` held in `any` spread it exactly when it was an
  array: a `Symbol.isConcatSpreadable` accessor never ran (its throw was
  lost), a spreadable array-like was appended whole, and an array marked
  unspreadable was spread.

## Decision

- In a program naming both `defineProperty` and `bind`,
  `fn.bind(…)` also runs `__kml_Function_boundProps` (lib/node/
  kml_object.ts): ECMA-262's `HasOwnProperty`/`Get` of `length` and
  `Get` of `name` on the target, defined on the bound function. Other
  programs keep the metadata answer, which they cannot tell apart.
- A dynamic function's `name` read returns its own value of any type,
  falling back to the metadata name only when it has none (the accessor is
  invoked once).
- In a program naming `Symbol.isConcatSpreadable`, a `concat` with an
  `any` argument runs the library's generic concat (IsConcatSpreadable);
  the resolver links it for such programs.

## Consequences

- `TestE2EBindReadsTargetNameLength` compares these with Node.
