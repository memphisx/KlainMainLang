# ADR-01783: A `.then` callback with no return resolves to undefined

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- `p.then(() => { cc++; })` resolved the next promise to the value of `cc++`, and `() => { f(x); }` resolved to its argument. The `.then` emitter typed the callback's result by inferring the body. A block with no `return <value>` was inferred as the type its context accepts (a number), not void. The runner then called a `void` closure as if it returned a double and read a stale register.
- Test262 runs pass `$DONE` straight to `.then`, so each such test failed with the stale value as its error.

## Decision

- `inferUnannotatedReturnTypeParams` returns void for a body with no `return <value>`.
- The `.then`/`.catch` emitter takes the callback's result type from the closure it emitted (`emittedCallbackReturn`), falling back to inference only when that is unknown. The runner calls the closure by the ABI it was compiled with.

## Consequences

- `TestE2EJSFileVoidThenCallbacks` compares fulfilled, rejected and async-generator chains against Node.
