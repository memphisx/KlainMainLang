# ADR-00604: Enforce the `readonly` class-field modifier

- **Relations**: Implements [TDD-00154](../tdd/TDD-00154.md); supersedes the "parsed but not enforced" stance of [ADR-00447](ADR-00447.md) (parameter properties) and [ADR-00480](ADR-00480.md) (plain fields)
- **Date**: 2026-09-01

## Context

`readonly` on a class field and on a constructor parameter property was parsed
and erased — a later write was silently accepted. TypeScript rejects a write to a
readonly field outside its declaring class's constructor. This closes that
fidelity gap with a compile-time check (no runtime IR).

## Decision

Record `readonly` and check writes at emit time.

- The class-member modifier loop sets a new `AnnotField.Readonly` flag; the
  parameter-property path feeds `Param.PropReadonly` into it.
- `registerClasses` collects readonly instance-field names into
  `ClassInfo.ReadonlyFields` (own + inherited).
- A new emitter flag `currentCtorClass` names the class whose constructor body is
  being emitted (and is cleared inside any nested function/closure body, so a
  readonly write in an arrow nested in the constructor is still rejected).
- `checkReadonlyWrite`, called from the class-field-assignment path, rejects a
  write to a readonly field unless `currentCtorClass` equals the field's
  declaring class (`FieldOrigin`). A regular method, an external `obj.x = v`, or a
  subclass constructor writing an inherited readonly field are all clean errors —
  TS's exact rule. Field initializers are covered because they are spliced into
  the constructor body.

The class name in the diagnostic is de-mangled via `inspectClassName`.

## Verification

`TestE2EReadonlyFieldConstructorWriteOK` (ctor + initializer writes allowed;
non-readonly sibling still mutable), plus rejection tests for an outside write, a
method write, a `readonly` parameter property write, and a subclass writing an
inherited readonly field. Example `examples/classes/classes.ts` gains a
`readonly`-field `Endpoint`. Class suites still pass. Built and verified on Mac
(Apple Silicon). Node can't run parameter-property syntax (a TS-only runtime
construct its type-stripping rejects), so those cases are covered by the Go E2E
tests rather than a node-oracle example.
