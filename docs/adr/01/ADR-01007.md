# ADR-01007: Error options bag — `new Error(msg, { cause })`

- **Relations**: Extends ADR-01004 (reason/`any` slot conventions), TDD-00222 (boxed-Error type-id)
- **Date**: 2026-09-18

## Context

The stale-caveat sweep confirmed "`new Error(m, { cause })` fails to parse, so
`.cause` is unavailable" — the error-kind constructor grammar accepted exactly
one argument, so the ES2022 options bag was a parse error. Node stores any
value as `err.cause` (default `undefined`).

## Investigation

- `parser/parser_literals.go` `parseNewErrorBody` parsed `(msg?)` only;
  `DOMException`/`AggregateError` have their own two-argument bodies.
- The runtime error shape `errorObjType` (`emit_exceptions.go`) is a fixed
  struct (kind/message/name + the Node code/fs trios). A cause is untyped in
  Node, so the natural slot is a NaN-boxed `any` field — the exact convention
  `AbortSignal.reason` adopted in ADR-01004, which also gives faithful
  rendering/`instanceof`/member reads for an Error-valued cause via the
  TDD-00222 type-id machinery, for free.
- `AggregateError` instances were malloc'd at the smaller 40-byte
  `aggregateErrorStructIR`, so a trailing shared-field read (`.code`, now
  `.cause`) was latently out of bounds.

## Decision

- Parser: `parseNewErrorBody` accepts an optional second argument that must be
  a `{ cause: <expr> }` object literal (sole member). Anything else is a clean
  parse rejection naming the expected shape — a compile-time narrowing (a
  runtime options bag has no static field to read), disclosed as a caveat.
- AST: `NewErrorExpression.Cause` (walked in `resolver/rename.go`).
- Codegen: `errorObjType` gains a trailing field 10 `cause: TypeAny`;
  `buildErrorObj` defaults it to `nbUndefined`; `emitNewError` boxes the cause
  expression via `emitBoxValue` and stores it. Reads (`e.cause`) come free via
  the named-field object access, typed `any`.
- `buildAggregateErrorObj` now allocates through `buildErrorObj` (full
  `errorObjType` size, everything defaulted) and overlays its trailing
  `{ data, len }` pair — making every shared-field read on an AggregateError
  bounds-safe and well-defined, fixing the latent OOB in passing.

## Implementation notes

Adding a trailing field keeps every existing hardcoded field index and the
`aggregateErrorStructIR` prefix offsets valid. The cause travels with the
error pointer through throw/catch and boxing untouched.

## Side effects discovered

- `structuredClone` of an Error copies kind/message/name only — a cause is
  dropped (pre-existing field-list clone; minor, not fixed here).
- Node's `console.log(err)` appends a `[cause]` block to its inspect output;
  this compiler's error rendering (`name: message`) doesn't — subsumed by the
  existing no-stack rendering divergence.

## Verification

New `TestE2EErrorCauseBasics` (primitive/Error causes, `instanceof`,
`String(cause)`, absent → `undefined`, throw/catch), `...RejectsNonLiteral`,
`...AggregateReadsUndefined` — byte-exact vs Node. `Error|Exception|
Aggregate|Throw|Catch` groups + parser tests pass; `make examples` +
`make conformance-node` green (macOS arm64).
