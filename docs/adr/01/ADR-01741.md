# ADR-01741: An `any` value keeps its kind at typed parameters and bindings

- **Relations**: `Implements TDD-00230`, Supersedes the decision of [ADR-01361](ADR-01361.md), Extends [ADR-01215](ADR-01215.md)
- **Date**: 2026-10-19

## Context

TypeScript erases types. A value held in `any` is the same value at a typed parameter or binding, so Node runs `function f(s: string)` called with `5 as any` with `typeof s === "number"`. Here the value was converted to the declared type:

- `path.join(5 as any)` passed `"5"`, so its own `typeof` validation never threw `ERR_INVALID_ARG_TYPE`;
- `const c: Uint8Array = anyU16` read a Uint16Array through a Uint8Array layout;
- a non-array passed where an array is declared threw a TypeError (ADR-01361);
- a value of another kind written into an object's field shadowed the field (ADR-01215), and writing a fitting value afterwards did not remove the shadow.

## Decision

- **Any-argument dispatch.** At a direct call to a top-level function, each `any` argument at a parameter whose kind can be checked is evaluated once. Those kinds are a primitive, an array (by its box's element kind) and a typed array (by its class). If every argument fits, the typed entry runs. Otherwise a variant runs. A variant is the function body emitted again with the non-fitting parameters held as boxes, using the dynamic entry's widening. Rest parameters widen to `any[]`. A variant never dispatches again.
- **Boxed returns.** A variant whose declared return type can be kind-checked returns `any`. One predicate (`anyArgReturnsBox`) decides this for inference, emission, the type oracle and the binding analysis.
- **Any-held bindings.** A binding annotated with a primitive or a typed array is held as a box in two cases: it is initialized from an unconstrained `any`, or some assignment gives it one. An unannotated binding is held as a box when its initializer is a call that returns a box.
- **Unshadowing.** A fitting static write to a shadowed field deletes the shadow expando. The hook is a weak pointer that stays null until the first shadow exists, so programs without shadows pay one null check per field write.
- **BigInt typed arrays from `any`.** `new BigInt64Array(x)` with `x: any` builds from a length, an ArrayBuffer, or an array-like whose elements each go through ToBigInt (a number element throws `Cannot convert 1 to a BigInt`).
- **Typed-array kind checks** read the box's typed byte and element kind, which together name the class (a Buffer, a Uint8ClampedArray and a Uint8Array differ). BigInt64Array and BigUint64Array share an element kind, so a box of either never fits and runs the variant.
- **`Buffer.concat([…])` with an `any`-held element** checks it at run time: a Uint8Array or a Buffer is read as itself; anything else throws Node's `ERR_INVALID_ARG_TYPE` (`The "list[0]" argument must be an instance of Buffer or Uint8Array. Received …`).
- **An array-subclass instance** (`class Args extends Array<string>`) held in `any` fits an array parameter of its element kind, as a static call passes it, so library code calling Array's own methods on it does not run the subclass's override.
- **Bindings now held as boxes elsewhere:**
  - a native byte-region argument (`@lower`) that is a box passes its bytes, not its elements read as numbers;
  - object destructuring from an expression emitted as a box (`const { n } = ds[0]`) goes through the dynamic gets.
- **`fs.constants`** has @types/node's members as an interface (`FsConstants`), so `fs.constants.O_BOGUS` is TypeScript's error. The object stays the platform's own, and a member it lacks reads `undefined`.
- **A call returning `any`, bound to an interface-typed binding,** is converted like an identifier would be. Before this it was stored as the raw box, which was invalid IR.
- **Fixes found on the way:**
  - a function body whose emission fails restores the caller's builder;
  - the missing-import diagnostic skips locally bound names;
  - a Worker thread under `-mm=gc` unblocks the collector's suspend and restart signals (Linux; Darwin stops threads with Mach calls);
  - the js-lane test harness resolves programs that contain `import`.

Direct static reads of a field shadowed by a write through `any` still read the old value. That needs a per-field representation change, which belongs to the escaped-object work.
