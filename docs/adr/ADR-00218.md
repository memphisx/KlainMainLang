# ADR-00218: Object-to-string — Node-style `console.log` inspection + `-compat`-gated `[object Object]` coercion

- **Date**: 2026-08-18
- **Relations**: Implements [TDD-00075](../tdd/TDD-00075.md) (a further inhabitant); extends [ADR-00217](ADR-00217.md)

## Context

A stale-entry audit of `docs/status/`'s "What Is NOT Implemented" (prompted by a wrongly-listed tuple entry) surfaced that `console.log(new Foo())` for a plain class instance had *drifted*: it used to be a clean compile error, but now compiled and printed an **empty string** — silently wrong, worse than the old error. `` `${obj}` `` / `"" + obj` still hard-errored (`cannot convert type ptr to string`).

The right fix hinges on a distinction JS/Node already makes and this compiler had collapsed: **`console.log(obj)` and string coercion are different operations**. `console.log(new Foo())` in Node runs `util.inspect` → `Foo { x: 1 }` (informative); only `String(obj)` / `` `${obj}` `` / `"" + obj` run the primitive `ToString` → `[object Object]`. So the "empty string" bug is really "`console.log` isn't doing inspect," and the ugly `[object Object]` only belongs in the (rare) coercion path.

## Investigation

- `console.log(obj)`: `emit_call_console.go` had no object case, so an `IsObject` value fell through to `emitConsolePrintVal`'s `ptr` branch and printed the struct pointer via `%s` — reading bytes until a NUL, i.e. empty. `console.log(array)` is itself a clean rejection (no array-to-string exists), and tuples/symbols/nullable-scalars already had dedicated branches.
- String coercion: `emit_exprs_types.go:emitValueToString` hit its `default:` "cannot convert type ptr to string" for any `IsObject` value.
- `JSON.stringify`'s `emitJSONStringifyObject` (`emit_call_json.go`) already had the field-walk (`VisibleFields`/`FieldIndex`/GEP+load with `StructFieldIR`, accumulate with `emitStringConcat`) to model the inspector on, with inspect formatting instead of JSON.
- The class name carried the resolver's per-file `__kml_mod<N>` mangling (`resolver.go`), so a naive render showed `Point__kml_mod0`.
- Many special types (`URL`/`Headers`/`Response`/`Symbol`/`Error`/…) also set `IsObject`, so the inspector needed a conservative gate to fire only on genuine class instances / plain object literals.

## Decision

**Two distinct conversions, one gated:**

- **`console.log(obj)` → `ClassName { field: value, ... }`** (Node `util.inspect`), in **both** `-compat` modes — this is the correct, useful behavior and *not* a strict-vs-JS tradeoff, so it is always-on. Fixes the empty-string bug. An anonymous object literal omits the name (`{ x: 1 }`); an empty object is `Name {}`.
- **String coercion** (`` `${obj}` ``, `"" + obj`, `String(obj)`) of an object **with no user `.toString()`** — the one `-compat` knob (TDD-00075):
  - **`-compat=strict`** (default): the same useful `util.inspect` view. Never `[object Object]` — `"" + obj` → `[object Object]` is a JS footgun (silently drops all info), exactly the "stricter/better by default" bucket.
  - **`-compat=js`**: `[object Object]` (JS's primitive `ToString`), faithful on demand.

Field formatting (`emitInspectField`) matches Node inspect: strings single-quoted (`'hi'`), bigints suffixed (`100n`), booleans `true`/`false`, nested objects recursed, `null`/`undefined` bare. **Arrays render fully** — `[ 1, 2, 3 ]`, empties `[]`, strings quoted, nested arrays recursed — via a runtime accumulator loop (`emitInspectArray`), which as a bonus makes **`console.log(array)` work at all** (previously a hard rejection). Function and special-object fields stay `[Function]`/`[Object]` placeholders. The class name is demangled for display.

**A user-defined class `.toString()` is honored in string coercion** (both modes — the developer chose it), detected via the class's `MethodSigs["toString"]` and dispatched through `emitClassCall`. `console.log` deliberately does *not* call it (Node's `util.inspect` ignores `toString`), so `console.log(m)` shows `Money { amount: 42 }` while `` `${m}` `` shows the `toString` result.

## Implementation notes

- New `codegen/llvm/emit_inspect.go`: `emitInspectObject` (the `Name { … }` walk, mirroring `emitJSONStringifyObject`, canonicalizing a placeholder class type first — [ADR-00219](ADR-00219.md)), `emitInspectField` (per-field inspect formatting), `emitInspectArray` (the runtime `[ … ]` accumulator loop), `isInspectableObject` (the conservative gate excluding `IsSymbol`/`IsError`/`IsTuple`/`IsMap`/`IsSet`/`IsURL`/`IsHeaders`/`IsResponse`/… — a missed exclusion surfaces as a changed console/string test for that type), and `inspectClassName` (strips `__kml_mod<N>`).
- Wiring: `emit_call_console.go` routes `isInspectableObject`/`IsArray` args through the inspector (the array route replaces the old rejection); `emit_exprs_types.go:emitValueToString` honors a class `toString()` first, else routes through `emitInspectObject` (strict) or a `[object Object]` literal (`compatJS()`).

## Side effects discovered

- The nested-object test initially failed on a **pre-existing, unrelated bug**: a class-typed *interface field* (`interface W { p: Point }`) mis-stores the instance pointer in an `i64` slot, so even `w.p.x` fails with "field access on non-object" — independent of inspection (reproduces with no `console.log` at all). Left as a separate gap; the inspector handles nested *object literals* (`{ inner: { … } }`) correctly.
- `docs/status/`'s "What Is NOT Implemented" object-to-string entry and the stale tuple/`import.meta` entries were corrected in the same pass.

## Verification

- `tests/inspect_test.go` — 7 E2E tests: class instances (demangled name, quoted strings, bool), object literals + empty, nested literal + bigint field, strict string coercion (`${}` and `"" +`), `-compat=js` coercion → `[object Object]` (while `console.log` still inspects), arrays (`console.log([1,2,3])`, quoting, empty, nested, array field), and the `toString()` override (coercion uses it, `console.log` doesn't).
- `go vet ./...` clean; targeted `Console|Object|Class|String|Template|Json` suites green (no regression from the `emitValueToString`/console changes); full `go test ./...` + `make conformance` at the end of the delivery.
- Platform: macOS Apple Silicon; platform-independent (no new native code).
