# ADR-00648: Standard-dialect getter/setter decorators + `accessor` auto-field syntax

- **Relations**: `Implements TDD-00161` (Stage 5), `Extends ADR-00647`
- **Date**: 2026-09-02

## Context

The standard dialect's remaining member placements: getter/setter decorators
and `accessor x` auto-fields.

## Decision

### Getter/setter decorators

A getter is invoked through `emitClassCall` under its accessor dispatch key
(`accessorMethodName("get", prop)`), which already carries the Stage-2
decorated-method slot routing; a setter goes through `emitClassSetterCall`.
So a decorated getter/setter routes through the *same per-method slot machinery*
as method decorators, keyed by the accessor name:

- `registerDecoratedMethodSlots` (standard dialect) registers a slot for each
  decorated instance getter/setter under its accessor key.
- `emitStandardDecoratorApplications` boxes the accessor (via
  `emitMethodBoxAdapter` on the accessor key), calls the decorator with `(fn,
  { kind: "getter"|"setter", ... })`, threads the (possibly replaced) callable,
  and stores it in the slot — factored into a shared `applyMemberDecorators`
  used by both methods and accessors.
- `emitClassSetterCall` gains the slot-routing branch (the getter already had
  it via `emitClassCall`).
- `emitClassDecl` allows accessor decorators under the standard dialect (still
  rejected under experimental); the `classHasObserveDecorators` gate now fires
  for any decorated method/accessor.

### `accessor x` auto-fields

`accessor` is recognized as a contextual class-member modifier (like
`readonly`), setting `AnnotField.IsAutoAccessor`; `accessor` before a method is
a parse error. A **non-decorated** `accessor x` behaves as an ordinary field
(observably identical to real TS's get/set-backed field without an interceptor).
A **decorated** `accessor x` — whose decorator follows the distinct
`{ get, set, init }` auto-accessor protocol — is a clean compile-time rejection
pointing at get/set pairs. (Previously `accessor x` compiled only by a general
two-IDENT parser leniency that silently dropped the leading identifier, which
would have mis-routed `@dec accessor x` as a *field* decorator.)

## Side effects discovered

- **Replacement-`this` limitation** (general, not accessor-specific): a
  decorator that *replaces* a method/getter/setter runs the replacement as a
  dynamic function whose `this` is a boxed receiver, so it cannot do typed
  `this.field` access on a statically-typed instance ("dynamic property access
  on a statically-typed value"). Observe-only decorators (return the original)
  are unaffected; a replacement that doesn't touch typed `this` fields works.
  This is the static-instance-in-dynamic-position boundary (same family as the
  D1 static bridge), disclosed as a caveat.
- The `accessor`-decorator `{get,set,init}` protocol is the one remaining
  standard-dialect placement, left as a focused follow-up.

## Verification

- `tests/decorators_test.go`: getter/setter observe decorators (both run, accessor
  works); non-decorated `accessor x` behaves as a field; decorated `accessor x`
  and `accessor`-on-method rejections.
- `go vet`, full `make test-par`, decorator/class/accessor suites, node oracle,
  `status-check`/`reference-check`. Mac (Apple Silicon).
