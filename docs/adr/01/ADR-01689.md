# ADR-01689: A number keeps undefined across a typed boundary

- **Relations**: Implements TDD-00230, Extends TDD-00241
- **Date**: 2026-10-17

## Context

A plain `number` slot can hold undefined as a sentinel double (TDD-00241), but two paths lost it:
- Converting a `number | undefined` into a plain `number`, at a typed return, a parameter or a lowered call's argument, applied ToNumber, so `return a[3]` from a `(): number` function printed `NaN`.
- A class's number field with no initializer started at the allocator's `0`, so an unassigned `x: number` printed `0`.

Node prints `undefined` in both cases.

## Decision

- **Conversion.** Converting an absent `number | undefined` to a plain `number` gives the undefined sentinel. ToNumber applies only to an operator's operands, through `nullableScalarOperand`, so `f() + 1` is still `NaN`.
- **Lowered calls.** A lowered call's argument goes through the same conversion instead of taking the payload.
- **Class fields.** `new` stores the sentinel in every plain-double field of the instance before the initializers and the constructor run. Error's own slots (`errno`, `port`, and their renamed `__kml_err_` forms) are skipped, since 0 is their absent state.

## Verification

- macOS: `TestE2ENumberUndefinedAcrossBoundaries`, compared against Node, along with the class, number, nullable and lowered-call tests.
- Four class-field tests had pinned the old `0`: `TestE2EClassBareFieldNoConstructor`, `TestE2EClassMixedInitAndBareFields`, `TestE2EGenericClassBareField` and `TestE2EClassFieldUnassignedInConstructorReadsUndefined` (renamed). They now expect Node's `undefined`.
