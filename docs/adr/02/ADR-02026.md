# ADR-02026: An error's own cause, message and property names

- **Date**: 2026-11-22

## Context

- `new Error(m, { cause: undefined })` installed no `cause`: the cause slot
  uses undefined for "none", so `"cause" in e` was false and inspect left
  out `[cause]: undefined`. A subclass's `super(m, opts)` skipped an
  undefined cause the same way.
- Problems found next to it:
  - `Object.getOwnPropertyNames` of an Error was always `[]`.
  - An error made without a message reported an own `message` (`""`).
  - `Object.getOwnPropertyDescriptor` of a field a class extending Error
    declares was undefined.

## Decision

- Both constructor paths share one cause install
  (`emitErrorOptionsCauseAt`). An installed undefined cause is recorded as
  a hidden entry in the error's extra bag (`__kml_error_option_cause_own`),
  so `in`, `hasOwnProperty`, the descriptor and inspect see it while
  `Object.keys` does not. An assignment makes it enumerable, as in Node.
- An error constructed without a message holds a shared empty string
  (`__kml_err_nomsg`, frames.c) told apart by identity; it is not an own
  property.
- `getOwnPropertyNames` of an Error lists Node's order: `stack`, an own
  `message`, system fields, an installed cause, `errors`, the extra bag's
  keys, then a subclass's declared fields (`__kml_error_own_names`).
- A descriptor lookup an Error does not own falls back to the layout of a
  class extending it.
