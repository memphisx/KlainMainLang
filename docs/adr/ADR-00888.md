# ADR-00888: `Promise.resolve(v)` boxes its value when widened to `Promise<any>`

- **Date**: 2026-09-12

## Context

`Promise.resolve(42)` bound into a `Promise<any>` slot produced a corrupted value
at `.then`/`await` — the conformance runner's async lane surfaced a `then`
handler receiving `5e-324` (`Number.MIN_VALUE`, double bits `0x…01`), the tell of
raw integer bits decoded as a NaN box. Reproduced (macOS arm64, both lanes):

```ts
const p: Promise<any> = Promise.resolve(42);
p.then((v) => console.log(v, typeof v));   // printed "38 number", want "42 number"
```

A *string* value was unaffected (`Promise.resolve("hi")` → `"hi"`), and an async
function returning a number as `Promise<any>` was correct — narrowing the fault
to `Promise.resolve` of a non-string scalar widened to `any`.

## Investigation

`storePromiseValue` (`emit_task_emit.go`) stores `promiseBitsOf(val)` — for a
number, the raw double bits — into the promise's value slot; `loadPromiseValue`
reads those bits back and interprets them per the promise's *declared* element
type. `emitPromiseResolve` (`emit_promise.go`) typed the promise
`PromiseOf(val.Ty)` and stored `val` unboxed. When the binding is `Promise<any>`,
`.then`/`await` read the slot as a NaN-boxed `any` — but the bits were an
unboxed double, so the decode produced garbage. A string slipped through only
because a string box *is* the raw pointer (identical stored and boxed forms).
The async-function return path already boxes to its declared `Promise<any>`
(hence its correctness), so `Promise.resolve` was simply not at parity. The
contextual `Promise<any>` type does reach the typed var-init via
`emitExprWithObjectHint(v.Init, ty)` (`emit_exprs_vardecl.go`), but the hint was
dropped at the `Promise.resolve` call, which self-typed from the argument.

## Decision

Thread the contextual hint into `Promise.resolve`. `emitPromiseResolve` takes a
`hint Type`; when `hint` is a `Promise<any>` (`hint.PromiseType.IsDynamic`) and
the value is concrete, the value is `emitBoxValue`-boxed before the store, so the
slot holds a real NaN box and the `Promise<any>` load decodes it correctly.
`emitExprWithObjectHint` (`emit_objects.go`) intercepts a `Promise.resolve(...)`
call under a `Promise<…>` hint and routes it through the hinted path — so a typed
var-init, an argument passed to a `Promise<any>` parameter, and a `Promise<any>[]`
element all get the boxing. The direct call site (`emit_call.go`) passes an empty
hint (self-typing preserved for `Promise.resolve` used without a widening
context, e.g. plain `Promise<number>`).

## Implementation notes

- The boxing is gated on `!val.Ty.IsDynamic` so an already-`any` value isn't
  re-boxed, and on `hint.PromiseType != nil` so a bare `Promise` hint is a no-op.
- Only the store side needed changing: the `.then`/`await` read already decodes
  by the declared element type correctly once the stored bits are a proper box
  (confirmed — the async-return path with the same `Promise<any>` already worked).

## Verification

- Repro now correct: number → `42 number`, boolean → `true boolean`, string
  unchanged, `Promise<any>` parameter and `Promise<any>[]` element paths correct;
  plain `Promise<number>` unaffected.
- New test `TestE2EPromiseResolveWidenedToAny`; `go build`, `go vet ./...` clean;
  full `make test-par` gate run.
