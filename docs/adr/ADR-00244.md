# ADR-00244: True async-function suspension (coroutine tasks) + concurrent combinators

- **Relations**: `Implements TDD-00083` (Stage 2); builds on [ADR-00050](ADR-00050.md) (non-blocking fetch), [ADR-00073](ADR-00073.md) (combinators over fetch), [TDD-00006](../tdd/TDD-00006.md) (fibers/event loop)
- **Date**: 2026-08-19

## Context

Async functions ran to completion synchronously (a malloc'd resolved-slot), so
the only genuinely-pending promise was `fetch()`'s — `Promise.all([fetchUser(a),
fetchUser(b)])` where `fetchUser` wraps a fetch could not overlap. TDD-00083
committed to closing this: user async functions that can actually suspend must
become real coroutines.

## Decision

A **may-suspend** async function (one whose body awaits a fetch, a Promise
combinator, or another may-suspend function — classified to a fixed point in
`classifyAsyncSuspension`) is compiled as a coroutine **task** on a ucontext
fiber; a purely-synchronous async function keeps the malloc-slot fast path
unchanged. Every new path is gated on `MaySuspend`/`current_task`/`PromiseTask`,
so a program without a suspending async fn is byte-for-byte identical.

**Runtime** (`runtime_task.go`): a task is `{ctx, stack, promiseSlot, state,
pendingFetch, pendingGroup, pendingPromise, fn, args, resumerCtx}`; a task promise
is `{resolved, waiter, v0, v1}`. `__kml_spawn_task` mallocs a fiber and runs it to
its first suspend; `__kml_task_finish` resolves the promise, wakes a parked
waiter, and swaps out; `__kml_task_await_ready` waits on a promise (drives the
scheduler at top level, parks the task otherwise); `__kml_task_sched_step` pumps
libcurl and resumes ready tasks; `__kml_task_run_all` is the program-exit drain.
The key design point is **`resumerCtx`**: every task exits (suspend or complete)
via `swapcontext(self → self.resumerCtx)`, set by whoever swapped in — so a
synchronously-completing child returns to its caller and a scheduler-resumed task
returns to the scheduler, sidestepping `uc_link`'s single-fixed-target ambiguity
across nested fibers (which the HTTP connection-fiber model never hits).

**Emit**: a may-suspend fn emits as `void @f(ptr %args)` — params unpacked from a
heap args bundle, return value marshalled into the running task's promise. Its
call site (`emitSpawnCall`) bundles args, allocates a promise, spawns, and yields
a `PromiseTask`-typed promise; `await` on such a promise routes through
`__kml_task_await_ready`. `__kml_await_fetch` gained a task-park branch so a fetch
awaited inside a task suspends the task rather than busy-spinning.

**Combinators** (`emit_promise.go`): `Promise.all`/`.race`/`.allSettled` and the
new `Promise.any` get a task-promise branch beside the untouched Response and
already-resolved branches. Because `__kml_task_await_ready` drives the whole
scheduler, awaiting members in order overlaps them; `.race`/`.any` use
`__kml_task_await_any_of` (first resolved).

## Rejection (fiber-safe exceptions)

A task that throws rejects its promise: the trampoline wraps the body in a
catch-all `setjmp`, and an uncaught throw sets the promise `resolved = 2` with the
error object; `await` on it (emitAwait / the combinators) re-throws at the awaiter
so `try/catch` works. `Promise.all`/`.race` reject on a rejected member,
`.allSettled` reports it `rejected`. This required making the exception jmpbuf
stack **fiber-safe**: `@__kml_cur_jmp_stk` indirects the stack (default: the main
global one) and each task carries its own, swapped with `jmp_top` on every
spawn/suspend/resume — otherwise two suspended tasks' catch frames would overwrite
each other's longjmp targets. Verified under concurrency (three tasks, two
throwing, correct catches; a rejecting sibling doesn't corrupt a resolving one).

## Consequences

- User async functions truly suspend, compose concurrently, and reject correctly.
- Documented residuals (kept out of Strict): no `.then`/`.catch`/`.finally` or
  microtasks; no `AggregateError` and `.any` doesn't skip a rejected member;
  `.any` over raw fetches is a clean rejection; `.race`/`.any` in-task multi-wait
  busy-polls; array returns and nullable/destructured params in a suspending fn
  are a clean rejection; a task program that also uses `http.listen`/EventSource/
  WebSocket gets the task drain or the event loop, not both (unification pending).

## Verification

`getData(a); getData(b); await …` overlapped two 0.4 s fetches in ~0.64 s (serial
~0.8 s); `Promise.all` of three overlapped in ~0.65 s (serial 1.2 s); `.race`/
`.any` returned the fast member; `.allSettled` reported both fulfilled. New E2E
tests (`TestE2EAsyncFnComposition`, `TestE2EPromiseCombinatorsOverTasks`,
`TestE2EPromiseAnyOverTasks`) pass; `go vet` clean; **full `go test ./...` green**
before and after each increment. Apple Silicon (macOS); the ucontext layout is
already CI-verified per-platform ([ADR context in runtime_http.go's
ucontextLayout]).
