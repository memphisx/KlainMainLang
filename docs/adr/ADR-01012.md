# ADR-01012: Cluster-level events, cluster.workers, cluster.disconnect()

- **Relations**: Part of [TDD-00105](../tdd/TDD-00105.md) (the module-level surface its Status listed as remaining); Extends ADR-00427 (worker IPC), ADR-00331 (fork + re-exec model)
- **Date**: 2026-09-18

## Context

Per-worker surface was complete (ADR-00427), but the module-level half was
missing: `cluster.on(...)`, the `cluster.workers` registry, and
`cluster.disconnect()` — the idiomatic Node shape (`cluster.on('exit', ...)`)
compile-errored.

## Decision

- **Worker registry.** The primary's pid table gains a parallel Worker-handle
  table (`@__kml_cluster_wrks`, shared len/cap; `__kml_cluster_register`
  appends both). `cluster.workers` surfaces it as a live `Worker[]` — Node's
  id-keyed object shape has no typed equivalent here; the iteration idiom is
  the observable contract. Exited workers stay listed (Node deletes them).
  A `ClusterWorker` annotation name maps to the handle type.
- **Cluster-level events** (`cluster.on`/`once`, one compile-time listener per
  event — the module's standing convention): every listener gets the Worker
  first. `'exit'`/`'message'` are relays installed into each worker's own cp
  listener slot (fields 11/18) as a fixed-ABI adapter whose env is a
  `{ userClosureHdr, worker }` pair — armed on already-forked workers at
  registration (`__kml_cluster_install_*` walks the registry) and on future
  workers inside `__kml_cluster_fork`. `'fork'` fires synchronously in
  `cluster.fork()`, `'online'` from a queued microtask; both only for forks
  after registration (Node parity). Adapters are emitted per registration
  site via the builder-swap pattern; the `'exit'` adapter reuses
  `cpExitCloseAdapter`'s (present, code) → `number|null` mapping.
- **`cluster.disconnect()`** walks the registry and closes every worker's IPC
  channel (`__kml_cp_disconnect`). No completion callback yet; a disconnect
  issued immediately after a worker's send can drop the in-flight message
  (Node flushes pending messages first).
- `contextTypeArrowParams` gained a skip-this-position `""` name, and the
  relay listeners are context-typed by annotation names (`ClusterWorker`),
  which survive a `test` mustCall wrapper where the hint route does not.

Still absent: `setupPrimary()`(`setupMaster`)/`settings` (the re-exec-self
model has no alternate `exec` to run), cluster-level `'listening'`/
`'disconnect'` events.

## Caveat interactions

A cluster-level `'exit'`/`'message'` relay shares the worker's own listener
slot with `worker.on(...)` for the same event — last registration wins (the
one-listener-per-event convention, now cross-level).

## Verification

- New `TestE2EClusterLevelEventsAndWorkers` (all four events, both
  registration orders, `cluster.workers` length + iteration, worker exit code
  through the relay) and `TestE2EClusterDisconnectAll`; cluster/ChildProcess/
  IPC/Fork suites green. New `examples/cluster/cluster_events.ts`.
- macOS arm64.
