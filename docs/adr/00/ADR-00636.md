# ADR-00636: `crypto.createHash` — a faithful Node Hash object

- **Relations**: `Implements TDD-00159`, `Extends ADR-00434` (the Node `crypto` module), `Closes TDD-00158`'s hand-rolled-upgrade open question
- **Date**: 2026-09-02

## Context

TDD-00158's faithful HTTP `'upgrade'` event let a WebSocket server be written
against Node core — but completing the handshake by hand needs
`crypto.createHash('sha1').update(key + GUID).digest('base64')` to compute
`Sec-WebSocket-Accept`, and this compiler exposed no `crypto.createHash`. So
the "faithful" path could not actually run pure-Node code; "klain:ws does it
internally" was covering the gap, not closing it. `crypto.createHash` is also
a broadly-useful primitive (checksums, etags) in its own right.

## Investigation

A one-shot digest primitive already existed —
`__kml_crypto_digest(hashId, data, len, out, outLen)` over OpenSSL
`EVP_Digest` / CommonCrypto — wired for `crypto.subtle.digest` with ids 1–4
(sha1/256/384/512). The hex and base64 byte encoders exist
(`__kml_buf_hex_enc`, `__kml_base64_encode_bytes`), as does BufferSource
extraction (`emitCryptoBufferSource`) and Buffer construction. So the only
missing backend piece was `md5`, and the emitter piece was a `Hash` object.

## Decision

`crypto.createHash(algorithm)` returns a `Hash` handle — a tagged ptr
(`HashType`, `IsHash`) to a `{ i64 hashId, ptr buf, i64 len, i64 cap }`
accumulation struct. `.update(data)` appends bytes (a `string` via its
binary-safe length header, or a Buffer/TypedArray/ArrayBuffer via
`emitCryptoBufferSource`) and returns the handle (chainable). `.digest(enc?)`
runs `__kml_crypto_digest` over the whole accumulated buffer and encodes:
`'hex'`/`'base64'` → string, omitted → Buffer.

**Accumulate-then-digest, not streaming.** The digest of concatenated updates
is bit-identical to a streaming (`EVP_DigestUpdate`) digest, so output is
faithful; internal streaming is a deferred perf/memory refinement per the
project's "faithful now, perf later" rule. This reuses the existing primitive
whole — the only new backend code is `md5` (id 5: `EVP_md5()` /
`CC_MD5_*`), giving the common Node set md5/sha1/sha256/sha384/sha512.

Algorithms and encodings outside that set are clean rejections.
`crypto.createHmac` (the sibling; `__kml_crypto_hmac_sign` already exists) is
noted as future work, not in this V1.

## Implementation notes

- New file emit_crypto_hash.go: `HashType`, `emitCryptoCreateHash`,
  `emitHashMethod`/`hashUpdateSource`/`emitHashAppend`/`emitHashDigest`.
- Dispatch: `createHash` added to `emitNodeCryptoModuleCall` and the `crypto`
  export allowlist; `.update`/`.digest` routed by `IsHash` in emit_call.go;
  return types (`createHash` → Hash, `.update` → Hash, `.digest` →
  string/Buffer) added to inferExprType.
- Backends: `md5` case added to `__kml_crypto_digest` in both crypto_openssl.c
  and crypto_commoncrypto.c (the CommonCrypto MD5 deprecation warning is
  benign — Node supports md5 for non-security digests; OpenSSL is the default
  backend anyway).

## Side effects discovered

None. The CommonCrypto `CC_MD5_*` deprecation is a warning, not an error.

## Verification

- Mac (Apple Silicon, OpenSSL): `go build`, `go vet` clean. Known vectors
  (`sha1('hello')`, `md5('hello')`, `sha256('abc')` hex/base64, multi-update
  streaming-equivalence, no-encoding Buffer length) match Node exactly;
  `crypto.createHash('sha1').…digest('base64')` computes the **RFC 6455 §1.3
  example** `s3pPLMBiTxaQ9kYGzzhZRbK+xOo=`. `TestE2ECryptoCreateHashVectors`,
  `TestE2ECryptoCreateHashWSAccept`, and `TestE2EHandRolledUpgradeAcceptKey`
  (a full hand-rolled Node WebSocket handshake, no klain:ws, verified by a
  real client's accept-key check) all pass; crypto suite green; example
  `examples/crypto/create_hash.ts` runs.
- **Linux verified** (Debian/glibc/arm64, Docker `golang:latest` + clang 19 +
  OpenSSL `libssl-dev`): `TestE2ECryptoCreateHashVectors` (incl. the new
  `md5` id), `TestE2ECryptoCreateHashWSAccept`, and
  `TestE2EHandRolledUpgradeAcceptKey` all pass — `crypto.createHash` and the
  faithful hand-rolled WebSocket handshake work on OpenSSL/Linux.
