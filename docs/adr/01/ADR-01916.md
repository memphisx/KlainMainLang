# ADR-01916: array patterns past a tuple's end; undefined past a source's end

- **Relations**: `Implements TDD-00230` (strict lane is tsc)
- **Date**: 2026-10-21

## Context

- tsc rejects an array pattern element past a tuple source's end (TS2493): `const [c, d] = [9]`, `[a, b] = t` with `t: [number]`, a nested literal, an annotated parameter, a `for…of` over tuples. The checker accepted all of them; codegen caught one late as an internal error, and an example and three tests relied on the rest.
- Past an array source's end, Node binds undefined. A destructuring assignment stored 0 into a number target (`[a, b] = src`, `src: number[]`), and a nested array position bound an empty array, so its `.length` read 0 instead of throwing.

## Decision

- The checker reports TS2493 for a declaration, assignment, parameter or `for…of` array pattern whose non-hole element lies past a fixed tuple source, an array literal counting as the tuple of its elements, plus an optional one for each defaulted element past them, as tsc types it.
- Past the end, an assignment target stores its slot's undefined (the double slot's sentinel, a box's undefined), and an array position binds no header with an element read's absent type, so reading it throws as in Node.

## Consequences

- The literal forms move to the js lane in the tests; the destructuring example drops its section documenting the zero.
