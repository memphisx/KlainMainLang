# ADR-00599: Constructor default parameters

- **Relations**: Completes [ADR-00598](ADR-00598.md); extends [ADR-00164](ADR-00164.md)
- **Date**: 2026-09-01

## Context

Class constructors supported **no** default parameters at all — `new C()` against
`constructor(a: number = 7)` was rejected. The constructor arg loop
(`emitNewExpression`) ranged only the *provided* arguments and required an exact
count, unlike the method call paths which already had the arg/default/optional
switch. (Discovered while extending ADR-00598's earlier-param defaults to class
methods.)

## Decision

Rework the constructor arg-handling to the same shape the method loops use:

- Compute `regularCount` and `minRequired` (decrementing past trailing
  default/optional params), and accept `minRequired ≤ len(args) ≤ len(params)`
  rather than an exact count.
- Loop `for i := 0; i < regularCount` with the `arg | default | optional`
  switch: a provided argument, else the parameter's default expression, else the
  optional zero.
- Reuse `paramDefaultScratch` (ADR-00598) so a constructor default may reference
  an earlier scalar/string parameter — including a **parameter-property** ctor
  (`constructor(public x = 1, public y = x)`), the common case.

A rest-parameter constructor stays out of scope (a clean rejection — it never
worked under the old exact-count loop either). The array/nullable/dynamic
parameter handling and the constructor-call emission are otherwise unchanged.

## Verification

`TestE2EConstructorDefaultParams` (plain default, default + earlier-param
reference, a parameter-property ctor with `y = x`, and omitting a defaulted
trailing arg), all matching Node v26. The class/constructor/parameter-property/
inheritance/super suites still pass. Built and verified on Mac (Apple Silicon).
