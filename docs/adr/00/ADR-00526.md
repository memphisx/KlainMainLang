# ADR-00526: `RegExp.prototype.test` honors `lastIndex` under the `g` flag

- **Relations**: Extends ADR-00115, ADR-00116; Implements TDD-00035
- **Date**: 2026-08-31

## Context

`.test(str)` was built in TDD-00035 Stage 1, before the `lastIndex`-driven
stateful-iteration machinery landed in Stage 2 for `.exec()`. It therefore
always matched from offset 0 and never read or wrote `.lastIndex`, even for a
`g`-flagged RegExp. Real JS runs `.test()` and `.exec()` through the same
`RegExpBuiltinExec` algorithm, so a `while (re.test(s))` loop over a global
pattern silently never advanced — an infinite loop / wrong-count footgun and a
tracked Fidelity Gap.

## Investigation

`emitRegexSingleMatchCore` (`codegen/llvm/emit_regexp.go`) already implements
the full real-JS lastIndex protocol for `.exec()`: read `lastIndex` as the
start offset when `global`, convert between the mode's index space and PCRE2's
byte offsets via `regexUTF16ToByte`/`regexByteToUTF16`, advance to the match
end on success, reset to 0 on failure. `.test()` needed the same logic but not
the result-array construction — it only reports a boolean.

## Decision

Rewrite `emitRegexTest` to mirror the core's lastIndex handling: load
`global`/`lastIndex`, select the byte start offset (`lastIndex` when global,
else 0), run one `pcre2_match_8` from there, then branch — on a match, advance
`lastIndex` to the (converted) match end when global; on no match, reset to 0
when global. A non-global RegExp keeps `lastIndex` verbatim in both branches
and always matches from 0. The boolean result is the `icmp sge` of the match
return code, computed before the branch so it dominates the merge block.

## Implementation notes

`emit_regexp.go` only. Reuses the existing `emitRegexLoadField`,
`emitRegexStoreLastIndex`, `regexUTF16ToByte`, `regexByteToUTF16`, and
`emitRegexHandleLoad` helpers — no new runtime code. The match_data block is
still created and freed within the single call. This compiler has no `y`/sticky
flag (TDD-00035 flag scope), so only `global` drives iteration.

## Side effects discovered

None.

## Verification

New E2E tests: `TestE2ERegExpTestGlobalAdvancesLastIndex` (a `while
(re.test(s))` loop over `/\d+/g` yields count 2, lastIndex 3 then 7, reset to 0)
and `TestE2ERegExpTestNonGlobalIgnoresLastIndex` (a non-global regex returns
`true` twice with `lastIndex` staying 0). Existing `.test()` tests still pass.
Verified on Mac (Apple Silicon).
