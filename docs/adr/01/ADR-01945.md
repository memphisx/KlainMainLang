# ADR-01945: A second super() throws; super.constructor is the base class

- **Relations**: Implements TDD-00230
- **Date**: 2026-10-28

## Context

Two class bugs were open:

- A constructor calling `super()` a second time ran the base constructor again on the same `this` and carried on. Node runs the base constructor, then throws `ReferenceError: Super constructor may only be called once`.
- `super.constructor` failed to compile ("unknown expression type *ast.SuperExpression").

## Decision

- **Repeated super():** a derived constructor with more than one `super(...)` site, or one that is not a top-level statement (in a loop, a branch, an arrow), is rewritten before emission. It declares a `let` flag; after each statement that calls `super()`, it checks the flag (throwing the ReferenceError if it is set) and then sets it. The base constructor still runs first, as in Node. A constructor with one top-level site is unchanged.
- **super.constructor:** reading `constructor` off `super` is the base class value, the same as naming the base class.

## Consequences

- The second base-constructor run writes to the existing `this`, not a fresh object as in Node. That only shows if the constructor catches the ReferenceError and then reads fields the base constructor changed.
- Tests: `TestE2ESuperCalledTwiceAndSuperConstructor`.
