# ADR-01861: An object literal's computed keys, typed as tsc types them

- **Relations**: `Implements TDD-00230` (P3.3: found while answering the shadow report's ArrowFunction bucket)
- **Date**: 2026-10-21

## Context

- The checker gave no type to an object literal with any computed key (`{ [v]: 1, f() {} }`), so neither the literal nor anything reading it (`const g = () => o`) was answered, and a strict-lane program indexing it with a key it lacks compiled where tsc rejects it.
- tsc (`getObjectLiteralIndexInfo`) names the property of a key whose type is a string or number literal (`const k = 'a'`), and for a key of type `string` (or `any`) or `number` adds a string or number index signature whose type is the union of the computed values and the properties it applies to (every property for a string index, the numeric-named ones for a number index).

## Decision

- The checker types such a literal that way. A computed accessor, or a key of another type (a union, a non-unique `symbol`), stays unanswered.
- `TestE2EComputedPropertyKeyWriteAndCompoundAssign` writes and reads a key its literal lacks, which tsc rejects (TS7053, TS2339); it moves to the JavaScript lane, which accepts it.

## Consequences

- `TestComputedKeyIndexSignature` holds tsc 5.6's declaration types; `TestE2EComputedKeyIndexSignature` matches Node.
- Verified on Apple Silicon.
