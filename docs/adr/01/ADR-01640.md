# ADR-01640: SIGPIPE is ignored from startup on POSIX

- **Relations**: Extends ADR-01625
- **Date**: 2026-10-15

## Context

The Linux x64 CI lane failed `TestE2EStdoutBrokenPipeSameAsNode`. The
reader closes the program's stdout. Node reports `stdout error EPIPE write`
and exits 3; this compiler's binary printed nothing and died by signal.

## Investigation

- Node sets SIGPIPE to ignored at startup, so a write to a closed pipe
  fails with EPIPE and reaches the stream's `'error'`.
- This runtime ignored SIGPIPE only when an HTTP server starts
  (`__kml_ignore_sigpipe`, TDD-00214). Any other program took the default
  disposition and was killed.
- Windows has no SIGPIPE, so the Windows run passed.

## Decision

On Linux and macOS, `main` sets SIGPIPE to `SIG_IGN` before any output,
next to the stdout line buffering. The HTTP path's call stays and is now
redundant but harmless.

## Implementation notes

`codegen/llvm/emitter.go`: `declare ptr @signal(i32, ptr)` beside the
`setvbuf` declaration, and `call ptr @signal(i32 13, ptr inttoptr (i64 1 to
ptr))` in `main`. SIGPIPE is 13 on both.

## Verification

Windows 11: the IR emitted for an x86_64 Linux target holds the call and
compiles with clang; the codegen unit tests pass. The test itself runs in
the Linux and macOS CI lanes.
