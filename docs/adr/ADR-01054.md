# ADR-01054: Mixed-kind `&&`/`||` yield a union under `-compat=js`; the conformance runner goes through the resolver

- **Relations**: Extends ADR-00220, ADR-01037, ADR-01043
- **Date**: 2026-09-22

## Context

The 2026-09-21 Test262 run left three `-compat=js` files in the invalid-IR bucket (BACKLOG §0, top entry — invalid
IR is never deferred) and a fourth message in the same set with a link error rather than a clang one:

- `language/statements/do-while/S12.6.1_A4_T2.js`, `…_A4_T4.js`: `'%t40' defined with type 'i1' but expected 'ptr'`
  on a `store ptr %t40`.
- `staging/sm/TypedArray/set-tointeger.js`: `expected value token` at a function's closing `}`.
- `language/expressions/modulus/S11.5.3_A4_T7.js`: `multiple definition of 'truncate'` from the linker — the test
  declares `function truncate(x)`, the Windows fs shim defines the C `truncate`.

## Investigation

**do-while.** Reduced to `if (!(a && b && !c && d))` over four `var`s, `c` declared behind a `break` (so hoisted,
never assigned). `emitShortCircuit` (`emit_exprs_operators.go`) under `-compat=js` takes the value-preserving path
only when both operands share a slot type (`sameShortCircuitType`) and otherwise falls back to the bool form — but
`inferExprType`'s `&&`/`||` case returned the *left* operand's type unconditionally. So `(a && b) && !c` was
inferred `string` while the emitter produced an `i1`; the outer `… && d` then saw string/string, took the value
path, and stored that `i1` through its `ptr` alloca. Strict mode is not affected: it rejects `let c = a && b` over
mixed operands as an incompatible initializer, and never reaches a store.

The bool fallback is also unfaithful: `"str" && 0` is `0` in JS, `"" || 7` is `7`. `??` already solved the same
problem in ADR-01037 — operands of different scalar kinds yield the constrained union `L | R` (`nullCoalesceUnion`,
`emit_nullable_scalar.go`), boxed the way a `number | string` annotation is.

**TypedArray.** `assert.throws(RangeError, () => ta.set(source, offset))`: `set` returns `undefined`
(`emitTypedArraySet` returns `TypeVoid`), but `inferExprType` had no `set` case for a typed-array receiver, so the
arrow's return type defaulted to `i64` and its implicit return emitted `ret i64 ` with no operand. The reduced file
also showed the throw was a plain `Error`; Node throws `RangeError: offset is out of bounds`.

**truncate.** `klainmain -compat=js -run` compiles `function truncate` fine: the resolver renames every top-level
declaration to `name__kml_modN` (TDD-00041, `mangleFileDecls`). The conformance runner never ran the resolver — it
concatenated harness and test and called `parser.Parse` straight into the emitter, so user functions kept their bare
names and any of them matching a libc/shim symbol (`truncate`, `write`, `stat`, `read`, …) collided at link time,
reported as invalid IR. The runner was measuring a pipeline the CLI does not have.

## Decision

1. **`&&`/`||` under `-compat=js`** — `shortCircuitValueType(lt, rt)` is the single decision shared by
   `emitShortCircuit` and `inferExprType`: the shared type when `sameShortCircuitType`; otherwise the join of both
   sides' scalar kinds as a constrained union (`number | string | boolean` members, deduplicated by kind; an operand
   that is already such a union contributes its members, so `a && b && !c && d` widens rather than degrading;
   `null`/`undefined`/a nullable operand contributes nullability only; a lone string member with nullability stays a
   null-pointer `string | undefined`); an unconstrained `any` on either side yields `any`; arrays, nullable-scalar
   aggregates and non-string pointers yield `ok=false`, and *both* sites then use the bool form. `emitShortCircuitValue`
   takes truthiness from the raw operand before boxing it, and boxes a `string | undefined` operand with the same
   null-pointer split `emitNullCoalesceUnion` uses (`coerceShortCircuitOperand`).
2. **`inferExprType` `set` on a typed array** → `TypeVoid`; the too-large `set` throws `RangeError("offset is out of
   bounds")` via `emitInternalThrowKind`.
3. **The conformance runner resolves** the assembled source like the CLI: it writes it to `<workdir>/w<N>.js` and
   calls `resolver.ResolveProgramWithOptions(path, lane == "js", false)`. `reFilePosPrefix` also strips a Windows
   drive-rooted `X:\…\wN.js: line:col:` prefix so resolver/parse errors keep bucketing by message.

## Implementation notes

`codegen/llvm/emit_exprs_operators.go` (`shortCircuitValueType`, `emitShortCircuitValue`,
`coerceShortCircuitOperand`), `emit_exprs_types.go` (`&&`/`||` and typed-array `set` inference),
`emit_arraybuffer.go`, `tools/conformance/main.go`. Tests: `tests/logical_values_test.go` (+2),
`tests/typedarrays_test.go` (+1, and `TestE2ETypedArraySetTooLargeThrows` now asserts the RangeError). The strict
lane's `&&`/`||` inference is unchanged (it still returns the left type; the strict emitter's bool result is a
documented divergence, ADR-00186/ADR-00220).

Running the resolver in the runner also applies its early errors (TDZ, redeclaration, Tier-2 reserved names) to
the corpus — exactly what the CLI applies — and each worker now writes one small `.js` per file into the (RAM/tmpfs)
workdir.

## Side effects discovered

- A hoisted `var` that is never assigned holds its type's zero value, not `undefined` (`typeof c` is `"string"`,
  Node `"undefined"`) — BACKLOG §0.
- `set-tointeger.js` now compiles and fails at run time: `set(src, offset)` does not apply ToInteger to the offset
  (`"3"`, `{valueOf}`, `NaN`, a Symbol) — BACKLOG §0, same entry.
- Strict mode's `inferExprType` for mixed `&&`/`||` still names the left type while the emitter yields a bool; it is
  caught earlier by the initializer check in every case found, and left as is.

## Verification

string/`undefined`, nesting, `typeof`) diff clean against Node 24. Conformance, single categories through the new
runner (workdir on `R:`): `language/expressions/modulus` 13 → 14 of 40 (the `truncate` file), `language/statements/
do-while` 20 of 36 with `S12.6.1_A4_T2/T4` now passing, `staging/sm/TypedArray` with an empty `clang-fail/`; the
same categories through the HEAD runner rebuilt against the new codegen give the same numbers except the `truncate`
link error, isolating the runner change. `go vet` on `codegen/llvm` and `tools/conformance`; the logical-value,
typed-array `set`, nullish-coalescing and optional-chaining E2E tests pass. Linux/macOS: not run yet — the
end-of-day pass.
