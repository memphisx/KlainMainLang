# ADR-01173: `querystring` in TypeScript, and the dictionaries it stands on

- **Relations**: `Supersedes [ADR-00139](ADR-00139.md)`; `Extends [ADR-01170](ADR-01170.md)`, [ADR-01171](ADR-01171.md)
- **Date**: 2026-09-26

## Context

The code-generated `querystring` took and returned a `Map<string, string>`
(`querystring.parse(s).get("a")`). That API matches nothing in Node: there,
`parse` returns a null-prototype object whose repeated keys collect into an
array, and `stringify` takes an object. The module is replaced by Node's own
`lib/querystring.js`, ported to TypeScript like `net` and `http`. Its types
are @types/node's (`ParsedUrlQuery extends NodeJS.Dict<string | string[]>`),
and compiling it exposed gaps in how dictionaries are typed and represented.

## Investigation

- Node v24's `lib/querystring.js` and `lib/internal/querystring.js`, run
  side by side with the port against Node v24.19: repeated keys, `+` and `%`
  decoding, malformed escapes (`unescapeBuffer`), custom separators,
  `maxKeys`, custom decoders and encoders, `null` and array values.
- `Object.create(null)` typed as a dictionary emitted invalid IR, and a
  dictionary rendered as `{ … }` where Node prints `[Object: null prototype]
  { … }`.
- `NodeJS.Dict<T>` resolved to an array in code generation; an interface
  extending it was a field-less object; the checker left `NodeJS.Dict<T>` (a
  qualified generic reference) and a qualified base unanswered.
- `Array.isArray(v)` on `string | string[]` narrowed to `any[]`; tsc's
  getNarrowedType keeps a member that is a subtype of the predicate type
  (`string[]`). A `ReadonlyArray<T>` member was not recognised as the union's
  array member.
- An object passed where a dictionary is expected was reinterpreted as a
  map (a crash); an array literal where a union with one array member is
  expected (`["a", 2]` for a `… | ReadonlyArray<string | number>` value) was
  a heterogeneous-array error.
- `escape`: Node's `noEscape` table is exactly `encodeURIComponent`'s
  unreserved set, so `escape` is `encodeURIComponent` here. Porting
  `encodeStr` as written would read `charCodeAt` over this compiler's UTF-8
  strings (a known divergence, TDD-00230 phase 5).

## Decision

- `lib/node/querystring.ts`: Node's module (`parse`/`decode`,
  `stringify`/`encode`, `escape`, `unescape`, `unescapeBuffer`); the
  code-generated module and its virtual-module entries are deleted.
- A string-keyed map carries a flags word; `Object.create(null)` where a
  dictionary is expected sets its null-prototype bit, and inspect renders it
  as Node does.
- `NodeJS.Dict<T>`/`ReadOnlyDict<T>` are dictionaries of `T`; a generic
  interface with an index signature instantiates as a dictionary; an
  interface extending a dictionary is one, with its own fields.
- Checker: a qualified reference takes type arguments, and an interface may
  extend a qualified base; a type predicate keeps a union member that is a
  subtype of its type before substituting the type.
- Code generation: a union's `ReadonlyArray` member is its array member; an
  object becomes a dictionary by copying its fields; a dictionary value and
  an array literal take the expected type (a union's single array member).
- `lib/node.d.ts` declares `util`'s code-generated `format` and `inspect`.

## Side effects discovered

- String `length`, `charCodeAt` and `slice` count UTF-8 bytes (the status
  pages' caveats; TDD-00230 phase 5).
