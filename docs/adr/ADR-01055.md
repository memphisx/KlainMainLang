# ADR-01055: A worker module with a top-level `await` is a module task on its thread; a worker's `'error'` carries the Error object

- **Relations**: Implements TDD-00224 (Stage 2, workers); Extends ADR-01050, ADR-01051
- **Date**: 2026-09-22

## Context

TDD-00224 Stage 1 made the entry program's top level a coroutine when it has a top-level `await`
(ADR-01050). A worker module (`new Worker('./w.ts')`) with a top-level `await` still took the main-stack wait,
so its continuation ran ahead of the promise's other reactions — BACKLOG §0 item 2. Probe, worker side:

```ts
const p = later(20); p.then(() => log("reaction 1"));
const v = await p; log("after await");
```

printed `after await` before `reaction 1`; Node prints them the other way round.

## Investigation

`emitWorkerModules` (`emit_worker.go`) emits a worker's statements into `define void @__kml_worker_entry_<i>()`,
and the worker thread (`@__kml_worker_main`, `runtime_worker.go`) calls it and then runs its own
`@__kml_event_loop_run()` — main()'s shape on another thread, which is what TDD-00224 §5 asked to confirm. So the
Stage 1 split applies verbatim: the body becomes the task function, the entry only spawns it, and the loop that
already follows resumes the task from its reactions. Every module-task global (`@__kml_module_task`,
`@__kml_module_wants_loop`) is thread-local, so a worker task and the entry task coexist.

Two probes of the surrounding behaviour did not match Node, both on the path a throwing or hanging worker top level
must take:

- **A top-level throw in a worker segfaulted the parent** — with or without an `await`. `w.on('error', (e: Error)
  => e.message)` received the uncaught *message string* (documented as a caveat) and read `.message` off it.
  Node delivers the Error object.
- **`pthread_exit` from a coroutine stack kills the process on Windows.** The worker's uncaught path ends its
  thread with `pthread_exit`. winpthreads implements that as a `longjmp` to the thread's start frame; taken from
  a fiber stack (the module task's) the jump fast-fails the whole process mid-`printf` in the parent. The
  synchronous case never hit it because the throw happened on the thread's own stack.
- An unsettled worker top-level await: Node prints the warning, the *worker* exits with code 13 (`'exit'` sees
  13), and the process exits 0.

## Decision

1. **Worker module task.** `stmtsHaveTopLevelAwait(wm.Body)` (the Stage 1 pre-pass over a statement list) decides
   per worker module. With one, the statements are emitted with `e.inModuleTask` set into
   `@__kml_worker_entry_<i>_body(ptr)`, and `@__kml_worker_entry_<i>()` allocates the module promise, stores it in
   the new thread-local `@__kml_module_promise`, and spawns the task with the module trampoline (no catch-all,
   main-thread stack size — as the entry program). `@__kml_worker_main` now calls `@__kml_worker_run_loop(ctrl)`
   after the entry: with no worker module task it is the plain loop; otherwise it is main()'s loop from
   ADR-01050 — run the loop, resume the task and loop again when it parked for an inline loop run, and when the
   loop returns with the module promise pending, print the warning and set the worker's exit code (control block
   slot 7) to 13. The worker's exit protocol then reports 13 to the parent and the process goes on.
2. **`'error'` delivers the Error object.** `@__kml_worker_uncaught(msg, err)` sends the thrown object (w0) and
   the rendered message (w1); the parent's kind-3 dispatch hands the listener `@__kml_worker_err_obj(w0, w1)` —
   the object itself, or for a non-Error throw an `Error` carrying the message — and the no-listener default keeps
   printing the message. The listener's payload type is `errorObjType`.
3. **Ending a worker thread from a coroutine.** On a task, `@__kml_worker_uncaught` sets the thread-local
   `@__kml_worker_abort` and swaps to the task's resumer for good instead of calling `pthread_exit`. Every task
   swap site (`@__kml_spawn_task_ex`, the scheduler's run loop, `@__kml_task_resume`) calls
   `@__kml_worker_abort_check()` after control returns, which calls `pthread_exit` once `@__kml_current_task` is
   null — the thread's own stack. A program without workers gets a no-op stub, as `@__kml_worker_uncaught` already
   did.

## Implementation notes

`codegen/llvm/emit_worker.go` (`emitWorkerModules`, `emitWorkerRunLoop`, the `'error'` payload type),
`emit_module_task.go` (`stmtsHaveTopLevelAwait`, `@__kml_module_promise`), `runtime_worker.go`
(`@__kml_worker_main`, `@__kml_worker_uncaught`, `@__kml_worker_err_obj`, `@__kml_worker_abort_check`),
`runtime_task.go` (the three swap sites), `runtime_exceptions.go` (the uncaught path passes the object),
`emitter.go` (stubs). Tests: `tests/module_task_test.go` (+4: reaction order, throw after await → `'error'` with
the object and exit 1, unsettled → 13, `-mm=gc`), `tests/worker_test.go` (the `'error'` test asserts the object).
Example: `examples/workers/top_level_await_worker.ts` + `await_worker.ts`. Status: the workers row's `'error'`
caveat now describes the non-Error wrap only.

`emitAwait`'s tick branch and `@__kml_top_await` stay: a dynamic-import island's top level still runs on the
importer's stack (below).

## Side effects discovered

- **Islands are not the shared-runtime case TDD-00224 §5 assumed.** An `import()` island is an independent
  whole-program compile — its own `main()`, event loop, scheduler and thread-locals in a shared library — and
  `import()` runs its `init` synchronously, so an island with a top-level await runs its *own* loop nested inside
  the importer's call: the importer's microtasks and timers wait behind it (probe: `main: microtask` printed after
  the island's 30 ms await; Node prints it first). "The importer's promise adopts the island's" needs a bridge
  between two runtime copies — a design of its own, TDD-00225.
- `parentPort!.postMessage(v)` — a non-null assertion on the virtual-module binding — infers `number` and fails to
  compile ("a number has no method 'postMessage'"); `parentPort.postMessage` works. BACKLOG §0.

## Verification

Windows 11 x64: the four worker probes (reaction order, sync throw, throw after await, unsettled) match Node 24
line for line; the example diffs clean against Node; the 13 module-task/worker tests named above pass, including
`-mm=gc`. Linux/macOS: not run yet — the end-of-day pass (the `pthread_exit`-from-a-fiber rule is Windows-specific;
glibc's forced unwind stops at `__start_context`, and the abort-check path is taken on every platform regardless).
