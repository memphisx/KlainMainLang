# ADR-00656: Per-flag conformance report folders + a strict-rejection phase

- **Relations**: Implements TDD-00022, Extends ADR-00651
- **Date**: 2026-09-03

## Context

The Node-core oracle already ran both compat lanes (`-compat=both`), but Test262
and TypeScript ran a single lane, and `-compat=both` was refused for them. So
their generated reports carried one number, with no way to see what the
`-compat=js` surface does relative to strict in those corpora.

The obvious first move — run both lanes and print both scores in the *same*
file — is the wrong shape. Two lanes' numbers sharing one Markdown file makes a
per-lane regression an ambiguous whole-file diff, and does not extend cleanly to
a third flag. Reports must be **monitorable per flag**: one flag, one file,
identical structure, so a regression (or an error that only appears under one
flag) is a clean per-file git delta.

Separately, the two-tier model (ADR-00651/00653) *deliberately* rejects some
untyped-JS patterns under strict, and those rejections were indistinguishable
from genuine front-end gaps or invalid-IR codegen bugs in the failure breakdown.

## Decision

1. **One folder per compat flag.** Every suite writes an identically structured,
   single-lane report into `docs/testing/<flag>/` — `strict/` and `js/` today,
   a new folder (not a new column) for any future flag. `-compat=both` runs each
   lane in turn and writes into its own folder; a single-lane run writes only
   its own. `reportPath(file)` centralises the `docs/testing/<lane>/<file>`
   layout, and every report opens with a one-line banner naming its lane and the
   sibling-folder convention (`reportLaneHeader`). The old top-level
   `docs/testing/CONFORMANCE-RESULTS*.md` are removed; a hand-written
   `docs/testing/README.md` indexes the folders.
2. **`-compat=both` for Test262 and TS.** The Test262 file-walk was extracted
   into `runTest262Lane`, the TS case-walk into `runTSLane`; `main`/`runTSSuite`/
   `runNodeSuite` each loop over the requested lanes and write per-lane.
3. **A dedicated strict-rejection phase.** Deliberate strict-lane typed
   rejections carry a stable `-compat=js` hint (ADR-00651); the runner buckets
   these as `STRICT_REJECT` → the phase *"strict typed-rejection (recoverable
   under -compat=js)"*, separate from `COMPILE_ERROR` (front-end gaps) and
   `CLANG_ERROR` (invalid-IR codegen bugs).
4. **Makefile**: `make conformance` / `conformance-ts` pass `-compat=both`.

## Implementation notes

- `main.go`: `reportPath`, `reportLaneHeader`, `runTest262Lane`, `laneLabel`;
  `writeReport(path, all)` is single-lane again (the report is one flag's). The
  `STRICT_REJECT` classification in `runOne` is detected on the *raw* message
  (the hint sits past `normalizeReason`'s 120-char cut). `-out` is now a
  single-lane override only, ignored under `-compat=both`.
- `ts.go` / `node.go`: `runTSLane`; `writeTSReport` / `writeNodeReport` reverted
  to single-lane, called once per lane into the per-flag folder. The old
  node dual-lane "passing only under -compat=js" cross-analysis is now just a
  diff of the two folders. The node report's `NODE-GAP-ANALYSIS.md` link gained
  a `../` (the report moved one folder deeper).

## Side effects discovered

The full-corpus run showed the js lane far behind strict in-scope — compat=js
regresses more than the strict rejections it recovers. Per-flag folders make
that trend directly monitorable; the underlying gap is broad compat=js
completeness work (TDD-00022 follow-up).

## Verification

- `-category=language/expressions/typeof -compat=both` (isolated workdir) writes
  `docs/testing/strict/CONFORMANCE-RESULTS.md` and
  `docs/testing/js/CONFORMANCE-RESULTS.md`, identical structure, each with the
  lane banner and a `strict typed-rejection` phase row.
- `go build` / `go vet` / `go test ./tools/conformance/` green. macOS.
