# ADR-00429: http client — variable-bound options objects + the `agent` key

- **Relations**: Extends [ADR-00412](ADR-00412.md) (options-object client)
- **Date**: 2026-08-28

## Context

Chasing the oracle's `http.Agent` cluster surfaced a **silent-wrongness
bug**: `const options = { port, … }; http.get(options, cb)` (a very
common corpus shape — the options in a variable, not an inline literal)
compiled the object *pointer* through the URL-string path — a garbage
request that hung the program (verified: the pre-fix binary dies only on
an external SIGALRM).

## Decision

- `http.get`/`request`'s first argument may now be any **object-typed
  value**: the typed fields are read at runtime (`port` required;
  `path`/`host`/`hostname` optional) and the URL composed exactly as the
  literal form does. Unknown fields are a clean rejection listing the
  supported set.
- The `agent` key is accepted in both forms and ignored *without* losing
  semantics: this client opens one connection per request, which is
  Node's own behavior with `agent: false` / a non-keepAlive Agent —
  pooling is simply never enabled (disclosed on NETWORKING.md).
  `new http.Agent(...)` itself remains unimplemented.

## Implementation notes

`codegen/llvm/emit_http_client.go`: the object-typed branch in
`emitHTTPClientGetScheme` + the literal form's `agent` case.

## Side effects discovered

The pre-fix behavior violated the "clean rejections over silent
wrongness" rule in the worst way (a hang); worth remembering that any
"reject non-literal, accept expression" split needs a static-type check
on the expression branch.

## Verification

`TestE2EHTTPClientVariableOptionsObject` (variable options incl.
`agent: null`, ephemeral port, full response roundtrip);
`TestE2EHTTPClient*`/`TestE2EHTTPCreateServer*` green (Mac).
