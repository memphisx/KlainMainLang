# ADR-00805: Non-primary WebSocket/upgrade server — TDD-00191 Stage 3

- **Relations**: `Implements TDD-00191`, `Extends ADR-00804`

- **Date**: 2026-09-09

## Context

ADR-00804 let the *primary* server handle WebSocket/`upgrade` alongside plain
additional servers, but rejected an *additional* server from being the ws/upgrade
server: the ws/upgrade handlers lived in the primary's fixed globals
(`@__kml_listen_ws_handler` / `_upgrade_handler`), the diverts were emitted only
in the primary dispatcher, and a registration on a non-primary handle was a
runtime rejection. The real shape this blocks: a WebSocket app on its own port
next to a plain server on another, where the WebSocket one isn't the first
`createServer`. This ADR lifts that restriction.

## Investigation

The obstacle was purely the registration side: the per-server dispatcher already
threads its suffix (`e.curDispatchSfx`, ADR-00803), so a dispatcher reading its
*own* suffixed handler global is trivial. What was missing was compile-time
knowledge, at a `server.on('upgrade', …)` / `new WebSocketServer({ server })`
site, of *which* server the handle names — the `.on` machinery still assumed one
server (a single `httpServerHandlerPending` bool + fixed globals).

Threading the handler pointers through the fiber/`append_conn` hand-off (so the
dispatcher reads them off the connection) was considered and rejected: it widens
the runtime connection slot and the streaming re-arm for what is really a
compile-time routing question. The suffix is known at `createServer` emit time;
it only needs to reach the registration site.

## Decision

Associate each server binding with its dispatcher suffix at compile time, and
give every dispatcher its own suffixed ws/upgrade globals.

- **Binding→suffix tracking.** `emitHTTPCreateServer` hands its computed suffix
  up via scratch fields (`pendingServerCreated`/`pendingServerSfx`);
  `emitVarDecl` captures them for the declared name into `httpServerVarSfx` when
  the initializer is directly an `http.createServer(...)` (or the chained
  `.listen()` form). `new WebSocketServer({ server: x })` resolves `x`'s suffix
  and hands *its own* suffix up the same way (`httpWSVarSfx`), so a later
  `wss.on('connection', …)` targets the right server's ws global. Save/restore
  around the (recursive) var-decl body keeps nested declarations from corrupting
  an outer one.
- **Per-server ws/upgrade globals.** `@__kml_listen_ws_handler_N` /
  `_upgrade_handler_N` are declared lazily per suffix
  (`ensureExtraWSUpGlobals`, deduped). The primary keeps its unsuffixed globals.
- **Suffixed reads.** Every dispatcher emits the ws/upgrade diverts (gated on the
  whole-program `usedKlainWS`/`usedHTTPUpgrade` flags, no longer on `isPrimary`),
  reading `@__kml_listen_{ws,upgrade}_handler{curDispatchSfx}`; the handshake
  loop (`emit_websocket.go`) and the upgrade block (`emit_http_upgrade.go`) read
  the same suffix. A server with no such handler has a null global and falls
  through to normal handling.
- **Suffixed stores.** `server.on('upgrade', …)` and the ws connection handler
  store into the resolved suffix's global. Only an *untracked* handle (a
  non-identifier or otherwise unrecognized handle expression) falls back to the
  ADR-00804 runtime primary guard.

## Implementation notes

- `emit_exprs_vardecl.go`: `emitVarDecl` wraps `emitVarDeclBody` with the
  suffix-capture defer; `isDirectCreateServerInit`/`isDirectNewWebSocketServer`
  keep a createServer buried in a nested function body from being attributed to
  the wrong binding.
- `emit_http.go`: `ensureExtraWSUpGlobals` + `httpServerSfxForExpr` helpers; the
  `.on('upgrade')` store and both dispatcher diverts suffixed.
- `emit_ws_server.go`: `new WebSocketServer` resolves + records the suffix;
  `wss.on('connection')` stores into the suffixed ws global.
- Limitation: only simple identifier-bound servers (`const x =
  http.createServer(...)`) are routed to a non-primary ws/upgrade global — the
  dominant shape. An unrecognized handle expression keeps the primary-only guard.
  Consistent with the existing single-server `.on('request')` constraint.

## Side effects discovered

None. Single-server programs are byte-unchanged (suffix ""); the added
per-dispatcher divert for a server without a handler is dead IR guarded by a null
global load.
