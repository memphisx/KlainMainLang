# ADR-01482: A string declaration keeps a read's undefined

- **Relations**: Extends ADR-01481
- **Date**: 2026-10-09

## Context

BACKLOG lists the representation gaps TDD-00230 P3.3 closes. Item 20: a
slot declared `string` given a value that may be undefined (`const s:
string = a[5]`) printed `null`, compared `s === undefined` false and typed
`object`; Node prints `undefined`, compares true and types `undefined`.

## Investigation

- The element read carries its possible absence (`T | undefined`, the
  unchecked index), and the declaration converted it to the declared
  `string`, whose absent pointer prints, compares and types as null.
- Treating every null pointer in a non-nullable `string` as undefined (the
  console's `absentLiteral`) broke `new Date(NaN).toJSON()`, which Node
  returns `null` from though its declared type is `string`; that
  convention was not kept.
- BACKLOG 129 (TypedArray `.buffer`/`.byteOffset` missing) and the status
  caveats "no `.buffer`" and "TypedArray construction is restricted to a
  variable declaration's initializer" were stale: `.buffer`,
  `.byteOffset`, a view's shared buffer and construction in an argument or
  array literal match Node (macOS). A view over a resizable ArrayBuffer
  does not track its length (4 where Node gives 8 after `resize(8)`).

## Decision

- A declaration whose type is a non-nullable string, initialized from a
  value that may be undefined (not null), keeps that undefined: the
  binding's type is `string | undefined`. A local `number` declaration does
  the same in a `number | undefined` slot of its own (`const q: number =
  a[4]` was NaN, `q === undefined` false); a module global's storage is
  fixed before its initializer runs (BACKLOG 64, narrowed).
- BACKLOG 20 is narrowed to a string parameter or field (`f(a[5])` into
  `t: string`) and 64 to a module-level number declaration; BACKLOG 129 is
  deleted; the typed-array status caveat states the length-tracking gap
  instead.
