# TDD-00141: child_process.fork — self-fork with a real IPC channel

- **Status**: Implemented
- **Date**: 2026-08-28
- **Notes**: Node's own NODE_CHANNEL_FD mechanism (socketpair + re-exec), NDJSON string framing in a self-contained embedded C; child-detection idioms (`if (process.send)`, argv branching) work verbatim

## Context

`child_process.fork` is the biggest single member gap in the Node oracle
(26 files fail on the missing export; the `cluster` messaging surface
sits behind the same IPC mechanism). The corpus's dominant call shape is
**self-fork**: `fork(__filename)` (12) and `fork(process.argv[1])` (3) —
the test re-runs *itself* as the child and branches on child-ness
(`process.send` presence, argv, env). Forking a *different* module
(`fork(fixtures.path(...))`, computed paths) is a separate, much harder
problem (a second compiled program) and stays out of scope here.

## Design

Node's own mechanism is fork+exec with an inherited socket and a
`NODE_CHANNEL_FD` environment variable; this design copies it directly,
which is what makes the child-detection idiom (`if (process.send) …`,
`'NODE_CHANNEL_FD' in process.env`) behave verbatim.

- **Spawn**: `fork(<self>, args?, options?)` where `<self>` is the AST
  shape `__filename` or `process.argv[1]` — anything else is a clean
  rejection naming the limitation. Runtime `__kml_cp_fork(argv, len)`:
  `socketpair(AF_UNIX, SOCK_STREAM)`, `fork(2)`; the child dups its end,
  sets `NODE_CHANNEL_FD=<fd>`, and `execv`s the current executable
  (argv[0] as saved at startup; the platform-independent choice since
  both dev machines exec the compiled binary by path) with the given
  extra args appended. Re-exec (not bare fork) is what restarts the
  child from `main()` the way Node restarts the module.
- **Wire format**: newline-delimited JSON — Node's own `json`
  serialization mode. V1 payloads are **strings** (the corpus's common
  `assert.strictEqual(msg, <string>)` shape); JSON framing on the wire
  keeps newlines/quotes safe and leaves the door open for object
  payloads later. Non-string `send` arguments are a clean rejection.
- **Parent surface**: the existing ChildProcess handle grows
  `.send(str) → boolean`, `.disconnect()`, and an `'message'` listener
  slot; the IPC fd joins the same `select()` set the child stdout/stderr
  pipes already use (runtime_childprocess.go), dispatching one
  `'message'` per parsed line. `'exit'`/`'close'` behave as today.
- **Child surface**: `process.send(str)` (returns false / clean throw
  when not forked — presence-checkable via `if (process.send)` special
  form), `process.on('message', cb)` / `process.disconnect()` reading
  `NODE_CHANNEL_FD` — a new single-slot listener beside
  `exit`/`uncaughtException`/`warning`, serviced by the event loop.
- **cluster.fork()**: out of scope here; it should later reuse this
  channel (`cluster` workers are `child_process.fork` children in Node).
