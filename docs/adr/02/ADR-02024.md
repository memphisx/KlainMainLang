# ADR-02024: Decorated generic classes, and a decorated method's result

- **Date**: 2026-11-22

## Context

- A decorator anywhere on a generic class was refused: "a decorator on a
  generic class ('G') is not supported yet". Generic classes are
  monomorphized, one class per type-argument set, while JavaScript has
  one class whose decorators run once.
- The class or member decorator's target, the other half of the same
  backlog entry, already matched Node (the constructor and the
  prototype).
- A method decorator that replaced `descriptor.value` had its result
  coerced to the declared return type. `@md m(): number` with a
  replacement returning a string gave NaN, and Node gives the string.

## Decision

- A decorated generic class compiles erased, as an inheriting one does
  (`eraseInheritingGenerics`): its type parameters are `any`, it is one
  ordinary class, and its type arguments at use sites are dropped. The
  resolver's refusal is gone.
- A call routed through a decorated method's slot is `any`
  (`decoratedMethodCall`), as are an unannotated binding it initializes
  and that binding's reads. Neither the checker's primitive for the call
  nor its flow type for the binding unboxes the result.
