# ADR-01427: The checker decides return types and bare fields

- **Relations**: Implements TDD-00230 (P2.6), Extends ADR-01425, ADR-01426, Supersedes ADR-00474 (its bare-field default)
- **Date**: 2026-10-06

## Context

After ADR-01425 the shadow report counted 160 disagreements for
`inferUnannotatedReturnType`. On every one examined the checker had the
answer TypeScript and Node give: codegen's inference kept an untyped
`number` as `i64`, gave an untyped JavaScript parameter its number default
where the checker says `any`, or (fixed in ADR-01426) the checker read
`never` in dead code.

The rows where the checker had no answer were mostly private names:
`class { #x; m() { this.#x = 42; return this.#x } }`. The parser gave a field
declared with neither a type nor an initializer the annotation `number`
(ADR-00474), a decision TypeScript does not make (the field is `any`, or
what the constructor assigns to it), and the checker skipped that synthetic
annotation, so the field had no type. Once it had one, `c.set("str")` on such
a class failed in `-compat=js`: a method's unannotated parameter was
`number`, not `any` as a function's is.

A static method returning one of its own class's statics (`static e() {
return C.p }`) had no return type either: typing it read `C`'s value while
`C`'s value was being built, which the cycle guard answers with nothing.

## Investigation

- `inferUnannotatedReturnType` and `inferUnannotatedReturnTypeParams` are
  the two entry points (a name-bound function, a closure value); a closure
  stored in a variable is typed through the first and emitted through the
  second, so the two must give the same answer (ADR-01065's invariant).
- A function type in `reprOf` has no parameter defaults: a returned closure
  whose call sites fill `y = base` needs `FuncParamDefaults`, which only the
  old inference sets.
- tsc 5.9.3: `class A { x; y; #z; constructor() { this.y = 1 } }` under
  `--strict` reports TS7008 on `x` and `#z`, not `y` (inference from
  constructors).

## Decision

- Both return-type entry points ask the checker first
  (`checkerBodyReturn`): its `BodyReturnType`, through `reprOf`; `void` is
  no value. The old inference answers only where the checker has none, or
  where the result is a function type. The shadow hook records each such
  fallback as an `unanswered` row, so the report counts what is left before
  the old inference is deleted.
- The parser no longer types a bare field. The checker types it: what the
  constructor assigns to it (`constructorFields`), else `any`; in the strict
  lane, a bare field the constructor does not assign is TS7008. Codegen
  takes its representation from the checker (`Checker.FieldType`,
  `bareFieldType`), else `any`; a bare static field is `any`.
- In `-compat=js` a method's unannotated parameter is `any` and its rest
  parameter `any[]`, as a function's are. An unannotated setter parameter
  has its getter's type, as in TypeScript (it had agreed with the getter
  only through the number default), and is no TS7006 in the strict lane.
- While a class's static methods are typed, its value is a partial object
  of its static fields, so a static method reading one has a type.
- `ast.AnnotField` carries its name's position, for TS7008.

## Implementation notes

- `codegen/llvm/emit_func.go`, `codegen/llvm/shadow.go`,
  `codegen/llvm/emit_classes.go`, `checker/symbols.go`, `checker/check.go`,
  `diag/messages.go`, `parser/parser_classes.go`, `ast/nodes.go`.
- A static method calling a later static method still has no type while the
  class is being built; TypeScript resolves those member by member.

## Side effects discovered

- The strict lane reports TS7006 only for a parameter of a function type
  written in a signature, not for a function's or method's own parameter:
  `function f(a) {}` compiles in the strict lane with `a` a number
  (ADR-00042), where tsc under `--strict` rejects it.
