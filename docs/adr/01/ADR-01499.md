# ADR-01499: A generic class construction's type arguments are the checker's

- **Relations**: Extends ADR-01207, TDD-00010
- **Date**: 2026-10-09

## Context

`const s: Stack<number> = new Stack()` failed in codegen ("requires
exactly 1 explicit type argument"). tsc infers `Stack<number>` from the
declaration's type.

## Investigation

- Codegen took a construction's type arguments from the checker's type of
  each constructor argument whose parameter is annotated with the type
  parameter. With no such argument there was nothing to take.
- The checker inferred `unknown` for a parameter no argument names and
  never consulted the contextual type, as tsc's inference from the return
  type does.
- Codegen asked the checker about copies of the `new` node made by later
  passes, which the checker never typed.

## Decision

- The checker types a parameter no argument names from the contextual
  type's argument (an instance of the same class), else its default,
  else `unknown`.
- Codegen takes the checker's instance type's arguments, memoized by the
  construction's class and position (`newClassArgs`), so a copy of the
  node gets the original's answer. The per-argument rule remains the
  fallback.
