# ADR-00593: TypedArray console.log TypeName(len) prefix

- **Relations**: Extends [ADR-00218](ADR-00218.md), follows [ADR-00592](ADR-00592.md)
- **Date**: 2026-09-01

## Context

`console.log` of a whole TypedArray printed a bare `[ 1, 2, 3 ]` for every kind,
where Node prints `Uint8Array(3) [ 1, 2, 3 ]` — the constructor name and length
as a prefix. This affected all TypedArrays, not just the bigint ones.

## Decision

`emitInspectArray` prepends `TypeName(len) ` to the rendered array when the value
is a TypedArray (excluding a Node `Buffer`, which has its own `<Buffer ..>`
rendering). The constructor name is reconstructed by `typedArrayConstructorName`
from the element type's IR, signedness, and the `Clamped`/`BigIntElem` flags
(`Int8Array`/`Uint8Array`/`Uint8ClampedArray`/`Int16Array`/…/`Float32Array`/
`Float64Array`/`BigInt64Array`/`BigUint64Array`); the length is the array's own
`length`. An empty typed array prints `Uint8Array(0) []`, and a plain array is
unaffected (`[ 1, 2, 3 ]`).

## Verification

`TestE2ETypedArrayInspectPrefix` (Uint8Array, Int16Array, Float32Array,
BigInt64Array, an empty array, and a plain array) compared byte-for-byte against
Node v26. The typedarray/buffer/inspect suites still pass (the one prior test
that asserted the bare form was updated to the now-correct prefixed output).
Built and verified on Mac (Apple Silicon).
