# ADR-00328: Node `net.connect` — TCP client sockets

- **Relations**: Extends ADR-00324 (net TCP server — reuses its socket machinery)
- **Date**: 2026-08-23

## Context

`net` shipped server-only in ADR-00324; `net.connect` (client sockets) was
deferred. Completing it gives net client/server symmetry and is a prerequisite
for a future standalone WebSocket. Re-verified in code that once a client fd is
connected and non-blocking it is structurally identical to a server-accepted
connection socket, so the entire read/'data'/'end'/write/close/keepalive/
fdset machinery (runtime_net.go) applies unchanged — the only new piece is
connect-establishment.

## Investigation

There is no async-connect precedent: the WebSocket client
(`__kml_ws_client_connect`) connects **blocking**, deliberately, to avoid
non-blocking-connect machinery in the hand-rolled `select()` loop. The loop's
write fdset (`%wfdset`) is populated and read only by libcurl; no non-curl fd
ever uses it, and no `getsockopt(SO_ERROR)` decl exists. So a truly async
connect would require new event-loop plumbing. Following the WS client's
precedent, `net.connect` V1 uses a **blocking `connect()`**, reusing 100% of the
socket machinery with zero loop write-set surgery.

Two hazards surfaced while implementing:

1. **Deadlock on the initial write.** A connected client socket is added to the
   read fdset; `select()` then blocks waiting for it to become readable — but
   nothing arrives until the client writes, and the client's first write happens
   in the connect callback, which only runs in `dispatch` *after* `select()`
   returns. Chicken-and-egg.
2. **Closure captures the socket binding before it is assigned.** The idiomatic
   `const sock = net.connect(port, host, () => sock.write(...))` closes over
   `sock` inside `sock`'s own initializer. This compiler captures closures **by
   value at creation time**, and the connect callback is created while
   `net.connect` is still evaluating — before `const sock` is assigned — so the
   captured `sock` is uninitialized. Harmless-looking at `-O0`, but `-O2`
   observes the read-before-init as UB and miscompiles the caller (it treated
   the non-null connect result as null). This is a general compiler limitation,
   now tracked as a bug on the status README's "bugs found but not yet fixed".

## Decision

- `net.connect(port, host, connectListener?)` and the alias
  `net.createConnection` → a client `NetSocket`. New runtime
  `@__kml_net_connect(port, host)`: resolve host via `@__kml_dns_lookup`,
  `socket()`, build the sockaddr_in (same construction as
  `@__kml_net_bind_and_listen`), blocking `connect()`; on success set
  O_NONBLOCK, allocate a `netSocketIR`, register it in the shared connection
  registry, return it; on failure return null → `emitNetConnect` throws a
  catchable `Error` (V1: connect failure throws, no async `'error'` event).
- **The connect callback (Node's, no arguments) is stored in a new `netSocketIR`
  field 4 and fired once on the first `dispatch` pass**, after `net.connect` has
  returned and the `const sock` binding is set, then cleared. It may freely close
  over `sock`. (Hazard 2 was initially worked around by passing the socket as the
  callback argument; the underlying closure-capture bug was then fixed properly
  in ADR-00330 and the workaround removed.)
- **`__kml_net_fdset_add` returns force-zero-timeout** when any socket has a
  pending connect listener (field 4 non-null), so the loop doesn't block in
  `select()` before firing the callback — resolving hazard 1.

## Implementation notes

- `netSocketIR` grew a 5th field (pending connect listener); both socket
  allocations (`__kml_net_dispatch` accept path and `__kml_net_connect`) updated
  32 → 40 bytes.
- `@connect`/`@inet_pton` are reused from the WebSocket-client runtime (pulled
  in by `ensureHTTPRuntime`); `ensureNetRuntime` now also calls
  `ensureDNSRuntime` for host resolution.
- `emit_net.go` `emitNetModuleCall` gains `connect`/`createConnection`;
  `inferExprType` returns `NetSocketType` for them (vs `NetServerType` for
  `createServer`). The existing `IsNetSocket` method dispatch (`.on`/`.write`/
  `.end`) is reused unchanged.

## Side effects discovered

Hazard 2 (a closure capturing a binding in its own initializer) is a general
compiler bug, not net specific — root-caused and fixed in ADR-00330.
`net.connect`'s blocking connect means a slow/unreachable host blocks the event
loop until the OS connect timeout; disclosed as a caveat.

## Verification

- `tests/net_test.go`: `TestE2ENetConnectClient` (Go-side TCP echo server, the
  compiled client connects + writes via the connect callback + prints the echo)
  and `TestE2ENetConnectFailureThrows` (connect to a refused port → caught
  Error).
- `examples/net/client_server.ts`: a self-contained server-connects-to-itself
  round trip, verified to exit 0 standalone on macOS (arm64).
- The `-O2` miscompile was root-caused by comparing `-O0` vs `-O2` builds of the
  emitted IR and reduced to the closure-capture repro before fixing.
- Machine: verified on Mac (Apple Silicon). Not yet re-verified on Linux.
