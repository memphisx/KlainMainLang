# ADR-00977: `http.createServer` accepts every option that states existing behavior

- **Relations**: Extends ADR-00503
- **Date**: 2026-09-16

## Context

`http.createServer(options, listener)` accepted only `{}` or
`{requireHostHeader: false}` (ADR-00503); every other option key was a clean
compile-time rejection. That is the correct default posture — a silent ignore of
an option that changes behavior is a faithfulness bug — but it was stricter than
it needed to be. Several Node options have a *disabled* or *default* value whose
meaning this dispatcher already matches exactly. A portable Node app that passes,
say, `{ noDelay: true }` or `{ requestTimeout: 0 }` fails to compile even though
accepting that value would change nothing. Widening the accepted set to those
values removes a portability paper-cut without any behavior change or silent
ignore.

## Investigation

- `codegen/llvm/emit_http.go:488` `emitHTTPCreateServer` — the two-arg branch
  looped the options literal and accepted only `requireHostHeader: false`.
- `codegen/llvm/runtime_http.go:953-959` — every accepted socket already sets
  `TCP_NODELAY` (`@__kml_http_nodelay_one`), matching Node's `noDelay: true`
  default; nothing sets `SO_KEEPALIVE`, matching `keepAlive: false`.
- The dispatcher enforces no request/headers timeout and no per-socket request
  cap, so Node's disabled value (`0`) for `requestTimeout`/`headersTimeout`/
  `maxRequestsPerSocket` matches, and the parser is a strict hand-written parser
  (never the lenient llhttp variant), matching `insecureHTTPParser: false`.
- Options that would genuinely change behavior — `highWaterMark` (per-response
  backpressure threshold, currently the fixed 16384 of ADR-00962),
  `keepAliveTimeout`, real non-zero timeouts, custom `IncomingMessage`/
  `ServerResponse` classes — remain rejections. They are separate features, not
  deferred halves of this one.

Alternative rejected: silently ignoring unknown options. That reintroduces the
exact faithfulness hazard ADR-00503 guarded against (a `requestTimeout: 30000`
that never fires would mislead).

## Decision

Accept a `createServer` option only when its value *states this dispatcher's
fixed behavior* — a pure no-op that changes no codegen. The accepted values:

| Option | Accepted value | Why it matches |
|---|---|---|
| `requireHostHeader` | `false` | never enforces a Host header |
| `noDelay` | `true` | every accepted socket sets `TCP_NODELAY` |
| `keepAlive` | `false` | accepted sockets get no `SO_KEEPALIVE` probes |
| `insecureHTTPParser` | `false` | parser is never the lenient/insecure variant |
| `requestTimeout` | `0` | no request timeout enforced |
| `headersTimeout` | `0` | no headers timeout enforced |
| `maxRequestsPerSocket` | `0` | no per-socket request cap |

Any other value for these keys, and any unrecognized key, is a clean, actionable
rejection naming the accepted set.

## Implementation notes

- `codegen/llvm/emit_http.go`: added `createServerNoopOption` /
  `createServerNoopOptions` (a table) and `checkCreateServerNoopOption`; the
  options loop now defers each property to it. Boolean options carry the single
  accepted literal; the timeout/limit options accept only the literal `0`.
- The change is confined to the plain-`http.createServer` `(options, listener)`
  branch. `https.createServer`/`http2` route their TLS/options object through
  `emit_tls.go` and hand `args[1:]` to this core, so they are unaffected.

## Side effects discovered

None. `highWaterMark` as a real, configurable per-response backpressure threshold
and real (non-zero) server timeouts remain open createServer edges (BACKLOG §1).

## Verification

- `go build` + `go vet ./codegen/llvm/` clean.
- New E2E tests (`tests/http_test.go`): `TestE2EHTTPCreateServerNoopOptions`
  (all seven accepted options compile and serve a live request over the loopback)
  and `TestE2EHTTPCreateServerOptionRejections` (behavior-changing values and
  unknown keys reject with the right message). Both pass on macOS arm64 (M4).
- New example `examples/http/create_server_options.ts` compiles and runs.
