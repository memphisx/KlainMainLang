# ADR-01403: Generic interface instantiations memoized; an object's own `map`

- **Relations**: Extends ADR-01217
- **Date**: 2026-10-05

## Context

The TypeScript conformance suite's js lane grew to over 40 GB on one case,
`compiler/promisePermutations3.ts`. Its `Promise<T>` declares
`then<U>(success?: (value: T) => Promise<U>, error?: …, …): Promise<U>`:
three mentions of another instantiation per method. Resolving
`Promise<number>` resolved its members, which instantiated `Promise<U>`,
whose members did the same, down to the expansion depth cap of 8, and the
whole tree was rebuilt at every mention of the type. Each `s.then(…)` call
in the file cost about 0.75 s on its own. The suite runner abandons a case
that overruns its time limit, but its goroutine kept allocating until the
run ended.

Testing the fix showed a second bug: a plain object's own method named like
an array built-in (`box.map(f)` on an interface with `map<U>(…)`) inferred
as `Array.prototype.map`'s result, and the declaration failed with "array
variable must be initialized with an array expression".

## Decision

- A generic interface instantiation built from the top (not inside another
  instantiation) is memoized, keyed by the interface name and each type
  argument's full shape (`reprKey`, which tells numeric widths apart). One
  built inside another is truncated by the depth cap, so it is not kept.
  The class-refresh pass clears the memo along with refreshing
  `e.interfaces`.
- Inferring a method call's type checks a plain object's own function-typed
  member before the built-in method-name table.

## Verification

- Mac (M4): `promisePermutations3.ts` compiles in about 1 s; the
  generic, interface and new
  `TestE2EGenericInterfaceSelfReturningMethods` tests.
- Linux (x86-64, Ubuntu 24.04 container), with ADR-01402 to ADR-01404: the
  full test suite (3,923 tests), the 393 examples, and Test262 in both lanes
  (strict 8,498, js 10,506, unchanged, no invalid IR).
