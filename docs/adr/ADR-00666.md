# ADR-00666: Same-name imports of the Web-global-backed Node modules (`url`/`timers`/`perf_hooks`/`buffer`/`events`)

- **Relations**: Implements TDD-00165 (Stage 1)
- **Date**: 2026-09-03

## Context

The [Node built-in modules index](../status/NODE-MODULES.md) named a gap: the
functionality of `url`, `timers`, `perf_hooks`, `buffer`, and `events` works
through an ambient global, but their `import … from '<name>'` (and `node:<name>`)
specifier was rejected by the resolver allowlist — so canonical Node code
(`import { setTimeout } from 'node:timers'`, `import { URL } from 'url'`) failed
to compile.

## Investigation

Per the official specs, the **primary same-named export of each of these modules
is a spec-identical re-export of the global** (TDD-00165's difference table):
`url` re-exports the very WHATWG `URL`/`URLSearchParams` globals, `timers`'
functions are Node's global timer functions, `perf_hooks.performance` is the
global `performance`, `buffer`'s `Buffer` is the Node global, and `events`'
`EventEmitter` is the global `EventEmitter`. There is no behavioral divergence to
reconcile for the primary exports — so the "import needs its own implementation
that shadows the global" branch is not exercised here; only the "no difference →
just make it work" branch is.

These globals are recognized by their **unshadowed identifier name** —
`URL`/`URLSearchParams`/`Buffer` at parse time (`parser/parser_literals.go`),
`setTimeout`/`performance`/`EventEmitter` in codegen (`emit_call.go`). Since
`import` declarations are dropped from the merged program
(`resolver/resolver.go`), a same-name import needs only to be *validated and
erased*: bind nothing, and the global name keeps resolving as before.

## Decision

Add a `globalReexportModules` category to `resolver/virtual_modules.go` listing,
per module, the primary exports that are spec-identical to a global. In the
resolver's import loop a new branch (before the generic virtual-marker path)
handles these:

- A **named same-name** import (`import { URL } from 'url'`) — and a **default**
  import where the module has a canonical default (`import EventEmitter from
  'events'`) — is validated against the export set, checked that the local name
  equals the export name, checked for a local re-declaration collision, then
  erased (no binding recorded). The global keeps working; **no codegen change**.
- An **aliased** import (`{ URL as U }`), a **namespace** import (`* as t`), a
  **default** import of a module with no canonical default, and a **module-only
  extra** (`{ parse } from 'url'`) each get a clear, specific error naming the
  supported form (Stages 2–4 / the standard "no exported member" rejection).

The specifiers are registered in `virtualBuiltinMarkers`/`virtualModuleMembers`
(and mirrored under `node:` by the existing `init()` prefixer, extended to the
new tables) so they route through the virtual-import machinery — but their
markers are never dispatched, because the reexport branch `continue`s before the
generic marker binding.

## Implementation notes

- The `node:`-prefix mirroring loop adds `node:<name>` keys to the maps it is
  ranging over; guarded with a `HasPrefix("node:")` skip (matching the existing
  marker/member loops) so a visited new key can't be double-prefixed.
- Aliasing a **parse-time constructor** (`URL`/`Buffer`) fundamentally can't work
  by a post-parse rename — the parser recognizes `new URL(...)` by the literal
  identifier before imports are resolved — so Stage 3 is a deliberate rejection,
  not a silent miscompile. `firstKey`/an inline min pick a stable example name
  for the error messages.

## Side effects discovered

A latent, global-level divergence noted (not fixed here): Web `setTimeout`
returns a numeric id while Node's returns a `Timeout` object; this compiler's
global follows the Web shape. That affects the global and any import equally
(Node's own global is the Node-shaped one), so it is a separate global-fidelity
follow-up, not an import-vs-global difference.

## Verification

E2E tests in `tests/node_core_modules_test.go`: same-name named imports for all
five modules (bare + `node:`), default `events` import, the no-import
no-regression case, and the four deferral/rejection forms. `go test` over the
import/module/buffer/timer/events/url suites green (Mac); `go vet ./resolver`
clean.
