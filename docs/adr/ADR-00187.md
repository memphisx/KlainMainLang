# ADR-00187: The `**` exponentiation operator (and `**=`)

- **Date**: 2026-08-13

## Context

The ES2016 exponentiation operator `**` (and its compound assignment `**=`) did not exist at all: the lexer had no exponent token, so `2 ** 10` lexed as two adjacent `*` tokens and failed to parse (`unexpected token * in expression`). It was listed as a clean ❌ on [LANGUAGE-CONSTRUCTS.md](../status/LANGUAGE-CONSTRUCTS.md) (found by the 2026-08-11 audit, [ADR-00166](ADR-00166.md), which noted it had previously been mis-claimed as ✅). `Math.pow` existed, but the operator form — the one Test262 and ordinary code actually use — didn't.

## Decision

Implement `**` end-to-end, at the same precedence and associativity as the spec:

- **Lexer**: add `POW` (`**`) and `POW_ASSIGN` (`**=`) tokens. The `*` scan now checks for a following `*` (then an optional `=`) before falling back to `*`/`*=`, so `**`/`**=` win over two `*` tokens without disturbing `*` or `*=`.
- **Parser**: a new `parseExponentiation` level sits between multiplicative (`* / %`) and unary — `**` binds *tighter* than `* / %` (`5 ** 2 * 2` is `(5 ** 2) * 2`) and is *right*-associative (`2 ** 3 ** 2` is `2 ** (3 ** 2)`, the right operand recursing back into `parseExponentiation`). `**=` joins the assignment-operator set.
- **Codegen**: float operands (either side) go through libm's `pow()` and yield a float, exactly like `Math.pow`. Integer operands use a new exact i64 exponentiation-by-squaring helper `__kml_ipow` and stay i64, consistent with this compiler's integer-arithmetic model for `number` (the same model under which `/` truncates rather than producing JS's float). `**=` reuses the same two paths via `emitArith`.

### Integer model and its one deliberate divergence

Real JS numbers are doubles, so `2 ** 53 + 1` loses precision and `2 ** -1` is `0.5`. This compiler's default `number` is i64, and every other arithmetic operator already commits to exact integer semantics with truncation (`7 / 2 === 3`). `**` follows suit: `__kml_ipow` is *exact* for all non-negative exponents within i64 range (no double round-trip, so `2 ** 62` is precise where a `pow()`-and-truncate would not be), and a **negative exponent returns 0** — the integer-model truncation of `1 / base^|n|`, the direct analogue of truncating integer division. A program that needs fractional powers uses an explicitly float-typed operand, which routes to `pow()`. i64 overflow wraps like every other integer op here.

### JS early error preserved

`-2 ** 2` is a `SyntaxError` in JS (ambiguous grouping); it must be written `(-2) ** 2` or `-(2 ** 2)`. `parseExponentiation` enforces this: if the left operand parsed to a prefix `UnaryExpression` **and** its start token was not `(`, it's rejected. The start-token check is essential because parentheses aren't kept in the AST — `(-2)` and `-2` parse to the identical `UnaryExpression`, so only the leading `(` distinguishes the valid parenthesized form from the illegal bare one. Prefix `++`/`--` are `UpdateExpression` nodes, not `UnaryExpression`, so they stay allowed on the left, matching the spec's `UpdateExpression ** ...` production.

## Implementation notes

- `__kml_ipow` (`runtime_core.go`, guarded by `usedIPow`) is a standard header/body/exit loop with three `phi`s (`result`, `base`, `exp`), emitted once per program that uses integer `**`.
- `inferExprType` gained a `**` case (float if either operand is float, else i64) so declaration-type inference and method dispatch see the right type; the runtime result type comes from `emitBinary`/`emitArith` directly.

## Verification (Linux, x86-64)

- `2 ** 10 === 1024`, `2 ** 3 ** 2 === 512`, `5 ** 2 * 2 === 50`, `2 ** 0 === 1`, `2 ** -1 === 0`; `n **= 5` works; float `2.0 ** 0.5 === 1.414...`; `(-2) ** 2 === 4`, `-(2 ** 2) === -4`, and bare `-2 ** 2` is a parse error.
- New E2E tests in `tests/exprs_test.go` (integer, negative-exponent-zero, float, `**=`, parenthesized-unary, and the unary-left rejection); lexer tokens covered in `lexer/lexer_test.go`; `examples/basics/exponentiation.ts` added.
- Full `go test ./...` green; `go vet` clean.
- `make conformance` re-run — see `docs/testing/CONFORMANCE-RESULTS.md`.
