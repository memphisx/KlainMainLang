# ADR-00583: console.dir depth option

- **Relations**: Extends [ADR-00029](ADR-00029.md), [ADR-00218](ADR-00218.md)
- **Date**: 2026-09-01

## Context

`console.dir(obj, options)` accepted its options object syntactically but
ignored it — the `depth` nesting control did nothing. The `util.inspect`
renderer (emit_inspect.go) already had a recursion cap (`maxInspectDepth`), so
honoring `depth` is a matter of overriding that cap for the one call.

## Decision

Parse `console.dir`'s options object literal for `depth` and `colors`:

- `depth`: a non-negative literal number caps nesting; `null` means unlimited.
  Node's `depth: N` maps directly to the inspector's cap `N` (the top object is
  at counter 0, so a value nested `N+1` levels renders as `[Object]`/`[Array]`).
- `colors`: accepted and ignored — inspected output emits no ANSI here.
- Any other key, or a non-literal depth, is a clean rejection.

The override is installed via two emitter fields (`inspectDepthCap` gated by
`inspectDepthSet`, so a valid depth of 0 is distinguishable from "no override")
and cleared after the call. `console.dir` with no options now uses Node's
`util.inspect` default depth of **2**, rather than a bare `console.log`'s deeper
default.

## Verification

`TestE2EConsoleDirDepth` (default, `depth: 0`, `depth: 1`, `depth: null` over a
three-level nested object) compared byte-for-byte against Node v26. The existing
console/inspect/string-coercion suites still pass (`console.log`'s own default is
unchanged). Built and verified on Mac (Apple Silicon).
