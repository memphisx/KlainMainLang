# ADR-01542: A builtin `new` infers its type arguments from its context

- **Relations**: Extends TDD-00230
- **Date**: 2026-10-10

## Context

`new Promise((resolve) => …)` with no type argument left the executor's
parameters without a type (its `T` uninstantiated): the checker
accepted `const n: number = resolve` (tsc: TS2322, `resolve` is
`(value: unknown) => void`), typed the expression `Promise<any>` (tsc:
`Promise<unknown>`), and did not take `T` from the expression's context
(`const p: Promise<number> = new Promise(…)`, or a `return` in an async
function declared `Promise<string>`).

## Decision

- A builtin constructor's type parameters no explicit argument names
  take what the non-callback arguments infer, else what the
  expression's contextual type infers when matched against the
  signature's result, else the parameter's default, else `unknown`
  (tsc's inference from the return type, then getInferredType). The
  executor's parameters are typed by that instantiation.
- A value an async function returns is matched as `Promise<T>` of the
  awaited return context (tsc's `T | PromiseLike<T>` context).
- An array literal's element takes its context from the literal's: the
  array's element type, or the tuple's at its index
  (`const steps: Array<() => Promise<void>> = [() => new Promise(…)]`).
- Calling an executor's `resolve` with no argument where `T` is not
  void reports TS2794 (tsc's isPromiseResolveArityError), not TS2554.
