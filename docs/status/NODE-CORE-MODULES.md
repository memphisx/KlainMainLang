# Other Node.js Core Modules

> Part of the [Implementation Status](README.md) index. Smaller or lower-priority Node built-in modules, grouped here rather than given a full page each. Split out to its own page (rather than [PROCESS-CLI.md](PROCESS-CLI.md)) once it's substantial enough to need one.

**Coverage**: 9/11 (~82%) · **Strict Coverage**: 1/11 (~9%).

Format: [Status page format](README.md#status-page-format).

| Module | Status | Caveats | Notes |
|---|---|---|---|
| `querystring` (`.parse`, `.stringify`) | ✅ | | • A `Map<string,string>` in, out — the same shape `req.query`/`URLSearchParams` already use<br>• `.parse` doesn't strip a leading `?` (matching real Node; distinct from `new URLSearchParams(str)`, which does) |
| `assert` (`.ok`, bare `assert(cond, msg?)`, `.equal`/`.strictEqual`, `.notEqual`/`.notStrictEqual`, `.fail`, `.throws`) | ✅ | • `equal`/`strictEqual` (and their `not*` counterparts) are aliases of each other — this compiler's `==` has no implicit coercion to distinguish them<br>• No `.deepEqual`/`.deepStrictEqual` (no generic recursive object-equality helper exists yet)<br>• `.throws` only checks that *something* was thrown, not the thrown value's type/message | • Distinct from `console.assert` (see [CONSOLE.md](CONSOLE.md)) — throws a catchable `AssertionError` (kind-tagged as a base `Error`, since this compiler's fixed error-kind enum has no dedicated slot) instead of logging and continuing |
| `util` (`.inspect`, `.format`) | ✅ | • No `.promisify` — the callback builtins (`zlib.gzip`, `child_process.exec`) are name-dispatched calls, not first-class function values to wrap; importing `promisify` fails cleanly ([ADR-00325](../adr/ADR-00325.md))<br>• `.format` requires a string-**literal** format (compile-time walk); a runtime format string is a compile error<br>• `.inspect`'s options object is accepted but ignored (no `depth`/`colors`) | • `.inspect` reuses the same value formatter as `console.log` (strings single-quoted, `ClassName { … }`, arrays, `10n`)<br>• `.format`: `%s`/`%d`/`%i`/`%f`/`%j`/`%o`/`%O`/`%%`, excess args appended space-separated, unrecognized specifiers left literal — matching Node |
| `net` (TCP server: `net.createServer`, `server.listen`/`on('connection')`/`close`; TCP client: `net.connect`/`createConnection`; connection socket `.on('data'\|'end')`/`.write`/`.end`) | ✅ | • `net.connect` uses a **blocking** `connect()` — a slow/unreachable host blocks the event loop until the OS connect timeout; a connect failure **throws** a catchable `Error` rather than emitting an async `'error'` event ([ADR-00328](../adr/ADR-00328.md))<br>• Server binds `0.0.0.0` only; no `host`/`path`/options object on `listen`<br>• No back-pressure: `.write` never returns `false` and there's no `'drain'` event<br>• Listeners must be arrow/function-expression literals | • Accept loop and per-connection read pipes fold into the same `select()` event loop as `child_process` ([ADR-00324](../adr/ADR-00324.md)); a client socket reuses the same machinery once connected. A plausible base for a future `WebSocket` (see [NETWORKING.md](NETWORKING.md))<br>• `'data'` delivers a Buffer; `.write`/`.end` take a string/Buffer/ArrayBuffer/DataView |
| `dgram` (UDP sockets: `createSocket('udp4')`, `bind`, `on('message')`, `send`, `close`) | ✅ | • `udp4` only — no `udp6`<br>• No `'listening'`/`'error'` events, options object, or multicast<br>• Message listeners must be arrow/function-expression literals | • Each socket's fd folds into the same `select()` event loop as `net`/`child_process` ([ADR-00327](../adr/ADR-00327.md))<br>• `'message'` fires with a Buffer and an rinfo `{ address, port }`; `send(msg, port, host)` resolves `host` (name or IP) via the `dns` helper<br>• `msg`/`send` payloads take a string/Buffer/ArrayBuffer/DataView |
| `tls` (TLS-wrapped sockets) | ✅ | • **Blocking** TCP connect + TLS handshake on both sides (a slow peer stalls the loop), the same simplification `net.connect` makes<br>• OpenSSL-only (libssl) — a `-crypto=commoncrypto` build using `tls` is a clean compile error (Mac's CommonCrypto has no TLS API)<br>• Client options `{ rejectUnauthorized }` only (SNI = the host; no client-cert / ALPN / `servername` override); server `{ cert, key }` are PEM **strings** only (one cert per server, no chain/passphrase, no `requestCert`) | • **Client** `tls.connect(port, host[, {rejectUnauthorized}][, onSecureConnect])` (cert verification + SNI on by default) and **server** `tls.createServer({ cert, key }, connectionListener)` (`.listen`/`.close`, per-connection `SSL_accept`) — both return **net-shaped** handles (an `SSL*` in the socket), so `.on('data')`/`.write()`/`.end()`/`.on('connection')` reuse the net machinery, routing through `SSL_read`/`SSL_write`. A handshake/verify failure throws a catchable `Error` ([TDD-00109](../tdd/TDD-00109.md)/[TDD-00110](../tdd/TDD-00110.md)/[ADR-00344](../adr/ADR-00344.md)/[ADR-00345](../adr/ADR-00345.md)) |
| `dns` (`dns.lookup`, `dns.resolve4`/`resolve`, `dns.promises.lookup`) | ✅ | • `dns.resolve4`/`resolve` use `getaddrinfo` (the OS resolver), not real DNS `A` queries — no `resolve6`/`resolveMx`/`resolveTxt`/`reverse`<br>• IPv4 (`AF_INET`) only; `family` is always 4<br>• The callback forms fire synchronously, not on a later event-loop tick<br>• Failure passes a generic `Error` (`getaddrinfo ENOTFOUND`), not a `code`-tagged Node error | • `getaddrinfo(3)`-backed ([ADR-00326](../adr/ADR-00326.md), [ADR-00329](../adr/ADR-00329.md)); `lookup` returns one dotted-quad, `resolve4` all A records as a `string[]`, `promises.lookup` a `Promise<{address, family}>`<br>• Verified on Mac (arm64) with the Darwin `struct addrinfo` `ai_addr`/`ai_next` offsets probed on the machine — the same layout the WebSocket-client resolver still gates out on Darwin |
| `zlib` (`gzip`/`gunzip`, `deflate`/`inflate`, `deflateRaw`/`inflateRaw`, `unzip`, each `*Sync` + `(err, result)` callback) | ✅ | • The callback form fires synchronously, not deferred to the next event-loop tick<br>• No Brotli (`brotliCompress*`) — it would pull in `-lbrotli`, a new system dependency this binding deliberately avoids<br>• No class/stream forms (`createGzip()`, `zlib.Gzip`, …) — the WHATWG `CompressionStream`/`DecompressionStream` cover the streaming case ([STREAMS.md](STREAMS.md))<br>• `{ level }` is the only supported option and must be a compile-time constant | • One-shot calls over the same libz backend as `CompressionStream` ([ADR-00302](../adr/ADR-00302.md)), driven by a shared `@__kml_zlib_oneshot` helper ([ADR-00321](../adr/ADR-00321.md))<br>• Input may be a Buffer/TypedArray, ArrayBuffer, DataView, or string (UTF-8); output is always a Buffer |
| `vm` (`vm.Script`, sandboxed `eval`-like execution) | ❌ | | • Same fundamental blocker as the already-tracked bare `eval()` — see [GLOBAL-FUNCTIONS.md](GLOBAL-FUNCTIONS.md). Opt-in embedded-engine path scoped in [TDD-00046](../tdd/TDD-00046.md), not started |
| `cluster` (`fork`, `isPrimary`/`isWorker`/`workerId`, `Worker.id`) | ✅ | • `cluster.fork()` re-execs the program as a worker (env-passed id) — no IPC / `worker.send()`, no `cluster.on('exit'/'online')`, no `cluster.workers`, no `worker.process.pid` ([TDD-00105](../tdd/TDD-00105.md)/[ADR-00331](../adr/ADR-00331.md))<br>• Workers each bind the port via `SO_REUSEPORT`; on Linux the kernel load-balances accepts across them, on Darwin the distribution is uneven (often one worker) — correctness holds, balancing differs<br>• Can't be combined with Worker threads (same restriction as `http.listen({workers})`) | • Unifies with `http.listen({ workers: N })`'s worker-id global — the primary blocks in `waitpid` at program end, staying alive while workers serve<br>• An http-based cluster runs indefinitely (workers have no shutdown IPC); a finite-work fork pool self-terminates |
| `http2` | ❌ | | • `http.listen`/`fetch` are HTTP/1.1 only |
