# ADR-01920: oracle rows of Object.assign, generic annotations, dictionary reads and interface unions

- **Relations**: `Implements TDD-00230` (P3.3 shadow buckets)
- **Date**: 2026-10-21

## Context

The oracle disagreed with codegen on:

- `Object.assign(target, src)` with a static target its sources add no property to, which codegen keeps as the target's layout (the checker's `T & U`);
- an annotation inside a generic body (`{ wait: Promise<T> }` in `once<T>()`), which the oracle resolved at module scope, so `T` did not exist; codegen reads the instantiation's `T`;
- an unannotated string binding of a dictionary read narrowed by a guard on the read (`const value = init.protocol` under `init.protocol !== undefined`), which codegen holds nullable unless a store proves it present;
- a member read off a box whose declared type the oracle cannot map (`m.pathname` on URLPattern's result), which codegen reads dynamically;
- a union of declared interfaces (`AnyRecord`), which codegen keeps as each member's layout; only tsc's normalized unions of anonymous object literals are a plain box.

## Decision

The oracle mirrors each codegen reading. An annotation in a generic body binds the type parameters codegen has in scope, as a generic alias's body already does.

## Consequences

- The object-static, URLPattern, DNS-lookup and Promise.withResolvers compiles lose most of their rows.
