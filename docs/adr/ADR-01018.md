# ADR-01018: CI regression sweep — Windows self-spawn fork bomb, reaper reproducer, ASan leak policy, cluster stdio, HTTP hang guard

- **Relations**: Extends [ADR-00972](ADR-00972.md) (self-spawn guard), [ADR-00867](ADR-00867.md) (stdout buffering), [ADR-00986](ADR-00986.md) (async-handler fiber park); Implements TDD-00177 (Windows platform lane), TDD-00213 (array reference semantics)
- **Date**: 2026-09-19

## Context

The `Release` CI lane had been red for a run of recent feature commits, on every platform, all in `go test ./...`. The Windows lane in particular hit the 50-minute suite timeout. Because one hung/failing test in a package takes the whole lane down, the failures compounded and masked each other. Triage (`gh run view --log-failed`) surfaced six distinct regressions, all introduced across the same recent feature pushes:

1. **Windows fork bomb (50m hang).** `TestE2EChildProcessExecPathSelfSpawnRejected` hung ~46m on Windows. The self-spawn guard's marker (`KML_KLAIN_REEXEC`) was never set on Windows, so `spawnSync(process.execPath, ['x'])` re-ran `main` in the child, which re-spawned — an unbounded fork chain.
2. **Reaper reproducer no longer leaks (all POSIX).** `TestReaperEndToEndDetachedWorker` failed "reproducer did not leak, test proves nothing". Its worker was a self-re-exec that looped forever; the self-spawn guard (ADR-00972) now correctly refuses that re-run, so the worker exited 9 and never orphaned.
3. **ASan free-policy leak reports (Linux).** `TestE2EArrayRefSharedBufferFreePolicyASan` failed every case with a nonzero exit. The free policy (TDD-00213 Stage 4, policy (a)) *deliberately* leaks shared/escaping buffers under non-GC modes; LeakSanitizer (on by default with ASan) flagged those by-design leaks.
4. **Non-portable spawn test (Windows).** `TestE2EChildProcessSpawnOtherProgramUnaffected` spawned `/bin/echo`, an absolute POSIX path `CreateProcess` cannot resolve → status 127.
5. **Cluster stdout ordering / loss (Windows).** `TestE2EClusterFidelitySurface` and `TestE2EClusterListeningAndSetupPrimary` failed on cross-process stdout ordering and on a lost/uncaptured worker line. Root causes: Windows stdout stayed fully buffered; and the Windows cluster fork ignored `setupPrimary({ args, silent })`.
6. **Intermittent HTTP hang (linux-x64).** `TestE2EHTTPCreateServerAsyncHandlerConcurrentTaskAwait` hung ~42m once. Not reproducible at HEAD (8/8 local passes); the danger is that its bare `http.Get` calls have no timeout, so a server-side deadlock consumes the whole suite budget.

## Investigation

- Self-spawn marker: `codegen/llvm/runtime_reexec_guard.go` `__kml_mark_child_if_self_spawn` is `#ifndef _WIN32`-only; the Windows spawn (`codegen/llvm/win32src/win32proc.c` `__kml_win_spawn`) never set the marker. The reader guard (`runtime_interp_guard.go`) only runs when `usedNodeInterpGuard` is set (a program that reads `process.execPath`), which is why cluster/fork self-re-exec was unaffected — and why the marker must stay off for those legitimate self-runs.
- Reaper: `tools/conformance/reaper.go` `scanWorkdirProcs` matches any process whose command line *contains* the run's workdir path (a substring test). So an orphan need not be a self-re-exec — any detached long-lived process carrying the path works.
- ASan: the reproduced output was `SUMMARY: AddressSanitizer: 250 byte(s) leaked` (LeakSanitizer), not a use-after-free/double-free. Only UAF/double-free are the failures under test; the leak is the documented policy.
- Cluster stdout: `emitter.go` line-buffers stdout at startup on POSIX (`_IOLBF`) but skips Windows because UCRT treats `_IOLBF` as full buffering. Fully-buffered stdout on a pipe reorders/loses cross-process output. `runtime_cluster.go` `clusterSilentEntryIR`/`clusterSilentParentIR` were POSIX-gated, and `runtime_spawn_win.go` `clusterForkIR` passed inherited argv and `-1,-1,-1` stdio — so `args`/`silent` were dropped. The Windows `child_process` spawn path already pipes a child's stdout via `@pipe` + `__kml_win_spawn`, so the machinery to reuse existed.

## Decision

1. **Windows self-spawn marker.** In `__kml_win_spawn`, detect a target that resolves to the running executable (`is_self_spawn`, best-effort `GetFullPathNameW` + case-insensitive compare against `GetModuleFileNameW`) and inject `KML_KLAIN_REEXEC=1` into the child's environment block — but only when a new `flags & 0x10000` guard bit is set. That bit is set by the three `child_process` paths (spawnSync C, async `cpSpawnForkIR`, `execSyncForkIR`) and left clear by the cluster / `child_process.fork` / http-cluster re-exec, mirroring POSIX (which marks only the `child_process` sites, never `execv` of a worker).
2. **Reaper reproducer redesign.** Replace the self-re-exec worker with a detached `/bin/sh` looping forever, with `absWorkDir` passed as its `$0` so its command line carries the path. This is a spawn of a *different* program (not guarded), reproduces the identical setsid/re-parent escape, and no longer depends on the now-refused self-run.
3. **ASan leak policy.** Run the free-policy binaries with `ASAN_OPTIONS=detect_leaks=0`. ASan (UAF/double-free) and UBSan stay on; only the by-design leak reporting is suppressed.
4. **Portable spawn test.** Use `printf` (a PATH lookup, resolves on the Windows runner's MSYS2 coreutils) instead of `/bin/echo`.
5. **Cluster stdio.** Unbuffer Windows stdout (`setvbuf(stdout, NULL, _IONBF, 0)` in the win32 shim constructor) to match Node's synchronous stdout. Implement `setupPrimary({ args })` in the Windows `clusterForkIR` (rebuild `[argv0, ...args, NULL]` like the POSIX path) and enable the silent-stdio pipe regions on Windows (the IR is platform-neutral; route the pipe write-ends through `__kml_win_spawn` under `%dosilent`).
6. **HTTP hang guard.** Give the concurrent-await test's client a 20s timeout (≫ the ~300ms window) so a server-side deadlock fails that one test fast instead of consuming the 50m suite budget.

## Implementation notes

- `flags & 0x10000` was chosen as a high bit so it never collides with the low `windowsVerbatimArguments`/hide/detached bits that `__kml_win_spawn` already reads.
- The Windows silent-stdio path reuses `@pipe`/`@fcntl`/`@close`, all ensured on Windows via `ensureChildProcRuntime` (called from `ensureClusterRuntime`); `__kml_win_spawn` already accepts a pipe write-end as `out_fd`/`err_fd` and only inherits the explicitly-listed handles.
- Stdout unbuffering is the faithful match on UCRT (which ignores `_IOLBF`); the POSIX line-buffering intent (ADR-00867) is preserved there unchanged.

## Side effects discovered

- The intermittent HTTP concurrent-await hang (item 6) has no reproduced root cause (8/8 local passes, absent at HEAD). It is left as a deferred investigation into the ADR-00986 fiber-park path under concurrency; the client-timeout guard prevents a recurrence from masking the rest of the suite.

## Verification

- Windows (MSYS2 UCRT64 clang 22): `TestE2EChildProcess*`, `TestE2ECluster*` all pass; the former 46m fork-bomb hang now completes in <1s. `go vet ./...` clean.
- Linux x86-64 (Docker `golang:latest`, clang 19): `TestE2EArrayRefSharedBufferFreePolicyASan`, `TestReaperEndToEndDetachedWorker`, cluster + child_process suites, and the hardened HTTP test all pass; `go vet ./...` clean.
- Full-suite runs on both lanes and `make conformance` recorded same-commit.
