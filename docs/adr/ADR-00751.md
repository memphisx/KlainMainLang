# ADR-00751: `fs.linkSync` — hard links (`CreateHardLinkW` on Windows)

- **Relations**: Implements a [TDD-00180](../tdd/TDD-00180.md) §4 row ("Missing entirely … `link`"); extends [ADR-00497](ADR-00497.md) (the one-shot path-based fs ops and their `__kml_fs_*` throwing wrappers), [ADR-00719](ADR-00719.md) (the Win32 fs shim layer), [ADR-00737](ADR-00737.md) (the `__asm__` symbol-alias convention)
- **Date**: 2026-09-07

## Context

`fs.symlinkSync` shipped in [ADR-00497](ADR-00497.md), but its sibling `fs.linkSync(existingPath, newPath)` — a POSIX hard link — did not. The [TDD-00180](TDD-00180.md) §4 audit listed `link` under "Missing entirely (link errors, not `ENOSYS`)": a program calling it would fail to link on Windows, and no emitter path existed on any host. Hard links are the standard primitive behind atomic-replace and dedup patterns (write a temp file, link it into place), so the gap blocked otherwise-portable tooling.

## Investigation

`emitFsPathOp` (`emit_fs.go`) already handled the two-path `symlinkSync` case (`__kml_fs_symlink(target, path)`), and `ensureFsPathOps` (`runtime_fs.go`) defined the throwing wrappers around `symlink`/`realpath`/`readlink`/`chmod`/`truncate`/`access`. `link` slots into exactly that shape: a two-argument path op returning void, throwing the shared fs error on a non-zero return.

POSIX `link(oldpath, newpath)` and Node `fs.linkSync(existingPath, newPath)` agree on argument order (existing first). Windows `CreateHardLinkW(lpFileName, lpExistingFileName, …)` is the reverse — the *new* link name first — so the shim swaps them.

## Decision

Add `fs.linkSync(existingPath, newPath)` through the existing path-op machinery:

- **Emitter** (`emit_fs.go`): fold `linkSync` into the `symlinkSync` case of `emitFsPathOp` (both are two-path void ops), dispatching to `__kml_fs_symlink` / `__kml_fs_link` by name; `argN["linkSync"] = {2, 2}`. Recognized in `emit_call.go`'s `emitFsPathOp` case list and the `fs` resolver allowlist (`virtual_modules.go`) for named imports.
- **Runtime** (`runtime_fs.go`, in `ensureFsPathOps`): declare `@link`, add a `linkDesc` ("cannot create link"), and define `__kml_fs_link(existing, path)` — call `link`, throw through `__kml_fs_throw` (with the *new* path, as Node's error reports) on failure. Argument order matches POSIX, so the IR passes `(existing, path)` straight through.
- **Windows shim** (`win32fs.c`): `int link(const char *existing, const char *path)` → `CreateHardLinkW(wp /*new*/, we /*existing*/, NULL)`, converting both through `to_wide` (so the `\\?\` long-path handling and UTF-8 boundary of [ADR-00748](ADR-00748.md)/[ADR-00719](ADR-00719.md) apply). `GetLastError()` routes through the shim's `win_errno` so `e.code` matches Node (`ENOENT` for a missing source, `EEXIST` if the target exists). Defined under an `__asm__("link")` alias per [ADR-00737](ADR-00737.md), collision-proof against mingw header drift.

Hard links need no Developer Mode on Windows (that is a *symlink* restriction), so `linkSync` works on an unprivileged box where `symlinkSync` throws `EPERM`.

## Implementation notes

- The `__kml_fs_link` define is inserted between `__kml_fs_symlink` and `__kml_fs_readlink` in the single `ensureFsPathOps` `emitGlobal`; the `linkDesc` argument was added to the trailing `Sprintf` list in that same emission order.
- `CreateHardLinkW` requires source and destination on the same volume (as POSIX `link` does); a cross-volume link surfaces the OS error through `win_errno` unchanged — no special-casing.

## Side effects discovered

None beyond confirming the shared `__kml_fs_throw` null-path fix from [ADR-00750](ADR-00750.md) is unrelated here (this op always passes a real path).

## Verification

- New E2E test `TestE2EFsLinkSync` (`tests/fs_test.go`): link a file, read the same content through the new name, observe `nlink === 2`, write through the original and see it through the link, unlink the original and confirm the content survives, and a missing source throws `e.code === 'ENOENT'`. Passes on **Windows 11** (no skip — hard links are unprivileged).
- `examples/fs/fs.ts` extended with a `linkSync` + `nlink` demonstration alongside the symlink section (the example's full run is a POSIX-lane CI recipe).
- `go build`, `go vet ./...` clean; `make status` / `make status-check` and `make reference-check` pass (status JSON + website reference JSON updated same-commit); `make conformance` run at delivery.
- Platform: implemented and verified on **Windows 11** (x86-64, MSYS2 UCRT); the POSIX path is the plain `link` syscall.
