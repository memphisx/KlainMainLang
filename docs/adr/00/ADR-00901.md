# ADR-00901: Arithmetic/relational on bare null/undefined; real-string concat test

- **Date**: 2026-09-12

## Context

Invalid-IR sweep. Arithmetic on bare `null`/`undefined` emitted invalid IR, and
`string + null` did too:

```ts
null + undefined     // clang: add ptr null, null
null * undefined
"x" + null           // clang: add ptr <str>, null
```

From `language/expressions/{addition,multiplication,subtraction}/*`,
`concatenation/S9.8_A2_T2.js`, plus the `division`/`modulus`/`equals` T1.4 files
(integer-constant bucket).

## Investigation

Two coupled root causes in `emitBinary` (`emit_exprs_operators.go`):

1. `null`/`undefined` literals are `ptr`-typed, so a pair of them shares an IR
   and slipped past the cross-type guard into the arithmetic switch — `add ptr
   null, null`.
2. `isStringTy` (`emit_strings.go`) matches *any* bare `ptr`, so it classifies
   `null`/`undefined` as a string. This poisoned the `+` concat detection
   (`isStringTy(l) != isStringTy(r)` read `"x"+null` as string==string and
   skipped concat) and had to be accounted for when detecting a null operand.

## Decision

- Add a guard (placed before the string/coerce steps) for a bare null/undefined
  operand paired with a non-real-string, non-object/array operand: arithmetic
  (`+ - * / % **`) and relational (`< > <= >=`) go through `emitAnyBinary` under
  `-compat=js` (ToNumber: null→0, undefined→NaN) and reject cleanly under
  `-compat=strict` (TypeScript reports the same error).
- Introduce a "real string" test — `isStringTy(t) && !(t.IsNull || t.IsUndefined)`
  — and use it in both the guard and the `+` concat detection, so `"x" + null`
  correctly concatenates ("xnull") via `emitConcatOperandString`.
- Equality (`== === != !==`) on null/undefined is handled by the same guard —
  see ADR-00909.
- `inferExprType` mirrors the same null/undefined arithmetic result typing
  (TypeAny / bool) so the inferred slot type agrees with the boxed value (a
  `var x = null + undefined` otherwise mis-stored the box).

## Implementation notes

- `lNullish`/`rNullish`/`lRealStr`/`rRealStr` are computed once and reused by the
  guard and the concat branch.
- `emitAnyBinary` already boxes operands and runs the runtime ToPrimitive/
  ToNumber dispatch, so routing nullish operands there needed no new runtime.

## Side effects discovered

`isNaN`/`isFinite` on the boxed result were wrong — fixed separately in
ADR-00902.

## Verification

- `TestE2ENullUndefinedArithmeticCompatJS`, `TestE2ENullArithmeticRejectedStrict`
  (new); string+null concat matches Node exactly.
- The addition/mult/sub/concat/division/modulus files compile clean (strict
  rejects, js runs).
- `make examples` 296/296.
