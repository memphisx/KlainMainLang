# ADR-01176: The rest of `fs`'s callback and Promise forms, and the fixes they needed

- **Relations**: `Extends [ADR-01166](ADR-01166.md)`, [ADR-01173](ADR-01173.md)
- **Date**: 2026-09-26

## Context

Node's own `fs` tests stopped on `fs has no method 'stat'` (and `truncate`,
`symlink`, `realpath`, `mkdtemp`, `link`, `chmod`, …): the callback and
Promise forms existed only for the whole-file operations (and, in
TypeScript, `open`/`close`/`read`/`write`/`writev`/`fsync`). Adding the rest
turned up gaps in code generation and in the code-generated operations.

## Investigation

- The code-generated types of Node's objects (`fs.Stats`, `Dirent`,
  `crypto.Hash`, `ChildProcess`, `DataView`, `TextEncoder`, `Blob`, …) had no
  name: an annotation naming one was a number.
- `fs.rmSync`'s options had to be an object literal of boolean literals.
- `link`/`symlink` errors named one path; Node's name both (`link 'a' ->
  'b'`), as `rename`'s and `copyfile`'s already did here.
- A concise arrow whose body is a void builtin call (`() => fs.linkSync(a,
  b)`) returned an i64 with no value: invalid IR. The call's type was the
  unknown-callee number default.
- `'dir' | 'file' | null | undefined | ErrnoCallback` resolved to a string:
  a union's head carries its first member's literal flag, which the literal
  checks read before the union branch did.
- A union-typed name the checker narrows to an array or `Buffer` member
  read through `coerce`, which does not unbox to an array: the value stayed
  the box.

## Decision

- The asynchronous operations table (`fsAsyncOps`) gains `stat`, `lstat`,
  `fstat`, `statfs`, `rm`, `utimes`, `futimes`, `ftruncate`, `fchmod`,
  `realpath`, `mkdtemp`, `readlink`, `link`, `symlink`, `chmod`, `truncate`
  and `access`: each has the callback form, `fs.promises`' member and
  `fs/promises`' export, declared with @types/node's signatures.
- An operation the thread pool has no worker for ran inline and called its
  callback synchronously. It now settles the inline form's Promise and
  fires the callback through the same settle reaction as a pooled one, on
  a later turn as Node does.
- `import { promises } from 'fs'` binds `fs/promises`' namespace.
- A number or boolean path was a compile error; it is Node's
  `ERR_INVALID_ARG_TYPE`, thrown when the call runs (Node's own tests assert
  it). `writeFileSync`/`appendFileSync` on a descriptor write at its
  position, as `writeSync` does.
- `ResolveTypeName` names the code-generated objects by @types/node's names.
- `rmSync` takes any options object, `recursive` and `force` by truthiness,
  and accepts `maxRetries`/`retryDelay`.
- `link`/`symlink` throw through the two-path error.
- Call inference types the void `fs.*Sync` operations void; a concise arrow
  whose body yields no value returns undefined.
- The literal checks read only a non-union annotation; a union whose
  members' annotations all name one primitive, by keyword or literal
  (`'a' | 'b'`), is that primitive (a `string | ReadableStream` stays a
  union: the member kinds are read from the annotations, not the IR).
- A union-typed name narrowed to an array or `Buffer` member unboxes to its
  header when read.

## Implementation notes

`codegen/llvm/emit_fs_async.go` (`fsPathOpAs`, `emitFsInlinePromise`),
`types.go` (`ResolveTypeName`), `emit_fs.go` (`emitFsRmSync`),
`runtime_fs.go`, `emit_exprs_types.go`, `emit_func.go`, `emitter.go`
(`decideAnnotationType`), `emit_exprs.go` (`emitIdent`); `lib/node.d.ts`;
`resolver/virtual_modules.go`, `resolver/resolver.go`.

## Side effects discovered

- These operations have no pool worker: they run on the loop thread
  (status caveat).
- `realpath`/`mkdtemp`/`readlink` take no `encoding` option (status caveat).
