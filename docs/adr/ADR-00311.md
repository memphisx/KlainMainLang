# ADR-00311: URLPattern — route matching over compiled per-component regexes

- **Relations**: Implements [TDD-00100](../tdd/TDD-00100.md)
- **Date**: 2026-08-23

## Context

`URLPattern` was the last ❌ row on [URL.md](../status/URL.md), and the standard WHATWG way to express route matching (`{ pathname: "/books/:id" }` → `.test`/`.exec` with named groups) — directly useful for `http.listen` request routing, this project's microservice priority. TDD-00100 scoped the V1 subset; this ADR implements it.

## Investigation

The design space (result shape, grammar subset, runtime placement) is worked through in TDD-00100. Implementation-relevant findings:

- Both external dependencies already exist as conditional links: PCRE2 (`runtime_regexp.go`, `-lpcre2-8`) and libcurl's URL API (`emit_url.go`'s `curl_url`/`curl_url_get`, `-lcurl`). The C runtime declares both libraries' prototypes by hand (no header include), the same header-less approach the emitted IR takes; constants (`PCRE2_ANCHORED` 0x80000000, `PCRE2_ENDANCHORED` 0x20000000, the CURLUPart values) verified against the installed headers on the Mac.
- The emitted-IR `__kml_map_str_create`/`__kml_map_str_set` helpers have external linkage, so the separately-compiled C runtime can call them directly to build `.exec`'s result Map — no marshalling layer needed.
- `pcre2_match`'s return is one more than the highest-numbered ovector pair it set; pairs past that are not guaranteed initialized, so the group-extraction loop guards on it rather than trusting `PCRE2_UNSET`.

## Decision

- **`new URLPattern()` / `new URLPattern({ ...components })`** — object-literal init over any subset of `protocol`/`hostname`/`port`/`pathname`/`search`/`hash`; omitted components default to `*`. The constructor-string form, `baseURL`, `username`/`password`, computed keys, and spreads are clean compile-time rejections. Component *values* may be runtime strings.
- **Construction compiles each component** to an `ANCHORED|ENDANCHORED` PCRE2 regex in the embedded C runtime (`urlpatternsrc/urlpattern.c`, compiled alongside the program only when used — the `json_parse.c` pattern). Grammar subset: literals (regex-escaped), `\x` escapes, `*` → `.*` (not exposed as a group), `:name` (pathname `[^/]+`, hostname `[^.]+`, others `.+`), `:name?` with the spec's full-segment `/`-folding for pathname (`(?:/([^/]+))?`). `{}`/`()`/`+`/bare `?` throw a catchable **TypeError** at construction (the spec's error type), with the offending pattern in the message.
- **`.test(url)` / `.exec(url)`** parse the input with `curl_url` and match every component; an unparseable input is `false`/`null`, never a throw. `.exec` returns a merged `Map<string, string>` of every named group across components (an unset optional group is absent → `.get` yields `null`), or `null` on no match — the merged-Map narrowing of the spec's `URLPatternResult`, per TDD-00100.
- **Result type**: a flagged fixed-shape object (`URLPatternType`) whose six visible fields are the (defaulted) component pattern strings — `pattern.pathname` reads like the spec's readonly accessors — plus a hidden `__kml_handle` to the C-side state (the `Response.__kml_pending` trick). `.test`/`.exec` dispatch on `IsURLPattern` ahead of the RegExp/string overloads of the same names.

## Implementation notes

- `ast/nodes.go` (`NewURLPatternExpression`), `parser/parser_literals.go` (parse body; a second argument rejected at parse time), `resolver/rename.go` (walk case), `resolver/reserved_names.go` (Tier 2 name).
- `codegen/llvm/types.go` (`IsURLPattern`, `URLPatternType`, `URLPattern` annotation), `emit_urlpattern.go` (construction/dispatch), `urlpatternsrc/urlpattern.c` (+ embed), `emit_call.go`/`emit_exprs.go`/`emit_exprs_types.go`/`emit_exprs_vardecl.go` hookups, `emitter.go` (`usesURLPattern`), `main.go` and `tests/compiler_test.go` (compile the C file alongside the program, mirroring each other like the bigint/JSON/dtoa files).
- Two bugs caught while smoke-testing: the C translator's string buffer stayed NULL for an all-empty pattern (`search: ""` must compile to a match-only-empty regex, not a failed compile), and the unannotated-`const` type switch in `emit_exprs_vardecl.go` needed its own `NewURLPatternExpression` case for `pattern.pathname` field reads to typecheck.

## Side effects discovered

None beyond the disclosed scope narrowings, tracked as Caveats on [URL.md](../status/URL.md).
