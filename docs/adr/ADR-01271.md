# ADR-01271: timers/promises written in TypeScript

- **Relations**: `Part of TDD-00230`, `Completes TDD-00165`
- **Date**: 2026-09-29

## Context

`timers/promises` was the last module-only extra of TDD-00165 that was
still unimplemented. P3.1 of TDD-00230 ports Node's modules to TypeScript
under `lib/node/`.

## Decision

- `lib/node/timers_promises.ts` ports Node v24's `lib/timers/promises.js`:
  - `setTimeout` and `setImmediate` return a promise of their value.
  - `setInterval` is an async iterator. It counts ticks that have not been
    yielded yet and parks between them.
  - `scheduler.wait` and `scheduler.yield` are also ported.
  - An `AbortSignal` rejects with an `AbortError` (`ABORT_ERR`, with the
    reason as `cause`), and `ref: false` unrefs the timer.
  - Options are validated with Node's `ERR_INVALID_ARG_TYPE` messages.
- The exported functions are declared with Node's types through an overload
  signature. The implementation takes `options: any`, so validation sees the
  argument as passed.
- `setInterval` wraps an inner async generator. An invalid option therefore
  rejects the first `next()` rather than throwing from the call, as in Node.
- The module's exports are named like the global timers. The globals are
  reached through `lib/node/internal_timers.ts`.
- A builtin library module may declare names the resolver otherwise
  reserves (`setTimeout`). Its declarations are file-private and mangled
  like any other module's.

## Verification

Mac (Apple Silicon): a program exercising the resolved values, ordering,
abort before and during a wait, option errors, the interval iterator with
`break` and with abort, `scheduler` and `ref: false` prints the same as
Node v24.19.0. The same holds for `examples/timers/promises.ts`.
