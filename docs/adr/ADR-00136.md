# ADR-00136: General union types beyond `T | null` (V1: scalar members)

- **Relations**: Extends [ADR-00008](ADR-00008.md). Implements [TDD-00043](../tdd/TDD-00043.md)
- **Date**: 2026-08-09

## Context

`docs/status/TYPE-SYSTEM.md` and [ADR-00008](ADR-00008.md) both documented the same long-standing gap: `parser_types.go`'s `T | U` loop only ever retained `U` when it was `null`/`undefined` — for any other `U` the parser accepted the syntax but discarded every member past the first, so `string | number` silently compiled down to just `string`. [TDD-00026](../tdd/TDD-00026.md) hit this directly (`http.listen`'s response object wanted `body: string | ArrayBuffer` and had to fall back to two separate optional fields instead), and this project's own priority list called it out as a real, standing blocker on modeling realistic API surfaces. Picked up now as the next general-core-language-completion item, scoped first in [TDD-00043](../tdd/TDD-00043.md).

## Investigation

- Confirmed the exact discard behavior at `parser/parser_types.go`'s union loop (pre-existing comment: "For other union members we silently accept the syntax but use the first type").
- Read [ADR-00008](ADR-00008.md) in full: `any`/`unknown` already exist as a runtime-tagged `{ i8, i64 }` box (`TypeAny`, `codegen/llvm/types.go`) with a full set of tag-dispatch helpers (`emitBoxValue`/`emitUnboxTagPayload`/`emitDynamicToString`/`emitDynamicTypeof`/`emitAnyEquals`, all in `emit_dynamic.go`). A union like `string | number` is representationally identical to `any` at runtime — the only real difference is a *static*, checkable member set. This meant the bulk of the runtime work ADR-00008 estimated at "400–600 call sites, comparable to `class`" was already paid for; this ADR only needed to add compile-time member-set checking on top, and to relax exactly where `any`/`unknown` are rejected outright (function param/return, `emit_func.go`'s `containsDynamicElement` guards) for the *constrained* case, since a union's member set makes those positions fully checkable, unlike bare `any`.
- Traced every call site that boxes a value into a dynamic-typed slot, to make sure the new member-set check landed everywhere a union could actually reach: `emitVarDecl`'s scalar path, `emitAssign`'s identifier `=` path, function-call argument passing (`emit_call.go`), and — found only by testing, not by reading — three more sites that all called `e.coerce(val, targetTy)` unconditionally on what could now be a dynamic target: `emitReturn` (`emit_stmts.go`), `emitClosureFunc`'s expression-bodied-arrow return (`emit_func.go`), and `emitClosureCallByPtr`'s argument passing for calling a closure through its function-pointer type (`emit_func.go`). All three had never been exercised with a dynamic target before, because `any`/`unknown` were unconditionally rejected as a function param/return type — the moment this ADR allowed a *constrained* union through that same guard, these three blind-`coerce` call sites became reachable and produced broken IR (`trunc i64 5 to { i8, i64 }`, a real `clang` failure caught by `TestE2EUnionArrowFunction` during implementation, not found by reading alone).
- Found and fixed a self-referential-cycle bug in the parser's own union-collecting loop while writing the first E2E test: the initial implementation built the returned "head" `TypeAnnotation` by reusing `members[0]`'s pointer directly (`head := members[0]; head.UnionMembers = members`), which makes `members[0]` its own first element in its own `UnionMembers` list. `resolveType`'s member-resolution loop (`for i, m := range ta.UnionMembers { members[i] = e.resolveType(m) }`) then recursed into that same node forever — a real stack overflow (`TestE2EUnionDeclareAndPrint`, first run), not a hang or wrong output, so it was loud and easy to catch. Fixed by making the returned head a distinct shallow copy of `members[0]`'s fields, so every entry actually *inside* the `UnionMembers` list — including the copy's own source — keeps `UnionMembers` nil.
- Deliberately scoped V1 to `number`/`string`/`boolean` members (plus `null`/`undefined` via the existing `Nullable` flag) — the same three scalar tags `any` already boxes cleanly. An object/interface/array member would need `emitDynamicToString`/`emitAnyEquals` to format/compare a payload they currently have zero field-shape knowledge of, which is real, separate design work; deferred rather than half-built. See TDD-00043's Open Questions.
- Also deliberately kept a union nested inside an array element or object field rejected (`containsDynamicElement` still treats a constrained union as dynamic there), separate from the top-level positions (var decl, function param/return) where it's now allowed. Member-set checking (`unionAllowsAssignmentFrom`) is only wired up at those top-level assignment/call/return boundaries — not at array-literal-element construction, HOF callback element passing, or object-literal field assignment — so allowing a union through unchecked in those nested positions would have been a real regression risk (skipping the actual type-safety check silently) rather than simply "not supported yet." Caught during implementation, before writing tests, once the first array-of-union case was considered and found unimplemented; not a design goal walked back after the fact.

## Decision

**Parser** (`parser/parser_types.go`): split `parseTypeAnnotation` into a thin wrapper plus `parseTypeAnnotationAtom` (everything the old function did directly). The wrapper parses one atom, then — if a `|` follows — loops collecting every subsequent atom via `parseTypeAnnotationAtom` (not the full `parseTypeAnnotation`, to avoid re-entering the same union-collecting loop recursively). `null`/`undefined` members set a `nullable` flag exactly as before; every other member is appended to a `members` slice. Zero real members (e.g. `null | undefined`) keeps the original single-type behavior; exactly one real member is returned as-is (matching today's `T | null` case precisely, no behavior change); two or more builds a copy of the first member with its `Nullable` set and a new `UnionMembers []*TypeAnnotation` field populated with the full list (`ast/nodes.go`).

**Representation** (`codegen/llvm/types.go`, `emitter.go`): `Type` gains `UnionMembers []Type`. `resolveType` recognizes `ta.UnionMembers != nil` before every other branch and builds `Type{IR: TypeAny.IR, IsDynamic: true, UnionMembers: resolved, Nullable: ta.Nullable}` — literally `TypeAny` plus a non-empty member set. `IsDynamic` alone still means bare, unconstrained `any`/`unknown`.

**Guard relaxation** (`emit_dynamic.go`): new `isUnconstrainedDynamic(ty)` (`ty.IsDynamic && ty.UnionMembers == nil`) replaces the bare `ty.IsDynamic` half of every `X.IsDynamic || containsDynamicElement(X)` check at the four function param/return checkpoints (`emit_func.go` ×4, plus the arrow-function-with-hints and method-parameter equivalents in `emit_classes.go`) — a constrained union now passes where bare `any`/`unknown` still doesn't. `containsDynamicElement` itself (the array-element/object-field nested check) is unchanged in effect: it still rejects *any* dynamic type, constrained or not, nested inside a container, per the scope note above.

**Member-set checking** (`emit_dynamic.go`): `scalarTypeKind(t Type) string` classifies a concrete type into `"number"`/`"string"`/`"boolean"`/`""` (empty = not a valid V1 member). `validateUnionMembers(ty, line, col) error` walks `ty.UnionMembers` and rejects any member whose kind is `""` — called at every declaration checkpoint (var decl, function param/return, arrow-function param/return, method param) right after `resolveType`, independent of the assignment-time check below (since a union's member set is invalid regardless of whether anything is ever assigned to it). `unionAllowsAssignmentFrom(unionTy, valTy) bool` allows null/undefined exactly when `unionTy.Nullable`, allows any already-dynamic `valTy` through unchecked (the same trust boundary bare `any` already crosses — its real tag is only known at runtime), and otherwise requires `scalarTypeKind(valTy)` to match some member's kind.

**Wire-up**: every one of the (now six, including the three found during implementation) call sites that box a value into a dynamic-typed slot calls `unionAllowsAssignmentFrom` first when `ty.UnionMembers != nil`, erroring cleanly if it fails, before calling `emitBoxValue` — `emitVarDecl`'s scalar path (`emit_exprs_vardecl.go`), `emitAssign`'s identifier path (`emit_exprs_assign.go`), call-argument passing (`emit_call.go`), `emitReturn` (`emit_stmts.go`), `emitClosureFunc`'s expression-bodied-arrow return path (`emit_func.go`), and `emitClosureCallByPtr`'s argument passing (`emit_func.go`). A `let x: T | U` with no initializer and no `null`/`undefined` member is rejected outright (`emit_exprs_vardecl.go`) — resolving TDD-00043's own open question in favor of requiring an initializer, since boxing an unconditional `undefined` default (bare `any`'s existing behavior) would otherwise put the slot into a tag state its own declared member set doesn't actually permit.

## Implementation notes

Files touched: `ast/nodes.go` (`TypeAnnotation.UnionMembers`), `parser/parser_types.go` (the split described above), `codegen/llvm/types.go` (`Type.UnionMembers`), `codegen/llvm/emitter.go` (`resolveType`'s new branch), `codegen/llvm/emit_dynamic.go` (`isUnconstrainedDynamic`, `scalarTypeKind`, `validateUnionMembers`, `unionAllowsAssignmentFrom`, plus updated doc comments), `codegen/llvm/emit_func.go` (four guard sites, `emitClosureFunc`'s expression-body return, `emitClosureCallByPtr`'s argument boxing), `codegen/llvm/emit_classes.go` (method-parameter guard), `codegen/llvm/emit_exprs_vardecl.go` (declaration-time checks), `codegen/llvm/emit_exprs_assign.go` (reassignment check), `codegen/llvm/emit_call.go` (call-argument check), `codegen/llvm/emit_stmts.go` (`emitReturn`).

Non-obvious: `containsDynamicElement`'s callers previously all wrote `X.IsDynamic || containsDynamicElement(X)` — the top-level check and the nested-container check were two separate conditions combined at the call site, not one function. This ADR's guard relaxation only touches the top-level half (swapping in `isUnconstrainedDynamic`); `containsDynamicElement` itself, and its own internal recursive calls, still check plain `f.Ty.IsDynamic`/`ty.ElemType.IsDynamic` unchanged — this is what keeps a union nested inside an array/object rejected while a top-level union param/return is allowed, using the exact same helper function for both, just combined differently.

## Side effects discovered

- The three blind-`coerce`-on-dynamic-target bugs (`emitReturn`, `emitClosureFunc`'s expression-body return, `emitClosureCallByPtr`) were latent but unreachable before this ADR — `any`/`unknown` were never permitted as a function/closure param or return type at all, so `coerce` was never actually called with a dynamic target in practice. They're fixed as part of this change (required for it to work at all), not filed separately, since there's no reachable path to them without union return/param types existing.
- Confirmed a pre-existing, separate gap while checking method return types in `emit_classes.go`: there is no `any`/`unknown`-as-method-return-type guard anywhere in that file (unlike the four guards this ADR touched in `emit_func.go`). Not fixed here — out of scope for this change, and a class method returning a union type happens to work correctly anyway (it goes through the now-fixed `emitReturn`), so this is a pre-existing dead-guard gap for bare `any`, not a regression risk this ADR introduces. Left as a known gap, not tracked further since it doesn't block anything here.
