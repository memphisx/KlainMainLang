# ADR-00873: URLSearchParams as an ordered pair-list (WHATWG multi-value)

- **Relations**: `Implements TDD-00203`
- **Date**: 2026-09-11

## Context

`URLSearchParams` was a `Map<string,string>` with an `IsURLSearchParams` flag
(ADR-00076): storage that keeps one value per key and groups by key, so it could
not represent the WHATWG model — cross-key insertion order and duplicate keys.
`?a=1&b=2&a=3` collapsed the first `a` and reordered; `.append()` and `.sort()`
didn't exist (compile errors); `.getAll()` returned at most one element. The WPT
`url/` oracle (ADR-00871) scored 0 largely because of this. The status page even
claimed a single-value-per-key caveat as if `.append()` existed. The fix had to
change the backing structure, which meant re-owning the whole method + iteration
surface the Map machinery had provided for free.

## Investigation

Read the emitter's string ABI (TDD-00120: a string value is a `char*` to bytes
with an i64 length header at `ptr-8` and a trailing NUL) and the existing
collection dispatch (`emit_call.go`, `emit_collections.go`, `emit_stmts.go`
for-of, `emit_call_console.go`, `emit_exprs_types.go` inference). Confirmed that
`URLSearchParams` rode ~7 `IsMap` branches: method dispatch, `.size`, inference,
for-of, spread, console.log, and string coercion. A Map<string,string[]> was
rejected — it still loses cross-key order. The correct model is the spec's
literal "list of name-value tuples": an ordered array of `{key,val}` pairs.

## Decision

A dedicated C runtime, `urlsearchparamssrc/urlsearchparams.c`: an ordered array
of `{char *key; char *val;}` pairs with an ABI (`__kml_usp_*`) for create /
append / set (replace-first-drop-rest) / get (first) / getAll (a `{ptr,i64}`
string array) / has / has2 / delete / delete2 / size / key_at / val_at / keys /
values / entries / sort (stable, by key) / to_string (application/x-www-form-
urlencoded: space→`+`, %XX otherwise) / inspect / parse (order- and
duplicate-preserving, percent-decoding). Strings it returns are allocated in the
native header layout so the rest of the compiler treats them as first-class.

`URLSearchParamsType()` becomes a bare `ptr` carrying `IsURLSearchParams` (no
longer a Map). All dispatch is re-owned against the ABI (`emit_usp.go`): method
calls (checked first in `emit_call.go`, before the array/Map paths that would
reject the receiver), `.size` (member access → a JS number), for-of (rewritten to
`params.entries()`, the WHATWG default iterator), console.log (`URLSearchParams {
'a' => '1', … }`), and string coercion (`params + ''`/`${params}` →
`__kml_usp_to_string`). `emitValueToString` stringifies non-string names/values
(`append('n', 1)` → `"1"`). `has`/`delete` accept the WHATWG optional `value`
2nd argument. Construction covers a query string, an array of `[k,v]` pairs, a
record object, and copying another URLSearchParams. `URL`'s `.searchParams` is
built from the query the same way.

## Implementation notes

- `entries()` is `ArrayOf(TupleType([string,string]))`. A tuple value is a
  *pointer* to a heap `{ptr,ptr}` (tuples are objects), so `__kml_usp_entries`
  returns an array of pointers into the pair array, not inline structs — matching
  Map.entries()'s own shape (found by an initial nested-array crash).
- `isStringTy` now excludes `IsURLSearchParams`: the handle is a bare `ptr`, and
  without the exclusion the whole compiler mistook a `URLSearchParams` for a
  string (so `params + ''` concatenated the raw handle bytes).
- `__kml_usp_parse` uses `strlen`, not the length header: callers pass a
  `?`-stripped substring pointer that has no valid header at `q-8` (a segfault,
  found in testing).
- The E2E harness links C sources explicitly (not via `EmbeddedCSources`), so
  `appendURLSearchParams` was added to `tests/compiler_test.go` alongside
  `appendURLPattern` at every compile site.

## Side effects discovered

Two now-obsolete E2E tests encoded the *old* behavior and were corrected to the
faithful one: `DuplicateKeyLastWins` → `DuplicateKeys` (get returns the first
value, both preserved), and `toString` space → `+` (was `%20`, encodeURIComponent's
rule; WHATWG uses `+`). The `[...params]` spread yields an empty array — but that
is a *pre-existing* Map-spread limitation (`[...map]` is equally empty), not a
regression; `[...params.entries()]` works. The WPT harness's `assert_equals(x,
null)` on a null string boxed as `any` compares unequal — a separate any-equality
gap (D1/TDD-00155), recorded in BACKLOG, that blocks a couple of `url/` files
independent of URLSearchParams.

## Verification

macOS (Apple Silicon). Every method verified directly (multi-value, order,
duplicates, set-replace, sort, has/delete 2-arg, forEach/keys/values/entries,
for-of, console.log, `+`/template coercion, number-value stringification, and the
array/object/copy constructors). New E2E tests in `tests/url_test.go`; the URL /
querystring / searchparams suite passes. WPT `url/` went 0→5 passing (the
remaining failures are the D1 any-array/member gap, the harness generic-inference
limit, and array-capture-in-closure — none in URLSearchParams itself). Node
oracle unaffected.
