# ADR-00578: fs.rmdirSync recursive option

- **Relations**: Extends [ADR-00027](ADR-00027.md), reuses [ADR-00497](ADR-00497.md)
- **Date**: 2026-09-01

## Context

`fs.rmdirSync(path)` removed only an empty directory (POSIX `rmdir()`), with no
recursive option — the disclosed residual caveat. `fs.rmSync` (ADR-00497)
already ships a recursive tree-removal helper (`__kml_fs_rm(path, recursive,
force)`).

## Decision

Accept an optional `{ recursive: true }` argument on `fs.rmdirSync`, parsed with
the same literal-only shape `mkdirSync` uses. When present, route to
`__kml_fs_rm(path, true, false)` — the same recursive removal `rmSync` performs,
but with `force = false` so a missing path still throws, matching `rmdirSync`'s
own posture. The plain (no-options) form keeps the empty-directory-only
`__kml_fs_rmdir` path.

Node deprecated `recursive` on `rmdirSync` in favor of `rmSync` but still honors
it; matching that behavior keeps existing Node code portable.

## Verification

New `TestE2EFsRmdirRecursive` (create a nested tree, remove it recursively,
confirm gone; the plain empty-dir form still works). Built and verified on Mac
(Apple Silicon).
