# ADR-00406: Variable-bound http.createServer handle (listen/close/address)

- **Relations**: Extends ADR-00357 (TDD-00131 chained createServer), Extends ADR-00027-era http.listen/http.close model
- **Date**: 2026-08-27

## Context

The Node oracle (TDD-00121 Track B) showed `http.createServer` failing in ~106
of the full `test/parallel` corpus files with `http has no method
'createServer'`, plus a long tail of `a number has no method
'close'/'address'/'on'` — because the only accepted form was the single chained
expression `http.createServer(cb).listen(port)` (TDD-00131). The universal Node
idiom — bind the server to a variable, call `.listen()` later, `.close()` from
inside a callback, read `.address().port` after `listen(0)` — did not compile
at all: the binding's type fell back to `number` and every later method call
failed with the misleading number-method error. This was the single largest
addressable bucket in the corpus failure histogram, and it is the shape every
real API service uses.

## Investigation

- `codegen/llvm/emit_call.go:51` intercepts only the exact chained AST shape
  (callee `.listen` on an inner `createServer` call); a bare
  `http.createServer(...)` call fell through to the generic member dispatch and
  the `http has no method` rejection at `emit_call.go`'s http builtin switch.
- `net.createServer()` already models exactly the needed handle
  (`emit_net.go:149`, `IsNetServer` flag, heap struct holding the listen fd,
  `.listen/.close/.address` methods, `__kml_net_sockname_port` getsockname
  helper for the `listen(0)` ephemeral-port idiom) — so the design space was
  settled; this is a port of that model onto the existing single-server HTTP
  core, not a new subsystem.
- The chained emitter (`emitHTTPCreateServerListen`) interleaved handler
  validation, dispatcher build, bind, and event-loop entry in one function;
  the handler/dispatcher half is position-independent (module-level decls +
  straight-line stores into the `@__kml_listen_*` globals), so it could be
  split cleanly from the bind/listen half.

## Decision

Split `emitHTTPCreateServerListen` into a shared core plus two entry forms:

- `emitHTTPCreateServerCore(cb)` — validates the `(req, res)` handler, builds
  the res-mode dispatcher, stores handler + dispatcher into
  `@__kml_listen_handler`/`@__kml_listen_dispatch`. Used by both forms.
- Chained form: unchanged surface, now core + bind + fd store + loop.
- New variable-bound form `http.createServer(cb)` (no chained `.listen`):
  runs the core, then callocs an 8-byte handle holding the listen fd (−1
  until listen) and returns it typed `HTTPServerType()` (new `IsHTTPServer`
  flag). Methods on the handle:
  - `.listen(port?, cb?)` — port defaults to 0 (ephemeral) when omitted or
    when the only argument is the callback; binds, forks (0 workers), stores
    the fd into both the global and the handle, fires the callback, then
    enters the event loop. Like `http.listen` and the chained form, the call
    blocks until the loop stops — Node's non-blocking listen is not modeled.
  - `.close(cb?)` / `.closeAllConnections()` — delegate to the existing
    `__kml_http_close` / `__kml_http_close_all_conns` machinery; the optional
    close callback is invoked immediately after.
  - `.address()` — getsockname on the handle's fd via the shared
    `emitNetAddressObject` (`{ address, family, port }`), which is the crux of
    the `listen(0)` + `.address().port` test idiom.

The single-server V1 restriction is preserved: the variable-bound
`createServer` sets the same `httpListenCallSeen` flag the chained/`http.listen`
forms use.

Three follow-on pieces in the same delivery, each unblocking its own corpus
bucket:

- **Named import**: `import { createServer } from 'http'` — `createServer` and
  `closeAllConnections` added to the http virtual-module member table
  (`resolver/virtual_modules.go`), so the destructured `require`/import form
  resolves like `listen`/`close`/`get`/`request` already did.
- **Contextual handler typing**: an inline arrow handler with two un-annotated
  params gets `IncomingMessage`/`ServerResponse` filled in (real Node infers
  both from the createServer signature; requiring explicit annotations made
  every corpus handler fail). Applies only where an annotation is absent.
- **Zero-arg form**: `http.createServer()` + `server.on('request', handler)` —
  the handler/dispatcher core runs at the `.on('request', …)` site;
  `.listen()` before a handler is registered, a second `'request'` listener,
  and any other event name are clean rejections.

## Implementation notes

- `codegen/llvm/types.go`: `IsHTTPServer` flag + `HTTPServerType()`.
- `codegen/llvm/emit_http.go`: `emitHTTPCreateServerCore`,
  `emitHTTPCreateServer`, `emitHTTPServerMethod`, `emitHTTPServerListen`;
  chained `emitHTTPCreateServerListen` rewritten over the core.
- `codegen/llvm/emit_call.go`: `createServer` case in the http builtin switch
  (the chained interception stays first and unchanged); `IsHTTPServer` member
  dispatch next to the `IsNetServer` one.
- `codegen/llvm/emit_exprs_types.go`: `http.createServer(...)` infers
  `HTTPServerType()`; `.address()` inference extended to `IsHTTPServer`.
- The handle is a bare i64 slot (no named struct): only the fd lives there,
  since handler/dispatcher are process-globals under the single-server rule.

## Side effects discovered

- `server.on('close'|'request'|'error', …)` remains unsupported (clean
  rejection listing the supported methods) — the corpus uses it; follow-on.
- A `fetch()` inside a sync timer callback returns an unsettled Promise and
  cannot self-request the server from non-async code; the E2E test uses a
  Go-side client instead.
- `http.get`/`http.request` still return void (TDD-00138 V1), so
  `new http.ClientRequest`-style corpus files stay failing on the parser's
  missing `new <member-expr>` form — tracked in the Node-oracle gap notes.
