# ADR-01232: A function's own properties; TypeScript expando declarations

- **Relations**: `Extends ADR-01093`
- **Date**: 2026-09-29

## Context

Node's `util.promisify` looks up `fn[util.promisify.custom]`, and
`child_process` defines that property on `exec` and `execFile`. Here a
function had no own properties:

- `Object.defineProperty(f, k, …)` was "requires a dynamic (any-typed)
  object";
- `(f as any).x = 1` threw "Cannot set properties of a non-object value";
- `(f as any)[k]` was "cannot index a non-array expression";
- `f.x = 1` on a function declaration (TypeScript's expando declaration,
  valid TS) was "field assignment on non-object";
- the checker let any property of a function through: `q.zzz` compiled,
  where tsc says TS2339, and `q.n` of an expando was untyped.

## Investigation

- A boxed function is a tag-12 record. Boxing the same closure twice gives
  two records, but `__kml_fn_identity_dyn` (fnmeta.c) already leads both
  back to the closure header. That header is the function object's
  identity, the same one listener removal uses.
- Growing the closure header (TDD-00229's Stage A design) stays unsafe:
  hand-built 16-byte headers are everywhere (ADR-01093's finding).
- `x as any` was erased for a function: the operand kept its static type,
  so `(f as any)[k]` took the static index path.

## Decision

- **Own-property bag.** Each function identity gets one dynamic-object bag
  on first write, kept in a table in `fnmeta.c` keyed by identity. An
  extended record (node:ffi) keeps its own bag. The table is static data
  (a `-mm=gc` root), guarded by a spin lock for workers.
- **Dynamic paths.** Every dynamic operation takes the bag on a tag-12
  value: member get and set, bracket get and set, `in` (then `name`,
  `length` and Function.prototype's members), `hasOwn`, `Object.keys`,
  `for…in`, `Object.entries`/`values`, `delete`, and
  `Object.defineProperty`/`getOwnPropertyDescriptor`, which box a
  function argument. Inspect prints `[Function: f] { x: 1 }` when the bag
  has enumerable keys.
- **Static function values.** A member or bracket read or write on a
  function-typed value (not an FFI function) boxes it and takes the
  dynamic path. A read is typed by the checker's primitive, else `any`.
  `inferExprType` mirrors this. `f as any` on a function is the boxed
  function.
- **Checker.** `f.p = v` statements in the scope declaring `f` (a function
  declaration, an overloaded one's implementation, or a const bound to a
  function expression or arrow) declare `p` on `f`'s type, typed as the
  widened union of the assigned values. Other members of a function type
  come from the `Function` interface. Any other property on such a
  function is TS2339, unless a namespace of the same name merges into it
  (`function f() {}` + `namespace f {}`, which the resolver renames apart):
  the namespace declares members too.
- **Symbol keys.** An `any` key holding a Symbol keys by the symbol's
  identity, as a Symbol-typed key does, rather than by its ToString.
  `util.inspect` prints symbol keys as `Symbol(desc): v`, after the string
  keys.

## Implementation notes

- Runtime: `fnmetasrc/fnmeta.c` (`__kml_fn_props_dyn`,
  `__kml_fn_props_dyn_make`, `__kml_fn_has_builtin`).
- Codegen: `fnmeta.go`, `emit_dynobj.go`, `emit_dyndesc.go`,
  `emit_exprs_member.go`, `emit_exprs_assign.go`, `emit_exprs_types.go`,
  `emit_undefined.go`.
- Checker: `checker/expando.go`, `checker.go`, `check.go`.
- Inspect: `dynjsonsrc/dynjson.c`.
- Writing a bag links the object inspector, which renders the bag.

## Side effects discovered

- Unboxing a function from `any` into a typed slot builds a new thunk
  each time, so `promisify(p) === p` is false (BACKLOG 44).

## Verification

Mac (Apple Silicon), against Node v24.19: `TestE2EFunctionOwnProperties`,
`TestE2EFunctionExpandoDeclarations` (including the TS2339 and TS2322
rejections), `examples/function_expressions/own_properties.ts`.
