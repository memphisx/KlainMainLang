# ADR-01157: Class-member accessibility checked by the checker; overrides with fewer parameters; `o["m"]()` calls

- **Relations**: `Implements TDD-00230` (P2.7, phase 2's "codegen's user-facing errors are gone"); `Extends ADR-01156`; found while scoping `TDD-00231`
- **Date**: 2026-09-25

## Context

A probe for [TDD-00231](../tdd/TDD-00231.md) wrote a small Node-style
`Readable` in TypeScript. Four valid programs failed:

- `if (opts?.read) this.fn = opts.read` was TS18048 ("'opts' is possibly
  'undefined'"). tsc narrows `opts` to defined when the chain is truthy.
- An override declaring fewer parameters than its base (`_read()` over
  `_read(size: number)`) was a codegen error ("overrides an inherited
  method with an incompatible signature"). TypeScript allows it.
- `const f = () => this.flow()` inside a method, with `flow` private, was
  a codegen error ("is private and not accessible here"). The arrow's
  body was emitted in a scope with no enclosing class.
- `a["m"]()` was "only simple function calls are supported".

Private and protected access was checked only by codegen, with its own
messages and not tsc's codes. The checker reported none of TS2341,
TS2445, TS2446, TS2673 or TS2674, and the TypeScript corpus has 104,
99, 27, and several of the constructor codes in its baselines. Codegen
also rejected `o["p"]` on a private member, which TypeScript allows as
the way around a modifier.

## Decision

- **The checker reports accessibility**, as tsc's
  `checkPropertyAccessibilityAtLocation` and `isConstructorAccessible`:
  - TS2341: a private member outside its class's body.
  - TS2445: a protected member outside its class and its subclasses.
  - TS2446: a protected instance member, not read through `super`, on an
    instance that is not of the enclosing class or a subclass.
  - TS2673 and TS2674: `new C()` of a class whose own or inherited
    constructor is private or protected, outside where it may be called.
    The message names the declaring class.
  - TS2855: a parent's field read through `super`, which is always
    `undefined` under ES2022 class fields.
  - Static members are looked up on the class and its bases.
  - An accessor pair reads with its getter's modifier and is written with
    its setter's.
  - A duplicate member keeps its first declaration.
  - An element access by name (`o["p"]`) is not checked, as in tsc.
- **Types:** `Property` carries `Visibility`, `WriteVisibility`,
  `Owner` and `Field`. `super.m` is typed as the base class's instance.
- **Narrowing:** a truthy optional chain narrows its base to non-nullish
  (tsc's `narrowTypeByTruthiness`).
- **Codegen:**
  - `checkMemberVisibility`, `checkFieldVisibility`, the four visibility
    tables and the `__kml_enclosing_class` scope symbol are deleted.
  - An override with fewer parameters gets its base's remaining ones as
    unused parameters, so both share one vtable signature. A rest
    parameter on either side is left alone.
  - `o["m"](…)` compiles as `o.m(…)` when the key is an identifier name.

## Side effects discovered

- Assigning a function to a method on an instance (`this._read = fn`) is
  "no field '_read'". JS gives the instance an own property (BACKLOG).
- The probe also hit three caveats already documented, which TDD-00231
  lists as its compiler prerequisites:
  - an object literal's method `this` typed by a `this:` parameter, with
    `.call` discarding `thisArg` (TDD-00137);
  - async generator methods (TDD-00063);
  - an array-typed ternary into `any`.

## Verification

- **tsdiag, TS 7.0.2 corpus:** 3,098 diagnostics over 6,004 cases, all
  matching, 0 false positives. Before: 3,002. No earlier match was lost
  (the match lists diffed). Over the project's `examples` and `apps`: 0
  diagnostics.
- **Tests:**
  - `TestCheck`: seven new cases, each code checked with tsc 7.0.2;
  - `TestE2EOverrideWithFewerParameters`,
    `TestE2EPrivateMemberFromArrowAndElementAccess` (output identical to
    Node, clean under `tsc --strict`) and
    `TestE2EProtectedMemberThroughOtherInstanceIsError`;
  - the five existing visibility tests now expect tsc's messages.
