# ADR-00360: `http.closeAllConnections()` via socket shutdown

- **Relations**: Implements [TDD-00118](../tdd/TDD-00118.md). Extends [ADR-00359](ADR-00359.md) (shared cluster flag), [ADR-00102](ADR-00102.md) (`http.close()`).
- **Date**: 2026-08-25

## Context

`http.close()` is graceful — it stops accepting and lets in-flight connections
finish. The missing forceful counterpart (Node's `server.closeAllConnections()`)
was the last caveat on the `http.close()` HTTP-Server row. Second item of the
HTTP-Server caveat-cleanup pass, after cross-worker close ([ADR-00359](ADR-00359.md)).

## Investigation

Each in-flight connection is a suspended fiber (`ucontext_t` + malloc'd stack,
parked mid-read — `runtime_http.go`'s `__kml_http_append_conn`). Freeing those
from outside is unsafe: the fiber owns its own `close(fd)` and active-count
decrement, and unwinding a stack mid-`swapcontext` is not reasoned about. But the
connection fiber's read loop already routes `read()==0` (EOF) to its normal
finish path (`emit_http.go`'s `noReqL`: `close` + active--). So shutting the
socket down is enough to make the fiber tear *itself* down safely.

## Decision

`http.closeAllConnections()`, a bare global mirroring `http.close()`:

- `__kml_http_shutdown_local_conns`: walk the connection registry
  (`{ i64 fd, ptr, ptr, ptr, ptr }` entries) and `shutdown(fd, SHUT_RDWR=2)`
  every slot with `fd >= 0`. Return value ignored (an already-closed or
  half-open fd is a harmless no-op). The fibers unwind through their existing EOF
  finish path on the loop's next resume, which happens promptly since a shut-down
  socket reads ready immediately.
- `__kml_http_close_all_conns` (public): set word[1] of the shared cluster flag
  region (atomic, when the region exists), then run the local pass. The shared
  region ([ADR-00359](ADR-00359.md)) is widened from one i64 to two: word[0] =
  close-listener, word[1] = force-close. Every worker's event loop polls word[1]
  alongside word[0] and runs its own local shutdown pass, so one worker's call
  force-closes the whole cluster — symmetric with `close()`.
- Emit: `emitHTTPCloseAllConnections` (`emit_http.go`) + a `closeAllConnections`
  case in `emit_call.go`'s `http__kml_builtin` dispatch. Takes no arguments.

`__kml_event_loop_run` calls `__kml_http_shutdown_local_conns` unconditionally in
its cluster-flag poll, so `ensureHTTPRuntime` pulls in `ensureHTTPCloseAllConns`
unconditionally (same "define everything the loop references" rule as
`ensureFetchAsync`/`ensurePromiseCombinators`).

## Implementation notes

- New `ensureHTTPCloseAllConns` (`runtime_http.go`); `usedShutdownDecl` +
  `usedHTTPCloseAllConns` flags. `shutdown` declared once.
- The shared flag mmap grew 8→16 bytes; both words zeroed before the fork.
- Self-close is intentional (Node parity): the calling handler's own socket is
  shut down too, so its response `write()` fails silently and the fiber finishes.
  Callers answer-then-close if they need the response delivered.

## Side effects discovered

The shared force-close word is monotonic/sticky, so in a cluster a
later-accepted connection would also be shut down on the next poll. Unobservable
in the realistic `close()` + `closeAllConnections()` pairing (listener gone → no
new connections); documented in [TDD-00118](../tdd/TDD-00118.md), not engineered
around.

## Verification

- `TestE2EHTTPCloseAllConnectionsTerminatesInFlight` (new): a partial-request
  connection parked mid-read is force-terminated (client hits EOF, ~0.85s) when a
  second request calls `closeAllConnections()`. **Negative control** (the runtime
  call stubbed out) fails — the connection stays parked until the read deadline.
- `HTTPListen|Cluster|Close|Timer|EventSource|WebSocket|Stream` suites pass.
- `go build`/`go vet` clean.
