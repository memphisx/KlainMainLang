# TDD-00174: Maturity gate for flipping `-mm=auto` (+ `-optimize-memory`) to default

- **Status**: Partially Implemented
- **Date**: 2026-09-04

Stage A knobs shipped ([ADR-00708](../adr/ADR-00708.md)): examples lane
(`make examples MM=auto OPTMEM=1`) and E2E lane
(`KLAIN_TEST_MM`/`KLAIN_TEST_OPTMEM`) run as mode-differential lanes; the
first auto-mode run found and fixed a `??`/`||`/`&&` use-after-free. Examples
+ E2E differential lanes are green on Mac. Remaining Stage-A tooling
(conformance flip-diff, fuzz Lane C, `-debug-frees` census, klainload soak)
and Stage B (the shipped-default flip, gated on the exit criteria) are not
yet built.

## Context

`manual` is the default memory mode, and it is the least Node-faithful of the
three: Node never asks a program to free anything, while `manual` leaks by
default and makes `Memory.free` the programmer's job. `auto`
([TDD-00173](TDD-00173.md)) is the only mode that is both dependency-free
(unlike `gc`'s bdw-gc requirement, which cuts against portability-by-default)
and moves toward Node-observable behavior. The long-term default should be
`auto` with `-optimize-memory` on.

What blocks the flip is not a missing feature — it's **confidence**. Both
`auto`'s free insertion and `-optimize-memory`'s stack planning ride the same
escape analysis, and their failure modes are asymmetric: a missed free is a
leak (exactly `manual`'s behavior — acceptable), but a wrongly-proven free or
stack slot is use-after-free — the worst class of bug, shipped in the default
configuration. The two defaults must therefore flip **together**, gated on the
same evidence.

The hard problem this document actually scopes: **the maturity evidence has
to be manufactured in-house.** The compiler is pre-alpha with a single
consumer — this repository itself. There is no user population to organically
soak the escape analysis; every mile on it has to be driven deliberately. So
the design below is mostly a catalog of ways to turn corpora, tooling, and
programs this project already owns into adversarial consumers of `auto`, plus
the quantified exit criteria that define "now is a good time."

## Design

### Two flips, not one: development default first

The single cheapest maturity generator available is to make `auto` the
default **inside this repository** long before it is the default of the
shipped CLI. The flip is split accordingly:

- **Stage A — dev-default flip (immediately, no gate)**: `buildBinary`, the
  examples runner, and the per-delivery workflow (relevant tests + Node
  oracle) compile in `-mm=auto -optimize-memory` *by default*. From that
  moment, every new feature and fix is exercised against auto first, as a
  side effect of normal development — no discipline required, no lane to
  remember to run. `manual` inverts into the secondary, differential lane
  rather than the primary one. This is the answer to "how do miles on the
  escape analysis accumulate with zero external users": by making them the
  miles that get driven anyway.
- **Stage B — shipped-default flip (gated)**: the public CLI's `-mm`
  default and `-optimize-memory` flip only when the exit criteria below
  have held. Stage A is what makes the criteria reachable; Stage B is the
  user-facing change.

Stage A has one honesty cost to manage: a test asserting exact output that
passes under auto but would fail under manual (or vice versa) must fail the
build, not silently drift — which is exactly what the differential lanes
below exist to catch. Mode-specific tests (`Memory.free` rejection, gc-mode
suites, churn/RSS tests) keep their explicit mode pins and are unaffected.

### The core oracle: mode-differential testing

`auto` (and `-optimize-memory`) claim **zero observable-behavior change** —
only the allocation/free profile differs. That claim is a perfect,
free-of-charge test oracle: any program whose output differs between
`-mm=manual` and `-mm=auto` (or with/without `-optimize-memory`) has found a
bug, with no hand-written expectation needed. Every corpus this project owns
becomes an `auto` stress corpus by re-running it in a second mode and
diffing:

1. **Examples lane** — `make examples MM=auto OPTMEM=1`: all ~283 example
   programs compiled in auto+optimize, stdout byte-compared against the
   default-mode run. Cheapest to build (the harness already loops files);
   first to land.
2. **E2E test lane** — a build-tag or env knob making `buildBinary` compile
   in auto+optimize, then the full `make test-par` suite runs against it.
   Assertions are unchanged; a mode-sensitive failure is the finding.
3. **Conformance flip-diff** — the Test262 and Node-oracle runners
   ([TDD-00121](TDD-00121.md)) get an auto lane whose *deliverable is the
   diff of pass/fail sets*, not the aggregate number: any file flipping
   PASS→FAIL (or changing failure class to a crash signal) under auto is an
   auto-attributable bug. Thousands of adversarial programs, already
   downloaded, already runnable — the closest thing to a user population
   this project can conjure. The per-file result cache should key on mode so
   the second lane doesn't double every run's cost.

### The severity amplifier: sanitizers as judge

Differential output-compare catches wrong *results*; it can miss a
use-after-free that happens not to disturb output. So the differential lanes
run twice-armed:

- **ASan/UBSan builds** (`buildBinaryASan` exists) of the examples + E2E
  lanes in auto mode — a wrongly-inserted free becomes a deterministic
  heap-use-after-free/double-free report instead of silent corruption. This
  is the single highest-value lane in the plan: ASan converts the scary
  failure mode into a loud one.
- **Free-site introspection** — a `-debug-frees` compiler flag that prints
  every inserted free (variable, position, placement: block-exit vs
  last-use) so a sanitizer finding is attributable to a decision, not just a
  stack trace. Also enables a corpus-wide "free census": a sudden jump or
  drop in inserted-free counts between compiler versions is a regression
  signal even before anything crashes.
- Linux lane note: ASan's allocator interposition vs the gc shim has
  history ([ADR-00100](../adr/ADR-00100.md)) — auto mode has no shim, so no
  conflict is expected, but the claim needs an actual Linux run, not
  inference.

### The reach extender: fuzzing aimed at the escape analysis

[TDD-00014](TDD-00014.md)'s Lane B fuzzer generates well-formed programs but
its grammar predates the escape analysis. Extend it with a **Lane C:
escape-shaped generation + mode-differential oracle**:

- Grammar biased toward exactly the constructs the escape checker judges:
  conditional escapes (`if (p) keep.push(x)`), aliasing chains
  (`const b = a`), closure captures (read-only vs mutating, escaping vs
  local), returns of locals vs fresh literals, loops redeclaring per-iteration
  values, `@free`/`@owned` annotations sprinkled where legal, values used
  across `try`/`catch`.
- Oracle = the differential one: compile each generated program in manual
  and in auto+optimize+ASan; outputs must match and ASan must stay quiet.
  No hand-modeled expectation needed, so the generator can be aggressive.
- **Metamorphic twist**, nearly free once the generator exists: apply
  output-preserving transforms (wrap a statement in a bare block, extract an
  expression to a `const`, swap `let`/`const` where legal) and assert the
  program still behaves identically in auto. Each transform shifts scope
  boundaries — exactly what block-exit free placement is sensitive to.

### The realism lane: dogfooding + soak

Corpora prove breadth; long-running processes prove the target use case
(microservices) that `manual` fails at. Being the only consumer means
*building* consumers:

- **Self-soak with existing tools**: the TS httpbin rewrite and the
  `klainload` load tester ([ADR-00618](../adr/ADR-00618.md)/
  [ADR-00620](../adr/ADR-00620.md)) are both real programs in this language.
  Compile the server in `-mm=auto -optimize-memory`, drive it with
  `klainload` for multi-hour sessions, assert bounded RSS (the
  churn-E2E pattern, scaled up) and zero crashes. This is the closest
  in-house analog to production traffic.
- **Grow the dogfood surface**: each new utility this project needs (corpus
  runners, report generators, small CLIs) is a candidate to be written in
  KlainMainLang instead of Go where feasible — every one is a permanent
  consumer exercising idiomatic (not generated) code in auto mode.
- **Chaos knob**: a `klainload` mode mixing request shapes/sizes/keep-alive
  churn, so the soak exercises allocation patterns beyond a steady-state
  loop.

### The flip itself

Mechanics once the gate below is passed, so they're decided now and not
litigated later:

- `-mm=auto` and `-optimize-memory` flip in the same release; `manual`
  and the flag remain available, documented as the opt-outs.
- `Memory.free(x)` under the new default is a compile error today
  (TDD-00173's exclusivity rule) — the error message must point at
  `-mm=manual` explicitly, since it will now be the first thing an
  existing manual-mode program hits.
- Docs sweep: README, status pages, website reference all currently assume
  `manual`-default phrasing ("never frees on its own" as the headline
  caveat). Pre-flip, an intermediate step is cheap and useful immediately:
  keep `manual` the default but lead the docs with `auto` as the
  *recommended* mode for long-running programs, so the eventual flip
  surprises no one.
- The conformance lanes swap roles: default-mode reports become auto-mode
  reports; the manual lane persists as the diff baseline.

### Exit criteria (the gate)

All of the following, sustained over a window of **N consecutive releases
developed under the Stage-A dev-default (proposed N=3)** with the lanes
actually running per-release, on **both machines** (Linux x86-64 + Apple Silicon — the allocator/TLS history says
don't infer parity):

1. Examples + E2E differential lanes green in auto+optimize (byte-identical
   outputs), including the ASan-armed variants — zero auto-attributable
   findings.
2. Conformance flip-diff empty: no Test262/Node-oracle file regresses
   PASS→FAIL or gains a crash-class failure under auto.
3. Fuzz Lane C: a defined budget (proposed ≥24 CPU-hours per release) with
   zero surviving differential or sanitizer findings (findings are fine —
   *unfixed* findings block).
4. Soak: ≥8-hour klainload run against the dogfood server in auto+optimize,
   RSS bounded (flat after warmup within a stated envelope), zero crashes.
5. The free census between the release's compiler and the prior one shows
   no unexplained placement shifts on the frozen corpus.

Any lane finding a use-after-free class bug **resets the window** for the
criterion that caught it. Leaks discovered in auto do *not* reset anything —
they are the designed, conservative fallback — but get tracked as analysis-
precision follow-ups.

## Open questions

- Stage A scope: flip *all* E2E tests to auto-default at once, or start with
  examples + new tests and migrate suites incrementally? A big-bang flip
  surfaces everything immediately but may drown the first week in
  mode-sensitivity triage rather than real findings.
- Is N=3 releases the right window, or should the gate be time-based
  (e.g. 6 weeks of nightly lanes) given releases have no fixed cadence?
- Where do the recurring lanes run? Both dev machines exist but neither is a
  CI box; a scheduled local `make maturity` target may be the honest v1,
  with CI adoption as its own later step.
- Does `gc` stay fully out of the gate (it has its own dependency story), or
  should the differential lanes include a three-way diff where bdw-gc is
  installed?
- Should the flip wait for `-optimize-memory` Stage 3 (value-returned
  tuples) so the default's performance story lands once, or is Stage 3
  orthogonal enough to ship later under an already-flipped default?
- Whether `async`/generator functions (currently excluded from auto's
  insertion entirely) need their own criterion, or whether "they leak like
  manual" remains acceptable under a flipped default.
