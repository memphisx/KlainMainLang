# ADR-01604: A Windows cluster worker takes its inherited listeners

- **Relations**: Extends ADR-01027, ADR-01602
- **Date**: 2026-10-13

## Context

A `klain:http` `{ workers }` program that also calls
`http.createServer().listen(port)` failed in every worker on Windows with
`EADDRINUSE` (`TestE2EHTTPClusterCombinedWithCreateServer`, BACKLOG §0).

## Investigation

Windows has no fork: a worker is the program re-run (ADR-01027). The primary
binds every listener before starting the workers, which inherit them, and it
deals each listener's connections round-robin over a per-worker channel,
as Node's cluster does on Windows. `klain:http`'s `listen` in a worker takes
its listener from the inherited set (`__kml_win_inherited_listener`);
`net`'s `tcp_listen`, behind `http.createServer().listen()`, bound a new
socket on the port the primary already held. On Linux the worker's own bind
succeeds through `SO_REUSEPORT`.

The backlog also listed `http.close()` in one worker not reaching its
siblings on Windows; `TestE2EHTTPListenClusterCloseReachesAllWorkers` passes
there: workers map the primary's close-flag page (`__kml_win_cluster_flag`).
The item and the comment in `runtime_spawn_win.go` were stale.

## Decision

On Windows `__kml_native_tcp_listen` first asks for an inherited listener on
the port and, when there is one, makes it the server's handle instead of
binding. In a primary or a program without workers there is none.

## Verification

Windows 11: every `Cluster` E2E test passes, the combined one included.
Linux: unaffected (Windows-only branch).
