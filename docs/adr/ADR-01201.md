# ADR-01201: A function boxed into `any` twice is one function

- **Relations**: `Implements TDD-00229`
- **Date**: 2026-09-28

## Context

`const a: any = f; const b: any = f; a === b` was `false`, and
`arr.indexOf(f)`, `arr.includes(f)` and `map.get(f)` on `any`-keyed
collections missed. Found writing an `EventTarget` in TypeScript
(TDD-00232), whose duplicate-listener check is an `indexOf` over the
listener list.

## Investigation

Boxing a statically typed closure (`emitDynClosureAdapter`,
`codegen/llvm/emit_dynfunc.go`) allocates a new tag-12 record per boxing
site and evaluation, `{adapter, closure header, arity}`. `__kml_any_eq`
compared such records by pointer, and `__kml_map_any_hash` hashed their
bits. The function-metadata runtime already has the right notion:
`__kml_fn_identity_dyn` follows adapters through their env to the closure
header (it backs EventEmitter's `removeListener`).

## Decision

`__kml_any_eq` compares two dynamic-function boxes (pointer kind 7) by
`__kml_fn_identity_dyn`, and `__kml_map_any_hash` hashes one by that
identity, so SameValueZero (Map/Set keys, `includes`) and `===`/`indexOf`
agree.

## Implementation notes

`codegen/llvm/runtime_dynamic.go`, `runtime_collections.go`; both now pull
in the function-metadata runtime.

## Side effects discovered

- Union `function | object` listener types (`EventListenerOrEventListenerObject`)
  do not narrow in codegen (`typeof l === "function"` then `l.handleEvent`
  is "an object has no method"); tracked in BACKLOG.

## Verification

Mac (Apple Silicon), against Node v24.19:
`TestE2EFunctionIdentityThroughAny` (`===`, `!==`, `indexOf`, `includes`,
a helper taking `any`, a `Map<any, …>` key).
