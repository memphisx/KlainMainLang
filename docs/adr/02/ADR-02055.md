# ADR-02055: `--unhandled-rejections` modes; an uncaught exit runs the 'exit' listeners

- **Date**: 2026-11-22

## Context

- A compiled program always treated an unhandled rejection as Node's
  default (`throw`) does. Node reads `--unhandled-rejections` (and
  `--no-warnings`) from `NODE_OPTIONS` as from its command line: `none`
  leaves the reason untouched, `warn` and `warn-with-error-code` print
  warnings (the second also sets `process.exitCode` 1), `strict` raises
  the uncaught exception before the event, and an unknown mode ends the
  process with status 9 before the program runs.
- An uncaught exception nothing handled printed its report and exited 1
  without the `'exit'` listeners, which Node runs with `process.exitCode`
  1.

## Decision

- microtask.c parses `NODE_OPTIONS` in a constructor (both
  `--unhandled-rejections=m` and `--unhandled-rejections m`; the invalid
  mode's message names argv[0], as Node's does), numbers each unhandled
  rejection as it happens (the warning's rejection id). The warning is
  Node's pair: the reason (an Error's stack, another value's V8 text), then
  the notice — through `process.emitWarning` when the program links it (a
  `'warning'` listener sees both), else printed by the runtime as the
  default listener prints them, with the one-time `--trace-warnings` hint.
- The default `'warning'` listener (lib/node/internal_process_warning.ts)
  prints nothing under `--no-warnings` in `NODE_OPTIONS`; the event is
  still emitted.
- `__kml_unhandled_report` branches on the mode: the `'unhandledRejection'`
  event first except under `strict`; then `throw`'s uncaught exception,
  `warn`'s warning, `warn-with-error-code`'s warning and exit code, or
  nothing for `none`; `strict` raises the exception and, when an
  `'uncaughtException'` listener takes it, emits the event and warns when
  nothing listens.
- hooks.c keeps an exit code the runtime sets (`__kml_store_exit_code`)
  for a program without process.c; process.c stores it as
  `process.exitCode`. Both uncaught-exit paths (top level, a loop
  callback) set it to 1 and run the `'exit'` listeners before exiting.

## Consequences

- `TestE2EUnhandledRejectionsModes` and
  `TestE2EUnhandledRejectionsWarningEvent` compare every mode, an invalid
  one and `--no-warnings` with Node (stdout, stderr less the pid, program
  name and stack frames, and the status);
  `TestE2EUncaughtRunsExitListeners` checks the exit listeners.
