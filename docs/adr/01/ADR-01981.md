# ADR-01981: Local classes in loops, closures and generics

- **Relations**: Implements TDD-00230 (P2.7); follows [ADR-01980](ADR-01980.md)
- **Date**: 2026-11-07

## Context

A class declared in a function that names the function's locals is
closure-converted: each instance holds the locals in hidden fields, which
a `new` fills from the scope it runs in. Three cases failed:

- A generic local class was refused outright.
- A class in a loop body naming the loop's own binding was refused as "a
  loop binding written after the class". This covered `for (let i = 0;
  …; i++)`, `for (const x of …)` and `for (const k in …)`.
- `() => new D()`, where `D` names a local, failed with an undefined
  variable. The closure captured only the names it reads itself, and `D`'s
  locals are read implicitly by `new`.

## Decision

- A write in the update clause of the `for (let …)` that declares a
  binding is not a write after the class: it writes the next iteration's
  copy. Neither is the loop's own store of each element into a `for…of`
  or `for…in` `let`/`const` binding.
- A closure that reads a closure-converted class also captures the locals
  that class captures (`addClassCaptureReads`). The per-iteration `let`
  analysis counts them the same way.
- A generic local class is closure-converted like any other. Its
  instantiations take the captures recorded for the generic class
  (`capturesOf`).

## Consequences

- Covered by `TestE2ELocalClassClosureLoopsGenericsArrows`, which matches
  Node.
- A loop variable written in the loop body after the class is still
  refused: the conversion has no cell for a loop binding.
