# ADR-01448: Generator types, `yield` results, array spreads, TS7057

- **Relations**: Implements TDD-00230 (P2.3, P2.6, P2.7)
- **Date**: 2026-10-07

## Context

The largest unanswered-return bucket (368 locations) was an async
generator method read through `this.#gen`. The checker left an async
generator's type unanswered, and the builtin declarations had only empty
stubs for the async iteration interfaces. Probing found two more gaps:
a `yield` expression had no type, and any array literal containing a spread
(`[...xs, 1]`) was unanswered.

## Investigation

tsc 5.9 --strict, on the probes:

- `function* g() { yield 1 }` is `Generator<number, void, unknown>`: a lone
  literal yield widens, a union of them stays
  (`AsyncGenerator<string | 1, number, unknown>`).
- An async generator awaits what it yields and returns.
- A `yield` with no declared or contextual generator type results in `any`
  and, where its value is used, reports TS7057.
- `[...xs, 1]` is `(string | number)[]`; a spread of `any` gives `any[]`.

## Decision

- `lib/es.d.ts` declares `AsyncIterator`, `AsyncIterable`,
  `AsyncIterableIterator`, `AsyncIteratorObject` and `AsyncGenerator` as
  TypeScript's es2018 library does.
- `generatorReturn` builds `AsyncGenerator<Y, R, unknown>` for an async
  generator, with Y and R awaited, and widens a unit yield type.
- A `yield` is `any`; `yield* g` is g's return type.
- `iteratedType` gives `any` for `any` and reads the async iteration types.
- An array literal with spreads is an array of the union of its elements
  and each spread's iterated type; under `as const` or a tuple context it
  stays unanswered.
- TS7057 is reported in the strict lane for a used `yield` result in a
  generator with no declared return type, where nothing gives it a
  contextual type: not a `yield*`, not an annotated declaration's
  initializer, not a binding pattern's source, and not a computed key, a
  decorator or an `import()` specifier (contexts this checker does not
  model yet).

## Implementation notes

- `lib/tsmembers.txt` is regenerated (`tools/libconform -members`): it
  lists TypeScript's members for each interface the declarations name, now
  including `AsyncGenerator`.

## Side effects discovered

- A generator object's representation depends on its function's own
  layout (parameter slots, receiver), so the oracle cannot represent
  `Generator<…>` from the type alone. That is P3.3's work, and the bucket's
  rows also read a method as a value (BACKLOG #138).

## Verification

- `TestGeneratorTypes`, `TestYieldImplicitAny` (tsc 5.9 expectations); the
  generator, async iteration and for-await E2E tests pass on the Mac.
- `tools/tsdiag`: TS7057 matches 5 of TypeScript's 9 baseline errors with
  no false positive; no other code gains one.
- Test262's strict lane rejects 13 programs tsc rejects with TS7057 (an
  unannotated generator using a `yield` result, e.g.
  `language/expressions/yield/rhs-yield.js`): expected rejections, not
  regressions.
