# ADR-00559: Buffer string-form fill

- **Relations**: Extends TDD-00103, ADR-00558
- **Date**: 2026-09-01

## Context

`Buffer.fill` accepted only a numeric (single-byte) value — the string form
`buf.fill("ab")`, which repeats the string's bytes across the fill range, was
unsupported (part of the same Buffer status caveat ADR-00558 addressed for
indexOf/includes/lastIndexOf).

## Investigation

`buf.fill(...)` rides `emitArrayFill` (a Buffer is a `Uint8Array`), which
handles numeric fills. A string value needs a distinct byte-cycling fill;
`emitNormalizeSliceIdx` already normalizes the optional `offset`/`end` bounds
the array path uses, so those can be reused.

## Decision

Add `emitBufferStringFill(mem, args, pos)` and intercept `fill` in emit_call.go
when the receiver is a Buffer and `args[0]` is a string (numeric fills stay on
the array path). It normalizes `[offset, end)`, then loops writing
`needle[(i - offset) % needleLen]` into `buf[i]` — repeating the needle aligned
to the fill offset, matching Node (`Buffer.alloc(5).fill("ab", 1)` →
`00 61 62 61 62`). An empty needle is a no-op (the loop is skipped).

## Implementation notes

- Single value + optional `offset`/`end`; a fourth `encoding` argument is a
  clean compile error.
- Returns the same buffer aggregate, matching `.fill`'s chainable return.

## Side effects discovered

None. Numeric `.fill` and the rest of the Buffer surface are unchanged.

## Verification

`TestE2EBufferStringFill` cross-checks `fill("ab", 1)` (offset-aligned repeat),
a full-buffer repeat, and the empty-needle no-op against Node; numeric fill and
the string-search tests still pass. Built and verified on Mac (Apple Silicon).
