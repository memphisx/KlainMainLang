# ADR-00881: `any`-valued `Map.set` boxes its value into a NaN-box word

- **Relations**: `Implements TDD-00155`
- **Date**: 2026-09-11

## Context

`m.get(k) === null` on a `Map<K, any>` where `k` was set to `null` returned
`false` — the "any-equality: null boxed as `any` ≠ `null`" item on the backlog
(BACKLOG §4). Repro (macOS arm64):

```ts
const m = new Map<string, any>()
m.set('k', null)
console.log(m.get('k') === null) // printed false
```

The same map also mis-compared `any` numbers and booleans: `m.set('n', 5);
m.get('n') === 5` was `false`.

## Investigation

The emitted IR for `m.set('k', null)` stored the value as
`%v = ptrtoint ptr null to i64` — i.e. `0` — not the NaN-box null constant
`nbNull` (= 2). On the read side, `m.get('k')` returns the raw stored i64 typed
`any` (`mapValFromI64`, `emit_collections.go:929`, correct: `TypeAny.IR ==
"i64"`), and `=== null` boxes its `null` literal to `nbNull` via `emitBoxValue`
(`emit_dynamic.go:393`). So `__kml_any_eq(0, 2)` compared `0` against `2` and
returned false.

Root cause: the `set` method path (`emit_collections.go:345`) converts the value
argument with `valueToMapVal` (`:663`), which switches purely on the *value's*
IR shape — a `null` literal is `ptr`-shaped, so it took the `ptrtoint` arm — and
never consults `valTy`. When the map's value type is `any`, the value must first
be boxed into a NaN-box word so it round-trips by tag. Numbers/booleans hit the
same hole (stored raw, not tag-encoded). Strings were unaffected: the NaN-box
string encoding *is* the raw pointer, so a raw-stored string pointer already
matched.

The `new Map([...])` seed path (`:206`) was already correct — it loads
already-boxed `any` tuple fields — as are `Set<any>` and D1
dynamic-object/array reads from `JSON.parse` (all verified passing).

## Decision

In the `set` case, box the value when the map's value type is dynamic and the
incoming value is not already dynamic:

```go
if valTy.IsDynamic && !vVal.Ty.IsDynamic {
    vVal, err = e.emitBoxValue(vVal)
    if err != nil { return Value{}, err }
}
```

`emitBoxValue` is idempotent (returns an already-dynamic value unchanged), and
encodes `null`/`undefined`/bool/number/string/array by tag. `valueToMapVal` then
sees an `i64`-shaped dynamic value and passes the boxed word straight through.
This covers both string-key (`__kml_map_str_set`) and number-key
(`__kml_map_num_set`) maps, which share the `set` case.

## Implementation notes

- `codegen/llvm/emit_collections.go`, `set` case only. The read side and the
  seed path were already correct and are untouched.

## Side effects discovered

None. `Set<any>`, `new Map([...])` seeding, and D1 dynamic values were checked
and already boxed correctly.
