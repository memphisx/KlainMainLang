# ADR-01679: fdlibm Math, function-kind tags, FlatArray and function own keys

- **Date**: 2026-10-17

## Context

A declaration-coverage sweep found five places where Node's output differs from this compiler's:

- `Math.tan(1)` printed `1.557407724654902`, where Node prints `1.5574077246549023`.
- `util.types.isGeneratorFunction`, `isAsyncFunction` and `isGeneratorObject` returned `false` for real generator and async functions and for generator objects.
- `performance.timerify(add)` came back named `timed`, with length 0. Node names it `timerified add`, with length 2.
- klain:tui's `TextInput(text, { wrap: true })` was clipped to one line.
- `Array.prototype.flat` was declared to return `any`, because lib.es2019's `FlatArray<A, D>[]` result broke code generation's module-global pre-pass.

## Investigation

- **Math.**
  - V8, as shipped in Node 24 (13.6), computes its transcendental functions with its own fdlibm port (`src/base/ieee754.cc`), not the platform libm. Apple's libm and glibc each differ from it in the last bit for some inputs.
  - `Math.pow` is an exception. With V8's default `use_std_math_pow`, it calls the platform `std::pow`, which this compiler already uses.
  - Node's arm64 builds fuse multiply-adds inside fdlibm and its x86-64 builds do not, so Node's own bits differ between the two architectures.
- **Function-kind tags.**
  - `Object.prototype.toString` (`dynjson.c`, `__kml_object_tostring`) answered `Function` for every boxed function.
  - A generator object had neither a `Symbol.toStringTag` nor a tag row, so it printed as `{}`.
  - The function's metadata already records its kind (`fnmeta.c`, `FN_ASYNC`/`FN_GEN`/`FN_ASYNCGEN`).
- **timerify.**
  - Node's `timerify.js` defines `length` and `name` on the wrapper.
  - Doing the same here showed two more bugs:
    - a typed function's `name` and `length` read its own-property bag by its raw closure header, not through the adapter or box thunk wrapping it;
    - `Object.keys` of a function always returned `[]`.
- **TextInput.** The painter (`tui.go`) measured and painted `K_INPUT` as one line whatever `wrap` said.
- **FlatArray.** With the faithful declaration:
  - the checker lost a method's `this: A` parameter, because it resolved `A` outside the method's own type-parameter scope (`withThisParam`), and it never inferred a type parameter from the receiver;
  - code generation then typed a flattened mixed-depth array (`[[1, 2], [3, [4, 5]]].flat(2)`) as `number[]` through the checker. It stored the boxed elements unconverted, and read them back as doubles (`1.125, 2.25, …`).

## Decision

- **Math.**
  - `codegen/llvm/fdlibmsrc/fdlibm.c` ports V8 13.6's fdlibm. It exports `__kml_fd_<name>` for acos, acosh, asin, asinh, atan, atanh, atan2, cos, cosh, exp, expm1, log, log1p, log2, log10, sin, sinh, tan and tanh.
  - `lib/es.d.ts` lowers each of these Math members to its `__kml_fd_` function through the `fdlibm` runtime unit.
  - The file disables FMA contraction except on aarch64, so each host reproduces its own platform's Node.
  - `Math.pow` keeps the platform `pow`, as V8 does by default.
- **Tags.**
  - `__kml_fn_tag_dyn` gives a boxed function's tag from its kind.
  - Each generator layout registers a toStringTag row, through `__kml_generator_tag` or `__kml_async_generator_tag` in `shape.c`. Its member getter answers `Symbol.toStringTag`, and it is named `Object`, which gives `Object [Generator] {}`.
- **Function own properties.**
  - `fn_hdr_bag` resolves the own-property bag through `FN_THROUGH_ENV` adapters and `FN_THROUGH_BOX` thunks.
  - `Object.keys(f)` boxes the function and lists its bag's enumerable keys.
  - `timerify` defines `length` and `name` as `timerify.js` does.
- **TextInput.** A wrapping input measures and paints its wrapped lines. Its cursor follows the last line, or starts a new row when that line fills the width.
- **FlatArray.**
  - The checker:
    - `withThisParam` takes the signature's own type parameters (the interned key), so `this: A` resolves;
    - `inferArgsDetailRecv` unifies the `this` type with the receiver's type (`callRecv`).
  - Code generation: when `flat()`'s flattened element is boxed but the representation oracle gives a concrete element type, `flatCheckerType` lets the inference rule and the emitter both answer that type, and the emitter unboxes the elements (`emitUnboxAnyArray`).
  - `flat` is declared as lib.es2019 declares it, with the `FlatArray` type alias.

## Implementation notes

- `TestIRTextOnlyShrinks` caught the generator tag first written as an IR thunk. It is C in `shape.c` instead.
- `dynjson.c` gained three externs. The sidecar layout probe stubs them, and `sidecarExterns` lists them.

## Side effects discovered

- **Fixed in passing: goroutine shadow stack.** A klain:sync goroutine moves between threads at a safepoint or channel operation, and the optimizer keeps a thread-local's address across such a call. Two places then wrote the shadow stack's top and base into the previous thread's slots, and the scheduler later dereferenced a freed goroutine stack: `examples/goroutines/parallel_primes.ts` and `TestE2EGoroutineHTTPListenLoadTest` segfaulted on both hosts, found by ASan.
  - `KML_SWAPCONTEXT`'s restore is now `__kml_frame_resume`, out of line in `frames.c`.
  - In a program using klain:sync, every IR access to the two thread-locals goes through `__kml_frame_top_slot()`/`__kml_frame_base_slot()` (`frameSlot`). The heap-store check counts that slot as a global.
- **TS suite harness.** It now reads a case's `@experimentalDecorators` and `@emitDecoratorMetadata`. A case without the former compiles TC39 decorators, as tsc 5 does, instead of this compiler's experimental default (`tools/conformance/ts.go`, `node.go`).
- **Fixed in passing: own-method check with a nested literal.** A library call whose argument held a function literal (`{ cb: () => … }`) skipped the own-method check of [ADR-01644](ADR-01644.md). `spillFunctionLiteralArgs` now evaluates every argument up to the last one holding a literal, once and left to right, before either arm (`TestE2EOwnMethodNestedFunctionLiteralArg`). A spread ahead of such an argument still keeps the class's method in a library.
- **Fixed in passing: compat=js call-site inference.** A parameter's type inferred from its call sites skipped a `null` or `undefined` argument, so `f(null); f(undefined); f(1)` typed `v` as `number`, and `v === undefined` was false for `f(undefined)`. Such an argument now makes the parameter `any`, as an omitted one already did.

- `fdlibm.c` was checked against arm64 macOS Node and x86-64 Linux Node, but not against arm64 Linux. The compiler's fusing there could differ.

## Verification

- New tests, each compared with Node:
  - `TestE2EMathFdlibmBits`: 18 functions on edge inputs, called directly and passed as values;
  - `TestE2EFunctionKindTags`: tags, inspection and the `util/types` predicates;
  - `TestE2EFunctionOwnPropertiesKeys`;
  - `TestE2EArrayFlatFlatArray`;
  - `TestE2EDeclProcessHrtime`.
- `TestE2ETuiTextInputWrap` checks the wrapped rows.
- The port's harness compared 68,029 evaluations bit-for-bit with Node, with zero differences, on macOS arm64 and on linux/amd64 in Docker.
- `examples/goroutines/parallel_primes.ts` passes under ASan on macOS. The load test passed five repeated runs.
- On macOS (Apple Silicon): targeted runs of the math, flat, declaration, tag, function-property and TUI tests, plus every non-`tests` package.
