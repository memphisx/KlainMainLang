# ADR-00324: Node `net` TCP server

- **Relations**: Implements TDD-00006 (the select()-based event loop); Extends ADR-00322 (child_process fd-folding precedent)
- **Date**: 2026-08-23

## Context

`net` was the highest-leverage remaining gap on the "Other Node.js Core Modules"
page (NODE-CORE-MODULES.md): a raw TCP server is the base primitive under a
future standalone `WebSocket` server and the most broadly useful of the
unstarted modules there. The pieces it needs — a listening socket, an
accept loop, per-connection read pipes — all already exist in the codebase for
`http.listen`, but wired HTTP-specifically. The task was to expose them as a
general TCP surface without disturbing the shared event loop every http/timer/
fetch program depends on.

## Investigation

The event loop `@__kml_event_loop_run` (runtime_http.go) drives every fd-based
subsystem through a fixed **hook trio** called unconditionally each iteration:
`__kml_<sys>_keepalive` (i1, holds the loop open), `__kml_<sys>_fdset_add`
(ORs its fds into the read set), `__kml_<sys>_dispatch` (drains ready fds after
select()). worker/chan/cp/rl all follow it, each with a no-op stub in
`emitLoopTaskStubs` (runtime_task.go) that stands in when the subsystem is
unused. `child_process` (runtime_childprocess.go) was the closest precedent: a
process-wide handle registry, multiple per-handle non-blocking fds folded into
the set via the shared `@__kml_worker_fd_setbit`, and stored closure headers
the dispatch invokes directly (`call void %fp(ptr %ep, ...)`).

The POSIX socket declarations (`@socket/@setsockopt/@bind/@listen/@accept/
@htons/@fcntl`) are `emitGlobal`-deduped inside `ensureHTTPRuntime`, so they
are shareable; the bind/listen *logic* is not — it is inline in the
HTTP-specific `@__kml_http_bind_and_listen` (hardcoded backlog, HTTP error
throw, single-listener globals). So net reuses the decls and the platform
constant helpers (`httpSockConstants`/`httpSockaddrFamilyBytes`/
`httpNonblockFlag`) but emits its own bind-and-listen.

`net.connect` (client) was scoped out: it needs write-fd readiness inspection
after select(), and the loop currently populates the write/except fdsets only
for libcurl and never runs `FD_ISSET` on them for non-curl fds — a separate
piece of plumbing not worth coupling to the server work.

## Decision

Server-side `net` only, as a fourth hook-trio member:

- `net.createServer(connectionListener?)` → a `NetServer` handle (a ptr to
  `netServerIR = { i64 listenfd, ptr connListener, i64 closed }`). The listener
  is stored as a raw closure header, typed to receive a `NetSocket`.
- `server.listen(port, listeningCallback?)` calls `@__kml_net_bind_and_listen`
  (a copy of http's sequence: socket → SO_REUSEADDR → bind 0.0.0.0:port → listen
  → O_NONBLOCK; returns the fd or -1 rather than throwing), stores the fd, and
  fires the optional callback synchronously.
- `server.on('connection', listener)` is an equivalent way to set the same
  listener slot; `server.close()` closes the listen fd and marks the server.
- A connection socket (`netSocketIR = { i64 fd, i64 state, ptr dataL, ptr endL }`)
  supports `.on('data', cb)` (cb receives a Buffer), `.on('end', cb)`,
  `.write(data)`, `.end(data?)`.

Two process-wide registries (servers, connection sockets) mirror
`__kml_cp_*`. The hook trio: `keepalive` is true while any server listens or any
connection is open; `fdset_add` adds every listen fd and open connection fd via
`@__kml_worker_fd_setbit`; `dispatch` non-blocking-accepts pending connections
on each server (firing the connection listener with the new socket) and then
non-blocking-reads each open socket (firing 'data' with a fresh Buffer, or
closing + firing 'end' on EOF) — exactly the drain-until-EAGAIN shape of
`__kml_cp_drain`/`__kml_cp_dispatch`. Because every fd is non-blocking, dispatch
needs no `FD_ISSET` check: accept/read simply return EAGAIN when nothing is
pending.

## Implementation notes

- New `codegen/llvm/runtime_net.go` (runtime IR) and `emit_net.go` (codegen).
- The one edit into the shared loop IR (runtime_http.go) adds the net (and, in
  the same pass, dgram) trio to the keepalive OR-chain, the fdset block, and the
  dispatch block. The loop-integrity gate — the full existing http/childprocess/
  timer/worker suite — was run *before* adding any net-specific code, with the
  no-op stubs standing in, to isolate a loop-IR regression from a net bug.
- `usedNetRuntime` is added to `emitLoopTaskStubs`' stub guards and to
  `emitter.go`'s `useFullLoop` disjunction, so a net-only program invokes the
  full loop at program end.
- The connection listener's `socket` parameter is typed `NetSocket` via the
  hint passed to `resolveCallbackWithHints`, so `socket.on(...)`/`.write(...)`
  inside the listener body dispatch through `inferExprType` the same way a bound
  variable would.
- Listeners must be arrow/function-expression literals (the child_process
  posture), stored as `{ptr,ptr}` closure headers.

## Side effects discovered

None. `net.connect` (client sockets) and per-socket back-pressure/`drain` are
left unimplemented and disclosed as caveats on the status page.

## Verification

- `tests/net_test.go`: echo server, three independent connections (per-socket
  registry isolation), and the `server.on('connection')` registration path —
  all driven by Go's `net` package as the TCP client, the http_test.go posture.
- `examples/net/echo_server.ts` verified end-to-end on macOS (arm64): a Python
  pty harness confirmed the listen callback (`listening on 9099`), the echo
  (connection listener + data listener + write), and the end listener
  (`client disconnected`) all fire.
- Full `go test ./tests/` loop suite green after the shared-loop edit.
- Machine: verified on Mac (Apple Silicon). Not yet re-verified on Linux.
