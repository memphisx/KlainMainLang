# ADR-01765: An object pattern reads a key its source's layout lacks

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

`const { constructor } = new P()` and `({ constructor, message }) => …` over an Error failed to compile in both lanes ("object has no field 'constructor'"). `unpackObjectPatternInto` looked each key up in the source's static layout. `constructor` is not in the layout, though every object reaches it through its prototype. tsc accepts the pattern, and Test262 uses it to check a rejection's error kind in every async destructuring test.

## Decision

A key missing from the layout is read off the boxed source through the dynamic destructuring path (`unpackDynObjectPatternInto`), which reads a property as any dynamic read does, prototype included.

## Consequences

- `TestE2EObjectPatternInheritedKey` covers it.
- An `Object.prototype` method (`{ toString }`) still reads as `undefined`. `Object.prototype` holds none yet (backlog).
