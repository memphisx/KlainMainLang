# ADR-00810: `-package=rpm` / `rpm:harbour` — RPM package emitter (TDD-00146 Stage 2)

- **Relations**: `Implements TDD-00146`, `Extends ADR-00809`

- **Date**: 2026-09-09

## Context

TDD-00146 Stage 2 asks `-package` to grow an RPM shape so a cross-built Sailfish
CLI binary (ADR-00809) becomes an installable package. Sailfish distributes CLI
tools as plain RPMs (via Chum/OBS) and GUI apps under Harbour naming
(`harbour-<name>`, files under sanctioned paths), so the emitter needs both a
plain and a Harbour mode.

## Investigation

`-package` today (`packaging.go`, TDD-00142 Stage 4) is a bool that builds a
*host* bundle — `.app`/`.desktop`/`.exe` — gated on `runtime.GOOS`, because the
compiler builds for its host. RPM packaging is different in kind: it is a
*target* package that rides a `--target` cross build, so it must not be
host-gated and must derive its arch from the target, not the host.

`rpmbuild` expects a source tree and a `%build` step, but the binary is already
built. The prebuilt-binary spec pattern (`Source0` = the binary, empty
`%build`, `%install` just `install`s it) is the fit — plus
`%global debug_package %{nil}`, since rpmbuild would otherwise try to synthesize
a debuginfo subpackage from a prebuilt, stripped binary and fail.

The arch/triple work from ADR-00809 matters here: the exported Sailfish sysroot
proved the native triple is `aarch64-meego-linux-gnu` and the RPM arch is
`aarch64`.

## Decision

- **Flag**: `-package` becomes a bool-like `flag.Value` (`packageFlag`,
  `IsBoolFlag`). Bare `-package` keeps its meaning (host bundle); `-package=rpm`
  and `-package=rpm:harbour` select the RPM shapes. (The `=` form is required
  for the value — a space would not bind, given `IsBoolFlag`.)
- **`packaging_rpm.go`**: `writeRPM` lays down an `rpmbuild` tree
  (`SPECS/SOURCES/BUILD/BUILDROOT/RPMS/SRPMS`) next to the binary, stages the
  binary as `Source0` under the package name, writes the `.spec`, and runs
  `rpmbuild -bb --define "_topdir …" --target <arch>` **when `rpmbuild` is on
  PATH** — otherwise it writes the spec + tree and prints the exact `rpmbuild`
  command to run elsewhere (so a Mac emits, a Linux/SDK host builds).
- **Naming**: plain → `<slug>` at `/usr/bin/<slug>`; Harbour →
  `harbour-<slug>` at `/usr/bin/harbour-<slug>`, plus a `.desktop` +
  `108x108` hicolor icon under the sanctioned `%{_datadir}` paths **when an icon
  is supplied** (a GUI app); a CLI Harbour package is just the renamed binary.
- **Private-library bundling (Harbour)**: link libraries not on the Harbour
  allowed-list — pcre2 today (`harbourBundledLibs`) — are shipped app-privately.
  Their SONAME file is copied out of the `--sysroot` into
  `/usr/share/harbour-<name>/lib/` (found by `findSonameInSysroot`, matching
  `lib<name>.so.<major>` so the DT_NEEDED is satisfied), and the binary is
  linked with `-Wl,-rpath,/usr/share/harbour-<name>/lib` at the *original* link
  step (main.go, before the packaging block, since rpath is a link-time
  property). libcurl/OpenSSL/libstdc++/pthread/libm are Harbour-allowed and stay
  system libraries; bdw-gc (`-mm=gc`) is also not allowed but links via LocateGC
  rather than the requireLink list, so it is a separate future addition.
- **Arch**: from the `--target` triple's arch field (`aarch64-meego-linux-gnu`
  → `aarch64`), or the host `runtime.GOARCH` mapped to the RPM spelling for a
  host build.
- **License**: new `-app-license` flag (RPM requires the tag), default
  `Proprietary`; `-app-name`/`-app-version`/`-app-icon` are reused.
- Not host-gated, and no webview requirement (CLI tools are the primary case).

## Implementation notes

- `buildRPMSpec` and `buildRPMDesktopEntry` are pure string builders (unit
  tested without rpmbuild). `resolvePackageOptsRPM` validates the icon as `.png`
  host-independently (it is a target artifact, unlike the host bundle's
  GOOS-specific icon rule).
- `crossTriple` is hoisted to function scope in `main.go` so the packaging block
  (which runs after codegen/link) can read the resolved triple for the arch.
- Only `.so.N` runtime libs exist in a device rootfs; a proper SDK *target*
  sysroot (with `-devel`) carries the `.so` symlinks feature-lib linking needs
  (noted on ADR-00809). RPM packaging itself is unaffected — it wraps the
  already-linked binary.

## Side effects discovered

None. The Go `flag` package wraps a bool-like `Value`'s `Set` error as
"invalid boolean value …" — the specific message still shows through, so a bad
`-package=` value is reported clearly.

## Verification

- `packaging_rpm_test.go`: pure-builder tests for plain vs Harbour specs
  (names, `/usr/bin` paths, icon/desktop lines, `debug_package %{nil}`), the
  arch mapping, the package-name rule, the `.png` icon guard, and a
  structural `writeRPM` test (stub binary → spec + staged source + tree; robust
  to rpmbuild's presence).
- End-to-end on the arm64 lane (native, not emulated): `klainmain --target
  sfos-aarch64 --sysroot=<exported 5.1.0.11 rootfs> -package=rpm:harbour …`
  cross-compiled *and* packaged in one command, producing a valid
  `harbour-klaingreeter-1.2.0-1.aarch64.rpm` (correct Name/Version/Arch/License,
  `%files` = `/usr/bin/harbour-klaingreeter`).
- On real hardware: the RPM was read by the **device's own Sailfish `rpm`**
  (Xperia 10 II, OS 5.1.0.11) — metadata + file list correct — and the binary
  extracted from it (`rpm2cpio | cpio`) ran on-device (`Hello, Sailfish!` /
  `linux/arm64`, exit 0). A system install was not attempted (needs root). (Mac
  + arm64 Docker + device.)
- **Private-lib bundling**: a RegExp program packaged `-package=rpm:harbour`
  against the exported Sailfish sysroot produced an RPM containing both
  `/usr/bin/harbour-rxdemo` and `/usr/share/harbour-rxdemo/lib/libpcre2-8.so.0`,
  with the binary carrying `RUNPATH /usr/share/harbour-rxdemo/lib` resolving
  `NEEDED libpcre2-8.so.0` (readelf-confirmed). Install-time rpath isolation
  from the system pcre2 was not exercised (needs a root install). (arm64
  Docker.)
