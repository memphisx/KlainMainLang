# ADR-00626: Dual-compat conformance lanes (strict baseline + `-compat=js`)

- **Relations**: `Extends TDD-00121 (the conformance runner), ADR-00624, ADR-00625`
- **Date**: 2026-09-02

## Context

The conformance corpora (Node `test/parallel`, Test262) are untyped vanilla
JavaScript — exactly the surface `-compat=js` targets. With the TDD-00022
work landing, a single strict-lane score can no longer show what that work
buys (or catch a JS-mode-only regression). The runner also quietly ran a
*mixed* mode: resolver-side permissive (ADR-00472) with an emitter-side
strict compat — now made explicit.

## Decision

`tools/conformance` gains `-compat=strict|js|both` (default strict; a
`laneCompat` package global mirrors the `regexModeFlag` pattern — lanes run
strictly sequentially). Both emitter sites set `SetCompatMode(laneCompat)`;
the resolver-side permissive bool stays `true` in both lanes (both oracles'
referents allow global shadowing — the lane axis is the emitter semantics).

The Node suite supports `both` (and `make conformance-node` now uses it):
the corpus runs twice, and one report carries both Overall scores, the
per-file pass deltas (`passing only under -compat=js` / `-strict`), and
detail tables from the js lane — the representative surface for an untyped
corpus, with strict as the regression baseline. Test262/TS accept
strict-or-js single-lane runs, labeled in the report.

First dual measurement (2026-09-02): 45 = 45, zero pass delta — but the
failure-reason histogram shifts under js (11 fewer `a number has no method`,
fewer `no field`), i.e. inference advances files to their *next* wall. The
delta list is the direct metric for when the vanilla-JS work starts landing
whole files.

## Consequences

- `make conformance-node` takes ~2× (two lanes), still ~minutes.
- Report format change: dual Overall + delta lists; single-lane runs keep
  the historical shape plus a lane label.
- `-compat=both` for Test262/TS is a follow-on if wanted; those runs are
  occasional and can be launched once per lane meanwhile.
