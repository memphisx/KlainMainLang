# ADR-01221: The legacy url API is Node's lib/url.js in TypeScript

- **Relations**: `Implements TDD-00230`, `Implements TDD-00231`
- **Date**: 2026-09-29

## Context

TDD-00230 P3.1 declares the Node modules. Declaring `url` exposed the
legacy API's codegen as a partial reimplementation:

- `url.format({ protocol: "https", hostname: "h.test", pathname: "/x" })`
  returned `https/x`: no `//`, and the hostname was ignored.
- `url.parse` and `url.resolve` sat on libcurl's URL parser, whose rules
  are the WHATWG ones, not lib/url.js's.

TDD-00231 already lets a builtin module's members live in a TypeScript
companion (`lib/node/internal_<name>.ts`).

## Investigation

- Node v24's lib/url.js is plain JavaScript over `querystring` and
  `internal/idna`. Its `Url` class, `urlParse`, `urlFormat`, `urlResolve`
  and `urlResolveObject` port to TypeScript with only type annotations and
  a few null guards.
- `url` is a global-reexport module (`URL`, `URLSearchParams` are the
  globals). The resolver's reexport path bound a default or namespace
  import to the codegen marker only, and never looked at a companion.
- `urlParse` warns once with DEP0169, from `parse`, `resolve` and the
  string form of `format` alike.
- `domainToASCII` is ada's host parser in Node: it lowercases ASCII
  letters. The codegen form returned `Example.COM` unchanged.
- `process.emitWarning(message, type, code)` (the positional code) was a
  compile error.

## Decision

- `lib/node/internal_url.ts` is lib/url.js's legacy API: `Url` (`parse`,
  `format`, `resolve`, `resolveObject`, `parseHost`), `parse`, `format`
  (a `Url`-shaped object, a string, or a `URL` with `URLFormatOptions`),
  `resolve`, `resolveObject`, and the `UrlObject`/`URLFormatOptions`
  types. It calls the codegen `domainToASCII`/`domainToUnicode`, the same
  IDNA backend as the `URL` class.
- The resolver binds a global-reexport module's companion as it does a
  virtual module's (`companionMangled`): a named import of a companion
  export resolves to it; a default or namespace import reads companion
  members through the namespace.
- `parse`/`format`/`resolve` leave the codegen member table, the
  `declare module "url"` block and codegen (`emitUrlParse`,
  `emitUrlFormat`, `emitUrlResolve`, `LegacyUrlType` deleted).
- `domainToASCII`/`domainToUnicode` lowercase the ASCII letters of the
  result.
- `process.emitWarning` takes the positional `code` (and evaluates a
  `ctor` fourth argument, which only positions a stack trace).

## Implementation notes

`lib/node/internal_url.ts` (new), `lib/node.d.ts`,
`resolver/resolver.go`, `resolver/virtual_modules.go`,
`codegen/llvm/emit_url.go`, `emit_call.go`, `emit_exprs_types.go`,
`types.go`, `emit_process.go`.

## Side effects discovered

- Compiling the companion hung the binder: ADR-01222.
- The checker did not type regex literals or `Array`'s index signature:
  ADR-01223.
- An object literal passed through a union into a dictionary-typed field
  crashed, and a string field and a dictionary field shared a layout:
  ADR-01225.
- A non-ASCII hostname in `url.parse` needs the IDNA backend, which the
  Mac's libcurl lacks (the existing `domainToASCII` caveat): there it
  throws `Invalid URL`.
- Node's `(Use \`node --trace-deprecation ...\`)` hint line is not printed:
  the flag does not exist here.

## Verification

Mac (Apple Silicon), against Node v24.19: `TestE2EUrlLegacyParse`,
`TestE2EUrlLegacyFormatResolve`, `TestE2EUrlLegacyDeprecationWarning`,
`TestE2EProcessEmitWarningPositionalCode`; `examples/url/*.ts` print the
same as Node.
