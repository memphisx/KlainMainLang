# ADR-00961: Streamed `res` write backpressure — fiber park-on-writable

- **Relations**: `Implements TDD-00195` (Stage 2 backpressure). Extends `ADR-00959` (incremental `res` Writable), `ADR-00960` (binary chunk framing).
- **Date**: 2026-09-15

## Context

The incremental `res` Writable (ADR-00959) framed each `res.write` chunk to the
socket with a *blocking* `write()` (`__kml_res_begin` cleared `O_NONBLOCK` for
the stream's lifetime). A slow-consuming client whose kernel receive window
filled therefore blocked the server's OS thread inside that `write()` — and
because every connection fiber shares the one reactor thread, one slow client
**stalled the entire server**: no other connection, timer, or task made progress
until the slow socket drained. That is the server-wide defect behind the "no
socket-level backpressure/`'drain'`" caveat.

The faithful Node contract has two observable parts: (1) a slow client must not
block other work — writes proceed asynchronously; (2) `res.write` returns `false`
past `highWaterMark` and a `'drain'` event fires later while the handler
continues. Part 1 is the actual harm; part 2 is the literal event contract.

## Decision

Ship **part 1** now (Layer A): non-blocking chunk writes that park the *writing
fiber* on socket writability instead of blocking the reactor. Part 2 (the
observable `write()===false` + async `'drain'` event, with a per-response output
queue) is deferred to its own stage (Layer B) — recorded in `docs/status` /
BACKLOG, not silently dropped.

- **`__kml_res_write_all(fd, buf, len)`** replaces the raw `write()` calls in the
  sink: it loops writing the remaining bytes; on `EAGAIN` over a non-blocking fd
  it marks the fd in a new `@__kml_conn_writepark` bitset and `swapcontext`s back
  to the reactor, then — on resume — clears the bit and retries. Short writes are
  handled by the same loop. Over a blocking fd the `EAGAIN` branch is inert, so
  it degrades to a plain blocking write.
- **`__kml_res_begin`** sends the (tiny) chunked head over a blocking fd so the
  head can't partial-write, then re-enables `O_NONBLOCK` for the chunk-write
  lifetime on **plain HTTP**. **HTTPS/1.1** keeps the socket blocking (streamed
  TLS write backpressure is not validated — keep-alive re-arm is already forced
  off there), so its chunk writes stay blocking and never park.
- **The reactor** (`__kml_event_loop_run`): when building each iteration's
  fd_sets it adds any write-parked connection fd to `select()`'s **write**
  fd_set (the `%wfdset` that already exists for libcurl); the resume scan then
  resumes a fiber whose fd came back **writable**, in addition to the existing
  readable/poke resume conditions. Only write-parked fds are ever added to the
  write set, so a non-parked fd's writable bit is never spuriously set.

## Implementation notes

- `@__kml_conn_writepark` is an fd_set-shaped `[128 x i8]` bitset (1024 fds,
  matching the read fd_set), thread-local like the rest of the reactor state. It
  is addressed by the global's fixed address, so the park site's byte pointer
  survives the `swapcontext`.
- The park's `swapcontext` mirrors the read-loop yield exactly: it relies on the
  *resumer* (`__kml_event_loop_run`'s `rresume`) to restore `GC_stackbottom`, so
  no GC bookkeeping is needed at the park site itself.
- A spurious resume (the fd came back readable, or a completed-task poke) is
  benign: the write is re-attempted and re-parks if it still `EAGAIN`s — the same
  self-correcting property the read-wait path already has.
- `SIGPIPE` is still not ignored process-wide: a client that disconnects
  mid-stream can `SIGPIPE`-kill the server on the next `write()`. This is
  pre-existing (it affects every write path, buffered and streamed alike), out of
  scope here, and recorded as a follow-up.

## Verification

macOS arm64 (M4): `go vet` clean. New E2E tests:
`TestE2EHTTPCreateServerResStreamBackpressure` (a slow client parked mid-stream
does **not** stall a second client's quick request — the definitive proof; would
hang under the old blocking write) and `…ResStreamLargeBodyIntact` (a ~64 KB
body streams byte-for-byte intact across park/resume cycles). Existing
`res.write`/`res.end`/binary/`req.pipe(res)`/keep-alive tests still pass. Full
HTTP/HTTPS/HTTP2/WebSocket/net/fetch/streams/fs/worker/timer suites green
(exit 0). Example `res_stream_backpressure.ts` streams 2 MB intact. No new
invalid IR (http paths, not Test262-exercised; `make test-par` is the gate).
