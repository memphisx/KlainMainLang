# ADR-00564: ArrayBuffer.resize() supports shrinking

- **Relations**: Extends ADR-00494
- **Date**: 2026-09-01

## Context

ADR-00494 added resizable `ArrayBuffer`/growable `SharedArrayBuffer` backed by a
block reserved at `maxByteLength` up front, with `grow`/`resize` bumping a
length word. Both methods shared one emitter (`emitBufferGrow`), which rejected
any new length below the current length. That is correct for
`SharedArrayBuffer.grow` (the spec forbids shrinking a growable SAB) but wrong
for `ArrayBuffer.resize`, whose spec explicitly allows shrinking. The status
page disclosed the extend-only limitation as a caveat.

## Decision

Thread an `allowShrink` flag into `emitBufferGrow`, set from the method name at
the call site (`resize` → true, `grow` → false):

- `grow` (allowShrink=false): reject `new < current` **or** `new > max` — a
  growable buffer only grows.
- `resize` (allowShrink=true): reject `new < 0` **or** `new > max` — any length
  in `[0, maxByteLength]` is legal, in either direction.

Because the backing block is already reserved at `maxByteLength`, shrinking is
just a smaller length word; the bytes beyond the new length stay allocated but
unreachable, and a later grow back up re-exposes them (zero-initialized at
construction). No view is ever invalidated by the buffer moving.

## Implementation notes

- Only `emitBufferGrow` and its one call site changed. The throw message is now
  method-specific (`ArrayBuffer.resize: … negative or above maxByteLength` vs
  the existing SAB grow message).

## Side effects discovered

A TypedArray view captures its length at construction and does not length-track
a later `resize` — the spec auto-tracks a view created without an explicit
length. This pre-existing view-length model is unrelated to the shrink fix but
is now reachable (a shrink followed by a stale-view read), so it is disclosed as
the row's residual caveat: re-`new` the view after resizing.

## Verification

New `TestE2EArrayBufferResizeShrink` (grow, shrink, grow-again, over-max throw,
and a SharedArrayBuffer shrink still throwing) plus the existing
`TestE2EGrowableBuffers` pass. Built and verified on Mac (Apple Silicon).
