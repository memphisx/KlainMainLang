# ADR-00807: Per-listener HTTP/2 + coexistence edges — TDD-00191 Stage 4

- **Relations**: `Implements TDD-00191`, `Extends ADR-00803`, `Extends ADR-00805`, `Extends ADR-00806`

- **Date**: 2026-09-09

## Context

The final TDD-00191 stage: per-listener HTTP/2 (h2c and h2-over-TLS) so an
additional server can be an HTTP/2 server, plus deciding the `klain:http`/cluster
coexistence and confirming the shared `select()` fd ceiling. Before this, the h2
server bridge (`__kml_h2_dispatch` + the response getters) was a fixed set of C
symbols emitted only for the primary server; the C nghttp2 driver
(`http2src/http2.c`) called them by name, so every h2 connection — on any
listener — ran the primary's handler. That routing is what blocked multiple h2
servers.

## Investigation

The h2 request/response bridge is defined in IR (`buildHTTP2Bridge`) and called
from C (`on_frame_recv`). The block gap was purely the fixed symbol names: the C
driver had no per-connection hook to reach a different server's handler. The
connection already carries per-connection transport state (`h2_conn`: fd + the
TLS read/write shims), so a per-connection dispatch pointer fits the same
structure. Threading a function-pointer vtable through the session is far less
invasive than any name-based scheme and leaves the response lowering fully static
(each server emits its own specialized bridge).

The accept side mirrors the ADR-00806 HTTPS work: h2c is detected in the
dispatcher (already per-server), so an additional `http2.createServer` needs no
runtime change beyond the vtable; h2-over-TLS negotiates via ALPN at accept time,
so an additional `http2.createSecureServer` needs the drive in the
extra-listener accept path with the listener's vtable.

## Decision

**Per-server h2 bridge via a C dispatch vtable.**

- `http2.c` gains an `h2_disp_vtbl` (the 7 bridge fn pointers); `h2_conn` carries
  a `const h2_disp_vtbl *disp`; `__kml_h2_session_server_new` takes it; and
  `on_frame_recv` calls through `c->disp->…` instead of the fixed globals.
- IR: `buildHTTP2Bridge(…, sfx)` emits a suffixed bridge set per server plus an
  `@__kml_h2_vtbl{sfx}` constant of their addresses. Every dispatcher emits its
  own (keyed by `curDispatchSfx`); every `session_server_new` call passes the
  matching vtable (the h2c divert uses the dispatcher's suffix; the primary
  secure drive uses `@__kml_h2_vtbl`; the extra-listener drive uses the
  listener's).

**h2c multi-instance.** An additional `http2.createServer` already runs its own
suffixed dispatcher; with the per-server vtable its h2c divert now routes to its
own handler. No runtime change.

**h2-over-TLS multi-instance.** The extra-listener table entry grows to
`{ fd, dispatch, tlsctx, h2vtbl }` (32 B); the `Server` handle to 48 B (slot 5 =
its `@__kml_h2_vtbl{sfx}`). `http2.createSecureServer` hands its ctx + h2 marker
to the handle builder (an additional one keeps ctx out of the primary's global);
`listen` passes both to `register_extra_listener`. In `xl_accept`, a TLS accept
whose ALPN selects "h2" is driven as an inline nghttp2 session with the
listener's vtable (mirroring the primary secure branch); otherwise it is served
as HTTP/1.1 over the SSL shims, or dropped when the program has no HTTP/1.1 path
(Node's `allowHTTP1:false` default). A whole-program pre-scan
(`programUsesH2TLSServer`) wires the secure-h2 path before Pass 2, same ordering
fix as ADR-00806; the shared `@__kml_http_tls_ctx` global is emitted through a
single dedup (`ensureHTTPTLSCtxGlobal`).

**Coexistence edges (decisions).**

- **`klain:http` / cluster.** `klain:http`'s `http.listen` (and its
  `{ workers }` cluster fork) is the single blocking model; it sets
  `httpListenCallSeen`, and a Node `createServer` in the same program is rejected
  either way. Mixing the two stays a clean rejection — cluster runs the blocking
  klain:http path, not the Node multi-server reactor. This matches the TDD's
  leaning; SO_REUSEPORT-per-worker × N-listeners is not pursued.
- **`select()` fd ceiling.** The documented ~384-socket reactor ceiling
  (TDD-00182, a Windows-reactor limit) now spans every listener fd plus every
  live connection fd across all servers in the process — the accounting is the
  same shared read set, just with more listener fds in it. No new mechanism;
  documented so the many-listener case's headroom is understood.

This completes TDD-00191.

## Implementation notes

- The `h2_conn` vtable is set once at session creation; the primary and every
  additional server pass a stable per-server `@__kml_h2_vtbl{sfx}` constant.
- `xl_accept`'s TLS block is now a Go-built string with `has1`/`hasH2` variants:
  1.1-only (ADR-00806), h2-only (drop non-h2), or both (ALPN routes h2 vs 1.1).
- The `Server` handle grew 40→48 B and the extra-listener entry 24→32 B; the
  `calloc`/`realloc` sizes were bumped in lockstep.

## Side effects discovered

None. The vtable refactor is transparent to single-server h2 (the primary passes
its own `@__kml_h2_vtbl`); all existing h2c / h2-secure / allowHTTP1 tests pass
unchanged.
