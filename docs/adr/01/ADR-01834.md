# ADR-01834: An assigned function's context, and its call result

- **Relations**: `Implements TDD-00230` (P3.3: the checker answers what inferExprType did)
- **Date**: 2026-10-20

## Context

- In the full shadow report, async-arrow Test262 files left a call unanswered: `var ref; ref = async (a) => {…}; ref(false).then(…)`. Under it were two checker faults and one strict-lane gap.
  - **A cycle.** The arrow's contextual type was the target's declared type. For an auto-typed binding (`let f;`, no annotation, no value) that is its storage type, which is built from this very arrow, so the cycle guard left both unanswered.
  - **An unanswered parameter.** An arrow assigned to a name had no known call sites, and nothing else typed its unannotated parameter. Under checkJs that parameter is `any`, and codegen already held it so.
  - **A missing diagnostic.** The strict lane treated every assigned function as contextually typed. tsc reports TS7006 for `let f; f = (a) => a` and for `let h: any; h = (a) => a`: only a function type gives an assigned function context.

## Decision

- An auto-typed binding gives an assignment no contextual type.
- An arrow or function expression assigned to a name takes `any` for a parameter with no other type in the JS lane, as a method's or a returned function's does.
- An assigned function's parameters are contextually typed only through a function type, or a union with a function member (`let sink: F | null`), as tsc takes the signature from it. A name whose type the checker knows gives no context otherwise (TS7006). A target the checker cannot type yet (a builtin host's handler property such as `Worker.onmessage`) keeps the lenient answer, so no tsc-valid program is rejected.
- The oracle types a call through a name the checker cannot type from what codegen holds the name as: a box's call is `any`, a function value's is its return.

## Consequences

- The async-arrow call rows disappear. The strict lane rejects the two TS7006 programs tsc rejects, and no example under `examples/`, `tools/` or `lib/` gains an implicit-any error (scanned on Linux x86-64, Node304).
- Verified on Apple Silicon (checker unit tests and 122 JS-lane E2E tests), and with the gate on Linux x86-64 (DeskMini).
- Left open: a builtin host's handler property is not typed yet, so assigning a function with an unannotated parameter to one is accepted whether or not tsc would give it context.
