# ADR-00528: Array→string coercion (`String(arr)` / `` `${arr}` `` / nested `.join()`)

- **Relations**: Extends ADR-00152; Implements TDD-00029
- **Date**: 2026-08-31

## Context

An array had no string coercion at all: `String([1,2,3])`, a `` `${arr}` ``
template interpolation, and `Array.prototype.toString` all hit
`emitValueToString`'s `default` case and failed with "cannot convert type ptr
to string in template literal". Only `arr.join(sep)` produced a string, and it
rejected a nested-array element (`number[][]`). Real JS coerces any array to a
comma-joined string of its `String()`-ed elements, recursively for nesting —
`String([[1,2],[3,4]])` is `"1,2,3,4"`.

## Investigation

`emitArrayJoin` (`codegen/llvm/emit_arrays_sort.go`) already stringified each
element via `emitValueToString` and concatenated with a separator — it was
exactly `Array.prototype.toString` with a `","` default separator, minus
nested-array support (it did a raw `load elemTy.IR` and called
`rejectNestedArrayElem`). `emitValueToString` (`emit_exprs_types.go`) already
had a parallel `IsTuple` branch (`emitTupleToString`) doing the fixed-arity
version. Arrays reaching `emitValueToString` currently *error*, so adding a
branch can only improve — no working path routes an array through the failing
`default` today.

## Decision

1. Extract `emitArrayJoin`'s loop into `emitArrayJoinCore(ptrReg, lenReg,
   elemTy, sepVal)`, load elements through `loadArrayElem` (which transparently
   unboxes a nested-array element's box pointer to a real `{ptr,i64}`
   aggregate), and drop the `rejectNestedArrayElem` guard. A nested element is
   then stringified by `emitValueToString`, which recurses back into the array
   branch below.
2. Add an `IsArray` branch to `emitValueToString`: `extractvalue` the
   `{ptr,i64}` aggregate and call `emitArrayJoinCore` with the default `","`
   separator.

This single core now backs `arr.join(sep)`, `String(arr)`, `` `${arr}` ``, and
any other `emitValueToString` caller, with arbitrary nesting depth.

## Implementation notes

`emit_arrays_sort.go` (refactor + nested load) and `emit_exprs_types.go` (the
new branch). Recursion terminates on array nesting depth, which is finite and
statically known per this compiler's fixed-shape array types.

## Side effects discovered

`.indexOf()`/`.includes()`/`.sort()`/`Object.groupBy()` still reject a
nested-array element — they compare/bucket a bare register rather than routing
through a per-element stringify/callback, a separate concern (ADR-00152). The
Array-methods Fidelity Gap row is narrowed accordingly, not removed.

## Verification

`TestE2EArrayToStringCoercion` (new): `String(arr)`, `` `${arr}` ``, nested
`.join("-")`, `String` of a 2- and 3-deep nested array, and an empty array —
outputs cross-checked against real Node (`"1,2-3,4"`, `"1,2,3,4"`, etc.). The
`join` case was removed from `TestE2ENestedArrayHOFRejectedCleanly`. Existing
array/string/tuple/template suites pass. Verified on Mac (Apple Silicon).
