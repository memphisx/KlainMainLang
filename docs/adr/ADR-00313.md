# ADR-00313: `BigInt64Array`/`BigUint64Array` and `Uint8ClampedArray` — the TypedArray store/load conversion layer

- **Relations**: Implements [TDD-00101](../tdd/TDD-00101.md); extends [ADR-00078](ADR-00078.md), [ADR-00308](ADR-00308.md)
- **Date**: 2026-08-23

## Context

TDD-00018 excluded the three TypedArray variants whose element semantics differ from "stored scalar == surfaced scalar." With bigint shipped (and ADR-00312's u64 ABI half), all three could be built on the existing flagged-`ArrayOf` representation.

## Investigation

Element traffic turned out to flow through a small set of choke points: indexed assign (`emit_exprs_assign.go`), indexed read (`emit_exprs_member.go`'s `emitIndex`), the construction forms and `.set` (`emit_arraybuffer.go`), `.fill` (`emit_arrays_transform.go`), `.at`, `.map`'s result store (`emit_arrays_hof.go`), and the for-of array loop (`emit_stmts.go`). Everything else (HOF callbacks, search comparisons, sort, join, iterator objects) passes raw scalars — wiring bigint wrap/unwrap through all of it was judged disproportionate.

## Decision

Per TDD-00101: elem kinds `bigint64`/`biguint64`/`uint8clamped` map to i64/u64/u8 **storage** (stride machinery untouched); new `BigIntElem`/`Clamped` flags on `Type` drive two conversion helpers — `coerceTypedArrayStore` (bigint unwrap with a compile-time `IsBigInt` requirement; or the spec's ToUint8Clamp: int clamp via icmp+select, float NaN→0 + clamp + `llvm.roundeven.f64` + `fptoui`) and `wrapTypedArrayLoad` (bigint wrap) — called at each choke point. BigIntElem arrays reject every unlisted array method at a single dispatch guard (`bigIntElemRejectedMethods`, emit_call.go) so nothing can silently surface a raw i64 as a bigint; supported: indexing r/w, `.length`/`.byteLength`, `.at`, `.set`, `.subarray`, `.slice`, `.fill`, `.reverse`, for-of, `Atomics.*`. Atomics' integer check now admits i64 receivers, converting operands/results through the same helpers (the spec includes BigInt64Array). `Uint8ClampedArray` has no method restrictions — reads are plain u8; only stores differ (including compound assignment and `.map`'s result store).

## Implementation notes

`types.go` (flags, kind map, `TypedArrayType`, annotation names), `parser/parser_literals.go` (constructor names), `emit_arraybuffer.go` (helpers + construction/`.set`), `emit_exprs_assign.go`, `emit_exprs_member.go`, `emit_arrays_transform.go` (`.fill`/`.at`), `emit_arrays_hof.go` (`.map`), `emit_stmts.go` (for-of binds the loop variable as bigint), `emit_atomics.go`, `emit_exprs_types.go`. `.subarray`/`.slice` results preserve the receiver's `BigIntElem`/`Clamped` flags — dropping them made a for-of over `bigs.subarray(...)` print raw scalars, caught during verification. `emitAtomicsElemPtr` now also returns the receiver's array type; `wait`/`notify` stay Int32Array-only (spec's BigInt64 wait half not implemented — no use case without `waitAsync`).

## Side effects discovered

`console.log` of a *whole* BigInt64Array prints raw i64 element values (no `n` suffix) — the array inspector is elemTy-generic. Disclosed as a status caveat; single-element reads print correctly.

## Verification

`TestE2EBigInt64ArrayBasics`/`Atomics`/`Rejections`, `TestE2EUint8ClampedArray` (clamp values diff-checked against Node: `[-1, 300, 254.5, 255.5, NaN, 2.5, 3.5]` → `[0, 255, 254, 255, 0, 2, 4]`, round-half-to-even confirmed). `llvm.roundeven.f64` verified accepted by Mac clang (darwin/arm64); Linux unverified — the `llvm.rint` fallback noted in TDD-00101 if it ever rejects. Examples extended in `examples/typedarrays/`. Full `go test ./...` green (darwin/arm64).
