# ADR-01654: Strings are read to their length at the console, in JSON.parse and in Response.text()

- **Relations**: Implements [TDD-00230](../../tdd/TDD-00230.md) (P3.3, the bare-string producers); builds on [TDD-00120](../../tdd/TDD-00120.md), [ADR-01075](ADR-01075.md), [ADR-00094](../00/ADR-00094.md)
- **Date**: 2026-10-16

## Context

Three consumers stopped at a string's first NUL byte where Node reads the
whole string:

- `console.log(s)` printed through `printf("%s")`;
- `JSON.parse` bounded its input with `strlen`, so `{"a":1}\0junk` parsed,
  and a decoded `\u0000` cut the projected string short;
- `Response.text()` and `.json()` copied the body with `strlen`, and
  `.text()` did no UTF-8 decoding.

The console fix waited on every runtime string carrying its length header
(ADR-01075). A probe logged every `__kml_str_len` read whose header
disagreed with the bytes across the full E2E suite (4150 tests) and found
none, so no producer hands out a headerless string.

## Decision

- `console.log`/`console.error` write a string under a `%s`-plus-literal
  format with `__kml_write_str` (strheader.c): `fwrite` of the header
  length on stdout, sharing printf's buffer, and `write` on fd 2, as
  `dprintf` does. The emitter keeps a reverse map from interned string
  references to their text to recognize the format.
- `__kml_json_parse` ends the input at the header length. The string
  decoder records each decoded length (`str_len`), and
  `__kml_json_string_dup` copies that many bytes.
- `Response.text()` decodes `bodyLength` bytes with the WHATWG UTF-8
  decoder `buf.toString()` uses (`__kml_buf_utf8_str`), after dropping a
  leading UTF-8 BOM as TextDecoder does.

## Consequences

- `TestE2EConsoleLogEmbeddedNul`, `TestE2EJSONParseEmbeddedNul`,
  `TestE2EFetchTextKeepsEmbeddedNullByte` and `TestE2EFetchTextDecodesUTF8`
  match Node; the test that pinned `.text()`'s truncation is replaced.
- The console.log and Response rows carry no caveats.
