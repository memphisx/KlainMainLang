# TDD-00253: `--static` builds are self-contained

- **Status**: In Progress
- **Date**: 2026-10-13

## Context

`--static` means "fully static" on Linux (a scratch-image binary) and is
refused on macOS. On Windows it links some feature libraries statically
(the curl chain, pcre2, c-ares, winpthread, libuv), yet a `--static` build
of a program using `node:sqlite` and `BigInt` imports `libsqlite3-0.dll`
and `libtommath-1.dll` (measured, Windows 11), and Brotli and Zstd load
their DLLs at run time (`klainzlib.c`), so a `--static` binary copied to a
clean Windows machine fails to start, or fails at its first `brotli*`
call. The help text still says "Linux only".

What a user wants from `--static` on a desktop OS is a binary that depends
on nothing the OS does not ship. Linux keeps its fully static meaning.

## Design

**The promise.** A `--static` binary imports only libraries the OS ships:
on Windows the UCRT (`api-ms-win-crt-*`) and system DLLs (`KERNEL32`,
`WS2_32`, `ADVAPI32`, `bcrypt`, `CRYPT32`, …); on macOS `libSystem` and
system frameworks; on Linux nothing (fully static, unchanged).

**Windows.**

1. Every feature library links from its archive under `--static`:
   sqlite3 and tommath join pcre2 and c-ares (`winStaticFeatureLibs`), as
   `libsqlite3.a` and `libtommath.a` ship in the ucrt64 sysroot.
2. Libraries loaded at run time are linked instead under `--static`:
   `klainzlib.c` compiled with `KZ_STATIC` takes Brotli's and Zstd's
   entry points from the link (`-l:libbrotlienc.a -l:libbrotlidec.a
   -l:libbrotlicommon.a -l:libzstd.a`) rather than `LoadLibraryA`. Without
   `--static` they stay optional and run-time loaded, as today.
3. A guard test builds a feature-heavy program `--static` and reads its
   import table (`llvm-objdump -p`): every DLL must be on the OS list. It
   generalises `tests/tui_selfcontained_windows_test.go`.
4. The webview: the WebView2 runtime ships with Windows 11 and is
   installed on Windows 10, but MSYS2 has only the loader DLL
   (`WebView2Loader.dll`), no static loader. A `--static` webview program
   keeps importing it and the build says so; replacing the loader (it finds
   the runtime and calls its `CreateWebViewEnvironmentWithOptionsInternal`)
   is an open question.

**macOS** (Mac work). Link the Homebrew `.a` archives of every feature
library, leave `libSystem` and frameworks dynamic, check with `otool -L`
in the same guard; lift the refusal in `main.go`.

**Help and errors.** `--static`'s help says "self-contained" with the
per-OS meaning, and the macOS error goes once macOS is done.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| Static archives in the ucrt64 sysroot | Available | sqlite3, tommath, brotli, zstd, zlib, uv, curl chain |
| `llvm-objdump` on the Windows box and CI | Available | ships with the toolchain |
| Homebrew static archives | Unchecked | Mac |

## Open questions

- The WebView2 loader under `--static` (see 4).
- Whether `-package` should default to `--static` on Windows and macOS.
