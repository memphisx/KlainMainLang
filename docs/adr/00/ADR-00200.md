# ADR-00200: Named functions as first-class values (via an env-dropping trampoline)

- **Date**: 2026-08-17

## Context

A named top-level (or nested) function could be *called* directly (`f(x)`) and passed *directly* to a higher-order builtin (`arr.map(f)`, which special-cases a named callee as a direct call), but could not be used as a general first-class value: `const g = f`, `apply(f, ...)`, `return f`, or `setTimeout(f, ms)` all failed. `const g = f` errored with `undefined variable 'f__kml_mod0'` — surfaced incidentally while testing nullable-scalar parameters. A pre-existing general limitation, documented on `docs/status/TIMERS.md` ("a bare reference to a top-level named function isn't supported as a value yet") and referenced by [ADR-00031](ADR-00031.md).

## Investigation

Two root causes, both visible by emitting IR for `function f(v){...}; const g = (v)=>...`:

1. **No value-position handling for a function name.** The resolver mangles the reference `f` → `f__kml_mod0`, and `emitIdent` only ever looks up *variables* (the scope symbol table), so a name that resolves to a registered function fell through to `undefined variable`.
2. **ABI mismatch.** A named function is `define i64 @f__kml_mod0(i64 %p_v)` — no environment pointer. Every function *value*, however, is invoked through the closure ABI, which passes the environment first: a closure value is a `{ ptr funcPtr, ptr envPtr }` heap header, called as `call i64 (ptr, i64) %fp(ptr %env, i64 %arg)` (see `emitClosureCallByPtr`, `emit_func.go`). So a closure header cannot point at `@f` directly — the callee would read the first real argument as its env pointer and shift everything by one.

The two conventions otherwise agree operand-for-operand: an array (or rest) parameter expands to `(ptr, i64)` on both sides, a nullable scalar to `{ i1, T }` on both ([ADR-00199](ADR-00199.md)), a return array/nullable-scalar to its aggregate on both. So the only structural difference is that leading env pointer.

`emitClosureCallByPtr` was confirmed to already drive any `{funcPtr, env}` header correctly — including array/rest/void shapes — so the missing piece was purely *producing* such a header for a named function.

## Decision

Referencing a named function by value materializes a `{ trampoline, null }` closure header, where the **trampoline** is a small generated function that adapts the closure ABI to the named-function ABI by dropping the (unused) env pointer and forwarding every remaining operand verbatim:

```llvm
define <ret> @__fnval_<mangled>(ptr %env, <expanded params>) {
entry:
  %r = call <ret> @<mangled>(<same operands, minus env>)
  ret <ret> %r        ; or `ret void`
}
```

- `emitIdent`, on a scope-lookup miss, consults `resolveFuncRef`; a hit returns `emitNamedFuncValue`, which ensures the trampoline (memoized once per function) and mallocs a 16-byte header storing `{@__fnval_<mangled>, null}` — reusing the exact header shape `emitArrowFunction` already builds.
- The binding's type is `funcTypeFromSig(sig)` (the function's parameter/return types plus its rest flag), so ordinary call sites (`emitClosureCallByPtr`) pack a trailing rest argument and expand array/nullable operands correctly.
- `emitVarDecl`'s type-inference for an unannotated `const g = f` recognizes the same function reference so the slot is sized as a `ptr`.

A direct call `f(x)` never reaches `emitIdent` (`emitCall` dispatches a named callee straight to a direct `call`), so it is untouched and keeps its zero-overhead path.

## Implementation notes

- New file `emit_func_value.go`: `funcTypeFromSig`, `paramABITypes` (the one place encoding "array → (ptr,i64), everything else → `storageIR`"), `ensureFuncValueTrampoline` (memoized via a new `Emitter.fnValueTrampolines` set), `emitNamedFuncValue`.
- The trampoline is written as a self-contained `define` string straight into the `functions` builder with fixed local names (`%a0…`, `%r`), so it needs none of `emitClosureFunc`'s save/restore of the per-function `body`/`allocas`/counters.
- Rest parameters need no special case: a rest parameter's declared type *is* the collected array type, so it already flows through the `IsArray → (ptr, i64)` branch on both the trampoline signature and the forwarded call.
- Generic functions live in `genericFuncs`, not `funcs`, so `resolveFuncRef` never resolves one — a generic function by value stays a clean `undefined variable` rejection (out of scope; a monomorphized instance has no single symbol to point at).

## Side effects discovered

- `setTimeout`/`setInterval` with a bare named-function callback (`setTimeout(tick, 0)`) now works as a consequence — the callback is just a function value — closing the specific gap `docs/status/TIMERS.md` called out.
