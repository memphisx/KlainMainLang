# ADR-00836: `String(x)` / `` `${x}` `` of an absent scalar render "undefined"

- **Relations**: Extends [TDD-00187](../tdd/TDD-00187.md) / [ADR-00833](ADR-00833.md); mirrors the concat null-awareness of [ADR-00537](ADR-00537.md)
- **Date**: 2026-09-10

## Context

`String(miss)` and template interpolation `` `${miss}` `` of an absent
`number | undefined` **local** (e.g. `const miss = arr.find(...)` with no match)
rendered the unwrapped payload — `"0"` — instead of `"undefined"`. String
*concatenation* (`"x" + miss`) was already null-aware (ADR-00537) and
`console.log(miss)` printed `undefined`, so the divergence was inconsistent.
Inline (`String([1,2,3].find(...))`) already worked — only a value read back
from a nullable-scalar *local* was affected.

## Investigation

`emitValueToString` already renders a nullable-scalar aggregate null-aware (its
`absentLiteral`). The bug was upstream: `emitTemplateLiteral` and
`emitGlobalStringConv` evaluated the operand with `emitExpr`, which — for a
nullable-scalar **local** — auto-unwraps to the bare payload (the lenient
local-read collapse), discarding the presence bit before `emitValueToString`
ever saw it. `console.log` avoids this by special-casing a nullable-scalar
lvalue (`nullableScalarLValue`) and reading it null-aware; String()/template did
not.

## Decision

New `emitStringifyOperand(expr)`: when `expr` is an un-narrowed nullable-scalar
local, load the whole `{ i1, T }` aggregate (`loadNullableScalarAgg`) instead of
the unwrapped payload; otherwise `emitExpr`. `emitTemplateLiteral` and
`emitGlobalStringConv` use it, so `emitValueToString` receives the aggregate and
renders `undefined`/`null` (its own kind) when absent. A narrowed local is proven
present and takes the ordinary path.

## Implementation notes

`emit_nullable_scalar.go` (`loadNullableScalarAgg`, `emitStringifyOperand`);
`emit_exprs_types.go` (`emitTemplateLiteral`); `emit_call_number.go`
(`emitGlobalStringConv`).

## Side effects discovered

`JSON.stringify` of an object with an **omitted optional field** still serializes
the key as `null` where Node drops the key entirely (only a genuinely `null`
value serializes as `null`). That needs the object serializer to skip an absent
`T | undefined` field with runtime comma handling (compact + pretty, empty-object
edge) — a moderate rework, tracked separately, not part of this change.

## Verification

macOS (Apple Silicon M4): `String(miss)` and `` `${miss}` `` → `undefined` for an
absent `number | undefined` local, the value when present; `"x" + miss` stays
`"xundefined"`. New `TestE2EStringifyAbsentScalar` + the string/template/console/
nullable suites green.
