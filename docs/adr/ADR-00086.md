# ADR-00086: Optional catch binding (`catch { ... }`)

- **Date**: 2026-07-31

## Context

Flagged in `docs/status/README.md`'s "Newly identified gaps" list (2026-07-30
audit) as confirmed absent from the parser. Picked up alongside ADR-00085/
ADR-00087/ADR-00088 as another small, self-contained, low-complexity
front-end feature.

## Investigation

Read `parser/parser_stmts.go`'s `parseTryStatement` (the `catch` branch):
it unconditionally consumed `LPAREN`, an `IDENT`, an optional type
annotation, then `RPAREN` before the catch body — `(e)` was hard-required,
with no path to a bare `catch { ... }`.

Checked the codegen side (`codegen/llvm/emit_exceptions.go:182`) before
touching the parser: it already guards the catch-variable binding with
`if s.Catch.Param != ""`, so an empty `Param` string is already handled
correctly — this made the fix purely parser-side, no codegen change needed
at all.

## Decision

Made the `(IDENT [: Type])` clause conditional on actually seeing `LPAREN`
right after `catch`: if present, parse it exactly as before (paren, ident,
optional type annotation, paren); if absent, `paramName` stays `""` and the
catch body is parsed directly. `ast.CatchClause.Param` ends up empty for a
bindingless catch, which `emit_exceptions.go` was already prepared for.

## Implementation notes

Files touched: `parser/parser_stmts.go` (`parseTryStatement`'s `catch`
branch — `LPAREN` check now gates the whole binding-parsing block instead of
being unconditionally `expect`ed).

No AST or codegen changes needed.

## Side effects discovered

None. A `catch (e) { ... }` clause parses through exactly the same code
path as before (the `LPAREN` check is true, so every subsequent line runs
unchanged).

## Verification

- `tests/exceptions_test.go`: `TestE2EOptionalCatchBinding` — a bindingless
  `catch { ... }` that both fires (after a genuine `throw`) and is skipped
  (no throw, falls straight through).
- `examples/try_catch/try_catch.ts` extended with a bindingless-catch
  example, output verified against the compiled binary.
- `go build -o klainmain . && go vet ./... && go test ./...` all green.
- `make examples`: full suite passed.
