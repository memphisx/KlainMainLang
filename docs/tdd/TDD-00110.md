# TDD-00110: `tls.createServer` (TLS server)

- **Status**: Implemented
- **Date**: 2026-08-24
- **Notes**: The server half of tls: a net-shaped Server with an `SSL_CTX` (from PEM `{cert,key}` strings) in a new field; the net accept loop wraps each accepted fd with a blocking `SSL_accept`, storing the `SSL*` in the socket's field 5 so reads/writes route through `SSL_*`. Blocking handshake; PEM-strings-only; no client-cert/ALPN

## Context

TDD-00109 shipped the TLS client (`tls.connect`) and scoped `tls.createServer`
as "later". This adds the server half: an HTTPS/TLS-terminating listener, the
counterpart that lets a program *accept* TLS connections (a secure `http.listen`
alternative, a line-protocol server). It reuses the `net` server wholesale, the
same way the client reused the net client.

## Design

**`tls.createServer(options, connectionListener?)`** returns a **net-shaped
Server** (`NetServerType`) with a server `SSL_CTX*` stored in a new struct field.
`options` is an object literal `{ cert, key }` — PEM **strings** (as Node's are),
loaded into the ctx via a mem BIO. `server.listen(port)` / `.close()` /
`.on('connection')` all reuse the net server machinery unchanged.

- `netServerIR` gains a 4th field: the server `SSL_CTX*` (null for a plaintext
  `net` server — `calloc` zeroes it, so **net is behavior-unchanged**).
- **Accept path** (`@__kml_net_dispatch`'s accept loop): after `accept()` returns
  a (still-blocking) fd, if the server's ctx is non-null, wrap it —
  `__kml_tls_server_accept(ctx, fd)` does `SSL_new`+`SSL_set_fd`+ a **blocking**
  `SSL_accept`, storing the resulting `SSL*` in the connection socket's field 5
  (the same field the client uses). On handshake failure, the fd is closed and
  the connection dropped (no listener fired). Then the existing non-blocking
  fcntl + socket build + connection-listener fire proceed unchanged, and every
  read/write on that socket already routes through `SSL_read`/`SSL_write` (the
  field-5 branch TDD-00109 added).

Two new C helpers in the existing `tlssrc/tls.c`:
```c
void* __kml_tls_server_ctx(const char* cert_pem, const char* key_pem, char** errout);
void* __kml_tls_server_accept(void* ctx, int fd);   // SSL* or NULL
```

## Scope / exclusions (V1)

- `cert`/`key` are **PEM strings only** (no file paths, no cert chains, no
  passphrase, no SNI cert selection — one cert per server).
- **Blocking `SSL_accept`** in the event loop — a client that connects but stalls
  the handshake blocks the loop (the same simplification the client's blocking
  handshake and `net`'s blocking connect make; a non-blocking handshake needs the
  missing "retry when fd ready" loop primitive).
- No client-cert request (`requestCert`), no ALPN, no `'secureConnection'` vs
  `'connection'` distinction (fires `'connection'`, like net).
