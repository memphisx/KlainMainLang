# ADR-01631: An HTTP/2 session nghttp2 ends itself fails as in Node

- **Relations**: Extends ADR-01401
- **Date**: 2026-10-14

## Context

Node's `test-http2-misbehaving-flow-control` (a peer overrunning a stream's
flow-control window) threw on Windows: `The value of "code" is out of range …
Received -530`.

## Investigation

- The `'frameError'` handler closed the stream with `stream.close(code)`, as
  Node's `onFrameError` does, but with nghttp2's library error (negative).
  Node's C++ never reports a frame that was not sent because its session or
  stream is closing (`NGHTTP2_ERR_SESSION_CLOSING` −530,
  `NGHTTP2_ERR_STREAM_CLOSED` −510, `NGHTTP2_ERR_STREAM_CLOSING` −511), nor
  any frame while nothing listens for `'frameError'`.
- With the report filtered the program hung. Windows has nghttp2 1.69, the
  version Node 24 bundles; the Linux image has 1.64. At 1.64 nghttp2 resets
  the stream (`FLOW_CONTROL_ERROR`); at 1.69 it ends the whole session with
  its own GOAWAY. Node's debug trace (`NODE_DEBUG_NATIVE=http2session`) shows
  "nghttp2 session terminated internally" after sending; Node then writes the
  GOAWAY and destroys the session with `NghttpError(NGHTTP2_ERR_PROTO)`
  ("Protocol error"). Ours did neither, so nothing closed.
- Node also registers nghttp2's invalid-frame callback: past
  `maxSessionInvalidFrames` (1000) it fails the session with
  `ERR_HTTP2_TOO_MANY_INVALID_FRAMES`, and a fatal, stream-closed or protocol
  error destroys it with that error. Ours had no such callback.

## Decision

- `on_frame_not_send` (`h2node.c`) drops the three closing codes; the library
  emits `'frameError'` only while the session or one of its streams listens.
- An invalid-frame callback raises a new `H2E_SESSION_ERROR` event (code, and
  a flag for the invalid-frame limit); the library destroys the session with
  `NghttpError(code, 'ERR_HTTP2_TOO_MANY_INVALID_FRAMES' when flagged)`.
  `NghttpError` takes Node's optional custom code.
- The session records a GOAWAY it submitted and one it received.
  `h2State(11)` is true when nghttp2 stops reading while neither happened:
  the session ended itself. After each read and each send the library
  checks it, writes nghttp2's pending frames (its GOAWAY), and destroys the
  session with `NGHTTP2_ERR_PROTO`.

## Implementation notes

`http2src/h2node.c`, `lib/node/http2.ts`. A graceful GOAWAY (ours or the
peer's) also stops nghttp2 reading once its streams finish, which is why the
check excludes sessions that exchanged one.

## Side effects discovered

The corpus file (Node 22.11, nghttp2 1.64) expects the stream reset. On
Windows ours now matches Node 24 instead, so that file stays a Windows
failure until the corpus moves.

## Verification

Windows 11: the test's frames, sent in one write or three, print the same
events as Node 24.19 (stream `ERR_HTTP2_ERROR Protocol error`, stream and
server close, session error and close). Linux (Docker, nghttp2 1.64) keeps
the stream reset. `TestE2EHttp2MisbehavingFlowControl` accepts either outcome
and requires the close. The http2 tests pass.
