# ADR-00693: AbortSignal default reason and static abort()/any()

- **Relations**: Implements TDD-00081
- **Date**: 2026-09-04

## Context

Two AbortController/AbortSignal fidelity gaps against Node.js v26 remained:

1. A no-argument `controller.abort()` left `signal.reason` as `null`. Node
   defaults it to an `AbortError` DOMException (`reason.name === 'AbortError'`).
   Only the default was missing — a custom `abort(reason)` already propagated.
2. The static constructors `AbortSignal.abort(reason?)` and
   `AbortSignal.any(signals)` did not exist. `AbortSignal.abort()` failed to
   compile with `a number has no method 'abort'` because the `AbortSignal`
   identifier had no static-method surface.

Repros:

```
const c = new AbortController(); c.abort();
console.log(c.signal.reason?.name);   // want: AbortError, got: null
const s = AbortSignal.abort();
console.log(s.aborted);               // want: true, was: compile error
```

## Investigation

`emit_abort.go:emitAbortControllerAbort` stored `reason` only when an argument
was supplied, leaving the `new`-time `null` in place otherwise. `emit_call.go`
dispatched only static `AbortSignal.timeout`; `abort`/`any` fell through to
generic member dispatch, which typed the `AbortSignal` identifier as a number.

`buildErrorObj` (emit_exceptions.go:91) already builds an errorObjType carrying
a `name` — the same shape fetch uses for its `AbortError` throw
(runtime_fetch.go:208) — so the default reason reuses it with the DOMException
kind tag.

The `reason` field was typed `TypePtr` (types.go:1346), so `signal.reason.name`
did not resolve (`optional chaining '?.' does not support property 'name' on
type ptr`). Typing the field as `errorObjType` lets `.name`/`.message` resolve
through the error-object shape; a custom non-error reason is still stored and
prints verbatim.

## Decision

- Default a no-argument `controller.abort()` reason to an `AbortError`
  DOMException via a shared `buildDefaultAbortReason` helper.
- Add static `AbortSignal.abort(reason?)` (an already-aborted signal, default
  reason as above) and `AbortSignal.any(signals)` (a composite signal latched
  aborted, inheriting the reason, as soon as any input signal is aborted).
- Type the AbortSignal `reason` field as `errorObjType` so `reason?.name`
  resolves.

## Implementation notes

- `emit_abort.go`: `buildDefaultAbortReason`, `emitAbortSignalStaticAbort`,
  `emitAbortSignalAny`; the no-arg branch of `emitAbortControllerAbort`.
- `emit_call.go`: static `AbortSignal.{timeout,abort,any}` dispatch on the
  identifier.
- `emit_exprs_types.go`: static `AbortSignal.{timeout,abort,any}` infer to
  AbortSignalType.
- `types.go` (shared file, forced): AbortSignal `reason` field retyped to
  `errorObjType`. The struct layout is unchanged — both are pointer-width — so
  `storeEventField(..., "ptr", ...)` continues to store the raw pointer.
- `any()` reuses `__kml_signal_aborted` (which also latches an elapsed
  `AbortSignal.timeout` deadline) and `resolveArrayForHOF` for the input array.

## Side effects discovered

`AbortSignal.any()` snapshots the input signals' aborted state at construction.
Live propagation for a source aborted *after* the composite is built needs
listener wiring and is deferred (noted as a caveat in
`docs/status/data/events-cancellation.json`).

## Verification

- `go build -o klainmain .` clean.
- Both repros match Node v26: `c.signal.reason?.name` → `AbortError`;
  `AbortSignal.abort().aborted` → `true`.
- New E2E: `tests/abortsignal_reason_static_test.go` (default reason, static
  abort, any) — pass. Existing `tests/abort_test.go` + event suites pass.
- Example `examples/events/abort-signal-static.ts` runs with the expected
  output (verified on Mac / Apple Silicon).
