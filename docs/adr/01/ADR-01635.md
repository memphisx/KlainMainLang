# ADR-01635: An HTTP request body resumes after backpressure

- **Date**: 2026-10-14

## Context

Node's `test-http-client-keep-alive-release-before-finish` timed out on
Windows: a 16 KB POST body whose last chunk follows 100 ms later never
finished on the server, so the keep-alive GET queued behind it never ran.

## Investigation

The client sent every byte (a `net` server saw the same bytes Node's client
sends), and `net` pause/resume worked. In the HTTP module (`internal_http.ts`)
`onBody` pushes each chunk into the `IncomingMessage` and, when the push
reports a full buffer, pauses the socket (`readStop`). Reading the request
calls `readStart`, which returned early when the socket's `readableFlowing`
was `false`: the very state `readStop` leaves. The rest of the body never
came. Node's `readStart` resumes unless the server's own pipelining pause
(`_paused`) holds the socket. On Linux the first push did not fill the buffer
in this test, so the bug stayed hidden there; a request read after a pause
hangs on every host.

## Decision

`readStart` resumes the socket when it is readable and not held by the
server's pipelining pause, as Node's does.

## Implementation notes

`lib/node/internal_http.ts`.

## Verification

Windows 11: the test's program, and a 1 MB variant, print the same as Node
24.19; a 256 KB body read after `req.pause()` hangs with the old code and
completes with the new. `TestE2EHTTPServerBodyResumesAfterBackpressure`
(compared with Node). The Node file passes.
