# ADR-00859: ToPrimitive number-hint coercion of objects (TDD-00201 Stage 1)

- **Relations**: `Implements TDD-00201`
- **Date**: 2026-09-10

## Context

An object used in a numeric context — `{valueOf(){return 5}} * 2`,
`{valueOf(){return 1}} & 1`, `obj > 4` — must be converted by JS's ToPrimitive
(number hint): `Symbol.toPrimitive` → `valueOf` → `toString`, first primitive
wins. This compiler emitted the object's `ptr` register straight into the numeric
op (`mul ptr`, `trunc i64 <ptr>`), invalid IR that clang rejects. It is the
dominant root cause of the A1 invalid-IR cluster (the largest in the backlog).

## Investigation

`coerce` (`emit_exprs_coerce.go`) is the central conversion point; an `IsObject`
source into a numeric target fell through its `default: return v` arm unchanged.
Its `target` type is the hint. Objects are fixed-shape, so whether
`valueOf`/`toString`/`@@toPrimitive` exist and their return types are known
statically (`Type.FieldIndex`) — the ladder is ordinary typed method calls
(`emitClosureCallByPtr` on the loaded method-field closure), no dynamic-property
bag. `Symbol.toPrimitive` reuses the existing well-known-symbol trick: the parser
already desugars `[Symbol.iterator]` to the reserved string field `@@iterator`
(`wellKnownSymbolMemberName`); extended to `[Symbol.toPrimitive]` → `@@toPrimitive`.

Two operator routes exist: bitwise/shift already `coerce(operand, i64)` (so the
`coerce` hook covers them), while arithmetic/relational unify to the left
operand's type *before* coercing to a number — so an object operand there never
reaches a numeric `coerce`. Both are handled (see Decision).

## Decision

- **Parser**: `wellKnownSymbolMemberName` recognizes `[Symbol.toPrimitive]` →
  `@@toPrimitive`, so a literal computed-key method is an ordinary static field.
- **`emitObjectToPrimitive(v, hint)`** (`emit_toprimitive.go`): walks the
  hint-ordered ladder (`@@toPrimitive` → `valueOf`/`toString`), takes the first
  method field whose declared return is usable for the hint, calls it (the hint
  string is passed to `@@toPrimitive`), and returns the RAW primitive — the
  caller applies the surrounding ToNumber/ToString. A candidate whose return is
  an object/composite is skipped (spec's "if result is an Object, continue").
- **`coerce` hook**: an object source into a `double`/`iN` target runs the number
  ladder and coerces the result. Covers bitwise/shift and typed numeric slots.
- **`emitBinary` pre-pass**: for `- * / % ** < > <= >=`, an object operand is run
  through the number ladder before the numeric-promotion logic.

Scope guard: for the **number** hint a candidate must return a *numeric* type; a
string-returning method (needing ToNumber(string)) is skipped, so no string
pointer is misused as an integer — such a case stays a (pre-existing) compile
error rather than becoming silently wrong. Faithful in both `-compat` lanes (the
object is statically typed; no NaN-box/any involved).

## Implementation notes

- New file `codegen/llvm/emit_toprimitive.go`; hooks in `emit_exprs_coerce.go` and
  `emit_exprs_operators.go`; recognizer in `parser/parser_classes.go`.
- The ladder engages only when the object declares an applicable method *field*;
  Date/Map/Set/Symbol carry their methods as builtins (not struct fields), so they
  never match — their existing handling is untouched.

## Side effects discovered

- **String hint is Stage 2, and is independently pre-existing-broken**:
  `String(obj)` / `` `${obj}` `` / a string-typed argument render an object's
  debug form (`{ toString: [Function] }`) instead of calling `toString` today —
  unrelated to this change. Because a Test262 A1 file often mixes a number-hint
  and a string-hint object argument (e.g. `str.indexOf(searchObj, posObj)`),
  Stage 1 lets such a file *compile* (the number operand now coerces) while it
  still fails at runtime on the string operand. This is not a regression (the file
  failed to compile before, and nothing that passed now fails), but it means Stage
  1's standalone Test262 pass-count gain is small — the A1 wins land with Stage 2.
- **A separate full-file interaction bug**: the pure-number bitwise A1 files
  (e.g. `bitwise-and/S11.10.1_A2.2_T1.js`) still emit invalid IR only when the
  *whole* file is compiled — each individual case (including a throwing
  `valueOf`/`toString` inside try/catch) compiles in isolation, but the full
  harness+7-cases file does not, and it predates this change. Not isolated;
  tracked as remaining TDD-00201 work.
- `{toString(){return "5"}} * 2` (a string-returning method in numeric context,
  needing ToNumber(string)) stays a compile error — deferred, documented.
