# ADR-00756: `fs.watch` — the FSWatcher subsystem + Linux inotify backend (TDD-00181 Stage 1)

- **Relations**: Implements [TDD-00181](../tdd/TDD-00181.md) Stage 1; extends [ADR-00322](ADR-00322.md) (the `select()` event loop + hook-trio convention), [ADR-00497](ADR-00497.md) (the shared `__kml_fs_throw`)
- **Date**: 2026-09-07

## Context

`fs.watch(filename[, options][, listener])` — the last unimplemented [TDD-00180](../tdd/TDD-00180.md) §4 fs item, and the only *subsystem* among them: it must feed a live OS change source into the compiler's single `select()` event loop rather than being a one-shot call. [TDD-00181](../tdd/TDD-00181.md) chose the faithful, event-driven design (native OS backends) and staged it. This ADR is **Stage 1**: the event-loop integration + `FSWatcher` object + the **Linux inotify** backend. Windows (`ReadDirectoryChangesW` + a wakeup socket) and macOS (`kqueue`) are Stages 2/3; the coverage row is not claimed until all three pass.

## Decision

- **Event-loop integration** (`runtime_fswatch.go`): fs.watch registers the standard hook trio the loop already calls for worker/cp/readline — `__kml_fswatch_keepalive` (true while an FSWatcher is open), `__kml_fswatch_fdset_add` (adds the backend's wait fd), `__kml_fswatch_dispatch` (reads pending events after `select()` and fires listeners). Wired into `runtime_http.go`'s `%anywork` keepalive chain, its fd-scan, and its post-`select()` dispatch; no-op stubs in `emitLoopTaskStubs` when fs.watch is unused; `usedFsWatchRuntime` joins `useFullLoop`.
- **Linux backend**: one process-wide `inotify_init1(IN_NONBLOCK|IN_CLOEXEC)` instance (lazily created). Each `fs.watch` adds a watch (`IN_MODIFY|IN_ATTRIB|IN_CREATE|IN_DELETE|IN_MOVED_FROM|IN_MOVED_TO|IN_MOVE_SELF|IN_DELETE_SELF`) and registers an `FSWatcher`. The inotify instance **is a readable fd**, so `fdset_add` drops it into the loop's read `fd_set` with no thread; `dispatch` `read()`s the `struct inotify_event` stream, maps each mask (`IN_CREATE`/`DELETE`/`MOVED_*` → `'rename'`, `IN_MODIFY`/`ATTRIB` → `'change'`), finds the watcher by `wd`, and fires its listener with `(eventType, filename)` — the event's own `name` for a directory watch, else the watched path.
- **`FSWatcher` object** (`FSWatcherType`, `IsFSWatcher`): `.on('change'|'rename', (eventType, filename) => …)` stores one listener slot per event (arrow-literal only, the `ChildProcess` posture); `.close()` `inotify_rm_watch`es and drops the keepalive. `fs.watch(path, listener)` registers the listener as both events (Node's overload). Options are accepted but mostly deferred (Stage-1 caveat).
- Non-Linux `__kml_fs_watch` throws (the same coded fs error) and the hooks are inert, so the build and the rest of the loop are unaffected on Windows/macOS until their stages land.

## Implementation notes

- `@read` is declared via the shared `ensureReadDecl()` (a private `declare` collided — "invalid redefinition of function 'read'").
- The `FSWatcher` is a heap `{ i64 wd, ptr changeCb, ptr renameCb, i64 open, ptr name }`; a process-wide growable registry lets `dispatch` map an event's `wd` back to its watcher.
- No `select()` timeout change is needed — the inotify fd is readable, so `select()` wakes on a change like any socket.

## Side effects discovered

The core event loop (`runtime_http.go`) gained one hook trio; verified the existing loop-driven suites (timers/workers/child_process/net/HTTP-listen) still pass on Windows, where fs.watch itself is inert.

## Verification

- New E2E test `TestE2EFsWatchChange` (`tests/fs_test.go`), gated to Linux: watch a file, a `setTimeout` writes it, the `'change'` event fires, `close()` lets the loop exit. **Verified on Linux via the project's Docker image** (`klain-ci:latest`) — a real `IN_MODIFY` delivered `event=change`; a directory watch delivered `evt=rename name=new.txt` (create → rename with the entry name). Exit code 0 both times (the loop terminates once the watcher closes).
- Windows/macOS: `fs.watch` throws (backends pending); the loop-integration compiles and the existing event-loop suites are unregressed on Windows 11.
- No status/reference row or example yet — added in [TDD-00181](../tdd/TDD-00181.md) Stage 4 once every target platform's backend passes. `go build`/`go vet` clean.
