# ADR-01578: A call of a function whose result is boxed reads the box

- **Relations**: Extends ADR-01562, Implements TDD-00230
- **Date**: 2026-10-11

## Context

The node suite's js lane lost `test-sync-fileread`, `test-fs-readfile-fd`
and `test-fs-truncate-clear-file-zero`. All three fail on
`fs.readFileSync(p).toString()`: the string came back as zero bytes, or
a float64's bytes.

`readFileSync` is overloaded and its implementation returns
`string | Buffer`, so codegen holds the result boxed as `any`. With
ADR-01562, a call's type comes from the checker. The checker picks the
`Buffer` overload, so `.toString()` was compiled as Buffer's method on the
box itself and read the box's bits as bytes. Binding the result to a name
first worked, because the name reads its storage type.

`codegenCallRepr`, the hook through which the oracle defers to emission
for calls, handled only generators, iterators and method calls on boxed
receivers. The import is resolved to the module's function before
emission, so the call's callee is an identifier.

## Decision

`codegenCallRepr` returns a function's registered return type when that
type is unconstrained `any`. The call is then typed as the box it returns.
Where the checker resolves the overload to a primitive, the rule returns
that primitive itself (`checkerPrimitive`), as the emitter unboxes the
result to it. The oracle's answer for a call does not pass through
`inferRefined`, so leaving the primitive to it does not work. A first
version did, and the full E2E run failed 23 tests with invalid IR (a
webcrypto call result typed `any` but emitted as a `double`).

## Verification

- `TestCompatJSReadFileSyncChainedToString`.
- The three node tests pass on Linux (Node304 kmlbox).
- Full gates on both boxes.
