# ADR-01019: Windows example pass — HEAD/NOBODY, fs O_ flags, self-signal, node:ffi shim, binary-safe socket/zlib length

- **Relations**: Extends [ADR-01018](ADR-01018.md); Implements TDD-00164 (node:ffi), TDD-00177 (Windows platform lane)
- **Date**: 2026-09-19

## Context

After the CI-regression sweep (ADR-01018) unblocked the Windows `go test` lane, a full run of the example suite on Windows (324/333) surfaced a tail of real Windows-only bugs and a few POSIX-only examples. This ADR takes the examples the rest of the way and fixes the underlying runtime bugs they exposed. The example step is POSIX-lanes-only in CI, but a real Windows release needs the examples working.

## Investigation & fixes

1. **HEAD requests hung (`http/client_server`).** The libcurl-backed client (`runtime_fetch.go` `__kml_fetch_async`) set `CURLOPT_CUSTOMREQUEST` for the method but never `CURLOPT_NOBODY`; libcurl then blocks waiting for a response body a HEAD reply never sends, and the reader-completion path never fires (a hang, seen on Windows). Fix: set `CURLOPT_NOBODY` (44) when the method is `HEAD`. Hardens Linux too.

2. **`fs.constants.O_*` wrong on Windows (`fs`).** `fsOpenConstant`'s Windows map returned the MSVC `_O_*` values (`O_CREAT` 0x0100), but the Windows fs runtime (`win32fs.c` `L_O_*`) and `openFlagBits` both use the **Linux** O_ encoding (`O_CREAT` 0x40). A numeric `openSync(p, O_WRONLY|O_CREAT|O_TRUNC)` therefore missed the create bit and failed `ENOENT`, while the string flag `'w'` worked. Fix: the Windows map now uses the Linux encoding its own runtime checks. (The raw numeric values differ from Node's Windows constants, documented in the code — internal consistency wins, and openSync now works.)

3. **`process.kill(self, SIGINT)` killed the process (`process/graceful_shutdown`).** The Windows `kill()` shim `TerminateProcess`es any signalled target — right for a child, but for self-signalling it kills the process before the registered handler runs. Fix: a self-directed signal that Windows can actually deliver to a handler — the console controls SIGINT/SIGHUP/SIGBREAK and SIGWINCH — is queued through the same reactor path the console Ctrl handler uses (`kml_deliver_self_signal`), so the handler runs and the program shuts down gracefully. Everything else (SIGTERM included — a listener is accepted but never fires on Windows) and the no-handler case fall through to the default terminate, unchanged (`TestE2ESignalSigtermIsTerminateOnWindows` guards this).

4. **node:ffi on Windows (`ffi`).** Removed the Windows rejection and added `FFIWinDlShimSource` — `dlopen`/`dlsym`/`dlclose`/`dlerror` over `LoadLibrary`/`GetProcAddress`/`FreeLibrary`, wired through `ensureFFIDl`/`embedded_c.go`. `dlopen(NULL)` (the process image, used to reach libc) returns a sentinel whose `dlsym` searches the loaded UCRT + core system modules, where `qsort`/`strlen`/`pow`/… live. The example runs clean on Windows (native callback into `qsort` included).

5. **Binary-safe socket/zlib length (`zlibResolveInput`).** For a string argument, `socket.write`/`zlib` computed the byte length with `strlen`. klain strings are length-prefixed and may hold embedded NUL bytes; using `strlen` truncates such a string. Fix: use the KML string header length (`emitStrLenHeader`). Correctness improvement across the shared helper (found while chasing item 7).

6. **POSIX-only examples made cross-platform.** `fs`'s `symlinkSync` needs Developer Mode on Windows — guarded in a try/catch as portable Node code does. `exec_file_sync` used `/bin/echo`, `/usr/bin/false`, `/bin/sh` — a `process.platform` branch runs the same surface via `cmd.exe`/`where.exe` on Windows.

## Side effects discovered

- **`http/client_error_event` and `http2/client_session` are not klain bugs on the dev box.** A raw truncated request (`"GET / HT…"`) over `net.connect` was received mangled/dropped. A pure PowerShell↔PowerShell loopback TCP transfer reproduced it *without klain*: `"XET / HT"` and `"HELLOwld"` cross cleanly, but `"GET / HT"` is dropped — a local HTTP-shaped-loopback interceptor (host security/WFP inspection) on that machine, not the compiler. Full-HTTP examples (libcurl/fetch) are unaffected. These pass on a clean Windows runner; left as environmental, not a code change.

## Verification

- Windows (MSYS2 UCRT64 clang): `fs`, `exec_file_sync`, `graceful_shutdown`, `ffi`, `client_server` examples pass; the HEAD/O_flag/self-signal/ffi fixes each confirmed by a direct run.
- Linux x86-64 (Docker `golang:latest`): `go build`/`go vet` clean; zlib/net/ffi/stream/gzip and HTTP/fetch/client test suites pass — no regression from the shared HEAD and `zlibResolveInput` changes.
- Full suites and `make conformance` recorded same-commit.
