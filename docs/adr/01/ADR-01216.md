# ADR-01216: `this` in method signatures, their class types, assignment values

- **Relations**: `Extends ADR-01215`
- **Date**: 2026-09-28

## Context

Probing TDD-00233 Stage 3 against Node found five bugs outside the view
itself. Each one crashed or refused a program that Node runs.

## Investigation

- **`this` in a method signature.** The parser dropped a method
  signature's leading `this: T` (`read?(this: H, n: number): void`), so
  the member's function type had no receiver. An object literal method
  that declares `this: H` did not match it: a closure ABI mismatch and a
  segfault on `o.read.call(h, 5)`.
- **Class types in a method signature.** The resolver renamed a signature's
  parameter and return types, but not the function type built from them
  (`InterfaceMethodSig.Type`, ADR-01210). A class-typed parameter
  (`f(h: H): string`) resolved to `number`.
- **Assignment values.** `inferExprType` had no case for an assignment
  expression and typed `b += c` as a number. An arrow returning it
  (`r.on("data", (c) => b += c)`) returned a string pointer from an `i64`
  function: invalid IR.
- **`this` through a dynamic-to-static thunk.** The thunk passed a
  `this: T` parameter as an ordinary argument.
- **An absent optional function** (`undefined` converted to a function
  type) became a thunk around `undefined`. The stream constructor saw a
  `construct` option that was not given and called it.

## Decision

- The parser records a method signature's `this: T`
  (`MethodSignature.This`); the converter makes the member's function type
  take it as its leading parameter (`FuncThis`), as a function type does.
  The AST walker is regenerated.
- The resolver renames `InterfaceMethodSig.Type`.
- An assignment expression's type is its target's.
- The thunk passes a `this: T` parameter as the dynamic call's receiver;
  `emitAnyToClosure` refuses a `this` plus rest signature.
- `emitAnyToClosure` yields the null closure for `undefined`/`null`.
- The view binds a method it reads to the object only when the member's
  type has no `this: T` of its own.
- A type name codegen does not know that names a top-level interface of
  the builtin declarations (`RequestInit`) resolves to that interface's
  object type, registered on first use like a program interface
  (`emit_ambient.go`); it was `number`.

`parser/parser.go`, `parser/parser_types.go`, `ast/type_nodes.go`,

## Side effects discovered

- `fetch` reads its init's fields at their static types and takes only a
  string body, so an init typed `RequestInit` (union-typed `headers` and
  `body`) is still rejected there (BACKLOG).
- `fs.readFileSync(path, opts)` takes only an object literal as `opts`.

## Verification

Mac (Apple Silicon), against Node v24.19: `TestE2EFunctionMembersThroughView`,
`TestE2EAssignmentExpressionValueType`.
