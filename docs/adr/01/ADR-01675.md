# ADR-01675: A builtin constructor is one value, and function unions keep each signature

- **Relations**: Implements TDD-00230
- **Date**: 2026-10-17

## Context

While moving `Object(…)` onto the declaration path (TDD-00230 P3.5, builtin-name rules), probing against Node turned up a cluster of divergences around builtin constructors used as values and around unions of function types:

- `const a = Object()` stored a dynamic object in a number slot (`typeof a` was `"number"`).
- `Object(v)` with `v: any` did not compile, and neither did `globalThis` read as a value, which made the same call.
- `const O: any = Object; O()` threw "value is not a function".
- `s.constructor === String` was false for a string `s`. The same held for Number and Boolean.
- `String(parseInt)` and `String(String)` printed `function () { [native code] }`, without the name.
- `Symbol.length` was 1.
- `c ? String : Number`, `[String, Number]` and `[(x) => String(x), (x) => Number(x)]` crashed when called. One closure slot held every member under the first member's signature.
- `const b: Object = { x: 1 }` failed in codegen, and the checker rejected an array passed as `Object`.

## Decision

- **`Object(…)` call.** It keeps its rule (a call of the global `Object`). Both the variable-declaration and structural inference type its result `any`. With an `any` argument, the result is decided at run time: a new object for null or undefined, the argument itself for an object, and a TypeError for a primitive (`emitObjectCtorDynamic`).
- **One constructor value.** A builtin constructor with a call-signature intrinsic (String, Number, Boolean, Symbol, BigInt) is its function value wherever it is reached. A primitive's `.constructor` read through `any` returns that same boxed value (`builtinCtorValue`), so identity holds. Other constructors stay class references (`Object`, `Map`, …). Calling one held as a value goes through `__kml_classref_call` (dynobj.c): `Object` runs its call semantics, and every other constructor throws Node's "Constructor X requires 'new'".
- **Names and lengths.** A boxed function's `String()` is `function <name>() { [native code] }`, from its metadata (`__kml_fn_tostring_dyn`, fnmeta.c). `Symbol` gets its spec length, 0.
- **Function unions.**
  - The checker resolves a call through a union of function types whose members have identical parameters, as TypeScript does: those parameters, with the union of the results (`unionSignature`).
  - In codegen, a union with a function member is held as `any`: a boxed function, called dynamically.
  - A ternary or an array literal whose function members' signatures differ is boxed the same way.
- **`Object` annotation.** It is held as `any`, as `Function` is: every non-nullish value fits. The checker's array-to-interface relation now counts `Object.prototype`'s members, as `propsFit` already did.
- **`Function.prototype`.** The lib declares `prototype: any` on `Function`, as TypeScript's own lib does. Expando detection on function values asks the lib's `Function` and `Object` interfaces instead of an eight-name list.

## Divergence

`Object(primitive)` throws a TypeError where Node returns a wrapper object. Primitive wrapper objects do not exist yet. Before this change, a statically known primitive was a compile error, and a dynamic one did not compile at all.

## Side effects discovered

Every builtin function value's `String()` lacked its name. It was fixed in the same place.

## Verification

- New E2E tests, each compared with Node:
  - `TestE2EObjectCtorCallInferred`;
  - `TestE2EBuiltinConstructorValueIdentity`;
  - `TestE2EMixedSignatureFunctionUnion`;
  - `TestE2EObjectTypeAnnotation`.
- New checker unit case for a union call. Constructor, union, ternary, strict-mode and global-value tests pass on Mac.
