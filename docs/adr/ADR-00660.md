# ADR-00660: Bitwise & shift operators on any-typed operands (-compat=js)

- **Relations**: Extends ADR-00656
- **Date**: 2026-09-03

## Context

The per-flag two-lane report (ADR-00656) plus a completed js-lane run (once the
codegen guard, ADR-00659, let it finish) put the true `-compat=js` vs strict
Test262 delta at **js +351 ahead of strict** — and enumerated the 86 files that
still *regress* under js (pass strict, fail js). Ranked by reason, the single
largest bucket was **26 files** failing with `operator '<op>' on any/unknown is
not yet supported`. The offenders use **bitwise and shift** operators on values
that, under `-compat=js`, flow through untyped parameters and are therefore
`any` — e.g. `decodeURI`/`decodeURIComponent` (which mask and shift char codes:
`& 0x3F`, `<< 6`) and the `compound-assignment` corpus (`x &= y`, `x <<= y`).

## Investigation

`emitAnyBinary` (`codegen/llvm/emit_anyops.go`) is the runtime operator
dispatcher over the NaN-boxed word (`-compat=js`, TDD-00076 A2). It handled `+`
(concat/add), `- * / % **`, and `< > <= >=`, but its switch fell through to the
rejection for every other operator — including all of `& | ^ << >> >>>`. The
typed-`number` path already has the exact machinery this needs: `toInt32`
(ToInt32 → i32), the `and/or/xor i32` sequence with `int32ToNumber`, and
`emitBitShift` (`emit_exprs_operators.go`). Only the any dispatcher was missing
the cases; the call sites (`emit_exprs_operators.go`'s binary path and
`emit_exprs_assign.go`'s compound-assignment path) already route to
`emitAnyBinary` under `-compat=js` and reject only under strict.

## Decision

Add the bitwise and shift cases to `emitAnyBinary`, reusing the typed-number
machinery over the any operands' numeric coercion (`emitAnyToNum` → double):

- `& | ^`: `toInt32` each operand, `and/or/xor i32`, `int32ToNumber` → double,
  re-box as `any`.
- `<< >> >>>`: `emitBitShift` over the two double operands (it applies the 0-31
  shift-count mask and the signed/unsigned result rule), re-box as `any`.

Strict is untouched — it still rejects operators on `any` cleanly. Equality
(`=== == != !==`) keeps its own `emitAnyEquals` path.

## Implementation notes

- `emit_anyops.go`, `emitAnyBinary`: two new `case` arms before the fallback
  error, each ending in `emitNbEncodeDouble` to re-box the numeric result.
- The result type is a JS Number (double), boxed back to `TypeAny` — matching
  the arithmetic arms already there.

## Side effects discovered

Fixing the operator error advances some files to their *next*, unrelated blocker
rather than to a pass — e.g. `decodeURIComponent/S15.1.3.2_A2.2_T1.js` now
reaches an undefined test-local helper. That is expected of a first-error
histogram (ADR-00153): closing the top bucket redistributes its files to
whatever blocks them next. The compound-assignment cases pass outright.

## Verification

- New E2E test `TestE2EAnyOpsBitwise` (`tests/anyops_test.go`): `& | ^ << >>
  >>>` on any operands, including `-1 >>> 0 === 4294967295`.
- `language/expressions/compound-assignment/S11.13.2_A3.1_T10.js` now compiles
  and runs under `-compat=js`.
- The `anyops` + `jsmode` + class suites stay green. macOS (Apple Silicon).
