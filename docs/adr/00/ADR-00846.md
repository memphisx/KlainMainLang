# ADR-00846: `Error.prototype.toString` / `String(err)` / `` `${err}` ``

- **Relations**: Extends the Error object ([ADR-00082](ADR-00082.md) layout, [ADR-00630](ADR-00630.md) subclassing)
- **Date**: 2026-09-10

## Context

An Error had no string rendering: `err.toString()` was "an object has no method
'toString'", and `String(err)` / `` `${err}` `` didn't produce Node's
`"Error: boom"` form. Logging or interpolating a caught error — extremely
common — failed to compile.

## Decision

New `emitErrorToString(errVal)`: reads the error object's `name` (field 2) and
`message` (field 1) and builds JS's `Error.prototype.toString` result — `name`
when the message is empty, otherwise `name + ": " + message`. Wired into:
- the method dispatch, for `err.toString()` (receiver `IsError`);
- `emitValueToString`, so `String(err)`, `` `${err}` ``, and `"" + err` route
  through it before the generic object handling.

## Implementation notes

`emit_exceptions.go` (`emitErrorToString`); `emit_call.go` (`.toString()`
dispatch); `emit_exprs_types.go` (`emitValueToString` IsError branch). The
empty-message check is a runtime `strlen == 0` select; `name` is always set (the
kind name), so the common result is `name: message`.

## Verification

macOS (Apple Silicon M4): `new Error("x").toString()` → `Error: x`,
`String(new RangeError("r"))` → `RangeError: r`, `` `err: ${new TypeError(
"bad")}` `` → `err: TypeError: bad`, `"" + new Error("boom")` → `Error: boom`,
`new Error("").toString()` → `Error`. New `TestE2EErrorToString` + the
error/exception/try-catch suites green.
