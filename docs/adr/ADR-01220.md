# ADR-01220: The Web Crypto global and the crypto module are declared

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-09-29

## Context

TDD-00230 P3.1 moves the builtin surface into declaration files that the
checker reads. Neither the global `crypto` (Web Crypto) nor the `crypto`
module was declared. The checker let every use through, so a type error
(`const n: number = crypto.randomUUID()`) reached codegen as a generic
"incompatible" message or not at all.

## Investigation

- TypeScript's lib.dom declares `Crypto`, `SubtleCrypto`, `CryptoKey` and
  the algorithm parameter dictionaries. `randomUUID` returns a template
  literal type, and the checker had no model for those, so the result was
  unanswered.
- @types/node declares the `crypto` module. Codegen implements
  `createHash`, `createHmac` (`update(data)`, `digest(encoding?)`),
  `randomBytes`, `randomUUID`, `getRandomValues`, the PEM form of
  `generateKeyPair(Sync)` for RSA and EC, and `subtle`/`webcrypto`.
- Node takes the OpenSSL curve names (`prime256v1`, `secp384r1`,
  `secp521r1`) as well as the NIST ones; codegen took only `P-256`,
  `P-384` and `P-521`.

## Decision

- `lib/webcrypto.d.ts` holds lib.dom's declarations for `Crypto`,
  `SubtleCrypto`, `CryptoKey`, `CryptoKeyPair` and their dictionaries,
  extracted as a closure of the referenced names, and
  `declare var crypto: Crypto`.
- `declare module "crypto"` in `lib/node.d.ts` declares the implemented
  members with @types/node's signatures. A member it leaves out
  (`hash.copy()`, `update(data, inputEncoding)`) is not implemented.
- The checker types a template literal type: the string literals it spells
  when every hole is a literal type (or a union of them), else `string`.
- `generateKeyPair(Sync)`'s `namedCurve` takes the OpenSSL names.

## Implementation notes

`lib/webcrypto.d.ts` (new), `lib/node.d.ts`, `checker/symbols.go`,
`codegen/llvm/emit_nodecrypto.go`.

## Side effects discovered

- The checker does not report TS2339 on a builtin interface: each is
  marked partial, since a declaration lists only what this compiler
  implements. A member left out is still codegen's error.
- A template literal type with a non-literal hole (`${string}-x`) accepts
  any string; tsc checks the pattern.

## Verification

Mac (Apple Silicon), against Node v24.19 and tsc: `TestE2EWebCryptoDeclared`,
`TestE2ECryptoModuleDeclared`, `TestE2ETemplateLiteralTypes`.
