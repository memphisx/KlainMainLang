# ADR-01639: Windows links libuv with the synchronization library

- **Relations**: Extends ADR-01602
- **Date**: 2026-10-15

## Context

The Windows CI lane failed `TestE2ETuiMenuAppNavigates`, a `--static`
build: `ld.lld: error: undefined symbol: WakeByAddressSingle` and
`WaitOnAddress`, referenced from `libuv.a(pipe.c.obj)`.

## Investigation

- The runner installs the current MSYS2 `mingw-w64-ucrt-x86_64-libuv`,
  unpinned. That build's pipe code waits with `WaitOnAddress`, which lives
  in `libsynchronization`.
- The dev box's `libuv.a` does not reference either symbol, so its links
  succeeded.
- `LocateUV` (`codegen/llvm/loop.go`) names the Windows system libraries
  itself, and the list had no `-lsynchronization`. A dynamic link takes
  libuv's DLL, which carries its own imports, so only static links failed.

## Decision

The Windows list adds `-lsynchronization`. A libuv that does not use it
leaves it unused.

## Implementation notes

`codegen/llvm/loop.go`, `LocateUV`.

## Verification

Windows 11: `TestE2ETuiMenuAppNavigates` and the `TestE2EStatic*` tests
pass. The runner's libuv is exercised by the Windows CI lane.
