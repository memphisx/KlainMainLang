# ADR-01325: Type-id dispatch goes through tables each unit registers

- **Relations**: Implements TDD-00238 (Stage 3), Amends ADR-01323
- **Date**: 2026-10-01

## Context

[TDD-00238](../tdd/TDD-00238.md) compiles the builtin library once and
links it. After Stages 0–2 ([ADR-01323](ADR-01323.md)) a library class
has the same symbols and type ids in every program, but the runtime still
found what a type id means through code generated over the whole program
at finalize. A separately compiled library object could not contribute
to any of it:

- `__kml_obj_tostring_tag` and `__kml_obj_inspect_custom`: a compare
  chain over every class with the member;
- the host-box hooks (`__kml_host_inspect`, `_tag`, `_class_tag`,
  `_iter`, `_tojson`, `_toprim`, `__kml_host_is_<Class>`): a compare
  chain over every host layout;
- the shape table `@__kml_shapes`, one sorted array per program;
- the function-metadata table `@__kml_fnmeta_tab`, scanned linearly;
- the constructor-reference dispatchers (`__kml_dyn_instanceof`,
  `__kml_dyn_construct`, `__kml_ctor_kind`, `__kml_classref_*`,
  `__kml_constructor_of`): a compare chain over every class boxed as a
  value.

Two more depended on the whole program and were not in the TDD's list.
Each `instanceof` inlined the type ids of every subclass of its target
(`ClassInfo.Descendants`), and `x instanceof TypeError` inlined every
error class that extends `TypeError`. Library code testing against its
own class would miss a user subclass compiled after it.

## Decision

1. **A registry runtime.** `unitregsrc/unitreg.c` holds one hash table
   per kind of row. A row is any struct that starts with its i64 key.
   Each unit emits its rows as constant arrays, plus a constructor
   `__kml_unit_init` that hands them to `__kml_unit_register`. It runs
   from `@llvm.global_ctors` before `main`. `__kml_unit_find(kind, key)`
   returns the row. The program's constructor list is now collected in
   one place (`addCtor`), shared with `performance.now`'s time origin.
2. **The kinds**, each looked up by the dispatcher that switched before:

   | Kind | Key | Row |
   |---|---|---|
   | toStringTag | type id | the class's getter thunk |
   | inspect.custom | type id | the class's thunk |
   | host box | header word | the inspect routines by depth, toString, `[object X]`, class name, iterator, toJSON, toPrimitive |
   | shape | type id | `KmlShape`, unchanged |
   | function metadata | code pointer | `KmlFnMeta`, unchanged |
   | constructor reference | payload pointer | the class's rendering, static-field walkers, instanceof, ctorKind, construct, static get/set |
   | constructor of | type id | the class's reference payload |
   | class parent | type id | the base class's id, or the builtin Error kind's |

3. **`instanceof` walks the class chain.** `__kml_class_is(stored,
   target)` follows the registered parent ids from the stored id, as the
   prototype chain would. The bits above the id (the header magic, the
   Error flag) must agree. This replaces the compile-time descendant
   lists at all four sites: an `any` value, a static ancestor type, a
   caught value, and an error kind. As a result, `class B extends A {}`
   where `A extends TypeError` now answers `b instanceof TypeError`
   through any number of levels. Before, only direct subclasses of the
   kind matched.
4. **Thunk names are per target.** A class's routines are named after
   the class (`@__kml_cr_get.<class>`, `@__kml_tostring_tag_<id>`), and a
   class reference's payload is `@__kml_classref.<class>`. A library
   class's are therefore the same in every program.

Fixed in passing (each verified against Node):

- `util.inspect` prints `Name [Tag]` when an instance's
  `Symbol.toStringTag` differs from its class name, in both the static and
  the `any` path. Past the depth cap a class instance is `[Name]` (or
  `[Name [Tag]]`), not `[Object]`.
- `URL`, `URLSearchParams`, and the `Headers` and `URLSearchParams`
  iterators have their `Symbol.toStringTag`.
- `x.constructor` with `x: any` holding a class instance is its class (it
  was `undefined`).
- `new (5 as any)()` reports `5 is not a constructor`. The type assertion
  is erased from the message, as Node's type stripping erases it.

## Consequences

- Every dispatch is one hash lookup and an indirect call instead of a
  compare chain. A program with many classes gets faster dispatch; one
  with a single class pays the lookup. `instanceof` against a class
  costs one lookup per level of the chain.
- Each program links `unitreg.c` (cached with the other runtime objects,
  Stage 0).
- Error-kind references (`TypeError` as a value) are still keyed by an
  interned string, which is per unit. Stage 4 must give them a symbol
  shared between units.
- A dispatcher that falls back to a default for an unregistered key keeps
  its old default (`[Object]`, `[object Object]`, `undefined`, the
  TypeError).
