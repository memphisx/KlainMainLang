# ADR-01722: ECMAScript RegExp groups and `v` flag; coded errors are base instances

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-18

## Context

RegExp runs on PCRE2, which differs from ECMAScript in three places URLPattern's WPT data exercises:

- **Optional groups:** an optional group that matched empty reads `""` where JavaScript reads `undefined` (`/^(.*)(.*)?$/`, group 2).
- **`v`-flag class sets:** set operations (`[[a-z]--a]`, `&&`, `\q{…}`) never matched.
- **Invalid syntax:** a lone `]`/`}` or a bad `{` under `u`/`v` was accepted.

Separately, every coded error the builtin library throws (`ERR_INVALID_URL`, …) was a subclass instance, so `e.constructor.name` read `NodeTypeError` where Node reads `TypeError`. Building them as base instances hit two compiler gaps:

- **Inherited members lost:** an interface extending a builtin class (`interface E extends TypeError { code: string }`) lost the base's members, so `e.name` was "no field".
- **Name collision:** an interface and a function of one name collided in the resolver, although TypeScript keeps types and values in separate spaces.

## Decision

- **Class sets:** the `v` flag translates class sets to PCRE2 constructs before compiling.
- **Syntax checks:** `u`/`v` patterns are checked for lone brackets and incomplete quantifiers. A failure throws `SyntaxError: Invalid regular expression: /p/f: …` with V8's reason.
- **Optional groups:** after each match, a group inside an optional (`?`, `*`, `{0,…}`) group that matched empty is reported unset.
- **Interfaces over builtin layouts:** a program interface extending a builtin with a native layout (Error kinds, `Date`, …) is that layout.
  - Its own members are the instance's run-time properties.
  - `expr as I` and an `I` annotation keep the interface.
- **Type/value names:** an interface or type alias may share a name with a function or variable.
- **Coded errors:** `NodeError`/`NodeTypeError`/`NodeRangeError` are factory functions returning a plain `Error`/`TypeError`/`RangeError` carrying `code`, as Node's `lib/internal/errors.js` builds them.

Left open: a repeated group's final empty iteration (`/(a|)*/`), and PCRE2's wording for syntax errors outside these checks.

## Verification

macOS (Apple Silicon): `tests/regexp_es_fidelity_test.go` (RegExp groups and `v` flag, `u` brackets, URLPattern `v`-flag groups, interfaces over builtin layouts, coded-error constructor, type/value names) matches Node. The RegExp and URL suites pass.
