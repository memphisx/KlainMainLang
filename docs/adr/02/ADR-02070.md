# ADR-02070: The nested-error inspect head in C; one NaN-box header

- **Relations**: Implements TDD-00240, TDD-00230
- **Date**: 2026-11-23

## Context

`__kml_error_inspect`, the head line `util.inspect` prints for an Error
nested in another value (`{ e }`, `[err]`), was the last runtime routine
still written as IR text in `emit_record_view.go` (`TestIRTextOnlyShrinks`
allowance 1). Every program that inspects a boxed value generated it, and
hooks.c reached it through a hook pointer.

It also rendered the error as `String(err)` does, calling a `toString` the
error was given after construction. That differs from Node, which prints
the stack captured when the error was made: with `d.toString = () =>
"custom!"`, `console.log({ d })` printed a stray `\x02` byte where Node
prints `RangeError: r`.

Eight runtime C files (anystr, loose_eq, toprim, buffill, dynjson,
dynjsonnode, dynarr, dynobj) each kept a private copy of the NaN-box
encoder or decoder, several marked "keep in sync" with
`runtime_nanbox.go`; hooks.c had a ninth for the exported primitives.

## Investigation

- The generated body (`-emit-llvm`) depends on nothing in the program: it
  reads the error object's name and message fields and concatenates them,
  or calls `__kml_any_tostr` on the box when the error has an own
  `toString`.
- Node's `formatError` starts from `err.stack`; V8 fixes the stack's first
  line from `name` and `message` at construction. An own `toString` is
  never consulted.
- The NaN-box copies agree with each other and with `runtime_nanbox.go`.
  Every runtime C file is compiled after one prelude (`kml_heap.h` and the
  header-state constants, embedded_c.go), but kml_layout.h, which defines
  `KML_NB_DOUBLE_OFFSET`, reached only the 29 files whose source functions
  prepend it.

## Decision

- `__kml_error_inspect` is defined in dynjson.c, its only caller: the name,
  then `: message` unless the message is empty (`undefined`/`null` for an
  absent or null field). It reads the fields through `KML_ERR_NAME` and
  `KML_ERR_MESSAGE` from kml_layout.h, which `DynJSONSource` now prepends.
- The own-`toString` branch is dropped, as in Node.
- The hook (`hooks.c`, `hookFuncs`) and the IR generator are deleted, and
  so is the file's ratchet allowance.
- The prelude adds kml_layout.h and a new kml_nanbox.h: `kml_nb_pack`,
  `kml_nb_double`, `kml_nb_tag`, `kml_nb_pay`, `kml_nb_ptr`,
  `kml_nb_decode` and `kml_nb_number`, as `static inline` functions over
  `KML_NB_DOUBLE_OFFSET`. The eight copies are deleted and hooks.c's
  exported primitives call the header.

## Consequences

- Six IR-text definitions remain, all thunks generated per program or the
  IR emitter's own plumbing.
- The dynjson layout probe test force-includes the prelude's two headers
  and checks the shared encoder's answers against `runtime_nanbox.go`.
- `TestE2EErrorNestedInspectOwnToString` covers the head line.
- Verified on Node304 (Linux x86-64): nested errors, subclasses and an own
  `toString` print the same head lines as Node.
