# ADR-01159: Buffers through `any`, `typeof`-narrowed `any`, async generators as `[Symbol.asyncIterator]`

- **Relations**: `Implements TDD-00231` (stage 1, compiler gaps 2 and 3); `Implements TDD-00230` (P2.5, P3.3); `Extends ADR-01059`, `ADR-00889`
- **Date**: 2026-09-25

## Context

A Node stream keeps its chunks as `any` and converts a string written to a
non-object-mode stream to a Buffer:

```ts
push(c: any) { this.chunks.push(typeof c === "string" ? Buffer.from(c) : c) }
```

That line did not compile, and a Buffer stored as `any` did not stay one:

- `Buffer.from(c)` was "Buffer.from takes a string, array, …": codegen typed
  `c` as `any` inside the `typeof` guard.
- The checker did not narrow `any` at all. tsc narrows it by `typeof` and
  `instanceof`.
- `cond ? Buffer.from(c) : c` was "ternary branches have incompatible types
  (an array vs a non-array)". The rejection came before the check that
  makes a ternary with an `any` branch an `any`.
- A Buffer boxed into `any` became a plain number array:
  - `console.log` printed `[ 104, 105 ]` for Node's `<Buffer 68 69>`;
  - `Buffer.isBuffer(x)` was false;
  - `String(x)` was `104,105` for Node's `hi`;
  - `JSON.stringify(x)` was `[104,105]` for Node's
    `{"type":"Buffer","data":[104,105]}`.
- `async *[Symbol.asyncIterator]()` was "must return a class instance with a
  next() method": the loop did not accept the method's own async generator.
- Found on the way:
  - An object literal passed to a method's or a static method's `any`
    parameter printed `[object Object]`. The method paths emitted the
    argument without the parameter type as a hint, so the literal was a
    static object boxed. The free-function path, and since ADR-01158 the
    constructor, build it as a dynamic object.
  - A statically typed Buffer printed every byte. Node stops at
    `INSPECT_MAX_BYTES` (50): `<Buffer 61 … 61 ... 3 more bytes>`.
  - `JSON.stringify(buf)` of a statically typed Buffer gave `[104,105]`.
  - An `any` nested in a statically typed value lost its depth when
    `JSON.stringify` pretty-printed: the dynamic walker always indented from
    zero.

## Decision

- **Checker** (`narrowAny`, following tsc's `narrowTypeByTypeName`):
  - `typeof x === "string"` (and the other primitive names) narrows an
    `any` to that primitive; `"object"` and `"function"` keep it `any`; a
    host object's name gives `object`.
  - `x instanceof C` narrows it to C's instance.
  - Truthiness, equality and assignment keep it `any`.
- **Codegen reads the checker's narrowing** (`checkerNarrowed`). A read of an
  `any`/`unknown` identifier the checker narrows to one primitive is unboxed
  to it, the same conversion `x as string` makes. The inferred type mirrors
  it. This is the first place codegen takes a representation from the
  checker's type rather than its own decider (TDD-00230 P3.3). It applies to
  the strict lane only: `-compat=js` widens a binding assigned several kinds
  (`let x = 5; x = "hi"`) into an `any` the checker does not model.
- **Ternary.** A branch of type `any` makes the result `any` before any
  array or pointer rejection, so both branches are boxed.
- **A Buffer box kind.** The `any` array box's typed byte gains
  `anyArrayBuffer` (3). `dynjson.c` renders it:
  - inspected as `<Buffer 68 69>`, capped at 50 bytes;
  - as a string, its bytes as UTF-8;
  - as JSON, Node's `toJSON` form.

  `Buffer.isBuffer` on an `any` reads the box. The static Buffer's inspect
  calls the same C function (`__kml_buffer_inspect`) instead of its own IR
  loop, and its JSON boxes it and takes the same walker.
- **Pretty JSON.** The dynamic walker takes the depth it starts at
  (`__kml_dynjson_stringify_at`), used for indentation only; its cycle check
  still counts from the dynamic value.
- **Method arguments.** `emitClassCall` and `emitStaticMethodCall` build
  every argument against its parameter's type, as the other call paths do.
- **`for await` over `[Symbol.asyncIterator]()`** accepts an async (or sync)
  generator result and drives it as a generator.
