# TDD-00109: `tls` module — `tls.connect` (TLS client)

- **Status**: Implemented
- **Date**: 2026-08-24

## Context

`tls` is ❌ on [NODE-CORE-MODULES.md](../status/NODE-CORE-MODULES.md). All TLS
today is hidden inside libcurl (fetch, `http.listen` HTTPS); there is no direct
`SSL_*` code and no way to open an arbitrary TLS socket. A `tls` module is the
next networking primitive (tiebreaker #1) — most valuable as a **client**
(`tls.connect`) for talking to a TLS service directly (a REST endpoint, a
line-protocol server). `tls.createServer` needs cert/key loading + per-accept
`SSL_accept` + SNI for no shared-machinery gain, so it is a later stage.

## Backend — OpenSSL libssl

The `-crypto=openssl` backend already links **libcrypto** (`crypto.go`); libssl
ships in the same package/prefix. So:

- Compile a small C helper `tlssrc/tls.c` alongside the program (the exact
  `UsesCrypto()` pattern in `main.go`: write the `.c` next to the `.ll`, append
  `LocateCrypto("openssl")`'s `-I/-L` cflags, and `requireLink("ssl")` +
  `requireLink("crypto")`), gated on a new `UsesTLS()` predicate.
- **OpenSSL-only.** CommonCrypto has no TLS API (Mac's is the deprecated Secure
  Transport). If a program uses `tls`, force the OpenSSL discovery regardless of
  `-crypto`; a `-crypto=commoncrypto` program that also uses `tls` is a clean
  compile error.

The C helper keeps all `SSL_*`/`openssl/ssl.h` out of the emitted IR (same
posture as the crypto backend), exposing a tiny ABI:

```c
void*  __kml_tls_client_connect(int fd, const char* host, int reject_unauthorized, char** errout);
long   __kml_tls_read (void* ssl, void* buf, long n);   // <0 on fatal, 0 on clean close
long   __kml_tls_write(void* ssl, const void* buf, long n);
void   __kml_tls_free (void* ssl);
```

`__kml_tls_client_connect` builds a process-shared `SSL_CTX` (TLS_client_method,
`SSL_CTX_set_default_verify_paths`), `SSL_new` + `SSL_set_fd(fd)` +
`SSL_set_tlsext_host_name(host)` (**SNI**) + `SSL_set1_host(host)` for hostname
verification, `SSL_connect` (blocking), and — unless `reject_unauthorized==0` —
checks `SSL_get_verify_result()`. On any failure it writes a message to `*errout`
and returns NULL.

## Design

### `tls.connect(port, host[, options], onConnect?)` → a TLS socket

Reuse the `net` client wholesale (`__kml_net_connect` is the template):

1. Resolve `host` (`@__kml_dns_lookup`), build the `sockaddr_in`, **blocking**
   `connect()` — identical to `net.connect` (ADR-00328's "outcome known at
   establish time" posture; a failure throws a catchable `Error`).
2. `SSL* = __kml_tls_client_connect(fd, host, rejectUnauthorized, &err)` — a
   **blocking** handshake on the still-blocking fd. NULL → throw the `err`
   message as a catchable `Error`.
3. Set the fd O_NONBLOCK and register it in the **existing net connection
   registry**, storing the `SSL*` in a new socket-struct field.
4. Fire the `onConnect`/`'secureConnect'` listener.

**Socket representation.** Extend `netSocketIR` with one extra field holding the
`SSL*` (null for a plaintext `net` socket, non-null for TLS). `net`'s read/write/
close helpers branch on it: `SSL*` non-null → `__kml_tls_read`/`_write`/`_free`,
else raw `read`/`write`/`close`. A plaintext socket's new field is zero
(`calloc`), so **the net path is behavior-unchanged** — the whole net event-loop
registry, `dispatch` data/end machinery, and `.on('data')`/`.write()`/`.end()`/
`.on('close')` method dispatch are reused as-is. `tls.connect` returns a socket
of the same shape (a dedicated `IsTLSSocket` type-flag variant so the docs/errors
read "TLS socket", but structurally a net socket).

### options (V1)

An optional object literal: `{ rejectUnauthorized: false }` (accept a
self-signed / unverified cert — needed to talk to a local test server) and
`{ servername: "..." }` (override the SNI host, default = `host`). Anything else
(a runtime value, `ca`/`cert`/`key`/`secureContext`) is a clean compile error.

## Scope / exclusions (V1)

- **Client only** — no `tls.createServer` (cert/key + `SSL_accept` + SNI routing).
- **Blocking** TCP connect + TLS handshake (a slow host stalls the loop) — the
  same simplification `net.connect`/the WebSocket client already make; a
  non-blocking handshake needs new event-loop plumbing (a "retry when fd ready"
  primitive that doesn't exist yet).
- String/`Buffer` chunk handling follows `net`'s existing convention.
- No client-cert auth, no ALPN, no session resumption, no `tls.checkServerIdentity`
  override.

## Verification plan

Deterministic + offline: a **Go TLS server fixture** (`tools/tls-echo/`, a
self-signed cert generated in-process) that echoes a line. E2E: `tls.connect(port,
"127.0.0.1", { rejectUnauthorized: false })`, `.write("ping\n")`, collect
`.on('data')` → expect the echo; a handshake-failure case (`rejectUnauthorized:
true` against the self-signed fixture → catchable `Error`); a connect-refused
case. Example under `examples/tls/`. A real-host smoke test (`example.com:443`,
verified) is run manually and documented, not in the offline suite.
`make examples` + `make conformance` at the end.
