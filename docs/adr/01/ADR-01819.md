# ADR-01819: Arrays iterate through a replaced `Array.prototype[Symbol.iterator]`

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- Array destructuring, spread, `for…of` and `Array.from` walked an array's elements directly. Replacing `Array.prototype[Symbol.iterator]` changed nothing, and deleting it did not make arrays non-iterable. In Node, all four run the iteration protocol through the property. Test262's `*-array-prototype` destructuring tests exercise this: 36 in `statements/class/dstr` alone.
- `Array.prototype` had no `Symbol.iterator` property at all.
- In the js lane, destructuring or `for…of` over a value of no iterable type (`var [z] = 5`) was a compile error ("'n' is not an array"); Node throws a TypeError at run time.
- The "not iterable" messages named the source `value` or `object` where V8 prints the expression (`[1,2] is not iterable`) or describes the value (`number 5 is not iterable (cannot read property Symbol(Symbol.iterator))`).
- `arr[Symbol.iterator]` on a statically typed array was a compile error ("a Symbol cannot be converted to a number"), and in the js lane a run-time TypeError. Read through `any`, it gave a function that was not `Array.prototype.values`.

## Decision

- `Array.prototype` owns `[Symbol.iterator]`, the same function as its `values`. Both are the array iterator's own maker, which every read of either gives (`a.values`, `a[Symbol.iterator]`, the prototype's properties). Before, `a.values` and `a[Symbol.iterator]` read through `any` were two different functions.
- The runtime records that property's value when it makes the `Array.prototype` object. An array iterates through the protocol once the property no longer holds that value. A deleted property reads `undefined`, so the iteration throws `TypeError: … is not iterable`.
- The check is emitted only when the program names both `Array.prototype` and `Symbol.iterator`, directly or through an alias. Other programs keep the direct walk, with no added cost.
  - Destructuring, spread and `Array.from` of a statically typed array call `__kml_array_iter_patched()`. When it reports a change, they box the array and take the values the protocol yields, converted to the element type. Destructuring still takes only the values its pattern needs, then closes the iterator.
  - `for…of` over such an array iterates it as an `any`.
  - The builtins that iterate an argument take its values the same way: the `Set`, `WeakSet`, `Map`, `WeakMap` and typed-array constructors, and `Promise.all`, `allSettled`, `any` and `race`. A `Map` is filled through `for…of` over its entries, each checked as Node checks it (`TypeError: Iterator value 42 is not an entry object`).
  - The `any` paths leave the array fast path under the same check. Their shared helpers (`__kml_any_iter_collect`, `__kml_any_iter_take`) are reached for an array only once the property changed, so they always run the protocol for one.
- An array's `[Symbol.iterator]` read is the property as it is now. A symbol-keyed index on a statically typed array reads through its box, typed `any`.
- A js-lane iteration of a number or boolean value is compiled as one of `any`, which throws at run time.
- The "not iterable" message follows V8:
  - It prints the expression when V8's call printer would: names, literals, array literals, binary operations, a call as its callee, and a spread's property path.
  - It describes the value for a destructured property or parameter: `undefined`, `null`, `object`, or the primitive's type and value.

## Consequences

- Library code iterates its own arrays directly, as before; the check lives in the program's code.
- `TestE2EJSFileArrayIteratorReplaced` and `TestE2EJSFileIterateNonIterable` cover each path and message against Node.
