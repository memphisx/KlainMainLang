# ADR-00794: Response.text()/.json()/.arrayBuffer() return real Promise<T>

- **Relations**: `Implements TDD-00186`, `Extends ADR-00094`
- **Date**: 2026-09-08

## Context

WHATWG's `Response` body accessors — `.text()`, `.json()`, `.arrayBuffer()` —
return a `Promise<T>`; a program awaits them (`await res.json()`) or chains a
reaction (`res.text().then(...)`). This compiler returned the *value* directly
(a `string`, a parsed object, an `ArrayBuffer`), leaning on `await`-of-a-
non-thenable being identity so `await res.text()` still worked. The observable
consequence — the last unfaithful edge of the fetch body path (BACKLOG §1.2,
TDD-00186 Part B):

- The *return type* was `T`, not `Promise<T>`: `res.text().then(...)` had no
  `.then` to call, and `Promise.all([res.text(), ...])` saw bare strings.
- The unfaithful non-await forms *compiled*: `const s: string = res.text()` and
  `new Uint8Array(res.arrayBuffer())` were accepted, where real TS rejects them
  (a `Promise` is not a `string`/`ArrayBuffer`).

Note this was never a *blocking* gap: `__kml_await_fetch` already parks the fiber
(ADR-00050), so `await res.json()` never froze the loop. Purely a return-type /
thenability faithfulness fix — hence TDD-00186 sequenced it after Part A.

## Investigation

- The body is buffered synchronously at the accessor call: `emitResponseBody` /
  `emitResponseArrayBuffer` (`emit_fetch.go`) call `emitResponseDriveToDone`,
  which drives the parked transfer to completion (yielding inside an
  `http.listen` fiber, busy-spinning at top level) — so the value is *ready* at
  call time; only the wrapper type was wrong.
- A settled-task-promise helper already existed: `wrapSettledTaskPromise`
  (`emit_call_crypto.go`) boxes an already-computed value into a fulfilled
  `__kml_task_alloc_promise()` (state 1), the same shape a non-suspending async
  function returns (`emitSettledAsyncEpilogue`) and `await`-of-a-plain-value
  builds. `crypto.subtle` already uses it for exactly this reason.
- `await` on such a promise routes through `emitAwaitTaskPromise` (the type is
  `PromiseTask`), which returns the value after a microtask tick — the faithful
  deferral WHATWG requires.

## Decision

Wrap each accessor's computed value in a settled task promise, and report the
matching `Promise<T>` from `inferExprType`:

- `emitResponseCall` (`emit_fetch.go`): `text()` → `wrapSettledTaskPromise(body)`
  (`Promise<string>`), `json()` → wrap the parsed value (`Promise<T>`),
  `arrayBuffer()` → wrap the header (`Promise<ArrayBuffer>`).
- `inferExprType` (`emit_exprs_types.go`): the `text`/`json`/`arrayBuffer` arms
  on an `IsResponse` receiver return `PromiseOf(...)`/`PromiseTask`. `Blob`'s own
  `.text()`/`.arrayBuffer()` stay synchronous (their separate scope, unchanged).
- The `res.json() as T` arm (`emit_call.go`) still supplies the parse target but
  now returns `Promise<T>` — awaited like any other.

**Deliberate carve-out kept:** a *typed declaration* still parses `json()`
straight into the annotation without the promise box —
`const p: T = await res.json()` and, for back-compat, the no-await
`const p: T = (await fetch(u)).json()` both work through `emitDeclJSONProjection`
(the same projection `const p: T = JSON.parse(s)` uses). This is the one
ergonomic exception; every other position (`text()`, `arrayBuffer()`, untyped or
expression-position `json()`) now yields a real `Promise<T>` that must be
awaited. `text()`/`json()` remain strlen-based; `arrayBuffer()` carries the real
byte count (ADR-00094) — unchanged, only re-wrapped.

## Consequences

- `res.text().then(...)`, `Promise.all([a.text(), b.text()])`, and passing a body
  promise anywhere a `Promise<T>` is expected now work.
- The non-await forms that encoded the old synchronous behavior became compile
  errors (a `Promise` assigned to `string`/consumed as a length). Every such site
  in the tree — the fetch/http/stream tests and the fetch examples — was updated
  to `await`.
- **Perf gap deferred (not a behavior divergence):** the body is still buffered
  at the accessor call, not lazily at await/`.then`. So `const p = res.json();
  work(); await p` does not overlap `work()` with the download the way Node does.
  This is a concurrency/perf follow-on (a lazy body promise settled off the fetch
  reactor completion, TDD-00186 open question), recorded in the backlog — the
  observable value semantics are already faithful.
- **Edge:** a JSON parse error surfaces at the `json()` call, not as a promise
  rejection a `.catch` could see. Bounded by the same lazy-promise follow-on.
