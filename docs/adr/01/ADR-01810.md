# ADR-01810: generator functions own a prototype their instances inherit

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- A generator function had no `prototype`, and `Object.getPrototypeOf` on an instance did not compile. Test262's `default-proto` and `prototype-value` exercise the model, which programs use to add methods to every instance (`g.prototype.m = …`).
- In JavaScript, a generator function's own `prototype` is a fresh object inheriting `%GeneratorPrototype%` (`%AsyncGeneratorPrototype%`). Each call makes an instance whose `[[Prototype]]` is the function's `prototype` at that moment, or the root when that is not an object. The function's own prototype is `%GeneratorFunction.prototype%`, whose `prototype` is the root.

## Decision

- Runtime (`fnmeta.c`):
  - The roots, carrying `Symbol.toStringTag`, and `%GeneratorFunction.prototype%` are made on first use.
  - A generator function's own-property bag always exists. `__kml_fn_props_dyn` makes it on first access, and its seed adds a writable, non-enumerable `prototype`.
  - The seed now takes `length` and `name` from the function's own view, since the bag does not exist yet while it is being made.
- Instances:
  - The generator layout gains a first field, `__proto`. It sits at one offset in every layout, and the compiler emits that offset as `__kml_gen_proto_off`.
  - At creation, a capture-free generator's function value (made on demand) gives its bag, cached beside the value, and `__kml_gen_instance_proto` gives the prototype.
  - The instance takes its prototype before the parameter defaults run, as V8 does. The spec orders it after them, so a default reassigning the function's `prototype` changes the instance's prototype there and not in Node. Node's order is kept (Test262's `generator-created-after-decl-inst` fails as it does in Node).
- Reads:
  - A member the generator's shape row lacks is read off the recorded prototype (`shape.c`).
  - A call of a method other than `next`/`return`/`throw` is a dynamic call on the boxed instance, and such a member is inferred as `any`.
  - `Object.getPrototypeOf` answers the recorded prototype for an instance, and `%GeneratorFunction.prototype%` for a generator function.
- The work is gated on the program naming a prototype (`prototype`, `__proto__`, `isPrototypeOf`, `getPrototypeOf`, `setPrototypeOf`, as a member or a string key). Elsewhere the field stays 0, and a program that never observes the chain pays nothing at creation.

## Consequences

- A capturing (nested, closing over locals) generator's instances inherit the root rather than their function's `prototype`. Such a generator makes a new function value on every reference, so it has no single `prototype` to record.
- `%GeneratorFunction.prototype%` inherits `Object.prototype` rather than `Function.prototype`, which is a function record and not a property bag here.
- `TestE2EJSFileGeneratorPrototypes` covers identity, the function's prototype, own property names, methods and fields added through `prototype`, rendering, the async root, `prototype = null` before and during a call (Node's order), and `new` on a generator (ADR-01811).
