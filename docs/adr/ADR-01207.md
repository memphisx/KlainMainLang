# ADR-01207: URLs take any scheme; TLS checks an IP host against IP names

- **Date**: 2026-09-28

## Context

Found writing the WebSocket client (TDD-00232 Stage 2):
`new URL("ws://127.0.0.1:8981/")` threw "Invalid URL", and a malformed URL
threw a plain `Error` where Node throws a `TypeError` with
`code: 'ERR_INVALID_URL'`. Then `wss://127.0.0.1` failed against a
certificate that lists IP 127.0.0.1: "Hostname/IP does not match
certificate's altnames".

## Investigation

- `new URL` parses with libcurl's `curl_url_set`, which rejects a scheme
  curl has no protocol handler for unless given
  `CURLU_NON_SUPPORT_SCHEME`; the WHATWG parser takes any scheme.
- `__kml_native_tls_start` (`tlssrc/tlshandle.c`) called
  `X509_VERIFY_PARAM_set1_host` first and `set1_ip_asc` only if it failed;
  `set1_host` accepts an IP string, so an IP was matched against DNS
  names. `tls.connect` also passed no name at all for an IP host, and then
  checked nothing, where Node checks the IP.

## Decision

- Every URL-parsing `curl_url_set` passes `CURLU_NON_SUPPORT_SCHEME`, and
  the parse failures throw Node's coded `TypeError`. A `ws:` URL on port
  80 or a `wss:` one on 443 has its port cleared before the fields are
  read (`__kml_url_ws_default_port`): curl strips only the defaults of the
  schemes it supports.
- The TLS client checks an IP literal with `set1_ip_asc` and sends no SNI
  for it (RFC 6066); a name gets SNI and `set1_host`. `tls.connect` always
  passes the host to check (`servername`, else `host`), and
  `socket.servername` stays `false` for an IP, as Node's.
- An altname mismatch carries Node's `checkServerIdentity` reason: the
  certificate's names (`tlsInfo` 7, printed as Node prints
  `subjectaltname`) or its IP addresses, or its CN.

## Implementation notes

`codegen/llvm/emit_url.go`, `emitter.go`, `codegen/llvm/tlssrc/tlshandle.c`,
`lib/node/tls.ts`.

## Side effects discovered

None.

## Verification

v24.19; `TestE2EWSSClientEcho` connects to an `httptest` TLS server by IP;
`TestE2ETLSAltnameMismatchMessage` matches Node; the TLS and HTTPS tests
pass.
