# ADR-01183: Stream operators, `Readable.from`, `signal`, `pipeline`/`compose`/`Duplex.from`, FileHandle, and the request stream on `Readable.fromWeb`

- **Relations**: `Implements TDD-00231`, `Extends ADR-01161`, ADR-01166
- **Date**: 2026-09-28

## Context

TDD-00231's `stream` port lacked the operators (`map`, `filter`, `toArray`,
…), `compose`, the `signal` option, the fs streams' `fs`/`signal` options and
a `FileHandle` `fd`; `Readable.from` accepted only array-likes; `pipeline`
only streams; and klain:http's request still became a Node Readable through
the code-generated node-stream runtime (`emit_node_stream.go`,
`runtime_node_stream.go`).

## Investigation

Each piece was ported from Node v24's own source (`operators.js`,
`from.js`, `add-abort-signal.js`, `pipeline.js`, `duplexify.js`,
`compose.js`, `internal/fs/streams.js`, `internal/fs/promises.js`). The
compiler gaps they hit are fixed at their origin (ADR-01181, ADR-01182).

## Decision

- **Operators** as `Readable` methods: `map` (with `concurrency` and
  `highWaterMark`, calls in flight, results in order), `filter`, `flatMap`,
  `drop`, `take` wrap their async generator in `Readable.from`; `forEach`,
  `toArray`, `some`, `every`, `find`, `reduce` return promises; Node's
  argument validation and AbortError.
- **`Readable.from`** reads the iterable's `[Symbol.asyncIterator]`/
  `[Symbol.iterator]` through `any` (Node's `from.js`: sync values,
  promise values, async iterators, closing the iterator on destroy).
- **`signal`** on Readable/Writable/Duplex and the exported
  `addAbortSignal`.
- **`pipeline`**: an array of stages, async generator transforms, iterable
  sources, a promise-returning last stage (its value to the callback and to
  `stream/promises`' `pipeline`), `{ signal, end }`. **`Duplex.from`**
  (duplexify) and **`compose`**.
- **`FileHandle`** (fs/promises' `open()`): `fd`, `read`, `write`,
  `writev`, `sync`, `datasync`, `stat`, `truncate`, `chmod`, `utimes`,
  `readFile`, `writeFile`, `appendFile`, `close` (waiting for the streams
  that hold it), `createReadStream`, `createWriteStream`. The fs streams take
  `fd` as a FileHandle, `fs` (the operations called as given) and `signal`.
- **klain:http's request stream** is `stream`'s `_kmlFromWeb` over
  `req.stream()`, held as `any` and dispatched through its layout; the
  resolver includes `stream` in a klain:http program, and codegen calls a
  builtin module's export through `Program.LibExports`. The code-generated
  node-stream runtime, its types (`IsNodeReadable`/`IsNodeWritable`) and the
  dead `stream`/`stream/promises` virtual-module tables are deleted.

## Implementation notes

`lib/node/stream.ts`, `lib/node/stream_promises.ts`,
`lib/node/internal_fs.ts`, `lib/node/internal_fs_promises.ts` (new);
`resolver/resolver.go` (`LibExports`, klain:http pulls in `stream`),
`resolver/virtual_modules.go`, `resolver/rename.go`, `ast/nodes.go`;
`codegen/llvm/emit_http.go` (`reqAsNodeReadable`), `emit_call.go`,
`emit_stmts.go`, `emit_exprs_types.go`, `emit_strings.go`, `types.go`;
`emit_node_stream.go` and `runtime_node_stream.go` removed.

## Side effects discovered

Windows keeps no companion modules (`fs` streams, `http`, `net`, …), so
these are POSIX until the Windows work in TDD-00231 lands.
