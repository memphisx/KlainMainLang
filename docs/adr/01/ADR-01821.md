# ADR-01821: A static method's `this` is its call's receiver

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- `this` in every static member was rewritten to the class's name. A static method inherited by a subclass read the base's statics (`D.who()` gave `C`'s `tag`), `new this()` built the base, `C.m.call(o)` ignored `o`, and `this.#p` never threw its brand-check TypeError.
- `super.m()` in a static method did not compile.

## Decision

- A static method reading `this` (or `super`) whose receiver may be other than its class takes it as a leading `this` parameter, typed `any`, the way a function declared `function f(this: T)` does. Its receiver may differ when some class extends it, or when the class or one of its static methods is used as a value (other than `C.f` / `C.m(…)`). A builtin module's class always takes it, so its code does not depend on the program.
- A direct call passes the class it names (`D.m()` passes `D`). A call through the method's value passes that call's `this`, as for any function taking `this`.
- `super.m(…)` in a static method is `Base.m.call(this, …)`; `super.f` reads `Base.f`.
- `this.#p` (read, write, update, call) in such a method checks that the receiver is the class itself, else throws V8's TypeError (`Cannot read private member #p from an object whose class did not declare it`, `Cannot write private member …`, `Receiver must be class C`), then uses the class's own member.
- Every other static member keeps `this` as the class's name: static field initializers and static blocks (whose receiver is always the class), and methods whose receiver cannot differ.
- A function's `length` no longer counts a `this` parameter.

## Consequences

- Static methods with a receiver parameter read the receiver's members dynamically, as a `typeof C` value does.
