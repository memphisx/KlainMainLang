# ADR-02005: Array statics with a constructor as `this`; ArrayCreate length

- **Date**: 2026-11-21

## Context

`Array.from.call(C, items)`, `Array.of.call(C, …)` and
`Array.fromAsync.call(C, items)` returned a plain array and never called
`C`. ECMAScript builds `new C()` (`new C(len)` for an array-like and for
`Array.of`), defines each element on it, then sets its `length`. On the
Test262 js lane, `Array/fromAsync/this-constructor-with-unsettable-element-
closes-async-iterator.js` looped until its timeout at about 1 GB, because
the element definition that should fail and close the iterator never ran.

While probing the same code: `Array.from({ length: 2**32 })` grew past
10 GB. ArrayCreate refuses a length over 2^32 − 1 with a RangeError, and
Node throws `RangeError: Invalid array length` at once.

## Decision

- `Array.from`, `Array.of` and `Array.fromAsync` named directly and called
  through `.call(C, …)` (or `.apply(C, [ … ])`) lower to library forms that
  take C. When C is a constructor other than Array, they construct it,
  define each element with `Object.defineProperty` (a refused definition is
  a TypeError, which closes the iterator) and set `length` (a failed set
  throws). Any other `this` gives a plain array.
- The array-like paths of `Array.from` (static and run time) and
  `Array.fromAsync` throw `RangeError: Invalid array length` for a length
  over 2^32 − 1, before reading any element.

## Implementation notes

- lib/node/kml_array_ctor.ts (a module of its own, linked only by a
  program naming `Array.fromAsync` or a static's `.call`/`.apply`):
  `__kml_Array_fromCtor`, `__kml_Array_ofCtor`, `__kml_Array_fromAsyncCtor`;
  the length check in `__kml_Array_fromAsync`.
- codegen/llvm/emit_func.go: `arrayStaticCtorCall`; codegen/llvm/emit_call.go:
  its use at the head of `emitCall`.
- codegen/llvm/emit_iter_collect.go (`__kml_any_arraylike_collect`),
  codegen/llvm/emit_arrays_iter.go: `emitArrayLengthCheck`.
- A static read as a value first (`const f = Array.from; f.call(C, …)`)
  still ignores C.

## Verification

- `TestE2EArrayStaticsWithConstructorThis` matches Node (js lane).
- Test262 on Linux x86 (Node304), js lane: `Array/from` 32 → 38 of 47,
  `Array/of` 6 → 11 of 16, `Array/fromAsync` 56 → 64 of 95; strict lane:
  `Array/from` 11 → 12, `Array/of` 3 → 5. No test there is stopped by the
  memory cap.
- `Array.from({ length: 2**32 })` throws at 3 MB resident.
