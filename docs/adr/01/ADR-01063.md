# ADR-01063: An omitted optional field has no key — inspect/`Object.keys`/`in` presence, optional tuple absence, and null-safe object inspection

- **Relations**: Extends ADR-00779 (optional fields as `T | undefined`), ADR-01041 (optional array absence), ADR-00246 (tuple absence, now closed for heap tuples), ADR-00218 (util.inspect rendering); Implements TDD-00187 (the field-absence residue)
- **Date**: 2026-09-22

## Context

BACKLOG §0 items 5 and 6: `console.log({ name: "a" })` for an `interface P { name: string; age?: number }` printed
`{ name: 'a', age: undefined }` where Node prints `{ name: 'a' }`; an omitted optional *tuple* field had no absence
at all (`o.pair === undefined` was `false`). Reducing the repro found more of the same family: `Object.keys(a)` listed
the absent keys and `"age" in a` was a static `true`; a tuple printed as `1,a` (the String join) at top level and as
`[Object]` inside an object; an inline `{ y: number } | null` field or a `[number, number] | null` field lost its
`| null` in the type resolver, so the inspector dereferenced the null pointer (garbage numbers, or a segfault with
several such fields).

## Investigation

- `emit_call_json.go`'s `emitJSONStringifyObjectOptional` already did the right thing for JSON: a runtime "emitted
  anything yet" flag and a per-field presence test (nullable-scalar presence bit / non-null array header / non-null
  pointer) for every `jsonFieldSkippable` (`T | undefined`) field. `emitInspectObject` (`emit_inspect.go`) walked the
  static field list unconditionally; `emitObjectKeys` returned the static names; `emitHasOwnProperty` (which `in`
  reuses) returned a compile-time constant.
- `undefinedableElem` (`emit_undefined.go`) refused to widen any tuple. That was written for the by-value tuple
  aggregate (`TupleByVal`, TDD-00134), but a heap tuple is an ordinary object pointer — null is a perfectly good
  absent state, exactly as for an object field.
- `resolveType` (`emitter.go`) applied `ta.Nullable` for named interfaces, enums, error kinds and the name fallback,
  but the inline-object-type and tuple branches returned before that check.
- `emitInspectField` had a `select` between the keyword and the rendered value for a nullable *array* (safe: a null
  data pointer inspects as `[]`), but an inspectable object went straight to `emitInspectObject`, which loads
  through the pointer — a `select` cannot work there, it must be a branch. Tuples fell to the `[Object]`
  placeholder because `isInspectableObject` excludes `IsTuple`.

## Decision

1. **One presence predicate.** `emitFieldPresent(objRef, objTy, field)` (`emit_undefined.go`) loads a field and
   returns `(present, value)`: the constant `"true"` for a non-optional field, else the same test JSON uses.
   `hasSkippableField` says whether an object has any optional field.
2. **Inspect omits absent fields.** `emitInspectObject` accumulates into a runtime slot with an "emitted" flag when
   the object has a skippable field; the key/separator is appended only behind the field's presence branch, and an
   object whose every field is absent renders `{}` (Node). Objects without optional fields keep the static path.
3. **`Object.keys` filters, `in`/`hasOwnProperty` test at runtime.** `emitObjectPresentFieldNames` builds the names
   array behind per-field presence branches; `emitHasOwnProperty` returns the presence bit for a skippable field.
4. **Optional tuple fields are `T | undefined`.** `undefinedableElem` excludes only `IsTuple && TupleByVal`; a heap
   tuple widens like an object and reads back a real `undefined` when omitted.
5. **Inline `{…} | null` and `[…] | null` annotations keep their nullability** in `resolveType`.
6. **Tuples inspect like arrays** — `emitInspectTuple` renders `[ 1, 'a' ]` (fields "0", "1", …, recursing through
   `emitInspectField`); `console.log(tuple)` uses it too (a by-value tuple keeps the join). **Nullable
   object/tuple values branch** through `emitInspectNullablePtr`: null → keyword (`undefined`/`null` by static
   type), else render — a real branch, never a `select` over a dereference.

## Implementation notes

`codegen/llvm/emit_undefined.go` (helper, tuple widening), `emit_inspect.go`, `emit_objects.go` (keys, hasOwn),
`emit_call_console.go` (top-level tuple), `emitter.go` (resolveType). The nullable-pointer branch stores its result in
an alloca slot rather than a phi, matching the file's other branch-and-merge idiom.

## Side effects discovered

- **`n?: T | null`: an explicit `null` and an omitted field are the same null pointer**, so every key-omitting
  consumer (inspect, JSON, keys, `in`) treats `{ n: null }` as omitted; Node keeps the key with `null`. A presence
  bit for nullable pointer fields would fix it; recorded as a caveat on the Interfaces row.
- **`Object.values`/`entries`/`for...in` still list an omitted optional field** (their element types are the
  static union); caveat on the `Object.keys` row.
- **Node's 72-column `breakLength`**: Node prints a long object across lines; the inspector always uses one line.
  Caveat on the `console.log` row.
