# ADR-01314: Three-state pointers and key presence

- **Relations**: `Implements TDD-00230` (P3.3); `Extends ADR-01063`, `ADR-01117`
- **Date**: 2026-09-30

## Context

A string or object typed `T | null | undefined`, or an optional member
`x?: T | null`, held both absences as the null pointer. Found on macOS arm64
with a REST-shaped DTO, `interface Dto { id: number; name?: string | null }`:

- `{ id: 1 }` serialized as `{"id":1,"name":null}`; Node omits the key.
- `name === undefined` and `name === null` were both true.
- `console.log` printed `null` for a missing field.
- `JSON.parse` into the DTO filled a missing string field with `""`, and a
  JSON `null` in it with `""` too.

Separately, `console.log`, `Object.keys` and `in` dropped every field holding
`undefined`:

- a class field (`C { name: undefined }` in Node);
- an object literal's own property (`{ v: undefined }`);
- a non-optional `b: number | undefined`.

Only a missing optional member has no key in JavaScript.

## Investigation

- The parser folds `null` and `undefined` union members into
  `Nullable`/`Undefined` flags, and `convUnion` lost whether `null` was one of
  them once `undefined` was.
- TDD-00230 P3.3 specifies a pointer with a presence bit for the case where
  the type distinguishes the absences. A spare bit in the pointer would break
  every dereference. A distinguished address does not: the null pointer
  keeps meaning undefined, which is also what a calloc-zeroed missing field
  reads as, and one sentinel address means null.
- Most readers do not care which absence it is (`??`, `?.`, truthiness).
  Those that do (printing, JSON, equality, `typeof`, boxing) have a few
  entry points.
- Codegen's `Field` had no notion of optionality; presence was decided by
  the value's type (`T | undefined` was skippable wherever it appeared).

## Decision

- **`HasNull`** on the type annotation records a `null` union member.
- **`Type.NullAndUndef`** marks a string, object, class instance, Map or Set
  pointer holding both absences. It is set in three places:
  - `resolveType`, when the annotation has both;
  - `optionalFieldType`, for an optional member or parameter over
    `T | null`;
  - `reprOfUnion`, for the checker's type with both.

  Ternaries (`ternaryNullablePointerType`) produce it when their branches
  bring both absences. `canonicalizeClassTy` carries it.
- **Encoding.** The null pointer is undefined. `nullRef` is null: the
  address of a zeroed global cell with a string header, so an unguarded
  read sees `""` or zeroed fields rather than faulting.
- **Scalars.** A number or boolean keeps its `{ i1 present, T }` slot. An
  absent slot with payload 0 is undefined, and one with payload 1 (as
  integer bits, `triMarker`) is null. Readers that ignore an absent slot's
  payload are unaffected, and a calloc-zeroed missing field is undefined.
  The nullable-scalar boxing, stores and comparisons go through
  `toThreeState` and `isTriNull`. A Map whose value type is a three-state
  scalar stores `any` boxes (`forceAnyMapVal`), since a value slot is one
  word.
- **Producers.** `coerce` converts into the three-state form
  (`toThreeState`: a null-typed null becomes `nullRef`) and out of it
  (`fromThreeState`: both absences become the null pointer). Object
  declarations and the JSON projection store through it.
- **Readers.**
  - Strict `=== null` and `=== undefined` test the sentinel and the null
    pointer; loose `==` tests either. The early nullable-scalar fold defers
    for these values.
  - `??`, `?.`, optional calls and truthiness normalize with
    `fromThreeState`.
  - `typeof` gives `"object"` for the sentinel.
  - String conversion, `console.log`, inspect and JSON render the sentinel
    as the null literal (`renderThreeState` branches, so a renderer that
    returns owned strings keeps ownership). Boxing into `any` boxes it as
    null.
- **Key presence.** `Field.Optional` marks a `?` member. It is set by
  interfaces, type literals, generic instantiation, ambient declarations,
  `Partial`, and mapped types with `?` or a homomorphic source's `?`. Class
  fields are not optional, since Node defines them all.
  `emitFieldPresentAt` reports every other field present, so inspect,
  `Object.keys`, `in` and spread keep an undefined-valued key. JSON still
  omits `undefined` values, as JSON does. `substituteAnnotation` now keeps a
  type literal's `?`.
- **`delete o.f`** of an optional member of a fixed-shape object stores the
  absent value. A required member stays a compile error, as in TypeScript
  (TS2790).
- **JSON projection.** A missing or null nullable string field is absent,
  not `""`; a three-state field's JSON null is `nullRef`.

## Implementation notes

- `emit_undefined.go`:
  - the eligibility test and the flag (`threeStateEligible`,
    `withNullAndUndef`);
  - the storage types (`optionalFieldType`, also used by
    `optionalParamType`);
  - the sentinel and its conversions (`nullRef`, `toThreeState`,
    `fromThreeState`);
  - the tests and rendering (`isNullRef`, `isAbsentPtr`, `absentWordRef`,
    `renderThreeState`).
- Mapped types ignored `?` entirely before; they now widen and mark the
  member.

## Side effects discovered

- An optional member explicitly set to `undefined` (`{ a: undefined }`
  against `a?: number`) still prints as missing: the slot cannot tell it from
  a missing key.
- Arrays (`T[] | null | undefined`) and function values keep the
  two-state form.
- Found along the way and fixed:
  - `c ? undefined : 5` was typed as `number | null`;
  - `new Map<K, V | null>` rejected null entries as heterogeneous;
  - `{ ...rest }` dropped its members' optionality.
- A sync generator's `next()`, `.throw()` and `.return()` results give
  the program `value: T | undefined` (`emitUserGenResult`, the
  `__hasret` field). Once the generator is done, value is undefined, except
  on the step that completed with `return expr` or `.return(v)`. Before,
  a number element read 0. The internal result the runtime's own loops
  read (`for...of`, `yield*`) keeps its plain layout. A `Generator<T,
  TReturn>` whose TReturn differs in representation from T still reads
  the return value as a T.

## Verification

Both files compare against Node (`assertSameAsNode`) on macOS arm64:
- `tests/three_state_test.go`: strings, objects, numbers and booleans
  (locals, parameters, returns, ternaries, arrays, Map values, fields), a
  DTO through `JSON.parse`/`JSON.stringify`, and optional nullable members,
  covering every reader above and `delete`;
- `tests/field_presence_test.go`: class, literal, interface, `Partial`,
  mapped and generic-alias fields, and the typed JSON projection.
