# ADR-00588: net.connect IPC (Unix-domain socket) form

- **Relations**: Extends [ADR-00328](ADR-00328.md), [ADR-00413](ADR-00413.md)
- **Date**: 2026-09-01

## Context

`net.connect` supported TCP only (`(port, host)` / `{ port, host }`); the IPC
`net.connect({ path })` form — connecting to a Unix-domain socket — was
unsupported. Unix sockets are common for local microservice IPC (a Docker
sidecar, a database socket), a target use case for this compiler.

## Decision

Add `__kml_net_connect_unix(path)` — an `AF_UNIX`/`SOCK_STREAM` blocking connect
that registers the fd in the same connection-socket registry as the TCP path, so
the whole `on('data'|'end'|'close')`/`write`/`end`/`destroy` surface applies
unchanged. `sockaddr_un`'s `sun_path` starts at offset 2 on both Linux and
macOS; the two preceding bytes differ (Linux: a 2-byte `sa_family_t`; macOS/BSD:
a 1-byte `sun_len` + 1-byte `sun_family`), so the family bytes are stamped
per-platform from `runtime.GOOS`. The emit side detects `{ path }` in the
options object (mutually exclusive with `port`) and routes to it; the
post-connect tail (fail-throw, deferred `'connect'` listener) is shared with the
TCP form via a new `finishNetConnect` helper.

## Verification

Round-trip against a real Node `net.createServer` listening on a Unix socket
path (`net.connect({ path })` → write → echo), verified on Mac (Apple Silicon).
The `sun_len`/`sun_family` byte layout differs on Linux and is branched on
`GOOS` but **not yet verified on Linux** — flagged in the status note per this
project's platform-verification practice. The existing net suite still passes.
