# ADR-00997: instanceof survives class-instance widening into `any`

- **Relations**: Extends ADR-00990
- **Date**: 2026-09-17

## Context

Two tests regressed — `TestE2EInstanceOfDynamicThroughInheritance` and
`TestE2EInstanceOfAnyNarrowsBetweenClasses` — both of the form
`const x: any = new C(); x instanceof C`, now returning `false`. Bisecting
against clean HEAD confirmed the regression rode in with the allocation-site
widening of ADR-00990 (TDD-00155 Stage 6): a fresh `new C()` of a data-only
class flowing into an `any` position is realized as a D1 dynamic object bag
(tag `kmlTagDynObject`) so member access / `Object.keys` / JSON / mutation work
on the `any` binding.

`emitInstanceOf`'s dynamic arm only handled a *raw* class instance box (tag
`kmlTagObject`), reading the class TagID from struct field 0. A widened bag has
tag `kmlTagDynObject`, so the `tag == kmlTagObject` gate failed and the result
was `false`. The bag also carried no record of the class it came from, so the
class identity was simply lost across the widening.

## Investigation

- `emit_dynobj.go:emitBoxValueWidened` → `emitStaticObjToBag` builds the bag; it
  had no place to record the source class.
- The bag header (runtime_dynobj.go) was 40 bytes across offsets 0/8/16/24/32;
  no code reads beyond offset 32, and only `__kml_dynobj_new`'s `calloc`
  allocates it — so a new trailing field is a localized, zero-initialized change.
- The three passing widening tests (`TestE2EWidenFreshClass*`, dynobj_test.go)
  require the bag representation for member access, so *not* widening classes
  was not an option — the bag must instead carry the class identity.

## Decision

Record the class's instanceof TagID in the bag and read it back in instanceof:

- Grow the bag header to 48 bytes; offset 40 holds an `i64 classtag`
  (`calloc`-zeroed, 0 = not from a class). New runtime helpers
  `__kml_dynobj_set_classtag` / `__kml_dynobj_classtag`.
- `emitStaticObjToBag`: when the source type is a class, store its `TagID`.
- `emitInstanceOf`'s dynamic arm now branches: a `kmlTagObject` box reads the
  TagID from field 0 (as before); a `kmlTagDynObject` bag reads it from the bag
  classtag; both feed the shared ancestor/descendant TagID comparison via a phi.
  A non-class bag has classtag 0, which matches no user class → `false`, correct.

## Implementation notes

- `emitErrorInstanceOf` is untouched: Error subtypes carry methods and are never
  widened to bags, so an Error instance in `any` stays a `kmlTagObject` box.
- The dynjson.c and runtime_dynobj.go layout contracts both note offset 40 to
  stay in sync.

## Verification

- Both regressed tests pass again; the `TestE2EWidenFreshClass*` member-access /
  identity / all-boundaries tests still pass; new
  `TestE2EWidenClassInstanceofAndMembers` exercises instanceof and member access
  on the same widened instance.
- `make examples` (bag-layout change) and full `make test-par` clean.
