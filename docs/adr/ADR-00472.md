# ADR-00472: conformance oracles measure under `-compat=js` shadowing

- **Relations**: Extends [TDD-00121](../tdd/TDD-00121.md), [TDD-00075](../tdd/TDD-00075.md)
- **Date**: 2026-08-29

## Context

The oracles' front-end ran `-compat=strict`, so a corpus file declaring a
binding named after a Tier-1 global (`var Symbol = …`) was rejected as
reserved — 51 TS false-rejects whose referent (TypeScript, and real Node)
permits the shadowing.

## Decision

`tools/conformance`'s shared `frontEnd` resolves with
`allowGlobalShadowing` — the existing, supported `-compat=js` mode
(TDD-00075), which is the faithful measurement configuration for both
referents. Tier-2 names stay reserved either way (no compat value lifts
them, by design). The compiler's own default is unchanged.

While validating, the previous "40 → 37" Node reading turned out to be
run-to-run flake (three timing-dependent files), not a compat effect —
both modes pass the identical 40-file list.

## Verification

Mac. TS oracle: agreement 5226 → 5232 (56.5%). Node oracle: 40, list
byte-identical across both modes.
