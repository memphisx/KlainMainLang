# ADR-01737: Generator method shorthands, generator layout ids, typed-array comparators, non-string `fromEntries` keys, weak keys and seeding, prototype-chain `for...in`, sanitizer-lane fixes

- **Relations**: `Implements TDD-00230`, Extends [ADR-01736](ADR-01736.md)
- **Date**: 2026-10-19

## Context

- **Generator method shorthands** (`*g() {}`, `async *g() {}`, `*[Symbol.iterator]() {}`) compiled, but `this` in their body was a compile-time rejection.
- **A sync generator returned a Promise from `next()`** when an async generator with the same fields existed anywhere in the program. With more code, the program looped until it ran out of memory. The two shared a layout id, so the boxed sync instance dispatched through the async generator's method table.
- **A typed array sorted with a comparator** read every element as 8 bytes: an `Int16Array`/`Float32Array`/… gave the comparator garbage (the order was wrong, the sort read past the buffer, and UBSan reported a misaligned load). An integer element also reached a `number` comparator as an integer.
- **The sanitizer-lane rerun** (12 failures, down from 89):
  - the HTTP/2 runtime passed NULL to `memcpy` for an empty output buffer or event;
  - `process.memoryUsage().heapUsed` was 0, because the C library's statistics see no allocation made through ASan's allocator;
  - ASan aborted a too-large typed-array allocation instead of returning NULL, which the RangeError path relies on;
  - ASan's one-time swapcontext note on stderr failed the tests that compare stderr;
  - the FFI `exportString` test read uninitialized `malloc` bytes past the terminator.
- **`Object.fromEntries` rejected a key that is not a string** (a number, symbol or object). A `Map` with number keys compiled, then crashed: it seeded the string-keyed result with numbers.
- **A member call through an interface method slot** (ADR-01736) dispatched by name as if the receiver could be an array: `path.posix.join(a, b)` failed with "join takes 0 or 1 arguments".
- **Weak collections:**
  - `WeakMap`/`WeakSet`/`WeakRef` were declared with `extends object`, so a symbol key was a type error; TypeScript's ES2023 lib declares them over `WeakKey`.
  - `new WeakMap(entries)` and `new WeakSet(values)` were rejected.
- **Contextual inference for overloads:** `const w: WeakMap<object, number> = new WeakMap()` relied on the old `object` default. The checker inferred type arguments from the return context only for a single signature, never for an overloaded one or a front-end builtin `new`.
- **Prototypes:**
  - `for...in` listed only own keys;
  - `Object.create(proto, descriptors)` was rejected;
  - `Object.defineProperties` rejected a typed descriptor map;
  - `Reflect.setPrototypeOf` on a non-extensible object answered `true` and changed the prototype, and `Object.setPrototypeOf` did not throw.
- `Object.values`/`entries`/`for...in` already skipped an omitted optional field ([ADR-01066](ADR-01066.md)). A status caveat still said they listed it.

## Decision

- **A generator method reading `this`** takes its receiver as a leading `this: any` parameter, and its constructor value is `FuncThis` (`emitGeneratorExpressionValue`). The receiver is the object, another object holding the method, or a `call` target; a bare call throws TypeError, as it does for a method shorthand ([ADR-01736](ADR-01736.md)).
- **A generator's layout key carries `|G`, or `|GA` for an async generator** (`layoutKeyMemo`), so a sync and an async generator never share an id or a method table.
- **Typed-array comparator sort:** a narrower element has its own trampoline (`__kml_sort_tramp_{i8,u8,i16,u16,i32,u32,f32}`), reading the element at its width.
  - The `_d` variant passes a widened `number` when the comparator's parameters are `double`.
  - Any other pairing converts the comparator to `(number, number)` first.
  - A boolean element reads as `u8`.
- **`Object.fromEntries` over non-string keys** (`fromEntriesKeyed`: a tuple key type, a literal pair or a `Map` key) runs the loop the specification runs, `o[k] = v` on a fresh `any` object (`emitObjectFromEntriesKeyed`). Its ToPropertyKey turns a number or object key into its string and keeps a symbol. Type inference gives the call `any` in the same cases.
- **The slot call's thunk branch** calls the receiver's property directly (`emitDynAnyMethodCallPlain`): the receiver is the object, so a method named like an array or string method is still its own.
- **Weak keys:** the lib declares `WeakMap<K extends WeakKey, V>`, `WeakSet<T extends WeakKey>` and `WeakRef<T extends WeakKey>`, as TypeScript's ES2023 lib does.
  - `NewWeakMapExpression`/`NewWeakSetExpression` carry the constructor's `Init` argument; the checker types it as the constructor's argument, and the capture scanners visit it.
  - Codegen runs the constructor's loop (`emitWeakSeed`): `set`/`add` per item, so a primitive throws their TypeError; a null or undefined source adds nothing.
  - K, V and T come from the type arguments, else from the source: a literal of pairs (`literalPairTypes`; values that disagree widen to `any`), a tuple array, a `Map`, or an array or `Set`.
- **Return-context inference** now also fills an overloaded signature's open type parameters (`resolveOverload`) and a builtin `new`'s. The synthesized call that types them finds its context through the original expression (`ctxStandIn`).
- **`for...in` over a dynamic object** enumerates as EnumerateObjectProperties does (`__kml_dynobj_forin_keys_c`): the object's own enumerable string keys, then each prototype's, in ES order per level, skipping a key a nearer level has (enumerable or not).
- **`Object.create(proto, props)`** is `Object.create(proto)` followed by `Object.defineProperties(o, props)`; an undefined `props` adds nothing. `defineProperties` reads a typed descriptor map through its bag copy (`emitStaticObjToBag`), since the map is only read. Such a call also turns on property attributes (`propAttrsUsed`).
- **`set_proto`** is OrdinarySetPrototypeOf: the same prototype (an unset slot counting as `Object.prototype`) succeeds, and a non-extensible object refuses another. `Object.setPrototypeOf` throws `#<Object> is not extensible`, and the cycle TypeError otherwise.
- **HTTP/2:** a zero-length take or event copy returns before `memcpy`.
- **Heap statistics under ASan** come from the sanitizer allocator (`__sanitizer_get_heap_size`, `__sanitizer_get_current_allocated_bytes`).
- **Sanitizer lane:**
  - the ASan options add `allocator_may_return_null=1`;
  - `compareLines` and the over-1024-descriptor fetch test drop ASan's swapcontext note (`dropSanitizerNotes`);
  - the FFI test allocates with `calloc`.
- **The stale caveat is removed.**

## Verification

macOS (Apple Silicon), against Node:

- `tests/objects_test.go` TestE2EObjectLiteralGeneratorMethodThis: the receiver through the object, another object, `call`, `Symbol.iterator`, an async generator method under `for await`, and a bare call's TypeError;
- `tests/collections_test.go` TestE2EObjectFromEntriesNonStringKeys; `tests/objects_test.go` TestE2EObjectFromEntriesSymbolAndObjectKeys (replaces the rejection test);
- the path and function-field families pass;
- `tests/collections_test.go` TestE2EWeakCollectionsFromIterable; `tests/objects_test.go` TestE2EForInPrototypeChainAndCreateDescriptors, TestE2ESetPrototypeOfNonExtensible, TestE2EReflectFlagsAndWeakSymbol; the weak, Reflect, `for...in`, prototype, `defineProperty`, freeze, Map, Set and Promise families pass;
- `tests/builtin_prototype_test.go` TestE2ETypedArraySortComparatorWidths: every element width, a predeclared `number` comparator and inline ones;
- the generator, object-literal, method-shorthand, async-iteration, sort, typed-array and FFI families pass.

Linux (Node304 `kmlbox`):

- under `KLAIN_TEST_SAN=1`: the ArrayBuffer allocation failure, `memoryUsage`, typed-array sort, HTTP/2 port, module-task argv and structural-view tests pass;
- under `KLAIN_TEST_MM=gc`: TestE2EWorkerGCModeRoundTrip and TestE2EStructuralViewOfAnyBag pass;
- the checker, sema, binder, ast and statusgen unit tests pass.

On macOS, ASan still aborts the too-large allocation even with `allocator_may_return_null=1`. The sanitizer lane runs on Linux.
