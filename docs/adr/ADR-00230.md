# ADR-00230: General mapped types — keyof, indexed access, `{ [K in …]: V }`

- **Relations**: `Implements TDD-00079` (Stage 2); `Extends ADR-00229`
- **Date**: 2026-08-19

## Context

Stage 2 of TDD-00079: user-defined mapped types `{ [K in keyof T]: V }`, and the
two operators they rest on — `keyof T` and indexed access `T[K]`. This is the
general form the stage-1 utility types are special cases of.

## Investigation

Monomorphization again makes this a compile-time evaluation: `keyof T` and `T[K]`
read a concrete object `T`'s field set and field types, and the mapped form
rebuilds a concrete `ObjectType` by mapping the value body over the source keys —
the same `resolveType` seam the utility types use.

`keyof`, `in`, `readonly`, and `as` are **not reserved words** here (like the
for-in/of `in`), so they are handled as contextual identifiers in the type
parser — no lexer changes. Indexed access `T[K]` had to be split from the array
suffix `T[]`: empty brackets stay the array form, non-empty brackets are an
indexed access.

## Decision

- **AST** (`ast.TypeAnnotation`): `IsKeyof`/`KeyofOperand`; `IsIndexedAccess`/
  `IndexObject`/`IndexKey`; `IsMapped`/`MappedKeyVar`/`MappedSource`/`MappedValue`/
  `MappedOptional`/`MappedReadonly`.
- **Parser**: a `keyof` prefix in a type atom; `T[K]` in the trailing-bracket
  handling (non-empty `[...]`); a mapped type detected by lookahead in the `{`
  branch (`[K in …]`, optional leading `readonly`, optional `?`), so a plain
  object type is unaffected.
- **Codegen** (emit_mapped_types.go), all at `resolveType`:
  - `keyof T` as a standalone value type → `string` (its structural use is read
    directly by the mapped evaluator).
  - `T["name"]` → the named field's type (unknown/non-literal key falls back to
    the array element type or i64).
  - `{ [K in Source]: V }` → evaluate: the source is `keyof T` (homomorphic over
    T's fields) or a string-literal union; for each key, the value body is
    resolved with `T[K]`→the field's type. V1 value bodies: `T[K]` (homomorphic),
    a bare `K` (→string), a concrete type (uniform), or `T[K]` wrapped one level
    in Array/Promise/Set. `?`/`readonly` are accepted (near-no-ops).

Deferred: key remapping (`as`), modifier-removal (`-?`/`-readonly`), and `T[K]`
nested deeper than one container level.

## Implementation notes

`rewriteType` (resolver) gained descent into the new annotation fields
(`KeyofOperand`/`IndexObject`/`IndexKey`/`MappedSource`/`MappedValue`) — without
it, a named type referenced only inside `keyof T` / `T[K]` / a mapped source
stayed unmangled while its declaration was renamed, so `keyof User` resolved to
nothing and the mapped type came out empty (the same gap the union/tuple/
intersection members had). Found immediately by the first identity-clone test.

No runtime representation: a mapped type resolves to an ordinary `ObjectType`.

## Verification

- `tests/mapped_types_test.go`: identity clone (`T[K]`), uniform (`boolean`),
  wrapped (`Array<T[K]>`), `readonly`/`?` modifiers, a string-literal-union
  source, and standalone indexed access. All pass; example IR verified with
  `clang`.
- `examples/types/mapped-types.ts` added and runs correctly.
- `go build`, `go vet ./...`, parser tests, and the object/interface/generic/
  utility/intersection/tuple/nullable E2E subset are green; a plain object type
  and an inline object literal still parse unchanged (mapped detection is
  lookahead-gated). Apple Silicon (macOS).
