# TDD-00065: Generalized destructuring (for-of loop variable, nested patterns, object rest)

- **Status**: Partially Implemented (Stages 1–2 + 3a + 3b done — see [ADR-00192](../adr/ADR-00192.md)/[ADR-00193](../adr/ADR-00193.md)/[ADR-00203](../adr/ADR-00203.md)/[ADR-00204](../adr/ADR-00204.md); Stage 3c deferred, scoped in [TDD-00068](TDD-00068.md))
- **Date**: 2026-08-13

## Context

Destructuring already works well in the statement-declaration, assignment, and
function-parameter positions (see `docs/status/LANGUAGE-CONSTRUCTS.md`'s three
destructuring rows — [ADR-00157](../adr/ADR-00157.md)/[ADR-00158](../adr/ADR-00158.md)/[ADR-00160](../adr/ADR-00160.md)/[ADR-00161](../adr/ADR-00161.md)/[ADR-00109](../adr/ADR-00109.md)).
Three concrete gaps remain, and they are the single largest coherent, in-scope,
non-`eval` cluster left in the Test262 corpus:

- **8,788 destructuring test files corpus-wide** (test262 `.../dstr/` dirs).
- The core binding/assignment/param dirs — the ones that don't rely on `eval`
  or the runtime iterator protocol — currently pass at only ~14%:
  `for-of/dstr` 57/569, `assignment/dstr` 78/368, `arrow-function/dstr` 57/231,
  `function/dstr` 12/186, `let`+`const`+`variable`/dstr 32/283.
- In `language/statements/for-of` specifically (751 files, 111 passing), the
  **single dominant blocker is destructuring in the loop variable**:
  `expected IDENT, got [` (139) + `expected IDENT, got {` (99) = 238 of ~640
  failures — a plain parse rejection, since `parseForOfBody` only accepts a
  bare `IDENT` loop variable today.

This is deliberately a *flip tests* effort, not a *cover new API surface* one.
Per [ADR-00169](../adr/ADR-00169.md)'s finding — that the raw failure-reason
buckets are a poor predictor of real flips, because most large buckets are
dominated by `eval`/untyped-JS files that fail for several reasons at once —
each stage below is measured with `tools/conformance -passlist` (before/after
pass-list diff), not by the headline bucket count.

### Honest scope limit

A meaningful slice of the `dstr` corpus exercises the **runtime iterator
protocol** — a custom `[Symbol.iterator]` on the source, iterator-`close`/
`return()` semantics, the `ary-init-iter-*` files — which this compiler's
static-shape value model cannot represent at all. Those will not flip from any
amount of pattern-syntax work, and are out of scope for this whole TDD. The
reachable target is the **plain array/object-literal pattern-shape** subset,
which is still comfortably the largest reachable group.

## Design

Three stages, smallest-blast-radius first. Each is independently shippable with
its own ADR + conformance re-measure.

### Stage 1 — destructuring in the for-of loop variable

`for (const [a, b] of pairs) {}` and `for (const { x, y } of points) {}`.

- **AST** (`ast/nodes.go`): extend `ForOfStatement` with two optional fields
  mirroring `Param`'s own pattern carriers — `ArrayPattern []ArrayPatternElem`
  and `ObjectPattern []DestructProp`. Both nil ⇒ the existing bare-`VarName`
  path, unchanged.
- **Parser** (`parser/parser_stmts.go`): `parseForStatement`'s for-of/for-in
  detection currently keys on `peekNth(2)` being the loop-variable `IDENT`.
  Add the case where, after `let`/`const`/`var`, the next token is `[` or `{`:
  parse the pattern element list (factored out of `parseArrayDestructuring`/
  `parseObjectDestructuring` into shared `parseArrayPatternElems`/
  `parseObjectPatternProps` helpers so the two positions can't drift), then
  require `of`. `for (const [a] in obj)` — a pattern in for-*in* — stays a
  clean rejection (real JS allows the grammar but it is near-useless and this
  compiler's for-in is already narrow).
- **Codegen** (`codegen/llvm/emit_stmts.go`, `emitForOf`): the per-iteration
  element is already loaded into `elemVal`. Instead of `e.define(s.VarName…)`,
  when a pattern is present, unpack `elemVal` each iteration by delegating to
  the **existing** `unpackArrayPatternInto` / `unpackObjectPatternInto` — the
  exact same core the declaration and parameter positions already share. An
  object pattern unpacks `elemVal.Ref` (the element's object pointer) against
  the element type; an array pattern extracts the element aggregate's
  `{ptr,i64}` and unpacks that.

Reuses every existing per-element rule (holes, `= default`, `...rest`,
array-typed elements) for free, since the unpack functions are shared.

**Map-entry caveat**: this compiler iterates a `Map` by *values*, not
`[key,value]` entries ([ADR-00011](../adr/ADR-00011.md)), so
`for (const [k, v] of map)` does **not** yield entries — it would try to
destructure each value. Left as-is and documented; real Map-entry iteration is
its own separate gap, not part of this stage.

### Stage 2 — nested patterns

`const [[a, b], c] = …`, `const { a: { b } } = …`, and the same nested shapes
inside a destructured parameter and (post-Stage-1) a for-of loop variable.

- **AST**: give `ArrayPatternElem` and `DestructProp` an optional nested
  `SubArray []ArrayPatternElem` / `SubObject []DestructProp` (a sub-pattern in
  place of a leaf `Name`). Parsing becomes recursive in the shared helpers from
  Stage 1.
- **Codegen**: `unpackArrayPatternInto`/`unpackObjectPatternInto` recurse — for
  a nested element, resolve that element to a data-ptr/obj-ptr (it must be
  statically an array/object type) and re-enter the matching unpack with the
  sub-pattern, instead of defining a leaf `Symbol`.

### Stage 3 — object-pattern rest / non-identifier keys

Stage 3 as originally scoped bundled two things of very different cost — a
non-identifier key (no new type machinery) and `{...rest}` (needs a residual
object type). Split here into three independently-shippable sub-stages so the
cheap, high-yield part isn't gated on the type-system work:

#### Stage 3a — non-identifier keys (`{ "k": v }`, `{ 0: v }`)

The pattern grammar's key position accepts only a bare `IDENT` today
(`parseObjectPatternProps`), while the object-*literal* grammar already accepts
`STRING`/`NUMBER` keys (`parseObjectLiteral`, [ADR-00066](../adr/ADR-00066.md)) and
the object model already carries string-named fields through `FieldIndex`. So
this is a **pure parser change** — accept `STRING`/`NUMBER` as the pattern key
(binding through a mandatory `: local`, since a non-identifier key has no
shorthand), reusing `keyTok.Literal` as the field name exactly as the literal
side does. Codegen (`unpackObjectPatternInto`) already resolves purely by
`prop.Key`, so it needs no change. No residual type, no new representation.

#### Stage 3b — `{...rest}` over a statically-known source shape

`const { a, ...rest } = obj` where `obj`'s object type is statically known.
The residual is just "source fields minus the named keys" — synthesize a new
nominal `ObjectType` from the remaining `Fields` and copy them field-by-field,
riding the exact fixed-shape struct machinery tuples ([TDD-00066](TDD-00066.md))
already use. This does **not** need general structural typing / index
signatures / `Omit<>`; it's mechanical and bounded, so it doesn't wait for a
broader effort that (as of this writing) isn't even queued.

#### Stage 3c — `{...rest}` over `any` / a union / a generic `T` source — deferred, scoped in [TDD-00068](TDD-00068.md)

When the source shape isn't statically known, the residual can't be computed at
compile time; this needs runtime field enumeration / real structural types.
Deliberately **deferred**, and now scoped in its own document: probing the three
non-static sources showed object rest is never the blocker — each fails to be
treated as an object at all, gated on a different deferred subsystem (object type
arguments in generics, boxed-`any` shape, object union members). See
[TDD-00068](TDD-00068.md), which recommends unlocking object generics first so
generic-`T` rest falls out of monomorphization + Stage 3b's `bindObjectRest`.
Left as a clean compile-time rejection until then.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| Flat array/object pattern parsing | ✅ Built | `parseArrayDestructuring`/`parseObjectDestructuring` — factor out the element-list core |
| `unpackArrayPatternInto` / `unpackObjectPatternInto` | ✅ Built | The shared codegen core; Stage 1 reuses verbatim, Stage 2 makes recursive |
| Per-element defaults / holes / rest | ✅ Built | [ADR-00157](../adr/ADR-00157.md)/[ADR-00158](../adr/ADR-00158.md)/[ADR-00161](../adr/ADR-00161.md) |
| Array-typed element two-alloca representation | ✅ Built | [TDD-00029](TDD-00029.md); already handled inside the unpack core |
| for-of element materialization loop | ✅ Built | `emitForOf` already loads each element per iteration |
| Nested-pattern AST field | ❌ Missing | Stage 2 adds `SubArray`/`SubObject` |
| Object "type minus fields" residual | ❌ Missing | Stage 3 blocker for `{...rest}` |
| Runtime iterator protocol (`Symbol.iterator`) | ❌ Out of scope | Bounds the reachable share of the corpus; see Honest scope limit |
