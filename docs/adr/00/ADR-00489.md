# ADR-00489: Blob parts from a string[] variable

- **Date**: 2026-08-29

## Context

`new Blob(...)`'s parts had the inline-array-literal-only restriction —
a variable-bound parts array (the common builder pattern) was rejected.

## Decision

A non-literal parts expression inferring as `string[]` builds the Blob at
runtime: pass one sums byte lengths (`__kml_str_len`), pass two `memcpy`s
each part at its running offset into one buffer, then the ordinary Blob
header wraps it. Mixed-type variable parts (TypedArrays/Blobs inside a
variable array) stay with the literal form — a plain array can only carry
one element type here anyway.

## Verification

Mac. `tests/blob_test.go` E2E (size/type + `await b.text()` content
round-trip) passes; Blob batch green.
