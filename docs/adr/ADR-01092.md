# ADR-01092: Release CI green — pin the Node oracle, fix two stale test expectations

- **Relations**: `Extends ADR-01090` (the net.connect hang fixed in the same sweep)
- **Date**: 2026-09-23

## Context

The Release workflow had been red for over a week across every platform lane.
The failures were several unrelated things, not one regression:

- `TestE2EFsStatfsSyncSameAsNode` failed on **all** platforms — our
  `fs.statfsSync` object exposes a `frsize` key that the runner's preinstalled
  Node lacked, reading as a spurious "differs from node" diff.
- `TestE2EHTTPClientRefusedConnectExitsCleanly` (new in the prior commit)
  asserted the wrong substring.
- `TestE2EWinRealpathWalksLinks` (Windows) compared realpath output against an
  un-canonicalized temp path (8.3 short name vs long name).
- A 50-minute macOS hang — the `net.connect` pre-connect-write bug (ADR-01090).
- Flaky Linux `-mm=gc` segfaults (BACKLOG §0 item 20).

## Investigation

The root of the `statfs` failure was Node-version drift: the `assertSameAsNode*`
oracle (23 test files) diffs our stdout against whatever `node` is on PATH, and
`release.yml` pinned **no** Node — so the oracle was the runner's drifting
default. The two dev machines disagreed too (macOS 26.3.0, Windows 24.19.0), and
`fs.statfsSync`'s `frsize` field exists in Node 24+ but not the older runner
Node. `TestE2EHTTPClientRefusedConnectExitsCleanly` wanted `"Could not connect"`
but the runtime has always emitted libcurl's `"Couldn't connect to server"`
cross-platform (a wrong assertion, not a runtime bug). `TestE2EWinRealpathWalks`
expected `C:\Users\RUNNER~1\...` while our realpath — correctly, as Node does —
canonicalizes the 8.3 short name to `C:\Users\runneradmin\...`; the sibling
Windows tests already `EvalSymlinks` their expectation and this one did not.

The Linux `-mm=gc` segfaults were tested for a Windows-session regression: the
same 10-round resolver-churn workload, built with the pre-Windows compiler
(`a0b049f`, Sep 18) vs HEAD, run 30× each in a Linux container. Pre-Windows
crashed 30/30 (25 segfault, 5 abort); HEAD passed 30/30. The Windows work's
gcshim (ADR-01088) **fixed** that crash — the residual CI flake is the deeper,
older collector bug (item 20), not a regression.

## Decision

- Pin one exact oracle Node across CI and both dev boxes: **24.19.0** (Active
  LTS; Windows dev already ran it; `frsize` present). `release.yml` gains a
  `setup-node@v4` step at `24.19.0`; dev boxes run the same (`nvm use 24.19.0`).
- Fix the two stale expectations to what the correct, Node-faithful runtime
  already produces: the refused-connect substring → `"Couldn't connect to
  server"`; the realpath expectation → `EvalSymlinks(tempDir)` (the idiom its
  siblings use).
- Leave the Linux `-mm=gc` flake as the tracked, deferred item-20 bug (not a
  regression; do not mask it).

## Side effects discovered

- **Event-loop wait test is unresolved.** `event_loop_wait_test.go` asserts a
  `setInterval` fires ≥ 8 times during a 600 ms parked fetch. On a loaded macOS
  runner it legitimately drops to 5–7 (the loop is healthy — 21 ticks locally
  vs Node's 22, and the loop's `select()` wait is deadline-driven, not
  hardcoded). No absolute tick threshold separates "healthy under load" from a
  partial-cadence regression — the ranges overlap. The right fix is a Node-
  relative / structural check (the project's own robust pattern is
  `top_level_await_tick_test.go`'s deterministic ordering), not a magic number;
  left for a deliberate decision rather than re-tuning the constant here.

## Verification

- The four fixed tests pass locally on macOS (Apple Silicon M4): statfs (on the
  pinned 24.19.0), refused-connect, net.connect round trip (ADR-01090).
  Realpath is Windows-only and matches the established sibling idiom;
  diagnosed from the CI diff, not run on a Mac.
- Verified on: macOS (Apple Silicon M4); Linux via Docker `golang:latest`
  (arm64) for the `-mm=gc` old-vs-new comparison.
