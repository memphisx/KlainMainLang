# ADR-00232: Type-system caveat reductions — tuple `.length` + element assignment; `A | B | null`; intersection same-name object fields

- **Relations**: `Extends ADR-00201`, `ADR-00225`
- **Date**: 2026-08-19

## Context

A pass over the disclosed caveats in `docs/status/TYPE-SYSTEM.md`, closing the
tractable ones to move rows toward Strict Coverage.

## Decision

Three caveat reductions:

1. **`T | null` "only one non-null branch" was stale.** A multi-branch
   `A | B | null` already works — it is handled by the general union machinery
   ([TDD-00043](../tdd/TDD-00043.md)), which supports scalar members plus
   null/undefined. Verified: declare, reassign across every branch, `typeof`,
   `=== null`, and as a function parameter all behave correctly. The "limitation"
   was purely which internal representation is used (the presence-flagged
   `{ i1, T }` nullable slot for a single branch vs. the union box for several),
   which is an implementation *note*, not a behavioral caveat — so it moved to
   Notes and the nullable row is now Strict.

2. **Tuple `.length`.** A tuple's arity is fixed and compile-time known, so
   `.length` returns that constant (`emitMember`'s length handler, both the
   named-variable and general-expression paths). Previously a clean
   "`.length` is only supported on arrays and strings" error.

3. **Tuple element assignment `t[0] = x`.** A tuple is a fixed-shape struct, so a
   constant index maps to a struct field: `emitTupleElemAssign` GEPs the field
   and stores via the existing object-field store path
   (`storeScalarOrNullableFieldExpr`), so scalar, nullable, and array element
   types all work. A non-constant index, an out-of-range index, and (for now) a
   compound `t[0] += x` are clean rejections. Previously `t[0] = x` failed with
   "not an array".

4. **Intersection same-name object fields are recursively intersected.** A field
   name appearing in two members with two different **object** types is itself an
   intersection of those objects (`{ x: A } & { x: B }` ⇒ `x: A & B`), so
   `mergeIntersectionFields` merges them recursively rather than reporting a
   conflict (extends [ADR-00225](ADR-00225.md)). Conflicting **non-object** types
   still cleanly reject. Object-type nesting is finite (resolved types have no
   cycles), so the recursion terminates.

## Implementation notes

`emitTupleElemAssign` mirrors the existing read path `emitTupleIndex` (same
`getelementptr StructIR, ptr obj, i32 0, i32 idx`), then stores instead of loads.
Routed from `emitAssign` ahead of the array-element path, gated on
`inferExprType(object).IsTuple`.

## Side effects discovered

The tuple row keeps caveats (no rest/optional/named elements, non-constant index,
array methods, nesting in `any`/a union), so it stays out of Strict — but two of
its five caveats are now closed. The nullable row reaches Strict (features Strict
6/13 → 7/13).

## Verification

- `tests/tuple_test.go`: `.length` + constant-index element assignment (read
  back), and an out-of-range assignment rejection. New nullable behavior spot-
  checked directly (`number | string | null` across all branches). Tuple example
  IR verified with `clang`.
- `go build`, `go vet ./codegen/...`, and the tuple test set are green on Apple
  Silicon (macOS). Status page counts updated same-change.
