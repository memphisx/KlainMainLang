# ADR-01817: `await` as an identifier outside async code; `async x => …`

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- The scanner reads `await` as a keyword everywhere. In script code it is an identifier outside async functions and class static blocks. `var await = 0` and `function* await() {}` failed to parse, which Test262's `static-init-await-*` exercise.
- An async arrow with one bare parameter (`async x => await x`) never parsed in either lane.

## Decision

- The parser tracks where `await` is read, as it tracks `yield`:
  - In a function that is not async, and at the top level, `await` is the operator unless no operand can follow it (`=`, `;`, `)`, a binary operator, …), as in `var await = 0`. At the top level that operator is top-level await; in a function, `return await 1` keeps tsc's TS1308.
  - In an async function or async arrow, and directly in a class static block, it is the operator. A non-async arrow keeps its enclosing context.
  - A function expression's own name may be `await` (`(function* await() {})` in a static block).
- Module code (any import or export) rejects `await` used as a name: a reference or a binding, but not a property name. tsc rejects it the same way. The check shares a walk with strict code's `yield` check (`reservedNameIn`).
- `async x => …` parses as a one-parameter async arrow.

## Consequences

- `TestE2EJSFileAwaitIdentifier`, `TestE2EAsyncArrowBareParam` and `TestModuleAwaitNameRejected` cover these. `examples/async/async.ts` uses the bare-parameter arrow.
- A top-level `await /re/` reads as a division, not an await of a regular expression literal.
