# ADR-02009: The global object's eval is the global eval

- **Date**: 2026-11-21

## Context

- A sloppy script's `eval = f` already rebound the global (evalReassignment:
  reads hold the assigned value, calls are direct evals only while the
  global holds the builtin).
- `globalThis.eval = f` (or `global.eval`, `globalThis["eval"]`) wrote a
  property no read of `eval` saw. Bare `eval(…)` kept calling the builtin,
  and `globalThis.eval = …` alone failed to compile ("undefined variable
  'globalThis'"), at HEAD too.
- The global object had no own `eval` property:
  `Object.getOwnPropertyDescriptor(globalThis, "eval")` was undefined and
  `global.eval === eval` was false.
- `globalThis.parseInt = f` (any assigned builtin) likewise left
  `parseInt(…)` calling the builtin.

## Decision

- evalReassignment treats the global object's `eval` member as the same
  binding as the bare name: its writes set the held value, its reads and
  its callee read what is held.
- The global object carries `eval` (writable, non-enumerable,
  configurable).
- jsRebindAssignedBuiltins treats `globalThis.N` / `global.N` /
  `globalThis["N"]` of an assigned builtin N as N's variable.

## Implementation notes

- resolver/resolver.go: `evalReassignment`.
- codegen/llvm/emit_builtin_rebind.go: `globalObjectMember`.
- lib/node/internal_global_object_fill.ts and codegen/llvm/emit_exprs.go
  (`globalObjectBuiltins`): `eval`.
- What is left: a write of the global's eval through `globalThis.eval` does
  not update the object's own property, so its descriptor's value still
  reads the builtin.

## Verification

- `TestE2EGlobalThisEvalRebindJS` matches Node, on Linux x86 (Node304).
