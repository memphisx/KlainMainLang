# ADR-00318: CryptoKey model + symmetric `crypto.subtle` (HMAC, AES-GCM/CBC, keys, JWK oct)

- **Relations**: Implements [TDD-00104](../tdd/TDD-00104.md) (Phase 2); extends [ADR-00316](ADR-00316.md)
- **Date**: 2026-08-23

## Context

With the `-crypto` backend seam and `digest` in place (ADR-00316), the key-
consuming half of Web Crypto needed its CryptoKey object model plus the
symmetric algorithm set: HMAC sign/verify, AES-GCM/AES-CBC encrypt/decrypt,
generateKey, and importKey/exportKey in `raw` and `jwk` (oct) formats.

## Investigation

- CommonCrypto's GCM entry points are private SPI. Per TDD-00104's decision,
  the commoncrypto backend composes GCM from public `kCCModeCTR` plus an
  in-shim table-free GHASH. Validated two ways before wiring anything: the
  NIST case-4 vector (12-byte IV, AAD — encrypt, decrypt, and
  tamper-rejection) directly, and byte-identical output against the OpenSSL
  backend on the non-12-byte-IV path (which exercises the GHASH-derived J0),
  via standalone C drivers.
- JWK for this compiler can't return a spec JWK *object* — there is no
  dynamic object model (the same constraint URLPattern's `exec` hit, which
  returns `Map<string,string>` instead). The same shape fits JWK: every
  member of an oct/RSA/EC JWK is a string.
- `Promise.resolve`'s settled-task machinery (Phase 1's return surface)
  stores any single-word payload, so Promise<CryptoKey>/Promise<boolean>
  needed no new plumbing.

## Decision

- **CryptoKey**: malloc'd hidden header `{ i64 algId, i64 hashId,
  i64 usages, i64 extractable, i64 kind, ptr keyData, i64 keyLen }`
  (`runtime_crypto_subtle.go`), compile-time `IsCryptoKey` Type flag with
  dedicated `.type`/`.extractable` property reads (the Blob pattern).
  Usage enforcement is a header-bitmask check that throws
  `InvalidAccessError`; non-extractable exportKey throws the same. keyData
  is a *copy* of the imported bytes, so later mutation of the source view
  can't alias key material.
- **importKey/exportKey**: `raw` (BufferSource ↔ fresh ArrayBuffer) and
  `jwk` for oct keys — export returns `Map<string,string>`
  (`{kty: "oct", k: base64url}`); import accepts that Map or an object
  literal with a `k:` member. base64url codec lives in the backend shims
  (`__kml_crypto_b64url_encode/decode`, RFC 4648 §5, no padding).
- **generateKey**: AES via literal-or-runtime `length:` bits; HMAC via
  `hash:` with the spec's default key length = the hash's block size
  (512/1024 bits). Both fill from the existing CSPRNG — no new ABI.
- **sign/verify (HMAC)**: one shared MAC computation; verify recomputes and
  compares via the constant-time `__kml_crypto_memeq` plus a length check,
  returning Promise<boolean> (never throwing on mismatch).
- **encrypt/decrypt**: AES-GCM (`iv`, optional `additionalData`, optional
  `tagLength` default 128 — tag appended to the ciphertext per spec) and
  AES-CBC (`iv`, PKCS#7). GCM auth failure → `OperationError`.
- The usage-check error code (-4 → InvalidAccessError) extends
  `__kml_crypto_check`'s mapping; it is emitter-generated only — the C ABI
  itself still returns -1/-2/-3.

## Implementation notes

- `cryptosrc/crypto_openssl.c`: EVP_MAC HMAC, EVP AES-GCM/CBC.
  `crypto_commoncrypto.c`: CCHmac, CCCrypt CBC, CTR+GHASH GCM. Both carry
  the (deliberately duplicated) base64url codec so each stays one
  self-contained TU.
- `emit_call_crypto.go`: `subtleAlg` compile-time algorithm parsing
  (literal `name:`/`hash:`, runtime `iv`/`additionalData`/`length`/
  `tagLength`), `parseUsagesBitmask` folds the keyUsages array literal at
  compile time. `types.go`: `IsCryptoKey`/`IsCryptoKeyPair` flags.
- HMAC keys longer than the hash block work as-is (both libraries apply
  the spec's key pre-hashing internally).

## Side effects discovered

None new; the TypedArray vardecl restriction from ADR-00316 continues to
shape test/example style.

## Verification

Mac: `TestE2ESubtleHmacJwk` (RFC 4231 case-2 known answer, verify true +
tamper false, JWK Map + object-literal roundtrips) matrix-run on **both**
backends with identical output; `TestE2ESubtleAesRoundTrips` (GCM with AAD
+ raw export length + CBC); `TestE2ESubtleErrorNames` (InvalidAccessError
usage/export, OperationError tamper). Standalone C NIST-vector +
cross-backend GCM drivers as above. `go build`, `go vet ./...`, targeted
test run, crypto example extended and rerun.
