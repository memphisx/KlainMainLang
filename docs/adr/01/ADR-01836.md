# ADR-01836: Eleven more expression kinds take their type from the checker

- **Relations**: `Implements TDD-00230` (P3.3: inferExprType's kinds switch to the checker one at a time)
- **Date**: 2026-10-20

## Context

- The full shadow report counts, per kind, how often inferExprType was asked and how often the two sides disagreed.
- Four kinds never disagreed: UnaryExpression (262,397 queries), UpdateExpression, SequenceExpression and SuperExpression.
- Four had a handful of rows, all in examples or library code:
  - AsExpression: 5 rows in 311,277 queries;
  - YieldExpression: 2 rows;
  - NewTargetExpression: 2 rows;
  - NonNullExpression: 1 row;
  - AwaitExpression: 1 row, in a method body compiled for any receiver (its shape record), where emission never asks the checker. The shadow harness compared there anyway, so it now skips such bodies.
  - NewMapExpression and NewSetExpression: 1 row each, both where the checker is the more faithful side. `const annotated: Set<number> = new Set()` was built as a string set by the old default, where the checker gives `Set<number>` from the annotation. `make(Map)` through a generic constructor parameter builds `Map<any, any>`, as tsc types it. A bare `new Map()` with no context already agreed.
- A targeted run with them switched turned up two more AsExpression cases that the corpus doesn't exercise: an object literal asserted to a shape (`{} as { xs?: number[] }`), and a typed array re-asserted through `unknown`.

## Decision

The oracle answers each as emission builds it:
- **`yield*` over a generator** is its return value, carried in the result object's element slot: the inner generator's element type (`emitYieldStar`). The old side fell through to its default integer, which emission never produced.
- **A function declaration's `new.target`** is the function (`any`) only where the body is compiled to be constructed, with a receiver; otherwise `undefined`. That is emitter state, so the emitter exposes it as `newTargetHeld`.
- **`expr!`** holds the operand without its null and undefined.
- **`as`:**
  - an erased assertion keeps its operand's unchecked index bound;
  - a concrete operand asserted to a union stays the operand (emission boxes only into `any`);
  - an object literal whose keys are fields of the asserted object type, and an array literal of `any` elements or none, are built in the asserted shape;
  - a typed array re-asserted through a box to another kind (`u16 as unknown as Uint8Array`) stays the box, so it keeps its run-time kind (`keepsBoxedTypedArray`, exposed to the oracle).

All eleven kinds join `switchedExprKind`. Toward IndexExpression, `reprOf` names the builtin `TemplateStringsArray` as the array of strings a tag receives, so an element read off a tag's `strings` is the unchecked `string | undefined` emission reads it as. The `regexp` example's comment claimed an unmatched capture group prints as an empty string. It prints `undefined`, as in Node, and the comment now says so.

## Consequences

- Still on the old inference, with their rows in the last full report: FunctionExpression (144), ObjectLiteral (91), ArrowFunction (74), IndexExpression (40), BinaryExpression (36), ArrayLiteral (31), AssignmentExpression (28), NewExpression (9).
- Verified on Apple Silicon (242 generator, yield, assertion, non-null, new.target, regexp, unary, update, sequence and super E2E tests; the assertion, object-literal and tuple tests; the await, async, Map and Set tests), and with the gate on Linux x86-64 (DeskMini).
