# ADR-01129: Codegen looks through `x!` receivers; any string-typed base indexes

- **Relations**: `Extends ADR-01126`, `ADR-00606`
- **Date**: 2026-09-25

## Context

With the possibly-null family reported ([ADR-01126](ADR-01126.md)), test
programs that deliberately read an absent value now say so as TypeScript
code does: `a!.push(1)`, `s![0]`, `p.q!.x++`. Each is valid TypeScript that
the strict lane failed to compile, or compiled with the wrong message:
- `a!.push(1)`: "push requires an array variable, array field, or
  nested-array element";
- `s![0]`: "cannot index a non-array expression";
- `p.q!.x++` with `p.q` null threw "Cannot read properties of undefined";
  Node says "of null".

## Investigation

- **`resolveArrayMutLoc`** (`emit_arrays_mutate.go`) matched only an
  identifier, a member or an index receiver. The absent-receiver guard
  already looks through `!` (`registerDerefGuard`).
- **String indexing** (`emitIndexUnguarded`) handled an identifier base
  only. Any other string-typed base fell into the array path. That included
  `o.name[i]` and `f()[i]` as well as `s![i]`.
- **A postfix update's receiver is hoisted** into a temporary so it runs
  once (ADR-00606). For `p.q!` it hoisted the asserted value, whose type had
  lost the null flavour that `absentWord` names in the message.

## Decision

- **`resolveArrayMutLoc`** unwraps `NonNullExpression`.
- **`emitIndexUnguarded`** indexes any base `inferExprType` calls a plain
  string, after the identifier case.
- **`hoistUpdateReceiver`** hoists the operand under any `!`, and re-wraps
  the temporary in `!`.

## Implementation notes

`codegen/llvm/emit_arrays_mutate.go`, `codegen/llvm/emit_exprs_member.go`,
`codegen/llvm/emit_exprs_operators.go`.

## Side effects discovered

None.

## Verification

`TestE2ENullableArrayAbsence`, `TestE2EArrowExprBodyParamTypedReturn` and
`TestE2ENullDerefThrowsTypeError` (its `update` line) pass with the `!`
forms, and print what Node prints.
