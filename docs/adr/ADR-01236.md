# ADR-01236: util.promisify.custom; exec and execFile promisified

- **Relations**: `Implements TDD-00234`; `Extends ADR-01228`
- **Date**: 2026-09-29

## Context

`util.promisify(exec)("echo hi")` resolved `"hi\n"`. Node resolves
`{ stdout, stderr }` and rejects with the error carrying both. Node's
`promisify` returns `fn[util.promisify.custom]` when a function has one,
and `child_process` defines it on `exec` and `execFile`.
`util.promisify.custom` itself did not exist.

## Decision

- **promisify.** `lib/node/internal_util.ts` ports Node's check:
  - a function's `[promisify.custom]` is returned, validated as a
    function;
  - otherwise the promisified function defines it on itself;
  - `promisify.custom` is `Symbol.for('nodejs.util.promisify.custom')`,
    declared as an expando (ADR-01232).
- **child_process.** `lib/node/child_process.ts` defines
  `customPromiseExecFunction` on `exec` and `execFile`. The promise's
  `child` is the process.
- **execFile arguments.** `execFile`'s arguments now follow Node's
  `normalizeExecFileArgs`: the callback is the last function given, and
  `args` may be null. A trailing callback after an options object or a
  null `args` used to be dropped.

## Verification

Mac (Apple Silicon), against Node v24.19: `TestE2EPromisifyCustom`
(`promisify(exec)`, `util.promisify(execFile)`, a rejection's
`code`/`stdout`/`stderr`, `.child`, a user-defined custom); the
child_process suites.
