# RegExp

> Part of the [Implementation Status](README.md) index.

**Coverage**: 100% (14/14) — all 7 stages done, including Stage 6 (`--static` linking, verified both on bare Linux and inside a real Docker `scratch` container — `docker/Dockerfile.regexp-test`). See [TDD-00035](../tdd/TDD-00035.md) for the full design and [ADR-00114](../adr/ADR-00114.md), [ADR-00115](../adr/ADR-00115.md), [ADR-00116](../adr/ADR-00116.md), [ADR-00117](../adr/ADR-00117.md), [ADR-00118](../adr/ADR-00118.md), [ADR-00119](../adr/ADR-00119.md), [ADR-00120](../adr/ADR-00120.md) for what actually shipped.

**Caveats** (real, deliberate V1 scope narrowings — not bugs): `.test()` always matches from offset 0 and never reads/writes `.lastIndex`, even for a `g`-flagged RegExp — real JS's `.test()` shares `.exec()`'s stateful `lastIndex` iteration, but `.test()` itself wasn't revisited when `.exec()`'s `lastIndex` machinery landed (see [ADR-00115](../adr/ADR-00115.md)). `.exec()`/`str.match()`'s result array is scope-narrowed: an unmatched optional capture group becomes `""` rather than a true per-element `null` (no per-element-nullable-string array exists), and real JS's `index`/`input`/`groups` extra properties on the result aren't built. `str.matchAll()` returns an eager `string[][]`, not a real lazy iterator (no lazy-iteration infrastructure exists anywhere in this compiler). Neither `match()`/`matchAll()`/`replace()`/`replaceAll()`/`search()` implicitly coerces a non-`RegExp` argument (a compile-time error instead). `replace()`/`replaceAll()`'s replacement template supports `$1`-`$9`/`$&`/`$$` only (`` $` ``/`$'` — pre-/post-match text — are out of scope); its callback form is invoked with a fixed `(match, offset, string)` — real JS's variadic `...capturedGroups` in the middle isn't supported, since a callback's arity is fixed at compile time but a pattern's capture count is only known at runtime (a callback declaring more than 3 parameters is a compile-time error). `str.split()` only splits on a non-zero-length match — real JS's more intricate zero-length-match handling isn't replicated (see [ADR-00119](../adr/ADR-00119.md)), and captured groups in the split pattern are never spliced into the result (out of scope from the start). `u`(nicode)/`y`(sticky)/`d`(hasIndices) flags are out of scope for the whole feature's V1 (deferred, see the TDD's flag scope table); `g`/`i`/`m`/`s` are supported. `--static` linking works with zero extra flags (PCRE2 has no TLS-backend-style transitive dependency chain, unlike `fetch`'s libcurl) — verified on bare Linux and inside a real Docker `scratch` container; see [ADR-00120](../adr/ADR-00120.md). Building `.exec()` also found and fixed 3 general, RegExp-unrelated bugs — bare `ptr`-typed truthiness (`if (someString)`), array-vs-`null` comparison, and string content-based truthiness — see [ADR-00116](../adr/ADR-00116.md).

| Feature | Status | Notes |
|---|---|---|
| Construction: `new RegExp(pattern, flags?)` | ✅ | Compiles the pattern once via `pcre2_compile_8`; throws a real, catchable `SyntaxError` on an invalid pattern |
| Literal syntax: `/pattern/flags` | ✅ | Desugars to the same construction at parse time — see [ADR-00114](../adr/ADR-00114.md) for the lexer's regex-vs-division disambiguation (a small, deliberately-accepted gap: `x in /foo/` mis-lexes the `/` as division, since `in` isn't its own token in this lexer) |
| `.source` / `.flags` | ✅ | Plain field reads, original constructor arguments verbatim |
| `.global` / `.ignoreCase` / `.multiline` / `.dotAll` | ✅ | Decomposed from the flags string once at construction — no method needs to re-parse it |
| `.lastIndex` | ✅ | Mutated by `.exec()`/global `str.match()`/`str.matchAll()`/`str.replace()`/`str.replaceAll()` (advances on a successful `g`-flagged match, resets to `0` after a failed one) — see [ADR-00116](../adr/ADR-00116.md)/[ADR-00117](../adr/ADR-00117.md)/[ADR-00118](../adr/ADR-00118.md). Deliberately untouched by `.test()`/`str.split()`/`str.search()` — see the caveats above ([ADR-00119](../adr/ADR-00119.md): `.search()` explicitly saves/restores it; `.split()` never reads or writes it at all, matching real JS) |
| `.test(str)` | ✅ | Always matches from offset 0 regardless of `g` — see the caveat above. See [ADR-00115](../adr/ADR-00115.md). |
| `.exec(str)` | ✅ | Returns `string[] \| null` — real, working `m !== null`/`if (m)` checks against the result. See the caveat above and [ADR-00116](../adr/ADR-00116.md). |
| `str.match(regexp)` | ✅ | Without `g`: identical to `regexp.exec(str)`. With `g`: full-match-only strings, `null` (not `[]`) on zero matches — matches real JS exactly. See [ADR-00117](../adr/ADR-00117.md). |
| `str.matchAll(regexp)` | ✅ | Eager `string[][]`, one `.exec()`-shaped match array per match; throws `TypeError` without `g`. See the caveat above and [ADR-00117](../adr/ADR-00117.md). |
| `str.replace(regexp, replacement)` (string or callback) | ✅ | Replaces the first match without `g`, every match with `g`. String replacement expands `$1`-`$9`/`$&`/`$$`; callback form is `(match, offset, string) => string`, invoked exactly once per match. See the caveat above and [ADR-00118](../adr/ADR-00118.md). |
| `str.replaceAll(regexp, replacement)` (string or callback) | ✅ | Same replacement rules as `.replace()`; requires the `g` flag, throwing `TypeError` otherwise. See [ADR-00118](../adr/ADR-00118.md). |
| `str.split(regexp)` | ✅ | Finds every match regardless of `g` (its own local search loop, like real JS); only non-zero-length matches split — see the caveat above and [ADR-00119](../adr/ADR-00119.md) |
| `str.search(regexp)` | ✅ | Always searches from offset 0, restores `.lastIndex` afterward — invisible to later `.exec()`/`.test()` iteration, matching real JS exactly. A plain-string argument still falls back to the pre-`RegExp` `.indexOf()`-shaped behavior. See [ADR-00119](../adr/ADR-00119.md). |
| `u` / `y` / `d` flags | ❌ | Deferred for the whole feature's V1, not just Stage 0 — see the TDD's flag scope table |
