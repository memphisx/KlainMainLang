# ADR-01409: The h2c server session yields instead of blocking

- **Relations**: Implements TDD-00244; Extends ADR-01401
- **Date**: 2026-10-05

## Context

An `http.listen` (`klain:http`) connection that opens with the HTTP/2
preface is driven as an nghttp2 session on its connection fiber
(`http2src/http2.c`). The fiber cleared the socket's `O_NONBLOCK`
(`__kml_h2_set_blocking`) and waited for frames in `poll(…, -1)`: one h2c
client that opened a connection and went quiet stopped the whole loop, every
other connection and timer included, until it disconnected.

The same file carried an in-process h2c client (`__kml_h2c_connect_url`,
`__kml_h2c_request`, the session pump and flush) and four IR callbacks it
fired (`__kml_h2c_on_header/response/data/end`). Nothing has called the
client since `http2.connect` became TypeScript over `net`; its only live
reference was the server's wait, which pumped an empty client list.

## Decision

- The socket stays non-blocking. `__kml_h2_session_recv` reads; when nothing
  is ready it yields the connection fiber to the loop, which resumes it when
  the socket is readable. `__kml_h2_session_send` writes all of each nghttp2
  output chunk, parking the fiber on writability
  (`__kml_conn_park_write`) when the socket is full. `http2.c` carries the
  generated layout header for the connection slot's offsets.
- `__kml_h2_set_blocking` and the in-process h2c client with its IR
  callbacks are deleted. `http2.go` has no IR text left; its ratchet entry
  goes.

## Verification

- Mac (M4): the HTTP/2 tests, and `TestE2EHTTPListenH2cIdleDoesNotBlock`: a
  raw client sends the preface and a SETTINGS frame and idles while a
  `fetch` to the same server is answered. Built before this change, the
  program hangs.
- Linux (x86-64, Ubuntu 24.04 container), with ADR-01406 to ADR-01409: the
  full test suite (3,927 tests), the 393 examples, and Test262 in both lanes
  (strict 8,498, js 10,506, unchanged, no invalid IR).
