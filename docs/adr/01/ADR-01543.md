# ADR-01543: `++`/`--` on an `any` holding a BigInt steps by 1n

- **Relations**: Extends ADR-01061
- **Date**: 2026-10-10

## Context

An `any` binding, property or element holding a BigInt stepped as a
number: `let x: any = 1n; x--` gave NaN, and `o.n--` on `{n: 1n}`
threw "Cannot mix BigInt and other types" (the member path desugared
to `-= 1`). The binding path's comment recorded it as a gap ("the box
has no BigInt kind"); boxes now carry BigInts.

## Decision

- Where a box may hold a BigInt (`anyMayHoldBigInt`), `++`/`--` on it
  takes ToPrimitive of the old value; a BigInt steps by 1n through the
  any-BigInt operator helper, anything else is ToNumber'd and steps by
  1. The new value is stored with a plain `=` (a member or element
  target reuses the assignment paths); a postfix yields the numeric old
  value (the BigInt, or the number), as a box.
- Under -compat=js, a module `var` redeclared with initializers of
  different kinds (a BigInt, then an object) is one any box to the
  shadow oracle too, as codegen already held it.
- TS2403 names the variable by its source name, and reports a
  primitive against an object type, which no identity makes the same.
