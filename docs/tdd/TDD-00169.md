# TDD-00169: faithful async rejection values (`Promise.allSettled` reason, `throw <non-Error>`)

- **Status**: Implemented
- **Date**: 2026-09-03

## Context

`Promise.allSettled` reports a rejected element's `.reason` as a wrapped
`Error` (stringified message), not the **original** rejected value — `await
Promise.allSettled([Promise.reject(42)])` gives `reason.message === "42"`, where
Node gives `reason === 42` ([ADR-00683](../adr/ADR-00683.md) fixed the
`JSON.stringify` crash that sat on top of this, but not the value fidelity).
The same root cause makes `throw 42` / `Promise.reject({obj})` lossy: every
rejection value is coerced to an `Error` at reject/throw time
(`errorPtrFromValue`, `emit_exceptions.go`), destroying the original.

**Update (2026-09-18) — partial progress, and a new crash.** The reject-reason
channel now rides a type-preserving caught value (TDD-00207), and the
`allSettled` producer (`emit_promise.go`, `settled.fail`) renders that reason to
a **string** via `emitCaughtToString`, with the JSON arm reading the slot back
as a raw string. Re-characterised vs `node`:

- A **string** reject value is now faithful in JSON (`reject("e")` →
  `"reason":"e"`) — the one case the shape test locks in.
- A **number** reject value is still wrong everywhere: `JSON.stringify` →
  `"reason":"42"` (Node `42`), `typeof reason` → `"object"` (Node `"number"`),
  `reason.message` → `null` (Node `undefined`).
- An **Error** reject value: JSON → `"reason":"Error: x"` (Node `{}`), and
  `reason.message` **crashes (exit 255)** — the slot holds a string pointer but
  is typed `errorObjType`, so the member read dereferences a string as an Error
  struct.

So the remaining work is exactly the `reason`/`value` → `any` move below.

**A staging split that does *not* hold (verified by attempting it, 2026-09-18).**
The tempting decomposition — ship `reason: any` first (3a: primitives faithful,
crash→clean error) and defer only the Error shape (3b) — was implemented and
**reverted**, because it *regresses the common case*. Storing the caught reason
via `emitCaughtToAny` boxes a caught Error to a bare `kmlTagObject` (its shape is
dropped), so with `reason: any`:

- `typeof` → correct for every reason; JSON and `.message` correct for
  **primitive** reasons; the segfault becomes a clean catchable `TypeError`. All
  wins.
- **But** for an **Error** reason (the *typical* rejection — people
  `throw new Error(...)`), `console.log(reason)` and `String(reason)` render
  `"[object Object]"` (was `"Error: neg"`), and `JSON.stringify` / `.message`
  throw the Stage-6 `TypeError`. The regression test
  `TestE2EPromiseAllSettledArrayValues` catches the `console.log` case.

The blocker is the same for display, JSON, and member access: **there is no safe
runtime discriminator to recognise a boxed Error at a general render/JSON/member
site.** `errorObjType`'s field 0 is a `kind` i64 and a class instance's field 0
is the `__kml_tag` i64 — they can collide, so the catch-all in
`emitBoxedValueToString` / `emitDynAnyMemberGet` cannot tell an Error box from an
arbitrary object box. That discriminator *is* the D1 Stage-6 static bridge
(TDD-00155 Stage 6, "`class X extends Error` becomes Tier-D-compatible").

**Shipped (ADR-01002, 2026-09-18) — the crash/introspection half.** Without
touching the field type, the `allSettled` reason is now materialised as a *real*
`errorObjType` (an Error reason keeps its own message/name/code; a non-Error is
wrapped in a base Error whose message is its string form). This removes the
`.reason.message`-on-an-Error segfault and makes an Error reason byte-exact for
`message`/`name`/`String`/`console.log`. What remains is the **non-Error value fidelity** — `typeof` and JSON of a
primitive reason, and an Error's JSON `{}` — plus one that a first attempt
proved is the *same* gap: `console.log` of a statically-typed `errorObjType`
prints an empty token, but a global "render it as an Error" branch is unsafe
because `AbortSignal.reason` is *also* typed `errorObjType` yet holds a raw
string for a non-Error `abort(reason)` (it Bus-errored `abort-controller`). Both
lying slots need the boxed-object type-id below.

**Conclusion:** the remaining step is atomic with a Stage-6 prerequisite — the
`reason: any` move must land *together* with a unified boxed-object type-id that
lets the render/JSON/member paths recover an Error's shape. Do not ship the
`any` field alone. The same type-id also fixes the general
`catch (e) { console.log(e /* boxed to any */) }` shape loss, so it is worth
building once, generally, rather than special-casing the settlement site.

**Shipped (ADR-01003, 2026-09-18) — the faithful reason.** The unified
boxed-object type-id landed as [TDD-00222](TDD-00222.md) (a field-0 marker bit
that a render/JSON/member/instanceof site tests to recover an Error), and on it
`SettlementType.reason` became `any` carrying the original rejected value:
`reject(42)` keeps `typeof`/JSON fidelity, a rejected Error serialises `{}` and
reads `.message`/`.name`/`String`, and `instanceof Error` is now precise. A
non-Error `throw`'s value was already preserved via the caught-value channel
(TDD-00207). Remaining, on separate surfaces: `AbortSignal.reason` (TDD-00081)
and a boxed **error-subclass** instance's render/members (needs the class's own
field metadata) — both now unblocked by the type-id.

## Design

The promise rejection slot (`promiseStructIR` field 2) stores an `errorObjType`
pointer; `await`-rejection re-throws it as an Error. JS lets you reject/throw
**any** value, so faithful rejection needs the raw value preserved:

- **Rejection carries a NaN-boxed `any`** (the raw value), not a coerced Error.
  `await`/`catch`/uncaught-throw unbox it: an Error value re-throws as-is; a
  non-Error prints/propagates as its own value (`throw 42` → "Uncaught 42").
- `SettlementType.reason`/`value` become `any`, with the absent side set to
  boxed `undefined`; `JSON.stringify` **omits** an `undefined`-valued field and
  serializes an `Error` value as `{}` — yielding Node's exact
  `[{"status":"fulfilled","value":1},{"status":"rejected","reason":42}]`.

This touches the exception machinery (`__kml_throw`, the catch-and-settle async
wrapper, uncaught-throw formatting) as well as the promise combinators, so it is
staged as its own design rather than a bug patch: (1) reject/throw store a boxed
`any`; (2) the throw/await/uncaught paths handle a non-Error boxed value; (3)
`SettlementType` → `any` fields + JSON undefined-omission + Error→`{}`.

## Open questions

- Whether to keep an Error fast-path (most rejections *are* Errors) so only a
  non-Error rejection pays the boxing cost.
- How an uncaught non-Error throw formats at process exit (Node prints the value
  via its inspect, not `Error: <msg>`).
