# ADR-01354: A custom inspect string is re-indented to its nesting level

- **Relations**: Extends ADR-01067
- **Date**: 2026-10-03

## Context

A class whose `[inspect.custom]` returns a multi-line string printed the
string's continuation lines at column 0 when nested in an array or object.
Node indents them under the enclosing entry. Found with DataView's inspect
output (ADR-01352), which is multi-line.

## Investigation

Node's `formatValue` splices a string result as
`ret.replaceAll('\n', '\n' + ' '.repeat(ctx.indentationLvl))`: each
continuation line is shifted by the enclosing indentation. The runtime's
indentation is two spaces per nesting level, less the `depth` option's shift
(`inspect_reduce.c`).

## Decision

`__kml_inspect_reindent(s, depth)` in `inspectsrc/inspect_reduce.c` inserts
`2 × (depth − shift)` spaces after every newline. `emitInspectCustomAt` passes
every string result through it: a static string, and a string held in `any`.
The dynamic hook's per-class thunks use the same routine, so `any` values
re-indent too.

## Implementation notes

`codegen/llvm/inspectsrc/inspect_reduce.c`, `inspect_c.go` and
`emit_inspect.go`.

## Verification

Mac (Apple Silicon), against Node 24: a DataView inside an array prints with
Node's indentation (`TestE2EDataViewGlobalClass`). Single-line custom strings
are unchanged, as the inspect groups show.
