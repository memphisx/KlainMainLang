# ADR-02010: A deleted static method is gone

- **Date**: 2026-11-21

## Context

After `delete C.m` of a static method:

- `C.m === undefined` was false, and `const v = C.m` held a null function
  pointer (printed `null`, `v === undefined` false). A read of an
  overridable static (one the program replaces or deletes) already
  returned the value the class holds now, but its static type was still
  the method's function type, so an undefined held there was unboxed as a
  function.
- `"m" in C`, `C.hasOwnProperty("m")` and `Object.hasOwn(C, "m")` stayed
  true: delete stored undefined in the class's own bag, so the key was
  still there.
- `[1, 2].map(C.k)` after `C.k = f` was invalid IR (at HEAD too), for the
  same typing reason.

## Decision

- A read of an overridable static method is typed `any` (typeOfExpr and
  inferExprType), matching what emitStaticMethodOverrideRead returns.
  Calls `C.m()` keep their own path.
- `delete C.m` marks the property deleted in the class-reference runtime
  (`__kml_classref_static_delete`); a write clears the mark. Own-property
  checks of a literal key that the program deletes answer false while it
  is marked.
- Equality with an overridable static compares both sides boxed.

## Implementation notes

- codegen/llvm/boxsrc/hostbox.c: the deleted list,
  `__kml_classref_static_delete`, `__kml_classref_static_deleted`.
- codegen/llvm/emit_static_override.go: `overriddenStaticRead`,
  `emitBoxedEquality`, `staticDeletedKey`, `emitStaticPresence`; used from
  emit_exprs_operators.go, emit_objects.go (`emitHasOwnProperty`) and
  emit_classes.go (`C.hasOwnProperty`).
- Run-time own-key checks of a class reference (`k in C` with a computed
  key) and its property snapshots (`Object.getOwnPropertyNames(C)`)
  consult the same list.
