# ADR-01510: Short-circuit operators over a nullable scalar

- **Relations**: Extends TDD-00230
- **Date**: 2026-10-09

## Context

`sameShortCircuitType` tested only the left operand for a nullable
scalar. `m || n`, with `m: number` and `n: number | undefined`, counted
as one plain `double`, so `0 || undefined` gave `0`, not `undefined`.

In the other direction, any nullable scalar operand sent `a && b` /
`a || b` to a boxed `any`. So `err && x === "y" && r.ended` (a
three-state boolean after its first `&&`) was boxed, where the checker's
`boolean | null | undefined` is one nullable boolean slot. That was shadow
bucket 5 (348 rows).

## Decision

- `sameShortCircuitType` rejects a nullable scalar on either side.
- `nullableScalarShortCircuit`: two operands of one scalar kind, either
  of which may be absent, share one nullable slot of that kind.
  - `&&` yields the falsy operand, so it takes the absent operand's
    nullability. Two absent operands must be absent the same way;
    otherwise the result stays boxed.
  - `||` yields a truthy left operand, which is present, or the right
    one, so it takes the right operand's nullability.
- `emitShortCircuitValue` allocates, stores and loads through the
  storage type (`{i1, T}` for a nullable scalar).

## Divergences

None. The `||` case was a wrong value; it now matches Node.
