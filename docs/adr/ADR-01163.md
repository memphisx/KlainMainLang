# ADR-01163: Async `fs` as Node's: Buffer results and options; `fs` async and `fs/promises` declared; `await` typed by the checker

- **Relations**: `Implements TDD-00230` (P3.1 `fs` async and `fs/promises` declarations; P2 `await` typing); `Extends ADR-01148`, `ADR-00785`, `ADR-00820`
- **Date**: 2026-09-25

## Context

P3.1 declares each Node module as `@types/node` has it. Declaring
`fs/promises` and the callback forms exposed that they did not behave as
Node's:

- `fs.promises.readFile(p)` and `fs.readFile(p, cb)` delivered a string;
  Node delivers a `Buffer` unless an encoding is given.
- No async form took its options argument (`readFile(p, 'utf8')`,
  `mkdir(p, { recursive: true })`), so a program tsc accepts, and the only
  correct way to read text, did not compile.
- On an error the callback's `data` was an empty value, not `undefined`.

The declarations then showed the checker did not type `await` at all:
`const s: string = await readFile(p)` was left to code generation's own
rejection rather than tsc's TS2322.

## Investigation

- `readFileSync` was already faithful (a Buffer without an encoding), but
  accepted only `'utf8'`. The async forms reused it with only the path
  argument, and the pool's `readfile` op read text.
- Node decodes `'ascii'` by clearing each byte's high bit; ours decoded it
  as latin1 (`Buffer.from([0xe9]).toString('ascii')` is `'i'` in Node).
- Printing an absent `Buffer | undefined` gave `<Buffer >`, although
  `=== undefined` was true; a callback argument with a null header got a
  fresh, present header.

## Decision

- **`readFile` results follow Node.** A new pool op (`readfile_bytes`,
  `KML_OP_READFILE_BYTES`) reads the bytes; the Promise and callback forms
  resolve to a `Buffer` without an encoding, and to a string with one.
- **Options.** Every async op takes its trailing options argument. The
  pool thunks take none: a utf8 encoding is what they do, so it pools; any
  other option (`flag`, `mode`, `recursive`, `withFileTypes`, another
  `readFile` encoding) runs the sync helper inline, faithfully but on the
  loop thread. The result type is the sync form's for the same arguments
  (`fsAsyncSpecFor` infers `fs.<op>Sync(...)`).
- **Encodings.** `readFileSync` and the async `readFile` take every Buffer
  encoding, decoding the bytes as `buf.toString(encoding)`; `'ascii'` has
  its own decoder (`__kml_buf_ascii_str`), also used by `toString('ascii')`.
- **Absence.** A callback's `data` on an error is the absent value
  (`undefined`): the data parameter is typed `T | undefined`, the empty
  result carries a null header, and a callback argument with a null header
  stays absent. `console.log` of an absent `Buffer | undefined` prints its
  keyword.
- **Declarations** (`lib/node.d.ts`): the `fs` callback forms, `fs.promises`
  (an interface of the promise functions) and `declare module
  "fs/promises"`, with `NodeJS.ErrnoException`, all in `@types/node`'s
  shapes.
- **`await` in the checker.** `await x` has tsc's awaited type: a
  `Promise<T>`'s T (recursively, and through unions), a non-thenable
  itself; a user object with a `then` stays unanswered. An awaited
  operand takes the `await`'s contextual type, and an assignment of
  `await <non-promise>` checks the operand, so `await { key: "value" }`
  keeps its literal as in tsc.
- **Escape analysis** (`-optimize-memory`) models `new C(args)`: an
  argument that is the value itself escapes (the constructor may keep it);
  a read through it (`t[0]`) is a copy. The free-variable scan now walks
  every expression kind (ADR-01162), which had made every mention inside a
  `new` escape.

## Side effects discovered

- Two event-loop order differences in the fs examples (a pool completion
  before a due 0 ms timer; a promise-form op settling before an earlier
  callback-form one) are phase ordering, BACKLOG → TDD-00230 phase 4.
- A string's `.length` counts UTF-8 bytes (the string model's documented
  caveat): `readFileSync(p, 'latin1').length` differs from Node on
  non-ASCII bytes.

## Verification

- **Node:** a program over `readFile` (Promise and callback, with and
  without encodings, hex/base64/latin1/ascii), `writeFile` with options,
  `mkdir({ recursive })`, `readdir` with and without `withFileTypes` and a
  failing read prints what Node v24 prints.
- **Tests:** `tests/fs_async_test.go` rewritten to Node's forms (`'utf8'`
  where a string is wanted, a Buffer for the binary round trip);
  `TestE2EFsReadFileSyncBadEncodingRejected` now rejects an unknown
  encoding (tsc rejects it too). `TestE2EFsAsyncReadFileBufferAndEncodings`
  covers the rest. The optimize-memory, escape, free and fs groups pass.
- **tsdiag:** 3,157 diagnostics, 0 false positives.
