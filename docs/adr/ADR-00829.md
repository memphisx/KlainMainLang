# ADR-00829: the server `'connection'` event via a dispatcher-entry hook

- **Relations**: Implements [TDD-00198](../tdd/TDD-00198.md); extends [ADR-00502](ADR-00502.md) (server `.on` events); reuses [TDD-00158](../tdd/TDD-00158.md) (the `'upgrade'` `net.Socket` build)
- **Date**: 2026-09-10

## Context

`http.Server` had no `'connection'` event — Node's once-per-accepted-connection
signal, handed the raw socket before HTTP parsing. Wanted for connection
counting/logging and raw-socket handles.

## Investigation

`accept()` lives in the reactor IR (`runtime_http.go`), hand-written and with no
closure-call path. But each connection runs a codegen-emitted dispatcher fiber
(`emit_http.go` `buildHTTPDispatcher`), whose entry (before the `readLoopL`
loop) runs once per connection — keep-alive reuse loops back to `readLoopL`, not
the entry. The `'upgrade'` path (`emit_http_upgrade.go`) already builds a
`net.Socket` over the connection fd (`calloc 64`, fd in field 0, TLS ssl in
field 5) and invokes a stored handler; the connection fd is read from the conn
array via `@__kml_current_conn_idx` (the scheduler sets it before resuming the
fiber, so it is valid at entry, exactly as `readLoopL`'s own read relies on).

## Decision

- New per-server global `@__kml_listen_connection_handler<sfx>`, declared
  unconditionally (primary in `ensureHTTPRuntime`, additional in
  `ensureExtraWSUpGlobals`). `server.on('connection', cb)` stores the closure,
  routed by `httpServerSfxForExpr`; the callback is hint-typed `(net.Socket)`.
- New `emitHTTPConnectionEvent(sfx, readLoopL)`, called in `buildHTTPDispatcher`
  in place of the entry `br readLoopL`: load the handler; null → branch to
  `readLoopL`; else read the fd from the conn array, build a `net.Socket`
  (TLS-aware), invoke `(socket)`, then fall into `readLoopL`. Once per
  connection, before HTTP parsing.
- No pre-scan (unlike `'upgrade'`): the hook is a load + null-check, cheaper
  than a scan; it ensures its own suffixed global via `ensureExtraWSUpGlobals`
  so a dispatcher referencing it always has the declaration.

The socket is a `write`/`destroy`/inspect handle only — the HTTP parser owns the
byte stream, so its `'data'`/`'close'` listeners are not driven, and
`remoteAddress`/`remotePort` are absent (`accept(fd, null, null)`). Documented.

## Implementation notes

- `runtime_http.go`: the primary `@__kml_listen_connection_handler` global.
- `emit_http.go`: the suffixed global in `ensureExtraWSUpGlobals`; the
  `'connection'` arm in the `on`/`once` dispatch; the entry-hook call replacing
  `br readLoopL`.
- `emit_http_upgrade.go`: `emitHTTPConnectionEvent` (self-declares its global via
  `ensureExtraWSUpGlobals`, the fix for an additional server whose dispatcher
  references the global without ever registering a handler).

## Side effects discovered

The readiness-probe TCP connection some tests make (a `net.Dial` to confirm the
port is listening) legitimately fires `'connection'` too — so a connection count
is relative to an unknown baseline; the E2E test asserts increments, not
absolutes. This is correct Node behaviour (every TCP connection counts).

## Verification

Verified on macOS (Apple Silicon M4): new `TestE2EHTTPServerConnectionEvent`
(fires once per TCP connection — a keep-alive-reused socket does not re-fire, a
fresh socket does) passes; full `go test -run TestE2EHTTP` green (61s), plus
WebSocket/net/upgrade suites (the shared dispatcher + globals) green; example
`examples/http/server_connection_event.ts` runs and exits cleanly.
