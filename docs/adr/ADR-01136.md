# ADR-01136: Calls compiled from builtin declarations (`@lower`, P3.2 first stage)

- **Relations**: `Implements TDD-00230` (Phase 3, P3.2); `Extends ADR-01134`
- **Date**: 2026-09-25

## Context

[ADR-01134](ADR-01134.md) declared the builtin surface in `lib/es.d.ts`, but
those declarations only answer the checker. Every builtin call is still
compiled by a hand-written emitter that re-derives the argument and result
representations. It also keeps its own name list in `inferExprType`, which
must stay in step with the emitter. P3.2 lets a declaration name the runtime
entry point a call compiles to, so the signature drives both the emission
and the result type.

`Math` is the first step, because most of its functions are a single libm
call. `Math.exp`, `Math.asinh`, `Math.acosh` and `Math.atanh` had no emitter
at all; each failed with "Math.exp is not supported".

## Investigation

- **The hand-written path.** `emitMathUnaryFloat` and the `atan2` case of
  `emitMathBinaryFloat` (`codegen/llvm/emit_call_math.go`) each emit one
  `call double @fn(double)`, after `emitMathOperand` demotes a
  `T | undefined` scalar to its payload. `inferExprType` separately lists
  the same names as giving `TypeF64`.
- **Arity.** The hand-written path rejected any other argument count at
  compile time. JavaScript evaluates an extra argument and ignores it, and a
  missing number is `ToNumber(undefined)`, which is NaN. The strict lane
  rejects both as tsc does (TS2554), so only `-compat=js` reaches them.
- **Precision against Node.** A sweep of 19 functions over 16 inputs,
  compared with Node 24 on macOS, differs in the last binary digit for
  `log`, `log10`, `cos`, `tan`, `asin`, `acos`, `atan`, `cosh`, `sinh`,
  `expm1`, `log1p`, `acosh` and `atanh` (`Math.tan(1)` prints
  `1.557407724654902` here and `1.5574077246549023` in Node). The platform
  libm is not V8's fdlibm port. The hand-written path called the same libm
  symbols, so this predates the change. `cbrt` already uses an fdlibm port
  ([ADR-00242](ADR-00242.md)) for the same reason.
- **Resolving a call to its declaration.** The checker now records the
  member declaration a property access resolves to (`Property.Decl`,
  `Checker.MemberDecl`), when the access has a single declaration.

## Decision

- **Declarations.** A method signature may carry `/** @lower symbol */` (the
  entry point) and any number of `/** @link lib */` (libraries it needs).
  The parser records them on `ast.MethodSignature` (`Lower`, `Link`).
  `lib/es.d.ts` lowers `acos`, `acosh`, `asin`, `asinh`, `atan`, `atanh`,
  `atan2`, `cos`, `cosh`, `exp`, `expm1`, `log`, `log10`, `log1p`, `log2`,
  `sin`, `sinh`, `sqrt`, `tan` and `tanh` to the libm symbol of the same
  name, linking `m`.
- **`loweredCall`** (`codegen/llvm/emit_lowered.go`) is the single decider
  that both `emitCall` and `inferExprType` consult. It resolves
  `Global.method(…)` through the checker and applies when all of these hold:
  - the object is the builtin global itself, not a program binding that
    shadows it;
  - the member's declaration carries `@lower`;
  - the signature is neither generic nor overloaded, and has no optional or
    rest parameters;
  - every parameter and the result have a representation this path
    supports. So far that is `number` → double, `boolean` → i1, and `void`.

  The result is cached per call node. Any call it declines falls through to
  the hand-written emitters.
- **`emitLowered`** evaluates the arguments in order:
  - each argument is coerced to its parameter's representation, and a
    nullable scalar is demoted to its payload first, as `emitMathOperand`
    did;
  - an extra argument is evaluated and dropped;
  - a missing `number` argument is NaN.

  It then emits one call to the entry point. The entry point is declared once
  from the signature (`declareFn`, shared with `ensureMathFuncs`, so the
  lowered path and the hand-written runtime never declare a symbol twice),
  and its libraries are linked.
- **The checker for codegen** (`Emitter.front`) is built on first use over
  the program being emitted, bound with the builtin declarations.
- **Deleted:** `emitMathUnaryFloat`; the lowered names in `emitMathCall` and
  in `inferExprType`'s Math result list.
- **`Math.clamp` removed.** It is not a JavaScript function: Node throws
  "Math.clamp is not a function". It was undocumented and only
  `examples/math/math_methods.ts` used it. A program calling it now gets the
  same compile error as any other missing Math member.

## Implementation notes

- **A second checker.** `front()` builds its own checker rather than reusing
  the strict lane's. The strict lane checks the same merged program, but its
  checker does not reach codegen yet. P3.3, which moves codegen's type
  deciders onto the checker, is where one checker should be passed through.
  The checker is lazy, so only the expressions asked about are checked.
- **Shadowing.** The binder's global scope (`Binding.Globals`) is the test,
  alongside the emitter's own `isShadowedByLocal`: a local `const Math = …`
  keeps its own method.

## Side effects discovered

- **Precision.** The libm-vs-fdlibm last-digit differences are now disclosed
  on the Math status rows. A port of fdlibm is the fix, and it only
  requires changing the symbol each `@lower` names.
- **Assertions on absent values** (BACKLOG, P3.3): `u!` and
  `u as number` on an absent `number | undefined` read `0`, where Node
  reads `undefined`.
- **Math functions are not values** (BACKLOG): `xs.map(Math.sqrt)` and
  `const f = Math.sin` do not compile, before and after this change.
- **Clang warning on macOS 27.** Apple clang 21 warns on every textual-IR
  compile that it overrides the module triple, even when the IR stamps the
  canonical host triple verbatim. The host toolchain on macOS now passes
  `-Wno-override-module`, as the cross-target path already did
  (`codegen/llvm/hostclang.go`).

## Verification

- `TestE2EMathLoweredFromDeclarations`: exp and the inverse hyperbolic
  functions, NaN and Infinity edges, a shadowed `Math`, and, under
  `-compat=js`, missing and extra arguments. The existing Math tests pass
  unchanged.
- `examples/math/math_methods.ts` gains an exp/inverse-hyperbolic section,
  and its output is identical to Node's.
- The 19-function sweep above: every difference from Node is in the last
  digit. For the 15 functions the previous build supported, its output is
  byte-identical to this build's (macOS).
- Test262: strict 7,004 of 53,578 (up from 6,992), js 7,733 (up from 7,721).
- `make examples` 358/358. `make test-par` fails only on the known macOS
  `-mm=gc` segfaults and a known HTTP hang (`TestE2EHTTPChainedListenBinding`,
  which passes alone).
