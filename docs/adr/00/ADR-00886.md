# ADR-00886: Empty-array element-type inference from usage (TDD-00205 Stages 0+1)

- **Relations**: `Implements TDD-00205`
- **Date**: 2026-09-11

## Context

An untyped empty array literal `[]` had its element type blindly defaulted to
`number[]` (`inferArrayType`, `emit_exprs_types.go`), and `arr.push(v)` coerced
each value to that type — so `const a = []; a.push("hi")` (and the common
`var x = []; x.push(nonNumber)` shape) emitted invalid IR. This was the largest
non-one-line invalid-IR contributor left after the A1 coerce-site sweep
(ADR-00882–00885) — the RegExp exec-loop residue
(`built-ins/RegExp/prototype/exec/S15.10.6.2_A3_T{1,5,6,7}`,
`var __matched = []; __matched.push(re.exec(s)[0])`). Scoped in TDD-00205.

## Investigation

Two facts (measured, macOS arm64): the indexed-assignment grow path already
rejects a mismatch cleanly, and whole-array reassignment already retypes — only
the `push`/insert path emitted invalid IR, because it blindly coerced to the
declaration-time element type (`emit_arrays_mutate.go`). The existing
`crossTypeWidenedBindings` pre-pass (`emit_func.go`) is the model for a
whole-scope usage scan.

A subtlety surfaced in implementation: the pre-pass runs before the body's
symbols are defined, so `inferExprType` of a pushed *local* (`const s = …;
a.push(s)`, or `const e = re.exec(s); a.push(e[0])`) could not resolve it —
the first attempt (an ad-hoc `localTypes` table for bare identifiers) still
failed on a method call with a *local receiver* (`re.exec(s)`). The fix is to
register the body's bindings in a throwaway scratch scope in source order so
`inferExprType` resolves identifiers, index-into-local, and method-call
receivers naturally, then discard the scope.

## Decision

**Stage 0 — backstop.** The `push`/`unshift`/`splice`-insert/`fill` element
stores use `coerceChecked` (not bare `coerce`), so a still-mismatched element is
a clean COMPILE_ERROR ("array element") instead of invalid IR — the same
hardening the A1 sweep applied.

**Stage 1 — inference.** New pre-pass `inferEmptyArrayElemTypes` (`emit_func.go`)
scans a scope body for untyped bindings initialized to an empty `[]` and unifies
their element-contributing usages — `push`/`unshift`/`splice`-insert, `a[i] = v`
(grow), and whole-array reassignment. When every contribution unifies to one
element *kind* (Stage 1 scopes the safe, high-value kinds: number → `float64`,
string, boolean), that type replaces the `number[]` default; heterogeneous or
out-of-scope kinds are left out (Stage 0 rejects them). The pass runs where
`crossTypeWidenedBindings` runs (all four function/arrow/fn-expr sites +
module), saved/restored per body via a new `emptyArrayElems` emitter field, and
is consulted by `declaredArrayType` at the two var-decl type sites
(`reliableGlobalType`, `emitVarDeclBody`). Unlike the scalar pass it includes
`const` (a const array's contents still mutate) and runs in both lanes.

## Implementation notes

- The scratch scope uses `pushScope`/`defer popScope`; dummy symbols carry only a
  `Ty` (inference reads no register, emits no IR).
- `unifyElemTypes`/`elemKindKey` deliberately block object shapes, bigint, Date,
  nested arrays, and symbols (Stage 2) so two shapes can never mis-merge into a
  wrong element representation; `elemKindKey` uses `isForOfStringTy` (not the
  loose `isStringTy`) so a Symbol/Date/RegExp is not mistaken for a string.
- `emitArrayVarDecl` already threads the computed `ty` into both the Symbol and
  the empty-literal aggregate hint, so setting the declared type is sufficient —
  no back-patching.

## Side effects discovered

- `built-ins/RegExp` sampled category: **4 → 0 CLANG_ERROR** (the exec-loop
  untyped-array files, the ADR-00885 residue). RegExp is now 11 → 0 across this
  session.
- Nested-closure contributors are not seen (the pass does not descend into
  nested function/arrow bodies — the same boundary `crossTypeWidenedBindings`
  draws); such a binding keeps the default and Stage 0 rejects a mismatch. A
  documented V1 edge (TDD-00205 open questions).

## Verification

- Cases now compile+run: `push("hi")` → `string[]`, boolean pushes, loop of
  string pushes, `const s: string; a.push(s)`, `const r = /a/.exec(s);
  a.push(r[0])`, and the full `do { … a.push(re.exec(s)[0]) } while` RegExp
  idiom. Heterogeneous `push(1); push("x")` cleanly rejects (Stage 0). A
  never-pushed `[]` is unaffected.
- `go test ./tests/ -run
  'TestE2E(Array|Slice|Splice|Fill|CopyWithin|IndexOf|Push|Regex|RegExp|Sort|Map|Set)'`
  green; full `make test-par` gate run (core-codegen change).
- `go build`, `go vet ./...` — clean.
