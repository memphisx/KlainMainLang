# ADR-01709: Resuming a running generator throws

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-18

## Context

A generator body that called its own `next()`, `return()` or `throw()` swapped into its own running context and hung. The Test262 `GeneratorPrototype/*/from-state-executing` files timed out. The BACKLOG had them as Linux-only, but they hang on macOS too. When a `next()` was called on an `any` receiver, a finished step returned the element type's zero as its value, where Node returns `undefined`.

## Decision

- The caller-context field is set only while the body runs: a resume sets it and clears it once control returns. A resume that finds it set throws `TypeError: Generator is already running`. The error is thrown inside the body, so the generator completes, as in Node.
- The dynamic method adapter reads a sync step's result the same way a typed call does (`emitUserGenResult`), so `value` is undefined once the generator is done without a return value.

## Verification

macOS (Apple Silicon): the three `from-state-executing` Test262 files pass with their harness, as do `TestE2EJSGeneratorReentry` and the `Generator` E2E tests.
