# ADR-00330: Closure capture of a not-yet-initialized binding (self-reference in initializer)

- **Relations**: Extends ADR-00001 (capture-time promotion / boxing); surfaced by ADR-00328 (net.connect)
- **Date**: 2026-08-23

## Context

A closure that references a `const`/`let` inside that same binding's initializer
— `const s = f(() => use(s))` — miscompiled. The idiom is common and valid in
JS when the closure runs *later* (a self-cancelling timer `const id =
setInterval(() => clearInterval(id), ms)`; a `net.connect` connect callback that
writes to `const sock`). It produced garbage at `-O0` and, worse, undefined
behavior the optimizer exploited at `-O2` (a non-null call result observed as
null, crashing `net.connect`). Found building ADR-00328.

## Investigation

Captures are always **boxed** (ADR-00001): the first closure to capture a
variable promotes it to a heap cell shared by pointer with the enclosing scope
and every capturing closure (`promoteCaptureToCell`, emit_func.go). Reads/writes
need no special handling — the symbol's `Ptr` just points at the cell. Two
defects combined to break the self-reference case:

1. **Seeding by loading an uninitialized slot.** Promotion seeded the new cell by
   `load`-ing the variable's current slot value. For a binding still inside its
   own initializer, that slot holds no value yet (a `const x = <init>` gets no
   default-init). The `load` reads uninitialized memory — benign-looking at
   `-O0`, but at `-O2` it is UB that propagates as poison and miscompiles
   surrounding code.
2. **Object bindings never re-resolved the final store.** The generic scalar
   var-decl path (emit_exprs_vardecl.go) already re-resolves the final store to
   the variable's *current* slot (the box, if the initializer promoted it) —
   this is what makes the self-cancelling-timer idiom work. But
   `emitObjectVarDecl` (emit_objects.go) stored straight into the original
   alloca, so for an object-typed binding (`const sock: NetSocket = …`) the real
   value was written to the stale alloca, never the box the closure reads. So
   even a deferred call saw the seed, not the assigned value.

The debug that pinned it: `const x = make(() => x)` (number) took the generic
path and hit defect 1 only; `const sock = net.connect(…, () => sock.write())`
(object) took `emitObjectVarDecl` and hit both.

## Decision

When the captured variable is still being initialized, **seed its box with the
type's deterministic default instead of loading the uninitialized slot**, and
ensure the variable declaration's final store targets the (possibly promoted)
box. A binding currently having its initializer emitted is tracked in
`e.varsBeingInitialized`; `promoteCaptureToCell` consults it.

Consequences:
- A closure invoked **after** the declaration completes (the common, valid case)
  sees the assigned value — the real value lands in the shared box via the
  re-resolved store.
- A closure invoked **synchronously during** the initializer (genuine
  temporal-dead-zone misuse) sees the type default rather than garbage — a
  deterministic, memory-safe outcome.
- The `-O2` UB is gone: no `load` of an uninitialized slot is ever emitted.

Alternative considered — emit a TDZ ReferenceError for access-before-init.
Rejected: distinguishing a synchronous in-initializer call from the valid
deferred case needs flow analysis this compiler doesn't have, and the deferred
case *must* work; the default-seed makes the valid case correct and the invalid
case deterministic, which is the pragmatic win. A real TDZ pass can layer on
later without changing this.

## Implementation notes

- `promoteCaptureToCell` (emit_func.go): new shared helper replacing the three
  duplicated promotion blocks (arrow, function-expression, generator). Seeds the
  cell by default when `e.varsBeingInitialized[name]`, else by copying the
  current value.
- `e.varsBeingInitialized` (emitter.go): set around initializer emission in both
  the generic `emitVarDecl` path and `emitObjectVarDecl`.
- `emitObjectVarDecl` (emit_objects.go): every store now goes through a
  `storeObj` closure that re-resolves the variable's current slot — matching the
  generic path's ADR-00001 re-resolve, which object bindings previously lacked.

## Side effects discovered

`emitObjectVarDecl` was silently missing the ADR-00001 re-resolve entirely — any
object binding captured-and-promoted inside its own initializer wrote its real
value to the wrong location, not just in the net.connect case. Now fixed for all
object initializer shapes. The `net.connect` connect callback can now close over
the `const sock` binding directly; passing the socket as the callback argument
(ADR-00328) remains supported as a convenience but is no longer required.

## Verification

- Repros: `const x = make(() => x)` (sync, number) and object equivalents now
  print the deterministic default then the assigned value; the self-cancelling
  `setInterval` idiom sees the real id; a `net.connect(…, () => sock.write())`
  client (closing over `const sock`) completes a round trip at `-O2`.
- Full `go test ./tests/` passes (core var-decl + closure + timer + net paths).
- Machine: verified on Mac (Apple Silicon); the `-O2` vs `-O0` divergence was the
  original symptom, so both optimization levels were checked.
