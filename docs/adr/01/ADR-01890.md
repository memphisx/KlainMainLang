# ADR-01890: a method returning `this`

- **Relations**: `Implements TDD-00230` (the checker models tsc's types; P3.3's unanswered bucket)
- **Date**: 2026-10-21

## Context

- tsc infers `return this` in a method as the polymorphic `this` type, instantiated with the receiver at each access: `new B().m()` is a `B` when `m` is A's, and an object literal's method returning `this` returns the literal's own (circular) type. The checker left any such return unanswered, and with it the function, the object literal holding it (`{ [Symbol.asyncIterator]() { return this; }, next() {…} }`, a common Test262 shape) and everything read from either.

## Decision

- `return this` contributes the polymorphic `this` type to the inferred result; a member read through a receiver already instantiates it (withThis). While an object literal is being typed, a `this` it returns whole is that polymorphic type rather than the literal's partial snapshot.

## Consequences

- Fluent methods type as tsc types them, through subclasses; object literals returning themselves are answered.
- Verified on Apple Silicon against tsc 5.6.3.
