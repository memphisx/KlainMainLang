# ADR-01966: The E2E programs' top-level bindings agree with the front end

- **Relations**: Implements TDD-00230 (P3.3); follows [ADR-01965](ADR-01965.md)
- **Date**: 2026-10-29

## Context

Run over `make test-par` with `KML_SHADOW_KEEP`, the shadow harness compared about 186,000 top-level bindings of the E2E programs. 44 disagreed between codegen's `decideGlobalType` and the front end's answer. In some, the front end's mapping from a checker type to codegen's layout had no rule. In others, codegen or the builtin declarations diverged from tsc.

## Decision

Where tsc and codegen diverged, codegen and the declarations follow tsc:

- `lib/es.d.ts` declares tsc's generic overload `fromEntries<T = any>(entries: Iterable<readonly [PropertyKey, T]>): { [k: string]: T }`. An unannotated `Object.fromEntries(…)` is held as an annotated `{ [k: string]: T }` binding holds it.
- `Object.assign(target)` with one argument matches only tsc's `(target: object, ...sources: any[]): any` overload, so codegen holds its result boxed.
- `PromiseLike<T>` is a native promise or any thenable. `resolveType` holds it boxed: it had read the unknown generic name as an array (`string[]`).
- A `.flat()` result of boxed elements takes the checker's element type, a box too: `(number | undefined)[]`, `(number | number[])[]`.

The front end's layout mapping (`reprCtx.of`, `GlobalType`) gains these rules, matching codegen:

- A void call's result is stored as `undefined`, and `void` beside other union members is `undefined`.
- `Iterable<T>` and `AsyncIterable<T>`, which values of many layouts satisfy, and `PromiseLike<T>` are boxed. Beside one other member (`T | PromiseLike<T>`, a resolver's value), `PromiseLike<T>` drops out: codegen's resolvers take the value. Beside several, the union is boxed.
- An annotated binding of the empty tuple `[]` is an empty positional struct. A `[] | [T]` rest parameter (`Generator.next`) keeps no layout.
- A program interface with no members of its own that extends `Array<T>` or `ReadonlyArray<T>` is that array.
- A callable interface of only call signatures is its first signature; codegen erases the rest.
- A library interface implemented as a library class is that class whatever its type arguments (`DataView<ArrayBufferLike>`, `WeakRef<T>`). An instantiated iteration interface (`Generator<number>`) stays boxed.
- A binding of an overloaded function, or of a function with properties, holds the implementation's signature (`export default strict`).
- A tuple rest parameter of mixed elements is the boxed array its arguments are collected into.
- A function expression's return annotation declares the tuples in its result.
- A type of the same name as a `const` (`type Pair` beside `const Pair`) is not an earlier declaration of the variable.
- An unannotated union of several array types is the box codegen's literal inference builds. A union of strings, scalars and one object boxes every member. An object member keeps its literal tags (`k: "a"`).
- An alias of an object literal's binding (`const q = a`), and an array of object literals with methods, hold that literal's layout, its methods taking their boxed `this`.
- A collection or `matchAll` iterator's `next()` is its `{ value, done }` step.
- A `new` of a Promise subclass with no constructor and no instance members passes its executor to Promise, so the executor's `resolve` is a resolver of the `Promise<T>` the class extends.
- A bare `new Map()` whose calls the pre-pass never saw has the pre-pass defaults. A `new WeakSet()`, `new WeakSet(null)` or `new WeakMap(null)` has the key type `weakSetElem` and `weakMapKV` infer.
- A constructor type (`new (n: string) => A`) holds a constructor reference, boxed, as a class's value (`typeof A`) already did.
- Under `-compat=js`, an unannotated copy of a boxed binding (`var e = d` where `d` is later assigned `null`) holds the same box. A copy of a binding whose initializer is held dynamically (`var a2 = arr` after `var arr = [1, [2, 3]]`) has that binding's layout.
- Typing an object literal's fields or method results stops at the literal itself when one of its methods reads the literal's own binding (`n: function () { return o.m(); }`). Before, the oracle looped through the method and back to the literal until the stack overflowed. The comparison hook also no longer asks the oracle while the oracle itself is asking codegen.

## Consequences

- None of the 44 bindings disagrees any more, and those programs' output still matches Node.
- `TestE2EObjectFromEntriesNonStringKeys` and `TestE2EObjectFromEntriesSymbolAndObjectKeys` indexed `{ [k: string]: T }` with a symbol, which tsc rejects (TS2538). They now index through `any`, which tsc accepts.
- The parser still rejects a symbol index signature (`[k: symbol]: T`).
- Whether a binding's initializer is held dynamically is now computed once per declaration. Before, every read of the binding typed the whole initializer again, so a shadow run on a 20,000-row table took 33 s where a plain compile takes 5 s. It now takes 4 s.
