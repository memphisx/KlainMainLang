# ADR-01794: hasOwnProperty on functions and primitives; typeof of a generator function

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- `Object.prototype.hasOwnProperty.call(fn, k)` and `Object.hasOwn(fn, k)` on a function or primitive failed to compile ("requires an object"). Test262's `verifyProperty` helper starts with exactly this call.
- `typeof g` for a generator function declaration read "undefined".

## Decision

- `emitHasOwnProperty` boxes any non-object receiver and answers through the dynamic own-property test, which knows a function's `name`/`length` and own-property bag and a string's indices and `length`.
- In that test, a primitive converts to its object as hasOwnProperty requires: a string has its indices and `length` (`__kml_str_has_own`), other primitives have nothing, and null and undefined throw "Cannot convert undefined or null to object". The `in` operator still throws on any primitive.
- `typeofStaticAnswer` answers "function" for a registered generator.

## Consequences

- `TestE2EJSFileFunctionOwnPropertyChecks` compares functions, generators and strings against Node.
- Still open: a generator function's `prototype` object.
