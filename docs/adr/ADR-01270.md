# ADR-01270: The monotonic clock is nanosecond-grained on macOS

- **Relations**: `Extends ADR-00568`
- **Date**: 2026-09-29

## Context

Darwin's `CLOCK_MONOTONIC` (6) counts microseconds, so two
`performance.now()` calls in a row often returned the same value, and
entries made in quick succession tied. libuv's `uv_hrtime` reads
`mach_absolute_time`, which is nanosecond-grained.

## Decision

On Darwin the runtime's monotonic clock is `CLOCK_UPTIME_RAW` (8,
`mach_absolute_time`). This covers timers, `performance.now()` and
`process.hrtime`. Linux keeps `CLOCK_MONOTONIC`.

## Verification

Mac (Apple Silicon): consecutive `performance.now()` readings differ;
timer, hrtime and perf tests pass.
