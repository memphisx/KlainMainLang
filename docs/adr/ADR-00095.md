# ADR-00095: Remove dead `__kml_fetch` (blocking single-transfer fetch, superseded by ADR-00050)

- **Relations**: Extends [ADR-00094](ADR-00094.md), which found this during its own investigation but deferred removing it; superseded by [ADR-00050](ADR-00050.md)'s non-blocking multi-interface rewrite, which is what actually made this dead
- **Date**: 2026-08-04

## Context

While implementing ADR-00094 (fetch/fs embedded-null-byte fix), tracing every caller of `runtime_fetch.go`'s functions to figure out which return-aggregate shapes actually needed a `bodyLength` field added, `grep` turned up that `@__kml_fetch` — a full blocking, single-`curl_easy_perform`-call GET implementation, complete with its own status/body-extraction and network-error-throwing logic — had exactly one caller: `ensureFetchAsync`, and only for its *side effect* of also declaring the shared `curl_easy_*` primitives and `__kml_curl_write_cb`. `emitFetch` (`emit_fetch.go`), the only place a user's `fetch(...)` call is ever lowered, has gone through `__kml_fetch_async`/`__kml_pending_finish`/`__kml_await_fetch` exclusively since ADR-00050. `@__kml_fetch` itself was reachable from no live code path, undocumented as removable, had no test exercising it directly (impossible — nothing in this compiler could still name it), and no example used it either.

ADR-00094 initially chose to leave it alone — a scope decision, not an oversight — and recorded it under "Side effects discovered" instead. Reviewing that call: it doesn't meet the bar of *unfixed* the way an actual latent bug does — dead code can't misbehave — so it read as a defensible thing to defer rather than something silently dropped. Told directly that this reasoning was wrong: code that serves no purpose and carries no documentation/examples/tests pointing at it as intentionally-kept is exactly the shape of thing that should be treated as a bug and removed, not filed away as a footnote. Correcting course here.

## Investigation

- Confirmed via `grep -rn "__kml_fetch\b" codegen/llvm/*.go` (excluding `__kml_fetch_async`/`__kml_await_fetch`/etc., which are separate symbols) that the only reference to the literal `@__kml_fetch` call target was its own `define` site plus one doc-comment mention — no `call` site anywhere.
- Confirmed `ensureFetchAsync` (`runtime_fetch.go`) needs from `ensureFetch()` only: `requireLink("curl")`, `ensureMalloc`/`ensureRealloc`/`ensureMemcpy`/`ensureExceptionHelpers`, the `curl_easy_*` `declare`s, the `@__kml_curl_inited` global, and `@__kml_curl_write_cb` — none of which live inside `__kml_fetch`'s own function body.
- Compiled a throwaway program with `--emit-llvm` before and after removal and grepped the output: `@__kml_fetch(` went from present to zero occurrences; `__kml_curl_write_cb` (still needed) stayed present.

## Decision

Deleted `__kml_fetch`'s entire `define { i64, ptr } @__kml_fetch(ptr %url) { ... }` IR block and the `errNamePtr := e.internString("Error")` local that only it used, from `ensureFetch()` (`codegen/llvm/runtime_fetch.go`). Rewrote `ensureFetch`'s doc comment, which previously described `__kml_fetch` itself, to instead describe what the function now actually declares (the shared `curl_easy_*` primitives and write callback) and to record why the removed function existed and went dead, for anyone who finds a reference to it in git history or an older ADR. Also dropped the `CURLINFO_RESPONSE_CODE=2097154` mention from that comment — that constant was only ever used inside the deleted function's own `curl_easy_getinfo` call.

No alternative considered — this is a straightforward deletion of confirmed-unreachable code, not a design decision with tradeoffs.

## Implementation notes

File touched: `codegen/llvm/runtime_fetch.go` only. `ensureFetch()`'s exported behavior (what it declares, callable by `ensureFetchAsync`) is otherwise unchanged — `usedFetch`'s guard-flag semantics, and every symbol other code actually calls, are untouched.

## Side effects discovered

None new.

## Verification

- `go build -o klainmain .`, `go vet ./...` — clean.
- `--emit-llvm` diff on a fetch-using program: `@__kml_fetch(` present before, zero occurrences after; `__kml_curl_write_cb` present in both (2 occurrences each — declare-site aside, unaffected by the removal).
- `go test ./... -count=1` — full suite green, no regression in any `fetch`/`Promise.all`/`.race`/`.allSettled` test (the exact tests that would catch a mistake here, since they're the only live callers of anything `ensureFetch()` declares).
