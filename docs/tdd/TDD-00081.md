# TDD-00081: EventTarget / Event / CustomEvent (+ AbortController)

- **Status**: Implemented
- **Date**: 2026-08-19
- **Notes**: The WHATWG event trio (distinct from Node's `EventEmitter`) — a generic `EventTarget` bus (`addEventListener`/`removeEventListener`/`dispatchEvent`) plus `Event`/`CustomEvent`, and the `AbortController`/`AbortSignal` it enables. Mostly a *generalization*: EventSource already reuses EventEmitter's `Map<string, listener-list>` registry + snapshot dispatch, so this reuses `__kml_ee_list_*`/`__kml_map_str_*`/`emitCBCall` and adds `Event`/`CustomEvent` object types, an `IsEventTarget` tag, construction nodes, and dispatch-by-`event.type`. Staged: Event/CustomEvent → EventTarget → AbortController (signal fires `"abort"`, wired into `fetch`/timers). No `class X extends EventTarget` (built-in `extends` unsupported)

## Context

The Events & Cancellation area is 0/3. The WHATWG event trio — `Event`/
`CustomEvent` and the `EventTarget` bus (`addEventListener`/`removeEventListener`/
`dispatchEvent`) — is distinct from Node's `EventEmitter` (already shipped), and
the status page flags the real leverage: `EventTarget` is the prerequisite for a
general `AbortController`/`AbortSignal`, i.e. cancellation for `fetch`/timers/
streams. So this closes a category *and* sets up cancellation, which ties back to
the REST priority.

The machinery is already almost entirely built. **EventSource reuses
EventEmitter's listener registry wholesale**: a `Map<string, listener-list>` keyed
by event-type string, each value an array of `{closure, once}` entries, dispatched
by a snapshot-copy-then-invoke loop. This TDD generalizes that into a first-class
`EventTarget`.

## Design

### Representation

- **`EventTarget`** — modelled on `EventEmitter` (emit_eventemitter.go:78): the
  value *is* a `Map<string, listener-list>` pointer (`__kml_map_str_create`),
  tagged with a new `IsEventTarget` flag on `Type` (alongside `IsEventEmitter`,
  types.go). `new EventTarget()` mallocs nothing beyond the map. Listener lists
  reuse the `__kml_ee_list_*` ABI (runtime_eventemitter.go) verbatim.
- **`Event` / `CustomEvent`** — fixed-shape objects, modelled on
  `MessageEventType()` (types.go:685): `Event` is `{ type: string, defaultPrevented:
  bool, cancelable: bool }` (plus an internal `stopImmediate` flag); `CustomEvent`
  adds `detail`. `new Event(type)` / `new CustomEvent(type, { detail })`. Detail is
  `CustomEvent<T>`-parameterized (mirroring `EventEmitter<T>`), defaulting to
  `any`/dynamic when unparameterized.

### Methods

- **`addEventListener(type, cb, opts?)`** — `emitEventEmitterGetOrCreateList` on the
  target's map for `type`, then `__kml_ee_list_push(list, closure, once)`. `opts`
  is an object literal: `{ once }` uses EventEmitter's *real* `once` flag path (not
  EventSource's hardcoded-0); `{ capture, passive }` are accepted no-ops (no DOM
  tree); `{ signal }` is deferred to the AbortController stage.
- **`removeEventListener(type, cb)`** — `__kml_ee_list_remove(list, closure)`,
  matching by the closure header pointer (see Open questions on inline-arrow
  identity).
- **`dispatchEvent(event)`** — read the `type` field off the event object, look up
  its list, snapshot-copy it (so mid-dispatch removal is safe), and invoke each
  listener with the *event object* via `emitCBCall` (`FuncType([eventTy], void)`);
  remove `once` entries afterward; return `!event.defaultPrevented`. This is
  `emitEventEmitterEmit`'s loop (emit_eventemitter.go:331) with the type read from
  `event.type` instead of a separate argument.

### Event methods

- `preventDefault()` — set `defaultPrevented` (only when `cancelable`).
- `stopImmediatePropagation()` — set the event's internal stop flag, which the
  dispatch loop checks to halt the remaining listeners.
- `stopPropagation()` — accepted no-op (single target, no capture/bubble tree).

### Construction wiring (the genuinely new code)

New AST nodes `NewEventTargetExpression` / `NewEventExpression` /
`NewCustomEventExpression`, a `parseNew` case each (parser_literals.go:131,
modelled on `parseNewEventSourceBody`), and routing in both `emit_exprs.go` and
`emit_exprs_vardecl.go` (the var-decl fast-path). Method dispatch adds an
`IsEventTarget`-guarded block in `emit_call.go` beside the `IsEventSource` chain
(:139).

### V1 semantics scope

Single-target dispatch only (no DOM → no capture/bubble/propagation path);
`once`, `preventDefault`/`defaultPrevented` (→ `dispatchEvent` return),
`stopImmediatePropagation`; `capture`/`passive` accepted no-ops. **No
`class X extends EventTarget`** — built-in `extends` targets are rejected, so
`EventTarget` is used directly or by composition (disclosed caveat).

### Staged delivery

1. **`Event` / `CustomEvent`** — object types + constructors, `type`/`detail`/
   `defaultPrevented`/`cancelable`, `preventDefault`/`stop*`.
2. **`EventTarget`** — `new EventTarget()` + `addEventListener`/
   `removeEventListener`/`dispatchEvent` over the generalized registry.
3. **`AbortController` / `AbortSignal`** (designed here, its own ADR): `AbortSignal`
   is an `EventTarget` with extra state (`aborted: bool`, `reason`) that fires an
   `"abort"` event; `AbortController.abort(reason?)` sets the state and dispatches.
   Then wire `signal` into `fetch` (the status note: `curl_multi_remove_handle` +
   `curl_easy_cleanup` on the tracked in-flight transfer, ADR-00050) and into the
   timer cancellation path. Because `AbortSignal` needs fields beyond the bare map,
   it is a small struct wrapping the target map + `aborted`/`reason`.

## Open questions

- **`CustomEvent` detail typing**: `CustomEvent<T>` (generic, mirroring
  `EventEmitter<T>`) vs. plain `any`/dynamic. Recommend generic with an `any`
  default.
- **`removeEventListener` identity**: matching relies on the *same* closure header
  pointer, so a listener held in a variable removes fine, but an inline arrow
  re-emitted at the remove site is a different closure and won't match (the same
  limitation EventEmitter has). Accept as a V1 caveat, or require a named binding.
- **`stopImmediatePropagation`**: implement via an internal event flag the dispatch
  loop checks each iteration — confirm the event object can carry mutable internal
  state cheaply.
- **`AbortController` first form**: the general `EventTarget`-based signal (the
  point of this work) vs. the lower-effort fetch-specific token the status page
  notes. Recommend the general one, since EventTarget is being built anyway.
- **`AbortSignal` shape**: a struct wrapping the target map plus `aborted`/`reason`,
  vs. reusing the bare-map EventTarget with side-table state. Struct is cleaner.
