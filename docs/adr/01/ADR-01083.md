# ADR-01083: `-mm=auto` no longer frees a Blob's `slice()` as a string

- **Relations**: `Extends TDD-00173`
- **Date**: 2026-09-23

## Context

`make examples MM=auto` (and `MM=auto OPTMEM=1`) failed on `examples/blob/blob.ts`:
- Linux: `free(): invalid pointer`, abort;
- Windows: `0xC0000374`, heap corruption.

The smallest repro is `const w = g.slice(7, 12, "text/x-word")` on a `Blob`. The output is correct, and the process dies at the block exit.

## Investigation

- The `-mm=auto` IR ends `main` with `call void @__kml_str_free(ptr %w)`, the string free, which releases `ptr - 8`, on a Blob record.
- `autoFreeOwningInit` (`codegen/llvm/emit_autofree.go`) treats `x.slice()` as an owning fresh result when the receiver `isStringTy`. `isStringTy` is the loose test, and it matches any bare `ptr`, a `Blob` handle (`Type{IR: "ptr", IsBlob: true}`) included.
- `freeResolvedPointer`'s string arm (`emit_memory.go`) used the same loose test, so even an explicit free of a Blob went to the string free.

## Decision

- The receiver test uses `isForOfStringTy` (the strict "a genuine string" predicate), which excludes the Blob, URL, TypedArray, RegExp and other handle types.
- `freeResolvedPointer`'s string arm excludes `IsBlob`, so a Blob record takes the plain `free()` arm below it.

## Implementation notes

`codegen/llvm/emit_autofree.go`, `codegen/llvm/emit_memory.go`. A non-string receiver is simply not an auto-free candidate: no free is emitted, which is the safe direction.

## Side effects discovered

None.

## Verification

- Windows x64: the repros and `examples/blob/blob.ts` exit 0 under `-mm=auto`, both with and without `-optimize-memory`.
- `tests/memory_auto_test.go` `TestE2EMemoryAutoBlobSliceNotFreedAsString`.
- Linux x86-64 (Docker): `make examples MM=auto` and `MM=auto OPTMEM=1` were re-run.
