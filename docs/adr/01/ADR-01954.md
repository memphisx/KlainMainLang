# ADR-01954: A callback to a generic call is checked against the inferred instantiation

- **Relations**: Implements TDD-00230 (P2.7)
- **Date**: 2026-10-29

## Context

`red(0, (x) => "s")` for `function red<U>(init: U, cb: (p: U) => U): U` compiled and ran, though tsc rejects it: `0` fixes U to `number`, the callback's parameter is typed from U, and its `string` result does not fit `(p: number) => number` (TS2345). The checker checked a generic call's arguments against the inferred instantiation but skipped every context-sensitive argument, so a callback's result was never checked. The same callback with an annotated parameter, `(x: number) => "s"`, was rejected.

## Decision

- An arrow function or function expression passed to a generic call is checked against the parameter instantiated with the call's inferred type arguments, as tsc's second inference pass checks it. Other context-sensitive arguments (object literals with methods, nested context) are still skipped.
- For an overloaded callee, an overload whose instantiated callback parameter the callback's result does not fit is a misfit. When every overload misfits, the call matches none (TS2769), as `xs.reduce((a, b) => "s", 0)` on a `number[]` does in tsc. The callback is typed once, under the context of the overload the call resolves to, and that type is checked against each overload. A call is rejected only when no overload fits, so this cannot reject a call that another overload accepts.

## Consequences

- `TestE2EGenericCallbackResultChecked` covers the rejection in both argument orders and the calls that stay valid. Outputs were compared against Node on macOS (Apple Silicon).
- Overload resolution itself still picks without typing a callback against each candidate; only the misfit report reads the callback's result.
