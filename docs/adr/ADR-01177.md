# ADR-01177: `worker_threads.isMainThread`, and a program that is its own worker

- **Relations**: `Extends [ADR-00305](ADR-00305.md)`, [TDD-00098](../tdd/TDD-00098.md)
- **Date**: 2026-09-26

## Context

`worker_threads.isMainThread` did not exist (20 of Node's own tests import
it). Node's tests also start their workers from their own file, `new
Worker(__filename)` in the `isMainThread` branch with the worker's code in
the other. That was rejected: a worker needed a literal path, and the
entry file could not be a worker module.

## Investigation

- A worker module's code is compiled into the binary as its own entry
  function (TDD-00098): its declarations join the program, and its
  executable statements become the worker's body.
- `isMainThread` is known where code is compiled: the program's code runs
  on the main thread, a worker module's on a worker.
- A file that is its own worker needs its executable statements twice, once
  in the program and once in the worker, and the two copies must not share
  nodes: code generation keeps per-node state (a promoted module global).

## Decision

- `isMainThread` is `true` in the program's code and `false` in a worker
  module's. `if (isMainThread)` / `if (!isMainThread)` emits only the branch
  that runs there, so the worker's copy has no worker start of its own.
- The resolver reads `new Worker(__filename)` as a worker of the file
  itself. Such a file (the entry included) is also its worker module; the
  worker's body comes from a second parse of the file, mangled and renamed
  exactly as the first, so both copies name the same declarations.
- The annotated `workerData` read that types a worker's data is found in
  nested statements too (the `else` branch).

## Implementation notes

`resolver/resolver.go` (`rewriteSelfWorker`, `onlySelfWorker`, the worker
copy), `resolver/virtual_modules.go`; `codegen/llvm/emit_exprs.go`,
`emit_exprs_types.go`, `emit_stmts.go` (`isMainThreadTest`), `emit_worker.go`.

## Side effects discovered

- A worker start not guarded by `isMainThread` inside a file that is its own
  worker is still the compile error for a worker that starts workers.

## Verification

Mac (Apple Silicon), against Node v24.19 (CommonJS, both lanes):
`tests/worker_test.go` (`TestE2EWorkerIsMainThread`,
`TestE2EWorkerSelfFilename`).
