# ADR-01693: A class-typed method call runs the instance's own method

- **Relations**: Implements TDD-00230
- **Date**: 2026-10-18

## Context

TDD-00230 P3.3. A method call on a value typed as class `A` called `A`'s method directly, or through `A`'s vtable. The value can be an instance of an unrelated class: a cast through `any`, or a structurally compatible class TypeScript accepts as `A`. Then `(new B() as any as A).m()` ran `A.m`. Node looks the method up on the instance and runs `B.m`.

## Decision

The decision is made at compile time, per call:
- **No other class has the method:** when no class outside `A`'s hierarchy has a method named `m` (and `A`'s ancestors are not counted), the call stays as it was. No instance can be found that has another `m`.
- **Another class has it:** the call first compares the instance's header word with the header words of `A` and its subclasses.
  - **A match, or a null receiver:** the typed call runs, as before. A null receiver keeps the typed call's error.
  - **Any other header:** the instance is boxed and the method is called by name, through the dynamic call. Its result is converted to the typed call's result type.
- **Arguments:** only one arm runs, so each argument is evaluated once.

The check applies only between the program's own classes. A call written in the builtin library, or on a library class, keeps the typed call: those classes are not cast between, and their callback-taking methods inline the callback they can see.

An abstract method's dynamic adapter (the method a boxed instance of the abstract class's type exposes) dispatches to the instance's override, as it has no body to call directly.

Not covered:
- A call whose argument is a function literal keeps the typed call. The callee inlines what it sees of the literal, and each arm would emit the closure again.
- A class whose header is not at offset 0 (a host subclass such as `extends Array`) keeps the typed call.
