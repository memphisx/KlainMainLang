# ADR-02060: toLocaleUpperCase/toLocaleLowerCase; case mapping reads the length header

- **Date**: 2026-11-22

## Context

- `toLocaleUpperCase` and `toLocaleLowerCase` were declared but had no
  implementation: a call threw `TypeError: … is not a function` at run
  time.
- `toUpperCase`, `toLowerCase` and `normalize` measured their argument with
  `strlen`, so a string holding `\0` was mapped only up to it. The comment
  justifying that ("sidecar strings carry no length header") was stale:
  every literal and heap string has the header, and `.length` reads it.

## Decision

- Both locale methods are TypeScript (lib/node/kml_string.ts). They read
  the first entry of the locale list, as V8 does: `undefined` means the
  default; a non-string, non-object entry is a TypeError; a malformed tag
  is V8's RangeError, and a tag ending in `-` gives its "Invalid language
  tag" message. The tag's language then picks a mapping in casemap.c
  (`__kml_native_locale_case`).
- The mappings are SpecialCasing.txt's language-sensitive ones, as ICU
  applies them:
  - tr/az: `i` → `İ`. `İ` → `i`. `I` → `ı`, or `i` with the following
    U+0307 dropped.
  - lt: `I`, `J` and `Į` keep a dot above before an accent. `Ì`, `Í` and
    `Ĩ` expand. Upper case drops U+0307 after a soft-dotted letter.
  - The context tests skip combining marks by their canonical class.
- Case mapping and `normalize` take the byte length from the header.

## Consequences

- `TestE2EStringLocaleCase` matches Node across those locales, the tag
  checks and NUL-holding strings.
- Verified on Node304 (Linux x86-64).
