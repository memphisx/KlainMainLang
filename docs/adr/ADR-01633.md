# ADR-01633: `copyFile` onto a read-only file fails with EPERM on Windows

- **Relations**: Extends ADR-01030
- **Date**: 2026-10-14

## Context

Node's `test-fs-copyfile-respect-permissions` failed on Windows: copying onto
a destination made read-only (`chmod 444`) succeeded.

## Investigation

`__kml_win_copyfile` (`win32fs.c`) retried a refused `CopyFileW` after
clearing the destination's read-only attribute, on the stated assumption that
Node replaces such a file. Node 24.19 refuses with EPERM in all three forms
(sync, callback, promise) and leaves the destination's content; libuv's
`fs__copyfile` does not retry.

## Decision

`__kml_win_copyfile` is the single `CopyFileW`; the error maps as before
(`ERROR_ACCESS_DENIED` → EPERM).

## Implementation notes

`win32src/win32fs.c`.

## Verification

Windows 11: the three forms print `EPERM` with the destination unchanged, as
in Node. `TestE2EWinCopyFileReadOnlyDestinationEPERM`;
`TestE2EWinCopyFileCarriesMetadata` still passes. The Node file passes.
