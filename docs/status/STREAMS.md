# Streams API

> Part of the [Implementation Status](README.md) index. `ReadableStream`, `WritableStream`, and `TransformStream` are the WHATWG (browser-standard) backbone of pipeline-style data processing. Node has its own, older, differently-shaped `stream` module — see the Node rows below — that real Node code (including `fs`/`http`/`child_process` internally) actually uses far more than the WHATWG API.

**Coverage**: 7/8 (~88%) · **Strict Coverage**: 1/8 (~13%).

Format: [Status page format](README.md#status-page-format).

Full design: [TDD-00097](../tdd/TDD-00097.md) ([ADR-00296](../adr/ADR-00296.md)–[ADR-00302](../adr/ADR-00302.md), [ADR-00304](../adr/ADR-00304.md)). `pipeTo` (all four shutdown-propagation rules + `prevent*` + `AbortSignal`), `pipeThrough`, and `tee()` come with the rows below; in-memory pipelines run on the promise/microtask runtime alone — no fibers or libcurl. HTTP integration is tracked where it surfaces: fetch `Response.body` on [NETWORKING.md](NETWORKING.md), streaming response/request bodies on [HTTP-SERVER.md](HTTP-SERVER.md).

| Feature | Status | Caveats | Notes |
|---|---|---|---|
| `ReadableStream` | ✅ | • No BYOB readers / byte controllers (`type: 'bytes'` rejected at compile time) — byte data flows as `Uint8Array` chunks through default readers<br>• `ReadableStream.from()` accepts arrays only, not async iterables<br>• Source callbacks must be arrow/function-expression/method-shorthand literals; a cancel callback can't take a reason parameter; *async* method shorthand (`{ async pull(c) {…} }`) doesn't parse — use `pull: async (c) => …`<br>• `read()` on a closed stream yields the chunk type's zero value, not `undefined`; `controller.desiredSize` is `0` (not `null`) once closed/errored<br>• `releaseLock()` leaves queued pending reads pending instead of rejecting them<br>• `values()` returns a reader usable in `for await` only (no standalone `.next()`)<br>• In the no-fiber tier, `await` of an already-settled `read()` skips the microtask drain, so a pending pull can run one tick later than real JS<br>• A synchronously-throwing pull/start propagates to the caller instead of erroring the stream<br>• `tee()` forwards the last cancelling branch's reason instead of composing both; a signal abort of `pipeTo` takes effect at the next chunk boundary | • One 144-byte heap struct fuses stream + controller + reader (compile-time retyping); chunk queue + pending-read promise FIFO with HWM/size accounting; spec CallPullIfNeeded; per-site fulfill thunk builds typed `{value,done}` records ([ADR-00296](../adr/ADR-00296.md))<br>• Runs on the promise/microtask runtime alone — no fibers or libcurl for in-memory pipelines |
| `WritableStream` | ✅ | • `desiredSize` is `0` (not `null`) once errored; `releaseLock()` doesn't reject a pending-write view<br>• A synchronously-throwing sink write propagates instead of erroring the stream (an async rejection is handled per spec)<br>• A sink abort callback can't take a reason parameter; no transformer/sink `start` promise-vs-write interlock beyond the started flag | • 128-byte fused stream+controller+writer struct; 32-byte write-queue entries carry their own per-write promise; `ready` re-armed on backpressure flips ([ADR-00297](../adr/ADR-00297.md)) |
| `TransformStream` | ✅ | • No transformer `start` callback<br>• Cancelling the readable side doesn't error the writable side<br>• An identity transform (no callback) requires matching I/O chunk representations | • Writable sink write runs the transform when the readable side has capacity, else parks the chunk (at most one, by write serialization); readable pull resumes it; spec defaults writable HWM 1 / readable HWM 0 ([ADR-00298](../adr/ADR-00298.md)) |
| `CompressionStream` / `DecompressionStream` | ✅ | • The format argument must be a string literal ("gzip", "deflate", "deflate-raw") — a runtime-computed format string is a compile error<br>• Chunks are `Uint8Array` only (no ArrayBuffer/DataView BufferSource variants) | • A `%kml.ts` TransformStream context with native zlib transform/flush closures; `-lz` linked only when constructed; inflate auto-detects gzip/zlib wrappers ([ADR-00302](../adr/ADR-00302.md)) |
| `Blob.stream()` | ❌ | | • `Blob` itself — with `.text()`/`.arrayBuffer()`/`.bytes()` — shipped ([ADR-00314](../adr/ADR-00314.md)), tracked on [BINARY-DATA-TYPED-ARRAYS.md](BINARY-DATA-TYPED-ARRAYS.md); `.stream()` needs a from-memory ReadableStream source kind |
| `stream.Readable` / `.Writable` / `.Transform` (`Duplex` ❌) | ✅ | • Options-form construction only — no `class X extends Readable`, no `_read`/`_write` overrides, no standalone `Duplex`<br>• The `read` callback receives the stream as a parameter, not as `this` (object-literal callbacks have no `this` binding)<br>• Event names must be string literals; supported events are `data`/`end`/`error`/`close`/`finish`/`drain`<br>• No `.read()`/`.unshift()`/`.destroy()`/`.setEncoding()`, no `objectMode` flag (chunk types are the type argument), no `highWaterMark` option<br>• Event delivery can lag Node's synchronous re-entrancy by a microtask (emissions ride the reaction queue)<br>• `fs`/`http` still don't hand out Node streams (their surfaces are WHATWG-based or buffered) | • Wrappers over the WHATWG internals: rstream/wstream sides + the EventEmitter listener-list runtime; flowing mode is a reaction-driven read→emit loop started by the first `'data'` listener; `Readable.from`/`.fromWeb`/`.toWeb` bridge both worlds ([ADR-00304](../adr/ADR-00304.md)) |
| `stream.pipeline()` / `.finished()` | ✅ | • Only the `stream/promises` promise-returning forms — the callback-style `stream.pipeline(a, b, cb)`/`stream.finished(s, cb)` variants are not provided | • `pipeline` chains `.pipe` stages and returns the final destination's completion promise; `finished` returns the stream's own closed promise ([ADR-00304](../adr/ADR-00304.md)) |
| `stream/promises` | ✅ | | • `import { pipeline, finished } from 'stream/promises'` ([ADR-00304](../adr/ADR-00304.md)) |
