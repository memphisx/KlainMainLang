# ADR-00426: promote http server-handle bindings to module globals

- **Relations**: Extends [ADR-00342](ADR-00342.md) (module-global promotion), [ADR-00423](ADR-00423.md)
- **Date**: 2026-08-28

## Context

After ADR-00423/00425, the biggest residue of the "a number has no
method 'address'/'close'" oracle cluster (~60 files) was one shape: a
top-level helper function referencing the sibling server binding —
`function nextRequest() { http.get({ port: server.address().port, … }) }`.
ADR-00342's promotion covered class instances and builtin `new` handles
but no call-initialized handles, so the function body couldn't see
`server`.

## Investigation

An `http.createServer(cb)` (or chained `….listen(0, cb)`) binding
satisfies the promotion invariant — "promote iff the type cannot drift":
the handle is a single ptr slot with a constant compile-time type
(`HTTPServerType()`), and both var-decl emission paths
(`storePtrHandleVarDecl` for the chained split, the generic ptr store
otherwise) are already promotion-aware.

## Decision

`reliableGlobalType` recognizes two initializer shapes — the plain
`http__kml_builtin.createServer(...)` member call and the
`chainedCreateServerListen` chain — and returns `HTTPServerType()`.
Other factory handles (net/dgram/http2) are deliberately not added here:
each needs its own type-drift check before joining.

## Implementation notes

One clause in `codegen/llvm/emit_exprs_vardecl.go`'s
`reliableGlobalType`, reusing the ADR-00423 matcher.

## Side effects discovered

None.

## Verification

`TestE2EHTTPServerHandleInTopLevelFunction` (recursive top-level helper
driving two requests through `server.address().port`, exit-verified
mustCall counts); `TestE2EHTTPCreateServer*`/`TestE2EHTTPChained*`
re-run green (Mac).
