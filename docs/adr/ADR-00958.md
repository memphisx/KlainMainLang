# ADR-00958: `null`/`undefined` boxed into an `any` slot are the NaN-box sentinels, not raw 0

- **Date**: 2026-09-15

## Context

A `null` or `undefined` value stored into a dynamic (`any`) slot compared unequal
to everything. Surfaced (ADR-00957 side note) with an `any[]` literal:

```ts
const b: any[] = [undefined, 5, "x", null];
b[0] === undefined  // false (wrong)
b[3] === null       // false (wrong); and b[3] printed "undefined", typeof "undefined"
```

`typeof` and printing rendered the element as "undefined", but every `===` against
`null`/`undefined` was false, and a boxed `null` was even mis-rendered as
`undefined`. The scalar case (`const u: any = undefined`) was already correct, so
the bug was specific to a boxing path that ran `coerce`, not `emitBoxValue`
directly — the WPT-surfaced "a null value compares unequal to null" family
(BACKLOG §3).

## Investigation

Array-literal elements box via `coerce(elem, TypeAny)` (`emit_arrays_core.go:685`),
as do function-return, Map-value, and object-`any`-field assignments. In `coerce`
(`emit_exprs_coerce.go`) the null/undefined handling ran *before* the dynamic-box
handling:

```
if v.Ty.IsNull && target.IR != "ptr" {          // line 103
    return Value{Ref: zeroRef(target), Ty: target}
}
...
if target.IsDynamic && !v.Ty.IsDynamic {         // line 150
    return emitBoxValue(v)                         // → nbNull / nbUndefined
}
```

`undefined`/`null` both carry `IsNull=true` (undefined additionally `IsUndefined`).
`TypeAny.IR` is `"i64"` (non-`ptr`), so line 103 matched and returned
`zeroRef(TypeAny)` = the raw i64 `0` — the *boxed integer 0* — never reaching the
`emitBoxValue` at line 150 that produces the real `nbUndefined`/`nbNull`
sentinels. A boxed 0 decodes as int 0, which is why `=== undefined`/`=== null`
failed and a boxed `null` lost its tag. (`emitBoxValue` itself was always correct;
only this `coerce` shortcut wasn't.)

## Decision

Two parts:

1. **null/undefined literal → any** (`coerce`): guard the null/undefined-to-zero
   branch with `!target.IsDynamic`, so a `null`/`undefined` flowing into an `any`
   target falls through to the dynamic-box path (`emitBoxValue` →
   `nbNull`/`nbUndefined`). Concrete non-ptr targets keep the zero-value behavior.

2. **nullable pointer (`string | null`) → any** (`emitBoxValue`): the `ptr` case
   boxed every pointer as a string-tagged box, so a `string | null` whose runtime
   value is the null pointer became a string box with a 0 payload (`=== null`
   false once boxed). Add a runtime null-check for a `Nullable` pointer: `select
   (icmp eq ptr, null) → nbNull, else the string box`. This is the general "a null
   string boxed as any is not `=== null`" half of BACKLOG §3.

## Implementation notes

- `coerce` (`emit_exprs_coerce.go`): `target.IR != "ptr"` →
  `target.IR != "ptr" && !target.IsDynamic`. The single choke point every boxing
  `coerce` call flows through, so uniform across `any[]` literals, function
  returns (`(): any => null`), `Map<string, any>` values, and object `any` fields.
- `emitBoxValue` (`emit_dynamic.go`) `ptr` case: a `Nullable` pointer gets the
  runtime `select` to `nbNull`; a non-nullable pointer is unchanged (no branch).

## Side effects discovered

- `JSON.stringify` of an object with an `undefined`-valued `any` field renders the
  key as `null` (`{"a":null,"b":null}`) where Node OMITS it (`{"a":null}`). This
  is a distinct, pre-existing JSON-stringify gap (undefined own-properties should
  be skipped), independent of this fix — the array case already matches Node
  (`[1,null,null,"s"]`). Not fixed here.
- `URLSearchParams.get(missing)` boxed into `any` still reads `typeof "undefined"`
  / `=== null` false: USP's runtime `get` produces a value that boxes as
  `undefined` rather than the null pointer the static `string | null` type implies
  (its direct `=== null` is correct). A URLSearchParams-specific runtime
  representation quirk, distinct from the general nullable-string path fixed here
  (verified via a plain `string | null` returner).
- A nullable OBJECT (`T | null` where T is an object) that is null still boxes as
  an object-tagged box (it reaches the `IsObject` arm before the `ptr` arm), so
  `=== null` remains false for it. Same shape, different arm; not fixed here (the
  §3 line is about null strings).
