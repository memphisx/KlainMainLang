# ADR-01770: Async generator yield and return await their value

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

In the spec, `yield v` in an async generator is `AsyncGeneratorYield(? Await(v))`, and `return v` awaits v before completing. Each costs one microtask turn, even for a value that is not a promise. Here a request's promise settled, with any promise operand left unwrapped, as soon as the body reached `yield` or `return`. An async generator's `next()` result therefore arrived a tick before Node's, ahead of `then` callbacks that Node runs first. Test262's async-generator tests that compare callback order failed on that.

## Decision

In an async generator body, `emitYieldExpression` and `emitGeneratorReturn` (for `return v`, not a bare `return`) await the operand before completing the request (`emitAsyncGenOperand`):

- A promise or `any` operand is awaited, so a yielded or returned promise gives its settled value. The element type inference (`awaitedIn`) takes the promise's settled type, as TypeScript's `AsyncGenerator<T>` does.
- Any other operand is followed by an `await undefined`, the same one-turn park an explicit `await` makes, and keeps its value.

A bare `yield` takes the same one-turn park.

## Consequences

- `TestE2EJSFileAsyncGeneratorStepTiming` matches Node's interleaving of async-generator steps, an async function's settle and a promise chain.
- A yielded or returned promise used to arrive as the promise object itself. It now arrives as its settled value.
