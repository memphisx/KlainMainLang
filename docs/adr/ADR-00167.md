# ADR-00167: Guard pop and shift against empty arrays

- **Relations**: Found by [ADR-00166](ADR-00166.md)
- **Date**: 2026-08-11

## Context

[ADR-00166](ADR-00166.md)'s status-doc audit found that `.pop()` on an empty `number[]` returned uninitialized memory (garbage heap value) and corrupted `.length` to `-1`, while `.shift()` additionally did an unguarded `memmove` with an underflowed byte count. Real JS returns `undefined` and leaves the array's `.length` at 0.

## Investigation

`emitPop` (`emit_arrays_mutate.go:8`) and `emitShift` (`emit_arrays_mutate.go:328`) both loaded `curLen` but unconditionally subtracted 1 from it and indexed `curPtr[curLen - 1]` — on an empty array (`curLen == 0`), `curLen - 1` wraps to `uint64_max`, producing an out-of-bounds load and writing `-1` back to the length slot.

While fixing this, three additional latent type-inference bugs surfaced:

- **`inferExprType` for pop/shift/push/unshift/splice**: Every array mutation method fell through to the blind `TypeI64` fallback in `inferExprType` (`emit_exprs_types.go:1063`). This was harmless for `number[]` (i64 matches i64), but broke for any other element type — `string[]` allocated an `i64`-sized slot for a `ptr`-valued pop result, so `clang` rejected the generated IR with a type mismatch. Confirmed pre-existing (repro on unmodified tip-of-tree: `const arr: string[] = ["hello"]; const r = arr.pop()` hard-fails `clang`).

- **Var-decl pop/shift inference (`emit_exprs_vardecl.go:146`)**: An extra `s.Ty.ElemType.IsObject` guard restricted the pop/shift return-type inference to object-typed arrays only — `string[]` and `float64[]` arrays were excluded, so `const result = arr.pop()` for those array kinds allocated a wrong-sized slot.

## Decision

1. Empty guard both `emitPop` and `emitShift`: after loading `curLen`, branch on `icmp eq i64 curLen, 0`. The empty path returns the element type's zero value (`inttoptr i64 0 to ptr` for string, `fadd double 0.0, 0.0` for float, `or i64 0, 0` for int, `{null, 0}` aggregate for nested arrays) and leaves length unchanged. The non-empty path is the existing logic, now behind a `phi` merge at the end. This compiler has no general `undefined` sentinel for concrete scalar types, so returning the type's own zero value is the same simplification already established by optional parameters, under-assigned class fields, and destructuring past the source's length (ADR-00157 / ADR-00158 / ADR-00164).

2. Fix type inference for all five array mutation methods: add explicit `push`/`unshift`/`pop`/`shift`/`splice` cases to `inferExprType`'s per-method-name switch in `emit_exprs_types.go`.

3. Remove the spurious `IsObject` guard on pop/shift var-decl type inference in `emit_exprs_vardecl.go`.

## Implementation notes

- `emitScalarZero` helper added to `emit_arrays_core.go`: handles `i1`/`i8`/`i32`/`i64` (via `or`), `float`/`double` (via `fadd`), and `ptr` (via `inttoptr`). Does not handle aggregate types — pop/shift handle those inline.
- Reused the two-builder pattern: empty-guard branch + pop/shift logic both emit terminators to a shared `done` label, with a phi at the merge point.

## Side effects discovered

- **push/unshift/splice type inference was also wrong**: All three fell through to `TypeI64` regardless of receiver type. `push` and `unshift` return the new length, which IS `i64` in practice (this compiler's lengths are always i64), so the blind fallback was accidentally correct for them too — but only by luck, not by design. `splice` returns a new array of the receiver's own element type; with the old fallback, `const removed: string[] = arr.splice(0, 1)` allocated an `i64`-sized slot for what codegen actually produces as a `{ptr, i64}` aggregate — same mismatch class. Not previously tracked as bugs anywhere; fixed here alongside pop/shift.

## Verification

- Linux x86-64. Verified directly: before the fix, `const arr: number[] = []; arr.pop()` prints a garbage number and corrupts `.length` to `-1`; after, prints `0` and `.length` stays `0`. Same for `.shift()`.
- 6 new E2E tests in `tests/arrays_test.go`: `TestE2EPopOnEmptyArray`, `TestE2EPopOnEmptyStringArray`, `TestE2EShiftOnEmptyArray`, `TestE2EShiftOnEmptyStringArray`, `TestE2EPopShiftOnNonEmptyArray`.
- `go build`, `go vet ./...`, `go test ./...` all pass.
- `make examples` — 110/110.
- `make conformance` — 4463/53578, unchanged from pre-fix.
