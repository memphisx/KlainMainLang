# ADR-01813: every generator body cuts its callees' frames from its creator's

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- On Linux, a static async generator method that destructures its parameter crashed with SIGSEGV when a function it called made an Error. Test262's `statements/class/dstr/async-gen-meth-static-*` hit this 40 times, with an empty failure message. On the Mac the same stale memory happened to hold a valid record.
- A static generator method's body is a declaration the compiler synthesizes beside the class (`K__kml_sgen_m`), outside the program's statement-to-file map. It had no source file, so its body entered neither its own frame nor a fiber base frame.
- A destructured parameter starts the body at the call to run the destructuring. The callees' frame records then linked to the creator's frames, which are gone by the time a later `next()` resumes the body. The resume's cut applied to the base of whatever context was running, not to a base the body owned. Capturing an Error walked into the dead stack.

## Decision

- A generator body enters its fiber base whenever the program has frames at all (`programHasFrames`: any statement of a user file), whether or not the body has a frame of its own. The cut on resume then applies to that base.

## Consequences

- A synthesized static generator method's own frame still does not appear in an Error's stack. Its callees' frames do, and the walk stops at the fiber base.
- `TestE2EJSFileStaticAsyncGeneratorErrorFrames` covers errors made before and after a suspension. Verified on Linux x86-64 (the Node304 box), where it crashed before.
