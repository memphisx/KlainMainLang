# ADR-01447: Shadow oracle: narrowed references, `arguments`, annotation unions

- **Relations**: Implements TDD-00230 (P2.2); extends ADR-01442, ADR-01444
- **Date**: 2026-10-07

## Context

After ADR-01442 the shadow report grew from 27,828 to 57,567 rows.
24,184 of them were an Identifier `Nullable` row: codegen now reads a
narrowed nullable reference as present, the oracle still answered its
storage type. The rest of the run left three oracle mismatches with no
codegen behaviour behind them:

- 372 `emitIdent` rows for a function's `arguments`;
- 916 `resolveType` rows for an annotation union of string literals and
  `undefined` (`getters?: 'get' | 'set' | boolean | undefined`).

## Investigation

- The oracle's `ExprType` reads a nullable scalar flow proves present as its
  payload (ADR-01439), but had no such rule for pointers.
- 45 of 100 inferences of one such read in `internal_timers.ts` ran before
  the function's scope existed. They took the unbound-identifier fallback,
  which applied the presence rule only to scalars, so codegen itself was
  inconsistent between passes.
- The binder declares an implicit `arguments` symbol in each function
  (`Implicit`, no declaration); codegen defines `arguments` only where it
  synthesizes the object (a class method, not a function expression).
- Codegen keeps an annotation union's string-literal members as literals
  (the discriminant machinery reads them) and does not mark a box's absence
  as undefined; the box's tag carries it.

## Decision

- The oracle reads a nullable instance, function, promise or object
  reference as present where the checker's flow type is, unless an array
  pattern declares it (mirroring `checkerPresentRef`).
- Codegen's unbound-identifier fallback applies `checkerPresentRef` too.
- The oracle gives no answer for an implicit `arguments`: codegen defines
  it only in the functions whose lowering builds the object, so whether it
  counts as declared depends on the lowering, not the binding.
- An annotation's union keeps its string-literal members (`reprCtx.literals`).
- `reprKey` leaves out a union box's `IsUndefined`/`NullAndUndef`; its
  `Nullable` stays. A box's string-literal member keys as a string, and
  equal members once: the box tags a string as a string.
- `RefName` (a named structural type's re-resolution handle, ADR-01444's
  metadata class) is left out of `reprKey`: the layout is the fields. So
  are `IsStrLiteral` and `LitValue`: a string literal type is a string at
  run time. An annotation union of string literals only (`'a' | 'b'`) is a
  string in the oracle too, as codegen resolves it.
- Codegen's lone string-literal annotation keeps its `| null` /
  `| undefined` (`'p' | null` was a plain literal; the value already ran
  as a nullable string).

## Verification

- Shadow tests pass on the Mac; the probes' rows are gone.
