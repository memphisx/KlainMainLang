# ADR-01210: A class instance behind an interface is read as itself

- **Relations**: `Implements TDD-00233`
- **Date**: 2026-09-28

## Context

TDD-00233 Stages 1 and 2. A class instance passed where an interface was
expected was read at the interface's offsets (a segfault when the field
order differed), and an interface's method signatures were not members of
its type, so `s.area()` through an interface-typed value did not compile —
nor through a `function | object` union (BACKLOG 80). A static object in
`any` printed `[object Object]`, and `JSON.stringify` of one threw.

## Investigation

- `interfaceMethodSigs` fed `implements` checking only; the interface's
  object type had its properties alone (`emitter.go`, `emit_generics.go`).
- A class-to-interface coercion kept the pointer (it is not a
  `plainRecordType` pair, so `needsObjectRelayout` skipped it): the
  pointer was then read with the interface's `StructIR`.
- The layout table (`emit_shape.go`, `shape.c`) already serves
  `anyObj.x`/`anyObj.m()` for a boxed class instance, with methods as
  dynamic-function records. dynjson.c rendered and serialized a static
  object in a dynamic position as `[Object]` / an error: it had no access
  to the table.
- Builtin code reads option objects (`RequestInit`, `TlsOptions`, …) at
  fixed offsets in about 260 places, so plain-object relayout copies stay
  for now.

## Decision

- **Stage 1.** An interface's method signature `m(p): R` (and `m?`) is a
  function-typed member of its object type (`withMethodFields`), for plain
  and generic interfaces; `InterfaceMethodSig` carries the signature as a
  function type. `implements` checks a method signature as a method.
- **Stage 2, the checked view.** A plain object type's member access
  compares the object's header with the type's layout id
  (`emitRecordForeign`, null-safe): its own layout reads the static
  offset; a header of another layout reads and writes through the layout
  table, via per-(type, member) routines
  (`@__kml_rec_read_<id>_<name>`, `@__kml_rec_write_…`). The call site
  picks a slot address — the field's, or a temporary the routine fills —
  so every existing load and store is reused. A method read to be called
  comes back bound to the object (`__kml_dyn_bound`). Wired into member
  reads and writes (compound and logical assignment included), array
  mutators on a member, destructuring and its rest, object spread and the
  relayout copy's source.
- **Whole-object operations** on another layout (`console.log`,
  `JSON.stringify`, `Object.keys`/`values`/`entries`, `for…in`) branch on
  the header (`emitRecordSplit`) to the dynamic path of the boxed object.
- **Static objects in dynamic positions.** dynjson.c reads a layout row
  through finalize-defined hooks (`__kml_obj_nkeys`/`key`/`get`/`name`):
  console.log prints `Name { … }` / `{ … }`, `JSON.stringify` serializes
  the fields, and `Object.keys`/`for…in` of an `any` enumerate them;
  `ensureDynJSONC` links the layout table.
- A class-to-structural coercion registers the class's (and its
  subclasses') layout rows (`noteRecordViewSource`); so does a plain object
  whose layout has the same storage as the target's but other field flags
  (a `boolean` passed as `readable?: boolean`), which is passed without a
  copy and so carries its own header.
- A class instance is a member of a union whose object member is a plain
  object type (`((x) => void) | Handler`); it is kept as itself and the
  narrowed member reads it through the view. `implements` does not require
  an optional method (`m?(): R`).
- The view routines' bodies are written at finalize
  (`emitRecordFnsFinalize`). With no layout row in the program, no header
  can resolve, and a routine throws the dynamic path's TypeError without
  linking the layout table and the dynamic runtime.
- `Object.values`/`entries` of a heterogeneous shape, and of any
  structural type, are `any` (boxed values), as TypeScript types them;
  they were strings.

## Side effects discovered

- A plain object of one layout passed as another plain type is still
  copied (BACKLOG 74): the builtin consumers' fixed-offset reads need the
  view before the copy can go (TDD-00233 Stage 3).
- The slow path looks a member up by name per access; per-site caches are
  TDD-00220.
