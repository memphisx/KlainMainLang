# ADR-00994: TextEncoder.encodeInto and .encoding property

- **Date**: 2026-09-17

## Context

`TextEncoder` implemented only `.encode()`. `.encodeInto(src, dest)` was a
compile error and neither `TextEncoder` nor `TextDecoder` exposed the spec's
`.encoding` property — a documented caveat. Both are well-defined and fit the
existing byte-string model, so closing the caveat is a straightforward fill-in.

## Investigation

- `emit_call_encoding.go:emitTextEncoderEncode` copies the string's raw UTF-8
  bytes into a fresh `Uint8Array` — the same "strings are already UTF-8 bytes"
  premise `encodeInto` needs.
- `path.parse` (`emit_path.go`) shows the pattern for returning a small record:
  build a named `ObjectType`, `malloc(StructSize())`, store fields by
  `FieldIndex`, read back through the ordinary field-access path.
- `resolveArrayForHOF(expr, pos)` normalizes either array shape to
  `(ptr, len, elemTy)` — the right way to reach the destination `Uint8Array`'s
  data pointer and length regardless of its representation.

## Decision

- `encodeInto(src, dest)`: resolve `dest` via `resolveArrayForHOF` (require a
  `Uint8Array` element type), `copyLen = min(strlen(src), dest.length)`,
  `memcpy` that many bytes, and return a new `{ read, written }` object with both
  fields set to `copyLen`. In the byte-string model source units read equal
  bytes written equal bytes copied.
- `.encoding`: a constant `"utf-8"` string for both `TextEncoder` and
  `TextDecoder` (UTF-8 is the only encoding this model supports; a non-UTF-8
  `TextDecoder` label is already rejected at construction, ADR-00567). The
  receiver is stateless, so the object is evaluated for side effects only.

## Implementation notes

- `types.go`: new `EncodeIntoResultType()` (`{ read: i64, written: i64 }`).
- `emit_call.go`: dispatch `encodeInto` alongside `encode`.
- `emit_exprs_types.go`: call-return inference for `encodeInto`
  (`EncodeIntoResultType`); member inference for `.encoding` (`TypePtr`).
- `emit_exprs_member.go`: emit `.encoding` as the interned `"utf-8"` string.
- `emit_call_encoding.go`: `emitTextEncoderEncodeInto`.

## Side effects discovered

None. The multi-byte-truncation nuance (Node never splits a code point when the
destination fills) is subsumed by the pre-existing, separately documented
byte-string limitation, not a new divergence introduced here.

## Verification

- New E2E `TestE2ETextEncoderEncodeIntoAndEncoding` (full write, truncated
  write, `.encoding` on both types); existing encoding tests still pass.
  Differential against `node` — all values match.
- Caveat removed from the `TextEncoder` row; `make status`/`status-check`/
  `reference-check` and `make examples` clean.
