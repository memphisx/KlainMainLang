# ADR-01280: `timers` as a TypeScript module

- **Relations**: `Implements part of TDD-00230` (P3.1), `Supersedes part of ADR-00666`
- **Date**: 2026-09-29

## Context

`timers` was a re-export of the global timer functions, erased at the
import (ADR-00666). This had several consequences:

- only a same-name or aliased named import compiled;
- `import timers from 'timers'` was rejected ("no default export"), and so
  was a namespace import through it;
- `timers.promises` did not exist;
- the forms that did compile inherited the globals' limits: no arguments
  forwarded to the callback.

## Decision

- `lib/node/timers.ts` is the module, as Node's `lib/timers.js` is:
  - `setTimeout`, `setInterval` and `setImmediate` forward extra
    arguments to the callback;
  - `clearTimeout`, `clearInterval` and `clearImmediate` ignore
    `undefined` and `null`;
  - `promises` is `timers/promises`.
- A default import reads the module's exports (`kml:default-namespace`).
- The functions call the globals through `internal_timers.ts`, the helper
  `timers/promises` already uses.
- `timers` leaves the erased re-export set.
- `promises` wraps the generic `timers/promises` functions in arrows,
  because a generic function has no value form yet.
- Still open: the module's functions are not the globals themselves, so
  `timers.setTimeout === setTimeout` is `false`.

## Verification

Mac (Apple Silicon): `TestE2ETimersModule` and `examples/timers/module.ts`
print what Node v24.19.0 prints.
