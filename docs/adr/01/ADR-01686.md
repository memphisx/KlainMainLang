# ADR-01686: An array's null is nullRef

- **Relations**: Implements TDD-00230, Extends ADR-01314
- **Date**: 2026-10-17

## Context

An array is a header pointer (ADR-01655), and its one absent state was the null header. A `T[]` binding still receives null from `any` or from JSON, and Node keeps it as null:
- `const x: number[] = null as any` printed `undefined`, and `x === undefined` was true.
- `JSON.parse('null')` into a `number[]` read as `[]`.
- An undefined array compared `=== null` as true.
- `?.` on an array that was not declared nullable never tested for absence: `o.a?.length` read 0 and `o.a?.[0]` threw.

ADR-01314 already gave strings and objects that may hold both null and undefined a second absent pointer, `nullRef`: a zeroed sentinel cell, so a read that skips the check sees empty data instead of faulting.

## Decision

An array's null is `nullRef` and its undefined is the null header, as for a three-state pointer.
- **Unboxing.** Unboxing a null `any` into an array, or projecting a JSON null into one, gives `nullRef`.
- **Strict equality.** `=== null` is `nullRef`, or the null header when the type's only absent value is null (`T[] | null`, a RegExp miss). `=== undefined` is the null header otherwise.
- **Loose equality.** `== null` and every absence test (`emitArrayIsAbsent`: `??`, nullish guards) accept both.
- **Output.** `console.log` and inspect print `null` for `nullRef`. `JSON.stringify` writes `null` for it, and returns `undefined` for a top-level array holding undefined. Before this, such a call threw "is not iterable".
- **Optional chaining.** `?.` (`.length`, `[k]`, and longer chains) tests every header-pointer array for absence, its type inferred as `T | undefined` to match.

`nullRef`'s zeroed cell, including the word before it, reads as an empty array, so a path that does not check yet sees `[]` rather than faulting.

## Verification

- macOS: `TestE2EArrayNullFromAny`, compared against Node, along with the optional-chain, JSON-array and three-state tests.
