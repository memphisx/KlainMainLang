# ADR-00637: `crypto.createHmac`, streaming Hash/Hmac, and the full digest encoding set

- **Relations**: `Extends ADR-00636` (crypto.createHash), `Implements TDD-00159` (closing its open questions)
- **Date**: 2026-09-02

## Context

ADR-00636 shipped `crypto.createHash` with three documented deferrals:
`createHmac` (the keyed-MAC sibling), the full digest encoding set
(`base64url`/`latin1` beyond hex/base64), and internal streaming (it
accumulated `update()`s and digested in one shot). The accumulate approach is
observably identical to streaming and sanctioned by the project's
"faithful-now-perf-later" rule — but the deferrals were still real *surface*
gaps (`createHmac` missing, valid encodings rejected). This ADR closes all
three so `Hash`/`Hmac` match Node's surface with no caveat beyond the global
UTF-8-only string model.

## Decision

**Real streaming contexts.** Both `Hash` and `Hmac` handles are now the
opaque backend streaming context pointer, not an accumulation buffer:
`createHash`/`createHmac` allocate a context (`__kml_crypto_hash_new` /
`__kml_crypto_hmac_new`), `.update` streams bytes in
(`_update`, chainable — returns the handle), `.digest(encoding?)` finalizes
(`_final`, which frees the context) and encodes. No input buffering; handles
arbitrarily large inputs. Backends:
- OpenSSL: `EVP_MD_CTX` (`EVP_DigestInit/Update/Final_ex`) for hash;
  `EVP_MAC`/`EVP_MAC_CTX` (streaming) for HMAC.
- CommonCrypto: a tagged union of the `CC_*_CTX` types with
  `Init`/`Update`/`Final` for hash; `CCHmacContext`
  (`CCHmacInit`/`Update`/`Final`) for HMAC.

**`createHmac(algorithm, key)`** — same `.update`/`.digest` surface as `Hash`
(dispatched by an `IsHmac` handle flag, sharing the emitter path with an
`isHmac` toggle that swaps the backend fn names). The key takes the same
source types as `.update` (string / Buffer / TypedArray / ArrayBuffer).

**Full encoding set** on `.digest`: `hex`, `base64`, `base64url`, `latin1`/
`binary` (reusing the Buffer codecs — `__kml_buf_hex_enc`, `__kml_buf_b64_enc`
with the urlsafe flag, `__kml_buf_latin1_str`), or a `Buffer` when omitted.
`hex`/`base64`/`base64url` are byte-exact; `latin1`/`binary` inherit the
UTF-8-only string caveat for non-ASCII bytes (identical to
`Buffer.toString('latin1')`, TDD-00034) — documented, not silently wrong.

**Algorithms:** `md5`/`sha1`/`sha256`/`sha384`/`sha512` (MD5 added to the
HMAC name map alongside the digest map from ADR-00636).

## Implementation notes

- Backends: `__kml_crypto_hash_new/_update/_final` and
  `__kml_crypto_hmac_new/_update/_final` added to crypto_openssl.c and
  crypto_commoncrypto.c; `kml_md_name` gained `MD5`.
- emit_crypto_hash.go rewritten from accumulate to streaming; `HmacType`
  (`IsHmac`), `emitCryptoCreateHmac`, shared `emitHashMethod(..., isHmac)`,
  and the four-way encoding switch.
- Dispatch: `createHmac` added to `emitNodeCryptoModuleCall` + the `crypto`
  export allowlist; `.update`/`.digest` routed by `IsHash`/`IsHmac`;
  return-type inference for both handles + their methods.
- New ensure decls `ensureCryptoHashStream`/`ensureCryptoHmacStream`.

## Side effects discovered

None. The CommonCrypto `CC_MD5_*` deprecation stays a benign warning (Node
supports md5; OpenSSL is the default backend).

## Verification

- Mac (Apple Silicon, OpenSSL): `go build`, `go vet` clean. Canonical vectors
  match Node exactly — the **Wikipedia HMAC-SHA256** example
  (`f7bc83f4…1a3cd8`), HMAC-MD5, `sha256('abc')` in base64/base64url, chained
  multi-update, and Buffer results. `TestE2ECryptoCreateHmacVectors`,
  `TestE2ECryptoHashEncodings`, and the ADR-00636 hash/upgrade tests pass;
  crypto + subtle suites green; `examples/crypto/create_hash.ts` runs.
- **Linux verified** (Debian/glibc/arm64, Docker `golang:latest` + clang 19 +
  OpenSSL `libssl-dev`): `TestE2ECryptoCreateHmacVectors`,
  `TestE2ECryptoHashEncodings`, the createHash vectors, and the hand-rolled
  upgrade all pass — streaming Hash/Hmac and the encoding set work on
  OpenSSL/Linux, not just macOS.
