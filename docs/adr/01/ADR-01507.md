# ADR-01507: JS function expressions take their call sites' parameter types

- **Relations**: Extends ADR-01504, TDD-00230
- **Date**: 2026-10-09

## Context

Under `-compat=js`, codegen typed an unannotated parameter of a function
declaration from its call sites (`jsCollectFuncParamTypes`), but held a
function expression's or arrow's as `any`:
`var km = val => ({ key: val }); km(1)`. The checker infers both alike,
and that disagreement was bucket 6 of the shadow report (535 rows).

## Investigation

- The checker's `inferFromSites` skipped an `any` argument, so one site
  passing a number and another passing an `any` value gave `number`.
  Codegen's collector marks such a parameter polymorphic instead, which
  is the sound choice: an `any` value may hold a string at run time.

## Decision

- An `any` argument makes the checker's call-site parameter `any`.
- `Checker.JSCallSiteParam(fn, i)` answers only where all the calls are
  in sight.
- Under `-compat=js`, codegen types an unannotated, non-pattern
  parameter of a function expression or arrow by it when the type is a
  string, number or boolean (`jsSiteParam`). Emission and inference
  share the rule.

## Divergences

None. A parameter whose callers are not all visible, or disagree,
stays `any`.

## Files

checker/jsmode.go, codegen/llvm/emit_func.go,
codegen/llvm/emit_exprs_types.go

## Verification

- Mac (Apple Silicon), compared with Node: a probe covering an arrow, a
  function expression, a string parameter, an argument held as `any`,
  and a callback passed to `map`. `TestCompatJS` and the js-mode E2E
  tests pass.
