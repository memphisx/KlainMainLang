# ADR-00199: Presence-flagged representation for nullable non-pointer scalars

- **Relations**: `Implements TDD-00064`
- **Date**: 2026-08-16

## Context

`T | null` / `T | undefined` worked for a *pointer* `T` (string/object/array/class/Map/Set/...) because the null pointer is a distinct, unused bit pattern meaning "absent." It did **not** work for a *non-pointer scalar* `T` (`number`/i64, `boolean`/i1, an annotated `float32`/`float64`, `Date`/i64): those stored a bare scalar with only a `Nullable` type flag and **no runtime value reserved for null**, so "is this null?" was unanswerable and every code path that needed the answer silently guessed. Three shipped bugs shared this root cause (TDD-00064):

1. **`??` / `??=` on a non-pointer `T | null`** returned the left value unconditionally — `let x: number | null = null; x ?? 42` evaluated to `0`, not `42` (found building `??=`, ADR-00087).
2. **A class iterator's `next(): number | null` terminated on a legit `0`** — the Stage-1a iterator protocol (ADR-00063) used bare `0` as both the number zero and the "done" sentinel (found verifying `Array.from`, ADR-00088).
3. **`Map<K, number>.get()` on a missing key returned `0`, not `undefined`** (2026-08-11 audit, ADR-00166).

A fourth, closely related defect surfaced immediately: `x === null` on a nullable scalar "worked" only by accident — null was stored as `0`, so `let z: number | null = 0; z === null` wrongly returned `true`.

## Investigation

`emitNullCoalesce` (`emit_exprs_operators.go`) short-circuited `if left.Ty.IR != "ptr" { return left }`; the iterator done-checks (`emit_classes.go` `emitForOfClassIterator`, `emit_arrays_iter.go` `Array.from`) compared `icmp eq <scalar>, 0`; `Map.get` returned `mapValFromI64` directly. All three needed one shared decision: *how does a scalar carry "absent"?*

TDD-00064 compared four representations and recommended **Option A** — a presence-flagged `{ i1 present, T value }` aggregate — over reusing the constrained-union `{ i8, i64 }` box (Option B, heavier per value), a reserved sentinel (Option C, collides with real values — exactly bug #2), or heap-boxing (Option D, wasteful for a value type). The TDD's open question asked to prototype `storageIR` threading and reassess Option A vs B by how many scalar-storage sites actually change. That prototyping is this ADR: returns, parameters, and Map were contained; the object/interface **field** boundary was the broad one (StructFieldIR ripples through JSON/spread/reflection), confirmed still tractable, so Option A held throughout.

## Decision

Represent a nullable non-pointer scalar as `{ i1, T }`. `isNullableScalar(ty)` (`ty.Nullable && !ty.IsDynamic && ty.IR != "ptr" && ty.IR != "void"`) gates it; `storageIR`/`nullableScalarStorageIR` (types.go) give the slot shape. Plain `number` stays a bare i64 — no cost on the non-nullable path.

Representation invariant: **a Value whose Ty satisfies `isNullableScalar` carries the `{ i1, T }` aggregate in its register; a bare payload Value always has `Nullable` cleared.** So `isNullableScalar(v.Ty)` reliably means "this Ref is an aggregate." `coerce` demotes an aggregate to its bare payload wherever a plain scalar is wanted (the single central point), so most consumers never see the aggregate.

Staged per TDD-00064:

- **Stage 1 — representation + locals.** A nullable-scalar *local* allocates `{ i1, T }`; a null stores `{ present=0, payload=0 }` (payload a defined zero, so ordinary truthiness stays correct), a real value `{ present=1, payload=v }`. `emitIdent` auto-unwraps a local read to its bare payload, so existing arithmetic/printing keep working; the presence bit is consulted only at null-aware sites (`??`/`??=`/`=== null`/`!== null`), which read it from the local's storage. `Symbol.NullableBoxed` distinguishes a `{ i1, T }`-stored binding from a bare one (a not-yet-converted param/field).

- **Stage 2 — flow narrowing.** `if (x !== null)` / `if (x === null) return` narrow a nullable-scalar local to non-null in the guarded region (`Symbol.NarrowedNonNull`, a scope-shadowed binding), the compiler's first flow narrowing. Observably, an un-narrowed nullable-scalar local now prints its real JS rendering (`null` when absent, its value when present) instead of the payload `0`; a narrowed one is known present.

- **Stage 3 — boundaries.** Nullable scalars as function/method/constructor/closure **parameters** (passed as the `{ i1, T }` aggregate, boxed at every call site), **return values** (`LLVMRetType` returns `{ i1, T }`), **object/interface/class fields** (`StructFieldIR`/`StructFieldSize` give the field its `{ i1, T }` slot; reads/writes/object-literals/JSON.stringify/JSON.parse/spread/structuredClone box/unbox accordingly), and **`Map.get`** (a scalar-valued map returns `V | null`, presence from `has()`) — fixing bug #3 and the `f(0)` parameter 0-collision.

- **Stage 4 — the Stage-1a iterator.** With nullable-scalar return values in place, `next(): number | null` returns a `{ i1, T }` aggregate and the `for...of`/`Array.from` done-check reads its presence bit instead of comparing against `0` — fixing bug #2. A pointer element type keeps its null-pointer sentinel.

## Implementation notes

- New file `emit_nullable_scalar.go` holds the representation helpers (build/extract aggregate, box-from-expression, store/load field, narrowing detection, null-aware console printing, `??`/`=== null` scalar paths).
- `coerce` gained two branches: demote an aggregate to its payload toward a non-nullable target; box a `null` toward a nullable-scalar target (keeping the "nullable Ty ⟹ aggregate Ref" invariant).
- Boxing from an *expression* (`emitNullableScalarBoxedValue`) is used wherever null-ness must survive a nullable-scalar *lvalue* source — a local/param that `emitIdent` would otherwise unwrap to a present payload. Object-literal fields and field `=` go through the expression-aware store for exactly this reason.
- Parameter ABI widening had to be matched at every def **and** call site (top-level functions, methods, constructors, super calls, setters, arrow closures, function expressions, and the indirect closure-call function-type string) or clang rejects the mismatch. Generators were left bare-lenient (self-consistent, no boxed call path).
- JSON.parse of a field detects a literal `null` branchlessly: `present = strncmp(value, "null", 4) != 0`, boxed with that bit (atoll("null") is 0, so the payload is safe to compute either way).

## Side effects discovered

- `console.log`/template interpolation of a nullable-scalar value now render `null` for an absent value rather than `0` — a correctness improvement folded into Stage 2, not a separate change.
- `??=` / `&&=` / `||=` on a nullable-scalar *field* (as opposed to a local) is not yet routed through the boxed path — a niche remaining gap, noted in `docs/status/`. Every non-field form works.
- A nullable-scalar produced by a *complex* non-lvalue expression assigned to a local (e.g. a ternary) is treated as present unless it is a recognized null literal / nullable-scalar lvalue / nullable-returning call — the documented Stage 1 scope boundary.
