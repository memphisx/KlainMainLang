# ADR-00857: FinalizationRegistry.register() evaluates to undefined, not void

- **Relations**: `Extends ADR-00856`, `Implements TDD-00163`
- **Date**: 2026-09-10

## Context

`FinalizationRegistry.prototype.register(target, holdings)` returns `undefined`
per spec. This compiler emitted it as a `Ref`-less `Value{Ty: TypeVoid}`. In
statement position (`reg.register(a, h)`) that was harmless, but any use of the
result — `const r = reg.register(...)`, `assert(reg.register(...) === undefined)`
(the shape of Test262's `holdings-any-value-type.js` and siblings) — fed an empty
`Ref` into downstream codegen, producing invalid IR such as
`%t = sitofp i64  to double` (clang: "expected value token") or, once the guard
of ADR-00856 forced a type, `alloca void`.

Surfaced while grinding the invalid-IR backlog: the "expected value token"
CLANG_ERROR bucket includes several FinalizationRegistry files whose only sin is
using `register`'s return value.

## Investigation

Two independent paths reported the result type and both said void:

- Emit: `emit_finalization.go:213` returned `Value{Ty: TypeVoid}` after the
  `@__kml_finreg_register` call.
- Type inference: `emit_exprs_types.go:1531` (`case "register"`) returned
  `TypeVoid`, so `const r = reg.register(...)` allocated `alloca void` — itself
  invalid IR (`void type only allowed for function results`).

The canonical `undefined` value elsewhere is `Value{Ref: "null", Ty:
TypeUndefined}` (`emit_exprs.go:138`), where `TypeUndefined = {IR: "ptr", IsNull,
IsUndefined}` (`types.go:2481`) — a real, comparable value.

## Decision

Return `undefined`, not void, from both paths:

- Emit path returns `Value{Ref: "null", Ty: TypeUndefined}`.
- Inference path returns `TypeUndefined`.

So `r === undefined` is true and `typeof r === "undefined"`, matching Node.

## Implementation notes

- `codegen/llvm/emit_finalization.go` and `codegen/llvm/emit_exprs_types.go`.
- The two paths must agree: fixing only emit left `alloca void` from the still-void
  inference path — a reminder that a method's result type lives in both places.

## Side effects discovered

This is one instance of a broader latent class: **any builtin method typed
`TypeVoid` that JS actually specs as returning `undefined`** emits invalid IR
when its result is consumed. Other such methods are candidates for the same fix
as they surface in the backlog; this ADR fixes `register` (the one hit here) and
flags the pattern rather than sweeping it blind.

## Verification

- E2E `TestE2EFinRegRegisterReturnsUndefined` (result `=== undefined`, `typeof`
  `"undefined"`); full `TestE2EFinReg*` suite green.
- The three FinalizationRegistry `register` Test262 files that were `CLANG_ERROR`
  now compile.
- `go build`, `go vet` clean. Platform: Apple-Silicon Mac.
