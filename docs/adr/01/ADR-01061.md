# ADR-01061: Every conformance run-timeout was a terminating program that never terminated here — non-finite float→int poison, `unreachable` fall-off, `++` on a NaN-box, unchecked Atomics access, and a string-keyed bare `new Set()`

- **Relations**: Extends ADR-01045 (the in-process codegen hangs, now gone — this is the emitted-code half), ADR-01057 (ToNumber on unary `+` / `TypedArray.set`, reused here for Atomics), TDD-00211 (bare `new Map()` widening, extended to `Set`), TDD-00187 (`T | undefined` results), TDD-00099 (Atomics)
- **Date**: 2026-09-22

## Context

BACKLOG §0 item 2: the 2026-09-21 conformance run reported `RUN_TIMEOUT` for eleven test262 files (three in both lanes,
eight js-only) and `CLANG_TIMEOUT` for two. A run timeout in a terminating test is an infinite loop in emitted code,
not slowness. Each file was reduced to a standalone repro and every one turned out to be a distinct bug:

| test262 file | standalone repro | what actually looped |
|---|---|---|
| `Array/prototype/indexOf/15.4.4.14-5-13.js`, `…-5-14.js` | `[true].indexOf(true, -Infinity)`, `(true, NaN)` | `fptosi double NaN to i64` is **poison**; the scan index started at an arbitrary word and the loop's exit test was `icmp eq idx, len` |
| `Set/prototype/has/…-nan.js` | `var s = new Set(); s.has(NaN)` | a bare `new Set()` is string-keyed by default; `has(NaN)` `fptosi`'d NaN to a "pointer" and `strcmp`'d it |
| `arguments-object/10.6-10-c-ii-1.js`, `…-2.js` | `function foo(a){ a = 1; if (…) return true }` | the body can fall off the end; the emitter's fall-through terminator was `unreachable`, which `clang -O2` folded into an infinite loop |
| `statements/for/S12.6.3_A11_T2.js`, `A12_T2.js`, `head-init-…` | `var i, j; for (j = 0; j <= i; j++)` under `-compat=js` | `j++` on an untyped (`any`, NaN-boxed) binding emitted `add i64 %box, 1` — the box's payload never crossed the tag boundary |
| `Atomics/wait/retrieve-length-before-index-coercion.js` | `Atomics.wait(ta, {valueOf(){…}}, …)` | the index was `coerce`'d straight from an object pointer (a raw reinterpretation) and there was no bounds check; `wait` blocked forever on a foreign address |
| `Array/prototype/filter/15.4.4.20-9-c-i-2.js`, `tagged-template/cache-eval-inner-function.js` | — | the same `unreachable` fall-off, reached through a callback / an `eval` body |

The two `CLANG_TIMEOUT`s are not loops: `regress-561031.js` (1,822 top-level `try {} catch {}`) compiles in 1.7 s
alone and only timed out under the 8-worker commit-limit collapse ADR-01060 already fixed; `string-upper-lower-mapping.js`
(65 K `[string, string]` literal pairs, 3.3 MB) emits 49 MB of IR and takes clang minutes even alone — a genuine
compile-time cost recorded as a new backlog item (static data for literal tables), not a correctness bug.

## Investigation

- `codegen/llvm/emit_exprs_coerce.go` float→int: a plain `fptosi`/`fptoui`. LLVM defines both as poison for NaN and
  for any out-of-range value, so *every* integer consumer of a `number` that might be NaN/±Infinity was undefined —
  `indexOf`/`slice` bounds, TypedArray stores, Set keys, `| 0`-style paths that reach it. JS's rule is
  ToIntegerOrInfinity (NaN → 0, ±∞ preserved and clamped by the consumer) and ToInt32/ToUint8 (non-finite → 0).
- `emit_arrays_search.go:68`: the `indexOf` loop exit was `icmp eq` — a legitimately large `fromIndex` (`5` on a
  3-element array) also scanned past the end. `includes`/`lastIndexOf` start at 0 / `len-1` and were fine.
- `emit_collections.go`: `inferEmptyMapKVTypes` (TDD-00211) widens a bare `new Map()` from its `.set/.get/.has`
  uses; a bare `new Set()` had no such pass and `emitSetVarDecl` also ignored a `Set<T>` annotation. Worse, a
  top-level `var s = new Set()` never reached `emitSetVarDecl` at all: the promoted module global already exists, so
  `emitVarRedeclaration` (`emit_stmts.go`) turns it into an assignment and `emitExpr(NewSetExpression)` builds the
  default (string) family while the binding's *type* — from the pre-pass — says number: `__kml_map_num_has` on a
  `str` set (invalid IR once the type was fixed, wrong family before).
- `emit_func.go:390`, `:2696`, `:4014`, `emit_classes.go:2089`: every non-void body ended in `unreachable`. UB,
  and `clang -O2` exploits it: the block before it becomes an infinite loop. `inferUnannotatedReturnType` takes the
  first `return <expr>`'s type and never asks whether the body can also complete normally — tsc infers
  `true | undefined` for `function f(x) { if (x) return true }`.
- `emit_exprs_operators.go:1476`: `emitUpdate`'s "numeric operand" test is `sym.Ty.Float || sym.Ty.IsInteger()`,
  and `TypeAny`'s IR is `i64`, so an `any` passed as an integer (the memory note from session 21: check `IsDynamic`
  first).
- `emit_atomics.go`: `emitAtomicsElemPtr` did `coerce(idx, i64)` and a bounds-free `getelementptr`; the spec's
  ValidateAtomicAccess reads the length *before* ToIndex(index) and throws `RangeError` for an out-of-range index;
  `wait`'s value/timeout were plain `coerce`s too (an object operand reinterpreted). `__kml_atomics_wait` took `-1`
  as "no timeout" and treated any negative as infinite; the spec clamps a negative timeout to 0 (times out at once)
  and treats NaN/+∞ as forever.

## Decision

1. **Saturating float→int everywhere.** `ensureFptosiSat`/`emitFloatToI64` (`runtime_core.go`) declare and call
   `llvm.fptosi.sat.i64.f64` (and `.f32`): NaN → 0, ±∞ → `INT64_MIN/MAX`, which is ToIntegerOrInfinity as seen by a
   consumer that clamps to a length. The generic `coerce` float→int path uses it for a 64-bit target; a narrower
   target additionally maps a non-finite source to 0 before the truncation (ToInt32/ToUint8). The `any`→int path
   now routes through the same float branch instead of its own `fptosi`.
2. **`indexOf` exits on `idx >= len`.**
3. **Bare `new Set()` inference.** `inferEmptyMapKVTypes` registers a bare `new Set()` binding and takes `.add` (as
   well as `.has`/`.delete`) arguments as key contributions; `emitSetVarDecl` and the vardecl type decider honour a
   `Set<T>` annotation and the pre-pass, through `emitNewSetValueTyped`. `emitVarRedeclaration` passes a promoted
   binding's already-decided Map/Set type down to the bare `new` through a one-shot `newCollectionHint`
   (`emitExpr`'s `NewMapExpression`/`NewSetExpression` cases consume it) — the same fix covers `var m = new Map()`.
4. **Falling off the end returns `undefined`.** `emitValuelessRet` (`emit_stmts.go`) is the one terminator for a
   bare `return;` and for the implicit end of a non-async, non-generator body: the absent `{ i1, T }` aggregate for
   a nullable scalar, `ret ptr null` for pointers and array headers, the `undefined` NaN-box for a dynamic return,
   `ret void`, else the type-correct zero — never `unreachable`. `widenIfMayFallOff` (`emit_fallthrough.go`) widens
   an *unannotated* inferred return type to `T | undefined` when `blockMayCompleteNormally` (return/throw, both
   arms of an if/else, try/catch/finally, `while (true)`/`for (;;)` with no own `break`, a `switch` with a default
   whose last group doesn't complete) or a bare `return;` says the body can also yield `undefined` — the analysis is
   conservative toward "may", which only widens. It applies to `inferUnannotatedReturnType` (function declarations,
   function expressions, methods, block arrows) and deliberately not to the `…Params` callback variant
   (`arr.filter(x => { if (c) return true })` keeps its concrete callback type; the fall-off there now returns the
   zero rather than UB — a remaining divergence, noted below).
5. **`++`/`--` on an `any` operand** does ToPrimitive → ToNumber on the box, steps as a double, stores a number box
   back; a postfix yields the numeric old value (`x = "5"; x++` → `5`, `x` is `6`). `inferExprType` gained an
   `UpdateExpression` case (a dynamic/nullable operand yields `number`).
6. **Atomics validate the access.** The length is read before the index is coerced; the index goes through
   `emitUnaryPlus` (ToNumber, so a `valueOf` runs and a string converts), ToIntegerOrInfinity, and a `< 0 || >= len`
   check that throws `RangeError("Invalid atomic access index")` — for every Atomics op. `wait`'s value and timeout
   also go through ToNumber, in spec order (index, value, timeout). The runtime's "no timeout" sentinel is NaN; a
   negative timeout clamps to 0, NaN/+∞ wait forever, and the ms→ns conversion saturates.

## Implementation notes

- `codegen/llvm/runtime_core.go` (`ensureFptosiSat`, `emitFloatToI64`, the ±∞ literals), `emit_exprs_coerce.go`,
  `emit_arrays_search.go`, `emit_collections.go`, `emit_exprs_vardecl.go`, `emit_stmts.go` (`emitVarRedeclaration`,
  `emitValuelessRet`), `emit_exprs.go`, `emitter.go` (`newCollectionHint`, `usedFptosiSat`), `emit_func.go` (four
  fall-off sites, the `widenIfMayFallOff` call), `emit_classes.go`, new `emit_fallthrough.go`,
  `emit_exprs_operators.go` (`emitUpdate`), `emit_exprs_types.go` (`UpdateExpression`), `emit_atomics.go`,
  `runtime_atomics.go`.
- `emitValuelessRet` reads `e.currentRetType`, which every body path sets before emitting statements; an array
  return type's LLVM return is the header `ptr` (`LLVMRetType`), so the array case must be `ret ptr null`, not the
  `{ptr, i64}` zero.
- The `-compat=js` lane compiles the untyped `var` as `any`; the strict lane still rejects `i < 3` on an `any`, so
  the strict test for (5) uses a typed loop counter around the `any` increment.
- A `float` (`f32`) constant in LLVM IR is spelled as its exactly-representable double bit pattern, so the ±∞
  literals are the same for both widths.

## Side effects discovered

- **Node 24 (V8) still reads the TypedArray length *after* coercing the index** in `Atomics.wait`, so on the
  growable-buffer test it reaches the value coercion and throws that Error where the spec (and test262) throw
  `RangeError`. The compiler follows the spec; that one test has no Node-oracle twin.
- The `arguments`-object test still fails (not hangs): `arguments` is a snapshot of the parameters (unmapped —
  strict-mode/ESM semantics, which is what Node gives a `.ts` module); the test expects sloppy-mode mapping.
- A callback whose block body can fall off (the `…Params` inference path) returns the zero of its concrete type on
  that path rather than `undefined` — defined behaviour now, but still a divergence from `T | undefined`; widening
  there needs the HOF call sites to accept a nullable-scalar callback result. BACKLOG §0.
- A BigInt held in an `any` steps as a number under `++` (the box has no BigInt kind — BACKLOG §0 item 14's family).
- `string-upper-lower-mapping.js`: a 65 K-pair literal table emits per-element allocation code (49 MB of IR);
  literal-only arrays should lower to static data. New BACKLOG item.
