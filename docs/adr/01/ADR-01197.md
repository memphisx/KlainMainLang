# ADR-01197: Fetch's Body members: stream and null bodies, `bodyUsed`, Request

- **Relations**: `Extends ADR-01190`
- **Date**: 2026-09-28

## Context

`new Response(stream)` was rejected, a body-less Response's `.body` was an
empty stream instead of `null`, every `.body` read built a new stream,
`bodyUsed` did not compile, and a body could be read any number of times —
Node rejects a second read with "Body is unusable: Body has already been
read".

## Investigation

Node (undici) keeps one body stream per Response: `.body` returns it, a
body method reads it (locking and disturbing it), and a used or locked
body makes every body method reject with a TypeError. A Response built
with no body (and `Response.error()`/`Response.redirect()`) has a `null`
body. The WHATWG ReadableStream runtime already tracks `disturbed` and
`locked` in its flags word (`runtime_streams.go`, field 11).

## Decision

- Response gains `__kml_stream` (the stream `.body` returns, built on the
  first read and kept) and `__kml_bodyflags` (null body, unread stream
  body, used).
- `new Response(stream)` keeps the stream (a `ReadableStream<Uint8Array>`;
  other chunk types are refused at compile time). A body method on it
  calls `@__kml_resp_collect`: a TypeScript snippet reads the stream to its
  end into a Blob, then `@__kml_resp_collect_done` stores the bytes as the
  buffered body and runs the method's runner, or rejects with the read's
  error.
- Every body method first checks for an unusable body (used, or its stream
  disturbed or locked) and rejects with Node's TypeError; else it marks
  the body used and locks an already-handed-out `.body` stream. A `.body`
  built after a body method is the consumed stream: locked and disturbed.
- `bodyUsed` reads the used flag or the stream's disturbed flag.
- `const x: T = await res.json()` goes through the body promise (awaited)
  instead of reading the body synchronously, so it works for a body still
  arriving or a stream body.
- `new Request(…)` has the same Body members: its type carries Response's
  body fields, and `hasBodyMixin` routes `.body`, `bodyUsed` and the body
  methods of either to the same code (the body-method runner is emitted
  per type). A Request without a body has a null `.body` and reads as `""`;
  a string body sets `content-type: text/plain;charset=UTF-8` unless the
  headers have one; a GET or HEAD request with a body is Node's TypeError;
  the standard methods' case is normalized (`"post"` is `"POST"`).
  A null body is never marked used. A Request, like a Response, has no own
  enumerable properties.

## Implementation notes

`codegen/llvm/emit_response_new.go`, `emit_fetch.go`
(`emitResponseCall`, `emitResponseBodyUsed`, `hasBodyMixin`),
`emit_fetch_request.go`, `emit_streams_pipe.go`
(`emitResponseBodyStream`), `emit_objects.go` (`emitDeclJSONProjection`),
`types.go`.

## Side effects discovered

- The `.then` bridge built its Response with an unzeroed `malloc`, so a
  fetched Response reached through `.then` read garbage headers,
  statusText and type; it is `calloc`'d now.
- A body method's runner rejected with the error's payload but no tag, so
  its reason decoded as a number; it stores the thrown value's tag too.
- The locked-stream TypeErrors (`getReader`, iteration, `tee`,
  `pipeTo`/`pipeThrough`, `getWriter`) now carry Node's messages ("Invalid
  state: ReadableStream is locked") and code `ERR_INVALID_STATE`.
