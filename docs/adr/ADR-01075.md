# ADR-01075: `toUpperCase`/`toLowerCase` — full Unicode case mapping

- **Relations**: Extends ADR-01064 (the conformance file this completes), TDD-00120 (length-headed strings)
- **Date**: 2026-09-22

## Context

BACKLOG §0 item 2: `@__kml_toupper`/`@__kml_tolower` (`runtime_strings.go`) mapped `a-z`/`A-Z` only —
`"ß".toUpperCase()` stayed `ß` (Node `SS`), `"Σ".toLowerCase()` stayed `Σ`, test262's
`string-upper-lower-mapping.js` (every BMP code point against its full mapping) failed.

## Investigation

- ECMA-262 defines both methods as the Unicode Default Case Conversion: the `UnicodeData` simple mappings plus
  the unconditional `SpecialCasing` expansions (`ß → SS`, `İ → i̇`, `ﬁ → FI`, `ᾀ → ἈΙ`, …) plus the one
  language-independent conditional mapping, Final_Sigma (`Σ → ς` when preceded by a cased letter and not followed
  by one, case-ignorables skipped). Node/ICU does exactly that (`"ΟΔΥΣΣΕΥΣ".toLowerCase()` → `οδυσσευς`).
- No ICU here, and Go's `unicode` package has only the simple mappings. Python's `str.upper()`/`lower()`
  implement the full algorithm from the interpreter's own database, so the tables can be *generated* from it
  rather than by vendoring `UnicodeData.txt`/`SpecialCasing.txt`.
- The ASCII `@__kml_tolower` also serves the runtime's own raw buffers (HTTP header names, URL hosts, WebSocket
  tokens), so the user-facing method gets its own entry point.
- A length-headed variant (an embedded NUL as an ordinary character) and a length-driven `console.log` string
  write were implemented and reverted in the session: sidecar-produced strings (URL fields, crypto output,
  EventSource data, `Blob.text()`) carry no TDD-00120 header, and reading it printed heap garbage in 14 tests on
  both platforms. Both stay `strlen`-bounded; the header-less producers are the real fix (BACKLOG §0).

## Decision

1. **`tools/gencasemap/gencasemap.py`** generates `codegen/llvm/casemapsrc/casemap_tables.h` (committed; Unicode
   version stamped from the generating Python): 1,335 delta ranges for single-code-point mappings, 103 special
   entries with both expansions, and the Cased / Case_Ignorable ranges for Final_Sigma.
2. **`casemapsrc/casemap.c`** — `__kml_str_toupper(s, len)` / `__kml_str_tolower(s, len)` over UTF-8:
   special table first, then Final_Sigma, then the delta ranges; invalid bytes pass through; returns a header
   string. Compiled in only when a program uses either method (`UsesCasemap`, `CasemapSource` splices the
   tables into the one translation unit). The emitter passes `strlen`.

## Implementation notes

`codegen/llvm/casemap_c.go`, `casemapsrc/`, `embedded_c.go`, `emit_strings.go` (`emitStringCasemap`), the test
builders (`appendCasemap`, every sidecar build site), `tools/gencasemap/`. Regenerate with `py
tools/gencasemap/gencasemap.py > codegen/llvm/casemapsrc/casemap_tables.h` on a newer Python to pick up a
newer Unicode.

## Side effects discovered

- The generating Python (3.12 on the Windows box) is Unicode 15.0; Node 24's ICU is 16 and the test262 file is
  17 — letters added in those versions (a handful) still map to themselves. Regenerate to close.
- Header-less strings from sidecars (above); `emitConsoleScalarValue` now renders a float32 index read as its
  JS number (`0.10000000149011612`, as every other path already did) instead of `printf %g`'s `0.1`.

## Verification

Windows, all equal to Node 24: `ß İ ŉ ﬁ ǰ ᾀ ǅ Ⅷ ⓐ`, `ΟΔΥΣΣΕΥΣ`, `ΣΑΣ Σ` (final and non-final sigma),
`straße`, accented Latin, Deseret (supplementary plane). E2E: `tests/string_casemap_test.go`. Full suites:
Windows + Linux (Docker).
