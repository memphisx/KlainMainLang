# ADR-01297: Callback arity, function identity, dictionaries, overload results, and views through `any`

- **Relations**: `Extends ADR-00477`, `Extends ADR-00478`, `Implements part of TDD-00230`
- **Date**: 2026-09-30

## Context

The zlib port (ADR-01296) ran into these. All were wrong at run time
except the last two, which were compile errors.

- **A callback typed with fewer parameters.** `new Writable({ write(c, e,
  cb: () => void) { cb() } })`: `cb` is the stream's `(error?) => void`.
  Called with no arguments, it read a garbage error, so the stream failed.
  `pipeline(Readable.from([...]), writable, …)` stopped after one chunk,
  and one form crashed.
- **Function identity.** One function stored in two slots of different
  function types compared unequal (each coercion wrapped it in a fresh
  adapter). lib stream.ts's `cb === nop` tests broke on this.
- **A plain object into an index-signature binding.** `const c: { [k:
  string]: number } = o` (also `= Object.freeze({...})`) stored the
  record pointer where a dictionary was expected. A read then hung or
  crashed.
- **Overload results with an untyped argument.** When the checker could
  not type one argument, `zlib.gzipSync(new TextEncoder().encode(s))`
  took the implementation signature's `any`, not the overload's
  `Buffer`.
- **Views held in `any`:**
  - `ArrayBuffer.isView` was false for a boxed `DataView`;
  - `byteLength`/`BYTES_PER_ELEMENT` of a boxed TypedArray read
    `undefined`;
  - `DataView.setBigInt64(i, v)` rejected a `v` held in `any`;
  - `NodeJS.ArrayBufferView` resolved to no representation ("expression
    is not an array").
- **Writable callback arguments:**
  - `write`/`end` callbacks got `undefined` where Node passes `null`;
  - `pipeline`'s callback got `null` where Node passes `undefined`.
  
  lib stream.ts's `Callback` typed its argument `Error | null`, a null
  pointer either way, so the two could not both be right.

## Decision

- **Adapter for callback parameters** (emit_func_adapt.go):
  - When a source function's parameter and the target's are both
    function types that themselves need adapting,
    `funcParamNeedsAdapt` marks the adapter needed.
  - The adapter coerces that argument to the source's parameter type.
    Through the box, a missing argument is `undefined`, as in JS.
- **Function `===`/`!==`** compares `__kml_fn_identity_hdr` of each side
  (fnmeta.c): a closure header, followed through adapters
  (`FN_THROUGH_ENV`, env = the adapted header) to the function itself.
- **Dictionaries**: `emitObjectVarDecl` coerces a plain record into an
  index-signature type (`emitObjectToDict`). This applies to a call
  initializer as well as any other expression. A call initializer answering
  `any` (an implementation signature) is unboxed into a declared class type
  (BACKLOG #109: invalid IR). A plain record type keeps the box: a field
  declared `Buffer` may be `null` at run time (`spawnSync`'s `stdout` with
  inherited stdio).
- **Overload results**: `Checker.OverloadResult` is the result type every
  arity-fitting overload agrees on, treating an argument the checker
  cannot type as fitting anything. `checkerPrimitive` uses it when the
  call itself is unanswered, and also answers a `Buffer` result for a
  call (not a property read: a property declared `Buffer` may hold `null`). A
  variable declared from such a call takes that type.
- **Views**:
  - `ArrayBuffer.isView` of a box also tests the `DataView` host class;
  - the boxed-array key read answers `byteLength` and
    `BYTES_PER_ELEMENT` for a TypedArray;
  - `setBigInt64`/`setBigUint64` unbox an `any` value;
  - `NodeJS.ArrayBufferView`/`NodeJS.TypedArray` are `any`, as a union
    of several representations is, and so is any other qualified builtin
    name no table resolves (`NodeJS.ExitListener`), instead of the numeric
    default (BACKLOG #107).
- **Writable callbacks**:
  - lib stream.ts's `Callback` is `(error?: any) => void`, so a callback
    gets the `null` or `undefined` it was called with;
  - `nop` has the same type (no adapter);
  - `pipeline` keeps its error `undefined` until one occurs, as Node's
    does.

The ASan test harness (`buildBinaryASan`) now resolves a program with
imports and links the bigint/crypto/TLS/HTTP2 backends, as `buildBinary`
does.

## Side effects discovered

- `const x = opts.optionalNumber as number` stores 0 for an absent field:
  a bare `number` slot has no `undefined`. lib code holds such values as
  `any`.
- Boxing a `DataView` generates its host-method adapters, which include
  the bigint getters. The program then links the bigint backend (a
  default dependency, installed in CI).

## Verification

- `tests/value_boundary_test.go`: fewer-parameter callbacks, identity
  through adapters with Writable's `null`, object into an index signature,
  views through `any`, overload results with an untyped argument, and
  qualified builtin types. Each is compared with Node.
- The stream, zlib and function test groups pass.
- **Mac (Apple Silicon):** Node v24.19.0.
- **Linux (Docker, glibc/arm64):** the stream and zlib probes against
  Node 26.10 (both also give `null` for write/end callbacks).
