# ADR-00475: uninitialized unions; generic-method rejection; any-return closure bug (deferred)

- **Relations**: Extends [ADR-00454](ADR-00454.md), [ADR-00469](ADR-00469.md)
- **Date**: 2026-08-29

## Context

Continuing the bucket sweep:

- `a union type without null/undefined as a member requires an
  initializer` (38 TS-oracle false-rejects) — `var c: E | F;` is legal
  JS/TS, reading `undefined` until assigned.
- `expected IDENT, got <` (81) — generic class methods (`then<U>(…)`)
  died as a *parse* error mid-class, poisoning the rest of the class body.

## Decision

- **Uninitialized unions**: the requires-an-initializer rule is removed —
  the existing IsDynamic no-init path already boxes `undefined`
  (`typeof x` → "undefined", assignment then works), which is exactly
  JS's `let x; console.log(x)` semantics. `const` stays
  parse-rejected without an initializer; in-function `let`
  read-before-assign stays a definite-assignment error. The old
  `TestE2EUnionWithoutNullRequiresInitializer` becomes a positive test.
- **Generic class methods**: the member parser now recognizes
  `name<T>(…)` and rejects it *cleanly* ("a generic class method is not
  yet supported") instead of a confusing mid-class parse error.

## Deferred bug, found while scoping this (needs a decision)

The natural ADR-00469-style fix — erase the method's type parameters to
`any` — was implemented and then **reverted**, because it surfaced a
**pre-existing silent-wrongness bug** reproducible with no generics at
all:

```ts
const g: (n: number) => any = (n: number): string => "n" + String(n);
console.log(g(1));   // prints "[object Object]" — the string return is mistagged
```

A concrete-return closure read back through an `any`-returning function
type is not adapted: the call site unboxes the raw return word as a
dynamic box. The proper fix is an adapter trampoline at closure
coercion when return (and likely parameter) dynamism mismatches — a real
subsystem change left **deferred for a decision**, per this project's
own large-bug practice. Until then, generic methods stay rejected rather
than silently wrong.
