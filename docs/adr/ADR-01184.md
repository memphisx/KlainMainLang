# ADR-01184: The C string and number runtime links libm

- **Date**: 2026-09-28

## Context

The Release run on the restructure commit failed about 85 tests on each
Linux runner: every program using the C string runtime (`string.c`) or the
C number formatting (`number.c`) failed to link with
`undefined reference to 'trunc'`.

## Investigation

`stringsrc/string.c` and `numbersrc/number.c` call `trunc`/`floor`. glibc
(and mingw) keep them in libm; macOS has them in libSystem, which is always
linked, so the Mac lanes never saw it.

## Decision

Both sources carry `LibmLibs()` (`-lm` everywhere but macOS) as their link
libraries, in `EmbeddedCSources` and in the test build's `appendStringC`/
`appendNumberC`.

## Implementation notes

`codegen/llvm/embedded_c.go`, `tests/compiler_test.go`.

## Side effects discovered

None.
