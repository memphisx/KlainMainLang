# ADR-01141: The index-based String methods in the C string runtime, and optional results (P3.2 third stage)

- **Relations**: `Implements TDD-00230` (Phase 3, P3.2); `Extends ADR-01137`
- **Date**: 2026-09-25

## Context

[ADR-01137](ADR-01137.md) set up the lowered-call path for string receivers,
and moved `trim`, the case mappings, `indexOf` and `includes` into it.
Thirteen more String methods, all built from positions, were still
hand-written IR:

- `charAt`, `charCodeAt`, `at`, `codePointAt`;
- `slice`, `substring`, `substr`;
- `startsWith`, `endsWith`, `lastIndexOf`;
- `padStart`, `padEnd`, `repeat`.

Each re-derived its argument conversions separately.

## Investigation

- **A sweep against Node.** 14 positions (including negative, fractional,
  NaN and ±Infinity) crossed with 5 end values, over every method, run on
  the previous build. It diverged from Node three ways:
  - `lastIndexOf(s, NaN)` searched from 0. The spec reads a NaN position as
    +∞, from the end.
  - An optional position holding a `number | undefined` that is undefined
    at run time was read as 0, so `s.slice(2, u)` gave `""`, where Node
    gives `s.slice(2)`.
  - `padStart(Infinity)` tried to allocate the result. Node throws
    `RangeError: Invalid string length` past V8's longest string,
    536,870,888 bytes.
- **Raising a JavaScript error from C.** The C runtime had no way to throw
  one. The IR runtime's null-dereference thrower shows the shape: build the
  error object, then `__kml_throw` it.

## Decision

- **`codegen/llvm/stringsrc/string.c`** implements the ten methods from
  the spec's steps:
  - ToIntegerOrInfinity (`to_integer`) and clamping (`clamp`);
  - `slice`'s and `substr`'s negative bounds counting from the end;
  - `substring` ordering its bounds;
  - `lastIndexOf`'s NaN or absent position meaning the end;
  - the padding functions' filler, repeated and truncated, with an empty
    filler a no-op.

  Positions stay byte offsets ([ADR-00028](ADR-00028.md)).
- **`lib/es.d.ts`** lowers each method to its entry point.
- **The RangeError.** `@__kml_throw_range_error` (`ensureRangeErrorThrow`)
  is defined whenever the string runtime is linked. `string.c` throws
  through it when a padded length passes the longest string Node makes.
- **Optional arguments.** An optional parameter's argument keeps a
  `number | undefined` variable's presence bit
  (`emitPreserveNullableOperand`), so an argument that is undefined at run
  time is absent, as in JavaScript.
- **Optional results.** A `T | undefined` result
  (`at(index): string | undefined`, `codePointAt(pos): number |
  undefined`) is passed back through a final pointer argument. The entry
  point returns whether the value is present, since a C struct return has
  no portable IR form. The value is wrapped as codegen's undefinedable `T`
  (`wrapUndefinedable`), which is also what `inferExprType` answers
  (`lowering.resultType`).
- **`repeat`** throws its RangeError, `Invalid count value: -1.5`, for a
  negative or infinite count after ToIntegerOrInfinity (so `-0.5` repeats
  zero times). The message names the count the way `Number#toString` would
  (`js_number`: shortest round-trip digits, `Infinity`). A result longer
  than the longest string is `Invalid string length`.
- **Deleted:** thirteen hand-written emitters (with `at`, `codePointAt`
  and `repeat`), their `emitCall` dispatch, and their names in
  `inferExprType`'s string-method table. Array, Blob and ArrayBuffer
  receivers keep their own routes.

## Side effects discovered

- **`u as any`** of an unset `number | undefined` still reads 0
  (BACKLOG: assertions on absent values): the assertion's
  representation, not these methods.
- **An intermittent HTTP hang** (`TestE2EHTTPCreateServerRequireHostHeaderFalse`,
  BACKLOG: HTTP examples hang on the M4) happens with the session-start
  build as often as with this one, 1 run in several on the M4.

## Verification

- **The sweep:** its 86 result lines now match Node, apart from the `as
  any` case.
- **`TestE2EStringIndexMethodsLowered`** covers positions, negative
  bounds, a run-time-undefined optional, the padding rules and the
  RangeError. Its expected output is Node's.
- **`TestE2EStringOptionalResultsLowered`** covers `at`, `codePointAt`
  and `repeat`'s RangeErrors, with Node's output. The previous build printed
  nothing for this program.
- **`make examples`:** 358/358. **`make test-par`:** only the known macOS
  `-mm=gc` segfaults fail.
- **Test262:** strict 7,024, js 7,784 (from 7,019 and 7,769).
