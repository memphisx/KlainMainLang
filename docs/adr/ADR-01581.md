# ADR-01581: A shell that starts this executable is a self-spawn

- **Relations**: Extends ADR-00972
- **Date**: 2026-10-11

## Context

The Linux arm64 Node conformance run aborted at 2000/3957 when the
workdir processes' total RSS passed the runner's 4 GB cap. 593 copies of a
single binary were running, all compiled from
`test/parallel/test-pipe-head.js`:

```js
const cmd = `"$NODE" "$FILE" | head -2`;
exec(cmd, { env: { ...process.env, NODE: process.execPath, FILE: script } }, ...);
```

`exec` runs `/bin/sh -c <cmd>`, and the shell starts the compiled binary.
The binary has no interpreter mode, so it re-runs its own program body,
which calls `exec` again. The result is an unbounded chain of processes.

## Investigation

ADR-00972 marks a child whose spawn target resolves to this executable
(`KML_KLAIN_REEXEC=1`), and the child's startup guard exits 9 before
running main. The async spawn path (`proc_spawn_on` in
`codegen/llvm/threadpoolsrc/klainpool.c`) checks only `file`. For `exec`
and `shell: true`, `file` is `/bin/sh`, so the mark was never set.

Alternatives considered:

- Mark every non-fork child with the parent's executable path, and have the
  guard compare it with its own. This needs a change to the startup guard,
  which is hand-written IR text (banned from growing).
- Scan all of the child's environment values for this executable's path.
  Shells set `_` to the last command run, so most spawns from a binary
  started in a shell would be falsely marked.

## Decision

When the spawn is `<shell> -c <command>` and a word in command position
resolves to this executable, the shell child is marked. The shell passes
the mark to the copy it starts, and that copy's guard exits 9.

A word is in command position at the start of the command and after `|`,
`;`, `&` or a parenthesis. Quotes are stripped. A word that is a variable
(`$NAME` or `${NAME}`) is looked up in the child's given environment, or in
the current one when none is given. A bare name is resolved on `PATH`, as
for a direct spawn. `fork` is never marked.

## Implementation notes

The new code is `proc_shell_runs_self` and `proc_env_value` in
`klainpool.c`, next to `proc_is_self`. It applies only when `argv[1]` is
`-c`, which is how exec and `shell: true` build a POSIX shell spawn.
Windows marks through `__kml_win_spawn` and is unchanged.

## Side effects discovered

- A self-reference that is not a command word is still missed, for
  example `sh -c 'env "$SELF"'`.
- `usedReexecGuard` (`codegen/llvm/emitter.go`) is never set, so
  `runtime_reexec_guard.go` and its caller in `childprocsrc/spawnsync.c`
  are not linked. spawnSync goes through `proc_spawn_on` and gets this fix.

## Verification

- New test `TestE2EChildProcessShellSelfSpawnRejected`: `exec` through a
  variable and through a quoted path both report exit code 9.
- Existing self-spawn and exec tests pass (Mac).
