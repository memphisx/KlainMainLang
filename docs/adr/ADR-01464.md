# ADR-01464: The `override` member modifier

- **Date**: 2026-10-07

## Context

`class B extends A { override m() {} }` was a parse error ("expected ';'");
TypeScript 4.3 added the modifier and code written for `noImplicitOverride`
uses it on every overriding member. Found writing a class extending RegExp
(ADR-01463).

## Investigation

- The class-member modifier loop (`parser_classes.go`) knew `static`,
  visibility, `readonly`, `accessor` and `abstract`, not `override`.
- tsc rejects `override` on a member the base class does not declare
  (TS4113) and on a member of a class without a base (TS4112), whatever
  `noImplicitOverride` says; that option only adds the reverse check (an
  overriding member without the modifier, TS4114), which is off by default.

## Decision

- `override` is a contextual modifier, as `abstract` is: a modifier only
  when a member name follows on the same line, so a field or method named
  `override` keeps working. It has no run-time effect.
- `FunctionDeclaration.IsOverride` and `AnnotField.Override` record it, and
  the checker reports TS4112 and TS4113: an instance member against the
  base's instance type, a static one against the base's constructor (a
  builtin base such as RegExp or Map included).
