# ADR-01237: Object.defineProperties; Object.assign with `any`

- **Relations**: `Extends ADR-01232`
- **Date**: 2026-09-29

## Context

- `Object.defineProperties` was a compile error ("Object has no method
  'defineProperties'").
- `Object.assign({}, anyValue)` was a compile error ("Object.assign's
  sources must be objects"). `Object.assign` was fixed-shape only: every
  source field had to exist on the target's static type.
- `Object.defineProperty(f, …)` returned the function's property bag
  rather than `f`.

## Decision

- **`Object.defineProperties(o, props)`.** Each of `props`' own enumerable
  keys is defined on `o` by its descriptor, with `defineProperty`'s rules.
  A descriptor that is not an object is a TypeError. The result is `o`.
  The descriptor application is factored out of `defineProperty`
  (`emitDefinePropertyOn`).
- **`defineProperty`** returns its first argument.
- **`Object.assign`.** When the target or a source is `any`, the copy runs
  on run-time properties, and the result is `any`, as TypeScript types it:
  - null and undefined sources are skipped;
  - each source's own enumerable string keys are read, so getters run;
  - each value is written to the target as an assignment through `any`
    writes it (a static target takes the key beside its layout).

  `inferExprType` mirrors this (`dynamicAssign`).

## Side effects discovered

- Symbol keys are neither copied nor defined (BACKLOG 112).
- An array target is still rejected (BACKLOG 111).

## Verification

Mac (Apple Silicon), against Node v24.19:
`TestE2EObjectDefinePropertiesAndDynamicAssign`.
