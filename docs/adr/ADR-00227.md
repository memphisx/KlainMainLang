# ADR-00227: User-facing output — drop doc references, wrap `--help`

- **Date**: 2026-08-19

## Context

Someone running `klainmain` sees flag descriptions (`--help`), invalid-flag
errors, and codegen compile errors. Many of these ended in a repo breadcrumb —
`(see docs/tdd/TDD-00074.md)`, `(TDD-00063 Stage 2b)`, `— see docs/adr/ADR-00042.md`
— which is meaningless to a CLI user who will not open the git repository. The
information they need should be inline, not a pointer. Separately, `--help` used
Go's `flag.PrintDefaults()`, which dumps each long description as a single
unwrapped line under a lone tab — the multi-clause mode/dialect descriptions ran
off the screen and read as one ugly block.

## Investigation

- `main.go`: flag descriptions and every `fatal(...)` for an unrecognized flag
  value carried `see docs/tdd/TDD-NNNNN.md` fragments; one also carried internal
  history ("Governs the strict-vs-JS behaviors that used to live behind -globals").
- `codegen/llvm/*.go`: 21 `fmt.Errorf(...)` user-facing compile-error strings ended
  in a `(see docs/…)`/`(TDD-NNNNN …)` reference. A broad grep also matched hundreds
  of *code comments* with the same references — those are legitimate developer
  cross-links and were left untouched; the line drawn is *runtime output the user
  sees*, not source comments or `docs/`.
- `--help` rendered via `flag.PrintDefaults()`: no wrapping, `\t`-prefixed
  description on the line below the flag, Go's `(default "…")` appended awkwardly.

## Decision

1. **Strip doc references from all user-facing strings.** Flag descriptions and
   flag-value errors in `main.go`, and the 21 codegen `fmt.Errorf` strings, keep
   their actual explanation and lose the repo pointer. Where a reference carried
   real information it was reworded to state it directly — e.g. "a static generator
   method … is not yet supported (a non-static generator method is)" instead of
   "(TDD-00063 Stage 2b covers instance methods)". Code comments were not touched.
   The codegen edits were applied with `sed` restricted to lines containing
   `Errorf`, so no comment reference was altered.
2. **Readable `--help`.** Replace `flag.PrintDefaults()` with a custom `flag.Usage`
   that word-wraps each description to 74 columns via a small `wrapText` helper and
   indents it six spaces under `  -name <placeholder>`, one blank line per flag.
   Backtick placeholders were added to the string flags (`` `mode` ``, `` `library` ``,
   `` `name` ``) so `flag.UnquoteUsage` renders `-mm <mode>` etc.

## Implementation notes

`wrapText` measures width in bytes, so a description containing multi-byte runes
(the `—`/`→` used in a few) wraps a hair early — harmless for help text. The
README's CLI-flags block keeps its `docs/tdd/…` links: a README reader is already
in the repo, so those are ordinary documentation cross-references, not runtime
output.

## Side effects discovered

None. No behavior change beyond message text and help layout.

## Verification

`go build`, `go vet ./codegen/...` clean; `klainmain --help` shows the wrapped,
reference-free block; a grep confirms no `fmt.Errorf` string in `codegen/llvm`
still contains a `TDD-`/`ADR-`/`docs/` reference.
