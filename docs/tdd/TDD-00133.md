# TDD-00133: `klain:sync` — CSP channels and structured concurrency (opt-in, non-Node)

- **Status**: Not Started
- **Date**: 2026-08-27

## Context

The compiler's positioning is *portability by default, Go-class power by opt-in*:
standard TS/Node code runs faithfully (and under real Node), while a growing set
of toggles let a program dial toward native-language performance. Concurrency is
the marquee gap. JavaScript's `async` is single-threaded by contract, and this
compiler **deliberately keeps it that way** so code stays portable to Node — so
`async` must *not* become multi-threaded. But Go's real differentiator is
lightweight CSP concurrency (goroutines + channels), and this compiler already
has the substrate to offer it *as a separate, explicitly-non-Node API*: the
fiber scheduler, `Worker`/OS-thread + `cluster` parallelism, `SharedArrayBuffer`/
`Atomics`, and the established pattern of linking a small C runtime for a builtin.

This is the natural first inhabitant of the `klain:` namespace beyond `klain:http`
([TDD-00131](TDD-00131.md)) — a bespoke re-imagining, not a Node shim.

## Design

### Surface (`import { go, Channel, select } from 'klain:sync'`)

- **`go(fn: () => void)`** — spawn a structured task. Not a raw OS thread per
  call: `go` schedules onto a fixed **M:N work-stealing pool** of OS worker
  threads (default = CPU count), each running the fiber scheduler — mirroring
  Go's goroutine model. `fn` may block on a channel; the worker steals other
  ready tasks meanwhile.
- **`Channel<T>(capacity = 0)`** — a typed CSP channel. `await ch.send(v)` /
  `await ch.receive(): T` (blocking, capacity-bounded); `ch.close()`;
  `for await (const v of ch)` to drain. `capacity 0` is a rendezvous (unbuffered)
  channel.
- **`select(...)`** — wait on the first ready of several channel operations
  (Go's `select`), V2.

TS-compatibility note: the surface is plain typed TS. A pure-TS reference
implementation (Promises + a shared queue) can ship so the *same import* runs —
slowly, single-threaded — under Node, while this compiler lowers it to the native
pool. (Whether to ship that Node shim is an open question below.)

### Lowering

- The channel type is a marker (like `Map`/`EventEmitter`): `ch.send`/`receive`
  emit calls into a linked C runtime (`klainsyncsrc/*.c`) implementing a
  bounded, mutex+condvar (or lock-free ring-buffer) channel — the same
  "link a small C runtime for a builtin" pattern `fetch`/`net`/`bigint` already
  use. Blocking `send`/`receive` park the calling **fiber** (not the OS thread):
  the worker's scheduler resumes another ready task, so N goroutines multiplex
  over the pool exactly as Go's do.
- `go(fn)` enqueues a task onto the pool; the pool is created lazily on first use
  (a program that never imports `klain:sync` pays nothing and links nothing).

### GC + threads

The pool's worker threads must be registered with the collector under `-mm=gc`
(`GC_register_my_thread`, the `-DGC_THREADS` Boehm build — already used by
`Worker`), and a parked fiber's frame must stay reachable from a live scheduler
queue so it isn't prematurely collected (the same invariant the existing fiber/
worker code maintains). Under `-mm=manual`, channel buffers are freed on
`close()`; a leaked open channel leaks (documented, like other manual-mode
handles).

### Why not multi-thread `async` instead

Rejected up front (this document's framing): multi-threading `async` would make
identical code behave differently — and race unsafely — versus Node, breaking the
portability contract. Concurrency-as-`klain:` keeps `async` faithful and puts the
Go model where it belongs: an explicit, opt-in, non-Node import.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| Fiber scheduler / cooperative parking | Built | `ucontext` fibers used by `http.listen`/`await` — the parking primitive `send`/`receive` reuse |
| OS-thread parallelism (`Worker`) + GC thread registration | Built | The pool's workers mirror `Worker`'s thread setup |
| `SharedArrayBuffer`/`Atomics` | Built | Available for lock-free channel internals if chosen |
| C-runtime-for-a-builtin linking pattern | Built | `fetch`/`net`/`bigint` — `klainsyncsrc` follows it |
| `klain:` specifier namespace | Built | [TDD-00131](TDD-00131.md) — `klain:sync` registers the same way |
| A work-stealing scheduler over the fiber model | Missing | The core new runtime |

## Open questions

- Whether to ship the pure-TS (Node-runnable) reference implementation of the
  `klain:sync` surface, or make it native-only (a compile error under a plain
  `tsc`/Node run). The former maximizes the "same code everywhere" story at the
  cost of maintaining two implementations.
- Rendezvous (capacity-0) semantics and `select` fairness — match Go exactly, or
  a documented subset.
- Interaction with the single-threaded event loop: a `go`-spawned task that calls
  `fetch`/timers must cooperate with (or be isolated from) the main loop.
- Structured-concurrency guarantees (does the program wait for outstanding `go`
  tasks at exit, à la a nursery, or Go's fire-and-forget?).
