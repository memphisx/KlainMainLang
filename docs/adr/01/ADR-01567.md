# ADR-01567: A construction's contextual inference does not re-enter itself

- **Relations**: Extends ADR-01562
- **Date**: 2026-10-10

## Context

Test262 crashed the compiler with a stack overflow in the checker on
`staging/sm` cases that nest generic constructions, such as
`new Proxy(array, new Proxy({}, { get(…) {…} }))`.

## Investigation

The checker infers a generic construction's type parameters from its
arguments and from its contextual type (`inferFromReturnContext`). For an
argument of an enclosing builtin construction, that context is the
enclosing construction's parameter (`constructParamContext`), whose type
parameters are inferred from all of its arguments, the asking one
included. Typing that argument asks for its context again, endlessly. A
generic call in the same position (`checkExpr`'s contextual-type check for
literal arguments) goes round the same loop through
`constructParamContext`.

tsc breaks these loops with its stack of inference contexts: an argument
being inferred is not re-inferred from its own context.

## Decision

Two re-entrancy sets on the checker:

- `returnCtx`: a call or construction whose contextual type is being read
  for return-type inference. Asked again meanwhile, it infers from its
  arguments alone.
- `paramCtx`: a construction whose argument contexts are being inferred.
  Asked again meanwhile, the argument has no context.

The sets are separate because `constructParamContext` itself calls
`inferFromReturnContext` for the same construction.

## Implementation notes

`checker/generics.go` (`inferFromReturnContext`, `constructParamContext`),
`checker/checker.go` (the two fields).

## Side effects discovered

None.

## Verification

`TestTypeOf` case (a construction nested in a generic construction);
the seven `staging/sm` files that overflowed compile to the same result as
the previous build (Mac).
