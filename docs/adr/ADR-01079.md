# ADR-01079: `url.fileURLToPath` / `pathToFileURL` `{ windows }` option, file-URL parsing off libcurl

- **Relations**: Extends ADR-00722 (the Windows halves), ADR-00671 (the legacy `url` helpers)
- **Date**: 2026-09-22

## Context

BACKLOG §2: `url.fileURLToPath(url, { windows })`. Both functions picked their flavor from the build host
(`hostPathFlavor()`), so a program could not ask for the other platform's form — a cross-platform tool
converting a Windows file URL on Linux (or the reverse) had no way to. Node 22+ takes the same option on
`pathToFileURL`.

## Investigation

- Both emitters already had the two halves (ADR-00722): the win32 one hands the still-encoded pathname and
  the host to the `path_win32.c` sidecar; the POSIX one read the decoded path back from libcurl. The flavor
  was a Go-side constant, so parameterizing the bodies by `pathFlavor` is the whole change in shape.
- Running the other flavor on a host surfaced two libcurl limits: a **Windows** build strips the `/` before a
  drive letter (`file:///C:/x` → path `C:/x`), and a **Linux/macOS** build refuses a drive letter in a file
  URL outright (`CURLUE_BAD_FILE_URL`, `urlapi.c`'s non-Windows guard) — so `{ windows: true }` on Linux
  could not even parse `file:///C:/…`. Node's own algorithm needs only the scheme and the still-encoded
  pathname; libcurl was contributing nothing but these quirks.
- Node's POSIX half rejects a non-empty, non-`localhost` host with `ERR_INVALID_FILE_URL_HOST`, whose message
  names the *host* platform (`… or empty on linux`) whatever `windows` says; the previous implementation
  ignored the host (the ADR-00671 caveat). It also rejects an encoded `/` and decodes with the strict
  `decodeURIComponent` (a malformed escape is a `URIError`).

## Decision

- `emitFlavorBranch(opt, what, pos, body)`: absent / `undefined` / `{ windows: undefined }` → the host
  flavor; a literal boolean → that flavor at compile time; a run-time boolean → both halves emitted under a
  branch, joined by a phi. Any other option key is a clean rejection.
- `emitFileURLToPathFlavor(urlStr, flavor)`: the host is split off first on both flavors (the existing
  `__kml_path_win32_split_file_host`); the POSIX flavor throws `File URL host must be "localhost" or empty on
  <nodePlatformName()>` for a bad host. The pathname comes from a new sidecar helper
  `__kml_path_win32_file_url_pathname(url)` — scheme check (case-insensitive), `//` authority skipped, cut at
  `?`/`#`, `\` → `/`, a rooting `/` added — `NULL` for a non-`file:` scheme. The win32 half feeds it to
  `__kml_path_win32_from_file_url` as before; the POSIX half rejects `%2F`/`%2f` and decodes with
  `__kml_decode_uri_component_strict`. libcurl is no longer involved in `fileURLToPath`.
- `emitPathToFileURLFlavor(raw, flavor, pos)`: the same bodies as before, keyed on the parameter;
  `emitPathResolveValues` (a value-taking split of the POSIX `path.resolve`) lets the already-evaluated
  argument feed the POSIX resolve.
- The resolver already exported both names; the arity checks admit the second argument.

## Implementation notes

`codegen/llvm/emit_url.go`, `emit_path.go` (`emitPathResolveValues`), `path_win32.go` (the new extern),
`pathsrc/path_win32.c` (`__kml_path_win32_file_url_pathname`). The path sidecar is linked on every host
already (it is what `path.win32` runs on), so the POSIX half using it costs nothing new.

## Side effects discovered

The ADR-00671 caveat ("a non-`localhost` host is ignored rather than rejected on POSIX") is fixed by this
change and deleted from the row.

## Verification

Windows, byte-identical to Node 24 (`R:\kml-scratch\s26\url1.ts`, both outputs diffed): drive and UNC URLs
under `{ windows: true }`, a POSIX path with `%20` under `{ windows: false }`, `file:///C:/x/y` as `/C:/x/y`
on the POSIX flavor, `{ windows: undefined }` ≡ no option, a run-time boolean both ways, `pathToFileURL` in
both flavors (drive, UNC, `#` escaping), and the four error messages (absolute, host on win32, encoded `/`
on both). Linux (Docker): the same probe — `C:\p\f.txt`, `\\srv\share\f`, `/home/u/a b`, `/C:/x/y`,
`file:///C:/U/a%20b`, `file:///tmp/a%20b`, `… or empty on linux`, the encoded-`/` message. E2E:
`TestE2EFileURLToPathWindowsOptionSameAsNode` (Node as oracle) plus the pre-existing URL suite green on both.
