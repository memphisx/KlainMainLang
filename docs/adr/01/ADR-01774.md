# ADR-01774: Generator functions take default and optional parameters

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- A generator function, method or expression with a default or optional parameter was rejected at compile time.
- The ordinary-function path already handles such parameters. It types a parameter as `T | undefined` (`optionalParamType`) and fills the default in a body prologue (`emitParamDefaultPrologue`).
- An unannotated parameter after an optional one is itself omittable in JavaScript.
- Separately, the yield-type join treated `any` and `number` as the same type, because both are `i64` in IR. So a generator yielding both narrowed an undefined to `0`.

## Decision

- `buildGeneratorSigThis` types optional and defaulted parameters through `optionalParamType`. In the js lane, an unannotated one after the first optional one is `any`.
- `GeneratorInfo` gains `MinArgs` (used as `Function.length` and as the construction minimum) and `Optional` (copied into the value type's `FuncParamOptional`). Construction pads omitted arguments with undefined.
- The default prologue runs at the body's start, inside its catch-all, with captures in scope.
- A generator with a body-filled default starts eagerly (`EagerStart`). Construction swaps into its fiber once, the prologue runs, and the body suspends at a start point whose resumption dispatches like a yield's. So defaults run at the call, as FunctionDeclarationInstantiation does, and a throwing one throws from the call.
- The yield join reports a mix of `any` and a typed value as `any`.

## Consequences

- Only a generator with a default pays the extra fiber swap at construction.
- `TestE2EJSFileGeneratorParameterDefaults` and `TestE2EGeneratorTypedParameterDefaults` cover both lanes.
