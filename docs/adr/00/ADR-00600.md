# ADR-00600: Logical assignment on a computed dynamic-object key

- **Relations**: Extends [ADR-00390](ADR-00390.md) (dynamic object model), [ADR-00461](ADR-00461.md)
- **Date**: 2026-09-01

## Context

`&&=` / `||=` / `??=` worked against every fixed-ptr lvalue (scalar variable,
array element, object field, static field) via `emitLogicalCompoundAssign`, but
not against a **computed dynamic-object key** — `dynObj[key] ??= v`, where the
object is the map-backed `{ [k: string]: T }` form. That path
(`emitDynamicObjectAssign`) routed a logical operator into
`emitArith("??", …)`, which cleanly rejected it (`??`/`||`/`&&` aren't arithmetic
operators), so the whole form was a clean compile error.

## Decision

Add a logical-assignment branch to `emitDynamicObjectAssign` that mirrors
`emitLogicalCompoundAssign` but goes through the map's `get`/`set`:

- Read the current value with `__kml_map_str_get`.
- `??=` on a non-`ptr` value type can never trigger (no null to coalesce) — return
  the current value, RHS unevaluated, exactly like the fixed-ptr path.
- Compute the short-circuit condition (`&&=` → current truthy; `||=` → current
  falsy; `??=` → current null, which a missing key also reads as for a `ptr`
  value type) and, only down that branch, evaluate the RHS and `__kml_map_str_set`
  it.
- Re-read the key at the merge point for the expression's value.

So `dynObj[key] ??= v` sets the key when it is absent/null, `||=` when the current
value is falsy, `&&=` when truthy — each evaluating the RHS only when it stores,
matching JS's short-circuit semantics.

## Verification

`TestE2EDynamicObjectLogicalAssign` (`??=` present vs absent key, `||=` on a `0`
value, `&&=` on a truthy value), matching Node v26. The dynamic-object /
index-signature / logical-assignment suites still pass. Built and verified on Mac
(Apple Silicon).
