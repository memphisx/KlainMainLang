# ADR-01065: A callback that falls off the end returns `undefined` — one widening rule for every closure, and `T | undefined` through a promise

- **Relations**: Extends ADR-01061 (fall-off-the-end returns `undefined` for declarations/expressions/methods — this closes the `…Params` callback path it left concrete), ADR-01057 (`T | undefined` widening), TDD-00064 (nullable scalars), TDD-00083/TDD-00084 (promise value slots)
- **Date**: 2026-09-22

## Context

BACKLOG §0 item 2a: `arr.filter(x => { if (c) return true })` returned `false` on the fall-off path, `arr.map(x => {
if (c) return x * 2 })` returned `0`, where Node gives `undefined`. ADR-01061 widened a declaration's, function
expression's and method's inferred return type to `T | undefined` when the body can complete normally, and
deliberately left the pattern-aware callback sibling (`inferUnannotatedReturnTypeParams`) concrete.

## Investigation

- The probe `const cb = (x: number) => { if (x > 1) return x * 2 }; cb(2)` printed `undefined` for *every* call.
  `inferExprType`'s `ArrowFunction` case goes through `inferUnannotatedReturnType` (which widens), so the
  binding's type — and the indirect call's `call { i1, double }` — was already `number | undefined`; the arrow's
  *emitted* define (`emitArrowFunctionWithHints`, via `inferUnannotatedReturnTypeParams`) returned a bare
  `double`. An ABI mismatch on every block-bodied arrow with a fall-off path, not a missed widening — the
  `undefined` was whatever the presence register happened to hold.
- With the sibling widened, the HOF sites already accepted a `{ i1, T }` callback result (`map` boxes it,
  `filter`/`find`/`some`/`every` take the payload's truthiness, `sort`/`replace`/`Array.from` coerce). Three
  consumers did not:
  - `Promise.prototype.then` (`emit_promise_then.go`): the runner called the callback as `call double` and stored
    the bits; `thenCallRetIR`/`thenStoreResultIR`/`thenValLoadIR` had no nullable-scalar case. An *annotated*
    `(x: number): number | undefined =>` then-callback already produced `0` — pre-existing.
  - An `async function` whose body falls off (widened since ADR-01061): `storePromiseValue` emitted
    `bitcast double <aggregate>` — invalid IR, clang error (`'%t11' defined with type '{ i1, double }' but
    expected 'double'`). And the coroutine's return-value slot was `malloc`'d and never written on the fall-off
    path, so the epilogue read heap garbage as the fulfilment value (`await f(1)` → `2`, from the previous call).
  - `reduce` collapsed the absent accumulator to zero (`5` where Node computes `NaN` through `undefined + 2`);
    `flatMap` flattened past an absent row (Node appends the `undefined` as an element).
- A closure bound to a *declared* function type (`function apply(f: (x: number) => number)`, `const g: (x:
  number) => number = …`, an interface field) is emitted against the slot's parameter hints only; its return type
  is its own. A widened closure in such a slot is the same ABI mismatch (`call double` into a `{ i1, double }`
  define). tsc rejects all of these: "Type 'number | undefined' is not assignable to type 'number'".

## Decision

1. **One widening rule.** `inferUnannotatedReturnTypeParams` widens with `widenIfMayFallOff` exactly as
   `inferUnannotatedReturnType` does. Every closure's emitted return type, its HOF callback type and its
   `inferExprType` now agree.
2. **`T | undefined` through a promise** = payload bits in `v0`, presence in `v1` — the split the task-args bundle
   already used for a nullable-scalar parameter. Implemented in `storePromiseValue`/`loadPromiseValue`
   (`nullableScalarFromWords` is the shared inverse), `streamChunkWords`/`streamChunkFromWords`, and the then
   runner (`thenCallRetIR` returns the `{ i1, T }` aggregate, `thenStoreResultIR` splits it into the two words,
   `thenValLoadIR` rebuilds it for a callback taking a `T | undefined` argument).
3. **The async result slot is `calloc`'d** (both prologues): a fall-off leaves zero = absent `{ i1, T }` /
   0 / null, which the epilogue stores as the fulfilment value.
4. **tsc's rejections, not a collapse:** `closureFallOffMismatch` (called from `coerceChecked` and from the two
   hinted closure sites in `emitExprWithObjectHint`) rejects a `T | undefined` closure bound to a declared
   `(...) => T`; `reduce` rejects a `T | undefined` callback result against a bare-`T` accumulator (strict mode;
   `-compat=js` keeps its lenient collapse, see below); `flatMap` rejects a callback that can return `undefined`
   (the faithful result is a `(U | undefined)[]`, a nullable-scalar element array, unsupported storage).
   A `void`, `any`, or `T | undefined` expected return accepts the closure unchanged.

## Implementation notes

- `emit_func.go` (`inferUnannotatedReturnTypeParams`), `emit_task_emit.go`, `emit_streams.go`,
  `emit_promise_then.go`, `emit_async.go` (both prologues), `emit_exprs_coerce.go` (`closureFallOffMismatch`),
  `emit_objects.go` (`emitClosureAgainstHint`), `emit_arrays_hof.go` (reduce), `emit_arrays_transform.go`
  (flatMap).
- `thenStoreResultIR` for a nullable scalar reuses the base type's own store text: the aggregate is split into
  `%rvpr<sfx>` (presence) and `%rv<sfx>` (payload, the name the base path already consumes), then the presence
  word is stored before the base store settles.
- `Promise<void>` keeps its 1-byte slot; `calloc(1, n)` is the only change.

## Side effects discovered

- `-compat=js`: `undefined + 2` is `2` (Node: `NaN`) — the nullable-scalar arithmetic collapse; the `reduce`
  fall-off case inherits it there. BACKLOG §0.
- A `(T | undefined)[]` element type (what `flatMap` with an absent row, or `[1, undefined]`, needs) remains
  unsupported storage; the rejection names it.
