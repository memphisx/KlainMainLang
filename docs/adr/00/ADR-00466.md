# ADR-00466: class + interface declaration merging (coexistence)

- **Relations**: Extends [ADR-00452](ADR-00452.md)
- **Date**: 2026-08-29

## Context

TS declaration merging lets an interface share a class's name, merging its
members into the class type — a large slice of the oracle's `'%s' is
declared more than once` bucket (the `accessorsOverrideProperty*` /
DeclarationMerging corpus families).

## Decision

Coexistence, not full merging: the resolver permits a same-file
class+interface name pair (either order), sharing one mangled name; the
defensive cross-decl uniqueness check learns the pair; and codegen's
`registerInterfaces` skips an interface shadowed by a class so
annotations of that name resolve to the class instance. The interface's
extra members are *ignored* — a use site touching an interface-only
member gets the ordinary "no field" error — a disclosed narrowing of
real merge semantics. Interface+interface and other merge pairs stay
rejections.

## Verification

Mac. `tests/interfaces_test.go` merge E2E and the example extension pass;
import/module/interface/class/export batch green (resolver-touching
change). TS oracle roughly flat (match-accept 1540 → 1542; a few merge
cases whose baselines flag unrelated errors now count as false-accepts).
Node oracle unchanged (40).
