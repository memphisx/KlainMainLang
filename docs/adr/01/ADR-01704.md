# ADR-01704: A `for (var x of/in …)` binding outlives its loop

- **Relations**: `Implements TDD-00230`; `Extends ADR-01057`
- **Date**: 2026-10-18

## Context

`function f() { for (var s of xs) {} return s }` failed with "undefined variable 's'". Node returns the last element, or `undefined` when there were no iterations. The binding lived only in the loop's scope. At top level it already worked, because a top-level `var` is bound before the loop.

## Decision

Inside a function, when `name` is not bound yet, a `for (var name of …)` loop over an array or string, or a `for (var name in …)` loop, is emitted as follows (`emitForVarOuter`):
- A function-scope binding of type `T | undefined` is declared, starting as undefined. T is the element type, or string for `for…in`.
- The loop body first stores the iteration's value into that binding.
- After the loop, `name` refers to that binding.

The loop's own per-iteration binding keeps type T, so the body compiles as before. For return-type inference, `defineNestedVarsForInference` binds the name with the same widened type. Other iterables (a Map, a generator) and destructuring heads keep the loop-scoped binding.

## Verification

macOS (Apple Silicon): the probes match Node's output. They cover the last element, zero iterations, `break`, a closure reading the binding after the loop, `for…in`, and the `-compat=js` lane. `TestE2EForVarBindingAfterLoop` passes.
