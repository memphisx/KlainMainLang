# ADR-01057: A skipped `var` reads `undefined`; a `try` body's writes survive the throw; unary `+`, `Number(any)` and `TypedArray.set` offsets run the real ToNumber

- **Relations**: Extends ADR-00454, ADR-01040, ADR-00215; Extends ADR-00191 (`try`/`finally`)
- **Date**: 2026-09-22

## Context

BACKLOG §0 item 1: a hoisted `var` whose initializer never ran read its declared type's zero value — `do { var a =
1; break; var b = "x" } while (0); console.log(b, typeof b)` printed `null string`, and a `var` object read under
`-compat=strict` crashed the program; Node prints `undefined undefined`. The smaller half of the same item:
`%TypedArray%.prototype.set(src, offset)` coerced the offset with a bare `fptosi`, so `"3"`, `{valueOf}`, `NaN` and
`-0.9` were wrong, and a negative or infinite offset was never range-checked — `ta.set([1], -4294967297)` wrote out
of bounds and segfaulted. `staging/sm/TypedArray/set-tointeger.js` compiles since ADR-01054 and failed on all of it.

Two more bugs surfaced under the same repro and each blocked the item, so they are fixed here rather than deferred:

- **A local written inside a `try` body read its pre-`try` value in the `catch` and after it.** `let x = 0; try { x
  = 1; throw new Error() } catch { console.log(x) }` printed `0`. This is not new and not specific to `var`: every
  `try` in every program had it whenever the slot was a plain alloca.
- **Unary `+` was a parse error** (`+s` → `unexpected token + in expression`), and `Number(x)` on an `any` returned
  the box unchanged — `Number(y) + 1` with `y: any = "  7 "` printed `"  7 1"` — because the NaN-box is an `i64`
  and `IsInteger()` matched it before the dynamic case. The runtime `ToNumber` over a boxed string also used a bare
  `strtod`, so `"  Infinity  "` was `NaN` and `"inf"` was `Infinity`.
- **`console.log` printed each argument as it was evaluated**, so `console.log(a, f())` with `f` logging put `f`'s
  line in the middle of the outer line. Found because the hoisting repro used `console.log(f(), typeof f())`.

## Investigation

`emitVarDecl` (`codegen/llvm/emit_exprs_vardecl.go`) registers a `var` at its declaration point and pre-stores the
type's zero in the entry block (`emitVarSlotDefault`, TDD-00070); `promoteVarToFuncScope` (`emitter.go`) documents
that this was deliberately "promotion-at-declaration, not hoist-to-undefined". The representation for "runtime may
be `undefined`, tsc types it as plain `T`" already exists: ADR-01040's `Nullable|IsUndefined|UncheckedIndex` shape
(`indexReadType`, `emit_undefined.go`) for an out-of-range `a[i]` — scalars ride the `{ i1, T }` aggregate,
pointers use null with the static flags, arrays the null header (ADR-01041), and every consumer (`console.log`,
`typeof`, `===`, narrowing, strict-lane gates, coerce's unwrap) already handles it. Optional parameters widen the
same way (`optionalParamType`). A hoisted `var` is exactly that shape.

The `try` bug is the classic setjmp/longjmp hazard read at the IR level: `emitTry` (`emit_exceptions.go`) branches
from the `setjmp` call's block to either the try body or the catch block, so the catch block is a CFG successor of
the setjmp, not of the try body. For an alloca whose address never escapes, SSA promotion is entitled to forward
the value the slot held at the setjmp into the catch — that is what clang did at `-O2`. C's answer is `volatile`
for such locals; every load/store site in the emitter would have to change for that. The cheaper, complete answer
is to make the address escape before the setjmp: once a pointer has been handed to something opaque, every later
call (the setjmp itself, the `__kml_throw`) may read or write through it, so the try body's store is materialized
and the catch reloads. `call void asm sideeffect "", "r,~{memory}"(ptr %slot)` in the entry block is that escape
with no runtime cost (the `asm volatile("" :: "r"(p) : "memory")` idiom). Verified by the repro flipping from `0`
to `1` and by a loop mixing `try`/`throw`/`finally` accumulating the right total. Module globals never had the bug:
the setjmp call is an opaque clobber point for a global.

For `TypedArray.set`, the spec order is ToIntegerOrInfinity → negative → `+∞` → `srcLength + offset > targetLength`.
The old code compared in `i64` after `fptosi`, which is poison for `±∞` and for `-4294967297`-sized magnitudes on
the way in; the comparisons have to run on the double.

The `Number(x: any)`/`+x` gap: `emitGlobalNumberConv` (`emit_call_number.go`) had no dynamic case and its numeric
case matched the box's `i64` IR. `__kml_any_tonum` (`emit_anyops.go`) parsed a boxed string with `strtod` and a
full-consumption check, while `Number(s)` on a static string already used the real `__kml_to_number`
(`runtime_core.go`: whitespace trim, `Infinity`, `0x`/`0o`/`0b`, junk → NaN).

A Symbol inside an `any` box is boxed as a static object (kind 1) with no runtime discriminator, so `typeof`
answers `"object"` and ToNumber yields NaN where Node throws. Making it distinguishable is a NaN-box layout change,
out of this ADR's scope; recorded below.

## Decision

1. **Hoisted `var` widening.** `hoistedVarMaySkip()` (`emitter.go`) is true when the declaration being emitted sits
   in a nested block (`len(e.scopes) > 1`) or is dead code (`e.blockDone`); a `for` init clause is exempt via
   `forInitDepth` (the init runs whenever the loop is reached, and keying on the scope depth keeps a closure nested
   in the init unaffected). `emitVarDecl` widens such a `var`'s type with `indexReadType` — arrays/objects before
   their sub-emitters, scalars/strings after the numeric-literal → `number` adjustment — and gives the slot an
   absent default in the entry block: `{ i1, T } zeroinitializer` for a scalar (a new branch next to
   `emitNullableScalarVarDecl`), `ptr null` for an object (`emitObjectVarDecl`) or array header
   (`emitArrayVarDecl`). The choice is syntactic on purpose: a nested-block `var` read only inside its block carries
   a presence bit it never needs — a cost, not a divergence.
2. **Return-type inference sees the widened type.** `inferBlockReturnExpr` (`emit_func.go`) first binds every
   nested-block `var` with `defineNestedVarsForInference` (same exemptions), so `if (c) { var q = 3 } return q`
   returns `number | undefined` instead of unwrapping to 0.
3. **`typeof` on a nullable-scalar local** reads the presence bit from storage (`emitUndefinedableTypeof`): an
   identifier read auto-unwraps to the payload, which made `typeof r` say `undefined` for a present value.
4. **Pinning across setjmp.** `e.tryDepth` is raised around the try/catch/finally bodies; `lookup` and `define`
   call `pinSlotAcrossSetjmp(sym.Ptr)` while it is non-zero, which emits the escape asm into the entry block for a
   register that is an alloca of the current function (checked against the allocas buffer; a heap-boxed capture
   cell is a malloc'd pointer and already opaque). Idempotent per slot.
5. **`TypedArray.set` offset**: ToNumber by operand type (`any` → `ToPrimitive(number)` + `__kml_any_tonum`, string
   → boxed + the same, null/undefined → 0/NaN, static Symbol → `TypeError` and the call is dead from there, else
   `coerce` to double), NaN → 0, `trunc`, then `< 0` or `> targetLength` (covers `+∞`) → `RangeError` on the double,
   then the existing `srcLength + offset > targetLength` check on the `i64`.
6. **Unary `+`** parses (`parser_exprs.go`) and lowers through `emitUnaryPlus` (`emit_exprs_operators.go`); the
   inference mirrors it (numeric operand keeps its type, everything else is a double). `Number(x)` uses
   `emitUnaryPlus` for every non-numeric operand and runs the dynamic case first; `__kml_any_tonum` calls
   `__kml_to_number` for a boxed string. `emitExprKeepNullable` (`emit_nullable_scalar.go`) is the shared "read a
   nullable-scalar local as its aggregate" helper for consumers that must see absence (`+x`, `Number(x)`, console).
7. **`ToInt32` is the spec's.** `toInt32` on a double truncates, `frem`s by 2^32 and maps NaN (what ±∞ leaves after
   the `frem`) to 0 before the `fptosi`; the shifts go through it too. A bare `fptosi` was poison for NaN/∞ and
   for a magnitude past i64 — `~({})` came out `-2` once the runtime's ToNumber changed shape, `1e20 | 0` was
   garbage. `~` on an object/array/`any` operand runs the unary-`+` ToNumber (`~[5]` is -6).
8. **`console.log` evaluates all arguments first** (`emitConsoleEvalArgs`, `emit_call_console.go`), then prints;
   the format-string leftovers path does the same.

## Implementation notes

- `codegen/llvm/emitter.go` (`forInitDepth`, `tryDepth`, `pinSlotAcrossSetjmp`, `hoistedVarMaySkip`, `lookup`,
  `define`), `emit_exprs_vardecl.go`, `emit_arrays_core.go`, `emit_objects.go`, `emit_stmts.go` (`emitFor`),
  `emit_exceptions.go` (`emitTry`), `emit_func.go` (`defineNestedVarsForInference`), `emit_exprs_operators.go`
  (`emitUndefinedableTypeof`, `emitUnaryPlus`), `emit_exprs_types.go` (unary `+` and `Number()` inference),
  `emit_call_number.go`, `emit_anyops.go`, `emit_call_console.go`, `emit_nullable_scalar.go`,
  `emit_arraybuffer.go`, `parser/parser_exprs.go`.
- The scalar-hoist branch must come *after* `checkStrictUndefinedAssign`: the widened slot type is nullable and
  would silence the strict initializer gate otherwise.
- A statically Symbol-typed `set` offset must return right after the throw: `coerce`'s own Symbol `TypeError` is a
  terminator, and the offset arithmetic emitted after it was dropped while the later `okoff` label still used it —
  clang's "use of undefined value" on the first build.
- `emitConsoleNullableScalar` is gone; the aggregate print path (`emitConsoleNullableScalarAgg`) serves both.

## Side effects discovered

- A **mixed array literal** `[[7], new Int32Array([8])]` is silently typed `number[][]` and the `Int32Array`'s bits
  are reinterpreted as doubles (`[ [ 7 ], [ 4e-323 ] ]`); `ta.set(src)` with `src: any` is a compile error
  (`'src' is not an array`). Both in BACKLOG §0.
- A **Symbol inside an `any`** is not distinguishable from an object: `typeof x` is `"object"`, `x * 1` / `+x` /
  `Number(x)` / a `set` offset give NaN instead of the `TypeError`. BACKLOG §0.
- `emitCall` has no generic ToNumber hook; `parseInt`'s radix, `Number()`, unary `+` and the `set` offset each
  spell the by-type dispatch. A shared `emitToNumber(Value)` would be the next simplification.
