# ADR-01816: `arguments.length` counts the parameters passed, on every call path

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- A function reading `arguments` takes, from its caller, how many declared parameters the call passed (TDD-00210). Several paths dropped that count, so `arguments.length` counted every declared parameter:
  - A generator: its body runs at the first `next()`, after the call, and always counted all of them.
  - A function with an empty body whose parameter default reads `arguments`. An empty block's statement list is nil, which the implicit rest parameter's check took for no body, so the function never collected `arguments`.
  - A call through `any`: neither the closure adapter nor a class method's adapter stored the count. `Headers.append("a")` through `any` did not throw webidl's "2 arguments required".
  - A constructor function (`new F(…)`), whose argument list rejected the rest parameter that `arguments` adds. Test262's harness constructor `Test262Error` failed to compile in any test reading `f.caller`.

## Decision

- A generator instance has an `__argc` field: the passed count plus one, so 0 (a zero-filled field) means not known. The construction stores it before the body can start, and the body's `arguments` reads it.
  - A direct call knows the count. The construction thunk of a generator value takes the caller's stored count. A generator value's function type now says it counts its arguments, so typed calls store the count.
  - The count is taken first in the construction core, because emitting the instance's prototype may emit the thunk, itself a construction.
- An empty body no longer skips the implicit rest parameter.
- The dynamic-call adapters store the count: the argv words, capped at the declared parameters. A class method's adapter hands it to the call it makes (`argcOverride`).
- A constructor function's rest parameter takes the trailing arguments as an array. The call stores the count.

## Consequences

- `TestE2EJSFileArgumentsCountCallPaths` and `TestE2EMethodArgumentsCountThroughAny` cover each path against Node.
