# ADR-01273: void parameters, bindings and returns hold undefined

- **Relations**: `Extends ADR-00479`
- **Date**: 2026-09-29

## Context

There were three problems with `void`:

- A parameter of type `void` was emitted as an LLVM `void` parameter
  (invalid IR). This covers both a written `v?: void` and a type argument,
  as in `T = void` for `v?: T`.
- A `return v` from a function whose return type resolved to `void`
  emitted `ret ptr`.
- `const x: void = f()` was rejected. `const x: void = undefined` read as
  a number.

## Decision

- A `void` parameter or binding is represented as undefined.
- `return v` in a void function evaluates `v` and returns.
- A void initializer may bind to a `void`, `any` or `unknown` annotation.
  With `any` or `unknown` the binding holds undefined. Any other annotation
  keeps the rejection, as tsc does.
