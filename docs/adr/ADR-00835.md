# ADR-00835: absent object values print `undefined` (not a segfault), optional object fields are `C | undefined`

- **Relations**: Extends [ADR-00833](ADR-00833.md)/[ADR-00834](ADR-00834.md) (the `T | undefined` work that surfaced these) and [TDD-00187](../tdd/TDD-00187.md)
- **Date**: 2026-09-10

## Context

Two linked bugs surfaced while hunting `T | undefined` adopters, once object-typed
absences (Map object-value miss, object-array `.find()` miss, optional object
fields) actually flowed as `C | undefined`:

1. **`console.log` of an absent object segfaulted.** An absent object is a null
   pointer; the console object branch dereferenced it to inspect fields. Node
   prints `undefined`.
2. **An optional *object* field read as `C | null`, not `C | undefined`** —
   `q.inner` (for `inner?: C`) printed `null`, `=== undefined` was false,
   `=== null` true (Node: `undefined` / true / false). Optional *scalar/string*
   fields were already correct.

## Investigation

- `emitConsolePrintValueToken` (`emit_call_console.go`) sent any
  `isInspectableObject` value straight to `emitInspectObject`, which GEPs and
  loads fields — a null-pointer deref for an absent value.
- The interface field resolver (`emitter.go`) *does* apply `undefinedableElem` to
  an optional field, so the field's stored type was `C | undefined`. But the
  field *read* runs the type through `canonicalizeClassTy` (`emit_classes.go`),
  which rebuilt the class type carrying only `Nullable` — **dropping
  `IsUndefined`/`IsNull`** — so `C | undefined` collapsed to a bare nullable
  (rendered `null`).

## Decision

- `emitConsolePrintValueToken`: when an inspectable object value is statically
  nullable (`Nullable`/`IsNull`), emit a runtime null check — a null pointer
  prints its `absentLiteral` (`undefined`/`null`), otherwise it inspects as
  before. No deref of a null object.
- `canonicalizeClassTy`: carry `IsUndefined` and `IsNull` alongside `Nullable`,
  so a `C | undefined` field stays `undefined` through the read.

## Implementation notes

`emit_call_console.go` (object null-guard); `emit_classes.go`
(`canonicalizeClassTy` kind carry-over). The guard is general — it fixes the
crash for every absent-object print path (find/Map/optional field/optional
chaining), not just `.find()`.

## Side effects discovered

None — the broad class/object/collection/inspect/console/nullable/instanceof
suites stay green. `canonicalizeClassTy`'s `Nullable`-only copy predated the
sentinel work; carrying the kind is strictly more correct.

## Verification

macOS (Apple Silicon M4): an object-array `.find()` miss, an object-valued
`Map.get()` miss, and an omitted `inner?: C` all print `undefined` (was a
segfault / `null`); `q.inner === undefined` true, `=== null` false; a present
object still inspects (`C { n: 1 }`). New `TestE2EInspectAbsentObjectValue` +
the class/object/collection/inspect/console suites green.
