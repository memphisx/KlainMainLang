# ADR-01844: Fewer switched nodes without a checker answer

- **Relations**: `Implements TDD-00230` (P3.3: the checker answers what inferExprType did)
- **Date**: 2026-10-20

## Context

- A switched node the checker leaves unanswered falls back to the old inference and is logged as a `switchFallback` row. The first shadow run after ArrayLiteral was switched logged 56,369 such rows for array literals and 10,267 for binary expressions. Almost all came from library modules compiled into every program:
  - empty literals (`const out: any[] = []`), which the checker types `never[]`;
  - the `arg ?? default` that emission synthesizes for a parameter default (`input: string = ''`), whose `arg` names no declaration the checker resolved;
  - assertions tsc rejects (`input as DataView` of a string).

## Decision

- An empty array literal the checker leaves unanswered is the default `number[]`, as `inferArrayTypeOf` gives it. An annotated binding's slot still takes its declared type (`declaredArrayType`).
- The `&&`, `||` and `??` rules read their operands through `heldOperand`, which falls back to a name's binding when the checker has no answer. A synthesized default is then typed like a written one (`nullCoalesceType`).
- A literal asserted to an array of tuples (`[[1, "x"]] as [number, string][]`) is built in that shape, the outer literal as the asserted array and its element literals as its tuples. The gate caught the missing rule (`Object.fromEntries` printed raw doubles as keys). The asserted type comes from the annotation, not from the `as` node: asking the node recursed through the literal back into itself.
- A read of an undeclared name (`-compat=js`, `unresolvedReference`) is a box. Emission throws its ReferenceError, or reads the global object's property, and yields a box either way (`emitNotDefined`, `emitGlobalPropertyRead`). The old structural answer, an i64, never matched that value.
- A call the checker leaves unanswered, through a binding held as a function, returns that held signature's result, as emission calls it. An example is `let f = () => o`, where `o`'s literal has a computed key the checker does not type, so `f()` is that function's box.
- A binding the checker leaves unanswered reads what its storage holds (`heldIdent`), as emission reads a bound name. Test262's `propertyHelper.js` is an example: `var label = options && options.label || String(name)` reads `options.label` off a JSDoc `{object}`, which tsc gives its error type.
- Under `-compat=js`, a member read the checker leaves unanswered, on a receiver held as a box, reads a box. That is the dynamic property read emission runs. JSDoc parameter types stay unenforced in that lane: the same harness declares `options.label` a `boolean` and passes strings.
- An assertion the checker rejects is held as its asserted type. That comes from the oracle's own annotation mapping, else from emission's (`resolveType`, through the `annotation` hook).

## Consequences

- In a Test262 file compiled with its harness, the fallbacks left are nodes emission synthesizes (position 0:0) and a symbol-keyed index on an `any`. Both are typed structurally.
- Verified on Apple Silicon (targeted compile of a harnessed Test262 file). The gate on Linux x86-64 (DeskMini) and a full shadow run (Node304) follow.
