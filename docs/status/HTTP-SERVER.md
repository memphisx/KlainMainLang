| Query string (`req.query: Map<string, string>`) | ✅ | | • Split from `req.path` and parsed (`a=b&c=d`), both keys and values percent-decoded via the same `decodeURIComponent` primitive this compiler already had — [ADR-00072](../adr/ADR-00072.md) |
| Request body (`req.body: string`) | ✅ | | • `Content-Length`-aware, accumulated across reads, capped at 10MiB — [ADR-00072](../adr/ADR-00072.md)<br>• Binary-safe: the buffer, the `string` value, and every string operation carry/read a length header, so an embedded null byte survives — an `"ab\0cd"` body reports length 5 and echoes 5 bytes ([TDD-00120](../tdd/TDD-00120.md)/[ADR-00364](../adr/ADR-00364.md)) |
| Binary-safe request body (`req.bodyBytes(): ArrayBuffer`) | ✅ | | • Wraps the same already-buffered, `Content-Length`-accurate bytes into an `ArrayBuffer` (no copy) — an explicit `ArrayBuffer` view for callers that want one; `req.body: string` is itself binary-safe now ([TDD-00120](../tdd/TDD-00120.md))<br>• See [TDD-00026](../tdd/TDD-00026.md)/[ADR-00106](../adr/ADR-00106.md) |
| Response headers (optional `headers: Map<string, string>` field) | ✅ | | • Fully user-controlled, including `Content-Type` if set — omitting the field behaves byte-identically to before this existed — [ADR-00072](../adr/ADR-00072.md) |
| Binary-safe response body (optional `bodyBytes: ArrayBuffer` field) | ✅ | | • Wins outright over `body`'s own content whenever present and non-null — the response writer (`__kml_http_send_response`) writes the body via an explicit-length `write()` (not a NUL-terminated `sprintf %s`), so a binary payload with embedded null bytes reaches the socket whole<br>• The plain string `body` field is itself binary-safe now — it too writes via the header length, so `bodyBytes` is an explicit-`ArrayBuffer` convenience rather than the only NUL-safe path ([TDD-00120](../tdd/TDD-00120.md)/[ADR-00364](../adr/ADR-00364.md))<br>• See [TDD-00026](../tdd/TDD-00026.md)/[ADR-00106](../adr/ADR-00106.md) |
| Streaming response body (`body: ReadableStream<string \| Uint8Array>` field) | ✅ | | • A handler whose returned object's `body` field is statically a `ReadableStream` produces a `Transfer-Encoding: chunked` response, written chunk-at-a-time by a promise-reaction-driven writer — the handler returns immediately and a slow producer holds only its own connection open; `http.close()` still waits for in-flight streams<br>• A stream error mid-response closes the connection without the chunked terminator (nothing else is signallable mid-stream)<br>• See [ADR-00300](../adr/ADR-00300.md) |
| Streaming request body (`req.stream(): ReadableStream<Uint8Array>`) | ✅ | | • `req.body`/`req.bodyBytes()` after consuming `req.stream()` throw a catchable `TypeError` (WHATWG "body already disturbed", [ADR-00362](../adr/ADR-00362.md))<br>• A handler may mix response `body` shapes across branches by declaring a union `body: string \| ReadableStream<Uint8Array>` — the writer branches on the runtime tag ([TDD-00119](../tdd/TDD-00119.md)/[ADR-00363](../adr/ADR-00363.md))<br>• Using `req.stream()` anywhere switches the program to headers-complete dispatch: the handler runs once headers are parsed and the body flows as `Uint8Array` chunks read off the socket (fiber-yield on EAGAIN, event-loop pump for non-fiber consumers); the 10MiB request cap then applies to the header block only<br>• `req.body`/`req.bodyBytes()` stay correct — they drain the remaining body into the pre-allocated buffer in place<br>• `req.stream()` piped into a streaming response body echoes without ever buffering the payload<br>• See [ADR-00301](../adr/ADR-00301.md), [ADR-00307](../adr/ADR-00307.md) |
| Graceful shutdown via `process.on('SIGINT'/'SIGTERM', handler)` | ✅ | | • The handler runs from ordinary control flow at the top of a loop iteration (never real signal context) and may clean up and `process.exit()` — [TDD-00019](../tdd/TDD-00019.md)/[ADR-00079](../adr/ADR-00079.md), [PROCESS-CLI.md](PROCESS-CLI.md) |
| `http.close()` (formal listener teardown, distinct from the graceful-shutdown row above) | ✅ | | • A bare global function (like `http.listen` itself), reachable only from inside a running request handler, `setTimeout`/`setInterval` callback, or `process.on(...)` handler — the only places code ever runs "alongside" the event loop<br>• Graceful by design: stops accepting immediately and lets already-open connections finish before `http.listen()`'s own call returns control to the rest of the program (matching Node's default `server.close()`) — `http.closeAllConnections()` (next row) is the forceful counterpart<br>• In a `{ workers: N }` cluster, one worker's `.close()` shuts down every worker — it sets a shared `mmap`'d flag each worker's event loop polls, so the whole cluster drains and exits with no external signal ([TDD-00117](../tdd/TDD-00117.md)/[ADR-00359](../adr/ADR-00359.md))<br>• See [TDD-00027](../tdd/TDD-00027.md)/[ADR-00102](../adr/ADR-00102.md) |
| `http.closeAllConnections()` (forceful in-flight teardown) | ✅ | | • The forceful counterpart to `http.close()` (Node's `server.closeAllConnections()`): `shutdown(2)`s every in-flight connection so each fiber unwinds through its own EOF finish path — no suspended-fiber teardown from outside<br>• Shuts down the calling handler's own connection too (Node parity), so send the response before calling it if the response must be delivered<br>• In a `{ workers: N }` cluster, one worker's call force-closes every worker's connections via the same shared `mmap` flag `http.close()` uses (word[1])<br>• See [TDD-00118](../tdd/TDD-00118.md)/[ADR-00360](../adr/ADR-00360.md) |
