# ADR-00828: the server `'close'` event + drain-accurate `server.close(cb)`

- **Relations**: Implements [TDD-00197](../tdd/TDD-00197.md); extends [ADR-00502](ADR-00502.md) (server `.on` events) and [TDD-00027](../tdd/TDD-00027.md) (`http.close()` graceful drain)
- **Date**: 2026-09-10

## Context

`http.Server` had no `'close'` event, and `server.close(cb)` fired `cb`
synchronously the moment it was called — Node fires both only once the server
has stopped listening and every in-flight connection has ended.

## Investigation

`__kml_http_close()` (`runtime_http.go`) clears `@__kml_listen_fd` immediately
but the reactor lets accepted connections finish, decrementing
`@__kml_conn_active` as each does ([TDD-00027](../tdd/TDD-00027.md)). So the
faithful "close moment" for the primary server is exactly `listen_fd < 0 &&
conn_active == 0` — both already in the reactor's `ccdone` block
(`%haslistener`, `%hasactiveconns`). The existing `server.close(cb)` path
(`emit_http.go`) resolved the callback after the primary/extra branch and
invoked it synchronously via `emitCBCall`.

## Decision

- Three primary reactor globals (thread-local, beside `@__kml_conn_active`):
  `@__kml_http_close_cb`, `@__kml_http_close_evt`, `@__kml_http_close_pending`.
- New `__kml_http_fire_close()` (declared unconditionally from
  `ensureHTTPRuntime` via `ensureHTTPFireClose`): fires once when `pending &&
  listen_fd<0 && conn_active==0`, clearing all state first so a re-entrant
  handler can't re-fire, then invoking the `'close'` handler and the `close(cb)`
  callback as zero-arg `{fn,env}` closures. The reactor calls it once per
  iteration in `ccdone`, right after draining is computed and before the
  keep-alive/exit decision.
- `server.close(cb)` on the primary now stores `cb` into `@__kml_http_close_cb`
  and sets `@__kml_http_close_pending = 1` instead of firing synchronously; an
  additional server keeps the synchronous `cb` (no per-server drain global).
- `server.on('close', cb)` stores the handler into `@__kml_http_close_evt`;
  registering it on a non-primary server (`httpServerSfxForExpr` returns a
  suffix) is a clean compile-time rejection.

## Implementation notes

- `runtime_http.go`: the three globals in the conn-globals block; `ensureHTTPFireClose`;
  one `call void @__kml_http_fire_close()` inserted into the event loop's
  `ccdone` (a plain instruction, no block split). `emitter.go`: `usedHTTPFireClose`.
- `emit_http.go`: the `close` method resolves the optional callback once before
  the primary/extra branch (so its header dominates both), defers on the
  primary, stays synchronous on the extra; a new `'close'` arm in the `on`/`once`
  dispatch.
- No handle-slot change — the 48-byte server handle is full; the close state
  lives in primary reactor globals, which is where the loop reads it anyway.

## Side effects discovered

`server.close(cb)`'s timing change is observable but faithful; no existing test
or example passed a callback to `close()` or registered a server `'close'`
listener, so nothing regressed. Multi-server `'close'` and the remaining server
events (`'error'`/`'connection'`/`'clientError'`) stay open (backlog).

## Verification

Verified on macOS (Apple Silicon M4): new `TestE2EHTTPServerCloseEvent`
(event + deferred cb fire in order, clean exit) and
`TestE2EHTTPServerCloseWaitsForInFlight` (close mid-handler still delivers the
in-flight response, then refuses new connections); full `go test -run
TestE2EHTTP` green (63s), plus net/fetch/eventsource/websocket suites (the
shared reactor) green.
