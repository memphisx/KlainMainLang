# ADR-00606: Hoist a side-effecting receiver in a consumed postfix `++`/`--`

- **Relations**: Refines [ADR-00376](ADR-00376.md) (`++`/`--` on member/index targets)
- **Date**: 2026-09-01

## Context

`++`/`--` on a member/index target desugars to a compound assignment
([ADR-00376](ADR-00376.md)). A **postfix** update whose value is *consumed* reads
the target twice — once for the pre-read (`old`), once inside the compound
assignment — so a side-effecting receiver ran its side effects twice:
`const before = makeObj().x++` called `makeObj()` twice. A statement-position
postfix (the pre-read is dead-code-eliminated) and a simple receiver
(identifier/`this`/static name, all idempotent) were never affected.

## Decision

Before emitting a consumed postfix update, **hoist a non-trivial member receiver
into a temp binding** and rewrite the target to read it back. `makeObj().x++`
becomes, in effect, `const t = makeObj(); t.x++` — `makeObj()` runs once, and
both the pre-read and the compound assignment go through `t`. The temp is a `ptr`
alloca bound under a fresh synthetic name (`__kml_upd_recv_<n>`); a receiver that
is already an identifier/`this` is returned unchanged, as is a non-`ptr` receiver
(none exist for member access today). Prefix updates read once and are untouched.

This reuses the existing compound-assignment machinery unchanged — only the
receiver expression is pre-bound — so accessor dispatch, nullable fields, and the
frozen check all keep working.

## Scope

Covers every side-effecting component of a consumed postfix target: a **member**
receiver (`makeObj().x++`, hoisted into a ptr temp), a side-effecting **index
expression** (`arr[side()]++`, into an `i64` temp), and a side-effecting
**array-producing object** (`makeArr()[i]++`, boxed to a header and rebound via a
ptr slot — the same array-materialization pattern [ADR-00610](ADR-00610.md) uses).
Object-then-index evaluation order matches JS. No double-evaluation edge remains.

## Verification

`TestE2EPostfixSideEffectingReceiverEvaluatedOnce` (a `makeBox().v++` read into a
variable increments once and calls the factory once), matching Node v26. The
identifier / `this` / static-field / index / prefix / decrement forms still match
Node. Built and verified on Mac (Apple Silicon).
