# ADR-01496: Generator rest and array parameters, `arguments`, `yield*` over an iterable

- **Relations**: Extends TDD-00061, TDD-00086, TDD-00210
- **Date**: 2026-10-09

## Context

A generator function rejected a rest parameter and an array-typed
parameter ("not yet supported"), so one reading `arguments` failed too
("undefined variable 'arguments'"). `yield* arr` over an array, string,
Set or Map was rejected ("a general sync `Symbol.iterator` iterable is
not yet supported").

## Investigation

- A generator instance already stores array-typed fields as a header
  pointer, and the first-class generator value already passed an array
  parameter in the closure ABI.
- The parameter binding in the body only knew scalars, and construction
  stored an array argument by copying its elements.
- A generator used as a value was typed without its rest flag, so a call
  through the value treated the first argument as the array.

## Decision

- A generator takes a rest parameter (the call's trailing arguments,
  packed as an array literal, spreads included) and array parameters. An
  array argument is the caller's array, by its live header, as for a
  function.
- A generator body reading `arguments` gets the hidden `any[]` rest and
  the `arguments` object a function gets. Its declared parameters are
  required, so every one counts.
- A generator value's type carries the rest flag (`generatorValueType`),
  and its `length` excludes the rest.
- `yield*` over an array, string, Set or Map yields each element (a
  `for…of` of `yield`) and evaluates to undefined, as an array
  iterator's return value is.

## Side effects discovered

- `yield*` over an array, above.
