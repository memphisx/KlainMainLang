# ADR-01957: A symbol type computed across an open cycle cut is not cached

- **Relations**: Implements TDD-00230 (P2.3)
- **Date**: 2026-10-29

## Context

The shadow report left `d[key]` in `node:http`'s `IncomingMessage.trailers` getter unanswered, though `key` is a `const` whose initializer types as `string`. The checker had typed `key` while resolving `field`, the binding it reads: typing `field`'s initializer walked the loop's flow, and that walk asked about `key`. `key`'s read of `field` hit the cycle guard and was unanswered, so `key` came out unanswered. `typeOfSymbol` cached that answer for the rest of the compile.

Expression types already handle this case. `TypeOf` keeps an answer computed across a cut of a binding still being resolved as provisional, and the flow cache skips answers computed across a cut (`cutCount`). Symbol types had no such rule.

## Decision

`typeOfSymbol` notes the cuts logged while it computes a symbol's type. If any of them belongs to a resolution still open when it finishes, the result is returned but not cached, and a later read computes it again once the enclosing binding is known.

## Consequences

- `examples/http/async_handler_inproc_client.ts` reports no disagreement. It previously reported this read and a member read whose receiver depended on the same cached answer.
- The example's compile time is unchanged (3.7 s on the Mac, with and without the change).
- The checker unit tests and the diagnostic-fidelity E2E tests pass (Mac).
