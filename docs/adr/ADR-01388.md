# ADR-01388: Every wait parks; one loop drives every program

- **Relations**: Implements TDD-00244; Extends ADR-01387
- **Date**: 2026-10-04

## Context

[TDD-00244](../tdd/TDD-00244.md) Stage 2, the rest. After
[ADR-01387](ADR-01387.md), a wait outside a coroutine still had a main-stack
path: `__kml_top_await` and the combinator waits (`top_wait`) took turns of
the loop through `__kml_loop_turn`, and the fetch wait (`spin`) did too. A
program with only timers drained them in `__kml_timer_drain`, and one with
only tasks in `__kml_task_run_all`, beside the loop.

## Investigation

A test-par run on Node304 with a log line in `__kml_top_await`, `top_wait`,
`spin` and `__kml_task_await_ready`'s main-stack branch found three callers:

- `TestE2EAsyncGeneratorOverFetch`: `await fetch(u)` in an async
  generator's body used the direct fetch wait, which ran loop turns on the
  generator's fiber stack.
- `TestE2EStreamOperatorsFlatMapDropTake`: `for await` in an async
  generator's body (`stream.ts`'s `dropGen`, `takeGen`) awaited each step
  through `__kml_task_await_ready`, which found no task and waited on the
  main stack.
- Neither test failed: the turns happened to be sound there.

A probe found a fourth, outside the corpus: an async function that returns
a pending promise in a program with no `await` (`return new Promise(r =>
setTimeout(r, 10))`). `programMayWait` saw no `await`, so the function was
no coroutine and its flattening waited on the caller's stack: at top level
`f().then(...)` blocked until the timer fired (`top 7` printed before the
rest of the script), and from a timer callback it hit the internal error.
Node prints `a c b top 7 cb 7`.

## Decision

- **An async generator's body parks its step** on the fetch's bridge
  promise (`emitAwaitFetchSlot`) and on each `for await` step, as its
  other awaits already did.
- **A value-returning async callable may wait.** `programMayWait` counts a
  `return <expr>` in an async function, function expression or arrow (and an
  expression-bodied async arrow), and the flattening marks its callable
  `sawAwait`, so it is a coroutine.
- **The main-stack waits are deleted**: `__kml_loop_turn`,
  `__kml_top_await`, `top_wait`, `spin` and `__kml_httpc_drive` (which had
  no caller). Each former call site calls `__kml_wait_outside_coroutine()`.
  The emitter's no-may-suspend await branch is a compile-time internal
  error.
- **The full loop drives every program with timers or tasks.**
  `__kml_timer_drain` (and `timers.c`'s self-pipe sleep) and
  `__kml_task_run_all` are deleted.
- `__kml_loop_pin` and `__kml_loop_depth` go with `__kml_loop_turn`, and
  `klainsync_on_goroutine` with its one caller.

## Implementation notes

- `runtime_loop_turn.go` keeps the loop globals a dynamic-import island's
  poll export uses (`_oneshot`, `_nowait`, `_idle`) and Node's
  unsettled-top-level-await warning text.
- The IR-text allowances of `runtime_loop_turn.go`, `emit_http_client.go`
  and `runtime_task.go` are lowered.

## Side effects discovered

- Dynamic-import islands (the opt-in `isolated` mode) still turn their own
  loop from the importer's poll. Polling the island loop's backend
  descriptor needs handles that stay registered between passes; it moves
  to Stage 4.

## Verification

- New: `TestE2EAsyncReturnPendingWithoutAwait`.
- Mac (M4): the async, await, fetch, stream, generator, worker, promise,
  import and event-loop suites; the four probes above print what Node 24
  prints.
- Linux x86-64 (Ubuntu 24.04 container): test-par 3922 tests pass,
  examples 393/393, Test262 strict 8498 and js 10506 (unchanged), no
  invalid IR.
