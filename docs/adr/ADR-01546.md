# ADR-01546: Method values and a method's `arguments`

- **Relations**: Extends TDD-00230, TDD-00210
- **Date**: 2026-10-10

## Context

- A private method read as a value (`get g() { return this.#m }`,
  `pub() { return this.#m }`) compiled to a dynamic read of the key `#m`
  on the instance, which no shape lists (private names are never
  dynamic keys): the value was null, and calling it segfaulted. (HEAD
  rejected the program with "no field '#m'".)
- A method read as a value while its class registers (a getter's
  `return this.m`, inferred then) fell to the integer default; the
  checker's function type is the member's.
- A class method reading `arguments` had no implicit rest parameter, as
  a function has: any call with arguments failed to compile ("expects 0
  argument(s)").
- The checker left an unannotated rest parameter unanswered under
  -compat=js, so a method with one, read as a value, was a number
  (`var f = c.r; f.call(…)` failed to compile).

## Decision

- A private method read on an instance whose class (or an ancestor)
  declares it is its static function record, the one a public method's
  shape lookup returns.
- An inferred member type that is the bare integer default, where the
  checker answers a function type, is the checker's (with the implicit
  `arguments` rest when the method reads `arguments`).
- A class method (not an accessor) reading `arguments` takes the
  implicit rest parameter (maybeAddArgumentsRestParam), and an
  unannotated rest parameter is any[] in buildParamSig as everywhere
  else.
- The checker types an unannotated rest parameter with no contextual
  type `any[]` in both lanes (strict still reports TS7019).
