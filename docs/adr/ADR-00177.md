# ADR-00177: Box arrays (by reference) and fix reference-type toString for `any`/`unknown`

- **Relations**: `Extends ADR-00176`, `Implements TDD-00062` (fills its deferred array-boxing item).
- **Date**: 2026-08-12

## Context

[ADR-00176](ADR-00176.md) shipped bare `any`/`unknown` parameters/returns but left **boxing an array value** deferred: `emitBoxValue` rejected an array with a clean error. That closed the "never broken IR" gap but left a real hole — an array can't be passed into an `any` slot at all, so `assert.sameValue(arr, arr)` and any array-valued `any` don't compile. Filling that gap also surfaced an adjacent, now-reachable bug.

## Investigation

- An array Value is a `{ ptr, i64 }` aggregate (data pointer + length); the box has one `i64` payload slot. The length + element type can't both fit. But arrays are **reference types** in JS, so `===` on two arrays is reference identity, not content comparison — which needs only an identity, and a value-typed array's stable identity is its **data pointer**. Boxing the data pointer gives correct semantics: `a === a` boxes the same pointer twice → true; two distinct literals have distinct buffers → false.
- `__kml_any_eq` (`runtime_dynamic.go`) already compares the object tag (6) by pointer; an array tag can reuse that exact path.
- `emitDynamicTypeof`'s fallthrough already returns "object" for any unmatched tag, so a boxed array's `typeof` is "object" (correct — arrays are objects) with no change.
- **Now-reachable bug found:** `emitDynamicToString`'s object branch `inttoptr`'d the payload and stored it *as a string pointer*, printing the object's raw struct bytes as a C string (blank/garbage). Harmless while nothing boxed an object; reachable the moment ADR-00176 let an `any` parameter carry one (`console.log(x)` where `x: any` holds `{a:1}` printed blank).

## Decision

1. **Box an array by its data pointer** under a new `kmlTagArray` (7): `extractvalue` element 0, `ptrtoint` into the payload. The length and element type are intentionally *not* preserved — a boxed array supports `===`/`!==` (reference identity) and `typeof` (→ "object"), but not indexing, `.length`, or content-accurate printing.
2. **Compare arrays by pointer in `__kml_any_eq`**: the object branch now matches tag 6 *or* 7 → the existing pointer comparison.
3. **Reference-type toString**: a boxed object stringifies to `"[object Object]"` (matching JS `String({})`, fixing the blank/garbage bug); a boxed array to `"[object Array]"` — the honest non-garbage stand-in, since the contents aren't recoverable from the pointer (a deliberate deviation from JS's `String([1,2,3]) === "1,2,3"`).

## Implementation notes

- `codegen/llvm/emit_dynamic.go` — `kmlTagArray` const; array-boxing branch in `emitBoxValue`; array + object branches in `emitDynamicToString`.
- `codegen/llvm/runtime_dynamic.go` — `__kml_any_eq` object branch extended to tag 7.
- `tools/conformance/harness-shim/assert.js` — unchanged from ADR-00176 (its `any` parameters now additionally accept array arguments).
- Identity via data pointer shares object identity's pre-existing caveat: under manual memory management, a freed-then-reallocated buffer could alias, so two logically distinct arrays could compare equal. Acceptable for V1 (same as object pointer identity).

## Side effects discovered

None beyond the boxed-object toString bug fixed here.
