# ADR-00598: Default parameter may reference an earlier parameter

- **Relations**: Supersedes the earlier-param half of [ADR-00166](ADR-00166.md)
- **Date**: 2026-09-01

## Context

A parameter default that referenced an earlier parameter
(`function f(a: number, b: number = a * 2)`) failed with `undefined variable 'a'`.
Defaults are evaluated at the **call site** (in the caller's scope), where the
callee's other parameters are not bindings — so `a` was undefined.

## Decision

In the free-function call path (`emit_call.go`), as each **scalar/string**
parameter's final value is fixed — the passed argument, its own default, or the
optional zero — materialize it into a scratch symbol keyed by the parameter
name. When a later parameter's default is emitted, push a temporary scope
populated with those scratch symbols, so the default resolves earlier parameters
(and earlier defaults — `c = b + 1` chains correctly). The scratch scope is
active **only** while a default is emitted: an ordinary argument is still
evaluated in the caller's scope and never sees a sibling parameter (verified:
`let a = 99; f(1, a)` passes the caller's `a`, not parameter `a`).

## Class methods

The same mechanism is wired into the two class-method call paths
(`emitClassCall` for instance/`super` calls, `emitStaticMethodCall` for statics)
via a shared `paramDefaultScratch` helper: each earlier scalar param is
materialized and the scratch scope is entered only around a default's emission
(`scratch.enter(fromDefault)` / `leave`), leaving ordinary-argument emission in
the caller's scope. So `c.compute(a, b = a * 3)` and `M.scale(a, b = a * 4)`
both work.

## Scope

- **Instance methods, static methods, and free functions** are covered here.
  Constructors — which previously supported no defaults at all — are handled in
  the follow-on ADR-00599 (which reworks the constructor arg loop and reuses the
  same `paramDefaultScratch`).
- Only earlier **scalar/string** params are bound (an array or nullable-scalar
  earlier param isn't materialized) — the common `number`/`string` case; the rest
  stay clean rejections.

## Verification

`TestE2EDefaultParamReferencesEarlierParam` (`b = a * 2`, a string default
`"Hi " + name`, a chained `c = b + 1`, and the caller-scope-for-arguments guard),
all matching Node v26. The existing default/optional/param and function/class
suites still pass. Built and verified on Mac (Apple Silicon).
