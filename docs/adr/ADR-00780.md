# ADR-00780: `process.env` and out-of-range `argv[i]` as `string | undefined` (TDD-00187 Stage 3)

- **Relations**: Implements [TDD-00187](../tdd/TDD-00187.md) Stage 3, on Stages 1–2 ([ADR-00778](ADR-00778.md)/[ADR-00779](ADR-00779.md)); completes the null-aware string groundwork of [ADR-00724](ADR-00724.md)
- **Date**: 2026-09-08

## Context

`process.env.MISSING` returned a null string with a bare `string` static type
(so it printed `null` and never compared `=== undefined` true), and an
out-of-range `process.argv[i]` substituted `""` — both typed `string |
undefined` by TS/Node (`env` via its `Dict<string>` shape even under default
tsc, argv per this project's TDD-00187 stance). Both were documented caveats.

## Decision

Exactly the cheap Stage 3 the TDD predicted — `string` is a pointer, so
`undefined` is the null pointer and only the static type had to change:

- `emitGetenvCall` (both `process.env.KEY` and `process.env[expr]`) returns
  `Ty: undefinedableElem(TypePtr)` — the value flow is unchanged (`getenv` →
  header copy, null stays null).
- The `argv[i]` out-of-range branch yields `null` instead of the interned
  `""`, with the same flagged type. The corpus's fork-idiom reliance
  (`!process.argv[2]`, `argv[2] === 'child'`) is safe because string
  truthiness and comparison were already made null-aware (ADR-00724: null is
  falsy; `undefined` equals only `undefined`, orderings are false).
- `inferExprType` mirrors both (the env member/index cases and a new
  `process.argv[i]` index case), so unannotated bindings adopt the nullable
  type and the strict gate engages: `const p: string = process.env.PATH` is
  now a compile error under strict (narrow / `??` / `!`), auto-widened under
  `-compat=js`.

With the type flagged, everything downstream came from earlier stages for
free: printing/`String()` render `undefined` (Stage 1's `absentLiteral`),
`=== undefined` is a plain null-pointer compare, `??` takes the ptr path,
and `if (v !== undefined)` narrows the local.

## Corpus migration (measured)

One E2E test (`TestE2EProcessEnv`) bound env reads to bare `string` and took
a `!` each; zero examples broke (279/279).

## Consequences

- The `process.env` and `argv` caveat rows retire their zero/`""`-substitute
  wording; `process.env.X === undefined` and `argv[99] === undefined` are
  faithful.
- Out-of-range `argv[i]` no longer masquerades as an empty string — code that
  relied on `""` specifically (rather than falsiness) must narrow, which is
  the faithful behavior.
- Remaining TDD-00187 work is Stage 4 only: `stdout.columns`/`.rows` off a
  TTY (retiring the deliberate 80×24 divergence) and closed-stream reads.

Verified on macOS/Apple Silicon: full `make test-par`, 279/279 examples
(+ `examples/process/env_argv_undefined.ts`), Node oracle flat.
