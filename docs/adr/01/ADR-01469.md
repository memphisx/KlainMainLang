# ADR-01469: The array header word; classes extending Array and the typed arrays

- **Relations**: Implements TDD-00247 (stage 5), Extends ADR-01468
- **Date**: 2026-10-08

## Context

Every other host layout had gained a header word before its body (stages
2 to 4); an array's `{data, len}` header had none, and `class X extends
Array` or `extends Uint8Array` was a compile error. Node's Array subclasses
are arrays: their elements, `length`, every Array method, `Array.isArray`,
species results (`map`, `filter`, … make an instance of the class) and an
override reached through a plain `T[]` reference.

## Investigation

- Array headers are made by `boxArrayValue` and `newArrayHeader`, four
  hand-rolled Go sites, two IR-text runtime functions
  (`__kml_arr_lit_rows`, the `.then` array argument), the two RegExp exec
  result headers (40 bytes: `{data, len}` then index, input, groups), three
  `dynjson.c` sites, and the two shared empty headers
  (`__kml_empty_arr_hdr`, `__kml_absent_array`). One free site
  (`emit_free_deep.go`). Stack `{ptr, i64}` slots are aggregates, never
  headers.
- TypeScript types a species result as the plain array (`b.map(…)` is
  `string[]`), so the subclass instance must be recognizable from an
  array-typed value at run time.
- Found on the way, older than this work, each fixed here:
  - `a.sort() === a` (and `reverse`, `fill`, `copyWithin`) was false, and a
    push through the result did not reach `a`: the result was a fresh
    aggregate, not the receiver.
  - `Object.keys`/`values`/`entries` and `for…in` rejected an array.
  - A boxed `Uint8Array` was `instanceof Array`.
  - `const from = Uint8Array.from([1])` failed at run time: the resolver
    took a top-level binding named like a lowered function's member
    (`from`) for a shadow of the global.
  - A top-level binding named `any` renamed the `any` type keyword in
    annotations (`const any: any = []` was a compile error).

## Decision

- Every array header has a header word at `header - 8`, the Array host's
  type id (`arrayHeaderWord`), allocated through `allocArrayHeader`/
  `allocArrayHeaderSized`; C passes it in as `KML_ARRAY_HDR_WORD`. The
  shared empty headers are `{word, null, 0}` constants addressed at `+8`.
- `class X extends Array<T>`, and a typed array: the instance is
  `[class tag][data][len][vtable][fields]`, so its body is an ordinary array
  header whose word is the class's tag. `hostBaseOf` gives the array (typed
  array) type; `new X(…)`/`super(…)` build the body as `new Array(…)` (the
  typed array's constructor) does.
- An element, `length` or Array method on the instance runs on its body,
  bound as a named array (`hostArrayReceiver`, `bindHostBody`): reads,
  writes, destructuring, calls taking `T[]` and spread all see the
  instance's own header, so writes are the instance's.
- An array value whose header word is not the Array word is a subclass
  instance's body: it boxes as the instance, inspects as Node shows it
  (`Stack(3) [ 1, 2, 3, x: 1 ]`, `Bytes(3) [Uint8Array] [ … ]`), and answers
  `instanceof` by its class's parent rows. These checks are emitted only in
  a program that declares such a class.
- Species: `map`, `filter`, `slice`, `splice`, `concat`, `flat`, `flatMap`
  (typed: `map`, `filter`, `slice`, `subarray`) construct the receiver's
  run-time class (`new C(n)`) and give it the result's elements; `from`/
  `of` through the class do the same.
- An Array method a subclass overrides, called on an array-typed value,
  checks the header word and runs the override on an instance.
- Through `any`: the shape getter reads an array member on the body; an
  Array method call re-boxes the body as an array unless the class declares
  the method; `Array.isArray` walks the parent rows to the Array row.

## Divergences

- A species or `of` construction whose constructor's first parameter
  cannot hold a number (`constructor(...items: string[])`) calls it without
  the length: a native string slot has no room for one. The instance's
  elements are the result's either way.
