# ADR-01056: An `import()` island with a top-level `await` is driven by the importer's event loop

- **Relations**: Implements TDD-00225; Extends ADR-01050, ADR-01055, ADR-00515
- **Date**: 2026-09-22

## Context

The last module top level that was not a coroutine: a lazy dynamic-import island (TDD-00056) with a top-level
`await` ran its own event loop nested inside the importer's synchronous `import()` call, so the importer's
microtasks and timers waited behind the island's awaits (probe in TDD-00225; Node interleaves them). BACKLOG §0 item
2. TDD-00224 §5's plan assumed the island shares the importer's runtime; it does not — an island is a separate
whole-program compile in a shared library with its own loop, scheduler and thread-locals.

## Investigation

TDD-00225 weighs three shapes and picks the poll bridge: the island evaluates its top level as a module task with no
loop of its own and exposes `_state` / `_poll` / `_next_deadline_ns` / `_error`; the importer's loop polls pending
islands each turn through the `child_process`-style hook trio (keep-alive, dispatch, deadline fold) and settles the
`import()` promise — now a pending task promise — from the island's module promise.

Facts that shaped the details, all read or measured in the runtime rather than assumed:

- The loop already had a single-turn mode (`@__kml_loop_oneshot`, `runtime_loop_turn.go`) but no non-blocking one;
  its `select()` wait is zero when `%needimmediate` holds, so a thread-local `@__kml_loop_nowait` folded there gives
  the island's poll a turn that never sleeps.
- `%cmdlabs` (`runtime_http.go`) is the shared absolute extra-deadline slot on `@__kml_monotonic_ns`; every runtime
  copy computes that clock the same way (`clock_gettime` over QPC on Windows), so an island's timer deadline is
  directly comparable in the importer.
- `@__kml_task_trampoline`'s catch-all rejects the task's promise with the thrown Error pointer in `v0`; the island's
  `_error` returns it, and since both compiles lay out `errorObjType` identically the importer's `catch (e)` reads
  `e.message`/`instanceof` from it.
- A rejected task promise re-throws at the awaiter (`emitAwaitTaskPromise`), so `try { await import() } catch`
  works unchanged once the promise is a task promise.
- The one bug found while bringing it up was mine: the importer bound the `_error` and `_next_deadline_ns` symbols
  to each other's slots, so the "deadline" was an Error pointer read as nanoseconds and the importer slept for
  what the reactor printed as 359 days. Found with `KML_IO_TRACE=1` plus two temporary prints.

## Decision

TDD-00225 as designed. Island side: `e.moduleTask` is decided for islands too; `endModuleBody` stores the module
promise in `@__kml_module_promise` and, for an island, spawns with `@__kml_task_trampoline` (catch-all) instead of
the entry program's `@__kml_module_trampoline`; the island's `main()` returns right after the spawn (no loop drive,
no unsettled check); `emitIslandTaskGlue` emits the four exports (constant answers for an island without a top-level
await). Importer side: `emitImportCall` (lazy) `dlsym`s the four exports, allocates a task promise and calls
`@__kml_dynimport_watch`, which settles at once when `_state` is already settled and otherwise appends a watcher;
`@__kml_dynimport_dispatch` / `_keepalive` / `_next_deadline_ns` are wired into the loop next to the
`child_process` hooks, with no-op stubs in `emitLoopTaskStubs`; the per-site `@__kml_dynimport_settle_<n>` builds
the typed result object from the accessors. An island that is pending and not idle but has no timer caps the
importer's wait at 10 ms (its fds are invisible here — the disclosed gap).

TDD-00224 §3: `emitAwait`'s main-stack tick branch is deleted. `@__kml_top_await` stays for its two non-module
callers (`@__kml_task_await_ready`'s no-task branch, the no-coroutine await of a task promise).

Also in this change: the browser-shape `worker.onerror` wrapper reads `message` off the Error object the envelope
now carries (ADR-01055 changed the payload; this adapter still expected the string).

## Implementation notes

`codegen/llvm/emit_dynimport.go` (call site, `emitIslandTaskGlue`), `emit_dynimport_watch.go` (new: watcher runtime,
`emitImportSettleFn`), `emitter.go` (`moduleTask` for islands, the island epilogue, glue call, fields),
`emit_module_task.go` (`@__kml_module_promise` store, trampoline choice), `runtime_http.go` (nowait fold, the three
hooks), `runtime_loop_turn.go` (`@__kml_loop_nowait`), `runtime_task.go` (stubs), `emit_async.go` (tick branch
removed), `emit_worker.go` (onerror wrapper). Tests: `tests/dynamic_import_test.go` (+4: interleaving from the top
level and from an async function, a throwing island rejects `import()`, an unsettled island exits 13). Status:
the dynamic `import()` row gains a note and the fd-blind-spot caveat. No example: the examples runner builds with the
default `-dynamic-import=eager`, which rejects `import()`.

The `_poll` export sets `@__kml_loop_idle` false, `oneshot` and `nowait`, runs the island's `@__kml_event_loop_run`,
and returns `state | (idle << 8)`. The importer stores the idle bit per watcher; keep-alive is "pending and not
idle", which is what makes an island that can never settle fall through to the importer's own unsettled exit.

## Side effects discovered

- Node defers a dynamically imported module's *synchronous* prefix to a later job; here it runs inside `import()`
  (TDD-00225 open question 3). Only log order differs in every probe tried.
- A synchronous throw in an island without a top-level await still exits the process from the island's `main()`
  where Node rejects `import()` (TDD-00225 open question 2).

## Verification

Windows 11 x64: the four island probes (top-level import, import from an async function, throwing island,
unsettled island) match Node 24 line for line apart from the sync-prefix deferral above; the six lazy dynamic-import
tests, the module-task, worker and async E2E subsets pass; `go vet`. Linux/macOS: not run yet — the end-of-day
pass (the bridge is platform-neutral IR; the only platform code touched is the shared `%needimmediate` fold).
