# ADR-01607: Windows static links: no duplicate-symbol noise; non-ASCII TEMP

- **Relations**: Extends ADR-01597, ADR-00772, ADR-01035
- **Date**: 2026-10-13

## Context

Since the Windows link moved to lld (ADR-01597), every `--static` build
printed a page of `ld.lld: warning: duplicate symbol: socket` (and `bind`,
`select`, `htons`, `clock_gettime`, `nanosleep`, `curl_multi_fdset`, …).
BACKLOG §2 also listed a `%TEMP%` with non-ASCII characters breaking the
build, because mingw `ld` opened intermediates through the narrow API.

## Investigation

- The duplicates are the shim's POSIX-named definitions against the same
  names in the static archives and Winsock's import library; the static
  link passes `--allow-multiple-definition` so the shim's win (ADR-00772).
  GNU ld was silent about them; lld warns for each. A static program with an
  HTTP server and `fetch` works: libuv and libcurl reach Winsock through
  their `__imp_` pointers, which the shim does not define.
- With `TMP`, `TEMP` and the scratch directory set to `R:\…\ΤΕΣΤ τμπ`, a
  program compiles and runs, dynamic and `--static`: lld opens its inputs
  through the wide API.

## Decision

The link's stderr is captured and, for a Windows `--static` link, lld's
`duplicate symbol` warnings (with their `>>> defined at` lines) are
dropped; everything else is printed as before (and annotated, under
`-ir-sites`). The non-ASCII `%TEMP%` item is closed: lld fixed it.

## Verification

Windows 11: `--static` builds of a timer program and of an HTTP server with
`fetch` print only `compiled:`, and run; the non-ASCII temp directory run
above.
