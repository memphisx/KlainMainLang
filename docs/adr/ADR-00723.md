# ADR-00723: `path.normalize` / `relative` / `toNamespacedPath` in both flavours

- **Relations**: Implements [TDD-00178](../tdd/TDD-00178.md) (open question 1); extends [ADR-00722](ADR-00722.md)
- **Date**: 2026-09-06

## Context

ADR-00722 shipped the win32 flavour with the module's existing method set
and left `normalize`, `relative` and `toNamespacedPath` missing from both
flavours (TDD-00178 open question 1). `normalize` was already inside the
win32 sidecar because `join` needs it; the posix flavour had none of the
three. This ADR adds all three to both flavours so the module's surface
matches Node's apart from `matchesGlob`.

## Investigation

- The win32 `relative` and `toNamespacedPath` are ported from `lib/path.js`
  (v24.x) like the rest of the sidecar. `relative` lower-cases both resolved
  ends for comparison but slices the original-case `to`; Node's extra branch
  for a case fold that changes string length (Unicode special casing) cannot
  arise with ASCII folding and is not ported.
- The posix `normalize`, `resolve` and `relative` are ported into the same C
  file rather than the IR runtime: they share `normalizeString`, and
  Node's posix `normalize` keeps a trailing `/`, which the IR `join` does
  not (its known caveat). The posix `resolve` port exists only because
  `relative` needs it; the user-facing `path.posix.resolve` stays on the IR
  path (behaviourally identical for absolute results).
- Differential harness against Node v24.19.0 (both flavours, `cwd`
  pinned): 74 of 75 cases identical under ASan/UBSan. The one difference
  is the oracle, not the port: Node on Windows rewrites a *relative* fake
  `cwd` in `posix.resolve` (`posixCwd()` slices from the first `/`), and a
  real `process.cwd()` is never relative.

## Decision

- Sidecar (`pathsrc/path_win32.c`): `__kml_path_win32_normalize` (exposes
  the existing function), `__kml_path_win32_relative`,
  `__kml_path_win32_to_namespaced_path`, `__kml_path_posix_normalize`,
  `__kml_path_posix_resolve`, `__kml_path_posix_relative`. The `relative`
  and `toNamespacedPath` entry points take `process.cwd()` and Node's
  `isWindows` from the emitter, as `resolve` already did.
- Emitter (`path_win32.go`): `emitPathNormalize`, `emitPathRelative`,
  `emitPathToNamespacedPath`, flavour-dispatched like the rest; the posix
  `toNamespacedPath` is the identity and emits no call. Any program using
  one of the three links the sidecar, on every host.
- `emit_call.go` dispatch, `emit_exprs_types.go` return types and the
  resolver's member list gain the three names.

## Implementation notes

- The file keeps its `path_win32.c` name although it now holds three posix
  functions; TDD-00178 option C (moving the whole posix flavour there) is
  the natural point to rename it.
- `normalizeStringWith` is `normalizeString` with the separator predicate
  as a parameter, mirroring Node's signature; the win32 code keeps calling
  the fixed-predicate version.

## Side effects discovered

- None new. `matchesGlob` remains out (it needs Node's glob matcher), and
  the posix `join` trailing-slash caveat remains until option C.

## Verification

- Differential harness (WSL2 clang 18, ASan/UBSan) vs Node v24.19.0: 74/75, the remaining case being the oracle artefact above.
- Windows 11 and Linux (WSL2): `go test -run 'TestE2EPath|TestE2EFileURL' ./tests` passes with the three new tests (`TestE2EPathNormalizeBothFlavours`, `TestE2EPathRelativeBothFlavours`, `TestE2EPathToNamespacedPathBothFlavours`) alongside ADR-00722's.
- Linux x86-64 Docker (CI-equivalent image): full `go test ./...`, `make examples`, `make conformance` — results in the commit message.
