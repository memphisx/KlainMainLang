# TDD-00122: Native `test` builtin — callback-assertion helpers (`mustCall` family)

- **Status**: Implemented
- **Date**: 2026-08-25
- **Notes**: A first-class Go-codegen builtin module (`import { mustCall } from 'test'`) giving examples/tests real async assertions: `mustCall`/`mustCallAtLeast`/`mustNotCall`/`mustSucceed` (wrap a callback, count invocations, verify at process exit via the existing exit sink), `skip`, `expectsError`/`expectWarning`, env probes. The hard piece is a signature-parametric counting trampoline (new closure-synthesis); V1 bounds it to 0–2-arg scalar/pointer callback ABIs, rejecting exotic ones cleanly

## Context

This project's examples and E2E tests currently assert behavior by printing with `console.log` and comparing
against an expected-output comment (or, for `make examples`, just checking the process exits 0). That is weak
for **asynchronous** behavior: nothing verifies that a callback — a timer, a socket `'data'` handler, a
`child_process` `'close'` listener — actually *fired*, or fired the right number of times. A handler that is
silently never invoked passes today.

The need surfaced concretely from external-conformance work: the majority of files in the large Node
behavioral suite that this project cannot run are blocked on exactly one helper — a callback-tracking utility
that wraps a function, counts how many times it is invoked, and asserts that count at process exit. Providing
a real, first-class version of that utility (a) gives this project's own examples/tests genuine async
assertions, and (b) lets that whole class of external tests become runnable as a side benefit.

A throwaway object shim does not work: a `mustCall(fn)` that returns an `any` is not callable in this
compiler's typed model. The utility has to return a value with the *same callable function type* as its
argument — which means real language/codegen support, not a data stub.

## Design

A new **Go-codegen builtin module** named `test`, dispatched exactly like `assert`
(`codegen/llvm/emit_assert.go` is the structural template; `resolver/virtual_modules.go` is the registry).
Imported first-class: `import { mustCall, skip } from 'test'`. Named imports are already rewritten to
`test__kml_builtin.member` member-expressions by `resolver/rename.go`, so both `import { mustCall }` and a
namespace form reach one dispatch site.

### Surface

- **`mustCall(fn, exact = 1)`** — returns a wrapper with `fn`'s exact function type. Each invocation of the
  wrapper increments a counter and forwards to `fn` (returning its result). At program exit the counter must
  equal `exact`, else the program prints a diagnostic and exits non-zero.
- **`mustCallAtLeast(fn, min = 1)`** — as above, but the exit check is `count >= min`.
- **`mustNotCall(msg?)`** — returns a zero-effect wrapper that, if ever invoked, fails immediately
  (`exit(1)`).
- **`mustSucceed(fn)`** — `mustCall` shape for an error-first callback: also asserts the first argument
  (the `err`) is falsy on each call.
- **`skip(msg)`** — prints a skip notice and exits **0** (a skipped test is not a failure).
- **`expectsError(fn)` / `expectWarning(...)`** — run a thunk and assert it throws / warns; copies
  `emitAssertThrows`'s setjmp/longjmp shape (`emit_assert.go`).
- **Environment probes** (value members, not calls): `isWindows`, `isLinux`, `isMacOS`, `hasCrypto`,
  `hasIntl`, `isMainThread`, … — each a constant `i1`, dispatched through `emit_exprs_member.go`.

### Verification at exit (no user call needed)

A hand-written runtime helper (`ensureTestRuntime`, new `codegen/llvm/runtime_test.go`, following the
`ensureX`+`emitGlobal` pattern of `runtime_path.go`) owns:
- an `internal global` growable registry of expectations (`{counterPtr, min, max, msgPtr}`), the
  `{data,len,cap}`-realloc idiom already used by `__kml_path_stack_*`;
- `@__kml_test_register(counterPtr, min, max, msgPtr)` — appends one expectation;
- `@__kml_test_verify()` — iterates the registry, and on the first unmet expectation prints a message and
  `call void @exit(i32 1)`.

`@__kml_test_verify` is hooked into the **existing** program-exit sink (`__kml_run_exit_handlers`,
`runtime_process.go` / `emitter.go`), so it runs on normal end and on `process.exit()` with no user action —
the same sink `process.on('exit')` already uses. (`process.on('exit')` + `process.exit(1)` are both confirmed
working, so this mechanism is proven.)

### The hard part: the counting wrapper (closure synthesis)

`mustCall(fn)` must produce a *new closure* whose function is a generated trampoline that: (1) increments the
expectation's counter, (2) invokes the wrapped `fn` via the standard `{funcPtr,envPtr}` load-slot0/slot1
indirect call, forwarding all args and returning the result. The wrapper header is a direct clone of
`emitNamedFuncValue` (`malloc(16)`, trampoline symbol in slot 0, a `{origClosure, counterPtr}` env in slot 1).
The trampoline itself is new closure-synthesis — like `ensureFuncValueTrampoline` but **signature-parametric
and memoized per callback ABI**, with the counter-increment + inner closure-call inserted.

**Arity/ABI strategy (V1 scope, staged not dropped):** support the common callback ABIs — 0-, 1-, and 2-
parameter callbacks over scalar or pointer args (covering `()`, `(err)`, `(err, result)`, `(value)`), each
trampoline memoized by its resolved LLVM signature. Callbacks with exotic ABIs — rest parameters
(`FuncHasRest` packing), nullable-scalar `{i1,T}` params, or arity > 2 — are a **clean compile error** naming
the limitation, never a silent miscompile. This keeps the crux bounded while covering the overwhelming
majority of real callbacks.

## Prerequisites

| Dependency | Status | Notes |

| Growable-global idiom | ✅ | `runtime_path.go` `{data,len,cap}` stack |
| Signature-parametric counting trampoline | ❌ new | the one genuinely hard piece; V1 bounded to 0–2-arg scalar/pointer ABIs |

## Open questions

- Module name: `test` (chosen) vs a more specific name. `test` reads cleanly at the import site and is the
  natural home if a `test(name, fn)` runner is added later.
- Whether `mustSucceed`'s "err is falsy" check should also unwrap a nullable-scalar first arg — deferred with
  the nullable-param ABI.
- Whether to add a `test(name, fn)` grouping/runner on top of these primitives (a later version; the plan's
  V1 is the `mustCall` family + probes).
- Exit-verify ordering vs a user `process.on('exit')` handler that itself asserts — both run in the one sink;
  document the order (verify last) so a user handler's own failure still surfaces.
