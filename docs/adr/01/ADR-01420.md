# ADR-01420: Literal class member names and numeric property keys

- **Relations**: Extends ADR-00608, ADR-01415
- **Date**: 2026-10-05

## Context

Found while testing ADR-01419:

- `class T { 'a-b' = 1; 0 = 3; 1() {} }` was a parse error ("expected IDENT,
  got STRING/NUMBER"); only the bracketed `['a-b']` form parsed.
- A numeric key kept its literal's text: `{ 0x10: 1 }` had the key `0x10`
  (JavaScript's is `16`), and `o[1.5]` on `{ 1.50: 2 }` was "not an array".
  The checker's `canonicalNumber` used Go's shortest `%g`, which writes
  `1000000` as `1e+06`.
- `obj[k]` with `const k = 'a'` was "not an array" in code generation while
  the checker and tsc accept it, and `t[1]()` / `t['m x']()` were "only
  simple function calls are supported".
- Under `-compat=js`, `t['nope']` on a class instance was "object has no
  field 'nope'" (JavaScript reads `undefined`), and `typeof t['m']` of a
  method was `'number'`.

## Decision

- `ast.NumberKey` is a numeric literal's key: its value as JavaScript's
  Number::toString writes it (hex, octal, binary, legacy octal, separators,
  exponents; `1e21` → `1e+21`, `1e-7` → `1e-7`, `0.000001` → `0.000001`).
  The parser names numeric object-literal keys and class member names with
  it, code generation's `constObjectKey` reads a numeric index with it, and
  the checker's `canonicalNumber` is it.
- A class member name may be a string or numeric literal; a string
  `"constructor"` is the constructor, as in JavaScript (a computed
  `['constructor']` is not).
- Code generation rewrites `obj[k]` whose key is a const holding a string or
  number literal (resolved by the checker, so a parameter or local of the
  same name is untouched) to `obj[<literal>]`, and a call whose callee is
  `obj[<literal>]` naming a member the checker knows to the member call.
- A constant key naming no field of a fixed-shape object reads the property
  through the boxed object (undefined, a method, a property added at run
  time), typed `any`; the strict lane's checker reports TS7053 before.

## Verification

Mac (M4): `TestE2ELiteralClassMemberNames` matches Node byte for byte
(literal names, `0x10`/`1.50`/`1e3` keys, a const key beside a shadowing
parameter, members called through literal indexes, `util.inspect`);
`TestNumberKey` against Node's own keys for 17 literals;
`TestE2ECompatJSMissingLiteralKey`.
