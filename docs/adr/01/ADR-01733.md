# ADR-01733: Generic classes in inheritance; Array species across element layouts

- **Relations**: `Implements TDD-00230`, Extends [ADR-00103](../00/ADR-00103.md), [ADR-01469](ADR-01469.md)
- **Date**: 2026-10-18

## Context

- **Generic classes:** a generic class could not `extend` a class, be `abstract`, or be extended with type arguments ("generic class cannot use 'extends' — not yet supported"). A generic class is monomorphized at each construction (TDD-00010), but base and derived classes share one class object, one prototype chain and one `instanceof`. `class P<T> extends Promise<T>` and `class R<T> extends Array<T>` were rejected for the same reason.
- **Species across layouts:** on `class Q extends Array<number>`:
  - `q.map(x => String(x))` stored the strings through Q's number layout, so `console.log` printed `Q(1) [ 2.14772022e-314 ]`;
  - a species method on a species result (`q.filter(f).filter(g)`, statically a plain `number[]`) returned a plain array;
  - `(q as any).map(f)` returned a plain array.
  
  Node returns a Q each time.
- **Found on the way:**
  - `xs.flatMap(f)` with `f: any` did not flatten;
  - `[1].map(5 as any)` and `[1].forEach(undefined as any)` did not throw;
  - `anyArr.splice()` and `anyArr.map()` were compile errors;
  - a non-function callee was named "value" (`u(1)`) or by its property alone (`o.x()`), where V8 names the callee: `u`, `o.x`, `a[0]`, `f(...)`.

## Decision

- **Erased generic classes:** a generic class that extends a class, is extended, or is abstract compiles once, as an ordinary class (`eraseInheritingGenerics`):
  - each of its type parameters reads as `any` in its members (`T`, `T[]`), except where a method declares its own parameter of that name;
  - type arguments at use sites are ignored, as for a type-only generic (ADR-01727's `typeOnlyGenerics`).
  
  Values of a type parameter are boxed. The monomorphized layout per type argument stays the default for every other generic class; giving inheriting classes one is future speed work.
- **Array class variants:** a species result whose elements another layout holds is an instance of the class's variant for that layout (`arrayClassVariant`, `Q__elems_<type>`):
  - the variant is registered on first use as a child of the class, shown under its name, with the new element layout as its host;
  - its instance is made by the class's constructor, its header word then set to the variant's;
  - the elements are the result's alone.
  
  This mirrors Array's own hosts, one per element layout, each a child of `any[]`'s.
- **Species on a plain-typed array:** in a program with a class extending Array, a species method on a value typed as a plain array checks the receiver's header word at run time (`arrayBodySpeciesRule`). A class's word makes the result through that class, as ArraySpeciesCreate reads the constructor.
- **Species through `any`:** an instance's shape getter returns, for each species method the class does not override, a dynamic-function record that runs the species call (`arraySubclassMethodRecord`). The `any` array fast path no longer unwraps such an instance to its plain body for these methods.
  - Arguments are forwarded by count: up to the method's own count, and up to eight for `splice` and `concat`. `splice()` makes an empty instance.
  - A callback's `thisArg` is not forwarded. `flat`'s depth must be a constant, as through `any` on a plain array.
- **Callbacks and callees:**
  - `flatMap` flattens a callback's `any` results per element through the dynamic flatten;
  - an `any` callback is checked before the method runs (`__kml_require_callable`), throwing V8's message (`number 5 is not a function`, `undefined is not a function`, `object null is not a function`);
  - a callback-less `any` call passes `undefined`;
  - a typed `splice()` returns an empty array;
  - a dynamic call that is no function names its callee as V8 does (`calleeDisplayName`, `notFunctionMsg`).

## Consequences

- **Speed:** an erased generic class boxes its type parameter's values.
- **Variant methods:** a variant's methods are its class's, compiled for the class's element layout. A method that reads the elements of an instance of another element kind reads them through the class's layout.

## Verification

macOS (Apple Silicon), against Node:

- **`tests/generic_inheritance_test.go` TestE2EGenericClassInheritance:** a generic class over a class and over a generic base; a non-generic class over a generic base; an abstract generic; `P<T> extends Promise<T>`; `R<T> extends Array<T>` with species.
- **`tests/extends_array_test.go` TestE2EArraySpeciesAcrossLayouts:** `map` to strings and booleans, species on a species result, and species through `any` (`map`, `filter`, `slice`, `concat`, `flat`, `flatMap`, `splice`).
- **`tests/builtin_prototype_test.go` TestE2ENotAFunctionMessages:** the callback messages for six kinds of value, the callback-less `any` calls, `splice()`, `flatMap` with an `any` callback, and five callee shapes.
