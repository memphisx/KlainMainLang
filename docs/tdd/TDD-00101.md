# TDD-00101: `BigInt64Array`/`BigUint64Array` & `Uint8ClampedArray` — TypedArray store/load conversion layer

- **Status**: Implemented
- **Date**: 2026-08-23
- **Notes**: Raw i64/u64/u8 storage keeps the stride machinery untouched; `BigIntElem`/`Clamped` flags drive one store helper (bigint unwrap / spec ToUint8Clamp with round-half-to-even) and one load helper (bigint wrap) at the element-traffic choke points. BigIntElem arrays compile-time-reject unlisted methods so no raw scalar ever masquerades as a bigint

## Context

TDD-00018's TypedArray design deliberately excluded the three variants whose element semantics differ from "stored scalar == surfaced scalar": `BigInt64Array`/`BigUint64Array` (memory holds a raw i64/u64, the language-level element is a `bigint` handle) and `Uint8ClampedArray` (writes clamp to [0,255] with round-half-to-even, not the mod-2^width wrap `e.coerce`'s `trunc` gives every other integer TypedArray). With `bigint` (TDD-00074) shipped and a `from/to_{i64,u64}` C ABI available, both can now be built on the existing `ArrayOf(elemTy) + IsTypedArray` representation by adding one focused mechanism instead of new array kinds.

## Design

**Representation.** Element kinds `bigint64`/`biguint64` map to i64/u64 storage, `uint8clamped` to u8 — so all pointer/stride/length machinery (`emit_arrays_*.go`) is untouched. Two new flags on `Type` carried by the array type: `BigIntElem` (elements cross the language boundary as `bigint` handles) and `Clamped` (stores clamp). The flags ride on the same flagged-`ArrayOf` shape `IsTypedArray` already uses.

**Conversion layer.** Two helpers in `emit_arraybuffer.go` become the single choke point for element traffic:

- `coerceTypedArrayStore(v, taTy, pos)` — `BigIntElem`: require `v.Ty.IsBigInt` (compile-time error otherwise, the spec's TypeError) and unwrap via `__kml_bigint_to_i64`/`to_u64`; `Clamped`: the ToUint8Clamp algorithm (integers: clamp [0,255]; floats: NaN→0, clamp, round-half-to-even via `llvm.roundeven.f64`, `fptoui`); otherwise plain `e.coerce`.
- `wrapTypedArrayLoad(raw, taTy)` — `BigIntElem`: wrap via `__kml_bigint_from_i64`/`from_u64` and surface `BigIntType()`; otherwise identity.

Hook points routed through the helpers: indexed element assignment, indexed element read (+ `inferExprType` returning `bigint` for `ta[i]`), literal/array-like construction, `.set`, `.fill`, `.at`, for-of iteration, and `Atomics.*` operand/result conversion (the spec includes BigInt64Array in Atomics; the atomic instructions themselves operate on the raw i64 unchanged).

**Method policy for BigIntElem arrays.** Rather than threading wrap/unwrap through every HOF/search/sort path (`emit_arrays_hof.go`, `_search.go`, `_sort.go` pass raw scalars into callbacks and comparisons), any array method not on the explicitly-wrapped list is a **compile-time rejection** with a clear message. Supported: indexing r/w, `.length`, `.byteLength`, `.at`, for-of, `.set`, `.subarray`, `.slice`, `.fill`, `.reverse`, `Atomics.*`. Rejected (caveat on the status row): `.map`/`.filter`/`.reduce`/`.forEach`/`.some`/`.every`/`.find`/`.indexOf`/`.includes`/`.sort`/`.join`/`.keys`/`.values`/`.entries`. The guard sits at the method-dispatch choke point so nothing silently returns a raw i64 as if it were a bigint. `Uint8ClampedArray` has no such list — reads are plain u8, every read-side method works; only stores differ.

**Unsigned 64-bit.** `__kml_bigint_from_u64`/`to_u64` added to both C backends (libtommath: decimal round-trip in, two's-complement cast out; GMP: `mpz_set_ui` in, `mpz_fdiv_r_2exp` mod-2^64 out) — `to_i64`/`to_u64` both implement the spec's wrapping ToBigInt64/ToBigUint64 semantics.
