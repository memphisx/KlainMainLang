# ADR-01049: What the collector scans — thread-local roots and the running fiber's stack

- **Relations**: `Extends ADR-00350, ADR-01028`; `Implements TDD-00098` (stage 4: `-mm=gc` with threads)
- **Date**: 2026-09-21

## Context

The [ADR-01048](ADR-01048.md) probe (20,000 sequential `await`s of a timer promise) segfaulted under `-mm=gc`,
inside `GC_malloc`, with and without that change. Narrowed with three programs, five runs each:

| Program | Windows 11 x64 | Linux x86-64 (Docker, glibc) |
|---|---|---|
| coroutines + timers | crashes most runs | 5/5 crash |
| coroutines, microtasks only | crashes most runs | 5/5 crash |
| timers only, no coroutine | passes | 5/5 crash |

`GC_DONT_GC=1` made every one pass: objects were being collected while in use and handed out again.

## Investigation

1. **Thread-local storage is not a root — on either platform.** A C program holding one `GC_malloc` block only
   through a `_Thread_local` pointer and one only through a plain global, then churning and calling `GC_gcollect`:
   the global-held block survives, the thread-local-held one comes back overwritten. Same on the Linux main thread
   and on a `GC_register_my_thread`-registered pthread. Boehm scans the image's data sections and thread stacks; a
   thread's TLS block is a separate loader allocation. The runtime keeps its loop state in `thread_local` globals
   (task array, microtask queue, timer list, worker registry…), so all of it was collectable. ADR-00350 met this
   once and moved a single structure to `GC_malloc_uncollectable`; the hole was general.
2. **Windows: the running fiber's stack was never scanned.** The shim re-pointed `GC_stackbottom` on every fiber
   switch (ADR-01028). The Win32 collector is the threaded build: it scans each registered thread from its SP to
   the stack base recorded *for that thread* and never reads `GC_stackbottom`. With the SP on a fiber's OS stack
   and the recorded base still the thread's own, it finds the SP out of range and scans the thread's original stack
   instead — so nothing a running coroutine held only in its own frames was a root.
3. **Windows: the IR undid the shim.** After a swap returns, the emitted code restores the stack bottom itself
   (`@__kml_task_gc_restore`, the generator and connection-fiber equivalents) from the *malloc'd* stack block —
   which on Windows is never the stack in use (a fiber runs on an OS-owned stack) — overwriting the value the shim
   had just set. One site wrote `@GC_stackbottom` directly instead of going through `gcSBStore`.
4. **Windows: a parked fiber's callee-saved registers were invisible.** `SwitchToFiber` keeps them in the fiber's
   control block, not on its stack; the parked-stack root started at a local of `swapcontext`.

## Decision

- `gcshim.c` gains `__kml_gc_tls_register()` / `__kml_gc_tls_unregister()`: add / remove the calling thread's TLS
  block(s) as GC roots.
  - Windows: `TEB.ThreadLocalStoragePointer[_tls_index]`, sized by the mingw CRT's `_tls_start`/`_tls_end`.
  - Linux: `dl_iterate_phdr` — each module's `PT_TLS` segment, at `dlpi_tls_data` for the calling thread.
  - macOS: a no-op for now (`_Thread_local` is allocated lazily by dyld; unverified on that platform — backlog).
  Called from the shim's constructor for the main thread, and at thread start / before thread exit for Worker
  threads (`@__kml_worker_main`) and the goroutine scheduler's M threads (`klainsync.c`). Pool threads run no
  emitted code and hold no GC pointers in TLS.
- Windows: the shim's stack-bottom hook sets the **per-thread** record — `GC_set_stackbottom(NULL, &sb)` under
  `GC_call_with_alloc_lock` — and keeps the global in step.
- Windows: `gcSBStore` ignores its operand and emits `call void @__kml_gc_sb_cur()` (gcshim.c: "the stack now
  running", from the TEB). Every IR-side set/restore thereby becomes correct wherever it runs; the direct store in
  the scheduler's resume goes through `gcSBStore` like the rest (which also fixes it for Worker programs on POSIX,
  where a raw store to the process-wide global was wrong).
- Windows: `swapcontext` calls `__builtin_unwind_init()` so the callee-saved registers are spilled into its own
  frame, above the local that marks the low end of the parked range.

## Verification

Windows 11 x64: the three programs pass 10/10; the 20,000-iteration probe completes at 15 MB. Linux x86-64
(Docker): 5/5 each (was 0/5). The C reproduction of (1) was run on both. macOS not run; the Windows shim changes are
compiled against this machine's mingw headers only — CI is the check for the runner's.
