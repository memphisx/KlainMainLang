# ADR-00256: Rest parameters in a genuinely-suspending async function

- **Relations**: refines [ADR-00249](ADR-00249.md) / TDD-00084 Part C (nullable-scalar + destructured params through the task boundary); reuses the array-param bundle path
- **Date**: 2026-08-20

## Context

A may-suspend async fn (one that awaits a fetch/another such fn) runs on a
coroutine-task fiber, so its arguments cannot live on the caller's stack — they
are marshalled into a heap args bundle at spawn (`emitSpawnCall`) and re-bound
from that bundle in the callee (`bindTaskParamsFromBundle`). Part C already
carried nullable-scalar and destructured (object/array) params across this
boundary. A **rest** parameter (`async function f(...ns: number[])`) was still a
clean rejection at both the call site (`emitMaySuspendCall`) and the callee
binding — a `TDD-00083 Stage 2` "not yet supported".

## Decision

A rest parameter is, by type, an array — its declared type is the `T[]` the
trailing args collect into. Treat it as an ordinary array param on both sides:

- **Call site** (`emitMaySuspendCall`): the last `len-1` params are evaluated
  normally; the remaining trailing args are packed by a new
  `emitRestArgsArray` into an `{ ptr, i64 }` array aggregate Value (malloc the
  data, store each coerced element, build the `{data, len}` pair — an empty rest
  yields `{ null, 0 }`). That Value fills the last `argVals` slot.
- **Callee** (`bindTaskParamsFromBundle`): the `p.Rest` rejection is removed; the
  rest param falls into the existing `pty.IsArray` case, which loads `ptr`/`len`
  from its two bundle slots and binds `ns` as a `Symbol{Ptr, LenPtr}` — a normal
  iterable array.

`taskBundleFields` already allocates two i64 slots for any array param, so the
rest param needs no bundle-layout change.

## Consequences

- `async function sum(...ns: number[])` that awaits a fetch works: the trailing
  args (or none) become an in-body array, iterable with `for...of`, `.length`,
  indexing — the same surface a named array param has.
- The rest element type follows the array's `ElemType` (default `i64`); a rest of
  a non-scalar array type rides whatever the array-param path already supports.
- Non-suspending async/ordinary calls were never restricted (they use the direct
  heap-pack in `emit_call.go`); this only closes the may-suspend gap.
