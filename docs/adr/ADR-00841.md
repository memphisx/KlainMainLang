# ADR-00841: `a ?? b` with a nullable right operand stays `T | undefined`

- **Relations**: Extends [TDD-00064](../tdd/TDD-00064.md) (nullable-scalar `??`) and [ADR-00833](ADR-00833.md) (the null-vs-undefined `===` this relies on)
- **Date**: 2026-09-10

## Context

`a ?? b` where the right operand is itself nullable (`m.get("x") ?? m.get("y")`,
both `number | undefined`) collapsed to the payload zero when both were absent:
`m.get("x") ?? m.get("y")` gave `0`, and a chained `m.get("x") ?? m.get("y") ??
-1` gave `0` instead of `-1`. `undefined ?? undefined` must be `undefined`, so a
following `?? d` reaches the default.

## Investigation

`emitNullCoalesceScalar` allocated a result slot of the bare payload type and
`coerce`d the right operand to it — unwrapping a nullable-scalar right (like
`m.get("y")`) to its payload `0`, discarding the presence bit. The result type
was the bare payload, so a chained `?? d` saw a present `0` and never took the
default. `inferExprType`'s `??` case likewise returned the bare payload.

## Decision

When the right operand's inferred type is a nullable scalar, `emitNullCoalesce`
produces a **`T | undefined`** result via `emitNullCoalesceScalarNullableRight`:
a `{ i1, T }` slot where the present branch (left present) stores `{true, left}`
and the absent branch stores the right's own aggregate (which may itself be
absent — read via `emitPreserveNullableOperand`, which keeps a nullable local's
aggregate instead of unwrapping it). `inferExprType`'s `??` case mirrors it
(returns the right's nullable type when the right is nullable). Otherwise the
existing bare-result path is unchanged.

The shared "read an operand preserving its nullable aggregate" helper was
generalized from `emitStringifyOperand` to `emitPreserveNullableOperand`
(String/template + `??`).

## Implementation notes

`emit_nullable_scalar.go` (`emitNullCoalesceScalarNullableRight`, the rename);
`emit_exprs_types.go` (`??` inference); callers in
`emit_call_number.go`/`emit_exprs_types.go` updated for the rename.

## Side effects discovered

`TestE2ENullOptionalChain` asserted `null?.length` → `0`; corrected to
`undefined` (a pre-existing baked-in assertion from ADR-00834's optional-chaining
work, only now exercised by the broadened test run).

## Verification

macOS (Apple Silicon M4): `m.get("x") ?? -1` → -1, `m.get("x") ?? m.get("y")` →
`undefined`, `(…) === undefined` → true, the chained `?? -1` → -1, and with `y`
set → `5`. New `TestE2ENullCoalesceNullableRight` + the null/expr/map/optional/
process/array suites green.
