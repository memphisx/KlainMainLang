# ADR-01120: Binder, parser and runtime faults found over TypeScript's test corpus

- **Relations**: `Extends ADR-01108`, `ADR-01106`; found by the measurement of ADR-01122
- **Date**: 2026-09-24

## Context

Running the new front end over TypeScript's own test corpus (11,874 cases,
[ADR-01122](ADR-01122.md)) crashed or misparsed on programs this compiler
accepts or should accept. Each fault below is user-visible: the compiler
itself panics, rejects a valid program, or runs one wrongly.

## Investigation

- **Dotted namespaces crash the binder.** `namespace A.B.C { … }` next to
  `namespace X.Y.Z { … }` panics (`nil pointer dereference` in
  `binder.inNamespace`), in the real compiler as in the corpus run. The
  intermediate namespaces (`A`, `A.B`) have no group node of their own, so
  every one of them entered the scope keyed by `nil`. They shared one scope
  whose parent was wherever it was first created, and leaving it could reach
  a nil scope. Eleven corpus cases panicked this way; the build from before
  the binder (the last commit) did not panic.
- **A class name declared in two namespaces** is a disclosed limitation:
  namespace type members desugar to bare top-level names (ADR-00450). Since
  the binder binds each namespace in its own scope, such a program reached
  the resolver's defensive check and printed `internal error: mangled name
  'c__kml_mod0' collided`. The last commit reported `'c' is declared more
  than once`.
- **A block-bodied arrow was a callee.** `f = () => { }` followed by a line
  starting with `(` parsed as a call of the arrow. In JavaScript an arrow
  function is not a left-hand-side expression, so the `(` on the next line
  starts a new statement (automatic semicolon insertion). The last commit
  rejected the valid program `let g = () => { … }` / `(g)()` with `cannot
  access 'g' before initialization`; Node runs it.
- **An optional parameter property was not optional.** `constructor(public
  p?: number, public s?: string)` called without arguments read `p` as `0`
  and `s` as `null`, and `c.p === undefined` was `false`; Node reads
  `undefined` for both. The parser desugared the property to a field
  without its `?`.

## Decision

- **The binder keys an intermediate namespace by its own record** when it
  has no group node, so each dotted chain has its own scopes.
- **The resolver reports the namespace type-member clash** as the
  diagnostic 90023, naming the source name: `'c' is declared as a class,
  interface, type or enum in more than one namespace; namespace type members
  share one top-level name, so each name must be unique`.
- **A bare block-bodied arrow ends the member and call chain.** The parser
  records the last such arrow; parentheses clear it, so `(() => {})()`
  still calls.
- **A parameter property keeps its `?`**: `public p?: T` declares the field
  `p?: T`.

## Side effects discovered

- **An explicit `undefined` stored into an optional field reads as
  omitted.** `{ a: undefined }` prints `{}` and `"a" in o` is `false`; Node
  keeps the key. This is independent of this step: an optional parameter
  property called without its argument now shows it, as does any
  `this.f = undefined`. It needs the missing-versus-`undefined`
  representation of TDD-00230 P3.3. It is disclosed as a caveat on the
  interfaces status row and in BACKLOG §0 item 5.
- **`-compat=js` does not hoist a block-level function** (Annex B B.3.3):
  `function f(a) { if (a) { function g() {} } return g() }` is a clean
  rejection, and Node runs it. It is disclosed as a caveat on the scoping
  status row and in BACKLOG §0 item 30.

## Verification

All on macOS arm64 (M4):

- `go test ./binder ./parser ./resolver`.
- The E2E tests above, and the namespace and class suites.
- `(g)()` after an arrow statement, `;(function () {…})()` and
  `(() => { return 5 })()`: output identical to Node 24.
- Parser corpus dump (59,519 files): identical. Over TypeScript's 11,874
  cases, 16 files parse differently, all successfully both before and
  after: 14 declare an optional parameter property, and 2 are the arrow
  statement followed by `(`.
- Resolver corpus dump (107,567 runs): identical, with the new
  `Program.Assertions` field of ADR-01122 left out of the hash.
