# ADR-00887: Boxed-element arrays — `any[]` and heterogeneous arrays under `-compat=js` (TDD-00205 Stage 2)

- **Relations**: `Implements TDD-00205`, `Extends ADR-00886`, `Implements TDD-00200`
- **Date**: 2026-09-12

## Context

TDD-00205 Stage 1 (ADR-00886) inferred a single element type for an untyped
empty array literal from its usage, but a genuinely *heterogeneous* usage
(`const a = []; a.push(1); a.push("x")`) had no single element type: the Stage 0
backstop rejected the mismatched push as a clean compile error rather than
emitting invalid IR, but the program still did not compile. The array half of
[TDD-00076](../tdd/TDD-00076.md)'s deferred boxed-`any` completeness — a
statically-typed heterogeneous / `any[]` array — was still missing
([TDD-00200](../tdd/TDD-00200.md)): an explicit `any[]` annotation and an
inferred heterogeneous literal (`[1, "two"]`) were both rejected
(`any/unknown is not yet supported as an array element or object field type`;
`array elements must share one type …`). This blocked `JSON.stringify` of a
mixed array and every method over one.

## Investigation

Measured on macOS arm64. Two representations for a mixed array were possible:
the **D1 dynamic array** (`runtime_dynarr.go`, tag 11 — 16-byte self-describing
`{tag,payload}` slots, the JSON.parse universe) that TDD-00205's prose named,
or — TDD-00200's recommendation — a **normal `Symbol{Ptr,LenPtr}` array whose
element type is a NaN-boxed `any`** (`TypeAny`, IR `i64`, one 8-byte box per
slot; `types.go`). The second was chosen: the entire array-method suite is
already generic over `elemTy` (`push`/`slice`/`concat`/…), and `coerce(v,
TypeAny)` already boxes, so the default i64 store/load path stores boxes and
loads `any` values with no new storage subsystem. A one-line relaxation of
`containsDynamicElement` (allow a bare-`any` element) made `any[]` compile, and
push/index/`length`/`typeof`/`for..of`/`map`/`filter`/`forEach`/`reduce`/
`find*`/`some`/`every`/`reverse`/`flat`/`flatMap`/`fill`/`copyWithin`/`with`/
`toReversed`/`toSpliced`/`entries`/`keys`/`slice`/`at`/`join`/spread all worked
immediately. Only the element-*comparing* and cross-`elemTy`-*copying* methods,
plus `JSON.stringify`, needed dynamic handling (each verified as a concrete
failure before fixing).

## Decision

Represent a boxed-element array as `ArrayOf(TypeAny)` — box-on-write /
unbox-on-read over the normal machinery — and route it through the dynamic
element helpers everywhere a raw scalar was assumed:

- **`containsDynamicElement`** (`emit_dynamic.go`): a bare-`any` array element is
  now permitted (a constrained *union* element is still rejected — element-level
  union checking isn't wired). So an explicit `any[]` is legal in **both**
  `-compat` lanes — the developer opting into boxing.
- **`JSON.stringify`** (`emit_call_json.go`): `emitJSONStringifyValue` gained an
  `isUnconstrainedDynamic` branch routing a boxed element through the dynamic
  walker (`emitJSONStringifyDynamic`), rendering `undefined`→`null` in value
  position — previously the i64 default rendered the raw box payload as a number.
- **`indexOf`/`lastIndexOf`/`includes`** (`emitElemEq`, `emit_arrays_core.go`):
  a dynamic element compares via `__kml_any_eq` (=== / SameValueZero — content
  equality for strings) rather than raw i64 box identity.
- **`concat`** (`emit_arrays_transform.go`): merging a *concrete*-element array
  into a boxed array copies element-wise, boxing each value (`emitBoxCopyLoop`),
  instead of a raw `memcpy` that would leave source scalars un-tagged.
- **`sort`** (`emit_arrays_sort.go`): default → `__kml_cmp_any_lex` (each element
  to its JS String() form via the new callable `__kml_any_to_cstr`, then
  `strcmp` — JS's type-agnostic lexicographic default); custom comparator →
  `__kml_sort_tramp_any` (the closure takes/returns boxed `any`; its boxed-number
  result is reduced to a sign via `__kml_any_tonum`).
- **Object/array-literal elements** (`emitPush`/`emitUnshift`,
  `emit_arrays_mutate.go`): an object/array literal pushed into an `any` slot is
  emitted through `emitExprWithObjectHint(arg, TypeAny)` so it lowers to a
  self-describing D1 dynamic value — then JSON and property access work on it.

**Inference & the lane split.** `inferEmptyArrayElemTypes` (`emit_func.go`) now
maps a heterogeneous inferred `[]` (≥2 element kinds, `isHeterogeneousElems`) to
`ArrayOf(TypeAny)`, and `inferArrayType` (`emit_exprs_types.go`) does the same
for a heterogeneous *literal*. The `-compat` split is applied at the var-decl
site, not in inference (the emitted type is identical): under `-compat=js` the
boxed array is accepted; under **strict** an *inferred* heterogeneous empty
array is rejected with a recognizable, actionable message
(`heterogeneousArrayStrictError`) naming the escape hatches — a fixed-length
tuple, an explicit `any[]` annotation, or `-compat=js` — since strict keeps
arrays uniform. An explicit `any[]` annotation stays legal in strict (the one
strict-legal spelling that opts into boxing); a heterogeneous *literal* under
strict keeps its existing element-coercion rejection.

## Implementation notes

- `__kml_any_to_cstr` is emitted with the builder-swap idiom (cf.
  `emitClassStaticInit`) so it reuses the full tag-dispatch of the inline
  `emitDynamicToString` rather than duplicating it as raw IR.
- The strict rejection is guarded at both `declaredArrayType` consumers
  (`emitVarDeclBody` emits the error; `reliableGlobalType` returns not-reliable
  so a global doesn't promote and bypass it).
- `isHeterogeneousElems`/`elemKindKeyBroad` classify by a coarse kind so a mix
  of two distinct kinds triggers boxing, while a single non-scalar kind (e.g.
  all-objects) is left out (not this pass's job).

## Side effects discovered

- **Type-erasure boundary.** A *statically-typed* object or array *value* (not a
  literal) boxed into an `any` slot keeps its compile-time-only layout, so the
  runtime dynamic walker cannot introspect it: deep `JSON.stringify` of such an
  element throws the existing clean "statically-typed value in a dynamic
  position" TypeError rather than serializing. A nested homogeneous *array*
  element (tag-7, type-erased per ADR-00478) has the same boundary. Object
  *literals* avoid it (they lower to a self-describing dynamic object). Storage
  and typed access work in all cases. Tracked as TDD-00200's nested open
  question.
- `TestE2EAnyArrayParamRejected` / `TestE2EAnyArrayElementRejected` encoded the
  old rejection of `any[]`; both were rewritten to assert the now-working
  behavior.
- **Capability gain (`@erased` generics over `T[]`).** The boxed-element array
  removed the reason `containsDynamicElement` had to reject a dynamic array
  element, so an `@erased` generic parameter/return typed `T[]` (T erasing to a
  boxed element) now compiles and runs — `first<T>(arr: T[]): T`,
  `len<T>(arr: T[]): number`, `tail<T>(arr: T[]): T[]` all work for both number
  and string instantiations (verified). Previously out of TDD-00010 V2 scope
  (a clean rejection). The stale carve-out comment in `emitFunc` (return-type
  check) and `TestE2EErasedGenericFunctionArrayOfTRejected` were updated to the
  working behavior; the return-type rejection now names only an `any`/union
  nested as an *object field*, the one shape still unwired. (Arithmetic on a
  bare erased `T` stays rejected — a separate wall.)

## Verification

- Cases now compile+run (`-compat=js`): inferred heterogeneous `[]` and mixed
  literal → boxed `any[]`; full method surface (map/filter/reduce/indexOf/
  includes by value/concat with boxing/slice/sort default+comparator/join/JSON/
  spread/for..of); object-literal elements JSON + access. Strict: inferred
  heterogeneous `[]` → the actionable rejection; homogeneous inference (Stage 1)
  and typed arrays unaffected.
- New tests: `TestE2EEmptyArrayHeterogeneousCompatJS`,
  `TestE2EEmptyArrayHeterogeneousRejected` (rewritten),
  `TestE2EArrayPushTypeMismatchRejected`, `TestE2EAnyArrayMethodParity`,
  `TestE2EAnyArrayObjectElement`, `TestE2EAnyArrayParam`,
  `TestE2EAnyArrayElement`. New example `examples/jsmode/heterogeneous_array.js`.
- `go build`, `go vet ./...`, targeted array/dynamic suites green; full
  `make test-par` gate run (core-codegen change).
