# ADR-01188: A string iterates its code points, also when held in `any`

- **Relations**: `Supersedes ADR-00535`, `Extends ADR-00536`, `Extends ADR-01182`
- **Date**: 2026-09-28

## Context

`for (const c of s)`, `[...s]`, `Array.from(s)` and `const [a, b] = s`
walked a string byte by byte (ADR-00535): with this compiler's UTF-8
strings, `"aé😀b"` produced eight one-byte strings, six of them broken
halves of multi-byte characters, where Node yields four code points.
Iterating a string held in `any` threw "is not iterable" (BACKLOG).

## Investigation

All four forms share `emitStringToCharArray`. A string's iterator yields
code points (ES `%StringIteratorPrototype%.next`), and a code point is one
UTF-8 sequence, so iteration can be exact whatever `.length` counts.

## Decision

- `emitStringToCharArray` steps by UTF-8 sequence (`emitUTF8SeqLen`: 1 for
  ASCII, 2–4 from the lead byte, 1 for a stray continuation byte, never
  past the end); the array's length is the code-point count.
- `for…of` over `any` turns a string into that array first
  (`anyStringAsCodePoints`), then walks it as an array.

## Implementation notes

`codegen/llvm/emit_arrays_iter.go`, `emit_stmts_forof_any.go`,
`emit_stmts.go`, `emit_arrays_core.go`.

## Side effects discovered

None.
