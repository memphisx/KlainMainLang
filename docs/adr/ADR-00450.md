# ADR-00450: namespaces V2 — module synonym, non-exported/type members, sibling references

- **Relations**: Implements [TDD-00148](../tdd/TDD-00148.md); Extends [ADR-00290](ADR-00290.md) (TDD-00095 V1)
- **Date**: 2026-08-29

## Context

Internal modules were the TS acceptance oracle's largest remaining
agreement cluster (the `module` blocker at 124 false-rejects, `export
module` behind the 144-case `'export' can only precede…` bucket, plus a
share of the 291 `undefined variable` sibling-reference rejects). V1
supported only `namespace X { export function/const }`.

## Investigation / Decision

Design and alternatives in [TDD-00148](../tdd/TDD-00148.md). Summary of
what shipped, all four stages:

1. `module X { }` parses as `namespace X { }`. Contextual guard (IDENT
   then `{` or `.`), so `module.exports` expressions and variables named
   `module` are untouched. `export namespace/module X {}` at top level
   parses as the plain declaration (exportness meaningless single-file).
   Dotted names (`module A.B.C`) are a clean rejection.
2. Non-exported value members parse and desugar like exported ones;
   `ast.Program.Namespaces` values now mean *exported* (was: constant
   true), and outside `X.member` access to a non-exported member is a
   clean "not exported" rejection. The resolver's namespace merge
   preserves the flag (it used to force true — found when the negative
   test compiled anyway).
3. Type members (class/`const enum`/enum/interface/type, incl. `abstract
   class`) desugar to bare-name top-level declarations, riding the
   qualified-`new`/`extends` final-segment precedent (ADR-00408); same-name
   collisions across namespaces surface the ordinary duplicate error.
4. Sibling references by bare name inside member function bodies:
   `emitFunctionDeclAs` derives the namespace context from the `__kmlns_`
   name infix; `resolveFuncRef` (functions — covers calls, value refs, and
   every inference site that goes through it) and `emitIdent`/`emitCall`
   (variables/closures) retry the mangled sibling name after every local
   lookup misses, so shadowing wins. Sibling consts ride the existing
   ADR-00342 module-global promotion, with its type limitations.

## Implementation notes

`parser/parser_stmts.go` (rewritten `parseNamespaceDecl`, `module` branch),
`parser/parser_imports.go` (export tolerance), `ast/nodes.go` (map meaning),
`resolver/resolver.go` (flag-preserving merge), `codegen/llvm/emitter.go` +
`emit_func.go` + `emit_call.go` + `emit_exprs.go` + `emit_exprs_member.go`
(context tracking, `nsSibling` fallback, not-exported rejection).
V1's `TestE2ENamespaceMemberRequiresExport` asserted the old parse-time
rejection; replaced by the V2 outside-access rejection test.

## Side effects discovered

- Top-level namespace `const` initializers referencing siblings still
  emit in `main` outside any namespace context — unsupported, clean error
  (status caveat; TDD-00148 open item).
- `X.Enum.Member` outside access unsupported (bare `Enum.Member` works
  everywhere, since enums desugar bare-name).
