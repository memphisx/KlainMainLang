# ADR-01699: User class prototypes as values

- **Relations**: `Implements TDD-00230`; `Extends ADR-01698`
- **Date**: 2026-10-18

## Context

`C.prototype` failed to compile for a user class with "class 'C' has no static field 'prototype'". So did `C.prototype.m.call(x)`. `Object.getPrototypeOf` of a typed instance was refused, and for a boxed instance it returned `null`.

## Decision

1. **The prototype object.** `C.prototype` is a bag built once per class in `@__kml_cproto_obj_<C>` (`emitClassProto`, `__kml_class_proto`). In declaration order it holds:
   - `constructor`, which is C;
   - C's own methods, as the shape method records that an instance's dynamic read already returns;
   - C's own accessors, as accessor properties over the getter and setter records.
   None of these properties are enumerable. Its `[[Prototype]]` is the base class's prototype object, or `Object.prototype` for a root class.
2. **An inherited method's record is its implementor's.** The shape method record of a method a class inherits without overriding is its implementor's record. So `D.prototype.m === C.prototype.m === d.m` holds, as with one function on the base prototype.
3. **A foreign receiver.** A method record's adapter checks its receiver with `instanceof`.
   - A receiver of another kind (`C.prototype.m.call({ x: 10 })`) runs the method's body on it as an `any`. The body is compiled once more as `function (this: any, …)`.
   - A body that does not compile that way gets the TypeError `Method C.prototype.m called on incompatible receiver …`. These are generator and async methods, generic methods, rest or destructured parameters, `super`, and private names.
4. **Reads that reach the prototype.**
   - `Object.getPrototypeOf` of a class instance, typed or boxed, returns its class's prototype object. Classes are tested most derived first.
   - `x instanceof C` of a plain object is true when `C.prototype` is on the object's prototype chain (`D.prototype instanceof C`).

## Consequences

- `getPrototypeOf` of an instance builds the prototype objects of the program's own classes; library classes are not tested.
- `Object.setPrototypeOf` of a typed instance is still refused.

## Verification

macOS (Apple Silicon): the probe covers identity across instances and subclasses, `constructor`, accessors (`getOwnPropertyNames`), `getPrototypeOf` (typed, boxed, and the chain), `instanceof`, `hasOwnProperty`, and foreign receivers (`{x}`, `Map`). It matches Node's output. `TestE2EClassPrototypeValues` passes.
