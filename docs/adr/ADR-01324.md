# ADR-01324: Two front-end runaways on generic code

- **Relations**: Fixes TDD-00230 (P2), Extends TDD-00010
- **Date**: 2026-10-01

## Context

The WPT suite's js lane on linux-x64 died partway through with a Go stack
overflow in the checker. The run had no report. The cause was
`webcodecs/audio-data-copyTo.any.js`, which calls the harness's
`assert_array_equals<T>(a: T[], b: T[], desc: string)` with a template
literal for `desc`. The cycle:

1. Typing the template literal asks whether its contextual type holds a
   string literal type (`literalContext`).
2. The contextual type of an argument of a generic call is its parameter,
   instantiated with the call's inferred type arguments (`contextualType`
   calling `inferArgs`).
3. Inferring them types each argument, the template literal included.

The overflow surfaced minutes later, in an unrelated file. The runner had
timed out on this file and abandoned its front-end goroutine, which kept
recursing.

With the cycle broken, the call failed in codegen, because a type
parameter was inferred only from the first parameter that names it. `a`
received an `any` (`output as any`), and codegen reported "cannot infer
type argument 'T'", where TypeScript infers `T` from `b`.

## Decision

1. **The checker.** While a call's type arguments are inferred for an
   argument's contextual type, that call is marked (`Checker.inferring`).
   A contextual-type query for an argument of a marked call answers with
   the parameter uninstantiated, without starting inference again. Calls
   and `new` expressions both work this way.
2. **Codegen's inference** (`inferGenericCallConcreteTypes`) considers
   every parameter position naming the type parameter, in order:
   - the first answer that is not `any` wins;
   - an `any` answer is used only when no other position answers.
   `genericFuncTypeParamIndex` lists every such position.
   `inferFromGenericArg` is one position's answer, and an `any` argument
   for a `T[]` parameter answers `any`.
3. **A generic class's instance type is memoized** per instantiation
   (`genericClassInstanceType`). A field whose type is the instantiation
   itself gets the class by name while its fields are still being built.
   The TS suite's `classTypeParametersInStatics.ts` (a list with `next`
   and `prev` of type `List<T>`) rebuilt the type once per such field per
   level. Memory grew by gigabytes a second until the kernel killed the
   run, so the TS lane never finished at this corpus pin.
4. **The WPT runner.** It gains two debugging switches:
   - `WPT_TRACE` logs each file's start and result;
   - `WPT_ONLY` restricts the run to matching paths.

## Consequences

- A front-end timeout still leaves its goroutine running in the runner
  process. A file that recurses is found through `WPT_TRACE`: it is the
  one that started and never finished.
- Codegen still requires explicit type arguments for `new C(x)` of a
  generic class (BACKLOG 137).

## Verification

- New `TestE2EGenericClassTwoSelfFields` matches Node. The
  two-self-field program exceeds 8 GB in 8 s at the previous commit, and
  now compiles at once (Linux x86-64, DeskMini).
- New `TestE2EGenericCallTemplateArgInference` matches Node. The same
  program overflows the stack at the previous commit.
- The generics E2E tests pass on macOS (Apple Silicon).
- `audio-data-copyTo.any.js` now reaches its compile error ("unknown
  class AudioData") through the WPT runner.
