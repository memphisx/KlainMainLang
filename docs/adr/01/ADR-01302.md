# ADR-01302: `cluster` as Node's lib/internal/cluster, with handles over the fork channel

- **Relations**: `Implements part of TDD-00230` (P3.1), `Supersedes ADR-00331`, `Extends ADR-01228`, `Extends ADR-01250`
- **Date**: 2026-09-30

## Context

The `cluster` module was compiled directly (`emit_cluster.go`,
`runtime_cluster.go`). `cluster.fork()` re-ran the program with
`KML_CLUSTER_WORKER_ID` set, and every worker bound the port itself with
`SO_REUSEPORT`. `cluster.workers` was an array rather than an object keyed
by id, `'online'` fired from a microtask rather than the worker's message,
and a worker's `cluster.worker` had no `process` or messaging. The fork
channel could not pass handles (`child_process.send(msg, handle)`), which
Node's cluster is built on.

## Investigation

Node's lib/internal/cluster/primary.js forks workers with `NODE_UNIQUE_ID`
set. child.js routes a worker's `net.Server.listen` to the primary
(`_getServer`, from net.js `listenInCluster`) with a `queryServer` message.
The primary answers in one of two ways:
- **round-robin** (`SCHED_RR`, the default outside Windows): it listens
  itself, accepts, and sends each connection to a worker as a `newconn`
  message carrying the socket's handle;
- **shared** (`SCHED_NONE`): it binds once and sends the listening handle
  to every worker.

Both forms need lib/internal/child_process.js's `setupChannel`:
`NODE_`-prefixed messages go to `'internalMessage'`, a handle travels as a
`NODE_HANDLE` message with its descriptor attached (libuv's `uv_write2` on
an IPC pipe, SCM_RIGHTS), and the receiver acknowledges it
(`NODE_HANDLE_ACK`/`NACK`). Until that acknowledgement, later sends queue
behind it.

## Decision

**Natives** (klainpool.c, `@link pool`):
- `ipcOpen(h)` marks a stream handle as an IPC pipe, whose reads use
  `recvmsg` and queue the descriptors that arrive;
- `ipcTakeFd(h)` takes the oldest queued descriptor (`uv_accept` of the
  pending handle);
- `ipcWriteHandle(h, buf, …, sendHandle, cb)` is a write whose first bytes
  carry `sendHandle`'s descriptor. A queued write keeps the descriptor until
  its first byte goes out. It returns `-ENOTSUP` on Windows.
- `tcpListenOpen(fd, cb)` listens on a received descriptor;
- `tcpBind(host, port, backlog)` creates a bound, listening socket nothing
  accepts on here (the shared handle);
- `tcpFileno(h)` returns the descriptor under a handle.

**Channel** (`lib/node/internal_child_process_channel.ts`): Node's
`setupChannel` and `handleConversion` with json serialization. One `Channel`
serves both ends: `ChildProcess` and the forked program's `process`. It
provides:
- internal messages and `'internalMessage'`;
- the handle queue until `NODE_HANDLE_ACK`;
- retransmission after `NACK`;
- messages held until a `'message'` listener exists;
- `net.Socket`, `net.Server` and native-handle conversion, where a sent
  socket is detached and closed once acknowledged.

Channel writes go straight to the native write queue, not through the
socket's `Writable`, so a message carrying a handle cannot overtake the ones
before it. The receiver pairs descriptors with `NODE_HANDLE` messages in
arrival order. `SendHandle` is `@types/node`'s union.

**net** (`lib/node/net.ts`):
- `_KmlNativeHandle` stands for Node's TCP/Pipe wrap objects. It holds a
  handle id or a received descriptor, and has an `onClose` hook and an
  owner.
- `listen(handle)` and `listen({ fd })` listen on a received or given
  descriptor.
- A worker's `listen` goes through the cluster hook (`listenInCluster`).
  The result is either a shared descriptor it accepts on or round-robin's
  faux handle, through which `_kmlOnConnection` receives the primary's
  connections. `address`, `close`, `ref` and `unref` follow that handle.

**cluster** (`lib/node/cluster.ts`): primary.js, child.js, worker.js,
utils.js, round_robin_handle.js and shared_handle.js in one module. Its
`cluster` is the primary's or, with `NODE_UNIQUE_ID` set, a worker's. Two
things differ from Node:
- the shared handle's close tells the primary through the handle's
  `onClose` hook rather than a monkey-patched `close`;
- round-robin's faux handle is a class rather than an object literal.

`setupPrimary`'s `exec` defaults to `process.argv[1]`, so forking works as
long as `exec` names this program. `process.execArgv` is `[]`.

**Deleted**: `emit_cluster.go`, `runtime_cluster.go`, the Windows cluster
fork IR, `ClusterWorkerType`/`IsClusterWorker`, the `cluster` virtual module
and its `KML_CLUSTER_WORKER_ID` start-up seed. Kept: `klain:http`'s
`http.listen({ workers })`, which now also shares the port with
`SO_REUSEPORT` in a Node cluster worker (`NODE_UNIQUE_ID` set).

## Implementation notes

Compiler fixes the port needed:
- `any + string` infers as a string. emitBinary already emitted a
  concatenation, so passing it as an `any` argument (`Buffer.from(…)`)
  boxed a raw pointer.
- Object spread copies only the source's present fields
  (`emitFieldPresentAt` on the field's `emitRecordGep` address, so a
  structural view of another layout keeps working). An absent optional
  field no longer overwrites an earlier property
  (`{ exec: x, ...settings }`).
- A class-typed dictionary or Map field (`NodeJS.Dict<C>`,
  `Map<K, C>`) re-resolves its value type to the finished class layout
  (`canonicalizeClassTy`). The field had captured `C`'s placeholder before
  `C`'s inherited fields existed.

## Side effects discovered

- Windows cannot pass handles yet (`WSADuplicateSocket` is the route), so a
  cluster worker's `listen` does not work there (cluster status row).
- A `dgram` socket cannot be sent as a handle, and one bound in a worker
  does not go through the primary.
- `serialization: 'advanced'` is not ported (fork status row).
- `examples/cluster/cluster.ts` assumed a worker ends on its own. A
  connected worker stays alive, in Node too (its `'disconnect'` listener
  keeps the channel referenced), so the example now calls
  `cluster.worker.disconnect()`.
- `TestE2EFsReadOptionsVariable` raced a callback `fs.readFile` against an
  awaited `fs.promises.readFile`, an order Node leaves open too; the test
  now awaits the callback read first.
- The `tests/` suite now takes about 23 minutes per `make test-par` shard,
  past its 20-minute cap (compile time, BACKLOG 113).

## Verification

Each program's output matches Node 24's:
- `tests/cluster_test.go`: primary state; messaging; cluster-level events
  and `workers`; `disconnect(cb)`; a net server under both scheduling
  policies; an HTTP server with `setupPrimary` args/silent and `kill()`.
  The `klain:http` workers test is kept, checking the response only.
- `TestE2EChildProcessForkSendHandle`: a `net.Server` passed to a child.
- Regression tests for the three compiler fixes:
  `TestE2EAnyPlusStringIsString`, `TestE2EObjectSpreadSkipsAbsentOptional`,
  `TestE2EClassDictFieldOfLaterClass`.

Verified on the Mac. The pool C was syntax-checked for Windows (mingw).
