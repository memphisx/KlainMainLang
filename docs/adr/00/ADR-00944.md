# ADR-00944: Array-valued Promise combinator results (Promise.all/.allSettled over Promise<T[]>)

- **Relations**: `Extends ADR-00940` (array reference semantics, TDD-00213); `Extends ADR-00073` (Promise combinators)
- **Date**: 2026-09-15

## Context

`Promise.all` over members that resolve to arrays (`Promise<T[]>[]` → `T[][]`)
produced invalid IR; `Promise.allSettled` over the same did too. Scalar-valued
combinators worked. Confirmed pre-existing on committed HEAD — two of the five
array-in-container bugs surfaced closing out TDD-00213.

Repros:

```ts
async function f(): Promise<number[]> { return [1, 2] }
await Promise.all([f(), f()])        // store ptr %{ptr,i64} — aggregate into a ptr slot
await Promise.allSettled([f(), f()]) // store {ptr,i64} null — null-init an array field
```

## Investigation

The result array of a combinator is built one element per slot with
`storeArrayElement` (`emit_promise.go`), which stores `elemTy.IR`-typed values.
For an array element type, `elemTy.IR` is `"ptr"` (the header-pointer model,
ADR-00940) but the resolved value is the `{ptr,i64}` aggregate — a 16-byte
aggregate stored into an 8-byte `ptr` slot, invalid IR. Both the already-resolved
loop and the may-suspend `emitTaskCombinatorAwaitEach` callback hit it.

`allSettled` builds a settlement record (`buildSettlement`) with `status`,
`value`, `reason` fields. The array `value` field is a header slot
(`storeArrayFieldHeader`), but the rejected side passes the literal `"null"` for
`value`, which `storeArrayFieldHeader` tried to box as `{ptr,i64}` →
`store {ptr,i64} null`, invalid.

## Decision

- New `storeArrayElementValue(outPtr, idxVal, val, elemTy)`: for an array element
  it stores `arrayReturnHeader(val)` (the shared/minted header pointer); every
  other type stores its plain value. Used by both Promise.all element-store
  paths.
- `buildSettlement`'s array-field store special-cases a `"null"` ref (the absent
  side of a settlement) to `store ptr null` rather than boxing.

## Implementation notes

`arrayReturnHeader` mints a header for a transient array and shares an existing
one, so a `T[][]` result keeps each inner array's identity. The result is typed
`ArrayOf(ArrayOf(T))`, so `rs[0]` reads back through the standard nested-array
element (header-pointer) path — no consumer-side change needed.

## Side effects discovered

None beyond the two fixes. `.race` (single value, not an array of arrays) and
scalar combinators were already correct and stay so.

## Verification

- `TestE2EPromiseAllArrayValues`, `TestE2EPromiseAllSettledArrayValues`
  (tests/async_test.go): all/allSettled over `Promise<number[]>`, fulfilled and
  rejected members, both the already-resolved and genuinely-suspending
  (`await delay()`) paths.
- Regression: `go test -run 'TestE2E(PromiseAll|PromiseRace|PromiseAllSettled|
  PartANonSuspending|AwaitMemberAfterCombinator|SamePromiseTwice|
  AllSettledMemberReuse)'` green on macOS arm64 (Apple Silicon M4).
- `clang -O0 -S -emit-llvm -x ir` clean on both repros.
