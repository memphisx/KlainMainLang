# ADR-01769: Extra method arguments in JavaScript, and generator `arguments` counts

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- In a `.js` file, `o.m(1, 2)` on a method declared `m(a)` (or with no parameters) was a compile error ("expects 1 argument(s), got 2"), at both the instance and the static call site. JavaScript evaluates the extra arguments and ignores them. Free functions already accepted them.
- A generator reading `arguments` took the count of declared parameters passed from the thread-local `@__kml_argc`. Its body first runs at its first `next()`, so it read whatever an earlier, unrelated call had left there: `f(1); g(1, 2).next()` reported three arguments.

## Decision

- `dropExtraArgs` (js lane, no rest parameter, no spread) evaluates every argument left to right. Declared ones go into temporaries, except function literals, which keep their contextual type and have no side effects. Extra ones are evaluated only for their side effects. The call then gets the declared arguments. Strict TypeScript still rejects the call, as tsc does.
- `synthesizeArgumentsObject` does not read `@__kml_argc` in a generator. Every declared parameter counts.

## Consequences

- `TestE2EJSFileMethodCallArgumentCounts` covers both.
- A generator called with fewer arguments than it declares reports `arguments.length` as the declared count. The missing ones read `undefined`. It used to read a stale count instead.
