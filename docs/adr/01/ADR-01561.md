# ADR-01561: The checker types optional chains; a `T | null` link keeps its null

- **Relations**: Extends ADR-01558, TDD-00230
- **Date**: 2026-10-10

## Context

The checker left every link of an optional chain (`a?.b`, `a?.[i]`,
`f?.(x)`, and the links after them, `a?.b.c`) unanswered, so codegen's own
inference typed them. Codegen also builds copies of a chain's links while
emitting it (the `?.` resolved, the receiver bound to a temporary), which
the checker never saw.

Separately, a link whose property is `T | null` folded the chain's
`undefined` into its null:

```ts
class Row { inner: Inner | null = null }
const k = new Row()?.inner   // Node: null; ours: undefined
```

## Decision

- The checker types an optional chain as tsc's
  `checkPropertyAccessChain`/`checkElementAccessChain`/`checkCallChain` do:
  a `?.` link reads its receiver with null and undefined removed, a link
  after one reads its receiver's non-optional type, and a link's type
  gains `undefined` where the chain can short-circuit. A link that
  continues a chain is checked for nullness against the non-optional type,
  so `a?.b.c` reports nothing. `ChainNonOptional` exposes a link's type
  without the chain's `undefined`.
- Codegen records each copy of a chain link it builds against the link it
  copies. The checker-side mapping answers a copy that is still in an
  optional chain as the original, and one that is not as the original's
  non-optional representation.
- A chain link the checker types with the chain's `undefined` is
  represented as `optionalCallResultType` of its read: the read's value or
  undefined.
- That result is three-state (`optionalFieldType`) when the read is
  itself `T | null`: a null read stays null, a short-circuit is undefined.
  Both chain emitters (`emitOptionalMember`, `emitNullGuardedExpr`) store
  the read through `toThreeState`.
- The mapping memoizes `ExprType` within one outermost query: its
  receiver rules otherwise retyped a call chain's receivers once per rule
  and link (a 24-link `.then` chain took minutes).

## Side effects discovered

- `TestE2ENullDerefUncaughtExitsCleanly` compiled `(r?.name).length`,
  which tsc rejects (TS2532: the parentheses end the chain, so the
  receiver is `string | undefined`). The checker now rejects it too. The
  test reads `(r?.name)!.length`, which still dereferences undefined at
  run time.

## Verification

- Mac (Apple Silicon): checker unit tests (`TestTypeOf` chain cases match
  tsc 5.9.3 `--strict`); `TestE2EOptionalChainNullLinkStaysNull`, the
  optional-chain, nullish and non-null suites, and
  `TestE2EDeepMethodChainCompilesInLinearTime`, with the checker-side
  mapping deciding and without.
