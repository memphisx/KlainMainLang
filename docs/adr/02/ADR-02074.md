# ADR-02074: Piping into an HTTP/2 compat response

- **Relations**: Implements TDD-00230
- **Date**: 2026-11-24

## Context

`test-stream-pipeline-http2` grew to 2 GB and crashed. The test pipes an
endless readable into an HTTP/2 request, and the server pipes each request
into its response (`pipeline(req, res)`); Node finishes it at once. A
finite version hung: the client never received a response.

## Investigation

- `pipeline` and `pipe` write to and end a destination through
  `_kmlWrite`/`_kmlEnd`. `Writable` implements them; the base `Stream`
  answers `true` and does nothing. `Http2ServerResponse` extends `Stream`
  and did not override them (HTTP/1's `OutgoingMessage` does), so
  `req.pipe(res)` dropped every chunk and never ended the response. The
  endless upload then grew without the echo that ends it.
- With that fixed, a peer resetting the stream left the server's
  `pipeline` succeeding where Node's fails with `ERR_STREAM_PREMATURE_CLOSE`,
  and its callback ran before the response finished:
  - Node's `eos` listens for `'aborted'` on a stream that will not emit
    `'close'` itself and has a boolean `aborted` (the compat request,
    built with `autoDestroy: false`); ours did not.
  - For a writable without writable state, Node's `eos` waits for its
    `'finish'` unless it is destroyed, not writable or ended
    (`isWritable`), and reads `writableFinished` from the stream; ours
    took it as finished at once.
- `Http2Stream._write` completed each write as it was queued. Node
  completes it when nghttp2 has consumed its bytes into DATA frames, so
  a peer that stops reading stops the writer through `write()` returning
  false.

## Decision

- `Http2ServerResponse` implements `_kmlWrite`/`_kmlEnd` with `write` and
  `end`.
- `finished` (eos) listens for `'aborted'` when `!willEmitClose` and the
  stream's `aborted` is a boolean, and, for a writable without writable
  state, adds Node's legacy `'end'`/`'close'` listeners, finishes at once
  only when `legacyNotWritable`, and reads `writableFinished` from the
  stream.
- `Http2Stream._write` records each write's end offset; after each flush
  the session completes the writes whose bytes nghttp2 has sent
  (`h2Queued`), for the streams with writes outstanding (`_kmlWriting`).

## Consequences

- `test-stream-pipeline-http2` passes; the endless upload runs in 25 MB.
- A finite echo, `req.pipe(res)`, a reset mid-upload and HTTP/1
  `pipeline(src, res)` print the same output and event order as Node.
- Verified on Node304 (Linux x86-64).
