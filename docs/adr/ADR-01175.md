# ADR-01175: The builtin modules compile in the strict lane under `-compat=js`

- **Relations**: `Extends [ADR-01170](ADR-01170.md)`, [TDD-00022](../tdd/TDD-00022.md)
- **Date**: 2026-09-26

## Context

A `-compat=js` program that required `http` failed to compile: `a number
has no method 'trim'`, at a line of the library's own TypeScript. The lane
decides how code generation reads the program: implicit `any`, untyped
object literals as dynamic objects, bindings widened across kinds, and
parameter types inferred from call sites. That setting also applied to
the builtin modules written in TypeScript (`net`, `http`, `stream`, …),
which are strict TypeScript. The same program's own untyped read
`server.address().port`, on `AddressInfo | string | null`, was a compile
error where JavaScript reads the property at run time.

## Investigation

- `Emitter.compatJS()` read the program-wide option at every one of its
  44 call sites. The js lane's whole-program passes
  (`jsCollectCtorParamTypes`, `jsCollectFuncParamTypes`,
  `jsCollectProtoCtors`, the module-scope `crossTypeWidenedBindings`) read
  every top-level statement, the library's included.
- The resolver already knows each merged top-level statement's file.
- JavaScript's `x.port` on such a value: the object's field, `undefined` on
  a string, a TypeError on null or undefined (`Cannot read properties of
  null (reading 'port')`).

## Decision

- The resolver records the library's top-level statements
  (`Program.LibStatements`). Code generation marks registering or emitting
  one (`libScope`), and `compatJS()` is false inside it; the js lane's
  whole-program passes read only the program's own statements.
- A property read on a union whose one object member declares the property
  reads at run time: that member's field when the box holds an object,
  JavaScript's TypeError on null or undefined, else the primitive's
  property. The strict lane's checker rejects the read first, as tsc does.

## Implementation notes

`ast/nodes.go` (`LibStatements`), `resolver/resolver.go`,
`codegen/llvm/emitter.go` (`libScope`, `userStatements`),
`emit_classes.go`, `emit_exprs_vardecl.go`, `emit_exprs_member.go`
(`emitUnionSoleObjectMemberRead`).

## Side effects discovered

- `this` inside an untyped `function` callback (`server.listen(0,
  function () { this.address() })`) is a number in the js lane; JavaScript
  passes the emitter as the receiver. The Node suite's largest js-lane
  bucket (BACKLOG).

## Verification

Mac (Apple Silicon), against Node v24.19: `tests/jsmode_test.go`
(`TestCompatJSProgramUsingHTTP`, `TestCompatJSUnionSoleObjectMemberRead`).
