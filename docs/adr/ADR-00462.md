# ADR-00462: ambient namespace members; construct signatures in object types

- **Relations**: Extends [ADR-00450](ADR-00450.md), [ADR-00448](ADR-00448.md)
- **Date**: 2026-08-29

## Context

Namespace bodies in the corpus carry ambient members (`export declare var
x;` — the `ambientInsideNonAmbient` family behind much of the remaining
`unsupported namespace member` bucket), and object type literals carry
construct signatures (`{ new(): Foo }`, the `assignmentCompatOnNew`
shape) that only the prefix `new () => T` and interface forms handled.

## Decision

- A `declare` namespace member is parsed by the existing top-level
  ambient skipper (`parseAmbientDeclaration`) and erased; its depth-0 `}`
  stop condition already makes it safe inside a brace body.
- A `new (…): T` member in an inline object type erases its `new` and
  rides the ADR-00448 call-signature path (alone → the function type;
  mixed → clean rejection), matching the interface treatment.

## Trade-off, disclosed

The four-ADR batch regenerated in this oracle window (00459–00462) moved
match-accepts 1444 → 1534 (+90) while false-accepts rose 717 → 782 —
ambient/erasure semantics also accept ~65 cases whose only TS errors are
strict-mode rules this compiler doesn't model. Aggregate agreement is
flat (5134 → 5131); kept for the genuine coverage gain.

## Verification

Mac. `tests/namespaces_test.go` additions (`declare` members erased
beside real members; construct-signature E2E) pass; parser + namespace +
object-type batches green. Node oracle unchanged (40).
