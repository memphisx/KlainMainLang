# ADR-00520: `klain:tty` `readKey(timeoutMs)` — a polling raw-key read

- **Relations**: `Extends ADR-00518` (terminal primitives). Enables `klain:tui` live-refresh loops ([ADR-00519](ADR-00519.md)/TDD-00150).
- **Date**: 2026-08-30

## Context

ADR-00518 shipped `klain:tty` `readKey()` — one blocking read of fd 0's whole
key burst. That is exactly right for an input-*driven* TUI (redraw on a
keystroke), but a self-refreshing dashboard (redraw on a timer *and* on input —
a live process/resource monitor) needs to wait for a key only up to some
deadline and otherwise wake to repaint. With a purely blocking read the loop can
only advance when a key is pressed, so a clock or a live counter never ticks.

## Decision

Give `readKey` an optional timeout: **`readKey(timeoutMs)`** waits at most
`timeoutMs` milliseconds for a keystroke via `poll(POLLIN)` on fd 0, returning
the key's byte-burst string when one arrives and the empty string `""` when the
timeout elapses first. The no-argument `readKey()` is unchanged — it blocks
until a key arrives (the C shim treats a negative timeout as "block forever", and
codegen passes `-1` for the zero-arg form). The loop shape a live app writes is:

```ts
while (running) {
  render(view(state))                 // repaint
  const key: string = readKey(1000)   // wake on a key OR after 1s
  if (key === "q") running = false
  else if (key !== "") handle(key)    // "" == the tick, no key
}
```

## Implementation notes

- `emit_tty.go`: the shim's `__kml_tty_read_key` gains an `int timeout_ms`
  parameter and `poll()`s when it is `>= 0` (`<poll.h>` added); codegen for
  `readKey` accepts 0 or 1 argument, passing `-1` (block) or the truncated
  `i32` millisecond value. The extern decl is now `ptr @__kml_tty_read_key(i32)`.
- No new runtime dependency — `poll` is libc on both dev platforms.

## Verification

- `tests/tty_test.go` `TestE2ETtyReadKeyTimeout`: over a pipe, `readKey(1000)`
  returns the buffered byte and a subsequent `readKey(50)` returns `""` at EOF,
  proving both the ready and timed-out paths and that neither blocks forever.
- Existing `readKey()` no-arg tests still pass (the `-1` block path).
- Verified on macOS (Apple Silicon). `poll` is POSIX; the Linux path is the same
  libc call, not yet re-run there.
