# ADR-01290: `path` as Node's lib/path.js in TypeScript

- **Relations**: `Implements part of TDD-00230` (P3.1), `Supersedes ADR-00722`, `Supersedes ADR-00723`
- **Date**: 2026-09-30

## Context

`path` was compiled directly. The posix algorithms were hand-written IR,
and the win32 ones a C port behind a sidecar. `path.posix` and
`path.win32` could only be called through (`path.win32.join(…)`): they
were not values, and `path/posix` and `path/win32` did not exist.

## Decision

- **Modules.** `lib/node/path.ts` is Node's lib/path.js. It is converted
  mechanically: primordials become method calls, and each flavour's
  methods are typed functions (`win32_join`, `posix_join`, …) gathered into
  the `win32` and `posix` objects, which reference each other. The module's
  own functions call the host's flavour. `path_posix.ts` and `path_win32.ts`
  are `path/posix` and `path/win32`.
- **Compiled path deleted.** The `path` dispatch and its type cases go. The
  compiled resolve stays, as `url.pathToFileURL`'s (emit_path.go,
  runtime_path.go, path_win32.go).
- **Codegen: function fields.** Calling a plain object's function-typed
  field is dispatched before the methods called by name. So `{ join: … }`,
  and a function field named `map` or `split`, call their own function
  instead of `Array.prototype.join`.
- **Resolver: `typeof ns.x`.** `typeof ns.x` through a namespace import
  names that module's `x`, as `ns.T` already did. A `typeof` query finds a
  module global by its mangled name as well as its source name.

A non-string argument held in `any` is converted to a string at the call,
because the parameters are typed `string`. Node would throw
`ERR_INVALID_ARG_TYPE` there. `matchesGlob` is not ported (Node's glob
matcher).

## Verification

On the Mac (Apple Silicon), outputs match Node v24.19.0:
`tests/path_port_test.go` (both flavours over roots, UNC shares, drive
letters, dotfiles and trailing separators), and the 43 existing tests that
use `path`.
