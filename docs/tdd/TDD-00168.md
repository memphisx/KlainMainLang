# TDD-00168: `async_hooks` — `AsyncLocalStorage` (context propagation over the fiber model)

- **Status**: Partially Implemented
- **Date**: 2026-09-03

Stages 1–4 shipped: the AsyncLocalStorage instance surface
(`run`/`getStore`/`exit`/`enterWith`/`disable`) with real context propagation
across `await` (the store lives in the coroutine task struct) and spawn
inheritance ([ADR-00678](../adr/ADR-00678.md)); timer-callback propagation — a
`setTimeout`/`setInterval` inside `run(...)` carries the context to its fire
([ADR-00679](../adr/ADR-00679.md)); and static `AsyncLocalStorage.bind(fn)` plus
`AsyncResource` (`runInAsyncScope`) ([ADR-00680](../adr/ADR-00680.md)).
`AsyncLocalStorage.snapshot()` is a clean rejection — its runner is fully
generic, needing generic first-class closures this compiler lacks. Stage 5
(`.then`/EventEmitter-listener propagation, exception-safe `run` restore, the
diagnostics_channel store-binding integration) and `snapshot()` on a future
generic-closure foundation are the remaining follow-ups.

## Context

`async_hooks` is ~52 Node oracle files blocked, the second-largest
unimplemented-module gap ([NODE-GAP-ANALYSIS](../testing/NODE-GAP-ANALYSIS.md)).
The module is really two very different APIs:

- **`AsyncLocalStorage`** — the modern, recommended API (request-scoped context,
  tracing, propagating a "current user"/"current transaction" through an async
  call tree). ~6 corpus files; the piece people actually use. It is the
  intended backend for `diagnostics_channel`'s already-shipped-but-stubbed
  `channel.bindStore`/`runStores` (`emit_diagch.go:119` rejects with "the store
  bindings ride AsyncLocalStorage, which does not exist").
- **Low-level `createHook`** (`init`/`before`/`after`/`destroy`),
  `executionAsyncId`/`triggerAsyncId`, GC-tracked `AsyncResource` lifecycle —
  ~30 corpus files, most tied to V8 promise-hooks, GC finalization, the
  inspector, and `trace_events` (`destroy-on-gc`, `promise-triggerid`,
  `correctly-switch-promise-hook`, the `inspector-*`/`trace-events-*` families).

Scoped now because this compiler already owns its async scheduler (a real fiber
per suspending async call, TDD-00083/00084/00088), so the hard part of ALS —
propagating context across an `await` — is nearly free given how tasks are
represented. It also unblocks the `diagnostics_channel` store bindings.

## Design

### What is in scope, and what is a faithful impossibility

**In scope:** `AsyncLocalStorage` in full — `run`, `getStore`, `exit`,
`enterWith`, `disable`, static `bind`, static `snapshot` — with real
propagation across `await`, timer callbacks, and spawned tasks; and
`AsyncResource` limited to `runInAsyncScope` (built on the same context frames).

**Out of scope (documented faithful impossibility):** `createHook`'s
`init`/`before`/`after`/`destroy` tracing, `executionAsyncId`/`triggerAsyncId`
numeric-id lifecycle, GC-`destroy` tracking, the promise-hook switch, and the
`inspector`/`trace_events` integrations. A statically-compiled runtime has no
per-async-resource, GC-tracked async-id lifecycle and no V8 promise-hook — these
APIs observe engine internals that do not exist here, not merely awkward-to-build
ones. They stay clean rejections. (This is the same line TDD-00061 drew against
the dynamic object model: the corpus assertions probe an engine, not a
behavior.) `AsyncResource` is supported only for its context-carrying use
(`runInAsyncScope`), not its hook-firing use.

### Representation — context lives in the task, not a global

The crux. A **context frame list** is an immutable, singly-linked, prepend-only
list of `{ i64 alsId, i64 value, ptr next }` nodes (`value` is a NaN-boxed `any`
word, D1/TDD-00156 — so a `number`/`boolean`/`string`/object store all fit one
8-byte slot with no per-store heap box). "The current context" is a single
pointer to the head of that list. Frames are never mutated, so a head pointer
can be freely shared/copied — which is exactly what `snapshot`/`bind` and
task-spawn inheritance need.

The current head is stored **per task**, in a new field on the coroutine task
struct (`runtime_task.go:33-48` — add field index 12, bump `taskStructBytes`
256→264 and every hand-spelled 12-field IR literal, grep
`{ ptr, ptr, ptr, i64, ptr, ptr, ptr, ptr, ptr, ptr, ptr, i64 }`), plus a
top-level fallback global `@__kml_root_async_ctx` for code running outside any
task. A tiny accessor pair `__kml_async_ctx_get()/__kml_async_ctx_set(head)`
reads/writes `@__kml_current_task`'s field 12 when a task is current, else the
root global.

**Why this makes `await` propagation nearly free:** a parked task's struct
persists across the suspension, and the scheduler restores `@__kml_current_task`
to that task before resuming it (`runtime_task.go:576/859`). So context read
after an `await` is the same task's field 12 — no per-resume save/restore is
needed anywhere. The whole difficulty of ALS in other runtimes (threading
context through the microtask queue) is absorbed by the task already being the
unit of suspension.

### Methods (all frame-list operations on the current head)

- `getStore()`: walk the current head for a node with this instance's `alsId`;
  return its `value` (or `undefined` when absent/disabled). Typed as
  `AsyncLocalStorage<T>` → `getStore(): T | undefined` (unbox the `any` word to
  `T`); an untyped store is `any`.
- `run(store, cb, ...args)`: `prev = head; set head = {alsId, store, prev};
  try { return cb(...args) } finally { set head = prev }`. Synchronous
  save/restore over the current context; if `cb` awaits, the task parks with the
  new head already in field 12, so the awaited continuation still sees `store`,
  and the `finally` restores `prev` only when `cb`'s frame truly unwinds.
- `exit(cb, ...args)`: same, but the pushed frame carries a "cleared" marker for
  this `alsId` (getStore skips it), so `getStore()` is `undefined` inside.
- `enterWith(store)`: push a frame but **do not** restore — it persists for the
  rest of the current task's execution (Node semantics).
- `disable()`: mark the instance id disabled (getStore returns `undefined`
  regardless of frames).
- static `bind(fn)`: capture `head` now; return a wrapper closure that sets
  head=captured around a call to `fn`, restoring after. Throw
  `ERR_INVALID_ARG_TYPE` for a non-function argument.
- static `snapshot()`: capture `head`; return `(cb, ...args) =>` run `cb` under
  the captured head.

### Propagation surfaces (staged)

1. **`await` + task spawn.** Spawn inheritance is one copy: at
   `__kml_spawn_task` (`runtime_task.go:399`, where `%prev` — the parent task —
   is already loaded) the child's field 12 is initialized from the parent's, so
   a child async task inherits the spawner's context. `await` needs nothing
   (above).
2. **Timer callbacks.** setTimeout/setInterval/setImmediate must capture the
   current head at *schedule* time (a new 5th field on the timer-queue entry,
   `emit_timers.go:335`) and set/restore it around the three closure fire sites
   (`__kml_timer_drain` ~`:530`, `__kml_timer_fire_next`, `__kml_timer_tick`).
   This is what makes `als.run(store, () => setTimeout(() => als.getStore()))`
   work — the common HTTP-context idiom.
3. **(Fidelity follow-ups, ranked)** promise `.then` reactions and EventEmitter
   listener dispatch capturing/restoring context, for full transparency. Not
   required by the core ALS tests; staged after the above.

### Module wiring (mirrors `diagnostics_channel`, ADR-00420)

- `resolver/virtual_modules.go`: marker `"async_hooks": "asynchooks__kml_builtin"`
  (+ `node:` alias auto-added), member set `{AsyncLocalStorage, AsyncResource}`.
- `resolver/rename.go` (~`:585`): bind `AsyncLocalStorage`/`AsyncResource` as
  identity constructors so `new AsyncLocalStorage()` routes through the generic
  `NewExpression` (like `sync__kml_builtin` `Channel`).
- `codegen/llvm/types.go`: `IsAsyncLocalStorage` flag + `AsyncLocalStorageType(T)`
  helper (carry the store element type `T` in `ElemType`).
- `codegen/llvm/emit_classes.go:1863`: `new` dispatch branch.
- `codegen/llvm/emit_call.go:420` / `emit_exprs_member.go:637`: method/member
  dispatch on `IsAsyncLocalStorage`.
- New `codegen/llvm/emit_asynchooks.go` (emitters) + `runtime_asynchooks.go`
  (the frame ops + accessors, `ensureAsyncLocalStorageRuntime`, `usedAsyncLocalStorage`).
- Once landed, wire `diagnostics_channel`'s `bindStore`/`runStores`
  (`emit_diagch.go:119`) onto the same frames.

### Stages (ordering, not dropping)

1. Synchronous ALS core: representation + `run`/`getStore`/`exit`/`enterWith`/
   `disable` over the per-task/root head. Passes the sync corpus files
   (deep-1000-nesting, exit-no-leak).
2. Cross-`await` + spawn inheritance (the field-12 copy). Passes the async
   `run` + `getStore`-after-`await` files.
3. Timer-callback propagation (capture at schedule, restore at fire).
4. static `bind`/`snapshot` + `AsyncResource.runInAsyncScope`.
5. `diagnostics_channel` store-binding integration; promise/EventEmitter
   propagation fidelity if the corpus rewards it.

## Open questions

- **Store typing.** `AsyncLocalStorage<T>` (typed store, `getStore(): T |
  undefined`) is the faithful-to-this-compiler choice; the untyped corpus tests
  fall back to `any`. Confirm the NaN-boxed `any` word round-trips a `number`
  store (`run(123, …)`) and an object store through `getStore()` without a
  strict-mode member-access rejection on `getStore().field`.
- **Frame-list vs. flat map per task.** A prepend-only immutable list is simplest
  and makes snapshot/bind O(1); a program with very many ALS instances pays O(n)
  `getStore`. Acceptable for V1 (instances are few); revisit only if a corpus
  file stresses it.
- **`exit` representation.** A "cleared" sentinel frame vs. rebuilding the head
  without this `alsId` — the sentinel is O(1) and matches Node's stack model;
  confirm it composes with a later `run` of the *same* instance inside the
  `exit`.
- **Whether promise-reaction/EventEmitter propagation is worth Stage 5** — decide
  from the post-Stage-4 oracle histogram, not upfront.
