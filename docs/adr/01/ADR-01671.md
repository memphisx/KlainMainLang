# ADR-01671: A destroyed IncomingMessage emits 'error' only to a listener

- **Relations**: Implements TDD-00230
- **Date**: 2026-10-17

## Context

When a client closes a connection whose request the server has not finished answering, the server destroys the request with `ECONNRESET: aborted`. Our `IncomingMessage._destroy` passed that error to the stream's destroy callback unconditionally, so the request emitted `'error'`. With no listener attached, the program died with "Uncaught: aborted". Any server whose client gives up early, for example a fetch with `AbortSignal.timeout`, could crash this way. Node keeps a compatibility rule in `IncomingMessage`'s `onError`: the error is emitted only when an `'error'` listener is attached.

## Decision

`_destroy` routes both of its callback paths through `onDestroyError`. It calls `cb()` when the request has no `'error'` listener, and `cb(err)` when it has one, as Node's `_http_incoming.js` does.

## Side effects discovered

None.

## Verification

- `TestE2EFetchTimeoutSignalInHandler`: a handler's fetch to a slow upstream server times out. The program prints `err TimeoutError`, the same as Node 24 on Mac.
