# ADR-00573: forEach passes the collection as the callback's 3rd argument

- **Relations**: Extends ADR-00053
- **Date**: 2026-09-01

## Context

`Array.prototype.forEach` and `Map.prototype.forEach` invoked their callback with
only the leading arguments — `(elem, index)` and `(value, key)` — dropping the
trailing `array`/`map` argument real JS also passes. A callback written as
`(v, k, map) => …` received nothing for its 3rd parameter. Disclosed as a
`Map.forEach` caveat.

## Decision

Pass the collection as the 3rd argument when the callback's arity is ≥ 3:

- **Array.forEach**: the source array as a `{ptr,i64}` value aggregate over the
  same backing data (the array-value shape every HOF already produces) — element
  reads through it are live; the length is a snapshot, the same HOF-callback
  array narrowing the reference-semantics caveat already documents.
- **Map.forEach**: the map object itself (the same `mapPtr` being iterated), so
  `.size`/`.get()` inside the callback observe the live map.

A callback declaring fewer parameters still receives only the leading ones
(arity-driven, unchanged) — so no existing 1-/2-parameter callback is affected.

## Side effects discovered

None. The change is guarded on `cb.arity() >= 3`; `Set.forEach` keeps its own
`(value, value, set)` shape (a separate ADR-00053 quirk) and is untouched here.

## Verification

New `TestE2EArrayForEachThirdArrayArg` (`a.length`/`a[i]` through the 3rd arg)
and `TestE2EMapForEachThirdMapArg` (`mm.size`/`mm.get(k)`), plus the existing
array/map/set forEach suites. Built and verified on Mac (Apple Silicon).
