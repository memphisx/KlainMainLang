# ADR-00669: Legacy `url.parse` — the first module-only member of a hybrid reexport module (TDD-00165 Stage 4)

- **Relations**: Implements TDD-00165 (Stage 4); Extends [ADR-00668](ADR-00668.md)
- **Date**: 2026-09-03

## Context

Stages 1–3 wired up the *primary* exports of the Web-global-backed modules (the
spec-identical globals). Stage 4 is the genuinely module-only surface — members
with no same-named global. The first and highest-value one is Node's legacy
`url.parse(urlString)`, which returns a legacy `Url` object (`protocol`/`auth`/
`host`/`port`/`hostname`/`hash`/`search`/`query`/`pathname`/`path`/`href`) —
distinct from the WHATWG `URL`.

## Decision

Make `url` a **hybrid** reexport module: its primary exports (`URL`/
`URLSearchParams`) stay global reexports (Stages 1–3), and a new
`moduleFunctionMembers` table registers its module-only functions (`parse`),
which dispatch via the module marker exactly like `querystring.parse`.

Resolver (`resolver/resolver.go`, reexport branch rewritten to a hybrid):

- A **named** import of a function member (`import { parse } from 'url'`) records
  an ordinary `builtinMemberRef{marker, "parse"}`, so the rename pass synthesizes
  `<marker>.parse` and codegen dispatches it.
- Because the module now has function members, a **namespace** import
  (`import * as url from 'url'; url.parse(…)`) and a **default** import
  (`import url from 'url'`) bind the marker instead of being rejected. Reexport
  primaries remain unreachable through the namespace (they are globals, not marker
  members) — a documented asymmetry; use a named import or the global.
- A reexport-primary default (`events` → `EventEmitter`) still routes through the
  named-export path; the two default meanings don't collide because only one of
  `defaultReexportName` / `moduleFunctionMembers` is set per module.

Codegen: `emitUrlParse` parses with the same libcurl URL API `new URL()` uses,
builds the WHATWG object via the shared `deriveURLFieldsIntoObject`, then remaps
its components into the legacy `Url` shape (`LegacyUrlType`) — deriving `auth`
(`user[:pass]`), `path` (`pathname`+`search`), and `query` (`search` minus the
leading `?`).

## Scope and divergences (Stage 4a)

- Parses **absolute** URLs faithfully; on a malformed/relative input it throws a
  catchable `Invalid URL` like `new URL()`, rather than Node's never-throw lenient
  object. Documented as the remaining Stage-4 follow-up (a lenient legacy parser).
- An absent component is `""`, not Node's `null` — the same representation the
  existing WHATWG URL object already uses (a consistent, documented divergence).
- `slashes` and the `parseQueryString`-object form of `query` are not produced
  yet.

## Implementation notes

- `virtualModuleMembers` for a reexport module is built as a **fresh union** of
  the reexport primaries and the function members — never the shared
  `globalReexportModules` map, so registering `parse` cannot leak into the
  reexport-vs-function distinction.
- `emitStrNonEmpty` distinguishes a present component from the `""` used for an
  absent one, driving the `auth` derivation.

## Verification

E2E tests in `tests/node_core_modules_test.go`: `url.parse` via named, namespace,
and `node:url` default imports with a full field check against Node's output; the
hybrid `{ URL, parse }` coexistence; the relative-URL throw; and the still-unbuilt
extras (`url.format`, `perf_hooks.PerformanceObserver`) keeping their rejection.
`go test` over the import/module/url/rename suites green (Mac); `go vet ./...`
clean.
