# ADR-00438: klain:webview Stage 2 — bind/unbind, page↔native IPC, served SPA

- **Relations**: Implements [TDD-00142](../tdd/TDD-00142.md); Extends [ADR-00437](ADR-00437.md), [ADR-00425](ADR-00425.md)
- **Date**: 2026-08-28

## Context

Stage 2 is the point of the whole feature: a page button calling straight into
typed native code. `webview_bind("f", fn, arg)` injects `window.f(...)` into
every page; calling it returns a page-side Promise and invokes `fn(id, req,
arg)` on the GUI thread with `req` = the JSON array of arguments.
`webview_return(w, id, status, result)` settles the promise.

## Investigation

The `{fp, env}` closure ABI (`buildBuiltinClosure`, `emit_promise_new.go:245`)
and the fork-IPC message trampoline (`runtime_ipc.go:169` — copy a C string to a
kml string via `__kml_str_alloc`+`memcpy`+NUL, then `call void %fp(ptr %ep, ptr
%mstr)`) are the exact idioms Stage 2 needs. `emitFsGuarded`
(`emit_fs_async.go:63`) is the setjmp/catch scaffold for turning a callback
throw into a rejected promise. `emitCBCall` (`emit_func.go:2610`) already emits
the closure invocation for any callback Type.

## Decision

- `w.bind(name, cb)` allocates a retained node `{ ptr w, ptr closureHdr, ptr
  next }`, links it into the handle's `boundListHead`, and registers a per-bind
  C-ABI trampoline `void @__kml_wv_bind_N(ptr id, ptr req, ptr env)` with the
  node as `arg`. The node both carries the trampoline's env AND retains the
  closure so it is never freed (manual mode) / stays reachable (gc mode).
- The trampoline copies `req` to a kml string, invokes the user closure under an
  `emitFsGuarded` frame, and on success calls `webview_return(w, id, 0, result)`
  with the returned JSON string (a void/non-string return resolves JSON `null`);
  a throw calls `webview_return(w, id, 1, "…")` — a rejected page promise.
- `unbind` maps to `webview_unbind`.
- Served-SPA recipe (`examples/webview/spa.ts`): `http.createServer` serves
  `dist/` in a Worker thread (which owns its own event loop), the main thread
  navigates and enters `run()`.

## Implementation notes

- The V1 bind contract is string-JSON-in / string-JSON-out; `JSON.parse`/
  `JSON.stringify` already exist, so no automatic typed marshaling is needed.
- The rejection result is a fixed JSON string in V1 (`"native handler threw"`);
  extracting `error.message` is a later refinement.
- A named-function callback is wrapped into a `{fp, env=null}` header so the
  trampoline has a uniform closure to call.

## Side effects discovered

Event-loop coexistence is resolved by contract, not machinery: bound callbacks
may use every synchronous facility (fs/spawnSync/crypto/JSON); anything
event-loop-shaped runs in a Worker. Loop fusion (page-tick timers on the GUI
thread) is TDD-00142 Stage 3, deliberately out of this scope.

## Verification

- macOS (windowed, by hand): the page calls `window.finish(["hello"])`, native
  receives the JSON args, `terminate()`s the loop, `run()` returns — asserted by
  `TestE2EWebviewSmoke` (gated behind `KML_WEBVIEW_SMOKE=1`, run manually).
- `examples/webview/inline.ts` (counter + `fs.readdirSync` file browser) and
  `examples/webview/spa.ts` (Worker serves `dist/`) both compile and launch;
  `curl` against the SPA worker returns the served page while the window is up.
- Compile-tier `TestE2EWebviewBindCompiles` covers bind/unbind/JSON.
- Linux: compile-tier only, not yet run.
