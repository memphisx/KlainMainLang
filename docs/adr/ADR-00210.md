# ADR-00210: `let`/`const`/`var` scope semantics — function-scoped `var`, block-scoped redeclaration early-errors

- **Relations**: `Implements TDD-00070`. `Extends ADR-00209` (which added the `const`-initializer and strict binding-name early-errors this builds directly on).
- **Date**: 2026-08-18

## Context

`docs/status`'s variable-declarations row carried a long-standing caveat: *"No `let`/`const`-vs-`var` scoping distinction — no TDZ/hoisting or redeclaration checks (all three are mutable allocas)."* A direct audit (Mac, Apple Silicon M4) showed that caveat had drifted out of date and needed both correcting and closing. Three of the four things it claimed were missing already worked:

- `const` reassignment is rejected (`Symbol.IsConst`, [ADR-00209](ADR-00209.md) completed the initializer half).
- `let`/`const` are effectively block-scoped — `emit_stmts.go`'s `*ast.BlockStatement` case pushes/pops a scope, so sibling blocks are independent.
- A module-top-level duplicate (`let x; let x;`) is rejected in `mangleFileDecls`.

The four real remaining gaps, each with a verified repro:

1. **`var x = 1; var x = 2;` at top level was wrongly rejected.** `mangleFileDecls`'s duplicate check was kind-agnostic; real JS permits re-declaring the same `var`/`function`.
2. **Block-scoped `let y; let y;` inside a function was not caught** — it compiled and used the second value, because the redeclaration check only existed at module top level.
3. **`var` was not function-scoped** — `{ var x = 5 } console.log(x)` failed with `undefined variable 'x'`; `var` was treated as block-scoped, identical to `let`.
4. **No true TDZ** — a `let` used before its declaration reported a generic `undefined variable`. Behaviorally this already rejects, so it is message quality rather than a wrong result.

## Investigation

- **Top-level duplicate check** (`resolver/resolver.go`): `mangleFileDecls` maps each top-level declaration to a file-private mangled name and rejected any repeated name. `declRefsOf` already unwrapped every declaration to its `declRef`s but did not surface the binding *kind* the collision rule needs.
- **Codegen tolerance of repeated `var`**: confirmed directly that a repeated top-level `var` lowers correctly with no further work — each `emitVarDecl` uses a fresh `freshReg()` alloca and `define()` re-points the symbol, so the second declaration is observably `x = 2` with no IR redefinition. This is why Stage A needed only the early-error relaxed, not a storage change.
- **Scope stack** (`codegen/llvm/emitter.go`, `emit_func.go`): every function-like body (`emitFunctionDeclAs`, closures, generators) resets `e.scopes = nil` then pushes one fresh frame, so `e.scopes[0]` is always the current function boundary and `popScope` only ever tears down *block* scopes. This is what makes `var` function-scoping expressible as a single move down to `scopes[0]`.
- **`any` box encoding** (`emit_dynamic.go`): the box IR is `{ i8, i64 }` and the undefined tag is `5` (`kmlTagUndefined`), so an undefined box is the compile-time constant `{ i8 5, i64 0 }` — storable directly in the entry block, which is what lets an any-typed `var` default to `undefined` without emitting instructions.

## Decision

Three stages, matching [TDD-00070](../tdd/TDD-00070.md).

**Stage A — kind-aware top-level duplicate check.** `declRef` gains a `Kind` field, populated by `declRefsOf` (`var`/`let`/`const` from the node's own `Kind`; `function`/`class`/`enum`/`interface`/`type` from the node type). `mangleFileDecls` permits a repeated same-name declaration only when both the previous and current kinds are `var`/`function` (`isVarOrFuncKind`), re-pointing the second to the existing mangled name idempotently; any lexical kind colliding with anything stays a `declared more than once` error. The defensive post-mangle uniqueness assertion is taught the same exception (a same-file `var`/`function` duplicate is expected, not a mangling-scheme failure).

**Stage B — block-scoped redeclaration early-errors** (`resolver/scopecheck.go`, new). A static per-file walk (`checkLexicalScopes`), run before `mangleFileDecls` so messages carry the original name, descends only into *nested* scopes (blocks, loop/`if`/`try`/`switch`/function bodies) — module top level stays `mangleFileDecls`'s job, so the two never double-report. Within one scope it applies the same var/function-vs-lexical rule as Stage A, raising `identifier 'x' has already been declared`. A switch's whole case list is treated as one scope; a destructuring pattern's leaf names are flattened (recursing through sub-patterns).

**Stage C — function-scoped `var`** (`codegen/llvm/emitter.go`, `emit_exprs_vardecl.go`, `emit_stmts.go`). `promoteVarToFuncScope` moves a just-defined `var` binding from its innermost block scope down to `scopes[0]`; `emitStmt` calls it after every `var`-kind declaration (covering `for (var …)` via the shared `emitStmt(Init)` path). Because promotion is at-declaration, a `var` becomes visible from its declaration onward but not before — a read strictly before it stays a clean `undefined variable` error (the TypeScript definite-assignment view, not sloppy hoist-to-undefined). To keep a `var` read on a *not-taken* control-flow path deterministic rather than reading uninitialized stack memory, `emitVarSlotDefault` pre-initializes each scalar/dynamic `var` slot in the entry block to a constant default: the `undefined` box `{ i8 5, i64 0 }` for an any-typed `var` (JS-faithful), the type's zero literal for a typed scalar.

This realizes the signed-off **hybrid** typing model: an any-typed `var` reads back as `undefined`; a typed `var` reads a deterministic zero on a path where it was never assigned. The one deliberate V1 narrowing is that a typed `var` conditionally-unassigned yields that zero rather than a full TypeScript definite-assignment *error* — flow analysis for the error form is deferred (see below).

## Implementation notes

- Stage C's promotion *moves* (not copies) the binding, so it keeps a single home and `updateSymbolInPlace` (closure-capture boxing) stays correct. A `var` declared directly at function scope (`len(scopes)==1`) needs no move.
- `emitVarSlotDefault` emits its store via `emitAlloca` (the entry-block builder). The value is a compile-time constant in every case, which is what makes an entry-block store valid; a redundant pre-init before an unconditional initializer is dead and removed by `clang -O2`.
- Stage B deliberately **under-reports** rather than risk a false positive: it does not check the cross-nested-block var/lexical intersection (`let x; { var x }`) or function-parameter-vs-body collisions. Missing a check only fails to reject an illegal program; a false positive would reject a legal one.

## Side effects discovered

- **`var` block-scoping was a latent correctness gap, not just a missing feature.** Before Stage C, function-scoped `var` idioms (`{ var x = … } use(x)`, `for (var i …) {} use(i)`) failed to compile at all. Fixing scoping without slot pre-initialization would have turned that clean rejection into a silent uninitialized-memory read on not-taken paths — confirmed directly (`if (false) { var r = 42 } console.log(r)` printed stale stack contents) — which is why `emitVarSlotDefault` is part of the same change, not a follow-up.
- **Deferred (documented in `docs/status`):** full TypeScript definite-assignment *errors* for a typed `var`/`let` read before assignment (V1 yields a zero/undefined default instead); TDZ *message* quality for `let`/`const` (already rejected as `undefined variable`, not yet as `Cannot access … before initialization`); and Stage C slot pre-init for the rarer array/object/`Map`/`Set` `var` on a not-taken path. These are the V1 remainders named in [TDD-00070](../tdd/TDD-00070.md)'s Open questions.
