# ADR-00495: fs.statSync

- **Date**: 2026-08-29

## Context

No `fs.statSync` at all — file size/kind probing needed workarounds
(readFileSync length, existsSync). struct stat has no portable layout,
which is why it had been left out.

## Decision

Per-platform offset constants in `statLayout()` (the `direntNameOffset`
approach): Darwin (mode u16@4, mtimespec@48, size@96), glibc x86-64
(mode u32@24, size@48, st_mtim@88), glibc aarch64 (mode u32@16, same
size/mtim). `__kml_fs_stat` stats into a 256-byte scratch buffer,
extracts {mode, size, mtimeMs}, and throws the shared fs error on
failure. The result is a Stats object: visible `size`/`mtimeMs` (integer
ms) fields over a hidden leading st_mode word backing
`isFile()`/`isDirectory()` (S_IFMT mask — identical constants on all
targets). No other Stats fields/methods yet (no `isSymbolicLink`,
`mode`, `uid`, `atimeMs`...; `statSync` follows symlinks, and no
`lstatSync` exists to not follow them).

## Verification

Mac (Linux offsets encoded but **not** run — verify on the Linux box or
Docker before relying on them). `tests/fs_test.go` `TestE2EFsStatSync`
(size, kind checks, mtime sanity, ENOENT throw) passes; fs batch green;
`examples/fs/fs.ts` extended and re-run.
