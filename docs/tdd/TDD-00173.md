# TDD-00173: `-mm=auto` — @free/@owned annotations, escape check, implicit auto-free

- **Status**: Implemented
- **Date**: 2026-09-04

## Context

[TDD-00001](TDD-00001.md) defined three memory modes. `manual` and `gc` are
shipped; `auto` has been design-only since then — `-mm=auto` is rejected at the
CLI. Its Stages 2 and 3 sketched the mechanism (a `@free` block-exit free
behind a conservative escape check, and an `@owned` last-use free behind a
liveness pass) but explicitly left the exact escape-check rules and the
annotation/mode interaction matrix open. This document settles both and adds
one layer TDD-00001 only implied: with the escape check built anyway, `auto`
can free *unannotated* provably-local values too — which is what makes the mode
worth selecting for a plain program with zero annotations. That is the actual
completion of the mode as TDD-00001 defined it: "the compiler frees what it can
prove is safe to free."

## Design

### The three layers

1. **`/** @free */ let x = …`** — free `x` at every exit path of its declaring
   block (fall-through, `return`, `break`, `continue`), gated by the
   escape check below. A variable that fails the check is a **compile error**
   at the annotation: the tag is a claim, and a claim the compiler cannot prove
   is refused, never silently ignored.
2. **`@owned`** — free at the statically-determined *last use* rather than
   block exit. On a parameter (function-level `/** @owned name */` tag, the
   same named-tag shape as `@param {T} name`): the callee frees its argument.
   On a local binding: same as `@free` but freed at last use. Same escape
   check; ambiguous control flow falls back to block-exit placement (below).
3. **Implicit auto-free** (`-mm=auto` only) — every unannotated local of a
   freeable static type that passes the same escape check is treated as
   implicitly `@free`. Failing the check means *silently skip* (the value
   leaks, exactly as all values do today) — never an error, because no claim
   was made.

### Annotations are honored in every mode

`@free`/`@owned` are compiler-checked, compiler-placed `Memory.free` — the
emitted free is the same per-type logic `Memory.free` uses today, routed
through one shared helper. That makes the annotation meaningful in all three
modes rather than auto-only:

| Mode | `@free`/`@owned` | Implicit auto-free | `Memory.free` |
|---|---|---|---|
| `manual` (default) | honored | no | allowed — but a compile error on a variable that is *also* annotated (see rule 4) |
| `gc` | honored — the emitted `free` rides the existing GC shim (`free` → guarded `GC_free`, ADR-00351), an early-release hint to Boehm | no | allowed (same per-variable exclusion) |
| `auto` | honored | **yes** | **compile error** — in auto the compiler owns every free; a manual call it cannot plan for reintroduces the double-free hazard the per-variable check solves in the other modes |

The one hard exclusivity rule from TDD-00001 (`Memory.free` banned in `auto`)
stands. The manual/gc cases need no mode rule at all because the collision is
excluded per-variable: `Memory.free(x)` is a *use* of `x` the escape check
sees, and it rejects the annotation with a dedicated diagnostic. Sources using
the annotations therefore compile identically under all three `-mm` values.

### Escape-check rules (normative)

A new front-end AST pass (`codegen/llvm/escape_check.go`, modeled on
`pure_check.go` but strictly more conservative — a purity gap under-reports a
style violation, an escape gap here is a use-after-free). The unit of analysis
is one identifier within its declaring block/function body. The variable
**escapes** — compile error for an explicit annotation, silent skip for the
implicit layer — if any of the following holds:

1. **Returned**: the identifier appears anywhere inside a `return` expression
   (`return x`, `return [x]`, `return f(x)`, `return c ? x : y` all reject).
2. **Thrown**: appears anywhere inside a `throw` expression.
3. **Stored**: appears on the RHS of any assignment or in another declarator's
   initializer. This one rule covers assignment to an outer-scope variable,
   member stores (`obj.f = x`), element stores (`arr[i] = x`), *and* aliasing
   to a same-block local (`const y = x`) — the alias would dangle after the
   free, and tracking alias liveness is precisely the analysis this design
   refuses to build.
4. **Passed to a call**, with a small audited whitelist of callees that read
   but never retain: `console.log`/`error`/`warn`/`info`, `String(x)`, and the
   string coercions (template-literal interpolation, `+` concatenation), all
   of which copy into a new string. Everything else — user functions, other
   builtins, member calls (`other.push(x)`, `map.set(k, x)`) — rejects.
   `Memory.free(x)` is called out specially: "annotated variable is also
   manually freed", the per-variable exclusion above. The whitelist lives in
   one table in `escape_check.go`; each future addition needs a does-not-retain
   audit of the emitted runtime code, not of JS semantics.
5. **Captured by a closure**: the identifier is free in any nested
   function/arrow body (the existing `capturedLocalNames` machinery already
   computes this). Hard disqualifier for a second reason beyond escape:
   captured locals are eagerly boxed into shared heap cells (ADR-00619), so the
   alloca no longer owns the storage.
6. **Reassigned** (`x = other`): rejected. Otherwise the block-exit free would
   free the new value and orphan the original; "free the old value at
   reassignment" is a plausible future extension, not V1.
7. **Spread/destructured/deleted**: `...x`, `{...x}`, destructuring reads from
   `x`, `delete` on it — blanket reject (spread retains element pointers for
   nested shapes).
8. **Receiver of an unlisted method**: receiver position (`x.foo()`) is
   checked against a per-method table of known copy-semantics builtins
   (`.length`, `.slice()`, `.map()`, indexing reads, `for..of`, etc. — arrays
   and strings copy on these operations in this compiler). Unknown methods
   reject by default.
9. **Non-freeable type** (checked before any flow analysis): `any`/`unknown`
   (NaN-boxed scalars, not pointers), `-compat=js` dynamic objects (no
   `__kml_dynobj_free` exists; the bag has internal buffers a bare `free`
   would orphan), and anything `Memory.free` rejects today. The annotation on
   such a type is an immediate compile error with the type named.
10. **Alive across `await`**: in an async function, any use (or the block
    exit itself) separated from the declaration by an `await` rejects/skips in
    V1 — the value lives in the async frame across suspension and "block exit"
    is no longer a single well-defined point. Documented V1 limitation.

**Loops.** Declared *inside* a loop body → the declaring block is the body, so
the free runs every iteration (including via `continue`) — the churn-friendly
case the mode exists for. Declared *outside* and used inside → freed at its own
block's exit as usual.

**Multi-declarator statements.** `/** @free */ let a = …, b = …` is a
parse-time error ("annotate one variable per declaration") — the doc comment
attaches only to the first declarator, and accept-first would be a silent
surprise.

### `@owned` last-use placement (Stage 3)

A per-function, statement-granularity liveness pass run before body emission,
producing `symbol → freePoint` where freePoint is `AfterStatement(s)` or
`BlockExit`. Placement rules, all erring toward later (never earlier):

- **Straight-line**: free immediately after the last statement whose subtree
  mentions the identifier.
- **If/else**: last use inside a conditional → free after the *join* (the
  whole `if` statement is the last-use statement). Per-branch placement is a
  future optimization, not V1.
- **Loops**: any use inside a loop makes the loop statement the use; free
  after the loop.
- **`try`/`catch`/`finally`**: any use inside → fall back to `BlockExit`, so
  the existing finally/unwind machinery covers every path.

Safety net making Stage 3 structurally unable to miss an exit path: every
`@owned` value is *also* registered on the block-exit free stack with a done
flag; the early free at the last-use point marks it done, so an early
`return`/`throw` between declaration and the planned point still frees exactly
once via the stack, and the stack entry becomes a no-op after the early free.

**`@owned` parameters** — the callee-side is the same escape check applied to
the param. The caller-side contract ("the argument is dead after this call") is
checked at each call site: the argument must be a local that itself passes the
escape check with that call as its last use; anything else is a compile error
at the call site ("argument to @owned parameter must be a provably-dead
local"). Statically-resolved direct calls only; passing a function with
`@owned` params *as a value* is rejected (the contract can't follow the
function pointer).

### Free emission

- One shared helper, `freeSymbol`, extracted from `emitMemoryFree`: per-type
  free (string interior `ptr-8` via `__kml_str_free`; array data buffer plus a
  `{null,0}` store into the header, header intentionally kept — identical to
  the tested `Memory.free` behavior; Map/Set via `__kml_map_free`; closures via
  `__kml_closure_free`; objects/promises bare `free`), then null out the slot.
- A `pendingFrees` stack parallel to `pendingFinallys`, drained by an
  `emitFreesToDepth` mirroring `emitFinallysToDepth`, called from the same
  exit sites (return, break, continue, block fall-through). Interleaving is
  **finallys first, frees after** — a finally body may legitimately still
  read the value. Thrown paths deliberately do NOT free: a throw caught by a
  `catch` in the same function resumes execution with outer bindings still
  live, so freeing on the unwind would be a use-after-free; a thrown path
  leaks instead (safe, disclosed).

### FinalizationRegistry seam (TDD-00163)

Sequenced *after* this work, but the seam is fixed now: `freeSymbol` is the
single chokepoint every free goes through — `Memory.free`, `@free`, `@owned`,
and implicit — so TDD-00163 Stage 2's pointer→registration lookup hooks there
once and fires identically in manual and auto. When it lands,
`reg.register(target, …)` gets a whitelist row in rule 4 (the registry is a
ledger that *expects* the target to die; the free is its trigger). One
correction to TDD-00163's mode table recorded here rather than by editing it:
its `auto` row says unprovable targets fire "at collection", but `auto` has no
collector — unprovable registrations flush at `atexit`, as in manual.

## Open questions

1. Whitelist growth policy: rule 4/8 tables start minimal; is there a
   worthwhile audit batch (e.g. `Math.*`, `JSON.stringify`) for V1.1, and
   should the table be shared between arg-position and receiver-position
   checks or stay two tables?
2. Reassignment (rule 6): "free the old value at the reassignment point" is
   safe under the same rules and would widen coverage — V2 candidate.
3. Async (rule 10): values whose uses all precede the first `await` could be
   freed before suspension; worth the frame-analysis complexity?
4. Should the implicit layer report what it *did* free under a diagnostic flag
   (an opt-in `-mm-report` listing freed/skipped locals), as a trust-building
   and tuning tool?
