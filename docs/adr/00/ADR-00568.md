# ADR-00568: performance.now() has a process-start time origin

- **Relations**: Extends ADR-00024
- **Date**: 2026-09-01

## Context

`performance.now()` returned the raw `CLOCK_MONOTONIC` reading in milliseconds.
That counts from an arbitrary point (typically system boot), so an absolute
reading was a large, machine-dependent number — the spec instead defines
`performance.now()` as milliseconds since a **time origin** (process start in
Node). Only the difference between two readings was faithful; a single absolute
value diverged. Disclosed as a caveat.

## Decision

Capture the time origin once at process start and return `now - origin`:

- `__kml_perf_raw_ms` is the shared `CLOCK_MONOTONIC`→milliseconds read.
- `__kml_perf_init` (registered in `@llvm.global_ctors` at priority 65535)
  stores one `__kml_perf_raw_ms()` reading into the `@__kml_perf_origin` global
  before `main` runs — i.e. at process load, the closest the runtime gets to
  the spec's process-start origin.
- `__kml_performance_now` returns `__kml_perf_raw_ms() - @__kml_perf_origin`.

The origin is a plain process-global (not thread-local), so every thread/Worker
shares the one origin — a single process-wide time base, as the spec intends.

## Side effects discovered

None. Differences between two readings are unchanged (the origin cancels), so
`console.time`/`timeEnd`, `performance.mark`/`measure`, and every elapsed-time
measurement behave identically; only an absolute reading is now small
(origin-relative) instead of seconds-since-boot. This is the first
`@llvm.global_ctors` use in the emitted module; it is only emitted when
`performance.now()` is actually used.

## Verification

`TestE2EPerformanceNow` extended to assert the first reading is small
(`>= 0 && < 60000`, i.e. origin-relative, not seconds-since-boot); the existing
performance/timer/date/console-time/worker suites pass. Built and verified on
Mac (Apple Silicon).
