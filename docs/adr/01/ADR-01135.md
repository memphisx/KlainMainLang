# ADR-01135: An invalid assignment target is a syntax error

- **Relations**: `Implements TDD-00230` (Phase 2, P2.7)
- **Date**: 2026-09-25

## Context

After [ADR-01125](ADR-01125.md), Test262's strict lane accepted 16 more
negative tests (`language/expressions/assignmenttargettype`), for example
`1 == 2 = 1;`, which is an early SyntaxError.

## Investigation

- **The parser never validated an assignment's left-hand side.** Code
  generation rejected such a program ("can only assign to identifiers or
  array elements"). The checker now reports `1 == 2` as TS2367 before code
  generation runs. A type error is not the parse-phase rejection the test
  expects, and a type error on the operands is not the program's real
  error.
- **JavaScript's rule (AssignmentTargetType)** accepts:
  - a name;
  - a member or element access, but not one in an optional chain;
  - for `=` only, a destructuring pattern.
  TypeScript adds `x!` and `x as T` around a valid target. A call is an
  early error only in strict code; sloppy code throws a ReferenceError at
  run time (Annex B).
- **`undefined` is an identifier** in JavaScript, and the lexer makes it a
  keyword token.

## Decision

- **The parser rejects an assignment or compound assignment** whose target
  is not a valid one (`InvalidAssignTarget`, 2364), and `++`/`--` on one
  (`InvalidUpdateTarget`, 2357), at the operator.
- **`assignTarget` accepts** the forms above, `undefined`, and a call
  (left to code generation and the run time, as before).

## Implementation notes

`parser/parser_exprs.go`: `assignTarget`, `inChain`, and the checks in
`parseAssignment`, `parseUnary` and `parsePostfix`.

## Side effects discovered

None.

## Verification

- **AST dumps over 65,853 files:** 362 newly fail to parse, every one a
  TypeScript or Test262 negative case. No positive Test262 test is newly
  rejected, and no project file is.
- **`1 == 2 = 1`** is rejected at parse time, with 2364.
