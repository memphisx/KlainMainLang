# ADR-01977: A tuple is an array

- **Relations**: Implements TDD-00230 (P3.3, one representation per type); follows [ADR-01976](ADR-01976.md); revises [ADR-00201](../00/ADR-00201.md)
- **Date**: 2026-11-07

## Context

A tuple was a fixed-shape struct with fields "0", "1", and so on. In
JavaScript a tuple is an Array. Wherever a program used a tuple as an
array, it got a copy:

- `const r: (number | string)[] = pair` was a new array, so `r === pair`
  was false and `r[0] = 8` did not change `pair`.
- `push` and `sort` on a tuple went to a copy, or were not rewritten at
  all.
- `length` was the declared element count, even after an alias grew the
  array.
- A tuple boxed into `any` was boxed as a copy of its elements.

## Decision

- `TupleType` builds an array: a pointer to its header, like any other
  array. `kindTuple`'s parent kind is `kindArray`, not `kindObject`.
- The tuple's elements share one storage type (`tupleStorage`). When all
  elements have one plain type (a string, a number, a boolean), that type
  is the storage. When they all have one other type (an object type, an
  array type), that type is used. Otherwise the storage is `any`.
- `Fields` keep each element's own type. A constant-index read converts
  from the storage type to the element's type (`tupleElem`), and a write
  converts back. Building a tuple goes through `tupleOf`, and the
  producers of `[key, value]` entries use it too.
- Conversions:
  - A tuple and an array, or two tuples, with the same storage are the
    same value.
  - With different storage, the result is a copy, element by element. An
    array read as a tuple reads `undefined` past its end.
  - A box holding NaN-boxed words is the tuple itself when the tuple's
    storage is `any`.
- `length`, rendering, `JSON.stringify`, iteration and the array methods
  go through the array paths, so they see elements added through an
  alias.
- `-optimize-memory`'s by-value return of a small tuple stays. Its
  aggregate is the elements' own types (`tupleAggIR`). A caller that only
  destructures never builds the array; any other caller builds the array
  from the aggregate.

## Consequences

- Covered by `TestE2ETupleArrayIdentity` and the existing tuple suites,
  each matching Node.
- An object type of a tuple's numeric members (`const p: { 0: A; 1: B } =
  pair`) is still a copy. Its record view finds a layout through the word
  at the object's start, and an array keeps its type word before its
  header.
- A tuple whose element types differ holds them boxed. Reading an element
  unboxes it, which costs more than the struct's direct field read did.
