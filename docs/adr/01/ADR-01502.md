# ADR-01502: Shadow oracle maps dictionary views, generator methods and `arguments`

- **Relations**: Extends TDD-00230
- **Date**: 2026-10-09

## Context

The 2026-10-09 shadow report had 14,353 disagreements. Several buckets
came from the oracle's type mapping (`reprCtx.of`) giving a different
representation from codegen for the same value:

- dictionary reads (`inspect.colors[name]`, a `bindings[name]` record)
  were `any`, where codegen reads the record's value type. The
  "read through an `any` receiver is `any`" rule fired first, and a
  dictionary view is an `any` box;
- a local holding a record read was marked `UncheckedIndex`;
- an object literal with a generator method was unanswered;
- `arguments` was unanswered.

## Investigation

- A union of a dictionary view with only `null`/`undefined` collapsed
  to `any`, because any dynamic member made the whole union `any`.
- `NodeJS.Dict<T>` is an interface with only a string index. Only an
  anonymous `{ [k: string]: T }` was recognized as a dictionary.
- The oracle reused the array element-read rule for record reads, and
  that rule adds `UncheckedIndex`. Codegen's record read
  (`dynPropReadType`) adds only `undefined`.
- Codegen holds an object literal's generator methods as `any` fields.
  The oracle had no mapping for a function returning a `Generator`.
- The oracle had no mapping for `IArguments` (see ADR-01505).

## Decision

- A dictionary view in a union with only `null`/`undefined` stays the
  view.
- An interface with only a string index is a dictionary view. A value
  type's `| undefined` belongs to the read, not the storage.
- A record read marks absence without `UncheckedIndex`.
- A member or element read through a dictionary view is the view's
  value type, absent on a miss (`dynPropReadType`), not `any`.
- A generator-function field, or a module global initialized from one
  that is not a plain function name, maps to `any`.
- `IArguments` maps to `any[]`.
- A `var` declared a second time is the first declaration's global: the
  later declaration is not promoted.
- `process.env` is `any` (its own rewrite); `process.env.X` is
  `string | undefined`. A `NodeJS.Dict<T>` (an interface) holds its values
  as `T`; an explicit `{ [k: string]: T | undefined }` keeps the
  `undefined`.
- A class-instance local read from an array element holds the pointer
  (null when absent); a scalar record value holds its own absence; a
  record-read local flow proves present reads present.
- A nullable local every reaching store makes present reads present
  (mirrors `storesPresent`).
- A property read through an erased `x as C` may be absent when the
  operand's own type lacks the property or has it optional, and so may
  a `const` initialized from that read.
- The js lane's rules follow codegen's library scoping: a statement of a
  builtin TypeScript module is mapped as the strict lane maps it.
- In the js lane, an unannotated arrow or function-expression parameter
  whose default codegen does not type (a function, `null`, another
  parameter) is `any` unless its call sites agree; an uninitialized,
  unannotated `var` is `any` before narrowing; a literal of only holes
  or of two or more element kinds is `any[]`, and so is a global holding
  one.
- A comma expression is its last operand.
- A well-known symbol (`Symbol.iterator`), and a `const` holding one, is
  `any`.
- A union variable flow narrows to one of its primitive members is that
  member.
- The rest parameter of a function literal bound to an `any` binding is
  one `any`.
- An element of a regular-expression match is possibly absent (a group
  that did not participate), as codegen reads any array element.
- An optional method a class leaves unimplemented (`m?(): T;`) reads as
  a possibly-undefined pointer, not a typed closure.
- `a || b` / `a && b` of one pointer type keeps a three-state left
  operand's null/undefined marker, and so does a `const` holding it.
- A function's (or a builtin constructor's) `prototype` is `any`, as
  codegen reads it.
- An unannotated function declaration whose body only throws returns
  `never` (codegen's ADR-00869 representation), though TypeScript says
  `void`.
- A builtin global object's intrinsic static method read as a value takes
  every argument boxed (its widest overload; `Date.UTC` one rest), and
  an unannotated `const` holding one, or a typed array's
  `buffer`/`byteOffset`, holds what the read gives.
- A typed array's `buffer` is `any` (it may be shared), its `byteOffset`
  an integer.
- Where the checker has no return type for a body but every `return`
  value has one representation, that is the body's.
- A union of string and a handle type (`Promise<T> | string`) is a box
  naming its members, not a string.
- A mixed array literal, an unannotated binding of one and its element
  reads hold plain `any` boxes (codegen's `any[]`), not boxes naming the
  union's members.

- A mixed array literal (and an unannotated binding of one) maps to
  `any[]` only under `-compat=js`; strict keeps the union, as
  `inferArrayType` does.

- Under `-compat=js`, a function literal assigned to an untyped module
  `var` declared without a value is bound to `any` (boxed), and its
  `arguments` is one box.

- Under -compat=js, an array whose element type is only null or
  undefined (`var a = [,]`, `[null]`) holds boxed elements: JavaScript
  stores anything into it.

## Divergences

None. These are oracle mappings only; codegen behavior is unchanged.
