# ADR-01038: A property access on a run-time `undefined`/`null` throws Node's `TypeError`

- **Relations**: `Extends ADR-00834, ADR-01037`; `Implements TDD-00187` (the consumer side of `T | undefined`)
- **Date**: 2026-09-21

## Context

`function q(s?: string) { console.log(s.length) } q()` segfaulted. In Node it is `TypeError: Cannot read properties of undefined (reading 'length')` — catchable, `instanceof TypeError`. A second shape, `(r?.name).length` with an absent `r`, did not even crash on Windows outside a `try`: the program **hung**.

The defect is cross-cutting: every member read, method call, element access and member/element write whose base is a statically-typed pointer (or a `{ i1, T }` optional) dereferenced an absent base.

## Investigation

- A statically-typed absent value is a null pointer with the static type flagged `Nullable` (`IsUndefined` tells `T | undefined` from `T | null`, TDD-00187), or a `{ i1, T }` aggregate with a cleared presence bit. Only the `any` path (`emitDynAnyMemberGetNamed`, `emit_dynobj.go`) already threw the faithful `TypeError`.
- The access sites are spread over `emitMember` (~50 dispatch branches), `emitCall` (2,500 lines of receiver dispatch), `emitIndex`, `emitAssign`, `emitUpdate`. Most evaluate the base with a plain `emitExpr`; a number read a named symbol straight from its slot (`.length`, `.size`, array indexing).
- **The hang is not an OS or shim problem.** `__kml_str_len(null)` is a load from address −8. In the `(r?.name).length` shape the optimiser can *prove* the pointer null on the short-circuit path, a load through it is undefined behaviour, so the path is deleted and control falls into whatever block follows — here the `console.log` group-indent loop, which never terminates. The first repro died instead only because nothing there made the null provable. Reproduced by compiling the same program with the guard disabled: `rc=139` for the first shape, a 40 s timeout for the second.
- A non-nullable type can be absent at run time too (an unassigned object field). But the type flags cannot tell a string from a runtime handle, and some handles are legitimately null: `new TextDecoder()` holds no storage at all (`TextDecoderType` is a bare `ptr`). A first version that guarded every string-shaped pointer threw on `dec.decode(...)` — caught by the targeted regression run.
- An absent array cannot be told from an empty one by its value: both are the `{null,0}` aggregate (the documented nullable-array edge, ADR-00246). Only a null *header* means absent.

## Decision

**One guard, registered at the dispatch entry points, applied by `emitExpr`** (`codegen/llvm/emit_nullderef.go`).

- `emitMember`, `emitIndex`, `emitCall` (a member callee) and `emitAssign` (a member/index target) call `guardBase` / `guardIndexBase` with the base node and the property. For a base that is a **named binding** the guard is emitted on the spot (a second load of a local is free, and the slot-reading dispatch paths never reach `emitExpr`). Any other base is recorded in `Emitter.pendingDeref`; `emitExpr` — now a thin wrapper over `emitExprUnguarded` — applies the guard to whatever that node evaluates to. The base is never evaluated twice, and no dispatch branch had to change. The entry point defers an undo so a branch that never evaluates the base (a compile-time namespace) leaves nothing behind.
- The guard is a null test (pointer), a presence-bit test (`{ i1, T }`), or a header test (an array value that carries its header) branching to `@__kml_throw_nullderef(ptr msg)` — one shared `cold noreturn` function that builds the `TypeError` and calls `__kml_throw`. A guarded access costs a compare-and-branch; after the first test of an SSA value the optimiser removes the rest.
- **What is guarded** (`derefGuardable`): every declared-nullable type; of the non-nullable ones only struct pointers (objects, class instances). Bare pointers are left alone for the `TextDecoder` reason above. An array value with no header is left to read as the empty array it may be.
- **The message is Node's**: `Cannot read properties of undefined (reading 'x')` / `Cannot set properties of null (setting 'x')`. `null` vs `undefined` is the static discriminator the string/typeof/JSON coercions already use (`absentWord`). A compound assignment or `++` reads first, so it reports the read. `x!.p` guards the operand of the assertion, whose type still carries the flavour. A bracket access with a literal key names it (`'0'`); a **run-time key is evaluated in the throw branch** and rendered into the message (`dynAnyKeyRef`) — JS evaluates the key before the access throws, and on the non-throwing path `emitIndex` evaluates it as before, so it runs exactly once either way.
- `?.` falls back to the plain access for a base it has already classified; those fallbacks call `emitMemberUnguarded` / `emitIndexUnguarded`, so an optional access never throws.

**Arrow return-type inference** (found by the probes, fixed here): `inferExprType`'s `*ast.ArrowFunction` case typed an expression body *without the parameters in scope*. `(s: string) => s.length` and `=> s[0]` fell to the `i64` default while the closure itself returned `double` / `ptr`, so `const f = …; console.log(f("ab"))` printed the raw bits. The body is now inferred inside a scope holding the parameters (`definePatternParamForInference`), as the callback-hint path already did.

## Implementation notes

- `codegen/llvm/emit_nullderef.go` (new), `emit_exprs.go` (`emitExpr` wrapper), `emit_exprs_member.go` (`emitMember`/`emitIndex` split into guarded entry + `…Unguarded` body), `emit_call.go`, `emit_exprs_assign.go`, `emitter.go` (two fields), `emit_exprs_types.go` (arrow inference).
- The thrower allocates with `malloc` + `memset`, not the zeroing allocator: the `-optimize-memory` tests count that allocator's call sites in the IR to prove an instance left the heap.
- A named nullable-scalar local is read with `emitPreserveNullableOperand` for the guard — a plain identifier read surfaces the bare payload and loses the presence bit.

## Side effects discovered

- **Write ordering.** JS evaluates the right-hand side of `p.x = f()` before the write throws; the guard fires when the base is evaluated, so `f()` does not run. Only observable as a missing side effect immediately before a `TypeError`.
- **Nullable arrays** cannot express absence faithfully: `let a: number[] | null = null` and passing `null` to a `T[] | null` parameter are compile-time rejections, an omitted optional array parameter is indistinguishable from `[]` (so `xs[0]` on it reports the out-of-bounds error, and `for…of` / spread over it iterate nothing instead of `TypeError: ys is not iterable`), and `[] === null` is `true`. One representational problem (absent = null header, everywhere), tracked as the next bug in the working list.
- An out-of-range element read (`rows[5].name`) still throws the project's own `Array index out of bounds` rather than reading `undefined` and then throwing this `TypeError` (ADR-00157's long-standing choice).

## Verification

Windows x64. Probes diffed against Node 24 (`klainmain -run` vs `node --experimental-strip-types`): 10 access shapes, 22 further cases (nested chains, run-time key, nullable scalar receiver, `++`/`+=`, `!`, narrowing, `?.`), and the uncaught path (exit 1, message printed, no hang, `after` not reached). `tests/null_deref_typeerror_test.go` (3 tests), example `examples/basics/null_deref_typeerror.ts`. Targeted regression: 559 E2E tests selected by source pattern, all green after the two fixes that run prompted (the `TextDecoder` false positive, the allocator count). Not run on Linux/macOS.
