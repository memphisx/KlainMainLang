# ADR-01199: Host handles compare by identity, not as strings

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-09-28

## Context

`res.body === res.body` crashed intermittently with a bus error (about one
run in ten), found by `TestE2EFetchedResponseStatusTextAndType` under the
full suite. The crash report's top frame was `memcmp` inside the program.

## Investigation

`emitBinary` (`codegen/llvm/emit_exprs_operators.go`) sends two `ptr`
operands that are neither objects, arrays nor functions to
`emitStringBinary`, which compares them as strings: `__kml_str_cmp` reads
each operand's length from the 8 bytes before it and `memcmp`s that many
bytes. A ReadableStream, a Map, a Set, a Blob, a Promise and every other
host handle is a bare `ptr` carrying only its `Is*` flag, so `===` on two
of them read heap words as lengths — a wrong answer, or a read off the end
of a mapping. `isStringTy` itself matches any bare `ptr` (a long-standing
loose predicate with many callers); the equality site is where the wrong
decision was made.

## Decision

`hasHandleFlag(t)` reports a `ptr` type carrying any `Is*` flag other
than those a string can carry (`IsStrLiteral`, `IsNull`, `IsUndefined`,
`IsNever`); the flag list is read from the `Type` struct by reflection
once, so a new handle kind is covered without an edit. A pair with a host
handle on either side skips the string comparison and compares pointers
(identity), as JavaScript compares objects. The bound-native-function
exclusion (TDD-00229) is one of these flags and folds in.

## Implementation notes

`codegen/llvm/emit_strings.go` (`hasHandleFlag`), the string branch of
`emitBinary`.

## Side effects discovered

None beyond the class of bug: `===` on two Maps, Blobs, Promises or streams
was a string comparison before.

## Verification

Mac (Apple Silicon), against Node v24.19: a repro comparing streams, Maps,
Blobs, Promises, strings and a Response body by `===`/`!==` prints what
Node prints; the fetched-response repro ran 200 times without a crash
(14 of 150 crashed before).
