# ADR-00321: Node `zlib` module — one-shot compress/decompress family

- **Relations**: Extends ADR-00302 (CompressionStream/DecompressionStream libz runtime); Implements TDD-00049 (import-gated built-in modules, Stage 2 named members)
- **Date**: 2026-08-23

## Context

The `zlib` Node built-in was the highest-leverage unimplemented item in the
Node core-modules backlog: the `-lz` link and the whole codec machinery
(z_stream ABI, deflate/inflate init + drive loops) already existed for the
WHATWG `CompressionStream`/`DecompressionStream` (ADR-00302), so exposing the
Node call shapes was a surface-binding job rather than a new dependency. The
target use cases — CLI tools and microservices — routinely gzip/gunzip whole
buffers in one call rather than through a stream.

The goal was Node parity for the one-shot family: `gzip`/`gunzip`,
`deflate`/`inflate`, `deflateRaw`/`inflateRaw`, and `unzip`, each in both the
`*Sync` form (returns a `Buffer`) and the `(err, result)` callback form, over
the input types Node accepts (Buffer/TypedArray, ArrayBuffer, DataView, and a
string encoded as UTF-8).

## Investigation

- `codegen/llvm/runtime_streams_zlib.go` already declared the libz externs and
  poked the z_stream fields at their 64-bit ABI offsets (next_in +0,
  avail_in +8, next_out +24, avail_out +32). The streaming pump re-mallocs a
  fixed 64 KiB output block per iteration and enqueues each; a one-shot call
  instead wants a single growable output buffer driven with `Z_FINISH`.
- The import wiring is a fixed table: `resolver/virtual_modules.go`'s
  `virtualBuiltinMarkers` maps `'zlib'` to a reserved marker the codegen
  dispatch matches, and `virtualModuleMembers` validates named imports. Adding
  a module is two map entries plus a dispatch block, mirroring `querystring`.
- `fs.readFileSyncBytes` (`emit_fs.go:41`) showed the return convention: a
  runtime `{ ptr, i64 }` is already the exact SSA aggregate a first-class
  TypedArray value uses, so a Buffer result needs no repacking.
- `emit_fs.go`'s `emitFsWriteLikeCall` showed the input-normalization pattern
  for the three binary shapes (ArrayBuffer via `emitArrayBufferByteLength` + a
  field-1 load; TypedArray via `resolveArrayForHOF` + `emitTypedArrayByteLength`;
  DataView's `{ ptr data, i64 byteLength, ... }` layout in `emit_dataview.go`).
- `resolveCallbackWithHints` + `emitCBCall` (`emit_func.go`) already fire a
  callback with pre-evaluated `Value` arguments and handle the array-typed
  parameter's `(ptr, i64)` ABI split — exactly what a `(err, Buffer)` callback
  needs.

## Decision

Add one runtime helper and one dispatch file; reuse everything else.

- **Runtime** (`runtime_streams_zlib.go`): factor the six libz extern
  declarations into `ensureZlibExterns()` (idempotent), shared by the streaming
  runtime and the new `ensureZlibOneshot()`. The latter emits
  `@__kml_zlib_oneshot(ptr data, i64 len, i64 mode, i64 wbits, i64 level)
  -> { ptr, i64 }`: a single `Z_FINISH` pass into a growable output buffer
  (initial capacity `len + len/2 + 64`, doubled on fill), returning
  `{ base, total }`, or `{ null, -1 }` on any zlib error (bad init, or a stuck
  `Z_BUF_ERROR`/short-read on corrupt input).
- **Codec table** (`emit_zlib.go`): a per-method `(mode, windowBits)` pair —
  gzip 31, zlib 15, raw -15 for compression; 47 (auto-detect) for the decoders,
  so `gunzip` and `unzip` both accept either wrapper, matching Node.
- **Input normalization**: ArrayBuffer / DataView / TypedArray / (default)
  string → `(dataPtr, byteLen)`; a string uses its stored UTF-8 bytes + strlen.
- **Sync form**: call the helper, throw on the `-1` length sentinel, return the
  aggregate as a `uint8` TypedArray (a Buffer).
- **Callback form**: branch on the sentinel; on success fire `cb(null, buffer)`,
  on error fire `cb(Error, emptyBuffer)`, via `emitCBCall`.
- **`{ level }` option**: accepted on the compressors as a compile-time integer
  literal (or `-1`), default 6.

## Implementation notes

- Files: `codegen/llvm/runtime_streams_zlib.go` (externs refactor +
  `ensureZlibOneshot`), `codegen/llvm/emit_zlib.go` (new dispatch),
  `codegen/llvm/emit_call.go` (one dispatch block), `codegen/llvm/emit_exprs_types.go`
  (`inferExprType`: `*Sync` → Buffer, callback → void), `resolver/virtual_modules.go`
  (marker + member list), `codegen/llvm/emitter.go` (two `used*` flags).
- The one-shot loop carries `out`/`cap`/`total` in allocas rather than phis to
  keep the hand-written IR legible; `avail_out` is capped to `1 << 30` per pump
  so a chunk length always fits the i32 field.
- The callback closure header is resolved once, before the success/error
  branch, so both `emitCBCall` sites share it.

## Side effects discovered

None. `.buffer` on a TypedArray remains unimplemented (a pre-existing
Binary-Data caveat), so constructing an ArrayBuffer input from a typed array is
done via an explicit `DataView` in the test rather than `u8.buffer`.

## Verification

- `go build` / `go vet` clean.
- New `tests/zlib_test.go` (12 cases): sync round-trips for every codec, the
  `{ level }` option, all four input types, the callback form and its error
  path, the sync throw on corrupt input, named imports, missing-import
  rejection, and Go cross-implementation interop both directions
  (`compress/gzip` ⇄ KlainMainLang, plus `compress/zlib` and `compress/flate`
  read by `inflateSync`/`inflateRawSync`). All pass.
- `examples/zlib/zlib.ts` builds and runs (Mac / Apple Silicon M4).
- Existing Streams/Compression suites still pass after the externs refactor.

### Known limitations (tracked on docs/status/NODE-CORE-MODULES.md)

- The callback form fires synchronously, not deferred to the next event-loop
  tick as in Node.
- No Brotli (`brotliCompress*`) — it would add `-lbrotli`, a new system
  dependency, which this binding deliberately avoids.
- No class/stream forms (`createGzip()`, `zlib.Gzip`, …) — the WHATWG
  `CompressionStream`/`DecompressionStream` already cover the streaming case.
- `{ level }` is the only supported option and must be a compile-time constant.
