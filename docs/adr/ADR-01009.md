# ADR-01009: `.length` through `any` (boxed string / boxed array)

- **Relations**: Extends TDD-00212 (live any-array box header), TDD-00155 Stage 6
- **Date**: 2026-09-18

## Context

The stale-caveat sweep confirmed "primitive members through `any` read as
`undefined`": `(s: any).length` on a boxed string was `undefined` (strings fall
into the primitive-tag fallback of `emitDynAnyMemberGetNamed`), and on a boxed
statically-typed array it *threw* the "dynamic property access on a
statically-typed value" TypeError (tag `kmlTagArray` fell into the
static-reference rejection). Node: `5` / `3`.

## Investigation

The member-get dispatcher (`emit_dynobj.go`) already branches per box tag with
a compile-time `propName`. A string's byte length is `__kml_str_len`; a boxed
array's box cell (TDD-00212 Stage 3) carries the LIVE array header, whose
field 1 is the current length — so a post-box `push` through the named binding
is reflected. Full primitive-method dispatch (a `s.toUpperCase()` /
`a.push()` call through `any`) is a much larger surface and stays open.

## Decision

In `emitDynAnyMemberGetNamed`, when `propName == "length"`, add two branches
ahead of the object probe: `kmlTagString` → `__kml_str_len`, boxed as a
number; `kmlTagArray` → live header length, boxed as a number. Every other
property keeps the prior behavior (string/primitive → `undefined`, as JS;
boxed static array non-`length` → the honest TypeError).

## Implementation notes

`codegen/llvm/emit_dynobj.go` only. Lengths box via `sitofp` +
`emitNbEncodeDouble` so `typeof x.length` is `'number'`.

## Side effects discovered

Method *calls* through `any` on primitives/boxed arrays remain undispatched —
the reworded caveat in `docs/status/data/type-system.json` now names exactly
that residue.

## Verification

New `TestE2EAnyPrimitiveLength` (string length + typeof, live array length
across a `push`, non-length string prop → `undefined`) — byte-exact vs Node.
`Dyn|Any|Compat` groups pass; `make examples` + `make conformance-node` green
(macOS arm64).
