# ADR-00422: stream named exports — PassThrough, callback pipeline/finished, duplexPair

- **Relations**: Extends [ADR-00304](ADR-00304.md) (Node stream module), [ADR-00412](ADR-00412.md) (contextual typing through `test` wrappers); Implements part of [TDD-00131](../tdd/TDD-00131.md)
- **Date**: 2026-08-28

## Context

The Node-oracle gap list ranked the `stream` module's missing named
exports as the cheapest remaining cluster (~40 corpus files touch
`PassThrough` alone, plus the `finished`/`pipeline` callback forms and
`duplexPair`). Only the class constructors and the `stream/promises`
Promise forms existed; the named function exports were resolver errors.

## Investigation

- The resolver bound *every* `stream` member as identity
  (`resolver/rename.go`) because the class names are parse-time
  constructors. Function members can't ride that route — nothing
  dispatches a bare `finished(...)` call.
- The corpus idiom for completion callbacks is
  `finished(rs, common.mustCall((err) => …))`; listener registration
  (`resolveEventEmitterListenerArg`) rejected `test`-wrapper-wrapped
  listeners because the wrapper is emitted as an opaque expression and
  the inner arrow's bare parameter defaulted to `number`.
- `duplexPair()` needs no new runtime: the Transform's TSCTX sink
  (`__kml_ts_sink_write`: enqueue into ctx's rstream, park on
  backpressure) becomes a cross-wire by pointing each side's sink ctx at
  the *peer's* rstream.

## Decision

- **Resolver split**: `stream`'s class names (`Readable`/`Writable`/
  `Duplex`/`Transform`/`PassThrough`) stay identity bindings; its
  function members (`pipeline`/`finished`/`duplexPair`) rewrite to
  `stream__kml_builtin.<member>` and dispatch in codegen like
  `stream/promises`' members do.
- **PassThrough**: a fourth node-stream constructor kind sharing the
  Transform emission as the identity transform (no `transform`/`flush`
  options). Chunks default to **string** (`<T>` overrides) — Node's
  non-objectMode streams carry strings/Buffers, and the identity shape
  has no callback whose signature could pin the type.
- **Callback `finished(s, cb)` / `pipeline(...streams, cb)`**: reuse the
  Promise forms' plumbing (`streamClosedProm`, the extracted
  `emitStreamPipelineWire`) and attach a per-site runner to the closed
  promise via the reaction-registration block extracted from
  `emitPromiseThen` into `emitAttachPromiseReaction`. The runner calls
  the callback with `null` on fulfill / the error on reject; the
  callback may take zero parameters or one. `pipeline` returns its
  destination stream (as Node does); `finished` returns nothing.
- **`duplexPair()`**: two identity-transform sides whose TSCTX sinks
  point at each other's rstream (and whose pulls resume the *peer's*
  parked ctx), packaged as a 2-element array so destructuring and
  indexing work through the ordinary array machinery. String chunks.
- **Wrapper-wrapped listeners**: `resolveEventEmitterListenerArg` now
  contextually annotates the inner arrow of a `test` counting wrapper
  from the event payload type (`string`/`number`/`boolean`/`Error`,
  per-element for tuple payloads) before emission — the same ADR-00412
  treatment `createServer` handlers get, so
  `p.on('data', mustCall((d) => …))` compiles.

## Implementation notes

- `parser/parser_literals.go`: `PassThrough` case; single type param
  fills both sides for `passthrough` like `transform`.
- `codegen/llvm/emit_node_stream.go`: `passthrough` kind (string
  default), `streamClosedProm` + `emitStreamPipelineWire` extractions,
  `emitStreamFinishedReaction`, `emitStreamModuleCall`, `emitDuplexPair`.
- `codegen/llvm/emit_promise_then.go`: `emitAttachPromiseReaction`
  extraction (behavior unchanged for `.then`/`.catch`/`.finally`).
- `codegen/llvm/emit_call.go` / `emit_exprs_types.go`: marker dispatch +
  result-type inference (`pipeline` → its last-stream argument's type;
  `duplexPair` → `NodeTransform<string, string>[]`).
- `codegen/llvm/emit_eventemitter.go`: `listenerTypeName` +
  wrapper-aware contextual annotation.
- `resolver/rename.go` / `resolver/virtual_modules.go`: class-vs-function
  member split, new members registered.

## Side effects discovered

- `finished()` returns nothing rather than Node's cleanup function —
  callers invoking the return value get a clean rejection (tracked as a
  STREAMS.md caveat).
- `duplexPair()` has no `<T>` form (call-site generics aren't parsed
  there); chunks are strings.

## Verification

- New E2E tests (`tests/streams_test.go`): PassThrough (named/qualified/
  typed/piped), callback `finished` (plain + qualified + `mustCall`,
  exit-verified), 3-stage callback `pipeline`, `duplexPair`
  (destructuring, indexing, cross-delivery, end propagation,
  `mustNotCall`). New example `examples/streams/named_exports.ts`.
- Full `make test-par` and the Node oracle rerun accompany this change
  (Mac).
