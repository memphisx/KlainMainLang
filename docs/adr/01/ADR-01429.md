# ADR-01429: Immediately invoked parameters, `any` promise handlers

- **Relations**: Implements TDD-00230 (P2.3), Extends ADR-01428
- **Date**: 2026-10-06

## Context

ADR-01428's implicit-any parameters left two Test262 files invalid in the
IR:

- `function g(a) { return function () { return g; }(); }()`: an
  immediately invoked function's unannotated parameter had no type, so the
  function had none, and codegen read `g` with the wrong representation.
  Typing every context-free parameter `any` inside `signatureType` made the
  checker's flow analysis grow without bound (TestFlowCost ran out of
  memory).
- `Promise.resolve().then(onFulfilled)` with `onFulfilled` an `any`
  parameter stored the boxed word into the reaction's closure slot.

## Investigation

- tsc's `getContextuallyTypedParameterType` types an immediately invoked
  function's parameter from its argument, and `isOptionalParameter` makes a
  parameter past the last argument optional (so `(function (a) {})()` is
  not "expected 1 arguments").
- PerformPromiseThen treats a non-callable handler as absent.
- Probing the `then` path also showed a named handler whose parameter is
  `any` (`const cb = function (v: any) {…}; p.then(cb)` over a number)
  receiving the raw double as a box: the adapter that boxes the value
  existed only for function literals.

## Decision

- The checker types an immediately invoked function's unannotated
  parameter from its argument (widened), or `any` past the last argument,
  where it is also optional. Only the call that encloses the function
  itself is consulted, so the change is bounded to that shape.
- A `.then`/`.catch` handler held in an `any` converts through the
  dynamic-to-static thunk; a value whose tag is not a function becomes the
  null callback, the pass-through.
- A named fulfilled handler taking `any` over a concrete value type is
  wrapped in the boxing adapter, as a literal one is.

## Verification

- Both lanes compile `staging/sm/Function/regress-528082.js` and
  `language/expressions/await/syntax-await-in-ConditionalExpression.js`.
- `language/statements/try/tco-catch-finally.js` still overflows the native
  stack at its 100000-deep recursion: it needs proper tail calls, which Node
  does not implement either.

Gates on this tree (Linux, kmlbox): test-par on Node304, examples 396/396
and Test262 strict on DeskMini, Test262 js on Node304. Against the previous
full run, strict passes 8401 (101 new; the 236 it no longer passes are
programs tsc rejects: implicit-any parameters, a possibly-undefined call,
`f.call()`/`f.apply()` without `thisArg`) and js passes 10810 (232 new, only
`tco-catch-finally.js` lost); neither lane has invalid IR. A first strict run
overflowed the checker's stack on `(function (f) {…})(x => x)`, whose
argument's context is the parameter being typed; a re-entry guard leaves
that parameter unanswered.
