# ADR-00241: `await` of a non-thenable is identity — fixes the Response body-accessor crash

- **Relations**: Fixes a 2026-08-11-audit bug ([ADR-00166](ADR-00166.md)); touches `Response.text()`/`.json()`/`.arrayBuffer()` ([ADR-00021](ADR-00021.md), [ADR-00094](ADR-00094.md)) and the JSON projection ([ADR-00224](ADR-00224.md))
- **Date**: 2026-08-19

## Context

`Response.text()`/`.json()`/`.arrayBuffer()` are synchronous in this compiler —
they return a `string`/parsed value/`ArrayBuffer` directly, not a `Promise`. But
the most instinctive way a TS developer writes them is `await res.text()`, and
that hard compile-crashed: `emitAwait`'s only non-Promise guard was
`hdlVal.Ty.IR != "ptr"`, which a plain string result (also `ptr`) satisfies, so a
synchronous value fell into the Promise-slot path. That path treated the string
pointer as a heap Promise slot, `free()`d it (a use-after-free on the live body
buffer), and — because it decided the unwrapped type was `void` — returned an
empty-`Ref` value, so the enclosing var-decl emitted `store i64 , ptr %tN` (an
empty operand → invalid IR, clang failure). This was in the number-one REST path.

## Decision

`await` of a non-thenable is identity in JS — the value passes straight through.
Implement that:

- **`emitAwait`** (emit_async.go): before the Promise-slot logic, if the argument
  is not actually a Promise (`!hdlVal.Ty.IsPromise && !inferExprType(arg).IsPromise`),
  return the already-evaluated value unchanged. Only genuine Promises reach the
  load-and-free path.
- **`inferExprType(AwaitExpression)`** (emit_exprs_types.go): a non-Promise await's
  type is the argument's own type (was a blind `TypeI64`), so the var-decl slot is
  sized correctly (e.g. `await res.text()` → `string`).
- **Type-directed JSON projection through `await`**: the var-decl emitters project
  `JSON.parse(...)`/`Response.json()` into the declaration's target type, but keyed
  off a bare `CallExpression`, so `await res.json()` (an `AwaitExpression`) missed
  it and yielded a null/default value. Factored the detection into one shared
  `emitDeclJSONProjection` (emit_objects.go) that unwraps a surrounding `await`
  (identity over these synchronous calls) and is now used by all three var-decl
  emitters — scalar (emit_exprs_vardecl.go), object (emit_objects.go), and array
  (emit_arrays_core.go), the last of which also gains `Response.json()` projection
  it previously lacked.

## Consequences

- `await res.text()`/`.json()`/`.arrayBuffer()` work and match the un-awaited
  forms; the response body is not freed, so it stays usable afterward.
- `const p: T = await res.json()` projects into `T` exactly as `res.json()` does.
- More broadly, `await <non-Promise>` is now a harmless no-op rather than an error,
  matching JS. The one remaining divergence on these methods is that they are
  synchronous rather than Promise-returning (kept as a status caveat).

## Verification

Against a local server: `await` forms of `.text()`, `.json()` (object and
`number[]` projection), and `.arrayBuffer()` all produce correct output and the
response stays valid after an awaited accessor. The emitted IR compiled under
`clang -fsanitize=address` and ran clean — no `heap-use-after-free`. New E2E tests
(`TestE2EFetchAwaitText`/`AwaitJSONProjection`/`AwaitJSONArray`/
`AwaitArrayBufferAndReuse`) plus `go build`/`go vet ./...` clean, on Apple Silicon
(macOS).
