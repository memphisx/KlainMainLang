# ADR-01587: The dns resolver on c-ares, as cares_wrap drives it

- **Relations**: Implements TDD-00250
- **Date**: 2026-10-11

## Context

The resolver was an own DNS client ([TDD-00236](../../tdd/TDD-00236.md)).
It differed from Node in what it sent and in how it read answers:

- it sent EDNS;
- `resolveAny` returned `ENOTIMP` against `test/common/dns` servers;
- it parsed in TypeScript (`shapeAnswer`).

`TestE2EDnsPortResolve` queried public names (gmail.com, example.com,
8.8.8.8). Its output depended on the network and on the moment, and it
failed in CI on both Linux lanes.

## Investigation

The reference is Node v26.10.0 `src/cares_wrap.cc`/`cares_wrap.h`. A probe
answered every record type from a local `dgram` server built with Node's
`test/common/dns.js`. Node's output for that probe was recorded as the
reference: the values, the key order, and `type: undefined` on SOA and
NAPTR.

## Decision

The resolver is cares_wrap over c-ares, in its own C unit
(`codegen/llvm/caressrc/klaincares.c`, the `@link cares` natives):

- `Setup`, `EnsureServers` and the sockstate/poll/timer glue;
- one `Parse` per trait;
- `GetServers`/`SetServers`/`SetLocalAddress`/`Cancel`/`StrError`.

A query's parsed value crosses as JSON, `{"r":…,"x":ttls}`. In TypeScript,
`runQuery` only:

- converts TLSA data to an ArrayBuffer;
- restores the `type` slot that the SOA/NAPTR record templates leave
  undefined.

The query name passes through IDNA to-ASCII (`idnaToASCII` in
`kml_url.ts`). A completion runs through the pool's completion queue:
`__kml_pool_begin` and `__kml_pool_finish` are new in `klainpool.c`.

`dns` and `dns/promises` now share one default channel, as Node's
`bindDefaultResolver` does. Before this, `dns.setServers` did not reach
`dns.promises.resolve*`.

## Implementation notes

- **Removed**: the own client and its natives from `klaindns.c` (that file
  keeps `getaddrinfo`/`getnameinfo`), and `shapeAnswer`, `anyRecords` and
  `reverseName` from `internal_dns_utils.ts`.
- **`setServers`**: the spec lines carry the family (`family address port`),
  as cares_wrap's `[family, ip, port]` triples do.
- **Error messages**: `ERR_DNS_SET_SERVERS_FAILED` now carries
  `ares_strerror` text (`dnsStrerror`).
- **TXT and TLSA**: read straight from the answer section. Ubuntu 24.04's
  c-ares 1.27 joins a TXT record's strings, while the c-ares Node bundles
  keeps them as chunks; TLSA's parser is newer than 1.27.
- **Windows**: a channel uses `ARES_OPT_EVENT_THREAD`, because no libuv
  loop runs there yet. This is a documented divergence until
  [TDD-00244](../../tdd/TDD-00244.md) Stage 6.
- **Toolchain**: c-ares joins CI (brew `c-ares`, apt `libc-ares-dev`,
  MSYS2 `mingw-w64-ucrt-x86_64-c-ares`), the README requirements, and the
  test-box containers.

## Side effects discovered

Writing the hermetic test surfaced five compiler bugs, each fixed:
- [ADR-01588](ADR-01588.md): `concat` did not spread an `any` holding an array;
- [ADR-01589](ADR-01589.md): converting an `any` into a tuple, or into an
  array of tuples or nested arrays, failed;
- [ADR-01590](ADR-01590.md): a module-global `Record` read was mistyped;
- [ADR-01591](ADR-01591.md): `Buffer.concat` rejected a spread in its list;
- [ADR-01592](ADR-01592.md): `new a.b.C()` failed when rooted at a value.

## Verification

`TestE2EDnsPortResolve` and `TestE2EDnsPortSetLocalAddress` were rewritten
to answer from a local UDP server, so they need no network. Every record
type, `resolveAny`, NXDOMAIN, NODATA, reverse v4/v6, TTLs, CNAME chains,
upper-case names, the promises API and an own `Resolver` all match Node:
- Mac, c-ares 1.34.8;
- Linux (Node304), c-ares 1.27.0.

The Node 26.10 probe output is byte-identical. The dns/dgram suites pass
on both machines. Windows is compile-unverified here; its first build is
the CI lane.
