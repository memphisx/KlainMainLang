# ADR-01519: A narrowing another function may undo is not trusted

- **Relations**: Extends TDD-00230
- **Date**: 2026-10-09

## Context

TypeScript's flow analysis, and the checker's, keeps a narrowing across a
call: after `o = { a: 1 }; reset();` it still types `o` as present, though
`reset` set it to `undefined`; after `if (b.v) { b.clear(); … }` it still
types `b.v` as present. Codegen read such a value in its narrowed
representation: a cleared object segfaulted, a cleared `number |
undefined` read its payload `0`, and an `any` or `number | string` read
through the stale member printed `NaN`. tsc accepts all of these
programs; Node prints `undefined`, the new string, and so on.

## Decision

- The binder records the variables some function other than their own
  stores to (`StoredElsewhere`); `ReachingStores` gives no answer for
  them.
- A read is flow-trusted (`flowTrusted`) when its variable is not stored
  elsewhere, and, for a property path, when no call lies between the read
  and the condition or store that made it present on any path
  (`callBetweenNarrowing`, over the flow graph's call nodes).
- An untrusted read is not narrowed: the checker-presence reads
  (`checkerPresent`, `checkerPresentRef`, `assignedString`), the `any` and
  union narrowings (`checkerNarrowed`, `checkerNarrowedUnion`) and the
  guard narrowings (`narrowingFromCondition`, `applyUnionBranchNarrowing`)
  keep the declared representation, and the value is read as it is at run
  time.
- A method call or `.length` on an un-narrowed union of scalars goes
  through the box's run-time dispatch, as on `any`.
- The shadow oracle mirrors each rule.
