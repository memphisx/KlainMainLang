# ADR-01660: Heap allocations, stores and frees through single primitives

- **Relations**: Implements [TDD-00230](../../tdd/TDD-00230.md) (P3.3a)
- **Date**: 2026-10-16

## Context

TDD-00230 P3.3a asks that every allocation, every store of a value into a
heap object and every explicit free be emitted through one primitive each,
in codegen and in the C runtime, so that a collector's allocation fast path
and write barrier each land in one place. Before this, about 180 codegen
sites called `malloc`/`calloc`/`realloc` directly, about 400 built their own
`store` into heap slots, and the C runtime called libc for program values
and its own scratch memory alike.

## Investigation

- Codegen allocations and stores were all `emitInstr` text, so a check at
  `emitInstr` sees every one of them. Telling a heap store from a stack store
  needs the destination's provenance: a store into an `alloca` (or a GEP
  over one) or a global is not a heap store.
- The 68-file IR corpus (examples across every area) is the yardstick for
  the rewrite: the primitives emit the same text the sites built by hand, so
  the IR must stay byte-identical.
- In the C runtime, the program-visible blocks (header strings, array
  headers and data, boxes, cells, Buffer bytes) mix with blocks the runtime
  keeps to itself (string builders, sort orders, OS and library handles,
  queues). Only the first kind is the managed heap.
- A barrier kind needs no annotation at each site: whether a store can
  write a heap reference follows from its IR type (`ptr`, an `i64` that may
  be a boxed word, an aggregate), so the primitive derives it.

## Decision

- `heap_prims.go` holds the primitives: `heapMallocInto`, `heapCallocInto`,
  `heapReallocInto`, `heapAllocCall` (a named allocator such as
  `GC_malloc_uncollectable`), `heapMallocAt` (an entry-block cell),
  `heapStore`, `heapStoreTV`, `heapStoreAtomic`, `heapStoreAt`, and
  `heapFree`. Every codegen allocation, heap store and free goes through
  one of them.
- Each store derives its static barrier kind (`storeBarrier`):
  `barrierNone` for a value that can hold no heap reference,
  `barrierPointer` otherwise, and `barrierRC` reserved for a
  reference-count cluster's slots under `-mm=auto`. `emitBarrier` emits it
  before the store; no memory model needs one today, so it emits nothing.
- `heap_check.go`: `KML_HEAPCHECK=panic` makes `emitInstr` panic on an
  allocation, heap store or free emitted outside a primitive, naming the Go
  site; `KML_HEAPCHECK=<file>` records each such site once instead. Off,
  it costs one string test per instruction.
- `kmlheapsrc/kml_heap.h`, prepended to every C runtime member
  (`EmbeddedCSources`), gives the runtime the same interface: `kml_alloc`,
  `kml_calloc`, `kml_realloc`, `kml_free` with a block kind
  (`KML_HEAP_RAW`, no pointers; `KML_HEAP_WORDS`, may hold pointers or
  boxed words), `KML_STORE_PTR` and `kml_copy` (a bulk copy, the barrier
  for every slot copied). A runtime block that never becomes a program
  value stays on libc with a `scratch` marker on its line.
  `TestCRuntimeAllocatesThroughHeapInterface` holds each converted file to
  that rule.

## Implementation notes

`heap_prims.go`, `heap_check.go` (hooked at the top of `emitInstr`, skipped
while a primitive emits), the rewritten sites across `emit_*.go`,
`kmlheapsrc/kml_heap.h`, `embedded_c.go`, `heap_c_test.go`, and the C
runtime files listed in `heapCoveredC`. The layout probe of
`sidecar_layout_test.go` includes `kml_heap.h` ahead of `dynjson.c`, as the
build does. Element data of a dynamic array box takes its kind from the
element kind (`kj_heap_kind`): numbers and booleans are raw, strings,
boxes, arrays and objects are words.

The IR-text helpers of `runtime_*.go` (written as whole `define` text,
frozen by the IR-text ratchet) keep their own `free` calls; they move to C,
and then through `kml_heap.h`, as that ratchet shrinks.

## Side effects discovered

- Some runtime-private records stay on libc while holding the only
  reference to a program value: the unit registry's instance and statics
  tables (`unitreg.c`), thread-pool work items and the fs watcher holding
  closures, the HTTP/2 request record holding its headers map. Every
  current memory model sees them (malloc never collects; Boehm's shim
  routes libc). A tracing collector that does not scan libc needs them as
  roots; that is the collector's own work, not this interface's.
- The header first included `<stdlib.h>`/`<string.h>`, which, prepended,
  ran before a member's own `_GNU_SOURCE` and hid `REG_RSP` and
  `sched_getaffinity` on Linux. It includes nothing and declares the four
  libc allocators itself, with C linkage for the C++ member (`ffiumap.cc`).

- `__kml_buf_fill_any` (ADR-01659) lived in `dynjson.c` but called the
  Buffer codecs, which are not linked with every `dynjson.c` user: a
  link failure for any program using dynamic values without Buffer. It is
  its own member, `buffill.c`, linked by `ensureBufFill`.
- `__kml_fn_static_get` (ADR-01659) was IR text over the IR-text ratchet's
  allowance; it is C in `fnmeta.c` over a unit table of
  `{identity, getter}` rows.

## Verification

- IR byte-identical on the 68-file corpus after the codegen rewrite.
- `go test ./codegen/llvm` (with the new heap test), and every unit
  package.
- Targeted E2E suites over the converted runtime paths (dynamic values,
  strings, collections, fs/fetch/HTTP/streams/zlib/DNS/os/process,
  crypto/promises/async/FFI/weak/finalization/hooks/dynamic import) on the
  Mac; Linux compile of examples on the x86-64 box.
