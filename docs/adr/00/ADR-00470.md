# ADR-00470: qualified type references (`ns.Type`)

- **Relations**: Extends [ADR-00450](ADR-00450.md), [ADR-00408](ADR-00408.md)
- **Date**: 2026-08-29

## Context

`unexpected token . in expression` and type-position failures on
`export type MC = m.c;` — namespace-qualified type names in annotations,
common across the corpus's declaration-file suites.

## Decision

A dotted name in the type-atom position (`ns.Type`, `a.b.C`) consumes the
chain and resolves to its **final segment** — the same rule qualified
`new ns.C(...)` and `extends ns.C` already use (ADR-00408), consistent
with namespace type members desugaring to bare top-level names
(ADR-00450). Same disclosed consequence: two namespaces declaring the
same type name collide.

## Verification

Mac. `tests/namespaces_test.go` E2E (interface + alias through `m.`) and
the example extension (`Geometry.Point` annotation) pass; type/interface/
namespace batches green. TS oracle: **55.9% → 56.0%** (agreement
5173 → 5184). Node oracle unchanged (40).
