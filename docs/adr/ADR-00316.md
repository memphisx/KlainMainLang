# ADR-00316: `-crypto` backend flag, `__kml_crypto_*` subtle ABI, and `crypto.subtle.digest`

- **Relations**: Implements [TDD-00104](../tdd/TDD-00104.md) (Phase 1); extends [ADR-00024](ADR-00024.md)'s crypto namespace
- **Date**: 2026-08-23

## Context

`crypto.subtle` needs real cryptographic primitives. Per TDD-00104, they are
delegated to external native libraries behind a new compiler flag rather than
implemented in-house, with the backend seam designed so a future
self-contained implementation could slot in unchanged.

## Investigation

- The `-bigint` plumbing (`codegen/llvm/bigint.go`, TDD-00074) is the exact
  precedent: per-backend embedded C files implementing one shared ABI,
  written next to the `.ll` and compiled alongside, plus a locator for
  cflags/libs. `requireLink`'s doc comment (`emitter.go`) already named
  crypto.subtle as its intended next user.
- Homebrew's OpenSSL is keg-only: `brew --prefix` (LocateBigInt's posture)
  is not enough; `pkg-config libcrypto` first, then
  `brew --prefix openssl@3`, then bare `-lcrypto`.
- `crypto.subtle.digest(...)`'s receiver is a MemberExpression
  (`crypto.subtle`), not an Identifier — none of the existing
  namespace-dispatch guards in `emit_call.go`/`emit_exprs_types.go` matched
  that shape; a dedicated `isCryptoSubtle` helper was needed.
- Result promises: `Blob.arrayBuffer()`-style raw returns would break
  `.then()` chains. The `Promise.resolve` machinery
  (`emitAllocSettledPromise` + `storePromiseValue` + fulfilled state +
  `PromiseTask`, `emit_promise.go`) gives a settled task promise on which
  both `await` and `.then/.catch/.finally` behave — verified by test.

## Decision

- New flag `-crypto=openssl|commoncrypto` (default `openssl` on all
  platforms). `commoncrypto` is rejected outside macOS and with `--static`.
  Backend plumbing in `codegen/llvm/crypto.go` mirrors `bigint.go`:
  `CryptoBackends`, `CryptoBackendSource` (embedded
  `cryptosrc/crypto_openssl.c` / `crypto_commoncrypto.c`), `LocateCrypto`
  (commoncrypto needs no `-l` — symmetric primitives live in libSystem —
  just `-framework Security -framework CoreFoundation` for the SecKey-based
  asymmetric work of later phases).
- Shared ABI error contract: `0` ok, `-1` OperationError, `-2` DataError,
  `-3` NotSupportedError. `__kml_crypto_check(code, msg)` (IR helper,
  `runtime_crypto_subtle.go`) maps negatives to a thrown catchable error
  named with the matching DOMException name — the fetch error-object shape.
- Phase 1 ABI surface: `__kml_crypto_digest` (SHA-1/256/384/512; the
  CommonCrypto side chunks `CC_SHA*_Update` calls so the i64 length stays
  honest past `CC_LONG`) and `__kml_crypto_memeq` (constant-time compare,
  for later HMAC verify).
- `emit_call_crypto.go`: `isCryptoSubtle` dispatch, compile-time algorithm
  literals (string literal or object literal with a literal `name:` —
  anything else is a compile error), `emitCryptoBufferSource` (ArrayBuffer
  header load or `resolveArrayForHOF` with element-size scaling), digest
  results returned as fresh ArrayBuffers wrapped in settled task promises.
  Unimplemented subtle methods fail with an explicit
  "not implemented yet" compile error rather than falling through.
- `em.UsesCrypto()` gates writing/compiling the backend C file and its
  cflags/libs in `main.go` — programs that don't touch `crypto.subtle` gain
  no new dependency.

## Implementation notes

- `emitter.go` (fields + `SetCryptoBackend`/`CryptoBackend`/`UsesCrypto`),
  `main.go` (flag, validation, link block), `codegen/llvm/crypto.go`,
  `cryptosrc/*.c`, `runtime_crypto_subtle.go`, `emit_call_crypto.go`,
  `emit_call.go` (router), `emit_exprs_types.go` (Promise<ArrayBuffer>
  inference), `tests/compiler_test.go` (`appendCryptoBackend` in every
  build helper + `buildBinaryCryptoMode`/`compileAndRunCryptoMode` matrix),
  `tests/webcrypto_test.go`, `.github/workflows/release.yml` (libssl-dev).
- Every `ensure*` for a subtle ABI symbol sets `usesCrypto`, keeping the
  "declared exactly once" convention and the main.go gate in one place.

## Side effects discovered

- The TypedArray-constructor-in-expression-position limitation ("must be
  used in a variable declaration") shapes how subtle call results get
  viewed; tests/examples bind `new Uint8Array(buf)` to a variable first.

## Verification

Mac (Apple Silicon): known-answer digests of "abc" for all four hashes
match NIST vectors on **both** backends (`TestE2ESubtleDigestVectors`
matrix); `.then()` chaining, ArrayBuffer input, unknown-algorithm and
non-literal-algorithm compile errors, and flag validation
(`-crypto=bogus`, `--static` + commoncrypto) all covered by test or manual
run. `go build`, `go vet ./...`, full `go test ./...`, and the crypto
example rerun.
