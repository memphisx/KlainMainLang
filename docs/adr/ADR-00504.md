# ADR-00504: HTTP/2 over TLS server — `http2.createSecureServer`

- **Relations**: `Implements TDD-00111` (Stage 3b), `TDD-00139` (`createSecureServer`); `Extends ADR-00357` (h2c driver), `ADR-00344`/`ADR-00345` (TLS server CTX/ALPN)
- **Date**: 2026-08-29

## Context

`http2.createSecureServer` was the last clean rejection in the `http2` module,
and Stage 3b (h2 over TLS) was the sole remaining item on TDD-00111. Real-world
HTTP/2 is served over TLS — browsers speak h2 only over TLS, negotiated via ALPN
— so a secure server closes the gap between the shipped h2c driver and how h2 is
actually deployed. It also unblocks the 22 Node-oracle files that construct
`http2.createSecureServer`.

## Investigation

The C layer was already TLS-ready. `http2src/http2.c`'s
`__kml_h2_session_server_new(fd, io, rd, wr)` (ADR-00357) takes an optional
transport handle plus read/write shims — `io == NULL` means raw-fd I/O, non-null
routes every `conn_read`/`conn_write` through the shims. `tlssrc/tls.c` already
had the whole server side from Stage 2: `__kml_tls_server_ctx` (with an
`alpn_select_cb` that prefers `h2`), `__kml_tls_server_accept` (blocking
`SSL_accept`), `__kml_tls_alpn_selected`, and `__kml_tls_read`/`_write`/`_free`.
So no C changes were needed — the whole task was Go/IR plumbing.

The h2c path detects the connection preface inline in the shared 1.1 connection
fiber (`emitHTTP2PrefaceDivert`, `emit_http.go`) and drives the session with
blocking `recv`/`send` reading the raw fd. The 1.1 read/write event loop
(`__kml_event_loop_run`, `runtime_http.go`) is hand-written IR over raw fds and
is not SSL-aware. Making the whole 1.1 loop TLS-capable (an HTTPS/1.1 server)
is a much larger change and a distinct feature — Node draws the same line:
`http2.createSecureServer` defaults to `allowHTTP1: false` (h2-only), and
HTTPS/1.1 lives in a separate `https.createServer`. So the faithful, contained
scope is an h2-only secure server; the 1.1-over-TLS fallback (`allowHTTP1`) and
`https.createServer` are follow-ups.

## Decision

`http2.createSecureServer({ cert, key }[, handler])` builds a server `SSL_CTX`
from the PEM options and stores it in a new module global `@__kml_http_tls_ctx`,
then delegates to the shared `emitHTTPCreateServer` — so the handle,
`listen`/`close`/`address`, the compat `(req, res)` API, and the `.on('stream')`
streams API are all inherited unchanged, exactly as `http2.createServer` inherits
them.

The event loop's `doaccept` block gains a gated TLS branch (spliced only when
`usedH2TLSServer`, so a plain http server links neither libssl nor nghttp2 nor
pays a runtime branch). When `@__kml_http_tls_ctx` is non-null, a freshly
accepted fd — still blocking, before the non-block switch — is:

1. TLS-handshaken via `__kml_tls_server_accept` (blocking `SSL_accept`);
2. checked for the negotiated ALPN protocol (`__kml_tls_alpn_selected`,
   `memcmp` against a `"h2\0"` constant);
3. if `h2`, driven as an nghttp2 session
   (`__kml_h2_session_server_new(fd, ssl, @__kml_tls_read, @__kml_tls_write)`)
   with the same send/want/recv loop the h2c divert uses — but over the SSL
   shims, and with no preface `feed` (ALPN already told us it's h2);
4. anything else (no ALPN, or `http/1.1`) is closed — Node's `allowHTTP1:false`
   default.

The connection never joins the fiber conn table: the drive runs inline to
completion, then closes. So a secure server handles one connection at a time —
the V1 blocking-drive posture the h2c path already takes, one notch stricter
(serialized rather than one-blocking-fiber-among-many).

## Implementation notes

- `emitHTTP2CreateSecureServer` (`emit_tls.go`) calls `ensureH2TLSServer` (which
  sets `usedH2TLSServer`/`usedTLS`/`usedHTTP2` and emits the ctx global + ALPN
  constant) **before** the handler wiring triggers `ensureHTTPRuntime`, because
  the event loop is emitted once, lazily, on the first server call — the flag has
  to be set in time for the loop to include its TLS branch. The single-server
  rule (one `http.listen`/server per program) makes the plain-server-emitted-first
  ordering edge moot.
- The `__kml_tls_*` extern decls are centralized in `emitTLSNetSymbols`, now also
  gated on `usedH2TLSServer` (and it declares `__kml_tls_alpn_selected` there),
  so a secure server that uses neither `net` nor the WebSocket client still gets
  them exactly once — the duplicate-declaration trap hit during development.
- The `{ cert, key }` parse (inline literal or a variably-bound options object)
  was extracted from `emitTLSCreateServer` into the shared `emitCertKeyPtrs`.
- `inferExprType` maps `http2.createSecureServer` to `HTTPServerType()`, same as
  `createServer`, so `const s = http2.createSecureServer(...)` resolves `.listen`.

## Side effects discovered

- The `_index.json` http2 summary was still describing the module as "Stage 1
  … streams/sessions/createSecureServer are clean rejections" — long stale after
  TDD-00139's four stages. Corrected while touching the page.
- `allowHTTP1: true` (1.1-over-TLS inside the h2 server) and `https.createServer`
  (HTTPS/1.1) remain unimplemented, now tracked as the residual TDD-00111 items.

## Verification

- New E2E `TestE2EHTTP2SecureServer` (`tests/http_test.go`): compiles a
  `createSecureServer({cert,key}, (req,res)=>…)` over a self-signed fixture,
  `curl -sk --http2` negotiates h2 (`http_version=2`, correct body); a
  `--http1.1` client is dropped (curl exits non-zero) and the server survives to
  serve h2 again.
- Manual: the `.on('stream')` streams API over TLS returns `HTTP/2 201`, a custom
  response header, and the correct body (verified on Mac).
- `go test` http/tls/net/websocket/fetch suites pass; `go vet` clean;
  `make status-check` OK.
