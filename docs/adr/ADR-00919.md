# ADR-00919: Promise rejection reasons carry the real thrown value

- **Relations**: Implements TDD-00207; Extends ADR-00202 (caught-value record)
- **Date**: 2026-09-12

## Context

A rejected promise dropped or corrupted its reason for every non-Error value.
Repros (vs Node):

- `Promise.reject("x").then(_, e => console.log(e))` → printed empty; Node: `x`.
- `Promise.reject(42).catch(e => …)` → `e` empty; Node: `42`.
- `new Promise((_, rej) => rej(42))…` → **invalid IR** (`double` stored where a
  `ptr` reject arg was expected).
- An `async` fn that `throw`s a non-Error, or `await`s a rejected promise,
  surfaced an `Error` wrapper instead of the real value.

The handover flagged this as a suspected segfault ("then-handler gets 5e-324");
the staged work had already turned the crash into value-loss. Root cause: the
rejection reason was modeled as a single ptr-shaped slot (v0) assumed to be an
`Error`; `Promise.reject` wrapped every value in a synthetic `Error{message:…}`,
and the `.then`/`.catch` reject handler received a raw `ptr` it could not read
back as the original value.

## Investigation

A rejection is the async twin of a `throw`, and `try/catch` already solved
"hold an arbitrary thrown value" with the **caught-value record** (`{ i8 tag, i64
payload }`, `TypeCaught`, ADR-00202 / TDD-00202), complete with typeof /
instanceof / member / toString / console support (`emit_caught.go`). The task
promise struct `{ i64 state, ptr waiter, i64 v0, i64 v1, ptr reactions }` already
has a spare slot on the rejected path — `v1` is only used by *fulfilled* two-slot
(array) values — so the reason fits with no struct growth: `v0` = payload, `v1` =
tag.

A second, pre-existing bug surfaced while testing: an **unannotated `async`
function** never had its signature return type wrapped in `Promise`
(`buildFunctionSig`), so `h().then(…)` / `g().catch(…)` failed with "a number has
no method 'then'" and `await f()` of a throwing `f` took the wrong branch. Only
`Promise<T>`-annotated async fns worked.

## Decision

Route every rejection reason through the caught-value channel.

- New helpers (`emit_reject_reason.go`): `emitValueToCaughtParts` (value →
  `(tag,payload)`, Error → tag 13, else NaN-box split — the single source of
  truth, also now used by the value→`TypeCaught` coercion so a reassigned catch
  var keeps Error-ness); `storeRejectReason`/`storeRejectReasonI64Tag`
  (payload→v0, tag→v1); `loadRejectReasonCaught` (rebuild a `TypeCaught`).
- `__kml_task_alloc_promise` defaults v1 to `kmlTagError`, so every legacy path
  that rejects with just an errorObj ptr in v0 reads back as a caught Error; a
  non-Error reject overrides v1.
- Write sites store `(tag,payload)`: `Promise.reject`, the `new Promise`
  `reject` thunk (param now the `{i8,i64}` caught record), the async
  catch-and-settle epilogue (from the throw channel's `get_thrown_tag/pay`), the
  async-generator reject, and the pooled-fs worker (`klainpool.c` sets
  `v1 = kmlTagError` on reject).
- Read sites reconstruct/rethrow: the `.then`/`.catch` runner passes a `{i8,i64}`
  reason to `onR` and propagates v1 on a no-handler reject; `await` and the
  Promise.all/race rethrow via `__kml_throw_any(tag,pay)`; `allSettled` renders
  the reason through the caught toString.
- The reject handler param is `TypeCaught`. An `any`/`unknown`-annotated param is
  treated the same (lenient). A concretely-annotated handler (`string`/`Error`/…)
  is wrapped in an adapter closure that coerces the caught reason to the declared
  param type, so the runner's uniform `{i8,i64}` ABI always matches.
- `buildFunctionSig`/`buildErasedFunctionSig` wrap an async function's inferred
  (unannotated/bare/never) return type in `PromiseOf`.

## Implementation notes

- `inferExprType`'s MemberExpression gained a caught-object branch mirroring
  `emitCaughtMemberGet`'s result type — without it a reject handler like
  `(e) => (e as Error).name` had its declared return type (i64) disagree with its
  body's IR (ptr), emitting `ret i64 <ptr>`. This is the recurring two-site
  gotcha (emit ↔ inferExprType must agree).
- `coerciblePure` accepts any value into a `TypeCaught` target (a reason can be
  anything), so `rej(42)` type-checks.
- The `allSettled` reject arm pins its phi predecessors with explicit trailing
  labels, because the caught toString now introduces its own blocks.

## Side effects discovered

- A thrown/rejected **static object** loses its field shape through the throw
  channel (`.catch((e:any) => e.code)` reads undefined) — a pre-existing
  TDD-00202 limitation, now consistent between `try/catch` and rejections rather
  than a separate breakage. `Promise.any`'s `AggregateError.errors` still reads
  each member reason as an errorObj ptr (faithful for Error/string reasons).
  Both tracked in TDD-00207's open questions.
