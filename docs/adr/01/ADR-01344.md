# ADR-01344: A `@lower` target can be a TypeScript function; template objects carry `raw`

- **Relations**: Implements TDD-00230 (P3.2), Extends ADR-00562, ADR-01203, ADR-00152
- **Date**: 2026-10-03

## Context

TDD-00230 P3.2 says a `@lower` target "may name a C function or a function
of the TypeScript builtin library", and lists array and object arguments as
open. `String.raw(template, ...substitutions)` is the first builtin that
needs both. Called as a function it failed to compile ("String has no
method 'raw'"). Only the tag form worked, through its own emitter.

Two related gaps were documented caveats. A user tag's `strings` had no
`raw`. The strict lane never checked a tag call's arguments, so a
`strings: string[]` parameter compiled where tsc reports TS2345.

## Investigation

- Global modules (ADR-01203) link only exported classes and constants.
  The resolver brings a module in when the program names one of them.
- The C path would have to read a boxed object's members and a boxed
  array's elements, and convert each with ToString. The `any` member read
  is generated per kind, so C has no stable entry point for it. In
  TypeScript, the same function is a few lines of the spec's algorithm,
  and the normal call path already passes objects, arrays and rest
  arguments.
- Writing the function exposed three compiler bugs:
  - An index into a string held in `any` (`s[0]`) read `undefined`. The
    `any` member dispatch had no string arm for an index.
  - `arr[0] === arr[1]` was false for the same nested array. An element
    read's type carries `IsUndefined`, so the array-vs-nullish arm took it
    for `=== undefined`.
  - The checker related `readonly T[]`, and any type without `push`, to a
    mutable array as "maybe". So `const b: string[] = ro` compiled, where
    tsc reports TS4104 and TS2740.

## Decision

1. **A `@lower` target can be a TypeScript function.** A global module
   exports it, marked with the dotted path a program must name:
   `export function __kml_String_raw(…) … // kml:lower String.raw`.
   - `lib.LoweredFuncUses` maps it to its identifiers. The resolver
     includes the module when the program names all of them.
   - `loweredCallDecl` sees the declaration's `@lower` in the global links.
     The call is then an ordinary call of the linked function, with the
     receiver, if any, as its first argument (`lowering.libFn`).
   - Arguments follow the TypeScript function's parameter types. So an
     object, an array or a rest argument needs no marshaling. The user's
     call is still checked against `lib/es.d.ts`.
2. **`String.raw` is TypeScript** (`lib/node/kml_string.ts`), as ECMA-262
   §22.1.2.4 gives it: ToObject of the template and of its `raw`, ToLength,
   and ToString of each piece. So any array-like works. The tag's
   dedicated emitter is deleted: a `String.raw` tag is a tag call like any
   other.
3. **Template objects.** A tagged template's first argument is the site's
   template object (the `%TemplateObject%` intrinsic).
   - It is built once per site into a cache global (GetTemplateObject's
     template map), so every call gets the same object.
   - The cooked array's header is registered with its raw array in a
     runtime table (`__kml_template_register` / `__kml_template_raw` in
     `dynjson.c`, under a spinlock for worker isolates).
   - `strings.raw` on a `TemplateStringsArray` reads the table. So does
     `raw` on a string array held in `any`, which `String.raw(strings,
     ...v)` inside a tag needs.
4. **Index into a string held in `any`:** a canonical index reads that
   character (`__kml_str_get_by_key`), `undefined` past the end.
5. **Array identity:** a nullish operand that is itself an array is not
   nullish for the array-vs-nullish arm. Two arrays compare by header.
6. **Checker.**
   - A tagged template is checked as its call: `TemplateStringsArray`
     against the first parameter, each substitution against the next ones.
   - An interface or instance type that has `length` and no `push` is not
     assignable to a mutable array.

## Implementation notes

- **Lowering:** `lib/lib.go` (`exportedLoweredFunc`, `LoweredFuncUses`),
  `resolver/resolver.go`, and `codegen/llvm/emit_lowered.go` (`libFn`,
  `libCall`).
- **Templates:** `codegen/llvm/emit_call.go` (`desugarTaggedTemplate`,
  memoized per node so the site global is stable, plus
  `emitTemplateObject` and `emitTemplateRaw`), `emit_exprs.go`,
  `emit_exprs_types.go`, `emit_exprs_member.go` and `emitter.go`.
- **Runtime:** the string index arm and `isCanonicalIndex` are in
  `codegen/llvm/emit_dynobj.go`. The table and the string and `raw` reads
  are in `codegen/llvm/dynjsonsrc/dynjson.c`; `dynjson_c.go` declares
  them.
- **Array identity:** `codegen/llvm/emit_exprs_operators.go`.
- **Checker:** `checker/check.go` (`checkTaggedTemplate`) and
  `checker/relate.go`.
- **Library:** `lib/es.d.ts` and `lib/node/kml_string.ts`.
- **Test harness:** `tests/compiler_test.go` resolves a program that
  names a lowered function's path.

## Side effects discovered

- tsc reports a readonly array where a mutable one is expected as TS4104,
  showing the type as `readonly string[]`. Here it is the general
  not-assignable error, showing `ReadonlyArray<string>`.
- A template object is not frozen. A tag that mutates `strings` changes
  later calls of the same site.

## Verification

Mac (Apple Silicon), against Node v24.19:
- the reduced programs: `String.raw` called with an array, an array-like,
  a string `raw`, `null` and `{}`; `strings.raw`; `String.raw(s, ...v)`
  in a tag; per-site identity; the `any` string index; array identity;
  and the same programs under `-compat=js`;
- new tests `TestE2EStringRawCallAndTemplateRaw`,
  `TestE2EAnyStringIndexAndArrayElementIdentity` and
  `TestE2ETaggedTemplateMutableStringsParamRejected`. The tagged-template
  tests now type `strings` as `TemplateStringsArray`;
- `examples/tagged_templates` matches Node;
- the checker test binary under the memory guard, and the `lib`,
  `resolver`, `sema` and `codegen/llvm` unit tests.
