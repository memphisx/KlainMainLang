# ADR-00749: Windows — SIGWINCH (console resize) via a watcher thread

- **Relations**: Implements a [TDD-00180](../tdd/TDD-00180.md) §2 row; extends [ADR-00728](ADR-00728.md) (the Windows signal-queue/`__kml_win_sig_deliver` cross-thread path this reuses), [TDD-00031](../tdd/TDD-00031.md)/[ADR-00719](ADR-00719.md) (the `SIGWINCH` handler surface)
- **Date**: 2026-09-07

## Context

`process.on('SIGWINCH', …)` registered a handler on Windows but it never fired — Windows has no `SIGWINCH` signal, and the audit recorded "SIGWINCH has no console equivalent." Node (libuv) runs a console-resize watcher thread and delivers the event on the loop thread, so a TUI can re-read `process.stdout.columns`/`.rows` on resize.

The obstacle was cross-thread delivery: the IR records the event in a **thread-local** pending flag the reactor polls, which only works when the handler runs on the main thread. A watcher thread cannot set that TLS slot. But ADR-00728 already solved exactly this for the console Ctrl handler (also a foreign thread): a global `kml_sig_queued[]` array set with `InterlockedExchange`, drained by `__kml_win_sig_deliver` **on the installing thread** (from the `select`/`nanosleep` waits), which runs the registered handler there — setting the TLS flag on the right thread.

## Decision

`signal(28, handler)` in `win32proc.c` starts a resize-watcher thread once (and marks the signal machinery installed on the calling/main thread, as the Ctrl path does, since a SIGWINCH-only program has no SIGINT to do it). The thread polls `GetConsoleScreenBufferInfo` every 200 ms — a **read-only** query that consumes no console input, so it never races the raw-mode reader — and on a window-size change queues signal 28 via the same `InterlockedExchange(&kml_sig_queued[28], 1)` + wake path the Ctrl handler uses. `__kml_win_sig_deliver` then runs the IR's handler on the main thread, and the existing loop machinery fires the `SIGWINCH` closure. No console (piped/file) → the watcher exits immediately, since no resize is possible.

## Consequences

- `tests/tty_resize_windows_test.go`: a program with a `SIGWINCH` handler and a `setTimeout` to stay alive prints the new `columns`×`rows` when the pseudo-console is resized mid-run — verified on Windows 11. The ConPTY harness gained a `conptyResize` helper (`ResizePseudoConsole`), test-only.
- Reuses the proven ADR-00728 cross-thread queue, so no new concurrency surface beyond one polling thread doing read-only console queries; the signal/tty/console/child_process suite passes unchanged.
- 200 ms poll latency on resize (libuv is event-driven via the console input thread, but that path would contend with the raw-mode reader here; polling is the safe choice). Recorded as a minor fidelity gap, not a behavioural divergence.
- This closes the last targeted §2 console row; remaining Windows items in TDD-00180 are the exit-code width (touches the cross-platform status ABI) and the CRT fd table (its own structural TDD).
