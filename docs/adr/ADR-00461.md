# ADR-00461: number index signatures

- **Relations**: Extends [TDD-00130](../tdd/TDD-00130.md)'s string index signatures
- **Date**: 2026-08-29

## Context

`only a string index signature is supported` marked 33 TS-oracle
false-rejects, plus a share of `expected ], got :` (the class-body form).
JS numeric object keys *are* strings, so `[i: number]: T` can share the
string signature's entire map-backed machinery.

## Decision

- `parseIndexSignature` accepts a `number` key.
- Every map-backed dynamic-object key site stringifies a numeric key:
  a new `dynObjectKeyExpr` normalizer wraps numeric keys in a synthetic
  `String(...)` at the literal/get/assign paths, and the `Map<string,…>`
  bracket read converts an already-evaluated numeric key via
  `emitValueToString`. Reads of an absent key stay `null` (the usual
  `undefined` stand-in).
- The class-body form (`class C { [n: number]: T }`) remains a parse
  rejection — classes have fixed field layouts, no map backing (disclosed
  caveat).
- TDD-00130's `TestE2EIndexSignatureNumberKeyRejected` becomes a positive
  E2E of the new behavior.
