# ADR-02072: A compile holds one copy of the module's text

- **Relations**: Implements TDD-00248, TDD-00230
- **Date**: 2026-11-24

## Context

The macOS conformance lanes for the Node suite and the WPT js lane were
stopped by the 3 GB memory guard. The runner compiles in-process, and its
heap grew to 2.4 GB on Linux x86-64 within the first seconds of the WPT
js lane; at HEAD it reached 2.7 GB.

An 11 KB WPT test emits a 66 MB module: the program's own unit is 2.5 MB,
the rest is the builtin library's 1,649 units, emitted with every program
and split into cached objects. A compile of that test peaked at 313 MB
of live heap (596 MB RSS).

## Investigation

A heap profile taken at each new live peak (after a collection) showed
the module's text held several times over while it was split:

- `LibObjects` read the `.ll` file back (63 MB) while its caller still held
  the same text.
- The emitter kept `finalIR`, the text before the managed-space and
  ASCII-locals passes, beside the text it returned (60 MB).
- `parseIREntities` split the module into lines and joined each
  definition's lines into a new string: a second copy (36 MB) and a
  16-byte header per line.
- `splitUnits` built every unit's text before any was compiled (76 MB in
  all).
- Module assembly kept the function builder (65 MB) alive while the output
  builder grew past its estimate (the `notail` each call gains), which
  copied it once more.

## Decision

- `eachUnit` splits as `splitUnits` did and hands each unit to a callback
  as it is built, modules in key order and then the program's.
  `splitUnits` collects through it; `LibObjectsOf` compiles each unit (or
  finds it in the cache) and drops it.
- `LibObjectsOf` takes the IR its caller holds; `LibObjects` reads the
  file and calls it. The CLI and the conformance runners call
  `LibObjectsOf`, and write the `.ll` with `WriteTextFile`, which does not
  copy the text into a byte slice.
- `EmitProgram` stores the text it returns in `finalIR`.
- `parseIREntities` takes each entity as a slice of the module's text.
- Module assembly releases the function builder once copied and sizes the
  output for a sixteenth more than its parts.

## Consequences

- The WPT test's compile: 313 MB live peak to 179 MB, 596 MB RSS to
  307 MB. The runner's WPT js peak: 2.38 GB to 1.36 GB (HEAD 2.71 GB).
- Unit texts are unchanged: all 1,719 cache keys (hashes of the unit
  texts) of a cold compile match the previous compiler's, and
  `parseIREntities` returns identical entities on the 66 MB module and on
  hand-made edge cases (no trailing newline, empty input).
- The library's text is still emitted with every program; caching it
  without emitting it is TDD-00248's remaining work.
- Verified on Node304 (Linux x86-64).
