# ADR-00498: fd-based fs ops (openSync/closeSync/readSync/writeSync/fstatSync)

- **Date**: 2026-08-29

## Context

The Node corpus's most-called missing fs surface after ADR-00497 is the
raw-fd family (openSync 84 call sites, closeSync 86, writeSync 27,
readSync 22, fstatSync 17).

## Decision

Five fd ops over POSIX open/close/read/write/lseek/fstat:
`openSync(path[, flags[, mode]])` maps a compile-time flags string
literal (`r r+ w w+ a a+ wx ax`) to the host's O_* bits (Darwin and
glibc disagree past O_RDWR — per-OS constants in `openFlagBits`),
numeric flag expressions pass through, mode defaults 0o666;
`writeSync(fd, string[, position])` (string data only — no
Buffer/offset variant); `readSync(fd, buffer[, offset, length,
position])` into a Uint8Array/Buffer; positioned forms lseek first;
`fstatSync` reuses the statLayout extraction and Stats object. Failures
throw the shared fs error; a failed read/write can't name its path (fd
only), so its message carries no path.

## Verification

Mac (same Linux-offsets caveat as ADR-00495 for fstatSync).
`tests/fs_test.go` `TestE2EFsFdOps` (write/read round-trip, positioned
read, fstat size/kind, open throw) passes; fs batch green;
`examples/fs/fs.ts` extended and re-run.
