# ADR-00352: Object type arguments in generics (structural instantiation mangling)

- **Relations**: Implements [TDD-00069](../tdd/TDD-00069.md); extends [TDD-00010](../tdd/TDD-00010.md), [TDD-00037](../tdd/TDD-00037.md)
- **Date**: 2026-08-25

## Context

User-defined generics monomorphize, but a concrete type argument could only be a
scalar or a one-level array of scalars — `mangleTypeArg` rejected any object/
interface/class type. That excluded the most common real generic pattern (a
helper or container over a record type), and was the blocker under a constrained
generic like `<T extends { id: number }>`.

## Investigation

TDD-00069's plan was to mangle a named object/interface type by a `Type.Name`
field. Probing that empirically: **`Type` has no `Name` field** — a resolved
named interface is a structural `ObjectType` carrying only its `Fields`, with no
surviving name (Open Question #1, answered: nominal identity is not available at
the mangling site). So a name-based mangle can't work.

## Decision

Mangle an object/interface type argument **structurally**: a deterministic,
LLVM-safe encoding of its field count then each field's name and (recursively
mangled) type, in declaration order (`mangleObjectStructural`, emit_generics.go).
A **class** type argument mangles by `ClassName` (which classes do carry, and
which the per-instantiation body needs for method dispatch). Everything
downstream already works: the body is emitted per-instantiation against the
concrete shape's real `Fields`/`FieldIndex`, so field access, destructuring,
`T[]`, and passing/returning `T` all ride existing machinery unchanged.

Structural mangling is strictly stronger than the TDD's nominal-only V1 plan: it
also handles an anonymous inline object type and a bare object-literal argument
(`f({ x: 1 })`), since two structurally-identical shapes correctly share one
monomorphization (they produce identical code). A field whose own type is an
unsupported argument type (Map/Set/Promise/closure) propagates the existing
rejection.

## Scope

- **In:** a named or anonymous object/interface type, and a class type, as a
  generic type argument (function inference from `T`/`T[]`; `new C<Obj>()`;
  `C<Obj>` annotations); bare `T` and one-level `T[]` substitution (the existing
  depth limit).
- **Out (unchanged):** Map/Set/Promise/closure/dynamic type arguments; nesting a
  type parameter deeper than one array level.

## Verification

- `tests/generics_test.go`: interface arg, `T[]` arg, `new Box<Point>()`,
  anonymous object-literal arg, and coexisting scalar instantiations; the former
  "object arg rejected" test repurposed (object args now work; a Map arg is the
  new still-unsupported rejection case).
- `examples/generics/generics.ts`; `make examples`; `go test ./...`;
  `make conformance`.
- Machine: verified on Mac (arm64).
