# ADR-00652: `null ?? x` yields the right operand's type; a ptr|non-ptr `??` union rejects cleanly

- **Relations**: `Implements TDD-00162` (the coerce-honesty prerequisite it names), `Extends ADR-00651`
- **Date**: 2026-09-03

## Context

ADR-00651's strict incompatible-reassignment guard relies on a coerced value's
`Ty` honestly matching its register's LLVM type. One case slipped through —
`var x; x = undefined; x = (null ?? 42) || 43` still emitted invalid IR
(`floating point constant invalid for type` → `store ptr 0x4045000000000000`).

The offender was the `??` emitter (`emitNullCoalesce`, emit_exprs_operators.go),
not `coerce` in general. For a ptr-typed left operand it allocates a single
`ptr` result slot and, in the null branch, stored
`e.coerce(right, TypePtr)`. When the right operand is a non-ptr scalar
(`42` → a `double`), `coerce(number, ptr)` has no conversion and falls through
returning the value *unchanged* (a `double` register) — which the next line
stored as `store ptr <double>`, invalid IR. For `null ?? 42` the left is
literally `null`, so the result type should be the right operand's (`number`),
never the left's null-(ptr) type.

## Decision

Two changes in `emitNullCoalesce`:

1. **`null ?? x` / `undefined ?? x` fast path.** When the left operand is
   statically nullish (`left.Ty.IsNull || left.Ty.IsUndefined`), the whole
   expression *is* the right operand — return `emitExpr(ex.Right)` with the
   right's own type. Matches JS (`null ?? 42 === 42`) and keeps the IR
   well-typed. (A nullish literal has no side effects, so re-evaluating the
   right after emitting the left costs nothing observable.)

2. **Checked coercion for a genuine ptr|non-ptr union.** The remaining
   ptr-slot path now stores `coerceChecked(right, TypePtr, …)` instead of
   `coerce`. A nullable-ptr left with a non-ptr right (`str | null ?? 42`) is a
   real `ptr | number` union the single-`ptr` result slot can't represent — a
   clean compile error now, not an invalid `store ptr <double>`. A ptr right
   (`str ?? "def"`) coerces to the same IR and is unaffected.

## Investigation

With this fix the Test262 `language/expressions/coalesce/...` file that started
the trace compiles clean, and `(null ?? 42) || 43` no longer emits invalid IR
(in strict it yields the `||` bool per the existing documented caveat; under
`-compat=js` `||` is value-preserving). Combined with ADR-00651, the
`language/expressions` invalid-IR cluster is now either compiling or cleanly
rejected rather than emitting bad IR.

## Side effects discovered

None. The nullish suite (literal/typed/chained/nullable-scalar left operands)
and the full `go test ./tests/` pass — the fast path only fires on a
statically-nullish left, and `coerceChecked` only rejects a right operand whose
IR the ptr slot could never have stored soundly.
