# TDD-00097: Streams — WHATWG core, fetch body streaming, Node `stream` module

- **Status**: Implemented
- **Date**: 2026-08-22
- **Notes**: First genuinely incremental data path: ReadableStream/WritableStream/TransformStream as fused opaque handles over the promise/microtask runtime; backpressure (HWM + pull scheduling + writer.ready) closed in the design, pipeTo as a pure promise-reaction state machine (no fiber). Staged: WHATWG core → pipe/transform/tee → fetch `Response.body` (curl pause) → http chunked → zlib streams → EventEmitter lifts → Node `stream` classes. BYOB/byte controllers out of scope (no ArrayBuffer detach semantics)

## Context

Every data path in this compiler is buffered end-to-end: `fetch` accumulates the
whole response body before the promise settles, the HTTP server reads a request
fully (10 MiB cap) and writes a single materialized response, `fs` is entirely
synchronous, and `TextDecoder` has no streaming mode. [STREAMS.md](../status/STREAMS.md)
is 0/8, and it blocks a cluster: `Blob.stream()`, `CompressionStream`/
`DecompressionStream`, incremental fetch bodies, chunked HTTP responses, and
Node's `stream` module.

The reason it was never scoped — the WHATWG backpressure model — no longer has a
scheduler prerequisite: microtask-accurate `await` (TDD-00088/ADR-00268), promise
reactions on a microtask FIFO (ADR-00263), reusable promises (ADR-00270), async
generators with `Symbol.asyncIterator` (ADR-00283/00269), and a unified event
loop (ADR-00250) are all in place. Streams are a state machine over exactly those
primitives.

Grounded target — this must work, chunk at a time, without buffering the whole
sequence:

```ts
const upper = new TransformStream<string, string>({
  transform(chunk, controller) { controller.enqueue(chunk.toUpperCase()) }
})
await readable.pipeThrough(upper).pipeTo(writable)
```

and, with one real producer so the surface has actual users from day one:

```ts
const res = await fetch(url)
for await (const chunk of res.body) { /* Uint8Array chunks as they arrive */ }
```

## Design

### D1 — Representation: opaque runtime handles, fused controller

A stream and its controller are **one** malloc'd hidden heap struct (the
opaque-handle idiom of `EventEmitter`/`ArrayBuffer` — deliberately not
`IsObject`, so `Object.keys`/JSON never see it). The "controller" value passed
to user callbacks is the stream pointer itself, typed differently at compile
time. All state-machine logic lives in IR-text runtime helpers in a new
`codegen/llvm/runtime_streams.go` (emitted only when streams are used);
compiler-side lowering in a new `codegen/llvm/emit_streams.go`.

`%kml.rstream` (ReadableStream + default controller):

| field | type | purpose |
|---|---|---|
| state | i32 | 0 readable · 1 closed · 2 errored |
| err0, err1 | i64 ×2 | stored error (two-word value idiom, as in promise v0/v1) |
| qData, qCap, qHead, qLen | ptr + i64 ×3 | chunk FIFO, head-index pattern from runtime_microtask.go; entry = 24 B `{v0 i64, v1 i64, size double}` |
| queueTotalSize | double | Σ entry sizes |
| hwm | double | high-water mark (default 1) |
| sizeFn, sizeEnv | ptr ×2 | size algorithm closure; null ⇒ every chunk counts 1 |
| pullFn/Env, cancelFn/Env | ptr ×4 | underlying-source closures (16 B `{funcPtr, envPtr}` headers) |
| flags | i64 bitfield | started, pulling, pullAgain, closeRequested, disturbed, locked |
| rdData, rdCap, rdHead, rdLen | ptr + i64 ×3 | FIFO of pending `read()` promise ptrs (reusable 40 B promises, ADR-00270) |
| closedPromise | ptr | backs `reader.closed` |
| pipeCtx | ptr | null unless piping/teeing |

`%kml.wstream` is analogous: state i32 (0 writable · 1 closing · 2 erroring ·
3 errored · 4 closed), stored error, the same-shape write queue (an entry with a
sentinel size marks the close request), queueTotalSize/hwm/sizeFn, sink closures
writeFn/closeFn/abortFn, locked flag, `readyPromise` (re-armed on backpressure
flips — reusable-promise semantics make this natural), `closedPromise`,
inFlightWrite flag, per-write pending promise FIFO.

`%kml.tstream` = `{readable ptr, writable ptr, transformFn/Env, flushFn/Env}`.
The writable side's sink-write invokes the transform with the *readable* side's
controller; the writable side's `desiredSize` reports from the readable queue
(the spec's backpressure coupling), so a slow consumer throttles the producer
through the transform with no extra machinery.

Chunks are stored as raw i64 bit-patterns (the Map-value idiom); array-shaped
values (`Uint8Array` = `{ptr, i64}`) use both words. `read()` fulfills its
promise with a pointer to a malloc'd 24 B record `{v0 i64, v1 i64, done i64}`;
the call site unpacks `.value`/`.done` from the static chunk type. The runtime
is fully type-agnostic — all bitcasts happen at enqueue/read lowering.

### D2 — Backpressure (closed here, not deferred)

- `desiredSize = hwm − queueTotalSize`; null when errored, 0 when closed
  (`__kml_rs_desired_size`).
- **Pull scheduling** per the spec's *CallPullIfNeeded*: shouldPull ⇔
  `state == readable && started && !closeRequested && (rdLen > 0 || desiredSize > 0)`.
  If `pulling` is set, set `pullAgain` and return; otherwise set `pulling` and
  invoke the pull closure. The pull closure is a compiler-built wrapper (via
  `buildBuiltinClosure`) that normalizes the user callback's return: a void pull
  counts as immediately fulfilled; a promise-returning pull gets a reaction that
  clears `pulling` and re-runs shouldPull if `pullAgain`. `start()` runs
  synchronously inside the constructor; the *first* pull is deferred one
  microtask (`__kml_microtask_enqueue`), matching spec timing.
- **Writer side**: `writer.desiredSize` from the writable queue; `writer.ready`
  is pending iff backpressure (desiredSize ≤ 0) or the sink's `start` hasn't
  settled; it re-arms on every flip. `write()` never blocks — it always
  enqueues and returns a per-write promise; the drain loop dequeues one entry,
  sets inFlightWrite, calls sink.write (same normalized-closure pattern), and
  advances on its settlement via a promise reaction. A sink error moves the
  stream to erroring→errored and rejects all queued write promises.
- **pipeTo** is a heap "pipe context" struct (reader, writer, preventClose/
  Abort/Cancel flags, optional `AbortSignal` ptr) driven *entirely by promise
  reactions* — read → await writer.ready → write → loop. No fiber, so pipeTo
  works under the promise runtime alone. Shutdown propagation per spec: source
  error → `writer.abort` (unless preventAbort); dest error → `reader.cancel`
  (unless preventCancel); source close → `writer.close` (unless preventClose);
  signal abort → both, and the pipe promise rejects with the abort reason.
  `pipeThrough` = pipeTo(transform.writable), return transform.readable.
- **tee()** (in scope, Stage 3): two branch rstreams over a shared tee context;
  a pull on either branch reads once from the source and enqueues into both
  branch queues; cancel of both branches cancels the source with a composite
  reason. No new backpressure architecture — fan-out over the finished core.

**Scoped out, with reasons.** BYOB readers / readable *byte* controllers: the
zero-copy path requires ArrayBuffer detach/transfer semantics that don't exist
here (TypedArrays have no `.buffer` back-reference); default readers carrying
`Uint8Array` chunks cover the code this project targets. Everything else in the
default-reader surface — including `{highWaterMark, size}` strategies,
`CountQueuingStrategy`, `ByteLengthQueuingStrategy` — is in scope.

### D3 — Frontend plumbing (standard builtin cost model)

- New AST nodes (`ast/nodes.go`) for `new ReadableStream(...)`,
  `new WritableStream(...)`, `new TransformStream(...)`, recognized by name in
  `parser/parser_literals.go`; type arguments hardcoded alongside
  `Promise`/`Map` in `parser/parser_types.go`. The underlying source/sink
  object literal is destructured **at compile time** into its named callbacks
  (start/pull/cancel · write/close/abort · transform/flush) plus the strategy
  (`highWaterMark`, `size`) — no generic object representation needed.
- New `Type` flags (`codegen/llvm/types.go`): `IsReadableStream` /
  `IsWritableStream` + `StreamChunk *Type`; `IsTransformStream` + `StreamIn`/
  `StreamOut`; `IsStreamReader`/`IsStreamWriter`; `IsRSController`/
  `IsWSController`/`IsTSController`. Method dispatch in `emit_call.go`
  narrower-flag-first; property reads (`.locked`, `.desiredSize`, `.readable`,
  `.writable`, `.ready`, `.closed`) in member lowering.
- `ReadableStream<T>` (a compiler-recognized generic builtin, like
  `Promise<T>`): T may be anything representable in ≤ 2 words — number, string,
  boolean, arrays/TypedArrays, object refs; anything wider is a compile error.
- `for await...of stream` and `stream.values()`: a thin async-iterator adapter
  over `getReader()`, plugged into the existing `Symbol.asyncIterator` protocol
  in `emit_generators.go`.

### D4 — Runtime tiers

A new `ensureStreamRuntime()` layers on `ensurePromiseRuntime` only. An
in-memory stream pipeline — including pipeTo, which is pure promise reactions —
must link **neither** the fiber scheduler **nor** libcurl. The task runtime is
pulled in only by what already pulls it in: a may-suspend `await` around
`reader.read()`, `for await...of`, or the fetch/http producers.

## Stages

Ordered by dependency; this document's first delivery is Stages 1–4.

1. **ReadableStream core (L).** Queue/HWM/size/pull machinery, `getReader()`,
   `read()`/`releaseLock()`/`cancel()`, `.locked`/`.closed`/`.desiredSize`,
   controller `enqueue`/`close`/`error`, queuing strategies,
   `ReadableStream.from(asyncIterable | array)`, `values()` + `for await...of`.
2. **WritableStream (M).** Writer lock, `write`/`close`/`abort`,
   `ready`/`desiredSize`/`closed`, in-flight write serialization,
   erroring→errored transitions.
3. **pipeTo/pipeThrough + TransformStream + tee() (L).** Pipe state machine
   with all four propagation rules, prevent* options, `AbortSignal`;
   TransformStream with transform/flush, identity default, backpressure
   coupling; `tee()`.
4. **fetch `Response.body` (M).** The curl write callback enqueues into an
   rstream and returns `CURL_WRITEFUNC_PAUSE` when desiredSize ≤ 0; the pull
   hook unpauses (`curl_easy_pause`) and nudges the event loop (the established
   scanned-resource pattern in the loop; no-op stub when fetch is absent).
   Buffered `.text()`/`.json()` keep their fast path; a consumed body is marked
   disturbed. Spike first: paused easy handles can delay multi timeouts on some
   libcurl versions; may need a forced socket-action kick.
5. **HTTP server streaming (M).** A handler response whose body is a
   ReadableStream ⇒ chunked transfer encoding, the connection fiber consuming
   reads via the event loop; then (5b) streaming request bodies, lifting the
   10 MiB buffer.
6. **CompressionStream / DecompressionStream (S/M).** TransformStream-shaped
   over a `z_stream` opaque handle; `-lz` linked only when used (same
   discipline as libcurl).
7. **EventEmitter lifts (M).** Prerequisites for Node streams: variadic /
   multi-type `emit`, subclass method override, `instanceof EventEmitter`.
8. **Node `stream` module (L).** `Readable`/`Writable`/`Duplex`/`Transform`
   base classes over EventEmitter (`'data'`/`'end'`/`'error'`/`'finish'`,
   flowing/paused modes, `.push()` from `_read`, `.pipe()`), then
   `stream.pipeline()`/`.finished()` and `stream/promises`. A thin compat
   layer over the WHATWG internals is *not* faithful enough — the event-driven
   flowing mode and overridable `_read`/`_write` are load-bearing in real Node
   code — hence the dedicated stage and its Stage-7 prerequisites.

`Blob` (and therefore `Blob.stream()`) stays with a future Blob/File design,
not here — it needs Blob itself, not stream machinery.

## Open questions

- **Stage 4 curl pause spike.** Whether `curl_easy_pause(CURLPAUSE_CONT)` from
  the pull hook reliably resumes transfers across the libcurl versions on both
  dev machines (GnuTLS vs Secure Transport backends), or needs a forced
  `curl_multi_socket_action` kick. Resolve by experiment before committing to
  the Stage 4 shape.
- **Conformance oracle.** Test262 contains no stream tests, so the corpus stays
  flat by construction; the real oracle is a WPT `streams/` slice via the
  TDD-00082 runner — deliberately a follow-up, not a gate on Stage 3.
- **Chunk identity across the queue.** Strings pass as pointers (no copy);
  whether enqueue should deep-copy array-shaped chunks to protect against
  producer mutation, or document JS-faithful reference semantics. Leaning:
  reference semantics (matches JS).
