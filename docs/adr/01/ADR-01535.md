# ADR-01535: The checker types an evolving `[]` array

- **Relations**: Extends TDD-00230, ADR-01530
- **Date**: 2026-10-10

## Context

A binding declared `const a = []` (or `let`) with no type was
unanswered in the checker: the strict lane accepted programs tsc
rejects (`a.push("s"); const n: number = a`, or such an array returned
and used as a number), and the codegen answered for it on its own.

## Decision

As tsc's evolving array:

- The declared type is an array of every element type stored to the
  binding anywhere (push/unshift arguments, a spread one's elements,
  numeric element stores, assigned arrays), `any[]` with none.
- A read follows the flow graph: each push/unshift call and element
  store on the binding adds its widened element types; an assignment
  replaces them; joins union them.
- A read where no element type reached it, or one in another function,
  is `any[]`: TS7034 at the declaration and TS7005 at the read (not in
  the js lane).
- The array of a push/unshift call, of an element store and of a
  `.length` read reads the declared type, as tsc's
  isEvolvingArrayOperationTarget.
