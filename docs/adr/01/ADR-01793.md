# ADR-01793: Runtime computed keys in object patterns

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- An object pattern accepted a computed key only as a string or number literal (`{ ["a"]: x }`). `{ [k]: x }` with any other key expression was a parse error, although JS evaluates the key when the pattern reaches it.
- The resolver's rename pass left defaults inside nested parameter patterns (`{ a: [p = k] }`) and nested declaration patterns unrenamed. A module-level name used there was then undefined.

## Decision

- `DestructProp.KeyExpr` holds a runtime key. Its value can be a name, a nested pattern, or either with a default.
- The binder, resolver, free-variable and capture scans, and the empty-array push inference visit it with the pattern's defaults. The resolver now rewrites nested pattern defaults through `rewriteArrayPatternDefaults` / `rewriteObjectPatternDefaults` for both parameters and declarations.
- Codegen reads a pattern with a runtime key through the boxed value. `emitPropertyKeyTemp` evaluates the key once as a property key: a symbol stays a symbol, anything else becomes its string. That key is used for the read and for a following rest's exclusion list.

## Consequences

- `TestE2EJSFileComputedPatternKeys` compares declarations, parameters, arrows with evaluation-order side effects, symbol keys, rest, nested patterns and methods against Node.
