# ADR-00362: `req.body` after `req.stream()` throws (body already disturbed)

- **Relations**: Extends [ADR-00301](ADR-00301.md), [ADR-00307](ADR-00307.md) (streaming request body). Implements part of [TDD-00097](../tdd/TDD-00097.md) Stage 5b's fidelity.
- **Date**: 2026-08-25

## Context

Reading `req.body` / `req.bodyBytes()` after `req.stream()` had already consumed
the request body returned only the pre-stream prefix — a documented caveat on the
`req.stream()` HTTP-Server row. WHATWG semantics are that a disturbed body throws
a `TypeError`. Third item of the HTTP-Server caveat-cleanup pass.

## Investigation

The per-request body context (`runtime_http_reqbody.go`,
`{ fd, remaining, bodyBuf, filled, stream, active }`) already records whether the
body was streamed: field 4 (`stream`) is non-null once `req.stream()` was called.
Both buffered accessors funnel through `__kml_reqbody_drain(ctx)` (`.body` via
`emit_exprs_member.go:511`, `.bodyBytes()` via `emit_http.go`'s
`emitRequestBodyBytes`), and that function already branched on `stream != null` —
it just fell through to a silent no-op (returning the prefix). So the disturbed
signal and the single choke point both already existed.

## Decision

In `__kml_reqbody_drain`, change the `stream != null` branch from a silent return
to a thrown `TypeError`: build the standard `{ i64 kind, ptr msg, ptr name }`
error object inline (kind 0, name `"TypeError"`, message
`"request body already consumed by req.stream()"`) and call `@__kml_throw`, then
`unreachable`. Because both `.body` and `.bodyBytes()` route through this one
function, both now throw. `ensureReqBodyRuntime` pulls in
`ensureExceptionHelpers` for `@__kml_throw`.

Only a *same-request* body-after-stream access is affected — a request that never
calls `req.stream()` has a null `stream` field and drains normally, and a program
that uses `.body` and `.stream()` on different requests is unaffected (separate
contexts).

## Implementation notes

- `runtime_http_reqbody.go`: one branch retarget + a `disturbed:` block appended
  at the end of `__kml_reqbody_drain` (placed last so the two new interned-string
  format args append cleanly without renumbering the existing ones).
- The throw is catchable ordinary control flow (the handler runs synchronously
  inside its fiber), so a `try/catch` around the access works as in real JS.

## Verification

- `TestE2EStreamsRequestBodyAfterStreamThrows` (new): a handler that streams the
  body then reads `req.body` inside `try/catch` returns `threw:TypeError`.
- `TestE2EStreamsRequestBodyStream` / `...BodyEcho` / `...BufferedAccessorsStillWork`
  still pass (the buffered accessors on non-streamed or separate requests are
  unaffected).
- `go build`/`go vet` clean.
