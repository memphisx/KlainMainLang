# ADR-01032: Windows `process.env` is the live wide environment; `os.homedir()` falls back to the profile directory

- **Relations**: `Implements TDD-00180` (§6); `Extends ADR-00724`, `ADR-00790`
- **Date**: 2026-09-21

## Context

Two §6 rows of the [TDD-00180](../tdd/TDD-00180.md) audit were still open.

`process.env` read through the UCRT's `getenv`, which is a **startup snapshot in the ANSI code page**. Three observable consequences: a variable set through the Win32 API (the spawn shim's markers, and — once [ADR-01030](ADR-01030.md) made `chdir` write them — the `=X:` drive directories) was invisible; a non-ASCII value was mangled on the way in; and a value *written* by the program was mangled on the way out to children (`_putenv_s` re-encodes UTF-8 bytes as ANSI).

`os.homedir()` threw when `USERPROFILE` was unset, where Node (libuv's `uv_os_homedir`) asks the process token for the profile directory.

## Investigation

libuv's `uv_os_getenv`/`uv_os_setenv`/`uv_os_unsetenv` are `GetEnvironmentVariableW`/`SetEnvironmentVariableW` with UTF-8 conversion at the boundary; lookup is case-insensitive because the OS's is.

The shim already replaces POSIX names the UCRT lacks; defining `getenv` there shadows the import for every emitted program and embedded C helper. Every caller in the tree copies the result immediately (`__kml_str_from_cstr` in the IR; `strcpy`/immediate use in the C helpers), so the C contract — the storage may be reused by a later call — is enough. A `_Thread_local` buffer keeps Workers apart.

A first version wrote the OS block and then called `_putenv_s` to keep the CRT copy in step; the narrow call re-encoded the value and overwrote the correct wide one. `_wputenv_s` first, then `SetEnvironmentVariableW`, is order-safe.

## Decision

`win32shim.c` defines `getenv`/`setenv`/`unsetenv` over the wide API. `setenv` keeps the CRT copy in step through `_wputenv_s` (for C libraries that read it directly), which rejects an empty value and the `=X:` names — those go to the OS block alone. `unsetenv` deletes from both.

`__kml_os_homedir()`: `USERPROFILE` if set, else `GetUserProfileDirectoryW` on the process token. `userenv.dll` is bound at run time so programs that never ask carry no import for it. The emitter calls it and throws only when both fail.

## Implementation notes

`codegen/llvm/win32src/win32shim.c`, `emit_os.go`, `emitter.go` (dedupe flag).

Key *enumeration* (`Object.keys(process.env)`) is absent on every host and is not Windows work; it stays a cross-platform row.

## Side effects discovered

`path.win32.resolve('C:x')` reads `process.env['=C:']`; it only started returning the right directory once both halves (the `chdir` write and the live read) existed.

## Verification

Windows 11 (26200): `TestE2EWinProcessEnvUnicodeAndCase` (inherited and self-written non-ASCII values, case-insensitive read, `delete`), `TestE2EWinChdirWritesDriveVariable`, `TestE2EWinHomedirWithoutUserProfile`; the `TestE2EProcessEnv*` and child_process `env` suites pass; the native shim tests (`TestWin32*`) still link with the shim now defining `getenv`. Not applicable to Linux/macOS.
