# ADR-01984: Accessors on declared fields

- **Relations**: Implements TDD-00230 (P2.7); follows [ADR-01983](ADR-01983.md)
- **Date**: 2026-11-07

## Context

`Object.defineProperty(o, "a", { get() {…} })`, where `a` is a declared
field of a statically typed object or class instance, was refused at
compile time. A typed field read is a struct load, which no accessor
reaches. Through `any` it threw at run time: redefining a declared field
of a boxed class instance, even with a data descriptor, reached a path
that took only dynamic bags ("called on non-object").

## Decision

- At run time (`__kml_anyarr_defprop`), a declared field takes a
  descriptor.
  - An accessor becomes an added property shadowing the field. Its
    attributes default to the field's, and a non-configurable field
    refuses it.
  - A data descriptor validates against the field's attribute record,
    then stores the value.
- `__kml_shape_set` runs a shadowing accessor's setter. One with only a
  getter refuses the write: a TypeError in strict code, nothing in sloppy
  code.
- The shadow read hook runs a shadowing accessor's getter. A new set
  hook runs its setter.
- Typed code sees the accessor through the names accessors are defined
  under (`accessorKeys`). A typed read of a field of such a name consults
  the shadow, whatever the field's type. A typed `=` write of one goes by
  name.
- An unannotated object literal or class instance binding that an
  accessor is defined on is held boxed (`accessorLiteral`).
- The compile-time refusal is deleted.

## Consequences

- Covered by `TestE2EAccessorOnDeclaredField`, which matches Node.
- An accessor defined under a key known only at run time is not one of
  `accessorKeys`. Typed reads and writes of that field read and store the
  field itself.
