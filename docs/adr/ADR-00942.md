# ADR-00942: Shared array buffers are never auto-freed — the reference-semantics free policy (TDD-00213 Stage 4)

- **Relations**: Implements TDD-00213 Stage 4 (completes TDD-00213); Relates to ADR-00939, ADR-00940, ADR-00941, TDD-00173, TDD-00175, TDD-00127
- **Date**: 2026-09-14

## Context

Stages 1-3 (ADR-00939/00940/00941) made an array's `{data,len}` header — and
therefore its backing buffer — shareable across local bindings, object/class
fields, function returns, and closure captures. That raises a memory-safety
question for the `-mm=auto` deep-free (TDD-00175) and the shallow auto-free
(TDD-00173): if two bindings share one buffer, freeing it at one binding's scope
exit would leave the other dangling (use-after-free), and freeing it twice would
double-free. The TDD weighed two policies: (a) never auto-free a shared buffer
(it leaks under non-GC modes — the documented perf tradeoff — while GC mode
reclaims it), or (b) reference-count the header. It leaned to (a), consistent
with TDD-00127's precedent of deferring array memory-perf work.

## Decision

**Policy (a): a shared/header-backed array buffer is never auto-freed under the
non-GC modes.** This is *already realized* by the conservative escape +
interior-alias analysis (`escape_check.go`) that gates every auto-free — no new
runtime mechanism is added; Stage 4 is the decision to keep (a) and the
verification that it is sound and complete against the Stage 1-3 aliasing:

- **The gate already rejects every sharing form.** A binding is auto-freed only
  when the analysis proves its value stays block-local. `return x`, `throw x`,
  aliasing (`let a = x` / `a = x`), capturing it in a closure, passing it to a
  non-whitelisted call, and — for deep-free candidates — any *interior* pointer
  escape (a member/index chain rooted at the candidate, or reassigning a field
  to a shared array) all mark the binding as escaping, so it is left un-freed.
  Only a genuinely-owned, un-aliased buffer (a fresh literal / `JSON.parse` /
  fresh container-method result that never escapes) is ever freed.
- **The deep-free array-field walk is therefore sound.** A candidate whose array
  field is aliased anywhere is never deep-freed, so the field-buffer free
  (`emit_free_deep.go`, added in Stage 2) can never reach a shared buffer — the
  "documented hazard" the Stage 2 comment flagged is unreachable. Its comment is
  updated to record the verified soundness.
- **Refcounting (b) stays deprioritized.** It is a large separate mechanism for
  a perf gain (reclaiming aliased arrays sooner under non-GC modes); the leak is
  acceptable for the CLI/microservice targets, and GC mode already reclaims.

The observable cost: an array that is aliased/returned/captured leaks its buffer
under `-mm=manual`/`-mm=auto`/`-optimize-memory` (never under `-mm=gc`). This is
the same class of documented, opt-out-via-GC leak the project already accepts.

## Verification

- A permanent AddressSanitizer/UBSan guard
  (`TestE2EArrayRefSharedBufferFreePolicyASan`) builds under `-mm=auto` and
  `-mm=auto -optimize-memory` and runs eight aliasing scenarios spanning every
  Stage 1-3 boundary — local aliasing, returning an object field, closure
  capture, aliasing a `JSON.parse` object's array field, returning a parsed
  array, an interior field/element alias that **escapes its owner's block**, and
  storing a shared array **into** a parsed object's field then using it after
  that object's block exit — asserting no sanitizer error and a clean exit. All
  pass; a regression that freed a shared buffer would surface as a
  use-after-free/double-free here.
- The same block-escape and shared-into-field cases produce Node-matching values
  under `-mm=auto` and `-mm=gc` (the aliased owner leaks rather than freeing, so
  the survivor's data is intact). macOS arm64.

## Notes

TDD-00213 is now complete (all four stages). The pre-existing array-in-container
gaps noted in ADR-00940/00941 (`Map<K, T[]>`, `Promise.all` of `Promise<T[]>`,
an array `.then` callback, a self-referential class array field) remain out of
scope. Reclaiming aliased array buffers sooner under non-GC modes (a header
refcount, policy (b)) is the documented future perf follow-up.
