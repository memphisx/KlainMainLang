# ADR-01509: A nullable array reference flow proves present reads present

- **Relations**: Extends ADR-01442, TDD-00230
- **Date**: 2026-10-09

## Context

`checkerPresentRef` (ADR-01442) reads a nullable class, object, function
or promise reference as present where the checker's flow type has no
null or undefined. Arrays, typed arrays and buffers were left out with
no recorded reason. So `const k = this.#p as Buffer` after a
`this.#p === null` throw kept `k` nullable, as did any narrowed
`number[] | undefined` property or variable. Shadow bucket 13 (176 rows).

## Decision

The rule covers arrays too: the same pointer, with `Nullable` cleared.
The existing exclusions still apply: an array pattern's binding and an
element read (`UncheckedIndex`).

A variable some store gives a key or element read (`d[k]`, `a[i]`,
through `as`) is excluded as well (`storesIndexRead`). Without
`noUncheckedIndexedAccess` the checker types that read `T`, yet a miss is
absent. Before, `const o = objs[k]; o === undefined` folded to `false`
for an object or class value on a missing key (the truthiness test was
already right); this predated the array extension.

## Divergences

None. Node's output on a missing key is now matched.

## Verification

- Mac (Apple Silicon): a probe of narrowed `Buffer | null`,
  `number[] | undefined` and `string[] | null` references (indexing,
  `push`, `map`, `join`, template rendering, the absent branch) prints
  the same as Node; the targeted narrowing, nullable, buffer, dictionary
  and `arguments` E2E tests pass.
- `TestIndexReadLocalAbsenceAndNarrowedArrays` (against Node).
