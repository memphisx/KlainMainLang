# ADR-01815: a generator function's prototype chain, instanceof, caller and arguments

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- Test262's generator tests reached these divergences once ADR-01810 let them compile:
  - `Object.getPrototypeOf(%GeneratorFunction.prototype%)` was `Object.prototype`, not `Function.prototype`. `Function.prototype` is a function record, and a property bag links only to bags.
  - `g() instanceof g` did not compile: the right side named a generator, which no class registry holds.
  - Assigning a generator's `caller` or `arguments` did nothing. Function.prototype's setter for them throws.
  - A sloppy function did not report its own `caller` and `arguments`.

## Decision

- `getPrototypeOf` of a `%GeneratorFunction.prototype%` bag answers Function.prototype (`__kml_genfn_proto_parent`).
- `instanceof` against a generator name or a generator function value is decided at run time. `__kml_gen_has_instance` walks the instance's chain looking for the function's current `prototype`. An instance's first link is the prototype it took when made.
- A write of `caller`/`arguments` on a function value goes through `__kml_fn_restricted_set` first. A strict function's (a generator, an arrow, a method) throws the TypeError. A sloppy function's is read-only: ignored in sloppy code, a TypeError in strict code.
- `hasOwnProperty` of `caller`/`arguments` is true for a sloppy function (`__kml_fn_owns_restricted`).

- A function's own-property bag is marked as such: a miss there reads on in `Function.prototype`, then `Object.prototype`'s bag, not the bag's own fallback to `Object.prototype`. A function owning a property had read `toString` from `Object.prototype` and printed `[object Function]`.

## Consequences

- `TestE2EJSFileGeneratorFunctionObject` covers each against Node.
- A sloppy function's `getOwnPropertyNames` still leaves out `caller`, `arguments` and `prototype`.
