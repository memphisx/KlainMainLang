# Process / CLI I/O

> Part of the [Implementation Status](README.md) index. What CLI tools and containerized services actually need day-to-day (argument parsing, stdin, environment config, exit codes). Prioritized because the long-term project direction favors CLI/microservice use cases. `console.log`/`.error` already write to stdout/stderr respectively — see [CONSOLE.md](CONSOLE.md) — the gaps below are everything *else* a CLI program needs.

**Coverage**: 22/24 (~92%) · **Strict Coverage**: 11/24 (~46%).

Format: [Status page format](README.md#status-page-format).

| Feature | Status | Caveats | Notes |
|---|---|---|---|
| Command-line arguments (`process.argv`) | ✅ | • Mirrors C's `argv` directly (`argv[0]` is the binary's own path), not Node's two-prefix convention — see [ADR-00002](../adr/ADR-00002.md) | |
| Environment variables (`process.env.KEY` / `process.env["KEY"]`) | ✅ | | • Both dot and bracket notation; returns a possibly-null string (same convention as `.find()`), so `process.env.X ?? "default"` works |
| Exit codes (`process.exit(code)`) | ✅ | | • Calls C `exit()`; never returns, code after it is correctly unreachable |
| Reading stdin (sync line read) | ✅ | | • `process.readLineSync()` — one line via POSIX `getline()` (handles arbitrarily long lines), stripped of its trailing `\n`/`\r\n`. Returns `null` at EOF (same possibly-null convention as `process.env`). See [ADR-00024](../adr/ADR-00024.md). |
| Simple synchronous file read/write (`fs.readFileSync`/`writeFileSync`-style) | ✅ | | • See [FILE-SYSTEM.md](FILE-SYSTEM.md) |
| `process.execFileSync(file, args?)` | ✅ | • No options object (no `cwd`/`env`/`timeout`/`stdio` overrides yet)<br>• stderr is inherited (visible on the terminal live), not captured | • Node's `child_process.execFileSync`, not `execSync`: `fork()`+`execvp()`s `file` directly with no shell involved, so shell metacharacters in `args` are never interpreted<br>• Returns captured stdout as a string; throws a catchable `Error` on a non-zero exit status or a signal death. See [ADR-00025](../adr/ADR-00025.md). |
| `process.cwd()` | ✅ | | • Current working directory, via POSIX `getcwd(NULL, 0)` (auto-sizing). See [ADR-00026](../adr/ADR-00026.md). |
| `process.chdir(path)` | ✅ | | • Changes the current working directory via POSIX `chdir()`. Throws a catchable `Error` (same "`<opDesc>` '`<path>`': `<strerror>`" shape `fs.*`'s failures already use) if the path doesn't exist or isn't a directory. See [ADR-00026](../adr/ADR-00026.md). |
| `process.pid` | ✅ | | • The current process ID, via POSIX `getpid()`. A property read, not a call, matching `process.argv`. See [ADR-00026](../adr/ADR-00026.md). |
| `process.platform` | ✅ | | • A pure compile-time constant (`"darwin"`/`"linux"`/`"win32"`/...) baked in from the Go compiler's own `runtime.GOOS` — no runtime code at all, since this compiler doesn't cross-compile. See [ADR-00026](../adr/ADR-00026.md). |
| `process.arch` | ✅ | | • A compile-time constant (`"arm64"`/`"x64"`/...) from the Go compiler's `runtime.GOARCH`, exactly like `process.platform` ([ADR-00332](../adr/ADR-00332.md)) |
| `process.kill(pid, signal?)` | ✅ | | • Sends `signal` (defaults to `15`/`SIGTERM`, matching real Node) to `pid` via POSIX `kill()`. Throws a catchable `Error` if the target process doesn't exist or the signal can't be sent; signal `0` is the standard POSIX "does this process exist" check and never actually delivers a signal. See [ADR-00026](../adr/ADR-00026.md). |
| `process.stdout.write(s)` / `process.stderr.write(s)` (raw write, no auto-newline) | ✅ | • Text-only (byte-string, not binary-safe past an embedded null — same scope narrowing `console.log`'s own string formatting already has) | • Unlike `console.log`/`.error` (always a trailing newline), a plain write of exactly `s` with nothing appended — useful for a progress indicator or assembling one line from several pieces<br>• `stdout` goes through buffered `printf` (matching `console.log`'s own fd=1 convention, so output ordering against `console.log` calls elsewhere in the same program stays correct); `stderr` goes through unbuffered `dprintf` (matching `console.error`'s own fd=2 convention) |
| Writing `process.env` (`process.env.KEY = val` / `process.env["KEY"] = val`) | ✅ | • Write only — no `delete process.env.KEY` (`delete` is not a parser keyword; the fixed-shape object model has no dynamic delete)<br>• Compound assignment (`process.env.X += …`) is a clean rejection | • `setenv(key, String(val), overwrite)` ([ADR-00333](../adr/ADR-00333.md)); a written variable is inherited by child processes |
| `process.on('SIGINT'/'SIGTERM', handler)` (signal handlers) | ✅ | • The handler runs from ordinary control flow at the top of the event loop's own iteration, never from real async signal context<br>• Event name must be a compile-time string literal, exactly `'SIGINT'`/`'SIGTERM'` (dynamic event names are a clean compile error, matching `Object.hasOwn`'s dynamic-key rejection)<br>• Handler must be a zero-argument `() => void` closure, same shape `setTimeout`'s own callback requires<br>• One handler slot per signal — registering the same signal twice overwrites the previous handler<br>• Only fires while a `http.listen`-driven or timer-driven event loop is actively iterating; a plain synchronous script with neither has no loop to check from | • Lets a running program (e.g. an `http.listen` server) intercept a signal and shut down gracefully instead of dying immediately. See [TDD-00019](../tdd/TDD-00019.md)/[ADR-00079](../adr/ADR-00079.md), [HTTP-SERVER.md](HTTP-SERVER.md). |
| `process.on('exit'/'uncaughtException', ...)` + `process.exitCode` | ✅ | • `'uncaughtException'` runs the listener (suppressing the default `Uncaught:` print) but the process still exits (code 1) — the setjmp/longjmp exception model has already unwound to the top-level catch-all, so it can't resume execution like Node does<br>• No `'unhandledRejection'` yet (needs rejected-promise tracking)<br>• One listener slot per event, arrow-literal only | • `'exit'` fires at normal end and from `process.exit()`, receiving the exit code; `process.exitCode = N` sets the deferred code a bare program returns; `process.exit()` with no argument uses it ([ADR-00334](../adr/ADR-00334.md)) |
| `process.hrtime()` / `process.hrtime.bigint()` | ✅ | • `hrtime()` takes no argument — the legacy diff-from-a-previous-reading form isn't supported (use `.bigint()` and subtract) | • `CLOCK_MONOTONIC` via the same layer as `performance.now()` ([ADR-00332](../adr/ADR-00332.md)); `hrtime()` → a `[seconds, nanoseconds]` tuple, `.bigint()` → total-nanoseconds bigint |
| `process.memoryUsage()` | ❌ | | • RSS/heap-size reporting — not meaningful in `manual` memory-management mode the same way it is under a real GC; more relevant once `-mm=gc` is the default (see [MEMORY-MANAGEMENT.md](MEMORY-MANAGEMENT.md)) |
| `process.nextTick(fn)` | ✅ | • Shares the one microtask FIFO with Promise reactions rather than draining strictly before them (Node keeps a separate nextTick queue ahead of promises); zero-argument `() => void` callback only | • Enqueued on the existing microtask queue ([ADR-00332](../adr/ADR-00332.md)) |
| `process.version` / `process.versions` | ❌ | | • Reports the Node runtime's own version — not obviously meaningful for a compiled native binary with no runtime to version, but commonly probed by scripts checking compatibility |
| `process.uptime()` | ✅ | | • Seconds (a `double`) since process start, captured once at `main` entry via `CLOCK_MONOTONIC` ([ADR-00332](../adr/ADR-00332.md)) |
| `process.stdin` (streamed reads, not just `readLineSync()`) | ✅ | • `'data'` delivers each read chunk as a UTF-8 string, not a `Buffer` — no `setEncoding`, no binary mode<br>• Flowing mode only (attaching `'data'` starts it) — no `.pause()`/`.resume()`/`.read()`/`'readable'`<br>• One listener per event, arrow/function-expression literal only; callbacks fire synchronously from the dispatch, not via a microtask | • `process.stdin.on('data'/'end')` over a non-blocking fd 0 folded into the same `select()` loop as `readline`/`child_process` ([ADR-00339](../adr/ADR-00339.md)); `'data'` per read chunk, `'end'` once on EOF. Distinct from the blocking `process.readLineSync()` and the line-oriented `readline` module above |
| `readline` module (`createInterface`, `'line'`/`'close'` events, `question()`, `close()`) | ✅ | • The listener callbacks fire synchronously from the event loop's dispatch, not deferred through a microtask queue (same as `child_process`)<br>• One listener per event, an arrow/function-expression literal only; no line history/editing, no `SIGINT`/`'pause'`/`'resume'`, no completer<br>• The `createInterface` options object is accepted but ignored — input is always stdin, output always stdout; one active interface at a time | • Non-blocking stdin (fd 0) folded into the same `select()` loop as `child_process` ([ADR-00323](../adr/ADR-00323.md)); emits one `'line'` per newline (CR stripped), flushes an unterminated final line on EOF then fires `'close'`. Distinct from the blocking `process.readLineSync()` above |
| `child_process.spawn()` / `.exec()` / `.execFile()` (async, event-driven) | ✅ | • The listener callbacks fire synchronously from the event loop's dispatch, not deferred through the microtask queue (`process.nextTick`, which does not exist yet — see the row above)<br>• One listener per event, an arrow/function-expression literal only (the same posture as `Worker`); no `removeListener`<br>• No `.fork()` (needs an IPC channel to a child KlainMainLang binary), no options object (cwd/env/timeout/stdio/encoding), and `'close'`/`'exit'` receive the exit `code` only (a signal death is folded to `128+signal`, no separate `signal` argument)<br>• No synchronous `child_process.spawnSync`/`execSync`/`execFileSync` (the sync `process.execFileSync` above is the only blocking spawn form)<br>• Handles and their buffered output are never freed (`-mm=manual`) | • fork()+execvp() with three pipes; the two read ends are non-blocking and fold into the same `select()` event loop as Worker/channel pipes ([ADR-00322](../adr/ADR-00322.md))<br>• `spawn` streams (`child.stdout`/`stderr` `'data'`/`'end'`, `child.on('close'/'exit')`, `child.stdin.write`/`.end`, `child.pid`, `child.kill`); `exec` runs via `/bin/sh -c` and `execFile` execvp's directly, both buffering into a single `(err, stdout, stderr)` callback |
