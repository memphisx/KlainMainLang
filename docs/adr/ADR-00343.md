# ADR-00343: `fs.createReadStream` / `fs.createWriteStream`

- **Relations**: Implements TDD-00108; builds on TDD-00097 (Streams), TDD-00107 (async fs)
- **Date**: 2026-08-24

## Context

`fs` had sync + async whole-file I/O but no streaming access. Node's
`fs.createReadStream`/`createWriteStream` return a **Node `Readable`/`Writable`**,
which this project's stream subsystem (TDD-00097) already implements — so the
feature is mostly a matter of sourcing/sinking those streams from a file.

## Decision

Per TDD-00108:

- **`createReadStream(path[, options])`** returns a Node `Readable`. A WHATWG
  `%kml.rstream` is allocated, filled by a new runtime helper
  `@__kml_fs_read_stream` (fopen `"rb"` → loop `fread` up to `highWaterMark`
  bytes → enqueue each as a **string** chunk → fclose), closed, then wrapped by
  the existing `wrapWebReadable` — the exact shape `Readable.from(array)` uses,
  sourced from `fread` instead of an array. Eager read-to-EOF; no `select()`
  (a regular file is always ready).
- **`createWriteStream(path[, options])`** returns a Node `Writable`. `fopen`
  once (`"wb"`, or `"ab"` for `{ flags: "a" }`); the `FILE*` is the closure env of
  two runtime sink thunks installed in the wstream — a per-chunk
  `@__kml_fs_stream_write` (`fwrite strlen(chunk)`) in field 9 and an
  `@__kml_fs_stream_close` (`fclose`) in field 10 — which `.write()`/`.end()`
  already drive (firing `'finish'`/`'close'`/`'drain'`).

**Chunk type is `string`, not `Buffer`.** A Node stream has a single chunk type
(`.write`/`.pipe` coerce to it), and this `fs` is text-first (`readFileSync`
returns a string), so string chunks make `createReadStream(a).pipe(create-
WriteStream(b))` and `ws.write("text")` both work. Inherits `readFileSync`'s
text caveat (an embedded NUL truncates a chunk); binary streaming is a follow-on.

A failed open throws a catchable `Error` (via the shared `@__kml_fs_throw`),
matching `readFileSync` — the eager-read model surfaces the failure synchronously
rather than as a deferred `'error'` event.

## Implementation notes

- New `runtime_fs_stream.go` (`@__kml_fs_read_stream`, `@__kml_fs_open_write`,
  `@__kml_fs_stream_write`, `@__kml_fs_stream_close`) and `emit_fs_stream.go`
  (`emitFsCreateReadStream`/`emitFsCreateWriteStream`, `{highWaterMark}`/`{flags}`
  option parsing). Dispatch in `emit_call.go`'s `fs__kml_builtin` switch, type
  inference in `emit_exprs_types.go`, member allowlist in
  `resolver/virtual_modules.go`.
- **`for await` over a Node `Readable`** was WHATWG-only; added an `IsNodeReadable`
  branch (`emit_stmts.go`) that unwraps the inner rstream (`nodeStreamSide(_, 0)`)
  and reuses `emitForAwaitOfStream` — benefits `Readable.from` and every Node
  Readable, not just file streams.
- Factored a shared `ensureFread` guard (`runtime_fs.go`); `fread` was declared
  inline in two places and a third declaration (the read-stream helper) tripped
  LLVM's "invalid redefinition of function 'fread'". All three now route through
  the guard.

## Scope / exclusions (V1)

- Eager read-to-EOF (not a lazy pull); string chunks only (no binary/`Buffer`);
  no `start`/`end` ranges, `fd:`, `autoClose`; `createWriteStream` flags `w`/`a`
  only; options must be object literals with compile-time-constant values.

## Verification

- `tests/fs_stream_test.go` (7 cases, over a temp dir): write-stream round-trip,
  read via `for await`, read via `.on('data')`/`.on('end')`, a multi-chunk
  (`highWaterMark: 1024`, 5000 bytes → 5 chunks) read, a `.pipe()` round-trip, an
  append (`{ flags: "a" }`), and a missing-file open error caught in `try`/`catch`.
- `examples/fs_streams/fs_streams.ts` builds and runs (macOS/arm64).
- `go build` / `go vet` clean.
- Machine: verified on Mac (arm64); platform-independent (POSIX stdio).
