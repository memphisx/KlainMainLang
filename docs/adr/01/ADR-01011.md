# ADR-01011: Arrays crossing as field/element/HOF-callback arguments share the live header

- **Relations**: Completes TDD-00127 (closes its residual); Extends ADR-00939–00942 (TDD-00213 reference semantics); Relates to ADR-00948, ADR-00517
- **Date**: 2026-09-18

## Context

The object-reference array model (TDD-00127/TDD-00213) gave named variables,
fields, returns, and captures shared `{data,len}` headers, but the last
transient-copy path remained: an array reaching a callee as `f(obj.field)`,
`f(m[i])`, or a HOF callback element (`outer.forEach(inner => inner.push(x))`)
was re-boxed into a fresh header at the boundary, so a length mutation inside
the callee was invisible to the caller. Also confirmed live this session
(stale-caveat hunt probe): `2` vs Node `3` on a field push.

## Decision

The nested-element box and the object field slot already *are* live
`{ptr,i64}` header cells — the fix is to carry and share them instead of
re-boxing:

- `unboxArrayValue` now seeds `Value.ArrayHeader` with the box pointer, so
  every nested-element read (`m[i]`, HOF element loads via `loadArrayElem`)
  carries its live header. `loadArrayElemMaybeNull` (the `.find()` "maybe no
  match" loader) seeds it too — possibly null, the existing no-match sentinel.
- `arrayArgFromAggregate` — the shared packer behind ordinary calls, defaults,
  closures/`emitCBCall`, adapters, workers — passes `val.ArrayHeader` when
  present instead of minting. Because a carried header can be **null** (an
  absent calloc'd field, a `Map` get miss) and the callee derefs its header
  parameter unguarded, a fresh box wrapping the (safe `{null,0}`) aggregate is
  still emitted and a `select` picks it only when the header is null — same
  cost as the old always-box path.
- The direct `boxArrayValue` call in `emitCallToFuncSig`'s non-identifier
  array-arg branch routes through `arrayArgFromAggregate`.
- `storeArrayElem` shares the value's live header the same way (with the same
  null-`select` fallback), so `m[i] = existingArray` aliases — matching
  `storeArrayFieldHeader`, and matching Node.

Fallout fixed for free: `arr[0] === namedArray` and array-keyed `Map`/`Set`
`keys()[i] === named` now read `true` (the ADR-00948 identity-loss caveat),
since the element slot holds the named array's own header; a `.find()` result
aliases its source; `.map(x => x)` output elements share the inputs (Node
shallow semantics). A true transient (literal, `.slice()` result) still mints
its own header, and whole-parameter reassignment stays frame-local.

## In passing

`arr.slice()` / `str.slice()` with **zero arguments** (a full copy — valid JS)
was rejected by an arity check requiring 1–2 args; both emitters now default
`start` to 0.
