# ADR-01864: A frozen template object, and a module var a function assigns its parameter

- **Relations**: `Implements TDD-00230` (P3.3: found through the shadow report's Identifier bucket)
- **Date**: 2026-10-21

## Context

- Under `-compat=js`, `var t = null; (function (p) { t = p; })`…`` left `t` null: the cross-kind widening counted only literal stores made by a nested function, so the slot kept its null type and dropped the stored array. With `var u = 0` the store read as `NaN`, and with a declared `function tag(p) { u = p; }` the compile failed on an undefined module global.
- GetTemplateObject freezes the template object and its `raw` array; the runtime never set their level, so a write through `any` added the property.
- A write through `any` to a new non-index key of a boxed static array ignored the array's integrity level.

## Decision

- A nested function's store of one of its own unannotated parameters into a free untyped binding counts as a value of unknown kind, widening the binding to the any box.
- The template object and its raw array get the frozen level at registration.
- `__kml_anyarr_set_by_key` returns 4 for a key a frozen, sealed or non-extensible array refuses; the dynamic set throws V8's TypeError in strict code and has no effect in sloppy code.

## Consequences

- `TestE2ETemplateObjectFrozenThroughAny` matches Node; Test262's `template-object-frozen-non-strict.js` passes in the js lane.
- Verified on Apple Silicon.
