# ADR-00855: `any === undefined` / `=== null` mis-folded to compile-time false

- **Relations**: Fixes a bug in the nullable-scalar null-compare fast path
  ([ADR-00851](ADR-00851.md) `Map.get`→`V | undefined`, [TDD-00187](../tdd/TDD-00187.md) undefined sentinel)
- **Date**: 2026-09-10

## Context

Surfaced by the first full `make test-par` run during the TDD-00199 delivery:
`TestE2EJSModeProtoMethodArgs` failed — `g.nope === undefined` on a missing
dynamic property returned `false`, though real JS gives `true` (and
`console.log(g.nope)` already printed `undefined` correctly). Reduced, the bug
was general to dynamic operands under `-compat=js`:

```
let x: any; x = undefined; x === undefined   // got false, want true
const o: any = { a: 1 }; o.b === undefined    // got false, want true
```

Both `=== undefined` and `=== null` on an `any` value returned `false`
regardless of the runtime tag, so no dynamic value could ever be tested for
absence — breaking a missing property read, `AsyncLocalStorage.getStore()`, and
any `any`-typed nullish check.

## Investigation

`emitBinary` intercepts `== / != / === / !==` against a `null`/`undefined`
literal via `emitNullableScalarNullCompare` (emit_nullable_scalar.go) before
evaluating operands, to answer from a nullable scalar's stored presence bit
rather than its auto-unwrapped payload. That function's **strict constant fold**
(`strict && litUndef != valUndef` → compile-time `false`/`true`) ran *before* it
verified the operand was actually a nullable scalar. For a dynamic/`any`
operand, `inferExprType(x).IsUndefined` is `false` (a bare `any` type carries no
undefined mark), so `x === undefined` (litUndef=true) satisfied
`litUndef != valUndef` and folded to a constant `false` — never reaching the
runtime tag-aware `__kml_any_eq`, which would have compared the NaN-box tags
correctly (undefined=10, null=2). The runtime helper and the box encodings were
correct; only the premature fold was wrong.

## Decision

Guard `emitNullableScalarNullCompare`: if the non-literal operand's inferred
type `IsDynamic`, return `ok=false` immediately and defer to the runtime path
(`emitAnyEquals` → `__kml_any_eq`). A dynamic value's kind is known only at
runtime — its tag may be undefined, null, or anything — so neither the constant
fold nor the presence-bit path applies. The guard sits right after the operand
roles are identified, before the strict fold.

## Implementation notes

One `if e.inferExprType(scalarExpr).IsDynamic { return Value{}, false, nil }` in
emit_nullable_scalar.go. Non-dynamic operands (genuine nullable scalars, and
statically null/undefined-typed values) are unaffected — the fold and
presence-bit paths behave exactly as before.

## Verification

macOS (Apple Silicon M4), all matching Node: `(x: any) === undefined` → true and
`=== null` → false when holding undefined; the reverse when holding null; a
missing dynamic property / prototype method (`g.nope === undefined`) → true;
`o.a === null` / `o.a === undefined` / `o.b === undefined` all agree with
`node -e`. `TestE2EJSModeProtoMethodArgs` and the nullable/optional/undefined
suites pass; new coverage added. Not a caveat — a correctness fix.
