# ADR-01931: The runtime on libuv is complete; the event-loop test asserts no tick count

- **Relations**: Implements TDD-00244, Extends ADR-01685
- **Date**: 2026-10-28

## Context

TDD-00244 moved the runtime's event loop onto libuv in seven stages. ADR-01685 finished Stage 6 (Windows). One item the TDD's Tests section names was left: `tests/event_loop_wait_test.go` still held a `minTicks` threshold that the TDD says Stage 1 removes.

## Investigation

- The select bridge is gone: no `*_fdset_add`, `*_dispatch` or `*_keepalive` hook and no `uv_prepare_t` collector remain in the runtime sources. Neither does `__kml_loop_turn`, `top_wait`, `__kml_httpc_drive` or `curl_multi_fdset`.
- Stage 7 is in: the webview and Sailfish pumps call `__kml_loop_run_once` (`loopsrc/loop.c`), and `__kml_loop_backend_fd` exposes `uv_backend_fd`.
- Stage 0's vendoring for Sailfish is the sysroot image (`docker/Dockerfile.sfos-sysroot`), which carries libuv. Android has no target yet (TDD-00147).
- `minTicks` was a named constant of 1, compared with `<`: the assertion was already "the interval fired at all".

## Decision

- **The threshold goes.** The test asserts that the interval fired during the wait (a count of zero means the wait starved the loop), with no named count to tune.
- **TDD-00244 is Implemented.**

## Verification

- `TestE2ELoopWaitSleeps` and the await-fetch loop tests pass (Mac, Apple Silicon).
