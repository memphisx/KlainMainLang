# ADR-00999: Non-configurable-delete TypeError embeds the property name

- **Date**: 2026-09-17

## Context

Deleting a non-configurable property of a dynamic object throws a `TypeError`
in strict mode. Our message read `Cannot delete property of #<Object>`, missing
the offending property name that V8 includes. Node/V8's exact wording is
`Cannot delete property 'x' of #<Object>`. The object-collections status page
carried this as a caveat on the `Object.defineProperty` row ("`Cannot delete`
TypeError text omits the property name").

## Investigation

The throw site is `emitDynAnyDelete` in `codegen/llvm/emit_dynobj.go:305`. The
runtime property key is already in hand there as `keyRef` (a string-pointer
register, produced by `dynAnyKeyRef` / the caller). The only reason the name was
absent is that `emitThrowTypeError` takes a compile-time constant string, so
there was no path to splice a runtime value into the message.

Confirmed the target wording against `node`:

```
$ node -e "'use strict';const o={};Object.defineProperty(o,'x',{value:1,configurable:false});try{delete o.x}catch(e){console.log(e.message)}"
Cannot delete property 'x' of #<Object>
```

## Decision

Add `emitThrowTypeErrorValue(msgReg string)` — a sibling of
`emitThrowTypeError` that takes a runtime string-pointer register for the
message instead of interning a constant. At the delete-throw site, build the
message at runtime as `"Cannot delete property '" + key + "' of #<Object>"` via
two `emitStringConcat` calls over `keyRef`, then throw it.

## Implementation notes

- `emit_dynobj.go`: new `emitThrowTypeErrorValue`; the `delErrL` branch of
  `emitDynAnyDelete` now concatenates the message around `keyRef`.
- `keyRef` is the same runtime key used for the bag delete itself, so the name
  in the message is exactly the one that failed (works for both `delete o.x`
  and computed `delete o["long name"]`).

## Side effects discovered

None. The property-name inclusion is the only difference; the throw kind
(`TypeError`), name, and control flow are unchanged.

## Verification

- `tests/dyndesc_test.go`: `TestE2EDescDeleteMessageHasPropertyName` asserts the
  exact message for both a dotted and a computed (spaced) key, byte-for-byte
  against Node under `-compat=js`.
- Existing `TestE2EDescReadOnlyAndDeleteThrow` still passes.
- macOS arm64 (M4): `go build`, targeted tests green.
