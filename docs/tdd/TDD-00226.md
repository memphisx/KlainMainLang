# TDD-00226: Array holes — a lazy hole bitmap beside the scalar buffer

- **Status**: Not Started
- **Date**: 2026-09-22

## Context

`a[a.length + 2] = v` throws "Array index out of bounds" here; Node extends `length` to `a.length + 3` and leaves
two *holes* — a third element state, distinct from `undefined`:

| operation on a holey `[1, , 3]` | Node |
|---|---|
| `a[1]` | `undefined` |
| `1 in a`, `a.hasOwnProperty(1)` | `false` |
| `forEach` / `map` / `filter` / `reduce` / `some` / `every` / `indexOf` / `Object.keys` | skip the hole (`map` keeps it as a hole in the result) |
| `for…of`, spread, `Array.from`, `values()`, `entries()`, `includes`, `find`, `findIndex`, `join`, `sort` | see `undefined` (`join` renders `""`; `sort` moves holes to the end, after `undefined`s) |
| `util.inspect` / `console.log` | `[ 1, <1 empty item>, 3 ]` |
| `JSON.stringify` | `[1,null,3]` |
| `delete a[i]` | makes a hole; `length` unchanged |
| `a.length = n` (grow) | holes appended; (shrink) elements dropped |
| `new Array(n)` | `n` holes (today: `n` zeros, BACKLOG line "new Array<T>(n) fills real zeros") |
| `[1, , 3]` literal elision | a hole (today: desugared to an `undefined` literal, ADR-00467) |

V8 has the same split: a one-way `PACKED → HOLEY` elements-kind transition per array, a `the_hole` sentinel for tagged
and double elements. A `(T | undefined)[]` element here is a NaN box (`arrayElemType`, `types.go`), so *that* family
already has a spare word; a plain `number[]`/`int64[]`/`string[]` buffer has none (ADR-01040 side effect 4).

Negative-index writes (`a[-1] = v`) are a named property `"-1"` on the array object in Node, never an element and
never a hole; they belong to the dynamic object model (TDD-00155), not here.

## Design

### Representation — Option A (chosen; see the session-25 discussion recorded in [BACKLOG](../BACKLOG.md) §0 item 4)

The array header grows by one hidden word: `{ ptr data, i64 len }` → `{ ptr data, i64 len, ptr holes }`.
`holes` is **null for a packed array** (every array today) and points to a bitmap of `⌈cap/64⌉` words once the first
hole is made. One bit per element: set = hole. The header cell is heap-allocated (`newArrayHeader`,
`emit_arrays_core.go:311`) and only its *pointer* crosses calls, so adding a field there changes neither the
`{ptr,i64}` SSA aggregate (`Value{Ref}`) nor the `Symbol{Ptr}` shape nor the call ABI — the two live shapes stay
exactly as the codegen conventions and ADR-01041 describe them. Sites that materialise a header from an aggregate
(`boxArrayValue`, `newArrayHeaderSlot*`, `arrayArgFromAggregate`) store `holes = null`; a transient aggregate cannot
carry holes, which is right: an aggregate is a *copy* (slice/map/filter result) and every producer below decides its
own hole bits explicitly.

Rejected alternatives:

- **Boxed elements with a hole sentinel** (every scalar array becomes NaN-boxed): a global layout change across
  arrays, TypedArrays, the `any` sidecars and every HOF, plus a real perf regression on the hot path, for a feature
  most programs never trigger. Integer `@type` arrays still could not fit a sentinel and would need a bitmap anyway.
- **Hybrid** (sentinel for `double`/pointer buffers, bitmap for full-width integers): two mechanisms to keep
  correct; the double sentinel would also collide with `emitIndexRead`'s existing NaN miss value and be erased by
  `__kml_nb_pack`'s NaN canonicalisation the moment the value crossed into `any`.

### The one-way transition

`__kml_arr_make_holey(header)` allocates and zero-fills the bitmap for the current capacity; called by the four
hole *producers*: gap write, `delete a[i]`, `a.length = n` growth, `new Array(n)`, and the literal elision. A packed
array never pays: every hole-sensitive site tests `holes == null` first (one load + branch) and takes today's code.

Bitmap maintenance rides the buffer's own mutators — the bitmap is realloc'd whenever the data is
(`push`/`unshift`/`splice`/index-append) and shifted by the same delta wherever `memmove` moves elements
(`splice`/`shift`/`unshift`/`copyWithin`), with a word-level shift helper `__kml_holes_move(bm, from, to, n)`.
`sort`/`reverse`/`toSorted`/`toReversed` on a holey array first compact: Node's `sort` places holes after
`undefined`s at the end, `reverse` mirrors positions — both are "compute the new bit vector" operations on a copy.

### Site inventory (from the survey; each is one `holes == null` fast path plus one holey arm)

- **Reads**: `emitIndexRead` (`emit_exprs_member.go:284`) — in-range *and* hole ⇒ the existing miss value
  (ADR-01040's undefined path, so `(T | undefined)` typing already covers it); `.at()`; `in`/`hasOwnProperty`
  (today a compile error on arrays — becomes a real answer).
- **Skipping walkers**: `map`, `forEach`, `filter`, `reduce`/`reduceRight`, `some`, `every`, `indexOf`,
  `lastIndexOf`, `flat`/`flatMap`, `Object.keys`/`entries`/`values`, `for…in` (`emit_arrays_hof.go`,
  `emit_arrays_search.go`, `emit_arrays_transform.go`, `emit_arrays_iter.go`, `emit_stmts.go`).
- **Undefined-seeing walkers**: `for…of`, spread (`emitSpreadArrayLitData`, call/console spread), `Array.from`,
  `values`/`entries`, `includes`, `find*`, `join`, `fill` (fills holes), `with`, `concat` (holes propagate).
- **Renderers**: `emitInspectArray` (`<n empty items>` runs, `emit_inspect.go:187`), `emitJSONStringifyArrayData`
  (`null`, `emit_call_json.go:189`), `__kml_array_inspect_at`/`__kml_array_join` in `dynjsonsrc/dynjson.c` for the
  boxed-`any` path — `KjBox` mirrors the header, so the sidecar layout test (`sidecar_layout_test.go`) pins the new
  field.
- **Producers**: `emitArrayIndexAssignGrow` (`emit_arrays_mutate.go:657` — the gap branch replaces the throw),
  `delete a[i]` (`emit_exprs_operators.go:1199`, today a rejection), `a.length = n` (today a rejection,
  ADR-00166), `new Array(n)` (`emit_arrays_core.go:1018`), the parser's elision desugaring (ADR-00467 — becomes a
  hole marker node the literal emitter turns into a bit).
- **Copies**: `emitArrayCopy`, `slice`, `toSpliced`, `structuredClone`, boxing into `any` (`boxAnyArray` shares
  the live header, so holes are visible through `any` for free).

### Static-literal arrays

ADR-01064's read-only literal images (`emit_arrays_literal_static.go`) stay packed; an elided literal
(`[1, , 3]`) takes the heap path with a bitmap.

### Stages

1. Header field + `holes == null` fast paths everywhere (no behaviour change; layout test updated).
2. Producers: gap write, `new Array(n)`, literal elision; readers: index read, inspect, JSON, skipping walkers.
3. Mutator bitmap maintenance (`push`/`splice`/`shift`/`unshift`/`copyWithin`/`sort`/`reverse`).
4. `delete a[i]`, `a.length = n`, `in`/`hasOwnProperty` on arrays.

Each stage: E2E tests against the Node oracle (`assertSameAsNode`) + an example; status rows for the array methods
lose their "holes" caveats as they close.

## Open questions

- Whether `map` over a holey array should allocate the result's bitmap eagerly or lazily on the first skipped
  index (Node's result is holey iff the source is).
- Whether the bitmap should be sized to `len` or to a future capacity word (ADR-00517's deferred amortised
  growth) — the realloc-on-every-growth of the data buffer already forces a matching realloc of the bitmap, so
  the two should be introduced together if capacity lands first.
