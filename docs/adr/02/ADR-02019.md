# ADR-02019: A callback's annotated parameters against a generic overload

- **Date**: 2026-11-21

## Context

`xs.reduce((acc: number, v) => … as number | undefined, 0)` compiled in
the strict lane, but tsc reports TS2769. The callback is context-sensitive
(`v` is unannotated), so overload fitting skips it, and any overload fits.
The misfit check that follows (`argMisfit`) compares a function literal's
annotated parameters contravariantly, but only against a parameter whose
declared type names no type parameter. `reduce<U>`'s
`(previousValue: U, …) => U` was never checked. With U inferred as
`number | undefined`, `acc: number` does not accept it.

## Decision

`argMisfit` compares the literal's annotated parameters against the
instantiated parameter whenever the instantiation is resolved and no
longer names a type parameter.

## Implementation notes

- checker/overloads.go: `argMisfit`.

## Verification

- checker/check_test.go cases agree with tsc 5.9.3: the misfit (2:TS2769)
  and an `acc: number | undefined` callback (clean).
- The js lane's untyped `reduce` gives Node's output (Linux x86, Node304).
