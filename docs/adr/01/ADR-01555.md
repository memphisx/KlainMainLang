# ADR-01555: `this` in static members, statics read during class typing, method names in strict code

- **Relations**: Extends ADR-01551, TDD-00230
- **Date**: 2026-10-10

## Context

- The checker typed `this` in a static method, static accessor, static
  field initializer or static block as unanswered (as `any` downstream).
  In TypeScript it is the class's value, `typeof C`, so `return
  this.#m` in a static method has `#m`'s type.
- While a class's static side is being built, a static method's body that
  reads the class (`C.#f`, or `this.#f`) saw only the static fields, never
  the static methods and accessors already typed before it.
- Codegen rewrites a static member's `this` into the class's name after
  the checker's binding ran, so the synthesized identifier resolved to
  nothing and typed `any`.
- The strict-code check (ADR-01551) reported a method named `eval` or
  `arguments` (`eval(js: string) {…}` in the webview module) as an
  invalid binding; a method's name is a property key, not a binding.

## Decision

- `this` in a static member is the class's value.
- The class's partial static snapshot grows as each static method or
  accessor is typed, so a later member's body reads the earlier ones.
- The static-`this` rewrite records each identifier it synthesizes with its
  class (`Program.StaticThis`); the checker types such an identifier as
  that class's value.
- Class methods and object-literal methods are exempt from the strict
  binding-name check.

## Divergences

- A static member still sees only the static members declared before it
  while its own class is being typed; TypeScript resolves members lazily
  and sees all of them.
