# ADR-01116: `-compat=js` as a checker mode: call-site parameter types and constructor fields

- **Relations**: `Implements TDD-00230` (Phase 2, P2.6); `Extends ADR-01113`
- **Date**: 2026-09-24

## Context

[TDD-00230](../tdd/TDD-00230.md) P2.6 makes `-compat=js` a checker mode.
Unannotated bindings infer from their initializer, as TypeScript does, and
parameters take the call-site inference that codegen's jsinfer pass
performs. That pass moves into the checker and is deleted from codegen.
Until this step, the checker had one mode: the shadow oracle bound every
program with the strict lane's rules and left every unannotated,
uncontextual parameter unanswered.

## Investigation

- **`codegen/llvm/emit_classes_jsinfer.go`** (TDD-00022):
  - `jsCollectFuncParamTypes` and `jsCollectCtorParamTypes` walk the
    program for calls by name and `new` sites. The first site whose
    argument has a type gives an unannotated parameter its type. Two sites
    that disagree are a hard error asking for an annotation. A parameter no
    site types keeps the number default (ADR-00042).
  - `jsInferConstructorFields` collects a field-less class's fields from
    `this.name = value` in its constructor (first store wins; a
    disagreeing store is an error).
- **TypeScript's checkJs** types an unannotated parameter without JSDoc as
  `any`. The jsinfer pass is this project's extension to that.

## Decision

- **`checker.Options{CompatJS}`** (`checker.NewWith`). The shadow oracle
  now receives the lane and uses the lane's rules: Annex B binding
  (`binder.BindWith`) and the checker's js mode.
- **Call-site parameter types:** in js mode, an unannotated parameter with
  no contextual type and no default takes the widened type of the first
  call site's argument the checker types.
  - The call sites are a function declaration's calls by name, a function
    expression's or arrow's calls through the variable it initializes, and
    a constructor's `new` sites. All are indexed once over the program.
  - A site that disagrees leaves the parameter unanswered: codegen rejects
    that program.
  - A site whose argument depends on the parameter itself (recursion) is
    skipped.
  - With no site, the parameter is `any`, as checkJs has it. Codegen's
    number default is a representation choice the shadow report shows
    where it differs.
  - A method's parameters stay unanswered: which method a call reaches
    depends on the receiver's type. So does a function passed as an
    argument (a callback to `sort` or `reduce`): its callee calls it, out of
    the checker's sight until the builtin library is declared (P3).
- **Constructor fields:** in js mode, a non-generic class that declares no
  instance fields gets a field for each `this.name = value` in its
  constructor, outside nested functions. The first store types the field
  (widened); a store of another type leaves it unanswered.
- **Not in this step:** deleting jsinfer from codegen. That waits for its
  deciders to switch over (P3).

## Implementation notes

- **New:** `checker/jsmode.go`, `checker/jsmode_test.go`.
- **Changed:**
  - `checker/checker.go`: `Options`, `NewWith`;
  - `checker/symbols.go`: parameters in js mode, constructor fields;
  - `checker/generics.go`: the parameter path passes its function;
  - `codegen/llvm/shadow.go` and `shadow_binder.go`: the oracle takes the
    lane.

## Verification

All on macOS arm64 (M4):

- `go test ./checker`: js-mode parameters from calls, from an arrow's
  variable, disagreeing sites, no site (`any`), a recursive site, a
  callback passed to a builtin; constructor fields (from parameters, in a
  branch, disagreeing); strict mode unchanged.
- Shadow report over the examples and apps (404 compile runs, each `.js`
  file in both lanes): 476 disagreements, three more than ADR-01115's 473.
  All three are in `describe(city, times)` in
  `examples/jsmode/vanilla_class.js`, where the checker types `city.name`
  and `out` as `string` from the call site. Codegen answers them in its
  signature pass, before `city` is in scope, with its unbound-name `i64`
  (ADR-01111's side effect).
  A first run had typed the callbacks passed to `sort` and `reduce` as
  `any`, eight disagreements. Those callbacks are now unanswered, as their
  callers are out of sight.
- `make examples`: 356/358. `examples/http/client_server.ts` and
  `req_readable.ts` hung. Both compile to IR byte-identical to the previous
  build's, since the checker runs only under the shadow harness.
  `client_server` hung again once in three runs on its own, the
  intermittent hang BACKLOG §0 item 1 records.
- `make test-par`: pass apart from the four `-mm=gc` macOS segfaults
  (BACKLOG §0 item 1d), identical at HEAD.
- `make conformance`: strict 7,129 / 53,578, js 7,716 / 53,578, unchanged.
