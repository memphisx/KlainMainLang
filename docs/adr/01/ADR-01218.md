# ADR-01218: fs read options may be a variable

- **Relations**: `Extends ADR-01163`
- **Date**: 2026-09-28

## Context

`fs.readFileSync(path, opts)`, `fs.readFile` and `fs.promises.readFile`
chose the decoding codec at compile time and accepted only a string
literal or an object literal whose `encoding` was a literal. An options
variable (`const ro = { encoding: 'utf8' as BufferEncoding }`) or
`{ encoding: enc }` was a compile error (BACKLOG 96).

## Investigation

- TypeScript chooses `readFileSync`'s result from the options' static
  type: a string `encoding` gives a string, an absent one a Buffer, and an
  optional one `string | Buffer`.
- `__kml_buf_encode_enc` already decodes with a codec named at run time
  (`emitBufferEncodeStringDyn`), throwing Node's `ERR_UNKNOWN_ENCODING`.

## Decision

- A non-literal options argument, or a literal whose `encoding` is not a
  literal, is read at run time. An encoding string, or an object whose
  `encoding` member is a string, decodes with that codec
  (`readFileEncodingOf`, `emitReadFileEncodingRef`). An object without
  `encoding` gives a Buffer. The result type follows the same rule
  (`readFileHasEncoding` is type-aware).
- An optional `encoding` member (the `string | Buffer` overload) is a
  clean compile error.
- The pooled async read takes the inline path for such options.

## Implementation notes

`codegen/llvm/emit_fs.go`, `emit_fs_async.go`, `emit_exprs_types.go`.

## Side effects discovered

None.

## Verification

Mac (Apple Silicon), against Node v24.19: `TestE2EFsReadOptionsVariable`.
