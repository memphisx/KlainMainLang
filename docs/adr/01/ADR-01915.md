# ADR-01915: a type annotation on a destructuring declaration

- **Relations**: `Implements TDD-00230` (strict lane is tsc)
- **Date**: 2026-10-21

## Context

- `const { a, b }: T = e` and `const [a, b]: T = e` are valid TypeScript; the parser rejected the annotation.
- A test called `generateKeyPairSync(ty as any, o)`, which tsc resolves to the string-keys overload, and constructed `new crypto.KeyObject(…)`, whose constructor TypeScript's declaration makes private. tsc rejects both; the test compiled.

## Decision

- Both destructuring declaration nodes carry an optional annotation. The checker types the bindings from it, gives it to the initializer as its contextual type and checks the initializer against it.
- The crypto module's `KeyObject` constructor is protected: its subclasses in the module still construct it, and a program's `new KeyObject(…)` is rejected as tsc rejects it. The test annotates the key pair and constructs through an `any` cast.

## Consequences

- Annotated patterns compile and are checked as in tsc; the destructuring example shows them.
