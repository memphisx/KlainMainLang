# ADR-01723: Builtin prototypes as values; TypedArray methods through `any`

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-18

## Context

Several builtin prototypes were not values:

- `Number.prototype`, `Boolean.prototype`, `Symbol.prototype` and `BigInt.prototype` read as `undefined`.
- A host class's accessor (`Map.prototype.size`, `ArrayBuffer.prototype.byteLength`) had no descriptor.
- `Uint8Array.prototype` and the other TypedArray prototypes were missing.

The TypedArray gap went deeper:

- **Methods through `any`:** a TypedArray held in `any` answered no method of its own (`x.subarray` was "not a function"). An Array method ran over a plain `any[]` view, so `x.map(…)` returned an Array.
- **Sorting:** a TypedArray's default `sort()` compared elements as strings, through an 8-byte comparator whatever the element width. A `Float32Array` sort used the wrong element size.
- **Copies:** `toSorted`, `toReversed` and `with` returned plain arrays.

## Decision

- **Primitive prototypes:** a primitive class's prototype holds its methods.
  - Each method checks `typeof this` and throws V8's "requires that 'this' be a Number" TypeError otherwise.
  - The Boolean declaration gains `toString`, which JavaScript's `Boolean.prototype` has.
- **Host accessors:** a host class's readonly properties are its prototype's getters.
  - Each getter reads the receiver's own property once the receiver is an instance.
  - Any other receiver throws "Method get Map.prototype.size called on incompatible receiver …".
- **Receiver names:** an incompatible receiver is named as V8 names it: `[object Array]`, `[object Uint8Array]` or `[object Date]` for an exotic builtin, `#<Ctor>` for any other object.
- **`%TypedArray%.prototype`:** one record per method, shared by every kind, so `u8.map === f64.map` holds.
  - The record dispatches on the receiver's element kind to that kind's typed method.
  - A non-TypedArray receiver gets V8's message: "this is not a typed array.", or the incompatible-receiver form for `at`, `join`, `slice`, `sort`, `subarray`, `toReversed`, `toSorted` and `toLocaleString`.
  - It also carries the `buffer`, `byteLength`, `byteOffset` and `length` getters.
- **Kind prototypes:** each kind's prototype holds `constructor` and `BYTES_PER_ELEMENT` over `%TypedArray%.prototype`. `Object.getPrototypeOf` of a TypedArray is its kind's prototype.
- **Calls through `any`:** a TypedArray in `any` answers its methods through these records. Calls dispatch the same way, so their results are TypedArrays.
  - The dispatch is generated only for programs that name a TypedArray class.
- **Sorting:** a TypedArray's default order is numeric over its element width, with -0 before +0 and NaN last.
  - A BigInt64Array's default `sort`/`toSorted` is supported; a comparator to it is still rejected.
  - `toSorted`, `toReversed` and `with` keep the receiver's TypedArray kind.
- **`with` bounds:** an index outside `[-length, length)` throws V8's RangeError (`Invalid index : 5`, or `Invalid typed array index`). It no longer clamps a too-negative index to 0.

## Verification

macOS (Apple Silicon): `tests/builtin_prototype_test.go` (primitive prototypes, host getters, TypedArray methods through `any`, prototype receivers and identity, numeric sorts, `with` bounds) matches Node. The TypedArray, prototype, sort, Atomics, DataView and dynamic suites pass, as do the codegen unit tests.
