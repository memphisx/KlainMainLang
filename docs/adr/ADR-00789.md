# ADR-00789: Flip TDD-00076 and TDD-00121 to Implemented (status reconciliation)

- **Relations**: `Implements TDD-00076, TDD-00121`
- **Date**: 2026-09-08

## Context

Two design docs carried a stale `Status: In Progress` long after the work
they scoped had shipped, flagged for a reconciliation pass in the backlog's
bookkeeping tier. This ADR records the verification behind flipping both to
`Implemented`, and the two places where the shipped implementation diverged
from the design body (which, per the standing rule, is never edited
post-hoc — the divergence is recorded here instead).

## Investigation

- **TDD-00076** (real `any` semantics as a `-compat` axis inhabitant) scoped
  **Bucket A** only — the strict-vs-JS *policy* split — and explicitly pushed
  **Bucket B** (boxed-`any` representation completeness) out to TDD-00062's
  deferred set. Bucket A is two coupled sub-decisions, both now shipped:
  - **A2** (operators on a boxed `any` under `-compat=js`) shipped as
    [ADR-00628](ADR-00628.md), extended by [ADR-00660](ADR-00660.md) for the
    bitwise/shift operators. The two-word `{i8,i64}` box the design assumed
    was superseded by the single-word NaN-box ([TDD-00156](../tdd/TDD-00156.md)
    / ADR-00628); the logical `kmlTag*` dispatch the design reasoned about
    survives intact.
  - **A1** (implicit-`any` on unannotated parameters under `-compat=js`)
    shipped as call-site inference — [ADR-00624](ADR-00624.md) (constructor
    parameters) and [ADR-00625](ADR-00625.md) (plain-function parameters).
    This is TDD-00005's *option 2*, which TDD-00076's Design section judged
    "not worth building," recommending instead that an unannotated parameter
    default to boxed `any`. The implementation reversed that call: option 2
    keeps ordinary loosely-typed code at native static speed (no dynamic bag)
    where the boxed-`any` default would have forced every such parameter onto
    the D1 runtime path. The design's core move — Bucket A as a `-compat`
    inhabitant rather than N scattered local rejections — is exactly what
    shipped; only the A1 *mechanism* differs.
- **TDD-00121** (Conformance V4) scoped three tracks, all shipped:
  - **Track A** in-scope Test262 subset counter — [ADR-00365](ADR-00365.md);
    `tools/conformance/main.go` carries `InScope`/`inScope` and the
    "## In-scope subset" report section.
  - **Track B** Node-core oracle — [ADR-00366](ADR-00366.md), run as the
    whole `test/parallel` corpus (the design's implementation-scope correction
    away from the meaninglessly-small pure-modules denominator), `make
    conformance-node`.
  - **Track C** TypeScript acceptance oracle — [ADR-00367](ADR-00367.md),
    `-suite=ts`, `make conformance-ts`.

## Decision

Flip both `Status` fields from `In Progress` to `Implemented`, each with a
one-line note pointing at the shipping ADRs and the two divergences above.
No design-body text changes. Remove the two docs from the backlog's §5
bookkeeping item.

## Implementation notes

Edited only the `- **Status**:` line of `docs/tdd/TDD-00076.md` and
`docs/tdd/TDD-00121.md`; the ADR/TDD index rows are regenerated by
`make status`, never hand-edited. `docs/BACKLOG.md` §5 loses the "status
fields due a reconciliation pass" clause; §4's parenthetical on TDD-00076
being "In Progress" is corrected in lockstep.

## Side effects discovered

None. This is a documentation-status reconciliation; no code or status JSON
changed, so the `make status` / `reference-check` guards see only the two
Status-line edits and the regenerated index rows.

## Verification

macOS (Apple Silicon M4). Confirmed each track/bucket ships by reading the
cited ADRs, the Makefile `conformance-node`/`conformance-ts` targets, and the
`node`/`ts` suite modes plus `InScope` plumbing in `tools/conformance/main.go`.
`make status && make status-check && make reference-check` clean.
