# TDD-00213: Full array reference semantics — every binding shares one header cell

- **Status**: Implemented
- **Date**: 2026-09-14

## Context

Arrays in this compiler are only **partially** reference-typed. The object-reference
model (TDD-00127) gives a named array variable a stable slot holding a pointer to
a shared heap `{data,len}` header (`arrayHeaderTy`); `push`/splice write a new data
pointer/length *through* that header, so a mutation propagates to everything that
holds the *same header cell*. But most bindings do **not** share the header — they
mint a fresh one and snapshot:

- **Local aliasing** — `let a = b; b.push(4); a` shows `[1,2,3]`, Node shows
  `[1,2,3,4]`. `let a = b` runs `newArrayHeaderSlotFromAggregate`, minting a fresh
  header from `b`'s `{data,len}` aggregate; a later reallocating `push` on `b`
  swaps `b`'s header's data pointer, which `a`'s independent header never sees.
- **Object/class fields** — array fields are stored **inline** as `{ptr,i64}`
  (ADR-00061, `StructFieldIR`), not as a header pointer, so `obj.arr` reads a
  snapshot and `let x: any = obj.arr; obj.arr.push(y)` misses it — and because the
  snapshot holds the freed old data pointer after a reallocating push, it can read
  **garbage** (`1e-323`), not merely stale.
- **Returns** re-header at the callee's binding (same snapshot shape).

Live mutation currently propagates only through **function calls** (`packArrayArg`
passes the header pointer across the ABI, so a callee `push` is visible to the
caller) and, since TDD-00212 Stage 3, through the **`any`-box** (which now shares
the source header).

Two concrete bugs fall out of the same root cause (no stable array identity):

1. **`a === b` on two typed named arrays is invalid IR** — `emit_exprs_operators.go`
   emits `icmp eq ptr <left.Ref>` for an array `===`, but `left.Ref` is the
   `{ptr,i64}` aggregate, not a `ptr` (`array.IR == "ptr"`), so clang rejects it
   (`'%t' defined with type '{ ptr, i64 }' but expected 'ptr'`). Reproduces on
   committed HEAD. Array `===` needs to compare a stable identity pointer.
2. **Field-array→`any` dangling render** (the garbage above), the visible tip of
   the field-storage gap.

The faithfulness bar (this project's own standing rule): arrays are objects in JS; every binding of an
array is a reference to the *same* object. This TDD makes that true across the
board, so aliasing, identity (`===`), and mutation-visibility all match Node.

## Design

Give every array **value** a stable identity = its heap header cell, and make
every **binding** share that cell rather than minting a fresh one. Only a
genuinely new array object (literal, `new Array`, `.slice()`/`.map()`/`.concat()`/
spread, a fresh HOF result) mints a new header.

The seed already exists: `Value.ArrayHeader` (added in TDD-00212 Stage 3) carries
the live header pointer when a value originates from a header-backed array. This
TDD extends its producers and consumers:

- **Producers set `ArrayHeader`.** The array-identifier eval and the dynamic-param
  adapter already do (TDD-00212). Add: object/class field reads (once fields are
  header-backed, Stage 2), and confirm returns/params thread it. A transient
  array-producing expression leaves it empty (it *is* a new object).
- **Consumers share when present.** A binding of an array value — `let`/`const`
  var decl, assignment, field store, return, argument — reuses `ArrayHeader` (store
  the same header pointer / share the cell) instead of `newArrayHeader*`. Empty →
  mint (a new object).
- **Identity (`===`).** Compare the identity pointer — `ArrayHeader` when present,
  else the aggregate's data pointer for a transient (`extractvalue 0`). Two
  bindings of one array share the header → equal and stable across a reallocating
  push; two distinct arrays (even equal contents) differ. Fixes bug 1.
- **Field storage.** `StructFieldIR`/`StructFieldSize` for an array field become
  `ptr`/8 (a header pointer), joining the object-reference model. Field read loads
  the header and carries it as `ArrayHeader`; field write/reassign swaps the header
  pointer; `obj.arr.push(x)` writes through the header (`resolveArrayMutLoc`'s
  member case derives slots from the header like the identifier case already does).
  This shifts every struct field offset after an array field — a coordinated change
  across the ~40 `StructFieldIR` call sites the inventory enumerates.

### Ownership / memory (the hard constraint)

Sharing a header cell means multiple bindings/fields alias one heap allocation, so
the auto-free/`-optimize-memory` deep-free (`emit_free_deep.go`) can no longer free
an array's buffer at each binding's scope exit without risking a double-free or
freeing a still-referenced array. Options weighed in the ADR: (a) never
auto-free a shared (header-backed) array's buffer — leak under the non-GC modes,
correct under `-mm=gc` (Boehm scans it); (b) reference-count the header. Stage
plan leans to (a) with the leak documented as a perf follow-up (consistent with
TDD-00127's "amortized-growth deferred" precedent), because refcounting arrays is
a large separate mechanism and GC mode already handles it correctly.

## Stages

1. **Local aliasing + `===` fix.** `let a = b` / assignment of an array binding
   shares the RHS header (via `ArrayHeader`); array `===`/`!==` compares the
   identity pointer. Self-contained, no struct-layout change; fixes bug 1 and makes
   `let a = b; b.push()` live. E2E + example.
2. **Field storage migration.** Array fields become header pointers
   (`StructFieldIR` → `ptr`); field read/write/mutator/construction/destructuring/
   spread/JSON/clone/inspect/free updated per the site inventory. Fixes the field
   residue and the dangling-garbage. Largest, highest-risk stage; lands behind the
   full field-array regression net.
3. **Returns & remaining boundaries.** Any array-producing boundary that still
   re-headers (function return binding, closure capture) shares instead. Sweep for
   residual snapshot sites.
4. **Ownership.** Land the chosen free policy (never-free shared buffers under
   non-GC modes, documented) and verify ASan/`-mm=gc` clean.

## Open questions

- **Refcount vs never-free.** Leaning never-free (leak) under non-GC modes,
  documented as a perf follow-on, vs a header refcount. Decide in Stage 4.
- **Transient identity.** A transient array compared by data pointer is correct
  for `===` but a transient never aliases; confirm no path binds a transient to two
  names without going through a header first.
- **Struct offset churn.** Flipping `StructFieldSize` for array fields shifts
  offsets; verify no serialized/ABI layout (structured clone, JSON projection)
  hardcodes the 16-byte array-field slot beyond the inventory's list.
