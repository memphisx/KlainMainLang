# ADR-01752: A js number binding assigned null holds null

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-19

## Context

Under `-compat=js`, `var a = 1; a = null; console.log(a, a !== null)` printed `0 true` where Node prints `null false`. The cross-kind widening pass counted only scalar kinds, so null or undefined assigned into a number or boolean slot became that slot's zero. A copy of a widened binding (`b = a`) kept its own scalar slot too, because the pass decides widening only after the walk, and during the walk the copy saw the source's original number type. Test262's `for-of/set-contract-expand.js` looped forever on this.

The same test showed two more gaps:
- `for (var x of set) seen.push(x)` failed to compile ("type mismatch in array element"). `forOfBindingType` had no case for a Set, so the loop variable took the string default, and the empty-array pass ran before the bare-collection pass, so it never saw the set's element type.
- The front end answered a bare `new Set()` binding with the checker's element type, while codegen takes the type its later `.add` calls give it.

Also from the shadow report:
- A property of a function value other than its own (`f.toString`) took the checker's method type, though codegen reads it off the boxed function.
- The rule "a member read off a box is a box" also matched builtin globals (`Math['E']`, `process.env.TMP`), whose members codegen reads as declared.
- In `(x, y = x, z = y) => z`, codegen holds `y` and `z` as boxes (a default it can't type by). The front end typed the function that way but read `y` and `z` as the checker's number, and so answered the function's result, an async version's promise value and a `.then` callback's parameter as numbers.

## Decision

- Null and undefined count as a kind (`nullish`) in the js widening pass. Beside a number, boolean, array or unknown kind they widen the binding to the any box (`widenedKinds`). A string or object slot already holds null, so it stays as it is. An array counts as a kind only beside null; `map-expand.js` assigned `null` to an array binding and failed to compile ("cannot assign a non-array value to array variable").
- Each `b = a` records a copy. After the walk, widening flows along the copies to a fixpoint.
- `inferEmptyContainers` runs the map/set pass on both sides of the array pass. The array pass declares a bare collection binding with its final type (`bareCollectionType`), and a Set's for-of binding is its element type.
- The front end gives a bare `[]`, `new Map()` or `new Set()` binding codegen's type (`bareContainerType`), both as a global and as an identifier: a js `var array = []` nothing pushes into is codegen's `number[]`, where the checker's evolving array is `any[]`. It reads a function value's non-own property as the box codegen reads (`funcValueProp`). The member-off-box rule is narrowed to a builtin constructor's prototype object (`Array.prototype.map`).

- A read of a js parameter the function's own type holds as a box is that box. A return of a box makes the result a box (`ReturnType`, the function literal's `FuncRetType`), and an async body's promise value too (`asyncBodyReturn`, for the function, its global and its calls). A `.then` callback's unannotated value parameter takes a boxed promise value (`thenValueBox`). An arithmetic operator with a boxed operand is codegen's runtime-dispatch box (`dynamicBinary`), where the checker had typed `1 + (function (t) { return { a: t }; })(5).a` by the call's argument.

## Consequences

- `set-contract-expand.js` runs to completion and matches Node. `TestE2ECompatJSNullIntoNumberBinding`, `TestE2ECompatJSBareSetForOfPush` and `TestE2ECompatJSDefaultFromParam` cover the fixes.
- A copy is tracked only through a direct `b = a`. A value that reaches a binding through a call or a property read still takes that expression's own type.
