# ADR-02018: A static object as a dynamic object's prototype

- **Date**: 2026-11-21

## Context

`Object.create(new C())`, `Object.create(lit)` for a literal of a static
type, and `Object.setPrototypeOf(o, c)` threw "Object prototype may only
be an Object or null". A dynamic object's prototype chain is a chain of
bags, and a static object (a struct of its layout) is not a bag. This
happened in both lanes.

## Decision

- Each static object used as a prototype gets one stand-in bag
  (`__kml_dynobj_standin`, cached per object, so identity holds).
- The chain walk (`[[Get]]`, `in`) reads through a stand-in to what its
  object owns: a property added to it, with an accessor run with the
  receiver as `this`, and then a field of its layout.
- The stand-in's own prototype is the object's prototype, its class's
  prototype object. Class methods and accessors therefore read on with
  the receiver, and `instanceof` sees the class.
- `Object.getPrototypeOf` maps a stand-in back to the static object.

## Implementation notes

- codegen/llvm/dynobjsrc/dynobj.c: the stand-in table, `standin_read`,
  `__kml_dynobj_proto_box`, `__kml_dynobj_box_bag`.
- codegen/llvm/emit_dynobj.go: `emitDynProtoOperand`'s static-object arm.
  A bigint or symbol cell stays a primitive.

## Verification

- `TestE2EObjectCreateStaticObjectJS` and
  `TestE2EObjectCreateStaticObjectTS` match Node on Linux x86 (Node304).
