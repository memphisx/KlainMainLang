# ADR-01523: A captured evolving binding is TypeScript's implicit any

- **Relations**: Extends TDD-00162, TDD-00230
- **Date**: 2026-10-10

## Context

An unannotated binding declared without a value (`let a;`) evolves by its
assignments. Read in another function, tsc types it `any` and, under
noImplicitAny, reports TS7034 at the declaration and TS7005 at each such
read (a plain `=` store is not a read). The checker typed those reads by
the binding's storage type and reported nothing, so the strict lane
compiled programs tsc rejects, and the js lane's reads disagreed with the
`any` global codegen stores.

## Decision

- A read of an evolving binding in another function is `any`; the
  strict lane reports TS7034 and TS7005 as tsc does.
- -compat=js: such a top-level binding is the `any` global codegen
  stores, in codegen's pre-declaration inference and in the shadow
  oracle; the js parameter pre-pass types a top-level binding by the
  checker's declared type when it has one.
