# ADR-00913: Monomorphize a named-function HOF callback against element hints

- **Date**: 2026-09-12
- **Relations**: Extends TDD-00010 (monomorphization), TDD-00028 (callback hints)

## Context

Invalid-IR sweep. A named function used as a `reduce`/`reduceRight` callback over
a non-number array emitted invalid IR:

```ts
function callbackfn(prevVal, curVal, idx, obj) { return prevVal + curVal; }
['1','2','3','4','5'].reduce(callbackfn);   // clang: 'ptr' where 'double' expected
```

From `built-ins/Array/prototype/{reduce,reduceRight}/15.4.4.2{1,2}-10-{2,5}.js`.

## Investigation

`resolveCallbackWithHints` (`emit_func.go`) seeds element-type hints into an
arrow/function-EXPRESSION callback's untyped parameters (`emitArrowFunctionWithHints`
/ `emitFunctionExpression(fe, hints)`), but a NAMED-function reference fell
through to `resolveCallback`, which reuses the function's already-registered
signature — where unannotated parameters defaulted to `number` (i64). Over a
string array the accumulator/element are string pointers, so the body's
`prevVal + curVal` mixed an i64 parameter with a string value.

## Decision

Re-emit the named function monomorphized against the hints — the same
"emit a decl under a mangled name with a substituted signature" path
`instantiateGenericFunc` uses, keyed here on the hint types rather than type
parameters (ADR-00913):

- Store every non-generic top-level function declaration in `topFuncDecls`
  (registerFunctions), so the body is available to re-emit.
- In `resolveCallbackWithHints`, for a named-function callback, build a variant
  signature: each UNANNOTATED parameter covered by a real, differing hint takes
  the hint type; explicitly-annotated parameters and destructuring patterns are
  untouched. If no parameter changes, fall back to the ordinary path.
- Mangle a variant name from the specialized parameter types (`mangleTypeArg`),
  memoize in `e.funcs`, and `emitFunctionDeclAs` it. `emitFunctionDeclAs` is
  signature-driven (`pty := sig.ParamTypes[i]`), so the body is emitted with the
  specialized parameter types. The return type is re-inferred when unannotated.
- Skipped for async/may-suspend/rest functions and when a local closure variable
  shadows the name.

## Implementation notes

- `topFuncDecls` mirrors `genericFuncs` but for ordinary functions.
- Memoization is by mangled name, so the same specialization across many call
  sites emits once; the original (i64) function is still emitted for direct
  calls that use it normally.

## Side effects discovered

`var r = arr.reduce(cb)` with NO type annotation on `r` over a non-number array
is a pre-existing `inferExprType`-vs-emit gap (reduce's result type infers wrong
without an annotation) — reproduces identically for inline arrow/function-
expression callbacks, so it is orthogonal to this change and left as is (a clean
compile error, not invalid IR). The `staging/sm/Iterator/prototype/reduce` file
uses the Iterator-helper path (a generator misrouted), unaffected here.

## Verification

- Runtime: `['1','2','3'].reduce(cb)` → "123", matching Node.
- The four Array reduce/reduceRight coerced-element files compile clean.
