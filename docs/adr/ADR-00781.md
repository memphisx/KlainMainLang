# ADR-00781: `process.stdout.columns`/`.rows` as `number | undefined` off a TTY (TDD-00187 Stage 4)

- **Relations**: Completes [TDD-00187](../tdd/TDD-00187.md)'s staged plan (Stages 1–3: [ADR-00778](ADR-00778.md)/[ADR-00779](ADR-00779.md)/[ADR-00780](ADR-00780.md)); retires the deliberate divergence of [ADR-00518](ADR-00518.md)
- **Date**: 2026-09-08

## Context

`process.stdout`/`stderr` `.columns`/`.rows` off a TTY (piped/redirected)
returned a **deliberate, tested 80×24 fallback** — chosen when the compiler had
no undefined-number at all, and explicitly earmarked by TDD-00187 Stage 4 (and
BACKLOG §2) for retirement once the sentinel existed. Its test asserted `80x24`.

## Decision

- The TTY shim's `__kml_tty_cols`/`__kml_tty_rows` return **-1** on a
  non-terminal fd (both the POSIX `ioctl(TIOCGWINSZ)` and Windows
  `GetConsoleScreenBufferInfo` arms) instead of 80/24.
- `emitProcessWinSize` wraps the result as `number | undefined`: present =
  `result >= 0`, absent payload zeroed — the `{ i1, i64 }` optional from
  Stage 1's `wrapUndefinedable`. `inferExprType` mirrors it, so the strict
  gate applies (`const c: number = process.stdout.columns` and
  `rows * 2` are compile errors; narrow / `?? 80` / `!`), and `-compat=js`
  auto-widens (an off-TTY read then collapses to 0, not 80 — the honest
  payload, no fabricated size).
- The divergence test inverted: `TestE2ETtyWinSizeFallback` (asserting
  `80x24`) became `TestE2ETtyWinSizeUndefinedOffTTY` (asserting
  `undefined` + the `?? 80` idiom).
- One gate fix surfaced by the corpus: the Stage 1 strict arithmetic gate
  wrongly fired on **string concatenation** (`"terminal: " + columns`), which
  TS permits on `T | undefined` (an absent operand renders `"undefined"`, as
  in Node). The gate now exempts `+` with a string operand; the concat path
  already stringified the aggregate correctly (ADR-00537).

## The family member deliberately left (and why)

TDD-00187's Stage 4 sentence also names "closed-stream scalar reads" — the
`{value, done}` records. Examined and **not** flipped here, for two different
reasons, both recorded in the backlog:

- **Generator `.next().value` after completion** stays bare `T` zero-fill:
  tsc types `Generator<T>`'s result value effectively `any`, so the current
  typed `T` is already *stricter* than TS — flipping it to `T | undefined`
  would diverge further from tsc while breaking every `g.next().value`
  arithmetic consumer. Not a faithfulness win.
- **`ReadableStream.read()`** is typed as a discriminated record
  (`{done: false, value: T} | {done: true, value?: undefined}`), which this
  compiler's single fixed record shape cannot express with a mere field-type
  flip — making `value` nullable would also force narrowing on the hot
  `done:false` arm where TS requires none. That is a record-shape design of
  its own (alongside `desiredSize`'s `0`-vs-`null`), not a TDD-00187 type
  flip; the existing streams caveat rows stand and the item is tracked in
  BACKLOG §1.1.

With this, the sentinel work itself — representation, inference, strict/compat
policy, and every zero-fill site the TDD's Context enumerated as the caveat
family — is complete.

## Consequences

- The 80×24 caveat rows (process-cli, the platform known-gaps table, BACKLOG
  §2's deferred edge) are retired; `columns`/`rows` become zero-caveat rows.
- TUI-style code should read `process.stdout.columns ?? 80` — the same
  expression, with the fallback now explicit and chosen by the program
  rather than fabricated by the runtime.

Verified on macOS/Apple Silicon: full `make test-par`, 280/280 examples,
Node oracle flat. (The Windows shim arm compiles under the same source; its
behavior rides the existing Windows CI lane.)
