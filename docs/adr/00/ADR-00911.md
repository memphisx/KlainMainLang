# ADR-00911: Default/omitted parameter filling for IIFE closure calls

- **Date**: 2026-09-12

## Context

Invalid-IR sweep. An immediately-invoked function expression that omitted a
trailing parameter emitted invalid IR:

```ts
(function(f = 123) { /* ... */ }());   // clang: not enough parameters specified for call
(function(c) { c = 3; }());            // same — c omitted
```

The dominant shape in the Test262 "not enough parameters specified for call"
bucket (the annexB `*-func-skip-dft-param` family + parameter-shadowing IIFEs).

## Investigation

A named-function call fills defaults / omitted args at the call site from
`sig.Defaults` (`emit_call.go`). The IIFE path (`emit_call.go`, the
`*ast.FunctionExpression` callee case) instead routed straight to
`emitClosureCallByPtr`, whose arg loop runs only `i < len(args)` — so it emitted
a `call` with fewer operands than the function's parameter count. JS allows a
call with fewer arguments than parameters (omitted → `undefined`, or the
parameter's default).

The function expression is *literal* at this call site, so its own
`Param.Default` expressions are in hand — no `Type` extension needed (unlike a
call through an opaque stored closure value, which is left as future work).

## Decision

In the IIFE call path, pad the argument list up to the function's regular
(non-rest) arity: each missing parameter contributes its `Default` expression if
it has one, otherwise a synthesized `undefined` literal (which coerces to the
parameter slot's zero for a typed parameter). Then dispatch through
`emitClosureCallByPtr` as before.

## Implementation notes

- Rest parameters are never defaulted, so the last slot is excluded from the pad
  count.
- A default that references an earlier parameter (`function(a, b = a)`) is passed
  as its own expression; it resolves in the caller scope, which is correct for
  the constant/self-contained defaults in the corpus. Cross-parameter defaults
  evaluated against sibling parameters (the call-site scratch-symbol machinery
  named calls use) are not replicated here.
- An omitted *untyped* parameter pads with `undefined`, which the untyped-param
  arg-type guard then reports as a clean compile error ("add a type annotation")
  rather than invalid IR — a strict-subset rejection, not a miscompile.

## Side effects discovered

Default-parameter filling through an *opaque* closure value / stored object
method (`obj.method(3)` where `method(x, y = x)`) is NOT fixed — the defaults
live in the method AST, not the closure's `Type`, so the call site can't see
them. Needs a `Type`-level default carrier (or body-prologue default
application); deferred as a design decision. The `meth-dflt-params-*` Test262
files remain CLANG_ERROR.

- `TestE2EIIFEDefaultAndOmittedParams` (new).
- 9 of the 22 "not enough parameters" files now compile+run; 3 more become clean
  compile errors (out of the CLANG_ERROR bucket).
- `make examples` 296/296.
