# ADR-01137: Lowered string methods: receivers, optional parameters, a C string runtime (P3.2 second stage)

- **Relations**: `Implements TDD-00230` (Phase 3, P3.2); `Extends ADR-01136`
- **Date**: 2026-09-25

## Context

[ADR-01136](ADR-01136.md) lowers static methods of a builtin global
(`Math.sin(x)`) whose parameters are required numbers. Most of the builtin
surface is methods on a value (`s.trim()`), with optional parameters
(`s.indexOf(search, position?)`) and string arguments. Those need three
things the first stage lacks:

- a receiver passed to the entry point;
- a string representation;
- a way for the entry point to tell an omitted optional argument from any
  value of its type.

## Investigation

- **Receivers.** The checker reads a string's members through its apparent
  type, `String`, and records the method's declaration (`MemberDecl`). A
  callback parameter it cannot type is still one codegen holds as a string:
  `"hello".replace(/l/g, (m) => m.toUpperCase())`, where the replacer's
  parameter is unanswered.
- **Memoising the decision is unsound.** `inferExprType` consults
  `loweredCall` before a callback's parameters are bound in codegen's scope,
  so a cached "not lowered" answer outlived the binding and failed the call
  later. The decision reads codegen state, so it is recomputed per query.
- **Optional parameters.** JavaScript treats an argument of `undefined` as
  omitted (`s.indexOf("o", undefined)` searches from 0). Presence is
  therefore a run-time fact whenever the argument may be undefined: a
  `number | undefined`, an `any`.
- **The C boundary.** A C `bool` is an `i1` that the IR must mark `zeroext`,
  both as a parameter and as a result.
- **Empty search strings.** macOS `memmem` returns NULL for an empty needle,
  where glibc returns the haystack. The runtime's search used `memmem`, so
  on macOS `"s".includes("")` was `false`, `s.indexOf("", 99)` was `-1` and
  `"abc".replace("", "-")` was `"abc"`. Node gives `true`, the length, and
  `"-abc"`. Windows has no `memmem` at all: the IR runtime defines one, and
  no C header declares it.
- **`search` fell back to the deleted `indexOf` emitter** for a non-string,
  non-RegExp argument. That path did not compile in the previous build
  either (`s.search(5)`). JavaScript compiles any non-RegExp argument of
  `search`, `match` and `matchAll` as `new RegExp(String(arg))`, with
  `matchAll`'s being global. `match` and `matchAll` rejected a string
  argument outright, which was a disclosed caveat.

## Decision

- **Receivers.** `loweredCall` also accepts a method on a string: one the
  checker types as `string`, or, when the checker cannot type it or types
  it `any`, one codegen holds as a string, resolved through
  `Checker.StringMember` (String's own member). The receiver is passed
  first. `loweredCall` is not memoised. A possibly-absent receiver (a
  `string | null`, a spawn result's `stdout`) is lowered too. `emitCall`
  consults `loweredCall` after registering its receiver guard, so an absent
  receiver throws Node's `Cannot read properties of null (reading
  'toUpperCase')` rather than reaching the entry point.
- **Representations.** `string` is added to `number`, `boolean` and `void`,
  as a pointer. A string argument is converted by ToString
  (`emitArgToString`), a number argument by ToNumber.
- **Optional parameters.** Each one is passed as two arguments: an
  `i1 zeroext` presence flag, then the value (zero when absent). An absent
  argument is an omitted one, a literal `undefined`, or, at run time:
  - a `T | undefined` scalar whose presence bit is clear (a `T | null`
    scalar is present);
  - an `any` word equal to the undefined box;
  - a possibly-undefined pointer that is null.

  `optionalPresence` decides which applies.
- **The C ABI.** Booleans cross the boundary as `zeroext i1`
  (`paramIR`/`resultIR`).
- **Where entry points come from.** A `@link` name is either an embedded C
  source (`runtimeUnits`: `casemap`, `string`), compiled in when used, or a
  system library. A `@lower` target the IR runtime defines
  (`runtimeSymbols`: `__kml_trim`, `__kml_trim_start`, `__kml_trim_end`) is
  emitted by its `ensure*` rather than declared.
- **`codegen/llvm/stringsrc/string.c`** is the C string runtime.
  - It holds `__kml_String_indexOf` and `__kml_String_includes`:
    ToIntegerOrInfinity of the position, clamped to the string.
  - Its search is portable, with no `memmem`, and finds an empty needle at
    the position.
  - Positions are byte offsets, as everywhere in the string layer
    ([ADR-00028](ADR-00028.md)).
- **`casemap.c`** gains `__kml_String_toUpperCase`/`toLowerCase` taking the
  receiver alone.
- **Lowered** in `lib/es.d.ts`:
  - `trim`, `trimStart`, `trimEnd`, `toUpperCase`, `toLowerCase`, `indexOf`
    and `includes`;
  - deleted: their hand-written emitters and `emit_call.go` dispatch, the
    IR `__kml_str_indexof`/`__kml_str_indexof_from`, and `casemap.c`'s
    length-taking entry points.
- **Empty search in `replace`.** `__kml_replace` treats an empty search as
  matched at 0.
- **RegExp coercion.** `emitRegExpArg` gives `match`, `matchAll` and
  `search` a non-RegExp argument's RegExp, as JavaScript builds it.

## Implementation notes

- **The test harness.** It links embedded C sources through its own list
  (`tests/compiler_test.go`'s `append*`), which needed `appendStringC`
  beside `EmbeddedCSources`. BACKLOG §5 records building it from
  `EmbeddedCSources` instead.
- **Rejections move to the checker.** The strict lane's rejection of a
  `Symbol` position (`"hello".indexOf("l", Symbol("x"))`) is now the
  checker's TS2345, from the `symbol` type ([ADR-01138](ADR-01138.md)).
  Under `-compat=js` the call throws JavaScript's own TypeError from
  ToNumber.

## Side effects discovered

- **Byte offsets.** String positions are still byte offsets, not UTF-16
  indices (`"héllo".indexOf("l")` is 3 here, 2 in Node). This is disclosed
  on the string status rows. The lowered methods now keep that rule in one
  C file.
- **`string | symbol`** narrowed by `typeof` is not narrowed by codegen
  (BACKLOG: `typeof` symbol narrowing in codegen).
- **`match` results** still lack `index`/`input`/`groups`, as already
  disclosed.

## Verification

- **New tests:** `TestE2EStringLoweredFromDeclarations` covers receivers, a
  user `trim` method, an optional position that is absent, `undefined`,
  run-time undefined or present, empty searches, a callback parameter, and
  ToString under `-compat=js`. `TestE2EStringMatchCoercesNonRegExpArgument`
  replaces the rejection test. Every expected output was checked against
  Node.
- **Example:** `examples/strings/search_compare.ts` gains empty searches and
  optional positions, and prints what Node prints.
- **`make examples`:** 358/358. It caught the unguarded receiver
  (`examples/basics/null_deref_typeerror.ts` segfaulted) and the nullable
  one (`examples/process/spawn_sync*.ts`) before they were fixed.
- Test262: strict 7,005 (up from 7,004), js 7,738 (up from 7,733).
- `make test-par` fails only on the known macOS `-mm=gc` segfaults, after
  the Symbol-argument rejection tests moved to the checker's message.
