# ADR-00960: `res.write`/`res.end` frame a binary chunk as raw bytes

- **Relations**: `Implements TDD-00195` (Stage 2 remainder). Closes the binary-chunk side effect noted in `ADR-00959`.
- **Date**: 2026-09-15

## Context

`res.write(chunk)` / `res.end(chunk)` coerced every chunk to a string via
`emitStringConcat` (`emitResSinkWriteVal`, the buffered `body` append). A binary
chunk — `Uint8Array`/`Buffer`/any TypedArray — is an array aggregate, not a
`ptr`, so this both mis-framed the payload (it stringified the array rather than
sending its bytes, per ADR-00959's noted side effect) and, on the buffered
`res.end(buf)` branch, emitted invalid IR (`icmp eq ptr <{ptr,i64}>, null`
inside the concat's null-guard). Node sends `res.write(buf)`'s exact byte range.

## Decision

Detect a binary chunk (`Ty.IsTypedArray`, which covers `Buffer`) in the two
sink-write paths and frame its raw bytes:

- **Streaming path** (`emitResSinkWriteVal`): extract `{ptr, len}` from the
  array aggregate, compute `byteLen = len * elemSize`, and push the data pointer
  + `byteLen` straight through `__kml_ws_write` — no stringification.
- **Buffered path** (`res.end` with no prior `res.write`): a new
  `binaryChunkToHeaderString` copies the array's raw bytes into a fresh
  length-headered string, which is then concatenated onto `body` as before. The
  buffered flush already frames `body` by its header length (binary-safe,
  TDD-00120), so an embedded NUL reaches the socket whole with the correct
  Content-Length.

A string chunk is unchanged (the existing concat path).

## Implementation notes

- Element byte size is `elemTy.Align()` (1 for `Uint8Array`/`Buffer`), matching
  `emitArrayCopy`'s convention; the `* elemSize` multiply is elided when it is 1.
- `emitStringAlloc` writes the length header, so `binaryChunkToHeaderString` only
  memcpys the bytes and appends the retained NUL terminator.
