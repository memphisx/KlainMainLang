# ADR-01990: WeakMap entries are ephemerons under -mm=gc

- **Relations**: Implements TDD-00230; fixes TDD-00112
- **Date**: 2026-11-20

## Context

TDD-00230's GC interface names ephemerons (`WeakMap`). Under `-mm=gc` a
WeakMap kept its key through a disappearing link, but its value in the map's
own cell, strongly. A value that references its key (`wm.set(k, { k })`, a
closure over `k`) then kept the key reachable forever: 2,000 such keys, none
collected, where Node collects them all. The GC test only stored string
values, which cannot reach back to their key.

Boehm 8.2 has no ephemerons and no hook at the end of marking, so a fixpoint
over the entries is not available; a finalizer's client data is a strong
root; a side table keyed by the key is a root too. The only place a value can
live and be traced exactly while its key lives is inside the key's own block.

## Decision

- A program that makes a WeakMap or WeakSet (its IR names `__kml_weak_create`
  or `__kml_ptab`; `UsesWeakMaps`) compiles the collector shim with
  `KML_EPH`. Every scanned block then gets two extra words, and the block's
  next-to-last word is its ephemeron slot (`kml_gc_eph_slot`): with interior
  pointers on, Boehm adds a byte to each request and does not scan a block's
  last word. `__kml_heap_usable` reports the size without them, and
  `realloc` carries the slot to the moved block's end.
- `weak.c` keeps an entry's value in a node chained from its key's slot,
  naming its map by the map's handle complemented, so a key never keeps a map
  alive. A collected map's finalizer removes its nodes from keys still alive.
  A key with no slot (static data, a pinned or pointer-free block) keeps its
  value in the map's cell, as before; such a key is never collected.
- With `KML_EPH`, typed allocation (ADR-01943) falls back to conservative
  scanning: Boehm stores a typed block's descriptor in its last word.
- `kml_gc_finalizer` is unordered (`GC_register_finalizer_no_order`). A key
  that reaches itself through its value is still finalized, as JavaScript's
  FinalizationRegistry does; Boehm's ordered finalization refused it
  ("Finalization cycle").
- A program without WeakMap pays nothing: its machine code is identical.
- A disappearing link is registered on the key's block start, so a key that
  points inside its block is cleared too.

## Side effects discovered

- `WeakMap.get` of a missing key with an object, string or array value type
  returned a null object, which `console.log` dereferenced (a crash in every
  memory mode). It is now `V | undefined`, as `Map.get` is (ADR-00833).

## Verification

`TestE2EGCModeWeakMapEphemeron` (self-referencing entries collected and
finalized; a live key keeps its value), `TestE2EWeakMapGetPointerMiss`
(output equal to Node's), the weak, finalization and `-mm=gc` suites, on the
Mac (arm64).

Benchmark (Mac arm64, `-mm=gc`, 20 M allocations): without WeakMap the text
section is byte-identical and runs 248 ms before and after (8 interleaved
runs); with a WeakMap, 242–251 ms before, 219–247 ms after (typed allocation
skipped), at 16 bytes more per scanned block.
