# TDD-00153: Object-literal getters/setters (and object `this`)

- **Status**: Implemented

- **Date**: 2026-09-01

## Context

Class getters/setters work ([TDD-00030](TDD-00030.md)); **object-literal**
getters/setters do not — `const o = { get x() { return this._x }, set x(v) { this._x = v } }`
is a parse error (`get x()` isn't recognized in `parseObjectLiteral`). This is
the last piece of the "Getters / setters" status row, which currently sits at
loose-only because object-literal accessors, static accessors, and logical
assignment on an accessor are all unimplemented.

The blocker is deeper than parsing: an accessor body needs `this` bound to the
object it reads/writes. This compiler deliberately has **no rebindable `this`** —
a plain `function(){}` body with `this` is a clean rejection, and object-method
shorthand `{ foo() {} }` is sugar for a closure-typed field with no `this`
binding. Class methods, by contrast, *do* bind `this` (to the receiver pointer).
So "object `this`" is really "give an object literal the same receiver-binding a
class instance already has."

## Design

### Key enabling fact

`ClassType` in `types.go` **always also sets `IsObject`** — a class value is an
ordinary heap struct (same `StructIR`/`StructSize`/`FieldIndex`/GEP machinery as
any object literal) *plus* a `ClassName` that drives method/accessor dispatch.
Every accessor read/write path is keyed purely on `objVal.Ty.IsClass` /
`objVal.Ty.ClassName`:

- Read: `emitMember` → `classAccessorSigs(ClassName, prop)` → `emitClassCall(..., accessorMethodName("get", prop), ...)` (`codegen/llvm/emit_exprs_member.go`).
- Write: `tryEmitAccessorAssign` → `classAccessorSigs` → `emitClassSetterCall(..., accessorMethodName("set", prop), rhs)` (`codegen/llvm/emit_exprs_assign.go`).
- `this`: `emitClassCall` already passes the receiver pointer as the method's
  implicit first argument and binds `this` to it in the body.

### Recommended: synthesize an anonymous class per object-literal-with-accessors (Option A)

When an object literal declares at least one `get`/`set` (or a method-shorthand
that references `this`), emit it as an instance of a **synthesized anonymous
class** `__kml_objlit_<N>` registered in `e.classes`:

- Plain data properties (`_x: 10`) become the synthetic class's **fields**.
- Each `get x`/`set x` becomes a method registered under
  `accessorMethodName("get"|"set", "x")` — the exact dispatch key the class path
  already reads.
- Method-shorthand properties that reference `this` become ordinary class
  methods (a free bonus: object methods gain a working `this`); those that don't
  keep the current closure-field lowering, so nothing regresses.
- The literal is constructed exactly like a class instance (calloc the struct,
  store the field initializers); its `Type` carries `IsClass`+`ClassName` so all
  existing read/write/`this` dispatch applies **with zero changes** to the
  member/assign paths.

This reuses the entire proven class-accessor subsystem. Concretely it is a
**desugaring pre-pass**, not on-the-fly synthesis at emit time (which would fight
the class registration/emission ordering — classes register in a pre-pass and
emit in their own pass, but object literals emit mid-function-body):

1. **Parser** — accept `get x()`/`set x()` in `parseObjectLiteral`, storing each
   as an `ObjectProperty` carrying `AccessorKind` + a `FunctionExpression` value
   (mirroring the class-member accessor parse at `parser_classes.go:248`).
2. **Desugar pass** (before `registerClasses`) — walk the AST; for each object
   literal that declares an accessor (or a `this`-referencing method), synthesize
   an `ast.ClassDeclaration` `__kml_objlit_<N>`:
   - data properties → class fields;
   - `get x`/`set x` → methods with `AccessorKind` set (already the class path's
     dispatch key);
   - a synthesized constructor taking the data initializers as parameters and
     assigning `this.<field> = arg`;
   - replace the object-literal expression with `new __kml_objlit_<N>(<data
     values>)`.
3. Everything downstream is the **existing class path, unchanged**:
   `registerClasses` builds the `ClassInfo` and accessor `MethodSigs`;
   `emitClassDecl` emits the accessor functions with `this` bound; the member-read
   (`emit_exprs_member.go`) and assign (`emit_exprs_assign.go`) hooks fire because
   the value's `Type` is now `IsClass`.

The only genuinely new code is the parser branch and the desugar pass; no changes
to member/assign/`this`/dispatch codegen.

### Rejected: extend the object `Type` with a parallel accessor table (Option B)

Add an accessor-sig table to `IsObject` (non-class) types and a separate object
`this`-binding path. This duplicates `classAccessorSigs`/`emitClassCall`/
`tryEmitAccessorAssign` for objects and re-solves `this`-binding from scratch —
more code, more surface, and a second dispatch path to keep in sync. Rejected in
favor of A's reuse.

### Structural-typing boundary (the real V1 scope question)

A synthetic class is nominal; a structural target that names an accessor property
(`const p: { x: number } = o`, or passing `o` to `f(a: { x: number })`) expects
`x` as a *field*, which the synthetic class exposes only as an accessor method —
a genuine mismatch. V1 scope: object-literal accessors are supported for **direct
use** (`o.x` read, `o.x = v` write, `this` inside the accessor). Assigning such a
literal to a structural object type that names an accessor property, or spreading
it, is a clean rejection with a clear message — not a silent miscompile. This
mirrors how the compiler already scopes other "value used two ways" cases.

| Dependency | Status | Notes |

## Open questions

- **Synthetic-class dedup/naming**: one synthetic class per literal *site*, or
  structural dedup across identical shapes? Per-site is simplest and correct;
  decide whether identical shapes must share a name for any equality/`instanceof`
  semantics (likely irrelevant — object literals aren't `instanceof`-tested).
- **Structural assignment**: exactly which target shapes reject vs. coerce. Start
  with "reject any assignment of an accessor-bearing literal to a differently-
  named structural object type"; widen only if a real case needs it.
- **Static accessors on object literals** don't exist in JS (that's a class-only
  concept) — out of scope by definition; the status row's "static accessors"
  caveat refers to *class* static accessors, tracked separately.
- **Logical assignment on an object accessor** (`o.x ??= v`) inherits the class
  path's existing V1 rejection (double-invocation risk) unchanged.
