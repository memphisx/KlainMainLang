# ADR-00296: `ReadableStream<T>` core — queue/high-water-mark/pull state machine, readers, strategies, `from()`, `for await`

- **Relations**: Implements [TDD-00097](../tdd/TDD-00097.md) Stage 1; builds on [ADR-00263](ADR-00263.md) (promise settle), [ADR-00268](ADR-00268.md) (microtask-accurate await), [ADR-00270](ADR-00270.md) (reusable promises)
- **Date**: 2026-08-22

## Context

TDD-00097 Stage 1: the first WHATWG stream surface, and the compiler's first
genuinely incremental data path — everything before this (fetch bodies, http
req/res, fs) is buffered end-to-end. The core deliverable is the backpressure
model: a chunk queue with a high-water mark and size accounting, the spec's
*CallPullIfNeeded* scheduling, and read() promises that park when the queue is
empty and are fulfilled by a later enqueue.

## Investigation

The promise/microtask runtime already covers everything a stream state machine
needs: `__kml_promise_settle` + the reaction list (ADR-00263), the microtask
FIFO's head-index queue pattern (`runtime_microtask.go`), reusable promises
(ADR-00270), and `emitAwaitTaskPromise`'s two-tier await (scheduler park under
fibers, microtask/timer drive without — ADR-00268). No new scheduler
primitives were needed.

The builtin cost model (hand-written per-builtin plumbing — see
`emit_eventemitter.go` as the closest precedent) was followed rather than
inventing a generic object system: a dedicated AST node, `Is*` type flags with
a `StreamChunk` payload, name-keyed parsing, flag-keyed dispatch in
`emit_call.go`.

Two design points worth recording:

- **One allocation, three compile-time views.** The stream, its default
  controller, and its reader are the *same* `%kml.rstream` pointer, typed
  `IsReadableStream` / `IsRSController` / `IsStreamReader` respectively.
  `getReader()` is a lock-flag check plus a retype; controller callbacks
  receive the stream pointer hinted as the controller type.
- **Type-agnostic runtime, per-site fulfill thunk.** Chunks travel the queue
  as two raw i64 words (the promise-v0/v1 marshalling; array-shaped values
  use both). The runtime settles read() promises through a compiler-emitted
  `@__kml_rs_fulfill_N` stored in the struct, which rebuilds the typed chunk
  and mallocs the `{value, done}` record (`genNextResultType`'s shape, so
  `.value`/`.done` and destructuring ride the ordinary object machinery).

## Decision

- New `codegen/llvm/runtime_streams.go`: the 144-byte `%kml.rstream` struct
  (state, stored error, chunk FIFO with 24-byte `{v0,v1,size}` entries,
  `queueTotalSize`/`hwm` doubles, size/pull/cancel closure slots, flags
  bitfield, pending-read promise FIFO, closed promise, fulfill thunk) and its
  helpers: alloc, queue push/pop (compact-then-grow head-index FIFOs),
  `__kml_rs_pull_if_needed` (spec CallPullIfNeeded with pulling/pullAgain
  coalescing; an async pull's promise gets a `pull_settled` reaction that
  errors the stream on rejection), enqueue/close/error/read/cancel/
  desiredSize/lock/unlock, plus a generic `__kml_promise_add_reaction`
  (attach-or-enqueue, the runtime-side form of the pattern `.then` emits
  inline). Layered on `ensurePromiseSettle` only — no fibers, no libcurl.
- New `codegen/llvm/emit_streams.go`: construction (compile-time destructuring
  of the underlying source `{start, pull, cancel}` and strategy
  `{highWaterMark, size}` object literals; `CountQueuingStrategy`/
  `ByteLengthQueuingStrategy` accepted as the strategy argument), normalized
  callback wrappers (pull → `ptr (env)` returning the callback's promise or
  null; size → `double (env, v0, v1)`), method/property dispatch, spec start
  timing (start runs synchronously; the started flag that gates the first
  pull is set via microtask, or via a reaction on an async start's promise),
  `ReadableStream.from(array)`, and `for await...of` over a stream/reader.
- Frontend: `NewReadableStreamExpression` (`ast/nodes.go`), name-keyed parse
  (`parser/parser_literals.go`), `ReadableStream`/`ReadableStreamDefaultReader`/
  `ReadableStreamDefaultController` type args (`parser/parser_types.go`,
  `emitter.go` resolveType).
- `reader.read()` returns `Promise<{value: T, done: boolean}>` as a
  task-shaped promise, so plain `await` works in both runtime tiers.

## Implementation notes

- Files touched beyond the two new ones: `ast/nodes.go`, `resolver/rename.go`
  (import-rename walk), `parser/parser_literals.go`, `parser/parser_types.go`,
  `codegen/llvm/{types,emitter,emit_call,emit_exprs,emit_exprs_types,
  emit_exprs_member,emit_exprs_vardecl,emit_stmts,emit_func,emit_objects}.go`.
- Two pre-existing gaps surfaced and fixed in passing:
  - `scanExprFV` (closure free-variable scan) must descend into every new
    expression node — the pull callback's captures were invisible until a
    `NewReadableStreamExpression` case was added, producing "undefined
    variable" at emission.
  - An **async block-bodied arrow with no `return`** inferred a `void` return
    and emitted `ret ptr` (the inline-async promise slot) inside a
    `define void` — invalid IR. `emitArrowFunctionWithHints` now wraps a
    non-Promise inferred return in `PromiseOf(...)` for async arrows.
  - `const { value, done } = await …` — `resolveObjectPtr` gained an
    `AwaitExpression` case (destructuring an awaited object result also
    benefits async generators' `.next()`).
- An array-shaped `for await` loop variable binds through the two-alloca
  `Symbol{Ptr, LenPtr}` array shape, not a single `{ptr,i64}` cell.

## Side effects discovered

- The no-fiber await fast path skips the microtask drain when the awaited
  promise is already settled, so a pull scheduled by the start microtask can
  run one observable tick later than real JS (recorded as a STREAMS.md
  caveat).
- `read()` on a closed stream yields `{value: 0-value, done: true}` rather
  than `undefined` (typed-language zero value) — caveat.
- `releaseLock()` with queued pending reads leaves them pending instead of
  rejecting them — caveat.

## Verification

- `tests/streams_test.go`: 12 E2E cases — start/enqueue/read, pull cadence
  under HWM 1 via `for await`, error→read rejection, `from().values()`,
  cancel running the source's cancel, size algorithm + `desiredSize`
  accounting, async pull (awaiting inside pull), `Uint8Array` chunks with
  `ByteLengthQueuingStrategy`, destructured read + `closed` + lock/release,
  double-getReader() TypeError, enqueue-after-close TypeError, and a parked
  read fulfilled by a `setTimeout` enqueue. All pass (Mac).
- `examples/streams/readable.ts` — pull-based squares, byte chunks decoded
  through `TextDecoder`, reader-level reads.
- Full `go test ./...` green (Mac); `go vet` clean.
