# ADR-01754: Static generator methods and generator method values

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

The shadow report's generator buckets came from four separate gaps:
- A static generator method (`static *sg()`) was a compile error.
- `const r = c.g`, where `g` is an instance generator method, gave `typeof r` `number`. Codegen's member inference had no case for a generator method read as a value, so the binding took the `i64` default, although the read itself returns the method's function record as a box.
- A class method returning a generator function's call (`static w() { return g(); }`) was typed `number`. Generators registered with the functions, after the classes, so a method's return inference could not see `g`.
- A class declared in a function whose static member calls a local function (`static w() { return k(); }`) failed with "no static method `#__kml_scap_k`". The closure conversion stores the local in a hidden static field, but a call of `M.field(...)` only looked up static methods.

The shadow report also had front-end gaps around these values:
- A library global as a receiver or a callee (`process.pid`, `setTimeout(…)`, `Reflect.ownKeys`) had no answer. Codegen never materializes one there: it dispatches the member or call by name, so its type is the default number, or the box it holds for a namespace object.
- A top-level `var gen = function* () {}` had no answer. Codegen rewrites it into a generator declaration, but the front end only matched declarations, and its binding answer was the box a nested one is held as.
- `var it = gen()`, `var r = it.next()` and `r.value` had no answer: the identifier read did not consult the call type codegen gives the declaration.
- Once static generator methods compiled, `var gen = C.gen; gen()` had no answer: the checker types `C.gen` as a generator method, which has no representation, and the binding and call followed from it. The call in the forwarding method names the lifted function, which no source declares.
- Under `-compat=js`, a function literal initializing a class field (`#f = (a, b) => undefined`) was unanswered: the checker types an unannotated parameter from call sites or, for a method, as `any`, and a field's function had neither, where checkJs gives `any`.
- A generator method read off an object literal (`var ref = obj.method`) had no answer, though the object's layout holds it boxed. In `const holder = { seq }`, the front end boxed `seq` as it boxes a generator method, where codegen holds the generator declaration's value.

## Decision

- `liftStaticGenerators`, after `staticThisToClass`, moves each static generator method of a module-level class into a generator function declared before the class. The method becomes a plain one that returns that function's call with its parameters' values, so its defaults are evaluated by the method. A class declared in a function and a body reading `arguments` keep the compile error: the binder has already run, and the forwarding call passes only the declared parameters.
- Codegen types a class instance's generator method read as a value as a box (`isGeneratorMethod`).
- `preRegisterGenerators` records each non-generic top-level generator's signature before the classes register. `registerFunctions` registers them again once the classes exist.
- A call of a class's static field holding a function calls the field's value: a closure directly, a box through the dynamic call (`emitStaticMethodCall`, with the matching inference).
- The front end answers a library global as a receiver or a callee with codegen's held value (`builtinValue`), else the default number, and so a namespace that is nothing else as a member's receiver.
- A module-scope binding of a generator expression is the generator value codegen registered under its name, both as a global and as an identifier.
- An unannotated binding of a call only codegen can type (`codegenCall`) reads as that type where the front end has none. A field of the generator step layout is that field's type (`isGenStepLayout`), and so is an object layout's boxed field or generator value (`isGeneratorCtor`), whose call is that generator's instance.
- A property whose value names a generator declaration holds that generator's value (`literalGenFields`).
- A class's static method, the class declared or a module binding of a class expression, read as a value where the checker has no type is codegen's static method value (`staticMethodValue`). An unannotated, unwidened binding the checker cannot type holds its initializer's function or generator. A call of a binding holding a generator's value is its instance, and the lifted function's name is its generator value.
- The checker types a class field's function literal's unannotated parameter `any` under `-compat=js` (`isFieldInit`).

## Consequences

- `TestE2EStaticGeneratorMethod`, `TestE2EClassMethodReturnsGenerator`, `TestE2EGeneratorMethodAsValue` and `TestE2ELocalClassStaticCallsCapturedFunction` cover the fixes.
- A static generator method in a class declared inside a function, or one reading `arguments`, is still a compile error.
