# ADR-01595: Windows library imports and the process unit's headers

- **Date**: 2026-10-11

## Context

On the Windows lane, most E2E tests failed in two ways:

- **"cannot find module './internal_util_inspect' (resolved to
  D:\\__kml_lib\\node\\…)"**: a builtin library module's relative import
  of another went to the disk.
- **"clang: exit status 1"**: `process.c` failed to compile against
  MinGW's headers: "conflicting types for 'clock_gettime'", "conflicting
  types for 'getcwd'", "no member named 'tv_sec' in 'kml_ts'".

## Investigation

- **The import**: `filepath.Dir` of the library's pseudo-path
  `/__kml_lib/node/x.ts` is `\__kml_lib\node` on Windows, so the
  `ModuleRoot` prefix test in `resolveImportPath` never matched.
- **`process.c`**:
  - it included `<time.h>` and `<sys/stat.h>` on Windows, whose
    `clock_gettime(struct timespec *)` and CRT old-name `getcwd(char *, int)`
    clash with the shim's own definitions (`win32shim.c`, `win32fs.c`);
  - its Windows `kml_ts` named its fields `sec`/`nsec` while the code read
    `tv_sec`/`tv_nsec`.

## Decision

- `resolveImportPath` compares and joins the directory slash-separated
  (`filepath.ToSlash`).
- `process.c` on Windows:
  - defines `NO_OLDNAMES` and skips `<time.h>`/`<sys/stat.h>`, as
    `win32fs.c` and `timers.c` already do;
  - declares the shim's `{tv_sec, tv_nsec}` layout and `_umask`.

## Verification

- `process.c` passes `-fsyntax-only` under x86_64-w64-mingw32-gcc, in the
  MinGW Docker image on the Mac.
- `GOOS=windows go vet ./resolver` is clean.
- Resolver unit tests pass.
- The Windows lane itself is not run locally.
