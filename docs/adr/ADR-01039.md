# ADR-01039: Scalar unions as values — mixed-kind ternary, union / nullable array elements, `??` result types

- **Relations**: `Extends ADR-01037, ADR-00538, ADR-00136`; `Implements TDD-00043` (the array-element scope cut), `TDD-00200` (boxed-element storage reused)
- **Date**: 2026-09-21

## Context

Three rejections and two wrong results around a value that is "one of several scalar kinds", all valid TypeScript that Node runs:

1. `c ? 1 : "a"` — *"a union-typed ternary … is not supported"*. `c ? 1 : true` compiled, but coerced the boolean branch to a number (`1`, not `true`).
2. `(number | string)[]` and `(number | undefined)[]` — *"a nullable or union array element type is not yet supported"*. Hit writing `[process.getuid?.(), …]`.
3. `["a","b"].map(k => m.get(k))` — **invalid IR**: the callback returns a `{ i1, double }` optional and the result buffer was typed and stored as bare `double`.
4. `(row ?? dflt).name` — *"field access on non-object"*: for a pointer left operand emission returned an untyped `ptr` while `inferExprType` returned the *right* operand's type. The two disagreed whenever the right was nullable or a subtype.
5. `console.log(anyArray)` printed boxed string elements unquoted (`[ 1, two ]`).

## Investigation

- A declared scalar union is an `IsDynamic` type with `UnionMembers`: the same self-describing NaN box `any` uses, plus a checked member set (`unionAllowsAssignmentFrom`). `coerce(value, unionTy)` boxes a member. ADR-01037 already made `??` produce that type for operands of different kinds (`nullCoalesceUnion`).
- `any[]` is a supported array shape (TDD-00200): one box per slot, box-on-write / unbox-on-read over the ordinary array machinery. A *constrained* union element was rejected only because "element-level member-set checking isn't wired" (`containsDynamicElement`, `emitArrayLiteralData`) — the storage is identical.
- The mutators (`push`/`unshift`/`splice`) and `xs[i] = v` already funnel through `coerceChecked(…, "array element")`; the literal path used plain `coerce`.
- The `{ i1, T }` optional is a local-slot/parameter/field shape; nothing stores it as an array element.
- `coerce` demoted a `{ i1, T }` to its payload before boxing it, so an absent optional boxed as a present `0`; and a box flowing into a `{ i1, T }` slot was unboxed to a number and re-wrapped as present, so a boxed `undefined` arrived as `NaN`.

## Decision

- **Ternary.** `ternaryUnion` (the kind rule of `nullCoalesceUnion`) gives `cond ? a : b` the union of its branches when they are scalars of different kinds; `emitConditionalAny` takes the target union and coerces each branch into it. `inferExprType` calls the same function. A pointer-vs-scalar mix that is not a scalar union (`number | Addr`) stays a clean rejection.
- **Union array elements** ride the boxed-element array. `containsDynamicElement` no longer rejects a union element, and `emitArrayLiteralData` only rejects what it cannot store. The member check moves into `coerceChecked` — a constrained-union target that does not admit the value's type is *"value's type is not a member of the declared union type"*, the same rejection a union local gives — and the literal paths call it for a union element. So `[1, true]`, `.push(true)` and `xs[0] = true` against `(number | string)[]` are compile errors, as in tsc. Discriminated object unions work as elements through the same path.
- **Nullable scalar elements.** `arrayElemType` (used by `ArrayOf`) stores a `T | undefined` / `T | null` scalar element as the union box `T | undefined`. A producer that fills a buffer by hand must size and store against it: `emitArrayMap` now does, which is the invalid-IR fix.
- **Optional ⇄ box conversions in `coerce`.** `{ i1, T }` → box keeps absence (select between the boxed payload and the boxed `undefined`/`null`); box → `{ i1, T }` reads the tag for the presence bit. `boxNullableScalarFromValue` routes a dynamic source through `coerce`, and `emitExprWithObjectHint` preserves a nullable-scalar local's aggregate when the hint is a box (a plain read surfaces the bare payload).
- **`??` result types.**
  - Boxed left (`nullCoalesceBoxResult`): against a plain scalar right operand the nullish half is gone — a right of the box's single kind leaves the bare `T` (`xs[i] ?? 0` is a number, usable in arithmetic), any other scalar leaves the non-nullable union. Bare `any`, or a nullable right, keep the `any` result. Inference previously returned the left's type while emission returned `any`.
  - Pointer left (`nullCoalescePtrResult`): the left's type with its nullability dropped, staying nullable — with the right's `null`/`undefined` flavour — when the right can itself be absent.
  Both functions are shared by emission and `inferExprType`.
- **Inspect.** `emitInspectField` renders a self-describing box by its run-time tag, quoting a string like any other nested string (`isSelfDescribingBox`: bare `any` or a scalar-only union). `JSON.stringify` uses the same predicate to send union elements through the dynamic walker.

## Side effects discovered

Only `.map` was audited for a callback returning `T | undefined`; other result-building HOFs take their element type from the receiver.
