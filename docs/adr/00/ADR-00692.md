# ADR-00692: fs.readFileSync on a directory throws EISDIR

- **Date**: 2026-09-04

## Context

`fs.readFileSync(dirPath)` did not throw. `fopen(2)` on a directory succeeds on
both Linux and macOS, so the read path opened the directory, `fread` returned
zero/garbage bytes, and `readFileSync` handed back a bogus string instead of
failing. Node throws:

```
EISDIR: illegal operation on a directory, read
```

with `err.code === 'EISDIR'`. A repro (`fs.readFileSync('/tmp')`) returned a
value where Node raises, so any program branching on the directory-vs-file
distinction via a caught error silently mis-behaved.

## Investigation

`readFileSync` lowers to `__kml_fs_read_file` → `__kml_fs_read_file_raw`
(`codegen/llvm/runtime_fs.go`), whose body was a bare `fopen("rb")` +
`fseek`/`ftell`/`fread`. There was no directory check anywhere on the path, and
`fopen` does not fail for a directory on the supported hosts, so nothing ever
set errno to `EISDIR`.

The shared fs error helper `__kml_fs_throw` builds `"<opdesc> '<path>':
<strerror>"` from the current errno and throws it as an ordinary catchable
Error. It already had the 6-field `errorObjType` shape available
(`kind/message/name/code/errcode/errstr`, `emit_exceptions.go`) but was still
emitting the old 3-field object and under-allocating 24 bytes — so `.code` was
never populated for any fs failure. `struct stat`'s `st_mode` offset/width is
already tabulated per host in `statLayout()` for `statSync`.

Alternatives considered: (a) attempt the `fread` and inspect errno — rejected,
since `fopen` succeeds and no read error is guaranteed before bytes come back;
(b) `fdopen`/`fstat` after opening — equivalent but requires threading a file
descriptor through; a plain `stat(2)` before `fopen` is simpler and reuses the
existing `statLayout()` offsets.

## Decision

Guard `__kml_fs_read_file_raw` with a `stat(2)` up front. If `stat` succeeds and
`st_mode & S_IFMT == S_IFDIR`, set errno to `EISDIR` (via the platform errno
accessor) and route through `__kml_fs_throw`. If `stat` fails, fall through to
`fopen`, which produces the correct `ENOENT`/`EACCES`/... error as before.

Also complete `__kml_fs_throw` to the full 6-field `errorObjType`: allocate
`errorObjType.StructSize()`, map errno → Node code name via a new
`__kml_errno_code` switch built from Go's per-host `syscall` constants, and
store `code`/`errcode`/`errstr`. This is what makes `err.code === 'EISDIR'`
(and every other fs error's `.code`) match Node.

## Implementation notes

- `codegen/llvm/runtime_fs.go`: added `ensureErrnoCode` (errno → code-name
  switch) and `ensureStatDecl` (single `declare i32 @stat`, shared with
  `ensureFsStat`); rewrote `__kml_fs_throw` to the 6-field object; added the
  directory guard block to `__kml_fs_read_file_raw`. The `st_mode` load width is
  taken from `statLayout()` (`i16` on Darwin, `i32` on Linux) and zero-extended
  to `i32` before masking with `S_IFMT` (0o170000) / `S_IFDIR` (0o40000).
- `codegen/llvm/emitter.go`: added `usedErrnoCode` and `usedStatDecl` guard
  flags.
- The guard sits on `__kml_fs_read_file_raw`, so the callback and Promise forms
  (`fs.readFile`, `fs.promises.readFile`) — which share `emitFsReadFileSync` /
  the raw helper — inherit it, as does `fs.readFileSyncBytes`.

## Side effects discovered

- `createReadStream` opens its own `fopen` in `runtime_fs_stream.go`
  (`__kml_fs_read_stream`) and does **not** go through the guarded raw path, so
  it still does not throw `EISDIR` on a directory. Left unfixed here — it needs
  its own `stat` guard, tracked as a follow-up.
- `__kml_fs_throw` previously under-allocated the error object (24 bytes for a
  now-6-field type) and left `.code` null for all fs errors; fixed in passing so
  the whole fs family reports `.code`.

## Verification

- `go build -o klainmain .` clean (Apple Silicon / macOS).
- `tests/fs_readfilesync_eisdir_test.go`: directory read throws with
  `.code === 'EISDIR'` and a non-empty message.
- Existing `TestE2EFs*` fs suite green (no regression to normal file reads or
  the `ENOENT` path).
- `examples/fs/fs_eisdir.ts` prints `code: EISDIR` / `is Error: true`.
- Repro `fs.readFileSync('/tmp')` now prints `EISDIR` where it previously
  returned bytes.
