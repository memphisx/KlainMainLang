# ADR-00947: Nested named-object array types (`P[][]`) resolve their element type

- **Relations**: none
- **Date**: 2026-09-15

## Context

`const a: P[][] = [[{x:1}],[{x:2}]]` — a nested array of a NAMED object type
(interface or `type` alias) — was rejected: `array elements must share one type
… a heterogeneous array is not supported`, pointing at the inner object literal.
An inline element type (`{x:number}[][]`) worked, and a single-level named array
(`P[]`) worked. Surfaced while closing the five array-in-container bugs
(TDD-00213); the untyped nested-object-array literal itself already compiles, so
this is the residual explicit-annotation half.

## Investigation

The parser hands a named array type as a single suffix-name
(`ta.Name == "P[]"`, `ElemType == nil`), which `resolveType`
(`emitter.go`) special-cases: strip the `"[]"` suffix and look the base up in the
interface/enum registries. For `P[][]` the name is `"P[][]"`; stripping one level
gives base `"P[]"`, which is not a registered interface, so it fell through to
the `i64` unknown-name default. That made the outer array's element type `i64`
rather than `P[]`, and building an object literal against an `i64` element type
tripped the heterogeneous-array guard (`emit_arrays_core.go:693`). Inline types
take the `ElemType`-recursion branch instead, so they were unaffected.

## Decision

When the stripped base is itself suffixed (`"P[]"`), `resolveType` now recurses —
`ArrayOf(resolveType({Name: base}))` — so every nesting level resolves the named
element to its real object type. Single-level and non-array names keep their
existing behavior (the recursion only triggers on a nested `"[]"` suffix).

## Side effects discovered

None. `number[][]` / `string[][]` (scalar element types, which reach the resolver
through the `ElemType` branch) and single-level named arrays are unchanged.

## Verification

- `TestE2ENestedArrayOfNamedObjectType` (tests/arrays_test.go): `P[][]`
  (interface) and `Q[][][]` (`type` alias, triple-nested), indexing to the leaf
  object field.
- Regression: `go test -run 'TestE2ENestedArray'` green on macOS arm64 (Apple
  Silicon M4).
