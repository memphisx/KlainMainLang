# TDD-00210: Variadic `arguments` — reflect actual call-time arguments

- **Status**: Implemented — [ADR-00928](../adr/ADR-00928.md)

## Context

`arguments` inside a function today is synthesized from the function's
**declared parameters** only (`synthesizeArgumentsObject`, emit_func.go). A
function that receives more arguments than it declares — the classic
`function f() { return arguments[0] + arguments[1] }` called as `f(3, 4)`, or a
`String.prototype.replace` replacer `function () { return arguments[2] +
arguments[1] }` that reads capture groups positionally — sees an empty (or
short) `arguments`, so it reads out of bounds. This is a real Node-fidelity gap
(a function's `arguments` should hold every value actually passed) and the
remaining blocker under the String.replace capture-group work (ADR-00922): those
Test262 files (`built-ins/String/prototype/replace/S15.5.4.11_A4_T{1..4}`) use
the `arguments` form.

## Design

`arguments` becomes a real reflection of the arguments actually passed: the
declared parameters followed by any overflow. Elements are heterogeneous, so
`arguments` is an `any[]`-style boxed array (one NaN box per slot — the
boxed-element representation from TDD-00200), and `arguments[i]` has type `any`.

The variadic-collection machinery already exists for an explicit `...rest`
parameter (callers pack overflow into a homogeneous `T[]`); this reuses it with
a boxed element type.

### Stages

1. **Implicit boxed rest for `arguments`-using functions.** A function that
   references `arguments` and has no explicit rest gains an implicit trailing
   rest parameter of element type `any` (`...__arguments_rest: any[]`). The
   existing rest-collection call ABI then delivers all overflow arguments to it.
   (A function that already has an explicit `...rest` keeps today's clean error,
   or later merges — out of V1 scope.)
2. **Build `arguments` from declared params + rest.** At entry, construct the
   `arguments` boxed array as `[box(p0), …, box(p_{n-1}), rest[0], …]` — each
   declared parameter boxed to `any`, concatenated with the already-boxed rest
   elements. Replaces the declared-params-only builder for these functions.
3. **Callback ABI.** `emitCBCall` must pack a callback's trailing arguments into
   its implicit rest when the callee is an `arguments`-using function value — the
   path the `String.replace` replacer takes. This is the highest-risk stage (the
   closure ABI is shared across every HOF); a callback with `FuncHasRest` already
   exists (arrow/function-expression rest), so the groundwork is there.
4. **Direct-call verification.** `f(a, b, c, d)` to an `arguments`-using `f`
   delivers all four via stages 1–2 with no call-site change (the rest ABI
   already packs overflow) — verify and test.

### Consequence for the String.replace files (honesty)

Making `arguments` populated is **necessary but not sufficient** for the four
`S15.5.4.11_A4_T*` files to *pass*: `arguments[i]` is `any`, so their
`arguments[2] + arguments[1]` is an **operator on `any`**, which strict rejects
(a documented general `any` limitation) and only `-compat=js` supports. So those
files pass only under `-compat=js` (variadic `arguments` + operators-on-`any`);
under strict they move from a runtime near-miss to a clean operator-on-`any`
rejection. Variadic `arguments` is worth doing on its own merits (every
`arguments`-reading function), independent of those four files.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| Explicit `...rest` collection ABI | Done | emit_func.go — callers pack overflow into a `T[]` |
| Boxed-element arrays (`any[]`) | Done | TDD-00200 — the element representation for a heterogeneous `arguments` |
| `arguments` from declared params | Done | `synthesizeArgumentsObject` — the builder to generalize |
| Operators on `any` (`+`) | compat=js only | Not required for variadic `arguments` itself; gates the String.replace files' *pass* |

## Open questions

- Mixing an explicit `...rest` **and** `arguments` in one function: merge (rest
  is a tail-slice of `arguments`) or keep the current clean rejection? V1 keeps
  the rejection.
- Boxing cost: every `arguments`-using function now boxes its parameters into the
  array at entry. Acceptable (only functions that actually read `arguments` pay);
  a future optimization could build lazily on first `arguments` read.
- Callback ABI (Stage 3): whether every HOF call site can pack a rest uniformly,
  or only the ones with a statically-known `arguments`-using callee — the latter
  is a safer V1.
