# ADR-01321: `Headers` is undici's, in TypeScript

- **Relations**: Implements TDD-00237 (Stage 3), Extends ADR-01320, ADR-01190, ADR-00490
- **Date**: 2026-10-01

## Context

TDD-00237 Stage 3, and BACKLOG 85. `Headers` was a `Map<string, string>`
under an `IsHeaders` flag (`emit_headers.go`), with its own `new` node from
sema. That had three consequences:

- console.log showed the names lowercased.
- Iteration followed insertion order, not the Fetch standard's sorted
  "sort and combine" order.
- Repeated `set-cookie` values were joined; there was no `getSetCookie`.

There was no name or value validation, and it could not be subclassed or
used as a value. A fetched response's headers were reparsed into a fresh
map on every `.headers` read, so two reads were different objects. Within
one response's raw text, later duplicates overwrote earlier ones, and the
headers of a redirect's earlier responses were mixed in.

## Investigation

- Node's `Headers` is undici's `lib/web/fetch/headers.js`. Its header list
  maps each lowercased name to the name as first given and the values
  combined, and keeps `set-cookie` values in a list of their own.
  - Iteration sorts the names and lists each cookie separately.
  - util.inspect prints `Headers` followed by the record of given names.
  - A response from `fetch`, `Response.error()` or `Response.redirect()`
    has the `immutable` guard.
- The native side only needs three things from a Headers:
  - the list, to build libcurl's `curl_slist`;
  - a way to fill one from libcurl's captured header text;
  - `has`/`set`, for the implied `Content-Type` and `Location`.

  All three are members of the class, so codegen calls them through
  synthesized source, as `Response.redirect` already builds a `URL`. That
  makes the pair-array factory TDD-00237 sketched unnecessary.
- `runtime_strheader.go`, which TDD-00237 lists for deletion, holds
  length-prefixed string buffers, not HTTP headers. It stays.
- `Object.prototype.toString.call(h)` is `[object Headers]` through
  `[Symbol.toStringTag]`, which the compiler did not accept as a class
  member key.

## Decision

1. **`lib/node/kml_headers.ts`** is a global module holding `Headers` and
   its iterator, ported from undici:
   - the header list, with `append`, `delete`, `get`, `getSetCookie`,
     `has` and `set`;
   - the Fetch standard's name (token) and value checks, and leading and
     trailing HTTP whitespace removed from values;
   - webidl's ByteString conversion and its error messages;
   - iteration in sorted-and-combined order, and `forEach`;
   - the inspect form, and the `immutable` guard.
2. **Native bridge** (`emit_headers.go`). Request, Response and fetch hold
   a Headers instance and reach it through four members:
   - `new Headers(init.headers)` for every init;
   - `#pairs()`, the list fetch sends;
   - `#fillRaw(raw)` for a fetched response. It keeps only the last
     response's block, dropping those of redirects and 1xx responses.
   - `#seal(guard)`.

   A fetched response fills its Headers on the first read of `.headers`
   and stores it, so later reads return the same object.
   `lib.NativeGlobalUses` brings the module into any program naming
   `Request`, `Response` or `fetch`.
3. **`[Symbol.toStringTag]`** desugars to `@@toStringTag`. String
   conversion of a class instance with that getter is `[object Tag]`, and
   a generated `__kml_obj_tostring_tag` gives `__kml_object_tostring` the
   tag of a boxed instance.
4. **Deleted:**
   - `IsHeaders` and every site testing it, and `HeadersType`;
   - `NewHeadersExpression` and its sema builder;
   - the map-based `emitHeadersCall`, `headersFromInit`,
     `emitHeadersFromMapValue`, `emitHeadersFromBox` and
     `emitInspectHeaders`;
   - `Headers` in `reserved_names.go` and in the host-box tables.

   XMLHttpRequest and `http` keep their own header maps.
   `buildFetchHeaderList` builds their `curl_slist` through the new shared
   `buildCurlSlist`.

## Implementation notes

- `codegen/llvm/emit_headers.go`: `bindValue` binds an evaluated value for
  synthesized source; `emitSynthExpr` prepares such source and emits it.
- `codegen/llvm/runtime_fetch.go`: `__kml_fetch_headers_raw`.
- `codegen/llvm/emit_fetch.go`: `buildCurlSlist`.
  `emit_fetch_request.go` adds `emitRequestHeaders`; a Request's headers
  field is now `__kml_headers`, as on a Response.
- `codegen/llvm/emit_exprs_types.go`: the `[object Tag]` string form.
  `emit_inspect.go`: `emitToStringTagHook`. `emit_narrowing.go`:
  `classHasMethodInherited`.
- `parser/parser_classes.go`: `Symbol.toStringTag`.

## Side effects discovered

- `arguments.length` counts every declared parameter, even when a call
  passes fewer arguments, so webidl's "N argument(s) required" check never
  fires. This is BACKLOG 130 and a caveat on the Headers row. Fixing it
  needs the argument count from every call-packing path.
- `structuredClone` of a Headers is rejected at compile time. Node throws
  `DataCloneError` at run time.
- `(m as any)[Symbol.iterator]` was `undefined` for a Map or Set, so a
  `Map` given as HeadersInit came out empty. It is now a function, built
  from the host's spread (`emit_dynobj.go`; the `hostValues` record in
  `emit_shape.go`). A string still answers `undefined` (BACKLOG 132).
- An object literal passed for `string | URL | RequestOptions` found two
  object members once `URL` became a class, and lost its member's field
  types. `unionLiteralMember` no longer counts a class for an object
  literal.
- `res.setHeaders` was typed `Map` only, so a Headers argument was misread.
  It takes `Headers | Map`, as Node's does, and a Headers' `set-cookie`
  values are set together.
- The `fetch` init fuzzer sent a body with `GET`, which Node's fetch
  rejects; it now picks `POST` for a body.
- `x as any` now holds x as `const v: any = x` does: an object literal
  becomes a dynamic bag, so `ta.set({ length: 2, 0: 7 } as any)` reads it.
  Holding the value boxed exposed three paths that had relied on the cast
  keeping the static type:
  - A constructor's `return 5 as any` is classified by its operand, so it
    still returns a primitive.
  - `indexOf`, `lastIndexOf` and `includes` compare an `any` search value
    without coercing it, so `[42].includes("42" as any)` is false.
  - An `any` operand of a bigint arithmetic operator is a bigint operand
    when it holds one; otherwise the operator throws "Cannot mix BigInt and
    other types", and `+` with a string still concatenates.
- `ffi`'s `getFunction` takes its signature through an `any`
  implementation behind the typed overload, so its run-time checks see a
  member of the wrong kind (`{ arguments: 'x' } as any`). Typed as the
  interface, the value was converted first (BACKLOG 135).
- `typeof ns.x` through a namespace import (`typeof path.posix`) resolves
  as a value reference does.
- `parseInt(s, radix)` with a radix outside 2..36 is NaN, and a radix of 0
  auto-detects. glibc's `strtoll` parsed base 1 as 0 (Linux x86-64 only).
- `casemap.c` calls `floor`, which glibc keeps in libm, but did not link
  libm itself; it had relied on another runtime file of the same program
  linking it. Without the URL runtime, `floor` went unresolved on Linux.
  casemap now links libm, in the CLI and the test build.
- Two tests and an example typed `res.headers` as `Map<string, string>`,
  which tsc rejects. The checker accepts any object for `Map`, because it
  does not yet model the lib globals' members (TDD-00230 P3.1).

## Verification

- New E2E tests `TestE2EHeadersListSemantics`, `TestE2EHeadersErrors` and
  `TestE2EHeadersSubclass`, against Node. The existing fetch, Request,
  Response, XHR and http client suites also pass.
- New example `examples/fetch/headers.ts`. Its output is identical to
  Node's.
- Verified on macOS (Apple Silicon) and Linux x86-64 (Ubuntu 24.04,
  clang 18).
