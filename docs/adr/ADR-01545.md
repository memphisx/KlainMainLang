# ADR-01545: The checker types an object literal's accessors

- **Relations**: Extends TDD-00230
- **Date**: 2026-10-10

## Context

An object literal with a getter or setter had no type in the checker:
every expression reading it fell back to codegen's own inference, and
the strict lane missed tsc's diagnostics on it (a write to a getter-only
property, TS2540; a mismatched use of the literal). The old inference's
empty-array pre-pass also skipped a `return` statement's value, so a
push inside an accessor of a returned literal
(`return { get p() { log.push("g") } }`) left `log` at the `number[]`
default: Node printed `[ 'g' ]`, the binary `[ NaN ]`.

## Decision

- A getter's property has the getter's return type and, alone, is
  readonly; a setter-only property has its parameter's type; a pair is
  the getter's type, writable (`Write` the setter's when it differs).
- A write to a readonly property of an anonymous object type (a
  getter-only accessor, a `Readonly<T>` member) reports TS2540.
- A property printed in a type shows `readonly` as tsc prints it.
- The empty-array pre-pass walks a `return` statement's value.
- An accessor whose body reads `this` stays unanswered (the literal's
  own type is what `this` reads, which tsc resolves lazily).
