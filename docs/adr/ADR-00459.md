# ADR-00459: numeric-literal types; string-named enum members

- **Relations**: Extends [ADR-00246](ADR-00246.md)-era TDD-00079 literal types
- **Date**: 2026-08-29

## Context

Two TS-oracle parse buckets: `expected type name, got NUMBER` (45 —
numeric-literal types, `type Dir = -1 | 0 | 1`, `{ retries: 3 }`) and part
of `expected IDENT, got STRING` (string-named enum members,
`enum E { A, "non identifier" }`).

## Decision

- Numeric-literal types parse in the type-atom position (including a
  leading minus) into a new `IsNumberLiteral` annotation and resolve to
  `number` — exactly the string-literal type's V1 stance (TDD-00079): the
  literal value is not narrowed or enforced, a disclosed simplification.
  Unions of numeric literals collapse to `number` through the existing
  union machinery.
- An enum member name may be a string literal. It declares the member and
  advances the auto-increment counter; its value is only reachable through
  bracket access this compiler doesn't model (`E["non id"]`), so the
  declaration alone is the supported surface.

## Verification

Mac. `tests/overloads_test.go` additions and the
`examples/types/erased-syntax.ts` extension pass; parser + enum/type/union
E2E batches green. TS oracle 5108 → 5111 agreement (most affected cases
stack strictness/other blockers). Node oracle unchanged (40).
