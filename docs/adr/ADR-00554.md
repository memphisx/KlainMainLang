# ADR-00554: getRandomValues enforces the 65,536-byte quota and integer-view rule

- **Relations**: Extends ADR-00317
- **Date**: 2026-09-01

## Context

`crypto.getRandomValues(view)` enforced neither of the WebCrypto spec's two
guards: the 65,536-byte quota (an oversize view must throw
`QuotaExceededError`) and the integer-TypedArray-only rule (a float TypedArray
must throw `TypeMismatchError`). Both were disclosed in a single caveat on the
web-crypto status row.

## Investigation

`emitCryptoGetRandomValues` (emit_call_encoding.go) computes a `byteLenReg` in
both the ArrayBuffer and TypedArray fill paths, and knows the view's element
type at compile time (`argTy.ElemType`). The catchable-throw machinery
(`buildErrorObj` + `__kml_throw`, DOMException kind) is already used by
`atob`'s `InvalidCharacterError` in the same file.

## Decision

- Add `emitCryptoQuotaCheck(byteLenReg)`: throws a `QuotaExceededError`
  DOMException when the byte length exceeds 65,536. Called in both the
  ArrayBuffer and integer-TypedArray fill paths.
- Reject a float TypedArray (`argTy.ElemType.Float`) at compile time with a
  clear error naming the spec's `TypeMismatchError`, before any fill.

The non-spec extension of accepting a whole `ArrayBuffer` is kept (it predates
this change and some code relies on it) and is now the row's remaining,
explicitly-documented caveat.

## Implementation notes

- `emitCryptoQuotaCheck` builds the DOMException with the `QuotaExceededError`
  name via the existing `buildErrorObj` path.
- The float rejection is compile-time rather than a runtime `TypeMismatchError`
  throw, consistent with this compiler's handling of statically-known type
  mismatches.

## Side effects discovered

None.

## Verification

`TestE2EGetRandomValuesQuota` (70,000-byte view throws `QuotaExceededError`,
65,536 succeeds) and `TestE2EGetRandomValuesFloatRejected` (Float32Array is a
compile error) pass, along with the existing getRandomValues tests. Built and
verified on Mac (Apple Silicon).
