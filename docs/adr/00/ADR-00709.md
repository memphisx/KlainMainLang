# ADR-00709: Promote computed constant-scalar top-level bindings to module globals

- **Relations**: Extends ADR-00342 (Implements TDD-00093)
- **Date**: 2026-09-04

## Context

A top-level `const SOLAR_MASS = 4 * Math.PI * Math.PI` read inside a named
function failed to compile: `codegen error: undefined variable
'SOLAR_MASS__kml_mod0'`. Found while writing an `nbody` benchmark (the classic
n-body integrator keeps `SOLAR_MASS`/`DAYS_PER_YEAR` as top-level constants and
references them from a body-construction function).

A named `function` is emitted with its own fresh scope, so it can read a
top-level binding only when that binding has been promoted to an LLVM module
global (TDD-00093/ADR-00342). Promotion (`registerModuleGlobals` /
`reliableGlobalType` / `promotableInitInPrePass` in
`codegen/llvm/emit_exprs_vardecl.go`) only accepted *literal*-initialized scalars
and a fixed set of handle/`new` shapes. A computed initializer — even one whose
value is an unambiguous number — was not promoted, so it stayed a `main()` local
that no function could see. The mangled name in the error shows the reference
side resolved to the resolver's `__kml_mod0` symbol while no global was ever
emitted for it.

## Investigation

- `emitVarDecl` already types an un-annotated `BinaryExpression` /
  `UnaryExpression` / `IndexExpression` / `SequenceExpression` initializer via
  `e.inferExprType(init)` (`emit_exprs_vardecl.go`, the un-annotated inference
  switch). So the store side already had a stable type for these; only the
  promotion pass refused them.
- The invariant the whole promotion feature rests on is that the pre-declared
  global's IR type must *exactly* match what `emitVarDecl` later stores — hence
  the conservative gate. The safe way to extend it is to promote a computed
  initializer only when its type is **context-stable**: every leaf resolves
  identically in the pre-pass (before `main()`'s body) and at emit time, and the
  type is taken from the same `inferExprType` call `emitVarDecl` uses.
- A constant scalar expression satisfies that: literals, the numeric builtin
  constants (`Math.PI`/`Number.EPSILON`/…, all doubles), `NaN`/`Infinity`, and
  already-registered earlier module globals, combined with unary/binary
  operators, reference no runtime local, so `inferExprType` is invariant to
  context.

## Decision

Promote a top-level `const`/`let`/`var` whose initializer is a **constant
scalar/string expression** to a module global, typed by the same
`inferExprType` the store uses.

- New `constFoldableScalarInit(expr)` predicate: true for number/string/bool/
  template literals, `NaN`/`Infinity`, member expressions that are `Math.*`/
  `Number.*` numeric constants (`numericBuiltinConst`), already-registered
  module-global identifiers, and any `UnaryExpression`/`BinaryExpression` built
  recursively from those.
- `promotableInitInPrePass` accepts `BinaryExpression`/`UnaryExpression`/
  `MemberExpression` when `constFoldableScalarInit` holds.
- `reliableGlobalType`'s un-annotated switch gains a matching case returning
  `inferExprType(init)` only when `isSimpleGlobalType` (a scalar or string slot);
  anything else stays a local, unpromoted, as before.

String concatenation of constants (`const L = "a" + "b"`) and arithmetic over
earlier module globals (`const H = SOLAR_MASS / 2`) fall out of the same rule.

## Implementation notes

- All changes in `codegen/llvm/emit_exprs_vardecl.go`.
- The type is never hand-derived: both promotion and store call
  `inferExprType`, so they cannot disagree, and the `isSimpleGlobalType` gate
  keeps the global a fixed scalar/string slot.
- Bindings referencing a non-promoted runtime local are excluded by
  `constFoldableScalarInit` (a leaf identifier must already be a module global),
  preserving the "promote iff the type cannot drift" invariant.

## Side effects discovered

- None. The `nbody` benchmark's original top-level-constant form now compiles
  (a workaround that moved the constants into the function was reverted).

## Verification

- New E2E regression `TestE2EModuleGlobalComputedScalarConst`
  (`tests/module_global_new_test.go`): a computed `4 * Math.PI * Math.PI`
  constant, an arithmetic-over-module-global constant, and a constant string
  concatenation, all read from a named function.
- `go build`, `go vet ./codegen/llvm/`, `go test ./tests/ -run ModuleGlobal`
  (all module-global tests pass). Mac (Apple Silicon).
- Full `make test-par` / `make examples` / `make conformance-node` deferred to a
  low-load window (this was fixed on a shared machine mid-use).
