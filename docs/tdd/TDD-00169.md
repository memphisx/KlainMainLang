# TDD-00169: faithful async rejection values (`Promise.allSettled` reason, `throw <non-Error>`)

- **Status**: Not Started
- **Date**: 2026-09-03

## Context

`Promise.allSettled` reports a rejected element's `.reason` as a wrapped
`Error` (stringified message), not the **original** rejected value — `await
Promise.allSettled([Promise.reject(42)])` gives `reason.message === "42"`, where
Node gives `reason === 42` ([ADR-00683](../adr/ADR-00683.md) fixed the
`JSON.stringify` crash that sat on top of this, but not the value fidelity).
The same root cause makes `throw 42` / `Promise.reject({obj})` lossy: every
rejection value is coerced to an `Error` at reject/throw time
(`errorPtrFromValue`, `emit_exceptions.go`), destroying the original.

## Design

The promise rejection slot (`promiseStructIR` field 2) stores an `errorObjType`
pointer; `await`-rejection re-throws it as an Error. JS lets you reject/throw
**any** value, so faithful rejection needs the raw value preserved:

- **Rejection carries a NaN-boxed `any`** (the raw value), not a coerced Error.
  `await`/`catch`/uncaught-throw unbox it: an Error value re-throws as-is; a
  non-Error prints/propagates as its own value (`throw 42` → "Uncaught 42").
- `SettlementType.reason`/`value` become `any`, with the absent side set to
  boxed `undefined`; `JSON.stringify` **omits** an `undefined`-valued field and
  serializes an `Error` value as `{}` — yielding Node's exact
  `[{"status":"fulfilled","value":1},{"status":"rejected","reason":42}]`.

This touches the exception machinery (`__kml_throw`, the catch-and-settle async
wrapper, uncaught-throw formatting) as well as the promise combinators, so it is
staged as its own design rather than a bug patch: (1) reject/throw store a boxed
`any`; (2) the throw/await/uncaught paths handle a non-Error boxed value; (3)
`SettlementType` → `any` fields + JSON undefined-omission + Error→`{}`.
