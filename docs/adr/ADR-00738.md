# ADR-00738: -l flags ordered before sidecar objects broke every Windows link that needed them

- **Relations**: Extends [ADR-00719](ADR-00719.md) (the Windows toolchain path this surfaced on), [ADR-00020](ADR-00020.md) (conditional `-l` linking via `LinkLibs`); touches every build entry point (driver, E2E helpers, conformance runner)
- **Date**: 2026-09-07

## Context

Every `URLPattern` E2E test failed on Windows with `undefined reference to pcre2_compile_8`/`curl_url` out of the sidecar `urlpattern.c` — with `-lpcre2-8` and `-lcurl` present on the command line. The driver (and the test helpers mirroring it) appended the program's `-l` flags *before* the embedded sidecar `.c` files. GNU ld processes the command left to right and never re-searches a library for symbols an object needs later; ELF/Mach-O *shared* libraries forgave the order (a loaded `.so`/`.dylib` stays searchable), which is why Linux and macOS always passed. Windows links against `.dll.a` import *archives*, where the rule bites for real — so the combination "sidecar C file + external library" (URLPattern is currently the only one) never linked on Windows. `prog.ll` itself was unaffected: it is listed first, before the libraries.

## Decision

`HostClangArgv` — the single shared entry every build path already goes through (driver, E2E helpers, conformance runner, webview builds) — stable-partitions the final argv: every `-l<name>` flag moves after all objects and sources, preserving relative library order. `main.go` also moves its `LinkLibs` loop after the sidecar loop so the canonical command reads in the correct order even before the partition. The 13 `LinkLibs` loops in the test helpers are deliberately left where they are: the partition normalizes them all at the one point they share, which is also what keeps the next helper from reintroducing the bug.

## Consequences

- All six `URLPattern` E2E tests pass on Windows (first time on any Windows host; they were also absent from the CI lane's log because the lane died earlier on the shim — [ADR-00737](ADR-00737.md)).
- `-L` flags keep their positions (always before the moved `-l` flags), and libraries keep their relative order (`-lssl -lcrypto` pairs intact).
- Verified on Windows 11 x86-64 (URLPattern + RegExp + Fetch suites) and Linux x86-64 (Docker, full suite — the partition is a no-op in effect there).
