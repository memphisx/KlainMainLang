# ADR-01340: `URLPattern` as the URL Pattern Standard, in TypeScript

- **Relations**: Implements TDD-00230 (P3.2), Supersedes ADR-00311, ADR-00585, Extends ADR-01320
- **Date**: 2026-10-03

## Context

`URLPattern` was a code-generated host object ([ADR-00311](ADR-00311.md),
[ADR-00585](ADR-00585.md)):
- C component regexes (`urlpatternsrc/urlpattern.c`);
- an object-literal init only, with no constructor string and no `baseURL`;
- a pattern grammar limited to literals, `*`, `:name` and `:name?`;
- `exec` returned one merged `Map<string, string>` instead of the
  standard's `URLPatternResult`.

It was undeclared, so the checker typed it from codegen's own name list.
Node 24 has `URLPattern` as a global (ada's implementation of the
standard).

## Investigation

- The WHATWG URL Pattern Standard is self-contained:
  - a tokenizer, a pattern-string parser and a part list;
  - regular-expression and pattern-string generation;
  - a constructor-string parser;
  - URLPatternInit processing, whose components are canonicalized through
    the URL parser.

  `URL` is already a TypeScript global module (ADR-01320), so the
  canonicalizers can be written over it, as the standard writes them over
  the URL parser.
- Node departs from the standard where ada does. Diffing against Node 24.19
  found:
  - a string input without a base that fails URL parsing is read against
    `foo://`;
  - ASCII-lowercase hostnames skip the host parser;
  - pathnames are read as URL path strings;
  - non-special pathnames are canonicalized as `foo:` + value;
  - leading-zero ports are rejected in patterns only;
  - argument validation has its own errors and codes.
- **Group order.** A result's `groups` lists its keys in the order of
  ada's `std::unordered_map`, which differs between libc++ (macOS) and
  libstdc++ (Linux). Inserting the names into the real container
  reproduced Node only after `reserve(n)` (ada reserves the group count
  first). That was checked against Node with 7 and 11 groups, where
  `reserve(n)` and `reserve(n+1)` give different bucket counts.
- **`new URLPattern(x, undefined, o)`.** Node rejects it, while
  `new URLPattern(x, o)` is fine, so the constructor must count its
  arguments. A rest parameter on a constructor was a compile error
  (fixed in ADR-01341).

## Decision

1. **`lib/node/kml_urlpattern.ts`** is a global module (`// kml:global`)
   exporting `class URLPattern`, a port of the standard with ada's
   departures. It covers the tokenizer (strict and lenient), the parser,
   the generators, the constructor-string parser, the init processor, the
   getters, `hasRegExpGroups`, `test` and `exec`. `exec` returns a
   null-prototype `URLPatternResult` whose unmatched groups are
   `undefined`. The regexes use the `v` flag. The constructor takes
   `...args` and dispatches on their count. `url` re-exports it.
2. **The declarations** (`lib/node.d.ts`) are `@types/node`'s:
   `URLPattern`, `URLPatternInit`, `URLPatternOptions`, `URLPatternResult`,
   `URLPatternComponentResult` and `URLPatternInput`. The class carries
   them as overload signatures.
3. **Group order from the platform's own container.** Each component's
   group order is computed once, through `__kml_native.umapOrder` (`@link
   umap`). It is `ffisrc/umap_order.c` over the ffi registry's container:
   `ffi_umap_stl.cc` with the platform's C++ library on POSIX, and the MSVC
   port on Windows. That gives the same reserve-then-insert sequence as
   ada. `kml_umap_reserve` and `kml_umap_free` were added to both
   container implementations.
4. **The code-generated `URLPattern` deleted:** the `NewURLPatternExpression`
   AST node and its sema mapping, `emit_urlpattern.go`, `urlpattern.c`,
   `IsURLPattern`, and `URLPattern` among the checker's compiler type
   names.

## Implementation notes

`lib/node/kml_urlpattern.ts`, `lib/node/url.ts`, `lib/node.d.ts`,
`lib/native.d.ts`, `codegen/llvm/ffisrc/{umap_order.c,ffi_umap_stl.cc,
ffi_umap_msvc.c}`, `codegen/llvm/{emit_ffi_runtime,emit_lowered,emitter}.go`.
The removal touched `ast/nodes.go` (walkers regenerated),
`sema/builtin_new.go`, `checker/{check,checker}.go` and the codegen sites
that named the flag.

## Side effects discovered

Found while porting, and fixed in ADR-01341:
- a rest parameter on a constructor;
- a spread in `new`;
- `return fail()` of a never function emitting invalid IR;
- definite assignment past a never call;
- `JSON.stringify` of `undefined` values in a dictionary.

Still open:
- `arguments.length` counts declared optional parameters;
- the RegExp engine's PCRE semantics: an empty optional group iteration is
  `""` where JavaScript gives `undefined`;
- `v`-flag set operations and strict `v`-syntax errors;
- `URL` hostnames get no UTS #46 mapping (`Ａ.com`).

## Verification

Mac (Apple Silicon), against Node v24.19 byte for byte:
- the WPT `urlpatterntestdata.json` corpus, 366 of 369 cases (the three
  differences are the RegExp-engine items above);
- a 553-case argument/error/component corpus;
- about 15,000 fuzzed constructor and exec cases;
- group order for 3 to 17 groups.

Linux x86-64 (Node304, Node 24.19): group order for 3 to 17 groups matches
Node. `tests/urlpattern_test.go` checks it against the local Node.
`examples/url/urlpattern.ts` matches Node.
