# ADR-01572: Getter return check, and diagnostics at the declared name

- **Relations**: Extends ADR-01568, Implements TDD-00230
- **Date**: 2026-10-11

## Context

A sample of Test262 files the strict lane now rejects was compared with
tsc 5.9.3. Every code matched, with two differences:

- TS7034 (a variable implicitly `any` in some locations) and TS1100 (an
  invalid use of `arguments` or `eval` in strict code) were reported at
  the declaration's start (`var`, `function`), not at its name, as tsc
  reports them.
- tsc's TS2378, "A 'get' accessor must return a value", was missing: a
  getter whose end is reachable and that has no `return` statement at all.

## Decision

- TS7034 and the strict-code TS1100 checks report at the declared name
  (`namePos`), falling back to the declaration's position when the parser
  recorded none. The parser now records an object-literal accessor's name
  position on its function (`NamePos`).
- `checkGetterReturns` reports TS2378 at the getter's name, for class
  getters and object-literal getters, in the default lane only. It
  follows tsc's condition: the body's end is reachable and it contains no
  `return`.

## Verification

Codes and positions identical to tsc on the sampled Test262 files and on
a probe of class and object getters (a getter that returns, and one that
only throws, are accepted). Unit cases in `checker/check_test.go`. Linux
(DeskMini and Node304 kmlbox) full gates.
