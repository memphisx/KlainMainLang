# ADR-00930: Symbol-keyed dynamic-object properties

- **Date**: 2026-09-13

## Context

`obj[sym] = v` / `obj[sym]` / `Object.hasOwn(obj, sym)` on a dynamic (`any`)
object emitted invalid IR (`use of undefined value`) across ~24 Test262 files
(`built-ins/Object/{freeze,seal,preventExtensions,hasOwn,prototype/hasOwnProperty,
prototype/propertyIsEnumerable}/…symbol…`, `built-ins/Reflect/{get,has,set,
defineProperty,deleteProperty,ownKeys}/…symbol…`, `staging/sm/Symbol/
property-inheritance`). Surfaced while ranking the remaining invalid-IR
(CLANG_ERROR) backlog on both compat lanes.

## Investigation

Root cause: the dynamic-object key conversion (`dynAnyKeyRef`,
emit_dynobj.go) applied **ToString** to the key. For a Symbol that is a
TypeError in JS ("Cannot convert a Symbol value to a string"), so codegen
emitted an unconditional throw + `unreachable`, leaving `e.blockDone` set. The
*following* statement (`Object.hasOwn`) then emitted a fresh label that reopened
a live block referencing SSA registers (the object's unboxed payload) that the
dead-code mechanism had already dropped — hence `use of undefined value %tN`
where `%tN` was never defined. The real defect is semantic: property keys use
**ToPropertyKey**, not ToString — a Symbol is a *valid, unique* property key
that must be kept, not stringified.

A Symbol here is a heap object (`SymbolType`, identity by pointer — see
emit_symbol.go / TDD-00044). The dynobj bag (runtime_dynobj.go) is string-keyed.

## Decision

Map a Symbol property key to a synthetic, stable string key derived from its
pointer identity: `"\x01@@sym:%p"` (the `symbolKeySentinel` — a leading SOH
byte that never appears in a real source-level property key). Two references to
the same Symbol share the pointer, so set/get/has/delete round-trip. Symbol
keys are excluded from the *string* enumeration (`Object.keys` / for...in / JSON
via `__kml_dynobj_keys_enum`, and `getOwnPropertyNames` via `__kml_dynobj_keys`)
by skipping any bag key whose first byte is the `0x01` sentinel. Object spread
(`__kml_dynobj_merge`) is intentionally *not* filtered — `{...obj}` copies
enumerable symbol-keyed properties, and the synthetic key preserves identity.

## Implementation notes

- `dynAnyKeyRef` (emit_dynobj.go): a new `kv.Ty.IsSymbol` branch calls
  `emitSymbolPropertyKey` (sprintf of the pointer into a scratch buffer with the
  sentinel prefix). A new `IsArray || IsObject` branch ToStrings non-symbol
  array/object keys via `emitValueToString` (`obj[[1,2]]` → `"1,2"`), which
  also fixed the `Object.defineProperty(obj,[1,2],{})` invalid IR.
- `__kml_dynobj_keys_enum` and `__kml_dynobj_keys` (runtime_dynobj.go) gained a
  running-counter filter that drops sentinel-prefixed keys.

## Side effects discovered

`obj.hasOwnProperty(sym)` / `obj.propertyIsEnumerable(sym)` are still missing as
dynobj *methods* (they throw "not a function" at runtime) — a separate coverage
gap, not invalid IR. `Object.hasOwn(obj, sym)` works. `getOwnPropertySymbols`
would need the reverse (symbol reconstruction from keys) — not implemented.

## Verification

New E2E tests `tests/symbol_keys_test.go` (set/get, distinct identity, hasOwn,
enumeration exclusion) and example `examples/objects/symbol_keys.ts` (runs
clean in the default lane). The ~24 target Test262 files no longer emit invalid
IR. `make test-par` green; `make examples` 302/302.
