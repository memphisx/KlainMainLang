# ADR-00286: Math NaN/±Infinity correctness — float-preserving `floor`/`ceil`/`round`/`trunc`/`sign`, NaN-propagating `min`/`max`, JS `round` ties

- **Relations**: Extends [ADR-00187](ADR-00187.md) (integer-vs-float operator split); same audit source as [ADR-00284](ADR-00284.md)/[ADR-00285](ADR-00285.md)
- **Date**: 2026-08-22

## Context

The 2026-08-11 audit: `Math.floor/ceil/round/trunc/min/max/sign` produced
undefined-behavior garbage on `NaN`/`±Infinity` input. Root causes: the
rounding family ended in `fptosi double → i64` (poison for any non-finite
value); `Math.sign` coerced *every* input to i64 (so a double went through
the same poison); `Math.min/max` coerced later arguments to the *first
argument's* type (`Math.min(1, NaN)` forced NaN through i64) and used an
ordered `fcmp`+`select` fold, which silently drops a NaN operand. `Math.round`
was additionally libm `round` (half-away-from-zero), not JS's
ties-toward-+Infinity.

## Decision

Integer inputs keep their exact-i64 paths unchanged. Float inputs stay
doubles end to end — real JS returns doubles here, and only a double can
carry NaN/±Infinity through:

- **`floor`/`ceil`/`trunc`** — the libm call's double result is returned
  as-is (`TypeF64`), no `fptosi`. An integral double prints without a
  fraction (TDD-00080), so `Math.floor(2.9)` still displays `2`.
- **`round`** — `floor(x + 0.5)` (JS ties toward +Infinity:
  `Math.round(-2.5)` is `-2`), plus a signed-zero select so a zero result
  from a negative input is `-0` (`Math.round(-0.5)`).
- **`sign`** — a float path: ordered `fcmp` against 0.0 selects ±1.0, and
  everything failing both compares returns the *input itself* — NaN stays
  NaN and a signed zero keeps its sign, exactly the spec.
- **`min`/`max`** — all arguments are emitted first; any float operand
  promotes the whole fold to double through `llvm.minimum.f64`/
  `llvm.maximum.f64` (IEEE-754 minimum/maximum: NaN propagates, and
  `-0.0 < +0.0`), fixing both the NaN drop and the mixed-type coercion.
  All-integer calls fold with `icmp`/`select` on i64 as before.

`inferExprType`'s Math cases mirror the new result types (float argument →
`TypeF64` for the rounding family and `sign`; any-float-argument → `TypeF64`
for `min`/`max`).

## Verification

- Node-diff (node v26.3.0, byte-identical): all 14 NaN/±Infinity cases of
  the audit repro (`Math.floor(NaN)` → `NaN`, `Math.ceil(-Infinity)` →
  `-Infinity`, `Math.min(1, NaN)` → `NaN`, `Math.sign(-Infinity)` → `-1`,
  ...), plus finite spot checks (`round(2.5)`, `round(-0.5)` → `-0`,
  `min(1.5, 2)`, `max(-0.5, -1)`).
- New E2E: `TestE2EMathNaNInfinity` (tests/exprs_test.go); full suite green.
