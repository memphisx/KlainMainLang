# ADR-01748: The front end answers generators, literal unions and builtin values

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-19

## Context

The shadow report (P0.2) ranked 5915 disagreements between the codegen deciders and the new front end. The largest buckets were expressions the front end left unanswered: generator functions and their instances, `arguments` in generator methods, and builtin values. Then came a wrong answer: a union of string literals reduced to its first literal. The reason was that the dedupe key of a union's members leaves out a literal's value, so `'a' | 'b'` collapsed to `'a'`.

## Decision

- A union's members dedupe by representation plus a string literal's value, so two literals make a string.
- A generator function read as a value takes codegen's constructor closure type (`generatorValueRepr`). A binding initialized by a generator call holds codegen's instance layout. A generator method read off a boxed object, and a call through a boxed generator function, are boxes. `arguments` in an object literal's generator method keeps the generator's own convention (`any[]`).
- `process` read as a value is its boxed emitter object, in codegen's inference as well as in the front end.
- A builtin generic or overloaded function read as a value (`structuredClone`) is the closure codegen builds. A `const` holding one is its initializer's value. A call through such a binding whose closure returns a box returns that box.

## Consequences

- These disagreements leave the shadow report, so the switched deciders fall back to the old code less often.
- One bug the comparison turned up is now fixed: reading `process` as a value used codegen's placeholder `i64` in inference.
