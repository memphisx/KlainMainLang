# ADR-01628: An uncaught error is reported on stderr

- **Relations**: Extends ADR-01584
- **Date**: 2026-10-14

## Context

The Node-core conformance runner names a failed program by the first line of
its stderr. On Windows, thirteen files that pass on Linux failed with an empty
reason, including the ones that end in an uncaught exception.

## Investigation

`exceptions.c` (`__kml_throw_any`, both exits) and `emit_unhandled.go` (an
unhandled rejection) printed `Uncaught: <message>` with `printf`, to stdout.
Node writes an uncaught exception's report to stderr. A program that pipes its
stdout (as the runner, a shell pipeline or a test harness does) got the error
report mixed into its output and nothing on stderr. The report's shorter
format is a separate, recorded gap (`node-core-modules.json`, the `assert`
row); the stream is not.

## Decision

- One runtime helper, `__kml_print_uncaught(tag, payload)`, flushes stdout and
  then writes `Uncaught: <message>` to stderr. Flushing first keeps the
  report after what the program already printed, as on a terminal.
- Both exits in `__kml_throw_any` (the listener that throws, and the default)
  and `__kml_unhandled_report` call it. The `@.kml_unc_fmt` global goes.

## Implementation notes

`exceptionssrc/exceptions.c`, `runtime_exceptions.go`, `emit_unhandled.go`.
The tests' expect-exit helpers (`compileAndRunExpectExit`,
`compileAndRunExpectExitImports`) now return stdout followed by stderr through
one `runExpectExit`, which is what a terminal shows.

## Side effects discovered

The Node runner's failure reasons gain the program's own error text (ADR-01623).

## Verification

Windows 11: `throw new Error("boom")` prints nothing on stdout and
`Uncaught: boom` on stderr. `TestE2EUncaughtErrorSubtypePrintsMessage` checks
the stream. The uncaught, unhandled-rejection, null-dereference,
stack-overflow and module-task tests pass.
