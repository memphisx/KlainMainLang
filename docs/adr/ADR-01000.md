# ADR-01000: Byte-exact fs sync-error messages (libuv description + two-path form)

- **Relations**: Extends ADR-00768 (fs `err.code`/`syscall`/`path`), ADR-00770 (`err.errno`)
- **Date**: 2026-09-17

## Context

Every `fs.*Sync` failure throws through one runtime helper, `__kml_fs_throw`
(`codegen/llvm/runtime_fs.go`). `err.code`, `err.syscall`, `err.path`, and
`err.errno` already matched Node exactly (ADR-00768/00770), but the `.message`
string was built in a bespoke shape — `"<opdesc> '<path>': <strerror>"`, e.g.
`cannot open file for reading '/x': No such file or directory` — that shares
nothing with Node's. This was carried as a caveat on ~8 file-system rows ("Only
the error message text differs from Node's `ENOENT: …, <syscall> '<path>'`
format"), several of which had no other caveat and so were held out of Strict
coverage purely by it.

Node's message shape, verified with `node`:

```
readFileSync('/nope/x')        ENOENT: no such file or directory, open '/nope/x'
readFileSync('/etc')  (a dir)  EISDIR: illegal operation on a directory, read
fsyncSync(<bad fd>)            EBADF: bad file descriptor, fsync
renameSync('/a','/b')          ENOENT: no such file or directory, rename '/a' -> '/b'
copyFileSync('/a','/b')        ENOENT: no such file or directory, copyfile '/a' -> '/b'
```

So the shape is `<CODE>: <libuv-description>, <syscall>[ '<path>'[ -> '<dest>']]`:
the path clause is present only when a path is carried (absent for `read`-on-a-
directory and for fd ops like `fsync`, where `err.path` is also `undefined`), and
a second `-> '<dest>'` clause appears for the two-path ops (`rename`, `copyfile`),
which also set `err.dest`.

Two wrinkles: (1) the description is libuv's canonical string (`uv_strerror`),
not C `strerror` — they differ in case and sometimes in words (`EEXIST` is "file
already exists" in libuv vs "File exists" in strerror). (2) `copyFileSync` was
composed from the raw read+write helpers, so a missing source surfaced as the
underlying `open` on one path, not `copyfile '<src>' -> '<dest>'`.

## Investigation

- `runtime_fs.go`: `__kml_fs_throw(opdesc, syscall, path)` — the syscall
  argument at every call site already carries the correct Node syscall name
  (`open`/`read`/`unlink`/`scandir`/`stat`/`rename`/…); only `opdesc` (the human
  verb) fed the message. So the syscall token needed no new plumbing.
- `ensureErrnoCode` already maps errno → code name via a switch built from Go's
  per-platform `syscall.E*` constants (Linux numbers on Windows). The same
  (errno, code) enumeration can drive an errno → libuv-description switch.
- libuv descriptions taken from `uv-common.c`'s `uv_strerror` table.
- The `read`-on-a-directory EISDIR is synthesised by `__kml_fs_read_file_raw`'s
  own guard; it passed the path, but Node omits it (and `err.path` is undefined).
- `copyFileSync` (`emit_fs.go`) validated only `COPYFILE_EXCL` up front via
  `__kml_fs_copy_excl_guard`; all other failures fell through to the raw
  read/write helpers.

## Decision

1. Extract the (errno, code) enumeration into `errnoCodePairs()`; `ensureErrnoCode`
   now consumes it, and a new `ensureErrnoDesc` builds `__kml_errno_desc(errno)`
   → libuv description (null for an unmapped code) from the same list, keyed
   through the `libuvErrnoDesc` map.
2. New `ensureFsErrmsg` emits `__kml_fs_errmsg(code, desc, syscall, path, dest)`,
   a branch-free assembler: it null-normalises path/dest to `""`, sizes a headered
   KML string, and `sprintf`s one of three format strings selected on whether path
   and dest are non-empty. This is the single point that knows the message shape.
3. `__kml_fs_throw` is split: `__kml_fs_throw2(opdesc, syscall, path, dest)` does
   the work (resolve code+desc, build the message, fill the error object, throw);
   `__kml_fs_throw` forwards `dest=null`. `opdesc` stays in the ABI (every call
   site still passes its verb) but no longer appears in the message.
4. `errorObjType` gains a 10th field `dest` so `err.dest` matches Node on the
   two-path ops; `rename` throws through `__kml_fs_throw2` with the new path, and
   the fd/EISDIR sites pass `path=null` (no clause, `err.path == null`).
5. `copyFileSync`'s `__kml_fs_copy_excl_guard` is replaced by
   `__kml_fs_copy_file_guard(src, dest, excl)`, which probes both ends (open src
   `O_RDONLY`; open dest `O_WRONLY|O_CREAT|O_TRUNC`, `+O_EXCL` under
   COPYFILE_EXCL) and throws the two-path `copyfile` error via `__kml_fs_throw2`
   on either failure — matching Node's syscall, both paths, and `err.dest`.

Unmapped errnos fall back to `strerror` for the description (rare; the table
covers every code the fs surface produces).

## Implementation notes

- Appending `dest` grows `errorObjType` to 80 bytes; `aggregateErrorStructSize`
  is bumped 72 → 80 in lockstep (AggregateError is over-allocated to the full
  errorObjType size so a bounds-safe reinterpret of any field stays in-bounds),
  and the manual spawn-error builder in `runtime_childprocess.go` now
  null-inits field 9. `buildErrorObj` defaults it for every other error path.
- `err.path`/`err.dest` are null (not `undefined`) when absent — a ptr field is
  always present in the struct; `x.path == null` is the faithful loose-equality
  test, matching JS for an absent property.

## Side effects discovered

- The former `ptr null` path argument on the `__kml_fs_fdrw` failure path was a
  latent `strlen(null)` crash (never hit by a test); the null-tolerant message
  builder folds it in — null path is now first-class.
- A void-typed expression-bodied arrow (`() => fs.unlinkSync(x)` passed where
  `() => void` is expected) emits `ret i64` with no value — invalid IR. Unrelated
  to this change (worked around in the local repro with a block body); noted for
  a separate follow-up.

## Verification

- New `tests/fs_errno_fidelity_test.go` cases assert the byte-exact message,
  `code`, `syscall`, `path`, and `dest` for ENOENT-with-path, EISDIR-no-path,
  EBADF-no-path, the two-path `rename`, and the two-path `copyfile`.
- Updated the stale old-format assertions in `fs_test.go` (mkdir EEXIST, stat,
  rmSync, openSync) to the new message / `err.code`.
- `go build`, `go vet ./codegen/...`; targeted fs/exceptions/aggregate/
  structuredClone/spawn/sqlite suites pass. macOS arm64 (M4).
