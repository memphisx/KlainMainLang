# ADR-01902: an optional parameter's string and a generic executor's resolve in the oracle

- **Relations**: `Implements TDD-00230` (P3.3 shadow buckets)
- **Date**: 2026-10-21

## Context

- resolveType holds an optional parameter's string or number (`basename(path, suffix?: string)`) as possibly undefined: the parse records the undefined the type node leaves out. The oracle mapped the bare node, a plain scalar (every program linking path).
- `new Promise<T>` inside a generic function gives its executor's `resolve` the value type of the instantiation being emitted. The oracle answered from the checker's `Promise<T>`, whose `T` it read as `any` (every program linking fs.promises).

## Decision

- The oracle applies the annotation's recorded undefined to a plain scalar.
- Emission records the value type each `new Promise` executor was emitted with; the oracle answers `resolve` from it when the promise names its type argument.

## Consequences

- The shadow rows for both go away; no emission change.
