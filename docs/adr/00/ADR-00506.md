# ADR-00506: fetch header-buffer segfault on Linux (out-of-bounds slot-3 read)

- **Relations**: fixes a crash in the `fetch` runtime (`runtime_fetch.go`); relates to [ADR-00490](ADR-00490.md) (header capture), [ADR-00050](ADR-00050.md) (async fetch buffer)
- **Date**: 2026-08-29

## Context

Every `fetch`/async E2E test segfaulted on the Ubuntu CI runner (and reproduced
in Docker `golang:latest`), while all passed on macOS — the classic signature
of a heap-layout-dependent out-of-bounds read. The crash PC was
`__kml_curl_write_cb+40`, very early in the callback.

## Investigation

`__kml_curl_write_cb` is registered for **both** the body write
(`CURLOPT_WRITEFUNCTION`/`WRITEDATA`) and the header capture
(`CURLOPT_HEADERFUNCTION`/`HEADERDATA`, ADR-00490). Its userdata is a growable
buffer struct, and the callback's first act (TDD-00097 Stage 4 streaming hook)
is to read **slot 3** — byte offset 24 — as a pending-fetch backpointer, then
branch on whether it's null.

The body buffer is malloc'd at 40 bytes with slot 3 explicitly stored null. But
the **header** buffer (`%hbuf`) was malloc'd at only **24 bytes** — a bare
`{ data, len, cap }` — with no slot 3. So on every header callback the slot-3
read landed 8 bytes past the allocation. On macOS the adjacent heap happened to
read as null (→ the safe buffered branch); on Linux it read non-null garbage,
sending the header path into the streaming branch and dereferencing the garbage
pointer → SIGSEGV.

## Decision

Allocate `%hbuf` at 32 bytes (through slot 3) and store null into slot 3, so the
shared callback always reads a valid, null backpointer for header data and takes
the buffered branch. No callback change — the fix is purely the header buffer's
size and initialization matching what the shared callback reads.

## Verification

- Reproduced pre-fix in Docker `golang:latest` (all `fetch`/async tests SIGSEGV);
  gdb located the fault at `__kml_curl_write_cb+40`.
- Post-fix: the full `Fetch|Async|Promise|Task|HTTP|Https|TLS` suite passes in
  the same Docker image (Linux/arm64), and on macOS.
