# ADR-00909: null/undefined equality folds to a constant

- **Date**: 2026-09-12
- **Relations**: Extends ADR-00901

## Context

Invalid-IR sweep. Loose/strict equality between null/undefined and a concrete
scalar emitted invalid IR:

```ts
undefined == 0      // clang: icmp eq ptr null, 1
undefined == true
```

From `language/expressions/equals/S11.9.1_A6.2_T1.js` and
`does-not-equals/S11.9.2_A6.2_T1.js` (integer-constant bucket).

## Investigation

null/undefined is equal (loosely or strictly) only to null/undefined. The generic
comparison path compared a `ptr null` against the other operand's scalar constant
— `icmp eq ptr null, <number>`, invalid IR. The ADR-00901 guard already isolated
a bare null/undefined operand but handled only arithmetic/relational ops.

## Decision

Extend the ADR-00901 guard's switch with `== === != !==`:

- one nullish side + a concrete non-nullish scalar → constant: `false` for
  `==`/`===`, `true` for `!=`/`!==`.
- both nullish → loose `==`/`!=` treat null and undefined as equal; strict
  `===`/`!==` require the same nullish kind (`null === undefined` is false).

A void-typed operand counts as nullish (it is `undefined`, ADR-00900), so
`set.clear() === undefined` folds to true. The `emitNullableScalarNullCompare`
fast-path likewise treats a void operand as the `undefined` kind.

## Implementation notes

- Computed inside the existing guard from `lNullish`/`rNullish` and
  `left.Ty.IsNull == right.Ty.IsNull`, so it is pure compile-time folding.
- Object/array vs null keep their own dedicated paths (the guard excludes them);
  nullable-scalar vs null is still handled by `emitNullableScalarNullCompare`
  earlier.

## Side effects discovered

None; equality semantics verified exhaustively against Node.

## Verification

- `TestE2ENullUndefinedEqualityCompatJS` (new), matching Node across
  null/undefined/number/bool combinations.
- Both `A6.2` files compile clean.
