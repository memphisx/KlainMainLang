# ADR-00991: unannotated class field typed by a sibling `new C()` during registration

- **Relations**: `Extends ADR-00990` (surfaced by allocation-site widening)
- **Date**: 2026-09-17

## Context

An unannotated instance field initialized with another class's constructor —
`class Box { p = new Point(); }` — resolved to a zero type, so even static
`b.p.x` failed at codegen: `field access on non-object (no field 'x')`. An
*annotated* field (`p: Point = new Point()`) worked, because it resolves through
`resolveType` rather than initializer inference. Surfaced by ADR-00990
(allocation-site widening), which walks field types, but the bug is
independent — it broke plain static access too.

## Investigation

- Field types for an unannotated field come from `inferExprType(f.Initializer)`
  (`emit_classes.go`, registerClasses Pass 1). Debug printing showed
  `inferExprType(new Point())` returned a zero `Type` (`IR=""`, `IsObject=false`).
- The `*ast.NewExpression` arm (`emit_exprs_types.go`) returns
  `e.classes[ex.ClassName].Ty` for a user class. During Pass 1 the sibling's
  `ClassInfo` is already in `e.classes`, but its `.Ty` field is not populated
  until a later pass (line ~1711) — so it was the zero `Type`, and the arm
  returned that empty value before any fallback.
- Registration order is topological (base-before-derived), not source order, so
  two unrelated classes can be registered in either order; the sibling's finalized
  `.Ty` is simply not guaranteed to exist yet.

## Decision

In `inferExprType`'s `*ast.NewExpression` user-class arm, trust
`e.classes[name].Ty` only when it is a real object type (`IsObject`); otherwise
fall back to the nominal class type published in `e.interfaces` by
`registerClassNamePlaceholders`/the provisional in `registerClasses`. That
nominal `IsClass` type is re-resolved to its full field shape on demand by
`canonicalizeClassTy` at each access — the same mechanism the class
self-reference path already relies on — so the field gets the sibling's real
shape instead of the zero-type default.

## Implementation notes

- One guard added (`&& info.Ty.IsObject`) plus the `e.interfaces` fallback in
  `emit_exprs_types.go`. No layout or ABI change; purely which type the field
  binds to at registration.

## Side effects discovered

None. The fix also makes ADR-00990's widening apply to unannotated-field data
classes (`class Box { p = new Point(); tags = ["a"]; }` into `any`).

## Verification

- `tests/classes_test.go`: `TestE2EUnannotatedFieldSiblingClassType` (static
  `b.p.x`), and the widening path re-checked with unannotated nested/array
  fields — both byte-identical to Node.
- Regression: `TestE2EClass|Inherit|Field|Interface|Generic|Widen` pass.
  macOS arm64 (M4).
