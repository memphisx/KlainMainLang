# ADR-01457: Buffer-encoding overloads of the path-returning fs calls

- **Relations**: none
- **Date**: 2026-10-07

## Context

A shadow row in `internal_fs.ts` (`realpathSync(path, options)` under an
`any` option) led to the declarations: `realpathSync`, `readlinkSync` and
`mkdtempSync` declared only `(…, options?: EncodingOption): string`. The
strict lane rejected `fs.realpathSync('.', { encoding: 'buffer' })`, which
tsc with Node's declarations accepts and Node runs, returning a Buffer.

## Investigation

- Node's declarations give each three overloads: `string` for an encoding,
  `Buffer` for `BufferEncodingOption` (`'buffer' | { encoding: 'buffer' }`),
  and `string | Buffer` for either.
- The implementations already return a Buffer for that encoding.

## Decision

`BufferEncodingOption` is declared beside `EncodingOption`, and the three
calls take Node's three overloads. A call with an `any` option now meets
overloads that disagree, so its result is `any`, as codegen holds it
(`AnyArgOverloadCall`); the oracle mirrors that rule.

## Verification

- `TestE2EFsBufferEncodingPaths` (against Node).
