# ADR-00932: Any-keyed `Map<any, any>` runtime and bare-`new Map()` widening

- **Relations**: Implements TDD-00211
- **Date**: 2026-09-13

## Context

A bare `new Map()` with no type arguments, annotation, or seed entries defaulted
to **string keys, number values** (`mapKVTypes`). Heterogeneous use miscompiled:
`new Map(); map.set(1, 42)` inttoptr'd the numeric key through the string path,
and object/array/symbol/boolean/null keys reached `__kml_map_str_set` with a
non-pointer operand — invalid IR. Three Test262 CLANG_ERROR files exercise this:
`built-ins/Map/prototype/{get/returns-value-different-key-types,
has/return-{true,false}-different-key-types}` — a `var map = new Map()` followed
by heterogeneous `.set()`/`.has()` over every key kind.

## Investigation

`Map` had exactly two backing runtimes chosen from the key type
(`emitMapOrSetCreate`): `__kml_map_str_*` (content-hashed string keys) and
`__kml_map_num_*` (raw-i64 keys, `icmp eq`). Neither can hold heterogeneous keys
with JS `Map` key semantics. The dispatch (`emitMapCall`, `emitMapSeedFromEntries`,
`mapKeysAndVals`, `mapOrSetValuesArray`, `emitMapEntries/ForEach/GetNullable`)
branched on a `strKey bool` throughout.

`__kml_any_eq` (runtime_dynamic.go:17) is SameValueZero **except** `NaN`: its
numeric arm is `fcmp oeq`, so `NaN === NaN` is false. Because every encoded
number is canonicalized before boxing (runtime_nanbox.go), two `NaN` keys are
bit-identical — so a leading `icmp eq i64` over the boxes covers `NaN` (and
short-circuits identical immediates/pointers), with `__kml_any_eq` handling the
rest (string content, `-0`/`+0` via `fcmp oeq`, array/object identity).
`inferEmptyArrayElemTypes` (emit_func.go) was the template for a name-keyed
widening pre-pass.

## Decision

Add a third monomorphic runtime `__kml_map_any_*`, structurally identical to the
numeric map (same 56-byte open-addressing header, probe/rehash/tombstone
machinery), storing NaN-boxed `i64` keys and values. It differs in two helpers:

- `__kml_map_svz` — SameValueZero: `icmp eq i64 %a, %b` else `__kml_any_eq`.
- `__kml_map_any_hash` — consistent with SVZ: string-kind boxes hash by content
  (`__kml_map_str_hash` on the char\*), array-kind by their inner data pointer
  (the identity `__kml_any_eq` compares), the numeric-zero box normalized
  (`-0`→`+0`) so `set(-0)`/`get(0)` collide, everything else by raw bits.

`get` returns the `undefined` box on a miss.

Dispatch is refactored from `strKey bool` to a `(suffix, keyIR)` pair via
`mapRuntime(keyTy)` (`"any"`/i64, `"str"`/ptr, `"num"`/i64), collapsing every
str/num branch into one formatted call. Keys reaching the any runtime are boxed
with `emitBoxValue` (`mapKeyRef`), never `coerce` (an already-evaluated `NaN` is
an i64 box `coerce`'s shortcut would leave unboxed).

A bare `new Map()` takes its K/V from a widening pre-pass `inferEmptyMapKVTypes`
(mirrors `inferEmptyArrayElemTypes`): it unifies key types across the binding's
`.set()`/`.get()`/`.has()`/`.delete()` calls and value types across `.set()`.
All-string keys → string map, all-one-numeric → numeric map, anything else →
any map; values unify likewise. An any-keyed map's value type is **forced to
`any`** (`forceAnyMapVal`) so the boxed-value miss sentinel decodes correctly —
a non-dynamic value type would read the `undefined` box as a raw pointer and
crash.

## Implementation notes

- `runtime_collections.go`: `ensureMapSvz`, `ensureMapAnyHash`,
  `ensureMapAnyHelpers` (+ `usedMapAnyHelpers`/`usedMapSvz`/`usedMapAnyHash`).
- `emit_collections.go`: `mapRuntime`/`ensureMapFamily`/`mapKeyRef`/
  `forceAnyMapVal`, the `strKey`→`suffix` refactor, `inferEmptyMapKVTypes` +
  `mapKV`/`unifyMapKeyType`/`unifyMapValType`/`mapKeySig`/`mapValSig`.
- `emitter.go`: `emptyMapKV` field, populated at `prog.Body` **before**
  `registerModuleGlobals` (so a promoted global's type agrees with the runtime
  family `emitMapVarDecl` creates).
- `emit_func.go`: save/restore `emptyMapKV` per function/arrow/function-expr body.
- `emit_exprs_vardecl.go` `reliableGlobalType`: apply the same widening +
  `forceAnyMapVal` so a promoted map global's declared type matches its store —
  the map lives at `@__kml_global_*` (maps *are* promoted), so this site, not
  just `emitMapVarDecl`, drives the dispatch type at call sites.
- The four external `mapKeysAndVals` callers (fetch/headers/inspect/
  structured-clone) and the structured-clone Map/Set copy loops were updated to
  the `suffix` API; they now handle any-keyed maps for free.

## Side effects discovered

- `get/returns-value-different-key-types` still CLANG_ERRORs, now on an unrelated
  bug: its `var item = {}` is cross-reassigned to `[]`/`Symbol`/`null`, and an
  array aggregate stored into that widened (`any`) promoted global's ptr slot is
  not boxed (`store i64 <{ptr,i64}>` type mismatch). Independent of Map —
  reproduced with a two-line `var x = {}; x = []`. Belongs to the cross-type-
  widened-binding / boxed-element boundary (TDD-00205 Stage 2), tracked there.
- A pure-numeric bare `new Map()` correctly routes to `__kml_map_num_*`, which
  does **not** normalize `-0`/`+0` (a raw-bits map) — a pre-existing numeric-map
  fidelity gap, unchanged here and separate from this ADR.
