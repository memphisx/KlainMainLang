# ADR-01921: enum members by constant evaluation; the enum as a value

- **Relations**: `Implements TDD-00230` (Node fidelity, number representation)
- **Date**: 2026-10-21

## Context

- Numeric enum members were 64-bit integers parsed from a bare number literal only. `B = 2.5` read `0`, `C = 2 ** 53 + 1` and `Y = X * 8` read `1` (the auto-increment of whatever came before), and a `let` holding a member truncated `x + 0.5`.
- An unmatched reverse lookup (`E[99]`) returned the string `"undefined"`.
- The enum read as a value (`Object.keys(E)`, `console.log(E)`, `const o = E`) did not compile.

## Decision

- A member's value is TypeScript's constant evaluation of its initializer: number and string literals, earlier members (bare, `E.A` or `E["A"]`), unary `+ - ~`, the arithmetic, shift and bitwise operators, and `+` concatenation. A numeric member is a number (a double), as every number is.
- A computed member (a non-constant initializer) and an enum mixing string and numeric members are compile errors, not silently wrong values.
- The reverse lookup compares numbers and yields `undefined` on a miss.
- Each enum is also a module constant holding its object, each name mapped to its value and, for a number, the value back to the name; the enum's name read as a value is that object.

## Consequences

- Enum output matches Node with type transformation enabled; numeric enums share the number representation the rest of the compiler uses.
