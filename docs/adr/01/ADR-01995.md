# ADR-01995: Iterator result that is not an object

- **Date**: 2026-11-21

## Context

Test262 `built-ins/AggregateError/errors-iterabletolist-failures.js` hands
`new AggregateError` an iterable whose `next()` returns the string
`'a string'`. Node throws `TypeError: Iterator result a string is not an
object`. On the Mac js lane the program grew to 1.5 GB and the runner's
reaper killed it; on Linux (Node304) it reached 1.6 GB before the data limit
ended it. `for…of`, spread, `Array.from` and `new Set` over the same value
did the same.

## Investigation

- Every walk of the iteration protocol over a value held in `any` is the
  `for…of`-over-`any` lowering (`emitForOfAnyValue`,
  codegen/llvm/emit_stmts_forof_any.go): spread, `Array.from`, the collection
  constructors and AggregateError's `errors` collect through
  `__kml_any_iter_collect`, which is that lowering.
- After `r = it.next()` the lowering read `r.done` and `r.value` directly. A
  primitive's `done` reads as undefined, so the loop never ended and pushed
  undefined until memory ran out.
- The destructuring lowering (emit_exprs_assign.go) and `yield*`
  (emit_yieldstar_any.go) already checked the result.

## Decision

After `next()` (and its await under `for await`), a result whose box is a
primitive (number, string, boolean, null, undefined) throws the TypeError
`Iterator result <String(r)> is not an object` — ECMAScript IteratorNext step
3, with V8's message.

## Implementation notes

- codegen/llvm/emit_stmts_forof_any.go: the check, before the `done` read.

## Verification

- `TestE2EAnyIteratorResultNotObject` matches Node (js lane): for-of, spread,
  Array.from, new Set and AggregateError over results `'a string'`, 7,
  undefined, null and true.
- The Test262 file's eleven cases match Node on Linux x86 (Node304).
