# ADR-01108: A binder: symbols, scopes, name resolution and the redeclaration checks

- **Relations**: `Implements TDD-00230` (Phase 2, P2.1); `Extends ADR-01107`, `ADR-01106`
- **Date**: 2026-09-24

## Context

Codegen resolves every name by string, while it emits: `Emitter.lookup`
walks a stack of per-block maps it builds as it goes, and `emitIdent` falls
through a chain of other tables when that misses (a namespace sibling, a
generator, a named function, a builtin global such as `NaN` or `workerData`,
an error constructor) before reporting "undefined variable". Which name an
identifier denotes is therefore decided in the middle of emitting IR, in an
order that depends on what has been emitted so far.
[TDD-00230](../tdd/TDD-00230.md) P2.1 introduces a binder that declares every
name in the scope that owns it and resolves every reference before codegen
runs, so codegen can later ask it instead of resolving strings.

## Investigation

- **Binding forms in this AST.** A binding name is a string on its declaring
  node, not an identifier node: `VarDeclaration.Name`, the names inside
  `ArrayDestructuring`/`ObjectDestructuring` patterns, `Param` structs inside
  function nodes, `CatchClause.Param` (a helper struct inside `TryStatement`),
  `ForOfStatement.VarName` and its patterns, `ForInStatement.VarName`,
  `ImportSpecifier.Local`, and the names of function, class, enum, interface
  and type-alias declarations. References are the `*ast.Identifier` nodes, and
  the class name of a `new` (`NewExpression.ClassName`, a string since P1.6).
- **Scope rules.** Module code is strict: `var` hoists to the enclosing
  function or module, `let`/`const`/`class` and a function declared in a block
  are scoped to the block; a loop head and a catch clause are scopes; a named
  function or class expression sees its own name; parameters and the body's
  top-level declarations share the function's scope; a non-arrow function has
  an implicit `arguments`.
- **Class members** are properties, not bindings: the generated traversal
  would visit a class's methods as function declarations, which must not
  declare their names.
- **typescript-go's binder** (`internal/binder/binder.go`,
  `internal/ast/symbolflags.go`): `SymbolFlags` with exclude masks, a symbol
  per name per container, declarations merged into it.
- **Namespaces.** The parser desugars a namespace's function and variable
  members into top-level declarations named `NS__kmlns_member` (classes,
  interfaces, types and enums keep their bare names), and records only the
  member names. Codegen resolves a bare sibling reference inside a member by
  parsing the namespace back out of the function's mangled name
  (`emit_func.go`, `nsSibling`). The resolver merges each file's body by
  appending the same statement values, so a list of a namespace's member
  statements survives the merge.
- **The redeclaration checks the binder replaces.** `resolver/scopecheck.go`
  checked same-scope clashes and a `var` hoisting through a lexical binding,
  but only in blocks, loops, `try`, `switch` and function declarations: not
  in arrow functions, function expressions, class methods or static blocks,
  and not parameters or a catch variable against the body. Its errors had no
  file. `mangleFileDecls` rejected top-level duplicates separately, with no
  position ("'x' is declared more than once in <path>"), and allowed an
  interface to merge with a class. Neither collected names inside nested
  destructuring patterns.
- **Where the program comes from.** The resolver merges every module into one
  program and renames module-level names apart; the binder runs on that
  merged program, the one codegen emits, so the two resolve the same names.

## Decision

- **A `binder` package.** `Symbol{ID, Name, Flags, Declarations, Scope,
  Implicit}` with TypeScript's flag values and exclude masks for the kinds
  this compiler has; `Scope{Kind, Node, Parent, Symbols}` for a module,
  function, block (also a loop head or switch body), catch clause, the name
  of a named function or class expression, and an enum's members; symbol
  tables that keep insertion order, so ids and walks are deterministic.
- **Two passes over the program.** The first declares every name in its
  scope; the second resolves each identifier reference, and each `new`'s class
  name, from the reference's scope outwards among value symbols. The AST is
  not changed: results live in side tables keyed by node. A reference to a
  name the program does not declare is recorded as a global.
- **Namespaces are container scopes.** The parser records each namespace's
  member statements, nested ones under their dotted name, in
  `Program.NamespaceGroups` (the resolver merges the lists; the generated
  traversal skips the field, whose statements are already in `Body`). The
  binder binds each member statement inside its namespace's scope (and its
  parents'), declares each namespace's name in the scope around it, and
  declares a mangled member under the name the source gave it, so a member's
  body resolves a bare sibling to that sibling, and a `var` member hoists to
  the namespace, not the module. The desugaring itself stays in the parser
  until codegen reads symbols.
- **Redeclarations follow the early errors of strict code**, not
  TypeScript's exclude masks (which also cover type-space clashes). Each
  declaration has a kind: var-like (`var`, a parameter, a catch variable, a
  function declared directly in a function, namespace or module), lexical
  (`let`, `const`, `class`, `enum`, an import, a function declared in a
  block), type-only, namespace, or name-only. Two declarations of one name in
  one scope clash when either is lexical; var-likes merge, interfaces merge
  with each other and with a class, a namespace merges with a function,
  class, enum or namespace, and a type alias shares its name with no type. A
  catch body binds into the catch variable's scope, so `catch (e) { let e }`
  clashes and `catch (e) { var e }` does not. A `var` that hoists through a
  scope declaring the name lexically clashes (checked after every name is
  declared). Two enums of one name are a merge TypeScript allows and this
  compiler does not implement: reported as not yet supported, as before.
- **Annex B under `-compat=js`.** Sloppy scripts let two plain function
  declarations in one block share a name (ECMAScript B.3.3.4); with the
  js lane's option the binder merges them.
- **The binder's checks replace the resolver's.** The resolver binds each file
  before renaming (so messages carry the source names) and reports every
  clash as a diagnostic with the file, position and byte offset: TS2451 when a
  `let`/`const` is involved, TS2300 otherwise, in V8's wording
  ("identifier 'x' has already been declared"). `resolver/scopecheck.go` is
  deleted (the helpers the readability checks share moved to
  `readability.go`), and so is `mangleFileDecls`'s duplicate branch, which
  can no longer fire.
- **The binder is the first shadow oracle.** `codegen/llvm/shadow_binder.go`
  registers it with the P0.2 harness. `emitIdent` records, at each of its
  branches, whether codegen took the identifier as bound by a declaration (a
  local or module binding, a function or generator, a namespace member) or
  as a global it knows or an undefined name; the harness compares that with
  whether the binder resolved it to a symbol. The binder has no answer to the
  type questions yet.
- **Not here:** TDZ reads (a runtime ReferenceError in JavaScript, which
  `resolver/readability.go` still rejects at compile time) move with the flow
  graph (P2.2), and type-space clashes with the checker.

## Implementation notes

- **New:** `binder/symbol.go`, `binder/binder.go`, `binder/binder_test.go`,
  `codegen/llvm/shadow_binder.go`.
- **Deleted:** `resolver/scopecheck.go`.
- **Changed:** `ast/nodes.go` (`Program.NamespaceGroups`,
  `NamespaceGroup`), `ast/gen/main.go` and `ast/walk_test.go` (the field is
  an alias of body statements), `parser/parser.go` and
  `parser/parser_stmts.go` (recording the groups), `resolver/resolver.go`
  (merging them, the per-file binder check, `fileInfo.src`, the removed
  duplicate branch), `resolver/readability.go` (the shared helpers),
  `diag/diag.go` (`Offsets`), `diag/messages.go` (three messages),
  `codegen/llvm/shadow.go` (the `Reference` question and its
  hook), `codegen/llvm/emit_exprs.go` (`emitIdent`'s branches record their
  answer), `tools/shadow/main.go` (`-roots` narrows the corpus; records are
  concatenated in a buffer).
- **A typed nil child** (an absent `finally` block held in an interface) is
  skipped the way the generated traversal skips it.

## Side effects discovered

- **`examples/basics/destructuring.ts` declared `const lo` and `hi` twice at
  the top level** (the second pair inside a nested object pattern, which no
  check collected). Node rejects the file; the second pair is renamed.

- **An empty record file broke the report** (`multiple Read calls return no
  data`): the records were streamed through a pipe, and an empty file wrote
  zero bytes. They are concatenated in memory now.

## Verification

- **Resolver-level equivalence** against the previous resolver, over the
  whole corpus (107,567 resolve runs: examples, tools, apps, tests, Test262,
  each `.js` file in both lanes): no AST changed on a file that resolves.
  The errors that changed:
  - 196 same clash, now with the file, a position and V8's wording (14 of
    them were the position-less top-level message);
  - 175 files that resolved before and are now rejected: Test262's
    early-error negative tests (redeclarations in blocks and `switch`,
    parameters against the body in async, generator and arrow functions and
    methods, lexical catch clashes, `for (const x …) { var x }`, static
    blocks), and two Annex B `noStrict` tests in the strict lane, which is
    strict code (their js-lane runs resolve);
  - one file that now reports an earlier redeclaration first;
  - `examples/basics/destructuring.ts` (above).
- **Node 26.10.0** rejects every clash newly reported that the old checks
  missed (an arrow's parameter and body, a lexical catch clash, a repeated
  function in a block, a method's parameter and body, `let x; { var x }`).

All on macOS arm64 (M4):

- `go test ./binder`: var hoisting, block shadowing, parameters and defaults,
