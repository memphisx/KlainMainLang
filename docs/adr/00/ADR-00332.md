# ADR-00332: process introspection + `process.nextTick`

- **Date**: 2026-08-24

## Context

Part of completing the Process / CLI area (15/23). This batch adds the
mechanically-clean, genuinely-useful `process.*` reads and scheduling that reuse
existing machinery: `process.arch`, `process.uptime()`, `process.hrtime()` /
`process.hrtime.bigint()`, and `process.nextTick()`.

## Decision

- **`process.arch`** — a compile-time string constant via a new `nodeArchName()`
  (GOARCH → Node's arch strings: `amd64`→`x64`, `386`→`ia32`, else identity),
  mirroring the existing `nodePlatformName()`.
- **`process.nextTick(fn)`** — enqueues `fn` onto the existing microtask FIFO
  (`@__kml_microtask_enqueue`, the Promise-reaction queue). V1 takes a zero-arg
  `() => void` (Node forwards extra args). Node drains nextTick before the
  promise microtask queue; this compiler has one queue, so nextTick and
  `Promise.then` share FIFO order — a documented simplification.
- **`process.uptime()`** — seconds (a double) since process start. A monotonic
  timestamp is captured once into `@__kml_proc_start_ns` at `main` entry (a
  finalization-injected `@__kml_proc_uptime_init()` call, guarded by
  `usedProcessUptime`, like the cluster seed); `process.uptime()` returns
  `(now − start) / 1e9`.
- **`process.hrtime()`** — the monotonic time as a `[seconds, nanoseconds]`
  tuple (`{ i64, i64 }`). V1 takes no argument; the legacy diff-from-previous
  form is unsupported (use `hrtime.bigint()` and subtract).
- **`process.hrtime.bigint()`** — total nanoseconds as a bigint, via
  `@__kml_bigint_from_i64`. Dispatched as a two-level member call (like
  `process.stdout.write`).

All clocks read `CLOCK_MONOTONIC` through the existing `clock_gettime` /
`monotonicClockID()` layer that `performance.now()` already uses.

## Implementation notes

- `runtime_process.go`: `nodeArchName`, `ensureProcessUptime`
  (`@__kml_proc_uptime_init` + `@__kml_process_uptime`), `ensureProcessHrtime`
  (`@__kml_process_hrtime` returning the malloc'd tuple + `@__kml_process_hrtime_ns`).
- `emit_process.go`: `emitProcessNextTick`/`Uptime`/`Hrtime`/`HrtimeBigint`.
- Dispatch in `emit_call.go` (method switch + the `hrtime.bigint` nested member),
  `emit_exprs_member.go` (`arch` read), `emit_exprs_types.go` (return types).
- `usedProcessUptime`/`usedProcessHrtime` flags; the uptime capture is injected
  at `main` start in `emitter.go`.

## Side effects discovered

Deferred (still ❌, lower value / heavier): `process.version`/`versions`
(semantically fraught for a non-Node runtime), `process.memoryUsage()` (no heap
tracking exists; only rss would be real). Noted on the status page.

## Verification

- `tests/process_test.go`: arch constant; nextTick ordering (`sync` before the
  queued `tick`); uptime ≥ 0; hrtime tuple shape; hrtime.bigint monotonic +
  `typeof === "bigint"`.
- Machine: verified on Mac (arm64). Clock ids / arch strings are platform-branched
  and correct for Linux; not separately re-run there this session.
