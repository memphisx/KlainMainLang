# ADR-00508: globalThis as an alias-peeling desugar

- **Date**: 2026-08-29

## Context

`globalThis` was a `missing` row, noted as "not meaningful in a native
single-file context." That is true of the *dynamic* global object (enumerating
globals, adding new ones at runtime), but the overwhelmingly common real usage
is `globalThis.X` as a portable, explicit way to reach an ambient global that
happens to already be supported bare — `globalThis.setTimeout(...)`,
`typeof globalThis.fetch`, `globalThis.JSON.stringify(...)`, feature-detection
idioms, and the `globalThis.crypto` binding the WebCrypto corpus already
special-cased. Supporting that member-access subset costs little and unblocks
those idioms (and Test262 files that reference `globalThis`).

## Investigation

`globalThis.crypto` was already handled by an ad-hoc `cryptoGlobalExpr` check
(`emit_objects.go`) — evidence the general form was worth a uniform treatment
rather than one special case per global. The blocker for the general case is
that structural dispatch throughout codegen inspects the raw AST
(`id.Name == "console"`, etc.), so a `globalThis.console.log(...)` callee —
`Member{Member{globalThis, console}, log}` — never matches without first peeling
the `globalThis.` prefix.

A full mutating AST-rewrite pass over every expression/statement node was
considered and rejected as far larger than the value: `MemberExpression` has no
`computed` flag (computed access is a separate `IndexExpression`), so the only
shape to handle is `globalThis.<name>` chains. This follows the existing
`stripNSTypeQualifier` precedent (`emit_exprs_member.go`), which likewise
rewrites-and-re-dispatches a member chain at the emit boundary.

## Decision

Add `unwrapGlobalThis(expr)`: recursively, if an expression is a
`MemberExpression` whose (recursively unwrapped) object is the unshadowed
identifier `globalThis`, return a bare `Identifier` of the property name; else
rebuild with the unwrapped object. Applied at three boundaries so codegen and
type inference agree:

- `emitMember` — value reads (`globalThis.crypto`).
- `emitCall` — callee peeling (`globalThis.setTimeout(...)`,
  `globalThis.JSON.stringify(...)`).
- `inferExprType` — the member and call forms, so member-type-driven dispatch
  matches codegen.

Because it recurses, arbitrary depth desugars: `globalThis.a.b` →
`Member{Identifier a, b}`. Only *known* globals resolve — an unknown
`globalThis.foo` peels to a bare `foo` and hits the ordinary
"undefined variable" compile error, never a runtime lookup.

## Implementation notes

- `unwrapGlobalThis` in `emit_exprs_member.go`; hooks in `emit_call.go` and
  `emit_exprs_types.go`.
- A pathological local shadow of `globalThis` is respected via
  `isShadowedByLocal`, so the rewrite is skipped then.
- Rewrites build fresh AST nodes (non-destructive), preserving `Optional`.
- The pre-existing `cryptoGlobalExpr` globalThis branch is now redundant but
  left in place (harmless).

## Side effects discovered

Out of scope, recorded as caveats on the status row: a bare `globalThis` used as
a standalone object value, computed access (`globalThis["x"]`), and assigning a
new global (`globalThis.x = …`) — all of which need the unstarted dynamic global
record.

## Verification

- New `tests/globalthis_test.go` — namespace method, nested console, Math, a
  global function, a timer, and an unknown-member rejection; all passing.
- `examples/globals/globals.ts` extended and run.
- Verified on macOS (Apple Silicon M4).
