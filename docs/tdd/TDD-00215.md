# TDD-00215: HTTP server `'clientError'` and `'error'` events

- **Status**: Implemented
- **Date**: 2026-09-16

## Context

`http.createServer(...)` returns a server handle whose `.on(event, listener)`
recognizes `'request'`, `'stream'`, `'listening'`, `'upgrade'`, `'close'`, and
`'connection'`; any other event name is a clean compile-time rejection
(`emit_http.go`, `emitHTTPServerMethod`'s `case "on"`). Two Node server events
are still missing:

- **`'clientError'`** `(err, socket)` — fires when a client connection produces a
  protocol error before it could be dispatched to a request handler (a malformed
  request line, a bad header block, an oversized header block). Node's default,
  when no listener is registered, is to write `HTTP/1.1 400 Bad Request` +
  `Connection: close` and destroy the socket. This is a common hardening surface:
  servers front-ending untrusted clients log or rate-limit off it.
- **`'error'`** `(err)` — fires on a server-level failure, in practice a bind
  failure (`EADDRINUSE`, `EACCES`). Without a listener the process should surface
  the failure (Node throws it as an uncaught exception).

Both are genuinely reachable through the ordinary `http.createServer` API, unlike
the previously-tracked "ReadableStream-body return over HTTPS/1.1" keep-alive
caveat, which no public API can actually produce (a returned `ReadableStream`
body only routes through `klain:http`'s plain-TCP `http.listen`; `createServer`
requires `(req, res) => void` and ignores a returned object — corrected in the
status page same-commit as this TDD).

## Design

### Firing sites in the existing dispatcher

`buildHTTPDispatcher` already has the two exact points these events need:

- **`noReqL`** (`emit_http.go`) — the connection-abort label. Reached by *both*
  malformed-request cases (oversized header block; a partial, unparseable read)
  **and** clean keep-alive EOF (an idle persistent connection the client closed
  between requests). `clientError` must fire on the former and stay silent on the
  latter, so the dispatcher needs a per-connection discriminator: a `malformed`
  i1 that the too-big/parse-failure edges set to 1 before branching to `noReqL`,
  left 0 on the clean-EOF edge (`isZero` read with no bytes buffered mid-request).
- **`__kml_http_bind_and_listen` failure** (`runtime_http.go`) — currently
  `failwithfd`/`failnofd` call `__kml_http_throw` and `unreachable`. For `error`,
  the bind failure must instead route to the registered listener when one exists.

### `clientError` — `(err, socket)`

At `noReqL`, guarded on `malformed == 1`:

1. Load `@__kml_http_clienterror_evt<sfx>`. If null → **Node default**: write
   `HTTP/1.1 400 Bad Request\r\nConnection: close\r\n\r\n` via the connection's
   normal send path (`__kml_http_conn_send` on TLS, `write` on plain), then close.
   This *changes* current behavior (today `noReqL` closes silently); it matches
   Node and is strictly more useful. Gate the 400 write on `malformed` so a clean
   idle-EOF close stays byte-identical to today.
2. If a listener is set → build a `net.Socket` over the fd (reuse the
   `emitHTTPConnectionEvent` calloc-64 + fd + TLS-ssl-field-5 shape) and an
   `Error` object, invoke `listener(err, socket)`, then close the socket (the
   listener owns the response; V1 does not let it resume the connection). No
   auto-400 when a listener is present (Node parity — the listener decides).

**Error object.** Reuse the existing thrown-`Error` object shape (the `Error`
class the runtime already constructs for `throw`/`catch`). V1 populates
`.message` (`"Parse Error"` / `"431 Request Header Fields Too Large"`) and best-
effort `.code` (`'HPE_INVALID_...'` bucketed coarsely; `'HPE_HEADER_OVERFLOW'`
for the oversized case). `bytesParsed`/`rawPacket` are out of V1 scope (noted as
a caveat), since the dispatcher does not retain the raw header bytes past the
parse attempt.

### `error` — `(err)`

`__kml_http_bind_and_listen` takes an extra "has error listener" signal. Cleanest
without changing its arity: a thread-local `@__kml_http_error_evt` global set at
`.on('error')` registration, read in `failwithfd`/`failnofd`. When set, build an
`Error` (`.code = 'EADDRINUSE'` when `errno == EADDRINUSE`, else `'EACCES'`/the
raw errno name; `.message` from `strerror`) and invoke `listener(err)` instead of
throwing, then `return -1` (the caller already stores the listen fd; a -1 fd must
then skip the accept loop — the event loop's accept path treats a negative
listen fd as "nothing to accept", which needs a guard added).

Timing mirrors the existing `'listening'` immediate-fire divergence: the listener
runs synchronously at `listen()` time rather than on a later tick.

### Staging

- **Stage 1 — `clientError`.** The `malformed` discriminator, the Node-default
  400, the `(err, socket)` listener path. Primary server only initially (like
  `'close'`); additional servers reject with a clear message. E2E test drives a
  raw malformed request line and asserts the 400 default, then a second test with
  a listener registered asserts the listener sees the error and the socket.
- **Stage 2 — `error`/`EADDRINUSE`.** The bind-failure interception + negative-fd
  accept guard. E2E test binds a port twice in one program (second
  `createServer(...).listen(samePort)`) and asserts the `error` listener fires
  with `code === 'EADDRINUSE'` rather than the process aborting.

Recommended: land Stage 1 first (higher value, self-contained), Stage 2 as a
follow-on ADR.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| `.on(event, listener)` dispatch | Built | `emitHTTPServerMethod` `case "on"`; add two branches before the reject at the `'request'`/`'stream'` fallthrough |
| net.Socket-over-fd construction | Built | `emitHTTPConnectionEvent` (calloc 64, fd field 0, TLS ssl field 5) — factor out and reuse |
| Stored-listener invoke trampoline | Built | Same site loads `{ptr,ptr}` header and calls the closure |
| `Error` object construction | Built | Runtime `Error` class used by `throw`; need a codegen helper to mint one with `.message`/`.code` from IR |
| `malformed` discriminator at `noReqL` | Missing | New i1 alloca set on the too-big + parse-failure edges, 0 on clean-EOF |
| Negative listen-fd accept guard | Missing | Needed only for Stage 2 (`error` returns -1 instead of throwing) |

## Open questions

- Should the Stage 1 default-400 also send a minimal body, or headers-only? Node
  sends headers-only for the built-in `clientError` 400 — match that (no body).
- `clientError` on an **additional** (non-primary) server: defer (reject) in V1,
  or wire the suffixed global through immediately? Leaning defer, matching how
  `'close'` shipped primary-only first.
- Coarse `.code` bucketing vs. exact llhttp-style `HPE_*` codes: the compiler's
  hand-rolled parser does not produce llhttp error codes, so exact parity is not
  achievable without a parser rework — V1 uses a small honest set and documents
  the divergence.
