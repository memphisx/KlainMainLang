# ADR-01155: The non-standard `process.execFileSync`, `process.readLineSync`, `fs.readFileSyncBytes` and `cluster.workerId` removed; their Node forms made faithful

- **Relations**: `Implements TDD-00230` (Phase 3, P3.1); `Extends ADR-01154`; `Supersedes ADR-00025` (and ADR-00024's `process.readLineSync`)
- **Date**: 2026-09-25

## Context

The tsc run over the examples (ADR-01154) found four APIs that TypeScript
rejects and that no standard defines: `process.execFileSync`,
`process.readLineSync`, `fs.readFileSyncBytes` and `cluster.workerId`. No
`klain:` module uses them. The status pages described them as working
features. Each stood in for a Node form that did not work faithfully:

- `fs.readFileSync(path)` returned a string, where Node returns a
  `Buffer`. `readFileSyncBytes` was the byte-exact read.
- `child_process.execFileSync`/`execSync` returned a string without an
  encoding, where Node returns a `Buffer`.
- `readFileSync(0)` (all of stdin) was a compile error.
- `cluster.worker` did not exist.

## Investigation

- **`readdirSync` order.** On the `fs` example, one `withFileTypes` listing
  differed from Node's. libuv's `uv_fs_scandir` sorts entries with
  `strcmp` on Unix, so Node's order is sorted. This compiler returned raw
  `readdir(3)` order; the plain form came out sorted only by chance.
- **`writeFileSync(path, arrayBuffer)`.** The `fs` example wrote a bare
  `ArrayBuffer`. Node throws `ERR_INVALID_ARG_TYPE` (a string, Buffer,
  TypedArray or DataView only), and tsc rejects it.
- **`String(buf)` and `buf + ""`** joined the bytes as numbers, since a
  Buffer is a typed array here. Node's `Buffer.prototype.toString` decodes.
- **`cluster.worker?.id`** failed with "no field 'id'".
  `emitOptionalMember` knew struct fields and class accessors only, so a
  handle whose members are dispatched could not follow a `?.`.
- **Node's `execFileSync` failure message** is `Command failed: <file>
  <args…>`. Here the arguments were missing.

## Decision

- **Removed:**
  - `process.execFileSync`, with `__kml_exec_file_sync` and
    `execSyncForkIR`;
  - `process.readLineSync`, with `__kml_read_line_sync`,
    `stdinGlobalName` and the Windows shim's `__kml_win_stdin`;
  - `fs.readFileSyncBytes`;
  - `cluster.workerId`.

  Their examples and tests move to the Node forms:
  - `examples/process/exec_file_sync.ts` is deleted, since
    `spawn_sync.ts` already shows `child_process.execFileSync`.
  - The `process.execFileSync` tests become `child_process.execFileSync`
    tests, their expectations regenerated from Node.
- **`fs.readFileSync`**:
  - Without an encoding (or with `null`, or options with no `encoding`)
    it returns a `Buffer` of the file's exact bytes, from
    `__kml_fs_read_file_raw`. With one it returns a string.
  - A number argument is a file descriptor, read to its end by
    `__kml_fs_read_fd_all`. That function grows its buffer and retries
    `EINTR`. A read error throws Node's `<CODE>: <desc>, read`.
- **`execSync` / `execFileSync`** return a `Buffer` of stdout without an
  encoding (`encoding: 'buffer'` too), and a string with `'utf8'`.
  `execFileSync`'s failure message joins the file and its arguments.
- **`readdirSync`** sorts entries by name (`qsort` with `strcmp`), for
  names and Dirents alike.
- **`writeFileSync` / `appendFileSync`** given a bare `ArrayBuffer`
  throw Node's `TypeError` with `.code` `ERR_INVALID_ARG_TYPE`.
  `emitFFIThrowCoded` becomes the general `emitThrowCoded`.
- **ToString of a Buffer** decodes it as UTF-8.
- **`cluster.worker`**: in a forked worker, a Worker handle with this
  process's id and pid; in the primary, `undefined`.
- **`emitOptionalMember`** handles a member with no struct field by binding
  the checked object to a temporary and emitting the plain member access on
  it in the non-null branch. It works for any dispatched handle member.

## Implementation notes

- `readFileHasEncoding` and `cpSyncHasEncoding` read the options
  statically, so `inferExprType` and emission agree on Buffer versus
  string.
- Tests that printed an encoding-less `readFileSync` or `execSync` result
  as text now pass `'utf8'`. Node prints `<Buffer …>` for those programs,
  and tsc rejects `.trim()` on a Buffer.
- `TestE2EFsWriteFileSyncArrayBufferThrows` runs under `-compat=js`, since
  tsc rejects the call.
- `apps/explorer` reads images with `readFileSync(path).toString("base64")`.
  `apps/klaintop` imports `execFileSync` from `child_process`.

## Side effects discovered

All four are BACKLOG items:

- `spawnSync`'s `stdout`/`stderr`/`output` are still strings, not
  Buffers. That needs a different result-record layout.
- Async `fs.readFile` without an encoding still delivers a string.
- `cluster.worker` in a worker exposes `.id` only (its `.process` and
  messaging are the global `process`).
- Node's deprecation warnings (DEP0147 for `rmdirSync` recursive) are not
  emitted.
