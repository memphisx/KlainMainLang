# ADR-01594: The node suite's common/dns harness

- **Date**: 2026-10-11

## Context

Node's DNS tests answer the resolver from a local UDP server built with
`test/common/dns.js` (`parseDNSPacket`/`writeDNSPacket`). The node-suite
runner had no such module, so those tests compile-failed on the missing
import. That hid the resolver's own differences
([ADR-01587](ADR-01587.md)).

## Investigation

`common/dns.js` is untyped and writes its packets through typed-array
views that are byte-swapped on a little-endian host.

## Decision

`tools/conformance/node-shim/dns.ts` is a typed port with the same
exports, writing byte-identical packets. It keeps the original's quirks:
- the record-data length read from the TTL's offset;
- the TXT length that counts characters, not bytes.

The runner embeds it, writes it as `common/dns.ts` beside the other
shims, and maps both `require('../common/dns')` forms (whole module and
destructured) onto imports.

## Verification

The Node probe that answers every record type from the shim's packets
gives byte-identical results under Node 26.10 and this compiler.
