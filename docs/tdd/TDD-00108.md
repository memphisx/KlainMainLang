# TDD-00108: `fs.createReadStream` / `fs.createWriteStream`

- **Status**: Implemented
- **Date**: 2026-08-24

## Context

`fs` has sync + async (callback/Promise) whole-file I/O (TDD-00107), but no
streaming file access — `fs.createReadStream`/`createWriteStream`, the last item
on [FILE-SYSTEM.md](../status/FILE-SYSTEM.md)'s async row and a natural
continuation of both the async-fs work and the Streams subsystem (TDD-00097).
Node returns a **Node `Readable`/`Writable`** from these (not a WHATWG stream), so
they slot directly onto this project's existing Node-stream machinery.

## Machinery reused (survey confirmed)

- A Node `Readable` is a `%kml.nodestream` (`runtime_node_stream.go`) wrapping a
  WHATWG `%kml.rstream` at field 0; `Readable.from(array)` builds it by
  `@__kml_rs_alloc` → loop `@__kml_rs_enqueue` → `@__kml_rs_close`, then
  `wrapWebReadable` (emit_node_stream.go). `.on('data'/'end'/'error'/'close')`
  and `.pipe()` already work over it.
- A Node `Writable` wraps a `%kml.wstream`; `new Writable({write, final})` stores
  a **write sink** thunk in wstream field 9 and a **final/close sink** in field
  10, driven by `.write()`/`.end()`.
- Whole-file I/O: `@__kml_fs_read_file_raw` (`fopen`/`fread`) and
  `@__kml_fs_write_file_bytes` (`fopen`/`fwrite`); `fopen`/`fread`/`fwrite`/
  `fclose`/`fseek`/`ftell` decls already emitted; `@__kml_fs_throw` turns an
  `errno` into a catchable `Error`.

**No `select()` event-loop integration** — regular files are always
`select()`-ready, so the readline/socket fd-fold pattern buys nothing here.

## Design

### `createReadStream(path[, options])` → Node `Readable`

Eager, chunked read at construction — consistent with the "blocking I/O under
the hood" posture the async-fs (TDD-00107) already documents:

1. `fopen(path, "rb")` (throw a catchable `Error` via `@__kml_fs_throw` on
   failure — matching `readFileSync`).
2. Loop: `fread` up to `highWaterMark` bytes (**default 64 KiB**) into a fresh
   `malloc`'d, NUL-terminated buffer, `@__kml_rs_enqueue` each non-empty chunk as
   a **`string`** (`streamChunkWords`: v0 = string ptr, v1 = 0), until `fread`
   returns 0.
3. `fclose`, then `@__kml_rs_close` the rstream.
4. `wrapWebReadable` → return `NodeReadableType(string)`.

This is `emitReadableStreamFrom`'s enqueue-then-close shape with `fread` chunks
instead of array elements — a new runtime helper `@__kml_fs_read_stream(path,
rstream, hwm)` that does the fopen/loop/fclose against an already-alloc'd rstream.

**Chunk type — string, not Buffer.** A Node Readable/Writable has a *single*
chunk type (`.write`/`.pipe` coerce to it), so the stream can't accept both a
string and bytes. This project's `fs` is already text-first (`readFileSync`
returns a string), and string chunks make `createReadStream(a).pipe(create-
WriteStream(b))` and `ws.write("text")` both ergonomic — so V1 delivers/accepts
**string** chunks. This inherits `readFileSync`'s text caveat (an embedded NUL
truncates a chunk); binary (`Uint8Array`) streaming is a follow-on.

**`options`**: an optional object literal. V1 honors `{ highWaterMark: N }` (a
compile-time integer) for the chunk size. `encoding`/`start`/`end`/`fd` and any
runtime-variable option are a clean compile error.

### `createWriteStream(path[, options])` → Node `Writable`

1. `fopen(path, "wb")` (or `"ab"` for `{ flags: "a" }`) once at construction,
   store the `FILE*` in the stream.
2. Install a **runtime** write sink (wstream field 9) that `fwrite`s each chunk's
   bytes to the stored `FILE*` (a string chunk uses `strlen`, a `Uint8Array`/
   `ArrayBuffer` its length), and a **final sink** (field 10) that `fclose`s it —
   mirroring the Transform sink wiring, but a runtime thunk rather than a user JS
   callback.
3. `.write(chunk)`/`.end([chunk])` already drive those sinks and fire
   `'finish'`/`'close'`/`'drain'`.
4. Return `NodeWritableType(string)` — the write sink `fwrite`s `strlen(chunk)`
   bytes (same string chunk type as the read side, so a pipe round-trips).

### Consumption — for-await gap

`.on('data')`/`.on('end')`/`.pipe(dest)` work today over a Node Readable. But
`for await (const chunk of readable)` currently supports only a WHATWG
`ReadableStream`/reader (`emit_stmts.go`), **not** a Node `Readable`. Since
`for await` over a file stream is idiomatic, wire it: add an `IsNodeReadable`
branch that unwraps the inner rstream (field 0) and reuses `emitForAwaitOfStream`
— a small, self-contained addition that also benefits `Readable.from` and every
other Node Readable.

## Scope / exclusions (V1)

- Eager read-to-EOF (not a lazy pull) — a huge file is fully read into per-chunk
  buffers at construction; incremental lazy reading is a follow-on.
- No `start`/`end` byte ranges, no `fd:` option, no `autoClose`/`emitClose`
  tuning; `createWriteStream` supports `flags: "w"|"a"` only.
- `options` must be an object literal with compile-time-constant values (the same
  static-args posture as `zlib`'s `{ level }`).

| Dependency | Status |

## Verification plan

E2E over a temp dir: write a file with `createWriteStream` (`.write`×N + `.end`),
read it back with `createReadStream` via (a) `.on('data')`+`.on('end')` and (b)
`for await`; a round-trip pipe (`createReadStream(a).pipe(createWriteStream(b))`);
`{ encoding: "utf8" }` string chunks; a missing-file open error caught in
`try`/`catch`; `{ flags: "a" }` append. Example under `examples/fs_streams/`.
`make examples` + `make conformance` at the end.
