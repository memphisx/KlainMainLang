# ADR-00657: Per-process scratch isolation for the conformance runner

- **Date**: 2026-09-03

## Context

The Test262/Node/TS conformance runner gives each worker goroutine a fixed
scratch module path derived only from its worker id — `.conformance-out/w{id}.ll`
(and the matching `.bin` / embedded-C files). Within one invocation that is
safe (ids are unique and a worker compiles sequentially). Across **two
invocations sharing the default workdir**, it is not: an overlapping run — or a
stale run that outlived its parent — writes the same `w{id}.ll` while the first
run's clang is mid-parse, handing clang a half-overwritten module. The result is
a **spurious, non-reproducible `CLANG_ERROR`**.

This was the mechanism behind an apparent (and alarming) Test262 pass-count
"regression": two full runs at different times, with other category runs racing
against the same `.conformance-out`, diverged by ~190 files even though the
compiler itself is deterministic (verified: identical IR over 2000 repeated
in-process compiles of the same input, and 0 IR-hash differences compiling a
whole category twice). The number moved; nothing in the compiler had changed.

## Investigation

`runOne` (`tools/conformance/main.go`) builds `llFile`/`binFile` as
`filepath.Join(workDir, fmt.Sprintf("w%d.ll", workerID))`. `workDir` defaults to
`.conformance-out` and is shared by every process that uses the default. Two
processes with the same default therefore contend on the same per-id files.
Confirmed by running two default-workdir category runs concurrently: their pass
sets diverged. Reason strings for the corrupted files were `CLANG_ERROR` with a
`.conformance-out/w{id}.ll:line:col:` prefix — a real clang parse error against
a corrupted module, not a codegen bug.

## Decision

When the **default** workdir is in effect, place this run's scratch files in a
per-process subdirectory `.conformance-out/run-<pid>/`. Two invocations then
never share a `w{id}.ll`. An explicit `-workdir` is left exactly as given — the
caller owns isolation in that case. The subdirectory is not auto-deleted, so the
`.ll` files remain inspectable after a run (the same debugging affordance the
flat layout gave).

Because the scratch path now carries a per-pid segment, a clang error's
`…/w{id}.ll:line:col:` prefix would otherwise fragment the reason histogram
(one bucket per pid). `normalizeReason` now strips that prefix
(`reScratchPrefix`), so `CLANG_ERROR` reasons bucket by the clang *message* —
which also cleans up the pre-existing case where the flat relative path was left
in the reason and had to be stripped by hand for the blocked-by histogram.

## Implementation notes

- `main.go`: after `flag.Parse`, `if *workDir == ".conformance-out" { *workDir =
  filepath.Join(*workDir, "run-<pid>") }`.
- `main.go`: `reScratchPrefix = ^\S*w\d+\.ll:\d+:\d+:\s*`, applied first in
  `normalizeReason`.
- No change to the report path (`-out`) or to any suite's own scratch shims —
  those already sit under `workDir` and inherit the isolation.

## Side effects discovered

Two noise sources remain independent of this fix and are not addressed here: a
subset of Test262 runtime tests are genuinely flaky under parallel load
(`RUNTIME_NONZERO_EXIT` timing), and `-compat=js` regresses a few
strict-passing assignment cases (surfaced by the new two-lane report,
ADR-00656). Both are tracked as follow-ups.

## Verification

- Two **concurrent** default-workdir runs of `built-ins/Array/prototype/findIndex`:
  identical pass sets (0 diff), each in its own `run-<pid>/` subdir — the
  collision is gone.
- `CLANG_ERROR` reasons now carry no `w{id}.ll` path (verified on
  `built-ins/DataView`).
- `go test ./tools/conformance/` green. macOS (Apple Silicon).
