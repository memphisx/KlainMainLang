# ADR-02051: Promise statics take their `this`; a subclass is a Promise through `any`

- **Date**: 2026-11-22

## Context

- `Promise.withResolvers.call(86)`, `Promise.resolve.call(86, x)` and
  `Promise.reject.call(null, r)` threw nothing and made a plain promise; V8
  throws (`… called on non-object`) and, given a constructor `C`, makes
  `C`'s promise. The combinators already did this, but not when the static
  was read through `as any` (`(Promise.all as any).call(86, [])`).
- An instance of a class extending Promise, held in `any`, answered
  `instanceof Promise` false: the check knew only the plain promise
  wrapper's header.

## Decision

- `Promise.resolve`, `Promise.reject` and `Promise.withResolvers` called
  with a receiver other than `Promise` run their library forms
  (`lib/node/internal_promise_combine.ts`): the non-object TypeError, then
  `NewPromiseCapability(C)`. `PromiseResolve` returns the value itself when
  it is a promise whose `constructor` is `C`. The receiver match sees
  through `as any`.
- `instanceof Promise` on a value held in `any` also accepts the class tag
  of every class extending Promise.

## Consequences

- `TestE2EPromiseStaticsCallOn` compares these forms with Node.
