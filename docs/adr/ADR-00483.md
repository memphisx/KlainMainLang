# ADR-00483: Node stream destroy() and setEncoding()

- **Relations**: Extends [ADR-00449](ADR-00449.md); clears part of the streams "No `.read()`/`.unshift()`/`.destroy()`/`.setEncoding()`" caveat
- **Date**: 2026-08-29

## Context

The Node-gap caveat list and `docs/status`'s streams row both carried
`.destroy()`/`.setEncoding()` as missing surface — common enough that the
oracle's `test-fs-read-stream-resume.js` was blocked on them.

## Decision

- **`destroy([error])`** tears the stream down: the readable side closes
  its source queue, the writable side its sink (whose existing
  closed-promise reaction emits 'finish'/'close'). A **non-flowing**
  readable has no flow loop to emit 'close', so destroy queues a guarded
  microtask (`__kml_ns_destroy_close` — skips if flowing, where the flow
  loop's own drain already emits 'end'/'close'; double-fire checked by
  test). The optional error argument is evaluated and dropped —
  'error'-event re-emission isn't modeled (disclosed).
- **`setEncoding('utf8')`** is an accepted no-op — chunks are strings by
  default since ADR-00449; any other encoding is a clean rejection.

## Verification

Mac. `tests/streams_test.go` E2E (flowing destroy → data then exactly one
'close'; setEncoding no-op) and the example extension (non-flowing
destroy → 'close' fires) pass; full stream batch green. **Node oracle:
40 → 41 passed** (`test-fs-read-stream-resume.js`). TS oracle unchanged
(57.2%).
