# TDD-00257: A plain string's null and undefined

- **Status**: Implemented
- **Date**: 2026-10-17

## Context

A `string` slot is a pointer. Its only absent value is the null pointer, and it has to stand for two things:
- **undefined:** an out-of-range element (`f(a[5])`), an omitted argument, a child that never started (`spawnSync(...).stdout`);
- **null:** `null as any`, an Invalid Date's `toJSON()`.

The readers disagree about what it means:
- `typeof` says "object", for `toJSON`'s sake.
- `=== undefined` folds to false.
- Arrays print it as `undefined`.
- `console.log` of a field prints `null`.

So BACKLOG #20 is wrong one way and `toJSON` the other. Types that may hold both (`string | null | undefined`, ADR-01314) already have `nullRef`, a zeroed sentinel cell, for null. ADR-01686 gave arrays the same split.

## Design

**Recommended: three states for every string pointer.** The null pointer is undefined, and `nullRef` is null, in every string slot, `T | null` included:
- **Producers of null give `nullRef`:** the null literal converted into a string, null unboxed from `any`, JSON null projected into a string, and natives documented to return null (`toJSON`, `getAttribute`-style lookups).
- **Undefined stays the null pointer:** out-of-range reads, omitted arguments, missing fields.
- **Readers test both:**
  - strict comparison: `=== null` is `nullRef`, `=== undefined` the null pointer;
  - loose comparison and every absence test (`??`, `?.`, `isAbsentPtr`): either;
  - `typeof`: "undefined" or "object";
  - output: inspect and `console.log` print `undefined` or `null`, `JSON.stringify` writes `null` for both in an array or omits the key, and `String()`, concatenation and templates give "undefined" or "null".
- **Boxing into `any`** gives the null box or the undefined box.
- `nullRef`'s cell has a string header and zero length, so a reader that does not check yet sees `""` instead of faulting.

**Rejected: deciding from the static type.** `T | null` would read its null pointer as null and `string` as undefined. That is what the readers half-do today. It cannot represent a `string` that holds null (`toJSON`, `any`), or a `T | null` that holds undefined from an out-of-range read.

### Stages

1. **Producers.** The null literal, `any` and JSON unboxing, and the native returns produce `nullRef` for every string target. The readers listed above check for it.
2. **`T | null`.** Readers stop treating a `T | null` null pointer as null. Its producers already moved in Stage 1.
3. **C runtime.** The C helpers that take a string and test for a null pointer (`__kml_str_*`, inspect, JSON) learn `nullRef` through the cell's exported address.
