# ADR-00740: child_process on Windows — verbatim shell command lines, `shell: true`, and `.bat`/`.cmd` refusal

- **Relations**: Implements the first rows of [TDD-00180](../tdd/TDD-00180.md) §3; extends [ADR-00719](ADR-00719.md) (the Win32 spawn layer), [ADR-00737](ADR-00737.md) (the same session's spawn hardening)
- **Date**: 2026-09-07

## Context

The `child_process` shell surface diverged from Node on Windows:

- `exec` / `execSync` routed the command through `quote_arg` like any argv element, so `cmd.exe` received an escaped string: `exec('echo "hi"')` printed `\hi\` instead of `"hi"`. Node hands the shell the command line **verbatim** (`cmd.exe /d /s /c "<command>"`).
- `spawn(cmd, { shell: true })` evaluated the option and discarded it — the command was spawned directly, so shell built-ins, pipelines and redirection silently failed.
- A `.bat`/`.cmd` spawned without a shell reached `CreateProcessW`, which hands such files to an implicit `cmd.exe` whose argument parsing turns quoted arguments into command injection (CVE-2024-27980). Node refuses with `EINVAL` unless the caller passes `shell: true`.
- `cmd.exe` was hardcoded; Node honours `%ComSpec%`.

## Decision

A `flags` argument is threaded to `__kml_win_spawn` (and its `windowsVerbatimArguments` bit 0). The IR-level `mode` on the async path becomes a bitmask: **bit 0 = buffered** (exec/execFile, unchanged meaning), **bit 1 = shell/verbatim**. The four internal read/dispatch sites that compared `mode == 0` / `mode != 0` now mask bit 0 first, so the new bit never disturbs streaming-vs-buffered. The sync path (`__kml_cp_spawn_sync`) gains a parallel `flags` parameter.

- **Verbatim**: when the shell/verbatim bit is set, `__kml_win_spawn` joins arguments with single spaces and no quoting, so `cmd.exe /d /s /c <command>` reaches the shell exactly as written. The POSIX side is unchanged (`/bin/sh -c` already received the command as one argv element).
- **`shell: true`** on `spawn` now routes the command through `emitShellArgv` (the same `cmd.exe /d /s /c` / `/bin/sh -c` construction `exec` uses), mode bit 1 set, streaming. A literal `shell: false`/absent keeps the direct spawn. A shell *path* or a dynamic value is a clean compile error, and `shell: true` combined with an args array is rejected (Node's array-join into the command line is not implemented yet — a rejection beats a silently mis-quoted command).
- **`.bat`/`.cmd` without a shell**: `__kml_win_spawn` refuses a command whose program ends in `.bat`/`.cmd` when the verbatim bit is clear, setting `EINVAL` and returning through the existing failed-spawn path (exit 127); with `shell: true` it runs normally through `cmd.exe`.
- **`%ComSpec%`** selects the shell on Windows (`cmd.exe` only as the fallback).

## Consequences

- `tests/childprocess_shell_test.go`: quote preservation through `exec`/`execSync` (per-host expectation — `cmd`'s `echo` keeps the quotes, `sh`'s strips them, both Node's), `spawn({shell:true})` running a command, and the `.bat`-without-shell refusal (Windows) with the same file running under `shell: true`.
- The full `child_process`/exec/spawn/fork/cluster suite passes on Windows 11 x86-64 and Linux x86-64 (Docker).
- Still open from §3 (not in this change): spawn-failure firing `'error'` rather than `'exit' 127`, exit-code width (`& 0xff` vs Node's full 32-bit), `execSync` throwing on non-zero status, and the remaining spawn options (`env`, `detached`, `windowsHide`, `timeout`/`killSignal`/`maxBuffer`, `stdio` beyond `'pipe'`), plus the `shell: true` + args-array join.
