# ADR-00607: `typeof` of a value-receiver method reference

- **Relations**: Extends [ADR-00282](ADR-00282.md)/[ADR-00596](ADR-00596.md) (`typeof` of a namespace method); reuses [TDD-00030](../tdd/TDD-00030.md) accessor dispatch
- **Date**: 2026-09-01

## Context

`typeof` answered `"function"` for a *namespace* method (`typeof Math.max`,
`typeof Object.keys`), but a **value-receiver** method reference — `typeof c.m`
(class method), `typeof "hi".slice`, `typeof [1].push` — fell through to normal
inference, which types a member access as the `i64` default and so wrongly
answered `"number"`. A related gap: `typeof d.getterProp` inferred `"number"`
because a class getter's read type wasn't consulted.

## Decision

Two fixes:

1. **Value-method reference** (`typeofStaticAnswer`): after the namespace cases,
   consult the receiver's static type via `isValueMethodRef(objTy, prop)` —
   `"function"` when `prop` is a class instance method (`ClassInfo.MethodSigs`)
   or a known method of a built-in value type (curated `typeofStringMethods` /
   `typeofArrayMethods` sets). Conservative: an unrecognized name falls back to
   normal inference, so this only ever upgrades a wrong `"number"` to the right
   `"function"`, never the reverse. A class **accessor** is deliberately excluded
   — `typeof obj.accessor` is the accessed value's type, not `"function"`.

2. **Accessor read-type inference** (`inferExprType` member case): a class
   getter's read type is its return type — consult `classAccessorSigs` before
   `FieldIndex` (an accessor name is never a real field), mirroring the read path
   in `emit_exprs_member.go`. This makes `typeof d.getterProp` (and any other
   inference of a getter read) correct.

The built-in method sets are membership tests only, so they need not be
exhaustive to stay sound — an omitted name simply keeps the prior behavior.

## Verification

`TestE2ETypeofValueMethodRef` — class method / field / getter, string/array
method, and `.length` on both — matching Node v26. The typeof, class, object,
getter, and member-inference suites still pass. Built and verified on Mac
(Apple Silicon).
