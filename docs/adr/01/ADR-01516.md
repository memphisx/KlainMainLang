# ADR-01516: Unary `-` and `~` run ToNumber on any operand, in both lanes

- **Relations**: Extends ADR-00898, TDD-00230
- **Date**: 2026-10-09

## Context

tsc accepts unary `-` and `~` on a string, boolean or object operand
(`-"3"`, `~{}`), and JavaScript runs ToNumber on it first. The strict
lane rejected those operands, and `-true` emitted an `i1` subtraction.
Inference typed `~x` as `i64`, while emission produces a double
(`int32ToNumber`); a `const b = ~0` was inferred one way and emitted
another (shadow bucket 12, 74 rows).

## Decision

- `-x` on a non-number operand runs the same ToNumber as unary `+`
  (`emitUnaryPlus`), then negates the double, in both lanes. `~x` does the
  same before ToInt32.
- Inference types `~x` as a double (a bigint stays a bigint) and `-x` on
  a non-number operand as a double.
