# ADR-00394: Scrub absolute paths from conformance report failure reasons

- **Relations**: Extends the conformance runner (TDD-00121)
- **Date**: 2026-08-27

## Context

The Node `test/parallel` oracle (and the Test262 report) bucket each failure by
its normalized first-line reason. Parse-phase compile errors carry the
front-end's `<abspath>: line:col: message` prefix, where `<abspath>` is the
per-worker temp scratch file the corpus test was copied to. That leaked the
local machine's directory layout into the committed report and — worse for the
report's purpose — fragmented one logical blocker into many buckets, one per
unique scratch path, so the "top blockers" histogram undercounted real blockers.

## Decision

`normalizeReason` (shared by both suites) strips the leading
`<abspath>: line:col: ` file-position prefix, then collapses any remaining
absolute path elsewhere in the message to `<path>`, before the existing
position-prefix and quoted-token normalization.

## Consequences

Reasons now bucket by message alone. The immediate effect on the Node report was
large: with per-path fragmentation gone, `only simple function calls are
supported` (282 files) surfaced as the true top blocker, and the stream-relevant
buckets consolidated cleanly. No path from any machine's filesystem appears in
the committed report. The Test262 report's `Example` column (a corpus-relative
path, intentional and useful) is unaffected — only the reason text is scrubbed.
