# ADR-01912: recursive object aliases; self-references at run time

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-21

## Context

- The checker typed an alias's self-reference (`type Cons = { tail: Cons | null; head: number }`) as unanswered, so a mistyped nested member was accepted and the oracle disagreed with codegen on every use.
- Codegen resolves a named shape's self-reference to the placeholder registered before its fields, re-resolved on access. Three walkers read the placeholder directly: a nested object literal against it failed to compile (`kids: [{ kids: [], v: "b" }]` inside `Tree`), and `JSON.stringify` and `console.log` rendered the nested value as `{}` and `[Object]`, for interfaces as well as aliases.

## Decision

- The checker types a module-level, non-generic alias of a literal that names itself as one object type registered before its members, as an interface is, printed by the alias's name. The type-parameter walkers stop at it, since it names none.
- A literal built against a placeholder uses the live layout. `JSON.stringify` and inspect box a placeholder-typed value with the live layout and use the run-time walker, which follows the recursion to any depth; the static walker would unfold it without end.
- The oracle cuts the same self-reference codegen does, including inside the alias's own declaration.

## Consequences

- Recursive shapes compile, print and serialize as in Node; tsc's nested-member errors are reported.
