# ADR-01818: Species dispatch in shared library code names no program class

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- A builtin library unit compiles to the same IR in every program, so its object is built once and shared.
- An Array method call in library code whose result may be a species (`slice`, `map`, …) checked, inline, whether the receiver's class overrides the method. That check named the program's own classes extending Array. A program declaring such a class changed the IR of `node:path`, `node:events` and ten other units.

## Decision

- In program-independent code the inline check is skipped. The program's species dispatcher, which already picks the class, first returns the method's own result for an instance whose class overrides the method.
- The dispatcher's name hashes the method too, since the overrides differ per method.

## Consequences

- Library units are again identical across programs (`TestLibUnitsSameAcrossPrograms`).
- `TestE2EArrayRefSharedBufferFreePolicyASan` now links the libraries the program needs, as every other build helper in the tests does. A string-method table in a library unit referenced pcre2 and the link failed.
