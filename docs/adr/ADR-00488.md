# ADR-00488: Date multi-argument setters; Symbol.for registry

- **Relations**: Extends TDD-00044 (symbols) and the Date model
- **Date**: 2026-08-29

## Context

Two caveats: Date setters supported only their single-argument form
(`setFullYear(y, m, d)` was a rejection), and there was no
`Symbol.for`/`Symbol.keyFor` registry.

## Decision

- **Date setters cascade** per JS: `setFullYear(y, m?, d?)`,
  `setMonth(m, d?)`, `setHours(h, m?, s?, ms?)`, `setMinutes(m, s?, ms?)`,
  `setSeconds(s, ms?)` — the existing decompose/override/recompose path
  simply takes its start slot from the setter and lets extra arguments
  continue along the settable-field chain. TDD-00071-era's
  multi-arg-rejected test becomes a positive test.
- **`Symbol.for(key)`** interns through a lazily-created global
  string-keyed registry map — one shared symbol pointer per key, so
  `Symbol.for("k") === Symbol.for("k")` while a loose `Symbol()` stays
  distinct; **`Symbol.keyFor(sym)`** scans the registry (key or `null`).
  Inference rows added for both.

## Verification

Mac. `tests/date_test.go` (cascade E2E, replacing the rejection test) and
`tests/type_features_test.go` (registry identity + keyFor + null) pass;
Date/Symbol batches green. Oracles: TS 57.2%, Node 42 (unchanged —
caveat clears).
