# ADR-01186: Windows test expectations follow Node on Windows; `-emit-llvm` takes any target

- **Relations**: `Extends ADR-01185`
- **Date**: 2026-09-28

## Context

The Windows CI lane of the restructure commit failed tests whose expected
output is what Node prints on macOS/Linux, not on Windows, plus a showcase
app that did not type-check. The failures could only be inspected from the
CI log: `--target` refused every cross-OS pair but macOS→Linux, even for
`-emit-llvm`, which links nothing.

## Investigation

- `path.join('a', 'b')` is `a\b` and `JSON.stringify(os.EOL)` is `"\r\n"` in
  Node on Windows; `fs.chmod(f, 0o600)` then `stat` reports `666` there
  (chmod toggles only the read-only attribute). The tests expected the POSIX
  values.
- The Windows branch of `TestE2EFileURLToPath` read `e.message` on an
  `unknown` catch variable, which tsc rejects (TS18046).
- `apps/todo` split `readFileSync(FILE)` — a Buffer, which has no `split` in
  Node either.
- A Windows-target module declared `_setmode` only when the *host* was
  Windows, so a cross-emitted module called it undeclared.
- `TestE2EGeneratorExpressionAsValueRejected` expected a compile error for a
  generator function passed where `() => void` is declared; tsc accepts it,
  and generator expressions are values since ADR-01182.

## Decision

- Tests compute the host's Node value (`nodeJoin`, `nodeEOLJSON`,
  `chmodMode600`); the FileURLToPath test casts its catch variable; the todo
  app reads its file as `utf8`; the rejection test is deleted.
- `-emit-llvm` accepts any `--target` (the refusal concerns linking).
- `_setmode` is declared whenever the target is Windows.

## Implementation notes

`tests/compiler_test.go`, `tests/type_features_test.go`,
`tests/fs_async_test.go`, `tests/node_core_modules_test.go`,
`tests/generators_test.go`, `tests/crosstarget_test.go` (the rejection is
checked on a real build; `TestCrossTargetEmitLLVMAnyOS`),
`apps/todo/store.ts`, `main.go`, `codegen/llvm/emitter.go`.

## Side effects discovered

None.

## Verification

Mac (Apple Silicon): the four touched tests pass; every app under `apps/`
builds; a program emitted for `x86_64-w64-mingw32` compiles with clang. The
Windows expectations are Node's documented Windows behavior; the Windows CI
lane runs them.
