# ADR-01562: Identifiers, member reads and calls take their type from the checker

- **Relations**: Extends ADR-01558, ADR-01560, ADR-01561, Implements TDD-00230
- **Date**: 2026-10-10

## Context

TDD-00230 P3.3 switches `inferExprType` to the checker for its three
largest expression kinds — `Identifier`, `MemberExpression` and
`CallExpression` — and deletes codegen's own inference for them. Before
this change the three kinds were switched only under an experiment toggle,
and a node the checker left unanswered still fell back to the old arms
(roughly 1,450 lines in `emit_exprs_types.go`).

## Investigation

A per-node tracer on the fallback showed the unanswered nodes are almost
all nodes codegen builds itself after checking: temporaries bound to
synthesized identifiers, rewritten calls (`processMemberRewrite`), lowered
method calls, namespace-mangled names, and chain copies (ADR-01561). The
checker never saw them, so it cannot answer them. Each one is built from
parts codegen has already typed: a temporary has a binding, and a rewritten
member read has a receiver whose representation is known.

The remaining in-program residue (iterator and generator results, stream
reads, collection iterators) was mapped in `codegenCallRepr` and by the
mapping rules of ADR-01558.

## Decision

The three kinds become settled (`settledExprKind`): a node the checker saw
takes the checker's type, with no fallback to codegen's inference. A node
the checker never saw is typed by `settledFallbackType`:

- an identifier from its binding (`identStorageType`);
- a member read or call from the dispatch `emitMember`/`emitCall` run on
  it (`structuralMemberType`, `structuralCallType` in
  `infer_structural.go`).

The former inference arms became those two functions. A first attempt
replaced them with a smaller reimplementation, and the full E2E run
rejected it: the calls codegen builds (`builtinIteratorCall`'s rewrite of
`arr.keys()`, `Array.from`'s intrinsic, a host subclass's forwarded method,
a lowered `@lower` target) need the whole dispatch mirror. Without it they
were typed `any` or `i64`, which gave invalid IR (a global array's header
stored as `ptr`) and wrong values (array indices printed as denormal
doubles).

The checker's answer is never second-guessed by that mirror. Both paths
end in the same refinements (`inferRefined`): union narrowing of a
property read, the presence the checker proves, and the primitive result
of an overloaded call.

The experiment toggle and the census tracing are removed, along with the
helpers no path reaches any more.

Two cases take emission's answer over the checker's, because the value
is read the way emission stores it:

- A name with a binding in scope (or a function declaration) reads its
  storage, so its type is the binding's, refined by flow
  (`identStorageType`). The checker reaches the binding through its
  initializer. Without this, a binding emitted as a box (`aWords` from
  `Object.groupBy`'s record) was typed as the checker's array.
- A method call on a value held boxed runs through the dynamic dispatch,
  so its type is that dispatch's result (`codegenCallRepr` defers to
  `structuralCallType`). A lib iterator helper's `toArray()` returns
  `any[]` even where the checker knows `number[]`.

The oracle's per-query memo is keyed on the node plus codegen's scope
identity, because inference pushes scopes for callback bodies and a name's
answer depends on its binding.

## Implementation notes

- `codegen/llvm/infer_structural.go` (new), `infer_memo.go`
  (`settledFallbackType`, `inferRefined`), `shadow_binder.go`
  (`oracleKey`), `emit_exprs_types.go` (arms moved out).
- The settled fallback has to go through `inferRefined`. An earlier
  version returned the fallback directly and skipped union narrowing, so
  `typeof existing.value === 'object' ? existing.value.slice() : …` in
  `lib/node/internal_http.ts` failed with "field access on non-object".

## Side effects discovered

- The shadow unit test asserts a `BinaryExpression` disagreement in place
  of a `CallExpression` one, since calls are no longer shadowed.

- `examples/objects/group_by.ts`, `examples/generators/iterator_helpers.ts`
  and `examples/function_expressions/call_apply.ts` failed the examples
  gate until the two rules above and ADR-01563 were in place.

## Verification

Linux (DeskMini kmlbox) full E2E run; Mac targeted runs: foreign class
argument, optional chain, deep method chain, null deref, HTTP/2
`allowHTTP1` and WebSocket suites; `checker`, `binder`, `ast` and
`codegen/...` unit packages.
