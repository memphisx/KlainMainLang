# ADR-01486: A computed-key object literal is a dynamic object

- **Relations**: Extends ADR-01484; Supersedes the representation in ADR-00066
- **Date**: 2026-10-09

## Context

An object literal with a computed key (`{ [k]: v }`) was a string-keyed
map (TDD-00012): its value type came from the first property only, a
spread beside the computed key was rejected, and BACKLOG 29 recorded that
its methods could not be called (`q[k]()`, `q.name()`: "unknown Map
method") and that it could not be held in `any`.

## Investigation

- A literal built with an `any` contextual type already becomes a dynamic
  object with computed keys, methods and spreads, matching Node.
- With ADR-01484 a dictionary type is that same object, so the map form
  no longer has a reader that needs it.

- examples/objects/computed_keys.ts called `obj.has()`/`obj.get()` on
  the literal, which only the map form had (Node: "obj.has is not a
  function").
- The same example showed a separate bug. In `for (const [k, v] of
  Object.entries(obj))` the body's `k` read the module-level `const k`:
  the module renamer bound a for-of's plain variable name but not the
  names a destructuring pattern binds. It also skipped a for-of pattern's
  defaults and the nested names of a `catch` pattern.

## Decision

- A computed-key literal is built as a dynamic object
  (`emitDynObjLiteral`). Its type is a dictionary of its values' type
  when every property is a plain value of one static type, else `any`.
  Either way it is the object itself.
- The module renamer binds every name a for-of pattern binds (nested
  patterns included), rewrites the pattern's defaults, and binds a
  `catch` pattern's nested names (`bindArrayPattern`,
  `bindObjectPattern`, `rewrite*PatternDefaults`). Parameters use the
  same helpers.
- The example uses `in` for membership.
- BACKLOG 29 is deleted. The four status caveats are removed: first-value
  inference, spread with a computed key, the declared-type form, and
  methods / `any`.
