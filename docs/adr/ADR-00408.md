# ADR-00408: Qualified constructor & base-class parsing — `new mod.Class(...)`, `extends mod.Class`

- **Relations**: Extends ADR-00406
- **Date**: 2026-08-27

## Context

The Node oracle's largest single compile-failure bucket (~142 files,
`expected (, got .`) was the parser's inability to parse `new` on a member
expression at all: `new stream.Readable(...)`, `new http.ClientRequest(...)`,
`new assert.CallTracker()` — the standard shape for any code using a
namespace/default import. `parseNew` accepted only `new Ident(...)`.

## Investigation

`parser/parser_literals.go:parseNew` peeks one IDENT and dispatches a
~40-case switch of builtin constructor names, each `parseNew*Body` consuming
the name token itself; anything else goes to `parseNewGenericBody` (user
classes). A full member-expression callee in the AST would require every
body function and codegen's `NewExpression` handling to learn a qualifier —
but for this corpus the qualifier carries no information codegen needs: the
supported constructors are globally unique names (`Readable`, `EventEmitter`,
`URL`, …) regardless of which module binding they're reached through.

## Decision

In `parseNew`, when the lookahead is `IDENT . IDENT`, consume qualifier
segments (looping, so `a.b.C` works) and dispatch the existing switch on the
final name. `new stream.Readable(opts)` therefore parses and emits exactly
like `new Readable(opts)`; a final name no case matches falls through to
`parseNewGenericBody` and gets codegen's precise per-class rejection
(`unknown class 'ClientRequest'`) instead of a parse error.

The same treatment applies to a class heritage clause: `class X extends
events.EventEmitter` / `extends stream.Readable<T>`
(`parser/parser_classes.go`) consumes the qualifier segments and keeps the
final name as the base — the corpus's second parse bucket (~26 files,
`expected {, got .`) and the standard shape for extending an imported base.

Deliberate looseness, documented rather than fixed: the qualifier is not
validated against the module the name actually came from, so `new
MyNamespace.Error(...)` would dispatch the builtin `Error` body. No corpus or
example code hits this; revisit if a real collision appears.

## Implementation notes

`parser/parser_literals.go` only — a lookahead loop (`peekNth`) ahead of the
existing switch. `new Foo().bar()` is unaffected (lookahead after `Foo` is
`(`, not `.`).

## Side effects discovered

- With the parse error gone, those files now fail on their real next blocker,
  which reshaped the oracle histogram into module-level gaps
  (`MODULE_NOT_IMPLEMENTED: http2/vm/https/...`) — the intended effect.

## Verification

New E2E `TestE2ENodeStreamQualifiedNewReadable` (qualified options-form
Readable, data/end events) passes; `new http.ClientRequest({})` rejects
cleanly; new example `examples/streams/qualified_new.ts` compiled and run;
full `make test-par` green before this change and re-run after (Mac).
