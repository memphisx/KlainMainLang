# ADR-00367: TypeScript acceptance oracle — front-end accept/reject vs baselines

- **Relations**: `Implements TDD-00121`
- **Date**: 2026-08-25

## Context

TDD-00082 concluded the TypeScript-conformance track was terminal: "a type-checker
-output corpus with no expected-stdout oracle, so it cannot be run against a
compile-and-run pipeline." That holds only for the compile-and-run framing.
Microsoft's `tests/cases/{compiler,conformance}` corpus ships a baseline per case
in `tests/baselines/reference/`; a case that TypeScript rejects has a companion
`*.errors.txt`, one it accepts has none. That is an **accept/reject oracle** for a
*front-end* pipeline (parse + resolve + codegen, no clang, no run): does this
compiler reject what TypeScript rejects and accept what it accepts? TDD-00121
Track C reverses the terminal conclusion on that basis and implements the track;
this is the first TypeScript-language conformance number the project has had.

## Investigation

Pinned sparse checkout of `microsoft/TypeScript@v5.6.3` (`tests/cases/{compiler,
conformance}` + `tests/baselines/reference/*.errors.txt`, blobless): 11,874 `.ts`
cases, 6,131 error baselines. TypeScript flattens baseline names to the case
basename, so the oracle is a basename→has-errors-baseline map, built once by
scanning the reference dir.

The compiler already exposes exactly the needed seam: `resolver.ResolveProgram` +
`llvm.EmitProgram` return an error on any parse/resolve/codegen rejection without
running clang, so "did the front-end accept?" is `err == nil`. Multi-file cases
(`// @filename:` directives) are the main classification hazard — they describe a
module graph a single-entry run can't reproduce — so they are binned out of scope
for V1 rather than counted as disagreements.

## Decision

- `fetch.sh` gains the pinned sparse TS checkout into gitignored `.ts-tests/`,
  tag-pinned (TypeScript is versioned; a tag is a stable denominator).
- `tools/conformance/ts.go`: a `-suite=ts` runner. Per single-file case, write it
  to a scratch entry, run the front-end, and classify against the baseline:
  - baseline present + we reject ⇒ **match-reject**;
  - baseline absent + we accept ⇒ **match-accept**;
  - baseline present + we accept ⇒ **false-accept** (a soundness gap — we let
    through what TypeScript catches);
  - baseline absent + we reject ⇒ **false-reject** (usually a scope gap — a valid
    -TS feature this narrow subset doesn't implement).
  - multi-file cases ⇒ `SKIP_OUT_OF_SCOPE`.
- Headline is **accept/reject agreement** = (match-accept + match-reject) /
  classified. V1 measures the verdict only, not error-message text or position —
  recorded as the explicit V1 scoping.
- Report `docs/testing/CONFORMANCE-RESULTS-TS.md`: overall, per-group, and an
  enumerated (bounded) list of false-accepts — the actionable soundness worklist.

## Implementation notes

The false-reject bucket dominates the disagreements by construction: TypeScript
accepts the full language, this compiler targets a deliberately narrow typed
subset, so most valid-TS features it doesn't implement land here. That is expected
and is the front-end coverage frontier, not a defect count. The false-accept
bucket is the interesting one: it names cases this compiler should have rejected
(some are TypeScript rejecting for type-system reasons outside this compiler's
model, so not every entry is a bug — the report says so).

Front-end-only means no per-file subprocess, so a pathological case can't be
killed by a subprocess timeout; the panic-recover in `frontEnd` bounds crashes,
and no infinite-loop case was hit across the 11,834 processed.

## Side effects discovered

The 375 false-accepts are a standing worklist of soundness gaps (enumerated in the
report). Not triaged here — surfacing them is the point of the track; individual
fixes are separate work.

## Verification

`go vet` + `go build ./...` clean. `-suite=ts` over the full corpus classified
9,256 cases (2,578 multi-file skipped): **4,754 / 9,256 agree (51.4%)** — 750
match-accept, 4,004 match-reject, 4,127 false-reject, 375 false-accept. Report
written and spot-checked (a co-rejected case and a co-accepted case classify
correctly). Verified on macOS (arm64).
