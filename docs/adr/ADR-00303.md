# ADR-00303: EventEmitter event maps + `instanceof` for built-in emitters/streams

- **Relations**: Implements [TDD-00097](../tdd/TDD-00097.md) Stage 7; extends [TDD-00023](../tdd/TDD-00023.md)/[ADR-00089](ADR-00089.md) (EventEmitter), [ADR-00162](ADR-00162.md) (built-in `instanceof`)
- **Date**: 2026-08-22

## Context

TDD-00097 Stage 7: the EventEmitter capabilities Node's `stream` module
(Stage 8) needs. The design diverges from the TDD's original sketch
("variadic emit, subclass override of on/emit") after working out what
Stage 8 actually consumes: Node streams' events are *heterogeneous but
fixed-shape* — `data` carries a chunk, `error` an Error, `end`/`finish`/
`close` carry nothing — which a **typed event map** models exactly, without
untyped variadics; and overriding `on`/`emit` isn't needed when the stream
classes themselves are compiler-provided. Recorded here per the house rule:
the TDD's design text stays as written, the divergence lives in the ADR.

## Decision

- **Event maps**: `EventEmitter<{ data: string; count: number; end: void;
  error: Error }>` — a plain structural object-literal type argument makes
  the emitter *map-typed*: `.on`/`.once`/`.off`/`.removeListener`/`.emit`
  require a string-literal event name that is one of the map's fields, and
  that field's type is that event's payload. A `void` field is a
  payload-less event: zero-argument listeners, one-argument `emit(event)`.
  An undeclared event name, or a non-literal name on a map-typed emitter,
  is a compile error. Works identically through
  `class X extends EventEmitter<{...}>` (the payload type already threads
  through `EventEmitterPayload`).
- **Compatibility**: a scalar/`Error`/class/tuple type argument keeps the
  original single-`T`-for-every-event semantics unchanged (map mode is
  gated on *plain* object-literal types only — `EventEmitter<Error>`'s
  rethrow-exact-Error behavior was the regression the gate caught). The
  `'error'`-unlistened-throws special case works per event type: an `Error`
  payload rethrows exactly, a `void` `error` event throws a generic Error.
- **`instanceof`**: `builtinInstanceofTypes` gains `EventEmitter` (true for
  emitters *and* classes extending one, via `HasEventEmitter`),
  `ReadableStream`, `WritableStream`, and `TransformStream` — compile-time
  constants like the existing five (ADR-00162's reasoning: static typing
  already answers the question; there is no prototype trickery to disagree).

## Implementation notes

`emit_eventemitter.go`: a `resolveEventPayload` helper (map-vs-single-T
selection + per-event type), listener validation generalized to zero-arg,
`emit` generalized to one-or-two arguments with the per-event payload
threaded into the callback invocation and the `'error'` throw path.
`emit_classes.go`: four `builtinInstanceofTypes` entries. The
`TestE2EEventEmitterInstanceofRejected` test asserting the old limitation
became `...InstanceofWorks`.

## Side effects discovered

- An object-literal payload type now means an event map — the hypothetical
  old use of `EventEmitter<{x: number}>` as "every event carries this
  object" changes meaning (no in-tree usage existed; noted as the one
  deliberate semantic change).
- Fully-variadic `emit(event, a, b, ...)` (more than one payload argument)
  remains unsupported — nothing in Stage 8's consumer needs it.

## Verification

`tests/eventemitter_test.go`: event-map on/emit across string/number/void/
Error events, the `extends` form, undeclared-event compile rejection,
`instanceof` positives/negatives (subclass true, `Map` false), plus stream
`instanceof`; the full pre-existing EventEmitter suite (including
`EventEmitter<Error>` exact-rethrow) green. `examples/eventemitter/
event_map.ts`. Full `go test ./...` + examples + conformance in the
delivery run (Mac).
