# ADR-00989: cluster workers combine with additional HTTP servers

- **Relations**: `Implements TDD-00219`, `Extends ADR-00514`
- **Date**: 2026-09-17

## Context

The last `http.createServer` "edges" item: a `klain:http`
`http.listen(port, handler, { workers: N })` cluster could not coexist with an
additional `http.createServer(...).listen(...)` in one program — a clean
compile-time rejection ("http.listen may only be called once per program"). The
two used different reactor-entry models: `http.listen` **forks then runs the
event loop inline** (blocking), while `createServer().listen()` registers a
listener and **returns**, the Pass-3 tail driving the shared non-blocking
`select()` loop over the primary scalar (`@__kml_listen_fd`) plus the
extra-listener table (TDD-00191).

## Investigation

- `emitFsListen` (emit_http.go) — `http.listen` — binds, `cluster_fork(N)`,
  builds the primary dispatcher, stores `@__kml_listen_fd`, then
  `__kml_event_loop_run()` inline.
- `emitHTTPServerListen` — `createServer().listen()` — already calls
  `cluster_fork(0)` (a no-op fork), registers primary-or-extra, returns; the
  tail (`emitter.go`, gated on `usedHTTPListen`) runs `__kml_event_loop_run()`.
- The block was the shared `httpListenCallSeen` flag: the first `createServer`
  claims the primary and sets it, so a following `http.listen` trips the
  "only once" guard. Even past that, both writing `@__kml_listen_fd` would
  collide.
- `__kml_http_cluster_fork` forks after `mmap`ing the shared close-flag page;
  every process (parent + workers) then runs identically. `buildHTTPDispatcher`
  already accepts a `sfx`/`isPrimary=false`, so a `klain:http` handler-model
  server can be built as an **extra** listener.

## Decision

Unify on the non-blocking reactor (TDD-00219 option 1), by emit order rather
than a pre-scan. When `http.listen(port, handler, { workers: N })` is emitted
**and at least one `http.createServer` already exists** (`httpServerCount > 0`,
"combo mode"), `http.listen`:

1. builds a **suffixed, non-primary** dispatcher for its handler-returns
   (`{status, body}`) model;
2. binds its fd and registers it as an **extra listener**
   (`__kml_http_register_extra_listener`), leaving the `createServer` that ran
   first as the primary;
3. performs the cluster `fork(N)` — now after every prior listener is bound, so
   each worker inherits the whole listener set (primary scalar + extra table,
   all fork-shared);
4. sets `usedHTTPListen` and **returns** (no inline loop) — the Pass-3 tail runs
   the one shared loop in every worker.

Standalone `http.listen` (no `createServer` in the program) is unchanged: inline
`fork` + primary + blocking loop, preserving its documented block-until-drain
semantics (and any code after it still runs only after the loop exits). Two
`http.listen` calls remain a clean rejection (new `httpFsListenSeen` flag,
distinct from the createServer-shared `httpListenCallSeen`). The
`{ workers }`-with-`Worker`-threads rejection stays (fork + threads is a genuine
hazard, TDD-00098).

## Implementation notes

- Combo detection is `httpServerCount > 0` at the `http.listen` site, so the
  `createServer`(s) must be declared first (their `.listen()` before
  `http.listen`). That is the natural order and the only one that ever ran
  (code after the old blocking `http.listen` ran only post-drain).
- The fork stays a `fork()` of a single-threaded process (no `Worker` threads,
  guarded), so the extra-listener table, TLS `SSL_CTX*`, and h2 vtables are
  plain inherited memory — each worker `accept()`s and does its own
  handshake/session per connection.

## Side effects discovered

`emitHTTP2ServerDecls` (http2.go) had no idempotency guard — a combo program
now emits the h2 session-ABI declares from both the createServer and the
`http.listen` sites, so it was made once-only (`usedHTTP2ServerDecls`). Harmless
before because only one server ever emitted them.

## Verification

macOS arm64 (M4). New E2E test `TestE2EHTTPClusterCombinedWithCreateServer`
(tests/http_test.go): a Node `createServer` + a `{ workers: 3 }` `http.listen`
in one program — the createServer port answers, and 40 **concurrent** requests
to the cluster port are served by more than one worker PID (sequential requests
would race to one worker, so concurrency is required to prove distribution).
Example `examples/http/cluster_plus_extra_server.ts` (both ports verified with
curl). The existing multi-server (`TestE2EHTTPMultipleServers*`), standalone
cluster (`TestE2EHTTPListenClustering*`), basic `http.listen`, and h2 suites
pass unchanged. `go build`/`vet` clean; `make examples`; `make status` +
`make reference-check`.
