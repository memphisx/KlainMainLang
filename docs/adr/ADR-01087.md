# ADR-01087: The event loop takes another turn for work its keep-alive check produced

- **Relations**: `Extends ADR-01051, TDD-00223`
- **Date**: 2026-09-23

## Context

`make examples` on Linux failed `examples/fetch/fetch.ts`, `fetch_init.ts` and `fetch_request_headers.ts` intermittently, in different memory modes on different runs. Run on their own they passed.

A repeat run in Docker (15 iterations of each, in two modes, plus 8 in parallel) caught 3 failures in 90 sequential runs and 1 in 8 parallel ones. Each printed `Warning: Detected unsettled top-level await` and exited 13, after the response had already been received.

## Investigation

- `__kml_event_loop_run` (`codegen/llvm/runtime_http.go`) decides whether to take another turn from a list of keep-alive conditions. The last one is `__kml_curl_inflight()`.
- That function calls `curl_multi_perform` and then `__kml_curl_drain_messages`, which settles the promise of every transfer libcurl reports finished.
- So when a transfer completes *during* the check, the function returns 0 in flight while the promise's continuation sits queued: a microtask, or the parked module task made runnable.
- A parked task holds nothing open by itself (ADR-01051, faithful to Node). The fetch socket was the only thing keeping the loop alive, so the loop went idle with the continuation still queued. `main` then found the top-level-await promise pending and exited 13.
- A timing window of this size explains the rate, and why load and memory mode only shift it.

## Decision

After `__kml_curl_inflight()`, also treat `__kml_microtasks_pending()` or `__kml_task_resumable()` as work. The loop then takes one more turn, whose `dowork` pass already refuses to block when either is true (the zero-timeout path), and runs the continuation. Both predicates are always defined, as stubs when a program has no tasks or microtasks.

## Implementation notes

`codegen/llvm/runtime_http.go`, the keep-alive block just before `br … %dowork, %loopidle`. This is the one event loop every platform uses.

## Side effects discovered

None.

## Verification

- Linux x86-64 (Docker):
  - `fetch_init` + `fetch_request_headers`: 0 failures in 200 sequential runs and in 24 parallel ones, against about 3 in 90 before.
  - `tests/event_loop_wait_test.go` `TestE2ETopLevelAwaitFetchCompletingInKeepAliveCheck` (150 sequential top-level awaited fetches) passes 5/5 with the fix, and fails with the fix disabled in-container.
- Windows x64 and Linux: the full suites and `make examples` were re-run after this change.
