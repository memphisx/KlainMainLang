# ADR-01124: Property and assignment-target type errors; the checker sees renamed types

- **Relations**: `Implements TDD-00230` (Phase 2, P2.7); `Extends ADR-01122`, `ADR-01123`
- **Date**: 2026-09-24

## Context

[ADR-01122](ADR-01122.md) and [ADR-01123](ADR-01123.md) made the strict lane
reject tsc's assignability, argument and operator errors. TypeScript's next
most frequent errors in its own baselines are about properties:
- a property that does not exist (TS2339, with its suggestion forms TS2551
  and TS2576);
- a required property missing from an object (TS2741, TS2739, TS2740);
- an object literal's excess property (TS2353).

Assignment targets that are not variables are next: a constant (TS2588), a
function (TS2630), a class (TS2629) and an enum (TS2628).

## Investigation

- **The checker was blind to user-declared types on every real compile.**
  The resolver renames each top-level declaration per file (`P` becomes
  `P__kml_mod0`). It renamed an annotation's converted fields, but not its
  type-syntax tree, which the checker reads. So `const a: P = …` named a `P`
  the checker could not find, and every such annotation was unanswered.
  - The unit tests, which parse without the resolver, never saw this.
  - `tools/tsdiag`'s own-programs lane never saw it either: it called the
    resolver, which now returns type errors as its error, and it discarded
    every program with an error.
- **TypeScript's `this`, standard-library merging, and assertion calls**
  showed up in the corpus measurement:
  - a class, interface or enum a program declares under a library global's
    name (`interface Element`) merges with the library's members, which the
    checker does not have yet;
  - a class merged with an interface has the interface's members too;
  - two namespaces' classes of one name share a symbol (ADR-00450).
- **An assertion call inside a loop** (`cfg.headers.push(…)`, a call flow
  node since ADR-01122) typed its own callee with flow narrowing. That read
  `cfg`, whose walk met the same call again, recursing until the flow budget
  ran out: 530,000 steps for one read in `apps/loadtest/config.ts`, and an
  answer that differed between two asks (`TestTypeOfWholeCorpus`).
  TypeScript types an assertion's callee through declared types only
  (`getTypeOfDottedName`).
- **tsc 5.6.3 details:**
  - up to five missing properties are listed under TS2739, six or more
    under TS2740 ("…, and N more");
  - an excess property is reported before any missing one;
  - an object type prints as `{ x: number; }`;
  - a union containing `unknown` is `unknown`.

## Decision

- **The resolver renames the type-syntax tree** (`rewriteTypeNode`) with the
  same lookup and scope rule as the converted annotation. **The checker
  prints source names** (`sourceName`: the per-file suffix removed, and a
  namespace member's mangling read back as `ns.P`).
- **TS2339** on a property read from a single object literal type, interface
  or class instance. It is not reported:
  - for `Object.prototype`'s members, private `#` names, or this compiler's
    own `__kml_` fields;
  - for a merged name (a class with an interface, an enum with a namespace,
    two namespaces' classes);
  - for a library global's name.
  A class's getter is an instance property with the getter's type; a setter
  alone gives its parameter's type. A pair that differs writes through the
  setter's type.
- **Missing properties:** TS2741, TS2739 (up to five), TS2740 (six or more);
  an argument reports TS2345. Checked only when every property the source
  has fits.
- **TS2353**, an object literal's excess property, before any missing one.
  A `<T>{…}` cast is not a fresh literal: the parser now records the cast in
  `Program.Assertions`, and the checker types the expression as `T`.
- **TS2588, TS2630, TS2629, TS2628** for a store (`=`, compound, `++`/`--`)
  to a constant, a function, a class or an enum. The assignability check is
  skipped for such a store.
- **An explicit `this: T` parameter** types `this`: the parser records it in
  `Program.ThisParams`, since it drops it from the parameters. `this` does not
  narrow yet, so a `this` type that could narrow is unanswered.
- **Narrowing:**
  - object types narrow: interface and object-literal types join unions,
    `unknown`, `boolean`, literals and classes;
  - a type guard narrows each member to the candidate when the candidate is
    assignable to it (TypeScript's `getNarrowedType`);
  - a generic guard's predicate is inferred and instantiated, and a guard or
    assertion the checker cannot type leaves the references its arguments
    mention unanswered (`console`'s methods excepted);
  - a guard's or assertion's callee is typed through declared types
    (`dottedType`).
- **Unions:** `unknown` absorbs every other member, as `any` does.
- **`tools/tsdiag`:**
  - maps TS2551 and TS2576 to TS2339, and TS2561 to TS2353;
  - compares the property and assignment-target codes on non-strict cases
    too;
  - reads the own-programs lane's diagnostics from the resolver's error.

## Implementation notes

- **Checker:**
  - `checker/check.go`: `checkProperty`, `checkMissing`, `reportMissing`,
    `checkTarget`, `writeType`, `nominalOpen`, `libGlobals`;
  - `checker/symbols.go`: accessors in `instanceOf`, the `this`-return rule;
  - `checker/narrow.go`: `narrowable`, `narrowToType`, `dottedType`,
    `unknownGuard`;
  - `checker/generics.go`: predicate inference, `this` parameters;
  - `checker/types.go`: `sourceName`, object printing, `unknown` absorption;
    `checker/checker.go`: the cast.
- **Front end:**
  - `resolver/rename.go` (`rewriteTypeNode`), and the merged `ThisParams`
    in `resolver/resolver.go`;
  - `parser/parser_exprs.go` (the cast), `parser/parser_stmts.go`
    (`parseFunctionRest`, `thisParam`), `parser/parser.go`;
  - `ast/nodes.go` (`Assertion.Cast`, `Program.ThisParams`).
- `diag/messages.go`: TS2339, TS2353, TS2588, TS2628, TS2629, TS2630, TS2739,
  TS2740, TS2741.
- `tools/tsdiag/main.go`.
- **Tests:** `checker/check_test.go`, `checker/narrow_test.go` (the loop-call
  cost case), `tests/typecheck_test.go` (strict rejection, the js lane, an
  interface from another file, the CLI's label and hint).

## Side effects discovered

- `Type.String` printed `{ x: number }`; tsc prints `{ x: number; }`. Fixed,
  and the narrowing tests updated.
- The 70-file tsc sample below found one more code: an assignment to a
  function is TS2630, not TS2322.
