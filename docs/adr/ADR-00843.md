# ADR-00843: `Array.prototype.lastIndexOf` and `String.prototype.lastIndexOf`

- **Relations**: Siblings of `indexOf` ([ADR-00558](ADR-00558.md) buffer path); array element compare per [ADR-00152](ADR-00152.md)
- **Date**: 2026-09-10

## Context

`lastIndexOf` was unimplemented on both arrays and strings ("an array has no
method 'lastIndexOf'"; strings had no handler either). It is a standard method —
`"path/to/file".lastIndexOf("/")`, `arr.lastIndexOf(x)` — and the compiler's
inference/allowlists already expected it, so only the emit + dispatch were
missing.

## Decision

- **Array**: `emitArrayLastIndexOf` — a mirror of `emitArrayIndexOf` with a
  descending scan (`len-1 … 0`), returning the first (highest) matching index,
  or -1. Rejects a nested-array element like `indexOf` does.
- **String**: a new runtime `__kml_str_lastindexof(hay, needle)` — a descending
  `memcmp` scan from offset `len(hay)-len(needle)` down to 0, returning the
  highest matching byte offset or -1 (binary-safe; an empty needle matches at
  `len(hay)`, as in JS). `emitStringLastIndexOf` calls it.
- Dispatch: `emit_call.go` routes `lastIndexOf` to the array or string emitter by
  receiver type (the Buffer string-search path already ran ahead of it).

## Implementation notes

`emit_arrays_search.go` (`emitArrayLastIndexOf`), `emit_strings.go`
(`emitStringLastIndexOf`), `runtime_strheader.go` (`__kml_str_lastindexof`),
`emit_call.go` (dispatch). New status rows added for both surfaces (they were
absent, not merely uncaveated).

## Verification

macOS (Apple Silicon M4): matches Node — `[1,2,2,3].lastIndexOf(2)` → 2, miss →
-1, `"path/to/file".lastIndexOf("/")` → 7, `"abcabc".lastIndexOf("bc")` → 4,
`"abc".lastIndexOf("x")` → -1, `"abc".lastIndexOf("")` → 3. New
`TestE2EArrayLastIndexOf`/`TestE2EStringLastIndexOf` + the array/string/buffer
suites green.
