# ADR-00515: Lazy dynamic `import()` via `dlopen`'d shared-library islands

- **Relations**: `Implements TDD-00056`
- **Date**: 2026-08-30

## Context

Dynamic `import()` was a clean rejection. TDD-00056 designed a *lazy* backend:
each dynamic-import target compiled to its own shared library, `dlopen`'d on
first use, so its top-level runs only when the call site executes — the real ES
module semantic TDD-00055's eager whole-program-merge model cannot provide.
This ADR records building that backend, opt-in behind `-dynamic-import=lazy`.

## Investigation

A minimal probe first confirmed the mechanism on macOS: `_NSGetExecutablePath`
self-location → `dlopen` a sibling `.dylib` → `dlsym` an init + accessor →
run-once init. The compiler already had every reusable part: the worker-module
seam (a file's top-level emitted into a named function, no `main`), the module-
global promotion (`@__kml_global_<name>` for scalar/string top-level vars,
tracked in `e.moduleGlobals`), `wrapResolvedPromise`, and the per-feature
embedded-C-source + `LinkLibs` build plumbing. Workers, notably, compile into
the *same* binary (a pthread entry function) — so the separate-`.so` island was
genuinely new emission, but modeled on existing seams.

## Decision

Each dynamic-import target is an **independent whole-program compile emitted as a
shared library**, not merged into the main program:

- **Frontend (shared with TDD-00055):** `ImportCallExpression` AST node; parse
  `import(expr)` in expression/statement position; resolver treats a string-
  literal specifier as a dependency edge and annotates the node's `ResolvedPath`;
  a non-literal specifier is a clean codegen error.
- **Resolver partition (lazy):** dynamic-import targets are *not* merged —
  recorded as `IslandRoots`, and the node's annotated value exports
  (`export const/let/var name: T`) captured for the call site.
- **Island codegen:** `EmitProgram` with `islandHash` set appends an idempotent
  `__kml_dynmod_<hash>_init` (runs the island's `main()` once) and a
  `__kml_dynmod_<hash>_<name>` accessor per scalar/string entry export, reading
  the mangled module global. `hash` = FNV-1a of the target's absolute path,
  computed identically by both sides.
- **Orchestration (`main.go`):** each island is resolved + emitted + built via
  `clang -shared -fPIC` into a sibling `<binary>.d/` directory.
- **Runtime shim (embedded C, `-ldl` on Linux):** self-locates
  (`_NSGetExecutablePath` / `/proc/self/exe`), builds `<exe>.d/<hash><ext>`,
  `dlopen`s (`RTLD_NOW|RTLD_LOCAL`), runs init once, returns the handle; a second
  entry `dlsym`s one accessor.
- **Call site:** loads the island, then — because island symbols live in the
  separately-`dlopen`'d `.so`, not the main binary — `dlsym`s each accessor and
  calls it indirectly to fill a fixed-shape result object, wrapped in a resolved
  Promise. `inferExprType` reports `Promise<{…exports}>` so `const m = await
  import(...)` types.
- **`--static` rejection:** `--static` + `-dynamic-import=lazy` + real usage is a
  clean mutual-exclusion error (a static binary can't `dlopen`).

## Implementation notes

- Module globals are mangled (`answer__kml_mod0`); the accessor is named by the
  *public* export name but reads the *mangled* global, so the resolver stashes a
  public→mangled map (`EntryExportMangled`) for the island compile.
- The main binary cannot statically reference island symbols — the call site
  must `dlsym`, never a direct `call @__kml_dynmod_*`.

## Side effects discovered

V1 scope limits, all clean (omitted, not miscompiled): only annotated
scalar/string exports appear in the result object (`function`/`class`/array/
object exports omitted — the same shape TDD-00055's design omits); a nested
`import()` inside an island compiles eagerly; the eager (`-dynamic-import=eager`,
TDD-00055) backend is still unbuilt and errors clearly. Islands are self-
contained (their own runtime copies) — shared mutable runtime state is not
crossed, adequate for value-returning modules.

## Verification

- New E2E `TestE2EDynamicImportLazy` (laziness ordering + typed field read) and
  `TestE2EDynamicImportNonLiteralRejected`, shelling to the CLI (islands need the
  `clang -shared` orchestration, not the in-process emitter). Pass.
- Manual: single + multi-export (`number`/`string`/`boolean`) modules — laziness
  and field values correct.
- **Both platforms:** darwin/arm64 (`.dylib`) and Linux glibc/arm64 via Docker
  (`.so`, `/proc/self/exe`, `-ldl`) — identical lazy behavior and field reads.
- `go vet` clean; module/import/worker/async E2E regression green.
