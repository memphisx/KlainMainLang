# ADR-01368: A generic class's instances show its own name

- **Relations**: Extends TDD-00010
- **Date**: 2026-10-03

## Context

`console.log(new Q<Box>(b))` printed `Q__kml_mod0__clsBox { … }`, and a
single-file program printed `Box__num { … }`. Node prints `Q { … }` and
`Box { … }`. Found with the generic inference of ADR-01367.

## Investigation

- An instantiation is named after its generic plus a suffix per type
  argument. A class argument's suffix carries that class's own module
  suffix.
- `ast.Unmangle` cut at the last module suffix. For a class argument that
  is the argument's, so `Q__kml_mod0__clsBox` was left. With no module
  suffix (a single file), nothing was cut at all.

## Decision

- `ast.Unmangle` cuts at the first module suffix. A source name never
  contains one.
- `instantiateGenericClass` records each instantiation's display name as
  its generic's (`classShownNames`), so `.name`, inspect and `toString`
  show `Box` with or without module suffixes.

## Implementation notes

`ast/nodes.go` and `codegen/llvm/emit_generics.go`.

## Verification

Mac (Apple Silicon), against Node 24: instances of `Q<number>` and `Q<Box>`
and their `.constructor.name`; inferred `Box<number>`/`Box<Item>` in a single
file; the ast, resolver and generics tests.
