# ADR-01609: server.listen(path) on Windows: a named-pipe server

- **Relations**: Extends ADR-01034, ADR-01602
- **Date**: 2026-10-13

## Context

`server.listen(path)` listens on a Unix-domain socket on POSIX
(`__kml_native_pipe_listen`); on Windows Node's equivalent is a named-pipe
server (`\.\pipe\name`). Only the client half existed there (ADR-01034):
`listen` failed with `ENETDOWN`. BACKLOG §2 also said "no host has it",
which was out of date for POSIX. `net.connect(path, listener)` did not type
check (no `path` overload).

## Investigation

Node 24 on Windows, same program: listening, a client's echo, three
clients at once, a second server on the same name (`EADDRINUSE listen`).
A first version offering one pipe instance at a time timed out with
concurrent clients: the client end waits for a busy pipe synchronously,
holding the loop that would accept. libuv's pipe server keeps four
instances offered (`pending_instances`).

## Decision

- The shim's `bind` records a pipe-namespace path for an `AF_UNIX` socket;
  `listen` turns the descriptor into a pipe listener offering four
  overlapped instances, each with a `ConnectNamedPipe` on the port (the
  first with `FILE_FLAG_FIRST_PIPE_INSTANCE`, so a taken name is
  `EADDRINUSE`). A completion makes the listener readable through the
  loop's shim bridge; `accept` turns a connected instance into the duplex
  pipe descriptor the client end already is and offers a fresh one; `close`
  cancels and closes the offered instances. No runtime above the shim
  changed: `__kml_native_pipe_listen` is the POSIX code.
- `net.connect(path[, listener])` and `createConnection(path[, listener])`
  overloads, as Node's (a numeric string is still a port).

## Verification

Windows 11: `TestE2ENetPipeServerWindows` (Node's output, line for line),
the named-pipe client tests and the `net` tests.
