# ADR-00577: URL `host`/`username`/`password` setters

- **Relations**: Completes the setter scope opened by ADR-00572
- **Date**: 2026-09-01

## Context

ADR-00572 wired the `URL` component setters via re-parse-and-re-derive, but left
`host` (the combined `hostname:port`), `username`, and `password` as a residual
caveat: curl exposes the parts, only the value-splitting and field-derivation
were undone. `url.username`/`url.password` were also unreadable — the fields
didn't exist on `URLType()`.

## Decision

1. Add `username` and `password` fields to `URLType()`, derived in
   `deriveURLFieldsIntoObject` from `CURLUPART_USER`/`CURLUPART_PASSWORD`
   (absent → `""`, like every other optional part). Reads now work through the
   ordinary object field-access path.
2. Extend `emitURLComponentSet`'s settable map with `username → CURLUPART_USER`,
   `password → CURLUPART_PASSWORD` (clean single-part sets), and `host`.
3. `host` has no single curl part (`CURLUPART_HOST` rejects an embedded port, rc
   `URLE_BAD_HOSTNAME`), so split the value on the first `:` via `strchr`: set
   `CURLUPART_HOST` to the prefix always, and `CURLUPART_PORT` to the suffix only
   when a colon is present. A value with no port therefore leaves the existing
   port untouched — verified byte-for-byte against Node v26, whose `.host` setter
   does the same.

## Verification

New `TestE2EURLHostUserPassSetters` (username/password read + set, `host` with
and without a port, `href` re-derivation carrying the userinfo); the existing
URL suite still passes (the derivation additions are behavior-preserving for
URLs with no userinfo — an absent part derives to `""` as before). Built and
verified on Mac (Apple Silicon).
