# ADR-01685: Windows sockets and IPC as libuv handles

- **Relations**: Implements TDD-00244, Extends ADR-01681
- **Date**: 2026-10-17

## Context

ADR-01681 moved POSIX net, dgram and IPC onto `uv_tcp_t`, `uv_udp_t` and `uv_pipe_t`. Windows sockets stayed entries in `win32io.c`'s descriptor table, watched with `uv_poll_init_socket`:
- `threadpoolsrc/klainpool.c` did accept, connect, `recvfrom`/`sendto` and the socket options itself, on the table's descriptors.
- `dgram`'s send waited out a full buffer with a blocking `poll()`.
- The IPC channel to a child was a loopback socket pair. A sent socket travelled as a `KMLH` frame holding a `WSAPROTOCOL_INFOW`, a format only this runtime spoke, so a Windows parent could not exchange handles with a real Node child, or the reverse.

## Decision

**Connections.** An accepted or connected TCP socket leaves the table:
- `__kml_win_fd_release_socket` frees its slot without closing it.
- `uv_tcp_open` hands it to libuv, sharing one `us_tcp_adopt` with POSIX.
- A socket the table must keep is refused and stays a polled descriptor: a dup'd one, one shared with a child, or a cluster channel. So is one libuv refuses, re-registered as a polled descriptor.
- `setNoDelay`, `setKeepAlive` and `address()`/`remoteAddress` go through `uv_tcp_nodelay`, `uv_tcp_keepalive` and `uv_tcp_getsockname`/`getpeername` on every platform. Before this, a libuv stream's `US_FD` placeholder reached `setsockopt` on Windows.
- `tcpFileno` is -1 for such a socket, as Node's `_handle.fd` is on Windows.

**Datagrams.** Every UDP socket is `uv_udp_init_ex`'s, on every platform. The descriptor fallbacks are deleted, including the blocking `poll()` send.
- `setBroadcast`, `setTTL`, `setMulticastTTL`, `setMulticastLoopback`, `addMembership`/`dropMembership` and `setMulticastInterface` are libuv's setters, as in Node's `udp_wrap`. They replace hand-written `setsockopt` calls with per-platform option numbers.
- libuv's range checks now apply: `setTTL(0)` is EINVAL, as under Node.
- Buffer sizes are `uv_recv_buffer_size`/`uv_send_buffer_size`.

**Listeners.** A listening socket is a `uv_tcp_t` with `uv_listen`, its table slot kept as the record of a listener (`wlfd`).
- A worker spawned later still inherits it from that record.
- `klain:http`'s round-robin deal moves from the shim's `accept()` into the accept dispatch: a connection libuv accepted goes to `__kml_win_rr_deal`. That calls `WSADuplicateSocketW` for the worker whose turn it is, and the dispatch then closes its own handle.
- Closing the listener drops the record and its hand-off channels without closing the socket a second time (`__kml_win_listener_forget`).
- A bound shared handle (`tcpBind`, a Node cluster primary's) is libuv's too, so it can be sent to workers.

**IPC.** The channel is a libuv IPC pipe (`UV_CREATE_PIPE` on an `ipc` pipe), as Node's is.
- The child opens `NODE_CHANNEL_FD`, a CRT descriptor, as a pipe. `ipcOpen` reopens a duplicate as an IPC pipe, as POSIX does with `dup`.
- A socket goes with `uv_write2`, by its table id.
- A received socket is accepted into a new table entry. `ipcTakeFd` returns a token for it (bit 29 set), which `streamOpen` and `tcpListenOpen` take over: on Windows there is no descriptor to hand back.
- The `KMLH` framing, the peer-pid table and the socket adoption at startup are deleted.

**What stays in the table.**
- `klain:http`'s own cluster model: a worker's inherited listener and its round-robin channels, whose readiness is the channel's.
- Unix-domain socket paths, since libuv on Windows has named pipes only.
- Sockets libuv refuses.

## Verification

- macOS: the dgram tests, since the UDP and socket-option paths are shared with POSIX now.
- Linux x86-64 (Node304): `x86_64-w64-mingw32-gcc -fsyntax-only` over `klainpool.c`, `win32io.c` and `win32proc.c` against libuv's Windows headers. The only error is `UV_TTY_MODE_RAW_VT`, which Ubuntu's libuv 1.48 headers predate.
- Windows: compile-checked only. CI's Windows lane is the first run.
