# ADR-01121: Bounding the checker's cost and recursion

- **Relations**: `Implements TDD-00230` (Phase 2, P2.3/P2.5); `Extends ADR-01112`, `ADR-01113`; found by the measurement of ADR-01122
- **Date**: 2026-09-24

## Context

[TDD-00230](../tdd/TDD-00230.md) P2.3 says every expression is checked once,
so the exponential re-inference class is gone by construction. Running the
checker over TypeScript's test corpus ([ADR-01122](ADR-01122.md)) showed
that it was not:

- some cases never finished;
- one overflowed the stack;
- one, bounded only by memory, filled the disk through swap.

TypeScript keeps several of these cases precisely as regression tests for
the same faults in its own checker.

## Investigation

- **`interface I<T> { x: I<T[]> }`** overflowed the stack. Members are
  typed eagerly, so instantiating `I<number>` types `I<number[]>`, and so
  on without end. Classes and aliases have the same shape. TypeScript
  resolves members lazily and caps instantiation depth.
- **`controlFlowCaching.ts`** (TypeScript issue #8401) did not finish. The
  flow walk (ADR-01112) had no cache, so each read walked every path back
  through every branch.
- **`controlFlowManyConsecutiveConditionsNoTimeout.ts`**: 120 `if`s inside a
  `while (true)`. A cache of complete answers did not help: with the loop
  label on the walk's path, every answer inside the loop was "cut" and
  none was kept.
- **`controlFlowSelfReferentialLoop.ts`** (issue #12319): evolving `var`s
  assigned in a loop from calls reading each other. Each assignment's value
  was a provisional recursion answer, never cached, so the cycle was
  re-derived once per path. Sharing loop state across nested queries, as
  TypeScript's flow-loop stacks do, was tried and rejected: the nested
  query for `x`'s own value (`x = x + 1`) was cut at the loop instead of
  walking it, a wrong answer the narrowing tests caught. It also blew up
  memory under another shape.
- In that case the callee (`FF`, with unannotated parameters) is unanswered,
  so the call's type needs no argument types at all; typing them anyway is
  what walked the cycle.
- **Contextual typing recursed.** A function expression's return
  (`contextualReturn`, ADR-01122) asked for its context, and inferring the
  enclosing generic call's type arguments typed that function again. An
  object literal holding a callback did the same through the new
  object-literal property context.

## Decision

- **Instantiation depth:** one generic declaration may be instantiated at
  most five levels deep inside its own members (`maxNesting`); a deeper
  instantiation is unanswered.
- **The flow cache:** a complete answer at a branch or loop label is
  memoised per label, reference and declared type. It is complete when no
  loop outside the label cut it and no assignment it read was a provisional
  recursion cut (`cutCount` unchanged).
- **The per-walk memo:** within one backward walk, an answer at a label is
  kept with the loop labels it was cut at, and reused while those are still
  on the path. A loop label's own cut resolves at the label, so the answer
  there is complete and goes to the flow cache.
- **Provisional answers:** a `TypeOf` answer that depended on assignment
  values still being computed is memoised with them, and reused while every
  one is still open. Reusing it logs those cuts again, so its readers stay
  provisional too.
- **The callee comes first:** a call to an unanswered callee is unanswered
  without typing its arguments.
- **A flow budget:** an outermost `TypeOf` query takes at most 500,000 flow
  steps, as TypeScript bounds its own analysis (TS2563). Past the budget the
  query is unanswered, and nothing computed during it is cached.
- **Contextual recursion:** `contextualReturn` does not consult a function's
  context while that context is typing the function. An object or array
  literal holding a context-sensitive function is itself context-sensitive
  (TypeScript's `isContextSensitive`), so a generic call's first inference
  pass leaves it for the second.
- **Circular `extends` and base-member cycles** keep their guards from
  ADR-01118.

## Implementation notes

- `checker/checker.go`:
  - `provisional`, `allAssigning`;
  - `depth`, `steps`, `exhausted`;
  - `flowCache`, `contextualizing`, `nesting`;
  - the callee-first `CallExpression`.
- `checker/narrow.go`: `flowKey`, `flowWalk`, `mergeDeps`, `flowBudget`.
- `checker/symbols.go`: `maxNesting`, `tooDeep`, `nest`, and the guard in
  `contextualReturn`.
- `checker/generics.go`: `contextSensitive`.
- Tests: `TestExpandingGeneric` and `TestFlowCost` (the loop repro with 64
  chained assignments, and 200 conditions in a loop).

## Side effects discovered

- The checker's own test suite runs in about a third of its former time
  (0.4 s instead of 1.4 s), from the flow cache.

## Verification

All on macOS arm64 (M4):

- `go test ./checker`.
- `tools/tsdiag` over the whole TypeScript corpus in about three seconds,
  with no panic. Before these bounds it did not finish.
- `controlFlowCaching.ts` and `controlFlowManyConsecutiveConditionsNoTimeout.ts`
  check in about a millisecond each.
- Shadow report: see ADR-01122.
