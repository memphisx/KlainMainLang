# ADR-01149: A closure narrows a captured binding along its own flow; a condition on an assignment narrows its target

- **Relations**: `Implements TDD-00230`; `Extends ADR-01148`
- **Date**: 2026-09-25

## Context

Two false positives came up while testing the timer declarations
(ADR-01148). tsc accepts both programs:

- `let b: number | null = 3; const bump = () => { b = b === null ? 1 : b + 1 }`
  reported `'b' is possibly 'null'`.
- `while ((match = re.exec(s)) != null) { match[1] }` reported `'match'
  is possibly 'null'`, once `RegExpExecArray extends Array<string>`
  resolved (ADR-01148).

## Investigation

- **Captured bindings in a closure.** `narrowedType`
  (`checker/narrow.go`) returned a captured binding's declared type
  whenever `ClosureNarrows` was false. tsc starts such a read from the
  declared type at the closure's start, then narrows it along the
  closure's own flow. The flow walk already stops at the closure's
  `FlowStart` with the declared type when `ref.outer` is false.
- **Assignments in a condition.** `refersTo` matched only a reference.
  tsc's `getReferenceCandidate` reads an `=`, `&&=`, `||=` or `??=`
  assignment as its target.

## Decision

- **`narrowedType`.** A non-local read always walks its own flow, with
  `ref.outer` set from `ClosureNarrows`. An evolving `let` keeps its
  declared type, as before.
- **`refersTo`.** A condition on an assignment tests its left side. Only
  condition narrowing uses `refersTo`; the other `refOf` callers are
  unchanged.
- **A builtin declaration reads as declared.** A global such as `Math`
  belongs to the library's scope, so every read of one is non-local.
  Walking the program's flow for each such read exhausted the flow
  budget in a long file. Test262's harness file lost 26 `Math.*` tests
  that way: the call was left unanswered, the lowering declined, and
  the hand-written path said "not supported". `narrowedType` skips the
  walk for a symbol `inLibrary`.
