# ADR-02047: An Error's system fields in insertion order

- **Date**: 2026-11-22

## Context

- An Error's system fields (`errno`, `code`, `syscall`, `address`, `port`,
  `path`, `dest`, `errcode`, `errstr`) live in fixed slots, listed in
  uvException's order before the extra bag's keys. `e.code = …; e.errno = …`
  listed `errno` first, and `e.syscall = …; e.extra = 1; e.code = …` put
  `code` before `extra`, unlike Node's insertion order.
- `delete err.code` kept the field. An assignment to a property of a catch
  binding (`catch (x: any) { x.extra = 1 }`) failed to compile.

## Decision

- An assignment by the program of a system field the Error lacks puts a
  hidden marker key (`\x7f` + the name) into its extra bag
  (`__kml_error_note_field`). The walkers (`__kml_error_nextra`,
  `__kml_error_extra_key`, `__kml_error_own_names`) list the fields the
  runtime set first, in uvException's order, then the bag in insertion
  order with each marker standing for its field. A field the Error has
  keeps its place.
- `delete` of a system field clears its slot and its marker
  (`__kml_error_delete_field`, reached from `__kml_shape_delete_field`).
- A catch binding's property write boxes the caught value and takes the
  dynamic write.

## Consequences

- Tests: `TestE2EErrorSystemFieldOrderTS`.
