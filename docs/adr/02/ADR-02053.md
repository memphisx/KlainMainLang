# ADR-02053: Global declarations from `declare global` and a script's top level

- **Date**: 2026-11-22

## Context

- tsc merges an interface a script declares at its top level under a
  builtin's name (`interface Array<T> { second(): T }`) into the global
  declaration, as it does a module's `declare global { … }` members. This
  compiler renamed the script's interface per file and erased the
  `declare global` block, so a call of the added member was a type error
  (`property 'second' does not exist`), and a `declare global` var or
  function was an unknown name.

## Decision

- The parser keeps a program's `declare global` members, each marked
  `Global`: interfaces and type aliases as written, a `var`/`let`/`const`
  or `function` as an ambient declaration. The resolver renames none of
  them, nor a script's top-level interface named as a builtin one
  (lib/tsmembers.txt).
- The binder declares such an interface in the global scope, as one more
  declaration of the builtin's symbol, when the program is a script (or,
  merged, has no module syntax) or the interface is a `declare global` one.
- Code generation: a builtin host's members leave out the program's own
  (no native stub for them); a primitive receiver's call of a member the
  program declared reads it off the prototype when it runs; a
  `declare global` value is dropped after the check, as `declare class`
  is, and its reads, calls and `typeof` go to the global object.

## Consequences

- `TestE2EScriptGlobalInterfaceAugmentation`,
  `TestE2EDeclareGlobalAugmentation` and `TestE2EDeclareGlobalValues`
  compare with Node.
- A TypeScript file runs as strict code (tsc's `alwaysStrict`): a method
  added to `String.prototype` sees its receiver unwrapped, where Node's
  type-stripping runner, adding no directive to a CommonJS file, wraps it.
