# TDD-00240: The runtime written in C, not in IR text

- **Status**: In Progress
- **Date**: 2026-10-01

## Context

About 15,000 lines of the runtime are LLVM IR written as Go string
literals (`runtime_*.go`, and IR blocks in some `emit_*.go`): the task and
promise core, microtasks, collections, the dynamic object, strings,
streams, fetch, child processes, fs.watch, IPC, net, timers, the HTTP
server. That text bypasses the emitter's helpers (fresh registers, the
type layouts, the store guards), so each routine repeats a struct's layout
by hand. The last bug it hid: the stream runtime rejected promises with
the reason's payload and not its tag, and the result depended on stray
memory ([ADR-01326](../adr/ADR-01326.md)).

[TDD-00230](TDD-00230.md) Phase 4 moves the runtime onto libuv, in C;
this is the step it presupposes, taken now because it also blocks
[TDD-00238](TDD-00238.md) Stage 4. A shared library
object needs one runtime per option set, but these routines are emitted
per program and their bodies change with what the program uses:
`tools/libdrift -runtime` over the examples finds 131 runtime routines
that differ between programs (`__kml_drain_microtasks` drains ticks only
when the program has them, the host-box hooks, the fetch, HTTP/2 and
fs.watch dispatchers, …). A C file compiled once into the object cache is
the same in every program by construction.

## Design

1. **One source for shared layouts.** The structs both sides touch (the
   promise, the task, the error object, the readable and writable stream,
   the pipe context, the array header, the closure header, the string
   header) are defined once, as the Go `Type` values codegen already uses.
   The emitter generates `kml_layout.h` from them (field offsets and sizes
   as `#define`s and packed `struct`s, plus a `_Static_assert` per size) and
   prepends it to every runtime C source. A layout change is then a compile
   error in C, not a silent shift, and the hand-kept "keep in sync"
   comments go.
2. **A routine moves to C whole.** Its IR text is deleted, and its callers
   keep calling the same symbol, now declared. Routines the IR generated
   per program (a dispatcher over the program's classes) already read the
   unit registry (ADR-01325); one that still switches on program data
   reads a registered table instead.
3. **No used* variants.** A C routine handles every case: the part a
   program does not use costs a branch, and the linker drops unreferenced
   functions (`-ffunction-sections`, `--gc-sections`, `-dead_strip`).
   Where the IR emitted a stub because a subsystem was absent (the TLS
   symbols the net runtime calls without `tls`), the C file defines the
   stub weakly, and the real one overrides it.
4. **Order**, by what depends on what and by the drift each removes:
   1. task, promise settle/reject, microtasks and ticks (everything
      settles through them);
   2. the dynamic object and array, collections, strings, JSON, dates;
   3. streams (readable, writable, pipe, tee, transform);
   4. fetch, child processes, fs.watch, IPC, net, timers, path: the event
      loop's users, ported straight onto the loop interface of TDD-00230
      Phase 4 rather than once onto `select()` and again onto libuv;
   5. the HTTP server, after the `klain:http` redesign (TDD-00230).
5. **A ratchet.** A test counts the IR `define`s in Go string literals
   per file and fails when a count rises; each ported file lowers its
   allowance to zero, and the test is deleted with the last one.

## Open questions

- **Calling convention for aggregates.** Some IR routines take or return
  first-class aggregates (`{ i8, i64 }` caught values, `{ ptr, i64 }`
  arrays). C passes small structs per the platform ABI, which matches LLVM's
  lowering of the same struct on the host targets, but not on every
  target. Either the C side takes pointers, or each such signature gets a
  per-target check.
- **Coroutine and fiber code.** The task runtime's stack switches
  (`ucontext`, Windows fibers) already live partly in C; how much of the
  scheduler stays in IR because it is generated around a task's frame
  layout.
- **Inlining.** Hot IR routines (string length, the NaN-box tag) are
  inlined by clang today within the one module. In C they need LTO or a
  header of `static inline` definitions; measure before deciding.
