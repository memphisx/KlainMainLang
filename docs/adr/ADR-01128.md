# ADR-01128: Calls no overload matches (TS2769); type-parameter operands; `this.x` narrowing

- **Relations**: `Implements TDD-00230` (Phase 2, P2.5, P2.6, P2.7); `Extends ADR-01113`, `ADR-01126`
- **Date**: 2026-09-25

## Context

This continues the strict lane's tsc codes past
[ADR-01126](ADR-01126.md):
- a call that no overload of a function accepts (TS2769);
- arithmetic on an unconstrained type parameter;
- `this.x` narrowing, left unanswered in [ADR-01124](ADR-01124.md).

Each change was measured against TypeScript's baselines before it reports
anything.

## Investigation

- **tsc 5.6.3's `resolveCall`** reports only once no overload applies. Its
  error depends on how many candidates passed the arity check:
  - one candidate: that overload's own argument error (TS2345);
  - two or three: TS2769, at the failing argument when every candidate
    fails at the same one, otherwise at the call;
  - more than three: TS2769 at the last candidate's failing argument.
  - A call no overload takes by arity is TS2575/TS2554, which is not modelled
    here.
- **An ambient overload set was not typed as one.** The parser attaches
  overload signatures to the implementation's declaration. `declare function
  g` written three times, however, is three declarations, each with a
  synthesized throwing body (ADR-00471). The checker typed only the first
  signature. Relaxing the merged-declaration guard so these calls were
  checked showed 9 false positives, all against the wrong signature, which
  is how this surfaced.
- **tsc on a type-parameter operand:**
  - an unconstrained `T` in `a - 1` is TS2362, and `a + b` is TS2365 naming
    `T`;
  - `-a` and `a < b` are accepted;
  - a constrained `T` is checked as its constraint:
    `T extends number | undefined` gives TS18048.
  - The checker had excluded every type parameter. So `/** @erased */
    function add<T>(a: T, b: T) { return a + b }` was a codegen rejection
    until [ADR-01127](ADR-01127.md) removed that, and was then accepted: a
    regression the E2E suite caught.
- **`this.x` narrowing** in tsc:
  - `this` references match within one `this` container (arrow functions are
    transparent);
  - a `this.x` read narrows within its own flow container only (a property
    access never continues out of a closure's start node);
  - a store to `this.x` resets the reference.
  - An assigned `[]` is `never[]`, so `if (this.items === null) this.items =
    []` leaves `string[]`.
- **tsc does not treat `void` as absent** in `checkNonNullType`. `f() & 1`,
  where `f` returns `void`, is TS2362, and `v.x` is TS2339.

## Decision

- **`checkOverloadCall`** implements `resolveCall`'s reporting (above).
  `argMisfit` infers a generic overload's type arguments first. An argument
  it cannot decide, a context-sensitive callback, or an unanswered inference
  counts as a possible fit, and nothing is reported then.
- **`ambientOverloads`** types two or more `declare function` declarations
  of one name as an overload set. `FunctionDeclaration.Ambient` marks the
  synthesized stub.
- **Type-parameter operands:**
  - `plainOperand` admits an unconstrained type parameter, which is then not
    arithmetic;
  - `checkNonNull` checks a constrained one as its constraint, and does not
    report an unconstrained one.
- **`this` narrowing:**
  - the binder records each `this` expression's flow node, whether it is in
    its `this` owner's own flow, and a symbol standing for each owner's
    `this` (`thisScope`, `ThisAt`);
  - a `this.x` store makes a property-assignment flow node;
  - the checker's `refOf` accepts a `this` root, and `flowAtRoot` reads the
    flow of either kind of root.
- **An assigned empty array literal** is `never[]` for assignment narrowing
  (the declaration of an evolving array is unchanged). **`void`** is not an
  absent value for the possibly-null family.

## Implementation notes

- `checker/overloads.go`: `argMisfit`, `checkOverloadCall`,
  `ambientOverloads`.
- `checker/nonnull.go`: `checkNonNullType`, the constraint rule, and `void`.
- `binder/flow.go`: `thisScope`, `ThisAt`.
- `binder/binder.go`: the `ThisExpression` case, and `rootIdentifier`
  accepting `this`.
- `checker/narrow.go`: `refOf`, `flowAtRoot`, and the `[]` rule in
  `assignedType`.

## Side effects discovered

- **Test programs held tsc errors, found by checking every changed one with
  tsc.** For example, `TestE2ENeverReturningFunctionInBitwiseOperand`'s
  `function boom()` returns `void` there, so `boom() & 1` is TS2362. The
  test now declares `boom(): never`, which is what it means.

## Verification

- **`tools/tsdiag`:** 1,343 reports, of which 1,341 match tsc's baselines;
  the two misses are the known Annex B cases.
  - TS2362 rose from 321 to 409 matches, and TS2365 from 22 to 31, with
    unconstrained type-parameter operands.
  - TS2769 reports no false positives. It matches none in the corpus, whose
    overload cases use interfaces, generics or libraries the checker does
    not model whole yet. Checked directly, `f(true)` against
    `(string)|(number)` overloads is reported.
  - The project's own programs report 0.
- **Every E2E program the new codes rejected** was compared with tsc 5.6.3
  on the same text. Each report matches a tsc error at the same line with
  the same code.
