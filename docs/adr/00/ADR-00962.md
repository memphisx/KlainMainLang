# ADR-00962: Observable `res` backpressure — `write()===false` + async `'drain'`

- **Relations**: `Implements TDD-00214`. Extends `ADR-00961` (Layer A socket backpressure), `ADR-00959` (incremental `res` Writable).
- **Date**: 2026-09-15

## Context

Layer A (ADR-00961) fixed the real harm — a slow client no longer stalls the
reactor — but left the *observable* Node contract unimplemented: `res.write()`
always returned `true`, and `res.on('drain', …)` was unsupported. A Node-faithful
producer stops writing on a `false` return and resumes on `'drain'`; Layer A
could not serve that producer, because its inline fiber-park left no queue to
drain and nothing to fire `'drain'`. Faithfulness-first (this project's own practice) requires the
real contract.

## Decision

Give a **direct** `res.write` its own per-response output queue, separate from the
WHATWG sink that `req.pipe(res)` drives (which keeps Layer A's blocking-park —
its backpressure already works via the per-write promise, and interleaving raw
`res.write` with `req.pipe(res)` on one response is a documented degenerate case).

- **Queue** — `res.__kml_outq`, a lazily-allocated
  `{ ptr buf, i64 head, i64 len, i64 cap, i64 needDrain }` holding the unsent,
  already-chunk-framed byte tail (a single growable buffer with a drained-prefix
  offset, compacted on append). `res` also gains `__kml_drain_cb` (the `'drain'`
  listener `{fp,env}`) and `__kml_drain_once`.
- **`__kml_res_qwrite(res, data, len)`** frames one chunk (`<hexlen>CRLF data
  CRLF`), appends it, attempts an immediate **non-blocking** flush
  (`__kml_res_drain_try`), and returns `queued <= highWaterMark` (16 KiB, Node's
  socket default) — arming `needDrain` when it crosses above. `res.write` returns
  this boolean; it never parks.
- **`__kml_res_flush(res)`** drains the whole queue, parking the connection fiber
  on socket writability at each `EAGAIN` (Layer A's `@__kml_conn_writepark` /
  `%wfdset` mechanism, reused unchanged) and, on a terminal `EPIPE`, dropping the
  queue and forcing the response ended. It does **not** fire `'drain'`.
- **`__kml_res_drain(res)`** (the dispatcher-tail park loop) flushes, then — once
  the queue empties after a write returned `false` and the response is not yet
  ended — fires `'drain'` on the connection fiber, then loops to flush whatever
  the listener enqueued (re-parking with the write bit correctly set). Splitting
  flush from fire is what lets `res.end`'s own flush avoid a re-entrant `'drain'`
  after end, and lets the reactor stay unchanged: no new "resume reason" — the
  fiber re-derives its state each resume, exactly as the other park loops do.
- **`res.end`** flushes the queue (`__kml_res_flush`) before the terminal chunk;
  the park loop's exit condition (`ended`) is unchanged.
- **`res.on('drain')` / `res.once('drain')`** store the listener + once-flag;
  other events are rejected with a clear error rather than accepted as a listener
  that would silently never fire.

## SIGPIPE

Folded in (chosen scope): `signal(SIGPIPE, SIG_IGN)` once at
`__kml_http_bind_and_listen` entry, so a client disconnecting mid-write surfaces
as a `write()` `EPIPE` (unwinding the connection) instead of killing the whole
server (previously exit 141 on every write path). The flush/give-up path treats a
non-`EAGAIN` `n<=0` as terminal, so `EPIPE` retires the connection gracefully.
The shared `@signal` declaration is guarded independently of the process
signal-handler runtime.

## Consequences

- A synchronous producer that ignores the `false` return buffers unboundedly —
  exactly Node's own behavior; `__kml_res_drain_try` still flushes opportunistically
  as it goes, so memory stays bounded to the un-flushed tail in practice.
- HTTPS/1.1 keeps blocking chunk writes (streamed TLS backpressure unvalidated),
  so over TLS `res.write` may keep returning `true` until the write completes —
  disclosed as a caveat, not a silent divergence.

## Verification

macOS arm64 (M4): `go vet` clean. New E2E tests:
`TestE2EHTTPCreateServerResWriteBackpressureDrain` (a drain-gated 8 MiB producer
delivers the full body to a slow de-chunking client — proving `false`/`'drain'`,
since a broken signal would stall the producer) and
`TestE2EHTTPCreateServerResClientAbortSurvives` (a client aborting mid-stream
does not kill the server; a follow-up request still succeeds — the SIGPIPE fix).
All existing `res.write`/`res.end`/binary/`req.pipe(res)`/keep-alive/backpressure
tests still pass on the new queue path. Example `res_backpressure_drain.ts`
streams 8 MiB intact and exits clean. No new invalid IR (http paths, not
Test262-exercised; `make test-par` is the gate).
