# ADR-00755: `fs.utimesSync` — set access/modification times

- **Relations**: Implements a [TDD-00180](../tdd/TDD-00180.md) §4 row ("Missing entirely … `utimes`/`futimes`"); extends [ADR-00497](ADR-00497.md) (the one-shot path fs ops + shared `__kml_fs_throw`), [ADR-00719](ADR-00719.md)/[ADR-00737](ADR-00737.md) (the Win32 fs shim + asm-alias convention), [ADR-00565](ADR-00565.md) (the `Stats` `atimeMs`/`mtimeMs` that read the times back)
- **Date**: 2026-09-07

## Context

`fs.utimesSync(path, atime, mtime)` — set a file's access and modification times — was absent (the [TDD-00180](TDD-00180.md) §4 "missing entirely" list: `utimes`/`futimes`). It is the primitive behind `touch`-style cache/build tooling, and a program calling it failed to link on Windows and had no emitter path on any host.

## Investigation

The path-op family ([ADR-00497](ADR-00497.md)) established the shape: a throwing `__kml_fs_*` wrapper over a libc call. The one new concern is the time arguments. Node accepts a number (seconds since the epoch), a `Date`, or a numeric string. POSIX `utimes(2)` takes `struct timeval times[2]` — two `{ time_t tv_sec; suseconds_t tv_usec }`. On the 64-bit targets here `tv_sec` is 8 bytes; `tv_usec` is 8 bytes on Linux and 4 (plus 4 padding) on macOS, so a 16-byte element written as `{ i64 sec, i64 usec }` is read correctly on both as long as `usec` stays in `[0, 1e6)` (it always does) — the macOS read takes the low 4 bytes and the high 4 (always 0) fall in its padding. mingw has no `utimes` at all, so Windows needs a shim.

## Decision

Add `fs.utimesSync(path, atime, mtime)`.

- **Emitter** (`emit_fs.go`): `emitFsUtimesSync` builds a `[4 x i64]` — two `{sec, usec}` pairs — and calls the throwing wrapper. `emitSecondsToTimeval` turns each argument into `(sec, usec)`: a `Date` value is milliseconds (divided to seconds), any other value is already seconds (Node's number form); the fractional part becomes microseconds via `fptosi((frac) * 1e6)`. Dispatched in `emit_call.go`; added to the `fs` resolver allowlist for named imports.
- **Runtime** (`runtime_fs.go`): `ensureFsUtimes` declares `utimes` and defines `__kml_fs_utimes(path, times)` — calls it and throws the shared fs error (with the path) on a non-zero return, so `e.code === 'ENOENT'` matches.
- **Windows shim** (`win32fs.c`): `utimes(path, times)` (asm-aliased per [ADR-00737](ADR-00737.md)) reads the two `{sec, usec}` pairs, opens the file `FILE_WRITE_ATTRIBUTES` + `FILE_FLAG_BACKUP_SEMANTICS` (so directories work), converts each Unix time to a `FILETIME` (`sec*1e7 + usec*10 + 116444736000000000`, the 1601↔1970 offset in 100 ns units), and `SetFileTime`s the access and write times, mapping failures through `win_errno`.

Only number and `Date` are supported; a numeric string (which Node coerces) and the fd-based `futimesSync` are documented gaps.

## Implementation notes

- The `[4 x i64]` element stride (16 bytes) matches `struct timeval` on every 64-bit target here; writing `usec` as an `i64` in `[0,1e6)` is safe on macOS's `{i64,i32,pad}` layout as reasoned above.
- Windows opens with `FILE_WRITE_ATTRIBUTES` (not `GENERIC_WRITE`) — the minimum right `SetFileTime` needs — and does not depend on the caller having an open fd (this is the path form, not `futimes`).

## Side effects discovered

None. Reads back through the existing `Stats.atimeMs`/`mtimeMs` unchanged.

## Verification

- New E2E test `TestE2EFsUtimesSync` (`tests/fs_test.go`): a number-seconds pair (`1000000000`/`1500000000`) reads back as `1000000000000`/`1500000000000` ms; a `Date` pair reads back correctly; a missing path throws `e.code === 'ENOENT'`. Cross-platform, verified on **Windows 11**.
- `examples/fs/fs.ts` extended with a `utimesSync` + `statSync().mtimeMs` demonstration.
- `go build`, `go vet ./...` clean; `make status`/`make status-check` and `make reference-check` pass (status JSON + website reference JSON updated same-commit, fs coverage 17/18→18/19 loose); `make conformance` run at delivery.
- Platform: verified on **Windows 11** (x86-64, MSYS2 UCRT); the POSIX path is the plain `utimes` syscall.
