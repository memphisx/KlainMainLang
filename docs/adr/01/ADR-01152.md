# ADR-01152: TS2304 in type positions; Node classes as named imports; a type parameter narrowed through its constraint

- **Relations**: `Implements TDD-00230` (Phase 3); `Extends ADR-01139`, `ADR-01146`, `ADR-01151`
- **Date**: 2026-09-25

## Context

The checker reported TS2304 for a value name only (ADR-01139).
`const x: Frobnicator = 1` compiled until codegen, where tsc rejects it.

The blocker was the names a type position can legitimately use without a
declaration the checker sees:

- **Generic-arrow type parameters**, fixed in ADR-01151.
- **Node classes as named imports.** `import { IncomingMessage } from 'http'`
  was "no exported member", while `import type` worked.
- **This compiler's own `klain:` type names.**

## Investigation

- **Named imports of Node classes.** The resolver checks a named import
  of a builtin module against `virtualModuleMembers`, which lists values
  only. @types/node exports `IncomingMessage`, `ServerResponse`, `Agent`
  and more from `http`. Codegen already resolves `IncomingMessage` and
  `ServerResponse` as annotation types. An aliased type import
  (`import type { IncomingMessage as IM }`) left `IM` unknown to codegen.
- **Which names can be exempted.** Program symbols, lib globals
  (`lib.KnownGlobal`), builtin imports, namespace aliases and ambient
  names already exempt a value name. A type position adds:
  - every type parameter the program declares;
  - an erased Node type import;
  - the JSDoc widths;
  - the names codegen's `ResolveTypeName` knows that neither TypeScript
    nor Node declares (`WSConnection`, `HttpRequest`, `ClusterWorker`, …);
  - `intrinsic`.
- **tsc reports a near miss as TS2552** ("Did you mean …?") within
  `getSpellingSuggestion`'s distance, not as TS2304.
- **A constrained type parameter.** Once `controlFlowGenericTypes.ts`
  parsed (ADR-01151), it showed that `if (x) x.length`, with
  `x: T extends string | undefined`, reported `'x' is possibly
  'undefined'`. tsc narrows T's constraint in a constraint position.
  `checkNonNull` read the declared constraint. This predates this work.

## Decision

- **Module exports.** `tools/libconform -modules lib/nodemodules.txt`
  generates every type name each Node module exports: an interface,
  class, type alias or enum. It reads @types/node's `declare module`
  blocks as text: their top-level declarations and `export * from`
  chains. A function or constant is left out. Erasing one would turn a
  missing value into a silent no-op (`import { transcode } from 'buffer'`,
  which `TestE2EReexportModuleOnlyExtraRejected` keeps rejected).
  `lib.NodeModuleExport` reads the list.
- **The resolver** (`eraseBuiltinTypeImports`) takes a named import of a
  type Node's module exports, but that this compiler has no value for, as
  a type import:
  - it is erased and recorded on `Program.NodeTypeImports`;
  - a value use is the error "'X' from 'http' is supported as a type
    only";
  - an alias, of either kind of type import, becomes `type Local = X`.
- **`checkTypeNames`** walks every TypeScript annotation in the program:
  each `*ast.TypeAnnotation` field, found by reflection, including those
  inside parameters and fields. It reports TS2304 for an unqualified type
  reference that none of the exemptions above covers, and that is not
  within tsc's spelling distance of a known name (`nearKnownName`, tsc's
  `levenshteinWithMax`). The check is lenient on scope: any declaration
  of the name in the program counts (BACKLOG).
- **`narrowedConstraint`.** `checkNonNull` of a type-parameter value
  narrows its constraint along the reference's flow.

## Side effects discovered

- **A value use of a type-only Node class**, such as
  `x instanceof IncomingMessage`, is a compile error. This is a modules
  status caveat.
- **What TS2304 does not cover yet** (BACKLOG):
  - out-of-scope type names;
  - near misses (TS2552);
  - `const C = class {}` used as a type (TS2749).

## Verification

- **New tests:**
  - `TestE2ENodeTypeImportsAndTypeNames` runs a server handler typed with
    aliased and `node:` imports of `IncomingMessage`/`ServerResponse`,
    and checks the value-use error and two TS2304s.
  - `TestCheck` covers TS2304, the TS2552 near miss (not reported) and
    every kind of type parameter.
- **tsdiag:** TS2304 6 of 6 match (was 4), TS2339 87 of 87 (was 85), no
  new false positives. The project's programs have 0 diagnostics.
- **Test programs.** Five tests assigned `readFileSync(path)` with no
  encoding to a `string`. tsc rejects that since ADR-01148 declared the
  `Buffer` overload, so they now pass `'utf8'`.
- **Gates (with ADR-01148–01153):**
  - Test262: strict 7,032 and js 7,832 (the handover's were 7,034 and
    7,825), no clang failures in either lane. The two strict files lost
    call `str.slice(obj, obj2)` with objects for `number` parameters,
    which tsc rejects (TS2345).
  - Node suite: strict 61, js 63, unchanged.
  - `make examples`: 360 pass. `chained_listen` timed out once, its
    known intermittent hang, and passes 3 of 3 runs alone.
  - `make test-par`: only the four macOS `-mm=gc` failures.
