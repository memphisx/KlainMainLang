# ADR-01877: JavaScript's undeclared members; method values during class registration

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's MemberExpression bucket)
- **Date**: 2026-10-21

## Context

- In JavaScript, a member a class neither declares nor assigns (`this.__lookupGetter__`, which tsc's library lacks) is tsc's error type, any, with no diagnostic. The checker left it unanswered.
- A method returning another method as a value (`getM() { return this.#m }`) has its result inferred while its class is registered, before the class's method signatures are. A generator method then read as an untyped default (`i64`) in codegen's inference while its emission built the method's function record; the shadow oracle, asking the same registry, had no answer. The call of such a method (`c.getM()`) was unanswered too: the checker's function-of-a-generator type has no representation, while codegen returns the method's boxed result.
- A returned function keeps codegen's own inference (the closure carries its parameters' defaults); the oracle answered such a body by the checker's type regardless.

## Decision

- In the js lane, a member read on a program class instance that no class in its chain declares or assigns (`this.x = …`) is any.
- While a class is registered, its own methods (accessors aside) count as methods read as values (classMethodValue), so the read is the boxed function record in both deciders.
- A program class method whose registered result is a box returns the box (codegenCallRepr), as a function's already did.
- The oracle answers a body returning a function by what its returns read as when that is a function or a box, as inferUnannotatedReturnType does.

## Consequences

- `TestJSUndeclaredMember` covers the js lane rule. `private-async-generator-method-name.js` and `private-getter-is-not-a-own-property.js` leave the shadow report.
- Verified on Apple Silicon.
