# ADR-00344: `tls` module — `tls.connect` (TLS client)

- **Relations**: Implements TDD-00109; builds on the net client (ADR-00328) and the OpenSSL crypto backend (TDD-00104)
- **Date**: 2026-08-24

## Context

`tls` was ❌ on [NODE-CORE-MODULES.md](../status/NODE-CORE-MODULES.md) — all TLS
was hidden inside libcurl (fetch, HTTPS), with no way to open an arbitrary TLS
socket. This delivers the client half, `tls.connect`, the highest-value
remaining networking primitive.

## Decision

Per TDD-00109. **`tls.connect(port, host[, {rejectUnauthorized}][, onSecureConnect])`**
reuses the `net` TCP client wholesale and wraps the connected fd in TLS via a
small OpenSSL C helper.

- **Backend: OpenSSL libssl.** A new `codegen/llvm/tlssrc/tls.c` implements a tiny
  client ABI (`__kml_tls_client_connect`/`_read`/`_write`/`_free`) over
  `openssl/ssl.h`, compiled alongside the program and linked `-lssl -lcrypto`
  only when `tls` is used (`main.go`'s `UsesTLS()` block, mirroring the crypto
  backend's `UsesCrypto()`; reuses `LocateCrypto("openssl")`'s `-I/-L` discovery).
  OpenSSL-only: a `-crypto=commoncrypto` build that uses `tls` is a clean compile
  error (Mac's CommonCrypto has no TLS API). All `SSL_*` stays out of the emitted
  IR, same posture as the crypto backend.
- **Reuse net.** `@__kml_tls_connect` (runtime_tls.go) mirrors `@__kml_net_connect`
  — DNS-resolve, socket, **blocking** connect — then, on the still-blocking fd,
  `SSL_new` + `SSL_set_fd` + SNI (`SSL_set_tlsext_host_name`) + a **blocking**
  `SSL_connect`, with peer + hostname verification (`SSL_set1_host` +
  `SSL_get_verify_result`) unless `rejectUnauthorized: false`. Only on success
  does it switch the fd to non-blocking and register it in the existing net
  connection registry.
- **Socket = a net socket with an `SSL*`.** `netSocketIR` gained one field (the
  `SSL*`, null for a plaintext net socket — `calloc` zeroes it). The net
  read/write/close helpers and the dispatch read-loop branch on it: non-null →
  `SSL_read`/`SSL_write`/`SSL_free`, else raw `read`/`write`/`close`. So the whole
  net event-loop dispatch and `.on('data')`/`.write()`/`.end()`/`.on('close')`
  method surface is reused unchanged, and `tls.connect` returns a `NetSocketType`.

The blocking handshake matches `net.connect`'s blocking connect — the codebase's
established "outcome known at establish time" posture; a failure throws a
catchable `Error` rather than a deferred `'error'` event. A fully non-blocking
handshake would need a "retry when the fd is ready" event-loop primitive that
doesn't exist yet.

## Implementation notes

- The net runtime references the `__kml_tls_*` ABI unconditionally (the branches
  are dead for plaintext sockets). `emitTLSNetSymbols` (tls.go, at finalization)
  resolves them: extern `declare`s when `tls` is used (libssl provides them), else
  no-op stub `define`s so a plain-net program links — its sockets always have a
  null `SSL*`, so the stubs never run.
- The test harness (`tests/compiler_test.go`) gained `appendTLSBackend`, mirroring
  `main.go`'s `UsesTLS()` block so the two clang invocations can't drift.

## Scope / exclusions (V1)

- Client only; no `tls.createServer`. Blocking handshake. `{ rejectUnauthorized }`
  the only option (SNI = host; no `servername` override, client cert, or ALPN).

## Verification

- `tests/tls_test.go`: against a local `httptest.NewTLSServer` (self-signed):
  a full round-trip (`{ rejectUnauthorized: false }` → GET → response body), a
  verify-failure (default `rejectUnauthorized` against the self-signed cert →
  catchable `Error`), and connect-refused. Net/dgram suites still pass (the stub
  path).
- Manual real-host smoke: `tls.connect(443, "example.com", …)` + HTTP GET →
  `HTTP/1.1 200 OK` (verified, with cert verification + SNI on).
- `examples/tls/tls_client.ts` (excluded from `make examples`' offline run — it
  hits a real host).
- Machine: verified on Mac (arm64), Homebrew `openssl@3` (libssl). libssl is the
  same class of build dependency as libcurl/libcrypto (README Requirements).
