# ADR-00922: `replace`/`replaceAll` callbacks receive capture groups (invalid-IR sweep)

- **Date**: 2026-09-13

## Context

`String.prototype.replace(re, fn)` invoked `fn` as `(match, offset, string)` and
rejected any callback declaring more than three parameters — capture groups were
never passed. Real JS invokes the replacer as
`(match, cap1..capN, offset, string)`, where `N` is the pattern's capture-group
count. A declared-parameter replacer over a capturing pattern
(`(m, g1, g2) => g2 + g1`) therefore received the numeric `offset` in `g1`'s
`string` slot — a `double` value stored into a `ptr` field ("floating point
constant invalid for type" / "defined with type i64 but expected ptr").

Surfaced in the Test262 CLANG_ERROR sweep
(`built-ins/String/prototype/replace/S15.5.4.11_A4_T{1..4}.js`).

The count `N` was previously treated as unknowable at compile time. But for a
regex **literal** it is knowable: the pattern source is a compile-time string, so
its capturing groups can be counted directly — whether the literal appears inline
or is bound to a `const`.

## Decision

- When the pattern argument is statically a regex literal (inline, or an
  identifier bound to an unambiguous `const` regex literal), count its capture
  groups `N` and invoke the callback with the real
  `(match, cap1..capN, offset, string)` shape. Seed the callback's parameter
  hints accordingly (match + captures + string are `ptr`; offset is `i64`) and
  allow up to `N+3` parameters.
- When `N` is not statically known (a dynamic `RegExp`, a reassignable binding,
  or a plain-string search value), keep the `(match, offset, string)` narrowing
  and the 3-parameter cap. Capture groups are unavailable there — a documented
  limitation, not invalid IR.
- A replacer whose result is not a string is `ToString`'d before splicing
  (matching JS: `s.replace(re, () => 9)` → `"9"`), instead of reinterpreting a
  number's bits as a `ptr` passed to `strlen`.

## Implementation notes

- `codegen/llvm/emit_regexp_replace.go`: `regexSourceCaptureCount` (counts `(`
  opening a capturing group, skipping `(?:`/`(?=`/`(?!`/`(?<=`/`(?<!`, escapes,
  and character classes); `staticRegexCaptureCount`; a lazily-scanned
  `constRegexLiteral` map (`emitter.go` fields; ambiguous/shadowed names fall
  back). `resolveRegexReplacer` seeds hints from `N`;
  `emitRegexComputeOneReplacement` builds the argument sequence and `ToString`s a
  non-string result.
- An `arguments`-based replacer (`function () { return arguments[2] + ... }`)
  still cannot receive capture groups: `arguments` is synthesized from a
  function's *declared* parameters, so delivering call-time positional values
  needs a variadic `arguments` object — a separate, general feature. Such a
  callback no longer emits invalid IR (its non-string arithmetic result is now
  `ToString`'d); it runs to a defined result. The `S15.5.4.11_A4_T*` files use
  this form, so they move from CLANG_ERROR to a runtime near-miss rather than
  passing.

## Verification

- New E2E tests (`tests/string_replace_callback_test.go`): capture groups for
  `replace`/`replaceAll`, a `const`-bound pattern, capture-then-offset ordering,
  and a numeric-returning replacer — all matching Node. Existing zero-capture
  offset/string callbacks unchanged.
- `example/strings/replace_capture_groups.ts` added.
- Regex/replace test lane green; `S15.5.4.11_A4_T{1..4}` no longer CLANG_ERROR.
- macOS arm64.
