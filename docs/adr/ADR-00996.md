# ADR-00996: ES own-property enumeration order (integer keys first)

- **Date**: 2026-09-17

## Context

Object key enumeration used insertion/declaration order, diverging from the ES
own-property order Node follows: integer-index keys ascending numeric first,
then the rest in insertion order. `Object.keys({b:1,a:2,'2':3,'1':4})` returned
`['b','a','2','1']` (Node: `['1','2','b','a']`). Documented on the `for…in`
(language-constructs) and `Object.keys` (object-collections) rows, noting it
applies equally to `Object.values`/`entries`, spread, and `JSON.stringify`.

## Investigation

Two families of enumeration sites, static and dynamic:
- **Static objects** iterate `Type.VisibleFields()` — a compile-time field list
  — at `emitObjectKeys`/`Values`/`Entries` (emit_objects.go), for…in
  (emit_stmts.go), static `JSON.stringify` (emit_call_json.go), and inspect
  (emit_inspect.go). Physical field access is by name (`FieldIndex`), so the
  iteration order can be reordered without disturbing struct layout.
- **Dynamic (`any`) objects** enumerate through the D1 bag: `__kml_dynobj_keys`
  / `__kml_dynobj_keys_enum` (runtime_dynobj.go) for keys/for-in, and the
  embedded C walker (dynjsonsrc/dynjson.c) for JSON.
- Spread needs no direct change: the merged result is itself enumerated through
  these paths, so its observed order follows transitively.

## Decision

Apply the same ordering rule at every enumeration site. An "array index" is the
canonical decimal string of an integer in [0, 2^32-1) (no leading zero).

- Static: `esOrderedFields([]Field)` (emit_objects.go) returns fields with
  array-index-named fields sorted ascending numeric first, then the rest in
  declaration order — returning the input unchanged when there are no index
  keys (the common case, zero cost). Applied at all six static sites.
- Dynamic (IR): `__kml_dynobj_is_index` + `__kml_dynobj_es_reorder` reorder the
  key-pointer array both enumerators build, in place, before returning it.
- Dynamic (JSON, C): `es_is_index` + `es_order` in dynjson.c reorder the object
  serialization loop's entry indices.

## Implementation notes

- The index test is duplicated in three languages (Go, IR, C) by necessity;
  each carries a comment pointing at the others to keep them in sync.
- `esOrderedFields` reorders iteration only; `FieldIndex` still resolves the
  physical slot by name, so layout, initialization, and field reads are
  untouched — the reason a compile-time reorder is safe.

## Side effects discovered

`console.log`/inspect of an object now also follows ES key order (the same
`esOrderedFields`), for consistency with `Object.keys`. The pre-existing,
separately-scoped detail that inspect prints numeric keys unquoted (`2:` vs
Node's `'2':`) is unchanged.

## Verification

- New E2E tests: `TestE2EStaticObjectESEnumOrder`,
  `TestE2EDynamicObjectESEnumOrder`, `TestE2EObjectESEnumOrderNonIndexKeys`
  (leading-zero / out-of-range strings correctly stay non-index). Differential
  against `node` for static and dynamic objects across keys/values/entries,
  for-in, JSON (compact + pretty), and spread — all match.
- Both caveats removed; `make status`/`status-check`/`reference-check` and
  `make examples` clean.
