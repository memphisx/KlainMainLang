# ADR-01534: An async function's dynamic result is resolved, not awaited

- **Relations**: Extends ADR-00265, TDD-00223
- **Date**: 2026-10-10

## Context

In an async function whose result is `any`, `return v` of an `any`
value was compiled as `return await v`. The epilogue already resolves
the function's promise with the value as PromiseResolve does
(`__kml_promise_resolve_any`: a promise or thenable is adopted, anything
else fulfills it). The extra await settled the promise one microtask
late for a plain value (`async function a() { return x }` with `x: any`
ran its reaction after one returning a number), and turned a body with
no await into a suspending one.

## Decision

A value returned from an async function with an `any` result (an `any`,
or a promise boxed into one) is stored as it is, and both epilogues
resolve with it: the settled one as before, and a suspending body's
through `__kml_promise_resolve_any` too, after which the trampoline
leaves the promise alone (ADR-01536). An http.listen handler, whose
slot the dispatcher reads directly, still awaits.
