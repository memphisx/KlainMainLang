# ADR-01093: Function values render, name and measure themselves (code-pointer metadata)

- **Relations**: `Implements TDD-00229`
- **Date**: 2026-09-23

## Context

A differential pass of `node:ffi` needed bound native functions to behave as
function objects, and probing plain functions first showed the core had no
object side for function values at all:

- `console.log(f)` of a named function or arrow printed raw bytes: the closure
  header `{fnptr, env}` fell through `emitConsolePrintValueToken`'s arms to the
  `%s` printf of the header pointer.
- A function inside an object or array rendered `[Function]` (no name).
- A function boxed into `any` rendered `[Function (anonymous)]`; a built-in
  constructor reference (`const t: any = TypeError`) rendered `[Object]`.
- `f.name` / `f.length` did not compile.

Node renders `[Function: f]`, `[AsyncFunction: f]`, `[GeneratorFunction: f]`,
`[AsyncGeneratorFunction: f]`, `[Function: bound f]`, `[Function (anonymous)]`,
and names anonymous literals by ECMAScript NamedEvaluation (binding, property
key, assignment target, default, class field).

## Investigation

[TDD-00229](../tdd/TDD-00229.md) Stage A proposed growing the closure header to
`{fnptr, env, meta, props, dynrec}`. Counting header creators ruled that out as
a first step: 91 hand-built `malloc(i64 16)` sites across the codegen build
headers — promise resolvers, stream/HTTP callbacks, bind trampolines,
adapters — and several reach user code (`new Promise((res) => console.log(res))`
is legal). Every one would have to grow in lockstep or a metadata read would
run past a 16-byte allocation.

The metadata of a function is, however, a property of its **code**, not of the
header: every closure instance of one literal shares name, length and kind.

## Decision

Key function metadata by the code pointer.

- Each emitted function registers `{sym, name, length, kind}`
  (`fnmeta.go` `registerFnMeta`); at finalize the program gets one constant
  table `@__kml_fnmeta_tab` (`emitFnMetaFinalize`), emitted only when something
  renders or inspects a function.
- `fnmetasrc/fnmeta.c` resolves a header or a tag-12 record by linear scan of
  the table. An unregistered code pointer (every runtime-internal callable) is
  an anonymous plain function — Node's rendering for those too. Two kinds look
  *through* the env instead of naming the code: a bind trampoline
  (`FN_BOUND`, env[0] = target header → `bound <name>`, length = target's minus
  the bound count) and a closure/dynamic adapter (`FN_THROUGH_ENV`, env = the
  adapted header).
- Registration sites: arrows (`emitArrowFunctionWithHints`), function
  expressions, named functions as values (the `@__fnval_<f>` trampoline, with
  the source name threaded in), dynamic-ABI callables, both adapter families,
  bind trampolines, generator constructor closures.
- Names come from `inferFunctionNames`, a reflective AST pre-pass implementing
  NamedEvaluation (var declarator, `=`/`&&=`/`||=`/`??=` to an identifier,
  object-literal key, parameter default, class-field initializer; through `as`
  and `!`). Reflective so AST nodes added later are walked without edits.
- `length` follows `Function.prototype.length`: parameters before the first
  default or rest one; a TS-optional `x?` counts (it is a plain parameter once
  types are stripped).
- Consumers: the top-level `console.log` arm, the struct-field/array inspector
  (`emitInspectField`), the dynamic inspector (tag 12 via
  `__kml_fn_inspect_dyn`, tag 8 as `[Function: Name]`), and `f.name`/`f.length`
  statically and through `any` (a `dynget` arm for tags 12 and 8; built-in
  Error constructors report length 1).

The header layout is unchanged, so no existing call site moved.

## Implementation notes

`fnmeta.c` is a new embedded C member (`EmbeddedCSources`, and the test
harness's `appendFnMeta`). `dynjson.c` calls `__kml_fn_inspect_dyn`, so
`ensureDynJSONC` ensures fnmeta. The registration map dedupes by symbol (a
memoized trampoline registers once).

## Side effects discovered

- The test harness selects C members with its own per-member `append*`
  helpers instead of `EmbeddedCSources`, so a new member must be added in two
  places (13 builders); a missed one fails every dependent test at link time.
  Recorded in BACKLOG.
- Not done here (TDD-00229 Stage A remainder, in BACKLOG): boxing the same
  closure twice yields two records (not `===`), no reverse adapter from a
  tag-12 value to a typed function slot, no own properties on user functions,
  `Function.prototype.toString` source text, `[class X]` for class values.
