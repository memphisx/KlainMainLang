# ADR-00259: Generator protocol completion — `.throw()`, `.return()`, `yield*`

- **Relations**: `Implements TDD-00086`; builds on [ADR-00172](ADR-00172.md) (generator fiber), [ADR-00244](ADR-00244.md) (fiber-safe exceptions)
- **Date**: 2026-08-20

## Context

Generators ([ADR-00172](ADR-00172.md)) had `.next()`/`yield` but not the rest of
the iterator protocol. TDD-00086 scoped the three missing pieces —
`.throw(e)`, `.return(v)`, `yield*` — plus a folded-in fix (a `return` inside a
generator's `try/finally` never ran the `finally`).

## Decision

### Resume-mode dispatch at the `yield` point

Three new generator fields — `__resumeMode` (i64), `__thrown` (ptr), and the value
reusing `__sent` — let each resumer pick how the suspended `yield` continues.
After a `yield` swaps back in, `emitYieldResumeDispatch` switches on `__resumeMode`:
`0` returns `__sent` (normal `.next(v)`); `1` throws `__thrown` at the suspension
point (`emitThrow`'s `__kml_throw`, so a body `try/catch` handles it); `2` runs
enclosing finallys (`emitPendingFinallys`) then completes with `__sent`.
`emitGeneratorReturn` (the `return` statement) now also runs `emitPendingFinallys`
— the folded-in `finally` fix.

### Per-generator jmpbuf-stack isolation + an outer body catch-all

The exception jmpbuf stack is a single global (`@__kml_jmp_top` over
`@__kml_cur_jmp_stk`). With a generator and its caller alternating fibers, a
caller `try` pushed after the body's own `try` would sit *above* it, so an
injected `.throw()` would longjmp to the wrong frame. Two changes fix this
soundly, mirroring how coroutine tasks already isolate ([ADR-00244](ADR-00244.md)):

- **Each generator gets its own jmpbuf stack** (`__jmpStk`, 16×512 bytes) and a
  saved top (`__jmpTop`). `emitGeneratorSwapIntoBody` activates it across every
  swap into the body and restores the caller's afterward — so caller and body
  try-frames never interleave.
- **The body is wrapped in an outer catch-all** (sync generators only): a throw
  that escapes every body `try` — or an injected `.throw()` with no handler, or a
  throwing `.return()` finally — lands in the bottom-most frame of the
  generator's own stack, which records the error in `__genError`, marks the
  generator done, and swaps back. The resumer (`emitGeneratorSwapIntoBody`)
  re-throws it on the *caller* side, where the caller's jmpbuf stack is active
  again. So `.next()`/`.throw()`/`.return()` never push a caller-side frame and
  nothing inverts.

### `.throw(e)` / `.return(v)`

Dispatched on `IsGenerator` alongside `.next` (emit_call.go). A not-started or
done generator: `.throw()` throws to the caller, `.return(v)` yields
`{value: v, done: true}` without running the body. A suspended generator resumes
in mode 1 / mode 2 through the shared swap helper. Both are exposed as
by-value helpers (evaluated instance + error/value) for `yield*` forwarding.

### `yield*` delegation

`emitYieldStar` lowers `yield* inner` to a loop over the inner generator: it
re-yields each inner value and evaluates to the inner's return value. V1 requires
the inner operand to be a (sync) generator of the same element type — a general
iterable needs `Symbol.iterator` (TDD-00044). On resume it forwards the caller's
action into the inner: `.next(v)` sends `v`, `.throw(e)` calls the inner's throw
(the inner may catch), `.return(v)` calls the inner's return and then completes
the outer with the inner's (finally-adjusted) return value.

## Consequences

- `.throw()` (caught in the body, or propagated to the caller), `.return()`
  (running finallys, and the not-started case), `yield*` (delegation, sent-value
  forwarding, return-value, and `.throw()`/`.return()` forwarding) all work on
  sync generators. A `return` inside a generator `try/finally` now runs the
  `finally`.
- Every generator now carries its own jmpbuf stack + outer catch-all, so a throw
  inside a generator body is robust even when the caller has interleaving `try`s
  — not only via `.throw()`.
- Out of scope (unchanged): `.throw()`/`.return()` on an **async** generator (a
  follow-on — async generators keep their per-`.next()` setjmp path); `yield*`
  over a non-generator iterable; a `yield` reached *inside* a `finally` during a
  `.return()`.
