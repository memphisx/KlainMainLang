# ADR-01725: Function source text, identity through `any`, own object-literal accessors

- **Relations**: `Implements TDD-00230`, Extends [TDD-00229](../../tdd/TDD-00229.md)
- **Date**: 2026-10-18

## Context

Function objects still differed from Node in several ways:

- **Source text:** `String(f)` gave `function f() { [native code] }` for every compiled function and class. Node gives the source text, with the type syntax blanked to spaces by its type stripping.
- **Identity:** a function unboxed from `any` into a typed slot became a new thunk. `promisify(pp) === pp` was false, as was `===` between two typed slots filled from one `any`.
- **Structural targets:** an accessor-bearing object literal could not be assigned to a structural type.
- **Object-literal accessors:** an accessor-bearing object literal is lowered to a synthetic class, so its accessors behaved like prototype accessors. `Object.keys`, `for...in`, JSON, spread, `Object.entries`/`values` and `hasOwn` skipped them. Inspect did not show `[Getter]`, `getOwnPropertyDescriptor` returned `undefined`, and a class getter was named `__kml_get_z`.
- **Generic declarations as values:** reading a generic function or class as a value (`const f = id`, `String(K)`, `K.prototype`) was an "undefined variable" error.
- **Methods returning `this`:** on a generic class, these failed with an internal conversion error.
- **`Function.prototype`:** it read as `undefined`. A function value's `toString`/`call`/`apply`/`bind` read through `any` were `undefined` too.
- **Local types:** an interface or type alias declared in a function body did not resolve in codegen, because codegen registers types by name at the top level only.

## Decision

### Source text

- The parser keeps the file text and the ranges it blanks: type annotations, type-parameter lists, call and `new` type arguments, `extends` type arguments, TS-only member modifiers, the `?`/`!` field markers, and whole `declare`, `abstract` or body-less members.
- Every function, arrow, method, accessor and class records its source range:
  - a method's range starts at its modifiers and name (`async *m`, `get g`);
  - an async arrow's starts at `async`;
  - a declaration's starts at `function` or `async`.
- The function-metadata row gains a fifth field: the source text, with blanked ranges as spaces. `__kml_fn_tostring_dyn` returns it when present.
- A class reference gets a metadata row keyed by its payload pointer. `__kml_classref_tostring` returns the class's source. This replaces the 64-byte `sprintf` buffer, which overflowed on a long constructor name.
- `K.toString()` on a class name calls the same routine; it used to be "no static method".
- A method call on a function's own object (`parseInt.toString()`) goes through the dynamic method call with its receiver bound. It used to call the boxed member as a closure, which was invalid IR.

### `Function.prototype`

- `Function.prototype` is a value: a shared function that does nothing.
- Its `toString`, `call`, `apply` and `bind` are dynamic-ABI functions acting on their receiver, each with its own static record and metadata row (`fnproto.go`). They are generated with the emitter's own instruction builders.
  - `bind` builds the existing dynamic bound-function form, so the result renders as `bound f`.
- A function or class value without an own property of that name reads the method unbound, so `Function.prototype.toString.call(f)` and `(g as any).call.call(f, …)` work.
- `Object.getPrototypeOf` gives `Function.prototype` for a function. For a class reference, a generated routine gives the class it extends, else `Function.prototype`.

### Identity

- `__kml_fn_identity_dyn` follows a thunk of a function unboxed from `any` to that function's identity, as it already followed adapters.
- `__kml_fn_identity_hdr` is now the same walk.

### Object-literal accessors

- The synthetic class records its property names in source order (`OwnKeyOrder`), and its shape row lists them as its own keys.
- A getter read answers as an own property. A setter alone reads `undefined`.
- Reserved keys `\x01@@get:k` and `\x01@@set:k` return the accessor functions. From them, `__kml_shape_own_desc` builds `{ get, set, enumerable, configurable }` and inspect shows `[Getter]`, `[Setter]` or `[Getter/Setter]` without running the getter.
- Key enumeration, JSON, inspect, `entries`/`values`, `hasOwn`/`in` and spread take the value's boxed form. Spread runs each getter, as Node does.
- A class accessor's function is named `get z` or `set z` and carries its source text.
- **Structural targets:** such a literal may now be assigned to a structural type (`const p: { x: number } = o`), which reads and writes its accessors through its layout row.
  - Before, this was a compile-time rejection.
- **Layout rows for views:** every class with a member that a view routine reads now gets a layout row. Previously a class instance stored as is into a structural slot had none, so a write through the view threw `dynamic property access on a statically-typed value`. A class with only a setter was affected the same way.

### Generics and local types

- **Generic declarations as values:** a generic function or class read as a value is its erased instantiation, with every type parameter `any`. That is the one function JavaScript has. Its type is computed without emitting code.
- **Instantiation scope:** a generic function's instantiation now sees only its own type arguments. It used to also see the instantiating site's type parameters, so `box<any>` could get a different return layout depending on where it was first made.
- **Erased results:** the return layout of a generic function read as a value gets a layout row, since its results reach callers as values of any shape.
- **`this` returns:** a generic class method returning `this` returns the instantiation's own instance.
- **Generic class members:** a generic class's generator methods (`*[Symbol.iterator]()`, `async *m()`) build per instantiation like any other method. Its static fields and `static {}` blocks join its static methods on the one non-generic companion class, so all instantiations share them, as JS's single class object does.
- **Chained `this` returns:** `new K<T>().add(1).add(2)` used to infer the first call as a number when no earlier construction had registered the instantiation.
- **Local types:** before codegen, each block's interfaces and type aliases are renamed to their own top-level names, and the annotations inside the block are rewritten to match. Inner blocks are processed first, so an inner redeclaration wins. The checker has already run against the original names.

## Verification

macOS (Apple Silicon):

- New tests in `tests/function_source_test.go` match Node:
  - function and class source text;
  - identity through `any`;
  - object-literal own accessors;
  - local types and generic values.
- The new example `examples/function_expressions/source_text.ts` also matches Node.
- The function-object, accessor, generic and class-reference suites and the codegen unit tests pass.
