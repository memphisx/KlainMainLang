# TDD-00196: `ReadableStream.read()` / `desiredSize` — the last `T | undefined` adopters

- **Status**: Implemented
- **Date**: 2026-09-10

## Context

[TDD-00187](TDD-00187.md) retired the zero-fill caveat family by giving
absence-capable operations a real `T | undefined` result, reusing
[TDD-00064](TDD-00064.md)'s presence-flagged `{ i1, T }` optional. Its Stages
1–4 shipped ([ADR-00778](../adr/ADR-00778.md)–[ADR-00781](../adr/ADR-00781.md)),
but [ADR-00781](../adr/ADR-00781.md) explicitly left two stream-shaped members
out, as "a record-shape design of its own":

- **`reader.read()` after close** returns a `{ value, done }` record whose
  `value` field was bare `T` — so a closed read yielded the chunk type's zero
  (`0`/`""`), not `undefined`. TS types the result
  `{ done: false; value: T } | { done: true; value?: undefined }`.
- **`controller.desiredSize`** returned a plain `double` — `0` for both the
  closed and the errored state. The spec's `desiredSize` is `number | null`:
  `null` once **errored**, `0` once **closed**.

These were the only remaining inhabitants of the zero-fill family
(`docs/status/data/streams.json`). Flipping them is mostly a reuse task, not a
new representation — the sentinel, its storage, inference, the strict/compat
policy, and every consumer path (`===`, `??`, `!`, console rendering) already
exist from TDD-00187/00064.

## Design

**`read()` result record — a dedicated type.** A generator's `.next()` result
keeps its bare-`T` `value` (tsc types it `any`, so the current typing is already
*stricter* than TS — flipping it is a non-goal, [ADR-00781](../adr/ADR-00781.md)).
Streams need the opposite, so `read()` gets its own record shape
`streamReadResultType(chunkTy)` = `{ value: undefinedableElem(chunkTy), done:
bool }`, distinct from `genNextResultType`. `undefinedableElem` (TDD-00187
Stage 1) gives a scalar chunk the `{ i1, T }` optional and a pointer chunk the
null pointer; an **array/tuple/dynamic** chunk passes through unchanged (an
array slot has no spare absent state — [ADR-00246](../adr/ADR-00246.md)), so an
array-chunk stream keeps its documented zero-on-close behaviour.

The record is built by the per-site fulfill thunk and consumed by the for-await
loop and the pipe/tee decode thunk — all internal, all centralized through two
helpers (`buildStreamReadRecord` stores `value` in its field type with
`present = !done`; `loadStreamResultValue` demotes the field back to a bare
chunk on the `done:false` path those readers only run on). The user-facing
`rec.value` read rides the ordinary object-field machinery, which already reads
a nullable-scalar field as a real `T | undefined` (TDD-00187 Stage 2).

**`desiredSize` — `number | null`.** The runtime `__kml_rs_desired` still
returns `0` for both closed and errored; the emit site reads the stream's state
word (field 0; `2` = errored) and wraps the double as a `{ i1, double }` optional
with `present = state != 2`. Absent renders `null` (not `undefined` — the field
is `T | null`, no `IsUndefined` flag), matching the spec.

**The one real decision — hot-path narrowing.** TS's discriminated union lets
`if (!res.done) { res.value /* : T */ }` use `value` with no assertion. This
compiler does not narrow a record field on a *sibling* field's value, so under
strict mode a bare-`T` use of `res.value` needs `!` or `if (res.value !==
undefined)` (the latter narrows via the existing nullable-local machinery once
destructured). This is the same strict/`-compat=js` policy TDD-00187 Stages 1–4
established — honest strictNullChecks in strict mode, auto-widening in
`-compat=js` — not a new concept. Full `done`-discriminant field narrowing was
considered and rejected as out of scope: it is a general flow-analysis feature,
disproportionate to retiring two caveat rows, and the `!`/destructure-narrow
idioms are valid TS.
