# ADR-00468: namespace-body statements; `export declare` pass-through

- **Relations**: Extends [ADR-00453](ADR-00453.md), [ADR-00462](ADR-00462.md)
- **Date**: 2026-08-29

## Context

The remaining `unsupported namespace member` bucket was largely executable
statements in namespace bodies (`module M { init(); }` — real TS runs them
at namespace initialization), and `'export' can only precede …` was partly
top-level `export declare namespace/var/…` (ambient) forms.

## Decision

- A namespace-body member that isn't a declaration parses as an ordinary
  statement and flattens to top level in declaration order — the same
  ordering every desugared member already gets; genuinely invalid input
  still errors from `parseStatement`.
- `parseExportDeclaration` passes an erased form through unwrapped: an
  ambient `export declare …` (and an exported namespace's own
  empty-desugar) arrives as the empty block its parser returns.

## Verification

Mac. `tests/namespaces_test.go` E2E (statement ordering across a
namespace + ambient top-level form) and the example extension pass;
parser + namespace/ambient/export batches green. TS oracle agreement
5145 → 5150 (55.6%). Node oracle unchanged (40).
