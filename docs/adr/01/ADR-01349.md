# ADR-01349: `util.parseArgs`; spread `push`/`unshift`; nullable array literals; custom inspect depth; inferred type arguments checked against constraints

- **Relations**: Extends ADR-01300, ADR-01341
- **Date**: 2026-10-03

## Context

`util.parseArgs` was missing. That matters for the command-line tools this
project targets (`process`/argv is priority 3). Porting it, and checking
`util`'s status row, found these compiler bugs:
- `arr.push(...items)` and `arr.unshift(...items)` did not compile ("a
  spread is only supported inside an array literal or …").
- An array literal mixing `null` with one other kind took the first
  element's type: `[null, { k: 1 }]` lost the object, and
  `[{ k: 2 }, null]` printed scrambled.
- `util.inspect(obj, { depth })` called a class's `[inspect.custom]` with
  the compile-time default depth, 2, not the configured one. So `%o`'s
  depth 4 never reached it. The status row and the website reference also
  claimed custom inspect methods do not apply to `util.inspect`, which was
  wrong.

Separately, backlog 40: a generic call's arguments were not checked at all
(`checkCall` returned for a generic callee), so
`crypto.getRandomValues(xs)` with `xs: number[]` was no TS2345.

## Investigation

- Node's `lib/internal/util/parse_args/parse_args.js` and `utils.js`,
  read from the running Node's built-in sources, were ported line by line.
  The error messages come from its `internal/errors` definitions:
  `ERR_PARSE_ARGS_UNKNOWN_OPTION` with its `--` suggestion,
  `…_INVALID_OPTION_VALUE`, `…_UNEXPECTED_POSITIONAL`, and
  `validateUnion`'s `must be ('string|boolean')`.
- `emitPush`/`emitUnshift` grow by a compile-time count, so a spread,
  whose count is known only at run time, was rejected before them.
- `inferArrayType`'s last fallback was the first element's type. The mixed
  element path (`inferMixedArrayElem`) needs two kinds, so one kind plus
  `null` fell through to it.
- The custom-inspect thunk shared by the run-time inspector subtracted the
  depth from `effectiveInspectDepth()`, a compile-time value, instead of
  reading `__kml_inspect_opt_depth`, which `util.inspect` sets.

## Decision

1. **`lib/node/internal_util_parse_args.ts`** is Node's tokenizer, its
   strict checks, its storage (into an `Object.create(null)` values object,
   with `__proto__` ignored) and its defaults. `util` exports `parseArgs`
   and its config types.
2. **Spread `push`/`unshift`:** the arguments are built as one array of the
   element type, spreads expanded in order. Then the array grows once, with
   `realloc` and `memcpy` (plus `memmove` for `unshift`), and the new length
   is returned.
3. **Nullable literal elements:** one kind with `null`/`undefined` among it
   is that kind, `Nullable` when it is a reference, as TypeScript's
   `(T | null)[]`.
4. **Custom inspect depth:** the run-time hook loads
   `__kml_inspect_opt_depth`. The method gets the levels left, and
   `options.depth` is the configured depth, or `null` when unlimited. A
   `console.log` site keeps its compile-time depth.
5. **Inferred type arguments and their constraints:** for a generic call
   without explicit type arguments, each argument whose parameter is a
   bare constrained type parameter (`f<T extends C>(x: T)`) is checked.
   When its inferred type is not assignable to C (missing members count),
   the argument is checked against C, as tsc falls back to the
   constraint: TS2345, or TS2353/TS2741 elaborated on an object literal.
   The rest of a generic call's arguments are still not checked against
   the instantiation.

## Implementation notes

- **Libraries:** `lib/node/internal_util_parse_args.ts` and
  `lib/node/util.ts`.
- **Codegen:** `codegen/llvm/emit_arrays_mutate.go`
  (`emitArrayInsertSpread`), `emit_exprs_types.go` (`inferArrayType`) and
  `emit_inspect.go`.
- **Checker:** `checker/check.go` (`checkInferredConstraints`).
- **Docs:** the util status row and the reference entry now list
  `[inspect.custom]` among what applies.

## Side effects discovered

- An unlimited depth reaches a custom method's `depth: number` parameter as
  `Infinity`. Node passes `null`, which a number parameter cannot hold.
- `(number | null)[]` elements still have no storage (backlog 60). Only
  reference kinds become nullable here.
