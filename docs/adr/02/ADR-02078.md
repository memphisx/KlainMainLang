# ADR-02078: A BigInt64Array's elements copy out as bigints

- **Relations**: Implements TDD-00230
- **Date**: 2026-11-24

## Context

Found while verifying ADR-02076. With `t = new BigInt64Array([1n, -2n])`:

- `Array.from(t)` printed `[ 104118149796912, 104118149797216 ]`, and
  `a[0] === 1n` was false;
- `[...t]` crashed with a segmentation fault;
- `Array.from(t, x => x * 2n)` threw `Cannot mix BigInt`.

## Investigation

- A BigInt64Array or BigUint64Array stores plain 64-bit words; the
  array type carries `BigIntElem`, and an element read converts the
  word to a bigint through `wrapTypedArrayLoad`.
- `emitArrayFrom` copied the storage with `memcpy` into an array of the
  element type (i64), and the type rule for `Array.from` named the same
  type, so the result held raw words where bigints belonged. The mapFn
  form goes through the same rule, so its callback got numbers.
- The spread copy (`emitSpreadArrayLitData`) took the element type from
  `resolveArrayForHOF` (i64) and converted each word to the
  destination's bigint, reading the word as a bigint pointer.

## Decision

- `emitBigTypedElemsLoop` writes each element of a big typed array's
  storage to a destination array as `wrapTypedArrayLoad` of its word,
  boxed for an `any` destination and converted for any other.
- `Array.from` of a big typed array is `bigint[]`, built by that loop.
- A spread records its source's type when it is a big typed array, and
  copies it with that loop.

## Implementation notes

- `codegen/llvm/emit_arrays_core.go`: `emitBigTypedElemsLoop`, the
  `big` field of `spreadSrc`.
- `codegen/llvm/emit_arrays_iter.go`: the branch in `emitArrayFrom`.
- `codegen/llvm/emit_exprs_types.go`: the `Array.from` type rule.

## Verification

- `TestE2EBigIntTypedArrayElementsAsBigints`: `Array.from` with and
  without a mapFn, spreads before and after other elements, for-of, a
  BigUint64Array holding 2^64-1, and a spread into `any[]`, each
  matching Node. Passes on Linux x86-64 and macOS arm64.
