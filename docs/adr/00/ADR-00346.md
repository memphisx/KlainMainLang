# ADR-00346: `wss://` — the WebSocket client over TLS

- **Relations**: Extends TDD-00039 (WebSocket) Stage 4; reuses ADR-00344 (`tls` / libssl)
- **Date**: 2026-08-24

## Context

The WebSocket client was `ws://` only — `wss://` threw. Now that a libssl TLS
layer exists (ADR-00344's `tls`), the client can wrap its socket in TLS.

## Decision

`new WebSocket("wss://…")` is accepted. After the (blocking) TCP connect, the
client runs a blocking `SSL_connect` handshake (`__kml_tls_client_connect`, cert
verification + SNI on — the same helper `tls.connect` uses), then does the WS
HTTP upgrade and all framing over TLS.

**fd→SSL registry, not a threaded `SSL*`.** Rather than thread an `SSL*` through
the WS client's many functions, a small thread-local fd→SSL registry
(`__kml_wsc_tls_set/get/clear`) holds each wss socket's `SSL*`. Every WS I/O site
routes through `__kml_wsc_io_read`/`__kml_wsc_io_write(fd, …)`, which look the fd
up: a hit (wss) → `SSL_read`/`SSL_write`, a miss (`ws://`, or a cleared entry) →
raw `read`/`write`. So the change is five `read`/`write` → `io_read`/`io_write`
swaps plus the handshake insert — the `ws://` path is byte-for-byte the raw path.
`close` clears the entry (`SSL_free` + null), so a reused fd never sees a stale
`SSL*`.

Default port is scheme-derived (443 for `wss`, 80 for `ws`). A WebSocket URL's
scheme is a runtime value, so any WebSocket program links libssl (via the WS
client setting `usedTLS`) — the honest cost of runtime `wss` support; `ws://`
programs simply never populate the registry.

## Scope / exclusions

- **Client only** — there is no server-side `wss` TLS listener (front a `ws://`
  server with `tls`/a reverse proxy).
- Cert verification is always on (browser-like) — no `rejectUnauthorized` opt-out.
- Inherits the WS client's existing limits (blocking connect/handshake, no binary
  `.send()`, numeric-IP-only host resolution on macOS).

## Verification

- `tests/wss_test.go`: a local `httptest.NewTLSServer` whose handler hijacks the
  connection and speaks the WebSocket handshake + a masked-frame echo — a real
  TLS + WebSocket peer at 127.0.0.1. The client trusts the self-signed cert via
  `SSL_CERT_FILE`; a full round-trip (`send` → echo) confirms TLS both
  directions. The `ws://` client suite still passes (registry miss → raw path).
- Machine: verified on Mac (arm64), Homebrew `openssl@3`.
