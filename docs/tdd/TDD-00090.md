# TDD-00090: A Promise is a reusable value — `await`/combinators stop consuming the slot

- **Status**: Implemented (see ADR-00270)
- **Date**: 2026-08-20

## Context

`await` and the `Promise` combinators (`Promise.all`/`.race`/`.allSettled`/`.any`) each
`free()`d the promise slot after reading it. That made a promise **single-consumption**: the
second read of the same promise was a use-after-free (SIGTRAP). Grounded, all real JS:

```ts
const p = f(42)
console.log(await p)   // 42
console.log(await p)   // JS: 42 — this compiler: SIGTRAP (exit 133)
```
```ts
const p = f(5)
const arr = await Promise.all([p])   // frees p's slot
console.log(await p)                 // use-after-free
```
```ts
await Promise.all([p, p])            // double-free within one combinator
```

This is severe: it made the `await` row's zero-caveat **"strict"** claim untrue (the project's own
"a zero-caveat row is a claim nothing is wrong — verify it" discipline), and it was the real
content behind the combinator row's "a member can't be reused after" caveat. In ECMAScript a promise is
an ordinary value you may `await` any number of times and pass to any number of combinators;
settling is idempotent and reads are non-destructive.

## Investigation

The frees are: `emitAwaitTaskPromise` (`emit_async.go` — the task-promise path, three sites:
reject/void/value), the generic `emitAwait` non-task path (void + value), and every combinator
branch in `emit_promise.go` that loaded a member slot (`emitTaskCombinatorAwaitEach`, the
already-resolved `.all`/`.race`/`.any` paths, both `.allSettled` paths). The `.race`/`.any`
**task** paths already did *not* free the winner — proof the read is non-destructive and the
free was the only thing breaking reuse. The `.race` "may not return the shortest-delay member"
caveat was separately **verified stale** — `__kml_timer_fire_next` fires strictly earliest-due
and the event-driven waiter list wakes the awaiter, so a `setTimeout`-raced set returns the
shortest delay (confirmed with 2/3/5-member races in both array orders).

The reads themselves (`loadPromiseValue`, the settled-state check) never mutate the slot, so the
only question is **ownership**: who frees the promise? Options considered:

1. **Refcount each promise slot.** Correct and leak-free, but adds a retain/release discipline to
   every promise-producing and -consuming site (await, combinators, `.then` chaining, task
   settle) — a large, error-prone surface for a value that is 40 bytes.
2. **Escape analysis** to free only provably-last reads. The compiler has no such analysis for
   promises, and it would still be conservative.
3. **Stop freeing; let the slot leak in manual mode, collected under `-mm=gc`.** A promise is
   then an ordinary heap value with the same lifetime story as every other allocation this
   project's manual mode already leaks (the `Memory.free`-is-opt-in model). Zero new discipline;
   the read sites simply don't free.

## Decision

**Option 3.** `await` and the combinators read the promise slot and do not free it. A promise is
a reusable value: `await p; await p`, `await p` after a combinator, and the same promise twice in
one combinator all work. The 40-byte task-promise struct (or the small value/void slot) leaks in
manual mode — the same ambient behavior every unreclaimed allocation has — and is collected under
`-mm=gc`. ASan's leak check is already disabled project-wide (`detect_leaks=0`,
`asanOptionsSource`), consistent with this model.

**Fetch is covered too — it turned out to be the same root cause.** A raw-fetch
`Promise<Response>` was expected to need a new representation, but investigation showed the
pending struct is **never freed** (like every fetch allocation — `runtime_fetch.go`),
`__kml_await_fetch` already short-circuits an already-done handle (`chkdone` → `finish`), and
`__kml_pending_finish` is a non-destructive read of the stored status/body. So the only thing
breaking fetch reuse was the same slot `free` — removing it (at both the `await` site and the
combinator's `buildPendingMembersArr`) makes `await r; await r` and reuse-after-combinator
re-read the finished Response. One safety fix was needed: `__kml_await_fetch` must check *done*
before the abort signal, so a re-await of a completed fetch never re-enters the abort teardown on
its already-cleaned easy handle (a second `curl_easy_cleanup` would be a double free).

## Stages

1. **Task-promise await** stops freeing (reject/void/value). Verify `await p; await p`.
2. **Generic non-task await** stops freeing (void/value).
3. **Combinators** stop freeing member slots (`.all`/`.race`/`.allSettled`/`.any`, task +
   already-resolved + fetch paths). Verify combinator-then-await and same-promise-twice.
4. **Fetch** stops freeing its `Promise<Response>` slot at `await` and in the combinator; reorder
   `__kml_await_fetch` to check done before the abort signal. Verify fetch double-await and
   fetch-member reuse after `Promise.all`.
5. **Regression battery + stale-caveat removal.** Double-await, member-after-combinator,
   same-promise-twice, allSettled reuse, fetch double-await, fetch reuse-after-combinator; remove
   the verified-stale `.race` timer-ordering caveat.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| Non-destructive promise read (`loadPromiseValue`, state check) | Built | the read never mutated the slot |
| `-mm=gc` reclaims leaked slots | Built | Boehm GC ([ADR-00100](../adr/ADR-00100.md)) |
| ASan leak check disabled project-wide | Built | `detect_leaks=0` (`asanOptionsSource`) |

## Open questions

- **Long-running manual-mode programs.** A server awaiting millions of promises under `-mm=manual`
  leaks one small slot each. Acceptable for the target (the `-mm=gc` path collects them, and a
  crash-on-reuse is strictly worse than a bounded leak); a future refcount/pool could reclaim them
  without changing semantics. Out of scope here.
- **Fetch `Promise<Response>` reuse.** Closed here (same root cause — see the Decision section);
  no representation change was needed once the pending struct's never-freed, non-destructive-read
  nature was confirmed.
