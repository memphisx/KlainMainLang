# ADR-00647: Standard-dialect field/addInitializer decorators + typed dynamic-function parameters

- **Relations**: `Implements TDD-00161` (Stage 5, construction-time sub-stage), `Extends ADR-00645`
- **Date**: 2026-09-02

## Context

The standard (TC39) decorator dialect's remaining construction-time placements:
instance **field** decorators (which return an initializer that transforms the
field's initial value per-instance) and **`context.addInitializer`** (callbacks
that run per-instance during construction). Both need decorator-driven logic
injected into the constructor, which is emitted before decorator application.

While wiring field initializers, a blocking limitation surfaced: a dynamic
function (any closure boxed into an `any`/decorator position — a tag-12 record)
bound *all* its parameters as `any`, so a typed initializer body like
`(initial: number) => initial * 2` failed with "operator on any/unknown".

## Decision

### Typed parameters + captures in dynamic functions

Two general improvements to `emitDynCallable` (`emit_dynfunc.go`), benefiting
every dynamic function (any closure boxed into an `any` position), not just
decorators:

- **Typed parameters**: a parameter with a concrete declared type binds to
  *that* type — unboxing the received argument box to it — so the body can do
  typed operations (`(initial: number) => initial * 2`). An unannotated /
  `any` / `unknown` / array / nullable-scalar parameter stays a boxed `any`.
- **Captures**: a dynamic function that references an enclosing local now
  captures it (previously a clean rejection). The capture uses the exact
  shared-heap-cell mechanism arrows/closures use (`promoteCaptureToCell`,
  `envStructIR`), packed into the tag-12 record's env (previously always null)
  and read back in the body from `%env`. This is the linchpin that makes
  factory decorators returning an `any`-typed capturing closure, wrapping method
  decorators, and capturing `addInitializer` callbacks all work.

### Construction-time standard decorators

- **Registration** (`registerDecoratedMethodSlots`, standard dialect only): a
  per-field `__fieldinit` global (a boxed initializer, `undefined` for none) for
  each decorated instance field, and a per-class `__initlist` global (a dynamic
  array of `addInitializer` callbacks).
- **`context.addInitializer`** is a generated per-class tag-12 callable
  (`emitAddInitializerFn`) that pushes its argument onto the class's init list
  (creating the array on first use); it's set on every member's `context`.
- **Application** (`emitStandardDecoratorApplications`): a field decorator is
  called `(undefined, context)`; a returned callable is stored in the field's
  init slot.
- **Constructor tail** (`emitStandardConstructorTail`, run at the end of the
  constructor via the `e.currentCtorClass` hook): for each decorated field, if
  its slot holds a callable, `this.field = initializer(this.field)`; then every
  `addInitializer` callback runs with `this` as receiver.
- **Constructor synthesis**: a standard-decorated class with no fields and no
  explicit constructor now gets a synthesized one, so the tail runs (previously
  a field-less decorated class emitted no constructor and the callbacks silently
  never ran).

## Side effects discovered

- The dynamic-function capture fix broadened this delivery beyond decorators:
  every dynamic function (prototype methods under `-compat=js`, dynamic-object
  function properties, object-method-shorthand callbacks) can now capture, so it
  is verified across the full suite rather than only the decorator tests.
- Still a sub-stage of the standard dialect: `accessor x` auto-fields (new
  syntax), getter/setter decorators, and static-field decorators — all clean
  rejections. The dynarr runtime must be `ensureDynArr`'d wherever the
  constructor tail / addInitializer list touches it (a linking bug fixed here).

## Verification

- `tests/decorators_test.go`: standard field initializer (typed `initial * 2`),
  `addInitializer` running per-instance, static-field rejection.
- Smoke-tested field transforms and addInitializer under `-decorators=standard`;
  experimental dialect + factory decorators unaffected.
- `go vet`, full `make test-par`, decorator/class/closure/HOF suites, node
  oracle, `status-check`/`reference-check`. Mac (Apple Silicon).
