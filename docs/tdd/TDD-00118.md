# TDD-00118: `http.closeAllConnections()` — forceful in-flight teardown

- **Status**: Implemented

## Context

`http.close()` is graceful: it stops accepting and lets already-open connections
finish (TDD-00027). Node pairs that with `server.closeAllConnections()`, which
*forcefully* terminates in-flight connections. The absence of a forceful variant
was the last caveat on the `http.close()` HTTP-Server row after cross-worker
close (TDD-00117) landed. Scoped now as the second item of the HTTP-Server
caveat-cleanup pass.

## Design

Each in-flight connection is a suspended fiber — a `ucontext_t` + a malloc'd
stack, parked mid-read at a `swapcontext` (`runtime_http.go`'s
`__kml_http_append_conn` / event loop). The obvious "force close" — free each
fiber's context/stack from outside — is the dangerous path: the fiber is exactly
the machinery that owns its own socket close and active-count bookkeeping, and
tearing down a stack mid-`swapcontext` is unreasoned-about territory.

**Chosen approach: `shutdown(fd, SHUT_RDWR)` each active connection, let the
fiber unwind itself.** A shut-down socket reads EOF, and the connection fiber's
existing read loop already routes `read()==0` to its end-of-request finish path
(`emit_http.go`'s `noReqL`: `close(fd)` + active--). The event loop resumes the
fiber promptly because a shut-down socket becomes readable immediately. So the
force-close is just a nudge — no external fiber/stack teardown, and every
connection still closes through its own normal, already-tested path.

Rejected: iterating the registry and `free`ing each fiber's `ucontext_t`/stack
directly (unsafe, as above); sending the fibers a signal (no per-fiber signal
target exists).

### Cluster propagation

Reuses TDD-00117's shared `mmap` flag region, widened from one i64 word to two:
word[0] = close-listener (`http.close()`), word[1] = force-close
(`http.closeAllConnections()`). The public `__kml_http_close_all_conns` sets
word[1] atomically (when the shared region exists) and runs the local shutdown
pass; every worker's event loop polls word[1] alongside word[0] and runs its own
local shutdown pass. So one worker's `closeAllConnections()` force-closes the
whole cluster's connections — symmetric with how `close()` propagates.

The shared word is monotonic 0→1 (sticky), so in a cluster a later-accepted
connection would also be shut down on the next poll. In practice
`closeAllConnections()` is called together with `close()` (the listener is gone,
so no new connections arrive), making the stickiness unobservable; documented
rather than engineered around.

### Self-close

`closeAllConnections()` shuts down the calling handler's own connection too
(matching Node) — its response `write()` after the handler returns then fails
silently on the SHUT_RDWR socket, and the fiber finishes normally. Callers that
need to answer first should send the response before calling.
