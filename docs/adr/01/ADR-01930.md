# ADR-01930: A function body's pre-pass state moves into its context; the module output is one object

- **Relations**: Extends ADR-01674, Implements TDD-00230
- **Date**: 2026-10-27

## Context

P3.5 splits the Emitter by lifetime. ADR-01674 moved the function builder and 24 function-context fields into `funcBuilder` and `funcContext`. Six fields that each function body sets from its own pre-passes stayed on the Emitter:

- `hoistedCaptures`: the locals a nested closure captures, boxed where they are declared.
- `forwardClosures` and `forwardBoxes`: closures called before their declaration, and the entry-block cell each gets.
- `widenedBindings`: the `-compat=js` bindings that hold more than one scalar kind.
- `emptyArrayElems` and `emptyMapKV`: the element and key/value types inferred for a bare `[]` or `new Map()`.

The function, closure and function-expression emitters each saved these six by hand after installing their fresh context, and restored them in a separate defer.

## Investigation

- The save sites coincide with the context swaps. `emitFunctionDeclAs`, `emitClosureFunc` and `emitFunctionExpression` set all six from the body right after their swap. `emitClassMember` and `emitGeneratorFunctionDecl` set the capture sets.
- The other swaps let a body see the enclosing function's sets: the static initializer, a detached helper (`beginDetachedFunc`) and the sets the class-member and generator emitters do not reset. The names in those sets are the enclosing body's locals, not this body's.

## Decision

- **The six fields move into `funcContext`** (funcstate.go). A fresh context starts with none of them; the function emitters set them from their bodies as before.
- **`forInitDepth` and `tryDepth` move too.** A nested function's body is neither in its enclosing `for` init nor in its enclosing `try`: before, every local it looked up inside a `try` was pinned across a `setjmp` that its own function never calls.
- **The hand saves go.** The three function emitters lose their saves and restore defers, and the `else` arms that cleared the fields for a body-less declaration.
- **The dynamic callable keeps its sets in its own context.** `emitDynCallable` swapped in a detached context, then saved `hoistedCaptures` and, later, the widened and empty-container sets, deferring their restore. Once the fields moved, the saves read the fresh context's empty sets, and the deferred restores, run after the enclosing context was back, wrote those empty sets over the enclosing function's. Two failures followed:
  - Captured locals were boxed where the closure was made, a block that need not dominate their other uses: invalid IR in `structuredClone`'s Map and Set branches.
  - A top-level `-compat=js` array widened by a later element of another kind was declared `number[]` after the module-global pre-pass had typed it `any[]`, a compile error in `examples/jsmode/array_named_properties.js`.

  It now sets each once, in its detached context.

- **The module output is one object.** `moduleOut` (funcstate.go) holds what the module being written owns for its whole emission: the `globals` and `functions` builders, the interned string table (`strConsts`, `strConstRaw`) and the declared runtime functions (`fnDecls`). The Emitter embeds `*moduleOut`, as it does the function builder and context, so `e.globals` and the rest read as before. It also holds the once-written declarations and helper caches (`declaredBigInt`, `contentDefined`, the dynamic get and set helpers and their kin), which, like the `used*` flags, describe what the output already contains. So do the `uses*`, `emitted*`, `*Done` and `programUses*` flags and the emit-once helper caches (function-value trampolines, promise runners, prototype builders, map views, deep-free functions, records and their kin), and the class and unit tables the output carries (class references, records and their pending sites, static areas, constructor rows, the import() units' tables, shown names, prototype and method-value slots). The Emitter is constructed once per program and never copied, so the shared pointer changes nothing. The memo tables and the other per-module state stay on the Emitter for now.

- **Inference's state is one object.** `inferState` (infer_memo.go) holds the memo layers, the outermost inference's depth and the guards that stop a recursive question (a signature being inferred, a `typeof` resolving, an annotation or a return being typed).
- **The program's declarations are one object.** `programDecls` holds the functions, classes, interfaces, enums, generic declarations, generators and namespaces codegen registers before emission and reads throughout it, and what it derives from them (generic instantiations, `@lowerType` classes, static companions, the top-level names). The Emitter embeds `*programDecls`.
- **The program's module units are one object.** `moduleUnits` holds the builtin library's and the import() targets' statement groups, the inits emitted for them and the builtin modules' export names (`libExports`). These are set once per program, before emission; the Emitter embeds `*moduleUnits` beside `*moduleOut`.

- **`emitCall` loses `missingImportRule`.** A count of which call rule emits each call, over the test suite (4.8M calls) and the examples, found it never fires in a TypeScript program: the checker rejects an unimported `fs.readFileSync(…)` first (`cannot find name 'fs'`). Under `-compat=js` it made the call a compile error ("did you forget import …"), where Node throws `ReferenceError: fs is not defined` when the call runs. Without it, the call reaches the undeclared-name path and throws that ReferenceError. The rule and its table of module names are gone.

- **`callSiteSourceRule` becomes a pre-pass.** It was the one rare rule that only asked the checker: whether a callee wants its call site's source text (an assertion's message). `markCallSiteSources` now walks the program once before emission and sets `PassSource` on those calls, so the chain no longer runs it on every call.

- **`erasedAssertionMutatorRule` goes: an assertion of an `any`-held array keeps the box.** TypeScript erases `x as T[]`, so the value is still x's array. Codegen gave the assertion `T[]`'s representation, which for an array boxed with `any` elements means a typed copy; the rule patched one symptom, a mutator called through the assertion. Now `keepsBox` (which already kept a typed array re-asserted to another kind boxed) also keeps the box for an array asserted from `any`, at emission, inference and the oracle alike. A mutator, a read or an iteration through the assertion works on x's own array, and a typed binding or parameter converts at its own boundary, as before.
- **`queueMicrotaskRule` goes.** It served one call codegen synthesizes (a Promise subclass's thenable-resolve job) under an internal name. That call now carries `Intrinsic: "queueMicrotask"`, which the generic path dispatches, so a program's own `queueMicrotask` still does not capture it.

- **`builtinIteratorRule` goes.** Each builtin iterable's `[Symbol.iterator]` declaration names the method it is (`@intrinsic Array.prototype.values`, `Map.prototype.entries`, `Set.prototype.values`, a BigInt typed array's `@lower` values, and `String.prototype[Symbol.iterator]` for a string's code points). An intrinsic emits under the method name it registers, not the member that was called.
- **`tupleArrayMethodRule` goes.** A non-mutating Array method on a tuple is the Array intrinsic, which runs it on the tuple's elements as an array.
- **`primitiveCtorCallRule` goes.** The checker now records an interface property signature as the member's declaration, as it already did for a method. A call through a property the library declares (`n.constructor("7")`) is a call of the value it holds, so it takes the callable-value path instead of the missing-method diagnostic.
- **`@lower` names a builtin module's export too** (`@lower internal_process_methods:cwd`), linked when the program has that module. `process`'s `cwd`, `chdir`, `exit`, `uptime`, `memoryUsage`, `kill`, `umask` and `emitWarning` are tagged that way in `node.d.ts`, and the generic lowered path replaces their entries in the Go name table, for calls and for value reads. A property signature takes `@lower` too: a read calls the named function (`process.pid`, `argv`, `argv0`, `execArgv`, `execPath`, `version`, `versions`).
- **`objectProtoRule` goes.** `Object.prototype.m.call(o, …)` lowers through m's declaration: an intrinsic with a `.call` form in the table (`Object.prototype.hasOwnProperty.call`, `propertyIsEnumerable` (now tagged), `toString`) takes the receiver as its first argument. Only Object's own prototype qualifies; `Error.prototype.toString` shares the declaration by inheritance but is its own method. Object.prototype's records, whose source no checker types, mark the same calls when they are prepared.
- **`objectCtorRule` goes.** ObjectConstructor's call signatures are tagged `@intrinsic Object`, so `Object(v)` takes the generic path. The Object constructor's value stays its record (what every object's `constructor` reads), except as a callback argument, where it is its call's function value. Object.prototype's records and the sloppy-`this` wrapping mark their own `Object(…)` calls.
- **The byte-receiver name tables go.** ArrayBuffer's `slice` and `resize` and SharedArrayBuffer's `slice` and `grow` (now declared, as ES2024 has them) are tagged `@intrinsic ArrayBuffer.prototype.*`, and Number's `toLocaleString` `@intrinsic Number.prototype.toLocaleString`. Buffer's string search and fill were already intrinsics. The receiver owner that looked those names up per receiver kind is deleted.
- **A generator's protocol is declared.** Generator's and AsyncGenerator's `next`, `return` and `throw` are tagged `@intrinsic Generator.prototype.*`, so a written call lowers through its declaration. The calls for…of's desugaring synthesizes (its `next`, and the `return` that closes a loop left early) are built already marked, and an untyped JavaScript receiver codegen holds as a generator or collection finds its owner from that representation. The generator owner keeps only the prototype-chain members (`g.prototype.m = …`).
- **process's credential reads are declared.** `getuid`, `geteuid`, `getgid` and `getegid` are tagged `@lower internal_process_methods:*`. An optional call of a builtin's declared method is its plain call, since the method is never nullish; before, `process.getgid?.()` lowered that way emitted invalid IR.
- **`http` and `https` are declared modules.** They were virtual markers whose members codegen took by name, with their TypeScript companions behind them. `lib/node/http.ts` and `https.ts` now re-export the companions' Node-public names, so an import is a real module the checker types. `http.nope()` is TS2339, as tsc reports it, where before it reached codegen as "a number has no method". The marker, its member allowlist and codegen's `http.listen` rejection go.
- **The collection owner goes.** Every Map, Set, WeakMap and WeakSet method was already an intrinsic. The owner remained only for the calls codegen synthesizes, which no declaration reaches: a `new Map(entries)`/`new WeakSet(values)` seed loop, a typed collection's `any` view and its copy, and the methods a class extending Map or Set inherits through its host body. Each of those now builds its call already marked with its owner's intrinsic. The view dispatcher swallowed a failed call as `undefined`, which hid one such call that had lost its route.
- **process's remaining member tables go.** `hrtime` and `memoryUsage` are declared as @types/node has them, function-valued properties (`HRTime`, `MemoryUsageFn`) tagged `@lower`. A `@lower` property whose type is callable reads the linked function itself, so `process.hrtime` is that function. `bigint` and `rss` are expando members the modules set on their functions, as Node does. The emitter members, the fork channel's and `title` move into a `ProcessEmitter` interface that `Process` extends, tagged `/** @lower internal_process:_kmlProcess */`: each of its members is read and written on the object that function returns. The parser stamps the interface's link on each member, since codegen reaches a library member's declaration but not its parent. The name tables for the emitter members and for `hrtime.bigint`/`memoryUsage.rss` are deleted. `exitCode` joins the held members, read and written through the process object's accessor, so its read and write rewrites go. A `@lower` property linked to a module variable reads and writes that variable: `Buffer.poolSize` is `@lower internal_buffer:poolSize`, which replaces its own read and write rewrites. The now-empty `processMethodExports` table is deleted. `process.platform` and `process.arch` are `@lower internal_process_methods:platform`/`arch`, functions over natives the C runtime answers with the target's own macros. The Go-side name mappings and their `case` arms go. The resolver no longer keeps its own tables of which `process` member needs which module (`processMethods`, `processEnvMembers`, `processEmitter`, the `Buffer.poolSize` pattern). `lib.LoweredMembers` derives them from the declarations: each builtin global's members with a `@lower module:export` link, their own or their holder interface's. A newly lowered member brings its module in with no resolver change.
- **Builtin iterators' own methods are intrinsics.** `ArrayIterator`, `MapIterator`, `SetIterator` and `RegExpStringIterator` declare `next` with `@intrinsic`. Their `next`, their `toArray`, and the Iterator helpers reached without a declaration (a synthesized call) register under each owner, and a receiver held as one finds its owner by representation. The `collIterCall` owner in emitCall's chain is deleted, and so are the name tables that typed these calls: `collIterMethodTypes`, `generatorMethodTypes`, and the inference's switch. A generator's or iterator's call is typed by its lowering's result type, the one its emission produces. `return()` with no value, or with `undefined`, now completes with an undefined value; before, a suspended sync generator and any async generator returned the element's zero (`{ value: 0, done: true }`). Declaring ES2024's ArrayBuffer members makes `SharedArrayBuffer` no longer assignable to `ArrayBuffer`, as in tsc 5.9's lib. A `ReadableStream<Uint8Array>` piped through a `CompressionStream` is then rejected, as tsc rejects it, so the streams tests and the gzip example declare `Uint8Array<ArrayBuffer>`.
- **Property intrinsics.** A property signature may carry `@intrinsic Owner.prototype.name`. Its read is emitted and typed by that entry of a property table (`emit_prop_intrinsics.go`), which emitMember and the structural inference both consult. A read the checker never saw finds its entry through the owner of the receiver's representation, as a method's does. Response's `statusText` and `type`, Body's `body` and `bodyUsed`, the typed arrays' `buffer` and `byteOffset`, the ArrayBuffer limits, Map/Set `size`, the web streams' `locked`/`desiredSize`/`closed`/`ready`, TransformStream's sides and Response/Request `headers` move there. The structural call inference's XMLHttpRequest header-getter and `process.send` branches go as well; the declarations type those calls. A Set built from a string now holds its code points; before, it failed to compile. FinalizationRegistry's `register`/`unregister` intrinsics carry their result types, which replaces the inference's switch on their names. Their object arguments now follow the weak-key rule: a value held boxed (`const tok = {}`) is checked at run time instead of being rejected at compile time, and in a JavaScript file a primitive throws Node's TypeError. ES2024's `resizable`/`maxByteLength` (ArrayBuffer) and `growable`/`maxByteLength` (SharedArrayBuffer) are now declared, where before the checker let them through undeclared. Their per-name branches in both places are deleted.
- **`globalGCRule` goes.** `gc` (Node's `--expose-gc` global) is declared `@intrinsic gc`, so the generic path finds it through its declaration and a program's own `gc` shadows it as any binding does.
- **Five rewrite rules become intrinsic-table entries.** The module namespace object, a namespace's live bindings, and the three runtime operations the Promise-subclass lowering synthesizes (`__kml_thenable_resolve`, `__kml_then_const`, `__kml_resolve_then`) were each a rule matching its call by name or mark. Each synthesized call now carries its `Intrinsic`, and the intrinsic table holds its emitter and result type, so the generic path dispatches and types it like any other intrinsic; `synthCall` builds such a call. A shape an entry does not take is emitted as the plain call it was synthesized from.
- **An intrinsic entry carries its own applicability, dynamic form and held type.** `applies` replaces the switch that decided whether an entry takes a call's shape. `dyn` is the method's body when it is read off a boxed receiver and called as a function value: a generator's `next`/`return`/`throw`, an Array Iterator's `next`, and Promise's `then`/`catch`/`finally`, whose records now call it instead of switching on the method name. `held` is the shadow oracle's rule for a call whose result the program holds boxed (`Object.defineProperty`, `getOwnPropertyDescriptor`, `create`, `getPrototypeOf`, `setPrototypeOf`, `groupBy`, `values`/`entries` of a dynamic argument, `JSON.stringify`), which replaces the oracle's switch on those names. Promise's three reactions are a table of setups instead of a switch on the kind; a subclass's `catch` is `then(undefined, onRejected)`, as the spec defines it. TransformStream's `readable`/`writable` read one slot each through a shared emitter.
- **`Symbol.hasInstance` is honored.** A class's static `[Symbol.hasInstance]` decides `x instanceof C`, and an `instanceof` against a value held dynamically first reads the target's `Symbol.hasInstance` and calls it when it is present, as OrdinaryHasInstance's caller does.
- **A well-known symbol key on an object literal is a real key.** `{ [Symbol.toStringTag]: "T" }` and the other well-known symbols read and write as the field the class syntax already gave them, enumerate as symbols (not strings), and print as `Symbol(Symbol.toStringTag)`. `Object.prototype.toString` and `String(o)` use an own `Symbol.toStringTag`.
- **Body's `body` is `ReadableStream<Uint8Array<ArrayBuffer>> | null`**, as tsc 5.9's lib declares it.
- **A generic Promise subclass's values reach their readers as their types.** `class P<T> extends Promise<T>` holds every value boxed, since T is erased. Its derived instances (`p.then(f)` and the class's statics) now carry `any` in inference and in the oracle alike, so a `const` bound to one reads the box, where before it read the box's bits as a number (`1` read as `1.125`). Its body is flagged boxed when it is constructed, so a typed `Promise<T>` binding holding one decodes the value: `await` reads the box through the flag, and `then`/`catch`/`finally` on such a receiver branch on the flag. A subclass `then` whose callback returns nothing can be chained again; before, the third link of `q.then(f).then(g).then(h)` was a compile error.
- **`await` of a Promise subclass held as a typed Promise adopts it through `then`.** Every subclass body is flagged when it is constructed. An `await` of a typed promise, in a program that declares a Promise subclass, checks the flag and, when it is set, awaits the promise PromiseResolve makes for a constructor other than %Promise%, settled from a job that calls the value's `then`. Before, it took one tick where Node takes three.

## Implementation notes

- A save of a context field made after the swap and restored after the context comes back writes into the enclosing context. The class-member and generator emitters' remaining restores run before their context restore, so they write into their own context.
- `forwardBoxes` is created on first write (`forwardClosureSym`), so a fresh context's nil map is safe.

## Side effects discovered

- `process.on('beforeExit')` never fired: the runtime had no such event. It is now hook 4. When the loop drains, the runtime emits it with `process.exitCode`, and if its listeners leave the loop alive, runs the loop and emits it again, as Node's SpinEventLoop does. `process.exit` skips it. `process.connected` read `undefined` outside a forked child; it reads the emitter object's `false` now.

- A module namespace object listed the module's re-exported types as values. A type that arrived through `export type {…} from` or `export *` was not counted a type, so `const o: any = fs` failed with "cannot find name 'Abortable'". Re-exports now carry their kind.
- In JavaScript (`-compat=js`), a namespace import's member that the module does not export was a compile-time TS2339. It now reads off the module namespace object: `undefined`, and its call is Node's "fs.nope is not a function".

- The Object constructor held as a value failed three ways. `C(1)` threw "primitive wrapper objects do not exist yet", though `Object(1)` written out made the wrapper. `new C()` threw "not supported". `[1].map(C)` crashed: the any-to-closure thunk called the box as a dynamic function without checking its tag. The runtime's call of the constructor record now builds the wrapper through code generation's own lowering, passed in as a hook. `new` through the record is `Object(v)`, and the thunk dispatches through the checked call.

- A typed array's `values()`, `keys()` and `entries()` gave a copy, not an iterator: `t.values().next()` threw, and a write after the call did not show. They are now the live Array Iterators an array's are. A BigInt typed array keeps its own.

- A static object or class instance did not reach what it inherits from Object.prototype. `({}).constructor` and `p.isPrototypeOf(x)` were codegen errors, `c.isPrototypeOf(c)` was invalid IR, and an object literal boxed in `any` read `undefined` for `toString`, `hasOwnProperty` and the rest. Now a property a static object's layout lacks reads through its box. The box's getter falls back to Object.prototype's bag for those names and for a run-time key. A read of a method `interface Object` declares (tagged `@lowerType dynamic`) is a boxed function value, which keeps its `this` through `.call`. A call of one runs on the boxed receiver.

- A test-par run with the ten rules that emit 11 calls or fewer removed failed 12 tests, each rule accounting for at least one. Of those ten, `callSiteSourceRule`, `erasedAssertionMutatorRule`, `queueMicrotaskRule` and the synthesized-call rules are retired above; the rest still route calls the generic path does not reach with the same representation.

## Verification

- A function whose Map and Set branches each make a closure capturing a parameter and a local compiled to invalid IR mid-change. It compiles and prints `Map(1) { 1 => Set(1) { 2 } }`, as Node does.
- The codegen unit tests pass on Mac after the `moduleOut` move, which changes no emitted text.
- `examples/jsmode/array_named_properties.js` matches Node again.
- `TestE2EJSFileUndeclaredNames` covers a method call on an undeclared name and matches Node.
- The try/catch/finally, `for`-init and hoisted-`var` tests pass on Mac.
- The empty-container, widening, forward-closure, capture, class-method, static-block, generator-declaration and `structuredClone` tests pass on Mac.
