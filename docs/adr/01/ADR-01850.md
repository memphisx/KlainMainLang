# ADR-01850: ReturnType and typeof of a declared function

- **Relations**: `Implements TDD-00230` (P3.3: the checker answers what inferExprType did)
- **Date**: 2026-10-21

## Context

- `ReturnType<typeof f>` and `typeof f` for a function declaration `f` failed to compile: `const a: ReturnType<typeof f> = f(3)` reported "array variable must be initialized with an array expression". Codegen's `resolveTypeofType` holds a function declaration as no value, so it fell back to its untyped default. `ReturnType` then saw no function, and the annotation fell through to an array shape.
- The checker deferred a conditional type whose check type is a generic signature (`ReturnType<typeof setTimeout>`, whose global overloads include `<TArgs extends any[]>`). It counted the signature's own type parameters as free, so the result was `unknown` instead of `NodeJS.Timeout`. tsc infers from the signature with its own parameters erased.

## Decision

- Where codegen cannot resolve a `typeof` query or a `ReturnType` argument, it uses the checker's answer for the annotation (`checkerTypeofType`, and the `ReturnType` arm of `resolveUtilityType`), through the switch-path oracle.
- A conditional type defers only on type parameters that are free in its check type. A generic signature's own parameters are bound by it (`hasFreeTypeParam` with the signature walk).

## Consequences

- `TestE2EUtilityReturnTypeOfFunction` covers `ReturnType<typeof f>` (number and array results) and `typeof f` bindings against Node. `TestConditionalOverGenericSignature` covers the overloaded and generic cases, and `ReturnType<typeof id>` staying `unknown` as in tsc.
- Verified on Apple Silicon (checker, binder, ast and codegen packages; targeted utility, typeof, timer, net, events and instanceof E2E tests).
