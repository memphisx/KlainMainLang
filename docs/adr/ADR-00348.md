# ADR-00348: `Object.fromEntries` — a dynamic object from a `[string, V][]` array

- **Relations**: Implements [TDD-00012](../tdd/TDD-00012.md) (dynamic objects); extends [ADR-00347](ADR-00347.md) (`new Map(entries)`)
- **Date**: 2026-08-24

## Context

`Object.fromEntries` was ❌ on [OBJECT-COLLECTIONS.md](../status/OBJECT-COLLECTIONS.md).
It is the inverse of `Object.entries`: build an object from an iterable of
`[key, value]` pairs. Its keys aren't known at compile time, so a fixed-shape
struct can't represent the result — but this compiler already has the exact
representation for a runtime-keyed object: the **dynamic object**, a
`Map<string,V>`-backed value with `.field`/`[expr]` sugar ([TDD-00012](../tdd/TDD-00012.md)/[ADR-00066](../adr/ADR-00066.md)).
And [ADR-00347](ADR-00347.md) just built the `[K, V][]`-array seeding machinery
`new Map(entries)` uses.

## Decision

`Object.fromEntries(entries)` returns a **dynamic object**
(`Type{IsMap, IsDynamicObject, MapKey: string, MapVal: V}`) built by creating a
string-keyed map and seeding it with the same `emitMapSeedFromEntries` walker
`new Map(entries)` uses. `V` is inferred from the `[string, V][]` source's tuple
field 1. Reads afterward go through the existing `emitDynamicObjectGet`
(`obj.field` / `obj[key]`). Keys must be strings (real JS stringifies them; a
non-string key type is a clean compile error).

- Dispatch: a `fromEntries` case in `emit_call.go`'s `Object.*` switch →
  `emitObjectFromEntries` (emit_objects.go).
- `inferExprType`'s `Object.*` switch gains a `fromEntries` case returning the
  same dynamic-object type, so the result flows into `.field` access correctly.

## Implementation notes

- The whole feature rides existing machinery: the entries walker (ADR-00347),
  the dynamic-object representation and its member-access codegen (TDD-00012).
  `emitObjectFromEntries` is ~20 lines.
- A bare array literal source (`Object.fromEntries([["a", 1]])`) is seeded with a
  `[string, V]` tuple element hint, the same hinted-array-literal path ADR-00347
  uses; a non-2-tuple element is the clean compile error that path already emits.
