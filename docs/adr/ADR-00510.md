# ADR-00510: `class X extends Duplex` (Node stream subclassing, Stage C1)

- **Relations**: `Implements TDD-00132`
- **Date**: 2026-08-30

## Context

TDD-00132 stages Node stream subclassing Readable → Writable → Duplex/Transform.
Stages A/B (`extends Readable`, `extends Writable`) shipped; `extends Duplex`
and `extends Transform` were both rejected at compile time by one guard. Duplex
is the cheaper half of Stage C: unlike Transform it needs no new dispatch — it
is just the two existing sides (`_read` pull + `_write` sink) on one instance.

## Investigation

The both-sided plumbing was already present, only gated:

- `nodeStreamRootKind` (`emit_classes.go:567`) already mapped `Duplex`/`Transform`
  → `(readable, writable) = both`.
- `emitConstructNodeStreamHandle` (`emit_node_stream_class.go:137`) already
  builds **both** the `rs` and `ws` handles when both flags are set, and arms the
  writable side via `__kml_ns_arm_writable`. The missing-`_read`/`_write` errors
  (lines 154, 168) already fire per-side.
- `nodeStreamTy()` already returns `NodeTransformType` for the both-flagged case;
  `asNodeStreamValue` / `emitClassNodeStreamCall` are side-neutral.

So the only real code was removing the guard for `Duplex` and letting a single
`<T>` name both chunk types (the type-arg branch set only the readable-out side).

## Decision

1. Narrow the guard at `emit_classes.go` to reject only `Transform`, letting
   `Duplex` flow through the existing both-sided registration.
2. For a stream root that is both readable and writable, a single `<T>` base
   type-arg sets **both** `streamInTy` and `streamOutTy` (previously the `else`
   branch meant a readable-and-writable root took only the readable side).

A `Duplex` subclass must implement both `_read` and `_write` — enforced for free
by the existing per-side "does not implement" errors.

## Implementation notes

- `codegen/llvm/emit_classes.go`: guard narrowed to `Transform`; type-arg branch
  changed from `if rootReadable {…} else {…}` to two independent `if`s so a
  both-sided root applies the arg to both sides.
- No changes to `emit_node_stream_class.go` were needed — the construction and
  dispatch paths already handled both flags.

## Side effects discovered

None. Transform remains rejected (Stage C2) because it needs genuinely new
dispatch: a `_transform(chunk, enc, cb)` override whose `this.push` feeds the
readable side, rather than independent `_read`/`_write`. Tracked in TDD-00132.

## Verification

- New E2E `TestE2ENodeStreamClassExtendsDuplex` (`tests/streams_test.go`) — a
  `_read` push loop + `_write` sink on one instance; passes.
- All `TestE2ENodeStreamClassExtends*` pass (`go test ./tests/ -run …`).
- `examples/streams/class_extends.ts` extended with a `Duplex` subclass;
  compiled output matches `node` per stream (every chunk delivered correctly).
  The one difference from `node` is the interleaving order of two independent
  readable streams' lines, which follows microtask/event-loop scheduling and is
  not guaranteed identical across runtimes.
- Machine: Apple Silicon M4 (macOS).
