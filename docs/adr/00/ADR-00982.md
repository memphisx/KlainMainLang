# ADR-00982: Options-form Node `Writable`/`Duplex` sink accepts `write(chunk, encoding, callback)`

- **Relations**: Extends ADR-00449, ADR-00483, ADR-00493
- **Date**: 2026-09-16

## Context

A `class X extends Writable` override already supported Node's full
`_write(chunk, encoding, callback)` signature (three parameters, the completion
callback treated as fired when `_write` returns — the V1 semantics of
`emitClassStreamWrite`). The **options form**, `new Writable({ write })`, did
not: its sink callback had to be single-parameter `write(chunk)`, and any extra
parameter was a clean rejection (`a Writable write callback takes one (chunk)
parameter`). Node's idiomatic options-form sink is
`write(chunk, encoding, callback)` — extremely common — so a portable snippet
that calls `cb()` at the end of its sink failed to compile against the options
form even though the class form accepted the identical shape.

## Decision

Accept the options-form `write` callback in either shape:

- one parameter `write(chunk)` — the existing implicit-completion form; or
- three parameters `write(chunk, encoding, callback)` — Node's full signature.
  `encoding` is supplied as the interned `'buffer'` string (matching the
  class-form `_write`), and `callback` is a no-op completion closure so an
  idiomatic `cb()` inside the body runs. The write is treated as complete when
  the sink thunk returns — the same V1 limitation the class form documents (a
  sink can't defer completion past the call).

A two-parameter shape is ambiguous (encoding vs. callback) and rejected. This
applies to both `Writable` and `Duplex` options forms; the WHATWG
`WritableStream` and the `Transform` sink keep their own `(chunk, controller)`
convention, untouched.

## Implementation notes

- `codegen/llvm/emit_node_stream_class.go`: new `emitNodeWriteWrap3` — the
  options-form counterpart of `emitClassStreamWrite`, over the same
  `{userClosure, stream}` env shape as `emitStreamWriteWrap` but supplying the
  `encoding` string and no-op `callback` in place of a WHATWG controller. A
  `nodeOptionsWriteWrap` helper validates arity (0/1 → `emitStreamWriteWrap`,
  3 → `emitNodeWriteWrap3`, 2/≥4 → rejection) and, for the three-param form,
  checks the encoding and callback parameters are ptr-represented (a string and
  a function).
- `codegen/llvm/emit_node_stream.go`: the `Writable` and `Duplex` options-form
  `write` sites route through `nodeOptionsWriteWrap` instead of hard-rejecting
  `>1` parameter.
- No runtime/ABI change: reuses the existing no-op-callback closure
  (`ensureNoopCallback`) and env-closure calling convention.

## Side effects discovered

None. The instance method `.write(chunk[, encoding][, callback])` (ADR-00981) and
the class-form `_write` are unchanged; the WHATWG and Transform two-parameter
sinks are untouched (verified by the full streams suites).

## Verification

- `go build` + `go vet ./codegen/llvm/` clean.
- Byte-matches Node for an uppercasing `write(chunk, enc, cb)` sink over two
  writes + `end` (`finish: ALPHA,BETA`) on macOS arm64 (M4).
- New E2E tests `TestE2ENodeStreamOptionsFormThreeArgSink` and
  `...TwoArgSinkRejected`; the full `TestE2ENodeStream*`/`TestE2EStreams*` suites
  pass (no regression to the one-param sink or the WHATWG controller path).
