# ADR-01935: Runtime files without libraries are linked by the symbols a program names

- **Relations**: Implements TDD-00230, Extends ADR-01934
- **Date**: 2026-10-28

## Context

TDD-00230 replaces the `used*` flags that pick runtime files with link inputs derived from the symbols a program references. `EmbeddedCSources` gated each of about 80 C runtime files on a `Uses*()` method, set by `ensure*` calls scattered through codegen. A file was linked only if codegen remembered to set its flag. `ensureRuntimeDeps` patched the dependencies between runtime files by hand.

## Investigation

- 78 of the files bring no library of their own: the C library, plus `-lm` on Linux. The rest name one (libuv, libcurl, OpenSSL, libtommath, Yoga, webview, c-ares, h2o), or exist only on Windows.
- Weak defaults in `hooks.c` and other files answer a call into a feature the program does not use. Two consequences:
  - A symbol answered weakly is not, by itself, a reason to link the strong file.
  - The IR declares several hooks always, and its generic paths name `__kml_boxed_bigint_str`. Linking `bigintbox.c` for that name needs the BigInt backend (libtommath), which such a program does not link.
- A weak default can mean either "feature unused" or "fallback when the strong file isn't linked". exceptions.c prints an uncaught `any` object through `dynjson.c`'s inspector. Its weak default prints `[thrown value]`. `holes.c` shows array holes, behind weak defaults in dynjson.c. Taking the strong file whenever it can link covers both meanings.
- An island's entry points are reached through `dlsym` and named by nothing, so `island.c` stays gated.
- Probes that differed from Node while checking this change, both fixed here:
  - **A `Promise` subclass's static `resolve`**: `class P<T> extends Promise<T>`, then `P.resolve(5).then(v => …)`, gave 4.5. The result's type reads its value as `any`, but the capability settled it with the argument's own type, a raw double. Reading a raw double as a box subtracts the NaN-box double offset (2^49).
  - **`process.versions.uv`** was missing, though every program with an event loop links libuv.

## Decision

- **The 78 library-free files form a pool.** `runtime_resolve.go` picks from it:
  - Each file is compiled once per source, flags and toolchain. Its symbol table (strong, weak, undefined) is kept as a small text file under the user cache directory. It is read from Mach-O, ELF or COFF with Go's `debug/*` packages.
  - The program's IR is read for the symbols its definitions and globals name. A `declare` alone is not a use.
  - The pool closure starts from those symbols and the always-linked files.
- **Resolution rules:**
  - A weak definition in the IR (`weak`, `linkonce`) or in a linked file is a default.
  - A symbol answered only by a default takes the pool's strong definition when that file's closure links. A closure does not link if it leaves a `__kml_` symbol undefined: the file needs a library unit the program does not link (bigintbox.c without the BigInt backend).
  - A pool file whose strong definitions clash with the program's or a linked file's is never pulled. The program's own version stands. The program's `internal` and `private` definitions are its own and clash with nothing.
- **Files that bring libraries keep their option and usage gates.** These are fetch (libcurl), the zlib stream (zlib), BigInt, crypto, TLS, HTTP/2, ffi, the dlopen loader, timers and the loop (libuv), os info (Windows `iphlpapi`), webview, the TUI, `klain:sync`, the thread pool, c-ares, h2o and embedded assets. They will move when the archive split by dependency lands.
- **60 `Uses*` methods are deleted.** Their flags still guard each `ensure*` declarator's run-once.
- **The usage-variant `-D` flags are gone,** so a pool file's object depends only on options, not on the program:
  - `KML_WORKERS`: exceptions.c always reports through `__kml_worker_uncaught`, hooks.c's trampoline whose default is a no-op. It ends through `__kml_thread_exit`, a weak default that calls `exit`. The Worker runtime defines the strong one.
  - `KML_VIEWS`/`KML_BOXED_VIEWS`: `byteOffset` and `buffer` of a typed array held in `any` always work.
  - `KML_WEAK_NATIVES`: the WeakRef natives are always compiled.
- **`renameHooks` renames a hook function only when the program defines it.** Otherwise the program's call goes to hooks.c's trampoline and its default. The emitter's no-op `__kml_worker_uncaught` stub is replaced by a `declare`.
- `KML_RESOLVE_TRACE=1` prints each picked file and the symbol that pulled it in.
- **Bugs fixed:**
  - `b.length = 4` on an `any` array printed `undefined` for the new slots instead of `<1 empty item>`, because no flag linked `holes.c`.
  - A `Promise` subclass static settles to `any` when the derived type's value is unconstrained.
  - A capability that settles a typed value clears the boxed flag the erased host's construction set.
  - `process.versions.uv` is `uv_version_string()`, from `loop.c`.
  - `dynobj.c` includes `<stdint.h>` for `uintptr_t`; macOS headers brought it in, glibc's do not.

## Implementation notes

- The emitter keeps the IR it returned (`finalIR`), so the three link sites (CLI, tests, conformance runner) need no new argument. They all go through `EmbeddedCSources`.
- The symbol scan compiles at `-O2`, as the runtime links, so an inlined helper's references match the linked code.

## Verification

- 172 saved probes, built with the new resolver and compared with Node v24. All build. The differences left are the same as before the change and expected:
  - finalizers at exit;
  - `gc()` without `--expose-gc`;
  - stack-trace formatting.
- New E2E test: `TestE2EPromiseSubclassResolveNumber`. `TestE2EProcessVersionsTyped` gains `uv`.
- `make test-par` (14 shards) and `make examples` (420/420) pass on Linux x86-64 (Node304, DeskMini; ELF symbol tables, lld).
- Targeted E2E suites run on the Mac (Apple Silicon; Mach-O symbol tables, ld64).
