# ADR-00953: Clean rejection of type-changing `Object.assign` and non-string `Object.fromEntries` keys

- **Date**: 2026-09-15

## Context

Two `built-ins/Object` Test262 invalid-IR (Bucket B) families, three files:

```js
// assign/ObjectOverride-sameproperty.js
Object.assign({a: 1}, {a: 2}, {a: "c"});   // store ptr into a double slot

// fromEntries/supports-symbols.js
Object.fromEntries([[Symbol(), 'value']]);  // store a non-string key

// fromEntries/to-property-key.js
Object.fromEntries([[objWithToPrimitive, 'value']]);
```

Both emitted invalid IR rather than a clean compile error.

## Investigation

**assign**: `emitObjectAssign` (emit_objects.go:1338) copies each source field
with `e.coerce(srcField, dstTy)`. When a source's same-named field has a type
`coerce` can't actually convert (a string into the target's `double` field),
`coerce` relabels the value's type to the target's but keeps the original
register — the coerce-honesty slip — so a string ptr was stored into a
`double` slot. The target field keeps its own type in this typed-object subset,
so the merge is genuinely unrepresentable.

**fromEntries**: `emitObjectFromEntries` (emit_objects.go:1266) already rejects
a non-string key when the entries element infers as a `[K, V]` 2-tuple with a
non-string `K`. But a `[Symbol(), 'value']` / `[obj, 'value']` pair is
*heterogeneous*, so it doesn't infer as a 2-tuple at all — the guard is
bypassed and seeding stored the non-string key raw. Real JS runs ToPropertyKey
on each key (a Symbol becomes a symbol-keyed property; an object is ToString'd),
neither of which the string-keyed dynamic-object representation supports.

## Decision

Both take the established strict-lane posture: reject cleanly (the typed-subset
equivalent of the behavior, matching the clean rejections
spread-in-object-literal and JSON.parse→object already use) instead of invalid
IR.

- **assign**: guard each source-field copy with `coerciblePure(f.Ty, dstTy)`;
  a non-coercible field type is a clean compile error naming the field. A
  compatible merge (same or widening field types, last-write-wins) is unchanged.
- **fromEntries**: when the entries argument is an array literal, walk its pairs
  and reject a non-string (Symbol/object) key directly, before seeding — closing
  the heterogeneous-pair gap the tuple-inference guard couldn't see.

## Implementation notes

Both changes are in emit_objects.go. No new type machinery; the fromEntries
check inspects the literal AST, so it applies only to literal entries (a
non-literal entries source keeps the existing tuple-typed path).

## Side effects discovered

`built-ins/Object` drops to 0 CLANG_ERROR. Symbol-keyed properties on a
dynamic object exist (ADR-00930's sentinel keys) but are not wired into
`Object.fromEntries`; supporting real symbol/object keys there (via
ToPropertyKey) remains a possible future extension, tracked only as this
rejection's message.
