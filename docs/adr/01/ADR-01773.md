# ADR-01773: Async generator results carry undefined, and return(v) awaits v

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- An async generator's next/throw/return promise settled with `{value, done}` laid out by the element type alone. A generator of numbers that completed without a return value gave `{ value: 0, done: true }` where Node gives `undefined`. The sync path already reads results through `emitUserGenResult`, whose layout can hold undefined.
- `return(v)` settled its promise at once. In the spec it awaits `v` first. A fresh or finished generator goes through AsyncGeneratorAwaitReturn. A suspended one goes through the yield's return resumption. So the result arrives a turn later than an immediate settle, and requests queued behind it complete after it.

## Decision

- Async generator results use `asyncGenResultType`, the sync program-facing layout (`genUserResultType`), for every producer and reader:
  - the step function, next/throw/return, `for await` and async `yield*`;
  - `inferExprType` of `.next()`.
- `buildAsyncGenResult` stores the value only when present: while not done, or on the step that returned a value (`__hasret`). `loadGenResultValue` reads the payload back for internal consumers.
- The resume dispatch marks a return completion as carrying a value. In an async generator it awaits that value first.
- `return(v)` on a fresh or finished generator settles through the new runtime helper `__kml_promise_settle_later`, one microtask turn later. A request drained after it in the same step also settles later, so the order holds.

## Consequences

- `TestE2EJSFileAsyncGeneratorCompletionValues` checks values and turn order against Node.
- An async generator of scalars carries a presence bit in each result object.
