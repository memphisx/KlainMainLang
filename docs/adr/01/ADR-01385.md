# ADR-01385: The event loop in C, waiting through libuv

- **Relations**: Implements TDD-00244, TDD-00240
- **Date**: 2026-10-04

## Context

[TDD-00244](../../tdd/TDD-00244.md) Stage 1 moves the event loop onto libuv.
The loop was about 900 lines of IR text in `runtime_http.go`
(`@__kml_event_loop_run`): a `select()` over three 128-byte bitmaps, one
due timer fired per pass, and a wait that ended on `EINTR` from a signal.
Every part of that shape had an open BACKLOG entry: `fd_set` overflow at
fd ≥ 1024, one due timer per iteration, a signal arriving before
`select()`.

## Investigation

- The loop reads the primary HTTP server's connection table, the timer
  queue (`timers.c`), the loop-turn globals, nine subsystem hook triples
  (`*_keepalive`, `*_fdset_add`, `*_dispatch`) and libcurl's multi handle.
  Only the primary listener's accept is generated per program (the TLS and
  HTTP/2 head of `__kml_http_append_conn`). The GC stack-bottom swap
  around a fiber resume depends on two options: `-mm=gc`, and whether
  Workers are in use.
- Every subsystem hook sets bits by hand (`__kml_worker_fd_setbit`,
  `fswatch.c`'s `fdset_set`), except `klainpool.c`, which used libc's
  `FD_SET`. macOS's `FD_SET` aborts at fd ≥ `FD_SETSIZE`.
- libuv's poll wait resumes after `EINTR` on its own, so a signal no
  longer ends the wait the way `select()`'s `EINTR` did.
- Under `-mm=gc` on Linux the shim's `malloc` is the collector's for the
  whole process, libuv included. The collector does not scan libuv's
  memory, or thread-locals on macOS ([ADR-01049](ADR-01049.md)).
- A descriptor closed and reopened between two passes keeps its number.
  The kernel dropped its registration with the close (kqueue and epoll
  both do), but libuv still holds the watcher and re-registers only when
  the wanted events change. A socket's `st_ino` does not tell the two
  files apart on macOS. A first version that compared (`st_dev`,
  `st_ino`) passed on Linux, but on the M4 it hung a loop of 150
  top-level fetches to a server that closes every connection
  (`TestE2ETopLevelAwaitFetchCompletingInKeepAliveCheck`: "Timeout was
  reached").
- `curl_multi_fdset` cannot report a socket ≥ `FD_SETSIZE`, so a fetch
  above fd 1024 fails ("Couldn't connect to server"). A `net` client works.
  This is curl's interface, which [TDD-00244](../../tdd/TDD-00244.md) Stage 3
  replaces with its socket API.

## Decision

- **`loopsrc/loop.c` is the loop**, with the IR's pass order unchanged.
  - The primary listener's accept stays IR, as
    `__kml_http_accept_primary(listenfd)`, because its TLS/h2 head is
    generated per program.
  - The fiber resume's GC stack-bottom swap is chosen by `-DKML_GC_SB`
    (none, `GC_stackbottom`, `__kml_gc_set_sb`, `__kml_gc_sb_cur`), which
    mirrors `gcSBStore`.
  - The cluster orphan check is `-DKML_CLUSTER_ORPHAN` (POSIX).
- **The loop-turn globals live in C.** The IR declares them `external`.
  The globals the loop reads from IR lose `internal`: `__kml_listen_fd`,
  `__kml_conn_len`/`active`/`ran`/`writepark`, and
  `__kml_cluster_primary_pid`/`close_flag`.
- **libcurl joins the loop through four `fetch.c` entry points**:
  `__kml_curl_loop_active`, `_fdset`, `_deadline_ns` and `_perform`.
- **The wait is libuv's, through a bridge (POSIX).** Each pass:
  - The hooks still fill bitmaps, now 8,192 bytes long.
  - `wait_ready` keeps one `uv_poll_t` per wanted descriptor and re-arms
    it every pass (stop, then start). Re-arming makes libuv register the
    descriptor with the kernel again, as `select()` rebuilt its sets every
    pass.
  - A descriptor libuv cannot poll (a regular file, `/dev/null` under
    epoll) is always ready, as `select()` reports it.
  - It runs `uv_run` once, bounded by a `uv_timer_t` rounded up to whole
    milliseconds so it never wakes early (`UV_RUN_NOWAIT` for a zero
    wait), and hands readiness back as bitmaps.
  - Windows keeps `select()` over `win32io.c` until Stage 6.
- **A signal wakes the wait.** `process.c`'s handler calls
  `__kml_signal_wake`, set by the first loop to `uv_async_send`, which is
  async-signal-safe. The loop creates it on entry, before its first signal
  dispatch.
- **The timers-only drain sleeps in `poll()` on a self-pipe**
  (`timers.c`) that the same hook writes, not in `nanosleep`. A signal that
  arrived between the drain's dispatch and its sleep used to leave the
  sleep running to the next timer; on Linux it reproduced every time
  (`TestE2ELoopSignalWakesTheWait`: the 10 s timer, then the watcher).
- **The loop's libuv memory is libc's under `-mm=gc` on Linux**
  (`uv_replace_allocator` with `__libc_malloc` and the rest).
- **The timers phase fires every due timer.** Every timer due by the
  phase's start time fires in due order, with microtasks drained after
  each callback, as Node has done since v11.
- **`klainpool.c` sets bits by hand on every platform.**
- **The host link passes `-Wno-override-module` on Linux too.** Clang 18
  normalizes the IR's `x86_64-unknown-linux-gnu` to `x86_64-pc-linux-gnu`
  and warned on every compile; macOS already passed the flag.
- **A C source taken from the object cache no longer passes its `-I`/`-D`
  flags to the link** (`main.go`). They made clang warn "argument unused"
  on every link of a program with such a source.
- **libuv is a dependency**: CI's apt, brew and MSYS2 lists and the README.
  `LocateUV` reads pkg-config and drops its `-lpthread -lm`, which the link
  already has.

## Implementation notes

- `runtime_http.go`'s loop define is replaced by the accept function, so
  its IR-text allowance holds.
- The wait-probe tests (`tests/event_loop_wait_test.go`) now assert that
  the interval fired during the wait, not that it fired 8 times. The count
  is a timing figure that a loaded machine stretches.

## Side effects discovered

- `TestE2EDgramSendFormsAndConnect` asserted when the server's datagrams
  arrive relative to the client's `send`/`connect` callbacks. Those are two
  sockets racing, and the order differs between hosts (Node 24 on macOS
  prints the client's three lines first). The server now prints its
  messages together once all three have arrived.

- A fetch above fd 1024 fails inside libcurl (above). It is fixed by
  [TDD-00244](../../tdd/TDD-00244.md) Stage 3.

## Verification

- New: `tests/event_loop_uv_test.go`:
  - timers are never early;
  - due timers fire together, with ticks and microtasks between them;
  - a timer wait sleeps (CPU < 150 ms over 500 ms);
  - `SIGUSR2` wakes a wait bounded by a 10 s timer;
  - an HTTP server and a `net` client above fd 1024.
- Mac (M4): those and the wait probes pass.
- The C loop still on `select()`: examples 393/393 (DeskMini).
- Linux (Node304): `TestE2ELoopSignalWakesTheWait` 30/30. test-par on the
  libuv tree: one failure, that test, before the self-pipe fix.
- Examples on the libuv tree (DeskMini): 393/393.
- Strict Test262 (DeskMini): 8,498 (baseline 8,497), no invalid IR.
- macOS (M4), libuv's kqueue backend: every example under async,
  child_process, cluster, dgram, events, eventsource, fetch, fs_async,
  fs_watch, http, http2, https, net, process, process_stdin, streams,
  timers, websocket and workers passes (122; the `*_worker.ts` modules are
  not programs).
