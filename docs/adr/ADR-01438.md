# ADR-01438: Promise callback parameters; `void`-typed parameters

- **Relations**: Implements TDD-00230 (P2.2)
- **Date**: 2026-10-07

## Context

The fourth shadow bucket after ADR-01434 (1554 rows; `events.ts`,
`stream.ts`, `internal_fs.ts`) was a function-valued name whose parameters
codegen and the checker's answer disagreed on:

- an executor's `reject` (`new Promise((resolve, reject) => …)`), which
  codegen calls with the caught-value record and the checker types
  `(reason?: any) => void`;
- `done` in `this.call<void>('fsync', (fd, done) => …)`, typed
  `(err: any, value: T) => void` with T = void.

## Investigation

- A rejection's reason is the `{i8, i64}` caught-value record
  (TDD-00207): `reject` takes it, and a native promise's rejection handler
  (`.catch(f)`, `.then(_, f)`) receives it when its parameter is
  unannotated or `any`/`unknown`. The checker's answer had no such rule.
- A `Promise<void>` executor's `resolve` takes no argument in codegen.
- Probing the `done` shape outside the library: codegen gave the callback a
  `void` parameter and emitted `call void (ptr, i64, void)`, which clang
  rejects.

## Decision

- A function type's `void` parameter is held as `any`, in codegen's
  annotation resolution and in the checker's answer: no value has the void
  IR type.
- The checker's answer gives an executor's `resolve` and `reject`, and a
  native promise's rejection-handler parameter, the representations
  codegen calls them with.

## Verification

- `TestE2EVoidTypedCallbackParam` (against Node) and the Promise, `then`,
  `catch` and executor tests pass on the Mac.
- The probes' shadow rows are gone except one: inside a generic function
  `new Promise<T>` is instantiated with `T = void` by codegen, while the
  checker answers for the generic body.
