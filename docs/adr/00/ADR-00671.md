# ADR-00671: `url.fileURLToPath` / `url.pathToFileURL` — the file-URL pair (TDD-00165 Stage 4)

- **Relations**: Implements TDD-00165 (Stage 4); Extends [ADR-00670](ADR-00670.md)
- **Date**: 2026-09-03

## Context

Continuing the hybrid `url` module's Stage-4 functions after `parse`/`format`:
the file-URL conversion pair `fileURLToPath(url)` and `pathToFileURL(path)`,
widely used to bridge `import.meta.url` / `file:` URLs and filesystem paths.
This compiler is POSIX-only (no cross-compile; `path` is POSIX-only), so only
POSIX semantics are implemented.

## Decision

Register `fileURLToPath` and `pathToFileURL` in `moduleFunctionMembers["url"]`
(importable named / namespace / default via the hybrid machinery), dispatch both
in codegen, and infer their result types (`string` and `URL` respectively). Both
reuse the libcurl URL API already backing `new URL()`/`url.parse`.

- **`emitFileURLToPath`**: accepts a `file:` URL string or a WHATWG `URL` (whose
  `href` is read). Parses it, requires the scheme to be `file` (a `strcmp` guard
  that throws a catchable "The URL must be of scheme file" otherwise, matching
  Node's `ERR_INVALID_URL_SCHEME`), then returns the **percent-decoded** path via
  `curl_url_get(CURLUPART_PATH, CURLU_URLDECODE)`.
- **`emitPathToFileURL`**: resolves the argument to an absolute, normalized path
  (reusing `emitPathResolve`), then builds a WHATWG `URL` handle by setting
  `scheme=file`, an empty host (→ the `file://` authority), and the path with
  `CURLU_URLENCODE` (so a space / `#` / `?` stays part of the path rather than
  being reinterpreted). The handle is materialized into a `URLType` object via
  the shared `deriveURLFieldsIntoObject`.

## Implementation notes

- The `CURLU_URLDECODE` (1<<6) / `CURLU_URLENCODE` (1<<7) flag values were taken
  from the system `curl/urlapi.h`, per the project's verify-against-the-header
  practice for libcurl constants.
- Setting the path part with `CURLU_URLENCODE` (rather than encoding by hand in a
  char-scanning loop) is what keeps `pathToFileURL` faithful — curl encodes the
  path's reserved characters while preserving the `/` separators.

## Scope / divergences

- POSIX only (Windows drive-letter / UNC handling is out of scope, as everywhere
  in this compiler). A non-empty, non-`localhost` host on `fileURLToPath` is not
  specially rejected; the host is ignored and the path returned.
- `fileURLToPath`'s and `pathToFileURL`'s `options` argument (the `windows`
  toggle) is not supported.

## Verification

E2E tests in `tests/node_core_modules_test.go`: `fileURLToPath` (plain +
percent-decoded), the non-`file` scheme throw, `pathToFileURL` (basic + special
character encoding to `%20`/`%23`), and a full `pathToFileURL`→`fileURLToPath`
round-trip that recovers `/a/b c/d#e`. The now-obsolete "fileURLToPath rejected"
case was repointed to a still-unbuilt extra (`domainToASCII`). `go test` over the
import/module/url suites green (Mac); `go vet ./...` clean.
