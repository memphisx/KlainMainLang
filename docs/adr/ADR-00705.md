# ADR-00705: -optimize-memory — stack-allocated tuples and class instances (Stage 1 complete)

- **Relations**: Extends ADR-00702, ADR-00704; Implements TDD-00134 (Stage 1, final part)
- **Date**: 2026-09-04

## Context

ADR-00702/00704 covered object and closure literals; tuples and class
instances were the last Stage-1 allocation-site kinds. Tuples are the same
fixed-shape-struct swap as object literals. Class instances are harder for
one reason: the constructor and every method receive `this`, and any of
them may leak it somewhere that outlives the binding's block — invisible to
the binding-level escape checker.

## Investigation

- A tuple literal is one calloc in `emitTupleLiteral` (emit_tuple.go), and
  a class instance is one calloc at the `new` site in
  `emitNewClassInstance` (emit_classes.go) — the constructor is *called
  with* the pointer, it does not allocate. Both swap like object literals.
- Instance-field initializers are spliced into the constructor body by
  registerClasses (`classFieldInitStmts`), and getters/setters register as
  ordinary methods — so auditing `ClassInfo.Constructor` plus the effective
  `Methods` table (own + inherited, overrides resolved) covers the whole
  `this` surface, including the base chain's method bodies. Subclass
  constructors additionally run ancestor constructors via `super(...)`, so
  those are audited too.
- Testing caught a real soundness hole in the first audit draft: an arrow
  inside a method reading a bare `this.n` matched the "field read on this"
  safe shape — but an arrow *captures* lexical `this` into a heap env, so
  even that is an escape. Nested closures now fail on any `this` at all.

## Decision

- **Tuples**: stack-plan candidacy adds `ArrayLiteral` initializers with a
  tuple type annotation (`const t: [A, B] = [...]`); `emitTupleLiteral`
  gains the literal node and routes through the shared `structAlloc`
  helper (alloca + at-site zero store when planned, calloc otherwise —
  the same helper object literals and the class site now use).
- **Class instances**: candidacy adds `NewExpression` initializers; the
  flow check is the binding-level one (receiver-position method calls stay
  safe *because* the emit-time class audit holds the other half). At the
  `new` site, `classStackEligible(className)` (memoized per class) gates
  the swap:
  - ineligible outright: Node-stream classes (construction wires `this`
    into a runtime handle) and classes with decorated-method slots;
  - `thisEscapesFn` scans the constructor, every ancestor constructor, and
    every non-static effective method: `this` is only allowed as
    `this.field` read/write, `this[i]`, and `this.m(...)` calls (m is in
    the audited table). Anything else fails — returned/passed/stored
    `this`, a method extracted as a value (`this.m` uncalled, told apart
    from a field read via the method-name table), ANY `this` inside a
    nested closure, any decorator on the declaration, and any construct
    the reflection walk does not positively recognize.
  - An ineligible class silently keeps the heap path (the marker is
    cleared before `structAlloc`).
- Method chaining (`return this`) therefore keeps a class heap-bound —
  conservative and documented; vtable dispatch, overrides, and
  `instanceof` all work on stack instances (the tag/vtable words are
  ordinary struct stores).

With this, TDD-00134 Stage 1 covers every fixed-size allocation-site kind
it named: object literals, closure headers/envs, tuples, class instances.

## Implementation notes

Files: escape_check.go (candidacy cases), emit_stackalloc.go
(`structAlloc`, `classStackEligible`/`thisEscapesFn`/`containsThis`),
emit_tuple.go (lit param + structAlloc), emit_objects.go (structAlloc +
call sites), emit_classes.go (`new` site gate), emitter.go (audit memo
map), tests in optimize_memory_test.go.

## Side effects discovered

None beyond the audit-draft hole above (fixed before landing). Flag-off
output remains byte-identical; generic classes audit under their mangled
instantiation name.

## Verification

Mac (Apple Silicon): IR tests — tuple + this-clean class lose every calloc;
all three leak shapes (ctor self-registration, `return this` chaining,
arrow-captured `this`) keep theirs; behavioral equivalence with/without the
flag across inheritance, override dispatch, `instanceof`, and an escaping
subclass. Class/Tuple/Destructuring/Memory/FinReg/Closure/Generic suites
pass (120s run); `go vet` clean; full example suite passes.
