# ADR-01471: The klain: modules as TypeScript over natives

- **Relations**: Implements TDD-00230 (P3.1, P3.2), extends ADR-01344, ADR-01170
- **Date**: 2026-10-08

## Context

TDD-00230's builtin-declarations row still listed the `klain:` modules as
compiled directly: `klain:tty`, `klain:tui`, `klain:assets`, `klain:webview`
and `klain:sync` were virtual modules whose imports the resolver rewrote to
marker identifiers (`tty__kml_builtin.readKey`), each member call dispatched
by name to a Go emitter writing its IR, and `Webview` and `Channel`
parse-time constructors with their own AST nodes (`NewWebviewExpression`,
`NewChannelExpression`) and codegen types (`IsWebview`, `IsChannel`,
`IsEmbeddedAssets`). `klain:ws` was already `lib/node/klain_ws.ts`.
`klain:http` stays as it is: its server is the one whose backend is to
become selectable (libh2o first), so it is ported last.

## Investigation

- Each module's native side is already C behind a handle: the tty shim
  (emit_tty.go's `TTYShimSource`), the tui painter over Yoga (tui.go), the
  embedded-asset server (embed_assets.c), webview/webview's `webview_*` API
  and the goroutine scheduler (klainsync.c). The Go emitters only marshalled
  arguments, so a TypeScript module over `@lower` natives can do the same.
- A native callback (`@lower` parameter typed as a function) arrives in C as
  the lowered invoker and the closure, `inv(clo, args…)`, as `fs.watch` uses
  (fswatch.c). `klainsync_go(fn, env)` calls `fn(env)`: the invoker of a
  `() => void` callback has that shape, so `go(fn)` passes the pair as is.
- A value of any type crosses a native as its 8-byte `any` word, the size
  of a klainsync channel slot, so `Channel<T>` needs no per-type slot
  conversion (`chanSlotFromValue`/`chanSlotToValue`).
- Goroutines migrate between threads at safepoints, so state a native keeps
  between two calls (a receive's ok flag, a select being built) cannot be
  thread-local: it lives on the goroutine (`ks_g.nat`), thread-local only on
  a thread that is no goroutine.
- `embedDir(path)` reads the directory at compile time: a TypeScript wrapper
  would receive its argument at run time, so the call site itself must be
  the intrinsic. `@intrinsic` worked only on a global `declare function`.
- `new Webview({ serve: "./dist" })` read `serve` at compile time the same
  way. Passing `serve: embedDir("./dist")` keeps the compile-time part on
  the one intrinsic.
- A typed binding decoded the page's JSON arguments into the callback's
  declared parameter types at compile time. Calling the callback through
  `(...args: any[]) => any` with `JSON.parse(req)` spread gives the same
  results: probed with number, string, tuple, object and async callbacks
  against Node (identical output).
- `--emit-window-dts` read the bindings' codegen types at the bind sites;
  the same types are available where `new Webview(...)` of the library class
  and `.bindTyped(...)` on it are emitted.

## Decision

- `lib/node/klain_tty.ts`, `klain_tui.ts`, `klain_assets.ts`,
  `klain_webview.ts` and `klain_sync.ts`, each over natives declared in
  `lib/native.d.ts` with a `@link` unit (`tty`, `tui`, `assets`, `webview`,
  `sync`) that compiles its C in. A handle (a tui node, a window, a channel,
  an asset blob) crosses as its address in a double.
- The C entry points sit beside each runtime: `__kml_native_tty_*` in the
  tty shim, `__kml_native_tui_*` in tui.go, `__kml_native_assets_*` in
  embed_assets.c, `webviewsrc/natives.c` over `webview_*` (with the Windows
  page-tick pump and the deferring navigation shims), and
  `__kml_native_sync_*` in klainsync.c.
- `@intrinsic` on a builtin module's `declare function` reaches its emitter
  from a call of the imported name (`loweredCallDecl`, names mangled from
  library files only). `embedDir`'s intrinsic links the blob, hands it to the
  runtime (`__kml_embed_push`) and calls the module's `_kmlEmbedded()`,
  which makes the `EmbeddedAssets`; `get` is a zero-copy `ffiView` over the
  blob.
- Behaviour changes, the API being this project's own: `serve` takes an
  `EmbeddedAssets`; a second `new Webview` throws rather than failing to
  compile; `klain:tui` props are a typed `Props` object, checked by the type
  checker and buildable at run time; a closed, drained channel gives
  `undefined` from `receive()` and a select receive case; `select` throws
  past 64 cases instead of overrunning the runtime's case array; `go`'s and
  `bindings`' misuse are tsc's own diagnostics.
- Deleted: the virtual-module entries, markers and rename cases, both AST
  nodes and their sema builders, the codegen types and dispatch, and
  emit_webview.go with its hand-written IR (the eval trampoline and the
  async-return runner, lowering the IR-text ratchet's allowances).

- The webview natives' C source is named `wvnatives`: the test helper
  compiles the binding itself and skips every source named `webview*`.
- Safepoint insertion stays a compiler pass, keyed on a program importing
  `klain:sync`, and declares `klainsync_safepoint`.
- `export declare function` is not an export here, as in Node, which
  strips it and fails the import; the module declares `embedDir` and exports
  it by name.

## Side effects discovered

- The checker did not check `new C(…)`'s arguments against a class's
  constructor (ADR-01472).
- A generic class's method called through an annotation (`b: Box<number>`)
  before any `new Box<number>` was emitted failed to compile (ADR-01473);
  `klain:sync`'s generic `Channel<T>` hit it in apps/loadtest.
- A `[Symbol.iterator]()` returning a plain iterator object did not compile
  in `for…of` (ADR-01474).

## Verification

- macOS: the tty, tui, assets, webview (compile tier) and goroutine E2E
  tests; every windowed webview smoke run (`KML_WEBVIEW_SMOKE=1`, ten
  tests, including the second-window throw and `serve`); `TestWindowDTS`;
  every program importing these modules in examples/ and apps/ compiles.
- Windows: compile-checked by CI only; the windowed runs there predate this
  change (recorded on the desktop status page).
- Linux boxes: the gates in ADR-01474's verification.
