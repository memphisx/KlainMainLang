# ADR-02015: A promise's `constructor`, and await's read of it

- **Date**: 2026-11-21

## Context

- `p.constructor` of a boxed promise read as `Object`: its wrapper
  carries no class type id, so the instance's constructor lookup found
  none.
- A `constructor` defined on Promise.prototype was never read, neither
  by `p.constructor` nor by PromiseResolve. PromiseResolve runs for
  `await` and for each `for await` step: the element's promise, and each
  next() result's promise, the done step's included.

## Decision

- A boxed promise's `constructor` read (identified by the wrapper's
  header word) gives Promise.prototype's own `constructor` when it has
  one, an accessor running with the promise as `this`. Otherwise it gives
  Promise.
- A program that defines or assigns `constructor` on Promise.prototype
  gets `__kml_promise_proto_ctor_read`. The await hook calls it when the
  promise has no `constructor` of its own; a throwing getter rejects the
  await. A `for await` loop over an array also calls it for the done
  step's next() result.

## Implementation notes

- codegen/llvm/emit_dynobj.go (`emitPromiseBoxCtor`).
- codegen/llvm/emit_async.go (`ensurePromiseProtoCtorRead`,
  `writesPromiseProtoCtor`), codegen/llvm/emit_generators.go.
- codegen/llvm/tasksrc/task.c (`__kml_promise_own_ctor`).
