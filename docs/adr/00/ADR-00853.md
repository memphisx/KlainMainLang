# ADR-00853: `String`/`Number`/`Boolean` as a first-class callback

- **Relations**: Extends the callback resolver ([ADR-00686](ADR-00686.md) HOF arity)
- **Date**: 2026-09-10

## Context

`[1, 2, 3].map(String)`, `["1", "2"].map(Number)`, and `arr.filter(Boolean)` —
passing a builtin conversion by name as a HOF callback — failed with
"'String' is not a callable". `resolveCallback` recognized only named functions
and function-typed variables; the builtin conversions are compiler intrinsics
with no closure header, so a bare reference to one had nowhere to resolve. This
is an extremely common idiom (`.map(Number)` to parse a column, `.filter(Boolean)`
to drop falsy entries).

## Decision

A new callback kind `cbBuiltinConv` carries the conversion's name. `resolveCallback`
returns it for an unshadowed `String`/`Number`/`Boolean` identifier (the
user-binding lookup runs first, so a `-compat=js` shadow still wins). `emitCBCall`
special-cases the kind before its arity/coerce reconciliation: it converts the
element (`args[0]`) directly and ignores the HOF's index/array extras — matching
how these functions bind only their first argument. The conversion reuses the
value-level cores factored out as `emitBuiltinConvValue` (the same logic as the
global `String()`/`Number()`/`Boolean()` calls). The callback's reported return
type — `string`/`number`/`boolean` — flows into the HOF's result element type, so
`.map(String)` yields a `string[]`, `.map(Number)` a `number[]`.

Works uniformly across every HOF that goes through `emitCBCall` (`map`, `filter`,
`forEach`, `find`, …) — no per-method change.

## Implementation notes

`emit_func.go`: `cbBuiltinConv` kind + `builtinConvRetType`; `paramTypes()`
reports a single `any` param; `resolveCallback` identifier branch; `emitCBCall`
short-circuit + `emitBuiltinConvValue` (reuses `emitValueToString` /
`emitDynamicToString` / `emitToBool` / the `Number` value switch).

## Verification

macOS (Apple Silicon M4): matches Node — `[1,2,3].map(String)` → `1|2|3`,
`["1","2","3"].map(Number).reduce(+)` → 6, `[0,1,2,0,3].filter(Boolean)` →
`1,2,3`, `["","a","","b"].filter(Boolean)` → `a,b`, `[true,false,true].map(String)`
→ `true,false,true`; `forEach(String)` runs. New `TestE2EBuiltinConversionAsCallback`
+ the array/HOF suites green.
