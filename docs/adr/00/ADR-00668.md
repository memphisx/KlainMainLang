# ADR-00668: Aliased imports of the parse-time reexport constructors (TDD-00165 Stage 3)

- **Relations**: Implements TDD-00165 (Stage 3); Extends [ADR-00667](ADR-00667.md)
- **Date**: 2026-09-03

## Context

Stages 1–2 (ADR-00666/00667) made same-name imports work and aliased the
codegen-recognized reexports. The remaining deferral was aliasing the
**parse-time constructors** — `import { URL as U } from 'url'`, then `new U(...)`.
The parser recognizes `new URL(...)` by the literal identifier and produces a
specialized AST node (`NewURLExpression`, …); an aliased `new U(...)` was parsed
as a *generic* `NewExpression`, so a post-parse rename couldn't recover the
built-in construct.

## Investigation

Two facts reshaped the stage:

- **`Buffer` was mis-classified as parse-time.** It is `Buffer.from(...)` — a
  member call recognized in codegen (`emit_call.go`), not a `new Buffer()`
  parser construct (there is no such case in `parser/parser_literals.go`). So a
  `Buffer as B` alias renames like any Stage 2 codegen reexport (`B.from(...)` →
  `Buffer.from(...)`). Buffer moved out of `parseTimeReexports` — a free win.
- The genuine parse-time reexports are `URL`/`URLSearchParams`/`Blob`/
  `EventEmitter`, each with a dedicated AST node built from a small, fixed set of
  arguments (`NewNewURLExpression(url[, base])`, `NewNewURLSearchParamsExpression(init?)`,
  `NewNewBlobExpression(parts?, options?)`, `NewNewEventEmitterExpression(payload?)`).
  A generic `NewExpression` already carries the parsed `Args`/`TypeArgs`, so those
  nodes can be rebuilt from it directly.

## Decision

Do the rewrite in the resolver's rename pass (`resolver/rename.go`), which
already walks every expression *with scope tracking* (so a local of the alias
name still shadows the import). A new per-file `parseTimeAliases` map (alias →
canonical built-in name) is populated in `resolver.go` where the aliased
parse-time import used to be rejected. In `rewriteExpr`'s `NewExpression` case,
when the (unshadowed) `ClassName` is an alias, the sub-expressions are rewritten
and then `buildReexportConstructor` returns the specialized node under the
canonical name. Argument-count violations record a first-write-wins error via the
existing `reservedErr` channel, so the alias form enforces the same contract as
the native form (e.g. `new EventEmitter(arg)` still rejects).

This keeps the parser untouched (no coupling of the parser to the virtual-module
tables) and avoids any textual-ordering dependency — the resolver sees the whole
file.

## Implementation notes

- `buildReexportConstructor` is a `lookupTable` method so it can reach
  `reservedErr`; it maps `Args`/`TypeArgs` to each node's constructor and
  validates arity (`URL` 1–2, `URLSearchParams` ≤1, `Blob` ≤2, `EventEmitter`
  exactly 0 + optional single type arg).
- The conversion runs inside the `!sc.bound(ClassName)` guard, so shadowing wins
  (tested); it returns the new node directly, so its already-rewritten
  sub-expressions are not re-visited.

## Side effects discovered

With Buffer reclassified, **all five modules' primary exports are now fully
importable in every common form** (same-name, `node:`, and aliased). The only
remaining TDD-00165 work is Stage 4 — the genuinely module-only *extras* (legacy
`url.parse`/`fileURLToPath`, `PerformanceObserver`, `timers/promises`,
`events.once`), which are new feature surfaces rather than import wiring.

## Verification

E2E tests in `tests/node_core_modules_test.go`: aliased `URL`/`URLSearchParams`,
aliased `EventEmitter`, aliased `Blob`, `Buffer` alias via member call, the
arg-count rejection, and local-shadow-wins. Two now-obsolete "aliased reexport
rejected" tests (Stages 1–2) were removed. `go test` over the
import/module/rename/shadow/blob suites green (Mac); `go vet ./resolver` clean.
