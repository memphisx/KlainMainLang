# ADR-01208: The WebSocket client and EventSource are TypeScript global modules

- **Relations**: `Implements TDD-00232`, `Extends ADR-01203`
- **Date**: 2026-09-28

## Context

TDD-00232 Stage 2. The global `WebSocket` was code-generated
(`emit_websocket_client.go`, `runtime_websocket_client.go`): a synchronous
connect and handshake in the constructor, a bespoke message record
(`ev.data` always a string, `ev.isBinary`, `ev.dataBytes()`), no
`binaryType`, `CloseEvent`, `ErrorEvent`, `addEventListener` or protocol
list. `EventSource` was code-generated too (`emit_eventsource.go`,
`runtime_eventsource.go`, 1,600 lines of libcurl plumbing) and its
dispatch owned the codegen name `MessageEvent`, so the two had to move
together.

## Investigation

- undici's `lib/web/websocket` fires `open`, `message` and `close`
  synchronously from its parser, not a task per event as the TDD's design
  guessed; the module follows undici.
- `data instanceof Blob` on an `any` parameter did not compile, and a
  host value in `any` read as a string: fixed first (ADR-01204). A
  `wss://` connect by IP failed the certificate check and `new URL("ws://…")`
  threw (ADR-01207). A fetch with a signal resolved only at the end of its
  body, so EventSource never opened (ADR-01205).
- `TextDecoder` has no `{ stream: true }`: EventSource splits lines on
  bytes and decodes each line, which is what undici's `EventSourceStream`
  does anyway.
- `crypto.randomBytes` returned a plain `Uint8Array` (no
  `.toString('base64')`); Node returns a Buffer.
- The resolver brought in a global module when its name appeared anywhere
  in a file, comments included: klain:ws's comment "the browser
  WebSocket's…" pulled the client into every WebSocket server.

## Decision

- **`lib/node/kml_websocket.ts`** (`// kml:global`), after undici: URL
  validation (`http:`/`https:` rewritten, a fragment or other scheme a
  `SyntaxError` with undici's messages), the protocol list, the connect
  over `net.connect`/`tls.connect` returning `CONNECTING`, the opening
  handshake (a random key, `Sec-WebSocket-Accept` checked, the chosen
  protocol checked against the offer), masked client frames, masked server
  frames refused, fragments reassembled, text frames UTF-8 checked
  (failing with 1007), ping answered with pong, the closing handshake
  (`wasClean`), `binaryType` (`blob` by default), `bufferedAmount`, and
  `send` of a string, `ArrayBuffer`, view or `Blob` in order (a Blob's
  bytes are read first, undici's send queue). A failed connection fires an
  `ErrorEvent`, then a `CloseEvent` with 1006.
- **`lib/node/kml_eventsource.ts`**: undici's `EventSource` over `fetch`
  with an `AbortController` — `text/event-stream` and status 200 checked
  (anything else fails for good), the stream parsed per the HTML event
  stream rules (CRLF/LF/CR, comments, `data`/`event`/`id`/`retry`, a
  leading BOM dropped), `MessageEvent`s with `origin` and `lastEventId`,
  reconnect after `retry` with `Last-Event-ID`, `close()` aborting the
  fetch.
- **`MessageEvent`, `CloseEvent`, `ErrorEvent`** join
  `kml_event_target.ts`; `lib/node.d.ts` declares them, `WebSocket` and
  `EventSource` in TypeScript's `lib.dom` shapes (`ports`/`source` as
  `any`: `MessagePort` is not declared yet).
- **The frame codec** moves to `lib/node/internal_websocket_frame.ts`
  (`encodeFrame`, `parseFrame`, `isUtf8`), used by klain:ws's server and
  the client.
- **Resolver**: a global module comes in when its name appears as an
  identifier outside comments and quoted strings (`codeIdents`); a global
  module file is not importable as a module.
- `crypto.randomBytes` returns a Buffer.
- **Deleted**: the four emitter/runtime files above, `emit_websocket.go`
  and `runtime_websocket.go` (their SHA-1 and frame helpers had no user
  left) and their unit test, the `NewWebSocketExpression` and
  `NewEventSourceExpression` nodes and their `new` rewrites,
  `WebSocketClientType`, `EventSourceType`, `MessageEventType`,
  `WSMessageEventType` and the `IsWebSocketClient`/`IsEventSource` flags,
  the event loop's WebSocket and EventSource scans, fd-set entries,
  keep-alive terms and reconnect deadline.

## Side effects discovered

- The client offers no `permessage-deflate` (Node's does), so
  `extensions` is always `''` (BACKLOG).
- `TextDecoder.decode(input, { stream: true })` is not supported
  (BACKLOG).
- A property or method of a host value read through `any` is `undefined`
  (ADR-01204, BACKLOG).
- `crypto.randomBytes(n, cb)` calls `cb` synchronously; Node calls it
  from the thread pool (BACKLOG).

## Verification

Mac (Apple Silicon), against Node v24.19: the same client program run
under this compiler and under Node against a klain:ws server prints the
same (open, a text echo, a `Uint8Array` and a `Blob` echoed as
`ArrayBuffer`s, a clean 1000 close); the EventSource example prints what
`node --experimental-eventsource` prints (the order of two independent
connections' first events aside); `TestE2EWebSocketConstructorErrorsAndRefusal`
matches Node; the WebSocket, WSS and EventSource tests pass, with the
client tests rewritten to Node's API (`binaryType`, `ev.data`,
`readyState` 3 after a refused connect);
`TestE2EWebSocketSendBlobInOrder` and
`TestE2EWebSocketInvalidUTF8FailsConnection` are new.
