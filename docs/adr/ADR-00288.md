# ADR-00288: Blocked-by histogram in the conformance runner

- **Relations**: Extends [TDD-00082](../tdd/TDD-00082.md)'s runner (TDD-00008 Design V2 report format)
- **Date**: 2026-08-22

## Context

A missing API compile-fails a *whole* Test262 file, masking bugs in every
in-scope feature the file co-exercises — which is exactly why
intrinsically-low-value leaf APIs deserve elevation by leverage, not face
value. What was missing was the measurement: a ranking of which concrete
missing identifiers gate the most files.

## Decision

`tools/conformance` now records, for every compile-phase failure, the
concrete blocker extracted from the *raw* (position-prefixed,
identifier-carrying) compile error — the exact information the existing
`normalizeReason` bucketing deliberately collapses to `'%s'`. Extraction is
heuristic: the first single-quoted token, falling back to the leading token
of an "... is not supported" message; empty when nothing identifier-like
exists (those files still appear in the reason buckets).

The report gains a **Blocked-by histogram (compile-phase)** section: one row
per blocker with the count of files whose *first* error it was, plus a
representative example file. First-error-only is by design — the ranking is
iterative (fix the top row, re-run, its files redistribute to their next
blocker). Low-count rows can be program-local variable names caught by the
same extraction; no lexical filter is applied since real blockers (`assert`)
are lowercase too, and ranking sinks the noise.

## Verification

Smoke run over `built-ins/Reflect` (153 files, macOS): histogram ranks
`assert` (44), `TypeError` (26), `Proxy` (10) — plausible and immediately
actionable. Full-corpus report regenerated by `make conformance` at delivery.
