# ADR-00231: Conditional types + infer + generic type aliases + structural assignability

- **Relations**: `Implements TDD-00079` (Stage 3); `Extends ADR-00230`
- **Date**: 2026-08-19

## Context

Final stage of TDD-00079: conditional types `T extends U ? X : Y` with `infer`.
To be useful they need generic **type aliases** (`type NonNull<T> = …`), which
didn't exist, and a general **structural assignability** predicate for the
`extends` test, which also didn't exist (only nominal `implements` conformance
and a scalar-union match). So this stage is four coupled pieces.

## Investigation

Monomorphization is again the enabler: a conditional's check type is concrete
once its enclosing generic alias is instantiated, so the conditional evaluates at
`resolveType` — no lazy type-level machinery. `extends`/`infer` are handled as a
reserved token (`EXTENDS`) / a contextual identifier. Generic aliases can reuse
the object seam, but the existing `substituteGenericType` is shallow (bare `T`
and one-level `T[]` only), so a body containing a conditional/object/mapped form
needed a full annotation-level substitution instead.

## Decision

- **Generic type aliases.** `TypeAliasDeclaration` gains `TypeParams`;
  `parseTypeAliasDecl` parses an optional `<T>`. Non-generic aliases resolve
  eagerly as before; generic ones register into `genericTypeAliases` and are
  instantiated on demand: at a use `Name<Concrete>`, `substituteAnnotation`
  replaces each parameter (bare `T`, incl. `T[]` suffixes) throughout the body
  annotation with its concrete argument, and the result is resolved.
- **Conditional grammar.** `parseTypeAnnotation` becomes a conditional level over
  the union level (`parseUnionType`): after a union, an `extends` starts a
  conditional whose check/extends operands are union-level and whose two branches
  are full annotations (so conditionals nest right-associatively). `infer R` is a
  type atom inside the extends clause.
- **Evaluation** (emit_conditional_types.go). `resolveConditionalType` resolves
  the check type, `matchExtends` structurally matches it against the extends
  pattern — a bare `infer R` captures anything; `Array<infer E>`/`Promise<infer V>`
  match through the container; anything else is an `assignable` test — binding
  `infer` variables, then resolves the taken branch (`resolveWithInferBindings`
  substitutes a captured variable, optionally wrapped one level in
  Array/Promise/Set).
- **`assignable(a, b)`** — the first general structural subtype check: `any`/
  `unknown`/union on the right accept anything; null/undefined follow nullability;
  objects use width subtyping (a has all of b's fields, assignably); arrays are
  element-wise; scalars are IR-equal with numeric-width leniency.

Deferred: function-signature inference (`(...) => infer R`), deeper `infer`
nesting, and `<T extends X>` *constraints* on generic functions/interfaces (still
a clean parser rejection; conditional types don't need it).

## Implementation notes

`rewriteType` (resolver) gained descent into the conditional fields
(`CheckType`/`ExtendsType`/`TrueType`/`FalseType`) — the same rename gap the
composite members and mapped operands had. `substituteAnnotation` recurses
through every nested annotation (fields, members, mapped/keyof/indexed, nested
conditionals) so a parameter is replaced wherever it appears. No new runtime
representation: everything resolves to an ordinary concrete `Type`.
