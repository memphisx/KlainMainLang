# ADR-00902: isNaN / isFinite on a dynamic (any) operand

- **Date**: 2026-09-12
- **Relations**: Extends ADR-00901

## Context

Found in passing while fixing ADR-00901: the global `isNaN`/`isFinite` on an
`any`-boxed value returned the wrong answer.

```ts
const x = null + undefined;  // any-boxed NaN
isNaN(x)                     // returned false; Node: true
isFinite(x)                  // returned true;  Node: false
```

## Investigation

`emitNumberIsNaN`/`emitNumberIsFinite` (`emit_call_number.go`) short-circuit a
non-`Float` operand to the trivial constant (`isNaN→false`, `isFinite→true`). For
a dynamic operand `val.Ty.Float` is false, so a boxed NaN returned the constant
without ever inspecting the value.

## Decision

For a dynamic operand, ToNumber it first (`coerce(any → double)`, which unboxes
and runs the JS numeric conversion) and then apply the existing `fcmp uno` /
finiteness test. This is the global-`isNaN` semantics; for a number-holding box
it also matches `Number.isNaN`. Other static non-float types keep the trivial
constant.

## Implementation notes

- `coerce(anyVal, TypeF64)` already does the unbox-and-ToNumber (verified: a
  boxed NaN coerces to a double NaN).
- Global `isNaN`/`isFinite` still do not ToNumber a *string* operand
  (`isNaN("foo")` should be true) — a separate, pre-existing gap not addressed
  here; only the dynamic case is fixed.

## Side effects discovered

The global-vs-`Number` distinction (coerce vs no-coerce) remains unmodeled for
string operands; noted as future work.
