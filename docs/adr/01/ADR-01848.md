# ADR-01848: A call through an unannotated variable is no assertion

- **Relations**: `Implements TDD-00230` (P3.3: the checker answers what inferExprType did)
- **Date**: 2026-10-21

## Context

- A call statement can narrow what flows past it when its callee is an `asserts` function. A call whose callee the checker cannot type, with an argument that mentions a reference, made that reference unknown (`unknownGuard`), because the call might be an assertion.
- The callee was typed through `dottedType`. For `const b = s.buffered[n]; b.cb(s.errored ?? e)` inside a loop, `b`'s type is its initializer. Typing it needs `s`'s flow type at the loop head, which walks back through the back edge to this same call. The cycle left the callee unanswered, so `s` was unknown everywhere in the loop.
- In `lib/node/stream.ts` (`errorBuffer`), that made every `s.…` read in the loop unanswered, in every program that links `stream`.
- tsc reads an assertion's callee through `getEffectsSignature`. It requires every name in the call target to be declared with an explicit type (TS2775), so a call through an unannotated variable is never an assertion and is skipped.

## Decision

- `effectsType` types the callee of a call statement for assertion narrowing (`callMayNarrow`, `narrowByAssertion`) and for a never-returning call (`neverReturning`). When the callee is rooted at a variable declared without an annotation, it has no effects signature. `require("m")` is the exception: it is an alias of the module.
- A condition's type guard (`if (isStr(x))`) still reads its callee through `dottedType`. tsc resolves that call's signature normally, so an unannotated `const` guard keeps narrowing.

## Consequences

- `TestCallThroughUnannotatedVariableIsNoAssertion` covers the loop shape.
- Verified on Apple Silicon (checker package, targeted assertion, narrowing, never, guard, stream and require tests).
