# TDD-00135: Precise/moving GC backend (Immix) — future goal, low priority

- **Status**: Not Started
- **Date**: 2026-08-27

Reference/feasibility doc (same role as [TDD-00020](TDD-00020.md) Windows /
[TDD-00124](TDD-00124.md) self-hosting): captured as a direction, deliberately
low priority given the effort-to-payoff ratio at this stage.

## Context

`-mm=gc` uses **Boehm** — a conservative, non-moving collector
([TDD-00001](TDD-00001.md)). It was the right bootstrap choice (works with the
existing IR, no GC stack maps needed, scans the flat struct/array layout out of
the box). But conservative + non-moving means heap fragmentation and
stop-the-world pauses at scale, versus Go's precise concurrent collector. A
**precise, moving/compacting** collector — Immix is the strong candidate — would
close the last GC-latency gap and fits the "menu of memory options" identity as a
third mode (`-mm=gc-immix` or similar) alongside `manual`/`gc`.

## Why Immix specifically

A mark-region collector combining a compacting collector's space efficiency with
a free-list allocator's low overhead. Mature open-source reference
implementations (Rust/C) exist that are designed to be linked as a runtime for an
LLVM-based custom language, which matches this compiler's C-runtime-linking
pattern.

## The real cost (why it's low priority)

Precise (non-conservative) collection needs the compiler to tell the GC **exactly
which stack/register slots hold pointers at each collection safepoint** — LLVM
`llvm.experimental.gc.statepoint` + generated stack maps, plus a `gc "..."`
strategy. That is a substantial, cross-cutting IR-emission change (every call
site becomes a potential safepoint; every live pointer must be spillable/
relocatable), and a *moving* collector additionally requires that no raw,
un-tracked pointer is ever held across a safepoint — which interacts with every
hand-emitted-IR builtin in the codebase (`fetch`, streams, `http`, fibers). The
fiber/`ucontext` model and the C-runtime handles are the hardest part: a moved
object's address changing under a suspended fiber or inside a C helper is a
correctness minefield.

## Prerequisites / open questions

- Pin down whether a precise collector is compatible with the `ucontext` fiber
  frames and the many C-runtime builtins holding raw pointers, or whether those
  paths need pinning/handles — likely the gating feasibility question.
- Evaluate Immix reference implementations for LLVM-language embedding, and the
  statepoint-based stack-map emission cost against real workloads (does any target
  workload — CLI tools, microservices — actually feel Boehm's pauses?).
- Keep `manual` and Boehm `gc` as-is; this is purely an additional opt-in mode,
  never a replacement.
