# ADR-01030: Windows `fs` — POSIX-semantics unlink/rename, libuv's errno table, `readlink`/`chdir`/`stat.blocks`, OS copy, junctions

- **Relations**: `Implements TDD-00180` (§4); `Extends ADR-00739`, `ADR-00743`, `ADR-00768`, `ADR-00769`
- **Date**: 2026-09-21

## Context

A row-by-row re-check of the [TDD-00180](../tdd/TDD-00180.md) audit against the tree found that §4 (`fs`) still had eight open rows, all of them places where the Windows shim produced a plausible answer rather than Node's:

- an unlinked file that another descriptor holds open kept its **name** until the last close (`DeleteFileW` leaves it delete-pending), so `unlinkSync(p); writeFileSync(p, …)` failed; `renameSync` over an open target failed `EPERM`;
- `rename` passed `MOVEFILE_COPY_ALLOWED`, silently copying across volumes where Node reports `EXDEV`;
- the Win32→errno table mapped `ERROR_ACCESS_DENIED` to `EACCES` and every unknown code to `EIO`; libuv maps the first to `EPERM` and the rest to `UNKNOWN`;
- `readlink` preferred the reparse point's PrintName and only stripped `\??\`;
- `chdir` did not maintain the hidden per-drive `=X:` variables;
- `stat.blocks` was `ceil(size / 512)`;
- `copyFileSync` was a read-then-write, dropping attributes, timestamps and alternate streams;
- `symlinkSync` had no `type` argument, so no junctions.

## Investigation

libuv's `src/win/fs.c` is the reference for each: `fs__unlink` (`FileDispositionInfoEx` with `POSIX_SEMANTICS | IGNORE_READONLY_ATTRIBUTE`, classic path as the fallback for filesystems without the class), `fs__rename` (`FileRenameInfoEx`, then `MoveFileExW(MOVEFILE_REPLACE_EXISTING)` — no copy flag), `fs__readlink_handle` (SubstituteName; `\??\C:\…` → `C:\…`, `\??\UNC\…` → `\\…`; a mount point that is not a drive path is not a link), `uv_chdir` (`SetEnvironmentVariableW(L"=C:", cwd)`), `fs__stat_handle` (`st_blocks = AllocationSize >> 9`, `st_blksize = 4096` — the audit's "2048" was stale), `fs__copyfile` (`CopyFileW`), `fs__create_junction`, and `uv_translate_sys_error`.

The two `Ex` information classes postdate some mingw header sets (the header-drift problem ADR-00734 records), so their structures and class numbers are spelled out locally rather than taken from `<winbase.h>`.

`ENOTSUP` and `UNKNOWN` have no Linux errno, and the shim speaks Linux errno numbers to the IR. They get private numbers above the Linux range (`4049`, `4094`) that only the errno→code table knows.

## Decision

All eight rows are closed in `win32fs.c`, each following libuv:

- `unlink`: `posix_delete()` first, the existing clear-read-only + `DeleteFileW` path as fallback.
- `rename`: `posix_rename()` first, then `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`. A cross-volume rename is now `EXDEV`.
- `win_errno`: rewritten as libuv's table; default `L_UNKNOWN`. `errnoCodePairs`/`libuvErrnoDesc` gain `UNKNOWN` ("unknown error"), `ENOTSUP`, `ESRCH`, `ECHILD`.
- `reparse_target_utf8`: SubstituteName with the NT prefix rewritten; `lstat().size` follows automatically (ADR-00769 shares the helper).
- `chdir`: writes `=X:` after a successful `SetCurrentDirectoryW`.
- `stat`: `blocks` from `FILE_STANDARD_INFO.AllocationSize`.
- `copyFileSync`: the pre-flight guard (which owns Node's two-path error shape and the atomic `COPYFILE_EXCL` create, ADR-01000/ADR-00788) stays; the transfer becomes `__kml_win_copyfile` → `CopyFileW`, with one retry after clearing a read-only destination. POSIX hosts keep the binary-safe read+write.
- `symlinkSync(target, path[, type])`: `'file' | 'dir' | 'junction' | null`. A literal is validated on every host; the value only has an effect on Windows, where the IR stages it through `__kml_win_symlink_type` immediately before `symlink()`. `'junction'` builds an `IO_REPARSE_TAG_MOUNT_POINT` reparse point (substitute `\??\C:\dir\`, print `C:\dir\`), resolving a relative target against the link's directory first because a junction can only name an absolute path.

## Implementation notes

`codegen/llvm/win32src/win32fs.c`, `emit_fs.go` (`symlinkSync` arity and type staging, Windows copy branch), `runtime_fs.go` (`ensureFsCopyFileOS`, errno pairs), `emitter.go` (two dedupe flags).

The `type` hand-off is a thread-local consumed and cleared by `symlink()`, so a Worker's call cannot leak into another thread's.

## Side effects discovered

- `fchmod` and `statfs` are absent on every host — not Windows work; they remain rows for the cross-platform `fs` surface.
- A junction reads back with a trailing separator (`C:\dir\`), which is what libuv stores and Node returns.

## Verification

Windows 11 (26200), MSYS2 UCRT64 clang. New `tests/fs_faithful_windows_test.go`: unlink-while-open then recreate, rename over an open target, `blocks` from the allocation size, `chdir` + drive-relative `path.resolve`, junction create/lstat/readlink/read-through/unlink (absolute and relative target — runs without Developer Mode), copy carrying mtime and the read-only bit plus `COPYFILE_EXCL` → `EEXIST`/`copyfile`, and `EISDIR` with libuv's `-4068`. The existing `TestE2EFs*` suites pass unchanged. Linux/macOS: the POSIX paths are untouched apart from the shared errno table gaining `ESRCH`/`ECHILD`; not run here.
