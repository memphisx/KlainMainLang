# ADR-00090: `os` module

- **Relations**: Implements TDD-00024.
- **Date**: 2026-08-03

## Context

`docs/status/OS.md` tracked `os` at 0/7, flagged as high relevance to this project's own CLI-priority tiebreaker (`os.homedir()`/`.tmpdir()` for config/scratch-file locations). Requested directly by the user as the follow-up to `EventEmitter<T>` (ADR-00089).

Two scoping decisions were made with the user before implementation (see [TDD-00024](../tdd/TDD-00024.md) for the full design pass):

1. `os.freemem()` implements the real Darwin path now (Mach `host_statistics`), accepted as unverified in this Linux-only dev sandbox, to be tested later on real Apple Silicon hardware.
2. `os.cpus()` builds real per-core `model`/`speed`/`times`, not a placeholder-filled count array — Linux via `/proc/cpuinfo`/`/proc/stat` parsing, Darwin via `sysctlbyname`/Mach `host_processor_info`.

## Investigation

Read `runtime_process.go`'s `nodePlatformName()` (the `runtime.GOOS`-branch precedent `process.platform` already uses) and `runtime_http.go`'s `ucontextLayout()` (same Go-side-platform-branch mechanism, applied to a harder case — a struct whose *size* differs by target). Read `emit_process.go`'s `emitGetenvCall`/`ensureGetenv` (reused for `homedir`/`tmpdir`), `emit_path.go`'s dispatch shape (flat identifier-name switch in `emit_call.go`, the pattern `os.*` also uses), and `types.go`'s `SettlementType`/`PathParsedType` (nested-object-field and small-object-construction precedent for `CPUInfoType()`/`CPUTimesType()`).

Two real correctness risks were resolved before writing any IR, not discovered afterward:

- **`sysconf()`'s constants are not portable across Linux and Darwin.** Rather than trust memory for either platform's numbering, Linux's `_SC_PAGESIZE`/`_SC_PHYS_PAGES`/`_SC_AVPHYS_PAGES`/`_SC_NPROCESSORS_ONLN`/`_SC_CLK_TCK` (`30`/`85`/`86`/`84`/`2`) were verified by compiling and running a small C probe (`unistd.h`, `printf`ing each constant and its live `sysconf()` value) directly on this project's own dev sandbox. Darwin's `_SC_*` numbering is a different, unverified-here enum, so Darwin deliberately uses `sysctlbyname` (a string-keyed MIB lookup) instead everywhere it's an option — no numeric constant to get wrong there at all.
- **`/proc/cpuinfo`/`/proc/stat` aren't seekable.** `emit_fs.go`'s existing `__kml_fs_read_file` sizes its read via `SEEK_END`+`ftell()`, which doesn't return a real size for procfs files (synthesized on read, not backed by fixed storage) — confirmed by reading `/proc/cpuinfo`'s actual real-machine output before writing any parsing code. This is why `os` needed its own growable-buffer, read-until-`fread()`-returns-0 helper (`__kml_os_read_proc_file`) rather than reusing the existing one.
- **Naively substring-matching a `"cpuN"` marker is ambiguous** (`"cpu1"` is a literal substring of `"cpu10"`/`"cpu11"`/…). Both `/proc/cpuinfo` (block walking) and `/proc/stat` (line walking) instead advance strictly by *position* — the next `"processor\t:"` occurrence forward from the current block, or the next line after the current one — never by re-matching a numbered label.

## Decision

Platform selection is a Go-side `switch runtime.GOOS` at codegen time, not a runtime IR branch — this compiler doesn't cross-compile, so a Linux build only ever contains the `sysconf`/`/proc` code path in its output, and a Darwin build only ever contains the `sysctlbyname`/Mach path.

`os.platform()`/`os.EOL`/`os.homedir()`/`os.tmpdir()`/`os.hostname()` are thin, inline (no separate declared C-runtime helper function) Go-emitted wrappers around `nodePlatformName()`/`getenv()`/`gethostname()` — `homedir()` throws a catchable Error if `HOME` is unset (matches real Node); `tmpdir()` falls back to `"/tmp"` silently (also matches real Node, never throws).

`os.totalmem()`/`os.freemem()` are similarly inline, `runtime.GOOS`-branched wrappers: Linux via two `sysconf()` calls multiplied together; Darwin's `totalmem()` via one `sysctlbyname("hw.memsize")` call, `freemem()` via `mach_host_self()`→`host_statistics(HOST_VM_INFO)`→`vm_statistics_data_t.free_count * getpagesize()`.

`os.cpus()` is the one genuinely substantial piece — two large hand-written IR-text C-runtime functions (`__kml_os_cpus_linux`/`__kml_os_cpus_darwin`, `runtime_os.go`), each building a runtime loop over the (runtime-known) core count that mallocs one `CPUInfoType()` heap object per core (itself pointing to a separately-malloc'd `CPUTimesType()` sub-object — nested objects are always stored by pointer, per `StructFieldIR`'s existing `IsObject → "ptr"` rule, the same shape `SettlementType`'s `reason` field already uses), and returns a `{ptr, i64}` array aggregate. Field offsets/struct sizes are computed once via a small `cpuInfoFieldIndexes` helper (`CPUInfoType().FieldIndex(...)`/`.StructIR()`/`.StructSize()`) and threaded into the generated IR — never hardcoded — so the two functions can't silently drift out of sync with `types.go`'s field layout.

## Implementation notes

New files: `codegen/llvm/emit_os.go` (Go codegen — the 8 simple/medium wrappers), `codegen/llvm/runtime_os.go` (the 3 substantial hand-written IR helpers: `__kml_os_read_proc_file`, `__kml_os_cpus_linux`, `__kml_os_cpus_darwin`).

Modified: `codegen/llvm/types.go` (`CPUTimesType`/`CPUInfoType`), `codegen/llvm/emit_call.go`/`emit_exprs_member.go`/`emit_exprs_types.go` (dispatch + type inference — `os.*` follows the exact same flat-identifier-switch pattern `path.*`/`process.*` already use), `codegen/llvm/emitter.go` (new `used*` idempotency-guard fields).

The IR-text-building code in `runtime_os.go` deliberately uses a `strings.Builder` with one `fmt.Fprintf` call per line rather than one giant `fmt.Sprintf` with dozens of positional `%s`/`%d` verbs — an earlier draft of `ensureOSCpusLinux` attempted the latter and became unreviewable (a single misplaced argument would silently shift every verb after it with no compiler error, since it's all just string formatting). The per-line-builder version was rewritten from scratch specifically to be checkable by inspection, not just by testing.

`/proc/cpuinfo`'s per-processor blocks and `/proc/stat`'s per-core lines are walked in strict file order — a documented, stable Linux kernel behavior this implementation depends on (not re-verified per-kernel-version, consistent with how the rest of this codebase treats documented OS/libc contracts).

## Side effects discovered

None in already-shipped code. (Two design-time risks were caught and designed around before implementation — see Investigation — rather than discovered as bugs afterward.)

## Verification

- `go build -o klainmain .` clean.
- `go test ./...`: 696 passed, 0 failed (9 new tests in `tests/os_test.go`).
- All 71 examples (including the new `examples/os/os.ts`) compile and run; the new example's output manually diffed against its inline comments and matches.
- **Linux path fully verified against real hardware** (this project's own 16-core AMD Ryzen dev sandbox): `os.platform()` → `"linux"`; `os.homedir()`/`os.tmpdir()`/`os.hostname()` match real `$HOME`/fallback/actual machine hostname; `os.totalmem()`/`os.freemem()` return real, sane byte counts (`freemem() <= totalmem()`); `os.cpus()` returns exactly 16 entries, each with the correct real CPU model string ("AMD Ryzen 7 8840U w/ Radeon 780M Graphics"), a plausible per-core dynamic clock speed (observed ranging 400–2326 MHz across cores, consistent with real frequency scaling), and monotonically-sane `times` fields (`idle` dominant, matching an actual mostly-idle system) — manually printed and eyeballed per-core, not just aggregate-checked.
- **Darwin path (`os.freemem()`, `os.cpus()`'s `times`) is NOT compiled or run anywhere in this work** — no Darwin target available in this sandbox. Written against documented Mach ABI shapes (`vm_statistics_data_t`, `host_processor_info`'s tick array — both use `natural_t`/`unsigned int`, a stable 4-byte Mach convention on every Darwin architecture) and cross-checked against `libuv`'s own public Darwin implementation for field mapping/tick-rate conventions, but this is design-time confidence, not test confidence. Flagged in `docs/status/OS.md`'s Known Limitations and expected to need adjustment once the user tests it on real Apple Silicon hardware.
