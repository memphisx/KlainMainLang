# ADR-00585: URLPattern username/password components

- **Relations**: Extends [ADR-00311](ADR-00311.md), [TDD-00100](../tdd/TDD-00100.md)
- **Date**: 2026-09-01

## Context

`URLPattern` matched six components (protocol/hostname/port/pathname/search/
hash); `username` and `password` were a deliberate TDD-00100 scope cut. With
`URL` now exposing username/password (ADR-00577), extending the pattern matcher
to them is straightforward.

## Decision

Grow the component set to eight in lockstep across both halves:

- **C runtime** (`urlpattern.c`): `KML_UP_NCOMP` 6 → 8, add
  `CURLUPART_USER`/`CURLUPART_PASSWORD` and extend `partIDs` so `parse_input`
  extracts the input URL's userinfo. The two new components use the default
  `.+` segment class and default to `""` when absent (a URL with no userinfo),
  so existing patterns still match (an unspecified component defaults to `*`,
  which matches empty).
- **Go** (`emit_urlpattern.go`): add `username`/`password` to
  `urlPatternComponents` and the error message; `URLPatternType()` gains the two
  fields so the construction/store loop and component reads work unchanged.

## Verification

`TestE2EURLPatternUserPass` (a username pattern matching/not-matching a URL's
user, `:name` capture alongside it, a password pattern) compared byte-for-byte
against Node v26. The existing URLPattern suite still passes (the new components
default to `*`, so six-component patterns are unaffected). Built and verified on
Mac (Apple Silicon).
