# ADR-00634: `klain:ws` WebSocketServer, and removing the `http.listen({ ws })` option

- **Relations**: `Implements TDD-00158` (Stage 2), `Extends ADR-00633`, `Extends ADR-00126`/`ADR-00127` (WS server codec/handshake/ping-pong)
- **Date**: 2026-09-02

## Context

The ergonomic WebSocket-server surface (a `WSConnection` with
`.onmessage`/`.send()`/`.close()`, automatic ping→pong, and the Close-frame
handshake) shipped in TDD-00039 as a bespoke `http.listen(port, handler,
{ ws })` option. Under the faithful-under-Node-namespaces rule this is a
double violation: `http.listen` itself is non-Node, and a built-in WebSocket
server is non-Node (Node exposes only the raw `'upgrade'` event, ADR-00633).
The convenience is worth keeping — it is what the `ws` npm package occupies —
but it belongs under an explicitly-non-Node specifier.

## Decision

Re-home the convenience as `klain:ws`'s `WebSocketServer`, built on the
faithful `'upgrade'` machinery, and **remove** the `http.listen({ ws })`
option.

- **`klain:ws` virtual module** (resolver/virtual_modules.go): marker
  `ws__kml_builtin`, export `WebSocketServer`, bound as identity (a parse-time
  constructor, like `Channel`/`Webview`/stream classes — rename.go). The
  resolver records the import on the merged program (`UsesKlainWS`), mirroring
  `UsesKlainSync`.
- **`new WebSocketServer({ server })`** — recognized in `emitNewExpression`
  (and `inferExprType`/the var-decl type switch) when `usedKlainWS`; returns an
  opaque `WebSocketServerType` handle (a bare tagged ptr — the http server is a
  process-singleton, so the handle carries no per-instance state, and the
  `{ server }` option is validated for shape only).
- **`wss.on('connection', listener)`** — routed by receiver type
  (`IsWebSocketServer`) to `emitWebSocketServerMethod`, which stores the
  `WSConnection` listener into `@__kml_listen_ws_handler` — the same global the
  dispatcher's WS block reads.
- **Dispatcher gating** — the WebSocket handshake + frame loop is now emitted
  when `e.usedKlainWS` (was: the `hasWSHandler` param threaded from
  `http.listen`), guarded at runtime by a null-check on the handler global
  (klain:ws sets it via `.on('connection')`, which may run before or after the
  dispatcher is built). The `hasWSHandler` parameter is removed from
  `buildHTTPDispatcher`.
- **`wss://`** — `emitWSHandshakeAndLoop`/`emitWSServerLoop`'s eight raw
  `write`/`read`/`close` sites now route through the TLS-aware conn shims when
  `usedHTTPS1Server` (helpers `wsWriteCall`/`wsReadCallee`/`wsCloseCall`); a
  plain server keeps byte-identical raw I/O. So a `WebSocketServer` on an
  `https.createServer` speaks `wss://` with no further code.
- **Removal** — the `ws` field on the `http.listen` options object is rejected
  with a message pointing at `klain:ws`; `{ workers: N }` is unaffected.

## Implementation notes

- New file emit_ws_server.go: `WebSocketServerType`, `emitNewWebSocketServer`,
  `emitWebSocketServerMethod`.
- The single in-repo caller (`examples/websocket/websocket_server.ts`) and the
  seven WS-server E2E test sources were migrated to
  `http.createServer(...)` + `new WebSocketServer({ server })` +
  `server.listen(...)`.

## Side effects discovered

None beyond ADR-00633's note. The `http.listen`-under-the-`http`-namespace
faithfulness gap (a broader sweep: `listen`/`close`/`closeAllConnections` are
Server methods in Node, not `http.*` functions) is real but out of scope here
— tracked as its own follow-up.

## Verification

- Mac (Apple Silicon): `go build`, `go vet` clean. New E2E test
  `TestE2EWSSServerKlainWS` (a real WebSocket handshake + masked frame echo
  over TLS via klain:ws) green; the seven migrated WS-server tests green; all
  255 examples pass (incl. the migrated `websocket_server.ts`); broad
  HTTP/net/TLS/WS suites green.
- **Linux verified** (Debian/glibc/arm64, Docker `golang:latest` + clang 19 +
  `libssl-dev`/`libcurl4-openssl-dev`/`libnghttp2-dev`):
  `TestE2EWSSServerKlainWS` (a full WebSocket handshake + frame echo over TLS
  via klain:ws) passes, alongside the plain-`ws` handshake and the wss client
  — the TLS-routed server frame path works on OpenSSL/Linux.
