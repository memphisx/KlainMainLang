# ADR-00834: optional chaining `o?.x` yields `PropType | undefined`

- **Relations**: Extends [TDD-00187](../tdd/TDD-00187.md) (the `T | undefined` sentinel) and [ADR-00833](ADR-00833.md) (the null-vs-undefined `===` distinction it relies on)
- **Date**: 2026-09-10

## Context

`o?.x` on a `null` receiver returned the property type's **zero value** — `null`
for a pointer prop, `0` for a scalar prop — where TS/JS short-circuit to
`undefined`. So `o?.name` printed `null` and `o?.name === undefined` was `false`
(Node: `undefined` / `true`). A real parity gap in a core operator.

## Investigation

`emitOptionalMember` (`emit_exprs_member.go`) allocated a slot of the bare
property type, stored `zeroRef(resultTy)` on the null branch and the property on
the non-null branch, and returned `Value{Ty: resultTy}` — no undefined anywhere.
The `inferExprType` `MemberExpression` case likewise returned the bare property
type for an `Optional` read. The absent representation already existed (the
`{ i1, T }` optional for scalars, the flagged null pointer for pointers,
TDD-00187), and `ADR-00833` had just made `=== undefined` / `=== null`
distinguish the kind — so the value only needed to carry `IsUndefined`.

## Decision

- `emitOptionalMember`: the result type is `undefinedableElem(resultTy)`. On the
  null branch it stores the absent value — a `{ present=false }` optional for a
  scalar prop, the null pointer for a pointer prop, the zero-shaped `{null,0}`
  for an array prop (no spare absent state, ADR-00246). On the non-null branch a
  scalar prop is wrapped `{ present=true, value }`. It returns `T | undefined`
  for scalar/pointer props, the bare type for array/tuple/dynamic (where
  `undefinedableElem` is a no-op).
- `inferExprType`'s `MemberExpression` case mirrors it: for an `Optional` read
  off a pointer (non-array) object, wrap the non-optional inner type with
  `undefinedableElem`.
- Consumer policy is TDD-00187's strict/`-compat=js` split — a bare-`T` use of
  `o?.x` narrows / `?? d` / `!` in strict, auto-widens under `-compat=js`.

## Implementation notes

`emit_exprs_member.go` (`emitOptionalMember` null/non-null branches + return);
`emit_exprs_types.go` (`MemberExpression` optional wrap). An array receiver still
falls back to plain access (an array is never a null pointer, ADR-00539).

## Side effects discovered

`TestE2EClassAccessorOptionalChaining` asserted the old `maybe?.area === 0` for a
null receiver; corrected to `undefined`. Broad-suite blast radius was a single
test — optional chaining is used precisely where a value may be absent, so its
consumers already handle the nullish result.

## Verification

macOS (Apple Silicon M4): `o?.name` on a null object → `undefined`,
`=== undefined` true; a `Circle | null` getter `maybe?.area` → `undefined` on
null, the value when present. Updated `TestE2EClassAccessorOptionalChaining` +
the exprs/objects/classes/nullable/optional suites green; `make examples` clean.
