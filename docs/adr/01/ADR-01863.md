# ADR-01863: A conditional between object literals, and a member two shapes declare differently

- **Relations**: `Implements TDD-00230` (P3.3: found while answering the shadow report's ConditionalExpression bucket)
- **Date**: 2026-10-21

## Context

- tsc types a conditional with subtype reduction (`checkConditionalExpression`), so `options !== undefined ? options : {}` (`node:cluster`'s Worker) is the options type: the empty literal is a subtype of a type whose properties are all optional. And it normalizes object literals in a union: `c ? { a: 1 } : {}` is `{ a: number } | { a?: undefined }`, so `.a` reads on either. The checker gave `{} | { … }` and `{ a: number } | {}`, which the oracle could not map, and a read of a property one branch lacks failed.
- Codegen built `c ? { a: 1 } : { b: "x" }` as the first branch's layout, so `.b` was "object has no field 'b'".
- A read through a union of object shapes that declare one member with different kinds (`{ a: number; b?: undefined } | { b: string; a?: undefined }`) took the first shape's member type when the two shared an IR, so `y.b` read `undefined` from an object holding `"q"`.

## Decision

- The checker drops an object-literal branch the other branch's type covers (each of its properties the other's, of an assignable type, every other property optional), and otherwise gives each of two object-literal branches the other's missing properties as optional `undefined`.
- A union of plain object shapes maps to the box an annotation of it gives, and `emitConditional` builds a conditional between object literals of different layouts as that box.
- `unionCommonMember` compares the members' representations, not only their IR: different kinds read as the boxed value.

## Consequences

- `TestConditionalObjectLiteralBranches` holds tsc 5.6's declaration types; `TestE2EConditionalObjectLiteralUnion` matches Node, the annotated union's reads included.
- Verified on Apple Silicon.
