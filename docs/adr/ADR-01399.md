# ADR-01399: Dead connection-timeout IR deleted; write parks on any fd

- **Relations**: Implements TDD-00244; Extends ADR-01397
- **Date**: 2026-10-05

## Context

[TDD-00244](../tdd/TDD-00244.md) Stage 5 moves the HTTP server's runtime off
the select bridge, and its IR text into C. Two pieces of that IR turned out
to be dead code or unsafe:

- **The connection-timeout path** ([TDD-00217](../tdd/TDD-00217.md)):
  - a per-dispatcher arming of `headersTimeout`/`requestTimeout`/
    `keepAliveTimeout`;
  - a `[1024 x i64]` deadline table indexed by fd;
  - the loop's sweep and deadline fold.

  The options that enable it (`curServer*TimeoutMs`) are never set, and
  nothing sets the `__kml_http_any_timeout` gate. `createServer` and its
  timeouts are `lib/node/internal_http.ts`'s, so the path never ran, and
  `TestE2EHTTPCreateServerConnectionTimeouts` passes without it.
- **The write-park bitset**, which marks a connection fiber waiting on a
  full socket. It was a fixed `[128 x i8]`. The IR set the bit with no
  bounds check, so a back-pressured connection on descriptor 1024 or above
  wrote past the array.

## Decision

- The timeout path is deleted: the arming in `emit_http.go`, the four
  helpers, the deadline table and gate, `append_conn`'s clearing call, and
  the loop's sweep and fold.
- The write park is a growable set in `loop.c`
  (`__kml_conn_park_write(fd, on)`), for any descriptor number. The two
  parking sites in `runtime_http_reswrite.go` call it instead of computing
  bits.
- The IR-text ratchet for `runtime_http.go` drops from 34 to 30.

## Verification

- Mac (M4): the connection-timeout, close and keep-alive tests; the
  backpressure, highWaterMark and streaming tests; codegen unit tests.
- Linux x86-64 (Ubuntu 24.04 container): test-par passes (14 shards,
  3922 tests); examples 393/393; Test262 strict 8498 and js 10506
  (unchanged), no invalid IR.
