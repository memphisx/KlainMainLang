# TDD-00189: Go-fidelity `klain:` modules for self-hosting (`klain:embed` + the Go-stdlib gap set)

- **Status**: Not Started
- **Date**: 2026-09-09

## Context

The self-hosting plan ([TDD-00124](TDD-00124.md)) rewrites this compiler in its
own TypeScript dialect. The compiler is a Go program, and a mechanical port is
only mechanical where the Go stdlib surface it leans on has a faithful
equivalent on this side. Most of it does — `os`/`os/exec`/`path/filepath`
map onto the already-faithful `os`/`child_process`/`path`/`fs` modules — but a
residue does not, and that residue is exactly what this TDD scopes: bespoke
Go-shaped functionality, exposed under the `klain:` namespace per the
namespace rule ([TDD-00131](TDD-00131.md): non-Node surface never squats on a
Node module name).

The forcing example is Go's `embed` (`//go:embed`): compile-time file
embedding is a *compiler feature*, not an API — no Node module provides it
(Node 21+ SEA blobs are a clumsy single-blob build-tool flow), and no FFI call
can ever provide it, because the work happens at build time. This compiler
already embeds runtime C sources and status templates via `embed` itself; a
self-hosted compiler needs the same capability from inside the language.

Survey of the Go packages this compiler's own source actually imports, ranked
by (gap size × self-hosting necessity):

| Go package / feature | Node-side equivalent | Gap | Disposition |
|---|---|---|---|
| `embed` (`//go:embed`) | none | compile-time embedding is a language feature | **`klain:embed`** — the core of this TDD |
| `flag` | `util.parseArgs` (partial) | no Go single-dash `-name=value` style, typed defaults, auto-usage — the `klainmain` CLI *is* Go-flag-shaped (`-mm=gc`, `-optimize`) | **`klain:flag`** — small faithful clone, keeps the CLI byte-compatible |
| `fmt` verbs (`%v` `%+v` `%q` `%T` width/precision) | `util.format` (much weaker) | error messages + IR emission are Printf-heavy; hand-porting every format string is error-prone | **`klain:fmt`** — `sprintf` with the Go verb set (numerics can lower to C `snprintf`) |
| `unicode/utf8` byte-oriented decoding | JS strings are UTF-16-unit-indexed | Go indexes **bytes**; porting the lexer changes all offset math unless byte-fidelity is kept | **`klain:utf8`** (conditional) — `decodeRune(buf, i)`/`runeLen` over `Uint8Array`, *if* byte-identical positions are wanted for differential testing |
| `strconv.Quote`/`Unquote` | none | Go string-literal escaping used in codegen/diagnostics | small — fold into `klain:fmt` (`%q`) or a TS lib |
| `sync` + goroutines | none (JS threading model) | already covered: `klain:sync` ships ([TDD-00133](TDD-00133.md)/[TDD-00143](TDD-00143.md)) | audit API completeness against the compiler's actual uses, no new module |
| `text/template` | none | used for generated docs | port call sites to template literals — no module; revisit only if `.tmpl` assets must survive |
| `regexp` (RE2 semantics) | JS `RegExp` (superset syntax, different engine) | low practical risk — the compiler's patterns are simple | port patterns; a RE2-via-FFI wrapper only if fidelity paranoia proves justified |
| `strconv.ParseFloat`/`FormatFloat` shortest-repr | `Number()` / `String(num)` | none — JS `String(num)` gives the same shortest-round-trip guarantee | no work |
| `bufio`, `strings.Builder`, `errors`, `os.Getenv`/`runtime.GOOS` | whole-file reads, string ops, exceptions, `process`/`os` | idiom ports, not API gaps | no work |
| `exec.LookPath` | none in stdlib | trivial | via `node:ffi` (`access(2)` loop) or a TS helper — no module |

## Design

### `klain:embed` — compile-time embedding (the load-bearing piece)

`import { embedFile, embedDir } from 'klain:embed'` — calls are **compiler
intrinsics**, constant-folded at build time, mirroring how `//go:embed` is a
directive rather than a runtime call:

- `embedFile(path)` → `string`; `embedFileBytes(path)` → `Uint8Array`. The
  path must be a compile-time string literal, resolved **relative to the
  importing source file** (Go's rule), read at compile time, and baked into
  the binary as a constant global. Emitting the bytes reuses the asset-global
  machinery `klain:assets`' `embedDir` ([TDD-00142](TDD-00142.md) Stage 7)
  already built — that module is webview-flavoured (an asset *map* for HTTP
  serving); this one is the general single-value form.
- `embedDir(path)` → a read-only `Map<string, Uint8Array>` keyed by relative
  path (the `embed.FS` analogue), recursively walked at compile time — the
  existing `klain:assets` walker relocated behind a Go-shaped API. Whether
  `klain:assets` then becomes a thin wrapper over this (one embedding engine,
  two surfaces) is decided at implementation; the wrapper direction is
  preferred so there is exactly one path-resolution/walk/limit rule.
- Guard rails as compiler errors, matching Go: no `..` escaping above the
  importing file's module root, no absolute paths, missing file = compile
  error (never a runtime one).

### `klain:flag`

Faithful subset of Go's `flag`: `flag.string/bool/int/float(name, default,
usage)` returning a value handle read after `flag.parse()`, plus `flag.args()`,
`flag.usage()`, `-h`/`--help` auto-usage, `-name=value` and `-name value`
forms, `--` terminator. Deliberately Go's semantics, not `util.parseArgs`' —
that is why it lives under `klain:`. (Go's pointer-returning API shape can't
port literally; the handle carries `.value` — the one deliberate reshaping,
noted in the module docs.)

### `klain:fmt`

`sprintf(format, ...args)`/`printf`/`errorf` supporting the verb set the
compiler actually uses (audit first; expected: `%s %d %q %v %t %x %c %f %g`
with width/precision, `%%`). Numeric verbs lower to C `snprintf` through the
existing libc-decl machinery; `%v`/`%q`/`%t` are native. Explicitly **not** a
general reimplementation of Go `fmt` — the acceptance test is "every format
string in this compiler's own source renders byte-identically."

### `klain:utf8` (conditional)

Only if the self-hosting differential harness (Go compiler vs ported compiler,
byte-identical output — TDD-00124's B==C criterion) demands byte-oriented
source positions: `decodeRune(buf: Uint8Array, i: number)` → `{rune, size}`,
`runeLen(rune)`, `encodeRune`. Otherwise the ported lexer goes UTF-16-native
and this module is dropped — decide via a spike port of the lexer before
building anything.

### Staging

- **Stage 1 — `klain:embed`** (`embedFile`/`embedFileBytes`/`embedDir`,
  the guard rails, `klain:assets` rebased or not). Standalone value now
  (config/templates/SQL baked into any program), self-hosting value later.
- **Stage 2 — `klain:flag`.** Small, independently shippable.
- **Stage 3 — `klain:fmt`.** Preceded by the verb audit of this repo.
- **Stage 4 — lexer spike port** → decide `klain:utf8` and close the
  `klain:sync` completeness audit against the compiler's real usage.

Ordering rationale: 1 is the only piece nothing else can substitute for; 2–3
are cheap accelerants for the mechanical port; 4 is a decision point, not a
committed build.

## Open questions

- **`klain:assets` relationship**: wrapper-over-`klain:embed` (preferred, one
  engine) vs two parallel walkers. Wrapper needs `embedDir`'s map to carry
  enough (path, bytes, maybe content-type sniffing stays on the assets side).
- **Embed size limits**: `klain:assets` has limits today; inherit them, or
  make the general module unlimited-with-warning? Go has no limit.
- **`klain:fmt` verb scope**: freeze on the audited in-repo set, or take the
  full Go verb grammar? The acceptance test says audited set; the module doc
  must then state the subset honestly.
- **`flag.Var`-style custom values**: skip (the compiler doesn't use them) or
  reserve API space?
- **Where the port's `(T, error)` returns land** ([TDD-00124](TDD-00124.md)'s
  idiom question) is out of scope here — exceptions vs result objects changes
  no module in this TDD.
