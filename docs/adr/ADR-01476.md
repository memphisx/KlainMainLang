# ADR-01476: One runtime object per C file, whatever the program uses

- **Relations**: Extends ADR-01471; Implements TDD-00238
- **Date**: 2026-10-09

## Context

TDD-00238's object cache compiles each embedded C runtime file once and
links the object into every later program. On the test boxes the cache
held 127 objects for `fetch`, 55 for `shape`, 37 for `threadpool`, 26 for
`process`: each program compiled the file with its own set of `-D`
section switches (`KML_FETCH_GROUP`, `KML_SHAPE_SPREAD`,
`KML_PROC_SIGNALS`, …), one per feature it used, and every combination is
a separate cache entry. So most programs still compiled the runtime
themselves. The Node and WPT suite runners did not use the cache at all:
they compiled every runtime file from source for every test.

## Investigation

- A front-end-only pass over the Node suite (each program's IR split into
  library units, without clang) found at most 3 variants of any builtin
  library unit: a program that uses BigInt anywhere gets a BigInt check
  in `any` arithmetic (`mayHoldBigInt`, codegen/llvm/emit_anyops.go), and a
  program with Workers makes module globals `thread_local`. The library
  units were not the duplicated work; the C runtime objects were.
- The switches exist because each section calls runtime pieces that only
  the matching `ensure*()` brings into the program; compiled in without
  them, the link fails on undefined symbols.
- Linked with dead-code removal (`-ffunction-sections -fdata-sections` and
  `--gc-sections` on Linux, `-dead_strip` on macOS), an object whose unused
  functions reference undefined symbols links on both: the functions go,
  and their references with them (checked on the Mac and on Linux).
- macOS rejects an undefined weak reference, but accepts a weak
  definition, which a strong one elsewhere replaces.
- A link that exports the executable's symbols keeps every exported
  function, unreachable or not: GTK's pkg-config flags carry
  `-Wl,--export-dynamic`, so every webview program on Linux failed on the
  references of runtime functions it never calls. An isolated island is a
  shared library loaded with `RTLD_NOW`, where nothing may stay unresolved.
- Switches that change the inside of a shared function cannot simply be
  dropped: fetch.c's `park` (`KML_FETCH_TASKS`, `KML_FETCH_GC_RESTORE`),
  process.c's exit (`KML_PROC_WORKERS`), fnmeta.c's property-bag inspector
  (`KML_FN_DYNJSON`), and fetch.c's body-stream hooks, which a live drain
  path calls and which the generated module defined as no-op IR text when
  no body stream existed.

## Decision

The fetch, shape, process, cryptorand, native and threadpool-fs C files
are compiled the same way for every program, with every section, and
`DeadStripFlags` (codegen/llvm/cobj_cache.go) adds the section, hidden
visibility and dead-strip flags to their CFlags, so every driver (CLI,
conformance runners, test helpers) compiles and links them that way.
Hidden symbols are never exported, so the link drops them whatever else
it exports; the program's own calls into them link as before. An
isolated island's runtime is compiled hidden and dead-stripped too.

A switch inside a shared function becomes a weak definition that does
what the switched-off branch did, which the real runtime replaces when the
program links it: `__kml_current_task` (null) and `__kml_task_gc_restore`
(nothing) in fetch.c; `__kml_rs_desired/enqueue/close/error` in
fetch_stream.c (never reached without a body stream); fetch.c's
`__kml_fetch_bodyprom_on_done` (nothing); process.c's `__kml_thread_exit`
(`exit`); fnmeta.c's `__kml_dynobj_inspect_at` (the empty string). The
body-stream hooks are now always fetch.c's own; the generated module's
no-op IR definitions of them and of the body-promise hook are gone.

A program whose runtime must stay visible (ffi `dlopen(null)`, the
`-dynamic-import=lazy` executable, whose libraries bind to it) keeps
default visibility, and its unreachable references stay unresolved
(`UnreachableRefFlags`: `-undefined dynamic_lookup`,
`--unresolved-symbols=ignore-in-object-files`).

The Node and WPT runners compile the runtime files through the cache, as
the Test262 runner does, and the Node runner links each builtin library
module through it too (`llvm.LibObjects`, as the CLI). The runners' cache
lives outside the workdir (`objCacheDir`).

Kept: the zlib and SQLite parts of the thread pool (their headers would
otherwise be needed by every program), the GC-mode switches (a different
program, not a feature selection), and dynjson's boxed typed-array views
(its section references constants only the generated module defines).

## Side effects discovered

- The BigInt check in `any` arithmetic depends on the whole program, so a
  library unit differs between programs with and without BigInt (BACKLOG
  156).
- The conformance reaper (tools/conformance/reaper.go) killed processes
  that were not escaped test children, because it takes any process whose
  command line names the workdir and that is not a registered live child:
  - the runner's ancestors: `go run` and the shell that launched it with
    an absolute `-workdir`, which ended the whole run. It now spares the
    runner's ancestor chain.
  - the runners' own clang commands, run without registering (`Run`
    instead of `runTracked`). Under load they were killed mid-compile and
    counted as clang failures. Both runners now register them.
  With compiles no longer killed, the memory ceiling (`-mem-cap-mb`) fired
  on the compilers' own memory, and then on single test programs growing
  past 6 GB, aborting the whole run. The ceiling now counts only test
  programs, and when one alone puts the total over it, that one is killed
  (its test fails) and the run goes on; the abort lists the processes.

## Verification

- On the Mac: the fetch, XHR, Response/Headers, abort-signal, ReadableStream,
  shape, dynamic-import (bundled, lazy, isolated) and FFI E2E tests; the
  conformance runner's unit tests (reaper included). On the Linux box: the
  webview, dynamic-import and Worker GC tests that failed before visibility
  was hidden (GTK's --export-dynamic).
- One cached object per runtime file: the Node-suite runner went from
  roughly 47 minutes per lane, with 38 (strict) and 205 (js) clang
  timeouts, to about 26 (strict) and 43 (js) minutes, with 19 timeouts in
  the strict lane and none in the js lane, at 8 workers.
- Gates on the Linux boxes for ADR-01476 and ADR-01477 together: test-par
  green; examples 401/401; Test262 strict 8487 (one fewer: tsc 5.6 also
  rejects `Object.fromEntries(['ab'])`, TS2769), js 11021, no invalid IR;
  TS suite strict 7005 (from 7002), js 6812; Node suite strict 301, js 587
  (from 297/474), no invalid IR; WPT strict 403/664, js 3116/5194 (from
  401/662, 3115/5192).
