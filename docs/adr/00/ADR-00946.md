# ADR-00946: Self-referential class ARRAY field element resolution

- **Relations**: `Extends ADR-00064` (canonicalizeClassTy / self-referential class fields)
- **Date**: 2026-09-15

## Context

A self-referential class array field — the tree shape
`class Node { children: Node[] }` — failed to compile when an indexed element
was drilled into: `root.children[0].val` reported `no field 'val'`, even though
`root.children[0]` is a valid `Node` at runtime. A distinct-class array field
worked. Confirmed pre-existing on committed HEAD; one of the five
array-in-container bugs.

## Investigation

ADR-00064 already fixed the direct case (`nextNode: Node | null`) via
`canonicalizeClassTy` (`emit_classes.go`): a class field's `Type` is a stored
snapshot that, for a self-reference, captured the empty placeholder
`registerClasses` seeds in Pass 0, so drilling further saw no fields. That
helper re-resolves a CLASS-typed field through the live registry.

For an ARRAY field the field type is `Node[]`, and the stale placeholder lives
in `ElemType` — `canonicalizeClassTy` returned the array type unchanged (the
`ty.IsClass` guard is false for an array), so indexing yielded the empty-Node
snapshot and `.val` was not found.

## Decision

`canonicalizeClassTy` now recurses into a class array element: when
`ty.IsArray && ty.ElemType.IsClass`, it re-resolves the element through itself
and returns the array type with the canonical element. Every chaining call site
(emitMember, emitOptionalMember, inferExprType's field-read case) already routes
field types through `canonicalizeClassTy`, so no other change is needed;
indexing the field now yields the fully-resolved element class.

## Side effects discovered

Self-referential **interface** (structural, not class) recursion is a separate,
still-open cluster — this fix does not touch it: a self-referential interface
array field with a non-empty element literal
(`const root: N = { children: [c], val: 1 }`) is rejected as a heterogeneous
array, and even a non-array self-referential interface field
(`interface N { next: N | null }`) produces an invalid-IR clang error. Interfaces
have no class registry to canonicalize through, so the ADR-00064 mechanism does
not apply. Tracked in docs/BACKLOG.md.

## Verification

- `TestE2ESelfReferentialClassArrayField` (tests/classes_test.go): a two-level
  tree, drilling `root.children[0].val` and
  `root.children[0].children[0].val`.
- Regression: `go test -run 'TestE2E(SelfReferentialClass|Class)'` green on
  macOS arm64 (Apple Silicon M4).
