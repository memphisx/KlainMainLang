# ADR-01196: The WHATWG streams are declared; `for…of` checks its iterable

- **Relations**: `Implements TDD-00230`, `Extends ADR-01134`
- **Date**: 2026-09-28

## Context

`for await (const c of res.body)` compiled, although `Body.body` is
`ReadableStream<Uint8Array> | null` and tsc reports TS18047 ("'res.body' is
possibly 'null'"). Two gaps: the checker did not check a `for…of`
iterable at all, and `ReadableStream` was not declared, so the member's
type went unanswered and nothing about it was decided.

## Investigation

tsc's `checkForOfStatement` runs the iterable through
`checkNonNullExpression`. With that added, `for (const v of x)` on
`x: number[] | null` was reported, but `res.body` still was not: the
library named `ReadableStream` in `Body` without declaring it. @types/node
declares the web streams in `stream/web.d.ts` (globals through
`web-globals/streams.d.ts`) in lib.dom.d.ts's shapes, plus
`ReadableStream.from` and `values()`.

A sweep of every example and app with the declarations in place found six
real tsc errors (five `res.body` iterations, and `nis[name]` of
`os.networkInterfaces()` in `examples/os/os_info.ts`, confirmed against
tsc 7.0.2).

## Decision

- `lib/node.d.ts` declares the streams as @types/node has them:
  `ReadableStream` (with `from`, `values`, `[Symbol.asyncIterator]`), its
  default reader and controller, `WritableStream` with its writer and
  controller, `TransformStream` and its controller, the queuing strategies,
  the underlying source/sink/transformer shapes, `CompressionStream` and
  `DecompressionStream`. Byte streams (BYOB readers,
  `ReadableByteStreamController`) are not implemented and not declared:
  `getReader()` has only its default overload (allowlisted in
  `tools/libconform/allow.txt`).
- The checker's `ForOfStatement` case checks the iterable non-null.
- A `for await` over an array binds the awaited element type (tsc's
  `getIteratedTypeOrElementType` for async iteration).
- The examples and tests that iterated `res.body` assert it non-null.

## Implementation notes

`checker/check.go` (the `ForOfStatement` case), `checker/symbols.go` (the
loop variable's type), `lib/node.d.ts`.

## Side effects discovered

- `for (const x of xs!)` and `[...xs!]` over an absent array iterated
  nothing: the assertion dropped the nullable type, and with it the "xs is
  not iterable" guard, though `!` is erased at run time. `emitForOf` and
  `resolveArrayForHOF` now walk the asserted array itself. Found by the
  tests that iterated possibly-undefined arrays, which assert non-null now
  that the checker rejects them as tsc does.

- `lib/conform/conform_test.go` keyed the allowlist by the whole line,
  reason included, so every allowlisted divergence failed the test; it now
  keys by the first field, as `tools/libconform` does.

## Verification

Mac (Apple Silicon): `tools/libconform` 0 divergences; `go test
./lib/... ./checker/...`; the example/app sweep reports no type error;
tsc 7.0.2 reports the same two diagnostics as the checker on the repro.
