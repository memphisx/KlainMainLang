# ADR-00501: net socket 'close' + 'connect'/'ready' listeners

- **Date**: 2026-08-29

## Context

A net socket accepted only `'data'`/`'end'` listeners (plus
net.connect's inline callback); the corpus's most-registered socket
events after those are `'close'` (47) and `'connect'` (41).

## Decision

The socket struct grows 48→64 bytes: slot 6 holds a `'close'` listener,
fired exactly once (cleared on fire) at either teardown site — the EOF
dispatch path (after `'end'`, Node's ordering, listener or not) or an
explicit `end()`/`destroy()` close. `.on('connect')`/`.on('ready')`
store into the same pending slot net.connect's own callback uses, so
the dispatch pass fires them after the socket variable is bound.
`'error'` stays a rejection — the runtime's failure paths throw rather
than emit, and storing a never-fired error listener would silently
mask that. No `hadError` argument on close (no error teardown to
distinguish).

## Verification

Mac. `tests/net_test.go` `TestE2ENetSocketCloseAndReadyEvents`
(ready → data → end → close ordering) passes; net + TLS batch green
(the TLS accept path shares the grown struct);
`examples/net/client_server.ts` extended and re-run.
