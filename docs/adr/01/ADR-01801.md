# ADR-01801: Reads off undefined receivers at run time; generator pattern defaults see top-level bindings

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- In `-compat=js`, a member read whose receiver codegen types as `undefined`, `null` or a void call's result (`var u = v(); u && u.next`) was a compile error ("field access on non-object"). JavaScript throws a TypeError only when the read runs, and here it never does.
- A generator's destructured parameters are moved into its body before top-level bindings are promoted to globals (`desugarGeneratorPatternParams`). The promotion scan (`namesReadInFunctions`) then missed names read only by those patterns' defaults, so `function* a([y = iter])` failed with "undefined variable".

## Decision

- In the js lane, a read off such a receiver boxes it and takes the dynamic get, which throws Node's "Cannot read properties of undefined (reading 'x')" when it runs.
- The promotion scan also walks every generator's recorded pattern statements.

## Consequences

- `TestE2EJSFileUndefinedReceiverAndGeneratorPatternGlobals` compares both against Node.
- The strict lane keeps reporting the read, as tsc does.
