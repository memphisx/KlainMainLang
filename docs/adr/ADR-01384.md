# ADR-01384: CI lanes green again — library drift, nondeterministic IR, a -mm=gc leak, per-platform job layout

- **Relations**: Extends ADR-01326, ADR-01074; refines TDD-00179
- **Date**: 2026-10-04

## Context

Every Release run since the compiler restructure failed on every platform.
The POSIX lanes ran all 393 examples green, then failed on `make drift`,
which ran in the same job. Under per-platform `fail-fast`, that failure
cancelled every suite shard, so the shards never reported a result. On
macos-arm64, `TestE2ETaskStackReclaimedGC` failed with `rss 89 MB`. Windows
fails for its own reasons, which are left to the Windows machine.

The box gates never ran `make drift`, which is why local runs looked green.

## Investigation

- `tools/libdrift -l` over every example (DeskMini): 13 library functions
  differed between programs. Every difference was a call to
  `@__kml_dynget.<hash>`, the per-property read helper. Its body dispatches
  over the program's own classes, and it was named by a hash of that body
  (`contentNamedHelper`, `codegen/llvm/contentsym.go`). So library code that
  called it was spelled differently in every program.
- That left 6 functions, all calling `ArrayBuffer.isView` on an `any`. The
  inline check adds an `instanceof DataView` only when the program has the
  DataView global class (`emitArrayBufferIsView`,
  `codegen/llvm/emit_dynamic.go`).
- The second stage of `make drift` (`-repeat 2`) had never run, because the
  first stage always failed. It listed many examples whose IR differed
  between two compiles. The diff was one constant in the error
  `constructor` read (`emitDynAnyMemberGetInline`): a map keyed by demangled
  class name, filled by ranging over `e.classes`. Two modules' error classes
  with the same short name raced for the slot.
- The GC leak: 5,000 sequential awaits reached 88 MB RSS under `-mm=gc` at
  HEAD, against 13 MB at the previous commit and 8 MB in manual mode. The
  Boehm heap stayed near 2 MB (`GC_PRINT_STATS`). Counting
  `__kml_task_stack_alloc`/`_free` showed 5,001 of each, so stacks were
  released. The cause was `jmpstacksrc/jmpstack.c`, which allocated chunks
  with `aligned_alloc`. The GC shim replaces only
  `malloc`/`calloc`/`realloc`/`free`, so each chunk came from the system
  allocator. The shim's `free` then ignored it as a foreign pointer, leaking
  32 KiB per task.

## Decision

- `dynGetHelper` names the helper by its property
  (`contentSymbol("@__kml_dynget.", propName)`) and defines it `hidden`. The
  `__` prefix makes the program's unit its owner (`libOwner`), so library
  units name the same symbol in every program.
- The `any` arm of `ArrayBuffer.isView` becomes a call to
  `@__kml_isview.<box IR>`. This is a program-owned helper with a fixed
  name, whose body still includes the DataView check when the program has
  one.
- The error `constructor` dispatch emits one check per type id, sorted by
  (name, id). Two same-named classes both get their check, and the IR is
  identical on every compile.
- `jmpstack.c` allocates chunks with `malloc` on POSIX. It is 16-aligned on
  every 64-bit target, and it is the shim's allocator under `-mm=gc`. The
  Windows branch is unchanged.
- CI layout:
  - `release.yml` has one job per platform, not a matrix.
  - `test-platform.yml` builds the compiler once, then runs two fail-fast
    matrices on that binary: unit plus six suite shards, and four example
    shards plus `drift`.
  - A gate job publishes one marker per platform.
  - The toolchain setup is the composite action `.github/actions/toolchain`.
  - `tools/runexamples` gains `-shard`/`-shards`; `make examples` passes
    `SHARD`/`SHARDS` through.

## Implementation notes

- `writeHelper` (`contentsym.go`) is the one place a generated helper's
  definition is written. Both content-named and key-named helpers use it.
- The two new key-named helpers bypass `contentNamedHelper`'s placeholder
  path. Their name is known before their body is emitted, so recursion
  needs no rename.

## Side effects discovered

- `TestE2EAsyncArrowAwaitFetchIsACoroutine` saw 6 interval ticks in 600 ms
  (wants ≥ 8) on the macos-arm64 runner. It passes on the Mac. Not changed
  here; the next CI run shows whether it recurs.

## Verification

- `make drift` on the DeskMini (Linux x64 box): 0 of 9,666 library
  functions differ, and every example compiles to the same IR twice.
- `make examples` on the DeskMini: 393 passed, 0 failed.
- `make test-par` on the Node304 (Linux x64 box): all unit packages and 12
  of 12 shards (3,915 tests) pass.
- On the Mac (arm64): `TestE2ETaskStackReclaimed*`, the GC thread-local
  roots test and the try/catch, generator and AsyncLocalStorage tests pass.
  The probe program reads 13 MB under `-mm=gc`.
- `ArrayBuffer.isView` over a typed array, an array, a DataView, an object,
  a Buffer and a number matches Node.
- `make conformance` on the DeskMini, both lanes: no invalid-IR files
  (strict was 39, js 70). In-scope passes went from 8,142 to 8,267 (strict)
  and from 9,762 to 10,176 (js).
- `actionlint` is clean on both workflows.
