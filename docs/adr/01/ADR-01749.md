# ADR-01749: An object literal's method parameters are any in the js lane

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-19

## Context

In the js lane, the checker typed an unannotated parameter from its call sites, and gave `any` where the callers are out of sight (a class method, a returned function). It missed an object literal's method (`{ f: function (a) {} }`, `{ f(a) {} }`). That parameter stayed unanswered, which made the method and the whole literal unanswered. The unanswered sentinel then leaked into inferred type arguments: `p.then(_ => { throw e }, e => assert.sameValue(…))` checked as `Promise<unanswered>`, so the next `.then` in the chain had no answer. Test262's harness `assert` object is such a literal, so the gap reached almost every async test.

## Decision

- An object literal's method counts as a method in `isMethod`: its receiver decides the call, so an unannotated parameter is `any`, as checkJs gives.
- A method called on an object held as a box is a dynamic call, so the front end answers its result as a box, whatever the checker knows of the method. A function literal whose returns are such boxes returns a box, both as a value and through an unannotated binding. This applies even where the checker's result is `void`.

## Consequences

- `{ f: function (a) {} }` checks as `{ f: (a: any) => void; }` in the js lane. A promise chain through such a method has an answer at every link.
