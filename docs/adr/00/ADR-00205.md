# ADR-00205: One denominator for Strict Coverage — always the page's total feature count

- **Relations**: `Extends ADR-00166`
- **Date**: 2026-08-17

## Context

`docs/status/` tracks two per-area numbers: **Coverage** (a feature works for its
core case, with real caveats disclosed) and **Strict Coverage** (a feature works
with zero known caveats/bugs of any severity — a caveat always excludes a row,
even one that stays ✅ in the Coverage column). The Strict figures were produced
by the 2026-08-11 audit ([ADR-00166](ADR-00166.md)).

Reviewing the `docs/status/README.md` summary surfaced that the Strict column
was not computed against a single denominator, so it was not comparable across
rows and sometimes looked nonsensical against the row's own Coverage:

- Most pages divided the caveat-free count by the page's **total** feature count
  — the same base as Coverage, so Strict ≤ Coverage and the two line up
  (`STRING-METHODS` 15/33, `ARRAY-METHODS` 25/40, `NUMBER-MATH` 22/35,
  `OBJECT-COLLECTIONS` 12/27, `LANGUAGE-CONSTRUCTS` 35/65, `TYPE-SYSTEM` 13/20).
- Four pages divided by the **implemented-only** count instead (Coverage's
  numerator), answering a different question ("of what's built, how much is
  pristine") that isn't comparable to Coverage's X/total: `JSON` 7/9, `CONSOLE`
  5/11, `GLOBAL-FUNCTIONS` 3/14, `MODULES` 8/14.
- `REGEXP` was a plain off-by-one — 2/13 on a 14-row page (matching neither
  convention).

## Decision

Strict Coverage's denominator is **always the page's total feature count** — the
identical base the Coverage column uses. This is the only convention under which
Strict and Coverage are directly comparable (Strict is a strict subset of the
✅ rows, so it can never exceed Coverage). The numerator is unchanged: the count
of repro-verified, caveat-free rows. A caveat-free row is necessarily
implemented, so switching the denominator from the implemented-count to the
total never changes the numerator — only the ratio.

Renormalized figures (numerator kept, denominator → total), across all three
status sections:

| Page | Was | Now |
|---|---|---|
| `JSON` | 7/9, ~78% | 7/11, ~64% |
| `CONSOLE` | 5/11, ~45% | 5/12, ~42% |
| `GLOBAL-FUNCTIONS` | 3/14, ~21% | 3/17, ~18% |
| `MODULES` | 8/14, ~57% | 8/15, ~53% |
| `REGEXP` | 2/13, ~15% | 2/14, ~14% (off-by-one, not implemented-count) |
| `TIMERS` | 1/3, ~33% | 1/4, 25% |
| `URL` | 0/2, 0% | 0/3, 0% |
| `BINARY-DATA-TYPED-ARRAYS` | 1/2, 50% | 1/17, ~6% |
| `FILE-SYSTEM` | 7/11, ~64% | 7/13, ~54% |
| `PROCESS-CLI` | 10/13, ~77% | 10/23, ~43% |
| `NODE-CORE-MODULES` | 1/2, 50% | 1/11, ~9% |
| `MEMORY-MANAGEMENT` | 0/2, 0% | 0/3, 0% (3 modes incl. design-only `auto`) |

The remaining pages were already on the total-feature denominator and are
unchanged (`STRING-METHODS`, `ARRAY-METHODS`, `NUMBER-MATH`, `OBJECT-COLLECTIONS`,
`LANGUAGE-CONSTRUCTS`, `TYPE-SYSTEM`, `WEB-CRYPTO`, `PERFORMANCE-TIMING`,
`NETWORKING`, `ENCODING-TEXT`, `HTTP-SERVER`, `PATH`, `OS`, `EVENT-EMITTER`, and
the all-zero `STREAMS`/`EVENTS-CANCELLATION`/`CONCURRENCY-WORKERS`).

A `(page)` tag in the summary's Strict column marks a figure shared by several
categories that live on one status page (the six `LANGUAGE-CONSTRUCTS.md` rows
share 35/65; both `TYPE-SYSTEM.md` rows share 13/20) — previously applied to only
one of the two `TYPE-SYSTEM.md` rows, now to both.

## Implementation notes

- Page headlines updated: `JSON.md`, `CONSOLE.md`, `GLOBAL-FUNCTIONS.md`,
  `MODULES.md`, `REGEXP.md`, `TIMERS.md`, `URL.md`,
  `BINARY-DATA-TYPED-ARRAYS.md`, `FILE-SYSTEM.md`, `PROCESS-CLI.md`,
  `NODE-CORE-MODULES.md`, `MEMORY-MANAGEMENT.md`.
- `docs/status/README.md`: the matching summary rows across all three sections,
  the `(page)` tag on the Type-system-features row, and the Strict Coverage note
  now states the single-denominator convention so it can't silently drift again.
- Documentation-only change; no code or coverage claims touched — only the
  denominator each Strict ratio divides by.

## Verification

- Each renormalized denominator equals its page's Coverage denominator
  (`JSON` 11, `CONSOLE` 12, `GLOBAL-FUNCTIONS` 17, `MODULES` 15, `REGEXP` 14);
  every Strict numerator is ≤ that page's Coverage numerator.
- No feature row's ✅/❌ or Coverage figure changed.
