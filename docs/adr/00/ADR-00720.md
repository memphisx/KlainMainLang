# ADR-00720: Linux TUI build break after the Windows port, and the Pages workflow's path filter

- **Relations**: Extends [ADR-00719](ADR-00719.md) (Windows Stages 1–4)
- **Date**: 2026-09-06

## Context

The Windows port commit turned the Linux CI lane red: every `TestE2ETui*`
test failed at the clang step with

```
tui.c:507:14: error: call to undeclared function 'termcols'; ISO C99 and later do not support implicit function declarations
tui.c:507:33: error: call to undeclared function 'termrows'; ...
```

The same commit also touched `docs/status/` without triggering the
"Deploy website to GitHub Pages" workflow, although the website build reads
those files.

## Investigation

`codegen/llvm/tui.go` (`TuiSource`) gained an `#ifdef _WIN32` block that
defines console-API versions of `termcols`/`termrows`. The old POSIX
definitions (`ioctl(1, TIOCGWINSZ, ...)`) were deleted from their original
place below `paint_node` but never re-added to the `#else` branch, so on
Linux and macOS the two functions were called with no definition. The
Windows E2E run could not catch this: the TUI tests are console-only and
skip there, and the Windows branch does define both functions.

`.github/workflows/pages.yml` filters pushes to `website/**` and
`examples/**`. The website build (`npm run build`) also runs
`scripts/check-reference.mjs`, which reads `docs/status/*.md`, and
`scripts/gen-conformance.mjs`, which reads
`docs/testing/conformance-summary.json`. A commit that changes only those
inputs rebuilt nothing.

Also seen while reproducing under WSL2: `TestE2EHTTPListenManyRequestsDoesNotLeakStack`
takes about 50 ms per request there, on both the previous and the current
commit, because the response is two small `write()` calls on a socket
without `TCP_NODELAY` and WSL2's loopback applies delayed ACK. Not a
regression and not this ADR's fix; recorded under Side effects.

## Decision

Restore the POSIX `termcols`/`termrows` inside the `#else` branch of the
platform block in `TuiSource`, next to the `<sys/ioctl.h>` include they
need. Add `docs/status/**` and `docs/testing/conformance-summary.json` to
the Pages workflow's path filter.

## Implementation notes

- `codegen/llvm/tui.go`: two lines in the `#else` branch, byte-identical to
  the definitions the port removed.
- `.github/workflows/pages.yml`: two extra `paths` entries with a comment
  naming the scripts that read them.

## Side effects discovered

- HTTP server responses go out as header and body writes without
  `TCP_NODELAY`. Node's `http.Server` defaults `noDelay` to `true`, so the
  faithful behaviour is to set it on accepted sockets. This ADR only
  restores the build; the option is set in [ADR-00721](ADR-00721.md).
- `TestE2ETLSConnectVerifyFails` makes Go's test server log
  `TLS handshake error ... local error: tls: bad record MAC`. Reproduced
  identically on the previous commit, so it predates the port. The test
  passes (the client does refuse the certificate), but a clean rejection
  should surface on the server as a `bad certificate` alert, not as a
  record the server cannot decrypt. Worth a look at what the compiled
  client writes on the socket after `SSL_connect` fails. Deferred.

## Verification

- Linux (WSL2 Ubuntu 24.04, clang 18, Go 1.27): `go test -run TestE2ETui ./tests` passes; full `./tests` package, `make examples`, `make conformance` results recorded in the commit message.
- Windows 11: `go test -run TestE2ETui ./tests` still passes (tests skip on the console-only path, as before).
