# TDD-00232: `EventTarget` and the WebSocket client as Node's, in TypeScript

- **Status**: Implemented
- **Notes**: Stage 1 [ADR-01203](../adr/ADR-01203.md); Stage 2 [ADR-01208](../adr/ADR-01208.md), with `EventSource` moved too
- **Date**: 2026-09-28

## Context

[TDD-00230](TDD-00230.md) P3.1 declares each builtin for the checker in
TypeScript's and `@types/node`'s shapes. Declaring the global `WebSocket`
that way rejects the programs this compiler's client accepts, because the
client is not Node's (Node 22+ ships undici's WHATWG `WebSocket` as a
global):

- The connect and the opening handshake run synchronously in the
  constructor (`__kml_ws_client_open`), and `readyState` is `OPEN` when the
  constructor returns. Node's constructor returns `CONNECTING`; the
  connection opens on the event loop.
- A message event is a bespoke record: `ev.data` is always a string (a
  binary message's bytes read up to the first NUL), with `ev.isBinary` and
  `ev.dataBytes(): ArrayBuffer` beside it. Node's is a `MessageEvent` whose
  `data` is a string for a text message and, for a binary one, a `Blob` or
  an `ArrayBuffer` as `binaryType` (`"blob"` by default) says.
- No `binaryType`, `bufferedAmount`, `protocol`, `extensions`, protocol
  list in the constructor, `addEventListener`, `CloseEvent` (`code`,
  `reason`, `wasClean`) or `ErrorEvent`. A failed connect in Node fires an
  `ErrorEvent`, then a `CloseEvent` with code 1006.
- `.close()` does not wait for the peer's close frame.

The client is written in codegen: `emit_websocket_client.go` (460 lines)
and `runtime_websocket_client.go` (843), plus `WebSocketClientType` and
its `Is*` flag. Seven tests and two examples construct a client.

Since [TDD-00231](TDD-00231.md) stage 4, `net`, `tls` and klain:ws's
server (with its frame codec) are TypeScript modules compiled with the
program, over native socket and TLS primitives. Node's own client is
JavaScript over the same layers. The client moves the same way.

## Design

### A web global written in TypeScript

A builtin module so far is reached by an `import`. `WebSocket` is a
global: a program names it without importing anything. The resolver gains
**global modules**: `lib/node/` files marked `kml:global` whose exported
classes implement globals. When a file refers to one of those names (a
value or a type) without declaring it at its top level, the resolver adds
the module to the program. The names are **linked after checking**: the
checker keeps typing the global from its declaration in `lib/node.d.ts`
(TypeScript's library shape, which `tools/libconform` checks), and
`sema.Prepare` — which already runs after the checker and decides every
`new X` scope-aware — rewrites each free reference to the module's
exported class. This is TypeScript's own split between a library's
declarations and the runtime that implements them, and it lets the
implementation use simpler internal types than the declaration (a
non-generic `CustomEvent` holding `detail: any`, where the declaration is
`CustomEvent<T>`); codegen erases type arguments on a class that is not
generic.

### Stage 1: `Event`, `CustomEvent` and `EventTarget` in TypeScript

The client is an `EventTarget` and its events are `Event`s, but neither
can be subclassed today: `EventTarget` is a bare listener-map handle and
`Event` a fixed host layout (`emit_event.go`, `emit_eventtarget.go`), so
`class X extends EventTarget` is "extends unknown class" in any program.
Stage 1 is the first global module, `lib/node/event_target.ts`, following
Node's `lib/internal/event_target.js`: `Event` (`type`, `bubbles`,
`cancelable`, `composed`, `defaultPrevented`, `timeStamp`, `isTrusted`,
`target`/`currentTarget`, `eventPhase`, `preventDefault()`,
`stopPropagation()`, `stopImmediatePropagation()`, the phase constants),
`CustomEvent` (`detail`), and `EventTarget` (`addEventListener` with
`once`, `passive`, `signal` and a `handleEvent` object, duplicate
suppression, `removeEventListener`, `dispatchEvent`; a listener's throw is
reported as Node reports it, through `process.nextTick` to
`uncaughtException`). `AbortSignal` and `AbortController` follow as
subclasses; fetch's native reads of a signal (`__kml_signal_aborted`)
read the class's fields by name. The code-generated Event, CustomEvent,
EventTarget, AbortSignal and AbortController are deleted.

### Stage 2: the client

`lib/node/websocket.ts` (`kml:global`), following undici's
`lib/web/websocket`:

- `class WebSocket extends EventTarget` with `CONNECTING`/`OPEN`/
  `CLOSING`/`CLOSED` (static and instance), `url`, `readyState`,
  `protocol`, `extensions`, `bufferedAmount`, `binaryType`, the `on*`
  attributes, `send(data)` for a string, an `ArrayBuffer`, a view or a
  `Blob`, and `close(code?, reason?)` with the spec's validation
  (`InvalidAccessError` for a code other than 1000 or 3000–4999, a
  `SyntaxError` for a reason over 123 bytes).
- The constructor validates the URL (`ws:`, `wss:`, and `http:`/`https:`
  rewritten, as undici does; a fragment is a `SyntaxError`) and the
  protocol list, then starts the connect with `net.connect` or
  `tls.connect` and returns in `CONNECTING`.
- The opening handshake: a 16-byte random `Sec-WebSocket-Key`, the
  upgrade request, the `101` response parsed by the HTTP parser primitive
  the `http` module uses, `Sec-WebSocket-Accept` checked against
  SHA-1(key + GUID) in base64, the selected protocol checked against the
  offered list. A failure fails the connection: `error`, then `close` with
  1006.
- Frames: the codec klain:ws's server uses, moved to a shared internal
  module; the client masks every frame it sends (RFC 6455 §5.3) and rejects
  a masked frame from the server. Text frames are UTF-8 checked; a
  fragmented message is reassembled; ping gets a pong; the closing
  handshake echoes the peer's close frame and waits for the socket to end
  (`wasClean`).
- Events are dispatched as a task each (`setImmediate`-ordered, as undici
  queues them on the event loop), after the attribute handler and the
  listeners of `EventTarget`.
- A binary message's `data` is a `Blob` or an `ArrayBuffer` per
  `binaryType`; the event types are `MessageEvent<any>`.

### What is deleted

`emit_websocket_client.go`, `runtime_websocket_client.go`, the
`NewWebSocketExpression` AST node and its parse-time dispatch,
`WebSocketClientType`, `IsWebSocketClient` and every site that tests it,
and the `ev.isBinary`/`ev.dataBytes()` members of the client's message
event. Every test and example that uses the client is rewritten to Node's
API and checked against Node.
