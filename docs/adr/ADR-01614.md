# ADR-01614: Windows' own reactor goes: named pipes on libuv, a plain socket layer, the webview loop embedded

- **Relations**: Implements TDD-00252 (Stage 4), Extends ADR-01602, ADR-01609, ADR-01613
- **Date**: 2026-10-13

## Context

With the loop (ADR-01602) and children (ADR-01613) on libuv, the Windows shim
still carried its own event loop: `select()` over a completion port, AFD
polls, zero-byte overlapped reads, `AcceptEx`/`ConnectEx`, overlapped pipe
writes, pipe and console reader threads, a forwarder thread that woke libuv
for completions that arrived on the shim's port, wait-completion-packet
timers, and a `curl_multi_fdset` bridge. Only three users were left: the
named-pipe client and server (`net.connect(path)`, `server.listen(path)`,
ADR-01034/ADR-01609), the stream table's `tcp_shim_poll` for descriptors
libuv could not poll, and sockets whose `connect`/`accept` still went
through `ConnectEx`/`AcceptEx`. The Windows webview drove the loop from the
page: a bound `__kml_tick` the page called every 16 ms (ADR-01405).

## Investigation

- `net.connect(path)` and `server.listen(path)` on a pipe-namespace name are
  libuv's `uv_pipe_connect` / `uv_pipe_bind` + `uv_listen` in Node; the
  stream adapter of ADR-01613 already reads and writes a `uv_pipe_t`.
- After that, no stream-table descriptor on Windows is unpollable except a
  file, which the POSIX code treats as always ready.
- libuv polls a socket with `uv_poll_init_socket`, which needs nothing from
  the shim but non-blocking Winsock calls; `ConnectEx`'s completion and
  `AcceptEx`'s pre-accepted socket only existed to feed the shim's
  `select()`.
- Nothing calls `select()`, `curl_multi_fdset` or `pipe()` any more:
  `runtime_http.go` and `runtime_fetch.go` still declared the first two;
  `childprocsrc/spawnsync.c` (deleted by ADR-01613) was the last `pipe()`.
  `win32fswatch.c` was unreferenced since fs.watch moved to
  `uv_fs_event_t` (ADR-01602).
- The no-op hooks `__kml_ipcc_*`, `__kml_fswatch_*`, `__kml_pool_*`,
  `__kml_tcp_*` (`runtime_ipc.go`, `runtime_task.go`) and
  `__kml_worker_fd_setbit` were called by nothing.
- libuv's Windows backend is a completion port with no descriptor
  (`uv_backend_fd` is -1), so the POSIX hosts' embedding (watch the backend
  descriptor from the GUI loop, `webviewsrc/loop_embed.cc`) does not apply.
  Electron embeds Node's loop on Windows with a thread that waits on the
  port, posts back what it took, and wakes the GUI thread.

## Decision

- **Named pipes** are `kml_ustream`s: `__kml_native_pipe_connect` and
  `__kml_native_pipe_listen` on a `\\.\pipe\` / `\\?\pipe\` name make a
  `uv_pipe_t` and `uv_pipe_connect` it, or `uv_pipe_bind` + `uv_listen` it
  (libuv offers four instances, as Node's server does), each accepted
  connection a new stream in the table. Any other path stays an `AF_UNIX`
  socket.
- **`win32io.c`** keeps the descriptor table (sockets and owned handles in
  one pool, CRT fds below it, `dup2` descriptions), the socket calls under
  their POSIX names as plain non-blocking Winsock calls (`connect` answers
  `EINPROGRESS`, then libuv's poll and `SO_ERROR`), the cluster round-robin
  and IPC socket hand-off, the console reader for blocking reads, `poll()`
  for the runtime's blocking helpers (`WSAPoll` for sockets, short slices
  otherwise), the signal wake registry (`__kml_win_set_loop_wake`, every
  registered loop's `uv_async_send`), the high-resolution sleep, and fibers.
  Everything the shim's own reactor needed goes: 3,410 lines to 1,550.
- `klainpool.c`'s `tcp_shim_poll` and its Windows readiness branches go;
  an unpollable descriptor is always ready, as on POSIX.
- `win32fswatch.c`, the unused declarations and the no-op hooks go.
- **The Windows webview** embeds the loop as described above
  (`loop_embed.cc`'s `_WIN32` branch): a message-only window whose message
  runs one pass and records the next deadline; a thread that waits on
  libuv's port (`__kml_loop_backend_port`) for a completion or that deadline,
  posts the completion back, and posts the message; a bound callback's kick
  is an empty completion, which libuv ignores. The page tick is gone.
- **The reactor idle tests** measure the processor time an idle program
  uses (user + kernel), since the trace they counted was the shim's.
- The native shim tests drop `select()`, `pipe()` and the emulated-completion
  test, whose mechanism is gone.

## Implementation notes

- `codegen/llvm/win32src/win32io.c` (rewritten), `win32fswatch.c` (deleted),
  `hostclang_win32shim.go`.
- `codegen/llvm/threadpoolsrc/klainpool.c`: `us_pipe_listen`,
  `us_pipe_connect`, `us_on_connection`, `us_take_conn`; the listener branch
  of the dispatch takes an accepted stream.
- `codegen/llvm/loopsrc/loop.c`: `__kml_loop_backend_port`; the wake flag
  nothing read.
- `codegen/llvm/webviewsrc/loop_embed.cc`, `natives.c`, `webview.go`.
- `runtime_ipc.go`, `runtime_task.go`, `runtime_worker.go`, `emitter.go`,
  `runtime_http.go`, `runtime_fetch.go`, `fetchsrc/fetch.c`, `hostclang.go`.
- Tests: `reactor_windows_test.go`, `fd_descriptions_windows_test.go`,
  `sock_options_windows_test.go` and their C, `net_named_pipe_windows_test.go`,
  `dgram_test.go`; `reactor_emulated_windows_test.go` deleted.

## Side effects discovered

- `go test -run '(?i)…'` with alternatives ran only some of the matching
  tests on this machine while `-list` listed them all; the targeted runs use
  plain names.

## Verification

Windows 11 (this machine): the named-pipe, `net`, HTTP, fetch, TLS, dgram,
cluster, child-process, IPC, stdio, tty, signal, reactor, Worker and
fs.watch tests, and the native shim tests. The windowed webview needs a
desktop session: compiled here, its run is the owner's.
