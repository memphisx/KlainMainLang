# ADR-01913: a generic alias's body and an annotated literal in the oracle

- **Relations**: `Implements TDD-00230` (P3.3 shadow buckets)
- **Date**: 2026-10-21

## Context

- resolveType instantiates a generic alias by substituting its arguments into a copy of the body, which keeps the declaration's type nodes. Read at module scope, `{ value: T }` names no `T`, so the oracle answered a box where codegen held the argument's type.
- A module variable annotated by an alias that names a string literal (`const u: Named<User> = "named"`) keeps the literal in resolveType; the oracle widened it to a string.

## Decision

- resolveType binds the alias's parameters to the resolved arguments while it resolves the body. The checker reads a type node inside a generic alias with the alias's parameter names as type parameters (TypeFromNodeWithParams), which the oracle maps through that binding.
- The oracle keeps an annotated module variable's string literal.

## Consequences

- The conditional-types example's rows go away.
