# ADR-00265: Unify async-method promises with async functions; declared `Promise<T>` await; async-return flattening

- **Relations**: refines [ADR-00249](ADR-00249.md) (task-struct promise, TDD-00084 Part A); closes the `await`-row and `new Promise`-row promise-representation caveats
- **Date**: 2026-08-20

## Context

Async *functions* were migrated to a task-struct promise (value in field 2,
[ADR-00249](ADR-00249.md)), but async *methods* were left on the pre-TDD-00084
**bare-slot** model (value in field 0, `emitAsyncPrologue`/`emitAsyncEpilogue`).
Two representations for one `Promise<T>` type meant `await` couldn't know which
slot to read:

- `const p: Promise<number> = f(); await p` read the wrong slot (an explicit
  `: Promise<T>` annotation resolved to a non-task-shaped promise, discarding the
  task tag inference otherwise keeps) — it printed the state field, not the value.
- `function f(): Promise<T> { return new Promise(...) }` (a plain function
  returning a promise) and `async function f() { return new Promise(...) }` (async
  return) both mis-typed / double-wrapped — the common `delay()` helper
  (`async () => new Promise(res => setTimeout(res, ms))`) didn't work.

Tagging `Promise<T>` annotations as task-shaped had previously broken async
methods precisely because methods were bare-slot.

## Decision

Three changes, together:

- **Unify async methods onto the task-struct model.** `emitClassMember`'s async
  path now uses `emitInlineAsyncPrologue`/`emitInlineAsyncEpilogue` (the inline
  catch-and-settle task promise) instead of the bare-slot pair. Method sigs carry
  `IsAsync`, and every method-call result (`emitClassCall`/`emitStaticMethodCall`
  and their type inference) is tagged `PromiseTask` via a shared `taskTaggedRet`,
  matching the plain-function path.
- **A declared `Promise<T>` annotation is task-shaped.** With one representation,
  `resolveType(Promise<T>)` now sets `PromiseTask` for non-`Response` `T`, so
  `const p: Promise<T> = …; await p` reads the right slot.
- **Async-return flattening.** In an async `return`, if the returned value is
  itself a task promise (and the fn's own value type isn't a promise), await it
  first (`emitAwaitTaskPromise`, factored out of `emitAwait`) and settle with its
  value — re-throwing its rejection into this fn's own settle. So
  `return new Promise(...)` / `return Promise.resolve(x)` adopt the inner promise's
  state instead of double-wrapping.

## Consequences

- `await` on an explicitly `: Promise<T>`-annotated variable, a plain function
  returning `new Promise`, an async function returning a promise, and the deferred
  `delay()` helper all work. The `await`-row annotation caveat and the
  `new Promise`-row cross-function-boundary caveat are closed.
- Async methods now compose with the scheduler / `.then` / combinators exactly
  like async functions; the two-representation split (a latent source of bugs) is
  gone.
- `new Promise` still has narrower residual caveats (a `resolve(aPromise)` doesn't
  adopt a thenable; the executor must be an arrow/function expression), so that row
  stays non-strict; `await` stays non-strict on the microtask-tick-ordering wall.
