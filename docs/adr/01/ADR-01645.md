# ADR-01645: An `any` holding null keeps null in a three-state pointer

- **Relations**: Extends [ADR-01642](ADR-01642.md)
- **Date**: 2026-10-16

## Context

A socket or http write callback got `undefined` where Node passes `null`.
Our `net.Socket.write` override forwards the callback to `super.write`,
whose parameter type is `(error?: any) => void`, so the callback is adapted.
The minimal case: `const x: any = null; f(x)` with
`f(e?: Error | null)` printed `undefined`.

## Investigation

An optional `Error | null` parameter is three-state (`NullAndUndef`): the
null pointer is undefined and `nullRef` is null. `coerce`'s three-state
branch only covers pointer and scalar sources, so a box (i64) went to the
plain unbox, which maps both null and undefined to the null pointer. The
closure adapter unboxes through `emitUnboxBoxToType`, which had the same gap.

## Decision

`emitUnboxBoxToType` unboxes a three-state pointer target as the plain
nullable pointer, then selects `nullRef` when the box is `nbNull`. `coerce`
sends a box into a three-state pointer through it. The socket's
synchronous-write completion also passes `null`, as its async path did.

## Implementation notes

`codegen/llvm/emit_narrowing.go`, `codegen/llvm/emit_exprs_coerce.go`,
`lib/node/net.ts`.

## Side effects discovered

The streams caveat that `finished`/`pipeline` callbacks typed
`(err?: Error | null)` see `null` no longer reproduces; both now print
`undefined`, as Node does. Removed from the status data and BACKLOG.

## Verification

`TestE2EAnyNullIntoThreeStatePointer` and `TestE2EWriteCallbackGetsNull`
match Node. Apple Silicon Mac and Linux x86-64 (DeskMini) probes.
