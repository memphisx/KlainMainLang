# ADR-01193: Promise combinators are the spec's algorithms

- **Relations**: `Extends ADR-00248`, `Extends ADR-01192`
- **Date**: 2026-09-28

## Context

`Promise.all`/`allSettled`/`race`/`any` awaited their members at the call
(driving the scheduler) and returned a pre-resolved value slot, not a task
promise: `.then`/`.catch`/`.finally` on the result were compile errors
("currently supported only on a promise from a may-suspend async function"),
a member's rejection was thrown at the call rather than rejecting the
result, and the call blocked the rest of the synchronous code.

## Decision

The members first become task promises: a task promise (what every
`async` function, `new Promise` and `Promise.resolve` produce) as it is, a
raw `fetch` promise through its bridge (`@__kml_fetch_slot_to_promise`), a
plain value as a promise fulfilled with it (the spec's PromiseResolve), and
a value held in `any` through `Promise.resolve` of it. Then each combinator
allocates a pending result promise, attaches one
reaction per member and returns at once. A member's reaction, a
per-call-site runner over the member value type, settles the result by the
spec's rule: `all` stores the value and fulfils with the array once every
member has, and rejects with the first rejection; `allSettled` stores a
`{ status, value | reason }` record and fulfils once every member settled;
`race` settles with the first member to settle; `any` fulfils with the
first fulfilment, and rejects with an `AggregateError` of the reasons once
every member rejected. An empty list fulfils `all`/`allSettled` with `[]`
and rejects `any`; `race` stays pending. The result is a task promise, so
`await`, `.then`, `.catch` and `.finally` all apply; attaching the
reactions marks the members handled (ADR-01192).

The former per-shape paths (await each member at the call, a pre-resolved
value slot as the result, a fetch group wait) are deleted.

## Implementation notes

`codegen/llvm/emit_promise_combinators.go` (new), `emit_promise.go`
(`emitCombinator`, `combinatorMembers`, `wrapValueMembers`,
`bridgeFetchMembers`), `runtime_promise_adopt.go` (the bridge's own task
promise is handled), `emit_exprs_types.go` (the combinators' task-promise
type), `emitter.go`.

## Side effects discovered

- An inline list mixing promises and values (`[p, 4]`) is a heterogeneous
  array literal, rejected in the strict lane; an `any[]` list works.

## Verification

Mac (Apple Silicon), against Node v24.19: a program chaining `.then`/`.catch`
on each combinator over delayed and rejecting members, over `fetch`es of a
local server (one refused), and over plain values prints Node's output line
for line, in Node's order; `tests/promise_combinators_async_test.go`; the
promise, async, combinator and fetch test files.
