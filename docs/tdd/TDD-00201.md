# TDD-00201: ToPrimitive coercion of objects in numeric/string contexts

- **Status**: Implemented
- **Date**: 2026-09-10

## Context

An object used where a primitive is required — `{valueOf(){return 1}} & 1`,
`arr.indexOf(x, {toString(){return '1'}})`, `"s".slice({valueOf(){return 2}})`,
`` `${obj}` ``, `obj + 1`, `obj == 1` — must be converted by JS's **ToPrimitive**
abstract operation: consult `Symbol.toPrimitive`, else try `valueOf`/`toString`
in a hint-dependent order, and use the first that returns a primitive.

This compiler implements none of it. An `IsObject` value reaches a numeric/string
operator or a typed slot and its `ptr` register is used directly where an `i64`/
`double`/string is expected — invalid IR (`'%tN' defined with type 'ptr' but
expected 'i64'`), which clang rejects. This is the **dominant root cause of the
A1 invalid-IR cluster** (the largest bucket in the backlog: ~203 CLANG_ERROR
Test262 files as of the 2026-09-10 histogram — bitwise ops, `Array.indexOf`
`fromIndex`, `String.slice`/`substring`/`indexOf` args, `RegExp.exec` arg, etc.,
overwhelmingly the `{valueOf}`/`{toString}` object-coercion pattern).

It is scoped now because it is the single highest-leverage invalid-IR item, and —
critically — it is a **faithful, implementable JS feature, not a native-
compilation impossibility**. The runtime already discloses it as a planned later
stage (`emit_anyops.go`: "heap references → NaN … the full ToPrimitive ladder is
a later stage, disclosed"). Leaving it emits invalid IR; a clean rejection would
be a documented divergence from real JS, which the zero-caveat direction rejects.

## Design

### The hook: `coerce`, keyed by target type

`coerce(v, target)` (`emit_exprs_coerce.go:9`) is the central conversion point and
already special-cases dynamic/nullable/null sources. Add an `IsObject`-source arm
**before** the same-IR ptr passthrough. The `target` type carries the hint:

- `target.Float` or integer IR (`i64`/`i32`/…) → **number** hint.
- `target.IR == "ptr"` string target → **string** hint.

Hooking `coerce` covers the large majority of A1 for free, because operator and
argument-passing sites already funnel their operands through `coerce` to reach
`i64`/`double`/string (e.g. `obj & 1` coerces `obj` to `i64`; `indexOf`'s
`fromIndex` coerces to a number; a string-typed parameter coerces to `ptr`).

### The ToPrimitive ladder (static)

Because objects are fixed-shape, whether `valueOf`/`toString` exist and their
return types are known **at compile time** — no runtime property lookup needed.
`emitToPrimitive(v, hint)`:

0. **`Symbol.toPrimitive` first** (per spec). This fits the *static* model via
   the existing well-known-symbol trick: the parser already desugars a literal
   computed key `[Symbol.iterator]` to a reserved **string** field `@@iterator`
   (`wellKnownSymbolMemberName`, `parser/parser_classes.go`), keeping it an
   ordinary static method field — no dynamic bag. Extend that recognizer to
   `[Symbol.toPrimitive]` → `@@toPrimitive`. If the object's static type declares
   `@@toPrimitive`, call it with the hint string (`"number"`/`"string"`/
   `"default"`) and coerce its (primitive) result. This is genuinely in reach for
   the literal-computed-key form and should NOT be deferred.
1. **hint = number**: try `valueOf`, then `toString`.
   **hint = string**: try `toString`, then `valueOf`.
   **hint = default** (`+`, `==` — Stage 2/3): number order.
2. For each candidate method, if the object's static type declares it callable —
   an object-literal `Field` holding a function, or a class `MethodSigs` entry —
   emit the call (reusing `emitClassMethodCall` for classes; the object-literal
   field-call dispatch for literals) and, if its declared return type is a
   primitive, `coerce` that result to `target` and stop. If the return type is
   itself an object, fall through to the next candidate (mirrors "result must be
   primitive").
3. If no candidate yields a primitive: the default. Number hint → `NaN`
   (`0x7FF8000000000000`); string hint → the literal `"[object Object]"`
   (or the class name form real JS uses for a class instance without `toString`,
   `"[object Object]"` for a plain object).

Method dispatch to a user-declared `toString()` on a class instance already works
(`emit_call.go:769`, checked before the generic built-ins) — this generalizes the
same mechanism to `valueOf` and to object-literal method fields, invoked from the
coercion path rather than an explicit `.toString()` call site.

### Operator sites that don't route through `coerce`

`+` (string-concat vs numeric add overload) and loose `==`/relational have their
own operand logic and choose the **default** hint. These are separate, later
stages that call the same `emitToPrimitive` before their existing type decision.

### strict vs `-compat=js`

ToPrimitive on a **statically-typed** object is faithful in **both** lanes — it is
not a `compat` inhabitant; the value's shape is known, the calls are ordinary
typed method calls, no NaN-box/any is involved. The `-compat=js`-only extension is
the **dynamic** path (below).

## Staging

- **Stage 1 — number hint** — SHIPPED (ADR-00859): `IsObject` → numeric target
  runs the ladder (`@@toPrimitive`/valueOf/toString), hooked into `coerce` (covers
  bitwise/shift + typed numeric slots) and an `emitBinary` pre-pass (arithmetic/
  relational). `@@toPrimitive` recognizer added. Object literals; class-instance
  valueOf and a string-returning method in numeric context (ToNumber(string)) are
  the remaining Stage-1 residue. NOTE: standalone Test262 A1 gain is small — most
  A1 files also carry a string-hint object argument (Stage 2) and/or the full-file
  interaction bug below, so the visible A1 wins land with Stage 2.
- **Stage 2 — string hint** — SHIPPED (ADR-00860): `emitValueToString` (String()/
  template/concat) honors a user `toString`/`@@toPrimitive`; string-hint order is
  `@@toPrimitive`→`toString` (valueOf omitted — inherited Object.prototype.toString
  intercepts). `coerceStringArg` ToStrings an object argument, applied to every
  string method with a string search/pattern/replacement arg —
  `indexOf`/`lastIndexOf`/`includes`/`startsWith`/`endsWith` and
  `replace`/`replaceAll`/`split` (after their existing `IsRegExp`/`IsFunc`
  dispatch, so a regex/callback arg is never ToString'd). `slice`/`substring` take
  numeric indices → already covered by Stage 1's number-hint hook. The string-hint
  side of TDD-00201 is now complete.
- **Stage 3 — operator sites** — SHIPPED (ADR-00861): `obj + x` (default hint →
  the +overload concat/add decision) and loose `==`/`!=` (default hint, only when
  the other side is a number/string/bigint — `obj == null` and `obj == obj` stay
  uncoerced). Relational `< > <= >=` were already Stage 1. Also fixed a
  found-in-passing invalid-IR bug: `obj === 5` (object vs disjoint scalar) now
  rejects cleanly instead of emitting a `ptr`-vs-`double` `icmp`; this rejection
  was generalized to the arithmetic/relational operators too (`{a:1} + 5` /
  `* 2` / `< 5` in strict — TS errors on object arithmetic — reject cleanly rather
  than emit invalid IR; faithful under compat=js via Stage 4's default form).
- **Stage 4 — dynamic path (`-compat=js`)** — SHIPPED (ADR-00862): runtime
  ToPrimitive over a NaN-boxed dynamic object — `@__kml_toprimitive(box, strHint)`
  looks up valueOf/toString/`@@toPrimitive` on the D1 bag and invokes them via the
  tag-12 ABI, wired into `emitAnyBinary` (arithmetic/`+`) and `emitDynamicToString`
  (`String()`/template/concat). compat=js arithmetic and string coercion are now
  faithful (were NaN / "[object Object]"). Loose `==`/`!=` is also implemented:
  `@__kml_any_loose_eq` runs JS's Abstract Equality over boxed values — both-
  objects reference compare (`{}=={}` false), one-object ToPrimitive, nullish
  rule, same-type strict, mixed-primitive ToNumber — routed from the dynamic
  `==`/`!=` branch and (for static mixed-kind pairs like `5 == "5"`/`"" == 0`) an
  early compat=js divert. `===`/`!==` stay uncoerced.

## Open questions

- **`Symbol.toPrimitive`**: RESOLVED — in scope via the `@@toPrimitive`
  string-alias desugar (see ladder step 0), the same mechanism that already makes
  `[Symbol.iterator]` work, so no dynamic-bag dependency. The only piece left
  undecided is placement: fold the parser recognizer + ladder step 0 into Stage 1,
  or land it as Stage 1b immediately after the valueOf/toString core. The genuine
  boundary (unchanged): a symbol used as a *runtime value* key
  (`const k = Symbol.toPrimitive; obj[k]`) still needs the D1 dynamic bag
  (TDD-00155 Stage 7) — but no known A1 file uses that form.
- **Return-type not statically primitive**: if `valueOf`'s declared return type is
  itself an object (or `any`), can Stage 1 prove the ladder statically, or does it
  need a runtime primitive-check + fallthrough? For the concrete A1 corpus the
  return types are primitive; the general case may need a guarded runtime check.
- **`"[object Object]"` vs class tag**: exact default string form for a class
  instance lacking `toString` — confirm against Node (`[object Object]` unless a
  `Symbol.toStringTag`/constructor-name rule applies).
- **The A2 mis-dispatch overlap**: some invalid-IR files (iterator-helper
  `gen().includes(1000)` mis-dispatching to string `includes`) look A1-adjacent
  but are a *dispatch* bug, not ToPrimitive — keep them out of this TDD's scope.
- **Full-file interaction bug (found in Stage 1)**: `bitwise-and/S11.10.1_A2.2_T1.js`
  and its siblings still emit invalid IR when the *whole* harness+7-cases file
  compiles, though every individual case (including a throwing valueOf/toString in
  try/catch) compiles in isolation. Predates ToPrimitive; not yet isolated. Likely
  a codegen interaction (object-literal type identity across many similar shapes,
  or try/catch), NOT a ToPrimitive-ladder issue — it blocks the pure-number A1
  files from landing and needs its own repro.
