# ADR-01240: A generic class named without type arguments takes its defaults

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-09-29

## Context

After `events` became a TypeScript module (ADR-01238), `http.createServer({
highWaterMark: "big" })` compiled: the checker no longer reported TS2345.
`EventEmitter` is `class EventEmitter<T = any>`, and every type that named
it without type arguments (`Server extends EventEmitter`, a function
returning `EventEmitter`) went unchecked, and so did every function whose
signature named one of those types.

## Investigation

`class G<T = any> {}; function f(): G { … }; const s: number = f` compiled.
`instanceOf` (`checker/symbols.go`) returned no type when the argument count
differed from the class's type-parameter count. `interfaceOf` already fills
omitted arguments from the parameters' defaults.

## Decision

`instanceOf` fills omitted type arguments from the class's
`TypeParamDefaults`, each typed with the ones before it in scope, as
`interfaceOf` does. A parameter without a default is still no type.

## Verification

Mac (Apple Silicon): `TestE2ETypeErrorClassDefaultTypeArgs`;
`TestE2EHTTPCreateServerOptionRejections` passes again; the full test
suite.
