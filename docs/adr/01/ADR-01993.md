# ADR-01993: WPT js-lane invalid IR and the Response body bugs found with it

- **Relations**: Implements TDD-00230
- **Date**: 2026-11-20

## Context

The Linux x86-64 WPT run compiled programs in the js lane to invalid IR,
and tracing them turned up two more divergences from Node:

1. `p.finally(f)` with `f` known only as `any` (the harness's
   `globalThis.done`) stored the box where the reaction expects a closure
   pointer.
2. `.clone()`, `.text()` and the other body readers on a Response held in
   an object's field (a boxed value in the js lane) took the box for a
   Response: an internal compile error.
3. `typeof res.body` answered `"string"`: the type came from the raw body
   slot, not the stream the accessor returns.

## Decision

1. An `any` onFinally is checked at run time: when callable, the reaction
   gets a closure calling it with no arguments; otherwise none, the
   runner's pass-through, as `then(onFinally, onFinally)` is for a
   non-callable one (no extra ticks, so the order matches Node's).
2. The clone and body-reader intrinsics call the receiver's own method,
   looked up at run time, when the receiver is a box.
3. `typeof` of a Body member answers from the accessor's own type.

## Verification

Tests, each compared with Node: `TestE2EJSPromiseFinallyDynamicCallback`,
`TestE2EJSResponseInObjectFieldCloneRead`, `TestE2ETypeofResponseBody`.

## Also found in the same runs

4. A Response's clone read its body through a `body` property read, which
   a program writing a property of that name routes through the
   own-property shadow as a box (invalid IR): it now reads the body itself
   (`TestE2EJSResponseCloneWithBodyPropertyWrite`).
5. A nested generator in a callback emitted twice was registered twice but
   its body emitted once, keyed by its declaration: the second
   registration's body was an undefined symbol at link. Bodies are now
   keyed by registration (`TestE2EJSNestedGeneratorInTwiceEmittedCallback`).
6. The conformance runners compiled a program that looks its own symbols
   up (dlopen(null), which a WebAssembly memory view marks) as one
   unsplit module, so a WebAssembly test took past the clang timeout;
   they now split it as the CLI does, without dead-stripping and with the
   CLI's FFI link flags.
7. A nested function using `this` moved to the top of its block ahead of
   a `var` the block declares further down, so codegen saw the var
   undeclared (an internal error): the moved functions now follow an
   uninitialized declaration of each such `var`, JavaScript's hoisting
   (`TestE2EJSThisFunctionCapturesLaterVar`).
8. A boolean's or number's method only the program's own interface
   declares (`x["doStuff"]()`) was an internal error; it is read from the
   prototype when the call runs, as in JavaScript
   (`TestE2EPrimitiveAugmentedMethodCall`).
9. A file's `interface Number {}` renamed the file's value references to
   `Number` with it, so `Number.prototype` was a ReferenceError; a name
   the file declares only as a type now leaves value references to the
   global (`TestE2EInterfaceNamedLikeGlobalKeepsValue`).
