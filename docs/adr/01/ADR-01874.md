# ADR-01874: Iterating an object whose iterator key is no method

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's CallExpression bucket)
- **Date**: 2026-10-21

## Context

- Test262's `yield-star-*` family delegates to `{ get [Symbol.iterator]() {…}, get [Symbol.asyncIterator]() {…} }`. tsc reports TS2504 (TS2488 for a sync `yield*` or `for…of`) and types the delegation as its error type, any. The checker left it unanswered, so every `iter.next()` after it was too (about 700 shadow rows), and the strict lane compiled programs tsc rejects.
- A literal getter whose body only throws was inferred `never`; tsc's mayReturnNever allows `never` only for function expressions, arrows and literal methods, so the getter is `void` (the TS2504 message names the type).

## Decision

- An object literal type the checker models whole that declares an iterator key, but not as a method (and not async iterable when async), iterates as any; the strict lane reports TS2488/TS2504 for it in `yield*` and `for…of`.
- A literal accessor whose end is unreachable returns void.

## Consequences

- `TestCheck`'s new case and `TestLiteralAccessorThrowsVoid` hold tsc 5.6's codes and types. `yield-star-getiter-async-get-abrupt.js` leaves the shadow report; the strict lane rejects it with tsc's message, and the js lane passes.
- An object with no iterator key at all is still left to the checker's earlier reading: inference reads `{ length: 2 }` against `Iterable<B>` through the same path.
- Verified on Apple Silicon.
