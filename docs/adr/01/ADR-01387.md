# ADR-01387: Waits outside a coroutine abort instead of driving a subset

- **Relations**: Implements TDD-00244; Extends ADR-01386
- **Date**: 2026-10-04

## Context

[TDD-00244](../../tdd/TDD-00244.md) Stage 2, first part. When a wait could
neither park (no coroutine, no connection fiber) nor run the loop (it was
inside a loop callback), `top_wait` (`task.c`), the fetch `spin`
(`fetch.c`) and `__kml_loop_turn`'s cannot-run result
(`runtime_loop_turn.go`) each drove a subset of the event sources by hand:
curl, timers, the scheduler. Every other source starved for the length of
that wait.

## Investigation

- The traced test-par run of [ADR-01386](ADR-01386.md) found these drives
  reached only by request-body connection fibers, which Stage 5 owns and
  which take a separate path (`await_ready_busy`).
- Every async function that awaits is a coroutine (TDD-00223 section 2), so
  any other arrival is a compiler bug, which the subset drive hid.

## Decision

- **The three subset drives are replaced by
  `__kml_wait_outside_coroutine()`** (`loop.c`). It writes an internal
  error to stderr and aborts.
- The connection-fiber busy waits stay until Stage 5 resumes those fibers
  from read callbacks.
- Running top-level code in a fiber, and deleting `__kml_loop_turn`,
  `top_wait` and `__kml_httpc_drive`, remain Stage 2 work.

## Verification

- Full gates on the result: Node304 test-par (3,921 tests), DeskMini
  examples (393/393), Test262 strict 8,498 (unchanged), js lane on
  DeskMini.
