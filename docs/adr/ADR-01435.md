# ADR-01435: Annotated array locals take the annotation's nullability

- **Relations**: Implements TDD-00230 (P2.2)
- **Date**: 2026-10-07

## Context

The largest shadow bucket after ADR-01434 (2581 rows) was an array
identifier codegen held as nullable where the checker does not:
`internal_json.ts`'s

```ts
const names: string[] = this.props !== undefined ? this.props : Object.keys(value);
```

## Investigation

- Array declarations mark the binding nullable whenever the initializer's
  value is (TDD-00213: a `Map<K, T[]>` get that may miss binds a
  `T[] | undefined`, read back null-safely).
- The conditional's branches are inferred without the `!== undefined`
  narrowing, so the value looked nullable even though the annotation, which
  tsc has already checked the initializer against, says `string[]`.

## Decision

The initializer's nullability carries to the binding only when the
declaration has no annotation or a nullable one (`T[] | undefined`). A
non-nullable annotation is the binding's type.

## Verification

- `TestE2EAnnotatedArrayFromNullableBranch` (both annotation forms, against
  Node) and the existing array-reference tests pass on the Mac.
- The probe's shadow row is gone.
