# ADR-01111: The checker core and its type representation, a first increment answering the shadow harness

- **Relations**: `Implements TDD-00230` (Phase 2, P2.3 and P2.4, first increment); `Extends ADR-01107`, `ADR-01108`
- **Date**: 2026-09-24

## Context

Codegen decides every expression's type itself, while emitting
(`inferExprType` and 22 other deciders). [TDD-00230](../tdd/TDD-00230.md)
P2.3 and P2.4 introduce a checker with one memoised `TypeOf(node)` and an
interned type representation, and the P0.2 harness compares its answers with
the old deciders' over the corpus, so each decider is replaced only where the
two agree. This first increment builds the checker's core and the types it
needs to answer for the primitive part of the language.

## Investigation

- **typescript-go** (`internal/checker/`): `getTypeOfExpression` memoised in
  node links, `getTypeOfSymbol` in symbol links with a resolution stack for
  cycles, literal types widened for mutable bindings
  (`getWidenedLiteralType`), unions keyed by their sorted member ids, and an
  error type (an `any`) standing in where checking fails.
- **Codegen's representation of the primitives** (`ResolveTypeName`,
  `codegen/llvm/types.go`): `number` is a `double` (`TypeF64`, since
  TDD-00123), `string` a `ptr`, `boolean` an `i1`, `bigint` its boxed type,
  `any`/`unknown` the NaN-boxed `i64`, the JSDoc widths `int8`…`uint64` and
  `float32` their LLVM types, and `T[]` `ArrayOf(T)`.
- **Type names in annotations** resolve through the binder's scopes: the
  binder's symbols carry type flags (class, interface, type alias, enum), and
  a declaration's symbol knows its scope.

## Decision

- **A `checker` package.**
  - `Type{Flags, ID, …}` with one flag bit per kind, including the native
    widths (`Int{Bits, Signed}`, `Float32`) as kinds of their own. Literal
    types, unions (flattened, ordered by member id, `never` dropped, `any`
    absorbing), arrays, tuples, function types, anonymous objects and the
    nominal instance and interface types are interned, so type equality is
    pointer equality. A union also drops a literal whose primitive is a
    member and folds `true | false` into `boolean`, as TypeScript's literal
    reduction does.
  - `TypeOf(expr)` is memoised per node. It types literals (numeric literals
    by their canonical value), identifiers through the binder, the operators
    by TypeScript's rules (`+` with a string is a string; arithmetic a number
    or a bigint; comparisons boolean; `&&`, `||`, `??` from the truthy,
    falsy and non-nullish parts of their operands), conditionals, `=`,
    sequences, array and object literals, member access on known object
    types (and `.length`), indexing an array, calls to function-typed callees,
    `new` of a non-generic class, `!` and `as`. An instance type holds its
    fields and methods after its base class's, when the base is a class the
    program declares (a builtin base such as `Error` waits for the
    declaration-driven library, P3).
  - A symbol's type comes from its declaration, memoised, with a resolution
    stack for cycles: an annotation; else a `const` initializer's type, or a
    `let`/`var` initializer's widened; a parameter's annotation (optional
    adds `undefined`) or its default's widened type; a function's signature
    when its parameters are annotated, its result annotated or inferred; a
    `for…of` variable from an array or string; a destructured name from its
    element or property of the source (a tuple rest is the remaining tuple,
    a default replaces `undefined`, widened for `let` and `var`); a catch
    variable is `unknown`, as under `--strict`.
  - **Return types are inferred** when not annotated: the join of every
    `return`'s value in the body (not in nested functions), plus
    `undefined` when a `return;` or the end of the body is reachable (the
    binder's flow graph says which), or `void` when no `return` carries a
    value; an expression-bodied arrow returns its expression's type. A
    result that is a single literal is widened (`return 2` is `number`,
    even `return k` for `const k = 1`); a union keeps its literals
    (`1 | "x"`, `2 | undefined`), as tsc infers without a contextual type.
    A function whose result depends on itself (recursion) is unanswered.
  - Annotations become types from the P1.5 type nodes, names resolved through
    the binder's scopes: keywords, literals, arrays, `Array<T>`, tuples
    (labelled elements), unions, function types, type literals, classes,
    interfaces (their `extends` bases' members first, own members
    replacing them) and type aliases. An interface with a generic or
    qualified base, which the parser drops from `Extends`, is unanswered
    (the parser now records the drop: `InterfaceDeclaration.ExtendsDropped`).
  - **Unanswered** is a distinct marker (an `any`) for what the checker does
    not model yet (generics, the builtin library, async functions and
    generators, a rest property). It propagates, and the
    shadow harness records nothing where the checker has not answered.
- **The shadow oracle** (`codegen/llvm/shadow_binder.go`) now answers
  `inferExprType` and `resolveType` with the checker's type mapped by a first
  `reprOf`: the primitives, the native widths, and arrays of them, as above.
  Unions and objects have no representation mapping yet (P3.3).

## Side effects discovered

- **Codegen's signature pass reads names that are not bound yet.** While
  it infers a function's return type (Pass 1), `inferExprType` resolves the
  body's locals and parameters before they are in scope, and falls through
  to its number default, `i64`. The shadow report shows 87 such answers
  over the examples and apps: string, array and `any` bindings typed
  `i64`, for example `let full = dir` in `apps/files/fs.ts` and `argv[i]`
  in `apps/loadtest/config.ts`. The emitted code is right, because
  emission asks again with the scope in place. The same fall-through
  produced invalid IR in ADR-01060. The checker's answer replaces these
  when the decider switches over.

## Verification

All on macOS arm64 (M4):

- `go test ./checker`: literal, operator, binding, parameter, call, member,
  class, interface, tuple-alias, native-width and float32 cases; every
  expression of every example and app file is typed without a panic, and a
  second asking returns the same type.
- Each checker expectation in the tests that TypeScript prints differently
  from the obvious answer (union printing and literal reduction,
  destructuring defaults, `catch` variables, inferred return types: literal
  widening, a reachable end, a `throw` or infinite loop at the end) was
  checked against tsc 5.6.3 `--strict`. Union members print as tsc prints
  them, `null` and `undefined` last.
- The resolver's output with the checker's parser change
  (`ExtendsDropped`) is identical over the 107,567-run corpus dump.
- **Shadow report** (`tools/shadow -roots examples,apps`, 404 compile runs,
  0 timed out): 462 disagreements in 29 buckets, with ADR-01112's
  narrowing in place. By cause:
  - 186: codegen represents an integer-valued `number` as `i64`; the
    checker's type is `number`, a `double`. This is representation, which
    P3.3 decides.
  - 89: a `catch` variable (83 directly, 6 through `as` or `instanceof`),
    `unknown` to the checker as under `--strict`, which codegen holds in
    its caught-value box or types as the error class. Also representation.
  - 87: codegen's unbound-name `i64` answers (see Side effects).
  - 88: codegen adds `undefined` where TypeScript does not: an array
    element read (`UncheckedIndex`, 86; TypeScript without
    `noUncheckedIndexedAccess` types it as the element type), an array
    destructuring element, and `s?.length` on a non-nullable string. This
    is the absence question of P2.5.
  - 4: a narrowed read (`x` after `x = 42`, `absent` after `= null`) that
    the checker types narrowed, while codegen keeps the declared union or
    nullable representation. P2.5 separates the storage type from the
    read type.
  - 3: an optional parameter of a function type annotation, which codegen
    folds into the parameter's type.
  - 3: a `-compat=js` binding that codegen holds as `any`.
  - 2: `key === undefined ? "constructor" : key` with `key: any`, which
    TypeScript types `any`; codegen tracks a string-or-`any` union.
- Two checker bugs the report found are fixed:
  - arithmetic on an operand the checker could not type (`hrtime.bigint()
    - start`), or on an object (a `Date`), no longer answers `number`;
  - an annotation's string literal type keeps its literal in the mapped
    representation.
- `make examples`: 358/358. `make test-par`: pass apart from the four
  `-mm=gc` macOS segfaults (`task_reclaim_gc_tls_test.go`), which fail
  identically at HEAD (BACKLOG §0 item 1d). The checker runs only under
  the shadow harness, so compiled output does not depend on it.
