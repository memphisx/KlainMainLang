# ADR-01647: An error's own property set to undefined stays its own

- **Relations**: Extends [ADR-01080](ADR-01080.md)
- **Date**: 2026-10-16

## Context

A c-ares DNS error lacked Node's `errno: undefined` key. Node's
`DNSException` assigns `this.errno = code` even when code is a string's
undefined errno. The library skipped the assignment, because the error
layout's `errno` slot is a double where 0 means absent.

## Investigation

Assigning undefined (`lib/node/internal_dns_utils.ts`) made no difference:
the dynamic setter's error arm (`emitDynAnyMemberSetInline`) stored
undefined as the absent 0 or null, so the key vanished. Two neighbouring
bugs:

- `in` and `Object.hasOwn` on a boxed error checked the layout row and
  `message`/`stack` only: `'bar' in err` was false for any property
  assigned on it.
- `__kml_error_extra_get` reported a hit for any key once the error had an
  `extra` bag, so `__kml_obj_has` answered true for a key the bag lacked.

## Decision

- The setter's error arm stores a value of the field's kind in the field.
  Any other value, undefined included, clears the field and goes to the
  `extra` bag, as other values already did. Reads and key listing consult
  the bag, so the key appears with undefined, after the set fields as
  before.
- `emitDynAnyHas`'s static-object arm also asks `__kml_error_extra_get`
  for an error.
- `__kml_error_extra_get` reports found only when the bag holds the key.
- `DNSException` assigns `errno` unconditionally, as Node's does.

## Implementation notes

`codegen/llvm/emit_dynobj.go`, `codegen/llvm/boxsrc/errkeys.c`,
`lib/node/internal_dns_utils.ts`.

## Verification

`TestE2EErrorOwnUndefinedField` matches Node. A `dns.resolve4` failure
prints the keys `code,errno,hostname,syscall`, `'errno' in err` true, as in
Node (Apple Silicon Mac).
