# ADR-02062: Strict code rejects Annex B's legacy literals

- **Date**: 2026-11-22

## Context

- These forms are Annex B's, and strict code rejects them:
  - a legacy octal escape (`"\01"`, `"\101"`, `"\08"`);
  - a non-octal-decimal escape (`"\8"`, `"\9"`);
  - a legacy octal literal (`010`);
  - a leading-zero decimal literal (`08`).
- tsc reports TS1487, TS1488, TS1121 and TS1489 for them in every
  TypeScript file. V8 throws a SyntaxError in strict JavaScript. Both lanes
  accepted them.
- Sloppy JavaScript read `010` as ten, not eight.

## Decision

- The lexer records a string's first legacy escape on its token, and the
  parser copies it onto the literal (`StringLiteral.LegacyEscape`). A
  number literal's form is read from its digits (`NumberLiteral.LegacyForm`).
- The parser's strict-region pass raises V8's SyntaxErrors:
  - in a strict program (a directive, a module);
  - in a "use strict" function;
  - in a class body.
- The checker's strict-code pass raises tsc's diagnostics, including its
  suggested `\xHH` and `0oN` forms, unless the program is sloppy
  JavaScript.
- An untagged template with such an escape is a SyntaxError in any code,
  as ES makes it (`TemplateOctalEscape`). The lexer records the escape on
  each template token, and nested templates keep their own record.
- Codegen reads a legacy octal literal in base 8.
- The `escape_sequences` example keeps strict-valid escapes only. The legacy
  forms move to `examples/jsmode/legacy_octal.js`.

## Consequences

- `TestE2ELegacyOctalStrictErrors` covers both lanes' diagnostics.
  `TestE2EStringLegacyOctalEscape` and
  `TestE2EStringNonEscapeAndNonOctalDecimal` cover the sloppy values in the
  JavaScript lane.
- A TypeScript module is strict to the parser, so it gets V8's wording
  with tsc's code. A TypeScript script gets tsc's wording from the
  checker.
- `TestE2ETemplateLegacyEscapeIsError` covers templates, nested ones
  included.
- Left: a tagged template's cooked string for such an escape is the
  decoded text, where ES makes it `undefined`; the strings array's typed
  shape has no undefined element yet.
- Verified on Node304 (Linux x86-64).
