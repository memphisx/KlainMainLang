# ADR-01708: Method values: rest parameters, explicit `this`, library receivers

- **Relations**: `Fixes ADR-01699`; `Fixes ADR-01698`
- **Date**: 2026-10-18

## Context

The full test lane showed four problems with prototype records and method values:

1. **A method that reads `arguments`.** Its implicit `arguments` rest parameter made the foreign-receiver body (ADR-01699) give up. A call through a method value with an `undefined` receiver therefore threw "called on incompatible receiver", but Node runs a class method on any receiver.
2. **Explicit `this` in the arguments object.** A function expression's explicit `this` parameter was counted as its first argument, so `arguments` gained a leading entry.
3. **Library-class receiver errors.** A library class's method value checked its receiver in the adapter, which replaced the method's own Node error (`crypto.getRandomValues.call(undefined)` must be `ERR_INVALID_THIS`).
4. **Program-unit size.** The builtin prototype adapters (ADR-01698) were emitted into the program's unit. The http2 example's unit went over its 6 MiB budget.

## Decision

1. The foreign-receiver body takes a trailing rest parameter. A copy of the remaining argument words is spread into it. The synthesized `arguments` rest is left for the function expression to make again.
2. The arguments object skips a leading `this` parameter, and the passed-argument count is reduced by one to match.
3. A library class's adapter does not check its receiver.
4. The builtin prototype adapters are program-independent (`sharedBody`). Each builtin class's adapters form a library unit of their own (`proto_<Class>`, `libOwner`).

## Verification

macOS (Apple Silicon): these tests pass:
- `TestE2EMethodArgumentsAndValuesJS`;
- `TestE2ECryptoAsValue`;
- `TestProgramUnitStaysSmall`;
- the prototype-value tests;
- the class-extends and stream-subclass tests that failed in the full lane.
