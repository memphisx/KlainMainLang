# ADR-00443: klain:webview Stage 7 — embed a SPA bundle into the executable

- **Relations**: Implements [TDD-00142](../tdd/TDD-00142.md); Extends [ADR-00437](ADR-00437.md), [ADR-00411](ADR-00411.md)
- **Date**: 2026-08-28

## Context

A served-SPA webview app read its `dist/` from disk at runtime, so it wasn't
self-contained and couldn't find its assets when launched as a `.app` bundle
(CWD `/`). Stage 7 makes a Quasar/Vite/etc. build **embed into the compiled
binary** — a true single-file desktop app — via a new `klain:assets` module and
a `new Webview({ serve: "./dist" })` one-liner. Grounded in a real experiment:
Quasar `-m spa` (~160 files/3.1 MB, one `index.html`) and SSG (~400 files/23 MB,
per-route `index.html` + `404.html`) both reduce to "serve a static dir with a
dir→`index.html` / miss→fallback rule", and both carry **binary** assets (fonts)
so the path must be byte-exact. SSR is out of scope (static output only).

## Decision

- **Compile-time embedding via `.incbin`.** The emitter records the compile-time
  string-literal directory path (`requireEmbed`, deduped); `EmbeddedBlobs()` (read
  by the driver after `EmitProgram`, like `LinkLibs()`) walks the dir and packs it
  into a self-describing blob (16-byte header, sorted 24-byte entries, string
  table, concatenated bytes; content-type derived by extension). The driver writes
  a sidecar `.bin` and a generated `.s` that `.incbin`s it under a **per-GOOS
  symbol** (`_kml_embed_N` on Mach-O, `kml_embed_N` on ELF; the IR references the
  un-underscored `@kml_embed_N`). A C byte-array was rejected — clang compiles a
  23 MB array far too slowly.
- **`klain:assets`**: `embedDir("./dist"): EmbeddedAssets` (literal path only) and
  `assets.get(path): ArrayBuffer` (`__kml_embed_get` binary-searches the manifest;
  the ArrayBuffer points straight at the static bytes, no copy — length 0 on miss).
- **The serving architecture is a minimal static HTTP server in C on a detached
  pthread** (`embedassetssrc/embed_assets.c`, libc + pthread) — *not* a TS Worker
  and *not* a webview URI-scheme handler. `__kml_embed_serve(blob)` binds
  `127.0.0.1:0`, reads the OS-assigned port via `getsockname`, spawns the accept
  loop, and **returns the port synchronously** — so `serve` desugars to embed →
  serve → `webview_navigate("http://127.0.0.1:<port>/")` with no port race, no
  reload-guard, no synthesized worker module, and no patching the vendored engine.
  The server writes raw bytes with `Content-Type`/`Content-Length` (binary-safe)
  and applies the SPA/SSG fallback (exact → dir/index.html → /index.html or
  /404.html).

## Implementation notes

- The two build drivers (`main.go`, `tools/conformance/main.go`) gain a loop over
  `EmbeddedBlobs()` parallel to `EmbeddedCSources()`; `embed_assets.c` links via
  `EmbeddedCSources` (gated on `UsesEmbeddedAssets`, with `-pthread`). The test
  build path (`appendEmbedBlobs`) mirrors both so it can't drift.
- The `serve` path is resolved relative to the compiler's CWD at emit time
  (documented); server runs on its own OS thread, independent of the GUI loop.

## Verification

- macOS (Apple Silicon M4): `embedDir` + `get` is **byte-exact** — a fixture's
  `index.html` (48 B) and a **binary** `blob.bin` (14 B) read back with the right
  lengths and a matching byte-checksum (`TestE2EEmbedGetByteExact`), miss → 0.
- `Webview({ serve })`: the in-binary server serves the embedded bytes (curl:
  `GET /` → the index.html with correct headers; SPA fallback → 200), and the
  **window renders** the embedded page — a gated windowed smoke reads the embedded
  `<title>` back through a bound probe (`TestE2EWebviewServeSmoke`). Run from a
  directory with **no `dist/`** present, proving self-containment.
- Compile-tier `TestE2EWebviewServeCompiles`; non-literal path rejected cleanly.
- `go build`/`go vet ./...` clean; webview/JSON regression green.
- Linux: compile-tier only (the `.incbin` per-GOOS ELF path is generated but a
  windowed run is not yet exercised).
