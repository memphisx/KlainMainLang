# ADR-00305: Worker threads — spawn/join + typed copy-only postMessage (manual mode)

- **Relations**: Implements [TDD-00098](../tdd/TDD-00098.md) (stages 1–3); Extended by [ADR-00306](ADR-00306.md)
- **Date**: 2026-08-23

## Context

First real OS-thread concurrency: `import { Worker } from 'worker_threads'`, `new Worker('./w.ts', { workerData })`, bidirectional `postMessage`, `.on('message'|'exit')`, cooperative `terminate()`. Everything before this ran on one thread (fibers + `fork()`). Design in [TDD-00098](../tdd/TDD-00098.md), which superseded [TDD-00047](../tdd/TDD-00047.md) after its prerequisites went stale.

## Investigation

Per the TDD's own recommendation, the four riskiest mechanisms were prototyped first as hand-written `.ll` files compiled with the exact production invocation (`clang -O2`, darwin/arm64) before any compiler change: (1) `thread_local global` isolation across two pthreads; (2) concurrent setjmp/longjmp against thread-local jump-buffer stacks (200k throws across 2 threads); (3) ucontext fibers created and swapped on non-main pthreads with the hardcoded Darwin 880/8/16/32 layout; (4) `GC_register_my_thread` + `GC_malloc` on spawned threads against Homebrew bdw-gc. All four passed — (4) is banked for the `-mm=gc` stage, not used here.

One prototype-class bug appeared only after the real conversion: `@__kml_cur_jmp_stk`'s initializer took `@__kml_jmp_stk`'s address — for a `thread_local`, that bakes in the TLS *template* address, not the per-thread one, and three E2E tests crashed (SIGSEGV/SIGBUS). Root-caused via the failing tests; fixed with a null sentinel resolved at the two consumer load sites (`__kml_push_jmpbuf`, `__kml_throw`).

A second real bug surfaced in the first end-to-end run: the worker thread set its own `exited` flag before writing the exit envelope, so the parent's keepalive could see the child gone and exit the process before the `'exit'` event was ever dispatched. Fixed by making the exited flag parent-written only (set when the exit envelope is processed).

## Decision

- **Worker file = extra entry in the same binary.** The parser records `new Worker('<literal>')` paths; the resolver visits each as a dependency edge, keeps the worker file's var/executable statements as `Program.WorkerModules` (functions/classes/interfaces/types/enums hoist into the shared body), and rejects: non-literal paths, a worker file that is also imported, the entry file as a worker, and nested workers. Codegen emits each module into `define void @__kml_worker_entry_<i>()` via the same builder-swap seam closures use — *before* main, so the channel types it records gate every parent-side use.
- **Per-thread runtime state via `thread_local global`** — ~50 runtime singletons converted (exceptions, tasks, microtasks, timers, conn/listen, curl multi, request-body pumps, EventSource/WebSocket tables, sort scratch, signal flags, console counters, RNG seed, generator handoff). Same `@name`s, so zero call-site changes. Kept shared deliberately: module globals/argv (documented as unsynchronized), `@__kml_curl_inited` (init-once), `@__kml_cluster_worker_id`, gc stackbottom snapshot.
- **Channel = pipes carrying envelope pointers.** Per worker, a 112-byte control block with two pipes; `postMessage` deep-clones the payload (`emitDeepClone`, ADR-00113 machinery), flattens it to two i64 words, mallocs a `{kind, w0, w1}` envelope and `write()`s its pointer — atomic for 8 bytes per POSIX, so no mutex exists anywhere. Kinds: 0 message, 1 exit, 2 terminate. Both threads run the unified event loop (all its state now TLS) with three stub-backed hooks added to `@__kml_event_loop_run`: `__kml_worker_fdset_add` (pipe fds into the select set), `__kml_worker_dispatch` (drain + dispatch after select), `__kml_worker_keepalive` (parent: any un-exited child; worker: message listener registered && no terminate). Listener dispatch goes through per-call-site synthesized adapter shims (`void(ptr userClosure, i64 w0, i64 w1)`) that decode the envelope back into the typed payload.
- **Typing: worker declares, parent is checked.** One message type per direction: inbound from the (required) annotation on `parentPort.on('message', (msg: T) => …)`, workerData from a (required) annotated `const cfg: T = workerData`, outbound inferred from the worker's first `parentPort.postMessage`. Payload restrictions are exactly `structuredCloneUnsupportedKind`'s set.
- **Mode/interaction guards**: `-mm=gc` + Worker is a clean compile error (next stage); `http.listen({workers:N})` fork-clustering + Worker threads rejected (fork in a threaded process is hazardous). `__kml_worker_spawn` runs `curl_global_init` (once) before the first `pthread_create`, since that call is not thread-safe. Worker threads block all signals — signal handling stays on the main thread. `-pthread` added to the clang invocation when workers are used (the project's first pthread dependency).

## Implementation notes

- `ast/nodes.go` (`NewWorkerExpression`, `Program.WorkerPaths/WorkerModules`), `parser/parser.go` + `parser/parser_literals.go` (`parseNewWorkerBody`), `resolver/resolver.go` (worker dependency edges, conflict checks, `splitWorkerBody`), `resolver/virtual_modules.go` + `resolver/rename.go` (`worker_threads` import gating; members bind as identity, path canonicalization in the rename walk).
- `codegen/llvm/runtime_worker.go` (new: control block, spawn/trampoline/post/drain/hooks), `codegen/llvm/emit_worker.go` (new: entry emission, channel typing, encode/decode, adapters, method dispatch), `emit_call.go`/`emit_exprs*.go`/`types.go`/`emitter.go` dispatch + `WorkerType` + Pass 2d wiring, `runtime_http.go` loop hooks, `runtime_task.go` stubs, `main.go` `-pthread`.
- The TLS conversion is declaration-site-only across ~15 `runtime_*.go`/`emit_*.go` files; the whole pre-existing E2E suite passed unchanged after it (single-threaded behavior is unaffected by TLS on one thread).
- LLVM traps worth remembering: a function parameter named `%entry` collides with the `entry:` block label; a block label named `store` is rejected — both hit and renamed.

## Side effects discovered

- A worker module's *named* functions can't read the worker's top-level bindings (they are entry-function locals — the pre-[TDD-00093](../tdd/TDD-00093.md) situation, scoped to worker modules); arrow closures capture them fine. Tracked as a caveat on [CONCURRENCY-WORKERS.md](../status/CONCURRENCY-WORKERS.md).
- String payloads inside cloned messages share their underlying buffer between threads (safe under both allocators — strings are never mutated in place — but not isolation in the strictest sense). Caveat on the status page.
- Worker programs always link libcurl: the worker drive is the unified event loop, which pulls the async-fetch machinery unconditionally (same pre-existing behavior `http.listen`/async programs have).

## Verification

darwin/arm64 (Apple Silicon), `clang -O2`: 10 new E2E tests in `tests/worker_test.go` — echo round-trip with workerData + `'exit'` event, two concurrent workers each catching 20k thrown exceptions (the TLS regression test; also run manually at 100k×2 under ASan+UBSan, clean), object-with-array payloads, setTimeout inside a worker, and six compile-rejection cases (function payload, gc mode, worker-also-imported, nested worker, unannotated handler, parentPort outside a worker). Top-level `await` inside a worker module verified working manually. Full `go test ./...`, `go vet`, and `make examples` pass; new `examples/workers/parallel_sum.ts` (+ `sum_worker.ts`; the examples Makefile now skips `*_worker.ts` as standalone entries). `--static` + `-pthread` is Linux-only — pending re-verification next Linux session.
