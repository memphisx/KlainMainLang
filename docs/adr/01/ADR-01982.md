# ADR-01982: Void async returns and array-instance intersections

- **Relations**: Implements TDD-00230 (P2.7); follows [ADR-01981](ADR-01981.md)
- **Date**: 2026-11-07

## Context

Two bugs found while probing union members:

- `return <expr>` in an async function whose promise holds `void` stored
  nothing and skipped the expression. `async () => console.log(await p)`
  is such a return, so the call never ran and nothing printed.
- `Array.isArray(s)` narrows a `Set<number>` to `Set<number> & any[]`.
  Merging the two member lists gave up on a member both declare with
  unrelated function types (`forEach`, `keys`, …). The whole intersection
  was left without a type, and codegen stopped with "no type for
  MemberExpression".

## Decision

- The async return path evaluates the expression of a `void` return for
  its effects before settling.
- Two function-typed members of one name merge into their intersection,
  both signatures as overloads in order, as tsc does.

## Consequences

- Covered by `TestE2EAsyncVoidReturnRunsExpression` and
  `TestE2EArrayIsArrayIntersectionMembers`, both matching Node.
