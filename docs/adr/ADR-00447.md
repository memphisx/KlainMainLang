# ADR-00447: constructor parameter properties

- **Date**: 2026-08-29

## Context

The TS acceptance oracle's `expected IDENT, got public` bucket (75 cases,
plus `private`/`protected` variants further down the histogram) is
TypeScript's constructor *parameter properties* —
`constructor(public x: number, readonly id: number)` declaring and assigning
same-named fields. Beyond the oracle, this is an everyday TS idiom worth
having for its own sake.

## Investigation

Sampled cases (`ClassAndModuleThatMergeWithStaticFunctionAndNonExportedFunctionThatShareAName`
et al.) confirm the shape. TS semantics: each modified constructor parameter
declares a class field of the same name/type and assigns
`this.x = x` at the top of the constructor body (before user statements).
The existing pipeline already has everything needed — declared fields
(`ast.AnnotField` with visibility), and constructor body statements — so a
pure parse-time desugar keeps codegen untouched.

## Decision

- `ast.Param` gains `PropVisibility` ("public"/"private"/"protected"; ""
  when absent) and `PropReadonly`; `IsPropertyParam()` reports either.
- `parseParamList` accepts the modifiers before a plain parameter name.
  `readonly` stays contextual — it is a modifier only when another IDENT
  follows, so a parameter literally named `readonly` keeps working. The
  modifiers are gated by a parser flag set only for a constructor's own
  parameter list (captured-and-cleared at `parseParamList` entry so nested
  arrow/function-expression parameter lists inside the constructor never
  inherit it); anywhere else they are a clean parse error.
- `parseClassDecl` desugars: each property parameter appends an
  `AnnotField` (public maps to the default "" visibility; an unannotated
  parameter mirrors the untyped-parameter `number` default, or infers from
  its default-value expression) and prepends `this.x = x` to the
  constructor body. Rest/destructured property parameters are rejected,
  matching TS.
- `readonly` is recorded but not enforced as immutability — the field
  behaves like any declared field (disclosed as a status caveat).

## Implementation notes

`ast/nodes.go` (Param fields + helper), `parser/parser.go` (`inCtorParams`
flag), `parser/parser_stmts.go` (modifier parse in `parseParamList`),
`parser/parser_classes.go` (desugar in the constructor branch). Codegen
unchanged — it sees ordinary fields and ordinary assignments.

## Side effects discovered

None. The oracle's false-accept count rose 562 → 578 (cases whose only
TS error involves rules this compiler doesn't model, e.g. readonly-write
checks, now compile clean) — disclosed in the report's false-accept table.

## Verification

Mac. `tests/overloads_test.go` additions (positive E2E incl. private/readonly,
outside-constructor rejection, private-access enforcement) and
`examples/language/parameter_properties.ts` pass; parser + class E2E batches
green. TS oracle: **54.1% → 54.2%** (match-accept 1191 → 1213). Node oracle
unchanged (37 passed).
