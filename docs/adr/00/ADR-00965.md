# ADR-00965: Nullable string/object boxed into `any` compares `=== null`

- **Relations**: Extends ADR-00958
- **Date**: 2026-09-15

## Context

BACKLOG §3 (TDD-00155 any-equality residue) left two cases where a nullable
value, once boxed into an `any` slot, failed `=== null` at runtime even when it
was null:

- `URLSearchParams.get(missing)` (type `string | null`) — a miss `!== null`.
- A null-valued nullable *object* (`C | null` holding `null`) — `!== null`.

Repro (both printed the wrong result before this change):

```ts
const p = new URLSearchParams("a=1")
const v: any = p.get("missing")
console.log(v === null)          // was false, want true
class C { x: number = 1 }
let o: C | null = null
const w: any = o
console.log(w === null)          // was false, want true
```

## Investigation

ADR-00958 already taught `emitBoxValue`'s bare-pointer arm
(`emit_dynamic.go:442`) to encode a null `string | null` pointer as the `nbNull`
sentinel when `v.Ty.Nullable` — but only when that arm is reached with the flag
set. Both residual cases sidestepped it:

- `URLSearchParams.get` returned `Value{Ty: TypePtr}` with `Nullable` unset
  (`emit_usp.go`), so the boxer took the plain-string path and encoded the null
  pointer as a string-tagged 0 payload — `=== null` (compared against `nbNull`)
  read false.
- A nullable object is `IsObject`, caught by the earlier `case v.Ty.IsObject`
  arm (`emit_dynamic.go:438`), which tagged the pointer `kmlTagObject`
  unconditionally — a null object pointer became an object-tagged 0, never
  `nbNull`.

## Decision

Two one-spot fixes, both reusing the existing null-pointer→`nbNull` shape:

1. `URLSearchParams.get` returns a `TypePtr` with `Nullable = true`, so the
   established nullable-ptr arm encodes a miss as `nbNull`.
2. `emitBoxValue`'s `IsObject` arm, when `v.Ty.Nullable`, `icmp eq ptr null` on
   the payload and `select`s `nbNull` over the object-tagged box — mirroring the
   string-ptr arm below it.

`typeof null` stays `"object"` (unchanged — the `typeof` path is separate), and
a null miss remains distinct from `undefined`.

## Implementation notes

- `Type` is a value struct, so `nt := TypePtr; nt.Nullable = true` is a safe
  local copy.
- `emitNbTagPtr` on a possibly-null pointer is pure tag arithmetic (no deref),
  so tagging first and `select`ing `nbNull` when null is safe.

## Side effects discovered

None. A present `get` value stays a normal string box; a non-null object stays
object-tagged with `typeof === "object"`.

## Verification

- `TestE2EAnyNullableBoxedEqNull` (new) covers both fixes plus the present-value
  and non-null-object non-regressions and the null≠undefined distinction.
- Related suites (`URLSearchParams|USP|URL|Any|Dynamic|Nullable|Box`) green.
- `go build` / `go vet` clean. macOS arm64 (M4).
