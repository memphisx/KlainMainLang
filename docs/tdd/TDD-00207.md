# TDD-00207: Promise rejection reasons carry the real thrown value

- **Status**: Implemented
- **Date**: 2026-09-12

## Context

A rejected promise dropped or corrupted its reason for every non-Error value:

- `Promise.reject("x").then(_, e => …)` — the handler fired but `e` was empty
  (the string was wrapped into a synthetic `Error{message:"x"}` whose pointer the
  handler, treating its argument as a raw value, could not read as `"x"`).
- `new Promise((_, rej) => rej(42)).then(…)` — invalid IR (`double` stored where a
  `ptr` reject argument was expected): the reject callback param was typed
  `errorObjType` (a pointer), so a numeric reason had nowhere to go.
- Any `async` function that `throw`s a non-Error, or `await`s a rejected promise,
  settled its promise with an `Error` wrapper rather than the real value.

Node rejects with the value *itself* — `Promise.reject("x")` rejects with the
string `"x"`, `rej(42)` with the number `42`, `Promise.reject(new Error("m"))`
with that Error (so `.catch(e => e.message)` works). The old model only ever
represented a single ptr-shaped reason and assumed it was an `Error`.

A rejection is the async twin of a `throw`: `throw v` inside an `async` body is
observably identical to `Promise.reject(v)`. TDD-00202 already solved "hold an
arbitrary thrown value" for `try/catch` with the **caught-value record**
(`{ i8 tag, i64 payload }`, `TypeCaught`), with full typeof / instanceof / member
/ toString / console support. Rejection reasons should ride the same channel.

## Design

**A rejection reason is a caught value.** The task-promise struct
(`{ i64 state, ptr waiter, i64 v0, i64 v1, ptr reactions }`) already has a spare
slot on the rejected path: `v1` is only used by *fulfilled* two-slot values, never
by a rejection. So store the reason with **no struct growth**:

- `v0` (slot 2) = payload (the caught record's `i64` payload)
- `v1` (slot 3) = tag (the caught record's `i8`, widened to `i64`)

Reused, single source of truth:

- `emitValueToCaughtParts(val) → (tag, pay)` — factored from `emitThrow`: a caught
  value passes its parts through; an `Error`/`class X extends Error` yields
  `tag = kmlTagError(13)`, `pay = ptrtoint errptr`; anything else boxes to a
  NaN-box `any` and splits via `emitUnboxTagPayload`. The value→`TypeCaught`
  coercion (`emit_exprs_coerce.go`) is upgraded to route through this helper too,
  so a reassigned catch var (`catch(e){ e = someError }`) now keeps its Error-ness.
- `storeRejectReason(prom, tag, pay)` / `loadRejectReasonCaught(prom) → Value`
  (`TypeCaught`) — the only readers/writers of the v0+v1 rejection encoding.

**Callback ABI.** The `.then(onF, onR)` / `.catch(onR)` reject handler and the
`new Promise` executor's `reject` parameter are typed `TypeCaught` (was
`errorObjType`). `TypeCaught` is a `{ i8, i64 }` aggregate passed by value exactly
as array `{ptr,i64}` aggregates already are. So `e`, `e.message`, `typeof e`,
`String(e)`, `console.log(e)`, `e instanceof Error` all resolve through the
existing `emit_caught.go` machinery, for every reason type.

**Sites (all routed through the two helpers or `__kml_throw_any`):**

| Site | Change |
|---|---|
| `emitPromiseReject` (`Promise.reject`) | derive parts, store v0+v1, settle rejected |
| `emitRejectThunk` (`new Promise` `rej`) | param `{i8,i64}`; store v0+v1 |
| async catch-and-settle (`emit_async.go`) | store `get_thrown_tag/pay` into v1/v0 |
| then-runner `rCall` | load v0+v1, pass `{i8,i64}` to onR |
| then-runner `propReject` (no onR) | copy v1 as well as v0 to Q |
| await-rethrow of a rejected promise | rethrow via `__kml_throw_any(tag, pay)` |
| thenable adoption (`emit_promise_new.go`) | copy v1 alongside v0 |
| `allSettled` reason | reconstruct caught → string |

Reject param hint flips `errorObjType → TypeCaught` in `emitRejectCallback` and in
`new Promise`'s `rejectTy`; both `inferExprType` mirrors must agree (the two-site
gotcha).

## Open questions

  `errorObjType` ptr — faithful only for Error/string-ptr reasons. A numeric

  (rare; its own follow-up), not addressed here.
