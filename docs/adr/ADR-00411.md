# ADR-00411: child_process spawnSync/execSync/execFileSync (embedded C core)

- **Relations**: Extends [ADR-00322](ADR-00322.md) (async child_process); Extends ADR-00409
- **Date**: 2026-08-27

## Context

The Node oracle's largest non-module compile bucket after the createServer
work was `built-in module 'child_process' has no exported member 'spawnSync'`
(~43 files) plus `execFileSync` (~7) — and the blocking spawn family is a
staple of exactly the CLI-tool use case this project targets. Only the
bespoke `process.execFileSync` existed.

## Investigation

The async child_process runtime (`runtime_childprocess.go`) is event-loop
IR — reusing it for a blocking call would mean pumping the loop from a
synchronous position. The embedded-C mechanism (`embedded_c.go`, used by
dtoa/bufcodecs/urlpattern/…) is a far better fit: the whole feature is one
self-contained POSIX routine, and the string ABI is trivial to reproduce
from C (length-prefixed `[i64 len][bytes][NUL]`, value ptr = base+8 —
runtime_strheader.go).

## Decision

One C core, `__kml_cp_spawn_sync(file, argv, argc)` (`runtime_spawnsync.go`,
linked via `EmbeddedCSources` when used): pipe stdout+stderr, fork, child
dup2 + execvp (`_exit(127)` on exec failure, Node's convention), parent
poll-multiplexes both pipes to EOF (so a child filling stderr while stdout
drains can't deadlock), then blocking waitpid. Result struct: `{ i64 status;
ptr stdout; ptr stderr; i64 pid }`, status folding a signal death to
`128+signal` and a spawn failure to `-1`.

Three emitters over it (`emit_childprocess.go`):

- `spawnSync(command, args?)` → `{ status, stdout, stderr, pid }` object
  (strings — the `encoding: 'utf8'` shape; no Buffer default).
- `execSync(command)` → stdout string, command via `/bin/sh -c`.
- `execFileSync(file, args?)` → stdout string, no shell.
- The options object supports `{ cwd }` (child `chdir` before exec) and
  `encoding: 'utf8'` (validated literal — results are already utf8 strings);
  every other key is a clean rejection naming the limitation. Documented
  divergence: `execSync`/`execFileSync` do **not** throw on a nonzero exit
  status (Node throws) — recorded as a status caveat, `spawnSync().status`
  is the escape hatch.

## Implementation notes

- `emitter.go` (`usedSpawnSync`), `embedded_c.go`, `runtime_spawnsync.go`,
  `emit_childprocess.go`, `emit_exprs_types.go` (result typing),
  `resolver/virtual_modules.go` (named exports), and
  `tests/compiler_test.go` (`appendSpawnSync`, mirroring the other embedded-C
  append helpers).
- **Pre-existing runner bug found and fixed here**: the Node oracle's
  `compileAndRun` never linked `EmbeddedCSources` at all (only `-l` libs), so
  every Node test whose program needed dtoa/bufcodecs/… died as a bogus
  CLANG_ERROR. `frontEnd` now returns the C sources and the clang invocation
  includes them — CLANG_ERROR fails dropped and two additional files pass.

## Verification

- New E2E tests: `TestE2EChildProcessSpawnSync`,
  `TestE2EChildProcessExecSyncAndExecFileSync`,
  `TestE2EChildProcessSpawnSyncLargeInterleavedOutput` (3000 lines on both
  pipes — the deadlock stress) — all pass; full child_process suite green
  (Mac).
- New example `examples/process/spawn_sync.ts` compiled and run.
- Node oracle re-run: 27 → 29 passing.
