# ADR-01323: The library's names and type ids are the same in every program

- **Relations**: Implements TDD-00238 (Stages 0–2), Amends TDD-00041
- **Date**: 2026-10-01

## Context

[TDD-00238](../tdd/TDD-00238.md) compiles the builtin library once and
links it. Before any library code can live in a separately compiled
object, two things it emits must stop depending on the program:

- **Its symbol names.** A library file's top-level names were
  `name__kml_modN`, with N the file's place in this program's import walk
  (`resolver.go`). `stream.ts` was `mod3` in one program and `mod11` in
  another.
- **Its type ids.** The object header's id came from one counter per
  program (`allocTypeID`), in emission order. This applied to classes,
  generic instantiations, object layouts, host boxes and error
  subclasses.

The CLI also compiled every embedded C runtime file with each program.
The test and conformance runners already cached them as objects
(`CSource.CachedObject`); the CLI did not.

Seven places stripped the `__kml_modN` suffix by hand, in four packages.
One of them only recognised a suffix made of digits.

## Decision

1. **Stage 0: the CLI's object cache.** `main.go` compiles each embedded
   C runtime file through `CachedObject`, into the user cache directory's
   `klainmain/cobj`. It is skipped for cross-target builds, for
   `-no-cache`, and for members the cache refuses (the C++ and moc ones).
   `-cache-dir` moves the cache.
2. **Stage 1: library names.** `ast.ModuleMangle` gives a builtin library
   file's names a suffix built from the file's path under the library
   root, length-prefixed: `URL__kml_modL12node_kml_url`. The length lets
   text that codegen appends after the suffix (`_static_parse`) stay
   distinct from it. A program's own files keep `__kml_modN`. All of the
   stripping goes through four helpers:
   - `ast.Unmangle`;
   - `ast.UnmangleText`, for messages;
   - `ast.TrimModuleSuffix`, for the checker's exact-suffix form;
   - `ast.IsLibraryName`.

   Codegen already reached library symbols only through `LibExports`, so
   no codegen lookup changed.
3. **Stage 2: two id ranges.**
   - Ids below `kmlStableIDBase` (2^31) are numbered per program, as
     before. These are user classes, and any generic instantiation over a
     user type.
   - Ids from `kmlStableIDBase` up are an FNV-1a hash of a key that is the
     same in every program:
     - a library class: `C` plus its mangled name;
     - a library error class's kind: `E` plus its mangled name;
     - an object layout: `L` plus its layout key;
     - a host layout: `H` plus its host key.
   - Two keys hashing to one id is an internal compile error, not a
     probe. A probed id would depend on what else the program holds.
   - The shape table is sorted by id and searched, not indexed, so sparse
     ids need no change there.

## Consequences

- Stage 0 saves about 0.1 s a build on macOS. The program's own IR
  dominates: an `fs` program takes 8.6 s with or without the cache. A
  build also no longer writes a `.c` file per runtime member next to the
  source.
- A library generic instantiation over library types only (a
  `Map<string, Socket>` inside `net`) gets a stable id too: its mangled
  name contains no program file's suffix.
- An error message's mangled names now always read as written. Two
  messages had shown `B__kml_mod0` (the generic-class inference error and
  the generic-function inference error).

## Verification

- `ast` unit tests cover the mangling helpers.
- The resolver, sema and ast packages pass.
- On macOS (Apple Silicon), the E2E sets for namespaces, `@pure`,
  dynamic import, generics, errors, inspect and host boxes pass.
- The full suite runs on Linux x86-64 (Node304).
