# ADR-01051: A parked coroutine does not hold the event loop open

- **Relations**: `Extends ADR-01050`; `Implements TDD-00084` (Part B, corrected)
- **Date**: 2026-09-21

## Context

Found while building the unsettled-top-level-await path of [TDD-00224](../tdd/TDD-00224.md), which needs the loop to
*return* when nothing alive can settle the module promise.

```ts
async function f(): Promise<void> {
  console.log("in");
  await new Promise<void>(() => {});
  console.log("never");
}
f();
process.on("exit", (c) => console.log("exit", c));
console.log("sync-end");
```

Node: `in`, `sync-end`, `exit 0`. This compiler: `in`, `sync-end`, then a hang — the process never exited.

## Investigation

`@__kml_event_loop_run` (`runtime_http.go`) folded `@__kml_task_active > 0` into its keep-alive condition (TDD-00084
Part B: "an active coroutine task keeps the loop alive"). `@__kml_task_active` counts every task that has not
finished, including one parked on a reaction (state 3) that nothing will ever run. With no fd and no timer the loop
then blocked in `select()` with no timeout.

A pending promise keeps nothing alive in Node. What can settle it — a timer, a socket, a child, a transfer, a worker,
the thread pool — is a loop source with its own keep-alive term, all already present in that condition.

## Decision

The term becomes `@__kml_task_holds_loop()`: a task holds the loop when it can run right now
(`@__kml_task_resumable()`, which already existed for the loop's "never block while work is ready" check), or when it
is parked on a fetch or a fetch group (state 1 with `pendingFetch`/`pendingGroup` set). A task parked on a promise —
state 3, or state 1 with only `pendingProm` — holds nothing.

The fetch exception is not optional. The first cut used `@__kml_task_resumable()` alone, on the reasoning that
libcurl's in-flight count already holds the loop for a transfer; `TestE2EPromiseCombinatorsOverTasks` then exited
before printing anything: a task parks on its fetch before the transfer has reached `curl_multi`, so at the loop's
first keep-alive check the in-flight count is still 0.

## Implementation notes

`codegen/llvm/runtime_http.go` (one term), `codegen/llvm/runtime_task.go` (`@__kml_task_holds_loop` + its no-op stub
for a loop program without the task runtime). `@__kml_task_run_all` still loops on `@__kml_task_active`; it is unreachable
from `main()` since TDD-00223 (every task program ends in the full loop).

## Verification

Windows 11 x64: the repro matches Node; `TestE2EParkedTaskDoesNotHoldTheLoop`. Broader runs: see the session's final
pass.
