# ADR-01880: A generator expression's own name, read after its binding's rewrite

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's Identifier bucket)
- **Date**: 2026-10-21

## Context

- A top-level `let ref = async function* BindingIdentifier() { … return BindingIdentifier; }` becomes a generator declaration named after its binding, its own name in its body renamed to it (rewriteTopLevelGeneratorExpressions, renameGeneratorSelfName). The renamed reference still resolves, in the binder, to the function expression's own name, so the shadow oracle's rule for a generator function read as a value did not apply, and the checker's function type maps to no representation: the read was unanswered.

## Decision

- The oracle's generator-value rule also applies to a function expression's own-name symbol of a generator, asking codegen's registered generator by the reference's current name (unanswered when none is registered).

## Consequences

- The Test262 `named-*-reassign-fn-name-in-body*` async generator files leave the shadow report; generator E2E tests pass.
- Verified on Apple Silicon.
