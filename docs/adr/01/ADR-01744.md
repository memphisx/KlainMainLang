# ADR-01744: push grows an array geometrically

- **Relations**: `Implements TDD-00230`, Extends [ADR-00517](../00/ADR-00517.md)
- **Date**: 2026-10-19

## Context

`push` reallocated the array's data to exactly `len + n` elements on every call, the amortized growth ADR-00517 deferred. With the system allocator that is mostly cheap, because realloc usually grows a block in place. ASan's allocator never does: every push copied the whole array. The sanitizer lane (TDD-00230 P0.3) hung for 45 minutes on `TestE2EProcessMemoryUsageRssPositive`, which pushes a million numbers. Any allocator without in-place growth makes n pushes cost O(n²).

## Investigation

- A capacity word in the array header was tried first. A header is written by IR emitters and four C runtimes, and the data pointer is replaced by every resizing mutator. A capacity guarded by "its data word still equals the data pointer" is not safe: a writer that frees the old buffer and stores one that malloc hands back at the same address, smaller, would validate the stale capacity. Every data store would have to clear it.
- The allocator already knows each block's real size: `malloc_size` on macOS, `malloc_usable_size` on glibc and musl, `_msize` on Windows, and `GC_size` under Boehm. That answer stays correct whoever wrote the pointer and however the block was obtained.

## Decision

- `push` (`emitArrayReserve`) asks `__kml_heap_usable` how many bytes the data block holds. When the new length fits, it stores into the block as it is. Otherwise it reallocates to twice the length, at least the new length and at least 4 elements.
- `__kml_heap_usable` is a weak function in `coresrc/core.c` that calls the platform's usable-size query. Under `-mm=gc` the shim's strong definition answers `GC_size` for a collector object. For a bump-allocated or foreign block it answers 0, so that block is reallocated.
- The array header layout does not change. The other resizing mutators still reallocate to their exact size, so a block is never left smaller than it says.

## Consequences

- One million pushes take 12 seconds under ASan instead of over 45 minutes. Without ASan the program also no longer reallocates on most pushes.
- The data block can hold up to twice the array's elements, as an engine's backing store does.
- `unshift`, `splice` and index assignment past the end still reallocate exactly. That is a perf follow-up, not a semantic one.
