# ADR-01190: `new Response`, its statics, `statusText`/`type`, and a HeadersInit as a record or pairs

- **Relations**: `Extends ADR-00490`, `Extends ADR-00130`
- **Date**: 2026-09-28

## Context

Only `fetch` could make a Response: `new Response("hi")` was "unknown class
'Response'", and `Response.json`/`redirect`/`error` did not exist. A fetched
Response had no `statusText` or `type`. `new Headers(init)` and the
`headers` of fetch's and Request's init took only a `Map`/`Headers`, not
the record (`{ "Content-Type": "…" }`) or `[name, value]` pairs the Fetch
standard's HeadersInit allows — the most common way code writes them. An
untyped `await res.json()` was typed as a string, so `data.x` failed to
compile. `Object.keys`/`JSON.stringify` of a Response listed its internal
fields; Node's Response has no own properties.

## Investigation

- A Response without a fetch handle already reads its buffered body for
  `text()`/`json()`/`arrayBuffer()`; a constructed one needs its own
  headers, statusText and type slots.
- Node (undici): a string body implies `text/plain;charset=UTF-8`, a Blob
  its own type, URLSearchParams `application/x-www-form-urlencoded;charset=UTF-8`;
  a status outside 200–599 is `RangeError: init["status"] must be in the
  range of 200 to 599, inclusive.`; a body with a null-body status is
  `TypeError: Response constructor: Invalid response status code 204`;
  `Response.redirect` accepts 301/302/303/307/308 (`RangeError: Invalid
  status code 200` otherwise) and serializes the URL into Location;
  `Response.error()` is status 0, type `"error"`; a fetched Response's
  `statusText` is the server's reason phrase and its `type` `"basic"`.

## Decision

- `new Response(body?, init?)`: the body normalised through a Blob (a
  string, typed array, ArrayBuffer or Blob) into the buffered-body fields,
  or URLSearchParams through `toString()`; init's `status`, `statusText`
  and `headers`; the implied content type unless the headers set one; both
  errors as Node raises them.
- `Response.json(data, init?)` (`application/json`), `Response.redirect(url,
  status = 302)` and `Response.error()` share the constructor's core.
- The Response layout gains `__kml_headers`, `__kml_status_text` and
  `__kml_type`, null on a fetched one (allocated zeroed): `.headers`,
  `.statusText` and `.type` read the constructed values, else the captured
  header map, the reason phrase of the last status line
  (`__kml_fetch_status_text`) and `"basic"`.
- `headersFromInit`: a HeadersInit as a Headers/Map (copied), a record of
  strings, or `[name, value]` pairs (appended); used by `new Headers`, and
  the `headers` of fetch's, Request's and Response's init.
- `res.json()` without a target is `Promise<any>`, as bare `JSON.parse` is
  `any`.
- A Response enumerates no own properties.

## Side effects discovered

- A ReadableStream body is not supported, and `.body` of a Response with no
  body is an empty stream rather than `null` (BACKLOG).
- An unhandled promise rejection is dropped silently where Node reports it
  and exits 1 — a failing `await fetch` inside an async callback looked like
  a hang (ADR-01192).
