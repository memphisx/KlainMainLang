# ADR-00425: child_process.fork — self-fork with a NODE_CHANNEL_FD IPC channel

- **Relations**: Implements [TDD-00141](../tdd/TDD-00141.md); Extends [ADR-00423](ADR-00423.md), [ADR-00412](ADR-00412.md)
- **Date**: 2026-08-28

## Context

The biggest single member gap in the Node oracle (26 files on the
missing export, `cluster` messaging behind the same mechanism). The
corpus's dominant shape is self-fork — `fork(__filename)` /
`fork(process.argv[1])` — with the child branching on
`if (process.send)` or `process.argv[2]`.

## Investigation

TDD-00141 settles the design: copy Node's own mechanism (fork+exec with
an inherited socket named by `NODE_CHANNEL_FD`), which is what makes the
child-detection idioms behave verbatim. Key findings during
implementation, beyond the TDD:

- Node's forked-child argv layout is `[exe, modulePath, ...args]` —
  extra args land at `argv[2]`. Getting this wrong (args at `argv[1]`)
  made the `process.argv[2] === 'child'` branch miss in the child and
  **fork-bomb** — the child re-forked forever. The self-fork fills the
  modulePath slot with the binary path again.
- `process.argv[2]` on a 2-element argv hit the general array bounds
  throw; Node yields `undefined`. `process.argv[i]` out-of-range now
  yields `""` (string-typed and falsy — both the `=== 'child'` and
  `if (!argv[2])` idioms behave; a disclosed deviation from `undefined`).
- `mustCall`-wrapped `'message'` listeners need the ADR-00412/00422
  contextual-typing pre-pass (`contextTypeArrowParams(arg, "string")`),
  or the untyped param defaulted to number and stringified as NaN.

## Decision

Per TDD-00141: `fork(<self>, args?, {}?)` where `<self>` is the AST
shape `__filename` or `process.argv[1]` (anything else names the
limitation); `socketpair` + `fork(2)`; the child `setenv`s
`NODE_CHANNEL_FD` and `execv`s `argv[0]`. Wire format is one JSON
string per line (Node's `json` mode), implemented in a self-contained
embedded C (`ipcsrc/ipc.c`: quote/unquote incl. `\uXXXX` + surrogate
pairs, line buffering) linked only when fork/IPC is used.

- Parent: the ChildProcess handle grows `ipcFd`/`'message'` slot/channel
  fields (struct grows 136→160 bytes); the IPC fd joins the existing
  select() set; `'message'` fires per decoded line; `.send(str)→bool`,
  `.disconnect()`; stdio is inherited (fds -1 — no pipes), and finalize/
  force-timeout conditions treat an open channel as live work.
- Child: `process.send(str)→bool` (false when unforked),
  `process.on('message', cb)` (arms the channel, holds the event loop
  open while connected — new `__kml_ipcc_*` loop hooks with no-op stubs
  when unused), `process.disconnect()`; bare `process.send` reads as a
  boolean forked-ness probe (Node's value is function-or-undefined; the
  truthiness use is what the corpus exercises).

## Implementation notes

- `codegen/llvm/ipcsrc/ipc.c` + `ipc.go` (embedded source, `UsesIPC`).
- `codegen/llvm/runtime_ipc.go`: `__kml_cp_fork` / `__kml_cp_ipc_drain`
  / `__kml_cp_send` / `__kml_cp_disconnect` + the child-side
  `__kml_ipcc_*`; stubs via `emitCPRuntimeStubs` (a no-op
  `__kml_cp_ipc_drain` for plain-spawn programs).
- `codegen/llvm/runtime_childprocess.go`: struct fields 17–19; dispatch/
  fdset/finalize conditions.
- `codegen/llvm/runtime_http.go`: the three `__kml_ipcc_*` loop hook
  sites; `emitter.go`: `useFullLoop` includes the child channel.
- `codegen/llvm/emit_childprocess.go` / `emit_process.go` /
  `emit_call.go` / `emit_exprs_member.go` / `emit_exprs_types.go`:
  surface + inference (`send` → bool both sides, argv clamp).
- `tests/compiler_test.go`: `appendSpawnSync` also links the IPC C.

## Side effects discovered

- `process.argv[i]` out-of-range reads are now `""` everywhere, not just
  in fork programs — disclosed on PROCESS-CLI.md.
