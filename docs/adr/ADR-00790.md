# ADR-00790: os.homedir() passwd-database fallback on POSIX

- **Relations**: `Implements TDD-00024`, `Extends ADR-00090`
- **Date**: 2026-09-08

## Context

`os.homedir()` read `getenv("HOME")` and threw a catchable Error whenever it
was unset. Real Node does not: its libuv `uv_os_homedir` treats a *set* HOME
(even an empty one) as authoritative, but on an *unset* HOME it falls back to
the passwd database — `getpwuid(getuid())->pw_dir` — and throws only if that
lookup also fails. So a program run under a login that never exported HOME (a
bare cron/systemd unit, many container entrypoints) got a thrown exception
here where Node returns a real home directory. This was the last open POSIX
caveat on the `os` module.

## Investigation

- `codegen/llvm/emit_os.go:emitOSHomedir` — the single-path `getenv → throw`
  shape, shared across platforms via a `homeVar` switch.
- Node oracle: `HOME=/x node -e "os.homedir()"` → `/x`; `HOME= node …` → `""`
  (empty, *not* the passwd home); `env -u HOME node …` → the passwd home.
  Confirms the three-way rule — set / empty-still-set / unset — and that empty
  HOME must **not** route to passwd (an early draft did, and diverged).
- The `struct passwd` layout differs between Darwin and glibc, so reading
  `pw_dir` from IR by offset is a struct-layout hazard. The project's standing
  answer (termios shim ADR, `os.tmpdir()` Windows shim ADR-00739) is a tiny C
  shim compiled against the platform's own headers — reused here.

## Decision

Split `emitOSHomedir` by platform. Windows is unchanged (`USERPROFILE`, throw
if unset). POSIX now:

1. `getenv("HOME")` via `emitGetenvCall` (wraps into a length-prefixed header
   string; `""` stays `""`, unset stays `null`).
2. If non-null, use it directly — an empty HOME returns `""`, matching Node.
3. If null, call the new `__kml_os_homedir_pw()` shim; if it returns a path,
   wrap and return it; if it returns `NULL`, throw the same catchable Error as
   before.

The shim (`OSHomedirPwSource`, gated by `usedOSHomedirPw` /
`UsesOSHomedirPw()`, linked via `EmbeddedCSources` and the test harness's
`appendOSHomedirPw`) is:

```c
const char *__kml_os_homedir_pw(void) {
  struct passwd *pw = getpwuid(getuid());
  return pw ? pw->pw_dir : NULL;
}
```

`pw_dir` points into a static buffer libc owns, so there is no free; the
returned string is copied into a header string by the caller's
`__kml_str_from_cstr`, so it does not outlive the next `getpwuid`.

## Implementation notes

- Files: `codegen/llvm/emit_os.go` (rewrite + shim source + getter),
  `codegen/llvm/emitter.go` (`usedOSHomedirPw` flag),
  `codegen/llvm/embedded_c.go` (POSIX-only `CSource` append),
  `tests/compiler_test.go` (`appendOSHomedirPw`, threaded into every build
  chain), `tests/os_test.go` (two new tests).
- The result is merged through an entry-block `alloca` slot (the project's
  branch/merge idiom), not a `phi`.

## Side effects discovered

None. Windows behaviour is byte-identical to before.

## Verification

macOS (Apple Silicon M4). `os.homedir()` manually across all three states:
`HOME=/Users/testuser` → `/Users/testuser`; `HOME=` → `""`; `env -u HOME` →
the passwd home — each matching the Node oracle. New tests
`TestE2EOSHomedirEmptyHomeStaysEmpty` and
`TestE2EOSHomedirUnsetFallsBackToPasswd` (POSIX-gated) pass, full
`TestE2EOS*` suite green, `go vet ./...` clean.
