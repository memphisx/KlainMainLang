# ADR-00464: `arguments` object in class method bodies

- **Relations**: Extends [ADR-00387](ADR-00387.md)
- **Date**: 2026-08-29

## Context

The synthesized-`arguments` support (ADR-00387) was wired only into plain
function emission; a method body referencing `arguments` (the corpus's
`argsInScope` shape) still errored `undefined variable 'arguments'`.

## Decision

`emitClassMember` calls the same `synthesizeArgumentsObject` after binding
parameters (via a synthetic `FunctionDeclaration{Params, Body}` wrapper —
the helper only reads those two fields plus the signature, whose
`ParamTypes` align with the declared parameters, not the receiver). Same
scope rules: all parameters one type, no rest/destructured, arrows still
have no own `arguments`.

## Verification

Mac. `tests/classes_test.go` `TestE2EArgumentsObjectInMethod` (numeric
index loop + string `for…of`) and the `examples/classes` extension pass;
class E2E batch green. TS oracle agreement 5135 → 5136. Node oracle
unchanged (40).
