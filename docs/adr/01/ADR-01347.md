# ADR-01347: `crypto.subtle` is Node's Web Crypto in TypeScript

- **Relations**: Implements TDD-00230 (P3.2), Extends ADR-01345, ADR-01346, ADR-01344, Supersedes ADR-01343
- **Date**: 2026-10-03

## Context

`crypto.subtle` was a codegen path: `emit_call_crypto.go` and
`runtime_crypto_subtle.go`, about 1,800 lines over a per-backend
`__kml_crypto_*` C ABI. Its status page carried shared caveats on every
row:
- the algorithm had to be a literal, dispatched at compile time;
- failures threw synchronously instead of rejecting;
- `crypto.subtle` was not a value.

There were per-row gaps too:
- RSA was limited to exponent 65537;
- `CryptoKey.algorithm`/`usages` were missing;
- there was no JWK validation;
- there was no AES-CTR, AES-KW, RSASSA-PKCS1-v1_5, Ed25519, X25519 or ECDH.

A TypeScript port of Node's `lib/internal/crypto/webcrypto.js` existed
outside the tree. Its RSA/EC/X25519 math was BigInt TypeScript, not
constant-time and without blinding. ADR-01345 and ADR-01346 added the
`node:crypto` primitives Node's own implementation is written over.

## Investigation

- Node's Web Crypto calls `KeyObject` handles, `sign`/`verify` with
  padding, salt length and DSA encoding, the RSA cipher functions,
  `diffieHellman`, the ciphers, the KDFs and keygen. All of these now
  exist.
- So the port's own `KeyHandle` can be a `KeyObject`. Only CTR's
  counter-block arithmetic still needs BigInt, and that is public data.
- Wiring it found these compiler bugs:
  1. `TypedArray.from`/`of` were declared but never implemented ("from is
     not a function").
  2. `BigInt(string)` took decimal only and exited the process on bad
     input. StringToBigInt accepts `0x`/`0o`/`0b`, white space and `""`,
     and throws `SyntaxError`.
  3. An async arrow passed where `() => Promise<any>` is expected handed
     over its `Promise<T>` unconverted. An array or object result was read
     as an `any` word, which printed garbage.
  4. `TextDecoder.decode` of an `ArrayBuffer` held in `any` threw, because
     only views were probed.
  5. `getCiphers()`/`getHashes()` listed every OBJ name, lowercased. Node
     lists the names whose algorithm a provider can fetch, deduplicated
     case-insensitively and sorted (`filterDuplicateStrings`). On Linux
     ours had `des3-wrap` and lacked the `-wrap-pad` names.

## Decision

1. **The port is in the tree**: `lib/node/internal_crypto_webcrypto.ts`,
   `_algs.ts`, `_keys.ts` and `_webidl.ts`.
   - `KeyHandle` wraps a `KeyObject`, or a secret key's bytes. DER, JWK
     and raw points go through `createPublicKey`/`createPrivateKey`,
     `export` and `ECDH.convertKey`.
   - The operations go through `node:crypto`: OAEP through
     `publicEncrypt`/`privateDecrypt`, PSS and PKCS#1 through `sign` with
     options, ECDSA with `ieee-p1363`, EdDSA through `sign(null, …)`,
     ECDH/X25519 through `diffieHellman`, and AES-KW through
     `id-aes<bits>-wrap`.
   - The BigInt `_math.ts` and `_asn1.ts` are not brought in.
   - EC key checks (point on the curve; for a private key, d·G is the
     point) use `ECDH`.
2. **Wiring.**
   - The module is a global module, so `CryptoKey` and `SubtleCrypto`
     link to its classes.
   - A program naming `subtle` brings it in (`NativeGlobalUses`).
   - `crypto.subtle` and `globalThis.crypto.subtle` compile to its
     `_kmlSubtle()`, as does a `const { subtle } = crypto` alias wherever
     it is read (`emit_websubtle.go`).
   - `KeyObject.from(cryptoKey)` takes the key's KeyObject through
     `CryptoKey._kmlKeyObject`.
3. **Deleted:**
   - `emit_call_crypto.go`, `runtime_crypto_subtle.go`, and their typing
     and member hooks;
   - the `IsCryptoKey`/`IsCryptoKeyPair` type flags;
   - `dynobjsrc/jwk.c` (ADR-01343's JWK object, which the port's export
     replaces);
   - in both C backends, every `__kml_crypto_*` subtle function and static
     helper nothing references any more. The b64url and JWK-import helpers
     that the KeyObject natives use stay.
4. **The compiler fixes:**
   - `TypedArray.from`/`of` are a TypeScript global module
     (`kml_typedarray.ts`) reached through `@lower`. When every overload of
     a method lowers to one TypeScript function, the call takes it without
     choosing an overload (the generic `mapfn` form included).
   - `__kml_bigint_parse` in both bigint backends; codegen throws Node's
     `SyntaxError` on NULL.
   - The callback adapter is needed, and converts the result with
     `emitConvertPromise`, when the two promise element types disagree in
     representation.
   - `TextDecoder.decode` reads an `ArrayBuffer` (or `SharedArrayBuffer`)
     host box's `{ len, data }`.
   - The names native does what Node's `array_push_back` does, and
     `crypto.ts` applies `filterDuplicateStrings`.

## Implementation notes

- **Port and libraries:**
  - `lib/node/internal_crypto_webcrypto*.ts`, `kml_typedarray.ts`,
    `crypto.ts`;
  - `lib/lib.go`, `lib/es.d.ts` (`@lower` on the typed arrays'
    `from`/`of`).
- **Codegen:**
  - `codegen/llvm/emit_websubtle.go` (new);
  - `emit_lowered.go` (`sharedLibLowering`);
  - `emit_exprs.go`, `emit_exprs_types.go`, `emit_exprs_member.go`,
    `emit_objects.go`, `emit_call.go`, `types.go`;
  - `emit_call_encoding.go`, `emit_func_adapt.go`, `emit_bigint.go`;
  - `runtime_dynarr.go`, `embedded_c.go`, `emitter.go`, `crypto.go`.
- **Natives:** `cryptosrc/crypto_openssl.c`, `crypto_commoncrypto.c`,
  `bigintsrc/bigint_gmp.c`, `bigint_tommath.c`.
- **Tests:**
  - The two `TestSubtle…IsCompileError` tests asserted what Node does not
    do. They are now `TestE2ESubtleDigestAlgorithmAtRunTime`, checked
    against Node.
  - `TestE2ESubtleExportKindMismatch` now expects Node's
    `NotSupportedError`.

## Side effects discovered

- `-crypto=commoncrypto` (out of scope) loses the asymmetric Web Crypto
  algorithms. They run over KeyObject, which that backend stubs out. The
  symmetric ones (digest, HMAC, AES, PBKDF2, HKDF) still run there, and
  the asymmetric test runs on OpenSSL only.
- Node's experimental algorithms (Ed448, X448, SHA-3, cSHAKE, KMAC, Argon2,
  AES-OCB, ChaCha20-Poly1305, ML-DSA, ML-KEM) and `supports`,
  `getPublicKey` and `encapsulateKey` are not ported. `node:crypto` does
  not yet re-export `webcrypto`/`subtle`.

## Verification

Mac (Apple Silicon), against Node v24.19:
- **New tests:** `TestE2ESubtleEveryAlgorithm`, covering every algorithm's
  generate/import/export/sign/encrypt/derive/wrap, CryptoKey properties,
  errors and inspect. Also `TestE2ESubtleValidation`,
  `TestE2EKeyObjectFromCryptoKey`, `TestE2ETypedArrayFromAndOf`,
  `TestE2EBigIntFromString`, `TestE2EAsyncCallbackPromiseResultAdapted`
  and `TestE2ETextDecoderAnyArrayBuffer`.
- **Existing suites:** every `Subtle`/`WebCrypto`/`Crypto` test, and the
  encoding, typed-array, template and KeyObject groups.
- **Example:** `examples/crypto/crypto.ts` gained Ed25519, X25519 and
  AES-KW, and matches Node.
- **Unit tests:** the unit packages.
