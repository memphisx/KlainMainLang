# ADR-01426: Missing super(), unreachable reads, finally, Map entry objects

- **Relations**: Implements TDD-00230 (P2.5, P2.7), Extends ADR-01424
- **Date**: 2026-10-06

## Context

Working the shadow report's `inferUnannotatedReturnType` rows and the
Test262 results of ADR-01424 turned up four places where the compiler
differed from TypeScript or Node:

- `function f() { x++; return; return x }` returned `undefined` to the
  checker; tsc infers `number | undefined` from every return statement,
  reachable or not.
- A derived class's constructor that never calls `super()` ran to
  completion. Node throws `ReferenceError: Must call super constructor in
  derived class before accessing 'this' or returning from derived
  constructor`; tsc rejects it (TS2377). Codegen rejected only the case of
  a base class with its own constructor, with a check of the body's
  top-level statements.
- `new Map([{ foo: 'bar' }])` was a compile error ("expects a [key,
  value][] array of 2-element pairs"); Node reads each entry's `0` and `1`
  properties (`Map(1) { undefined => undefined }`), and throws `TypeError:
  Iterator value 1 is not an entry object` for a primitive entry.
- Test262's Map and Set subclass tests were invalid IR: a host class's
  inspect hook called `__kml_map_any_keys` without the any-keyed map
  routines being emitted.

## Investigation

- The checker's return-type collection (`checker/symbols.go`,
  `returnType`) walks every return statement. The unreachable one's `x`
  read `never`: the flow walk returned `never` at an unreachable node.
  tsc's `getTypeAtFlowNode` returns the declared type there (an evolving
  one as `any`), and its binder never adds an unreachable antecedent to a
  label; ours does not either (`binder/flow.go`, `addAntecedent`), so the
  walk meets an unreachable node only from a reference in dead code.
- Making that change failed `lib/node/timers_promises.ts`: a `finally`
  after a try that always throws read `interval` as `Timeout | undefined`
  inside `if (interval !== undefined)`. The binder entered `finally` only
  from the try's normal completion, which there is unreachable, so the
  narrowing had passed only because every read was `never`. tsc enters
  `finally` from every state an exception can leave the try in.
- `mapKeysAndVals` and four call sites that call a map family's `_keys`
  directly did not call `ensureMapFamily`; only map creation did, and a
  subclass's map is created through the headered path.

## Decision

- Flow: a reference at an unreachable node reads its declared type (an
  evolving binding's as `any`).
- Binder: each try with a `finally` opens an exception label, entered from
  the state before the try; every assignment inside the try or catch is an
  antecedent of it (not one inside a nested function or a field
  initializer). When neither the try nor the catch completes normally,
  `finally` is entered from that label and what follows the statement is
  unreachable. Otherwise `finally` is still entered from the normal
  completion only: binding it under both entries would visit its
  declarations twice.
- Checker: TS2377 for a derived class's constructor with no `super()` call
  anywhere in it (arrow functions included, nested functions and classes
  not).
- Codegen, for the `-compat=js` lane: such a constructor body becomes
  `let threw = false; try { <statements before the first one that reads
  this>; throw ReferenceError } catch (e) { threw = true; throw e } finally
  { if (!threw) throw ReferenceError }`, so a return or completion throws
  Node's error and an exception from the body propagates. The old
  base-has-a-constructor rejection stays for a constructor that calls
  `super()` only somewhere nested.
- Codegen: an entries literal whose elements are not all two-element array
  literals is built as an `any[]` and seeded through the existing
  entry-object path, with `any` keys and values; that path throws the
  TypeError for a primitive entry.
- `ensureMapFamily` is called by `mapKeysAndVals` and at every direct
  `_keys` call with a variable family.
- Parser: a private name a class declares twice (`#x; #x;`, a `#m` field
  and a `#m` getter) is the early error Node raises as a SyntaxError
  (TS2300); a getter and a setter of one name, both static or both not, are
  one accessor. These had been rejected only by accident: the bare field's
  `number` default (ADR-00474) disagreed with the getter.
- Parser: a `super(...)` call in a field initializer (outside a nested
  function or class) is the early error Node raises as a SyntaxError
  (TS2337), next to the `arguments` check there; it had reached codegen as
  "type 'void' is not assignable".

## Implementation notes

- `checker/narrow.go`, `checker/check.go`, `diag/messages.go`,
  `binder/binder.go`, `binder/flow.go`, `codegen/llvm/emit_classes.go`,
  `codegen/llvm/emit_collections.go`, `codegen/llvm/emit_inspect.go`.
- The constructor rewrite stops at the first top-level statement that
  reads `this`; an expression in that statement evaluated before the read
  does not run. Node would run it first.

## Side effects discovered

- Two class tests constructed derived classes without `super()`; Node
  throws for both programs, and they now call it.

## Verification

- Compared with Node: the missing-`super()` cases (plain and Map bases,
  an exception thrown before, a bare `return`), Map entry shapes (`[{}]`,
  `[[1, 2, 3], ['a']]`, `[1]`).
- tsc 5.9.3 on the unreachable-return program reports `number | undefined`;
  the strict lane now reports the same.
- Test262 `language/statements/class/subclass-builtins`,
  `subclass/builtin-objects` and `expressions/class/subclass-builtins`: no
  invalid IR; subclass-Map, subclass-Set, regular-subclassing and
  super-must-be-called pass.
