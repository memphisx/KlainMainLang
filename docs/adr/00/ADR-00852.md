# ADR-00852: `String.prototype.substr(start, length)`

- **Relations**: Sibling of `substring` / `slice` string extraction
- **Date**: 2026-09-10

## Context

`"abcdef".substr(2, 3)` was "a string has no method 'substr'". `substr` is
formally deprecated (Annex B) but still ubiquitous in real code, and its
`(start, length)` shape differs from `substring`'s `(start, end)` — so it is a
genuine missing method, not an alias.

## Decision

New `emitStringSubstr`: a negative `start` counts from the end
(`max(len + start, 0)`, then clamped to `[0, len]`); `length` defaults to the
rest of the string and is clamped to `[0, len - start]` (a negative length is an
empty string). Reuses `emitStringExtract` for the copy. `inferExprType` types it
`string` alongside `substring`.

## Implementation notes

`emit_strings.go` (`emitStringSubstr`); `emit_call.go` (dispatch, guarded on a
string receiver); `emit_exprs_types.go` (inference, in the `substring` case).

## Verification

macOS (Apple Silicon M4): matches Node — `substr(2, 3)` → `cde`, `substr(2)` →
`cdef`, `substr(-2)` → `ef`, `substr(-2, 1)` → `e`, `substr(2, 100)` → `cdef`,
`substr(100)` → `""`, `substr(-100, 2)` → `ab`, a negative length → `""`. New
`TestE2EStringSubstr` + the string suite green.
