# ADR-00661: WeakMap/WeakSet/WeakRef accept a dynamic object key under -compat=js

- **Relations**: Extends ADR-00656
- **Date**: 2026-09-03

## Context

Second-largest `-compat=js` Test262 regression bucket (13 files, plus the paired
WeakRef case): `a WeakMap/WeakSet key must be an object (not a primitive)` /
`new WeakRef requires an object referent (not a primitive)`. The offenders are
ordinary object-key tests — `var foo = {}; var map = new WeakMap();
map.set(foo, 42)` — that pass under strict and fail only under `-compat=js`.

The cause: under `-compat=js` a plain `{}` object literal is a **dynamic**
(any-typed, D1) value, not a fixed-shape struct. `weakObjectKey`
(`codegen/llvm/emit_weak.go`) requires the key's static IR to be `ptr` (a
non-string reference); the any box's IR is `i64`, so a genuine object reference
was rejected purely because its *static* type under `-compat=js` is dynamic.

## Decision

For an `any`/dynamic key or referent **under `-compat=js`**, unbox the NaN box's
payload pointer (`coerce(v, TypePtr)`, the ADR-00639 any→ptr arm) and proceed,
instead of rejecting on the static type. At runtime the value is an object
reference (the identity the weak collection keys on). A primitive at runtime is
a `-compat=js` divergence (real JS throws a TypeError; here it is best-effort,
not invalid IR) — strict is untouched and still rejects a statically-primitive
key/referent cleanly.

## Implementation notes

- `emit_weak.go`, `weakObjectKey`: an early `if kVal.Ty.IsDynamic &&
  e.compatJS()` returns `coerce(kVal, TypePtr).Ref`.
- `emit_weak.go`, `emitNewWeakRefValue`: the same guard coerces `obj` to
  `TypePtr` before the object-referent check.

## Side effects discovered

A WeakMap whose *value* is any-typed and then `console.log`'d prints the raw
NaN-box word rather than the decoded number — but that is the separate
any-value-decode path (`console.log` of an `any`), unaffected by and unrelated to
this key fix; the Test262 object-key cases compare values via `assert.sameValue`
and don't hit it.

## Verification

- New E2E test `TestE2EWeakMapDynamicObjectKeyCompatJS`
  (`tests/collections_test.go`): `var foo = {}` keying a `WeakMap` under
  `-compat=js` (`has`/`delete`/`has` round-trip).
- The Test262 `WeakMap/prototype/{delete,get}/*object-key*.js` files now compile
  and run under `-compat=js`.
- The strict rejection (`TestE2EWeakMapPrimitiveKeyRejected`) and the rest of the
  weak-collection suite stay green. macOS (Apple Silicon).
