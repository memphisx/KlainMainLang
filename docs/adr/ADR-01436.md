# ADR-01436: Closure types before emission match the emitted closure

- **Relations**: Implements TDD-00230 (P2.2)
- **Date**: 2026-10-07

## Context

The second shadow bucket after ADR-01434 (2245 rows, almost all in
`stream.ts`) was a closure-valued name whose return type codegen answered
differently from the checker before the closure was emitted:

- `const onDestroy = (er?: Error | null) => { if (called) return; … }` read
  as returning `i64`; the checker says `void`;
- `const nextAsync = async (): Promise<void> => { … }` read as returning
  `Promise<Promise<void>>`; the checker says `Promise<void>`.

## Investigation

- `inferExprType` types an arrow or function expression before any closure
  exists (a `const` binding to it). When return inference found no valued
  return it fell to `i64`, while the emitter already treats an all-bare
  `return;` body as `void` and a valued one as `double`.
- `asyncClosureRetType` unwrapped an annotated promise's element type
  before wrapping it again. `Promise<void>` has no element type, so the
  annotation itself became the element.

## Decision

- Both inference sites mirror the emitter: all-bare returns are `void`,
  otherwise the `double` default.
- An async closure whose return is already a promise keeps it, tagged as
  the task promise the async epilogue returns.

## Verification

- `TestE2EClosureTypeBeforeEmission` (against Node) and the async, closure
  and function-expression tests pass on the Mac.
- The probe's shadow rows are gone.
