# ADR-00803: Multiple concurrent HTTP servers — TDD-00191 Stage 1

- **Relations**: `Implements TDD-00191`, `Extends TDD-00131`, `Extends ADR-00802`
- **Date**: 2026-09-09

## Context

`http.createServer(...).listen()` was single-instance, once-per-program — a
second `createServer` was a hard codegen rejection. This ADR implements
TDD-00191 Stage 1: two-plus plain Node HTTP servers on different ports in one
program, each serving its own handler concurrently on the shared event loop (an
app port plus a health/metrics port, etc.). It also folds in the per-listener
`close()` that Stage 2 scoped, because closing an additional server was needed
for the loop to exit.

## Decision

Follow TDD-00191's recommended direction — a listener table plus per-server
dispatchers — in the **additive** form: the *primary* (first) server keeps the
existing `@__kml_listen_*` scalar globals and the whole reactor path unchanged,
and each *additional* server is a new participant.

**Runtime (`runtime_http.go`).** A thread-local extra-listener table
`@__kml_http_xl_{data,len,cap}` of `{ i64 fd, ptr dispatch }` entries
(realloc-doubling, the connection/timer-table shape), with the standard reactor
hook trio wired into `__kml_event_loop_run`:

- `__kml_http_xl_fdset_add(fdset, maxfd)` — add every open extra listener's fd
  (alongside the primary `@__kml_listen_fd`).
- `__kml_http_xl_keepalive()` — OR'd into the loop's keep-alive condition so an
  additional server holds the loop open.
- `__kml_http_xl_accept(fdset)` — in the post-select dispatch region, accept a
  connection on each ready extra listener and hand it to that server's dispatcher.
- `__kml_http_close_extra_listener(fd)` — `server.close()` for an additional
  server: clear its table entry (fd = -1) and close the socket; in-flight
  connections drain via the same `%hasactiveconns` path the primary
  `http.close()` uses.

`__kml_http_append_conn` gains a `ptr %dispatch` parameter — the connection-fiber
entry point — instead of reading `@__kml_listen_dispatch`. The primary accept
site passes the loaded global; the extra-accept site passes the table entry's
dispatch; the streaming writer's keep-alive re-arm (ADR-00802) passes a dispatch
now carried in its context (a 7th `%kml.hws` field, ctx 48→56 B).

**Codegen (`emit_http.go`).** Each `http.createServer` gets an index
(`e.httpServerCount`). Server 0 is primary (suffix `""`, existing behavior).
Server N>0 gets suffix `_N`: its handler lives in `@__kml_listen_handler_N`, its
dispatcher is emitted as `@__kml_http_dispatch_N` (via a threaded
`e.curDispatchSfx` read by the handler load, the streaming hand-off, and the
function name), and the HTTP/2 bridge is emitted only for the primary (its
symbols are fixed-named). The `Server` handle grows 16→32 B: slot 2 = the
server's dispatcher symbol, slot 3 = the primary flag. `server.listen` and
`server.close` branch on slot 3 to hit the primary scalars vs. the extra table.

## Stage-1 boundaries (clean rejections, not miscompiles)

An additional (N>0) server is plain HTTP/1.1. Combining a second server with
WebSocket/`upgrade` handling, HTTPS, or Worker/cluster is rejected with a
message pointing at the relevant later stage; the additional server also
requires its listener inline (`createServer((req,res)=>…)`) — the
`createServer()`+`on('request')` split stays single-server. h2c
prior-knowledge upgrade is primary-only (extra accept is plain). The primary
server keeps every existing capability.

## Implementation notes

- The primary path is byte-unchanged: all single-server tests (WebSocket, HTTP/2,
  cluster, streaming keep-alive) pass untouched.
- Additive hook placement mirrors `__kml_net_*`/`__kml_dgram_*` — the reactor
  already composes independent accept sources this way.

## Side effects discovered

The `%kml.hws` streaming-writer context grew a field; its `malloc` had to grow
48→56 B (a missed size bump corrupted the heap and reset streamed connections —
caught by the existing chunked-keepalive/union-stream tests before commit).

## Verification

Mac (Apple Silicon). New `tests/http_test.go`: `TestE2EHTTPMultipleServers`
(two servers, interleaved requests, each answers with its own handler),
`TestE2EHTTPMultipleServersCloseExits` (closing both lets the loop exit — the
extra-listener close), `TestE2EHTTPMultipleServersRejectsWithUpgrade` (Stage-1
boundary). Three concurrent servers verified manually via `curl`. Full
`TestE2EHTTP*`, streams, net, WebSocket, http2, cluster suites green; `go vet`
clean; every `examples/http/*.ts` compiles; `examples/http/multi_server.ts` runs
and exits cleanly.
