# ADR-00950: Truthiness of a possibly-undefined pointer value (`if (map.get(k))`)

- **Relations**: `Fixes` a pre-existing bug flagged in ADR-00943 Side effects
- **Date**: 2026-09-15

## Context

A `T | undefined` / `T | null` **pointer** value used directly in a boolean
position folded to a constant `false`, so a *present* value read as falsy:

```ts
const m = new Map<string, string>()
m.set('a', 'hello')
if (m.get('a')) { /* never taken */ }   // wrongly false
```

The same held for an object-valued map (`Map<string, {…}>`) and any
`string`/object value typed `V | undefined`. Flagged as a pre-existing,
independent bug while landing the array-valued-map fix (ADR-00943) — array-
valued maps route around it by marking their result `Nullable` but not
`IsUndefined`.

## Investigation

`toBool` (`emit_exprs_types.go`) folded any value to a constant `false` when
`v.Ty.IsUndefined || v.Ty.IsNull`, alongside the genuinely value-less `void`/`""`
cases. But a `Map<K, string>`/`Map<K, {…}>` `get()` result is a real runtime
pointer typed `V | undefined` (`IsUndefined` set, `Nullable` set): a miss is a
null pointer, a present key a live one. Folding its truthiness discarded the
runtime pointer entirely.

The downstream truthiness machinery already handles these values correctly —
`emitStringTruthiness` reads a null string pointer as falsy and an empty string
as falsy, and the generic `ptr != null` test covers object pointers — they were
simply never reached because the fold intercepted first. Nullable **scalars**
(`number | undefined`, the presence-flagged `{ i1, T }` path) are handled by an
earlier arm and never reach the fold.

The distinguishing signal is `Nullable`: a bare `null`/`undefined` literal is
`TypeNull`/`TypeUndefined` (`IsNull`/`IsUndefined`, Ref `"null"`) but **not**
`Nullable`, whereas a `T | undefined` union sets `Nullable`.

## Decision

Fold to a constant `false` only for a value-less or bare-literal-nullish value —
`IR == "void" || IR == "" || ((IsUndefined || IsNull) && !Nullable)`. A
`Nullable` pointer (`T | undefined` / `T | null`) falls through to the existing
runtime test: `emitStringTruthiness` for a string (null / `""` → falsy), the
`ptr != null` switch case for an object/handle. Bare `null`/`undefined`
literals still fold (they are not `Nullable`), preserving prior behavior — and
would read falsy via the pointer path anyway (Ref `"null"`).

The only behavioral change is for `(IsUndefined || IsNull) && Nullable` values,
which now test at runtime instead of folding.

## Verification

- `TestE2EMapGetTruthiness` (tests/collections_test.go): present string truthy,
  miss falsy, empty-string value falsy, present object truthy, object miss
  falsy.
- Regression: the hot truthiness path warrants the full gate — `make test-par`
  green on macOS arm64 (Apple Silicon M4), plus the truthiness/map/nullable/
  optional/if-while/logical/string/RegExp slice.
