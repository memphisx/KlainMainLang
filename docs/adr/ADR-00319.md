# ADR-00319: Asymmetric `crypto.subtle` — RSA-OAEP/RSA-PSS/ECDSA, CryptoKeyPair, pkcs8/spki/raw/JWK

- **Relations**: Implements [TDD-00104](../tdd/TDD-00104.md) (Phase 3); extends [ADR-00316](ADR-00316.md), [ADR-00318](ADR-00318.md)
- **Date**: 2026-08-23

## Context

The remaining non-derive Web Crypto surface: RSA-OAEP encrypt/decrypt,
RSA-PSS and ECDSA (P-256/P-384/P-521) sign/verify, asymmetric generateKey
(→ CryptoKeyPair), and importKey/exportKey in `pkcs8`, `spki`, `raw` (EC
public points), and `jwk`.

## Investigation

- **Key representation stays DER** (ADR-00318's model): PKCS#8 for private,
  SPKI for public — the two backends' native forms differ (OpenSSL speaks
  DER directly; SecKey's external representations are PKCS#1 for RSA and
  X9.63 raw `04||X||Y[||K]` for EC), so the commoncrypto shim gained a
  mini-DER reader/writer (~250 lines) that wraps/unwraps PKCS#1/X9.63 to
  PKCS#8/SPKI with the fixed rsaEncryption/ecPublicKey/curve OIDs.
- **Cross-backend interop was verified directly, not assumed**: standalone
  C drivers generated keys, PSS/ECDSA signatures, and OAEP ciphertexts
  under each backend and consumed them under the other — all four
  directions pass (same driver binary-pairs, file exchange).
- **JWK for asymmetric keys**: rather than exchanging JSON (which would
  drag a JSON parser into the shims), the ABI exchanges *components* —
  malloc'd base64url strings per JWK member (`n,e,d,p,q,dp,dq,qi` /
  `x,y,d`), NULL when absent. OpenSSL derives them via
  `EVP_PKEY_get_bn_param`/`OSSL_PARAM_BLD` + `EVP_PKEY_fromdata`; the
  commoncrypto shim reads them straight out of PKCS#1/X9.63 via the same
  mini-DER. The emitter surfaces them as the established
  `Map<string,string>` JWK shape.
- **ECDSA signatures**: Web Crypto uses raw `r||s`; both libraries produce
  DER `ECDSA-Sig-Value` — each shim converts (OpenSSL via
  `ECDSA_SIG`/`BN_bn2binpad`, commoncrypto via the mini-DER).
- `exportKey`'s format handling must branch at *runtime* on the key's
  algId (a CryptoKey value's algorithm isn't compile-time knowledge):
  `raw` (EC → SPKI-to-point conversion, else byte copy) and `jwk`
  (oct/RSA/EC three-way branch) emit label-based IR; a null-skipping
  `__kml_jwk_map_set` IR helper keeps the per-component branches out.

## Decision

- `generateKey` for RSA-OAEP/RSA-PSS (`modulusLength`, literal `hash`,
  `publicExponent` restricted to absent or the literal
  `new Uint8Array([1, 0, 1])`) and ECDSA (literal `namedCurve`), returning
  a CryptoKeyPair (`{ptr publicKey, ptr privateKey}` header,
  `IsCryptoKeyPair` flag, dedicated property reads). Spec usage split:
  public keeps encrypt/verify/wrapKey, private keeps
  decrypt/sign/unwrapKey.
- CryptoKey header field 1 is now `param`: hash id for HMAC/RSA keys,
  curve id for EC keys (Web Crypto binds hash to RSA keys but ECDSA's hash
  arrives per sign/verify call); the header's `kind` became a runtime
  value so JWK import (public vs private decided by the presence of `d`)
  can set it.
- `sign`/`verify`: RSA-PSS takes a required runtime `saltLength`; ECDSA a
  required literal per-call `hash`. Verify returns Promise<boolean>
  (negative shim codes still throw — parse failures are errors, mismatches
  are `false`).
- `encrypt`/`decrypt` RSA-OAEP with optional `label` BufferSource.
- `importKey`/`exportKey`: `pkcs8` (private), `spki` (public), `raw` (EC
  public uncompressed points, both directions), `jwk` (object literal or
  Map in; Map out). Export enforces kind/format agreement and
  extractability with `InvalidAccessError`.

## Implementation notes

- `cryptosrc/crypto_openssl.c` (+~450 lines, EVP/OSSL_PARAM only),
  `crypto_commoncrypto.c` (+~700 lines: mini-DER, SecKey, component
  bridge), `runtime_crypto_subtle.go` (declares + `__kml_jwk_map_set`),
  `emit_call_crypto.go` (pair keygen, asym import/export, OAEP, PSS/ECDSA
  sign/verify), member/type paths for CryptoKeyPair.
- Backend caveats (runtime `NotSupportedError` on commoncrypto only):
  OAEP `label` (SecKey has no label parameter) and PSS `saltLength` ≠ the
  hash length (SecKey fixes salt = digest size).

## Side effects discovered

- `new Uint8Array(arrayBuffer)` is a *view* (correct per spec) — a test
  that tampered a signature through a view silently mutated the original
  buffer; test style adjusted, no compiler change.

## Verification

Mac: `TestE2ESubtleAsymmetric` (ECDSA generate/sign/verify/tamper, raw +
jwk roundtrips, RSA-OAEP encrypt→decrypt + pkcs8 roundtrip, RSA-PSS
sign→verify + jwk roundtrip) matrix-run on **both** backends with
identical output; `TestE2ESubtleExportKindMismatch` (InvalidAccessError
on pkcs8-of-public / spki-of-private). Standalone C drivers: per-backend
full-surface pass (all three curves) plus four-direction cross-backend
interop. Example extended and rerun; `go build`, `go vet ./...`.
