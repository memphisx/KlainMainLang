# ADR-00565: fs Stats exposes the full numeric surface

- **Relations**: Extends ADR-00495, ADR-00497
- **Date**: 2026-09-01

## Context

`fs.statSync`/`lstatSync`/`fstatSync` returned a Stats object carrying only
`size` and `mtimeMs` (over a hidden `st_mode` word backing
`isFile()`/`isDirectory()`/`isSymbolicLink()`). Real Node's Stats has a dozen
more own-enumerable numeric properties — `dev`, `mode`, `nlink`, `uid`, `gid`,
`rdev`, `blksize`, `ino`, `blocks`, and the `atimeMs`/`ctimeMs`/`birthtimeMs`
timestamps. The gap was a disclosed caveat and blocked any code inspecting
ownership, permissions bits, link counts, or access/change times.

## Investigation

The runtime `__kml_fs_stat` already `stat(2)`'d into a 256-byte scratch buffer
and pulled three fields at per-host `struct stat` offsets. Extending it is
purely a matter of reading the remaining fields at their (per-OS/arch) offsets —
`struct stat` has no portable layout, so the offsets are constants the same way
`direntNameOffset` already handles `struct dirent`. The three supported hosts:

- **Darwin** (64-bit-inode default): `st_dev` i32 @0, `st_mode` u16 @4,
  `st_nlink` u16 @6, `st_ino` u64 @8, `st_uid` u32 @16, `st_gid` u32 @20,
  `st_rdev` i32 @24, atime @32, mtime @48, ctime @64, birthtime @80, `st_size`
  i64 @96, `st_blocks` i64 @104, `st_blksize` i32 @112.
- **glibc x86-64**: `st_dev` @0, `st_ino` @8, `st_nlink` @16, `st_mode` @24,
  `st_uid` @28, `st_gid` @32, `st_rdev` @40, `st_size` @48, `st_blksize` @56,
  `st_blocks` @64, atime @72, mtime @88, ctime @104.
- **glibc aarch64**: `st_dev` @0, `st_ino` @8, `st_mode` @16, `st_nlink` @20,
  `st_uid` @24, `st_gid` @28, `st_rdev` @32, `st_size` @48, `st_blksize` @56,
  `st_blocks` @64, atime @72, mtime @88, ctime @104.

Neither Linux `struct stat` carries a creation time (that needs `statx`), so
`birthtimeMs` is reported as `0` there; Darwin's `st_birthtimespec` is real.

## Decision

- `statLayout()` now returns a `statFieldLayout` struct of every field's offset
  and load width; `statBodyLL()` renders the shared ok-path that reads each
  field, converts the three/four timespecs to integer milliseconds
  (`sec*1000 + nsec/1e6`), and packs a 14-`i64` result in Node's own-property
  order (dev, mode, nlink, uid, gid, rdev, blksize, ino, size, blocks, atimeMs,
  mtimeMs, ctimeMs, birthtimeMs). `__kml_fs_stat`/`__kml_fs_lstat`/
  `__kml_fs_fstat` all share it.
- `StatsType()` exposes those 14 fields as real own-enumerable properties;
  `mode` is now visible (matching Node — it is enumerable) and doubles as the
  `isFile()`/`isDirectory()`/`isSymbolicLink()` mask source. The prior
  Object.keys/JSON strip of the hidden `__kml_mode` word is removed.

Times remain integer milliseconds; the Date-valued `atime`/`mtime`/`ctime`/
`birthtime` accessors are a disclosed remaining gap.

## Side effects discovered

None. `isFile()`/`isDirectory()`/`isSymbolicLink()` mask the now-visible `mode`
field with S_IFMT exactly as before.

## Verification

New `TestE2EFsStatFullSurface` (mode bits, uid/gid, nlink, ino, blksize,
atimeMs/ctimeMs, size) plus the existing `TestE2EFsStatSync`,
`TestE2EFsPathOps`, and open/fstat tests pass. Verified on Mac (Apple Silicon)
and on Linux — both **aarch64** and **x86-64** glibc (via Docker
`golang:latest`, the latter under `--platform linux/amd64`), where every new
field (`mode`/`uid`/`gid`/`nlink`/`ino`/`blksize`/`atimeMs`) reads a sane value,
confirming the per-arch offsets. The prior "Linux offsets verified on Mac only"
caveat is retired.
