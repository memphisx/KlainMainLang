# TDD-00116: Discriminated unions (tagged object unions)

- **Status**: Implemented
- **Date**: 2026-08-25
- **Notes**: ≥2 object members sharing a first-position string-literal tag field; literal values carried into the resolved Type; `s.tag` read on the un-narrowed union; `s.tag === "lit"` narrows to the matching member (if/else + early return). Number-literal tags, non-first-position tags, `switch` narrowing, and exhaustiveness deferred

## Context

[TDD-00115](TDD-00115.md) allowed **one** object member in a union, narrowable by
`typeof x === "object"`. Two-plus object members were deferred because `typeof`
can't tell them apart. The idiomatic way TypeScript distinguishes them is a
**discriminated union**: every member shares a literal-typed *tag* field with a
distinct value, and `switch (s.kind)` / `if (s.kind === "circle")` narrows to the
matching member:

```ts
type Shape = { kind: "circle"; r: number } | { kind: "square"; s: number };
function area(s: Shape): number {
  if (s.kind === "circle") return 3 * s.r * s.r;
  return s.s * s.s;
}
```

This is the natural completion of the object-union work and a very common real-TS
pattern.

## Design

### Prerequisite: literal types in the resolved `Type`

The parser already tracks `IsStringLiteral`/`LiteralValue` on a `TypeAnnotation`,
but `resolveType` collapses a standalone string-literal type to plain `string`
([TDD-00079](TDD-00079.md) simplification). Add `LiteralValue string` (+
`IsStringLiteral bool`) to the codegen `Type`, populated when resolving a
string-literal type. A literal type is still `string`-shaped at runtime (same IR,
same box tag) — the literal is compile-time metadata used only for discriminant
matching. (Number-literal discriminants are a follow-on; V1 is string tags.)

### Representation — the existing object box, discriminated at runtime by a field

All members box as tag 6 (object) + pointer, exactly as [TDD-00115](TDD-00115.md).
What distinguishes them at runtime is the **discriminant field's value**, not the
tag. For that read to be uniform across members, V1 requires:

- every member is an object type with a common **discriminant field**: same name,
  a **string-literal** type, a **distinct** literal value per member;
- the discriminant is the **first field** (offset 0) of every member, same
  base type — so `s.kind` on the un-narrowed union GEPs field 0 of the boxed
  pointer regardless of which member it holds.

A union is "discriminated" when `validateUnionMembers` finds ≥2 object members
all satisfying the above (else the existing one-object-member rule / rejection
applies).

### Discriminant read on the un-narrowed union

`s.kind` where `s` is a discriminated union: unbox the tag-6 pointer, GEP the
discriminant field (offset 0), load it (a string). This is the *only* field
access allowed on an un-narrowed discriminated union (every other field is
member-specific).

### Narrowing

Extend the narrowing seam ([TDD-00114](TDD-00114.md)): recognize
`s.kind === "literal"` (a member-access on a discriminated-union local `===` a
string literal), narrow `s` to the member whose discriminant literal matches
(and, in the `!==`/else branch, to the union of the rest — concrete if one
remains). `emitUnboxBoxToType` recovers that member's typed pointer, so
member-specific field access works. `switch (s.kind) { case "circle": … }` is the
same match per case (a follow-on if the branch wiring is more than the if-path).

### Assignment

An object value is assignable to a discriminated union when it structurally
matches one member (reusing `objectStructurallyAssignable`), with its discriminant
field's value equal to that member's literal.

## Scope (V1)

- **In:** a union of ≥2 object members sharing a first-position string-literal
  discriminant field; `s.disc` read on the un-narrowed union; `s.disc === "lit"`
  narrowing (if/else + early return) to the matching member; member field access
  after narrowing; structural + discriminant-checked assignment.
- **Out (deferred):** number/boolean-literal discriminants; a discriminant not in
  first position (needs per-member offset lookup — a bounded follow-on);
  `switch`-statement narrowing if it needs more than the if-path seam; mixing
  scalar and object members in the same discriminated union; exhaustiveness
  checking (`never` in the default arm).

## Open questions

- **Discriminant offset.** V1 requires the discriminant first (offset 0). Is
  per-member offset lookup worth it for V1, or is first-position an acceptable
  constraint (it matches how discriminated unions are almost always written)?
  Leaning first-position for V1, offset lookup as a bounded follow-on.
- **`switch (s.kind)`.** Does the existing if-path narrowing seam extend to
  switch cases cleanly, or is switch a separate wiring pass? Decide during
  implementation; the `if`/`else if` form is the V1 must-have.
