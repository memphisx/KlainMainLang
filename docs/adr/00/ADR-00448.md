# ADR-00448: object-type method signatures and bare call signatures

- **Date**: 2026-08-29

## Context

Two adjacent TS acceptance-oracle buckets: `expected :, got (` (73 — a
method signature inside an object type literal, `{ foo(bar: string): string
}`) and a slice of `expected IDENT, got (` (a bare call signature,
`{ (n: number): string }`). Both are everyday TS shorthands for
function-typed positions.

## Investigation

`cachedContextualTypes` and `anonterface` show the shapes. TS semantics:
a method signature `name(params): R` in a type literal is exactly a property
of function type `name: (params) => R`; a lone call signature makes the
object itself callable — which, for a compiler with no callable-object
runtime values, is meaningful only when the call signature is the *whole*
type, where it is exactly the function type.

## Decision

- New `parseObjectTypeSignatureTail` parses the `(params): R` tail into the
  existing `IsFuncType` annotation (parameter names documentation-only, as
  in arrow function types; rest marker supported; omitted return type
  defaults to `void`).
- In the object-type-literal loop: `name(…)` / `name?(…)` members desugar to
  function-typed fields; a bare `(…): R` member is collected and, when it is
  the *only* member, the whole `{…}` returns as that function type
  (trailing `[]` supported). A call signature mixed with fields or an index
  signature, or a second call signature, are clean rejections naming the
  limitation.
- Incidentally, a plain optional field `{ x?: T }` in an object type literal
  now parses (accepted-but-required, the same treatment interfaces already
  gave `x?:`) — previously only interfaces tolerated the `?`.
- Interfaces are untouched: their method signatures already parsed;
  interface *call* signatures stay rejections (an interface is a registered
  named shape, not desugarable to a bare function type without touching the
  implements/conformance machinery).

## Implementation notes

`parser/parser_types.go` only: the helper plus the object-type loop. The
desugared forms flow through the existing function-type/`Fields` codegen
paths unchanged.

## Verification

Mac. `tests/overloads_test.go` additions (method-signature and
call-signature E2E, mixed-members rejection) and
`examples/language/object_type_signatures.ts` pass; parser +
object/interface/type E2E batches green. TS oracle: **54.2% → 54.3%**
(match-accept 1213 → 1228). Node oracle unchanged (37 passed).
