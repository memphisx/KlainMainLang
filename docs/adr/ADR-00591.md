# ADR-00591: structuredClone copies ArrayBuffer and Error

- **Relations**: Extends [ADR-00574](ADR-00574.md), [TDD-00099](../tdd/TDD-00099.md)
- **Date**: 2026-09-01

## Context

`structuredClone` rejected a plain `ArrayBuffer` and an `Error` at compile time,
though a `SharedArrayBuffer` already passed through by reference. Both types are
serializable in Node (`structuredClone(new ArrayBuffer(4))` copies bytes;
`structuredClone(new TypeError("x"))` preserves the message/name/subtype), so
rejecting them diverged from Node. (`URL` stays rejected — Node itself throws
`DataCloneError` for it, so the rejection is faithful.)

## Decision

- **ArrayBuffer**: `emitDeepClone` gains two cases — a `SharedArrayBuffer`
  (`IsArrayBuffer && IsSharedArrayBuffer`) returns its header pointer unchanged
  (share-not-copy), and a plain `ArrayBuffer` is byte-copied by
  `emitDeepCloneArrayBuffer` (read `byteLength`, allocate a fresh header + data
  buffer, `memcpy` the bytes — the same copy `.slice()` performs).
- **Error**: `emitDeepCloneError` copies `kind`/`message`/`name` into a fresh
  object allocated at the AggregateError size (40 B, zeroed) so a cloned
  `AggregateError` never reads its trailing `errors` fields out of bounds — those
  degrade to an empty `.errors`. The kind tag carries the subtype identity, so a
  cloned `TypeError` is still `instanceof TypeError`.
- The compile-time rejections for a plain ArrayBuffer and an Error are removed.

Both clones are independent of the source (verified against Node).

## Verification

`TestE2EStructuredCloneArrayBuffer` (byte values + byteLength carry over, a write
to the clone leaves the source unchanged) and `TestE2EStructuredCloneError`
(message/name preserved, `instanceof` subtype holds), compared against Node v26.
The existing structuredClone suite still passes. Built and verified on Mac
(Apple Silicon).
