# ADR-01353: Shortest number digits across a rounding tie

- **Relations**: Fixes TDD-00080's dtoa
- **Date**: 2026-10-03

## Context

`console.log(2 ** -24)` printed `5.9604644775390625e-8` where Node prints
`5.960464477539063e-8`. Found while comparing the DataView port's Float16
output with Node (ADR-01352).

## Investigation

- Number::toString takes the fewest digits whose value round-trips. At
  each digit count the runtime tried only the correctly rounded string.
- 2^-24 is exactly `…0625`. At 16 digits the tie rounds to even, `…062`.
  Below a power of two the gap to the next double is half the gap above,
  so `…062` falls outside the value's interval while `…063` lies inside.
  The spec accepts any string of that length that round-trips.
- Trying the strings of the neighbouring doubles does not work: the double
  above 2^-24 rounds to `…064`. The candidate is the rounded string moved
  one unit in its last place, toward the value.
- The same loop was copied five times: `dtoa.c` (twice), `number.c`
  (twice), `string.c` and `casemap.c`. The last two used `%g`, whose
  exponent thresholds are not JavaScript's either; they only format numbers
  for error messages.

## Decision

`dtoasrc/dtoa.c`'s `__kml_dtoa_digits` is the one shortest-digits routine:
- At each count it tries the correctly rounded `%e` string. When that does
  not round-trip, it tries the string one unit in the last place toward the
  value (`kml_nudge`, carrying across digits and into the exponent).
- `__kml_dtoa` and `__kml_dtoa_exp` use it, and so does `number.c` for
  `toString` and `toExponential()`.
- `toExponential()` takes its digits from the round-tripping string instead
  of re-rounding the exact decimal.
- `string.c` and `casemap.c` call `__kml_dtoa`.
- dtoa is linked whenever the string, case-mapping or Number runtime is.

## Implementation notes

`codegen/llvm/dtoasrc/dtoa.c`, `numbersrc/number.c`, `stringsrc/string.c`,
`casemapsrc/casemap.c` and `float_fmt.go`.

## Side effects discovered

An error message's number now follows JavaScript's layout (`1e-7`, not
`%g`'s `1e-07` or its switch to exponent form at `1e-5`).

## Verification

Mac (Apple Silicon), against Node 24, with no difference:
- every power of two from 2^-1074 to 2^1023, and each times 3, both as
  `String` and as `toExponential()` (6,306 lines);
- 19,986 random bit patterns through `String`, `toExponential()`,
  `toPrecision(17)` and a scaled product.
