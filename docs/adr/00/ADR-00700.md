# ADR-00700: -mm=auto — implicit auto-free of provably-local values

- **Date**: 2026-09-04

## Context

With ADR-00698's escape check built, the annotations alone would make `auto`
a mere alias of manual-plus-annotations. TDD-00001 defines the mode as "the
compiler frees what it can prove is safe to free" — so `auto` should also
free what it can prove *without* being asked.

## Decision

- `-mm=auto` is now an accepted `-mm` value. Allocator-wise it is identical
  to `manual` (plain libc `malloc`/`free`, no `-lgc`, no shim) — all the
  work is compile-time analysis plus the inserted `free` calls.
- **Implicit layer**: every unannotated `let`/`const` local whose flow
  passes the same escape check, whose type is freeable, and whose
  initializer is *provably fresh* (array/object literal, `new
  Map/Set/Array`, closure literal, interpolated template, concatenation, or
  a fresh-result builtin container method / `JSON.parse`) is treated as
  implicitly `@free`: freed at its declaring block's exit. A candidate that
  fails any gate is silently skipped — it leaks, exactly as every value
  does in manual mode. No annotation, no claim, no error.
- The implicit initializer gate is stricter than the annotation's: a plain
  call result is *not* accepted (a user function could return a shared or
  global pointer), where an explicit `@free` accepts it as the user's
  ownership assertion.
- **`Memory.free(x)` is a compile error under `-mm=auto`** (TDD-00001's
  exclusivity rule): the compiler owns every free in this mode, and a
  manual call it cannot plan for would reintroduce the double-free hazard
  that the per-variable check solves in the other modes.
- `var` declarations are never implicit candidates (function-scoped
  hoisting doesn't match block-exit placement).

## Consequences

- A plain, annotation-free program gets loop-churn freeing for free: the
  RSS churn test allocates ~160MB across 300k iterations and stays under
  ~2MB peak RSS under `-mm=auto` (78MB+ under manual), with identical
  output — inserted frees are never observable.
- Conservatism is the safety story: the failure mode of every gate is a
  leak, never a use-after-free. Coverage grows by auditing whitelist
  entries, not by loosening the analysis.

## Verification

- `tests/memory_auto_test.go`: `TestE2EMemoryAutoModeBansMemoryFree`,
  `TestE2EMemoryAutoModeImplicitParity` (same source, manual vs auto,
  byte-identical output), and `TestE2EMemoryAutoModeBoundsMemory`
  (RSS-bounded churn, the `TestE2EGCModeBoundsMemory` pattern with a 30MB
  bound on ~160MB of churn).
- Verified on the Mac (Apple Silicon); Linux runs the same libc path.
