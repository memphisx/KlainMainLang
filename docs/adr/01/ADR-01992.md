# ADR-01992: Five Test262 programs with invalid IR, and the bugs behind them

- **Relations**: Implements TDD-00230
- **Date**: 2026-11-20

## Context

The Linux x86-64 js-lane Test262 run compiled five programs to invalid IR
(each one fails to compile, and invalid IR blocks a delivery). Each traced
to its own bug:

1. `new Array(k)` / `Array(k)` with `k` a hoisted `var` read where it may
   still be undefined (a number with a presence flag, `{ i1, double }`):
   the length check compared the pair as a `double`.
2. `s.replace(false, x)` with `x` known only at run time: the function arm
   of the run-time replacement passed the boolean search on unconverted.
3. A class declared in a function, reading a local holding a Map, Set,
   ArrayBuffer or Date: the hidden field carrying the local was typed
   `any`, while its uses were checked at the local's own type (strict: a
   compile error, "value is not a Map or Set"; js: invalid IR).
4. The same read in a class whose base is a run-time value: the private
   read's two arms meet as an `any`, used as the field's type unconverted.

Finding them surfaced two more. A method a wrapper object (`new
Boolean`) holds as its own property ran with the wrapper's property bag as
`this`, and a builtin method of the same name (`o.replace =
String.prototype.replace`) took the native string path instead of the
function stored there. And the constructor of a subclass of a run-time
base could not read its captured locals: the object the base builds
becomes `this`, but the hidden fields were left on the instance allocated
for the class, and the definitions that run after `super()` were skipped
for a run-time base.

## Decision

1. A nullable number length takes its payload for a typed array; an
   `any[]` boxes it, so `new Array(undefined)` is `[undefined]`, as in Node.
2. The callback form of replace ToStrings a non-string search, as the
   string-replacement form does.
3. A captured local's hidden field takes the type the `new` gives it (Map,
   Set, WeakMap, WeakSet with their type arguments or `any`; ArrayBuffer,
   SharedArrayBuffer, Date), or the checked type of a non-generic builtin
   made elsewhere (a helper returning an ArrayBuffer).
4. A private field read through the override branch converts to the
   field's type.
5. A method call on an `any` passes the receiver itself as `this` to the
   function the property read finds; when a wrapper holds a builtin
   method's name as its own property (`__kml_wrapper_own`), the call goes
   through that property, not the native method.
6. After `super()` to a run-time base, the object `this` became takes the
   hidden capture fields from the allocated instance, and the private
   definitions run whenever `this` may be another object.

## Verification

All five programs compile (they now fail at run time on features not yet
supported: `Iterator.zip`, `transferToImmutable`, TypedArray species).
Tests, each compared with Node: `TestE2EJSNewArrayNullableLength`,
`TestE2EJSReplaceNonStringSearchCallback`, `TestE2EJSWrapperOwnMethodThis`,
`TestE2EClassCapturedBuiltinLocal`, `TestE2EStrictClassCapturedMap`,
`TestE2EJSValueBaseCtorReadsCaptures`, `TestE2EJSClassCapturedHelperBuffer`.

7. A class-valued base (`extends C`, `C` a class) builds its own instance,
   given the subclass's prototype. A private brand or layout check reads
   the class tag only, not that prototype chain (it took the base's
   instance for one with the subclass's layout and read past it), and a
   run-time base's subclass counts as one whose `this` may be another
   object, so its methods read its private fields from the private table
   (`TestE2EJSClassValueBaseLayout`).
