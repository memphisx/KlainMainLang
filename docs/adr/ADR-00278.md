# ADR-00278: Sync `[Symbol.iterator]()` protocol for `for...of` and `for await...of`

- **Relations**: Extends [ADR-00269](ADR-00269.md) (`[Symbol.asyncIterator]` classes), [ADR-00063](ADR-00063.md) (structural `next(): T | null` for-of)
- **Date**: 2026-08-21

## Context

Sync `for...of` dispatched a class iterable only structurally, on a
`next(): T | null` method; the spec's real protocol — a `[Symbol.iterator]()`
method returning an iterator whose `next()` yields `{value, done}` — was not
recognized (`[Symbol.iterator]` as a class member name was a hard parse
rejection), and `for await` couldn't consume such an iterable either. The
`{value, done}` shape also matters semantically: the `T | null` sentinel can't
yield a legitimately-null element, which the spec protocol can express.

## Investigation

- `parser/parser_classes.go`'s `wellKnownSymbolMemberName` desugared only
  `Symbol.asyncIterator` (to the unlexable reserved key `@@asyncIterator`);
  `Symbol.iterator` was deliberately rejected.
- `emitForAwaitOfAsyncIterable` (`codegen/llvm/emit_generators.go`) already had
  the exact loop needed — get-iterator call, `{value, done}` field reads —
  modulo the per-step promise await.

## Decision

- The parser desugars `[Symbol.iterator]` to `@@iterator` alongside
  `@@asyncIterator`.
- **`emitForOfSymbolIterator`** mirrors `emitForAwaitOfAsyncIterable` for the
  sync protocol: call `@@iterator` (an ordinary class-method call), validate
  the returned class instance's `next()` — zero-arg, returning a non-promise
  object with `value` and `done` fields — and loop on it. `return this`
  self-iterators and separate per-loop iterator objects both work (a second
  loop over the same iterable gets a fresh iterator).
- One emitter serves both loops via an `isAwait` flag: sync `for...of`
  dispatches `@@iterator` *before* the structural `next(): T | null` check
  (the explicit protocol wins), and `for await` accepts the same iterable,
  awaiting each value before binding (identity for a plain value, a real await
  for a promise value via [ADR-00277](ADR-00277.md)'s `emitAwaitPromiseElem`).

## Implementation notes

- `parser/parser_classes.go`: `wellKnownSymbolMemberName` returns `@@iterator`
  for `Symbol.iterator`.
- `codegen/llvm/emit_generators.go`: `syncIteratorMethodName`,
  `emitForOfSymbolIterator`.
- `codegen/llvm/emit_stmts.go`: both dispatch sites (sync class branch, and the
  `s.Await` class branch after `@@asyncIterator`).
- A `next()` returning a Promise on an `@@iterator` iterator is a clean
  rejection pointing at `[Symbol.asyncIterator]` instead.

## Side effects discovered

- `TestE2EComputedNonConstantNameRejected` asserted `[Symbol.iterator]` in a
  class body is rejected — updated to use a genuinely dynamic key (`[k]()`),
  which stays a clean rejection.

## Verification

- New E2E: `TestE2EForOfSymbolIterator` (self-iterator, separate iterator,
  fresh-iterator-per-loop), `TestE2EForAwaitOverSymbolIteratorClass`.
- `examples/async/for_await_iterables.ts` exercises `Countdown` in both loops.
- `go build`, `go vet ./...`, full `go test ./...` green; `make examples` and
  `make conformance` run at delivery. Apple Silicon (macOS).
