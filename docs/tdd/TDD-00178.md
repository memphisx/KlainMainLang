# TDD-00178: `path.win32` — Windows path semantics, per-host default, and explicit `path.posix`/`path.win32`

- **Status**: Implemented
- **Date**: 2026-09-06

## Context

The `path` module (`emit_path.go`, `runtime_path.go`) is POSIX-only: `/` is
the only separator, `path.sep` is the constant `/`, `path.delimiter` is `:`,
and `isAbsolute` is `p[0] === '/'`. That was correct while the compiler only
ran on Linux and macOS ("no cross-compilation, so no Windows form is ever
needed", `docs/status/PATH.md`). Since [TDD-00177](TDD-00177.md) the
compiler runs on Windows, and there the faithful behaviour is Node's:
`path` **is** `path.win32` on Windows — `\` separator, `;` delimiter, drive
letters, UNC roots, mixed-separator input — while `path.posix` stays
available. TDD-00177's faithfulness catalog lists this as the open Stage 1
item; ADR-00719 shipped everything else in that stage. A Windows user
calling `path.join('C:\\Users', 'me')` today gets `C:\Users/me`, which Node
on Windows never produces.

Node also exposes **both** flavours on every platform (`path.posix.*` and
`path.win32.*` work on Linux), which is what makes this testable without a
platform switch: the win32 algorithms can be exercised on the Linux CI lane
and on the Mac through the explicit `path.win32` object, and the per-host
default only flips which flavour a bare `path.X` dispatches to.

## Design

### Surface

| Expression | Linux/macOS | Windows |
|---|---|---|
| `path.join/resolve/dirname/basename/extname/isAbsolute/parse/format`, `path.sep`, `path.delimiter` | posix flavour (unchanged) | **win32 flavour** |
| `path.posix.<same>` | posix | posix |
| `path.win32.<same>` | win32 | win32 |

The method set is the module's existing surface. `normalize`, `relative`,
`toNamespacedPath` and `matchesGlob` are not added by this TDD for either
flavour (they are missing from the posix flavour today as well; adding them
is a separate, symmetric piece of work — see Open questions).

### Where the win32 algorithms live: three options

**Option A — port into hand-written LLVM IR**, alongside the posix
helpers in `runtime_path.go`. Rejected: the win32 `resolve`/`normalize`
pair alone is ~350 lines of index arithmetic with a dozen early returns
(UNC, device roots, reserved device names, drive-relative paths); as IR
text that is several thousand lines nobody can review against Node's
source.

**Option B (chosen) — an embedded C sidecar, `codegen/llvm/pathsrc/path_win32.c`,
a function-by-function port of Node's `lib/path.js` `win32` object.**
Same mechanism as `jsonsrc/json_parse.c` and `urlpatternsrc/urlpattern.c`:
`//go:embed`, listed in `EmbeddedCSources()` when the program used any
win32-flavoured call, compiled with the program on every host (pure string
code, libc only, no platform headers). Reviewable side by side with Node's
JS, and the same C runs on Linux, macOS and Windows, so the Docker lane
tests the exact code the Windows default uses.

**Option C — move the posix flavour to C too**, one file with both
flavours. Deferred: the posix IR is tested and shipped; rewriting it buys
consistency but no behaviour. Noted as a follow-up so the two flavours
can converge later without a second design pass.

### C ABI

Strings cross the boundary as this compiler's heap strings
(TDD-00120: `[i64 len][bytes][\0]`, value pointer at base+8). Inputs are
read with `strlen` (Node validates paths are strings; embedded NULs are
out of scope for both flavours). Outputs are freshly allocated with the
same header, the idiom `json_parse.c`'s `__kml_json_string_dup` uses.

```
char *__kml_path_win32_join(int64_t n, char **segs);
char *__kml_path_win32_resolve(int64_t n, char **segs, char *cwd, int host_is_windows);
char *__kml_path_win32_dirname(const char *p);
char *__kml_path_win32_basename(const char *p, const char *suffix /* NULL = none */);
char *__kml_path_win32_extname(const char *p);
int   __kml_path_win32_is_absolute(const char *p);
void  __kml_path_win32_parse(const char *p, char **root, char **dir, char **base, char **ext, char **name);
char *__kml_path_win32_format(const char *root, const char *dir, const char *base, const char *ext, const char *name);
```

`join`/`resolve` are variadic in Node; the call site's argument count is
known at compile time, so the emitter fills an entry-block `[N x ptr]`
alloca and passes `(n, ptr)`. `resolve` takes `process.cwd()` from the
emitter (the existing `__kml_process_cwd`) rather than calling it itself,
so the sidecar has no dependency on the process runtime; the per-drive
current directory Node reads from `process.env['=C:']` is read with
`getenv("=C:")` inside the sidecar (the Windows CRT exposes those hidden
variables; on other hosts `getenv` returns NULL and Node's fallback to
`cwd` applies). `host_is_windows` reproduces the one place Node's win32
code branches on the host: `resolve()` with no arguments on a non-Windows
host returns `cwd` with `/` replaced by `\`.

### Emitter dispatch

`emit_call.go` currently matches `path__kml_builtin.<method>`. The member
expression gains one more shape: `path__kml_builtin.posix.<method>` and
`path__kml_builtin.win32.<method>`. A small resolver, `pathFlavorOf(objExpr)`,
returns `(flavor, ok)`: the bare marker maps to the host default
(`runtime.GOOS == "windows"` → win32, the same compile-time switch
`emit_os.go` uses for `process.platform`), the two-level form maps to the
named flavour. Each existing `emitPath*` function takes the flavour and
either runs the existing IR path or emits the sidecar call. `sep` and
`delimiter` (member reads in `emit_exprs_member.go`, types in
`emit_exprs_types.go`) follow the same table: `\`/`;` for win32.

The resolver's virtual-module member list (`resolver/virtual_modules.go`)
gains `posix` and `win32` so `import { win32 } from 'path'` and
`path.win32` both bind.

`parse` returns the existing `PathParsedType()` object; `format` reads the
same five fields and, for win32, hands them to the sidecar (`_format` with
`\`).

### Faithfulness notes (what the port must preserve)

- Mixed separators are accepted everywhere and normalised to `\`.
- `join` keeps a trailing separator (`join('foo', 'bar\\')` is `foo\bar\`);
  the posix flavour's known trailing-slash caveat is **not** carried over.
- `resolve` walks right to left, keeps the last device seen, and produces
  a drive-relative result (`C:foo`) when no absolute segment was given for
  that device — exactly Node, including the `|| '.'` for an empty tail.
- `basename`, `extname` and `parse` skip a leading `X:` device before
  scanning; `basename` keeps Node's asymmetric suffix rule (ADR-00368).
- `normalize`'s reserved-device handling (`CON`, `COM1`, `\\.\`, `\\?\`)
  is ported because `join` depends on it, even though `normalize` itself
  is not exposed by this TDD.

### Tests and examples

- Every existing `TestE2EPath*` gets a Windows expectation (backslash
  forms) under `runtime.GOOS == "windows"`, the convention ADR-00719 set.
- New `TestE2EPathWin32*` and `TestE2EPathPosix*` tests use the explicit
  objects and run **unconditionally on every host** — they are the tests
  that exercise the C port on the Linux and macOS lanes.
- `examples/path/path_win32.ts` exercises `path.win32` explicitly, so its
  output is host-independent; `examples/path/path.ts` drops its
  "POSIX-only" framing.

goes away; every row's notes mention both flavours; two new rows for

## Open questions

1. **`normalize`/`relative`/`toNamespacedPath` for both flavours.** Not in
   the module today. `normalize` is implemented inside the sidecar for
   `join`'s sake and could be exposed for win32 in one line, but exposing it
   for win32 only would be an asymmetric surface; do both flavours together.
2. **Converging the posix flavour onto C (Option C).** Worth doing when the
   posix trailing-slash caveat is fixed, since that fix is a rewrite of
   `__kml_path_normalize` anyway.
3. **`path.win32.resolve` on a non-Windows host with a POSIX `cwd`.** Node
   produces the same odd-looking result this port will (`/home/me` is
   treated as a rooted path with no device: `\home\me\foo`); faithful, and
   nobody should rely on it, but worth a caveat line in the status row.
