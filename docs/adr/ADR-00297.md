# ADR-00297: `WritableStream<T>` — writer lock, serialized sink writes, `ready` backpressure

- **Relations**: Implements [TDD-00097](../tdd/TDD-00097.md) Stage 2; extends [ADR-00296](ADR-00296.md)
- **Date**: 2026-08-22

## Context

TDD-00097 Stage 2: the writable half of the WHATWG pipeline — a write queue
with high-water-mark accounting, one-at-a-time sink writes (the spec's
in-flight write), and the `writer.ready` promise as the backpressure signal.

## Investigation

The readable side's architecture (ADR-00296) transfers directly: one fused
144-byte struct became a 128-byte `%kml.wstream` (runtime_streams_writable.go)
fusing stream + controller + writer, retyped at compile time
(`IsWritableStream` / `IsStreamWriter` / `IsWSController`). The one structural
difference: each queued write carries its **own** promise (32-byte entries
`{v0, v1, size, prom}`) — a reader FIFO is unnecessary, a per-entry promise
is.

`ready` exploits reusable promises (ADR-00270) in the spec's own shape: the
current ready promise is *replaced* with a fresh pending one when desiredSize
drops to ≤ 0, and settled fulfilled when it recovers — an old reference held
across a flip observes its own settled state, exactly as in JS.

## Decision

- `__kml_ws_advance` is the drain loop: while writable, started, and not
  in-flight, dequeue one entry and invoke the sink's normalized write wrapper
  (`ptr (env, i64 v0, i64 v1)` → the sink's promise or null); its settlement
  (via `__kml_promise_add_reaction`) settles the per-write promise, clears
  in-flight, and re-advances. A rejection errors the stream
  (`__kml_ws_error`): every queued write promise, `ready`, `closed`, and any
  pending `close()` promise reject with the sink's error.
- `close()` marks closeRequested and returns a close promise; the drain loop
  runs the sink's close once the queue empties, then settles closed +
  close promises fulfilled. `abort(reason)` errors the stream with the
  reason, runs the sink's abort, and returns its promise (or fulfilled).
- `write()` never blocks: it enqueues and returns the per-write promise;
  writing to a closing/closed stream throws a TypeError at the call site
  (null-promise sentinel), an errored stream returns a rejected promise.
- Sink `{start, write, close, abort}` and the strategy are destructured at
  compile time (`emit_streams_writable.go`), sharing Stage 1's strategy
  resolver, size wrappers, and start timing (started flag via microtask or a
  reaction on an async start).

## Implementation notes

New files `runtime_streams_writable.go` / `emit_streams_writable.go`; the
usual builtin wiring (AST node, parser, rename walk, scanExprFV, types,
resolveType, emit_call/member/vardecl/inferExprType dispatch). The
readable/writable constructors now share `parseNewStreamArgs` (parser) and
`resolveStreamStrategy` (codegen). Struct-IR names in the newest runtime file
are substituted by a string replacer rather than positional `%s` — two
positional-argument slips in this stage's IR motivated the change.

## Side effects discovered

- `writer.desiredSize` on an errored stream reports 0, not `null` (same
  Stage 1 caveat shape); a synchronously-throwing sink write propagates to
  the advance caller instead of erroring the stream (async rejection is
  handled properly) — both recorded in STREAMS.md.

## Verification

`tests/streams_test.go` Stage 2 block: basic write/close/closed, slow async
sink proving writes never overlap, `ready` re-arm across a backpressure flip
with desiredSize spot-checks, sink rejection rejecting both the write and
`closed`, abort rejecting queued writes and running the sink's abort. Full
`go test ./...` green (Mac).
