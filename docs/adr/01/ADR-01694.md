# ADR-01694: Property attributes on typed objects and Errors

- **Relations**: Implements TDD-00230
- **Date**: 2026-10-18

## Context

TDD-00230 P3.3. `Object.defineProperty` on a typed object's declared field was a compile error ("requires a dynamic (any-typed) object"). On an Error it was accepted, but:
- `writable` and `configurable` were ignored;
- a descriptor without `value` overwrote the property with undefined;
- `getOwnPropertyDescriptor(e, 'message' | 'cause')` was undefined.

A static layout has no room for per-property attributes.

## Decision

**A side record.** An object whose attributes were ever defined gets a record in a map keyed by its address (`propattrsrc/propattr.c`, beside the frozen set in `collections.c`, kept the same way under `-mm=gc`). The record lists `(name, attrs)` for each property that is not plain: not writable, not enumerable, not configurable. It is keyed by name, so C readers that know only a run-time key consult it as well: the descriptor reader and the dynamic delete.

**`defineProperty` on a declared field** reads the descriptor's attributes and validates them as `ValidateAndApplyPropertyDescriptor` does (`__kml_pattr_define`):
- a new key takes false for each attribute left out;
- a non-configurable key may not become configurable;
- it may not change its enumerability;
- it may not become writable again;
- once it is not writable, its value may not change (SameValue).

A rejection throws `TypeError: Cannot redefine property: k`. Otherwise:
- the value, when the descriptor gives one, is stored in the field;
- the key exists afterwards (its presence bit).

An accessor descriptor on a declared field remains a compile error.

**Readers.** Only a program that calls `defineProperty`/`defineProperties` pays (`propAttrsUsed`, an AST prescan); every other program's code is unchanged.
- **Writes:** a write to a non-writable property throws the strict-mode TypeError (`Cannot assign to read only property 'k' of object '#<Object>'`, an Error named by its string), as a frozen object's write already does: a program runs as a module.
- **Enumeration:** `Object.keys`/`values`/`entries`, for…in, `JSON.stringify`, inspect and spread skip a non-enumerable key.
- **Spread result:** a spread that skips a required key, because it is not listed or because the source lacks it, leaves it absent in the result unless the literal wrote it earlier. A later write in the literal makes it present again.
- **Delete:** deleting a non-configurable property throws `Cannot delete property 'k' of …`, through the typed or the dynamic delete. A deleted property's attributes are forgotten.
- **Descriptors:** `getOwnPropertyDescriptor` reports the record's attributes on a typed object.

**Errors.** `__kml_error_own_desc` (`errkeys.c`) gives an Error's own descriptors:
- `message`, when the constructor was given one;
- `cause`, when its option was given;
- `stack` and an own `name`, all non-enumerable;
- the system fields and extra-bag entries, enumerable as listed.

`defineProperty` on an Error validates and records the attributes before storing a value, and stores none when the descriptor gives none.

Not covered: `{ cause: undefined }` (an explicit undefined cause) reads as no cause, because its slot holds undefined either way.
