# ADR-00742: Windows socket fidelity — full WSA→errno table and IPv6 dual-stack default

- **Relations**: Implements two rows of [TDD-00180](../tdd/TDD-00180.md) §5; extends [ADR-00719](ADR-00719.md) (the Win32 socket layer), [ADR-00684](ADR-00684.md) (`err.code` on errors)
- **Date**: 2026-09-07

## Context

Two §5 rows, both affecting the REST client/server surface that is the project's top feature priority.

**WSA→errno.** `map_wsa_errno` (`win32io.c`) carried nine entries and defaulted everything else to `EINVAL`. So `WSAEHOSTUNREACH`, `WSAENETUNREACH`, `WSAEACCES`, `WSAEADDRNOTAVAIL`, `WSAEMFILE`, `WSAENOBUFS`, `WSAEISCONN`, `WSAEMSGSIZE`, `WSAEAFNOSUPPORT`, and the rest all surfaced to a program as `err.code === 'EINVAL'` — "invalid argument" for an unreachable host or an exhausted descriptor table. Node reports the true code on every host.

**IPv6 dual-stack.** Windows defaults a fresh `AF_INET6` socket to `IPV6_V6ONLY = 1`, so a `::` listener refuses IPv4 (and IPv4-mapped) clients. libuv/Node clear it by default (`ipv6Only` opt-in re-sets it), so a Node `::` server answers both families; the shim did nothing, leaving the Windows default.

## Decision

- **`map_wsa_errno`** now mirrors libuv's `uv_translate_sys_error`, mapped to the Linux errno numbers the IR and the errno→code table already speak: 30-odd `WSAE*` cases (`EHOSTUNREACH`, `ENETUNREACH`, `EADDRNOTAVAIL`, `ECONNABORTED` distinct from `ECONNRESET`, `ENOBUFS`, `EISCONN`, `EMSGSIZE`, `EOPNOTSUPP`, `EAFNOSUPPORT`, `EACCES`, `EMFILE`, …). The Linux errno constants were added to the shim's enum, and the matching numbers to `linuxErrnoPairs` (the Windows errno→code table in `runtime_fs.go`), so `err.code` on a network error now matches Node. `WSAECONNABORTED` was folded into `ECONNRESET` before and is now its own `ECONNABORTED`.
- **`socket()`** clears `IPV6_V6ONLY` (setsockopt `IPPROTO_IPV6`/`IPV6_V6ONLY = 0`) on every `AF_INET6` socket right after creation, so a `::` listener is dual-stack by default as on the other platforms. A program that wants v6-only can still set the option itself afterwards.

## Consequences

- No new E2E test: the current `http.listen`/`net.listen` path binds `127.0.0.1` (IPv4) only, so neither change is reachable through the high-level API yet — the v6only clear is inert until `::`-listen support lands, and the errno table needs a specific network failure that is not deterministically reproducible on the dev box (its loopback is traffic-filtered — see the project notes). Both are additive and correct by construction: the errno table only adds cases and codes, the v6only clear only touches `AF_INET6` sockets.
- Verified: `win32io.c` compiles clean against both the dev box's headers and the CI runner's r353 set; `go build`/`go vet` clean; the full net/http/dgram/socket E2E suite passes on Windows 11 with no regression.
- When arbitrary-host / `::` listen lands, the dual-stack test becomes possible and should be added then; the errno table will be exercised by any test that induces a real `WSAE*` failure with AdGuard disabled.
- Still open in §5: `SO_SNDBUF`/`SO_RCVBUF`/`SO_LINGER`/`TCP_KEEPIDLE` constant translation, `MSG_PEEK` semantics, and named-pipe (`\\.\pipe\…`) support.
