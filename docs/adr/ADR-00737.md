# ADR-00737: Windows process/socket hardening, and the shim header drift made structural

- **Relations**: Implements the security-flavoured rows of [TDD-00180](../tdd/TDD-00180.md) §3/§5; extends [ADR-00734](ADR-00734.md) (the first shim/header-drift fix — this one removes the conflict class), [ADR-00719](ADR-00719.md) (the Win32 platform layer), [ADR-00728](ADR-00728.md) (`process.kill` semantics)
- **Date**: 2026-09-07

## Context

Two threads land together because the CI lane forced the first one open.

**The Windows lane was still red after ADR-00734** (run 34067299691): `win32fs.c` no longer trips on the `S_IF*` macros, but the runner's newer mingw-w64 headers now *declare* `stat`, `fstat`, `mkdir`, and `getcwd` — pulled in transitively, with prototypes that differ from the shim's (`struct stat` vs the glibc-layout `kml_stat`; one-argument `mkdir`) — so the file fails with "conflicting types" on the runner while compiling cleanly on the dev box's older headers. And per ADR-00734's recorded side effect, a shim compile failure only *warned*: every one of 404 test failures surfaced as pages of `undefined reference to swapcontext/...` at link, 50 minutes in.

**TDD-00180's security rows** (§3/§5) were the next scheduled work: the cluster IPC `socketpair` accepted whatever connected first on 127.0.0.1; `SO_REUSEPORT` was emulated with Winsock `SO_REUSEADDR`, which lets any local process bind over the port (the exact hijack the `SO_REUSEADDR→SO_EXCLUSIVEADDRUSE` mapping in the same switch exists to prevent); `kill()`/`waitpid()` on an already-reaped child fell back to `OpenProcess(pid)` and could reach an unrelated process that reused the pid; the spawn marker `KML_WIN_INHERIT_FD` left a raw handle value readable in the child's CRT environment; and `bInheritHandles=TRUE` inherited every inheritable handle in the process rather than the four meant for the child.

## Decision

**Header drift, structurally:** the four colliding functions are defined under shim-local C names with an explicit assembly symbol (`int kml_win_stat(...) __asm__("stat")`). The object still exports `stat`/`fstat`/`mkdir`/`getcwd` for the emitted IR, but no header prototype can ever conflict again, whatever a future mingw-w64 release declares. Overrides whose prototypes match the CRT's (`unlink`, `rename`, `access`, …) stay as they are — a matching declaration is harmless.

**Fail fast:** a shim compile error now prints as an `error:` and appends a sentinel object path (`WIN32-SHIM-COMPILE-FAILED-see-error-above.o`) to the link, so the very first compile stops immediately with the real C error adjacent — not hundreds of misleading link failures. (The sentinel keeps `HostClangArgv`'s signature; the E2E helpers call it in-process, so it cannot exit.)

**Hardening:**
- `socketpair` verifies the accepted peer: `getpeername(accepted)` must equal the connecting socket's own `getsockname` (loopback address and port), retrying a bounded 16 accepts and failing closed otherwise.
- `SO_REUSEPORT` is accepted and ignored. Windows cluster workers never bind — they inherit the primary's listening socket (`httpListenInheritIR`) — so the Winsock-`SO_REUSEADDR` emulation protected nothing and exposed the port.
- The child table keeps reaped entries (`reaped` flag, handle closed) instead of freeing the slot: `kill()` — signal 0 included — and a second `waitpid()` of a reaped pid answer `ESRCH`/`ECHILD` from the table, never `OpenProcess(pid)`. libuv's `uv_kill` answers `UV_ESRCH` for an exited child the same way. Reaped slots are recycled only when the 256-entry table needs room, so the guard window is the table's depth, not unbounded. Also fixes a `WNOHANG` handle leak on the untracked-pid path.
- The child scrubs `KML_WIN_INHERIT_FD` from the CRT snapshot too (`_putenv`), not just the Win32 block — the CRT copies the environment before the adopting constructor runs, so `process.env` could still see the raw handle value.
- `CreateProcessW` passes `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` naming exactly the child's std handles (+ the inherited socket); `bInheritHandles=TRUE` no longer ships every inheritable handle in the process. Std slots the caller wants passed through are now inheritable *duplicates*, with a missing/invalid parent handle replaced by `NUL` (libuv's replacement) — a GUI-subsystem parent hands its children usable fds 0/1/2. If the attribute list cannot be built the spawn falls back to the previous wide inherit rather than failing.

## Consequences

- `tests/childprocess_kill_reaped_test.go`: kill-after-reap throws on every host (POSIX gets the OS's own `ESRCH`).
- The socketpair race and the handle-list narrowing have no deterministic E2E trigger; their regression coverage is the existing child_process/cluster/worker suites, which exercise both paths on every spawn.
- The `SO_REUSEPORT` change makes a Windows worker that *did* try to bind a fresh in-use port fail with `EADDRINUSE` instead of silently sharing — the faithful outcome.
- Verified on Windows 11 x86-64 (this box, MSYS2 clang — the runner's compiler); the asm-label fix is expected to be confirmed by the next runner build against its newer headers, the same way ADR-00734's was.
