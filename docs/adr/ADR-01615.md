# ADR-01615: The runtime's C resolves on its own: hooks.c

- **Relations**: Implements TDD-00251 (Stages 4–5), Extends ADR-01612
- **Date**: 2026-10-13

## Context

ADR-01612 added the guard that lists, for one program reaching most of the
runtime, every `__kml_` symbol a runtime object leaves undefined and no
runtime object defines, with 59 such symbols allowed by a list that was to
shrink to nothing. Each is something the program generates: thread-local
state the C reads (the connection fibers', the current task, the curl
multi handle), per-program values (interned error names compared by
address, two type ids), routines the C calls (the dynamic-value
conversions, inspection of classes, errors and promises, the HTTP loop's
per-pass callbacks, AbortSignal, throws, Worker hooks), and the NaN-box and
string-header primitives. A runtime object that names one links only
because the program happens to define it.

## Investigation

- TDD-00251's design: data the runtime reads is the runtime's; generated
  code the runtime calls is a hook in a table the program registers into
  from a constructor, with a default for programs without it.
- `libsplit.go` gives an internal definition external linkage when another
  unit names it, so internalizing the program's copy of a hook would put
  two definitions of one name in a lazy-import link; renaming the
  program's copy avoids both.
- Some of the 59 are defined by runtime C (`dynimportwatch.c`'s three loop
  hooks, `task.c`'s GC restore, `fetchbodyprom.c`'s drain) and were reached
  through weak stubs, which COFF resolves as undefined weak externals; three
  more (`__kml_ctx_release`, `__kml_current_rss_bytes`, `__kml_os_homedir`)
  are the Windows shim's, which the guard did not compile.
- A constructor list emitted before the last finalize steps would miss a
  hook those steps define (`__kml_process_uncaught`).

## Decision

- **`hookssrc/hooks.c`**, linked into every program:
  - defines the data (`__kml_main_ctx`, sized by `-DKML_MAIN_CTX_SIZE` from
    `ucontextLayout`, the `__kml_conn_*` state, `__kml_current_task`,
    `__kml_root_async_ctx`, `__kml_curl_multi`, `__kml_curl_inited`,
    `__kml_listen_fd`, `__kml_listen_dispatch`, `__kml_cluster_close_flag`,
    `__kml_cluster_primary_pid`)
    and holds the per-program values (`__kml_fetch_strs`, the two view type
    ids); the IR declares them `external`, and the program's constructor
    stores the values;
  - defines `__kml_nb_pack/tag/pay` and `__kml_str_alloc/len/free` in C;
  - defines, for each generated routine the C calls, a trampoline under its
    name that calls through `__kml_hookp_<name>`, initialised to a default:
    what a program without the feature observes (no listener, no signal
    aborted, no per-pass work), or an internal error where the C cannot be
    reached without it;
  - holds C-to-C hook pointers (`__kml_hook_<name>`) that a runtime file
    registers from its own constructor when linked: the dynamic-import
    loop hooks, the task GC restore, the body-promise drain.
- **The IR** renames its copies of the hooks and primitives `__kml_ir_<name>`
  at the very end (`renameHooks`), so its own calls stay direct and
  inlinable, and registers each hook it defines from `@__kml_hooks_init`.
  The constructor list is emitted last (`emitCtorList`), after every
  finalize step.
- The IR stubs for the dynamic-import hooks go; `fetch.c`'s weak stubs go.
- **The guard** compiles the Windows shim too and fails on any undefined
  `__kml_` symbol; the allow-list is deleted.

## Implementation notes

- `codegen/llvm/hookssrc/hooks.c`, `runtime_hooks.go` (the hook and
  primitive lists, registration, renaming); `embedded_c.go` links it first.
- `unitreg.go` (`emitCtorList`), `emitter.go`.
- Data declarations: `runtime_http.go`, `runtime_fetch.go`,
  `runtime_spawn_win.go`, `emit_task_classify.go`, `runtime_views.go`.
- C: `fetch.c`, `task.c`, `fetchbodyprom.c`, `dynimportwatch.c`, `loop.c`,
  `views.c`.
- A hook's trampoline signature is the C's (`u8` for an `i1` result, as the
  C callers already read it).

## Side effects discovered

None.

## Verification

Windows 11 (this machine): `TestRuntimeSymbolsResolveWithinRuntime` with no
allow-list, and targeted E2E runs over the hooked features. Linux (Docker,
`klain-ci`): the full E2E suite; the guard found one POSIX-only symbol
(`__kml_cluster_primary_pid`, the cluster's fork bookkeeping), now hooks.c's.
