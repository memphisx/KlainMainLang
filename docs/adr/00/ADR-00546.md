# ADR-00546: Array.sort default is lexicographic (JS-faithful)

- **Relations**: Extends ADR-00152
- **Date**: 2026-09-01

## Context

`arr.sort()` with no comparator sorted numerically (`__kml_cmp_i64` /
`__kml_cmp_f64` — a plain `icmp`/`fcmp`). Real JS
`Array.prototype.sort` with no comparator converts every element to a string
and compares the strings lexicographically — even for numbers — so
`[10,1,21,2].sort()` is `[1,10,2,21]`, not the numeric `[1,2,10,21]`. This was
a disclosed caveat on the array-methods status page. This project's
faithfulness-first practice makes the observable JS behavior the target.

## Investigation

`emitQsortCall` (emit_arrays_sort.go) selects a default comparator by element
type. The string case (`__kml_cmp_str`) already does a lexicographic `strcmp`
— which IS the faithful default for strings; only the numeric branches
diverged. A JS-faithful double→string formatter already exists as
`__kml_dtoa` (float_fmt.go), and integer elements render with a plain `%lld`
via `sprintf`.

## Decision

Add two default-only comparators:

- `__kml_cmp_i64_lex`: renders each i64 element with `%lld` into a 32-byte
  stack buffer and `strcmp`s them.
- `__kml_cmp_f64_lex`: renders each double via `__kml_dtoa` and `strcmp`s.

`emitQsortCall`'s no-comparator branch now selects `_lex` variants for the
float and integer cases; the string case is unchanged (already lexicographic).
A custom comparator is unaffected — it still routes through the numeric
trampolines, so `sort((a,b) => a-b)` remains numeric.

## Implementation notes

- The two comparators live in runtime_collections.go next to the existing
  `__kml_cmp_*`; guarded by new `usedSortCmpI64Lex`/`usedSortCmpF64Lex` flags.
- 32-byte buffers cover the longest i64 (`-9223372036854775808`, 20 chars) and
  any `__kml_dtoa` output with room to spare.
- `toSorted()` shares `emitQsortCall`, so it inherits the faithful default for
  free.

## Side effects discovered

Single-digit numeric arrays are unaffected (lexicographic == numeric for
one-digit values), so the existing `TestE2EArraySort` assertions still hold.

## Verification

`TestE2EArraySortDefaultLexicographic` (`[10,1,21,2]` → `1,10,2,21`, floats and
negatives cross-checked against Node) plus the existing sort tests pass. The
`examples/arrays/sort.ts` example was updated to demonstrate the lexicographic
default and a numeric comparator, and runs correctly. Built and verified on
Mac (Apple Silicon).
