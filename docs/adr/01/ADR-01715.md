# ADR-01715: Flattening keeps undefined rows; `(x): T =>`; nested nullable array names

- **Relations**: `Implements TDD-00230`; `Fixes ADR-01065`
- **Date**: 2026-10-18

## Context

Three divergences, found together:

1. **flatMap fall-off.** A `flatMap` callback that can fall off the end was a compile error (BACKLOG #60). Separately, `.flat()` over `(T[] | undefined)[]` dropped the undefined rows. Node keeps each one as an element.
2. **Arrow return annotation.** `(x): T => …` (untyped parameters, then a return annotation) failed to parse. The lookahead for `(a, b): T =>` also guessed from a token scan, which takes `c ? (a) : (q: number): number => q` for an arrow.
3. **Nested nullable names.** A nested array type spelled as one name (`number[][] | undefined`) lost its `| undefined`, so an absent row printed as `[]`.

## Decision

1. Flattening a level that may hold an absent row (`flatHasAbsentRow`) boxes the rows and flattens them through the dynamic flatten (`__kml_anyarr_flat`); the result is `any[]`. Inference and emission agree on that.
2. A parenthesized group followed by `:` is an arrow only if a type parses from there and `=>` follows it. This is TypeScript's own speculative parse, using the parser's `rewind`.
3. The nested-name branch of `resolveType` keeps the nullable flags, like its siblings.

## Verification

macOS (Apple Silicon): these tests pass:
- `TestE2EFlatKeepsUndefinedRows` and `TestE2EJSFlatMapFallOff` (both against Node);
- `TestArrowUntypedParamReturnType`;
- the `Flat`, `Arrow`, `Nested` and `Array` E2E tests and the parser package.
