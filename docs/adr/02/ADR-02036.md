# ADR-02036: An assignment through a type assertion stores to the name

- **Date**: 2026-11-22

## Context

- After `let y: number | string = 1; (y as any) = "s"`, a read of `y` was
  converted as `number` (NaN). The store went through the assertion, so
  the binder saw no assignment to `y` and kept the narrowing to `number`.

## Decision

- `unwrapAssignedAssertions`, the first codegen lowering, rewrites an `=`
  whose target is a name under `as` and non-null assertions into a store
  to the name. An asserted target's right side is held through `as any`.
  The program's diagnostics were already reported on it as written.

## Consequences

- The narrowing after the store starts from the declared type, and the
  slot holds the value written.
- Tests: `TestE2EAssignThroughAssertionTS`.
