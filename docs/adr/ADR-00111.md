# ADR-00111: `performance.mark(name)` / `performance.measure(name, start, end?)`

- **Date**: 2026-08-06

## Context

Picked up as a same-day quick win, at the user's explicit request, after a UI-directions research pass ([TDD-00031](../tdd/TDD-00031.md)/[TDD-00032](../tdd/TDD-00032.md)/[TDD-00033](../tdd/TDD-00033.md)) surfaced it as one of three items already sitting in the Roadmap's "Low effort" tier — the only one of the three genuinely small enough to finish in the same session (`TextEncoder`/`TextDecoder` and `structuredClone` were judged bigger, see the discussion that led here). `docs/status/PERFORMANCE-TIMING.md` already documented `performance.now()` as done and `performance.mark`/`.measure` as the one remaining gap in that page.

## Decision

Implemented as a lazily-created `Map<string, number>` reusing the exact same `__kml_map_str_*` runtime helpers `console.count()` already uses internally (`ensureMapStrHelpers`) — never exposed as a KML-level `Map` value, just borrowed machinery, the identical pattern `ensureConsoleCountMap`/`emitConsoleCountMapEnsure` already established. A mark's timestamp (a `double` from the existing `__kml_performance_now()`) is stored in the map's `i64` value slot via `bitcast double ↔ i64` — a bit-pattern reinterpretation, not a lossy numeric conversion, valid since both types are the same 64-bit width.

**`performance.mark(name)`**: evaluates `name`, records the current `performance.now()` reading under it, returns `void`. Real `performance.mark()` returns a `PerformanceMark` object; not modeled here since there's no `getEntriesByName`/`PerformanceObserver` machinery for such an object to usefully belong to — the same class of V1 scope narrowing this project already applies elsewhere (e.g. `console.time`'s single-slot scope). Re-marking an existing name overwrites its timestamp (last-write-wins) rather than appending to a full ordered entries list, since the backing store is a plain map, not a list — documented explicitly as a scope narrowing, not an oversight.

**`performance.measure(name, startMark, endMark?)`**: returns the elapsed milliseconds between two marks as a plain `number`, not a `PerformanceMeasure` object (same reasoning as `mark()` above) — meaning `measure()`'s own `name` argument is evaluated (matching real JS's evaluation-order guarantee for side effects) but never stored anywhere, since nothing can look a measure entry up by name. `endMark` defaults to a fresh `performance.now()` reading when omitted, matching real `performance.measure()`'s own "no end mark means through now" default. Referencing a `startMark`/`endMark` that was never marked throws — real `performance.measure()` throws a `SyntaxError` for exactly this case; this reuses the existing generic `emitInternalThrow` path (dynamic message built via `sprintf`, same shape `emitConsoleTimeEnd`'s `"%s: %gms"` formatting already uses) rather than modeling a distinct `SyntaxError`-vs-other-kind subtype for it, since the existing exception machinery ([ADR-00082](../adr/ADR-00082.md)) already has one shared internal-error kind that's sufficient here.

## Implementation notes

Files touched:
- `codegen/llvm/emitter.go`: new `usedPerformanceMarkMap` state flag.
- `codegen/llvm/runtime_date.go`: new `ensurePerformanceMarkMap`, declaring the hidden `@__kml_performance_mark_map` global next to the existing `ensurePerformanceNow`.
- `codegen/llvm/emit_date.go`: new `emitPerformanceMarkMapEnsure` (lazy-create-on-first-use, the same alloca+branch+merge shape `emitConsoleCountMapEnsure` uses), `emitPerformanceMarkLookup`, `emitPerformanceMark`, `emitPerformanceMeasure`, `emitMissingMarkGuard`.
- `codegen/llvm/emit_call.go`: two new dispatch branches for `performance.mark`/`performance.measure`, alongside the existing `performance.now` one.
- `codegen/llvm/emit_exprs_types.go`: `inferExprType` widened so `performance.measure(...)` (like `performance.now()` already did) reports `TypeF64`, needed for `const d: number = performance.measure(...)` to type-check correctly.
