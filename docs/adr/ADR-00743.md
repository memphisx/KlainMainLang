# ADR-00743: Windows fs — FILE_SHARE_DELETE so an open file can be unlinked/renamed

- **Relations**: Implements the first row of [TDD-00180](../tdd/TDD-00180.md) §4; supersedes the Windows expectation in [ADR-00736](ADR-00736.md) (the sharing-violation test); extends [ADR-00719](ADR-00719.md) (the Win32 fs layer)
- **Date**: 2026-09-07

## Context

`open()` and `fopen()` in `win32fs.c` went through the CRT's `_wopen`/`_wfopen`, whose default share mode is `FILE_SHARE_READ | FILE_SHARE_WRITE` — **no `FILE_SHARE_DELETE`**. So while a program held a file open, `unlink`/`rename` of that path failed with a sharing violation. On POSIX (and in Node on every platform, because libuv opens with `FILE_SHARE_DELETE`) an open file can be unlinked and its name disappears while the descriptor stays valid — the atomic-replace and temp-file-cleanup idioms depend on it. ADR-00736's sharing-violation test documented the gap by asserting `EBUSY` on Windows and flagged this as the fix that would flip it.

## Decision

`open()` and `fopen()` now open through `CreateFileW` with `FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE`, then wrap the kernel `HANDLE` into a CRT fd with `_open_osfhandle` (and, for `fopen`, a `FILE*` with `_fdopen`), so the rest of the read/write/seek path is unchanged. A shared `open_shared` helper translates the POSIX open flags to `CreateFileW` parameters:

- access: `O_RDONLY`/`O_WRONLY`/`O_RDWR` → `GENERIC_READ`/`GENERIC_WRITE`/both; `O_APPEND` → kernel `FILE_APPEND_DATA` (not the CRT's seek-then-write, which also fixes the §4 `O_APPEND` row);
- disposition: `O_CREAT|O_EXCL`→`CREATE_NEW`, `O_CREAT|O_TRUNC`→`CREATE_ALWAYS`, `O_CREAT`→`OPEN_ALWAYS`, `O_TRUNC`→`TRUNCATE_EXISTING`, else `OPEN_EXISTING`;
- a file created without the write bit gets `FILE_ATTRIBUTE_READONLY`;
- the fd carries `_O_BINARY` (Node's fs is byte-exact) plus `_O_APPEND`/`_O_RDONLY` as applicable.

`fopen`'s stdio mode string (`r`/`w`/`a`, `+`, forced binary) is translated to the same flag set and an `_fdopen` mode. The CRT `_wopen`/`_wfopen` declarations are dropped.

## Consequences

- `tests/fs_errno_fidelity_test.go`'s sharing-violation test now expects `unlinked` on every host (was `EBUSY` on Windows) — verified on Windows 11 and Linux (Docker).
- The full fs/io E2E surface (open/fopen/read/write/append/fd/stat/rename/truncate/streams/JSON/sqlite) passes on Windows 11 with no regression; `win32fs.c` compiles clean against both the dev box's headers and the CI runner's r353 set.
- `O_APPEND` is now a real kernel append, so concurrent appenders don't clobber via a stale CRT file position — a latent §4 row fixed in passing.
- Still open in §4: `\\?\` long-path prefixing (paths ≥ 260 chars), and the missing calls (`fs.watch`, `utimes`, `link`, `fsync`, `ftruncate`, `copyFile`, `statfs`, junction symlinks).
