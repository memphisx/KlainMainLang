# ADR-00280: Deferred (non-blocking) drive for `.then` on a raw fetch `Promise<Response>`

- **Relations**: Supersedes [ADR-00258](ADR-00258.md)'s synchronous drive (the reaction machinery it added stands); extends [ADR-00270](ADR-00270.md) (Promise as a reusable value)
- **Date**: 2026-08-21

## Context

`fetch(u).then(f)` bridged the raw fetch handle to a task promise by driving the
transfer to completion *synchronously at the `.then` call site*
([ADR-00258](ADR-00258.md)). Chain ordering already matched JS (reactions ran as
microtasks), but the synchronous script blocked on the network before
continuing — `fetch(slow).then(f); console.log("x")` waited the full transfer
before printing `x`, where JS prints immediately. This was the documented caveat
on the `.then`/`.catch`/`.finally` status row.

## Investigation

- `emitFetchHandleToSettledPromise` (`codegen/llvm/emit_promise_then.go`) did
  the setjmp-guarded `__kml_await_fetch` drive inline and returned an
  already-settled promise; reactions then took the "source settled → enqueue
  now" attach path.
- The microtask queue is drained at every await point and at program exit, and
  `__kml_promise_settle` both wakes a parked awaiter and enqueues reactions
  attached while pending — so a promise that settles *from inside a microtask*
  is already fully supported (async generators settle exactly this way).
- The fetch transfer itself is started non-blocking at the `fetch()` call;
  only the completion wait was happening at `.then` time.

## Decision

Defer the drive to a queued microtask and hand `.then` a *pending* promise:

- **`ensureFetchDriveRunner`** emits `@__kml_fetch_drive_run(ptr %env)` once
  (raw global IR, the same closure shape every then-runner uses): env is
  `{ slot, prom }`; the runner drives `__kml_await_fetch` under a setjmp guard,
  builds the `Response`, stores it into `prom`'s value slot, and settles via
  `__kml_promise_settle` — fulfilled, or *rejected* with the thrown error on a
  transport-level failure (an HTTP 4xx/5xx stays a fulfilled `Response`, per
  WHATWG).
- **`emitFetchHandleToPendingPromise`** (replacing the synchronous bridge)
  allocates the pending task promise, enqueues the `{runner, env}` closure on
  the microtask queue, and returns the promise; `.then`/`.catch`/`.finally`
  attach through the normal pending-reaction path.
- The fetch slot is **no longer freed** by the bridge (the old drive freed it):
  a fetch promise is a reusable value ([TDD-00090](../tdd/TDD-00090.md)) —
  `const p = fetch(u); p.then(f); await p` must still read a live slot, in
  either order (`__kml_await_fetch` short-circuits an already-done handle).

Remaining divergence, accepted: when the drain reaches the drive microtask it
blocks until that transfer completes (a due timer queued behind it waits),
rather than interleaving via a select loop — the same event-loop granularity
every other blocking drive in this compiler has.

## Implementation notes

- `codegen/llvm/emit_promise_then.go`: runner + bridge; `codegen/llvm/emitter.go`:
  `usedFetchDriveRunner` flag.
- The runner must settle through `__kml_promise_settle`, not a raw state store —
  reactions now attach *before* settlement, and an `await` may be parked on the
  bridge promise.
- Ordering note: `p.then(f)` before `await p` runs `f` before the await resumes
  (both settle-reactions FIFO on the same queue), matching JS.

## Side effects discovered

None.

## Verification

- New E2E: `TestE2EFetchThenDoesNotBlockSyncScript` (400 ms `/slow` endpoint;
  the sync tail's measured elapsed time must be < 300 ms — it was ≥ the delay
  under the old synchronous drive), `TestE2EFetchThenAndAwaitShareOneHandle`
  (`.then` + `await` on one fetch promise in both orders, one transfer each).
- All four pre-existing `.then`-on-fetch E2Es (chain, 404-fulfils,
  transport-rejects, finally) pass unchanged, as does the double-await
  reuse suite.
- `go build`, `go vet ./...`, full `go test ./...` green; `make examples`
  (145/145, includes `examples/fetch/fetch_then.ts` against the local
  httpbin-lite fixture) and `make conformance` run at delivery. Apple Silicon
  (macOS).
