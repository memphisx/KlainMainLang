# ADR-02032: Object.setPrototypeOf on a fixed layout

- **Date**: 2026-11-22

## Context

- The strict lane rejected `Object.setPrototypeOf` on a typed object that
  was not a literal's binding (SetPrototypeStatic). Code generation also
  refused an annotated binding.
- A class instance given another class's prototype through a parameter
  kept calling its own class's methods. `instanceof` the other class was
  folded to `false`.

## Decision

- The checker's refusal is removed. Code generation boxes a static object
  and sets the prototype on the box's side table, which every alias reads.
  An annotated literal or `new` binding whose prototype changes is held
  boxed, as an unannotated one already was.
- When the program replaces a prototype, a class method call goes through
  the run-time check (`emitOwnOrClassMethodCall`).
  `__kml_shape_method_shadowed` takes the static class's prototype.
  Another class's prototype, reached first on the given chain, shadows the
  method.
- `instanceof` against an unrelated class walks the given chain
  (`__kml_shape_given_chain_has`) when the program replaces a prototype.

## Consequences

- A program with no `Object.setPrototypeOf` keeps direct calls and the
  folded `instanceof`.
- Tests: `TestE2ESetPrototypeOfFixedLayoutTS`.
