# ADR-01929: checker — collection seeds, leftmost primitive inference, static private names, `arguments` in defaults

- **Relations**: `Implements TDD-00230` (P2 checker fidelity, found by the P3.3 shadow)
- **Date**: 2026-10-21

## Context

The shadow comparison turned up four places where the checker parted from tsc:

- `new Map([["a", 1], [2, "two"]])` compiled in the strict lane, where tsc reports TS2769. A collection's seed was never checked against its constructor. Its type arguments inferred `unknown` because three things were missing: the `Iterable<readonly [K, V]>` context did not type the literal's rows as tuples; a union of tuples counted as one inference candidate; and candidates of unrelated primitive types were unioned. tsc picks the leftmost (getCommonSupertype), so `f(1, "x")` for `f<T>(a: T, b: T)` is TS2345. `examples/map/any_keys.ts` relied on the gap.
- `this.#f()` in an instance method, where `#f` is static, was unanswered. tsc types it `any` and reports TS2339.
- In `function (x = arguments) { function arguments() {} }`, the binder resolved the default's `arguments` to a global. The body's declaration replaced the implicit symbol, and a parameter default does not see body declarations. Parameters with expressions still get the arguments object.

## Decision

- A `new Map`/`Set`/`WeakMap`/`WeakSet` with arguments and no type arguments is checked as a call of its builtin constructor. An `Iterable<tuple>` context, alone or in a union with `null`/`undefined`, types an array literal's rows as an array context does.
- `unify` infers from each member of a union source against a tuple target.
- When a type parameter's candidates are sites of unrelated primitive types, it takes the leftmost site, plus the other sites of the same primitive and any `null`/`undefined` candidates. Inference that keeps literals keeps them (`f(1, "x")` for `f<T>(a: T, b: T): T` infers `1`, then reports TS2345 at `"x"`). A single union candidate, such as an array's mixed elements, stays one candidate.
- A private name an instance lacks reads as `any`. When its class declares that name static, it is reported as TS2339.
- The binder keeps a function's implicit `arguments` on its scope when a body declaration replaces it (`Scope.ParamArguments`). A parameter default resolves `arguments` to it.
- `examples/map/any_keys.ts` gives its mixed seed explicit type arguments. Its output is unchanged and matches Node.
- A named function expression whose own name is read during its inference has an `any` result (`Promise<any>` when async), as tsc's circularity gives. A capture of that name from a nested arrow keeps its self-name flag, so assigning to it inside the arrow is the silent no-op it is in sloppy JavaScript.
- An unannotated destructuring parameter with no default takes the checker's type in the strict lane (`function f([a = 5])` is `[number?]`), for functions, methods and constructors alike.
- `arguments` in a class static block, through arrows, is the early error a field initializer's already was.
- A static `eval` string inlined into a field initializer or static block (through arrows), whose code reads `arguments`, becomes an expression throwing that SyntaxError when it runs, as direct eval does.
- A destructured parameter's defaults see the function's `arguments` (functions, function expressions, methods, constructors): the destructuring runs after `arguments` is built, whose slot for that parameter is the argument itself. A constructor reading `arguments` takes the implicit rest a method does, so it holds the overflow.
- `new class {…}()` and `new function () {…}` parse as `new` of an expression. In the js lane, a getter with no `return` returns `undefined`.
- A body function declaration replaces a parameter of its name once the defaults have run, and an initializer-less `var` beside it (in the body or at top level, never assigned) leaves the function bound; one named `arguments` replaces the arguments object. `typeof` of a nested function or generator declaration is `"function"`. The checker types a `var` sharing a function declaration's name by the function, as tsc does; the oracle maps a replaced parameter to the function.
- A parameter default reading its own parameter is TS2372 (with TS7022 when unannotated, the read then `any`), and one reading a later parameter TS2373, outside functions nested in the default.
- The oracle exempts a promoted module `var` from the hoisted-skip widening (codegen holds the registered global), maps a never-reassigned `var`/`let` binding of a function literal with the literal's parameter defaults and mask, and maps a strict-lane parameter a throwing default types `never` as emission's untyped default.
- `Date.now()` and `Number()` of a boolean, of `null` or with no argument are doubles, as every number is; it was an integer, so a later fractional store into the binding truncated.
- The oracle reads a function declared more than once (and its call) as its last declaration, as codegen runs it, and codegen's held-binding hook no longer answers for a local with the module global of its name when asked outside the local's function.
- The oracle keeps `undefined` for a binding initialized `undefined` (or `void 0`), boxes `arguments` in neither an async method nor a generator, maps a body `var arguments` beside the synthesized object as that object (never hoist-widened), and reads a binding of a method value as the bound closure, whose call counts no arguments.
- An array literal's element takes a `ReadonlyArray<T>`, `Iterable<T>` or `ArrayLike<T>` context's `T`, so a collection seed's rows are tuples (`new Map<K, V>([["a", 1], [2, "two"]])`), as in tsc; the oracle maps those rows as the arrays emission builds.
- In the js lane, a class member assigned only in a method or accessor (`set m(v) { this._v = v }`) has the union of the assigned values' widened types, as tsc declares it in a JavaScript file. Codegen boxes such a member read in a field initializer, where the class is not registered yet; it was an integer, so a string assigned through the setter read as 0.
- An async arrow's parameters read `await` as the operator: `async (a = await => {}) => {}` and `async (await) => {}` are syntax errors, and an `await` a default evaluates is TS2524. Awaiting a box always awaits it dynamically, whatever promise inference expected.
- A static method a class declares after the method being registered (`this.#g()` above `static #g()`) is typed from its declaration, as registration will type it. A method returning an accessor literal, or a literal whose methods do, returns the synthetic class's instance; `await` of a generator object is that object.
- The oracle applies caller-filled destructured defaults to globals and literal methods, and gives a method read off a literal, and its binding, the `this` parameter emission adds.
- An interface's members are registered in the library scope when the interface is a library declaration.
- The oracle warms declarations after the expressions they hold, maps lib calls returning tuples and Map for-of entries as tuples, and treats a user class's `.prototype` and members read off it as boxes, as codegen holds them.
- The conformance harness shim exposes `$DONE` on `globalThis`, which `asyncTest` reads.
- An arithmetic operator applied to a rejected operand still has its numeric result (`d - 1` is `number` beside TS2362), and a compound assignment to a private method reports TS2322 in its own statement before the next statement's diagnostics.
- `new C<T>()` and an unannotated binding of one take the monomorphized generic instance in the oracle. A static method's `super` resolves to the base class value, and the rewritten `super.m()` call keeps its origin.
- Duplicate class members are TS2300, and duplicate method implementations TS2393 on both. In the js lane a later plain method replaces the earlier one, as the class definition evaluates.
- A member a primitive's wrapper lacks (`(5).x`) is TS2339, typed `any`; in JavaScript the read falls through to `Object.prototype`, calling a getter with the primitive as receiver. A union read is TS2339 against the whole union when any member certainly lacks the property (`(number | { label: string }).label`).
- An unannotated destructuring parameter whose default is `null`/`undefined` reports TS2488 (array pattern), TS2531/TS2532 (empty pattern) or TS2339 per key.
- A function declaration in a return-type cycle has an `any` result (TS7023 alone, never a spurious TS2322), and a call of a parameter is no longer read as the function calling itself.
- An argument of an immediately invoked function whose matching parameter is unannotated has no context (TS7006 in strict), and an argument of a call through `any` has `any` parameters.
- A call-of-call or IIFE initializer takes its inferred slot type, so an integer slot no longer truncates a later value.
- A string `matchAll` call, a binding of a collection or match iterator, and `[...it]` of a match iterator take their iterator and array types in the oracle; a module-scope host binding read inside its declaring block is not hoist-widened.
- `this` in a function expression assigned to a member (`obj.m = function () {…}`) is the object (any in JavaScript); an array's named properties read as `any` in JavaScript.
- A module `var` with an initializer sharing a function declaration's name is one any-held global, seeded with the function before any statement runs; a call through the name reads the binding.
- An awaited call's return-context inference includes `PromiseLike<T>`, as tsc's await-operand context does.
- In JavaScript, a catch variable is `any`, a `new function (…) {…}(…)` is `any` with `any` parameters and `this`, and a `new.target` no `new` can reach (an async or generator function's) is `undefined`.
- An argument of an overloaded call whose pick needs that argument's own type takes parameter j of the first non-generic overload its arity and other arguments fit, as tsc checks each candidate in turn (`http.createServer(mustCall((req, res) => …))`).
- An overload signature of an implemented function keeps its type parameters' constraints and defaults, and a type parameter nothing infers takes its default (`T = void`).
- A generic interface takes the members of its non-generic bases (`AggregateOptions<T> extends FunctionOptions`).
- A call through a union of class instances that all declare the method dispatches per class without asking for a function-valued field. A member of an any-held binding the checker types a primitive is that primitive in the oracle, as codegen reads it. A plain function declared to return a generator, and a class read for its `.prototype`, are boxes in the oracle.
- A redeclared module `var` is not a separate promotion decision; a module-level scalar read in its declaring block is not hoist-widened; a JavaScript function returning a union the oracle cannot name returns a box.
- `x[Symbol.iterator]()` of a typed array is typed from its rewritten method call alone, so its spread no longer reads the bytes as doubles.
- A call of a user `declare function` declared more than once evaluates its arguments and throws the stub's "has no implementation" error; it was converted to one signature's parameters, an internal error when the arguments fit another.
- A skipped module-level `var` read is widened in the oracle exactly when the storage emission bound it to is; a `new.target` in a plain function expression keeps its function type in JavaScript.
- An interface with only a number index signature is a string-keyed map in the oracle, as an anonymous one is. `process.versions` is declared (`ProcessVersions extends Dict<string>`, as in `@types/node`), and a library interface with required members beside a string index is a box in the oracle.
- `typeof` of a host handle (a compression stream, `URL`, `AbortController`, `TextEncoder`, `Headers`) is `"object"`; it read `"string"`, the bare-pointer default.
- `CompressionStream` and `DecompressionStream` declare their native layout (`@lowerType`), so a binding of one has the same type in the checker's mapping as at emission.
- `inferExprType` takes the checker's answer for every expression kind: `new WeakMap`/`WeakSet`/`CompressionStream`/`XMLHttpRequest`, tagged templates and `import()` join the switched kinds, on which the full corpus records no disagreement.
- `import()` of a builtin module written in TypeScript (`node:path`), or of a `node:`-prefixed one, is the clean compile error the bare virtual names already gave; it failed reading the library's embedded path from disk.
- `Buffer.prototype.swap16`/`swap32`/`swap64` are written in TypeScript (`lib/node/kml_buffer.ts`) and lowered from their declarations: each swaps every group in place and returns the buffer, and a size that is not a multiple throws Node's `ERR_INVALID_BUFFER_SIZE` RangeError. A call on a Buffer held as `any` compiled without end: the dynamic Buffer branch's static call came back to the same dynamic probe. That branch now calls a method's lowered function directly, and the static call never re-enters the probe.
- `Array.prototype.pop`/`push`/`shift`/`unshift`/`splice`/`reverse` called on an object that is not an array (`Array.prototype.pop.call(obj)`, `obj.pop = Array.prototype.pop`) run ECMA-262's algorithms on the object's own properties (`lib/node/kml_array.ts`). The receiver was copied into an array first: the method changed the copy, and an object whose `length` is near 2**32 allocated that many elements, which aborted the Test262 run on memory.
- A library module whose lowered function a lone method name triggers (`// kml:lower push`) is linked even when the program declares a top-level binding of that name (`var push = obj.push(-1)`); only a global's name (`setTimeout`) is shadowed by a declaration.
- The module-global decision keeps the old inference: the checker's answer agrees with it on representation over the whole corpus, but not on the metadata the representation key leaves out (a Map's key and value types, an array element's class), so taking it whole broke `fs.promises` reads in functions.

- Every other `Array.prototype` method (`slice`, `indexOf`, `lastIndexOf`, `includes`, `join`, `at`, `forEach`, `some`, `every`, `map`, `filter`, `reduce`, `reduceRight`, the `find` family, `fill`, `copyWithin`, `sort` and the copying `toSorted`/`toReversed`/`with`/`toSpliced`) also runs its spec algorithm on an array-like receiver, from `lib/node/kml_array.ts`; each takes the receiver and the call's arguments as one array. A walk longer than 2^20 indices visits only the object's own integer keys, as a dictionary-mode engine does, so a `length` near 2^53 costs only the elements held instead of exhausting memory. A result array longer than 2^32-1 throws `RangeError`.
- An object literal whose getter returns the literal's own binding (`const a = { get self() { return a; } }`) overflowed the compiler's stack: building the getter's signature asked for the literal's class, which was registered only after its accessors. It is now registered before them.
- The conformance runner's `-passlist` (and `PASSLIST=` on every conformance make target) also writes the node and wpt suites' passing files, one file per lane, so two runs can be diffed for regressions.

- The array-like algorithms module links only when the program names `Array.prototype` (the only way to call one on a receiver that is not an array); keyed on each method's bare name it linked into nearly every program and grew the program unit past its budget.
- `in` (and so the array-like algorithms' presence checks) sees a String wrapper's indices from library code: program-independent code checks through a weak `__kml_wrapper_has_hook`, as reads already did through `__kml_wrapper_recv_hook`.
- `var a = { f: a }` overflowed the compiler's stack: the checker-side typing of the literal asked for `a`, whose type is the literal. The literal being typed is now marked, and a re-entry answers "unknown".
- The node and wpt suites' pass lists name the strict lane `strict` (they named it with an empty suffix).

- A `for...of` over a user iterator closes it (its `return()`) when the body throws, the body's error winning over one `return()` throws; `break` and `return` already closed it. Perf note: the body runs under a catch frame per iteration; one frame around the loop is the cheaper follow-up.
- `new Map(iterable)` of a user iterable adds each entry as the iterator yields it, through that loop, instead of collecting the whole iterable first: an endless iterator whose entry throws stopped only when memory ran out.
- A class adding nothing to a base whose constructor takes a rest parameter, or reads `arguments` (`class MyURL extends URL {}`), inherits that constructor: the implicit one spreads its rest back into `super()`.
- A module binding holding the box an any-argument call returns (`const dest = path.resolve(anyValue, "x")`) stored into a copy of its declaration, which missed the promoted module global: a closure reading it saw `undefined`. The declaration is now retyped in place for its emission.
- A method call through a member of a possibly-undefined object (untyped JavaScript, `cluster.worker.process.on(...)`) unboxes the receiver the generic getter reads, on both the class-call and the class-or-foreign-call paths; it was used as a class pointer (invalid IR).
- Untyped JavaScript passing a number or boolean where a builtin takes an optional callback (`http.createServer(listener, 1)`) passes no callback, as the callee ignores a non-function one; it was an internal compiler error. Divergence: a function slot cannot hold the number, so the callee cannot observe it.
- `http.request` expects the agent's protocol only when the agent has one, else the default agent's (Node's `ClientRequest`).
- AES-GCM decryption of data shorter than its tag rejects with "The provided data is too small." before decrypting, and an unsupported key usage names "an HMAC key" and "an AES key" (Node's mac.js and aes.js).
- A spawn's non-string env value (`cluster.fork({ maxConnections: 0 })`) is stringified, as Node does, instead of being null-byte checked as a string.

- An HMAC import with `length: 0` passes the WebIDL dictionary (only `HmacKeyGenParams` rejects zero there) and is rejected by the import as "Zero-length key is not supported" (DataError), as Node's mac.js does.
- The node conformance track's per-worker working directory holds one file, as Node's checkout is never empty: a test listing its cwd expects output.

- A function whose own body, or an enclosing one's, opens with "use strict", or that sits in a strict file or class body, is a strict caller: a sloppy callee's `f.caller` reads null during its call, and its own `caller`/`arguments` throw. A strict function was recorded as sloppy.
- The parser rejects, as Node does: a `let`/`const` declaration as the single statement of an if, loop or label (`while (x) let\n[a] = 0`); an identifier straight after a number (`3in []`, `10._`); `yield` as a name in a class body or a "use strict" function of a sloppy file; a parenthesized object or array literal as an assignment target (`({}) = 1`); an arrow function as a relational operand (`#x in () => {}`). A number's trailing dot is part of it, so `10..toString()`, `(10.)` and `1.e3` parse (they did not).
- A String.prototype method's receiver goes through ToString, which throws for a Symbol (`String.prototype.padEnd.call(Symbol())`); it took String(), which names it.
- An Array.prototype method called on a primitive works on its wrapper (`Array.prototype.pop.call("abc")` throws, its index being non-configurable), on null or undefined throws; `Array.prototype.values`, `Object.prototype.valueOf`, `isPrototypeOf` and the `__define*__`/`__lookup*__` accessors ToObject their receiver, throwing for null and undefined.
- `delete` of a String wrapper's index or `length` is refused (false in sloppy code, the TypeError in strict code); program-independent library code writes and deletes a wrapper's properties through weak hooks, as it reads them.
- A destructured member whose default calls a function returning nothing is typed void (as tsc infers it) and held as undefined: its layout had a void field (invalid IR, in a library unit too).
- A destructuring default of an array element that is a call returning nothing or a box binds undefined or the converted value (`[[] = f()]`); it was a compile error.
- `this` reads its binding's type wherever it is bound, as its emission does: in an object literal's accessor the checker's `any` disagreed with the synthetic class the accessor binds, and `this.n++` there was invalid IR.
- A `for await` array pattern over an iterator element steps it only as far as the pattern reads (`[]` reads nothing); the element was spread whole first, running the generator to its end.

- A `for await` over an array takes its async-from-sync iterator's two ticks per element, plain or promise (the step's promise settles from a reaction on the value's, then the loop's await resumes): a plain element ran with no tick at all, ahead of earlier awaits.

- ToPrimitive with the string hint skips an own `toString` that is not callable and goes on to `valueOf`, propagating its throw; an object with neither method throws "Cannot convert object to primitive value" (`String(o)`, template literals, String-method receivers).
- `ArrayBuffer.prototype` carries `maxByteLength`, `resizable` and `detached` accessors, and `SharedArrayBuffer.prototype` `growable` and `maxByteLength`, beside the declared ones, so reading them off the prototype throws the incompatible-receiver TypeError.
- `Object.freeze`/`seal`/`preventExtensions` on a RegExp record the level in a side table keyed by address, as the RegExp record has no header word; the integrity tests read it back.
- `Object.defineProperty` (and `__defineGetter__`/`__defineSetter__`) on a Proxy call its `defineProperty` trap, a falsish result a TypeError, else define on the target; it no longer crashes on a trapless Proxy.

- `Promise.prototype.catch` and `finally` on a receiver that is not a promise invoke its own `then` (Invoke(this, "then", …)); `then` throws the incompatible-receiver TypeError. Neither dereferences a null wrapper any more.
- `Array.from` of an ArrayBuffer is `[]` (no iterator, no `length`) instead of reading the buffer as a string.
- A generic function's type parameter that nothing infers takes its constraint, else `unknown`, as tsc infers it, instead of a compile error (`Promise.withResolvers` taken as a value compiles).
- `Promise.all`/`race`/`any`/`allSettled` accept any iterable (a Set, a generator, a dynamic value), read through the iteration protocol.

- `++`/`--` on a dynamic object indexed by a dynamic key converts the key (ToPropertyKey) once for both the read and the write.
- An optional RegExp (an element read, `RegExp | undefined`) boxes as its host cell (absent as undefined), and a union's sole object member read off a host cell skips the cell's header word: RegExps held in arrays read their fields again.

- Early errors: `#x in o` names a private member an enclosing class declares; a label is a name (`yield:` in strict code, `await:` in a module); an async function expression is never named `await` (nor `yield` for an async generator); an async function's parameter initializer never awaits. The conformance runner runs `module`-flagged Test262 files as module code.
- `#x in o` inside a class nested in the declaring class resolves to that outer class: its owner is recorded before class expressions hoist.
- An async function returning a value that may hold a promise (`Promise<T> | T`, or `any`) while its own result type is neither resolves with the promise's value, a tick after it settles, its rejection settling the function past its own `try` blocks, instead of converting the box.
- A `for await` loop whose body throws closes its iterator with AsyncIteratorClose, awaiting what `return()` gives, rather than the sync close that re-entered the stream pipeline without end.
- `Object.fromEntries` over a dynamic (`any`) iterable takes the ToPropertyKey path, so a boolean or `null` key is stringified rather than read as a string.
- Web Crypto's unsupported-usage error says `Unsupported key usage for <name> key` for every algorithm, as Node 24 does.
- Type-argument inference keeps a set of the (target, source) pairs it is inside, as tsc does, so a type that reaches itself ends the walk instead of overflowing the stack.
- The representation oracle types a loop variable from its loop's iterable once per loop at a time, so `for (var v of v)` no longer recurses without end.
- The conformance runner's ts, node and wpt suites resolve each lane as the CLI does under its `-compat`, as Test262 already did: the strict lane's definite-assignment errors (TS2454) now reject a case there, where the runner had resolved every lane as JavaScript.
- A computed enum member (`A = f()`) is evaluated where the enum is declared into a module constant, a bare member name inside it reading that member; its reverse entry is keyed at run time. An enum mixing string and numeric members is backed by a boxed value, its numeric members keeping their reverse entries.
- A decimal number literal past the double range is `Infinity` (`1e999`), and a hex, binary or octal literal past 64 bits is the nearest double, as JS reads them.
- Narrowing by `in` takes a template-literal or numeric key, and narrowing by a type predicate reaches arrays and tuples, an overloaded callee guarding by the signature its call resolves to (`arr.every(isString)` narrows `arr` to `string[]`).
- An enum index with a template-literal key reads that member, and one with a run-time key that is not a number (a string, a box) reads the enum object, its forward and reverse entries both.
- Enum literal types relate as TypeScript relates them: two members only when one, a member to its primitive (a numeric member is no string), a numeric member taking any number and a number literal of its value; an enum member's apparent type is its primitive's, so `E.A.toString()` is Number's method.
- An unannotated parameter whose default is an object, function or array (`a = console.log`) takes the default's type, a box when no representation holds it, where it fell to a number the default could not convert to.
- An array literal spreading elements of another kind than its own (`["a", ...nums, true]`) is boxed, as the union TypeScript infers holds them; a spread was read as the first element's kind.
- A `boolean` binding narrows by assignment as the union `true | false` it is: `let y = true` reads as `true` until it is reassigned, so `y && (a => a)` is the function.
- An object spread's operand takes the literal's own context, and an assignment's right side its target's declared type, when deciding whether a literal stays literal: `i = { ...{ a: "a" } }` against `a: "a"` holds.
- A union of signatures identical but for their results is one contextual signature returning the union of the results (tsc's getContextualSignature): `() => "bar"` against `(() => "foo") | (() => "bar")` keeps its literal; a binding of such a union type, held boxed, is called through the dynamic call where it was "undefined function or closure".
- The type oracle bounds how deeply one expression's typing may re-ask itself (four nested asks); a deeper ask is a cycle, cut with no answer, and an answer computed past a cut is not memoized. A cycle (a loop variable read in its own iterable) exhausted the Go stack.
- The empty object type `{}` is held boxed, as an annotation `{}` already was, so `{ headers = {} }` takes `{ foo: 1 }` where the field was a struct without fields; a destructuring default on a boxed field replaces its undefined, where it was dropped.
- A branded primitive (`string & { __brand: "id" }`, one primitive intersected with object types) is the checker's branded type: it goes where its primitive or its brand goes, and takes only a value carrying its brand, so a plain string or an object literal is no `Id` and two brands stay apart; codegen holds it as the primitive. It was a compile error.
- A union of objects that each declare `length` reads it as any other member of the union, where `.length` took only arrays and strings.
- An argument passed to a `never` parameter (`assertUnreachable(x)` in an exhausted switch) is unreachable and passed unconverted, where a string argument was an internal error.
- A `ThisType<T>` marker survives instantiation (`Opts<D> & ThisType<D>` with D inferred), and a method of a literal nested in a property value takes an enclosing literal's marker (tsc's getContextualThisParameterType walk); a marker still holding an uninferred type parameter leaves `this` unanswered.
- The checker reports TypeScript's enum member rules: a computed initializer in a const enum (TS2474) or a `declare enum` (TS1066), a computed value that is not a number (TS18033), a member without an initializer after a computed one (TS1061), a const enum value that is not finite (TS2477, TS2478). Codegen's blanket rejection of computed members had stood in for them.
- A reverse lookup on an enum without numeric members reads undefined, held as `any`, where it was a compile error.
- A union of signatures with different parameter lists is called through tsc's combined signature (combineUnionParameters): the longer list, each position's primitive types intersected, a position required when either side requires it, and the rest element of either; `f12345("a")` over five arities reports TS2554.
- A `boolean` binding narrowed by assignment reads as a fresh literal, so `var n = s` after `var s: boolean = false` widens to `boolean`.
- An array pattern binding an object (a generator, an iterable) reads the values its iteration protocol yields, where unboxing it as an array threw "the value is not an array".
- `Object.getPrototypeOf` on a Proxy runs its `getPrototypeOf` trap (else its target's prototype); `Object.prototype`'s prototype is immutable, and the prototype-cycle check follows an unset link as Object.prototype, so `Object.setPrototypeOf(Object.prototype, Array.prototype)` is refused (TypeError).
- `{...rest,} = o` (a comma after an assignment pattern's rest) and `[arguments] = []` / `[eval] = []` in strict code are early errors; codegen limitations had rejected them by accident.
- An array destructuring assignment whose nested pattern meets a boxed element (`[a, { b = 2 }] = [1, {}]`) destructures it through a hidden `any`, as a defaulted nested pattern did.
- `spawn`'s `stdio` array takes a stream, as @types/node's `StdioOptions` does; one over a descriptor (`process.stdin`) shares that descriptor with the child.
- Narrowing by a type-predicate call whose overload is being picked no longer recurses: the inner ask returns the type unnarrowed (a checker stack overflow on a Node-core test).
- A Map/Set view's helpers, a host type's `toString`/`toPrimitive` thunks and its `Symbol.toStringTag` thunk, each keyed by a library-stable type id, compile in that id's own cached unit rather than the program's (an http2 server's program unit had grown from 3.3 MB to 6.3 MB; now 5.2 MB).
- An enum member without an initializer takes its auto value for the members after it (`b = a`, `d = ~e` fold); TS2695 (an unused, side-effect-free comma operand, except `(0, o.f)()`) and TS2872/TS2873 (a condition always truthy or always falsy by its form: `if (null as any)`) are reported as tsc reports them; code spliced in from a constant `eval` string is exempt, since tsc never sees it.
- OpenSSL is initialised without its atexit cleanup, as Node initialises it, so `process.exit()` during a pooled RSA keygen no longer frees state the pool thread is reading (an intermittent segfault).

- An enum's computed member (`A = f()`) is a member type of its own with an unknown value, as TypeScript 5.0 types it, so a later member reading it (`B = A + 1`) is typed; the enum was unanswered.
- `import("./mod")` under the bundled and lazy backends resolves to the target's module namespace object, built (as for `import * as ns`) as the target's last top-level statement: every value export, `let` exports through live getters, keys sorted. The result object held only annotated scalar exports. Under lazy, a table row that names a dynamic-only file's code (a function's metadata, a literal's dynamic entry) is registered from that file's shared library when its body first runs; the executable may not name island code.
- `Promise.all` and the other combinators read their members with the element type the emitted array holds them by, not the checker's (`{}[]` is `any[]` to the checker, while a literal of empty objects holds pointers), so `values[0] === v1` again holds. An `onFulfilled` whose parameter holds the value's elements another way receives the promise converted.
- A compound update's hoisted receiver (`a.b!.c++`) carries its origin, so the checker answers it.
- A class field with no initializer that the constructor does not assign at its top level (`o!: T`, or one a method assigns) is held as an optional field is: an own property reading undefined until assigned, as in Node (`typeof`, `=== undefined`, JSON, inspect). tsc types its read `T`; the read is an unchecked one, as an out-of-range element's. It read as a present value (`null`, `[]`, `false`), and inspecting the instance crashed.
- The strict lane reports TS2564 (`--strictPropertyInitialization`): a typed instance field with no initializer, not `!`, `?`, `declare` or `abstract`, whose type does not admit undefined, and which the constructor does not definitely assign (a parameter property, a statement, or both arms of an `if`; not through a call, as in tsc). A generic class's fields are not checked yet, so it reports fewer than tsc, never more.
- `Object.defineProperty(array, "length", { value })` throws RangeError "Invalid array length" for a value that is no valid array length.
- A program that uses `Promise` as a value without the Worker runtime defines the no-op `__kml_worker_uncaught` its unhandled-rejection report calls; that report is emitted late in finalize, after the stub was decided, so the IR named an undefined symbol.
- `Atomics.wait` on a view of an ordinary ArrayBuffer throws TypeError ("[object Int32Array] is not a shared typed array."), before the index is coerced; a view over a SharedArrayBuffer reached through `any` is registered with its buffer (its `.buffer` is that buffer, and `wait` sees it shared).
- A converted promise view of an already-rejected promise rejects at once (a reaction attached to a settled promise never ran, so `L.allSettled([L.reject(x)])` never settled), and the source rejection is the view's to report.
- An inline `.then` callback whose first parameter is written `any` receives an array value boxed as `any` holds it; any other callback receives the value unconverted (a rest parameter like `console.log`'s, or a checker-typed one, read the boxed copy).
- A map view's dispatcher for a library type is built program-independently, so its shared library unit is the same in every program.
- A constructor assignment inside `try` whose catch always rethrows counts as definite for TS2564, as in tsc; a subclass redeclaring a field the base leaves unassigned keeps the inherited storage.
- A builtin prototype object carries only the methods the program can reach: the ones it names anywhere (a property, key, identifier or string literal), plus those the runtime calls itself. Its methods are non-enumerable, so only own-name reflection (`getOwnPropertyNames`, `ownKeys`, descriptor reads by a computed key), `in` with a computed key, or an index by a non-numeric computed key can reach the rest; any of these keeps every method. Building every method made a test that read `Array.prototype.map` thirteen times HEAD's IR size.
- A builtin prototype object is built by one function per class, the program's own (`__kml_proto_get_<Class>`), built once and returned from its slot on every later read, whoever reads it first, library code included: a library unit stays the same in every program, and the methods the object carries never depend on which reader ran first. Each prototype method is a cached unit of its own.
- Object.prototype's methods, the iteration collectors, Function.prototype's methods and each builtin function used as a value are built program-independently into cached units of their own (their literals named by position), not recompiled into every program's own unit, which had grown to four times HEAD's.
- A primitive wrapper (`new String("a")`) has no own method properties: a read goes on to its prototype, so `w.slice === String.prototype.slice` and `hasOwnProperty` answers false.
- A number's or boolean's method read as a value, statically (`(5).toFixed`) or through `any`, is its prototype's function; through `any` it read undefined, and statically it did not compile.
- A builtin module's own declaration whose source name has the reserved `__kml_` prefix (kml_array.ts's array-like algorithms) is compiled in its module's cached unit, not in every program's own unit; a helper generated about a library declaration stays the program's.
- `Object.defineProperty` on a possible array links the holes runtime itself: an accessor element is marked in the array's holes and read through its getter. A program had it only when building Object.prototype's methods linked it by chance, so an element getter was otherwise silently ignored (and Map's constructor looped on an endless iterator whose entry getter throws).
- `new Map(x)` from an untyped source (`any`, an iterable) is `Map<any, any>`, as TypeScript types it, and from another Map takes that Map's types; it defaulted to string keys and number values, losing each value.
- On a memory-cap abort, the conformance runner names the test each runaway program was running.
- A String, Number or Boolean wrapper object (a sloppy function's primitive `this`, `Object(false)`) reads a property it does not own from its class prototype and on along the chain, Object.prototype's included; the class's prototype methods accept the wrapper as their receiver, unwrapping it to its primitive value, as `thisBooleanValue` and kin do.
- An array key that is no array index (negative, or 2^32-1 and up) is an ordinary own property: a typed array's store and read go to its added-property table instead of growing it to the index (which on macOS committed gigabytes), and the dynamic paths accept only canonical indices below 2^32-1.
- The conformance runner names the test whose program it kills for memory.
- A typed function's dynamic adapter reads argument i only when the caller passed it: a getter run with no arguments passes a null argument list, which the eager load dereferenced (a segfault on macOS arm64).
- The runtime's C compiles with `-ffp-contract=off`: arm64 clang fused `a*b+c` into one rounding, which JavaScript's number arithmetic never does (Date's MakeTime/MakeDate precision).
- The server examples read their port from `PORT` (default 8080/8081) and the example runner passes each run a free port, so `make examples` no longer fails on a machine where something else holds a fixed port.
- The builtin library compiles to the same IR in every program again (`make drift`): key-order blocks and frame descriptors are named by their content, generator helpers after their body's library position, the `Object.prototype` helpers by their own unit whichever module first emits them; library field reads always take the shadow check and library generators always record their instance prototype, rather than only when the program's own code asks for it.
- The shadow read covers only fields of a primitive kind: a private field (never written through `any`) and a Promise or other host handle (which the loose pointer-is-string test let through, boxing a `Promise | null` field as a string) are read directly.
- A builtin constructor held as a value (`const M: any = Map`) reads `prototype` as the same object `Map.prototype` gives. A library class's reference row (DataView's) reads it through the class's prototype builder, `__kml_cproto_get_<C>`, so the row stays the same in every program, and `Object.getPrototypeOf` of a library class's instance is that object too.
- A function's `constructor` is `Function` (Function.prototype's), not Object.prototype's.
- The error kinds have prototype objects: each with its `name`, an empty `message` and its `constructor`, inheriting `Error.prototype`, which also holds the spec's `toString`. An error's `[[Prototype]]` is its kind's, and an error subclass's prototype inherits the kind it extends.
- An empty object literal is typed `{}`, which holds any value but null and undefined: an unannotated binding of one (`let v = {}`), and an unannotated destructuring parameter typed `{}` (an empty pattern, or one defaulting to `{}`), hold a box, so `v = 5` compiles and runs as JavaScript does instead of being rejected as a change of kind. This matches the checker's representation of the type.
- A destructured parameter's leaves are bound while its function's return type is inferred, so a JavaScript function returning one (`function g({ [k]: x } = {}) { return x; }`) returns it as `any`, not as the number fallback (which turned undefined into 0).
- A destructuring pattern's computed `string` or `number` key on an object type with no matching index signature is TS2537 (a declaration's source, or an unannotated parameter's default).
- A stack overflow's RangeError captures its trace from above the faulting guard page: the overflowing call's frame record can sit in that page, and reading it faulted again on the alternate signal stack (a segfault on Linux arm64; on macOS a signal that cannot be delivered, killing the process).
- An h2o-backend cluster worker binds its listener with SO_REUSEPORT, as the default backend's does, so the kernel spreads connections over every worker instead of one worker holding the port.
- `make drift` compiles each example twice in one pass (drift from the first compile, determinism from the second) instead of three times over two passes, and runs as its own CI job beside the examples.
- A large generated function the program's name does not tie to it (40 lines and up, a `__kml_` helper that is no user function, closure or `main`) compiles in a unit of its own keyed by its text and carrying only the types it names, so the object cache compiles it once instead of with every program; most such helpers are byte-identical across programs.
- `__kml_error_get_key` calls each key's own dynamic read instead of inlining that read's dispatch per key (6,200 lines of IR in every program that indexes an Error by a run-time key).
- A class's prototype object is read through one builder per class, `__kml_cproto_get_<C>`, which a library class's reference row names alike in every program: no per-program dispatch over library classes, and no prototype build inlined at each read.
- A new error's fields are set by one runtime call (`__kml_error_init`, frames.c) instead of a store per field at every construction site, and its layout is registered once per program.
- A caught value indexed by a key (`catch (e: any) { e["message"] }`) reads through its box, as a member read does, instead of failing to compile as a non-array index.
- An array's holes bitmap marks and clears a range a word at a time, and holds one long run of holes as its bounds: `length = 4294967295` no longer writes 2^32 bits.
- Linux links with lld when it is installed (CI installs it); the unit split scans each definition's symbol references once, by hand, instead of a regular expression per unit that names it.
- The conformance runner reports per-phase worker time (`KML_CONF_TIMES=1`) and takes `-cpuprofile`.
- `++`/`--` on an operand that is not any, a number, a bigint or an enum is TS2356, and a relational comparison of a string with a number or bigint is TS2365, as tsc reports them; the update check was codegen's alone, from the static type, so `let x = {}; ++x` compiled once an empty literal's binding held a box. A union or Date operand's TS2365 (tsc's comparability rules) is not yet reported.
- `make examples` prints why an example failed (the compiler's error, the exit status or time-out, the last output), and libdrift keeps only the distinct library bodies it has seen, copied out of each program's IR, so it no longer holds every example's IR at once (killed for memory in an 8 GB arm64 container; 5.8 GB peak at 6 jobs now).
- A string `+` is one runtime call (`__kml_str_concat`, strheader.c) instead of 18 inline instructions and two blocks per site, and a dynamic value's string or inspection form is one shared function per mode and depth (`__kml_dynrender_*`) instead of its ~300-line tag dispatch at each site: the Test262 harness's `verifyProperty` was 468 KB of IR.
- A function of 6 lines and up that is no user function compiles in its own cached unit (40 before), and the conformance runner puts large user functions there too (`AutoUnitUserFuncs`): its harness's functions are the same text in every test. The CLI keeps a user function in the program's unit, where clang can inline it.
- A function-metadata row of a function another unit defines moves into that unit, registered by the linker: a descriptor in the `kml_unitreg` section (`__DATA,__kml_unitreg` on Mach-O) that unitreg.c walks before main, so neither the rows nor a registration call per unit stay in the program's unit. Windows keeps the program's table. A global's declaration in another unit takes its type after the first of `global`/`constant`, not after `global` anywhere in its initializer.
- The front end: GOGC 400 by default in the compiler and the runner; `reassigned` walks each scope once for all its symbols; register and label names without `fmt`; a resolver check that compiled three regular expressions per `new X` is a hand scan (the same answer on all 53,872 Test262 files); the runtime-hook scan reads the IR once for every hook; the function-name pass's reflection walk skips fields that cannot hold a node.
- The conformance runner reports the clang processes' CPU and its own (`KML_CONF_TIMES=1`). The Array sample: 104 s → 39 s wall, front end 644 → 364 ms and clang+link CPU 1,345 → 318 ms a test, the same 303 passes.
- A sloppy script's assignment counts as one to an undeclared name (which links the global object, every builtin it can reach) only when the binder finds no binding for it: a parameter or a catch binding is one, which the text scan alone took for a global. Test262's `propertyHelper.js` assigns two parameters, so every test including it built the whole global object: 20 MB of IR of which 440 KB was the test's.
- `%TypedArray%.prototype` carries the methods the program can reach (protoMethodReachable), as the other builtin prototypes do, not every method in all 11 kinds.
- An instruction, terminator, label or global line is written to its builder piece by piece, not concatenated first.
- A frame descriptor is named by the function and its file's place among the program's files, not its URL: a unit naming it keeps the same text whatever path the file has, so the conformance runner's units are the same whichever worker compiles a test (a warm rerun compiled 129 units again; it now compiles none). The runner gives the resolver each test's text at the test's own path (`options.EntrySource`), so a module test's relative imports find their `_FIXTURE.js` files; `KML_CONF_SRC=1` keeps the assembled source.
- The namespace `import()` gives of a module whose exports are untyped (`var t; export { t as time }`) is the dynamic object the literal already is, not converted again (an internal error before).
- JavaScript (`-compat=js`): a class called without `new` throws its TypeError when the call runs (strict keeps tsc's TS2348); a method the builtin library declares no member for on the receiver's type (`ArrayBuffer.prototype.transferToImmutable`) throws `… is not a function` when called, named as V8 names the callee (`(intermediate value)`, a string literal quoted), while a declared method this compiler lacks stays the compile-time diagnostic; an untyped top-level binding a function reads that no rule types for a global is held as `any`; a JSDoc `[name]`, `[name=default]` or `{T=}` parameter is optional.
- A buffer constructed with `{maxByteLength}` and bound inside a function is growable, as one bound at the top level is (`resize` was rejected at compile time in any function), and so is a `var` every declaration of initializes with one.
- Test262: the runner's `assert.js` shim defines upstream's `isPrimitive` and `isNegativeZero`, which `testTypedArray.js` calls. A test including `testTypedArray.js` no longer fails to compile on its `throw Test262Error(…)` (2,094 files).
- BigInt64Array and BigUint64Array support every %TypedArray%.prototype method: `forEach`, `map`, `filter`, `some`, `every`, the `find` family, `reduce`/`reduceRight`, `indexOf`/`lastIndexOf`/`includes`, `join`, `keys`/`values`/`entries`, `copyWithin`, `with`, `sort`/`toSorted`. They are written in TypeScript (`lib/node/kml_typedarray.ts`) and reached through `@lower`. The same methods called through `any`, or through the dynamic %TypedArray% dispatch, take the bigint lowering instead of the number-array intrinsic. Only the methods no TypedArray has (`push`, `splice`, `concat`, …) stay compile errors.
- A BigInt64Array held in `any` boxes its elements as bigints, so reads, inspection (`1n`), iteration and `includes` all see bigints. A store through `any` runs ToBigInt: a bigint, or a boolean as `0n`/`1n`; anything else throws V8's `Cannot convert X to a BigInt`. Under `-compat=js` a non-bigint value stored into a statically typed BigInt64Array takes the same run-time path. That also fixes `cond ? big : arr[i]` failing to store.
- `set()` on a BigInt64Array takes any array-like, each element converted with ToBigInt. Storing a bigint into a number TypedArray (an element store, `set()`, or the constructor reading an `any` array-like) throws `Cannot convert a BigInt value to a number`, as ToNumber does.
- `Number(x)` and `-x` of an `any` holding a bigint are ToNumeric: the nearest double, and a negated bigint. Both used to be NaN.
- A host iterator class (an array iterator held in `any`) answers `[Symbol.iterator]` with itself, so `[...it]` and `for…of` over it work. A bigint searched for among number elements is boxed rather than converted, which was an internal compiler error.
- `new K(…)` inside a closure, where K is a constructor bound in an enclosing function (`function t(TA) { return () => new TA(2) }`), captures K. The free-variable scan used to skip a `new` expression's callee name, so the closure failed with `unknown class`.
- An uncaught thrown non-Error value prints as `util.inspect` shows it (`T { message: 'boom' }`, `{ a: 1 }`), as Node does, not `[thrown value]`. The conformance runner reads such a multi-line object as one failure reason.
- Test262: the runner's `assert.js` shim defines `compareArray` with `Object.is` element comparison, which the TypedArray suites assert through.
- The library-unit registration descriptors are left out of AddressSanitizer (`no_sanitize_address`): the runtime walks their section as one array, and the redzones macOS ASan puts between them made the walk read past each descriptor.
- A function `@llvm.global_ctors` names stays in the program's own unit. Moving the hooks constructor into a cached library unit left the program registering a declaration, which crashes clang's ASan pass.
- The cached library-unit and C-runtime objects are keyed by `clang --version` as the sidecar objects already were, so switching compilers no longer links objects built by the other one.
- Windows: the self-signal path reaches libuv's internal `uv__signal_dispatch` through a weak reference. Only a static libuv has it; a build against the libuv DLL failed to link and now falls back to the watcher table.
- An object literal with accessors, reached through an `any`, emits its accessor bodies before the class's dynamic method adapters name them.
- `Array.prototype.toString` on a non-array calls its `join`, or answers `Object.prototype.toString`'s tag when `join` is not callable.
- `toLocaleString` on an object is its `toString`; only a plain number takes the digit-grouping formatter. A bigint groups its digits too, typed or through an `any`.
- A boxed bigint answers `BigInt.prototype` methods (`toString`, `valueOf`, `toLocaleString`) through an `any`, as boxed numbers answer `Number.prototype`'s.
- A call returning nothing, used as a value (an argument, an interpolation, `Promise.resolve(f())`), is `undefined`; a `Promise<void>` stores and loads no value.
- `concat` appends `undefined` and `null` to a scalar array by boxing its elements.
- A primitive's inherited `hasOwnProperty`/`Object.hasOwn` answers from its box (a string's indices and `length` are its own).
- A reaction handler using its own `arguments`, or held boxed, is called through a one-parameter closure, so the runner never passes it a garbage rest slot.
- A regular expression literal's flags are V8's: each of `dgimsuvy` at most once, `u` and `v` not together; anything else is a SyntaxError at compile time.
- Goroutine stacks default to 1 MiB: a synchronous request (libcurl and the resolver below it) takes 130–160 KB on arm64 and more on x86-64, which overflowed 256 KiB there. The mapping is lazy.
- A stack overflow on the main thread is now caught by a software limit in each user function's prologue: a frame inside the 256 KiB band above the guard page throws the RangeError from the program's own code. The guard page moved that much lower and is only the backstop, so a native call made by the deepest frame (libc's `opendir`, `malloc`) no longer takes the fault itself, where the throw longjmped out of a held allocator lock and the process was terminated without output. The overflow depth stays Node's 984 KiB. Each user function pays one load, subtract and compare; fiber and goroutine stacks still rely on their guard pages alone.
- Windows links again: the weak hook pointers (`__kml_*_hook`, initialized null and defined by the C file that implements them) no longer get a COFF comdat, which had made each a strong definition colliding with that file's; and the C runtime's references into files a program may not link (`process.c` into the event loop, `shape.c` into the collections and dynamic-object runtimes, `fetch.c` into the string-keyed map) are weak, as COFF resolves them before dropping unused code.
- The compiler no longer raises its garbage collector's target to 4x the live heap: it saved no measurable time and took the heaviest compile from about 0.8 to 1.2 GB. The parser sizes its token buffers from the source length up front.
- `klain:http`'s `listen(0, …)` binds a port the system picks, and a new `onListening(port)` option receives the bound port once listening (in the primary, before workers fork); both backends' bind now reports it. The httpbin-lite fixture listens that way and hands its port to the example runner through a file, and the examples it serves read its URL from `HTTPBIN_URL` (httpbin.org when run by hand). The tests and examples that bound fixed ports now take one from the system, so a run no longer fails, or talks to a stranger, because another program holds the port.
- Every incompatible-receiver TypeError builds its message through one per-program helper, `__kml_recv_msg`, instead of inlining the receiver conversion into each prototype getter.

## Consequences

- `new Map([["a", 1], ["b", null]])` is `Map<string, number | null>` and `new Set([1, "x"])` is `Set<string | number>`, as in tsc. Both compile.
