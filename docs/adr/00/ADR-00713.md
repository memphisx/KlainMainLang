# ADR-00713: JSON.stringify frees its intermediates; stringify result is an owning initializer

- **Date**: 2026-09-04

## Context

The benchmark campaign's `json_churn` (60 rounds of stringify/parse over
800 records) was MEM-KILLED at 512MB in manual/auto/auto-opt *at scale 1*,
while gc mode peaked at 182MB — meaning ~180MB of transient garbage per
run that only a collector reclaimed. Source: the stringify emitters build
their result by repeated full-copy concatenation (`jsonAppend` /
`emitStringConcat`), leaking every intermediate accumulator and element
fragment — quadratic transient allocation in the output length, in every
memory mode.

## Decision

Stringify's internal allocations are compiler-owned with statically known
lifetimes, so they are freed inline, independent of memory mode:

- `__kml_json_concat2(a, b, freeA, freeB)` (runtime_json.go): header-string
  concat that conditionally frees its inputs. All 15 concat sites in
  emit_call_json.go (array/object/tuple/settlement/map-dict loops and
  closing brackets) now route through it with compile-time ownership flags.
- Accumulators are uniformly owned: seeds ("[", "{") become heap copies
  (`jsonSeed` → `__kml_str_from_cstr`), so every append frees the previous
  accumulator unconditionally — no interned/heap discrimination at runtime.
- Fragments are uniformly owned: `emitJSONStringifyValue`'s interned-
  returning branches (bool select, JSON `null` for null objects /
  non-finite floats / absent nullable scalars) now hand back heap copies,
  materialized branch-locally so the copy only allocates when taken; the
  absent-nullable branch also frees the unconditionally-computed payload
  fragment. Interned key/punctuation fragments stay interned and are
  simply not freed (freeB=false).
- `JSON.stringify` joins `JSON.parse` in the implicit layer's owning-call
  whitelist, so `const text = JSON.stringify(data)` gets the block-exit
  free under `-mm=auto`.

## Consequences

- `json_churn` scale 1: MEM-KILLED → passes in every mode (manual 153MB,
  auto 136MB, auto-opt 145MB); scale 10 completes everywhere (auto 434MB).
- ASan/UBSan churn round-trip test (`TestE2EJSONStringifyChurnASan`)
  covers the new frees across fragment kinds — no double-free, no
  interned-literal free. Full JSON/Promise/Console/Memory lanes green;
  `make examples` 283/283 in default and MM=auto; Node oracle unchanged.
- Remaining, tracked separately: parse *trees* still only shallow-free
  (per-row objects/strings leak — the container/class deep-free gap shared
  with rbtree/closure_churn), and stringify's copying is still O(n²) in
  CPU (a growable builder would fix it; memory is now bounded either way).
