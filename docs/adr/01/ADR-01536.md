# ADR-01536: An async function adopts a returned promise when it settles

- **Relations**: Extends ADR-00265, ADR-01534, TDD-00223
- **Date**: 2026-10-10

## Context

`return p` of a typed promise in an async function awaited `p` at the
`return`. An enclosing `try` then caught a rejection of `p` (Node: the
function's promise rejects with it), and the function settled on a
different tick from Node's (PromiseResolve of a promise is a
NewPromiseResolveThenableJob, then `p`'s reaction). The inferred result
of an async function returning a promise on one path and a value on
another kept the promise as a union member (`Promise<never> | string`)
where tsc's is the awaited `string`.

## Decision

- The function's first `return <promise>` makes an adoption slot. A
  `return` of a promise whose value is stored as the function's own (or
  one that never fulfills) stores it there, runs the enclosing
  `finally` blocks and leaves; a `return` of a value clears it.
- The settled epilogue adopts a stored promise (`__kml_promise_adopt`)
  instead of fulfilling. The task epilogue does the same and calls
  `__kml_task_adopted`, so the trampoline's finish leaves the task's
  promise pending (a later microtask settles it and wakes its waiter).
- A suspending body with an `any` result resolves its promise with the
  value (`__kml_promise_resolve_any`) as the settled one does.
- An async function's inferred result type unwraps its promise members
  (Awaited); a promise that never fulfills adds none.
- Other promise returns (value types stored apart) still await.

None.
