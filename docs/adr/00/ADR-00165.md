# ADR-00165: String concatenation with a null operand

- **Relations**: Found while implementing [ADR-00164](ADR-00164.md)
- **Date**: 2026-08-11

## Context

Testing optional string parameters (ADR-00164) surfaced a crash unrelated to that feature: `function greet(name?: string) { return 'Hi, ' + name; } greet()` segfaulted (exit 139). Isolated to string concatenation itself, not optional parameters — `let s: string | null = null; console.log('Hi, ' + s)` crashed identically.

## Investigation

`emitStringConcat` (`codegen/llvm/emit_strings.go:27`) calls `strlen(ptr %left.Ref)` and `strlen(ptr %right.Ref)` unconditionally on both operands before allocating and `memcpy`-ing. `strlen(NULL)` is undefined behavior — a hard segfault in practice. Any code path that produces a null string and concatenates it hits this: a nullable-typed (`T | null`) string whose value happens to be null, an optional parameter's zero value (ADR-00164), or (per `emit_call_console.go:369`'s own existing comment on the identical hazard for `console.log`) a `Map`/collection lookup miss with no type-level nullability marker at all.

`emit_call_console.go`'s `emitConsoleArg` already solved the same problem for its own `ptr`-typed `console.log` argument: a runtime `icmp eq ptr %v, null` + `select` substitutes the interned `"null"` string before handing the value to `printf`'s `%s`. Real JS stringifies `null` the same way in `+` (`"x" + null === "xnull"`), so the fix is the same substitution, applied to both of `emitStringConcat`'s operands before `strlen`.

## Decision

Added `emitStringNullToLiteral(v Value) Value` to `emit_strings.go`: emits the `icmp eq ptr ..., null` / `select` pair and returns the substituted value, factored out so `emitStringConcat` can apply it to `left` and `right` identically. `emitStringConcat` now runs both operands through it before any `strlen`/`memcpy` call. Not folded into `emitConsoleArg`'s own copy of this pattern — one prints directly via `printf`, the other feeds a `strlen`/`memcpy` concatenation; keeping them separate, small functions matches this codebase's accepted pattern of small local duplication over a premature shared abstraction (see `FuncSig`-builder precedent in `codegen/llvm/emitter.go` et al.).

## Implementation notes

File touched: `codegen/llvm/emit_strings.go`. The added `icmp`/`select` pair is unconditional — including for arguments statically known to be non-null (e.g. two string literals concatenated together). Left this way rather than gating it behind a static-nullability check: the extra pair of instructions is cheap, and for any operand whose LLVM value is a constant non-null global pointer (string literals via `internString`), `clang -O2` constant-folds `icmp eq ptr @.str, null` to `false` and the `select` away entirely — verified no functional or binary-size difference on the existing string-concat-heavy call sites (`emit_arrays_sort.go`, `emit_call_json.go`, `emit_websocket.go`, `emit_headers.go`, `emit_fetch.go`, `emit_symbol.go`) via the full `go test ./...`/`make examples` run below.

## Verification

- `go build`, `go vet ./...`, full `go test ./...` — all pass.
- `make examples` — 110/110 pass, including the string-concat-heavy paths listed above (JSON stringify, WebSocket handshake, fetch header joining, `Symbol.toString()`).
- New regression test `TestE2EStringConcatWithNull` (`tests/strings_test.go`): a `string | null` variable set to `null`, concatenated on both the left and right side of `+`, both print `"null"` instead of crashing.
- Manual repro (`'Hi, ' + name` on an omitted optional string parameter, and the standalone `T | null` case) confirmed fixed, both now printing `Hi, null` / `null, world` instead of segfaulting.
