# ADR-01574: A program-wide bound on generic interface instantiation

- **Relations**: Extends ADR-01568, ADR-01573, Implements TDD-00230
- **Date**: 2026-10-11

## Context

The TypeScript acceptance suite was killed for memory a second time.
Running each case in its own process, with a 20-second timeout and a 4 GB
address-space limit, found a single case that misbehaves on its own:
`complexRecursiveCollections.ts` (Immutable.js-style `Collection`, `Keyed`,
`Indexed`, `Seq` interfaces whose methods return each other's
instantiations).

The checker resolves an interface's members eagerly when it instantiates
the interface. The per-symbol nesting guard (`tooDeep`, `maxNesting`)
bounds depth but not breadth, so these interfaces instantiated each other
combinatorially until the process ran out of memory. Inside the
conformance tool, the case's goroutine outlived its timeout and kept
allocating. That took the whole suite to 57 GB.

ADR-01568's return check first reached the explosion: it resolved every
return annotation, including async and generator ones, which the rest of
the check leaves alone. The ordinary return-type path reaches it too.

## Decision

- `interfaceOf` counts fresh generic instantiations per program. Past
  100,000 the instantiation is left unanswered, as `tooDeep` already does.
  This is the same bound tsc places on this growth with its instantiation
  count (TS2589).
- `checkReturnPaths` resolves the annotation only when the answer is
  needed. A generator annotation naming a standard iterator type is
  accepted by name. Any other annotation is resolved only when the body's
  end is reachable.

## Verification

The case finishes in 3 seconds with an ordinary codegen error. A
per-case scan of all 12,074 TypeScript suite cases under the same limits
found no other runaway. Mac: checker unit tests. Linux (DeskMini and
Node304 kmlbox) full gates, the TypeScript suite in both lanes among them.
