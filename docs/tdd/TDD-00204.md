# TDD-00204: Conformance denominator honesty — full upstream corpora, mechanical exclusions only

- **Status**: Partially Implemented
- **Date**: 2026-09-11

## Context

Every conformance suite in `tools/conformance` measures against a denominator
that was quietly narrowed at import time, and the narrowing has repeatedly
drifted from "genuine scope boundary" into "curated allowlist that flatters the
runner." An audit against the pinned upstream trees (counted from full git tree
metadata, not the sparse working copies) found:

- **WPT**: the pinned tree holds **4,207** headless multi-global source files
  (`.any.js`/`.window.js`/`.worker.js`) across the whole repo; the hand-picked
  21-directory `wptRoots` allowlist fetches and runs **1,344 (32%)**. Areas with
  implemented surface (`workers`, `eventsource`, `webstorage`, most of `html/`,
  full `wasm`) were never fetched — excluded by omission, invisible in the
  report.
- **Test262**: the raw run walks all 53,872 files, but the in-scope filter
  excludes the **5,624 `async`-flagged files** with a "deferred until measured"
  note despite async/await, Promises, and the event loop being long shipped;
  excludes the **832 `module`-flagged files** despite the resolver's import
  merging; and still lists `decorators` (COMPLETE, ADR-00641–00649) and all of
  `Reflect` (`Reflect.get`/`has` shipped, ADR-00640) as out-of-scope features.
- **Node oracle**: only `test/parallel` is fetched. `test/es-module` (175 — an
  ESM compiler skipping the ESM suite), `sequential` (121), `message` (11),
  `internet` (38), `pummel` (52), `known_issues` (17) are absent from the
  denominator entirely.
- **TypeScript oracle**: the full case corpus is fetched, but every multi-file
  case (`// @filename:` directives) is skipped as "out of scope for single-entry
  V1" even though the compiler resolves multi-file imports.

Well-respected runners publish against the full corpus: wpt.fyi/Servo report
~52–56K WPT test documents (~1.8–2M subtests). Numbers published here will be
compared against those; a denominator that can't be defended line-by-line reads
as dishonesty even where each individual cut had a rationale.

## Design

One principle, applied to all four suites: **the denominator is the full pinned
upstream corpus; every exclusion is mechanical (derived from the file's own
metadata or a named capability gap), appears in the report as a counted bucket,
and is re-justified when a related feature ships. Allowlists are banned.**

### Track 1 — WPT: run the whole headless class, report the capability ladder

- Delete the `wptRoots` allowlist; walk the entire `.wpt-tests` corpus for
  headless sources. The existing DOM-needle / out-of-scope-include classifiers
  absorb browser-hardware and DOM-tree files into the *reported* skip
  histogram — classification moves from fetch time (invisible) to run time
  (counted).
- `fetch.sh` switches the WPT sparse-checkout from directory names to
  suffix/pattern rules (`*.any.js`, `*.window.js`, `*.worker.js`, plus
  `resources/`, `common/`, per-test `resources/` and `util/` helper dirs), so
  the blobless clone stays small while covering every area. The readiness
  marker gains a slice-version suffix so a pattern change forces a refetch.
- `fetch.sh` also writes a corpus-stats manifest (from `git ls-tree -r`) with
  the full-tree class counts: total files, `.html` documents (css vs non-css),
  `-manual`, `crashtests/`, `webdriver/`, headless sources. The report opens
  with the **capability ladder** so the numbers are comparable to Servo/wpt.fyi
  instead of challengeable:
  1. full browser engine (rendering): ~52–56K test documents — includes ~36K
     css reftests, unreachable for any non-browser runner;
  2. DOM-but-no-rendering (jsdom-tier): + the testharness `.html` class
     (~20–25K documents) — reachable **after Track 5**;
  3. no DOM (this runner today): the 4,207 headless sources.
- **Variant-aware comparability count**: wpt.fyi counts each `META: global=`
  expansion (`.any.html`, `.any.worker.html`, …) as a separate test. Parse the
  `global=` line (default `window,dedicatedworker`) and report the expanded
  document count alongside the source-file count. Each source still *runs*
  once — this runtime has no distinct worker global scope to vary — stated
  explicitly in the report rather than silently counted as coverage.

### Track 2 — Test262: retire stale exclusions, run async

- Drop `decorators` from `outOfScopeFeature`; narrow the blanket `Reflect`
  exclusion to the genuinely unimplemented members (keep `Proxy`,
  `proxy-missing-checks`, prototype-mutation tags).
- **Async harness**: support the `doneprintHandle.js` protocol — inject the
  `$DONE` include, detect `Test262:AsyncTestComplete` /
  `Test262:AsyncTestFailure:` on stdout after the event loop drains, and bring
  the 5,624 `async`-flagged files into the in-scope denominator.
- **Module flag**: attempt `module`-flagged files through the resolver instead
  of pre-excluding; real failures (multi-file graphs, namespace semantics)
  surface as counted FAIL reasons.
- **Dynamic code is a pending capability, not out of scope.** The `-compat=js`
  lane exists precisely for the untyped corpus, and eval/dynamic `import()`
  are a planned opt-in embedded-engine path (TDD-00046). `dynamic-import`,
  `import-assertions`/`import-attributes`, and eval-dependent files therefore
  stay **in** the denominator, reported under a named
  "pending opt-in engine" bucket — a capability rung on the ladder (like the
  DOM shim for WPT), never an exclusion. `outOfScopeFeature` shrinks to the
  genuinely-never set (Intl, `IsHTMLDDA`, ShadowRealm, tail-call metadata).

### Track 3 — Node oracle: fetch the missing suites

Add `test/es-module`, `test/sequential`, `test/message` to the sparse checkout
and the walk (es-module first — highest relevance). `test/internet` fetched and
run (real network exists here); `pummel`/`known_issues` fetched but reported as
named skip buckets (stress-scale / documented-upstream-bugs), so they sit in
the denominator visibly.

### Track 4 — TypeScript oracle: materialize multi-file cases

Split `// @filename:` cases into real files in a per-case scratch dir and
compile the last file as the entry (TypeScript's own convention). Cases the
single-entry model genuinely can't express (triple-slash `/// <reference>`,
`@module: amd/umd` variants) become counted skip reasons.

### Track 5 — headless DOM shim (the jsdom move)

The capability that unlocks ladder tier 2 (~20–25K testharness `.html`
documents). Real subsystem design — element tree, event propagation, parser —
scoped in its own TDD before any code; this track only fixes its place in the
ladder and the reports.

### Reporting rule (all suites)

Every report leads with: full upstream corpus size → mechanical exclusion
buckets with counts and reasons → runnable denominator → pass numbers (files
and subtests where the suite defines them). A shipped feature's exclusion tag
is removed in the same delivery that ships the feature.

## Open questions

- Whether to *execute* WPT worker-scope variants once real Worker-global
  differences exist (today execution would be identical; only counting differs).
- Test262 `module`-flag files that import sibling fixture files: whether the
  resolver's single-merged-program model is observably equivalent for the
  affected semantics tests, or some must become a named exclusion bucket.
- DOM shim scope line (element tree + events + parser vs layout-adjacent APIs
  like `getBoundingClientRect`) — deferred to its own TDD.
