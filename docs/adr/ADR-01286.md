# ADR-01286: checker inference — constraints, defaults, tuples in arrays

- **Relations**: `Extends ADR-01283`, `Implements part of TDD-00230` (P2)
- **Date**: 2026-09-29

## Context

ADR-01283 made `instantiate` substitute inside generic class and
interface references. References that used to stay uninstantiated, and
so were accepted by default, were now checked. That exposed inference
gaps as false type errors:

- **`Buffer.from(string, encoding)`** picked the overload
  `from<TArrayBuffer extends ArrayBufferLike>(arrayBuffer)` with
  `TArrayBuffer = string`. Constraints were not checked while picking an
  overload, and a declared method signature's type parameters had no
  constraint or default recorded at all.
- **`new Map([['a', 1]])`** inferred `Map<unknown, unknown>`. An array
  literal of tuples was not typed against a `(readonly [K, V])[]` context
  (nor a `ReadonlyArray`, nor such a context inside a union).
- **`promisify(exec)`** became `() => Promise<unknown>`. Before, a type
  parameter that nothing inferred left the result unanswered.

Three tests were not valid TypeScript, and tsc rejects them as the
checker now does:

- `ref.deref().id`;
- a call of a `Map.get` result;
- a FinalizationRegistry holding a value of another type.

## Decision

- An overload whose inferred type arguments break their `extends`
  constraints does not fit, and the next overload is tried (tsc's
  chooseOverload).
- A method or call signature's type parameters carry their constraint and
  default.
- `argTypeFor` types an array literal against an array or `ReadonlyArray`
  context of tuples element by element, and takes the array or tuple
  member of a union context.
- An overload's result that mentions a type parameter with no inference,
  no explicit argument and no default stays unanswered.
- Return type inference: an argument whose parameter is a type parameter
  `T` the other arguments leave uninferred, of a call returning `T`, is
  typed in the call's own context. So `take(wrap((x) => …))` gives `x`
  `take`'s parameter type.
- A function literal does not fit an overload parameter that cannot hold a
  function (`mustCall(exact?: number)`).
- `ContextualSignature(fn)` exposes a literal's contextual signature.
- The three tests use the forms tsc accepts (`!`, an `object` held
  value).

## Verification

Mac (Apple Silicon): `checker/check_test.go` covers each case, and the
tests that failed after ADR-01283 pass.
