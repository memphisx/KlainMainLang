# TDD-00175: Deep reclamation — container elements and object graphs under `-mm=auto`

- **Status**: Not Started
- **Date**: 2026-09-04

## Context

The `-mm=auto` implicit layer (TDD-00173) frees a binding's *top-level*
allocation at block exit — "shallow free" by design: an array free releases
the data buffer, an object free the one struct, a map free the header and
its internal arrays. Everything reachable *through* the value is untouched.
The first benchmark campaign (benchmarks/results/2026-09-04.md) showed this
is now the dominant leak class, and the main blocker for TDD-00174's
auto-default flip:

- `json_churn`: each round's `JSON.parse` tree gets a shallow array free;
  the per-row objects, their strings, and their nested arrays all leak —
  auto peaks at 434MB (scale 10) where gc holds 120MB.
- `closure_churn`: 15k closures pushed into a per-round array; the array
  buffer is freed, the 15k `{fn, env}` pairs (and captured cells) leak —
  auto 210MB vs gc 6.8MB.
- `rbtree`: a persistent tree rebuilds the path on every insert; the
  dropped path nodes are garbage immediately, mid-block — auto OOMs at
  512MB, gc holds 50MB.

These are three different problems wearing one symptom, and they need
different machinery. Conflating them would either overreach (whole-program
RC for what is mostly a scoped-churn problem) or underdeliver (a deep free
that can't touch rbtree's mid-block garbage). This TDD separates them.

Rebind-free (ADR-00712) and the stringify-internal frees (ADR-00713) are
prerequisites already landed: bindings can churn without leaking their own
top-level value, and compiler-owned intermediates are freed inline. What is
missing is reclaiming what a freed value *owns*.

## Design

The problem decomposes on one axis: **when does the garbage die?**

1. Everything under the binding dies together, at block exit → a deep
   (recursive) free suffices — if exclusive ownership can be proven.
2. Garbage arises mid-block, while the binding lives on (rbtree's dropped
   path nodes) → block-scoped freeing can never reclaim it; only a
   per-object lifetime mechanism (reference counting) can.

### Stage 1 — Type-directed deep free for transitively-owned bindings

For a binding whose static type is a tree of freeable types (arrays of
objects, objects with string/array fields, arrays of closures), synthesize
a recursive free routine and use it instead of the shallow one, when the
flow analysis proves the binding *transitively* owns its graph.

**Synthesized frees.** Per concrete type, a `__kml_free_deep_<hash>`
function generated on demand (same on-demand pattern as the JSON
stringify/projection walkers, which already traverse exactly these
shapes): array → loop elements, recurse, then free data buffer; object →
recurse pointer-typed fields, then free struct; string/closure/map →
existing shallow frees (`__kml_str_free`, `__kml_closure_free`,
`__kml_map_free`). Null-checked at every pointer hop (absent nullable
fields). Static types cannot express cyclic ownership without an escaping
alias having been stored first, so a qualifying graph is acyclic and
termination is structural.

**Eligibility: transitive ownership.** The existing escape analysis proves
the *top* pointer stays block-local. Deep free additionally requires that
no *interior* pointer outlives the block or is shared inside the graph:

- Every value stored into the graph is provably fresh at the store site —
  an object/array literal, `new`, an owning-call result (`JSON.parse`,
  `JSON.stringify`, the fresh-result container methods), or a closure
  literal. Storing an identifier (a potential alias) disqualifies —
  exactly `autoFreeOwningInit`'s freshness discipline, applied to
  `push`/element-store/field-store sites instead of initializers.
- No interior extraction escapes: reading `x.field` / `x[i]` into a new
  binding, passing it to a non-whitelisted call, returning it, or storing
  it elsewhere disqualifies the root. Leaf reads (scalar fields,
  `.length`, comparisons, string-coercion into fresh buffers) are safe —
  the same read-vs-alias classification `escChecker` already makes for
  the top-level name, extended to member/index chains rooted at it.
- The type gate excludes graphs containing class instances (a method may
  retain `this` — same rule as today), `any`/dynamic values, and weak/
  finalization-registered types under gc.

This covers `json_churn`'s `parsed` (only `.length` is read) and typed
parse trees generally — the single biggest real-workload shape (request
bodies, config). It does *not* yet cover `closure_churn` (elements come
from `makeAdder(i)`, a user call — freshness stops at the function
boundary) or `rbtree` (interior nodes flow through `ins`/`balance`
constantly, and its garbage is mid-block anyway).

**Placement.** Verdict piggybacks on `planAutoFrees` (a `deep` flag beside
the existing plan/rebind maps); emission replaces `freeSymbol`'s shallow
call for flagged bindings. Rebind-free composes: a rebind of a
deep-qualified binding deep-frees the old graph.

### Stage 2 — Interprocedural freshness (`@fresh` returns)

Widen Stage 1 across function boundaries: a function whose every return
path yields a provably fresh, transitively-owned value (a closure literal,
an object literal of fresh parts) is a *fresh producer*; its call results
count as fresh at store sites. Inferred bottom-up over the program's
non-recursive call graph (same whole-program pre-pass shape as
`collectOwnedFns`), with a `/** @fresh */` JSDoc escape hatch for cases
the inference misses (mirroring `@owned`'s explicit-contract pattern —
except violations of an *inferred* freshness are silent downgrades, while
an annotated one that fails is a compile error).

This is what `closure_churn` needs: `makeAdder` returns a closure literal
capturing only a scalar — a fresh producer — so `fns.push(makeAdder(i))`
keeps the array transitively owned, and the per-round deep free reclaims
all 15k closures.

### Stage 3 — Reference counting for mid-block garbage (rbtree-class)

Block-scoped freeing structurally cannot reclaim a value dropped while
its owner lives on. The options considered:

- **Per-scope arena/region**: interior aliasing becomes harmless
  (everything dies together), but mid-block garbage accumulates until
  scope exit — rbtree's peak is unchanged. Rejected as the primary
  mechanism; may return later as an allocator optimization for Stage 1
  graphs (one arena free instead of N walks).
- **Whole-program RC**: inc/dec on every store/copy/call. Correct and
  general (the Perceus literature's home turf — reuse-in-place is the
  natural follow-on, and `rbtree.ts` was written as that yardstick), but
  it taxes every pointer operation program-wide and needs cycle handling
  for `-compat=js`-era dynamic values.
- **Scoped RC** (recommended): RC only for allocations the escape
  analysis routes into a *qualifying cluster* — a binding group whose
  types form a closed ownership graph (rbtree's `Node`: fields only
  point to `Node | null`, tree never escapes the block). Within the
  cluster, stores emit dec-old/inc-new and last-reference death frees
  the node; outside it, nothing changes. The static type closure makes
  the counted world small and cycle-free-by-construction (a cycle would
  require storing a live alias, which the same store analysis flags —
  a flagged cluster silently falls back to today's leak).

Stage 3 is the largest piece and the only one touching hot store paths;
it ships behind `-optimize-memory` first (per the TDD-00174 posture:
every deliverable tests auto+optimize), promoted when the differential/
ASan/soak gates pass. If scoped RC proves out, reuse-in-place (freeing
into a per-size free list consulted by the very next same-shape
allocation — Perceus's trick, and the actual prize on rbtree) is a
natural Stage 4, but is out of scope here.

### Explicitly out of scope

- The `-optimize-memory` binary_trees RSS regression (107MB where plain
  auto holds ~0) — a separate bug in the existing stack-allocation
  planner, to be root-caused independently.
- The O(n²) stringify builder (CPU, not reclamation).
- Thrown-path frees (auto's documented leak-on-throw posture is
  unchanged).

## Open questions

- Stage 1 store-site analysis granularity: per-binding whole-graph verdict
  (simple, recommended start) vs. per-field/per-element partial deep frees
  (free the owned parts, skip the aliased field) — partial frees double
  the analysis surface for unclear real-workload gain.
- Stage 2: is inference over non-recursive calls enough for real code, or
  does `@fresh` end up mandatory in practice (making it a documented
  annotation rather than an escape hatch)?
- Stage 3 counting representation: header word before the allocation (à
  la the string length prefix — uniform, but perturbs every qualifying
  type's layout) vs. side-table (no layout change, hash cost on every
  touch). Header word is the working assumption.
- Whether Stage 3's cluster fallback (silent leak) should be surfaceable
  (a `-finalizers=report`-style diagnostic listing clusters that failed
  qualification and why) for tuning real programs.
