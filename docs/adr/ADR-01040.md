# ADR-01040: An out-of-range element read is `undefined`, not a throw

- **Relations**: `Supersedes ADR-00157` (the read half — the bounds *throw*); `Extends ADR-01038, ADR-01039`; `Implements TDD-00187` (the `T | undefined` representation, reused)
- **Date**: 2026-09-21

## Context

`rows[5]` on a three-element array threw a catchable `Error: Array index out of bounds` (ADR-00157). Node reads `undefined`: `console.log(a[5])` prints `undefined`, `a[5] === undefined` is `true`, `a[5] ?? d` takes the default, `a[5]?.name` short-circuits, and `a[5].name` is the `TypeError: Cannot read properties of undefined (reading 'name')` ADR-01038 introduced. The throw was a deliberate safety choice made when there was no way to represent an absent element; TDD-00187 has since given every scalar and pointer a `T | undefined` form, so the faithful behaviour is now representable. The project is pre-alpha and nothing outside its own examples depended on the throw.

## Investigation

- `emitIndexPtr` (`codegen/llvm/emit_exprs_member.go`) did the bounds check and the throw for reads, compound assignment (`a[i] += 1`) and the fixed-bounds store alike.
- `.at()`, `.pop()`, `.shift()`, `.find()` already return the `T | undefined` value (`wrapUndefinedable`). A probe comparing every consumer of `nums.at(9)` against Node under `-compat=js` matched exactly (console.log, `===`, `typeof`, `??`, template literal, arithmetic, call argument, object field, array literal, `JSON.stringify`) — the consumers existed; only the producer was missing.
- tsc types `a[i]` as plain `T` (no `noUncheckedIndexedAccess`), so the strict-mode "possibly undefined" gates (`checkStrictUndefinedAssign`, the arithmetic/relational gate in `emitBinary`) must not fire for it, and an *inferred declaration* (array element type, return type) must stay `T` — otherwise `idx.map(i => vals[i])` becomes a boxed `(number | undefined)[]` that no `number[]` parameter accepts.

## Decision

- **`emitIndexRead`** replaces the read use of `emitIndexPtr`. One unsigned compare (`index < length`, which also rejects a negative index) selects between loading the element and the miss value; the result is the element's `T | undefined` form: `{ i1, T }` for a scalar, a null pointer for a string/object, the `{null,0}` aggregate with a null header for a nested array, the `undefined` box for a dynamic element. A missing `double` payload is NaN, so arithmetic on a missing float element gives what Node gives.
- **`Type.UncheckedIndex`** marks that result type (`indexReadType`, shared by emission and `inferExprType`). The two strict gates let an `UncheckedIndex` value through, as tsc does. `Type.staticIndexType()` drops the flag and the nullability where a declaration is inferred — `arrayElemType` applies it, so inferred arrays keep plain `T` elements.
- `emitIndexPtr` keeps its throw for the remaining callers: compound assignment and the fixed-bounds store.
- A ternary with a `T | undefined` scalar branch (`c ? a[i] : 0`) is the nullable scalar, not a bare `T` slot (`ternaryNullableScalarType`) — this was invalid IR for `c ? xs.pop() : 0` before this change too.

## Implementation notes

`emit_exprs_member.go` (`emitIndexBase`, `indexElemGEP`, `emitIndexRead`), `emit_undefined.go` (`indexReadType`, `isNullishLiteralTy`), `types.go` (`UncheckedIndex`, `staticIndexType`, `arrayElemType`), `emit_exprs_types.go`, `emit_exprs_operators.go`, `emit_collections.go`, `emit_inspect.go`.

## Side effects discovered

- `emitBinary` classed any type carrying `IsUndefined` as a bare `undefined` operand, so `string | undefined` + `string | undefined` (`process.argv[2] + process.argv[3]`) was rejected as "operator '+' on null/undefined". `isNullishLiteralTy` now tells the literal from a `T | undefined` value. Fixed.
- `Map.set(k, xs.pop())` stored the `{ i1, T }` aggregate through a scalar `bitcast` — invalid IR. `valueToMapVal` unwraps the payload. Fixed.
- A null string inside an inspected array/object printed as the quoted text `'null'`; it now prints the bare keyword (`undefined`, or `null` for a `string | null`). Fixed.
- An integer (`i64`-backed) element has no NaN: arithmetic on a missing integer element reads the payload zero (`ints[9] + 1` is `1`, Node gives `NaN`). Every non-arithmetic observation (`console.log`, `===`, `typeof`, `??`, `?.`, truthiness) is faithful. This is the same limit the `number → i64` mapping already has everywhere.
- A *write* that leaves a gap (`a[len + 2] = v`) and a negative-index write still throw: a hole has no representation in a typed scalar buffer. Unchanged here.

## Verification

Windows x64. Probe programs diffed against Node 24 (`node --experimental-strip-types`): reads of number/float/string/object/boolean/nested/typed arrays in and out of range, consumers listed above, inferred containers, ternaries, compound assignment — identical output. E2E: see the tests in `tests/arrays_test.go`.
