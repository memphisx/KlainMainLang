# ADR-00189: `JSON.parse` into an array-typed field is a clean rejection, not invalid IR

- **Relations**: Fixes a bug tracked under [TDD-00015](../tdd/TDD-00015.md)
- **Date**: 2026-08-13

## Context

`JSON.parse` into an object/interface type whose target shape had an **array-typed field** (`interface Bag { tags: string[] }`) emitted invalid LLVM IR and hard-failed at the clang stage (`'%tN' defined with type 'i64' but expected 'ptr'`) instead of raising the clean compile-time rejection that a **nested-object** field already gets. Found while scoping [TDD-00015](TDD-00015.md) and tracked in the status doc's "bugs found but not yet fixed" table with the fix pre-identified as a one-line addition.

## Investigation

- `emitJSONParseObject` (`emit_call_json.go`) runs an upfront rejection loop over the target type's fields, but only checked `f.Ty.IsObject`. An array-typed field passed that check and fell through to the per-field parse path (`emitJSONParseFieldValue`), whose scalar-only switch defaults to an `atoll` (`i64`) parse. That `i64` value was then merged via `phi` against the field's actual `ptr`/aggregate array slot — a type mismatch clang rejects outright.
- This is a compile-time failure, not silent runtime corruption (the mismatched IR never links), but it's the wrong *kind* of failure: an internal codegen crash surfaced as a clang error, rather than the compiler's own clear diagnostic.

## Decision

Add an `f.Ty.IsArray` branch to the same upfront rejection loop, mirroring the existing `IsObject` one: `JSON.parse into an array-typed field ('tags') is not yet supported`. Actually parsing a JSON array into a typed field stays out of scope (the same scope boundary as nested-object fields, [TDD-00015](TDD-00015.md)); this ADR only fixes the *failure mode*, turning an internal IR crash into a clean, actionable rejection.

## Verification (Linux, x86-64)

- `interface Item { name: string; tags: string[] }; const it: Item = JSON.parse('{"name":"x","tags":["a","b"]}')` now reports `codegen error: JSON.parse into an array-typed field ('tags') is not yet supported`, where it previously emitted invalid IR and a clang type-mismatch error.
- New E2E test `TestE2EJSONParseArrayFieldRejected` in `tests/objects_test.go` asserts the clean rejection; scalar-field `JSON.parse` (including the `float64` field case) still works.
- Full `go test ./...` green; `go vet` clean.
- `make conformance` re-run — see `docs/testing/CONFORMANCE-RESULTS.md`.
