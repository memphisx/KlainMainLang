# ADR-01406: A connection fiber's await parks on its promise

- **Relations**: Implements TDD-00244; Supersedes ADR-00986
- **Date**: 2026-10-05

## Context

`__kml_task_await_ready` on a connection fiber (an await outside any task)
did not wait the way the rest of the runtime does:

- With no request body streaming, it looped: drain microtasks, step the
  task scheduler, `__kml_timer_fire_next`, then yield. `__kml_timer_fire_next`
  *sleeps* until the earliest timer is due, so the whole server stopped for
  as long as the next timer was away.
- With the fiber's own request body streaming, it never yielded at all
  ([ADR-00986](../00/ADR-00986.md)): it spun on the fiber, the same three calls
  plus `usleep(200)` per cycle, because a yielded fiber would have been
  resumed on its own readable descriptor.

## Decision

- The fiber parks on the promise: the connection slot's group field holds
  the promise tagged by bit 0, and the loop's resume scan
  (`conn_park_ready` in `loop.c`) resumes the fiber once the promise has
  settled, not on its descriptor's readiness. Timers, I/O and the
  request-body pump run in the loop meanwhile. `loop.c` now carries the
  generated layout header for the promise's state offset; `KML_CONN_GROUP`
  joins it.
- Back on the loop's stack after a fiber swap, `__kml_current_conn_idx` is
  -1. The stale index had made loop-context code (the request-body pump's
  continuations, now able to run while a fiber is parked) take the fiber's
  path in `__kml_reqbody_pull` and swap through the parked fiber's context
  from the loop's stack, corrupting it (a SIGBUS in the upload example).
- With no caller left, `__kml_timer_fire_next` (and its sleep) and
  `__kml_reqbody_active_on_fd` are deleted. The IR-text ratchet drops for
  `emitter.go` (17 to 16), `runtime_task.go` (20 to 19) and
  `runtime_http_reqbody.go` (10 to 9).

## Verification

- Mac (M4): the request-body stream test and the 8 MiB upload example; a
  handler awaiting a timer while a second request arrives (`fast` answered
  before `slow`, as Node orders them).
- Linux (x86-64, Ubuntu 24.04 container), with ADR-01406 to ADR-01409: the
  full test suite (3,927 tests), the 393 examples, and Test262 in both lanes
  (strict 8,498, js 10,506, unchanged, no invalid IR).
