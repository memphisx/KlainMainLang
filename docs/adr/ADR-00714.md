# ADR-00714: Append-by-index — `arr[i] = v` at `i == length` grows the array

- **Date**: 2026-09-04

## Context

Fetching PerryTS's benchmark suite into the harness (benchmarks/programs/
perry/, 17 kernels) surfaced a JS-faithfulness gap: four of the kernels
populate arrays with the standard idiom
`const arr: number[] = []; for (let i = 0; i < N; i++) arr[i] = v` —
and every klain mode died with "Array index out of bounds". Real JS
extends the array on a write at `index == length`; the bounds check
treated any `index >= length` store as an error.

## Decision

A plain `=` store into a growable array distinguishes three cases
(emitArrayIndexAssignGrow, emit_arrays_mutate.go):

- `index < length`: in-place store, as before.
- `index == length`: grow by one — the same realloc-append `push` uses,
  through the shared array header, so every alias (including a callee
  the array was passed to) observes the growth.
- `index > length`: still throws. Real JS would materialize `undefined`
  holes; a typed element model has no representation for those, so the
  divergence remains — now scoped to genuine hole-creating writes only,
  and documented here.

The RHS is evaluated before the header is read (a RHS like `arr.push(0)`
may itself reallocate the array), with the fixed-bounds path's exact
element-typing discipline (`emitExprWithObjectHint` + `coerceChecked`,
TDD-00028/ADR-00688 — a type-mismatched store stays a clean compile
error). Scope: named/field/element-resolvable growable arrays via
`resolveArrayMutLoc`; flat `@value` arrays, TypedArrays (fixed length by
spec), compound ops (they read the slot first, where out-of-range is a
genuine error), and rvalue receivers keep the fixed-bounds path.

## Consequences

- All four failing Perry kernels (03_array_write, 04_array_read,
  10_nested_loops, 11_prime_sieve) now run with node-identical output.
- E2E coverage: append via loop/`arr.length`/callee-alias growth, string
  concat RHS, gap-write still throwing, type-mismatch still rejected.
  Array/Tuple/Flat/Boxed lanes green; examples 284/284 (new
  `examples/arrays/index_append.ts`).
