# ADR-00135: `export default`, default imports, and namespace imports

- **Relations**: Extends [ADR-00022](ADR-00022.md), [ADR-00134](ADR-00134.md). Implements [TDD-00042](../tdd/TDD-00042.md)
- **Date**: 2026-08-09

## Context

[MODULES.md](../status/MODULES.md) listed `export default`, `import * as ns from '...'` (namespace import), and re-exports as the three remaining named-import-adjacent gaps at ~46% coverage, right after [TDD-00041](../tdd/TDD-00041.md)/[ADR-00134](ADR-00134.md) shipped true per-file module scope and import aliasing. [TDD-00042](../tdd/TDD-00042.md) scoped the first two (re-exports left for a future TDD — a distinct problem: a file re-publishing a name it didn't itself declare). This ADR is that implementation.

## Investigation

- Confirmed `export`'s existing `exported map[string]bool`/`mangled map[string]string` tables (`resolver.go`, built by TDD-00041) already generalize to a default export with zero structural change — `"default"` is just one more possible key in each, alongside a real declaration's own name. The only new work was populating that key correctly.
- Confirmed `lexer.DEFAULT` is already a real reserved keyword (used today only by `switch`'s `default:` clause), not an `IDENT` — meaning no real top-level declaration can ever be named `default` via normal parsing. This makes the literal string `"default"` a permanently collision-free synthetic name for the anonymous-declaration and wrapped-expression default-export forms, reusing `mangleFileDecls`'s existing per-declaration mangling and duplicate-detection with no special-casing needed for those two sub-cases.
- Checked `parser.parseNew` (`parser/parser_literals.go:111`) directly before assuming `new ns.SomeClass(...)` needed handling: it already requires a single `IDENT` token after `new`, with no member-expression form at all, regardless of namespaces. Confirmed this is a pre-existing, namespace-independent restriction, not a new gap introduced here — no parser work attempted for it.
- Considered two ways to let the rename pass (`resolver/rename.go`, TDD-00041) replace a `*ast.MemberExpression` node (`ns.foo`) with a plain `*ast.Identifier` (foo's mangled name) — a wholesale node-type swap the pass's original in-place-mutation design couldn't do: (1) change `rewriteExpr`'s signature to return the (possibly replaced) expression and update every call site to reassign it back into the field/slice element that held the original, or (2) a second, separate, self-contained tree-walking pass just for namespace resolution, run before the existing one, leaving `rename.go` untouched. Went with (1), per the TDD's recommendation: (2) would require re-implementing a second full expression/statement/type walker with the same ~30-case shape as `rewriteExpr`'s existing switch, an ongoing duplication-maintenance cost every future new AST node kind would need updating twice for, versus (1)'s one-time mechanical churn.
- Found, while testing the first namespace-import example by hand, that `ns.default` — the natural way to reach a default export through a namespace import — was unparseable: `parseCallMember`'s dot-access handling (`parser/parser_exprs.go`) required a plain `IDENT` token after `.`/`?.`, and `default` lexes as the reserved `lexer.DEFAULT` keyword, not `IDENT`. This is a real, generic pre-existing gap (accessing a property literally named `default` on *any* object was already impossible, not something this feature introduced), directly blocking a legitimate use of the feature being built — fixed per this project's own standing practice of fixing bugs found during development rather than papering over them, narrowly scoped to just this one keyword (`expectPropertyName`, `parser/parser_exprs.go`) rather than a broader "any reserved word can be a property name" change real JS/TS allow.

## Decision

**`export default`**: `ast.ExportDeclaration` gained an `IsDefault bool` field. The named form (`export default function foo() {...}`/`class Foo {...}`/`interface`/`type`/`enum`) keeps the declaration's own name for mangling and intra-file self-reference (recursion, static self-reference), and `mangleFileDecls` additionally aliases `mangled["default"]` to that same mangled name; `exportedNames` exposes the file's export set under `"default"` only for an `IsDefault` declaration, not also under its own name — matching real ES modules, where `export default function foo() {...}` does not also make `foo` importable via `import { foo }`. The anonymous form (`export default function() {...}`/`class {...}`) and the expression form (`export default 42`, wrapped at parse time as `ast.VarDeclaration{Kind: "const", Name: "default", ...}`) both just use the literal name `"default"` directly, reusing the exact same generic mangling path with no special-casing. A second `export default` in the same file is rejected explicitly in `mangleFileDecls` (the two underlying declarations may have different own names, e.g. `foo`/`bar`, so wouldn't be caught by the existing same-name duplicate check).

**Default import** (`import x from './path'`, or combined `import x, { a, b } from './path'`): parsed as sugar for `ast.ImportSpecifier{Imported: "default", Local: "x"}`, prepended to any named specifiers. This reuses every existing specifier-validation and lookup-building code path in `resolver.go` unchanged — no new resolver logic beyond what `export default` above already provides. `import x, * as ns from './path'` (combining default + namespace) is deliberately not supported.

**Namespace import** (`import * as ns from './path'`): `ns` is a compile-time-only construct, fully erased during resolution, never a runtime value — this compiler has no runtime module-object representation, and building one for a mix of genuine runtime values (functions, consts, classes) and pure compile-time constructs (interfaces, type aliases) would be real, disproportionate work given this compiler's fixed-shape-struct object model. `ast.ImportDeclaration` gained a `Namespace string` field (local alias; empty unless this is a namespace import). The rename pass's `MemberExpression` case (in `rewriteExpr`, now returning `ast.Expression`) checks whether `e.Object` is an `Identifier` bound (via a new per-file `ns map[string]map[string]string` table, alongside the existing `names` table, bundled into a `lookupTable` struct threaded through the whole walk) to a namespace import; if so, and the accessed member is one of the target file's actually-exported names, the whole `MemberExpression` node is replaced with a fresh `Identifier` referencing that member's mangled name — indistinguishable afterward from a normal named import of just that one member. `ns` used any other way (assigned to a variable, passed as a value, computed access) is left unresolved and reaches codegen as a genuinely undefined reference, which fails there with codegen's existing generic error rather than a namespace-specific message — an accepted V1 quality gap, not a functional one, per the TDD's own Open Questions.

## Implementation notes

- `ast/nodes.go`: `ExportDeclaration.IsDefault`, `ImportDeclaration.Namespace`, `NewExportDeclaration`/`NewImportDeclaration` signatures updated (one call site each, both in `parser/parser_imports.go`). Also corrected `ImportSpecifier`'s doc comment, which still said aliasing was "not yet supported" — stale since TDD-00041 shipped it.
- `parser/parser_imports.go`: `parseImportDeclaration` now branches on the token after `import` (`{` named-only, bare `IDENT` default [+ optional `, { ... }`], `*` namespace) via a new `parseImportSpecifierList` helper factored out of the old body. `parseExportDeclaration` branches on `lexer.DEFAULT` and delegates to a new `parseDefaultExportTarget`.
- `parser/parser_stmts.go` / `parser/parser_classes.go`: `parseFunctionDecl`/`parseClassDecl` both gained a `defaultName string` parameter — used as the declaration's name only when no `IDENT` follows `function`/`class` and `defaultName != ""` (the anonymous-default-export forms); every pre-existing call site passes `""` and keeps the original "name required" behavior unchanged.
- `parser/parser_exprs.go`: new `expectPropertyName` helper (accepts `IDENT` or the literal `default` keyword) used by both `DOT`/`OPTIONAL_DOT` cases in `parseCallMember` — the `ns.default` fix described above.
- `resolver/resolver.go`: `mangleFileDecls` now also returns the `"default"` alias (with the one-default-per-file check) and takes the file path for its error message; `exportedNames` special-cases `IsDefault`. The "build each file's own lookup table" loop in `ResolveProgram` now also builds a per-file `ns map[string]map[string]string` (namespace alias → {exported member name → mangled name}, restricted to `target.exported`) and passes both tables to `renameFile` as a `lookupTable`. Namespace aliases are checked against the same "already declared in this file" collision the specifier loop already enforced, in both directions.
- `resolver/rename.go`: `map[string]string` lookup parameters across the whole file became `lookupTable` (bundling `names` and the new `ns`), and `rewriteExpr` now returns `ast.Expression` — every one of its ~50 call sites was updated to reassign the result back into the field/slice element that held the original expression (a bare discarded call would silently drop a namespace-member replacement). The `MemberExpression` case does the actual namespace-member rewrite, guarded by `!sc.bound(id.Name)` so a local variable that happens to shadow a namespace alias's name is left as an ordinary, unresolved member access.

## Side effects discovered

- `ns.default` was unparseable before the `expectPropertyName` fix described in Investigation — fixed as part of this same piece of work, narrowly scoped to the one keyword this feature actually needs (`default`), not a general "any reserved word is a valid property name" change.
- Verified only on the x86-64 Linux box this session ran on, same as ADR-00134 before it — nothing in this change touches platform-specific code (`gcsrc/`, `runtime_os.go`, etc.), so no reason to expect Mac-specific divergence, but it hasn't been directly re-run there.
