# ADR-02011: A class expression in a function is a class per evaluation

- **Date**: 2026-11-21

## Context

- A class expression that captures no local was hoisted to one top-level
  class. Every evaluation (each call of the function around it) gave the
  same class: `mk() === mk()` was true, and its statics were shared.
- In the js lane, a base variable's type was its declared (initializer)
  type. `var Base = B1; … Base = B2;` therefore selected among `[B1]`
  only, and the class built after the reassignment threw "Class extends
  value … is not a constructor". When the candidates were class
  expressions held by variables, the js lane refused to lift them. The
  class then kept its base as written, hoisted and read before the
  program's first statement ("Class extends value undefined").
- `Object.getPrototypeOf(C)` of a class record answered Function.prototype.

## Decision

- Every class expression inside a function makes its record per
  evaluation, as a capturing one already does (TDD-00242): its own
  constructor identity, statics and `instanceof`.
- In a JavaScript program, the type of a base variable reassigned to other
  values is the union of every value stored to it. Class expressions it
  holds are lifted as candidates when it is reassigned.
- `__kml_classref_proto` of a record is the record of the local class it
  extends, otherwise its class's own answer.

## Implementation notes

- codegen/llvm/emit_classexpr.go: `hoistClassExpressions` (`inFn`).
- checker/dynbase.go: `storedBaseType`, DynamicBase's js branch.
- codegen/llvm/fnproto.go: `emitClassRefProto`;
  codegen/llvm/unitregsrc/unitreg.c: `__kml_classrec_base`,
  `__kml_classrec_static_ref`.
- What is left: the evaluations share one `prototype` object
  (`mk().prototype === mk().prototype`).
