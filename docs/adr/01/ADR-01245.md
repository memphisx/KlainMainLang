# ADR-01245: `.next(v)` is the `yield` expression's value

- **Relations**: `Extends ADR-00954`
- **Date**: 2026-09-29

## Context

readline's key decoder (`emitKeys`, ADR-01243) is a generator that reads
each character from `ch = yield`. Every value `.next(v)` sent arrived as
`null` or `0`. The sent-value slot had the yield type (`TYield`), so a
string sent into a `Generator<undefined, void, string>` was converted to
`undefined` before the body saw it.

## Decision

- **The sent slot is boxed `any`.** `.next(v)` boxes its argument as it
  is: TNext is its own type, `any` unless declared, and checking the
  argument is the checker's job. The `yield` expression reads the slot
  as it is.
- **The other slot users match:**
  - `.return(v)` and the paths that complete a generator unbox the slot to
    the element type;
  - async generators' queued requests carry the boxed word;
  - `yield*` forwards it to the inner generator.
- **Typing.** `inferExprType` types a non-delegating `yield` as `any`, and
  so does an unannotated `const x = yield v`. The declaration switch
  otherwise fell back to `i64`.

## Verification

Mac (Apple Silicon), against Node v24.19:
`TestE2EGeneratorNextValueIsYieldResult` (a string into a
`Generator<undefined, void, string>`, `false` into a number-array
generator); the generator suites.

It replaces `TestE2EGeneratorMismatchedNextValueRejected`, which asserted
a guard against the invalid IR the element-typed slot produced.
