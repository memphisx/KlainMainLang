# ADR-01601: Test servers bind to loopback; `http.listen` takes `host`

- **Relations**: Extends ADR-00801, ADR-01598
- **Date**: 2026-10-13

## Context

With Windows Firewall on, every new `prog.exe` that listened on all
interfaces raised an "allow access" prompt; a full E2E run raised about a
thousand. The test programs used `listen(port)`, which binds every interface
in Node and here alike. `klain:http`'s own `http.listen(port, handler)` had
no way to name an address: it always bound `INADDR_ANY`.

## Investigation

- Windows prompts only for a bind to a non-loopback address; a server on
  `127.0.0.1` raises nothing.
- Node's `server.listen(port, host, cb)`, `listen({ port, host })` and
  `dgram`'s `bind(port, address)` already work here and bind the address
  given (`netstat` on Windows: `127.0.0.1:<port> LISTENING`).
- `http.listen`'s third argument was `{ workers }` only, and the bind helper
  `__kml_http_bind_and_listen` already takes a network-order IPv4 word.

## Decision

- `http.listen(port, handler, { host })` binds that IPv4 address, read at
  compile time from a string literal as Node's options form is (ADR-00801);
  `'localhost'` is `127.0.0.1`. `host` and `workers` may appear together.
- Every test program that listens or binds names `127.0.0.1` (the IPv6 test
  keeps `::1`). Rewritten mechanically: `x.listen(p)` → `x.listen(p,
  '127.0.0.1')`, `x.listen(p, cb)` → `x.listen(p, '127.0.0.1', cb)`,
  `http.listen(p, h)` → `http.listen(p, h, { host: '127.0.0.1' })`,
  `dgram` `bind(p[, cb])` likewise.

## Implementation notes

`ipv4Word` in `emit_http.go` packs the address in the byte order the bind
helper stores as is. A non-literal or non-IPv4 `host` is a compile error that
names the value.

## Verification

Windows 11: `http.listen(18903, h, { host: '127.0.0.1' })` listens on
`127.0.0.1:18903` only. `go vet ./tests` passes; the network tests are run
in the next full pass.
