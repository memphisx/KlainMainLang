# ADR-00304: Node's `stream` module — Readable/Writable/Transform, events, `.pipe()`, `stream/promises`

- **Relations**: Implements [TDD-00097](../tdd/TDD-00097.md) Stage 8 (the final stage); extends [ADR-00296](ADR-00296.md)–[ADR-00303](ADR-00303.md)
- **Date**: 2026-08-22

## Context

TDD-00097's last stage: Node's own `stream` module. The TDD's original
sketch assumed subclass-based streams over a lifted generic EventEmitter;
the shipped design (per the Stage 7 pivot, ADR-00303) instead builds the
classes as **wrappers over the WHATWG internals** with options-form
constructors — the modern Node idiom — reusing every piece of Stages 1–7:
the readable side is an `%kml.rstream`, the writable side an `%kml.wstream`,
Transform is the Stage 3 `%kml.ts` coupling, `.pipe()`/`pipeline` are the
Stage 3 pipe machine, events ride the EventEmitter listener-list runtime,
and completion promises are the streams' own closed promises.

## Decision

- **Module surface**: `import { Readable, Writable, Transform } from
  'stream'` and `import { pipeline, finished } from 'stream/promises'`. Two
  new virtual modules; the class names bind as *identity* in the rename
  pass (constructors are parse-time name-keyed like every builtin, and
  `Readable.from` dispatches on the bare name), while `stream/promises`
  members use the ordinary marker rewrite.
- **Wrapper** (`%kml.nodestream`, 80 B): inner rstream/wstream (either may
  be null), an event map (name → EventEmitter listener list), the flow
  state, and two compiler thunks — the Stage 3 record decoder plus a typed
  `'data'`-listener invoker. A Transform holds both sides.
- **Events** (Stage 7-style literal-name typing): `'data'` carries the
  readable's chunk type, `'error'` an `Error`, `'end'`/`'close'`/
  `'finish'`/`'drain'` are payload-less; `on`/`once` chain and validate
  listener arity at compile time. Attaching `'data'` starts **flowing
  mode** — a reaction-driven read→emit loop; `pause()`/`resume()` gate it.
  Writable completion is one reaction on the inner closed promise
  (`'finish'`+`'close'`, or `'error'`); `write()` returns the backpressure
  boolean and arms one `'drain'` per backpressure episode.
- **Producers/consumers**: `push(chunk)` / `push(null)`;
  `new Readable({ read: (self) => … })` — the callback receives the stream
  itself (no `this` binding exists for object-literal callbacks; documented
  deviation from Node's this-based `_read`); `Writable`'s `write`
  (sync or async, a rejection errors the stream) and `final`;
  `Transform`'s `transform(chunk, controller)`/`flush(controller)` reuse
  the WHATWG transformer shape. `Readable.from(array)`,
  `Readable.fromWeb(rs)`, `.toWeb()` bridge both worlds.
- **`pipeline(...streams)`** chains `.pipe` stages and returns the final
  destination's completion promise; **`finished(stream)`** returns the
  stream's own closed promise directly (both are already task-shaped
  promises — zero new machinery). The callback-style `stream.pipeline`/
  `stream.finished` forms are not provided (caveat) — the promise forms
  are the modern Node idiom.

## Side effects discovered / deliberate deviations

- `Readable`/`Writable`/`Transform` become reserved constructor names
  (parse-time recognition), like every other builtin constructor.
- No subclassing (`class X extends Readable`), no `_read`/`_write`
  overrides, no `Duplex`, no `.read()`/`.unshift()`/`.destroy()`, no
  `objectMode` flag (chunk types are just the type argument), and event
  names must be string literals — all listed on STREAMS.md.
- Event delivery order can differ from Node by a microtask (emissions ride
  the reaction queue, not synchronous re-entrancy).
