# ADR-01560: A class-typed parameter given another object by a dynamic call

- **Relations**: Extends ADR-01558, TDD-00230
- **Date**: 2026-10-10

## Context

A parameter typed as a program class reads its fields at the class's fixed
offsets. A call through the dynamic ABI can pass it any object, and
JavaScript then reads that object's own members:

```ts
class A { x = "A"; m() { return "mA"; } }
class B { x = "B"; m() { return "mB"; } }
em.on("r", (v: A) => console.log(v.x, v.m()));
em.emit("r", new B() as any);   // Node: B mB
```

Ours read `B` through `A`'s layout: wrong values or a segfault. The same
held for a function held as `any`, one stored in a `(...args: any[]) =>
void` slot, and an HTTP/2 handler that `allowHTTP1` hands HTTP/1 request
and response objects (`TestE2EHTTP2SecureServerAllowHTTP1`,
`TestE2EHttp2PortSecure` crashed or hung). An unannotated parameter of a
dynamic literal is bound as a box, but member reads on it followed the
checker's contextual class type and unboxed it to that layout.

## Decision

- A function literal (arrow or function expression) and a top-level
  function taken by value get a second body, its dynamic entry, with each
  parameter typed as a plain program class bound as `any`, over the same
  captured environment. A unit-registry row (kind 8) maps the typed body's
  code pointer to it.
- The boxing adapters (`emitAdapterFunc`, `emitDynClosureAdapter`) check
  each such argument: an object that is not an instance of the class runs
  the dynamic entry; an instance, or a non-object, runs the typed body.
- A dynamic literal (`emitDynCallable`) emits both bodies inline behind the
  same check.
- Inside a dynamic entry, and for an unannotated parameter a dynamic
  literal binds as a box, the parameter and every member read, index,
  call or `!` rooted at it are `any` to the checker-side mapping and to
  `inferExprType`; checker narrowing does not unbox it, and a read off it
  is never taken as the primitive the checker types it.
- A `this` parameter keeps its type.
