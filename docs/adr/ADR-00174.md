# ADR-00174: Box union/dynamic arguments at static-method call sites (fixes `assert.sameValue`)

- **Date**: 2026-08-12

## Context

Reviewing Test262 conformance for the highest-leverage next win, the failure-reason table pointed at the harness shim's `assert` (the backbone of ~30k files that use `assert.sameValue`). Probing the *unmodified* shim revealed a far larger problem than the documented "scalar-only" limitation: `assert.sameValue(1 + 1, 2)` — a plain scalar comparison — failed to compile at all, with `invalid cast opcode for cast from 'i64' to '{ i8, i64 }'`. The entire static-method-with-union-parameter path was miscompiling, silently, for every argument that needed boxing.

## Investigation

`assert.sameValue` is a static method whose parameters are a constrained union (`number | string | boolean`), whose runtime representation is the `{ i8, i64 }` tag+payload box (`emit_dynamic.go`). Passing a scalar requires *boxing* (insertvalue tag+payload, `emitBoxValue`), not an integer cast.

- The free-function call path (`emit_call.go:953`) already special-cases `paramTy.IsDynamic` and boxes explicitly, with a comment noting "coerce has no notion of boxing."
- The static-method call path (`emit_classes.go:1809`) did a bare `e.coerce(val, paramTy)` with no dynamic handling.
- Root cause in `coerce` (`emit_exprs_coerce.go`): `dstInt := target.IsInteger()`, and `IsInteger()` (`types.go:1101`) is `!Float && IR != "ptr" && IR != "void"` — which is **true for the `{ i8, i64 }` box**. So a union target was treated as a machine integer, `typeBits("{ i8, i64 }")` fell back to 64, and the narrowing branch emitted `trunc i64 %x to { i8, i64 }` — invalid IR, caught only at the clang stage.

Because the passing corpus was dominated by negative parse-phase tests and files not exercising this path, the breakage never surfaced as an obvious regression — it just capped conformance.

## Decision

1. In `emitStaticMethodCall`, mirror the free-function path: when `paramTy.IsDynamic`, validate the argument against the union's members (`unionAllowsAssignmentFrom`) and box with `emitBoxValue`; otherwise `coerce` as before.
2. Add a defensive backstop in `coerce` itself: if the target is dynamic and the source is not, box via `emitBoxValue`, so no coerce call site anywhere can emit the invalid `trunc`-to-box IR again.
3. Widen the Test262 harness shim's `assert.sameValue`/`notSameValue` parameters from `number | string | boolean` to `number | string | boolean | null`. The `| null` member accepts both `null` and `undefined` arguments (union V1's Nullable branch), covering the extremely common `assert.sameValue(x, undefined)` / `..., null)` comparisons — which this fix makes compilable for the first time.

## Implementation notes

- `codegen/llvm/emit_classes.go` — dynamic-aware argument handling in `emitStaticMethodCall`.
- `codegen/llvm/emit_exprs_coerce.go` — box-on-dynamic-target backstop, placed before the int/float cast switch.
- `tools/conformance/harness-shim/assert.js` — param widening + comment update (still-open gap: object/array arguments).
- The backstop also repairs any instance-method or other call site that reaches `coerce` with a dynamic target, not just static methods.

## Side effects discovered

The conformance harness could hang for minutes on a single pathological 39 MB-IR input, masking the true full-corpus total. Fixed separately in [ADR-00175](ADR-00175.md).

## Verification

- New E2E regression tests `TestE2EStaticMethodUnionParam` and `TestE2EStaticMethodUnionParamNullMember` (`tests/classes_test.go`), both passing.
- `go vet ./...` clean; full `go test ./...` green (Linux).
- `make conformance` (Linux): **4503 → 4998 passing (8.4% → 9.3%), +495 files** — `language` 4396 → 4594 (+198, the codegen fix), `built-ins` 89 → 370 (+281, the shim's `| null` widening applied to undefined-property checks), `staging` 11 → 26.
