# ADR-00309: `BroadcastChannel` + `MessageChannel`/`MessagePort`

- **Relations**: Implements [TDD-00099](../tdd/TDD-00099.md); extends [ADR-00305](ADR-00305.md), [ADR-00306](ADR-00306.md) (Worker channels)
- **Date**: 2026-08-23

## Context

The last two ❌ rows on the Concurrency status page. Both were open questions in [TDD-00098](../tdd/TDD-00098.md) ("whether a MessageChannel/MessagePort pair falls out of the same control-block design", "BroadcastChannel fan-out semantics"); [TDD-00099](../tdd/TDD-00099.md) settled them on a shared endpoint design.

## Investigation

The Worker channel's transport (8-byte envelope pointers through non-blocking pipes, drained by each thread's select() loop) generalizes: what BroadcastChannel and MessagePort add is *routing* (name-keyed fan-out vs. a fixed peer), not a new transport. The open problem was per-subscriber copy semantics: the sender's codegen emits one static-typed deep clone, but a broadcast has a runtime-known subscriber count. Resolved with a codegen-synthesized clone thunk (`{i64,i64} f(i64,i64)`: decode → `emitDeepClone` → re-encode) the runtime calls once per subscriber — the same builder-swap synthesis the worker listener adapters already use.

## Decision

- **One endpoint block for both APIs** (`runtime_chan.go`'s `chanEpIR`): `{ name, pipe r/w fds, atomic alive flag, adapter cb, loop-hold flag, kind, peer }`. BroadcastChannel endpoints (kind 0) additionally live in a process-wide, mutex-guarded registry (`cmpxchg`-gated lazy mutex init — zeroed statics are invalid on Darwin, [ADR-00308](ADR-00308.md)); ports (kind 1) hold their peer directly and skip the registry.
- **Ownership by listener**: construction never claims an endpoint for any event loop. `onmessage =` registers the adapter *and* appends the endpoint to the current thread's `thread_local` drain list — so a port constructed on main and handed to a worker is drained by the worker, with no adoption protocol. A registered listener holds that thread's loop alive (Node ref semantics) until `close()`.
- **Event loop**: a hook trio `__kml_chan_keepalive`/`_fdset_add`/`_dispatch` folded into `__kml_event_loop_run` beside the worker trio, with no-op stubs from `emitLoopTaskStubs` when the program never uses channels.
- **`BroadcastChannel` post**: under the registry mutex, for every *other* live same-name endpoint, call the clone thunk and pipe the private copy. One message type per channel **name**, program-wide — first `postMessage` or annotated `onmessage` fixes it, later sites are checked (the worker single-type rule keyed by name; the name must be a string literal for the same reason the worker path must).
- **`MessageChannel<T>`**: the explicit type argument declares the symmetric message type (default `number`); `port1`/`port2` are `MessagePort<T>` halves of a malloc'd pair box. `port.postMessage` deep-clones (single receiver — no thunk) into the peer's pipe; a closed peer silently discards, matching the spec. A `MessagePort` crosses the worker boundary **shared by reference** (like an SAB — the spec's transfer semantics minus neutering, documented): `workerData: ch.port2` + worker-side `const port: MessagePort<T> = workerData`. A `MessageChannel` pair box itself is a clone-time rejection.
- `close()` marks the endpoint dead and releases the hold but deliberately leaks the two pipe fds — a concurrent poster that read the alive flag just before the close may still write; fd leak per closed channel is the safe trade.

## Implementation notes

`ast/nodes.go` + `parser/parser_literals.go` (both `new` forms; `MessageChannel<T>` reuses the `new Map<K,V>` type-argument grammar), `codegen/llvm/types.go` (three flags + `BCName` + constructors, `MessagePort<T>` annotation resolution in `emitter.go`), `runtime_chan.go` (new — endpoint runtime + hook trio), `emit_chan.go` (new — construction, methods, `onmessage`, clone thunk), dispatch wiring in `emit_call.go`/`emit_exprs_assign.go`/`emit_exprs_member.go`/`emit_exprs_types.go`/`emit_exprs_vardecl.go`, loop folds in `runtime_http.go`, stubs in `runtime_task.go`, full-loop trigger in `emitter.go`. Shared decl dedup: `pipe(2)` and the fd_set bit-set helper were inlined in the worker runtime — extracted to `ensurePipeDecl`/`ensureWorkerFdSetbit` so both runtimes can require them (the missing-setbit case was caught as a clang "use of undefined value" on the first channel-only program, which never initializes the worker runtime).

## Side effects discovered

None beyond the decl-dedup refactor above.

## Verification

darwin/arm64 (Mac): `tests/shared_memory_test.go` — same-thread BC fan-out with name isolation (an `'elsewhere'` subscriber never fires), BC main→worker delivery, same-thread MessageChannel round trip, and a port handed to a worker via `workerData` echoing back to `port1` on main. Type-mismatch across two same-name BC endpoints asserted as a compile error. Examples `examples/workers/broadcast.ts` and `port_pair.ts` run clean. Full `go test ./...` green on the Mac; the same suites also pass on Linux (glibc/arm64, Docker `golang:latest` + clang 19).
