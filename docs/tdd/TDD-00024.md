# TDD-00024: `os` module

- **Status**: Implemented ([ADR-00090](../adr/ADR-00090.md)) — Linux verified; Darwin's freemem()/cpus().times unverified pending real hardware
- **Date**: 2026-08-03

## Context

`docs/status/OS.md` tracks Node's `os` module at 0/7, flagged as high relevance to this project's own CLI-priority tiebreaker (config/scratch-file locations, `os.homedir()`/`.tmpdir()`) in the project's own project-direction section. `path` (ADR-00081) shipped in the same "low-effort POSIX wrapper" category with no TDD; most of `os` fits that same mold (`platform`/`EOL`/`homedir`/`tmpdir`/`hostname`/`totalmem` are all thin single-libc-call wrappers). Two items don't: `os.freemem()` and `os.cpus()`'s per-core `model`/`speed`/`times` need real per-platform system APIs, decided here rather than left implicit, which is what earns this a TDD instead of going straight to an ADR like `path` did.

Two scoping decisions made with the user before implementation:

1. **`os.freemem()` implements the real macOS path now** (Mach `host_statistics`/`vm_statistics_data_t`), not deferred/stubbed — accepting it can't be verified in this (Linux-only) dev sandbox and will be tested on real Apple Silicon hardware later. Flagged explicitly here and in the ADR as **unverified on Darwin**.
2. **`os.cpus()` builds real `model`/`speed`/`times` where available**, not just a placeholder-filled core-count array — Linux via `/proc/cpuinfo`/`/proc/stat` parsing (verifiable in this sandbox), Darwin via `sysctlbyname` (model/speed) and Mach `host_processor_info`/`PROCESSOR_CPU_LOAD_INFO` (times) — also unverified on Darwin.

## Design

### Platform selection: Go-side `runtime.GOOS` branch, not runtime IR branching

Same mechanism `nodePlatformName()` (`process.platform`) and `ucontextLayout()` (the fiber scheduler) already use: this compiler doesn't cross-compile (`clang -O2` always targets the host it's running on), so which platform's C API to call is a decision the **Go compiler itself** makes once, at codegen time, via `switch runtime.GOOS`. Nothing in the emitted IR branches on platform at runtime — a Linux build only ever contains the `sysconf`/`/proc` code path; a Darwin build only ever contains the `sysctlbyname`/Mach path.

### Easy five: `platform`, `EOL`, `homedir`, `tmpdir`, `hostname`

- `os.platform()` reuses `nodePlatformName()` directly (already used by `process.platform`) — no new mechanism, just a new call-site dispatching to the same Go function.
- `os.EOL` is always `"\n"` — this compiler is POSIX-only (no Windows target, TDD-00020 not started), so there's no real `"\r\n"` case to branch on.
- `os.homedir()`: `getenv("HOME")`, throwing a catchable Error if unset (matches real Node, which throws when `uv_os_homedir` can't determine it) — reuses `emitGetenvCall` (`emit_process.go:52-60`, already backing `process.env`) plus the existing `emitInternalThrow` path.
- `os.tmpdir()`: `getenv("TMPDIR")`, falling back to the literal `"/tmp"` (never throws) — same `emitGetenvCall` plus a `select`, the same null-fallback shape `emitValueToString`'s `Nullable` branch already uses.
- `os.hostname()`: `gethostname(buf, 256)` into a malloc'd buffer, throwing on a non-zero return. Genuinely new C surface (`gethostname` has zero prior references in this codebase) but a single trivial `declare`.

### `os.totalmem()`: safe on both platforms, no magic numbers guessed

- Linux: `sysconf(_SC_PHYS_PAGES) * sysconf(_SC_PAGESIZE)`. The two `_SC_*` constants (`85`, `30`) were **verified by compiling and running a real C probe on this sandbox** (`unistd.h`'s `_SC_PHYS_PAGES`/`_SC_PAGESIZE` values), not recalled from memory — this project already has one incident (`ucontext_t`, ADR-00051) from trusting an unverified platform constant.
- Darwin: deliberately **not** `sysconf` at all — Darwin's `_SC_*` numbering is a completely different enum than Linux's, and guessing it blind is exactly the risk this TDD is trying to avoid. `sysctlbyname("hw.memsize", &value, &size, NULL, 0)` instead: a string-keyed MIB lookup, self-documenting, no numeric constant to get wrong. `libuv`'s own `uv_get_total_memory()` does the same thing on Darwin.

### `os.freemem()`: Linux safe, Darwin flagged unverified

- Linux: `sysconf(_SC_AVPHYS_PAGES) * sysconf(_SC_PAGESIZE)` — same verified-constant approach as `totalmem`.
- Darwin: `mach_host_self()` → `host_page_size()` → `host_statistics(host, HOST_VM_INFO, &vm_stat, &count)` → `vm_stat.free_count * pagesize`. `vm_statistics_data_t` (from `<mach/vm_statistics.h>`) is 15 consecutive `natural_t` (`unsigned int`, always 4 bytes on every Darwin architecture — a decades-stable Mach ABI convention, unlike `ucontext_t` which is a deliberately-opaque scratch buffer whose *size* varies by arch) fields, `free_count` first — this is what makes the struct low-*layout*-risk even though it's still functionally unverified. `HOST_VM_INFO` is the documented constant `2`. **Not compiled or run anywhere in this work** — no Darwin target available. First real test happens on the user's own Apple Silicon hardware later; a struct-layout mistake would most likely surface as a wildly wrong (not a crash-causing) freemem() value, or a `host_statistics` failure return, both easy to diagnose against real docs once it can actually run.

### `os.cpus()`: count is safe everywhere; model/speed/times is the most novel work in this feature

- Core count: Linux `sysconf(_SC_NPROCESSORS_ONLN)` (constant `84`, verified); Darwin `sysctlbyname("hw.logicalcpu", ...)` (string-keyed, safe).
- Return shape: `CPUInfoType()` (new `ObjectType` in `types.go`, `{model: string, speed: number, times: CPUTimesType()}`) nested inside `CPUTimesType()` (`{user, nice, sys, idle, irq}`, all `number`/ms) — nested nested-object-in-object precedent already exists (`SettlementType`'s `reason: errorObjType` field). The *array* of these is built inside a genuine runtime loop over the core count (structurally like `emitMapEntries`'s "malloc one heap object per iteration, store its pointer into an output array" shape), not a compile-time-known-arity object like `PathParsedType()` alone.
- Linux `model`/`speed`: parsed from `/proc/cpuinfo`, `strstr`-locating `"model name"`/`"cpu MHz"` within each processor block, extracting via `sscanf`. `/proc/cpuinfo`'s per-core blocks appear in strict index order (Linux kernel documented behavior); block `i`'s start is found by walking `i+1` occurrences of `"processor\t:"` from the buffer start each time, rather than trying to substring-match a literal `"cpuN"` marker (which would be ambiguous — `"cpu1"` is a substring of `"cpu10"`/`"cpu11"`/…).
- Linux `times`: parsed from `/proc/stat`'s per-core `cpuN ...` lines, walked by **line position** (skip the first `cpu ` aggregate line, then read exactly `count` further lines in order) rather than string-matching a `"cpuN"` prefix, for the same cpu1-vs-cpu10 ambiguity reason. Fields are `user nice system idle iowait irq …` (space-separated jiffies); Node/libuv's mapping is `user`/`nice`/`sys`/`idle` from fields 1-4 and `irq` from field 6 (field 5, `iowait`, is skipped) — read via one `sscanf` per line with a `%*s` to skip the leading `cpuN` token. Jiffies are converted to milliseconds via `* 1000 / sysconf(_SC_CLK_TCK)` (`_SC_CLK_TCK = 2`, verified; the runtime value itself, typically `100`, is read via `sysconf` rather than assumed, since `HZ` isn't universally `100` on every kernel build).
- **Neither `/proc/cpuinfo` nor `/proc/stat` is seekable** — `ftell()` after `SEEK_END` doesn't return a real size for procfs files (they're synthesized on read, not backed by a fixed-size file). This ruled out reusing `emit_fs.go`'s existing `__kml_fs_read_file` (which assumes exactly that seek-based sizing) — `os` needs its own growable-buffer, read-until-EOF helper.
- Darwin `model`: `sysctlbyname("machdep.cpu.brand_string", ...)`, a single string-keyed call, no parsing needed. Darwin `speed`: `sysctlbyname("hw.cpufrequency", ...)` — **known to return 0/unavailable on Apple Silicon** (Apple removed the fixed-clock-speed model starting with M1; this is a documented, expected Node.js behavior on M-series Macs too, not a bug to fix here). Darwin `times`: `host_processor_info(mach_host_self(), PROCESSOR_CPU_LOAD_INFO, &count, &info, &infoCount)`, returning a `processor_cpu_load_info_data_t` array (4 `unsigned int` ticks per core: user/system/idle/nice) — same "stable Mach ABI, unverified on real hardware" caveat as `freemem()`.

## Open questions

- Whether Darwin's `freemem()`/`cpus().times` will need adjustment once tested on real hardware — expected, not a design gap; flagged explicitly rather than silently assumed correct.
- Whether `os.cpus()`'s Linux `speed` (current `cpu MHz` from `/proc/cpuinfo`, which reflects the CPU's current/scaled frequency, not its rated base/max clock) is the right number to report — this matches what `libuv`/real Node itself reports on Linux, so treated as correct-by-precedent rather than a gap.
