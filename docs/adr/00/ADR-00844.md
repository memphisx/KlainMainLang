# ADR-00844: `Date` `getUTC*` / `setUTC*` accessors

- **Relations**: Extends [ADR-00014](ADR-00014.md) (`Date`), [ADR-00039](ADR-00039.md) (setters)
- **Date**: 2026-09-10

## Context

`Date`'s `getUTCFullYear`/`getUTCMonth`/… and `setUTCFullYear`/… accessors were
unimplemented ("a Date has no method 'getUTCFullYear'"). This compiler stores a
Date as UTC milliseconds and every field getter/setter already operates in UTC
(the deliberate deterministic-output deviation from JS's local-time `get*`), so
the UTC accessors are exact aliases of the field accessors — and, unlike the
local `get*`/`set*`, they are **fully faithful** to Node (whose `getUTC*` is also
UTC).

## Decision

Add the eight `getUTC*` names to `dateDecomposeFieldIndex` (mapped to the same
decomposed-field indices as their `get*` siblings) and the seven `setUTC*` names
to `dateSetterFieldIndex`, the setter `maxArgs` table (mirroring each sibling's
arity), and the cascade `start` table. Add all of them to `inferExprType`'s Date
method case (→ `number`). No new runtime; they reuse the existing
decompose/compose path.

## Implementation notes

`emit_date.go` (three maps); `emit_exprs_types.go` (inference). The multi-argument
cascade (`setUTCHours(h, m?, s?, ms?)`, etc.) works unchanged since it is keyed
on the field index, which the UTC names alias.

## Verification

macOS (Apple Silicon M4): `new Date(1609459200000)` → `getUTCFullYear()` 2021,
`getUTCMonth()` 0, `getUTCDate()` 1, `getUTCDay()` 5, `getUTCHours/Minutes/
Seconds()` 0/0/0; `setUTCFullYear(2000)`/`setUTCMonth(5)` then re-read → 2000/5;
a typed `const y: number = d.getUTCFullYear() + 1`. New
`TestE2EDateUTCAccessors` + the Date suite green.
