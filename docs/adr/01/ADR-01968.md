# ADR-01968: The E2E shadow rows name their program; oracle and inference gaps closed

- **Relations**: Implements TDD-00230 (P3.3); follows [ADR-01967](ADR-01967.md)
- **Date**: 2026-10-29

## Context

With top-level bindings switched to the front end's answer, the remaining shadow rows over the E2E programs were the work list for switching `inferExprType` the rest of the way: 454 disagreements. Most E2E programs are compiled from a source string, with no entry file, so a row named neither its test nor its program. `KML_SHADOW_KEEP` kept a copy of the entry only when one existed.

## Investigation

- `startShadow` (`codegen/llvm/shadow.go`) passed `prog.EntryPath` to `KeepEntry`. An in-process program has none, and `ast.Program` kept no source text: only function ranges point at the parser's `SourceText`.
- Three `reliableGlobalType` presence rows were bindings codegen promoted and the oracle did not:
  - `const values = [2, 1, 3]` read from a generator's destructured parameter default. `desugarGeneratorPatternParams` moves those defaults off the signature, and `registerModuleGlobals` counts their reads (`genPatternInits`). The oracle's `readInFunctions` walked the program and missed them.
  - `var g = 1; function g() {}` is one binding: codegen makes it a global `any`, holding the function until the `var` runs. The oracle had no such rule.
- The largest `inferExprType` bucket (function return types) traced to `function h([p = 7] = []) { return p; }`. The checker types `p` as `number`, as tsc does, and codegen stores it as a `double`. The oracle's rule for leaves of a defaulted array-pattern parameter, which unpacks them from the parameter's boxes, forced `p` to `any`, ignoring the leaf's own default.
- The largest group of unanswered calls (24 rows) came from one program chaining `.then` on a `Deferred<T>` whose `then` has four generic overloads. The checker typed `s1.then(tfD, tf, tf)` as `Deferred<number | U>`, the method's own `U` leaking into the result; tsc gives `Deferred<number>`. Two gaps in `unify` (`checker/generics.go`):
  - It inferred from a generic source signature as written, so the source's own type parameters became candidates. tsc's `inferFromSignatures` infers from the source's base signature (each own type parameter its constraint, else `unknown`) and the target's erased one (each own type parameter `any`).
  - An overloaded type has its first signature's shape, so inference used only the first overload. tsc pairs overloads from the last signature of each, the most general.
  - With the program's full `Deferred` (it also declares `done`, so a `Thenable` is no `Deferred`), `s1.then(tfD, tf, tf)` still differed: tsc gives `Deferred<Thenable<number>>`. Overload 2 infers `U` from two candidates, `number` and `Thenable<number>`. Ours unioned them, so the overload passed. tsc's `getSupertypeOrUnion` picks one by a left-to-right reduction, a later candidate replacing the current one when the current one is assignable to it. That leaves `number`, the `err` argument then fails, and overload 4's candidates reduce to `Thenable<number>`. Ours applied that rule only to primitive candidates (`firstPrimitiveCandidate`).
- With the checker answering those calls, the oracle still could not represent `Deferred<…>`: its `then` is an overloaded generic method, and `reprCtx.of` maps only non-overloaded function types. Codegen lays the member out as its first overload, its type parameters erased. Applying that to every overloaded function type broke four examples (`fs.promises`, `dns.promises`), whose overloaded members codegen represents through their host types. Narrowing it to members whose overloads are all generic still reached a library module's namespace object (`util.inspect`), and multiplied the shadow rows sixty-fold.
- `g.next().then(r => r.value)` on an async generator: the checker types `r` as the `IteratorYieldResult | IteratorReturnResult` union. Codegen resolves the promise with its own `{value, done}` struct, as a step held in a `const` already maps.

- `GeneratorElemType` rows were all `-compat=js` programs. The oracle mapped a generator to the element type the checker infers from its yields' literal types (`number`, `void`, `never`). Codegen skips the checker there (`checkerGeneratorElem` declines under `compatJS`) and fell back to its own body inference (`inferGeneratorElemType`), which typed an empty generator's slot as `i64`. JavaScript holds a generator's yields boxed.
- `globalFallback` rows were declarations whose initializer the checker leaves untyped (`var a = g1()` over a `yield*` of an untyped object). For a binding no function reads, the type decides nothing: it stays a local.

- A function-return bucket: `function f({ x, y } = { x: 1, y: 2 }) { return x + y; }` and `function g([a, ...r]) { return r.length; }`. The checker returns `number`, and the return expressions agree with it where they are emitted (no row for `x + y`). Codegen's old inference returned `any`: it binds a destructured parameter's leaves as boxes while it infers. `widerStorage` then kept that `any` over the checker's type, a rule meant for storage that really is wider (a hoisted `var` read before its assignment, a field that evolves to `any`).

## Decision

- `ast.Program` gains `Text`, the parser's source. `KeepEntry(entry, src)` keeps that text when there is no entry file, so every row names its program.
- `readInFunctions` counts the reads of a generator's moved pattern defaults, through a `genPatternInits` hook.
- `GlobalType` answers an initialized, unannotated `var` sharing its name with a top-level non-generic function as a promotable `any`.
- A leaf with its own default (`[p = 7] = []`) keeps the checker's type.
- `unify` infers between generic signatures through the source's base and the target's erased signature, and pairs overloads from the last, as tsc does.
- Candidates that are each one type, an object among them, reduce to tsc's common supertype (`objectSupertypeCandidate`). A relation the checker leaves maybe counts as assignable, as the assignment check counts it.
- A member of an interface-declared object type whose overloads are all generic, and that `reprCtx.of` leaves unanswered, is laid out as its first overload with its own type parameters erased (`firstOverload`).
- In the JavaScript lane a generator's element is `any` on both sides: the oracle maps a `Generator`/`AsyncGenerator` instance to `GeneratorType(any)`, and codegen takes `any` before its own body inference.
- `GlobalType` answers an untyped declaration no function reads as not promotable. A library, dynamic-only or worker module's binding answered that way is still typed by `registerModuleGlobals`' own pass.
- `widerStorage`'s `any` case no longer overrides the checker when every return expression is held as the checker's type where it is emitted (`returnsHeldAs`).
- The unannotated first parameter of a callback passed straight to `.then` on a generator step's promise takes that promise's resolved type (`thenStepParam`).

## Consequences

- Each E2E shadow row is traceable to the program that produced it.
- `s1.then(tfD, tf, tf).then(tf, tf, tf)` and the other chains of that program type as tsc types them (`TestInferFromGenericOverloadedSignatures`).
- The three presence rows, the function-return bucket's destructured-default rows and the async-generator step rows are gone.
- Not yet closed: rows where codegen's `any` is the faithful JavaScript answer and the checker's type is not (`function f(a = 5) { return a; }` called with `null` returns `null`), and the `switchFallback` rows the checker leaves unanswered.
