# ADR-01235: A caught error's own properties

- **Date**: 2026-09-29

## Context

After `e.code = 3; e.extra = "y"` on an `any` Error:

- `throw e` then `catch (c: any)` read `c.code` as undefined;
- `c.extra` read garbage (the dynamic-object bag's magic bytes);
- a rejection lost them the same way.

Node errors carry `.code` everywhere. The case surfaced through
`util.promisify(exec)`'s rejection. The bug is at HEAD.

## Investigation

`emitCaughtMemberGet` loaded every property named like an `errorObjType`
field straight from the struct:

- `code` is a string field, so a number set there went to the error's
  own-property bag and the field was cleared;
- `extra` is the bag pointer itself.

The dynamic read (`emitDynAnyMemberGetNamed`'s error arm) already consults
the bag.

## Decision

A caught value's read keeps its typed struct field only for `message` and
`name`, which every Error has as strings. Every other property reads
through the dynamic path, as `any`. `inferExprType` agrees
(`caughtTypedField`).

Through the dynamic path, a caught plain Error's `errno` reads undefined,
as in Node (the typed read gave 0). node:sqlite's `errcode`/`errstr` read
through it too; the dynamic Error read had excluded them.

## Implementation notes

`emit_caught.go`, `emit_exprs_types.go`, `emit_dynobj.go`.

## Verification

Mac (Apple Silicon), against Node v24.19: `TestE2ECaughtErrorOwnProperties`
(through `throw`, `.catch`, `await` of a rejection).
