# TDD-00120: Length-carrying (binary-safe) strings

- **Status**: Implemented (Stages 1–4; `console.log` display-truncation the one deferred consumer — see Stage 2/3 progress and [ADR-00364](../adr/ADR-00364.md))

## Context

Every string in the compiler is a NUL-terminated C string — `.length` and
concatenation go through `strlen` (`emit_strings.go`). A string value carrying an
embedded `\0` therefore reads as shorter than it is, and any operation on it
truncates at the first NUL. This surfaces as the standing caveat on several
✅/100% rows across the project — notably HTTP Server's `req.body` and response
`body` string fields (binary-safe escape hatches `req.bodyBytes()` /
response `bodyBytes` exist, but the string fields themselves truncate), and the
same note on `Response.text()`/`.json()` (NETWORKING.md) and elsewhere.

Deliberately deferred to its own effort (it is language-wide, not HTTP-local) so
the HTTP-Server caveat-cleanup pass could clear the self-contained caveats first.
This TDD records the deferral and the shape of the eventual work.

## Design

Grounding (measured 2026-08-25): a string value is a bare `ptr` (`IR:"ptr"`,
`TypePtr`) to a NUL-terminated buffer; literals are `[N x i8] c"..."` globals
(`internString`); ~100 `@strlen` call sites compute length; and every C-interop
boundary (`printf`, libcurl, OpenSSL, `getenv`, file reads, …) consumes a
`char*`. The representation decision dominates everything else.

### Option A — length-prefixed heap strings (RECOMMENDED)

Keep the string *value* a bare `ptr`, but every string buffer is allocated as
`[ i64 byteLength ][ bytes… ][ \0 ]` with the `ptr` pointing at `bytes`. So:

- **ABI unchanged**: a string is still one `ptr` in every param/return/field/
  array/global slot — none of the thousands of string-value flow sites change.
- **C interop unchanged**: the `ptr` is still a valid NUL-terminated `char*`;
  `printf`/curl/OpenSSL keep working with zero shims (a C API that itself can't
  represent an embedded `\0` is unaffected — that's a `char*` limitation, not
  ours).
- **Binary-safe length**: `.length`, indexing, `slice`, `concat`, `indexOf`,
  `TextDecoder`, `req.body`/response `body`, `Response.text()` read the length
  from `ptr[-8]` instead of `strlen` → embedded `\0` survives.
- **Cost / risk**: *every* value typed `string` must carry the prefix, or a
  `ptr[-8]` read is garbage. The migration is bounded to string **producers**
  (literals, concat/substring/format results, and every C→string boundary —
  each must allocate-with-header or wrap) and string **length consumers** (the
  ~100 `strlen` sites → header reads). The failure mode of a missed producer is
  a bad length read, so producers must be audited exhaustively before the
  consumers switch.

### Option B — fat pointer `{ ptr, i64 }`

Every string value becomes a two-word aggregate carrying its own length.
No "is it prefixed?" ambiguity (length travels with the value), but the ABI of
*every* string param/return/field/array/global changes — a far larger mechanical
diff, and interop passes the `.ptr` component. Rejected as the first move:
Option A reaches the same binary-safety while leaving the string ABI (and all
interop) untouched, which is the difference between a bounded producer/consumer
migration and rewriting every string-value site.

### Producer/consumer audit (2026-08-25)

Sized before committing to Stage 1. The surface is bounded and hub-shaped.

**Length consumers (~100 `@strlen` sites)** — nearly all compute the length of a
KML `string` value and become an 8-byte-header read (`load i64, ptr-8`).
Concentrated in the string core: `runtime_strings.go` (15) + `emit_strings.go`
(13); the rest scattered one/two per subsystem (path, http header/query parse,
process/fs error messages, encoding input). None are genuine foreign-`char*`
scans that must stay `strlen` (a precedent already exists — `runtime_encoding.go`
carries a length-parameter `__kml_btoa` variant beside the `strlen`-based one).

**KML-level producers** funnel through four hubs — fixing these covers dozens of
callers:
- `emitStringConcat` (`emit_strings.go:64` malloc) — concat/template/`join`/
  JSON structure/path/url/http/ws/headers/inspect builders.
- `emitValueToString` (`emit_exprs_types.go:111` malloc) — number/bool→string.
- `emitStringExtract` (`emit_strings.go:100` malloc) — slice/substring/at/charAt.
- `internString` (`emitter.go:746`) — every literal; header baked into the
  static `constant [N x i8]` global.
Plus ~30 leaf mallocs (trim/case/replace/split/pad/repeat/fromCharCode, regex
outputs, number-radix/toFixed/…, Date/BigInt/JSON leaf formatting) — each a
discrete `@malloc` that reserves the header. All go through the one shared
`@malloc` (GC-remapped); **no** `GC_malloc`/`calloc` produces string bytes.

**C→string boundaries** — the risk set, and it is small:
- *Category 1 (foreign pointer used directly — MUST copy into a header buffer):*
  `getenv` (`emit_process.go:123`, backs `process.env`/`os.homedir`/`os.tmpdir`/
  cluster), `process.argv` raw OS `argv[i]` (`emit_process.go:22` /
  `emitter.go:1286`), `readdir` `strdup` (`runtime_fs.go:494`) and `getline`
  (`runtime_process.go:46`) — libc allocations with no header room. **~4 sources.**
- *Category 2 (our own `malloc`/`realloc`/`sprintf`/`memcpy`/`fread`/`read`
  buffers — just reserve 8 bytes + offset):* file/socket/stdin/child/dgram reads,
  libcurl response body (`runtime_fetch*.go`), `TextDecoder.decode`
  (`emit_call_encoding.go:194`), base64/hex/percent decoders (`runtime_encoding.go`),
  DNS dotted-quad (`runtime_dns.go`), `Buffer`/`Blob.toString`, and `JSON.parse`
  string nodes (in C: `jsonsrc/json_parse.c:387`) + strerror/curl-error message
  buffers. ~30 sites, all low-risk.

**GC note**: the string `ptr` points at `base+8`; Boehm must keep the block live
via an interior pointer. Confirm `GC_all_interior_pointers` (default on) covers
it, or store the header so the base stays reachable — a Stage-1 gate for `-mm=gc`.

### Staging (Option A)

1. **Producers**: literal emission (`internString` → prefixed global), the
   concat/substring/`repeat`/format/`String(...)` allocators, and each C→string
   boundary all emit the `[i64 len]` header. NUL terminator retained. No
   consumer changes yet — the suite stays green (headers written, still unread).
2. **Length + core ops**: `.length`, indexing, `slice`/`substring`, `charAt`,
   `at` read the header length.
3. **Search/split/compare**: `indexOf`/`includes`/`split`/comparison use the
   length (memchr/memcmp) instead of `strlen`/`strcmp`.
4. **Subsystem adoption**: `req.body`/response `body`, `Response.text()`/`.json()`,
   `TextDecoder`, file reads — flip their caveats to binary-safe, per-row in
   `docs/status`.

Each stage keeps loose coverage intact and moves specific rows toward Strict;
tracked per stage. Multi-week, whole-compiler — not a single feature.

### Stage 1 progress (2026-08-25)

Infrastructure done: `runtime_strheader.go` (`__kml_str_alloc`/`__kml_str_len`/
`__kml_str_free`), and Go helpers `emitStringAlloc`/`emitStringScratch[Reg]`/
`emitStringFinalizeLen`/`emitStringFree` (`emit_strings.go`).

Producers flipped so far (header written, still NUL-terminated, consumers still
on strlen): `emitStringConcat` and `emitStringExtract` (→ concat/template/join/
slice/substring/at/charAt, and transitively bigint/symbol/tuple/inspect/path/url/
http/ws/headers builders that go through concat); `emitValueToString`
(number/bool→string); `fromCharCode`, `padStart`/`padEnd`, `repeat`; number
formatters `toFixed`/`toExponential`/`toPrecision`/`toString(radix)`; Date
formatters; dynamic `String(any)` (int/float/funcref). `Memory.free` on a string
now frees `ptr-8` (`freeResolvedPointer`).

Bug found + fixed in passing: `toString(radix)` filled digits up to buf[69] but
its returned interior pointer relied on a NUL at buf[70] — a 1-byte over-read
past the 70-byte buffer. The Stage-1 copy-out (into a header-prefixed buffer with
an explicit NUL) fixes it.

Now flipped (all green, full suite passes): regex string outputs
(`emit_regexp_replace.go`, `emit_regexp_split.go` — NOT the work arrays); the
runtime-IR string ops (`__kml_trim*`/`toupper`/`tolower`/`replace*`/`split`);
JSON leaf stringify (`__kml_json_str_num`/`str`); and two C→string boundaries so
far — `getenv` (via a new `__kml_str_from_cstr` copy helper) and
`TextDecoder.decode`. Runtime helpers `__kml_str_finalize` (strlen→header) and
`__kml_str_from_cstr` (null-safe foreign-`char*` copy) added for the IR sites.

C→string boundaries now flipped (all green): `readFileSync`/`readFile`
(header-copy with the exact byte count), base64/hex/percent encoders+decoders
(`runtime_encoding.go`, exact-length for the binary decoders), `Buffer` codec
strings (`buffersrc/buffer_codecs.c`, inline C header helper), libcurl response
body via `Response.text()`/`.json()` (`emit_fetch.go`, `from_cstr` copy off the
dual-use buffer), DNS dotted-quad (`runtime_dns.go`), `JSON.parse` string nodes
(`jsonsrc/json_parse.c`, inline C header), `execFileSync` stdout, `readline`
`getline`, and `readdir` names. New IR helpers `__kml_str_finalize` (strlen →
header) and `__kml_str_from_cstr` (null-safe foreign-`char*` copy) back these.

**Genuinely remaining (Stage 2 / edge)**: `process.argv` (raw OS pointers —
foreign, so `Memory.free` is already UB there; copied during the Stage-2 literal
pass); the `'data'` event chunks (net/stdin/socket/dgram/child — passed as
`(ptr,len)` and consumed mostly as Buffers, only strlen-bounded when read as a
string, ADR-00358); and a few thrown-Error message buffers. None are a routine
`Memory.free` hazard.

Bug found + fixed in passing: `toString(radix)`'s 1-byte over-read past buf[69]
(the copy-out gives it a real NUL terminator).

### Stage 2 (2026-08-25): representation complete, consumer switch gated

**Done + green:** string **literals** now carry the `{i64 len, [N x i8]}` header
(constant-GEP value pointer, `internString`); `process.argv` is header-copied at
startup (`__kml_argv_headerize`); the remaining producers found while sweeping
(bigint→string via `from_cstr`, net/dgram/child `'data'` chunks, `os.hostname`,
`crypto.randomUUID`, `readline`, fs read-stream chunks) are headered; and the
**binary-safe primitives** are implemented — `__kml_str_cmp` (memcmp + length
tiebreak), `__kml_str_indexof` (memmem), plus `__kml_str_len`/`_finalize`/
`_from_cstr`. So every string value the audit + sweep covers is length-prefixed,
`Memory.free` is offset-safe, and `strlen` consumers still work throughout.

**Consumer switch — LANDED (2026-08-25).** Rather than revert, the failing
tests from the first switch attempt were used directly as the producer coverage
map: each one named a subsystem-local producer still emitting a headerless
string, and each was headered in place until the full switch went green. The
producers that surfaced and were fixed: `req.method`/`req.path`/query values
(HTTP request-parse), `__kml_split_first`'s both halves, `path.*` dirname/
basename/extname, URL parts (curl → `from_cstr`), regexp capture substrings,
WebSocket server + client payloads, the HTTP bind-error message, and the h2c
dispatch bridge's method/path/body. A duplicate `memcmp` declare (from the
primitives) was the other failure cluster — resolved by routing through the
shared `ensureMemcmp()`.

**Length/core + search/compare consumers (Stages 2–3): binary-safe.** `.length`,
concat, and the string methods read `__kml_str_len`. `===`/`!==`/`<`/`>`/`<=`/
`>=`, `switch` on a string discriminant, and `localeCompare` route through
`__kml_str_cmp`; `indexOf`/`includes` through `__kml_str_indexof`; and the
hand-written runtime `__kml_replace`/`__kml_replace_all`/`__kml_split` now
search the subject with `memmem` over the header length (tracking a remaining-
byte counter) instead of `strstr`/`strlen`, so a separator or match past an
embedded NUL is found. Full suite green.

**Subsystem adoption (Stage 4): `req.body`/response `body` binary-safe.** Their
length and the socket write both use the header length — an `"ab\0cd"` body
reports length 5 and echoes 5 bytes (Content-Length: 5).

**One consumer left on `strlen` by choice: `console.log`.** The print path bakes
its trailing terminator into a `printf` `"%s"` format string, so a value with an
embedded NUL still truncates *on display only* (the stored string is intact —
`.length` and every operation above see the full bytes). A binary-safe
`fwrite`-based print needs the terminator threaded separately through ~8 call
sites; deferred as display-only, low-value (binary bytes to a TTY are garbage
anyway; `process.stdout.write` is the binary channel). Documented as the sole
remaining string-consumer caveat.

## Open questions

- Representation settled to Option A (length-prefixed, bare-`ptr` ABI) above;
  confirm before Stage 1 since it is effectively irreversible once producers
  emit headers. Producer/consumer audit done (above) — surface is bounded.
- `-mm=gc` interior-pointer question (above) — the one real correctness gate for
  Stage 1; verify against Boehm before flipping producers.
- Whether a Stage-0 helper (`__kml_str_alloc(len)` returning `base+8`, and
  `__kml_str_len(ptr)` reading `ptr-8`) should be introduced first so every
  producer/consumer edit is a one-line call rather than open-coded pointer
  math — strongly implied by the hub shape; decide at Stage 1 start.
