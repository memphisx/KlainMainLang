# ADR-00826: `ReadableStream.read()` value + `desiredSize` as `T | undefined` / `number | null`

- **Relations**: Implements [TDD-00196](../tdd/TDD-00196.md); extends [ADR-00781](ADR-00781.md) (the deferred stream members of [TDD-00187](../tdd/TDD-00187.md)); reuses [ADR-00779](ADR-00779.md) (nullable-scalar fields), [ADR-00296](ADR-00296.md) (the streams runtime)
- **Date**: 2026-09-10

## Context

`reader.read()` on a closed stream returned a `{ value, done }` record whose
`value` was the chunk type's zero value (`0`/`""`), not `undefined`; and
`controller.desiredSize` returned `0` for both the closed and the errored
state. Both were the last inhabitants of [TDD-00187](../tdd/TDD-00187.md)'s
zero-fill caveat family, explicitly left by [ADR-00781](ADR-00781.md) as needing
their own record-shape design. TS types them `{ done: false; value: T } |
{ done: true; value?: undefined }` and `number | null` respectively.

## Investigation

The read-result record is built by a per-construction-site fulfill thunk
(`emitStreamFulfillThunk`, `emit_streams.go`) and consumed in exactly two
internal places — the `for await` loop (same file) and the pipe/tee decode
thunk (`emit_streams_pipe.go`) — plus the user-facing `rec.value`/`rec.done`
reads, which go through the ordinary object-field path. That path already reads
a nullable-scalar field as a real `T | undefined` (TDD-00187 Stage 2,
[ADR-00779](ADR-00779.md)), so flipping the record's `value` field type is
enough for user reads; only the two internal build/consume sites needed to agree
on the new field layout. `desiredSize`'s runtime (`__kml_rs_desired`,
`runtime_streams.go`) already returns `0` for both closed and errored; the
stream's state word (field 0, `2` = errored) distinguishes them at the emit
site.

A generator's `.next()` result was deliberately **not** touched — tsc types its
`value` as `any`, so the existing bare-`T` typing is already stricter than TS
([ADR-00781](ADR-00781.md)). Hence a dedicated `read()` result type rather than
reusing `genNextResultType`.

## Decision

- New `streamReadResultType(chunkTy)` = `{ value: undefinedableElem(chunkTy),
  done: bool }`, used by `read()`'s dispatch + inferred type, the fulfill thunk,
  the for-await loop, and the decode thunk. `undefinedableElem` flips scalars
  (`{ i1, T }`) and pointers (null pointer); an array/tuple/dynamic chunk passes
  through unchanged (no spare absent state, [ADR-00246](ADR-00246.md)).
- `buildStreamReadRecord` now takes a `present` bit (= `!done`) and stores the
  `value` field in its field type: a nullable scalar as a `{ i1, T }` aggregate,
  a pointer/array directly (a done read's rebuilt chunk is already the null/zero
  that reads as absent). `loadStreamResultValue` is its inverse for the two
  internal consumers, demoting a nullable-scalar field to its payload on the
  `done:false` path they run on.
- `controller.desiredSize` wraps the runtime double as a `{ i1, double }`
  optional with `present = state != 2` (errored). Absent renders `null` (the
  field is `T | null`, no `IsUndefined`), matching the spec's `null`-when-errored
  / `0`-when-closed distinction.
- The **WritableStream** controller/writer `desiredSize` gets the identical
  `{ i1, double }` treatment (`present = state != 2`), so it too is `number |
  null` — `null` once errored. (Applied in the same spirit the day this shipped,
  rather than left as a parallel caveat.)
- Consumer policy is TDD-00187's existing strict/`-compat=js` split, unchanged:
  strict mode gates a bare-`T` use of `rec.value` (narrow with `if (value !==
  undefined)` after destructuring, or assert `value!`); `-compat=js` auto-widens.
  Full `done`-discriminant field narrowing is out of scope (a general
  flow-analysis feature; the `!`/`!== undefined` idioms are valid TS).

## Implementation notes

- `emit_streams.go`: added `streamReadResultType`/`loadStreamResultValue`,
  reworked `buildStreamReadRecord`, threaded `present` through the fulfill
  thunk, swapped `genNextResultType` → `streamReadResultType` at the `read()`
  dispatch + for-await sites, and rebuilt the `desiredSize` property read.
- `emit_streams_pipe.go`: decode thunk now demotes the value field via
  `loadStreamResultValue`. Fulfill (build) and decode (read) must agree on the
  record layout — both route through the shared helpers so they cannot drift.
- `emit_exprs_types.go`: `read()`'s inferred type uses `streamReadResultType`.
- Array-chunk streams keep zero-on-close (documented); only scalar + pointer
  chunks gain a real `undefined`.

## Side effects discovered

None. The generator `.next()` result and the Node-stream sync `.read()` (which
already returns `T | null`) are unaffected — both use separate paths.

## Verification

Verified on macOS (Apple Silicon M4):

- New `TestE2EStreamsReadUndefinedOnClose` (scalar + pointer chunk read
  `undefined`/`=== undefined` after close) and
  `TestE2EStreamsDesiredSizeNullWhenErrored` (`1` readable / `0` closed / `null`
  errored); `TestE2EStreamsStartEnqueueRead`'s closed-read assertion updated
  `0 true` → `undefined true`.
- `go test ./tests/ -run 'Stream|Generator|ForAwait|Pipe|Tee|Readable|Writable|Transform'`
  green; the strict gate fires on `const x: number = rec.value` and
  `-compat=js` widens it.
- `examples/streams/read_done_value.ts` runs as expected; full `make examples`
  + Node oracle flat.
