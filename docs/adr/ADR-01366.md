# ADR-01366: WeakRef is a TypeScript class, with the spec's kept objects

- **Relations**: Implements part of TDD-00230 P3.4; refines TDD-00112
- **Date**: 2026-10-03

## Context

WeakRef was a host type: the `NewWeakRefExpression` node, the `IsWeakRef`
flag and a one-word link box, with codegen for `deref()`, inspect and
`instanceof`. It diverged from Node in several ways:
- `deref()` of a collected target gave `null`, not `undefined`;
- a target held in `any` was rejected in the strict lane;
- the target could be collected in the same job, where the spec keeps it
  alive to the end of the job (AddToKeptObjects / ClearKeptObjects).

## Investigation

From Node 24:
- `new WeakRef(1)` and `new WeakRef(Symbol.for('x'))` throw `TypeError:
  WeakRef: invalid target`; an unregistered symbol is a valid target.
- It inspects as `WeakRef {}`, and `Object.prototype.toString` gives
  `[object WeakRef]`.
- With `--expose-gc`, `deref()` after `gc()` in the same job still returns
  the target; in a later task it is `undefined`.

A TS class needs a weak link on the target's object, not on its `any` box.
The class holds the link's handle as a number, which no collector traces.

## Decision

1. **`lib/node/kml_weakref.ts`** is a global module exporting `class
   WeakRef` with CanBeHeldWeakly, `deref()`, inspect and `toStringTag`.
   It is not generic: TypeScript's declaration types `WeakRef<T>`, and a
   `deref()` result reaches the caller's `T` through `any`. That also keeps
   `instanceof WeakRef` an ordinary class test.
2. **Natives** (`weak.c`, compiled in under `KML_WEAK_NATIVES` when used):
   - `__kml_weak_link_any` keeps the box word's object pointer in a cell,
     beside its tag bits. Under `-mm=gc` the cell is
     `GC_malloc_atomic_uncollectable` and its pointer is a disappearing
     link, registered on `GC_base` of the target.
   - `__kml_weak_deref_any` rebuilds the box, or returns undefined.
   - Both add the target to the kept objects. `__kml_drain_microtasks`
     clears them, zeroing the slots, through a hook once the microtasks
     have run.
   - `@link weak` brings in the weak and microtask runtimes.
3. **Deleted:** `NewWeakRefExpression` and its sema, checker and walker
   entries; `IsWeakRef` and `WeakRefType`; the WeakRef emitters, intrinsic,
   inspect, host-class and lowering rows; the `@intrinsic
   WeakRef.prototype.deref` annotation.

## Implementation notes

- **Library:** `lib/node/kml_weakref.ts`, `lib/native.d.ts` and
  `lib/es.d.ts`.
- **Runtime:** `codegen/llvm/weaksrc/weak.c`, `microtasksrc/microtask.c`
  and `runtime_weak.go`.
- **Front end:** `ast/nodes.go` (walker regenerated), `sema/builtin_new.go`
  and `checker/checker.go`.
- **Codegen:**
  - `emit_weak.go`, `emit_exprs*.go`, `emit_func.go`, `emit_intrinsics.go`,

    `emit_call_console.go` and `types.go`;
  - in `emitter.go`, a linked global's annotation also erases a lone type
    argument (`WeakRef<Box>`), which the parser keeps in `ElemType`.

## Side effects discovered

- **GC tests.** `TestE2EGCModeWeakCollected` and
  `TestE2EFinRegGCModeCollectedFires` expected collection in the same job
  and a `null` deref. They now make the orphan in one task and check it in a
  later one, as Node behaves.
- **Main-script targets.** A target made during the main script can stay
  pinned under `-mm=gc` after the kept objects are cleared. The main frame
  stays live for the whole run under the event loop, and the conservative
  scan finds a stale copy there. A target made in a task is collected.
  Collection timing is not observable by the spec, and the status page
  already documents conservative pinning.
- **Link cells.** Each WeakRef keeps a 16-byte cell for the life of the
  process, because the class holds its handle as a number.
