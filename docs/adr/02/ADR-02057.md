# ADR-02057: The d flag's match indices

- **Date**: 2026-11-22

## Context

- A `d`-flag match had no `.indices`: reading it was a compile error, so
  `/(?<y>\d{4})/d.exec(s).indices` could not be written.
- The lib declared neither `indices` nor `RegExp.hasIndices`, `dotAll` and
  `unicodeSets`; `RegExpMatchArray` lacked `groups`, which tsc's lib has.

## Decision

- An exec result's header grows one word (offset 48): the indices as a
  box, `undefined` without the flag (and in a global match's plain array).
- When the regexp's `hasIndices` is set, the match builds them in the
  runtime (`__kml_regex_indices`, dynarr.c): a boxed array of each
  group's `[start, end]` (`undefined` unmatched) in the offsets exec's
  `index` uses, with a null-prototype `groups` of the named groups' pairs
  in pattern order, `undefined` when the pattern names none.
- Boxing an exec result copies `indices` when present; `console.log` lists
  it after `groups`, as Node does.
- The lib gains `RegExpIndicesArray`, `indices?` on both result
  interfaces, `groups?` on `RegExpMatchArray` and the three flag getters.

## Consequences

- `TestE2ERegExpHasIndices` matches Node: exec, match, matchAll, unmatched
  and named groups, a boxed receiver, inspect output, non-ASCII offsets.
- Verified on Node304 (Linux x86-64).
