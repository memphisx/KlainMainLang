# ADR-00984: `http.createServer` connection timeouts

- **Relations**: Implements TDD-00217; Extends ADR-00977, ADR-00983
- **Date**: 2026-09-16

## Context

`http.createServer` accepted `requestTimeout`/`headersTimeout` only at `0` and
rejected `keepAliveTimeout` (ADR-00977), because the fiber-per-connection
dispatcher enforced no per-connection idle deadline — a slow or idle connection
tied up a fiber indefinitely. TDD-00217 designs real enforcement on top of the
reactor's existing deadline-folding machinery.

## Investigation

- The reactor already bounds its `select()` wait by a soonest deadline: JS timers
  via `%bestfire`, and a `%cmdlabs` "extra-deadline" slot (EventSource-reconnect,
  fetch-`AbortSignal`, libcurl, spawn-timeout) that wakes `select()` *without*
  firing JS timers early — the spawn-timeout fold (`cptofold`) is the exact
  min-merge template (`runtime_http.go`).
- Connections are tracked in `@__kml_conn_data`; `@__kml_conn_writepark` is the
  precedent for an fd-indexed parallel array. A parked read returns EOF when the
  socket is `shutdown()`, and the fiber then unwinds through its own
  `noReqL`/`abEndL` cleanup — the mechanism `__kml_http_shutdown_local_conns`
  already relies on.
- `buildHTTPDispatcher` (`emit_http.go`) exposes clean phase points: connection
  entry (read loop), `accumulateL` (bytes read), the `headersParsed = 1` store,
  `parseL` (dispatch), and three keep-alive re-arm tails (buffered / streamed /
  `res.write`).

## Decision

Per TDD-00217: an fd-indexed `@__kml_conn_deadline` holds each connection's
current absolute deadline (`0` = none), gated by `@__kml_http_any_timeout`. The
dispatcher publishes the deadline at each phase transition (baked compile-time
constants; the initial pre-headers deadline is `connStart + min⁺(headers,
request)`); the reactor folds the soonest into `%cmdlabs` and, at the top of the
loop, `shutdown()`s any that have expired. **No fiber is torn down externally** —
the reactor only shuts the socket; because the deadline is *cleared* at `parseL`,
a fiber is only ever swept while parked on a read.

## Implementation notes

- `runtime_http.go`: `@__kml_conn_deadline`/`@__kml_http_any_timeout` globals and
  `emitHTTPConnTimeoutHelpers` (`__kml_http_conn_set_deadline`,
  `__kml_http_arm_from`, `__kml_http_conn_next_deadline_ns`,
  `__kml_http_conn_sweep_timeouts`) in `ensureFiberRuntime`; the fold beside the
  spawn-timeout fold (`ctofold`); the sweep at the top of the loop beside
  `__kml_abort_to_fire_due`; a deadline clear for the fd in `__kml_http_append_conn`.
- `emit_http.go`: the three timeout options captured
  (`createServerTimeoutOption`/`createServerTimeoutMs`), primary-server-only for a
  positive value; `@__kml_http_any_timeout` set at server registration;
  `buildHTTPDispatcher` gains `phase`/`connStart` locals and the `armInitial`/
  `armKeepAlive` injections at the six phase points (all no-ops when no timeout is
  configured, so a default server's IR is unchanged).
- `emitter.go`: `curServerHeadersTimeoutMs`/`RequestTimeoutMs`/`KeepAliveTimeoutMs`
  and the `usedHTTPConnTimeouts` guard.

## Side effects discovered

None. The default (no-timeout) path is byte-identical: the dispatcher injections
and the `any_timeout` store are gated off, and the reactor fold/sweep early-return
on the zero flag. `requestTimeout`/`headersTimeout` are no longer in the no-op
option table (they have dedicated handling now).

## Scope / caveats (V1)

- Primary server only; an additional `createServer` rejects a positive timeout.
- **Silent close, no `408` body** — the security-relevant bound (freeing the
  fiber) is delivered by `shutdown`; emitting a 408 needs a TLS-aware write from
  the reactor sweep, deferred. HTTP/2 not covered (its dispatch is synchronous
  and separate). The advertised `Keep-Alive: timeout=5` header stays independent
  of the configured value.
