# ADR-00549: RegExp flags string validation (SyntaxError on invalid/duplicate)

- **Relations**: Extends ADR-00166
- **Date**: 2026-09-01

## Context

`new RegExp(pattern, flags)` and the `/pattern/flags` literal did not validate
the flags string at all. A duplicate flag (`"gg"`) or an unrecognized flag
character (`"z"`) was silently accepted, where real JS throws a `SyntaxError`
("Invalid flags supplied to RegExp constructor"). This was a disclosed caveat
on the RegExp construction and literal-syntax status rows. An earlier test
(`TestE2ERegExpUnknownFlagLetterIsPermissive`) actually pinned the unfaithful
permissive behavior.

## Investigation

`emitNewRegExpExpression` (emit_regexp.go) already throws a catchable
`SyntaxError` for an invalid *pattern* (via `buildErrorObj` +
`__kml_throw`). The flags string was only decomposed by
`__kml_regex_parse_flags`, which ignores any character it doesn't recognize.
The literal form desugars to the same `NewRegExpExpression`, so validating in
this one place covers both syntaxes.

## Decision

Add `__kml_regex_validate_flags(ptr) -> i32` (returns 1 if invalid): it walks
the flags string maintaining a seen-bitmask over the eight valid JS flag
letters `d,g,i,m,s,u,v,y`; a character not among them, or a repeat of an
already-seen flag, returns 1. `emitNewRegExpExpression` calls it right after
resolving the flags value and throws a `SyntaxError` on a nonzero return,
before the pattern is compiled.

`u`/`v`/`y`/`d` are treated as *valid* (no throw) even though their matching
behavior isn't implemented — that unimplemented-behavior gap is a separate
status row; this change is strictly about the throw-vs-silent-accept
distinction, matching exactly the conditions under which real JS throws.

## Implementation notes

- Runtime function in runtime_regexp.go, guarded by `usedRegexValidateFlags`.
- The throw block reuses the existing `buildErrorObj`/`__kml_throw` machinery
  already used for the invalid-pattern path.

## Side effects discovered

`TestE2ERegExpUnknownFlagLetterIsPermissive` asserted the old silent-accept
behavior; it was replaced by `TestE2ERegExpUnknownFlagLetterThrows`.

## Verification

`TestE2ERegExpInvalidFlagsThrow` (`"gg"`/`"z"`/`/a/mm` throw, `"gi"` accepted)
and the rewritten unknown-flag test pass, as does the full `TestE2ERegExp*`
suite. Built and verified on Mac (Apple Silicon).
