# ADR-01110: A control-flow graph in the binder; the TDZ and definite-assignment checks run on it

- **Relations**: `Implements TDD-00230` (Phase 2, P2.2); `Extends ADR-01108`
- **Date**: 2026-09-24

## Context

`resolver/readability.go` (about 1,800 lines, from ADR-00212 and ADR-00213)
held two hand-written walks
over the AST: one for the temporal dead zone (a `let`/`const`/`class`/`enum`
used before its declaration ran) and one for definite assignment (a typed
`let` read before a value was stored). Each re-derived control flow on its
own: a textual order for the first, per-construct merge rules for the
second, with documented escapes (a loop that might not run, a `try` that
might throw) and conservative approximations.
[TDD-00230](../tdd/TDD-00230.md) P2.2 replaces them with one flow graph the
binder builds, which later also feeds narrowing (P2.5) and `-mm=auto`'s
liveness facts.

## Investigation

- **typescript-go** builds the graph in its binder
  (`internal/binder/binder.go`: `createBranchLabel`, `createLoopLabel`,
  `createFlowMutation`, the `currentFlow` threaded through each statement)
  and answers "definitely assigned" by walking a reference's flow node
  backwards (`internal/checker/flow.go`).
- **What the two checks decide.** TDZ: a read of a lexical binding reached,
  within the same function, before its declaration ran; reads from nested
  functions are exempt (they may run later). Definite assignment: a read of a
  tracked `let` (a type not `any`, `unknown` or nullable) not assigned on
  every path; `var` and destructured bindings exempt; off under
  `-compat=js`.
- **Where the old checks diverged from TypeScript**, checked against `tsc`
  5.6.3:
  - they tracked an unannotated `let x;`, which TypeScript gives an evolving
    type and does not check;
  - they read a destructuring assignment's targets as reads
    (`let a: number; [a] = [1]` was rejected);
  - they let a loop that might not run, and a `try` that might throw before
    its assignment, assign (`tsc` reports TS2454 for both);
  - a loop-carried read (`if (i === 0) { x = 1 } else { x = x + 1 }` in a
    loop) was accepted; `tsc` reports TS2454 there and after the loop.
- **Block-scoped bindings are fresh per entry**: a `let` in a loop body is a
  new binding each iteration, so "reached after its declaration" must not
  follow a back edge past the block's entry.
- **Parameter defaults** are evaluated in an environment without the body's
  declarations when a function has parameter expressions
  (`function f(p = arguments) { let arguments }` reads the arguments object).

## Decision

- **The binder builds the graph** while resolving (`binder/flow.go`): a
  `Start` node per function and for the module, a `ScopeStart` node at each
  block-scope entry, branch labels where paths join (after an `if`, a
  conditional expression, `&&`/`||`/`??`, a `switch`, a loop's exit), a loop
  label per loop head with its back edges, assignment nodes (a declaration
  running initializes; a store assigns), and unreachability after `return`,
  `throw`, `break` and `continue`, each jump wired to its target (labels
  included). A loop whose condition is absent or the literal `true` exits only
  through `break`. A `catch` clause is entered from the state before the
  `try`; `finally` is bound on the normal paths out.
- **Each reference records its flow node** and the function (or module) it
  occurs in. A plain `=` and a destructuring assignment's targets store
  without reading; a compound assignment reads first; a destructuring
  declaration binds element by element, so a later default reads an earlier
  element.
- **Two backward walks answer the checks** (`FlowDiagnostics`):
  - **TDZ:** a read or write of a `let`, `const`, `class` or `enum`, in the
    function that declares it, from which no path reaches the declaration
    having run (only the binding's scope entry, or the function start). Such
    code always throws when it runs.
  - **Definite assignment:** a read of a `let` declared with a type and
    without an initializer (the type not `any`, `unknown` or nullable) from
    which some path reaches the binding's scope entry without a store.
    With an initializer, a path where the declaration has not run is the TDZ
    question instead.
  Answers cut short by a loop back into the walk are not cached.
- **Parameter defaults** resolve past declarations made only by the
  function's body, and a body declaration of `arguments` replaces the
  implicit one instead of merging into it.
- **The resolver** reports the redeclaration and flow diagnostics of a file
  together, in source order. `resolver/readability.go` is deleted.

## Implementation notes

- **New:** `binder/flow.go`, `binder/flow_test.go`.
- **Changed:** `binder/binder.go` (the graph, loop and jump targets,
  assignment targets, pattern order, parameter environments),
  `binder/symbol.go` (`Declaration.Body`; a symbol table entry may be
  replaced), `diag/messages.go` (TS2448, TS2454), `resolver/resolver.go`.
- **Deleted:** `resolver/readability.go`.
- **Tests:** `tests/func_test.go`'s loop-carried, while-only and try
  definite-assignment tests asserted the old escapes; they now expect
  `tsc`'s errors. `TestE2EWhileEscapeReadsDeterministicDefault` read the
  zero default an escaped read got in strict mode, where the read is now
  rejected; it is removed.

## Side effects discovered

- **Under `-compat=js` an unassigned typed `let` reads `0`**, where Node
  prints `undefined` (BACKLOG §0 item 1c, for P2.5's absence in the type
  lattice).

## Verification

All on macOS arm64 (M4):

- **Resolver-level equivalence** against the previous resolver over the whole
  corpus (107,567 resolve runs: examples, tools, apps, tests, Test262, each
  `.js` file in both lanes): no AST changed on a file that resolves. The
  errors that changed:
  - 28 dead-zone reads, the same error now reported with the file path;
  - 33 files that the old readability pass rejected and that now resolve:
    - the Annex B function-in-block tests (16), whose function binding it
      took for an unassigned variable;
    - destructuring-assignment targets, class and object-literal cases
      (Test262, 16);
    - `examples/jsmode/vanilla_class.js` in the strict lane (a `let`
      assigned on every path before its read);
  - `language/global-code/decl-lex-configurable-global.js`, now rejected
    first by the reserved-built-in check (the strict lane's rule), not by
    the old pass's false unassigned read.
- **`tsc` 5.6.3 `--strict`** confirms TS2448 or TS2454 for each new error
  the flow tests assert: loop-carried reads, a `while` that may not run, a
  `try` that may throw before its store, reads before a declaration in the
  same function, and none through a closure.
- `go test ./binder ./diag ./resolver ./parser`: pass.
- `make examples`: 358/358.
- `make test-par`: pass apart from the four `-mm=gc` macOS segfaults
  (`task_reclaim_gc_tls_test.go`), which fail identically at HEAD (BACKLOG
  §0 item 1d).
- `make conformance`: strict 7,129 / 53,578, js 7,716 / 53,578, unchanged
  from ADR-01108's run.
