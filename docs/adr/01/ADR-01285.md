# ADR-01285: host values' members through `any`

- **Relations**: `Implements part of TDD-00230` (P3.3), `Extends ADR-01204`
- **Date**: 2026-09-29

## Context

A host value in `any` was opaque past `typeof`, `instanceof` and
printing:

- A boxed Map or Set read `size`, but `m.get`, `s.add` and the other
  methods were "not a function".
- A RegExp is a headerless host object, so it boxed as a static pointer
  that nothing could identify:
  - `r instanceof RegExp` was false;
  - `r.source` threw "dynamic property access on a statically-typed
    value";
  - `String(r)` was `[object Object]`.
- A typed RegExp could not be stringified at all: `String(r)` was
  `[object RegExp]`, a template literal did not compile, and `r.toString()`
  was "no method".

This blocked porting `assert`, whose comparison and messages work over
`any`.

## Decision

- A host box's layout row is generated from its class's declaration
  (`lib/es.d.ts`, `lib/node.d.ts`; `emit_host_shape.go`):
  - **Property read:** the typed read on the unboxed handle, boxed.
  - **Writable property:** the typed assignment.
  - **Method:** a dynamic-function record whose adapter checks the
    receiver ("Method X.prototype.m called on incompatible receiver"),
    then unboxes the arguments. A parameter declared as the collection's
    `K`, `V` or `T` takes the boxed map's or set's own key or value type.
    The adapter makes the typed call with as many arguments as were
    passed.
  - Code generation's own emitters do the work, so a member behaves the
    same through `any` as on a typed value.
- A RegExp boxes into a host cell, as handles do (`hostCellObject`):
  - `instanceof`, union discrimination and unboxing treat it as a host
    handle;
  - `String(box)` of a class with its own `toString` (RegExp) renders
    through the typed conversion.
- Typed RegExp: `String(r)`, template interpolation and `r.toString()`
  are `/source/flags`.
- A callback wrapper that returns its argument (`mustCall((req, res) =>
  …)`, a signature `<T>(fn: T, …): T`) no longer hides its literal:
  - in a function-typed slot (or a union with one), the literal takes the
    slot's parameter types, and the wrapper's `any` result converts back
    to that closure type;
  - codegen's own callback slots (cluster, http2) see the literal through
    the wrapper.

  This is what tsc does when it infers `T` from the context.
- Two bugs this exposed are fixed:
  - A typed `(chunk: string) => …` literal handed straight to a dynamic
    call now converts a non-string argument with ToString, as the boxed
    closure adapters already did. It used to read a Buffer's pointer as
    characters.
  - A captured `any` parameter's cell is created where its boxed value
    exists, not in the entry block. That was invalid IR.
- The checker gains `GlobalInterface(name)`, a global interface's type,
  and function types expose `OptionalParam(i)`.
- The layout-view routines are finalized again after the layout table:
  the host rows' typed reads can request more.
- Still open (TDD-00230 P3.3):
  - A Date boxes as a number.
  - Other headerless host objects (URL, Worker, …) are not host cells yet.
  - Iterating a boxed Map or Set (`for…of` through `any`) needs
    `[Symbol.iterator]`, which the declarations' computed members do not
    give.

## Verification

Mac (Apple Silicon): `TestE2EHostMembersThroughAny` prints what Node
v24.19.0 prints for Map and Set methods, RegExp `exec`, `lastIndex`,
`instanceof` and `String` through `any`, and typed RegExp stringification.
