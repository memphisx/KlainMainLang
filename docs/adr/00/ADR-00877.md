# ADR-00877: Per-platform conformance report folders

- **Relations**: `Implements TDD-00204`
- **Date**: 2026-09-11

## Context

Conformance reports lived at `docs/testing/<lane>/` — one folder per compat
lane, no platform dimension. But the numbers are a property of the
(platform, lane) pair: the runtime has real per-platform code paths (reactor
implementation, fs, signals, libcurl TLS backend), and the two dev machines
(macOS arm64, Ubuntu x86-64, with Windows visits) already produce slightly
different results that overwrote each other's reports, so a cross-platform
regression was indistinguishable from machine drift.

## Decision

Layout becomes `docs/testing/<platform>/<lane>/…` with
`docs/testing/<platform>/conformance-summary.json` beside the lane folders.
`<platform>` is `<os>-<arch>` with user-facing names (`macos-arm64`,
`linux-x64`, `windows-x64` — `darwin`→`macos`, `amd64`→`x64`), derived in the
runner (`platformLabel()`), never passed by hand. Existing reports (all
generated on the Mac) moved to `docs/testing/macos-arm64/`. The website's
`gen-conformance.mjs` scans the platform folders and publishes the primary
dev platform's summary (`macos-arm64` first, then a fixed priority, then any
present), keeping its committed-copy fallback.

## Consequences

Each platform's report history is an independently diffable git delta —
running conformance on the Linux box no longer clobbers the Mac's numbers,
and a per-platform regression is a per-file diff. New platforms (the Sailfish
device, Windows) appear by adding a folder. Comparing two platforms is a diff
of sibling folders generated from the same pinned corpora.
