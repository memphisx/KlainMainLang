# ADR-00824: Server request as a Node Readable (TDD-00195 Stage 1)

- **Relations**: `Implements TDD-00195`, `Extends ADR-00362`
- **Date**: 2026-09-10

## Context

BACKLOG §1 "real async streaming": an http server `req` exposed `.body`
(buffered), `.bodyBytes()`, and `.stream()` (a WHATWG `ReadableStream`,
incremental + backpressured, TDD-00097 Stage 5b) but had no `.on('data')`,
`.pipe()`, or async iteration — so the idiomatic Node forms
(`for await (const chunk of req)`, `req.on('data')`, `req.pipe(dest)`) did not
compile. TDD-00195 Stage 1 closes this; Stage 2 (`res` as a Writable) is designed
there but deferred.

## Investigation

- The Node `Readable` machinery already exists in full (TDD-00132):
  `wrapWebReadable` wraps a WHATWG readable into a Node `Readable` with
  `.on`/`.pipe`/for-await, and `req.stream()` already yields exactly such a WHATWG
  readable (`emit_http.go` `emitRequestStream`). The gap was only *connecting*
  them.
- Single-consumption must be preserved: a second `req.stream()` throws the WHATWG
  "disturbed" TypeError (ADR-00362), so `req.on('data')` then `req.on('end')`
  must attach to **one** shared readable, not two.
- The for-await dispatcher already unwraps a Node `Readable` to its inner WHATWG
  stream (`emit_stmts.go`); the Node-stream `.on`/`.pipe` dispatch
  (`emitNodeStreamCallOn`) already implements the methods.

## Decision

Expose the request body as a Node `Readable`, created once and cached on the
request:

- A new trailing `__kml_noderd` field on `RequestType` (null until first use;
  null-initialized in both request builders, and hidden from
  `Object.keys`/JSON like the other trailing internals).
- `reqAsNodeReadable(req)` lazily builds `wrapWebReadable(emitRequestStream(req))`
  on the first Node-`Readable` access and caches it in `__kml_noderd`; every
  subsequent access reloads the cached value (a merge-reload rather than a phi
  over `wrapWebReadable`'s own block). So `.on`/`.pipe`/for-await share one
  underlying stream.
- Dispatch: `req.on`/`req.once`/`req.pipe` (`emit_call.go`) forward to
  `emitNodeStreamCallOn` on the cached readable; `for await (const chunk of req)`
  (`emit_stmts.go`) iterates its inner WHATWG stream. Chunks are `Uint8Array`.

## Implementation notes

- `reqAsNodeReadable` calls `ensureNodeStreamRuntime()` — `wrapWebReadable` emits
  `__kml_ns_alloc`, which the pure-for-await path (no `.on`/`.pipe`) would
  otherwise leave undeclared.
- Emitting `emitRequestStream` inside the conditional "make" block still flips
  the compile-time `usedReqBodyStream` flag, so the dispatcher builds the body
  context regardless of the runtime branch.

## Side effects discovered

`req.on('data')` with a *fire-and-forget* handler that defers `res.end` to the
`'end'` listener races this compiler's flush-on-handler-return model — the
response flushes before `'end'` fires. It works when the handler stays alive
until end (a `for await`, or `await`ing a promise resolved in `'end'`). The
imperative fire-and-forget form needs the `res`-as-Writable model (TDD-00195
Stage 2, deferred). In-process `fetch`-to-self with a streamed request body can
deadlock on the single loop; the native `http.request` client does not (this is
the fetch-reactor scheduling caveat, not new to this change).

## Verification

- New E2E tests (`tests/streams_test.go`): `for await (const chunk of req)` over
  a 3 MiB multi-chunk POST, `req.on('data')`/`'end'` with an awaited handler, and
  `req.pipe(fs.createWriteStream)`. Example `examples/http/req_readable.ts`
  (self-contained, exits 0). Full http/stream/fetch/upgrade/websocket suites
  pass.
- `go build`, `go vet` pass.
