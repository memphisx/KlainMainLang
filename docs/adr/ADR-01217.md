# ADR-01217: fetch reads its init as RequestInit, and sends every BodyInit

- **Relations**: `Extends ADR-01215`
- **Date**: 2026-09-28

## Context

`fetch(url, init)` read `init` at its static type. It accepted a string
`body` only, and `headers` only as a Headers, a string map, a record or
pairs. Code typed the way TypeScript types it failed: an
`async function api(path: string, init?: RequestInit)` wrapper, the
ordinary shape of a REST client, did not compile (`RequestInit` resolved to
`number`, BACKLOG 95).

Four more divergences from Node:

- A string body went out with no Content-Type; Node sends
  `text/plain;charset=UTF-8`.
- A binary body went out with curl's form-urlencoded default.
- A body on a GET request was sent as a POST; Node rejects it.
- A failed fetch rejected with an `Error`; Node's is a `TypeError`.

## Investigation

- `RequestInit`'s members are `body?: BodyInit | null` and
  `headers?: HeadersInit`. `BodyInit` includes types this compiler has no
  representation for (`AsyncIterable<Uint8Array>`, `FormData`), so the
  union has no static layout.
- undici's `extractBody` settles the body at run time: a string, a
  URLSearchParams, a Blob, an ArrayBuffer or an ArrayBufferView, with the
  Content-Type each implies. Any other value is converted with `String()`.
- `CURLOPT_POSTFIELDS` alone measures the body with `strlen`, so a binary
  body was cut at its first NUL.
- The suspending-call path (`emitMaySuspendCall`) did not fill an omitted
  optional or defaulted argument.

## Decision

- A builtin-declaration interface or type alias resolves in codegen
  (ADR-01216). An alias with no representation (`BodyInit`) is `any`.
- `fetch` boxes `init.body` and reads it at run time
  (`emitFetchBodyFromBox`), with its bytes, length and implied
  Content-Type. `__kml_fetch_async_n` passes the length
  (`CURLOPT_POSTFIELDSIZE_LARGE`).
- A `headers` of a union type, `any` or an optional member is read at run
  time (`emitHeadersFromBox`), as `new Headers(init)` reads it:
  - a Headers is copied;
  - an array is appended as `[name, value]` pairs;
  - an object is a record of its entries;
  - a primitive is Node's TypeError.
- The implied Content-Type is added unless the headers set one. A body
  with none sends `Content-Type:` so curl adds no default.
- An absent optional `init` sends a plain GET.
- A `signal` member is ignored when the program has no `AbortSignal`, so
  there is none to pass.
- A body on a GET or HEAD request (the default method is GET) settles the
  fetch with Node's `TypeError: Request with GET/HEAD method cannot have
  body.` (`__kml_fetch_failed_pending`, `__kml_fetch_errstr`). Every
  failed fetch rejects with a `TypeError`.
- `emitMaySuspendCall` fills an omitted argument with its default, or an
  optional parameter's absent value.
- `new Request(url, init)` reads its init the same way (BACKLOG 77): every
  BodyInit, copied into the Request (Node copies it too), with its implied
  Content-Type; any HeadersInit; an optional init. `loadFieldValue` reads an
  array member as its value and a nullable-scalar member in its `{ i1, T }`
  storage.

## Implementation notes

`codegen/llvm/emit_fetch.go`, `emit_fetch_request.go`, `emit_fetch_body.go` (new),
`runtime_fetch.go`, `runtime_fetch_stream.go`, `emit_ambient.go`,
`emit_task_emit.go`, `emitter.go`.

## Side effects discovered

- The checker accepts any value as `BodyInit`/`HeadersInit` (BACKLOG).
- A network failure's message is curl's (`Couldn't connect to server`);
  Node's is `fetch failed` with the reason as its `cause`.
- `typedArray.buffer` is not supported.
