# ADR-01060: Node as the test oracle, layout/extern contracts under test, a promotion-invariant guard, and two invalid-IR fixes in top-level binding inference

- **Relations**: Extends ADR-01059 (the session that surfaced every item), TDD-00093 (module globals), TDD-00212 (any-boxed array box), ADR-00540 (the node:sqlite oracle this generalises)
- **Date**: 2026-09-22

## Context

ADR-01059's work kept tripping over the same structural costs, so this records the changes made to remove them —
and the two real bugs the new guards found the moment they existed:

1. Every "matches Node" expectation was produced by running Node by hand, diffing, and pasting the string into a
   Go test. Nothing kept that string honest afterwards.
2. `reliableGlobalType` (the module-global pre-pass) and `emitVarDecl` decide a binding's type independently;
   ADR-01059's `Int32Array(0) []` was the two disagreeing, silently. Nothing checked that they agree.
3. `dynjson.c` mirrors the any-array box, the array header and the NaN-box encoding by hand ("keep in sync"
   comments); drift showed up as a wrong value at runtime.
4. A C sidecar's `extern` dependencies were implicit — a new one is a link error in every program that pulls the
   file in, discovered only by running one.
5. `tools/testsel/` (area-scoped test batches) lived untracked on one machine.
6. The conformance runner's default worker count is CPU-derived; on this box 8 `clang -O2` workers exceeded the
   Windows commit limit and the resulting clang deaths were reported as invalid IR. A `-limit 1` smoke run of the
   runner also overwrote the committed full-corpus report.

While writing the tests for (2), two invalid-IR bugs appeared:

- `const s = "x"; function f() { return s }` (no annotation on `f`) emitted `ret ptr` for an `i64` return —
  in the compiler since before session 21 (the Sep-21 binary fails the same way). `function g() { return arr }`
  over a top-level array, and `return [anyGlobal, 7]`, misinferred the same way (raw NaN-box words printed).
- `const m: any = new Map(); function f() { return m }` emitted the same `ret ptr` — BACKLOG §0 item 14.

## Investigation

- Function signatures are built in Pass 1 (`registerFunctions`); module globals are registered in Pass 1.7. So
  while an unannotated function's return type is inferred, an identifier naming a top-level binding resolves
  neither as a local nor as a module global, and `inferExprType`'s Identifier case fell through to the zero
  type — the number default. `resolveValueType` (the `typeof x` query) already types a top-level declaration
  from the AST with a cycle guard, but `e.topLevelNames` (the set that says "this identifier is one of ours")
  was only filled in Pass 1.7.
- A Map/Set/WeakMap/WeakSet/WeakRef/channel initializer types its binding from itself in both deciders (so they
  agree), but has no NaN-box kind: under an `any` annotation the binding is a ptr handle while every reader of an
  `any` expects an i64 box.

## Decision

1. **`assertSameAsNode(t, src)` / `assertSameAsNodeCompatJS`** (`tests/compiler_test.go`): the same TypeScript
   program runs here and under `node --experimental-strip-types`; stdout must be identical. Node is probed once
   per test binary; absent Node the test skips, so the Node-less CI lanes keep the hand-pinned `assertOutput`
   twins. ADR-01059's tests gained `TestOracle*` twins.
2. **`promotedStorageAgrees(v, declTy)`** (`emit_exprs_vardecl.go`): every promoted declaration (scalar/box,
   array, handle paths) compares the pre-pass global's storage shape (IR, array-ness, box-ness, typed-array
   family) with what the declaration is about to store, and a mismatch is an internal compile error naming both
   — a loud failure instead of a silent misread, until the two deciders are one function (BACKLOG).
3. **`sidecar_layout_test.go`** (`codegen/llvm`): compiles a probe that `#include`s `dynjson.c` and checks
   `KjBox`'s size/offsets against `anyArrayBoxTy`, the header reads against `arrayHeaderTy`, `nb_pack`/`nb_double`
   against `runtime_nanbox.go`'s constants, and the `KJ_*` enum against `arrayElemKind`.
4. **`sidecarExterns`** (same file): the declared `extern` set of each sidecar and the ensure functions that
   provide it; the test fails when the C file's externs differ from the list.
5. **`tools/testsel/`** is tracked, with a README and a `file:<area>,<area>` selector — the test files are the
   area map (`tests/<area>_test.go`); `probes/` stays ignored scratch.
6. **Conformance runner**: the default worker count is capped by available commit (Windows
   `GlobalMemoryStatusEx`, Linux `/proc/meminfo` + cgroup limit; macOS uncapped) at 1.5 GiB per worker, printed
   when it applies; a `-limit`/`-category` run writes its report into the work dir, never over the committed one.
7. **Pass 1 identifier inference**: `collectTopLevelNames` runs before Pass 1; `inferExprType`'s Identifier
   fallthrough types a top-level name via `resolveValueType` (annotation, else initializer; cycle-guarded).
8. **A container handle under an `any` annotation** (`Map`/`Set`/`WeakMap`/`WeakSet`/`WeakRef`/channel) is a
   clean compile-time rejection naming the fix; holding one in an `any` faithfully needs a type-id like
   Symbol's (ADR-01059) and stays in BACKLOG §0.

## Side effects discovered

- The Symbol-style hidden type-id word (bit 47) could generalise to Map/Set/Date/RegExp handles so they can live
  in an `any` — the follow-up to item 8; BACKLOG §0.
- `resolveValueType` prefers the AST declaration over a same-named function local, a pre-existing corner it
  documents; the Pass 1 fallthrough only runs when the identifier is not in scope, so it cannot widen that.

## Verification

- The runner now reports "workers: 22 by CPU, but only 10.0 GiB of commit is available — defaulting to 6" on this
  box; a `-limit 1` run writes `R:\…\conf-probe\CONFORMANCE-RESULTS-strict.md` and leaves `docs/testing` alone.
- Full suites: Windows and Linux (Docker) on the final tree — results in the session handover.
