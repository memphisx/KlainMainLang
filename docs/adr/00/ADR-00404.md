# ADR-00404: Node `http` client `http.get`/`http.request` (TDD-00138 Stage 1)

- **Relations**: Implements TDD-00138; Extends ADR-00021/ADR-00050 (fetch/libcurl)
- **Date**: 2026-08-27

## Context

The Node `http` **client** was the single largest real Node-oracle blocker (117
files: `http.get` 82, `http.request` 44) and the project's #1 REST-client
priority. This implements Stage 1.

## Decision

`http.get(url, cb)` (and `http.request`, which reduces to it in V1 — GET, no
request body yet) is built on the existing libcurl `fetch` primitive:
`__kml_fetch_async` + `__kml_await_fetch` perform the request and yield
`{ status, body, bodyLen }`. The callback receives an **`IncomingMessage`**
(`IsIncomingMessage` object) with `res.statusCode` and `res.on('data', chunk)` /
`res.on('end')`. The body is delivered as a single `'data'` chunk then `'end'`,
fired synchronously right after `cb` registers its listeners. `res.setEncoding`/
`resume`/`pause`/`destroy` are accepted no-ops; `on('error'|'close')` are
accepted (our fetch throws on a network error rather than emitting `'error'`).
The callback's response parameter is hinted as `IncomingMessage` so
`res.statusCode`/`res.on(...)` resolve without an annotation.

## Boundary found: blocking client vs the single event loop

`__kml_await_fetch` **blocks** (busy-spins libcurl's multi-interface), like a
top-level `fetch` outside any fiber. So `http.get` against an **external /
separate-process** server works (verified byte-identical to Node against a Go
`httptest` server, statusCode + body). But `http.get` against **this program's
own** `http.listen` server **deadlocks** — the blocking client starves the same
single-threaded event loop the server runs on (unlike `await fetch`, which yields
its fiber). The in-process server+client shape is what most Node tests use, so
the critical follow-on is **async, event-loop-integrated delivery**: schedule the
response callback as a reaction/microtask when the transfer completes rather than
blocking. Tracked in TDD-00138.

## Consequences

Node oracle: the `http has no method` bucket dropped 117 → 105 and one more file
passes (25). The remaining 105 are gated on the **bare `const server =
http.createServer()`** server form (today only the inline `createServer(h).listen(p)`
chain exists) plus the async-delivery follow-on — both now the clear next steps.
E2E tests run `http.get` against a Go `httptest` server (a separate process),
sidestepping the in-process deadlock; no self-contained example ships for the
same reason.
