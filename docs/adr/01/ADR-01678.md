# ADR-01678: Shadow call stack for `Error.stack`, `console.trace` and inspection

- **Relations**: Implements TDD-00188
- **Date**: 2026-10-17

## Context

`Error.stack` read back only the error's header, `console.trace` printed its message line with no frames, and `util.inspect`/`console.log` of an error, like the uncaught-exception report (`Uncaught: <message>`), showed no frames. Node prints the program's `.ts` frames in all four places, each frame named and positioned the way V8 does it. TDD-00188 designed a per-fiber shadow call stack for this. TDD-00230's builtin-library work (P3.5) needs it, because library code written in TypeScript reads `err.stack` the way Node's own internals do.

## Investigation

- **Where frames come from.** A native `backtrace()` would give mangled `@fn__kml_modN` symbols, and `-O2` inlining drops frames from it, so the frames have to be kept by the program itself.
- **What V8 shows.** Probes against Node 24 (`.ts` run with type stripping):
  - A function is named by its declaration or binding. An object literal's method is `Object.m`. A class has `Class.method`, `new Class` and static `Class.s`.
  - A function called through an object's property is named after the receiver's type: `Timeout.tick [as _onTimeout]`, or `Timeout._onTimeout` for an anonymous one.
  - Positions:
    - a call sits at its callee's name (for `o.m()`, the `m`), or at the parenthesis when the callee is unnamed;
    - a `new` sits at its keyword;
    - a property read's `TypeError` sits at the property;
    - a suspended async function sits at its `await`.
  - The top-level frame is `Object.<anonymous>` for a file Node runs as CommonJS. For a file with module syntax it is the bare location.
  - Microtasks, ticks, timers and immediates run with no frames of the program below them.
  - After an `await`, the stack continues with `at async <fn>` for each async function awaiting the current one.
  - `Error.captureStackTrace(obj, fn)` sets `obj.stack` to the frames below `fn`'s topmost frame. `Error.stackTraceLimit` defaults to 10.
- **Unwinding.** A `longjmp` to a `catch` skips the epilogues, so the try snapshot must carry the stack top. A ucontext switch must keep each side's own top.

## Decision

- **Frame records.** Every user function's prologue links a frame record `{prev, desc, pos}`, allocated in the entry block, into the thread-local `__kml_frame_top`. Every `ret` restores the previous top. `desc` is a constant `{name, file-URL}`.
  - Each call, `new`, `await` and maybe-throwing property read stores its position, `line<<32|col`, into the running frame.
  - Once a call nested in the arguments returns, the enclosing call's position is stored again. The frame therefore names the call in progress when its callee runs.
- **Errors.** An error captures its frames when it is made: Error construction, an Error subclass's allocation at its `new`, and errors made by the runtime, captured at their throw. The header is formatted on the first read of `.stack`, as V8 does.
- **Output.**
  - `console.trace` prints the frames after its message (a bare `Trace` with no message).
  - Inspection prints an error's frames, indented to its depth. A stack that has become a string prints as it is, in brackets when it has no frames.
  - The uncaught report prints the error's stack, or a thrown non-error value as it prints.
- **Fibers.**
  - Each fiber has a base frame (`KML_FIBER_ENTRY`).
  - `KML_SWAPCONTEXT`, the IR `fiberSwitch` and the C helper `__kml_swapcontext_kept` used by the IR HTTP runtime each:
    - park the fiber's top in its base record;
    - restore top and base on resume;
    - cut the base from its creator's frames, which may be gone.
  - The jmpstack slots save and restore top and base.
  - A task records its base frame (task field 14). The async part of a stack walks from the current task's promise to the task awaiting it — through the waiter field, an await's `__kml_task_resume` reaction, or a pending-promise field — and prints that task's own frame.
- **Method-call markers.** A call through a function-valued property links a marker record (a descriptor with no file) naming the receiver's type and the property. The callee's frame then renders as `Type.fn [as prop]`. The timers library calls `timer._onTimeout()` and `immediate._onImmediate()` as methods, as Node does.
- **Event loop and jobs.** The event loop and each microtask job run with the frames below them set aside.
- **`Error.captureStackTrace`** is a library function (`lib/node/internal_error_stack.ts`) over the native `captureFrames`.
- **`Error.stackTraceLimit`** is a thread-local `double` that the emitter reads and writes.
- **Always on.** The frames are not behind a flag, unlike TDD-00188's recommendation, because the observable behaviour is Node's. Their cost (an alloca, three stores, one load, and a store per return and per call site) is recorded below as a performance follow-up: an opt-in flag that drops the frames for a program that never reads them.

## Implementation notes

- **Frames:**
  - `codegen/llvm/frames.go` covers the prologue, epilogue, call-site, access-site and method-marker emission, the module frame's name, and V8's call position.
  - `codegen/llvm/framesrc/frames.c` covers capture and formatting, the async part, `captureFrames` and the limit.
- **Fibers and the loop:**
  - `kmlheapsrc/kml_heap.h` holds the macros.
  - `tasksrc/task.c` records the base frame and provides `__kml_task_awaiting`, which it hands to frames.c through a hook pointer, because a weak undefined symbol does not link on macOS.
  - `promisesrc/module.c` records the base frame too.
  - `loopsrc/loop.c` and `microtasksrc/microtask.c` set the frames below aside.
- **Separate frame state.** Frame state lives on the function builder. A module body under top-level await (`beginModuleBody`) and the standalone IR helpers (`emitStandaloneFunc`) keep their own, otherwise a `ret` there restored `main`'s record.
- **Module syntax.** `resolver` records which files have module syntax (`Program.ESMFiles`). Node's detection goes by it when naming the top-level frame.
- **Other changes:**
  - `exceptionssrc/exceptions.c` captures frames at the throw of a runtime-made error and prints the stack in the uncaught report.
  - `dynjsonsrc/dynjson.c` prints the frames when inspecting an error.
  - `lib/es.d.ts` declares `captureStackTrace` and `stackTraceLimit` as `@types/node` does.
  - `tests/compiler_test.go` gains `assertSameAsNodeFrames`, which compares with Node after normalizing file URLs and dropping Node's internal frames.

## Side effects discovered

- **Fixed in passing:** a named function reading a top-level generator object (`const it = gen()`) failed with `undefined variable`. It is now promoted, typed as the generator.
- **Fixed in passing:** an object literal whose method reads the object's own binding was not promoted, and failed in a constructor that read it. The promotion pre-pass now accepts that self-reference.
- **Remaining:** `constructorOpt` is matched by the function's name, not its identity.
- **Remaining:** V8's builtin frames (`Array.map (<anonymous>)`) and Node's internal frames are not shown.
- **Remaining:** the uncaught report leaves out Node's source excerpt and version line.
- **Remaining:** `Error.prepareStackTrace` is not supported.

## Verification

- `tests/stack_frames_test.go` compares names, positions, inspection, the async chain, callbacks, the ES-module top-level frame, `captureStackTrace` and `stackTraceLimit` with Node.
- The inspect tests (`TestE2EErrorSubclassInspect`, `TestE2EErrorInspectCause`) now use Node as their oracle, and the uncaught-report tests were updated to the stack.
- `examples/try_catch/stack_traces.ts` was added.
- On macOS (Apple Silicon): targeted runs over the error, inspect, timer, microtask and stack tests.
- On Linux x86-64 (Node304): the broad error, exception, async, generator and console subset, whose one failure was the uncaught-report expectation since updated.
