# ADR-00678: `async_hooks` AsyncLocalStorage — context across `await`

- **Relations**: Implements TDD-00168 (Stages 1–2); builds on TDD-00083/00084/00088
  (coroutine task scheduler), TDD-00156/ADR-00628 (NaN-boxed `any`), ADR-00420
  (diagnostics_channel wiring precedent)
- **Date**: 2026-09-03

## Context

`async_hooks` is the second-largest unimplemented Node module gap (~52 oracle
files). Its valuable, implementable half is `AsyncLocalStorage` — request-scoped
context that propagates through an async call tree across `await`. The low-level
`createHook`/async-id/GC-lifecycle half observes V8 engine internals a compiled
runtime has no equivalent for (TDD-00168), so it stays out of scope.

## Investigation

The one design question that decided the shape (TDD-00168): can context survive
an `await`? An exploration of the coroutine runtime (`runtime_task.go`) found the
answer is nearly free. A task is a heap struct with a fixed field layout and a
thread-local `@__kml_current_task` pointer that the scheduler restores to a task
before resuming it (`runtime_task.go:576/859`). So if the current async context
lives *in the task struct* rather than a global, a parked task's context is
still there when it resumes — no microtask-queue threading, no per-resume
save/restore. Spawn inheritance is a single copy at `runtime_task.go:399`.

Two obstacles surfaced during implementation, both fixed:
- A module-level `const als = new AsyncLocalStorage<T>()` read inside a *named*
  function typed as `number` — the module-global promotion machinery
  (`promotableNewExpr`/`reliableGlobalType`) didn't recognize the handle, so it
  promoted an i64 global. Adding `AsyncLocalStorage` to the promotable
  single-ptr handles fixed it (the canonical ALS use is exactly a module-level
  singleton read by many functions).
- The var-decl and inference `new`-expression switches (three sites) needed an
  `AsyncLocalStorage` case beside `Promise`/`PerformanceObserver`.

## Decision

**Representation.** "The current async context" is the head of an immutable,
prepend-only linked list of `{ i64 alsId, i64 value, ptr next }` frames; `value`
is a NaN-boxed `any` word, so any store type fits one slot and "no store" is just
the `undefined` word. The head lives per task — in a new field 12
(`taskAsyncCtx`) on the coroutine task struct — with a top-level fallback global
`@__kml_root_async_ctx`. `__kml_als_ctx_get`/`_set` read/write the running task's
field 12, or the root when no task is running.

**Task struct widening.** `taskStructIR` is a single named constant used through
field-index constants everywhere, so widening was appending one `ptr`
(96→104 bytes, index 12). `__kml_spawn_task` initializes it by inheriting the
spawner's head (parent task's field 12, or the root) so a store set with
`run(...)` before an async call propagates into the spawned task. Validated
against the full async/promise/generator/timer/worker suite before any ALS
surface was added.

**Methods.** `run(store, cb, ...args)` boxes the store, pushes a frame, invokes
the callback via `emitClosureCallByPtr` (forwarding trailing args, returning the
callback's own result), then restores the previous head. `exit` pushes an
`undefined` shadow frame. `getStore()` walks the current head for this
instance's id (`undefined` when absent or the instance is disabled), unboxed to
`T`. `enterWith` pushes without restoring; `disable` flips a per-instance flag.
Typed as `AsyncLocalStorage<T>` (the user-chosen shape) — `getStore(): T`, with
absence yielding `T`'s zero/`null` (the compiler's established undefined
stand-in for a scalar store).

**Wiring** mirrors `diagnostics_channel`: marker + member set
(`resolver/virtual_modules.go`), identity constructor (`resolver/rename.go`),
`new` dispatch (`emit_classes.go`), method dispatch (`emit_call.go`), type +
inference (`types.go`, `emit_exprs_types.go`, `emit_exprs_vardecl.go`). New
`runtime_asynchooks.go` (frame ops) + `emit_asynchooks.go` (methods).

## Implementation notes

- The root global `@__kml_root_async_ctx` is emitted unconditionally in
  `ensureCurrentTaskGlobal` (alongside `@__kml_current_task`) so `__kml_spawn_task`
  can reference it whether or not the program uses ALS (it stays null when unused).
- The spawn inherit is an inline 4-block branch (parent field-12 vs root) added
  to `__kml_spawn_task`, hardcoding the struct IR literal to avoid disturbing the
  function's positional format-string arguments.

## Side effects discovered

Two pre-existing, unrelated async-edge bugs surfaced while writing the example
(both avoided in it, not caused by ALS): `Promise.all` over `void`-returning
promises emits an invalid `trunc i64 to void`; and `return await
als.run(store, asyncCb)` (returning *and* awaiting an async callback's promise
straight out of `run`) segfaults. Both are general async-combinator/return-flow
edges, tracked as follow-ups.

**Staged (TDD-00168 Stages 3–5, not in this ADR):** timer-callback context
propagation (`setTimeout` inside `run` currently sees no store — capture at
schedule + restore at fire), static `AsyncLocalStorage.bind`/`snapshot` +
`AsyncResource.runInAsyncScope`, exception-safe `run` restore, and wiring
`diagnostics_channel`'s `bindStore`/`runStores` onto these frames.

## Verification

Mac. New E2E tests in `tests/node_core_modules_test.go`: sync run/exit nesting,
**context across `await`** (the crux — a store survives an await/park/resume),
1000-deep nesting, disable/enterWith. Example `examples/async/async_local_storage.ts`
(two requests each keeping their own id across an await). Full
async/promise/generator/timer/worker regression green after both the core
struct widening and the ALS surface. `go build`/`go vet` clean.
