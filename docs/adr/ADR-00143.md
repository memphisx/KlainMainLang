# ADR-00143: Reserved ambient-global names — `-globals=strict|permissive`

- **Relations**: Implements [TDD-00050](../tdd/TDD-00050.md). Extended by [ADR-00217](ADR-00217.md) (the `-globals` flag was later absorbed into `-compat`)
- **Date**: 2026-08-10

## Context

Raised directly, from testing real browser behavior: `const Math = {}` genuinely works in a real browser (and Node) — JS has no reserved words for its own built-in globals. [TDD-00049](../tdd/TDD-00049.md)/[ADR-00141](ADR-00141.md)/[ADR-00142](ADR-00142.md) already fixed this class of bug for Category B (`fs`/`path`/etc., now import-gated), but deliberately left Category A (`Math`/`JSON`/`console`/…) and Category C (`process`) alone — a local variable using one of those names still silently miscompiled, routing to the built-in instead of the user's own value.

The ask was the inverse of TDD-00049's fix, though: reject shadowing these names as a compile error **by default** — stricter than real JS, a deliberate safety net — with a compiler flag for real JS/browser semantics on request. See [TDD-00050](../tdd/TDD-00050.md) for the full design, including the two-tier split found while investigating (below) and the direct decision on scope, asked and answered before implementation started: constructor-style built-ins (`Map`/`Date`/`RegExp`/…) stay reserved even under the permissive flag.

## Investigation

- `parser/parser_literals.go`'s `parseNew`: confirmed by direct read, a bare textual `switch` on the identifier immediately after `new` — 23 explicit cases (`Map`, `Set`, `Date`, the `Error` family, `RegExp`, `URL`, `EventSource`, `WebSocket`, `URLSearchParams`, `Headers`, `Request`, `XMLHttpRequest`, `ArrayBuffer`, `TextEncoder`/`TextDecoder`, `EventEmitter`) plus `typedArrayElemKinds` (the 8 TypedArray constructors) checked in the `default` branch. This commits to the built-in AST node type unconditionally, before any resolution phase exists — real permissive shadowing here would need the parser to defer that decision to the resolver instead, out of scope (decided directly, see Context).
- `codegen/llvm/emit_exprs.go`'s identifier-evaluation case and `emit_exprs_types.go`'s `inferExprType` both already check `e.lookup(ex.Name)` **first**, falling back to `NaN`/`Infinity` only on a miss, with a comment confirming this was deliberate. This is the exact mechanism generalized to every other Tier 1 name below — not a new pattern, an existing one extended.
- Every other Tier 1 dispatch site (`Math`/`JSON`/`console`/`process`/`crypto`/`performance`/`Object`/`Array`/`String`/`Number`-as-namespace, and the ~19 bare global functions in `emit_call.go`'s "Global built-in functions" switch) matched on bare `id.Name` unconditionally — no lookup-first check. Confirmed by grepping every such site across `emit_call.go`/`emit_exprs_member.go`/`emit_exprs_types.go`/`emit_exprs_vardecl.go`/`emit_objects.go`/`emit_process.go`.
- `resolver/rename.go`'s `scope.bind(name)` — confirmed to be the single choke point every local binding already passes through (function/arrow params, `let`/`const`/`var`, array/object destructuring, `for...of`/`for...in`, `catch` params); `resolver.go`'s `mangleFileDecls` is the equivalent for top-level declarations. No other place introduces a name.
- **Verified no existing example or test would break** under the new stricter default before committing to it: grepped `examples/`/`tests/` for any declaration, parameter, destructuring target, or loop variable using any of the ~50 reserved names — none found. `-globals=strict` as the new default is a pure addition, not a behavior change to anything already shipped.

## Decision

**New flag, `-globals=strict|permissive`** (default `strict`), mirroring `-mm=manual|gc`'s shape in `main.go`.

**Reserved-name registry** (`resolver/reserved_names.go`, new): `reservedTier1` (30 names — the plain-identifier globals) and `reservedTier2` (30 names — the parser-level `new`-form built-ins), plus `checkReservedBinding(name, line, col, allowGlobalShadowing) error` — Tier 2 always rejected, Tier 1 rejected only when `allowGlobalShadowing` is false.

**Strict-mode validation, resolver-side**: `resolver.ResolveProgram(path)` is now a thin wrapper over the new `resolver.ResolveProgramWithOptions(path, allowGlobalShadowing bool)` — kept as a zero-risk addition rather than changing the widely-used original signature (7 existing call sites, 6 of them in `tests/compiler_test.go`, all left untouched). Top-level declarations are checked directly inside `mangleFileDecls` (already returns `error`, one new check added). Local bindings needed a different mechanism: none of `rename.go`'s traversal functions return `error` today, and restructuring all of them to do so (12 `scope.bind` call sites, several layers deep) was rejected as disproportionate to the actual need — instead, `lookupTable` gained `allowGlobalShadowing bool` and `reservedErr *error` fields, and a `checkBinding(name, pos)` method that records the *first* violation found (first-write-wins; the traversal always completes regardless of a violation, so no early-exit plumbing is needed) into a slot `resolver.go` checks once `renameFile` returns. Generic type parameters (`function f<Math>()`) are deliberately unchecked — `ast`'s `TypeParams []string` carries no position, and it's an extremely low-value edge case; noted, not fixed.

**Permissive-mode shadowing, codegen-side, Tier 1 only**: every Tier 1 dispatch site gained the same one-line guard `NaN`/`Infinity` already had — `!e.isShadowedByLocal(id.Name)` (a new `Emitter` method wrapping `e.lookup`) added to each `if id.Name == "X"` condition, or wrapping the outer `if id, ok := ...Identifier); ok {` for the two switch-shaped sites (`emit_exprs_types.go`'s property-read switch, `emit_call.go`'s bare-global-function switch) where multiple cases share one guard. **Provably safe regardless of mode**: under `strict`, no colliding local binding can ever exist (the resolver already guarantees it), so every one of these checks is a structural no-op there — it only ever changes behavior, and only ever needs to, under `-globals=permissive`. This is why the codegen change needed no `-globals` value threaded into `codegen/llvm` at all — `isShadowedByLocal` is unconditionally correct.

Tier 2 gets no codegen change under either mode — `strict` rejects the declaration at the resolver level (same validation pass as Tier 1), and `permissive` has nothing to lift, by decision.

## Implementation notes

- `resolver/reserved_names.go` (new): `reservedTier1`/`reservedTier2`/`checkReservedBinding`.
- `resolver/resolver.go`: `ResolveProgram` → thin wrapper; `ResolveProgramWithOptions` (new, the real implementation); `mangleFileDecls` gained an `allowGlobalShadowing` parameter and one check; the `renameFile` call site builds a `reservedErr` slot and checks it immediately after.
- `resolver/rename.go`: `lookupTable` gained `allowGlobalShadowing`/`reservedErr`; new `checkBinding` method; all 9 real binding sites (function/arrow params via `bindParams`, `VarDeclaration`, array/object destructuring, `for...of`/`for...in`, `catch` param) call it alongside their existing `scope.bind`. `bindParams` gained `lu lookupTable, pos ast.Pos` parameters (2 call sites updated) since `ast.Param` carries no position of its own.
- `codegen/llvm/emitter.go`: new `isShadowedByLocal(name string) bool` method.
- `codegen/llvm/emit_call.go` (14 sites + 1 switch wrap), `emit_exprs_member.go` (3 sites), `emit_exprs_types.go` (10 sites + 2 switch wraps), `emit_exprs_vardecl.go` (1 site), `emit_objects.go` (1 site), `emit_process.go` (1 site, `isProcessEnvExpr` converted from a free function to an `*Emitter` method since it now needs `e.isShadowedByLocal`, its 4 call sites updated) — 30 mechanical sites via a scripted regex substitution (verified by full diff review and the test suite, not trusted blind), plus 3 hand-edited switch-wrapping sites.
- `main.go`: `-globals` flag, validated against `strict|permissive` the same way `-mm` is validated; threaded into `resolver.ResolveProgramWithOptions`.
- `tests/compiler_test.go`: `resolveMultiFilePermissive`/`buildBinaryMultiFilePermissive`/`assertMultiFileOutputPermissive` added alongside the existing strict-only helpers, following the same additive-rather-than-modify-shared-helpers pattern [ADR-00141](ADR-00141.md) established.
- `tests/reserved_globals_test.go` (new): 10 tests (12 with subtests) covering strict rejection (top-level, parameter, destructuring, `for...of`), Tier 2's permanent rejection under both modes, permissive-mode shadowing (top-level, local — the direct regression case), and confirming ordinary unshadowed usage is unaffected under either mode.
- `examples/globals/reserved_globals.ts` (new): documents the feature via comments (a real, directly-verified command sequence and its exact output/error text — see Verification) rather than live shadowing code, since `make examples` always compiles with default flags and a real shadowing declaration would fail to compile under `strict` by design, breaking the example suite if included as live code.

## Side effects discovered

None beyond what was already known going in from [TDD-00049](../tdd/TDD-00049.md)'s own Open Questions (Category A/C's prior lack of protection) — this ADR is exactly that follow-up, not an incidental discovery.

## Verification

- `go build ./...`, `go vet ./...`, `go test ./...` all clean, including the pre-existing suite (zero changes needed to any pre-existing test or example — confirmed via the Investigation section's grep before implementation started, and by both `go test ./...` and `make examples` staying green afterward with no edits to unrelated files).
- `tests/reserved_globals_test.go`'s 10 tests (12 with subtests) pass.
- `make examples`: 99/99 passed (98 from [ADR-00142](ADR-00142.md) plus the new `reserved_globals.ts`).
- Manual verification (this session, Linux) of every command/output documented in `examples/globals/reserved_globals.ts`'s comments before publishing them — the permissive-mode shadow demo (prints `42`) and the strict-mode rejection's exact error text and line:col (`2:3`), both run directly against the built compiler rather than assumed from memory.
