# TDD-00248: The program unit carries only the program

- **Status**: In Progress
- **Date**: 2026-10-11

## Context

ADR-01323, ADR-01326, ADR-01329 and ADR-01478 made the builtin library
compile the same in every program, and cache each library module as an
object. The module units are still identical across programs: two http2
examples share 27 modules, all byte-identical, and `libdrift` reports 4 of
1,544 library functions differing.

The program's own unit is what grew. `libOwner` gives every generated
`__` name to the program. That covers:

- the library's function literals;
- the shape rows of every layout the program boxes into `any`
  (`__kml_shape_get_<id>`, `__kml_shape_set_<id>`, the method adapters);
- the host inspect routines at every depth;
- the conversions out of `any` (`__kml_any_to_layout.<id>`);
- the record views.

When ADR-01329 landed this was small. The port of Node's modules to
TypeScript (TDD-00231) then multiplied the library's literals and the
library types that reach `any`.

An http2 example's program unit is now about 30 MB of the IR's 55 MB.
Every compile runs `clang -O2` over it: 11 to 14 seconds on the Mac,
whatever is cached. Under the conformance runners' parallel load it passes
the 30-second clang timeout, so about 80 http2 node-suite tests fail as
CLANG_TIMEOUT. Every helper in that unit has a library-stable id (the
`kmlStableIDBase` range); the program in question defines no class of its
own.

## Design

**Stage 1. Library function literals belong to their module.** A literal
of library code is named by its position (`literalSymbol`:
`__closure.<module>.<line>_<col>`). It is emitted with the function that
holds it, so `libOwner` gives `__closure`, `__generator_body`,
`__generator_method` and `__kml_dynfn` names carrying a library module key
to that module. This alone takes the http2 example's program unit from
29.8 MB to 26.6 MB, and the module units stay identical across programs.

**Stage 2. A library module emits the dynamic surface of its own types.**
For every library class and host layout a module defines, the module
always emits that type's dynamic helpers, in its own unit:

- the shape row (getter, setter, keys, method adapters);
- the inspect routines;
- the conversion out of `any`.

The module registers each row through `unitreg`'s per-unit tables
(`@__kml_unit_register`), so the program's `emitShapeFinalize` no longer
lists library rows. The set no longer depends on what the program boxes,
so the module's text, and its cached object, are the same in every
program. A layout built over a program type (a generic instantiation, an
object literal holding a user class) keeps its program-numbered id and its
row in the program unit, as now.

Library layouts that are not class or host layouts (an object literal type
inside library code) are named by `stableTypeID("L"+key)`. Their rows go
to the module whose code allocates them. A layout two modules both
allocate is emitted `linkonce_odr` by both, under its id's name.

Stage 2 as built (ADR-01579) is simpler than described above. Each helper
generated for a library-stable id goes to a unit of its own (`stb_<id>`),
and each dynamic property helper to a per-name unit, cached by text. A
module does not have to emit helpers its program never uses. The http2
example's program unit is 3.1 MB.

**Stage 3. A size budget.** A test compiles an http2 example and fails if
its program unit exceeds a fixed budget, so the growth cannot return
unnoticed. `libdrift` also reports the program unit's size.

**Stage 4. Prebuilt library objects.** The module objects for the release
hosts (linux-x64, linux-arm64, darwin-arm64) are built with the compiler
and embedded next to the library's TypeScript source. A native build seeds
the cache from them. A cross build (`--target`, e.g. Sailfish) or another
host compiles from the source once and caches the result, as now. The
source stays embedded: the checker reads the library's declarations for
every program.
