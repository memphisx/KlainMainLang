# ADR-00224: Type-directed JSON projection off the parse tree (P3) — nested objects, array fields, top-level `T[]`

- **Relations**: `Implements TDD-00077` (Track P, P3); `Extends ADR-00223`; `Supersedes ADR-00007`, `ADR-00189`, `ADR-00166`
- **Date**: 2026-08-18

## Context

P1 ([ADR-00223](ADR-00223.md)) built a validating JSON parser producing a tagged value tree, but still projected onto the target type with the old lenient `strstr` extractor — so it parsed the document twice and kept every extractor limitation: nested object fields, array-typed fields, object-array fields, and top-level `JSON.parse` → `T[]` were all rejected or unimplemented, and a `float64`/`float32`-typed top-level variable was a hard compile failure ([ADR-00166](ADR-00166.md)). P3 replaces the extractor with a type-directed walk of the tree, closing that whole cluster in one path — the payoff [TDD-00077](../tdd/TDD-00077.md) was built toward.

## Investigation

- The tree already carries everything projection needs (P1): object nodes with `(key, value)` pairs, array nodes with items, numbers with a raw lexeme (for exact large-integer projection), decoded strings. It just needed accessors and a consumer.
- Array *values* in this compiler are `{ptr,i64}` aggregates built as `malloc(n*elemTy.Align())` + per-slot `getelementptr elemTy.IR` + `storeArrayElem` (which boxes nested-array elements), then `insertvalue {ptr,i64}` (`emit_arrays_core.go`, TDD-00028/TDD-00029). Projection reuses exactly this so a projected array is indistinguishable from a literal.
- A nested object/array projection emits its own control flow (loops, branches), so the per-field found/missing merge can't use a `phi` (its predecessor wouldn't be the branch label). Storing the projected value **directly into the result struct's field GEP in each branch** sidesteps the predecessor problem entirely.
- A projected value must outlive the tree (freed right after projection): strings are copied out via `__kml_json_string_dup`; numbers/booleans are by value; structs/arrays are fresh mallocs holding only copied-out scalars/strings. So `__kml_json_free` after projection cannot dangle — confirmed under ASan.
- The array *var-decl* path (`emitArrayVarDecl`) has its own initializer dispatch and called `JSON.parse` through the generic, type-context-free `emitExpr` path (`emit_call.go:79` passes `TypePtr`), so `const xs: T[] = JSON.parse(...)` failed with "array variable must be initialized with an array expression". It needed the same JSON.parse type-context branch the scalar/object var-decl already had.

## Decision

Add `emitJSONProject(node, targetTy)` (`emit_json_project.go`): a type-directed dispatch —
- **object/interface** → fresh struct; per field, `__kml_json_get(node, key)` then project the field type (or a type-appropriate default when the key is absent), storing directly into the field slot per branch; a nullable-scalar field boxes present/absent by whether the value node is `null`. **Nested objects fall out.**
- **array `T[]`** → a runtime-length buffer with each element projected as `T` (`__kml_json_item`), returned as the standard `{ptr,i64}` aggregate. **Array fields, object-array fields (`Item[]`), nested arrays (`T[][]`), and top-level `T[]` all fall out.**
- **scalars** → `i1` via `__kml_json_bool`; float via `strtod(lexeme)` (**fixes the float-variable compile bug**); integer via `atoll(lexeme)` + `coerce`; string via `__kml_json_string_dup`.
- **class / `any` / tuple targets** → clean rejections (`any` is P4).

`emitJSONParseValue` now parses into a validated tree, projects, then frees it — retiring the double parse. Added the JSON.parse type-context branch to `emitArrayVarDecl`. Added the C tree accessors (`__kml_json_kind`/`_bool`/`_num_lexeme`/`_len`/`_item`/`_string_dup`/`_get`) and their declarations. Deleted the now-dead extractor path: `emitJSONParseObject`, `emitJSONParseFieldValue`, and the `__kml_json_find_value`/`__kml_json_parse_str`/`__kml_json_parse_field_str` runtime helpers.

This supersedes [ADR-00007](ADR-00007.md) (flat extraction), [ADR-00189](ADR-00189.md) (array-field rejection — now supported), and [ADR-00166](ADR-00166.md) (float-target compile bug — now projected).

## Implementation notes

- `__kml_json_string_dup` returns an owned copy; every other projected scalar is by value — this is what makes the post-projection `__kml_json_free` safe.
- Object-field stores go straight to the field GEP in both the found and missing branches (no phi), because a nested projection introduces intermediate blocks.
- `emitArrayVarDecl` gained a `JSON.parse` branch mirroring `emit_exprs_vardecl.go`'s scalar/object one; a bare reassignment `xs = JSON.parse(...)` still lacks type context (a pre-existing limitation of the generic expression path, unchanged).
- `TestE2EJSONParseArrayFieldRejected` flipped to `TestE2EJSONParseArrayField` (now asserts it parses).
