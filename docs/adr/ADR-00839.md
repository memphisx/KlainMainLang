# ADR-00839: `Number(undefined)` is `NaN` (not `0`)

- **Relations**: Extends [ADR-00291](ADR-00291.md) (`String`/`Number`/`Boolean` conversions)
- **Date**: 2026-09-10

## Context

`Number(undefined)` returned `0`, where JS returns `NaN`. `Number(null)` is
correctly `0`. The two share the `NullLiteral` AST node (distinguished by
`IsUndefined`), and `emitGlobalNumberConv` handled both with a single `return 0`.

## Decision

In `emitGlobalNumberConv`, split the `NullLiteral` case on `IsUndefined`:
`undefined` → the NaN double (`0x7FF8000000000000`), `null` → `0` (unchanged).

## Implementation notes

`emit_call_number.go`, one branch. Scoped to the literal `Number(undefined)`; a
runtime `T | undefined` value that is `undefined` isn't covered here (rare).

## Verification

macOS (Apple Silicon M4): `Number(undefined)` → `NaN`, `Number(null)` → `0`,
`Number("42")` → `42`, `Number(true)` → `1`. Updated
`TestE2EGlobalConversionFunctions`; number/conversion suites green.
