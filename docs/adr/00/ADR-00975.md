# ADR-00975: Reference-keyed Map `.get()` miss with a pointer value reads a real `undefined`

- **Relations**: `Extends ADR-00948` (reference-type Map keys via the any-keyed runtime)
- **Date**: 2026-09-16

## Context

Surfaced during a documentation-staleness audit of `docs/status/`. A Map keyed by
an object or array (ADR-00948) rides the any-keyed runtime. `.get()` on such a map
whose **value** type is a concrete pointer (`string`, an object, an array) returned
a bad result on a *miss*: `map.get(absentKey) === undefined` evaluated to `false`,
and *using* the missed value crashed.

Repro (macOS arm64 / M4):

```ts
const m = new Map<number[], string>()
m.set([1], "x")
console.log(m.get([2]) === undefined)   // printed `false` (should be `true`)
console.log("v:[" + (m.get([2]) ?? "N") + "]")  // segfault (exit 139)
```

A scalar value (`Map<T[], number>`) already missed correctly — its `.get()` goes
through the presence-flagged nullable-scalar path (`emitMapGetNullable`, gated on
`has()`), which never touches the raw miss word.

## Investigation

`codegen/llvm/emit_collections.go`:

- `mapRuntime` (line 27) routes an object/array key to the `"any"` runtime
  (`isReferenceKeyTy`, ADR-00948).
- The any-keyed runtime stores concrete values **raw** in its i64 slot (so a
  string/object value round-trips on a *hit* via `inttoptr`), but its
  `__kml_map_any_get` returns the boxed `undefined` **sentinel** on a miss — a
  nonzero NaN-box pattern, not `0`.
- In the get case (line 491) a concrete pointer/array value takes the raw path:
  `raw = call __kml_map_any_get(...)` then `mapValFromI64(raw, valTy)`. The
  downstream null-pointer-miss marking (line 499, `mapGetUndefinedablePtr`) and
  `mapValFromI64`'s null-header guard (line 1097) both assume the miss word is
  `0`. For the any runtime it is the undefined box, so `inttoptr <box>` yielded a
  garbage pointer — wrong `=== undefined`, crash on deref.

The str/num runtimes don't hit this: they return `0` on a miss, so the existing
machinery already produces a clean null.

Alternative rejected: widening a reference-keyed map's **value** type to `any`
(as dynamic-keyed maps do via `forceAnyMapVal`). It fixes the miss but makes a
concrete object value read back as a NaN-boxed `any`, and a boxed static-object
value hits the type-erasure boundary — `(m.get(key) as O).x` fails with "field
access on non-object", so typed field access on a hit would break. Preserving the
concrete value type is the faithful choice.

## Decision

In the get case, for the `"any"` suffix with a **non-dynamic** value type, gate
the raw get on `has()` and substitute `0` on a miss:

```
present = call i1 @__kml_map_any_has(...)
gated   = select i1 present, i64 raw, i64 0
```

`mapValFromI64` then rebuilds a null pointer / `{null,0}` array header on a miss,
and the existing `V | undefined` marking makes `=== undefined` true and use safe.
A dynamic (`any`) value is deliberately skipped — its slot is meant to read back
as the box, undefined sentinel included.

## Implementation notes

- `codegen/llvm/emit_collections.go`, get case: added the `suffix == "any" &&
  !valTy.IsDynamic` has-gate before `mapValFromI64`.
- `forceAnyMapVal`'s comment updated to record that a reference key keeps its
  value type concrete (only the miss needs handling), distinguishing it from the
  dynamic-key case it still widens.
- Ordering: the gate must precede `mapValFromI64` so the null-header/null-pointer
  guards see `0`.

## Side effects discovered

None beyond the fixed bug. The scalar-value and dynamic-value paths are
untouched; existing reference-keyed Map/Set tests continue to pass. The mixed-type
ternary invalid-IR case seen while writing the repro (`typeof addr === 'object' &&
addr ? addr.port : addr`) is a separate, pre-existing item in the invalid-IR
backlog and is not addressed here.

## Verification

- `TestE2EMapReferenceKeyPointerValueMiss` added (string value + object value:
  hit reads the concrete value with no cast, miss reads `undefined`, use of a miss
  does not crash).
- `go test ./tests -run 'TestE2EMap|TestE2ESet|TestE2EWeakMap'` — green.
- Manual repros above now print `true` / `v:[N]` / `42` and exit 0.
- Machine: macOS arm64 (M4).
