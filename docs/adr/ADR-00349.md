# ADR-00349: `WeakMap` / `WeakSet` / `WeakRef` — mode-dependent weak collections

- **Relations**: Implements [TDD-00112](../tdd/TDD-00112.md)
- **Date**: 2026-08-24

## Context

`WeakMap`/`WeakSet`/`WeakRef` were the last ❌ collection rows on
[OBJECT-COLLECTIONS.md](../status/OBJECT-COLLECTIONS.md) (`Object.create` stays
out of scope — its core is the prototype model, [TDD-00068](../tdd/TDD-00068.md)).
Their defining feature — a referent that does not keep the object alive —
depends on the memory mode, so the design forks on `-mm` (scoped in
[TDD-00112](../tdd/TDD-00112.md)).

## Decision

All three key on **object-pointer identity** (a non-object/primitive key is a
clean compile error) and are **non-iterable** (no `size`/`keys`/`values`/
`entries`/`forEach` — matching the spec exactly). Surface: `WeakMap.set/get/
has/delete`, `WeakSet.add/has/delete`, `WeakRef` + `deref()`.

One runtime interface, two backings, chosen at emit time by `e.isGCMode()`
(runtime_weak.go, the runtime_chan.go pattern):

- **`-mm=manual`** (default): a weak reference is indistinguishable from a strong
  one — nothing is ever collected ("leak by design"), so `.deref()` never nulls
  and keys persist. Cells are plain `malloc`'d; no link registration.
- **`-mm=gc`** (Boehm): genuinely weak via
  `GC_general_register_disappearing_link`.

**Layout.** A weak map/set is a head box → singly linked list of cells
`{ next; link; val }` (24 B, scanned). `next` keeps the list alive; `val` is the
WeakMap value; `link` points to a separate **one-word link cell** holding the
referent. WeakRef is a bare link cell. `deref`/lookup read `*linkcell`; a
collected referent reads back NULL.

**The crux (found the hard way — see Side effects).** Under gc the link cell is
`GC_malloc_atomic`'d — an **unscanned** allocation — and registered as a
disappearing link. Boehm traces a normal (scanned) `GC_malloc`'d object's words
as potential pointers, so a referent stored in scanned memory is kept alive and
the link never fires. Putting only the referent word in unscanned memory makes
the disappearing link the sole reference mechanism, so Boehm nulls it on
collection. The cell's `next`/`val` stay in scanned memory (list liveness), which
is why the referent word is a *separate* atomic allocation, not an atomic cell.

A linked list (not a growable array) keeps every link cell's address stable,
which the by-address disappearing-link registration requires.

**`gc()` global.** Added the Node `--expose-gc` `gc()` idiom — a forced full
`GC_gcollect()` under gc, a no-op under manual. It makes weak reclamation
deterministically observable (and testable), and is a genuine GC-mode utility.

## Implementation notes

- New AST nodes (`NewWeakMap/WeakSet/WeakRefExpression`), parser bodies, resolver
  rename cases, and `Type.Weak`/`IsWeakRef` flags + `WeakMapType`/`WeakSetType`/
  `WeakRefType` constructors. Both the `new`-form and the `: WeakMap<K,V>`
  type-annotation form resolve (the annotation path was needed to return a weak
  handle from a function).
- Reserved as Tier-2 built-in names (never shadowable — parser-committed).
- Top-level weak bindings promote to module globals (reliableGlobalType) so a
  named `function` can see them.
- Dispatch (emit_call.go) checks WeakRef then Weak-flagged Map/Set *before* the
  plain Map/Set branch, since WeakMap/WeakSet also carry IsMap/IsSet.
- `WeakMap.get` returns `V | null` for a scalar value (a real absence vs a stored
  0/false), the same nullable-scalar representation `Map.get` uses.

## Side effects discovered

- **Boehm disappearing links need the referent in unscanned memory** — a
  standalone C repro (GC_malloc box → link never cleared; GC_malloc_atomic box →
  cleared) pinned this before the runtime was finalized. Documented above.
- **`-mm=gc` collection crash on class-instance churn** — surfaced here (churning
  class instances crashed on Boehm's first collection), root-caused to the
  thread-local, Boehm-unscanned frozen set, and **fixed in
  [ADR-00350](ADR-00350.md)**. The weak tests use object-literal referents,
  independent of that path either way.

## Verification

- E2E `tests/collections_test.go` (manual mode): WeakMap set/get/has/delete,
  WeakSet add/has/delete, WeakRef deref, primitive-key rejection.
- E2E `tests/memory_gc_test.go` (`-mm=gc`, skipped when libgc/clang absent):
  a referent created in a helper (so its pointer leaves the stack) is collected
  after `gc()` — `deref()` → null, `WeakMap.has` → false — while a kept referent
  survives. This exercises the disappearing-link path end to end.
- `examples/weak/weak.ts`; `make examples`; `make conformance`.
- Machine: manual + gc verified on Mac (arm64), Homebrew `bdw-gc`. The gc weak
  path uses object-literal referents and passes on Mac; re-verify on Linux via
  Docker when convenient (the unrelated class-churn crash it shared a harness
  with is now fixed — [ADR-00350](ADR-00350.md)).
