# ADR-01826: Strings index by UTF-16 code units

- **Relations**: `Implements TDD-00230` (phase 5's string encoding bit), supersedes the byte-index model of ADR-00028
- **Date**: 2026-10-20

## Context

- A string is a length-headered UTF-8 buffer. Every position and length JavaScript exposes was a byte count: `'café'.length` was 5, `s[3]` read half of `é`, and `indexOf`/`slice`/`padEnd`/`charCodeAt`/`codePointAt` all diverged from Node on non-ASCII text.
- The default regex mode reported byte offsets so that they matched this string layer.
- `String.fromCharCode` wrote a lone surrogate as its own three bytes, so two halves concatenated did not form the pair's character.

## Decision

- **Storage stays UTF-8.** A lone surrogate is its three-byte form (WTF-8, `ED A0..BF xx`). A pair is always the four-byte character: concatenation (`+`, template literals) and `join` merge a high half ending one side with a low half starting the other, so equal text is equal bytes.
- **The header caches the UTF-16 length.** The word before the bytes holds the byte length in bits 0..31 and the unit count plus one in bits 33..62 once counted (`kml_heap.h`).
  - A producer still writes the bare byte length. Every reader masks (`KML_STR_LEN`, `__kml_str_len`).
  - Bit 32 stays clear, so a counted header can never read as an object header's magic (`0x4B4D` in bits 32..46 is odd).
  - A read-only string carries its count from the start: the compiler's string constants (`strHeaderWord`), and C literals through `KML_STR_ASCII_HDR`.
- **ASCII is free, other text walks.** A string whose unit count equals its byte count is ASCII, and its byte offsets are its indices. Other text converts at the C boundary (`__kml_u16_off`, `__kml_u16_index`, `__kml_u16_sub`, strheader.c).
  - A walk resumes from the last position this thread found in the same string, so a front-to-back loop over `s[i]` stays linear.
  - Counting a new string's length drops the remembered position, so a string at a reused address never uses a stale one.
- **What indexes by units:** `length`, `s[i]` (undefined past the end), `charAt`, `charCodeAt`, `codePointAt`, `at`, `slice`, `substring`, `substr`, `indexOf`, `lastIndexOf`, `includes`, `startsWith`, `endsWith`, `padStart`/`padEnd`, `split('')`, `replaceAll('', …)`, a replacer's `offset`, `Object.keys`/`values`/`entries` and `for…in` over a string, and the same reads through `any`.
  - A bound inside a pair keeps that half as a lone surrogate.
  - The default regex mode (`ecmascript`) reports UTF-16 offsets, as `es-utf16` did.
- **Output encodes UTF-8:** console writes, `process.stdout.write` and `Buffer.from(s)` turn a lone surrogate into U+FFFD. `JSON.stringify` writes it as `\udXXX`, and inspect as `'\udXXX'`.
- An empty search with a function replacer calls it at every position (`replaceAll`) or at 0 (`replace`), as Node does.

## Consequences

- `TestE2EStringUTF16Indexing` covers indexing, slicing, search, regex offsets, surrogate halves, output, keys and `any`. `examples/strings/utf16_indexing.ts` shows it.
- A regex without the `u` flag still matches by code point (PCRE2 matches UTF-8): `.` takes a whole astral character, and an empty match never falls between a pair's halves.
- Indexing into non-ASCII text that is not read in order costs a walk from the start.
