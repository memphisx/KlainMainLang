# ADR-00388: Ambient declarations (`declare`), parsed and erased

- **Date**: 2026-08-27

## Context

A `declare` ambient declaration (`declare const X: T;`, `declare function f(): T;`,
`declare global { … }`, `declare module "m" { … }`, `declare namespace N { … }`)
was a hard parse error — `declare const VERSION: string;` tripped the ordinary
const parser's "must be initialized" rule. Ambient declarations are common in
`.d.ts`-style code and ambient-global augmentation, and a single one failed the
whole file at parse.

## Decision

Parse `declare` as a statement-initial contextual keyword and **erase** it. TS
ambient declarations describe types the surrounding environment provides — they
carry no implementation — so this compiler emits no storage or code for them.
`parseAmbientDeclaration` consumes the declaration's tokens by balance: a
brace-bodied form (`global`/`module`/`namespace`/`class`/`interface`/`enum`) is
its `{ … }` block; a valueless `const`/`let`/`var` or bodiless `function`/`type`
ends at a `;` or a line break (ASI). The result is an empty statement.

## Implementation notes

- Added in `parser/parser_stmts.go`: a `case "declare"` in the statement-initial
  contextual-keyword switch, plus `parseAmbientDeclaration`.
- A runtime *use* of a declared binding this compiler doesn't itself provide
  surfaces as an ordinary `undefined variable` error — honest, since nothing was
  emitted for it. Where the compiler already provides the name ambiently
  (`process`, etc.), that resolution is unaffected (the `declare` is erased, not
  a competing binding).
- The ASI heuristic ends a non-brace declaration at the next line break once
  outside any brace body; a body brace opening on its own line is not mistaken
  for the end.

## Side effects discovered

None. `declare` is purely additive at the front end — no codegen path changes.
