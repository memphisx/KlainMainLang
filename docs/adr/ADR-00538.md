# ADR-00538: `cond ? scalar : null` produces a nullable-scalar aggregate

- **Relations**: Extends ADR-00537; Implements TDD-00064
- **Date**: 2026-08-31

## Context

A ternary mixing a non-pointer scalar and `null` — `b ? 3 : null` — collapsed
`null` to a payload zero instead of producing a `number | null`. This was the
root of the "nullable-scalar call return loses its presence bit" gap noted in
ADR-00537: a function `return b ? 3 : null` returned a bare `0`, so `get() ?? -1`
gave `0`, `"x" + get()` gave `"x0"`, and `get() === null` was unreliable — all
downstream of the ternary, not the return. Separate `if (b) return 3; return
null;` already worked, which localized the bug to the conditional expression.

## Investigation

`emitConditional` (`emit_exprs_operators.go`) inferred the result type from the
*consequent* alone (`3` → double), allocated a bare `double` slot, and coerced
both branches into it — so the `null` alternate became `0`. Two further sites
inferred the same consequent-only type: `inferExprType`'s `ConditionalExpression`
case, and `emitVarDecl`'s unannotated-declaration inference (which additionally
had no `ConditionalExpression` case at all, and whose call-result branch did not
preserve a nullable-scalar return type — so `const a = get(false)` also dropped
null-ness).

## Decision

1. `ternaryNullableScalarType(a, b)`: when exactly one branch is `null` and the
   other a non-pointer scalar, the result is that scalar made `Nullable`.
2. `emitConditional` dispatches such a ternary to `emitConditionalNullableScalar`,
   which boxes each branch via `emitNullableScalarBoxedValue` (null → absent,
   scalar → present) into the `{ i1, T }` aggregate through the same
   store/load-via-alloca shape the plain ternary uses.
3. `inferExprType`'s `ConditionalExpression` case returns the same nullable-scalar
   type, so an unannotated binding gets the aggregate storage.
4. `emitVarDecl`'s unannotated inference gains a `ConditionalExpression` case and
   preserves `isNullableScalar` return types from a call (and closure call).

A ptr-typed branch (`string`/object/array `| null`) is untouched — it keeps its
existing null-pointer representation.

## Implementation notes

`emit_exprs_operators.go` (helper + dispatch + the aggregate ternary),
`emit_exprs_types.go` (inference), `emit_exprs_vardecl.go` (unannotated
inference: the new `ConditionalExpression` case + `isNullableScalar` in the
call-return-type lists).

## Side effects discovered

Fixing the unannotated-declaration inference also fixed an unrelated
pre-existing bug: `const s = cond ? "a" : "b"` (a string-valued ternary with no
annotation) previously fell through to the blind `i64` default; it now infers
the branch type correctly. Resolves the deferred call-return item in ADR-00537
end to end.

## Verification

`TestE2ETernaryNullableScalar` (new): both ternary directions, a
function-returned `b ? 3 : null` through `??`/concat/`=== null`, unannotated and
annotated locals, and a string ternary — all cross-checked against real Node.
Full suite green. Verified on Mac (Apple Silicon).
