# ADR-01879: Import types; process stdio typed as tsc types it

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's MemberExpression bucket)
- **Date**: 2026-10-21

## Context

- lib's `process.stdout`/`stderr`/`stdin` are typed `WriteStream & { fd: 1 }` (and so on), where `WriteStream` is `import("tty").WriteStream & { … }`, as @types/node declares them. The checker did not resolve import types, and its intersection typing gave up on a class instance part, so every stdio read was unanswered: the strict lane checked nothing on it (`process.stdout.fd = 3`, `process.stdout.write(5)`), and the shadow report counted each read.
- The streams are typed tty's at any descriptor, while at run time a pipe's is a net.Socket and a file's a sync write stream, without `isTTY` or `columns` (`typeof process.stdout.isTTY` is `"undefined"` under a pipe in Node). Codegen reads a box's member as the checker's primitive, and narrows a boxed binding to the checker's class.
- net.Socket's `write` took `any`; @types/node declares `Uint8Array | string` overloads.

## Decision

- The checker resolves `import("mod").A.B<T>` for a builtin module the program includes, through the merged names the resolver records (`LibExports`).
- An intersection of one class instance with object literals is the instance with each redeclared property narrowed and each added one appended (refinedInstance).
- A stdio stream, a binding of one or of its member, and the stream's members read as the box: checkerPrimitive and checkerNarrowed leave them, and the shadow oracle answers them so (hook `stdio`).
- net.Socket's `write` declares @types/node's two overloads.

## Consequences

- `TestE2EProcessStdioImportTypes` covers the two tsc rejections and the run-time reads; `TestE2EProcessStdioIsTTY` keeps passing.
- Verified on Apple Silicon.
