# ADR-00235: EventTarget bus (Events & Cancellation, stage 2)

- **Relations**: `Implements TDD-00081` (Stage 2); `Extends ADR-00234`
- **Date**: 2026-08-19

## Context

Stage 2 of the WHATWG event work ([TDD-00081](../tdd/TDD-00081.md)): the
`EventTarget` bus — `new EventTarget()` + `addEventListener`/
`removeEventListener`/`dispatchEvent` — that actually fires the `Event`/
`CustomEvent` objects from Stage 1.

## Decision

An `EventTarget` is a bare `Map<string, listener-list>` pointer — the exact
registry EventEmitter uses — tagged `IsEventTarget`. This lets add/remove reuse
`emitEventEmitterGetOrCreateList` / `eventEmitterListPtr` + the `__kml_ee_list_*`
helpers verbatim, and `dispatchEvent` reuse EventEmitter's snapshot-copy-then-
invoke loop.

- **`addEventListener(type, cb, opts?)`** — get-or-create the per-type list and
  `__kml_ee_list_push(list, cb, once)`. `{ once: true }` is honored; `capture`/
  `passive`/`signal` are accepted no-ops. Listeners resolve through a dedicated
  `resolveEventTargetListenerArg` that hints the `Event` type onto an untyped
  param and requires the single event parameter, but — unlike EventEmitter's
  resolver — does **not** require a void return (a WHATWG listener's return value
  is ignored).
- **`removeEventListener(type, cb)`** — `__kml_ee_list_remove`, matching by
  closure header identity.
- **`dispatchEvent(event)`** — read `event.type` off the object, snapshot its
  listener list, invoke each listener with the *event object*
  (`emitCBCall`, `FuncType([eventTy], void)`), honoring `once` (removed after) and
  `stopImmediatePropagation` (the loop checks the event's internal stop flag each
  iteration). Returns `!event.defaultPrevented`.

`EventTarget` also resolves as a type name, and construction routes through
`emit_exprs.go` + the var-decl fast-path.

## Implementation notes

`inferExprType` gained the return types for the new method surface —
`dispatchEvent`→bool, `addEventListener`/`removeEventListener`→void, and (found
via the example) the `Event` methods `preventDefault`/`stop*`→void. Without the
last, an expression-body arrow `(e) => e.preventDefault()` inferred the i64
default and emitted a malformed `ret i64` with no operand.

## Side effects discovered

- **Single-target dispatch only** — no DOM tree, so no capture/bubble/propagation
  path (`stopPropagation` stays a no-op).
- **`removeEventListener` matches by closure identity** — a listener held in a
  named binding removes correctly, but an inline arrow re-emitted at the remove
  site is a different closure and won't match (same as EventEmitter). A V1-scoped
  0-argument listener is rejected (the event parameter is required).
- No `class X extends EventTarget` (built-in `extends` targets are rejected).

## Verification

- `tests/eventtarget_test.go`: dispatch (multiple fires), CustomEvent detail to a
  listener, removeEventListener, `{ once: true }`, `dispatchEvent` return value
  after `preventDefault`, and `stopImmediatePropagation` halting the rest. All
  pass.
- `examples/events/eventtarget.ts` runs correctly; IR verified with `clang`.
- `go build`, `go vet ./...`, and the event/emitter/arrow/closure subset are green
  on Apple Silicon (macOS).
