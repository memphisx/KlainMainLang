# ADR-00414: http2 module Stage 1 — resolution, server handle, compat API

- **Relations**: Implements [TDD-00139](../tdd/TDD-00139.md) Stage 1; Extends [ADR-00406](ADR-00406.md), [ADR-00357](ADR-00357.md)
- **Date**: 2026-08-27

## Context

TDD-00139 scoped the explicit `http2` module — the largest Node-oracle block
(237 files). Stage 1 is the high-leverage cheap slice: make the module
resolve, give `http2.createServer` the real handle surface, and route the
compat `(req, res)` API through machinery that already exists.

## Decision

- `http2` resolves as a builtin (`http2__kml_builtin`) with the member table
  from the TDD's histogram.
- `http2.createServer(handler?)` **is** the http server core: it returns the
  same variable-bound handle (`HTTPServerType`), inheriting
  `.listen(port?, cb?)`/`.close()`/`.address()`/`.on('request', …)`, the
  contextual `(req, res)` typing through `mustCall` wrappers, and — the crux —
  the h2c support the transparent-h2 work already built (ADR-00357): the
  accept path detects the HTTP/2 preface per connection and drives the
  nghttp2 session, so an `http2.createServer` server genuinely speaks
  HTTP/2 to an h2c client with zero new runtime code. (It also still answers
  HTTP/1.1 — a superset of Node's `http2.createServer`, disclosed as a
  caveat rather than hidden.)
- Clean rejections, each naming its missing piece: `createSecureServer` (no
  TLS server mode — never silently cleartext under a secure name),
  `connect` (client session driver is Stage 3), the settings helpers, and
  `constants`.
- The Node oracle's supported-module set includes `http2`, so the 237
  formerly `MODULE_NOT_IMPLEMENTED` files are now attempted and fail (or
  pass) on their real per-API surface.

## Implementation notes

`resolver/virtual_modules.go`, `codegen/llvm/emit_call.go` (dispatch),
`emit_exprs_types.go` (createServer → server-handle type),
`tools/conformance/node.go` (supported set). No new runtime: `usedHTTP2` was
already set by the server core, so nghttp2 links exactly as before.

## Side effects discovered

- The corpus's dominant `server.on('stream', …)` form now fails on the
  existing "supports only .on('request')" rejection — the honest next
  blocker, which is exactly Stage 2's scope.

## Verification

- New E2E tests: `TestE2EHTTP2ModuleCreateServer` (curl
  `--http2-prior-knowledge` → `http_version=2` response through the module
  handle) and `TestE2EHTTP2SecureServerRejected` — both pass (Mac).
- New example `examples/http2/module_server.ts` compiled and run.
- Node oracle re-run after the change (regenerated results).
