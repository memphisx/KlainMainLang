# ADR-02013: Any heritage expression, `extends null`

- **Date**: 2026-11-21

## Context

- The parser took `extends` followed by a name, a qualified name or a call
  only. `extends null`, `extends (a, B)` and other LeftHandSideExpressions
  were parse errors.
- A class *expression* whose heritage is a call (`var K = class extends
  f() {}`) built a class without that base, at HEAD too: its instances had
  none of the base's methods. Only class declarations bound the call's
  value.
- A value heritage of null threw "Class extends value null is not a
  constructor or null".

## Decision

- Any heritage other than a name is parsed as a LeftHandSideExpression and
  bound to a constant before the class (`ast.LowerBaseCalls`), as a call
  already was.
- A class expression's heritage expression is bound before its statement
  when the expression initializes a variable (so it keeps the binding's
  name). Otherwise it is assigned to a variable of its own, in a sequence,
  where the expression is evaluated.
- A hoisted class expression with a value heritage evaluates the heritage
  at its own site, not where the hoisted class is declared.
- `extends null` follows ClassDefinitionEvaluation: the prototype's
  [[Prototype]] is null, the constructor's is Function.prototype, and
  `new` of a class without a constructor of its own throws.
