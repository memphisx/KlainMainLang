# ADR-00341: `Blob.stream()` — a ReadableStream over a blob's bytes

- **Relations**: Extends ADR-00314 (Blob), TDD-00097 (Streams)
- **Date**: 2026-08-24

## Context

`Blob` shipped with `.text()`/`.arrayBuffer()`/`.bytes()` (ADR-00314) but not
`.stream()`, the last ❌ on [STREAMS.md](../status/STREAMS.md). `.stream()`
returns a `ReadableStream<Uint8Array>` over the blob's bytes — the bridge from
the Blob surface into the Streams surface both of which already exist here.

## Decision

`blob.stream()` builds a closed, pre-filled `ReadableStream` whose chunk type is
`Uint8Array` — the exact shape `ReadableStream.from(array)` already produces,
reusing `__kml_rs_alloc`/`__kml_rs_enqueue`/`__kml_rs_close` and the
`streamChunkWords` packing. The blob's bytes are enqueued as a **single**
owned-copy `Uint8Array` chunk, then the stream is closed. An empty blob enqueues
nothing (the enqueue is guarded on `size > 0`), matching WHATWG's "no chunk for
an empty blob."

V1 emits one whole-blob chunk rather than incrementally chunking the byte source
(a real byte-stream would hand out fixed-size pieces). That is a documented
caveat, not a behavioral bug for a consumer that reads to end via `for await` or
`.getReader()`.

## Implementation notes

- `emit_blob.go`: a `stream` case in `emitBlobCall` — alloc, a `size > 0`-guarded
  enqueue of the `{copy, size}` Uint8Array chunk, then close; returns
  `ReadableStreamType(TypedArrayType("uint8"))`.
- `emit_call.go`: the Blob method dispatch now routes `stream` to `emitBlobCall`
  (it was previously an explicit "not supported" rejection).
- `emit_exprs_types.go`: `blob.stream()` infers `ReadableStream<Uint8Array>`, so
  `for await` and `.getReader()` see the right chunk type.

## Verification

- `tests/blob_test.go`: `for await` over a multi-part blob (one chunk, 21 bytes),
  the `.getReader()` read→done sequence, and an empty blob (zero chunks).
- `go build` / `go vet` clean.
- Machine: verified on Mac (arm64); platform-independent (pure IR over the
  existing stream runtime).
