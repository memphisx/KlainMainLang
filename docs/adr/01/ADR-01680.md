# ADR-01680: libcurl waits in libcurl; the dead post-loop flush goes

- **Relations**: Implements TDD-00244
- **Date**: 2026-10-17

## Context

TDD-00244 Stage 3 drives libcurl through its socket API, and every synchronous curl drive goes. Three leftovers remained:
- `drive_once` (`fetchsrc/fetch.c`), the wait outside the event loop, built a `pollfd` array from libcurl's reported sockets and called `poll(2)`. On Windows that went through a `WSAPoll` shim (`__kml_win_poll_sockets`).
- `__kml_fetch_pump`, the drive after a paused response body resumes, ran that wait too.
- `@__kml_httpc_flush` was IR text that pumped libcurl after the event loop returned, behind `@__kml_httpc_flush_hook`.

## Investigation

- `grep` found no store into `@__kml_httpc_flush_hook`. The hook was always null, and the flush and both call sites (`emit_http.go`, `emitter.go`) were dead code. Since [ADR-01672](ADR-01672.md), a referenced handle holds the loop while a transfer runs, which is what the flush was standing in for.
- libcurl can wait on its own sockets: `curl_multi_poll` does this on every platform, so the hand-written wait and its Windows shim were duplicating it.
- After `curl_easy_pause(…, 0)`, a timeout action starts whatever unpausing made due, with no wait needed.
- `curl_multi_perform` was declared in C and in IR, and called by neither.

## Decision

- `drive_once` is now a timeout action, then `curl_multi_poll` for up to `max_ms` while transfers run, then `curl_multi_socket_all` and a drain. The `pollfd` array, the `poll` include and `__kml_win_poll_sockets` are deleted.
- `__kml_fetch_pump` is a timeout action and a drain.
- `@__kml_httpc_flush`, its hook, `emitPostLoopFlush` and the `curl_multi_perform` declarations are deleted.
- The waits that remain outside the loop are synchronous `XMLHttpRequest.send()` and a scheduler step outside the loop. They wait in libcurl. The second goes away when the HTTP server's connection fibers resume from read callbacks (Stage 5).

## Implementation notes

- `TestIRTextOnlyShrinks`: `emit_http_client.go`'s allowance is now 2.

## Verification

- On macOS (Apple Silicon): the fetch, HTTP client and XMLHttpRequest tests (`-run 'Fetch|HTTPClient|XHR|XMLHttp|HTTPGet|HTTPRequest'`).
- The Windows build is compile-checked only, by CI.
