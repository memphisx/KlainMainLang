# ADR-00476: class index-sig erasure; comma statements; ambient enums

- **Relations**: Extends [ADR-00461](ADR-00461.md), [ADR-00471](ADR-00471.md)
- **Date**: 2026-08-29

## Context

Three residual parse buckets: class-body index signatures
(`class C { [n: number]: T }` — previously a mid-class parse error),
statement-level comma sequences (`~E.A, ~E.B;` — the parser had a
SequenceExpression node but never produced it at statement level), and
`declare [const] enum` (erased entirely, leaving `E.b` undefined).

## Decision

- A class-body index signature parses (shared `parseIndexSignature`) and
  is **dropped** — classes have fixed field layouts, no map backing;
  indexing keeps its ordinary use-site rejection. Disclosed narrowing.
  Distinguished from computed member names by the `[IDENT :` prefix.
- `parseExpressionStatement` folds `a, b, c;` into the existing
  SequenceExpression (left-to-right evaluation).
- `declare [const] enum E { … }` parses as a real enum — auto-increment
  members behave identically; the spec's ambient "computed member"
  nuance is not modeled.

## Verification

Mac. `tests/overloads_test.go` additions (erased class index sig, comma
statements + ambient enum) pass; parser + enum/class/for batches green.
TS oracle flat at 56.9% (5264 → 5263 — the affected files stack further
blockers; the parse errors they now surface are later, more specific
ones). Node oracle unchanged (40).
