## Context

`http2` is the single largest block in the Node oracle: **237 files** fail
`MODULE_NOT_IMPLEMENTED: http2` — more than `vm`, `async_hooks`, and the
`node:test` runner combined. It is also the last big lie-shaped gap from the
honesty audit: HTTP/2 was "shipped" as transparent protocol support
(TDD-00111 — `fetch` negotiates h2, `http.listen` serves h2c via nghttp2),
but the *module* — `http2.createServer`, `http2.connect`, `Http2Session`/
`Http2Stream` — never existed, and the docs called that out only after the
audit. This TDD scopes the explicit API.

What the corpus actually uses (histogram over the 237 files):

| Surface | Refs / files | Notes |
|---|---|---|
| `http2.createServer()` | 221 files | Almost always the zero-arg handle form + `.listen(0)` |
| `http2.connect(authority)` | 164 | Client session, nearly always to the same process's server, `http://` (h2c) |
| `client.request(headers)` | 241 refs | Returns a client stream; `req.on('response'/'data'/'end')`, `req.end()` |
| `server.on('stream', (stream, headers))` | 156 files | The **core streams API** — dominant server shape |
| `stream.respond({ ':status': … })` / `stream.end(body)` | 110 / 99 | Server-side response path |
| `server.on('request', (req, res))` | 13 files | The **compat API** — minority |
| `http2.constants` | 23 | `HTTP2_HEADER_*` / `NGHTTP2_*` names |
| `http2.createSecureServer` | 22 | Needs the TLS server mode TDD-00111 Stage 3b still lacks |
| `getPackedSettings`/`getUnpackedSettings`/`getDefaultSettings` | 31 | Settings-buffer helpers, self-contained |

## Design

### Reuse map

Nearly every hard piece already exists somewhere:

- **nghttp2 session driver** — `http2src/http2.c` (ADR-00357) already runs a
  full *server-mode* nghttp2 session per connection (preface detect, HPACK,
  frame drive, request assembly), dispatching through `__kml_h2_dispatch`
  into the shared 1.1-shaped handler core. Linked via the `UsesHTTP2` gate.
- **Server handle model** — the variable-bound `http.createServer` handle
  (ADR-00406): `.listen(port?, cb?)`/`.close()`/`.address()`/`.on(evt, cb)`
  over the shared event loop, `httpListenCallSeen` single-server rule.
- **Contextual callback typing through `mustCall` wrappers** (ADR-00412) —
  the corpus wraps every listener; the same `contextTypeArrowParams` machinery
  types `(stream, headers)` and `(req, res)` here.
- **Event loop + fibers** — one fiber per connection; the h2 session drive is
  blocking within its own fiber (V1 posture, unchanged).

The genuinely new work is: a **client-mode** nghttp2 session (the C driver is
server-only today), the **Http2Stream object surface** on both sides, and the
**module resolution** itself.

### Stage 1 — module + server handle + compat API (small; unblocks compile of most files)

- `http2` resolves as a builtin (marker `http2__kml_builtin`), named members
  per the table above.
- `http2.createServer(options?, handler?)` returns an `Http2ServerType()`
  handle (new flag, same shape as `IsHTTPServer`): `.listen(port?, cb?)`
  binds and enters the loop **serving h2c only** (no 1.1 fallback needed — the
  clients in these files are `http2.connect`); `.close()`/`.address()` reuse
  the existing machinery.
- `server.on('request', (req, res))` — the compat API — routes into the
  existing `emitHTTPCreateServerCore` res-mode dispatcher, which the h2c
  bridge already knows how to call. This is nearly free and covers the 13
  compat files plus the many files whose *server side* is compat-shaped even
  when the client side is a session.
- `http2.createSecureServer` stays a clean rejection pointing at the TLS
  dependency (TDD-00111 Stage 3b) — same honesty posture as
  `https.createServer` (ADR-00410).

### Stage 2 — core streams server API

- `server.on('stream', (stream, headers) => …)`: a second dispatch mode on the
  h2c bridge. `headers` is a `Map<string, string>` including pseudo-headers
  (`:method`, `:path`, `:authority`, `:scheme`) — the same lowercased-keys
  convention `req.headers` uses.
- `Http2StreamType()` (server side): `.respond(headersObject)` (only
  `':status'` + regular headers; queues HEADERS), `.end(body?)` (DATA +
  END_STREAM), `.write(chunk)`, `.on('data'|'end')` for request bodies,
  `.close(code?)` (RST_STREAM). Backed by small C additions to `http2.c`
  (submit_response / submit_data on an existing session — nghttp2 primitives
  the server driver already links).
- **Pseudo-header keys**: `{ ':status': 200 }` parses today (verified); the
  emitter consumes the literal's properties at the `respond()`/`request()`
  call site (no string-keyed bracket reads needed anywhere in the design).

### Stage 3 — client: `http2.connect` + `session.request`

- `http2.connect(authority, opts?, cb?)` parses the authority (string;
  `http://host:port` → h2c prior-knowledge TCP connect, reusing
  `__kml_net_connect`), then runs a **client-mode nghttp2 session** on its own
  fiber — the symmetric counterpart of the server driver in `http2.c`
  (`nghttp2_session_client_new`, preface send, settings exchange). Returns
  `ClientHttp2SessionType()`: `.request(headersObject)` → client stream,
  `.close(cb?)`, `.destroy()`, `.on('error'|'close'|'connect')`.
- `ClientHttp2StreamType()`: `.on('response', (headers))`, `.on('data')`,
  `.on('end')`, `.end(body?)`, `.write(chunk)`, `.close(code?)`,
  `.setEncoding` (accepted no-op, matching the net socket posture).
- `https://` authorities are a clean rejection until TLS+ALPN client sockets
  exist outside libcurl (the curl client can't expose raw h2 streams — this
  is why the client must be native nghttp2, not another curl wrapper).
- Delivery: same blocking-drive-in-fiber V1 the server uses; the event loop
  interleaves the in-process server and client fibers, which is exactly the
  corpus shape (`server.listen(0, () => { const client = http2.connect(…) })`).

### Stage 4 — long tail, by count

- `http2.constants` — a compile-time namespace of string/number constants
  (evaluated like `Math.PI`-style member reads; no runtime object).
- `getDefaultSettings`/`getPackedSettings`/`getUnpackedSettings` — pure
  functions over a settings object/Buffer; self-contained.
- `session.ping(cb)`, `goaway`, `settings()` — nghttp2 one-liners; add when a
  measured bucket justifies each.
- Out of scope until demanded: push streams (`pushStream`), `ALTSVC`/`ORIGIN`
  frames, `sensitiveHeaders`, `performServerHandshake`, trailers.

### What is deliberately different from Node

- One server per program (the existing V1 rule) and blocking listen — same
  caveats as `http.createServer`, disclosed on the status page.
- Session/stream error semantics are simplified: protocol errors surface as
  thrown `Error`s or `'error'` events with a message, not Node's full
  `ERR_HTTP2_*` code taxonomy (the corpus files asserting exact codes will
  keep failing honestly — same class as `invalidArgTypeHelper`).

## Open questions

- **Headers object vs Map**: `stream.respond({ ':status': 200, 'content-type':
  'text/plain' })` is an object literal with dynamic-ish keys; is the emitter
  better served by compiling it to the existing string-Map runtime (as
  `http.listen` response headers do) rather than a typed struct? Leaning Map.
- **Where the client fiber blocks**: drive the client session inside
  `session.request`/`req.end` synchronously (simplest, matches the blocking
  V1 posture) or park it on the loop like the http client's reaction registry
  (ADR-00405)? The corpus's `client.close()`-from-`'end'` shape suggests the
  reaction model composes better with the post-loop flush (ADR-00412).
- **Interplay with the single-server rule**: an `http2.createServer` and an
  `http.createServer` in one program — reject (V1) or allow one of each? V1:
  reject, same flag.
