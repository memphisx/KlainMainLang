# ADR-00357: HTTP/2 server — h2c (cleartext) via nghttp2

- **Relations**: Implements [TDD-00111](../tdd/TDD-00111.md) Stage 3a; builds on the dispatcher refactor (`emitHTTPCallHandler`) and Stage 2 ALPN ([ADR-00345](ADR-00345.md) server ctx)
- **Date**: 2026-08-25

## Context

`http.listen` was HTTP/1.1 only. TDD-00111 stages HTTP/2 as: client (shipped —
one `curl_easy_setopt`), ALPN in `tls.c` (done), and the server. Hand-rolling
HTTP/2 framing + HPACK is out of scope, so the server rides **nghttp2** (already
a libcurl transitive dependency), compiled alongside like `tlssrc/tls.c`. This
ADR delivers **Stage 3a — h2c** (cleartext, prior-knowledge): a `http.listen`
server that transparently serves HTTP/2 cleartext clients as well as 1.1.

## Decision

- **`http2src/http2.c`** wraps an nghttp2 server session behind a small C ABI
  (`__kml_h2_session_server_new`/`_feed`/`_recv`/`_send`/`_want_read`/`_want_write`/
  `_del`, `__kml_h2_set_blocking`). nghttp2 callbacks accumulate each stream's
  method/`:path`/headers/body, and on `END_STREAM` invoke the shared handler core
  and submit the response via `nghttp2_submit_response`. Gated by `UsesHTTP2()`
  (set when `http.listen` is used) + linked `-lnghttp2` (`http2.go`, mirroring the
  TLS plumbing); a missing libnghttp2 is a link error for http-server programs.
- **IR bridge** (`buildHTTP2Bridge`, emitted per call site): `__kml_h2_dispatch`
  builds the `HttpRequest` from the nghttp2-parsed parts and runs the user handler
  via the refactored `emitHTTPCallHandler`, and `__kml_h2_resp_status/body/bodylen`
  read the response — so h2 reuses the exact routing/`Request`/`Response` the 1.1
  path uses.
- **Transparent detection**: the connection fiber, at the point it first scans
  the request (`findHeaderEndL`, **before** any 1.1 header parsing — the preface's
  binary frames would crash the 1.1 splitter), checks for the h2 preface
  (`PRI * HTTP/2.0\r\n…`). On a match it feeds the buffered bytes to a session and
  runs a blocking recv/send loop to completion, then closes; otherwise it falls
  through to the unchanged 1.1 path. So `http.listen` serves 1.1 and h2c on one
  port with no API change.

## Scope / V1 limits

- **In:** h2c GET/POST (method, path, body, headers), transparent coexistence
  with 1.1, response status/body via the shared handler.
- **Out (deferred):** h2 over TLS (Stage 3b — needs an `http.listen` TLS mode,
  cert/key + the Stage 2 ALPN branch after `SSL_accept`); an async handler under
  h2 (the drive is a blocking recv/send loop in the fiber — sync handlers only,
  the 1.1 path keeps full async); response-body streaming over an nghttp2 data
  provider (a full-buffer response for now); h2 query-string parsing off `:path`.

## Verification

- `tests/http_test.go`: `TestE2EHTTPListenHTTP2Cleartext` — `curl
  --http2-prior-knowledge` GET + POST-with-body over h2, plus a 1.1 request on the
  same server (skips if curl absent). The existing 1.1 HTTP suite still passes
  (the preface check falls through for non-h2). Test build path mirrors the CLI
  (`appendHTTP2Backend`).
- `examples/http2/h2c_server.ts`; `make examples`; `go test ./...`;
  `make conformance`.
- Machine: verified on Mac (arm64), Homebrew `nghttp2` 1.70.
