# ADR-01544: An untyped `[]` pushed an `any` is `any[]`; polymorphic JS parameters are `any`

- **Relations**: Extends TDD-00230, ADR-00887
- **Date**: 2026-10-10

## Context

- An untyped `[]` whose only pushes were values of unknown kind (an
  untyped parameter, an `any`) fell to the `number[]` default: pushed
  strings read back as numbers and a Symbol threw "Cannot convert a
  Symbol value to a number" (`var ks = []; function h(k) { ks.push(k) }`).
- Under -compat=js, an unannotated parameter whose call sites pass
  different types was left unanswered by the checker (TypeScript's
  checkJs types it `any`), and codegen's own call-site collection
  treated a string and a Symbol argument as agreeing (both a pointer).
- The strict lane rejected an inferred heterogeneous `[]`
  (`a.push(1); a.push("x")`) with its own error, which tsc accepts as
  `(string | number)[]`.

## Decision

- An `any` contribution to an untyped `[]`'s element type makes it
  `any[]`, as an evolving array's `any` element does in tsc.
- The checker types a JS parameter whose call sites disagree as `any`,
  and codegen takes that answer before its own call-site slots.
- An unannotated rest parameter with no contextual type is `any[]` on
  every path (a declaration's signature, an arrow, a function
  expression, and their inferred types), where the paths had defaulted
  it to `i64[]` or `double[]` inconsistently.
- The strict lane's heterogeneous-array rejection is removed: such an
  array is the boxed-element array in both lanes.
