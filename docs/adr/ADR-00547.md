# ADR-00547: replaceAll("") inserts between every character

- **Relations**: Extends ADR-00003
- **Date**: 2026-09-01

## Context

`String.prototype.replaceAll` with an empty search string was a no-op
(returned a copy unchanged). Real JS treats an empty search as a zero-length
match at every position: `"abc".replaceAll("", "-")` is `"-a-b-c-"` — a leading
replacement, then each character followed by the replacement. This was a
disclosed caveat on the string-methods status page.

## Investigation

`__kml_replace_all` (runtime_strings.go) short-circuited `search_len == 0` to a
`copy_unchanged` block because the generic `memmem` count/fill loop makes no
forward progress on a zero-length match. The faithful behavior is a simple
fixed interleave — no search loop needed — so it fits a dedicated branch.

## Decision

Replace the `copy_unchanged` block with an `empty_search` block that allocates
`slen + rep_len*(slen+1)` content bytes, writes a leading `%rep`, then loops
over the original characters writing each character followed by another `%rep`.
An empty input string yields just the single replacement (`"".replaceAll("",
"-")` → `"-"`), which the `slen+1` count handles naturally.

## Implementation notes

- Only the empty-search branch of `__kml_replace_all` changed; the non-empty
  `memmem` count/fill path is untouched.
- `__kml_str_alloc` is length-prefix aware, so passing the exact content byte
  count sets the header correctly — same as the existing fill path's `total0`.

## Side effects discovered

None. Regex-backed `replaceAll(/…/g, …)` is a separate path (emitRegexReplace)
and unaffected.

## Verification

`TestE2EStringReplaceAllEmptySearch` (`"abc"`→`"-a-b-c-"`, `""`→`"-"`,
`"x"`→`"*x*"`) plus the existing `TestE2EStringReplaceAll` pass. Built and
verified on Mac (Apple Silicon).
