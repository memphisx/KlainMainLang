# ADR-01837: A hinted callback parameter, and `+` over what codegen holds

- **Relations**: `Implements TDD-00230` (P3.3: the checker answers what inferExprType did)
- **Date**: 2026-10-20

## Context

- A `replace` callback's parameters are typed by codegen from the pattern: the match a string, each capture group `string | undefined`, then the offset and the subject (`resolveRegexReplacer`). The lib types them `any`.
- Identifier is a switched kind. So the checker's side answered `any` for a capture-group parameter that emission had bound as a string. A read of it then converted the string into a box, and `digits + letters` was typed `any` against the old side's string.

## Decision

- An unannotated, non-rest parameter without a default that the checker leaves `any` is answered with the binding emission made for it in the scope being emitted. The emitter exposes that as `heldIdent`. Where codegen boxes the parameter too, the answer stays `any`.
- `+` that the checker types `any` is a string when either operand, as held, is a string type and neither is a box. Emission concatenates there, `undefined` included.
- A rest parameter widened for a dynamic entry is bound as an array of boxes. The oracle answered it as a bare box; it now answers with the array, as `heldIdent` gives it. A member read or call rooted at it stays a box, as before. Found in `node:path`'s `win32_resolve`, compiled beside `node:fs` (`examples/fs/statfs_umask_fchmod.ts`). That example had failed to compile in the previous full run, so its rows had not been counted.

## Consequences

- `examples/strings/replace_capture_groups.ts` has no disagreements left, and a capture group is read as the string it is held as, without a round trip through a box.
- Verified on Apple Silicon (replace, callback, higher-order, sort and JS-lane E2E tests), and with the gate on Linux x86-64 (DeskMini).
