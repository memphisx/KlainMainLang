# ADR-01625: Windows' broken-pipe and TLS write errors are Node's; the windowed webview runs on the embedded loop

- **Relations**: Extends TDD-00180, TDD-00252, ADR-01614
- **Date**: 2026-10-14

## Context

Three Windows items were left: a write to a broken anonymous pipe surfaced
as `EBADF` where Node gives `EPIPE`, the TLS write error after the peer
closes was unprobed (TDD-00180 §5), and the windowed webview had not been
run on Windows since the event loop was embedded in the GUI loop
(ADR-01614).

## Investigation

Measured against Node 24 on the same machine:

- A write to a child's stdin while the child exits: `EPIPE`, syscall
  `write`, on the stdin's `'error'`, as Node. Writes after the child has
  exited are dropped silently by both.
- `process.stdout` into a reader that has gone: `EPIPE`, syscall `write`,
  as Node. Both came with the move of Windows' I/O onto libuv (TDD-00252).
- A TLS server writing while its client destroys the connection
  (`TestE2ETLSServerWriteAfterClientDestroy`): `ECONNRESET` on the server
  socket, as Node, three runs of three.
- The windowed smoke tests (`KML_WEBVIEW_SMOKE=1`): all pass but
  `TestE2EWebviewLoopEmbedSmoke`, whose program read `/etc/hosts`, a file
  Windows does not have (Node fails the same way).

## Decision

- Tests pin the two broken-pipe cases against Node.
- The loop-embedding smoke test reads the program's own executable, present
  on every platform.
- The backlog's Windows webview and broken-pipe/TLS items are closed.

## Implementation notes

`tests/broken_pipe_test.go` (`TestE2EChildStdinBrokenPipeSameAsNode`,
`TestE2EStdoutBrokenPipeSameAsNode`), `tests/webview_test.go`,
`docs/BACKLOG.md`.

## Side effects discovered

None.

## Verification

Windows 11 (this machine): the broken-pipe tests three runs of three, the
TLS probe three of three, every `TestE2EWebview*` test with
`KML_WEBVIEW_SMOKE=1` (windows opened on the desktop session), the loop
smoke three of three.
