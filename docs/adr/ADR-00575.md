# ADR-00575: http client request bodies (req.write / req.end(body))

- **Relations**: Extends ADR-00430, TDD-00138

- **Date**: 2026-09-01

## Context

The `http`/`https` client (`http.request`/`http.get`) was GET-only:
`req.end(body)` and `req.write()` were clean rejections, so a POST/PUT with a
request body was impossible. The underlying primitive
`__kml_fetch_async(url, method, headers, body, signal)` already accepts a body
pointer — the client just passed `null`.

## Decision

Thread a request body through the ClientRequest handle:

- The handle grows a 6th pointer slot (`calloc` 40 → 48 bytes): `{ url, cb,
  state, method, headers, body }`, body calloc-zeroed to `null`.
- `req.write(chunk)` stages a string chunk into the body slot, **appending** to
  any bytes a prior `write` staged (Node's `req.write` semantics), and returns a
  boolean.
- `req.end([body])` appends an optional final chunk, then fires as before.
- `__kml_httpc_begin` gains a `body` parameter passed straight to
  `__kml_fetch_async`; the deferred `req.end` path loads the body from slot 5,
  and the immediate `http.get`/eager path passes `null` (a body only ever
  travels the deferred `write`/`end` route).

A `method: "POST"` (etc.) option, already accepted, pairs with the body. Chunks
are strings (the client's text-first model); a non-string chunk is a clean
rejection.

## Side effects discovered

None. Existing GET flows (`http.get`, `request().end()` with no body) pass `null`
for the body exactly as before; the completion thunk and response surface are
untouched.

## Verification

New `TestE2EHTTPClientRequestBody` (a `req.write("hello ")` + `req.end("world")`
POST whose server echoes `method + ":" + body` → `POST:hello world`), plus the
existing `TestE2EHTTPClientRequestHandle`/`Abort` and the full http suite. Built
and verified on Mac (Apple Silicon).
