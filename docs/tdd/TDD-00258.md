# TDD-00258: Reading a Map or Set through another element type

- **Status**: Implemented
- **Date**: 2026-10-18

## Context

A Map or Set stores its keys and values in its static type's representation:
- a `Map<string, number>` keeps raw string pointers and raw doubles;
- a `Map<any, any>` keeps NaN-boxed words and hashes them as boxes.

The same object can be reached through another type. Node has one representation, so the object behaves the same through every type:
- a `Map<string, number>` passed to a `Map<any, any>` parameter;
- `box as Map<any, any>` over a typed map;
- a `Set<number>` cast to `Set<any>`.

Here the view's code runs its own flavor over the other layout's words:
- `m.get('a')` misses, since the boxed key hashes differently;
- values read as boxes (`1` prints `0.9375`);
- `m.set('z', 26)` writes a box into a table of raw doubles.

The object must stay shared: a write through the view is visible through the original.

## Design

**Recommended: dispatch on the header word.** Every Map and Set already carries its instantiation's host header word before its body (TDD-00247), and the emitter registers every instantiation it creates (`hostLayouts`).
- **View sites.** A Map or Set operation whose static key or value type involves `any` loads the receiver's header word. If it is the static type's own id, the operation runs as today. Otherwise it calls a dispatcher.
- **Dispatchers.** At module end, the emitter generates one per operation (`get`, `set`, `has`, `delete`, `entries`, and so on). It switches on the header word over every registered Map or Set layout, and each case runs that layout's own typed operation:
  - the `any` arguments are converted into the layout's key and value types;
  - the result is boxed.
  - This reuses the per-layout routine machinery the host inspect and iteration rows use (`bindHostSelf`).
- **Iteration and output.** `keys()`, `values()`, `entries()`, `forEach`, for-of, spread and `console.log` through a view read the layout's boxed entries array (the routine `[...m]` already has).

A view of a map whose own type is the view's type costs one compare and branch. Typed code is unchanged.

**Rejected: kinds in the map's flags, translated in C.** The C runtime would box and unbox each key and value by a kind code. It would duplicate the emitter's boxing (strings, numbers, objects, arrays, nested hosts) in C, and the emitter's own converters would still have to agree with it.

**Rejected: copying at the conversion.** A copy breaks identity: a write through the parameter would not reach the caller's map.

### Stages

1. **`any` views of typed maps and sets:** the operations above, through a view whose key or value type involves `any`.
2. **A typed view of a differently-typed object:** `box as Map<string, number>` over a `Map<any, any>`, or over a `Map<string, string>`. The same dispatch, applied where `any` is unboxed into a Map or Set type.
