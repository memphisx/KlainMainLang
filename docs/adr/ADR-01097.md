# ADR-01097: Core fixes found while making node:ffi faithful

- **Relations**: `Extends ADR-01080, ADR-00963`
- **Date**: 2026-09-23

## Context

Writing Node-differential probes for [TDD-00229](../tdd/TDD-00229.md) hit a set
of unrelated core bugs, all reproducible at HEAD. Each is small and fixed here
rather than masked in the probes.

## Decision (one fix per item)

1. **Module global from a constant ternary.** `const lib = process.platform ===
   'darwin' ? 'a' : 'b'` read from a named function failed with
   `undefined variable 'lib__kml_mod0'`: ADR-01080 promoted
   `const isWin = process.platform === 'win32'` but not the ternary pick.
   `constFoldableScalarInit` accepts a `ConditionalExpression` whose test and
   arms are constant; the existing `isSimpleGlobalType` gate rejects arms of
   differing kinds. (`emit_exprs_vardecl.go`)
2. **A caught value passed to an `any` parameter** arrived as `typeof
   "number"`: `emitBoxValue` had no arm for the `{i8 tag, i64 payload}` caught
   record and fell to the numeric default. It now packs it via
   `emitCaughtToAny` (as `coerce` already did). (`emit_dynamic.go`)
3. **A function returning its catch binding** (`catch (e) { return e }`)
   inferred a `number` return and returned 0: return-type inference now binds
   an otherwise-unbound catch parameter as `any`. (`emit_func.go`)
4. **`e.constructor`** on a boxed Error was undefined; it is now the built-in
   constructor reference (tag 8, the interned name), so `.name` works and
   `e.constructor === TypeError` compares equal. (`emit_dynobj.go`)
5. **Calling a variable that holds an `any`** (`const h: any = …; h(3)`) failed
   with `undefined function or closure`; it now makes the runtime dynamic call.
   (`emit_call.go`)
6. **Unboxing a number into an integer slot** read the double's raw bits
   (`emitUnboxBoxToType`'s integer arm predated the NaN box), so a closure
   called through `any` got 4607182418800017408 for `1`. It now converts with
   ToNumber and the ordinary number→integer coercion. (`emit_narrowing.go`)
7. **Defaults through `any`.** The dynamic-ABI closure adapter passed
   `undefined` for an omitted defaulted argument without applying the default:
   a call-site default is now evaluated in the adapter (earlier parameters in
   scope for `(a, b = a) => …`), a body-filled default gets its presence-mask
   bit, and an explicit `undefined` triggers the default as in JS.
   (`emit_dynfunc.go`)
8. **Parameter types from defaults.** An unannotated parameter was `number`
   whatever its default, so `(who: string, p = '!')` rejected `greet('B', '?')`
   and filled `'!'` into a numeric slot. A literal default (string, template,
   number, bigint, boolean, array, object) or a module-global identifier now
   types the parameter, as TypeScript does, at every signature site (named
   functions, arrows, function expressions, `inferExprType`).
   (`fnmeta.go` `paramDefaultType`)
9. **`(p = '!') => p`** failed to parse ("unexpected token =>"): the arrow
   lookahead had no case for a defaulted first parameter. A matching-paren scan
   (`parenGroupFollowedByArrow`) decides arrow vs. parenthesized assignment.
   (`parser/parser_literals.go`)
10. **`[true, 5]` compiled to `[true, true]`**: boolean and number are both
    plain scalars, so the element coerce silently converted. Strict mode now
    rejects the mix like any heterogeneous literal; `-compat=js` already boxed it
    correctly. (`emit_arrays_core.go`)
