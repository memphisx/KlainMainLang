# ADR-00699: @owned last-use frees — locals and parameters

- **Date**: 2026-09-04

## Context

TDD-00173 Stage 3 (TDD-00001's "linear-value" stage): block exit can be too
late for a long block, and pipeline-style code wants each stage's input
released the moment data flow is done with it.

## Decision

- **`/** @owned */` on a local binding**: same escape check and emit-time
  gates as `@free` (ADR-00698), but the free lands immediately after the
  variable's *last-use statement* — the last statement in its declaring
  list whose subtree mentions it. Placement always errs later, never
  earlier: a last use inside an `if` frees after the join; inside a loop,
  after the loop; inside a `try`, or when the last-mentioning statement is
  an abrupt exit, it falls back to plain block-exit placement.
- **Safety net**: every `@owned` obligation is *also* registered on the
  block-exit `pendingFrees` stack; the early free marks it `emitted`, so an
  exit path emitted before the last-use point (source order = dominance
  order at the same list level) still frees exactly once and later exit
  paths skip it. Stage 3 is structurally an acceleration of Stage 2's
  guarantee, incapable of missing an exit path.
- **`/** @owned name */` on a function declaration** (the `@param {T} name`
  named-tag shape — an inline `/** @owned */` inside the parameter list
  would bleed onto the body's first statement via `pendingDoc`, so the
  function-level form is the syntax): the callee owns and frees the
  argument after its last use in the body, with function exits as the
  safety net. The param is escape-checked against the body like a local;
  a typo'd name, a rest param, or an async/generator function is a parse
  error.
- **Caller-side contract, checked at every call site**: the argument must
  be a value the caller provably no longer needs — a fresh
  expression-produced value (literal, constructor, concatenation, call
  result), or a local identifier that never appears again in any following
  statement at any enclosing nesting level. A live local is a compile
  error at the call site. Direct calls to statically-resolved function
  declarations only; referencing an `@owned`-param function *as a value*
  is a compile error (the contract can't follow a function reference).

## Consequences

- No per-branch last-use placement in V1 (join/after-loop instead) —
  a future optimization, not a correctness gap.
- A caller's local passed to an `@owned` param is by construction never
  itself auto-freed (call-argument passing is an escape-check rejection),
  so callee-free and caller-free can't collide.

## Verification

- `tests/memory_auto_test.go`: owned-local last-use and owned-param
  pipeline behavior; rejections for a live argument, function-as-value,
  and unknown param names. IR inspection confirmed the early free lands
  before the statement following the last use.
- Verified on the Mac (Apple Silicon).
