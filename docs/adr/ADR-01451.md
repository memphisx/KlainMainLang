# ADR-01451: `arguments` in a dynamic function

- **Relations**: Extends TDD-00210
- **Date**: 2026-10-07

## Context

Under `-compat=js`, a function in an object literal (`{ m() {…} }`,
`{ m: function () {…} }`) that read `arguments` failed to compile with
"undefined variable 'arguments'". Test262's `arguments-object` tests hit it.

## Investigation

- A function-valued property compiles under the dynamic calling convention
  (`emitDynCallable`): the caller passes `argc` and `argv`, every argument
  already boxed.
- Named functions, function expressions and class methods bind `arguments`
  through an implicit rest parameter (`synthesizeArgumentsObject`); the
  dynamic path had no such step.

## Decision

A dynamic function that is not an arrow (`bindThis`) and reads `arguments`
binds it to a dynamic array of all `argc` argument words, the same loop a
rest parameter uses (`emitDynArgvFrom`).

## Side effects discovered

- `Array.prototype.slice.call(arguments)` fails: `Array.prototype` is not a
  value yet (BACKLOG #152).
- A generator reading `arguments` fails too: generators reject rest
  parameters, which the implicit `arguments` parameter is (BACKLOG #153).

## Verification

- `TestE2EObjectLiteralFunctionArguments` (against Node, `-compat=js`).
