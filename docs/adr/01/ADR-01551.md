# ADR-01551: Nullish elements of an array literal; a `try` that never completes

- **Relations**: Extends ADR-00869, TDD-00230
- **Date**: 2026-10-10

## Context

- The inference of an array literal skipped its `null`/`undefined`
  elements only when their type had no IR, but `null` and `undefined`
  literals are typed `TypeNull`/`TypeUndefined` (IR `ptr`, both
  `IsNull`). `[2, null]` was counted as two kinds and inferred `any[]`,
  where TypeScript (and an annotation) has `(number | null)[]`; and
  `["a", undefined]` counted its `undefined` as a `null` too, giving a
  three-state element.
- The checker-side global type held a module variable initialized with
  a mixed literal as `any[]`, copying the old inference.
- Divergence analysis (`blockAlwaysDiverges`) had no `try` case: an async
  arrow whose `finally` always throws was `Promise<void>`; TypeScript
  infers `Promise<never>`.

## Decision

- A `null` or `undefined` literal's type (nullishLiteralType) is skipped
  as an element kind, and recorded as the null or the undefined it is.
- The global type of a mixed literal is the checker's union.
- A `try` diverges when its `finally` does, or when the try block and its
  catch (if any) both do.

## Divergences

None.

## Verification

- Mac (Apple Silicon): a literal/annotation probe of `[2, null,
  undefined]`, `[2, null]` and `["a", undefined]` prints as Node with no
  shadow disagreement; the try/finally async arrow rejects with the
  thrown value.
