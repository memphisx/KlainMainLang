# ADR-00974: Wire net.Socket write/end/destroy into the HTTP `'clientError'` socket

- **Relations**: `Extends ADR-00971`
- **Date**: 2026-09-16

## Context

Stage 1 of the server `'clientError'` event (ADR-00971) handed the listener a
`net.Socket` over the connection fd, but `socket.end()`/`socket.write()` from the
listener link-failed on an http-only program: `emitNetSocketMethod`'s
`write`/`end`/`destroy` cases emit calls to `@__kml_net_sock_write` /
`@__kml_net_sock_close`, and those runtime functions were defined only inside
`ensureNetRuntime` — which an `import http`-only program never calls. So the
socket was an inspect/handle-only object (documented caveat).

## Decision

Extract the two low-level byte-IO helpers (`__kml_net_sock_write`,
`__kml_net_sock_close`) out of `ensureNetRuntime` into a new `ensureNetSockIO`
(`runtime_net.go`), guarded by its own `usedNetSockIO` flag. `ensureNetRuntime`
now calls it (single-definition via the flag); `emitNetSocketMethod`'s
`write`/`end`/`destroy` cases call it too, so a `net.Socket` handed out by a path
that never stands up a net server (the HTTP `'clientError'`/`'connection'`
events) pulls in exactly those two functions and nothing else.

The helpers reference `@__kml_tls_write`/`@__kml_tls_free`. Those are resolved
(real extern when the program uses `tls`, no-op stubs otherwise) by
`emitTLSNetSymbols` in the finalize pass; its gate now includes `usedNetSockIO`
so an http-only program that only reaches the socket still gets the symbols.

### Teardown / double-close

The listener's `socket.end()` closes the connection fd (and sets the socket
struct's fd to `-1`); the dispatcher's shared `ceCloseL` teardown then closes the
same raw fd again. This is benign: the dispatcher and the listener run on the
same fiber synchronously, so no other fiber can reuse the fd between the two
`close()`s, and the second close returns `EBADF` harmlessly. No fd-reuse hazard,
so the teardown is left shared with the default-431 path.

## Consequences

A `'clientError'` listener can now answer the client itself —
`socket.write(...)`/`socket.end()`/`socket.destroy()` all work — most usefully on
the header-overflow path where the peer is still connected (a truncated-request
reset has already closed the peer, so a write is a no-op). E2E test
`TestE2EHTTPClientErrorSocketWriteEnd` drives an oversized header block and
asserts the listener's custom 400 replaces the default 431. The `net` suite still
passes, confirming the extraction is transparent to the full net runtime.
Verified macOS arm64 (M4).
