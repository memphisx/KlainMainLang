# ADR-01423: `@lowerType` — builtin layouts named by their declarations

- **Relations**: Implements TDD-00230 (P3.2)
- **Date**: 2026-10-06

## Context

TDD-00230 P3.2 has a builtin interface name its native layout with
`/** @lowerType <layout> */`, so codegen reads a host type's representation
from its declaration instead of from its name. Codegen matched names in four
places: `ResolveTypeName`'s switch (Date, RegExp, ArrayBuffer, the typed
arrays, Buffer, Request, Response, XMLHttpRequest), `decideAnnotationType`'s
arms for Promise, Map, Set, WeakMap, WeakSet and the WHATWG streams,
`lowerRepr`'s `Symbol.Name == "Error"` and `isBytesType`'s
`"Uint8Array"`/`"Buffer"`, and `isErrorRootKind`'s list of the Error kinds a
class may extend.

## Investigation

- The parser never took a doc comment for an interface declaration, so an
  annotation there was dropped.
- Name matching ignores scope: a program's own `class Map` reached the builtin
  Map arm. A program's `class Map` with a `get` method now shadows it.
- `class X extends DOMException` failed with "extends unknown class": the
  kind list left it out, although DOMException has Error's runtime layout.
- An Error subclass without a constructor took at most one argument, so
  `new E("m", { cause })` was rejected; JavaScript's Error takes the options
  bag second, DOMException a name.
- `AggregateError extends Error` would inherit `error`; its layout is wider
  (`aggregateErrorStructIR`), so it names its own.
- Found while testing the generic layouts, both older than this work:
  - an annotated module-level `const s: Set<number> = new Set([…])` read in a
    function failed with "undefined variable" (the read-in-functions promotion
    skipped every annotated declaration);
  - `const wm: WeakMap<object, number> = new WeakMap()` stored a number as
    raw double bits, since the declaration kept the integer default value
    type instead of the annotation's.

## Decision

- `InterfaceDeclaration.LowerType` holds the annotation (parser).
- `codegen/llvm/lower_type.go`:
  - `lowerLayouts` maps a layout name to its Type for the non-generic
    layouts; `genericLayouts` builds Promise, Map, Set, WeakMap, WeakSet and
    the stream types from an annotation's type arguments.
  - `declaredLowerType(sym)` reads a symbol's `@lowerType`, else the first a
    base interface names (`TypeError extends Error` is `error`).
  - `lookupBuiltinType` resolves a name in the program's module scope, so a
    program's declaration shadows the builtin; before `EmitProgram` stores the
    program, it resolves against the builtin declarations bound alone.
- `ResolveTypeName` keeps the primitives and native widths; `resolveTypeName`
  tries the declaration first. `reprOf`, `lowerRepr` and `isBytesType` read
  the layout, and a class is an Error subclass when its base resolves to an
  `error` layout.
- An Error subclass takes its base constructor's second argument in
  `super(...)`, in the constructor-less form and in the synthesized
  constructor: `options.cause`, or DOMException's `name` (whose default is
  "Error").
- The promotion pass admits an annotated `new Set([…])`, typed from its
  initializer as `emitSetVarDecl` types it; a bare `new WeakMap()` takes K/V
  from its `WeakMap<K, V>` annotation at the declaration and the promotion.
- `front()` no longer caches a nil checker when called before the program
  is stored.

## Implementation notes

- `lib/es.d.ts` and `lib/node.d.ts` annotate Error, AggregateError, Date,
  RegExp, ArrayBuffer, SharedArrayBuffer, the typed arrays, Promise, Map, Set,
  WeakMap, WeakSet, Buffer, Request, Response, XMLHttpRequest and the WHATWG
  stream interfaces. A merged interface needs the annotation on one of its
  declarations.
- `genericLayouts` is filled in `init()`: its builders call `resolveType`,
  which reads the map.

## Side effects discovered

Still matched by name rather than declared: klain:http's request and
response (`HttpRequest`, and the `IncomingMessage`/`ServerResponse` names its
handler annotations use; Node's own are TypeScript classes in
`lib/node/internal_http.ts`) and `Channel` (klain:sync), both ported with
the klain: modules, last; and the iterator and generator types. `@lowerType`
on a class declaration, and user classes extending a host layout other than
Error's, are open.

## Verification

Mac: `TestInterfaceLowerType` (parser), `TestE2EExtendsBuiltinErrorLayouts`,
`TestE2EBuiltinGenericLayouts`, `TestE2EWeakMapAnnotatedValueType` (each the
same output as Node); host annotations (Date, RegExp, typed arrays,
ArrayBuffer, Buffer, `instanceof`) the same as Node.
