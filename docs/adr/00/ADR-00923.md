# ADR-00923: Evolving-any for `null`-initialized bindings; `??`/`??=` on any (invalid-IR sweep)

- **Date**: 2026-09-13

## Context

An unannotated `let x = null; x ??= 1` (or `x = 5`) emitted invalid IR: the
binding inferred type `null` (a `ptr` slot), and the numeric right-hand side was
stored into it as a `double` constant — "floating point constant invalid for
type". `x = "hi"` on such a binding silently kept `null` (the assignment was
dropped). Surfaced in the Test262 CLANG_ERROR sweep
(`language/expressions/object/cpn-obj-lit-...-coalesce.js`,
`language/expressions/logical-assignment/left-hand-side-private-reference-data-property-nullish.js`).

TypeScript treats an unannotated `let`/`var` initialized to `null`/`undefined` as
an *evolving any*: the binding has type `any`, and a later assignment gives it a
concrete value. Two supporting defects also existed on the any-box path:
`nullBox ?? x` returned the box unchanged (it never consulted the NaN-box tag),
and `anyVar ??= x` never fired (the `??=` fast-path treated any non-`ptr` type as
never-nullish).

## Decision

- **Evolving-any widening.** Widen an unannotated `let`/`var` initialized to a
  bare `null`/`undefined` literal to the any-box when it is later reassigned in
  the same scope — a plain `=` to a non-nullish value, or a logical-compound
  assign (`??=`/`||=`/`&&=`). A never-reassigned null binding stays `null`-typed
  (unchanged). This runs in both lanes (TypeScript accepts evolving-any in strict
  mode), extending the existing `-compat=js`-only cross-kind widening
  (`crossTypeWidenedBindings`), which now also descends into initializer and
  nested expressions to find the reassignment.
- **`??` on a dynamic operand** tests the NaN-box tag for null/undefined and
  falls through to the right operand only when actually nullish; the result is an
  any-box.
- **`??=` on a dynamic location** computes nullishness from the box tag (not the
  never-fires non-`ptr` fast-path) and stores the boxed right-hand side when
  nullish.

## Implementation notes

- `codegen/llvm/emit_func.go` (`crossTypeWidenedBindings`): the pre-pass now
  returns null-evolving names in both lanes; a deep expression walker finds
  reassignments (including inside object literals / index expressions / calls).
- `codegen/llvm/emit_exprs_operators.go`: `emitNullCoalesce` dispatches an
  `IsDynamic` left operand to new `emitNullCoalesceDynamic`.
- `codegen/llvm/emit_exprs_assign.go`: `emitLogicalCompoundAssign` handles a
  dynamic (`IsDynamic`) location for `??=`.

## Scope / not covered

A `null`-initialized **class field** (`#field = null; this.#field ??= 1`) is not
widened: `any` as an object/class field type is not yet supported (the dynamic
object-model work). That Test262 file
(`logical-assignment/left-hand-side-private-reference-data-property-nullish.js`)
stays blocked on that subsystem, unlike the local-binding files here.

## Verification

- New E2E tests (`tests/invalid_ir_sweep_test.go`): `x ??= 1`, `x = "hi"`,
  never-reassigned null stays null, and `??`/`??=` on explicit `any` — all
  matching Node. `example/nullish/evolving_any.ts` added.
- `cpn-obj-lit-...-coalesce.js` no longer CLANG_ERROR.
- Broad let/var/null/dynamic/compat/closure test lane green; macOS arm64.
