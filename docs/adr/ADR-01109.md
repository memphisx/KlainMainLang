# ADR-01109: Mode lanes: every example compared across the memory modes

- **Relations**: `Implements TDD-00230` (Phase 0, P0.3)
- **Date**: 2026-09-24

## Context

The restructure rewrites the code that `-mm=auto`'s escape analysis and free
insertion sit on (the flow graph, P2.2, becomes their source of liveness
facts), and a mode that frees too early or too late usually still exits 0:
it prints something different, or nothing. [TDD-00230](../tdd/TDD-00230.md)
P0.3 asks for every example and E2E program to run under `-mm=auto`,
`-mm=auto -optimize-memory` and `-mm=gc` as well, with the output required to
match the default mode's.

## Investigation

- **What existed.** The E2E suite already takes a mode:
  `KLAIN_TEST_MM=auto|gc` and `KLAIN_TEST_OPTMEM=1` make every
  `assertOutput` program compile in that mode, and those tests compare with an
  expected output, so the E2E lanes are differential already.
- **`make examples MM=auto OPTMEM=1`** compiled the examples in that mode, and
  its comment says the outputs must match a default-mode run, but the recipe
  sends every program's output to `/dev/null` and checks only the exit
  status: a mode that printed something else passed.
- **Two examples pin the default mode** (`memory_free.ts`, whose
  `Memory.free` is a compile error under `-mm=auto` by design, and
  `finalization_registry.ts`), and `-mm=gc` needs libgc on the machine.
- **Some examples are not deterministic** (they print times, dates or random
  values), so a comparison needs to know which.

## Decision

- **`make mode-lanes`** (`tools/modelanes`) builds and runs each example in
  the default mode, twice, and in each of `-mm=auto`,
  `-mm=auto -optimize-memory` and `-mm=gc`, and compares stdout and exit
  status with the default run.
  - An example whose two default runs differ is reported as nondeterministic
    and not compared.
  - The pinned examples keep the default memory mode in every lane (the
    `-optimize-memory` lane still applies to them).
  - A mode that rejects an example at compile time is reported apart from a
    mismatch; a failed `-mm=gc` build that names the collector is "mode
    unavailable" on this machine.
  - Examples run one at a time (several start servers on fixed ports), under
    the same per-run limit as `make examples`, with the httpbin-lite fixture
    running.
  - The report goes to `.modelanes-out/MODE-LANES.md`; any mismatch fails the
    target.
- **The E2E lanes** are the existing switches, run as `KLAIN_TEST_MM=auto
  make test-par`, `KLAIN_TEST_MM=auto KLAIN_TEST_OPTMEM=1 make test-par` and
  `KLAIN_TEST_MM=gc make test-par`.
- **Sanitizers** (ASan/UBSan on the Linux lane) are not part of this step.

## Implementation notes

- **New:** `tools/modelanes/main.go`.
- **Changed:** `Makefile` (`mode-lanes`), `.gitignore`.

## Side effects discovered

- **The first run's mismatches were mostly the harness's own.** Two examples
  print their own path (`process.argv`), and each mode's binary lived in its
  own directory; timings and the order of concurrent output (workers, child
  processes, event sources) also differed between runs that two default runs
  had not exposed. Every build of an example now goes to the same path, and a
  mismatch is rerun (both builds) before it counts: runs that differ again
  make the example nondeterministic. `finalization_registry.ts` is left out of
  the gc lane: when cleanups run is mode-dependent by design (TDD-00163).
- **Five examples segfault under `-mm=gc` on macOS**, deterministically:
  `async/async_generator.ts` (after its output), and
  `fs/read_stream_backpressure.ts`, `http/res_backpressure_drain.ts`,
  `http/res_stream_backpressure.ts` and `streams/http_upload.ts` (before any).
  Recorded in BACKLOG §0 beside the known macOS `-mm=gc` test failures; not
  yet checked on Linux.

## Verification

All on macOS arm64 (M4):

- `make mode-lanes`, first full run (347 examples compared, 25 minutes): 23
  mismatches, of which 18 were the harness artifacts above.
- The fixed harness over the fourteen examples that had mismatched: ten
  compared, four nondeterministic (`one_event_loop`, `child_process`,
  `console`, `fetch_then`), and five mismatches, the five `-mm=gc` segfaults.
  No example differs under `-mm=auto` or `-mm=auto -optimize-memory`.
- **Not done here:** the sanitizer lane (ASan/UBSan on Linux) that P0.3 also
  asks for, and the E2E suite in the three modes (`KLAIN_TEST_MM`), which runs
  as three more `make test-par` passes.
