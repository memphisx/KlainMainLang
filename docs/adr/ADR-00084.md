# ADR-00084: Classes Stage 4 — `static`, `private`/`protected`, `abstract`, `implements`

- **Relations**: Extends [ADR-00083](ADR-00083.md). Implements
  [TDD-00009](../tdd/TDD-00009.md).
- **Date**: 2026-07-31

## Context

Stage 4 was the last piece of [TDD-00009](../tdd/TDD-00009.md), left
undesigned by the TDD itself ("further out, not designed in depth"):
`static` members/`static {}` blocks, `private`/`protected` visibility,
`abstract` classes/methods, and `implements`. Picked up as a direct
continuation of Stage 3 ([ADR-00083](ADR-00083.md)) to close out the TDD
entirely, with design work done as part of this same piece of work per this
project's standing rule for significant scoping before implementation
(the design itself now lives as this ADR's Decision section — the TDD's own
Stage 4 paragraph stays as originally written, per this project's "TDD
design content is never edited to match what shipped" convention).

Two scope decisions made explicit with the user before implementation:

1. **Build all four pieces, including `implements`** — even though this
   compiler had zero structural-conformance-checking code anywhere before
   this change (confirmed directly: `registerInterfaces`,
   `emitter.go:571-584` at the time, treated an interface exactly like a
   type alias — a bare `ObjectType`, no conformance check of any kind, not
   even for a plain data interface) and interfaces couldn't declare method
   signatures at all.
2. **Static members are inherited** through `extends`, matching real
   JS/TS (`Derived.thing` resolves to `Base.thing` if `Derived` doesn't
   declare its own, and can be overridden) — not scoped as a
   non-inherited narrowing, the lower-risk alternative that was offered
   and declined.

## Investigation

Read the pre-Stage-4 implementation before designing the diff:

- `codegen/llvm/emit_classes.go`'s `ClassInfo`/`registerClasses` (Stage 3
  shape) — confirmed no visibility/static bookkeeping existed anywhere, and
  every existing field/method table was instance-scoped (flattened into
  `Ty`'s struct layout or per-method LLVM functions taking an implicit
  `this`).
- `emitClassMember` (then unconditional receiver splice) — confirmed a
  static method must skip the `this`/`super` binding and the `ptr %p_this`
  parameter-slot-0 splice entirely, since it has no receiver at all.
- `parser/parser_classes.go`'s member loop and its own doc comment,
  confirming `static`/`private`/`protected`/`implements`/`abstract` were
  still hard parse errors, not silently accepted — and that none of them
  were lexer keywords at all (`grep` against `lexer/token.go`'s keyword
  table).
- `ast.AnnotField`'s shared reuse across class fields, interface fields,
  and plain object-type annotations — confirmed adding visibility/static
  flags directly to it (rather than forking a class-only type) is safe:
  every other reuse site simply never reads them, the same "harmless
  zero-value elsewhere" shape `FunctionDeclaration.IsAsync` already
  established.
- Confirmed real TypeScript has two genuinely different privacy
  mechanisms — `#x` runtime-private fields (a real JS feature) and the
  `private`/`protected` keyword modifiers (TS-only, compile-time,
  erased) — and that TDD-00009's own Stage 4 paragraph explicitly settles
  on the keyword-modifier form ("arguably the *correct*, minimal match,
  since real TypeScript's own privacy is erased at compile time"). `#x`
  was confirmed to have zero lexer support and was deliberately not
  built here.

## Decision

**Static members + `static {}` blocks**: a static field is a plain LLVM
global (`@ClassName_static_name = global TY zeroinitializer`), not a
struct slot. A static method is a plain top-level function
`@ClassName_static_name(args...)` with no implicit receiver —
`emitClassMember` gained an `isStatic bool` parameter gating the receiver
splice. Inheritance needs no dynamic dispatch at all: a bare class-name
receiver (`Derived.thing`) is never polymorphic (there's no "value of
static type X actually holding a Y instance" scenario for a class *name*),
so it's always resolvable at compile time by walking `AncestorChain` — the
exact same "copy base's table, let own declarations override" shape Stage
3 already established for instance methods, just without any
`MethodSlot`/vtable concept. An inherited, non-redeclared static field
shares its base's *same* global (`StaticFieldOwner`), not a per-subclass
copy, matching real semantics — confirmed directly (`Derived.tag =
"changed-via-derived"` then reading `Base.tag` returns the changed value).
`static {}` blocks concatenate (declaration order) into one
`@ClassName_staticinit()` per class, called once per class in `prog.Body`
order at the very start of `EmitProgram`'s Pass 3, before any top-level
statement runs.

**Static member dispatch**: a bare class-name identifier in
`MemberExpression.Object`/`CallExpression.Callee` position is a
compile-time namespace, exactly like the pre-existing `Math`/`JSON`/`Date`
bare-identifier checks in `emit_call.go` — checked first, before any
generic `mem.Object` evaluation, since a class name is never a real
runtime value bindable via `e.lookup`/`inferExprType`. Added symmetrically
at four sites: `emit_call.go`'s `emitCall` (static method calls),
`emit_exprs_member.go`'s `emitMember` (static field reads),
`emit_exprs_assign.go`'s `emitAssign` (static field writes), and
`emit_exprs_types.go`'s `inferExprType` (both the field-read and
call-return-type cases).

**`private`/`protected`**: compile-time-only, zero runtime check ever
emitted — matches real TypeScript's own erasure exactly. One shared helper,
`checkMemberVisibility(originClass, vis, kind, name, pos)`
(`emit_classes.go:259`) — a no-op fast path when `vis == ""` (public, the
common case). Needs "which class is this code lexically inside" for both
instance and static contexts; `"this"` doesn't work for statics (no
receiver), so `emitClassMember`/`emitClassStaticInit` unconditionally bind
a new `Ptr`-less scope symbol `"__kml_enclosing_class"` — the same
established "`Symbol` with only `Ty` set, used purely for lookup" idiom
`registerClasses`' own return-type inference already used for a bare
`"this"`. `private` requires an exact class match; `protected` requires a
match or the enclosing class to have `originClass` in its `AncestorChain`;
top-level code (no enclosing class at all) fails both. Wired into six call
sites: instance field read (`emitMember`, `emitOptionalMember`) and write
(`emitAssign`), static field read/write (`emitStaticFieldRead`/
`emitStaticFieldAssign`), instance method call (`emitClassCall`), and
static method call (`emitStaticMethodCall`). This one check, with no
special-casing anywhere, correctly rejects `super.privateMethod()` too:
`emitSuperMethodCall` routes through `emitClassCall`, whose enclosing class
is the *subclass* — a private check on the *base*'s member is right to
refuse that, verified directly (`TestE2ESuperPrivateMethodIsError`). A
**private constructor** falls out of the same mechanism at near-zero extra
cost (`emitNewExpression` gained one check against
`info.Constructor.Visibility`) — a real, useful pattern (factory/
singleton), confirmed working end-to-end
(`TestE2EClassPrivateConstructor`).

**`abstract`**: reuses Stage 3's whole-program override-detection machinery
almost entirely for free — an abstract method (`Body == nil`, parsed via a
`bodyOptional` variant of `parseFunctionRest` terminated by `;` instead of
`{...}`) follows the exact same "declares a method name" path as a concrete
one; any concrete override anywhere in the tree is *already* detected as an
override of it, automatically marking it `Virtual` and giving it a vtable
slot with zero new dispatch logic. What's actually new: `emitNewExpression`
rejects `new AbstractClass()`; after building a class's effective method
table, a non-abstract class errors if any entry's backing declaration is
still a bare stub ("class X does not implement abstract method Y inherited
from Z"); `emitClassDecl` skips emitting a function for any `Body == nil`
method (nothing to emit — a genuine correctness requirement, not just
tidiness: without this, `emitClassMember`'s body-emission loop would
nil-dereference on `body.Body`); and `emitClassVTable` is skipped entirely
for an abstract class (its own vtable, if built, would need a slot pointing
at its own never-emitted stub — since no instance of it can ever exist, the
simplest correct fix is not emitting the vtable at all, not null-filling a
slot nothing will read).

**`implements`**: the genuinely new subsystem. `InterfaceDeclaration`
gained `Methods []InterfaceMethodSig` (a new lightweight signature-only
node — no body, ever); `parser_types.go`'s `parseInterfaceDecl` member loop
now mirrors `parser_classes.go`'s existing field-vs-method dual branch
(`IDENT` then `LPAREN` → method signature, else `COLON` → field). A new,
purely additive registry `e.interfaceMethodSigs
map[string]map[string]FuncSig` is built alongside the existing
`registerInterfaces`, reusing `buildParamSig` — deliberately kept separate
from `e.interfaces` (the shared `map[string]Type` classes/interfaces/type-
aliases all use for name resolution) so nothing about that existing
mechanism changes. Conformance checking (`registerClasses`' Pass 1, once a
class's own effective field/method tables are built) is explicitly scoped
as a **compile-time-only self-check** — does class `C` already have the
right shape — not a mechanism for polymorphic dispatch through an
interface-typed reference; a `Greeter`-typed variable holding a class
instance still doesn't call through to the class's methods after this
change, only `class Foo implements Greeter` itself gets validated at
declaration time. Every interface field needs a same-name, IR-compatible
match in the class's `FlatFields`; every interface method needs a
same-name match in `MethodSigs` passing the exact same `sigCompatible`
check Stage 3's override validation already uses — fails fast on the first
mismatch.

## Implementation notes

Files touched: `lexer/token.go` (`STATIC`/`PRIVATE`/`PROTECTED`/`PUBLIC`/
`ABSTRACT`/`IMPLEMENTS`); `ast/nodes.go` (`AnnotField.{Static,Visibility}`;
`FunctionDeclaration.{IsStatic,Visibility,IsAbstract}`;
`ClassDeclaration.{IsAbstract,Implements,StaticBlocks}`;
`InterfaceDeclaration.Methods`; new `InterfaceMethodSig`);
`parser/parser_classes.go` (a modifier-token loop before each member,
`static { ... }` recognized by peeking `LBRACE` immediately after `static`
before any member name is consumed, optional `implements A, B, ...`
clause); `parser/parser_stmts.go` (`abstract class` prefix dispatch,
`parseFunctionRest` gained a `bodyOptional` parameter); `parser/parser_types.go`
(interface method-signature parsing); `codegen/llvm/emit_classes.go` (the
bulk: `ClassInfo`'s ~15 new fields — static tables, `FieldOrigin`,
visibility maps, `IsAbstract`, `Implements` — `registerClasses`' Pass 1
extended in place rather than as a new pass, since static-member
inheritance needs the exact same base-before-derived topological walk
instance members already use; `checkMemberVisibility` and its supporting
`checkFieldVisibility`/`emitStaticFieldRead`/`emitStaticFieldAssign`/
`emitStaticMethodCall` helpers; `emitClassStaticFieldGlobals`/
`emitClassStaticInit`); `codegen/llvm/emitter.go` (`registerInterfaces`
extended for method signatures; `EmitProgram` gained the static-field-
global/static-init emission pass and the static-init call-out at the top
of Pass 3); `emit_call.go`/`emit_exprs_member.go`/`emit_exprs_assign.go`/
`emit_exprs_types.go` (the class-name-as-namespace early check, four
symmetric sites).

Non-obvious: `ownFields` in `registerClasses`' Pass 1 changed from a
fixed-size `make([]Field, len(cd.Fields))` indexed by position to an
`append`-built slice, since `cd.Fields` now mixes instance and static
declarations (`f.Static` routes to the separate static-table-building
branch, `continue`s past the instance-field append) — a fixed-index array
would have left gaps or panicked once static fields started being skipped
mid-loop.

## Side effects discovered

None found beyond what's already covered above — no fan-out bugs this
time (unlike [ADR-00082](ADR-00082.md)'s 15-site hand-written-IR fan-out or
[ADR-00083](ADR-00083.md)'s `instanceof` static-descendant gap), likely
because Stage 4 deliberately builds on Stage 3's already-hardened
override/dispatch machinery rather than introducing a second one.

## Verification

- `tests/classes_test.go`: 16 new E2E tests — static field/method
  read+write+inheritance+override, a `static {}` block, private/protected
  positive and negative cases (unrelated class, top-level code,
  `super.privateMethod()`), a private constructor (positive and negative),
  abstract method override + direct-instantiation rejection +
  missing-override rejection, and `implements` (positive, missing method,
  missing field).
- `examples/classes/classes.ts` extended with one representative example
  per sub-feature (a `Registry` static counter with a `static {}` block, a
  `BankAccount`/`NamedSavingsAccount` private/protected pair, an
  `abstract class Shape2`/`Square` pair, and a `Dog implements Greeter`) —
  every line's inline expected-output comment verified against the actual
  compiled binary's output.
- Manual smoke testing beyond the permanent suite: static-field sharing
  across `extends` confirmed by mutating through the derived class's name
  and reading it back through the base's; every negative-path error
  (private field from an unrelated class, protected field from an
  unrelated class, private field from top-level code,
  `super.privateMethod()`, private static field from an unrelated class,
  a private constructor called from outside, direct instantiation of an
  abstract class, a concrete class missing an abstract override, two
  separate `implements` conformance failures) triggered by hand and read
  for message accuracy.
- `go build -o klainmain . && go vet ./... && go test ./...` all green —
