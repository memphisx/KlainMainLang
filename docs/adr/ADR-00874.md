# ADR-00874: URL WHATWG normalization, static parse/canParse, and JSON toJSON

- **Relations**: `Implements TDD-00203`, `Extends ADR-00076`
- **Date**: 2026-09-11

## Context

`URL` was a libcurl passthrough (ADR-00076): every field read back verbatim, so
no WHATWG normalization happened. The status page disclosed the shape of this but
overstated the surface — three concrete gaps the WPT `url/` oracle (ADR-00871)
named: a default port was kept (`new URL('http://x:80/').port` was `'80'`, Node
`''`), the host case was not lowercased (`HTTP://ExAmple.COM` kept its case), the
WHATWG static methods `URL.parse`/`URL.canParse` were absent, and
`JSON.stringify(url)` dumped the component struct instead of honoring
`URL.prototype.toJSON()` (which returns `href`).

## Investigation

Probed libcurl directly with a small C program on this build: curl already
lowercases the *scheme* but not the *host*; `CURLU_NO_DEFAULT_PORT` (verified
`= 2`) strips a default port from both the port part and the full-URL read; and a
non-special scheme (`new URL('foo:bar')`) is rejected by curl with `CURLUE_BAD_SCHEME`
— so faithful non-special-scheme parsing would require abandoning libcurl for a
hand-written WHATWG parser (a separate, much larger piece, recorded as blocked in
TDD-00203, not attempted here). `JSON.stringify` already honors a `toJSON` for
user classes and Date, and `URLType` already carries an `IsURL` marker.

## Decision

In `deriveURLFieldsIntoObject`: read the host, ASCII-lowercase it via
`__kml_tolower`, and write it back into the curl handle (guarded on the host
being present — a file:// URL has none) so every derived field reads the
normalized form; read the port and the href with `CURLU_NO_DEFAULT_PORT` so a
default port is stripped everywhere.

Add `URL.parse(input[, base])` and `URL.canParse(input[, base])` as static
methods dispatched off the `URL` identifier (`emit_call.go`), sharing a
non-throwing parse core (`emitURLStaticParse`) — unlike `new URL()`, they never
throw: `canParse` returns a boolean, `parse` returns a `URL | null`. Distinct
from the legacy lowercase `url.parse()` module function.

Give `JSON.stringify` an `IsURL` case (`emit_call_json.go`) that serializes the
`href` field (field 0 of `URLType`) as a JSON string, matching `toJSON`.

## Implementation notes

- `curlURLGetPartFlag` generalizes `curlURLGetPart` with an explicit
  `curl_url_get` flag; `curluNoDefaultPort = 1<<1`.
- The host lowercase/set-back and both flagged reads happen before the existing
  field derivation, so href/host/hostname/origin all reflect the normalized host
  and stripped port with no further change.
- `emitURLStaticParse` accumulates an `ok` bit across the `curl_url_set` calls
  (base then url) rather than throwing; `parse` branches on it to build the object
  or yield null. Return-type inference for both statics added in
  `emit_exprs_types.go` (`canParse` → boolean, `parse` → `URL | null`).

## Side effects discovered

The host lowercase initially ran `__kml_tolower` unconditionally on a
possibly-null host pointer, segfaulting a file:// URL round-trip (no host) — fixed
by moving it inside the host-present branch.

## Verification

macOS (Apple Silicon). Verified directly: default-port stripping (http:80,
https:443) and preservation of a non-default port; host lowercasing;
`URL.canParse` valid/invalid/relative-with-base; `URL.parse` valid (href)/invalid
(null); `JSON.stringify(new URL(...))` → the quoted href. New E2E tests in
`tests/url_test.go`; the existing URL suite (setters, base resolution, file URLs)
still passes. WPT `url/`: `url-tojson` now passes; `url-statics-*` remain blocked
only by the untyped mixed-array test tables they iterate (the D1 any gap), not by
the statics themselves (verified working directly). Node oracle unaffected.
