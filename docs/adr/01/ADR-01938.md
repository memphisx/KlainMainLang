# ADR-01938: `-g` debug and `-lto` link-time-optimized builds of the program and its runtime

- **Relations**: Implements TDD-00230, Extends ADR-01937
- **Date**: 2026-10-28

## Context

TDD-00230's Phase 4 compiles the runtime once into cached objects, links it with LTO, and asks for a `-g -O0` debug variant of it. Every compile hard-coded `-O2`: the program's IR, the library objects, each runtime unit's cached object and a lazy import's shared library. A runtime crash could only be chased through stderr and sanitizer builds.

## Investigation

- `main.go` passed `-O2` in four places: the link line, `libFlags`, `CachedObject`'s compile flags and the island libraries.
- `CachedObject` (`codegen/llvm/cobj_cache.go`) already keys an object on its compile flags, so a `-g -O0` object never meets an `-O2` one. However, each unit compiles from a per-process scratch `.c` that is deleted afterwards. The debug info then names a file that no longer exists.
- macOS keeps DWARF in the objects and needs `dsymutil` after the link. The program's own object was clang's temporary from compiling the `.ll` inline, which is gone by the time `dsymutil` would run.
- First attempt: precompile the `.ll` to a kept object as soon as the link line is built.
  - The link then failed on `__kml_absent_array_cell`, referenced from a library object.
  - Dumping `SplitLibUnits` for the same program showed the split is right: the program unit defines the cell `hidden`, and the library units declare it `external`.
  - The precompile simply ran before `LibObjects` rewrites the `.ll` into the program's own unit, so it compiled the unsplit text, where the cell is still `internal`.
  - At `-O2` the same mistake would not surface, because the reference folds away.

- LTO, measured on the Mac with a Map/sort/object-key benchmark:
  - A warm compile takes 13.1 s with ThinLTO against 1.8 s without, because every link re-optimizes the bitcode of the library and the runtime.
  - The run time is unchanged (1.33 s either way) and the binary grows by 0.7%.
  - On the Linux boxes, clang 18 links bitcode through the gold plugin or lld, and both are installed.

## Decision

- `-g` sets the code-generation flags of every compile to `-g -O0` instead of `-O2`: the program, the library objects, the runtime units and the island libraries.
- A debug runtime object keeps its source beside it, as `<name>-<key>.c` next to `<name>-<key>.o`. The object's DWARF therefore names a file a debugger can open.
  - The source is written atomically.
  - The cache key carries the source mode, so a debug object compiled before sources were kept is never reused.
- On macOS (host target), a `-g` build compiles the program's unit to a kept object just before the link, after the library split. It then runs `dsymutil` to write `<bin>.dSYM` beside the binary. A `dsymutil` failure is a warning, not an error.
- `-lto` adds `-flto=thin` to the same code-generation flags. Every object becomes bitcode (cached apart from native objects through the flag-keyed cache), and the link optimizes them together. On Linux the link goes through lld when `ld.lld` is installed.
  - It is opt-in, not the default: on today's runtime it slows every compile about sevenfold for no measured run-time gain.
  - Observable behavior is the same either way.
- The generated program code carries no debug metadata yet, so `-g` gives source-level line info for the runtime's C only.

## Implementation notes

- `main.go`: the `-g` and `-lto` flags, `codeFlags` replacing each `-O2`, the macOS precompile (placed right before `RunLink`), `dsymutil`, and lld for an LTO link on Linux.
- `codegen/llvm/cobj_cache.go`: the kept-source mode, `writeFileAtomic`, and the source mode in the cache key.
- `README.md`: both flags' entries.

## Side effects discovered

None beyond the ordering trap above.

## Verification

- `tests/build_modes_test.go` `TestE2EDebugBuild` builds a program with `-g`, checks that its output matches the optimized program's, and reads the DWARF. On macOS it reads the dSYM through `debug/macho`; on Linux it reads the binary through `debug/elf`. Every runtime compile unit must name a source that exists. Passes on the Mac and on Linux (DeskMini container, Ubuntu 24.04 x86-64, clang 18).
- `TestE2ELTOBuild` builds a program with `-lto` and checks its output against Node's (a Map, a sorted array, an object with an added property, an awaited promise). Passes on the Mac and on Linux (DeskMini, through lld).
- By hand on the Mac: a `-g` build of a boxed-promise probe matches Node's output, and its dSYM holds 41 compile units.
