# ADR-00155: `#x` private names

- **Relations**: Implements [TDD-00021](../tdd/TDD-00021.md); Extends [ADR-00153](ADR-00153.md) (Test262 full-corpus conformance harness)
- **Date**: 2026-08-11

## Context

After ADR-00154 (object literal string/numeric-literal keys), the next-largest realistically-scoped Test262 failure bucket was `unexpected character '%s'` (4,023 files) — confirmed by directory breakdown to be almost entirely `#` (class private names), not `@` (decorators, only ~3 files, `staging/decorators`). Unlike the still-undesigned mega-buckets (function expressions, generators, class expressions, Temporal/Intl), this one already had a complete, not-started design — TDD-00021 — that explicitly identified most of the needed machinery as already built by the `private`/`protected` keyword-modifier work (TDD-00009 Stage 4, ADR-00084): `FieldOrigin`/`OwnFieldVisibility`/`checkMemberVisibility` already implement exact-class-only access control, keyed generically by name string.

## Investigation

Confirmed TDD-00021's own three "not started" deltas still held against current code: no lexer handling for `#` anywhere (`lexer/lexer.go`), every member-name and property-access parse site hard-required `lexer.IDENT` (`parser/parser_classes.go`'s member loop, `parser/parser_exprs.go`'s `expectPropertyName` — the single choke point for both `.prop` and `?.prop`), and `VisibleFields()` (`codegen/llvm/types.go`) only stripped a fixed leading-index prefix, no name-based filtering.

## Decision

Implemented TDD-00021 as designed: `#name` is a distinct lexer token (`PRIVATE_NAME`, literal includes the `#`) recognized wherever an identifier could start, but never itself an ordinary identifier. Parser-side, a class member name may be `PRIVATE_NAME` as well as `IDENT` (visibility is then forced to `"private"`; combining `#name` with an explicit `private`/`protected`/`public` modifier is a parse error, matching real TypeScript), and `expectPropertyName` accepts `PRIVATE_NAME` alongside `IDENT`/`DEFAULT`. No parser-level "declared in an enclosing class" lexical-validity stack was built (TDD-00021's own deliberate scope cut) — an invalid `#name` reference is a `registerClasses`/`checkMemberVisibility`-time compile error instead, same as `super` misuse already is. Reflection (`VisibleFields`) now additionally filters any field whose name starts with `#`, on top of its existing index-based skip — the one genuinely new runtime-observable behavior `#x` needs beyond what `private` already provided.

One deviation the TDD didn't need to consider, found during implementation: a private name's literal `#` isn't a legal character in a bare LLVM identifier. Every call site that builds a method/static-field LLVM symbol from a name (`codegen/llvm/emit_classes.go`, `emit_generics.go`) now routes through a new `llvmSafeSymbol` helper, substituting `#` for the `__kml_priv_` reserved-namespace prefix (same non-collision convention `accessorMethodName`'s own `__kml_` prefix already established) — a no-op for any symbol with no private name in it.

## Implementation notes

- `lexer/token.go`/`lexer.go`: new `PRIVATE_NAME` token type; `readPrivateName` reuses `readIdent`'s scan loop after consuming the leading `#`; only recognized when `#` is immediately followed by an identifier-start character (`#1` stays an "unexpected character" rejection, not a mis-lex). Added to `regexIllegalAfter` alongside `IDENT` — `obj.#x / 2` is division, not the start of a regex literal.
- `parser/parser_classes.go`, `parser/parser_exprs.go`: the two sites TDD-00021 named. A third site needed a matching widen not called out by the TDD: the `get`/`set` contextual-accessor lookahead (TDD-00030) only checked for `IDENT` after `get`/`set`, so `get #x()` (a private accessor — valid real JS) failed to parse; widened the same lookahead to accept `PRIVATE_NAME` too.
- `codegen/llvm/types.go`: `VisibleFields()` restructured around a `switch` (behavior-preserving) with a private-name filter pass appended, skipped entirely when no field starts with `#` (avoids a reallocation on the by-far-common case).
- `codegen/llvm/emit_classes.go`, `emit_generics.go`: `llvmSafeSymbol` applied at all 7 sites that concatenate a method/static-field name into LLVM symbol text (instance/static method definition and call sites, vtable slot entries, static field global declaration/read/write, the generic-class method-definition path).
- Beyond TDD-00021's own explicitly-scoped V1 (which named static private fields as "a natural, low-risk follow-on... not designed further here"): verified directly that static `#x` fields/methods already work end-to-end once the same `llvmSafeSymbol` fix covers the static-field global-variable sites (`emitStaticFieldRead`/`emitStaticFieldAssign`/`emitClassStaticFieldGlobals`) — cheap enough, given the mechanism already existed, that shipping it now was preferable to a partial implementation that compiled to invalid LLVM IR (a `static #x` field's global-variable name hit the identical unescaped-`#` problem methods did, independently discovered while checking the feature didn't silently miscompile if used).

## Side effects discovered

Regenerating the conformance report moved overall passed count from 4,474 to 4,474 — no net change, same cascading-blocker pattern ADR-00154 already found. The raw `unexpected character '#'` blocker itself dropped from ~4,023 to 990 matches in a direct corpus scan (not all `#`; some residual non-`#` characters share the bucket) — a real, large syntax-level win — but the overwhelming majority of real-world `#`-using code (including virtually all of Test262's own private-field tests) uses ES2022 class-field-initializer syntax (`#x = 1;`, no separate constructor assignment), which this compiler doesn't support for *any* field, private or public — a much larger, pre-existing, entirely separate gap (`docs/status/LANGUAGE-CONSTRUCTS.md`'s classes row: "no field initializer syntax yet"). `#x` parsing being real and correct doesn't help a file blocked one step earlier by that unrelated wall.

Diffing per-file pass/fail against a stashed baseline (same instrumented-dump method as ADR-00154, reverted before landing) found 2 newly-passing files (both genuine: a nested class's own `#m` not colliding with an outer class's `#m` of the same name, confirming per-class scoping; `static #prototype()` correctly *not* rejected — the real "prototype" static-name ban only applies to public static members) and 2 newly-failing ones, both narrow early-error syntax rules this compiler doesn't implement and TDD-00021 didn't scope: `language/statements/class/elements/syntax/early-errors/grammar-privatemeth-duplicate-meth-staticmeth.js` (real JS: an instance private method and a static private method of the same class share one private-name namespace — declaring both `#m()` and `static #m()` in the same class is a `SyntaxError`; this compiler tracks static/instance methods in separate maps with no cross-check) and `grammar-static-private-meth-constructor.js` (real JS specifically bans `"#constructor"` as any private name, static or not; not checked here). Both were previously "passing" only because the blanket pre-`#`-support rejection coincidentally produced the expected `SyntaxError` for an unrelated reason — same pattern as ADR-00154's `__proto__`-duplicate finding. Noted here as real, narrow, deferred gaps rather than fixed or silently dropped.

## Verification

- `go build`, `go vet ./...`, full `go test ./...` — all pass.
- New tests: `lexer/lexer_test.go`'s `TestPrivateName` (tokenization, including the `#1`-isn't-a-private-name negative case); 12 new E2E tests in `tests/classes_test.go` covering field/method/static-field/accessor private names, same-class coexistence with a same-stemmed public name, cross-instance-same-class access (privacy is per-class not per-instance), reflection-hiding (`JSON.stringify`/`Object.keys`), and four negative cases (outside-class access, subclass access, undeclared name, modifier+`#` combination).
- `examples/classes/classes.ts` extended with a `#x` section (fields, private methods, reflection-hiding, same-stem coexistence, static private fields, private-backed accessors); built and ran directly, output matches the file's own inline comments exactly.
- Full Test262 corpus re-run; before/after per-file diff via the same temporary debug-dump instrumentation ADR-00154 used (not landed), isolating the two early-error gaps documented above from noise.
