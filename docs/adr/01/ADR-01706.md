# ADR-01706: Array callbacks read the live array

- **Relations**: `Implements TDD-00230`; `Extends ADR-00573`
- **Date**: 2026-10-18

## Context

These array methods loaded the array's data pointer once, before their loop: `forEach`, `map`, `filter`, `reduce`, `reduceRight`, `some`, `every`, `find`, `findIndex`, `findLast` and `findLastIndex`.

A callback that grows the array reallocates its data. The loop then kept reading the old, freed buffer. Node reads each element through the array (spec `Get(O, k)`).

On the Mac, `['Skateboard','Barefoot'].findLast(…)`, with a callback that pushes and then sets `a[0]`, segfaulted. It is the Test262 `array-altered-during-loop.js` case.

The callback's third argument was also a fresh header over the old data, not the array itself.

## Decision

- **The live header.** For a plain array (not a typed, flat or nullable one), the walk keeps the array's header, which is the array object (`hofLiveHeader`). Each step re-reads its data pointer and length (`hofLiveGep`).
- **An index past a shrunk length.**
  - It is skipped for the methods whose spec step checks `HasProperty`: `forEach`, `map`, `filter`, `reduce`, `some` and `every`.
  - For the `find*` methods it reads the element type's miss value. This is `undefined` for a dynamic element, but 0 or null for a scalar one, since a typed `number` cannot hold `undefined`.
- **The third argument** is the array itself (`hofCBArgs`).

## Consequences

The remaining divergence is the scalar `find*` case. It is listed in the BACKLOG.

## Verification

macOS (Apple Silicon): the probes match Node's output. They cover growth, shrinking, writes through the array and through a member (`o.xs`), and the third argument's identity. `TestE2EArrayCallbackMutatesArray` passes, and so do the 51 existing callback-method tests.
