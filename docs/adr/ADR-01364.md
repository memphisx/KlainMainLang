# ADR-01364: JSON.stringify escapes an embedded NUL

- **Relations**: Fixes the JSON string quoting of TDD-00077
- **Date**: 2026-10-03

## Context

`JSON.stringify("a\u0000b")` gave `"a"` where Node gives `"a\u0000b"`. Found
while checking that a Blob's `text()` keeps NULs (ADR-01362).

## Investigation

- The static quoting (`coresrc/json.c`, `__kml_json_str_str`) bounded the
  string by `strlen`. Its comment said not every runtime string has a
  length header. That is no longer so: `__kml_str_len` reads the header of
  every string, and the same file's concatenation uses it.
- The dynamic serializer (`dynjson.c`) quoted a string value through
  `strlen` too.

## Decision

Both bound a string value by its length header, so a NUL is escaped as
`\u0000`. Object keys keep `strlen`.

## Implementation notes

`codegen/llvm/coresrc/json.c` and `dynjsonsrc/dynjson.c`.

## Verification

Mac (Apple Silicon), against Node 24: a NUL string as a value, an object
member and an array element, statically and through `any`
(`TestE2EJSONStringifyEmbeddedNul`); the JSON groups.
