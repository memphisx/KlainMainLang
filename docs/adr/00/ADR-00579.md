# ADR-00579: URL base resolution — `new URL(url, base)`

- **Relations**: Extends [ADR-00076](ADR-00076.md), completes the last `URL` caveat
- **Date**: 2026-09-01

## Context

`new URL(url)` accepted a single argument only; the two-argument
`new URL(url, base)` form — which resolves a relative `url` against an absolute
`base` — was the URL row's last remaining caveat. libcurl's URL API already
resolves a relative value set on a handle that holds a base URL, so no new
parsing code is needed.

## Decision

1. `NewURLExpression` gains an optional `Base` field; `parseNewURLBody` accepts a
   second `,`-separated argument. The `resolver/rename` walker recurses into
   `Base` so an identifier base is renamed like any other reference (without
   this, a variable base failed with `undefined variable`).
2. `emitNewURLExpression`: when `Base` is present, seed the CURLU handle with the
   base first, then set the (possibly relative) `url` — curl resolves it against
   the base per the WHATWG algorithm. An absolute `url` simply overwrites the
   base. Both sets throw a catchable "Invalid URL" Error on failure, matching
   Node, which throws `ERR_INVALID_URL` for both an invalid base and an invalid
   relative URL. The base is evaluated before the handle is created so its side
   effects order first.

## Verification

New `TestE2EURLBaseResolution` (relative path, relative segment, absolute
override, `../` resolution through a variable base, invalid-base throw, and the
one-arg form still working); outputs compared byte-for-byte against real Node
v26. The existing URL suite still passes. Built and verified on Mac (Apple
Silicon).
