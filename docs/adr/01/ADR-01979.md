# ADR-01979: Mixins

- **Relations**: Implements TDD-00230 (P2.7); follows [ADR-01978](ADR-01978.md)
- **Date**: 2026-11-07

## Context

A mixin is a function that returns a class extending its argument:
`function Timestamped(Base) { return class extends Base {} }`. Codegen
rejected it, because the class's base is a value known only at run time,
and a class's layout here is fixed at compile time. The parser also
rejected a base written as a call, `class Admin extends Timestamped(User)`.

## Decision

- The parser takes a call as a class's base. Right after parsing, the
  call is bound to a constant declared just before the class (`const
  Admin__kml_base = Timestamped(User)`), and the class extends that
  constant. JavaScript evaluates the heritage expression once, where the
  class is defined.
- Before checking, each call of a mixin is specialized for its argument:
  - A mixin is a top-level function, or a constant holding an arrow or a
    function expression, with a parameter that a class in its body
    extends.
  - A call whose argument is a top-level class, or a constant holding a
    mixin's result, calls a copy of the mixin made for that argument. In
    the copy, the parameter names the class.
  - A mixin that is no longer named anywhere is removed.
- A class extending a top-level constant takes the class the constant
  holds when the constant is a call of a function whose every `return`
  names one class. This is how mixins compose (`Tagged(Timestamped(User))`
  through constants).
- A deep copy of an AST tree is `ast.Clone`.

## Consequences

- Covered by `TestE2EMixins` and `examples/classes/mixins.ts`, both
  matching Node.
- A mixin applied to a value that is not a class at compile time (another
  function's parameter, a conditional) is still rejected.
