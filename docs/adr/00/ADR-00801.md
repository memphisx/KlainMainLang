# ADR-00801: `server.listen(options)` object form with host/backlog

- **Relations**: `Implements TDD-00131`, `Extends ADR-00503`, `Extends ADR-00514`
- **Date**: 2026-09-09

## Context

The Node `http` server exposed only the positional `server.listen(port?,
callback?)` form. Node also accepts an options object —
`server.listen({ port, host, backlog, exclusive }[, callback])` — which real
code uses constantly (`server.listen({ port: 3000, host: '127.0.0.1' })`). This
form was a clean rejection, and the server always bound `INADDR_ANY` (`0.0.0.0`)
with a hard-coded `listen(2)` backlog of 128, so there was no way to bind a
specific interface. This is the smallest slice of the "options mostly rejected"
caveat on the HTTP-server status page (backlog item §1.3).

## Investigation

The single bind helper `@__kml_http_bind_and_listen(i32 port)`
(`codegen/llvm/runtime_http.go`) constructs a `sockaddr_in` with `s_addr` left
zero by the `memset` — i.e. `INADDR_ANY` — and calls `listen(fd, 128)`. Both the
chained (`createServer(cb).listen(...)`) and variable-bound
(`emitHTTPServerListen`) paths route through it. `server.address()`
(`emit_net.go:271`) already reads the real bound address back via `getsockname`,
so a specific-host bind is observable end-to-end with no extra plumbing on the
read side.

Binding a *hostname* would need `getaddrinfo` (DNS) — out of scope here. But a
numeric IPv4 literal parses to its `s_addr` word at compile time with no runtime
support, which covers the common `'127.0.0.1'` / `'0.0.0.0'` / `'localhost'`
cases faithfully.

## Decision

Extend the bind helper to `@__kml_http_bind_and_listen(i32 port, i32 hostaddr,
i32 backlog)`: `hostaddr` is a network-order IPv4 `s_addr` word (0 =
`INADDR_ANY`), stored into `sockaddr_in` bytes 4–7; `backlog` replaces the
literal 128 in the `listen()` call. `klain:http`'s bespoke `http.listen` always
passes `0, 128` (host/backlog selection is a Node-shape feature, not part of the
bespoke re-imagining).

`emitHTTPServerListen` gains an options-object branch: when the first argument is
an **object literal**, `parseHTTPListenOptions` reads `port` (any expression),
`host` (a string literal → `parseIPv4ToNetworkWord`), `backlog` (a non-negative
integer literal), and accepts `exclusive` as a statement of existing behavior
(this server never sets `SO_REUSEPORT` outside cluster workers). A non-literal
options value is rejected (the `host` word must be resolved at compile time); a
hostname that isn't a dotted-quad IPv4 is rejected pointing at the
no-DNS limitation; unknown keys (and `path`, i.e. Unix-socket listen) are
rejected rather than silently ignored.

`parseIPv4ToNetworkWord` maps `""`/`"0.0.0.0"`/`"::"` → 0, `"localhost"` →
`127.0.0.1`, and any dotted-quad `a.b.c.d` → `a | b<<8 | c<<16 | d<<24` (the
little-endian in-memory layout of the network-order word on both target arches,
x86-64 and arm64). It rejects leading-zero octets and out-of-range values.

## Implementation notes

- `runtime_http.go`: signature + `s_addr` store + `%backlog` in `listen()`; doc
  comment updated.
- `emit_http.go`: `parseHTTPListenOptions` / `parseIPv4ToNetworkWord` helpers;
  the options branch in `emitHTTPServerListen`; both bespoke and Node call sites
  updated to the 3-arg helper. Added `strconv` import.
- The Windows inherited-fd fast path (`httpListenInheritIR`) returns before the
  bind, so it ignores host/backlog — correct, since a worker adopts an
  already-bound socket.

## Side effects discovered — and fixed

An expression-bodied handler arrow whose body is a void-returning `res` call —
`http.createServer((req, res) => res.end('x'))` — emitted `ret i64` with no
value (invalid IR). Pre-existing and independent of the listen work (it
reproduces with positional `listen(0)`); block-bodied handlers were unaffected.

Root cause: an expression-bodied arrow infers its return type from
`inferExprType(body)` (`emit_func.go`), and `inferExprType` special-cased only
`res.write` (→ `bool`), letting every other `ServerResponse` method
(`writeHead`/`setHeader`/`end`/`cork`/`uncork`) fall through to the scalar
`i64` default — even though `emitServerResponseMethod` returns `void` for them.
The arrow was then declared `i64`-returning but its body produced no value.

Fixed in `emit_exprs_types.go`: a `ServerResponse` method call now infers
`bool` for `write` and `void` for every other method, matching the emit path, so
the arrow infers `void` and takes `emitClosureFunc`'s existing `retTy.IR ==
"void"` → `ret void` branch. Covered by
`TestE2EHTTPExpressionBodiedHandler`.

## Verification

Mac (Apple Silicon). `tests/http_test.go`
`TestE2EHTTPServerListenOptionsObject` (binds `127.0.0.1`,
`address().address` reflects it), `TestE2EHTTPServerListenOptionsDefaultHost`
(no host → `0.0.0.0`), and `TestE2EHTTPExpressionBodiedHandler` (the void-return
fix) pass; the full `TestE2EHTTP*` plus arrow/closure/function suites are green
and `go vet ./codegen/...` is clean. All four expression-bodied `res` methods
(`writeHead`/`setHeader`/`write`/`end`) compile and run.
`examples/http/listen_options.ts` compiles and prints the loopback bind.
