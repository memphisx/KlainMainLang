# ADR-02003: Compiler peak memory on a whole-library module

- **Date**: 2026-11-21

## Context

`examples/globals/namespace_values.ts` boxes the global object, so its module
holds every builtin library module: 119 MB of IR. Compiling it peaked at
1.45 GB resident (Linux x86, Node304); the crypto and http examples peaked
near 1 GB. A compile that size cannot run beside a test suite under the Mac's
3 GB budget.

## Investigation

- A heap profile at the Go heap's peak: the live data near 300 MB is the
  module text and its units; the rest is garbage. The garbage is a full copy
  of the module from each pass over the finished text. `markNoTail` rewrote
  every call, the three managed-address-space passes copied the module one
  after another, `declareCalled` split it into a line slice, and `main.go`
  converted it to `[]byte` to write it and back to a string to split it.
- The default collector pacing lets the heap grow to twice its live size
  between collections, so the copies show up as resident memory.

## Decision

- Calls are marked `notail` as the module is written (`noTailWriter`), not
  by a rewrite of the finished module.
- The managed-space rewrites run as one line-by-line pass that copies the
  module once; a line none of them touches is copied through unchanged.
- `declareCalled` walks the lines with `strings.SplitSeq`.
- The IR file is written from the string, and read back as a string over
  the bytes read, with no extra copy.
- The emission's buffers are released when the module is assembled. One
  collection runs before the final passes.

A soft heap limit (`debug.SetMemoryLimit`, 640 MB) brought the peak to
760 MB, but cost about 5% compile time on this program, so it is not set.

## Implementation notes

- codegen/llvm/emitter.go: `EmitProgram`; codegen/llvm/runtime_stackguard.go:
  `noTailWriter` (replaces `markNoTail`).
- codegen/llvm/irptr_slots.go: `toManagedSpace`.
- codegen/llvm/declare_calls.go, codegen/llvm/libsplit.go: `readFileString`;
  main.go: `writeStringFile`.

## Verification

- Linux x86 (Node304), `namespace_values.ts`: peak RSS 1.37–1.50 GB at HEAD,
  1.02–1.05 GB now. The emitted IR is the same as the build before these
  changes, every body call is `notail`, and the program's output matches.
- Compile time: 14.2–14.5 s at HEAD, 15.0–15.6 s now. The tree emits 4% more
  IR for this program than HEAD (features added since), and a small program
  (`array_bounds.ts`) compiles in the same time as at HEAD (593–622 ms).
