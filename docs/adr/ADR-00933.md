# ADR-00933: Array aggregate into a `ptr`-shaped slot is a clean cross-type rejection

- **Date**: 2026-09-14

## Context

The Test262 `Map.prototype.get` "different key types" idiom exercises a single
untyped `var` reassigned across kinds:

```js
var item = {};
item = [];          // <-- invalid IR here
item = Symbol('item');
item = null;
item = undefined;
```

In strict mode this compiled to invalid LLVM IR
(`'%tN' defined with type '{ ptr, i64 }' but expected 'ptr'`) at the
`item = []` store. The binding was promoted to a fixed-shape object global (its
`{}` initializer), then the array aggregate was stored straight into that
`ptr`-shaped slot. It is the last blocker of that Test262 file and one of the
`js`-lane `CLANG_ERROR` entries.

## Investigation

An array Value reports `Type.IR == "ptr"` but is really a `{ ptr, i64 }`
aggregate register (data pointer + length — see `StructFieldIR`'s own note). The
identifier scalar-store path (`emit_exprs_assign.go`) rejects a genuine
cross-type reassignment by comparing `rhs.Ty.IR != sym.Ty.IR`. For an array RHS
into an object/string/handle slot both sides read `"ptr"`, so the guard passed,
`coerce` returned the array Value unchanged (its `.IR` already matched at the
same-IR passthrough, `emit_exprs_coerce.go:139`), and the emitter produced
`store ptr %agg` — the aggregate where a pointer is required.

`-compat=js` is unaffected: `crossTypeWidenedBindings` doesn't cover this shape
either, but the object-literal binding is a D1 dynamic object there, so the
whole binding is an any-box and every store boxes (verified: the repro runs and
prints under `-compat=js`).

## Decision

Extend the scalar-store cross-type rejection to also fire on a storage-shape
divergence the `.IR` string misses: `rhs.Ty.IsArray != sym.Ty.IsArray`. An
array-typed slot takes its own store branch far above this point, so this
`else` branch only ever runs for a non-array slot; an array RHS reaching it is
always the aggregate-into-pointer mismatch. The `describe` helper gained
`array`/`object`/`symbol` labels so the message names the real kinds rather than
`ptr`.

Strict now rejects cleanly with the standard actionable message (annotate
`: any`, or compile with `-compat=js`), matching this compiler's two-tier rule
for a binding that genuinely holds different types.

## Implementation notes

`codegen/llvm/emit_exprs_assign.go`, the non-dynamic branch of the identifier
`=` store. One condition widened, one describe helper extended. No change to the
array-typed-slot branch or to `-compat=js`.

## Side effects discovered

`Array.isArray` on a dynamic (`any`) value was computed purely at compile time
and always returned `false` for a boxed array — a separate pre-existing bug
fixed in the same delivery (ADR-00934).
