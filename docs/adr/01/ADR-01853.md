# ADR-01853: Compound assignments and pattern parameters are typed; generator expressions are boxed closures

- **Relations**: `Implements TDD-00230` (P3.3: the checker answers what inferExprType did)
- **Date**: 2026-10-21

## Context

- The checker typed only `=` assignments. Every compound assignment (`c += 1`, `x ??= y`, `n <<= 2`) came back unanswered, and so did any function whose parameter default held one (`(a = count += 1) => …`, a pattern across Test262's default-parameter tests). With function literals now switched to the checker, each such function fell back.
- A generator function expression (`function* () {}`, an object literal's `*m() {}` or `async *m() {}`) is emitted as a boxed constructor closure, but the oracle tried to map the checker's `() => Generator<…>` signature and failed, so every one fell back.

- In the strict lane, an unannotated destructured parameter with a default (`[x, y] = [1, 2]`, `{ a } = { a: 1 }`) was unanswered in the checker, so every function declaring one fell back (static async generator methods in Test262's `dstr` tests among them). Codegen typed the same parameter as a number: `function f([x, y, z] = [1, 2, 3])` failed with an internal compiler error even when called with no arguments, and with a "called with a non-numeric argument" error when passed an array.

## Decision

- `x op= y` is typed as `x op y`, as tsc's checkBinaryLikeExpression does. `checkBinary`'s operator switch moves into `binaryResult(op, l, r)`, which both the binary expression and the compound assignment call.
- The oracle answers a generator function expression with a box, as emission holds it.
- The checker types such a parameter from its default, contextually typed by the pattern as tsc does: an array pattern over an array literal is the tuple of its widened elements (`[number, string]`), otherwise the widened default. The pattern's bindings read the element at their position.
- Codegen's `paramDefaultType` gives the same type: a tuple of mixed element kinds stays positional, one of a single kind is the array codegen builds (the representation the oracle gives an inferred tuple), and an object pattern takes the literal's object type.
- A destructured parameter's default is filled by the caller (`callSiteDefault`), so the oracle drops `undefined` from that parameter in the function type, for a literal, a function declaration and a `const` bound to a literal.

## Consequences

- `TestPatternParameterFromDefault` (checker, with the builtin declarations bound by the new `typeOfLastLib`) and `TestE2EPatternParameterTypedFromDefault` (against Node) cover array, mixed-tuple and object pattern defaults and a static async generator method.
- `TestCompoundAssignmentInParameterDefault` covers a compound and a plain assignment as a parameter default.
- Verified on Apple Silicon (checker package; targeted assignment, operator, default-parameter and generator E2E tests).
