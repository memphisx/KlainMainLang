# ADR-01547: Covariant builtin interfaces relate by type arguments; async expressions that never complete are `Promise<never>`

- **Relations**: Extends TDD-00230
- **Date**: 2026-10-10

## Context

- The checker related two instantiations of a generic builtin
  interface only structurally, and through their generic methods
  (`then<TResult1 = T, …>`) the comparison could not tell them apart:
  `Promise<number>` was accepted as a `Promise<string>`, as were
  `Promise<void>` for `Promise<never>` and `Map<string, number>` for
  `Map<string, string>`. tsc relates them by the interface's measured
  variance (covariant for these) and reports TS2322.
- An async function expression or arrow whose body never completes
  (`async () => { throw 1 }`) was `Promise<void>`; tsc infers
  `Promise<never>` for a non-declaration (a declaration stays
  `Promise<void>`).

- `a = null; a!.push(1)` typed `a!` as `never`; tsc asserts the
  reference's declared type when its flow type is only null/undefined.

## Decision

- Two instantiations of the same builtin `Promise`, `PromiseLike`,
  `ReadonlyArray`, `Set`, `ReadonlySet`, `Map`, `ReadonlyMap`,
  `WeakSet`, `WeakMap`, or iterable/iterator interface relate `no` when
  any type argument does not relate covariantly; otherwise the
  structural comparison decides, as before. (Variance is not measured
  for other interfaces.)
- An async function expression or arrow with no `return` and an
  unreachable end returns `Promise<never>`.
- A non-null assertion on an identifier whose flow type holds only
  null/undefined is the declared type, made non-nullable.

None.
