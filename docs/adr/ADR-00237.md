# ADR-00237: Wire AbortSignal into fetch (Events & Cancellation, stage 3b)

- **Relations**: `Implements TDD-00081` (Stage 3b); `Extends ADR-00236`, `ADR-00050`
- **Date**: 2026-08-19

## Context

Stage 3a shipped the `AbortController`/`AbortSignal` token but did not connect it
to anything ([ADR-00236](ADR-00236.md)). This wires `signal` into `fetch` so
`fetch(url, { signal })` actually cancels.

## Investigation

Execution is strictly synchronous between await points: `fetch()` kicks off a
non-blocking curl-multi transfer and returns a pending handle immediately, and the
wait happens later at `await` inside `__kml_await_fetch` (runtime_fetch.go). So the
awaiting fiber never runs user code while its own transfer is in flight — which
means the reachable, valuable abort cases both reduce to **"the signal is aborted
by the time we await"**: `ctrl.abort(); await fetch(url, {signal})` (aborted before
fetch) and `const p = fetch(...); ctrl.abort(); await p` (aborted before await).
An abort *during* the network wait (a peer fiber, or an `AbortSignal.timeout`)
would need per-spin checks in the await/event loops and is deferred (see Side
effects). There is no `AbortError` kind, but a base `Error` with `name:
"AbortError"` matches how the codebase already fakes named errors.

## Decision

- **`fetch(url, { signal })`** extracts the `signal` init field (validating
  `IsAbortSignal`) and threads it through `emitFetchAsyncCall` → `__kml_fetch_async`.
- The **pending struct** gains a trailing `signal` pointer field (40→48 bytes,
  append-only so every existing field-0..4 GEP is unchanged).
- **`__kml_await_fetch`**, at entry before the wait loop, loads the pending's
  signal; if non-null and its `aborted` byte (AbortSignal field 0) is set, it
  tears the transfer down (`curl_multi_remove_handle` + `curl_easy_cleanup`, the
  pair the drain path already uses) and throws an `AbortError` (`{kind 0, "The
  operation was aborted", "AbortError"}` via `__kml_throw`) instead of waiting.
- The XHR direct caller of `__kml_fetch_async` passes a null signal (XHR has its
  own abort path); the `fetch(request)` form passes null (no signal on Request in
  V1).

## Implementation notes

`__kml_await_fetch_settled` (the non-throwing sibling used by XHR/allSettled) is
deliberately left unmodified — those callers pass a null signal, and the settled
path returns rather than throws. The abort check reads the signal's `aborted`
field as a raw `i8` at offset 0, matching `AbortSignalType`'s layout.

## Side effects discovered

- **Mid-flight and timeout cancellation are not covered.** An abort that lands
  while the awaiting fiber is blocked in the wait loop (a peer fiber calling
  `abort()` during a yield) is not noticed until — and only if — a checkloop pass
  re-examines it, which the entry-only check doesn't do. `AbortSignal.timeout(ms)`
  is unimplemented (no static `AbortSignal` methods) and would need the fetch/timer
  loops (two separate loops today) unified via a per-spin deadline check. Both are
  the remaining Stage-3c follow-on.
- A defaulted `AbortError` DOMException is still not synthesized; `err.name ===
  "AbortError"` works, `instanceof` matches only `Error`.

## Verification

- `tests/abort_test.go`: `fetch` with an already-aborted signal throws
  `AbortError` at the await (no network reached), and abort-after-fetch-before-
  await likewise. Normal `fetch`/XHR/HTTP/Response tests still pass (the pending-
  struct change is append-only).
- `examples/events/fetch-abort.ts` runs correctly; IR verified with `clang`.
- `go build`, `go vet ./...` clean on Apple Silicon (macOS).
