# ADR-02000: A replaced Map, Set, WeakMap or WeakSet method is the one that runs

- **Date**: 2026-11-21

## Context

Test262 `built-ins/Map/iterator-close-after-set-failure.js` replaces
`Map.prototype.set` with a function that throws, then constructs a Map from
an iterator that never finishes. In Node the first `set` throws, the
iterator closes, and the constructor ends. Here the program grew until the
Mac's 1.2 GB per-program cap killed it, which stopped the Test262 js lane
there.

## Investigation

- A method replaced on a collection prototype was never called:
  `Map.prototype.set = f; m.set(1, 2)` ran the built-in `set`, `m.set === f`
  was false, and `new Map(iterable)`, `new Set(iterable)` and the Weak
  constructors added through the built-in adder directly. So the throwing
  `set` never ran and the endless iterator never stopped.
- Node looks up every call on the prototype, and each constructor reads its
  adder (`set` / `add`) once, before getting the iterator. A non-function
  adder is a TypeError: `'<value>' returned for property 'set' of object
  '#<Map>' is not a function`.
- `Map.prototype` as a value lists only the methods the program names
  (proto_reach.go). A constructor that reads `add` from it needs `add`
  listed even where the source never writes `add`.
- HEAD has the same behaviour.

## Decision

A scan of the program (coll_proto_patch.go) finds the collection methods it
may replace:
- an assignment to `Owner.prototype.method`;
- a computed-key assignment, an alias of `Owner.prototype`, or
  `Owner.prototype` passed to `Object.defineProperty` / `defineProperties` /
  `assign` or `Reflect.set` / `defineProperty`, any of which counts as every
  method.

Only for those methods:
- a call `recv.m(…)` runs `Owner.prototype.m.call(recv, …)`;
- a read `recv.m` gives `Owner.prototype.m`;
- the constructor reads the adder once, checks that it is callable, and
  calls it with the new collection as `this` for each value the iterator
  yields, inside the `for…of` lowering, so a throw closes the iterator.

Every other method keeps the native fast path. Reading or comparing a
prototype doesn't count as a write.

## Implementation notes

- codegen/llvm/coll_proto_patch.go: the scan, `emitCollProtoCall`,
  `emitCollPatchedSeed`.
- codegen/llvm/emit_intrinsics.go (`emitCollectionIntrinsic`),
  emit_exprs_member.go (method reads), emit_collections.go (Map and Set
  constructors), emit_weak.go (Weak constructors), proto_reach.go (the
  adder is listed on the prototype).

## Verification

- Linux x86 (Node304): `TestE2ECollectionPrototypeMethodReplaced` matches
  Node (js lane). The `Map|Set|Collection|Weak|ClassExtends` E2E tests
  pass.
- Test262, js lane (before → after, both on this tree): Map 140 → 145,
  Set 331 → 335, WeakMap 107 → 111, WeakSet 74 → 78; no program reaches
  the 1.2 GB cap. Strict lane: Map 77, Set 199, WeakMap 67, WeakSet 55.
- Left: a class extending a collection, called through a replaced method,
  is boxed as its class object, which the built-in method's adapter rejects
  as a receiver.
