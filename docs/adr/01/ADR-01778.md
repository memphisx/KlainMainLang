# ADR-01778: Destructured parameters take a default

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- Both parameter parsers (statement functions and methods, arrows and function expressions) rejected `({x, y} = d)` and `([a] = d)` with "a default value on a destructured parameter is not yet supported".
- Codegen already fills a destructured parameter's default at the call site (`callSiteDefault`). Only the parser stood in the way. Test262's `dstr` suites use this form throughout.

## Decision

- Both parsers read the default after a pattern parameter (and its annotation) into `Param.Default`. The diagnostic is deleted.

## Consequences

- `TestE2EDestructuredParamWithDefault` (typed) replaces the test that expected the rejection. `TestE2EJSFileDestructuredParamDefaults` covers functions, arrows, object and class methods, and a default re-evaluated per call.
