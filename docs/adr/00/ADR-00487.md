# ADR-00487: delete operator; fs.mkdirSync recursive

- **Date**: 2026-08-29

## Context

Two process/fs caveats: `delete process.env.KEY` didn't parse (`delete`
wasn't a parser keyword at all), and `fs.mkdirSync` had no
`{ recursive: true }` — it threw on an existing path or a missing parent.

## Decision

- **`delete expr`** parses as a contextual prefix operator (`delete` is a
  JS reserved word, so an IDENT spelling it in prefix position is
  unambiguous). Semantics: `process.env.KEY` unsets for real
  (`unsetenv(3)`); an index-signature/dynamic-object key deletes through
  the backing map (dot and bracket forms, returning the map's had-it
  boolean); fixed-shape fields and array elements are clean rejections —
  static layouts have nothing to delete from.
- **`mkdirSync(path, { recursive: true })`**: a new `__kml_fs_mkdir_p`
  walks the path creating each missing prefix (temporarily NUL-ing at
  each `/`), tolerates already-exists at every step, and throws only when
  the final directory genuinely doesn't exist afterwards (an `access(2)`
  probe). Only the literal `{ recursive: true }` option; anything else in
  the options object is a clean rejection.

Also removed in this pass: the stale "Parameter properties are not
supported" caveat on the Classes row (shipped in ADR-00447).
