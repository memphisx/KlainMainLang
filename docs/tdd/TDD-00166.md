# TDD-00166: `PerformanceObserver` (perf_hooks) — observing performance entries

- **Status**: Partially Implemented
- **Date**: 2026-09-03

V1 shipped ([ADR-00673](../adr/ADR-00673.md)): `new PerformanceObserver(cb)`, `observe({entryTypes})`/`disconnect()`, the global registry `mark`/`measure` walk, and `getEntries()` yielding `PerformanceEntry` objects — **synchronous** dispatch. Follow-ups (Stage 2): async batched delivery, `buffered`/`takeRecords`/single-`type` form, `getEntriesByName`/`getEntriesByType`.

## Context

[TDD-00165](TDD-00165.md) Stage 4 named `perf_hooks.PerformanceObserver` as a
module-only extra to build. Unlike the `url` helpers (localized functions),
`PerformanceObserver` is a small **subsystem**: it needs an entry store, an
observer registry, the observer/list/entry object types, and a dispatch path
that fires an observer's callback when a matching entry is produced. Hence its
own TDD.

Today `performance.mark(name)` records `name → timestamp` in a map and
`performance.measure()` returns a bare number ([emit_date.go]); no
`PerformanceEntry` objects and no entries list exist.

## Design

### Object model

- **`PerformanceEntry`** — a fixed-shape object `{ name: string, entryType:
  string, startTime: number, duration: number }`.
- **`PerformanceObserverEntryList`** — wraps an array of entries; `getEntries()`
  returns it. (`getEntriesByName`/`getEntriesByType` deferred.)
- **`PerformanceObserver`** — a handle holding the user callback and an
  entry-type bitmask (`mark`=1, `measure`=2). `new PerformanceObserver(cb)` is
  recognized in codegen's generic-`new` path by class name (like `Promise`/
  `Proxy`/`WebSocketServer`) — **no parser/AST change**. `.observe({ entryTypes:
  […] })` sets the mask and registers the observer; `.disconnect()` clears the
  mask (unregisters).

### Registry + dispatch

A process-global singly-linked registry (emitted IR: `__kml_perfobs_add` /
`__kml_perfobs_set_mask`, node `{ closure, i32 mask, next }`). `performance.mark`
and `performance.measure` each, in addition to their current behavior, build a
`PerformanceEntry`, then walk the registry and — for every observer whose mask
includes the entry's type — build a one-entry list and invoke the callback.

**Dispatch timing (the load-bearing V1 decision).** Node fires observer
callbacks **asynchronously**, batching all entries produced in a turn into one
callback call at the next microtask checkpoint. V1 dispatches **synchronously**
— the callback runs during the `mark`/`measure` call, once per matching entry.
This delivers the correct entry *data* through the real callback/list/entry
objects, at the cost of Node's async timing and batching. It is chosen because
faithful async dispatch here requires invoking a KML closure with object
arguments from the microtask queue (a trampoline the promise-reaction machinery
has but which isn't yet factored for reuse); synchronous dispatch avoids that and
ships a working, useful observer now. **Async batched dispatch is the documented
Stage-2 follow-up.**

### Scope (V1)

- Entry types `mark` and `measure` only (the entry kinds this compiler produces).
- `observe({ entryTypes: [...] })` array form; the single-`type`/`buffered` form,
  `takeRecords()`, and `getEntriesByName`/`getEntriesByType` are deferred.
- The callback receives the list; the second `observer` argument is omitted (V1).
- `performance.measure` keeps returning its number for back-compat *and* now also
  produces an entry for observers.

## Prerequisites

| Dependency | Status | Notes |

## Open questions

- **Async batched dispatch** (Stage 2): factor the promise-reaction "enqueue a
  call of closure C with value V" into a reusable primitive so the observer
  callback can fire on the microtask queue with a batched list, matching Node.
- **`buffered: true`** replay of entries produced before `observe()` — needs a
  global entry buffer beyond the per-dispatch list; deferred with Stage 2.
