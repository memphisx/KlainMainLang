# ADR-00784: `child_process` spawn `'error'` carries `err.code` and `err.errno`

- **Relations**: Extends [ADR-00754](ADR-00754.md) (the spawn `'error'` event) and the fs error-shape work [ADR-00768](ADR-00768.md)/[ADR-00770](ADR-00770.md) (`err.errno` as the negated libuv value); addresses [TDD-00180](../tdd/TDD-00180.md) OQ2 / BACKLOG §1.2
- **Date**: 2026-09-08

## Context

A failed spawn (a missing command) emits an `'error'` `Error` (ADR-00754), but
that Error carried only `.message` — not Node's `err.code` (`'ENOENT'`) or
`err.errno` (`-2`). The canonical spawn-failure guard `e.code === 'ENOENT'` and
the numeric `err.errno` are the last of the error-shape cluster; fs errors
already carry the negated `errno` (field 8 of the shared `errorObjType`,
ADR-00770).

## Decision

`__kml_cp_spawn_errobj(errno)` (`runtime_childprocess.go`) now fills, besides
message/name, the Node error props on the shared `errorObjType`:

- **`err.code`** (field 3) via `__kml_errno_code(errno)` — the same per-platform
  errno→name map fs uses.
- **`err.errcode`** (field 4) — the positive raw errno (the internal slot, kept
  parallel to fs).
- **`err.errstr`** (field 5) — the `strerror` text (also the message body).
- **`err.errno`** (field 8) — the **negated** errno.
- `err.syscall`/`err.path` (fields 6/7) explicitly null.

The malloc already sized the full `errorObjType`, so no allocation change was
needed — the earlier 6-field fill simply left fields 6–8 unwritten.

## The Linux↔macOS "normalization" question (OQ2)

BACKLOG §1.2 framed the open question as *normalizing codes whose raw number
differs Linux↔macOS (e.g. `EAGAIN` = 11 vs 35)*. The resolution is that on POSIX
**no normalization is needed**: Node's `err.errno` is exactly the negated
platform errno, and Node itself reports different numbers per platform
(`EAGAIN` → `-11` on Linux, `-35` on macOS). Negating the platform errno is
therefore faithful on both. The *code string* is what must stay stable across
platforms, and `__kml_errno_code` already guarantees that — it is built from
Go's per-platform `syscall.E*` constants, so `EAGAIN`'s differing raw number
still maps to `'EAGAIN'` on each host. The libuv-negative-vs-CRT divergence is a
**Windows-only** concern (the win32 shim reports Linux-ABI errno numbers, not
libuv's `-4058`-style values) and stays tracked under TDD-00180 §4/§5, verified
on the Windows CI lane.

## Not in scope

- **Message wording.** Node's message is `spawn <file> <CODE>` (e.g.
  `spawn ls ENOENT`); this keeps ADR-00754's `spawn <strerror>` form. Both the
  faithful message and `err.syscall`/`err.path`/`err.spawnargs` need the command
  string threaded into the errobj builder — a separate, larger change.
- **`spawnSync`** exposes no `.error` field at all (documented caveat), so it has
  no errno to carry.

## Verification

Verified on macOS/Apple Silicon: a missing-command `spawn(...).on('error', …)`
reports `code: ENOENT`, `errno: -2` — matching `node -e` on the same host.
`TestE2EChildProcessSpawnErrorCodeErrno`, the updated `child_process` example,
full `make test-par`, and Node oracle flat.
