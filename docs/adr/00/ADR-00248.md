# ADR-00248: Promise.any skip-rejected + AggregateError, and .then/.catch/.finally value-chaining

- **Relations**: `Implements TDD-00083` (Stage 3 follow-on); builds on [ADR-00244](ADR-00244.md), [ADR-00245](ADR-00245.md)
- **Date**: 2026-08-19

## Context

Three related gaps remained in the promise-combinator/reaction surface after
[ADR-00244](ADR-00244.md)/[ADR-00245](ADR-00245.md):

1. **`Promise.any` did not skip rejections.** It reused `__kml_task_await_any_of`
   (first *settled* member — correct for `.race`, which then re-throws), so a
   rejected member that settled first was treated as the winner and its reason
   read as if a value.
2. **No `AggregateError`.** All-reject threw the first member's plain `Error`, not
   an `AggregateError` with `.name`/`.errors`.
3. **`.then`/`.catch`/`.finally` did not chain a value.** Each returned a resolved
   `Promise<void>`; the callback's own result was discarded, so `p.then(f).then(g)`
   could not pass `f`'s result to `g`.

## Decision

**Promise.any skip-rejected (`runtime_task.go`).** A new
`__kml_task_await_first_fulfilled(members, count) → i64` waits for the first member
with `resolved == 1` (fulfilled), skipping rejections; if every member has settled
and none fulfilled it returns `-1`. `emitPromiseAny`'s task branch throws an
`AggregateError` on `-1`, else returns the fulfilled winner. The drive/park loop is
identical to `await_any_of`.

**AggregateError (`emit_exceptions.go`).** A new `errorKinds` entry. To avoid
changing the shared 24-byte `errorObjType` (3 fields: kind/message/name — read by
22 GEP sites and built by 7 raw-IR runtime sites), only an `AggregateError` is
allocated at an extended 40-byte layout (`{ kind, message, name, errData, errLen }`)
whose first three fields are byte-identical, so `.message`/`.name`/kind/`instanceof`
work unchanged. `err.errors` is a **kind-guarded** member access: it reads the
trailing `{ data, len }` only when `kind == AggregateError`, else yields an empty
array — so a non-aggregate error (still 24 bytes) is never read out of bounds.
`new AggregateError(errors, message?)` parses to the existing `NewErrorExpression`
(new `Errors` field); `Promise.any` builds one from the members' rejection reasons.

**Value-chaining (`emit_promise_then.go`).** `.then`/`.catch`/`.finally` now return
a *pending* promise Q whose value type is the callback's return type
(`callbackReturnType`). The per-call-site runner, after invoking the callback,
stores its result into Q, marks Q fulfilled, and drains Q's own reactions — so a
chained `.then` fires. Semantics: `.then(onF,onR?)` → Q gets `onF(value)` on
fulfillment, `onR(reason)` on rejection when present (recovery) else Q rejects with
the same reason (propagation); `.catch(onR)` = `.then(undefined,onR)`; `.finally`
runs its callback for effect and passes the source settlement through unchanged.
The runner is type-specialized on both the argument type (source value) and the
result type (what Q settles to); per-block SSA-name suffixes keep the fulfill/reject
paths distinct.

## Consequences

- `Promise.any` over task promises resolves to the first fulfilled member and
  throws `AggregateError` (with `.errors`) only when all reject.
- `AggregateError` is a first-class error kind: construction, `.name`/`.message`,
  `instanceof`, and `.errors` (an `Error[]`, so `e.errors[i].message` works).
  `.errors` on a non-aggregate error yields `[]` (a benign lenient divergence from
  real JS's `undefined`, and unreachable from well-typed code).
- `p.then(f).then(g)`, `.catch` recovery into a following `.then`, and `.finally`
  pass-through all chain correctly.
- Still scoped (the architectural remainder, TDD-00083): `.then`/`.catch`/`.finally`
  and `Promise.any` require a *task* promise — a non-suspending `async` function
  that throws still throws synchronously at call time rather than returning a
  rejected promise, and `Promise.any` over raw fetch responses stays rejected.
