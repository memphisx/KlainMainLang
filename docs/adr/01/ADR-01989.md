# ADR-01989: The handle table: native code holds managed objects by ref

- **Relations**: Implements TDD-00230
- **Date**: 2026-11-20

## Context

TDD-00230 phase 4: native code never holds a raw managed pointer. libuv
handles, libcurl easy handles, OpenSSL and nghttp2 sessions, the thread pool
and `node:ffi` refer to a managed object only through a pinned reference or a
handle-table index, so a moving collector can relocate everything the native
side does not pin. The GC interface (`kml_heap.h`) had pinned allocation and
root ranges, but no way for native code to hold an existing object.

## Investigation

An audit of every `*src/*.c` unit listed each slot where native code keeps a
managed pointer past the current call:

- Closure slots in `calloc`'d native records: the pool item, a TCP handle's
  six callbacks, a write request, a child process's exit callback, a message
  port, a Worker's parent callback, sqlite user functions, an ffi callback,
  an h2o exchange's write callback, an fs.watch listener.
- Thread-local native arrays: the sqlite authorizer, the wasm host
  dispatcher, fetch's signal list, the parked fetch body reads. Boehm does
  not scan thread-local storage on macOS.
- Library-owned user data: curl's `CURLOPT_PRIVATE`, `WRITEDATA` and
  `HEADERDATA`, and the borrowed `POSTFIELDS` bytes.
- Managed buffers a worker thread writes while the loop runs: fs reads,
  zlib's input and output, crypto's random fill and key derivation output.
- Boxed values queued across threads: a posted message, `workerData`.

Plain static globals (the process hooks, the h2o listener) are already roots
a collector can rewrite, and are left as they are. So are the runtime's own
queues (microtasks, tasks, timers); they belong to the GC interface's
thread-local root registration, not to the native layers.

## Decision

- `kmlrefsrc/kmlref.c`, a pool unit linked by symbol: `kml_ref_new`, `_get`,
  `_set` (a moving collector's update), `_free` and `_live`. A ref is a slot
  index plus one (0 is none); the slot array is reached from a static, so it
  is a root in every mode (under `-mm=gc` `malloc` is the collector's). A
  spinlock guards it; any thread may use it.
- Every slot above holds a `kml_ref` and reads through the table; each ref is
  freed where its holder releases the object (the completion callback, the
  handle's close, the easy handle's cleanup, sqlite's destructor, the ffi
  closure's free, the exchange's release).
- curl gets one ref per transfer for `PRIVATE`, `WRITEDATA` and `HEADERDATA`;
  the callbacks reach the buffers through the pending fetch, so `pend_t`'s
  88-byte layout (indexed by the generated IR) is unchanged. The body goes
  through `CURLOPT_COPYPOSTFIELDS`.
- A worker's buffer is pinned for the job (`kml_pool_item.pin[2]`, and
  `__kml_pool_job_pinned` for the crypto backends).

## Implementation notes

`kmlref.c`, `kml_heap.h`, `kml_pool.h`, `klainpool.c`, `klainfs.c`,
`klainzlib.c`, `klainsqlite.c`, `klainwasm.c`, `crypto_openssl.c`,
`crypto_commoncrypto.c`, `crypto_cng.c`, `fetch.c`, `fetchbodyprom.c`,
`ffi_native.c`, `klainh2o.c`, `fswatch.c`, `dynimportwatch.c`.

## Side effects discovered

- The webview binding's user data is now native memory holding the closure
  by ref (`natives.c`).
- `klain:sync`'s runtime became a pool unit linked by symbol; `usedSync` and
  `ensureSyncRuntime` are gone.
- The runtime's thread-local queues need registering as roots through the
  GC interface before a moving collector.
- A captured variable's cell holding a plain number or boolean is allocated
  unscanned (`cellAllocKind`), so under `-mm=gc` a double in it never pins
  a block it happens to look like.

## Verification

`TestKmlRefTable` (create, read, rewrite, free, slot reuse, four threads).
Targeted E2E suites on the Mac: fetch, abort, net, child_process, workers,
message ports, fs, zlib, dns, crypto ports, sqlite, wasm, ffi, fs.watch,
dynamic import.

Benchmark (Mac arm64): 20,000 awaited `fs.promises.stat` calls, three runs each: 209/186/181 ms before, 205/181/186 ms after: within noise.
