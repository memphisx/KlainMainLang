# ADR-01373: Iterator helpers in TypeScript, and generators typed as Generator

- **Relations**: Implements TDD-00230 P3.1/P3.2 for `IteratorObject`; Extends ADR-01344, ADR-01313
- **Date**: 2026-10-03

## Context

Test262's `Iterator/prototype/every` and `some` files regressed from pass
to "a string has no method 'every'". At HEAD they passed only because
`every` on a generator reached the array emitter, which drained the whole
generator first: `function* g() { log("a"); yield 1; log("b"); yield -1;
log("c"); yield 2 }` then `g().every(x => x > 0)` printed `a b c` where Node
prints `a b` and stops. The rest of ES2025's helper set (`map`, `filter`,
`take`, `drop`, `flatMap`, `reduce`, `forEach`, `find`) was missing.

## Investigation

- `lib/es.d.ts` declared only `toArray` on `IteratorObject`.
  `tools/libconform` did not report the gap: it reads only top-level
  declarations, and TypeScript declares the helpers inside
  `es2025.iterator.d.ts`'s `declare global` block.
- The checker left every generator function unanswered, so a generator
  call never resolved to a declaration, and dispatch fell back to codegen's
  name-based inference.
- `loweredCallDecl` (`codegen/llvm/emit_lowered.go`) took a library
  function's receiver only for a string or a number.
- Driving iterators from TypeScript through `any` surfaced four bugs:
  - A Map, Set or Array iterator boxed into `any` had no layout for its
    `{value, done}` result: `emitShapeFinalize` generated the host rows
    after the object-layout loop had finished, so a layout a host row
    registered was never emitted.
  - Reading an optional member a host value lacks (an Array iterator's
    `return`) threw instead of reading `undefined`.
  - `hostKey` ignored a collection iterator's kind and source, so a Map's
    `keys()` and `values()` shared one host row; the second read the
    first's elements (`keys()` yielded the values).
  - `gen.return(undefined)` returned `{ value: 0 }`: `undefined` parses to
    an undefined literal, which `isUndefinedLiteral` did not recognize, so
    the explicit-value flag was set.
- tsc 7 types `function* u() { yield 1; yield -1; return "s" }` as
  `Generator<-1 | 1, string, unknown>`: the yield type keeps literals, the
  return type widens.

## Decision

1. **The helpers are TypeScript** (`lib/node/kml_iterator.ts`), as
   ECMA-262 §27.1.4 gives them: GetIteratorDirect reads `next` once,
   IteratorClose on early exit, a throw completion keeping the original
   error, `reduce` telling an omitted initial value from `undefined`.
   `map`/`filter`/`take`/`drop`/`flatMap` return an `IteratorHelper`
   (§27.1.2.1): `return()` closes the source even before the first
   `next()`, a re-entrant `next()` throws, `Symbol.toStringTag` is
   `Iterator Helper`, and it carries the helpers itself.
2. **Declarations.** `IteratorObject` declares the helpers with
   TypeScript's signatures, each `@lower`ed to its function, plus a
   `Generator` interface extending it.
3. **Object receivers.** A builtin interface method whose declaration
   lowers to a library function takes any receiver, passed boxed as the
   first argument.
4. **Generators are typed.** An unannotated non-async generator function,
   expression or method returns `Generator<Y, R, unknown>`: Y the union of
   its `yield` operands (a bare `yield` undefined, `yield*` the iterable's
   element type), R its returns widened. Anything unanswered leaves the
   generator unanswered, as before.
5. **Through `any`.** A generator's and a dynamic array iterator's shape
   rows list the linked helpers, each a record calling the TypeScript
   function with `this` (cases inside the existing record generators, no
   new IR definitions). A host iterator's adapter reaches them through
   `emitCollIterCall`.
6. **The four bugs.** Shape and host rows are generated to a fixed point;
   an optional host member a value lacks reads `undefined`; `hostKey`
   includes an iterator's kind and source; `isUndefinedLiteral` accepts the
   parsed undefined literal (not `void x`, whose operand must run).
7. **libconform** reads `declare global` blocks, so the helpers are now
   checked against TypeScript's (and `lib/tsmembers.txt` lists them).

  (`emitIteratorHelperCall`, `linkedIteratorHelpers`, the finalize loop),
  `emit_host_shape.go`, `emit_hostbox.go`, `emit_collections_iter.go`,
  `emit_generators.go`.
- `tests/collection_iterators_test.go`: `TestE2EGeneratorDoneValue` called
  `e2.return()`, which tsc rejects (TS2554: `Generator.return` requires its
  argument). It now passes `undefined`, which Node treats the same.

## Side effects discovered

- tsc rejects `[1 as 1 | 2].reduce((a, b) => a + b)` (TS2322 through
  overload resolution); the checker accepts it, at HEAD too: overload
  resolution does not re-check a callback argument against each
  candidate.
- `Iterator.from` and the `Iterator` global are still missing (status
  caveat).

## Verification

Mac (Apple Silicon): `TestE2EIteratorHelpers` (both lanes, against Node),
`TestE2EAnyCollectionIteratorResult`, `TestE2EGeneratorDoneValue` and the
generator, iterator and collection E2E tests; the checker test binary;
`examples/generators/iterator_helpers.ts` matches Node in both lanes, and the
other generator examples run as they did at HEAD; libconform reports no
divergence.
