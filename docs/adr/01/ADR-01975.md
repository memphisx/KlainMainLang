# ADR-01975: Top-level patterns, the empty-string key, process on globalThis

- **Relations**: Implements TDD-00230; follows [ADR-01974](ADR-01974.md)
- **Date**: 2026-11-06

## Context

Three programs were rejected with internal errors. All turned up in the
shadow round, in Web Platform Tests whose WebAssembly or WebCrypto gaps
had hidden them until now:

- A top-level `const { pk } = o` whose `pk` holds an object, read inside a
  function, failed with `undefined variable 'pk'`.
  `registerPatternGlobals` promotes a destructured name to a module global
  only when the checker's type has a representation of its own, and an
  object literal's type has none. In JavaScript, `var { pk, sp } = f()`
  read by a function failed the same way.
- A function returning an object literal with an empty-string key
  (`{ "": 0 }`) had no type. The checker read `Key == ""` as a missing key,
  but the AST marks a spread by its `SpreadElement` value, not by the
  empty key.
- `const g: any = globalThis; g.process` failed with `undefined variable
  'process'`. Reading `process` off an alias links it onto the global
  object ([ADR-01973](ADR-01973.md)), but the value of `process` is its
  emitter object, and that module was included only for a direct read of
  `process` as a value.

## Decision

- A destructured top-level name whose checker type has no representation
  takes the static type of the field it binds, as
  `unpackObjectPatternInto` types the local (`patternFieldType`). This
  covers a plain `{ k }` or `{ k: name }` with no default and no nested
  pattern. Under `-compat=js`, a name still untyped holds `any`, as
  JavaScript holds every binding.
- In an object literal, a non-spread property with an empty key is the
  property `""`, as in tsc.
- The resolver includes `internal_process.ts` whenever the global object
  carries `process`.
- `registerPatternGlobals` takes each statement's own lane. It used to
  inherit the lane of the last library statement an earlier pass saw, so
  a JavaScript program could be typed as if it were strict.

## Consequences

- All three now match Node. They are covered by
  `TestE2ETopLevelObjectPatternReadByFunction`,
  `TestE2EObjectLiteralEmptyKey` and
  `TestE2EGlobalObjectAliasReadsNatives`.
