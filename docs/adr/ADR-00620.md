# ADR-00620: klainload — a real interactive HTTP load tester

- **Relations**: `Supersedes ADR-00616, ADR-00617` (the load-tester example), `Extends ADR-00615, ADR-00619`
- **Date**: 2026-09-01

## Context

The `examples/goroutines/load_test.ts` example was not a usable tool: it bundled
its own HTTP server, tested *that*, hardcoded its settings, ran a couple of
seconds, and left no record once the TUI closed. A load tester targets an
endpoint the operator chooses and produces a report that stays.

## Decision

Rebuild it as `klainload`, an interactive HTTP load tester driving a pool of
`klain:sync` goroutine "agents" that hit an external URL with synchronous
`XMLHttpRequest`s (ADR-00615). Split by real concern (not compiler mechanics),
under `examples/goroutines/loadtest/`:

- `config.ts` — the `Config` shape + CLI parsing (`-c` agents, `-d` duration or
  `inf`, `-X` method, `-H` header (repeatable), `--body`, `--run`, `-h`).
- `engine.ts` — the agent goroutines: a closed loop that fires a request and
  streams a `Result` until the shared `stop` channel closes.
- `stats.ts` — the `Result` shape + aggregation (latency histogram/percentiles,
  success/failure by HTTP status class, throughput window).
- `report.ts` — the persistent text summary.
- `screens.ts` — the live dashboard + results screen (`klain:tui`).
- `configform.ts` — the interactive config screen (a `todo.ts`-style field form).
- `load_test.ts` — the orchestrator.

Three modes: a config screen (first TUI screen, pre-filled from CLI args), a
live dashboard **stoppable at any time** by a keypress (a `stop.close()`
broadcast every agent observes in a non-blocking `select`), and a results
screen whose report is also printed to stdout so it survives after exit. A
duration bound closes `stop` at a `performance.now()` deadline; infinite mode
runs until the keypress. `--run` skips the config screen. Non-TTY (piped /
`make examples`) runs headless — short by default, honoring `-d` — and prints
the report. The tool no longer bundles a server; `make examples` points it at
the httpbin fixture.

## Implementation notes

- Building this drove the compiler fix in ADR-00619 (the agent stop-check
  captures a local inside a `select` case). It also confirmed compiler
  realities to design around, documented inline: `klain:tui` nodes are bare
  `ptr` with no nameable TS type, so a node can be *returned* and placed in a
  children array but never annotate a *parameter* (helpers take data, return
  nodes); `readKey` returns a value that needs an explicit `: string`
  annotation; TUI `color` must be a string literal; an uninitialised `let` node
  var infers a non-node type (initialise it).
- A `Channel<Result>` carries the per-request object by pointer — richer than a
  bare latency number, folding status class + bytes in one pass.

## Verification

Mac (Apple Silicon M4). Headless: real reports against the fixture (8 agents /
10s → ~37k requests, 100% success, latency percentiles, status breakdown,
transfer); `-c`/`-d`/`-X` honored; a dead port is counted entirely as connection
errors. Interactive (driven through a pty): config screen → navigate → start →
live dashboard → `s` stops it early (1.68s, not the 10s duration) → results
screen → dismiss → the report is printed to stdout. `make examples` green.
