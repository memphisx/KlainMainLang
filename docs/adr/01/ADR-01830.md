# ADR-01830: A Map seed of mixed key or value types is any-keyed

- **Relations**: `Implements TDD-00230` (found while working the shadow report), extends [TDD-00211](../../tdd/TDD-00211.md)
- **Date**: 2026-10-20

## Context

- `new Map([["a", 1], [2, 2]])` is valid TypeScript (`Map<string | number, number>`), and Node keeps both entries.
- Codegen took K and V from the first pair alone. It then rejected any later pair of another type with "entries must share one key type", even under explicit `<any, any>` type arguments.
- A bare `new Map()` with mixed `.set` keys has used the any-keyed runtime since TDD-00211.

## Decision

- A seed of pair literals unifies across every pair. If a key differs in representation from the first pair's key, the key type is `any`. The same rule applies to values. An any-keyed map's values are boxed, as before (`forceAnyMapVal`).
- The homogeneity check skips a dynamic key type, as it already skipped a dynamic value type.

## Consequences

- Mixed seeds match Node, annotated or not: `TestE2EMapHeterogeneousSeed`, and `examples/map/any_keys.ts`.
- Verified on Apple Silicon.
