# ADR-01379: Destructuring assignment: its value, a dynamic source, computed keys

- **Relations**: Extends ADR-00160, ADR-00663
- **Date**: 2026-10-03

## Context

Test262's `assignment/dstr/obj-id-identifier-resolution-*` produced
invalid IR under the strict lane and failed to compile under `-compat=js`,
at HEAD too:

```js
var x = null;
var result;
var vals = { x: 2 };
result = { x, } = vals;
```

## Investigation

- The null-evolving pre-pass (`crossTypeWidenedBindings`) widens a
  `let`/`var x = null` binding to the any-box when it is later assigned,
  but counted only `x = …`, not a destructuring target, so `x` stayed a
  null pointer slot and a double was stored into it.
- Both destructuring-assignment forms returned `void`; the value of
  `({ x } = v)` is `v`.
- The object form read only a statically-shaped source
  (`resolveObjectPtr`): a dynamic one was "not an object", and a runtime
  computed key was rejected.
- A declaration initialized by an assignment (`var z = y = "s"`,
  `var r = ({ a } = o)`) took the `i64` default type: the initializer
  switch had no assignment case.

## Decision

- A destructuring assignment's identifier targets (through nested
  patterns, defaults and rest) count as assignments of a non-nullish value
  of unknown kind in the null-evolving pre-pass.
- The object form returns its source; inference agrees.
- Over a dynamic source, or with a computed key, the object form
  evaluates the source once into a boxed temporary and assigns each target
  its property (`emitDynDestructAssign`), the default when the property
  reads `undefined` (read once), a nested pattern as its own destructuring
  assignment. A rest element there stays a clean rejection.
- A declaration's initializer that is an assignment takes the
  assignment's type.

## Implementation notes

`codegen/llvm/emit_exprs_assign.go`, `emit_func.go`
(`assignmentPatternTargets`), `emit_exprs_types.go`,
`emit_exprs_vardecl.go`.

## Side effects discovered

The array form still returns `void` rather than its source.

## Verification

Mac (Apple Silicon): `TestE2EDestructuringAssignmentValue` in both lanes;
the four Test262 files compile to valid IR in both lanes.
