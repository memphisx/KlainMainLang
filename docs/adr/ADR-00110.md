# ADR-00110: Getters / setters on classes

- **Date**: 2026-08-06

## Context

`docs/status/LANGUAGE-CONSTRUCTS.md` documented `get x() {}`/`set x(v) {}` as a confirmed gap: no accessor-property parsing anywhere in `parser_literals.go`/`parser_classes.go`, `get`/`set` recognized only as plain identifiers. Picked up at the user's explicit request ("Let's do getters/setters next"), immediately following destructured function parameters (ADR-00109) and the operator-completeness pass (ADR-00108). [TDD-00030](../tdd/TDD-00030.md) scoped the design beforehand, per this project's standing rule for work needing a design pass first — see that TDD for the full options considered; this ADR covers the implementation itself and what changed relative to the design.

## Decision

Implemented per TDD-00030's design: **classes only** (not object literals — an object literal's `Type` is pure structural value-equality with no name to hang an accessor table off, a materially larger change deliberately deferred). An accessor is registered as an ordinary zero-arg (getter) or one-arg (setter) method under an internal dispatch key, reusing the entire existing method-table/inheritance/override/vtable-dispatch machinery (`ClassInfo.Methods`/`MethodSigs`/`MethodImplementor`/`MethodDispatchSlot`/`MethodOrder`, TDD-00009 Stage 3) completely unmodified — inheritance and polymorphic dispatch through accessors fall out for free, no new dispatch logic anywhere.

**One deviation from the TDD's own design**: the TDD proposed mangling the dispatch key with a literal space (`"get x"`/`"set x"`), reasoning a space can never appear in a real user identifier. That's true for the Go-side `map[string]...` key, but it doesn't survive contact with `emitClassCall`'s own `llvmName := implementor + "_" + methodName` construction — `@Circle_get x` is not valid LLVM IR symbol syntax (a bare space breaks tokenization). Caught this myself while implementing and testing, not flagged by the user. Switched to `accessorMethodName(kind, prop) = "__kml_" + kind + "_" + prop` (e.g. `"__kml_get_area"`) — valid identically as a Go map key and as an LLVM symbol fragment, and matches the project's existing `__kml_`-prefixed reserved-name convention (`ClassTagField`/`ClassVTableField`/`ClassEventEmitterField` in `types.go`).

**Parsing**: `get`/`set` are contextual, not reserved tokens — matching how `in` is already handled (ADR-00091). In the class-member parsing loop (`parser_classes.go`), right after the existing `static`/`private`/`protected`/`abstract` modifier loop and before consuming the member name: if the current token is an `IDENT` with literal `"get"`/`"set"` **and** the next token is also an `IDENT`, treat it as an accessor keyword; otherwise it's parsed as an ordinary member name exactly as before, so a field/method/variable literally named `get`/`set` is unaffected. A `constructor` can't be a getter/setter (explicit rejection); an accessor keyword not immediately followed by `(` (i.e. no method body — `get` used as a bare field name would already have consumed just the identifier) is rejected with a clear "must be a method" error rather than silently misparsing.

**Registration/validation** (`registerClasses`, `emit_classes.go`): a new branch for `m.AccessorKind != ""`, inserted before the existing `static`-method branch, validates: rejects `static` on an accessor; getter must take 0 params and return non-void; setter must take exactly 1 param (its `sig.RetType` is forced to `TypeVoid` regardless of any declared return type); mutual exclusion against a same-named field (`FieldIndex`) and against a same-named plain method (`info.MethodSigs[m.Name]`) in both directions — a symmetric check was also added to the plain-method registration branch so declaration order doesn't matter; get/set type agreement, comparing the getter's return type against the setter's parameter type; duplicate-accessor-of-the-same-kind rejection. Once validated, registers under `accessorMethodName(kind, prop)` into the exact same maps a plain method uses.

**Read path** (`emit_exprs_member.go`): `emitMember` and `emitOptionalMember` (the `?.` variant) both gained an accessor check — if `objVal.Ty.IsClass` and `e.classAccessorSigs(className, prop)` finds a getter, the read becomes a call through `emitClassCall` with the mangled key, the same function every ordinary `obj.method()` call already goes through (inheritance/override/vtable/visibility all come free). A property with only a setter is a clean compile-time "no getter" error on read, not a silent wrong value.

**Write path** (`emit_exprs_assign.go`): new `tryEmitAccessorAssign`, wired into `emitAssign`'s object-field-assignment branch before the plain `FieldIndex` path. Plain `=` does a hint-aware coercion against the setter's declared parameter type, then calls through `emitClassSetterCall`. Compound assignment (`+=` etc.) reads the current value through the getter, applies `emitArith`, writes the result through the setter — errors if the getter is missing (compound assignment needs to read the old value first). `&&=`/`||=`/`??=` are rejected outright: `emitLogicalCompoundAssign` assumes a re-loadable memory location to conditionally skip the write, which an accessor doesn't have.

**New `emitClassSetterCall`** (`emit_classes.go`): a sibling to the existing `emitClassMethodCall`, duplicating its direct-vs-vtable dispatch shape but accepting an already-evaluated `Value` argument (the setter's RHS needs its own coercion/read-modify-write logic to happen first, upstream in `tryEmitAccessorAssign`, before the call itself).

## Investigation / bugs found and fixed

1. **Wrong function name/return type in emitted IR** (`define  @Circle_area(ptr %p_this) {` — blank return type, wrong symbol name): `emitClassDecl`'s method-emission loop looked up `info.MethodSigs[m.Name]` (the plain name `"area"`) instead of the mangled key, getting a zero-value `FuncSig{}` for any accessor. Fixed by computing `methodKey := accessorMethodName(m.AccessorKind, m.Name)` when `m.AccessorKind != ""` and using it for both the `MethodSigs` lookup and the `llvmName` construction.

2. **`panic: index out of range [0] with length 0`** in `registerClasses`'s get/set type-agreement check: the first version unconditionally read `otherSig.ParamTypes[0]` regardless of which kind `m` itself was — when `m.AccessorKind == "set"`, `otherSig` is the *getter* (0 params), so indexing `[0]` panicked. Fixed with an explicit `if m.AccessorKind == "get" { ... } else { ... }` branch computing `getterRet`/`setterParam` correctly in both directions.

3. **Pre-existing, unrelated bug found as a prerequisite while scoping setter argument-passing**: `emitClassCall` — the single shared codegen path behind *every* `obj.method(args)` call in the compiler, accessor or not — never decomposed an array-typed argument into its `{ptr,i64}` parts. Confirmed directly, independent of getters/setters entirely: a plain class method taking a `number[]` parameter (`f.addAll([1,2,3])`) crashed at the `clang` stage with a type mismatch (`'%t10' defined with type '{ ptr, i64 }' but expected 'ptr'`). Fixed both the direct-call argument-building loop and the vtable indirect-call `paramTyStrs`/function-type construction to decompose an array-typed parameter the same way scalar/`ptr` parameters already are. Needed as a prerequisite since `emitClassSetterCall` was designed to correctly handle an array-typed setter parameter, and consistency with the (now-fixed) general path was the simpler option over a second, accessor-only special case.

4. **The mangled-key space-vs-underscore issue**, covered under Decision above.

## Implementation notes

Files touched:
- `ast/nodes.go`: `FunctionDeclaration` gained `AccessorKind string` (`"get"`/`"set"`/`""`).
- `parser/parser_classes.go`: contextual `get`/`set` detection in the class-member loop.
- `codegen/llvm/emit_classes.go`: `accessorMethodName`/`classAccessorSigs` helpers; `registerClasses`'s new accessor-validation branch plus the symmetric collision check added to the plain-method branch; `emitClassDecl`'s method-emission loop fixed to use the mangled key; `emitClassCall`'s array-argument decomposition fix (direct call + vtable call); new `emitClassSetterCall`.
- `codegen/llvm/emit_exprs_member.go`: `emitMember`/`emitOptionalMember` accessor-aware read paths.
- `codegen/llvm/emit_exprs_assign.go`: new `tryEmitAccessorAssign`, wired into `emitAssign`.

## Side effects discovered

The `emitClassCall` array-argument bug (Investigation #3) — a real, independently-reproducible pre-existing bug affecting any class method call with an array argument, found and fixed as a prerequisite for this work rather than deferred.

## Open items (deliberately deferred, not bugs)

Per TDD-00030's own Open Questions: whether a getter/setter's own visibility modifier (`private get x()`) must match its counterpart's visibility when both exist — real TypeScript enforces this; V1 here does **not**, so a class may currently declare a public getter alongside a private setter (or vice versa) with no error. Left as a known, documented gap rather than committed either way.
