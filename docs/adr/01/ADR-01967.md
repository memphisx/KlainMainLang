# ADR-01967: Top-level bindings take the front end's type; unread ones stay locals

- **Relations**: Implements TDD-00230 (P3.3); follows [ADR-01966](ADR-01966.md)
- **Date**: 2026-10-29

## Context

`reliableGlobalType` decides whether a top-level declaration becomes a module global and its storage type. It called `decideGlobalType`, codegen's own inference. The shadow harness compared it with the front end's answer only for declarations that became globals or that a function read. On those it agreed everywhere.

The first switch to the front end's answer promoted every top-level declaration it called promotable, including ones `decideGlobalType` kept as `main()` locals that no function reads. Those had never been compared, and their checker-mapped type differed from the layout their initializer builds. For example, `const opts = { headers: [['X-Trace', 'abc']] as [string, string][] }` builds `headers` as an array of tuples, but the front end typed it as an array of string arrays. The object's layout getter was registered under a layout no object has, and `fetch` reading `opts.method` threw a TypeError.

## Decision

- `reliableGlobalType` takes the front end's `GlobalType`, and `decideGlobalType` is deleted. Across the corpus the front end left two declarations unanswered, both unread bindings `decideGlobalType` also kept local, so an unanswered declaration stays a local. A shadow record, `globalFallback`, counts any that appear.
- A top-level declaration no function reads is not promotable. As a global it would behave the same as a local, and its own declaration lays it out. Only a function's read needs the global, and the checker's type for it. A library module's or a dynamic-only file's declarations are the exception: their statements run in an init function, so each stays a global. So is a namespace member, which is read through its namespace's qualified names (`Config.port`) wherever they appear. So are a worker module's declarations, emitted a second time into its entry function; a binding the compiler synthesizes (an enum's value), read by the code it generates; and the entry's exports, which a dynamic-import island's accessors read.
- A new shadow comparison, `localGlobalType`, checks a top-level declaration that stays a local against the front end's answer whenever the front end would promote it.
- An unannotated object-literal global stores each field as the literal builds it (`literalStorage`).
- A collection iterator's method whose lowered result is boxed, and that the checker types as a primitive (`map.values().reduce((s, p) => s + p, 0)`), is unboxed to it, as other boxed call results already were.

## Consequences

- A top-level binding that a function reads, whose layout `decideGlobalType` refused to promote, now compiles. Before, the function failed with `undefined variable`.
- Bindings `decideGlobalType` promoted although no function reads them are now `main()` locals.
- The loop that makes every library-module binding a global typed one by its initializer even under an annotation (`export const self: any = new WorkerGlobalScope()`), while its declaration stored the annotation's box. It now takes the annotation.
- A void-typed call that emits a real `undefined` (`FinalizationRegistry.register`) now binds `undefined` in a function's local too. It used to keep the `i64` placeholder, so `typeof r` was `"number"`.
- A generic class's `new` without type arguments, in a function body codegen copies, asks the checker about the program's original node, which has the contextual type (`const s: Stack<number> = new Stack()`). The copy had no parent, so the checker answered `any` and the compile failed.
