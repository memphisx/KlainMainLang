# TDD-00089: `Symbol.asyncIterator` — user-defined async iterables in `for await...of`

- **Status**: Implemented
- **Date**: 2026-08-20
- **Notes**: Lifts `for await...of` from "async-generator instances only" to the async-iteration protocol: a user class with a `[Symbol.asyncIterator]()` returning an iterator whose `async next(): Promise<{value,done}>` is awaited each turn. The well-known symbol is a reserved compile-time `MethodSigs` key (`@@asyncIterator`, the accessor-key trick), not a runtime value — no new machinery, reuses `emitClassCall` + `emitAwaitTaskPromise` + structural `{value,done}` reads. Two rejection sites relaxed (parser computed-key, `for await` gate). `Symbol.iterator` (sync) and object-literal iterables stay out; iterable + iterator must be class instances

## Context

`for await...of` (TDD-00085) consumes only an **async-generator instance** — its dispatch
checks `objTy.IsGenerator && objTy.GeneratorIsAsync` and rejects everything else with
`'for await...of' requires an async generator (V1 scope, TDD-00085)`. A user class that
implements the async-iteration protocol by hand — a `[Symbol.asyncIterator]()` method
returning an object with `async next(): Promise<{value,done}>` — cannot be consumed, even
though every piece it needs (method dispatch on a class instance, awaiting a task promise,
reading `{value,done}` structurally) already exists. Grounded, both halves reject today:

```ts
class Countdown {
  [Symbol.asyncIterator]() { return new CountdownIter(this.n); }   // parse error
}
for await (const x of c) { ... }                                   // codegen reject
```

Two independent rejection sites block it:

1. **Parser** (`parser_classes.go`): a computed class-member key must be a constant string
   or number literal — a `Symbol.*` key is a clean rejection (`a dynamic key … is not yet
   supported`). So `[Symbol.asyncIterator]()` never parses.
2. **Codegen** (`emit_stmts.go` `emitForOf`): the `for await` gate accepts only an
   async-generator instance.

`Symbol` itself (TDD-00044) is an opaque unique value with **no** well-known symbols — there
is no `Symbol.asyncIterator` member and no runtime protocol-dispatch point. TDD-00085
explicitly listed `Symbol.asyncIterator` as a V1 cut; this closes it.

## Design

**Represent the well-known symbol as a reserved method name, not a runtime value.** The
protocol is resolved entirely at compile time (monomorphized classes, structural
`{value,done}` reads) — a well-known symbol needs no runtime object, only a stable, un-forgeable
member key. This mirrors the accessor convention (`"get x"` / `"set x"` are `MethodSigs`
keys a user can't spell).

- **Parser.** In the computed-class-member branch, before the constant-literal check,
  recognize the `MemberExpression` `Symbol.asyncIterator` and desugar it to the reserved
  member name `@@asyncIterator` (the spec's `@@`-prefix convention; not a lexable
  identifier, so it can't collide with a user method). Any other dynamic key stays a clean
  rejection. `Symbol.iterator` (the sync protocol) remains rejected — the sync `for...of`
  already has a structural `next(): T | null` class path, and a general sync
  `Symbol.iterator` protocol is a separate future item, kept out to avoid a half-wired
  state.
- **Codegen (`for await` dispatch).** When the iterable is not an async generator, accept a
  **class whose `MethodSigs` has `@@asyncIterator`**. Lower it to:
  1. `it = iterable[Symbol.asyncIterator]()` — an ordinary `emitClassCall` on the reserved
     name; its declared return type is the iterator class.
  2. Loop: `prom = it.next()` (an async method → a task-shaped `Promise<{value,done}>`),
     **await** it via the shared `emitAwaitTaskPromise` (parks/​drives + re-throws a
     rejection), read `.done`/`.value` off the settled result object via `FieldIndex`
     exactly as `emitForAwaitOfGenerator` already does past its own `.next()` call.
  3. `.done` true ⇒ exit; else bind `.value` to the loop variable (or unpack a
     destructuring pattern through the shared `unpack*PatternInto` core) and run the body.

**Why minimal:** it adds no runtime machinery — method dispatch (`emitClassCall`), the task
await (`emitAwaitTaskPromise`), and structural `{value,done}` reads all pre-exist. The new
code is the parser desugar (one branch) and one loop-emitter that wires those three together.

## Stages

1. **Parser desugar.** Admit `[Symbol.asyncIterator]` as the reserved `@@asyncIterator`
   member; a method by that key registers in `MethodSigs` through the normal path. Verify a
   class with the method compiles (the method is callable, still un-consumed).
2. **`for await` dispatch.** Relax the gate to accept a class with `@@asyncIterator`; emit
   the get-iterator + await-`next` loop. Verify end-to-end consumption, including a
   `return this` iterator and a separate iterator object.
3. **Rejection quality + patterns.** A class missing `@@asyncIterator` or an iterator
   missing a `Promise`-returning `next()` gives a clear message; destructuring loop
   variables (`for await (const {…} of …)`) reuse the unpack core.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| Class method dispatch on an instance (`emitClassCall`) | Built | emit_classes.go — reused for `@@asyncIterator` and `next` |
| Task-promise await (`emitAwaitTaskPromise`) | Built | emit_async.go — parks/drives + re-throws rejection |
| `{value,done}` structural read + destructuring unpack | Built | emit_generators.go `emitForAwaitOfGenerator` |
| Reserved (un-forgeable) `MethodSigs` key precedent | Built | accessor `"get x"`/`"set x"` keys |
| Computed-key desugar to a named member | Built | parser_classes.go (constant literals today) |

## Open questions

- **Object literals.** `{ [Symbol.asyncIterator]() {…} }` has no representation — object
  literals hold value properties, not `this`-bound methods. Out of scope; the iterable and
  the iterator must both be **class instances** (the same limitation the sync class-iterator
  path lives with). A clear rejection, not silent mishandling.
- **`Symbol.iterator` (sync).** Deliberately kept out (above) to avoid a parses-but-doesn't-
  dispatch half-state; revisit as its own item if a general sync iterable is wanted.
- **`next()` shape.** The iterator's `next()` must return `Promise<{value,done}>`; a
  non-promise or a non-`{value,done}` return is rejected at the `FieldIndex`/await site.
