# ADR-00896: ToNumber(Symbol) throws a TypeError

- **Date**: 2026-09-12

## Context

Part of the invalid-IR (Test262 `CLANG_ERROR`) sweep. A statically-typed Symbol
flowing into a numeric context reinterpreted the symbol pointer as a number,
emitting invalid IR (`ptr` where an `i64`/`double` is required):

```ts
new ArrayBuffer(Symbol());     // ToIndex(Symbol) → ToNumber(Symbol)
(0n).toString(Symbol());       // radix ToNumber(Symbol)
```

Affected: `built-ins/ArrayBuffer/return-abrupt-from-length-symbol.js`,
`built-ins/SharedArrayBuffer/return-abrupt-from-length-symbol.js`,
`built-ins/BigInt/prototype/toString/radix-tointegerorinfinity-throws-symbol.js`.
All three are `assert.throws(TypeError, …)` negative tests: real JS's
`ToNumber(Symbol)` throws a TypeError ("Cannot convert a Symbol value to a
number"), so the faithful behavior makes them pass.

## Investigation

`coerce` (`emit_exprs_coerce.go`) had no Symbol case, so a Symbol→numeric coerce
hit the default "return v unchanged" fall-through — leaving the `ptr` where a
numeric scalar was expected. Two viable layers: reject at compile time, or throw
at runtime. Runtime throw is what V8 does and, because these are `assert.throws`
tests, it makes them pass.

The complication: string methods already reject a statically-known Symbol index
at compile time with a targeted diagnostic (`coerceChecked(idx, TypeI64, pos,
"charAt index")`, `emit_strings.go`), locked in by
`TestE2EStringNonNumericArgRejected`. A blanket runtime throw inside `coerce`
made `coerceChecked` see a "sound" i64 (the throw's zero stand-in) and stop
producing that compile error — regressing 14 cases.

## Decision

Two coordinated changes:

1. In `coerce`, when the source is `IsSymbol` and the target is a concrete
   numeric machine type (`Float`, or an integer IR that is neither empty nor
   `ptr`), emit a runtime `TypeError` via the existing `emitThrowTypeError`
   helper and return a well-typed zero stand-in (the block is already
   terminated `unreachable`, so the consumer's dropped instructions stay
   well-typed). This covers sites with no compile-time reject path (builtin
   argument coercion such as the ArrayBuffer ctor and BigInt radix).

2. In `coerceChecked`, detect the same Symbol→numeric case *before* calling
   `coerce` and return a clean compile error instead — preserving the
   typed-subset diagnostic ("charAt index", …) that call site asked for.

So a Symbol reaching a numeric position throws at runtime by default, but a
call site that opts into `coerceChecked` (it wants a clean compile error) gets
one.

## Implementation notes

- `emitThrowTypeError(msg string)` already exists in `emit_dynobj.go` (interns
  the message, throws kind-1 TypeError, terminates `unreachable`).
- The numeric-target guard is duplicated in both functions and must stay in
  sync; kept identical (`target.Float || (target.IsInteger() && target.IR != ""
  && target.IR != "ptr")`) so the two layers agree on what "numeric" means.

## Side effects discovered

The three negative tests now pass at runtime (the shim's `assert.throws`
accepts any thrown value). No change to the string-method compile rejections.

## Verification

- `TestE2ESymbolToNumberThrows` (new): `new ArrayBuffer(Symbol())` throws, caught.
- `TestE2EStringNonNumericArgRejected` still green (compile rejections intact).
- The three Test262 files compile and run to exit 0.
- `make examples` 296/296; symbol / bigint / arraybuffer E2E suites green.
