# ADR-01234: Promises through `any`; util.inspect of promises and nested Errors

- **Relations**: `Extends ADR-01182`
- **Date**: 2026-09-29

## Context

- `const p: Promise<any> = anyValue; p.then(…)` threw. The `any` →
  `Promise` coercion reinterpreted the box wrapper as the promise.
- A function returning `(…) => Promise<any>` from an `any` failed when its
  result was used.
- `console.log(promise)` printed an empty line, or `{}` through `any`.
  Node prints `Promise { 2 }`, `Promise { <pending> }` and
  `Promise { <rejected> reason }`.
- An Error nested in an inspected value (`{ f: err }`, a promise's reason)
  printed `[Object]`.

## Decision

- **Coercion.** `any` → `Promise<T>` takes the promise the box holds.
  - A `Promise<any>`'s wrapper is the promise itself.
  - A typed promise gets its `Promise<any>` view
    (`__kml_promise_view_any`). The view is fulfilled at once when the
    source is, since JS has one object and its reactions are not delayed.
    Otherwise it settles from the source's reaction.
  - A non-`any` element type then converts (`emitConvertPromise`). The
    conversion also runs at once for a fulfilled source.
  - `Promise.resolve(anyPromise)` takes the same view, as PromiseResolve
    returns its argument.
- **Inspect.** A finalize-time hook, `__kml_promise_inspect_parts`, gives
  the object inspector a boxed promise's state and its value or reason
  boxed. A static promise is inspected through its box.
- **Nested Errors.** A second finalize-time hook, `__kml_error_inspect`,
  renders a boxed Error nested anywhere as the top-level one does
  (`emitErrorToString`).

## Implementation notes

`emit_exprs_coerce.go`, `emit_anyprom.go`, `emit_record_view.go`,
`emit_inspect_host.go`, `dynjsonsrc/dynjson.c`, `sidecar_layout_test.go`.

## Side effects discovered

- A pending or rejected typed promise's view still settles one reaction
  later than the source. JS has one object; here the element
  representations differ.
