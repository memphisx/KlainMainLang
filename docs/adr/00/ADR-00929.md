# ADR-00929: `as T` narrows a dynamic value to the asserted concrete type

- **Relations**: `Extends ADR-00371` (type-assertion erasure), `ADR-00628` (NaN-boxed `any`). Follow-up to `ADR-00928` (variadic `arguments`)
- **Date**: 2026-09-13

## Context

TypeScript type assertions were erased wholesale (ADR-00371): `expr as T` kept
the operand's own inferred type, with a single carve-out for `JSON.parse(s) as
T` / `res.json() as T` (`CallExpression.AssertedType`). That left a real gap:
`const n = x as number` where `x: any` inferred `n` as `any`, not `number`, so
the value needed an explicit `: number` annotation to be usable — surfaced while
writing the `arguments` example (ADR-00928), where `const v = x as number`
inside a `for…of arguments` did not narrow. The assertion's meaningful,
*sound* direction — narrowing a dynamic (NaN-boxed) value to a concrete type by
unboxing — was simply not modelled.

## Decision

`expr as T` is honored as a real narrowing **when the operand's type is dynamic**
(`any`/`unknown`): the result type is the asserted concrete `T`, and codegen
unboxes the NaN-boxed word to `T`. Every other assertion stays erased — a
concrete operand keeps its own type and value, since a reinterpret across two
differing concrete representations is unsound and remains unmodelled (ADR-00371).
This matches TypeScript, where `any`→`T` is exactly an unchecked narrowing, and
is sound here because the box actually carries the value.

## Implementation notes

- New AST node `ast.AsExpression{Expr, TypeAnnot}` (ast/nodes.go). The parser
  (`parser_exprs.go`) wraps every non-carve-out `expr as T` in it; the JSON.parse
  /`.json()` `AssertedType`-on-call path is unchanged, and `satisfies`/`as const`
  stay pure identity (never wrapped).
- `inferExprType` returns the asserted type when the operand is
  `isUnconstrainedDynamic`, else the operand's own type.
- `emitAsExpression` (emit_undefined.go): unboxes via `coerce` for
  scalar/string/object targets (which already carries the correct any→concrete
  decode — `emitAnyToNum`→`fptosi` for integers, truthiness for bool,
  payload-pointer extraction for string/object) and via `emitUnboxBoxToType` for
  array / nullable-scalar targets (heap-header and presence-aware decode); a
  concrete operand returns unchanged.
- **A new node touches every AST walker.** Hand-written walkers updated to
  recurse through `AsExpression.Expr`, mirroring their existing
  `NonNullExpression` case: the resolver's rename pass (`resolver/rename.go` —
  the critical one, or an operand referencing a mangled top-level binding stays
  un-renamed and fails as "undefined variable") and its three readability walks
  (`walkExpr`, `walkExprDA`, `gatherAssignedNamesExpr`); codegen's free-variable
  scan (`scanExprFV`), the var-decl init-type switch (so `const n = x as T` takes
  T's slot), the async-hooks/`http.upgrade` new/call walks, and the four
  `escape_check.go` alias/expr walks. Reflective walkers (`lexicalThisIn`,
  `collectReassignedIdents`) handle it automatically.

## Side effects discovered

The resolver-rename omission was found the hard way: a narrowing `as` over a
promoted top-level `const`/`let` (a module global) failed as "undefined variable"
because the rename pass never descended into the new node, leaving the operand
spelled with the pre-mangling name while its declaration and the `moduleGlobals`
key were renamed. Fixed by adding the `AsExpression` case to the rename walker
(and, for completeness, the other resolver walks).
