# ADR-01101: Automatic semicolon insertion, restricted productions, contextual `async`/`abstract`

- **Relations**: `Implements TDD-00230` (Phase 1, P1.2); `Extends ADR-01100`
- **Date**: 2026-09-23

## Context

The parser had no automatic-semicolon-insertion (ASI) rule. Statements ended
with `consumeSemicolon()`, which accepted an optional `;` and nothing more, so:

- **`a` then `++b` on the next line printed `2 2`; Node prints `1 3`.** A
  postfix `++` was attached across the line break.
- **Two statements ran together without error.** `let x = 1 let y = 2`
  compiled, and so did `class A { x = 1 y = 2 }`.
- **Keyword rules ignored line breaks.** A line break before `=>`, or after
  `throw`, was accepted.
- **Some forms failed to parse.** An abstract method or an overload signature
  had to end with an explicit `;` before `}`. `async` and `abstract` were
  reserved words, so `const async = 5`, `{ async: 1 }` and
  `{ async pull(c) {} }` did not parse.

[ADR-01100](ADR-01100.md) gave every token a `PrecedingLineBreak` flag, which
is all these rules need.

## Investigation

- **Twelve `consumeSemicolon()` sites** in declarations, statements,
  destructuring, type aliases, namespaces and `import X = …`. The import/export
  declarations used bare `check(SEMICOLON)` instead.
- **Line numbers instead of line breaks.** `return`, `break`, `continue` and
  `yield` compared `peek().Line == tok.Line`. That works only when a token
  cannot span lines, and it ignores a comment containing a line break.
- **typescript-go's rules** (`internal/parser/parser.go`): `canParseSemicolon`
  accepts `;`, `}`, EOF or a preceding line break (`:6065`). Postfix `++`/`--`
  is taken only without a preceding line break (`:4781`). `async` and
  `abstract` are identifiers, recognised by look-ahead only where their keyword
  form applies.
- **Node 26.10.0 as the oracle,** for every case below. It rejects `(a)\n=> …`
  with "Unexpected line break between arrow head and arrow", and rejects
  `class A { x = 1 y = 2 }`.

## Decision

- **`parseSemicolon()`** accepts a `;`, or nothing before `}`, at EOF or at a
  line break (`canParseSemicolon()`), and otherwise reports
  `expected ';', got …`.
  - It ends every statement, the import/export declarations, and class fields
    and index signatures. A comma between class members is no longer accepted,
    since it is a syntax error in JavaScript.
  - A body-less method signature (abstract or overload) ends by the same rule.
  - The `;` after a do-while's `)` stays optional even on the same line, as the
    specification inserts it there.
- **Restricted productions, all read from the line-break flag:**
  - postfix `++`/`--`;
  - `return`, and the label of `break`/`continue`;
  - `yield`'s operand;
  - `throw` (`line break not allowed after 'throw'`);
  - `=>` (`line break not allowed before '=>'`).
- **`async` and `abstract` are scanned as identifiers.**
  - `isWord(n, w)` and `sameLine(n)` recognise the keyword forms:
    `async function`, `async x =>`, `async (…) =>`, `async <T>(…) =>`,
    `abstract class`, and a member modifier followed by a member name. Each
    requires the pair on one line.
  - `asyncFunctionAhead()` makes the decision in `parsePrimary`. Otherwise
    `async` is a plain identifier: a variable, a field, or a function called
    `async(1)`.
  - The `ASYNC` and `ABSTRACT` token types are removed.
- **Object-literal method shorthand gains the async and generator forms**
  (`async m() {}`, `*m() {}`, `async *m() {}`). Each builds the same
  `FunctionExpression` that `m: async function () {}` does.

## Implementation notes

- **Changed:**
  - `parser/parser.go`: `parseSemicolon`, `canParseSemicolon`, `isWord`,
    `sameLine`, `asyncFunctionAhead`.
  - `parser/parser_stmts.go`: statements, the restricted productions and
    body-less signatures.
  - `parser/parser_exprs.go`: postfix and `yield`.
  - `parser/parser_literals.go`: arrows, `parsePrimary`'s async path (now
    `parseAsyncFunctionOrArrow`), object methods,
    `parenGroupFollowedByArrowAt`.
  - `parser/parser_classes.go`: member modifiers and field ends.
  - `parser/parser_imports.go`, `parser/parser_types.go`, `lexer/token.go`.
- **Tests:** `tests/asi_test.go`. **Example:** `examples/basics/asi.ts`.
- **Docs:** a new status row ("Automatic semicolon insertion and the
  no-line-break rules") with its website reference entry (`lang.asi`). The
  streams caveat that `{ async pull(c) {…} }` does not parse is removed.

## Side effects discovered

- **A top-level `const r = rs.getReader()` is invisible inside a named
  function** (`undefined variable 'reader__kml_mod0'`). The previous binary
  fails the same way. Recorded as BACKLOG §0 item 27, for TDD-00230 phase 2.
- **A generator method in an object literal now parses,** but codegen rejects
  it with the existing rule that a generator expression is supported only as a
  top-level binding. That is a codegen limit, for TDD-00230 phases 2–3.
- **`return` then a value on the next line, in a function typed `number`,**
  now parses correctly as `return;`, but the absent value prints `0` where Node
  prints `undefined`. This is the representation problem owned by TDD-00230
  phase 2.
- **A user function named `main` still collides with the entry point** in the
  test harness (BACKLOG §0 item 17).

## Verification

All on macOS arm64 (M4):

- **Equivalence corpus** (24,125 files, as in ADR-01100), comparing the
  pre-change binary with this one:
  - No file that compiled before fails now.
  - 9 files that failed before compile now, among them
    `future-reserved-words/abstract.js`.
  - The remaining changes are between two errors. Test262 negative tests are
    now rejected at parse time rather than failing later in codegen. Code the
    parser used to get past by accident now stops at the first missing
    statement boundary: `with (o) {`, `using x = …`, import attributes.
  - All example IR is unchanged.
- **Every case matches Node 26.10.0:**
  - `a` then `++b`, and `c`, `--`, `b` on three lines;
  - `return` or `break` at a line break;
  - a regex after `if (…)`;
  - `>>`, `>>>`, `>=`, `>>=`;
  - `async`/`abstract` as names;
  - an async object method as a `ReadableStream` source;
  - the rejections of `let x = 1 let y = 2`, `throw` then a line break, a line
    break before `=>`, and `class A { x = 1 y = 2 }`.
- **Test suites:** `go test ./parser`, `tests/asi_test.go`, `make examples`
  (358/0), `make test-par`, `make status-check`, `make reference-check`.
