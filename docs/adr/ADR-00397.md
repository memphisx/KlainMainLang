# ADR-00397: `net.Server.address()` and the `listen(0)` ephemeral-port idiom

- **Relations**: Implements TDD-00131 (per-module Node API fidelity); Extends ADR-00324, ADR-00358 (net runtime)
- **Date**: 2026-08-27

## Context

Continuing TDD-00131's per-module work on `net`. `net` was already ✅ (server
`createServer`/`listen`/`on('connection')`/`close`, client `connect`, socket
`data`/`end`/`write`/`end`), but `server.address()` was missing — and a usage
tally over the corpus `test-net-*.js` ranks `.address()` (67 uses) second only to
`.listen()`. The reason is the dominant Node test idiom:

```js
const server = net.createServer(onConn);
server.listen(0, () => {                 // 0 = OS picks an ephemeral port
  const port = server.address().port;    // read it back
  net.connect(port, '127.0.0.1', onReady);
});
```

Without `address()`, `listen(0)` is unusable (no way to learn the assigned
port), which blocks the most common self-contained server+client test shape.

## Decision

`server.address()` returns Node's `AddressInfo` record `{ address, family, port }`:

- The **port** is read from the live listen socket via `getsockname` (new runtime
  helper `__kml_net_sockname_port`), so it reflects the actual bound port —
  including an OS-assigned ephemeral port from `listen(0)`. `bind(port=0)` already
  worked (the OS picks the port); the missing half was reading it back.
- **address** = `"0.0.0.0"`, **family** = `"IPv4"` — an honest reflection of what
  this compiler's server actually binds (IPv4 `INADDR_ANY`, ADR-00324/00358),
  **not** Node's dual-stack `"::"`/`"IPv6"` default. Tests overwhelmingly consume
  `.port`, so the family/address divergence is bounded and documented.
- `port` is a `number` (double, TDD-00123), so `net.connect(server.address().port,
  …)` and numeric comparisons work directly.

The record is built as a real object (calloc + typed field stores), so field
access, `JSON.stringify`, and `Object.keys` all work; its shape is declared once
(`netAddressType`) so member-type inference and the emitted struct agree.

## Also: `socket.address()` and `server.on('listening')`

- **`socket.address()`** reuses the same builder on the socket fd, reporting the
  socket's real local address+port (a loopback client reports `127.0.0.1` + its
  ephemeral local port). The address string is the *real* `getsockname` result
  via `inet_ntop` (`__kml_net_sockname_addr`), so server and socket both report
  honest addresses rather than a hardcoded one. Because the bind is IPv4-native,
  an accepted socket reports `127.0.0.1` where Node's dual-stack default reports
  `::ffff:127.0.0.1`.
- **`server.on('listening', cb)`** stores the listener in a new server-struct
  field (widened to 5 slots) and fires it when `listen()` binds; if registered
  after the server is already bound, it fires immediately. `listen()`'s own
  callback continues to fire as Node's one-time listening listener.

## Scope / follow-ons

- Server `'error'`/`'close'` events, an options-object `listen({ port, host })`,
  and `host` binding remain unimplemented (existing caveats).

## Verification

A self-contained `listen(0) → address().port → connect` round-trip (E2E
`TestE2ENetServerAddressEphemeralPort`) reports `port > 0` and round-trips a
payload. Verified on Apple Silicon (Mac). Against real Node the only difference
is `family`/`address` (`IPv4`/`0.0.0.0` vs Node's `IPv6`/`::`), as designed; the
port and the byte round-trip match.
