# ADR-00334: process lifecycle — `on('exit'/'uncaughtException')` + `exitCode`

- **Date**: 2026-08-24

## Context

Completing the Process / CLI area: `process.on` handled only `'SIGINT'`/
`'SIGTERM'`. This adds the lifecycle events `'exit'` and `'uncaughtException'`,
plus the deferred `process.exitCode`.

## Decision

A small always-consistent lifecycle runtime (`emitProcessLifecycleRuntime`),
emitted whenever exceptions or any process-lifecycle surface is used:

- Globals: `@__kml_process_exit_code` (i64, 0), `@__kml_exit_handler` /
  `@__kml_uncaught_handler` (closure headers, null), `@__kml_exit_ran` (i1).
- `@__kml_run_exit_handlers(code)` — runs the `'exit'` listener **once** with the
  code (no-op when unset). Called at normal program end, from `process.exit()`,
  and after an uncaughtException.
- `@__kml_process_uncaught(err) -> i1` — runs the `'uncaughtException'` listener
  and returns 1 if one is registered, else 0.

Because each function no-ops when its handler global is null, one definition
serves whether or not a listener was registered.

- **`process.on('exit', (code) => …)`** stores the listener; it runs at normal
  end (the emitter's `main` tail now returns `process.exitCode` and calls
  `run_exit_handlers` when `usedProcessLifecycle`) and from `process.exit()`.
- **`process.exit(code?)`** now runs the exit listener first, and with no
  argument exits with the current `process.exitCode` (matching Node).
- **`process.exitCode = N`** stores the deferred code; a bare `process` program's
  `main` returns it. Read via `process.exitCode`.
- **`process.on('uncaughtException', (err) => …)`** hooks `__kml_throw`'s
  uncaught path: `@__kml_process_uncaught` runs the listener and, if present,
  the default `"Uncaught: …"` print is skipped. The process still exits (code 1)
  — this compiler's setjmp/longjmp exception model has already unwound the stack
  to the top-level catch-all, so there is no in-progress computation to resume
  (unlike Node, which can continue). The exit listener runs on the way out.

## Implementation notes

- `runtime_process.go`: `emitProcessLifecycleRuntime`. `emit_process.go`:
  `emitProcessOn` gains `exit`/`uncaughtException` (resolving the listener with
  the right arg hint — `(code:number)` / `(err)` — instead of the zero-arg
  `timerCallbackPtr` the signals use); `emitProcessExit` rewritten.
- `runtime_exceptions.go`: the `__kml_throw` uncaught block now calls the hook
  and branches. `emitter.go`: emits the runtime + a lifecycle-aware `main` tail.
- `emit_exprs_assign.go`: `process.exitCode = N` write; `emit_exprs_member.go` /
  `emit_exprs_types.go`: the read.
- Gating: `usedProcessLifecycle` (set by the exit/uncaught/exitCode/exit
  emitters) drives the `main`-tail rewrite; the runtime is also emitted when
  `usedExceptionHelpers` (the uncaught hook references it). Non-lifecycle
  programs keep a plain `ret i32 0` — no behavior change.

## Side effects discovered

`'unhandledRejection'` is not implemented (needs rejected-promise tracking, a
separate hook) — disclosed on the status page. A stale signals test used
`process.on('exit', …)` as its "unsupported event" example; updated to
`'beforeExit'` (still unsupported).

## Verification

- `tests/process_test.go`: exit listener + `exitCode` (output order and exit
  code 3); `process.exit(5)` runs the listener and exits 5; `uncaughtException`
  runs the handler (skipping the default print) and exits 1; the default
  uncaught path (no listener) is unchanged (`Uncaught:` + exit 1).
- Full exceptions/try-catch/process/signals suites pass — the core `__kml_throw`
  change is behavior-preserving when no `uncaughtException` listener is set.
- Machine: verified on Mac (arm64).
