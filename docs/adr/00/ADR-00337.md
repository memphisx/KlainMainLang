# ADR-00337: Spread in call arguments V2 — multiple/mixed spreads into a rest parameter

- **Relations**: Implements TDD-00106 (V2); follows ADR-00335 (V1)
- **Date**: 2026-08-24

## Context

ADR-00335 shipped V1 of spread in call arguments: a *single* spread as the sole
filler of a callee's rest parameter, optionally after fixed arguments
(`f(...arr)`, `f(a, b, ...arr)`). It forwarded the array's own `(ptr, len)`
buffer straight into the rest slot — no copy — because a rest parameter's ABI is
byte-identical to how an array argument already lowers.

V1 deferred three cases as clean compile errors: multiple spreads (`f(...a,
...b)`), a spread mixed with positional args in the rest region (`f(...a, x)`,
`f(x, ...arr, y)`), and a spread into a variadic builtin. The concat primitive
V2 needs (`emitSpreadArrayLitData`, already used by array-literal spread) existed
but was unwired to calls.

## Decision

Support **any number of spreads, in any order, freely mixed with ordinary
positional arguments — but only within the rest region** (after the fixed
parameters). `f(...a, ...b)`, `f(...a, x, ...b)`, `f(x, ...a, y)` all work, for
named functions, closures/arrows, and now class instance/static methods too.

The single-spread V1 fast path (direct `(ptr, len)` forward, no copy) is kept.
Anything with a positional arg alongside a spread, or more than one spread, goes
through a new `emitRestArgBuffer`: it evaluates every rest-region argument once
in left-to-right source order, sizes one contiguous buffer at runtime (each
static arg counts as 1, each spread adds its runtime length), and fills it with
a write cursor — `memcpy` per spread, `store` per static arg. This mirrors
`emitSpreadArrayLitData`'s cursor technique but keys off a call's arg list and
resolves each spread via `resolveArrayForHOF` (so an array-*returning*
expression works, not only a bare array variable).

Still rejected as clean compile errors (each would need work outside this
change):

- A spread into a **fixed-arity** (rest-less) function — needs a runtime split
  against static arity, ill-defined.
- A spread filling a **fixed parameter slot** of a rest function (`f(...arr)`
  where `f(a, b, ...rest)`, or `f(1, ...arr)` where the `...arr` would have to
  feed a defaulted fixed param) — same static-split problem.
- A spread into a **variadic builtin** (`console.log(...a)`, `Math.max(...a)`) —
  each folds a static arg list one expression at a time and would need bespoke
  array-input handling.

## Implementation notes

- `emit_call.go`: `checkSpreadArgs` relaxed — a spread is allowed at any
  rest-region index (`i >= regularCount`); only a spread at a fixed slot, or into
  a rest-less callee, is rejected. New `anySpread` helper picks the concat path;
  new `emitRestArgBuffer` is the shared V2 buffer builder.
- The rest-packing branch in all four call paths — named
  (`emitCallToFuncSig`), closure (`emitClosureCallByPtr`, emit_func.go), and
  class instance/static (`emitClassCall`/`emitStaticMethodCall`,
  emit_classes.go) — gained the same three-way branch: `singleSpread` forward →
  `anySpread` concat → plain malloc-and-store.
- The class instance/static method paths had **no** spread handling at all in V1
  (V1 scoped to named functions and closures). They now call `checkSpreadArgs`
  and route both the single-spread and mixed cases, closing `obj.m(...arr)` /
  `C.s(...arr)`.
- Element-type check per spread is unchanged from V1 (exact match on
  `IR`/`IsArray`/`IsObject`).

## Verification

- `tests/spread_test.go`: V2 behavior tests for multiple spreads, mixed
  positional+spread (named, closure), instance- and static-method spread, plus
  the two remaining rejection cases (fixed-slot fill, variadic builtin). V1's
  fixed-arity rejection test stays.
- `examples/language/spread_args.ts` extended with a multiple/mixed spread and a
  class-method spread; run on macOS (arm64).
- Machine: verified on Mac (arm64); the change is platform-independent.
