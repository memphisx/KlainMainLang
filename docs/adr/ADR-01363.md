# ADR-01363: A promise viewed under another type settles with its source

- **Relations**: Refines TDD-00230 phase 5's promise views
- **Date**: 2026-10-03

## Context

Measuring Node's Blob reader timing (ADR-01362) through a helper taking a
`Promise<unknown>` showed one microtask more than Node for any promise that
was still pending when passed.

## Investigation

- A typed promise passed where another element type is expected (a
  converted `Promise<T>`, `emitConvertPromise`) or boxed into `any`
  (`__kml_promise_view_any`) gets a second promise. A settled source fills
  it at once. A pending one fills it from a reaction job, so the view's own
  reactions run one microtask after the source's.
- In JS both names are the same object, so they settle in the same step.
- A plain `.then` chain already matched Node: settling enqueues reactions
  directly.

## Decision

- **Synchronous reactions.** `microtask.c` keeps a set of reactions that
  run inside the settlement rather than as jobs. `__kml_promise_attach_sync`
  registers one, marks the source handled (the view answers for its
  rejection), and pushes it. `__kml_promise_drain_reactions` runs such a
  reaction inline and queues the rest.
- **Converter.** The promise converter attaches its runner this way.
- **`any` view.** The view attaches a mirror (`pview_mirror`) that copies
  the settlement, boxing a fulfilled value.

Neither runner calls user code.

## Implementation notes

`codegen/llvm/microtasksrc/microtask.c`, `promisesrc/anyprom.c` and
`emit_anyprom.go`.

## Verification

Mac (Apple Silicon), against Node 24: hop counts for a resolved promise, one
and two chained `then`s, an `any` view, and a rejection caught through a
`Promise<unknown>` (`TestE2EPromiseViewSettlesWithSource`); the Blob reader
timing table; the promise, async, await, microtask and rejection groups.
