# ADR-00641: Decorators Stage 1 — parsing + observe-only property/parameter decorators

- **Relations**: `Implements TDD-00161` (Stage 1)
- **Date**: 2026-09-02

## Context

TDD-00161 Stage 1: lex/parse `@decorator` at every placement and run the
*observe-only* experimental decorators — property and parameter — faithfully at
class-definition time, while cleanly rejecting the placements whose return value
can replace a target (class, method, accessor), which need later stages. The
lexer previously rejected `@` outright, so every decorated file died at lex
time; decorators are the #1 TypeScript-oracle front-end blocker (TDD-00121
Track C).

## Investigation

- Lexer: `@` fell through to the `unexpected character` default (`lexer.go`).
- Class/member/param AST nodes carried no decorator field; the member loop in
  `parseClassDecl` (`parser_classes.go`) and `parseParamList`
  (`parser_stmts.go`) are the two positions that needed a decorator prefix.
- Invoking a decorator needs a `target` object and the ability to *call* the
  decorator value. Two findings shaped the approach:
  - Reusing the ordinary call path by synthesizing an `ast.CallExpression`
    (callee = the decorator expression, args = the spec's `(target, key[,
    index])`) sidesteps hand-writing the ABI: named-function decorators dispatch
    directly, argument coercion is automatic. A single per-class D1 dynamic
    object (`__kml_dynobj_new`) stands in for the prototype `target`.
  - **Ordering matters.** Decorators must run at the class's *source position*
    in top-level execution — a decorator that pushes to a module-level registry
    declared above the class must see it initialized. Emitting the applications
    into the hoisted `_staticinit` (which runs before all module top-level code,
    ADR-00375) produced empty registries. The fix emits them from the top-level
    `ClassDeclaration` statement in `emitStmt` instead, where preceding
    statements have already run.
- A pre-existing bug surfaced: `rewriteClassDecl` (`resolver/rename.go`)
  rewrote field *types* but never field *initializers*, so a top-level name in
  `static x = f()` was never mangled — `f` was `undefined function or closure`
  at emit. The same gap blocked decorator expressions. Fixed both.

## Decision

1. **Lex** `@` as a new `AT` token.
2. **AST**: a `Decorators []ast.Expression` field on `ClassDeclaration`,
   `FunctionDeclaration` (methods), `AnnotField` (properties), and `Param`.
3. **Parse** decorator runs (`@` + a `parseCallMember` left-hand-side
   expression) before a class (statement position, incl. `export`/`export
   default`), before each class member, and before each parameter.
4. **Emit** (`emit_decorators.go`, from `emitStmt`'s `ClassDeclaration` case):
   create one per-class dynamic `target`, bound to a synthetic per-class local,
   then for each decorated property emit `dec(target, "name")` and for each
   decorated parameter `dec(target, key, index)` (key = method name, or
   `undefined` for a constructor parameter). Multiple decorators on one element
   apply bottom-up. Return values are discarded — spec-exact for these two
   kinds.
5. **Reject** class and method/accessor decorators at `emitClassDecl` with a
   clear compile-time message (they can replace the target; Stages 2/4).
6. **Resolver**: `rewriteClassDecl` now also rewrites field initializers, field
   decorators, and class decorators; `rewriteFunctionLike` rewrites parameter
   decorators.

## Implementation notes

- The synthesized-call approach means a decorator expression that is itself a
  call — a factory decorator, `@tag("x")` — compiles to calling the *returned*
  value, which hits the bare-function-as-value ABI gap (a returned top-level
  function is not a closure header): a clean compile-time rejection, not a
  crash. Direct decorators (`@tag`) are the Stage 1 supported form.
- The per-class target binding name is `__kml_dec_target$<Class>` so several
  decorated classes emitting into the same top-level scope don't collide.

## Side effects discovered

- Fixed the static-field-initializer name-rewrite bug above (a top-level
  function/const referenced in `static x = f()` now resolves) — verified by
  `TestE2EStaticFieldInitializerCallsFunction`, independent of decorators.
- Factory (`@dec(...)`) decorators and decorators whose returned closure
  captures its factory arguments are not supported in Stage 1 (the latter is
  the separate dynamic-prototype-method capture limitation). Both are clean
  rejections. Tracked under TDD-00161's later stages.

## Verification

- `tests/decorators_test.go`: property decorators run in order with correct
  args; multi-decorator bottom-up order; parameter decorators (constructor key
  `undefined`, method key = name, indices); class/method decorators rejected;
  factory decorator rejected cleanly; the static-field-initializer regression.
- `examples/decorators/decorators.ts` compiles and runs (a required-field +
  injection registry populated in correct source order).
- `go vet ./...`, class/object/static/dyn/reflect/namespace/generic E2E suites,
  and lexer/parser package tests pass. Mac (Apple Silicon).
