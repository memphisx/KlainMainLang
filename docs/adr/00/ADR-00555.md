# ADR-00555: EventSource Content-Type match is case-insensitive

- **Relations**: Extends TDD-00038
- **Date**: 2026-09-01

## Context

`EventSource`'s connect-time `Content-Type` validation compared both the header
name (`Content-Type:`) and the MIME value (`text/event-stream`) with
case-sensitive `strncmp`. HTTP header names and MIME types are
case-insensitive, so a server sending `Text/Event-Stream` (or
`content-type:`) was wrongly treated as a malformed response and the
connection failed permanently. The value-match case-sensitivity was a
disclosed caveat on the networking status row.

## Investigation

`__kml_eventsource_header_cb` (runtime_eventsource.go) matched the header-name
prefix (13-byte `strncmp` at the header line start) and, in
`__kml_eventsource_scan`, the stored value prefix against `text/event-stream`.
Both are simple `strncmp` calls; `strncasecmp` is the drop-in
case-insensitive equivalent from the C library.

## Decision

Add `ensureStrncasecmp` (declares `strncasecmp`) and switch both comparisons —
the `Content-Type:` header-name prefix and the `text/event-stream` value prefix
— to `strncasecmp`. The prefix lengths are unchanged.

## Implementation notes

- `ensureStrncasecmp` mirrors `ensureStrncmp` in runtime_core.go, guarded by a
  new `usedStrncasecmp` flag; `runtime_eventsource.go` calls it alongside
  `ensureStrncmp`.
- A charset parameter after the MIME type (`; charset=utf-8`) is already
  tolerated by the prefix match; only the casing needed fixing.

## Side effects discovered

None.

## Verification

`TestE2EEventSourceMixedCaseContentTypeAccepted` (a `Text/Event-Stream;
charset=utf-8` response delivers its `onmessage` event) passes, and
`TestE2EEventSourceWrongContentTypeEndsClosedNoRetry` (a genuinely wrong
`text/plain` still fails terminally) still passes. Built and verified on Mac
(Apple Silicon).
