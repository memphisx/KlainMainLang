# ADR-01505: `arguments` has the lib's `IArguments` type

- **Relations**: Extends ADR-01489, TDD-00230
- **Date**: 2026-10-09

## Context

The checker left a function's own `arguments` unanswered. A function
returning it had an unanswered return type, which was bucket 2 of the
shadow report (802 rows), and calls through such a function were not
checked.

## Decision

- `lib/es.d.ts` declares tsc's `IArguments`:
  `[index: number]: any; length: number; callee: Function`.
- The implicit `arguments` binding has that type.

## Side effects discovered

- tsc reports TS2554 for a call with more arguments than a `.ts`
  function declares, even when the function reads `arguments`. The
  strict lane now does the same where it used to compile.
  `TestArgumentsLengthCountsPassedArguments` keeps only tsc-valid
  calls. The extra-argument calls moved to
  `TestArgumentsLengthExtraArgumentsJS`, the JS form tsc accepts.
- That JS test exposed ADR-01506.

## Divergences

None.
