# ADR-01142: Overloaded builtins lower per overload; array results (split)

- **Relations**: `Implements TDD-00230` (Phase 3, P3.2); `Extends ADR-01141`
- **Date**: 2026-09-25

## Context

TDD-00230 P3.2 maps a builtin's overloads one-to-one to runtime entry
points, selected as TypeScript resolves the call.

`String.prototype.split` is the first case. Its string-separator form is a
plain search, and its RegExp form a pattern match. The hand-written emitter
chose between them by the argument's codegen type, and returned a
by-value `{ptr, i64}` aggregate.

## Investigation

- **The checker's member type** for an overloaded method is one interned
  `overloaded` type. It kept only the last member's declaration, so an
  overload's own `@lower` could not be reached from its signature.
- **tsc picks the first overload the arguments fit.** An `any` argument
  fits every overload, but which form runs depends on its run-time value
  (`s.split(x)` with a RegExp in `x`). A generic overload before the fitting
  one would decide by inference.
- **Returning an array from C.** A 16-byte struct is returned in registers
  on arm64 and x86-64 SysV, but through a hidden pointer on Windows x64,
  so a `{ptr, i64}` return has no portable IR form. A header pointer
  (the `{data, len}` cell a JavaScript array value refers to, TDD-00213)
  does, and `arrayValueFromHeaderReg` reads it back.
- **Behaviour against Node.**
  - The old byte-wise empty-separator split broke a multi-byte character
    into invalid halves (`"héllo".split("")`). Node splits into UTF-16 code
    units, which for Basic Multilingual Plane text are the UTF-8 sequences.
  - Under `-compat=js`, `s.split(undefined)` segfaulted in both the old
    and the new builds. JavaScript returns `[s]`: the separator's undefined
    check comes before ToString.

## Decision

- **Checker.**
  - `Property.Decls` keeps every declaration of an overloaded interface
    method, in the order of its type's `Overloads`.
  - `Checker.MemberOverloadDecls` returns them.
  - `Checker.OverloadIndex` names the overload a call resolves to: the
    first one that fits by arity and assignability. It declines (-1) when
    an argument is `any`, `unknown` or unanswered, or when a generic
    overload comes first.
  - `StringMember` returns the overloads too.
- **Lowering.** `loweredCall` lowers an overloaded method through the
  resolved overload's own declaration and signature, and declines when it
  cannot tell which overload runs.
- **Array results.** `lowerRepr` represents `string[]` as the array's
  header pointer: an entry point returns it, and the value is the array
  read through it. An array argument is not lowered yet.
- **`lib/es.d.ts`** declares `split` as three overloads:
  - `split(separator: string, …)`, lowered to `__kml_String_split`;
  - `split(separator: RegExp, …)`, on the hand-written RegExp path;
  - `split(separator: string | RegExp, …)`, which keeps a union argument
    type-checking as before.
- **`string.c`'s `__kml_String_split`**:
  - ToUint32 of the limit;
  - an empty separator splits by UTF-8 sequence;
  - `""` gives `[""]`, or `[]` with an empty separator;
  - a null (undefined) separator leaves the string whole.

  The hand-written emitter routes a JavaScript `split(undefined)` to it.

## Side effects discovered

- **A `string | RegExp` separator splits as a string** even when it holds a
  RegExp (BACKLOG: `string | RegExp` separator), in the previous build
  too. The union has no run-time dispatch.

## Verification

- **`TestE2EStringSplitLowered`:** ten separators with limits of 2, 0 and
  -1, a pushed-to result, the RegExp overload, and the `-compat=js`
  undefined separator. The expected output is Node's.
- **`tools/tsdiag`:** 1,584 of 1,586 (the 2 are the known Annex B cases);
  0 on the project's programs. **`tools/libconform`:** 0 divergences.
- **`make examples`:** 358/358.
- **Test262 (both lanes, together with ADR-01142–01144):** strict 7,031
  (+7), js 7,793 (+9).
- **`make test-par`:** only the four known `-mm=gc` failures and the
  load-dependent HTTP hang (`TestE2EHTTPChainedListenBinding`).
