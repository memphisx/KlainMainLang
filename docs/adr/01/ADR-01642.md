# ADR-01642: Socket end-of-stream fidelity on macOS: reset, writeAfterFIN, same-pass shutdown

- **Relations**: Extends [ADR-01625](ADR-01625.md), [TDD-00180](../../tdd/TDD-00180.md)
- **Date**: 2026-10-16

## Context

After the Windows libuv work, CI failed on both macOS lanes:

- `TestE2ETLSServerWriteAfterClientDestroy`: ours `server error ECONNRESET`,
  Node `server error EPIPE`. The test was new with [ADR-01625](ADR-01625.md)
  and had only run on Windows.
- `TestE2EDgramUdp6MulticastOptions`: ours and Node both print
  `join EADDRNOTAVAIL` on macOS. The test hardcoded Linux's result, where
  the join works and only a second drop fails.

## Investigation

A TLS server writes 64 KiB every millisecond while its client destroys the
connection on the first `'data'`. Node on the Apple Silicon Mac, ten runs:
five `write EPIPE`, five `read ECONNRESET`. It never closes cleanly. The
client closes with bytes unread, its kernel answers with a reset, and
whichever server operation meets the reset first reports it. Ours,
traced with stderr probes in `klainpool.c`, did something else:

1. `tcp_recv` on a TLS socket drained the kernel socket into the session's
   memory BIO before returning any plaintext (`tls_pull` loops to EAGAIN).
   The client's first `'data'` came after every byte had left the kernel,
   so its `close()` sent a FIN, not a reset.
2. The server then read a clean end. OpenSSL 3 reports an end without
   close_notify as `SSL_ERROR_SSL` (`SSL_R_UNEXPECTED_EOF_WHILE_READING`).
   `tls_sess_read` mapped that to `-ECONNRESET`, which made up a reset
   that never happened. Node's TLSWrap passes the stream's EOF on as an end.
3. On that end without `allowHalfOpen`, Node swaps `socket.write` for
   `writeAfterFIN`, which makes a later write EPIPE ("This socket has been
   ended by the other party"). Our `net.Socket` recorded `endedByPeer` and
   never read it.
4. The shutdown that end requests ran one loop iteration late. libuv's
   `uv__stream_io` drains a shutdown right after the read that asked for
   it, so `'finish'` comes before a `setImmediate` queued from `'end'`. Our
   dispatch ran the shutdown step before the read step, so it waited for
   the next pass.

## Decision

- TLS reads and the handshake pull one chunk of ciphertext at a time, only
  when the session needs more (`tls_pull_once`). This matches libuv handing
  each chunk on before reading the next. Application data behind the
  handshake's last flight stays in the socket.
- A TLS write completes only once its ciphertext has left the session's
  output buffer, as a libuv write request does. Before, the write was
  reported done while ciphertext was still pending, and a later failure to
  send it (EPIPE) reached no one. `tls_push` records the errno for the
  waiting request.
- `tls_sess_read` treats the unexpected-EOF reason as an end. A socket error
  under the session wins over that end: `tcp_recv` returns the recorded
  errno (`read ECONNRESET`).
- `net.Socket.write` implements `writeAfterFIN`: the error goes to the
  write's callback on the next tick and destroys the socket.
- The shutdown step is `tcp_try_shutdown`, run before the read step as
  before and again after it.
- The TLS test's client pauses and destroys 50 ms after its first data,
  so its socket always holds unread records and its close is a reset on
  every platform. Without that, whether the client closes with bytes unread
  is a race: a fast client reads everything sent so far, its close is a
  FIN, and the server ends cleanly, which Node also does when it loses that
  race. Both sides must then report the reset's error. Which operation meets
  it first still varies on Linux (`read` or `write` ECONNRESET, in Node
  too), so the test accepts EPIPE or ECONNRESET. The udp6 test compares
  against Node on the same host.

## Implementation notes

`codegen/llvm/threadpoolsrc/klainpool.c` (`tls_pull_once`, `tcp_recv`,
`tcp_try_shutdown`), `codegen/llvm/tlssrc/tlshandle.c`, `lib/node/net.ts`,
`tests/tls_write_error_test.go`, `tests/dgram_test.go`.

An earlier attempt gated the shutdown on the descriptor being reported
writable. It moved `'finish'` later, away from Node, and was dropped.

## Side effects discovered

The absent-callback adapter crash, [ADR-01641](ADR-01641.md).

A review of the Windows work for other macOS gaps found one:
`TestRuntimeSymbolsResolveWithinRuntime` matched `__kml_` against `nm` output,
and Mach-O prints C's `__kml_x` as `___kml_x`, so on macOS the guard
checked nothing. `nmSymbols` now drops that leading underscore on Darwin;
the test passes there with real symbols.

## Verification

TLS probe with the paused client: Apple Silicon Mac, ours `write EPIPE`
8 of 8, Node 6 of 6. Linux x86-64, ours and Node both a mix of
`read ECONNRESET` and `write ECONNRESET`. New tests `TestE2ENetWriteAfterPeerEndIsEPIPE`
and `TestE2ENetEndShutdownSamePass` match Node's output line for line. The
net, TLS and dgram suites pass. Linux x86-64 (DeskMini): `make test-par`.
Windows: not re-run, so the Windows half of the TLS probe still rests on
[ADR-01625](ADR-01625.md).
