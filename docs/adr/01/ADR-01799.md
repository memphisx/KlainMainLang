# ADR-01799: `yield` is an identifier outside generators in sloppy code

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- `yield` was a hard keyword everywhere (TDD-00061). JS reserves it only inside generator functions and in strict code, so sloppy scripts can bind and read it elsewhere: `var yield`, `function yield() {}`, and in a plain function nested in a generator. Test262 covers these in its generator directories ("expected IDENT, got yield").

## Decision

- The parser tracks generator context. `parseFunctionRestThis` sets `inGen` from `nextGen` for a function's parameters and body, and each generator call site sets `nextGen`. A function expression's own name is read in that function's context.
- Outside a generator, `peek` reads a `yield` token as an identifier and records it. When the program is strict (a "use strict" directive or module syntax), the first recorded one is a parse error ("'yield' is a reserved word that cannot be used here").
- As in tsc's parser, a `yield` outside a generator followed on the same line by an identifier, keyword or literal (`yield 1`) is still parsed as a yield expression, so it gets the early error TS1163 rather than a stray-name parse error.
- The strict lane follows tsc's alwaysStrict: the checker reports TS1212 ("Identifier expected. 'yield' is a reserved word in strict mode.") for `yield` as a name, parameter, binding or reference.

## Consequences

- `TestE2EJSFileYieldIdentifier` compares a nested plain function binding `yield`, a function expression named `yield`, a top-level binding, and `yield` as a property name against Node.
- `TestYieldReservedAsIdentifier` covers sloppy acceptance and the strict and in-generator rejections.
- Not yet covered: a strict region inside a sloppy script (a "use strict" function, a class body) does not yet reject `yield` as an identifier.
