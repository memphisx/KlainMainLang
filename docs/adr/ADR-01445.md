# ADR-01445: An empty array literal takes its asserted type

- **Relations**: Implements TDD-00230 (P2.2)
- **Date**: 2026-10-07

## Context

A shadow probe of a module-level object literal showed codegen typing
`{ items: [] as string[] }` as `items: number[]`. Pushing a string into it
failed to compile with "type mismatch in array element"; Node runs it.

## Investigation

- `as` keeps its operand's own type except when narrowing from `any`
  (ADR-00929). An empty literal's own type is the `number[]` default, so
  the assertion was lost.
- A binding (`const e = [] as string[]`) worked: its declaration path takes
  the annotation. An object literal's field and a return value had no such
  path.
- `emitAsExpression` already built a literal as its asserted array type
  when the element is `any`.

## Decision

An empty array literal asserted to an array type is built and inferred as
that type, as the `any[]` case is: the assertion is its only type source.

## Verification

- `TestE2EEmptyArrayAssertion` (against Node) passes on the Mac.
