# ADR-00868: Incremental piped stdout — line-buffer + per-write flush

- **Relations**: `Fixes gap found in ADR-00867`
- **Date**: 2026-09-11

## Context

ADR-00867 found that piped `stdout` was block-buffered and flushed only at exit:
C stdio full-buffers a stream that is not a TTY, so `console.log` / `printf` to a
pipe or file withheld all output until the program ended. A program piped to
`tee` / `grep` or a Docker log collector showed nothing while it ran — unlike
Node, which delivers `process.stdout` incrementally. This matters directly for
the CLI-tool and Docker-microservice targets.

## Decision

Two changes, both POSIX-only (Windows keeps its own stdio path — the IOCP reactor
owns it, and the UCRT treats `_IOLBF` as full buffering anyway):

- **Startup**: `main`'s prologue calls `setvbuf(stdout, NULL, _IOLBF, 0)` so
  stdout is **line-buffered** regardless of whether it is a TTY or a pipe —
  flushing on each newline, matching a TTY's own default and Node's
  line-at-a-time delivery, rather than withholding until exit. The `stdout`
  `FILE*` is a libc extern global whose symbol differs by platform (`stdoutGlobalSymbol`:
  glibc `stdout`, macOS `__stdoutp`).
- **`process.stdout.write`**: followed by `fflush(stdout)`. Line buffering alone
  would hold a write with no trailing newline until the next newline or exit;
  Node delivers it immediately, so each explicit write flushes. `console.log`
  (always newline-terminated) relies on line buffering and is not per-call
  flushed, so its common high-volume path keeps one write syscall per line.

The existing `ensureFflushDecl` is reused for the `fflush` declaration (a second
`declare` with a mismatched signature is an IR redefinition error — caught in
testing). `fflush` on the same `stdout` stream preserves ordering against any
buffered `console.log` output, so interleaving stays correct.

## Faithfulness / perf

Line buffering is the faithful default (it is what a TTY already does and what
Node's incremental delivery looks like for line output). The residual divergence
is mid-line coalescing of a newline-less `console.log` fragment built across
multiple calls — not expressible here, since `console.log` always terminates its
own line. The per-write `fflush` on `process.stdout.write` trades a syscall per
write for Node-faithful immediacy; a program doing millions of tiny
`process.stdout.write` calls pays for it, which is the faithful cost (Node's
stdout-to-pipe is synchronous on Unix). No opt-out flag added; revisit only if a
real workload shows it dominating.

## Verification

- E2E `tests/stdout_flush_test.go` (`TestE2EStdoutFlushesIncrementally`): a
  newline-less `process.stdout.write` marker is read off the pipe *before* the
  child is triggered to exit — a deadlock-or-pass handshake, no timing. Verified
  by hand that three timer-separated `console.log`s arrive 300 ms apart through a
  pipe (not batched at exit), and that a newline-less `process.stdout.write`
  arrives immediately.
- `make test-par` green; `go vet` clean.
- Platform: Apple-Silicon Mac.
