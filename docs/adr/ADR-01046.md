# ADR-01046: `import.meta.url` and `url.pathToFileURL` render a file URL the way Node does

- **Relations**: `Extends ADR-00148, ADR-00671, ADR-00722`
- **Date**: 2026-09-21

## Context

Found while diffing IR across two copies of `examples/` (ADR-01045's check): the string baked in for
`import.meta.url` on Windows was `file://R:\kml-scratch\…\import_meta_url.ts`. Node's is
`file:///R:/kml-scratch/…/import_meta_url.ts`. The resolver built it as `"file://" + absolutePath`, which is only
right for a POSIX path with no character that needs escaping; the two E2E tests pinned that same concatenation, so
they passed on every host.

A usage probe (`tools/testsel/probes/import_meta_usage.ts`: `fileURLToPath(import.meta.url)`,
`new URL('./data file.json', import.meta.url)`, `pathToFileURL(here).href === import.meta.url`) then showed a
second gap, in the runtime `url.pathToFileURL`: a name containing `[ ] { } ~` came back unescaped.

## Investigation

- Node computes a module's `import.meta.url` as `pathToFileURL(filename).href`. What it escapes was taken from
  Node 24 itself (`tools/testsel/probes/fileurl.mjs`, both `{ windows: true }` and `{ windows: false }`): C0
  controls, space, DEL, every byte of a non-ASCII character, and `" # % < > ? [ ] ^ { | } ~` plus the backtick —
  wider than the WHATWG path percent-encode set. The sub-delims `! $ & ' ( ) * + , ; = @` stay literal. On POSIX a
  backslash is a file-name character (`%5C`); on Windows it is a separator, a drive path gains a leading `/`, and a
  UNC path's server becomes the URL host.
- `emitPathToFileURL` handed the resolved path to `curl_url_set(CURLUPART_PATH, …, CURLU_URLENCODE)`. libcurl's
  encoder leaves `[ ] { } ~` alone. Pre-escaping and passing the path without the flag does not work either:
  libcurl then lower-cases the hex digits of the escapes (`%5b`), Node's are upper-case.

## Decision

- `resolver/fileurl.go`: `fileURLFromPath(path, windows)` — the rendering above, as a pure function; the
  `ImportMetaUrl` rewrite calls it with the host OS (the compiler targets its host).
- `url.pathToFileURL`: the path is escaped by the shared table-driven encoder with a third table
  (`fileURLPathSafe`, `@__kml_encode_file_url_path`), and the URL object's `pathname` and `href`
  (`"file://" + host + path`) are stored from that string on every platform. libcurl still parses the URL for the
  other fields. This replaces the Windows-only block that rebuilt `href` for a UNC host.

## Implementation notes

`resolver/fileurl.go` (new), `resolver/rename.go`, `codegen/llvm/runtime_encoding.go`, `emit_url.go`, `emitter.go`.
The two tables (Go-side and IR-side) must stay in step; both cite the probe.

Tests: `resolver/fileurl_test.go` (21 rows, expected values copied from the Node probe),
`TestE2EImportMetaUrlIsPercentEncoded` (new), the two existing `import.meta.url` E2E tests now expect the Node
form instead of the raw concatenation, `TestE2EPathToFileURLNodeEscapeSet` (new).

## Side effects discovered

- The `url.pathToFileURL(path) (POSIX)` status row and its website reference entry still said "POSIX only"; the
  Windows half shipped with ADR-00722. Caveat text corrected; the row name is unchanged.

## Verification

Windows 11 x64: both probes diff clean against Node 24 (`import_meta_usage.ts` fully;
`path_to_file_url_chars.ts` except the two non-ASCII rows, which differ only because a string iterates per byte —
the disclosed caveat of ADR-00535 — not in what `pathToFileURL` returns). All 37 non-network E2E tests mentioning
`pathToFileURL`/`fileURLToPath`/`import.meta`/`URL` pass. Linux x86-64 (Docker): `go test ./resolver`, the
`import.meta`, `PathToFileURL` and `FileURL` E2E tests pass. macOS: not run.
