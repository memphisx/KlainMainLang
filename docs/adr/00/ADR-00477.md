# ADR-00477: closure adapter trampolines (the any-boundary boxing fix)

- **Relations**: Fixes the bug deferred in [ADR-00475](ADR-00475.md); Extends [ADR-00469](ADR-00469.md)
- **Date**: 2026-08-29

## Context

ADR-00475 deferred a silent-wrongness bug: a closure compiled against a
concrete signature, stored into a function-typed slot whose signature
differs in *dynamism*, was passed through as a raw header-pointer copy.
The call site then dispatched by the slot's declared type and
reinterpreted the concrete return word as an `{ i8, i64 }` dynamic box
(or vice versa):

```ts
const g: (n: number) => any = (n: number): string => "n" + String(n);
console.log(g(1));   // printed "[object Object]"
```

The same held for parameters in both directions. It also blocked generic
class methods (their ADR-00469 erasure to `any` rides exactly this path).

## Decision

`coerce` gains a function-type branch (before the same-IR passthrough —
both sides are "ptr"): when `funcAdapterPlan` reports the two signatures
disagree on return/parameter dynamism and every needed conversion is
supported, `emitClosureAdapter` generates a trampoline
(`@__kml_fnadapt_N`) whose LLVM signature is exactly the *target* type's
caller ABI, whose env is the *original closure header*, and whose body:

1. loads the original fn/env from the header,
2. converts each argument — unboxing a dynamic argument for a concrete
   parameter (`emitUnboxBoxToType`), boxing a concrete argument for a
   dynamic parameter (`emitBoxValue`), forwarding same-dynamism ones,
   dropping extra target arguments (JS's ignore-extra-callback-args),
3. makes the indirect call typed by the *source* signature,
4. converts the return the same way (`void` under a dynamic slot returns
   a boxed `undefined`).

A fresh `{adapter, originalHeader}` closure header is returned, typed as
the target. Emission uses the existing `beginThunkEmit` builder-swap, so
an unsupported conversion discovered mid-build discards cleanly and falls
back to the old passthrough (never worse than before).

Scope guards (`funcAdapterPlan`): no rest parameters, source arity ≤
target arity, aggregate parameters (arrays' split `(ptr, len)`, nullable
scalars' `{ i1, T }`) not converted or forwarded — those keep the
passthrough, disclosed. Concrete-vs-concrete IR mismatches are not this
adapter's job.

**Generic class methods are re-enabled** via the ADR-00469 erasure —
the ADR-00475 clean rejection is superseded; `Box.map<U>(f)` with a
concrete callback now produces correct values through the boxed
boundary.

## Verification

Mac. `tests/dynamic_test.go`: `TestE2EClosureAdapterMatrix` (all seven
directions: string/number/boolean returns boxed, any-return unboxed into
a concrete slot, both parameter directions, arity narrowing,
argument-position coercion, void→`undefined`) and
`TestE2EGenericClassMethodViaAdapter` (string- and number-typed
instantiations of one erased method) replace ADR-00475's rejection test;
`examples/types/any_unknown.ts` extended. **Full `make test-par` green**
(coerce is on every assignment/argument path — the two standing
embed-fixture cwd artifacts are the only exceptions, as always). TS
oracle: agreement 5264 → 5261 (match-accept 1752 → **1805**; a handful of
previously-rejected ill-formed-generic cases now compile and count as
false-accepts — the erasure trade disclosed in ADR-00469). Node oracle
unchanged (40).
