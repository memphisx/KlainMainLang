# ADR-00876: Test262 async protocol, raw/module attempts, pending-capability buckets

- **Relations**: `Implements TDD-00204`, `Extends ADR-00151`
- **Date**: 2026-09-11

## Context

The Test262 in-scope filter had drifted from scope boundary to excuse
(TDD-00204 audit): the 5,624 `async`-flagged files were excluded with a
"deferred until measured" note although async/await, Promises, and the event
loop shipped long ago; the 832 `module`-flagged and 32 `raw`-flagged files
were pre-excluded rather than attempted; `decorators` was still tagged
out-of-scope after decorators shipped completely (ADR-00641–00649), as was
all of `Reflect` after `Reflect.get`/`has` (ADR-00640); and dynamic-code tags
(`dynamic-import`, import attributes) plus the dynamic-object tags (`Proxy`,
`Reflect.*`, `__proto__`) were labeled "out of scope" although both have a
planned home (the TDD-00046 opt-in embedded engine; the D1 dynamic object
model, TDD-00155/TDD-00068) and one compat lane (`-compat=js`) exists
precisely for untyped corpus behavior.

## Decision

- **Async protocol** (`tools/conformance/main.go` + a new
  `harness-shim/doneprintHandle.js`): `async`-flagged files get a
  compiler-compatible `$DONE` reporter prepended (upstream's branches on an
  untyped structural probe); a file passes only if the binary exits 0 AND
  stdout carries `Test262:AsyncTestComplete` and no
  `Test262:AsyncTestFailure:` after the event loop drains. New reason kinds:
  `ASYNC_TEST_FAILURE` (carries the test's own assertion message) and
  `ASYNC_NO_COMPLETION` (drained without `$DONE()`).
- **`raw` files** run harness-free (the flag's definition); **`module`**
  files are attempted through the normal pipeline — multi-file graphs fail
  with a counted reason instead of being pre-excluded. No flag excludes a
  file from the in-scope denominator any more.
- **`outOfScopeFeature` shrinks to the genuinely-never set**: `IsHTMLDDA`,
  `ShadowRealm`, `tail-call-optimization` (plus the `Intl.*`/`Temporal`
  prefixes and the `intl402`/`annexB`/`staging` categories). `decorators` is
  simply gone (shipped).
- **New `pendingFeature` map**: dynamic-code tags → "opt-in embedded engine",
  dynamic-object tags → "D1 dynamic object model",
  `explicit-resource-management` → "using/Symbol.dispose resource
  management". These files stay IN the in-scope denominator; the report gains
  a "Pending capabilities" section attributing them by capability name and
  quoting the attemptable-now figure beside the in-scope one. A tag leaves
  the map in the same delivery that ships its capability.
- `test262SummaryLane` gains a `pending` pass/total pair.

## Consequences

The in-scope denominator grows by ~6,500 files (async + module + raw +
un-excluded features), most failing today — the in-scope percentage drops
accordingly and becomes defensible. The async lane immediately surfaced real
behavioral findings (e.g. a `then`-handler receiving `5e-324` where the
resolution object was expected — a boxed-value corruption to investigate),
which is exactly what the exclusion had been masking. Canonical reports and
`conformance-summary.json` regenerate with `make conformance`.
