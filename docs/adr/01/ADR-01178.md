# ADR-01178: Node's function-style constructors, called without `new`

- **Relations**: `Extends [ADR-01170](ADR-01170.md)`, [ADR-01175](ADR-01175.md)
- **Date**: 2026-09-26

## Context

Node's own tests call `http.Server(…)`, `net.Server()`, `stream.Readable({…})`
without `new` (23 of the Node suite's js-lane files stopped on
`undefined function or closure 'Server__kml_mod1'`). In Node those
constructors are plain functions that begin `if (!(this instanceof
Server)) return new Server(…)`; the TypeScript ports declare them as
classes. TypeScript rejects the call (TS2348, "Value of type 'typeof
Server' is not callable"), and the checker did not.

## Investigation

- Node v24's sources: `net.Server`, `net.Socket`, `http.Server`,
  `http.Agent`, `https.Server`, `https.Agent`, `tls.Server`, and the stream
  classes (`Readable`, `Writable`, `Duplex`, `Transform`, `PassThrough`)
  construct when called; `EventEmitter`, `ClientRequest`,
  `IncomingMessage` and `ServerResponse` do not.
- The Node suite's own runner linked a C unit's link flags as library names
  (`-l-L/opt/homebrew/…`): 25 files failed to link.

## Decision

- A builtin module written in TypeScript marks such a class `//
  kml:callable <Name>`; the resolver collects them
  (`Program.CallableClasses`), and code generation compiles a call of one as
  `new` (the call, its inferred type, a declaration's type).
- The checker reports TS2348 for a call of a class.
- `tools/conformance`'s Node runner passes a C unit's link flags as given.

## Implementation notes

`lib/node/{net,tls,stream,internal_http,internal_https}.ts` (the markers),
`ast/nodes.go`, `resolver/resolver.go` (`callableMarkers`),
`codegen/llvm/{emitter,emit_call,emit_exprs_types,emit_exprs_vardecl}.go`,
`checker/check.go`, `diag/messages.go` (`ClassNotCallable`),
`tools/conformance/node.go`.

## Side effects discovered

None.

## Verification

Mac (Apple Silicon), against Node v24.19 and tsc: `tests/jsmode_test.go`
`TestCompatJSCallableNodeConstructors`; `tools/tsdiag` 3227/0.
