# ADR-01444: Shadow oracle: union order, intersection pieces, interfaces

- **Relations**: Implements TDD-00230 (P2.2)
- **Date**: 2026-10-07

## Context

About 500 `resolveType` UnionType rows differed only in member order:
codegen lists `boolean | number` as `[i1, double]` in source order; the
checker sorts a union's members, so the oracle answers `[double, i1]`.

A further 759 rows (`net.ts`'s `SocketConstructorOpts & { … }`) differed
only in `IntersectionMembers`: codegen keeps an intersection's pieces next
to the merged fields; the oracle answers the merged layout.

381 `reliableGlobalType` presence rows were a global typed by a program's
own interface (`const p: P = { … }`): the oracle had no representation for
a named interface.

## Investigation

- A union is a NaN-boxed `any` whatever its members' order.
- Codegen reads members by position only for a one-member union
  (`emit_narrowing.go`) and when matching a `typeof` tag, where a union
  holds one member per tag.
- `IntersectionMembers` is not a runtime shape (`types.go`): it is kept
  only so each use site can re-check the merge.

## Decision

- `reprKey` renders `UnionMembers` sorted, so two unions with the same
  members are one representation.
- `IntersectionMembers` joins the metadata fields `reprKey` leaves out.
- `reprCtx` gains an `iface` hook: a program's own non-generic interface
  is the layout codegen registered under its name, after the builtin
  `@lowerType` layouts. Only the shadow oracle's context sets it.

## Side effects discovered

- 689 `inferExprType` rows on no node at all: an annotated object
  declaration without an initializer (`let s: Socket;`) ran the
  accessor-literal check on its missing initializer. The check now needs
  one; nothing it decided changes.

## Verification

- A `TestReprKey` case; the shadow tests pass on the Mac.
- An interface-typed global probe records no row.
