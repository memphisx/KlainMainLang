# ADR-01098: `utf16le`/`ucs2` for Buffer, and `ffi.exportString` encodings and validation

- **Relations**: `Implements TDD-00229`, `Extends ADR-01091`
- **Date**: 2026-09-23

## Context

`ffi.exportString(str, ptr, len, encoding = 'utf8')` accepted only `'utf8'`,
reported its own messages for a short buffer, and rejected a `bigint` length
at compile time. Node's version (`lib/ffi.js`) validates the string, the
encoding's type and the length (`validateInteger(len, 'len', 0)`), encodes
with `Buffer.from(str, encoding)` (an unknown encoding throws
`ERR_UNKNOWN_ENCODING`) and then requires room for the encoded bytes plus a
terminator — two bytes for `utf16le`/`ucs2`. The `utf8`-only restriction came
from `Buffer` itself, which rejected `utf16le`/`ucs2` because "strings are
UTF-8-native" — a status caveat on the Buffer row.

## Investigation

UTF-8-native strings do not make UTF-16LE impossible: it is a transcoding of
the same code points (a surrogate pair above the BMP). Node's texts, by probe:
`The value of "len" is out of range. It must be >= 6. Received 3`,
`… It must be an integer. Received 2.5`,
`… It must be >= 0 && <= 9007199254740991. Received -1`,
`The "len" argument must be of type number. Received type bigint (5n)`,
`The "string" argument must be of type string. Received type number (5)`,
`Unknown encoding: nope`.

## Decision

- `buffer_codecs.c` gains `__kml_buf_utf16le_bytes` (UTF-8 → UTF-16LE) and
  `__kml_buf_utf16le_str` (back; a lone surrogate or invalid byte becomes
  U+FFFD, a trailing odd byte is dropped as Node does); `bufferEncodingArg` maps
  `utf16le`/`utf-16le`/`ucs2`/`ucs-2` to it, so `Buffer.from`/`toString` gain
  the encoding everywhere they take one.
- `emitFFIExportString` follows Node's order and messages above, encodes
  through the Buffer codecs, and writes the encoded bytes plus a 1- or 2-byte
  terminator. The encoding stays a compile-time string literal (the codec is
  chosen at compile time, as for `Buffer`).

## Verification

`TestE2EFFIExportStringEncodingsAndErrors` (Node 26.10.0 FFI oracle) and
`TestE2EBufferUTF16LE` (Node 24.19.0), macOS/arm64 (M4).
