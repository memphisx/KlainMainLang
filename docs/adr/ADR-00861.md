# ADR-00861: ToPrimitive at operator sites — `+` and loose equality (TDD-00201 Stage 3)

- **Relations**: `Extends ADR-00859, ADR-00860`, `Implements TDD-00201`
- **Date**: 2026-09-10

## Context

Stages 1–2 covered numeric and string coercion of objects. The remaining
ToPrimitive operator sites are `+` (whose overload picks string concat vs numeric
add) and loose `==`/`!=` (an object compared to a primitive). Both use the
**default** hint (`valueOf` → `toString`). `===`/`!==` never coerce.

While wiring loose equality, a pre-existing invalid-IR bug surfaced: `obj === 5`
emitted `icmp eq ptr %obj, 0x4014000000000000` (comparing the object pointer to a
`double` constant) — the object-vs-scalar case slipped past the incompatible-types
guard, which exempts object operands (for the valid object-vs-object ptr compare).

## Decision

Extend the `emitBinary` ToPrimitive pre-pass:

- **`+`** — run the ladder with the **default** hint on each object operand and
  substitute the RAW primitive (number or string). The existing `+` overload logic
  then decides concat vs add: `{valueOf(){return 5}} + 3 === 8`,
  `{toString(){return "a"}} + "b" === "ab"`, `"x" + {valueOf(){return 5}} === "x5"`.
- **`==`/`!=`** — run the default-hint ladder on an object operand **only when the
  other side is a number/string/bigint** (`isLooseEqPrimitive`). `obj == null`/
  `undefined` stays false without coercion, and `obj == obj` stays reference
  equality — neither coerces, matching JS.

And fix the surfaced bug: for the equality operators, when exactly one side is a
heap object/array (`ptr`) and the other is a bare non-`ptr` scalar, reject cleanly
instead of emitting a `ptr`-vs-scalar `icmp`. The rejection is **strict-only** —
under `-compat=js` the object is NaN-boxed (`IsDynamic`), so the `!IsDynamic`
guard skips it and the existing any-comparison path evaluates it as JS does
(`obj === 5` → `false`). The message names that escape hatch and states the
constant result the comparison always has (`false` for `==`/`===`, `true` for
`!=`/`!==`), consistent with the disjoint-scalar rejection below and TS's own
no-overlap comparison error. Object-vs-object and object-vs-string stay `ptr==ptr`
comparisons; null/undefined checks are exempt.

## Implementation notes

- `emit_exprs_operators.go`: the `+` and `==`/`!=` cases in the pre-pass, and the
  equality object-vs-scalar rejection after the string-binary path.
- `emit_toprimitive.go`: `isLooseEqPrimitive`.
- The default hint reuses `emitObjectToPrimitive`'s existing `"default"` path
  (valueOf→toString order, any primitive accepted).

## Side effects discovered

- **`-compat=js` is currently LESS faithful than strict for object ToPrimitive**
  (an inversion of the usual axis, pre-existing not a regression): under
  `-compat=js` a plain object is NaN-boxed, so the Stage 1–3 static ladder
  (`objectMayToPrimitive` requires `!IsDynamic`) is skipped and the value hits the
  dynamic path's "heap ref → NaN" arm — `{valueOf(){return 5}} * 2` is `NaN`,
  `String({toString(){return "hi"}})` is `"[object Object]"`. Strict (static
  object) is correct. This is exactly the deferred **Stage 4** (runtime ToPrimitive
  over a NaN-boxed object in `__kml_any_tonum`/a new `__kml_any_tostr`) and is now
  the highest-value ToPrimitive follow-up, since it makes the faithful lane
  faithful.
- The object-vs-scalar equality rejection is scoped to the equality operators
  only; `+` deliberately does NOT reject an object operand — a method-less object
  in `+` should concat via `Object.prototype.toString` (`"[object Object]"`),
  which is the method-less-object default-form follow-up (a plain object with no
  own `toString`/`valueOf`/`@@toPrimitive` currently yields `ok == false` from the
  ladder, so `{a:1} + 5` is not yet the faithful `"[object Object]5"`).

- E2E `tests/toprimitive_test.go`: `+` (valueOf/toString/`@@toPrimitive`, both
  concat and add directions) and loose `==`/`!=` (incl. `obj == obj` reference and
