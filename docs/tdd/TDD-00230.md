# TDD-00230: Compiler restructure — a real front end (scanner, parser, binder, checker), declaration-driven builtins, and a libuv runtime

- **Status**: In Progress
- **Date**: 2026-09-23

## Context

For a month the work has been bugs and caveats only, with no new API surface, and the
open-bug list has kept growing. A whole-project audit (four independent passes over
the source, plus the full ADR history) shows that the bugs come from how the compiler
is structured, not from individual mistakes. Each fix at the site of a symptom adds
another special case, and those special cases produce the next bugs.

### What the history says

Of the 299 records ADR-00800 to [ADR-01098](../adr/ADR-01098.md), about 209 are fixes.
Hand-classified by the layer the bug originated in:

| Origin | Share of fixes |
|---|---|
| Value representation: two sites assumed different shapes for one value (header vs bare string, `{ptr,len}` snapshot vs shared array header, absent vs `null`, `i64` vs `double` bits) | 30% |
| Types: codegen did not know an expression's static type, or two places decided it differently | 27% |
| Builtin-library semantics | 14% |
| Platform | 11% |
| Event loop / async | 9% |
| Memory | 4% |
| LLVM IR mechanics | 3% |
| Lexer/parser | 1.5% |

Invalid IR is a *symptom*, not an origin. Of 90 records whose Context describes
invalid IR, nearly all trace to a representation or type disagreement. Only about 3% of
fixes were IR mechanics (dominance, terminators). The number of invalid-IR fixes in
ADR-00800 to ADR-00999 reflects that invalid IR was deliberately prioritised then; it
is not a rate at which such bugs appear.

Two TDDs are marked Implemented while stages their own design defines remain open:
[TDD-00155](TDD-00155.md), where only part of Stage 6 (allocation-site widening)
shipped, and [TDD-00120](TDD-00120.md), where BACKLOG (headerless strings) lists string
producers still returning bare C strings. Unsupported shapes are more often fenced
off with clean rejections (136 records) than modelled.

### Structural causes (counts from the tree at the date above)

1. **No binder, no checker, no typed intermediate layer.** `resolver/` merges modules,
   renames and checks declarations. Identifiers stay strings; codegen resolves them on
   its own scope stack (`Emitter.lookup`, `codegen/llvm/emitter.go:1461`). Every
   expression's type is decided *during IR emission*:
   - `inferExprType` has about 545 call sites in 64 files, plus 22 other `infer*`
     deciders (`reliableGlobalType`, the jsinfer pass, generic concretisation, …).
   - The predicted type and the `Value.Ty` that emission actually produces are computed
     separately. 57 "must mirror" comments keep them in step.
   - Inference was exponential until it was memoised ([ADR-01045](../adr/ADR-01045.md):
     a five-link `.then` chain took about 52 s to compile).
   - Two deciders for one binding are kept in agreement by a runtime guard
     ([ADR-01060](../adr/ADR-01060.md), `promotedStorageAgrees`) instead of being one
     function.
2. **Codegen's `Type` is a flag bag.** It has 149 fields, 104 of them `Is*` booleans
   (`IsResponse`, `IsHTTPServer`, `IsH2ClientStream`, …). Every host class adds a flag
   and a precedence rule at every place that reads one.
3. **Builtins are recognised by name at every layer.**
   - The parser turns `new <BuiltinName>(…)` into 42 dedicated node kinds by matching
     the callee's text, before any scope exists. So a user's own `class Event` compiles
     to the builtin (codegen error `no field 'n'`; Node prints `5`), and
     `resolver/reserved_names.go` makes those names permanently unshadowable.
   - `emitCall` is one function of about 1,450 lines: an ordered chain of
     `if inferExprType(obj).IsXxx { return … }`.
   - There are 1,264 `case "name":` arms across the package.
4. **The Emitter is a god object.**
   - About 630 fields, 403 `used*` flags, 407 `ensure*` declarators, 2,250 methods.
   - `emitter.go` is touched by 72% of commits. `emit_call.go`, `emit_exprs_types.go`
     and `types.go` are next.
   - Which runtime gets emitted depends on the combination of flags set, so some bugs
     appear only for particular feature combinations.
5. **About 27,600 lines of the runtime are hand-written LLVM IR inside Go strings.**
   - Nothing checks that IR until clang runs on a user program, and a template branch
     is checked only when a program sets the flags that reach it.
   - It cannot be stepped through in a debugger.
   - Its data layouts are mirrored "in lockstep" by hand across Go-string IR, C
     sidecars and codegen.
6. **The event loop is one `select()` monolith** (`__kml_event_loop_run`,
   `codegen/llvm/runtime_http.go:1832`):
   - It rebuilds `fd_set`s from about 15 subsystems every iteration, keeps the loop
     alive with about 16 predicates, and bounds its wait with ad-hoc deadline folds and
     `forcezero` flags.
   - Several private loops exist beside it: `__kml_timer_drain`,
     `__kml_timer_fire_next`, the `usleep(200)` subset drive, and synchronous curl
     drives.
   - Confirmed defects of this design:
     - An `fd_set` stack overflow for fd ≥ 1024: `fsetbit` indexes `fd/8` unchecked.
     - HTTP/2 sessions and TLS handshakes block the loop (`http2.c:325`, `tls.c:94/339`).
     - DNS lookups block the loop (`getaddrinfo` on the loop thread).
     - A handler's `await` can `nanosleep` the whole server until the next timer
       (`emit_timers.go:261`).
     - The timer array is append-only (`emit_timers.go:385` is the only write to its
       length).
     - Due timers fire one per iteration.
     - A signal can be lost between the flag check and `select()`.
7. **The front end's real defects are few but structural.**
   - There is no automatic-semicolon-insertion algorithm. `a` then `++b` on the next
     line prints `2 2`; Node prints `1 3`.
   - The lexer tokenizes the whole file first, so the `>>` in generics, regex vs
     division and the arrow-vs-parenthesis ambiguity are patched after the fact.
   - `new` accepts only a bare name. Contextual keywords such as `async` are rejected as
     names.
   - The first error aborts the parse. Positions are line and column only.
   - One `ast.TypeAnnotation` struct with about 30 flag fields represents every TS type
     construct.
   - There is no traversal abstraction: about 30 hand-written walkers each switch over
     every node kind.
   - The parser also does semantic work: namespace desugaring and collecting worker and
     dynamic-import paths.

### Reference architecture

[typescript-go](https://github.com/microsoft/typescript-go) (the Go port of the
TypeScript compiler, studied at `89d5d5b2`) solves each of the problems above with a
pattern this project can adopt without taking the code. Its packages are
`internal/`, and its structural type system is not what a monomorphic native target
needs. The patterns are cited below where they are used.

## Design

The target pipeline:

```
source
  → scanner       on demand, driven by the parser; byte offsets; token flags
  → parser        syntax only; real ASI; speculative parse with mark/rewind;
                  error recovery; generic NewExpression; type syntax as node kinds
  → resolver      module graph; every file keeps its identity (its own SourceFile and
                  module scope) instead of being merged into one flat, renamed body
  → binder        Symbols, symbol tables per container, node→symbol, control-flow graph
  → checker       lazy, memoised; ONE type per expression; narrowing over the flow graph;
                  absence in the type lattice; overload resolution to a declaration;
                  every user-facing error is a checker diagnostic
  → lowering      representation chosen once per type (closed set); explicit
                  conversions from ONE total conversion function
  → IR emission   reads checker results only; never infers
runtime:          a thin native layer (libuv, libcurl, OpenSSL, nghttp2 bindings,
                  string/array/GC primitives) + the builtin library, described to the
                  checker by declaration files and lowered through `@lower` annotations
```

The rule that makes the restructure converge: **a fact is computed in exactly one
place, and everything else reads it.** Types come from the checker, representations
from `reprOf`, conversions from `convert`, builtin semantics from declarations,
readiness from libuv.

### Phase 0 — safety net and migration harness

The existing behaviour is encoded in about 61k lines of Go tests, 357 examples, the
Node differential oracle and Test262. Every step of every phase lands only with all of
them green on macOS. Linux is checked through Docker (`golang:latest` + clang, libcurl,
libtommath) and Windows through CI, per the platform rules.

- **P0.1 Invalid IR names the Go site that emitted it.** Behind a test-only switch,
  `emitInstr`/`emitGlobal` append `; @site file:line`, taken from `runtime.Caller` of
  the first frame outside the builder helpers. The harness maps clang's error line back
  to that comment. Invalid IR then points at its origin without rewriting 8,330
  `emitInstr` call sites. A fully typed IR builder is deliberately not part of this
  restructure: once the checker and `reprOf` decide types and representations, the
  disagreements that produce invalid IR have no source.
- **P0.2 Shadow-mode agreement harness.** This is how phases 2 and 3 replace the old
  deciders without a flag day.
  - While both exist, every compile in the test lanes also runs the new pass (binder,
    then checker).
  - At every point where codegen asks an old decider (`inferExprType`, `resolveType`,
    `reliableGlobalType`, …), it also asks the checker, maps the checker's type through
    `reprOf`, and records any disagreement: expression kind, source position, both
    answers.
  - `make shadow-report` aggregates the disagreements over the whole corpus into a
    ranked histogram. It works like the conformance blocked-by histogram.
  - A decider is switched over to the checker's answer only when its disagreement count
    is zero. It is then deleted, not left as a fallback.
- **P0.3 Mode-differential lanes.** The restructure rewrites the code that escape
  analysis and free insertion sit on, so every example and E2E program also runs under
  `-mm=auto`, `-mm=auto -optimize-memory` and `-mm=gc`, with sanitizers armed on
  Linux, and the outputs must match the default mode's. [TDD-00174](TDD-00174.md)'s
  maturity window restarts from these lanes.

### Phase 1 — the syntax layer

Each step keeps the existing AST consumers working, so it lands on its own. Order:
P1.1, P1.2, then P1.4, P1.6 and P1.5, which phase 2 builds on, and P1.3 (error
recovery) last, since it changes only how diagnostics are reported.

- **P1.1 On-demand scanner** (typescript-go `scanner/scanner.go:192-227`, `469`,
  `1013-1067`).
  - The scanner is a `Scanner{text, ScannerState}`. `Scan()` produces one token.
    `Mark()`/`Rewind()` copy the state.
  - The context-free token is always emitted. The parser asks for a re-reading where its
    grammar context requires one: `ReScanGreaterThanToken` (glues `>>`, `>>>`, `>=`),
    `ReScanSlashToken` (regex), `ReScanTemplateToken`.
  - `TokenFlags` carries `PrecedingLineBreak`, `Unterminated`, `Octal`,
    `ContainsSeparator`, and so on.
  - Positions are byte offsets (`TextRange{Pos,End}`) plus a file id, with line and
    column computed lazily from a line-start table. Every node's range reaches lowering,
    so the function builder can carry a current source location from the start
    (DWARF, [TDD-00073](TDD-00073.md); `Function.prototype.toString` source text,
    [TDD-00229](TDD-00229.md); stack traces, [TDD-00188](TDD-00188.md)).
  - JSDoc comments attach through the scanner's comment ranges instead of `JSDOC`
    tokens interleaved in the stream.
- **P1.2 Parser discipline** (typescript-go `parser/parser.go`).
  - `mark()`/`rewind()` restore scanner state *and* truncate diagnostics.
  - A three-valued (`Tristate`) arrow look-ahead with a memo of known non-arrows.
  - Uniform ASI:
    - `canParseSemicolon` accepts a `;`, a `}`, EOF, or a preceding line break.
    - Every statement ends in `parseSemicolon()`.
    - The restricted productions check `!hasPrecedingLineBreak()`: postfix `++`/`--`,
      `return`, `throw`, `yield`, `break`/`continue` labels, `=>`, and `async`.
  - Context flags (`await`, `yield`, `decorator`, `disallowIn`) are stamped onto nodes.
  - `new` parses a general member expression.
  - Contextual keywords are valid identifiers wherever TypeScript allows them.
- **P1.3 Error recovery and diagnostics.**
  - Parsing contexts for lists, with `isListTerminator`/`isListElement`.
  - Recovery either skips a token or aborts to the enclosing list.
  - Missing nodes are synthesised (a zero-width token, an empty identifier) rather than
    stopping.
  - One error per position.
  - Diagnostics come from a message table and are collected per file. A diagnostic
    carries: a stable numeric code (TypeScript's where the condition is the same, e.g.
    TS2339, so the TypeScript oracle compares by code, not wording); severity (error or
    warning); file id and byte span; related spans ("declared here"); a hint; the
    JavaScript error kind it corresponds to (`SyntaxError`, `TypeError`, …, for
    `-compat=js` and Test262's negative tests); the Test262 phase (parse, resolution,
    early); and a structured payload (e.g. the qualified missing symbol) so the
    conformance blocked-by histogram groups by API. A machine-readable output mode
    prints them as JSON ([TDD-00072](TDD-00072.md), [TDD-00204](TDD-00204.md)).
  - Every phase from here on reports through the same collection. Messages in the
    `--help`/runtime-error sense stay free of document references.
- **P1.4 Generated AST traversal** (typescript-go `_scripts/ast.json` →
  `ast_generated.go`).
  - The generator reads the node structs in `ast/nodes.go` themselves, so the schema
    cannot drift from the AST.
  - `go generate` emits `ForEachChild(visitor)` for every kind, with `Inspect` built on
    it. The same generator later emits an AST serializer and TypeScript declarations of
    the node shapes: the stable AST boundary self-hosting needs
    ([TDD-00124](TDD-00124.md)).
  - The about 30 hand-written walkers become visitors that switch only on the kinds they
    care about and defer to `ForEachChild` for the rest.
  - Adding a node kind means one schema entry. A kind missing from the schema fails
    `go generate`'s check instead of silently skipping a subtree.
- **P1.5 Type syntax as node kinds.** `TypeReference`, `UnionType`, `IntersectionType`,
  `FunctionType`, `ArrayType`, `TupleType` (with labelled elements), `TypeLiteral`,
  `TypeOperator`, `IndexedAccessType`, `ConditionalType`, `MappedType`, `TypePredicate`,
  and the rest.
  - Until phase 2 replaces codegen's `resolveType`, a single conversion function
    produces the existing `ast.TypeAnnotation` for codegen. Its deletion is an exit
    criterion of phase 2.
  - Type predicates are kept as nodes, not erased at parse time, so the checker can
    narrow on them.
- **P1.6 Semantic work leaves the parser.**
  - `new <BuiltinName>` becomes a generic `NewExpression`: the parser knows no builtin
    names.
  - A `sema` package, run at the entry of code generation so every compile path goes
    through it, decides which `new X(…)` constructs a builtin: the scope-aware walk
    builds the specialised node only where no user binding named `X` (a class,
    parameter, local, or import from a user module) is in scope. It runs before any
    binding exists, so it replaces nodes rather than annotating them; phase 3 deletes
    it together with the specialised node kinds.
  - Worker and dynamic-import path collection move to the resolver, which resolves
    each specifier into a `Program.ResolvedModules` table.
  - A constant-string `eval` (ADR-00198) is parsed into a subtree before binding, and
    bound in the caller's scope.
  - Two parser-side semantics stay until the binder can take them: namespace
    desugaring (a namespace is a container symbol in phase 2, so a transitional pass
    would be thrown away), and `resolver/reserved_names.go`'s builtin list (a user
    `class Map` would still be read as the builtin in a type annotation until phase 2
    resolves types through symbols).

Exit criteria for phase 1:
- `lexer.Tokenize` is gone.
- The parser has no builtin constructor names in it.
- Every AST walk goes through the generated traversal.
- ASI matches Node on a dedicated corpus (restricted productions and statement
  boundaries).
- `a` then `++b` on the next line prints `1 3`.
- The TypeScript-oracle false-accept and false-reject buckets whose messages are
  parser-shaped are re-measured and recorded in the ADR.

### Phase 2 — binder and checker

- **P2.1 Binder** (typescript-go `binder/binder.go`, `ast/symbol.go`, `ast/flow.go`).
  - `Symbol{Flags, Name, Declarations, ValueDeclaration, Members, Exports, Parent}` with
    `SymbolFlags` and exclude masks. Duplicates are detected and declarations merged
    through the masks.
  - Per-kind container flags route each declaration to a symbol table:
    - module or file → exports or locals
    - class → members, or exports for statics
    - function → locals
    - block → block-scoped locals
  - Every module has its own symbol table. Imports bind to the exporting module's
    symbols, so the resolver stops renaming names apart; a module export may alias a
    global's symbol (`require('url').URL === URL`, [TDD-00165](TDD-00165.md)).
  - Symbol tables are insertion-ordered, and symbol and type ids are assigned
    deterministically. Output does not depend on map iteration order, which the
    self-hosting bootstrap's byte-identical stage check needs.
  - Symbols carry modifier flags (readonly, private, protected, override) from both
    inline modifiers and JSDoc, and the ownership annotations (`@owned`, `@free`,
    `@fresh`) that `-mm=auto` reads.
  - **One static descriptor per function**, owned by the binder: name (including
    NamedEvaluation), length, kind, file id, source span and source text. Function
    objects, `Error.stack` frames, decorators' metadata and module islands all read
    it, not side tables of their own ([TDD-00229](TDD-00229.md),
    [TDD-00188](TDD-00188.md), [TDD-00161](TDD-00161.md), [TDD-00055](TDD-00055.md)).
  - The binder's own checks replace `resolver/scopecheck.go`'s duplicate and TDZ
    checks.
  - Codegen stops resolving names by string. `lookup(name)` becomes
    `storageOf(*Symbol)`.
- **P2.2 Control-flow graph.**
  - Every identifier, `this` and property-access node records the current `FlowNode`.
  - Flow node kinds: `Start`, `BranchLabel`, `LoopLabel`, `Assignment`,
    `TrueCondition`/`FalseCondition` (created only for narrowing expressions),
    `SwitchClause`, `Call`, `Unreachable`.
  - Destructuring assignments are `Assignment` nodes, so each target narrows.
  - The same graph yields definite assignment, unreachable code and implicit return,
    which replaces `resolver/readability.go`'s separate walks. It also yields the
    liveness and last-use facts that `-mm=auto`'s escape analysis and free insertion
    move onto, replacing the analysis's own walkers ([TDD-00174](TDD-00174.md),
    [TDD-00175](TDD-00175.md)).
- **P2.3 Checker core.**
  - Everything is lazy and memoised in link side tables (a `LinkStore[K,V]` generic
    backed by an arena): `NodeLinks{resolvedType, resolvedSignature, …}`,
    `SymbolLinks{type, declaredType, …}`.
  - The AST is immutable after binding. A transform that needs checker results (a
    compile-time reactivity lowering, [TDD-00150](TDD-00150.md); compile-time
    intrinsics such as `embedFile`, [TDD-00189](TDD-00189.md)) produces a separate
    lowered tree, never an edit of the bound one.
  - Cycles are caught by a resolution stack, which reports a diagnostic and falls back
    to `any`.
  - `TypeOf(node)` is the one oracle.
  - The exponential re-inference class is gone by construction: every expression is
    checked once.
- **P2.4 The checker's type representation.**
  - `Type{flags TypeFlags, objectFlags, id, symbol, data}`, with one flag bit per kind
    and typed payloads.
  - Our native widths are first-class: `/** @type {int32} */` is an `IntType{bits,
    signed}` kind, not a codegen side channel.
  - Types are interned (intrinsics are singletons, literal and union types are keyed by
    sorted member ids), so type equality is pointer equality and types serve directly as
    monomorphisation cache keys.
- **P2.5 Absence and narrowing.**
  - Strict null checks always.
  - `undefined` and `null` are ordinary union members. A distinct `missing` singleton
    marks an absent optional property, so an explicit `null`, an explicit `undefined`
    and an omitted field are three different facts (superseding
    [TDD-00227](TDD-00227.md); BACKLOG: optional fields, declared-type slots).
  - Narrowing is computed by walking the flow graph backwards from a reference:
    - an assignment gives the assigned type;
    - a condition applies truthiness, equality, `typeof`, `instanceof`, `in`,
      discriminants, optional-chain containment, and user type predicates;
    - a branch label unions its antecedents;
    - a loop label iterates to a fixpoint.
  - An unannotated `let x;` gets a storage type (the union of everything assigned to it)
    separate from the narrowed type of each read; `reprOf(storage type)` decides its
    representation with no pre-pass ([TDD-00162](TDD-00162.md)).
  - Destructuring defaults apply for `undefined` and `missing`, never for `null`.
  - Codegen's per-site absence handling is deleted as the shadow report for it reaches
    zero.
- **P2.6 Signatures, generics, `any`.**
  - Calls resolve to a `*Signature` that keeps its declaration. Overloads are tried in
    declaration order: arity, then inference, then applicability.
  - Generics are instantiated per concrete argument set; the monomorphic default of
    [TDD-00010](TDD-00010.md) is kept, and the `@erased` form stays opt-in.
  - `any` is a real type with dynamic semantics, not an escape from checking.
  - `-compat=js` becomes a checker mode: unannotated bindings infer from their
    initializer as TypeScript does, and parameters take the call-site inference the
    current jsinfer pass performs. That pass moves into the checker and is deleted from
    codegen.
  - **One options struct carries every mode** (`-compat`, `--no-any`,
    `--strict-modifiers`, the decorator dialect, `--stack-traces`, the memory mode, the
    target) to the checker, `reprOf` and `@lower` alike. Several `-compat` differences
    are lowering facts, not checker facts: string coercion of objects,
    value-preserving `&&`/`||`, the `number` representation. So a lowering target may be
    mode-conditional ([TDD-00075](TDD-00075.md), [TDD-00209](TDD-00209.md),
    [TDD-00126](TDD-00126.md)).
  - Assignability stays **structural** where TypeScript's is — `implements`,
    `satisfies`, excess-property checks — even though representations are nominal.
    typescript-go's relation engine is not copied, but structural compatibility is kept
    ([TDD-00126](TDD-00126.md)).
  - The checker also needs: unique and well-known-symbol-keyed members
    (`[Symbol.iterator]`, for-of and spread through the declared iterator,
    [TDD-00065](TDD-00065.md), [TDD-00155](TDD-00155.md)); module-namespace objects and
    `ImportMeta` as real types ([TDD-00055](TDD-00055.md)); decorator applications typed
    per dialect, with the context types declared in the lib ([TDD-00161](TDD-00161.md));
    and checker-side intrinsics — a return type computed from literal argument values
    (`node:ffi`'s `getFunction(name, sig)`), constant `sizeof`/`offsetof`, and an
    instantiated type argument passed to a `@lower` target as a layout descriptor
    (`.all<T>()`, typed `JSON.parse<T>`) ([TDD-00164](TDD-00164.md),
    [TDD-00190](TDD-00190.md), [TDD-00151](TDD-00151.md)).
- **P2.7 Diagnostics own user errors.**
  - A program the checker accepts must compile. Codegen reports only internal errors.
  - Every codegen "clean rejection" of user code becomes either a checker diagnostic
    with a stable code, or a supported feature. The existing rejections are inventoried
    and ranked in the shadow report.

Exit criteria for phase 2:
- No `inferExprType`, `inferUnannotatedReturnType`, `reliableGlobalType`,
  `promotedStorageAgrees`, `resolveType` or jsinfer in codegen.
- `ast.TypeAnnotation` is deleted.
- The shadow report is empty.
- Codegen's user-facing errors are gone.
- The BACKLOG's two-deciders cleanup is closed by deletion.

### Phase 3 — declaration-driven builtins and a closed representation model

- **P3.1 Builtin surface as declaration files.** This follows typescript-go's
  `bundled/libs/lib.*.d.ts`, where `Map`, `Promise` and `fetch` are plain declarations
  with zero name checks in the checker.
  - The project ships its own `lib/*.d.ts` files, embedded in the binary, for ES, each
    supported `node:*` module and the web APIs. They are parsed and bound like user code
    and merged into globals or module exports.
  - The files are authored for this compiler rather than ingested: the real TypeScript
    libs and `@types/node` rely on conditional and mapped types and structural overload
    sets that a monomorphic target does not reproduce faithfully.
  - A conformance test diffs every declared name and signature against the real
    `lib.*.d.ts` and `@types/node`. A mismatch fails the test unless an allowlist entry
    names it; each such entry is a disclosed divergence.
  - A missing API becomes the checker diagnostic "property does not exist". The
    conformance blocked-by histogram is then the checker's own diagnostic count.
  - **Which declarations load depends on the options and the target**, not the host:
    `/** @platform linux */`-style conditions make an API unavailable on a target a
    checker diagnostic ([TDD-00033](TDD-00033.md), [TDD-00036](TDD-00036.md),
    [TDD-00048](TDD-00048.md)), and option-gated libs (an embedded `eval` engine,
    [TDD-00046](TDD-00046.md)) load only with their flag.
  - The loader also accepts **third-party declarations**: a package's own `.d.ts`,
    possibly with `@lower` bound to the package's C sources (a native addon without FFI,
    [TDD-00054](TDD-00054.md)), and npm `.d.ts` files ([TDD-00053](TDD-00053.md)).
    Constructs the checker does not model (conditional and mapped types in those files)
    degrade to `any` instead of rejecting the file.
  - Each declaration may carry `@status <area>/<row>`, joining it to its status row, so
    `make status` checks "every ✅ row has a declaration" and the website reference's
    signatures can be generated from the declarations ([TDD-00145](TDD-00145.md)).
- **P3.2 Lowering annotations.**
  - `/** @lower <runtime symbol> */` on a function, method or overload names the runtime
    entry point it compiles to.
  - `/** @lowerType <layout> */` on an interface or class names its native layout.
  - `intrinsic` marks the small, enumerated set of builtins that need inline IR (math
    intrinsics, array fast paths), as TypeScript does for `Uppercase`.
  - Call emission becomes one generic path: read the node's resolved signature, read
    its `@lower` target, and marshal each argument by its declared parameter type.
  - Overloads map one-to-one to runtime entry points. For example,
    `readFileSync(path)` returns `Buffer` and `readFileSync(path, "utf8")` returns
    `string`, selected by a literal-type overload.
  - A `@lower` target is a backend-neutral symbol: the implementation is picked at link
    time (as `-crypto` picks a backend today), so a backend swap is a different archive,
    not new codegen ([TDD-00003](TDD-00003.md)). It may name a C function or a function
    of the TypeScript builtin library, so the library can move to TypeScript one
    function at a time.
  - Declarations also carry what they need linked (`@link sqlite3`, `SDL2`, a vendored
    source), which replaces the `used*`/`requireLink` gating once the linker's dead-code
    elimination decides what is used ([TDD-00151](TDD-00151.md),
    [TDD-00170](TDD-00170.md)).
  - The generic call path supports C variadic calls, by-value aggregates, a per-site
    constant cache slot (inline caches, [TDD-00220](TDD-00220.md)), and a hook
    immediately after the call with no safepoint or microtask drain in between (reading
    `errno`, [TDD-00190](TDD-00190.md)).
  - `@lowerType` layouts support single inheritance: a derived layout begins with its
    base's, and user classes can extend host classes (`extends EventEmitter`,
    `extends Error`, `File extends Blob`, [TDD-00172](TDD-00172.md)).
  - During the migration, a declaration without `@lower` falls through to the existing
    hand-written emitter. That fall-through, and the post-binding `new` mapping from
    P1.6, are deleted when the last builtin has moved.
- **P3.3 One representation per type.**
  - `reprOf(checker.Type)` returns one of a closed set of representations:
    - unboxed `double`, `i64`/sized integer, `i1`
    - string (always a headered pointer)
    - array (one shape: a pointer to the shared array header)
    - object (static layout or dynamic bag)
    - closure
    - a nullable wrapper `{i1, T}` for scalars and a null pointer for references
    - a three-state wrapper `{i8 state, T}` for scalars (missing / null / present) and a
      pointer with a presence bit for references, where the checker's type
      distinguishes `missing` from `null` ([TDD-00227](TDD-00227.md))
    - the NaN-boxed `any`
    - an opaque host handle whose first word is a type id
    - a class constructor as a value ([TDD-00055](TDD-00055.md),
      [TDD-00161](TDD-00161.md), [TDD-00229](TDD-00229.md))
    - a Buffer whose backing store is foreign, unmanaged memory
      ([TDD-00164](TDD-00164.md)), and a foreign-engine object
      ([TDD-00046](TDD-00046.md))
  - Every union has a representation: unions of one representation collapse to its
    nullable or three-state form, mixed unions are the NaN box
    ([TDD-00200](TDD-00200.md)).
  - A representation can depend on the allocation site as well as the type: an object
    literal that flows into a dynamic position is allocated dynamic from the start
    ([TDD-00155](TDD-00155.md) Stage 6). The checker records that as a distinct
    "widened" type on the allocation node, so `reprOf` stays a function of the type.
  - Managed pointers have their own IR type (`ptr addrspace(1)`), distinct from native
    pointers. That keeps precise stack roots (statepoints or a shadow stack) and a
    debugger's view of the heap possible later ([TDD-00135](TDD-00135.md),
    [TDD-00048](TDD-00048.md), [TDD-00073](TDD-00073.md)).
  - `convert(from, to)` is total over that set, and may allocate (`Date`→`any`, a
    function value into the dynamic calling convention). A pair it does not define is a
    compiler bug reported at the call, never a raw reinterpretation.
  - The two array shapes, the transitional nullable locals-only mode and the bare-string
    producers (BACKLOG: headerless strings) are removed. This supersedes
    [TDD-00228](TDD-00228.md) and [TDD-00227](TDD-00227.md), and provides the header
    fields [TDD-00226](TDD-00226.md) (holes) is built on.
- **P3.3a Heap stores and allocations are single primitives.** Lowering emits every
  store of a pointer into a heap object (field, element, property, closure-environment
  slot) through one helper, and every allocation through one `alloc(typeid, size)` call.
  No other code path writes a heap pointer or allocates. Today neither needs a hook; a
  generational or reference-counting collector (see "Collector-readiness") needs a
  write barrier at exactly those stores, and a bump-pointer collector needs its inline
  fast path at exactly that allocation. Both then land in one place, not across the
  ~8,300 emit sites.
  - Each store site carries a static barrier kind (none, reference-count cluster,
    generational), so an RC cluster under `-mm=auto` and a collector's barrier can
    coexist ([TDD-00175](TDD-00175.md)).
  - A matching `free(typeid, ptr)` primitive serves `-mm=manual`/`auto`. It is optional
    per collector: a tracing or moving collector ignores explicit frees.
  - The rule covers the C runtime too: `dynjson.c`, array growth and bulk copies store
    and reallocate managed pointers only through the same interface (with a bulk-copy
    barrier).
- **P3.3b Exceptions and suspension are lowered through one abstraction each.** A
  `throw`/`catch` is lowered through one primitive (setjmp/longjmp today, WebAssembly
  exception handling later), and an `await`/`yield` through one suspend/resume
  primitive (stackful fibers today, a stackless state machine or Asyncify on
  WebAssembly, which has no `ucontext`) ([TDD-00048](TDD-00048.md),
  [TDD-00036](TDD-00036.md)).
- **P3.4 Codegen's `Type` becomes a lowering type.**
  - The 104 `Is*` flags go. Codegen's `Type` is replaced by the checker's type plus
    `reprOf`.
  - Host classes are identified by their declaration symbol and `@lowerType`, not a
    flag.
- **P3.5 The Emitter is split by lifetime.**
  - Per-function state (builders, allocas, current block) and per-module state (globals,
    string table, declared runtime symbols) become separate objects.
  - Checker access goes through an interface, so emission code cannot mutate
    front-end state.
  - `emitCall`'s chain is deleted in favour of P3.2's generic path.
  - The function builder carries the current source location (from P1.1's byte ranges)
    and has one prologue/epilogue emission point and one call-site hook, which a shadow
    call stack for `Error.stack` and DWARF line tables both use
    ([TDD-00188](TDD-00188.md), [TDD-00073](TDD-00073.md)).

Exit criteria for phase 3:
- `emitCall` is a single generic path plus the intrinsic table.
- Codegen has no `Is*` flags and no `case "<builtin name>"` dispatch outside the
  intrinsic table.
- `coerce` and its 14 variants are replaced by `convert`.
- Every builtin the status pages mark ✅ has a declaration, with its lowering covered by
  a test.

### Phase 4 — the runtime on libuv

Its own TDD, written when phase 3's builtin declarations exist, because the native
binding layer is exactly what the `@lower` targets call. Settled now:

- **The loop is an interface; libuv is its hosted backend**, linked and vendored as
  source for targets without a system package (Sailfish, Android). A freestanding
  target (a microcontroller, [TDD-00036](TDD-00036.md)) or WebAssembly
  ([TDD-00048](TDD-00048.md), no libuv on WASI) gets a different implementation
  behind the same interface. On hosted targets, Node's own loop replaces:
  - the `select()` monolith and its fd_set rebuild;
  - the keep-alive predicates, replaced by handle ref counts (`uv_ref`/`uv_unref`, which
    also gives timers `unref`);
  - the `forcezero` flags (`uv_idle_t`/`uv_async_t`);
  - the deadline folds (one `uv_timer_t` each);
  - the timer array (libuv's timer heap; every due timer fires in one pass);
  - the private loops;
  - Windows' separate IOCP reactor (`win32io.c`), replaced by libuv's Windows backend;
  - DNS (`uv_getaddrinfo`) and signals (`uv_signal_t`).
- **libcurl through its embedding API.** `CURLMOPT_SOCKETFUNCTION` maps onto `uv_poll_t`
  and `CURLMOPT_TIMERFUNCTION` onto `uv_timer_t`, with `curl_multi_socket_action`
  driving it. `curl_multi_fdset` and every synchronous curl drive are removed.
- **TLS moves to memory BIOs over `uv_tcp_t`**, making handshakes non-blocking.
  **nghttp2 is driven per connection** from read callbacks through
  `nghttp2_session_mem_recv`/`mem_send`.
- **Handlers run in a fiber per request (HTTP/1.1) or per stream (HTTP/2)**, started
  from the read callback. nghttp2's frame callbacks then run outside any fiber, so an
  HTTP/2 handler that awaits needs its own stream fiber, a data provider that defers
  (`NGHTTP2_ERR_DEFERRED` / `nghttp2_session_resume_data`), and `WINDOW_UPDATE`
  un-parking the stream's fiber. [TDD-00218](TDD-00218.md)'s set-aside Stage 1 becomes
  required.
- **Fibers stay.** A libuv callback resumes the fiber, and the fiber yields back. `uv_run`
  is never entered from a fiber or re-entrantly, so every "cannot run the loop from
  here" subset drive becomes a coroutine park.
- **Microtasks drain after every callback**, through the single callback trampoline.
  The trampoline also:
  - carries the async context: captured when a callback is *registered* (timers, fs,
    promise reactions, libuv requests) and restored when it runs
    (`AsyncLocalStorage`, [TDD-00168](TDD-00168.md));
  - wraps callbacks from foreign toolkits (webview bindings, Qt slots, JNI) the same
    way ([TDD-00142](TDD-00142.md), [TDD-00192](TDD-00192.md),
    [TDD-00147](TDD-00147.md));
  - exposes a generic `enqueueMicrotask(closure)` and an end-of-task hook
    (`PerformanceObserver` batching, IndexedDB auto-commit;
    [TDD-00166](TDD-00166.md), [TDD-00011](TDD-00011.md)).
- **The loop can live inside a foreign main loop.** A GUI toolkit (Cocoa, GTK, Qt,
  Win32, SDL) watches `uv_backend_fd` and calls `uv_run(UV_RUN_NOWAIT)` on each wakeup,
  or libuv runs on its own thread and hops through `uv_async_send`. The webview's timer
  pump and the Sailfish QTimer pump move onto this, since the private loops they call
  are deleted ([TDD-00142](TDD-00142.md), [TDD-00144](TDD-00144.md),
  [TDD-00171](TDD-00171.md), [TDD-00192](TDD-00192.md)).
- **Any thread can post to the loop:** one `uv_async` plus a queue for worker
  completions, `node:ffi` thread-safe callbacks and Workers alike, with `uv_queue_work`
  exposed to lowering for non-blocking foreign calls ([TDD-00190](TDD-00190.md)).
- **Fiber context switching sits behind a port interface** (ucontext, Win32 fibers,
  libucontext or assembly), which also registers each fiber's stack and saved
  registers with the GC interface ([TDD-00147](TDD-00147.md)).
- **A library entry mode:** runtime start-up that does not own `main()` or assume the
  main thread, for Android and embedding hosts ([TDD-00147](TDD-00147.md)).
- **Errors carry libuv's negative `errno` on every host**, as Node's do
  ([TDD-00180](TDD-00180.md)).
- **Native code never holds a raw managed pointer.** libuv handles, libcurl easy
  handles, OpenSSL and nghttp2 sessions, the thread pool and `node:ffi` refer to a
  managed object only through a pinned reference or a handle-table index, registered
  and released through the GC interface. A moving collector can then relocate
  everything the native side does not pin.
- **One GC interface in the runtime:** `kml_gc_alloc(typeid, size)` (inlinable, with a
  thread-local allocation buffer), optional `free`, root registration (globals,
  thread-local blocks, fiber stacks and saved contexts, handle tables), pin/unpin,
  weak references, ephemerons (`WeakMap`) and finalizers (`FinalizationRegistry`),
  and safepoint and write-barrier hooks that are no-ops for the current collectors.
  The current collectors (`-mm=gc` Boehm, and the `manual`/`auto` modes' allocation
  paths) are its first implementations; codegen never names a collector. Boehm can use
  the layout table for typed allocation (fewer false retentions).
- **The runtime is compiled once into static libraries and linked with LTO and section
  garbage collection.** The IR-in-Go-strings runtime (about 27,600 lines) moves to C
  now. The 403 `used*` flags and 407 `ensure*` declarators are replaced by the linker's
  dead-code elimination and one header. The archives are split by profile (hosted,
  freestanding) and by optional dependency (per backend, per library), with a `-g
  -O0` debug variant, and link inputs are derived from the `@lower` symbols a program
  references ([TDD-00036](TDD-00036.md), [TDD-00193](TDD-00193.md),
  [TDD-00073](TDD-00073.md)).
- **The target shape is Node's.** The native layer stays thin: bindings plus
  string/array/GC primitives. Library logic belongs in the builtin library, which moves
  to TypeScript compiled by this compiler once phases 1 to 3 make it sound enough to
  build its own library.
- **Tests assert structure, never timing counts.**
  - An interval fires before a slow response arrives.
  - No timer fires before its delay.
  - A waiting process sleeps (low CPU).
  - Each such test also runs throttled (`taskpolicy -b` on macOS, `nice -n 19` on
    Linux).
  - The fixed `minTicks` threshold in `tests/event_loop_wait_test.go` is removed.

### Phase 5 — uniform heap layout

Once the runtime is C on libuv and representations are closed:
- Every boxable heap object starts with one header word, closures included: type id,
  GC bits, reference-count bits (sized now for `-mm=auto`'s reference counting), an
  immortal bit (read-only literals and static data), flags for dynamic objects
  (null prototype, frozen, sealed, proxy), a string's encoding bit (one-byte vs
  other, so UTF-16 `length`/`charCodeAt` can be made faithful later), and length
  where applicable. A dynamic object reserves a shape word (hidden classes,
  [TDD-00220](TDD-00220.md)); an array header carries a capacity word and a holes
  pointer ([TDD-00226](TDD-00226.md)). Finding a handle's kind in an `any` is then an
  exact header read, not an address-bit probe ([TDD-00228](TDD-00228.md)'s bit-46
  flag fails on macOS arm64, whose heap addresses exceed 2^46). Closures get their
  metadata through the header, retiring the code-pointer side table of ADR-01093.
- **This reverses two earlier decisions**, deliberately, with an ADR: TDD-00068
  rejected a per-type shape descriptor, and TDD-00155 promised statically-typed objects
  zero headers. The header here serves the collector, exact `typeof`/`instanceof`/
  inspect dispatch and weak references, not property enumeration, and costs one word
  per object. The principle: avoiding a cost is good, but faithfulness to TypeScript
  and Node comes first. JavaScript-only semantics belong to `-compat=js`. The partial
  headers that grew up without this (the `Error` field-0 flag, magic words, a
  code-pointer side table, an address-keyed frozen set) show the cost was already being
  paid, piecemeal.
- **Value-like data stays headerless:** `@value` flat arrays (ADR-00706), tuples
  returned by value, stack-allocated objects under `-optimize-memory`, and whatever
  else escape analysis proves never reaches `any`, a weak reference or the collector's
  heap. The header is for boxable heap objects only.
- Considered and not chosen: typing whole blocks instead of objects (the type id
  stored once per block). It costs no per-object memory, but it fragments the heap
  (one partly-filled block per type), fits Immix's block and line model poorly, and
  still needs a lookup to identify a handle in `any`.
- **Object identity never depends on the address:** a stable identity hash lives in the
  header (or a side table the collector updates), so no table is keyed by `ptrtoint`
  (today: the frozen/sealed set in `emitStaticIntegrity`, and address-hashed
  `Map`/`Set`/`WeakMap` keys).
- **The type id indexes a layout table:** object size (or element size for arrays and
  strings); a pointer map whose slots are raw managed pointers, NaN-boxed words
  (traced by tag), interior pointers, variable-length boxed arrays, side pointers
  (the holes bitmap) and external memory never traced; field names and kinds (for a
  generic structured-clone serializer, inspect and deep free,
  [TDD-00011](TDD-00011.md), [TDD-00175](TDD-00175.md)); the class name; the parent
  type id (`instanceof`, inheritance); and a method table (`toJSON`, inspect), so
  `JSON.stringify` calls a host class's declared `toJSON` generically
  ([TDD-00203](TDD-00203.md)). Type ids are nominal and map many-to-one onto layouts
  (`Map`, `Headers` and an `EventEmitter` map can share one), and stay stable across
  separately compiled units ([TDD-00055](TDD-00055.md) islands). It serves
  `typeof`/`instanceof`/inspect dispatch and precise tracing alike. The table is
  generated from the same Go definitions `reprOf` uses, as are the C-side layouts
  (`dynjson.c`, string and array headers, the error object), so nothing is mirrored by
  hand.
- Every string producer goes through one allocator.
- **Interior pointers are part of the layout.** A string value points past its header
  into the allocation, and the collector must map such pointers back to the object
  start: `alloc` maintains a per-block object-start bitmap for that. The header offset
  is a named constant of the layout table, not a literal repeated at every site.
- **Layouts follow the target's data layout,** not a hard-coded 8-byte pointer: a
  32-bit target (a microcontroller, `wasm32`) gets 4-byte words and offsets
  ([TDD-00036](TDD-00036.md), [TDD-00048](TDD-00048.md)).

### Collector-readiness

A precise, possibly moving collector (Immix, later a generational or RC variant) is
planned as a compiler option alongside Boehm. It needs:

- precise layouts (phase 5's layout table);
- a single allocation path and a single heap-pointer store path (P3.3a);
- no raw managed pointers held by native code, and all roots registered in one place
  (phase 4's GC interface);
- a decision on stack roots.

The decision on stack roots: **conservative stack scanning with pinning first.** Every
object a stack or register word may point to is pinned for that collection; everything
reachable only from the heap can move. That is how Immix is commonly run beside native
code ("conservative Immix"). It keeps fibers as they are: a fiber stack is one more
conservatively scanned range, registered by the GC interface. Precise stack maps (LLVM
`gc.statepoint`) remain possible later as an opt-in, because lowering already marks
every pointer-typed value. Adding a collector is then a new implementation of the GC
interface, not a change to codegen.

What the collector also needs, settled now:
- **Threads and safepoints.** Workers are real threads, so even a conservative
  collector must stop every mutator. Lowering places safepoint polls on loop back-edges
  and in function prologues, and the runtime enters a safe region around every
  blocking native call.
- **Heaps per Worker**, as Node's isolates are: each Worker's heap is collected on its
  own, and `klain:sync` shared memory never holds managed pointers.
- **Weak references, ephemerons and finalizers** go through the GC interface, which
  a moving collector updates.
- **Conservative stack scanning is impossible on WebAssembly** (the value stack cannot
  be inspected), so a collector there needs a shadow stack or precise roots. The
  `addrspace(1)` managed-pointer type (P3.3) is what makes either possible.
- **`-mm=auto`'s reference counting beside a tracing collector:** the header's
  reference-count bits and the per-site barrier kinds (P3.3a) let an RC cluster and a
  collector coexist; how they share a heap is decided when the collector lands.

[TDD-00135](TDD-00135.md) (Immix) is updated to this plan: conservative stack scanning
first instead of statepoints, and Boehm moved behind the GC interface.

### Process rules for this restructure

- **Status is honest.** A TDD stage is Implemented only when it has shipped on every
  platform with its tests. Remaining work is a new BACKLOG item and keeps the TDD at
  Partially Implemented. The two TDDs named in Context are corrected accordingly.
- **Fix at the origin.** A bug in a type, representation, builtin or loop fact is fixed
  where that fact is computed. A symptom-site fix that leaves the origin in place is
  not a fix.
- **Nothing old survives its replacement.** When a new mechanism covers an old one, the
  old one is deleted in the same change. No fallback, no "legacy path" flag.
- **Coupled codegen work is serial.** Parallel discovery (inventories, shadow-report
  triage) is fine.

## Open questions

- **Which AST structs change shape in P1.5, and when.** Replacing `ast.TypeAnnotation`
  touches every reader of annotations. The conversion shim bounds that to phase 2, but
  the order in which readers move is decided in the phase-1 ADRs.
- **Generic inference depth.** How much of TypeScript's inference (contextual typing of
  callbacks, return-type inference from `.then` chains) phase 2 needs before the shadow
  report reaches zero. It is measured from the report, not guessed.
- **How far status rows derive from declarations.** `@status` keys (P3.1) join the two;
  whether the API-surface rows themselves are then generated from `lib/*.d.ts`, leaving
  only caveats hand-written, is decided when phase 3 starts.
- **Whether the builtin library moves to TypeScript before or after phase 4.** `@lower`
  allows either, function by function.
