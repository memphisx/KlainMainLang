# ADR-00891: String-coercing builtins ToString a non-string argument (invalid-IR sweep)

- **Relations**: `Extends ADR-00885`
- **Date**: 2026-09-12

## Context

`parseInt`/`parseFloat`, `String.prototype.padStart`/`padEnd` (fill), and
`String.prototype.indexOf` (search) emitted invalid IR on a non-string
argument: the value was passed straight through as a `ptr`, so a number/boolean
became `strtoll(ptr 1, …)` / `__kml_str_len(ptr 0)` — `error: integer constant
must have integer type`. Part of the `integer constant must have integer type`
bucket in the 2026-09-12 strict faillist: Test262 `parseInt/S15.1.2.2_A1_T1`
(`parseInt(true) === NaN`), `parseFloat/S15.1.2.3_A1_T1`,
`String/prototype/pad{Start,End}/fill-string-non-strings`
(`'abc'.padEnd(10, false) === 'abcfalsefa'`), and `indexOf/searchstring-tostring`.

## Investigation

Each site consumed its argument as a raw `ptr`: `emitStringPad` used the fill
`Value.Ref` directly in `__kml_str_len`; `emitStringIndexOf` ran the needle
through `coerceStringArg`, which ToStrings **only** an object operand
(`objectMayToPrimitive`), leaving a number/boolean untouched; `emitParseInt`/
`emitParseFloat` ran the input through `nullSafeParseInput`, which only null-safes
a `ptr` and passes a non-`ptr` through unchanged. The faithful JS behavior is
ToString on all of these (`parseInt(true)` parses `"true"` → NaN,
`"abc".padEnd(10, false)` fills with `"false"`, `s.indexOf(123)` searches
`"123"`) — the same choice ADR-00885 made for a RegExp subject, and it makes the
tests pass rather than merely reclassify. `regexSubjectToString` already
implemented exactly this normalization, unnamed for reuse.

## Decision

Generalize the RegExp subject normalizer into a shared `emitArgToString`
(`emit_exprs_types.go`): an already-string value coerces to `ptr` unchanged,
`undefined`/`void` becomes the literal `"undefined"`, anything else runs through
`emitValueToString`. Apply it at every string-coercing builtin argument site:
`emitStringPad` (fill), `emitStringIndexOf` (search, replacing the
object-only `coerceStringArg`), `emitParseInt` and `emitParseFloat` (input,
before `nullSafeParseInput`). `regexSubjectToString` now delegates to it, so the
one normalization has a single definition. Faithful in both lanes (JS ToStrings
here regardless of `-compat`).

## Implementation notes

- `emitParseInt`/`emitParseFloat` keep `nullSafeParseInput` after the ToString:
  a genuine string input still flows through unchanged and a null string ptr is
  still mapped to `"null"`.
- `emitArgToString` is a strict superset of the old `coerceStringArg` for the
  indexOf needle (objects still ToString via `emitValueToString`; numbers/
  booleans now too), so no object-coercion behavior is lost.

## Verification

- The five sampled Test262 files now **PASS** (exit 0, self-asserting):
  `parseInt/S15.1.2.2_A1_T1`, `parseFloat/S15.1.2.3_A1_T1`,
  `pad{Start,End}/fill-string-non-strings`, `indexOf/searchstring-tostring` —
  real gains in both lanes, not merely CLANG_ERROR → COMPILE_ERROR.
- Behavior checks: `parseInt(true)`→NaN, `'abc'.padEnd(10,false)`→`abcfalsefa`,
  `padEnd(10,0)`→`abc0000000`, `padStart(6,1)`→`111abc`, `'a1b1'.indexOf(1)`→1,
  `indexOf(9)`→-1; string inputs unchanged (`parseInt('0x1F')`→31,
  `parseFloat('3.14')`→3.14, `padEnd(3,'-')`→`x--`).
- New `TestE2EStringToStringArgs`; String/Number/RegExp/Template suites green;
  `go build`, `go vet ./...`, gofmt clean; full `make test-par` gate run.
