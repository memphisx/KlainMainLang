# ADR-00460: arrow functions capture the enclosing method's lexical `this`

- **Date**: 2026-08-29

## Context

`'this' is only valid inside a method or constructor body` was a 50-case
TS-oracle false-reject bucket, and the underlying gap — an arrow inside a
class method could not touch `this` (`xs.forEach(x => this.total += x)`)
— is one of the most common real TS idioms.

## Investigation

`this` is already an ordinary scope symbol ("this") inside method bodies;
arrows already capture enclosing locals through `gatherCaptures`' free-
variable scan. The scan missed `this` only because `ThisExpression` is
not an `Identifier`. Function expressions must *not* capture (their
bodies keep JS's dynamic `this`), so the detection can't just be added to
the shared scanner.

## Decision

`gatherCaptures` (the arrow path only) appends a `"this"` capture when
the arrow's subtree lexically uses `this` and a receiver is in scope.
Detection is `lexicalThisIn`, a small reflective AST walk (covers every
node shape without a hand-maintained visitor) that recurses through
nested arrows and stops at `FunctionExpression`/`FunctionDeclaration`
boundaries. Inside the closure body `emitThisExpression`'s existing
`lookup("this")` then resolves to the captured heap cell — mutation
through `this` propagates, matching JS reference semantics. `this` in a
function expression stays a clean rejection.

## Verification

Mac. `tests/classes_test.go` additions (mutating capture + nested arrows,
async arrow, function-expression rejection) and the `examples/classes`
extension (`forEach` + `this.total`) pass; class/closure/arrow/async E2E
batch green. TS oracle: **55.2% → 55.4%** (agreement 5111 → 5129). Node
oracle unchanged (40).
