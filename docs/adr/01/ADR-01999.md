# ADR-01999: path/posix and path/win32 default-export the flavour object

- **Date**: 2026-11-21

## Context

In Node, `import p from 'path/posix'` gives `path.posix` itself, so
`p === posix` is true. The Node test `es-module/test-esm-path-posix.mjs`
asserts exactly that. Here the comparison was false.

## Investigation

- lib/node/path_posix.ts and path_win32.ts were default-namespace modules:
  the default import was the module's namespace (forwarding functions plus
  `sep` and `delimiter`), a separate object from `path.posix`.

## Decision

Each module default-exports its flavour object (`export default flavour`).
The named exports stay, so `import { join } from 'path/posix'` works as
before.

## Implementation notes

- lib/node/path_posix.ts, lib/node/path_win32.ts.

## Verification

- Linux x86 (Node304): `TestE2EPathFlavourDefaultIsSameObject` matches Node

- Node suite, files matching `path`: js lane 14 → 19 passed, strict lane
  7 → 9, compared with HEAD's runner. Some of that gain comes from earlier
