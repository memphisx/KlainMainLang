# ADR-00623: D1 Stage 3 — the prototype chain

- **Relations**: `Implements TDD-00155 (Stage 3)`, `Extends ADR-00621, ADR-00622`
- **Date**: 2026-09-01

## Context

Stages 1–2 gave dynamic objects a property bag and made untyped JSON real.
Stage 3 makes the bag header's proto pointer live: prototype-chain semantics
— the defining content of the D1 model per [TDD-00068](../tdd/TDD-00068.md),
and the foundation Stage 4's vanilla-JS prototype "classes" build on.

## Decision

**Runtime** (`runtime_dynobj.go`): `__kml_dynobj_get` walks the chain (own
table first, then each proto link); a new `has_chain` backs the `in`
operator while `has` stays own-only for `Object.hasOwn`/`hasOwnProperty`
(an `ownOnly` flag threaded through `emitHasOwnProperty`). `get_proto`/
`set_proto` read/re-link the pointer; `set_proto` refuses a cycle by
scanning the proposed chain for the target, which keeps every chain acyclic
so the hot get/has walks need no visited set. Writes, `delete`,
`Object.keys`, `for...in`, and `JSON.stringify` stay own-table — exactly
JS's own/inherited split (delete re-exposes the proto's value; keys and
stringify enumerate own only).

**Codegen** (`emit_dynobj.go`):

- `Object.create(proto | null)` — fresh bag with the given proto; the
  property-descriptors second argument is rejected until Stage 5.
- `Object.getPrototypeOf` / `Object.setPrototypeOf` with JS edge behavior:
  TypeError on null/undefined targets, non-object targets returned
  unchanged, `Object prototype may only be an Object or null` for a bad
  proto operand, and V8's `Cyclic __proto__ value` on a refused cycle.
- `__proto__` as member read/write on a dynamic object routes to the proto
  link with the accessor's semantics — a non-object, non-null assigned value
  is silently ignored, not stored as a plain property.
- The `{ __proto__: base }` literal special form sets the proto at
  construction (a computed `["__proto__"]` key stays a plain property, as in
  JS).
- Shared plumbing: `emitDynProtoOperand` (bag-or-null resolution, strict
  throw vs. setter-silent modes), `emitDynSetProtoChecked`,
  `emitBoxBagOrNull`.

## Consequences

- `Object.create` — previously "out of scope: prototype model" — flips ✅
  for dynamic objects; the fixed-shape rationale now applies only to the
  static tier, and the status pages' "no dynamic property add/delete" claim
  is rescoped accordingly.
- Disclosed limits: prototype machinery exists on dynamic objects only
  (statics have no proto link; a boxed primitive's `getPrototypeOf` answers
  `null` — no primitive prototype objects); inherited enumerables don't
  appear in `for...in`; a runtime-computed `"__proto__"` bracket key is a
  plain property.
- Verified on the Mac (arm64): 4 new E2E tests (20 total), the Stage-3
  smoke program byte-identical to Node, example extended.
