# ADR-00490: Response headers + XHR getResponseHeader/getAllResponseHeaders

- **Date**: 2026-08-29

## Context

Neither `fetch` `Response` nor `XMLHttpRequest` exposed response headers —
a long-standing caveat on both rows. The fetch runtime discarded header
text entirely (libcurl only got a body `WRITEFUNCTION`).

## Decision

Capture, then parse lazily:

- `__kml_fetch_async` allocates a second growable `{data,len,cap}` buffer
  fed by the same `__kml_curl_write_cb` via `CURLOPT_HEADERFUNCTION`/
  `HEADERDATA` (20079/10029, frozen curl ABI values). The body buffer
  grows to 40 bytes; slot 4 points at the header buffer, reachable later
  through the pending struct.
- `res.headers` calls `__kml_fetch_headers_map(pending)`: skips
  status/blank lines, lowercases keys (fetch's Headers rule), left-trims
  values, and fills a fresh string map. The result types as `Headers`
  (`HeadersType()`), so `.get()` is case-insensitive via the existing
  lowered-key path. Null pending (combinator-built Response) → empty map.
- XHR gains a hidden `__kml_xhr_resp_headers` field, filled from the same
  parser in `send()`'s success branch. `getResponseHeader(name)` lowercases
  the query and returns the mapped value (null map/miss → null, matching
  the spec's pre-DONE/absent return). `getAllResponseHeaders()` serializes
  via `__kml_xhr_headers_all` into the spec's `name: value\r\n`
  concatenation, in arrival order (spec wants a lowercase sort — accepted
  narrowing), empty string when the map is null.

Headers are parsed on each `.headers` access, not cached — cheap, and
avoids another Response field.
