## Known limitations

- **Strict-mode early errors**: there's no general strict-mode parser context, so several Test262 early-error cases around a literal `"use strict"` directive stay unrejected — notably `eval`/`arguments` as an *assignment* target in strict code, and bindings inside a getter/setter accessor body. A narrower safe subset is caught: duplicate parameter names, a non-simple parameter list, and `eval`/`arguments` as a parameter or `let`/`const`/`var` (or for-of/for-in loop-variable) binding name under `"use strict"` (or an always-strict class method). Block-scope `let`/`const`-vs-`var` redeclaration *is* tracked — a strict-independent early error, including the cross-nested-block `let x; { var x }` intersection (see [TDD-00070](../tdd/TDD-00070.md)/[ADR-00210](../adr/ADR-00210.md)/[ADR-00211](../adr/ADR-00211.md)).
