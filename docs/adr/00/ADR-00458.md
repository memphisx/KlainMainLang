# ADR-00458: atob throws InvalidCharacterError; typeof DOMException

- **Date**: 2026-08-29

## Context

The Node oracle's `test-global-domexception.js` exposed two gaps found in
passing: `typeof DOMException` answered `"undefined"` (the name was in
`errorKinds` but missing from `typeofBuiltinConstructors`), and `atob` on
invalid input silently decoded garbage instead of throwing — real atob
raises an `InvalidCharacterError` DOMException.

## Decision

- `DOMException` added to `typeofBuiltinConstructors` → `"function"`.
- `__kml_atob` gains a validation pre-pass over a 256-entry validity table
  (base64 alphabet + `=`); an invalid byte throws a real error object
  (kind `DOMException`, name `InvalidCharacterError`) through
  `__kml_throw`, catchable and `assert.throws(…, DOMException)`-matchable.
  Remaining disclosed simplifications: whitespace is rejected rather than
  stripped (forgiving-base64 strips it), and a length not a multiple of 4
  still silently drops the trailing group.

## Side effects discovered

The first fix attempt corrupted `btoa` — the two functions' loop headers
are textually identical, and a replace-all rewrite of the atob phi nodes
hit both (caught immediately by a round-trip repro; fixed before commit).

## Verification

Mac. `tests/call_test.go` `TestE2EAtobInvalidCharacterThrows` (throw +
typeof + round-trip) and the `examples/encoding_text` extension pass;
call/encoding E2E batches green. Node oracle: **39 → 40 passed**
(`test-global-domexception.js`).
