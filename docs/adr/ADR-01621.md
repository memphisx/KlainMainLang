# ADR-01621: concat with an any argument makes an any[]; a dynamic function gets its own body analyses

- **Relations**: Extends ADR-00463, TDD-00205, TDD-00200
- **Date**: 2026-10-14

## Context

A WPT observer test hung: its observers never collected all their entries.

## Investigation

- `stored = stored.concat(entryList.getEntries())`, with `entryList` an
  `any`, appended the array as one element. With a typed receiver an `any`
  argument was coerced to the element type as a scalar: `[0].concat(v)` with
  `v` an array gave `[0, NaN]`. JavaScript spreads an argument that is an
  array (IsConcatSpreadable) and appends anything else, decided at run time.
- `[].concat(xs)` over a typed `xs` produced a `number[]`, the empty literal's
  default, holding the elements' pointers as numbers; tsc types the literal
  `never[]`, its elements the arguments'.
- The usage pass that types an untyped `[]` from its later assignments and
  pushes (`inferEmptyArrayElemTypes`) did not look into a `new` expression's
  arguments (the callback given to `new PerformanceObserver(…)`) or a
  `yield`'s.
- A function compiled as a dynamic function (one passed where nothing types
  it) ran neither that pass, nor the Map pass, nor the cross-kind widening:
  its body saw whatever its enclosing function had left. `var a = []` there
  stayed `number[]`; `let x = 5; x = "hi"` and `new Map()` with object values
  failed to compile.

## Decision

- `concat` makes an `any[]` when an argument is `any`
  (`concatWidensToAny`): the receiver's elements are boxed in, each `any`
  argument spread or appended at run time. Under `-compat=js` an empty
  literal receiver takes the element type its arguments share, else `any`;
  the strict lane keeps rejecting it, as tsc does (`never[]`,
  `TestE2EStrictEmitterRejectsUnconvertibleArgs`). `inferExprType` and the
  emitter share `concatElemType`.
- The usage pass walks `new` and `yield` operands.
- `emitDynCallable` computes `widenedBindings`, `emptyArrayElems` and
  `emptyMapKV` for its own body and restores them after.
