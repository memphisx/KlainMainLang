# ADR-01599: Windows runtime fidelity after the restructure

- **Relations**: Implements TDD-00249 (Stage 3), Extends ADR-01597
- **Date**: 2026-10-13

## Context

With Windows programs linking again (ADR-01597), 61 E2E tests still failed:
crashes, wrong output against Node 24 on the same machine, and test
expectations written for POSIX. Each was compared with `node` on Windows
before any change.

## Investigation and decision

**Crashes**

- *Worker exit* (`0xC00000FF`): `__kml_worker_end_thread` called winpthreads'
  `pthread_exit`, which unwinds with `RtlUnwindEx` and fails the process at a
  frame without unwind data. The worker thread now records its start frame
  with `__builtin_setjmp` and the end jumps back to it
  (`__builtin_longjmp`, registers only), returning from the thread function.
- *Struct by value* (`0xC0000005` in `Reflect.ownKeys`, namespace objects):
  the IR passed two `{ ptr, i64 }` values to `__kml_own_keys_c`, which took C
  structs. LLVM flattens an aggregate argument into its fields on every
  target; Windows x64 passes a 16-byte C struct by reference. The C function
  now takes the fields as separate parameters. It was the only such call.
- *Stack overflow* (`0xC00000FD`), TDD-00249 Stage 3: `stackguard.c` installs
  a vectored handler for `EXCEPTION_STACK_OVERFLOW` and a 64 KB
  `SetThreadStackGuarantee`; it throws the RangeError (try frames use
  `_setjmp(buf, NULL)`, so the longjmp does not unwind). A throw from within
  the stack's last 128 KB marks the thread, and the catch that reads the
  value (`__kml_get_thrown*`) calls `_resetstkoflw()`, so a second overflow
  throws too.

**Cross-platform bug found on Windows**

- `buildErrorObjSized` never stored `__kml_name_own`: every Error had a
  malloc'd, unset flag, so `Object.keys(new Error())` was `['name']` when the
  memory was not zero. It is stored as 0.

**Node on Windows**

- fs errors report `path` and `dest` resolved (`'/nope'` → `'C:\nope'`):
  `fserror.c` resolves them with `path_win32.c`'s `win32.resolve`; a symlink
  target only gets backslashes; `mkdtemp` and `watch` keep the path as given.
- `mkdirSync(…, { recursive: true })` returns the first directory namespaced
  (`\\?\C:\…`), and a file in the way of an intermediate component is
  `ENOTDIR` (Node's `MKDirpSync`; Windows reports it as a missing path).
- A directory opens for reading (`FILE_FLAG_BACKUP_SEMANTICS`); its reads,
  and `readFileSync`, fail `EISDIR` on `read`; `w` on it is `EISDIR` on
  `open`.
- A positioned read or write restores the file position, as libuv does.
- `symlink` turns `/` in the target into `\`.
- `process.ppid` is the parent's pid (a Toolhelp snapshot).
- `os.constants.signals` and `process.kill`'s table hold Node's eleven
  Windows signals (libuv adds SIGHUP, SIGQUIT, SIGKILL, SIGWINCH; SIGABRT is
  22); `process.kill(pid, 'SIGHUP')` is `ENOSYS`.
- `util.getSystemErrorName`/`getSystemErrorMessage` and DNS errors map
  libuv's Windows numbers (`-4071`) back to the errno before the table
  lookup; `ENOBUFS` is pinned to the Linux value in `kml_posix_compat.h`.
- Dates follow ICU, as Node does: `string.c` loads Windows' `icu.dll` and
  takes the offset and the long zone name from a per-thread `ucal` calendar
  for `TZ` (the system zone when unset), reopened when `TZ` changes. The C
  runtime read `TZ=Europe/Athens` as a POSIX string ("ope").
- stdin as a pipe no longer blocks the loop: the readable stdio stream is
  set non-blocking, which the shim serves from its reader thread.
- A forked child's IPC channel: the inherited socket lives in the socket fd
  range, so the child points `NODE_CHANNEL_FD` at it before its runtime
  reads (and deletes) the variable.
- `fetch` failures: libcurl reports Winsock codes in `CURLINFO_OS_ERRNO`; they
  map through the shim to `ECONNREFUSED` and the rest.
- Brotli and Zstd load `libbrotlienc.dll`, `libbrotlidec.dll`, `libzstd.dll`.
- A socket sent over an IPC channel (`child.send(msg, server)`) travels in the
  stream as a 0 byte, `KMLH` and the `WSAPROTOCOL_INFOW` duplicated for the
  peer, as libuv frames it; each end records its peer's pid.
- The WebSocket tests' TLS server reads the client's close frame before
  closing: closing with it unread resets the connection on Windows, and Node
  24 then fires `error` as well.

**Test expectations**

Tests that hard-coded POSIX output now take the platform's: path separators
(`path`, recursive `readdirSync`), `errno` values, the resolved fs error
paths (`winPaths`), the default `highWaterMark` (16 KiB on Windows), the
`node:ffi` key order (MSVC STL), Node 24's synchronous `spawn` EINVAL for a
`.bat`, and its env-block dedup (`ALPHA` sorts first and wins). Two tests
compare with Node on Windows instead (`TestE2EPathPort`,
`TestE2EProcessMethodsErrors`). `runNodeTS` runs Node in the test's working
directory, as the compiled program runs.

## Side effects discovered

- A `klain:http` `{ workers }` program that also calls
  `http.createServer().listen()` fails in each worker with `EADDRINUSE`;
  Linux shares the port through `SO_REUSEPORT` (fixed by ADR-01604).
- `-dynamic-import=lazy` still refuses Windows: the module DLL would need the
  executable's thread-local globals, which Windows cannot import (BACKLOG).
- `fs.realpathSync.native` fails `EISDIR` on an OSFMount RAM drive in Node
  itself; not a difference on a real disk.

## Verification

Windows 11, against Node 24.19.0 on the same machine: each case above was
run under both and compared. The 61 failures are down to the cluster and
realpath items above and the five lazy-import tests. Linux and macOS not yet verified for
the shared changes (Docker run owed).
