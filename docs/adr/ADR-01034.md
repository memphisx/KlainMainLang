# ADR-01034: Windows — named pipes behind `net.connect({ path })`, socket-option/flag translation, wide raw-mode key input

- **Relations**: `Implements TDD-00180` (§2, §5); `Extends ADR-00588`, `ADR-00742`, `ADR-00760`, `ADR-00865`, `ADR-01021`, `ADR-01022`
- **Date**: 2026-09-21

## Context

The remaining §2/§5 rows of the [TDD-00180](../tdd/TDD-00180.md) audit:

- **Named pipes.** `net.connect({ path })` made an `AF_UNIX` socket on every host. Node's IPC path on Windows is a named pipe (`\\.\pipe\name`, `\\?\pipe\name`) — what local Windows services listen on. A pipe path therefore failed `ECONNREFUSED`.
- **`recv`/`send` flags discarded** and **`SO_SNDBUF`/`SO_RCVBUF`/`SO_LINGER`/`SO_RCVTIMEO` passed with Linux numbers.** Latent (no caller used them), but wrong: `MSG_PEEK` consumed, option 7 is not `SO_SNDBUF` to Winsock, and two options differ in representation.
- **Non-ASCII raw-mode input.** `klain:tty` `readKey`/`readByte` read the console with `ReadFile`, i.e. through the input code page.

## Investigation

The IOCP reactor already serves overlapped pipe ends (a child's stdio): a zero-byte `ReadFile` on the port for readiness, a queued-write FIFO for output. A named-pipe client handle opened `FILE_FLAG_OVERLAPPED` is the same object, so the design is a *conversion*: the IR keeps its host-agnostic `socket(AF_UNIX)` + `connect(sockaddr_un)`, and the shim's `connect()` — seeing a path in the pipe namespace — opens the pipe and turns the description into `KFD_PIPE` with both `ovl` and `ovl_rd` set.

The first version hung after `'connect'`. Cause: the write-only pipe ends associate their handle lazily with `FILE_SKIP_COMPLETION_PORT_ON_SUCCESS`, and the write pump relies on it (a synchronous success frees the op at once). On a **duplex** handle that mode also swallows the packet of a zero-read that completes immediately — data already waiting — so the descriptor was never reported readable. A duplex handle needs the sockets' discipline instead: no skip mode, every issued op owned by the drain.

A pipe has no half-close. libuv's `uv_shutdown` on a pipe drains the writes and then lets the handle go (its EOF timer), which is how the peer learns the stream ended.

`server.listen(path)` does not exist on any host, so the server side of named pipes is part of that cross-platform feature, not of this port.

`ReadConsoleW` is exact on every code page, and with `ENABLE_VIRTUAL_TERMINAL_INPUT` it carries the same `ESC [ A` sequences; an astral character arrives as a surrogate pair, possibly across two reads.

## Decision

- `connect()`: a `sockaddr_un` whose path is in the pipe namespace goes to `kfd_pipe_connect()` — `CreateFileW(…, FILE_FLAG_OVERLAPPED)`, a bounded `WaitNamedPipeW` retry on `ERROR_PIPE_BUSY`, then the conversion, with **one up-front port association without skip mode**. `kfd_wq_pump` leaves a synchronously-completed write to the drain when the description is such a pipe. Failure leaves the fd the socket it was (`ENOENT` for a missing pipe), so the caller's error path closes it as usual and the socket's `'error'` event fires in the normal shape. Any other path stays a real `AF_UNIX` socket.
- The socket-API calls a `net.Socket` makes keep answering on the converted fd: `getsockopt(SO_ERROR)` → 0, `setsockopt` → 0 (Node ignores `setNoDelay`/`setKeepAlive` on a pipe too), `getsockname`/`getpeername` → an empty `AF_UNIX` address, and `shutdown(SHUT_WR)` flushes the write queue and releases the handle, after which reads are end-of-file and writes `EPIPE`.
- `msg_flags()` translates `MSG_*` (PEEK/OOB/DONTROUTE share values, `WAITALL` does not, `NOSIGNAL`/`DONTWAIT` have no Winsock bit); `recv`/`send` with such a flag route to `recvfrom`/`sendto` instead of the flag-less `read`/`write`. `setsockopt` maps `SO_SNDBUF`/`SO_RCVBUF`, converts `SO_LINGER`'s `{int,int}` to `{u_short,u_short}` and `SO_RCVTIMEO`/`SO_SNDTIMEO`'s `timeval` to milliseconds.
- `klain:tty`: at a console, `readKey` reads up to 31 UTF-16 units with `ReadConsoleW`, completes a dangling high surrogate, and returns UTF-8; `readByte` hands out the UTF-8 bytes of one key at a time. A redirected stdin keeps the byte read.

## Implementation notes

`codegen/llvm/win32src/win32io.c` (two new description flags, `npipe`/`npipe_eof`), `kml_posix_compat.h`, `emit_tty.go`.

## Side effects discovered

Winsock's `AF_UNIX` provider *opens* a `\\.\pipe\…` path far enough to complete the server's `ConnectNamedPipe` before refusing the connect — a pipe server saw a phantom zero-byte client from the old code path.

## Verification

Windows 11 (26200): `tests/net_named_pipe_windows_test.go` — a native one-shot pipe server; the client connects, writes, receives two separate `'data'` events, writes again (the server reports receiving it), then `'end'` and `'close'` when the server closes; 3/3 runs. A missing pipe: `'error'` with `ENOENT`/`connect`, then `'close'`. `TestE2ENetConnectUnixSocket` (a real `AF_UNIX` path) still passes. `TestWin32SockOptionTranslation` drives `MSG_PEEK` and the four options through the shim natively. `TestE2ETtyConsoleRawReadKeyNonASCII` types `λ`, `😀` and `é` into a pseudo-console and reads them back as UTF-8 through `readKey` and `readByte`. Not applicable to Linux/macOS.
