# TDD-00112: `WeakMap`/`WeakSet`/`WeakRef` — mode-dependent weak collections

- **Status**: Implemented
- **Date**: 2026-08-24
- **Notes**: Object-identity-keyed, non-iterable. One `__kml_weak_*`/`__kml_weakref_*` interface, two backings: `-mm=manual` strong-backed (nothing collected); `-mm=gc` genuinely weak via Boehm disappearing links, with the referent word in `GC_malloc_atomic`/unscanned memory (a scanned word would keep the referent alive). Added the `gc()` (`--expose-gc`) global to force a collection. `Object.create` stays out of scope (prototype model)

## Context

`WeakMap`/`WeakSet`/`WeakRef` are the last ❌ collection rows on
[OBJECT-COLLECTIONS.md](../status/OBJECT-COLLECTIONS.md) (alongside
`Object.create`, which stays out of scope — its core is the prototype model,
[TDD-00068](TDD-00068.md)). Their defining feature — a key/element/referent that
does **not** keep the object alive — depends entirely on the memory-management
mode, so the design forks on `-mm`:

- **`-mm=manual`** (default) never frees anything ("leak by design"). A weak
  reference is *semantically indistinguishable* from a strong one here: nothing
  is ever collected, so `.deref()` never returns `undefined` and a WeakMap key
  never disappears. A strong-backed implementation is therefore not a fake — it
  is the *only* observable behavior this mode can have, and it matches how every
  other allocation in the mode already behaves.
- **`-mm=gc`** (Boehm) genuinely collects unreachable objects, so weak semantics
  are both meaningful and required: a WeakMap entry / WeakRef whose referent is
  collected must observably drop.

## Design

All three key on **object-pointer identity** (`ptrtoint` of the referent), never
on value. The referent must be a heap object reference (class instance, object,
array, Map/Set, …) — a scalar/string key is a clean compile error (a weak
reference to an unboxed scalar is meaningless). Weak collections are **not
iterable** in the spec (no `size`, `keys`, `values`, `entries`, `forEach`), so
this compiler implements exactly the spec surface and nothing more:

- `WeakMap<K,V>`: `set(k, v)` / `get(k)` / `has(k)` / `delete(k)`.
- `WeakSet<T>`: `add(v)` / `has(v)` / `delete(v)`.
- `WeakRef<T>`: `new WeakRef(obj)` / `deref()`.

### `-mm=manual` (strong-backed)

- `WeakMap<K,V>` ≡ a **number-keyed** `Map` on `ptrtoint(key)`, reusing
  `__kml_map_num_*` verbatim. `V` is the declared/inferred value type.
- `WeakSet<T>` ≡ a number-keyed set (map with dummy `0` values) on
  `ptrtoint(elem)`, reusing the same runtime `Set` already uses.
- `WeakRef<T>` ≡ a one-word heap box holding the referent pointer; `deref()`
  loads it. Never null (nothing is collected).

Because the key array holds `i64`s (never the value type of the referent), no
runtime type info about the key is needed — pointer identity is all that's used,
exactly as `Set`'s existing number path already does for object elements.

### `-mm=gc` (real weak semantics via Boehm disappearing links)

Boehm's `GC_general_register_disappearing_link(void** link, void* obj)` clears
`*link` to NULL when `obj` becomes collectable, and a registered link is **not
followed during marking** — so the link location does not keep `obj` alive. The
naive "store keys in the map's i64 array" fails twice: (1) conservative marking
would treat the i64 as a root and keep `obj` alive, and (2) the array is
realloc'd on growth, invalidating the by-address link registration.

**Per-entry cell design.** Each weak entry is its own stable, `GC_malloc`'d cell:

```c
struct weak_cell { void* link;  /* referent, disappearing */  int64_t val; };
```

- `link` is registered via `GC_general_register_disappearing_link(&cell->link, obj)`.
  The cell is stable (never moved/realloc'd), so the registration stays valid for
  the cell's life.
- The WeakMap stores an array of `weak_cell*` (ordinary GC refs — that array may
  grow/move freely). Lookup walks live cells comparing `cell->link == obj`,
  skipping cells whose `link` has gone NULL (referent collected). `has`/`get`
  treat a NULL-link cell as absent; a periodic/at-access compaction drops dead
  cells.
- `WeakSet` is the same cell without the `val` word (or `val` unused).
- `WeakRef<T>` is a single cell: `deref()` returns `cell->link` (the compiler's
  null stand-in once collected).

A small C runtime file (`weaksrc/weak.c`, linked only when a program uses a weak
type — the same on-demand-link pattern `fetch`/`tls`/`bigint` use) provides:

```c
void*   __kml_weak_create(void);                         // new weak map/set
void    __kml_weak_set(void* w, void* key, int64_t val); // register disappearing link
int64_t __kml_weak_get(void* w, void* key, int* found);
int     __kml_weak_has(void* w, void* key);
int     __kml_weak_delete(void* w, void* key);
void*   __kml_weakref_create(void* obj);
void*   __kml_weakref_deref(void* box);                  // obj or NULL
```

Under `-mm=gc` these use `GC_malloc` + disappearing-link registration; the same
symbols are **not** used in manual mode (manual routes to the existing
`__kml_map_num_*` path instead), so `weak.c` is a GC-only translation unit.

### Mode dispatch

The emitter already knows the mode (`e.isGCMode()`, emitter.go). `WeakMap`/
`WeakSet`/`WeakRef` codegen branches on it: manual → `__kml_map_num_*` /
inline box; gc → `__kml_weak_*`. The AST/parser and the surface method dispatch
are mode-independent; only the emitted runtime calls differ.

## Open questions

- **Dead-cell compaction cadence** under gc: compact on every `set`, or only when
  the live-ratio drops below a threshold? Start with compact-on-`set` (simplest,
  bounded), revisit if it shows up in profiling.
- **Boehm thread/registration interaction**: the existing `-mm=gc` + Worker
  segfault on Linux ([CONCURRENCY-WORKERS.md]) is a separate open bug; weak refs
  should be verified single-threaded first and not assumed to compose with the
  worker path until that's resolved.

## Verification plan

- Manual mode: E2E that `WeakMap.set/get/has/delete`, `WeakSet.add/has/delete`,
  and `WeakRef.deref()` all behave (deref never null; keys persist).
- GC mode (`-mm=gc`, skipped when libgc absent, like the other GC tests): a
  referent dropped and `GC_gcollect()`-forced shows `deref()` → null and a
  WeakMap `has` → false. Verified on Mac first (Boehm disappearing links
  unverified here), then Linux via Docker.
- Non-object key ⇒ clean compile error (test).
- Example under `examples/`; `make examples` + `make conformance` at the end.
