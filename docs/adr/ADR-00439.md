# ADR-00439: klain:webview Stage 3 — loop fusion (page-tick pump) + async bind

- **Relations**: Implements [TDD-00142](../tdd/TDD-00142.md); Extends [ADR-00438](ADR-00438.md), [ADR-00437](ADR-00437.md)
- **Date**: 2026-08-28

## Context

`webview_run` owns the process main loop on the GUI thread; this runtime's own
event loop (`__kml_event_loop_run`) cannot also own it. Stage 2 resolved
page↔native calls synchronously and pushed anything event-loop-shaped into a
Worker. Stage 3 lets *timers, microtasks, and the task scheduler run on the GUI
thread itself*, so `setTimeout`-driven UI updates and async `bind` work without
a Worker — the one real design problem the TDD named.

## Investigation

- `emit_timers.go:380` `__kml_timer_drain()` is a **blocking** drain — it
  `nanosleep`s until every timer is due. Calling it from a GUI loop would block
  the window. A non-blocking "fire what's due now, return" variant was needed.
- `runtime_microtask.go:70` `__kml_drain_microtasks()` and
  `runtime_task.go` `__kml_task_sched_step()` already exist (real when used,
  no-op stubs otherwise) — the pump just needs to call all three each tick.
- `emit_promise_new.go:184` `emitPromiseAdopt` is the reusable template for
  registering a native reaction that fires at a promise's settlement (enqueue
  now if already settled, else attach to the promise's reaction list at field
  4). Promise layout: `{ i64 state, ptr, i64 value, i64, ptr reactions }`
  (`runtime_task.go:53`).

## Decision

**Loop fusion (mechanism (a) from the TDD).** `run()` installs a page-driven
pump before `webview_run`:
- a new non-blocking `__kml_timer_tick()` (added to `ensureTimerRuntime`) fires
  every already-due timer, earliest-first, reschedules repeating ones, and
  returns without sleeping;
- an internal `webview_bind("__kml_tick", @__kml_wv_pump, handle)` whose handler
  calls `__kml_timer_tick` + `__kml_task_sched_step` + `__kml_drain_microtasks`
  then resolves;
- `webview_init` injects `if(!window.__kml_pump){window.__kml_pump=setInterval(
  () => window.__kml_tick(), 16)}` — the page is the timer source.

**Async `bind`.** When a bound callback's return type `IsPromise`, the bind
thunk does not `webview_return` synchronously — it copies the call `id` (owned by
webview only during the callback), builds a `{ promise, w, id }` env, and
registers a `@__kml_wv_return_runner` reaction (the `emitPromiseAdopt` pattern).
The runner reads the settled promise's state/value and calls
`webview_return(w, id, 0, value)` (fulfilled — value is the JSON string) or
status 1 (rejected). Settlement is driven on the GUI thread by the pump's
microtask drain.

## Implementation notes

- The pump calls `__kml_timer_tick`/`__kml_task_sched_step`/
  `__kml_drain_microtasks` unconditionally, but their real definitions are
  gated on feature use and the existing stub block (`emitLoopTaskStubs`) only
  ran under `usedHTTP`. Added a webview-guarded stub block *above* that early
  return, emitting a no-op for each symbol the HTTP path does not already stub
  (guarded on `!usedHTTP`) so nothing is defined twice.
- Async bind is **`Promise<string>`** in V1 (the value slot is passed straight
  to `webview_return`); a non-string resolution has no JSON encoding yet.

## Side effects discovered

Typed `bind` (auto-JSON-decode declared params / encode return) — the third
Stage 3 bullet — is **not** in this ADR; it is additive ergonomics that pairs
with the Stage 5 `bindings`-object surface (both want natural signatures), and
is tracked there. The hard architectural piece of Stage 3 (event-loop
coexistence) is what this delivers.

## Verification

- macOS (Apple Silicon M4), windowed, by hand + gated tests:
  `TestE2EWebviewPumpSmoke` (a `setInterval` ticks 3× on the GUI thread with no
  Worker, then `terminate()`s) and `TestE2EWebviewAsyncBindSmoke` (a bound
  `async` callback's `Promise<string>` settles and its value reaches the page's
  `.then`, reported back to native) both pass under `KML_WEBVIEW_SMOKE=1`.
- Compile-tier `TestE2EWebviewPumpCompiles`/`…AsyncBindCompiles` run everywhere.
- Linux: compile-tier only, not yet run.
