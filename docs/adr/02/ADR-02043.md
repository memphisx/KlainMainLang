# ADR-02043: A prototype object per class evaluation; replaced methods

- **Date**: 2026-11-22

## Context

- Each evaluation of a class expression (or of a class declared in a
  function) is a class of its own, a record (TDD-00242). All of them
  shared one `prototype` object. A record whose class captures nothing
  did not even bind its instances.
- `C.prototype.m = f` (or `delete C.prototype.m`) did not change what
  `c.m()` runs, for any class.

## Decision

- `__kml_classrec_proto(rec, shared)` (unitreg.c) makes a record's own
  prototype on first use. It copies the shared object's own properties,
  gives each method a record of its own (`__kml_dynobj_clone_methods`),
  sets `constructor` to the record, and keeps the shared parent.
  `C.prototype` reads, a class value's `prototype` and
  `Object.getPrototypeOf(instance)` take the record in scope
  (`emitClassProtoFor`).
- An instance of a record class capturing nothing is bound to its record
  too.
- A method call that the program may replace (it writes a member of that
  name) checks the class's prototype after the instance's own
  properties: `__kml_proto_method_now` reports a value other than the
  class's method (a cloned record counts as the class's own). That value
  is called with the instance as `this`.

## Consequences

- Tests: `TestE2EClassPerEvaluationPrototypeJS`,
  `TestE2EClassPrototypeMethodReplacedTS`.
