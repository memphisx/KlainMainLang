# ADR-01437: Element and record reads bound to a local keep their absence

- **Relations**: Implements TDD-00230 (P2.2), Extends ADR-01431
- **Date**: 2026-10-07

## Context

The third shadow bucket after ADR-01434 (1556 rows; `kml_url.ts`,
`internal_util_inspect.ts`, `kml_encoding.ts`) was a local bound from an
element read whose possible absence codegen and the checker's answer
disagreed on:

- `const b = bytes[i]` read as plain `number` in some places and as the
  element read's `number | undefined` in others;
- `const nb = j < n ? bytes[j] : -1` and `const alias = colorAliases[name]`
  (a `Record<string, string>`) held as possibly undefined by codegen only.

## Investigation

- Codegen binds `const b = a[i]` with the read's `T | undefined`
  (TDD-00187). A body pre-pass that reads `b` before the declaration is
  emitted (`crossTypeWidenedBindings` for `cp = b & 0x1F`) took ADR-01431's
  checker fallback, which has no element-read rule, so the same name read
  as two types in one function.
- The checker's answer applied the element-read rule only to a direct array
  read. Codegen also keeps the absence through a conditional whose other
  branch is a present number, and for a string-keyed record's value (a
  missing key reads `undefined`; an array value's absence is a null array).

## Decision

- The unbound-name fallback applies the element-read rule, so a pre-pass
  sees the type the declaration binds.
- The checker's answer applies it through conditionals (against a present
  scalar) and to string-keyed record reads, with an array-valued record
  read nullable.

## Verification

- `TestE2EElementReadLocalAbsence` (against Node) and the record,
  conditional, element-read, `TextDecoder` and inspect tests pass on the
  Mac.
- The probes' shadow rows are gone.
