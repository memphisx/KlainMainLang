# ADR-01937: Runtime files with libraries are linked by symbol too; CompressionStream takes any BufferSource

- **Relations**: Implements TDD-00230, Extends ADR-01935, Extends ADR-01936
- **Date**: 2026-10-28

## Context

ADR-01935 linked the runtime files that need no library by the symbols a program names. Each file that brings a library (zlib, OpenSSL, nghttp2, the Windows IP helper) still sat behind a usage flag that codegen had to set. Moving the zlib stream unit across turned up two bugs in `CompressionStream`/`DecompressionStream`.

## Investigation

- Finding a library runs `pkg-config` or `brew --prefix`, uncached. Running that for every program, so that each unit's symbol table could be read, would slow down every compile.
- **A chunk that reached the zlib transform as `any` was dropped.** That covers a chunk from an untyped `ReadableStream`, or one written through `getWriter()`. The transform read the (boxed word, 0) pair as (data, length 0). So `stream.pipeThrough(new CompressionStream("gzip"))` from `new ReadableStream({ start(c) { c.enqueue(bytes) } })` compressed nothing, and a round trip printed an empty string. An `ArrayBuffer`, a `DataView` or a string chunk was dropped the same way. Node takes all of them; it takes a string as its UTF-8 bytes.
- **A format not written as a literal was a compile error.** Node checks the format at construction and throws `TypeError` `ERR_INVALID_ARG_VALUE` ("Failed to construct 'CompressionStream': 1st argument 'x' is not a valid enum value of type CompressionFormat.").

## Decision

- **A runtime file that brings a library is a `libUnit`** (`runtime_resolve.go`):
  - Its symbol table is cached by its source alone. Its library is located only to compile it for that table, or when the link takes it.
  - If the library is not installed, the table is empty, so nothing pulls the unit in.
  - The resolver pulls a library unit only for a symbol nothing else defines, never to replace a weak default. A program pays for a library only when it calls into it.
  - A unit's `LinkLibs` names (zlib's `z`) are added when it is pulled. `LinkLibs` resolves the sources first, so the drivers may call it in either order.
- **Moved to library units:**
  - The zlib stream, TLS, HTTP/2 (nghttp2) and os-info files.
  - fetch (libcurl), timers and the event loop (libuv), the selected BigInt and crypto backends, c-ares and h2o.
  - The thread pool stays gated: per-program defines (`KLAINPOOL_ZLIB`, `KLAINPOOL_SQLITE`) change its symbols, and a table cached by source alone cannot hold both. Their `Uses*` gates, their `used*` flags and their declarators (`ensureZlibStreamRuntime`, `ensureNativeTLS`, `ensureH2Natives`, `ensureOSInfo`) are deleted. So is the thread pool's dependency entry for os-info; the resolver follows that reference.
- **The zlib transform takes a boxed chunk:** a typed array or Buffer, an `ArrayBuffer`/`SharedArrayBuffer`, a `DataView` window, or a string's UTF-8 bytes.
- **A compression format known only at run time** is checked by `__kml_zs_wbits`. One that is no `CompressionFormat` throws Node's `TypeError` and message.
- Four stubs that were IR text in Go become weak defaults in `hooks.c`: `__kml_fetch_pump`, `__kml_worker_curl_preinit`, `__kml_worker_abort_check` and `__kml_pool_job`. The strong `__kml_worker_curl_preinit` moves into `fetch.c`.
- More IR text in Go moves to C:
  - The class-reference dispatchers (`__kml_classref_shown`/`nstatic`/`skey`/`sget`/`get`/`set`, `__kml_dyn_instanceof`, `__kml_ctor_kind`, `__kml_constructor_of`) are `hostbox.c`'s now, reading the same unit rows; they leave the hook table.
  - `__kml_dyn_construct` gets its own `dynconstruct.c`, linked only when a program constructs through `any`. That is because it needs `fnmeta.c` and the emitted fail path, which becomes a plain function.
  - The stubs for a program without a boxed host value (`__kml_host_inspect`/`tojson`/`tag`/`class_tag`/`toprim`) are deleted: `hostbox.c` finds no row and answers the plain object's forms.
  - The `__kml_promise_inspect_parts` and `__kml_unhandled_report` stubs fall to hooks.c's defaults. The promise default now answers -1 (no promise) instead of 0 (pending), and the report default is a no-op instead of a missing-hook abort.
- Generated IR text drops further, and `TestIRTextOnlyShrinks` now counts `funcDef` wrappers as well as literal `define` text:
  - `objextra.c` holds a static object's added-property reads (`__kml_obj_has_extra`, which now answers an `int`; `inspect_dyn`, `json_dyn`; `keys_dyn`, which writes through an out-slot instead of returning an aggregate).
  - `promisebox.c` holds the boxed-promise wrapper recognizer and its inspect parts. They compare against `__kml_promise_box_hdr`, a per-program value hooks.c holds and the program's constructor stores, and they leave the hook table.
  - Both are library units without a library: the program names a marker (`__kml_obj_extra_on`, `__kml_promise_box_on`) when it needs the real forms, and otherwise hooks.c's weak defaults answer. A library unit never replaces a weak default on its own.
  - `__kml_shape_keys_array`'s wrapper goes: its one caller writes through `__kml_shape_keys_array_c` directly.
  - The island exports `_state`, `_error` and `_next_deadline_ns` move from per-island generated text into `island.c` under fixed names. The watcher reads a missing `state` as fulfilled, which is the case for an island without a top-level await.
  - `__kml_native_entry_path` becomes `entrypath.c`, which reads `__kml_entry_path`, another per-program value in hooks.c (`TestRuntimeSymbolsResolveWithinRuntime` keeps every symbol the runtime names defined within the runtime).
  - `__kml_error_inspect`'s fallback stub falls to hooks.c's default, which now answers `[Error]` instead of null.
- The emitter sheds the state symbol linking made dead:
  - 165 `used*`/`uses*` flags that were never read, or only ever assigned, are deleted.
  - Four declare-once helpers (`ensureDtoa`, `ensureCurrentRSS`, `ensureJSONParseTree`, `ensureBufferCodecs`) are deleted. After the flag removal they did nothing, or emitted only plain `declare` lines.
  - About 80 plain `declare` lines go too, because the call-site declarator synthesizes them. Variadic and attribute-carrying declarations (`curl_easy_setopt`, `setjmp`'s `returns_twice`, `longjmp`'s `noreturn`, `zeroext` returns) stay explicit.
- A library unit whose library is absent fails its locate step (h2o without libh2o), so its table is empty instead of a failed compile.
- Repeated `ensure*` calls inside one function, left by ADR-01936's inlining, are reduced to the first.
- The empty `emit_bytes_input.go` is deleted.

## Verification

- `TestE2EStreamsCompressionBufferSourcesAndRuntimeFormat` covers every chunk kind, the run-time format, and the invalid-format error.
- The 172 saved probes match Node v24, with the known differences of ADR-01935.
- `KML_RESOLVE_TRACE=1` on a `console.log` program pulls no library unit, and the binary links neither libuv nor libcurl. An `os` program pulls `osinfo` by symbol. A timers program pulls `loop` and `timers` and links no libcurl. A `dns` program pulls `cares`, and a `crypto` program pulls `crypto`.
- Targeted streams, TLS, HTTP/2 and os suites run on the Mac (Apple Silicon).

## Addendum: the loop without libcurl, and fetch's Request and Response gaps

Context:
- The event loop and the task runtime declared fetch's runtime, so every program with a timer linked libcurl.
- `fetch("data:…")` rejected with "fetch failed".
- Reading a Response's `url` or `redirected`, or an unmodeled `Request` member (`mode`, `cache`, `signal`), boxed the host object as a dynamic one and recursed until the stack overflowed.
- `console.log` of a Response or a Request printed raw memory or crashed.
- Reading a fetched Response's body cleared its pending-fetch handle, so its headers and status text read afterwards were empty.
- `bytes()` and `blob()` were compile errors.

Decision:
- The loop and the task runtime no longer declare fetch. `hooks.c` gives weak defaults for what the loop calls into fetch for (`__kml_curl_inflight`, `__kml_curl_kick`, `__kml_curl_drain_messages`, `__kml_group_satisfied`). `ensureFetch` links the loop itself.
- **A `data:` URL** is answered in `fetch.c` without a transfer. The Fetch standard's data-URL processor gives its MIME type (`text/plain;charset=US-ASCII` by default) and its percent- or base64-decoded bytes. The pending fetch is already done, with a 200 status line and a Content-Type header. A malformed one fails as a network error.
- The transfer's buffer keeps the effective URL and the redirect count. **`Response.url` and `.redirected`** read them; a constructed Response has `""` and `false`.
- **A Request carries every init member:**
  - `cache`, `credentials`, `mode`, `redirect`, `referrerPolicy`, each checked against its enum with undici's message (`request.c`), and navigate mode rejected.
  - `only-if-cached` needs same-origin mode.
  - `referrer` must be a URL, `""` or `about:client`.
  - `destination`, `integrity` and `keepalive`.
  - Its `signal` follows the init's (`AbortSignal.any`), or is a fresh one. `fetch(request)` honors it and sends the body's real byte count.
- A member a Response or Request layout lacks, that no intrinsic serves, is a compile error instead of a dynamic read of a host object.
- `util.inspect` renders a Response and a Request as Node's accessor list.
- The body drive keeps the pending handle.
- `bytes()` is a `Uint8Array` over `arrayBuffer()`'s bytes; `blob()` is a `Blob` typed by the Content-Type.

Verification:
- `TestE2EFetchDataURL`, `TestE2EFetchResponseURLRedirectedInspect`, `TestE2EFetchRequestInitMembersAndSignal` and `TestE2EFetchBodyBytesBlobAndHeadersAfterBody` compare against Node v24 on the Mac.
- A timers-only program links no libcurl (`otool -L`).
