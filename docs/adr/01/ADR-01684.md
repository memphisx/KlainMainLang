# ADR-01684: `@lowerType` on a class declaration

- **Relations**: Implements TDD-00255, Extends ADR-01683
- **Date**: 2026-10-17

## Context

TDD-00255 Stage 3: a class declared `/** @lowerType <layout> */` has instances that C code builds, filling the fields it owns, so the library makes no copies. `HttpRequest` is the first user: the h2o backend built it in TypeScript from strings it read back through natives. `@lowerType` already existed on interfaces and type aliases, naming one of the fixed native layouts (`lowerLayouts`); classes had no form of it. The parser read no JSDoc for a class at all.

## Decision

**Parsing.** `parseClassDecl` takes the class's pending JSDoc, as the interface path does, and records `@lowerType` as `ClassDeclaration.LowerType`.

**The layout is exported, not mirrored.** A C struct copied by hand would drift from the class the moment a field moved. Instead, the code generator exports the class's layout under the layout's name, as `weak_odr` constants: every unit that registers the class emits the same values, and unlike `linkonce_odr` they are kept when nothing in their own unit reads them:

- `__kml_lt_<layout>_size`: the instance's byte size;
- `__kml_lt_<layout>_tag`: the header word;
- `__kml_lt_<layout>_vtable` and `_vtable_at`: the method table and its offset, for a class whose tree overrides a method (`HttpRequest`'s does), else null and 0;
- `__kml_lt_<layout>_<field>`: each field's byte offset. A private `#x` is `priv_x`. Field 0 and the vtable word are left out.
- `__kml_lt_<layout>_init`: a pointer to the class's field initializers.

C declares only the ones it reads, as externs, so renaming or removing a field the backend fills breaks the link instead of the memory. Offsets come from `Type.FieldOffset`, which uses the same rules as `StructSize`.

**Field initializers.** C builds the instance with `calloc` (the collector's allocation under `-mm=gc`), stores the header word and any method table, and calls `init`. A first version left the method table out: the instance linked and then crashed at its first method call. `init` is a synthesized private method, `__kml_lt_init`, whose body is the class's field initializers (`classFieldInitStmts`). It compiles like any other method, so a library class's method stays in the library's own unit. That is why `init` is a function-pointer constant rather than an alias: an alias must point to a definition in the same unit.

**Restrictions.** A `@lowerType` class cannot extend another class or be generic, since C builds the whole instance. Either is a compile error.

**Entry points return the class.** A `@lower` native whose result is a `@lowerType` class returns the instance pointer, typed as the class. A library class is typed through its ambient declaration (`node.d.ts`'s `interface HttpRequest`), so the class is found by that name (`lowerTypeClassRepr`).

**`HttpRequest`** is `/** @lowerType kml_khttp_req */`.
- On the h2o backend, `khttpH2oRequest(id)` builds it, filling `method` and `path` (the target before its `?`) straight from h2o's request.
- TypeScript then calls `_adopt(resume, query, headers)`, which parses the query (`khttpH2oReqString(id, 3)`, the target after `?`) and sets the headers map it built.
- The method and path cases of `khttpH2oReqString` are deleted.
- The native backend is TypeScript over the parser natives and still constructs requests with `new`.

## Verification

- Tests:
  - `TestLowerTypeClassExportsLayout`: the exported symbols and offsets, and the class still behaving as written;
  - `TestLowerTypeClassRejectsExtends`.
- Mac: own keys, `JSON.stringify` and inspect output of a `@lowerType` instance match Node; the native `klain:http` tests pass.
- Linux x86-64 (Node304): `make test-h2o`, where every request is built in C.
