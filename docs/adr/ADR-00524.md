# ADR-00524: Link libm for `roundeven` intrinsic and Yoga on Linux

- **Relations**: Extends ADR-00034, ADR-00313
- **Date**: 2026-08-31

## Context

CI (Release workflow, glibc/x86-64) failed the `go test` lane with two
distinct linker errors, both invisible on the macOS dev machine:

- `TestE2EUint8ClampedArray`: `undefined reference to 'roundeven'`.
- `TestE2ETui*` (RenderFrame, FlexJustify, WideCharWidth, ListViewport):
  `yoga_algorithm_pixelgrid.o: undefined reference to symbol 'round@@GLIBC_2.2.5'
  / DSO missing from command line`.

Both features were verified only on macOS at the time they shipped
(ADR-00313 explicitly flagged `llvm.roundeven.f64` as "Linux unverified"); the
TUI/Yoga work landed the same way.

## Investigation

Same macOS-vs-Linux link gap as ADR-00034: macOS's `libSystem` folds libm's
symbols in with libc, so no explicit `-lm` is ever needed there, while glibc
keeps libm as its own shared object that clang's default link step does not pull
in.

- The `Uint8ClampedArray` store path (`emit_arraybuffer.go:146`) emits
  `call double @llvm.roundeven.f64(...)`. On Linux this intrinsic lowers to a
  libm `roundeven` call rather than expanding inline, so libm must be on the
  link line — but `ensureRoundEven` never called `requireLink("m")`.
- Yoga's pixel-grid rounding (`yoga_algorithm_pixelgrid.o`) references libm
  `round`; the prebuilt-objects link list in `yoga.go` carried only the C++
  runtime, not `-lm`.

## Decision

Name libm explicitly in both paths, unconditionally (harmless no-op on macOS,
matching ADR-00034's rationale — no `GOOS` branch):

- `ensureRoundEven()` now calls `e.requireLink("m")`.
- Yoga's `libs` list appends `"-lm"` alongside the C++ runtime.

## Implementation notes

- `codegen/llvm/emit_arraybuffer.go`: `requireLink("m")` in `ensureRoundEven`.
- `codegen/llvm/yoga.go`: `-lm` added to the prebuilt-object `libs` slice.

## Verification

- macOS (darwin/arm64 dev machine): `go build`, `go vet ./codegen/llvm/`, and
  `go test ./tests/ -run 'TestE2ETui|TestE2EUint8ClampedArray'` all green
  (expected — `-lm` is a no-op there).
- Linux (glibc, Docker `golang:latest` on the Mac): the two representative
  previously-failing tests `TestE2ETuiRenderFrame` and `TestE2EUint8ClampedArray`
  now pass — confirming the fix on the actual failing platform.
