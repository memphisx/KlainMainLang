# ADR-01641: An absent optional function passed across function types stays undefined

- **Relations**: Extends [TDD-00229](../../tdd/TDD-00229.md)
- **Date**: 2026-10-16

## Context

`net.Socket` gained a `write` override (Node's `writeAfterFIN`,
[ADR-01642](ADR-01642.md)) that passes its optional `cb` on to
`Writable.write`. Every plain `s.write('x')` then crashed with SIGSEGV in
`afterWrite`, which called a null callback through `__kml_fnadapt.*`.

The repro without the library: a subclass method with
`cb?: (e?: Error | null) => void` calling `super.write(chunk, encoding, cb)`
where the base declares `cb?: (e?: any) => void`, called with no callback.
The base sees `cb !== undefined`, picks it over its `cb ?? nop` default, and
the later call jumps to address 0. Node runs it and prints the callbacks.

## Investigation

The two function types differ, so the call site converts the argument with
`emitClosureAdapter` (`codegen/llvm/emit_func_adapt.go`), which builds a new
closure header `{adapter, original}`. An absent function is a null header
pointer, and `cb === undefined` is `icmp eq ptr %cb, null`. The adapter
was built around the null pointer, and the new header is not null, so the
absent function became a present one that calls nothing.

## Decision

`emitClosureAdapter` returns `select (orig == null) ? null : header`: an
absent function stays absent across the conversion. The header is still
built unconditionally (a small allocation on that path). Splitting the
block to skip it would complicate every caller's control flow.

## Implementation notes

`codegen/llvm/emit_func_adapt.go` (`emitClosureAdapter`). The boxed path
(`emitBoxedClosureAs`) already maps an undefined box to a null closure.

## Side effects discovered

None.

## Verification

Apple Silicon Mac: `TestE2EAbsentCallbackThroughAdapterIsUndefined` (new, against Node)
and the net/TLS/dgram suites pass. Linux x86-64 (DeskMini): `make test-par`.
