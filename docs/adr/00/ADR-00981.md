# ADR-00981: Node `writable.write`/`end` accept `encoding` and a completion callback

- **Relations**: Extends ADR-00449, ADR-00483
- **Date**: 2026-09-16

## Context

Node's `writable.write(chunk[, encoding][, callback])` and
`writable.end([chunk][, encoding][, callback])` both take an optional string
`encoding` and an optional completion `callback` after the chunk. This
compiler's Node `Writable` accepted only the bare one-argument forms
(`write(chunk)` / `end(chunk?)`); a second or third argument was a clean
rejection. A portable app that passes `res.write(data, 'utf8', cb)` or
`stream.end(cb)` — extremely common shapes — failed to compile.

Chunks are already strings in this model (ADR-00449), and a non-`utf8` encoding
is a documented rejection (`setEncoding`, ADR-00483). The one genuinely missing
piece was the completion callback, which Node invokes once the chunk is handled
(next-tick delivery). A microtask queue already exists (`process.nextTick`,
`__kml_microtask_enqueue`), so the callback can be delivered faithfully.

## Decision

Accept `write(chunk[, encoding][, callback])` and
`end([chunk][, encoding][, callback])`:

- A trailing string literal (after the chunk) is the `encoding` — `'utf8'` /
  `'utf-8'` only; any other value is a clean rejection.
- A trailing function is the completion callback, enqueued onto the microtask
  queue after the write/close so it fires after the current synchronous run, in
  write/end order — matching Node's next-tick callback delivery.
- The callback is a `() => void` (the same restriction as `process.nextTick` and
  the timers). Node passes `err` as the first argument, which is `null` on the
  success path taken here, so a zero-argument callback observes nothing lost. An
  `(err) => …` callback is rejected rather than silently mis-shaped.

## Implementation notes

- `codegen/llvm/emit_node_stream.go`: new `streamWriteExtras` helper parses the
  post-chunk `[encoding][, callback]` tail for `write`. `end` parses its own tail
  inline because its chunk is *also* optional (`end(cb)`): a trailing
  function-typed argument (detected via `inferExprType(...).IsFunc`, no codegen)
  is peeled off as the callback first, then a remaining post-chunk string literal
  is the encoding. Both paths enqueue the callback via
  `ensureMicrotasks` + `@__kml_microtask_enqueue`.
- No runtime or ABI change: the callback reuses the existing microtask path and
  `timerCallbackPtr`.

## Side effects discovered

None. The pre-existing asynchronous delivery of the user-provided `write()` sink
(a chunk pushed in `new Writable({ write })` becomes visible after the current
run, not synchronously) is unchanged — this ADR only adds the *completion*
callback and encoding parsing, not the sink timing.

## Verification

- `go build` + `go vet ./codegen/llvm/` clean.
- Callback ordering byte-matches Node (`write('a','utf8',cb)`, `write('b',cb)`,
  `end('c','utf8',cb)` fire cb-a/cb-b/cb-end after the synchronous run) on macOS
  arm64 (M4).
- New E2E tests `TestE2ENodeStreamWriteEndCallbacks` and
  `TestE2ENodeStreamWriteBadEncodingRejected`; `examples/streams/node_stream.ts`
  extended and runs.
