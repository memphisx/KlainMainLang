# ADR-00572: URL component setters

- **Relations**: Supersedes the setter-rejection half of ADR-00465
- **Date**: 2026-09-01

## Context

`URL` stored its components (`href`/`protocol`/`host`/`hostname`/`port`/
`pathname`/`search`/`hash`/`origin`/`searchParams`) as fields derived from one
libcurl parse. A component *setter* (`url.hash = …`) was a clean compile
rejection (ADR-00465), because a bare field store would update one field while
leaving every other derived field — and `href`/`origin` — stale. Construction
was the only way to change a URL.

## Decision

Implement setters by re-parsing and re-deriving, so the object never desyncs:

1. Refactor the field-derivation tail of `emitNewURLExpression` into
   `deriveURLFieldsIntoObject(handle, objReg)` — reads every part out of a
   parsed `CURLU` handle and stores the derived fields into a given object.
2. `emitURLComponentSet(objVal, property, rhs)`:
   - **`href`**: seed a fresh handle with the new value via
     `curl_url_set(CURLUPART_URL, …)`; an invalid value throws a catchable
     `Error` ("Invalid URL"), matching Node.
   - **other components** (`protocol`/`hostname`/`port`/`pathname`/`search`/
     `hash`): seed the handle from the object's current `href` (valid by
     construction), then `curl_url_set` the one changed part. A failed part-set
     is ignored — the handle keeps the original URL, so re-derivation reproduces
     it unchanged, matching Node's silent-ignore leniency for a bad component.
   - Re-derive **all** fields (including a freshly re-populated `searchParams`
     map) into the same object via `deriveURLFieldsIntoObject`.

Marker normalization matches Node: a leading `#` on `hash`, a leading `?` on
`search`, and a trailing `:` on `protocol` are stripped before handing the value
to curl (`url.hash = "#x"` and `url.hash = "x"` behave identically). A compound
assignment (`url.hash += …`) is a clean rejection.

## Scope

`host` (the combined `hostname:port`), `username`, and `password` setters are
not wired yet (curl has the parts; the value-splitting/derivation just isn't
done) — set `hostname`/`port` separately. Disclosed as the row's residual
caveat.

## Verification

New `TestE2EURLComponentSetters` (every wired setter, marker normalization,
`searchParams` re-derivation, `href` re-parse), `TestE2EURLHrefSetterInvalidThrows`
(invalid `href` throws, other state intact), and
`TestE2EURLComponentCompoundAssignmentRejected`; outputs compared byte-for-byte
against real Node v26. The existing URL/URLSearchParams suite still passes (the
derivation refactor is behavior-preserving). Built and verified on Mac (Apple
Silicon).
