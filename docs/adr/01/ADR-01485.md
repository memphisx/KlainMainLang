# ADR-01485: Object.assign onto an array

- **Relations**: Extends ADR-01237
- **Date**: 2026-10-09

## Context

BACKLOG 111: `Object.assign([], xs)` was a compile error ("Object.assign's
target must be an object"). BACKLOG 108 listed `.buffer` on a
`TypedArray | DataView` union as a codegen error.

## Investigation

- The run-time copy (ADR-01237) already handles an array held as `any`
  (`Object.assign(t as any, xs)` writes the indices onto the array itself
  and grows it, as in Node). The static path only took struct targets.
- Writing through the box grows the array's shared header, but a literal
  target's `{ptr, len}` value had already been read, so `Object.assign([],
  xs)` printed `[]`.
- `v.buffer.byteLength` with `v: Uint8Array | DataView` compiles and
  matches Node (macOS). BACKLOG 108 was stale.

## Decision

- An array target (not a typed array or Buffer) goes through the run-time
  copy onto the array itself. The result is the target, re-read through
  its box so a grown length shows, and keeps the array's type. An empty
  literal target takes an array source's type.
- BACKLOG 108 and 111 are deleted. The status caveat "an array target is
  a compile error" is removed.
