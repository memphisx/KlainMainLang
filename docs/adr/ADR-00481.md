# ADR-00481: `for (const [k, v] of map)` decomposes entries

- **Relations**: Clears [ADR-00011](ADR-00011.md)'s values-only caveat
- **Date**: 2026-08-29

## Context

The oldest surviving caveat in `docs/status`: a Map's `for...of` iterated
values only, so the ubiquitous `for (const [k, v] of map)` idiom didn't
decompose — one of the most common real-JS patterns there is.

## Decision

`emitForOf` gains a dedicated entries path: a two-plain-name array
pattern (no holes/rests/nested sub-patterns) over a Map-typed iterable
builds the runtime's keys and values arrays — both emitted in the one
insertion order — and drives a parallel index loop binding `k`/`v` per
iteration, with the standard break/continue/labeled targets. Everything
else (bare variable, Sets, non-Map iterables, other pattern shapes)
keeps the existing behavior — a bare `for (const v of map)` still
iterates values, the documented deviation that remains.

## Verification

Mac. `tests/collections_test.go` E2E (string- and number-keyed maps,
plus the unchanged bare-variable values iteration) and the
`examples/map/map.ts` extension pass; Map/Set/for-of/destructuring
batches green. TS oracle 5296 → 5298; Node oracle unchanged (40).
