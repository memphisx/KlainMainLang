# ADR-01849: Erased generic classes and single-rest tuples stay typed

- **Relations**: `Implements TDD-00230` (P3.3: the checker answers what inferExprType did)
- **Date**: 2026-10-21

## Context

- Code generation compiles some generic classes as ordinary ones: one whose type parameters type only overload signatures (`eraseTypeOnlyGenerics`), or one that takes part in inheritance (`eraseInheritingGenerics`). It did this by clearing the class node's type parameter list. The checker reads the same node, lazily, after that pass. So it saw `class EventEmitter` with no `T`, and every member naming `T` came back unanswered.
- The checker's tuple type has no variadic element. A tuple type node with a rest or optional member was left unanswered.
- `lib/node/events.ts` declares `type AnyRest = [...args: any[]]` for the event-map typing. The `EventEmitter` overloads (`emit<K>(eventName: Key<K, T>, ...args: Args<K, T>)` and the listener forms) all reach it. So every `EventEmitter` method that has an overload was unanswered (`emit`, `on`, `removeListener`, `listenerCount`, …), on the class and on every subclass (`Stream`, `Socket`, …), in every program.
- `dottedType` returned unanswered for a callee rooted at anything other than a dotted name (`/re/.test(p)`, `f().g()`). tsc's `getTypeOfDottedName` returns undefined there, so such a call is never an assertion. Because of this, a conditional like `/^\/[A-Za-z]:/.test(p) ? p.slice(1) : p` made `p` unknown.

## Decision

- Erasure keeps the list as written in the class node's `Declared` field. The binder and the checker read a class's type parameters through `DeclaredTypeParams`, so they see the class as it was written. Code generation still sees it erased. The oracle maps an instance of an erased class to that one class, whatever its type arguments.
- A tuple type node whose only element is a rest over an array (`[...args: T[]]`, `[...T[]]`) is that array type, as tsc normalizes it. A rest over anything else, and any longer variadic tuple, is still unanswered.
- `dottedType` answers `any`, meaning no guard, for a callee root that is not a dotted name.
- In the oracle (`shadow_binder.go`):
  - A conditional the checker leaves unanswered joins its two branch answers the way `emitConditional` does.
  - An array literal the checker leaves unanswered either takes an annotated binding's declared array type or joins its element answers (`mixedArrayElem`, `mixedKindsBoxed`).
  - A call of a declared function whose annotated result is a union the repr refuses (`boolean | Error`) takes the annotation's representation, as emission registers the result.
  - An unanswered read of an unannotated binding stored once, by its initializer, reads what that initializer is held as. This covers narrowing to an unrepresentable type or to `never`.
  - `+` with a string or template literal operand is a string when the checker leaves it unanswered (`label + " getter"`).
  - `&&`/`||` with an operand held as a box is a box, the other operand boxed into it (`shortCircuitValueType`'s dynamic arm).
  - The checker's `object` is the box, as `resolveType` holds it.
  - The switch-path oracle (`reprOracle`) gets the `nodeJS` hook the shadow oracle has, so `NodeJS.Timeout` maps to the lib's `Timeout` class.
  - `ReadableStreamReadValueResult<T> | ReadableStreamReadDoneResult<T>`, the expansion of the `@lowerType` alias `ReadableStreamReadResult<T>`, maps to that alias's read-result layout.
  - The empty type literal `{}`, alone or as a union member (`AddressInfo | {}`), is the box `resolveType` gives it.

## Consequences

- `TestCodegenErasedClassKeepsTypeParams` covers the erased class.
- `TestSingleRestTupleIsArray` covers both tuple forms and an overload over one.
- Verified on Apple Silicon (checker package; targeted events, stream, generic, inheritance, tuple, conditional and mixed-array E2E tests).
