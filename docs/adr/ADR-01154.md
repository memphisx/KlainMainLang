# ADR-01154: `events` declared; EventEmitter as TypeScript and Node have it; builtin imports typed from their declarations

- **Relations**: `Implements TDD-00230` (Phase 3, P3.1, P3.3); `Extends ADR-01148`, `ADR-01152`
- **Date**: 2026-09-25

## Context

P3.1 continues with the network modules, `events` first. A tsc run over
every example and app (393 programs, tsc 5.6.3 `--strict`, @types/node)
showed that `EventEmitter` compiled only in forms TypeScript rejects:

- a bare `EventEmitter` with no import (TS2304);
- `EventEmitter<string>`, one payload type for every event (TS2344);
- event maps with non-tuple values (`{ progress: number; done: void }`);
- subclass constructors with no `super()` (TS2377, TS17009).

The forms TypeScript accepts did not compile: `super()` in a subclass
("EventEmitter has no constructor to call"), `extends EventEmitter` with
no type argument ("expected exactly 1"), and a tuple map value `[]`
("an empty tuple type '[]' is not supported"). The status page
described the non-TypeScript forms as working features, with no caveat.

`EventEmitter` is no global in ECMAScript, Node or the web platform. The
web's event type is `EventTarget`. `Readable`, `Writable` and the other
module-only builtins compiled without an import too.

## Investigation

- **Why the non-TS forms existed.** Codegen's EventEmitter carried one
  payload type `T` per emitter (`resolveEventPayload`). A scalar `T` gave
  every event one argument, an object `T` was a map, and a tuple `T`
  meant several arguments. Listeners were stored as closure headers
  called with the payload's static signature.
- **One representation per type (P3.3).** Keeping typed and untyped
  emitters on different listener representations (closure headers in
  one, dynamic function records in the other) would break the moment an
  `EventEmitter<{…}>` flowed into an `EventEmitter` parameter, which
  TypeScript allows. So every emitter stores dynamic function records
  (`emitDynClosureAdapter`) and `emit` calls them through the dynamic
  ABI. The event map now only drives checking and parameter hints.
- **@types/node's EventEmitter** types listeners through conditional
  types over the map (`Key`, `Args`, `Listener`). The checker does not
  model conditional types, `keyof` or indexed access, so the declaration
  gives every event `...args: any[]`, the default map's shape.
- **Typing a builtin import.** The resolver erases imports from builtin
  modules, and the checker only exempted their names from TS2304
  (ADR-01152). It never typed them from the `declare module` block.
- **`extends` a value with construct signatures** (`Error`, `Map`, the
  declared `EventEmitter`). `baseInstance` returned nil for any base
  that is not a class symbol. The comment said this "waits for the
  declaration-driven library, P3".
- **Found on the way:**
  - `tsc` reads `(): (number[]) => []` as an arrow returning `number[]`.
    Our parser read `(number[]) => []` as a function type with an
    unnamed parameter. The empty-tuple error had hidden this. TypeScript's
    `isUnambiguouslyStartOfFunctionType` requires a parameter name. In
    `(string) => void`, `string` is a parameter's name (TS7051 in strict
    mode), not its type.
  - Once `inferTypePredicates.ts` parsed, tsdiag showed 8 false positives.
    They came from TypeScript 5.5's inferred type predicates, which the
    checker did not implement.
  - Three more bugs, each fixed at its origin:
    - `instantiate` dropped a function type's `Overloads`, so any
      overloaded library method collapsed to one signature once
      instantiated for `this`.
    - A function type with a predicate result (`(v: T) => v is S`) was
      unanswered.
    - A plain primitive was not narrowable, so `string` never narrowed to
      `never`.
  - A closure with fixed parameters passed where `(...args: any[]) =>
    void` is expected was neither adapted nor hinted per position. The
    listener received the rest array as its first argument.
  - `removeListener` swapped the last listener into the removed one's
    place, reordering the rest, and `eventNames()` kept events with no
    listeners. Node does neither.
  - @types/node was pinned at 22.20.4 while the Node oracle is v24.
    `URLPattern`, a Node 24 global, was reported as TS2304.

## Decision

- **`lib/node.d.ts`** declares `events`:
  - `EventEmitter<T = any>` as an interface plus a
    `var EventEmitter: EventEmitterConstructor`, the pattern TypeScript's
    lib uses for `Map`;
  - `EventEmitterOptions`;
  - `once` and `on`.
- **`lib/es.d.ts`** adds:
  - `filter`'s type-guard overload to `Array` and `ReadonlyArray`;
  - `AsyncIterable`, `AsyncIterator` and `AsyncIterableIterator`.
- **Imports.**
  - The resolver records each builtin import's module and export name in
    `Program.BuiltinImportRefs`, mapping `import X from 'events'` to
    `EventEmitter`.
  - For an aliased import of a parse-time constructor it also records the
    canonical name, since the rename pass rebuilds `new EE()` under it.
- **Module-only constructors need their import.**
  - Sema maps `new X()` to a builtin only when X is imported, by name or
    as its module's namespace. This covers `EventEmitter`, the Node
    streams, `Agent`, `DatabaseSync`, `Channel` and `Webview`.
  - The checker reports TS2304 for an unbound bare `new X` or
    `extends X`. The parser now marks a qualified name (`Qualified`,
    `BaseQualified`) so `new stream.Readable()` is not taken for a bare
    name.
- **Checker.**
  - **Builtin imports** resolve through `builtinImport`, for:
    - a value identifier;
    - a `new` target;
    - a type reference;
    - an `extends` base.
  - **A base with construct signatures** gives the instance its
    signature constructs (`constructedBase`). A type parameter with no
    argument takes its default in `interfaceOf`.
  - **Inferred type predicates** (`inferredPredicate`) follow
    `checkIfExpressionRefinesParameter`:
    - The function has no return annotation, a boolean result and one
      return or an expression body.
    - A parameter that is never assigned is narrowed to T by the
      expression when true.
    - T narrowed by the false branch must leave `never`.
  - **Type guards in relations and overload picks.**
    - A type guard relates only to a type-guard signature with the same
      subject.
    - A context-sensitive callback for a guard parameter must itself be a
      guard, so `filter(x => x > 1)` takes the next overload.
  - **Smaller fixes:**
    - `instantiate` keeps overload sets.
    - Function types carry predicate results.
    - Primitives narrow.
    - An array of a union prints as `(string | symbol)[]`.
- **Codegen.**
  - **One emitter representation.** Every emitter stores dynamic
    function records. Untyped listener parameters are `any`, or the
    event tuple's elements on a typed map. `emit` boxes its arguments once
    and calls each record through the dynamic ABI, with the emitter as
    receiver. A `once` listener is removed before it runs.
  - **Payload rules.** A type argument must be a map whose values are
    argument tuples (`[]` for none). `EventEmitter<string>`,
    `EventEmitter<Error>` and non-tuple values are clean rejections.
  - **`super()`** in a subclass of `EventEmitter`, or of a class with no
    constructor, is a no-op. Constructor options are rejected.
  - **Unhandled `'error'`** throws an Error argument as is, and otherwise
    an Error reading `Unhandled error. (<value>)`.
  - **Removal.** `removeListener` removes the most recently added match
    and keeps the rest in order. The removal matches a record by identity
    or by its shared closure header. An emptied event is deleted from the
    map.
  - **`events.once` / `events.on`** on an untyped emitter resolve with
    the `any[]` arguments. The `events.on` helper takes the untyped
    `EventEmitter`.
  - **The dynamic closure adapter** now takes array and nullable
    parameters and keeps `any` rest elements boxed.
  - **The closure adapter** spreads a target's rest tail into fixed
    source parameters, reading undefined past its end.
  - **`contextParamHints`** types a closure's parameters per position
    against a rest signature.
  - **The `this` type** in a class body lowers to that class for code
    generation (`TypeAnnotationOfIn`).
  - **The empty tuple type** `[]` is a zero-length tuple.
- **Parser.**
  - Function types follow TypeScript's lookahead (`isFunctionTypeStart`).
  - An unannotated function-type parameter is `any`.
- **@types/node** is pinned to 24.13.6, matching the Node v24 oracle.
  `lib/tsglobals.txt` and `lib/nodemodules.txt` are regenerated.

## Implementation notes

- `codegen/llvm/emit_eventemitter.go`: the typed-closure `emit` and
  `emitBuildTuple` are deleted. `resolveEventEmitterListenerArg` stays for
  the Node-stream listeners, which keep their own lists.
- `codegen/llvm/runtime_eventemitter.go`: `__kml_ee_list_remove_at`
  (order-preserving), `__kml_ee_list_remove_dyn`, `__kml_ee_prune`.
- `eventsElemAnnotationName` must test `IsDynamic` before `i64`: an `any`
  is an `i64` box word, and the old order named it `number`.
- The `events.on` helper's generator is annotated `AsyncGenerator<…>`.
- `lib.go`'s module-type exemption (ADR-01152) stays for modules not yet
  declared.
- Rewritten to TypeScript forms and checked against Node:
  - the tests in `tests/eventemitter_test.go`, `TestE2ENewEventEmitterAsReturnValue`
    and `TestE2EModuleGlobalEventEmitter`;
  - `examples/eventemitter/*` and `examples/literal_expressions/literal_expressions.ts`.
- Two tests asserted rules TypeScript does not have:
  - `ListenerWrongArityRejected` is deleted.
  - `MultiArgWrongArity` is now `MultiArgFewerListenerParams`.
- `TestE2EClassExtendsUnknownClassIsError` now expects tsc's TS2304 text.

## Side effects discovered

- A missing argument read through a fixed `number` parameter is `0`, not
  `undefined` (the declared-type slot BACKLOG bug, P3.3).
- A lib interface lists only what this compiler implements, so it is
  partial and a member it lacks is not TS2339 (`emitter.nope()` falls to
  codegen). BACKLOG.
- Conditional types, `keyof` and indexed access are not modelled, so a
  typed event map is checked by codegen only. BACKLOG.
- The checker does not report TS2416 (an incompatible override) or TS7051.
- The tsc oracle and TypeScript's test corpus are pinned at 5.6.3;
  TypeScript 7.0.2 is current. Moving the oracle is the next step.
- The bespoke `process.execFileSync`, `process.readLineSync`,
  `fs.readFileSyncBytes` and `cluster.workerId` match no standard; they are
  deleted in the next change.
