# ADR-00653: `-compat=js` cross-type binding widening — untyped scalars that hold multiple kinds become the any-box

- **Relations**: `Implements TDD-00162` (the compat=js half; strict rejection is ADR-00651), `Extends ADR-00628` (the NaN-boxed any value)
- **Date**: 2026-09-03

## Context

ADR-00651 made the strict lane cleanly reject an incompatible scalar
reassignment (`let x = 5; x = 'hi'`). TypeScript-without-`noImplicitAny` — the
behavior `-compat=js` targets — instead treats such a binding as a plain
dynamic variable: it holds a number, then a string, then a boolean, and every
read sees the current runtime value. The machinery for this already exists (an
annotated `let x: any` cross-type reassignment works via the D1 NaN-boxed
value), but an *untyped* binding wasn't routed to it — under `-compat=js` it
still got a fixed scalar slot and hit the same rejection (or, before ADR-00651/
ADR-00652, invalid IR).

The slot can't be retrofitted at the first incompatible assignment (earlier
concrete stores/reads would misinterpret a later boxed value), so the decision
must be made at declaration — a pre-pass.

## Decision

A per-scope pre-pass, `crossTypeWidenedBindings` (emit_func.go, `-compat=js`
only), walks a body and returns the untyped `var`/`let` bindings assigned **two
or more distinct scalar kinds** (number / string / boolean, via
`scalarTypeKind` over `inferExprType`) across their lifetime. Those bindings are
backed by the any-box (`TypeAny`, a NaN-boxed `{ i8, i64 }`) from declaration:

- Stored in `e.widenedBindings`, saved/restored per body exactly like
  `hoistedCaptures`, and set at all five body-emission sites (module program,
  function declaration, arrow, function expression).
- `emitVarDecl` types a widened binding `TypeAny` (and skips the numeric-literal
  slot re-inference), so its initializer and every later store box, and reads go
  through the dynamic path — identical to an annotated `let x: any`.
- `reliableGlobalType` promotes a widened top-level binding as an `any` global
  (computed before `registerModuleGlobals`), so a named function referencing it
  reads an `any` rather than a stale concrete type.

Only *untyped* bindings are eligible — an explicit annotation is a contract kept
even under `-compat=js`. A binding assigned a single scalar kind is **not**
widened: it stays a plain unboxed scalar, so ordinary numeric code keeps its
speed. Strict is unchanged (the pre-pass returns nil when not `-compat=js`), so
the same program is still a clean rejection there — the two-tier model.

## Investigation

Scoped tight deliberately. Nested function/arrow bodies are separate scopes
with their own pre-pass, so this walker does not descend into them; a rare
closure that reassigns an *enclosing* binding to a different kind is not seen by
the enclosing scope's pass and stays a clean rejection — a documented V1 edge,
not invalid IR. Widening is also limited to scalar kinds (the invalid-IR /
rejection cases were all scalar-into-ptr); object/array bindings are out of
scope. An assignment nested inside a larger expression (`f(x = 1)`) rather than
a statement is likewise not scanned in V1.

## Side effects discovered

None expected. A single-kind binding's representation is unchanged, so existing
typed/inferred code is byte-identical; widening only fires on a binding that
would otherwise have been rejected (compat=js) under ADR-00651.
