# ADR-00915: Body-prologue default filling for captured-scope defaults (TDD-00206 Stage 2)

- **Date**: 2026-09-12

## Relations

- Implements [TDD-00206](../tdd/TDD-00206.md) Stage 2. Completes [ADR-00914](../adr/ADR-00914.md) (Stage 1).

## Context

[ADR-00914](../adr/ADR-00914.md) fills an omitted parameter of a first-class
function value at the call site, from the default expression carried on the
closure `Type`. That is correct for a self-contained default — a constant, a
sibling-parameter reference (`y = x`), or a module global — but a default that
references a variable *captured* from the closure's defining scope cannot be
evaluated at the call site, because that variable is not in scope there:

```ts
function make(base: number) {
  return (x: number, y: number = base): number => x + y;   // `base` is captured
}
const f = make(100);
f(5);   // Stage 1: codegen error "undefined variable 'base'"
```

Each returned closure captures its own `base`, so the default must be evaluated
inside the closure body, against that closure's environment — not at the caller.

## Decision

Evaluate a capture-referencing default in the closure **body prologue**, gated by
a hidden argument-presence mask.

- **Classification** (`setFuncParamDefaults`, purely syntactic so the emit path
  and `inferExprType` agree): a default whose free-variable set — computed with
  the sibling parameter names bound — is non-empty is a *body default*
  (`FuncBodyDefaults[i]`); otherwise it stays a *call-site default*
  (`FuncParamDefaults[i]`, Stage 1). A closure with any body default sets
  `FuncHasDefaultMask`.
- **ABI**: such a closure gains a hidden trailing `i32 %__dmask` parameter (params
  otherwise keep their declared types — no per-parameter ABI change). The mask's
  bit *i* is set when argument *i* was actually supplied.
- **Callers**: `emitClosureCallByPtr` (and `Function.prototype.call`/`apply`,
  which route through it) append the mask as a compile-time constant — the low
  `provided` bits, where `provided` is the count of regular arguments supplied.
  An omitted body-default parameter is passed its slot's zero (the body
  overwrites it). `emitCBCall` (higher-order-method callbacks) passes the mask
  reflecting the arguments the HOF actually supplies, so a defaulted parameter the
  HOF fills (e.g. `map`'s index) wins, while one it omits falls back to the
  default.
- **Body prologue** (`emitBodyDefaultPrologue`, shared by the arrow and
  function-expression emit paths): runs after parameters *and* captured variables
  are bound; for each body-default parameter whose mask bit is clear, evaluates
  the default (captures and sibling parameters both in scope) and stores it into
  the parameter's slot.
- **Capture discovery**: `gatherCaptures` and the function-expression capture scan
  now also scan parameter default expressions, so a variable referenced only by a
  default is captured into the closure environment.

## Scope / clean rejections

Body-default support is limited to plain scalar/string parameters (the single-word
alloca slot the prologue overwrites). A body-default parameter that is an
array/tuple/object/nullable/destructured type, or a body-default on an async
closure, is a clean compile error. `Function.prototype.bind` and the zero-argument
http/timer void-callback path (`emitClosureCallByPtrVoid`) reject a
`FuncHasDefaultMask` closure cleanly rather than emit a call that omits the mask.

## Consequences

- Captured-scope parameter defaults on first-class function values now work
  faithfully, including distinct captures per returned closure and correct
  fallback when invoked through a higher-order method.
- The Stage-1 call-site path and its `paramDefaultScratch` are unchanged for
  self-contained defaults, so the common ABI (closures with no capture default) is
  untouched — the mask exists only on closures that need it.
