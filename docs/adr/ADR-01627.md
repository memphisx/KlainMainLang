# ADR-01627: `JSON.parse` and `Array.prototype.join` allocate in proportion to their input

- **Relations**: Extends ADR-01582, ADR-01623, TDD-00120
- **Date**: 2026-10-14
- **Notes**: Under the conformance runner each Windows test program runs in a
  512 MB job (ADR-01582); untouched memory counts there, unlike Linux's RSS.

## Context

WPT's `url` area passed 56 of 82 subtests on Windows, 2689 of 4058 in the
last Linux report: `url-constructor`, `url-origin` and `IdnaTestV2` failed at
"Loading data…" (`JSON.parse` of `resources/urltestdata.json`, 228 KB).

## Investigation

- Run by hand the program passed (407 / 413); under the runner's per-program
  job it failed with `SyntaxError: Unexpected token in JSON at position
  32919`. With a 4 GB job it passed, peaking at 1.85 GB of committed memory
  while its resident set stayed under 20 MB.
- `JSON.parse` of the file alone committed 1.1 GB: `parse_string_raw` sized
  each string's buffer by the rest of the input (`end - p`), so every string
  of a large document held a buffer of the remainder. Linux leaves the
  untouched pages uncommitted; Windows charges them. When `malloc` failed the
  parser reported a syntax error.
- Writing a test for it found the second: `[...].join(",")` of 20 000 short
  strings committed 1.5 GB. The join concatenated into an accumulator, one new
  string per element, none freed in the default memory mode: quadratic in
  bytes and time on every platform.

## Decision

- `parse_string_raw` scans to the closing quote first and allocates the raw
  span plus slack (an escape decodes shorter than it is written).
- `join` stores each element's string in a scratch array and builds the
  result in one allocation (`__kml_str_join` in `strheader.c`).
- The conformance runner: `-out` applies to a single-lane Node, WPT or TS run
  as it does to Test262's (a triage run no longer replaces the committed
  report), and `WPT_TRACE` prints each file's subtest counts.

## Implementation notes

`codegen/llvm/jsonsrc/json_parse.c`, `stringsrc/strheader.c`,
`runtime_strheader.go`, `emit_arrays_sort.go` (`emitArrayJoinCore`);
`tools/conformance/main.go`, `wpt.go`; test
`TestE2EJSONParseManyStringsBoundedMemory`.

## Side effects discovered

A string's `.length` counts UTF-8 bytes (BACKLOG §0 25), seen in the test's
first draft.

## Verification

Windows 11 (this machine): the JSON program's peak commit 1148 MB → 5 MB, the
URL-data program's 1851 → 11 MB, the joins' 2.7 GB / 1.5 GB → 4 MB; the JSON,
join, string and array tests; WPT `url` 58 / 80 → 2284 / 3645. Linux
(Docker, `klain-ci`): WPT `url` per file identical to Windows.
