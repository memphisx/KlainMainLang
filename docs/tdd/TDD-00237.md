# TDD-00237: `URL`, `URLSearchParams` and `Headers` as Node's, in TypeScript

- **Status**: Implemented
- **Date**: 2026-10-01

## Context

[TDD-00230](TDD-00230.md) P3.2 leaves host objects open: classes the
compiler implements in codegen as handles with their own `Type` flags,
their own `new` node from sema, and hand-written member emitters. Three of
them sit at the centre of the REST priority (fetch, `http`):

- **`URL`** (`emit_url.go`, 1,464 lines; `IsURL`: 53 sites in 22 files)
  parses with libcurl's `CURLU`, not the WHATWG URL Standard parser Node
  uses (ada, written to the standard). The two disagree beyond the cases
  [ADR-01207](../adr/ADR-01207.md) and [ADR-01308](../adr/ADR-01308.md)
  patched: opaque paths, IPv4 number forms (`http://0x7f.1/`), host
  code-point validation, special-scheme backslashes, the percent-encode
  sets of each component, the setters' state overrides. Component
  setters re-parse a rebuilt string ([ADR-00572](../adr/ADR-00572.md))
  rather than run the standard's state machine from the component's state.
- **`URLSearchParams`** (`urlsearchparamssrc/urlsearchparams.c`, `IsURLSearchParams`:
  30 sites in 18 files) is a native list with a URL write-back hook
  (`ensureURLUSPWriteback`).
- **`Headers`** (`emit_headers.go`, `runtime_strheader.go`; `IsHeaders`: 17
  sites in 12 files) is a lowercased, insertion-ordered map. BACKLOG 85:
  iteration is not sorted by name, and repeated `set-cookie` values are
  joined rather than listed (`getSetCookie()`).

None of the three can be subclassed (`class X extends URL` is "extends
unknown class"), none is a value (`const U = URL`), and each `Is*` flag is
one more case every generic path has to remember.

[TDD-00231](TDD-00231.md) and [TDD-00232](TDD-00232.md) moved Node modules
and web globals to TypeScript modules compiled with the program (`net`,
`http`, `url`'s legacy API, `EventTarget`, `WebSocket`). In Node, all three
of these are JavaScript: `URL` and `URLSearchParams` are
`lib/internal/url.js` over ada's parser, and `Headers` is undici's
`lib/web/fetch/headers.js`.

## Design

Each class becomes a **global module** (`kml:global`, the resolver
mechanism of [ADR-01203](../adr/ADR-01203.md)), linked after checking: the
checker keeps typing the globals from `lib/node.d.ts`, and sema points free
references at the module's class. `url`'s module exports re-export them, so
`import { URL } from 'url'` and the global are one class.

### Stage 1: `URLSearchParams`

`lib/node/kml_url_search_params.ts`, following Node's `lib/internal/url.js`:

- The list of name/value pairs; a constructor from a string (one leading
  `?` dropped), a sequence of pairs (each exactly two, else `TypeError`), a
  record, or another `URLSearchParams`.
- `append`, `delete(name, value?)`, `get`, `getAll`, `has(name, value?)`,
  `set`, `sort` (a stable sort by UTF-16 code units), `size`, `toString`
  (the `application/x-www-form-urlencoded` serializer), `forEach`, `keys`,
  `values`, `entries` and `[Symbol.iterator]`, and util.inspect's
  `URLSearchParams { 'a' => '1' }`.
- Parsing and serializing are the URL Standard's form-urlencoded parser and
  serializer, over the percent-decode and `querystring` encode tables
  already ported.
- A params object made by a `URL` holds the URL and writes its query back
  on every mutation (Node's `#context`), and the URL's `search` setter
  re-parses the list.

### Stage 2: `URL`

`lib/node/kml_url.ts`:

- **The parser is the URL Standard's basic URL parser in TypeScript.** Its
  state machine, host parser (domain, IPv4 with its number forms, IPv6
  compression and the embedded IPv4 form, opaque hosts), the
  percent-encode sets, and the setters as state overrides follow the
  standard's algorithm step by step. Ada implements the same algorithm in
  C++. The reference for porting is the `whatwg-url` package's
  `url-state-machine.js` (MIT), which mirrors the standard's prose.
- **Domain to ASCII** (UTS #46 processing and Punycode) stays native: a
  `@lower` function in `lib/native.d.ts`, over the IDN library libcurl
  links today. `url.domainToASCII`/`domainToUnicode` use it too.
- `URL` has the standard's members (`href`, `origin`, `protocol`,
  `username`, `password`, `host`, `hostname`, `port`, `pathname`, `search`,
  `searchParams`, `hash`, `toString`, `toJSON`), the statics `canParse` and
  `parse`, and `URL.createObjectURL`/`revokeObjectURL` as Node has them
  (`blob:nodedata:` ids over the Blob registry). An invalid URL throws
  Node's `TypeError` with `code: 'ERR_INVALID_URL'` and `input`.
- `fileURLToPath`, `pathToFileURL` and `urlToHttpOptions` move to
  TypeScript beside it, from Node's `lib/internal/url.js`.
- Native consumers (fetch, `http.request`, `new WebSocket`) take the URL's
  `href`, a string, wherever they take a URL today.

### Stage 3: `Headers`

`lib/node/kml_headers.ts`, following undici's `lib/web/fetch/headers.js`:

- A header list of lowercased names and their values, with the Fetch
  standard's name and value validation (`TypeError` on an invalid name or
  value) and value normalization (leading and trailing HTTP whitespace
  removed).
- `append`, `delete`, `get` (values of one name combined with `, `),
  `getSetCookie`, `has`, `set`, and iteration in the standard's
  "sort and combine" order: names sorted, values combined, except
  `set-cookie`, whose values are listed separately. util.inspect shows
  Node's `HeadersList`-free `Headers { … }` form.
- Guards (`immutable` for a response's headers, `request-no-cors`) as
  undici has them.
- **Interop with fetch.** `Request`, `Response` and `fetch` stay native in
  this TDD. They exchange headers as a flat array of `[name, value]`
  string pairs. A Headers' list is handed to the native side by an internal
  method, and a response's headers are built from the native pairs by an
  internal factory the module exports. codegen calls both by name, as it
  calls `EventTarget`'s dispatch since [ADR-01203](../adr/ADR-01203.md).

### What is deleted

Per stage: the `NewURLExpression`, `NewURLSearchParamsExpression` and
`NewHeadersExpression` nodes and their sema builders, `IsURL`,
`IsURLSearchParams` and `IsHeaders` with every site that tests them,
`emit_url.go`, `urlsearchparamssrc/`, `emit_headers.go`,
`runtime_strheader.go`, and libcurl's `CURLU` from URL handling. Every
test and example using these classes is checked against Node.
