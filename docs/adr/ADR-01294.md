# ADR-01294: `dns` as Node's lib/dns.js over a native DNS client

- **Relations**: `Implements TDD-00236`, `Implements part of TDD-00230` (P3.1), `Supersedes ADR-00326`, `Supersedes ADR-00329`
- **Date**: 2026-09-30

## Context

TDD-00236 designs the port. The compiled `dns` answered `resolve4` with
`getaddrinfo` and returned one IPv4 address from `lookup`. Its callbacks
ran synchronously, and its errors had no code.

## Decision

**Modules** (Node's files, converted as the other P3.1 ports):

| Node source | Here |
|---|---|
| lib/dns.js | `lib/node/dns.ts` |
| lib/dns/promises.js | `lib/node/dns_promises.ts` |
| internal/dns/utils.js (with `DNSException`) | `internal_dns_utils.ts` |
| internal/dns/callback_resolver.js | `internal_dns_callback_resolver.ts` |
| internal/dns/promises.js | `internal_dns_promises.ts` |
| @types/node's record and option types | `internal_dns_types.ts` |

`internal/net`'s `isIP` moved from `net.ts` to `internal_net.ts`, which
`net` and `dns` share. Each function carries @types/node's overloads, so a
mistyped callback is a type error.

**Natives** (`threadpoolsrc/klaindns.c`, in the pool's translation unit).
Each runs on the thread pool and hands its result back as JSON in the
item's string:
- **`dnsGetaddrinfo`.** Every address, in libuv's `verbatim`/`ipv4first`/
  `ipv6first` order. A failure is libuv's code (`UV_EAI_NONAME` is
  `ENOTFOUND` with errno `-3008`).
- **`dnsGetnameinfo`.** `NI_NAMEREQD`, as libuv's caller asks.
- **Channels** stand in for c-ares' `ChannelWrap`: a resolver's servers,
  timeout, tries and max timeout. Servers come from where c-ares reads
  them:
  - macOS: libSystem's DNS configuration, every resolver without a domain
    that is not mDNS (4-byte packed `dnsinfo.h` structs);
  - Linux: `/etc/resolv.conf`;
  - Windows: the adapters' DNS servers;
  - `127.0.0.1` when there are none.
- **`dnsQuery`** (the client):
  - Sends an RD query with EDNS0 over UDP to each server in turn, and
    re-asks over TCP when the answer is truncated.
  - Retries for `tries` rounds, with a timeout that doubles per round up to
    `maxTimeout`.
  - SERVFAIL, NOTIMP and REFUSED move on to the next server.
  - Returns c-ares' statuses (`ENOTFOUND` for NXDOMAIN, `ETIMEOUT`,
    `ECONNREFUSED`, `ECANCELLED` after `cancel()`).
  - Parses A, AAAA, NS, CNAME, PTR, MX, TXT, SRV, SOA, NAPTR, CAA and TLSA.
- **TypeScript shaping** mirrors cares_wrap.cc's parsers:
  - A/AAAA follow the question's CNAME chain, their TTLs capped by it;
  - TXT records are chunk lists;
  - MX, SRV and CAA carry `type`; NAPTR and SOA carry an `undefined` `type`
    key;
  - `resolveAny` is in cares_wrap's order;
  - an answer without the type is `ENODATA`;
  - `reverse` of a non-address throws `EINVAL`.

**Also changed:**
- `util.getSystemErrorName`/`getSystemErrorMessage` name libuv's own codes
  (the `EAI_*` family, `EOF`, `ECHARSET`), which DNS errors carry.
- The compiled `dns` (emit_dns.go, runtime_dns.go), its virtual marker and
  its `declare module` are deleted.
- A c-ares error leaves `errno` unset. Node's has an `errno: undefined`
  key, but the error layout's `errno` slot is numeric.
- `setLocalAddress` validates as cares_wrap does, and the client binds its
  sockets to those source addresses.

## Verification

Outputs match Node on the same host at the same moment. Multi-record
answers are sorted in tests (servers rotate them).
- **Mac (Apple Silicon):** Node v24.19.0; `tests/dns_port_test.go` and the
  examples. The lookups, errors and validation are compared as they are.
  The live resolver probe covers MX, NS, TXT, SOA, SRV, CAA, NAPTR, CNAME,
  PTR, reverse (IPv4 and IPv6), the promises API, `resolve(…, 'MX')`, a
  `Resolver`, `resolveAny` and NXDOMAIN.
- **Linux (Docker, glibc/arm64):** the same tests against Node 26.10.
- **Windows:** klaindns.c compiles with x86_64-w64-mingw32-gcc.
