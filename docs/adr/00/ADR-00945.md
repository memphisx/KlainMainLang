# ADR-00945: Array values through `.then`/`.catch` reaction callbacks

- **Relations**: `Extends ADR-00941` (array return ABI, TDD-00213 Stage 3); `Extends ADR-00073` (`.then`/`.catch`/`.finally`)
- **Date**: 2026-09-15

## Context

A `.then`/`.catch` callback taking OR returning an array was broken after the
header-pointer array model landed. `p.then(arr => ...)` on a `Promise<T[]>`
crashed (silently produced nothing before the header model); a callback
returning an array (`then(n => [n, n*2])`) produced invalid IR. `await` of the
same promises worked. Confirmed pre-existing on committed HEAD — one of the five
array-in-container bugs.

## Investigation

The per-call-site reaction runner (`emit_promise_then.go`, emitted as an IR
string) mishandled arrays in two directions:

- **Argument:** `thenValLoadIR` reconstructed the callback argument as a single
  `inttoptr i64 %v0 to ptr`. An array is passed by the two-slot array-param ABI
  (`ptr <header>, i64 <len>` — `bindArrayParam`/`emit_func.go:258`), where the
  `ptr` is a `{data,len}` header. The promise stores the array's DATA pointer in
  v0 and length in v1 (`loadPromiseValue`, `emit_task_emit.go:261`), so passing
  v0 as the "header" made the callback read `header->data` off the first
  element — a crash.
- **Return:** an array's IR is now `"ptr"`, so `thenStoreResultIR`'s
  `switch retTy.IR { case "ptr": ... }` caught arrays in the scalar-pointer arm
  (`ptrtoint ptr %agg`) before its own `default`/`IsArray` branch — and that
  branch was itself stale, assuming a `{ptr,i64}` aggregate return when an
  array-returning arrow now emits `ret ptr <header>` (ADR-00941,
  `emit_func.go:2566`).

## Decision

- Argument: `emitThenRunner` special-cases an array `argTy` — mint a fresh
  `{data,len}` header from v0 (data) + v1 (len) and call the closure with
  `(ptr %env, ptr %header, i64 %len)`.
- Return: `thenCallRetIR(array)` → `"ptr"` (the callback returns a header
  pointer). `thenStoreResultIR` checks `retTy.IsArray` BEFORE the `retTy.IR`
  switch and derefs the returned header for its data pointer (→ v0 bits) and
  length (→ v1) — the two slots `loadPromiseValue` reads an array back from. The
  dead `{ptr,i64}`-aggregate branch in `default` is removed.

## Implementation notes

The IsArray-before-IR-switch ordering is the load-bearing part: every
array-shaped value now reports `IR == "ptr"`, so any `switch ty.IR` that
predates the header model can silently misroute arrays into a `case "ptr"` arm.
The minted argument header gives the callback a normal, mutable array with its
own identity — faithful for a reaction callback (the resolved value isn't
aliased elsewhere by identity).

## Side effects discovered

None beyond this runner. `.finally` (no value argument) and scalar/void
callbacks were already correct.

  return (chained), array→array `.map` chain; plus manual `.catch` returning an
  array and `string[]` argument.
- Regression: `go test -run 'TestE2E(PartANonSuspendingThenChain|
  PromiseCatchErrorParam|PromiseThenFunctionExprCallback|AwaitThenChainResult|

  PromiseThenArrayValue)'` green on macOS arm64 (Apple Silicon M4).
- `clang -O0 -S -emit-llvm -x ir` clean on both repros.
