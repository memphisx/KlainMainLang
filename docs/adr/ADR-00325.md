# ADR-00325: Node `util` — `util.inspect` / `util.format`

- **Date**: 2026-08-23

## Context

`util` was flagged on NODE-CORE-MODULES.md as "the remaining CLI-relevant gap":
`util.inspect` (generic value formatting) and `util.format` (printf-style string
building) are broadly useful, and — unlike most of the remaining backlog — need
no new system dependency. The status note claimed `util.promisify` would be
"near-meaningless until this compiler has callback-based async APIs to wrap";
that claim was stale (zlib/`child_process.exec` already take error-first
callbacks), but promisify has a different, real blocker (below), so this ADR
ships inspect/format and defers promisify.

## Investigation

The value inspector already exists: `emitInspectField(v, depth)`
(emit_inspect.go) is what `console.log` and strict-mode string coercion use to
render a value — strings single-quoted, `ClassName { … }`, arrays `[ … ]`,
bigints `10n`, `[Function]`/`[Object]` placeholders past depth. That is exactly
`util.inspect`'s output, so inspect is a one-line delegation.

`util.format` is printf-style. Because arguments are statically typed and the
format string is almost always a literal, the substitution can be done at
codegen time, walking the literal and emitting an `emitStringConcat` chain — the
same approach the compiler already takes for other format-string-shaped work.
The per-verb conversions all have existing helpers: `emitValueToString` (%s, and
%d/%f after an i64/f64 coerce), `emitJSONStringifyValue` (%j), `emitInspectField`
(%o/%O).

`util.promisify(fn)`: the Promise machinery to build on exists (`emitNewPromise`,
`__kml_promise_settle`, first-class resolve/reject closures, `emitCBCall`). The
blocker is that the callback APIs are **not first-class function values** —
`zlib.gzip`/`child_process.exec` are name-dispatched call expressions, so there
is no `fn` value to hand to `promisify(fn)`; wrapping them would need per-builtin
special-casing, and `promisify` of a user-defined `(…, cb)` function needs new
machinery to synthesize-and-append a callback. Out of scope for this ADR.

## Decision

Expose `util.inspect(value, options?)` (options accepted, ignored in V1) as
`emitInspectField(val, 0)`, and `util.format(format, ...args)` as a codegen-time
walk of a **string-literal** format:

- `%s` → `String(arg)`; `%d`/`%i` → integer; `%f` → float; `%j` →
  `JSON.stringify(arg)`; `%o`/`%O` → `util.inspect(arg)`; `%%` → literal `%`.
- An unrecognized specifier is left literal; excess args are appended
  space-separated (`String()`-formatted); excess specifiers with no arg are left
  literal — all matching Node.
- A non-literal format string is a compile error in V1.

`util.promisify` is omitted from `virtualModuleMembers`, so importing it fails
cleanly rather than compiling to a stub.

## Implementation notes

- New `codegen/llvm/emit_util.go`; no runtime file (pure reuse).
- Registration in `resolver/virtual_modules.go` (`util` → `util__kml_builtin`,
  members `inspect`/`format`), dispatch in `emit_call.go`, and a `TypePtr`
  (string) return in `emit_exprs_types.go`.

## Side effects discovered

None. Options-object support for `inspect` (depth/colors) and non-literal
format strings are disclosed as caveats.

## Verification

- `tests/util_test.go`: format specifiers (`%s`/`%d`/`%f`/`%j`), literal `%%`
  + excess args, and inspect of a string/array/object.
- `examples/util/format_inspect.ts` run on macOS (arm64).
- Machine: verified on Mac; platform-independent (no syscalls), so parity
  expected but not separately run on Linux.
