# ADR-00635: Move bespoke `http.listen`/`close`/`closeAllConnections` off the Node `http` namespace to `klain:http`

- **Relations**: `Extends TDD-00131` (the `klain:` namespace policy), `Extends ADR-00634` (the same faithfulness pass that removed `http.listen({ ws })`)
- **Date**: 2026-09-02

## Context

The `http` module exported bespoke module-level `listen`/`close`/
`closeAllConnections` functions (the handler-returns-`{status, body}` server
model). These are not Node APIs: Node's `http` has `createServer`/`get`/
`request`/`Agent`, and `listen`/`close`/`closeAllConnections` are methods on
the `Server` object `createServer` returns. Under the project's
faithful-under-Node-namespaces rule (a Node specifier matches Node; bespoke
conveniences live under `klain:`), these three don't belong on `http`. They
already existed under `klain:http` too — but `http` and `klain:http` shared
one codegen marker, so `http.listen` slipped through the Node namespace.

## Investigation

Removing the three names from `http`'s export allowlist
(resolver/virtual_modules.go) was necessary but not sufficient: the allowlist
gates *named* imports (`import { listen } from 'http'`), while the common
`import http from 'http'; http.listen(...)` default-member form dispatches by
marker + member name in the emitter — and `http`/`klain:http` shared the
marker `http__kml_builtin`, so the origin specifier was lost by codegen and
`http.listen` still compiled. A repo scan found the real migration surface is
small: 15 example `.ts` files, ~56 embedded test sources, and one fixture
(`tools/httpbin-lite/httpbin.ts`) actually call `http.listen`; **none** mix
it with a real-Node `http` member, so every caller is a clean import swap.

## Decision

Give `klain:http` its own marker, `klainhttp__kml_builtin` (distinct from
`http__kml_builtin`), so codegen can tell the two apart:
- The `http__kml_builtin` dispatch keeps `get`/`request`/`createServer` and
  rejects `listen`/`close`/`closeAllConnections` with a message pointing at
  both the faithful `http.createServer(...).listen()` and `klain:http`.
- A new `klainhttp__kml_builtin` dispatch handles `listen`/`close`/
  `closeAllConnections` (the same implementations) and rejects the Node
  client/server members.
- `http`'s export allowlist drops the three names; `klain:http`'s keeps them.

Callers migrate by swapping `import http from 'http'` → `import http from
'klain:http'` (the examples carry a one-line "bespoke" note). The faithful
`http.createServer(handler).listen(port)` path is unchanged and is the
recommended shape.

## Implementation notes

- resolver/virtual_modules.go: klain:http marker → `klainhttp__kml_builtin`;
  `http` exports trimmed to `{get, request, createServer, Agent}`.
- codegen/llvm/emit_call.go: split the marker dispatch; the `http` marker's
  `listen`/`close`/`closeAllConnections` cases now return the redirect error.
- Migrated: 15 example `.ts` files, `tools/httpbin-lite/httpbin.ts`, and the
  ~56 listen-only embedded test sources across 6 test files (a scripted
  per-raw-string-literal import swap, guarded to only touch listen-only
  literals).
- Website: the landing page's `server` showcase snippet now leads with the
  faithful `http.createServer` shape (a new `serverBespoke` snippet keeps the
  klain:http model), the "Real servers" copy updated, `http.json`'s lede +
  `http.listen` entry re-pointed at klain:http, and `examples-content.json`
  regenerated.

## Side effects discovered

None. `https` never exported the bespoke functions (its server is
`https.createServer(...).listen()` already). Coverage counts are unchanged —
the same rows, just reachable under a different specifier.

## Verification

- Mac (Apple Silicon): `go build`, `go vet` clean; `http.listen` from `'http'`
  now errors with the redirect message, from `'klain:http'` works; all 255
  examples pass; broad HTTP/net/TLS/WS/streams/signals/cluster/goroutines/
  fetch/async suites green; `make status-check` + `make reference-check` OK.
