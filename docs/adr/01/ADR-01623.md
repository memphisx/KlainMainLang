# ADR-01623: The conformance runners fit their memory and Windows' command line

- **Relations**: Extends ADR-01582, ADR-01598, ADR-01476, ADR-01615
- **Date**: 2026-10-14

## Context

On Windows the Node-core suite died twice of memory exhaustion (the second
time the machine ran low), and the WPT suite passed nothing.

## Investigation

- **Memory**: the runner puts itself in a job capped at `-mem-cap-mb`
  (4 GB, ADR-01598), which counts the runner's own heap and every clang.
  Codegen runs in the runner's process: an http2 program's IR is about 70 MB
  (the whole http/http2/tls/stream stack, compiled from TypeScript; the last
  commit's compiler is the same size), its emitter peaks near 750 MB and its
  clang near 460 MB. Nine such compiles at once, sized by clang's memory only
  and with Go's default GC pacing letting the heap double, ran past the cap.
  The program processes were bounded; the runner was not.
- `renameHooks` (ADR-01615) rewrote the whole IR with a regexp, whose result
  grows by doubling: several copies of 70 MB per compile.
- **WPT**: every file that reached clang failed with an empty reason. The
  runners pass clang the cached library objects on its command line, which
  passes Windows' 32,767-character limit ("The filename or extension is too
  long"); the CLI already moves such a command into a response file
  (`Toolchain.Command`), the runners built their own. The same limit hit the
  Node and Test262 runners.
- The WPT harness's `t.step_func(f)` called `f()` with no arguments
  (testharness.js passes them on: an observer's `(list, observer)`), and the
  harness had no `self`, which a `.any.js` file reads as its global object.
- `TestIRTextOnlyShrinks` failed on the staged work: ADR-01615's hooks
  constructor is IR text without an allowance, and three files had shrunk
  below theirs.

## Decision

- **A memory budget** (`tools/conformance/budget.go`): a compile reserves
  256 MB before codegen and twelve times its IR's size once the IR exists,
  until its clang and program are done; one compile is always admitted, and
  growing never waits (two compiles each waiting to grow would deadlock).
  The budget is four fifths of the job cap on Windows, three fifths of the
  available commit elsewhere; it is also Go's soft memory limit.
- **`renameHooks`** is one pass into a buffer sized up front.
- **`llvm.HostClangExecArgv`**: the runners' clang command lines go through
  the response file as the CLI's do.
- A clang that fails silently reports its exit status; `NODE_TRACE` names
  each Node file a worker starts and finishes, `WPT_DUMP` writes each WPT
  program as compiled.
- The WPT harness's `step_func`/`step_func_done` pass their arguments on, a
  failure prints its error on a second line, and `self` is `globalThis`.
- `runtime_hooks.go` gets an allowance of one IR definition (a per-program
  constructor, as `unitreg.go`'s); the shrunk allowances are lowered.
- **The default cap is 2 GB** (was 4 GB): with an IDE, a VM and a RAM drive
  the development machine rests at ~59 of 75 GB committed, and a 4 GB run
  (the runner's own codegen most of it) left under 4 GB of RAM free, where
  the session's memory guard stopped it, twice. On Windows the budget is
  half the cap, the test programs (each in its own 512 MB job) the other
  half: at four fifths of 2 GB the programs had 400 MB, and when they took
  it the job refused the runner an allocation, a fatal error in Go.
- **Corpora are checked out with `core.autocrlf=false`** (`fetch.sh`
  `crlf_checkout`): on Windows git had converted every corpus to CRLF, so
  every earlier Windows conformance number was measured on a different
  corpus; a converted checkout is fetched again.
- **TypeScript virtual file names** are normalized alike on every host: a
  drive prefix (`c:/root/f1.ts`) becomes a directory and a trailing space
  goes, so the 23 such cases Windows could not write are run there too.
  `aux.ts` (a reserved device name) stays unwritable on Windows.
- **The Node suite's `common` shim takes the host's platform flags**
  (`isWindows`, `isLinux`, `isMacOS`) and, on Windows, a named pipe for
  `PIPE`, as Node's `common` does. It said macOS on every host, so Windows
  ran POSIX-only tests (signals, `umask`, privileged ports) that skip
  themselves there in Node, and Linux ran macOS branches.
- **The `common/tmpdir` shim lives under `os.tmpdir()`** (was `/tmp/…` on
  every host): on Windows `/tmp/x` is not absolute, so a test comparing a
  path it built with one the runtime reported (`C:\tmp\x`) failed.
- **A failed program's reason is its error text**: stderr's first non-empty
  line, else stdout's, else the exit status. With `NODE_RAW_REASONS` the
  first eight non-empty lines are kept, so an assertion names the values
  that differed.

## Implementation notes

`tools/conformance/budget.go`, `main.go`, `node.go`, `ts.go`, `wpt.go`,
`wpt_harness.go`, `budget_test.go`, `fetch.sh`; `codegen/llvm/hostclang.go`,
`runtime_hooks.go`, `irtext_allowance_test.go`.

## Side effects discovered

Running the WPT files that now compiled found ADR-01619 to ADR-01622.

## Verification

Windows 11 (this machine): the runner's unit tests (`TestMemBudget` included);
the Node-core suite ran through with the job peaking at 3.8 GB under its
4 GB cap (305 strict / 631 js passes, from 56 / 46); WPT 31 strict / 44 js
(from 0); every package but `./tests` passes its unit tests.
