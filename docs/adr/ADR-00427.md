# ADR-00427: cluster workers ride the fork IPC channel

- **Relations**: Extends [ADR-00425](ADR-00425.md) (fork IPC), [ADR-00331](ADR-00331.md) (cluster re-exec); part of [TDD-00105](../tdd/TDD-00105.md)'s deferred messaging
- **Date**: 2026-08-28

## Context

The oracle's cluster corpus (~35 files across two buckets) needs worker
messaging: `cluster.fork().on('message'/'online'/'exit')`, `worker.send`,
in-worker `process.send`/`process.on('message')`. ADR-00331's cluster had
re-exec workers but explicitly no IPC.

## Investigation

With TDD-00141/ADR-00425 in place, the whole channel already exists —
cluster workers in Node *are* `child_process.fork` children. The only
missing pieces were plumbing: give the cluster fork a socketpair +
`NODE_CHANNEL_FD` (beside its existing `KML_CLUSTER_WORKER_ID`), wrap the
parent end in a ChildProcess handle, and route Worker methods through it.

## Decision

- `__kml_cp_wrap_ipc(pid, fd)` extracted from `__kml_cp_fork`'s parent
  block (build + register a pipe-less ChildProcess around an IPC socket);
  `__kml_cluster_fork` creates the socketpair, sets both env vars in the
  child, and stores the wrapped handle in the Worker
  (`{ i64 id, i64 pid, ptr cp }` now).
- Worker surface routes to the embedded handle: `send`/`disconnect`/
  `on('message'/'exit'/'close'/'error')` reuse `emitCPHandleMethod`
  verbatim; `kill`/`destroy` map to the ChildProcess kill; `.process`
  exposes the handle (`.pid`); `'online'` — which has no wire handshake
  here (the worker is exec'd by the time fork returns) — fires its
  listener as a queued microtask, which still orders before any IPC
  message (those only flow through later loop iterations).
- The exec-family/`_exit` libc declarations moved to shared `ensure*`s
  (`ensureExecvDecl`/`ensureExecvpDecl`/`ensureExitRawDecl`) — cluster +
  fork-IPC + child_process now co-occur and would otherwise emit
  duplicate declares.

## Implementation notes

`runtime_ipc.go` (wrap extraction), `runtime_cluster.go` (socketpair +
3-field Worker), `emit_cluster.go` (member `.process`, method router),
`emit_call.go` (ClusterWorker method dispatch), `emit_exprs_types.go`
(`.process`/`send` inference), `runtime_core.go`/four runtimes (shared
decls).

## Side effects discovered

- The primary now stays in the event loop while workers live (the
  handle's keepalive) instead of only blocking in
  `__kml_cluster_wait_all`; the wait remains as the post-loop backstop.

## Verification

`TestE2EClusterWorkerIPCMessaging` (online → worker→primary message →
primary reply → worker exit, mustCall-verified both ways);
`examples/cluster/worker_messaging.ts` run clean; regressions green:
`TestE2ECluster*`, `TestE2EHTTPListenClusterWorkers*`,
`TestE2EChildProcess*`, `TestE2EWorker*` (Mac).
