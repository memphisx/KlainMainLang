# ADR-01156: The checker's false positives against TypeScript 7's baselines, fixed

- **Relations**: `Implements TDD-00230` (P2.7); `Extends ADR-01154`, `ADR-01155`
- **Date**: 2026-09-25

## Context

Moving the oracle to TypeScript 7.0.2 made tsdiag strict by default, since
TypeScript 6 made `strict` the default. About 4,300 corpus cases the 5.6
harness compared on a few codes only were now compared on every code. The
checker reported 243 diagnostics that no baseline has:

| Code | False positives |
|---|---|
| TS2304 | 151 |
| TS2322 | 50 |
| TS2345 | 24 |
| TS2339 | 6 |
| TS18048 | 5 |
| others | 7 |

The strict lane rejects every program the checker reports, so each one
could reject a valid program, or report the wrong code for an invalid one.

## Investigation

- **Sorting.** A script printed tsc's baseline errors on each false
  positive's line. About 110 were invalid programs where tsc gives a more
  specific code than TS2304; the rest were wrong errors on valid code.
- **The rules came from the TypeScript 7 source** (`typescript-go` at tag
  `typescript/v7.0.2`), read for these functions:
  - `onFailedToResolveSymbol` and its helpers;
  - `getSpellingSuggestion` and `levenshteinWithMax`, where a substitution
    costs 2, not 1 as `levenshtein` had it;
  - `reorderCandidates`;
  - `getModuleInstanceState`;
  - `narrowTypeByTypeof` and its host-object facts;
  - `isCompoundLikeAssignment`;
  - `getWidenedLiteralType`, which widens a literal only when it is fresh.
- **Stale baselines.** Running the real tsc 7.0.2 on a disputed case
  settled several:
  - it has no ten-suggestion cap;
  - `parserindenter` and `parserRealSource8` are TS2552 in tsc 7;
  - five more are errors tsc 7 reports and the older baselines lack.

## Decision

- **Name resolution** (`checker/unresolved.go`). An unresolved value
  reference gets the diagnostic tsc picks, in its order:
  1. TS2662 or TS2663: a missing `C.` or `this.` prefix, where a static
     member counts `Function` and `Object` members;
  2. TS2301: a constructor's local read by an instance field initializer,
     under the legacy class-field semantics only (`LegacyClassFields`);
  3. TS2708: a namespace with no values, read as a value;
  4. TS2693: a type read as a value, including a primitive type keyword;
  5. TS2552: a spelling suggestion. Scopes are searched from the reference
     outwards and the first table with a candidate wins. The globals are
     one table, which includes a script's top-level names and the library's
     global values;
  6. TS2593 or TS2592: a test runner or jQuery name;
  7. TS18004: a shorthand property;
  8. otherwise TS2304.

  `export default T` names a type or namespace without error.
- **Binder:**
  - A namespace with no value members is bound `TypeModule` (not a value).
  - An exported `import x = …` or an ambient `export { x }` makes a
    namespace a value.
  - An empty namespace is bound.
  - A merged enum's declarations share one member scope.
  - A parameter property's default is bound once, not again as a field
    initializer.
  - A destructuring-assignment target is its own store node.
  - The lookup scope of an unresolved name is kept (`LookupScope`).
- **Parser:**
  - `` tag<T>`…` `` parses, with its type arguments, and so do type
    arguments after an element access, a call or `super`.
  - A namespace's `export declare var` and `declare enum` are members.
  - `declare [export] import x = y` is an alias.
  - `export { … }` in a non-ambient namespace is TS1194. An ambient
    namespace's `export { … }` exports its members (and declaration files
    are ambient).
  - `{ x }` records `Shorthand`.
- **Lexer:** a template's CR LF and lone CR are LF, cooked and raw. This
  was a runtime bug too: the CR bytes reached the program's strings.
- **Types:**
  - A template literal is a string literal type: always without
    substitutions, and with them when every span is a literal and the
    context is const or literal.
  - A fixed tuple's `length` is a literal.
  - `typeof e` is the union of its eight possible results.
  - An enum member read in an initializer is its literal.
  - An object literal's last duplicate property wins.
  - `||`, `&&` and `??` are their left side when the right one can never
    be the value.
- **Freshness** (`widenFrom`). A mutable binding, parameter default, field
  initializer or literal element widens only the literals its expression
  makes fresh:
  - Fresh literals come from literal expressions, conditionals, logical
    operators, consts initialized with one, and generic calls without type
    arguments.
  - A regular occurrence beats a fresh one.
  - A literal whose context is a literal type, or a type parameter
    constrained to its primitive, keeps its type (`isLiteralOfContextualType`).
    So does a returned literal under a literal contextual return type.
- **Narrowing:**
  - A destructuring target is narrowed by the matching element or property,
    with a default standing in for `undefined`.
  - An assignment condition is narrowed by its right side, then by the
    target's truthiness.
  - The truthiness of a discriminant (`if (x.done)`) narrows, and so does
    `typeof x.p === …`.
  - A discriminant may be read as `x["p"]` or `` x[`p`] ``.
  - A reference is matched through a comma and an assignment.
  - Any other name in a `typeof` comparison is a host object's
    (TypeofEQHostObject).
  - `x = x + 1` targets x's base type (`isCompoundLikeAssignment`).
  - An object type with a required property that a primitive's apparent
    type lacks is never comparable with that primitive.
- **Calls and inference:**
  - Type arguments beyond every signature's are TS2558, and an overload
    with too few type parameters is skipped.
  - `super<T>(…)` is TS2754.
  - Candidates are ordered as `reorderCandidates`: a later declaration
    before an earlier one, a base's signatures after, a literal-typed
    signature first.
  - Inference follows the members of a different declaration
    (`ReadonlyArray<T>` from `Array<X>`).
  - A type parameter in an unanswered argument's interface is unanswered,
    not `unknown`.
  - An array literal against a tuple parameter is a tuple.
  - A rest parameter's contextual type is the rest of the signature.
  - An IIFE and an arrow's expression body take their context's result.
  - `Object.prototype`'s members satisfy a required property.
  - A literal is elaborated element by element only when the whole does not
    fit, though excess properties are still checked.
- **Library:**
  - The type-guard overloads of `find`, `findLast` and `every`;
  - `TemplateStringsArray`, which codegen represents as a string array;
  - `tsglobals.txt` marks which global names are values.
- **tsdiag:**
  - Each case's `@lib` (or its target's default library) limits the
    suggestions.
  - The baselines' ten-suggestion cap is modelled.
  - `-tsc` re-checks each false positive with the oracle's tsc, and lists
    the ones it reports too as stale baselines.
  - `-only` and `-matches` flags.

## Implementation notes

- tsc's freshness is a property of a literal type. Here it is worked out
  from the expression at each widening site, since the checker compares
  types by identity and a fresh twin of every literal would split them.
- `LibGlobal` and `LegacyClassFields` are harness options: the compiler
  checks with the whole library and ES2022 class fields.
- An unresolved destructuring target, or one the checker cannot type, reads
  unanswered, not its declared type.

## Side effects discovered

- A tagged template's call is not checked, so a `strings: string[]` tag
  compiles where tsc says TS2740 (BACKLOG). `examples/tagged_templates`
  used that form; it now uses `TemplateStringsArray`, and its note that an
  arrow cannot be a tag was stale and is removed.
- A near-miss *type* name is still not reported (BACKLOG).
- Merged enums still fail in codegen, and a defaulted nested destructuring
  target stays a codegen rejection.
- A lib interface is partial, so `s.push` on a `TemplateStringsArray` is
  not TS2339 (BACKLOG).

## Verification

- **tsdiag, TS 7.0.2 corpus:** 3,002 diagnostics over 6,004 cases, 3,002
  matching and 0 false positives. Before: 2,825 matching and 243 false
  positives over 6,002 cases. tsc 7 reports 9 more that the baselines lack.
- **tsdiag over the project's programs** (`examples`, `apps`): 0
  diagnostics.
- **libconform:** 0 divergences.
- **Tests:**
  - `TestCheck` (21 cases, codes from tsc 7.0.2) and `TestTypeOf`;
  - `TestTemplateLineTerminatorsNormalized`;
  - `TestTypeArgsBeforeTemplateAndSuper`, `TestNamespaceAmbientMembers`;
  - `TestE2ETaggedTemplateExplicitTypeArguments`,
    `TestE2ETaggedTemplateStringsArrayParameter`,
    `TestE2ETemplateLiteralLineTerminators`,
    `TestE2ENamespaceDeclareVarMember`,
    `TestE2EParameterPropertyDefaultClosure`.
- **Node:** each runtime change, and the tagged-templates example, has
  output identical to Node's. The example is clean under
  `tsc --noEmit --strict`.
