# ADR-01891: an array destructuring assignment's value; null-initialized globals

- **Relations**: `Implements TDD-00230` (P3.3 shadow buckets)
- **Date**: 2026-10-21

## Context

- `r = [a, b] = v` must give `r` the value `v`, evaluated once; the array destructuring assignment yielded void, so `r` was wrong (Test262 `array-elem-iter-nrml-close.js` and siblings).
- A top-level `var x = null` that a function assigns was never promoted to a global by the checker's declared type, unlike every other initializer the checker agrees on, so the shadow oracle disagreed on its presence.

## Decision

- Where its value is read, the destructuring assignment evaluates the right-hand side once into a binding that both the pattern and the result read.
- An unannotated null-initialized declaration a function reads promotes with the storage of the checker's declared type when that is a box or a nullable pointer.

## Consequences

- Chained destructuring assignments behave as in JavaScript; the null-init presence rows are gone from the shadow report.
- Verified on Apple Silicon against Node.
