# ADR-01707: undefined and null array indexes; a zero-argument onFinally

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-18

## Context

Two crashes, which the BACKLOG had listed as Linux-only Test262 failures. Both reproduce on macOS too.

1. `[0, 1, 2, 3].copyWithin(1, undefined)` and `(1, null)` segfaulted. `arrayIndexToI64` sent an `undefined` or `null` value, whose type is a pointer, down its string path, so it called `strtoll(NULL)`. The same happened in `toSpliced(undefined, undefined)` and in every other method that converts an index this way.
2. `p.finally(function () { arguments.length })` segfaulted. The finally runner calls onFinally with no arguments. A function that reads `arguments` takes an implicit rest parameter, which then read garbage.

## Decision

1. An `undefined` or `null` index is 0 (ToIntegerOrInfinity). An absent `string | undefined` index is converted as `"0"` rather than read.
2. An onFinally whose function type takes parameters is called from a closure that takes none: `() => onFinally()`.

## Verification

- macOS (Apple Silicon): `copyWithin` and `toSpliced` with `undefined`/`null` match Node, and so do the three `Promise.prototype.finally` Test262 files (`rejection-reason-no-fulfill`, `rejection-reason-override-with-throw`, `resolution-value-no-override`), run with their harness.
- Linux x86-64 (DeskMini): the failures were reproduced before the fix.
