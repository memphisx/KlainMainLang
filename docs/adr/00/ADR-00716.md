# ADR-00716: Deep free for transitively-owned typed JSON.parse trees (`-mm=auto`)

- **Relations**: Implements TDD-00175 (Stage 1); builds on ADR-00712 (rebind-free), ADR-00715 (`as T` projection targets)
- **Date**: 2026-09-05

## Context

The `-mm=auto` implicit layer's block-exit free is shallow by design
(TDD-00173): it releases a binding's own top-level allocation and nothing
reachable through it. The first benchmark campaign showed this as the
dominant remaining leak class — `json_churn` peaked at 434MB (scale 10)
where gc holds ~126MB: each round's parsed tree got one buffer free while
the per-row structs, their strings, and their nested score buffers all
leaked. TDD-00175 Stage 1 specifies the fix: a type-directed recursive
free for bindings whose flow proves the graph transitively owned.

## Investigation

- Free chokepoints: `freeSymbol`/`freeResolvedPointer` (emit_memory.go);
  drain sites in emit_autofree.go. Layout truth for the walk: object
  array-typed fields are inline `{ptr,i64}` slots (ADR-00061,
  `StructFieldIR`); nested-array *elements* are boxed pointers to a
  malloc'd `{ptr,i64}` (`storeArrayElem`/`boxArrayValue`); strings are
  length-prefixed (`__kml_str_free` frees base = ptr−8, and does **not**
  null-check); nullable scalars are inline `{i1,T}` aggregates.
- Every string a typed projection produces is a fresh heap dup
  (`__kml_json_string_dup`) — **except** an absent field's default, which
  was the interned `""` (`jsonDefaultRef`). A deep free of a tree with a
  missing string field would have freed an interned global and corrupted
  the heap. Fixed here: under `-mm=auto` the default is a
  `__kml_str_from_cstr` heap copy, making the whole tree uniformly owned.
- Pre-existing bug fixed in passing: `autoFreeOwningInit`'s
  JSON.parse/stringify recognition was nested inside
  `if escFreshMethodResults[m.Property]`, whose keys include neither
  `"parse"` nor `"stringify"` — dead code, so typed JSON.parse results
  never received even the shallow free.
- `json_parse.c` audit: the parser copies every decoded string and
  numeric lexeme into fresh mallocs and retains nothing of its argument;
  stringify only reads into a fresh output buffer. Both are therefore
  legitimate `escCallWhitelist` entries — without them,
  `JSON.parse(text)` counted as "callee may retain" and disqualified
  `text` from its own block-exit free.

## Decision

**Synthesized frees.** Per structural type signature (memoized by a
canonical key, so identically-shaped interfaces share one routine), an
on-demand `__kml_deep_free_N(ptr)` for objects/tuples — null-check, free
each owned field (string with null-check + `__kml_str_free`; nested object
by recursive call; inline array field via the element walker), then the
struct — and `__kml_deep_free_arr_N(ptr,i64)` for arrays — null-check,
per-element recursion (object / string / boxed nested array + box free),
then the buffer. Emitted with the emitChanCloneThunk save/restore builder
discipline into `e.functions`. Each freed struct/string fires the
FinalizationRegistry death signal exactly as `freeResolvedPointer` does.

**Eligibility — a downgrade lattice.** `escape → no free`,
`interior-unsafe → shallow (today's behavior)`, `interior-safe → deep`; a
rejection can only reproduce the pre-existing leak, never a new
unsoundness. Deep requires all of:

- the existing plan approval (top pointer block-local), no rebinds;
- a second escape-checker pass in **interior mode**: any member/index
  chain rooted at the binding is treated as a potential interior pointer
  wherever the *pointer itself* could be stored — plain-`=` assignment
  RHS, declaration initializer, return/throw/yield, non-whitelisted call
  argument, literal element, spread — and additionally: any store *into*
  the graph, any method call on it, and `for...of`/`for...in` over it all
  decline deep. Consuming positions stay eligible: `.length`/`.size`
  terminals, compound-op assignments (`total += x[0].n` stores the
  arithmetic/concat result, never the chain pointer), comparisons,
  template interpolation, whitelisted printers;
- a type gate: trees of scalars / nullable scalars / strings / objects /
  arrays only — class, dynamic, map/set, closure, promise, flat `@value`
  excluded (JSON can't produce them; gated defensively);
- an initializer whose emission is a typed projection producing a
  transitively-fresh graph: `JSON.parse(...)` / `res.json()`, optionally
  awaited. Array/object **literals are deliberately not accepted** — a
  literal can embed interned string literals and aliases of other
  bindings; per-store freshness for literals is TDD-00175's follow-up
  work, not Stage 1.

**Wiring.** `escPlanner.deeps` → `e.autoFreeDeep`; `pendingFree.deep`;
all drain sites (block exit, return, break/continue, owned-last-use,
rebind) go through one `freePending` dispatch; `freeSymbolDeep` resets
the binding's storage exactly as the shallow path does.

## Implementation notes

- New: codegen/llvm/emit_free_deep.go. Touched: escape_check.go
  (interior mode, `deeps`, whitelist), emit_autofree.go (`deep` flag,
  `freePending`, the dead-gate fix), emit_json_project.go (heap-dup
  string default under auto), emitter.go (fields).
- Interior mode's chain classification is type-free (the pass runs before
  emission); `const y = x[0].id` (a scalar) rejects the same as
  `const y = x[0].name` (a string pointer). Type-aware refinement is a
  possible follow-up; rejection is only a leak.
- Tests: tests/memory_auto_test.go (`TestE2EMemoryAutoDeepFree*` —
  manual/auto output parity incl. missing + null string fields, RSS
  bound on the json_churn shape, interior-extraction rejection asserted
  against the IR, length-only admission), tests/as_cast_test.go
  (`TestE2EAsCastJSONParse*`). Example:
  examples/memory/memory_deep_free.ts. The test builders' clang chain
  gained `appendJSONParseTree`/`appendDynJSON` (buildBinaryAuto lacked
  them; any auto test using JSON would have failed to link).
- ASan (`-fsanitize=address`, macOS/M4): clean over the parity shape and
  the example with deep frees active. `leaks --atExit` on json_churn
  scale 1: 135KB total at exit — the `build()` rows that escape via
  `return` (interprocedural freshness, TDD-00175 Stage 2) plus the
  intentionally-retained array headers.
- json_churn (M4, scale 10): auto 434MB → 197MB; auto+`-optimize-memory`
  129MB / 2.26s — matching gc's RSS (126MB) at 2.2× gc's speed and
  beating manual (227MB / 2.31s) on both axes. Checksums identical
  across all modes.

## Side effects discovered

- The residual json_churn RSS slope (~55KB/round of allocator high-water,
  not leaked blocks per `leaks`) and plain auto's wall-time gap vs
  `-optimize-memory` (4.05s vs 2.26s at scale 10) are unexplained
  performance follow-ups, not correctness issues.
- `closure_churn` and `rbtree` remain untouched by design — Stages 2/3.
