# ADR-00194: Full string-literal escape-sequence decoding

- **Date**: 2026-08-13

## Context

The lexer's string-literal escape handling decoded only `\n \t \r \\ \" \'`.
Every other escape fell through a default branch that re-emitted the backslash
verbatim — so `"\x41"` produced the four characters `\x41` instead of `A`,
`"A"` produced `A` instead of `A`, and `"\A"` produced `\A` instead
of the spec-mandated `A` (a backslash before a NonEscapeCharacter is that
character). Template literals had their own, separately-incomplete copy of the
same switch.

Found by adding a `-faillist` mode to the conformance runner and grouping the
`RUNTIME_NONZERO_EXIT` bucket (files that already compile *and run*, then fail
an assertion — the purest near-misses) by directory: `language/literals/string`
was the single largest cluster (27 files), all of them escape-sequence tests
whose plain `assert.sameValue` value checks this compiler can satisfy once the
escapes decode correctly. Escapes are also incidental in a large number of
otherwise-in-scope files corpus-wide (property keys, error messages), so the
blast radius was much wider than that one directory.

## Investigation

The gap was purely in `lexer.readString` (`lexer/lexer.go`) and its template
twin `readTemplateSegment`. The rest of the pipeline already treats a string as
opaque UTF-8 bytes (this compiler's string model, [TDD-00034](../tdd/TDD-00034.md)),
so decoding a code point to its UTF-8 encoding via `strings.Builder.WriteRune`
needed no downstream change. `l.src` is already `[]rune`, so multi-byte source
and the `\u{…}`/LS/PS cases fall out naturally.

The `-faillist` flag (mirroring the existing `-passlist`) was added to the
conformance runner to make this kind of near-miss hunting repeatable — it
writes each failing file as `path\treason`, so a `grep RUNTIME_NONZERO_EXIT`
surfaces the compile-and-run-but-wrong cluster directly. This is the same
measure-first discipline [ADR-00169](ADR-00169.md) established after finding
that raw first-error bucket counts mispredict real flips.

## Decision

Replace both hand-rolled escape switches with one shared
`lexer.scanStringEscape(buf, line, col)` implementing the full grammar:

- Simple: `\n \t \r \b \f \v`, and `\\ \" \' \``.
- `\xHH` (two hex digits) and `\uHHHH` (four) via a shared `readHexEscape`;
  `\u{H…}` variable-length with the ≤ `0x10FFFF` range check.
- Annex B `LegacyOctalEscapeSequence` (`\0`–`\377`, up to three octal digits,
  capped at 255 — a leading `4`–`7` takes only one more digit). A bare `\0`
  not followed by an octal digit is the ES NUL escape.
- `NonOctalDecimalEscapeSequence` (`\8`, `\9`) and every other
  `NonEscapeCharacter` fall to the default: the character itself, without the
  backslash.
- `LineContinuation`: a backslash before any line terminator (`\n`, `\r`,
  `\r\n`, U+2028, U+2029) yields nothing.
- An invalid `\x`/`\u` is a lex-time error (a `SyntaxError` in real JS), rather
  than silently mishandled.

`readTemplateSegment` calls the same helper — its former special cases (`\``,
`\$`) are subsumed (`\$` is just a NonEscapeCharacter → `$`).

## Implementation notes

- Files touched: `lexer/lexer.go`; `tools/conformance/main.go` (`-faillist`).
- Decoded code points are written as UTF-8 (`WriteRune`), consistent with the
  UTF-8 string model — a `\xHH`/`\uHHHH` above U+007F becomes its multi-byte
  encoding, not a raw byte.

## Side effects discovered

- **Embedded NUL truncates.** `"\x00"` / `"\0"` now decode to a real 0x00 byte,
  but strings are stored NUL-terminated (C strings), so a string containing an
  interior NUL is truncated there (`"a\x00b".length` is 1, not 3). A
  representation limitation, not a lexer one — documented on the String
  literals row in [LANGUAGE-CONSTRUCTS.md](../status/LANGUAGE-CONSTRUCTS.md).
- **No strict-mode rejection of legacy octal.** A legacy octal escape under a
  `"use strict"` directive should be a `SyntaxError`; it's accepted
  unconditionally (same class as the other deferred strict-mode early-error
  gaps already documented).

## Verification

- Linux (x86-64). `go build`, `go vet ./...`, `go test ./...` all pass.
- Eight new E2E tests in `tests/strings_test.go` (`\x`, `\u`, `\u{…}`,
  NonEscapeCharacter / `\8`/`\9`, legacy octal, line continuation, and a
  template with `\x`/`\u`/`\$`).
- New example `examples/strings/escape_sequences.ts`, runs with the expected
  output.
- Conformance: `language/literals/string` **65.8%** (48/73); full corpus
  **5068 → 5169 (+101)** — the wide corpus-level gain confirms escapes were
  incidental in many otherwise-in-scope files, not just the string-literal
  directory.
