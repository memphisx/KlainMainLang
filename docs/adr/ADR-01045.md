# ADR-01045: Type inference is linear in method-chain depth; static-field globals emit in a stable order

- **Relations**: `Extends ADR-01044` (its open "CODEGEN_TIMEOUT is not explained" side effect)
- **Date**: 2026-09-21

## Context

`TestE2ETopLevelAwaitTakesOneTick` — a five-link `.then` chain followed by four top-level awaits — passed, but
took 55 s on Windows x64 and 31 s on Linux x86-64. The same program through the CLI: `-emit-llvm` alone took
51.7 s for 1,670 lines of IR. That is the `CODEGEN_TIMEOUT` of Test262's
`language/module-code/top-level-await/top-level-ticks.js` / `top-level-ticks-2.js`, which ADR-01044 recorded as
unexplained ("the TypeScript transcription compiles in well under a second" was measured on a shorter chain).

Chain depth against `-emit-llvm` wall time, before: 2 links 147 ms, 3 links 190 ms, 4 links 1,331 ms, 5 links
~52 s — roughly ×8 per link.

## Investigation

A CPU profile of the test (`go test -cpuprofile`): 89 % of the time under `(*Emitter).inferExprType`, recursing
into itself directly and through `isH2ConstantsExpr` / `isFsConstantsExpr` / `inferOptionalChain`.

`inferExprType` (`codegen/llvm/emit_exprs_types.go`) decides a member access's or member call's type by asking
"what is the receiver?" once per builtin family it knows — several dozen `e.inferExprType(mem.Object)` probes in
the `MemberExpression` and `CallExpression` cases. Each probe re-infers the whole receiver, which is itself a
member call, so a chain costs probes^depth. Emission then repeats the exercise at every level.

Alternatives considered:

- Hoisting `objTy := e.inferExprType(mem.Object)` to the top of the two cases. It removes most probes but not the
  ones made through helpers (`isH2ConstantsExpr`, `inferOptionalChain`, `callbackReturnType`, …), it would infer
  receivers that today are never inferred (several early branches return before touching the receiver, and some
  receivers are not value expressions at all), and the next helper added brings the blow-up back.
- A memo kept across the whole compilation. Wrong: an expression's type depends on the scopes in force and on
  flow narrowing, both of which emission changes between two inferences of the same node.

## Decision

Memoise `*ast.CallExpression` and `*ast.MemberExpression` results **for the duration of one outermost
`inferExprType` call** (`codegen/llvm/infer_memo.go`). Inference emits no code and reads only the scope stack, so
inside one outermost call a node's type is a pure function of the scopes in force:

- the memo is created when the outermost call starts and dropped when it returns, so nothing emission does in
  between (declarations, narrowing, a function body's fresh scope stack) can be observed stale;
- inference itself pushes a scope to type a callback body with its parameters bound (`callbackReturnType`, the
  arrow-function case): `pushScope` opens a fresh memo layer, `popScope` drops it, `define` clears the current one;
- each layer records the scope stack it was filled under (its depth and the identity of the function frame's symbol
  map) and is ignored under any other, which covers helpers that replace `e.scopes` wholesale.

The previous body is unchanged, renamed `inferExprTypeUncached`.

In passing: `emitClassStaticFieldGlobals` iterated a Go map, so a class with two or more static fields produced
IR whose global order changed from build to build (4 distinct outputs in 6 runs of
`examples/types/static-field-init.ts`). The names are now sorted.

## Implementation notes

`codegen/llvm/infer_memo.go` (new), `emit_exprs_types.go` (rename), `emitter.go` (`pushScope`/`popScope`/`define`
hooks, two fields), `emit_classes.go` (sorted static fields). Test: `tests/infer_chain_depth_test.go` — a 25-link
`.then` chain, a 10-link string chain and a 6-link array chain, with a wall-clock bound.

`tools/testsel/irdiff.py` compiles a source tree to IR under two compilers (or one compiler under two
environments) and reports differing files; it is how "this changes no codegen" was checked.

## Side effects discovered

- `String.prototype.concat` is not implemented ("a string has no method 'concat'") and has no status row.
- `import.meta.url` on Windows is `file://R:\dir\file.ts`; Node gives `file:///R:/dir/file.ts`.

## Verification

Windows 11 x64: the five-link program's `-emit-llvm` 51.7 s → 0.09 s with byte-identical IR. All 347
`examples/**/*.ts` compiled with the memo on and off (a temporary switch, since removed): 340 identical IR, 7
identical compile errors (six worker modules that are not entry points, one example that needs
`-decorators=standard`), 0 differences; three further same-compiler passes: 0 differences (the static-field order
included). `TestE2ETopLevelAwaitTakesOneTick` 55.6 s → 0.35 s. Regression subset — every non-network E2E test
whose source contains an arrow function (the path where inference pushes a scope): 624 tests, 0 failures.
Linux x86-64 (Docker): the new test and the top-level-await tests pass, `TestE2ETopLevelAwaitTakesOneTick`
31.4 s → 0.13 s. macOS: not run. The two Test262 files themselves were not re-run through the conformance harness.
