# ADR-00783: Optional parameters (`f(x?: T)`) read as `T | undefined` (TDD-00187 adopter)

- **Relations**: Completes the parameter half of [ADR-00164](ADR-00164.md); the last per-site adopter in [TDD-00187](../tdd/TDD-00187.md)'s BACKLOG §1.1 cluster besides the discriminated `ReadableStream.read()` record; reuses the nullable-scalar parameter ABI of TDD-00064 Stage 3
- **Date**: 2026-09-08

## Context

An optional parameter `f(x?: number)` bound `x` to the parameter type's **zero
value** when the argument was omitted (ADR-00164) — the pre-sentinel stand-in
for `undefined`. So the body read `x` as a bare `number`, indistinguishable
from a genuine `f(0)`, and TypeScript's `x: number | undefined` typing was not
observed. This was the largest remaining `T | undefined` adoption site
(BACKLOG §1.1).

## Decision

An optional parameter with no default resolves to `undefinedableElem(T)` — a
real `T | undefined` — in the function signature, via a new `optionalParamType`
helper applied at all three signature builders (`buildParamSig`,
`buildGenericParamSig`, `buildFunctionSig`). Everything downstream already
existed: the nullable-scalar parameter ABI (TDD-00064 Stage 3) passes a scalar
`T | undefined` as its presence-flagged `{ i1, T }` aggregate and a pointer
`T | undefined` as a nullable pointer, and every call site already boxed a
provided argument into that aggregate and passed an absent aggregate for an
omitted nullable-scalar param. The only missing wiring was the omitted-argument
branch of the three **class**-call sites (constructor / instance / static),
which still emitted a bare zero — they now emit an absent `{ i1, T }`
(`zeroinitializer`) and `bindNullable`, matching the free-function path.

Consequences that fall out of the widened type for free:

- The body reads `x` as `T | undefined`; the strict gate rejects returning /
  assigning / passing it as a bare `T` (`return x` on `f(x?: number): number`
  is a compile error — narrow, `?? d`, or `!`), and `-compat=js` auto-coerces.
- A present `0` / `""` is distinguishable from an omitted argument
  (`x !== undefined`, `x ?? d`) — the parameter carries a presence bit.

Carve-outs (matching `undefinedableElem` and keeping corpus breakage small):

- A defaulted parameter (`x = 5`) is always present, so it is never widened.
- A **destructuring-pattern** parameter is skipped (its unpack expects a
  concrete aggregate).
- An **array-typed** optional parameter stays an empty array when omitted — an
  array aggregate has no spare absent state (ADR-00246), the same narrowing the
  other sentinel stages carry.
- **Generators** keep the bare-`T` optional param (their bespoke arg-binding
  path has no nullable-scalar support and no omitted-optional call form),
  a pre-existing narrowing, not a regression.

## Pointer `undefined` rendering fixed in passing

`emitStringNullToLiteral` (the concat null-guard) substituted "null" for any
absent pointer operand, so `"Hi, " + name` on an omitted `name?: string`
printed "Hi, null". It now consults the operand's static `IsUndefined` flag and
substitutes "undefined" for a `T | undefined` operand (keeping "null" for a
plain `T | null`) — Node stringifies `undefined` in a `+` as "undefined". This
also corrects the already-shipped `string | undefined` sites (`process.env.X`,
out-of-range `argv[i]`), which rendered "null" in concatenation before. The
scalar path (`console.log` of an absent `number | undefined`) already rendered
"undefined"; the bare-`console.log`-of-a-string path already did too.

## Residual (documented, shared with all nullable locals)

An un-narrowed optional **scalar** is still lenient in arithmetic: `emitIdent`
unwraps the `{ i1, T }` payload before `emitBinary` sees it, so `a + b` on an
absent `b` reads `0` rather than erroring. This is the same Stage-4 residual
noted for any un-narrowed nullable local (the static gate catches
return/assign/arg boundaries, not the mid-expression operator). Not specific to
optional parameters.

## Verification

Verified on macOS/Apple Silicon: `go test ./tests` (func/class/generic/param
suites + the updated `TestE2EOptionalParam*` and new
`TestE2EOptionalParamPresentZero`/`…StrictUndefined`), `make examples`
(the rewritten `examples/basics/optional_params.ts`), full `make test-par`, and
Node oracle flat. Two lanes unchanged.
