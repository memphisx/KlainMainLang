# ADR-00432: `new http.Agent(...)` as an inert pool-config token

- **Relations**: Extends [ADR-00429](ADR-00429.md), [ADR-00430](ADR-00430.md)
- **Date**: 2026-08-28

## Context

~18 oracle files construct `new http.Agent({ keepAlive, maxSockets, … })`
and pass it through client options. The client already treats `agent` as
a no-behavior option (ADR-00429 — one connection per request is Node's
own non-keepAlive-Agent behavior); only the constructor was missing.

## Decision

`Agent` joins the parse-time constructor names (qualified
`new http.Agent(...)`/`new https.Agent(...)` and the bare name after a
named import — `Agent` is exported from both modules' member tables).
The value is an inert single-slot handle (`IsHTTPAgent`): recognized
options (`keepAlive`/`keepAliveMsecs`/`maxSockets`/`maxFreeSockets`/
`maxTotalSockets`/`timeout`/`scheduling`) are validated and their values
evaluated but stored nowhere — there is no pool to configure; unknown
options are a clean rejection. `.destroy()` is the one method (a no-op);
everything else (`.sockets`, `.requests`, `.getName`) rejects cleanly.

Like every parse-time constructor name (`EventEmitter`, `Request`, …),
a user class named `Agent` is now shadowed by the builtin — the existing
convention's known trade-off.

## Implementation notes

`ast/nodes.go` (`NewHTTPAgentExpression`), `parser/parser_literals.go`,
`types.go` (`IsHTTPAgent`/`HTTPAgentType`), `emit_http_client.go`
(construct + `.destroy()`), `emit_exprs.go`/`emit_exprs_types.go`/
`emit_exprs_vardecl.go` dispatch/inference/var-decl,
`resolver/virtual_modules.go` (http/https `Agent` export).

## Side effects discovered

None.

## Verification

`TestE2EHTTPAgentInert` (construct with options, pass as `agent`,
destroy, full request roundtrip) plus a named-import construction check;
http/fetch/class suites re-run after the concurrent full-suite run
completed (Mac).
