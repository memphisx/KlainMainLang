# ADR-00691: HTTP server response `Date` header and HTTP/1.1 keep-alive

- **Date**: 2026-09-04

## Context

An `http.createServer` response diverged from Node.js v26 in two observable,
non-cosmetic ways that a `curl -D -` against an identical Node server exposes
immediately:

1. **No `Date` header.** Node stamps an RFC 7231 IMF-fixdate `Date` on every
   response; this server emitted none.
2. **No keep-alive.** Every response carried `Connection: close` and the socket
   was closed after a single exchange. Node/HTTP-1.1 defaults to persistent
   connections (`Connection: keep-alive` + `Keep-Alive: timeout=5`) and reuses
   the socket for subsequent requests on the same connection.

HTTP server fidelity is a top-priority area, so both were worth closing.

## Investigation

The single response writer is `__kml_http_send_response` in
`codegen/llvm/runtime_http.go`: it formatted a fixed header block
(`HTTP/1.1 %lld %s\r\nContent-Length: %lld\r\nConnection: close\r\n%s\r\n`),
wrote headers then body, and always `close()`d the fd. The per-connection fiber
dispatcher (`buildHTTPDispatcher` in `codegen/llvm/emit_http.go`) read one
request, called the handler, called `__kml_http_send_response`, stored `-1` into
the connection slot's fd, decremented `@__kml_conn_active`, and returned — ending
the fiber after exactly one request.

The dispatcher already has everything keep-alive needs: its read loop
(`readLoopL`) yields the fiber on `EAGAIN` and is resumed by the event loop when
the fd is readable again, and a `read()` of `0` (client EOF) already routes to
`noReqL`, which closes cleanly. So keep-alive is: send the response *without*
closing, reset the per-request parse state, and branch back to `readLoopL`
instead of returning — the same socket then serves the next request, and a
client close (or a `Connection: close`) tears it down through the existing paths.

## Decision

- Add `__kml_http_date(ptr buf)` (`gmtime`+`strftime`, `"%a, %d %b %Y %H:%M:%S
  GMT"`) and stamp `Date` on every buffered and chunked response.
- Give `__kml_http_send_response` an `i1 %keepalive` parameter selecting the
  connection header at runtime — `Connection: keep-alive\r\nKeep-Alive:
  timeout=5` when persistent, `Connection: close` otherwise — and skip the
  `close()` on the keep-alive path (the fiber's read loop owns the fd's fate
  then).
- Add `__kml_http_keepalive_decision(reqHeaders, extraHeaders)`: defaults to
  keep-alive, returns close when the client sent a `Connection: close` request
  header or the handler set `Connection: close` on the response (matched
  case-insensitively via `strcasestr`).
- In the dispatcher's buffered response tail, compute the decision, pass it to
  the writer, and on keep-alive reset `totalRead`/`headersParsed`/`headerEnd`/
  `contentLen`/`headersMap` and branch back to `readLoopL`; on close, retire the
  fiber as before (fd already closed by the writer).

## Implementation notes

- Files: `codegen/llvm/runtime_http.go` (new `ensureHTTPDate`,
  `ensureHTTPKeepAliveDecision`, reworked `__kml_http_send_response`),
  `codegen/llvm/runtime_http_stream.go` (Date on the chunked head),
  `codegen/llvm/emit_http.go` (keep-alive loop in the buffered tail; the two
  `__kml_http_send_response` call sites gained the flag),
  `codegen/llvm/emitter.go` (two `used*` flags).
- The keep-alive loop reuses the existing read buffer; resetting `totalRead` to 0
  and NUL-terminating on the next read means stale bytes past the new terminator
  are never scanned. Registers redefined per iteration are dominated within each
  iteration's linear flow, so no φ nodes are needed on the back-edge (same shape
  as the pre-existing `doYieldL → readLoopL` loop edge).
- Scope: keep-alive is applied to the single-shape buffered response path (the
  `res.end("…")` common case, both `http.createServer` and the bespoke
  object-return `http.listen`). The chunked-streaming and union-body tails still
  close per response (they gained the `Date` header but pass `keepalive=0`).
- LLVM textual IR tolerates duplicate `declare` lines, so `@time`/`@gmtime`
  redeclared alongside their other users is fine (same convention the existing
  date/random runtimes already rely on).

## Side effects discovered

- Request pipelining is not supported: the keep-alive reset discards any bytes
  read past the current request. Ordinary keep-alive clients (curl, browsers,
  libcurl) send one request and await its response before the next, so this is
  not exercised in practice; documented as a caveat.
- `server.close()` drains idle keep-alive connections, matching Node ≥19's
  `close()` (which closes idle keep-alive sockets rather than waiting on them).
  Three pieces: `__kml_http_keepalive_decision` answers "close" when the
  listener is already gone (a handler that calls `server.close()` before its
  response is sent gets `Connection: close`); the dispatcher's `readLoopL`
  re-checks `@__kml_listen_fd` when parked idle between requests (zero bytes of
  a next request buffered) and retires through the existing `noReqL` path; and
  `__kml_http_close` sets `@__kml_conn_poke` so those parked fibers actually
  wake to run that re-check. Without this drain, an in-process client holding
  its pooled libcurl connection open kept `@__kml_conn_active` non-zero forever
  and the process never exited (`TestE2EHTTPCreateServerNodeTestIdiom` hung,
  leaking orphaned server binaries).
- No independent idle-timeout enforcement yet: `Keep-Alive: timeout=5` is
  advertised, but the server does not itself reap a connection left idle for 5s
  while the listener is still open (it stays parked until the client closes or
  `server.close()` runs). Documented as a caveat.

## Verification

- `go build -o klainmain .` clean.
- `curl -D - http://127.0.0.1:<port>/` against a compiled `res.end("ok")` server
  shows `Date: <RFC 7231 GMT>`, `Connection: keep-alive`, `Keep-Alive:
  timeout=5`; `curl -v` two-URL run reports `Re-using existing connection`; a
  request with `Connection: close` gets `Connection: close` back and the socket
  closes — matching an identical Node server.
- New E2E tests `tests/http_response_headers_test.go`
  (`TestE2EHTTPResponseDateAndKeepAlive` asserts Date + `Keep-Alive` and a
  reused connection via `httptrace`; `TestE2EHTTPResponseConnectionClose`
  asserts client `Connection: close` is honored) pass.
- The full HTTP/server/cluster/stream/websocket/fetch and createServer/listen
  E2E suites pass unchanged (`go test ./tests/ -run 'HTTP'`), including
  `TestE2EHTTPCreateServerNodeTestIdiom` exiting cleanly via the idle drain.
- Example `examples/http/keepalive_and_date.ts` added.
