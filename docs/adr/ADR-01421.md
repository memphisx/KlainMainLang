# ADR-01421: Symbol-keyed properties in reflection and spread

- **Relations**: Implements TDD-00246; Extends ADR-01414
- **Date**: 2026-10-05

## Context

TDD-00246's last pieces: `Object.getOwnPropertySymbols` was not a function
(a run-time "is not a function"), `Reflect.ownKeys` returned the string keys
only (so `EventEmitter.prototype.eventNames()` left out symbol event names,
a recorded caveat), and a spread or `Object.assign` of a class instance
dropped its symbol-keyed fields, where Node copies them.

## Decision

- A shape row (shape.c's `KmlShape`) carries `syms`: for each layout key,
  the global holding the symbol of a symbol-keyed field, NULL for a string
  key (null for the row when it has none).
- `Object.getOwnPropertySymbols(o)` boxes `o` and calls
  `__kml_own_symbols_c` (shape.c, `KML_OWN_SYMBOLS`): a static object's
  symbol-keyed fields from its row and the symbol keys added to it, or a
  dynamic object's symbol keys (`"\x01@@sym:%p"`), as a `symbol[]`.
- `Reflect.ownKeys(o)` is getOwnPropertyNames then getOwnPropertySymbols
  of the once-evaluated `o`, joined boxed (`__kml_own_keys_c`), typed
  `(string | symbol)[]` as declared.
- `Type.SpreadFields` (the string-keyed fields, then the symbol-keyed ones)
  is what a static spread copies and types its result with; a copy into a
  dynamic object stores a symbol-keyed field under its symbol's key
  (`fieldPropertyKey`), as does a boxed object's run-time spread
  (`__kml_shape_spread` through the row's `syms`).

## Verification

Mac (M4): `TestE2ESymbolReflection` matches Node (`getOwnPropertySymbols` of
a class instance and a dynamic object, `Reflect.ownKeys`, `typeof` of its
elements, spread and `Object.assign` of a class instance, `eventNames()`
with a symbol event); `go test ./codegen/llvm` (shape row layout probes);
`go test ./tests -run 'Reflect|OwnKeys|OwnProperty|Spread|Symbol|Shape|Assign'`.
