# ADR-00329: Node `dns` extras — `resolve4` and `promises.lookup`

- **Relations**: Extends ADR-00326 (dns.lookup — reuses its getaddrinfo helper)
- **Date**: 2026-08-23

## Context

`dns` shipped `dns.lookup` only (ADR-00326). This rounds out the module with the
two next-most-useful surfaces, both over the same `getaddrinfo` backend: the
all-records form `dns.resolve4` and the Promise form `dns.promises.lookup`.

## Decision

- **`dns.resolve4(host, (err, addresses: string[]) => …)`** (and the V1 alias
  `dns.resolve`): a new runtime `@__kml_dns_resolve4(host) -> { ptr, i64 }` runs
  `getaddrinfo` and walks the `ai_next` linked list (offset **40** on both
  Darwin and glibc), collecting every result's IPv4 dotted quad into a malloc'd
  pointer array, returning the `{ data, count }` aggregate — the same
  runtime-array shape `os.cpus()` uses (`{ptr, i64}` → `ArrayOf(...)`). The emit
  side fires the callback with the address array, or `(Error, [])` when the
  count is zero.
- **`dns.promises.lookup(host)`** → `Promise<{ address, family }>`: reuses
  `@__kml_dns_lookup`; on success builds a `{ ptr address, i64 family }` object
  and stores it into a fulfilled task promise, on failure rejects the promise
  with an `Error`. Both branches mutate one pre-allocated promise so the two
  control-flow paths converge on a single value (no phi).

## Implementation notes

- `runtime_dns.go` gains `@__kml_dns_resolve4`; the `ai_addr` field offset still
  uses the platform-branched `dnsAiAddrOffset()` (24 glibc / 32 Darwin), while
  `ai_next` is 40 on both (verified via the same on-machine offsetof probe used
  in ADR-00326).
- `emit_dns.go` gains `emitDnsResolve4` and `emitDnsPromisesLookup`.
  `dns.promises.lookup` is a two-level member chain (`dns.promises` is a
  pseudo-namespace, not a bindable value), dispatched in `emit_call.go` with its
  own shape check mirroring `process.stdout.write`, with a matching
  `inferExprType` case returning the task `Promise` type.
- Reuses `emitAllocSettledPromise`/`storePromiseValue`/`emitSetPromiseState`/
  `emitAsyncGenRejectPromise` (promise machinery) and `buildErrorObj`.

## Side effects discovered

None. `dns.resolve4` uses `getaddrinfo` (system resolver) rather than issuing
real DNS `A` queries, so it returns the same set the OS resolver would for a
`lookup` — no `dns.resolve6`/`resolveMx`/`resolveTxt`, disclosed as caveats.

## Verification

- `tests/dns_test.go`: `resolve4("localhost")` contains `127.0.0.1`;
  `promises.lookup("localhost")` resolves `{address:"127.0.0.1", family:4}`; a
  bogus host rejects.
- `examples/dns/resolve_promises.ts` run on macOS (arm64), exits 0.
- Machine: verified on Mac (Apple Silicon). Linux uses `ai_addr` offset 24;
  `ai_next` 40 on both — not separately re-run this session.
