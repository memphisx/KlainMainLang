# ADR-01096: A bigint in `any`, and `bigint | undefined` slots

- **Relations**: `Implements TDD-00229`, `Extends TDD-00228`
- **Date**: 2026-09-23

## Context

`node:ffi`'s `lib.symbols` holds bigints in a dynamic object. Probing that:

- `const x: any = 5n` gave `typeof x === "string"` and printed nothing:
  `emitBoxValue` had no bigint arm, so the bigint pointer fell through to the
  string-kind case.
- `console.log(map.get(missing))` on a `Map<string, bigint>` segfaulted
  (the digit conversion was handed a null bigint), and any comparison or
  arithmetic with such a `bigint | undefined` value crashed the same way.

## Investigation

The NaN box has no free pointer kind ([TDD-00228](../tdd/TDD-00228.md)).
TDD-00228's plan tells handles apart by a field-0 type-id with flag bit 46,
assuming a plain object's field 0 is below 2^46 — not true on macOS/arm64,
whose heap addresses (≈`0x6000_0000_0000`) already exceed 2^46, and a number
field's raw double bits can set any bit. A single-bit probe would misfire.

## Decision

- Box a bigint as a 16-byte cell `{ i64 magic, ptr bigint }` tagged
  `kmlTagObject`, made only when a bigint crosses into a dynamic slot. The
  magic `0x7FF40000B1616B16` is compared for exact equality: a non-canonical
  NaN pattern no JS number or pointer takes, with bits 47/48 clear so neither
  the Symbol nor the Error probe can mistake it.
- Consumers: `typeof` → `"bigint"`; `console.log` → `5n` (IR and `dynjson.c`);
  `String()`/template → digits; `===` compares two cells by value
  (`__kml_any_eq`); unboxing into a `bigint` slot (`coerce`,
  `emitUnboxBoxToType`) yields the bigint (null otherwise);
  `JSON.stringify` throws "Do not know how to serialize a BigInt".
- The dynamic runtime is always present but the bigint runtime is linked only
  when a program uses bigints, so `dynjson.c` and `any_eq` reach bigints through
  two finalize-time IR hooks (`__kml_boxed_bigint_str`/`_eq`): real calls when
  the program links the bigint runtime, inert stubs otherwise (no cell can
  exist then).
- `bigint | undefined`: `emitBigIntToString` renders a null bigint as
  `undefined`/`null`; `emitBigIntBinary` orders an absent operand as false,
  compares absent == absent as equal, and throws "Cannot mix BigInt and other
  types, use explicit conversions" for arithmetic.

## Implementation notes

`emit_bigint_box.go` (cell, probe, hooks), `emit_dynamic.go` (box, render,
typeof), `emit_narrowing.go` + `emit_exprs_coerce.go` (unbox),
`runtime_dynamic.go` (`any_eq`), `dynjsonsrc/dynjson.c`, `emit_dynobj.go`
(stringify error), `emit_bigint.go` (nullable operands).

## Side effects discovered

A first version rendered the bigint arm with `emitBigIntToString`, which marked
the bigint runtime as used in *every* program that renders an `any` — decorator
tests then failed to link `__kml_bigint_cmp`. Routing through the hook keeps
the bigint runtime out of programs without bigints.

## Verification

`tests/bigint_any_test.go` (`TestE2EBigIntInAny`, `TestE2EBigIntMaybeUndefined`)
against Node 24.19.0; full `make test-par` on macOS/arm64 (M4).
