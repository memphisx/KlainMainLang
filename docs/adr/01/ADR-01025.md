# ADR-01025: Windows fd layer — refcounted descriptions, one owned pool

- **Relations**: `Implements TDD-00183` (Stage 3); `Extends ADR-00864` (the kind-tagged fd table), `ADR-00865` (Stage 1), `ADR-01022` (Stage 2), `ADR-01024` (Stage 4)
- **Date**: 2026-09-20

## Context

The Windows fd layer (`codegen/llvm/win32src/win32io.c`) kept one state record *per fd number*, and the fd's number encoded what it was:

- `[0, 512)` CRT fds — files, the std fds, and every pipe end (`_open_osfhandle`);
- `[512, 896)` sockets this layer owns — a hard **384-socket cap**, however few files or pipes were open;
- `[896, 1024)` foreign (libcurl) sockets — "is foreign" was literally `fd >= 896`.

Because state was keyed by number, `dup2(sock, newfd)` could only *copy* the socket handle into a second record (`kfd_adopt_socket`). The two fds then had no shared lifetime: closing either one ran the full teardown (`shutdown`, `closesocket`) and left the other holding a dead handle; readiness, the non-blocking flag and pending overlapped ops were per-copy. POSIX's model is one *open file description* shared by both fds and destroyed by the last `close`. These are the last two symptoms on TDD-00183's list (TDD-00180 §1): the 384-socket cap and `dup2`-of-socket aliasing.

## Investigation

- All 218 state accesses had one shape, `kfd[fd].field`, all inside `win32io.c`; the other shim files reach the table only through `kfd_kind_of` / `kfd_handle` / `kfd_register` / `kfd_adopt_socket` / `kfd_set_inherited`. So the representation could change under a stable accessor surface.
- Completions and reader threads referred back to their fd by **number + generation** (`op->fd`, `kfd_thr.fd`). Under sharing that is wrong in a new way: closing the fd an op was issued *through*, while an alias stays open, would mark a perfectly live op stale and drop its readiness. They have to refer to the description.
- Who calls `dup2` on this platform: nothing in the emitted IR. The three fork+exec sites hand a child its stdio by handle through `__kml_win_spawn` (`runtime_spawn_win.go`); their `dup2` calls are in the POSIX branch. So aliasing is reachable only from C-level callers — which is why it is verified natively (below) rather than by an E2E program.
- Moving pipe ends out of the CRT range means nothing may hand a pipe fd to a raw CRT call. Audit of the shim: `dprintf` used `_write(fd)` and `isatty` used `_get_osfhandle(fd)` — both would misbehave on any pool fd (they already did for sockets). `fstat` already dispatched through `kfd_handle`.
- Slot allocation had no synchronisation although every worker thread opens its own sockets and pipes (a first-free scan racing another thread's). A free-list pool would turn that latent race into list corruption.

## Decision

**Descriptions.** An fd is an index into `kfd_tab[1024]`, a table of pointers to `kfd_desc` — the open file description: handle (`sock`, or `h` for an owned pipe end), `kind`, `refs`, flags, and all overlapped/reactor state. `dup2` points the new slot at the same description (`refs++`); `close` drops a reference, and only the last one runs the teardown (cancel ops, flush the write queue, stop a reader thread, `shutdown` + drain + `closesocket` / `CloseHandle`). Readiness bits, `O_NONBLOCK` and pending ops therefore belong to the description and are seen through every alias, as on POSIX.

Descriptions come from a static pool with a free list and are **never returned to the heap**: an op (`op->d`) or reader thread (`t->d`) that outlives its fd can always read the description it was issued on, and the generation — bumped when a description is retired, preserved across reuse — is what marks it stale. This keeps Stage 1's safety model exactly, moved from the slot to the description. The port drain resolves everything through `op->d` (`kfd_wq_pump` and `op_wsa_error` take the description), never through `op->fd`, which is kept for tracing only.

A plain CRT fd (a regular file, an unclassified std fd) has no pooled description; its few flags live in `kfd_plain[fd]`, and `KD(fd)` resolves to whichever applies. When `kfd_classify` finds a std fd to be a pipe or the console it is *promoted* to a pooled description with `crt_fd` set: the CRT keeps the handle and closes it, the description carries the reactor state.

**One owned pool.** Sockets, pipe ends and foreign sockets all allocate first-free from `[512, 1024)`. The 384-socket cap becomes a shared 512-slot pool, pipe ends no longer consume CRT fds (`pipe()` hands out pool fds backed by their own handles; reads/writes are `ReadFile`/`WriteFile` on the handle), and **foreign-ness is the description's kind** (`KFD_FOREIGN`), not a number range. The remaining ceiling is the IR's 1024-bit `fd_set`; widening it is IR-side work outside this TDD and is the documented limit that replaces the 384 cap. A full pool answers `EMFILE`.

**`dup2` onto a CRT-range number.** The description shadows that number — all I/O dispatches through this layer by kind. So the CRT cannot later hand the same number to an `_open`, a shadowed slot in `[3, 512)` is parked on `NUL` (`_dup2(nul, fd)`, which also closes whatever CRT file was open there, as `dup2` must) and released with the slot. The std fds are always open in the CRT, so they are shadowed without parking, and replacing a classified std fd's description leaves the CRT fd open underneath. A plain CRT *file* is still duplicated by the CRT's own `_dup2` (CRT fds share a file object the same way) and can only target a CRT-range number.

**Locking.** Slot and pool mutation — allocate, bind, `refs` changes, retire — is under one `SRWLOCK`. I/O on an fd stays unsynchronised and with its owning thread, as before.

**Foreign sockets per thread.** Each reactor thread drives its own libcurl multi handle, but the sweep in `curl_multi_fdset` retired *every* foreign slot the current call had not reported — including another thread's. Foreign descriptions now record the reporting thread, and lookup and sweep are confined to it.

## Implementation notes

- `win32io.c`: `kfd_desc` (+ `h`, `refs`, `crt_fd`, `owner_tid`, free-list link), `kfd_tab`/`kfd_plain`/`kfd_pool`, `KD(fd)`, `kfd_desc_new`/`kfd_desc_retire`, `kfd_slot_new`/`kfd_slot_release`, `kfd_promote_crt`, `kfd_park`/`kfd_unpark`, `kfd_desc_handle`; `dup2` and `close` rewritten; `kfd_register`/`kfd_adopt_socket` allocate from the pool; the 218 accesses converted mechanically to `KD(fd)->`.
- `win32shim.c`: `dprintf` writes through the layer's own `write()` (bound by asm label — `io.h` declares a different `write`), `isatty` asks `kfd_handle`.
- The `KML_IO_TRACE` port-op line gains `foreign=0|1`, and `close` reports `refs=`. `tests/reactor_windows_test.go`'s libcurl-socket assertion reads the flag instead of `fd >= 896`.
- The description is cleared on allocation, so the old per-field socket reset on close is gone; only the generation and the lazily-created inline-wait events survive recycling.

## Side effects discovered

- The cross-thread foreign-slot sweep above (fixed here).
- `dprintf`/`isatty` on a socket fd reached raw CRT calls before this change too (fixed here).
- One boundary left as designed: if a classified std fd is closed while an alias of it remains, the CRT fd stays open underneath until the last reference goes (the description reads and writes through it), so the closed *number* still answers at the CRT level. Reachable only by a C caller that uses an fd after closing it.

## Verification

Windows dev box (Windows 11 26200, MSYS2 UCRT64 clang):

- `tests/fd_descriptions_windows_test.go` builds `tests/testdata/win32/fd_descriptions.c` against the shim sources and drives it natively: a socket alias keeps working after the original fd closes (ping/pong), the closed number is reused without disturbing the alias, the peer sees EOF only after the *last* close; both aliases report readable from one `select`; pipe fds are pool fds, a write-end alias keeps the pipe open and the reader sees EOF only after the last close; exactly 512 sockets open from the pool, the next answers `EMFILE` (as does `pipe()`), and the pool is usable again once drained. Before this change the first step fails (`dup2` refused any target outside the socket range, and a same-range alias died with the original).
- `tests/reactor_windows_test.go` (incl. the libcurl foreign-socket case), `tests/reactor_emulated_windows_test.go`, `tests/timer_precision_windows_test.go`.
- The full `./tests` package, and `make conformance`.
- Linux/macOS untouched (Windows-only C behind the shim boundary).
