# ADR-01866: A static initializer's `this`, and Function's members on a class value

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's AssignmentExpression bucket)
- **Date**: 2026-10-21

## Context

- A static field initializer reading the class (`static f = this.g`, `static h = (className = this.name)`) was typed while the class's value type was still being built, so its `this` met the cycle guard and was unanswered, and so was the field's type in `typeof C`. Static methods already saw the members typed so far (a partial snapshot of the class value); static fields did not.
- A class value had no `name` or `length`: tsc reads Function's members on `typeof C`, the checker only on function types.

## Decision

- The class value's snapshot starts before the static fields: each static field typed joins it, as each static method already did.
- A member a class value (or another callable object type) lacks reads Function's member, unless the class declares a static of that name the snapshot does not hold yet.

## Consequences

- `TestStaticInitializerThis` holds tsc 5.6's declaration types; Test262's `class-name-static-initializer-*.js` leave the shadow report.
- Verified on Apple Silicon.
