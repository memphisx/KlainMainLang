# ADR-01067: util.inspect line layout — Node's 80-column break, column grouping, depth 2 and string quoting

- **Relations**: Extends ADR-00218 (structured object rendering), ADR-00221 (inspect depth cap), ADR-00583 (`console.dir` depth), ADR-01063 (optional-field presence in inspect), TDD-00212 (any-boxed array rendering)
- **Date**: 2026-09-22

## Context

BACKLOG §0 item 6: `console.log` of an object or array was always one line; Node splits past its 72/80-column
`breakLength`, groups long arrays into aligned columns, and indents nested entries. Every multi-line Node output
(a table of rows, a list of records, a long numeric array) diverged, which shows up in any test that compares
console output against Node.

## Investigation

- Node's algorithm (`lib/internal/util/inspect.js`): `formatValue` renders each entry to a string, then
  `reduceToSingleString` decides: with `compact: 3`, an array of more than 6 entries first goes through
  `groupArrayElements` (columns sized from the widest entry, at most 16 per row / `breakLength`, numbers
  `padStart`, others `padEnd`); then, if `ctx.currentDepth - recurseTimes < compact` (the value nests fewer than
  three levels below this container) and grouping did not change the entry count, the entries join on one line
  when `output.length + indentation + braces + 10 + Σ widths ≤ 80` and none contains a newline; otherwise one
  entry per line at `indentationLvl + 2`. `ctx.currentDepth` is set to the depth of every *non-empty* container as
  it is entered and never reset, so after the children it holds the depth of the deepest recently visited one.
- The default `depth` is 2 (`[Object]`/`[Array]` at depth 3), and an empty `{}`/`[]` early-returns *before*
  the depth check. This compiler capped at 4 — the existing `TestE2EInspectDepthCap` asserted
  `{ a: { b: { c: { d: { e: [Object] } } } } }` where Node prints `{ a: { b: { c: [Object] } } }`, its comment
  notwithstanding. The dynamic inspector (`dynjson.c`) already used 2.
- Both inspectors (`emit_inspect.go` for typed values, `dynjson.c` for `any`) concatenated as they went, so
  neither could know the total width or the nesting below before committing to a layout. The layout also needs
  the *display width* of already rendered entries, `sqrt`, and padding — a runtime, not codegen.
- Quoting: `emitInspectField` wrapped every string in `'…'`; Node escapes control characters (`'x\ny'`) and
  chooses the quote (`"it's"`, `` `both ' and "` ``). An embedded newline also drives the layout decision.

## Decision

1. **A runtime entry list** — `inspectsrc/inspect_reduce.c`, compiled in (`EmbeddedCSources`, libm) only when a
   structured value is inspected: `__kml_inspect_begin(depth, nonempty)` (records `currentDepth` for a non-empty
   container), `__kml_inspect_push(list, entry)`, `__kml_inspect_end(list, open, close, indent, depth, isArray,
   numeric)` — `groupArrayElements` + `reduceToSingleString` verbatim, returning the rendered string;
   `__kml_inspect_quote(s)` is Node's `strEscape`.
2. **Both inspectors feed it.** `emitInspectObject`/`Tuple`/`Array`/`Collection` (Map/Set) push one rendered
   entry each and call `inspectEnd` with `open` = `{` / `Point {` / `[` / `Map(2) {`; `dynjson.c`'s
   `inspect_obj`/`inspect_arr`/`kj_inspect` do the same through the extern ABI. A dynamic value nested in a
   static container carries its depth (`__kml_*_inspect_at(ptr, depth)`, `emitDynamicInspectAt`) so its
   indentation and depth cap continue rather than restart.
3. **Depth 2** (`maxInspectDepth`), with an empty object/tuple/array still `{}`/`[]` past the cap (a runtime
   length test for arrays; an absent `T[] | undefined` stays its keyword). `console.dir({ depth })` is unchanged.
4. **Numeric right-alignment** follows Node's `typeof value[i] === 'number' | 'bigint'`: a numeric/bigint element
   type (static), all-number tags (dynamic), a numeric box kind (boxed static array).

## Implementation notes

- New: `codegen/llvm/inspect_c.go`, `inspectsrc/inspect_reduce.c`; `tests/compiler_test.go` gains
  `appendInspectReduce` (the test build mirrors `EmbeddedCSources`, as every sidecar does). `dynjson_c.go` pulls
  the inspect file in whenever it is linked, since `dynjson.c` now references its symbols.
- Display width counts UTF-8 code points (Node's `getStringWidth` also doubles full-width glyphs; not needed by
  anything rendered here yet).
- `open`/`close` are plain C strings inside the helper; entries are header strings (their length is read by
  `strlen`, valid because an inspected string is rendered escaped and never embeds a NUL).
- Node's `maxArrayLength` (100, then `... n more items`) is not implemented; every element is listed.

## Side effects discovered

- `util.inspect` of a *string* still truncates at an embedded NUL when the string is rendered by the older
  `emitValueToString` paths (top-level `console.log("a\u0000b")`); inside an inspected container it is now
  `'a\x00b'` (Node). BACKLOG §0 item 2 keeps the NUL family.
- A non-identifier key is quoted only by the dynamic inspector (`{ 'a-b': 1 }`); a static object field is always
  an identifier, so nothing to do there.
