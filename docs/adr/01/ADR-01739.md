# ADR-01739: Captures inside a repeated non-capturing group are cleared per iteration

- **Relations**: `Implements TDD-00230`, Extends [ADR-01738](ADR-01738.md)
- **Date**: 2026-10-19

## Context

ES clears a quantified atom's captures at the start of each iteration. After `/(?:(a)|b)*/` matches `"ab"`, group 1 is `undefined`. PCRE2 keeps the `"a"` from the first iteration. The post-match fixup (`__kml_regex_fix_optional`) already cleared stale captures inside a repeated *capturing* group, using that group's own start. A non-capturing group records no start, so its stale captures survived.

## Decision

- **Marking (`iter_mark`, after `empty_iter_guard`):** a non-capturing group that holds a capture and is repeated (`*`, `+`, `{n,m}`, but not `?`, `{0,1}` or `{1}`) becomes `(?:(?C"sk")(?:X)(?C"ek"))`. The inner group keeps both string callouts outside X's alternatives.
- **The callout:**
  - `sk` notes where the iteration under way starts;
  - `ek`, reached when an iteration completes, records that start as the last iteration's, along with the match attempt it was in.
- **After the match:** `__kml_regex_note_optional` notes the group's capture range. The fixup unsets every capture in that range that starts before the last iteration, provided the record belongs to this attempt (it starts at the match's offset). Each pattern's marks are reset after each match, failed matches included.

## Verification

macOS (Apple Silicon), against Node:

- `tests/regexp_captures_test.go` TestE2ERegexRepeatedGroupClearsCaptures covers `exec`, `replace` with `$1`, `matchAll`, `split`, named groups, a nested group, lazy, `+`, `{2,3}`, a global regex and backtracking into an earlier alternative.
- The RegExp, match, replace and split families pass.
