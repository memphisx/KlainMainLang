# ADR-00746: Windows CI — the failures the header fix uncovered (curl arg-mangling, packaging COFF, EventSource reconnect)

- **Relations**: Follows [ADR-00741](ADR-00741.md) (the header-drift fix that let the Windows suite actually run on the CI lane, exposing these); extends [ADR-00726](ADR-00726.md) (`-package` GUI exe), [ADR-00719](ADR-00719.md) (the EventSource refused-connect grace); the `isWindows` half is [ADR-00739](ADR-00739.md)
- **Date**: 2026-09-07

## Context

Once [ADR-00741](ADR-00741.md) made the Win32 shim compile against the runner's headers, the Windows CI lane ran the whole suite for the first time — and ten tests failed that had been masked for the entire life of the port by the compile/link failure. They passed locally, so only the runner surfaced them. Three distinct causes (plus the `isWindows` probe expectation, covered by ADR-00739):

1. **HTTP/2, HTTPS and h2c version assertions** (7 tests) — the runner reported `got "...|%http_version"`. The tests probe the negotiated version with `curl -w '%{http_version}'`. On the runner, `exec.LookPath("curl")` resolved to the **MSYS2 runtime curl** (`\msys64\usr\bin\curl.exe`, on `PATH` for the coreutils the child_process tests need), which is `msys-2.0.dll`-linked and glob-expands its own argv the Cygwin way: `%{http_version}` → `%http_version` (single-element brace expansion strips the braces) and `\n` → `n`. The server was correct — only curl's write-out was mangled. The native mingw curl (`\msys64\ucrt64\bin\curl.exe`) does not do this, which is why local runs passed.

2. **`-package` GUI exe** — `app.res: file format not recognized` at the GUI relink. `llvm-rc` and `windres -O res` emit a Microsoft `.res`, which the mingw `ld`/`lld` driver cannot link; it needs a **COFF object**.

3. **`EventSource` onerror** — a refused connection fired `onerror` twice on the runner: the default 3s auto-reconnect fired again inside the 4s Windows grace window before `.close()`. Locally the slower refused-connect detection hid it.

## Decision

1. A `nativeCurl()` test helper resolves curl to the native mingw binary from the compiler's UCRT sysroot (`$KLAIN_SYSROOT\bin\curl.exe`, else the first curl on `PATH`), and all 13 `curl` invocations in `http_test.go` go through it. It ignores `PATH` order, so the msys curl can sit first (for coreutils) without being picked for the write-out probes. The native curl also carries nghttp2, which the h2/h2c tests need anyway.

2. `compileRC` now produces a COFF object (`app.o`): `windres -O coff` first (MSYS2 binutils, always in the toolchain), `llvm-rc` + `llvm-cvtres` as the fallback. The packaged exe links the object directly.

3. `TestE2EEventSourceOnErrorFires` closes the source inside `onerror` (stopping the reconnect) and guards the print, so exactly one `error` is asserted regardless of how fast the refused connect is detected. The backstop `setTimeout` close remains.

## Consequences

- All ten runner failures pass on Windows 11, verified with the mangling msys curl placed first on `PATH` (the exact runner condition) — the version assertions, the GUI package, and the EventSource error all hold.
- The curl fix is test-only; the packaging fix ships in `klainmain` (`-package`); the EventSource fix is test-only (the runtime reconnect behavior is correct and unchanged).
- These were never green before because the lane never got past the shim compile; ADR-00741 + this ADR are what a first green Windows lane needs together.
