# ADR-00395: `process.execPath` and `process.emitWarning` (TDD-00131 process stage)

- **Relations**: Implements TDD-00131 (per-module Node API fidelity); Extends ADR-00026 (process introspection)
- **Date**: 2026-08-27

## Context

Continuing TDD-00131's per-module Node-API fidelity work on the `process`
module (the top failing module in the Node `test/parallel` oracle by fail count,
and project priority #3 — process/argv/stdin). A usage tally over the corpus's
`test-process-*.js` files ranked the missing portable APIs; `execPath` (24 uses)
and `emitWarning` (12) were the highest-value ones that are real application
surface rather than Node internals (`process.binding`/`config`/
`getActiveResourcesInfo`/`allowedNodeEnvironmentFlags` are internal and stay out
of scope).

## Decision

- **`process.execPath`** — the absolute, symlink-resolved path of the running
  executable. This compiler has no separate runtime binary (the compiled program
  *is* the executable), so execPath is its own path — the same value Node fills
  for a single-executable/bundled binary. Resolved by a platform-specific runtime
  helper `__kml_execpath()` (macOS `_NSGetExecutablePath` + `realpath`, Linux
  `/proc/self/exe`), **not** raw `argv[0]`: Node guarantees execPath is absolute,
  whereas argv[0] can be `./bin` or a bare PATH name. Host-only, like
  `process.platform`/`arch` (this compiler doesn't cross-compile).
- **`process.emitWarning(message, type?)`** — writes `(node:<pid>) <type>:
  <message>` to stderr, `type` defaulting to `"Warning"`, matching Node's default
  warning format. The options-object form (`{ code, detail }`), the `'warning'`
  process event, and Node's first-warning `--trace-warnings` hint line are out of
  V1 scope — this is the plain textual emission the vast majority of callers use.

## Fixed in passing

`process.cwd()` returned a raw `getcwd()` pointer with no length header, so
`.length` (and any header-based string op) read garbage — a pre-existing bug
the execPath work surfaced, since execPath needed the same fix. Both now copy
their raw libc string into a length-prefixed one (`__kml_str_from_cstr`), the
same boxing `process.env` already used.

## Consequences

Both verified byte-identical to Node v26 (Mac): execPath resolves to the same
absolute path regardless of how the binary is invoked (`./bin` vs absolute), and
the warning lines match Node's format. `process.version`/`versions` — the other
high-use gap (23) — is deferred to [TDD-00136](../tdd/TDD-00136.md): what a
non-Node compiled binary should report there is a genuine design decision (a
too-new version string would mislead feature-probing scripts), not a mechanical
addition.
