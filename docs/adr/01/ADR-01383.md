# ADR-01383: A Date in a nullable slot, setTime's TimeClip, and an Invalid Date's getters and setters

- **Relations**: Extends ADR-01315, ADR-00488
- **Date**: 2026-10-04

## Context

Conformance of the tree through ADR-01381 measured one file of invalid IR
in both lanes, `staging/sm/Date/timeclip.js`: a `var d = new Date()` in a
`for` body, then `d.setTime(times[i])` and `d.getTime()`. Before
ADR-01381's binder fix the file stopped at an earlier compile error.

## Investigation

- A `var` declared in a loop body is hoisted as `Date | undefined`, a
  `{ i1, i64 }` slot. The receiver's absent case is guarded, then
  `emitDateCall` used the whole pair as the `i64` time value
  (`sitofp i64 %agg`).
- `emitDateSetterCall` stored the bare `i64` over the pair's first field,
  so after the loop `d` read as `undefined`.
- `setTime` converted its argument straight to `i64`:
  `setTime(Infinity)` stored INT64_MAX instead of TimeClip's NaN, and the
  result was that integer.
- An Invalid Date's field getters decomposed the sentinel
  (`getFullYear()` printed 292278994), and a setter on one composed a
  date from it.

## Decision

- `emitDateCall` takes the payload of a nullable Date receiver.
- The setters read and write a nullable slot through its pair, storing it
  present.
- `setTime(t)` is TimeClip(ToNumber(t)) (`emitTimeValueToDate`, as
  `new Date(ms)` uses) and returns the new time value.
- The field getters (local and UTC) are `NaN` for an Invalid Date; the test
  is made before the local-time shift.
- `setFullYear`/`setUTCFullYear` on an Invalid Date start from +0; every
  other setter leaves it invalid. Every setter returns the new time value
  as a number, `NaN` when invalid; inference types the getters and
  setters as numbers (doubles), as `getTime` already was.

## Implementation notes

`codegen/llvm/emit_date.go` (`emitDateCall`, `emitDateSetterCall`),
`emit_exprs_types.go` (`inferMethodNameType`).

## Side effects discovered

- Under the strict lane `timeclip.js` still fails at run time: its
  `function addToLimit(n)` takes the unannotated `n` as an integer
  (ADR-00042), so `addToLimit(0.5000000000000001)` stays in range. TypeScript
  types `n` as `any` there.

## Verification

Mac (Apple Silicon): each case above against Node in both lanes;
`timeclip.js` gives valid IR in both lanes and passes in the js lane. Tests:
`TestE2EDateInLoopVar`, `TestE2EDateInvalidGettersSetters`, the existing
`Date` tests. Example: `examples/jsmode/invalid_dates.js`.
