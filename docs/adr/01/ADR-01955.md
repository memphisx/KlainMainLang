# ADR-01955: A generator's parameter is not the generator

- **Relations**: Implements TDD-00230 (P2.3)
- **Date**: 2026-10-29

## Context

The shadow report over the examples, tools and apps showed 1932 of its 2204 disagreements (`make shadow-report`) in two buckets: identifiers inside `node:stream`'s operator generators (`mapGen(stream: Readable, …)`), where codegen's inference held a class instance and the front end's representation said `any`. The checker itself typed them correctly. The front end's representation step has a rule for a generator function read as a value (a boxed constructor closure). It recognised the generator by the declaration node of the name's symbol, and a parameter's declaration node is its function. Every read of a generator's parameter, sync or async, was therefore taken for the generator itself.

## Decision

The rule applies only to the generator's own binding: a parameter symbol (`FunctionScopedVariable` declared by a function node) is excluded. A `var g = function* () {}` binding is unaffected, since its declaration is the variable.

## Consequences

- The report's two largest buckets are gone; probes over sync and async generators, their self-references and a generator expression's own name report no disagreement.
- The generator suites pass, and the E2E suite passes on Linux (x86-64).
