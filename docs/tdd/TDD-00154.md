# TDD-00154: Enforce the `readonly` class-field modifier

- **Status**: Implemented

- **Date**: 2026-09-01

## Context

The TS `readonly` field modifier — on a plain field (`readonly x: number`) and on
a constructor parameter property (`constructor(readonly x: number)`) — was parsed
and then **erased**: a later write was silently accepted ([ADR-00447](../adr/ADR-00447.md)/[ADR-00480](../adr/ADR-00480.md)). TypeScript treats a write to a
readonly field outside the declaring class's constructor as a compile error; this
was a disclosed fidelity gap on two status caveats (class field + parameter
property). Enforcement is a pure compile-time check — no runtime IR — so it is a
clean, bounded completion.

## Design

`readonly` is recorded, not erased, and a write is checked at emit time.

- **Parser**: the class-member modifier loop records `readonly` into a new
  `AnnotField.Readonly` flag (previously it advanced past the token and dropped
  it). The parameter-property path feeds the already-parsed `Param.PropReadonly`
  into the same flag.
- **Registration**: `registerClasses` collects readonly instance-field names into
  `ClassInfo.ReadonlyFields` (own + inherited, mirroring `FieldOrigin`).
- **Context**: a new emitter flag `currentCtorClass` is set to the class name
  while its constructor body is emitted (covering field initializers, which are
  spliced into the constructor), and cleared for any nested function/closure body
  emitted inside it — so a `readonly` write in an arrow nested in the constructor
  is still an error, matching TS.
- **Check**: the class-field-assignment path (`emit_exprs_assign.go`) calls
  `checkReadonlyWrite`, which rejects a write to a readonly field unless
  `currentCtorClass` equals the field's **declaring** class (`FieldOrigin`). This
  makes a write in a regular method, an outside `obj.x = v`, or a *subclass*
  constructor writing an inherited readonly field all clean errors — exactly TS's
  rule.

Only the declaring class's own constructor may set it; the check keys on
`FieldOrigin`, not merely "inside some constructor".

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| `readonly` parsing (contextual) | Built | Was erased; now recorded in `AnnotField.Readonly` |
| `Param.PropReadonly` (parameter property) | Built | Fed into the same field flag |
| `FieldOrigin` per-field provenance | Built | Reused to identify the declaring class |
| Constructor emission site | Built | Wrapped to set `currentCtorClass` |

## Open questions

- **`readonly` array/tuple element mutation** (`readonly x: number[]` then
  `x.push(...)`) stays unenforced — TS itself only shallow-checks the binding, and
  this compiler has no deep-immutability tracking. Out of scope; the modifier's
  reassignment check is what this delivers.
