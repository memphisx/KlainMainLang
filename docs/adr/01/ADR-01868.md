# ADR-01868: `[]` against a non-array object type

- **Relations**: `Implements TDD-00230` (P3.3: found through the shadow report's ArrayLiteral bucket)
- **Date**: 2026-10-21

## Context

- The checker leaves an empty array literal unanswered (its element type comes from context), and the assignability check skips an unanswered source. So the strict lane accepted `const g: Generator<never, void, unknown> = []`, `const m: Map<string, number> = []` and Test262's `[[,] = g()]` parameter called with `[[]]`, all of which tsc rejects (TS2739, TS2740, TS2741).

## Decision

- Against an interface or class instance type that is no union and has no string index, `[]` is checked as tsc's `never[]`: each required member its apparent type (Array's) and Object.prototype lack is reported as missing. A member our partial Array declaration may simply not model reports nothing.
- The literal's own type stays unanswered: only the check uses `never[]`.

## Consequences

- `TestEmptyArrayLiteralTarget` holds tsc 5.6's codes. The missing-member lists can name more members than tsc 5.6's because the bundled lib declares newer ones (iterator helpers).
- Verified on Apple Silicon.
