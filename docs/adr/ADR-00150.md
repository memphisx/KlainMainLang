# ADR-00150: Fixed-point unannotated-return-type inference

- **Relations**: Extends [ADR-00041](ADR-00041.md); Implements [TDD-00058](../tdd/TDD-00058.md); Extended by [ADR-00152](ADR-00152.md)
- **Date**: 2026-08-10

## Context

[ADR-00041](ADR-00041.md) added best-effort return-type inference for an unannotated function, accepting a known boundary at the time: an unannotated function calling another unannotated function *declared later in the same file*, when the callee returns a non-scalar, under-infers because the caller's own inference runs (in `registerFunctions`'s single top-to-bottom pass) before the callee has been registered. Confirmed still live with the exact repro from that ADR's own Investigation:

```ts
function makeA() { return makeB() }
function makeB() { return { x: 1 } }
console.log(makeA().x)
```
```
klainmain: codegen error: 3:21: field access on non-object (no field 'x')
```

Picked up now alongside [TDD-00057](../tdd/TDD-00057.md)/[ADR-00149](ADR-00149.md) (nested function declarations), since that work introduced a second call site — `pushNestedFuncScope` — with the exact same single-pass shape (and, on inspection, actually a *stricter* version of the same bug: see Investigation).

## Investigation

`buildFunctionSig` (`emitter.go`, factored out by [ADR-00149](ADR-00149.md)) calls `inferUnannotatedReturnType` for an unannotated function, which runs `inferExprType` on the first `return` expression. For `return makeB()`, `inferExprType`'s `*ast.CallExpression` case resolves `makeB`'s return type via `resolveFuncRef("makeB")` against whatever's in `e.funcs`/the nested scope stack *at that exact moment*. `registerFunctions`'s original single pass writes `e.funcs[fd.Name]` immediately as it iterates in source order, so a function's own inference can see every *earlier* sibling's real signature but not a *later* one's — exactly the documented boundary.

`pushNestedFuncScope` (TDD-00057) turned out worse in its original form: it only appended the fully-built `nestedFuncScope` to `e.nestedFuncScopes` *after* its whole pre-scan loop finished, so during the loop itself no nested sibling — earlier or later — was resolvable via `resolveFuncRef` at all. Confirmed this wasn't exercised by TDD-00057's own tests/example, since every nested-function test written for that work happened to use explicit return-type annotations, sidestepping `inferUnannotatedReturnType` entirely.

## Decision

Implemented exactly as scoped in [TDD-00058](../tdd/TDD-00058.md): a bounded fixed-point re-inference sweep, not a general multi-pass type system. Both call sites now write each declaration's signature into the live, already-pushed/visible structure (`e.funcs`, or — after restructuring `pushNestedFuncScope` to push its scope *before* scanning rather than after — the current `nestedFuncScope`'s maps) immediately as each is first computed, then re-run `buildFunctionSig` for every unannotated declaration, repeatedly, until a full sweep changes nothing or a sweep-count cap is hit. See the TDD's Design section for the full reasoning, including why a genuinely circular unannotated pair can't converge (and isn't a new failure mode — it keeps the same default-fallback behavior ADR-00041 already established).

## Implementation notes

- **`codegen/llvm/emitter.go`**: `registerFunctions` now collects every non-generic declaration with `fd.ReturnType == nil` into a `[]*ast.FunctionDeclaration` alongside its existing first pass, then calls a new shared helper, `reinferUntilFixedPoint(decls, build, store, current)` — generic over how a caller builds/stores/reads a signature, so both call sites reuse one sweep implementation rather than two copies that could drift. Change detection is `reflect.DeepEqual` on each declaration's `RetType` (`Type` carries ~30 fields today; a hand-rolled comparator would silently drift the next time it grows a field — the same reasoning that motivated extracting `buildFunctionSig` itself in ADR-00149). `reflect` had no prior use in `codegen/llvm`; introduced here for this one narrow, compile-time-only comparison.
- **`codegen/llvm/emit_func.go`**: `pushNestedFuncScope` restructured to push its `nestedFuncScope` onto `e.nestedFuncScopes` *before* scanning `body` (popped again on an early-error return, so every existing caller's "nothing pushed on error" assumption still holds) rather than only once fully built — `scope`'s two maps are reference types, so mutating the local `scope` variable during the scan and reading back through `e.nestedFuncScopes` see the same underlying data. This alone fixes same-scope-sibling resolution during inference for the common case (an earlier-declared sibling); the same `reinferUntilFixedPoint` call (storing back into `scope.byName`/`scope.byDecl` instead of `e.funcs`) then closes the forward-reference case exactly like the top-level fix.
- No change to `inferExprType`, `resolveFuncRef`, or any call/callback-dispatch site — the fix is entirely in *when* a signature becomes visible and how many times it's (re)computed, not in how it's looked up.

## Side effects discovered

`pushNestedFuncScope`'s "push after" ordering (found while designing this fix, not by an independent repro) meant a nested unannotated function calling *any* same-body sibling — not just a later-declared one — always mis-inferred a non-scalar return type. Fixed by the same restructuring described above; no separate tracking needed since [TDD-00057](../tdd/TDD-00057.md)/[ADR-00149](ADR-00149.md) shipped in this same work session and was never released with the older behavior.

## Verification

- `go build`, `go vet ./...`, and the full `go test ./...` suite pass unmodified plus the new cases below — confirmed on Linux.
- New E2E tests in `tests/func_test.go`: `TestE2EForwardReferenceUnannotatedObjectReturn` (the exact ADR-00041 repro), `TestE2EForwardReferenceChainDepthThree` (a 3-hop forward-reference chain, confirming the sweep isn't limited to one hop), and `TestE2ENestedFunctionForwardReferenceUnannotatedObjectReturn` (the same gap scoped to nested functions).
- Manually confirmed a genuine mutual-recursion cycle (`function a() { return b() }; function b() { return a() }`, both unannotated) still compiles cleanly and quickly rather than hanging the compiler — the sweep cap terminates it with the same default fallback as before this fix.
