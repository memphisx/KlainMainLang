# ADR-00903: Reassigning a catch parameter to a plain value

- **Date**: 2026-09-12

## Context

Invalid-IR sweep. Reassigning a catch-clause variable emitted invalid IR:

```ts
try { throw "s"; } catch (a) { a = 4; }   // clang: fptoui double 4.0 to { i8, i64 }
```

From `language/block-scope/shadowing/catch-parameter-shadowing-*` (3 files).

## Investigation

A catch variable is a `TypeCaught` value — the unpacked `{ i8 tag, i64 payload }`
thrown-value record (TDD-00202). `coerce` (`emit_exprs_coerce.go`) handled
caught→other (pack to any / unwrap an Error) but had no branch for other→caught,
so assigning a scalar into the caught slot fell through to the generic scalar
path, which `fptoui`'d the value into the `{ i8, i64 }` aggregate.

## Decision

Add the reverse coercion: a non-caught value assigned into a caught slot is boxed
to `any` (`emitBoxValue`), then split into the record's `(tag, payload)` via the
same `__kml_nb_tag`/`__kml_nb_pay` the initial catch binding uses, and rebuilt
with `emitCaughtAggregate`.

## Implementation notes

- Placed right after the existing caught→other branch in `coerce`.
- `coerce` has no error return; `emitBoxValue` does — on the rare boxing error
  the branch is skipped (best-effort), falling through unchanged.

## Side effects discovered

None.

## Verification

- `TestE2ECatchParamReassign` (new): prints the thrown string, then `4` after
  reassignment.
- All 3 catch-parameter-shadowing files compile clean.
- `make examples` 296/296.
