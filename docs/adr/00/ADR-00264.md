# ADR-00264: `Promise.reject` is `Promise<never>` (a bottom type)

- **Relations**: refines [ADR-00262](ADR-00262.md) (`Promise.reject`); closes that row's only caveat
- **Date**: 2026-08-20

## Context

`Promise.reject(e)` was typed `Promise<number>` by default ([ADR-00262](ADR-00262.md)),
so `const s: string = await Promise.reject(new Error(...))` was a clang error —
the `await` produced an `i64` (from `Promise<number>`) that clashed with the
`string` (ptr) binding. A rejected promise never produces a value (`await`
re-throws before it is read), so `number` was simply the wrong type — the correct
one is `Promise<never>`, and `never` assigns to anything.

## Decision

Add a minimal bottom type, `TypeNever` (`Type{IR: "i64", IsNever: true}`), and type
`Promise.reject(e)` as `Promise<never>` (both in `emitPromiseReject` and its type
inference). `coerce` gains one case: a `never`-typed value coerces to **any**
target as a zero of that target's type (`null` for a pointer, an empty aggregate
for an array, `0` for a scalar) — the value is dead (the `await` threw before it
could be read), so the zero keeps the IR well-typed and is never observed.

`never` only ever arises from `Promise.reject`, and only ever flows into a
`coerce` at the binding/argument site, so the blast radius is exactly that one
`coerce` case — no general `never` type-system surface (unions, narrowing, etc.)
is introduced.

## Consequences

- `const s: string = await Promise.reject(...)` (and any non-`number` binding of a
  rejected `await`) type-checks and runs — the value is never produced, the
  surrounding `try/catch` (or `.catch`) handles the rejection. The
  `Promise.resolve`/`.reject` row's only caveat is closed; the row is now strict.
- Not addressed here (a **separate, general** bug, correctly attributed to
  `await`, not `Promise.reject`): an *explicitly* `: Promise<T>`-annotated variable
  holding a task promise — `const p: Promise<number> = f(); await p` — reads the
  wrong value, because the explicit annotation resolves to a non-task-shaped
  `Promise<T>` (discarding the task tag inference keeps). Its root is that async
  *methods* still emit a bare-slot promise while async *functions* emit a
  task-struct one, so an annotation can't know the layout. Tracked on the `await`
  row; the real fix is unifying the two promise representations.
