# TDD-00184: ChildProcess `'exit'`/`'close'` `(code, signal)` event shape

- **Status**: Implemented
- **Date**: 2026-09-07

## Context

Node fires a streaming child's `'exit'` and `'close'` events with **two**
arguments, `(code, signal)`:

- normal termination → `code` is the integer exit code, `signal` is `null`;
- termination by a signal → `code` is `null`, `signal` is the signal **name**
  string (`'SIGTERM'`, `'SIGKILL'`, …).

The shipped streaming path ([runtime_childprocess.go](../../codegen/llvm/runtime_childprocess.go)
`__kml_cp_finalize`) instead folded a signalled death into the single `code`
argument as POSIX's `128 + signum`, and the listener ABI carried exactly one
non-nullable numeric parameter. So `child.on('exit', (code, signal) => …)` — the
canonical Node spelling — could not even be written, and a killed child reported
`143` where Node reports `(null, 'SIGTERM')`. This is a faithfulness gap in the
highest-value `child_process` surface, scoped now as the first of the remaining
[TDD-00180](TDD-00180.md) §3 rows.

It is more than a leaf fix because it touches the **listener calling
convention**: `__kml_cp_finalize` invokes the stored closure through a
hand-written fixed function-pointer signature, so widening the event to
`(code, signal)` is a deliberate ABI change, not a local edit — hence a TDD.

## Design

**Event ABI.** `'exit'`/`'close'` listeners receive `(code, signal)` where
`code: number | null` and `signal: string | null`. Listeners may declare 0, 1,
or 2 parameters.

**Uniform reactor signature + per-call-site adapter.** `__kml_cp_finalize` is
emitted once and cannot know a given listener's arity, so it always calls a
**fixed** signature `void(ptr env, { i1, double } code, ptr signal)` — the
nullable-scalar box ([types.go](../../codegen/llvm/types.go) `isNullableScalar`)
for `code`, a string pointer (`null` when absent) for `signal`. At the
`child.on(...)` call site, where the listener's real arity *is* known, the user
closure is wrapped in a per-call-site **adapter closure** presenting exactly that
uniform signature and forwarding to the user closure with its declared arity
(the same adapter mechanism `chunkHeaderAdapterClosure`/`dgramMsgHeaderAdapterClosure`
already use in [emit_net.go](../../codegen/llvm/emit_net.go)). The adapter is the
single place arity/nullability is reconciled, so the reactor stays arity-agnostic.

**Legacy 1-arg listeners (decided).** A listener that declares one **non-nullable**
`number` parameter (`(code) => …`, the pre-existing spelling) keeps compiling. On a
normal exit it sees the real code as before; on a signalled death, where the
faithful value is `null` and a non-nullable `number` cannot hold it, it sees `0`.
This is a **documented caveat**, not the general behaviour: a listener that types
its first parameter `number | null` (or reads the 2nd `signal` argument) gets the
faithful `null`/name pair. This was the chosen trade-off (Option A of the three
weighed) because it keeps every existing call site and example compiling while
making the faithful shape *expressible*; the alternatives were to force
`number | null` everywhere (breaking all existing sites) or to keep `128 + sig`
in the 1-arg path (a quiet permanent divergence).

**Signal source, per platform.**

- **POSIX**: `__kml_cp_finalize` already distinguishes `WIFSIGNALED` from a normal
  exit via the low 7 bits of the wait status; the signal number is `status & 0x7f`
  (`WTERMSIG`).
- **Windows**: `TerminateProcess` leaves no "signalled" bit in the exit status, so
  the child's `.kill(sig)` records the requested signal number into a new cp-struct
  field (21); `__kml_cp_finalize` treats a non-zero recorded signal as the signalled
  case and names it. This matches Node on Windows, which reports the `signalCode`
  it recorded for the `.kill()` that terminated the child.

**Signal name mapping.** A shared `__kml_cp_signal_name(i64) -> ptr` maps the
common signal numbers to their interned Node names (`SIGHUP` 1 … `SIGTERM` 15,
`SIGKILL` 9, `SIGINT` 2, `SIGSEGV` 11, `SIGABRT` 6, `SIGPIPE` 13, `SIGQUIT` 3,
`SIGBUS`/`SIGFPE`/`SIGALRM`, …), returning `null` for an unmapped number.

**Struct growth.** The cp struct gains field 21 (`i64` recorded kill signal),
22 slots / 176 bytes; both `calloc` sites (`runtime_childprocess.go`,
`runtime_ipc.go`) and `cpStructBytes` move in lockstep. `calloc`-zeroed, so an
unset field means "not killed via `.kill()`".

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| Nullable-scalar `{ i1, T }` param ABI | **Done** (`isNullableScalar`, types.go) | Boxes the nullable `code` argument |

## Open questions

None — the one genuine decision (legacy 1-arg behaviour on a signalled child) was
resolved above. Exposing `.exitCode`/`.signalCode` **properties** on the handle
(distinct from the event arguments) is out of scope here and left as a future row.
