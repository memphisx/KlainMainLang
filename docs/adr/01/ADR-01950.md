# ADR-01950: Every pointer kind keeps null and undefined apart; absent sort comparators

- **Relations**: Implements TDD-00230
- **Date**: 2026-10-28

## Context

A function value typed `F | null | undefined` had one absent state, the null closure pointer. Comparing it with `null` or `undefined` worked from its static type, but the value itself could not tell which absence it held. Against Node:

- `null` read back as `undefined` from arrays, fields, parameters and Maps: `[null, undefined, f]` printed `[ undefined, undefined, [Function] ]`, and `typeof` said `undefined` for both.
- `cb ?? "none"` returned the absent function itself. A function on one side of `??` and another kind on the other was typed as the function.
- `[...].sort(cmp)` with an absent comparator called through the null pointer and crashed. Node sorts in the default order for `undefined`, and throws `TypeError: The comparison function must be either a function or undefined: null` for `null`.
- A box flowing into a three-state number through `toThreeStateScalar` was converted as a two-state value, so `const r: number | null | undefined = g ? g() : g` read `undefined` for a null `g`.
- The same held for `bigint`, `Date` and tuple values: `[null, undefined, 5n]` printed `[ undefined, undefined, 5n ]`.
- `b === undefined` on a `bigint | null` was true when `b` held null: the comparison was a plain null-pointer test, whatever the operator and literal.
- A generic `T | null | undefined` resolved to a two-state type in each specialization, so `pick<T>(xs: (T | null | undefined)[], i)` returned `undefined` for a null element.
- `[a, b]`, with `a` a `T | null` and `b` a `T | undefined`, typed its elements as `T | null`.
- `console.log` of a nullable `Map`, `Set` or `RegExp` crashed (the absent value was inspected as present), and a nullable `RegExp` array element printed `[Object]`. `JSON.stringify` of an absent `Date` crashed.
- A conditional of `null` and a function, Map, Set, bigint or Date value kept the `null` branch's kind, so the declaration stored null whichever branch ran.
- `Promise.allSettled` over a `number | null` promise failed to compile: the rejected entry's absent `value` was a bare zero in an aggregate slot.
- A bare `new Map()` / `new Set()` assigned to a typed binding (or a conditional branch of one) built the default string-keyed family while reads used the binding's, printing `[Object]` and missing keys.
- `console.log` of an absent `Map` or `Set` crashed, and of a `(() => T) | null` holding null printed `undefined`.
- Inside a callback, `f ? 1 : f` boxed an undefined `f` as `null`: `fromThreeState` left the plain pointer's type without its undefined flag, and the function box path always boxed a missing closure as `null`.

## Decision

- **Three-state eligibility** covers every pointer kind: functions, `bigint`, `Date` and tuples join strings, objects, classes, Maps, Sets and arrays. Its null is the null cell and its undefined the null pointer. Every guard that tests whether a function is present (optional calls, `?.` method calls, `??`) uses `isAbsentPtr`, which sees both.
- **Nullable bigint comparisons** follow JS: `==` matches either absence; `===` matches the absence the literal names, which a two-state bigint holds only if it is its own.
- **Type parameters:** `typeParamWithAbsence` gives a substituted `T` the absence its reference spells, three-state when it spells both. The specialization signature and `resolveType`'s type-parameter scope share it.
- **Array literals** merge the absences of nullable-typed elements with those of `null` and `undefined` literals.
- **Absent host values in output:** inspect wraps a nullable `Map`, `Set` or `RegExp` in the absent-pointer check, and `console.log` sends a nullable `RegExp` there. `JSON.stringify` serializes an absent `Date` as `null`.
- **Conditionals** treat functions, Maps, Sets, bigints and Dates as pointer branches, so a null or undefined branch makes the result nullable or three-state.
- **allSettled:** a nullable scalar's absent side is its undefined aggregate.
- **Bare collections:** `setCollectionHint` hands an assignment's or annotated declaration's Map/Set type to every bare `new Map()` / `new Set()` leaf of the value, through conditionals.
- **`console.log`** sends a `Map` or `Set` through the inspector's absence check; an absent function prints the keyword its type names.
- **`??` with a function on one side only** produces the box that holds either.
- **Sort comparators:** before choosing a comparator, `emitQsortCall` looks through `as` casts. A comparator typed `undefined` sorts in the default order. A comparator that may be absent is tested at run time: undefined sorts in the default order, null throws Node's TypeError, and a present one is used. `sort`, `toSorted` and typed-array sorts share this path.
- **Box into a three-state scalar:** `toThreeStateScalar` sends a box to `convert`, whose tag test tells null from undefined.
- **`fromThreeState`** marks the plain pointer it returns as `T | undefined`: once the null cell is mapped away, a null pointer means undefined. The function box path boxes a missing closure as `undefined` when its type says so.
