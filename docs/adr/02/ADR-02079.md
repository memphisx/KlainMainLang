# ADR-02079: An HTTP/2 stream gives back receive window as it is read

- **Relations**: Extends ADR-02073; Implements TDD-00230
- **Date**: 2026-11-24

## Context

After ADR-02073 made an `Http2Stream` write complete only once nghttp2
had sent its bytes, `sequential/test-http2-timeout-large-write.js` and
`-large-write-file.js` failed on Linux x86-64 in 3 of 3 runs, where the
previous tree passed 3 of 3. The test writes 3 MB to a client that
pauses for longer than the server's timeout after every 500 KB read, and
expects no timeout while the transfer is still moving.

## Investigation

- Bisected over the tree's changes: with `lib/node/http2.ts` and
  `lib/node/stream.ts` reverted, both pass.
- A trace of the test's events: on the previous tree the client got all
  3 MB in one `data` event, so the pause was never taken, and the test
  passed without exercising what it tests. On the new tree data
  arrived in chunks, the client paused, and the server stream finished
  at 52 ms, all 3 MB sent to a paused reader; the session's timeout then
  fired with the client paused.
- nghttp2 was sending WINDOW_UPDATEs on its own as DATA arrived, read or
  not. Node turns those off and gives window back only as the stream
  consumes data (`OnDataChunkReceived`: at once while the stream is
  flowing, else when it reads again). A paused stream there stops its
  sender.
- On the previous tree a client paused after its first chunk received
  65535 of 1048576 bytes: the rest never came.
- Node's `callTimeout` also refreshes a session or stream timer, rather
  than reporting it, while writes are queued and some of their bytes
  went out since the last check. Here the timers always reported.

## Decision

- nghttp2's automatic window updates are off
  (`nghttp2_option_set_no_auto_window_update`); `h2Consume(session,
  stream, n)` gives n bytes back to the connection and the stream.
- A DATA chunk for a reading stream is consumed at once. When `push`
  returns false the stream stops reading; the bytes it receives then are
  counted, and consumed (and flushed) when `_read` is next called. DATA
  for a closed or unknown stream is consumed at once.
- A stream's timer with writes still pending, and a session's timer with
  writes pending on any of its streams or bytes queued on its socket,
  is refreshed when the bytes sent have changed since its last check,
  and reported otherwise.

## Implementation notes

- `codegen/llvm/http2src/h2node.c`: the option, `__kml_native_h2_consume`.
- `lib/native.d.ts`, `tools/libconform/allow.txt`: `h2Consume`.
- `lib/node/http2.ts`: `_kmlReading`, `_kmlUnconsumed`, the DATA case,
  `_read`; `_kmlOnTimeout`, `_kmlSentBytes`, `_kmlWritingSent`.

## Verification

- `TestE2EHttp2PausedStreamHoldsSender`: a client pausing for 250 ms
  after its first chunk receives all 1048576 bytes, and the server's
  write completes only after it resumes, as in Node; the previous tree
  gives 65535 bytes and completes the write first. Linux x86-64.
- `test-http2-timeout-large-write.js` on Linux x86-64: five
  pause-and-resume cycles, the write completing at the end; passes
  3 of 3.
