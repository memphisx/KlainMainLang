# ADR-00413: tls.createServer options as a value; net.connect(port) arity

- **Relations**: Extends [TDD-00110](../tdd/TDD-00110.md) (tls server), [ADR-00358](ADR-00358.md) (net client); Extends ADR-00412
- **Date**: 2026-08-27

## Context

Next two buckets on the Node-oracle work list: `tls.createServer's options
must be an object literal` (~26 files) and `net.connect takes (port, host,
…)` (~19). Sampling showed both are arity/shape gaps, not feature gaps: the
corpus binds the TLS options first (`const opts = { key: fixtures.readKey(…),
cert: … }; tls.createServer(opts)`), and calls `net.connect(port)` with no
host (`net.connect(server.address().port)`).

## Decision

- `tls.createServer(options, cb?)` accepts a non-literal options expression:
  the value must be statically an object with `cert`/`key` string fields,
  which are loaded off the object (same GEP path any field read uses). The
  literal path keeps its stricter unknown-key rejection; the value path
  validates field presence/type.
- `net.connect` (and `createConnection`) accepts every positional Node arity:
  `(port)`, `(port, cb)`, `(port, host)`, `(port, host, cb)` — the second
  argument disambiguated by static type (function vs value), the compile-time
  stand-in for Node's dynamic argument shuffling. `isInlineCallback` sees
  through `test` counting wrappers, matching ADR-00412's posture. Host still
  defaults to `localhost`.

A third small piece in the same sweep: **dgram `socket.address()`** — the
`bind(0)` ephemeral-port idiom on UDP sockets — via the shared
`emitNetAddressObject` getsockname builder. Wiring it surfaced a duplicate
`ntohs` declaration between the net and dgram runtimes (an LLVM redefinition
error whenever a program used both); now a shared `ensureNtohs`.

## Implementation notes

`codegen/llvm/emit_tls.go`, `emit_net.go`, `emit_dgram.go`, `emit_exprs_types.go` (dgram address inference), `runtime_net.go`/`runtime_dgram.go`/`emitter.go` (shared ntohs). Also fixed in passing: the
recently-added bound-handle http test double-booked port 8971 with the TLS
echo test (a latent parallel-run collision — moved to 8973), and a same-file
replace collateral on the binary-body test's port was caught and reverted
before it landed.

## Verification

New E2E tests `TestE2ETLSCreateServerOptionsVariable` (variable-bound
`{ cert, key }`, Go TLS client round trip) and `TestE2ENetConnectPortOnly`
(port-only connect, echo round trip, close from handler) and `TestE2EDgramSocketAddress` — all pass; full
net + tls suites green; Node oracle re-run (Mac).
