# ADR-00752: `fs.readdirSync(path, { withFileTypes: true })` — `Dirent[]`

- **Relations**: Implements a [TDD-00180](../tdd/TDD-00180.md) §4 row ("`withFileTypes` `d_type`"); extends [ADR-00027](ADR-00027.md) (the `readdir` string-list runtime), [ADR-00495](ADR-00495.md)/[ADR-00565](ADR-00565.md) (the `Stats` object and its `isFile()`/`isDirectory()` mode-masking, reused here), [ADR-00719](ADR-00719.md) (the Win32 fs shim's `opendir`/`readdir`)
- **Date**: 2026-09-07

## Context

`fs.readdirSync(path)` returned a `string[]`; the `{ withFileTypes: true }` form — which returns `Dirent[]`, each entry carrying its name and type predicates — was unsupported (the [TDD-00180](TDD-00180.md) §4 "`withFileTypes` `d_type`" row). It is a common directory-walk idiom (classify each entry without a second `stat` per file), so its absence forced callers into a `statSync` per entry, or a compile error on the option object.

## Investigation

Two pieces already existed to build on. `__kml_fs_readdir` (`runtime_fs.go`) walks `opendir`/`readdir`/`closedir`, copying each `d_name` (at a `runtime.GOOS`-conditional `direntNameOffset()`) into a growable `{ptr,i64}` string array. And `Stats` (`emitStatsKindCall`) already implements `isFile()`/`isDirectory()`/`isSymbolicLink()` by masking a hidden `mode` field with `S_IFMT` and comparing against `S_IFREG`/`S_IFDIR`/`S_IFLNK`.

The only new data a `Dirent` needs beyond the name is its type. POSIX `struct dirent` carries `d_type` (glibc offset 18, Darwin 20), but mingw-w64's `dirent` has none — the Windows shim (`win32fs.c`) defines its own `kml_dirent` struct and fills it from a `WIN32_FIND_DATAW`, so it can carry whatever field is wanted.

## Decision

Add `{ withFileTypes: true }` as `readdirSync`'s optional second argument, returning `Dirent[]`.

- **`Dirent` type** (`types.go`): `DirentType()` is a two-field object `{ name: ptr, mode: i64 }` with an `IsDirent` flag. `mode` holds the `S_IFMT` bits (not a raw `d_type`), so `isFile()`/`isDirectory()`/`isSymbolicLink()` dispatch reuses `emitStatsKindCall` unchanged. `name` is the only Node own-enumerable property, so the object-printer/`JSON.stringify` path strips the trailing `mode` (the `IsDirent` case in `structFieldsForEnumeration`), exactly as `Stats` keeps all of its own fields but `Dirent` must hide `mode`.
- **Emitter** (`emit_fs.go`): `emitFsReaddirSync` now takes 1–2 args; `readdirWithFileTypes` parses the literal `{ withFileTypes: true }` (rejecting anything else, mirroring `mkdirSync`'s `{ recursive: true }`) and is shared with `inferExprType` so the static type (`string[]` vs `Dirent[]`) and the emitted call agree. The kind-method dispatch (`emit_call.go`, `emit_exprs_types.go`) now fires for `IsStats || IsDirent`.
- **Runtime** (`runtime_fs.go`): `__kml_fs_readdir` gains an `i1 %withTypes`. When set, each entry's `storeit` builds a heap `Dirent` — `name` from `__kml_str_from_cstr`, `mode` selected from the entry's `d_type` byte (at the new `direntTypeOffset()`): `DT_DIR`→`S_IFDIR`, `DT_REG`→`S_IFREG`, `DT_LNK`→`S_IFLNK`, else `0` — and stores the `Dirent` pointer in the array slot instead of the bare name string.
- **Windows shim** (`win32fs.c`): `kml_dirent` gains a `d_type` byte at offset 8 (pushing `d_name` to offset 9 — `direntNameOffset()`/`direntTypeOffset()` updated to match), populated in `readdir()` from `dwFileAttributes`: `FILE_ATTRIBUTE_REPARSE_POINT`→`DT_LNK`, `FILE_ATTRIBUTE_DIRECTORY`→`DT_DIR`, else `DT_REG`.
- **Resolver**: no change — `readdirSync` was already in the `fs` member set.

## Implementation notes

- `mode` carries `S_IFMT` bits rather than the raw `d_type` deliberately, so a `Dirent` and a `Stats` share one `isFile()`/`isDirectory()`/`isSymbolicLink()` implementation with no per-object-kind branch.
- The Windows `d_type` offset (8) is chosen so `d_name` stays byte-addressable at a single documented offset; reordering the struct there was cheaper than teaching the IR two Windows name offsets.
- The async/`fs.promises` `readdir` form stays names-only for now; only the sync form takes the option.

## Side effects discovered

A filesystem that returns `DT_UNKNOWN` (some network/FUSE mounts) yields `mode 0`, so all three predicates report `false` — Node falls back to an `lstat` there. Recorded as a caveat (excludes the row from Strict coverage) rather than fixed, since it needs a per-entry path-join + `lstat` the string path deliberately avoids; a follow-up can add the fallback if a real workload hits it.
