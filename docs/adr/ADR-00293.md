# ADR-00293: Generator expressions (bound form) + yield-based element-type inference

- **Relations**: Implements [TDD-00096](../tdd/TDD-00096.md); extends [ADR-00171](ADR-00171.md)–[ADR-00173](ADR-00173.md) (generator machinery); picked from the [ADR-00288](ADR-00288.md) histogram (the `expected (, got *` 2,086-file cluster and the 662-file annotation-requirement bucket)
- **Date**: 2026-08-22

## Decision (per TDD-00096)

- **Part 1 — bound generator expressions.** `function* (...) {...}` (sync
  and async, named or anonymous) parses in expression position
  (`FunctionExpression.IsGenerator`). A top-level `const/let/var G =
  function* ...` binding is rewritten pre-emission into a named generator
  declaration (`rewriteTopLevelGeneratorExpressions`, the exact
  class-expression precedent). Any other use — argument, nested binding,
  IIFE — is a clean codegen rejection naming the V1 scope.
- **Part 2 — yield inference.** An un-annotated generator's element type is
  inferred from its body: every plain `yield <expr>` joins under the
  numeric rule (any float → double); `yield*` over a call to a known
  generator contributes that generator's element type; zero yields fall
  back to the first `return <expr>`'s type, then i64. Parameters and (a
  shallow, inference-only approximation of) body locals are temporarily
  bound so `yield i * 1.5` infers from real types. Only a genuinely
  non-joinable mix still demands the annotation.

## Verification

Node-diff (byte-identical): anonymous/named/parameterized bound generator
expressions driven by `for...of`, float-join inference (`yield i * 1.5` →
element double), mixed int/float yields. E2E:
