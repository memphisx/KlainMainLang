# ADR-01278: process's methods, argv, env and exit in TypeScript

- **Relations**: `Implements part of TDD-00230` (P3.1), `Extends ADR-01250`
- **Date**: 2026-09-29

## Context

After ADR-01250, `process` was an EventEmitter written in TypeScript, but
code generation still emitted its methods one by one:

- `cwd`, `chdir`, `uptime`, `hrtime` and `hrtime.bigint`;
- `kill`, `memoryUsage` and `umask`;
- the credential reads, and `pid`;
- `argv`, `execPath`, `version(s)`, `env`, `exitCode` and `exit`.

Each emitter had its own argument checks and error messages, and none of
them matched Node's:

- `chdir` failures read `cannot change directory to '…'`;
- `kill` failures read `kill(pid=…, signal=…): …`;
- `hrtime` rejected anything that was not a tuple at compile time.

The methods also did not exist on `process` read as a value, and
`process.kill` returned nothing. There were also several departures from
Node:

- `argv[0]` was the raw path the program was started by;
- `typeof process.env.MISSING` and `typeof process.argv[99]` were
  `'string'`;
- `process.env.X += …` was rejected;
- `process.exitCode` started as `0` and was not validated.

## Decision

- `lib/node/internal_process_methods.ts` implements these methods the way
  Node's `lib/internal/process/per_thread.js` and
  `does_own_process_state.js` do:
  - `hrtime` validates its argument (`ERR_INVALID_ARG_TYPE`,
    `ERR_OUT_OF_RANGE`) and applies the borrow;
  - `kill` accepts a signal name or number (`ERR_UNKNOWN_SIGNAL`), throws
    an ErrnoException (`kill ESRCH`), and returns `true`;
  - `chdir` throws Node's UVException (`ENOENT: …, chdir '<cwd>' ->
    '<dir>'`, with `path` and `dest`);
  - `umask` parses an octal string (parseFileMode);
  - `memoryUsage.rss()` exists.
- The same module holds the rest:
  - `argv`: Node's shape, with `argv[0]` and `argv[1]` the absolute
    executable path; `argv0` is the operating system's `argv[0]`;
  - `execPath`, `version` and `versions`;
  - `exitCode`: it starts `undefined` and is validated as Node's setter
    validates it. It reads a code the runtime set itself (13 for a
    top-level await that never settled);
  - `exit`: it sets the code, runs the `'exit'` hook once, and exits;
  - `env`: `envGet`, `envSet` (`String(value)`) and `envDelete`. A
    compound assignment reads the variable first.
- The natives are in `lib/native.d.ts`: `processCwd`, `processChdir`,
  `processUptime`, `processHrtime`/`processHrtimeRead`, `killPid`,
  `processMemory`, `processUmask`, `processId`, `processArgc`/
  `processArgv`/`processArgv0`, `processExecPath`, `processSetExitCode`,
  `processReallyExit`, `processVersion` and `envGet`/`envSet`/`envDelete`.
  A failing one returns -errno. `hrtime` reads the clock into a buffer
  and then reads that buffer back, the way Node's binding does.
- Code generation rewrites these forms to the module's exports:
  - `process.<method>`, `process.hrtime.bigint`, `process.memoryUsage.rss`;
  - the property reads;
  - `process.exitCode = v`;
  - `process.env` reads, assignments and `delete`.

  The process object built by `_kmlProcess` holds the methods too.
- On Windows the credential reads stay a compile error, as in Node, where
  they are undefined. The optional call `process.getuid?.()` still works.
- The old emitters and their IR runtime are deleted.
- Fixes needed along the way:
  - A tuple boxed into `any` is now an `any[]` of its elements. Before,
    `Array.isArray` was false and `.length` threw. An absent tuple boxes
    as `undefined`.
  - Unboxing a tuple reads an array box, or a dynamic array such as
    `JSON.parse`'s, element by element. An array passed where a tuple is
    expected converts through that box.
  - A boolean literal type (`(): true`) is a boolean. Before, it was
    represented as a number.
- `NodeJS.MemoryUsage` fields are numbers (they were integers).
- Still compiled directly:
  - `platform` and `arch`: they are the target's, and constant at compile
    time, so a `process.platform === 'win32'` branch folds away;
  - `nextTick`: its own queue, ahead of promise jobs, belongs to the event
    loop (phase 4);
  - the bare `process.env` value: still a snapshot, since `Proxy` does not
    call its `ownKeys` trap for enumeration yet.

## Verification

Mac (Apple Silicon): `TestE2EProcessMethodsErrors`,
`TestE2EProcessMethodsAsValue`, `TestE2EProcessArgvEnvExit` and
`TestE2ETupleThroughAny` print what Node v24.19.0 prints. `external`
stays 0, as before.
