# ADR-00518: Terminal-control primitives (raw mode, tty size, SIGWINCH, raw reads)

- **Relations**: `Implements TDD-00031`. `Extends ADR-00079` (signal allowlist), `ADR-00424` (isTTY).
- **Date**: 2026-08-30

## Context

TDD-00031 scoped four terminal-UI primitives on top of the existing CLI-tooling
priority. Two of the four (and both listed prerequisites) had already shipped
since it was written: `process.<stdio>.isTTY` (ADR-00424) and the raw,
no-trailing-newline `process.stdout/.stderr.write(s)`. What remained was raw
mode, live terminal size, terminal-resize notification, and a synchronous raw
byte read — enough to write an interactive keyboard-driven CLI (arrow-key
navigation, in-place progress, resize-aware layout) without a userland library.

## Investigation

The three still-missing Node-faithful pieces map to three libc calls the project
already uses in the same shape elsewhere: `tcgetattr`/`tcsetattr` (termios),
`ioctl(TIOCGWINSZ)`, and one more literal on the `process.on` signal allowlist
(`ensureSignalHandlerRuntime`, runtime_process.go — SIGWINCH is signal 28 on
both Linux and Darwin). The fourth, a synchronous single-byte read, has **no**
Node counterpart: Node does raw input via `process.stdin.on('data')` events, not
a blocking read. Per the project's `klain:` convention (TDD-00131) a bespoke,
non-Node primitive belongs under an explicit `klain:` specifier, not bolted onto
`process.stdin`.

The one real hazard is `struct termios`: `tcflag_t` is 4 bytes on glibc but 8 on
Darwin, so `c_lflag` sits at a different offset and the ECHO/ICANON/ISIG bit
values differ too — the exact struct-layout footgun ADR-00051 hit with
`ucontext_t`. Hand-laying the struct in LLVM IR would need per-platform offsets
and constants. Instead the whole surface routes through an embedded C shim
compiled by clang against the platform's own `<termios.h>`/`<sys/ioctl.h>`
(`EmbeddedCSources`, the same mechanism the bigint/crypto/tls/dtoa runtimes use),
so struct layouts and flag bits are always the host's, by construction, on both
dev machines with zero per-platform IR.

## Decision

- **`process.stdin.setRawMode(enabled)`** → `__kml_tty_set_raw(i32)`. Applies the
  libuv `UV_TTY_MODE_RAW` termios transform to fd 0 (clears ICANON/ECHO/ISIG/
  IEXTEN and the raw-input iflags, sets CS8, VMIN=1/VTIME=0; leaves `c_oflag`
  untouched so OPOST stays on and `\n`→`\r\n` still works). `c_oflag` untouched
  matches libuv. The original termios is saved on the first enable and restored
  on `setRawMode(false)`.
- **`process.stdout/.stderr.columns` / `.rows`** → `__kml_tty_cols`/`_rows(i32
  fd)`, a live `ioctl(TIOCGWINSZ)` read each access (never cached, matching
  Node). Returns i64 (numbers default to i64 here, like `process.pid`).
- **`process.on('SIGWINCH', handler)`** → a third pending-flag/closure on the
  existing signal machinery (ADR-00079): one more branch in `__kml_sig_handler`,
  one more `ensureSignalRegistered*`, and one more drain block in **both**
  event-loop drivers (`__kml_timer_drain`, `__kml_event_loop_run`). Delivered
  from ordinary control flow at the top of a loop iteration, never signal
  context — identical to SIGINT/SIGTERM.
- **`klain:tty` module** (bespoke, non-Node): `readByte(): number` (one blocking
  byte off fd 0, -1 at EOF) and `readKey(): string` (one `read()`'s whole burst
  as a string, so an escape sequence like an arrow key — ESC `[` `A` — is one
  key). Both via the same C shim.

### Non-TTY divergence (documented)

Node's `columns`/`rows` are `undefined` when stdout is not a terminal. This
compiler has no clean undefined-number, so the shim returns the classic **80x24**
fallback off a non-TTY — the same value most CLI libraries substitute for that
undefined anyway. A divergence in observable value, accepted because the faithful
`undefined` is not cleanly representable in the number type here.

## Implementation notes

- `emit_tty.go` holds all four emitters, the three `ensure*` decls, the
  `UsesTtyShim()` accessor, and `TTYShimSource()`. `embedded_c.go` links the shim
  when `UsesTtyShim()`.
- **Ordering trap fixed while implementing:** `setRawMode` dispatches through
  `emitStdinMethodCall` (because `process.stdin` infers to the streaming-stdin
  type). That path used to unconditionally evaluate `process.stdin`, which calls
  `__kml_stdin_create()` — and that flips fd 0 to **O_NONBLOCK** for the
  event-driven `.on('data')` reader. A synchronous `readByte`/`readKey` on a
  non-blocking fd 0 then sees `EAGAIN`, which the shim (correctly, for a blocking
  fd) reads as EOF — so the read returned immediately with nothing. Fixed by
  handling `setRawMode` at the very top of `emitStdinMethodCall`, before the
  runtime/handle setup, so it neither creates the handle nor flips the flag. The
  Node-idiomatic `setRawMode(true)` + `.on('data')` combo still works — there the
  non-blocking event loop is exactly what's wanted.
- `SIGWINCH = 28` is hardcoded (identical on Linux and Darwin), like the existing
  `SIGINT = 2` / `SIGTERM = 15`.

## Side effects discovered

- `setRawMode` and the synchronous `klain:tty` reads are one coherent I/O model
  (blocking fd 0); `process.stdin.on('data')` is the other (non-blocking, event
  loop). A program that mixes a `.on('data')` listener with a synchronous
  `readByte` in the same run will have fd 0 in non-blocking mode, and the
  synchronous read will see EOF-on-EAGAIN. This is inherent to the two models and
  is left as a documented caveat, not worked around.

## Verification

- `tests/tty_test.go` — 6 E2E tests (readByte/readKey off piped stdin, 80x24
  non-TTY fallback, setRawMode no-op-on-pipe not breaking a following read,
  SIGWINCH compile-acceptance, unknown-signal rejection now naming SIGWINCH).
- `examples/tty/keys.ts` — interactive raw-keyboard demo that degrades cleanly on
  a non-TTY (so `make examples`, which runs with `</dev/null`, passes).
- **Interactive path verified manually under a pty on macOS (Apple Silicon
  M4):** raw arrow-key read returned bytes `27 91 65` (ESC `[` A); a pty resize
  (`TIOCSWINSZ` to 120x40) fired the SIGWINCH handler which read the new size
  `120x40` live; `q` quit and the terminal was restored. Not yet re-verified on
  the x86-64 Ubuntu box — termios/ioctl go through the platform's own headers, so
  no layout drift is expected, but the platform-parity rule means a Linux run
  should confirm before any Linux-specific claim.
