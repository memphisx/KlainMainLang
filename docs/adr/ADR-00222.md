# ADR-00222: `JSON.stringify` `space` pretty-printing and generic `toJSON()` (TDD-00077 Track S)

- **Relations**: `Implements TDD-00077` (Track S)
- **Date**: 2026-08-18

## Context

`JSON.stringify` was compact-only and honored no user serialization hook: the `space` argument (`JSON.stringify(obj, null, 2)`) was silently ignored despite being one of the most-used JSON forms (config files, logs, readable request bodies), and only `Date` had special serialization — a user class with a `toJSON()` method serialized its raw fields instead. These are [TDD-00077](../tdd/TDD-00077.md) Track S, deliberately scoped first because both are additive to the existing serializer and need none of the planned parse-to-tree rewrite (Track P).

## Investigation

- The serializer (`codegen/llvm/emit_call_json.go`) builds JSON by runtime string concatenation: `emitJSONStringifyObject`/`emitJSONStringifyTuple` walk fields at compile time, `emitJSONStringifyArrayData` loops at runtime. Indentation depth is a **compile-time** property at every structural position (even array elements all sit one level below their bracket), so a `depth`+`unit` context can be threaded through as interned constants rather than computed at runtime — the only runtime piece is an array's empty-vs-non-empty close, which depends on its dynamic length.
- `emitValueToString` (`emit_exprs_types.go:92`) already dispatches a user `toString()` override via `canonicalizeClassTy` → `e.classes[name].MethodSigs["toString"]` → `emitClassCall`; `toJSON()` is the same lookup against a different method name, then serialize the *result*.
- A `toJSON()` returning its own type (`toJSON() { return this }`) recurses forever at compile time — the same class of bug as the object inspector's unbounded type recursion ([ADR-00221](ADR-00221.md)). Confirmed directly: a first cut without an effective guard stack-overflowed the compiler (`emitJSONStringifyValue` ↔ `emitClassCall` at `emit_call_json.go:377`). Real JS applies `toJSON` once, then serializes the returned value's own properties (so `return this` yields `{"v":1}`, not a loop), which a re-entrancy guard reproduces.
- Rejected extending the `Date` special-case into a unified `toJSON`: `Date` is a builtin with no user method table (`MethodSigs`), so folding it in would mean synthesizing a method entry for a non-class type — more churn than value. `Date` keeps its existing `toISOString`-based path; the generic rule covers user classes. (Divergence from the TDD's "delete the Date-specific path" note, recorded here per the TDD-vs-ADR rule.)

## Decision

**`space` (pretty-printing).** A `jsonIndent{unit string, depth int}` value threads through `emitJSONStringifyValue`/`Object`/`Array`/`Tuple`. An empty `unit` is compact mode — byte-identical to the previous output, so every existing path is unchanged. In pretty mode each element/member goes on its own line indented `depth+1` levels, the closing bracket sits at `depth`, and the key/value separator gains a space (`": "`). An empty container stays inline (`{}`/`[]`) — for arrays this is a runtime `select` on `len == 0` since length is dynamic. The `space` argument is resolved at compile time (`jsonSpaceUnit`): a numeric literal → that many spaces clamped to `[0,10]`, a string literal → used literally (first 10 chars), `null`/undefined → compact. A **runtime** (non-literal) space is a clean rejection in V1 (the indent strings must be interned constants). The `replacer` (2nd) argument is supported only as `null`/undefined — a function/array replacer is cleanly rejected, not silently ignored.

**`toJSON()`.** In `emitJSONStringifyValue`, before the object/tuple/array branches, a value whose canonicalized type is a class with a `toJSON()` method calls it and serializes the result. An `e.jsonToJSONActive` set marks a class name for the *entire* serialization of its `toJSON` result (not just the call): a same-typed result re-enters with the guard still set and serializes the object's fields instead of re-dispatching `toJSON`, bounding the recursion (the [ADR-00221](ADR-00221.md) lesson) and matching JS's once-then-serialize semantics.

## Implementation notes

- `emit_call_json.go`: `jsonIndent` type + helpers (`itemPrefix`, `closeBracket`, `colon`, `child`, `pad`/`childPad`), `jsonAppend` (skip-empty concat), `jsonSpaceUnit`; the six stringify functions gained a `jsonIndent` parameter (all callers are internal to this file — the public `emitJSONStringify` entry at `emit_call.go:77` is unchanged). Added `strconv`/`strings` imports.
- `emitter.go`: `jsonToJSONActive map[string]bool` field, initialized in the constructor.
- The `jsonToJSONActive` guard's `delete` must run *after* the recursive serialization of the `toJSON` result, not after the `emitClassCall` — deleting too early lets a `return this` re-dispatch `toJSON` and stack-overflow the compiler (found and fixed during verification).
- `Date.toJSON` stays a builtin special-case in the `default` branch (see Investigation) — a divergence from the TDD's Track S text, intentional.
