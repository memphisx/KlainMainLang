# ADR-00519: Native `klain:tui` — vendored Yoga flexbox + double-buffered ANSI diff painter

- **Relations**: `Implements TDD-00150` (Stage 1). `Extends ADR-00518` (terminal primitives), `ADR-00131`/`klain:` namespace, `ADR-00020` (conditional linking).
- **Date**: 2026-08-30

## Context

TDD-00031/ADR-00518 shipped the raw terminal primitives (raw mode, live size,
`SIGWINCH`, synchronous key reads) — enough for a hand-rolled prompt, not enough
for *layout*: flexing boxes, wrapped text, component trees that repaint on
resize. TDD-00150 scoped a staged TUI roadmap whose Stage 1 is a first-party
native substrate: a real flexbox layout engine plus a painter plus a component
authoring model, sitting directly on the shipped primitives, with no FFI (that
is Stage 2) and no JS runtime.

## Investigation

The layout engine is the one genuinely hard external asset, so the choice was
vendor-vs-handwrite. Facebook's Yoga is a self-contained flexbox engine with a
clean extern-"C" ABI (`yoga/Yoga.h`) — the faithful option. Vendoring it as a
single amalgamated `.cc` (the webview binding's shape) was tried and rejected:
Yoga is ~12k LoC across 19 `.cpp` + 59 `.h` with nested `#include <yoga/...>`
angle-bracket includes, and a naive unity build (one `.cc` that `#include`s
every `.cpp`) fails to compile — `event.cpp`'s anonymous-namespace `struct Node`
collides with `facebook::yoga::Node` once the TUs are merged (`reference to
'Node' is ambiguous`). Either way the angle-bracket includes need the header
tree on an include path.

The second constraint: the CLI compiles the emitted IR, this program's C
runtimes (dtoa/tty/crypto/…), and any embedded C++ in **one** clang invocation,
so any flag on that line is global. Yoga needs C++20, but `-std=c++20` is a hard
error on every C translation unit (`invalid argument '-std=c++20' not allowed
with 'C'`) — confirmed directly. So a global C++ standard flag is impossible;
clang's default (C++14 here) is too old for Yoga.

## Decision

**Vendor Yoga's real source tree** (`codegen/llvm/yogasrc/`, `//go:embed`,
pinned at `bd8fe0d`, MIT) and compile it the faithful way — **each `.cpp` as its
own TU, pre-compiled to an object file in Go** (a separate `clang -std=c++20 -O2
-c` per file), cached per-version under a temp extraction dir. Only the language-
neutral object files reach the shared link, so the C++20 requirement never
touches the C line. The painter runtime `tui.c` (a C TU that `#include`s
`<yoga/Yoga.h>`) carries a `-I` to the same extraction root — an `-I` is
language-neutral and safe globally. `EmbeddedCSources` gates all of this on
`UsesTui()`, exactly like every other conditional runtime (ADR-00020).

**Painter** (`tui.c`): builder calls create Yoga nodes (`YGNodeNew` + style
setters) carrying paint attributes (text, fg/bg SGR, border, and the leaf
component kinds); `render(root)` runs `YGNodeCalculateLayout` against the live
terminal size, paints the tree into a back cell-grid, diffs it against the
previously-painted front grid, and emits only the changed cells (minimal
cursor-move + SGR + write) — then frees the tree so a long-running loop does not
grow. Text is **decoded UTF-8 → code points** (one grid cell per code point) so
box-drawing/accented glyphs in user text render correctly; wide (CJK/emoji)
cells still count as one column (documented limitation). `enter()`/`leave()`
manage the alternate screen + cursor visibility.

**Authoring model**: builder functions (`Box`/`Text`/`List`/`Spinner`/
`Progress`/`TextInput`) that map 1:1 onto layout nodes and return an opaque node
handle (a `ptr`), plus `render`/`enter`/`leave`. The retained tree lives in C;
the `state → view(state) → update` **loop is written in userland TypeScript**
over the `klain:tty` key reads + `SIGWINCH` — because there is no closure→C
function-pointer trampoline yet (TDD-00150 Stage 2), a C-driven loop invoking a
KML callback is not yet possible, and the userland loop needs none. Style props
are read at compile time from the builder's object-literal argument: enum/colour/
border/boolean props must be literals (mapped to their integer form); numeric
props (sizes, padding, gap) may be arbitrary expressions, passed as doubles with
a NaN "unset" sentinel. `List` items / `Box` children accept either an inline
array literal or any runtime array (e.g. `items.map(...)`), the latter lowered to
a element loop.

## Implementation notes

- `codegen/llvm/yoga.go` — embed + per-version extraction + per-`.cpp` object
  compilation; `codegen/llvm/tui.go` — the `tui.c` painter source; `emit_tui.go`
  + `emit_tui_props.go` — builder/render codegen and style-prop lowering;
  `resolver/virtual_modules.go` — the `klain:tui` marker + member list;
  `inferExprType` returns `ptr` for builder calls (nodes are never method-
  dispatched, only passed on).
- The test build path (`tests/compiler_test.go`) links Yoga via a new
  `appendTui` mirroring the CLI's `EmbeddedCSources` loop, through the exported
  `Emitter.TuiCSources()` — so it can't drift from the CLI.
- `render` fills the screen only where the root left width/height unset; an
  explicit root size is honoured.

## Side effects discovered

- Text is code-point- but not grapheme/width-aware: wide (CJK/emoji) and
  combining characters occupy one cell, so alignment drifts for such content.
  Tracked as a Stage 1 caveat; a `wcwidth`-style pass is future work.
- Immediate-mode: the whole `Element` tree is rebuilt and laid out every frame
  (the cell diff keeps *output* minimal). A retained/memoized node tree is the
  TDD's own open perf question, deferred behind a real workload.

## Verification

- `tests/tui_test.go` (E2E): a full frame paints the alt-screen envelope, a
  rounded border, flex-justified/coloured/bold text, list/progress/spinner
  glyphs; a second test asserts `space-between` drives the paint (L/R justified
  apart). Both pass on macOS (Apple Silicon).
- `examples/tui/menu.ts`: an interactive picker that degrades to one frame off a
  non-TTY (so `make examples` runs it); renders correctly incl. a multibyte
  em-dash as a single cell.
- Interactive key/resize loop verified manually under a terminal, per ADR-00518.
- `go build`, `go vet ./...` clean.
