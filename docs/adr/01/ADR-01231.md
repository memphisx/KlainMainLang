# ADR-01231: process.cwd is a runtime string; `__filename`; libuv's active handles

- **Relations**: `Implements TDD-00234`
- **Date**: 2026-09-29

## Context

- `path.resolve("x")` returned `/x`. `@__kml_process_cwd` returned
  `getcwd`'s C string with no length header, so the concatenation read the
  header from whatever preceded it: sometimes 0, sometimes gigabytes (a
  forked parent resolving its module path grew to 3 GB and was killed).
- `__filename` and `__dirname` were only understood in two special forms
  (`new Worker(__filename)` and the codegen `fork`).
- An open TCP or pipe handle held the loop open whatever it was doing. A
  child's stdout at its end, unread, kept a program alive forever once an
  unref'd child's exit was no longer delivered first.
- An unref'd child's `'exit'` was always delivered. Node doesn't deliver it
  when nothing else holds the loop, because the loop ends first.

## Decision

- `@__kml_process_cwd` copies `getcwd`'s buffer into a runtime string.
- The resolver rewrites an unshadowed `__filename`/`__dirname` to the
  file's absolute path and directory, as Node's CommonJS wrapper binds
  them. The program records its entry path (`require.main.filename`),
  which `fork` uses to recognize this program's own module
  (`__kml_native.entryPath()`).
- A referenced stream handle holds the loop only while active: listening,
  connecting, reading before the end of the stream, writing, shutting
  down, handshaking or closing.
- An unref'd child's exit waits until its own stdio is no longer active,
  and is delivered on a later pass only if the loop is still running.

`TestE2EChildProcessUnref`, the unref-with-a-timer case (`'close'`
delivered), the net/http suites in the full test suite.
