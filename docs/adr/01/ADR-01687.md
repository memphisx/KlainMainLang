# ADR-01687: A presence word for optional members

- **Relations**: Implements TDD-00256
- **Date**: 2026-10-17

## Context

TDD-00256, all four stages. An optional member holding `undefined` read as a missing key: `{ a: 1, b: undefined }` printed `{ a: 1 }` and listed `a` only. Partial<T> also widened its fields differently from a declared `name?: T`, so `{ a: undefined }` stored 0.

## Decision

**The word.** `ObjectType` gives a field list one hidden field, `__kml_present` (`PresenceField`), when the list has an optional member. It is appended last unless the list already carries exactly one (see Classes).
- Bit *k* is set when the *k*-th optional member has its key.
- A list built from several types' fields (an intersection) can carry more than one word. `withPresence` drops them all and appends one.
- `UserFields` leaves the word out, as it leaves out the header word, so key enumerations and copies made from `UserFields` never see it. The walks over the raw field list that skip the header field by name now skip the word too: JSON projection and its known-keys table, object-to-dictionary conversion, Partial<T>, and webview bindings.
- The word is a real field, so every allocation and copy that sizes an object from its field list already includes it.

**Readers.** `emitFieldPresent`, the one presence test behind `Object.keys`/`entries`/`values`, `for…in`, `in`, `hasOwnProperty`, inspect and boxing, now reports a key as present when its bit is set or its value is not undefined.
- A layout whose stores never set a bit therefore behaves exactly as before.
- `forEachPresentField` keeps a present key's undefined value instead of demoting it to the payload.
- `JSON.stringify` keeps testing the value, since it drops undefined values whatever the key.

**Writers.** These set the bit:
- an object literal's own properties, a spread's included, where the source's bit counts as a key too;
- member assignment;
- JSON projection, for the keys its input has;
- converting `any` into the layout, through the value's own `in`.

**Structural views.** Through a structural type the object may have another layout, so the word is read and written only when the header is exactly this layout's id. A foreign layout's value decides presence, as before.

**Classes.** A class's `name?: T` field is optional too, but every declared field is an own property from construction, so `new` sets all of the instance's bits (`emitPresenceAll`).
- `delete` stores the absent value and clears the bit, so the key is gone.
- A subclass's layout extends its base's: the base's own code finds the word at its own index. A word already in a field list therefore stays where it is, and `FlatFields` includes it, so a subclass inherits it in place and its optional members take the following bits. The word may sit mid-list, and `UserFields` drops it wherever it is.

**Partial<T>.** It widens each field with `optionalFieldType`, as a declared `name?: T` member is widened.
