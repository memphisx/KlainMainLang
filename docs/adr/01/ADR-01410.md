# ADR-01410: Symbol keys inspect as symbols on class instances and Errors

- **Relations**: Extends ADR-00912
- **Date**: 2026-10-05

## Context

A property keyed by a symbol is stored under the key `"\x01@@sym:<pointer>"`.
`console.log` of an object literal decoded it (`Symbol(refed): true`), but a
class instance with a symbol-keyed property added at run time printed the
storage key itself: `C { x: 1, '\x01@@sym:0x1009cd310': 7 }`. An Error's own
properties had the same gap.

## Decision

- `dynjson.c` renders every key through one `append_key`: a symbol's as
  `Symbol(desc)` (a well-known one's as `Symbol(Symbol.iterator)`), an
  identifier bare, anything else quoted, an own `__proto__` in brackets.
- A class instance lists its string keys first and its symbol keys after
  them, as `Reflect.ownKeys` orders them and as object literals already did.

## Verification

- Mac (M4): `TestE2EClassInstanceSymbolKeyInspect` (an object literal and a
  class instance with string and symbol keys, against Node) and the inspect
  tests.
- Linux (x86-64, Ubuntu 24.04 container), with ADR-01410 to ADR-01415: the
  full test suite, the 394 examples, and Test262 in both lanes (strict 8,497,
  the one file of ADR-01412 fewer; js 10,506; no invalid IR).
