# ADR-01296: `zlib` as Node's lib/zlib.js over a native handle per stream

- **Relations**: `Implements part of TDD-00230` (P3.1), `Supersedes ADR-00321`, `Supersedes ADR-01006`
- **Date**: 2026-09-30

## Context

`zlib` was one of the modules TDD-00230 P3.1 still compiled directly
(emit_zlib.go, and the one-shot half of runtime_streams_zlib.go). It had:
- only the one-shot codecs;
- `{ level }` as the only option, and only as a compile-time constant;
- callbacks that ran synchronously;
- no streams (`createGzip()`, `zlib.Gzip`), no `crc32`, and no constants
  or codes.

## Investigation

Node's lib/zlib.js is a `Transform` subclass (`ZlibBase`) over a
`binding.Zlib` handle (node_zlib.cc's `ZlibContext`):
- `init`, `params`, `reset` and `close`;
- `write` on the thread pool, and `writeSync`;
- a shared two-word write state (avail_out, avail_in);
- an `onerror(message, errno, code)` hook.

`processChunk`/`processChunkSync`/`processCallback` drive the handle
through output chunks of `chunkSize`. `processCallback` holds the next
write back while `push()` reports a full readable side.

## Decision

**`lib/node/zlib.ts`** is lib/zlib.js converted as the other P3.1 ports:
- `ZlibBase`, `Zlib`, and `Deflate`/`Inflate`/`Gzip`/`Gunzip`/
  `DeflateRaw`/`InflateRaw`/`Unzip`, each `kml:callable`;
- the `create*` functions and the one-shot convenience methods (callback
  and `*Sync`);
- `crc32`, `constants` (Node's table), and `codes` in both directions;
- every option: `flush`, `finishFlush`, `chunkSize`, `windowBits`, `level`,
  `memLevel`, `strategy`, `dictionary`, `info`, `maxOutputLength` and
  `rejectGarbageAfterEnd`;
- `params`, `flush`, `reset`, `close` and `bytesWritten`;
- Node's range errors (`ERR_OUT_OF_RANGE`), `ERR_BUFFER_TOO_LARGE` and
  `ERR_TRAILING_JUNK_AFTER_STREAM_END`.

Where the port differs in shape (not in behavior):
- The write state is read after each write (`zlibState`) instead of a
  shared `Uint32Array`.
- A failed write returns 1, and the TS side builds Node's
  `genericNodeError(message, { errno, code })`.
- `flush()`'s zero-length writes carry their kind by identity (one
  `Buffer` per kind) rather than a symbol property.
- `processCallback`'s held-back write resumes from `_read` rather than by
  swapping `_read`.
- `*Sync` has an `info: true` overload returning `{ buffer, engine }`.
  @types types it `Buffer`, a type a `{ buffer, engine }` object cannot
  be held in here.

**Natives** (`threadpoolsrc/klainzlib.c`, compiled into the pool's unit
only under `-DKLAINPOOL_ZLIB`, with `-lz`) mirror `ZlibContext`:
- `zlib_new`/`init`/`params`/`reset`/`close`;
- `write` (pool) and `write_sync`;
- `state`, `error_message`/`errno`/`code`, and `crc32`.

UNZIP detects the gzip magic as `ZlibContext` does. A handle table grows
as streams are made. A handle closed while its pooled write runs is freed
when that write ends.

**Transform**: Node's `Transform` runs the flush at `'prefinish'` when a
subclass overrides `_final` (zlib does, so `'finish'` does not wait for the
flush). lib/node/stream.ts's `Transform` does the same.

**Deleted**:
- emit_zlib.go (its input normalizer moved to emit_bytes_input.go, which
  net and child_process use);
- `ensureZlibOneshot`, and `usedZlibOneshot`;
- the `zlib` virtual marker, its member list, and `declare module "zlib"`.

## Implementation notes

- A non-`Uint8Array` view is copied out through `typedBytes` (dynjson.c).
  `TypedArray.buffer`/`.byteOffset` do not exist here (BACKLOG).
- Brotli and Zstd are not in: they need libbrotli/libzstd located as
  optional backends (Homebrew's prefix is off clang's search path on the
  Mac). BACKLOG.

## Side effects discovered

Fixed in ADR-01297: callback parameters of fewer arity, function identity
through adapters, a plain object into an index signature, overload results
with an untyped argument, views held in `any`, and Writable's `null`
callback argument. BACKLOG #81 (constructing a class held in a value)
blocks `const U: any = zlib.Unzip; U()`.

## Verification

- `tests/zlib_port_test.go`: one-shot, stream events, options, and
  handles, each compared with Node. Compressed sizes are not compared
  (Node bundles its own zlib). An ASan/UBSan run of the handle lifecycle
  is included.
- The existing `tests/zlib_test.go` (Go interop) and the examples pass.
- **Mac (Apple Silicon):** Node v24.19.0.
- **Linux (Docker, glibc/arm64):** the same probes against Node 26.10.
- **Windows:** klainpool.c with `-DKLAINPOOL_ZLIB` passes
  x86_64-w64-mingw32-gcc `-fsyntax-only`.
