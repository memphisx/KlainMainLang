# ADR-01466: Classes extending Promise

- **Relations**: Implements TDD-00247 (stage 3, Promise), Extends ADR-01463, ADR-01465
- **Date**: 2026-10-07

## Context

TDD-00247 stage 3's second host is Promise. `class P extends Promise<number>
{}` was a clean compile error. Node makes the instance a promise, and
Promise's methods and statics construct the class (species): `p.then(f)`,
`p.catch(f)`, `p.finally(f)`, `P.resolve(x)`, `P.all(xs)` and the rest are
`P`s, made by P's constructor with an executor whose resolving functions
the result is settled through. A constructor wrapping them sees each call,
and `await p` (P is not `%Promise%`) goes through `p.then`, another
construction.

## Investigation

- Every promise came from `__kml_task_alloc_promise` (tasksrc/promise.c);
  the generator code freed some directly. No header word preceded the body.
- Promise's methods dispatch as intrinsics on a `Promise`-typed receiver;
  through `any` a boxed promise is a wrapper (`emitBoxPromise`), not the
  object.
- A class extending Promise is monomorphic in its extends clause's type,
  while a species result settles to its callback's: `p.then(v => String(v))`
  is a P holding a string.
- Synthesized source has no capture pre-pass (`hoistedCaptures`), so a
  closure in it capturing a synthesized local or parameter was boxed lazily,
  where the box did not dominate its uses.
- Found on the way, older than this work, each fixed here:
  - a throw from a `new Promise` executor escaped the constructor instead
    of rejecting the promise;
  - `__kml_promise_reject_with` wrote the reason before checking the
    promise was pending, so a reject after a resolve corrupted the value;
  - `Promise.allSettled` records showed both `value` and `reason` (one of
    them `undefined` or `0`) in `console.log`, `Object.keys` and `in`;
  - `await` of an `any` holding a thenable fulfilled with the object;
  - a combinator's members typed as a union (`[p, 5]`) were fulfilled with
    themselves instead of resolved, so a promise or thenable among them was
    not adopted;
  - an executor held as a value got resolving functions of another
    calling convention than its declared parameter types.

## Decision

- Every promise body has a header word at `body - 8` (`KML_PROMISE_HEADER`,
  a host header naming no class); frees go through `body - 8`.
  `__kml_promise_init_at` initializes a body in place.
- A class extending `Promise<T>` (`HostBase` the task promise of T) has its
  instance as `[tag][body: 7 words][vtable][fields]`. Construction runs the
  executor on the body (`emitPromiseExecutor`, factored out of
  `emitNewPromise`); the synthesized constructor takes `(executor)`.
- An instance's codegen type carries what it settles to as `PromiseType`
  (`promiseSubclassOf`), kept by `canonicalizeClassTy`; reading its body
  takes that type. A body settled to a boxed `any` while its class's T is
  not is flagged (`promiseFlagBoxedValue`), and the readers through a box
  (the dynamic method records, inspect) branch on the flag.
- Species (`emitPromiseSpecies`):
  - a class whose constructors each hand their first parameter to `super`
    unchanged (`promiseSpeciesPassThrough`) is constructed with a no-op
    executor and the reaction settles the new body directly
    (`emitPromiseThenInto`), as a plain `then` settles its result;
  - another is constructed with an executor capturing the resolving
    functions its constructor hands it, and the reaction calls them from
    the job, adopting a returned promise through a queued job;
  - `catch` is `then(undefined, f)`; `finally` is the spec's
    `then(v => C.resolve(f()).then(() => v), r => C.resolve(f()).then(() =>
    { throw r }))`.
- Statics through the class (`emitPromiseSubclassStatic`): `resolve` (the
  argument itself when it is a C), `reject`, and `all`, `race`,
  `allSettled`, `any` as the spec's algorithms run with C, each member
  through `C.resolve(x).then(…)`, a boxed member checked at run time for
  being a C (`__kml_resolve_then`).
- The instance is a thenable (`thenableClass`), so `await`,
  `Promise.resolve` and the combinators adopt it through its `then`.
  Through `any` it has `then`/`catch`/`finally` as dynamic methods.
- `console.log` renders `P [Promise] { value, fields }`
  (`__kml_promise_inspect_entry`), `<pending>` and `<rejected> reason` as
  Node does.
- Synthesized source gets exact parameter types by annotation
  (`synthTypeAnnotation`), its statements the capture pre-pass
  (`emitSynthStmt`), and three internal calls: `__kml_queue_microtask`,
  `__kml_then_const`, `__kml_resolve_then`.
- The older bugs: the executor runs under `__kml_promise_run_executor`,
  which rejects on a throw; `reject_with` returns on a settled promise; a
  settlement record's `value`/`reason` presence follows its status
  (`emitFieldPresent`, `in`); `await` of an `any` resolves through
  `__kml_promise_resolve_any`; a union member resolves at run time; an
  executor held as a value gets the resolving functions converted to its
  parameter types.

## Side effects discovered

- A generic class still cannot use `extends` (`class P<T> extends
  Promise<T>`), the existing generic-class limitation; the non-generic form
  is what works.
