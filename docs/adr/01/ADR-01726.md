# ADR-01726: Tuples as arrays: rest parameters, variable elements, array behaviour, unions

- **Relations**: `Implements TDD-00230`, Extends [ADR-00201](../00/ADR-00201.md)
- **Date**: 2026-10-18

## Context

A tuple is a fixed-shape struct ([TDD-00066](../../tdd/TDD-00066.md)). Everything beyond declaration, constant-index access and destructuring failed:

- **Rest parameters:**
  - a rest parameter of a tuple type (`...a: [number, string]`) or an alias for one was rejected;
  - so was `[...args: any[]]` in a declaration, which @types/node's event typings need.
- **Variable elements:** optional and rest tuple elements (`[a?: number]`, `[number, ...string[]]`) were parse errors.
- **Index and assignment:**
  - a non-constant index (`t[i]`) was rejected;
  - so was compound assignment to an element (`t[0] += 1`).
- **Array behaviour:**
  - array methods (`t.map`, `t.join`) were "no method";
  - spread (`[...t]`, `f(...t)`), `for...of` and `Array.from` on a tuple failed;
  - a rest element in tuple destructuring (`const [h, ...tl] = t`) failed.
- **Unions:**
  - a tuple could not be a union member (`[number, string] | string`);
  - a tuple literal in a conditional branch into a tuple slot (`c ? null : [1, "a"]`) was typed as an array and segfaulted.
- **Destructuring gaps found along the way:**
  - `[a, ...[b, c]]` (a pattern after `...`) was a parse error;
  - an object pattern over an array (`const { length, 0: first } = xs`) was rejected.
- **Checker gaps:**
  - a call through a tuple rest parameter was not checked against its elements;
  - generic call arguments were not checked against the inferred instantiation;
  - a conditional's or `??`/`||` operand's array literal got no contextual type;
  - `Array.isArray`'s false branch kept a tuple member.

## Decision

### Rest parameters and variable elements

- A tuple with an optional or rest element converts to `any[]` storage. Named members, optional and rest element types convert their inner type (`ast/type_convert.go`).
- Before codegen, a rest parameter whose annotation is not an array is rewritten to `any[]` storage, keeping its type node for the checker (`normalizeRestParams`).
- The checker expands a non-generic tuple rest parameter into its element parameters before checking a call (`expandTupleRest`). A rest of type `never` accepts no argument.

### Generic arguments

- After inference, each argument of a generic call is checked against the instantiated parameter.
- Arguments the inference itself shapes are skipped: array and object literals, context-sensitive functions, `any`/`unknown`, and results still naming a type parameter.
- In a union parameter with one generic member, the whole source is inferred to that type parameter only as a low-priority candidate, and is not widened, as tsc does.

### Tuples as arrays

- **Non-constant index:** `t[i]` switches over the positions. It yields the element boxed, or `undefined` past the end, typed `any` in codegen.
- **Compound assignment:** `t[k] op= x` reads the element, combines, and stores back, evaluating the tuple once.
- **Assertion:** `t as T[]` converts the struct to an array of its elements (`tupleAsArray`).
- **Methods:** a non-mutating array method on a tuple (`map`, `filter`, `join`, `includes`, `slice`, `reduce`, `at`, `entries`, …) runs on that array. A mutating one (`push`, `sort`) is not rewritten, because it would change a copy.
- **Spread and iteration:** spread into an array literal, `for...of`, `Array.from` and every walk through `resolveArrayHOF` take the same conversion.
  - A spread tuple's literal is typed by the elements' one type when they share a plain scalar or string type, else `any[]` (`tupleCommonElem`).
- **Spread into a call:** `f(...t)` expands the tuple's elements to positional arguments, since its arity is static. The receiver and every argument are evaluated once, in order. A fixed-arity callee therefore takes it.
- **Rest destructuring:** `const [h, ...tl] = t` binds a new array of the remaining elements, typed as above.
  - A by-value tuple spills to memory first.

### Destructuring

- **Pattern after `...`:** the parser accepts `[a, ...[b, c]]` and `[...{ length }]`. On the array path, the rest array is destructured by the sub-pattern (`bindRestArray`).
- **Object pattern over an array:**
  - `length` and other names read off the array;
  - a canonical index key reads `xs.at(k)`, which is `undefined` past the end;
  - a default fires on `undefined`.
  - An object rest (`{ ...o } = xs`) still takes the object path.

### Unions

- **Contextual type:** a conditional's branches, `??`/`||` operands and the right side of `&&` take the expression's context. A primitive union member no longer stops an array literal being typed as the union's tuple.
- **Narrowing:** for `Array.isArray`, a tuple is an array.
- **Codegen:**
  - a tuple counts as the union's one array member, boxed as an array of its elements;
  - an array literal is built as the tuple member;
  - `typeof`/`Array.isArray` narrowing maps a tuple to the `array` tag.
- **Conditionals and `??`/`||` into a tuple slot:** each branch is built against the tuple. `a ?? [x, y]` / `a || [x, y]` become a conditional over a temporary.

### Also fixed

- `__kml_classref_proto` (ADR-01725) was referenced by a builtin-function wrapper generated after the class-reference finalize step, so programs that used `Object.getPrototypeOf` as a value failed to link. It is now emitted once, and again at the end if a later routine requests it.
- `Boolean` in the builtin declarations declared a `toString` that TypeScript's library does not have (it comes from `Object`).
