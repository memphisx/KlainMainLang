# ADR-00730: `var` re-declared in a nested block is the same variable (Test262 `S12.14_A11` loops spun)

- **Relations**: Extends [ADR-00210](ADR-00210.md) (`var` function scoping, TDD-00070), [ADR-00719](ADR-00719.md) (recorded these as deferred cross-platform findings: "`try/finally{continue}` in `for(;;)` spins", "`catch{c++; continue}` leaves the outer counter at 0")
- **Date**: 2026-09-06

## Context

ADR-00719 listed two Test262 timeouts, seen on Windows and assumed cross-platform, as loop/exception bugs. Reproduced from `test/language/statements/try/S12.14_A11_T2.js` on Windows, neither was about `try`: both loops re-declare their counter — `var c5=0; for(var c5=0; c5<10;) { … c5+=1 … }` — and the increments went to a different variable than the condition read. Any such loop spins; the `try`/`catch`/`finally` bodies were incidental.

## Investigation

- Minimal repro: `var c = 0; for (var c = 0; c < 3;) { c += 1 }; console.log(c)` printed `0` (the loop terminated on a second `c`).
- Two layers each created a second binding:
  - The resolver's rename pass mangles a file's top-level declarations per module (`c` → `c__kml_mod0`) and rewrites references that are not bound in an enclosing block frame. A `for (var c …)` init bound `c` in the loop's frame, so the loop's references stayed `c` while the top-level declaration and everything after the loop used `c__kml_mod0`.
  - The emitter's `emitVarDecl` allocated a fresh slot for every `var` declaration and `promoteVarToFuncScope` moved it to the function frame, replacing the earlier binding — inside a function body, `var k = 1; for (var k = 0; …)` gave the loop its own `k`.
- JS: `var` is function-scoped; a repeated `var` in the same function is the same binding, and its initializer is an assignment. TypeScript accepts the re-declaration too.

## Decision

- **Resolver** (`resolver/rename.go`): the rename walk counts function-like bodies (`funcDepth`). A `var` declaration at file top level that is nested in a block, not already bound, and whose name is one of the file's top-level declarations is renamed to that declaration's mangled name and *not* bound as a block-local — so the loop body resolves the same mangled name.
- **Emitter** (`emit_stmts.go`, `emitter.go`): a `var name = init` whose name is already a binding of the current function's own frame (or a module global at top level) — and not a closure's captured cell, now marked `IsCapture` — is emitted as an assignment of `init` (nothing for a bare `var name;`), through `emitVarRedeclaration`.

## Implementation notes

- The two halves are independent: the resolver handles the top-level case (module-mangled names), the emitter the in-function case and any top-level `var` that reaches it under the same name.
- `tests/stmts_test.go`: `TestE2EVarRedeclarationInForInitIsSameVariable` — the loop, the catch-`continue` and finally-`continue` shapes from the Test262 file, two consecutive `for (var i …)` loops, an `if`-body `var`, and the in-function case.

## Side effects discovered

- The third ADR-00719 finding, `new Set().has(NaN)` on an untyped `Set`, is a different class and is **not** fixed here: an untyped `new Set()`/`new Map()` is string-keyed, a number key is bit-cast to a pointer, and `has`/`add` of any number then dereferences it — `s.add(1)` alone crashes, `NaN` merely hangs on Windows where a null read self-loops. `Set<any>`/`Map<any, any>` do not compile either (`__kml_map_num_set` handed a `ptr`), so untyped collections are a type-model gap needing a dynamic-key collection design (boxed keys, SameValueZero hashing), not a spot fix; recorded in TDD-00177's findings and the status caveats. `new Set([1, 2])` and annotated `Set<number>` work.
- `S12.6.3_A1.js` (`for (;;)` with `throw 1` … `catch (e) { if (e !== 1) …`) fails to compile because a caught primitive is force-shaped into the error object — the documented catch-parameter caveat, unchanged.
- `for (x in obj)` with a previously declared `x` (no `var`/`let`) is a parse error (`S12.14_A12_*`); not addressed here.

## Verification

Windows 11: the seven `S12.14_A9/A10/A11` files compile and run to exit 0 under `-compat=js` (A11_T2 timed out before); the new E2E test passes on Windows and in the Linux lane ([ADR-00731](ADR-00731.md)).
