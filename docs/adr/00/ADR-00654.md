# ADR-00654: Reconcile callback call arity in higher-order array methods

- **Date**: 2026-09-03

## Context

An array higher-order method called with a callback that declares **fewer
parameters than the method supplies** emitted invalid LLVM IR. The tightest
case is a zero-parameter predicate:

```ts
[].findIndex(() => true)          // or: [].findIndex(function () {})
[10, 20].forEach(() => { /* … */ })
```

`Array.prototype.{forEach,map,filter,every,some,find,findIndex,…}` invoke their
callback with a fixed argument set (element, index, array), but a callback is
free to declare fewer parameters — JavaScript silently ignores the extras. The
emitter passed the method's full argument set regardless of the callback's
declared arity, so the indirect call carried more operands than the callback's
function-pointer type declared:

```
call void (ptr) %fp(ptr %env, double %elem)   ; fp is (ptr) — one operand too many
```

which clang rejects: `error: too many arguments specified`. The symmetric
"too few" shape occurs when a callback declares *more* parameters than the
method supplies (a default-parameter skip). This is the invalid-IR "HOF-arity
mismatch" family (indirect-call arity disagreement).

## Investigation

The callback call site is `emitCBCall` (`codegen/llvm/emit_func.go`). It builds
the callee function-pointer type from `cb.paramTypes()` (the callback's declared
parameters) but built the *argument list* by iterating the raw `args` the
higher-order method passed — for `forEach`/`findIndex` that is always at least
the element (`emit_arrays_search.go:173`, `cbArgs := []Value{elemVal}`), even
when the callback declares zero parameters. Type list and argument list were
therefore derived from two different lengths, and any disagreement is invalid
IR the moment it reaches clang.

Confirmed with a standalone repro (`[].findIndex(function () {})` + the shim
harness): the emitted `.ll` carried `call void (ptr) %t26(ptr %t28, double
%t24)` — two operands against a one-operand pointer type.

## Decision

Reconcile the argument count to the callback's declared arity inside
`emitCBCall`, before emitting the call, so the call always has exactly as many
operands as the callee / function-pointer type declares:

- **more args than parameters** → truncate the extras (JS ignores them);
- **fewer args than parameters** → pad each missing parameter with a zero value
  of its type (`zeroRef`), or an empty `ptr null, i64 0` header for a missing
  array parameter.

Both the `cbClosure` and `cbNamed` branches then iterate the reconciled
`coerced` slice, whose length now equals `len(params)`, so the emitted operand
list and the type list are built from the same source and can never disagree.

## Implementation notes

- `codegen/llvm/emit_func.go`, `emitCBCall`: `coerced` is now sized to
  `len(params)` rather than `len(args)`; the two argument-building loops drop
  their `i < len(params)` guards (now always true) and add an empty-Ref check
  for a padded missing array parameter.
- The higher-order methods that pre-size their argument list by `cb.arity()`
  (e.g. `find`/`findIndex`) still do so; the reconciliation is the backstop that
  makes the emitted call well-typed regardless of what any individual method
  chose to pass.

## Side effects discovered

While tracing this, a broader observation: the Test262 conformance runner's
per-file pass/fail is not reproducible run-to-run when multiple runs share the
default `.conformance-out` scratch directory (concurrent invocations overwrite
each other's `w{id}.ll`). Tracked separately as harness robustness work; the
compiler itself is deterministic (verified: identical IR over repeated
in-process compiles).

## Verification

- New E2E test `TestE2EArrayHOFCallbackFewerParams` (`tests/arrays_test.go`):
  zero-parameter callbacks through `forEach`/`findIndex`/`map`/`every`/`some`
  and an empty-array `findIndex`. Confirmed it **fails without** the fix
  (`too many arguments specified`) and **passes with** it.
- `go test ./tests/ -run 'TestE2EArray|TestE2ECollections|TestE2EBoxedArray|TestE2ETypedArray'`
  — all green (no regression across the existing HOF suites). Mac (Apple
  Silicon).
