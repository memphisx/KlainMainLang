# ADR-01072: A generic function's type parameters are in scope for its whole instantiation

- **Relations**: Extends TDD-00010 (monomorphised generics), TDD-00037 (N-ary type parameters)
- **Date**: 2026-09-22

## Context

BACKLOG §0 item 10: `function later<T>(ms: number, v: T): Promise<T> { return new Promise<T>((resolve) =>
setTimeout(() => resolve(v), ms)); }` failed with "argument 1 has a type incompatible with the parameter's
declared type" at `resolve(v)` — the commonest async helper there is. The non-generic spelling compiled.

## Investigation

`substituteGenericType` (`emit_generics.go`) substitutes a bare `T` or `T[]` in a parameter/return position and
hands anything else to `resolveType`, which knows nothing about `T` and falls to `ResolveTypeName`'s i64
default. So the return type `Promise<T>` resolved to `Promise<number>`, and inside the body every `T` — the
`new Promise<T>` type argument, a `const xs: T[]`, a `Map<string, T>` — did the same. `v: T` itself was right
(bare-T position), so `resolve(v)` compared `string` against the promise's i64.

## Decision

An emitter-level type-parameter scope (`typeParamScope`, pushed by `withTypeParamScope`) that `resolveType`
consults first: a bare name in the scope substitutes its concrete type (with the annotation's `| null` /
`| undefined` applied), and a `T[]`/`T[][]` spelled as one suffixed name peels to `ArrayOf(...)`. Every deeper
shape (`Promise<T>`, `Map<K, T>`, `(x: T) => T`, a user generic `Box<T>`) resolves structurally and reaches the
scope for its inner `T`. `instantiateGenericFunc` builds the signature, infers an unannotated return type and
emits the body inside the scope; `genericCallReturnType` (inference for a call site) and
`substituteGenericType` push it as well, so the two paths agree. Scopes nest (an inner instantiation shadows
an outer's names) and unwind on the error path.

## Implementation notes

`codegen/llvm/emitter.go` (`typeParamScope`, the two checks at the top of `resolveType`),
`codegen/llvm/emit_generics.go`. `substituteGenericType`'s explicit bare-`T`/`T[]` fast paths stay — they
serve the callers that never enter a body (interfaces, classes, aliases).

## Side effects discovered

None. Generic interfaces/classes were already substituted per field through the same function and are unchanged.

## Verification

Windows, all equal to Node 24: the backlog `later` for `"x"` and `2`; `T[]` locals, `T[][]` returns,
`Map<string, T>`, `T | null` returns, `Promise<T>` awaited inside an async generic, a `(x: T) => T` parameter,
for string and number instantiations. E2E: `tests/generics_typeparam_scope_test.go`.
