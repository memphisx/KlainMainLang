# ADR-01691: `string | null` holds both absences, one null cell

- **Relations**: Implements TDD-00257
- **Date**: 2026-10-18

## Context

TDD-00257 Stage 2. A `string | null` read its null pointer as null. An out-of-range element or a missing argument stored into one (`n = xs[3]`) printed `null`, compared `=== null`, and `JSON.stringify({ n })` wrote `"n":null` where Node omits the key.

## Decision

`triStr` covers `string | null` too: its null pointer is undefined, and `nullRef` is null, as in a plain string.
- **Producers:**
  - the null literal converted into a `string | null` is `nullRef`;
  - so is a box holding null unboxed into one;
  - so is a JSON null projected into a `string | null` field.
  - A bare pointer target (an opaque argument, `TypePtr`) keeps the null pointer.
- **Removed:** the two boundary conversions between `string | null` and a plain string. The representations are now the same.
- **Unboxing:** `emitUnboxBoxToType` gives `nullRef` for a box holding null in any string target, so a typed listener `(s: string | null)` called through the dynamic ABI receives null.
- **Equality:** the inline string `===` (`emitStrEq`) matches the same pointer, and never matches `nullRef` against a different one. Without that, the empty cell would equal `""`, and `host === ''` held for a null host.
- **Conversion:** a three-state pointer converted to a `string | null` target is only retyped, because both represent null as `nullRef`. A filled default parameter keeps a passed null.
- **Readers:** `typeof` answers "object", "undefined" or "string" at run time. `??=` (on a variable or a field) and `s ?? 42` test both absences through `isAbsentPtr`.

**One cell (Stage 3).** `nullRef`'s cell was internal to each compiled unit, so the library's units and the program had different ones. It is now a weak definition, `@__kml_nullref_cell`, in every unit and in `collections.c`, which links to one cell. The C string map hashes and compares it apart from `""`: a `Map<string | null, …>` keeps a `null` key and a `''` key apart. A key converts `null` into `nullRef`, as a stored one does.

Not done: a key missing from JSON in a `{ v: string | null }` still lists `v` (BACKLOG #20).
