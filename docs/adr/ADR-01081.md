# ADR-01081: `spawnSync`'s absent `stdout`/`stderr` throw Node's `TypeError`, `error` is the first key

- **Relations**: `Extends ADR-01080, ADR-01038`
- **Date**: 2026-09-23

## Context

`examples/process/spawn_sync_options.ts` segfaulted under `make examples` in the Linux Docker image, which has no `node` on `PATH`. Every child failed to spawn, and `e.stdout.trim()` on the result crashed. Node throws `TypeError: Cannot read properties of undefined (reading 'trim')` there.

Repro, on both Windows and Linux: `spawnSync('no-such-cmd', ['a'], { encoding: 'utf8' }).stdout.trim()`.

## Investigation

- The result record (`cpSpawnSyncResultType`, `codegen/llvm/emit_childprocess_sync.go`) typed `stdout`/`stderr` as bare `string`, matching Node's typings. ADR-01038's null-dereference guard deliberately skips bare pointers, because some runtime handles are legitimately null. So a null stream reached `__kml_str_len` and crashed.
- Node 24, probed with `node --experimental-strip-types`:
  - A never-started child has the `stdout`/`stderr` keys with the value **`undefined`**, `output` is `null`, and `error` is the **first** key (`error,status,signal,output,pid,stdout,stderr`).
  - A started child with `stdio: 'inherit'`/`'ignore'` has `null` streams.
- `stdio` is always a literal (it changes what is emitted), so whether a stream can be `null` is known at compile time. `undefined` happens only when the child never started.
- An `UncheckedIndex` pointer (the type an array element read has, TDD-00187) already means "tsc types this as plain `T`, but at run time it may be `undefined`". That is exactly the stream's situation.

## Decision

- `cpSpawnSyncResultType(stdioModes)`:
  - A piped fd's field is `Nullable|IsUndefined|UncheckedIndex`.
  - A non-piped fd's field is `Nullable` (null flavour).
  - `output` is a nullable array.
  - `error` moves to the first field. Its key is absent when there is no error, so Node's order comes out both ways.
- `inferExprType` reads the call's `stdio` literal through `cpSyncStdioModesOf` (pure, no emission), so the inferred type agrees with the emitted object.
- `emitFieldPresent` treats an `UncheckedIndex` field as always keyed (`Object.keys`, `in`, `util.inspect` list it with `undefined`). `JSON.stringify` still drops an `undefined` value.
- Two consumers that rejected an `UncheckedIndex` string (array reads had the same gap), fixed here:
  - `ternaryUnion` compares the tsc-visible type (`staticIndexType`).
  - `str.toString()` identity dispatch does the same.
- `execSync`'s return value keeps the plain `string` type its inference reports.

## Implementation notes

`emit_childprocess_sync.go`, `emit_exprs_types.go` (the spawnSync inference), `emit_undefined.go` (`emitFieldPresent`), `emit_objects.go` (`forEachPresentField`), `emit_exprs_operators.go` (`ternaryUnion`), `emit_call.go` (`toString`).

## Side effects discovered

- A value that may be `undefined` loses that absence once stored in a binding declared `string`: `const s: string = a[5]` / `= r.stdout`, then `s === undefined` is false and it prints `null`. This is general and not spawnSync-specific. It is recorded in BACKLOG §0 and disclosed as a caveat on the child_process row.
- `http.get` to a refused port with no `'error'` listener died with a Windows stack overflow; fixed in ADR-01089.

## Verification

Windows x64:
- Hand probes are byte-identical to Node 24 for a never-started child, `stdio: 'inherit'`, mixed stdio arrays, the timeout kill, success and `execSync`. The one exception is the declared-binding gap above.
- Tests added in `tests/childprocess_sync_options_test.go`:
  - `TestE2ECPSpawnSyncAbsentStreamsSameAsNode`
  - `TestE2ECPSpawnSyncAbsentStreams`, the Node-less twin, since the Linux image has no `node`.
- The existing child_process tests pass.

Linux x86-64 (Docker): the full suite and `make examples` in all memory modes were re-run for this delivery.
