# ADR-01926: enums and namespaces — one constant evaluator, type members as values, import-equals aliases

- **Relations**: `Implements TDD-00230` (checker coverage, codegen/oracle agreement)
- **Date**: 2026-10-21

## Context

- The checker read enum members from literals only. An enum with a computed constant (`C = 2 ** 53 + 1`, `D = -3`) was unanswered as a whole, so every read of every member fell back to codegen's guess. Codegen had its own evaluator (ADR-01921).
- Codegen inferred `K.A` through the boxed enum object (the enum read as a value, ADR-01921), not as the member's constant that emission uses.
- A namespace's enum or class read as a value (`Object.keys(Geo.Kind)`, `const P = Geo.Point`) or indexed (`Geo.Kind[0.5]`) was a compile error. Only `Geo.Kind.Tall` chains went through the qualifier strip (ADR-00480).
- The checker could not find a namespace member the resolver had made file-private (`Kind__kml_mod0`), and the binder did not declare `import X = A.B` aliases. Both left namespace reads unanswered.

## Decision

- The constant evaluator lives in `ast` (`FoldEnumConst`). The checker and codegen both evaluate enum members with it.
- Codegen's member inference skips the boxed-object dispatch for an unshadowed enum name.
- The qualifier strip also applies to a namespace's type member read as a value or indexed, in emission and inference. A nested namespace reference infers as a box, the object it will be once namespaces are values.
- The checker's namespace member lookup falls back on the unsuffixed name, as type lookup already did. The binder makes an import-equals alias name stand for its target's symbol, in the scope it is written in.

## Consequences

- Enum and namespace reads agree between codegen and the oracle. Namespace enums and classes work as values, matching Node.
- A namespace itself read as a value is [ADR-01927](ADR-01927.md)'s.
