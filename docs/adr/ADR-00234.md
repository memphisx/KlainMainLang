# ADR-00234: Event / CustomEvent objects (Events & Cancellation, stage 1)

- **Relations**: `Implements TDD-00081` (Stage 1)
- **Date**: 2026-08-19

## Context

First stage of the WHATWG event work ([TDD-00081](../tdd/TDD-00081.md)): the base
`Event` and `CustomEvent` object types, distinct from Node's `EventEmitter`. The
`EventTarget` bus that dispatches them is Stage 2; these objects stand alone
(construct, read fields, `preventDefault`) and are the value a listener will
receive.

## Decision

- **`Event` / `CustomEvent`** are plain fixed-shape heap objects, modelled on the
  existing `MessageEventType` (types.go). `Event` = `{ type, defaultPrevented,
  stopImmediate }`; `CustomEvent` adds `detail`, whose type is inferred from the
  construction value (so `new CustomEvent("x", { detail: 42 })` types `detail` as
  a number, an object literal as that object, etc.). Both carry a new `IsEvent`
  tag so method calls dispatch on them; field reads (`e.type`, `e.detail`,
  `e.defaultPrevented`) use the ordinary object machinery.
- **Construction**: new AST nodes `NewEventExpression` / `NewCustomEventExpression`
  (the `detail` value is pulled from the init object literal at parse time), a
  `parseNew` case each, and routing in `emit_exprs.go` + the `emit_exprs_vardecl.go`
  var-decl fast-path. `emit_event.go` mallocs the struct and stores the fields.
- **Methods** (`emit_event.go`, dispatched via an `IsEvent` guard in
  `emit_call.go`): `preventDefault()` sets `defaultPrevented`;
  `stopImmediatePropagation()` sets the internal flag the Stage-2 dispatch loop
  will honor; `stopPropagation()` is an accepted no-op (single-target dispatch,
  no capture/bubble tree).
- **Annotations**: `Event` / `CustomEvent` resolve as type names
  (`ResolveTypeName`), so `function handle(e: Event)` works; a bare `CustomEvent`
  types `detail` as a pointer.

## Implementation notes

`Event`/`CustomEvent` are ordinary `ObjectType`s plus the `IsEvent` flag, so no
new runtime representation — the whole object model (field GEP, mutation visible
across a function call) applies unchanged. The var-decl fast-path infers
`CustomEvent`'s detail type via `inferExprType(detail)`, which must match the type
`emitNewCustomEventExpression` derives from evaluating the same expression.

## Side effects discovered

- V1 carries only `type`/`detail`/`defaultPrevented`; the fuller WHATWG surface
  (`target`/`currentTarget`/`bubbles`/`cancelable`/`composed`/`timeStamp`/
  `eventPhase`/`isTrusted`) is absent, and the `new Event(type, { cancelable,
  bubbles })` init options are accepted-and-ignored. `preventDefault` sets the
  flag unconditionally (no `cancelable` gate yet).
- No `class X extends EventTarget` (built-in `extends` targets are rejected) —
  relevant once EventTarget lands in Stage 2.

## Verification

- `tests/event_test.go`: Event type/defaultPrevented + preventDefault, CustomEvent
  string/number detail, Event as a mutated parameter, stop* no-ops. All pass.
- `examples/events/event-customevent.ts` (incl. an object `detail`) runs correctly;
  emitted IR verified with `clang`.
- `go build`, `go vet`, and the event/custom test subset are green on Apple
  Silicon (macOS).
