# ADR-02069: Audit fixes — sparse search, regex JIT, stringify, sort, runner memory

- **Relations**: Implements TDD-00230
- **Date**: 2026-11-23

## Context

An audit of the runtime and codegen for bug clusters (correctness, memory,
time) found, among others:

- `indexOf`, `lastIndexOf` and `includes` made a sparse array dense before
  walking it: past 2^27 elements the program ended out of memory, where V8
  walks only the elements present (Test262 `lastIndexOf/15.4.4.15-5-12`,
  `-8-9`).
- A global regex loop (`matchAll`, `replace(/…/g)`, `split`) was quadratic in
  the subject: 40,000 matches over 120 KB took 3.2 s. Every pattern is
  compiled with `PCRE2_MATCH_INVALID_UTF`, under which PCRE2's interpreter
  checks the subject from the start offset to its end on every call and
  ignores `PCRE2_NO_UTF_CHECK`. Patterns were never JIT-compiled.
- `JSON.stringify` copied its whole output so far for each element: 100,000
  objects did not finish in 90 s.
- `sort`/`toSorted` on an `any[]` with a comparator typed `(x: number, y:
  number)` passed the boxes as the numbers, so the order was wrong.
- A dynamic array (`JSON.parse` result) grew densely to any index or length:
  a far write took GBs, and `length = 4294967295` segfaulted on a failed
  realloc.
- A string with an embedded NUL ended at it as a Map/Set key (`"a\0b"`
  and `"a\0c"` one key), in `===` between two `any` values and in an array
  search: the hash, `__kml_any_eq` and the search used `strcmp`.
- `Object.fromEntries` took an entry that is not an object (`5`) as one,
  where the specification throws a TypeError and closes the iterator.
- `splice(i, n, ...items)` did not compile, and its items were evaluated
  after the array had shifted: `b.splice(0, 1, b[0] + 10)` read the
  shifted element.
- `util.inspect` of a deep self-referencing graph at depth Infinity
  (`test-util-inspect-long-running`) took 4 GB: each container's entry
  strings were copied into its text and never freed, so the output leaked
  once per nesting level; Node's 2^27-byte output budget was missing too.
- The conformance runner raised its Go heap's soft limit from 1.5 GB to 60%
  of free memory (tens of GB on a large machine) at `GOGC=400`, and kept test
  programs' whole stdout/stderr: its RSS reached 8–47 GB (BACKLOG).

## Decision

- A search over a named array of numbers, strings, objects or `any` reads it
  as it is (no densify) and, when its buffer is shorter than its length,
  calls `__kml_holes_search` (holes.c): the buffer's elements, then the
  sparse ones under their index keys, with `===` (or SameValueZero for
  `includes`, where a hole matches `undefined`). Other walks (`join`, …)
  still densify (BACKLOG).
- Every pattern is JIT-compiled after it compiles (`__kml_regex_jit`, as V8
  compiles its regexps); the per-thread match context carries a JIT stack
  growing to 64 MB. A PCRE2 without JIT, or a pattern the JIT refuses, keeps
  the interpreter. The UTF-16 ↔ byte offset conversions go through the
  string's cached cursor (strheader.c) instead of scanning from the start.
- `__kml_json_concat2` grows an owned accumulator with realloc (a large one
  by remapping) instead of copying it.
- A comparator with typed parameters sorting boxes is called through a
  closure taking boxes, whose call converts them, as a non-closure
  comparator already was.
- A dynamic array's growth past 2^27 elements, or a failed allocation, ends
  with Node's out-of-memory message, as the typed paths do (ADR-02067). Node
  keeps such an array sparse; that is open in BACKLOG.
- String keys hash and compare by their header length (every string has
  one, TDD-00120), as do `__kml_any_eq` and the search; a bigint's digits,
  which have no header, hash by `strlen`. Object property keys still end at
  a NUL (BACKLOG).
- `Object.fromEntries` over an iterable checks each entry is an object (or
  a function) and throws V8's TypeError otherwise, inside the loop, so the
  iterator is closed.
- `splice` evaluates its items before anything moves; spread items are
  built as one array of the element type and copied in at once.
- An inspect entry list owns the entries rendered for it
  (`__kml_inspect_push_owned`) and frees them when laid out; entries from
  generated code, which may be constants, stay unowned. Node's budget is
  kept: each container's text adds to its depth's total, and past 2^27
  bytes the depth limit drops to -1 for the rest of that call. The test
  takes 44 MB (Node 106 MB).
- The runner's heap soft limit is 1.5 GB plus 384 MB per front-end slot
  (6.9 GB at 14), never above the compile budget, and a program's
  stdout/stderr keep their first 16 MB. A flat 1.5 GB was tried first: the
  collector ran without pause and 97–142 Node files hit `CODEGEN_TIMEOUT`.

## Consequences

- `TestE2EArraySearchSparse` covers the search,
  `TestE2ESortAnyArrayTypedComparator` the sort, `TestE2EStringKeysWithNul`
  the keys, `TestE2EObjectFromEntriesNonObjectEntry` the entries and
  `TestE2EArraySpliceSpreadItems` the splice.
- The 40,000-match loop takes 0.08 s; `JSON.stringify` of 100,000 objects
  0.47 s, output identical to Node's. Valgrind finds no invalid access in
  the inspect walk.
- The conformance runner peaks at 7.1 GB in the Node js lane (8–47 GB
  before), with the same 1,134 files passing.
- Verified on Node304 (Linux x86-64).
