# ADR-02067: Fixes from the conformance and app runs

- **Date**: 2026-11-22

## Context

The Node conformance suite (JavaScript lane) found 14 files passing at the
previous release and failing in this batch (the first three faults),
files killed at the runner's memory cap (the next three), and one
test-par failure. The macOS Test262 run, which has no per-test memory
limit, found the array faults: five files whose arrays grew to gigabytes.
The Linux `--static` app build found the last fault:

- `Object.getPrototypeOf(process)` answered `EventEmitter.prototype`. The
  prototype dispatch lists a library class only if the program made its
  prototype. `ProcessObject`'s was not made; `EventEmitter`'s was, so
  `process` matched the base class first.
- `Socket.on`/`once` declared a `'data'` overload typing the chunk as
  `Buffer`. A listener passed through a generic wrapper (`mustCall`) took
  that type for its parameter. After `setEncoding` the chunk is a string,
  and converting it to the `Buffer` parameter threw "the value is not an
  array". 12 HTTP server tests read responses this way.
- `Duplex.from` had no branch for a web `ReadableStream` (alone or as a
  pair's `readable`). It fell through to the iterable path.
- `Readable.from(iterable, { signal })` dropped the signal. On an infinite
  source an abort never stopped the pull, and memory grew without limit
  (`test-stream-forEach` reached the runner's 2 GB cap, at HEAD too).
- `worker.terminate()` posts the worker's end to the worker's event loop.
  A worker that never returns there (an endless microtask chain, an
  endless `postMessage` loop) ran on, its queues growing to the same cap.
- The HTTP client and server made a new parser per request. Node takes
  parsers from a shared free list, so a kept-alive socket's requests share
  one (`test-http-parser-free` asserts it); the failed assertion's message
  then took 4 GB. Each response also added a socket `'timeout'` listener
  never removed, warning after ten requests on one socket.
- `TestE2ETimerNeverFiresEarly` allowed a timer to fire at most 1 ms
  early. With libuv's idle-time metric on (ADR-01987, as Node configures
  it) a loaded CPU sees up to 1.4 ms, in Node as in this compiler: Node
  itself failed the bound in one run.
- `a.length = 4294967295` grew the buffer to the new length and cleared
  it: 32 GB touched. Linux's per-test data limit made the test fail
  quietly; on macOS, which has none, it reached 6 GB before the runner's
  guard. `Object.keys` and `for...in` then walked every index up to the
  length. HEAD did the same.
- `--static` on Linux linked c-ares as `-lcares`. Debian and Ubuntu
  install its archive as `libcares_static.a`, so every app using `dns`
  failed to link (HEAD too).

## Decision

- The prototype dispatch also lists a library class one of whose ancestors'
  prototypes the program made.
- `Socket.on`/`once` drop the `'data'` overload. The chunk is a `Buffer` or
  a string depending on the encoding, so the catch-all `any` signature is
  the one that holds.
- `Duplex.from` adapts a web `ReadableStream` with `Readable.fromWeb`, as
  Node's `duplexify` does, before the Node-stream and iterable checks.
- `Readable.from` passes `signal` to the stream it builds, as Node's
  `from` passes its options.
- A worker polls its terminate flag before each microtask and each
  `postMessage`, and ends there with exit code 1, as V8's interrupt ends
  Node's. Off a worker the flag pointer is null, one thread-local load.
  A loop that never enters the runtime is still not stopped (BACKLOG).
- Parsers come from a free list of up to 1000, as in `_http_common.js`;
  `initialize` resets a reused one. The response's `'timeout'` listener is
  removed when the socket is kept alive.
- The test's bound is Node's: 2 ms early (libuv's whole-millisecond
  clock, and the metric's zero-timeout poll ahead of the real one).
- `length` set 1024 or more past the end makes the array sparse, as a
  write that far past it already did (V8 leaves fast elements at the same
  gap): the buffer is kept and every new element is a hole. The keys of a
  sparse array list the buffer's elements, then the sparse ones in index
  order, at the cost of the elements present.
- An array walk (`indexOf`, `lastIndexOf`, `join`, …) still rebuilds a
  sparse array's buffer first. Past 2^27 elements, V8's largest dense store,
  it now ends with Node's out-of-memory message before touching memory,
  where macOS let it fill 4 GB and more; walking only the elements present
  is open in BACKLOG.
- A write far past the end of an array whose elements cannot go sparse
  (booleans, `arr[2 ** 32 - 2] = true`) grew a dense buffer to the index:
  about 4 GB on macOS. Past 2^27 elements it now ends out of memory the
  same way (`__kml_array_oom`, core.c), before the buffer is touched.
- `new Array(n)` past 2^27 allocated all n slots (and an `any[]` wrote
  `undefined` into each). Past that size it now starts empty and sets its
  length sparse, as V8 keeps such an array; an element kind that cannot
  go sparse ends out of memory.
- The same far write or `length` set through `any` (a typed array boxed
  as `any`) grew the buffer to the index: 7.7 GB for
  `staging/sm/Array/length-truncate-with-indexed.js`. It now goes sparse
  the same way for the kinds that can (numbers, strings, `any`), and ends
  out of memory past 2^27 for the rest. A write through `any` between a
  sparse array's buffer and its length now stores a sparse element, where
  it wrote past the buffer; `in` sees such an element.
- `Promise.all`, `allSettled`, `any` and `race` over an untyped iterable
  read `C.resolve` once before iterating, as GetPromiseResolve does, also
  when `C` is `Promise`. They called the built-in resolve instead, so a
  replaced `Promise.resolve` that throws never closed the iterator: on an
  endless one the combinator read on until timeout, past 1 GB (Test262
  `invoke-resolve-error-close`, four files; HEAD too).
- In static mode, where the library directory holds `libcares_static.a`
  and no `libcares.a`, the link names the former.

## Consequences

- `TestE2EDuplexFromReadableWebStream` and
  `TestE2ESocketDataStringThroughWrapper` cover the first three faults,
  `TestE2EReadableFromSignalAbortsInfinite` the fourth.
- `TestE2EPromiseCombinatorResolveThrowClosesIterator` covers the
  combinators.
- `TestE2EWorkerTerminateBusy` covers both busy workers.
- `TestE2EHTTPClientParserReuse` covers the parser and the listener.
- `TestE2EArrayLengthGrowsSparse` covers the length and the keys; the
  five Test262 files that spiked on macOS end within the guard there.
- `TestE2EFsOpendirDir` printed a close callback and an async iteration,
  two independent chains, in arrival order; it failed under load. Both are
  printed at exit now.
- All 14 Node files pass again.
- Verified on Node304 (Linux x86-64); the Test262 file on macOS arm64.
