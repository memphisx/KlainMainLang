# ADR-00396: `process.version` / `process.versions` reporting (TDD-00136 decision)

- **Relations**: Implements TDD-00136; Extends ADR-00395 (process module), ADR-00026
- **Date**: 2026-08-27

## Context

Ratifies [TDD-00136](../tdd/TDD-00136.md). `process.versions` (23 corpus uses)
and `process.version` are commonly probed by real Node code to feature-gate.
What a compiled non-Node binary should report is a design decision, not a
mechanical value: too-new a version misleads the gate, `undefined` breaks the
probe, and fabricated bundled-library versions are dishonest.

## Decision

- **`process.version`** = `"v" + <pinned Node baseline>` = **`"v22.11.0"`** — the
  Node release the `test/parallel` corpus is pinned to
  (`tools/conformance/fetch.sh` `NODE_TAG`), which is this compiler's declared
  compatibility **ceiling** (the version it aims to fully match as coverage → 100%).
- **`process.versions`** = a real object (field access / `JSON.stringify` /
  `Object.keys` all work) carrying **only honest values**:
  - `node`: `"22.11.0"` — the baseline (agreed compatibility target).
  - `v8`: `"12.4.254.21-node.21"` — that Node release's bundled V8, verbatim (the
    default until this compiler ships its own JIT to version).
  - `klain`: this compiler's own version (`version.go`, the single source of
    truth; bumped per minor release).
- **No fabricated keys.** Node's `uv`/`undici`/`icu`/`acorn`/… are omitted rather
  than faked — this compiler doesn't bundle those components, so reporting
  versions for them would be made up.

The baseline strings come from running the exact pinned release
(`nvm install 22.11.0 && node -p process.versions`), not from memory.

## Deferred (follow-on)

- **Real linked-library versions.** `openssl` (under the OpenSSL crypto/tls
  backend, not CommonCrypto) and `zlib` (linked for CompressionStream) *can* be
  reported truthfully by querying the linked library at runtime — but that needs
  backend-aware conditional linking (don't force-link libcrypto just to read
  `versions.openssl`), so it's a separate change.
- **A `--node-compat` floor.** A flag switching `node`/`v8` between this ceiling
  and a conservative floor (the lowest version whose surface is fully covered).
  Finding that floor is real work, and behavior differing across Node versions is
  its own question — deferred (TDD-00136).

## Consequences

`node`/`v8`/`version` verified byte-identical to real Node v22.11.0. A future
compatibility number will only ever *rise* toward the ceiling as coverage grows,
and no consumer is ever handed a version string this project can't stand behind.
