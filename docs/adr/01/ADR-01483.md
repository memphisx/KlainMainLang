# ADR-01483: Dictionary membership, member arrays and nested literals; `in` with a runtime key

- **Relations**: Extends ADR-01482
- **Date**: 2026-10-09

## Context

TDD-00230 P3.3 works through how dictionary types (`Record<string, T>`,
an index signature) are represented. A probe of the common dictionary
operations against Node turned up five gaps.

## Investigation

- `"b" in d` on a dictionary was a compile error ("the 'in' operator
  requires an object"). The operator only knew fixed-shape objects and
  `any`.
- `r.x.push("2")` with `r: Record<string, string[]>` was a compile error.
  The mutator's receiver resolution read `r.x` as a struct field. `r["x"]`
  already went through the value's live header.
- `JSON.stringify` of a dictionary of arrays was invalid IR. The JSON map
  writer decoded every pointer-shaped value itself and missed the array
  case (the slot holds the array's header). `mapValFromI64` already
  decodes it.
- `{ g: { h: 1 } }` declared `Record<string, Record<string, number>>`
  segfaulted on the first read. Map `set` gave the inner literal no
  contextual type, so it was built as a fixed-shape struct and then read
  as a dictionary.
- On a fixed-shape object, `k in o` with a runtime key was a compile
  error. `"toString" in o` was false and so was `"m" in c` for a class
  method or accessor (Node: true, the prototype holds them).
- `d.hasOwnProperty("a")` on a dictionary was a compile error ("unknown
  Map method"): a dictionary's method calls went to the Map runtime.
- `"toString" in x` with `x: any` holding a plain bag was false. The bag's
  chain walk stops at the unmodeled Object.prototype link, or at the
  Object.prototype bag itself (`Object.create(Object.prototype)`), which
  holds none of its members.

## Decision

- `in` on a dictionary is the dictionary's `has`.
- A mutator on a dictionary's member (`r.x.push`) resolves as the indexed
  form, through the value's header.
- The JSON map writer decodes values through `mapValFromI64`.
- Map `set` (and so a dictionary literal's values) gives a dictionary
  value type as the contextual type, the way it already does for objects
  and arrays.
- `in` and `hasOwnProperty`/`Object.hasOwn` on a fixed-shape object accept
  a runtime string key, compared against the object's own keys (an
  optional member also tests presence). `in` (not the own-key tests)
  finds Object.prototype's members and a class instance's methods and
  accessors, inherited ones included, with a literal key or a runtime one.
- On a dictionary, `hasOwnProperty` is Object.prototype's (its own keys),
  and `in` also finds Object.prototype's members.
- The dynamic bag's chain walk (`__kml_dynobj_has_chain`) answers
  Object.prototype's member names when the chain ends at the unmodeled
  link or at the Object.prototype bag. An explicit null prototype still
  answers false.
- The `hasOwn` status caveat (literal keys only) and the matching website
  difference are removed.
