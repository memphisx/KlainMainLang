# ADR-00940: Object/class array fields become header pointers — field aliasing goes live (TDD-00213 Stage 2)

- **Relations**: Implements TDD-00213 Stage 2; Relates to ADR-00939, ADR-00061, TDD-00127, TDD-00212
- **Date**: 2026-09-14

## Context

Array-typed struct fields were stored **inline** as a `{ptr,i64}` aggregate
(ADR-00061, `StructFieldIR`). So a field read produced a *snapshot*: `obj.arr`
copied the data pointer and length, and a later `obj.arr.push(x)` wrote a new
pointer/length back into the inline slot that no earlier reader saw. Worse, when a
reallocating push freed the old buffer, a snapshot taken before it (e.g.
`let x: any = obj.arr`) dangled to **garbage**. Field arrays sat entirely outside
the object-reference model (TDD-00127), which only ever applied to named array
*variables*. Stage 1 (ADR-00939) made local `let a = b` aliasing live; this stage
extends it to fields.

## Decision

An array field slot holds a **pointer to the array's shared `{data,len}` header**
(the same cell the object-reference model uses), not the inline aggregate.

- **Storage flip.** `StructFieldIR(array)` → `"ptr"`, `StructFieldSize(array)` → 8.
  Because struct types and every GEP are built from `StructFieldIR`/`StructIR`,
  field offsets stay internally consistent automatically; only the load/store of
  an array field had to learn the header indirection.
- **Central helpers.** `loadArrayFieldValue(slot)` loads the header, derefs it to
  the `{ptr,i64}` aggregate, and carries the header in `Value.ArrayHeader` (so a
  binding of `obj.arr` aliases the same array); a null header (calloc'd/absent
  field) reads as the `{null,0}` empty array. `loadArraySlotAggregate` is its
  branchless sibling for state-machine slots always written before read.
  `storeArrayFieldHeader(slot, val)` shares `val`'s live header (reference
  aliasing) or mints one from the aggregate. The three generic field helpers
  (`loadScalarOrNullableField`, `storeScalarOrNullableField[Expr]`) route array
  fields through these — coercing first so a `null` literal for a `T[] | null`
  field becomes the `{null,0}` aggregate rather than a bare `null`.
- **The mutator through a member** (`resolveArrayMutLoc`) loads the field's header
  and derives its data/len slots, so `obj.arr.push(x)` writes through the shared
  header — visible to every alias, exactly like the named-variable case.

Because `StructFieldIR` is the *universal* struct-field-storage function (83 sites
across 31 files), the flip touched every subsystem that stores a value in a
struct. Each array-in-struct read/write was updated to the header model:
member read/assign, optional-chaining, fixed-key access, object-literal/class
construction, destructuring (object + tuple), object rest/spread (a header-pointer
copy *is* the correct shallow copy — the new object shares the array),
`Object.values`/`Object.entries`, JSON stringify + JSON.parse projection, inspect,
`console.table`, structuredClone (deep-copies to a fresh header), deep-free,
standard field decorators, generators (yield/next/`yield*` value slots, via
`genLoadElemAt`/`genStoreElemAt`/`genElemValIR` — the value stays a `{ptr,i64}`
register while the slot holds a header), async/task return-value slots, the
resolved-promise value buffer + its `await` reader, `Promise.all`'s collection,
streams (for-await chunk records), and tuple element read.

## Verification

- Field aliasing is live in both directions (`let a = obj.arr; obj.arr.push()`),
  object-literal + class fields, nested class-instance array fields, and the
  formerly-dangling `let x: any = obj.arr` now renders correctly; structuredClone
  deep-copies; object spread/rest share the array (Node-matching); nullable array
  fields (`{ items: null }`) and `obj?.arr` optional chaining compile and behave;
  generators/async-generators/Promise.all/await/streams over array values all
  match Node. A regression in `Promise.all` (the resolved-value buffer) and one in
  the stream for-await chunk path were found and fixed during the sweep.
- Broad object/class/tuple/JSON/clone/spread/destructure/generator/promise/stream/
  async/inspect/decorator/nullable/optional suites pass; the full `make test-par`
  and `make examples` gates are the final check. macOS arm64.

## Notes

The shared-buffer free policy (an aliased array field's buffer may be shared, so
`-optimize-memory` deep-free could double-free) is TDD-00213 Stage 4; the deep-free
path derefs the header to stay well-typed but keeps its prior ownership assumption.
Several *pre-existing* array-in-container gaps surfaced during testing and were
confirmed on committed HEAD (out of scope here): `Map<K, T[]>` values,
`Promise.all` of `Promise<T[]>`, an array `.then` callback, and a self-referential
class's array field.
