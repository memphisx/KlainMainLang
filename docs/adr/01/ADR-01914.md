# ADR-01914: an any key on an index signature; oracle rows of the crypto, test and child-process modules

- **Relations**: `Implements TDD-00230` (P3.3 shadow buckets)
- **Date**: 2026-10-21

## Context

- The checker left `kE[key.type]` unanswered when the key is `any`; tsc reads the string index signature (else the number one).
- The oracle disagreed with codegen on:
  - a conditional between a Buffer and a Uint8Array, which codegen holds as its consequent (they share a layout; tsc keeps the union);
  - `process.hrtime`, a callable `NodeJS.HRTime` codegen holds as its call signature's function;
  - a class named by an alias or interface before the class registers (`type HookFn = (t: TestContext) => any` above `class TestContext`), which codegen resolves to the class's name placeholder;
  - a string binding of an element read (`const argv1 = process.argv[1]`) read past a guard excluding undefined since its store, which codegen reads as the payload.

## Decision

- The checker answers an `any` key with the string index, else the number index.
- The oracle mirrors each of the four codegen readings.

## Consequences

- The create-hash, fork-IPC and klainconf compiles lose their rows.
