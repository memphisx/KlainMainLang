# ADR-01841: AssignmentExpression switched to the checker

- **Relations**: `Implements TDD-00230` (P3.3: the checker answers what inferExprType did)
- **Date**: 2026-10-20

## Context

- The previous full shadow run left 28 AssignmentExpression disagreements, all from Test262. Most are assignments the old inference could not type and so gave its `i64` default:
  - implicit globals (`(y = true) && y`, `f(x = 1, y = x, x + y)`);
  - assignments inside default parameters and static initializers (`function* g(a = (g.prototype = null))`, `static f = (className = this.name)`);
  - class fields across ASI.
- The checker answers each with the assigned value's type.

## Decision

- AssignmentExpression joins the switched kinds. A node the checker has no answer for falls back to the old inference and is logged as `switchFallback`.

## Consequences

- The 14 Test262 files behind the rows behave the same compiled with and without the switch. Five fail in both builds, and none of those failures is an assignment's type.
- Verified on Apple Silicon (targeted assignment/compound/destructuring/setter/increment/chain/global tests, and all unit packages). The gate on Linux x86-64 (DeskMini) ran on the tree one step before this switch: examples 417/417, E2E green; its one unit-test failure, a test that named BinaryExpression as an unswitched kind, is fixed here.
