# ADR-01504: A JS parameter is not typed from a `null` or `undefined` argument

- **Relations**: Extends TDD-00230
- **Date**: 2026-10-09

## Context

Under `-compat=js` the checker types an unannotated parameter from its
call sites. `var f = ({}) => {}; f(null)` typed the parameter `null`,
but codegen holds it as `any`. That was bucket 6 of the shadow report
(537 rows).

## Investigation

In a JS file, tsc widens `null` and `undefined` to `any`, so such an
argument says nothing about the parameter's type.

## Decision

`inferFromSites` skips an argument whose type is exactly `null`,
`undefined` or `void`, as it already skips an `any` one.

## Divergences

None.

## Files

checker/jsmode.go, checker/jsmode_test.go

## Verification

- Mac (Apple Silicon): `TestCompatJS` (`n(null)` gives `any`, and
  `u(undefined); u(2)` gives `number`).
