# ADR-00786: `fs.readdirSync(path, { recursive: true })`

- **Relations**: extends `fs.readdirSync` (`{ withFileTypes: true }` — [ADR-00752](ADR-00752.md)); addresses the "`readdirSync` no `recursive`" gap in BACKLOG §3
- **Date**: 2026-09-08

## Context

`readdirSync` listed a single directory level. `{ recursive: true }` — a whole
subtree walk returning every nested entry as a path relative to the start
directory — is a common need (config discovery, asset scans, a `find`-like
sweep) with no ergonomic workaround short of hand-rolled recursion in user code.

## Decision

A new runtime pair in `runtime_fs.go`:

- `__kml_fs_readdir_rec(full, rel, bufslot)` — a genuinely **recursive** descent
  (the IR function calls itself per subdirectory), threading a shared
  `{data, len, cap}` accumulator. For each entry it appends the relative path
  (`rel == "" ? name : rel + "/" + name`, built with `sprintf`, stored as a
  header string) and, when the entry is a directory, recurses with the joined
  full path. A subdirectory is recognised by `d_type == DT_DIR` (4) — the fast
  path every filesystem here populates (APFS/ext4/the Windows shim).
- `__kml_fs_readdir_recursive(path)` — the wrapper: it probes the top directory
  (throwing the shared fs error on failure, as Node does for the top level),
  then seeds the recursion with an empty relative prefix and returns the
  `{ptr, i64}` string aggregate — the same shape the non-recursive form
  returns, so the emitter's `string[]` path is unchanged.

`readdirOptions` (the shared option parser, was `readdirWithFileTypes`) now
accepts `{ withFileTypes }` and `{ recursive }` in any `true` combination.
`emitFsReaddirSync` routes `recursive && !withFileTypes` to the new runtime;
inference reports `string[]` for the recursive form.

The separator is `'/'` (the POSIX runtime; Node uses the platform separator, so
`'\\'` on Windows — a minor divergence, verified on macOS).

## Not in scope (clean rejections / documented caveats)

- **`{ recursive: true, withFileTypes: true }` together** — Node returns Dirents
  keyed by `parentPath`, a distinct object shape this compiler's `Dirent` (no
  `parentPath`) can't yet represent; rejected cleanly rather than returning the
  wrong shape.
- **`DT_UNKNOWN` filesystems** — an exotic filesystem that does not report
  `d_type` (some network/FUSE mounts) is not descended (no `stat` fallback). All
  normal local filesystems populate `d_type`.

## Verification

Verified on macOS/Apple Silicon: a 3-level tree (`a.txt`, `other/d.txt`,
`sub/b.txt`, `sub/deep/c.txt`, plus the intermediate dir entries) returns the
exact 7-entry relative-path list `node`'s `readdirSync(dir, {recursive:true})`
returns. `TestE2EFsReaddirSyncRecursive`/`…RecursiveWithFileTypesRejected` (and
the retargeted bad-option test), the updated `examples/fs/fs.ts`, full
`make test-par`, Node oracle.
