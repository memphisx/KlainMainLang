# ADR-00516: `/** @pure */` — compile-time purity enforcement

- **Relations**: `Implements TDD-00128`
- **Date**: 2026-08-30

## Context

Implements TDD-00128 as designed: a `/** @pure */` JSDoc tag whose guarantee
comes from **enforcement**, not assertion. A front-end pass rejects impurity
inside a `@pure` function, with **zero runtime and zero codegen cost** — the
emitted binary is byte-identical to the untagged version. (An earlier attempt
built an unsound *trusted LLVM-attribute* lowering instead; that was the wrong
feature — it duplicated this TDD and skipped the soundness that is its whole
point — and was reverted before this.)

## Investigation

`@erased` (TDD-00010 V2) is the precedent for a bare JSDoc tag: `doc.HasTag` sets
a `bool` on the function AST node. The five impurity classes the TDD enumerates
are all detectable by a recursive AST walk of the function body plus a program-
wide set of which functions are `@pure` (for contagion). The resolver mangles
top-level names before codegen, so the check runs on mangled names (consistent,
correct) and demangles them for diagnostics.

## Decision

Parse: `doc.HasTag("pure")` sets `Pure` on `FunctionDeclaration`, and via the
declaring `const/let/var`'s JSDoc on an `ArrowFunction`/`FunctionExpression`
init; `@pure` on an async/generator or a non-function binding is a clean
parse-time error.

Enforce (`pure_check.go`, `checkPurity` run at the start of `EmitProgram` so
every compile path enforces uniformly): collect the program's `@pure` functions,
then walk each `@pure` body rejecting —

1. **Parameter mutation** — reassigning a parameter, writing to a field/element
   reachable from it, or a mutating method (`push`/`splice`/`sort`/… /
   `Object.assign(param, …)`) on it.
2. **Free/global mutation** — assigning to any binding not declared inside the
   function.
3. **I/O** — calls on `console`/`process`/`fs`/`net`/… namespaces, and bare
   `fetch`/timer/etc. calls.
4. **Nondeterminism** — `Math.random()`, `Date.now()`, `performance.now()`,
   `new Date()` (argless).
5. **Contagion** — calling a user function that is not itself `@pure`.

Local mutation (own locals, locally-constructed objects/arrays) is allowed; only
observable effects are constrained. A diagnostic names the function and the
specific violation.

## Implementation notes

- The pass distinguishes a function's **parameters** (mutation = class 1) from
  its **inner locals** (mutation allowed); a root identifier in neither is a
  free/global binding (class 2). Assignment targets are classified by their root
  identifier (`x`, `x.f`, `x[i]`, `x.a.b`).
- Nested arrows/function-expressions inside a `@pure` body are walked with the
  outer scope extended, so a mutation of an outer parameter/free variable from a
  nested closure (e.g. an impure `.map` callback) is still caught.

## Side effects discovered

Documented conservative gaps (in TDD-00128, not silent): parameter aliasing
through a local (`const y = x; y.f = 1`) is not tracked; calling a
parameter/local-held function (higher-order) is allowed — the caller's contract
in V1; an unrecognized *builtin* bare call is allowed (the pure/impure builtin
tables are curated, not exhaustive). Calls to non-`@pure` *user* functions are
always rejected. The example also surfaced an unrelated pre-existing limitation
(a function declaration cannot reference a sibling `const`-arrow binding), worked
around by using function declarations.

## Verification

- `tests/pure_test.go`: a positive case (local mutation, fresh arrays, calling
  other `@pure` functions, `.map` with a pure callback) compiles and runs
  unchanged; a rejection test per class (param reassign / param field / param
  mutating-method / global mutation / I/O / nondeterminism / `new Date()` /
  contagion / transitive contagion / async). All pass.
- `examples/jsdoc/pure.ts` output byte-identical to `node`.
- Machine: Apple Silicon M4 (macOS). Pure front-end logic, no platform path.
