# ADR-01865: The type of an object literal with a spread

- **Relations**: `Implements TDD-00230` (P3.3: the shadow report's FunctionExpression bucket)
- **Date**: 2026-10-21

## Context

- The checker answered an object literal's spread only when the spread value was `any`; `{ a: 1, ...o }` was unanswered, and so was every expression typed from it, such as an IIFE whose parameter takes the literal (`(function (obj) { … }({ a: 1, ...o }))`, Test262's `spread-mult-obj-ident.js`), which left codegen on its own inference.

## Decision

- Spreading an object literal's or type literal's type, or an interface, with no index or call signatures and every member modeled, follows tsc's `getSpreadType`: the spread's properties override earlier ones and are writable, and an optional one keeps an earlier property as the union of both.
- Any other spread (a class instance, a union, `null`, a generic) stays unanswered.

## Consequences

- `TestObjectSpreadType` holds tsc 5.6's declaration types.
- Verified on Apple Silicon.
