# ADR-01470: Var redeclaration types (TS2403); the `any` overload pass

- **Relations**: Extends ADR-01469
- **Date**: 2026-10-08

## Context

ADR-01469 made `for…in` over an array compile. Two TypeScript-suite cases
tsc rejects had been rejected only because it did not, and became false
accepts:

- `duplicateLocalVariable2`: `for (var i in chars)` then `for (var i =
  0; …)`, a `var` redeclared with another type (tsc's TS2403). The checker
  had no TS2403.
- `unusedVariablesinForLoop2`: rejected by tsc under `noUnusedLocals`
  (TS6133), which neither the checker nor the suite's harness (it ignores
  per-file compiler options) implements.

## Investigation

- A first TS2403 by type identity (interned pointers) rejected 14 cases
  tsc accepts. Two causes:
  - tsc's `chooseOverload` runs the subtype relation before
    assignability: an `any` argument is a subtype only of `any` and
    `unknown`, so `f(a)` with `a: any` picks a later `(x: any): any`
    overload over `(x: number): number`. The checker took the first
    assignable overload, so `var r3 = foo2(a); var r3 = foo3(a)` read
    `number` then `string`.
  - Object types tsc finds identical are not always one interned type
    here: an intersection and its flattening, a mapped type
    (`Required<{ b?: number | undefined }>`) and its expansion.
- A `for…in` variable had no type at all (unanswered).

## Decision

- A `for (var k in …)` variable is a `string`.
- TS2403: a `var` declaration (or `var` loop variable) after the first, of
  a type not identical to the variable's, is an error. Identity is
  approximated as assignability both ways, and decided only for types the
  checker models exactly: primitives, literals, and unions, arrays and
  tuples of them. A declaration with neither a type nor an initializer
  takes the variable's.
- Overload resolution runs a subtype pass first when an argument is
  `any`: there an `any` argument fits only an `any` or `unknown`
  parameter; without a fit, the assignability pass decides as before.

## Divergences

- TS2403 between object types is not reported; tsc reports it.
- The subtype pass differs from assignability only for an `any` argument;
  tsc's subtype relation is stricter elsewhere too (optional properties,
  `{}`).
- `noUnusedLocals`/`noUnusedParameters` stay unimplemented (BACKLOG).

## Implementation notes

`checker/symbols.go` (`declType`, the `for…in` case), `checker/check.go`
(`checkVarRedeclared`, `exactForIdentity`), `checker/overloads.go`
(`pickOverloadPass`), `diag/messages.go` (`VarRedeclaredType`).

6996 agree (from 6989), no TS2403 false reject.
