# ADR-00315: Node `Buffer` — a flagged Uint8Array with codecs and binary accessors

- **Relations**: Implements [TDD-00103](../tdd/TDD-00103.md); supersedes [ADR-00094](ADR-00094.md)'s "no Buffer class" half (its WHATWG fetch/fs return surface stands); extends [ADR-00078](ADR-00078.md), [ADR-00294](ADR-00294.md)
- **Date**: 2026-08-23

## Context

ADR-00094 chose WHATWG types for fetch/fs binary returns and built no `Buffer`. That left the hex/base64 string↔bytes codecs — which real Node CLI/microservice code reaches for constantly — with no home, and compile-failed every conformance file touching `Buffer`. This ADR adds the class; fetch/fs still return `ArrayBuffer`/`Uint8Array`.

## Investigation

Two questions dominated. Representation: a distinct object would forfeit the whole array surface; `TypedArrayType("uint8") + IsBuffer` (the `IsURLSearchParams`-on-`IsMap` pattern) gets indexing/`.length`/`.slice`/`.subarray`/numeric `.fill`/`.indexOf`/`.includes`/HOFs/for-of/`.set`/`.byteLength`/`fs.writeFileSync` for free — verified rather than assumed via `TestE2EBufferSharedArrayMachinery`. Construction position: `Buffer.from`/`alloc` are *call* syntax, so dispatching them as a namespace (the `Atomics` pattern) and returning the `{ptr,i64}` aggregate `.subarray` already returns makes Buffers general expressions with no new AST node — the TypedArray vardecl-only restriction never applies.

## Decision

Per TDD-00103. Codecs live in an embedded libc-only C runtime (`buffersrc/buffer_codecs.c`, `__kml_buf_*` ABI — hex, lenient base64/base64url, latin1), compiled alongside the program only when used (the JSON parse-tree shape, mirrored in main.go and the test harness's clang invocation). Encodings must be compile-time string literals. Statics: `from` (string+encoding / array literal / array / TypedArray / ArrayBuffer-**copy** / Buffer), `alloc(n, byteFill?)`, `allocUnsafe`, `concat` (inline literal list, totalLength truncates), `compare`, `isBuffer` (compile-time constant), `byteLength`. Instance: `toString(enc?, start?, end?)`, `write(string, offset?, enc?)`, `copy`, `equals`, `compare`, and the full `read/write{U}Int{8,16,32}{LE,BE}` + Float/Double + BigInt64/BigUInt64 accessor set — a name-parse table over the same bswap/bitcast core DataView uses, with catchable RangeError bounds checks. Cuts per the TDD (utf16le, string fills/needles, 4-arg write, swap16/32/64, toJSON, arbitrary-width readIntLE, pool statics).

## Implementation notes

New `codegen/llvm/emit_buffer.go`, `runtime_buffer.go`, `buffersrc/buffer_codecs.c`; `types.go` (`IsBuffer`/`BufferType`, `Buffer` annotation), `emit_call.go` (static namespace + instance dispatch, gated by `isBufferMethodName` so everything else falls through to the array machinery), `emit_exprs_types.go` (statics, instance methods, accessor table), `emit_exprs_operators.go` (`typeof Buffer`, plus `Blob` and the now-real BigInt TypedArray constructors), `main.go` + `tests/compiler_test.go` (compile-alongside hookup). `memcmp` declared via a new `ensureMemcmp`.

## Side effects discovered

`fs.readFileSync` has no `(path, encoding)` 2-argument form (pre-existing fs surface, unrelated) — noticed while verifying the fs round trip.

## Verification

`tests/buffer_test.go` — every expectation **diff-verified byte-identical against real Node v26.3.0** (same script run through both; only the bigint `n` suffix normalized). Codec round-trips (hex, base64, base64url unpadded, latin1 both directions), accessor endianness, RangeError, compile-time rejections (runtime encoding name, utf16le). `examples/buffer/buffer.ts` run end-to-end; `fs.writeFileSync(buffer)` round trip confirmed. Full `go test ./...` green (darwin/arm64).
