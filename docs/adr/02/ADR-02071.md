# ADR-02071: A nested array pattern's names shadow a top-level name

- **Relations**: Implements TDD-00230
- **Date**: 2026-11-23

## Context

`{ let [p, [q]] = [1, [2]]; console.log(q) }` followed by a top-level
`let q` failed to compile: `internal: undefined variable 'q__kml_mod0'`.
The tests had not resolved `-compat=js` programs that name no global
module, so `TestE2EDestructuringNestedNotIterable` passed there while the
CLI failed on the same program; resolving every test program as the CLI
does exposed it.

## Investigation

- The resolver gives a file's top-level names a per-file suffix and
  rewrites each use not shadowed by a local binding (`resolver/rename.go`).
- Its statement-level array destructuring case bound only each element's
  own `Name`. A nested sub-pattern's names never entered the block's
  scope, so `q` was rewritten to the top-level `q__kml_mod0`, not yet
  declared at that point. The object destructuring case, and parameter
  patterns, already bind nested names (`bindObjectPattern`,
  `bindArrayPattern`).

## Decision

- Each element is handled as the object case handles a property: its
  defaults, nested ones included, are rewritten (`rewriteArrayPatternDefaults`),
  then its names are bound (`bindArrayPattern`), so a later element's
  default still sees the earlier names as local.

## Consequences

- `TestE2EDestructuringNestedNotIterable` covers it.
- Verified on Node304 (Linux x86-64).
