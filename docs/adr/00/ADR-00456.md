# ADR-00456: import-equals namespace aliases (`import X = Y.Z`)

- **Relations**: Extends [ADR-00453](ADR-00453.md) (TDD-00148)
- **Date**: 2026-08-29

## Context

Two TS-oracle buckets share one feature: `expected 'from' after import
specifier list, got =` (~36, top-level `import r = M.X;`) and a large
share of the remaining `unsupported namespace member` count (the
namespace-scoped `export import X = N;` form).

## Decision

- Parser: `import IDENT =` (top level and as a namespace member, with
  optional `export`) records an `ast.NSAliasDecl{Scope, Name, Target,
  Exported}` and desugars to nothing; the CommonJS
  `import x = require('…')` form is a clean rejection pointing at ES
  imports. The resolver concatenates alias lists across files.
- Codegen: `registerNSAliases` resolves targets against the completed
  namespace table — scope-relative (innermost enclosing namespace
  outward), then absolute, following already-resolved aliases, two passes
  for later-declared alias targets; unresolvable aliases are simply not
  registered (use sites keep ordinary diagnostics). `namespaceMembers`
  (direct + relative walk) and `namespaceByChain` (longest-prefix
  expansion, bounded) then treat an alias exactly as its target
  namespace.
- V1 scope: aliases to *namespaces* only. An alias to a value member
  (`import v = M.someConst`) is not resolved — a disclosed caveat.

## Verification

Mac. `tests/namespaces_test.go` additions (namespace-scoped `export
import` used by a sibling, top-level alias of a nested namespace, alias
of a whole namespace, `require`-form rejection) and the example extension
pass; parser + namespace suites green. TS oracle aggregate flat at 5108 —
the affected corpus files stack further blockers (value aliases, ambient
modules); the alias cases themselves now surface those next blockers.
Node oracle unchanged (37).
