# TDD-00093: Module-level variables — a named `function` can read a top-level `const`/`let`

- **Status**: Implemented
- **Date**: 2026-08-20
- **Notes**: Fixes the gap TDD-00092 surfaced: a named `function` declaration couldn't read a top-level `const`/`let`/`var` (`undefined variable`), because top-level statements run in the synthetic `main()` (locals), while a function has its own fresh scope (an arrow/closure captured them, masking it). Promotes a top-level binding to an LLVM module global (pre-registered before function bodies emit) whenever its type is determinable before `main()` runs — the invariant `promotableInitInPrePass` states directly: annotations, literals, earlier module globals, and named non-generic non-async functions, computed with the *same* `lookup`/`resolveFuncRef`/`inferX` helpers `emitVarDecl` uses so it can't drift. Covers scalar/string/array/object/`Map`/`Set`, an **un-annotated call** (`const cfg = loadConfig()`), and an **earlier-global reference** (`const b = a`). `lookup` falls back to it; the var-decl emitters store into it (keyed by decl-node pointer, since a function body also runs at scope depth 1); both closure-capture paths skip it so a capturing arrow/function-expression shares the one global rather than a boxed copy. Scope-dependent inits / `bigint` / scalar-returning calls stay `main()` locals. Fixing this moved Test262 conformance +23

## Context

A named `function` declaration could not read a top-level `const`/`let`/`var`:

```ts
const BASE = 100
function add(n: number): number { return BASE + n }   // undefined variable 'BASE__kml_mod0'
```

Top-level statements are emitted into the synthetic `main()`, so a top-level binding is a `main()`
**local**; a named function is a *separate* top-level LLVM function with its own fresh scope
(`emit_func.go` resets `e.scopes`), so `e.lookup` never finds it. An arrow function / closure *did*
work — it captures free variables through its env — masking how fundamental the gap is. A module
constant used by a function is everyday code; this is a real, previously **undocumented**
limitation surfaced while testing `for await` over a typed array.

## Design

Promote a top-level `const`/`let`/`var` to an **LLVM module global** so any function — named or
closure — resolves it. Because functions are emitted (Pass 2) *before* the top-level statements run
(Pass 3), the promotion must happen in a pass **before** function bodies are emitted:

- **`registerModuleGlobals` (new Pass 1.7):** for each direct top-level declaration whose type is
  reliably a **scalar/string/object slot** (one global — a ptr for string/object) **or an array**
  (two globals — data ptr + length, matching the `Ptr`/`LenPtr` Named-Symbol shape), emit the
  global(s), register a `Symbol` in `e.moduleGlobals`, and mark the exact decl node in
  `e.promotedGlobalDecls`. `emitVarDecl`/`emitArrayVarDecl`/`emitObjectVarDecl` store into the
  global(s) for a promoted decl.
- **`lookup`** falls back to `e.moduleGlobals` after every function scope, so a function body
  resolves the name to the global; a same-named local always shadows it (checked first).
- **`emitVarDecl`** stores the initializer into the global for a promoted decl (keyed by node
  pointer, not scope depth — a function body also runs at scope depth 1) instead of a fresh local
  alloca. The global is zero-initialized and the real initializer runs in `main()` at the
  declaration's position.
- **`gatherCaptures`** skips a module global — a closure references it directly (it's in scope
  everywhere, like a top-level function name), never capturing a *second* boxed copy. Without this,
  a mutation made through the global (by a named function) wouldn't be seen by a capturing arrow.

**The invariant the feature rests on.** The promoted global's IR type must exactly match the store
`emitVarDecl` later emits, or the module is malformed. That holds precisely when the type is
**computable in the pre-pass exactly as `emitVarDecl` computes it in `main()`** — i.e. when it
depends only on things resolvable before `main()` runs: annotations (`resolveType`), literals,
**earlier module globals** (the pass runs in source order and registers each global as it goes, so
`lookup` finds them just as `emitVarDecl` will), and **named non-generic non-async functions**
(`resolveFuncRef`). It fails only when the init depends on a runtime-local binding — a destructuring
target, a block local — or on a spread / computed key / generic-or-async call / scalar-returning
call (which hits `emitVarDecl`'s `i64` default). `promotableInitInPrePass` is that rule stated
directly ("promote iff the type cannot drift"), computed with the *same* `lookup`/`resolveFuncRef`/
`inferArrayType`/`inferObjectType` helpers `emitVarDecl` uses — not a shadow inference that drifts.
This handles scalars, strings, arrays, objects, `Map`/`Set`, **an un-annotated call to a named
function** (`const cfg = loadConfig()`), and **an initializer referencing an earlier global**
(`const b = a`) — all correctly. A scope-dependent initializer (`{ …rest }`, `[localVar]`) stays a
`main()` local, never miscompiled (the earlier reactive scope-independence gate was the special case
of this invariant for literals; two suite regressions surfaced it before this general form landed). Those remain
function-inaccessible for now, a narrower documented follow-on rather than a risk.

## Stages

1. **Global scope + lookup fallback.** `e.moduleGlobals`, `e.promotedGlobalDecls`, the `lookup`
   fallback.
2. **Promotion pass + store redirect.** `registerModuleGlobals` (before Pass 2); `emitVarDecl`
   stores into the global for a promoted decl.
3. **Closure interaction.** `gatherCaptures` skips module globals (direct reference, no boxed copy).
4. **Verify** read in a named function, write in a function, shared mutation seen by a capturing
   arrow, local shadowing, multi-declarator lists, and a function declared *before* the const.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| `emitGlobal` for a module global | Built | emitter.go |

| Closure free-variable gather (`gatherCaptures`) | Built | emit_func.go — extended to skip globals |

## Open questions

- **Remaining non-promoted shapes.** A `bigint` (its `null` zero-init would crash `__kml_bigint`
  ops on a read-before-init — needs a real `0n` prologue init), a **scalar-returning** un-annotated
  call (hits `emitVarDecl`'s `i64` default — a `emitVarDecl` quirk to fix at its source, not
  replicate), and a `new Set([…])` whose element type comes from its initializer array, stay
  `main()` locals. These are the invariant's genuine edges, not representational gaps; each is a
  small follow-on (fix the `emitVarDecl` scalar-call default; a `0n` bigint prologue init; replicate
  the `Set`-initializer element inference).
- **Read before the initializer runs.** A function called at top level *before* the promoted
  declaration's line sees the global's zero value (the initializer runs at the decl's position in
  `main()`). Matches the "read before assignment → default" behavior typed `var`/`let` already
  have; not a new hazard.
