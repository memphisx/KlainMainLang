# ADR-01986: Classes whose base is a run-time value

- **Relations**: Implements TDD-00230; follows [ADR-01979](ADR-01979.md)
- **Date**: 2026-11-07

## Context

`const Base = c ? A : B; class C extends Base {}`, and a mixin over a
parameter (`function mix(Base: Ctor) { return class extends Base {} }`
applied to anything but a class name), were rejected. A class's layout is
fixed at compile time, so its base has to be a class the compiler knows.

## Decision

The program is the whole world, so the classes a base value can hold are
known. Before the front end runs, a preliminary check lists them
(`checker.DynamicBase`):

- A member of the value's type that is a class's own value (`typeof A`)
  names that class. A builtin constructor's type (`TypeErrorConstructor`)
  names its global.
- Any other member with construct signatures names every program class
  whose value fits it. A class whose instance this checker types `any` is
  checked by the members its instance declares.
- A base typed `any` names every program class that has each member the
  class body reads through `this` or `super` without declaring it.

The class is then specialized. Each candidate gets a copy extending it, and
the declaration becomes a constant selecting the copy by the base's
identity: `const C = Base === A ? class C extends A {…} : … : <TypeError>`,
with `type C = InstanceType<typeof C>` beside a non-generic one. A value
matching no candidate throws Node's `Class extends value … is not a
constructor or null`. A class expression among the candidates that names
no local of its function is lifted to a top-level class, so that the base's
scope can name it.

Each copy is a real subclass of its base. `instanceof`, the prototype
chain, `super` and the base's fields and statics are those of that class.

A JavaScript file is left out. It already makes such a class from the
value at run time, which also takes a builtin or a constructor function
the candidates would miss.

A qualified base reached through a value is a value base as well:

- `class T extends events.EventEmitter`, with `events` a `require()` or a
  default import, extends a constant holding that member.
- When the member is a class's static getter that only returns a class
  (`events.EventEmitter`, the module being the class), the base, and any
  `new events.EventEmitter()`, is that class itself.
- The resolver now renames such a qualifier's root to the target's
  top-level name, as it does for a namespace import.

Two checker gaps found on the way are fixed:

- A class value whose construct signature only might fit a constructor
  type was taken as fitting. `const y: Ctor = Q`, with Q lacking a member
  `Ctor`'s instance requires, now fails as in tsc (TS2322, TS2345).
- A union of constructors taking another number of type arguments than
  the `extends` clause gives (`Map | Set` with two) is TS2507.

## Consequences

- A candidate class expression that names its function's locals cannot be
  lifted. A class whose base can hold one is still rejected.
- A lifted class expression is one class however often it is evaluated,
  as codegen's own class-expression hoisting already makes it.
- Covered by `TestE2EDynamicBaseClasses` and
  `TestE2EExtendsModuleStaticClass`, which match Node, and by the
  `examples/classes/dynamic_base.ts` example.
