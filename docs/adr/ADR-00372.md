# ADR-00372: Treat a UTF-8 BOM as whitespace; TS false-reject leverage map

- **Relations**: Implements TDD-00121
- **Date**: 2026-08-26

## Context

A review of the TypeScript accept/reject conformance oracle (Track C of the
conformance suite) surfaced that the single largest source of disagreement with
TypeScript was a lexer gap, not a missing language feature: a source file that
begins with a UTF-8 byte-order mark (U+FEFF) was rejected outright with
`unexpected character '﻿'`. A leading BOM is extremely common in
real-world editor/tooling output and is valid input every conforming
JS/TS toolchain accepts, so this was a genuine bug masking a large slice of
otherwise-compilable code.

## Investigation

The false-reject buckets in the TS oracle were previously unenumerated — the
report listed only false-accepts. To locate the gap, the report generator was
extended with two histograms over the false-reject set (TS accepts, this
compiler rejects): one bucketing the normalized rejection *reason*, one
bucketing the concrete *blocker* token (`blockerOf`, the un-masked
identifier/character). The blocker histogram ranked `﻿` first at 478
cases — more than 2× the next entry (`@`, decorators, 169).

Repro:

```
printf '\xef\xbb\xbfconst x: number = 5;\n' > bom.ts
klainmain bom.ts   # parse error: 1:1: unexpected character '﻿'
```

Root cause: `lexer.skipWhitespace` (`lexer/lexer.go`) gates on
`unicode.IsSpace`, which — matching Go's own source rules — does **not**
include U+FEFF. ECMAScript, by contrast, lists U+FEFF (ZWNBSP) in its
`WhiteSpace` production, so it is skippable whitespace anywhere, not only at
file start.

## Decision

Extend `skipWhitespace` to also skip U+FEFF, matching ECMAScript's `WhiteSpace`
production. This handles both a leading BOM and a stray mid-stream ZWNBSP with
one change, and keeps the treatment consistent with real JS/TS rather than
special-casing only offset 0. Strings and template literals are unaffected —
`skipWhitespace` is never called inside them.

## Implementation notes

- `lexer/lexer.go`: `skipWhitespace` now skips `unicode.IsSpace(c) || c ==
  '﻿'`.
- Report generator (`tools/conformance/ts.go`): added a false-reject reason
  histogram and a false-reject blocker histogram, mirroring the Node runner's
  failure-reason table, so the highest-leverage front-end gaps are visible in
  the report rather than requiring ad-hoc mining. `tsResult` gained a `Blocker`
  field populated from the raw compile error via the existing `blockerOf`.

## Side effects discovered

The blocker histogram surfaced several other common, currently-unsupported TS
constructs that the review has now documented as caveats/gaps on the status
pages rather than fixing here (each is its own feature-sized change): the
`debugger` statement, the `readonly T[]` array-type modifier, a `this`
parameter (`function f(this: T, ...)`), ambient `declare`, and the `arguments`
object. Conversely, it confirmed several common constructs already work and are
already marked ✅ (numeric/string/`const` enums, `namespace` blocks,
`satisfies`, `as const`).

## Verification

- `lexer/lexer_test.go`: added `TestLeadingBOM` (leading BOM before `const`,
  and a stray mid-stream BOM), passing.
- `go test ./lexer/ ./parser/` pass; `go vet` clean.
- TS oracle (`make conformance-ts`) agreement rose 51.4% → 53.5%, with
  match-accept 762 → 1001 (+239 previously-rejected cases now compile clean);
  the `﻿` blocker bucket is gone.
