# ADR-01342: TS2339 for a builtin interface's missing member

- **Relations**: Implements TDD-00230 (P2.7), Extends ADR-01132, ADR-01139
- **Date**: 2026-10-03

## Context

The builtin declarations (`lib/*.d.ts`) list what this compiler implements,
not all of TypeScript's library. A builtin interface's type is therefore
marked partial (`checker/symbols.go`), and the checker reported no TS2339 on
it. Before this, all of these compiled in the strict lane:

- `p.exec(u).get("id")` on a `URLPatternResult`;
- `[1].values().length`;
- `d.foo` on a `Date`.

Codegen then rejected some of them with its own error, and compiled others
silently. tsc reports each one as TS2339.

## Investigation

- `tools/libconform` already parses TypeScript's library (`lib/conform`,
  ADR-01132) to diff it against the builtin declarations. It recorded each
  interface's members but not its `extends` list.
- The question tsc answers is whether the member exists on TypeScript's
  declaration of the interface or a base. Our declaration missing a member
  doesn't make it absent.
- Taking every member of every one of TypeScript's declarations of an
  interface (all its lib files, `esnext` and `dom` included) is the most
  permissive reading. It never reports a member some lib configuration
  declares, so it gives no false positives against tsc with the full
  library.
- A callable value (a constructor interface such as `MapConstructor`) also
  has `Function`'s members (`Map.name`).

## Decision

1. `lib/conform` records each interface's `extends` names. `MemberLines`
   writes, for every TypeScript library interface the builtin declarations
   also declare, and each base those extend, its member names and bases.
   `tools/libconform -members lib/tsmembers.txt` generates the file;
   `TestMemberListUpToDate` guards it.
2. `lib.TSInterfaceHas(name, member)` reads the embedded list, walking
   the bases.
3. The checker's `libLacks` reports TS2339 when all of these hold:
   - the member is read on a builtin interface's type;
   - neither our declaration nor an index signature has it;
   - TypeScript's library knows the interface but neither it nor a base
     has the member;
   - for a callable type, `Function` doesn't have it either.

   A program's augmentation of a builtin interface declares its own
   members, which are found first.

## Implementation notes

`lib/conform/{conform.go,conform_test.go}`, `tools/libconform/main.go`,
`lib/lib.go`, `lib/tsmembers.txt`, `checker/check.go`.

## Side effects discovered

- Interfaces only `@types/node` declares (`Buffer`, the Node modules'
  types) are not in the list: its files do not parse whole
  (`lib/conform`). A member missing from them stays unreported.
- A member read on the result of a chained generic call
  (`Promise.resolve(1).then(x => x).foo`) is not reported: the checker
  leaves that `then`'s result open.

## Verification

Mac (Apple Silicon):
- probes of URLPatternResult, ArrayIterator, Date, RegExp and Promise
  against tsc 5.9.3;
- a program importing the builtin modules compiles unchanged;
- the checker test binary under the memory guard;
- `go test ./lib/...`.
