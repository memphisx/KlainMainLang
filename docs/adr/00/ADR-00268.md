# ADR-00268: Microtask-accurate `await` ordering — every `await` yields a tick

- **Relations**: `Implements TDD-00088`; refines [ADR-00249](ADR-00249.md) (TDD-00084 Part A's inline async fns), builds on [ADR-00248](ADR-00248.md) (reactions), the fiber scheduler
- **Date**: 2026-08-20

## Context

`await` on an already-settled promise read it synchronously instead of yielding a
microtask tick. Real JS suspends at *every* `await` and resumes via a microtask, so
code queued first runs first:

```
async function f() { console.log("a"); await Promise.resolve(1); console.log("b") }
f(); console.log("c")            // JS: a c b   — was: a b c
```
```
console.log("1"); Promise.resolve().then(()=>console.log("3"))
console.log("2"); await Promise.resolve(); console.log("4")   // JS: 1 2 3 4 — was: 1 2 4 3
```

Root: a non-may-suspend ("inline", TDD-00084 Part A) async fn ran straight through
with no suspension point; even a may-suspend fn took a settled `await` synchronously.

## Decision

**Every `await` yields a microtask tick, and the resume is a microtask ordered in
FIFO with `.then`/`queueMicrotask`** — reusing the promise reaction list, the
microtask FIFO, and the fiber scheduler's swap-into-a-task.

- **Classification** broadens: any async fn whose body contains an `await` runs as
  a coroutine task (fiber) — it needs a suspension point. A no-`await` async fn
  stays inline (settles immediately; nothing to order).
- **`@__kml_task_await_ready`** (on a task) builds a *resume-this-task* closure and
  either enqueues it now (promise already settled) or attaches it to the promise's
  reaction list (pending — enqueued when the promise settles), then parks the task
  in a new **state 3** ("parked on a reaction") that the scheduler ignores, so only
  the resume microtask wakes it. The resume runs as a microtask, in FIFO order.
- **`@__kml_task_resume`** is the resume closure's runner: it mirrors the
  scheduler's resume prologue (jmpbuf-stack swap, `current_task`, GC stackbottom,
  `resumerCtx = main`) and `swapcontext`s into the parked task from the
  microtask-drain context; the task swaps back here when it next parks/finishes.
- At **top level** (no current task, can't park) `await` drives the microtask FIFO
  + scheduler + timers until the promise settles.

## Consequences

- `await` (settled or pending) always yields a tick; `a c b`, `1 2 3 4`, and the
  full FIFO interleave of concurrent async flows against `queueMicrotask`
  (`a1 b1 sync a2 b2 qm a3 b3`) all match JS. The `async` functions and `await`
  rows are now strict.
- Every async fn containing an `await` now links the fiber/task runtime (TDD-00084
  Part A's "no fiber for a pure-async program" relaxes). `libcurl` is still linked
  only when `fetch` is used. Full suite runtime was unaffected (even slightly
  faster).
- The task-await mechanism changed from park-and-scheduler-poll to
  register-reaction-and-resume-via-microtask; the fetch/`await_fetch` path
  (a Promise<Response> handle, not a task promise) is untouched.

## Verification

- `go build`, `go vet ./...` clean; full `go test ./...` green — the entire
  async/generator/fetch/timer/http/websocket/event suite passes under the rewritten
  await, no regressions.
- New E2E: `TestE2EAwaitYieldsFireAndForget`, `TestE2EAwaitYieldsVsThen`,
  `TestE2EAwaitFIFOInterleave`.
- `make examples` at delivery; conformance batched to session end. Apple Silicon (macOS).
