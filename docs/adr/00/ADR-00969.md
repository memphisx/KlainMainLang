# ADR-00969: Stable header identity for named-function values

- **Date**: 2026-09-15

## Context

`removeEventListener`/`EventEmitter.off` given a listener by a *named-function*
reference never matched, so the listener was never removed:

```ts
function onPing(msg: string): void { count++ }
ee.on('ping', onPing)
ee.off('ping', onPing)   // did NOT remove
ee.emit('ping', 'x')     // still fired → count == 2
```

A const-bound closure (`const onPing = (msg) => {...}`) removed correctly. The
gap affected every arity and both the EventEmitter and EventTarget removal
paths, which compare stored listener *header pointers* for identity.

## Investigation

`emitNamedFuncValue` (emit_func_value.go) materializes the closure header a
named function is seen as when taken by value (`{ trampoline, env }`). It
`malloc`'d a **fresh** 16-byte header at *every* reference. So `ee.on('ping',
onPing)` and `ee.off('ping', onPing)` produced two different heap pointers, and
the pointer-equality removal check could never succeed.

The header's contents are, however, a compile-time constant: the trampoline
symbol is fixed per function (already memoized per mangled name), and the env
pointer for a named function is always `null` and is never mutated (only real
closures carry a captured, mutable env). So the per-reference `malloc` bought
nothing but a fresh — and therefore non-matching — address.

## Decision

Emit the `{ trampoline, null }` header **once per named function** as a private
global constant and return its address from `emitNamedFuncValue`:

```
@__fnval_hdr_<sym> = private unnamed_addr constant {ptr, ptr} { ptr @__fnval_<sym>, ptr null }
```

Every reference to the same named function now yields the same pointer, so
identity comparisons (removal, `===` between two references) behave correctly,
and no per-reference allocation is emitted.

## Implementation notes

- New memo `Emitter.fnValueHeaders` (keyed by mangled name), initialized in
  `NewEmitter`, guards single emission of the global.
- `emitNamedFuncValue` returns `Value{Ref: "@__fnval_hdr_<sym>"}` — an LLVM
  global symbol is a valid `ptr` operand anywhere the closure-call path uses the
  header, so the ordinary `emitClosureCall` path is unchanged.
- The header is now a static (non-heap) value. `Memory.free`-ing a bare
  function reference is therefore undefined in exactly the same way freeing a
  string literal already is — see the interned-literal note in
  `freeResolvedPointer` (emit_memory.go). This is consistent with existing
  project practice for non-owned static values.

## Side effects discovered

None new. The change removes a per-reference `malloc`, so named-function values
are also marginally cheaper.

## Verification

- New E2E regressions, both green:
  `TestE2EEventEmitterOffByNamedFunctionRef` (emitter: emit → off → emit,
  count stays 1) and `TestE2EEventTargetRemoveByNamedFunctionRef`
  (target: dispatch → removeEventListener → dispatch, hits stays 1).
- Existing function-value/closure/first-class/HOF/apply/callback and
  event/emitter/abort E2E suites pass unchanged.
- `go build`, `go vet ./...` clean. macOS arm64 (M4).
