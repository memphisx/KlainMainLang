# ADR-01044: A module top-level `await` takes its one microtask tick

- **Relations**: `Extends ADR-00268, ADR-00281`; `Implements TDD-00088, TDD-00223` (§1: waiting from the main stack)
- **Date**: 2026-09-21

## Context

Looking into Test262's `language/module-code/top-level-await/top-level-ticks.js` (in the conformance run's
timeout bucket) with a TypeScript transcription:

```ts
const actual: string[] = [];
Promise.resolve(0)
  .then(() => actual.push('tick 1')).then(() => actual.push('tick 2'))
  .then(() => actual.push('tick 3')).then(() => actual.push('tick 4'))
  .then(() => console.log(actual.join(",")));
await 1; actual.push('await 1');
await 2; actual.push('await 2');
await 3; actual.push('await 3');
await 4; actual.push('await 4');
```

Node: `tick 1,await 1,tick 2,await 2,tick 3,await 3,tick 4,await 4`. This compiler:
`await 1,await 2,await 3,await 4,tick 1,…` — every `await` line ran before the first reaction. The `await`
status row claimed "every `await` yields a microtask tick" without qualification.

## Investigation

- Inside an async function the order was already Node's (probe with `await 1` / `await undefined` /
  `await Promise.resolve(3)` against a five-link `.then` chain: identical). `emitAwait` wraps a plain value in a
  settled task promise and parks; the resume is a microtask (TDD-00088).
- At module top level there is no task to park: `emitAwait` returned a plain value unchanged ("outside a task
  context … the plain identity return stands"), and `@__kml_top_await` returned at once for a promise whose state
  word was already non-zero. Neither let a single queued job run.
- What JS does for such an await: the continuation is queued behind the jobs already in the microtask queue and
  ahead of anything those jobs enqueue. For code that cannot be queued — the main stack — the same order results
  from running exactly the jobs queued at that moment, then carrying on: a job enqueued by one of them lands
  after the continuation in both models.
- Making the module body a coroutine (what an engine does) would give this for free, including for a *pending*
  promise, where the continuation's position among the promise's other reactions is also observable. That
  reshapes `main()` (module-global initialisation order, the loop's ownership of the main stack — TDD-00223 §1
  chose main-stack waits deliberately); it is not needed for the settled/plain-value case.

## Decision

`@__kml_microtask_tick()` (next to `@__kml_drain_microtasks`): snapshot the queue length, run jobs while
`head < snapshot && head < len` (both re-read each iteration — a job may run a full drain, which resets the
indices), reset the indices if the queue ended empty. Called

- by `emitAwait` for a non-promise operand when there is no enclosing async callable or generator, and
- by `@__kml_top_await` on entry when the awaited promise is already settled (then it returns; the pending path
  is unchanged).

A program with no microtask runtime gets a no-op definition from `emitLoopTaskStubs` (`needMicrotaskTick`).

## Side effects discovered

The Test262 file itself is a `CODEGEN_TIMEOUT` in the conformance harness, which this does not explain: the
TypeScript transcription compiles in well under a second. The hang needs the harness-wrapped source
(`compareArray.js` + the async `$DONE` shim) to reproduce.

**A top-level await of a *pending* promise is still out of order — not fixed here.** Probe: a promise resolved
by a 5 ms timer, with a reaction `r1` registered before the top-level `await p` (and `r1` enqueueing a child
job), then a reaction `r2` registered after it. Node: `r1,top-7,r1-child,r2,end`; this compiler:
`top-7,r1,r2,end,r1-child` — the continuation runs *before* the reactions registered ahead of it, because
`@__kml_top_await` polls the state word after a loop turn instead of being a reaction in the promise's own list.
The faithful shapes are (a) the module body as a coroutine, or (b) the await registering a reaction that stops an
interruptible microtask drain at its own position; both change TDD-00223 §1 and want a TDD. Disclosed as a
caveat on the `await` status row.
