# ADR-01341: Compiler fixes found by porting URLPattern and Web Crypto

- **Relations**: Extends ADR-01339, ADR-01340, ADR-00265, ADR-01311, ADR-00619
- **Date**: 2026-10-03

## Context

Porting the URL Pattern Standard (ADR-01340) and Node's Web Crypto
`SubtleCrypto` to TypeScript compiled several thousand lines of
library-style code. They were diffed against Node 24.19 case by case and
found these compiler bugs, each reduced to a minimal program. The Web
Crypto port itself is not wired: its RSA/EC/X25519 private-key math is
BigInt TypeScript (not constant-time, no RSA blinding). It waits for
`crypto`'s missing OpenSSL primitives.

## Investigation and decision, per bug

**Control flow and types**
- **A statement call of a `never` function did not end the flow.** So
  `try { r = s } catch { fail() } return r` was TS2454. The binder now
  ends the flow after an expression statement calling a function whose
  every declaration states `: never` (tsc binds the same rule). `return
  fail()` emitted `ret i64` in a `ptr` function; a return of a
  never-typed call now emits the call and `unreachable`.
- **An assignment's right side had no contextual type.** So `pt = [d, d]`
  for `pt: [number, number] | null` was `number[]`, and the narrowing kept
  `null` (a false "possibly null"). The checker's `contextualType` now
  gives an assignment's right side the target binding's declared type.
- **Assignment narrowing computed the stored value's type even when the
  declared type is not a union.** It re-walked every binding that
  expression read, which is exponential for loop variables assigned from
  each other: a 15-line X25519 ladder took 3 GB in two seconds. As in
  tsc's `getTypeAtFlowAssignment`, a non-union declared type is returned
  without computing it.
- **Returns of different representations.** An unannotated function or
  arrow whose returns differ and whose checker type has no single
  representation (`false | ArrayBuffer`) kept the first return's type,
  which is invalid IR. It is now `any`, each return boxed. Closures
  (`inferUnannotatedReturnTypeParams`) now apply the same disagreement
  rule as declarations.
- **Generic inference from a callback.** `job<T>(fn: () => T)` now infers
  T from the callback argument's return type.

**Calls, rest and spread**
- **Spreads and rest parameters.**
  - `new C(...args)` did not parse.
  - A rest parameter on a constructor, and `super(..., ...rest)`, were
    rejected. Constructors and `super` calls now pack rest arguments
    (`packRestArgs`, shared with methods).
  - A spread whose elements differ from the rest's (numbers into
    `any[]`) was rejected. It is now built as an array literal of the
    rest's element type, on every call path.
- **A Buffer in a `Uint8Array[]` slot was rejected.** A Buffer is a
  `Uint8Array`, so the storage check accepts it.
- **`null` for a method's `T[] | null` parameter** passes the null header,
  as functions do.

**Module-level bindings read by functions**
- A constant bigint expression (`(1n << 255n) - 19n`) was not promoted to
  a module global; it is now.
- A property path off an `any` module global (`const s = c.subtle`) is
  promoted as `any`.
- An arrow or function-expression initializer is promoted with its
  function type.

**Promises and async**
- **A handler that throws rejects the derived promise.** It was an
  uncaught exception. Reactions run under `__kml_then_guard`
  (`promisesrc/defer.c`), which keeps the runner in a sixth env slot and,
  on a throw, rejects Q with the thrown value (NewPromiseReactionJob).
- **A `Promise<any>` async function returning a promise.** It boxed the
  promise, or read the inner value at `any`. It now awaits the returned
  promise at the promise's own value type; a value held in `any` is
  awaited as a thenable.
- **An async arrow's expression body.** It is now its `return` (an array
  stored as its header, a promise adopted). The arrow's emitted type is a
  task promise, as inference types it (an IIFE of one crashed).
- **`Promise.all`/`allSettled` over `Promise<void>` members** stored `void`
  elements (invalid IR); each value is now `undefined`.
- **A callback with an annotated parameter over `Promise<any>`**
  (`.then((buf: ArrayBuffer) => …)`) is adapted to unbox the value.
- **A parameter of a suspending async function captured by closures** is
  boxed at entry, which dominates every capture (a capture in a loop and
  another after it was invalid IR). This is ADR-00619 for task bodies.

**Values and representations**
- **A conditional where an object or dictionary is expected** builds each
  branch against it, so `{}` is the dictionary. It had been an empty
  struct read as a map, a segfault.
- **A typed array element bound to an unannotated local** is a number, not
  the element's storage width: `let n = b[1]; n = n * 256 + b[2]` wrapped
  at 8 bits.
- **`fill`/`sort`/`reverse`/`copyWithin` on a typed array** keep its type,
  so the result boxes as a view.
- **`Object.defineProperty` on an Error** stores the descriptor's value as
  an assignment does: a named key reaches the error's field.
- **DOMException.**
  - `new DOMException(message, { name, cause })` now takes the options
    form.
  - An error's `constructor` is its kind (a DOMException named
    `DataError` is a `DOMException`), or its class for an Error subclass.

**JSON and inspection**
- **`JSON.stringify`.**
  - A dictionary leaves out `undefined` values.
  - A dictionary follows the `space` argument.
  - A dictionary nested in an object or array is serialized; it had been
    a garbage string.
  - A `Map` or `Set` is `{}` (no enumerable own properties); a string-keyed
    Map had been serialized as an object.
- **`console.log`/`util.inspect`.**
  - A typed array past the depth limit is `[Uint8Array]` /
    `Uint8Array(0) []`.
  - A custom inspect function gets the configured depth as
    `options.depth`.

**Modules**
- **`events`' default export names itself.** `require('events').EventEmitter`
  (`import events from 'events'; events.EventEmitter`) was "no static
  field". `EventEmitter` now has a static `EventEmitter` returning the class,
  as lib/events.js assigns it.

**Text and regexes**
- **`TextDecoder.decode`** is the WHATWG UTF-8 decoder: U+FFFD for an
  invalid sequence, and a leading BOM dropped. It takes any
  ArrayBufferView, and one held in `any` (`__kml_any_view_bytes`).
- **`Buffer.toString('base64url')`** reported the padded length; the
  header now carries the written length.
- **`[^]` and `[]`** are rewritten for every ES regex dialect
  (`__kml_regex_es_classes`). PCRE reads a `]` right after `[` as a
  member.

- **The test harness** compiled a program without the resolver's renaming,
  so a top-level `main` met C's entry point there (never under the CLI). A
  program declaring `main` now goes through the resolver, as the CLI's does.

## Side effects discovered

Still open:
- `arguments.length` counts declared optional parameters (the call ABI
  passes no count);
- `u.buffer`/`u.byteOffset` need typed arrays to carry their buffer and
  offset (P3.3);
- a NUL in a parsed JSON string truncates it (NUL-terminated strings);
- `'é'.length` is a byte count (byte-indexed strings);
- `URL` hostnames get no UTS #46 mapping;
- descriptor attributes on an Error (a non-enumerable `cause`);
- an assigned `cause` is missing from `Object.keys`.

## Verification

Mac (Apple Silicon), against Node v24.19:
- each bug's reduced program;
- the checker test binary under the memory guard;
- the targeted E2E groups: Async, Await, Arrow, Promise, Closure, Capture,
  Generic, JSON, TypedArray, Buffer, TextDecoder, Error, RegExp.
