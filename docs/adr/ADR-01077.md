# ADR-01077: `os` breadth, `process.env` as a value, `for…of` / `Object.entries` over `any`

- **Relations**: Extends ADR-00090 (the `os` module), ADR-01032 (Windows `os.homedir`); Implements TDD-00155 Stage 6 residue (`Object.values`/`entries` on dynamic objects)
- **Date**: 2026-09-22

## Context

BACKLOG §2 (cross-platform features that block a Windows row): `process.env` enumeration (`Object.keys`,
`for…in`, spread) and the `os.*` breadth — `type`/`release`/`version`/`arch`/`endianness`/`uptime`/`loadavg`/
`userInfo`/`networkInterfaces`/`availableParallelism`/`devNull`/`machine`. None of them existed on any host:
`process.env` was a pseudo-namespace that only answered keyed reads and writes, and the `os` module stopped at
`cpus()`.

## Investigation

- `process.env.KEY` reads go through `getenv` and a header-string copy (`emit_process.go`), writes through
  `setenv`, deletes through `unsetenv`; on Windows the win32 shim implements all three over the wide API against
  the live block (`win32shim.c` "environment"). A bare `process.env` fell into the generic member path and
  failed.
- The enumeration surface a program uses — `Object.keys`, `for…in`, spread, `JSON.stringify`, `const env =
  process.env; env.X` — is exactly what a D1 dynamic object (`__kml_dynobj`, TDD-00155) already provides once
  the value is `any`. Building the value as a bag makes every one of those fall out of the existing paths.
- `os.networkInterfaces()` is keyed by interface *name*, a run-time key set, so it is a bag too; its entries are
  `{address, netmask, family, mac, internal, cidr, scopeid?}` in libuv's order, with `scopeid` present on IPv6
  entries only — the JSON shape is what tests compare against Node.
- The values libuv reports: `os.release()` on Windows is `RtlGetVersion`'s `major.minor.build` (unaffected by
  the manifest shim `GetVersionEx` applies); `os.version()` is the registry `ProductName`, with libuv's
  "Windows 10" → "Windows 11" rewrite for build ≥ 22000; `os.uptime()` is `CLOCK_BOOTTIME` (Linux),
  `kern.boottime` (Darwin), `GetTickCount64()/1000` (Windows); `loadavg()` is `[0,0,0]` on Windows;
  `userInfo()` has `uid`/`gid` `-1` and `shell` `null` on Windows; `availableParallelism()` is the affinity-set
  count on Linux.
- Iterating the result surfaced two D1 gaps: `for (const ni of nis[name])` — `for…of` over an `any` value was a
  hard rejection — and `Object.entries(process.env)`, the "`Object.values`/`entries` on dynamic objects" residue
  listed under §1 D1. Both block the item's natural use, so both are built here.
- The Windows win32 shim binds Winsock through `GetProcAddress` and *defines* `inet_ntop` under its POSIX name
  (`win32io.c`); a sidecar calling the header's `inet_ntop`/`htonl` links against `__imp_*` and fails, so the
  Windows address formatting is hand-rolled.

## Decision

1. **One C sidecar, `codegen/llvm/osinfosrc/osinfo.c`** (`osinfo_c.go`: `OSInfoSource`, `OSInfoLibs`,
   `UsesOSInfo`, `ensureOSInfo`), POSIX and Windows branches, read against the platform headers so no
   `utsname`/`passwd`/`ifaddrs`/`IP_ADAPTER_ADDRESSES` layout is reproduced in IR. It exposes
   `__kml_env_entries` (a NUL-terminated `"K=V"` array — `environ` copy on POSIX, `GetEnvironmentStringsW` on
   Windows with the `=X:` drive entries skipped), `__kml_os_type/release/version/machine`, `__kml_os_uptime`,
   `__kml_os_loadavg`, `__kml_os_avail_parallelism`, `__kml_os_userinfo` and `__kml_os_netifs` (a flat
   `kml_ifaddr` record array: name, address, netmask, family, mac, internal, scopeid, prefix — the CIDR prefix is
   computed in C, `-1` for a non-contiguous mask → `cidr: null`). Windows links `-liphlpapi`.
2. **`emit_osinfo.go`**: two IR bag builders (`@__kml_process_env_bag`, `@__kml_os_netifs_bag`) over the
   sidecar; `emitProcessEnvValue` for the bare `process.env` member (type `any`); `emitOSCall` for the new
   `os.*` calls — `arch`/`endianness` are compile-time constants like `process.arch`, `userInfo()` is a static
   `{uid, gid, username, homedir, shell: string | null}` object, `networkInterfaces()` is `any`; `os.devNull` is
   a member constant. `osInfoCallType` mirrors the types for `inferExprType`. The resolver's `os` export list
   gains the twelve names.
3. **`for…of` over `any`** (`emit_stmts_forof_any.go`): a dynarr or a boxed static array iterates by its runtime
   `length` and per-index dynamic reads (both shapes come out by their own element-kind rules), the loop variable
   is `any`, patterns destructure through the dynamic unpackers, and the length is re-read each pass. Any other
   tag throws Node's `TypeError: x is not iterable`.
4. **`Object.entries` / `Object.values` on `any`** (`emitDynAnyEntries`): a dynamic array of `[key, value]`
   two-element dynarrs (or of values) — JS's real tuple shape — for a bag (enumerable own keys in ES order) or
   either array shape (`["0", v0], …`); null/undefined throw; other tags give `[]`. The result type is `any`.
5. **An object literal spreading a bare `any`** (`{ ...process.env, X: "1" }`) builds as a D1 dynamic object
   (`hasDynamicSpread` → `emitDynObjLiteral`, type `any`), since its key set exists only at run time.

The `process.env` bag is a **snapshot** taken when the bare expression is evaluated: `Object.keys`, `for…in`,
spread and `JSON.stringify` see the live block at that moment, and keyed reads/writes (`process.env.X`) stay
live — but a write through an alias (`const env = process.env; env.X = "1"`) lands in the copy, not the
environment. Node's object is a live proxy; making the bag one needs a per-instance hook on `__kml_dynobj_set`
(a Proxy-shaped bag), recorded as the row's caveat.

## Implementation notes

`codegen/llvm/osinfosrc/osinfo.c`, `osinfo_c.go`, `emit_osinfo.go`, `emit_stmts_forof_any.go`,
`emit_dynobj.go` (`ensureDynObjEntries`, `emitDynAnyEntries`), `emit_objects.go` (the `any` arms of
`emitObjectValues`/`emitObjectEntries`, the dynamic-spread route), `emit_exprs_types.go` (`hasDynamicSpread`,
the `env`/`devNull`/`os.*`/`Object.values|entries` types), `emit_exprs_member.go`, `emit_call.go`,
`emit_stmts.go`, `embedded_c.go`, `emitter.go`, `resolver/virtual_modules.go`; `tests/compiler_test.go`
(`appendOSInfo` at every build site, `assertSameAsNodeImports`), `tests/memory_auto_test.go`.

The IPv6 formatter is RFC 5952 (longest zero run collapsed, lowercase) — what `inet_ntop` prints on every
platform, so the Windows output matches Node's byte for byte.

## Side effects discovered

- Array methods called through `any` (`anyArr.push`, `.includes`) and `<` on `any` are still rejected — the §1
  D1 "primitive-member dispatch through `any`" residue, unchanged.
- `Object.entries`/`values` on a *static* array (`Object.entries([7, 8])`) is still rejected — only the `any`
  route builds pairs. Recorded as a caveat on both rows.
- `emitObjectEntries`'s doc comment still describes the pre-tuple `{key, value}` shape; the status row (and the
  code) are the `[string, string][]` tuple form.

## Verification

Windows (this box), byte-identical to Node 24: `os.type/arch/endianness/devNull/release/version/machine`,
`loadavg`, `userInfo` (`-1 -1 null`), and the full `networkInterfaces()` walk — five adapters, interface order,
`fe80::…/64` CIDRs, `scopeid` on IPv6 only, the loopback JSON. E2E: `tests/os_info_test.go` (nine tests, Node
as oracle for every host-state answer). Linux: the Docker suite run at the end of the session.
