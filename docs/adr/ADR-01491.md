# ADR-01491: `instanceof` a builtin on a union member or an `any`

- **Relations**: Extends ADR-01204, TDD-00230
- **Date**: 2026-10-09

## Context

`x instanceof ReadableStream` with `x: string | ReadableStream<Uint8Array>`
holding a stream was false, and so was `x instanceof Uint8Array` over
`string | Uint8Array`. After `x instanceof Map` over `number | Map<…>`,
`x.size` did not compile. `const s: any = new ReadableStream()` held an
unboxed stream pointer, which `typeof` read as a string.

## Investigation

- A builtin's run-time test only ran for an unconstrained `any`. A
  union's box is dynamic too, but has members, so the test was skipped
  and the static answer (no member is the union itself) was false.
- A union holding a stream matched the headerless-host-object test first
  (its member names the class), whose answer for a stream is false.
- The union's narrowing knew classes and host handles, not builtins. A
  narrowed `Map` read reached the generic member path, which knows only
  objects (`.size` is decided earlier, from the unnarrowed type).
- `new ReadableStream()` (and the other three stream constructors) took
  a declaration shortcut that ignored the declared type. The Map and Set
  shortcuts already step aside for an `any` annotation.

## Decision

- Any boxed value, a union's included, answers `instanceof` a builtin
  from its box. A stream is its box's tag.
- The headerless-host test applies only to non-builtin names.
- `instanceof` narrowing puts a union's builtin members
  (`builtinInstanceofMatch`) on the true branch.
- A narrowed `Map` or `Set` reads `.size` from its header.
- The stream constructors' declaration shortcuts apply only without a
  dynamic annotation.

## Side effects discovered

- The `any`-annotated stream declaration, above.
