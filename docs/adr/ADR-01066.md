# ADR-01066: `Object.values`/`Object.entries`/`for…in` enumerate only present fields

- **Relations**: Extends ADR-01063 (omitted optional field has no key — keys/`in`/inspect/JSON), ADR-00492 (typed values for homogeneous shapes); Implements TDD-00187 (the field-absence residue)
- **Date**: 2026-09-22

## Context

BACKLOG §0 item 5 (first half): after ADR-01063, `Object.keys`, `in`, inspect and JSON.stringify skip an omitted
optional field, but `Object.values`, `Object.entries` and `for…in` still walked the static field list. Reducing
the repro showed something worse: for `interface Q { x: number; y?: number }`, `Object.values(q)` was **invalid
IR** — the optional field's `{ i1, double }` presence aggregate stored into a `double` slot
(`'%t917' defined with type '{ i1, double }' but expected 'double'`), so the program never compiled.

## Investigation

- `homogeneousFieldType` compares `Type.IR`, which is the *bare* T for a nullable scalar, so `number` and
  `number | undefined` looked homogeneous and the array's element type was the first field's; the element store
  then used the raw field load (`StructFieldIR` — the aggregate) against the bare slot.
- `emitObjectPresentFieldNames` (ADR-01063) already had the runtime-count pattern: branch on
  `emitFieldPresent`, append behind the branch, load the count at the end. `Object.values`/`entries` needed the
  same loop with the field's *present-typed* value; `for…in` needed the object evaluated (it only used the type
  before) and the present names.
- The second half of item 5 — `n?: T | null` cannot tell an explicit `null` from an omitted field — is a
  three-state problem (absent / null / present) the two-state storage cannot express: `undefinedableElem` leaves
  an already-nullable type unchanged, so `s?: string | null` *is* `string | null` and an omitted field reads
  `null`. Reads would need a `T | null | undefined` value kind. Left in BACKLOG §0 as its own design item.

## Decision

- `forEachPresentField(objVal, fields, body)` (`emit_objects.go`): runs `body` per *present* field in the given
  order with the runtime output index and the present-typed value (a nullable scalar's payload; an array/pointer
  as is); a constant index and count when no field is optional. Returns the count operand.
- `Object.values` and `Object.entries` build their arrays through it; homogeneity is judged on
  `presentFieldTypes` (an optional `T | undefined` field counts as T), so `{ x: number; y?: number }` gives a
  real `number[]` / `[string, number][]`. `entries` stores an array-typed value through `storeArrayFieldHeader`
  (the tuple slot is a header pointer; the raw aggregate store was wrong for homogeneous array-valued objects).
- `for…in` evaluates the object and uses `emitObjectPresentFieldNames` when the shape has an optional field.

## Implementation notes

`emit_objects.go` (`emitObjectValues`, `emitObjectEntries`, `forEachPresentField`, `presentFieldTypes`,
`presentFieldType`), `emit_stmts.go` (`emitForIn`). `emitFieldPresent` is the one presence predicate (ADR-01063).
A heterogeneous object still stringifies its values (ADR-00492's documented limitation).

## Side effects discovered

- `JSON.stringify` writes a `string | null` field holding `null` as `""` (`{"s":""}`; Node `{"s":null}`) — the
  null pointer takes the string arm untested. BACKLOG §0 item 2b.
- The `?: T | null` third state (above) — BACKLOG §0 item 5.
