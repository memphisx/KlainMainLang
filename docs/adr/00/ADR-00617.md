# ADR-00617: `Channel<T>` parameter types + the load tester split by concern

- **Relations**: `Extends ADR-00616`, `Implements TDD-00143`
- **Date**: 2026-09-01

## Context

Splitting `examples/goroutines/load_test.ts` into modules by concern (to
demonstrate the module system and keep the example legible) required passing
the CSP channels between functions and across module boundaries. That failed:

```
codegen error: an array has no method 'send'
```

A `Channel<number>` **parameter** did not dispatch `.send()`/`.receive()`/
`.close()`/`for..of` — it resolved to a plain array. Channels only worked as
top-level `new Channel` locals (whose type `inferExprType` reads off the
`new` expression), so all channel plumbing had to live in one file — the exact
opposite of a clean module split.

## Investigation

Channel method dispatch keys on `inferExprType(recv).IsChannel` (emit_sync.go,
emit_stmts.go for `for..of`). For a parameter, `inferExprType` returns the
parameter's declared type via `resolveType` (emitter.go). `resolveType` had
cases for `Map`/`Set`/`Promise`/`MessagePort`/streams/etc., but **none for
`Channel`** — so a `Channel<T>` annotation fell through to the default and was
treated as an array, and `.send` looked like an array method.

## Decision

Add a `Channel` case to `resolveType`, mirroring `MessagePort`: resolve the
element type from `ElemType` or the generic `TypeArgs` and return
`ChannelType(elem)`. A `Channel<T>` annotation — as a parameter, a typed field,
a return type — now carries `IsChannel`, so every dispatch site already keyed
on that flag works unchanged.

With that, the example is split into five modules by concern (a working
demonstration of imports; deliberately *separation of concerns*, not the deeper
DDD):

- `loadtest/config.ts` — knobs + the `Res` shape
- `loadtest/service.ts` — the HTTP server under test (`http.listen`, variable
  per-request cost)
- `loadtest/loadgen.ts` — the generator + worker goroutines (channels passed in
  as parameters)
- `loadtest/metrics.ts` — the histogram / percentiles / throughput over a
  `Metrics` value threaded by reference
- `loadtest/dashboard.ts` — the live klain:tui view

`load_test.ts` is now the orchestrator: it owns the channels + `Metrics`, spawns
the server/generator/workers, and runs the `select` collector loop. Each module
is declarations-only, so it also compiles+runs standalone as a no-op under
`make examples` (like `examples/imports/math.ts`).

## Implementation notes

One case added in `codegen/llvm/emitter.go` `resolveType`. The split relies on
three capabilities verified before writing it: `Channel<T>` parameters (this
ADR), object parameters mutated by reference (a `Metrics` struct passed to
`record`/`sampleRps`), and exported functions that call `http.listen` / build
klain:tui nodes.

## Verification

Mac (Apple Silicon M4). New `TestE2EGoroutineChannelParam` (a `Channel<number>`
filled and drained through helper functions) passes. The modular example
compiles (every module standalone too), runs headless (8000 requests, real
latency distribution), and is 0 hangs / 12 runs. Full goroutine / channel /
select / import suites green.
