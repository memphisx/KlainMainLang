# ADR-01411: Timers are Node's lib/timers.js, in TypeScript

- **Relations**: Implements TDD-00245; Supersedes ADR-01394; Extends ADR-01405
- **Date**: 2026-10-05

## Context

`setTimeout`, `setInterval` and `setImmediate` were compiler intrinsics over
an append-only C queue. A handle was the entry's number, `setImmediate` was
a 0 ms timer, and the queue grew by one entry per timer for the life of the
program, with `clearTimeout`, `refresh`, `ref`/`unref` and `hasRef` scanning
all of them. TDD-00245 lays out the replacement.

## Decision

- **The TypeScript side.** `lib/node/internal_timers.ts` ports Node v24's
  `lib/internal/timers.js` and `lib/timers.js`: `Timeout` and `Immediate`,
  lists of timers sharing a duration (Node's `internal/linkedlist`), a
  binary heap of the lists by expiry and id (Node's
  `internal/priority_queue`), `processTimers`/`listOnTimeout` with
  microtasks run between callbacks, `processImmediate`, `unenroll`,
  `[Symbol.toPrimitive]` with the known-by-id map `clearTimeout(number)`
  reads, Node's `[inspect.custom]` (one level), and its overflow, negative
  and NaN warnings. Each timer carries the async context frame it was
  created in (AsyncLocalStorage). Async hooks are left out, as elsewhere.
- **The globals.** `lib/node/kml_timers.ts` is a global module exporting
  `__kml_setTimeout` and the rest (`kml:lower setTimeout`); `node.d.ts`
  declares the six globals with `@lower` instead of `@intrinsic`, and
  `NodeJS.Timeout`/`NodeJS.Immediate` resolve to the two classes. `timers`
  and `timers/promises` call `internal_timers.ts` directly.
- **The native side** (`timerssrc/timers.c`) is Node's `src/timers.cc`: one
  libuv timer armed for the earliest list, whose firing runs
  `processTimers(now)` and re-arms from the expiry it answers (positive:
  referenced, negative: not), with microtasks run after the re-arm as
  Node's callback scope closes; a check handle that runs `processImmediate`
  while immediates are pending; an idle handle started while a referenced
  immediate is pending, so the poll does not block. The per-timer
  `uv_timer_t`s, the queue and its C API are deleted. On Windows the same
  state feeds the select() pass's `__kml_timers_*` hooks and the webview's
  tick pump until TDD-00244 Stage 6.
- **What the compiler needed for it.**
  - A builtin `declare function` takes `@lower` to a global module's
    function (`FunctionDeclaration.Lower`), called directly, through
    `globalThis`, or taken as a value (`const st = setTimeout`); a variable
    initialized by such a call, or holding such a value, takes its type.
  - A top-level `const` holding such a call's class instance is promoted
    to a module global like any other, so a named function reads it.
  - The resolver no longer brings a global module into a file that
    declares the lowered name itself (`internal_timers.ts`'s own
    `setTimeout`), which had made an import cycle.
  - `emitLowered` handles an identifier callee.
- `emit_timers.go`'s intrinsics, their handle-method intrinsics and the
  special cases that typed a timer as a number are deleted.

## Consequences

Measured on the Mac (M4), arming and clearing 200,000 timeouts: 208 ms
against 5.6 s before (the old queue scanned every timer ever created), but a
peak of 235 MB against 54 MB under the default memory mode, and 163 MB
under `-mm=gc`, while the symbol-keyed state (`refed`, `kHasPrimitive`, the
async id, trigger id and context frame) lived in per-object expando
properties. With those as declared fields (ADR-01414) the peak is 103 MB.

A timer now counts from the loop's millisecond clock, as Node's does, so
against `Date.now()` it can run up to 1 ms before its delay; the C queue
it replaces rounded up and never did. `TestE2ELoopTimerNeverEarly` checks
Node's bound. Which of two overdue timers of different durations runs
first also follows Node's lists, not their due times (a duration's list
runs all its due timers together); `TestE2ETaskStructFreedAfterRaceLoser`
no longer depends on which racer wins.

## Verification

- Mac (M4): the timer, loop, tick, microtask and immediate tests;
  `TestE2ETimersNodeObjectsAndPhases` (objects, `+timeout`,
  `clearTimeout(id)`, an immediate before a 0 ms timeout from an I/O
  callback, `hasRef` after firing) and a `Timeout`'s `console.log` output,
  against Node; methods through `any`; AsyncLocalStorage through timers.
- Windows: not built or run.
- Linux (x86-64, Ubuntu 24.04 container), with ADR-01410 to ADR-01415: the
  full test suite, the 394 examples, and Test262 in both lanes (strict 8,497,
  the one file of ADR-01412 fewer; js 10,506; no invalid IR).
