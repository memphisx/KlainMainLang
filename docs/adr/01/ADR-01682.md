# ADR-01682: klain:http in TypeScript over the `native` backend

- **Relations**: Implements TDD-00255
- **Date**: 2026-10-17

## Context

TDD-00255 Stage 1 replaces the code-generated `klain:http` server with a TypeScript module, `lib/node/klain_http.ts`, that runs over a backend chosen at build time. The first backend is `native`: TCP handles on the libuv loop and the HTTP/1 parser natives. Stage 1 also deletes the code-generated path and loop.c's connection table, which closes TDD-00244 Stage 5.

## Investigation

- Node's `http`, `https` and `http2` already run in TypeScript over `net`. Once the old server was deleted, `deadcode -test ./...` showed that the old server was the only user of `netsrc/net.c`, `netsrc/netsock.c`, `runtime_net.go`, about forty `ensure*` declarations and roughly ninety emitter fields.
- llhttp needs no reset between pipelined messages. The parse loop has to run until the parser reports "need more" (event 0), not until the input is used up, because a complete message can end exactly at the buffer's end.
- The first POST-body runs segfaulted. The old code generator still lowered `req.stream()` and `req.body` for any `HttpRequest`, so a TypeScript request object was read as the old struct. This forced deleting the old path before Stage 1 could pass.
- Moving the server onto the event loop exposed six existing bugs, listed below. Each one breaks something a program can do without `klain:http`.

## Decision

**Module layout.**
- `klain_http.ts` owns the surface: `listen`, `close`, `closeAllConnections`, `HttpResponse`, the response encoding (string, `bodyBytes`, `ReadableStream` bodies) and the cluster.
- It imports `./internal_khttp_backend`. The resolver maps that name to `internal_khttp_<lib.HTTPBackend>.ts` through `lib.BackendPath`, and `native` is the only backend until Stage 2.
- The backend exports `serve`, `respond`, `respondStart`/`respondWrite`/`respondEnd`, `abort`, `close`, `closeAll` and an opaque `Exchange`.
- `HttpRequest` is a global class in `kml_http_request.ts` (`// kml:global`). Handlers name it without importing it, as they always have.

**`native` backend** (`internal_khttp_native.ts`).
- The first bytes of a connection decide the protocol. The HTTP/2 connection preface makes it an nghttp2 session over the `h2*` natives that `http2.ts` uses (h2c with prior knowledge). Anything else gets an llhttp parser.
- HTTP/1 handles `Expect: 100-continue`, keep-alive (off for `Connection: close` either way, or once the server closes), pipelining, 400, and 431 for oversized headers.
- A request reaches the handler once its body is complete. A body that reaches the 10 MiB cap first starts the handler in streaming state: `stream()` and the Node `Readable` view read the rest, reading pauses the socket under backpressure, and `bodyBytes()` throws a `RangeError`.
- `req.body` is a class accessor, as TDD-00255 specifies: it throws a `TypeError` once `stream()` has taken the body, and a `RangeError` past the cap. Like any class accessor it is not an own key, so `Object.keys(req)` is `method,path,query,headers`; the old intrinsic object listed `body` too.
- Bytes read while a response is in flight queue behind it only when a request is waiting on that response. The body of the request being answered (one past the cap) goes on to the parser, and draining the queue stops only where a request waits again.
- `HttpResponse.body` stays required, as the old structural handler check required it.

**Blocking `listen`.**
- `listen` calls `__kml_native.runLoop()`, which is `__kml_native_run_loop` in loop.c.
- From top-level code, the module task parks through `__kml_module_park_for_loop` (module.c) and main() runs the loop. This also happens when the task was resumed from inside that loop after a top-level await. The hook now returns whether it parked, and is consulted before the `loop_depth` check. Before, `listen` after a top-level await returned at once, so "server closed" printed before the first request.
- From a callback, `listen` returns at once.

**Cluster (`workers`).** The fork and the shared close flags move to C (`threadpoolsrc/klainkhttp.c`: `khttpFork`, `khttpFlag`, `khttpSetFlag`, `khttpClustered`). On POSIX that is `fork()` after the bind plus a shared anonymous page of flags; on Windows the worker re-spawns through `win32proc.c`. Each process checks the flags on an unref'd 200 ms interval.

**Deleted.**
- `emit_http.go`, `emit_http_upgrade.go`, `runtime_http*.go`, `runtime_net.go`, `runtime_spawn_win.go`, `httpsrvsrc/`, `http2src/http2.c` and `netsrc/`.
- The resolver's `klain:http` marker and the `HttpRequest`/`IncomingMessage`/`ServerResponse` host types.
- The request intrinsics in `emit_call.go` and `emit_exprs_member.go`, and the bare-slot async model for handlers (`emittingHTTPHandler`).
- loop.c's connection table, readiness bitmaps, `sync_sources`, `scan_conns` and fiber parking (1006 lines down to 539), along with the fiber branches in task.c and fetch.c.
- `__kml_loop_fd_forget`.
- klain:sync's thread lock, which was an IR hook, is now a C call in loop.c under `-DKML_SYNC_LOCK`.
- IR text definitions drop from 242 to 144 (`TestIRTextOnlyShrinks`).

## Side effects discovered

Fixed here:
- **Checker: an object relates to `Promise<T>`, and to a union, without its required members.** When the source has no discriminant property, the union rule's `maybe` hedge is now `no` (`sharesDiscriminant`). A union or function target that relates `no` under missing-is-no reports TS2322. An object of the program's own lacking `then`/`catch`/`finally` reports TS2739 against `Promise`/`PromiseLike`.
- **`any` → `Map<K, V> | undefined` read the raw payload.** `isHostHandle` used `IsUndefined()`, which is true for the `T | undefined` representation and not only for the undefined literal. A boxed `Map` was therefore reinterpreted, and a handler returning `{ headers }` crashed the server. An absent `T | undefined` host handle now also boxes as `undefined` instead of `null`.
- **Streams: a reader typed `ReadableStream<any>` over a typed stream read unboxed words** (`__kml_rs_read_any`, a box thunk per stream).
- **`@lowerType` on a type alias** (`ReadableStreamReadResult<T>`), and a `.then` callback whose annotated object parameter has another layout (adapted through `emitBoxedClosureAs`).
- **`-mm=gc` on Linux: a socket stream closing during a collection was freed early.** `us_close` detaches the stream from its TCP handle and waits for `uv_close`. In that window only the libuv handle's `data` points at it, and handles are raw memory the collector does not scan. The collection freed the stream and its read buffer, then `us_on_close` freed blocks already handed out again, and the next allocation crashed in the free lists. Under concurrent connections this killed `net`, `http` and `klain:http` servers alike. Streams, their buffers and libuv's request structs now live in raw memory, like the handles.
- **`indexOf`/`lastIndexOf`/`includes` on an array of arrays** were rejected at compile time. They now compare by identity, as in Node.

Not fixed here: a `declare` class field is a parse error. Supporting it needs per-object property presence, because a declared field that was never assigned is not an own key (BACKLOG).
