# ADR-01753: Empty literals, outer-scope containers and lib classes in the front end

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

The shadow report after ADR-01752 showed 2974 disagreements. Eight of its buckets came from eight separate gaps in the front end:
- An empty array literal nested in another (`m([[]])`) kept the checker's `never` element, where codegen's `inferArrayType` makes it `number[][]`.
- ADR-01752 answered a bare `[]` binding with codegen's type through `decideGlobalType`. That read the empty-container answers of the scope being emitted, so a module-level `var log = []` pushed inside a nested function took the number default from inside that function, where codegen had typed it `string[]`.
- A member read off a class value held boxed (`C.access`, `C` a class expression) went through the dynamic-receiver rule, which excluded local class values but not module ones. The function-value property rule from ADR-01752 needed the same exclusion.
- A lib-declared interface that a lib module implements as a class (`Event`, `NodeJS.Timeout`) had no representation. So `const timer = setInterval(…)` and `const onTick = (e: Event) => …` were answered as no global at all.
- `const aWords = byLetter['a']` (an `Object.groupBy` result codegen holds boxed) read as the checker's `string[] | undefined`: `dynamicInit` did not take an index read.
- `var d = delete o.foo` printed `1 number`: codegen's `inferExprType` had no case for `delete`, so the binding took the `i64` default while every delete path yields a boolean.
- A `find`/`findLast`/`findIndex`/`findLastIndex` callback's element parameter read as `T`. Codegen deliberately passes `T | undefined` over a live array, so that an element the callback removed reads as undefined, as the spec says (`findElemHint`).
- `new.target` in an arrow inside an async function read as the checker's box, where codegen has `undefined` (`emitNewTarget`: no constructor and no function declaration owns it), and so did the result of `async () => new.target`.

## Decision

- An array literal's innermost `never` element is the number codegen gives an empty literal (`neverLeafToNumber`).
- `inferEmptyContainers` records each bare `[]`, `new Map()` or `new Set()` declaration with its own scope's answers (`emptyScopes`). `bareContainerType` answers from those, wherever the query comes from.
- The dynamic-receiver and function-value property rules skip a class value (`classValue`), as they already skipped a local one.
- `reprCtx.of` maps a lib-declared interface without type arguments to the class codegen's `resolveType` gives it (`libInterfaceClass`). That is the global module's class from `globalLinks` for a global interface, and the `internal_timers` class for `NodeJS.Timeout` and `NodeJS.Immediate`.
- `dynamicInit` takes an index read, and a read of a binding it holds boxed is that box.
- `inferExprType` types `delete` as a boolean (`TestE2ECompatJSDeleteResultBinding`).
- A find-kin callback's unannotated first parameter, and its reads, take `T | undefined` when codegen walks the receiver through its live header (`findElemParam`, mirroring `hofLiveHeader`).
- A `new.target` outside a constructor with no owning function declaration (`FnID` 0) is `undefined`. An expression-bodied async arrow's promise value is its body's answer when that is a box, or `undefined` where the checker's is a box.

## Consequences

- The eight buckets' examples are clean, except the enclosing function and its `.then` callback around `async () => new.target`.
- A generic lib class instance (`new AsyncLocalStorage<Ctx>()`, monomorphized per type argument) still has no front-end representation.
- Under `-compat=js`, `C.m.call({})` on a static method that reads `this.#f` does not throw. Codegen rewrites a static method's `this` to its class (`staticThisToClass`), so the receiver passed to `call` is lost. This is a separate codegen bug, recorded in the backlog.
