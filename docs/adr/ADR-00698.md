# ADR-00698: @free block-exit frees + the conservative escape check

- **Date**: 2026-09-04

## Context

TDD-00001 defined the `auto` memory mode; TDD-00173 settles its design. This
ADR records the first shipped stage: the `/** @free */` annotation and the
escape analysis behind it. `-mm=auto` becomes an accepted CLI value at the
same time (see ADR-00700 for what the mode adds beyond the annotations).

## Decision

- **`/** @free */ let x = …`** frees `x` at every exit path of its declaring
  block: fall-through, `return`, `break`, `continue` — labeled forms
  included. Thrown paths deliberately do *not* free (a throw caught by a
  `catch` in the same function resumes with outer bindings live; freeing on
  the unwind would be a use-after-free), so they leak instead.
- **Honored in all three memory modes.** The annotation is a
  compiler-checked, compiler-placed `Memory.free`: under `manual` it frees
  through the identical per-type logic; under `gc` the emitted `free` rides
  the existing shim as a guarded `GC_free` early-release hint (ADR-00351);
  under `auto` it composes with the implicit layer (ADR-00700). Sources
  using the annotation compile identically under every `-mm` value.
- **The escape check** (`codegen/llvm/escape_check.go`, run from
  `EmitProgram` like `checkPurity`) must *prove* the value's top-level
  pointer never leaves the block; a `@free` it cannot prove is a compile
  error naming the escaping use, never a silent no-op. Shallow-free
  semantics make the analysis tractable: only pointer-propagating uses
  reject (returned/thrown/stored/aliased/spread/destructured, passed to a
  non-whitelisted call, captured by a closure, reassigned, shadowed);
  copy-out reads (`x.length`, `x[i]`, member reads, comparisons, string
  coercion, `for..of`, builtin-container receiver methods) are safe. Any
  AST construct the checker does not positively recognize rejects if it
  mentions the identifier.
- **`Memory.free(x)` on an annotated `x` is itself an escape-check
  rejection** with a dedicated diagnostic — the double-free hazard is
  excluded per-variable, which is what lets manual/gc honor the annotation
  without a mode rule.
- **Emit-time gates** (in `maybeRegisterAutoFree`): freeable static type
  only (per `Memory.free`'s existing table, via the new `symbolTypeFreeable`
  predicate); no boxed captures; no class instances (a method could retain
  `this`); no `-compat=js` dynamic objects (no free routine exists); no
  async/generator bodies (lifetime spans suspension); the initializer must
  transfer ownership (a bare alias `let y = x` and an interned string
  literal are rejected — for the annotation the user's ownership claim is
  otherwise accepted, e.g. a call result).
- **Mechanics** mirror `pendingFinallys`: a `pendingFrees` stack of
  obligations tagged with declaring scope depth; block fall-through frees
  and pops its own depth; `return` frees all depths, `break`/`continue`
  free the depths inside their target loop (`breakFreeScope`/
  `continueFreeScope`, in lockstep with the finally-depth stacks; labeled
  targets carry `freeScope` on `namedLabel`). Ordering is finallys first,
  frees after — a `finally` body may still read the value. Exit-path
  emission never pops (each runtime path frees exactly once, the same
  inlining discipline finallys use). The per-type free is `freeSymbol`,
  extracted from `emitMemoryFree` as the single chokepoint every free —
  manual or inserted — goes through (the seam TDD-00163's
  FinalizationRegistry death-signal hook will use).
- Parser side: `VarDeclaration.Free` set from the `@pure`-style bare tag;
  `@free`+`@owned` together and multi-declarator statements are parse
  errors (the doc comment attaches only to the first declarator).

## Consequences

- The whitelists start minimal (`console.log/error/warn/info`, `String`,
  template/`+` coercion; fresh-result container methods for initializers) —
  growing them requires a does-not-retain audit of the emitted runtime, not
  of JS semantics.
- Over-rejection is the designed failure mode: anything unprovable leaks
  exactly as it does today, never corrupts.

## Verification

- `tests/memory_auto_test.go`: block-exit/loop-churn/break-path/
  finally-ordering behavior tests (default mode — annotations are honored
  everywhere) plus rejection tests for return-escape, closure capture, the
  `Memory.free` combo, multi-declarator, and string-literal initializers.
- Existing `Memory.free` suite unchanged through the `freeSymbol`
  extraction. Example: `examples/memory/memory_auto.ts`.
- Verified on the Mac (Apple Silicon); no platform-specific surface.
