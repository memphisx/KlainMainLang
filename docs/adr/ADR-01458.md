# ADR-01458: Parameter dead zone and omitted arguments under -compat=js

- **Relations**: Implements TDD-00230 (P2.1)
- **Date**: 2026-10-07

## Context

The last `emitIdent` shadow rows were Test262's `dflt-params-ref-later`
and `dflt-params-ref-self`: `(x = y, y) => …` failed to compile with
"undefined variable 'y'". Node throws `ReferenceError: Cannot access 'y'
before initialization` when the default runs. Once that compiled, the call
`f()` failed with "missing argument 2 — parameter is required".

The same run showed a program's own class in value position labelled a
global by codegen's `emitIdent`; the binder binds it to its declaration.

## Investigation

- Codegen binds parameters in order, so an earlier default reads a later
  parameter before it exists; the binder resolves the name to the
  parameter (declared `VarLike`, its node the function).
- A closure call fills an omitted argument with `undefined` except after a
  defaulted parameter, where an arity check rejects it. TypeScript rejects
  that call (TS2554), which the checker reports in the strict lane; in
  JavaScript any argument may be omitted.

## Decision

- An identifier codegen has not bound that the binder resolves to a
  parameter throws the dead-zone `ReferenceError` (the same error the
  closure dead-zone path builds), and the rest of its expression is dead.
- Under `-compat=js` an omitted argument is always `undefined`.
- A class in value position reports as declared to the shadow comparison.

## Verification

- `TestE2EParamDeadZoneAndOmittedArgs` (against Node, `-compat=js`).
- The probes' `emitIdent` rows are gone.
