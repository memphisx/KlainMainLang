# ADR-01833: An array conditional is its branches' storage on the checker's side

- **Relations**: `Implements TDD-00230` (P3.3: inferExprType's kinds switch to the checker)
- **Date**: 2026-10-20

## Context

- The full shadow report's third bucket (2,953 rows) came from one line of the JSON serializer: `this.props !== undefined ? this.props : Object.keys(value)`.
- A read is typed by its storage, not the type a test narrows it to. So the narrowed field read is still an absent-capable array, and `emitConditionalArray`'s slot holds whichever branch it picked. The checker's side gave the narrowed type of the whole conditional, without the absence.

## Decision

- When both branches are arrays of one representation that differ only in absence, the oracle answers with `ternaryArrayType` over their storage types, as `conditionalArrayType` does. An empty literal consequent defers to the alternate.

## Consequences

- The serializer line and its class repro have no disagreements left. The narrowed member reads themselves still show rows where the old side has no answer.
- Verified on Apple Silicon (48 ternary, conditional and narrowing E2E tests), and with the gate on Linux x86-64 (DeskMini).
