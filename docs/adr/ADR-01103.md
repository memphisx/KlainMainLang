# ADR-01103: The parser knows no builtin constructors; sema decides which `new` is a builtin

- **Relations**: `Implements TDD-00230` (Phase 1, P1.6); `Extends ADR-01102`
- **Date**: 2026-09-23

## Context

`parseNew` dispatched on the constructor's name as text, before any scope
existed. `new Map`, `new Event`, `new Worker` and 38 others became dedicated node
kinds whatever `Map` referred to, so a user's own `class Event` compiled to the
builtin: `new Event(5).n` failed with `no field 'n'`, where Node prints `5`.

The parser also collected worker and dynamic-import paths as it went. The
resolver had to rebuild four of the special kinds itself for aliased imports
(`import { URL as U }`), and carried a rename case for every special kind.

[TDD-00230](../tdd/TDD-00230.md) P1.6 moves that semantic work out of the parser.

## Investigation

- **What the special parsers read.** The 43 special body parsers (about 1,200
  lines of `parser/parser_literals.go`) read only type arguments and ordinary
  argument expressions. Each one's rules (argument count, a string-literal path,
  an options object's allowed keys) can be applied to a generic
  `NewExpression{ClassName, TypeArgs, Args}` after parsing.
- **Existing scope tracking.** The resolver's renamer tracks local scopes, and
  already rebuilt special nodes from a generic `new` for aliased imports
  (`buildReexportConstructor`).
- **The tests bypass the resolver.** They call `parser.Parse` and then
  `EmitProgram` directly. `EmitProgram` is called from 46 sites (the driver, the
  tests, the conformance runner), and it's the one entry point they all share.
- **Latent bugs the special parsers hid:**
  - `new Array(a, b)` parsed its "size" with `parseExpression`, so the comma
    became the sequence operator: `new Array(1, 2, 3)` was `new Array(3)`, where
    Node gives `[1, 2, 3]`.
  - `new X` without parentheses was a parse error.
  - The renamer's `NewChannelExpression` case never rewrote the channel's type
    argument, so an imported element type (`new Channel<Result>()` in
    `apps/loadtest`) was never mapped to its module-qualified name and fell back
    to `i64`.
  - The readability walkers (TDZ and definite assignment) never entered a
    generic `new`'s arguments, and saw only `new Array`'s size.

## Decision

- **The parser emits only generic `NewExpression`s.** `parseNew` keeps the
  qualifier handling (`new stream.Readable()` keeps the final name). An argument
  list is optional (`new Date`). The 43 special body parsers and the parser's
  typed-array table are deleted.
- **A new `sema` package** runs its `Prepare(prog)` at the top of
  `EmitProgram`, so every compile path goes through it once. It is idempotent.
  - **A scope-aware walk** over the generated traversal (`RewriteChildren`, added
    to the P1.4 generator) builds the special node for a `new X(…)` only where no
    user binding named `X` is in scope.
  - **What counts as a user binding:** a variable, function, class, enum,
    parameter (including destructured), loop or catch binding, or an import from
    a user module. An import from a builtin module binds the builtin itself.
  - **Scopes:** functions, function expressions and arrows are scopes. A
    block-scoped declaration counts for its whole function, which is
    conservative: it is never taken for the builtin anywhere in that function.
  - **The builders.** Each former special parser's rules move into a builder in
    `sema/builtin_new.go`, with its messages. Argument counts the grammar used to
    enforce (as a bare `expected )`) now get explicit messages.
  - **Faithful forms added:** `new Array(a, b, …)` builds the array of those
    elements, and `new RegExp()` is the empty pattern `(?:)`.
- **Module resolution stays in the resolver.**
  - `workerPaths` and `dynamicImports` find the dependency edges in the parsed
    file, where the parser used to accumulate them. A file that declares its own
    top-level `Worker` has no worker edges.
  - The renamer resolves a builtin `new Worker('./w.ts')` path into
    `Program.ResolvedModules`, a table from the specifier literal to the
    canonical file. `sema`'s Worker builder reads that table.
  - An aliased builtin import is renamed to its canonical name, and `sema`
    builds it.
  - The renamer's 30 special-kind cases are deleted. Its generic case rewrites
    every constructor's arguments and type arguments uniformly, which is the fix
    for the channel type argument.
- **`Program.DynamicImportPaths` is deleted** (only the parser used it).
  `WorkerPaths` and `DynamicImportNodes` are now filled by the resolver.
- **The readability walkers** check every generic `new`'s arguments.
- **Deferred to phase 2, and recorded in the TDD:**
  - Namespace desugaring: a namespace is a container symbol for the binder, so a
    transitional pass would be thrown away.
  - `resolver/reserved_names.go`'s builtin list: type annotations still resolve
    by name in codegen, so a user `class Map` would be read as the builtin in
    `x: Map<…>`.

## Side effects discovered

- **A missed edit, caught before landing.** One edit to `resolver.go` silently
  failed to apply: its pattern expected `return nil, fmt.Errorf` where the code
  had `return fmt.Errorf`. It left `WorkerPaths` empty, and the equivalence run
  caught it: all seven Worker examples reported "worker module … was not
  registered". Edits are now asserted to match.
- **`apps/loadtest`'s channels** now carry their imported element type as a
  pointer (the channel type-argument fix above). They had been passed as `i64`,
  which worked only because the two are the same width.

## Verification

All on macOS arm64 (M4):

- `go test ./ast ./parser ./resolver ./sema`: the `sema` tests cover builtin
  resolution, shadowing by a user class, a parameter, a local class, an arrow
  parameter and a user-module import, the builtin's return outside the shadowing
  scope, and the builders' argument checks.
- `tests/sema_builtins_test.go` matches Node 26.10.0: a user `class Event`
  prints `5`; `new RegExp()`, `new Date`, `new Array(1, 2, 3)` and
  `new Map<string, Array<number>>()` behave as in Node.
- **Equivalence corpus** (24,125 files, compared with the P1.4 build):
  - No file changed from compiling to failing. 787 files compile on both
    builds.
  - 68 failing files changed their error message, almost all because a `new`
    form the old parser rejected now parses and fails later, in codegen.
  - The one IR change among compiling files is in `apps/loadtest/main.ts`:
    the `select` handler of a `Channel<Result>` was called with an `i64`
    where the closure takes a `ptr`. The sema-built channel node carries its
    element type, so the call now converts the received slot to `ptr`. It is
    a signature-mismatch fix, with identical behaviour on arm64.
- `make examples`: 358 passed, 0 failed.
- `make test-par`: passes apart from the four known macOS `-mm=gc`
  thread-local-root failures in `tests/task_reclaim_gc_tls_test.go`.
