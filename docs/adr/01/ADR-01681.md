# ADR-01681: net, dgram, pipes, IPC and terminals as libuv handles; Windows signals on uv_signal_t

- **Relations**: Implements TDD-00244
- **Date**: 2026-10-17

## Context

TDD-00244's "Sources onto handles" table maps the `kml_tcp` handle table (net, dgram) to `uv_tcp_t`, `uv_udp_t` and `uv_pipe_t`. On POSIX, `threadpoolsrc/klainpool.c` still watched each raw descriptor with a `uv_poll_t`, and its own state machines did the accept, connect, `read`/`write`, `recvmsg`/`sendmsg` (IPC descriptors) and `recvfrom`/`sendto` work. `__kml_native_udp_send` waited out a full send buffer with a blocking `poll()` inside the runtime. On Windows, `process.on(signal)` went through the `signal()` shim and a per-pass `__kml_signal_dispatch`.

## Investigation

- On Windows the table already drove pipes and consoles as libuv streams (`kml_ustream`: buffered reads, one write request at a time, accepted connections queued). The dispatch reads that stream state as readiness, so a `uv_tcp_t`, `uv_pipe_t` or `uv_tty_t` fits the same struct on every host.
- `uv_tcp_open` and `uv_pipe_open` adopt a socket the runtime made itself, so the options set before `bind` (dual-stack `IPV6_V6ONLY` off, a cluster worker's `SO_REUSEPORT`) survive. `uv_listen` over an already listening socket only calls `listen()` again.
- `uv_udp_open` sets `SO_REUSEADDR` on the socket. A second bind to the same port then succeeded silently, and `TestE2EDgramUdp6AndOptions` hung waiting for `EADDRINUSE`. Node creates the socket with `uv_udp_init_ex` and binds with `uv_udp_bind`.
- libuv fixes a pipe's IPC mode at `uv_pipe_init`, but a fork channel learns it is IPC later (`ipcOpen`). A descriptor sent with `uv_write2` needs a write request, so the first write cannot be a `uv_try_write`. When that request was queued but never started, nothing ever reported the handle writable, and `TestE2EChildProcessForkSendHandle` hung.
- Every Stage 5 leftover the audit listed belongs to `klain:http`'s `http.listen`: the `sync_sources` connection table, the readiness bitmaps, `scan_conns`, accept IR, and `http2.c`'s fiber `read`/`write`. Node's `http`, `https` and `http2` are TypeScript over `net`. They now run on `uv_tcp_t`, so Stage 5 closes with `klain:http`'s TypeScript rewrite (TDD-00230 P3.2).

## Decision

POSIX:
- A TCP socket (listening, connecting, accepted, or opened from a descriptor) is a `uv_tcp_t`: `uv_listen` with `us_on_connection`, `uv_tcp_connect`, `uv_read_start`, `uv_write`/`uv_try_write`, `uv_shutdown`.
- A child's stdio pipe, a FIFO and a Unix-domain socket are a `uv_pipe_t`. A client connects with `uv_pipe_connect`.
- A fork channel is a `uv_pipe_t` with IPC set. `ipcOpen` moves a plain pipe's descriptor (a duplicate) onto an IPC pipe and keeps what was read so far. A sent descriptor goes with `uv_write2`, and its request starts at once. Received handles are accepted (`uv_pipe_pending_type`, `uv_accept`) and kept as duplicated descriptors for `ipcTakeFd`.
- A terminal opened as a stream is a `uv_tty_t`.
- A datagram socket is a `uv_udp_t` made by `uv_udp_init_ex`, bound with `uv_udp_bind`, connected with `uv_udp_connect`, read with `uv_udp_recv_start` into a per-handle queue, and sent with `uv_udp_try_send`, else a queued `uv_udp_send`. The blocking `poll()` is gone.
- A descriptor libuv has no handle for (a regular file) stays a `uv_poll_t`, as before.

Windows:
- `process.on(signal)` is a `uv_signal_t`, as on POSIX. `__kml_signal_dispatch` and the per-pass call are deleted.
- `kill()` of the current process runs libuv's `uv__signal_dispatch`, with the shim's queue as the fallback for a C-level handler.
- A number above SIGWINCH is `EINVAL`, as libuv reports it.
- Windows sockets stay shim descriptors watched by libuv's `uv_poll_init_socket`. Each one is an entry in `win32io.c`'s descriptor table, which the descriptor-level calls (`setsockopt`, `getsockname`, the IPC socket duplication) read, so moving them to `uv_tcp_t` means taking them out of that table first.

Comments that still described the select bridge (`klainpool.c`, `ipcc.c`, `task.c`, `runtime_process.go`, `runtime_fswatch.go`) now describe the code.

## Verification

- macOS (Apple Silicon): `-run 'TestE2ENet|TestE2ETLS|TestE2ETls|TestE2EHTTPAgent|TestE2EHTTPClient|TestE2ECluster|TestE2EIPC|TestE2EDgram'`; `-run Dgram`; `-run 'Signal|SIGINT|Sigint|FsWatch|Watch'`; repros for the `EADDRINUSE` and fork send-handle hangs.
- Linux (Node304, Docker Ubuntu 24.04): the child-process, spawn, IPC, cluster, net, pipe, stdin, TUI, TTY, readline, TLS, dgram, HTTP and Worker suites.
- Windows: compile-checked only, by CI.
