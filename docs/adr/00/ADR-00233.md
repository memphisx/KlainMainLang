# ADR-00233: JS-faithful float-to-string (shortest round-trip)

- **Relations**: `Implements TDD-00080`; `Supersedes ADR-00166` (the `%g` float-print behavior)
- **Date**: 2026-08-19

## Context

Floats printed through bare `%g` (C's 6-significant-digit default), so
`console.log(1.1 + 2.2)` printed `3.3` instead of `3.3000000000000003`
([ADR-00166](ADR-00166.md)). This was the only remaining single-caveat row in the
Type System primitives table, so fixing it closes a real correctness bug and
earns a Strict row.

## Decision

An embedded C helper `__kml_dtoa(char *buf, double v)` (`dtoasrc/dtoa.c`, libc
only) implements ECMAScript `Number::toString`:

1. Special-case `NaN`/`±Infinity`/`0` (both `+0` and `-0` → `"0"`, matching
   `String(-0)`); emit the sign, then work on `|v|`.
2. Find the shortest significant-digit count `d` (1..17) whose `%.*e` formatting
   `strtod`s back to exactly `v` — `%e` exposes digits + decimal exponent
   uniformly across magnitudes, and the round-trip check is a trivial, provably
   correct termination.
3. Reassemble from the `d` digits and the exponent per the spec's fixed/exponential
   rules (fixed for `-6 < n ≤ 21`, else exponential with a JS-style unpadded,
   always-signed exponent).

Compiled and linked only when a program prints a float (`UsesFloatFmt` flag +
`ensureDtoa` decl + a `main.go` compile step + a test-harness `appendDtoa`),
mirroring the bigint/JSON embedded-C helpers. It replaces `sprintf(buf, "%g", v)`
at the scalar (`emitValueToString`) and dynamic (`emit_dynamic`) print sites; the
`console.log` and template-literal paths now route floats through
`emitValueToString` (the console path previously printed floats via
`Type.PrintfFmt`'s raw `%g`), so all float output shares the one formatter.

This supersedes ADR-00166's `%g` behavior.

## Implementation notes

The 32-byte scratch buffer the print sites already `malloc` is sufficient (a
double's longest shortest-form string is well under 32). The shortest-digit
retry uses `%.*e`, not `%.*g`, precisely to avoid `%g`'s precision-coupled
fixed/exponential switch (which turns `100` into `1e+02` at low precision).

## Side effects discovered

- **`console.log(-0)` prints `0`, not Node's `-0`.** This compiler's `console.log`
  routes floats through `ToString` (the language behavior), and `String(-0)` /
  `${-0}` are `"0"` in JS — which is matched exactly. Node's `console.log` shows
  `-0` only because it uses `util.inspect`, a console-display quirk rather than a
  float-formatting one; recorded as a Note on the row, not a caveat.
- **float32** values are formatted against their widened `double`, so a value that
  originated as 32-bit may print more digits than a `Float32`-aware toString —
  JS has no float32 scalar to diverge from, so this is a representation note.
- Scientific-notation *literals* in source (`1e21`) are still not lexed — an
  unrelated lexer gap, out of scope here.

## Verification

- `tests/float_format_test.go`: `1.1+2.2`→`3.3000000000000003`, `0.1`,
  `123456789.123`, integer-valued floats, `NaN`/`Infinity`/`-Infinity`/negatives,
  exponential past the thresholds, and template-literal interpolation. All pass.
- `examples/basics/float-formatting.ts` added (incl. `0.1+0.2`→`0.30000000000000004`)
  and runs correctly. Emitted IR verified with `clang`.
- Full float/number/math/console/template test subset green (no prior expectation
  asserted the old truncated output); full `tests/` suite run for the whole
  change. Apple Silicon (macOS).
