# ADR-01223: Regex literals are RegExp to the checker

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-09-29

## Context

Porting lib/url.js (ADR-01221) raised `'proto' is possibly 'null'` on

```ts
let proto: string | null = null;
if (protoMatch) { proto = protoMatch[0]; proto.toLowerCase(); }
```

which tsc accepts.

## Investigation

- The checker left `/re/flags` (and `new RegExp(…)`, the same AST node)
  untyped, so `protoMatch` and `protoMatch[0]` were unanswered.
- An assignment of an unanswered value narrowed the variable to its
  declared type, `string | null`: a guess, and a wrong one here.
- `RegExpExecArray extends Array<string>`, but `lib/es.d.ts`'s `Array<T>`
  had no `[n: number]: T`, so indexing an interface that extends it was
  unanswered too.

## Decision

- `NewRegExpExpression` has the declared `RegExp` interface's type.
- An assignment whose value the checker cannot type leaves the variable
  unanswered at that point when its declared type is a union. Which
  members the value keeps is unknown, so no check guesses.
- `Array<T>` declares `[n: number]: T`, as TypeScript's lib does.

## Implementation notes

`checker/checker.go`, `checker/narrow.go`, `lib/es.d.ts`.

## Verification

Mac (Apple Silicon), against tsc and Node v24.19:
`TestE2ECheckerRegExpLiteralTyped`; the full test suite.
