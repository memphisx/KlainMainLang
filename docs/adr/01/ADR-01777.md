# ADR-01777: Class values have a prototype, and redeclared class names hold each class

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- `var C = class {...}` at top level is rewritten into a class declaration named C. Two such declarations of one name (legal for `var`) declared two classes named C, so the IR redefined each method. The compiler panicked on generator methods.
- A class held as a value, such as one returned from a function, read `.prototype` as undefined. The constructor-reference get row listed only `length` and the statics.

## Decision

- `rewriteTopLevelClassExpressions` rewrites only a name declared once at top level. A redeclared name's classes stay class-expression values.
- Each program class's get row also answers `prototype` with the class's prototype object (`emitClassProto`). A library class's prototype stays in its own unit, so the program unit stays within its size budget.
- `emitClassProto` leaves out abstract methods. They have no function, and JavaScript gives them no property.

## Consequences

- `TestE2EJSFileClassValuesAndRedeclaredClasses` covers both.
