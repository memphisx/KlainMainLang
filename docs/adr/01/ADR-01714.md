# ADR-01714: Intersections with a host member, and `Object.assign` grafting new keys

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-18

## Context

An intersection lowered to one struct holding its members' merged fields (TDD-00078). Two consequences diverged from Node:

- **Host members.** For `NodeJS.ErrnoException & { port?: number }` the merge failed ("conflicting types"). Even where it succeeded, a struct can't hold an Error value, so property reads were wrong.
- **`Object.assign`.** It was a compile error when a source had a property the target's type lacked. TypeScript accepts it and types the result as `T & U`, and Node copies the property onto the target.

## Decision

- An intersection with an Error, class or other host member resolves to `any`. Its value is that object, with the other members' properties as its own, and every access reads it dynamically.
- `Object.assign` with a source property the target's type lacks goes through the dynamic path: the property is written onto the target, and the result is `any`.

## Verification

macOS (Apple Silicon):
- `TestE2ENetConnectFailureEmitsError` (now in its intersection form), `TestE2EObjectAssignUnknownField`, and the `Assign`/`Intersection` tests pass;
- Error intersections and grafted plain-object keys match Node.
