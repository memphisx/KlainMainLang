# ADR-00353: Generic type-parameter constraints (`<T extends X>`)

- **Relations**: Implements [TDD-00113](../tdd/TDD-00113.md); builds on [ADR-00352](ADR-00352.md) (object type arguments)
- **Date**: 2026-08-25

## Context

`<T extends X>` was a hard parse error, so any TypeScript using constrained
generics (a very common idiom) failed to compile. Its main use — constraining `T`
to an object shape — is meaningful now that object type arguments exist
([ADR-00352](ADR-00352.md)).

## Decision

Because generics monomorphize, member access on a constrained `T` already
resolves per-instantiation (the body is emitted against the concrete type), so a
constraint's job here is narrower than in a classic checker: **accept the
syntax** and **enforce the bound**.

- Parser: `parseTypeParamList` parses a per-parameter `extends <TypeAnnotation>`
  and returns the constraints alongside the names; stored on the four generic
  declaration nodes as `TypeParamConstraints []*TypeAnnotation` (positionally
  aligned with `TypeParams`, nil = unconstrained).
- Resolver: the rename pass rewrites each constraint annotation with the type
  parameters bound in scope (so a constraint naming a type is per-file renamed,
  while a reference to a sibling parameter stays bound).
- Codegen: `checkTypeParamConstraints` runs at each instantiation site (function
  call after inference; class `new C<…>()`), testing each concrete argument
  against its constraint with `matchExtends` — the same structural-subtype test
  conditional types use, with width subtyping so an object with extra fields
  satisfies a smaller constraint shape. A violation is a clean compile error
  naming the parameter and constraint (demangled via `inspectClassName`).

## Scope

- **In:** enforced constraints on generic functions and generic classes;
  constraint may name an interface/class/object type or a scalar; member access
  on a constrained `T` (via monomorphization).
- **Out / unchanged:** constraints on type aliases are parsed and stored but not
  enforced (aliases expand, they don't instantiate); no default type parameters
  (`<T = X>`).

## Verification

- `tests/generics_test.go`: constraint satisfied (function + class); constraint
  violated (function + class) → clean compile error; plus the object-type-argument
  tests from [ADR-00352](ADR-00352.md).
- `examples/generics/generics.ts` (constraint + object-arg section); `make
  examples`; `go test ./...`; `make conformance`.
- Machine: verified on Mac (arm64).
