# ADR-01997: Array.from calls mapFn at each step of the iteration

- **Date**: 2026-11-21

## Context

Test262 `built-ins/Array/from/iter-map-fn-err.js` passes `Array.from` an
iterator that never finishes and a `mapFn` that throws. Node calls `mapFn`
on the first value, the throw closes the iterator, and the call ends. Here
the program ran until the 300 s timeout and grew past 1.2 GB, so the Mac's
per-program memory cap killed it.

## Investigation

- `Array.from(items, mapFn)` was rewritten as
  `Array.from(items).map(mapFn)` ([ADR-00491](../00/ADR-00491.md)). For an array, or an array-like
  object, that gives the same result. For the iteration protocol it doesn't:
  every value is collected before `mapFn` runs once, so an endless iterator
  never stops, and the iterator closes at the wrong time.
- HEAD has the same failure; this is not a recent regression.

## Decision

When the source is walked at run time (a value held in `any`, an object
with `[Symbol.iterator]`, a sync generator), `Array.from(items, mapFn)`
runs `@__kml_any_iter_collect_map(v, f)`. It is the `for…of`-over-`any`
lowering with `r.push(f(x, i++))` as its body, so `mapFn` runs between
`next()` calls, and a throw leaves the loop and closes the iterator. An
array or array-like source is read first and mapped after, since `mapFn`
can't cut that read short. The result is unboxed to `mapFn`'s return type,
as with `.map`.

## Implementation notes

- codegen/llvm/emit_iter_collect.go: `emitAnyIterCollectMap`,
  `emitAnyArrayFromMapped`.
- codegen/llvm/emit_arrays_iter.go: the two-argument `Array.from` route;
  an `any` mapFn's defined branch also goes through it.
- codegen/llvm/emitter.go, libsplit.go: the routine's registration.

## Verification

- Linux x86 (Node304): `TestE2EArrayFromMapFnPerStep` matches Node (js
  lane) for these cases: the throw from `mapFn`, the iterator closing, the
  order of `next` and map calls, generators, array-likes and arrays. The
  `From|Iter|Spread|Generator` E2E tests pass.
- Test262 `built-ins/Array/from`: 29 → 32 of 47 on the js lane; the strict
  lane is unchanged at 11.
