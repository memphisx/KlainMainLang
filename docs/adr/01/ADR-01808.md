# ADR-01808: calls through a well-known symbol key are typed from the member

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- `o[Symbol.iterator]()` on a plain object was typed as a number:
  - The checker's `accessKey` did not map `Symbol.iterator` to the `@@iterator` name the member declared as `[Symbol.iterator]()` carries. The element access had no answer. The strict lane missed tsc's TS2322 for `const n: number = o[Symbol.iterator]()` when the method returns a string, then failed in codegen.
  - A variable declaration initialized by a call through any computed key fell to the declaration switch's i64 default. `var f = s[Symbol.iterator]()` held a string as a number.
- ADR-01801's boxed read off a primitive receiver also caught generated iterator-closing code (`it.return`, `it.throw` over a raw pointer, which counts as a string). Array destructuring of a user iterable then recursed until the stack overflowed.

## Decision

- `accessKey` maps a `Symbol.<name>` index to `@@<name>` when `Symbol` is the library global.
- The variable-declaration call case takes the inferred type for a call whose callee is an index expression. In the js lane, inference answers `any` for a call through a well-known symbol key on a plain object.
- The primitive-receiver boxing applies only to the program's own reads, those with a source position. An integer receiver counts only as a number literal, since i64 is also the type inferred for a value of unknown kind.

## Consequences

- `TestE2EJSFileComputedSymbolMethodCall` covers both lanes: a user iterable's iterator, destructuring it as a binding and as a parameter, and a string-returning symbol method. `TestTypeOf` has the checker case. `TestE2EJSFileGeneratorDestructuredParams` passes again.
