# ADR-02029: `with` and `fill` storing a value the elements cannot hold

- **Date**: 2026-11-22

## Context

- In JavaScript, `[1, 2].with(0)` and `a.fill()` store undefined, and
  `.with(1, undefined)` or `.with(0, "s")` store a value a `number[]`
  cannot hold. Here the copy (or the filled binding) kept the receiver's
  `number[]` type. The element printed as undefined but read as a number:
  `a[0] === undefined` was false and `typeof` said "number".

## Decision

- `arrayWithType` types the copy as `any[]` whenever `withWidens` holds
  (JavaScript): the value is omitted, or it is of another representation
  than the elements. The emit takes the same test, so the dynamic copy and
  its static type agree.
- `storesOtherKind`, which widens a JavaScript array binding to `any[]`,
  counts a `fill` of another representation, an omitted value included.

## Consequences

- Tests: `TestE2EArrayWithFillUndefinedJS`.
