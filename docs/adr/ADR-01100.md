# ADR-01100: The parser drives an on-demand scanner

- **Relations**: `Implements TDD-00230` (Phase 1, P1.1)
- **Date**: 2026-09-23

## Context

`lexer.Tokenize` turned the whole file into tokens before parsing began, so a
token's reading was fixed before its grammatical position was known:

- **`>>` inside nested generics.** `Array<Promise<T>>` lexed as one `RSHIFT`,
  and `expectGT` rewrote the token array in place to split it (ADR-00073).
- **Regex vs division.** A `/` was a regex or a division depending only on the
  previous token, so `{}\n/x/g`, and a regex after a class or function body, was
  misread as division.
- **Automatic semicolon insertion was impossible.** A token carried only its
  line and column, not whether a line break preceded it.
- **No byte offsets,** and JSDoc comments were tokens of their own that every
  look-ahead had to skip.

[TDD-00230](../tdd/TDD-00230.md) adopts typescript-go's pattern: the scanner
always produces the context-free reading, and the parser asks for a different
one where its grammar knows better.

## Investigation

- **The parser's surface was small.** Tokens were reached only through `peek`,
  `advance`, `expect`, `match`, `peekNth` (about 740 uses) and four direct
  position restores. Only `parser.go` touched the token array.
- **Few sites consume combined `>` tokens:** assignment operators, relational
  operators and shift operators (`parser_exprs.go`). Division has two sites:
  the multiplicative operators and `/=`. Regex literals appear only in
  `parsePrimary`.
- **The lexer already scanned one token at a time** through `NextToken()`;
  `Tokenize` was only a loop over it.
- **typescript-go** (`internal/scanner/scanner.go`): `Scan()`,
  `Mark()`/`Rewind()` of a copyable `ScannerState`, and `ReScanGreaterThanToken`
  / `ReScanSlashToken` called by the parser; `TokenFlagsPrecedingLineBreak`.

## Decision

**Scanner (`lexer`)**

- `Scan(mode)` returns one token. A scanning error comes back as an `ILLEGAL`
  token whose text is the error; the scanner no longer returns errors.
- `Mark()`/`Rewind(State)` save and restore the scanner. `State` includes a
  copy of the template brace stack, so saving costs one struct copy.
- **Modes.** `ScanDefault` always gives a single `>`, and reads `/` by the
  previous token as before. `ScanGlueGreater` combines `>>`, `>>>`, `>=`, `>>=`
  and `>>>=`. `ScanRegex` and `ScanNoRegex` force the two readings of `/`.
- **`Token` gains:**
  - `Pos`/`End`: byte offsets, from a rune-to-byte table built once per file.
  - `Flags` with `PrecedingLineBreak`, which is set for LF, CR, U+2028 and
    U+2029, including inside a block comment before the token.
  - `Doc`: the last `/** … */` comment before the token.
- The regex-flags field is renamed `RegexFlags`.
- The scanner keeps every JSDoc comment, keyed by byte offset, in `Docs`.
- **Removed:** `lexer.Tokenize` and the `JSDOC` token type.

**Parser**

- **Lazy token list.** `tokens` fills as the parser reads. `states[i]` holds the
  scanner state just before token `i`. `at(i)` scans on demand. Past EOF, or
  past an `ILLEGAL` token, it returns EOF, so every parser loop terminates.
- **`rescanAt(i, mode)`** re-reads token `i` under a different mode and drops
  everything scanned after it.
- **`rewind(i)`** backtracks. It also drops any token from `i` onwards that a
  speculative parse had re-read, so a failed generic-call attempt leaves no
  glued `>` behind.
- **Where the parser re-reads.**
  - `peekOperator()`, at the assignment, relational, shift and multiplicative
    operator positions, glues a `>` and turns a regex back into division.
  - `peekPrimary()`, in `parsePrimary`, turns a `/` or `/=` into a regex.
- `expectGT` becomes a plain `expect(GT)`, and the in-place split is gone.
- **JSDoc.** `peek()` loads a token's `Doc` into `pendingDoc` once per token
  index. `collectTypedefs` reads the scanner's `Docs` after the parse and
  prepends the synthesized aliases, in source order.
- **Scanning errors.** `ParseProgram` reports a scanning error that the parse
  ran into, and also one that the parse got past. A syntax error that comes
  earlier in the source is reported first.

## Implementation notes

- **Changed files:** `lexer/lexer.go` and `lexer/token.go` (the scanner);
  `parser/parser.go` (the token layer); `parser/parser_exprs.go` (operator
  positions and the generic-call rewind); `parser/parser_literals.go`
  (`parsePrimary`); `parser/parser_types.go` (the curried-function-type
  rewind); `parser/jsdoc_types.go` (the JSDoc sub-parser now takes source).
- **`parser.New` takes source** instead of tokens. It was only called inside
  the parser package.
- **Tests:** the lexer tests scan through a helper that re-reads a `>` with
  gluing, as the parser does in operator position. New tests cover single vs
  glued `>`, regex vs division by mode, line breaks (LF, CR LF, U+2028, inside a
  comment), byte offsets over a multi-byte character, and JSDoc attachment. The
  fuzz target now checks that scanning ends at EOF or `ILLEGAL`.

## Side effects discovered

- **The first equivalence run hung on 96 Test262 files.** `at()` kept returning
  the `ILLEGAL` token, and a parser loop waiting for `}` spun on it. Returning
  EOF past an `ILLEGAL` token fixed it. `TestParseScanErrorIsReportedAndTerminates`
  covers it.

## Verification

All on macOS arm64 (M4):

- **Equivalence corpus:** 24,124 files, compiled to IR (`-emit-llvm`) with the
  previous binary and with this one, comparing a hash of exit status, IR and
  diagnostics per file. The corpus is every `.ts`/`.js` under `examples/`,
  `tools/` and `apps/`, plus Test262's `test/language`.
  - All 363 examples that compile produce byte-identical IR.
  - No file that compiled before fails now.
  - 8 files that failed before compile now: a regex after a block, class body
    or function body (`statementList/*-regexp-literal*.js`).
  - The rest of the changes are between two errors. A syntax error before the
    unreadable character is now reported first; these are all negative tests.
- `go test ./lexer ./parser`, `make examples` (358/0) and `make test-par` all
  pass. The only `make test-par` failures are the four known macOS `-mm=gc` TLS
  tests (BACKLOG §0 item 8).
- `tests/asi_test.go`: `TestE2EParserDecidesRegexVersusDivision`,
  `TestE2EGreaterThanGluedOnlyAsOperator`,
  `TestParseScanErrorIsReportedAndTerminates`.
