## Context

The Node `http` **client** (`http.request(options, cb)` / `http.get(url, cb)`)
is the **single largest real blocker** in the Node `test/parallel` oracle — 117
files fail on `http.get` (82) / `http.request` (44) (surfaced once the misleading
"only simple function calls" catch-all was split, ADR-00403). It is also this
project's **#1 stated priority** (REST client + server) — a gap that should never
have persisted this long. This compiler already has the WHATWG `fetch` client
(libcurl) and the Node `http.createServer` **server** (TDD-00131); the missing
piece is the Node-shaped callback/event client.

## Design

### Build on the existing `fetch` libcurl primitive, not raw sockets

`__kml_fetch_async` (runtime_fetch.go) already performs a full HTTP/1.1 request
over libcurl's multi-interface, folded into the same `select()` event loop, with
status + streamed body. The Node client is a **Node-shaped event API over that
primitive** — reuse, not a second HTTP stack. A program using `http.get` links
libcurl exactly as a `fetch` program does (the established conditional-link
convention).

### Surface

- **`http.get(url | options, cb?)`** = `http.request(...)` with method `GET` and
  an automatic `req.end()`. `url` is a string; `options` is `{ host/hostname,
  port, path, method, headers }` (assembled into a URL for the primitive).
- **`http.request(...)`** returns a **`ClientRequest`** — `req.write(chunk)` (body,
  Stage 2), `req.end(body?)` (send), `req.on('error'|'response', …)`,
  `req.abort()`/`destroy()`.
- **`cb(res)`** / the `'response'` event delivers an **`IncomingMessage`**:
  `res.statusCode`, `res.headers`, `res.on('data', chunk)`, `res.on('end')`,
  `res.setEncoding(enc)`, `res.resume()`/`pause()` (accepted).

### Delivery model (V1)

The transfer runs when `req.end()` fires (or immediately for `http.get`). The
response is delivered to `cb`/`'response'` on a **microtask** (so the handler's
`res.on('data'|'end')` registrations, which run inside `cb`, are in place before
delivery), and the body is delivered as a **single `'data'` chunk then `'end'`**
(the full-buffer simplification the Node-stream runtime already documents —
incremental streaming is a follow-on). `statusCode`/`headers` are available
synchronously on the `res` handed to `cb`.

### Staging

- **Stage 1** — `http.get(url, cb)` → `IncomingMessage` with `statusCode` +
  `on('data')`/`on('end')` (the dominant test shape: hit a `createServer` under
  test, read the body). `ClientRequest` minimal (`on('error')`, `end()`).
- **Stage 2** — `http.request` + request body (`req.write`/`req.end(body)`),
  method/headers, the `options` object form.
- **Stage 3** — `res.headers`, `req.on('response')` (vs the `cb`), `setEncoding`,
  redirects/keep-alive knobs, `http.Agent`/`globalAgent` (accept/ignore).

### Divergences to keep bounded (V1)

- Body arrives as one chunk (not incrementally streamed) — inherits the
  Node-stream/fetch full-buffer model.
- Text bodies only past an embedded NUL (the `fetch` `.text()` limitation).
- No trailers, no `100-continue`, no connection pooling semantics observable.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| `__kml_fetch_async` libcurl request primitive (status + streamed body) | Built | runtime_fetch.go — the transport the client rides |
| Response status/body extraction + drive-to-completion | Built | emit_fetch.go / emitResponseCall — how Stage 1 reads statusCode + body |
| Microtask enqueue (deferred response delivery) | Built | `__kml_microtask_enqueue` — used by streams/promises for the same register-then-deliver order |
| EventEmitter-style `on('data'|'end')` listener storage + flowing delivery | Built | the Node-stream `__kml_ns_*` listener runtime is the closest model to mirror |

## Open questions

- Whether `IncomingMessage` should be a real Node `Readable` (so `.pipe()` works)
  or a bespoke event object (V1) — the former reuses TDD-00132's class-stream
  runtime but couples the client to it.
- `http.get`'s return value (a `ClientRequest`) is often ignored in tests; how
  much of `ClientRequest`'s writable-stream surface is worth V1.
- Options-object `{ agent, timeout, signal }` — accept-and-ignore vs honor.
