# ADR-01478: Library units the same in every program

- **Relations**: Extends ADR-01476, Extends ADR-01469
- **Date**: 2026-10-09

## Context

A builtin library module's unit is compiled once and cached by its text
(TDD-00238 Stage 4), so it is shared only if every program emits the same
text for it. `tools/libdrift` over 250 examples found 21 library functions
whose bodies differed between programs: `any` arithmetic carried the BigInt
check only in a program that can make a bigint (`mayHoldBigInt`). With a
program declaring a class extending Array, three more differed (an Array
method call on an array typed `T[]` dispatched to the program's overrides),
and so did code that boxes, inspects or unboxes an array (`hasArrayClass`).
The Test262 runner and the test helpers did not link library units
through the cache at all.

## Investigation

- `libdrift` counted every name carrying a library module key, but the
  splitter (`libOwner`) puts `__`-prefixed names (shape method adapters,
  class-reference getters, content-named helpers) in the program's unit:
  they were reported as drift without being one.
- A content-named helper (`@__kml_dynadapt.<hash>`) is spelled by its
  body's hash, and library code names it: its body has to be the same in
  every program as well.
- Node's internals call Array's methods through primordials
  (`ArrayPrototypeSlice(args)` in `normalizeSpawnArguments`), so a program's
  override is never run by the library: `spawnSync("echo", args)` with
  `class Args extends Array<string>` overriding `slice` prints nothing from
  the override (Node 24.19).
- The same program failed here: unboxing an `any` into `string[]` rejected
  the instance (it boxes as the instance, ADR-01469) with "the value is not
  an array". Writing the probes also turned up four Array-subclass bugs on
  the program's side: the override dispatch stored an array result as its
  aggregate where the slot holds the header (invalid IR); when one branch
  failed to emit (a dynamic adapter's arity variant), its join label was
  never emitted (invalid IR); `const x: string[] = instance` was a compile
  error; and `super.filter(f)` in a class that overrides `map` inferred
  `number`, because `super` is bound to Array's unregistered (empty) class
  type.
- With library code reading every array's header word, the HTTP/2 suite
  failed ("the value is not an array"): `String.prototype.split`'s C
  implementation (stringsrc/string.c) allocated its header without the
  word, so in any program declaring a class extending Array its result
  boxed as an instance (also without this change: `"a\nb".split("\n")`
  through `any` into `string[]` threw).

## Decision

- Code that must compile the same in every program
  (`programIndependent`: the library's, or a content-named helper's body,
  marked by `sharedBody`) tests at run time what a program's own code
  knows statically:
  - `any` arithmetic always checks for a bigint; the operation on two
    bigints calls the program's `@__kml_any_bigint_<op>`
    (`emitAnyBigIntOpsFinalize`), the bigint operation when the program
    can make a bigint, else an unreachable stub, so the library names no
    part of the bigint runtime.
  - `hasArrayClass` is true: boxing and inspecting ask the program's
    `@__kml_is_arrclass_body` (false without such a class, else the
    header word against Array's), `Array.isArray` reads an object's word,
    and unboxing an `any` into an array goes through the
    program's `@__kml_arrclass_box_` (`emitArrayClassReceiver` with method
    `""`, any instance's body), which answers 0 in a program without such
    a class.
- The library never dispatches an Array method to a subclass's override,
  as Node's primordials do not.
- `split`'s result header carries Array's word (`KML_ARRAY_HDR_WORD`,
  passed to string.c as to dynjson.c), as every array header must.
- Unboxing an `any` into an array takes an instance's body (both lanes,
  library and program).
- Override dispatch stores an array result as its header and reads it back
  with the header (`arrayValueFromHeaderReg`); on an error it emits the
  labels its branches jump to (`arrovFail`).
- An array variable initialized with an instance takes its body
  (`coerce`); `super` in a class extending Array infers as the host array
  type.
- `libdrift` counts only definitions a library unit compiles
  (`llvm.LibOwner`).
- The Test262 runner and the test helpers link library units through
  `llvm.LibObjects` (`libObjectFlags`; `appendLibObjects`, keyed by the
  caller's code-generation flags), except for a program that keeps its
  runtime exported (`ExportsRuntime`).
- A Worker program's module globals stay `thread_local` (each Worker
  evaluates its modules afresh): two variants of a unit, both cached.

## Side effects discovered

- BACKLOG 159: a species result that changes the element type (a generic
  `map<U>` override returning `super.map`, Array's `map` through `any` on
  an instance) is a plain array; Node returns an instance of the class.

## Verification

- `libdrift` over 250 random examples plus examples/classes/extends_array.ts
  and three Array-subclass/BigInt probes: 0 differing library functions
  (21 before).
- tests/lib_units_shared_test.go: the library units of a plain program and
  of one making bigints and declaring an Array subclass are identical; an
  Array subclass passed to `spawnSync` and an override reached through
  `any`, `super.filter`, an instance in a `string[]` variable and a
  `split` result through `any` beside an Array subclass match Node.
- Gates: see the delivery's run.
