# ADR-01634: `realpathSync` walks a UNC path from its share root

- **Date**: 2026-10-14

## Context

Node's `test-fs-readfilesync-enoent` failed on Windows:
`fs.realpathSync('//HOST/c$/Windows/System32')` threw
`ENOENT … lstat 'C:\HOST'`.

## Investigation

`path.win32` matches Node on UNC paths (`resolve`, `normalize`, `parse`). The
walk in `realpathJS` (`lib/node/internal_fs.ts`) took the root as a drive or
a single separator, so `\\HOST\c$\…` began at `\` and looked `HOST` up on the
current drive. Node's walk splits the root with
`/^(?:[a-zA-Z]:|[\\/]{2}[^\\/]+[\\/][^\\/]+)?[\\/]*/` on Windows: a drive, or
`\\server\share`, with the separators after it. `realpathSync.native` was
already right.

## Decision

`rootEnd` follows that expression: a drive, or a UNC root when both the server
and share names are non-empty, then any separators.

## Implementation notes

`lib/node/internal_fs.ts`. On POSIX the root is the leading `/` run, as before
for one slash and as Node's `/^[/]*/` for more.

## Verification

Windows 11: six paths (three UNC spellings, `C:\`, `C:`, `%windir%`), each with
`realpathSync` and `realpathSync.native`, print the same as Node 24.19.
`TestE2EWinRealpathUNC` (skipped where the administrative share is
unreachable). The Node file passes.
