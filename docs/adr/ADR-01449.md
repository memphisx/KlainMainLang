# ADR-01449: Number's safe-integer bounds are numbers

- **Relations**: Implements TDD-00230 (P2.2)
- **Date**: 2026-10-07

## Context

A shadow bucket (407 locations) was `Number.MIN_SAFE_INTEGER` in
`internal_timers.ts` under `-compat=js`: codegen inferred `any`, the
checker `number`. Probing it found a compile failure: under `-compat=js`,
`let t = Number.MIN_SAFE_INTEGER; function f() { return t + 1 }` failed with
"undefined variable 't__kml_mod0'". The bug predates this work (HEAD fails too).

## Investigation

- Under `-compat=js` the checker's primitive types are not consulted, so
  `Number`, inferred as a function value, sent the read to the
  function-own-property path, which answers `any`.
- A module-level binding is promoted to a global only when its type is a
  simple slot; `any` is not, so the binding stayed local while the
  function's read still named the global.
- Emission gave both safe-integer bounds `i64`; the strict lane's inference
  already gave `double` through the checker.

## Decision

- The numeric constants of `Number` and `Math` are never a function's own
  property.
- `MAX_SAFE_INTEGER` and `MIN_SAFE_INTEGER` are doubles in inference and
  emission, as every other `number` is.

## Verification

- `TestE2ENumberSafeIntegerGlobals` (against Node, strict and js lanes);
  the Number tests pass on the Mac.
