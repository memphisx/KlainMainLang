# ADR-00284: Array mutators accept any mutable receiver — object/class fields and nested-array elements

- **Relations**: Extends [ADR-00056](ADR-00056.md) (splice clamping) and [ADR-00061](ADR-00061.md) (why a mutator needs a length *storage location*, not just a length value)
- **Date**: 2026-08-22

## Context

`push`/`pop`/`shift`/`unshift`/`splice` all began with a hard
`mem.Object.(*ast.Identifier)` assertion, so `this.items.push(x)`,
`obj.arr.pop()`, and `matrix[0].push(x)` were compile errors ("push requires
an array variable") — one of the 2026-08-11 audit's findings, and a blocker
for the ordinary class-with-an-array-field idiom. (The same audit's
"pop/shift corrupt state on an empty array" claim turned out to be stale:
both have had an empty guard returning the ADR-00157 zero value with length
untouched — re-verified by direct repro before this change.)

## Decision

A shared `resolveArrayMutLoc(objExpr, verb, pos)` resolves the *storage
location* of a mutable array — the address its data pointer lives at and the
address its length lives at — replacing each mutator's identifier-only
prologue:

- **Named variable** — the symbol's two allocas (`Ptr`/`LenPtr`), unchanged.
- **Object/class array field** (incl. `this.field`) — the field's inline
  `{ptr, i64}` struct slot, split into its two sub-slots by GEP. Class field
  visibility is checked; no frozen-object check, since JS's `Object.freeze`
  freezes the object's fields, not the array those fields point at.
- **Nested-array element** (`matrix[i]`) — the element slot holds a box
  pointer to a heap `{ptr, i64}` (TDD-00029's storage scheme), so the GEPs go
  through the box: mutation updates every alias of that inner array, which is
  exactly real JS reference semantics.

Anything else (a `.slice()` result, a call result) still rejects cleanly —
a temporary has no writable home for a resized length.

`emitSplice`'s return type and the `const x = obj.arr.splice/pop/shift(...)`
declaration-inference fast path (emit_exprs_vardecl.go) now infer through
`inferExprType` instead of the identifier-only symbol lookup, matching the
new receiver coverage.

## Verification

- Node-diff (node v26.3.0, byte-identical, macOS/Apple Silicon): class
  `this.items` push/pop/unshift/splice/shift round-trip; interface-typed
  field via a function-returned object; `matrix[0].push` / `matrix[1].pop`
  aliasing; `const rem = b.xs.splice(1, 2)` element typing.
- New E2E: `TestE2EArrayMutatorsOnFieldsAndElements` (tests/arrays_test.go).
- Full `go test ./tests/` green; `make examples`; `make conformance` at
  delivery.
