# ADR-01735: E2E memory-mode and sanitizer lanes, and what the auto lane found

- **Relations**: `Implements TDD-00230`, `Extends ADR-01109`
- **Date**: 2026-10-19

## Context

P0.3 runs every program under `-mm=auto`, `-mm=auto -optimize-memory` and `-mm=gc`, with sanitizers armed on Linux. [ADR-01109](ADR-01109.md) built `make mode-lanes` over the examples. The E2E programs and the sanitizer lane were still missing.

## Decision

- **Lanes:** `make test-lane-auto`, `test-lane-optmem`, `test-lane-gc` and `test-lane-san` run the E2E suite through the shard runner with one environment variable set:
  - `KLAIN_TEST_MM=auto|gc` sets the memory mode in every test emitter (`applyTestModeEnv`). Under gc, `buildBinary` also links the GC shim and the collector (`testGCArgs`); a machine without libgc skips.
  - `KLAIN_TEST_OPTMEM=1` adds `-optimize-memory`.
  - `KLAIN_TEST_SAN=1` builds every plain `-O2` program with `-O1 -g -fsanitize=address,undefined -fno-sanitize-recover=undefined` and the ASan options file (`testSanitizerArgs`).
- **Fixes from the first auto-lane run** (7 failures):
  - **A binding declared in a `try` body, freed at its scope's end:** the throw path skipped the declaration and freed an uninitialized slot. A slot with a pending free now starts null in the entry block (`maybeRegisterAutoFree`).
  - **`f.bind(…)` kept `f` local:** the escape check treated it as a receiver call, so auto freed the closure while the bound function could still run. `.bind` on the candidate now escapes it.
  - **`super.slice(…)` in a class extending Array:** the body-species rule emitted `super` as a value ("unknown expression type"). A `super` receiver is left to the super call.
  - **`@__kml_obj_has_extra` undefined:** a finalize hook generated after the last `emitObjExtraFinalize` call split an object. Finalize now runs it again after those hooks.
  - **Library units differed between programs:** the body-species rule enumerated the program's classes inside library code. Program-independent code now calls `@__kml_species_fill_<hash>(obj, res)`, which the program defines over its own classes whose element type is the result's (or returns the result when it has none). The name is a hash, since a library type's mangle carries its module's key, which would give the dispatcher to that module's unit. A synthesized binding (`bindValue`, a host body) shows the expression it stands for in "is not iterable" messages, not its generated name.
  - **An undefined optional end** (`arr.slice(s, e)` with `e?: number` absent) read as 0, where JavaScript reads the length; this affected `slice`, `subarray`, `fill` and `copyWithin` (`emitEndIndex`). Array `includes` and `lastIndexOf` gained their `fromIndex` argument.

## Verification

macOS (Apple Silicon), against Node:

- **The auto lane's failures** pass under `KLAIN_TEST_MM=auto`. TestLibUnitsSameAcrossPrograms passes in both modes.
- **New tests:**
  - `tests/memory_auto_test.go` TestAutoSkippedDeclAndBoundTarget;
  - `tests/array_search_null_test.go` TestE2EArrayOptionalIndexArgs;
  - `tests/json_test.go` TestE2EJSONParseDeepNesting (replaces the 512-depth rejection: the parser, free and `any` conversion are iterative).
