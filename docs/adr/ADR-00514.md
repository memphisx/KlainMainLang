# ADR-00514: Non-blocking `server.listen` + the buffered-sink Writable surface on `res`

- **Relations**: `Implements TDD-00131`, `Extends ADR-00513`, `ADR-00391`
- **Date**: 2026-08-30

## Context

Two remaining items on TDD-00131's `http.createServer` scope, both about the
`res`/`server` Writable-stream contract:

1. **`server.listen` blocked** until the loop stopped — top-level code after
   `listen()` never ran until the server closed, so Node's listen-then-continue
   flow ("bind, keep going, the loop drains at exit") was impossible to write.
2. **No `res.write` boolean / `cork` / `uncork`** — portable Node code that
   checks `res.write(...)`'s backpressure return or brackets writes with
   `cork`/`uncork` failed to compile.

## Investigation

**Listen.** `emitHTTPServerListen` (`emit_http.go`) already registered the
listener into globals (`@__kml_listen_fd`/`@__kml_listen_handler`/
`@__kml_listen_dispatch`), fired the ready callback synchronously, and stored the
bound fd (so `.address().port` works) — all *before* it called
`__kml_event_loop_run()` inline. The inline loop was the only thing making it
blocking. Meanwhile `EmitProgram`'s Pass 3 tail (`emitter.go`) already runs
`__kml_event_loop_run()` after the top-level script for timers/SSE/WS/workers/
net — the same drain the listener needs. The blocking behaviour was purely the
inline loop pre-empting that tail (its own comment noted the tail was "dead code"
because the inline loop never returned).

Crucially, the **cluster fork** (`__kml_http_cluster_fork`) only forks for the
bespoke `http.listen(port, handler, {workers})`; the Node bound-handle path calls
it with `0` and never forks. So making *only* the bound-handle path non-blocking
avoids the hazard of forked children running post-listen top-level code.

**Writable surface.** `res` is a buffered sink — the handler builds
`{status, body, headers}`, flushed after it returns (ADR-00300/ADR-00391). A
buffered sink genuinely never applies backpressure, so Node's `res.write`
boolean is correctly always `true`, and `cork`/`uncork` (write-coalescing hints)
are correctly no-ops. This is the accurate contract for the model, not a stub.

## Decision

**Non-blocking listen (bound-handle path only).** `emitHTTPServerListen` no
longer emits the inline `event_loop_run()`/post-loop flush; it sets a new
`usedHTTPListen` flag and returns. The Pass 3 tail adds `usedHTTPListen` to its
`useFullLoop` condition and, when set, calls `emitPostLoopFlush()` after the tail
loop (preserving the http-client reaction flush the inline loop used to do). The
bespoke `http.listen` is unchanged (stays blocking — cluster fork depends on it).

**Buffered Writable surface on `res`.** `res.write` now returns a boolean `true`
(with `inferExprType` reporting `TypeBool` for `res.write(...)`), and
`res.cork()`/`res.uncork()` are accepted as zero-arg no-ops. `res.end` stays
void. No `'drain'` event exists (never needed — write never returns false).

## Implementation notes

- The ready callback and `.address()` already being sequenced before the loop is
  what makes non-blocking safe with no reordering: nothing that ran before the
  inline loop moves.
- `usedHTTPListen` gates the post-loop flush so non-http full-loop programs
  (pure SSE/WS/workers) are unaffected.

## Side effects discovered

- **Ready-callback timing** remains a pre-existing divergence (unchanged here):
  the callback fires synchronously at `listen()` time, not on a later tick, so a
  `close()` issued before that tick does not cancel it. Documented on the status
  row.
- **True incremental backpressure** (streaming `res.write` to the socket during
  the handler, a real `'drain'`) is deliberately *not* done — it would require
  replacing the buffered response path, disproportionate to its value given the
  `ReadableStream` `body` field already streams large responses. The buffered
  contract (always-true `write`, no-op `cork`/`uncork`) is the honest surface.

## Verification

- New E2E tests (`tests/http_test.go`): `…NonBlockingListen` (proves
  listen-then-continue *through the response* — a top-level binding mutated after
  `listen()` is observed by the handler) and `…WriteBoolAndCork`
  (`cork`/`write`→bool/`uncork` over a real GET). Both pass.
- Full `TestE2EHTTP|Net|TLS|WebSocket|EventSource` suite passes (184s) — no
  regression from the terminal-control-flow change.
- Machine: Apple Silicon M4 (macOS).
