# ADR-00640: `Reflect.get`/`has` on a static object reject cleanly instead of emitting invalid IR

- **Relations**: `Extends ADR-00630`
- **Date**: 2026-09-02

## Context

A Test262 invalid-IR sweep (comparing the current compiler against the pre-D1
parent commit to isolate what the D1 work newly reached) surfaced three
`built-ins/Reflect/{get,has}/*` files that emit **invalid LLVM IR** — a
`CLANG_ERROR`, i.e. the emitter accepted the program and produced IR that only
`clang` rejects. The representative:

```js
var o1 = { p: 42 };
Reflect.has(o1, 'p');
```

produced `%t5 = call i8 @__kml_nb_tag(i64 %t4)` where `%t4` is a `ptr` (the
static object's struct pointer), not the `i64` NaN box `__kml_nb_tag` expects —
`'%t4' defined with type 'ptr' but expected 'i64'`.

These were `COMPILE_ERROR` on the parent (the front-end rejected the whole
file earlier), so D1's more permissive front-end is what let them reach codegen;
D1 introduced no *regression* of previously-valid code (the same sweep found 0
files that compiled to valid IR before and invalid IR now).

## Investigation

- ADR-00630 already settled the static→dynamic direction: allocation-site
  widening is **superseded, not built**. Under `-compat=js` a bare object
  literal *is* a D1 bag from the start; under `strict` a statically-typed struct
  in a dynamic position keeps a **clean rejection** by design (silently demoting
  a typed struct to a bag would surrender the static representation strict
  mode exists to guarantee).
- The defect is that `strict` did not *honor* that decision for two of the
  Reflect forms. In `emitReflectCall` (`emit_reflect.go`), `set` /
  `deleteProperty` / `setPrototypeOf` resolve their target through
  `emitDynBagOrThrow` (`emit_dyndesc.go:30`), which already carries the
  `if !v.Ty.IsDynamic { return "… requires a dynamic (any-typed) object" }`
  guard. `getPrototypeOf` guards the same way (`emitObjectGetPrototypeOf`), and
  `isExtensible` / `preventExtensions` `emitBoxValue` their operand first
  (`emit_dyndesc.go:368,391`) so a static object boxes to a valid tag-6 word and
  the tag check simply falls through — valid IR, JS-default behavior.
- Only `get` and `has` took the raw `emitExprWithObjectHint(args[0], TypeAny)`
  value straight into `emitDynAnyMemberGet` / `emitDynAnyHas`, which call
  `emitUnboxTagPayload` (`emit_dynamic.go:455`) — `nb_tag`/`nb_pay` on the
  register as-is. For an `any`/bag operand that register is the `i64` box and
  the IR is correct (verified: `const o: any = {…}; Reflect.has(o,'p')` runs and
  prints `true`/`false`); for a static object it is a bare `ptr`, so the `i64`
  call is malformed.
- Rejected: boxing the static operand first (as the flag helpers do). Its box
  carries tag `kmlTagObject`, which `emitDynAnyHas` does not treat as a bag, so
  it would *throw* "Cannot use 'in' on a non-object" at runtime — worse than a
  compile-time rejection and contrary to real JS (`Reflect.has` on a real
  object answers per its fields). The faithful behavior for a static struct
  under strict is the same clean rejection the sibling forms already give.

## Decision

Add the existing dynamic-operand guard to `Reflect.get` and `Reflect.has`:
after resolving the target, if `!v.Ty.IsDynamic`, return
`"Reflect.<m> requires a dynamic (any-typed) object"`. This makes all Reflect
forms uniform (a static target is a clean compile-time rejection everywhere)
and removes the invalid IR. The correct-behavior paths are untouched: an
`any`-typed target under `strict`, and any bare literal under `-compat=js`
(where it is already a bag), both still work.

## Implementation notes

- `codegen/llvm/emit_reflect.go`: two guards, mirroring
  `emitDynBagOrThrow`'s existing check verbatim in wording.
- No runtime/`.c` changes; purely a front-end rejection added ahead of an
  already-broken emit path.

## Side effects discovered

- The invalid-IR sweep found **427** `CLANG_ERROR` files total; **420** were
  already invalid IR before D1 (a pre-existing, cross-cutting backlog — sparse-
  array destructuring defaults, `ArrayBuffer.prototype.resize`, `Array.at`
  ToInteger-on-object, etc.), unrelated to this change and not addressed here.
  The remaining new-since-D1 handful beyond the three Reflect files are an
  `eval`-code case (out of scope, TDD-00046), two `NaN`-shadowing files
  (`-compat=js` territory), and one `class` static-init codegen error — each a
  distinct subsystem, tracked as part of the general invalid-IR backlog rather
  than this fix.

## Verification

- `tests/dynstage67_test.go`: `TestE2EReflectGetHasOnAnyTargetStrict` (positive,
  strict `any` target), `TestE2EReflectHasOnStaticObjectRejected`,
  `TestE2EReflectGetOnStaticObjectRejected` (clean rejection). Existing
  `TestE2EReflectStatics` (bare literal under `-compat=js`) still passes.
- Repro on all three Test262 files now returns a compile-time rejection, not
  `CLANG_ERROR`. Mac (Apple Silicon).
