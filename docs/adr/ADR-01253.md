# ADR-01253: Optional chains and calls on `any`

- **Relations**: `Extends ADR-01037`
- **Date**: 2026-09-29

## Context

On an `any` value, `?.` did not short-circuit:
- `o.m?.()` threw "m is not a function" where `o.m` was undefined.
- `n?.m()` and `n?.f?.()` threw "Cannot read properties of null" where `n`
  was null.

The chain guard (`classifyChainGuard`) knew nullable scalars and pointers
only, so an `any` base got no guard. The optional-call paths had no `any`
case. It came up as `process.send?.(x)` in a program that was not forked.

## Decision

An `any` base is guarded on its null and undefined tags:
- in an optional chain, as a new guard kind;
- in `a?.m()`;
- in `o.m?.()` / `o?.m?.()`, where the receiver is evaluated once, the
  member is read, and the call runs only when the member is neither null
  nor undefined.

A skipped result is the `undefined` box. The null branch of a
null-guarded call used to store the zero word for an `any` result.

## Verification

Mac (Apple Silicon): `TestE2EOptionalChainingOnAny`, where null, undefined
and object receivers match Node's output, and a skipped call's arguments
are not evaluated.
