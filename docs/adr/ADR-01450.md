# ADR-01450: Class expressions are class values

- **Relations**: Implements TDD-00230 (P2.1, P2.3)
- **Date**: 2026-10-07

## Context

A shadow bucket (294 + 290 locations, Test262's class-expression tests) was
`var C = class { … }; new C()`: codegen knew the instance, the checker
answered `any`.

## Investigation

- The binder declared a class expression's symbol only when it was named,
  with the `ClassExpression` as its declaration, so `classDecl` (which
  reads a `ClassDeclaration`) found nothing. An anonymous one had no symbol.
- The checker had no case for a `ClassExpression`.
- `new X()` through a variable returned a real `any` when the variable's
  type was unanswered: the unanswered sentinel carries the `Any` flag.
- tsc 5.9 prints an anonymous class by the binding it initializes
  (`const D = class {}` is `D`, `typeof D`), else `(Anonymous class)`; a
  named one by its own name.

## Decision

- Every class expression gets its own name scope declaring its symbol (the
  parser's `$…` name for an anonymous one, which no source can write), with
  the inner `ClassDeclaration` as its declaration.
- A `ClassExpression` is typed as its symbol's class value; `new` through a
  binding holding one gives the instance.
- A symbol's new `Display` name prints an anonymous class: the binding it
  initializes, else `(Anonymous class)`.
- `new` through an unanswered callee stays unanswered.
- Inference pairs two classes' instances member by member, and a class
  declared inside a generic function names its type parameters through its
  members (`foo<T>(x = class { prop: T })` called with `class { prop =
  "hello" }` infers `T = string`, as tsc does). A visited set ends the walk
  on a self-referential class.

## Verification

- `tools/tsdiag`: no code gains a false positive.
- `TestClassExpressionTypes` (tsc 5.9 messages); the class-expression E2E
  tests pass on the Mac.
- The probe's `new C()` rows are gone; the remaining ones read a method as
  a value (BACKLOG #138).
