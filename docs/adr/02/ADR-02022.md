# ADR-02022: A regular expression literal in a not-a-function message

- **Date**: 2026-11-21

## Context

`/a/.foo()` threw "(intermediate value).foo is not a function", and V8
prints "/a/.foo is not a function". The parser lowers a regular
expression literal to the node `new RegExp(pattern, flags)` produces, so
the call printer could not tell the two apart. The static-member case in
the same backlog entry (`D.m.zz()`) already matched.

## Decision

- `ast.NewRegExpExpression` gains `Literal`, which the parser sets for
  the literal form.
- The callee printer shows a literal as written, `/pattern/flags`; `new
  RegExp(…)` stays an intermediate value.

## Implementation notes

- ast/nodes.go (walker regenerated), parser/parser_literals.go,
  codegen/llvm/emit_dynfunc.go (`calleeDisplayName`).

## Verification

- `TestE2ENotFunctionCalleeNamesJS` matches Node on Linux x86 (Node304).
