# ADR-00673: `PerformanceObserver` (perf_hooks) — synchronous V1

- **Relations**: Implements TDD-00166; Extends [ADR-00672](ADR-00672.md)
- **Date**: 2026-09-03

## Context

`perf_hooks.PerformanceObserver` was the next TDD-00165 Stage-4 extra. Unlike the
`url` helpers, it is a small subsystem — an observer registry, the observer/list/
entry object types, and a dispatch path that `performance.mark`/`measure` drive.
Designed in TDD-00166.

## Decision

- **Objects** (`types.go`): `PerformanceEntry` (`name`/`entryType`/`startTime`/
  `duration`), a `PerfEntryList` handle wrapping the entries buffer as a
  `(data, len)` pair, and a `PerfObserver` handle holding the callback closure +
  its registry-node pointer. Two type flags (`IsPerfObserver`/`IsPerfEntryList`)
  route method dispatch.
- **`new PerformanceObserver(cb)`** is hooked in `emitNewExpression` by class name
  (like `Promise`/`Proxy`/`WebSocketServer`) — **no parser/AST change**. The
  callback is emitted with a `PerfEntryList` param-type hint so an untyped
  `(list) =>` arrow resolves `list.getEntries()` (it would otherwise default to a
  number). `PerformanceObserver` is registered as a `perf_hooks` reexport so it
  imports named/aliased/global (recognized in codegen, so aliasing renames the
  `new` class name).
- **`.observe({ entryTypes: [...] })`** computes a compile-time entry-type bitmask
  (`mark`=1, `measure`=2) from the literal options and prepends a node
  `{ closure, mask, next }` to a process-global linked registry
  (`__kml_perfobs_add`). **`.disconnect()`** clears the node's mask.
- **`performance.mark`/`measure`** now also build a `PerformanceEntry`, wrap it in
  a one-entry list, and walk the registry firing every observer whose mask matches
  (`emitPerfDispatch`).

## Dispatch timing — the V1 decision

Dispatch is **synchronous** — the observer callback runs during the `mark`/
`measure` call, once per matching entry — not Node's asynchronous, batched,
next-microtask delivery. This ships the correct entry data through the real
callback/list/entry objects; the observable difference is that observer output
precedes later straight-line output, and multiple entries in a turn arrive as
separate callback calls. Faithful async batched dispatch (invoking a KML closure
with object args from the microtask queue — a trampoline the promise-reaction
machinery has but which isn't yet factored for reuse) is the documented TDD-00166
Stage-2 follow-up, together with `buffered: true`, `takeRecords()`, the single-
`type` form, and `getEntriesByName`/`getEntriesByType`.

## Scope (V1)

Entry types `mark`/`measure`; the `entryTypes: []` array form; `observe`/
`disconnect`/`getEntries`; the callback receives the list (the second `observer`
argument is omitted). `performance.measure` keeps returning its number *and* now
also produces an entry.

## Verification

E2E tests in `tests/node_core_modules_test.go`: measure observation with a field
check, mark observation + `disconnect` (no further entries), an aliased import,
and an unsupported-`entryType` rejection. `go test` over the perf/date/timers/
import suites green (Mac); `go vet ./...` clean. Registry-walk IR was kept simple
(a single linked list, mask-gated) to stay verifiable.
