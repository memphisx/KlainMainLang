# ADR-01728: Foreign class instances' fields, process.title, cluster worker.process

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-18

## Context

Checking `cluster.worker` in a worker against Node turned up these problems:

- **`worker.process.pid`:** inside a worker it read `undefined`. In Node, `cluster.worker.process` there is the process object itself. `lib/node/cluster.ts` stores `process` in a field typed `ChildProcess`, and every field read used `ChildProcess`'s layout.
- **Program classes, too:** a value typed as one class but holding another class's instance (a cast through `any`) read and wrote fields at the typed class's offsets. For example, `h.a.y` returned B's `name`, and `h.a.x = 5` wrote another slot. Method calls already took the instance's own method by name (`foreignMethodTags`). Field access did not.
- **`process.title`:** it was missing. Assigning it also hid `process` itself ("undefined variable 'process'"), because no route sent the write to the process object.

## Decision

- **Field access by name when the instance may be foreign:**
  - A field read or write through a receiver other than `this` checks the instance's class header when some unrelated program class lays out that slot differently (`foreignFieldTags`): a different field there, or none.
  - The class or a subclass reads through the layout. Any other instance reads or writes the property by name through the dynamic path, as JavaScript does.
  - A compound assignment reads and writes by name.
  - `this` is always the class's own instance, so `this` accesses skip the check.
- **Library classes:** these are not cast between, except the pairs `libraryForeignClasses` names. Today that is only `ChildProcess` ← `ProcessObject`, for the cluster worker's `process`.
- **`process.title`:**
  - The process object has a `title` accessor. It reads the operating system's `argv[0]` until a program sets it.
  - Setting it keeps a copy and calls `uv_set_process_title`, defined beside the event loop in `loop.c`, which links libuv.
  - A write to `process.title` (or to another member the process object holds) goes to that object.

## Consequences

- **Cost:** in a program with unrelated classes of differing layouts, each non-`this` field access of such a class costs a header compare and a branch.
  - Narrowing it to classes whose values actually cross `any` is future work; it would need an escape analysis of casts.

## Verification

macOS (Apple Silicon), against Node:

- **New E2E tests:**
  - `tests/class_foreign_field_test.go` TestE2EClassForeignInstanceFields: reads, writes and compound writes of a foreign instance's fields; the own instance unchanged.
  - `tests/process_test.go` TestE2EProcessTitle.
  - `tests/process_test.go` TestE2EClusterWorkerProcessPid.
- **Cluster probe:** all of a worker's `cluster.worker` events, `send`, `id` and `process` match Node.
- **Unit tests:** codegen and declaration-conformance pass.
