# ADR-01306: `node:ffi` as Node's lib/ffi.js over libffi

- **Relations**: `Implements part of TDD-00230` (P3.1), `Supersedes ADR-00799`, `Supersedes ADR-00800`, `Extends ADR-01304`
- **Date**: 2026-09-30

## Context

`node:ffi` was compiled directly (`emit_ffi.go`, `emit_ffi_callback.go`,
most of `emit_ffi_runtime.go`): a signature had to be an object literal,
resolved at compile time into a direct C-ABI call, and callbacks came from
static per-signature trampoline families, sixteen live per signature shape.
Node resolves signatures at run time through libffi and has no callback
limit.

## Investigation

The existing registry (`ffisrc/ffi_registry.c`: Node's `symbols` and
`functions` tables in its std::unordered_map order, ResolveSymbol /
PrepareFunction / GetSymbol / Close, the per-type argument validators)
already carried Node's semantics independently of how a call is made. The
behaviour the tests pin (checked against a real `--experimental-ffi` build
when they were written): argument messages per kind, `Invalid argument
count`, signature errors, `ERR_FFI_LIBRARY_CLOSED`, function objects named
for their symbol with `length` and an own `pointer`, one identity per symbol,
`exportString`'s validation.

## Decision

- `ffisrc/ffi_native.c` (`@link ffi`, linking libffi; the SDK's on macOS):
  libraries as per-thread ids over the registry; call interfaces per
  signature (`ffi_prep_cif`), arguments validated with the registry's
  validators and results boxed (a 64-bit integer or a pointer as a bigint);
  callbacks as libffi closures whose handler hands the boxed arguments to the
  module's callback and takes its result back; the memory accessors, C
  strings, copies in and out. `__kml_native_ffi_view` (IR) wraps foreign
  memory as a Buffer or ArrayBuffer without copying.
- `lib/node/ffi.ts`: `DynamicLibrary` (`#`-private state, `path`,
  `symbols`, `functions`, `getFunction(s)`, `getSymbol(s)`, `close`,
  `[Symbol.dispose]`, `registerCallback`/`unregisterCallback`/`refCallback`/
  `unrefCallback`), `dlopen`/`dlclose`/`dlsym`, `suffix`, `types`, the
  accessors, `toString`/`toBuffer`/`toArrayBuffer`/`getRawPointer`,
  `exportString`/`exportBuffer`/`exportArrayBuffer`/`exportArrayBufferView`.
  A bound function is a closure with `name`/`length` defined on it and an
  own `pointer`. `node:ffi` only (`kml:scheme-only`).
- Deleted: the ffi codegen, the `node:ffi` virtual module, `UsesNodeFFI`,
  the `FFISignature`/`IsFFILibrary`/`IsFFIFunction` types and their
  branches.

## Implementation notes

Compiler fixes found on the way:
- `Object.defineProperty(fn, 'name' | 'length', …)` is honoured by
  `fn.name`/`fn.length` and inspect, and a function's property bag starts
  with Node's own `length` and `name` (not writable or enumerable,
  configurable), so their descriptors match Node's.
- `<`, `>`, `<=`, `>=` on `any` compare a bigint by value, against a bigint
  or a number (JS's IsLessThan); they read false before.
- `x === false` for an omitted `x?: boolean` (a `T | undefined` local read
  as its payload) compares the presence too.
- A bigint Map/Set key is boxed and compared and hashed by value;
  `new Set(bigints)` was invalid IR.

## Side effects discovered

- A class instance cannot carry own accessor properties (`Object.
  defineProperty(this, …)` is rejected, and `as any` is erased): `console.
  log(lib)` shows `DynamicLibrary {}`, not Node's `{ path: [Getter],
  symbols: [Getter] }`.
- `using` declarations are not parsed.

## Verification

`tests/ffi_test.go` passes (two tests that asserted the old limits — the
sixteen-callback cap and compile-time-only signatures — are replaced by
`TestE2EFFIRuntimeSignaturesAndManyCallbacks`; the inspect line of
`TestE2EFFIAccumulatorShapes` is dropped with the divergence recorded);
`examples/ffi/ffi.ts` runs. No Node ≥ 26.10 oracle on this machine. macOS
(arm64).
