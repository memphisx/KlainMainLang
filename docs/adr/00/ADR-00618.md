# ADR-00618: httpbin-lite fixture rewritten in KlainMainLang

- **Relations**: `Extends ADR-00096`, `Implements TDD-00026`
- **Date**: 2026-09-01

## Context

`tools/httpbin-lite/main.go` — the local fixture `make examples` starts so the
fetch / async / eventsource / streams examples don't depend on a third-party
host (ADR-00096) — was the last piece of this project's own example/CI
infrastructure written in a language other than KlainMainLang. TDD-00026's
motivating goal was to rewrite it in KlainMainLang once binary-safe response
bodies landed (they did, via `bodyBytes` / streaming `ReadableStream` bodies).

## Investigation

Every route is expressible with one `http.listen` handler routing on
`req.method`/`req.path`:

- The request/response routes (`/get`, `/ip`, `/status/{code}`, `/redirect-to`,
  `/post`, `/delete`, `/headers`) use arbitrary status/headers/body reads.
- `/bytes/{n}`'s embedded null byte survives via a `ReadableStream<Uint8Array>`
  response body (the `string | ReadableStream` union) — a single Uint8Array
  chunk carries a real byte count, so `strlen` never truncates it. This unifies
  the binary route with the streamed ones under one body type rather than
  reaching for a separate `bodyBytes` field.
- `/chunked` and the SSE routes stream chunk-at-a-time from a `ReadableStream`
  whose `pull` awaits `setTimeout`, so a slow response yields the fiber instead
  of blocking — concurrent `/delay` requests still overlap.

Several compiler realities shaped the code, verified by probe before committing:

- The `http.listen` handler must be an **inline arrow** — a named async handler
  reference isn't given the async treatment, and an *async* handler doesn't
  compose with a union `string | ReadableStream` body. A non-async handler with
  an async `pull` does, and is enough (no route needs an async handler).
- A closure can't capture an array variable, a function parameter, or a local
  through a nested `Promise` executor. So captured arrays/params are copied to
  locals inside the callback, and `/delay` sleeps as a loop of fixed-literal
  100ms ticks (the tick count captures fine; a variable timeout would not).

## Decision

Replace `main.go` with `tools/httpbin-lite/httpbin.ts`, compiled by this
project's own compiler. The Makefile's `examples` target now builds it with
`klainmain -o .httpbin-lite tools/httpbin-lite/httpbin.ts` instead of `go build`.
Generated sidecars next to the source are gitignored.

**SSE hold-open uses short, repeated keepalive pulls, not one long sleep.** An
SSE endpoint that held its connection open with a single multi-hour `setTimeout`
inside `pull` starved every other connection: while a streaming response's
producer idles on a distant timer, the event loop's `select()` wait is bounded
by that timer and new connections are not served until it fires. Re-pulling on a
short (250ms) interval keeps the loop waking — and is exactly how real SSE
servers hold a connection open (keepalive) — so concurrent requests are served
promptly. The event loop's responsiveness under a genuinely idle long-timer
streaming producer is a real latency edge, recorded as a follow-up (§Side
effects); the fixture doesn't depend on it.

## Verification

Mac (Apple Silicon M4). All 10 fixture-dependent examples (fetch ×5, xhr, the
two async /delay examples, eventsource, streams/fetch_body) pass against the TS
fixture, and per-endpoint curl checks match the Go fixture — including
`/bytes/16`'s null byte at offset 5, a ~1s non-blocking `/delay/1`, 302
redirects, and the SSE reconnect/`Last-Event-ID` replay. `make examples` green.

## Side effects discovered

A streaming `http.listen` response whose producer idles on a long timer delays
other connections' service until the loop's next wake (its `select()` timeout is
the timer deadline; a new connection isn't served early). Not hit by any example
(SSE keepalive pulls frequently), and out of scope here — recorded as a
follow-up on the event loop's new-connection responsiveness during idle streams.
