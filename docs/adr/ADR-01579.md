# ADR-01579: Library literals and per-type helpers compile outside the program unit

- **Relations**: Extends ADR-01329, ADR-01478, Implements TDD-00248
- **Date**: 2026-10-11

## Context

TDD-00248: an http2 example's program unit had grown to 29.8 MB of its
55 MB of IR. Every compile ran `clang -O2` over it: 11 to 14 seconds on
the Mac, whatever the cache held. Under the conformance runners' load
about 80 http2 node tests hit the 30-second clang timeout.

The library's module units were cached and byte-identical across
programs. What landed in the program unit was everything `libOwner` gives
the program for starting with `__`:

| What | Size |
|---|---|
| The library's function literals | 3.2 MB |
| Shape rows (getter, setter, keys) | 6 MB |
| Library classes' shape method adapters | 4.4 MB |
| Host inspect routines at every depth | 3.8 MB |
| Host method adapters, record views, generator adapters, host rows, conversions out of `any` | about 3.5 MB |
| Dynamic property reads and writes per property name | 6.2 MB |

## Decision

`libOwner` gives three more kinds of name a unit of their own:

- **A library function literal** (`__closure`, `__generator_body`,
  `__generator_method`, `__kml_dynfn` named `<prefix>.node_<module>.<pos>`)
  belongs to its module. It is emitted with the function that holds it.
- **A helper generated for one library-stable type id** belongs to unit
  `stb_<id>`, with the other helpers for that id. These are the shape
  getter, setter, keys and symbols; the inspect routines; the conversion
  from `any`; the host method adapters and host rows; the record views and
  writes; the generator adapters; and the custom-inspect hook. A library
  class's shape method adapters are now named
  `__kml_shape_m.<id>.<method>` instead of after the class, so they join
  that unit.
- **A dynamic property read or write** (`__kml_dynget.<hash>`,
  `__kml_dynset.<hash>`) belongs to unit `dyn_get_<hash>` or
  `dyn_set_<hash>`. Its body depends only on the property name, except for
  `constructor`'s, which lists the program's Error subclasses. That unit
  simply misses the cache in such a program.

These helpers no longer depend on the program:

- **Numbering:** a detached helper numbers its registers and labels from
  zero, as a declared function does, instead of continuing the program's
  counters.
- **Program-independent mode:** a helper for a stable id is built in that
  mode (`stableHelperBody`), so it tests at run time for a class extending
  Array instead of compiling in the program's own classes.
- **Host method adapters:** these skip the Array-override dispatch. The
  adapter accepts only the exact host layout, never a subclass instance's
  body, so the override branch could never be taken.

A record view still compiles to a throwing stub in a program that boxes
nothing. Reading the table instead would pull the dynamic runtime into
every program. The stub's unit is a second text for the same key, cached
separately.

A unit is cached by its text, so the split affects only how often objects
are reused, never correctness. A unit whose text differs between programs
compiles afresh. Definitions moving out of the program unit keep working
because the split already gives a cross-unit `internal` or `private`
definition hidden linkage.

## Consequences

For `examples/http2/streams_server.ts`:

- The program unit is 3.1 MB, down from 29.8 MB.
- A warm build takes 4.1 seconds, down from 11 to 14 (2.8 seconds is the
  front end).
- A different http2 program builds in 4 seconds on its first compile.
- The two examples share 510 units, all byte-identical.

A program now links several hundred small cached objects instead of
compiling them, and the cache holds one object per library type that some
program boxes.

`TestLibUnitsSameAcrossPrograms` holds the new units identical between a
program with no classes and one extending Array. `TestProgramUnitStaysSmall` fails if the example's program unit passes
6 MB, or if a unit the two examples share differs between them.

## Verification

Mac: the http2, inspect, generator, shape, dynamic, js-lane, dynamic
import, island and worker E2E suites, run with targeted `-run` filters.
Linux: full gates on both boxes.
