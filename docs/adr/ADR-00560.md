# ADR-00560: console.table()

- **Relations**: Extends ADR-00029, TDD-00075
- **Date**: 2026-09-01

## Context

`console.table()` was the one unimplemented console method. It renders tabular
data as a Unicode box-drawing table and had been deferred as needing genuinely
new layout machinery rather than an extension of the existing print path.

## Investigation

Node's v26 output is deterministic and matchable:

```
┌─────────┬────┬───┐
│ (index) │ a  │ b │
├─────────┼────┼───┤
│ 0       │ 1  │ 2 │
└─────────┴────┴───┘
```

Each column's width is `max(header, all cells)` in display characters; a cell
is `" " + content.padEnd(width) + " "` (left-aligned); the borders repeat `─`
`width+2` times per column, joined by `┬`/`┼`/`┴`. Cell content is exactly the
`util.inspect` form (`emitInspectField` already produces it — numbers/bools
unquoted, strings single-quoted, nested objects/arrays inlined). Object-array
elements expose their fields via the same `VisibleFields`/`FieldIndex`/`StructIR`
path `emitInspectObject` uses; a primitive array uses a single `Values` column.

## Decision

Add `emitConsoleTable` (emit_console_table.go). Columns are `(index)` plus each
object field (or a single `Values` column for primitives). Two runtime helpers,
`__kml_table_repeat` (repeat a unit string, for the `─` borders) and
`__kml_table_padend` (space-pad to a byte width), back the layout. Rendering is
two passes over the array: pass A grows per-column width allocas from each
cell's `strlen`; pass B builds the top/header/mid borders, then appends each
row line in a runtime loop, then the bottom border, and prints the whole string
with one `printf`. A non-array argument (or an empty-field object element)
falls back to `console.log`, matching Node's behavior for a non-tabular value.

Width is measured in bytes, so the layout is exact for ASCII content and
follows the same wide-character narrowing the rest of the string surface
already documents.

## Implementation notes

- `tableColumn` pairs a compile-time header with a cell-emitting closure, so the
  object-field and primitive-`Values` shapes share the width/render loops.
- Cell strings are recomputed in both passes (measure, then render) rather than
  stored — the array length is a runtime value, so there is no fixed-size place
  to cache per-row strings; recompute is simpler and only costs extra
  allocations.

## Side effects discovered

Corrected a stale `console.time` comment in the console example (it described
the pre-ADR-00544 single-slot behavior).

## Verification

`TestE2EConsoleTableObjects`, `TestE2EConsoleTablePrimitivesAndStrings`, and
`TestE2EConsoleTableFallback` pin the exact output; the object, class-instance,
primitive, boolean/float, and string cases were `diff`ed byte-for-byte against
Node v26 and are identical. The `examples/console/console.ts` example runs.
Built and verified on Mac (Apple Silicon).
