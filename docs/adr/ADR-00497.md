# ADR-00497: Path-based fs sync ops batch

- **Date**: 2026-08-29

## Context

The Node-oracle failure histogram puts `fs has no method '%s'` at 49
files; the corpus's most-called missing sync ops are path-based one-shot
libc wrappers.

## Decision

Nine additions, all throwing the shared fs error on failure:
`lstatSync` (statSync's lstat twin, same `statLayout()` offsets),
`realpathSync`, `mkdtempSync` (appends the six `X`s itself, per Node),
`symlinkSync`, `readlinkSync` (4096-byte cap), `chmodSync`,
`truncateSync`, `accessSync` (mode defaults to F_OK), and `rmSync` with
literal `{recursive, force}` options — recursive removal walks
opendir/readdir in the runtime (children recursed blindly; `remove(3)`
handles non-dirs, `rmdir` finishes each emptied directory), force
swallows a missing path. Stats also gained `isSymbolicLink()`
(S_IFLNK). The three string-returning ops wrap their raw C-string
results into length-prefixed header strings — returning the bare
pointer made `.length`/concat read garbage (hit during this change).
Duplicate libc decls (`access`, `rmdir`) are owned by their original
ensure functions.

## Verification

Mac. `tests/fs_test.go` `TestE2EFsPathOps` (all nine + isSymbolicLink +
recursive rm of a nested tree + force + throw) passes; fs batch green;
`examples/fs/fs.ts` extended and re-run (which caught the rmdir
redefinition when rmdirSync and rmSync share a program).
