# ADR-01583: Stack overflow throws a RangeError

- **Relations**: Implements TDD-00249
- **Date**: 2026-10-11

## Context

Node's `test-fs-readdir-stack-overflow.js` recurses through
`fs.readdirSync('.')` and expects `RangeError: Maximum call stack size
exceeded`. Compiled, it allocated until the machine ran out of memory: 10 GB
on the Mac, the whole 7 GB container on Linux arm64. That stopped the
macOS and Linux arm64 node conformance runs.

## Investigation

In a 3 GB arm64 container:

- `function recurse() { n++; recurse() }` never ended: `clang -O2` turned
  the self-call in tail position into a loop.
- With `fs.readdirSync('.')` in the body, every iteration kept a new
  listing, and memory ran out instead.

The only overflow check was `__kml_push_jmpbuf` in
`codegen/llvm/jmpstacksrc/jmpstack.c`, which counts nested `try` frames.
A recursion that does grow the stack died with SIGSEGV. Task fiber stacks
(`tasksrc/task.c`, 256 KB) were malloc'd with no guard page, so an
overflow there would write over the heap.

## Decision

As designed in TDD-00249, with one change. The handler does not compare
the fault address with the main thread's recorded stack bounds. It
compares it with the interrupted stack pointer from the signal context. An
overflow faults at a store into the frame being built: up to 64 KB below
the stack pointer, or within 1 MB above it. That covers every stack the
thread runs, main or fiber, with no per-stack bookkeeping at the 60-odd
context switches.

- `markNoTail` (`runtime_stackguard.go`) makes every call in the module
  `notail` on the finished IR text in `EmitProgram`.
- `main` first calls `__kml_stack_guard_init(throwFn, msg)`. `throwFn` is
  `@__kml_throw_range_error` when the program has a throw path, null
  otherwise. Then the handler prints the error and exits 1 itself.
- `stackguardsrc/stackguard.c` installs a 256 KB alternate signal stack
  (a mapping, so `-mm=gc` never frees it) and a SIGSEGV/SIGBUS handler
  with `SA_ONSTACK | SA_NODEFER`.
- The main thread overflows at Node's default `--stack-size`, 984 KB below
  `main`'s frame. On macOS the main stack is mapped in full, and the
  handler protects one page there. On Linux the stack grows on demand, so
  the handler maps a PROT_NONE page there (`MAP_FIXED_NOREPLACE`, never
  over an existing mapping). The kernel keeps its 1 MB guard gap above
  that page, so the Linux limit is about 2 MB.
- Async task stacks get a PROT_NONE guard page below the range handed to
  `makecontext`: `__kml_fiber_stack_alloc` in the default memory mode,
  `__kml_task_stack_alloc` in `gcshim.c` under `-mm=gc`. It sits below
  the range because macOS `makecontext` faults on a stack range holding a
  PROT_NONE page.

## Implementation notes

The handler is not installed under a sanitizer, which has its own
overflow report. On Windows `main` does not call it (TDD-00249 Stage 3).
On a host whose signal context the handler does not know (neither
x86-64 nor arm64), the stack pointer reads 0 and every fault keeps the
default action.

## Side effects discovered

- At the native 8 MB, the readdir test passed 3 GB before overflowing in a
  directory of 48 entries: the default memory mode frees none of the
  listings, and 8 MB holds tens of thousands of frames. With the 984 KB
  limit it peaks at 380 MB on macOS, and 875 MB on Linux arm64.
- Native frames are smaller than V8's: `function r() { n++; r() }`
  overflows after 62,006 calls on macOS and 128,463 on Linux arm64, against
  Node's 10,356.
- Generator stacks (malloc'd in `emit_generators.go`), HTTP connection
  fibers (`loopsrc/loop.c`) and goroutines (`klainsyncsrc/klainsync.c`)
  still have no guard page. Recursion there runs past the stack as before
  (TDD-00249 Stage 2).
- Worker threads have no alternate signal stack. An overflow there still
  ends the process.

## Verification

Mac (arm64), new tests in `tests/stack_overflow_test.go`:

- `TestE2EStackOverflowCaught`: self, mutual and method recursion are
  caught, twice, and the program continues.
- `TestE2EStackOverflowUncaught`: exit code 1.
- `TestE2EStackOverflowReaddir`: the Node test's shape.
- `TestE2EStackOverflowInAsyncTask`: on a task fiber, after an await.
