# ADR-01649: noUnusedLocals and noUnusedParameters

- **Relations**: Implements [TDD-00230](../../tdd/TDD-00230.md) (P2.7, the strict lane is TypeScript's)
- **Date**: 2026-10-16

## Context

The strict lane rejects what tsc rejects (TDD-00230 P2.7), but two of
TypeScript's most used checks, `noUnusedLocals` and `noUnusedParameters`,
had no counterpart: TS6133 and its group forms were never reported, and the
TS conformance harness compiled every case without the options its
`// @noUnusedLocals: true` directives turn on. 179 corpus cases use them;
tsc rejects 141.

## Investigation

The checker runs on the merged program (`resolver.TypeCheck`), where the
resolver has already dropped the imports and unwrapped the exports
(`resolver.go`, `unwrap`), and a multi-declarator `export const a = 1, b = 2`
reaches the binder as a plain block. None of an unused check's inputs —
which names a file imports, which it exports, its names as written —
survives the merge. Each file is, however, bound alone before mangling
(`binder.BindWith(info.prog, …)` in the resolver's per-file loop), with its
imports, `export` wrappers and original names intact.

The binder records every value reference with its scope and whether it
stores without reading (`written`). Type names are resolved by the checker,
not the binder, by name from a scope (`resolveTypeName`, `lookupName`). The
binder declares no symbols for an interface's or a type alias's type
parameters, and a generic class's type parameters live in a scope the class
opens under tag 3, which `OpenedScope` does not return. Namespaces are
desugared to `N__kmlns_member` top-level names before binding.

tsc's rules, from its `checkUnusedIdentifiers`:

- A reference counts when it reads: `isWriteOnlyAccess` covers a plain
  store, and an increment or compound assignment whose value is discarded
  (an expression statement).
- A reference inside the declaration it names (a recursive function, an
  interface naming itself) does not count (self-reference locations:
  function, class, interface, enum, type alias).
- Exempt: exported declarations, a script's top-level declarations
  (globals), a catch variable, a parameter or type parameter starting with
  `_`, an `_`-prefixed array element, renamed object element, `for…in`/
  `for…of` variable or import, and an object-pattern element whose pattern
  ends in a rest (it removes its key from the rest).
- Groups: an import whose every name is unused is one TS6192; a variable
  statement whose every declarator is, TS6199; an object pattern (or a
  parameter's array pattern) whose every element is, TS6198; a type
  parameter list, TS6205. A one-member group reports the member.
- A class's private member (`private`, `#name`) nothing reads is TS6133, a
  `private` parameter property TS6138. A store to it does not read it
  unless it is a setter; a method reading itself does not count.
- Merged declarations (`class C<T>` and `interface C<T>`) share their type
  parameters.

## Decision

`checker.Unused` checks one file's binding under `UnusedOptions`, and the
resolver runs it in its per-file loop, before the merge, for every file not
in the builtin library, when either option is on. Its diagnostics from every
file are collected and reported together, as tsc reports every file.

The pass walks the file once:

- each identifier the binder resolved, unless write-only or discarded, uses
  its symbol; `new X` uses `NewTarget`; a class's `extends`/`implements`
  names use theirs;
- every type tree held by a node — a TS annotation's node, a type node or
  type member as written, a type parameter's constraint and default — uses
  the names it refers to, resolved from the walk's current scope (a generic
  class's type parameter scope for its members);
- inside a generic interface or type alias, a reference to one of its type
  parameter names is recorded for that declaration;
- a stack of self-reference locations filters uses of a declaration's own
  name from inside it.

Then each symbol of the file's own scopes is classified by its declaration
node and reported with tsc's code, position (destructured names now carry
their own, `ArrayPatternElem.Pos` and `DestructProp.Pos`) and grouping.
Module-level exportedness comes from the resolver's per-file `exported`
table and local `export { … }` lists.

`-no-unused-locals` and `-no-unused-parameters` set the two options (the CLI
drops them, with a warning, under `-compat=js`). The TS conformance harness
reads each case's `@noUnusedLocals`/`@noUnusedParameters` and passes them in
the strict lane; `tools/tsdiag` runs the pass on cases that set them.

## Implementation notes

- `binder/binder.go`: `References`, `WriteOnly`, `RefScope`.
- `checker/unused.go`: the pass. `forEachTypeNode` reaches type trees by
  reflection without entering statements or expressions (the child walk's).
- `diag/messages.go`: TS6133, TS6138, TS6192, TS6196, TS6198, TS6199,
  TS6205.
- `ast/nodes.go`, `parser/parser_stmts.go`: `Pos` on pattern elements.
- `resolver/resolver.go`: the per-file call; `sortDiags`.
- `options/options.go`, `main.go`, `README.md`: the options and flags.
- `tools/conformance`: `frontEndWith`, `tsCaseChecks`.
- `tools/runexamples`: `examples/types/unused_checks.ts` compiles with both
  flags.

A private member read through a computed key credits the names of the key's
declared string-literal type (`this[key]` with `key: "a" | "b"`); with any
other key every private member counts as read, so nothing is wrongly
reported.

## Side effects discovered

Not checked yet, listed as caveats on the Type System page: a namespace's
members (the desugared names lose their exportedness); type parameters of a
signature written inside a type; an unused import is reported at its
statement, where tsc points at the name.

- `tests/unused_checks_test.go`: `TestE2ENoUnusedLocals`,
  `TestE2ENoUnusedParameters`, `TestE2ENoUnusedGroups`,
  `TestE2ENoUnusedAcrossFiles`, `TestE2ENoUnusedOffByDefault` (Mac).
- `examples/types/unused_checks.ts` with both flags: output matches Node.
- `tools/tsdiag` over the whole TypeScript corpus (DeskMini): TS6133 184
  reported, 184 matching tsc's baselines; TS6138, TS6196, TS6198, TS6199
  all matching; no false positive of any of these codes.
