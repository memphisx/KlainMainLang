# ADR-01980: A constructor returning another object

- **Relations**: Implements TDD-00230 (P2.7); follows [ADR-01979](ADR-01979.md)
- **Date**: 2026-11-07

## Context

When a constructor returns an object, that object is the value of `new`,
and a subclass's `super()` makes it the subclass constructor's `this`.
Under TypeScript typing the checker refused both cases (90027, 90028),
because a binding of the class's type is read with the class's fixed
layout and the returned object has another. `-compat=js` compiled the
first case. In the second it read the allocated instance instead of the
adopted one: `new B(true).a` gave the base's default and `b` was missing.

## Decision

- A class whose constructor may return an object that is not an instance
  of the class is a foreign-constructor class (`Checker.CtorReturnsForeign`).
  So is every class extending one.
- An instance of a foreign-constructor class is held as `any`, in both
  lanes. Its member reads and method calls go through the dynamic paths
  that `-compat=js` already uses: `new` yields the returned object or the
  boxed instance, and `super()` binds `this` to whichever one it gets.
- Diagnostics 90027 and 90028 are deleted.

## Consequences

- Covered by `TestE2ECtorReturnOverride`, which matches Node.
- Reading an instance of such a class is dynamic, so it is slower than a
  plain instance's direct field read. This is a documented performance
  gap.
