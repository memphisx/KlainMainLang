# ADR-01238: `events` is a TypeScript module

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-09-29

## Context

`EventEmitter` was code-generated. A class extending it carried a hidden
listener-map field. Its methods were hand-written dispatch, not class
methods, so:

- `once` never went through the stream's own `on`: a Readable's
  `once('data')` didn't resume it;
- an emitter's methods weren't found through `any`: `process.stdin.once`
  threw "once is not a function".

## Decision

- **`lib/node/events.ts`** is Node v24's `lib/events.js`:
  - listeners are stored as Node stores them: `_events`, a null-prototype
    object, holding one function or an array per event;
  - `on`, `addListener`, `prependListener`, `once`, `prependOnceListener`
    (a wrapper carrying `.listener`), `off`/`removeListener`,
    `removeAllListeners`, `emit` with `this` as the emitter;
  - `'newListener'`/`'removeListener'`, the MaxListenersExceededWarning,
    an unhandled `'error'` (the Error itself, else `ERR_UNHANDLED_ERROR`),
    `errorMonitor`, `captureRejections`;
  - `listeners`, `rawListeners`, `listenerCount(type, fn?)`, `eventNames`;
  - the statics and module functions `once` (with `signal`), `on` (an async
    iterator), `getEventListeners`, `getMaxListeners`, `setMaxListeners`,
    `listenerCount`;
  - the default export is `EventEmitter`.
- **Deleted:** the code-generated EventEmitter (`emit_eventemitter.go`,
  `runtime_eventemitter.go`, `emit_events_helpers.go`), its AST node,
  parser/sema/resolver special cases, class-layout field and type flags,
  and `declare module "events"`.
- **What the module needed from the compiler:**
  - static accessors;
  - a class whose type parameters no member uses compiles as an ordinary
    class, so `extends EventEmitter<Events>` and `new EventEmitter<X>()`
    erase their type arguments (`eraseTypeOnlyGenerics`);
  - `export default X;` naming a class or function is that declaration;
  - a call of an `any` field holding a function (`this.handler(e)`), with
    the instance as `this`;
  - spreading an `any` holding an array (a dynamic function's rest
    parameter);
  - `IteratorResult`/`IteratorYieldResult`/`IteratorReturnResult`
    declared in `lib/es.d.ts`.
- **Listener slots** (`(...args: any[]) => void`) now take:
  - a `this: T` function, through its box, so a dynamic call's receiver
    reaches it;
  - a closure over a dynamic function's thunk, which boxes back to that
    function (`__kml_fn_thunk_box`);
  - optional and nullable scalar parameters, spread from the rest tail;
  - any conversion the direct adapter does not take goes through the box
    (the dynamic ABI converts every parameter kind), never as a raw header.

- **Listeners are declared `(...args: any[]) => any`**, where
  @types/node has `=> void`: the closure adapter to a `void` slot drops the
  return value, and `captureRejections` needs an async listener's promise.
  Callers' typing is the same, since any function is assignable to both.

## Side effects discovered

- The typed event map (`EventEmitter<{ data: [string] }>`) is not checked:
  an undeclared event compiles (BACKLOG 115).
- `new EventEmitter(1)` is not TS2559 (BACKLOG 116).
- A generic builtin-declared type in codegen (BACKLOG 114); the module's
  iterator returns `Promise<any>`.

## Verification

Mac (Apple Silicon), against Node v24.19: the EventEmitter, events.once/on,
compat-js `this` and child_process suites; the full test suite.
