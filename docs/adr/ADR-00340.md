# ADR-00340: Asynchronous `fs` — callback and Promise (`fs/promises`) forms

- **Relations**: Implements TDD-00107; reuses ADR-00023/00027/00094 (sync fs), the settled-promise plumbing (dns.promises/crypto precedent), and the `setjmp` catch primitive
- **Date**: 2026-08-24

## Context

`fs` was synchronous only — the async row was the last ❌ on
[FILE-SYSTEM.md](../status/FILE-SYSTEM.md), on the priority path (file I/O).
TDD-00107 scoped both async shapes Node offers over the same operations: the
callback form (`fs.readFile(path, cb)`) and the Promise form
(`fs.promises.readFile` / `import from 'fs/promises'`).

## Decision

Per TDD-00107, ship both forms over the full sync operation set (`readFile`,
`writeFile`, `appendFile`, `unlink`, `mkdir`, `rmdir`, `rename`, `copyFile`,
`readdir`).

**Honest semantics.** No thread pool exists, so the underlying I/O is the
existing *blocking* syscall run inline; only *delivery* is async — the callback
fires right after the operation, the Promise is returned already settled
(immediately awaitable). Same posture as `dns.promises.lookup`, Web Crypto, and
every "callback fires synchronously from the dispatch" event source. The value is
API-shape compatibility (existing callback/`async`-`await` code compiles and
runs), not concurrency.

**Reuse over reimplementation.** The sync helpers already signal failure by
*throwing* (`@__kml_fs_throw` → `@__kml_throw`). Rather than add non-throwing
runtime variants, the async wrappers run each existing `emitFs<Op>Sync` emitter
verbatim as the body of the compiler's own `setjmp`/`@__kml_get_thrown` catch
scaffold (the exact mechanism `emitTry` uses) and re-surface a caught `Error` as
the `err` callback argument / a rejected Promise. So the async and sync paths
cannot diverge in I/O behavior, and no new C-level code was written.

## Implementation notes

- `emit_fs_async.go`: a `fsAsyncOps()` registry (sync emitter, result type, arg
  count, whether the callback gets data); `emitFsGuarded` is the shared
  setjmp/catch scaffold; `emitFsAsyncCallback` delivers `(err[, data])` via
  `resolveCallbackWithHints`/`emitCBCall`; `emitFsAsyncPromise` builds a settled
  task Promise via `emitAllocSettledPromise`/`storePromiseValue`/
  `emitSetPromiseState`, rejecting with `emitAsyncGenRejectPromise`. A void
  mutate op stores nothing (the await path returns void without loading the value
  slot); `readdir`'s `string[]` rides `storePromiseValue`'s existing `IsArray`
  `{ptr,i64}` split.
- `emit_call.go`: the `fs__kml_builtin` switch gained a default routing an async
  op name to the callback form; a two-level `fs.promises.<op>` chain and the
  `fspromises__kml_builtin.<op>` marker route the Promise form.
- `emit_exprs_types.go`: call-type inference — the callback form is `void`, the
  Promise form is `PromiseOf(<result>)` (`PromiseTask`).
- `resolver/virtual_modules.go`: the async member names added to `fs` (so
  `import { readFile } from 'fs'` works too), and a new `fs/promises` virtual
  module (marker `fspromises__kml_builtin`) with the nine ops.

## Side effects discovered

None. The setjmp catch nests correctly inside a user `try` (the jmpbuf is a
stack), and no tryL-computed SSA value is read after the merge, so `setjmp`'s
value-liveness rules hold — same as `emitTry`.

## Verification

- `tests/fs_async_test.go` (7 cases): callback round-trip (write→read→unlink),
  callback error-first (ENOENT), Promise `await` round-trip, Promise rejection
  caught in `try`/`catch`, `fs.promises.readdir`, the `fs/promises` named import,
  and the missing-callback rejection. All over a real temp dir.
- Manual: `.then()` on the Promise form; binary `writeFile` (Uint8Array) through
  the async callback; `mkdir`/`copyFile`/`rename`/`rmdir`.
- `examples/fs_async/fs_async.ts` builds and runs (macOS/arm64); clean under
  `make examples`.
- `go build` / `go vet` clean.
- Machine: verified on Mac (arm64); platform-independent (POSIX syscalls, same as
  the sync fs helpers).
