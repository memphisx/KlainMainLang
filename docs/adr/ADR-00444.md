# ADR-00444: docs/status flipped to a JSON source of truth with generated Markdown

- **Relations**: Implements TDD-00145
- **Date**: 2026-08-28

## Context

`docs/status/` was ~30 hand-edited Markdown pages plus the aggregate README,
with every Coverage/Strict fraction, percentage, and README section total typed
by hand. The failure modes [TDD-00145](../tdd/TDD-00145.md) catalogued —
hand-maintained numbers drifting, the load-bearing-but-unvalidated table
format, and the caveat duplication against the website reference JSON — were
all live. The TDD's plan: build a Markdown→JSON importer and a JSON→Markdown
generator, prove a **byte-identical round-trip** across the whole corpus, and
only then flip the source of truth to JSON.

## Investigation

The importer was built strict (any unmodeled construct is an error, never a
guess) and phased exactly as the TDD staged it: one representative page
(STRING-METHODS), then the full detail corpus, then the README. Running it as
the corpus lint it inherently is surfaced real drift in the committed pages —
every one fixed on the page before its shape was declared clean:

- **Stale derived numbers**: NODE-CORE-MODULES claimed Strict 1/16 where the
  rows derive 2/16; the README's Web Platform section total said 55/55 where
  the rows sum 57/57, and the Node.js section 90/93 vs the real 93/96 (both
  undercounts — categories grew without the totals following). The Node
  correction rippled to the README category row, the website's
  `nodecore.json` coverage, and the site's headline figures in
  `website/src/lib/content.js`.
- **Tilde-styling violations**: exact percentages written with a tilde
  (`21/30 (~70%)`, `1/2 (~50%)`, `7/14 (~50%)`, and three README cells). The
  convention is formalized as: `p = round(100·n/d)` half-away-from-zero;
  render `~p%` iff `100·n/d` is not an integer.
- **Malformed rows**: nine table rows across five pages — missing trailing
  Notes cells (NODE-CORE-MODULES `assert`, LANGUAGE-CONSTRUCTS overloads,
  four TYPE-SYSTEM rows), an extra `|` splitting one Notes cell into a fifth
  column (NODE-CORE-MODULES `test`), and double-space empty cells (JSDOC).

The TDD's fixed-slot schema sketch (intro / tables / known-limitations) did
not survive the corpus: JSDOC interleaves a second blockquote between the
coverage lines and the `Format:` line, several pages put prose after it, and
MEMORY-MANAGEMENT ends in an arbitrary prose section. The shipped schema is an
**ordered segment list** instead — divergence recorded here per the TDD's own
rule, its Design section untouched.

## Decision

A Go tool, `cmd/statusgen`, per the TDD's tooling recommendation. Source of
truth: `docs/status/data/<area>.json` (one per detail page) + `_index.json`
(the README).

Schema (see `cmd/statusgen/schema.go`, `index.go`): a page is a title plus
ordered segments — verbatim Markdown `block`s, a derived `coverage` segment
(styles `standard` / `multiCategory`; pages with bespoke coverage wording
simply have none and keep the wording as a block), and `table`s. A `## `
heading directly above a table attaches to it and doubles as the category
name in multi-category coverage lines; a parity-uncounted table (JSDOC's
extensions) is one no coverage line names. Cells store bullet fragments
(joined `<br>• `) with a per-cell plain flag for the 3-column pages. The
index adds `sectionTotal` (summed from the following category table) and
`categoryTable` segments whose Coverage/Strict cells derive from the linked
page — with authored overrides only for genuinely non-derivable cells
(Memory's `2/3 modes`, Compatibility's link-less row, Webview's Strict, whose
table has no Caveats column). No fraction, percentage, or total is ever
stored.

Commands: `generate` (data → pages, `make status`), `check` (diff-only CI
guard, `make status-check`, wired into the release workflow before the test
suite), `export` (Markdown → data re-derivation), and the retained
`import`/`gen`/`roundtrip` (`make status-roundtrip`) as the fuzz/re-derivation
path the TDD says to keep at least through the flip.

Deliberately deferred from this flip: switching the website reference
projection to derive `badge`/`differences[]` from the status source
(TDD-00145's reconciliation section). That changes public-facing wording, and
the reference `differences` content is due an editorial review first; the
existing `check-reference.mjs` guard keeps working unchanged against the now
generated pages.

## Implementation notes

- `cmd/statusgen/{schema,import,gen,index,data,main}.go`; `Makefile` targets
  `status`/`status-check`/`status-roundtrip`; `.github/workflows/release.yml`
  gains a `make status-check` step.
- The generator joins segments with exactly one blank line and ends with one
  newline; the importer rejects double blanks, so spacing is bijective.
- `\|` escapes are never unescaped — cells are stored verbatim, so escaping
  survives the round-trip by construction.
- Percent formatting, the multi-category `·`-separated lines with the
  trailing Strict-definition sentence, and the `n/d, p%` README cells are the
  determinism pitfalls the TDD predicted; each is a single shared formatting
  function.
- Footer `*Last updated:*` lines are ordinary verbatim blocks — preserved,
  never auto-bumped, matching the standing rule.

## Side effects discovered

- The corpus fixes above (stale numbers, tildes, malformed rows) — all fixed
  in this change, none tracked forward.
- The reference-projection derivation and the `differences[]` editorial
  review remain open on [TDD-00145](../tdd/TDD-00145.md)'s reconciliation
  section, plus its open question on structuring WEB-CRYPTO's shared-caveats
  block (kept verbatim for now).

## Verification

On the Mac: `make status-roundtrip` — all 33 files (32 detail pages + README)
round-trip byte-identically; `statusgen export` then `statusgen check` — 33
pages match `data/`; an `_index.json` edit + `make status` regenerates only
the README and `check` returns green; `go vet` clean; the website reference
guard passes (32 surfaces, 0 warnings). `make conformance-node` unchanged, as
expected for docs tooling.
