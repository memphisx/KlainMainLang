# TDD-00149: Generate the ADR & TDD index READMEs (and the status backlog) from the record files

- **Status**: Implemented
- **Date**: 2026-08-29

## Context

`docs/adr/README.md` and `docs/tdd/README.md` each carry a hand-maintained
Index table — one row per record file — and `docs/status/README.md` carries a
third hand-maintained table (the "Design Documents (TDDs)" backlog) that is a
filtered restatement of the TDD index. All three are edited by hand, in lockstep
with the record files, and nothing enforces that they agree.

They don't agree. A concrete drift was just found and hand-fixed: the status
backlog listed five TDDs whose own files were `Implemented`/`Superseded`, even
though that table's own preamble promises "completed and superseded ones are
omitted." Systematic scans surface more of the same class:

- `TDD-00046`'s file says `Partially Implemented`; the TDD index still says
  `Not Started`.
- 8 TDD files append prose to the Status line (`Implemented — …`,
  `Implemented (Stages 1–4)`) that the convention ([TEMPLATE.md](TEMPLATE.md))
  says must not be there.
- 37 of 148 TDD index Title cells diverge from the file `#` heading.
- Several ADR index `Relations` cells diverge from — and in at least
  [ADR-00406](../adr/ADR-00406.md) factually contradict — the ADR file's own
  `Relations` bullet.

These are not one-off mistakes; they are the expected outcome of keeping the
same fact in two hand-edited places. The fix is to make each index a *generated
projection* of the record files, the way `docs/status/*.md` is already a
generated projection of `docs/status/data/*.json` ([TDD-00145](TDD-00145.md)),
and to auto-sync the website reference coverage numbers that go stale for the
same reason.

## Design

A corpus analysis (three read-only passes over the 148 TDDs, 508 ADRs, and the
existing generators) established what is and isn't recoverable from the record
files. The design follows that evidence rather than wishing the files were more
structured than they are.

### Source-of-truth per column

**ADR index (`# | Title | Relations`):**
- **Title** — the ADR `#` heading. 508/508 clean, verbatim. Generated.
- **Relations (forward)** — the ADR file's own `- **Relations**:` bullet is
  authoritative. The generator joins line-wraps, linkifies bare/backticked refs
  (`Extends ADR-00083` → `Extends [ADR-00083](ADR-00083.md)`), and emits it.
- **Relations (reverse)** — `Extended by` / `Superseded by` / `Implemented by`
  back-references are **auto-derived** by scanning the whole corpus (if B's
  Relations says `Extends ADR-A`, A's row gains `Extended by [ADR-B]`). This
  removes the manual back-reference bookkeeping entirely and is strictly more
  correct than today's partial hand-maintenance.

**TDD index (`# | Title | Status | Related ADRs | Notes`):**
- **Status** — the file's `- **Status**:` line, *leading enum word only*
  (148/148 parse cleanly). Regeneration corrects the `TDD-00046` drift for free.
- **Title** — the file `#` heading (present in all 148).
- **Related ADRs** — **not stored in TDD files**; derived by scanning every
  `TDD-NNNNN` token inside ADR `Relations` bullets (238 ADRs carry them). Fully
  automatic, zero maintenance. Verb-agnostic: capture all `TDD-NNNNN` tokens,
  not just `Implements`.
- **Notes** — editorial; 124/126 exist only in the current table with no
  machine source. Given a structured home in the TDD file (see below).

**Status backlog in `docs/status/README.md`** — a derived segment that reads the
same parsed TDD data, filters to not-yet-done statuses (`Not Started`,
`In Progress`, `Partially Implemented`), and renders `# | Status | Notes`. A
shipped/superseded TDD drops out automatically the moment its file's Status
flips — the drift class is structurally eliminated.

### The one required format contract

Two facts have no machine-readable home in the record files today and must be
given one, or they can't be generated without loss:

1. **TDD Notes** — add an optional `- **Notes**: <one line>` header field to the
   TDD file, migrated one-time from the current index. The file becomes the
   single source; the convention ([TEMPLATE.md](TEMPLATE.md)) is updated to say
   Notes lives in the file, not the index table.
2. **Superseded-by pointer** — 3 of 5 superseded TDDs record their successor
   only in the index Notes. Standardize `- **Relations**: Superseded by
   [TDD-NNNNN]` in the file (the format 2 of the 5 already use), so both the
   status word and the successor are file-sourced.

Everything else (Related ADRs, ADR reverse-relations) is *derived*, not stored —
no new fields, no per-file maintenance.

### One-time reconciliation (a migration, not ongoing work)

Before the generators can own these files, a one-time pass reconciles the
current hand-authored content into the files so regeneration is loss-free:

- Move the 8 TDDs' trailing Status prose into their `Notes`/prose.
- Reconcile the 37 divergent Titles: apply the index's editorial polish
  (backticks, added qualifiers) *into the file `#` heading*, making the heading
  the canonical formatted title, so regeneration reproduces it.
- Migrate the 126 index Notes into per-file `- **Notes**:` fields.
- Resolve the divergent ADR `Relations` (incl. the ADR-00406 factual
  contradiction) by deciding which side is correct and fixing the file bullet.

This pass is human-reviewed (some cases are judgment calls); after it, the files
are authoritative and the READMEs are pure output.

### Where it plugs in

The existing Go generator `cmd/statusgen/` is the home (it already owns
`docs/status/`), extended with:
- a shared TDD/ADR record loader (parse header fields + `#` heading);
- `generate`/`check` also emit/verify `docs/adr/README.md` and
  `docs/tdd/README.md` (preamble prose preserved as a verbatim header block;
  only the Index table is generated), stamped with the same do-not-edit banner;
- the status-index TDD-backlog block becomes a derived `tddBacklog` segment
  reading the shared TDD data.

The website reference checker (`website/scripts/check-reference.mjs`,
`make reference-check`) gains a `--sync` mode + `make reference-sync` target: it
already parses each status page's `loose`/`strict` counts to *check* them, so
sync writes them back (and computes the currently-unchecked `loosePct`/
`strictPct`). Ends the stale-count hand-edit.

### Rejected alternatives

- **Fully regenerate ADR Relations from the files, blind.** Rejected: the cells
  are curated and sometimes contradict the files; blind regeneration loses
  intent and propagates the wrong side of a contradiction. Forward-from-file +
  derived-reverse keeps curation where it exists and only *adds* correctness.
- **Notes as a sidecar JSON keyed by TDD number.** Rejected: re-introduces a
  second hand-maintained file — the exact problem being removed. The note
  belongs with the record it describes.
- **Derive Related-ADRs from a new field in each TDD.** Rejected: redundant with
  the ADR `Relations` that already exists and is the project's canonical
  direction; would need 148 files hand-updated and kept in sync.

## Open questions

- Reverse-relation phrasing to emit (`Extended by` vs `Extensions:`), and
  whether to also derive `Implemented by [ADR-N]` onto TDD rows (the TDD index's
  Related-ADRs column is exactly that set, so it may be redundant to show on
  both sides).
- Whether the ADR README's 116 no-Relations rows render an empty cell or a `—`
  (match current output, whichever it is, for a clean first round-trip).
