# ADR-01122: The checker reports TypeScript's type errors, measured against TypeScript's baselines

- **Relations**: `Implements TDD-00230` (Phase 2, P2.7); `Extends ADR-01111`, `ADR-01112`, `ADR-01117`
- **Date**: 2026-09-24

## Context

[TDD-00230](../tdd/TDD-00230.md) P2.7: diagnostics own the user errors. A
program the checker accepts must compile. Codegen reports only internal
errors, and every clean rejection of user code becomes a checker
diagnostic with a stable code, or a supported feature.

Until this step the checker answered types for the shadow harness and
reported nothing. The step needs two things:
- a checking pass that reports TypeScript's errors;
- a way to tell a real error from the checker's own gaps before any user
  sees one.

## Investigation

- **TypeScript's test corpus** is local (`.ts-tests`, fetched by
  `tools/conformance/fetch.sh`): 11,874 cases, and 6,131 `*.errors.txt`
  baselines giving each error's line, column and code.
  - The most frequent codes: TS2304 (a missing name), TS2322 (not
    assignable), TS2362, TS2363 and TS2365 (operator operands), TS2339
    (a missing property), TS2345 (argument), TS2554 (argument count).
- **The harness strips the `// @option` lines** before compiling, and then
  the blank lines left at the top, so baseline line numbers are shifted from
  the source file.
- **Most cases run without strictNullChecks.** There `a && b` has the right
  operand's type, and null and undefined go anywhere. This compiler is
  strict-only.
- **tsc 5.6.3 positions**:
  - a declaration's error is at its name, and an assignment's at its left
    side;
  - a `return`'s is at the keyword;
  - an argument's is at the argument (TS2345);
  - too few arguments is at the callee, and too many at the first extra
    one (TS2554); a rest signature uses TS2555;
  - an object or array literal is elaborated: the error lands on the
    property or element that does not fit, and only when the whole is not
    assignable;
  - `&`, `|` and `^` on two booleans is TS2447, not TS2362/TS2363.

## Decision

- **`Checker.Check()`** walks the program once and reports, as `diag`
  diagnostics with TypeScript's codes and positions:
  - TS2322 on typed declarations, assignments, returns, parameter defaults
    and class field initialisers;
  - TS2345, TS2554 and TS2555 on calls to a function type the checker models
    whole (no type parameters, no overloads, no spread argument, and no
    callee with several declarations);
  - TS2362, TS2363 and TS2365 on operators.
- **One relation, three answers.** `assignableTo` (`checker/relate.go`)
  answers yes, no or maybe; only a definite no is reported. Overload
  resolution uses the same relation, taking maybe as a fit, and a missing
  property as a no (TS2741 is not reported yet).
- **Type facts the checker lacked**, found through the false positives, now
  follow TypeScript:
  - **Literals:**
    - `-1` and `+1` are literal types, and `1e999` is `Infinity`;
    - `let x = undefined` and `let x = null` evolve like `let x;`;
    - `unknown` is assignable to `{} | null | undefined`.
  - **Function expressions and arrows:**
    - an unreachable end with no `return` gives `never`;
    - no value returned where the context expects `undefined` gives
      `undefined`;
    - a literal is kept when the contextual return type has literal
      members.
    - A function relation with a rest or `void` parameter is maybe.
  - **Contextual types** reach an object literal's property values
    (`{ set: (d = "R") => … }` against an interface), and `e satisfies T`
    types `e` in `T`'s context.
  - **`as const` and `satisfies`**, which the parser erases, are recorded
    in `Program.Assertions`, which codegen never reads. Under `as const`,
    literals keep their types, array literals are tuples, and a
    const-asserted literal never widens.
  - **Narrowing:**
    - entering a `switch` clause means no earlier case matched (a repeated
      case is `never`);
    - `switch (true)` narrows by each case expression;
    - `typeof x === "symbol"` is handled;
    - `boolean` narrows as `true | false`;
    - a declared literal type narrows;
    - a destructured property is the narrowed type of the path it reads;
    - a union already narrowed to one member keeps discriminating by a
      literal property.
  - **Assertion calls:** the binder makes a flow node after every call
    through a dotted name, in any expression position, as TypeScript binds
    it. `(assert(x), x)` narrows.
- **`tools/tsdiag`** is the measurement:
  - It checks every single-file case and matches each diagnostic to the
    baseline by code and harness line.
  - Strict cases are compared on every code; the others only on the codes
    whose rules do not depend on strictNullChecks (TS2362, TS2363, TS2365,
    TS2554, TS2555).
  - A sloppy script (not strict, not a module) is bound with Annex B.
  - It honours `@ts-ignore`, `@ts-expect-error` and `@ts-nocheck`, and
    skips multi-file, multi-configuration, `@noCheck` and `@pretty` cases.
  - `-roots examples,apps` also checks this project's own programs, where
    every diagnostic is listed.
- **Three examples were not valid TypeScript** and now are, each keeping
  what it shows. tsc 5.6.3 `--strict` rejected each as the checker did.
  - `examples/arrays/arrays.ts`: a holey array literal is typed
    `(number | undefined)[]`.
  - `examples/basics/arguments_object.ts`: `sum` has an overload signature
    with a rest parameter, so its extra arguments are legal and still read
    through `arguments`.
  - `examples/types/unions.ts`: the arrow's return type is corrected, and
    so is a stale output comment (`// 1` for `true`).
- **When the errors reach users:** on the strict lane, from this batch on
  ([ADR-01123](ADR-01123.md)).

## Verification

All on macOS arm64 (M4):

- `go test ./checker ./binder ./parser ./resolver`. `TestCheck` holds each
  code, position and non-error above, from tsc 5.6.3 `--strict`.
- `tools/tsdiag -roots examples,apps` over 6,055 single-file cases:
  - 731 diagnostics, and 729 match a baseline error: TS2322 28/28, TS2345
    8/8, TS2362 321/321, TS2363 298/298, TS2365 22/22, TS2554 47/49, TS2555
    5/5.
  - The two mismatches are `blockScopedSameNameFunctionDeclarationES5/ES6.ts`:
    sloppy scripts whose block functions Annex B hoists, which the binder
    does not model (BACKLOG §0 item 30). The strict lane never meets them.
  - The project's own examples and apps: 0 diagnostics.
- Shadow report over the examples and apps: 471 disagreements, down from
  472. The one that went is an `i64`-versus-`double` identifier row
  (ADR-01111's representation class) in an example this step edited.
- **Gates for this batch (ADR-01120 to ADR-01123)**, all on the switched-on
  strict lane:
  - `make examples`: 357 of 358. `examples/http/client_server.ts` hung. Its
    IR is byte-identical to the previous build's, and run on its own it hung
    once in three: the intermittent hang in BACKLOG §0 item 1.
  - `make test-par`: pass apart from the four `-mm=gc` macOS segfaults
    (BACKLOG §0 item 1d), identical at HEAD.
  - Test262 conformance: see ADR-01123.
  - TypeScript oracle (`make conformance-ts`), agreement with tsc's
    accept/reject verdict: strict lane 6,207 → 6,300 of 11,034, js lane
    6,223 → 6,311. The js lane's gain comes from this batch's parser and
    binder fixes (ADR-01120); the strict lane's from both those fixes and
    the checker.
