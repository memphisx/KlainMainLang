# ADR-00544: console.time()/timeEnd() per-label backing map

- **Relations**: Extends ADR-00029
- **Date**: 2026-09-01

## Context

`console.time(label)`/`console.timeEnd(label)` shared a single process-wide
monotonic-time slot (`@__kml_console_time_start`). Calling `time()` with a
second label while a first was running overwrote the one slot, so nested or
concurrent timers reported the wrong elapsed time — a deviation from real
Node, which tracks each label independently. This was disclosed as a caveat
on the console status page.

## Investigation

`emitConsoleCount()`/`emitConsoleCountReset()` already solved the exact
per-label problem for `console.count()` by lazily creating a
`Map<string, number>` (`__kml_map_str_*` runtime helpers) keyed by label. The
time slot only needed to store a start time (a `double`) rather than a count
(`i64`); the map helpers store `i64` values, so a `bitcast double→i64` on
store and `i64→double` on load reuses the same machinery losslessly.

## Decision

Replace the single `@__kml_console_time_start` double global with a lazily
created `@__kml_console_time_map` (`ptr`, same shape as
`@__kml_console_count_map`). `console.time(label)` bit-casts
`__kml_performance_now()` to `i64` and stores it under the label;
`console.timeEnd(label)` reads it back, bit-casts to `double`, and subtracts
from the current time. Default label remains `"default"`.

## Implementation notes

- `ensureConsoleTimer` (runtime_misc.go) now declares the map global and calls
  `ensureMapStrHelpers` instead of declaring the double slot.
- `emitConsoleTimeMapEnsure` (emit_call_console.go) mirrors
  `emitConsoleCountMapEnsure` — the alloca+store-per-branch+load-after-merge
  shape for lazy creation.
- The bit-cast round-trip is exact: no double value is altered by moving
  through an `i64` map slot.

## Side effects discovered

None.

## Verification

`TestE2EConsoleTimePerLabel` (two concurrently-running labels each print their
own prefix and elapsed) plus the existing `TestE2EConsoleTimeEnd`/count tests
pass. Manual repro with nested `outer`/`inner` labels shows the outer timer's
elapsed strictly exceeds the inner's, confirming independent tracking. Built
and verified on Mac (Apple Silicon).
