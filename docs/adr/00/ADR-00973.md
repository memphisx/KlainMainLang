# ADR-00973: HTTP server `'error'` event / bind failure (TDD-00215 Stage 2)

- **Relations**: `Implements TDD-00215`
- **Date**: 2026-09-16

## Context

`http.createServer(...).on(event, listener)` recognized `'request'`, `'stream'`,
`'listening'`, `'upgrade'`, `'close'`, `'connection'`, and (Stage 1, ADR-00971)
`'clientError'`. Node's server-level `'error'` `(err)` event — fired on a bind
failure (`EADDRINUSE` when the port is taken, `EACCES` on a privileged port) —
was missing. Without it, a bind failure could only surface as an uncaught,
process-aborting error, so a program had no way to react to "port already in
use" the way every real Node server does.

## Investigation

`__kml_http_bind_and_listen` (`runtime_http.go`) already funnels both failure
edges — `failwithfd` (socket created, `bind`/`listen` failed) and `failnofd`
(`socket()` itself failed) — to `__kml_http_throw` followed by `unreachable`. The
event-loop accept path already treats `@__kml_listen_fd < 0` as "no listener"
(the `haslistener = icmp sge` guard the `http.close()` path relies on), so a bind
that returns `-1` needs no new accept-side guard: the reactor simply drains and
exits.

Building an `Error` and invoking a KML closure is codegen work (headered strings,
`buildErrorObjWithCode`, the `{fn,env}` closure ABI) that cannot be hand-written
inside the raw-IR `__kml_http_bind_and_listen` template. So the failure edges
call out to a codegen-emitted helper instead.

## Decision

A thread-local `@__kml_http_error_evt` global holds the registered listener,
mirroring `@__kml_http_clienterror_evt`. `server.on('error', fn)` stores the
closure header into it (`emit_http.go`).

`__kml_http_bind_and_listen`'s two failure edges now, **before** throwing,
capture `errno` (before `close()` can clobber it) and check the global:

- listener set → close the fd (on `failwithfd`), call
  `@__kml_http_fire_bind_error(errno)`, and `ret i32 -1`.
- listener null → the pre-existing `__kml_http_throw` + `unreachable` (behavior
  unchanged when no `'error'` listener is registered — Node parity).

`@__kml_http_fire_bind_error` (emitted via `emitStandaloneFunc`) builds a full
`errorObjType`: `.message` = `"listen <CODE>: <strerror>"` in a headered buffer,
`.code` = the bucketed errno name (`__kml_errno_code`), `.errno` = the negative
errno, then invokes the listener `fn(env, err)` synchronously.

Both `http.createServer(...).listen(...)` call sites branch on the returned fd:
`fd >= 0` runs the existing listen setup (fork / primary-or-extra registration /
`'listening'` fire / ready callback); `fd < 0` skips all of it (the listener has
already fired) and returns the server handle. `@__kml_listen_fd` stays `-1`, so
the reactor treats the failed server as "no listener".

### Scope / caveats (V1)

- **Any server, one shared global.** Unlike `'close'`/`'clientError'` (primary
  server only), `'error'` is accepted on any server — the canonical double-bind
  case registers it on the *second* (additional, suffixed) server. The listener
  lives in one shared `@__kml_http_error_evt`, so a program registering `'error'`
  on more than one server keeps only the last (documented caveat).
- **Bind failures only.** `'error'` covers `listen`-time failures. Runtime
  connection errors are not routed here.
- **Synchronous fire.** The listener runs synchronously at `listen()` time (same
  divergence the `'listening'` immediate-fire already documents), not on a later
  tick.
- **`.code` set.** `EADDRINUSE`/`EADDRNOTAVAIL`/`EACCES`/`ECONNREFUSED`/
  `ECONNRESET` were added to `__kml_errno_code` (the fs/exec errno→name table);
  an errno outside the table falls back to a headered `"UNKNOWN"` (never the raw
  un-headered `strerror` text, which would fault when `err.code` is
  concatenated).

## Consequences

`server.on('error', (err) => …)` catches `EADDRINUSE`/`EACCES` bind failures with
a Node-shaped `Error` (`.code`, `.message`, `.errno`) instead of aborting the
process; no listener preserves the throw. E2E tests
(`TestE2EHTTPServerErrorEventEADDRINUSE`, `…NoListenerThrows`) and
`examples/http/server_error_event.ts` cover both paths. Verified macOS arm64
(M4).
