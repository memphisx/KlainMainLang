# ADR-00927: `process.argv` is Node-shaped `[execPath, execPath, ...userArgs]`

- **Date**: 2026-09-13

## Context

`process.argv` on a compiled binary was the raw OS argv `[exePath, ...userArgs]`,
with only one entry before the user arguments. Node (and a Node
single-executable application) places the executable path at **both** `argv[0]`
and `argv[1]` — `[execPath, execPath, ...userArgs]` — so user arguments begin at
index 2 and `process.argv.slice(2)` is the user args. The compiler was therefore
off by one: `process.argv[2]` / `.slice(2)` dropped the first user argument
relative to Node. Found while adding `--run` (ADR-00926).

## Decision

`process.argv` is Node-shaped: the executable path appears at index 0 and 1,
user arguments at index 2+.

- A new `__kml_argv_node_shape(argc, hdr)` builds `[a[0], a[0], a[1..], NULL]`
  from the raw headerized argv at startup into separate globals
  `@__process_argv_ptr` / `@__process_argv_len` (length `argc+1`).
- The `process.argv` array read and `process.argv[i]` indexing consult those
  globals. The raw `@__argv_ptr` keeps its OS shape and remains what `execv` /
  `fork` / cluster / IPC use — a re-exec must pass the real OS argv, not the
  display shape.
- **Unified shape at the source.** `child_process.fork` previously pre-built its
  child's argv as `[exe, exe, ...args]` (compensating for the old pass-through);
  it now spawns the natural `[exe, ...args]`, and the child's own startup
  transform adds the `argv[1]` duplication. So every process — top-level, a
  plain `spawn` of the binary, a `fork` child, a cluster worker (which inherits
  the master's raw argv) — gets the identical Node shape from one code path, and
  a forked child's extra args still land at `process.argv[2]`.

## Verification

- `TestE2EProcessArgv` and `TestE2EProcessArgvNonASCII` updated to the Node shape
  (length 4, user args at `argv[2]`/`argv[3]`) — they had encoded the old
  one-prefix convention.
- Fork / cluster / child-process / IPC / process test lanes green — self-fork
  `process.argv[2]` child-branching still lines up. macOS arm64.
