# ADR-01858: An object or array literal's function without a context is an implicit any

- **Relations**: `Implements TDD-00230` (P3.3: found while answering the shadow report's ObjectLiteral bucket)
- **Date**: 2026-10-21

## Context

- The strict lane rejects every program tsc rejects. tsc reports TS7006 for an unannotated parameter of a method or function value in an object literal when no contextual type reaches the literal: `const o = { m(x) {} }`, `[{ m(x) {} }]`, `return { m(x) {} }` from a function without a declared result, `let q: any = { m(x) {} }`.
- `contextuallyTyped` counted every function whose parent is an object literal as contextually typed, so none of these was reported. The checker then left the function, and the literal, without an answer (`any`), and Test262's `to-prim-hint.js` (`{ [Symbol.toPrimitive](hint) {…} }`) compiled under the strict lane, which tsc rejects.

## Decision

- A function in an object or array literal (`[function* (a) {…}]`) is contextually typed only when the literal is (`literalInContext`): the literal's own contextual type, unless it is `any` (which types no member); else an argument of a callee the checker cannot type (the benefit of the doubt it already gives functions there); else an element of an object or array literal, a conditional branch or a spread that is itself in context.

## Consequences

- `TestCheck` holds tsc 5.6 `--strict`'s TS7006 lines for those shapes and none where a context reaches the literal (an annotated binding, a typed parameter).
- Verified on Apple Silicon.
