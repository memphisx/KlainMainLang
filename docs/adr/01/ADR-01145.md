# ADR-01145: `process` declared through `namespace NodeJS`, qualified type names, `path.format` partial objects

- **Relations**: `Implements TDD-00230` (Phase 3, P3.1); `Extends ADR-01144`
- **Date**: 2026-09-25

## Context

`process` was the next Node global to declare in `lib/node.d.ts`.
@types/node types it as `NodeJS.Process`, and its members use other types
from that namespace (`NodeJS.ProcessEnv`, `NodeJS.Platform`,
`NodeJS.MemoryUsage`). Programs spell those types too:
`env: NodeJS.ProcessEnv` is a common parameter type.

Neither half resolved. The binder put a library file's namespace members
in the global scope, and the checker had no lookup for a qualified type
name `NS.T`.

## Investigation

- **Codegen never saw the qualifier.** `ast` converted `NodeJS.Platform`
  to a `TypeAnnotation` named just `Platform`. With the checker accepting
  the annotation, codegen then rejected
  `const p: NodeJS.Platform = process.platform`.
- **The resolver renamed the last segment.** A user
  `interface Platform` made `NodeJS.Platform` resolve to it
  (`Platform__kml_mod0`), so a platform string was read as an object.
  A user namespace's type members desugar to bare top-level names
  (ADR-00450), so a user qualifier must keep renaming.
- **A test program tsc rejects.** `process.platform === 'nope'` in
  `TestE2EModuleGlobalTernaryReadByFunction` is now TS2367, as in tsc,
  since `'nope'` is not a `Platform`.

## Decision

- **Binder.** A library file's namespaces scope their members
  (`namespacesOf`, `inNamespace`), as a user program's do.
- **Checker.** `qualifiedTypeName` resolves `A.B.T` (interface, alias,
  class or enum) through namespace scopes, for library and user namespaces
  alike.
- **`lib/node.d.ts`** declares `namespace NodeJS { Dict, ProcessEnv,
  Platform, Architecture, MemoryUsage, Process }` and
  `declare var process: NodeJS.Process`. `Process` declares only the
  members implemented with a plain type. Streams and events come later.
- **`ast.TypeAnnotation.Qualifier`** carries a qualified reference's
  namespace path.
- **The resolver** leaves a library namespace's qualified type name
  alone (`lib.KnownGlobal`, unless the program declares that name).
- **Codegen** maps `NodeJS.Platform`, `NodeJS.Architecture`,
  `NodeJS.ProcessEnv` and `NodeJS.MemoryUsage` to the representation the
  matching `process` member already infers. The check runs before the
  interface registry.
- **libconform** skips namespace members, and accepts `lib.KnownGlobal`
  names.
- **The test program** compares against `'aix'`, which is a valid
  `Platform` and false on every CI platform.
- **`path.format`** takes a partial object, as
  `FormatInputPathObject` declares. Both flavours call the C sidecar's
  copy of Node's `_format` (`__kml_path_posix_format` beside
  `__kml_path_win32_format`), which replaces the posix hand-written IR. An
  absent field is passed as NULL, and a present one may be `undefined`;
  both read as empty. An `ext` without its dot gains one, as in Node.

## Side effects discovered

- **Type-only imports and exports do not parse** (`import type { P }`,
  `import { type P }`, `export type { P }`), in the previous build too.
  Fixed in ADR-01146.
- **A module's declared types are not usable in codegen.**
  `path.ParsedPath` as an annotation is rejected, like `NodeJS.*` was
  before this ADR (BACKLOG: TS2304 in type positions).
- **`NodeJS.Process` as a value type is not supported.** `process` is not a
  first-class value in codegen, so `function f(p: NodeJS.Process)` is
  rejected at the member access (BACKLOG).

## Verification

- **`TestE2EProcessDeclared`:** a user namespace's interface and alias,
  `NodeJS.Platform`, `NodeJS.MemoryUsage`, an absent env variable and
  `process.cwd()` run with Node's output. A number bound to
  `process.env.HOME` is TS2322. A user `interface Platform` beside
  `NodeJS.Platform` keeps both.
- **`tools/tsdiag -roots examples,apps`:** 1,590 of 1,592 (+6 over
  ADR-01144; the 2 are the known Annex B cases), 0 on the project's
  programs. **`tools/libconform`:** 0 divergences.
- **`TestE2EPathFormatPartial`:** absent and undefined fields, an ext
  without its dot, an empty object and `path.win32.format`, with Node's
  output (both host flavours).
- **Gates (with ADR-01145–01147):** Test262 strict 7,034 (+3 over
  ADR-01144), js 7,825 (+32), no clang failures in either lane; the Node
  suite is unchanged (strict 61, js 63). `make examples` 360/360 apart
  from `chained_listen`'s intermittent hang (1 in 3 alone; HEAD hangs at
  the same rate). `make test-par`: only the four macOS `-mm=gc` failures.
