# ADR-01158: `this` parameters: the receiver as a function's leading parameter

- **Relations**: `Implements TDD-00231` (stage 1, compiler gap 1); `Implements TDD-00230` (P2.7); `Extends ADR-00398`, `ADR-00372`
- **Date**: 2026-09-25

## Context

A Node stream written in TypeScript (TDD-00231) takes its callbacks the way
`@types/node` types them, `read?(this: Readable, size: number): void`, and
calls them with the stream as `this`. Three documented caveats stood in the
way:

- `Function.prototype.call`/`.apply`/`.bind` evaluated `thisArg` and
  dropped it (ADR-00398).
- `this` inside a method shorthand was a compile-time rejection.
- A `this: T` parameter was parsed and erased (ADR-00372):
  - `function f(this: T) { this.x }` was "'this' is only valid inside a
    method or constructor body";
  - a function type dropped `this: T` at parse time.

The checker typed a function expression's `this` as unanswered, and never
reported tsc's TS2684 for a call with the wrong receiver.

## Decision

- **Representation.** A function with a `this: T` parameter takes its
  receiver as its leading parameter, typed T. This is TypeScript's
  `thisParameter` made physical:
  - codegen's function `Type` carries `FuncThis`, and `FuncParams[0]` is
    T;
  - `FuncSig.This` does the same for a declared function.
- **Where a `this` parameter comes from:**
  - an explicit `this: T` on a function declaration or expression
    (`Program.ThisParams`), added at the one signature computation the way
    the implicit `arguments` rest is;
  - a function type `(this: T, …) => R`, now kept on
    `ast.FunctionType.This` and converted to a leading parameter;
  - a function literal compiled against such a type
    (`emitThisTakingClosure`). A function expression or method shorthand
    binds `this` to it; an arrow keeps its lexical `this` and ignores it.
  - `this: void` adds none.
- **Calls pass the receiver:**
  - `o.f(…)` passes `o`, evaluated once into a local.
  - `f.call(t, …)` and `f.apply(t, […])` pass `t`.
  - `f.bind(t, …)` binds `t` with the other arguments. The emitter and the
    type inference share `bindBoundCount`.
  - A call with no receiver (allowed by `this: unknown`) passes
    `undefined`.
- **Checker:**
  - a signature carries `ThisType` (interned with it, kept by
    `instantiate`, printed as tsc prints it);
  - a call reports TS2684 for a missing receiver, and checks a present one
    against `ThisType` (so a missing member is TS2741 at the receiver, as
    tsc elaborates it);
  - a function expression's `this` is its explicit `this` parameter, else
    its contextual signature's (`getContextualThisParameterType`);
  - a protected member may be read through a function's `this` typed a
    subclass (`getEnclosingClassFromThisParameter`);
  - the receiver is found through `!` (`o.test!()`).
- **Resolver.** A `this` annotation is renamed with its function's
  parameters, since it sits outside `Params`.
- **Parser.** A function expression's `this` annotation is recorded
  against the expression, not the declaration node it was parsed through.

## Side effects discovered

- Constructor arguments were emitted without the parameter type as a hint,
  unlike call arguments. An object literal passed to a constructor now
  builds against the parameter's type.
- A closure parameter's type referring to its own interface
  (`visit: (n: N) => void` inside `N`) kept an empty placeholder of `N`.
  It is canonicalized at the call.
- A named function used as a value was typed in three places, each
  building the closure type by hand; they share `funcTypeFromSig`.
- An existing object of another layout passed where a class instance is
  expected misreads its fields (`f(o)` with `f(b: Box)`); BACKLOG, P3.3.
- Async method shorthand already works; the caveat saying otherwise is
  corrected. Generator method shorthand is still rejected.
- Still open: borrowing a class method against another receiver
  (`obj.m.call(other)`), an interface's method signature with `this: T`,
  and `this` in a method shorthand with no contextual `this` type (tsc
  types it as the object literal).

## Verification

- **tsdiag, TS 7.0.2 corpus:** 3,113 diagnostics, all matching, 0 false
  positives. Before: 3,098. No match lost, no panic. Over `examples` and
  `apps`: 0 diagnostics.
- **Tests:**
  - `TestE2EThisParameterCallApplyBind`,
    `TestE2EThisTypedCallbackReceivesReceiver` and
    `TestE2EThisParameterWrongReceiverIsError`;
  - the existing `TestE2EThisParameterInExpression` (`this: unknown`,
    called directly) still passes.
- **Example:** `examples/function_expressions/call_apply.ts` gains a
  receiver section. Its output is identical to Node's, and it is clean under
  `tsc --strict`.
