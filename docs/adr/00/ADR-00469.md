# ADR-00469: generic function types erased (`<T>(x: T) => T`)

- **Relations**: Extends [ADR-00371](ADR-00371.md)'s erasure family
- **Date**: 2026-08-29

## Context

`expected type name, got <` (40 TS-oracle false-rejects) is the generic
function *type* — `var f: <T>(x: T) => T` — used across the corpus's
assignability suites.

## Decision

In the type-atom position, a leading `<T, …>` list parses via the shared
`parseTypeParamList` and the following annotation has every bare
type-parameter reference (including the `T[]` suffix form) rewritten to
`any` by a new parser-local `eraseTypeParamsIn` walk. This compiler's
generic functions are monomorphized declarations, never first-class
values, so the annotation's own parameters have nothing to bind to —
erasure matches the `as`-cast family's stance and lets `f("x")` / `f(42)`
flow through the existing any-param closure call path.

The same erasure applies to generic *method signatures* in interfaces and
inline object types (`map<T>(x: T): T` — the `expected :, got <` bucket,
65 cases): the member's type-parameter list parses via the shared
`parseTypeParamList` and its names erase in the parameter/return
annotations.

## Verification

Mac. `tests/type_features_test.go` (generic function type) and
`tests/interfaces_test.go` (generic method signature incl. `implements`
conformance through the erased signature) E2Es plus the
`examples/types/erased-syntax.ts` extension pass; parser +
generics/type/interface batches green. TS oracle: **55.6% → 55.9%**
(agreement 5150 → 5155 → 5173 across the two stages). Node oracle
unchanged (40).
