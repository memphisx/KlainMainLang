# ADR-00849: Spreading a string into an array literal (`[..."abc"]`)

- **Relations**: Extends array-literal spread ([ADR-00845](ADR-00845.md))
- **Date**: 2026-09-10

## Context

`[..."abc"]` (and `[...str]`) was "value is not an array": array-literal spread
resolved every spread source through `resolveArrayForHOF`, which only accepts an
array-valued expression. Spreading a string is a common idiom (splitting into
characters, `[...s].reverse()`, feeding `.map`).

## Decision

- In `emitSpreadArrayLitData`, a spread whose argument infers to a plain string
  materializes its character array once (`emitStringToCharArray`) and hands the
  extracted `ptr`+`len` to the existing count/copy loops — no new copy path.
- `inferArrayType` infers a leading string spread as a char array (`ptr`
  element, single-character strings), so a literal built **only** from string
  spreads (`[..."abc"]`) types correctly rather than defaulting to `number[]`
  and reinterpreting the character pointers as doubles.

## Implementation notes

`emit_arrays_core.go` (`emitSpreadArrayLitData` string branch);
`emit_exprs_types.go` (`inferArrayType` string-spread element type). Each string
character is a one-byte string in this compiler's per-byte string model — the
same shape `Array.from("abc")` already produced.

## Verification

macOS (Apple Silicon M4): matches Node — `[..."abc"].join("-")` → `a-b-c`,
`[...s].join(".")` → `h.i`, `[..."ab", ..."cd"].join("")` → `abcd`,
`["x", ..."ab", "y"]` → `x,a,b,y`, `[..."abc"].map(c => c.toUpperCase())` →
`ABC`, `.length` → 3. New `TestE2ESpreadStringIntoArray` + the spread/array
suites green.
