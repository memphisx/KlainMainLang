# ADR-00393: Node streams as real classes (TDD-00132 Stages A–B)

- **Relations**: Implements TDD-00132; Extends ADR-00089 (TDD-00023 EventEmitter synthetic root), ADR-00304 (options-form Node streams)
- **Date**: 2026-08-27

## Context

Node streams were supported only in **options form** — `new Readable({ read()
{…} })`, a documented deviation from Node's `this`-based `_read()`. The
idiomatic Node shape,

```ts
class Counter extends Readable<number> {
  _read() { this.push(next()) }
}
```

failed at compile: *"class 'Counter' extends unknown class 'Readable'"*. The
Node `test/parallel` oracle ranks `stream` the #2 failing module, and `class X
extends Readable/Writable` is the shape most real-world/test code uses.

## Decision

`Readable`/`Writable` become **synthetic stream roots** — never registered
classes, exactly like `EventEmitter` (ADR-00089). A class extending one gets
`HasNodeReadable`/`HasNodeWritable` on its `ClassInfo`, a hidden Node-stream
handle field (`ClassNodeStreamField`, `HasNodeStream` on the type), and the
readable-out / writable-in element types from the optional `<T>` argument. The
options-form runtime (rstream/wstream + `__kml_ns_*`) is reused wholesale; the
one new mechanism routes the runtime's pull/sink to the subclass's
`_read`/`_write` **method** instead of an options-object callback.

- **Construction** (in `NewExpression`, before the user constructor runs): build
  the `rstream`/`wstream` + `__kml_ns_alloc` handle, wire the readable pull slot
  to a thunk that calls `_read(this)` and the writable sink to one that calls
  `_write(this, chunk[, enc, cb])`, and store the handle into the hidden field.
- **Dispatch**: `on`/`once`/`push`/`pause`/`resume`/`write`/`end`/`pipe` on a
  stream-class instance load the hidden handle and delegate to the shared
  `emitNodeStreamCallOn` core (factored out of `emitNodeStreamCall`).
  `_read`/`_write`/`_transform` stay ordinary user methods; the eight dispatched
  names are reserved (a user method by those names is a compile error).
- **Consuming a stream-class instance as a value** (`finished`/`pipeline` args,
  `pipe` destinations) unwraps through `asNodeStreamValue`, so a class instance
  is accepted wherever an options-form stream is.

### Divergence from the TDD: no `HasEventEmitter`

TDD-00132 proposed also setting `HasEventEmitter` on stream classes. Rejected in
implementation: the Node-stream runtime already carries its **own** listener
surface (`__kml_ns_add_listener` + flowing-mode start), distinct from the
EventEmitter `Map<string,ptr>`. Setting `HasEventEmitter` would route `on`/`emit`
to the EventEmitter map (dispatched earlier in `emit_call.go`) while `data`/`end`
delivery rode the ns listener list — two disjoint maps for one stream. The stream
class's event surface is therefore the ns listener runtime alone, matching the
options form exactly.

## `super(options)` / `highWaterMark` / `objectMode`

`super({ highWaterMark, objectMode })` in a stream subclass constructor is
threaded into the hidden handle: the options object literal is read **statically**
off the constructor's top-level `super()` call at construction time (before the
constructor body runs), `highWaterMark` becomes the `double` watermark
`__kml_rs_alloc`/`__kml_ws_alloc` already take, and the `super()` call itself
lowers to a no-op. The same two options are accepted in the options form
(`new Readable({ highWaterMark, read })`). `objectMode` is validated as a boolean
and otherwise ignored — this compiler's chunks are already typed by `<T>`
(effectively always object-mode), so the flag has no representational effect;
accepting it is pure Node-fidelity. The `highWaterMark` expression is evaluated in
the construction-site scope, so it must be a literal / construction-scope constant
(the common Node form) — it can't reference a constructor parameter. Unknown Node
stream options on a `super()` call (`encoding`, `emitClose`, …) are silently
ignored there rather than rejected.

This cleared the two "unknown Readable/Writable option" buckets (15 files) off
that blocker in the Node `test/parallel` oracle; the whole-file pass count is
unchanged, since those files hit further blockers (`unknown stream method`, …)
once the option gate is passed.

## Consequences / bounded V1

- `extends Duplex`/`Transform` are rejected at compile time (Stage C) — a clean
  "not yet supported" error rather than a misleading "unknown class".
- A `_write(chunk, enc, cb)` completion callback is a no-op closure: the write is
  treated as complete when `_write` returns, so it can't be deferred past the
  call. `_write(chunk)` (1-arg) is also accepted.
- String/number-chunk limitations inherited from the options-form runtime carry
  over unchanged — this stage is about the class *shape*, not the chunk model.

## Verification

`examples/streams/class_extends.ts` (Readable + Writable subclasses) and two E2E
tests (`TestE2ENodeStreamClassExtends{Readable,Writable}`) produce byte-identical
output under `klainmain` and real Node.js v26. A `pipeline(classReadable,
classWritable)` round-trip also matches. Verified on Apple Silicon (Mac).
