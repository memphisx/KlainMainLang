# ADR-01824: Arrays' and static objects' other properties

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- `a.foo = 1`, `a.foo`, `delete a.foo` and `a.f()` on a statically typed array were compile errors. Only an array held as `any` could carry a named property, through the added-property table that shape.c keys by the array's header.
- `Object.defineProperty` and `defineProperties` refused arrays, static objects and class instances, except for a declared field of a static object. `getOwnPropertyDescriptor` and `getOwnPropertyNames` refused arrays. The table had no attributes and no accessors.
- An accessor element (`Object.defineProperty(a, "1", { get })`) had no representation.
- In the js lane, `const a = [1]; a[1] = "x"` kept `a` as `number[]` and read back `NaN`.

## Decision

- **Static array members.** A member read, write, compound write or `delete` on a static array, and a call of a member that is not an Array method, go through the array's box. That box already reads and writes the table.
- **Attributes and accessors in the table.**
  - Each table entry gets writable/enumerable/configurable bits.
  - An accessor's word is a `{getter, setter, owner}` triple. The owner (the boxed array or object) is the receiver when no other receiver is given.
  - A read runs the getter. A write runs the setter, or keeps a read-only value.
  - `Object.keys`, `for…in` and inspect list only enumerable entries. Inspect shows an accessor as `[Getter]`, `[Setter]` or `[Getter/Setter]`.
- **`Object.defineProperty` / `defineProperties`.**
  - A boxed static array, dynamic array, static object or class instance goes to one runtime entry (`__kml_anyarr_defprop`). It applies the spec's create defaults and the non-configurable redefinition rules.
  - A declared field of a static object keeps its own path. `length` and a data descriptor on an index write the element.
  - A static object's descriptor, names, keys, inspect, and `{ ...o }` spread read the table's attributes. Names come in insertion order.
- **Accessor elements.**
  - An accessor element is a hole whose index has an accessor in the table.
  - The hole test that guards every element read (`__kml_holes_is`) runs the getter into the element's slot and answers "not a hole". So indexing, every walk (`map`, `forEach`, `reduce`, `indexOf`, spread, `slice`, `join`, `JSON.stringify`), `in` and `Object.keys` see the getter's value.
  - A write runs the setter. Inspect and the descriptor read the raw bit and do not run the getter.
  - A data descriptor moves the value back into the element.
  - A TypedArray element refuses an accessor, as in V8.
- A refused redefinition names the key, as V8 does (`Cannot redefine property: k`, a symbol's as `Symbol(desc)`), on every defineProperty path.
- **js-lane widening.** In the js lane, a binding initialised from a non-empty array literal becomes `any[]` when the scope stores an element of another kind into it (index write, `push`, `unshift`, `splice`) or defines an accessor on it. It never narrows.

## Consequences

- `TestE2EJSFileArrayNamedProperties` and `TestE2EDefinePropertyBesideLayout` cover arrays, accessor elements, static objects and class instances. `examples/jsmode/array_named_properties.js` shows the feature.
- An accessor on a *declared field* of a typed object remains a compile error. A static field write would need to run the setter.
