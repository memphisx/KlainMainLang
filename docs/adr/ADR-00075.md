# ADR-00075: Split oversized codegen/parser files into domain files

- **Date**: 2026-07-29

## Context

Several files had grown well past the point of being easy to follow:
`codegen/llvm/runtime.go` (5756 lines), `codegen/llvm/emit_arrays.go` (2389),
`codegen/llvm/emit_exprs.go` (2261), `parser/parser.go` (2127), and
`codegen/llvm/emit_call.go` (1861) — the five largest files in the project by
a wide margin (the next-largest, `codegen/llvm/emit_strings.go`, was 1171).
Housekeeping requested directly: split anything over roughly 2000 lines
(with a stated preference for even smaller where practical) into files
scoped to a single domain, matching the one-file-per-domain convention the
rest of `codegen/llvm/` already followed (`emit_fetch.go`, `emit_fs.go`,
`emit_date.go`, `emit_collections.go`, `emit_process.go`, etc.). This is
pure housekeeping — no behavior change, no new features, no bug fixes
bundled in.

## Investigation

Three Explore agents surveyed the five files in parallel before any code
moved, each producing an exact `grep -n "^func "` function-boundary map and
a proposed grouping:

- `parser/parser.go`: confirmed zero package-level `var`/`const` outside the
  `Parser` struct — the split is purely a "move functions between files"
  operation, no shared state to account for. The precedence-climbing
  expression chain (`parseExpression` → ... → `parseCallMember`) needed to
  stay in one file as a structural unit rather than being cut mid-chain.
- The `emit_call.go`/`emit_exprs.go`/`emit_arrays.go` trio: confirmed most of
  `emitCall`'s dispatch targets already live in other `emit_*.go` files —
  only the pieces implemented *inline* (console/JSON/Math/Number/
  encoding-crypto) needed extracting. Found the cross-file dependency hub
  functions that had to keep stable names/signatures: `resolveArrayForHOF`,
  `emitValueToString`, `emitJSONParse`, `dateCompoundAssignGuard`,
  `coerce`/`toBool`.
- `codegen/llvm/runtime.go`: confirmed the file is 111 `ensure*()`-pattern
  functions (plus a handful of free helper functions) with two small
  package-level `const` blocks (`base64Alphabet`,
  percent-encoding-safe-char sets), both used only within their own bucket.

## Decision

Split into (all within package `llvm` except the parser package, so no
import-cycle risk anywhere):

- **`parser/parser.go`** (2127 → ~139) → `parser.go` (struct/token
  helpers/`ParseProgram`) + `parser_imports.go` + `parser_types.go` +
  `parser_classes.go` + `parser_stmts.go` + `parser_exprs.go` (the
  precedence chain) + `parser_literals.go`.
- **`emit_call.go`** (1861 → 629) → dispatcher only, kept in
  `emit_call.go`, plus `emit_call_console.go`, `emit_call_json.go`,
  `emit_call_math.go`, `emit_call_number.go`, `emit_call_encoding.go`.
- **`emit_exprs.go`** (2261 → 143) → `emitExpr`/leaf literals only, plus
  `emit_exprs_operators.go`, `emit_exprs_assign.go`, `emit_exprs_member.go`,
  `emit_exprs_types.go` (`inferExprType` stays whole — one ~600-line
  function that can't itself be split further), `emit_exprs_coerce.go`,
  `emit_exprs_vardecl.go`.
- **`emit_arrays.go`** (2389 → 0, fully replaced) → `emit_arrays_core.go`,
  `emit_arrays_mutate.go`, `emit_arrays_hof.go`, `emit_arrays_sort.go`,
  `emit_arrays_search.go`, `emit_arrays_transform.go`, `emit_arrays_iter.go`.
- **`runtime.go`** (5756 → 0, fully replaced) → `runtime_core.go`,
  `runtime_strings.go`, `runtime_json.go`, `runtime_dynamic.go`,
  `runtime_date.go`, `runtime_collections.go`, `runtime_exceptions.go`,
  `runtime_fetch.go`, `runtime_fs.go`, `runtime_encoding.go`,
  `runtime_crypto.go`, `runtime_process.go`, `runtime_misc.go`,
  `runtime_http.go`.

Two small adjacent cleanups folded in, both explicitly in-scope per the
plan (cheap, same-package, no behavior change):

- `ensureTimerRuntime` moved into the existing `emit_timers.go` instead of a
  new one-function `runtime_timers.go` — it's `emit_timers.go`'s own C-runtime
  backing store and nothing else calls it, so keeping codegen and runtime
  declaration together (like `emit_date.go` already does for Date) avoids a
  file that would exist only to hold one function.
- `ensureFree` moved from `emit_async.go` into `runtime_core.go` — it's a
  plain libc `free()` declaration (the `ensure*()` pattern), stylistically
  misplaced in an emitter-logic file.

`errnoAccessor`/`ensureErrnoAccessor`/`ensureStrerror` went to
`runtime_core.go` rather than `runtime_fs.go` despite fs being the heaviest
consumer, since `process` and `http` also call into them — a shared
primitive, not fs-specific.

## Implementation notes

- All moves were mechanical (`sed`-based extraction by exact line range,
  `gofmt -w` afterward), not retyped by hand, to avoid introducing silent
  logic drift on a >12,000-line change. Every extraction was followed by
  `go build ./...` to catch missing/unused imports immediately.
- **Doc-comment misattribution, found and fixed 11 times**: a doc comment in
  Go attaches to the *following* declaration, so a naive
  "`sed` from one `^func` line to the line before the next `^func` line"
  range silently pulls in the *next* bucket's doc comment along with the
  current bucket's code. This produced a dangling, function-less comment
  block at the tail of the wrong file and a (correct) duplicate at the head
  of the right one. Caught by checking whether each new file's last
  non-blank content was a comment (a real function-file should always end
  on a closing `}`) — found in `runtime_core.go` (→ `ensureFsThrow`'s
  comment, target `runtime_fs.go`), `runtime_crypto.go` (→
  `stdinGlobalName`, target `runtime_process.go`), `runtime_dynamic.go` (→
  `ensureDateNow`, target `runtime_date.go`), `runtime_encoding.go` (→
  `ensureCryptoRandomBytes`, target `runtime_crypto.go`),
  `runtime_exceptions.go` (→ `ensureFetch`, target `runtime_fetch.go`),
  `runtime_fetch.go` (→ `errnoAccessor`, target `runtime_core.go`),
  `runtime_fs.go` (→ `ensureConsoleGroupDepth`, target `runtime_misc.go`),
  `runtime_json.go` (→ `ensureAnyEq`, target `runtime_dynamic.go`),
  `runtime_misc.go` (→ `ensureTimerRuntime`'s comment, target
  `emit_timers.go`), `runtime_process.go` (→ `ensureFsMkdir`, target
  `runtime_fs.go`), and the same class of bug once during the `emit_arrays`
  split boundary check (`httpSockConstants`'s doc comment, caught before it
  was ever written to a file). Each was moved to precede its real function
  rather than just deleted, so no documentation was lost.
- One duplicate-declaration bug from the same root cause: `ensureSscanf`
  (physically inside the date-parsing line range) got extracted into both
  `runtime_core.go` (per the plan — it's shared with `process`/`http`, not
  date-specific) and `runtime_date.go` (as a side effect of a contiguous
  range copy). Caught immediately by `go build` (`method already declared`)
  and fixed by removing the accidental duplicate from `runtime_date.go`.
- Found and dropped one piece of dead documentation while moving
  `emit_call.go`: a leftover `// CapturedVar describes...` comment plus a
  `// === Closure / arrow-function support ===` section header sat above
  `emitConsolePrint` with no matching declaration in the file — the real
  `CapturedVar` type (and its own identical doc comment) lives in
  `emit_func.go`. Dropped as pure stale-comment cruft; verified via `grep`
  that no code in the repo depends on it.
- `CLAUDE.md`'s "Codegen file map" table updated to list every new file by
  domain, and to fold in several already-existing-but-undocumented files
  (`emit_promise.go`, `emit_timers.go`, `emit_http.go`, `emit_memory.go`,
  `gclocate.go`/`gcshim.go`) that had never been added to the table by the
  features that introduced them — found while updating the table for this
  reorg, fixed in the same pass rather than left stale.

## Side effects discovered

None affecting behavior. `examples/async/promise_all.ts` and
`examples/fetch/fetch.ts` both failed once with `Uncaught: Timeout was
reached` on a `make examples` run taken *before* this reorg's first commit
of work (parser split only, nothing in `codegen/llvm` touched yet) —
confirmed as a pre-existing, unrelated flake in already-uncommitted
Promise.all/fetch-init work from an earlier session, not something this
reorg introduced: both passed cleanly on every subsequent `make examples`
run once the full trio + runtime.go splits were in place.

## Verification

After each of the three areas (parser, `emit_call`/`emit_exprs`/
`emit_arrays` trio, `runtime.go`):

```sh
go build -o klainmain . && go vet ./... && go test ./...
make examples
```

All three passed cleanly after every area, and again after the full
reorg — `go test ./...` (lexer, parser, tests packages, ~160s) and
`make examples` (64/64 examples) both green on the final tree. `git diff`
reviewed per touched file to confirm each large diff was pure code motion
(function bodies unchanged byte-for-byte, only file boundaries and a small
number of doc-comment relocations/deletions as described above).
