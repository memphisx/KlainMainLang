# ADR-00283: Spec-faithful async-generator step model — synchronous start, park-at-await, request queueing

- **Relations**: Supersedes [ADR-00275](ADR-00275.md)'s deferred body start (its settle-through-`__kml_promise_settle` rule stands and is load-bearing here); closes the divergence disclosed in [ADR-00281](ADR-00281.md); extends [ADR-00253](ADR-00253.md)/[ADR-00254](ADR-00254.md) (the generator-fiber/await fusion)
- **Date**: 2026-08-21

## Context

[ADR-00281](ADR-00281.md)'s node diff showed the async-generator step timing
diverged from V8/spec in three connected ways: `.next()` deferred the whole
body start to a microtask (node runs it **synchronously** up to the first
`await`/`yield` — AsyncGeneratorResume); an `await` inside the body drove
inline within the fiber instead of suspending the step (so body side effects
did not interleave with consumer-side microtasks); and `await <plain value>`
in a body yielded no tick. These were briefly disclosed as caveats; this ADR
is the real fix — one coherent redesign, since a partial fix (sync start
alone) merely trades which programs diverge.

## Investigation

- The fiber machinery already had every needed primitive: `__callerCtx` is
  re-staged by each resumer (`emitGeneratorSwapCore`) so the fiber can be
  resumed *from any context* — including a microtask; and
  `__kml_promise_drain_reactions` **enqueues** reaction closures onto the
  microtask FIFO (never runs them inline), so a settle can safely schedule a
  fiber re-entry.
- The ADR-00274 deadlock's root cause (settling `q` by a bare state store,
  stranding attached reactions) is exactly why park-at-await works now: every
  settle goes through `__kml_promise_settle`, which wakes both `.then`
  reactions and a parked consumer.

## Decision

Generator instances gain step state: `__pendingQ` (the in-flight step's result
promise; null = idle), `__parked` (fiber suspended at an await-park), and
`__reqHead`/`__reqTail` (a FIFO of queued requests
`{resumeMode, sentSlot, thrown, q}` — the sent value spilled to a malloc'd
elem-typed slot so any element type round-trips).

- **One per-generator-type step function** `@__kml_agen_step_N(ptr genObj)` —
  both the synchronous step entry and the await-resume target. Its loop: if
  the generator is done, complete `__pendingQ` per `__resumeMode` (0 →
  `{zero, done:true}`, 1 → reject `__thrown`, 2 → `{__sent, done:true}` — the
  spec's drained-queue completions); else swap into the fiber; on return, a
  set `__parked` leaves q pending and returns, otherwise q settles from
  `__genError`/`__yielded`; then the next queued request (if any) is popped
  into the resume fields and the loop continues.
- **Submit-or-start** (`.next`/`.throw`/`.return` shared entry): idle → stage
  the resume fields + `__pendingQ` and call the step fn **synchronously**
  (V8's synchronous body start); busy → append to the request FIFO
  (AsyncGeneratorEnqueue — a request is never injected into a step mid-await).
  `.throw` on a fresh idle generator still rejects immediately without running
  the body; `.return` on one settles `{v, done:true}` — done generators route
  through the step fn's drained-queue dispatch instead.
- **Park-at-await** (`emitAsyncGenAwaitParkUntilSettled`, emitted inside the
  body): attach a `{stepFn, genObj}` resume closure to the awaited promise's
  reaction list (already-settled → enqueue it now, so a settled-promise/plain-
  value await still defers one tick, as JS), set `__parked`, and swap back to
  the step's caller — no `__yielded`/`__done` stores, and no jmpbuf/GC
  bookkeeping (the resumer's swapCore owns that, exactly as for yields). All
  three body-side await paths route here: `emitAwaitTaskPromise` (any task
  promise awaited while emitting an async-gen body), `emitAwait`'s
  non-promise wrap (settled task promise + park = the tick), and
  `emitAwaitSettledResult` (`yield*` inner-step awaits — nested parks compose:
  the inner generator parks on its promise, the outer parks on the inner's q).
  A raw `fetch` await keeps its own fiber-yield/busy-spin machinery, unchanged.

## Implementation notes

- `codegen/llvm/types.go` (fields), `emit_generators.go` (constructor init,
  `emitAsyncGenSettleFromFields`, `emitAsyncGenSubmitRequest`,
  `emitAsyncGenSubmitOrStart`, the rewritten `ensureAsyncGenStepFn`, the park
  helper; `emitAsyncGenSwapAndSettle`/`emitAsyncGenStepBody`/
  `enqueueAsyncGenStep` deleted), `emit_async.go` (await dispatch).
- The step fn's env **is** the generator object (no `{genObj, q}` wrapper —
  q lives in `__pendingQ`, which is what lets one closure serve as both the
  step entry and every subsequent await-resume).
- Ordering rule kept from ADR-00275: q settles only via
  `__kml_promise_settle`.
