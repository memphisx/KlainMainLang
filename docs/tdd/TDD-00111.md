## Context

`http.listen`/`fetch` are HTTP/1.1 only; `http2` is ❌ on
[NODE-CORE-MODULES.md](../status/NODE-CORE-MODULES.md). HTTP/2 splits into two
jobs of very different size:

- **Client** is small. `fetch` is libcurl-based
  (`codegen/llvm/runtime_fetch.go`), and libcurl already links **nghttp2**
  transitively (its static-link dependency is on record in
  [ADR-00033](../adr/ADR-00033.md)). It just never asks for h2. libcurl does
  ALPN negotiation and HPACK internally — the whole client change is one extra
  `curl_easy_setopt`.

- **Server** is genuinely from-scratch. `http.listen` is a hand-rolled HTTP/1.1
  line/header parser over raw `accept()`/`select()`
  (`runtime_http.go`, `emit_http.go`), with no framing layer, no HPACK, and no
  ALPN anywhere in `tlssrc/tls.c`. HTTP/2 is a binary, stream-multiplexed
  protocol with HPACK header compression and per-stream flow control —
  hand-rolling that is out of scope for this project. The server rides on
  **nghttp2** (a C helper compiled alongside, exactly like `tlssrc/tls.c`).

Both are scoped together here, implemented in the staged order below.

## Design

### Backend choice (server): nghttp2, not hand-rolled

HPACK alone (RFC 7541, static + dynamic table, Huffman coding) plus framing,
stream state machines, and flow control is a large, error-prone body of binary
protocol code. nghttp2 is the same library libcurl already pulls in, is
BSD-licensed, and exposes a callback-driven session API that maps cleanly onto
an event loop. A new `http2src/http2.c` helper wraps it behind a small C ABI and
is compiled next to the `.ll` when `UsesHTTP2()`, gated exactly like the crypto
(`UsesCrypto()`) and TLS (`UsesTLS()`) blocks in `main.go`. Link: `-lnghttp2`
via `requireLink("nghttp2")`. Keeps all `nghttp2/*.h` out of the emitted IR.

Hand-rolling the framer/HPACK is explicitly rejected.

### Stage 1 — Client: `fetch` over h2 (small, ships first)

Add one `curl_easy_setopt` to the easy-handle setup block
(`runtime_fetch.go:256-283`):

```
CURLOPT_HTTP_VERSION (84) = CURL_HTTP_VERSION_2TLS (4)
```

`2TLS` = "h2 over TLS, HTTP/1.1 over cleartext" — the browser-like default and a
match for web `fetch` semantics, where the HTTP version is transparent (Node's
`fetch` exposes no version knob). Negotiation is via ALPN, done inside libcurl;
on an h2 server the transfer uses h2, otherwise it transparently falls back to
1.1. **No API surface, no per-request opt-in.**

The setopt return code is ignored (as the existing setopt calls are): a libcurl
built without nghttp2 rejects the option and the transfer proceeds as 1.1, so a
missing-nghttp2 build still compiles and runs. Multiplexing multiple concurrent
`fetch`es over one h2 connection is a possible V2 on the multi handle
(`CURLMOPT_PIPELINING`), out of scope here — correctness of a single h2 transfer
is Stage 1.

### Stage 2 — ALPN in the OpenSSL layer (`tlssrc/tls.c`)

Prerequisite for the server; the client needs none of this (libcurl owns its own
ALPN). Two additions to `tls.c`:

- **Server CTX** (`__kml_tls_server_ctx`): `SSL_CTX_set_alpn_select_cb` with a
  callback that selects `h2` when offered, else `http/1.1`
  (`nghttp2_select_next_protocol` or a hand-written match on the wire-format
  protocol list `\x02h2\x08http/1.1`).
- **Per-connection introspection**: a `__kml_tls_alpn_selected(SSL*) -> const
  char*` wrapping `SSL_get0_alpn_selected`, so the accept path can branch h2 vs
  1.1 after the handshake.

Client-side `SSL_CTX_set_alpn_protos` is *not* needed (only `tls.connect`/wss
use the client CTX, and neither speaks h2 today).

### Stage 3 — Server: nghttp2 driver over the event loop

Sub-staged so the framing/HPACK/event-loop integration is proven before TLS is
added on top:

**S3a — h2c (cleartext, prior-knowledge).** A `http.listen` connection whose
first bytes are the HTTP/2 connection preface (`PRI * HTTP/2.0\r\n\r\nSM\r\n\r\n`)
is driven as an nghttp2 session instead of the 1.1 parser. This is testable with
`curl --http2-prior-knowledge` and needs no TLS, isolating the hard part:
- `http2.c` ABI (mirrors the session lifecycle):
  `__kml_h2_session_server_new(fd) -> void*`,
  `__kml_h2_session_recv(sess)` / `__kml_h2_session_send(sess)` (drain the socket
  in/out — driven by the event loop's readable/writable signals),
  `__kml_h2_session_want_read/want_write(sess) -> int`,
  `__kml_h2_session_del(sess)`.
- nghttp2 callbacks (`on_begin_headers`, `on_header`, `on_frame_recv` with
  `END_STREAM`, `on_data_chunk_recv`) accumulate each stream's method/path/
  headers/body into a request record, then invoke the **existing** dispatcher
  (`@__kml_http_dispatch`, `emit_http.go:212`) — so user handler code, routing,
  and the `Request`/`Response` shapes are reused unchanged. The response is
  submitted with `nghttp2_submit_response` (headers via HPACK) + a data source
  reading the handler's body.
- **Event loop**: a new fdset hook `__kml_h2_fdset_add` registered in
  `__kml_event_loop_run` (`runtime_http.go:1266-1297`), reporting each live
  session's fd for read and, when `want_write`, for write. Dispatch drains
  `recv`/`send`. Sessions are held in a small fd→session registry (the
  fd→SSL registry pattern from wss, ADR-00346).

**S3b — h2 over TLS.** `http.listen` gains a TLS mode (cert/key options, reusing
`__kml_tls_server_ctx` + the ALPN callback from Stage 2). After
`__kml_tls_server_accept`, branch on `__kml_tls_alpn_selected`: `h2` → the S3a
nghttp2 driver but with I/O routed through `SSL_read`/`SSL_write` (an io-shim
like wss's `__kml_wsc_io_*`); `http/1.1` (or none) → the existing 1.1 path over
TLS. This is the real-world h2 path (browsers do h2 only over TLS).

## Open questions

- **h2c reachability of the dispatcher body-shape**: the 1.1 dispatcher expects a
  parsed request record; confirm the record it consumes can be populated from
  nghttp2 callbacks without reserializing to a 1.1 byte stream (goal: feed the
  struct directly, no fake 1.1 buffer).
- **Response streaming**: S3a submits a full-body response first; whether
  `runtime_http_stream.go` chunked-response streaming maps onto an nghttp2 data
  source provider is a follow-on, not Stage 3 baseline.
- **nghttp2 availability policy**: unlike libcurl (always present for fetch),
  nghttp2 as a *direct* link is new. Decide whether a missing `nghttp2/nghttp2.h`
  is a hard compile error (like `tls` needing libssl) — likely yes, gated on
  `UsesHTTP2()` so only h2-server programs require it.
- **`http.listen` API for TLS**: option bag (`{ cert, key, allowHTTP1 }`) vs. a
  separate entry point. Lean option-bag, mirroring `tls.createServer`.
