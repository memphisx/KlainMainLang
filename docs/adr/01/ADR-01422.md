# ADR-01422: Regressions from symbol keys and literal member names

- **Relations**: Extends ADR-01419, ADR-01420, ADR-01421
- **Date**: 2026-10-06

## Context

The gates for the symbol-key and literal-member-name work (TDD-00246) found
three kinds of regression:

- `examples/enums/enums.ts` stopped compiling: the new TS7053 check rejected
  `Size[2]`, a numeric enum's reverse mapping.
- Test262 lost 8 strict and 11 js files: `fields-string-name-*-constructor`
  and `nested-string-literal-name-init-err-contains-arguments` (both class
  forms), and five `Object.getOwnPropertySymbols` files (a null/undefined
  argument, Proxy `ownKeys` invariants).
- `TestE2EObjectGroupByNullPrototype` read `g["none"]` off an
  `Object.groupBy` result in the strict lane.

## Investigation

- tsc gives a numeric enum's object a `[x: number]: string` index signature;
  `checker/enums.go`'s `enumObject` built a plain object, so TS7053 fired.
- `tsc --strict` rejects `g["none"]` on `Partial<Record<"even" | "odd",
  number[]>>` with TS7053 too: the checker was right, the test program is
  not TypeScript.
- The class files passed before only because a literal member name was a
  parse error. A field named `constructor` (TS18006) and `arguments` in a
  field initializer (TS2815) were never rejected, for identifier names either.
- The getOwnPropertySymbols files passed before only because the call was
  unsupported and threw. The new implementation returned `[]` for
  null/undefined and ignored a Proxy's `ownKeys` trap; the runtime had no
  `ownKeys` support at all.

## Decision

- `enumObject` adds the number index signature (string) when any member is
  numeric.
- The groupBy test runs in the js lane.
- The class-member parser rejects a non-computed field named `constructor`
  (static or not), and a field initializer referring to `arguments` outside
  a nested function or class (arrows look through).
- `Object.getOwnPropertySymbols` calls `__kml_own_symbols_checked`
  (shape.c): null/undefined throw TypeError; a Proxy with an `ownKeys` trap
  calls it with the target, requires an array of distinct strings and
  symbols, requires every non-configurable target key, and for a
  non-extensible target exactly the target's keys. A Proxy without the trap
  recurses on its target. A non-null result is the TypeError message the
  emitter throws.

## Implementation notes

- `dynobj.c` exports `__kml_dynobj_proxy_parts` and `__kml_dynobj_call_trap`
  so shape.c can reach the Proxy without the bag layout.
- The trap result is read through `__kml_anyarr_get_by_key` (a static
  array) or `__kml_dynarr_len`/`at` (a dynamic one), so the emitter now
  ensures dynjson.c and the dynamic-array runtime with KML_OWN_SYMBOLS.
- A symbol element is recognised by its field-0 `symbolTypeIDFlag`.

## Side effects discovered

`Object.keys`, `Object.getOwnPropertyNames` and `Reflect.ownKeys` still do not
consult `ownKeys`; recorded as the Proxy row's caveat.

## Verification

`TestE2EGetOwnPropertySymbolsProxyOwnKeys` (same output as Node) and
`TestClassFieldEarlyErrors`; the 11 lost Test262 files pass again in both
lanes (Mac, `-category` runs); `examples/enums/enums.ts` prints the expected
reverse mappings; checker unit tests pass.
