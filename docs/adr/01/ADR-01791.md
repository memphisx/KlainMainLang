# ADR-01791: Object rest over a dynamic or primitive value

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- `{ a, ...rest }` over a dynamic value (a js-lane parameter, `any`) was rejected ("object rest … over a dynamic (-compat=js) object is not yet supported"), as was a rest in a destructuring assignment from one.
- Object destructuring of a value that is not an object (`var { length } = "abc"`, a number variable, `null`) failed to compile ("requires an object variable, function call, or object literal" / "is not an object"). JS coerces a primitive to its object and throws a TypeError for null and undefined.

## Decision

- `@__kml_any_obj_rest(src, excluded)` is compiled once. It applies `Object.keys` and `Object.getOwnPropertySymbols` to the source, which both apply ToObject. The loops are parsed source and copy each enumerable key not in `excluded` into a new object, string keys first, then symbols.
- `unpackDynObjectPatternInto` binds a rest element to it, excluding the pattern's earlier keys. `emitDynDestructAssign` does the same for assignments. A computed key is evaluated once into a temporary, as a property key (a symbol stays one), and used for both the read and the exclusion.
- `resolveObjectPtr` boxes any non-object source for the dynamic path.
- A pattern starting with a rest checks that its value is object-coercible. Like ADR-01786's empty pattern, the TypeError names the source as written (`destrSourceText`) when the declaration has a name or literal source, as V8's message does.
- Return inference binds such a rest name as `any`.

## Consequences

- `TestE2EJSFileDynamicObjectRest` compares parameters, declarations, assignments with static, computed and symbol keys, defaults, class instances, strings, numbers, arrays and null against Node.
