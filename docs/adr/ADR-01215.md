# ADR-01215: A plain object behind another plain type is the object itself

- **Relations**: `Implements TDD-00233`, `Extends ADR-01210`
- **Date**: 2026-09-28

## Context

TDD-00233 Stage 3. A plain object passed where another plain object type
was declared (`{ a, c, extra }` as `Opts`, `{ hostname, port, extra }` as
`RequestOptions`) was copied into the declared type's layout
(`emitObjectRelayout`). A write through the parameter did not reach the
caller's object, and `===` against it was false (BACKLOG 74).

## Investigation

- The copy served two kinds of reader. User code already reads a
  structural type through the checked view (ADR-01210). The other kind
  is codegen's own consumers of option objects.
- Those consumers read an option object at its static type's offsets.
  Most go through `loadFieldValue` (fetch, XHR, SQLite, http, stream
  pipes).
- Optional chaining (`o?.x`) built its own static GEP.
- `objectFieldBoxingCompatible` refused a pair whose shared field is
  concrete in one type and a union in the other (`a: string` passed as
  `a?: string | number`), even though tsc accepts it.

## Decision

- A plain object where another plain object type is expected, in a
  coercion, an object-hinted expression or a union member, is the object
  itself (`emitObjectAsRecord`). Its layout row is registered
  (`noteRecordViewSource`, which now covers an empty `{}` too).
  `emitObjectRelayout` is deleted.
- `loadFieldValue` and the optional-chaining read go through the view.
- A structural target accepts a source whose fields differ only in
  boxing, since the view converts each member by name.
- A dictionary-typed member read through the view from a static object
  becomes a dictionary of the object's present keys
  (`emitBoxedObjToDict`), as the static coercion does.
- The empty `{}` counts as an object that can carry added properties, so
  its statically typed binding shows a property written through the view.
- A value of another kind than a field holds, written through the view or
  `any` (`o.x = "s"` into a `number` field), is not stored in the field:
  the row's setter refuses it (`emitBoxFits`) and it becomes an own
  property that shadows the field (shape.c looks own properties up first
  and lists a shadowing key at the field's place). Everything that reads
  through the row, printing and JSON included, sees it, as Node does.

## Implementation notes

`codegen/llvm/emit_exprs_coerce.go`, `emit_objects.go`, `emit_dynamic.go`,
`emit_fetch.go`, `emit_exprs_member.go`, `emit_record_view.go`,
`emit_shape.go`, `shapesrc/shape.c`.

## Side effects discovered

- Bugs this uncovered are recorded in ADR-01216.
- A direct read of a shadowed field through its statically typed binding
  still reads the field's old value (BACKLOG).
