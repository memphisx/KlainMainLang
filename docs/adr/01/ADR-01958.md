# ADR-01958: Iterator and generator bindings keep codegen's layouts in the front end

- **Relations**: Implements TDD-00230 (P2.3)
- **Date**: 2026-10-29

## Context

The shadow report showed three disagreements between the front end's representation step and codegen over iterators and generators:

- `const names = stock.keys()` reads were typed `any`. The binding's type, `MapIterator<string>`, has lost the map's value type, which codegen's collection iterator keeps (`IterSrc`).
- `const r = it.next()` on a generator was the `IteratorResult` union of two interfaces. Codegen holds a generator's step in its own `{value, done}` layout. A `let r` written only by further steps (`r = it.next()` in a loop) is held the same way.
- A generator whose return type has a different representation from its yields (`Generator<undefined, number, number>`) boxes its one value slot. Codegen applied that rule only when building the generator itself. The shared `Generator<…>` lowering read only the yield type, so the front end and an annotated binding of the same generator named the unboxed layout.

## Decision

- An unannotated `const` holding a collection iterator holds its initializer's representation.
- An unannotated binding initialized by a generator's `next()`, `return()` or `throw()`, or by an awaited one of an async generator, holds that initializer's representation. It must be a `const`, or every write to it must be another such call (`stepsOnly`). This applies to both identifier reads and the top-level declaration.
- Both rules are tried only for a call initializer of the right method name (`keys`, `values`, `entries`, `matchAll`, or a step), so other bindings do not re-type their initializers on every read.
- The slot rule is one helper, `genSlotElem`, used by generator construction and by both `Generator<…>` lowerings (annotation and checker type). On the checker path an `any` or `unknown` TReturn is skipped: the checker fills an unwritten TReturn with its default, which no annotation names.

## Consequences

- `examples/map/iterators.ts`, `examples/async/async_generator.ts` and every example under `examples/generators/` report no disagreement.
- A shadow compile of `examples/url/url_parse.ts` takes 11.4 s on the Mac, as before these rules; the unfiltered first version took 17 s.
- `TestE2EGeneratorAnnotatedReturnSlot` matches Node (Mac).
