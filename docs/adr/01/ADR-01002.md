# ADR-01002: `Promise.allSettled` rejected `reason` is a real Error object (crash fix)

- **Relations**: Implements TDD-00169 (partial — the crash/introspection half; faithful arbitrary-value reason remains), Supersedes the reason-stringify from the promise rejection-value-fidelity work
- **Date**: 2026-09-18

## Context

Surfaced during a stale-caveat hunt. The `Promise.allSettled` reason caveat
claimed the rejected `.reason` was "a wrapped `Error` (stringified message)".
Re-characterising it against `node` showed the caveat was itself stale, and
worse, that `settlement.reason.message` on an **Error** rejection reason
**segfaulted** (exit 255):

```
Promise.allSettled([Promise.reject(new Error("boom"))])
  ...[0].reason.message   →  crash (exit 255)
```

Root cause: `SettlementType.reason` is typed `errorObjType`
(`codegen/llvm/types.go`), but the producer
(`emitPromiseAllSettled`, `settled.fail`) stored the reason as a **string** via
`emitCaughtToString`, and the JSON arm read the slot back as a raw string. So a
member read of `.reason.message` did `getelementptr errorObjType` on a *string*
pointer and dereferenced field 1 as an Error struct — a wild read. The Response
(fetch) path had the same latent shape, storing a bare message string into the
`errorObjType` slot. This was a regression from the pre-rejection-fidelity code,
which stored a real Error and never crashed, traded away to make a *string*
reject value serialize as its own text in JSON.

## Investigation

- `emit_promise.go` — all three allSettled paths; only the task and Response
  paths take the rejected branch, and both put a non-`errorObjType` value into
  the `errorObjType` reason slot.
- `emit_caught.go` — a caught rejection value is a `{tag, payload}` record
  (TDD-00207): a caught Error (tag `kmlTagError`) carries its real
  `errorObjType` pointer as the payload; every other tag is a primitive.
- Considered flipping `reason` to `any` (the fully faithful target, TDD-00169):
  implemented and **reverted** — it regresses the *common* case, because a
  caught Error boxes to a bare `kmlTagObject` whose Error shape can't be
  recovered at a general render/JSON/member site (`errorObjType`'s field-0
  `kind` and a class instance's field-0 `__kml_tag` are both i64 and can
  collide; `emitErrorInstanceOf`'s dynamic arm already punts, treating any boxed
  object as an Error). Recovering it needs the D1 Stage-6 boxed-object type-id,
  so `reason: any` cannot ship without that. Recorded in TDD-00169.
- The bounded, safe fix that removes the crash *without* the Stage-6 work: keep
  the field `errorObjType` and always store a **real** Error there.

## Decision

Store the reason as a real `errorObjType` in every rejected path:

- **Task path**: a new `emitCaughtToErrorObj` (`emit_caught.go`) — a caught
  Error uses its own payload pointer directly (preserving
  message/name/code/stack fields); any other caught value is wrapped in a
  fresh base-kind Error whose `message` is the value's string form.
- **Response path**: wrap the transport-failure message string in
  `buildErrorObj(0, msg, "Error")`.
- **JSON arm** (`emit_call_json.go`): read the reason's `message` field and
  serialize *that* string, rather than treating the slot as a raw string — so a
  string/number reject value still renders its own text and a real Error's
  message renders, with no pointer-as-C-string deref.

The `reason` field type is unchanged (`errorObjType`), so there is no struct
layout / `SettlementType` ripple.

## Implementation notes

- `emitCaughtToErrorObj` mirrors `emitCaughtToString`'s tag branch; the else arm
  reuses `emitDynamicToString(emitCaughtToAny(v))` for the wrapped message.
- The `errorObjType` reason field type is unchanged, so member access
  (`.reason.message`/`.reason.name`) needed no change — it now reads a real
  Error's real fields.
- `TestE2EPromiseAllSettledArrayValues` previously logged the bare reason and
  asserted the *stringified* `"Error: neg"`; updated to log `reason.message`
  (`"neg"`, Node-faithful) now that the reason is a real Error object rather
  than a pre-flattened string.
- **A console fix attempted and reverted.** `console.log(err)` on a
  statically-typed `errorObjType` prints an *empty* token (`isInspectableObject`
  excludes `IsError`, `emit_inspect.go:45`, so an Error falls through every
  inspect branch). Adding a global `IsError` branch to
  `emitConsolePrintValueToken` that calls `emitErrorToString` **Bus-errored**
  `examples/events/abort-controller.ts`: `AbortSignal.reason` is *also* typed
  `errorObjType` but `abort("timed out")` stores a **raw string** there (a
  "lying" slot, like the pre-fix allSettled reason), so `emitErrorToString`
  dereferenced a string as an Error. Since an `errorObjType`-typed value is not
  guaranteed to be a real Error, that branch is unsafe without the same
  boxed-object type-id the rest of the fidelity work needs — reverted, left to
  TDD-00169 with the primitive-reason gap.

## Side effects discovered

- **Not fixed (Stage-6-gated), tracked in TDD-00169**: a *non-Error* reject
  value's `reason` is still not fully faithful — `typeof reason` reads
  `"object"` (Node: the value's own type) and `JSON.stringify` renders a number
  reason's text quoted (`reject(42)` → `"reason":"42"`, Node `42`). A real
  Error's JSON is its message string, not Node's `{}`. All three need a boxed
  object to carry the value's true type through `any`, i.e. the D1 Stage-6
  boxed-object type-id.
- `console.log(<a statically-typed Error>)` still prints an *empty* token (see
  the reverted-console note above). Fixing it safely needs the same type-id, so
  it too rides TDD-00169; `String(err)` / member access / a caught Error are the
  faithful paths today.

## Verification

macOS arm64 (M4). Byte-exact vs `node` for an Error rejection reason:
`reason.message` → `boom`, `reason.name` → `Error`, `String(reason)` →
`Error: boom` (was a segfault). New `tests/allsettled_reason_error_test.go`
covers the Error-reason introspection and the JSON no-crash shape;
`TestE2EPromiseAllSettledArrayValues` updated to assert `reason.message`.
`examples/events/abort-controller.ts` re-verified (the reverted console branch
had Bus-errored it). `make examples` 331, `make status-check`,
`make reference-check` green; Test262 run at delivery.
