# Memory Management

> Part of the [Implementation Status](README.md) index. Selected once per compiled binary via the `-mm=manual|gc|auto` CLI flag (default `manual`). Full design: [TDD-00001](../tdd/TDD-00001.md).

**Coverage**: 2 of 3 modes shipped (`manual`, `gc`); `auto` is design-only.

**Caveats**: `manual` mode never frees anything on its own — a program's memory footprint is a monotonically increasing function of its runtime unless the programmer calls `Memory.free(x)` by hand. `manual` is still the default (fine for short-lived CLI tools), even though `gc` now exists and is strictly safer for long-running processes — no decision has been made yet to flip the default. `auto` mode (compiler-inserted frees via static escape/liveness analysis, no runtime collector at all) is a bigger risk to get right than `gc` was: a wrong escape analysis there is a real use-after-free, not just a missed/delayed free, so it's deliberately sequenced last.

## The three modes

| Mode | Status | Who frees | Notes |
|---|---|---|---|
| `manual` (default) | ✅ | The programmer, via explicit `Memory.free(x)` | `Memory.free(x)` resolves `x`'s underlying heap pointer (array data pointer, object struct pointer, closure header + environment, Map/Set backing buffers) and frees it — shallow only, never anything reachable *through* it. Same footguns as C, including that a string *literal* is a compile-time global constant, not malloc'd, so freeing one crashes exactly like C's own `free("literal")`. See [ADR-00030](../adr/ADR-00030.md) (Stage 1 of the staged plan in [TDD-00001](../tdd/TDD-00001.md)). |
| `gc` | ✅ | The Boehm–Demers–Weiser collector (`libgc`), automatically | Swaps the declared `@malloc`/`@realloc` symbols for `@GC_malloc`/`@GC_realloc` and links `-lgc` — no changes needed to any per-feature codegen file beyond the allocation call sites themselves, since the collector conservatively scans the native stack/registers/managed heap for anything that looks like a live pointer. `Memory.free(x)` stays legal in this mode (lowers to `GC_free`, an always-safe early-release optimization Boehm itself documents). Needed a `GC_stackbottom` fix so `http.listen`'s concurrent fibers collect safely — a 100,000-request load test confirmed the server survives at that scale. A second, separate `GC_stackbottom` fix was needed for Ubuntu's `libgc-dev` build specifically, whose `GC_init()` crashes on startup unless `GC_stackbottom` is preset before *any* allocation happens, including ones made by other libraries' own constructors (see [ADR-00080](../adr/ADR-00080.md)). A third `GC_stackbottom` fix was needed for a connection fiber's own non-blocking-read yield path, which was missing the restore-to-original-stack half of the set/restore pairing the other 3 swapcontext sites already had — a CI-only-reproducing crash under concurrent load (see [ADR-00093](../adr/ADR-00093.md)). Requires `bdw-gc`/`libgc` installed at build time (`brew install bdw-gc` / `apt-get install libgc-dev` / `apk add gc-dev`) — this compiler's first non-libc external dependency, and only for binaries actually compiled with `-mm=gc`. See [ADR-00071](../adr/ADR-00071.md). |
| `auto` | ❌ Not started | The compiler, at compile-time-proven-safe points — no runtime collector at all | Staged like Rust's ownership model but much smaller in scope: Stage 2 is a `/** @free */` JSDoc annotation plus a conservative local escape check (insert `free()` at every exit path of the enclosing block, reject the annotation if the value might escape); Stage 3 is a `@owned` linear-value annotation with real last-use liveness analysis, freeing right after a value's statically-determined last use rather than at block-exit. `Memory.free(x)` would be a compile error in this mode (the compiler's own inserted frees can't account for a manual free it didn't plan for). See [TDD-00001](../tdd/TDD-00001.md)'s Design section for the full staging rationale and why a Rust-style borrow checker was ruled out as disproportionate to this project's scope. |

## Why this matters

Every heap allocation this compiler emits (arrays growing/`push`ing, object literals, closure environments, string concatenation/slicing/template literals, `Map`/`Set` backing tables, JSON/Date formatting scratch buffers, boxed `any`/`unknown` payloads, …) goes through a plain `malloc`/`realloc` call. In `manual` mode that's never freed except by an explicit `Memory.free(x)` — a complete non-issue for the short-lived CLI processes every example/test compiles to today, but a hard blocker for this project's other stated direction: long-running microservice-style processes fronting `http.listen`. `-mm=gc` is a one-flag opt-in fix for exactly that gap; see the [Roadmap](README.md#roadmap)'s Structural priorities for the current sequencing read.
