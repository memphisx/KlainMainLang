# ADR-01612: A guard on runtime objects' undefined symbols

- **Relations**: Implements TDD-00251 (Stage 1)
- **Date**: 2026-10-13

## Context

Windows' COFF link resolves every object's references, so a runtime C file
that names a symbol only some programs define fails there while Linux and
macOS link it (TDD-00251). Such references were found one link error at a
time on Windows (ADR-01597).

## Decision

`TestRuntimeSymbolsResolveWithinRuntime` compiles every runtime C source a
feature-heavy program pulls in (through the object cache), lists each
object's defined and undefined symbols (`llvm-nm`, or binutils `nm`), and
fails on an undefined `__kml_` symbol that no runtime object defines and
`tests/testdata/runtime_symbols_allowlist.txt` does not list. On Windows
the shim's `__kml_win_` symbols are its own object's. The list holds the 59
symbols the generated program provides today (category B: `__kml_str_alloc`,
`__kml_current_task`, the connection table, the `any` helpers, …); TDD-00251
Stage 4 moves them into the registered hook table and the list empties.
`KML_PRINT_RUNTIME_SYMBOLS=1` prints the current set.

## Verification

Windows 11: passes with the list; removing an entry fails it, naming the
runtime files that use the symbol. Linux and macOS: run there and add any
POSIX-only names.
