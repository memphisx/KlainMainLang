# ADR-00823: Lazy Response body promises settled off the fetch reactor

- **Relations**: `Implements TDD-00186`, `Extends ADR-00794`
- **Date**: 2026-09-10

## Context

`Response.text()/json()/arrayBuffer()` returned a real `Promise<T>` (ADR-00794),
but built it eagerly: the accessor drove the transfer to done *at the call site*
(`emitResponseDriveToDone` → `__kml_await_fetch`) and wrapped the finished value
in an already-settled promise. Two gaps remained, both flagged as the deferred
"lazy variant" in TDD-00186:

- **A JSON parse error was a synchronous throw, not a rejection.** `r.json()` on
  a malformed body threw the `SyntaxError` before any reaction could attach, so
  `r.json().then(onF, onReject)` / `.catch()` never saw it — the throw escaped
  and, in a `.then`-only flow, silently ended the async function.
- **No overlap.** `const p = r.json(); work(); await p` drove the body to done at
  `r.json()`, so `work()` ran only after the download.

## Investigation

- `__kml_await_fetch` parks on a fiber/task context but **busy-drives inline on
  the bare loop context** (`runtime_fetch.go:155`), so deferring the drive to a
  microtask would *block* the loop during download — a regression, since
  `await r.json()` already parks and is non-blocking today.
- The reactor already has a completion hook: `__kml_curl_drain_messages` sets
  `pending->done = 1` on `CURLMSG_DONE` and calls `__kml_fetch_body_on_done`
  (`runtime_fetch.go:391`) — the natural place to settle a body promise.
- `emitJSONParseValue` throws a catchable `SyntaxError` on malformed input
  (TDD-00077 Track P, `emit_call_json.go:734`), so a setjmp guard around it
  turns the parse failure into a rejection.
- At settle time `pending->done` is already set, so `emitResponseDriveToDone`
  extracts the buffered body without parking — meaning the settle runner can
  **reuse the eager `emitResponseBody`/`emitJSONParseValue`/`emitResponseArrayBuffer`
  emitters verbatim**, collapsing the implementation.

## Decision

`text()/json()/arrayBuffer()` now return a **pending** promise registered against
the Response's in-flight fetch handle and settled off the reactor's completion:

- A body-promise registry (`runtime_fetch_bodyprom.go`, plain thread-local
  memory) holds `{ pending, closure }` entries. `__kml_fetch_bodyprom_register`
  settles synchronously when the fetch is already done (or the handle is null —
  body previously driven), else parks the entry. `__kml_fetch_bodyprom_on_done`,
  called from the curl drain right after the existing hook, fires and removes
  every entry keyed to the completed handle.
- The closure is a per-kind synthesized settle runner
  (`@__kml_fetch_bodyprom_run_<method>`) built through the IR-builder-swap idiom:
  under a setjmp guard it builds the value with the reused emitters and settles
  the promise fulfilled, or — on a JSON `SyntaxError` — rejected.
- The promise + Response stay reachable via the awaiting task's own GC-scanned
  stack, so the registry needs no GC rooting (like `runtime_http_reqbody.go`).

The `__kml_fetch_body_on_done` hook is left untouched; the new drain is a
*separate* call in the curl loop, so streaming-fetch bodies are unaffected.

## Implementation notes

- New `usedFetchBodyProm` gate emits a no-op `__kml_fetch_bodyprom_on_done` stub
  when unused, so the drain reference always resolves.
- The runner reuses `emitResponseBody` etc. inside the builder swap; the drive
  they emit is a no-op branch at runtime because `pending->done` is set.
- `emitResponseCall` is fully rewritten from the eager `wrapSettledTaskPromise`
  path to the register-and-return-pending path; the typed declaration-context
  `json()` fast path (`emitResponseJSON`) is unchanged.

## Side effects discovered

The untyped `await r.json()` value round-trips as before (a pre-existing quirk
that `JSON.stringify` of the generic parsed value prints `""` is unrelated and
untouched). No streaming-fetch regression (separate hook).

## Verification

- New E2E tests (`tests/fetch_test.go`, `/badjson` route): a parse error reaches
  `.then`'s onRejected and `await`+`try/catch`; a well-formed body still
  fulfills through the lazy path. The full fetch / async / promise / http / stream
  suites pass. Manual repro against a local server confirms the rejection reaches
  `.catch` (the pre-lazy build threw uncaught and skipped the handler).
- `go build`, `go vet` pass.
