# ADR-01043: The conformance run's invalid-IR bucket — absent scalars in Number/Math, mistyped stores, void initializers

- **Relations**: `Extends ADR-01040, ADR-00479, ADR-00571`; `Implements TDD-00187` (the `{ i1, T }` optional reaching consumers that took a bare scalar)
- **Date**: 2026-09-21

## Context

Every file in the conformance report's `clang` phase is IR that clang rejected — a codegen bug by definition,
whatever the test was about. The reports cap their lists and the summary only counts, so the names were unknown.
One Test262 run with `-faillist` produced them (strict lane, Windows x64):

| File | clang said |
|---|---|
| `harness/nans.js` | `'%t59' defined with type '{ i1, double }' but expected 'double'` (`fcmp`) |
| `staging/sm/Iterator/prototype/reduce/left-associative.js` | `'%t40' defined with type 'ptr' but expected 'double'` (`store`) |
| `staging/sm/RegExp/exec-lastIndex-ToInteger.js` | `'%t188' defined with type 'ptr' but expected 'i64'` (`store`) |
| `staging/sm/RegExp/replace-sticky-lastIndex.js` | `constant expression type mismatch: got type 'ptr' but expected 'i64'` |
| `staging/sm/regress/regress-559402-2.js` | `void type only allowed for function results` (`alloca void`) |
| `language/expressions/modulus/S11.5.3_A4_T7.js` | link: `multiple definition of 'truncate'` |

All but the last reproduce from a few lines of ordinary TypeScript.

## Investigation

- **`Number.isNaN(xs[i])`** — since ADR-01040 an element read that may be out of range is a `T | undefined`
  optional, a `{ i1, T }` aggregate. `emit_call_number.go` and `emit_call_math.go` evaluated their argument with
  `emitExpr` and used the register as a `double`. Same for a `Map.get` result and an omitted optional parameter.
  Node: `Number.isNaN/isFinite/isInteger/isSafeInteger(undefined)` are `false`; the *global* `isNaN`/`isFinite`
  ToNumber first, so `isNaN(undefined)` is `true`, `isFinite(undefined)` `false`, and for `null` (ToNumber 0) the
  other way round; `Math.f(undefined)` is `NaN`.
- **`xs.reduce((x, y) => `(${x}+${y})`, 0)`** — the accumulator slot takes the initial value's type; `coerce` has
  no string→number conversion and returns the value unchanged, which was then stored into the `double` slot. tsc
  rejects the program ("No overload matches this call").
- **`p.n = "foo"` / `re.lastIndex = "1"`** — the *variable* reassignment path rejects a value whose IR differs
  from the slot's (ADR-00571, `emit_exprs_assign.go`); the *field* path stored whatever `coerce` handed back. A
  RegExp is an ordinary object here, so `lastIndex` went the same way. tsc: TS2322.
- **`var r = (function () { … })()`** — ADR-00479 rebinds a void initializer's name as `undefined`, and the
  call-inference branches each avoid adopting `void` as the slot type; an IIFE callee reaches none of them, so
  `alloca void` was emitted before the handler ran. Two neighbours found with the same probe: `c = nothing()`
  into such a binding was rejected ("cannot assign a void value"), and `console.log(nothing())` printed no token
  at all (Node: `undefined`), which also dropped its separator / newline.
- **`truncate`** — not an emitter bug. The CLI always goes through the resolver, which mangles top-level names
  per file (`truncate__kml_mod0`); the conformance harness calls `parser.Parse` on its concatenated source and
  emits `@truncate`, which collides with the platform layer's `truncate`. See Side effects.
- While writing the tests: a global `str.replace(re, …)` left `re.lastIndex` just past the last match (`/a/g`
  over `"aaa"`: 3; Node: 0). The fill pass stops after the counted matches and never runs the failing match that
  resets it.

## Decision

- `emitNumberPredicateOperand` / `numberPredicateResult`: the four `Number.isX` predicates and the global
  `isNaN`/`isFinite` split an optional into presence + payload, answer for the payload, and select the absent
  answer by presence — `false` for `Number.*`; for the globals what ToNumber gives (`undefined` → NaN, `null` →
  0). The argument is evaluated with `emitPreserveNullableOperand`, so a nullable *local* keeps its presence bit
  too. `emitNumberIsNaN`/`emitNumberIsFinite` take a `global` flag from their two call sites.
- `emitMathOperand`: every `Math.*` argument is demoted to its payload. An absent float payload is NaN
  (ADR-01040), which is ToNumber(undefined).
- `emitArrayReduce`: a callback result whose coerced IR is not the accumulator's is a compile error naming both
  types.
- Field `=` / compound assignment: after `coerce`, a plain (non-array, non-dynamic, non-optional) field whose IR
  the value does not have is a compile error in tsc's wording, naming the field.
- `emitVarDecl`: one net under all inference branches — a `void` slot type falls back to the default slot, which
  stays dead once the void handler rebinds the name. A void result assigned to an `undefined` binding is
  accepted and leaves it `undefined`. `console.*` prints `undefined` for a void argument.
- `emitRegexReplaceAllMatches` stores `lastIndex = 0` after the fill pass.
- `tools/conformance`: on `CLANG_ERROR` the IR and clang's full output are kept under
  `<workdir>/clang-fail/`; under `-compat=both` `-faillist`/`-passlist` write one file per lane
  (`<path>.strict`, `<path>.js` — only the last lane's survived before); a filtered run (`-category`, `-limit`)
  no longer merges its slice totals into the shared `conformance-summary.json`.

## Implementation notes

`codegen/llvm/emit_call_number.go`, `emit_call_math.go`, `emit_call.go` (the `global` flag),
`emit_arrays_hof.go`, `emit_exprs_assign.go`, `emit_exprs_vardecl.go`, `emit_call_console.go`,
`emit_regexp_replace.go`, `tools/conformance/main.go`. Tests: `tests/invalid_ir_bucket_test.go`.

An absent element of an **integer** array has payload 0, not NaN (ADR-01040: i64 has no NaN), so
`Math.abs(ints[9])` is 0 where Node gives NaN; the `Number.*`/global predicates are exact for both payload kinds
because they go by the presence bit.

## Side effects discovered

- The conformance harness does not run the resolver, so it measures a pipeline the CLI never uses: top-level
  names are unmangled (the `truncate` collision; on a POSIX host a user function named like a libc symbol would
  silently *replace* it inside the test binary). Routing the harness through the resolver changes what every file
  in the corpus compiles as, so it needs a full before/after run to land.
- The `y` (sticky) flag is accepted and has no semantics (status row "`u` / `y` / `d` flags": missing):
  `/a/y` with `lastIndex = 1` still matches at 0. `replace-sticky-lastIndex.js` and a probe of
  `replace`/`test`/`match`/`search` under `y` all differ from Node.
- `"ba".match(re)?.index` is a compile error (`no field 'index'`): the match result has no `index`/`input`/
  `groups` (already a caveat on the `.exec()` row).
