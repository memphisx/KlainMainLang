# ADR-01475: A class's type parameters are types; null is no type parameter

- **Relations**: Extends ADR-01473
- **Date**: 2026-10-08

## Context

After ADR-01473 the TypeScript suite's strict lane lost agreement on four
cases tsc rejects — `genericCloneReturnTypes2`,
`genericReversingTypeParameters`, `genericReversingTypeParameters2` and
`genericWithOpenTypeParameters1` — and its js lane on six. They had been
rejected only because codegen failed on a generic class's method called
through an annotation; with that fixed, they compiled.

## Investigation

- The suite's report lists only samples, so the conformance runner's
  `-passlist` now writes the TypeScript suite's verdicts too (`case`, tab,
  status, per lane). Running the suite with ADR-01473 switched off and on
  showed exactly those cases flipping.
- tsc rejects them for `return null` where the declared result is a type
  parameter (TS2322), among others. The checker accepted that in a generic
  function and a generic class alike:
  - relate (checker/relate.go) answered *maybe* for any relation to a type
    parameter, so a concrete source was never rejected;
  - the binder declared a function's type parameters in its scope but never a
    class's, so `V` in a member resolved to nothing and every check against it
    was unanswered.
- `class C<V> implements I<V>` did not parse (type arguments after
  `implements`), and codegen rejected `implements` on a generic class,
  though the clause emits nothing.

## Decision

- A primitive, a primitive literal, null or undefined is not assignable to an
  unconstrained type parameter (the parameter may be any other type).
- The binder declares a generic class's type parameters in a scope of their
  own around its members. The checker types such a symbol as the parameter
  the class's instance type is built with (`classTypeParam`), and inside an
  instantiation's members as its argument, which `instanceOf` binds in the
  environment.
- `implements` takes qualified names and type arguments; a generic class may
  implement an interface.

## Implementation notes

checker/relate.go, checker/generics.go (`typeParamType`),
checker/symbols.go (the type-parameter reference), binder/binder.go
(`class`), parser/parser_classes.go, codegen/llvm/emit_classes.go,
tools/conformance/ts.go and main.go (`-passlist` for `-suite=ts`),
checker/check_test.go. codegen/llvm/libsplit.go compiles a library unit
from a unique temporary file, so two compiles of one unit in one process
(a parallel run's goroutines) no longer share one.

## Side effects discovered

- The checker does not check an `implements` clause (TS2420); codegen checks
  a non-generic class's fields and methods against the interface, a generic
  class's not at all (BACKLOG).
- A `var` read before assignment is not TS2454 here (documented: `var` is
  exempt); for a generic class's `var a: C<string>` the read is a misleading
  codegen error ("an array has no method").

## Verification

- `TestCheck`: `return null` and `const x: V = 5` in a generic class,
  `return null` in a generic function, a member returning `this.v`, and a
  generic class implementing a generic interface.
- The generic-class, goroutine, extends-Array and for-of E2E tests; the
  checker's generics tests (an instantiation's members keep their argument
  types).
- Gates on the Linux boxes, for ADR-01471 to ADR-01475 together.
