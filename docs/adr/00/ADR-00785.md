# ADR-00785: `encoding` and `flag` options on `readFileSync`/`writeFileSync`/`appendFileSync`

- **Relations**: extends the sync `fs` file-I/O ([ADR-00021](ADR-00021.md), [ADR-00094](ADR-00094.md) the byte-safe siblings); addresses the "no `options`/`encoding`/`mode`/`flag` arg on write/append/read" gap in BACKLOG §3
- **Date**: 2026-09-08

## Context

`readFileSync`/`writeFileSync`/`appendFileSync` accepted only `(path)` /
`(path, data)` — the ubiquitous `readFileSync(path, 'utf8')` and
`writeFileSync(path, data, 'utf8')` idioms were a hard compile error
("takes exactly N arguments"). `fs` is the project's #2 priority, and the
encoding argument is the single most common `fs` call shape in real Node code.

## Decision

A shared `fsTextOption` parser (`emit_fs.go`) accepts the optional trailing
argument on all three calls: either a bare encoding **string literal**
(`'utf8'`/`'utf-8'`) or an **object literal** with a subset of
`{ encoding, flag }`.

- **`encoding`** must be `'utf8'` — this compiler's strings are UTF-8, so the
  encoding is a faithful no-op and the read result stays a `string`. Any other
  encoding is a clean rejection (not a silent wrong-decode).
- **`flag`** on `writeFileSync` beginning with `'a'` (`'a'`/`'a+'`/`'as'`)
  routes to the existing append runtime (`__kml_fs_append_file`
  /`__kml_fs_append_file_bytes`) — `writeFileSync(p, d, { flag: 'a' })` appends,
  as in Node; `'w'`/absent truncate (the default). `appendFileSync` always
  appends, so it ignores the flag. `readFileSync` parses but does not act on a
  flag (a plain read).
- The byte-data paths (ArrayBuffer/TypedArray, ADR-00094) inherit the same
  append routing, since the flag flips `isWrite` before the runtime-fn choice.

No runtime change was needed — this is argument parsing plus reuse of the
write/append runtimes already in place.

## Not in scope (clean rejections / documented residue)

- **`mode`** (creation permissions) — needs the write `open()` to thread a mode
  argument; rejected cleanly for now rather than silently ignored.
- **Non-`'utf8'` encodings** (`'base64'`/`'hex'`/`'latin1'`) — no byte↔text
  transcoding layer yet.
- **`readFileSync(path)` with no encoding still returns a `string`, not a
  `Buffer`** — the pre-existing documented divergence (use `readFileSyncBytes`
  for the byte form); this ADR does not change the default return type, only
  adds the explicit-encoding form. Making the default a `Buffer` is a separate,
  breaking change.

## Verification

Verified on macOS/Apple Silicon: `readFileSync`/`writeFileSync`/`appendFileSync`
with `'utf8'` and `{ encoding: 'utf8' }`, `writeFileSync` `{ flag: 'a' }` append
vs `{ flag: 'w' }` truncate — all matching `node`. Non-utf8 encoding and `mode`
reject cleanly. New `TestE2EFsReadWriteEncodingOption`/`…AppendFlag`/
`…BadEncodingRejected`/`…ModeOptionRejected` (and the retargeted arg-count
test), the updated `examples/fs/fs.ts`, full `make test-par`, Node oracle.
