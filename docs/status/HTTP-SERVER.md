| `http.listen(port, handler)` — bind, accept, dispatch | ✅ | | • One fiber per accepted connection (`ucontext.h`), so a slow connection never blocks the others<br>• Runs on the shared `select()` event loop with timers, fetch, and the other socket APIs<br>• [TDD-00006](../tdd/TDD-00006.md), [ADR-00048](../adr/ADR-00048.md), [ADR-00049](../adr/ADR-00049.md), [ADR-00052](../adr/ADR-00052.md) |
| `http.listen(port, handler, { workers: N })` — multi-process clustering | ✅ | | • `fork()`s `N-1` workers sharing the listening socket — parallelism across cores on top of each process's own fiber concurrency<br>• `cluster.isPrimary`/`cluster.workerId` (0 = original, 1..N-1 per fork) branch on the current process<br>• Works under both memory modes<br>• [TDD-00025](../tdd/TDD-00025.md), [ADR-00097](../adr/ADR-00097.md)–[ADR-00101](../adr/ADR-00101.md) |
| Request-line parsing (`req.method`, `req.path`) | ✅ | | • Any method token (`GET`/`POST`/`PUT`/`DELETE`/...), not GET-only<br>• `req.path` excludes the query string (that's `req.query`)<br>• [ADR-00072](../adr/ADR-00072.md) |
| Request headers (`req.headers: Map<string, string>`) | ✅ | | • Lowercased keys (case-insensitive lookup, matching real HTTP semantics) — [ADR-00072](../adr/ADR-00072.md) |
| Query string (`req.query: Map<string, string>`) | ✅ | | • Split from `req.path` and parsed (`a=b&c=d`), both keys and values percent-decoded via the same `decodeURIComponent` primitive this compiler already had — [ADR-00072](../adr/ADR-00072.md) |
| Request body (`req.body: string`) | ✅ | • The plain string `req.body` still truncates at an embedded null byte (every string here is a null-terminated C string) — use `req.bodyBytes()` for a binary-safe body | • `Content-Length`-aware, accumulated across reads, capped at 10MiB — [ADR-00072](../adr/ADR-00072.md) |
| Binary-safe request body (`req.bodyBytes(): ArrayBuffer`) | ✅ | | • The binary-safe counterpart to `req.body: string` — wraps the same already-buffered, `Content-Length`-accurate bytes into an `ArrayBuffer` (no copy), so a body with an embedded null byte survives whole where `req.body`'s own string operations would truncate it<br>• See [TDD-00026](../tdd/TDD-00026.md)/[ADR-00106](../adr/ADR-00106.md) |
| Response headers (optional `headers: Map<string, string>` field) | ✅ | | • Fully user-controlled, including `Content-Type` if set — omitting the field behaves byte-identically to before this existed — [ADR-00072](../adr/ADR-00072.md) |
| Binary-safe response body (optional `bodyBytes: ArrayBuffer` field) | ✅ | • The plain string `body` field it supersedes still truncates at an embedded null byte — this `bodyBytes` field is the additive binary-safe escape hatch, not a fix to the string field | • Wins outright over `body`'s own string content whenever present and non-null — the response writer (`__kml_http_send_response`) writes the body via an explicit-length `write()` (not a NUL-terminated `sprintf %s`), so a binary payload with embedded null bytes reaches the socket whole<br>• See [TDD-00026](../tdd/TDD-00026.md)/[ADR-00106](../adr/ADR-00106.md) |
| Streaming response body (`body: ReadableStream<string \| Uint8Array>` field) | ✅ | | • A handler whose returned object's `body` field is statically a `ReadableStream` produces a `Transfer-Encoding: chunked` response, written chunk-at-a-time by a promise-reaction-driven writer — the handler returns immediately and a slow producer holds only its own connection open; `http.close()` still waits for in-flight streams<br>• A stream error mid-response closes the connection without the chunked terminator (nothing else is signallable mid-stream)<br>• See [ADR-00300](../adr/ADR-00300.md) |
| Streaming request body (`req.stream(): ReadableStream<Uint8Array>`) | ✅ | • `req.body` after consuming `req.stream()` returns only the pre-stream prefix (spec: already-disturbed TypeError)<br>• `Object.keys`/JSON of `HttpRequest` expose an internal `__kml_bodyctx` field<br>• A handler must use one response `body` shape per program (mixing `string` and stream returns across branches trips first-return-wins type inference)<br>• The streaming mode requires `req.stream()` to be compiled before `http.listen`'s dispatcher — true for handlers and everything they reference | • Using `req.stream()` anywhere switches the program to headers-complete dispatch: the handler runs once headers are parsed and the body flows as `Uint8Array` chunks read off the socket (fiber-yield on EAGAIN, event-loop pump for non-fiber consumers); the 10MiB request cap then applies to the header block only<br>• `req.body`/`req.bodyBytes()` stay correct — they drain the remaining body into the pre-allocated buffer in place<br>• `req.stream()` piped into a streaming response body echoes without ever buffering the payload<br>• See [ADR-00301](../adr/ADR-00301.md), [ADR-00307](../adr/ADR-00307.md) |
| Graceful shutdown via `process.on('SIGINT'/'SIGTERM', handler)` | ✅ | | • The handler runs from ordinary control flow at the top of a loop iteration (never real signal context) and may clean up and `process.exit()` — [TDD-00019](../tdd/TDD-00019.md)/[ADR-00079](../adr/ADR-00079.md), [PROCESS-CLI.md](PROCESS-CLI.md) |
| `http.close()` (formal listener teardown, distinct from the graceful-shutdown row above) | ✅ | • Stops accepting new connections immediately and lets already-open ones finish naturally — it does **not** force-close in-flight connections ([TDD-00027](../tdd/TDD-00027.md))<br>• In a `{ workers: N }` cluster, `.close()` only affects the calling process's own copy of the listener — each worker is a separate `fork()`ed process with no IPC between them, so a full-cluster shutdown still requires an external signal to the whole process group | • A bare global function (like `http.listen` itself), reachable only from inside a running request handler, `setTimeout`/`setInterval` callback, or `process.on(...)` handler — the only places code ever runs "alongside" the event loop<br>• Already-open connections finish naturally before `http.listen()`'s own call actually returns control to the rest of the program<br>• See [TDD-00027](../tdd/TDD-00027.md)/[ADR-00102](../adr/ADR-00102.md) |
