# ADR-00779: Optional `?:` fields and destructuring absences as real `T | undefined` (TDD-00187 Stage 2)

- **Relations**: Implements [TDD-00187](../tdd/TDD-00187.md) Stage 2, on Stage 1's machinery ([ADR-00778](ADR-00778.md)); reuses [TDD-00064](../tdd/TDD-00064.md)'s field/local plumbing; supersedes the scalar-default rejection of [ADR-00158](ADR-00158.md) and the zero-read convention of [ADR-00157](ADR-00157.md) for these sites
- **Date**: 2026-09-08

## Context

Three ADR-00157-convention sites still zero-filled where TypeScript says
`T | undefined`: an omitted optional field (`interface P { y?: number }`, read
`p.y`) read calloc-zero, array destructuring past the source's length bound the
element type's zero, and the `?` marker itself was parsed but discarded
("treated as required for codegen"). Additionally, a `T | undefined` *annotation*
was indistinguishable from `T | null` (both resolved to bare `Nullable`), and a
destructuring default on a nullable-*scalar* field was rejected as unsound (its
"null" was an in-band 0 sentinel).

## Decision

**Optional fields become `name: T | undefined`.** `AnnotField` gains an
`Optional` flag (all four field parse sites: inline object types, interface
declarations — generic instantiation included — and class fields);
`resolveType`/interface registration/`genericClassMangledFields` widen an
optional field's type via `undefinedableElem`. The TDD's Stage 2 open question
(per-field `{ i1, T }` widening vs a presence bitmap) resolves to **per-field
widening** — and it costs nothing new, because `y?: number` now *is* a
nullable-scalar field and every piece of TDD-00064 Stage 3 machinery
(StructFieldIR's `{ i1, T }` slot, `storeScalarOrNullableFieldExpr`,
`loadScalarOrNullableField`) already handles it. The one deliberate alignment:
**calloc-zero of a `{ i1, T }` slot is `present=false`** — so an omitted field
reads back genuinely absent with no new initialization logic at all, and
ADR-00157's zeroing guarantee is what makes it sound. A pointer-typed optional
field (`s?: string`) keeps null-as-absent with the flagged static type.

**`| undefined` annotations carry the distinction.** `TypeAnnotation` gains
`Undefined` (set when the union's nullish member is spelled `undefined`),
propagated to `Type.IsUndefined` at every resolveType nullable site — so
`let u: number | undefined` renders/compares as `undefined` (previously
`null`) and engages the Stage 1 strict gate, while `| null` behavior is
untouched.

**Array destructuring past the source's length binds `undefined`** — but only
where absence is *possible*: a position that may be out of bounds (runtime
length) binds a nullable-scalar `{ i1, T }` local (absent on the OOB branch) or
a flagged pointer/dynamic local (`missRef` miss value). A provably-in-bounds
position (compile-time-constant source length, e.g. a literal init — the
`strconv.Atoi(lenVal)` check) and any position with a `= default` stay **bare
`T`**, matching tsc, which types tuple destructuring and defaulted bindings
bare. This carve-out is why the change broke zero examples.

**Destructuring defaults on nullable-scalar fields became sound.** The old
rejection existed because scalar "null" was an in-band 0; the presence bit
retires that. `{ y = 42 } = p` on a `y?: number`/`number | null` field now
branches on the stored presence bit — a legitimately stored `0` survives, only
genuine absence takes the default. Object destructuring of a nullable-scalar
field in general now copies the whole `{ i1, T }` slot into a nullable-scalar
local (it previously loaded the bare payload IR against the aggregate slot —
invalid IR, caught immediately by the first `const { y } = a` test).

## Corpus migration (measured)

Zero examples broke (278/278 first run). Eight E2E tests changed: five
asserted the zero-fill convention and now assert `undefined` (renamed
`…ReadsZero` → `…IsUndefined`), one rejection test
(`…DefaultOnNullableScalarFieldRejected`) inverted into a positive
zero-vs-absent test, one message-text update, one expected-output update
(`-optimize-memory` identity program prints `undefined` for its omitted
optional field).

## Consequences

- The `_index` known-gaps row shrinks to the honest residue: under-assigned
  **non-optional** class fields (no definite-assignment check) still read
  zero; an **array/tuple-typed** optional field stays bare (an omitted
  `tags?: string[]` reads as an empty array — its `{ptr,i64}` slot has no
  distinct absent state, same scope-out as Stage 1's nested-array elements);
  nested-array destructured elements keep the empty-array fallback.
- Field-level flow narrowing is still local-only: `if (p.y !== undefined)`
  compares correctly, but arithmetic on `p.y` inside the branch still needs a
  copy to a local, `??`, or `!` (TS narrows the member expression itself; this
  compiler narrows locals). Documented, not fixed here.
- Optional *parameters* (`f(x?: number)`) keep their ADR-00164 zero-default —
  a distinct site, left for a later stage alongside env/argv (Stage 3).

Verified on macOS/Apple Silicon: full `make test-par`, 278/278 examples
(+ the new `examples/objects/optional_fields.ts`), Node oracle flat.
