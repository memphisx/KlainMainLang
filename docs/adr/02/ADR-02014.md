# ADR-02014: A constructor function base that returns an object

- **Date**: 2026-11-21

## Context

A class extending a constructor function the program declares
(`function F() { return { fn: true }; } class E extends F {}`) ran F's
body on the new instance and ignored what it returned. Under ECMA-262
[[Construct]], F's returned object is the result of `super()`, so it is
the derived class's `this`. A class base whose constructor returns an
object already worked, with private names installed on the returned
object.

## Decision

- When F's own body returns a value, `super(…)` to it in the js lane
  passes that value through the constructor override slot. An object
  becomes `this`; a primitive is ignored.
- Such a class's instances are held as `any` (foreignCtorClass), as a
  class base's are. Its private names are installed on the object
  (overrideInstances).
- A derived class with no constructor of its own over such a base gets
  its default derived constructor written out (`constructor(...args) {
  super(...args); }`), so its fields and private names go on the returned
  object as well.

## Implementation notes

- codegen/llvm/emit_classes.go: `fnBaseReturns`, the super path,
  `ctorMayOverride`, `foreignCtorClass`.
- codegen/llvm/emit_privtab.go: `overrideInstances`.
- codegen/llvm/emit_heritage.go: `defaultCtorsOverReturningBases`.
