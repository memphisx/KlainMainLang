# ADR-01461: A -compat=js object-literal binding is a module global

- **Relations**: Implements TDD-00230 (P2.2); extends TDD-00022
- **Date**: 2026-10-07

## Context

The remaining `emitIdent` shadow rows were Test262 destructuring tests
whose generator reads a module-level `var iterable = {}`. Each failed to
compile with "undefined variable 'iterable__kml_mod0'"; so did any function
reading such a binding (`var o = {}; function f() { return o.x }`) under
`-compat=js`. The `reliableGlobalType` presence bucket (212 rows) was the
same binding: the oracle promotes it, codegen did not.

## Investigation

`decideGlobalType` refused an object literal under `-compat=js` because it
is a dynamic object, not a static struct, while `emitVarDecl` types the same
binding `any`. A function reading the binding names the global, which was
never declared.

## Decision

An unannotated object-literal binding under `-compat=js` promotes as an
`any` global, the type `emitVarDecl` gives it (as a cross-type-widened
binding already does).

## Verification

- `TestE2EJSObjectLiteralGlobals` (against Node); the js-lane, dynamic and
  object-literal E2E tests pass on the Mac.
