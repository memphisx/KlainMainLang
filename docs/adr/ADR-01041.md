# ADR-01041: An array that is not there — `T[] | null`, omitted `xs?: T[]`, and their TypeErrors

- **Relations**: `Extends ADR-01038, ADR-01040, ADR-00158`; `Implements TDD-00127, TDD-00213` (the header cell is the array's identity — its absence is the array's absence)
- **Date**: 2026-09-21

## Context

Found while writing ADR-01038's tests. A nullable array could not express "no array":

- `let a: number[] | null = null` — *"array variable must be initialized with an array expression"*; `a = null` — *"cannot assign a non-array value"*; `f(null)` into a `T[] | null` parameter — *"expression does not yield an array"*; `flag ? ["hit"] : null` — *"ternary operator is not supported for array types"*.
- An omitted `xs?: number[]` argument arrived as a fresh empty array: `xs === undefined` was `false`, `for (const x of xs)` iterated nothing and `[...xs]` was `[]` where Node throws `TypeError: xs is not iterable`, `xs[0]` reported the bounds error instead of `Cannot read properties of undefined (reading '0')`.
- `[] === null` was `true`, and an empty array was falsy: absence was tested on the *data pointer*, which an empty array shares with an absent one.
- `xs ?? "none"` was invalid IR (a string stored through the `{ptr, i64}` result slot), and `inferExprType` gave `xs ?? ys` the right operand's type while emission returned the left's.

## Investigation

- A named array is a slot holding a pointer to a shared `{data, len}` header (TDD-00127); an array Value carries that header in `Value.ArrayHeader`. Two absent forms already existed: a **null header** (a `Map<K,T[]>` miss, an unset field — read through `arrayValueFromHeaderSlotGuarded`) and a header-less `{null,0}` aggregate (a RegExp miss). ADR-01038's guard already tests the header (`emitNullDerefGuard`), and says why: the aggregate alone cannot tell absent from empty.
- The callee side derefs its header unguarded (`arrayDataLenSlots`), which is why omitted arguments were given an empty header (`emptyArrayArgHeader`) and `arrayArgFromAggregate` swaps a null header for a fresh one.
- A binding whose type is nullable is already read null-safely (`emitExpr`'s array-identifier path) and its member/index/call accesses are already guarded (`registerDerefGuard`); the unguarded readers left were `for…of`, spread/HOF resolution (`resolveArrayForHOF`), argument packing and `?.length`.

## Decision

**Absent = the null header, everywhere a header exists**; a header-less transient is absent when its data pointer is null. One predicate, `emitArrayIsAbsent`, implements that and replaces the three hand-written data-pointer tests (`=== null`/`=== undefined`, truthiness, `??`). An empty array is therefore present: truthy, `!== null`.

- **Producers.** `let a: T[] | null = null` / no initializer / `a = null` store a null header in the slot (only that binding — an alias keeps its array). `coerce(null → T[] | null)` yields `emitAbsentArrayValue` (the zero aggregate carrying a null header). `arrayReturnHeader` — the return, Map-value and ternary path — yields a null header for an absent value. An omitted `xs?: T[]` argument passes a null header when the parameter type is nullable (`omittedArrayArgHeader`); an empty *rest* array stays a real empty array.
- **Crossing a call.** `packArrayArg` takes the parameter type: into a nullable parameter a possibly-null header passes through unchanged; into a non-nullable one it is swapped for an empty array, as before, because that callee derefs unguarded. The plain-function call site now uses `packArrayArg` like the method/closure sites.
- **Consumers.** `arrayValueFromHeaderReg` reads a nullable result through a select onto one shared all-zero cell (`@__kml_absent_array`) — branchless, because it also runs inside state machines' linear control flow. `for…of` and `resolveArrayForHOF` call `emitNotIterableGuard` (`TypeError: xs is not iterable`). `xs?.length` is `number | undefined`.
- **Ternary.** `ternaryArrayType`/`emitConditionalArray`: the result slot holds the chosen branch's *header*, so the result aliases the array it picked.
- **`??`.** `nullCoalesceArrayResult` (shared with `inferExprType`): an array or nullish right operand gives the array type; anything else gives `any`, each side boxed (`emitNullCoalesceArrayAny`).

## Implementation notes

`emit_arrays_core.go` (`emitArrayVarDecl`, `omittedArrayArgHeader`, `emitAbsentArrayValue`, `emitArrayIsAbsent`, `emitNotIterableGuard`, `packArrayArg`, `arrayReturnHeader`, `arrayValueFromHeaderReg`, `resolveArrayForHOF`), `emit_call.go`, `emit_classes.go`, `emit_func.go` (omitted-argument and packing sites), `emit_exprs_assign.go`, `emit_exprs_coerce.go`, `emit_exprs_member.go` (`?.length`), `emit_exprs_operators.go`, `emit_exprs_types.go`, `emit_stmts.go` (`for…of`), `emitter.go`.

A promoted top-level binding keeps its declared type, so only a *declared*-nullable global can hold the null header; a non-nullable binding never receives one (`emitAssign` boxes instead).

## Side effects discovered

- `const v = ((x: number) => x === 1)(1)` stored the boolean in a number slot and printed `1`: `emitVarDecl`'s callee-name switch had no case for an immediately-invoked arrow / function expression and kept its blind default. Fixed (`emit_exprs_vardecl.go`, and the matching `inferExprType` case).

- `console.log(o.pair)` on an omitted optional **tuple** field read through the null pointer — undefined behaviour that hung the program on Windows. `emitValueToString` now renders the absent keyword. Fixed. (`o.pair === undefined` is still `false`: a tuple field has no absence test yet — the status row says so.)
- A SQL `NULL` blob was stored into its `Uint8Array | null` field as a fresh header around `{null,0}`, which the header-based absence test reads as present. `storeArrayFieldHeader` now goes through `arrayReturnHeader`. Fixed.
- An absent nested-array value stored as an element (`[e.at(9), e.at(0)]`) was boxed as a fresh header around `{null,0}` — present, under the header test. `storeArrayElem` now stores a **null box** for it, and `unboxArrayValue` reads any box through `loadArrayHeaderOrAbsent` (the same branchless null-safe load a nullable call result uses), so element reads never go through a null box. Caught by `TestE2ENestedArrayUndefinedConsoleLog`.
- The not-iterable guard covers an array reached through an expression too (`for (const t of o.tags)`, `[...get()]`), named as Node names it (`o.tags is not iterable`, `get is not a function or its return value is not iterable`); binding names are demangled.
