# ADR-00327: Node `dgram` — UDP sockets

- **Relations**: Implements TDD-00006 (the select()-based event loop); Extends ADR-00324 (shares the loop's hook-trio integration)
- **Date**: 2026-08-23

## Context

`dgram` (UDP) was one of the self-contained unstarted modules on
NODE-CORE-MODULES.md. Unlike `net`'s TCP server, a UDP socket has no accept
loop or per-connection state — a single fd both sends and receives — so it is a
simpler fourth member of the event loop's fd-folding hook-trio contract.

## Investigation

The hook-trio contract (keepalive / fdset_add / dispatch) and the shared
`@__kml_worker_fd_setbit` FD_SET helper are the same ones `net` (ADR-00324) and
`child_process` (ADR-00322) use; the loop edit that adds net's trio also added
dgram's in the same pass, so no further change to `@__kml_event_loop_run` was
needed here. `getaddrinfo` resolution now exists as `@__kml_dns_lookup`
(ADR-00326), which `send()` can reuse to accept a hostname or IP.

The 'message' listener receives `(msg, rinfo)`. `msg` is a Buffer — passed to
the closure as `(ptr, i64 len)`, the same ABI a `child_process` 'data' listener
already uses. `rinfo` is an object; to make `rinfo.address`/`rinfo.port` resolve
inside the listener body, the listener's second parameter is hinted with an
object type `{ address: string, port: number }`, and the runtime builds a
matching `{ ptr, i64 }` struct to pass.

## Decision

- `dgram.createSocket('udp4')` → a `DgramSocket` handle (ptr to
  `dgramSocketIR = { i64 fd, i64 state, ptr messageListener }`), created by
  `@__kml_dgram_create` (socket(AF_INET, SOCK_DGRAM) + O_NONBLOCK, registered).
- `socket.bind(port)` binds 0.0.0.0:port; `socket.on('message', (msg, rinfo) =>
  …)` stores the listener; `socket.send(msg, port, host)` resolves `host` via
  `@__kml_dns_lookup` then `inet_pton` + `sendto`; `socket.close()` closes the
  fd and marks the socket.
- Hook trio: `keepalive` is true while any open socket has a message listener
  (a bound receiver keeps the loop alive; a send-then-close socket does not);
  `fdset_add` adds every open socket fd; `dispatch` `recvfrom`s each open socket
  until EAGAIN, building a Buffer + rinfo `{ address, port }` (address from the
  source `sockaddr_in.sin_addr`, port from `ntohs(sin_port)`) and firing the
  listener.

## Implementation notes

- New `codegen/llvm/runtime_dgram.go` (runtime) and `emit_dgram.go` (codegen);
  `DgramSocketType` / `IsDgramSocket` in types.go.
- `inet_pton` is **not** re-declared: `ensureHTTPRuntime` (called for the event
  loop) always pulls in the WebSocket-client runtime, which already declares it
  — declaring it again is an LLVM redefinition error (caught on first compile).
- Registration/dispatch wired the same way as the other virtual modules
  (resolver marker, emit_call.go module + method branches, emit_exprs_types.go
  return type).

## Side effects discovered

None. `udp6`, `dgram.Socket` options objects, `'listening'`/`'error'` events,
and multicast are unimplemented and disclosed as caveats.

## Verification

- `tests/dgram_test.go`: a UDP echo server that replies to each datagram's
  sender (exercising receive + rinfo + send), driven by Go's UDP client.
- `examples/dgram/echo.ts` verified end-to-end on macOS (arm64) via a Python
  UDP client: the server logged the datagram and its source port and the client
  received the reply.
- Machine: verified on Mac (Apple Silicon). Not yet re-verified on Linux.
