# ADR-00939: Array binding shares the header cell (reference aliasing) + array `===` identity (TDD-00213 Stage 1)

- **Relations**: Implements TDD-00213 Stage 1; Relates to TDD-00127, ADR-00478, TDD-00212
- **Date**: 2026-09-14

## Context

Arrays were only partially reference-typed. `let a = b` (and reassignment
`a = b`) minted a *fresh* header for the new binding via
`newArrayHeader`/`boxArrayValue` and copied `b`'s `{data,len}` — a snapshot. So a
later reallocating `b.push(x)` swapped `b`'s header's data pointer, which the
independent header behind `a` never saw:

```ts
let b = [1, 2, 3]; let a = b; b.push(4);
console.log(a);        // [1,2,3]   — Node: [1,2,3,4]
console.log(a === b);  // (invalid IR — see below)
```

And array `===`/`!==` on two typed arrays was a hard **invalid-IR** bug:
`emit_exprs_operators.go` emitted `icmp eq ptr <left.Ref>`, but an array Value's
`Ref` is the `{ptr,i64}` aggregate, not a `ptr` (`array.IR == "ptr"`), so clang
rejected it. Array-vs-array equality was a known-untouched gap.

## Decision

Stage 1 of full array reference semantics (TDD-00213): a binding shares the
source array's header cell, and identity compares that cell.

- **Aliasing.** A var-decl (`emitArrayVarDecl`) or reassignment
  (`emit_exprs_assign.go`) of an array binding, when the initializer/RHS carries a
  live header (`Value.ArrayHeader`, the seed from TDD-00212 Stage 3 — set at the
  array-identifier eval), points the binding's slot at that **same** header cell
  instead of minting. So `a` and `b` alias: a `push` through either is visible
  through the other. A genuinely new array expression (literal, `new Array`,
  spread, `.slice()`/`.map()`/HOF result — no `ArrayHeader`) still mints its own
  header, so `a = a.filter(...)` / `let u = [...t]` correctly produce a distinct
  object.
- **Identity.** Array `===`/`!==` compares the identity pointer — `ArrayHeader`
  when present (shared cell), else the transient's own data pointer
  (`extractvalue 0`). Two bindings of one array are `===` (and stay so across a
  reallocating push, since the header cell is stable); two distinct arrays with
  equal contents are not. Fixes the invalid-IR crash.

## Implementation notes

Files: `codegen/llvm/emit_arrays_core.go` (`emitArrayVarDecl` generic branch
shares `ArrayHeader`), `codegen/llvm/emit_exprs_assign.go` (identifier-array
assignment shares `ArrayHeader`), `codegen/llvm/emit_exprs_operators.go`
(array-vs-array identity `===`/`!==`).

The fresh header minted at the top of `emitArrayVarDecl` before the initializer is
evaluated is discarded in the alias case (a small per-alias-decl leak, consistent
with TDD-00127's deferred-allocation posture); a later stage can defer the mint.

Scope: Stage 1 covers local `let`/`const` bindings and identifier reassignment.
Object/class fields (still inline `{ptr,i64}`) are Stage 2; returns and remaining
boundaries are Stage 3; the shared-buffer free policy is Stage 4.

## Verification

- `let a = b; b.push()` and `b = a; a.push()` are live in both directions;
  `a === b` true for aliases, false for distinct arrays; a spread/new array
  detaches; reassigning to a new array leaves the old alias untouched — all match
  Node. New `TestE2EArrayReferenceAliasing`.
- Broad array/object/class/collection/tuple/spread/JSON/dynamic/any/closure/func
  suites + `make examples`. macOS arm64.
