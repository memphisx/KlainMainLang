# ADR-00797: node:ffi Stage A — dlopen + statically-lowered typed C-ABI calls

- **Relations**: Implements TDD-00164 (Stage A); Supersedes the TDD-00032/TDD-00150 placeholder FFI sketch
- **Date**: 2026-09-09

## Context

TDD-00164 designed the general C FFI around Node's first-party experimental
`node:ffi` module (v26.1.0, `--experimental-ffi`): real Node module names get
the real Node API, so a program using Node's FFI compiles here unchanged. This
ADR ships Stage A — library loading and typed calls — plus the compile-time
signature machinery both later stages build on. Stage B (raw-memory helpers)
and Stage C (`registerCallback` trampolines) remain open in the TDD.

## Decision

**Surface.** `node:ffi` registers as a virtual builtin under the `node:`-only
specifier (same posture as `node:sqlite` — Node has no bare `ffi` module).
Shipped: `ffi.dlopen(path, definitions?)` → `{ lib, functions }`,
`new DynamicLibrary(path)`, `lib.getFunction(name, sig)`, `lib.getFunctions(defs)`,
`lib.getSymbol(name)`, `lib.close()` (idempotent), `ffi.dlsym`, `ffi.dlclose`,
`ffi.suffix`, `ffi.types.*`, and the bound function's `.pointer`.
`registerCallback`/`unregisterCallback`/`refCallback`/`unrefCallback` reject
with a clear message. POSIX only: a Windows host rejects the module cleanly
(no `LoadLibrary` shim yet).

**Signatures are compile-time constants.** A signature (and a `dlopen`/
`getFunctions` definitions map) must be an object literal; every type name —
including all alias spellings (`i32`, `ptr`, `str`, `double`, …) and the
`ffi.types.*` constants — normalizes to a canonical name at compile time
(`ffiParseSignature`, `emit_ffi.go`). This is the AOT trade the TDD called:
Node parses signatures at runtime; here they lower to a direct, correctly
typed indirect `call` through the `dlsym`'d pointer — no libffi, no generic
marshalling path, and the "Fast FFI" tier distinction disappears because every
call *is* the fast path.

**Value model.** A bound function is a bare symbol pointer whose compile-time
`Type` carries the signature (`IsFFIFunction` + `FFISig`); `DynamicLibrary` is
a two-field heap object (`__kml_handle`, `path`) flagged `IsFFILibrary`, the
node:sqlite handle shape. The `functions` object from `dlopen`/`getFunctions`
is an ordinary object type with one `IsFFIFunction` field per definition, so
destructuring, member reads, and passing it around all come free from the
object machinery. Because bindings are compile-time values there is no runtime
registry: the `library.functions`/`library.symbols` accumulator properties and
`getSymbols()` are not available (documented caveat).

**Marshalling.** Ints ≤32 bits truncate from `number` (i64) and widen back
sext/zext per signedness; `int64`/`uint64` marshal to/from `bigint`
(`__kml_bigint_*`), also accepting a plain `number` argument (looser than Node,
which requires `bigint` — documented caveat); `float32` narrows/widens through
`double`; `string` args pass the NUL-terminated string pointer, `string`
returns copy via `__kml_str_from_cstr` (`null` → `null`); pointer-family args
accept `null`/`undefined` → null, `bigint` → raw address, and
Buffer/TypedArray/ArrayBuffer → the backing data pointer; `pointer` returns
surface as `bigint` addresses. All exactly node:ffi's documented conversions.

**libdl.** `dlopen`/`dlsym`/`dlclose`/`dlerror` are `ensure*()`-declared once
(`runtime_ffi.go`); Linux adds `-ldl` via `requireLink` (a compat stub on
glibc ≥ 2.34); macOS finds them in libSystem. `dlopen(null)` opens the current
process image, so libc is callable with zero external dependencies. Failures
(`dlopen`, unresolved symbols) throw a catchable `Error` carrying `dlerror()`.

**Parser fix ridden in on.** `{ return: 'int32' }` exposed that the
object-literal parser rejected reserved words as property names — real JS/TS
allow any keyword there. Keyword tokens are now accepted as property keys
contextually (when `:` or `(` follows), which also un-wedged a handful of Node
conformance files that failed at that parse error.

## Consequences

- Any C library with scalar/string/pointer entry points is now callable from
  TS with no glue code; the `opentui`/GUI/ncurses/DB-client cluster waits only
  on Stage C's callback trampoline.
- A runtime-computed signature has no AOT lowering and is rejected with a
  message saying signatures resolve at compile time (exotic even in Node).
- `using`/`[Symbol.dispose]` disposal stays a follow-up (its own parse form,
  gated on TDD-00063 Stage 3 symbol keys); `.close()` is the disposal path.
- `ffi.getCurrentEventLoop()` has no faithful value here (no libuv loop) and
  stays unimplemented pending Node stabilizing the API.

## Verification

- `tests/ffi_test.go` (macOS M4): libc-via-`dlopen(null)` calls (`strlen`/
  `pow`/`getpid`/`strchr`), a custom clang-built shared library exercising
  every scalar width, sign extension, `int64`↔`bigint`, `float32`, buffer
  mutation visible from C, `string` returns, `.pointer`, missing-symbol
  throw/catch, `dlclose` + idempotent `close()`, compile-time rejections
  (non-literal signature, unknown type name, `registerCallback`).
- `examples/ffi/ffi.ts`. Node oracle re-run: aggregate flat, with a few files
  advancing past the former `{ return: ... }` parse failure.
