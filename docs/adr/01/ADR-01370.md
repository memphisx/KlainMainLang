# ADR-01370: A Date variable compound-assigned with arithmetic widens under -compat=js

- **Relations**: Extends TDD-00162's cross-type widening
- **Date**: 2026-10-03

## Context

Backlog 58. Under `-compat=js`, `let d = new Date(0); d += 1` kept `d` a
Date. JavaScript makes it the string of the date followed by `1`, and
`d -= 5` makes it the number -5.

## Investigation

`crossTypeWidenedBindings` widens an untyped binding to the any-box when it
is assigned values of two scalar kinds. A Date is not a scalar kind, and a
compound assignment's result type was never noted.

## Decision

Under `-compat=js`, an untyped `let`/`var` initialized with a Date and then
compound-assigned with any arithmetic operator (not `??=`, `||=`, `&&=`) is
widened to the any-box from its declaration. The compound assignment then
stores what JavaScript computes. The strict lane is unchanged: tsc rejects
`d += 1` on a `Date` binding.

## Implementation notes

`codegen/llvm/emit_func.go` (`crossTypeWidenedBindings`).

## Verification

Mac (Apple Silicon), against Node 24: `+=` gives a string, `-=` a number, and
a plain reassignment keeps a Date (`TestE2ECompatJSDateCompoundAssignWidens`);
the compat-js and Date groups. The time-zone name Node prints for a 1970
date (ICU's) differs from the C library's, the existing caveat on the Date
row.
