# ADR-00282: `typeof` correctness cluster — built-in values are "object", namespaces/constructors/undeclared answer statically

- **Relations**: Extends the compile-time `typeof` model (the Operators row); found by the same sweep as [ADR-00281](ADR-00281.md)
- **Date**: 2026-08-21

## Context

Seven `built-ins/Promise` Test262 files **compiled and exited nonzero** —
`assert.sameValue(typeof Promise.all, "function")` and friends. Probing showed a
whole cluster of silently wrong `typeof` answers:

- `typeof Promise` / `typeof Promise.all` / `typeof Math.floor` /
  `typeof JSON.parse` / `typeof <class name>` / `typeof undeclared` → `"number"`
  (JS: `"function"` / `"undefined"`);
- `typeof <promise/Map/Set/generator-instance/null>` → `"string"`,
  `typeof new Date()` → `"number"` (JS: `"object"` for all).

Two root causes: `typeofString` checked bare `IR == "ptr"` → `"string"` before
any heap-backed built-in flag, with a `"number"` default swallowing the zero
Type; and namespace/constructor references aren't expressions at all here, so
inference had nothing to say and the default answered.

## Decision

- **`typeofString` reordered**: `IsUndefined`/zero Type → `"undefined"`; the
  full heap-backed built-in flag set (`IsPromise`, `IsMap`, `IsSet`,
  `IsGenerator`, `IsDate`, `IsResponse`, `IsClass`, `IsError`, `IsRegExp`,
  `IsArrayBuffer`, `IsTypedArray`, URL/Headers/Request/EventEmitter, tuples,
  `IsNull`, …) → `"object"` ahead of the ptr→string case.
- **`typeofStaticAnswer`** resolves `typeof` statically before inference, for
  arguments that aren't first-class values in this runtime: user classes and
  implemented built-in constructors (`Promise`, `Map`, `Date`, the error
  family, TypedArrays, …) → `"function"`; `Math`/`JSON`/`console`/`globalThis`
  → `"object"`; implemented global functions (`fetch`, `setTimeout`,
  `queueMicrotask`, `parseInt`, …) → `"function"`; an *unimplemented* or
  undeclared name → `"undefined"` (JS's `typeof undeclared`, and honest for
  runtime-absent statics like `Promise.try`). Member tables cover the
  `Promise` combinators, the `Math` function set, and `JSON.parse`/`stringify`.
  A user binding shadowing any of these names wins (scope lookup first).
- **`inferExprType` gains `NewMapExpression`/`NewSetExpression` cases**
  (mirroring the emitters' defaults) — an inline `typeof new Map<K,V>()` was
  falling to the numeric default even after the reorder.

## Implementation notes

- `codegen/llvm/emit_exprs_operators.go` (typeofString, the tables,
  typeofStaticAnswer, the `emitUnary` hook), `emit_exprs_types.go` (Map/Set
  inference).
- The tables list only what the runtime implements — `typeof` never claims
  `"function"` for a static that would fail to compile if called.

## Side effects discovered

- Static-method references on namespaces *outside* the tables —
  `Object.keys`, `console.log`, `Number.isInteger`, `Date.now` — still answer
  from inference (`"number"`), not `"function"`; disclosed as the typeof row's
  caveat rather than growing an open-ended table piecemeal.
- `typeof g()` over a never-otherwise-called generator surfaced a latent
  emission corner: the generator's declaration references
  `@__kml_gen_pending_obj`, which only a real call site ensures — a program
  whose *only* use of a generator is `typeof g()` fails at `clang` with an
  undefined-global error (pre-existing; typeof emits no argument code by
  design). Left as-is: no valid program miscompiles, and the shape is
  pathological.

## Verification

- New E2E: `TestE2ETypeofBuiltinValues` (promise/class/Map inline + bound/Set/
  generator/null/Date/Error → `object`), `TestE2ETypeofNamespacesAndUndeclared`
  (constructors/statics/`Math.PI`/`Promise.try`/undeclared).
- `built-ins/Promise` conformance category: 1 → 8 passing (all seven
  wrong-at-runtime files now pass); the aggregate number is re-run at delivery.
- `go build`, `go vet ./...`, full `go test ./...` green. macOS (Apple Silicon).
