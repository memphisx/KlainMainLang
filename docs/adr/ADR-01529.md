# ADR-01529: A returned empty array keeps its pushed element type

- **Relations**: Extends TDD-00205
- **Date**: 2026-10-10

## Context

`function f() { const out = []; out.push("s"); return out }` emitted
`out` as `string[]` (the empty-array usage pass) but its return type was
inferred as the blind `number[]` default: the return-type inference
neither ran that pass nor bound the literal through it. The caller then
read string pointers as doubles. The pass itself also skipped `for-in`
bodies and left `for-of`/`for-in` loop variables unbound, so a pushed
loop variable defaulted to a number (`for (let p in x) a.push(p)` gave
`NaN`s).

## Decision

- Return-type inference runs the empty-array pass over the body and
  binds an array-literal local through `declaredArrayType`, as emission
  does.
- The pass walks `for-in` bodies and binds the loop variable: a for-of's
  to the iterable's element, a for-in's to a string.
