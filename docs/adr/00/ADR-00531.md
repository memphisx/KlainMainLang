# ADR-00531: `Number.isInteger` is false for non-finite values

- **Relations**: (none)
- **Date**: 2026-08-31

## Context

`Number.isInteger(Infinity)` and `Number.isInteger(-Infinity)` returned `true`;
real JS returns `false` (only a finite integer-valued Number is an integer).
`Number.isInteger(NaN)` was already correctly `false`. Documented as a caveat
on the `Number.isInteger(x)` row.

## Investigation

`emitNumberIsInteger` (`emit_call_number.go`) computed `floor(x) == x` as the
whole-number test. `floor(Infinity)` is `Infinity` and `Infinity == Infinity`
is true, so the test alone answered `true`. `NaN` slipped through correctly only
because `floor(NaN) == NaN` is false (every NaN comparison is false), not by
design.

## Decision

Gate the whole-number test on finiteness: `x - x` is `0` for a finite `x` but
`NaN` for `±Infinity`/`NaN`, so `fcmp oeq (x - x), 0` is a finiteness predicate
needing no extra libm declaration. The result is `(floor(x) == x) && finite`.

## Implementation notes

`emit_call_number.go` only. The non-float fast path (an already-integer-typed
operand returns `true` immediately) is unchanged — those values are finite by
construction.

## Side effects discovered

None.

## Verification

`TestE2ENumberIsIntegerNonFinite` (new): `Infinity`/`-Infinity`/`NaN` → `false`;
`5`/`0`/`-3` → `true`; `5.2` → `false`. Cross-checked against real Node.
Verified on Mac (Apple Silicon).
