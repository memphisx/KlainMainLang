# ADR-01456: Property descriptors are held as `any`

- **Relations**: Implements TDD-00230 (P2.2, P3.2)
- **Date**: 2026-10-07

## Context

A shadow bucket (268 locations; Test262's `forbidden-ext` tests) read a
descriptor from `Object.getOwnPropertyDescriptor`: codegen held it as a
dynamic object, so `d.configurable` and `d && d.configurable` were `any`,
while the checker typed them `boolean | undefined` from
`PropertyDescriptor`. Probing it found a compile failure: an object literal
annotated `PropertyDescriptor` was built as a static struct, which
`Object.defineProperty` rejected ("requires a dynamic (any-typed) object").

## Investigation

- The Object and Reflect builtins read and build descriptors as dynamic
  objects (TDD-00229's descriptor paths); a static descriptor layout has no
  consumer.
- The oracle had no representation for `PropertyDescriptor`. Where a
  receiver is held as `any`, codegen reads its members dynamically and a
  short-circuit over it is `any` (`shortCircuitValueType`), whatever the
  checker knows of the receiver's type.

## Decision

- A `dynamic` layout names a builtin held as `any`; `PropertyDescriptor`
  declares it, so a descriptor annotation is an `any` too.
- The oracle reads a member or element through a receiver held as `any` as
  `any`, gives a short-circuit with such an operand `any`, and gives a
  union with a member held as `any` that representation.

## Verification

- A `PropertyDescriptor`-annotated literal passed to `defineProperty` and a
  read-back descriptor match Node.
- The probe's member and short-circuit rows are gone.
