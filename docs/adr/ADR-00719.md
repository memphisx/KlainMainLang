# ADR-00719: Windows Stages 1–4 — libc shim, fd/select reactor, fibers, fs, processes, signals

- **Relations**: Implements [TDD-00177](../tdd/TDD-00177.md) (Stages 1–4); extends [ADR-00718](ADR-00718.md) (Stage 0)
- **Date**: 2026-09-05

## Context

ADR-00718 left the Windows port with a working toolchain and a failure histogram whose remaining rows were all the platform layer: glibc-only libc symbols, the `select()`/`fork()`/ucontext trio the runtime is built on, POSIX fs metadata, and the process model. TDD-00177's Option D says the toolchain stays mingw-w64 while the *semantics* are written against Win32 with Node's observable behaviour as the reference. This ADR is that platform layer, delivered as four C shim files compiled once into a per-user cache and linked into every Windows program, plus the handful of Go-side hooks the emitters needed.

## Investigation

Each subsystem was driven by the E2E failure histogram, a standalone repro, and (where the behaviour was in question) the same program under Node on this machine. Findings that shaped the design:

- **Linux ABI constants are already centralised.** Socket options, `O_NONBLOCK`, `EAGAIN`, `open` flags and the like reach the IR through per-OS Go helpers (`httpSockConstants`, `httpNonblockFlag`, `httpEagainErrno`, the fs open-flag map). Rather than adding a Windows case to each, the shim accepts the *Linux* values and translates internally, so the emitters stay untouched for this layer. Two layout hooks did need Windows cases: `dnsAiAddrOffset` (Winsock's `addrinfo` puts `ai_canonname` before `ai_addr`, like Darwin) and `ucontextLayout`.
- **Winsock `select` works on sockets only, and `WSAPoll` never reports a failed connect.** The reactor waits on sockets, pipes, and the console in one `fd_set`; a refused connection must surface as writable-with-`SO_ERROR`, which `WSAPoll` withholds (a long-standing Windows defect). Winsock `select` reports it in the except set.
- **CRT fds must not wrap sockets.** The first version gave sockets CRT fds via `_open_osfhandle`; closing them then had the CRT `CloseHandle` a socket the layer had already `closesocket`ed, which raises under a debugger and skips Winsock's teardown. Sockets now live in their own fd range with the handle in a side table.
- **Windows keeps returning `WSAECONNRESET`.** Linux returns the error from one `recv` and end-of-file from the next; the reactor's close-on-EOF path depends on the second read. The shim remembers a reset and answers 0 on the next read.
- **`_setjmp` needs a 16-byte-aligned buffer** (it stores XMM registers with aligned moves); the thread-local jmpbuf stack was `align 8` and faulted depending on layout. Found via `net.connect` to a refused port; the earlier throw tests had passed by luck.
- **libcurl's `curl_multi_fdset` fills Winsock-layout `fd_set`s** (a count plus an array of `SOCKET`s, 516 bytes) into the IR's 128-byte bitmaps; the reactor spun. The shim shadows the export, calls the real one through the loaded DLL, and maps curl's sockets into a reserved fd range.
- **`process.argv`'s headerized array was not NULL-terminated**, yet is handed to `execv()` on POSIX — a latent read past the end on every host, found when the Windows spawn path walked it.
- **The first `.then` on a `fetch` typed its callback's parameter as `number`**, so `r.status` inferred wrong and the runner called a `double`-returning closure as `i64`. `TestE2EFetchThenChain` was "status NaN" on Windows and mis-typed everywhere; passing the fulfilled type as the hint fixes both.
- **A refused loopback connect is reported ~2 s late through libcurl on Windows** (the `WSAPoll` defect again, inside curl). The event still fires; only latency differs.
- **A traffic-filtering product on this machine (AdGuard) intercepts loopback connections**: those that begin with the HTTP/2 client preface get an nghttp2 GOAWAY, TLS handshakes are reset, and large plain-HTTP request bodies are cut mid-stream (a pure Go server/client pair failed 5 of 15 4 MB echoes with the same "malformed chunked encoding" the suite reported). With the product disabled every one of those tests passes; the HTTP/2 preface probe skips them while it is on. It was first seen as an nghttp2 GOAWAY ("SETTINGS expected") answering the preface before the real peer saw a byte; Node's own `http2.connect` to an in-process `http2.createServer` fails there identically (`ERR_HTTP2_ERROR`).
- **Test expectations, not the compiler, were the last class**: `t.TempDir()` spliced into TypeScript literals (backslash escapes), `/bin/echo`, `/usr/bin/false`, `cwd: "/"`, `sh` arithmetic, SIGKILL death, Go's `os.Process.Signal` (cannot send SIGINT/SIGTERM on Windows), symlink creation needing Developer Mode. Node fails the same programs the same way on Windows.

## Decision

**Shim files** (`codegen/llvm/win32src/`, embedded, compiled once per content hash into `%LOCALAPPDATA%\klainmain\win32shim\`, linked before the caller's arguments so they shadow library exports):

- `win32shim.c` — libc extensions: `getline`, `dprintf`, `setenv`/`unsetenv`, `sysconf` (the ids the IR emits), `roundeven`, `getrandom` (`BCryptGenRandom`), `strcasestr`, `clock_gettime`/`nanosleep` against the IR's `{i64,i64}` timespec, `isatty` via `GetConsoleMode` (the UCRT's says yes to NUL), `__kml_current_rss_bytes` (working set), a stdin `FILE*` under this project's own symbol.
- `win32io.c` — the fd world: three ranges in the 1024-slot bitmap (CRT fds below 512; sockets 512–895 with the `SOCKET` in a side table; foreign sockets 896–1023 for libcurl), `socket`/`bind`/`listen`/`accept`/`connect`/`read`/`write`/`close`/`fcntl`/`setsockopt`/`pipe`/`dup2` with Linux constants in, `select` as a readiness poll (Winsock `select` over the socket subset, `PeekNamedPipe` and console waits over the rest, 10 ms slices only when both kinds are present), `poll` for the C helpers, `getcontext`/`makecontext`/`swapcontext` over Win32 Fibers, the `curl_multi_fdset` bridge, `SO_REUSEPORT` emulated with `SO_REUSEADDR`, `AF_INET6` mapped (10→23), strict IPv4 `inet_pton` (Winsock accepts leading zeros; Node and glibc do not), and a `KML_IO_TRACE=1` trace of every read/write/select decision.
- `win32fs.c` — `stat`/`lstat`/`fstat` written into the glibc x86-64 layout with Node's synthesised mode (`0666`/`0777`, minus write bits for read-only, `S_IFLNK` for reparse points) and a real birthtime in the struct's reserved tail; UTF-8 paths to UTF-16 everywhere; binary-mode `open`/`fopen`; 64-bit `fseek`/`ftell`; own `opendir`/`readdir` (`d_name` at offset 8); `mkdir`, `rmdir`, `unlink` (clears read-only first, like libuv), `rename` (replace), `access`, `chmod` (read-only bit only), `realpath`, `readlink` (reparse data; `/proc/self/exe` answered with the module path), `symlink` (file/dir/junction detection, unprivileged-create flag), `mkdtemp`, `truncate`; errno in Linux numbers with `strerror` in libuv's wording.
- `win32proc.c` — `__kml_win_spawn` over `CreateProcessW` with libuv's argument quoting, pipe ends as the child's stdio, a pid→handle table behind `waitpid` (status encoded the POSIX way, a kill recorded as death-by-signal) and `kill` (unconditional terminate; signal 0 probes), exec-failure reported as a pseudo-child exiting 127; `socketpair` as a loopback pair; an inherited-socket handshake (`KML_WIN_INHERIT_FD`) so a spawned worker adopts the parent's IPC or listening socket under the same fd number before its `main` runs; `signal` over `SetConsoleCtrlHandler` (Ctrl+C and Ctrl+Break as SIGINT, close as SIGHUP; SIGTERM listeners accepted but never fired, SIGWINCH ignored) plus `sigfillset`/`sigprocmask` stubs.
- `kml_posix_compat.h` — the header the embedded C helpers (`http2.c`, `tls.c`, `embed_assets.c`, the spawnSync source) include under `#ifdef _WIN32` instead of `unistd.h`/`poll.h`/`sys/socket.h`, declaring the surface above with Linux constants and coexisting with `winsock2.h` where OpenSSL pulls it in.

**Emitter hooks** (Go, all `runtime.GOOS == "windows"` branches): the four fork+exec sites (child_process spawn, execFileSync, `child_process.fork`, `cluster.fork`) and `http.listen({ workers })` become one `__kml_win_spawn` call each, with the primary setting the worker's environment itself and clearing it afterwards; `__kml_http_bind_and_listen` returns an inherited listening fd; `shell: true` and `exec()` use `cmd.exe /d /s /c`; `os.homedir` (`USERPROFILE`), `os.tmpdir` (`TEMP`, `TMP`), `process.getuid` family rejected at compile time (absent in Node on Windows); the errno→code table uses Linux numbers; `EISDIR` on a directory read uses the Linux number; the jmpbuf stack is `align 16`.

**Cross-platform fixes made in passing**: NULL-terminated `process.argv` array; `.then` callback parameter hint; i64 slots zeroed before libcurl's 32-bit `long` writes (`CURLINFO_RESPONSE_CODE`, `curl_multi_timeout`); `long` → `int64_t` in the embedded spawnSync and tty C sources.

**Tests**: `tempDir(t)` (forward slashes) replaces `t.TempDir()` where the path is spliced into a program; POSIX-shaped expectations are skipped on Windows with the reason stated (`skipPOSIXToolsOnWindows`, `skipSignalDeliveryOnWindows`, a symlink-privilege probe, `skipIfLoopbackH2PrefaceIntercepted` — a pure-Go probe for the host interception above); `TestE2EProcessExecPath` and `TestE2EEventSourceOnErrorFires` carry Windows variants (a drive-letter path; a longer grace period for the refused-connect latency); `killProcGroup` uses `taskkill /T` so spawned workers do not outlive a test.

## Implementation notes

- Shim objects are cached per content hash and never pruned: pruning raced concurrent test processes still linking an older object.
- `-I<cache dir>` is added only to compile steps (a link-only invocation would warn), and `-lbcrypt -lpsapi -lwinpthread` always.
- `select()`'s except set receives every write-set socket so a failed non-blocking connect is reported writable (POSIX shape), and a closed fd is never reported ready (POSIX would fail with EBADF; the reactor loops on either).
- The `curl_multi_fdset` shadow resolves the real symbol with `GetModuleHandle` on `libcurl-4.dll`, so programs without libcurl still link.
- Winsock is bound with `GetProcAddress`; including `winsock2.h` would conflict with the POSIX-shaped definitions this file provides.
- The Windows cluster shares one listening socket across spawned workers (the kernel picks the accepter), the same distribution the fork model gives on Linux. Node's Windows scheduling is round-robin from the primary; recorded as the gap in TDD-00177. `http.close()` from a worker does not reach siblings on Windows (no shared flag page).
- Test runs on Windows need MSYS2's `usr/bin` on PATH for the coreutils the child_process tests spawn (`echo`, `printf`, `cat`, `sh`), and MSYS2's `ucrt64/bin` *ahead of* Git for Windows' for a `curl` with HTTP/2 (Git's is built without nghttp2) and for the optional libraries' DLLs at run time.

- **Stage 5 items folded in here rather than a third ADR**, each a one-cause fix found by its test group:
  - `Atomics.wait` hung: the IR compares `pthread_cond_timedwait`'s result against Linux `ETIMEDOUT` (110); winpthreads reports 138. `etimedoutErrno()` gained a Windows case.
  - `-mm=gc` died with a breakpoint exception at startup: `GC_set_handle_fork(1)` makes Boehm abort where there is no `fork()`. Skipped on Windows; `GC_INIT` and the allocator shim are unchanged.
  - zlib (`CompressionStream`, `zlib.gzipSync`) returned errors on valid input: `z_stream` is 88 bytes on LLP64 with `next_out`/`avail_out` at 16/24 (112 and 24/32 on LP64). `zsFix` rewrites the template offsets on Windows; the numbers were measured with `offsetof` against the mingw-w64 `zlib.h`.
  - `klain:sync` goroutines crashed at `-O1` and above: the work-stealing scheduler resumes a goroutine (now a Win32 fiber) on a different thread than it left, and the optimizer had cached the thread-local scheduler variables' addresses across the switch. On Windows those two thread-locals are read through out-of-line accessors; Linux/macOS keep the plain `_Thread_local`s. Goroutine stacks come from `VirtualAlloc`.
  - `klain:tty`/`klain:tui` used termios/`TIOCGWINSZ`: console-mode API branches (raw mode clears line input, echo and processed input and enables VT input so arrow keys arrive as escape sequences; size from `GetConsoleScreenBufferInfo`; `readKey(ms)` waits on the console handle and drains non-key records).
  - Lazy `import()` islands are `.dll`s loaded with `LoadLibrary`; there is no `-ldl`.
  - `child_process.fork`/`cluster.fork` IPC worked at a console but not under the test harness: the parent's `closesocket` on the child's end tore down the socket object the child had inherited (a duplicated socket handle does not keep the object alive). A socket handed to a child is marked, and the parent's `close()` then releases only its own handle.
  - Two compiler builds running side by side (a test binary and a rebuilt CLI) overwrote each other's cached compat header; the shim cache directory is now keyed by the hash of all embedded shim sources.
  - The sanitizer build helpers skip on Windows: LLVM's Windows release carries the ASan/UBSan runtime only for the MSVC target.
  - `os.cpus()` read `/proc/cpuinfo`: the shim now reads the registry (`ProcessorNameString`, `~MHz`) and `NtQuerySystemInformation`'s per-processor times, the same sources libuv uses on Windows, and a Windows reader builds the same `CPUInfo` objects the Linux and Darwin readers produce.
  - TLS servers (`tls.createServer`, `https`, `http2` secure, `wss`) aborted every handshake: `SSL_set_fd` was handed this project's fd number, but OpenSSL's socket BIO speaks Winsock and needs the `SOCKET`. On Windows the fd is translated through the shim and kept as the SSL's app data for the `poll()` waits. The `wss://` client then closed on the first read: the non-blocking TLS read relied on the socket's `recv` leaving `EAGAIN` in errno, which Winsock never does; the helper now sets it explicitly on `WANT_READ`/`WANT_WRITE`.
  - A top-level user function named like a libc symbol (`read`) is a duplicate symbol when a test hands the parser's output straight to the emitter; the real pipeline's resolver mangles it. That test now goes through the resolver.

## Side effects discovered

- `readdir`/`stat`-style `declare`s for `atoi` and `readlink` are emitted unguarded in three runtimes and would collide if those modules meet in one program; untouched here.
- `console.log` output is fully buffered by the C runtime when stdout is a file or pipe, on every host; Node flushes synchronously. Same on Linux, so not a Windows regression, but it makes a hung program look silent.
- `TestE2EWorkerGCModeRoundTrip` dies with a breakpoint exception (`0x80000003`) and the `-mm=gc` cluster tests never start listening: `-mm=gc` on Windows is Stage 5.
- The tty C helper still includes `termios.h`/`sys/ioctl.h`; `klain:tui` and raw-mode stdin are Stage 5 (console mode API).
- `process.stdout.isTTY` under the Go harness is `false` as on POSIX — the UCRT would have said true for NUL; fixed in the shim, noted because it is the kind of divergence this port exists to catch.
- **Undefined behaviour reads differently per target.** Several Test262 files that crash on Linux *hang* on Windows: a read through a null pointer is `unreachable` to LLVM, which x86-64 Linux lowers to a trap and the Windows target to a self-loop (`jmp .`). Three such reads were real cross-platform bugs, fixed here with E2E tests: a dynamic `null` reaching a string-keyed `Set`/`Map` (`new Set().has(null)`), `parseInt`/`parseFloat` of `null`/`undefined` (NaN, as ToString gives "null"), and `new RegExp(p, undefined)` (flagless). The shim also switches off Windows Error Reporting's crash dialog so a genuine fault ends the process like a signal would.
- **Deferred, cross-platform, found the same way** (they time out on Windows and are counted as runtime failures or timeouts on Linux; not verified on Linux this session): `new Set().has(NaN)` on an untyped Set boxes the NaN as a string pointer (`fptosi`+`inttoptr`) — a type-model gap, not a null read; `for(;;){ try { c++; throw x } finally { continue } }` spins (a `continue` in `finally` with a pending exception); `for (var c = 0; c < 10;) { try { throw x } catch { c++; continue } }` leaves the outer `c` at 0 (the `for`-init `var` re-declaration shadows). Each needs its own fix and ADR.

## Verification

Windows 11 x86-64, mingw-w64 UCRT sysroot via MSYS2, LLVM 22.1.8 clang, Go 1.27, MSYS2 packages for curl/sqlite3/pcre2/libtommath/openssl/nghttp2/gc/zlib:

- `go build`, `go vet ./...`, and `GOOS=linux go vet` of the build-tagged packages pass.
- Standalone repros pass for: in-process net server/client, `child_process.fork` IPC round trip, `cluster.fork` IPC, `spawn` with newline-bearing arguments, `execFileSync`, refused-connect throw, EventSource error, fetch `.then` chains.
- Node on this machine reproduces the loopback HTTP/2 preface interception exactly, which is what makes the corresponding test skip host-specific rather than a Windows caveat.
- Full `go test ./tests` result and per-group table: filled in from the final run below.

`make conformance` (Test262, both lanes) on Windows, 2026-09-06, after the conformance runner was taught to build with the same host clang argv as the compiler (it had been invoking a bare `clang`, which on Windows targets MSVC and fails every link): strict lane **6260 passed of 53578** (Linux baseline 6254), js lane **6674** (6668). The six extra passes per lane are the null-read fixes above; the remaining differences are 3 compile-phase timeouts under load (top-level-await tick-order files that compile in time alone), 4 more `clang` failures and 2 fewer run timeouts — all timing, none a Windows-specific result. The committed reports stay the Linux ones; the Windows runner now writes slash-separated paths so a future Windows regeneration diffs cleanly.

Final `go test ./tests` on Windows 11 x86-64 (2026-09-06, AdGuard disabled): **2636 passed, 0 failed, 47 skipped** (plus one skip turned into a pass afterwards, below), 31 minutes. The 47 skips are the documented platform gaps: Webview (no Windows backend) 13, `child_process`/`execFileSync` tests that spawn POSIX tools 12, signal delivery (`process.kill` with SIGINT/SIGTERM terminates on Windows as under Node) 6, SQLite oracle tests (no `sqlite3` CLI) 4, `-mm=gc`/auto-mode memory-bound tests that read `/proc` 4, cluster worker-PID distribution (shared accept instead of round-robin) 3, sanitizer builds 2, and one each for `process.getuid` and `fs` POSIX path ops. A 48th skip, the destructured `crypto.subtle` alias test, was a masked failure — its top-level `main` collided with the entry point on the parser-direct harness path, on every host — and now runs through the resolver like the `read` test above. Examples: 219 of 222 pass; the three that do not are platform-expected — `fs/fs.ts` (symlink without Developer Mode), `process/exec_file_sync.ts` (runs `/bin/echo`), and `process/graceful_shutdown.ts` (sends itself SIGINT, which on Windows terminates the process with exit code 1 exactly as Node does).
