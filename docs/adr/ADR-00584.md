# ADR-00584: BigInt.asIntN / asUintN

- **Relations**: Extends [ADR-00216](ADR-00216.md), [TDD-00074](../tdd/TDD-00074.md)
- **Date**: 2026-09-01

## Context

`BigInt.asIntN(bits, x)` and `BigInt.asUintN(bits, x)` — clamp a bigint to the
low `bits` bits, two's-complement signed or non-negative — were unimplemented (a
disclosed sub-caveat on the `bigint` row).

## Decision

Add `__kml_bigint_as_intn`/`__kml_bigint_as_uintn(i64 bits, ptr x)` to **both**
bigint backends and dispatch `BigInt.asIntN`/`asUintN` member calls to them:

- **asUintN**: reduce `x` modulo `2^bits`, taken non-negative. GMP's
  `mpz_fdiv_r_2exp` is already floor (non-negative); tommath's `mp_mod_2d`
  truncates (keeps the dividend's sign), so a negative result gets `2^bits`
  added back.
- **asIntN**: reduce to `[0, 2^bits)` (asUintN), then subtract `2^bits` when the
  result is `>= 2^(bits-1)` (the sign bit is set).
- `bits <= 0` yields `0n`. `bits` must be a number, `x` a bigint (both checked
  at compile time). The member-call return type infers as `bigint`.

## Verification

`TestE2EBigIntAsIntN` (signed/unsigned wraparound at 8 and 64 bits, negative
inputs, a value past 2^53, chained arithmetic on the result) compared
byte-for-byte against Node v26 under both `-bigint=libtommath` (default) and
`-bigint=gmp`. Built and verified on Mac (Apple Silicon).
