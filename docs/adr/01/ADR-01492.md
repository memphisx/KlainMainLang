# ADR-01492: A namespace's type named qualified is checked

- **Relations**: Extends TDD-00230 P2
- **Date**: 2026-10-09

## Context

`const a: N.A = { v: 1 }` with `namespace N { export type A<T = string>
= { v: T } }` compiled past the checker and failed in codegen. tsc
reports TS2322. With an explicit argument (`N.A<string>`) it failed the
same way, and so did a qualified interface.

## Investigation

- The checker found `N` and its scope, but not `A` there. The resolver
  makes a file's top-level declarations file-private by suffixing their
  names (`A__kml_mod0`), and a namespace member is one of them. The
  binder strips the namespace prefix, not that suffix.
- With no symbol, a qualified type reference was unanswered, which the
  checker treats as unknown and does not check against. So every
  qualified namespace type in a program was unchecked, not only a
  generic alias with defaults.

## Decision

- A qualified type name also matches a namespace member by its name
  without the file-private suffix (`qualifiedTypeName`).
