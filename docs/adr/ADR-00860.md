# ADR-00860: ToPrimitive string-hint coercion of objects (TDD-00201 Stage 2)

- **Relations**: `Extends ADR-00859`, `Implements TDD-00201`
- **Date**: 2026-09-10

## Context

An object used where a string is required — `String(obj)`, `` `${obj}` ``,
`"a" + obj`, `str.indexOf(obj)` — must be converted by ToPrimitive with the
string hint: `Symbol.toPrimitive` → `toString` → `valueOf`. Stage 1 (ADR-00859)
covered the number hint. String contexts were independently broken: a user
`toString` on an object literal was ignored, `String(obj)` producing the
util.inspect dump instead of the method's result.

## Investigation

`emitValueToString` (`emit_exprs_types.go`) is the central string-conversion path
for `String()`, template interpolation, and concatenation — `console.log(obj)`
uses `emitInspectObject` separately, so the two do not share a fallback. For an
`isInspectableObject` value it honored a *class* `toString()` (MethodSigs) but not
an object-literal `toString` *field*, falling through to the inspect dump.

String methods emit their search argument directly (`emitStringIndexOf`,
`emitStringLastIndexOf`: `needleVal := e.emitExpr(args[0])`) and use it as a
`ptr` — an object argument was used as a string pointer with no ToString.

Semantics check against Node: `String({valueOf(){return 5}})` is
`"[object Object]"`, **not** `"5"` — the inherited `Object.prototype.toString`
always intercepts the string hint before `valueOf`. So `valueOf` is effectively
unreachable in the string hint for a plain object.

## Decision

- **`emitValueToString`**: before the inspect fallback, run the string-hint
  ToPrimitive ladder on an object literal (`emitObjectToPrimitive(v, "string")`)
  and stringify its primitive result. A no-op for class instances (methods are
  MethodSigs, not fields) — the existing class `toString()` path still wins — and
  for a plain object with no own `toString` (falls to the existing
  compatJS `"[object Object]"` / strict inspect-view default).
- **String-hint ladder order** is `@@toPrimitive` → `toString` only; `valueOf` is
  omitted (the inherited `Object.prototype.toString` intercepts it), so
  `String({valueOf(){return 5}})` correctly does not use `valueOf`.
- **`coerceStringArg`** helper: ToString an object argument flowing into a
  string-typed position; applied to every string method with a string
  search/pattern/replacement argument —
  `indexOf`/`lastIndexOf`/`includes`/`startsWith`/`endsWith` and
  `replace`/`replaceAll` (search + replacement) / `split` (separator). In the
  latter three a `RegExp` argument is dispatched to the regex path *before* this
  coercion, so a regex is never ToString'd; a function replacer is likewise
  dispatched first.

Faithful in both `-compat` lanes for a user-provided `toString`/`@@toPrimitive`
(the pre-existing strict-vs-compatJS difference for a *method-less* object's
default form is unchanged and out of scope here).

## Implementation notes

- `emit_exprs_types.go` (hook), `emit_toprimitive.go` (`coerceStringArg`,
  string-hint order), `emit_strings.go` (`indexOf`/`lastIndexOf` args).
- `slice`/`substring` take *numeric* index arguments, already coerced through
  `coerce(_, i64)` — so an object index there is handled by Stage 1's number-hint
  hook, not this path.
- For `replace`/`replaceAll`/`split`, `coerceStringArg` is applied only after the
  method's existing `inferExprType(arg).IsRegExp` and `IsFunc` dispatch, so the
  ToString path only ever sees a plain (non-regex, non-callback) argument — a
  regex `replace(/x/, y)` and a function replacer keep their current behavior.

## Side effects discovered

The A1 `String.prototype.slice`/`substring` invalid-IR files remain `CLANG_ERROR`:
their object argument coercion is a different site not yet hooked (Stage 2b). The
`indexOf`/`lastIndexOf` A1 files now pass.

## Verification

- E2E `tests/toprimitive_test.go`: `String`/template/concat honoring `toString`
  and `@@toPrimitive`, `indexOf`/`lastIndexOf` with object arguments, and a guard
  that `console.log(obj)` still renders its inspect dump — all matched to `node`.
- A Test262 string-method A1 sample went from 0 → 4 passing (indexOf/lastIndexOf);
  slice/substring remain (Stage 2b).
- `go build`, `go vet ./...` clean; full `make test-par` — no regression.
