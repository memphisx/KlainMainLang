# ADR-01313: Live Map, Set and Array iterators

- **Relations**: `Implements TDD-00230` (P3.2); `Extends ADR-00481`, `ADR-00057`
- **Date**: 2026-09-30

## Context

BACKLOG 130: `m.keys()`, `m.values()` and `m.entries()` returned arrays, so
`m.keys().next()` did not compile. Probing Map and Set iteration against Node
(macOS arm64) found more divergences:

- `m.delete(k)` moved the last entry into the deleted slot, so
  `[a, b, c]` minus `a` iterated as `c, b` (Node: `b, c`). The same held for
  a Set and for a dictionary object (`delete d.a`).
- `for (const x of m)` bound each value; Node binds `[key, value]`, and
  `for (const [k] of m)` did not compile.
- A `for...of` over a Map or Set walked a snapshot, so an entry added or
  deleted during the loop was not seen.
- A loop variable over an array of arrays (`for (const a of xs) a.push(1)`)
  was a fresh header over the element's buffer: a push reallocated that
  buffer and the element read freed memory. The same happened through
  `m.values()` of a `Map<K, T[]>`.
- `[...gen()]` of a generator gave `[]`.
- `arr.keys()`/`values()`/`entries()` also returned arrays.
- `new Map(m)`, `new Map(m.entries())`, `new Set(m.keys())` and a Map from a
  user iterable did not compile.
- `IteratorResult<T>` (BACKLOG 114) resolved in codegen as an array type.

## Investigation

- The Map runtime keeps keys and values in dense, insertion-ordered arrays
  behind an open-addressing index (`runtime_collections.go`). Every reader
  (forEach, inspect, JSON, keys()) walks the dense arrays, so density is
  worth keeping. The swap-remove in the three `delete` variants was the
  only thing breaking the order.
- V8's OrderedHashTable tombstones and rehashes, with each live iterator
  following the table's transition chain. SpiderMonkey's OrderedHashTable
  keeps a list of live `Range`s and updates each one when entries move.
  With dense arrays, the SpiderMonkey model fits: a removal shifts later
  entries down one, and every open iterator past the removed index steps
  back one.
- An iterator must advance before the loop body runs. Deleting the current
  entry then shifts the iterator back onto the next entry instead of
  skipping it. This matches Node:
  `for (const [k] of m) if (k === 'b') m.delete('b')` still visits `c`.
- A Map iterator has no `return()`, so a `break` out of a loop over an
  iterator value leaves it usable. Node resumes it in a later loop.
- TypeScript declares the iterators as `MapIterator<T>`, `SetIterator<T>`
  and `ArrayIterator<T>`, extending `IteratorObject<T>` (es2015.iterable),
  and ES2025 adds `toArray()` (es2025.iterator).

## Decision

- **Ordered removal.** `__kml_map_remove_at` (`runtime_collections.go`)
  removes an entry in place. It shifts the later keys and values down one,
  decrements every index slot naming a later entry, and steps back any open
  iterator past it. The three `delete` variants call it. The map header
  grows to 72 bytes, adding the open-iterator list at offset 64.
- **Iterator nodes.** An iterator is a 24-byte node `{next, pos, source}`:
  - A Map or Set iterator is on its map's list (`__kml_map_iter_open` and
    `__kml_map_iter_close`), and `clear()` rewinds it
    (`__kml_map_iters_reset`).
  - An Array iterator's source is the array's own header, so it sees a later
    `push`. It is not registered anywhere.
  - Reaching the end closes the node (source null), so the iterator stays
    done even after the collection grows.
- **Types.** Codegen's `CollIterType(src, kind)` marks an iterator of an
  array, Map or Set yielding keys, values or entries.
  - `next()` returns `{value, done}`, with `value` typed `T | undefined`
    for a scalar.
  - `toArray()`, spread and `Array.from` drain the iterator.
  - `for...of` walks it live.
  - `typeof` is `"object"`, and `String(it)` is `[object Map Iterator]`.
  - `console.log` shows the entries it has yet to yield
    (`[Map Iterator] { 'b' }`, `[Map Entries] { [ 'a', 1 ] }`,
    `[Map Iterator] {  }` once done) and `Object [Array Iterator] {}` for an
    array.
- **for...of over a Map or Set** (`emitForOfMapLive`):
  - It opens a node. The loop's own node is closed on leaving the loop by a
    `break`, `return` or labeled jump, through a new `native` hook on
    `pendingExit`.
  - A Map binds its `[key, value]` entry and a Set its value, as their
    `[Symbol.iterator]` do; `keys()`, `values()` and `entries()` in the loop
    head walk the same node.
  - An array-typed element binds the header the collection holds, so the
    variable aliases it. The generic array loop now does the same for an
    array of arrays.
- **Iterables where an array was required.** `iterableArraySource` presents
  a Map, Set, iterator or sync generator as `Array.from(x)`. This covers
  `resolveArrayForHOF` (so a Set seed, spread and the array methods take
  them), the Map seed and its K/V inference. A Map seeded from an `any[]`
  (a user `[Symbol.iterator]` object) reads each entry's `"0"` and `"1"`.
  A spread of a sync generator runs it through `Array.from`.
- **Declarations.** `lib/es.d.ts` now declares:
  - `Iterator`'s members, `IteratorObject` (with `toArray`) and
    `BuiltinIteratorReturn`.
  - `ArrayIterator`, `MapIterator` and `SetIterator`.
  - `[Symbol.iterator]`, `entries`, `keys` and `values` on `Array`,
    `ReadonlyArray`, `Map` and `Set`.

  The Array members are `@intrinsic`. `IteratorObject.toArray` is
  allowlisted in `tools/libconform`, since TypeScript declares it inside a
  `declare global` block the diff does not read.
- **Generic builtin aliases.** `registerAmbientGeneric` makes a generic
  alias of the builtin declarations (`IteratorResult<T, TReturn>`)
  instantiable, and so is a generic interface of theirs that is only a data
  shape (`IteratorYieldResult<T>`). Resolving the alias pre-registers its
  union members. A lib alias whose annotation was never converted from its
  type node is converted here.

## Implementation notes

- `emit_collections_iter.go` holds the iterator code. `emitMapCall` and
  `emitSetCall` return iterators for user calls. The array-producing forms
  moved to `emitMapMethod` and `emitSetMethod`, for internal callers:
  `Object.keys` of a dictionary, `for...in` over one, `Array.from(map)`.
- `emitInspectSet` now reads its elements through the element type's own
  runtime (`mapRuntime`). It had called the number runtime for everything
  but strings, an undefined symbol for an any-keyed Set.
- `defineForOfVar`/`bindForOfElem` were extracted from `emitForOf` so the
  live loop shares its binding code.

## Side effects discovered

- A present field holding `undefined` in a scalar union prints as absent:
  `{ v: undefined }` shows `{}`, and a done Array iterator's
  `{ value: undefined, done: true }` shows `{ done: true }`. Relatedly, a
  missing optional `string | null` field reads as `null`. Both need P3.3's
  three-state representation.
- A generator's `next()` after it is done gives `value: 0` for a numeric
  element, and `Generator<T, TReturn>` reads a `TReturn` return value as a
  `T`. The same P3.3 work covers it.
- The typed arrays' `keys`/`values`/`entries` still materialize arrays.
- Performance: `delete` is now linear in the map's size. It shifts the later
  entries and rescans the index, where the swap-remove was constant time. A
  queue-like Map that repeatedly deletes its oldest key pays O(n) a delete.
  V8's scheme (tombstones compacted on rehash, iterators following the
  table's transitions) would make it amortized constant; that is recorded
  as a performance follow-up, not a behavior change.
- The tests that pinned the old behavior now pin Node's:
  - `for (const v of m)` binds entries;
  - `m.keys()[0]` is `undefined`;
  - a destructured array field aliases its source;
  - a destructuring default never applies to `null`.

## Verification

`tests/collection_iterators_test.go` compares ten programs with Node
(`assertSameAsNode`) on macOS arm64:
- ordered delete, live for-of, entry binding and array aliasing;
- iterator objects and their inspect output;
- array iterators and generator spread;
- `IteratorResult` and iterable constructors.

The targeted collection, iteration and destructuring suites pass.
