# ADR-01415: Methods and const literals as computed member keys

- **Relations**: Implements TDD-00246; Extends ADR-01414
- **Date**: 2026-10-05

## Context

ADR-01414 let a class *field* be keyed by a declared symbol. A *method* so
keyed (`[kDescribe](p) {}`) was still rejected, and so was a member keyed by
a `const` holding a string or number (`const k = 'dyn'; class C { [k]() {}
}`), which TypeScript and JavaScript name `dyn`.

## Decision

- A method keyed by an identifier keeps it (`FunctionDeclaration.Key`), bound
  where the class is declared and renamed by the resolver, as a field's.
- `ast.NameComputedMembers` names every identifier-keyed member, after the
  resolver's renaming and before type checking (from `resolver.TypeCheck`,
  and again, idempotently, from code generation, which every lane reaches):
  a const symbol keys it (`SymbolMemberName`), a const string or number
  literal names it by value, anything else (a `let`, a parameter) is the
  rejection it was.
- `super[k]` with a symbol key reaches the base class's member.
- `util.inspect` quotes a static field's key that is not an identifier
  (`{ '2': 'two' }`), as Node does and as the dynamic renderer already did.

## Verification

- Mac (M4): `TestE2EComputedConstKeyedMembers` (a const string and number
  key, a symbol-keyed method overridden and reached through `super[k]` and
  through `any`, against Node), `TestE2EComputedNonConstantNameRejected`
  (a `let` key), and the class, symbol and inspect tests.
- Linux (x86-64, Ubuntu 24.04 container), with ADR-01410 to ADR-01415: the
  full test suite, the 394 examples, and Test262 in both lanes (strict 8,497,
  the one file of ADR-01412 fewer; js 10,506; no invalid IR).
