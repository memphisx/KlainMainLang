# ADR-00992: Global isNaN/isFinite coerce concrete non-numeric operands

- **Relations**: Extends ADR-00902
- **Date**: 2026-09-17

## Context

The global `isNaN`/`isFinite` (unlike `Number.isNaN`/`Number.isFinite`) apply
`ToNumber` to their argument before testing. ADR-00902 wired this up for an
`any`-boxed operand, but a status caveat on both rows noted the coercion was
still skipped for a *concrete* non-numeric operand reaching the call through an
erased `expr as any` assertion — `isNaN('hello' as any)` returned `false`
(Node: `true`).

Root cause: `expr as T` keeps the operand's concrete type when `T` is not a
narrowing from a dynamic source (ADR-00371), so `'hello' as any` is inferred and
represented as a plain `string`, never boxed. `emitNumberIsNaN`/`IsFinite` then
saw a non-float, non-dynamic value and took a trivial `false`/`true` shortcut.

## Investigation

`codegen/llvm/emit_call_number.go` — the `!val.Ty.Float` branch handled only
`val.Ty.IsDynamic` (via `coerce(val, TypeF64)` → `emitAnyToNum`), falling through
to the trivial answer for every other type. Confirmed the split with a repro:
the variable form `const s: any = 'hello'` (boxed at assignment) already gave
`true`, while the inline `'hello' as any` gave `false`.

`coerce(dynamic → f64)` (`emit_exprs_coerce.go:46`) already runs the real
`ToNumber` (`emitAnyToNum`) that parses strings and yields NaN for objects, so
the fix reuses it after boxing.

## Decision

For a concrete (non-float, non-dynamic) operand, keep the trivial fast path only
for types whose `ToNumber` is always finite — integers and booleans. For any
other type (string, object, `undefined`, other pointer types), box the value
with `emitBoxValue` and `coerce` it to `f64`, which runs the same `ToNumber` the
dynamic path uses. Introduced `toNumberCanBeNaN(Type)` to make the distinction.

## Implementation notes

- `emit_call_number.go`: both `emitNumberIsNaN` and `emitNumberIsFinite` now
  `switch` on dynamic / `toNumberCanBeNaN` / trivial.
- `toNumberCanBeNaN` treats `i1` and integer IRs as always-finite (except an
  `undefined`-typed integer sentinel, whose `ToNumber` is NaN); every pointer
  type routes through `ToNumber`.

## Side effects discovered

None. `Number.isNaN`/`Number.isFinite` (the non-coercing siblings) are unchanged.

## Verification

- New E2E `TestE2EGlobalIsNaNIsFiniteCoerce` (string/object/bool via `as any`, a
  variable-typed `any`, and the integer fast path); existing
  `TestE2ENaNInfinityBareGlobals` still passes.
- Both status caveats removed (number-math, global-functions); `make status`,
  `make status-check`, `make reference-check` clean.
