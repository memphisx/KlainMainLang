# ADR-01455: A catch binding is the caught-value record in every pass

- **Relations**: Implements TDD-00230 (P2.2); extends TDD-00202
- **Date**: 2026-10-07

## Context

A shadow bucket (129 locations; Test262's `catch (err)` tests, `stream.ts`)
was a catch clause's binding: codegen's answer was sometimes the
caught-value record and sometimes `any`, the oracle's the checker's
`unknown` (`any` in the js lane).

## Investigation

- `emitCatchBody` always binds the parameter as the caught-value record
  (`TypeCaught`, a `{ i8, i64 }` tag and payload).
- Inference before the catch scope exists (a whole-function pre-pass) took
  the unbound-identifier fallback, which asked the checker and answered
  `any`: the same read had two types in two passes.
- `err as T` is erased (ADR-00371): it keeps the record.

## Decision

- Codegen's unbound-identifier fallback answers `TypeCaught` for a name the
  binder places in a catch scope.
- The oracle answers `TypeCaught` for a catch binding, read directly or
  through `as`.

## Verification

- The probes' rows are gone; a caught subclass read through `as` matches
  Node.
