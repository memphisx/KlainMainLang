# ADR-00398: `Function.prototype.call` / `.apply` / `.bind` (TDD-00137)

- **Relations**: Implements TDD-00137
- **Date**: 2026-08-27

## Context

`only simple function calls are supported` is the single largest blocker in the
Node `test/parallel` oracle (282 files), and a confirmed common cause is dynamic
invocation via `Function.prototype.call`/`.apply`. TDD-00137 settles the design;
this ADR records the Stage A implementation.

## Decision / mechanism

A call whose callee is `fn.call` or `fn.apply`, where `fn`'s static type
`IsFunc` (a first-class function value — a closure, function parameter,
arrow/function expression, or named function), is intercepted in `emitCall`
before the generic field-call path and lowered by `emitFunctionCallApply`:

- The receiver `fn` is evaluated to its closure value.
- The first argument (`thisArg`) is evaluated **for its side effects then
  discarded** — this compiler's closures carry no rebindable `this`.
- `.call(thisArg, a, b, …)` forwards `a, b, …`; `.apply(thisArg, [a, b, …])`
  forwards the **literal array's** elements.
- The forwarded arguments go through `emitClosureCallByPtr` unchanged, so they
  are type-checked and coerced against `fn`'s parameter types exactly as a normal
  call, and the result type is `fn`'s return type (added to `inferExprType`).

## Stage B — runtime-array `.apply`

`fn.apply(thisArg, arr)` with a non-literal array is lowered to `fn(...arr)` — a
synthetic spread into `fn`'s rest parameter, reusing the existing
spread-into-rest machinery (which validates that `fn` actually has a rest slot
and the element types match; a fixed-arity `fn` is the usual spread-into-fixed
rejection). No new runtime.

## Stage C — `.bind`

`fn.bind(thisArg, …bound)` builds a **new closure**: an env captures the original
`fn` header plus the evaluated bound arguments (one 8-byte slot each), and a
per-site trampoline `@__kml_bind_N(env, remaining…)` loads them back and
tail-calls `fn(bound…, remaining…)`. The result is a real function value of the
reduced type (`fn`'s parameters minus the bound leading ones), so it flows
through the normal closure-call path — usable as a callback, stored, re-bound.
V1 is bounded to functions with plain scalar/string/pointer parameters and no
rest slot (an array/nullable-scalar/rest parameter is a clean error), covering
the dominant `handler.bind(null, id)` shape.

Remaining clean rejection: call/apply/bind on a non-first-class callee such as a
built-in (`net.connect.apply(…)` — built-ins are not function values here).

## Consequences

All three now work, verified byte-identical to Node v26 (partial application,
fully-bound, void return, bound-as-callback, runtime-array spread). Method
borrowing (rebinding `this` to a different receiver) is unsupported by
construction and documented. The whole-file oracle `only simple function calls`
bucket is unlikely to fully drain even so, since the corpus's heaviest uses are
`.apply`/`.bind` on **built-ins** (`net.connect.apply(net, args)`) — first-classing
built-ins is a separate, larger change — and those files also hit other
front-end gaps (`expected (, got .`, arrow-only callbacks).
