# ADR-01940: Function values carry their id in a prefix word, retiring the code-pointer side table

- **Relations**: Implements TDD-00230, Supersedes part of ADR-01093
- **Date**: 2026-10-28

## Context

TDD-00230 Phase 5 gives every boxable heap object one header word, closures included, and says closures get their metadata through it, "retiring the code-pointer side table of ADR-01093".

A function value is a closure header `{fn, env}` or a dynamic record `{fn, env, arity}`. Before this change, its name, length, kind and source text were found through rows keyed by the code pointer `fn`. Three tables were keyed that way:

- the fnmeta rows;
- a literal's dynamic entry (DynEntry);
- a builtin constructor's statics (FnStatic, keyed by the record's address).

## Investigation

- **Where function values are built:**
  - 22 Go sites allocate a header or a record (`allocClosure` with 16 or 24 bytes).
  - Two literal paths go through `closureAllocs`, which can also place a non-escaping literal on the stack under `-optimize-memory`.
  - 14 static records are constants.
  - About ten C sites build one (`asynchooks.c`, `fswatch.c`, `settle.c`, `finally.c`, `defer.c`, `anyprom.c`, `microtask.c`).
- **Where they are freed:** the explicit free path (`__kml_closure_free`) and `fetchbodyprom.c`, which frees its settle closure after running it. The first gate of the prefix word caught the second one: `free(): invalid pointer` in 13 fetch/HTTP examples on Linux (DeskMini).
- **Static records across library units:** a static record is an alias of its cell past the prefix word. The library split (`libsplit.go`) placed a library unit's alias apart from its cell ("Alias must point to a definition") and could not declare an alias.
- **Class source text:** the fnmeta rows also held class source text, keyed by the class reference's name pointer. That is not a function value.
- **Extended records:** `FN_EXT` records (a flag in the arity word, with an own name and bag) had no producer left.

## Decision

- **The prefix word:**
  - Every function value starts with a prefix word, at the same −8 as a string's or an array's. It holds the header magic, a new closure flag (bit 54, `kmlHdrClosure`) and the function's id in the type-id bits.
  - The value still points at `{fn, env}`, so the closure ABI is unchanged.
- **Ids:**
  - A function gets its id at its first `registerFnMeta`. A program function takes the next per-program type id.
  - Some ids are stable (a hash of the symbol), because the function's unit text is the same in every program. This covers:
    - a library function;
    - a library generator's constructor;
    - a helper named by its content's hash (an adapter a library unit allocates);
    - `__kml_dyn_bound`.
  - An unregistered function, such as a runtime-internal callable, has id 0: anonymous, as before. It is the same in every program.
  - A code reference given as its cast into the managed address space keys by its symbol.
- **Allocation:**
  - Every Go site allocates through `emitClosureAlloc(dst, size, fn)`, every C site through `kml_closure_alloc(n)` (id 0).
  - Static records go through `emitStaticFnRecord`: a constant cell with the prefix word (immortal bit set) and an alias past it.
  - A stack-allocated literal gets the word too, in a cell `{ i64, fn, env }` in the managed address space.
  - Both free paths free the base.
- **Rows:**
  - The fnmeta rows, the DynEntry rows and the FnStatic rows are keyed by the prefix word, with the object-state bits cleared.
  - `fn_find` reads the word of the object it is given. A word without the magic and the closure flag reads as anonymous.
  - Class source text moves to its own row kind (`unitKindClassSrc`, 10), keyed by the reference as before.
- **Library split:** an alias's cell always joins the alias's unit, and another unit declares the alias as an external global of its value type in the managed address space.
- **Address hashing:** the weak per-evaluation tables in `unitreg.c` (KwTab: class records, each instance's record) now hash keys through `kml_id_hash` (ADR-01939), like the `any` map.
- **Dead code:** the `FN_EXT` paths are deleted.

## Implementation notes

- **Prefix word and allocation:** `objheader.go` (`kmlHdrClosure`, `emitClosureAlloc`, `emitStaticFnRecord`), `kml_heap.h` (`kml_closure_alloc`), `emit_stackalloc.go`.
- **Ids and rows:** `fnmeta.go` (`fnWord`, `registerClassSrc`), `fnmetasrc/fnmeta.c`, `emit_dynentry.go`, `emit_classref_rows.go`, `emit_classref.go`.
- **Free paths:** `coresrc/core.c`, `promisesrc/fetchbodyprom.c`.
- **Library split:** `libsplit.go`.
- **Weak tables:** `unitregsrc/unitreg.c`.
- **Call sites:** the Go sites (`emit_anyprom.go`, `emit_asynchooks.go`, `emit_decorators*.go`, `emit_dynfunc.go`, `emit_fetch.go`, `emit_generators.go`, `emit_promise_*.go`, `emit_record_view.go`, `emit_timers.go`, `fnproto.go`, `emit_func.go`, `emit_func_value.go`, `emit_builtin_proto.go`, `emit_host_shape.go`, `emit_shape.go`) and the C sites listed above.

## Side effects discovered

- The direct free in `fetchbodyprom.c`.
- The library split's alias handling.
- `__kml_gen_fn_bag` passed a stack copy of the header, `{fn, env, 0}`, as the record that seeds a generator function's bag. `fn_find` then read the word before that copy, which is stack garbage. ASan reported it as a stack-buffer-underflow; without ASan it made `g() instanceof g` false for a generator function expression. It now passes the header itself.
- `TestLibUnitsSameAcrossPrograms` caught per-program ids in library units: a content-hashed adapter, `__kml_dyn_bound` and a library generator's constructor. All of these now get stable ids.

## Verification

- A probe covering named, arrow, bound, async and generator functions, class source text, builtin method names, own properties on a function, `Number`/`String`/`Object` statics through `any`, timers, microtasks and promise callbacks matches Node.
- The function-metadata, bind, foreign-instance (dynamic entry), fetch and HTTP E2E suites and the `codegen/llvm` unit tests pass on the Mac.
- The full gates on Linux are recorded with the delivery.
