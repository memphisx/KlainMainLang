# ADR-00455: callable interfaces (lone call/construct signature)

- **Relations**: Extends [ADR-00448](ADR-00448.md)
- **Date**: 2026-08-29

## Context

The `expected IDENT, got (` bucket's interface half: a bare call signature
as an interface member (`interface F { (n: number): string }`), the
callable-interface idiom (plus its `new (…): T` construct-signature twin).

## Decision

Mirror ADR-00448's object-type treatment: an interface whose *only* member
is a call (or construct — the `new` is erased) signature registers in
`e.interfaces` as the equivalent function type, so `const f: F = (n) =>
…; f(3)` works. Mixed with any other member it stays a clean rejection —
callable objects have no runtime shape here.

## Implementation notes

`parser/parser_types.go` (member branch reusing
`parseObjectTypeSignatureTail`), `ast/nodes.go`
(`InterfaceDeclaration.CallSig`), `codegen/llvm/emitter.go`
(`registerInterfaces` registers the function type).

## Verification

Mac. `tests/interfaces_test.go` additions (callable-interface E2E incl.
construct form, mixed-members rejection) and the
`examples/interfaces/extends_merge.ts` extension pass; parser + interface
suites green. TS oracle 5106 → 5108 agreement (most affected cases stack
further blockers). Node oracle unchanged (37).
