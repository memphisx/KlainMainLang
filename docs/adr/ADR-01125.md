# ADR-01125: Comparisons with no overlap (TS2367); `as` binds at relational precedence

- **Relations**: `Implements TDD-00230` (Phase 2, P2.5, P2.7); `Extends ADR-01112`, `ADR-01124`
- **Date**: 2026-09-25

## Context

After [ADR-01124](ADR-01124.md), TS2367 is the most frequent error in
TypeScript's baselines that the strict lane did not report. It flags an
equality whose operand types cannot hold the same value, such as `1 === "a"`,
or `x === "b"` after `x` was narrowed to `"a"`. That makes it a direct test
of the checker's narrowing: a type narrowed wrongly shows up as a false
positive.

## Investigation

- **tsc 5.6.3's rule** (`checkBinaryLikeExpressionWorker`) is
  `isTypeEqualityComparableTo(l, r) || isTypeEqualityComparableTo(r, l)`:
  - a target that is exactly `null` or `undefined` takes anything;
  - otherwise the comparable relation applies, in which a union relates
    when some member does.
  - The message names the operands' base types when those are unrelated too
    (`1 === "a"` prints `number` and `string`).
  - `==` is not exempt: `42n == 42` and `s == 1` are TS2367 as well.
- **The first measurement** gave 147 matches and 37 false positives. Every
  false positive traced to two defects elsewhere.
- **The parser bound `as` looser than the ternary.** So
  `"foo" === "bar" as string` parsed as `("foo" === "bar") as string`, and
  `test(state as any && state)` failed to parse. TypeScript gives
  `as`/`satisfies` the precedence of `<`, left-associative, and ends the
  expression at a line break before the keyword (`asOperatorASI.ts`).
- **Loose equality never narrowed**, and strict equality kept the
  primitive:
  - after `if (x == 1) break;`, a `const x = 1` was still `1`;
  - after `if (x === 1)`, `x: string | number` was still `number`, where
    tsc has `1`.
  tsc's `narrowTypeByEquality` works like this:
  - the true branch keeps the members comparable with the value, or those
    `isCoercibleUnderDoubleEquals` to it under `==`;
  - it then runs `replacePrimitivesWithLiterals`;
  - the false branch drops the unit members comparable with a unit value.
  - The `==` coercion applies against a non-literal `number`, `string` or
    `bigint` value only, so `s == 1` narrows a string `s` to `never`.
- **Enums** (probed with tsc): an enum member is comparable with a plain
  literal of the same value (`Col.Red` with `'r'`, `Dir.E` with `1`). It is
  not comparable with a different member or value.

## Decision

- **`checker.comparable`** is the comparable relation over primitives,
  their literals, null, undefined and enum members. It also covers an
  array, tuple or function against a primitive. Two object types, or an
  object and a primitive's possible apparent type, are `maybe`, and nothing
  is reported for them.
- **TS2367** (`diag.NoOverlap`) is reported when neither direction is
  comparable, and neither operand is exactly `null` or `undefined`.
- **Equality narrowing** follows `narrowTypeByEquality`, as described
  above. Narrowing uses the plain comparable relation, not the equality
  rule's nullable exemption.
- **The parser** parses `as`/`satisfies` in `parseRelational`'s loop
  (`parseAssertion`), not after the ternary.

## Implementation notes

- `checker/check.go`: `checkEquality`, `comparable`, `primKind`,
  `nullableUnit`.
- `checker/narrow.go`: `narrowByEquality`, `isUnit`, `coercible`,
  `replacePrimitives`.
- `parser/parser_exprs.go`: `parseAssertion`, called from `parseRelational`.
- `tools/tsdiag`: TS2367 is a strictness-free code.

## Side effects discovered

- **Two examples held TypeScript errors that tsc also reports.**
  - `examples/bigint/bigint.ts`: `42n == 42` is now written
    `(42n as bigint | number) == 42`.
  - `examples/types/unions.ts`: `a === c` after the two were narrowed to
    `number` and `string` now uses `c = "5" as string | number`.
  - The old comment there claimed `0`; the program prints `false`, as Node
    does.
- **Codegen rejects `const z: "q" = y` where `y: never`**, which is valid
  TypeScript. It is one of the codegen rejections P2.7 moves onto the
  checker.

## Verification

- **Checker tests:** `TestNarrowing` asserts tsc's `1` for `x === 1`.
- **`tools/tsdiag`:** TS2367 has 176 reports, all matching tsc's baselines,
  and 0 false positives. The project's own programs report 0.
- **AST dumps over 71,783 files** (TypeScript's cases, Test262, examples,
  apps, tests) differ in 5 files, each now parsed as tsc parses it. Four
  failed to parse before.
- **The two edited examples** print the same output as Node.
