# ADR-00624: `-compat=js` vanilla-class inference + suppressed definite-assignment

- **Relations**: `Implements TDD-00022 (sub-problems 1 ctor-slice, 2, 5)`, `Extends ADR-00217 (the -compat axis), ADR-00042`
- **Date**: 2026-09-02

## Context

[TDD-00022](../tdd/TDD-00022.md)'s first delivery. Since that document was
written, two things changed: the `-compat=strict|js` axis
([TDD-00075](../tdd/TDD-00075.md)) shipped — so JS mode needs no new flag,
just new inhabitants — and the D1 dynamic object model
([TDD-00155](../tdd/TDD-00155.md)) landed the runtime representation the TDD
had declared out of reach for its prototype-OOP sub-problem. This ADR ships
the static-inference half; prototype "classes" ride D1 Stage 4 separately.

## Decision

Three `-compat=js` behaviors, strictly additive (strict mode byte-identical),
plus one both-modes bug fix:

- **Constructor-inferred class fields** (sub-problem 2,
  `emit_classes_jsinfer.go`): a class with a constructor and no declared
  instance fields collects them from the constructor body's
  `this.NAME = expr` assignments (recursive statement walk — branches/loops/
  try/switch count). Types: a bare constructor-parameter RHS takes the
  parameter's type; anything else goes through `inferExprType`.
  First-assignment-wins; a later assignment of a different kind, or an
  uninferrable RHS, is a hard error asking for an annotation. Constructor-
  only by design: a method inventing a field stays a clean "no field"
  rejection. The synthesized fields join `ownFields` in `registerClasses`
  pass 1, so layout/visibility/inheritance machinery is untouched — the
  vanilla `class Point { constructor(x, y) {...} }` compiles to the same
  static struct an annotated one does, at native speed (no dynamic bag).
- **Call-site-inferred constructor parameters** (the constructor slice of
  TDD-00005's "option 2", adopted by sub-problem 1): a whole-program AST
  pre-pass collects every `new ClassName(args)` site before class
  registration and types each *unannotated* constructor parameter from the
  arguments actually passed (`jsCollectCtorParamTypes`). First-inferrable-
  site-wins; two sites disagreeing on a parameter's kind is a hard error.
  Annotated parameters always win; a parameter no site can type keeps the
  ADR-00042 number default. This is what makes `new Animal("Rex")` +
  `this.name = name` infer a real string field. Plain *function* parameters
  are the next slice, not this one.
- **Suppressed definite-assignment** (sub-problem 5, `resolver.go`): the
  TS-only "used before being assigned" early error is skipped under
  `-compat=js` — plain JS has no such concept. TDZ and redeclaration stay on
  in both modes (real JS errors); the suppressed read is deterministic
  because an uninitialized slot is zero-initialized (ADR-00215). The
  resolver-side `-compat=js` bool (formerly only ambient-global shadowing)
  now governs both.
- **Bug fix, both modes**: the ADR-00042 guard — a non-numeric argument to
  an unannotated (number-defaulted) parameter is a clean compile error — was
  never applied to *constructor* calls: `new C("oops")` against an
  unannotated ctor param silently stored the string pointer as a number.
  The guard now covers `emitNewExpression`'s argument loop.

## Consequences

- Idiomatic vanilla JS classes (fields via constructor, untyped params,
  `extends`/`super`, JS-style branch-assigned locals) compile natively under
  `-compat=js` with output byte-identical to Node on the verification
  programs — as concrete static structs, not dynamic bags.
- `make examples` gains a `-compat=js` lane (`examples/jsmode/*.js`).
- Disclosed limits: inference sees `new` sites whose argument types are
  statically inferrable (a local-variable argument contributes nothing);
  `super(...)` chains aren't collection sites yet; plain-function parameter
  inference and the prototype-class shape remain (TDD-00022's next slices).
- Verified on the Mac (arm64): 8 E2E tests (`tests/jsmode_test.go`), the
  class/compat regression suites green.
