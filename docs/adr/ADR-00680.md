# ADR-00680: AsyncLocalStorage — static `bind` + `AsyncResource`

- **Relations**: Extends ADR-00678, ADR-00679 (AsyncLocalStorage Stages 1–3);
  Implements TDD-00168 Stage 4; builds on the closure ABI (`emitClosureCallByPtr`)
- **Date**: 2026-09-03

## Context

Stages 1–3 delivered the AsyncLocalStorage instance surface with context
propagation across `await` and timer callbacks. Stage 4 adds the remaining
context-capture APIs: static `AsyncLocalStorage.bind(fn)` / `snapshot()` and
`AsyncResource` (`runInAsyncScope`). These capture the *current* async context
into a reusable callable — the tool for running a stored callback (an event
handler, a queued job) back in the async scope it was created in.

## Investigation

All three want to capture a runtime context head and reinstall it around a later
call. `AsyncResource.runInAsyncScope(fn, …)` is direct — a method that installs
the captured head, invokes `fn` (via the existing closure-call ABI), and
restores — no new closure is produced.

`bind(fn)` and `snapshot()` must return a *first-class callable*. The closure ABI
here is `<ret> fn(ptr env, params…)` — env first, then typed args. `bind(fn)`'s
returned wrapper has fn's own, already-known signature, so a **monomorphic
trampoline** with exactly that ABI can forward the params to the original.
`snapshot()` is different: it returns `<R, A extends any[]>(fn: (...a: A) => R,
...a: A) => R` — a *generic* runner whose parameter and return types are only
known at each later call site. This compiler has no generic first-class closures
(a monomorphic wrapper would have to fix `R`/`A` at `snapshot()` time, which the
API forbids), so `snapshot()` is a clean rejection — a language-level gap, not an
ALS one.

## Decision

- **`AsyncResource`** — a new handle type (`IsAsyncResource`, a `{ ptr
  capturedCtx }` record). `new AsyncResource(name?, opts?)` captures the current
  context head (name/opts accepted and ignored — labels for the tracing API that
  is out of scope). `runInAsyncScope(fn, thisArg?, ...args)` installs the captured
  head, invokes `fn` with the trailing args via `emitClosureCallByPtr`, restores,
  and returns `fn`'s result. `thisArg` this-binding is a V1 limitation (closures
  carry no dynamic `this`).
- **`AsyncLocalStorage.bind(fn)`** — captures the current head into a `{ ptr
  origClosure, ptr capturedCtx }` env and returns a closure value of `fn`'s own
  type whose fn-pointer is a **monomorphic trampoline** (`ensureAlsBindTramp`,
  memoized by signature) with `fn`'s ABI: it installs the captured context,
  forwards its own params to the original closure, restores, and returns the
  result. Scalar/pointer parameters and returns are supported; an array/rest
  parameter is rejected (the `(ptr,i64)` decomposition isn't threaded through the
  trampoline). A non-function argument is a compile-time type error (Node's
  runtime `ERR_INVALID_ARG_TYPE` has no analogue in the typed model).
- **`AsyncLocalStorage.snapshot()`** — a clean rejection naming the generic
  first-class-closure gap.

The static `bind`/`snapshot` calls are dispatched syntactically off the bare
`AsyncLocalStorage` identifier (it is not a variable), before any receiver-type
inference. `AsyncResource` is wired exactly like the other async_hooks handle
(marker member, identity constructor, `new`/method/inference/var-decl cases).

## Implementation notes

- `ensureAlsBindTramp` builds the trampoline IR directly into the globals buffer
  — a self-contained function needing no alloca/body builder — keyed by
  `retIR + "_" + paramIRs` so two same-shaped signatures share one trampoline.
- The Stage-3 timer wrapper and a Stage-4 `bind`/`runInAsyncScope` compose
  correctly: a `setTimeout` scheduled in a `run(...)` installs the schedule-time
  context, and the bound/scoped call installs its own captured context on top —
  both resolve to the same store in the common case.

## Side effects discovered

None. `.then`/EventEmitter-listener propagation (Stage 5) and `snapshot()` (on a
future generic-closure foundation) remain the open follow-ups.

## Verification

Mac. New E2E tests in `tests/node_core_modules_test.go`: `bind` (captured
context + argument forwarding, called outside the `run`), `AsyncResource`
(`runInAsyncScope` replaying a construction-time context after the `run` exited),
and the `snapshot()` clean rejection. Manual: `bind`/`AsyncResource` composing
with the timer wrapper. An `AsyncResource`-only program (no AsyncLocalStorage)
compiles and runs. Full ALS/async/timer regression green. `go build`/`go vet`
clean.
