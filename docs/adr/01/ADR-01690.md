# ADR-01690: A Map or Set read through an `any` view dispatches by layout

- **Relations**: Implements TDD-00258
- **Date**: 2026-10-18

## Context

TDD-00258 Stage 1. A `Map<string, number>` passed to a `Map<any, any>` parameter ran the view's flavor over raw words:
- `get('a')` missed;
- values read as boxes (`1` printed `0.9375`);
- `set` stored a box among raw doubles.

## Decision

**Views.** Every Map or Set type is a view. `any` and an assertion reach a typed variable without converting (`box as Map<string, number>` over a `Map<any, any>`), so a typed type can't promise its layout either.

**Layouts.** `noteMapLayout` registers every Map and Set instantiation the program creates (`emitMapOrSetCreate`). 

**Operations.** `get`, `has`, `set`, `delete` (a Set's `add`, `has`, `delete`) through a view test the receiver's header word:
- **The view's own layout:** the operation runs as before.
- **Another layout:** it calls a dispatcher, `@__kml_mview_<op>_<view>`.
- **Arguments:** each is evaluated once into a temporary of its own type. The own path reads it unboxed; the other path boxes it.

**Dispatchers.** They are generated at module end. Each switches on the header word over the registered layouts, and each case runs that layout's own typed method on the `any` operands and boxes the result. Requests can arrive from later finalize steps (structuredClone's routines), so generation runs again after them and emits only what is new.

**Reads of every entry.** Iteration (`keys`, `values`, `entries`, `forEach`, for-of, spread, `Array.from`) and structuredClone through a view read `mapViewPtr`:
- the object itself when it has the view's layout;
- otherwise a snapshot copied into the view's layout by the `copy` dispatcher.

The object stays shared: writes go through the dispatchers. Inspect renders a foreign object the way a boxed value renders, by its own header word.

**Keys and values from `any`.** A boxed key bound for a string- or number-keyed table:
- becomes the box's string or number when the box holds one;
- otherwise becomes a marker no program value can equal (a miss).

A boxed value bound for a typed slot is unboxed into the slot's type. Before, its raw word was stored.

**Not in this stage:**
- The shared builtin library's units are compiled once for every program, so their code can't name a program's dispatchers, and a typed view there keeps its own flavor. The library reaches a program's maps through `any` (`instanceof Map` on a boxed value), which reads by the object's own layout: `assert.deepStrictEqual`, `util.inspect`, `structuredClone` of a boxed object and `postMessage` of a typed map match Node.
- A value a typed view's static type cannot hold diverges: through a `Map<string, number>` view of a map holding `'x'`, a loop variable reads `NaN`. Node erases the type and reads `'x'`. An unboxed `number` slot cannot hold a string, so this follows from native representation. `console.log` of the map itself renders the real entries.

**Cost.**
- A view whose object has its own layout pays one compare and branch.
- A foreign object costs one routine call per operation, plus a copy per full read. A full read of a foreign map through a view is O(n).
