# ADR-01479: Counts and indexes are numbers; a nullable generic annotation

- **Relations**: Extends ADR-01478
- **Date**: 2026-10-09

## Context

TDD-00230 P3.3 moves codegen onto one representation per type: `reprOf`
of the checker's type. The shadow comparison over the examples (`go run
./tools/shadow -roots examples`) lists 9,731 `inferExprType` disagreements
in 238 buckets; this is the first pass over them.

## Investigation

- Callback indexes: every Array method passed its callback an `i64` index
  (`resolveCallbackWithHints(…, TypeI64, …)`), and the inference of a
  callback's return type assumed one, while the checker types the index
  `number`. `[0, 0].map((_, i) => (i + 2**32) * 2**32 + i)` is exact in
  double arithmetic and overflows in `i64`; `Array.from({ length: 4 },
  (_, i) => i * i)` printed the doubles' bit patterns once the callback
  took a double and the inference still said `i64`.
- Builtin counts: `length`, `size`, `byteLength`, `byteOffset` and
  `maxByteLength` of an array, string, collection or buffer were `i64`
  values; the checker's `number` is a double. Operators already promoted
  them where JavaScript's result differs, so this was a representation
  disagreement, not a wrong output.
- `Promise<T> | null` (and a generic class instance `| null`) lost its
  `null` in `resolveType`: the builtin-generic and generic-class branches
  returned before the annotation's nullability was applied. `const p =
  feed.promise; await p` with the field null segfaulted; Node resolves the
  await to `null`.

## Decision

- A callback's index argument is a double: every Array, search and
  `replace` callback hint, and `callbackReturnType`, take `TypeF64`
  (`hofCBArgs` passes the `i64` counter, converted at the call).
- A builtin count read is a double: `emitExpr` converts it
  (`countToNumber`) and `inferExprType` answers `TypeF64`
  (`builtinCount`), for an array, string, Map/Set, typed array, Buffer or
  ArrayBuffer receiver; a class or object field of that name keeps its
  declared type.
- `resolveType` applies an annotation's `| null`/`| undefined` to a builtin
  generic and a generic class instance (`withAnnotNull`).
- `await` of a nullable promise inside an async function, module task or
  generator boxes it (its null as `null` or `undefined`) and awaits the
  box (`emitAwaitAny`): the null after a tick, as JavaScript awaits a plain
  value.
- The oracle builds an object literal's fields from its values' storage
  types: a narrowed read does not change how a value is held.

## Divergences

None.
