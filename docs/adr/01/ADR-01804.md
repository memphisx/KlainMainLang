# ADR-01804: Failed writes and deletes do nothing in sloppy code; function own keys after delete

- **Relations**: `Implements TDD-00230`
- **Date**: 2026-10-20

## Context

- A write the object refuses (a read-only or getter-only property, a frozen or non-extensible object) and a refused delete (a non-configurable property) threw a TypeError everywhere. Node throws only in strict code. In a sloppy CommonJS file the write does nothing and `delete` answers false. Test262's `verifyProperty` relies on the sloppy form.
- A function's property bag is created holding its own `name` and `length`. After `delete f.name`, `hasOwnProperty` still answered true, because a miss in the bag fell back to the built-in pair. `in` also has to keep seeing `name` and `length` there, since `Function.prototype` has its own.
- `delete f.length` on a function declaration, `delete o.a` on a plain static object, and a property write or unknown-property read on a primitive (`"abc".length = 1`, `s.q`) were compile errors in the js lane.

## Decision

- `sloppyWriteSites` records, for each assignment, update and `delete` in a sloppy file (`sloppyFiles`), whether it runs in sloppy code. Class bodies and functions with a "use strict" directive are strict. `emitExpr` sets `sloppyWrite` while emitting such a node. The dynamic-object and static-object rejection paths then skip the throw, and a refused delete gives false. The outlined dynamic-set helper is keyed by sloppiness, since sloppy and strict sites can't share one body.
- When a function has a bag, a miss there is an own-key miss. `__kml_fn_has_proto_member` then answers for `in`, and `Function.prototype` now includes `name` and `length`.
- The other refusal sites follow too. A frozen or sealed array's direct element and `length` writes go through `__kml_array_refuses` (built-in methods such as `push` throw in sloppy code too, as in Node). A String wrapper's index and `length` take `__kml_wrapper_set`'s sloppy flag. A static object's field write tests `emitStaticWriteRefused` after evaluating the value (the strict path still checks first). A non-extensible object's new key is refused silently.
- In sloppy code, a compound write to an array element or a field whose receiver (and index) have no side effects is lowered to `x = x op v`, so the refused write does nothing.
- In the js lane, `delete` on a function or a plain static object boxes it and takes the dynamic delete. A write to a primitive takes the dynamic set: nothing in sloppy code, and in strict code Node's TypeError ("Cannot create property 'foo' on string 'abc'", or "Cannot assign to read only property 'length' of string 'abc'"), built by `__kml_prim_set_throw`. A read of a property the primitive's prototype lacks reads undefined.

## Consequences

- `TestE2EJSFileSloppyFailedWrites` compares sloppy writes and deletes on frozen, read-only and function properties, the strict-function and class-body throws, and function own keys after delete against Node.
- Not yet covered: `delete` of a class instance's field (no presence bits) stays a compile error. A refused logical assignment (`||=`, `??=`) and a compound write through a receiver with side effects still throw in sloppy code. In strict code, a static object's frozen or read-only check still runs before the value is evaluated.
