# ADR-00228: Built-in utility types, stage 1a — Partial/Required/Readonly/NonNullable

- **Relations**: `Implements TDD-00079` (Stage 1a)
- **Date**: 2026-08-19

## Context

First increment of mapped/conditional types ([TDD-00079](../tdd/TDD-00079.md)):
the single-type-argument built-in utility types `Partial`, `Required`,
`Readonly`, and `NonNullable`. Chosen first because they need none of the
feature's three big prerequisites (the type-level grammar, field optional/
readonly state, or a structural assignability predicate) and they fix a real
silent-wrong-result bug: today `Partial<User>` resolves to `User[]` via
`resolveType`'s generic `ElemType` fallback (emitter.go), and a bare unknown
`Name<Args>` resolves to `i64` — neither is correct or a clean error.

## Investigation

`resolveType` already turns a registered generic interface + concrete type args
into a concrete `ObjectType` (`instantiateGenericInterface`, emit_generics.go).
Utility types slot in at the same point: because the compiler monomorphizes, a
utility type has concrete inputs by the time `resolveType` runs and can be
*evaluated* to a concrete `Type` there, then flow through the unchanged object
machinery — no runtime representation of its own.

For this stage the four utilities need no new grammar: `Partial<User>` already
parses as `TypeAnnotation{Name:"Partial", TypeArgs:[User], ElemType:User}` (the
generic fallback in parser_types.go). The only reason it misbehaved is that
`resolveType` had no branch for the name, so it fell through to the `ElemType`
array fallback (`Partial<User>` → `User[]`).

Semantics in this compiler's object model: object-literal fields are already
omittable and calloc-zeroed (ADR-00157), and there is no mutation checking, so
`Partial`/`Required`/`Readonly` have **no observable runtime effect** — they are
structural transforms with nothing to transform yet. This is stated plainly
rather than dressed up; the value delivered here is correct *resolution* (the
right shape instead of `User[]`), which unblocks the common "options bag"
(`Partial<Config>` parameter) and DTO patterns.

## Decision

Add `resolveUtilityType(name, args)` (emit_utility_types.go), consulted from
`resolveType` **after** the user-defined generic registry (so a user type of the
same name still wins) and **before** the generic `ElemType` fallback:

- `Partial<T>` / `Required<T>` / `Readonly<T>` → resolve to `T`'s own type
  (structural no-ops in the current model; the shape is what matters).
- `NonNullable<T>` → resolve `T` and clear the `Nullable` flag.

A one-entry-per-name `utilityTypeNames` set gates the lookup so the common
non-utility name skips the switch. Only arity-1 utilities are handled here;
`Pick`/`Omit`/`Record` (string-literal keys), general mapped types, and
conditional types are later stages of TDD-00079.

## Implementation notes

Placed after the `genericInterfaces` branch in `resolveType` so user definitions
take precedence. No new runtime representation and no codegen changes — a
resolved utility type is an ordinary `ObjectType`/scalar and uses every existing
object path (`FieldIndex`, object-literal coercion, params/returns) unchanged.

## Side effects discovered

The broader silent-fallback problem TDD-00079 notes — an *unrecognized*
`Name<Args>` still silently becomes `Args[]`/`i64` rather than a clean rejection
— is **not** fixed here; it is TDD-00079 Stage 0 and needs the use-site-validator
plumbing (resolveType has no error return). This stage only stops the four named
utilities from hitting that fallback.

## Verification

- `tests/utility_types_test.go`: Partial with a missing field (the pre-fix
  failure), Required/Readonly, a Partial parameter, and NonNullable stripping
  `string | null`. All pass; emitted IR verified with `clang`.
- `examples/types/utility-types.ts` added and runs correctly.
- `go build`, `go vet ./codegen/...`, and the object/interface/generic/
  intersection/nullable test subset are green on Apple Silicon (macOS).
