# ADR-00204: Object rest `{ ...rest }` over a statically-known source shape

- **Relations**: `Implements TDD-00065` (Stage 3b); `Extends ADR-00193, ADR-00203`
- **Date**: 2026-08-17

## Context

Object destructuring had no rest element — `const { a, ...rest } = obj` was a
parse rejection, and `docs/status/LANGUAGE-CONSTRUCTS.md` disclosed the gap.
[TDD-00065](../tdd/TDD-00065.md)'s Stage 3 split (see [ADR-00203](ADR-00203.md))
isolated `{ ...rest }` into **3b** — the source object's shape is statically
known, so the residual ("source fields minus the named keys") is computable at
compile time — and **3c** — the source is `any`/a union/a generic `T`, needing
runtime field enumeration, deferred. This ADR delivers 3b.

## Investigation

- Every destructuring position (declaration, for-of loop variable, parameter)
  funnels through one codegen core, `unpackObjectPatternInto`
  (`codegen/llvm/emit_objects.go`), which resolves each property by
  `objTy.FieldIndex(prop.Key)` against a concrete `IsObject` type with real
  `Fields`. So at that point the source shape is always statically known — the
  3c case (`any`/union/generic) never reaches this path — which is precisely why
  3b is separable and cheap.
- The object-literal spread copy loop (`emitObjectLiteralWithHint`,
  `emit_objects.go:148`) already demonstrates the exact field-copy shape needed:
  iterate `VisibleFields()`, GEP the source field, load, store into the
  destination. `VisibleFields()` (`types.go:899`) is the right field set — it
  omits a class/error type's hidden metadata, so a class instance's rest is a
  plain own-enumerable-property object, matching JS.
- `ObjectType(fields)` (`types.go:328`) synthesizes a structural object type on
  the fly, and `StructIR()` emits an inline anonymous struct literal (no type
  registration), so a freshly-computed residual type is immediately usable by
  every downstream consumer (field access, further spread, `JSON.stringify`,
  `console.log`) with no new machinery.

## Decision

Parse `{ ...ident }` in `parseObjectPatternProps` as a new `DestructProp` with
`Rest: true`, requiring it to be the last property (real JS forbids anything
after it) and a plain identifier (no rename, default, or nested sub-pattern).

In `unpackObjectPatternInto`, first collect the set of keys named by the
non-rest properties. When the rest property is reached, `bindObjectRest`
computes the residual field list as `objTy.VisibleFields()` minus the named
keys, `calloc`s a fresh object of `ObjectType(residual)`, copies each residual
field from source to destination by a raw load/store of its storage IR
(`StructFieldIR`) — a shallow copy, so a pointer-valued field (string, array
header, nested object) is shared, exactly like object spread and JS's own
`{ ...x }` — and binds `local` to a `Symbol` over the new object.

The residual is a plain `ObjectType`, so it excludes hidden class/error fields
(a class instance's rest is a plain object) and rides all existing object
codegen unchanged.

## Implementation notes

- `ast/nodes.go`: added `DestructProp.Rest bool`.
- `parser/parser_stmts.go`, `parseObjectPatternProps`: leading `ELLIPSIS` branch;
  enforces last-position and identifier-only.
- `codegen/llvm/emit_objects.go`: named-key set built once at the top of
  `unpackObjectPatternInto`; new `bindObjectRest` helper. `calloc` (not `malloc`)
  for the residual, matching object-literal construction (ADR-00157) so an unset
  slot reads back zero.

## Side effects discovered

- The **assignment** form (`({ a, ...rest } = obj)`) goes through a separate,
  deliberately narrower path (ADR-00160, no nested/default there either) and
  cleanly rejects a rest target (`a rest target ('...') is not supported in a
  destructuring assignment`) rather than miscompiling — an acceptable scope cut,
  consistent with that form's existing limits; extending it is future work.
- 3c (`{ ...rest }` over `any`/union/generic) remains deferred by design.
