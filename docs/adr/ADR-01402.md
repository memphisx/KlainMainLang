# ADR-01402: Connection fibers and the HTTP accepts move to C

- **Relations**: Implements TDD-00244; Extends ADR-01400
- **Date**: 2026-10-05

## Context

With the TLS accept heads gone ([ADR-01401](ADR-01401.md)), the primary
listener's accept, the additional listeners' accept and the connection-fiber
start (`__kml_http_append_conn`) were fixed IR text, the same for every
program apart from three platform values: `O_NONBLOCK`, and `ucontext_t`'s
size and field offsets.

## Decision

- The three functions are C in `loopsrc/loop.c`, next to the fiber resume
  they mirror. One `accept_into` sets `TCP_NODELAY` and `O_NONBLOCK` and
  starts the fiber with the server's dispatcher.
- `ucontext_t` stays opaque to the C: the emitter passes its size and the
  `ss_sp`, `ss_size` and `uc_link` offsets as `KML_UC_*` cflags, from the
  same `ucontextLayout` that sizes `@__kml_main_ctx`. On Windows that is
  `win32io.c`'s own context record.
- `@__kml_conn_cap` and `@__kml_listen_dispatch` lose `internal` linkage so
  the C can reach them; `@__kml_http_nodelay_one` is deleted.
- The IR-text ratchet for `runtime_http.go` drops from 17 to 14.

## Verification

- Mac (M4): the HTTP listen, server and createServer tests, and the codegen
  unit tests.
- Linux (x86-64, Ubuntu 24.04 container), with ADR-01402 to ADR-01404: the
  full test suite (3,923 tests), the 393 examples, and Test262 in both lanes
  (strict 8,498, js 10,506, unchanged, no invalid IR).
