# ADR-01279: parameter defaults for arguments undefined at run time

- **Relations**: `Extends ADR-00598`, `Extends ADR-00915`
- **Date**: 2026-09-29

## Context

JavaScript applies a parameter's default whenever the argument is
`undefined`. Before this change, a call applied the default only when the
argument was omitted or was the literal `undefined`. An argument that
became undefined only at run time kept its converted value instead:

- an `any` holding `undefined`;
- a `number | undefined` local;
- a `string | undefined` local.

So `f(v)` for `function f(o: number = 5)` and `let v: number | undefined`
gave 0, where Node gives 5. `f(u)` for `u: any = undefined` gave NaN.
`options: any = {}` stayed `undefined`, which broke `timers.promises`.

A closure call also ignored a literal `undefined` argument.

## Decision

- For a defaulted scalar, string, object or `any` parameter whose argument
  may be undefined, every call site tests the argument at run time:
  - the call sites are functions, methods, static methods, constructors
    and closures;
  - an argument may be undefined when its type is dynamic, or a
    `T | undefined` scalar or pointer.

  The default is evaluated only on the undefined branch, so its side
  effects happen only when it applies. Both branches convert to the
  parameter's type and meet in a phi (`emitArgOrDefault`).
- A closure whose default is filled in its body (it references a captured
  variable) takes a presence mask. The mask used to be a compile-time
  constant; now a bit is cleared at run time for an argument that is
  undefined.
- A closure call treats a literal `undefined` argument as omitted, as the
  other call paths already did.

## Verification

Mac (Apple Silicon): `TestE2EDefaultParamRuntimeUndefined` and
`TestE2EDefaultParamRuntimeUndefinedBodyFilled` print what Node v24.19.0
prints, including a default with a side effect that runs only when it
applies.
