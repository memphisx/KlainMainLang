# TDD-00179: Multi-platform CI, per-platform release binaries, version stamping, installers

- **Status**: Implemented (ADR-00732)
- **Date**: 2026-09-06

## Context

Releases were tags cut by `go-semantic-release` after a single Ubuntu test job (a Windows lane joined it the same day); nothing was attached to them, and the compiler's own version (`process.versions.klain`) was a hand-typed constant that had drifted to `0.52.0` while the tags stood at `v0.63.0`. Three related needs, all reached by the Windows port making a second platform real:

1. Test on every supported platform in parallel — Windows x64, Linux x64, Linux aarch64, macOS x64, macOS aarch64 — without one platform's failure hiding the others' results.
2. Attach a binary per platform to each release, *only* for platforms whose tests passed for that version: a red lane drops its platform from the release until a later release is green there, it does not block the release.
3. Give users a way to install the binary without building: fetch the right asset into a user-writable location, verified.

Auto-update inside `klainmain` is deliberately left for after the first release of this shape.

## Design

### Where the binary is built
- **Option A — upload each lane's own build.** Each test job also uploads the `klainmain` it built. Simple, but the version is not known until `go-semantic-release` runs *after* the lanes, so the binaries would be unstamped (or stamped with a guess).
- **Option B (chosen) — cross-compile in the release job.** The lanes are pure gates; the release job, once the tag is known, cross-compiles one binary per passed platform with `-ldflags -X …KlainVersion=<v>`. The compiler is pure Go (no cgo — it shells out to `clang` at run time), so cross-compiling is one `GOOS`/`GOARCH` pair per platform and the artifact is byte-identical to what the lane would have produced apart from the stamp.

### How "this platform passed" is expressed
- `needs.test.result` on a matrix job is the aggregate (`failure` if any leg failed) — it cannot say *which* legs passed.
- Chosen: each leg's last step, `if: success()`, uploads a one-line artifact `gate-<platform>` naming its `GOOS GOARCH name`. The release job (`needs: test`, `if: always()`) downloads `gate-*`; the set of files present is the set of platforms to build for, and an empty set means no release.

### No-release pushes
`go-semantic-release` fails when no `feat`/`fix` commit is pending; its `custom-arguments: --allow-no-changes` makes it exit 0 with an empty `version` output instead, and every later step is guarded on that output.

### Runners
`ubuntu-latest`, `ubuntu-24.04-arm`, `macos-15-intel`, `macos-15`, `windows-latest`. The arm and macOS runners are free for public repositories, which this is. macOS uses Apple's clang; the optional libraries come from Homebrew, with keg-only `openssl@3` exposed through `CPATH`/`LIBRARY_PATH`/`PKG_CONFIG_PATH`. Windows is the MSYS2 UCRT64 lane of TDD-00177 Stage 5.

### Version plumbing
`codegen/llvm.KlainVersion` becomes an exported `var` (default `0.0.0-dev`, deliberately not a real version) so `-ldflags -X` can set it; `klainmain --version` prints it with `GOOS/GOARCH`; `process.versions.klain` reads it at compile time into every program. `make build` stamps `git describe --tags --always --dirty` so no local checkout ships as `0.0.0-dev`; `make dist` runs the same five cross-compiles as the release job into `dist/`.

### Installers
- Asset names `klainmain-v<version>-<platform>[.exe]` plus `checksums.txt` (`sha256sum` format).
- `install.sh` (POSIX sh, curl or wget) and `install.ps1` (PowerShell 5.1+). Both resolve `latest` through `https://github.com/<repo>/releases/latest/download/<asset>` — no API call, so no rate limit and no token — or a pinned `KLAINMAIN_VERSION`; download `checksums.txt` first, so a platform absent from that release is reported with the list of what *is* there; verify SHA-256; install to `~/.local/bin` / `%LOCALAPPDATA%\Programs\klainmain` (override `KLAINMAIN_INSTALL_DIR`), the Windows script adding the folder to the *user* PATH; print `--version`, a PATH hint, and a reminder that `clang` and the libraries are separate installs. `KLAINMAIN_BASE_URL` points them at any directory or server for testing (a `file://` URL works with both `curl` and `Invoke-WebRequest`).

## Open questions

1. **Auto-update** (`klainmain update`, or a notice when a newer release exists): after the first release with assets; the `latest/download` URL and `checksums.txt` are the inputs it would reuse.
2. **Windows on ARM** lane: GitHub's `windows-11-arm` runners are still experimental; add when stable. The asset name scheme (`windows-arm64`) is reserved.
3. **macOS lanes** have never run the suite; the first push will show what the Homebrew wiring is missing (the CommonCrypto tests run in CI for the first time there).
4. **Signing/notarisation** of the macOS and Windows binaries: not started; unsigned assets prompt Gatekeeper/SmartScreen.
