# ADR-01241: Parameter defaults through dynamic calls

- **Relations**: `Extends ADR-01238`
- **Date**: 2026-09-29

## Context

With `EventEmitter` in TypeScript (ADR-01238), a listener
`(x: number = 5) => …` read `0` when `emit` passed no argument; Node gives
`5`. Any function called with fewer arguments through `any` or through a
`(...args: any[])` callback slot lost its defaults, except a typed arrow or
function expression bound to a variable first.

## Investigation

Probes against Node v24.19 (all read `0`/garbage where Node gave the
default):

- a function declaration boxed into `any`: `emitNamedFuncValue` builds the
  value's type from the signature without its defaults;
- an arrow written directly where `any` is expected: the dynamic function
  (`emitDynCallable`) bound a missing argument to `undefined` and never
  evaluated the default;
- an arrow passed for a `(...args: any[]) => void` parameter: the direct
  closure adapter spreads the rest tail by position and passes `undefined`
  unboxed to the parameter's type;
- a defaulted array parameter was a clean rejection in the boxing adapter;
  once the rejection moved behind `emitBoxedClosureAs`, which swallows the
  error, it left a dangling branch label (invalid IR).

## Decision

- A function declaration's value carries its call-site defaults
  (`FuncParamDefaults`). A declaration's default sees only module globals
  and earlier parameters, so each is a call-site fill.
- The dynamic function's prologue evaluates a parameter's default when its
  argument is `undefined`, with the earlier parameters in scope.
- The direct adapter does not take a source parameter the rest tail may not
  supply when it has a default: that conversion goes through the box, whose
  adapter fills defaults.
- The boxing adapter fills a defaulted array parameter: its header and
  length come from the default or the unboxed argument.
- When boxing a closure fails, the branch it opened is closed, so a caller
  that takes another route still emits well-formed IR.

## Verification

`TestE2EDefaultParamsThroughDynamicCalls`,
