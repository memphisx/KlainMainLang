# ADR-00990: D1 Stage 6 (part 1) — allocation-site widening of a fresh object into `any`

- **Relations**: `Implements TDD-00155` (Stage 6); `Extends ADR-00621` (D1 bag), `ADR-00622` (D1 dynamic arrays)
- **Date**: 2026-09-17

## Context

D1 shipped a full dynamic object model behind box tag 10 (ADR-00621…00630):
member get/set, prototype chains, descriptors, `Object.keys`/`JSON`, dynamic
arrays. But a *statically-typed* object value crossing into an `any` slot stayed
boxed as tag 6 (a bare pointer with no runtime shape), so member access on it
threw at runtime: `dynamic property access on a statically-typed value is not
supported`. This was the single most-cited remaining D1 caveat, appearing across
Object/Collections, Type-system, HTTP-server (custom `IncomingMessage`/
`ServerResponse`), decorators (metadata target), and more — the residue
TDD-00155 named as Stage 6 (the static→dynamic bridge).

Repro (all three compiled; the first two crashed at runtime):

```ts
const o: { x: number } = { x: 1 }; const a: any = o; a.x;   // Uncaught
const a: any = new C();            a.x;                      // Uncaught
JSON.stringify(o as any);                                    // already worked
```

## Investigation

- `emit_dynamic.go:439` boxes a static object into `any` as `kmlTagObject` (6);
  the dynamic member path (`emit_dynobj.go`) rejects tag 6 at runtime because it
  has no property table to read.
- TDD-00155 Stage 6 specifies **allocation-site widening**: when the front end
  can see a struct literal / `new` flow into a dynamic position, allocate it as
  Tier D from the start, so there is one representation per instance and
  reference semantics are preserved — explicitly *not* a runtime migration/copy
  of a live struct (the rejected trap).
- The conversion machinery already existed inline: `emitDynObjLiteral`'s
  object-spread arm (emit_dynobj.go) walks a static value's `VisibleFields()` and
  boxes each field into a bag. D1 dynamic arrays (`runtime_dynarr.go`) and the
  once-only `ensureDynObj`/`ensureDynArr` emitters were likewise in place.
- A box-time conversion of an *aliased* binding was rejected: it copies, so
  `a === o` and post-box mutation would diverge from JS (the copy trap). Only a
  **fresh allocation** (`new C()` with no prior binding) can be widened
  unconditionally — there is no alias, so the widened bag is the sole
  representation and identity/mutation stay faithful.

## Decision

Realize a fresh, widenable static-object allocation as a D1 bag at the point it
is boxed into `any`, instead of a tag-6 box.

- `emitStaticObjToBag(v)` builds a fresh `__kml_dynobj` from `v`'s compile-time
  `VisibleFields()`: scalars/functions box via `emitBoxValue`, arrays convert to
  D1 dynamic arrays, nested static-object fields recurse into nested bags (deep
  `a.p.x`), and a nullable object whose pointer is null widens to the `null`
  sentinel.
- `emitStaticArrayToDynarr(arr)` converts a static array to a tag-11 dynamic
  array with a runtime boxing loop (each element boxed; object elements that are
  themselves widenable recurse to nested bags), so `a.tags[0]`/`.length`/`.push`
  work through the dynamic path.
- `dynWidenable(t)` gates eligibility: a data shape (interface/struct types,
  data-only classes) with scalar/array/nested-data-object fields. It rejects a
  class carrying **methods** (a data-only bag would silently drop `a.method()`)
  and a **cyclic** object graph (the helper unrolls the shape at compile time, so
  a self-/mutually-referential field would unroll forever — `seen` breaks the
  recursion by declaring a cycle non-widenable). Array fields are checked by
  element type.
- `emitBoxValueWidened(v, srcExpr)` centralizes the choice — widen when `v` is a
  fresh `new C()` (`isFreshObjectAlloc`) of a widenable type, else box normally —
  and is called at **every** box-to-`any` boundary so behavior is uniform:
  var-decl init, `return`, call argument (direct + default), and assignment.

Non-fresh (aliased) bindings, method-carrying classes, and cyclic shapes stay a
clean rejection — honest, and matching a real distinction, not a half-working
widening. Object literals in an `any` context already widen upstream via
`emitDynObjLiteral`, unchanged.

## Implementation notes

- New helpers in `emit_dynobj.go`: `isFreshObjectAlloc`, `emitBoxValueWidened`,
  `dynWidenable`, `emitStaticArrayToDynarr`, `emitStaticObjToBag`. The bag/array
  builders emit multiple basic blocks (nullable guards, the array loop), so the
  nullable-object phi pins its predecessor with an explicit trailing label rather
  than guessing the current block, and the array loop uses an alloca'd counter so
  element boxing may span blocks safely.
- Call sites switched from `emitBoxValue` to `emitBoxValueWidened`:
  `emit_exprs_vardecl.go` (init), `emit_stmts.go` (return),
  `emit_call.go` (argument + default argument), `emit_exprs_assign.go`
  (assignment). The `Array.isArray` arg site keeps `emitBoxValue` (already
  dynamic).
- Widening a fresh allocation's array field copies it into a dynarr; this is
  faithful only because the source is fresh (no external alias), matching the
  fresh-allocation invariant the whole feature rests on.

## Side effects discovered

- A class field initialized without a type annotation (`p = new Point()`) did
  not acquire the field's object type, so even static `b.p.x` was rejected
  (`field access on non-object`). Pre-existing, independent of this change;
  widening surfaced it. **Fixed** in [ADR-00991](ADR-00991.md).
- Member access on a *method-carrying* class instance boxed into `any` remains a
  runtime rejection (not widened here) — it needs dynamic method installation
  (tag-12 functions bound to the bag), the next part of Stage 6.
- Aliased static bindings (`const a: any = o`) and cyclic shapes remain clean
  rejections — the remaining Stage 6 surface (escape analysis for aliased
  bindings), tracked in the backlog.
