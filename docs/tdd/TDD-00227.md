# TDD-00227: `n?: T | null` — absent vs explicit `null` vs present

- **Status**: Not Started
- **Date**: 2026-09-22

## Context

An optional field whose type is itself nullable has three states in TypeScript/Node:

```ts
interface P { s?: string | null }
const a: P = {};          // absent:  "s" in a → false, Object.keys(a) → [], a.s → undefined, JSON → {}
const b: P = { s: null }; // null:    "s" in b → true,  keys → ["s"],      b.s → null,      JSON → {"s":null}
const c: P = { s: "x" };  // present
```

Here `undefinedableElem` (`emit_undefined.go`) leaves an already-nullable type unchanged, so `s?: string | null`
*is* `string | null`: `IsUndefined` stays false, `jsonFieldSkippable` is false, and every "can this field be absent"
decision (`emitFieldPresent`, `hasSkippableField`, `Object.keys`/`values`/`entries`, `for…in`, `in`,
`hasOwnProperty`, `util.inspect`, `JSON.stringify`, `typeof`) treats the field as always present. An omitted
field reads `null`, is enumerated, and `"s" in a` is true. The same collapse happens to an explicit
`T | null | undefined`: the parser (`parser_types.go:179-238`) folds both keywords into `Nullable` + `Undefined`
booleans on one member, so the `| null` arm is erased. BACKLOG §0 item 5; ADR-01063/ADR-01066 side effects.

Representation today (survey, session 25): a nullable scalar is `{ i1 present, T }`; a nullable string/object/
array is a null pointer (array: null data pointer); `IsUndefined` is the *static* null-vs-undefined
discriminator. There is no per-object presence word — ADR-00779 chose per-field widening over a bitmap.

## Design

### The type

A new flag on `Type`: `ThreeState` (set when a field is `?:` **and** its type is `T | null`, or when the
annotation is `T | null | undefined`). `undefinedableElem` sets it instead of returning early; the parser keeps
both `Nullable` and `Undefined` and additionally records `NullAndUndefined` so `resolveType` can tell
`T | null | undefined` from `T | undefined`.

### The storage — Option 1 (recommended): widen the presence bit to a state byte

A `ThreeState` scalar is `{ i8 state, T }` with `0 = absent`, `1 = null`, `2 = present`; the existing `{ i1, T }`
helpers already read/write field 0, so the change is confined to `nullableScalarStorageIR`,
`makeNullableScalarAgg`, `nullableScalarAggParts` and the presence predicates, which gain a "which absent" answer.
A `ThreeState` pointer field (string/object/array/class) keeps the null pointer for `null` and needs a second
state for absent: a **1-byte side slot** appended to the struct per such field (`StructFieldIR`/`StructSize` place
it after the field; `VisibleFields` hides it). Calloc-zero of a fresh object is `absent` in both encodings (state 0
/ side byte 0), exactly as it is for plain optionals today (ADR-00157), so an omitted literal property still needs
no store; an explicit `null` store writes state 1 / side byte 1.

### Option 2 (rejected): a per-object presence bitmap word

One hidden `i64` at struct offset 0 with a bit per optional field. Cheaper per field, but it changes the struct
layout of *every* object with an optional field (classes already carry hidden leading words that every reflection
site strips — one more is another round of `VisibleFields` surgery), and the plain `?: T` case, which works today
with zero layout cost, would either move to the bitmap (a large churn for no behaviour gain) or coexist with two
presence mechanisms. Option 1 touches only the fields that actually have three states.

### Option 3 (rejected): a sentinel pointer for `null`

`(ptr)1` as "explicit null" on pointer fields. Every null test in the compiler is `icmp eq ptr null`; a sentinel
would have to be masked at every read site, and it cannot express the third state for scalars at all.

### Read kinds

A `ThreeState` field read yields a `T | null | undefined` value: for scalars the `{ i8, T }` aggregate flows to
the same consumers as today's `{ i1, T }` with `absentLiteral` choosing `"undefined"` vs `"null"` from the state
byte at runtime rather than from the static `IsUndefined`; `emitNullableScalarNullCompare`'s constant fold on
static kind (`emit_nullable_scalar.go:618-632`) must not fold a `ThreeState` operand. For pointer fields the read
is the pointer plus the side byte; `=== undefined` tests the byte, `=== null` tests `ptr == null && byte == 1`.

### Sites (each gains a `ThreeState` arm)

`emitFieldPresent` / `jsonFieldSkippable` / `hasSkippableField` (the gate everything else uses), object literal
store (`storeScalarOrNullableFieldExpr`), `Object.keys`/`values`/`entries`, `for…in`, `in`/`hasOwnProperty`,
`util.inspect`, `JSON.stringify` (`null` when state 1, skipped when 0), `typeof`, `?.` and `??`, destructuring
defaults (`{ s = d }` applies for `undefined` only, not for `null`), spread/rest copies (copy the side byte),
`canonicalizeClassTy` (carry the flag, cf. ADR-00835), `checkStrictUndefinedAssign`.

## Prerequisites

| Dependency | Status | Notes |
|---|---|---|
| Nullable scalar aggregate `{ i1, T }` | Done (TDD-00064) | widen to `{ i8, T }` for `ThreeState` |
| Optional-field enumeration | Done (ADR-01066) | `forEachPresentField` is the one walker to teach |
| Parser: keep `null` and `undefined` distinct in a union | Missing | `parser_types.go` folds them |
| Field-level flow narrowing on members | Missing (ADR-00779) | independent; not required |

## Open questions

- Whether `T | null | undefined` on a *local* (not a field) should also get the state byte, or stay collapsed
  with a documented caveat until a use case appears.
- Whether the side byte for pointer fields should instead be folded into a class's existing hidden tag word when
  the object is a class instance (saves the byte; two encodings to maintain).
