# ADR-01663: Representation conversion is one function, convert

- **Relations**: Implements [TDD-00230](../../tdd/TDD-00230.md) (P3.4)
- **Date**: 2026-10-16

## Context

TDD-00230's phase-3 exit criteria ask that `coerce` and its variants be
replaced by `convert`, total over the representation set: a pair it does
not define is a compiler bug reported at the call, never a raw
reinterpretation. The undefined-pair report already existed
([ADR-01656](ADR-01656.md)); the names had not moved.

## Investigation

Eight functions carried the name:

- `coerce` (387 calls), `coerceChecked` (28), `coerceArrayElems` and
  `coerceShortCircuitOperand` change a value's representation.
- `coerceByteLengthArg`, `coerceTypedArrayStore`, `coerceNumArgRef` and
  `coerceStringArg` apply a JS abstract operation (ToIndex, the typed-array
  element conversions, ToNumber, ToString) at an argument or store; they
  call the conversion but are not one.

## Decision

- `coerce` is `convert`; `coerceChecked` is `convertChecked` (the
  conversion plus the type-mismatch diagnostic); the two helpers are
  `convertArrayElems` and `convertShortCircuitOperand`; `coercionIsSound`
  and `coerciblePure` are `conversionIsSound` and `convertiblePure`.
- The abstract operations are named for theirs: `toIndexArg`,
  `toTypedArrayElem`, `toNumberArgRef`, `toStringArg`.
- `emit_exprs_coerce.go` is `emit_convert.go`.
- `TestRepresentationConversionIsConvert` rejects a function or type
  named coerce.

## Implementation notes

A rename only. Comments that use "coerce" as an English verb stay.

## Side effects discovered

None.

## Verification

- `go build`, `go vet`, `go test ./codegen/llvm` (Mac).
