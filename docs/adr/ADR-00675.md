# ADR-00675: `events.once` — Promise-of-args via desugar (TDD-00167)

- **Relations**: Implements TDD-00167; Extends [ADR-00674](ADR-00674.md)
- **Date**: 2026-09-03

## Context

`events.once(emitter, name)` — the `events` module static helper that returns a
Promise resolving with the event's arguments the first time it fires — was a
TDD-00165 Stage-4 extra. It was the reason the `Promise<T[]>` corruption
([ADR-00674](ADR-00674.md)) was found and fixed first; with that in place it can
be delivered.

## Decision

Register `once` in `moduleFunctionMembers["events"]` (making `events` a hybrid
reexport module like `url`, dispatched via its marker) and emit it by
**desugaring** to the existing Promise + EventEmitter machinery:

```
once(ee, name)  ⟶  new Promise<elem[]>((res, rej) =>
                     ee.once(name, (__v0, …) => res([__v0, …])))
```

`emitEventsOnce` synthesizes that AST: N listener parameters (N = the event's
payload arity, from `resolveEventPayload`), an array literal of them passed to
`resolve`, all inside a `new Promise` executor. The synthesized `Promise` is given
an explicit `<elem[]>` type argument — the value type can't be inferred through
the nested listener, and without it `resolve`'s closure signature defaults to a
scalar and truncates the array.

The element's annotation name is chosen width-exactly (`double` → `float64`,
`i64` → `number`, string → `string`, `i1` → `boolean`): `listenerTypeName`
collapses `i64`/`double` to `"number"`, but a bare `"number"` resolves to a
double, so a name that round-trips to `elem`'s exact representation is needed for
the resolved array's element type to match the listener's.

## Scope (V1)

Single-value events and homogeneous multi-argument (same-type tuple) events resolve
to `Promise<elem[]>`. A **mixed-type** multi-argument event is a clean rejection
(homogeneous arrays only). Payload-less events and non-scalar payload element types
are deferred. `events.on` (the async-iterator helper) is the separate TDD-00167
follow-up.

## Verification

E2E tests in `tests/node_core_modules_test.go`: `once` on a number event and a
string event, each awaited to the args array. The `Async|Promise|Await|Event|
Import|Module|Reexport` suites are green (Mac); `go vet ./...` clean.
