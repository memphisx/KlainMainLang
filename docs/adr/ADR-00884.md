# ADR-00884: Date and Array methods reject a non-numeric index/count argument cleanly

- **Relations**: `Extends ADR-00883`
- **Date**: 2026-09-11

## Context

Continuation of the A1 invalid-IR sweep (BACKLOG §4, memory "Invalid-IR backlog
histogram"), after DataView (ADR-00882) and String (ADR-00883). The Date and
Array families had the same defect: a non-numeric argument to a method expecting
a numeric index/count/component reached arithmetic uncoerced and emitted invalid
IR (`'%t' defined with type 'ptr' but expected 'i64'`).

Repros (macOS arm64):

```ts
[1,2,3].slice(Symbol("x"));        // before: add/icmp i64 <ptr> — invalid IR
[1,2,3].splice(0, Symbol("x"));
const o = {v:1}; [1,2,3][o];
new Date(2020, Symbol("x"));
new Date(0).setFullYear(Symbol("x"));
```

## Investigation

As in ADR-00882/00883, the sites used bare `e.coerce(v, TypeI64)`, whose
"return unchanged" fallthrough leaves a `ptr` register typed as i64.

- **Array**: the central `arrayIndexToI64` normalizer (`emit_arrays_core.go`) is
  the shared path for slice/fill/copyWithin/at/bracket-index across 14 call
  sites — so fixing it covers the whole family at once. It already parsed a
  *string* index via `strtoll` (ADR-00694); only the numeric fallthrough was
  unchecked. Plus two direct-coerce sites: splice `deleteCount` (two spots) and
  indexOf `fromIndex`, and the `new Array(n)` size.
- **Date**: the multi-argument calendar constructor (`emitNewDateMulti`) and the
  setter arguments (`emitDateSetter`). The `new Date(string)` branch was already
  handled separately.

The rejection is the faithful typed-subset behavior — `tsc` rejects a
non-number index/argument type.

## Decision

- Changed `arrayIndexToI64` to `(Value, error)` taking a `pos`, using
  `coerceChecked` in the numeric fallthrough; updated all 14 callers
  (emit_arrays_{mutate,iter,transform,sort}.go, emit_exprs_member.go) to thread
  the error. String-index parsing is unchanged.
- Converted the splice `deleteCount`, indexOf `fromIndex`, and `new Array(n)`
  size sites to `coerceChecked`.
- Converted the Date calendar-constructor components and setter arguments to
  `coerceChecked` ("Date component" / "Date setter argument").

## Implementation notes

- Files: `emit_arrays_core.go`, `emit_arrays_mutate.go`, `emit_arrays_iter.go`,
  `emit_arrays_transform.go`, `emit_arrays_sort.go`, `emit_arrays_search.go`,
  `emit_exprs_member.go`, `emit_date.go`.
- `lastIndexOf` takes only one argument in this compiler (no `fromIndex`), so it
  has no site to fix. `new Date(Symbol)` routes to the string-parse branch (a
  separate "needs explicit element type"/parse path), not invalid IR.

## Side effects discovered

None. `a["2"]` string-index addressing, and all numeric index/count usage,
continue to work (verified). A pre-existing unrelated limitation remains:
`[].slice()` with zero arguments is rejected ("slice takes 1 or 2 arguments").

## Verification

- Per-method repros now reject cleanly (slice/at/fill/copyWithin/splice/indexOf/
  object-bracket-index; Date constructor + setFullYear).
- New E2E `TestE2EArrayNonNumericIndexRejected` and
  `TestE2EDateNonNumericArgRejected`; positive array/date programs and
  `TestE2E(Array|Slice|Splice|Fill|CopyWithin|IndexOf|Date)` suites stay green.
- `go build`, `go vet ./...` — clean. Full Test262 not re-run on macOS here (a
  Linux-arm64 Docker conformance run was in progress; isolated-only rule).
