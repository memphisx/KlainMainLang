# ADR-01432: Captured uninitialized globals, element-read and `any` reprs

- **Relations**: Implements TDD-00230 (P2.2, P3.3), Extends ADR-01431
- **Date**: 2026-10-06

## Context

The shadow report after ADR-01431 (107506 rows) led with three buckets
that were not a type disagreement but a representation the comparison did
not model, and one that was a compile failure.

## Investigation

- `(error?: any) => void` (the stream `Callback`): codegen marks the
  optional `any` parameter undefined-able; the checker gives `any`. The
  NaN-boxed `any` holds undefined and null itself, and the one place
  codegen branches on those flags for a dynamic value concerns a nullable
  function, not a plain box.
- `a[i]` and `const x = a[i]`: codegen gives an element read `T |
  undefined` with `UncheckedIndex` (an index past the end reads undefined);
  tsc types it `T` without `noUncheckedIndexedAccess`.
- `var value; function f(a) { value = a; }` (Test262
  `arguments-object/unmapped/via-params-*`): codegen did not promote a
  declaration with no initializer, so the function's write named a missing
  global ("undefined variable"), in both lanes (`let w;` in the strict
  lane). tsc 5.9.3 accepts the program under `--strict`.

## Decision

- A top-level declaration with no initializer and no annotation that a
  function reads or assigns is promoted as an `any` global.
- The shadow oracle gives an array element read, and an unannotated
  variable initialized by one, the element-read form codegen uses.
- The comparison key leaves out the nullable/undefined-able flags of a
  plain `any` (one with no union members).

## Verification

this tree (Linux, kmlbox DeskMini; Node304 unreachable): test-par, examples
396/396, Test262 strict 8409 (8 new, none lost) and js 10833 (22 new, none
lost), neither with invalid IR. The shadow report fell from 107506 rows to
