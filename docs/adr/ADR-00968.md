# ADR-00968: Conformance harness reaps escaped child processes

- **Date**: 2026-09-15

## Context

Running the Node conformance suite (`make conformance-node`) piled up hundreds
of live processes and drove RAM to ~42GB, at which point the OS began
OOM-killing. Recovery was a manual `pkill -9 -f '\.conformance-out/'`. The
symptom initially read as a per-file run timeout not killing its binary, but
that turned out to be only half the story.

## Investigation

`killableCommand` (main.go) already builds every compiled-test `exec.Cmd` with
`Setpgid: true` and a `Cancel` that `kill(-pgid)`s the whole group on timeout,
with `WaitDelay` bounding the residual pipe wait. A controlled single-process
experiment confirmed this reaps a plain CPU-loop binary cleanly — zero orphans.

So ordinary looping/listening single-process binaries are *not* the leak. The
leak is processes that **escape the group**:

- A test that spawns a `detached: true` child calls `setsid()` in the fork
  (ADR-00765), placing it in a new session + process group. `kill(-pgid)` of
  the parent's group never reaches it. Reproduced directly: the parent exited 0
  in 423ms (a clean PASS, no timeout fired at all) while its detached child
  survived and was re-parented to init.
- A `cluster.fork()` / `http.listen({workers:N})` peer re-execs the compiled
  binary; when its parent test exits, the worker re-parents to init and keeps
  serving.

Across ~3,957 files these accumulate unboundedly. Because the parent exits
cleanly, the existing timeout path never even attempts a kill — so the
handover's proposed "kill the timed-out binary" fix would not have addressed
the actual mechanism.

## Decision

Add a background reaper (`tools/conformance/reaper.go`, Unix; Windows stub in
`reaper_windows.go`) that runs for the whole invocation:

- Every 3s it enumerates, via `ps`, processes whose command line references the
  run's scratch workdir (`.conformance-out/run-<pid>`, unique per run, so a
  substring match is both sufficient and safe against unrelated processes).
- It SIGKILLs (group then pid) any such process that is **orphaned** — neither
  it nor its parent is a currently-registered live test child. A re-exec'd
  worker whose parent test is still within its timeout has `ppid ==` that live
  child and is spared until the parent finishes; once the parent exits the
  worker re-parents and the next sweep takes it.
- A hard aggregate-RSS ceiling (`-mem-cap-mb`, default 4096) kills every
  workdir process and aborts the run (`os.Exit(3)`) if total workdir RSS
  crosses it — the machine-safety backstop.
- A SIGINT/SIGTERM handler sweeps all workdir processes before exit, and a
  deferred final sweep runs on normal completion.

The node lane also gained `-limit N` (it previously ignored the flag), so the
harness can be smoke-tested over a bounded slice on a throttled machine without
committing to the full ~3,957-file run.

Each compiled-test run is now launched through `runTracked` (Start → register
PID → Wait → unregister) instead of `cmd.Run()`, so the reaper can distinguish
a legitimately-running test binary from an escaped orphan.

## Implementation notes

- `runTracked` uses `Start()`+`Wait()`, which is equivalent to `Run()` — the
  context-cancel watcher and `WaitDelay` configured on the cmd are honored by
  `Wait` — but exposes the PID between the two calls. Only the *test-binary* run
  sites (main.go, node.go; wpt routes through node's `compileAndRunInDir`) are
  tracked; clang invocations are left as plain `Run()`.
- The reaper matches on the absolute workdir path, so `filepath.Abs(*workDir)`
  is computed once and passed to `startReaper`.
- Unix-only (`syscall.Kill` with a negative pid); the Windows stub keeps the
  shared call sites compiling. Cross-builds verified for windows/amd64 and
  linux/arm64.

## Side effects discovered

- **Residual gap:** a test that spawns a *detached child of a different
  executable* (e.g. `/bin/sh`) which re-parents away is not caught by the
  workdir-path match. Such children are tiny (kilobytes) and rare in the Node
  corpus (which spawns `process.execPath` = the compiled binary = a workdir
  path); the `-mem-cap-mb` backstop still bounds aggregate damage.
- **Not addressed here (flaky pass counts):** the 5s per-file timeout covers
  both `clang -O2` and the run, so under CPU throttling slow-but-terminating
  files get bucketed as FAIL, making the pass count track CPU clock. Tracked as
  a separate follow-up (own TIMEOUT bucket + serial retry).
- The `removeEventListener`/`EventEmitter.off`-by-named-function-reference bug
  remains a separate compiler fix, tracked apart from this tooling change.

## Verification

- `tools/conformance/reaper_test.go`: `TestReaperKillsOrphanedWorkdirProcess`
  (an untracked workdir process is scanned, classified orphaned, and killed)
  and `TestReaperSparesLiveChild` (a registered live child survives a sweep).
- `tools/conformance/reaper_integration_test.go`:
  `TestReaperEndToEndDetachedWorker` — the full path. It compiles a real
  reproducer (a test that spawns a detached, `setsid`'d child re-execing the
  workdir binary, then exits 0), runs it through the actual harness exec path
  (`killableCommand` + `runTracked`) under a context that is never cancelled
  during the assertions, first asserts the orphaned worker *materializes* (the
  leak is real), then asserts the reaper's `sweepOnce` clears it — so
  `killableCommand`'s group-kill provably cannot be what reaped it. Passes;
  zero leftover processes.
- A bounded live run (`-suite node -limit 500 -workers 4 -mem-cap-mb 2048`)
  completed cleanly with zero leftover workdir processes and no crash — the
  wiring doesn't disturb normal operation.
- Root cause independently reproduced at the CLI: a detached-spawn binary whose
  parent exits 0 while the setsid child survives.
- `go build`/`go vet ./tools/conformance/` clean; cross-compile clean for
  windows/amd64 and linux/arm64. macOS arm64 (M4). The **full** conformance
  suite was not run (battery / low-power), but the mem-cap backstop now makes it
  safe to.
