# ADR-01293: An Error's own enumerable properties

- **Relations**: `Extends ADR-01080`, `Extends ADR-01287`
- **Date**: 2026-09-30

## Context

A Node error's own enumerable properties are those set on it:
- `errno`, `code`, `syscall`, `path`, `dest` on a system error (and
  `address`/`port` for a failed connection);
- `code`, `errcode`, `errstr` on a node:sqlite error;
- `status`, `signal`, … on an `execSync` failure;
- an Error subclass's own fields.

`message`, `stack` and `cause` are not enumerable. Here:
- `JSON.stringify` of a typed Error wrote every field of the internal
  layout (`"errcode":0,"cause":null,"port":0,"extra":null`).
- A caught value (`catch (e)`) was serialized as a number (`0`), and
  `Object.keys(e)` did not compile.
- A boxed error was always `{}` with no keys, even an `ENOENT`.

## Decision

- **Object hooks.** `__kml_obj_nkeys`, `__kml_obj_key`, `__kml_obj_get`
  and `__kml_obj_has`, which inspect, JSON and the key walkers read, take an
  Error's layout keys (a subclass's own fields) and then its own fields
  (`__kml_error_nextra`, `__kml_error_extra_key`, `__kml_error_extra_get`):
  - Present system fields, in Node's order: `errno`, `code`, `syscall`,
    `address`, `port`, `path`, `dest`, `errcode`, `errstr`. `errcode` and
    `errstr` count only on an error without `errno`, since a system error's
    copies of them are internal.
  - Then the keys of its `extra` bag.
- **Walkers.** `__kml_shape_keys_array` (`Object.keys` of a boxed value)
  and the JSON walker's boxed-Error arm read those hooks.
- **Typed and caught values.** A typed Error or Error-subclass value is
  serialized through the dynamic walker. A caught value is boxed for
  `JSON.stringify` and `Object.keys`.

## Verification

On the Mac (Apple Silicon), `tests/error_own_props_test.go` matches Node
v24.19.0:
- plain, subclass and nested errors;
- a caught fs error, typed and in `any`;
- node:sqlite and `execSync` failures.
