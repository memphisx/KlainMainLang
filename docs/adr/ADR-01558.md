# ADR-01558: More representation rules for member reads, calls and identifiers; `this` parameters on method signatures; asserted call types

- **Relations**: Extends ADR-01556, ADR-01557, TDD-00230
- **Date**: 2026-10-10

## Context

With member reads, calls and identifiers decided by the checker-side
mapping, the remaining end-to-end divergences were places where codegen
holds a value in a representation the checker's type alone does not name:

- A function literal reading `arguments` gains its implicit rest at
  emission, after the checker typed it; a value of it (a named function, a
  method read off its instance) carries that rest. A method read as a value
  is a bound closure whose call does not count its arguments.
- A function literal passed where an overloaded function's implementation
  takes `any` (`dns.resolve6(h, opts, (e, a) => …)`) is boxed: its
  parameters are boxes, whichever overload the checker picked. A method
  with overloads whose implementation returns `any` or `Promise<any>`
  (SubtleCrypto's) resolves a box.
- A property a function value carries by assignment (`ok.throws = throws`)
  lives in its boxed property table.
- A `null`-initialized class field later given a value is a box
  (classFieldNullEvolves); a `null`-initialized binding never given one
  holds the null.
- A `var` whose declaration can be skipped on the way to a read holds
  `T | undefined` (ADR-01057); an unannotated function returning one, and
  its calls and its binding, follow.
- An annotated tuple parameter holds a tuple; a call through a binding
  typed as a function returning a tuple returns that tuple.
- A binding of a builtin's type narrowed by `instanceof` to a program class
  extending it reads as that class (ADR-01469).
- An unannotated binding of an object literal with a getter or setter holds
  the literal's synthetic class (TDD-00153).
- A class name read as a value is the class itself, so its statics keep
  their types.
- A call an overload types `void` whose implementation returns a value
  (`dns.lookup`'s request object), or one whose `any`-returning
  implementation produces an object, is a box; the callback parameter
  rule above applies only where the implementation's parameter is `any`
  and the overloads disagree on it, or it is record-shaped.
- An interface-declared method a class implements is decided by the
  class's own declaration (`crypto.subtle.exportKey`'s `Promise<any>`);
  `await` of such a promise, and a binding of it, holds the box.
- `then`/`catch`/`finally` on an instance of a class extending Promise
  makes another instance of that class (species), and the executor it
  passes to `super(…)` takes the same resolve and reject as
  `new Promise`'s.
- `Promise.all` of a literal holding a thenable class instance resolves the
  literal's own elements, boxed.
- A binding of a regular-expression group read may be undefined; a binding
  declared `T | undefined` and narrowed by assignment keeps that form where
  it is compared against `null` or `undefined`, so a missed map read is
  still detected.
- A call of an overloaded function whose implementation declares that
  argument's slot `any` boxes a function literal passed there: its
  parameters are boxes, except one typed as a class instance. A listener
  the implementation takes as `(...args: any[]) => void`
  (`socket.on('data', (d) => …)`) is called with boxes too.
- An element-callback method (`map`, `filter`, …) called on an array held
  boxed whose elements are typed arrays (`readdirSync(p, 'buffer')`) is a
  call on the box: its callback takes boxes and its result is a box.
- An array pattern binds a string or an object, as well as a number or
  boolean, as possibly undefined (unpackArrayPatternInto).
- `f.bind(thisArg, …)` is a function of the remaining parameters; a global
  object's lowered static (`Math.sqrt`, also through `globalThis`) keeps
  its intrinsic type when read as a value; a recursive function's inferred
  return type stops at its own recursion.
- A skippable `var` at module level is answered as one in a function
  (ADR-01559).
- `str.match(re)` holds the exec-result array (plain when `re` has no
  `g` flag known at compile time), as do its `!` and a const binding of it
  narrowed present.
- A call of a method a generic class erases (its result written in terms
  of the class's type parameters) is the type codegen instantiates it at,
  except where that is an unconstrained box and the checker answers a
  number.

Several checker gaps surfaced too:

- A method signature's leading `this: T` parameter
  (`read?(this: H, size: number): void`) was dropped, so a read of the
  method lost it.
- `JSON.parse(s) as Rec[]` keeps its assertion on the call
  (`AssertedType`, ADR-00371); the checker ignored it and typed the call
  `any`, where TypeScript types the expression `Rec[]`.
- A contextual type that is an interface with one call signature
  (`TransformerTransformCallback<I, O>`) did not give a function literal's
  parameters their types, and a `T | undefined` object context did not
  reach its properties; TypeScript takes both (getContextualSignature).
- A receiver (`[].map(…)`'s `[]`) took a contextual type; a conditional
  with an empty `[]` branch and no context was not `never[]`; a property
  value of an object literal saw the literal as `this`; a member of a
  narrowed function value (`callback.call`) was unanswered.
- `f.call(…)`, `f.apply(…)` and `f.bind(…)` did not check their arguments
  against `f`'s parameters (TS2554, TS2345), and a generic call whose
  argument is a function was unanswered even without a context to defer
  to.
- A contextual parameter typed as a class with a generic method, a method
  returning `this`, or a member of an unresolved library type
  (`ReturnType<typeof setTimeout>`) lost its type: the member walk counted
  the method's own type parameters and the instance's own `this` as free.

## Decision

- The mapping applies each representation rule above.
- The checker keeps a method signature's `this` parameter on the method's
  type, in interfaces and type literals.
- The checker types a call carrying an asserted type as that type.
- The checker takes an interface's single call signature as a contextual
  signature, and an object context's non-nullable part for a property.
- The checker gives a receiver no context, types the empty-branch
  conditional `never[]`, resolves `this` in a property value to the
  enclosing one, answers a narrowed function value's members, checks
  `call`/`apply`/`bind` arguments as tsc does, infers a generic call with a
  function argument where the context allows, and treats a member
  signature's own type parameters, the instance's `this` and unresolved
  library members as bound when deciding whether a contextual parameter
  names a type parameter.
