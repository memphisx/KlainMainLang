# ADR-00479: interface merging; overloaded call signatures; void-init binds undefined

- **Relations**: Extends [ADR-00466](ADR-00466.md), [ADR-00455](ADR-00455.md)
- **Date**: 2026-08-29

## Context

Three TS-oracle buckets: `'%s' is declared more than once` residue
(interface+interface pairs — real TS declaration merging), `at most one
call signature is supported per interface` (34 — overloaded callable
interfaces), and `cannot assign the result of a void expression` (32 —
`var b = await voidFn()`-style bindings, legal JS yielding `undefined`).

## Decision

- **interface+interface merging**: the resolver's merge-pair rule accepts
  same-name interface pairs; `registerInterfaces` unions the second
  declaration's fields/method signatures into the first (first wins on a
  member-name collision; TS's no-conflicting-members check not modeled).
- **Overloaded callable interfaces**: additional call/construct
  signatures are erased first-wins — call sites check against the first
  signature, the same stance function overload signatures take
  (ADR-00446).
- **Void initializer**: an *untyped* binding whose initializer is a void
  call runs the call for its side effects and binds `undefined`
  (`typeof b` → "undefined", `b === undefined` → true) — JS's own
  semantics; an annotated binding keeps the clean rejection.

## Verification

Mac. `tests/interfaces_test.go` E2Es (merged fields, overloaded callable,
void-init) and the example extension pass; parser + interface/union/void
batches green. TS oracle: **56.8% → 57.1%** (agreement 5261 → 5289). Node
oracle unchanged (40).
